Context
The mesher reads each block through BlockGetter.getFn (a function pointer), then a 3×3 chunk lookup with division, then a bit-unpack from the palette. It does this for each neighbour of each block.
Acceptance Criteria
Each mesh job copies the chunk and a 1-block border into one dense array. Not done. Inside the chunk, the mesher reads the chunk directly. Only samples at the edge use the getter: about 21% of 0.21 ms per chunk. The two getters disagree for a missing neighbour (bug: World and SnapshotGetter give different skylight for a missing neighbour chunk #604), so a direct read must solve that first.
Greedy meshing finds visible faces and walks each slice with bit masks per column. The merge rule does not change, so the mesh does not change.
The goldens CI passes with no changed pixels.
The PR states the mesh time per chunk before and after, from --profile-csv or benchmark.sh.
