Abstract. Load balancing is the process of improving the performance of a parallel and
distributed system through a redistribution of load among the processors. The Round Robin (RR)
algorithm, known for its simplicity and fairness, distributes requests evenly across servers in a
cyclic manner [1] [5]. However, RR does not account for server capacity or dynamic workload
conditions, often leading to inefficient resource allocation and potential server overloading. In
this paper presents an enhanced approach based on the Dynamic Weighted Round Robin (DWRR)
algorithm. Unlike the traditional RR, DWRR dynamically adjusts the weight of each server based
on its current performance metrics, such as CPU load, memory usage, or response time. This
enables more intelligent and adaptive request distribution, ensuring that more capable servers
handle greater loads while preventing weaker servers from becoming bottlenecks. The main
purpose of this paper is to reduced response time, and more balanced load distribution compared
to standard RR.
Keywords: load balancing, DWRR, Dynamic Weighted Round Robin, dynamically assign
weights, web server clusters, RR.
INTRODUCTION.
The Load on many servers on the Internet is increasing day by day due to the present
increase of Internet users. A single server might not be able to serve web contents from multiple
concurrent users. So, the contents must be hosted on many servers to deliver the web contents
without any delay. If the contents are hosted on multiple servers, deploying the load balancing
algorithm in the server farm is mandatory. The load balancer will decide which server will respond
to the particular client request, and then the client request will be redirected to the selected server.
A server usually provides service to the client’s request[7] [9]. A web server responds to the web
services request of its clients. Suppose a single server is serving many responses to multiple clients
concurrently. In that case, the server resource might be over utilized and consequently increase the
server response time, and even the service may be denied after a certain point of time. So to
minimize the load on a single server in terms of resource utilization and to overcome the denial of
services, the resources are needed to be hosted on multiple servers. In this paper, we deploy a load
balancing algorithm with multiple servers to reply clients’ requests without any delay.
To overcome these limitations, enhanced versions of the RR algorithm have been proposed,
including the Weighted Round Robin (WRR) and, more recently, the Dynamic Weighted Round
Robin (DWRR) algorithm. DWRR introduces adaptability into the scheduling process by
assigning weights to servers based on their real-time performance metrics such as CPU utilization,
memory consumption, and response times. This dynamic adjustment enables more intelligent and

METHODOLOGY.
This paper proposes an improved variant of the DWRR algorithm specifically tailored for
server load balancing. The goal is to optimize resource distribution, reduce average response time,
and enhance overall system throughput under varying workload conditions. Simulation results
demonstrate the superiority of the proposed method over traditional RR in terms of adaptability
and efficiency in real-world scenarios.
Round Robin (RR) Algorithm: Overview. The Round Robin (RR) algorithm is one of the
simplest and most widely used scheduling techniques in computing and networking. It works by
distributing incoming tasks or requests sequentially and cyclically to a list of available servers or
processors. Once the last server in the list is reached, the scheduler loops back to the first server
and continues the process. This ensures that all servers are given an equal opportunity to handle
incoming requests [8] [12].

Dynamic Weighted Round Robin (DWRR) algorithm. Dynamic Weighted Round Robin
(DWRR) is an advanced version of the traditional Round Robin (RR) and Weighted Round Robin
(WRR) scheduling algorithms, designed to provide more intelligent and adaptive load balancing
in systems with dynamic workloads and heterogeneous resources.
How DWRR works: Unlike basic RR, which treats all servers equally, and WRR, which
assigns fixed weights to servers, DWRR dynamically adjusts weights based on real-time
performance metrics. These metrics may include:
CPU usage
Memory utilization
Current number of active connections
Response time
Server throughput
Each server is assigned a weight that reflects its current capacity or performance status.
The scheduler then distributes incoming requests based on these weights — servers with higher
weights receive more requests, while overloaded or underperforming servers receive fewer.
DWRR improves system performance by intelligently assigning requests based on current server
conditions. It is particularly useful in cloud environments, distributed systems, and web server
clusters, where workloads are unpredictable and resources vary in capability. By combining
