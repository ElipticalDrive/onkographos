Before: map.add3DTiles(url) に glTF の KHR_gaussian_splatting が入っていると、splat は点（mode 0 の点群）として描かれるだけだった。Gaussian splat は .ply / .splat / .spz のファイル 1 本ずつ（origin で置く）しか扱えず、タイル化して流す手段が無かった。
After: map.use(splatPlugin()) の上で map.add3DTiles(url) を呼ぶと、タイルの glTF の splat プリミティブがタイルごとに plugin-splat の層になる（SSE で選ばれ、親子の入れ替えで setVisible、unload で remove、当たりは properties.tile）。Release Candidate の属性名（KHR_gaussian_splatting:SCALE…・線形の尺）、Cesium の草案（_SCALE＝log・_ROTATION・_OPACITY）、COLOR_0 の fallback、SH 1〜3 次、KHR_gaussian_splatting_compression_spz_2（bytes を plugin の読み手が解く）を読む。plugin が無ければ従来どおり点（仕様の fallback）＋tileset ごとに一度 warn。add3DTiles(url, { splat: { depthTest, shDegree, lod, … } }) で層の opts を渡せる。
座標は worker が f32 の ECEF に直さず、局所のまま＋列優先 4×4 の transform（局所 → ECEF） で返し、plugin が倍精度で東北上に置く（f32 ECEF の 0.5 m のずれを避ける）。plugin-splat 0.4.0＝SplatData.transform / opts.transform（crs "local"）、層を目から錨までの距離で奥から描く（タイルの層が重なる所）、層が立つ前の setVisible(false) を覚える（親を伏せる便りが層より先に届く競合＝検定で見つけた）。
How: meshdecode.ts に splatPrim（属性の解き・SH の並べ替え・SPZ の素通し・transform と heightOffset）、tiles3d-decode.ts / model-worker.ts が splats を集めて transfer、gadgets/tiles3d.ts がタイルごとに map.addData({ crs: "local", transform, … }, { kind: "splat", … })。本体 splat.ts / globe.d.ts は crs "local"＋transform の検めと bytes の素通し。plugin は toEnu に transform の枝、checkTransform、on を層の便りに。
検定：node packages/globe/tests/tiles3d-splat.mjs（見本の tileset＝親＋子 4 枚：仕様の名・1 次の SH・草案の名・SPZ v2／20 件）を globe の npm test に、plugin の xf.*、tests/splat.mjs の local。ブラウザ t-tiles3d-splat（4 象限に赤・緑・青・白が正しい場所に出る・当たりの tile・遠いと親だけ・remove で全部降りる・?v=noplugin＝点の fallback）を verify:ui と verify:webgpu に。容器（WebGL2）で両変種 PASS、typecheck 51 package OK、plugin の node 全 PASS。Mac の WebGPU 検証は PR 作成後に RC で実施。
engine（packages/globe の worker と gadget）が変わる＝merge 後に npm run deploy:engine が要る。plugin 0.4.0 は npm 未公開（0.2.0 以降と同じ）。
文書：sdk/plugin-splat/README.md（transform・3D Tiles）、PLUGINS.md（dataKinds splat の契約に crs local＋transform・W10d）、maplibre-compat.md（W10d）、README の表。
