Summary
The per-site PVOL Cartesian render (polar_sample — WMS/Maps/Tiles for engine_type = "odim-volume") has sampled bilinearly since #186, which blends the four surrounding (ray, bin) cells to close the radial bin/wedge structure far from the radar. That smoothing also softens peaks and erases the discrete radar bins — detail that is visible in the COMP composite (nearest) and GeoTIFF (nearest) renders, so per-site DBZH layers look blurry by comparison (user-reported).
This adds a per-collection toggle and restores nearest-neighbour as the default:
```
[odim]
# resampling = "nearest"   # default — discrete bins visible, full detail
resampling = "bilinear"    # opt back into the #186 smoothing
```
nearest was the pre-#186 default: each output pixel takes its single enclosing polar cell, so cells tile the output plane and widen with range — the bins stay visible and every gate's value is preserved, with no gaps (there never were empty gaps; #186's "radial spokes" were this discrete-bin structure itself). bilinear keeps the #186 look available per collection.
Changes
New ds_core::config::ResamplingMethod enum (serde lowercase; Default = Nearest); #[serde(default)] field resampling on OdimConfig.
Threaded engine → every PolarVolumeSiteView → polar_sample, which now branches per pixel: nearest = floor of the fractional (ray, bin) (ray wraps at the 0°/360° seam); bilinear = the existing mask-aware bilinear_cell.
Unaffected (verified against the code): COMP composite render (always nearest), EDR position/area queries (always nearest — a point query wants the measurement, not a cosmetic blend), and the 3D Tiles voxel / isosurface / echo-top products (those sample nearest then apply a separate smooth_grid 3-D blur in ds-3dtiles, 3D Tiles isosurface: smooth the scalar field before marching (reuse the voxel blur) #381; the point cloud is raw). So this toggle is map-render-only.
Docs: OdimConfig/ResamplingMethod rustdoc + a CLAUDE.md PVOL note.
Test plan
cargo test -p engine-odim — 32 integration + lib tests pass.
New polar_sample_nearest_does_not_blend_rays locks in the default (ray-only field → every sampled value is an exact integer ray index, no blending); existing bilinear tests now pin ResamplingMethod::Bilinear explicitly (incl. the per-pixel-reference and blend-across-rays tests).
cargo clippy -p engine-odim --all-targets clean; cargo fmt --check clean.
cargo check --workspace --tests --examples clean.

Code Review
The resampling toggle itself is clean and correct: Copy+Default enum, #[serde(default)] on the config field, proper ray wraparound via rem_euclid, correct propagation engine → view → polar_sample. The new regression test (polar_sample_nearest_does_not_blend_rays) is well-constructed and locks in the default.
Three real issues below:
1. Live external URL committed to collections.d/ (operational risk)
collections.d/cap-alerts-feed.toml activates feed_url = "https://feeds.meteoalarm.org/..." as the primary setting (the data_path line is commented out). Any server started with collections_dir = "collections.d" — including the default demo setup — will make an outbound HTTPS request to MeteoAlarm on startup and every 300 s thereafter. If the network is unavailable (CI, air-gapped, offline dev), the engine starts degraded silently; CI jobs that spin up the server will acquire an external dependency. The prior convention in this repo is that committed configs under collections.d/ use local testdata/ paths. Either restore data_path as the active line, or move this file to docs/ / examples/ and add a note that it requires internet access.
2. bin_f.floor() as usize in the Nearest branch is unguarded
The comment asserts bin_f is already in [0, nbins) via pre-existing range-checking earlier in the loop, but that check is not visible in the diff. The old bilinear_cell path has its own internal clamping and is safe regardless; the new Nearest path is only safe if the pre-existing guard is actually in place. If bin_f can reach >= nbins for any output pixel, pixels.sample(ray, bin, ...) will index out of bounds. A debug_assert!(bin < sweep.nbins, ...) after the floor cast would make the invariant explicit and is zero-cost in release builds.
3. resampling on OdimConfig is silently ignored by the COMP engine
OdimConfig is shared between engine_type = "odim" (COMP composite, OdimEngine) and engine_type = "odim-volume" (PVOL, PolarVolumeEngine). The doc comment says "Only the per-site PVOL map render reads this", but there is no config-validation warning. A user who adds resampling = "bilinear" to a COMP collection's [odim] block gets a silent no-op. A startup tracing::warn! when resampling != Nearest is detected on an OdimEngine would prevent silent misconfiguration.
