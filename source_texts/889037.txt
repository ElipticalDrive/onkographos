Branch: frontier-voxel-engine · Master: #24 · Audit: https://github.com/DrewPhi/MicroVoxelProceduralGeneration/blob/frontier-voxel-engine/frontier/PIXEL_ADAPTIVE_RESEARCH_AUDIT.md
Scope: P1 representation; dependencies: #59 and existing #33/#46/#47; G1/G3.
Develop spatially keyed, camera-independent, reusable multiresolution descriptions of the authoritative 6.25 cm voxel world: empty / solid / mixed, minimum/maximum surface/bounds, visible face/material and normal coverage, uncertain silhouette bounds, cave/topology features and edit revision dependencies. For ordinary heightfield-safe terrain, reuse/prove compatibility with GPU height pages and parent-child residuals; for rock arches, tunnels, overhangs, towers, voxels steps and edits, use sparse 3D brick/cluster summaries. Do not voxelize all untouched world cells in memory.
Key traps: majority-vote coarse occupancy fills cave mouths and erases thin features; using only average height loses a ridge; independent sampling by LOD changes world identity. Provide conservative mixed-state handling or faithful proxy for narrow meaningful features; exact native cells always remain canonical.
Acceptance: pixel-scale progressive detail across camera zoom, mountain silhouette and cave/bridge/topology preserved down to chosen image-error tolerance, identical material/cell answers for canonical queries, deterministic edit invalidation, bounded producer memory/CPU. Write oracle tests for undercut cliff, edited cave, bridge, tall tower, thin gaps and all patch edges/corners. Document unproven bounds honestly.
Legacy R/P: reference frontier/world/src/terrain.rs, frontier/renderer/src/terrain.rs, frontier/renderer/src/volume.rs; selective port only after exact/source parity. Avoid copying main's coarse SummaryCache/old near-square. Research: https://doi.org/10.1145/3728299 ; https://arxiv.org/abs/2608.17390 ; https://voxel-tools.readthedocs.io/en/latest/smooth_terrain/ .
Non-goals: no artificial voxel stylization, no refitting quadratics, no forced opaque fog, no hand-authored LOD assets. Keep old comparison scenes but do not mark G1–G4 passed without measured evidence.
Adaptive implementation checkpoint and optimization follow-up — 2026-11-05
Local commit ce3e82a implements the candidate and records evidence in frontier/ADAPTIVE_RENDERING.md and frontier/reference/adaptive/. This commit was not yet pushed when this update was written. Integrated checks: 191 Rust tests and 9 Python tests pass; five manual experiments are explicitly ignored. Latest stationary laptop p95: 18.55 ms (fails the 16.67 ms target). Full motion acceptance remains unmet.
Camera-independent canonical surface/material/face summaries and exact bounded 3D occupancy/topology summaries.
Revision/parity, thin-feature, cave/bridge/tower, edge/corner and conservative-bound tests.
Bounded lazy source-page cache and reusable content identities.
Generic distributed volumetric display hierarchy and complete producer/transient memory limits remain unfinished.
Follow-up: [FV] Reduce cold adaptive refinement work with stage profiling and reusable summaries #69 (reuse), [FV] Parallelize adaptive CPU preparation with bounded jobs and memory #70 (bounded parallel preparation), [FV] Persist versioned procedural pages, summaries and geometry for fast revisits #72 (persistent derived data).
Original acceptance criteria above remain in force; completed substeps do not close this issue.
