Feature Description
Add an optional lossless volume-normalization path for MP3 exports: instead of re-encoding MP3→MP3 through ffmpeg (volume=dB,alimiter filter), apply the gain directly to the MP3 audio frames using mp3applygain (C fork of mp3gain 1.5.2, LGPL 2.1, ~14 KB single-file, no deps).
Motivation
DjManager already normalizes loudness on USB export (copyTrackToUsb: gainDb = targetLufs - track.loudness → convertAudio). For MP3 targets this means a generation-lossy re-encode (decode → volume filter → libmp3lame). Hardware players (CDJs etc.) ignore ReplayGain tags anyway, so the gain must be baked into the audio — which mp3applygain does frame-level, without re-encoding, preserving original quality and ID3/artwork.
Proposed Solution
Vendor mp3applygain.c + lgpl.txt into the repo (e.g. src/audio/native/ or third_party/), build per-platform like ffmpeg/analysis.exe (Linux native; Windows cross via mingw or on Win11 VM; macOS for parity).
New wrapper module src/audio/mp3ApplyGain.js (spawn binary, verify exit code, MP3-only guard).
In copyTrackToUsb: when target output is MP3 (or no conversion needed) and gainDb ≠ 0 → fs.copyFileSync then run mp3applygain on the copy (tool is explicitly "run only on copies" — USB export copies are perfect). Keep ffmpeg path for FLAC/AAC/WAV, zero gain, and positive-gain cases (mp3applygain has no limiter — positive gain can clip; ffmpeg alimiter handles that).
Settings toggle (e.g. "Lossless gain application for MP3 export", default ON when available), IPC channel in all three files per CLAUDE.md.
Unit tests for the wrapper + export-path decision (positive/negative gain, non-MP3 fallback). Windows build verified on win11-djmanager VM per project convention.
Alternatives Considered
ffmpeg only (status quo): works, but MP3→MP3 re-encode = generation loss and slower exports.
mp3gain (full): GPL + insecure embedded mpglib — rejected; mp3applygain is the stripped, LGPL fork.
ReplayGain tags only: useless for hardware players (CDJ) — this is exactly the gap mp3applygain fills.
Notes
Gain comes from existing track.loudness (mixxx-analyzer) — no new analysis needed.
~1.5 dB quantization of the tool is acceptable for loudness matching.
LGPL 2.1: keep lgpl.txt + attribution (source is vendored, so relinking is satisfied).
Repo last touched 2025-02, single maintainer, tiny (2★) — risk assessed, code is well-understood (stripped mp3gain).
