Abstract
This article discusses a set of techniques to solve basic problems in hardware-supported volume rendering. It first discusses a computer architecture that supports algorithmically optimized volume rendering using early-ray termination and space-leaping as acceleration techniques. We present unpublished hardware details and detailed performance measurements that describe the capabilities and limitations of this approach also concerning its use for rendering a combination of several volume- and polygon-based objects. One of the main limitations is the dependency of the rendering speed on the choice of the classification look-up table. In order to cope with this problem we have modified the rendering algorithm so that it uses a different integration rule to solve the ray integral. We give a detailed description of the theoretical derivation of this approach.

Introduction
Many modern imaging systems like CT, MRI, 3D-US generate data in regular grids. One of the standard methods to render images from such data sets is volume rendering. Despite recent advantages in CPU performance and custom rendering boards, high frame rates for large-volume objects remains an issue. There are two principle approaches to overcome this situation. One is the implementation on parallel processors, the other the hardware mapping of the algorithms. In this paper, we concentrate on hardware that accelerates the algorithm to interactive or real-time rates.
There is a long tradition of hardware-accelerated volume rendering. It began with approaches like the Cube systems [1], Vogue [2], and VIRIM [3] that directly implemented different versions of ray-casting into a hardware pipeline. The latter was also built as one of the first hardware accelerators and achieved 5Hz for a four-module system and a 2563 volume. In the meantime, a second generation of accelerators has been developed.
Vizard is a development from the University of Tübingen, Germany that for the first time realized hardware support for early-ray termination and space-leaping [4]. For the space-leaping approach distance coding was used. The ray steps through the volume until it encounters a surface, shading is performed and then the ray is terminated. Since for each step the processing consumes many cycles, Vizard overcomes the problem of data hazards, discussed here in this paper. Its performance was comparable to VIRIM but it was integrated onto a small FPGA card. A further development, Vizard II [5] uses many design ideas from Vogue and uses, like Vizard, an FPGA implementation on a PCI card. Here, features have been implemented like gradient pre-calculation and pre-integration in order to obtain artifact-free images. Similar to the architecture that we present here, Vizard II operates on a bundle of nine rays and uses early-ray termination, when all rays are absorbed. However, in contrast to Vizard, it does not implement space-leaping. In order to reduce the number of memory banks from 8 to 4, the data are replicated per bank in order to make a parallel readout of a 23 sub-cube possible. Vizard II achieves between 3 and 7frames/s for a 2563 data set and a 2562 image.
A sequence of high-performance volume renderers has been developed at the State University of New York at Stony Brook; the Cube systems. From these, Mitsubishi Electric Research Lab, Cambridge, MA, developed the EM-cube [6] and later the VolumePro500 [7], the latter being the first commercial volume rendering accelerator. Meanwhile at Terrarecon Inc., the newest approach is VolumePro1000 [8] which is able to render 5123 data sets in real time. These systems use four identical pipelines for processing the data. They are mapped onto ASICs and a special data flow concept is used, so that each datum is read only once from the memory. This concept, however, does not allow integrating algorithmic optimization techniques efficiently (i.e. it can only handle large empty blocks of voxels that are skipped. Due to their size, these empty blocks occur only rarely in typical volumes). In addition, perspective projections can only be approximated due to the fixed internal architecture.
Race II [9] is a proposal to combine the advantages of object- and image-oriented rendering. The main idea behind it is to read full sub-cubes into the memory and perform ray-casting on these blocks internally so that there is a high memory bandwidth; these subimages are then composited to the final result. Reloading can be avoided by caching the block borders. Space-leaping is realized by skipping transparent blocks like in VolumePro1000, having the same disadvantage. Simulation results for 256×256×218 data sets yield between 35 and 78frames/s depending on the realization and the empty space inside the data.
Recently, we proposed VGE, an approach that efficiently realizes algorithmic optimization in volume rendering. By introducing a multithreading approach it achieves approximately the same frame rate as VolumePro500 [10].
In this paper, we deeply discuss this approach by giving details of the hardware implementation and performance measurements. We discuss its flexibility to render scenes with multiple volumes and polygonal objects and present the limitations of the approach. Finally, we describe a method for accelerating rendering of semi-transparent regions.
