Eliminates the CPU-side performance overhead by routing the compute path directly through the flat VBO, bypassing octree traversal entirely.
Key changes:
Phase 1 – Bypass octree for compute path:
Add totalPointCount to PointCloud (set in setupPointCloudGLBuffers before buildOctree clears points); remove PointCloudChunk legacy fields
main.cpp: single renderNode() call per cloud using vbo+totalPointCount; octree traversal only for GL_POINTS fallback
OctreePointCloudManager: remove s_computeRenderer/s_currentMVP/ s_pointBaseSize/s_fieldOfView statics and the compute branch in renderNodeAtLOD()
PointCloudLoader: remove generateChunks/generateLODLevels dead code
GUI: remove Chunking section (isRecalculatingChunks, sliders, button)
Phase 2 – uint64_t framebuffer (faithful to Schütz):
pointcloud_rasterize.comp: GL_ARB_gpu_shader_int64, uint64_t ssFramebuffer at binding 1, ssColors at binding 44; packs (depth:32|index:32) and does single atomicMin per pixel
pointcloud_resolve.frag: reads uint64_t framebuffer and ssColors; discards sentinel pixels (0xFFFFFFFFFFFFFFFF)
ComputePointCloudRenderer: replace depth SSBO + color texture with single uint64_t framebuffer SSBO; use glClearNamedBufferSubData instead of a compute clear shader; lazy-allocate ssColors per cloud; 128-thread workgroups matching Schütz
Phase 3 – Remove obsolete shaders:
Delete pointcloud_clear.comp (replaced by glClearNamedBufferSubData)
