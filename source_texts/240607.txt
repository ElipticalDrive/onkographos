Adds a second rendering backend implementing stochastic transparency for Gaussian splatting (arXiv 2503.24366) using only PyTorch built-ins — no C++/CUDA extensions required. Selectable at runtime via --renderer stochastic.
Algorithm
Forward pass — tile-based; for each tile:
Project Gaussians to 2D (Jacobian-based perspective covariance, same convention as the CUDA renderer).
Compute per-(Gaussian, pixel) alpha values: α_i(p) = opacity_i · exp(-0.5 · dᵀ Σ⁻¹ d).
Derive alpha-compositing weights w_i = α_i · T_i where T_i = ∏_{j<i}(1 - α_j).
Draw S independent samples per pixel via the Gumbel-max trick on (w_0, …, w_{M-1}, w_bg). Expected value equals standard alpha compositing (unbiased estimator).
Backward pass — straight-through estimator: gradients propagate through the closed-form expected-value formula (alpha compositing), not through the discrete sample selection step. The screenspace_points add-zero trick preserves compatibility with the training loop's densification logic.
Changes
gaussian_renderer/stochastic_renderer.py (new) — StochasticTransparencyRenderer class with .render() returning the same dict as the original renderer. Handles 3D/4D Gaussians, temporal opacity, SH colour evaluation, and tile-based assembly via torch.cat (fully differentiable, no in-place graph breaks).
gaussian_renderer/__init__.py — render() dispatches to the stochastic backend when pipe.renderer == "stochastic"; original CUDA path unchanged.
arguments/__init__.py — three new PipelineParams fields: renderer, num_samples, tile_size.
Usage
```
# Training with stochastic renderer, 16 samples/pixel
python train.py --config configs/dnerf/lego.yaml --renderer stochastic --num_samples 16

# Inference
python render.py -m output/lego --renderer stochastic --num_samples 32
```
Higher --num_samples reduces Monte Carlo noise; --num_samples 1 is fastest but noisiest. The default (--renderer original) is unchanged.
