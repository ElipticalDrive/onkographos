Problem
OloEngine now has OpenGL and Vulkan render backends, a render graph, deferred/forward paths, virtualized geometry, heap-backed Vulkan resources, and a CPU reference path tracer. Adding ray queries, a GPU path tracer, and ReSTIR directly to today's per-pass scene submission would create a second scene representation with different material IDs, transforms, lifetime rules, and visibility semantics.
That is the failure mode to avoid: raster, hybrid RT, and path tracing must not become separate renderers that happen to read the same ECS.
Goal
Create one canonical, frame-versioned GPU Scene produced once from scene/ECS state and consumed by:
raster/deferred/forward rendering;
GPU culling and virtualized-geometry integration;
Vulkan BLAS/TLAS construction;
ray-query effects;
the GPU path tracer;
temporal validation and ReSTIR.
The data model is RHI-neutral. Backend-specific code decides how buffers, device addresses, descriptor-heap entries, and OpenGL bindings are exposed.
Effort note — this is expected to split
Scored effort 13, which per docs/process/issue-scoring.md §4 means split it (the anchor is #435, "three rendering sub-features"). This issue defines the contract and the acceptance bar; the implementation should land as sub-issues along roughly these seams:
instance + geometry records, stable identity, dirty-range upload, profiler counters;
material records and the shader-layout parity mechanism;
the canonical light/environment record;
the first raster-path migration and the anti-duplication ratchet.
File those as children rather than attempting one PR.

Canonical records
Define compact, explicitly laid-out records along these lines:
```
struct GPUSceneInstance
{
    Matrix3x4 CurrentTransform;
    Matrix3x4 PreviousTransform;
    u32 GeometryIndex;
    u32 MaterialIndex;
    u32 InstanceId;
    u32 VisibilityMask;
    u32 Flags;
    u32 Generation;
};

struct GPUSceneGeometry
{
    ResourceHandle VertexBuffer;
    ResourceHandle IndexBuffer;
    u64 VertexAddress;   // zero/unused on backends that do not expose one
    u64 IndexAddress;
    u32 VertexFormat;
    u32 IndexType;
    u32 FirstIndex;
    u32 IndexCount;
    u32 PrimitiveBase;
    u32 Flags;
};

struct GPUSceneMaterial
{
    u32 BaseColorTexture;
    u32 NormalTexture;
    u32 ORMTexture;
    u32 EmissiveTexture;
    vec4 BaseColorFactor;
    vec4 EmissiveAndFlags;
    vec4 RoughnessMetallicAlpha;
    u32 ClosureVersion;
    // ...
};
```
The exact layout should be chosen after an alignment/cache audit, but the semantic requirements are fixed. Note these are GPU-mirror structs and therefore follow the bare-PascalCase field / Pad0 padding convention in CLAUDE.md -> Conventions, not the m_ member style.
Required properties
Stable identity
Stable instance IDs across frames while the entity/renderer instance remains the same.
Stable material IDs with a generation/version so temporal history is rejected after incompatible edits.
A primitive identity strategy for ordinary triangle meshes.
Explicit policy for virtualized/software-raster geometry, procedural geometry, terrain, foliage, particles, fluids, and skinned meshes.
Unsupported geometry must be marked — not silently omitted from RT while still contributing to raster depth/colour.
Previous-frame state
Previous transforms and deformation metadata must be produced at the same ownership boundary as current transforms. Motion vectors, temporal denoisers, TLAS updates, and ReSTIR all consume the same previous-frame truth.
Incremental updates
Dirty-range uploads for changed instances/materials.
Generation-based removal/reuse rather than stale indices.
Frame-safe resource retirement.
Deterministic extraction order or explicit stable-index allocation.
Profiling for extraction time, upload bytes, live capacity, fragmentation, and growth.
Shared light/environment records
Define a canonical light record consumable by clustered raster lighting (#435), NEE, and ReSTIR candidate generation. Preserve analytic light type/radius/shape and stable IDs. Environment/emissive distributions may be built by later issues but must have a home in this contract. docs/agent-rules/light-path-photometric-parity.md is the existing statement of why the three light evaluators must agree.
RHI integration
Vulkan resolves records through resource handles / device addresses / descriptor heap. Note full runtime-indexed bindless is still open (RHI: full bindless on Vulkan — runtime-indexed heap access in shaders (re-opens ADR 0011 amendment (50)) #805); this issue must work with the heap-backed model as it stands today and not assume RHI: full bindless on Vulkan — runtime-indexed heap access in shaders (re-opens ADR 0011 amendment (50)) #805 has landed.
OpenGL consumes the same semantic buffers through the existing facade without requiring a Vulkan-shaped API leak.
Shader layouts are generated or statically checked on both C++ and shader sides.
First integration slice
Convert one existing raster path to consume GPU Scene instance/material records with bitwise or threshold-equivalent output. Do not attempt to migrate every renderer in the first PR. Add adapter paths for legacy submission and a ratchet test preventing new direct scene-layout duplication.
Acceptance criteria
The GPU Scene is built once per view/frame and has a documented ownership/lifetime boundary.
Instance/material/geometry/light records have static layout assertions and shader-reflection parity tests.
Stable IDs survive ordinary movement and reject history after removal/reuse or incompatible material changes.
Current/previous transforms drive both raster motion vectors and the future RT consumer contract.
One raster path renders through the GPU Scene with no visual regression on OpenGL or Vulkan.
Dirty updates do not rewrite the full scene buffer for a one-instance transform or one-material edit.
Scene extraction/upload timings and memory/capacity are visible in the renderer profiler.
Unsupported RT geometry categories are exposed in diagnostics and counted.
A scene reload/backend switch cannot leave stale resource handles or generations.
CPU tests cover allocation/reuse, generation rollover, deterministic extraction, and dirty-range merging.
Explicitly out of scope
Building BLAS/TLAS or invoking ray queries.
Implementing a path tracer or ReSTIR.
Rewriting every specialized renderer in one issue.
Making OpenGL expose Vulkan device addresses.
Delivering full runtime-indexed bindless (RHI: full bindless on Vulkan — runtime-indexed heap access in shaders (re-opens ADR 0011 amendment (50)) #805).
Solving virtualized-geometry RT representation; this issue defines the policy/hook and diagnostics.
