Refactors the Game World Planner's terrain handling by extracting all heightfield generation, sampling, and manipulation logic into a dedicated terrain.ts module. This centralizes terrain operations so that all map layers (contours, rivers, settlements, roads) read and write the same heightfield, ensuring consistency across the planner.
Key Changes
New terrain.ts module: Contains all terrain-related functionality including:
PRNG and Noise2D classes (moved from procedural_tools.ts)
Heightfield generation with generateTerrain() and generateHeightfield()
Terrain sampling and analysis (sampleTerrain(), sampleSlopeDeg(), terrainStats())
Contour extraction with extractTerrainContours() and traceIsolines()
Terrain erosion with erodeTerrain() and drainage computation
River tracing with traceRiverChannels()
Grid coordinate conversion (gridToWorld(), worldToGrid())
Terrain fitting to existing spots with fitTerrainToSpots()
Updated procedural_tools.ts: Now imports terrain utilities from terrain.ts rather than duplicating them; focuses on higher-level procedural generation (settlements, roads, rivers)
Updated planner_model.ts: Imports terrain functions and adds paletteForGenre() helper for map color themes
Updated travel_calculator.ts: Imports sampleTerrain() from terrain module
Enhanced type definitions: TerrainGrid interface added to planner_types.ts with proper documentation
New test coverage: Added game_planner_terrain.test.ts with comprehensive tests for terrain operations (contours, drainage, erosion, spot fitting)
Live BDD tests: Added game_planner_live.feature and game_planner_live.rs for end-to-end testing of map tools, terrain views, and procedural generation in the real window
UI updates: Game map widget now receives heightfield data via GameMapConfig; added terrain style and label display options
Implementation Details
The terrain module uses Perlin noise (Noise2D) with fractal Brownian motion and ridged multifractal techniques for natural-looking heightfield generation. Contour extraction uses marching squares algorithm. All world-space operations are consistent through shared coordinate conversion functions. The module maintains a single TerrainGrid that all tools reference, preventing desynchronization between visual representation and procedural calculations.

Freeze (Codex, Agent tab, map inspector):
- Engine: a multiline text input ended its branch of the widget loop with `continue`, which skips
  the loop's `i += 1`, so the same text area was laid out forever and memory grew until the app
  was killed. Any addon showing a multiline field froze. Fixed in addon_engine.rs.

Tools:
- Engine: MAP_ (and HEATMAP_/CHART3D_) widget events were missing from addon_setup.js's routing,
  so no map click, selection or drag ever reached the addon. Every map tool was dead.
- Map widget: one hover target at a time (spot > path > region); a spot drag starts after a few
  pixels, reports only real moves and its end, and is one undo step; draw and measure points snap
  to nearby spots; a live ruler from the measure anchor; Space-drag pans; zoom/fit buttons; the
  overview map can be dragged.
- Planner: moved/placed spots take the ground's elevation; type pickers for new spots, paths and
  regions; Esc/Enter/Delete and tool hotkeys; a second measurement restarts the ruler; the ruler
  shows the real distance (the old label was distance x difficulty) and travel uses the climb along
  the way; quest giver/turn-in/objectives/prerequisites are editable (linking the "selected spot"
  could never work from the Story tab); Apply Accepted for agent proposals; typing in one field
  is one undo step instead of one per keystroke.

Terrain and topology:
- terrain.ts: one heightfield per world (saved with it): domain-warped fBm with ridged ranges,
  particle hydraulic erosion, fitted to authored spot elevations by scaling the local relief,
  priority-flood drainage, rivers traced from real catchments, marching-squares contours chained
  into polylines. Presets and older saves get terrain on load.
- Procedural tools all work on that one grid (they used to regenerate unrelated grids at other
  resolutions): settlements scored on slope/water/coast, roads routed with A* around steep ground
  and water, POIs on land.
- Map widget renders it: relief (hypsometric tints + hillshade, per-genre palettes), elevation
  heatmap, slope map, or flat; coastline, index/intermediate/half contours with labels; legend,
  cursor elevation/slope readout, cased roads, dashed trails, tapered rivers with flow chevrons,
  Phosphor spot icons, decluttered labels, terrain mini-map. Emoji labels (rendered as boxes)
  replaced with icons.

Tests: tests/game_planner_terrain.test.ts (17), the 37 existing planner tests, two widget unit
tests, and tests/features/game_planner_live.feature + tests/game_planner_live.rs driving the real
