This PR introduces two highly creative features to the voxelizer-rs tool:
Porosity: Introduces a --porosity <fraction> flag. When passed, the algorithm leverages a high-performance pseudo-random number generator hash based on spatial coordinates. If the hash falls below the porosity threshold, the internal solid voxel is skipped. This allows for generating structurally porous materials without needing pre-modeled voids in the source mesh.
Fiber Orientation: Introduces a --fiber <x,y> flag. This allows users to pass a global fiber orientation that is propagated to the fiber_x and fiber_y fields of the generated ParticleData. This is extremely useful for downstream applications like 3D printing simulation or advanced rendering that require fiber path awareness.
Both features have been carefully integrated into the parallel raycasting loops and all tests/benchmarks have been updated.

Preserve surface voxels when applying porosity
When --surface-only is combined with any nonzero porosity, this branch can drop voxels that intersect the mesh surface whenever their center has sdf <= 0; for example, --surface-only --porosity 1.0 on a closed cube can remove the entire inside-facing surface shell. Since surface mode is supposed to keep intersecting surface voxels and the porosity feature is described as skipping internal solid voxels, the skip should not run in the surface-only branch unless surface holes are explicitly intended.

Validate porosity before comparing the hash
Because porosity is never constrained to a finite fraction, callers can pass values outside [0, 1]; with Some(2.0) or Some(INFINITY), every interior voxel is skipped because the generated hash is always below that threshold, while negative or NaN values silently disable porosity. This can silently corrupt generated particle sets, so the CLI and library entry point should reject non-finite or out-of-range porosity values before this comparison.
