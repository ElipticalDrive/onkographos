Summary
Fixes the last two failing C++ tests, RayMarch.CreateCapsule and RayMarch.CapsuleVsTriangle. The full suite now passes.
Causes:
sdCapsuleCapsule used an approximation. It implemented the endpoint shortcut from the WickedEngine article, which isn't a true segment-to-segment distance and gave wrong results for skewed 3D capsules (0.956 where the true value is −0.104).
CapsuleTriangleIntersect had two bugs. Its outside flag was inverted, so a capsule that missed the triangle counted as a hit. It was also a swept-sphere test that rejected u < 0, so a capsule already touching the triangle at its starting end counted as a miss.
Three test expectations were wrong. One had been copied from the code's wrong output, one reused that number for different capsules, and one expected a hit where there's a 0.114 gap against a 0.1 radius.
Fix:
Adds exact helpers for the closest points between two segments and the closest point on a triangle (Ericson, Real-Time Collision Detection, §5.1.9 and §5.1.5).
sdCapsuleCapsule now returns the segment-to-segment distance minus both radii.
CapsuleTriangleIntersect keeps its signature and now checks whether the capsule touches the triangle: it reports a hit when the closest distance between the axis segment and the triangle is at most the radius. *ptrdistance is now a signed surface distance.
Removes three helper functions that only the old code used.
Corrects the 3 test expectations to values computed independently with exact formulas.
Only the tests call these two functions, so rendering is unaffected.
Testing
I computed the expected values independently in Python before changing the C++. The corrected tests failed against the old code in exactly the predicted cases and pass with the rewrite.
raytrace --test-matrix: 93 tests pass, 0 fail, 161 are disabled. The build has no warnings.
