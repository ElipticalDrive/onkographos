Summary
In the Move tool with a photo selected, Shift+drag now rotates the photo around the line from camera origin through its center, instead of moving it. Useful for off-level photos where the horizon needs to be straightened before alignment.
Implementation
Pose and OverlayUserData gain a photoRoll (radians, CCW positive), input-only through the solver (not observable from azimuth-only residuals).
placeAt(o, dir, roll = 0) calls o.rotateZ(roll) after lookAt(0,0,0). moveSelectedTo and restoreOverlay re-apply the stored roll so move-drags and reloads don't reset it.
OverlayManager.setSelectedRoll(roll) with an early-return when roll is unchanged (avoids a no-op notify() → solver re-run during slow-drag pauses).
solver.ts:projectPOI rotates the local X/Y basis around localZ by photoRoll before sampling the POI's UV, so a rolled overlay's POIs project to the same world rays the renderer draws.
New 'rotate' ModeState in input.ts. Pointerdown on a body with shiftKey → captures projected center + start angle + start roll. Pointermove → Math.atan2 around center, writes startRoll - deltaAngle (sign chosen so a CW pointer drag rolls the photo CW visually).
POI map-view bearings update automatically — azFromLocal reads matrixWorld, so rotation is included.
OverlaySnapshot.photoRoll?: number for back-compat; old snapshots load with roll = 0.

Adds an in-plane "roll" rotation to a photo overlay around the line
from camera origin through the photo's center. Useful for photos
taken handheld or off-level, where the horizon needs straightening
before the photo lines up with the panorama grid.

Pose gains a `photoRoll` (radians, CCW positive) that round-trips
through every pose-handling site:
- overlay.ts: placeAt(o, dir, roll = 0) calls o.rotateZ(roll) after
  the existing lookAt(0,0,0). New OverlayManager.setSelectedRoll(roll)
  with an early-return when the value is unchanged so a stalled
  rotate-drag doesn't re-fire the solver. moveSelectedTo and
  restoreOverlay re-apply the stored roll so move-drags / reloads
  don't reset it. extractPose / applyPose plumb it through.
- solver.ts: projectPOI rotates the local X/Y basis around localZ by
  photoRoll before sampling the POI's UV — so a rolled overlay's
  POIs project to the same world rays the renderer is drawing. Roll
  is input-only; the solver doesn't try to fit it (not observable
  from azimuth-only residuals).
- input.ts: new 'rotate' ModeState. Pointerdown on a photo body in
  the Move tool with e.shiftKey starts a rotate drag instead of a
  move; pointermove computes Math.atan2 around the projected center
  and writes startRoll - deltaAngle (sign accounts for screen-Y-down
  + the heightfield back-face geometry so a CW pointer drag rolls
  the photo CW visually).
- persistence.ts: optional photoRoll field on OverlaySnapshot for
  back-compat; missing → 0.

POI map-view bearings update automatically through azFromLocal's
matrixWorld read — rotation is part of the overlay group's
transform, so getPOIs picks it up without explicit recomputation.
