Purpose and Scope
This page covers the sphere tracing tutorials implemented in tutorials 043, 044, and 045. These tutorials demonstrate how to render geometry entirely inside a fragment shader using Signed Distance Functions (SDFs) and iterative ray marching, without relying on traditional mesh rasterization. The progression goes from a flat-color unlit result, to diffuse lighting, to correct depth buffer integration.
For ray-marched soft shadows in 2D, see 2D SDF Shadows. For SDF space manipulation and combining primitives, see SDF Space Manipulation.
What Is Sphere Tracing?
In standard rasterization, geometry is defined by triangles. Sphere tracing instead defines geometry by a Signed Distance Function (SDF) — a function scene(pos) that returns the signed distance from a point in space to the nearest surface. The sign indicates whether the point is inside (negative) or outside (positive) the surface.
A ray is cast from the camera through each pixel. At each step, the ray advances by the distance returned by scene(). This is safe because scene() guarantees no surface lies closer than that distance. When the returned distance falls below a threshold (THICKNESS), the ray is considered to have hit a surface.

Vertex Shader Setup
The proxy mesh (a cube or sphere GameObject) serves only as a bounding volume. The vertex shader computes two interpolated values passed to the fragment shader:
localPosition: the mesh vertex position in object space — used as the ray origin.
viewDirection: the vector from the camera (transformed to object space) to the vertex — used as the ray direction (normalized in the fragment shader).
The camera position is transformed to object space via mul(unity_WorldToObject, float4(_WorldSpaceCameraPos, 1)).
Sources: Assets/043_SphereTracingBasics/SphereTracingBasics.shader38-49
The SDF: scene()
All three shaders implement an identical scene() function:
```
float scene(float3 pos){
    return length(pos) - 0.5;
}
```
This is the SDF for a unit sphere of radius 0.5 centered at the object origin. It returns the distance from pos to the sphere's surface.

Tutorial 043 — Sphere Tracing Basics
File: Assets/043_SphereTracingBasics/SphereTracingBasics.shader
The simplest form. The fragment shader runs the march loop and returns _Color on hit, or calls discard if no surface is found within MAX_STEPS.
The shader is tagged Queue=Geometry and batching is disabled (DisableBatching=True). Batching must be disabled because the vertex shader relies on per-object unity_WorldToObject, which is unavailable after batching merges objects.
Sources: Assets/043_SphereTracingBasics/SphereTracingBasics.shader7-83
Tutorial 044 — Sphere Tracing with Shading
File: Assets/044_SphereTracingShading/SphereTracingShading.shader
Adds diffuse lighting to the hit surface. Three new functions are introduced:
normal(float3 pos)
Estimates the surface normal at pos using central finite differences. For each axis, it samples scene() at pos ± NORMAL_EPSILON and computes the gradient:
changeX = scene(pos + (ε,0,0)) - scene(pos - (ε,0,0))
changeY and changeZ computed similarly.
The resulting gradient vector is then transformed from object space to world space via mul(unity_ObjectToWorld, ...) and normalized.
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader63-73
lightColor(float3 position)
Computes a simple Lambertian (N·L) light contribution using Unity's built-in _WorldSpaceLightPos0 and _LightColor0:
```
float lightAngle = saturate(dot(surfaceNormal, lightDirection));
return lightAngle * _LightColor0;
```
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader75-83
material(float3 position)
Combines the base _Color property with the computed lightColor:
```
float4 color = _Color * light;
```
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader85-93
Render Queue Note
This shader uses Queue=Transparent and ZWrite Off. This means sphere-traced objects in tutorial 044 do not write to the depth buffer and will not correctly occlude rasterized geometry behind them. This limitation is addressed in tutorial 045.
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader8-12
Tutorial 045 — Sphere Tracing with Depth Buffer Output
File: Assets/045_SphereTracingDepth/SphereTracingDepth.shader
Extends tutorial 044 to write a correct depth value to SV_Depth. This allows ray-marched surfaces to participate in the depth buffer, so they properly occlude other rasterized geometry.
Depth Calculation
The fragment function signature changes to output two values:
```
void frag(v2f i, out fixed4 color : SV_TARGET, out float depth : SV_Depth)
```
Once a surface hit is found at samplePoint (in object space), the depth value is computed by converting the hit point to clip space:
```
float4 tracedClipPos = UnityObjectToClipPos(float4(samplePoint, 1.0));
depth = tracedClipPos.z / tracedClipPos.w;
```
This produces the normalized device coordinate depth that the hardware depth buffer expects.
Sources: Assets/045_SphereTracingDepth/SphereTracingDepth.shader91-122
Loop Restructure
Unlike tutorials 043 and 044, the fragment function uses a bool hitsurface flag and a break to exit the loop early, keeping samplePoint available after the loop for both color and depth computation.
Sources: Assets/045_SphereTracingDepth/SphereTracingDepth.shader98-115
Render Queue
This shader uses Queue=Geometry+1, placing it just after standard opaque geometry. It also includes IgnoreProjector=True. ZWrite is on by default (no explicit ZWrite Off), which enables depth writes.

Relationship to Other SDF Systems
The sphere tracing shaders in tutorials 043–045 use only the most basic SDF primitive (a sphere: length(pos) - 0.5). The broader SDF ecosystem in this codebase includes:
SDF Space Manipulation: Advanced 2D and 3D SDF operations — mirror, repeat, rotate, combine. These can be applied to extend the scene() function.
2D SDF Shadows: Ray-marched soft shadows in a 2D context using a similar march-loop pattern.
Scene Setup Notes
All sphere tracing shaders require "DisableBatching"="True" in their SubShader tags. The proxy mesh geometry (visible in the Unity scenes) is a standard Unity cube or sphere used only as a bounding hull; the actual rendered shape is computed entirely by the SDF inside scene(). The size and position of the rendered SDF shape follows the GameObject's transform because all math is performed in local/object space.
