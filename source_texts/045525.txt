Problem and existing work
Matterweave already shares whole detail prototypes, isolates instance edits and uses shared chunk snapshots. Investigate additional within-volume sharing rather than claiming prototype sharing is missing.
Scope
Compare existing chunk/prototype storage with a bounded sparse DAG candidate on repetitive structures, irregular wetland foliage and heavily edited volumes.
Measure finer-grained copy-on-write against current instance edit behavior: untouched instances must remain unchanged.
Include material entropy, construction peak memory, query time, edit latency, retained history, reclamation/compaction and serialization costs.
Inspect viable Rust implementations before custom work; compare a narrow foreign adapter where justified under ADR-0014/0015. Pin any adopted source and record licenses.
Reference: Cubiquity storage. Its compression claims are hypotheses for our workloads.
Completion criteria
Exact voxel/material queries and persistence round trips; negative coordinates and isolated edits tested.
Memory includes all tables, materials, transient construction and edit growth; no file-size-only win.
Record whether savings enable useful visible detail, and an adopt/adapt/reject/defer decision; Android costs required for mobile performance claims.
Mapping: M2, ADR-0005/0007; bounded research after current technical gaps, not a world-format rewrite commitment.
Delivery and evidence
Reconciled against main fc6212e02009ced613009fece1386c7b5ddff9aa on 2026-09-13. Extend existing systems; reconcile the live board before implementation. This issue assigns no worker and does not replace the completion plan. Technical implementation/functional acceptance precede Phase B cost ranking and sustained thermal measurements.
Preserve authoritative voxel/material/collision semantics, bounded memory and stale-job rejection. Record source SHA, fixture/seed, commands, quality settings and actual device/OS/driver for results; mark unrun gates explicitly. Store durable findings in repository performance docs and update affected ADRs/STATUS/ROADMAP with the implementation delivery. An experiment may close with an evidenced adopt/adapt/reject/defer conclusion; no speedup is assumed.
