Owner
Adds a WallVolume setting (Esc menu line "Walls", --walls / ?walls=) that draws objects standing up in an oblique view, for the text renderer and so for the web build:
flat: as before (default, so nothing changes unless you pick a mode).
stacked: each standing object's glyph extruded straight up the screen, darker toward the floor.
leaning: the same, leaning up and to the right (a cavalier oblique view), so walls running up the screen show a side too.
Which objects stand, and how tall
Height is renderer-neutral model data, not tied to walls:
Stature(f32) component: how tall one object stands, in cells.
Otherwise its glyph's height in GlyphStatures, loaded from assets/rules/statures.txt (one line per height, followed by the glyphs that stand that tall). By default the wall shapes are 0.625 cells and a closed door + is 0.5.
Anything else lies flat. Heights go up to 4 cells.
How it works
Two GPU passes, in src/rendering/volume.rs and wall_volume.wgsl:
Wall map. A second camera draws every standing object's glyph as one sprite into a frame-sized texture at 8 texels per cell. Each sprite is drawn at its animated position (so walls that slide, rise or sink keep their volume), in its lit colour, with its height as alpha. The glyphs come from the cell font, rasterized without antialiasing by swash, which Bevy's text already uses.
Extrusion. One full-screen 2D material walks each pixel down from the tallest object in the frame to the floor, a screen pixel at a time, and draws the first one whose ink is that tall. That is the nearest one, so no sorting is needed. Each pixel's ray is a straight line in map space, so a step is one vector add. The map is sampled in map space, so objects turn with the view smoothly and have no seams at any zoom or angle.
The shader also writes a per-pixel depth matching the sprites' new draw order (nearer rows over farther ones). So actors behind a wall are hidden by it, and the floor stays under the walls.
Try it
Preview: https://suilevap.github.io/gridvail/pr/51/?walls=stacked&reveal
Zoom in with X, and turn with Q/E to watch the walls turn.
Switch modes in the Esc menu ("Walls").
Leaning: https://suilevap.github.io/gridvail/pr/51/?walls=leaning&reveal
Sliding walls: https://suilevap.github.io/gridvail/pr/51/?map=rooms&walls=leaning&reveal — step right onto the pressure plate.
I haven't run this in a browser yet. The web build compiles, and WebGL2 supports the per-pixel depth the shader writes. Worth checking on a phone for speed.
Performance
The shader runs for every pixel on screen, so its cost is the screen size times the steps per pixel. There is one step per screen pixel of the tallest object's height: about 10 at zoom 1 and 20 at zoom 2 for 0.625-cell walls. That is roughly 16 million cheap steps per frame at 1100×700 and 2× zoom. On the software renderer used for screenshots it adds about 39 ms per frame. On a real GPU it should take about a millisecond, a few on a weak phone; that is an estimate, not a measurement. If phones struggle, a small "tallest thing per cell" texture would let most pixels stop after 2–3 checks.
Known limits
Extruded actor glyphs (@, enemies) read as solid blobs. Upright billboards would suit actors better; walls and other blocks extrude well.
Mid-turn, the edges of the wall pixels are jagged; the shader samples them without smoothing.
A standing object's hop (lift) is not shown.
The player can disappear behind a wall in front of them.
Checks
cargo test --workspace (281 tests), clippy (native and wasm32 web profile) and cargo fmt --check pass. main is merged in, including the intro, which runs with every wall mode.
