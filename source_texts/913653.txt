Summary
New CadPointCloud entity (REQ-171/ADR-042), wired through the full entity lifecycle (select/erase/undo/extents/layer-visibility/DXF-DWG exclusion log/.gs persistence).
In-tree octree builder/query (pointcloudoctree) — pure Domain code, no file IO/GL.
E57 reader (libE57Format, vendored with Xerces-C) — bounded-memory streaming import (StreamE57File), never throws at the boundary.
.gscloud out-of-core sidecar cache (ADR-060) — a multi-GB scan no longer has to fit in memory; reopening reuses a matching cache instead of re-indexing.
Background import (POINTCLOUDATTACH / IMPORTE57) with a progress-bar modal (phase, ETA, cancel).
Camera-relative LOD rendering: pages full leaves from the .gscloud cache near the camera on top of a flat global preview, iterated through several real-file bug reports against a 7.8GB scan:
a per-leaf point budget that undercovered the viewport as the user zoomed in → fixed by budgeting on point count, not leaf count
an isotropic sphere query around the orbit pivot that preferred whatever sat at the pivot's depth over the near-facing surface → replaced with SelectLodLeavesInCylinder (lateral-only radius, unbounded depth, nearest-to-the-eye ordering)
a per-leaf full/nothing cutoff that looked like a shaded solid with blocky cliffs → replaced with uniform stride decimation shared across every leaf in view
per-frame reselection causing lag and a duplicate/offset-geometry glitch during orbit → fixed with movement + wall-clock hysteresis on reselection, and baking leaf vertices against the same sticky anchor the preview uses
Also fixed along the way: a real isLeaf() octree bug (an interior node whose first octant was empty was misclassified as an empty leaf, silently dropping points).
Full implementation log: workshop/tasks/TASK-270-issue-pointcloud-e57-octree.md.

… LOD rendering (REQ-171/172)

Delivers the point-cloud epic's increment 1 (TASK-270): a new CadPointCloud
entity wired everywhere CadMesh is (select/erase/undo/extents/layer-visibility/
DXF-DWG-exclusion-log/.gs persistence), an in-tree octree builder/query, an
E57 reader (libE57Format, vendored) with bounded-memory streaming import, and
an ADR-060 .gscloud out-of-core sidecar cache so a multi-GB scan no longer
needs to fit in memory.

Rendering iterated through several real-file bug reports against a 7.8GB E57:
- flat preview -> out-of-core LOD leaf paging near the camera
- a per-leaf point-count budget that undercovered a dense viewport as the
  user zoomed in (fixed: budget by point count, not leaf count)
- an isotropic sphere search around the orbit pivot that preferred whatever
  sat at the pivot's depth over the near-facing surface (fixed: a cylinder
  query, SelectLodLeavesInCylinder, bounding only lateral/on-screen extent
  and ordering leaves nearest-to-the-eye first)
- a per-leaf full/nothing density cutoff that looked like a shaded solid with
  blocky cliffs (fixed: uniform stride decimation shared by every leaf in
  view, targeting a deliberately sparse point count)
- per-frame reselection causing lag and a duplicate/offset-geometry glitch
  during orbit (fixed: movement + wall-clock hysteresis on reselection, and
  baking leaf vertices against the same sticky anchor the preview uses)

Background import with a progress UI (POINTCLOUDATTACH / IMPORTE57), and a
real isLeaf() octree bug (an interior node with an empty first octant was
misclassified as an empty leaf) are fixed along the way.

Full suite green: GoSurveyTests 1194 cases / 8,954,034 assertions,
GoSurveySnapTests 327 cases / 3,040 assertions.
