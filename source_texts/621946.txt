What problem are you trying to solve?
Closes #2120.
RegisteredGLBuffer(..., device="cpu") can register an OpenGL buffer with an ambient CUDA context and then wrap the mapped CUDA pointer as a CPU array. A CPU kernel reading that array can access device memory as host memory. A safe probe demonstrates the incorrect registration without dereferencing the pointer; an earlier separate CPU renderer run terminated with SIGSEGV.
I encountered this during an independent CPU/OpenGL correctness investigation while validating configurable primitive resolution. I do not have downstream application or production impact to report, and no maintainer assignment or approval is claimed.
What does this change?
Attempt CUDA/OpenGL registration only for CUDA devices. CPU devices always use the copy path.
Share ordinary host storage with the CPU OpenGL transfer buffer, avoiding pinned staging and redundant host copies.
Report an explicit RuntimeError when CPU copy fallback is disabled.
Preserve CUDA native interoperability, its pinned copy fallback and the three access-flag behaviors.
Add buffer-device regression tests to the existing renderer module and default/debug suites, move constructor documentation into the class docstring and add 2120.fixed.md.
No public parameters or native code change. This patch does not include the geometry-resolution feature in #1110 or expand the public get_pixels() contract.
Related independent work: the #1110 geometry-resolution prototype has a proposed PR body and a source-specific validation report, including filled/minimum-resolution drawing and independent Slurm measurements at cb86abb7. CPU-buffer validation for this PR remains associated with 8be105eb and d619a625 below.
