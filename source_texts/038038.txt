Summary
Implements Wronski/Frostbite-style frustum-aligned volumetric fog (froxels) that composites over the path-traced radiance and feeds DLSS-RR, giving Minecraft-RTX-like atmospheric fog and dynamic sun/moon god rays / light shafts.
The volume is a frustum-aligned grid: XY is a screen tile footprint and Z is an exponential depth distribution. Lighting work is done once per froxel (amortized ray-queried occlusion) instead of per-pixel per step, which is the spatial-accumulation savings a froxel grid exists to deliver; per-pixel fog cost collapses to a fixed march in the integrate pass.
Files
shaders/pipelines/froxel/froxel_common.slang — FroxelPush ABI (near/far, tile size, slices, density/phase/albedo, device addresses, packed dims), frustum-ray reconstruction identical to world.primary.rgen, exponential slice distribution, smooth value-noise fog field, normalized Henyey-Greenstein phase.
shaders/pipelines/froxel/lighting.comp.slang — one thread per froxel fills the volume (rgb = in-scatter, w = extinction). Samples the fog density, casts 4 jittered ray-query occlusion rays toward the dominant sun/moon derived from the same sky module + transmittance LUT the path tracer uses (so fog, terrain light and the drawn disc can't disagree). Submerged cameras get an 8× density boost for underwater murk. Only froxels with non-negligible density cast shadow rays.
shaders/pipelines/froxel/integrate.comp.slang — one thread per pixel; reconstructs the view ray + surface distance from the reversed-Z guide depth, marches the froxel column with the exact constant-extinction integral, emits fogInScatter + transmittance * surfaceRadiance. 1:1 copy when disabled so the frame graph always has a valid image.
RtFroxel.java — two compute pipelines (lighting: set0=TLAS/set1=LUT; integrate: set1 storage images), a 4-slot TLAS descriptor ring mirroring the existing AccelStructureSet pattern, resize-aware volume/history buffers, per-frame push constants, and a temporal EMA gated on a still camera (with a historyReady guard so the first frame / post-resize never reads uninitialized device memory).
RtComposite.java — creates RtFroxel lazily, allocates a render-res foggedOutput, records lighting → integrate after the trace, and feeds the fogged image to DLSS-RR (or the fallback blit) via a rrSceneImage() helper.
CausticaConfig.Rt.Froxel — tunable density, height falloff, phase-g, scatter albedo, noise intensity/scale, intensity, temporal blend, tile size, depth slices, far.
layout_probe.slang + GenerateShaderRecords.groovy — probe/register FroxelPushData codegen.
Notes / caveats
No local toolchain was available (java/gradle/slangc all absent), so nothing was compiled or SPIR-V validated. All code is correctness-by-inspection against the existing RtSkyLut, RtOverlayPipelines, and world shader ABI. When you next build, the two most likely things to confirm are:
RayQuery in a compute stage compiles (the repo currently only uses it in a fragment shader — block_outline). If not, the fix is localized (drop RAY_FLAG_FORCE_OPAQUE or route occlusion through the existing shadow SBT).
Slang's reflected push-constant size for FroxelPush stays within maxPushConstantsSize.
The occlusion ray uses RAY_FLAG_FORCE_OPAQUE (matching block_outline): god rays appear through canopy gaps and around solid geometry. Cutout-foliage/window transmission via the shadow any-hit SBT is a follow-up refinement.
Temporal accumulation reduces flicker/stabilizes a still view; per-frame SHADOW_SAMPLES reduction relying on history is a possible next optimization.
Verification
Default config: ENABLED=true, TILE_SIZE=8, DEPTH_SLICES=48, FAR=192, DENSITY=0.02, HEIGHT_FALLOFF=0.06, PHASE_G=0.60, SCATTER_ALBEDO=0.95, NOISE_INTENSITY=0.15, NOISE_SCALE=6.0, INTENSITY=1.0, TEMPORAL=true, TEMPORAL_BLEND=0.80.
