I am trying to replicate the optical flow calculation (induce flow function) but in Instant-NGP tl. In this repo they aren't converting to NDC nor contract. They are just using the ray in the world coordinates. given that I did the following steps:
Take sampled points along each ray calculated by the ray marcher.
Take the weights calcuated for each point along the ray by the volume rendrer
The Sampled points are calculated in the world coordinates so They are first transformed to screen space using the current frame's pose
Multiply the weights by the sampled points and sum all the points along each ray
Calculate acc_map = sum(weights). The acc_map summs all the weights along each ray (i am still confused about this step if you can elaborate more because if we have used all the sampled points why do we still need weighted rays)
Multiply (1 - acc_map) * (rays_o + rays_d) where rays_o are the ray origins and rays_d are directions
sum the weighted points with the weighted rays
let's call the current frame i and the frame after it i+1 so I take the pose of frame i+1 and convert the result of the sum to the world space
using the inverse pose of frame i+1 I convert back to the camera space
using the intrinsics matrix I calculate the pixel position
But this is still not working so I have the following question:
Why do we need to multiply the sampled points with the weights only in the camera space or NDC
If we calculate the weighted points in the camera space what can we do after that to get the optical flow using the pose of the neighbouring image.
