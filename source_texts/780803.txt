Carry the matrix/symbolic-planning rule from walnut-burgundy/computer-science#54 into the RISC-V follower backend.
Do not receive high-dimensional alignment already frozen as a Givens chain, a Householder implementation, or a particular control-flow schedule. Keep the semantic transform and required invariants visible long enough to compare Householder reflectors, products of reflections/proper rotations, Givens plane rotations, direct data-plane rotations, and structured/sparse/blocked variants supported by the actual workload.
Related:
Choose high-dimensional transform algorithms from evidence, including branch behavior walnut-burgundy/computer-science#53 — evidence-based transform selection;
Use symbolic matrix structure before choosing wide-machine lowering idric-big-iron#13 — wide-machine companion;
Plan matrix transforms mathematically before Thumb branch/register lowering idric-arm-thumb#37 — small-CPU/branch companion;
Preserve matrix/orthogonal-transform semantics before shader lowering idris-shader-backend#32 — GPU companion;
Survey existing CAS before reimplementing Coxeter/reflection-group machinery walnut-burgundy/coxeter#1 and Add an RV32I parity lane before claiming generic RISC-V #5 — reflection/group/CAS prior-art rule.
Numerical-linear-algebra reference: Trefethen & Bau, Numerical Linear Algebra: https://people.maths.ox.ac.uk/trefethen/text.html
Before choosing RV64I/vector instructions, ask whether symbolic/group/matrix facts can precompute the plan, eliminate candidate algorithms, or turn data-dependent decisions into a fixed replayable schedule. Do not assume sparsity, density, batch reuse, or future vector-extension availability.
Once a numerical algorithm is selected, retain exact semantic/numerical oracles and inspect branch count, dependency depth, loads/stores, register pressure/spills, code size, optional vector realization only when the target actually exposes it, and real execution evidence. RISC-V should be free to make a different target choice from x86/A64, ARM/Thumb, or GPUs while preserving the same high-level semantics.
