Edit: I almost forgot to mention - when I place NEW blocks they render, but nothing triggers the originals to render (I have a button assigned to recalculate/redraw for every block surrounding (and including) the currently moused-over one).
I've got a voxel engine that I've been working on for some time, and while developing core features I wasn't too concerned with performance yet. Everything runs pretty quick, but it was eating memory, so one of the obvious things I could do was change my block from a class to a struct (post-changes code below). The most annoying thing was the lack of null comparisons, as I'd used those all over, so I created an "Air" type and used that instead. However, when I was all done making the changes, all blocks were invisible - mousing over them still shows the name/health of the block, I can still jump on them and watch my coordinates change, but they do not render. If I literally just change the single word "struct" to "class" with no other modifications the blocks render properly again. My guess is something in my block struct isn't valid for use with a struct even though it doesn't generate syntax errors? I'm really not sure where the issue lies here, as I've never used structs for mass data storage like this before (in-memory or on-disk sequential mapping, on the other hand, a lot). If you need to see other code, let me know, but I'd suspect the issue is here or else is a fundamental/conceptual thing that seeing the code won't help find..

Well as you can see in the class, a model is generated (with appropriate face-culls and quad-flips taken into consideration) when a function is called, and this function is called for every visible block in a chunk when the chunk is visually rebuilt. This is then cached and not rebuilt until necessary (when things change). \$\begingroup\$
Changes when it was structs were not propagating because things were passed by value rather than reference. This meant that the face culling wasn't applying, and all blocks had all faces culled unless they were freshly-placed.
I opted to stick with classes for now, but that was the issue.

I wonder why you have decided to use the structure instead of a class? Personally, I abandoned structures in the first place, because it is possible for a class to get a reference to the block and change it without overwriting the entire struct, and secondly, the unit is not subject to the requirements for the structure. Do not take criticism, I wonder whether it will give a boost in performance.

I prefer classes functionally, but from what I've read a struct has a much lower memory overhead and access time - a class goes through another pointer (incurring up to 8 bytes waste on a 64-bit system per instance) whereas a struct is more direct. 8 bytes may sound insignificant, but in a block engine that means tens of thousands times that 8 byte waste and it adds up. Perhaps I've been mislead, though, as if I have to pass by ref then it sounds like the benefit might not be there.
