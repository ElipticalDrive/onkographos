Summary
calculateDepthOfField computed near/far limits as Hs/(H ± (s − f)) with H = f²/(Nc) + f. That is an approximation. It misplaces both limits, and when the lens is focused at the reported hyperfocal distance it returns a finite far limit (about 2.19 km in the issue's example) instead of infinity. This PR switches to the exact thin-lens limits. The far limit is now null (infinite) when s ≥ H.
src/optics/depth-of-field.ts: exact near/far expressions. H − f = f²/(Nc) is computed directly, so no cancellation. The infinity test also compares focusDistanceM with the reported hyperfocalDistanceM in metres, so a caller who passes back the returned hyperfocal distance always gets farLimitM: null, whatever the mm/m rounding. The model provenance version goes from thin-lens-depth-of-field 1.0.0 to 1.1.0, because the numbers it outputs change.
docs/PHYSICS_FOUNDATION.md: documents the equations, the derivation condition and the model change. docs/api/optics-depth-of-field.md is regenerated.
Science
Thin lens with focal length f, f-number N, focus distance s and subject distance d, all measured from the lens. With image distance v(x) = fx/(x − f) and aperture diameter A = f/N, the geometric blur diameter on the sensor (at v(s)) from a subject at d is
c(d) = A·|v(d) − v(s)| / v(d) = f²|s − d| / (N·d·(s − f))
which is exactly what the engine's calculateDefocusCircle evaluates. Set c(d) = c and write H − f = f²/(Nc):
Near limit (d < s): c·N·d·(s − f) = f²(s − d), so d = f²s / (f² + Nc(s − f)) = s(H − f)/(H + s − 2f)
Far limit (d > s): d(f² − Nc(s − f)) = f²s, so d = s(H − f)/(H − s). The denominator is ≤ 0 when s ≥ H. In that case the blur stays below c out to infinity, because lim d→∞ c(d) = f²/(N(s − f)) ≤ c. So the far limit is infinite.
At s = H the near limit is H/2.
Reference: Sidney F. Ray, Applied Photographic Optics (3rd ed., Focal Press, 2002), depth-of-field and hyperfocal-distance chapter. This is the standard thin-lens depth-of-field derivation. The model is still geometric only: no diffraction, aberrations, pupil magnification, focus breathing or macro effects.
Behaviour change
DOF numbers change for every input (public calculateDepthOfField and the composed simulatePocCamera().depthOfField). hyperfocalDistanceM does not change. Examples:

Near (old → new)
Far (old → new)

The near limit gets slightly closer, the far limit gets farther, and the far limit becomes infinite from H onward rather than from H + f. No API or schema shape changes.
Validation

New property test: over a grid of f ∈ {8, 24, 50, 135, 400} mm, N ∈ {1.4, 2.8, 8, 22}, c ∈ {0.005, 0.015, 0.03, 0.06} mm and s from 0.2% to 99.9% of H (more than 300 cases), calculateDefocusCircle at both returned limits equals c within a relative 1e-9.
New hyperfocal test: farLimitM/totalDepthOfFieldM are null at s = H, H + 25 mm and 3H. The near limit is H/2 at s = H, and the defocus circle of a subject at 10¹² m is c at s = H.
test/fixtures/basic-reference-scene.json: the near/far/total values are updated to the exact rationals (6250000/1547 mm, 6250000/953 mm).

It also asserts that the response's depthOfField equals the current calculateDepthOfField.
