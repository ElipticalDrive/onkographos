The tests op_neg_half and op_spec_constant_half_simple were generating/using fp16 denormal values and validating results via exact bitwise comparison without considering whether the device supports CL_FP_DENORM.
Devices that legally flush fp16 denormals to zero can therefore fail these tests despite being conformant.
The patch fixes this by:
Replacing raw integer-to-cl_half bit pattern generation with proper fp16 conversion using cl_half_from_float().
Updating the half spec constant test to use valid half-precision encoded values (1.0, 2.0, 3.0) instead of relying on integer literals and generic operators.
This avoids unintended denormal inputs and makes the tests behave correctly on devices that do not advertise CL_FP_DENORM support.
