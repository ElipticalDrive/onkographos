Description
Summary
When using Flywheel instancing backend and viewing a scene with many Create rails (Steam 'n' Rails), the game experiences severe frame drops even with shaders disabled. Switching to the indirect backend immediately restores smooth performance. In my test, indirect reached over 1000 FPS on an RTX 3050 Laptop, while instancing caused visible stuttering and very low framerates in the same scene.
This issue is not GPU performance related (the hardware is capable of >1000 FPS with indirect), nor is it a server TPS issue. The root cause is that each Create rail block is split into at least 3 independent geometry layers under Flywheel, breaking instancing batching and causing massive draw call overhead.
Steps to Reproduce
Create a superflat world and place a significant number of Create standard rails (e.g., 50–100 blocks) – shaders are not required.
Run /flywheel backend flywheel:instancing (default).
Look at the rails and observe the frame rate drop heavily.
Run /flywheel backend flywheel:indirect.
Observe the frame rate recover instantly to smooth values (over 1000 FPS in my test).

Root Cause Analysis (Debug Visualization)
With /flywheel debug shader model_id, each unique model_id appears in a different color. The video shows:
Each rail block has multiple colored regions, proving multiple model_ids per block.
Clicking a rail once generates a thick 3‑block‑wide colored model covering the hitbox. Clicking again generates three separate 1×1 thin colored models filling the bottom.
This confirms that each rail block is decomposed into at least 3 separate geometry layers (sleepers, rail surface, support). Since they are distinct meshes, Flywheel cannot batch them, resulting in linear growth of draw calls with rail count.
Consequence: CPU rendering thread becomes the bottleneck, GPU waits idle → high GPU usage percentage but low effective throughput.
Additional Context
Server TPS healthy: Spark profile shows Server Thread usage ~6%, 83% parkNanos idle.
No duplicate found in this repo's Issues.
Not caused by Copycats – happens with vanilla Create rails + Steam 'n' Rails alone.
Shaders are NOT involved – the issue reproduces with shaders completely disabled.

I think the issue may be Cased Tracks rendering not using Create's instancing, specifically: not passing in the same SimpleModel, instead constructing a new one every time, so Flywheel doesn't know its the same and can't use instancing for it. Indirect uses different mechanisms and so isn't affected.
The 3 geometry layers thing may be a red herring.
My naive patch for this just adds a cache for the Cased Tracks SimpleModels, feel free to take this but double check and take with a grain of salt :) zerastos@c054a9c
