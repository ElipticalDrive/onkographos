Motivation and Context
Recent models such as Qwen3.5-35B-A3B are available in community GGUF distributions with packed quantized weights, including Q8_0 and K-quants. DequantizePacked lets an ONNX importer retain these compact payloads as UINT8 initializers, including external data, and express their decoding in the graph instead of expanding the weights during export.
The proposed opset-29 interface is:
```
y = DequantizePacked<format, shape, output_dtype=FLOAT>(x)
```
x is a rank-one UINT8 tensor containing one packed tensor payload with canonical little-endian fields.
format selects a fixed ONNX decoding definition, such as "gguf:q4_0", "gguf:q2_0", or "gguf:iq2_xxs". Importers map GGML tensor type IDs to these identifiers.
shape specifies static logical dimensions in ONNX order. The last dimension is block-aligned, and the payload size follows from the format and shape.
output_dtype defaults to FLOAT and also supports FLOAT16, BFLOAT16, and DOUBLE. Decoding uses FLOAT arithmetic followed by one output conversion.
The initial set defines 27 quantized formats across conventional GGML, K-quant, IQ, ternary, MXFP4, and NVFP4 encodings. Plain floating-point and integer tensors use their existing ONNX types. These attributes provide output type and shape inference directly from tensor metadata.
The in-tree decoding specification defines byte layouts, scale conversions, bit-plane ordering, arithmetic, and complete IQ codebooks. Definitions are based on GGML revision da8e2a54, quantization version 2. GGUF descriptor dimensions are reversed into ONNX order while preserving flattened values; file parsing and model-specific weight permutations remain importer steps.
The implementation adds the schema, type/shape inference, NumPy reference decoding, and operator documentation. Decoding is self-contained, and the incorporated GGML tables and algorithms retain their upstream MIT notices.

@gramalingam I (with the help of AI) considered parameterized format names for affine/groupwise quantization and microscaling, but they do not seem necessary for this proposal right now.
The proposed Pack/Unpack operators in #8576 cover generic bit packing. Existing DequantizeLinear and other standard operators can express dequantization with separate scales and zero points, including MatMulNBits-style weights. Floating-point zero points or irregular group selection can be represented with Cast/Sub/Mul/Gather as needed, followed by MatMul and optional Add. This does not require defining a MatMulNBits-specific packing here or adding metadata inputs to DequantizePacked.
So this proposal remains unchanged: one UINT8 payload input, the existing format/shape/output_dtype attributes, and all 27 fixed GGUF encodings with their self-contained decoding specifications. We are not adding the parameterized affine/scaled profiles discussed as an alternative. Parameterized identifiers can be revisited when there is a concrete family of self-contained encodings that needs them; they are not needed for the formats currently proposed.
