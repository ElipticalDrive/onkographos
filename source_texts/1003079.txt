Summary
The ported terrain, biome and surface stages (PRs #7-#9) now run inside the server.
crates/mc-server/src/worldgen.rs: Generator (the wired RandomState, biome source, SurfaceSystem, compiled surface rule, cached biome grids of 4x4x4 cells) and GenPool, a pool of worker threads.
World gets Fallback::Generated: a chunk that is not stored in the region files is generated in the background. A chunk is sent once it and its eight neighbours exist (the light engine reads the 3x3 window); ensure_generated generates synchronously when a chunk is needed right now. Unmodified generated chunks are not saved (they are generated again after being unloaded, so later generator stages improve them without migration); edited chunks are saved as before.
New worlds follow level-type (normal, large_biomes, amplified, flat); worlds of the vanilla server with a noise generator are served too. LevelData::new_noise writes the noise generator into level.dat.
The initial world spawn follows MinecraftServer.setInitialSpawn (the Climate spawn search, then the first suitable column in the chunk spiral, PlayerRespawnLogic).
Fix: the default level-type was stored with a literal backslash; tools/vanilla_compare.sh now asks the Rust server for a flat world explicitly (it relied on the server always creating one).
Verification
tools/worldgen_smoke.sh: a fresh normal world, the bot joins, chunk packets decode, no panic.
tools/terrain_check.sh (mc-server --check-terrain): generates again the 289 chunks stored in a world made by the real vanilla server (seed 12345) and compares the blocks. This is a sanity check, not an equality test, because vanilla also carves caves and places features and structures: 90.31 % of the 28.4 million blocks are identical and the highest solid non-foliage block is at the same height in 95.93 % of the columns. The differences are exactly what the missing stages produce (caves, clay / tuff / andesite / diorite / granite / gravel blobs, ores, sculk, water lakes).
tools/vanilla_compare.sh (superflat): 38 / 38 against the vanilla server. cargo test --workspace passes (new tests: top-face check for the spawn search, escaped default level-type, new_noise level data, generator sanity).
Generation speed: about 35 ms per chunk and core (4 threads: about 30 chunks per second; not optimised yet).
Open issue found while testing
tools/world_compare.sh on a freshly generated vanilla world: the saved-world step differs in the light of 1 of 109 chunks (the edited chunk, 84 cells at its south-east corner, up to 5 levels brighter in Rust). It reproduces with the world generator disabled, so it is not caused by this PR; the previous run on another generated world matched 109/109. The likely cause is stale stored light of a neighbouring chunk in vanilla (vanilla relights only the edited chunk and takes the neighbours' stored arrays as given) while the Rust engine recomputes the 3x3 window from the blocks. Documented in the README; not fixed here.
Not in this PR
Carvers, features, structures and the Beardifier (new worlds have the exact terrain and surface of vanilla but no caves, trees or villages), the Nether and End dimensions, faster generation, the real client has never been tested.
