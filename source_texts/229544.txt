Motivation
The What's New in VTK-wasm webinar shows volume rendering as VTK-wasm's headline capability, but pyvista-wasm only renders surface geometry. pyvista-wasm has ImageData but no Plotter.add_volume, so volumetric scientific data (CT/MRI scans, simulation fields) cannot be displayed.
What changed
Plotter.add_volume(volume, scalars, cmap, opacity, clim, max_points, show_scalar_bar) following the PyVista signature, including the PyVista opacity presets ("linear", "sigmoid", "geom") and constant opacity
The volume renders as a translucent scalar-coloured point cloud (decimated to max_points) because the vtk-wasm binary does not register a deserializer for vtkSmartVolumeMapper/vtkVolumeProperty
The point cloud is the documented ceiling: true ray-cast volume rendering replaces it as soon as the volume mapper classes are registered upstream — only the actor backend inside add_volume changes.
Related Issue
Closes #743

Volume rendering with ImageData (#743): add Plotter.add_volume following
the PyVista signature (scalars, cmap, opacity presets linear/sigmoid/geom,
clim, show_scalar_bar). The vtk-wasm binary does not register a
deserializer for vtkSmartVolumeMapper / vtkVolumeProperty, so the volume
is rendered as a translucent scalar-coloured point cloud (decimated to
max_points) using the existing add_mesh machinery.

rendering replaces it as soon as vtkSmartVolumeMapper (or
vtkGPUVolumeRayCastMapper) is registered in the wasm deserializer, at
which point only the actor backend in add_volume changes.
