Summary
The tree and the surface are built block by block, and every block is stored. A larger world built this way uses too much memory. The tree's circumference, its blocks, and the surface should be generated by a formula. Only the exceptions (places that differ from the formula) should be stored.
Expected
The tree's bark, circumference, and the world surface are computed from a function, not stored cube by cube.
Only exceptions to the formula are saved, for example a block that was broken, placed, or changed by the player.
Where many blocks share the same content, store them as collections or ranges (for example runs or chunks), not as single cubes.
The same approach applies to the tree's floors. Each floor is mostly flat, so it should be stored as a flat plane with exceptions, not as every block.
Memory use should stay flat as the world gets larger.
Where
src/world/tree.ts (GiantTree writes its voxels one by one with put)
The chunk and world storage code (see src/world/)
Notes
Define the formula and the exception format first, then test that memory does not grow with the size of the world. Agree the storage format with the owner before building it.
