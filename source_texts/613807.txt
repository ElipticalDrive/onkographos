Changes
First implemented increment for #12: attribute each final surviving voxel face to the operation that removed its empty neighbor. Different faces of one voxel can have different exposure IDs. Optional postprocessing intersects final-boundary candidate masks with existing removal deltas; no timestamp is allocated for every removed volume voxel.
Add operation/tool coloring and exact operation-ID picking to the native macOS viewer. Initial/prehistory surfaces are neutral. Earlier playback frames do not reuse final labels, target comparison takes precedence, and section interiors are not attributed to a cutting operation.
Rebased onto main at fa91520 after #17, #18 and #20 merged. The rebase preserves CLI voxel overrides, default-drill Windows history support, defect inspection and large-world qualification. Conflicting documentation, CI and report fields retain both CLI and provenance behavior.
Validation
Rebased branch: 55 Debug / 55 ReleaseFast tests pass; ReleaseFast executable builds; independent exhaustive Python replay oracle agrees on all 5,393 final exposure-neighbor records in the general fixture.
Allocation failures leave authoritative stock unchanged. CLI voxel-override regression passes, including input preservation and saved-state spacing checks.
Rebased Swift viewer builds. Native operation/tool snapshots, exact operation-ID picking on the actual 25 µm pocket, and general-fixture finding navigation validate successfully. Pocket center identifies Layer 2 / 197 (operation 197, tool 0).
Default drill: all 225 mesh frame volumes agree with history; shared Windows reader replays both manifests and rejects unsafe/legacy redirects (C++17 reader test on macOS; no new native Windows rendering claim).
Isolated-increment measurement: 630,564 records / 10.09 MB, 0.109 s generation/export, 43.19 MB peak RSS. Single run, not a repeated, combined-branch, or rebase benchmark. Raw report and identifiers included.
Remaining scope
Issue #12 remains open: arbitrary-frame provenance, operation grouping, feed-derived rate/time heatmaps and Windows coloring are not implemented. This is categorical face attribution, not a local-accuracy guarantee or new formal-verification claim. It does not solve #11's large-world memory requirement.
