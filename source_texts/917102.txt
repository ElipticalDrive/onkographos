Summary
Part 1/3 of the classical-splat interop campaign (approved plan: import → PLY export → auto-download demos). This PR brings the four common photogrammetric 3DGS file dialects into Luxar as first-class GSplatData, after which the entire existing toolchain (LOD recipes, partition, filter, gsplat convert, scenes, viewer streaming) applies unchanged.
Dialect
Files
Decode
inria
point_cloud.ply (INRIA-style trainers)
header-driven (any SH degree), opacity logit→sigmoid, log-scales→exp, quats normalized
splat
antimatter15 .splat
flat 32-byte records
spz
Niantic/Scaniverse .spz
legacy gzip v1–3 (24-bit fixed positions, first-three/smallest-three rotations); v4 NGSP/zstd rejected with a clear error
supersplat
SuperSplat compressed .ply
chunked bit-packed (11-10-11 pos/scale, 2+10-10-10 smallest-three rot, 8888 color), 12- and 18-prop chunk layouts
Conversion: Σ = R·diag(s²)·Rᵀ → packed lower-tri Cholesky (eigenvalue-clamp guard for degenerate splats in real files); opacity → amplitudes; SH reduced to the DC band baked to per-splat RGB (f_rest dropped). NumPy + stdlib only — zero new dependencies.
Orientation is per-dialect: COLMAP y-down sources (INRIA/.splat/SuperSplat) get the canonical 180°-about-X fix by default; SPZ declares Y-up (RUB) data and is left untouched. --reorient/--no-reorient/--flip override; the applied matrix is recorded in stats["interop"] so the upcoming export can invert it. Columns stay world (x, y, z) — exactly what build_dimensions_from_data labels x/y/z.

…/ SPZ / SuperSplat)

New `luxar.gsplats.interop.classical_splats`: readers for the four common
photogrammetric 3DGS dialects — INRIA point_cloud.ply (header-driven, any SH
degree), antimatter15 .splat, Niantic/Scaniverse .spz (legacy gzip v1-3;
v4 NGSP rejected with a clear error), and SuperSplat compressed .ply (chunked
bit-packed, 12/18-prop chunks) — into a shared ClassicalSplats intermediate,
converted to GSplatData (scale+quat → Σ → packed Cholesky with an
eigenvalue-clamp guard; opacity → amplitudes; SH DC band baked to per-splat
RGB, f_rest dropped). NumPy + stdlib only, zero new dependencies.

Orientation is per-dialect: COLMAP y-down sources (INRIA/.splat/SuperSplat)
get the canonical 180°-about-X fix by default, SPZ declares Y-up (RUB) data
and is left untouched; --reorient/--no-reorient/--flip override. Columns stay
in world (x, y, z) order (what dimension inference labels x/y/z); the applied
orientation is recorded in stats["interop"] so a future export can invert it.

Surfaces:
- CLI `luxar gsplat import <src> <out.gsplats.zarr>` (--format auto|inria|
  splat|spz|supersplat, --reorient/--no-reorient, --flip, -e, --overwrite)
  with migrate-format-style post-write read-back verification.
- `scene.add_gsplats_from_file(...)` now sniffs .ply/.splat/.spz and imports
  on the fly — one-line scene embedding of classical captures.
- Python API `import_gsplats()` re-exported from luxar.gsplats.interop.

Bit layouts ported from the MIT reference implementations (nianticlabs/spz,
playcanvas/splat-transform) and verified against the official sample files
(hornedlizard.spz byte-exact, soar.compressed.ply, Babylon gs_Skull.splat,
an INRIA .ply). Tests generate miniature files of every dialect on the fly
(interop/tests/_synthetic.py) and assert reader parity plus covariance
fidelity through read → convert → save → load (cov relF p95 ≤ the AUTO
certificate bound).

Part 1/3 of the classical-splat interop campaign (next: PLY export, then
auto-download demos). Imports pair with blending_mode="normal" so scenes
become fully correct when depth-sorted rendering lands.
