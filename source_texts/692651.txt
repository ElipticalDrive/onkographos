Goal
Establish the smallest renderer-semantic surface-orientation contract required by the accepted R6 direct-lighting proof, before R6 lowering consumes it.
Base this work on accepted main 860dc366469e2d6990312ede41e3411f7b6a34ea.
Why this is required
R3 SurfaceQuery currently proves only hit/miss, non-negative ray distance, and the hit position derived from the canonical query ray. It does not provide geometric orientation/normal semantics.
The accepted R3 minimum material is Lambertian diffuse and the R6 proof requires one coherent direct-lighting method with a directional emitter. Evaluating Lambertian direct lighting requires a surface orientation. Letting R6 recover a normal from private sphere/plane/field realization while R4 declares only SurfaceQuery would create an undeclared semantic prerequisite and make method compatibility false.
This prerequisite therefore belongs in the R3/R4 semantic boundary, not hidden inside R6 method lowering.
Ownership
Introduce one narrow representation-generic protocol:
```
OrientedSurfaceQuery
    input: existing RenderSurfaceQuery semantics
    output: hit/miss + query-consistent hit distance/position + canonical scene-space geometric normal
```
The protocol means only that an exact surface hit can provide an orientation needed by consumers. It is not a primitive family, BSDF contract, shading normal policy, tangent frame, topology API, provider registry, dispatch ABI, GPU interface, or method-specific hook.
Keep existing SurfaceQuery unchanged for consumers that require only intersection semantics.
Required changes
Add a new versioned R3 representation protocol identity and exact protocol evidence for oriented surface query.
Add a narrow oriented result whose hit distance/position remain derived from the existing RenderSurfaceQuery, with a finite non-zero scene-space geometric normal canonicalized to unit length.
Extend RenderRepresentationRecord with optional oriented-surface evidence without forcing existing representations to claim it.
Extend R4 RenderRepresentationProtocolRequirement so a method can explicitly require the oriented protocol.
Extend R4 semantic planning/applicability to select only representations that actually advertise a compatible oriented protocol revision.
Preserve the existing plain SurfaceQuery protocol and all R1-R5 meaning.
Required proof
existing SurfaceQuery behavior remains unchanged;
oriented hit position is still derived from the canonical query ray and cannot contradict query distance;
oriented geometric normal is finite, non-zero, canonicalized to unit length, and expressed in renderer scene coordinates;
zero/non-finite normals are rejected structurally;
miss semantics require no fabricated normal;
compatible oriented protocol revision is accepted; unsupported/version mismatch is structured;
a representation advertising only plain SurfaceQuery does not satisfy an OrientedSurfaceQuery R4 requirement;
a representation advertising the oriented protocol can satisfy an ordinary R4 method output contract through the existing planning path;
representation ordering/determinism and all accepted R1-R5 planning laws remain unchanged;
no primitive/SDF/material/provider/dispatch/GPU/backend type leaks into the new protocol;
no assumption is made that FieldDistance implies differentiability or orientation;
cargo validate passes on the exact reviewed head and permanent CI is green.
Explicitly not owned
no public sphere/plane/SDF/mesh family;
no shading-normal vs geometric-normal hierarchy beyond the one geometric normal required now;
no tangent/UV/barycentric/element/material attributes;
no provider registry, Any, TypeId, callback/trait-object dispatch framework, or plugin ABI;
no GPU resource/program/binding/lowering work;
no R6 RenderWorkSet implementation;
no R7 residency/cache/session/presentation machinery;
no compatibility alias or duplicate semantic authority.
R6 relationship
Blocks #485 / PR #486. After this semantic prerequisite is accepted on main, R6 must re-census/rebase and use the declared oriented protocol rather than private primitive-specific orientation knowledge.

Critical semantic clarification before implementation: OrientedSurfaceQuery geometric-normal sign is representation-defined renderer-semantic orientation, expressed in canonical scene coordinates. The returned unit normal points toward the representation-defined geometric front side. It is not implicitly outward, viewer-facing, ray-facing, two-sided, a shading normal, or automatically flipped against the query direction. This makes orientation stable meaning that a Lambertian method may explicitly consume, while remaining valid for open/non-manifold/general representation families. Plain SurfaceQuery remains unchanged and does not imply orientation.
