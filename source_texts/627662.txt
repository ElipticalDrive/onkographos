Sparse copy data can crash statePosListToNBTMapArray: the packed array is allocated with list.size(), but the encoder walks the entire endpoint bounding box. We hit Index 14133 out of bounds for length 14133 while requesting copy data on Minecraft 26.1.2 / Building Gadgets 26.1.2.1. The same encoder then failed during SavedData serialization, crashing autosave and shutdown.
This sizes the array from checked spatial volume and includes air in the palette for missing cells. Resizing alone leaves missing cells encoded as -1, which the existing decoder cannot read. Normal dense NBT and the four-field format stay unchanged. Every recorded coordinate and block-state property is retained; duplicate coordinates use the last record, and outliers expand the bounds rather than disappearing. The packed buffer is bounded at 64 MiB, with checked arithmetic before allocation. Malformed or excessive input fails explicitly rather than being silently discarded.
Related: #249. Credit to @seekermarcel's #240 for the earlier bounding-volume fix on 1.21.1; this targets main / 26.1.2 and also handles valid palette indices for gaps.
Validation
gradlew test: 10 JUnit tests passed, with the upstream Minecraft/NeoForge versions and JDK 25. The local run used an external toolchain-vendor override to use the installed Adoptium JDK; no such override is included in the PR.
Added source regression tests for sparse data, the 14,133-record boundary, dense-format compatibility, duplicates, reversed/negative coordinates, outliers, block-state properties, SavedData roundtrip, overflow/resource limits, and seeded spatial conservation.
The same encoder logic was also tested as a separate server-only compatibility add-on in an isolated full FTB Evolution 2 1.6.3 instance: unpatched array-overrun reproduction, 83 final patched checks, actual native saving, fresh-JVM saved-data reopening, and the unchanged copy-data packet codec/decoder.
A player reported that repeating copy/paste and reopening the template worked after that compatibility add-on loaded. During a five-minute read-only observation, all six TPS samples were 20, the original errors did not recur, and Building Gadgets' data file updated across another natural save. This is supporting evidence for the compatibility add-on, not a claim that this upstream source build was deployed.
No server logs, player data, credentials, compatibility JARs, or local test worlds are included in this PR.
