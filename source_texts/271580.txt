Some clarifications:
vedo, which brainrender uses to handle the renderings, can handle volumes and does so beautifully. Check the exaples at vedo, it can render volumes or extract density maps or surface meshes.
currently brainrender does not work with Volumes however, only with meshes. So brainrender uses vedo's Volume class methods to create meshes from volumes. This can be done with a few different algorithms, not sure if marching cubes is one of these.
If you want to use volumes, and not just meshes, I should be able to make ti happen.
Now, as you say the more annoying part might be coding up the interactive slicing of the scene. However fear not, vedo has got this covered too:
vedo has a Slicer widget that allows you to do exactly what you need (example code).
In conclusion, there's two options here as far as I can see:
if your data are not registered to a reference atlas supported by Brainglobe's AtlasAPI and you are not planning to register it an any point, your best option might be to just use vedo and its great slicer widget.
if, however, you do want to use your data together with some atlas (which one?), then you need brainrender. In this case I can make Volumes work in brainrender, and you can use vedo's Slicer as a starting point to code something similar using brainrender

Oh great news, if you're using the allen atlas then brainrender is perfect for you.
It looks like a mesh, but it's really a volume (if you were to slice and look inside you'd see that it's full, unlike a mesh).
The reason why you're only seeing a shape that looks like the hippocampus is because the volume is thresholded to show only the voxels with higher gene expression (and interpolated to looks smooth).
I've added an example to show how to use volumes in brainrender: https://github.com/brainglobe/brainrender/blob/master/examples/volumetric_data.py
Note that brainrender's Volume class uses the Volume class from vedo to handle the rendering (I know, repeated names makes things confusing...). Vedo's Volume has many options to change how the volume should be rendered. You can pass keyword arguments to brainrender's Volume, these are passed. to vedo's Volume and can therefore affect how the volume is rendered.
e.g. if I wanted to use mode=2 in vedo's Volume I would do this:
```
actor = Volume(
    data,
    voxel_size=200,  # size of a voxel's edge in microns
    as_surface=False,  # if true a surface mesh is rendered instead of a volume
    c="Reds",  # use matplotlib colormaps to color the volume
    mode=2,  # <- get's passed to vedo
)
```
Have a go at playing around with the volumes visualizations in brainrender and let me know if you bump in any issue or have questions!
edit: nantille make sure to use the latest version of brainrender: pip install brainrender -U
