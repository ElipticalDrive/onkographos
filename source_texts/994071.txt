P4b — the rollback flag is retired
voxel.Seam.Meshing is deleted: the seam-ownership pipeline runs unconditionally for seam-capable meshers (DC + MC, CPU or GPU — GPU interiors still route per voxel.Seam.CPUInteriorRouting, which stays as the comparison lever).
Scope note (documented in §2.5): the legacy whole-chunk machinery (neighbor slices for render meshing, transition-face baking, boundary revalidation/coalesce cascades) is now reachable ONLY by meshers without seam support. Cubic still depends on it — slices for boundary face culling, revalidation for late-arriving neighbors — so deleting it outright is gated on cubic gaining seam support or being dropped as a supported config. That is a product decision to make explicitly, not silently inside P4b.
Performance HUD update
Seam= joins the per-system timing row; Coll= splits into prep/apply (the P4a attribution) plus the manager-tick Total.
New seam registry line: tracked / dirty / queued seams + lifetime processed (a dirty tail at the streaming frontier is normal — those seams wait for all participants to be resident).
UVoxelChunkManager::GetSeamRegistry() diagnostic accessor.
Verification
Suites 29/29 headless (DC + SeamRegistry + MC SeamClosure). The activation path with the flag gone is the same code the default-on flip (#51) and P3 (#53) verified live.
This completes the seam-ownership migration plan (P0–P4). 🎉

Fix invisible water: OR-combine material relevances in GetViewRelevance
…
44775f0
```
FMaterialRelevance::SetPrimitiveViewRelevance overwrites the primitive's
relevance bits wholesale (Raw = Raw) rather than OR-ing them, so calling
it once per material meant only the LAST material's relevance survived.
Since the crossfade feature made the derived masked fade material always
present, its opaque/masked relevance clobbered the water material's
translucent relevance every frame - the translucent pass never collected
the proxy's water tile batches, so the water surface mesh was invisible
even though the tiles, buffers, and material were all correctly submitted
(swim volumes and underwater shading, which do not go through the proxy,
kept working).

Fix: OR the terrain, water, and fade FMaterialRelevance values into one
combined relevance (the documented use of operator|=) and apply it once.
PIE-verified: water surface renders again on the demo map at the same
camera positions that previously showed bare lakebed.
```

```
The Queues line sampled the meshing queue once per frame, but the interior
pipeline drains its queue within a tick or two, so the count read 0 almost
always even during heavy streaming - the jobs fluctuate faster than the
HUD samples.

The Mesh entry now also shows async in-flight, a 2-second rolling peak of
queued+in-flight work, and completions/sec computed from the monotonic
TotalChunksMeshed counter, with a Verbose log breadcrumb at the window
cadence (the on-screen text is not capturable in screenshots or logs).
The Seams line gains the in-flight job count. New chunk-manager getters:
GetAsyncMeshingInProgressCount, GetSeamJobsInFlightCount,
GetTotalChunksMeshed.

PIE-verified: idle shows peak 0 / 0 per sec; a teleport burst shows
inflight=4, peak 8, up to 67 meshes/sec while the instantaneous queue
still reads 0.
```
