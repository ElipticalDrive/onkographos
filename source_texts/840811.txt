Description
Newton shades in linear light and encodes to sRGB only at output, with authored colors defaulting to display/sRGB. Gaussian splats did not follow this: SH radiance (SH_C0 * sh + 0.5) went straight into the blend, so values could be negative and sRGB-encoded data was treated as if it were linear.
Gaussian gains sh_color_space (ColorSpace.SRGB by default). It is exposed as a property, passed to the Warp data struct, and included in __eq__ and __hash__.
SensorCamera Gaussian shading decodes sRGB radiance to linear (which also clamps negatives) and clamps negative values on the linear path.
get_gaussian / Gaussian.create_from_usd read the color space of radiance:sphericalHarmonicsCoefficients (including inherited UsdColorSpaceAPI). Only linear color spaces (via the shared _texture_source_is_linear: lin_*, raw, linear, ...) give LINEAR; untagged radiance is sRGB. This is the opposite default from untagged scalar USD colors, which follow USD Preview Surface and are linear. 3DGS data is display-referred, so sRGB is the right default here. PLY loads are sRGB as well.
The GL and Viser viewers use a new gaussian_display_colors helper, so linear Gaussians are encoded to sRGB for display and match the camera output.
get_gaussian shares one attribute lookup helper with _get_float_array_attr.
The frozen SensorTiledCamera renderer (warp_raytrace) is intentionally not modified. It ignores sh_color_space.
Docs: conventions.rst and usd_parsing.rst describe the Gaussian color-space default.
Behavior change: untagged USD Gaussians and PLY Gaussians now render darker than before in SensorCamera, because their radiance is decoded from sRGB to linear. Assets tagged lin_rec709_scene keep their previous output apart from the negative clamp.

Bug fix
Steps to reproduce:
Create a Gaussian whose SH DC coefficients evaluate to negative and sRGB-range values.
Render it with SensorCamera and read the HDR color image.
The red channel is negative, and the other channels are the raw SH values with no sRGB decode.
Minimal reproduction:
```
import math

import numpy as np
import warp as wp

import newton
from newton.sensors import SensorCamera

gaussian = newton.Gaussian(
    positions=np.array([[0.0, 0.0, -2.0]], dtype=np.float32),
    scales=np.array([[0.5, 0.5, 0.5]], dtype=np.float32),
    opacities=np.array([1.0], dtype=np.float32),
    sh_coeffs=np.array([[-4.0, 0.0, 4.0]], dtype=np.float32),
)
builder = newton.ModelBuilder()
builder.add_shape_gaussian(body=-1, gaussian=gaussian)
model = builder.finalize(device="cpu")

camera = SensorCamera(model)
rays = camera.compute_camera_rays_pinhole(1, 1, camera_fov=math.radians(45.0), device="cpu")
transforms = wp.array([wp.transform_identity()], dtype=wp.transformf, device="cpu")
hdr = camera.allocate_image_color_hdr(1, 1, 1)
camera.update(model.state(), transforms, rays, hdr_color_image=hdr)
print(hdr.numpy().reshape(-1, 3)[0])
# Before: negative red, green 0.5 (not decoded). After: red 0.0, green ~0.214.
```
New feature / API change
```
import newton

# Default: SH radiance is display/sRGB and is decoded to linear when rendering.
gaussian = newton.Gaussian(positions=positions, sh_coeffs=sh_coeffs)

# Scene-linear radiance is blended as is (negatives are clamped).
gaussian = newton.Gaussian(
    positions=positions,
    sh_coeffs=sh_coeffs,
    sh_color_space=newton.utils.ColorSpace.LINEAR,
)
print(gaussian.sh_color_space)
```
Summary by CodeRabbit
New Features
Gaussian spherical-harmonics radiance can be tagged as sRGB or linear. USD imports use available color-space metadata; untagged radiance defaults to sRGB.
Gaussian viewers display colors according to the selected color space.
Behavior Changes
SensorCamera blends sRGB radiance in its encoded space, then decodes once per ray. Negative radiance is clamped, while HDR values above one are preserved.
Untagged USD and PLY Gaussians may appear darker in SensorCamera than before. Set the color space to linear to retain the previous output.
SensorTiledCamera does not apply the color-space setting. Unrecognized USD color spaces generate a warning and are imported without color conversion.
Documentation
Added guidance on USD color-space metadata and potential seams between overlapping Gaussian assets.
