Problem
Global mapping needs to handle dynamic objects with mid360
Closes DIM-XXX
Solution
Implement ray tracing approach for voxel mapping. When inserting a new point cloud, trace along rays of new points, and clear voxels in previous map along ray.
There are some parameters that can be changed;
shadow_depth: extend ray tracing beyond endpoints. Helps clear objects moving towards sensor.
grace_depth: ignore voxels from ray tracing within this range of endpoints. Helps prevent shallow incident rays (on floors, walls, etc.) from clipping other voxels on surfaces
min_health, max_health: assign a health value to each voxel, positive health means the voxel is occupied. Each hit increments health, misses decrement health.
Of course all these parameters introduce artifacts of their own, but they dramatically help overall! (Try setting the depths to 0, and min_heath to 0, max_health to 1 to see the behavior without them)

Greptile Summary
This PR adds a Rust-based voxel mapper with Amanatides & Woo 3D DDA ray tracing that clears stale map voxels along rays from the LiDAR sensor origin, enabling the global map to handle dynamic objects with the mid360 sensor.
A new RayTracingVoxelMap module wraps a compiled Rust binary that reads PointCloud2 + Odometry via LCM, maintains per-voxel health counters (min_health/max_health), traces rays to clear occluded voxels with configurable shadow_depth and grace_depth, and re-publishes the global map as a PointCloud2.
A new mid360_fastlio_ray_trace blueprint and all_blueprints entry expose the module as dimos run mid360-fastlio-ray-trace.
The Rust crate ships with a good unit-test suite that verifies ray traversal, shadow/grace regions, and health-counter semantics.
Confidence Score: 4/5
Safe to merge for development use; the Rust module is well-tested and the bounds-check gap from the previous review has been addressed.
The Amanatides & Woo DDA is correctly bounded, extract_xyz now validates field offsets within the stride, and the test suite covers shadow/grace/health corner cases. The remaining concern is the row_step signed-integer multiplication in build_pointcloud, which wraps silently in release mode for very large maps above 134 M voxels.
dimos/mapping/ray_tracing/rust/src/main.rs — specifically the build_pointcloud function.
