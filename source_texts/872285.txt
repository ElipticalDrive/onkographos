Hello, thank you very much for your attention to our work.
We used evo 1.14.0 and enabled the scale alignment function of evo.
```
traj_ref, traj_est = sync.associate_trajectories(traj_gt, traj_est)
traj_est.align(traj_ref, correct_scale=True)
```
There are some impacts on tracking acc. In the KITTI, we used Chunk Size = 75, Overlap = 30. Increasing the Overlap will improve the result. Plus, we also found that in Line 285 of ./vggt_long.py, increasing the conf_threshold will yield better results.
I recreate the python env today and conducted an new experiment. The results are as follows.
But I would like to mention that since the algorithm is running under the bfloat16 , its numerical stability may vary depending on the environment. That is to say, the alignment differences between each two chunks may be very small, but when the sequence is on a kilometer scale, these differences may be magnified. For example, using the bfloat16, the numerical precision difference between each two chunks is 2cm (2cm is very small in driving scene like KITTI). In 00 (if use 75 frames/chunk), there would be over 100 chunks in total. The numerical differences may accumulate to 2m.
It is truly acceptable to include the ATE results obtained from your own machine in the paper if you are doing research. I also strongly agree that conducting experiments under consistent conditions, using the same device, running environment, and operating system, ensures a fairer comparison. And i've recalculated the Avg in Table 1 using your results, the difference from the originally reported value remains small.
In KITTI, the 00 seq. was 8.67m and the 05 seq. was 8.31m in paper. However, these values are still worse than SOTA. In Table 1, ORB-SLAM2, LDSO, and DPV-SLAM++ all have relatively better accuracy. Moreover, other methods such as D3VO paper link and DVSO paper link also have better tracking performance in KITTI. So if you want to compare the SOTA methods in KITTI, perhaps VGGT-Long is not a very good baseline. I mean, it is still quite far from the SOTA methods.
The purpose of VGGT-Long is to verify the effectiveness of the latest 3D foundation model in long sequences, exploring the research potential and possible challenges in this field, rather than to surpass the current SOTA.

def load_proj(camera_poses_path):
    pose_path = PosePath3D(poses_se3=poses)
    timestamps_mat = np.arange(traj_w_c.shape[0]).astype(float)    
    traj = PoseTrajectory3D(poses_se3=pose_path.poses_se3, timestamps=timestamps_mat)
    xyz = traj.positions_xyz
    quat = traj.orientations_quat_wxyz
    traj_waymo = np.column_stack((xyz, quat))
    return traj_waymo
    
def make_traj(args) -> PoseTrajectory3D:
    if isinstance(args, tuple) or isinstance(args, list):
        traj, tstamps = args
        return PoseTrajectory3D(
            positions_xyz=traj[:, :3],
            orientations_quat_wxyz=traj[:, 3:],
            timestamps=tstamps,
        )
    assert isinstance(args, PoseTrajectory3D), type(args)
    return deepcopy(args)
