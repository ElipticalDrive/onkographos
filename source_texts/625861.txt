Summary
Add a BVH (Bounding Volume Hierarchy) acceleration structure to reduce ray-scene intersection from O(n) to O(log n).
Without BVH, every ray tests every object linearly. With 10 000+ objects this becomes a bottleneck — the BVH partitions objects into a binary tree of bounding boxes, letting the traversal skip entire subtrees on a single AABB miss.
Closes NIQ-224.
Changes
BVHNode — new IObject implementation in src/components/Primitives/BVH/. Recursively partitions objects along the longest AABB axis (median split). Traversal tests the node AABB first; only on hit are children visited, with closestSoFar tightening tMax after each left-child hit.
Collection::getObjects() — read-only accessor on children_ so Scene::buildBVH() can feed the flat object list to BVHNode.
Scene::buildBVH() — builds the accelerator from rootCollection_ and stores it as shared_ptr<IObject>. Scene::hit() delegates to it when set, falls back to linear traversal otherwise. The IObject type decouples Scene from the concrete accelerator — swapping to a KD-tree later only touches buildBVH().
CLI flag --no-bvh — BVH is active by default; pass --no-bvh to disable (useful for debugging or direct comparison).
scenes/benchmark_121.cfg — 10 000 spheres (100×100 grid) for benchmarking.
scenes/benchmark_100k.cfg — 100 172 spheres (317×316 grid) for stress testing.

NIQ-224 Bonus : BVH (Bounding Volume Hierarchy) — accélération des intersections rayon/scène
Labels: type: bonus P3 - Low L Milestone: M12
User Story
En tant qu'utilisateur final, je veux que le raytracer utilise une structure d'accélération BVH, afin que les scènes complexes avec de nombreux objets soient rendues significativement plus rapidement.
Contexte
Actuellement, chaque rayon teste tous les objets de la scène en O(n). Sur des scènes avec beaucoup de primitives, ce coût devient le goulot d'étranglement principal. Un BVH réduit ce coût à O(log n) en organisant les objets dans un arbre de boîtes englobantes (AABB). Cette optimisation sera surtout utile lors de l'utilisation de mesh. Le BVH doit être activé via un argument sur le binaire du raytracer.
Critères d'acceptation
Classe AABB (Axis-Aligned Bounding Box) avec méthode bool intersect(const Ray&) const
Classe BVHNode : nœud interne avec AABB, left, right ; feuille avec pointeur vers un IObject
Construction récursive du BVH à partir de la liste d'objets de la Scene (tri SAH ou médiane selon axe le plus large)
BVHNode::intersect(Ray, tMin, tMax) traverse l'arbre et retourne le hit le plus proche
Scene expose une option pour activer le BVH (--bvh CLI ou flag dans le .cfg)
Code isolé dans ./bonus/ ou src/acceleration/
Tests unitaires : arbre à 1 objet, 2 objets, rayon manquant tous les objets
Gains attendus
Scène avec ~10 objets : gain marginal
Scène avec ~1000 objets : ×10 à ×100 sur le temps de rendu
Depends on: NIQ-141 (RaytracerRenderer monothread)

Pull request overview
This PR introduces a BVH (Bounding Volume Hierarchy) acceleration structure to reduce ray–scene intersection cost by allowing large parts of the scene to be skipped via AABB culling, with a CLI switch to disable it.

Exposed Collection::getObjects() so Scene::buildBVH() can build the BVH from the scene’s top-level objects.
