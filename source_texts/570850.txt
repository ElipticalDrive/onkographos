Objective / goal
Preserve full animated actor silhouettes in detailed shadows and eliminate repeated silhouette stamps in volumetric visibility.
Why this approach
Recognize only proven stock weighted-skin layouts in the conservative envelope evaluator, then integrate visibility across intersected actor-depth cells instead of sampling one midpoint per long interval. Preserve pose, geometry, budgets and conservative capacity fallback rather than simplifying the actor or duplicating overlapping cascades.
Implementation and validation
Detailed actor shadows omitted the body when its stock weighted-skin shader used r0 for position and wrote w independently before XYZ skinning. The live diagnostic program hash 5267e7a8cb988451 matches stock CDiffuse_T1 lepola#29; its generic interval evaluator repeatedly exhausted the 70 microsecond heavy slice, leaving equipment in the fine map and the body in the coarse cascade. Recognize the strictly matched r0/r1, independent-w and commuted-MUL layouts in the existing conservative skin envelope. Geometry, animation, input validation and work/cache budgets remain unchanged.
Volumetric actor shadows previously sampled one point per long fog interval, producing repeated silhouette stamps. Traverse the intersected R32 actor-map texel cells and integrate each cell's depth comparison over the interval. Bound traversal to nine blocks of 228 iterations because SM3 loop counters are limited to 255. Compose far/actor visibility with minimum coverage rather than multiplying the same caster twice, preserving exact world visibility for a clear actor map. Reuse existing maps and conservative coverage bounds; no new shadow target, geometry submission, resolution reduction or fog-density/alpha change.
Compatibility: WorldFog/FogClouds retain the 512-slot baseline path (471/463 slots). Exact actor variants use 598/590 slots, validated against a separate 600-slot build budget, and are created only when the device advertises sufficient instruction capacity. Creation/capability failure retains the far-map path. Both native D3D9 and DXVK on the test machine support these variants. State restoration, per-source/current-map validity and resource release retain explicit checks.
Validation: eight focused CPU tests pass without skips, including O2/O0 and ASan/UBSan where applicable, 2,048 actual binding combinations, 20,000 conservative-coverage cases and destructive stale-map/wrong-source controls. The pinned real body shader, canonical/commuted layouts, malformed templates, changing palettes/cameras, nonunit weights and DEF/FTZ/overflow cases pass. An additional native Windows x86 run encloses 50,400 independently deformed vertices with unchanged budgets. Production x86 O2 DLL/PDB/source attestation passes.
The final production binaries pass 1,728 bit-exact neutral native/DXVK images and 72 active/inactive, source, range, stale and architecture controls. A separate GPU/CPU oracle checks 163,840 intervals in 20 FP16/FP32 cases over actual rasterized actor depth. It covers axial/diagonal rays, depth crossings, a solid full map, duplicate-cascade composition and bit-exact clear-map behavior. Maximum FP32 interval error is approximately 0.000007; the midpoint destructive control reaches approximately 0.94 visibility error. These authored caster/MPQ-derived-depth fixtures are not a full game replay.
Final alternating 1920x1080 pass timings on DXVK add approximately 0.15/0.11 ms for the humanoid and 0.37/0.21 ms for the prop (WorldFog/FogClouds), relative to the older far-map-only baseline. Inactive/architecture cases use the baseline dispatch. These are component costs for correct actor shafts, not a whole-game FPS uplift or a controlled comparison with the previously installed midpoint-filter build.
Installed candidate: commit 8fcb37f, source 4e4a6e71874eea57ee95a53c115b746e97665a87041d5c4aa6017d411ae13492, DLL SHA256 4feafd11b8e37e24a1ca780035c58c44a113ea2d4fc7042d7800fa900e9080f7, matching PDB. In-game visual confirmation and stable 120 FPS remain pending. The temporal shaft-map transition in lepola#107 remains separate. PR lepola#84 was closed without merging; no native-shadow game setting is changed here. Personal settings, MSAA and wow_optimize remain unchanged. Private client bytes, logs and credentials are excluded.
