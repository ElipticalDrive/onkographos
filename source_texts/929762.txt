Request
Pulse.Lib.Primitives provides read_atomic, write_atomic and cas, plus their _box variants, on U32.t only. We are writing a parallel sweep for a garbage collector, where the shared words are 64-bit heap headers. We would like the same operations on U64.t, for example:
```
val cas_u64 (r: ref U64.t) (u v: U64.t) (#i: erased U64.t)
  : stt_atomic bool #Observable emp_inames
    (pts_to r i)
    (fun b -> cond b (pts_to r v ** pure (reveal i == u)) (pts_to r i))
```
It would help even more to have a reference C implementation alongside, for example over _Atomic uint64_t and atomic_compare_exchange_strong, so that each user does not write their own trusted C.
What happens today
Repro.Cas64.fst:
```
module Repro.Cas64
#lang-pulse
open Pulse.Lib.Pervasives
open Pulse.Lib.Primitives
module U64 = FStar.UInt64

fn try_claim (r: ref U64.t) (id: U64.t) (#i: erased U64.t)
  requires r |-> i
  returns b: bool
  ensures cond b ((r |-> id) ** pure (reveal i == 0UL)) (r |-> i)
{
  cas r 0UL id
}
```
```
fstar.exe --cache_checked_modules --cache_dir _cache --odir _output \
  --already_cached 'Prims FStar Pulse PulseCore' Repro.Cas64.fst
```
```
* Error 189 at Repro.Cas64.fst(12,6-12,7):
  - Ill-typed term
  - Expected expression of type Pulse.Lib.Reference.ref FStar.UInt32.t
    got expression r
    of type Pulse.Lib.Reference.ref FStar.UInt64.t
```
We found no other compare-and-swap in the F* or Pulse libraries in this release.
