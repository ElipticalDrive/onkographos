Found while testing crates/engine/src/select.rs:49-52 (hit_polylines, Prim::Infinite) together with crates/geom/src/intersect.rs:17-21 (line_line) (no existing issue): Fence and crossing-window selection pick a RAY from up to 1 drawing unit behind its base point.
Cause
hit_polylines turns a ray into a 1e9-long segment from its base. line_line accepts a fixed 1e-9 slack on the segment parameter, which on a 1e9-long segment is about 1 drawing unit before the base. A fence or crossing window touching the ray's backward extension within that distance therefore selected the ray. The same happened for entities with a crossing window.
Fix
Added geom::line_line_capped. Its end slack is 1e-9 drawing units (the parameter tolerance divided by the segment length, with the length floored at 1), so it no longer grows with segment length. seg_hits_box, select_fence_with and select_polygon now use it.
Verified
Regression test fence_and_crossing_window_ignore_ray_behind_its_base: fails on main without the fix and passes with it (cargo test -p cadcraft-engine --lib fence_and_crossing_window_ignore_ray_behind_its_base).
cargo xtask ci passes.
Not changed
line_line keeps its existing behaviour for all other callers. The 1e9 ray length in hit_polylines is unchanged.

Keep endpoint hits on long segments inside the documented 1e-9 slack.
line_line_capped sets its end slack in parameter units as 1e-9 / l.len().max(1.0). For a segment longer than about 9.0e6 units, that slack is below half the spacing of doubles at 1.0. 1.0 + ta then rounds to 1.0, so the upper bound becomes exactly 1.0. An intersection at the upper endpoint can have a computed parameter slightly above 1.0 from rounding, and the check rejects it. line_line accepted the same case with its fixed 1e-9 parameter slack, which is about 0.01 units at this length.
seg_hits_box, select_fence_with, and select_polygon now call line_line_capped. A fence or crossing edge that meets the endpoint of a long segment can therefore miss that segment.
The function's doc comment states the intended contract: the end slack is at most 1e-9 drawing units. A parameter-based slack cannot express that tolerance for long segments. Near 1e7, the spacing of representable coordinates is about 1.9e-9 units, which is larger than 1e-9. Measure the overshoot in drawing units instead of parameter units. Use a tolerance that is not smaller than the coordinate rounding error at the segment's magnitude.
