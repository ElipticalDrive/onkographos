Hi Dusan,
Great question—your intuition is basically right.
How we made the 360° view. We separately inferred the left 180° and the right 180° views around the object and concatenated them to obtain a smooth orbit.
Input & geometry. As in the paper, we condition on a single image. We estimate monocular depth with VGGT, then follow a predefined camera path to do the initial view warping + inference. To keep quality high, we use an iterative pass: first produce dense ~30° segments on each side, then re-seed from the tail frame and iterate outward until each side reaches 180°.
We’ll release the warping utilities, the video/inference scripts, and the trajectory helpers (e.g., spiral/orbit paths). The release is taking a bit longer than we hoped because of the code size and some parallel commitments, but we’re actively organizing it and will open-source as soon as it’s ready. Thanks for your patience!
Kind regards,
Chenxi

Hi,
Thanks for your interest. To put it simply, the initial input for our horse scene was just a single view. We didn't apply any additional conditioning to preserve the object; the only "condition" was the text prompt itself (e.g., telling the model "it is a horse").
The 360° view is generated iteratively in an "auto-regressive" style. We use the last frame of the previous segment, combined with a warped view from that last frame, as the first frame for generating the next segment.
We have received a lot of curiosity about this panoramic scene generation. We will consider releasing the parameter-setting script for this specific case when we open-source the code. Thanks for following our work.
