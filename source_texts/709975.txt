Motivation
Re-enable the GeeseFS --cache capability for volumes while preventing user-supplied paths from accessing arbitrary host filesystem locations.
Provide a per-volume cache directory so each PV gets an isolated cache area rather than a shared or user-controlled path.
Allow operators to override the cache root via an environment variable while keeping a safe default for typical deployments.
Description
Add a DiskCache boolean to s3.FSMeta and the DiskCacheKey constant so the driver can parse a diskCache volume attribute (pkg/s3/client.go, pkg/mounter/mounter.go, pkg/driver/nodeserver.go).
Parse diskCache in getMeta(...) and carry it to the mounter metadata so mounters can act on it (pkg/driver/nodeserver.go).
Implement derivedCacheDirectory(volumeID string) in pkg/mounter/geesefs.go which derives a per-volume cache directory under the environment-controlled DISK_CACHE_PATH (default "/var/lib/geesefs-cache") and hashes unsafe volume IDs to prevent path traversal.
Continue to block user-provided filesystem options for safety by ignoring --cache when supplied in volumeAttributes.options and instead append --cache <derived-dir> to the GeeseFS args when DiskCache is enabled, ensuring the driver controls the host path (pkg/mounter/geesefs.go).
Update documentation and examples by adding diskCache: "true" to the static PV example and documenting DISK_CACHE_PATH and the diskCache attribute in README.md.
Add unit tests for cache-directory derivation and attribute parsing (pkg/mounter/geesefs_test.go, pkg/driver/nodeserver_test.go).
Testing
Ran go test ./... which executed the new unit tests and returned successfully.
Ran git diff --check to validate formatting and lint-like checks with no reported issues.
Added and exercised unit tests for derivedCacheDirectory and getMeta parsing which passed under the test run (pkg/mounter and pkg/driver).
