Core deliverable: src/Terrain/ - a density-field-to-mesh module (EC_DensityField, EC_MarchingCubesTables from the canonical Bourke/Lorensen-Cline reference, EC_MarchingCubesMesher with per-triangle winding correction and vertex welding) plus its own unit test suite. Pure C++/glm, no engine dependency, verified correct via extensive unit testing and live rendering in the actual engine before being scoped down to just this first slice.
Bugs found and fixed while getting a real mesh rendering end-to-end:
lightpass.frag's colour sampler was named "colourMap" while every other light-pass shader (6 of them) and the C++ binding code use "AlbedoMap" - the mismatch silently defaulted the sampler to reading the position texture instead of albedo. Invisible until now because every light in every existing scene cast a shadow (routing through the correctly-named shaders); this is the first non-shadow-casting light with real geometry.
setLight() sliced DirLightData's direction field when binding a non-shadow-casting directional light (only LightData's base fields were copied), leaving the light pass's direction uniform permanently zero.
EC_GameScene::activate()/deactivate() overwrote every entity's active flag unconditionally, discarding gameplay-level state a script had set independently (e.g. cycling to one active light of three). Split into active (gameplay) and sceneActive (scene membership), with a new EC_DOD_EntityManager::getActiveEntitiesWithComponents() helper checking both, replacing several ad-hoc checks.
EC_SceneManager::m_ActiveScene was a plain size_t written from the scripting thread and read from the render thread with no synchronization - made atomic.
Lua script event dispatch never checked whether an entity's scene was still active, so a deactivated scene's scripts kept firing.
ObjModel gains initialiseFromMeshData() - a small additive upload path for procedurally generated meshes that bypasses Assimp, reusable by future terrain chunk-streaming work.

Core deliverable: src/Terrain/ - a density-field-to-mesh module (EC_DensityField,
EC_MarchingCubesTables from the canonical Bourke/Lorensen-Cline reference,
EC_MarchingCubesMesher with per-triangle winding correction and vertex welding)
plus its own unit test suite. Pure C++/glm, no engine dependency, verified
correct via extensive unit testing and live rendering in the actual engine
before being scoped down to just this first slice.

Bugs found and fixed while getting a real mesh rendering end-to-end:
- lightpass.frag's colour sampler was named "colourMap" while every other
  light-pass shader (6 of them) and the C++ binding code use "AlbedoMap" -
  the mismatch silently defaulted the sampler to reading the position
  texture instead of albedo. Invisible until now because every light in
  every existing scene cast a shadow (routing through the correctly-named
  shaders); this is the first non-shadow-casting light with real geometry.
- setLight() sliced DirLightData's `direction` field when binding a
  non-shadow-casting directional light (only LightData's base fields were
  copied), leaving the light pass's direction uniform permanently zero.
- EC_GameScene::activate()/deactivate() overwrote every entity's `active`
  flag unconditionally, discarding gameplay-level state a script had set
  independently (e.g. cycling to one active light of three). Split into
  `active` (gameplay) and `sceneActive` (scene membership), with a new
  EC_DOD_EntityManager::getActiveEntitiesWithComponents() helper checking
  both, replacing several ad-hoc checks.
- EC_SceneManager::m_ActiveScene was a plain size_t written from the
  scripting thread and read from the render thread with no synchronization -
  made atomic.
- Lua script event dispatch never checked whether an entity's scene was
  still active, so a deactivated scene's scripts kept firing.

ObjModel gains initialiseFromMeshData() - a small additive upload path for
procedurally generated meshes that bypasses Assimp, reusable by future
terrain chunk-streaming work.
