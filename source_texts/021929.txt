Implements the Sparse Multi-Scale Grid algorithm (Benítez-Llambay 2025) as a new "nested" backend for both 3D volume rendering and 2D projection of SPH data.
Particles are assigned to a level of a grid hierarchy according to how many cells their kernel spans, deposited onto that (coarser) grid, and the hierarchy is then collapsed coarse-to-fine by trilinear (3D) or bilinear (2D) upsampling. This bounds the per-particle cost at O(ntarget³) / O(ntarget²) regardless of smoothing length, which gives large speedups for simulations with a wide range of smoothing lengths (zoom-ins, cosmological boxes including the IGM). For example, projecting 200k particles with h spread over ~3 decades at 1024² on 32 threads takes 0.12 s with nested vs 1.2 s with fast.
Features
backend="nested" for render_gas / render_voxel_grid (3D) and project_gas / project_pixel_grid (2D).
Optional ntarget (target cells per kernel diameter, default 6) and nlevels (hierarchy depth, default 4) arguments. resolution must be divisible by 2**nlevels; an incompatible combination raises a ValueError suggesting valid alternatives. Setting either argument with another backend raises a UserWarning.
Same Wendland-C2 kernels as the existing scatter (3D) and fast (2D) backends; periodic wrapping handled per image, only for images whose kernel overlaps the region.
Serial and parallel (Numba prange, per-thread private hierarchies) implementations.
Bounding-box tracking so the collapse only visits occupied regions.
Code layout
swiftsimio/visualisation/volume_render_backends/nested_grids_scatter.py — 3D backend.
swiftsimio/visualisation/projection_backends/nested.py — 2D backend.
swiftsimio/visualisation/_nested_grids.py — dimension-independent helpers shared by both (level assignment, hierarchy validation, input conversion).
backends / backends_parallel dictionaries in both backend packages include "nested".
Tests
Volume render tests that were duplicated for the new backend are now parametrized over ["scatter", "nested"] (smoke test, serial vs parallel, periodic wrapping, density with units, equivalent regions).
The projection tests already parametrized over all projection backends now cover nested too (scatter smoke test, equivalent regions, periodic wrapping); the serial-vs-parallel test is parametrized over ["fast", "nested"].
Nested-specific tests: agreement with the single-resolution backend when ntarget is large, mass conservation (2D and 3D), invalid-resolution error, and the warning for nested-only arguments.
Documentation
docs/source/visualisation/volume_render.rst: nested backend section (motivation, algorithm, accuracy, resolution constraint, memory, choosing parameters) and lower-level API examples.
docs/source/visualisation/projection.rst: new equivalent section for 2D projections, plus the backend list and lower-level API examples.
NumPy-style docstrings throughout.

Implement efficient Sparse Multi-Scale Grid algorithm (Benitez-Llambay 2025)
for 3D volume rendering of SPH data. Particles are hierarchically assigned
to grid levels based on kernel smoothing length, then scattered onto
coarse-to-fine grids and upsampled back to target resolution. This bounds
per-particle work regardless of smoothing length, providing significant
speedups for simulations with wide kernel distributions.

Features:
- New nested grid backend accessible via backend="nested" parameter
- Adaptive hierarchy with configurable target voxels per kernel (ntarget)
  and number of levels (nlevels)
- Kernel arithmetic matches scatter.py implementation (Wendland-C2)
- Parallel support via Numba prange
- Trilinear upsampling for hierarchy collapse
- Efficient bounding-box tracking to skip empty regions

API additions:
- render_voxel_grid() and render_gas() now accept backend, ntarget, nlevels
- backends dict updated to include "nested" alongside "scatter"
- Added validation and warnings for backend-specific parameters

Tests:
- Added TestNestedVolumeRender class with serial/parallel matching tests
- Tests cover periodic boundary conditions and edge cases
- Comparison against single-resolution backend validates correctness

Documentation:
- Updated volume_render.rst with nested backend description and examples
- Added parameter documentation for ntarget and nlevels

Code quality:
- Passes ruff linter
- Passes numpydoc validation
- All existing tests continue to pass

Refs: Benitez-Llambay A., 2025, MNRAS (in prep)
