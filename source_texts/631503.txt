Owner role: Engine render maintainer. Status: unimplemented on main; analysis done, pilot of a hierarchical depth buffer (HZB), a mipmapped depth image used to reject hidden geometry, drafted (new files only, unapplied).
Purpose and finite boundary
Close the frame-time gap to B5 without lowering quality. Historical prototype inference: the saved evidence places the gap on the render thread and in the shadow path rather than in cluster culling, though the cull's deferred cost is not yet attributed: after the world is ready the cluster path ran about 144 fps against about 178 to 190 baked; omitting cluster shadow draws raised it to about 175. Frames at the target need 6.25 ms.
The package works the cost down in order of measured size:
Shadow encoding. Recover the exact capture, selected post-ready interval and same-work counters before assigning a cost to each owner. Report render-thread critical-path wait separately from summed worker CPU time. Parallel cascade encoders are a hypothesis to test after attribution; cluster-cull encoding must not be ruled out solely from its own span because work can be deferred into encoder finish. A profiler capture provides attribution, while ordinary builds provide frame-rate acceptance.
Two-pass occlusion culling against the previous frame's depth (HZB). A pilot at unchanged level of detail (LOD) error and material quality, accepted only if it saves more than its probe, pyramid and dispatch cost. Its benefit is a hypothesis until measured.
Counters. Unbounded meshes (no automatic bounds and no box) are counted, never silently culled away.
Boundary: shadow and main passes, encoder structure, the HZB pilot (new passes behind a capability and option), and the profiling spans needed to attribute cost. Not in this package: the visibility buffer (#329), traversal hitches (#330), load time (#331).
Dependencies
#324.
Closure criteria
Per-pass attribution on the final head: render-thread ms per frame by owner, GPU ms per pass, draws and bind-group changes per pass, in one table from one quiet run, with nested spans not summed twice.
Shadow encoding: cascades finish in parallel; the shadow share of render-thread time falls from the baseline recovered by the attribution above, measured post-ready at the same settings and work (counters match).
The portal demo route meets B5: 160 fps (6.25 ms) stable post-ready, travelling and through load doors, with the 99th-percentile frame time (p99) and maximum reported; or the first remaining cost is named with its owner and the child issue that removes it. The prior prototype p99 was 8.61 to 8.99 ms.
HZB pilot: the net GPU and render-thread change is recorded with the depth probe, pyramid and dispatches included, at identical selection counters; the pilot is kept only if net positive and cluster results are unchanged (image difference zero within the Clusters C01: Freeze the bars, baseline, reference scenes and measurement protocol #317 threshold). Rejected pilots are recorded as fail evidence.
Occlusion culling is conservative: a test with a moving occluder shows no object missing in a frame it should be visible, including after a teleport or a world-origin rebase.
A frame with no new work in the secondary views does not re-run their passes at lower quality or lower cadence unless that is a named, defaulted-off option (no hidden cadence cuts).
Settings are not loosened to reach a number: error threshold and minimum instance changes are options with measured image impact, not the fix (the saved sweeps reduced triangles far more than time).
Added passes work on Apple Silicon or have a declared equivalent (Clusters C17: Apple Silicon: declared capability checks and an equivalent path for every GPU feature #333).
Evidence and limits
The first quiet Tracy figures are from the demo with Tracy attached, whose overhead is part of the render-thread figure (render-cost analysis; exact capture citation required); the quiet-machine post-ready range was 120 to 128 fps, and earlier 108 to 118 fps readings were under build load. Run-to-run noise is about 8 fps. A test of wgpu's indirect-call validation (WGPU_VALIDATION_INDIRECT_CALL) found no effect (120.1 / 128.0 with it against 125.7 / 123.4 without).
The wgpu source audit confirms hardware-layer command replay happens at encoder finish, so the finish zone includes real command generation. The saved evidence does not apportion the shadow saving between CPU and GPU. The HZB patch draft adds only new files and is not a wired feature; per-view resources, probe rendering, history publication, settings and hardware tests are still to be integrated (occlusion proposal dated 2026-10-20).
