Crash
Crashlytics, SceneView Demo 4.51.0-main (2026-10-01). The same signature shows up on Play in 4.38.0, 4.39.0 and 4.47.0. Filament aborts in RenderableManager.Builder.build with this message:
AABB can't be empty, unless culling is disabled and the object is not a shadow caster/receiver
Trace: MeshNode.kt:86 <- StreetscapeGeometryNode.kt:51 <- SceneMeshNode.kt:118 <- ARSceneScope.kt <- ARSceneGeometryDemo.kt (AR Scene Geometry sample).
Cause
StreetscapeGeometryNode built its MeshNode without a boundingBox. MeshNode then turned culling off but left Filament's default receiveShadows(true). Filament's precondition rejects an empty AABB on a shadow receiver. Every Streetscape geometry that ARCore delivered (only in VPS-covered areas) killed the app, so the low crash volume reflects VPS coverage, not rarity.
Fix
StreetscapeGeometryNode computes the AABB from the mesh vertices (computeStreetscapeAabb):
It skips non-finite vertices.
It clamps the read to the buffer limit and leaves the buffer position unchanged.
It floors every half-extent at 1 mm. Filament's Box::isEmpty() is length2(halfExtent) == 0, so only a mesh collapsed to one point would be empty; the floor covers that case and gives flat terrain tiles a non-zero thickness.
The renderable lives in StreetscapeMeshRenderable (internal), which the node drives with ARCore's mesh. That split lets the build / rebuild / drop path run on real Filament in an instrumented test without a Geospatial session.
Empty meshes build no renderable. If there are no vertices or fewer than 3 indices, meshNode is null. On update(), the node rebuilds or drops the renderable when ARCore changes the vertex or index count, so a geometry that becomes empty or non-empty later is handled too.
Breaking (source): meshNode is now MeshNode?. It is null while the mesh is empty. The JVM signature is unchanged and apiCheck passes, but Kotlin callers that dereference it need ?.. A rebuild replaces the instance, so changes made directly on it (visibility, layer, material, touchability) are lost; the KDoc says so and points to meshMaterialInstance / builder, which every rebuild re-applies. The changelog fragment lists this under Changed.
Cost of the change check. update(trackable) only runs when ARCore lists the geometry in the frame's updated trackables, and an unchanged mesh costs one getMesh() plus two size reads; the vertex and index buffers are only read on a rebuild. I kept the check on every reported update rather than gating it on pose or tracking changes, so a refined mesh is never missed.
MeshNode without a box now disables castShadows and receiveShadows as well as culling. Any future caller that omits the box gets a non-shadowed renderable instead of a native abort. With a box, culling(true) is set explicitly. The user builder lambda still runs last, so callers can override all of this.
Audit of the other MeshNode builders
No change needed in DepthMeshNode, PointCloudNode, AugmentedFaceNode or ShadowReceiverPlaneNode: they either pass a box or already disable culling and shadows.
No change needed in the ARSceneScope composables either.
The MeshNode change covers any remaining no-box path.
Tests
Instrumented, real Filament:
MeshNodeBoundingBoxTest (:sceneview): a box-less MeshNode builds, and it neither casts nor receives shadows; a boxed one keeps its box and default shadow receiving; the user builder still runs last. A regression here is a native abort, so the test process would die. Passes in CI (:sceneview:connectedDebugAndroidTest, Android library render tests job on 7062e2e). Locally the emulator could not start the test process: the host was overloaded (load average above 300) and every launch hit a startup ANR, before any test code ran.
StreetscapeMeshRenderableTest (:arsceneview): an empty mesh builds nothing; a flat terrain tile builds with its computed box; the same counts keep the instance; changed counts rebuild it and destroy the old one; a mesh that becomes empty is dropped and rebuilt when it comes back; unchanged counts never read the buffers. 6/6 pass on emulator-5554 (test APK installed with adb install, run with am instrument).
JVM: StreetscapeGeometryAabbTest keeps the 9 pure tests of the box math and the empty-mesh decision (empty and non-empty vertex lists). The two source-string tests are gone.
:arsceneview:testDebugUnitTest, apiCheck (both modules), detekt (:arsceneview, :sceneview) pass.
