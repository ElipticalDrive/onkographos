Problem
Core's only anti-aliasing is FXAA, a post-process: no MSAA option turned up in the render contract, passes or the Vulkan/WebGPU backends. FXAA smooths edges cheaply, but it blurs fine detail and texture, it crawls on thin geometry under motion, and it can't fix alpha-tested foliage (trees, grass, hair cards), which shimmers as the camera moves.
Proposal
MSAA for the scene pass:
multisampled colour and depth attachments, 2x/4x/8x clamped to the device's supported counts, resolved before post-processing;
set per camera or render plan (antiAliasing = Msaa(samples)), defaulting off so existing scenes don't change;
both backends.
Alpha to coverage for AlphaMode.Mask materials when MSAA is on, so foliage edges are smoothed instead of shimmering.
Shadow and depth prepasses stay single-sample. Depth-reading effects either sample the resolved depth or are documented as single-sample only.
Combining: MSAA plus FXAA must work, with FXAA off by default when MSAA is on.
UI: the canvas and UI overlay are drawn after resolve and post-processing, never multisampled or FXAA'd, so text stays crisp (see Text: crisp small UI text (pixel-size coverage glyphs) and higher-resolution distance fields #993).
Later: TAA is out of scope here, but the render plan should leave room for it.
Acceptance
Headless renders of a thin-geometry scene and an alpha-masked foliage scene at 1x, 4x MSAA, and 4x plus alpha to coverage: measurably smoother edges against the 1x baseline (edge-pixel metric), with snapshots.
Unsupported sample counts clamp with a log line, with no crash.
The UI overlay is pixel-identical with MSAA off and on.
GPU frame cost at 1920x1080 for 1x, 2x and 4x is measured and documented.
Both backends are covered, or WebGPU is tracked with its own limits documented.
Implementation and delivery
Implementation is open for review in PR #1123, milestone v0.27.0, head 1d8600c8969e3e12b8d7e2784780bc69c15937ce. The plan defaults to 1x; both backend resolve paths and material-aware coverage are implemented.
Local validation: 796 passing tests and one pre-existing ignored shadow-mode probe (797 total), including 11 production-plan GPU comparisons. Vulkan/WebGPU geometry metrics are 146/218 intermediate edge pixels; masked coverage adds 70/70 intermediate internal-edge pixels. UI strips and offscreen UI layers match byte-for-byte at 1x/4x, the UI follows explicit FXAA, and the hard shadow-map cutout stays identical. Negative controls are recorded in test KDoc and verification notes. No baseline images or tolerances changed.
Vulkan 1920x1080 timestamp medians for the documented small masked-quad fixture are 0.098272/0.116064/0.122656 ms at 1x/2x/4x. Spotless, targeted Detekt, published API checks, awakeVerify, capability layering and headless-runtime checks pass. Android Vulkan and wasmJs WebGPU compile.
All 15 successful CI checks passed on head 1d8600c8969e3e12b8d7e2784780bc69c15937ce; Graphify Formal Verification completed neutral. Reviews, inline threads and general comments had no unaddressed findings. Final diff review found no blocking issue. Squash-merged via exact-head guard as ce55c4b291d40c98dae3932f7c9746f05f1592c9; GitHub's merged state and merge SHA were verified. No release was cut. PNGs are generated under samples/engine-showcase/build/reports/msaa/ and the CI showcase job uploads them with test reports.

Done in fix(render): single-sample UI-only targets and deterministic WebGPU teardown #1159: both backends build scene attachments on a target's first scene pass, so a 4x UI-only target holds its 1x colour alone (OffscreenTargetAttachmentsTest, WebGpuUiTargetAttachmentsTest). Android memory profiling stays with the Android line above.

Repeated full-plan boots in one JVM reproduce native device-request memory exhaustion. The new GPU comparisons use one scenario per process, following the existing forkEvery = 1 convention; assertions and requested samples are unchanged. Done in fix(render): single-sample UI-only targets and deterministic WebGPU teardown #1159: every child object, then the surface, device with its queue handle, adapter and instance are released in order, and WebGpuRepeatedShutdownTest checks wgpu-native's registry report is empty after each of 12 full-plan boots in one process. forkEvery = 1 stays; see the next line.
Core rendering maintainer: move the hand-built WebGPU fixtures (webGpuHeadlessScene, webGpuHeadlessUi and the desktop tests that call wgpu4k's glfwContextRenderer directly) to the instance-retaining headless bootstrap, then re-evaluate forkEvery = 1 on a host that reproduced the device-request exhaustion. It does not reproduce on lavapipe, even on the pre-fix code, so no run there can show that relaxing it is safe.
Core rendering maintainer: report two wgpu4k lifetime defects upstream: the native Device never releases the queue handle it fetches, and glfwContextRenderer drops the instance it creates. Remove the local workarounds from fix(render): single-sample UI-only targets and deterministic WebGPU teardown #1159 once a pinned wgpu4k build fixes them.
Delivery owner for this PR: recorded verified head, passing CI and clear review, and verified squash merge ce55c4b291d40c98dae3932f7c9746f05f1592c9 in feat(render): add scene MSAA and masked alpha to coverage #1123. Other owned gates remain open.
Accepted limits: configuration is per render plan, default 1x; standard WebGPU negotiates only 1x/4x. Shadow, camera-depth and mask prepasses stay single-sample with hard cutouts. Depth consumers keep using those independent prepasses; no multisampled depth resolve/readback or TAA is introduced. Custom content shaders opt into alpha coverage through their own pipeline spec.
