We need to improve how BrickVerse loads and replicates large worlds. The recent ENet framing changes are a temporary hotfix, but they don't address the long-term scalability issue as creators build larger experiences.
Instead of sending the entire world to every client during joining, we should move towards a streaming-based system similar to Roblox.
What needs to be done
Add chunk-based world loading so clients only download nearby or required content.
Add spatial streaming to load and unload instances as players move around.
Separate static world downloads from live gameplay replication.
Introduce caching to avoid downloading unchanged world data repeatedly.
Improve network prioritization and bandwidth management so world loading doesn't affect gameplay.
Add proper memory limits and cleanup for both client and server.
Why
BrickVerse is a creator platform, and we cannot assume every world will be small. The current approach will become increasingly expensive as instance counts grow, affecting join times, memory usage, and network performance.
The goal is to make world loading scalable without requiring clients to download everything upfront, while keeping gameplay responsive.
