World-space moisture and temperature fields

```
should_carve() computes two full trilinear noise fields (field_a,
field_b - 8 hash samples each) unconditionally for every solid voxel
past the surface-roof and bedrock-floor checks, then combines them with
logical AND: tunnel = cond_a and cond_b. Since a tunnel requires BOTH
conditions, field_b's expensive sample never needed computing whenever
field_a's band check already fails - which is the common case, since
band_a/band_b are narrow bands around NOISE_MID relative to the full
0-65535 hash range.

This runs for every solid voxel in a chunk during generation (32x32x32
per chunk), so it's the single largest cost in the new cave system -
likely the main cause of the reported lag on both surface and
underground, since even surface-area chunks with no visible caves still
pay this per-voxel cost during generation.

Fixed identically in both implementations (GDScript is the parity
reference, Rust is the fast path used by NativeChunkBackend):
- Rust already used && for the final condition, but field_b was a
  separate  computed *before* the &&, so Rust's short-circuit
  evaluation didn't help - the expensive call already happened
  unconditionally. Restructured so field_b is only computed inside the
  branch where field_a's check already passed.
- GDScript had the same eager-both-then-compare structure; same fix.

No threshold or output value changed, purely lazy evaluation - verified
by running the existing Rust unit tests (all 3 cave tests pass,
including determinism check) and confirming the GDScript fallthrough
behavior is identical when tunnel ends up false. Did not run the full
cross-language Godot/Rust parity test locally (would need the complete
native .so built via SCons, which is a large from-scratch build) -
letting CI's existing native build + parity test suite be the final
verification, per usual practice here.
```
