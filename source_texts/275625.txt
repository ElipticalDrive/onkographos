Summary
The resolution slider used to control two unrelated things at once: FEM mesh accuracy, and a completely separate voxel grid built only for visualization (via buildPolygonLaplacian + nearest-node resampling). That extra grid was the source of the "why do I see fewer voxels than FDM at the same resolution" confusion, cost a second meshing pass plus a nearest-neighbour resample on every solve, and gave blocky, inaccurate visuals independent of how good the actual solve was.
Since a P1 tetrahedral mesh's field is already smooth at its own nodes, there's no reason to resample it onto anything. solve_room_modes now extracts the FEM mesh's boundary surface directly (faces belonging to exactly one tet) and returns those nodes' positions, the boundary triangle indices, and each mode's field values at those same nodes — no resampling, no second grid. targetPerAxis is now purely a computation-quality knob; the 3D view renders whatever mesh the solver actually used.
Dart side: introduces RenderMesh (positions + triangle indices) as the shared visualization contract for both solver paths. The native FEM path builds one straight from the FFI boundary-surface data; the Dart FDM fallback (used when native is unavailable) converts its voxel grid's boundary faces into the same shape, so the UI never needs to know which solver ran. ComputedMode3DView is rewritten to render RenderMesh with Canvas.drawVertices for smooth per-vertex (Gouraud) shading, replacing the old flat-shaded voxel-cube-face painter, with triangles depth-sorted back-to-front before a single draw call.
The interior slice view is removed: it was voxel-grid-specific (a horizontal cross-section sampled from cell-centered values) and doesn't have a clean equivalent on a boundary-only mesh. The 3D view already only ever rendered the room's surface, so this doesn't lose any interior information the slice view had that the 3D view didn't already forgo.
Testing
ctest — both native test binaries pass (2/2), including test_api.cpp updated for the new node/triangle struct layout (and the resolution-12 regression test from the previous fix).
Verified worst-case node counts (max mode count, min resolution, a 10-point star; max resolution on a rectangle) stay in the hundreds — well under the Uint16 index limit Canvas.drawVertices requires.
flutter analyze — no issues.
flutter test — 35/35 pass.
