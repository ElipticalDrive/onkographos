Click a part on the PartViews sheet to pin a review note; type it. Notes are plain model data, so an agent reads exact part-space mm from debug /state (and MCP get_state).
Stacked on #904.
API
Solid.raycast(ray, solid) => Option<{ point, normal, distance }> — part mm, either side, on the cached mesh (brute-force Möller–Trumbore; per click, not per frame).
PartViews.pick(pieces, mouse) => Option<{ piece, view, point, normal, distance }> — sheet ray → tile → that view's ortho camera → nearest piece. Pure; no GPU.
PartViews.sheetWith(overlay, pieces) — sheet plus a scene drawn in every view.
New stdlib PartReview (init / input / click / update / ui / pins / sheet): pieces gain a name; ~5 hooks wire it into any app.
Default part viewer embeds it: V → sheet, click pins, notes panel in the sheet's empty corner; pins also drawn in the orbit view. Clicks need "cursor": "visible".
Note shape (in model.review.notes):
```
{ "id": 1, "part": "part", "view": "FRONT",
  "point": { "x": 18.13, "y": -12, "z": 19.4 },
  "normal": { "x": 0, "y": -1, "z": 0 }, "text": "round this edge" }
```
Points are in the pieces' own space as passed to the sheet (0.01 mm), normals 0.001.
Tests
functor-solid: raycast cube/sphere (hit, inside, miss, zero dir).
Prelude: Solid.raycast, PartViews.pick (known screen points → mm in FRONT/TOP, gap/corner miss, nearer piece wins), PartReview (pin, blank-move, edit, add, miss, delete).
SDK e2e part-review.e2e.test.ts (runs in the headless e2e CI job): part-only file → V → /input click at a computed point → ui_event text → /state note within 0.5 mm, right part/view/normal.
Strict build, check:docs.
Review
xreview (Claude + Codex): no Critical/High. Fixed: pins only for shown pieces; note list capped (8, "N earlier"); Note: label; long notes truncated in rows; shared vec3_value; hoisted dir; cursor + entry-name caveats documented. Kept: own ray-triangle test instead of parry (f64, no physics dep in functor-solid). Not done: orbit-view picking, panel scrolling, text-field autofocus.
