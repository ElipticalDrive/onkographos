Motivation
Increases pixel-space dimensionality without touching physics. The study's
core argument rests on renders vastly outnumbering physics dimensions —
that
information asymmetry is what forces encoding models and RSA toward
render-correlated variables. More physics-irrelevant visual variation
strengthens the asymmetry and makes the simulation more realistic.
Secondary goal: lay groundwork for OpenGL/shadow rendering in the
visualization path.
Changes
Scene generation (scene_generator.py)
5 visual-only background spheres per scene (N_BACKGROUND_OBJECTS=5),
random position/size/color/specular
Backdrop wall (large visual plane behind the scene), random
color/specular
Ground color randomized per scene (was fixed gray 0.6)
Cylinder added as a third foreground shape (alongside sphere, box)
Wider object size range: 0.07–0.5 (was 0.1–0.35)
Per-scene camera jitter: ±0.35 m all axes, ±0.2/0.15 target jitter
Per-scene specular on foreground objects
Ambient lighting range: 0.1–0.7 (was fixed 0.4); light color 0.4–1.0,
distance 2.5–10.0
_lock_rotation applied after each sim step (rotation not in observable
physics dims)
SCENE_LIGHTING_DIM: 8 → 74 (15 base + 10 × 5 background objects)
SCENE_CONFIG_DIM: 9 → 13 per object (adds cylinder params + specular)
Reuse one PyBullet connection per batch (resetSimulation between
scenes)
_render_scene accepts use_opengl flag for shadow-enabled
visualization renders
Config (config.yaml)
n_timesteps: 30 → 120
linvel_x_max: 8.0 → 3.0 (object stays on-screen across longer window)
x_accel_max: 15.0 → 6.0
pp_early_frame / pp_late_frame: 5/15 → 40/80
Known issue: PP inverse model fails on these scenes
The SpatialSoftmaxV2 inverse model (validated at R²=0.83 on pre-diversity
scenes) collapses to R²≈0 on the new scenes. Root causes in order of
impact:
Background spheres — the spatial softmax latches onto colorful
background objects whose image coordinates are physics-irrelevant noise.
Camera jitter — same physical position → different image-space
keypoint coordinates in every scene; the head cannot learn the mapping.
Ground/backdrop color variation — fills large image fractions with
random per-scene color, corrupting CNN feature maps.
The inverse model needs an architectural update (or the diversity needs to
be
scoped) before the PP analysis can run. The encoding/RSA/dissociation
analyses are unaffected.
Test plan
uv run snakemake -n dry-run completes without errors
Scene generation produces correct array shapes (metadata assertions
in tests)
uv run pytest tests/test_scene_generator.py
Encoding and RSA results still pass evaluation.py criteria
Decide on PP inverse model strategy before merging to main

Add simplified-CNN diagnostic to probe the GAP bottleneck
…
019711d
```
The prior InverseCNN (scripts/eval_pp_cnn.py + analyses.predictive_processing.
InverseCNNNet) plateaus at mean R²=0.499 on rotation-locked scenes — below the
PCA(50)+MLP baseline at 0.655. Hypothesis: AdaptiveAvgPool2d(1) at the end of
the per-frame conv tower erases spatial position, which is exactly what
pos_x / pos_y prediction needs.

scripts/eval_pp_cnn_simple.py sweeps four progressively-more-CNN-like
architectures on the same val split / schedule (Adam lr=1e-3, ReduceLROnPlateau,
patience=30, max 200 epochs, no BN, CPU):

  variant            params   val_mse   mean R²   min R²   notes
  linear              246k     0.636    +0.361   +0.073   flatten → Linear
  downsample_mlp      199k     0.839    +0.156   -0.005   AvgPool2d(8) → MLP
  gridpool (=4)      1.70M     0.203    +0.796   +0.638   GAP → AdaptiveAvgPool2d(4)
  spatial_softmax      34k     0.243    +0.756   +0.572   DSAE-style (x,y) readout

Reference: PCA(50)+MLP=0.655, prior CNN with GAP (291k)=0.499.

Both gridpool and spatial_softmax clear the PCA+MLP bar by 10-14 R² points
while the prior CNN sat 16 points below it — confirming the GAP bottleneck was
the whole story. spatial_softmax matches ~95% of gridpool's signal at 1/50th
the parameters via an explicit "where each channel fires" inductive bias. The
spec row-3 conclusion ("perceiver isn't the bottleneck") needs revising:
capacity wasn't the issue; head architecture was.

Per-dim R² for the two winners — pos_x and linvel_x saturate near ceiling
(~0.98 / ~0.84), pos_y / pos_z / x_accel are noticeably harder for both:

       dim       gridpool   spatial_softmax
       pos_x       +0.98       +0.98
       pos_y       +0.87       +0.81
       pos_z       +0.64       +0.57
       linvel_x    +0.84       +0.84
       x_accel     +0.65       +0.58

Exploration only: analyses.predictive_processing.InverseCNN is unchanged. Next
iterations will continue here on architecture variants before integration into
the main pipeline.
```

```
Brain state changes from [actual_render | inv_acts | P_hat] to
[fwd_render | inv_acts | P_hat]: the camera bytes are replaced by the
cognitive forward model's predicted render (resimulated from inferred
physics), so raw sensation enters only through the inverse model rather

New gen_forward_renders.py script resimulates all scenes from PP
inferred physics and saves forward_program_states. All three analyses
(encoding, RSA, dissociation) gain an optional Predicted-S feature
family. All figures gain a corresponding bar/column. plot_pp and
plot_pp_frames functions are added (previously a gap). config.smoke.yaml
supports fast end-to-end smoke tests via CONFIG_FILE env var.

predictive_processing.py now slice only the RGBA portion); double-PCA
in dissociation behavioral scoring (raw pixels now used for behavioral
PCA, encoder PCA for neural R² only); PP frame index mismatch in
plot_pp.py (frame_idx saved and used to correctly align forward renders
to oracle test scenes).
```

```
predictive_processing.py was the only resim caller still using the DIRECT
tiny renderer (no shadows) while scene generation uses GUI/OpenGL, and was
comparing against the LATE frame (t=PP_LATE_FRAME) inside program_state
instead of target_renders (t=N_TIMESTEPS). Together these drove the oracle
to R²=-13 and dragged pp_r2 to the same floor, making the physics chain
look catastrophic.

Match the pattern in dissociation.py / dynamics.py: shared open_render_client
with use_gui=True across oracle, pp, and frame-viz resim calls, and switch
the behavioral target to target_renders[:, target_pixel_indices].

Resulting numbers: oracle R² 1.00, pp R² 0.87, render-only 0.67.
```

```
config: encoding_n_null_permutations), refits the physics-only and

r2_physics_only, r2_combined, and ΔR² with 95% CIs and one-sided
```
