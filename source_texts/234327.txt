I couldn't reproduce this with the torch versions gsplat currently supports.
setup.py / pyproject.toml now require torch>=2.7. I ran a minimal repro of the failing line in _decompress_kmeans (params = centroids[labels]), using the same save / load code as _compress_kmeans, so labels comes back from the .npz as np.uint16:
```
npz_dict = np.load(os.path.join(compress_dir, f"{param_name}.npz"))
centroids_quant = npz_dict["centroids"]
labels = npz_dict["labels"]  # dtype uint16

centroids_norm = centroids_quant / (2 ** meta["quantization"] - 1)
centroids_norm = torch.tensor(centroids_norm)
mins = torch.tensor(meta["mins"])
maxs = torch.tensor(meta["maxs"])
centroids = centroids_norm * (maxs - mins) + mins

params = centroids[labels]
```
Output:
```
python 3.13.14 | torch 2.7.0+cpu | numpy 2.5.3
labels dtype: uint16
centroids[labels] OK: shape (5000, 15, 3), dtype torch.float32, equal to int64 indexing: True

python 3.13.14 | torch 2.11.0+cpu | numpy 2.2.5
labels dtype: uint16
centroids[labels] OK: shape (5000, 15, 3), dtype torch.float32, equal to int64 indexing: True
```
So indexing with the uint16 labels works on torch 2.7.0 and 2.11.0, and the TypeError: can't convert np.ndarray of type numpy.uint16 looks limited to older torch versions below the current torch>=2.7 requirement. @ReverseGravity, could you check whether this still happens for you with torch >= 2.7?
