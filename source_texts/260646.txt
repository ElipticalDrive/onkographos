Test only checks for duplicates, not missing faces
The test correctly detects duplicate triangles, but it does not verify that no faces are missed after the change. By always returning False, the fix ensures consistency across adjacent cubes (both choose the same triangulation branch), but in the degenerate case where both cubes previously relied on a positive face value returning True, both will now return False — and neither may generate the face, potentially leaving a hole.
Adding a check that the total face count is non-zero would guard against this regression:
Suggested change
sorted_faces = np.sort(faces, axis=1)
unique_faces = np.unique(sorted_faces, axis=0)
assert len(unique_faces) == len(
faces
), f"Duplicate faces found: {len(faces)} total, {len(unique_faces)} unique"

Comment could explain why False is the right constant
The comment explains what the change does, but not why always returning False (rather than True, or the old sign-based rule) is the correct choice. Both adjacent cubes sharing a face have identical A, B, C, D corner values and therefore the same AC_BD = 0. The original face >= 0 fallback was insufficient to break the symmetry in all configurations, while any constant return value ensures both cubes always make the same triangulation branch choice.
A slightly expanded comment would help future maintainers:
Suggested change
if AC_BD > - FLT_EPSILON and AC_BD < FLT_EPSILON:
return face >= 0
# Returning False avoids adjacent cubes to both generate the same triangle
# on a shared face.
return False;
if AC_BD > - FLT_EPSILON and AC_BD < FLT_EPSILON:
# Degenerate case: adjacent cubes sharing this face have the same A, B, C, D
# values and therefore the same AC_BD = 0. The original `face >= 0` fallback
# could cause both cubes to independently claim the shared face (producing
# duplicate triangles). Returning a constant False ensures both cubes always
# choose the same triangulation branch regardless of their face sign.
return False;
