SUMMARY
The Gaussian trainer's loss uses ssim(). On the CPU, ssim() filtered five moment images (μx, μy, E[x²], E[y²], E[xy]) with five dense 11×11 depthwise conv2d calls. After #30 made the CPU rasterizer fast, these convolutions dominate the CPU train step at 256–512 px (a probe showed ~110 ms of a step at 256 px, scaling with pixels, not with Gaussians).
The 11×11 Gaussian window is the outer product of a 1-D kernel, and zero padding separates as well. So on the CPU the five moments are now stacked as 15 planes (5 moments × 3 channels) and filtered by one vertical and one horizontal 1-D depthwise convolution:
22 instead of 121 taps per pixel;
2 instead of 5 convolutions, in both forward and backward.
The math is the same; only float32 rounding differs. CUDA keeps the dense cuDNN path unchanged, because a probe showed the separable form is not faster there.
Result (CPU, 5000 splats, 6 order-alternated rounds): train step −42 % / −59 % / −68 % at 128 / 256 / 512 px, with 256 and 512 px faster in every round.
TECHNICAL DETAILS
MinkowskiEngine/gaussian/gaussian_trainer.cpp, ssim():
CPU branch: planes = cat({x, y, x*x, y*y, x*y}, 1) → conv2d(planes, k_vertical[15,1,w,1], pad (w/2, 0), groups 15) → conv2d(·, k_horizontal[15,1,1,w], pad (0, w/2), groups 15) → split(3, 1) into the five moments.
CUDA branch: unchanged (dense window × window depthwise filter per moment).
The SSIM map and its mean are computed as before from the moments.
Numerics against the dense float64 reference: value |Δ| < 3e-8, gradient relative error ~2e-6 (float32 rounding of a different summation order).
Memory: the 15-plane intermediate raises the peak working set at 512 px (see BENCHMARKS).
No API change.
TESTING
New tests/gaussian/test_gaussian_ssim.cpp (registered in gaussian_tests):
gaussian_ssim_identical_images_is_one.
gaussian_ssim_matches_dense_reference_cpu: value and gradient against a dense float64 reference, for windows 11/7/3/1, non-square images, and an image smaller than the window.
gaussian_ssim_matches_dense_reference_cuda: the same checks on CUDA.
gaussian_ssim_rejects_bad_arguments.

Technical summary
Investigated. After #30 sped up the CPU rasterizer, profiling the CPU train step showed ~110 ms per step at 256 px left over after the renderer's forward and backward. This cost scales with pixel count, not with the number of Gaussians. It is the SSIM loss: five dense 11×11 depthwise convolutions over the three colour channels.
Change. On the CPU, the five moments are stacked into 15 planes and filtered by two 1-D depthwise passes (vertical, then horizontal): 22 taps per pixel instead of 121, and 2 convolutions instead of 5. CUDA keeps cuDNN's dense filter, because in a standalone probe the separable form was slower on CUDA.
Tests. I added test_gaussian_ssim.cpp: value and gradient against a dense float64 reference on CPU and CUDA (window sizes 11/7/3/1, non-square images, an image smaller than the window), plus SSIM(x, x) = 1 and argument checks.
