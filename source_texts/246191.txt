Implements report row S-3: Position Based Fluids solver (parallel track; Rust source #87, rust/kansei-core/src/simulations/fluid/pbf.rs and PbfPasses in simulation.rs). Acceptance: a solver toggle in index_fluid.
What
FluidSolver is now 'sph' | 'pbf', and SOLVER_WORD packs PBF as 1. The new PbfOptions and DEFAULT_PBF_OPTIONS mirror Rust PbfOptions::DEFAULT, and FluidSimulationOptions.pbf holds them.
packPbfParams mirrors GpuPbf::new, which computes W(dq) as poly6 at dq·h.
latticeDensity(spacing, h) gives the rest density for a lattice fill (Rust lattice_density).
src/simulations/fluid/shaders/pbf.wgsl.ts ports the 9 PBF shaders: predict, lambda, delta, apply, unsort, velocity, gather, vorticity and XSPH. They live inline in Rust strings, so they cannot be imported with ?raw; they are copied with the {{ }}, BODY and __NEIGHBOR_WG__ substitutions done in TS.
FluidSimulation creates PbfPasses lazily on the first PBF step, on the sim's own buffers, grid and SimParams. They are dropped when rebuildGrid replaces the per-cell buffers, as in Rust.
encodeStep has the PBF branch in Rust's order:
predict, then the substep passes run on the prediction;
the grid, then N × (lambda, delta, apply), then unsort;
the bodies and substep passes run again;
velocity, gather, vorticity (only when > 0), then XSPH.
The SPH path is unchanged: same dispatches, same order.
main.ts exports PbfOptions, DEFAULT_PBF_OPTIONS and latticeDensity.
examples/index_fluid.html gets the toggle:
The "SPH" folder is now "Solver", with an SPH/PBF dropdown that switches live.
A PBF panel has iterations, rest density, relaxation, s_corr k/n, XSPH, vorticity and max speed.
?solver=pbf starts the page on PBF.
Rest density is latticeDensity(0.62, 1), the nozzle's spacing, so poured particles join at rest.
Notes:
PBF is 3D only, as in Rust.
The mouse pushes SPH only, because PBF runs no forces pass (same in Rust).
The TS-only FluidBody runs after the projection under PBF, before the velocity is derived.
S-2 ports fill.rs. It should reuse this latticeDensity (in FluidSimulationParams.ts) rather than add a second one.
Verification
tsc && vite build passes, re-run after rebasing on origin/ts-rust-alignment.
Numeric check in Chrome (WebGPU, readback). A scratch page (not committed) ran the same scenario as Rust's tests/fluid_pbf_gpu.rs:
Setup: an 8×12×8 block at spacing 0.537, dropped 1 unit into a 5×5 box, with 4 iterations and 2 substeps, for 360 steps at 1/60.
Result: all positions finite and in the box; mean speed 0.039 (Rust's threshold is < 0.2).
Bulk density / rest: mean 1.001 and max 1.009 over 84 particles (Rust's thresholds are |mean − 1| < 0.05 and max < 1.1).
index_fluid, headless Chrome via chrome-devtools-axi:
SPH looks the same before and after this change.
With ?solver=pbf the fluid settles into a flat pool.
Switching SPH → PBF live makes a splash, because PBF expands SPH's denser pool to its rest density, and then it settles. Switching back to SPH works.
?solver=pbf&nozzle=1 runs.
No WGSL or validation errors in the console.
index_fluid_text, which uses bodies on the SPH path, renders the same as before with no errors.
Not measured: PBF vs SPH frame time. Headless timing on a shared GPU is unreliable; ?profile=1 shows FluidSim/Substep for each solver.
