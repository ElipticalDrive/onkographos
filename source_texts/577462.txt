Security review details
Security Blast Radius
inferred — The demonstrated new outcome is bounded GPU allocation and probe recomputation within the running game instance. Replacement temporarily retains the old allocation while constructing the new one, so transition memory demand exceeds steady-state demand. The optional remote host's wider network and identity exposure remains unverified.
Trust Boundaries and Controls
observed — UI selection offers only three choices, settings loading caps the quality index, and dimension lookup independently caps it again. These controls prevent the new setting from selecting arbitrary texture dimensions; they do not establish authentication for the external settings host.
Resilience and Maintainability Implications
observed — Pending reset suppresses published probe readiness. Prepass clears the replacement volumes before rebuilding probe data, sets readiness after dispatch, and clears compute bindings. Map-menu and resource-validity guards defer processing rather than treating uninitialized probe contents as ready.
Hardening Proposals
proposed — Make resource replacement explicitly render-thread-owned and capture one requested quality for both allocation and active-quality publication. This would make the concurrency invariant auditable across UI and main-thread settings requests; it is not a verified race finding.
