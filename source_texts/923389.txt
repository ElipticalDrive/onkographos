Lets worlds with more than 128 voxel materials (many planet or voxel material mods) draw them correctly: the renderer only handles the first 128, so every material past that is drawn as plain stone. This lifts the limit to 254. Repo: https://github.com/blazeblue32/VoxelMaterialLimit (MIT), pinned at 33d23cc78cc219d25dc415fd8ba9259eb2ec6314.
It changes two things in the shader source as the game reads it for compilation: the size of the voxel material table, and how voxel vertices' material numbers are read back (numbers from 128 up arrive negative). Nothing in the game's files is edited, and it does not call UnpatchAll. On stock setups it hooks the game's shader include reader (nothing is written to disk). On Linux with the LinuxCompat plugin, which compiles shaders natively and bypasses that reader, it writes a local mirror of the player's own shader folder (links plus two rewritten copies) under the user data Storage folder and points only the voxel material shader compiles at it. It has no network access and starts no processes. If a game update changes what it looks for it logs a WARNING and does nothing.
Tested on game 1.210.014 with Pulsar 2.4.3 (-sources build) on Linux CoreCLR: a world with 188 voxel materials (Satreus, Planet - Miasma and others) drew correctly. The code compiles for net10 and net48 and without LOCAL_BUILD. Not yet run on Windows, .NET Framework or Mono.
