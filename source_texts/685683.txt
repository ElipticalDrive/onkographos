Instead of calling march function in PathTracer each time the volume is entered, we treat volume scattering in the same way we treat surface scattering, using PathTracer::trace function.
As we need to obtain somehow a position of the next volume scattering, instead of tracing the ray to the next surface in PathTracer completely, we sample the distance and create volumetric shading point. Since importance distance sampling might depend on the scene lights (with backward tracing) or on camera (with forward tracing), the whole procedure of obtaining the next shading point is delegated to the visitors.
Each distance sample contains information about the phase function at the sampled point. Since now there is a BSDF wrapper around phase functions, both direct lighting integration and the bounce itself can be processed in a general way, just like normal surface BSDF.
It seems that integrating direct lighting over the entire ray via several distance samples does not fit well with the entire path tracing architecture and isn't applicable to non-homogeneous volumes, though it can decrease the variance. One distance sample which is used both for determining the bounce and for the direct lighting integration allows to trace more rays per second and the overall result looks not much worse that the original one.
