IMPROVEMENTS.md §3.1
Current state: Commented-out orbital renderer concept. No actual orbital computation.
Fix: Compute hydrogen-like atomic orbital wavefunctions (spherical harmonics × radial functions). Render as 3D isosurfaces via marching cubes, or as volumetric ray-marched textures.
Implementation:
Compute ψ(r,θ,φ) = R_nl(r) × Y_lm(θ,φ) for selected orbitals
Evaluate on a 3D grid (e.g., 64³ voxels around the atom)
Extract isosurface at |ψ|² = threshold using marching cubes algorithm
Render positive and negative lobes in different colors (red/blue convention)
Support: 1s, 2s, 2p, 3s, 3p, 3d orbitals (covers most of general chemistry)
Toggle orbital display per atom from the PropertyPanel
For multi-electron atoms, use Slater-type orbitals with effective nuclear charge Z*
Complexity: High

Risks / Open Questions
Performance: 64³ grid evaluation may be slow for complex orbitals. Mitigation: only compute for selected atoms, cache aggressively, consider reducing to 48³ if needed.
Marching cubes tables: The edge table and triangle table are large (256 + 256×16 entries). Will include as static const arrays with citation (Lorensen & Cline, 1987; Paul Bourke's polygonising tables).
Slater's rules accuracy: Slater's rules give approximate Z* values. For educational purposes this is sufficient, but more accurate Clementi-Raimondi values could be used as a follow-up enhancement.
d orbital rendering: 3d orbitals have complex nodal structures. The 64³ grid should be sufficient but may need higher resolution for clear visualization of d_xy, d_xz, d_yz lobes.

Reflection — Issue #11: Orbital Visualization
What was delivered
Hydrogen-like atomic orbital computation (src/data/orbital.ts): Radial wavefunctions R_nl(r) with associated Laguerre polynomials and real spherical harmonics Y_lm(θ,φ). Uses Clementi-Raimondi effective nuclear charges (Z*) for Z=1–20 and Fe.
Marching cubes isosurface extraction (src/data/marchingCubes.ts): Paul Bourke lookup tables, gradient-based normals, returns indexed triangle mesh.
Electron configuration parser (src/data/orbitalData.ts): Parses "[He] 2s2 2p4" format with Hund's rule filling, enumerates available orbitals with quantum numbers.
3D orbital renderer (src/renderer/OrbitalRenderer.tsx): R3F component rendering positive (red) and negative (blue) lobes as translucent isosurfaces.
UI controls in PropertyPanel: orbital toggle, orbital selector dropdown populated from electron config, isovalue slider.
10 physics tests (ORB-01 through ORB-10): Spherical harmonic normalization, radial wavefunction normalization, node counting, Z* lookups, marching cubes mesh validation, lobe sign verification.
Architecture decisions
Placed pure math (orbital.ts, marchingCubes.ts) in src/data/ rather than src/engine/ to respect the eslint-plugin-boundaries layer rules (renderer can only import from data/store, not engine).
Used useMemo in the renderer to cache expensive grid/mesh computations, only recomputing on orbital selection or isovalue changes.
Bugs found and fixed
Radial normalization factor: Initial implementation used Math.pow(factorial(n+l), 3) but Griffiths Eq. 4.73 requires just factorial(n+l) — the ³ exponent belongs only to the (2Z/(na₀))³ prefactor. Caught by ORB-05 test.
Unicode in JSDoc: Non-ASCII characters (ψ, θ, φ, etc.) in comments caused ESLint parser failures. Replaced with ASCII equivalents.
Test results
All 66 tests pass (up from 27 pre-orbital, including 5 bond detection tests merged from #23 concurrently). Physics test ratchet updated to 66.
Follow-up opportunities
d-orbital visualization (3d, 4d) for transition metals
Orbital energy level diagram
Electron density surface (sum of occupied orbital |ψ|²)
Web worker offloading for grid computation on larger grids
Closing this issue. PR #118 merged via squash.
