Summary
Adds nine resampling filters to ResamplingFilter: Box, Hermite, MitchellNetravali, Robidoux, RobidouxSharp, Spline, Lanczos2, Lanczos5 and Lanczos8 (enum values 4–12).
Closes #3630
What changed
Kernels (ResamplingKernels): the Mitchell-Netravali cubic family, with B and C as parameters (Hermite B=C=0, Mitchell B=C=1/3, Robidoux and Robidoux Sharp Keys cubics, B-spline B=1), and Lanczos generalized to n lobes. The existing kernels are unchanged, bit for bit.
Box averages the source pixels whose centers lie in the footprint of the output pixel. The boundary at the footprint's end is included, so on a tie the higher pixel wins, as with nearest neighbor and ImageMagick. ResampleAxis.GetBoxContributors computes that range exactly from the rational axis, so ties never depend on floating-point rounding (for example at a 7 → 6 downscale).
Mitchell, Robidoux and Spline don't interpolate: they also smooth an axis that keeps its size. A resize that keeps both sizes still leaves the image unchanged. Both points are documented on the enum and in the readme, which now has a table of the filters.
Every filter goes through the existing weight tables, so linear sRGB, alpha weighting, 16-bit samples, the 8-bit fixed-point path and the parallel/SIMD loops all apply unchanged.
API design: the type stays an enum. CreateCubic(b, c) would need ResamplingFilter to become a type, a breaking change; the issue marks it optional. There are no Triangle/CatmullRom aliases, because Bilinear/Bicubic are those kernels and duplicate enum values make ToString() ambiguous.
Validation
Formulas: kernel values at known offsets are checked against closed forms (AdditionalKernelValuesMatchTheirDefinitions). New hand-derived resize cases cover Box ties (2→5, 3→2, 7→6), a Mitchell downscale, and smoothing of an axis that keeps its size.
Exact reference: TestHarness/Resampling/ReferenceResampler (exact fractions, decimal kernels) gets all nine kernels. ResizeGoldenTests therefore checks each one in both working spaces and every anchor, downscaling and upscaling, and three new corpus specs were added (box, Mitchell, linear Lanczos8). As a mutation check, changing Robidoux Sharp's B by 0.1% fails the suite.
ImageMagick 7.1.2-15 Q16-HDRI (Docker, -filter <name> -resize WxH!) on a 64x48 16-bit image, at 24x18, 32x24 and 100x75:
Every pixel whose support lies inside the source is within 1/65535, for all 12 kernel filters.
Box is identical everywhere.
At the edges the outputs differ by up to 6.4/255, because ImageMagick renormalizes the weights there while the library repeats the edge pixel.
Following the fixtures README, ImageMagick output is not stored as a reference. The check and how to reproduce it are documented in that README.
Performance: new benchmarks for Box, BoxOpaque, MitchellNetravali, MitchellNetravaliUpscale and Lanczos8. An A/B run against main (fixed iterations, retired instructions) shows the existing Bilinear, Catmull-Rom, Lanczos3 (alpha and opaque), Catmull-Rom upscale and 16-bit workloads within ±0.4%, which is inside the noise.
Tests: Meziantou.Framework.Imaging.Processing.Tests passes in full on net10.0 and net11.0 (8,699 tests each). The related Meziantou.Framework.Imaging.Tests classes (benchmark workloads, defaults, vectorized kernels, performance contracts) pass on both TFMs. Release builds succeed, and dotnet run ./eng/update-all.cs exits 0 with no further changes.
