What
cubicBezier solved each sample with Newton-Raphson plus a bisection safeguard at 1e-14 tolerance, about 10 curve evaluations per call.
It now samples x(t) at 32 points on creation and builds a table of starting guesses. Each call reads its start t by index, takes 2 Newton steps, and accepts the result when the estimated error is ≤ 1e-10. Otherwise it continues with the old bracketed solver from there (near-flat curves, zero or NaN slope). The linear fast path is unchanged, x <= 0 and x >= 1 now return exactly 0 and 1, and the table loop is bounded.

```
cubicBezier solved each call from t = x with Newton-Raphson and a
forward-difference slope, about 4-5 iterations (9-10 curve evaluations)
per sample.

At creation it now samples x(t) at t = i / 32 and interpolates a table
of starting guesses for t at x = j / 32. Each call takes two Newton
steps with the analytic slope from the interpolated guess. If the steps
do not show quadratic convergence (error estimate step2^3 / step1^2 >
1e-10), or t is NaN or outside [0, 1], it continues with the previous
bracketed Newton-Raphson solver. The branch is predictable, so typical
curves stay on the two-step path.

CSS ease, create + 100k samples (median of warm runs):
- Node 24: 2.1 ms -> 0.9 ms
- Headless Chromium: 2.2-2.8 ms -> 0.9-1.3 ms (first run in a fresh
  page 3.6 ms -> 2.3 ms)
easeIn, easeOut, easeInOut and backInOut speed up by similar amounts.

Creation goes from ~0.01 to ~0.1 us (33 curve evaluations). Max error vs
an exact BigInt reference is < 2e-10 on the standard curves and < 1e-8
on 1000 random curves (was ~1e-13). x <= 0 and x >= 1 now return exactly
0 and 1. Bundle cost is +160-200 B gzip on scenarios that include it.

Tests compare against a BigInt high-precision reference on named curves
(including backInOut, 0.68, -0.6, 0.32, 1.6) and 100 seeded random
curves, and check exact endpoints and the linear fast path.
```
