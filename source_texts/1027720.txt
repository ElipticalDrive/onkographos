This PR adds direct support for geographic datasets with some help from Claude.
The underlying approach for spherical data in the shader works for geographic data just as well with some initial pre-processing to scale geographic coords to spherical, so it mostly amounts to adding that pre-processing normalization and differentiating between the "rendering coordinate system" (always spherical) from the yt dataset coordinate system (spherical, internal_geographic, geographic).
Some extra bells and whistles:
cause the latitude / co-latitude direction is opposite, needed a uniform to reverse axes
handling the longitudinal wrapping (needed more for geographic data, but technically works for spherical data too)
a reference_height kwarg to override surface_height/outer_radius in case the yt dataset has it set to 0 (which results in a sphere rather than a shell)
fixes cartesian bbox cusps for negative or 0-spanning phi.
One thing I didn't add but probably will in a followup is a radial exaggeration factor: thin-shells that are common for atmospheric data at the scale of the whole-earth will be hard to resolve, so adding a radial scale would blow it up and make features resolveable.
