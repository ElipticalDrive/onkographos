📝 Walkthrough
Adds a public closest_hit_on_mesh API and CUDA implementation. The query traverses a mesh BVH and returns nearest-hit distances and face IDs, with interval and optional backface-culling rules. CUDA tests compare results with reference intersections and cover shared edges and vertices.
Changes: Mesh ray queries
Layer / File(s)
Summary
Expose and dispatch closest-hit queries
comfy_kitchen/__init__.py, comfy_kitchen/backends/cuda/__init__.py, comfy_kitchen/backends/cuda/dlpack_bindings.cpp, README.md
The package and CUDA backend expose closest_hit_on_mesh. The backend validates ray shapes and device placement, registers the operation for supported CUDA inputs, and forwards query parameters to the CUDA launcher. The README capabilities matrix lists CUDA support.
Implement ray intersection and BVH traversal
comfy_kitchen/backends/cuda/ops/mesh_bvh.cu
The CUDA implementation clips rays against BVH boxes, tests triangles with a watertight intersection method, and visits nearer children first. It returns the nearest hit or the documented miss values.
Validate closest-hit results
tests/test_mesh_bvh.py
Tests compare results with a float64 reference and cover mesh sizes, intervals, backface culling, validation errors, vertices, and shared edges.

Add deterministic endpoint cases to test_ray_interval.
The test uses random rays, so it does not guarantee a true hit at tmin or tmax. An implementation that changes the interval to closed bounds can therefore pass the test while violating the public contract. Add two deterministic rays that hit exactly at each endpoint and assert that both return misses.
Suggested fix
