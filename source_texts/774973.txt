Why this exists (plain version)
A .cube LUT is a 3D colour lookup table: for a grid of input colours it stores what each should become, and colours in between are interpolated. It's how film emulations and colourists' grades are shared, so it gives looks a breadth that hand-written operations can't. Two things matter:
The colour space. A LUT built for sRGB values gives nonsense on anything else, so every lut operation says what it expects.
How in-between colours are blended. We use tetrahedral interpolation, which keeps greys grey (see the learning note).
Per plan D8 it's our own numpy code. colour-science is only the test oracle.
Stacked on #133. Nothing renders differently: no built-in look uses a LUT yet.
Closes #119.
Summary
picturesq.colour.lut (pure):
parse_cube reads TITLE, LUT_1D_SIZE / LUT_3D_SIZE (3D at most 65), DOMAIN_MIN / MAX, LUT_*_INPUT_RANGE, comments and entries with red changing fastest. Errors name the line.
apply_lut_3d: tetrahedral interpolation. Sorting the fractions in each grid cell picks the tetrahedron, so all six cases are one formula. Inputs outside the domain are clamped.
apply_lut_1d: per-channel linear interpolation.
lut operation (display-referred):
file is relative to the look file, with no . / .. parts, and must end in .cube.
input_space is srgb (default) or rec709 (BT.1886 gamma 2.4, new bt1886_encode / decode).
amount (default 1) blends the result with the input, and intensity scales it. The result is clipped to 0–1.
Loading: load_look_file reads and parses each LUT a look uses, so a missing or broken file fails when the look loads. The look's sha256 now covers the look file and its LUT bytes, so the sidecar detects a changed LUT. Look.resolve attaches the tables; an operation applied without its table raises LutNotLoadedError.
Docs: #### lut (display) reference; regenerated look schema; learning-log entry on 3D LUTs and tetrahedral interpolation.
Test plan
ruff, pyright: clean. uv run pytest: 858 passed.
New tests/unit/test_lut.py (29 tests):
Parsing 3D, and 1D with a domain; eight malformed files, each with its message.
The identity LUT is the identity at sizes 2, 17 and 33.
colour-science oracle (LUT3D.apply, table_interpolation_tetrahedral) at sizes 2, 9 and 17, and with a non-unit domain: within 1e-5 (measured 9e-8). Clamping outside the domain.
With a neutral grey diagonal, random greys stay grey (spread < 1e-6).
The operation: identity in both spaces; a LUT that halves sRGB values halves the encoded value; amount and intensity blends (0.5 × amount, 0.5 × intensity, 150 %); unloaded tables; paths outside the folder rejected.
Look files: the LUT loads and is part of the hash; missing and invalid LUT errors.
Learning note
What a 3D LUT is, and why tetrahedral interpolation. A demo cell: mid grey through trilinear comes out (0.5, 0.5, 0.54), through tetrahedral exactly (0.5, 0.5, 0.5).
