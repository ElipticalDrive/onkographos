In the Render settings, under Geometry > Volume Sampling, the bigger the step size and the smaller the max steps, the faster the render, but also the less accurate the result. You have to find the optimal value in your context.
Also in Branched Path Tracing Sampling mode, you can set all the samples other than Volume higher than Volume.

Branched path can help with volumes in some cases, although it's awkward to use with GPUs since it has more memory overhead, and too many subsamples can lead to a TDR timeout. (which it sounds like you're experiencing)
Are you using branched path or plain path tracing? Try plain path, especially with GPU. At least until you've narrowed down where the issue is. Is this a homogeneous volume, aka no connections to the volume shader node's inputs or the "homogeneous" flag enabled in material/world properties. Otherwise, you get a heterogeneous volume which is much slower. (note that "step size" is for heterogeneous volumes, homogeneous volumes do not use steps as they do not have any changes to step through)
Also, I've had a lot of luck rendering volumes on a separate render layer with the rest of the geometry on layers set as mask layers, so you get a layer of just the volumes that you can comp over. Don't ask me why this is so much faster (as I think mask layer only affects the first hit) but it is.
