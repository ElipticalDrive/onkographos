Summary
Stacked on #238. The ray-cast depth camera stops being its own sensor type: the only entry point is a regular CameraSensorConfig with isaacsim.renderer = "raycast". Isaac Sim then renders it with #238's Warp kernel instead of an RTX TiledCamera; other backends ignore the field and render the camera natively, like every other isaacsim option.
```
CameraSensorConfig(
    mount=...,
    data_types=["depth"],
    isaacsim=IsaacSimCameraConfig(renderer="raycast", raycast_link_meshes={"pelvis": "...STL", ...}),
)
```
Changes
Config (config_types/sensor.py): RayCastDepthCameraConfig is removed. IsaacSimCameraConfig gains renderer: "rtx" | "raycast" (default "rtx") and raycast_link_meshes — robot link -> mesh file(s), ray cast against at the link's current pose in addition to the terrain (Add a Warp ray-cast depth camera sensor #238's self_occlusion). A ray-cast camera must be depth-only, pinhole (no f_stop), and mounted on a robot link; raycast_link_meshes requires renderer="raycast".
Isaac Sim (simulator/isaacsim/sensor_setup.py, isaacsim.py, utils/sim_utils.py): a ray-cast camera is a regular camera record. register_cameras creates its RayCastDepthCamera in sim.raycast_cameras (next to sim.tiled_cameras) and sets its re-render callback; render_cameras renders it on the camera's cadence. Only RTX cameras get a TiledCamera, de-instance the robot, enable the renderer, or constrain render_interval, so a ray-cast-only run doesn't start the RTX pipeline.
SensorManager is back to main: Add a Warp ray-cast depth camera sensor #238's separate shared-camera registry (SharedCameraRecord, register_shared_camera, render_shared) is removed. The mount-randomization term finds its camera in sim.raycast_cameras.
MuJoCo: back to main; a ray-cast-configured camera is a normal native camera there.
Preset: g1-head-d435i-depth is a CameraSensorConfig with renderer="raycast". Its near is now 0.01 (was 0): native renderers can't use near=0 (MuJoCo classic aborts, MuJoCo Warp returns no hits), and returns between 1 cm and the D435i's 0.3 m range are still kept for the preprocessing clamp.
Notes
Depth differs from RTX near the horizon, by design. Add a Warp ray-cast depth camera sensor #238's kernel casts rays through integer pixel coordinates (its documented convention); RTX samples pixel centres. Next to an RTX camera on flat ground the ray-cast depth reads ~1 % nearer in the near field and up to ~8 % nearer in the pixels next to the horizon (median −2.6 %); camera pose agrees to < 1 mm. So the live test checks the ray-cast path itself rather than RTX parity.
setup_depth_camera_mount (the opt-in mount randomization) still raises if its camera isn't ray-cast, so it can't be enabled for a camera MuJoCo renders natively.
Validation
Live Isaac Sim test_raycast_camera[frame|rerender]: a ray-cast-only run builds no TiledCamera and runs no RTX sensor; raising the robot in two envs and re-rendering only those envs, without stepping, moves their depth while the third env's frame is unchanged.
No-sim: config validation for the renderer rules; Add a Warp ray-cast depth camera sensor #238's kernel tests render a CameraSensorConfig into a regular camera record.
pre-commit and full mypy . are clean.
In progress after the shared-camera removal: full no-sim suite, Isaac Sim camera/LiDAR/render-cadence/frame-freshness tests, MuJoCo camera tests.

```
Sensors render at FRAME_END, before terminations and resets run, so an env
that is reset (or teleported by any other code) in a control step is
observed with a sensor frame of its state before the overwrite. Stateful
observation terms have no way to learn about such teleports either, other
than reading another component's private flags.

- BaseTask.notify_state_overwritten(env_ids) records overwritten envs;
  reset_envs_idx calls it after writing the new state. Before the next
  observation compute, the task re-renders those envs for sensors that
  support partial rendering and calls on_state_overwritten(env_ids) on
  stateful observation terms, once per compute with all such envs.
- SensorRecord.rerender is an optional per-sensor partial-render callback,
  and set_buffer_rows overwrites rows of a buffer with the same depth
  clipping as set_buffer. No existing sensor registers a callback yet, so
  their behaviour is unchanged.
- ObservationTermBase.on_state_overwritten defaults to a no-op.
```

```
WarpDepthCameraConfig is a new SensorConfig: a pinhole depth camera mounted on
a robot link that casts one ray per pixel against the terrain mesh and against
selected robot link meshes at their current poses (self-occlusion). It reads
only backend-neutral simulator state (rigid_body_pos_w / rigid_body_quat_w,
find_rigid_body_indice, the terrain term's warp_mesh), so IsaacSim, MuJoCo and
IsaacGym register and render it through the same shared code. Its frames are
read with get_camera_data(name, "depth") like any depth camera, and it
supports re-rendering a subset of envs, so envs reset in a control step are
observed at their new state.

- SensorManager.register_shared_camera / render_shared run shared-code cameras
  on their own cadence; collect_due and `cameras` keep returning only
  backend-rendered cameras, so backend render loops are unchanged.
- The kernel follows the PHP release depth camera: rays through integer pixel
  coordinates, image-plane depth, nearest robot hit unless terrain is closer.
- g1-head-d435i-depth preset: the D435i head rig used for perceptive
  locomotion (106x60, 58.6 deg vertical FOV, 27 deg pitch, per-env mount
  perturbation), with leg, waist and arm self-occlusion; adds the combined
  pelvis mesh.
```

```
The cosine correction measured against pixel (width // 2, height // 2)
while K puts the principal point at (width / 2, height / 2), so odd
image sizes were half a pixel off the optical axis; the principal ray
is the camera's +Z axis. Launch rows-major so neighbouring threads
write contiguous pixels, and on torch's current stream so the pose
writes before and the reads after are ordered on any stream. Output
at even sizes is unchanged.

Camera defaults now match CameraSensorConfig; the D435i values stay in
the G1 preset. Move the config and preset tests next to the code they
cover, and test the shared-camera manager API without Warp.
```

Add a ray-cast renderer for Isaac Sim depth cameras
…
407978f
```
CameraSensorConfig.isaacsim.renderer selects how Isaac Sim produces a camera:
"rtx" (default) keeps the TiledCamera; "raycast" builds an IsaacLab
MultiMeshRayCasterCamera that ray casts depth against USD meshes. Ray-cast
cameras are depth-only and pinhole-only, skip the RTX render pass entirely,
and re-render only the envs reset or teleported in a control step.

- IsaacSimCameraConfig gains renderer, body_filter (default: the mount body,
  so a camera inside a link's mesh sees past it) and mesh_prim_paths, with
  the same discovery semantics as the Isaac Sim LiDAR.
- The LiDAR's IsaacLab 2.3.2 fixes (disabled rigid-body tracking and the
  owner-to-mesh pose composition) move to a shared ray-caster base used by
  both sensors; the camera also composes its mount prim's offset from its
  physics owner, which the upstream camera omits.
- LidarBodyFilterConfig is renamed RayCastBodyFilterConfig (alias kept);
  mount resolution, target configs and body-filter discovery are shared.
- Only RTX cameras enable the renderer or constrain render_interval.
```
