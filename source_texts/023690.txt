Summary
This PR introduces octree and quadtree functionality to meshio++, enabling adaptive mesh generation around 3-D surfaces and 2-D planar polylines respectively. Leaves are fine only where the skin is located, with coarser cells elsewhere, providing an efficient alternative to uniform voxelization.
Key Changes
New octree operation (operations/octree.hpp and operations/octree.cpp):
Generates adaptive hexahedron (3-D) or quad (2-D) leaf meshes around a skin
Supports multiple refinement criteria: uniform levels, curvature-based, feature edges, and target edge sizes
Implements 2:1 balancing rules for conforming transitions between levels
Supports three fill modes: all cells, surface-touching cells, and interior cells
Includes signed-distance computation for inside/outside determination
Produces output in Morton order with deduplicated corner points
New planar_skin detail module (detail/planar_skin.hpp and detail/planar_skin.cpp):
Shared infrastructure for 2-D voxelization (pixels) and quadtrees
Extracts polylines from line cells or boundary edges of triangle/quad cells
Implements segment/box overlap testing and signed-distance kernels for 2-D geometry
Supports automatic plane detection (XY, XZ, YZ)
2-D voxelization support in voxelize:
Extended VoxelOptions to support 2-D pixel grids (resolution with zero z-component)
Automatically selects 2-D mode for polyline-only meshes with cell size
Generates quad cells on a 2-D lattice with shared corner deduplication
Comprehensive language bindings:
Python: _octree.py (numpy reference implementation), _planar_skin.py, CLI integration
C API: mio_octree_opts struct and mio_octree() function
Fortran, Julia, R, WebAssembly, and MCP bindings with full option support
Testing and documentation:
C++ tests validating sphere/circle geometries and 2:1 balancing
Python tests with byte-for-byte parity between C++ and numpy implementations
Comprehensive documentation in doc/octree.md
Example Jupyter notebook (38_octree.ipynb)
Implementation Details
Morton ordering: Uses bit-spreading technique for efficient space-filling curve ordering
Hanging nodes: Supports both conforming (with transitions) and non-conforming (hanging node) modes
Plane detection: Automatically determines 2-D plane from mesh extent or explicit specification
Lattice sharing: Both octree and voxelize use the same detail/grid_lattice.hpp numbering scheme
Python parity: The numpy implementation mirrors the C++ code step-for-step for byte-for-byte reproducibility
