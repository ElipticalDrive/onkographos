Summary
Fixes the mask overlay's raymarch compositing so its opacity behaves as a real transparency control: previously, lowering opacity made mask boundaries look blurrier instead of more transparent, and a thick masked region's interior stayed dark regardless of how low opacity was set.

Review notes
Root cause: the raymarch's mask block ran the same front-to-back compositing formula the density pass uses on every step where the mask was present, not once. That's correct for a substance whose apparent opacity should grow with how much of it a ray passes through, but a segmentation mask is a boundary label, not a substance with thickness -- per-step compositing converged toward full opacity within a few steps regardless of the configured alpha, while the boundary itself smeared across however many steps it took to build up that accumulation.
Fix tracks the previous step's mask class (prevMaskClass) and composites the highlight only on a crossing (prevMaskClass == 0 && maskClass != 0) -- once per boundary the ray passes through. Deliberately does not add a separate "interior wash" tint -- see the PR's Rendering Spec changelog entry for why, and how one could be added later without reintroducing this bug.
Testing
Shader compiles cleanly to WGSL and SPIR-V, both wasm-macos and native compile_shaders targets.
Native ctest unaffected (shader-only change).
Confirmed fixed via real-device mobile testing over a Cloudflare tunnel.
