Each GPU previously staged a complete volume even when views were split across cards. CPU-backed volumes and sinograms now execute through automatic spatial tiles and view batches, so projection and the matched adjoint can run when a complete volume exceeds the CUDA allocator's capacity.
This PR is stacked on #12, with codex/native-detector-surfaces as its base. Its diff contains the chunking work; retarget it to main after #12 merges.
Changes
CPU inputs automatically stream through the existing CUDA kernels. CUDA inputs retain the original full-volume path when a conservative working-set estimate fits. Outputs are float32 on the input device; data gradients return to its original dtype/device.
Size against participating devices' live memory and the observable PyTorch process ceiling, with 25% headroom. Account for native allocator segment sizes, existing live allocations, cone layouts, view/geometry buffers, output gathering and collective scratch. Ignore devices receiving no views unless they own an output or collective. volume_chunk_shape and view_chunk_size are optional manual overrides; their default is automatic.
Preserve the global voxel lattice, clipped tails, matched adjoint, data Hessians, first-order frame/surface gradients and saved forward geometry. Streamed surface callbacks return CPU offsets; a fitting CUDA full-volume call still accepts CUDA callbacks. Full-path surface estimates include world-point sampling for the total trajectory before view sharding.
Keep distributed view ordering and SUM/loss-scaling conventions. Ranks agree on a common plan; CPU-backed NCCL reductions use bounded CUDA staging.
Add a CPU-backed CGLS example, English/Chinese entry points, the chunking guide, migration/distributed/API notes, 115 independently written chunking test cases, and 17 formal checks. CI checks the new example's command-line help.
Validation
CUDA chunking tests (including two-GPU and NCCL cases), the new formal checks and CI pass.
Limits and compatibility
No breaking change, migration, new dependency or environment variable. To keep GPU residency bounded, place full data, trajectory tensors and learnable surface parameters on CPU. Full arrays, gradients and iterative state still need host RAM; each distributed rank retains its host volume. Caller CUDA geometry and callback intermediates consume additional memory. Older PyTorch versions without the public memory-fraction getter require explicit limits to respect a separately configured process ceiling. Concurrent allocations can invalidate an estimate.
Analytical FBP/FDK retains its existing execution path; the new reconstruction example reuses CGLS outside the core projection/adjoint API. Tile summation preserves the Siddon model with float32 rounding differences from accumulation order.
Implementation references
Inspected primary source at pinned revisions for host-backed work splitting, tile-local geometry and additive operators: ASTRA, TIGRE, tomosipo, TomoPy, RTK, and LEAP. Numerical kernels remain DiffCT's existing implementation; no reference source was copied. Native allocation bounds follow PyTorch's allocator source.
