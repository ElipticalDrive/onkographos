# Butterfly Swarm — art from pure mathematics

There is no 3D model here. No mesh, no textures, no artwork of any kind. The butterflies exist only as a set of equations, evaluated independently for every pixel, every frame. Change a coefficient and the creature changes shape.

## How a picture comes out of an equation

Nothing is ever *drawn*. Instead, each pixel asks a question about space.

**1. Every pixel casts a ray.** A pixel is a direction looking out from the camera, so the points it can see form a line:

$$p(s) = o + s\,\hat{r}$$

**2. A function answers "how far to the nearest surface?"** This is a *signed distance field*. `sdWing`, `sdBody` and `sdAntenna` each take a point in 3D space and return the distance to that part of the animal. Nothing is stored — the shape is defined entirely by the arithmetic.

**3. The ray walks forward by whatever distance is safe**, repeatedly, until that distance falls near zero. This is *ray marching*, and it makes the image a solved equation rather than a rasterised object.

## The wing problem

A jellyfish bell is a blob, and blobs are easy. A butterfly wing is a **thin sheet that bends while it flaps**, which is much harder: the surface is different at every instant, so it cannot simply be looked up.

The trick is to work backwards. Flapping is a rotation about the body's long axis, and rotation about that axis leaves the distance from it **unchanged**:

$$\mathrm{span} = \lVert p_{xy} \rVert$$

So `span` is a coordinate the flap cannot disturb — it labels how far out along the wing a point sits, no matter where the wing currently is. That makes it safe to *un-bend* the point: rotate it back by the local flap angle, and evaluate a simple flat wing shape in the resulting plane.

```glsl
float span = length(p.xy);
vec2  q    = rot(-flapAngle(span, t, phase)) * p.xy;
```

The wing outline is then just two rounded triangles in 2D — a forewing and a hindwing, kept separate so a notch survives between them.

Because the un-bending transform is not rigid, distances in that flattened space are slightly overstated, so the marcher takes deliberately conservative steps. Trading a little speed for correctness here is what stops rays tunnelling through the membrane.

## How the mathematics creates life

**The wing bends because the tip is late.** The flap angle samples the stroke at a *delayed* phase further out along the span:

$$\theta = \Theta\!\left(t - \lambda\,\mathrm{span}\right)$$

Nothing models elasticity, yet the wing visibly flexes: the root leads, the tip trails, and the membrane appears to whip through the stroke. One subtraction buys the entire effect.

**The stroke is asymmetric.** A real butterfly snaps the downstroke and coasts the recovery. A sine wave spends equal time on both and looks mechanical, so the cycle spends 36% of its time going down and 64% coming back:

```glsl
x < 0.36 ? smoothstep(0.0, 1.0, x / 0.36)
         : 1.0 - smoothstep(0.0, 1.0, (x - 0.36) / 0.64)
```

**Backlighting does the rest.** Wings are thin enough to transmit light, so the shader adds a term that brightens as the surface turns *away* from the sun while the camera looks *toward* it. That single term is why the swarm glows against the dark canopy instead of looking like painted card.

**The dorsal axis is anchored toward the camera.** Deriving orientation from velocity alone is more physical, but leaves butterflies edge-on and lifeless most of the time. Each one keeps a camera-facing bias, varied per individual, and its heading lives in the remaining freedom.

## Running it

Requires [`uv`](https://docs.astral.sh/uv/), `ffmpeg`, and a driver supporting OpenGL 3.3.

```powershell
uv sync
.\render.ps1
```

Roughly one minute of rendering per 10 seconds of output on integrated graphics. Options:

```powershell
.\render.ps1 -Duration 15 -StartTime 4 -Fps 30 -OutFile study.mp4
```

Single frames are near-instant, which is the sane way to iterate on a shader:

```powershell
uv run python preview.py 1            # one frame at t=1
uv run python preview.py 1.0 2.4 3.8  # contact sheet across a wingbeat
```

## Colour, measured rather than guessed

`palette.py` reports mean RGB across the shadow, midtone and highlight bands of an image.

```powershell
uv run python palette.py preview.png
```

Two measured problems shaped the final look:

- **Gamma lifts near-black hard.** A woodland that looked correctly dark in linear values came out at `rgb(24, 50, 39)` in the shadows and the butterflies stopped glowing. Background values had to drop roughly fourfold before the subject read as luminous.
- **Tonemapping desaturates the brightest colour.** Exponential tonemapping compresses the dominant channel hardest, so vivid orange drifted to tan exactly where the wing was brightest. A chroma-preserving step after the tonemap restores it:

```glsl
float lum = dot(col, vec3(0.2126, 0.7152, 0.0722));
col = clamp(mix(vec3(lum), col, 1.32), 0.0, 1.0);
```

## The poster

[`poster.jpg`](poster.jpg) composites a rendered frame with the governing equations typeset by Manim's `MathTex`.

```powershell
uv run manim -s -r 1080,1920 -o poster poster.py Poster
```

This step needs LaTeX, since `MathTex` shells out to it — the animation itself does not. On Windows:

```powershell
winget install --id MiKTeX.MiKTeX --exact --scope user
initexmf --set-config-value "[MPM]AutoInstall=1"
```

The `AutoInstall` line matters: without it MiKTeX blocks on an interactive prompt the first time Manim requests a package.

## Things worth knowing if you fork this

| Where | Controls |
| --- | --- |
| `SWARM` | position and scale; index 0 is the hero |
| `FLAP_HZ` | wingbeat rate |
| `TIP_LAG` | how much the wing bends during a stroke |
| `wingOutline` | forewing and hindwing silhouettes |
| `wingColour` | veins, margin, spots, apex |
| `face` in the march loop | how strongly each butterfly turns toward the camera |

- **The camera lives in GLSL**, so Manim's own camera does not move it. Manim supplies the timeline: a `ValueTracker` feeds the `u_time` uniform, and the GPU re-evaluates every equation per pixel per frame.
- **`Shader.set_uniform` swallows unknown names silently.** A typo, or a uniform the compiler optimised away, fails without complaint. Verify by rendering two timestamps and diffing them.
- **`renderer = opengl` in `manim.cfg` is ignored** — the OpenGL renderer must be selected with the `--renderer=opengl` CLI flag, which `render.ps1` passes. Resolution and frame rate in the config file *are* honoured.
- **Manim's OpenGL renderer draws meshes after mobjects**, so a full-screen shader quad paints over any text. `poster.py` sidesteps this by baking the frame to an image first.
- Manim's shader API is experimental, so the dependency is pinned. Re-check shader compilation and a short export before upgrading.
