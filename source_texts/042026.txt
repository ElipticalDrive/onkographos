Hi,
Sorry, we don't provide normals in our current zenodo but I can share our .blend files under this link. You should be able to generate any renders you need from them. Please note these files are quite messy. I hope to clean blender scripts and add them to the repository, but I don't think I'll have time to do so within the next month.
My notes of what to be careful about in provided files:
First basic remark: My .blend files are a very rough version. The code is not cleaned up and is hardcoded in a couple of places. Please also note that some parts are in the Scripting tab, while others are set directly in the Blender GUI—for example, imported actors, materials in the Shading tab, and some renderer settings are also in GUI. Be careful not to override those values in Script unintended because later you would need to manually find and add it again.
1.For the example hook scene, the main file is hook150_v5_specular32.blend, where we render the relit actor. In the roughness, and blendfiles_for_normals_examples, you can find some additional renders that we added later for roughness, normals.
2.To render from hook150_v5_specular32.blend, simply go to the Scripting tab and run the 360view.py file.
3.In this script, you need to change the hardcoded values:
RESULTS_PATH
ENV_TEXTURE_PATH
bpy.context.scene.frame_current = 1 or frame_id, depending on whether you want to render the static or dynamic version
4.From what I remember, it is really crucial to take care of color management in Blender. You need to use the environment texture in Blender in the same way as in your Gaussian code, and the same applies to the final renders—for example, whether the renders are saved in linear RGB or sRGB.
For the input environment texture, we use:
env_texture_node.image.colorspace_settings.name = "Linear Rec.709"
From what I remember, our final renders (render and albedo) are rendered in sRGB space.
In the renderer’s Color Management tab, I also disabled the blender’s view transformations, because we want to have physically accurate render. You probably also need to take a look how we rendered roughness, normals without such transformations.
5.If you want to render normals, Blender will use one of its own normal conventions. To make comparison with Gaussian normals easier, I rendered several different conventions here:
https://github.com/joaxkal/LumiMotion/blob/main/notebooks/visualize_normal_conventions.ipynb
This should make it easier to adjust Gaussian normals to Blender’s convention for the paper.
