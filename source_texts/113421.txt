You are an expert game engine developer building a high-quality, modular engine for an isometric turn-based PvP tactical game heavily inspired by classic XCOM / OpenXcom — but exclusively designed for two human players fighting each other.
Requirements:
Language: javascript
install no packages or anyhing outside of html/javascript. if not possible, ask before installing
if possible, no "server" but direct communcation between the players
playable in browser
Look & Feel: Clean pixel-art style. Tiles and units use larger sprites (minimum 64x64, preferably 128x128 or more) — modern "HD pixel art", not 1994 tiny pixels.
Assets: Use colored sprites/graphics
Gameplay Features:
Isometric diamond map (classic XCOM style)
Multi-level terrain (minimum 3 height levels)
Voxel-based geometry: floor + west wall + object (exactly like OpenXcom LOT/WAT/OBT)
Camera: 4-way rotation (0°, 90°, 180°, 270°) with smooth switch, panning, zoom levels
2 players, hotseat mode fully working first (Player 1 finishes turn → screen blackout + "Enemy Turn" → Player 2)
Each player controls 4–8 soldiers (configurable via ruleset)
Classic XCOM Time Units system (TU for movement, shooting, etc.)
Full action system: move, shoot (snap/aimed/auto), throw, reload, open door, use item, etc.
Inventory with grid (hands, belt, backpack, shoulders, legs — exact XCOM layout)
Weight system affecting max TU
Accurate Line-of-Sight and Line-of-Fire voxel traversal (deterministic, same algorithm both players)
Per-player fog of war + last-seen enemy memory
Reaction fire (opportunity fire) fully implemented and deterministic
Destructible terrain (explosions remove voxels)
Explosions with radius and falloff
Pathfinding with exact TU cost preview (highlight path, show remaining TU)
Animated unit movement along path
Hidden movement screen for non-active player
Multiplayer Foundation:
100% deterministic simulation (same RNG seed + same actions = identical outcome)
Lockstep-ready architecture
Full game state serialization
Checksum verification points prepared
Do you need any further clarification before we begin?
