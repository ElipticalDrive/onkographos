Priority: P2 (Medium)
Problem
Pixel-level diff (pixelmatch) is binary: a pixel either matches or doesn't. This makes it oversensitive to anti-aliasing, subpixel rendering, and minor color shifts, while being unable to express perceptual similarity. A 1px shift of text is reported the same as a complete color change.
Proposal
Implement SSIM (Structural Similarity Index) as an alternative or complementary diff metric.
SSIM compares images on three dimensions:
Luminance: overall brightness similarity
Contrast: dynamic range similarity
Structure: pattern/texture similarity
Output a per-pixel SSIM map and a global SSIM score (0.0–1.0).
API
```
pixelmatch ssim before.png after.png --output ssim-map.png
```
```
{
  "ssim": 0.97,
  "luminance": 0.99,
  "contrast": 0.98,
  "structure": 0.95
}
```
Why P2
Industry standard perceptual metric (widely used in image/video quality)
Complements pixelmatch: use pixel diff for precision, SSIM for "how bad is it?"
Useful for setting meaningful thresholds (SSIM > 0.99 = visually identical)
However: more complex to implement than clustering/shift detection, and the perceptual benefit over pixelmatch + threshold is incremental for typical VRT use cases
Implementation Notes
Window-based computation (typically 11x11 Gaussian window)
Per-channel or luminance-only variants
MoonBit/WASM: sliding window is cache-friendly, good WASM performance expected
Reference: Wang et al., "Image Quality Assessment: From Error Visibility to Structural Similarity" (2004)
