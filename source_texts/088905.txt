Context
F3D has many options, one is for controlling if volume should be displayed, one if point sprites should be displayed.
This is not great because if you enable both, then there is a priority issue going on.
It would be great to factorize that option into a single rendering-type option that takes a string parameter.
Suggested Solution
Deprecate both --volume and --point-sprites and related libf3d options
Add a new --rendering-type option and takes it into account in the vtkF3DRenderer
Modify the interaction logic so that we can cycle through rendering types
