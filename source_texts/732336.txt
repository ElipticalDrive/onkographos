Bug
A Pose built from a slightly non-unit quaternion (which Pose accepts, tolerance 1e-5) can't be passed through transform_pose, matrix_to_pose(pose.as_matrix()) or matrix_to_quaternion_wxyz(quaternion_wxyz_to_matrix(q)): they raise ValueError: ... must be orthonormal.
Reproduction
```
import numpy as np
from cap_harness.contracts import Pose
from cap_harness.geometry import matrix_to_pose, transform_pose

# 90 degree rotation about x, rounded to 4 places: norm 0.9999904, accepted by Pose
pose = Pose(position=np.zeros(3), quaternion_wxyz=np.array([0.7071, 0.7071, 0.0, 0.0]), frame="base")
matrix_to_pose(pose.as_matrix(), frame="base")
# ValueError: transform rotation must be orthonormal
transform_pose(pose, np.eye(4), source_frame="base", target_frame="world")
# ValueError: transform rotation must be orthonormal
```
Expected: the round trip succeeds (the quaternion was accepted on construction). Actual: ValueError from _rotation_matrix.
The same input reaches this through pose_from_mapping, since it passes quaternion_wxyz straight to Pose.
Cause
Pose.as_matrix() (src/cap_harness/contracts.py:266) and quaternion_wxyz_to_matrix() (src/cap_harness/geometry.py:61) build the rotation matrix from the quaternion as given, without normalising it. A norm error of ε becomes an orthonormality error of up to ~4ε in the matrix. Here that is 3.8e-5, above the 1e-5 _ROTATION_ATOL that _rotation_matrix (geometry.py:40) checks.
_libero_quaternion_xyzw_to_matrix in libero/adapter.py already normalises before building the matrix. Doing the same in these two builders fixes it: one line each. The stored quaternion stays unchanged.
Fix
A minimal fix with a regression test is ready (two changed source lines plus a regression test in tests/test_geometry.py). It fails before the change and passes after, and the rest of test_geometry, test_contracts, test_libero_codec, test_robosuite, test_providers, test_validation, test_registry and test_api still pass. Happy to open a PR (with DCO sign-off) if that's welcome.
I found this with patchwork, an automated code-audit tool I run, and verified the reproduction test in an isolated sandbox. If tool-assisted reports aren't welcome here, let me know and I won't send more.
