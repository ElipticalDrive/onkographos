Reworks @typegpu/radiance-cascades.
New:
two 2D ping-pong textures instead of per-cascade 3D arrays (way less memory)
the whole update is one compute pass; run(encoder?) records into your encoder
Morton ray ordering, so pre-averaged blocks are actually neighbouring directions
mergeMode: 'bilinear-fix'
baseStoredRayDim (1/2/4) for ray density
renderAspect plus tracing controls: maxRaySteps, stepSafety, erodeBiasProbes, epsProbes, minStepProbes
Breaking:
color → emission
colorSlot, sdfResolutionSlot and getCascadeDim are removed
the default is 4 rays at cascade 0, down from 16 (baseStoredRayDim: 2 matches the old default)

✅ No new issues found.
Reviewed changes — v2 rewrite of the radiance cascades package with better cascade sizing, Morton ray ordering, configurable merge modes, encoder support, and memory optimization.
Add getCascadeInfo with per-layer metadata — replaces the flat getCascadeDim with a rich CascadeInfo structure carrying per-layer probe counts, UV ranges, and valid dimensions. The old getCascadeDim is kept as a convenience wrapper.
Morton Z-order ray ordering — replaces linear ray indexing with Morton encoding for more uniform angular sampling. part1By1 and morton2D are defined in cascades.ts and used in makeCascadePassCompute.
Aspect-correct ray directions — rayDirection and segmentMetricLength use renderAspectSlot to produce correct ray distributions on non-square render targets. rayBoxExitUv clips rays to the unit box.
Configurable cascade layers — support for baseStoredRayDim (1/2/4), mergeMode (hardware or bilinear-fix), per-layer uniform buffers (CascadeLayerParams), and exposure of common slots (maxRayStepsSlot, rayMarchStepSafetySlot, traceSegmentSlot).
Encoder support — run() accepts an optional GPUCommandEncoder so cascade and jump-flood passes can be batched with surrounding work. When omitted, run() creates and submits its own encoder.
2D ping-pong cascade textures by default — reduces memory usage significantly. 3D array textures are used only when keepCascadeLayers: true.
Prebuilt JFA pipelines — createJumpFlood now prebuilds one pipeline per JFA step instead of writing offsetUniform at runtime. Fixes destroy() to clean up offset buffers and uniforms.

The biggest memory win comes from the cascade ping-pong textures switching from 3D arrays to 2D (the default keepCascadeLayers: false). The output texture format in jumpFlood also goes from rgba16float (8 B/texel) to r32float (4 B/texel) — a separate 50% saving on the SDF output.
Cascade texture memory: old vs new (default baseStoredRayDim=2)
The old path allocates 2 × 3D textures at rgba16float (8 B/texel): [cascadeDimX × cascadeDimY × cascadeCount].
The new default allocates 2 × 2D ping-pong textures: [cascadeDimX × cascadeDimY] — same rgba16float but no layer dimension, so savings factor ≈ cascadeCount : 1.

✅ No new issues found.
Reviewed changes — the Simplify radiance cascades commit (d959a8474) layered on the previously reviewed revision; the cross-layer ordering thread from the prior review is retracted (WebGPU §3.4.4 makes each dispatch in a compute pass its own usage scope, so ordering between dispatches is guaranteed).
Collapsed the specialized compute factories into slot-driven variants — makeCascadePassCompute/makeBuildRadianceFieldCompute and their module-level caches are gone; cascadePassCompute and buildRadianceFieldCompute are now specialized through hasUpperCascadeSlot, mergeModeSlot, and baseStoredRayDimSlot.
Transposed the cascade-pass invocation mapping — dirStored/probe now use modulo/division so consecutive invocations share a probe and trace neighbouring directions, while texture storage stays direction-major.
Changed the bilinear-fix boundary fork — traceBilinearFork now gates the upper cascade on the upper probe's ray-box exit (upperExitUv > endUv), and the intervalOverlapUv/intervalOverlapProbes plumbing was removed.
Reworked cascade layout math — getCascadeInfo takes renderAspect instead of minCascades, drops interval0/maxRange, stops clamping validDim, and defaults baseStoredRayDim to 1.
Dropped 3D cascade arrays and the owned-output API — keepCascadeLayers, CascadeTextureArray, outputTexture/cascadeTexture/ownsOutput, OwnedRadianceCascadesExecutor, and the traceSegment option were removed; the runner now always ping-pongs two 2D textures.
Renamed the scene callback color → emission across the API, examples, README, and the rewritten guide.
Replaced the snapshot test suite with 13 layout/regression tests plus a new tsconfig.test.json.
ℹ️ Nitpicks
The refactor removed the WGSL resolve snapshots for cascadePassCompute (all merge variants) and buildRadianceFieldCompute (all three baseStoredRayDim values); the new tests cover layout math and one boundary path but no longer pin the generated shader for the slot-driven tgpu.unroll or the merge specializations.
