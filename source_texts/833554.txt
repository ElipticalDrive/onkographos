Description
Runtime camera calibration previously copied matrices to the CPU, authored USD attributes for every camera, and reread USD to reconstruct the reported projection. OVRTX did not propagate runtime calibration into its renderer-owned scene, and Newton built its ray field only at initialization.
Use NumPy for initial camera calibration and Warp for runtime updates. The camera owns persistent calibration buffers; each renderer owns its camera-specific bindings and queries.
Initialization: read authored USD values once, build the pinhole matrices with NumPy array operations, preserve authored OpenCV calibration, and upload the completed arrays. Do not preload runtime calibration kernels. The two setter kernels share a separate Warp compilation unit within the existing camera file, so pose initialization cannot compile them incidentally.
Runtime: set_intrinsic_matrices accepts NumPy, Torch, and Warp matrices. Upload host inputs, then validate indices, resolve duplicates, and convert projection parameters on the camera device. Keep matrix/index batches on device. Submit pending buffers to BaseRenderer.update_camera_intrinsics before committing public storage in place. Register float32/float64 specializations together; compilation happens on first use and subsequent updates reuse it.
Kit: write five projection columns directly into Fabric with one Warp kernel, compiled on first use. Render data owns the selection and releases its tags on cleanup. Reinitialization restores authored calibration in both Fabric and the reported matrices.
OVRTX: write GPU columns through native bindings or an ovstage query owned by each camera's render data. Cameras sharing a renderer retain independent handles; cleanup releases only that camera's resources.
Newton Warp: regenerate the persistent shared ray field in Warp without changing its address. Reject nonuniform calibration before committing camera buffers. Avoid the native convenience helper's scalar GPU-to-host readbacks.
Errors are atomic, duplicate indices retain the last row, OpenCV distortion calibration stays fixed, and ordinary pinhole cameras retain the centered, square-pixel projection. This also addresses the cardinality issue in #7898. Runtime preparation has one device path, with no batch-size threshold or first-call switching. All production changes stay in existing Python files. Camera-specific AGENTS.md additions are removed.
Migration and limitations
Breaking: Camera.set_intrinsic_matrices changes runtime calibration without authoring USD. USD edit-target/layer composition no longer controls the result, and exporting USD does not persist runtime overrides. Use PinholeCameraCfg.from_intrinsic_matrix when spawning cameras to persist calibration. Custom renderers must implement update_camera_intrinsics for runtime updates.
Initial authored calibration uses NumPy. The public setter always uses Warp, including when called during setup. Its first invocation can incur JIT compilation; repeated invocations reuse compiled kernels. Renderer initialization still performs its existing native setup, including Newton's initial ray construction.
Synchronous index errors and projection warnings require one status integer readback. Newton also reads a scalar for its shared-calibration constraint. The setter is not CUDA graph capturable. Host inputs are uploaded; CPU-configured cameras retain CPU support.
All three backends support uniform runtime updates. On the tested Kit/OVRTX tiled runtimes, views share the first camera's projection: per-view attributes and reported matrices change, but independent rendered projections do not. Direct USD writes reproduce the same restriction. Newton explicitly rejects differing per-environment calibration and leaves active calibration unchanged. These limitations are documented in the API.

## Why this change?

Arena was on Lab 3.0 EA and Isaac Sim 6.1. Update to the [Isaac Lab
v3.0.0
release](https://github.com/isaac-sim/IsaacLab/releases/tag/v3.0.0),
pinned at

and adapt Arena to its released APIs and dependencies.

## What changes?

### Docker and uv workflow

- Follow the uv-based Docker installation introduced by Isaac Lab [PR
#7405](isaac-sim/IsaacLab#7405) and [commit
`eed50f77c53`](isaac-sim/IsaacLab@eed50f77c53),
while retaining Arena's Isaac Sim base-image stages and editable Lab
source.
- Interactive container shells alias `python` and `python3` to
`isaaclab.sh -p`, and `pytest` to `isaaclab.sh -p -m pytest`, so
commands initialize Isaac Sim and execute from `/opt/isaaclab-venv`.
- Non-interactive runtime and CI commands invoke `isaaclab.sh -p`
explicitly; build-time package operations use `uv pip` or
`/opt/isaaclab-venv/bin/python`. `/isaac-sim/python.sh` is no longer a
supported Arena entry point because it bypasses the Lab launcher and the
locked Lab virtual environment.
- Continue building from the Isaac Sim 6.2 image. Copy in uv 0.12.9 and
create `/opt/isaaclab-venv` with Isaac Sim's Kit Python.
- Sync third-party dependencies from the pinned Isaac Lab submodule's
frozen `uv.lock`. The metadata-only stage skips all local path packages;
after the complete submodule is copied, a second sync installs its
editable packages.
- Overlay Arena's non-Lab dependencies from Arena's frozen lock with `uv
sync --inexact`, then install Arena editable into the same environment.
- Pin uv 0.12.9 in Docker and native CI. Regenerating the lockfile with
the newer serializer puts Arena's Linux x86_64 constraint in top-level
`resolution-markers` and `supported-markers` and remove it from uv lock
edges.

### Torch 2.11 and CUDA 13 handling

- Isaac Lab [PR #8372](isaac-sim/IsaacLab#8372)
deliberately selects Torch 2.11.0 on CUDA 13.0. Torch 2.12's CUDA 13
NCCL 2.29 can fail beside Kit RTX or OVRTX on Blackwell because of a
driver shared-memory accounting issue. Torch 2.11 uses NCCL 2.28.9 and
avoids that failure while retaining Isaac Lab's
deferred-CUDA-initialization workaround.
- Native uv routes `torch==2.11.0` and `torchvision==0.26.0` to the
`cu130` PyTorch index. Docker takes those versions from Lab's frozen
lock instead of duplicating them in a hand-written constraint list.
Arena drops its direct `torchaudio` dependency, matching Lab.
- Build cuRobo with the CUDA 13.0 toolkit and
`CUDA_HOME=/usr/local/cuda-13.0`, matching PyTorch's CUDA major version.

### Other API and released-stack changes

- **Environment reset selectors — Lab [PR
#8030](isaac-sim/IsaacLab#8030) and [PR
#8015](isaac-sim/IsaacLab#8015 accept Lab's
tensor, slice, and `None` environment selections in Arena's environment
and recorder reset paths. This is API compatibility, no behavior change.
- **Camera observations — Lab [PR
#8051](isaac-sim/IsaacLab#8051 replace the
removed generic `mdp.image` term with the RGB, depth, normals, or
segmentation observation function selected for each modality.
Unsupported data types now fail explicitly.
- **Newton camera pose propagation — Lab [issue
#7676](isaac-sim/IsaacLab#7676), [PR
#7691](isaac-sim/IsaacLab#7691), and release
backport [PR #7935](isaac-sim/IsaacLab#7935
Lab 3.0 now mirrors Newton `FrameView` pose writes into Fabric so RTX
sees camera movement. Remove Arena [PR
#1196](#1196) and its
`CameraPoseWriter` USD workaround. Camera-extrinsics variations now use
Lab `set_local_poses()` directly; retained tests cover rendered images
and reported poses under PhysX and Newton with Fabric enabled and
disabled.
- **Runtime camera intrinsics — Lab [PR
#7916](isaac-sim/IsaacLab#7916 replace
private USD sensor access and `_update_intrinsic_matrices()` with
`Camera.set_intrinsic_matrices()`. Lab's ordinary pinhole runtime API
enforces square pixels, so Arena now samples one focal-length delta and
applies it to both `fx` and `fy`. **Note:** intrinsics variation has an
pre-existing bug before this Lab upgrade which results in env_0 camera
params being used for all parallel envs. Fix will go in a separate PR.
- **Clone-plan topology — Lab [PR
#8045](isaac-sim/IsaacLab#8045), backported in
[PR #8073](isaac-sim/IsaacLab#8073 resolve
representative scene geometry through asset-prototype IDs, prototype
paths, and clone-plan topology instead of the removed
`cloner.query.iter_sources()` helper. arena_world_scene_access.py was
updated to essentially re-implement the removed helper.
- **Franka presets — Lab [PR
#8169](isaac-sim/IsaacLab#8169) and [PR
#8170](isaac-sim/IsaacLab#8170 select
`FRANKA_PANDA_LEGACY_CFG` and `FRANKA_PANDA_LEGACY_HIGH_PD_CFG`
explicitly after Lab made the flat Franka asset the default and
introduced shared minimal presets. This keeps Arena's nested `/panda`
hierarchy, legacy joint names, and existing actuator grouping.
- **Replicator kitchen USD — Isaac Sim 6.2 asset update:** update tests
for `kitchen_peninsula.usda`, which now exposes 50 physics roots instead
of 56. Its `_OnlineVisual` physics roots decrease from 24 to 18, and the
previously discovered `_OnlineVisual` articulation is no longer present.
- Unit test pick and place success speed thresholds were relax due to
large observed residual speed. Root cause unknown yet.
