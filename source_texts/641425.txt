What does this PR do?
Foundation for accurate-but-inexpensive fluid dynamics covering wind, water, and honey.
Core solver (AZ::FluidSim, Code/Framework/AzCore/AzCore/Math/Fluid.h/.cpp)
Position Based Fluids (PBF/SPH density constraints, XPBD-style positional projection) — one shared solver spans the viscosity range: water (restDensity 1000, viscosity ~0.02) to honey (restDensity 1400, viscosity ~1.0). No per-fluid special cases; behavior comes from physical parameters.
Spatial-hash uniform grid neighbor search (sorted compact grid, packed 21-bit/axis cell keys) — no O(n²) pairs.
Poly6/Spiky kernels, artificial pressure (anti-clumping), XSPH viscosity, AABB container with restitution, external acceleration field hook.
Reused scratch buffers (no per-frame allocations), SoA-friendly data, optional AZ::ParallelFor multithreading — layout designed for a future GPU compute port (like the soft-body solver).
Wind (AZ::WindField)
Analytic wind: steady base velocity + gusts + turbulence sampled per position/time — wind costs nothing per-particle-free (no air particles). DragAcceleration() gives drag toward local wind velocity for coupling anything (fluids, future soft bodies/rigid bodies).
FluidDynamics gem
Fluid Volume component: Water/Honey/Custom presets, spawn + container extents, substeps/iterations, per-volume gravity scale, optional wind coupling (drag toward sampled wind), point/sphere debug visualization, parallel toggle. Simulates on the physics tick.
Wind component: direction/speed/gusts/turbulence; multiple wind components sum via WindRequestBus.
Editor components under Physics category; gem registered in engine.json.
How was this PR tested?
12 new unit tests (Tests/Math/FluidTests.cpp): gravity free-fall matches analytic, bounds containment, rest density convergence, honey damps motion faster than water, determinism, wind pushes particles, long-run stability, wind-field/drag properties — all pass (AzTestRunner libAzCore.Tests.so).
Built AzCore, AzCore.Tests, FluidDynamics + FluidDynamics.Editor (Linux profile, clean).
Editor smoke test on TestGame (null RHI, --runpython): created entity, added Fluid Volume + Wind components, entered game mode for 120 frames, exited cleanly — no errors/asserts.
GPU visual validation not possible on this box.
