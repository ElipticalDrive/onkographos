🎯 What
Introduces two new creative features to the voxelizer-rs project:
Procedural SDF Noise (--sdf-noise <amp>): Adds a procedural 3D Perlin noise pass using the noise crate to distort the underlying SDF scalar field before voxel decisions are made, resulting in interesting pseudo-random volume deformations.
Image Slicing (--slices <DIR>): Adds the ability to export the resulting point cloud layer-by-layer as a sequence of PNG files (using the image crate), useful for debugging or integrating into 2D raster toolchains.
💡 Why
This was implemented as an unconstrained brainstorm effort to expand the creative potential of the library.
🛠 Implementation Details
Refactored MeshProcessor::voxelize to use an add_particle closure, reducing duplicated logic and safely parallelizing the SDF evaluations with noise injection.
Appended a grid-mapping strategy at the end of main.rs to gather, map, and export the Z-ordered 2D pixel matrices as PNG files.
✅ Testing
Existing unit tests passed. No regressions observed.

Validate sdf_noise before perturbing signed distances
This path applies amp directly to every SDF sample without checking finiteness, so inputs like --sdf-noise NaN or inf propagate non-finite values into sdf; in non-surface mode that makes sdf <= 0.0 false for most/all voxels and can silently produce an empty or corrupted particle set. Since resolution and narrow_band are already validated, sdf_noise should be similarly constrained to finite values before use.

Handle empty particle clouds before computing slice bounds
When --slices is used and voxelization returns zero particles, the min/max sentinels remain at f32::MAX/MIN; the later size math then yields a synthetic 1x1x1 grid and writes a bogus blank PNG instead of reporting that there are no slices to export. This produces misleading output in valid scenarios (e.g., aggressive crop/narrow-band/noise removing all voxels).
