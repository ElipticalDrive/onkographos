As many fractal shapes can be rendered with raymarching, the sierpinski pyramid has been programmed with raymarching in order to reuse existing signed distance fields.
However, it is made of triangles so making rasterized version instead makes much more sense. This would be faster, enable easy collisions and occlusion.
we will need a testable generateSierpinskiPyramidVertexData(nbSubdivisions: number): VertexData function.
Then we can change the SierpinskiPyramid to use a Babylon Mesh with the given vertex data (take inspiration on GasPlanet that use the same representation)
The mesh can use a simple metallic PBR material
Remove the dead raymarching code in PostProcessManager, SierpinskiPyramidPostProcess and the associated GLSL shader.
The pyramid can be debugged easily at localhost:8080/playground.html?scene=xr&fractal=pyramid once the dev server is started.
Bonus: explore the possibility of running the vertex data generation in a compute shader!
This can be considered a good first issue if you know how BabylonJS meshes are represented.
