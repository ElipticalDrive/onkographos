Description
Part of #5033. This fixes how SensorCamera blends see-through Gaussian splats. The other half of that issue, view-dependent color from spherical-harmonics degrees above 0, is left for a follow-up PR.
Right now the camera treats the splats along a ray as all or nothing. If they let 49% or more of the light through, the ray shows the background as if they weren't there. Otherwise shade() divides the color by the accumulated opacity, so they come out fully solid. In practice any splat at 51% opacity or less vanishes, and the thin parts of captured scenes, like the sky, render as black holes.
This PR blends the splats front to back, the way 3D Gaussian splatting does, with C = sum(c_i * a_i * T_i) + T * background. The background is the nearest shape behind the splats, or the clear color.
What changes:
Splats are composited in linear light over whatever is behind them, in all three anti-aliasing modes. The alpha channel carries their coverage.
Splats are shaded after every opaque surface, so the blend stops at the nearest one. Particles are now traced before shapes for the same reason.
Depth, normal and shape index report the splats once their accumulated opacity passes one half, which is the old 0.49 threshold rounded. In the timing scene below, 36 of 12,288 pixels gain a depth value.
RenderConfig.gaussians_min_transmittance now does what its docstring already said. It's where a ray stops blending. The default is 1e-4, as in the 3DGS rasterizer. The name and type stay the same, and a changelog fragment explains the new meaning.
QUALITY mode used to blend some splats twice when their bounds reached into the next gather pass. Each pass now only takes splats beyond the previous one.
Not in this PR:
Spherical-harmonics degrees above 0 are still ignored.
The frozen warp_raytrace renderer behind SensorTiledCamera is untouched.
Splats from different Gaussian assets still don't blend with each other. The asset with the nearest splat wins, as docs/concepts/conventions.rst describes.

Bug fix
Steps to reproduce:
Render one white splat (linear radiance 1.0) over the black background at opacities from 0.3 to 0.9.
Read the pixel's HDR color and depth.
On main, opacities up to 0.5 give black with no depth, and 0.55 and 0.9 give full white.
Minimal reproduction:
```
import math

import numpy as np
import warp as wp

import newton
from newton.sensors import SensorCamera
from newton.utils import ColorSpace

for opacity in (0.30, 0.45, 0.50, 0.55, 0.90):
    builder = newton.ModelBuilder()
    builder.add_shape_gaussian(
        body=-1,
        gaussian=newton.Gaussian(
            positions=np.zeros((1, 3), np.float32),
            scales=np.full((1, 3), 0.5, np.float32),
            opacities=np.array([opacity], np.float32),
            sh_coeffs=np.full((1, 3), 0.5 / 0.2820947918, np.float32),
            sh_color_space=ColorSpace.LINEAR,
        ),
    )
    model = builder.finalize(device="cpu")
    camera = SensorCamera(model)
    rays = camera.compute_camera_rays_pinhole(1, 1, camera_fov=math.radians(10.0), device="cpu")
    transforms = wp.array([wp.transform(wp.vec3(0.0, 0.0, 2.0), wp.quat_identity())], dtype=wp.transformf, device="cpu")
    hdr = camera.allocate_image_color_hdr(1, 1, 1)
    depth = camera.allocate_image_depth(1, 1, 1)
    camera.update(model.state(), transforms, rays, hdr_color_image=hdr, depth_image=depth)
    print(f"opacity {opacity:.2f}: color {np.round(hdr.numpy().reshape(3), 3)}, depth {depth.numpy().item():.3f}")
```

```
QUALITY passes after the first reset the hit list to
max_distance - min_distance and passed that cutoff to the hit
response, which measures from the unshifted ray origin. Splats past
max_distance - min_distance were dropped, so a shape behind more
than gaussians_max_num_hits splats showed through. main has the same
cutoff, where it made the splats vanish instead.

Keep hit distances in the ray-origin frame and subtract min_distance
only from the BVH cutoff. Order splats by distance, then by index,
and resume each pass after the last splat of the previous one. Splats
at equal distances then blend once each instead of being skipped,
which also removes the 1e-6 step between passes.
```
