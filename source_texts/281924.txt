Summary
This PR implements a hierarchical 3D bounding volume octree spatial partition system for scene graph visibility culling in com.linkpoint.render.lumiya.spatial, replacing unindexed linear scans with O(log N) frustum culling.
Key Changes
Pre-allocated Node Memory Pooling (OctreeNodePool.kt):
Implemented OctreeNodePool with pre-allocated node instances (DEFAULT_INITIAL_CAPACITY = 2048) to eliminate heap allocation stalls and GC overhead on hot render paths during dynamic object re-allocation and node splitting.
Depth-Capped Octree & Diagnostic Safety Toggle (SpatialIndex.kt):
Enforced a strict octree depth cap of 8 levels (MAX_DEPTH = 8) to bound memory overhead in dense geometry clusters.
Added useOctree: Boolean = true diagnostic safety toggle allowing runtime switching between hierarchical octree traversal and legacy linear scanning.
Added getMemoryFootprintBytes() reporting for active region memory footprint verification.
Incremental Spatial Node Updates (SpatialIndex.kt):
Implemented updateIncremental(entry) to update object bounding box changes without full index rebuilds.
Re-indexes moved and rotated spatial entries dynamically across tree nodes.
Comprehensive Unit Tests & Benchmarks (SpatialIndexOctreeTest.kt):
Added tests and benchmarks validating all acceptance criteria:
Frustum Traversal Duration: ~0.22ms average per frame for 4,000 active objects (< 2.0ms budget).
Incremental Update Overhead: ~0.40ms total average duration for 100 simultaneous moving objects (< 0.5ms budget).
Spatial Index Memory Footprint: ~0.86 MB for 4,000 objects (< 5.0MB budget).
Octree Depth: Verified strictly capped at 8 levels under dense point clustering.
Diagnostic Parity: Verified 100% visible object parity between octree traversal and legacy linear scan.

High-level PR Summary
This PR replaces the legacy linear scan spatial indexing with a hierarchical 3D bounding volume octree for scene graph visibility culling. The implementation adds pre-allocated node memory pooling (OctreeNodePool) to eliminate GC stalls, enforces a strict 8-level depth cap to bound memory usage, supports incremental spatial updates for moving/rotating objects without full rebuilds, and includes a diagnostic toggle (useOctree) to validate octree behavior against the legacy linear scan. Comprehensive unit tests verify performance targets: frustum traversal under 2ms for 4,000 objects, incremental updates under 0.5ms for 100 simultaneous moves, and memory footprint under 5MB per active region.
