docs/DECISIONS.md §7 decides the art pipeline is hybrid: hand-authored .vox for characters, creatures and hero structures; trees, boulders, walls and clutter stay procedural.
Nothing in the repository reads a .vox file. The procedural half is real and good — src/gen/props.mjs has four tree kits, boulders, arcs, scree and clutter. The hand-authored half does not exist, so every character in the game is box(w, h, d, colour) assembled in makeAvatar and makeFoe.
Scope
A MagicaVoxel .vox reader producing the same plain arrays the generator emits, so a model and a chunk are the same kind of thing downstream.
Map the palette onto the material table rather than carrying raw colour — see Engine: colour behind the material, not baked per voxel #28, same argument.
An asset directory and a build step that does not break the "one self-contained file" constraint the playable build and the plate are under. This is the awkward part and worth deciding early: the pages are opened from disk and published as artifacts whose CSP admits no module graph, so binary assets need a representation those pages can carry.
Hero structures exceed the 16 m terrain ceiling by decision (§5), so placement has to tolerate that.
Done when
One hand-authored character model replaces the boxed avatar in the playable build, and the page still opens from disk as a single file.
Blocks the hand-authored half of #33. See §7.

Done in PR #68, merged as 14df60b. Live as play v33 (https://claude.ai/artifact/H3kZLpjDurCiH2DMEFfr8k).
Reader and writer. src/mesh/vox.mjs reads and writes .vox without the DOM. It handles SIZE, XYZI and RGBA, plus the nTRN/nGRP/nSHP scene graph, where a model's name lives. Parts are matched by the names given in MagicaVoxel, never by order.
Palette onto the tables, not raw colour.
Each colour index is a role: a player's cloth or skin tint (so host and guest still differ), or a palette group, plus a material.
CLOTH and FLESH are appended to the material table.
The hero's palette groups go after everything else, so no index moves and no digest changed.
Assets inside a one-file page. assets/vox/*.vox travel as base64 inside the generated bundle block. The page still opens from disk as a single file, and a changed model is a stale bundle that SYNC reports.
The avatar. assets/vox/hero.vox has one model per hero-rig part at 1/16 m, each within a voxel of the box it replaces, so bones and poses are unchanged. The sentry keeps its boxes.
Authoring. tools/author-hero.mjs wrote the file as readable code, and it opens in MagicaVoxel. The script retires the day someone edits the file by hand.
Checks.
VOX (node): byte-exact round trip, a named and sized model per rig part, every colour mapped, faces outward.
BUILD (browser): the hero on screen is the model, 10 of 10 parts.
Hero structures over the 16 m ceiling aren't exercised yet. Nothing places a structure from a model.
