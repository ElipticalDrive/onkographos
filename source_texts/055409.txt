#### Abstract

A new method for volume visualization is proposed with the aim of real-time previewing of 3D scalar fields. Instead of voxels, hierarchically sampled points are used to store scalar values, where each sampled point has a priority value, and the set of points that have higher priority than any particular level are evenly distributed in 3D. In rendering, points are selected by priority level, scalar value, and gradient magnitude. Each selected point is drawn as a simple primitive such as a line(s) or polygon.

With this approach, the high performance graphics hardware built into commercial workstations can directly accelerate drawing operations. This enables users to control viewing angle, clipping plane, and scalar values for isosurface in real-time or near real-time. The level of detail can be controlled for each frame to ensure constant time rendering. Also, by enhancing such geometric features as horiaontal and vertical lines on isosurface, viewers can understand the overview 3D shapes with a limited number of primitives.

# 1 Introduction

Visualizing 3D scalar fields is an indispensable tool for many areas of science, engineering, and medicine. Volume visualization is essentially different from ordinary photorealiitic rendering. In photorealistic rendering, the main task is to render each visible surface of 3D objects. The contents of the objects can be ignored unless they are actually visible like colored glass, smoke, clouds, etc. On the other hand, a 3D scalar field is Glled with inhomogeneous contents, and it is impossible to display all of the information on a 2D screen. Therefore, we must enhance the data from a certain point of view. In other words, we must select a part or a feature of the data, and visualize them with certain enhancements like coloring, but ignore the other information [12]. For example, isosurface mitthods enhance the distribution of specific scalar value(s), but ignore all others. # 2 Previous Works

Here, three categories of conventional techniques are introduced - direct volume rendering, isosurface methods, and sampled point visualizing.

# 2.1 Direct Volume Rendering

Direct volume rendering creates an image of the sampled volume data by mapping from the data values directly to pixel contributions, without creating intermediate geometric representations such as polygons. The pixel contribution calculation is processed either by object order (i.e. projecting each cell onto the image screen) [1,15,17], by image order (i.e. ray casting for each pixel) [6,7], or by frequency [14].

Direct volume rendering yields several flexible drawing techniques since semi-transparent volume and/or isosurfaces can be visualized. Semi-transparent volume can be shown simply by using a mapping function F from scalar values onto opacity:

$$\alpha(\mathbf{x}) = F(f(\mathbf{x})) \quad (\mathbf{x} \in \mathbb{R}^3), \quad (1)$$

$$\alpha(\mathbf{x}) = F(f(\mathbf{x})) \quad (\mathbf{x} \in \mathbf{R}^3), \quad (1)$$

where f(x) is the scalar value at point x and Q is the opacity. In order to make isosurfaces of a certain material, the si:mplest way is to map the range of scalar values corresponding to the material onto a constant color and opacity. In case the material cannot be classified by strict thresholding, it is presented by using a fu.zzy opacity mapping function (Fig. 1 (a)). Border surfaces of a transparently drawn material are weighted by another mapping function G of gradient matgnitude g(x) [1,6] (Fig. 1 (b)):

$$\alpha(\mathbf{x}) = F(f(\mathbf{x}))G(g(\mathbf{x})), \quad (2)$$

$$g(\mathbf{x}) = |\nabla f(\mathbf{x})|. \quad (3)$$

One disadvantage of direct volume rendering is its heavy computation cost. In the simple implementation, O(n3) size of data must be traversed for each view, where n is the volume resolution along each axis. Many studies have been done to improve calculation efficiency. The common idea among them is to make a sparse data set by compressing or eliminating the cells which have uninteresting scalar values and/or low gradient magnitudes [7,15]. Such an approach is effective if the scalar values or gradient conditions of the material are known and fixed (like bones in CT data, for example). However, if a wide range of scalar values must be examined (like a temperature distribution), data cannot be reduced efficiently.

Frequency domain computation offers excellent performance for large data sets. By preparing 3D spectrum in a preprocess operation, image from any view angle can be obtained by slice extraction and 2D inverse Fourier transform both of which take only O(n2 log n). However, such high performance can be achieved only when modifying just ,the view angle and lighting angle; heavy computation is necessary to reconstruct the 3D spectrum when the clipping plane or mapping function F is changed.

# 2.2 Isosurface Methods

Isosurface methods create polygon meshes or curved surface meshes as an intermediate geometric representation, and then render the surfaces with ordinary rendering techniques [3,8]. Since it can take advantage of the graphics hardware present in commercial workstations, the response to a change in viewing angle can be quite fast.

However, isosurface reconstruction is generally expensive and it is difficult to move the isosurface for another scalar value in real-time, especially if the isosurface occupies a huge number of voxels. Furthermore, isosurfaces cannot be strictly defined if the gradient magnitude is almost zero.

Data such as CT images have fuzzy material boundaries, and the isosurfaces of fixed scalar values may sometimes have topology and/or misclassification problems.

### 2.3 Sampled Point Visualizing

A set of points are sampled and rendered as simple primitives such as points, lines, or polygons. This type of method, often called particle systems, is used for modeling and rendering of special objects such as fire, water, or free-form surfaces [11,13]. For volume visualization, it is quite useful to visualize flow fields, which have been studied well [16]. For a 3D scalar field, it has been used as a simple visualization method, but not sufficiently elaborated. Since each primitive is simple and can be processed independently, this method has great potential for quick rendering.

There are two key ideas in the proposed method. First, scalar values are stored at hierarchically sampled points instead of voxels or mesh vertices. This allows us to control the level of detail continuously. Second, each point is rendered as a simple primitive such as a line segment(s) or polygon. These primitives can be efficiently rendered by graphics workstations.

Figure 2 illustrates the difference between the conventional methods and the proposed method. For simplification, 2D examples are used. Figure 2(a) is the original volume data. (b) and (c) are example results of conventional volume rendering, where darkness indicates opacity. In real 3D case, colors and opacities must be blended along the depth direction. (d) is an example of isosurface method. Line segments correspond to polygons in 3D case.

For the proposed method, volume data must be converted to the form like (e). Here, scalar values and gradient (not shown in this figure) at the irregularly sampled points are calculated and stored. This sampling pattern is hierarchical. In other words, each point has a priority level - in this example, points written in bold face have the higher priority. (f) and (g) are example results of the proposed method, which corresponds to (b) and (c), respectively. At each sampled point, a line segment is drawn. The direction of each line segment indicates the tangent of the isosurface, and the opacity is obtained with the same function of the scalar value as (b) or (c). In 3D case, a polygon or a set of lines can be drawn instead of single line segment. By using simple primitives such as line segments, commercial hardware can effectively accelerate the drawing process. Also, they can express certain geometric feature like the tangent of isosurface. Since the sampling points are hierarchical, it is possible to control the level of detail. For example, a rough image (h) can be obtained by processing only the high priority points. If more priority levels are assigned, the level of detail can be controlled smoothly, which can ensure the constant frame rate rendering.

#### 3.2 Hierarchical 3D Sampling

Hierarchical 3D sampling creates a series of points which satisfy the following feature. Suppose a series of points {PO, A, . . . . PN-~} are distributed in a unit cube. Then, for any subset from the beginning {PO, PI, . . . . Pn-l}, points are evenly distributed and evenly spaced - in other words, point density is uniform every where, and no two points are closer than a minimum distance. Serial number k of each point Pk can be called the priority number, where the smaller the number, the higher the priority. The total number of points n in the unit cube is the number of priority levels. In actual usage, a periodic sampling pattern is used and the unit cube is one period, so each face is treated the same as its opposite face. Notice that if the number of points n is too small, regularity of the pattern becomes obvious.

The simplest example of hierarchical sampling is ordered dithering. 2D ordered dithering is a well-known technique for digital halftoning [4], and here it is directly extended to 3D. Figure 3 shows an example of 3D dithering. Though ordered dithering is simple, the regularity often haa correlation with object surfaces or the screen coordinate. It creates severe aliasing artifacts. Therefore, an irregularly distributed pattern is necessary for many applications.

Hierarchical Poisson-disk sampling proposed by McCool and Fiume [9] creates irregular but hierarchical patterns. In this method, points are placed sequentially by the dortthrowing algorithm. Each new point is irregularly placed and compared to points already placed; if the distance to any other point is less than a limit length, then the new point is discarded and another new point is placed. If this procedure continues to fail many times (1000 times, for example), which means that very few spaces are left, the limit length is reduced by some fraction (0.99, for example). Figure 4 shows one result of hierarchical Poisson-disk sampling. Although this algorithm requires expensive computation, the sampled points can be pre-computed and reused for any object.

At each sampled point, scalar value 2 and gradient magni-

tude are calculated and stored. in the preprocess. Basically, this is done for all sa:mpled points. If the selected range of scalar values is known in advance, however, sampled points with the other values, can be discarded. Such preselection significantly reduces the number of data points for some applications, as used in other data dependent optimizations 27,151.





#### 3.3 Point Selection Criteria

In the proposed algorithm, the hierarchy of sampled data is used for density control. There are two purposes for density control. One is as an alternative to opacity control, where points are adaptively sampled according to their opacity. The other is to control the total number of rendered primitives (i.e. the level of detail) in each frame. This ena'bles constant frame rate rendering.

For each primitive drawn at a sampled point, similar techniques to those used in direct volume rendering can be applied: mapping from the scalar value and gradient to primitive color and opacity. In addition to the real opacity a by alpha blending, point density d, by adaptive sampling can be used. The point density function d-(x) is defined as the number of rendered points per total sampled paints in the local region. By calculating the point density at each sampled point and referring to the priority level, point selection is performed. Opacity Q and point density da pro,vide the similar effects. The merit of opacity control is image smoothness, whiIe that of density control is rendering sp'eed.

#### 3.4 Primitive Shapes

At each selected point, a simple primitive is rendered using the color and opacity mapped from the scalar value. Here, 'simple primitive' means a quickly rendered primitive - line segment(s) or a polygon with up to four vertices. Primitive vertices are pre-computed when the primitive shape is set or changed.

Figure 5 shows some primitives. To simulate isosurface extraction in conventional methods, it is natural to draw a polygon which is tangent to the isosurface at each point, like Fig. 5 (f). In order to help comprehension, however, line segments present more information than polygons. For example, the intersection of the tangent polygons and a horizontal plane creates latitudinal line pattern (b) in polar coordinates. If the line segment is on the tangent polygon but perpendicular to (b), a longitudinal line pattern appears (d). Or (b) and (d) can be combined to create a polar coordinate mesh pattern (a). If a plane perpendicular to a Cartesian axis is used to make a cross section with the tangent polygon, a Cartesian coordinate mesh pattern is formed (e). Thin

polygons (c) are also effective in visualizing certain directions. Besides isosurfaces, gradient direction (g) might be useful for some applications. The last example - random short branch (h) provides a rather new artistic expression.

#### 3.5 Primitive Drawing Order

In order to accumulate semi-transparent pixel values, rendering must proceed in either the back-to-front or front-to-back order. This is not so easy, however, with the irregularly located points created by hierarchical Poisson-disk sampling. A simple solution for this problem is to use bucket sorting. Sampled points are classified into coarse voxels. Primitive drawing proceeds from back-t&front in the voxel order. Within one voxel, the primitive drawing order is random. Although it is not a complete solution, it does provide reasonable efficiency and quality.

If the opacity is controlled by point density only, i.e. if each primitive is completely opaque, the simple z-buffer algorithm can be applied for hidden surface elimination. In this case, drawing order does not affect the resulting image. Therefore, incremental drawing is realized if rendering proceeds under priority order. It can limit the total number of primitives for quick response during interactive viewing control, and once the user's control is stopped, the drawing process continues incrementally until all candidate primitives are drawn or another viewing control action begins.

# 4 Interactive Viewing Control

Many kinds of interactive control are possible with the proposed method. In the sense of recomputation cost, they can be classified into three categories.

The first one is selection preserving control, where both point data and point selection results are not changed. In the procedure outlined in section 3.1, only step 3) is repeated. For this kind of control, the rendering process traverses only marked primitives so that the computation time mostly depends on the cost to draw the primitive. The following functions are classified as selection preservation.

The second class is point-data preserving control, where the point data are not changed but the point selection criterion is. In the procedure outlined in section 3.1, steps 2) and 3) are recomputed. In this case, the rendering process must traverse all sampled points for the selection. Computation time depends on both data traversal cost and primitive drawing cost. This class includes:
