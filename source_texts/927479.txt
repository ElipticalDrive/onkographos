Current State
Shapes and nodes support only 2D positioning; there is no 3D transform (Matrix4x4) API. Pseudo-3D visuals (perspective floors, projected maps, tilted cards, 3D-ish gauges) have to be computed by hand.
PanGui's update lists "3D matrices" among its new APIs. Its telemetry demo builds a 3D-looking map by projecting 2D geometry through a 3D matrix; PanGui states it isn't a 3D renderer, but simple 3D visuals are possible this way.
Tasks:
Add a transform scope that accepts Matrix4x4 (perspective included) for shapes, text, images and whole node subtrees (Skia SKMatrix44)
Add helpers: perspective/orthographic projection, look-at camera, and project/unproject between world and screen space
Make hit testing and OnHover work through the inverse transform for transformed nodes
Define depth-ordering guidance (painter's sort) for projected primitives such as extruded blocks
Add a sample: a rotatable projected grid with extruded boxes and a tilted card with pointer interaction
Acceptance Criteria:
A node subtree can render in perspective and stay interactive
An identity transform costs nothing on the plain 2D path
Works on all integrations without backend-specific code
Related:
Add world-space anchors, nameplates, and off-screen indicators #104 (world-space anchors)
Add virtualized infinite graph canvas, grid, camera, and minimap #83 (infinite canvas camera)
PanGui blog 07: https://pangui.io/blog/07-progress-update-september/
