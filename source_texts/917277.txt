Problem
World terrain was drawn one triangle per instance: 65,536 instances × 48 bytes per tile, with every triangle's three positions duplicated into its instance, and no chunk culling. Each tile cost 3 MiB of upload and 196,608 vertex-shader runs per draw. Every draw covered the whole tile, even the half behind the camera (#373, review renderer F3).
Approach
One indexed mesh per tile (WorldStreamPackedTile, built on the worker):
every vertex once, in the reader's order (145 shared vertices per ADT chunk), as 16 bytes: float xyz plus an RGBA8 fallback colour;
then u16 indices in the reader's triangle order (holes as today);
static water follows as its own vertex and index range, with its indices relative to its first vertex (drawn with startVertex).
Size: a full tile is now 987,136 bytes of geometry instead of 3,145,728. The worst case with water is 1,609,728 bytes (was 3,932,160). MAX_PAYLOAD_BYTES goes from 5,330,260 to 3,007,828.
The fallback colour (untextured or uncovered texels) keeps the old light and altitude tint, from the area-weighted vertex normal instead of each face's normal. It's smooth instead of faceted until part 2 brings real MCNR lighting. Textured terrain samples exactly as before.
Chunk culling. Terrain triangles form runs of consecutive triangles of one chunk, keyed by first vertex / 145. Each run gets a world bounding sphere. An unusual mesh with more than 1,024 runs becomes one run.
drawTerrain tests every run with the frame's WorldStreamObjectCulling.View (the same frustum, far-depth and size tests as objects, from Cull exterior object placements on the CPU before drawing (#356) #369).
It then merges contiguous visible runs into one index range per submit.
The cut. It used to be per triangle in the VS (instances had all three corners). Since the review fold, terrain has no discard, so it keeps early-Z. Chunks wholly past the cut are culled on the CPU, using the frame's fog cut. The few triangles of a straddling chunk that lie past it are fully fogged into the sky colour (Fog fully at the cut into a horizon sky, alpha to coverage for cutouts (#357, part 2) #407). Objects keep their per-pixel cut.
Fog is now per vertex, interpolated, instead of the triangle's far depth.
The renderer keeps per-slot dynamic vertex buffers (69,888 vertices) and index buffers (245,760 u16). Upload slices never cross from the vertex section into the index section, and stay within the existing step and ticket bounds.
Shaders. world-stream VS/FS now read a_position and a_color0. All 4 profiles are regenerated. The D3D11 test now pins this family's inputs to POSITION0, COLOR0. The instance-semantics rule still covers the families that instance.
No tile-file format change. This only changes the in-memory packing. dev-objmips (packet v3, World explorer: improve terrain texture and material quality #174) and I agreed that I take the next version bump in part 2.
