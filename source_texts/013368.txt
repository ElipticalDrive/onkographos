Part of epic #346. The Tier-B true-voxel track: radar polar volumes as a CesiumJS ray-marched volume, alongside the always-works .pnts/isosurface/echo-top products.
What
A VoxelGrid → EXT_primitive_voxels glTF .glb + 3DTILES_content_voxels / 3DTILES_bounding_volume_cylinder tileset that CesiumJS 1.142 renders with a VoxelPrimitive. Render-verified live (screenshot in the thread): the reflectivity field ray-marches as a true 3-D volume over southern Finland with coherent precipitation structure and visible vertical depth.
Commits
CesiumJS 1.124 → 1.142 — voxels need WebGL2 (≥1.135) and the EXT_primitive_voxels realignment (1.127); also picks up point-cloud filtering perf, the circles→squares fix, and shader-metadata correctness. SRI recomputed; existing reps re-verified.
Encoder (ds-3dtiles/voxels.rs) — encode_voxels_glb + tileset_json_voxels + voxel_subtree_json.
API — …/voxel/{tileset.json,subtrees/*,content/*} routes; VoxelGridCaps gains radius_m/height_m so the bounding cylinder matches the grid without a sample.
Viewer — "Voxels" in the View dropdown via Cesium3DTilesVoxelProvider + a reflectivity transfer-function CustomShader.
ENU transform fix — found in render-verify (see below).
Authoritative-source note
EXT_primitive_voxels is not in the Khronos glTF registry — it's a CesiumGS draft with CesiumJS as the only implementation. So I encoded against the live CesiumJS VoxelCylinder3DTiles fixtures, which caught that the draft README is stale: cylinder mode is 2147483650 (0x80000002), not the README's 2147483647. The mode encodes the shape (box 0x80000000, ellipsoid 0x80000001).
Load-bearing gotchas (all in voxels.rs doc comments)
Axis swap: content [radius, angle, height] → glTF dimensions [radius, height, angle]; data laid out radius-fastest → height → angle-slowest (our VoxelGrid is the transpose, so the encoder reorders).
EXT_structural_metadata (schema + propertyAttributes) at the glTF top level, not the primitive; embedded BIN buffer; NaN → a declared noData sentinel.
Implicit OCTREE tiling + a constant .subtree is required (CesiumJS's voxel traversal); for one tile that's a constant-availability subtree.
The tile transform must be the real ENU→ECEF frame, not identity-rotation — identity works for the mesh products (absolute-ECEF vertices) but tilts the parametric cylinder by the latitude (a ~60° slanted slab, which is exactly the first render). This was the one bug render-verify surfaced.
Scope (v1 MVP)
Single tile, latest time. Follow-ups (tracked in #351): implicit octree LOD over multiple tiles, the national mosaic, time-dynamic voxels, per-quantity transfer functions. Tier-A .pnts/mesh remain the portable fallback for non-CesiumJS clients.
Tests
ds-3dtiles (24) structural tests against the fixture shape; api-3dtiles (22) incl. a voxel tileset/subtree/content route test; ds-core/engine-odim green; clippy clean. Plus the live CesiumJS 1.142 render-verify.

Code Review
This PR implements the Tier-B EXT_primitive_voxels voxel rendering path for radar data. The encoder logic, axis-swap, ENU transform fix, and test coverage are solid. Four real issues worth addressing:
1. HTTP status inconsistency in get_voxel_subtree (handlers.rs)
The subtree handler returns 404 NotFound when voxel_grid.is_none(), but the tileset and content handlers both return 400 BadRequest for the same condition. All three should agree — a collection that does not expose voxels is a client error (400), not not-found (404). The subtree handler also omits the radius_m > 0.0 && height_m > 0.0 guard that the tileset handler has, so a collection with VoxelGridCaps { radius_m: 0.0, height_m: 0.0 } returns 404 from the tileset but 200 from the subtree.
2. Unchecked count * 4 multiplication in encode_voxels_glb (voxels.rs)
After the checked-multiply chain that produces count, the expression count * 4 is an unchecked usize multiply before u32::try_from. On 64-bit targets MAX_VOXELS = 32M keeps this safe in practice, but nothing in the function signature enforces that invariant. Prefer count.checked_mul(4).ok_or(Tiles3dError::TooLarge("voxel buffer")) then u32::try_from.
3. GLSL injection via quantity name (viewer/index.html)
voxelShader(q) concatenates q (from $qty.value) directly into the shader source:
```
"  float v = fsInput.metadata." + quantity + ";"
```
The dropdown is populated from server-controlled collection metadata, so ODIM quantities are safe alphanumeric identifiers in practice. However, there is no client-side guard. WebGL GLSL injection is sandboxed to the caller's own GPU context (no server or cross-user impact), but a simple if (!/^[A-Z][A-Z0-9_]*$/.test(quantity)) throw ... before constructing the shader would harden this at no cost.
4. geometricError: 0.0 undocumented deviation from CLAUDE.md
CLAUDE.md encoder gotchas say "tileset geometricError > 0". The voxel tileset uses 0.0 at both the root and content levels. The render-verified result shows this works for the single-tile implicit-tiling case (nothing to refine to), but the deviation is unexplained. A short inline comment in tileset_json_voxels clarifying why 0.0 is correct for a one-tile voxel implicit-tiling tileset would prevent future editors from cargo-culting the CLAUDE.md rule here.
Everything else looks correct and well-tested. The ENU→ECEF frame, axis-swap, nodata sentinel, BIN buffer padding, ETag caching, and render semaphore use all follow established project patterns correctly.

Overall: The implementation is solid. Three findings below, none blocking.
Finding 1 — Performance: smooth_grid angle sweep has stride-n_h inner loop
File: crates/ds-3dtiles/src/voxels.rs, angle sweep block in smooth_grid
The current angle sweep is r → h → a (a innermost). Because idx(r, a, h) = n_a·n_h·r + n_h·a + h, stepping a jumps by stride n_h (56 for med, 64 for high). That is ~4 cache lines between adjacent reads in the hot path, across an array that is up to 48 MB (high grid after smoothing).
Swapping to r → a → h (h innermost) gives stride-1 access on all three touched cells (a-1, a, a+1 rows) within the inner loop. The modular index can be hoisted out of the h loop:
```
// Angle (periodic).
for r in 0..n_r {
    for a in 0..n_a {
        let a_lo = (a + n_a - 1) % n_a;
        let a_hi = (a + 1) % n_a;
        for h in 0..n_h {
            let lo = src[idx(r, a_lo, h)];
            let hi = src[idx(r, a_hi, h)];
            dst[idx(r, a, h)] = blur(lo, src[idx(r, a, h)], hi);
        }
    }
}
```
The height and radius sweeps already have the fast axis innermost; this makes the angle sweep consistent with them.
Finding 2 — Consistency: voxel_subtree_json uses expect on serialization
File: crates/ds-3dtiles/src/voxels.rs, voxel_subtree_json
```
serde_json::to_string(&subtree).expect("subtree serializes")
```
The literal JSON value can never fail to serialize, so this is not a real bug. But it is inconsistent with the Tiles3dError::Serialize variant this PR introduces specifically to replace expect-panics in encoder paths. If someone later adds a dynamic field here and forgets to update the return type, the panic would surface as an opaque Axum 500. Aligning with the rest of the PR would mean returning Result<String, Tiles3dError> and using .map_err(|e| Tiles3dError::Serialize(e.to_string())) — same shape as tileset_json_voxels.
Finding 3 — Cosmetic: Cyrillic Т in doc comments
File: crates/ds-3dtiles/src/voxels.rs
Two instances of glТF use a Cyrillic Т (U+0422) instead of Latin T (U+0054) — visually identical in most fonts but technically wrong and will confuse grep/search. Appears in the module-level doc (lives at the glТF **top level**) and the transpose comment (into the glТF cylinder layout).
