Issue body actions
BC texture blocks cover 4×4 texels in one depth slice, not 4×4×4 voxels. The shared layout helper and DDS reader currently round all three dimensions to multiples of four.
A 4×4×4 BC1 volume with three mip levels should contain 32, 16, and 8 bytes (56 total). The reader consumes only 24 bytes, so later mips point into earlier depth planes and truncated payloads can be accepted. BC3 has the same defect with 16-byte blocks. Separately, CompressionMode.sizeInBytes multiplies block counts as int before widening, corrupting otherwise representable large byte counts.
Correct the shared layout to 4×4×1 and reuse it in DDS metadata, widening byte-count operands before multiplication. Preserve the scalar blockSize API, CompressionMode.None, header interpretation, mip/array/cube ordering, and WantMipMaps. Codecs, uploads, and resource validation are out of scope.
Regression coverage will include every BC mode, non-aligned dimensions, depth boundaries, large byte counts, synthetic legacy/DX10 volumes with distinct mip/depth payloads, truncation, and 1D/2D/array/cube compatibility. Compare layout and ordinary 2D DDS throughput and allocations against the unchanged baseline; volume payload timings must be reported separately because the corrected reader consumes more data.

The regression suite reproduces 54 failures before the fix, while 65 compatibility cases already pass. With the shared 4×4×1 layout in place, all 119 new tests pass, along with 96 existing backend-independent tests.
The minimal three-mip volumes now consume exactly 56 bytes for BC1 and 112 bytes for BC3. Legacy and DX10 fixtures verify each mip/depth payload, every truncated prefix, exact stream consumption, array/cube ordering, and both WantMipMaps values. Large-count tests also cover XY dimensions near Int32.MaxValue without allocating texture storage.
The implementation removes the unused block-count tuple entry in DDS metadata and leaves codecs, uploads, and resource validation untouched. Matched throughput/allocation measurements and final review are in progress.
