Description
RTXPT currently supports homogeneous volume rendering through the material system with HomogeneousVolumeData (as seen in PathTracerBridge.hlsli). I'm interested in whether there are plans to support heterogeneous volume rendering for effects like smoke, clouds, or fire.
Use Cases
Scientific visualization of volumetric datasets
VDB/NanoVDB support
Questions
Is heterogeneous volume rendering on the roadmap for RTXPT?
Are there any structural limitations that would make this difficult to implement?
Would you consider adding support for OpenVDB/NanoVDB?
If I were to attempt implementing this myself,
What would be the recommended approach to extend the current system to handle sparse heterogeneous volumes?
Are there specific areas in the codebase (like HomogeneousVolumeSampler.hlsli) that would need modification?
Do you have any tips for implementing efficient empty space skipping or adaptive sampling within RTXPT's architecture?
What would be the best way to handle the data structure for a sparse volume grid in the shader-accessible memory?
Are there any examples or existing code patterns in RTXPT that would be helpful to reference?
Thank you.

Hello!
Heterogeneous volume rendering isn't on the roadmap for RTXPT yet unfortunately. I don't know what the best approach to integrating it would be, but one of the main issues would also be denoising it reliably in real-time.
Would this perhaps help https://github.com/DQLin/VolumetricReSTIRRelease (they support VDB)? It's relying on https://github.com/NVIDIAGameWorks/Falcor which is more research oriented.
