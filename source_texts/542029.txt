Goal
Make ARC capable of rendering source-detail, extremely high-density geometry without authored LOD chains by combining deterministic hierarchical geometry cooking, GPU-driven visibility selection, bounded geometry streaming, hybrid rasterization, and material/shadow integration.
The user-facing goal is simple: import a high-detail mesh, keep the source detail, and let ARC choose and stream only the geometry needed for the current view down to approximately pixel-scale error.
Current state
ARC already has a strong virtual-geometry foundation:
fixed-size renderable clusters and hierarchical LOD nodes
geometric-error selection with parent fallback
independently streamable geometry pages with protected root pages
GPU page requests, residency budgets, eviction, and telemetry
frustum, normal-cone, projected-error, and HZB culling
GPU-selected visible clusters
compute/software visibility rasterization and material resolve
generic virtual geometry shared by meshes and terrain
This epic evolves that foundation into a production massive-geometry path rather than creating a second renderer.

Architectural principles
ARC owns its own .arcvg cooked format; do not depend on or reverse-engineer another engine's cooked geometry format
normal source formats such as glTF/FBX/OBJ and TerrainSurfaceIR feed the same ARC virtual-geometry cooker
hierarchy parents contain renderable simplified geometry, not only bounds
missing detail must always fall back to a resident parent; streaming may reduce detail but must not create holes
geometry selection is driven by projected error/visibility, not authored object-level LOD switches
mesh shaders are an optional acceleration path, not an architectural requirement
virtual geometry remains backend-neutral; Vulkan is the first production implementation
material, texture, shadow, picking, and motion-vector paths consume one coherent visibility representation
tiled virtual texturing is complementary, not required to enable virtual geometry for ordinary texture working sets

Completion target
A representative scene can contain tens to hundreds of millions of source triangles without authored LODs while ARC keeps CPU submission bounded, selects approximately pixel-error geometry on the GPU, stays inside configurable geometry memory/streaming budgets, falls back safely under IO pressure, uses a hybrid raster path, shades through normal ARC materials, integrates with virtual shadows, and provides enough telemetry/editor diagnostics to explain quality and residency decisions.
