今回の目標
UE4のファーストパーソンテンプレートをなぞって、まだ見ぬエンジンの機能を知っていく。
新しく得た知見をメモ代わりに、ここに書き残しておく。
FirstPersonCharacter
ビューポート
Use Pawn Control Rotation
Camera > Camera Options > Use Pawn Control Rotation
ドキュメントらしいドキュメントも見当たらなかったので自力で調べる
とりあえずエディタの説明を呼んで見る
なるほどわからん
仕方がないのでCameraComponent.h/cppのコードを読む
コードは載せないが、やってることは以下の通り
GetOwner()でカメラコンポーネントをアタッチしている持ち主、つまり今回の場合CharacterControllerをAPawnにキャストして取得
取得したポーンと関連付けされているコントローラーを取得
ネットワーク関連を考慮して、自信が操作するプレイヤーかIsLocalPlayerControllerを使用してチェック
カメラの回転とオーナーと関連付けされているコントローラーの回転に差があった場合、コントローラー側の回転にカメラの回転をあわせる
今回の場合、ざっくり言うと所持しているコントローラーの回転にカメラの回転をあわせる機能
Animation
Mesh2P (Skeltal Mesh Component) > Animation
Anim Class にアニメーションブループリントを指定すると、アニメーションブループリントに沿ってアニメーションの遷移がおこなわれる
カテゴリ
変数 > カテゴリ
赤線のやつ
Cast Shadow
Skeltal Mesh Component > Lighting > Cast Shadow
影を落とす落とさないの切り替えができる
イベントグラフ
Add Controller (Pitch / Yaw) Input
エディタ側の説明テキスト
これは説明の通りControlRotationに引数で与えた(値 * InputViewScale)の値をPitch または Yawに加算している処理になる
Characterコンポーネントを所有しているオブジェクトが回転していた理由がわからずコードを読み漁っていたのだけれど、CharacterコンポーネントのUse Controller Rotation Yawにチェックが入っていたのが原因だったようで、あくまでPlayerControllerを経由して回転させているのであって、この関数自体が直接Character側のRotateをいじっているわけではないようだった
Add movement Input
DefaultPawn CharacterコンポーネントではAddMovementInputを使用した際に移動の処理を自動でしてくれる
逆に言えばそれ以外は自前でその辺りのコードを組まなくてはいけない
内部的にはAddMovementInputで設定したベクトルとスケールをVelocityに設定している(その過程では結構色々な関数を通ってたりするるので注意)
ControlInputVectorに加算
毎フレーム呼ばれる関数(Tick)でConsumeInputVectorを使用してベクトルを取得
なんやかんやあってVelocityにセット
といった流れ
Jump / Stop Jumping
Jump
Stop Jump
CharacterコンポーネントにはJumpMaxHoldTimeというパラメータが定義されており、Jumpを実行してからStop Jumpを実行するまで or Jumpを実行してからJumpMaxHoldTimeで設定した時間経過するまでの間、キャラクターが上昇し続ける。
今回のサンプルの場合、JumpMaxHoldTimeが0に設定されているため、Stop Jumpを実行しなくても問題はないようになっている
コンストラクションスクリプト
そもそもコンストラクションスクリプトとは？
ブループリントがレベル内に配置したタイミングで実行される
使いみちは何やら色々あるらしい
参考になりそうなリンクたち

コンストラクション スクリプト | Unreal Engine ドキュメント
[UE4] コンストラクションスクリプトでお手軽にプロシージャルなアクターを作る
AttachToComponent
AttachToComponentの詳しい説明は↓のサイトを参照してもらえればおおよそ理解できる
Socket NameがGripPointになっており、FP_Gunのスケルトンに同名のものが存在する
これで銃がモデルの手の動きに合わせて移動するように自動で設定されるようになった
