Sparse attention reduces the algorithmic cost of long-sequence
video Transformers, but three-dimensional token layouts can leave
selected block-sparse regions only partially occupied. As a result,

Introduction
Self-attention is the core computation in Transformer architectures [19], and its quadratic complexity becomes particularly expensive in modern video diffusion Transformers (DiTs) [14]. Stateof-the-art video generators typically operate on compressed spatiotemporal representations and use Transformer backbones over

long token sequences [2, 8, 20, 23]. In particular, modern video variational autoencoders (VAEs) compress video along both temporal
and spatial dimensions, producing an underlying three-dimensional
token organization that can be written as 𝑇 ×𝐻 ×𝑊 . Once flattened
for Transformer execution, these representations can contain tens
or hundreds of thousands of tokens, making attention one of the
dominant costs of both training and inference.
Sparse attention is a natural way to reduce this cost. Earlier work
established structured sparse attention for long sequences using
strided, local, global, or mixed connectivity [1, 3, 26]. For video
generation, the spatial and temporal structure provides substantially stronger sparsity opportunities. Recent systems exploit either
structured spatiotemporal locality or content-dependent sparse selection. Sparse VideoGen identifies spatial- and temporal-dominant
attention heads [21]; STA converts 3D local attention into hardwarefriendly tiles [29]; VSA learns dynamic 3D block selection [28];
SVG2 uses semantic clustering and permutation to densify selected
regions [22]; and Radial Attention constructs a distance-dependent
sparse pattern for long videos [9]. SSTA further combines selective
and sliding-tile attention in HunyuanVideo 1.5 [18]. Other recent
systems, including SpargeAttention, VORTA, FPSAttention, and
SPADE, likewise exploit structured or dynamic sparsity to reduce
video attention cost [10, 11, 17, 27].
Despite their different sparse-selection mechanisms, efficient
implementations of these methods share an important property:
sparse attention is eventually quantized into block- or tile-level
GPU execution. This is necessary because reducing arithmetic work
alone does not guarantee wall-clock speedup. Efficient attention
kernels depend on sufficiently large matrix operations, regular
memory movement, and fused online softmax. Consequently, sparse
selection can identify useful interactions at a finer granularity than
the tiles a GPU executes efficiently.
This mismatch is particularly important for three-dimensional
video layouts. A logical sparse block is defined over a flattened
token sequence, while token validity is inherited from the original
𝑇 × 𝐻 × 𝑊 geometry. If a temporal or spatial dimension is not
aligned with the blocking geometry, boundary blocks contain fewer
valid tokens than their nominal block size. Unlike one-dimensional
sequence padding, which is commonly concentrated at the end of a
sequence, multidimensional boundaries recur along temporal and
spatial surfaces and their intersections. After flattening, partially
occupied blocks can therefore appear repeatedly throughout the
sequence.
This is not a hypothetical corner case. Existing video sparseattention systems have independently encountered closely related
forms of intra-block under-utilization. STA identifies mixed blocks,
in which only part of a hardware tile belongs to the desired 2D
or 3D attention window, and redesigns the sliding pattern so that
executed tiles are predominantly fully dense or fully empty [29].
SVG2 observes the same granularity problem for dynamically sized
semantic clusters: a useful 128 × 32 attention region executed with
a fixed 128 × 128 sparse kernel requires 75% of the physical computation to be spent outside the useful region [22]. VSA exposes
the complementary hardware trade-off: smaller sparse blocks provide finer selection granularity, but reducing the block size lowers
kernel throughput; its implementation therefore uses a 64 × 64
block-sparse kernel and carefully balances sparsity against hardware efficiency [28].
The difficulty is that simply shrinking the compute tile is not
free. The evolution from FlashAttention to FlashAttention-2 (FA2),
FlashAttention-3 (FA3), and FA4 has progressively increased the importance of hardware-aware tiling, asynchronous data movement,
and deeply pipelined matrix operations [4, 5, 15, 25]. ThunderKittens similarly builds high-performance attention around regular
tile abstractions and asynchronous pipelines [16], while FlashInfer
and FlexAttention retain block-structured execution to combine
flexibility with high GPU efficiency [6, 24]. Thus, smaller execution
granularity can remove padding but can also give up the efficiency
of large attention tiles.
Current systems address this tension in several ways. STA changes
the sparse pattern so that mixed blocks disappear. SVG2 changes the
compute geometry itself by supporting dynamically sized blocks.
General block-sparse executors such as NVIDIA BSA retain a fixed
block representation while accepting valid-length metadata so that
padded K/V rows are excluded from the mathematical attention
result [13]. For fixed-tile block-sparse execution, valid rows from different selected logical blocks remain uncombined, leaving physical
tile capacity underutilized. Fine-grained sparse execution such as
FG-Attn gathers selected K/V vectors into packed shared-memory
tiles [7], but its fine-grained units represent the attention sparsity
pattern itself rather than invalid rows inside an already selected 3D
sparse block.
We present KPage, which removes partial-block waste by packing data rather than shrinking the large compute tile. KPage keeps
the original blk128 sparse graph but divides selected K/V blocks into
16-row pages. Valid Page16 regions from different logical blocks are
compacted across block boundaries and gathered directly into the
shared-memory stages of the attention kernel. No compacted K/V
tensor is materialized in HBM. The resulting physical tile remains
large enough for efficient Tensor Core execution while containing
substantially less padding.
KPage also addresses partial occupancy on the query dimension.
Query blocks with at most 64 valid rows use an 𝑀64 × 𝑁 256 path,
while larger blocks use 𝑀128 × 𝑁 128; both geometries contain the
same 16,384 query–key positions per physical tile. Invalid rows
in partial pages are masked before the online-softmax row maximum, preserving exact attention semantics. For backward, KPage
constructs a K/V-owned paged layout, derives reverse-Q neighborhoods for packed K/V tiles, and uses page-pair adjacency metadata
to restore the original Q–K sparse graph after both sides have been
physically packed.
The page abstraction does not require Q and K/V to share one
logical partition. We expose separate per-head Q block sizes and K/V
block sizes and offsets, allowing independently clustered layouts
such as SVG2 to reuse the same page execution. Q clusters retain
the Q64/Q128 routes, while independently sized K/V clusters are
placed on Page16 boundaries.

3 Methodology and Implementation
3.1 Overview
KPage retains the logical blk128 sparse graph while changing its
mapping to physical attention tiles. In forward, selected K/V blocks
are divided into 16-row pages and valid pages from different blocks
are packed into the same large tile. Two query tile shapes reduce
Q-side padding without merging Q blocks with different sparse
neighborhoods.
Backward requires a different organization: multiple Q blocks
may contribute to the gradients of the same K/V block. KPage
therefore packs pages into K/V-owned tiles, traverses their reverseQ neighborhoods, and records page-pair adjacency to preserve the
original sparse graph. Algorithm 1 summarizes the execution flow.

Both paths expose the same number of Q–K positions per physical tile: 64 × 256 = 128 × 128 = 16,384. The Q64 path therefore
reduces unused Q rows without reducing the tile area presented to
Tensor Core. It consumes sixteen Page16 K/V regions per iteration;
the Q128 path consumes eight.
The two optimizations operate independently. Page compaction
reduces waste in the K/V dimension, while Q64/Q128 routing reduces waste in the Q dimension. Neither operation changes the
sparse neighborhood of the query block.
Query blocks from the two paths are placed in separate persistent
work queues. Within each route, longer page walks are scheduled
earlier to reduce the tail caused by uneven sparse workloads. The
underlying pipeline requires aligned iteration counts, so a small
number of dummy pages can remain at the end of a walk. These
pages are handled by the same validity mechanism as partial pages.
This ordering is required for exact attention semantics. Since
invalid scores are removed before the maximum and exponential,
they contribute neither to the online-softmax maximum nor to its
denominator.
KPage stores validity at Page16 granularity using compact bit
masks. Two Page16 masks are packed into one 32-bit word. The
page-table builder also records where the fully valid region ends,
so validity metadata is only accessed for physical tiles that overlap
the partial suffix.
The distinction is reflected in the kernel implementation. For
fully valid tiles, KPage retains the fused score-loading and rowmaximum path used by the underlying kernel. For a masked tile,
the scores are loaded, the packed validity predicate is applied, and
the row maximum is then computed from the masked values. The
additional masking work is therefore restricted to tiles that actually
contain partial or dummy rows.
For partial K/V pages, the unused suffix is also zeroed before the
attention launch so that the Page16 TMA transfer remains a regular
contiguous load. This zeroing is an implementation convenience;
exact softmax semantics are provided by Eq. (3).
3.2.3 Direct page-guided K/V loading. Materializing the compacted
K/V layout in HBM would require an additional gather kernel followed by another HBM read by the attention kernel. Instead, KPage
uses the page table to assemble packed K/V tiles directly in shared
memory during data loading, avoiding intermediate HBM materialization.

4.1 Experimental Setup
We evaluate KPage using a controlled padding comparison and
five representative sparse-attention workload cases covering varied
sequence lengths, sparsity levels, and block-occupancy patterns.
Timing methodology. Unless otherwise stated, we report bare
attention-kernel execution time. Sparse-graph construction, KPage
page-table construction, Q64/Q128 route assignment, and backward layout construction are performed outside the timed region
because these structures depend only on the sparse graph and block
occupancies and can be reused while the layout remains unchanged.
The timed region contains the complete attention kernel, including page-table traversal, page-guided K/V loading, partial-page
masking, online softmax, and output computation. No compacted
K/V tensor is materialized in HBM.
For the controlled workloads in Table 1, we report the median of
20 timed iterations after 5 warmup iterations. For the five representative workload cases, we report the median of 10 timed iterations
after 3 warmup iterations. For the SVG2 study, we report the median
of 20 timed iterations after 3 warmup iterations. All measurements
use synchronized wall-clock timing on a single GPU and a single
execution stream.
Controlled workloads. We construct two groups of matched-scale
workloads corresponding to 5, 10, 15, and 30 s video sequences.
The first group contains no padding: all selected logical blocks are
fully occupied. The second group uses three-dimensional layouts
that produce partially occupied boundary blocks. Across these workloads, padding accounts for 20.8–22.8% of the physical sequence,
and approximately one third of the logical blocks are partial.
Both groups use the same sparse-selection procedure and comparable sequence scales. Within each workload, KPage and NVIDIA
BSA consume the same sparse block graph and the same valid-row
metadata.
The two groups are not identical sparse graphs because the underlying layouts produce different numbers of logical blocks under
the same selection procedure. We therefore use this experiment to
compare two execution regimes: fully occupied blocks and layouts
with substantial partial-block fragmentation.

Conclusion
KPage improves the execution of partially occupied block-sparse
attention without changing the sparse graph or shrinking the large
10
compute tile. It decomposes selected K/V blocks into Page16 regions, packs valid pages across logical-block boundaries, and assembles the resulting physical tiles directly during K/V loading.
Query-adaptive 𝑀64 × 𝑁 256/𝑀128 × 𝑁 128 execution reduces Qside padding, while a K/V-owned paged layout extends the same
compaction principle to exact backward execution.
KPage is effectively on par with NVIDIA BSA when all logical blocks are fully occupied (1.03× geometric mean), but reaches
2.29× geometric-mean forward speedup under 3D partial-block
fragmentation and 1.77× across five representative workload cases.
Page16 K/V compaction and query routing reduce physical pair
capacity from 334.1G to 177.5G positions for 160.6G useful interactions, increasing pair-capacity efficiency from 48.1% to 90.5%.
The open-source cross-system evaluation confirms that this behavior is not pipeline-specific: across reconstructed SSTA, STA, and
VSA layouts, KPage achieves 1.13–4.25× forward speedup over the
strongest exact baseline while remaining close to parity as blocks
become full. Separate Q/K partition metadata further extends the
same page kernels to SVG2’s independent semantic clusters. On
the paper-matched Wan 14B/720p trace, KPage is 1.49× faster than
the strongest exact sparse baseline and 1.57× faster than NVIDIA
BSA.
The central result is that block-sparse attention need not choose
between fine-grained padding removal and large-tile execution:
fine-grained page packing can fill large physical tiles while preserving the original sparse-attention semantics.
