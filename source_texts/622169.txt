Owner
Adds <ray_mode>raycast</ray_mode>: every Ouster beam cast as an exact ray against an ECM scene mirror — the "full raycast" option, complementing the default depth-panel rig.
What it does
Exact geometry: calibrated beam elevation, per-beam azimuth offset, encoder column, and true beam-origin parallax — ray origins sit on the beam-origin circle and the reported range follows the Ouster XYZ-LUT convention (xyz = (r−n)·d̂ + n·[cosθ,sinθ,0]), so consumers reconstruct the exact hit points. Zero interpolation error anywhere in the pipeline.
Runs on the active backend, CPU always available: RayProcessor::castScan executes the same shared per-ray function (rcCastOneRay, cuda/raycast_math.hpp) as a CUDA / HIP / SYCL kernel, or as the OpenMP CPU fallback — the standard backend contract (CUDA → HIP → SYCL → CPU). GPU backends cache the uploaded scene geometry by a monotonically increasing scene version; steady state uploads only the per-scan transforms.
laser_retro restored: the raycaster reports the nearest hit's components::LaserRetro, so reflectivity/signal/near-IR are driven by scene materials again (the panel rig cannot carry this channel).
No rendering dependency: raycast mode never touches Ogre2 — no panel cameras, no anchor-sensor requirement, and the scan is throttled on sim time.
How
cuda/raycast_math.hpp — device/host (GZ_OUSTER_HD) intersectors (sphere/box/cylinder/plane/triangle-BVH) over flat POD arrays; NaN-free explicit-branch slab tests.
cuda/raycast_scene.{hpp,cpp} — flat scene builder (addMesh/addInstance; BVH indices, order entries and vertex indices globally rebased so the arrays upload to a device as-is) + the OpenMP CPU reference cast.
Backends — castScan on CPU/CUDA/HIP/SYCL with version-cached scene upload; processDepth runs the unchanged noise/channel stage on the cast output.
Plugin — ECM scene mirror (mesh URIs via MeshManager with caching; plane normals folded into instance poses; spawn/despawn-triggered rebuilds via immutable shared_ptr snapshots), worker thread feeding the existing triple-buffer, and processor_mtx_ serialising the worker's castScan against the sim thread's processDepth on the shared backend stream.
Install fix — the cuda/ headers that the public headers quote-include now install next to them (also fixes the same latent issue for the pre-existing imu_noise.hpp/panel_layout.hpp includes).
Verification (local, CPU stack)
Intersector unit checks; BVH ≡ brute force on a 300-triangle random soup; mesh-box ≡ analytic-box (max err 0.0); beam-origin XYZ-LUT invariant; retro of nearest hit; near-clip see-through (housing case); uniform shell at exactly the radius (max err 0.0); axis-parallel grazing-ray NaN regression; castScan + processDepth end-to-end through the dispatcher.
Perf sanity: ~12 ms/scan for OS1-128@1024 against a 40-instance scene on the CPU path in a low-core container; GPU kernels are one-thread-per-ray.
Limitations (documented in README / plugin_example.sdf)
Capsule/ellipsoid/heightmap/actor visuals are not mirrored (counted + logged at startup); visibility_mask does not apply in raycast mode; the 0.3 m near clip stands in for sensor-housing self-hits.

Casts every Ouster beam as an exact ray — calibrated elevation, per-beam
azimuth offset, encoder column, and TRUE beam-origin parallax (ray
origins on the beam-origin circle; reported range follows the Ouster
XYZ-LUT convention xyz = (r-n)*dir + n*[cos,sin,0], so consumers
reconstruct the exact hit points) — against a mirror of the scene. Zero
interpolation error anywhere in the pipeline, and laser_retro returns
as the reflectivity/signal source (the panel rig cannot carry it).

- cuda/raycast_scene.{hpp,cpp}: self-contained CPU raycaster. Analytic
  sphere/box/cylinder/plane intersectors plus triangle meshes behind a
  median-split BVH; per-instance rigid transforms with world-AABB broad
  phase; OpenMP across the H*W rays. No Gazebo/rendering deps.
- Plugin: ECM scene mirror (visual geometries extracted once, mesh URIs
  resolved through MeshManager with a per-URI cache, laser_retro from
  components::LaserRetro, plane normals folded into the instance pose);
  poses refreshed every scan, spawn/despawn triggers a rebuild shared
  with the worker via immutable shared_ptr snapshots. A dedicated
  worker thread casts the scan and feeds the existing frame
  triple-buffer. Raycast mode never touches the renderer: no panel
  cameras, no anchor-sensor requirement, scan throttled on sim time.
- RayProcessor/Backend::processDepth: noise/channel stage entry for
  callers holding exact ranges (CPU/CUDA/HIP/SYCL; lazy retro device
  buffer so the panels path pays nothing).
- test_raycast: intersector correctness, BVH-vs-brute-force equivalence
  on a random soup, mesh-box vs analytic-box agreement, beam-origin
  XYZ-LUT invariant, retro of nearest hit, near-clip see-through,
  zero-error uniform shell, processDepth through the dispatcher.

Verified locally on the CPU stack: all checks pass with max error 0.0
on the shell/mesh comparisons; ~9 ms/scan for OS1-128@1024 against a
40-instance scene in this (low-core) container.

Limitations (documented): capsule/ellipsoid/heightmap/actor visuals are
not mirrored; visibility_mask does not apply; near clip (0.3 m) stands
in for housing self-hits.

Pull request overview
This PR adds a new full per-beam “raycast” mode for the Ouster lidar plugin that casts each beam as an exact analytic ray against an ECM-mirrored scene (BVH + primitives), removing the Ogre2 panel-rendering dependency while restoring per-hit laser_retro for downstream intensity/reflectivity.
Changes:
Added ray_mode (panels | raycast) to switch between the existing depth-panel rig and a new CPU/OpenMP raycaster against an ECM scene mirror.
Introduced a self-contained raycasting library (rc::Scene) with primitive intersectors and per-mesh BVH traversal, plus an end-to-end gtest suite validating correctness/invariants.
Added RayProcessor::processDepth() to run the noise/channel stage directly from exact per-beam ranges (+ optional retro), implemented across CPU/CUDA/HIP/SYCL backends.
