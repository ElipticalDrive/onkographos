Hexenwail has exactly one GPU compute shader (engine/h2shared/gl_worldcull.c:454, the world-culling dispatch). vkQuake ships eight. This epic ports the high-value-gap shaders from vkQuake to close that gap, independent of the SDL_GPU backend decision in uhexen2-p4ln.
Source: vkQuake at https://github.com/Novum/vkQuake, GPL-2.0-or-later (same as uHexen2). Porting requires attribution in all derived files/functions and commit messages.
Measurement: vkQuake's 8 compute shaders are in Shaders/. SIX ARE EXCLUDED intentionally:
skinning.comp (149 lines) + mesh_interpolate.comp (87 lines): both state they exist for acceleration structure building (vkQuake's BLAS/TLAS). We have no ray-tracing path, and SDL_GPU explicitly excludes ray tracing.
ray_debug.comp (RT debug), indirect.comp, indirect_clear.comp (we already have GPU-driven culling in gl_worldcull.c + 3 glMultiDrawElementsIndirect sites, largely covered).
Key property: all ported shaders target GL 4.3 TODAY via uniform/SSBO conventions. This is algorithm not API; no SDL_GPU backend dependency.
Porting constraint: vkQuake's shaders are GLSL 4.60 targeting Vulkan/SPIR-V with descriptor sets and push constants. Our translation maps those to GL 4.3 uniform/SSBO conventions — the algorithm ports, the binding syntax does not.
Tracked in beads as uhexen2-0aez.

Re-audited against vkQuake master. The epic's "8 compute shaders" is stale: upstream now ships 18. The ones in scope, and where each landed:
upstream
status
screen_effects.comp
no-go, evaluated and closed in #88: our single fragment post pass already folds the same stages, and GLES/WebGL2 has no compute
update_lightmap.comp
filed as #439, but via Ironwail's design (per-style lightmap layers summed in the world fragment shader), which needs no compute and therefore also covers the GLES tier
ssao_*.comp (10 variants)
new since this epic; tracked by #188 (SSAO)
cs_tex_warp.comp
turbulent-liquid texture warp into a render target. We warp liquids per fragment in the turb shader, so there is no pass to replace; no gain identified
skinning, mesh_interpolate, ray_debug, indirect*
excluded, as originally stated
Compute shaders here today: world culling (gl_worldcull.c), light clustering (gl_lightcluster.c) and the softemu palette LUT builder (gl_postprocess.c). So the "one compute shader" premise is also out of date. Leaving this open as the umbrella until #439 lands.
