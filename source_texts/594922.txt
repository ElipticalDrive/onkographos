Summary
Implements an OrbitControls-first navigation UX on top of recovered/voxel-camera-ui, revised after hands-on comparison with the official Three.js OrbitControls example.
Standard Orbit behavior
Native Three.js OrbitControls is the default.
LMB = orbit.
MMB = dolly.
RMB = pan.
Mouse wheel = dolly.
Arrow keys = pan.
Shift/Ctrl/Meta + Arrow = rotate.
enableDamping = true, dampingFactor = 0.05.
screenSpacePanning = false.
cursorStyle = 'grab'.
60° default perspective FOV.
Full polar range is retained intentionally so the PLY viewer's ±X/±Y/±Z presets remain valid.
OrbitControls keyboard events are ignored while editing input/select/textarea controls.
PLY-specific behavior retained
Double-click geometry sets the Orbit target while keeping the camera position fixed.
Shift + double-click measures without changing the target.
Empty-space double-click is inert; Fit remains explicit.
Camera orientation presets and XYZ editing stay synchronized with the same target.
Trackball, Inverse Trackball, and Arcball remain available under Advanced Navigation.
VS Code integration
No new extension↔webview navigation protocol.
No CSP relaxation.
Existing retainContextWhenHidden: true behavior remains.
OrbitControls is attached directly to the webview canvas.
The r185 dispose() -> disconnect() -> stopListenToKeyEvents() lifecycle removes the global arrow-key listener when switching controls.
Final verification
GitHub Actions: https://github.com/estebvac/ply-visualizer/actions/runs/35971339618
Passed:
compile + Svelte checks
lint + feature diff whitespace
focused Orbit navigation regressions
damping and arrow-key interaction tests
pivot / measurement / camera preset tests
2M-point picking regression
recovery-baseline semantic-diff checks for excluded legacy stress tests
remaining engine browser suite
VS Code extension-host suite
VSIX package + artifact upload
Two known recovery-baseline browser failures remain excluded and are verified unchanged:
file-list-interactions.spec.ts references a missing fixture.
large-lidar-chunking.spec.ts targets a newer typed-buffer API than the recovered implementation.
