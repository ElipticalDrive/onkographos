Description
Created a new container that stores particles in two octrees: One for the owned particles and one for the halo particles.
Adapt the iteration patterns for containers (begin, getRegionIterator and iteratePairwise)
Added test cases that verify the validity of the internal octree structure
Added a simple C01 traversal that is capable of iterating the octree structure pairwise using the Samet-neighbor finding approach
Started to add a C18 traversal, that is currently disabled (see OTNaiveTraversal is disabled #621 for more information)
The code provides two methods of finding leaves in the octree:
A neighbor finding algorithm that uses the spacial structure of the octree (relationship between parents/children and careful crafting of the connecting pointers) according to the paper from Hanan Samet
A range query approach that includes all leaves that are found in a given region
These methods are used in the traversal functions and inside getRegionIterator and provide fast access to the leaf nodes of the octree.
How Has This Been Tested?
Add predefined particles to the octree and check whether children are correctly generated and spaced using the testChildIndexing test
Create an octree with random particles and check for each leaf whether found neighbors really touch the leaf in the intended way in the testNeighborLocator.
Check if the range-query finding of neighbor nodes in testRangeNeighborFinding
Verification that leaves only split if their size allows them to (tested in testUnableToSplit and testAbleToSplit)
Compare the interactions that are generated from the octree's iteratePairwise function with a reference implementation (LinkedCells) in testCustomParticleDistribution
