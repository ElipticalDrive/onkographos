Follow-up to #3167; used by visgl/deck.gl#10627
Background
Allow host render loops to prepare splat compute before their own render pass, and allow worker-driven RAD selection to publish coherent intermediate refinements after camera changes.
Change List
Add GPUPagedSplatRenderer.prepare() and borrowed-pass draw()
Support CPU-only generic residency and RAD hierarchy data
Add complete-cut and progressive selection with bounded page demand and protected visible dependencies
Avoid camera-only row uploads and clear stale sparse indirection
Keep deep traversal iterative and remove unused progressive retarget indexing
Sort paged splats by 32-bit linear depth and align final vertex depth with WebGPU host geometry
Refresh camera-only page priorities without rebuilding row arrays; reclaim least-priority complete groups when visible rows exceed capacity
Add ownership, progressive-selection, sorting and real shared-pass pixel regressions
Update API guidance, hard-budget behavior, roadmap and release notes

Documentation
The audited source and documentation remain unchanged. The final test-only correction to test/examples/gaussian-splat-docs-embed.node.spec.ts now explicitly checks the roadmap's partially implemented host-pass tranche while preserving the other planned-tranche checks. That correction passed the full Node suite but falls outside the final documentation-audit snapshot. Publishing it without another documentation audit was explicitly approved; the final expanded scope is not claimed fully re-audited.
Remaining risk
This is experimental infrastructure, not a merge-ready or full-browser-matrix claim. The complete repository browser/coverage matrix was not rerun locally in this update; use current-head CI for that gate. Earlier unrelated full-browser failures are not claimed fixed by this work.
Camera retargeting still walks the retained tree synchronously and belongs in a worker for large selections. Linear-depth sorting corrects quantization-induced ties, not every artifact from intersecting Gaussians. Live timing varied too much for a controlled performance claim. Neither these renderer changes nor the documentation audit establishes scene-data licensing or a fixed refinement-latency guarantee.
Note
Medium Risk
Large changes to RAD traversal, frontier publishing, and paged renderer command-graph lifecycle affect streaming LOD and deck.gl composition; behavior is heavily tested but remains experimental splats infrastructure.
Overview
Adds host-composable rendering for GPUPagedSplatRenderer: prepare() runs projection/sort compute without opening a pass, and draw() issues draws inside a caller-owned render pass (e.g. deck.gl). encode() remains the all-in-one path; switching modes rebuilds the command graph. Frontier updates can borrow unsplit activeRows without copying, skip GPU re-upload on camera-only changes, and clear stale sparse indirection when pages go dense.
RAD hierarchy and residency are generalized for worker-side selection: SplatResidencyData / SplatRADHierarchyData support CPU-only page metadata without a GPU device. New selectView() builds a full best-first cut (optionally sliced); refineView() retargets the displayed cut and publishes coherent sibling replacements while the camera moves. Traversal gains frustumCulling, maximumResidentPages, and maximumPendingPages, plus incremental publishing and page-demand logic so visible detail and dependencies stay stable under budgets.
Docs and release notes describe CPU-only RAD selection, package boundaries (residency/selection in @luma.gl/splats), and the prepare/draw integration pattern. Tests cover shared-pass behavior, row-upload elision, sparse-to-dense frontiers, and CPU residency.
