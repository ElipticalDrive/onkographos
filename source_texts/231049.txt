Closes #136. Part of #131; feeds the neural-field 4D-Var work (jejjohnson/geostack#82).
What
geonnax.SeparableINR (new module geonnax.separable): a separable neural field in the style of SPINN (Cho et al., NeurIPS 2023). Each of the A input axes has its own network φ_a : ℝ → ℝ^{r×K}, either a SIREN (the default) or a tanh eqx.nn.MLP (net="mlp", as in the paper). The field is
f(x)_k = Σ_r Π_a φ_a(x_a)[r, k].
SeparableINR.init(num_axes, rank, hidden_features, depth, out_features=1, *, net="siren", first_omega=30.0, key) validates its arguments and splits the key once per axis.
__call__(x: (A,)) -> (K,) evaluates one point; batch it with vmap.
on_grid((c_1, …, c_A)) -> (K, N_1, …, N_A) evaluates the tensor-product grid using Σ N_a network calls instead of Π N_a.
The A-ary contraction uses jnp.einsum, because einx.dot can only contract an axis shared by two operands.
Fields: axis_nets (a tuple), plus static rank and out_features.
Init scale (documented, not rescaled — as in SPINN). With SIREN axes the field starts at O(√r) for any number of axes. With tanh-MLP axes it shrinks geometrically with A (std ≈ 2e-3 at A=3, 2e-6 at A=6, r=16), so the docstring recommends net="siren" beyond two axes.
Docs and registration:
AGENTS.md records the new edge separable → siren and adds the family-table entry.
Added to docs/api/representation.md, the capability index and the plugin skill.
Tests (tests/test_separable.py)
on_grid equals vmap(__call__) over the meshgrid (atol 1e-5, float32 round-off from contraction order). Covered for A ∈ {1, 2, 3} (3 is slow), rank ∈ {1, 8}, and both siren and mlp.
__call__ equals the explicit rank sum of per-axis products.
Distinct keys per axis, validation of init and of the call shapes, and finite jit/grad and jacfwd.
on_grid under jax.vmap over a batch of coordinate arrays.
A fit of the rank-1 target sin(πx)·cos(πy) reaches MSE < 1e-3 (integration tier); observed 1.5–3.1e-5 over keys 0–4, a 30× margin. It uses a hand-rolled Adam, because optax is not a dependency.
Note: the pinned pre-commit ruff (v0.17.1) formats Python code blocks in Markdown, so it also reformatted the other examples in docs/api/representation.md (CI's ruff 0.15 does not check Markdown).
Lint, format, ty, the fast tier, all tiers of the new file and the doctests pass locally.
