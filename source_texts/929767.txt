Currently we have the Atomic.compare_and_set primitive. It would be nice to also have Atomic.compare_and_exchange as it also often found as a primitive in the description of multiprocessor algorithms and in other APIs (e.g. C++, guile).
It can be implemented on top of Atomic.compare_and_set with something like:
```
let rec atomic_compare_and_exchange a ~expect ~set =
  let current = Atomic.get a in
  if not (current == expect) then current else
  if Atomic.compare_and_set a expect set then expect else
  (backoff (); atomic_compare_and_exchange a ~expect ~set)
```
It's sometime found under the name compare_and_swap but since we have Atomic.exchange I'd suggest to stick with Atomic.compare_and_exchange. It also nicer to label the arguments to avoid having to memorize the order of arguments and provide more clarity in context. Here are two proposals:
```
Atomic.compare_and_exchange : 'a t -> expected:'a -> set:'a -> 'a
Atomic.compare_and_exchange : 'a t -> expected:'a -> desired:'a -> 'a 
```
And a doc string:
```
[compare_and_exchange r ~expected ~set] sets the value of [r] to [set] if 
and only if the current value of [r] is physically equal to [expected] -- the
comparison and the set occur atomically. The function returns the tested value 
of [r], so if it is physically equal to [expected], the [set] happened.
```
