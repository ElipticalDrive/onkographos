Closes K12 (Chapter 2, 2D), which finishes 2D's mesher work. There's no GitHub issue for it, so nothing to link.
Stacked on #32 (on #31, on #30). Merge those first; GitHub then retargets this.
What it does
BurstChunkMesher (Core, 0cc6f68) runs the K32 loop as a Burst IJob over native arrays:
densities copied in a Z layer at a time through IVoxelStorage.ReadLayer (A12);
Marching Cubes tables flattened;
output into NativeLists.
Same mesh as ChunkMesher: same corner reuse, early skip, edge placement and vertex sharing. Schedule() returns a JobHandle, and the job frees its own inputs, so many chunks can mesh at once.
WorldConfig.Mesher (fd07ff1) picks Managed or Burst for every chunk build (A6). ChunkMeshBuilder uploads Burst output straight from its native lists. Managed stays the default and is what step-through records (A11). The switch is in the panel's and Inspector's Meshing section.
Benchmarks (e81198c): both meshers per size, and at world scale the Burst job one chunk at a time and one job per chunk in parallel.

Smooth shading costs Burst almost nothing extra.
Generation (380 ms for that world) is now the whole cost. That's K35.
Packages
com.unity.burst 1.8.30, com.unity.collections 2.6.8 and com.unity.mathematics 1.3.3 are now listed in manifest.json. They were already installed as dependencies of other packages, so no versions change; the lock file only records them as direct dependencies. Core, Debug and the tests reference them.
Testing
EditMode suite in batch mode: 185/185 passed. That includes BurstChunkMesherTests, which matches the managed mesher for every edge placement and shading, plus an empty chunk.
WorldLab in Play mode, switched to Burst: same triangle and vertex counts as managed, flat and smooth. It renders correctly, with no errors or native leak warnings on exit.
Demo exe: builds (0 errors) with lib_burst_generated.dll.
