Changelog entry (a user-readable short description of the changes that goes to CHANGELOG.md):
Add in-memory compressed dictionary for LowCardinality to reduce memory consumption and enhance throughput
Documentation entry for user-facing changes
Documentation is written (mandatory for new features)
Adds session settings low_cardinality_experimental_compression and low_cardinality_compression_fc_block_parameter. These settings are used to enable in-memory front coding compression of dictionaries inside of LowCardinality(String). It greatly reduces memory consumption at the cost of some execution speed. Overall throughput is enhanced. Especially useful when there are high numbers of unique elements in a column.
Technical details: compression is implemented via a ColumnUniqueCompressed column that contains compressed data and can be used inside of LowCardinality. A lot of changes are made to enable all the systems to work with LowCardinality columns with compressed dictionaries inside.
Some additional optimizations are in development.

AI Review
Summary
This PR adds an experimental front-coded in-memory dictionary implementation for LowCardinality(String) / LowCardinality(Nullable(String)) and wires it into low-cardinality construction, hashing, and serialization. I found multiple blocker-level correctness issues in the new dictionary implementation and its serialization integration, plus one major configuration problem, so this is not ready to merge.
Findings
❌ Blockers
[src/Columns/IColumnUnique.h:25] Returning an owning ColumnPtr from getNestedColumn / getNestedNotNullableColumn is still only partially integrated. Unchanged callers in HashMethod.h, LowCardinalityExecutionHelpers.h, WindowTransform.cpp, StatisticsUniq.cpp, and similar sites still keep raw borrows from temporaries, so a compressed dictionary can leave them with dangling pointers/references.
[src/Columns/ColumnUniqueCompressed.cpp:492,504] uniqueInsertRangeWithOverflow still breaks non-zero slices in two places: it passes an absolute row index as the cut length, and it fills a length-sized result buffer via indexes_data[i] while i runs from start to start + length. Any caller that uses start != 0 can read the wrong rows and write past the end of the result column.
[src/Columns/ColumnUniqueCompressed.cpp:374,492] Both range-insert paths batch the nested ColumnString into prepareForInsert before they consult the null map. ColumnNullable does not guarantee meaningful nested bytes under NULL, so nullable range inserts can silently add phantom dictionary keys even though the returned row position is still the null index.
[src/Columns/ColumnUniqueCompressed.cpp:115,624,645] Serialized-size accounting double-counts block-header rows. Header entries already store the full string in data_column, but getSizeAt adds the header prefix length again, so preallocated serialized-key paths hash and compare trailing garbage bytes for those dictionary entries.
[src/Columns/ColumnUniqueCompressed.cpp:761] ColumnUniqueFCBlockDF::compareAt assumes that the RHS is another ColumnUniqueFCBlockDF and downcasts it with assert_cast, which is a plain static_cast in release builds. ColumnLowCardinality::compareAt is representation-transparent, and production code still constructs plain ColumnUnique<ColumnString> dictionaries directly (for example DWARFBlockInputFormat), so mixed compressed/uncompressed LowCardinality(String) comparisons become UB.
[src/DataTypes/Serializations/SerializationLowCardinality.cpp:611] When a compressed shared dictionary reorders existing keys, the writer emits a replacement dictionary for the current granule but leaves NeedUpdateDictionary cleared because need_update_dictionary was captured before the insert. The reader then decodes the current granule’s indexes against the previous global dictionary and returns wrong values.
⚠️ Majors
[src/Columns/ColumnUniqueCompressed.cpp:817,829] haveIndexesChanged() now effectively means “did prepareForInsert run?” rather than “did any existing dictionary position move?”. Duplicate-only batches or monotonic appends therefore force unnecessary dictionary rewrites and make low_cardinality_use_single_dictionary_for_part = 1 throw even when the mapping is an identity permutation.
[src/DataTypes/DataTypeLowCardinality.cpp:101-108] Unknown low_cardinality_experimental_compression values silently fall back to NONE, so typos and stale configs disable the feature instead of failing fast with a clear exception.
Tests
⚠️ I did not run local code in this review.
⚠️ Current coverage misses mixed compressed/uncompressed LowCardinality comparisons, nullable range inserts with non-default nested bytes under NULL, non-zero start in uniqueInsertRangeWithOverflow, preallocated serialized-key hashing, and shared-dictionary serialization after reindexing.
Final Verdict
❌ Request changes. The new compressed dictionary still has unresolved lifetime issues, breaks several insert/compare/serialization contracts, and can misdecode serialized data after dictionary reordering.
