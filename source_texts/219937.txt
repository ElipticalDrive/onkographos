Owner
Fixes #124. Graphics PR: needs the all-platform screenshot sets (CONTRIBUTING, "Graphics changes"). The win-arm64 set is below.
Cause. The Vulkan raster path never built shadow volumes. R_AddLightSurfaces queued each visible caster's own triangles as its shadow. DrawVulkanShadowSurface then got a no-caps count of 0 and fell back to tri->numIndexes, drawing model indexes against the doubled shadow vertex buffer, where vertex i is 2i on the surface and 2i+1 at infinity. That produced random triangles half-extruded to infinity: the black shards in aerial views and long dark bars from buildings. Ledger 032's draw-count checks couldn't see it.
How it was found (Adreno):
r_shadows 0 removes the shards.
r_useExternalShadows 0 turns them into a starburst.
A one-frame debug print showed every shadow draw with no-caps count 0, no shadow verts, capBits 0 and dsFlags 0.
r_interactionCache 0 changes nothing, so Renderer: light-interaction geometry no longer rebuilt from scratch every frame (canyon 95 → 292 fps) #108 isn't involved.
Fix (src/renderer/tr_light.cpp; tr_turboshadow.cpp, tr_stencilshadow.cpp and Interaction.cpp aren't compiled in this build).
The volume: BuildShadowVolume ports id Tech 4's vertex-program turbo volume for each {surface, light}:
facing is computed from the light's local origin, using R_DeriveFacePlanes' plane;
triangles outside the light frustum are dropped, using the cull bits with LIGHT_CLIP_EPSILON;
it emits the silhouette quads, then both caps;
it sets numShadowIndexesNoCaps, NoFrontCaps and SHADOW_CAP_INFINITE;
non-opaque materials keep their caps (idInteraction's rule).
Silhouette edges: FindSilEdges builds them, because this engine's model loading builds none (numSilEdges is 0 everywhere). Vertexes are welded by position; each edge is wound as in its first triangle, with the reversed edge giving p2, and an open edge refers to the dangling face. Edges are cached per index array, with a checksum because in-memory models reuse addresses.
Caching: CreateShadowVolumeGeometry caches the volume with the interaction (Renderer: light-interaction geometry no longer rebuilt from scratch every frame (canyon 95 → 292 fps) #108's key and cacheability rules). It's rebuilt when the light origin, frustum, model matrix or geometry changes. Each frame it's copied into the transient interaction index buffer.
Depth-pass or depth-fail: ViewPotentiallyInsideShadow (Doom 3's R_PotentiallyInsideInfiniteShadow on the bounds grown by twice the near plane) sets DSF_VIEW_INSIDE_SHADOW, which picks depth-fail with caps; otherwise it's depth-pass without caps.
Suppression: suppressShadowInViewID and suppressShadowInLightID are honoured.
Backend: DrawVulkanShadowSurface no longer falls back to the model's indexes, and the unused VulkanCreateShadowCache is removed.
Ray tracing: unchanged. R_AddLightSurfaces returns before any of this when RT is initialised.
Checks on win-arm64 (Adreno, raster):
Self-consistency: forcing depth-fail everywhere (r_useExternalShadows 0) gives the same frames as the default on valley and canyon (mean diff ≤ 0.15). On outskirts the remaining difference is the lightning storm's brightness.
Cost: none, and faster on valley. Uncapped fps over 30 s windows, two rounds:
valley GDF spawn: main 156.9 / 156.9, this PR 188.7 / 188.0;
canyon Strogg spawn (Renderer: light-interaction geometry no longer rebuilt from scratch every frame (canyon 95 → 292 fps) #108's viewpoint): main 170.2 / 216.1 (noisy), this PR 212.8 / 209.8.
Tests: vulkan-shadows, campaign-client-maps (asserts shadow draws), client-network-join and frame-poses-devmap pass. The full suite is running.
Screenshot set (main 2fbadab vs this PR, --rt 0, same anchors): images in the screenshots-pr<this> release; verdict in a comment.
Known limit (follow-up #128): casters still come from the view's visible surfaces, as before, so an off-screen building casts no shadow into view.
Ledger 074; STATUS updated.

With GPU skinning, Model.cpp copies the source surface (*geometry = *sourceSurface.geometry), so verts holds the unposed mesh, and the GPU poses it in the lit pass (worldInteractionSkinnedPipeline).
