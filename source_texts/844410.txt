Problem / Current Workflow Limitation
Export times on high-core-count AMD workstations (Ryzen 9 + Radeon RX 6000 series) currently lag behind Adobe Premiere Pro. Because full GPU-accelerated export pipeline integration (decode -> wgpu compositor -> direct hardware encode without CPU readback) is not yet fully leveraged on AMD hardware, exporting H.264/HEVC timelines relies heavily on CPU round-trips.
Proposed Improvement
Zero-Copy GPU Render-to-Encode Pipeline: Keep composited frames in GPU memory (wgpu textures on VRAM) and feed them directly into the hardware encoder (AMD AMF / D3D12 Video Encode) without copying raw frames back to system RAM.
Parallel Decode-Composite-Encode Queues: Overlap frame decoding (next batch), GPU compositing (current frame), and bitstream encoding (previous frame) across separate worker threads so neither the CPU nor GPU stalls waiting for the other during export.
Hardware Context
OS: Windows 11 Pro x64
CPU: AMD Ryzen 9 5900X (12-Core)
GPU: AMD Radeon RX 6800 (16 GB VRAM)
RAM: 64 GB

@ebunyt-dotcom Yes, that is the exact same issue!
The 8–15% GPU usage you are seeing is just the wgpu compositor rendering the frames, while the actual video encoding falls back to the CPU (pushing your 5600X to 99%) instead of using the RX 6600 XT's hardware encoder (AMD AMF/VCN) directly. Hopefully, once full AMD hardware encoding and zero-copy GPU export are wired up on Windows, our GPU usage will go up and export times will drop significantly.
