Context
The raytrace output is HDR linear (RGBId float pixels). When saved directly to LDR formats (PNG, etc.), bright areas clip, losing detail. image::generate_each() already has a tone_mapping parameter that applies Reinhard global tone mapping, but it's not exposed in scene::render() and there's no user control over the algorithm.
Current state
In scene::render() (line 584-617 of scene.cpp):
```
view.capture.generate_each(tracer, ..., tone_mapper);
```
The tone_mapper parameter is a bool passed through from the demo. generate_each() applies a hard-coded Reinhard operator when tone_mapping == true. There's no choice of tone mapper, no parameters (key, burn, saturation), and no way to apply it as a post-process on a saved image.
Proposed enhancement
Add a ToneMapper config class or enum:
```
enum class ToneMapOp { None, Reinhard, ACES, Unreal, Filmic };
```
Add tone mapping parameters (exposure key, white point, etc.) to scene::render() or as camera/image settings
Add a post-process method to save a tone-mapped copy:
```
void image::save_tonemapped(std::string const& filename, ToneMapOp op, precision key = 0.18_p);
```
Consider using the reference algorithms from https://64.github.io/tonemapping/:
Reinhard: simple, one-parameter
ACES: filmic, industry standard
Unreal: game-oriented, good for high contrast
Filmic: ALU-based, fast
