What
3D textures in the 64 KiB Z and S XOR swizzles threw ("3D textures are only supported linear or in SW_4KB_S / SW_64KB_S"). AMD addrlib's GFX10 rule (HwlIsThick) is that 3D S and D swizzles are thick while Z and R are thin. This follows it for the two modes added here:
SW_64KB_Z_X (thin): each depth slice is laid out like an array slice and addressed with the 2D Z_X equation (slice bits XORed in). It joins DescribeSurface's existing thin 3D path, which already held R_X and D_X. addrlib's 3D Z_X equation is identical to the 2D one.
SW_64KB_S_X (thick): it takes the standard 64 KiB thick block and mip-tail placement, which addrlib computes independently of the swizzle. The detiler gets a new thick equation keyed 0x119 (0x100 | SW_MODE), generated from addrlib for the same 16-pipe non-RB+ configuration as the existing tables.
How it was checked:
The generator reproduces the existing thick SW_4KB_S / SW_64KB_S tables (0x105/0x109) bit for bit.
agc_driver_graphics (tests/TextureTiling.cpp): four volumes (Z_X 32 and 64 bpp, S_X 8 and 128 bpp; 4 to 7 levels) must match addrlib's surface size, first tail level and addresses at corners and interior points of every level.
New execution test tests/execution/ImageXorSwizzleVolume.cpp fills a 40×24×20 RGBA8 volume in each mode and reads 32 texels back with image_load through the GPU detiler.
Not changed, flagged for review: the existing code lays out 3D SW_64KB_D_X as thin. Its comment ("only Z and standard ones are thick") matches GFX9's rule. With GFX10 addrlib, a 256×256×16 D_X volume is thick: texel (85, 255, 0) is at 0x3ad14c, not inside slice 0. Its 3D equation also differs from the 2D one. If the PS5 follows GFX10 here, as the rest of the tiling code assumes, 3D D_X textures are currently detiled incorrectly. I left it alone, since that path may have been checked against a title.
Tested
Linux, GCC 13.3, Release, -DBUILD_TESTING=ON, Vulkan on lavapipe (llvmpipe, LLVM 20.1).
Without the driver change, agc_driver_image_xor_swizzle_volume fails ("…not in XOR swizzle 25"). With it, the test and agc_driver_graphics pass.
Full ctest: 358/360 pass. The 2 failures, agc_driver_vopc_compare and agc_driver_vopc_compare_table, fail the same way on unmodified main under lavapipe.
Not tested with a title.
