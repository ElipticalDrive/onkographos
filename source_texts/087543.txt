Summary
Implements near-term raymarch quality priorities for the WebGPU volume renderer:
REQ-R04 quality tier control (Low/Medium/High) with anisotropic-spacing-aware step-size correction
Per-preset color LUTs (previously one shared grayscale ramp across all 4 presets)
Gradient-based Lambert shading with an on/off toggle
Pre-integrated 256x256 transfer-function LUT to reduce thin-structure loss at low step counts
Jittered sampling + temporal accumulation (capped running average) to reduce banding while the camera is static, via a new offscreen accumulation buffer and composite blit pass
See engine/docs/RENDERING_SPEC.md (added in this PR) for the full current rendering spec, kept up to date going forward.

Review notes
Two real bugs were found and fixed while wiring the accumulation buffer up (both caught by existing e2e tests regressing, not by inspection):
The raymarch pipeline switched to rendering into the new accumulation buffer (RGBA16Float) but was still built against the swapchain's color-target format (BGRA8Unorm), silently invalidating every draw using it. Fixed by having createRenderPipelineFor take the target format as a parameter.
The accumulation frame counter grew unbounded, so the blend weight decayed toward zero over time -- new content (e.g. a mask slice arriving after the screen had already been static for a while) stopped visibly affecting the image. Fixed with a 31-frame cap plus markAccumulationDirty() calls in loadVolume/applyMaskSlice.
Deliberately out of scope for this PR: full brick-atlas/LRU streaming, path tracing, full self-shadow ray-marching, and a full 2D transfer function (Kniss-style, gradient magnitude as a second LUT axis -- conflicts with the pre-integrated LUT's own use of the second axis). A follow-up branch (clipping box, directional occlusion shading, gradient-magnitude opacity modulation, TF detail controls) is planned to build on top of this one.
No .clang-format config exists in this repo yet, so new C++ was hand-matched to the surrounding file's existing style rather than auto-formatted.
Testing
Native build (cmake --preset windows-default && cmake --build build) passes.
WASM build (scripts/emsdk-shell.ps1 "cmake --preset wasm-windows" + "cmake --build build_wasm") passes.
Full viewer e2e suite (npx playwright test) passes: 10/10 (7 pre-existing + 3 new in viewer/tests/e2e/rendering-quality-controls.spec.ts covering the new quality-tier, shading, and colormap-preset controls).
Manually verified in a real Chrome session via the dev server (loaded a DICOM file, exercised the new Quality/Shading controls).
