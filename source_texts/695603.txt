Scalable Hole-Filling for Real-Time Multi-GPU
Light Field Path Tracing
Erwan Leria , Markku Mäkitalo , Pekka Jääskeläinen , and Mårten Sjöström , Senior Member, IEEE
Abstract—Light field (LF) displays address the mismatch in
focus cues present in traditional displays by triggering natural
defocus blur and enabling motion parallax. They rely on geometrical optics, displaying rays from multiple angles of view. LF
path tracing is computationally expensive for real-time applications, since it requires rendering multiple views. To reduce this
computational complexity, spatially reprojecting pixels between
views is commonly performed. Reusing pixels that are already
rendered is cheaper than path tracing additional ones. However,
when occluded areas are uncovered in some views, reprojection
is not possible, creating holes in these views. Filling-in the holes
requires extra path tracing computation. This paper investigates
scalable hole-filling strategies for LF path tracing, using multiple
GPUs to reach real-time performance. We propose an algorithm
search optimization procedure to determine whether a specific
assignment algorithm can be generalized across scenes, using the
hole-filling time as a minimization function. In addition, we introduce DaSH (Discarded and Subsampled path traced Hole-filling),
a novel method that reduces computation and divergence overhead
in fixed-size hardware thread-blocks. Based on local pixel sparsity
within pixel patches, DaSH adaptively subsamples and discards
hole-filling rays. Our evaluation demonstrates that DaSH achieves
significant performance gains while preserving the visual and structural quality of refocused light field images at the retina plane. The
experiments demonstrate an average speedup factor of 1.8× for
DaSH, compared to prior work, in a multi-GPU rendering system.
Index Terms—GPU, Ray tracing, parallel architectures, multithreading, partitioning algorithms, performance optimization,
computer graphics, multiview, displays.

Using multiple GPUs to perform path traced hole-filling
drastically reduces the computation time. In order to achieve
that, the views must be assigned to the GPUs, as shown in Fig. 1.
An assignment describes the mapping of data or computational
tasks to hardware resources (e.g., GPU). For disambiguation,
later in the paper, the term partition refers to a set of views that
are assigned to the same GPU.
For any number of GPUs, such assignment problems are not
trivial to generalize because they have a combinatorial complexity. Any assignment solution does not guarantee minimized
path traced hole-filling time. For instance, Fig. 1 does not show
an optimized solution. The best assignment solution would
maximize the number of solid arrows and minimize the number
of dashed lines.
As found in this article, assigning views with weak or no
assumptions on spatial coherence in view-space represents a
computational performance loss, when filling in the holes with
path tracing. By considering the geometrical structure of the LF
as an input parameter, we demonstrate that performance gain can
be generalized beyond any scene geometry in real-time multiGPU LF path tracing.
First, we define a performance model that describes the execution time of path traced hole-filling in a multi-GPU rendering system, given a LF and an assignment algorithm as input
(Section IV). Subsequently, we present an algorithm search
optimization procedure for minimizing the hole-filling time
(Section V). For lowering path traced hole-filling computation and overhead caused by divergent execution in GPUs, we
introduce Discarded and Subsampled path traced Hole-filling
(DaSH) (Section VI). It adaptively discards and subsamples
hole-filling rays in fixed-size GPU hardware thread-blocks,
based on local pixel sparsity. DaSH aims at preserving the quality
of images at the retina plane, while reducing computation. In
Section VII, we present the outcome of the algorithm search
optimization on two different sets of scenes. Then, we show outperforming scaling results against prior work, in a homogeneous
multi-GPU system for DaSH, coupled with different assignment
algorithms. Finally, we conduct an image quality evaluation,
confirming that rendering LF-based retinal images with DaSH
yields visually comparable quality against prior work, while
providing a significant performance gain.
II. RELATED WORKS
View synthesis consists of rendering a view or a set of views
from one (or many) source view (i.e., input image). Many works
have explored the use of rasterization and ray tracing techniques
coupled with reprojection and warping for synthesizing views
for real-time stereo and LF rendering [7], [8], [9], [10], [11]. Despite their potential, these methods have not gained widespread
adoption in the research community.
6465
Instead, the majority of the recent works on view synthesis
are frameworks that rely on image-based rendering techniques
combined with machine/deep learning methods. View synthesis
frameworks, based on image input for inference, are limited to
the features embedded in the specific datasets they are trained
on [12], [13], [14], [15]. Differentiable scene representation
frameworks [16], [17] allow having a continuous space for
synthesizing novel views. They build per-scene compact representations of radiance based on training images that are specific to a single scene. However, static illumination captured
in the training images and per-scene training constrain the use
of such frameworks to static scenes; otherwise, constant retraining becomes necessary. In practice, image-based view synthesis frameworks are generally not suited for applications such
as video games or visual effects. On the other hand, path tracing is convenient for reproducing dynamic global illumination
effects with moving objects and camera motion in real time.
Accelerating multiview rendering has been extensively studied for the single-GPU case. Fink et al. [18] propose an approach
based on tailored projection mappings for LF displays. They
rasterize LFs based on an adaptive image-space refinement of
the views, which maps the interlaced pixel arrangement of the
LF display. Gavane et al. [19] accelerate multiview rendering
for LF displays by improving traditional multiview rasterization
with a point-based approach, where points sampled from a 3D
mesh are mapped to elemental images for LF displays.
These methods are not suitable for multi-GPU path tracing,
since the path tracing workload depends on the number of rays
rather than on the number of visible primitives. Leimkühler
et al. [20] propose an optimal traversal of the views within a view
sampling space to minimize warp time within a single partition.
This method considers a continuous flow of pixels (e.g., densely
sampled) where at most 1 pixel difference between successively
sampled views is assumed. In this article, we do not assume any
pixel continuity in the domain of the sampled views. Moreover,
Leimkühler et al. propose an optimal traversal based on scene
information, which we aim to avoid in order to find assignment
solutions independently from the scene.
A few recent works focus on LF path tracing on multiple
GPUs. Liu et al. [21] present a dual-GPU pipeline for LF path
tracing. They use a split frame approach to balance the workload between the GPUs. They do not use spatial reprojection
techniques between views. Therefore, they do not address the
partitioning of the image-space domain to multiple GPUs, since
their pipeline does not use spatial reprojection (e.g., dependencies between views). Leria et al. [22] path trace a LF using
reprojection on a multi-GPU node. They distribute the views
in a round-robin fashion to the GPUs. Although they manage
to reduce the G-buffer rasterization time with a coarse-grained
distribution of the views, their pipeline suffers from additional
hole-filling time caused by holes in the images, causing diverging hardware thread execution paths. Weinrauch et al. [23] address the problem of heavy computation in real-time multiview
volume rendering using multiple GPUs. They assign views to
areas called view cells, which are formed based on distances between views. For each view cell, view-independent information
is cached in order to be reused between views looking in a similar
direction.

III. OVERVIEW OF THE MULTI-GPU PIPELINE
This section provides an overview of the multi-GPU rendering
system. Fig. 2 illustrates the logic between the assignment
algorithm and the renderer. We design the execution interface of
the assignment algorithm as a framework that converts the LF
grid ||s|| × ||t|| into the input layout of the selected assignment
algorithm and then runs the algorithm. When N partitions
are created, the central view within a partition becomes the
source view of that partition. The central view is the view that
minimizes the distance to all the other views within the same
partition [7], [22], [24]. The execution interface computes the
chosen assignment algorithm a(||s||, ||t||, N ) which outputs the
resulting partitions. For each partition, it returns the indices
of the source and the targets, which are later fetched by the
renderer. The assignment algorithm is static because it is not
refined at each time frame since the input parameters do not
vary during a run. The static assignment is computed on the
CPU at initialization. Then the path tracer fetches the partitions
to schedule computation on the GPUs.
The scheduling of the rendering stages is depicted in Fig. 3.
At each stage, for each GPU, the indices of the source and target
views involved for read and write operations are obtained from
the associated partition.
The path tracing stage path traces the source view. The Gbuffers rasterization stage rasterizes scene information used in
spatial reprojection and denoising. Each feature of the G-buffers
(e.g., albedo, normals, world positions, materials) contains perpixel information for each view. The spatial reprojection stage
reprojects the pixels from the source to the targets. The holefilling stage path traces the holes. The post-processing stage
executes a real-time path tracing denoiser and tonemapping.
The assignment problem for multi-GPU LF hole-filling is an
instance of the Quadratic Semi-Assignment Problem (QSAP),
which is an NP-hard problem: no known polynomial-time algorithm guarantees an optimal solution for all QSAP instances. In
this article, the QSAP instance is characterized by a number of
GPUs lower than the number of views, a combinatorially large
solution space caused by the view-GPU assignment possibilities,
and a hole-filling time function to minimize. Finding an assignment algorithm that produces optimal view partitioning for
different numbers of GPUs, different distances between views,
different scenes and different LF configurations is not trivial.
To model the relation between any assignment algorithm
and the hole-filling time, we reformulate the QSAP problem
as follows: Considering M views and N GPUs, the objective is
to assign at least one view to a GPU, such that the hole-filling
time from one view to another is minimized.

Our algorithm search optimization is done in two phases. For
each phase, the results section provides a rank for each candidate
algorithm based on its hole-filling time performance. In the
experiments, we use a different set of scenes for each phase
(see Section VII-A).
Preliminary Evaluation Phase: We expect the hole-filling
time to be high when views within the same partition are far from
each other, and low when views are tightly partitioned. To verify
our hypothesis, first we set up scenes that have non-overlapping
depth ranges. Then, we increase the scale b of the LF which is the
uniform distance between adjacent views, which affects β. Thus,
if the scale increases, β increases, and so does the disparity. As
a consequence, the assignment algorithms that create scattered
partitions are expected to suffer from a lack of visual similarities,
yielding a higher hole-filling time.
Validation Phase: We want to validate that the trend observed in the previous phase can be generalized for any depth
range. In other words, we are interested in validating the sceneindependent correlation between the hole-filling time improvement and the partition compactness. Less performant assignment
algorithms are expected to lead to high hole-filling times when
b increases.
After all the results have been collected, an offline script performs the aggregation, from which the optimal solution is found.
The outcome of the algorithm search is shown in Section VII,
where we assess if the solution found in the Preliminary Evaluation Phase is consistent with the one found in the Validation
Phase.
A. Portfolio of Assignment Algorithms
We investigate the following assignment algorithms: Contiguous, Generalized Hilbert Space-Filling Curve – shortened into
Gilbert, Munkres (or Hungarian) algorithm, (Sampling-based)
Label Propagation, Direct k-Way Partitioning, and Spectral
Clustering. As these are all generic assignment algorithms, we
also outline how they can be adapted to address multi-GPU
LF rendering. For some algorithms (e.g., Contiguous, Gilbert,
Label propagation), we must calculate the number of views per
partition prior to assigning the views. We use a greedy approach
to calculate a balanced number of views between the partitions.
Initially, we consider all the partitions to have size 0. For M
iterations, the lowest partition size is incremented by one.
1) Round Robin, Contiguous and Gilbert: Round robin assigns views one by one to a different GPU, whereas the Contiguous algorithm assigns a chunk of views in row-major order,
typically of size M/N (i.e., equal shares). The Gilbert algorithm
is similar to the Contiguous assignment, but the views are
partitioned based on a space-filling curve that describes a specific
traversal order of the view indices such that they are contiguous
in the view plane. Fig. 4 shows a partitioning example of a LF
grid into 8 partitions, using Gilbert. For instance, a Hilbert-based
space-filling curve has been used in Equalizer [26] to render tiled
displays.
2) Munkres/Hungarian Algorithm: The Munkres (or Hungarian) algorithm [27], [28] is commonly used to solve the more
general Quadratic Assignment Problem (QAP). As a consequence, the input of the solver is based on a squared dissimilarity
matrix. However, in our case, we face the QSAP (i.e., rectangular
matrix). We adapt this algorithm to our research purpose by
including padding in the matrix. Values in the padded area
are discarded by being set to infinity. We design an iterative
assignment process, where at each iteration, the best available
view is assigned to a GPU and its distance is set to infinity.
The N initial views (i.e., one per GPU), are selected using
the Farthest First Traversal algorithm [29]. Each view is picked
as far as possible from the set of views already picked. Such an
initialization suffers only from the selection of the first view that
is randomly picked. During the algorithm, a greedy approach is
performed: once a view is picked into a partition, it may worsen
the choice of the other partitions. In the worst case, a view could
end up far away from the rest of its partition, thus becoming an
outlier.
3) Sampling-Based Label Propagation: We design a
sampling-based label-propagation algorithm [30] in order to
control the spread of the partitions based on a concentration
parameter. In short, this algorithm propagates a GPU index
in graph representation. It starts from an initial view until it
reaches a fixed number of unassigned views, for each partition.
We set the concentration parameter to be equal to b. When b is
close to 0, the partitions are scattered in the grid. Towards 1,
they become tightly compact.
We create a similarity matrix M × M , composed of weights
wi,j that represent the similarity between views i and j. The

4) K-Way Partitioning: This algorithm aims at finding k
partitions. It follows three stages: coarsening, partitioning, and
refinement. The coarsening stage consists of representing the
initial graph as multiple coarse graphs. A coarse graph is an
aggregation of adjacent nodes into a ”super” node. This eases
partitioning, since there are fewer possible partitions to evaluate
as the number of nodes drops. The partitioning stage is usually
implementation dependent, and it can be applied by using any
graph partitioning algorithm. After partitioning, the graph is
uncoarsened: a coarse node is split back into the inner nodes
it spans. The refinement stage finds better partitions by using
implementation-dependent refinement heuristics. The refinement can happen during the uncoarsening phase.
We apply the k-way partitioning on an initial grid graph.
The edges and the nodes are unweighted. We employ a k-way
partitioning implementation [31] that performs flow-based refinement in order to find the best cut in a flow graph. This
inherently weights the graph to transform it into a flow network.
The cut defines the border between partitions. The edges located
on the cut have their endpoints in different partitions. Finding
the best cut generally provides better solutions than a greedy
approach, which may get stuck in a local optimum, and it leads
to better balanced partitions.

We introduce Discarded and Subsampled path traced Holefilling (DaSH), aimed at lowering hole-filling computation.
Divergent shader execution paths and incoherent memory
accesses occur directly for primary rays, due to missing pixels.
This causes non-active threads (i.e., reprojected pixels) to stall
while active threads (i.e., missing pixels) are tracing rays [22].
Moreover, it is unnecessary to fill in all the missing pixels, since
the retina sees the whole as a single image.
DaSH operates locally in every subgroup of GPU threads.
When the ratio of missing pixels within a subgroup is below a
25% sparsity threshold, its computation is discarded, avoiding
divergence in a subgroup of threads. Otherwise, subsampled
path traced hole-filling is performed for the sparse subgroup.
Evaluating the amount of missing pixels in a subgroup is
computationally cheap. Performing local sparsity evaluations in
small pixel patches allows a fine-grained control of our adaptive
solution.
A. GPU Subgroup Execution Model
In GPUs, a shader code is launched following a Single Instruction Multiple Threads (SIMT) execution model: the execution
code is fetched for each fixed-sized hardware thread-block,
called subgroup in Vulkan terminology (also known as warp
or wavefront). The shader code running on a hardware thread
is called shader invocation. A subgroup completes its execution
once all active shader invocations are complete. A subgroup has
a fixed size, determined by the hardware vendor. Mapping a
subgroup to pixels is either decided by the hardware vendor, or
reprogrammed in shaders. For coherent memory accesses, mapping a subgroup to a contiguous region of pixels (e.g., patch, row,
strip) is usually the preferred solution. In our implementation,
subgroups are mapped to rectangular pixel patches within the
same view, as highlighted in Fig. 6. A pseudo-shader code of
DaSH is described in the supplemental material.

a low threshold, avoiding sacrificing much quality. To count
the number of missing pixels within a subgroup, we use the
GLSL ballot extension. A ballot is a shared memory object

E. Quantitative Image Quality Measurements
In the following, we perform quantitative image quality measurements of the rendered LFs. We provide an evaluation between assignment algorithms (using DaSH), and another evaluation between FHF and DaSH. We want to verify our assumption
that applying DaSH does not heavily degrade the quality.
The views are merged in the retina once they are displayed.
We reproduce this behavior by projecting them directly on the
retina plane using image refocusing. To achieve that, we use
the geometrical image formation model proposed by Gudelek
et al. [50]. Since this model is designed for Near-eye LF configurations, we evaluate only the quality of Near-eye LFs. LFs are
rendered with our DaSH pipeline, and then fed into the optical
model, contained in a Python script. For compactness, results
are presented for the left eye only (i.e., 36 views), although
images are rendered from runs that render both eyes (i.e., 72
views).
Initially, in the renderer, the views are looking in parallel
directions, which corresponds to looking far at the horizon (i.e.,

infinity). Therefore, in the optical model, near objects appear
blurred in the retina because they are not in the accommodation
(i.e., focus) plane, located at infinity. In this case, far objects
or the environment map (if visible) appear sharp. The vergence
plane of the views (i.e., parameterized in the renderer), and the
accommodation plane (i.e., parameterized in the optical model)
are computationally independent depth parameters. However,
when both values are equal, the virtual objects located at the
matching depth appear sharp in the retina. This phenomenon
reproduces the vergence-accommodation of the human visual
system. To see sharp objects in refocused retinal images we
arbitrarily set a vergence plane per scene. This way, the quality
metrics are not measuring only blurry pixels.

G. Discussion
We have shown multiple input formats for representing a light
field grid. Our algorithm search optimization demonstrates that
the optimal solution is tailored for real-time LF path tracing. The
results suggest that k-way is the most reliable algorithm in terms
of performance and quality in different light field configurations.
DaSH provides a significant computational reduction in exchange for a minor quality degradation. The threshold in DaSH
affects mostly the rendering time rather than the quality for a
low b. The PSNR values exhibit the largest difference between
FHF and DaSH, ∼ 4 dB. However, PSNR has a poor correlation
with visual perception. Utilizing multiple metrics provides a
more comprehensive understanding of the quality degradation
of DaSH. Overall, the proposed solution remains competitive
because it preserves most of the visual and structural information for refocused retinal images while providing an average 1.8× hole-filling speedup and better scalability than prior
work.
An imbalance between partitions can occur due to dynamic
time-varying information within a scene. Leria et al. [51] propose a load balancing method for multiview path tracing. They
show that heterogeneous hardware capabilities have more impact on imbalance than time-varying scene information. Temporal inputs updated at each time frame could be further investigated for using assignment algorithms for load balancing.
VIII. CONCLUSION
We demonstrated that the hole-filling time is affected by the
assignment of the views. This shows that path traced hole-filling
time is sensitive to the distance between views rather than the
depth range of the scene. Thus, as the hole-filling workload
increases (e.g., more rays per pixel, order of magnitude of the
scale, higher distance β between views within the same partition), tightly partitioning the views becomes the key parameter
to reduce the computation, which can be achieved with spatial
awareness during the assignment of the views.
DaSH is effective at reducing the path traced hole-filling time.
It demonstrates that trading less computation against subgroup
divergence outperforms the prior work in terms of rendering
time, albeit the perceptible image quality can be slightly lower.
