Fixes #3629
GLGridAxisItem.view_angle() read azimuth and elevation from cameraParams(). In quaternion mode those keys are not there (only rotation), so every paint raised KeyError: 'azimuth'.
In quaternion mode the angles are now derived from the camera position, taken from the inverted view matrix like GLVolumeItem does since #3262. The euler path is unchanged.
I did not use GLViewWidget.cameraPosition() here. In quaternion mode it does not match the view matrix. For example, after setCameraPosition(elevation=30, azimuth=45) the view matrix puts the camera at (6.12, 6.12, 5), but cameraPosition() returns (0, -8.66, -5). That is probably worth its own issue, so I left it alone in this PR.
Tests:
New tests/opengl/items/test_GLGridAxisItem.py checks that view_angle() gives the same angles for euler and quaternion views after the same setCameraPosition(elevation=..., azimuth=...). It fails on master with the KeyError and passes with the fix.
Ran the GLGridAxisItem.py example with GLViewWidget(rotationMethod="quaternion"): before the fix, paint logs the KeyError; after, it draws without errors.
pytest tests/opengl and pytest pyqtgraph/examples -k GL pass locally (Windows, PyQt6, Python 3.12).

Would it make sense to rely on #3649 and make GLGridAxisItem agnostic to the rotation method?
Something like:
```
camera_params = view.cameraParams()
camera_pos = view.cameraPosition()
rel = camera_pos - camera_params['center']
azimuth = np.degrees(np.arctan2(rel.y(), rel.x()))
elevation = np.degrees(np.arctan2(rel.z(), np.hypot(rel.x(), rel.y())))
```
