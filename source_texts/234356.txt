Summary
Two new gaussian-splatting subprojects complementing splatvid (which creates splats from video):
splatkit/ — a Python toolkit for working with existing 3DGS scenes (pure NumPy + stdlib)
splatrs/ — the same toolkit rewritten from scratch in Rust, refactored for speed and targeting Apple Silicon (M4), with byte-compatible file formats
splatkit (Python)
I/O (io.py) — standard 3DGS .ply (lossless f_rest_* SH round-tripping) and antimatter15 32-byte .splat; format dispatch by extension.
Editing ops (ops.py) — covariance-correct similarity transforms, merge, box/sphere crop, opacity/scale pruning, voxel-hash radius outlier removal.
Compression (compress.py) — .skz: 16-bit positions/log-scales, smallest-three 10-bit quaternions, 8-bit color/opacity, zlib; typically 3–6× smaller than .ply.
Renderer (render.py) — CPU EWA splatter (perspective-Jacobian covariance projection, back-to-front compositing), stdlib-only PNG encoder.
CLI — info | convert | merge | transform | crop | prune | render | turntable.
splatrs (Rust, speed-focused, M4-tuned)
Same commands and formats, fundamentally faster architecture:
Tile-based rasterizer — 16×16 tiles, one global parallel depth sort, front-to-back compositing with per-pixel and per-tile early termination (the Python version paints every splat back-to-front).
Apple Silicon targeting — .cargo/config.toml pins -C target-cpu=apple-m4 for aarch64-apple-darwin; the compositing kernel has a NEON fast path (std::arch::aarch64, the only unsafe in the crate) processing 4-pixel groups entirely in registers (quadratic form, vectorized exp, masked alpha, blend, transmittance), with a lane-identical portable fallback; thin LTO + single codegen unit.
Rayon parallelism across projection, tile compositing, and editing ops; structure-of-arrays scene layout.
CLI parity plus bench — built-in benchmark reporting ms/frame, splats/s, and .skz encode/decode MB/s.
Input hardening — checked size arithmetic in parsers (hostile counts can't wrap size checks) and two-phase bounded zlib decompression capped at the header-implied size (defuses decompression bombs).
Cross-language compatibility (verified both directions)
tests/fixtures/ contains files written by Python splatkit; Rust tests verify every field against the exact-float .ply ground truth within each format's quantization bounds.
Files written by Rust load back in Python within the same bounds; .splat records and decompressed .skz payloads are byte-identical (numpy truncation/half-to-even rounding semantics matched deliberately, ulp-exact SH_C0).
Both renderers on the same scene agree to a mean pixel difference of 1.5e-4 (max one 8-bit step).
Testing & performance
Python: 35 tests passing (uv run pytest).
Rust: 82 tests passing (cargo test), clippy clean, NEON path compile-checked via cargo check --target aarch64-apple-darwin.
Measured on the 4-core x86 dev container (scalar path, no NEON): 140.7 ms/frame at 100k gaussians / 1024²; a 20k-gaussian 512² render is ~19× faster end-to-end than the Python implementation on the same scene (57 ms for the whole process vs 1107 ms for Python's render call alone). The M4's NEON kernel and core count widen the gap further.
Also lists both projects in the root README.
