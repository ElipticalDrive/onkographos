Rendering voxels with geometry shaders
Hello!
I've been sticking to opengl2.1 for a while now, but I'm now looking to more modern versions for more power & hopefully more performance.
I've been looking at geometry shaders, it looks like you can use a geometry shader to generate an arbitrary number of primitives from 1 input primitive, is that correct??
If I was to create a voxel renderer, could I pass each voxel as a point, then expand that to a full cube in the GS? Would you expect that to be better or worse than manually greedy meshing surfaces together? I'd imagine you'd get much faster mesh updates this way, no? I assume the downside would be that you'd be unable to texture one side of a cube differently to another.
If i choose this route, i won't have greedy mesh generation, instead I'll be rendering ALL cubes all the time. If that's the case, is there some stage in the pipeline where I could discard a whole primitive? is there a clever check to only end up rendering the surface cubes, and discard any voxels below the surface before they even got through to later pipeline stages?
