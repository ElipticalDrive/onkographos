apply_affine checks its input against the wrong shape, so it rejects any scalar-indexed array, even with a valid (4, 4) affine. A world-space affine acts on z/y/x, so it is always (4, 4), however many voxel dims the data has.
```
"""`apply_affine` rejects scalar-indexed VoxelData; the same slice as `[0]` works."""

import numpy as np

from confusius.xarray import create_voxeldata

data = create_voxeldata(
    np.zeros((2, 3, 4)), dims=("k", "j", "i"), spacing=(1, 1, 1), origin=(0, 0, 0)
)
shift = np.eye(4)
shift[0, 3] = 10.0

print("isel(k=[0]) z:", data.isel(k=[0]).fusi.affine.apply(shift).z.values.flat[0])
try:
    data.isel(k=0).fusi.affine.apply(shift)
except ValueError as error:
    print("isel(k=0) ValueError:", error)
```
```
isel(k=0) ValueError: voxel-to-world data requires an affine with shape matching voxel_to_world ((4, 3)), got (4, 4).
```
it asks for a (4, 3) affine, but passing one fails with LinAlgError from np.linalg.inv (:266). No input can succeed on this array.
The Proposed fix would use ensure_voxeldata, so apply would return (k, j, i) for (j, i) input.

Indeed, that's a tricky one. That's due to the fact that get_voxel_to_world_affine(da) has shape (4, dim + 1) where dim is the number of spatial dimensions of da. The true (4, 4) voxel-to-world affine is still stored in the VoxelToWorldIndex, but here we return the reduced one because that's the one you'd use to compute coordinates with.
So indeed, we just forgot to ensure_voxeldata inside apply_affine! We can also replace the has_voxel_to_world_index check by ensure_voxeldata directly.
