Abstract
Signed distance fields (SDFs) have emerged as an alternative shape representation for real-time collision detection and lighting effects. Computing these for complex models can be expensive, so one popular approach is to prepare an approximation via sampling and interpolation. Then, these may be rendered using sphere marching, which gets close to the surface quickly, but needs several iterations to converge to it. In this paper, we propose an alternative that computes the intersection of a given ray and the surface analytically at a narrow band. This may be combined with other enhancements like having variable error for the approximation depending on the distance to the surface and skipping regions that do not contain the surface to accelerate the outer band ray traversal while reducing the required memory. To achieve smoother representations with minimal computational cost, we propose a method for computing surface intersections and normals from separate interpolants. We evaluate all these to find the optimal combination improving the rendering performance and memory consumption of these SDF approximations.

1. Introduction
Signed Distance Fields have gained popularity as a helpful shape representation in several fields because of their properties and versatility. From them, distances, gradients and interior/exterior classification at arbitrary points in space can be computed efficiently. This is very useful to compute collisions in physics simulations [1], perform reconstruction with different goals [2], [3], approximate lighting effects in real-time [4], [5], and represent volumetric shapes for 3D printing [6].
However, the combination of the complexity of some models with the number of queries needed for many of these algorithms, makes SDFs computationally expensive for real-time tasks. Therefore, efficient algorithms and data structures to compute distances are key. One option is to use neural networks to capture the distance field [7]. Another is to store a sampling of the field or a set of much simpler functions that capture the SDF [8]. Rendering may then be the main goal of these representations, but even if it is not, being able to efficiently visualize them is useful to debug any problems these approximated representations may present. Also, the same ray/surface intersection test needed for rendering is useful in several other use cases of SDFs.
The main approach to render implicit functions and signed distance fields is sphere marching. In the case of SDFs, querying the field returns a distance that we may travel along the ray without intersecting the represented surface. Even though it gets close to the surface in very few steps (in many cases only one), depending on the relative orientations of the ray and the surface it may take several iterations to converge to a solution.
In this paper, we introduce a set of techniques aimed at improving the performance of real-time rendering of SDF approximations. We focus on reducing the number of iterations required by sphere marching in the surface narrow band, and the structure memory required in the outer band. Also, we concentrate on reducing the visual artifacts generated when using the trilinear interpolants in the surface gradient. The main contributions presented in this paper are:
•
An analytical method to compute the intersection between a ray and the SDF approximation in the narrow band.
•
A variable target error and an empty nodes strategy for the SDF approximation structure for improving the outer band ray traversal efficiency and the structure memory requirements.
•
A method for computing surface intersections and normals from separate interpolants.
•
A comparison of the rendering time and required memory between all the variants proposed and their basic implementations to find the optimal combination to accelerate rendering.
2. Previous work
Signed distance fields are useful in many computer graphics and geometry processing applications. These fields are usually represented as functions themselves. Takikawa et al. [9] presented a database of SDFs provided as analytic expressions. These are represented by using GLSL shader code. Frisken et al. [10] introduced an overview of the distance field techniques used in digital design. They highlight the simplicity of combining preexisting shapes, the ability to obtain any offset surface, and adding high-resolution detail via a brush-based carving functionality. Li et al. [6] presented the advantages of using implicit representations in additive manufacturing. They mention the advantages of implicit functions for defining an object’s internal micro-structure and the ability to design complex objects using a set of simple shapes.
Although these functions are very compact regarding the model complexity, they can be costly to evaluate if they are not correctly optimized. Therefore, in some cases, these functions are stored as accelerating structures that approximate the field in a given region. Frisken et al. [11] introduced an adaptive discretization of the field using an octree, in which each node leaf of the octree stores a trilinear interpolation. Wu et al. [12] proposed a method that only uses linear polynomials. Instead of an adaptative grid, they discretize the space using a BSP tree with no axis-aligned splitting planes. Pujol and Chica [8] presented an improvement of the method using trilinear and tricubic interpolation, which guarantees continuity between different octree depths. Koschier et al. [13] presented a similar algorithm that stores polynomials of different degrees dependent on the complexity required in that area. Also, these types of structures are used to retrieve objects given clues about the volume and some priors. Calakli et al. [14] proposed an algorithm for generating a signed distance field encoded in an adaptive grid from a point set with normals. They construct a linear system to reconstruct the signed distance field from the cloud, assuming the surface is smooth. Neuralangelo [15] is a method that from a set of object pictures is able to generate its signed distance field representation. They construct a neural SDF from the input images in an optimization process, trying to make the rendered SDF as similar as possible to the input pictures.
In order to render this final implicit function, there are two approaches. One way is to extract a triangle mesh, which will be easy to rasterize using current rendering pipelines. Another option is to render the function itself by using a ray tracing approach. We search the intersection between each ray and the implicit function isosurface (where the function is zero). These two strategies have their own advantages and disadvantages.
Mesh extraction.
Extracting a mesh that fits an implicit function without using many triangles is a difficult topic. In the literature, there are many proposals that try to improve mesh retrieval in different ways. One of the first proposals was Marching Cubes (MC) [16]; this method discretizes the space in a uniform grid, and then, for each cell, it generates the mesh with respect to the values of the function at the cell vertices. Dual Marching Cubes (DMC) [17], is an improvement of MC that generates smoother meshes by working in the dual of the grid used by MC. FlexiCubes [18] is a method similar to DMC that does a post-optimization step to improve the mesh quality regarding some objective function (e.g. the visual quality). Usually, these methods estimate the isosurface in each cell using only the field value at the corners. Sellán et al. [19] proposed a method for extracting from SDFs, in which they use the fact that the extracted surface must be tangent to the spheres induced by the distances measured at the samples. This improves the final mesh quality.
Ray tracing.
Extracting the mesh from an implicit function can produce the loss of features at some critical parts. Therefore, when we want better visual quality, it may be preferable to directly render the implicit function using ray tracing. In the case of implicit functions with a well-known Lipschitz constant, the most well-known method is Sphere Tracing [20]. It uses the value of the function and the Lipschitz constant to traverse the ray efficiently until an intersection is found. Later, Keinert et al. [21] and Bálint et al. [22] proposed some optimizations to the basic algorithm to reduce the number of iterations required. A global Lipschitz constant can be inefficient in some operations because different local areas have large constant differences. Galin et al. [23] presented a technique to compute the local Lipschitz constant in a ray for different types of primitives, operators and affine transformations.
In some implicit functions, its Lipschitz constant can be unknown or a very bad estimation of the real function behavior. There are other methods that do not depend on this constant. Mitchell [24], described a ray tracing approach based on interval arithmetics. They use interval arithmetic to find a monotonic interval containing a single root to later search for it with Newton’s method. As interval arithmetic trades precision for accuracy, it can significantly overestimate the real interval, slowing the intersection search. De Cusatis et al. [25] proposed a method similar to Mitchell’s but using Affine arithmetic. This arithmetic type works with affine combinations of uncertainty to estimate a range of values given an interval. This method is very similar to interval arithmetic but can give more precise intervals in most cases. Sharp et al. [26] proposed a ray tracing method for neural implicit fields by applying affine arithmetic to neural network architecture.
In cases where the field is encoded by low-degree polynomial patches, we can use some polynomial properties to find the ray intersection more efficiently. Söderlund et al. [27], introduced a method for searching intersections of trilinear interpolation based on the study of Parker et al. [28]. Working with a uniform grid of trilinear interpolations guarantees 𝐶0 continuity but does not have 𝐶1 continuity. Therefore, even though the model does not have holes, it does not have smooth normals, and the boundaries of the patches can be seen when it is rendered. They solve this problem by computing smooth normals using an approach similar to how they are computed in triangle meshes. Given the dual grid of the field discretization, they evaluate the normal at the grid vertices by computing the normal of the trilinear field at that point. Later, the field normal is estimated using a trilinear interpolation of these dual normals. Although this does not represent the correct normal of the field in some critical situations, in most cases, the approximated normal is good enough to hide the normal discontinuities of the field.
3. Background
This section introduces the basic components our technique is built on. First, we explain the structure used to compute our SDF representation and how it is computed. Then, we give more details about the solver we have tried to improve our polynomial ray intersection test.
3.1. Background techniques
Computing the signed distance of some primitives can be time consuming, for example, with triangle meshes. As we explained in the previous work, there are structures that precompute and store these Signed Distance Fields. Usually, these structures are more memory-intensive than using the primitives themselves, but are more efficient at query time. This paper uses the structure proposed in [8] implemented in the SdfLib library.
SdfLib stores the input field in an octree-like structure. Each leaf of the octree stores a polynomial approximation of the field. The library supports trilinear and tricubic polynomials. The user defines the maximum desired error. During the structure construction, only the nodes that do not fulfill this error are further subdivided. Fig. 1(a) shows a slice of the structure generated by the library using the Bunny model.
3.2. Sphere marching
Sphere Marching is a well-known technique for ray marching volumes or surfaces represented by implicit functions with a known Lipschitz constant 𝐾. Given an implicit function 𝑓:ℝ3→ℝ, a starting point 𝐱0 and a direction 𝐝, ray marching searches the intersection with the isosurface by moving forward an amount equivalent to the value function, 𝐱𝐭+𝟏=𝐱𝐭+𝐝⁢𝑓⁡(𝐱𝑡)/𝐾. In the case of SDFs, the Lipschitz constant is always one.

3.3. Bracketed Newton bisection
Bracketed Newton bisection is a root-finding algorithm named by Peters et al. [29] and first proposed by Yuksel [30]. This iterative method combines bisection and Newton’s methods with a preliminary step that splits the polynomial into monotonic pieces. Unlike other simple numerical solvers, this method is able to find all the possible real roots of high-degree polynomials.
Given a polynomial 𝑃:ℝ→ℝ of any degree 𝑛, the solver can find the values of 𝑥 where 𝑃⁡(𝑥)=0. For polynomials of high degree, we can find some of his roots using numerical methods, but we cannot know if we have lost some of the possible solutions. 𝑃 can have as many solutions as its degree, in this case 𝑛. Therefore, we need to split the polynomial into monotonic parts to ensure there is at most one solution within the interval. The endpoints of these intervals are the points where the gradient of 𝑃 has a change of sign. These points are a subset of the roots of the derivative of 𝑃, 𝑃(1), which will have degree 𝑛−1. Notice that each time we take the derivative, the resulting polynomial has one degree less. The algorithm starts at the (𝑛−2)th derivative of 𝑃, which has degree 2. The roots of this derivative, which can be found algebraically, are the interval endpoints of the derivative 𝑃(𝑛−3). Given the monotonic intervals of 𝑃(𝑖), this information is used to search the roots of the following derivative 𝑃(𝑖−1), which will provide the endpoints of the intervals of 𝑃(𝑖−2). This process is done iteratively until all the roots of the original polynomial, 𝑃(0), are found.
Given a monotonic interval [𝑥𝑚𝑖𝑛,𝑥𝑚𝑎𝑥] with a change of sign, we want to find its only root. This is done using a mixture of bisection and Newton’s method, which are numerical methods to find the roots given a value interval.
4. Method
This section describes our proposals to improve the ray intersections with a discretized Signed Distance Field. First, we describe some modifications that we have integrated into the SdfLib library, which is the library chosen to compute and store this SDF discretization. Then, we present our solution to find intersections when the ray traversal is near the surface.
4.1. SDF representation
As we explained before, we implemented and tested different strategies for doing ray casting in discretized SDFs. This proposal requires modifying the final octree of the SdfLib library. The two modifications that we have made are focused on improving the intersection search at iterations far from the surface.
Empty octree.
First, we implemented a new functionality to store the polynomial coefficients only at the octree leaves containing the field isosurface. Also, we do a node collapse postprocess to ensure that the empty nodes are as large as possible. With this new format, we are able to construct octrees with less memory requirements. During the ray traversal, instead of traveling through using sphere marching, we use a basic octree traversal algorithm to find if the ray intersects any leaf containing the isosurface. In Fig. 1(b) we can see the final octree using this new functionality. Notice that the nodes do not contain any part of the surface are larger than in the original octree (Fig. 1(a)). These nodes are filled in red because they do not contain any representation of the distance field.
In the octree construction, we decide if a node contains the isosurface by inspecting the polynomial coefficients. We use the convex property of Bézier polynomials to decide it. Given a Bézier polynomial of any degree, its corresponding coefficients are the curve’s control points. The convexity property says that all the values resulting from evaluating a Bézier patch inside the working interval are inside the convex hull of the control points. In our case, the trilinear and tricubic polynomials we use have equivalent representations as Bézier patches, where the control points are scalar values. Thus, we can conservatively check if the surface is within the node by testing if the range of these control values contains zero. In the case of trilinear interpolation, these control points correspond to the eight values of the node vertices, which are exactly the values used by SdfLib for computing the final coefficients. In the tricubic interpolation, the library computes the coefficients by using the field value and derivatives at the eight vertices. On the other hand, the corresponding Bézier polynomial has 64 control points. We transform the tricubic polynomial coefficients to the control points of the corresponding tricubic Bézier with a linear transformation. This linear transformation exists because the two functions correspond to the same order polynomial. Finally, we check if the range (convex hull) of the obtained control values contains the zero value or not. If it does not, we can be sure the zero iso-surface is not inside the node. Fig. 2 illustrates this test on a bicubic polynomial defined in 2D space.
Variable error.
SdfLib constructs the octree, ensuring that the error in each node is not bigger than a user-defined value, which we will call 𝜖. While this guarantees a uniform error bound across the entire space, it can lead to high memory consumption. However, when rasterizing the model using sphere marching, we are primarily interested in accurate representation at areas near the surface. Therefore, we add a new error term that depends on the distance value. We redefine the maximum allowed error as 𝜖+𝛿⁢|𝑓⁡(𝐱)|, where 𝑓 is the input distance function and 𝐱 is the current position, and 𝛿 is our new hyperparameter. In Sphere marching, we are interested in underestimating the real distance so that we do not skip any part of the isosurface. To ensure that the error is always an underestimation of the distance, we move forward using 𝑓⁡(𝐱)⁢(1−𝛿). This ensures that we will never overestimate the distance if the structure fulfills the requested error. Fig. 1(c) shows the final octree using this new approach with 𝛿=0.1. In the figure, you can see that the obtained octree has fewer nodes far from the surface.

4.2. Searching near intersections
In most cases, using Sphere Marching (introduced in Section 3.2) for rendering SDFs is a good option because it is simple and relatively fast compared to other techniques. The best-case scenario for the algorithm is when the ray approaches a concave or flat part of the object, and it is perpendicular to the intersecting surface. The worst situation is when the ray passes close to parallel surfaces without colliding with them. Fig. 3 shows this worst-case situation. Most situations where Sphere Marching needs many iterations to move forward occur at nodes containing the isosurface. Using the known polynomial representing the field behavior inside the node, we can use other types of solvers to improve the ray intersection search. The ray is defined by a start position 𝐩 and a direction 𝐯. We represent the polynomial of the current leaf as 𝑃𝑁:ℝ3→ℝ. Given the amount of ray traversed, which we call 𝑡, we can compute the current ray position as 𝐩+𝐯𝑡. Thus, we may find the intersection between the approximation of the surface at the node (𝑃𝑁) and the ray, if there is one, by solving 𝑃𝑁⁢(𝐩+𝐯𝑡)=0. This expression can be simplified into a polynomial on 𝑡. For the trilinear interpolation, we end up with a cubic polynomial equation (Eq. (1)), and for the tricubic, with a polynomial equation of degree 9 (Eq. (2)). These coefficients can be computed directly from the node coefficients. In the trilinear case, each node has 8 coefficients which require 7 multiplications to evaluate. For computing the intersection coefficients, we need 26 multiplications. In the case of tricubic, the original leaf polynomial has 64 coefficients which require 84 multiplications to evaluate. And computing the intersection coefficients requires 492 multiplications. Effectively, this means that evaluating the polynomial to power a sphere marching implementation is much cheaper than computing the intersection polynomials. Still, when close to the surface, performance is improved because the intersection polynomial has to be computed only once per ray and node, and this polynomial may be evaluated several times before exiting the node.

In the trilinear case, we have intersection polynomials with degree 3. There are analytical formulas to compute the roots like the Cardano formula, but we found this method very unstable in some situations. Therefore, we use the Bracketed Newton bisection method (explained in Section 3.3) to find the first intersection point. The polynomial can have at most three monotonic parts since its derivative can have, at most, two roots. If a monotonic part contains the root, then its interval bounds values have a change of sign. Notice that the algorithm can determine if a node does not intersect with the surface in constant time. And, if an intersection exists, it searches the root point using Newton’s bisection method in that monotonic part. Fig. 4 contains an example of the solver.

4.3. Smooth trilinear isosurface
The trilinear approximation is faster to compute than the tricubic because it has fewer coefficients. Although the trilinear guarantees shape continuity, it does not offer gradient continuity between nodes. Therefore, the rendered models encoded with this interpolant have visual discontinuities between patches corresponding to the node boundaries. To solve this, we use the gradient of the tricubic interpolation while we search the ray intersections using the trilinear interpolations. The needed tricubic coefficients are stored only at the nodes containing the isosurface. Fig. 5 compares this version and the one using the trilinear gradient directly.

5. Results
5.1. Method definition
In this section, we evaluate all the proposed methods. We compare combinations of strategies by distinguishing between the techniques for the nodes that do not contain the isosurface, the outer band, and the techniques for the nodes containing it, corresponding to the narrow band.
For the outer band, we test two strategies: Sphere Marching (SM) and Octree Traversal (OT). In SM, we do basic Sphere Marching ray traversal, searching the octree node containing the current point and computing the step length evaluating its corresponding polynomial. This strategy uses the implemented variable error extension to reduce the final octree memory size, using a 𝛿 of 0.02. The other strategy, OT, iterates the model outer band by doing an octree ray traversal. In each ray iteration, the algorithm moves forward to the next node by doing a node intersection search. In this strategy, we use the empty octree strategy because we do not need any information on the distance field in nodes that do not contain the isosurface.

In the case of the narrow band voxels, those that contain the isosurface, we test four strategies: None(N), Sphere Marching (SM), Bracketed Newton Bisection (BNB) and Early exit Sphere Marching (ESM). N does not use any narrow band solver. When the algorithm reaches a narrow band voxel, it immediately returns a hit. Therefore, the final render is a voxelization of the scene. SM is the basic Sphere Marching algorithm. In this case, we reuse the intersection polynomial coefficients until exiting the current node (in the case of no intersection) because the solver may need many iterations to exit. BNB is the numerical solver introduced previously. ESM is the usual Sphere Marching algorithm with the early exit condition based on Affine Arithmetics explained before. Moreover, the method uses the intersection polynomial coefficients, already calculated for the early exit test, to evaluate the field faster. This method is only tested with tricubic polynomials because the trilinear cannot take advantage of the technique.
During the method analysis, we defined the algorithm used in both situations by specifying the outer band strategy first and then the inner band strategy, separated by a dash. For example, SM-BNB uses Sphere Marching for voxels far from the surface and the Bracketed Newton Bisection method for the nodes containing the isosurface.

5.2. Method analysis
All the timings in the paper were obtained on an Intel(R) Core(TM) i7-12700 with 32 GB of RAM and a GeForce RTX 4080 with 16 GB. The renders were made using a screen resolution of 1920 × 1080. We test the different improvements proposed in the paper. First, we analyze the different render times obtained using all the combinations of outer and narrow band techniques using the trilinear and tricubic interpolation. We also examine in detail some of the combinations to get a more elaborate explanation of the times obtained. Finally, we analyze the memory required by the two octree alternatives we propose. All the octrees were generated using a precision of 0.7⁢𝑒−3 with respect to the model bounding box diagonal and a maximum depth of 9. For testing our method, we use five different scenes generated by a combination of mesh models and SDF primitives. Fig. 6 has an image of all the models. In all tables, times are calculated by taking an average render time at five different views. All the narrow-band methods require a stop threshold to decide when the solver is near enough the surface. We use the largest threshold that gives one pixel accuracy (using the screen resolution mentioned before). This threshold is linearly dependent on the distance in order to consider the perspective effect.
Table 1 contains the milliseconds taken by the different render methods using the trilinear interpolation. For the outer band columns, we have the two possible approaches without using any solver for the narrow band nodes. As we can see in the table, the Octree traversal is faster than the sphere marching in all models, but the difference depends on the model. The Sponza model has the largest time gap. This might happen because the model has big free-space areas, and almost all the geometry is aligned with the axes. Although the octree traversal method is faster, it requires more iterations. Fig. 7 shows the difference in iterations between both methods in the Temple model. As we can see, in most of the pixels the Octree traversal does more steps. The larger difference can be observed at the center of the image, with a higher density of objects around it. Notice the grid pattern that can be observed in the image produced because OT depends on the nodes’ location. Fig. 8 shows two histograms of the required iterations using the same view and model. As we can see, sphere marching has more pixels using a smaller number of iterations, while the octree traversal has a longer tail. Even though in average OT requires more steps, the method is faster because it uses the empty octree where nodes have a smaller average depth.
In the remaining columns of Table 1, we have the time the algorithm uses to search intersections at nodes containing the model’s surface. In this case, we consider them in combination with the two approaches for the outer band because they give different times. In the case of the Octree traversal, the solver always starts at the node’s border (at the nearest intersection between the node and the ray). On the other hand, sphere marching can start at any position on the ray inside the node. As we can see in the results, BNB is faster, giving an average speedup of 12% over basic sphere marching. Fig. 9 shows the solver behavior per pixel in the Temple model. In Fig. 9(a), we can see the iterations required by Sphere marching for leaving the node or intersecting the surface. Notice that a high number of iterations are needed for the silhouette of the object and the roof of the temple. The temple roof requires many steps because the surface is almost parallel to the camera view, so SM converges more slowly towards it. Fig. 9(b) shows the state in which the BNB solver finishes at each pixel. As can be seen, the method can skip nodes early on in the silhouette of the models. In most parts where there is an intersection with the object, only two iterations of the Newton bisection method are required to find the intersection point. Notice that the major advantage of the method is that at the silhouettes, the BNB method is faster because SM requires many iterations.

Table 2 shows the render times using the tricubic interpolation. It follows the same format as Table 1, explained previously. In this case, we have one more narrow band method called SM-ESM. In the columns comparing the outer band strategy, the gap difference between the sphere marching and the octree traversal has increased. This larger variance is produced because the leaf nodes contain tricubic interpolants, which require more operations to evaluate, and as expected the octree traversal results are the same as in the trilinear case (both have empty nodes). In the table, we also have the times required by the narrow-band strategies. We can clearly see that BNB is the slowest method. This decrease in performance compared to the trilinear case is produced because the method has to search the monotonic intervals of many derivatives. Looking at the other two alternatives, ESM is a 63% faster than the basic SM on average. This speedup comes from two factors, the proposed early skip test and the use of the intersection polynomial during the Sphere marching part (only used in ESM). Although evaluating the intersection polynomial coefficients requires a costly initial operation, the cost per step is reduced. This decrease in cost per iteration can be observed in the value difference between the approaches using SM or OT as outer band strategy. As we explained before, the octree traversal must always start at the node’s border, and the sphere marching strategy does not. Notice that in the trilinear case, this difference was tinier because the cost per step is less impactful.
Finally, we have a memory usage comparison between the different octree variations and different initial parameters. Fig. 10 has a plot comparing the memory and render times using different 𝛿 values. As we can see, the required memory decreases considerably at the start and then remains almost constant. On the other hand, the render times remain constant at the start, and at larger deltas, they start increasing. This increase in render times is produced because the algorithm does small steps when the 𝛿 increases, but the octree complexity is not reduced enough. Therefore, a smaller 𝛿 guarantees a good tradeoff between render time and memory usage. In Table 3, we can see the render times and memory consumption for the different models. Even though the empty octree, as we already saw before, has shorter render times and memory usage, the variable error method that can return distances at any point can be useful in many applications. We require the full field for doing soft-shadow estimations using sphere marching or combining the octree volume with other dynamic SDFs using all sorts of operators. In the tricubic case, the behavior is almost the same, but the memory and render times are larger. In addition, the last two columns of the table contain the results using the smooth trilinear isosurface proposal explained in Section 4.3. The extension stores the coefficients of the tricubic interpolant at the narrow band nodes to compute the smooth gradient. As we can see in the table, the render times are almost the same since the gradient evaluation is done only once per pixel. On the other hand, the octree occupies 7 times more memory because it has to store 64 coefficients more in each node containing the isosurface.

6. Conclusions
We have presented a set of techniques aimed at improving the performance of real-time rendering of signed distance field approximations using trilinear and tricubic interpolants. We present techniques for improving the ray traversal in the narrow band and outer band. In the narrow band, the proposed analytical intersection search with the trilinear interpolants is the fastest method for searching surface intersections. In order to improve the continuity of normals derived from trilinear interpolation, we extract them from the tricubic interpolant, which only introduces a small performance overhead. We also tried to perform rendering directly using the tricubic interpolants. In this case, the best solution is to use the ray polynomial equation with regular sphere marching and the Affine Arithmetics early exit.
We present two enhancements that reduce the structure memory consumption and outer band ray traversal. We have observed that the best solution is an empty tree approach. One of the downsides of this approach is that we are dropping the SDF polynomials from octree nodes that do not intersect the surface. This may be a problem when applying certain algorithms to SDF rendering (e.g. soft shadows, ambient occlusion). An option would be to use the variable error approach so that the SDF can be queried far from the surface, while still using the node skip and analytic intersections to raytrace the model. This will require to test these additional lighting techniques with the proposed enhancements.
Another avenue of improvement would be to try to use other acceleration structures, like BVHs or hierarchical grids, to store the polynomial approximations. In particular, Söderlund et al. [28] found out bounding volume hierarchies to provide the best performance. Finally, differentiable rendering approaches have been a very popular approach to reconstruct models from sets of input images. It would be interesting to apply our representation to these, with the main challenge being how to decide what level of detail to put on different parts of the represented space.
