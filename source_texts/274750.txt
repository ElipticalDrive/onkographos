Summary
load, list-series, seed-picker, sample-hu and process now accept a NIfTI file (.nii / .nii.gz) as well as a DICOM folder. NIfTI files inside a scanned folder are listed alongside DICOM series (UID nifti:<path>, modality NIfTI).
Implemented inside list_series / load_series (new load_nifti), so every existing caller works unchanged. The DICOM code path is untouched, and DICOM keeps the default on equal slice counts in mixed folders.
NIfTI volumes are reoriented to LPS on load (lossless axis flip/permute). sitk_to_vtk drops the direction matrix, so without this, flipped-axis NIfTI (e.g. dcm2niix output) produced mirrored meshes. Oblique volumes log a warning.
4-D files use the first volume; unreadable or 2-D files are skipped with a warning.
README and CHANGELOG (Unreleased) updated, including a note that voxel indices can differ from other viewers, so prefer --seed-mm or VORTEX's own seed picker.
Testing
Synthetic NIfTI with three axis layouts: meshes and seeds land at true world mm.
Real case (AA_009, 580-slice angio CT) converted with dcm2niix: the raw file has a flipped Y axis. After loading, size, origin and direction match the DICOM, and voxel values are identical. process (ROI 20 mm, centerlines) ran on both inputs: identical bounds, mean vertex distance 0.003 mm, max 0.33 mm (about one resampled voxel). The residual comes from dcm2niix storing float pixels (the resample doesn't round them) and the NIfTI header's float32 geometry precision.
Seed picker checked manually on a NIfTI from a second dataset.
