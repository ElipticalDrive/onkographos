Goal
Design and implement the geometric/material foundation for subtractive digital sculpture: begin with a solid marble block, remove material with sculpting tools, and derive a clean renderable surface from the remaining volume.
This is a volumetric material model, not a mesh that is repeatedly cut directly.
Core model
Represent the initial marble block as a bounded solid volume.
Do not allocate one object per microscopic cube. The conceptual billions/millions of tiny cubes must be represented compactly using sparse, chunked storage and/or a hierarchical adaptive spatial structure.
Tool size controls the effective removal resolution and brush footprint. Coarse tools remove larger regions; fine tools preserve and modify smaller detail.
Support subtractive operations first (scrape/chisel/grind); additive materials can be a later extension.
Keep material occupancy/density and sculpt-operation provenance separate from the derived surface mesh.
Surface derivation
Derive only the boundary between solid marble and empty space.
Avoid emitting every internal/shared voxel face and then trying to clean up the entire result.
Extract boundary surfaces using a documented algorithm (e.g. surface nets/dual contouring or marching cubes where appropriate).
Merge compatible adjacent coplanar faces/regions into larger polygons where safe, then triangulate with canonical CCW winding.
Preserve sharp edges and intentional detail; simplification must have an explicit error/tolerance budget and must not erase meaningful features.
Support incremental updates to dirty chunks/regions after a brush stroke rather than rebuilding the entire sculpture after every tool movement.
Correctness and performance
Deterministic edits for the same volume, tool parameters, and operation sequence.
Explicit coordinate system, physical units, voxel scale, and boundary behavior.
Tests for block initialization, coarse/fine removal, chunk boundaries, thin features, cavities, watertightness/manifold checks where supported, stable normals/winding, and repeated edits.
Benchmarks across volume size, active surface area, tool radius/resolution, and edit locality.
Track memory and mesh triangle counts; never equate conceptual voxel count with allocated object count.
Boundaries
Physics owns volume/geometry data structures, brush-to-volume operations, surface extraction primitives, and geometric validation.
GUI owns tool selection, brush sizing/preview, interaction, undo/redo presentation, and editor workflow.
Visualize/Renderer own presentation of the derived mesh; rendering must not perform volume mutation or per-frame mesh repair.
Keep work on development; no NuGet publishing, no promotion to master.
Initial milestone
Produce a small, testable vertical slice: initialize a marble block, apply one spherical subtractive brush at two different resolutions, extract its boundary mesh, and verify geometry/winding plus stable results. Document algorithm tradeoffs before committing to a long-term representation.
