Motivation
Replace per-chunk GPU job dispatch and full CPU readback/writeback with a batched resident-page simulation to reduce GPU roundtrips and enable correct cross-chunk fluid continuity.
Ensure deterministic simulation ordering and double-buffered page state so GPU-driven particle motion is consistent and stable across chunk boundaries.
Avoid full per-step CPU voxel loops and instead emit compact dirty metadata for remeshing/scheduling while keeping CPU ChunkStore authoritative only where gameplay needs it.
Description
Reworked the GPU-native stepping path in src/simulation/gpu_fluid.rs to operate on a set of resident pages instead of dispatching per-chunk jobs, and added resident_pages_current and resident_pages_next double buffers for simulation state.
Implemented halo/ghost exchange for all 6 neighbor faces (exchange_halos / fill_halo_face) so neighbor data is available when computing intents that cross chunk borders.
Introduced deterministic pass sequencing in the GPU path (advect/forces -> divergence -> pressure solve -> projection -> material update) with placeholders for the latter passes and a prioritized MoveIntent application to resident_pages_next.
Replaced full-material CPU writeback with flush_targeted_updates_to_cpu, which does targeted ChunkStore::set_voxel updates only for changed voxels and records compact dirty metadata (dirty chunk set, per-chunk dirty region, and global dirty bounds) via DirtySimulationMetadata.
Added two unit tests that assert cross-chunk continuity: liquid_crosses_two_chunk_boundary and liquid_settles_continuously_across_boundary (both in src/simulation/gpu_fluid.rs tests).
Testing
Ran cargo fmt to format changes (succeeded).
Ran cargo check / full build to verify type-checking (succeeded; crate builds in dev profile).
Attempted cargo test for the new boundary test; test execution failed to complete because of unrelated compile-time tuple-destructuring mismatches in src/renderer.rs (pre-existing errors surfaced when running the test build), so the new tests were added but could not be executed in isolation in this environment (failure is not due to the GPU flow changes themselves).
