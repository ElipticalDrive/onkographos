Thanks, everyone. The pattern here is kind of interesting, but definitely not pushing the boundaries in terms of aesthetic design.
However, traversals of curved patterns are not common at all. The purpose of the post was to show that traversals needn't be restricted to straight edge tessellations. This also indirectly demonstrates that it's possible to traverse packed circle patterns. I'll post an example along those lines later.
Shane, 2026-08-08
@pyBlob
The pattern here is built upon on a hexagon grid, so you could think of this as packed circles with the edges chipped off. You could apply this process to many tessellations. Some patterns would look a little mundane, like squares, but I'd imagine others would look pretty interesting.
The curves in this example are controlled by a constant curvature factor, "crvF". A value of 1.5 will turn the rounded triangles into circles. Very large values would give the appearance of straight edges, and so forth.

/*

    Curved Polygon Traversal
    ------------------------
    
    This is a traversal of polygons with curved sides. I put togehter a polar 
    grid traversal a while ago. The cells of the grid were bounded by curves 
    and straight lines. The cells here consist entirely of curved boundaries. 
    Don't quote me on this, but I think polygons consisting of rounded sides 
    with constant curvature are called Reuleaux polygons, so I guess you could 
    call this a 3,6,3,6 Reuleaux polygon tessellation raymarch traversal.
    
    I put this together as an academic exercise, and to show that traversals
    of curved polygons are possible. The internet is a big place, so there 
    might some other examples out there, but I couldn't find one.
    
    In order to traverse cells bounded by arcs, you need to raytrace curved
    lines. In this case, the curves are simple circle boundaries. I was having 
    accuracy problems right near the center of the ray, and I suspect the 
    problem lies with the 2D disc raytracing function I'm using. Shadertoy user 
    Cotterzz was helpful fixing a raytraced sphere function a while ago, so if 
    I'm lucky, he might take a look at the one I'm using here. Either way, I 
    was able to hack in a simple fix, so that it's not a problem here anyway.
    
    I had bigger plans for the presentation, but spent too long trying go fix
    accuracy issues, so left it in the form it's in now, which isn't necessary
    bad, but shiny metal is the look I go for when I couldn't be bothered 
    putting effort in. :)
    


    
    Related examples:
    
    // A raymarched traversal of polar grid cells.
    Polar Grid Raymarch Traversal -- Shane
    https://www.shadertoy.com/view/XXscRs
    
    // To my knowledge, Abje was the first to code up a polar grid
    // traversal on Shadertoy.
    polar wave -- abje
    https://www.shadertoy.com/view/wsSSWR
    
    // A nice simple example of a curved polygon tessellation.
    // Traversing this would depend on how efficiently you could
    // raytrace the boundaries.
    Sine Wave Tiling -- fizzer
    https://www.shadertoy.com/view/fdtXRn

// Max ray distance.
#define FAR 20.

// Height map value.
float hm(in vec2 p){  
    
    //return hash21(p + .13); 
    float d = dot(sin(p*.125 - cos(p.yx*.2875)), vec2(.25)) + .5;
    return mix(d, dot(sin(p*.25 - cos(p.yx*.575)), vec2(.25)) + .5, 1./3.);

}

/*
// IQ's extrusion formula.
float opExtrusion(in float sdf, in float pz, in float h){
    
    vec2 w = vec2( sdf, abs(pz) - h );
  	return min(max(w.x, w.y), 0.) + length(max(w, 0.));

}
*/

// IQ's extrusion formula.
float opExtrusion(in float sdf, in float pz, in float h, in float sf){
 
    // Slight rounding. A little nicer, but slower.
    vec2 w = vec2(sdf, abs(pz) - h) + sf;
  	return min(max(w.x, w.y), 0.) + length(max(w, 0.)) - sf;
     
}



vec3 gRd; // Global ray direction.
vec3 gDir; // Global step direction.
float gCD; // Global cell wall distance.

// Global values and object distances.
vec4 gVal;
vec4 vObj;

 

// The extruded image.
float map(vec3 p3){
    
    // Floor.
    float fl = p3.y;

      
    // The curved hexagon and triangle grid.
    vec4 p4 = distField(p3.xz);
    vec2 id = p4.yz;
    float d2 = p4.x;
    d2 += .003;
    
    vec2 p = gP;
    
    // Curved polygons, which means the boundaries are defined by circular
    // arcs, instead of lines. Therefore, we require the minimum ray 
    // circular boundary intersection.
    //
    // Ray circle intersection.
    
    gCD = 1e8;
    vec2 rdXZ = normalize(gRd.xz); // 2D XZ plane ray normal.
    
    // Minium circular side boundary. There are six for the hexagons
    // and three for the triangles.
    for(int i = 0; i<pID; i++){
         
         float tI = circleIntersect(p, rdXZ, cLn[i].xy, cLn[i].z);
         gCD = min(gCD, tI);
    }
    
    // Ray to boundary distance. Not to be confused with the nearest
    // isosurface boundary distance, which could be in any direction
    // from the ray point.
    gCD = max(gCD, 0.) + .005;
   
      
    // Giving the 2D objects some height.
    float h = hm(id + .13)*.42 + .03;
    // Extruding the 2D cell object.
    float d = opExtrusion(d2, p3.y - h/2. + .5, h/2. + .5, .004);
    
    // Using the 2D value to manipulate the face of the extruded pylon. It's 
    // a pretty standard CSG move, but I don't see it utilized very often.
    d += max(d2, -.024)*.15; // Beveling.
    //d += d2*.125;
    d += length(gP - cntr)*.03; // Rounding the faces.
    d = max(d, -abs(d2 + .012) + .0025); // Border groove manipulation.
    
    // Debug, to see the floor below.
    //if(hash21(id + .22)<.3) d = 1e5;
    
    // Saving some values for later use.
    gVal = vec4(d2, id, h);
 
    
    // Object IDs.
    vObj = vec4(fl, d, 1e5, 1e5);
    
    // Minimum scene distance.
    return min(fl, d); 
 
}

 
// Basic raymarcher.
float trace(in vec3 ro, in vec3 rd){

    // Overall ray distance and scene distance.
    //float t = 0., d;
    
    // IQ's suggestion: Moving the ray's jump-off point closer to the 
    // surface plane to gain some extra speed, especially when in 
    // fullscreen mode.
    float t = (.5 - ro.y)/rd.y, d;

    
    gRd = rd; // Global ray direction.
    gDir = step(0., gRd) - .5; // Step direction.
    

    
    for(int i = min(0, iFrame); i<96; i++){
    
        d = map(ro + rd*t);
     
        if(abs(d)<.001 || t>FAR) break;
        
        t += min(d*.8, gCD); 
    }

    return min(t, FAR);
}


// Normal function. It's not as fast as the tetrahedral calculation, but more symmetrical.
vec3 normal(in vec3 p) {
	
    //return normalize(vec3(m(p + e.xyy) - m(p - e.xyy), m(p + e.yxy) - m(p - e.yxy),	
    //                      m(p + e.yyx) - m(p - e.yyx)));
    
    // This mess is an attempt to speed up compiler time by contriving a break... It's 
    // based on a suggestion by IQ. I think it works, but I really couldn't say for sure.
    float sgn = 1.;
    vec3 e = vec3(.002, 0, 0), mp = e.zzz; // Spalmer's clever zeroing.
    for(int i = min(iFrame, 0); i<6; i++){
		mp.x += map(p + sgn*e)*sgn;
        sgn = -sgn;
        if((i&1)==1){ mp = mp.yzx; e = e.zxy; }
    }
    
    return normalize(mp);
}


// Cheap shadows are hard. In fact, I'd almost say, shadowing particular scenes with 
// limited iterations is impossible... However, I'd be very grateful if someone could 
// prove me wrong. :)
float softShadow(vec3 ro, vec3 rd, vec3 n, float lDist, float k){

    // Initialize the shade and ray distance.
    float shade = 1.;
    float t = 0.; 
 
    // Coincides with the hit condition in the "trace" function. I've added in 
    // a touch of jittering to alleviate banding.
    ro += n*.0015 + rd*hash31(ro + rd + n)*.005;
    
    // IQ's suggestion: It's analogous to moving the ray closer to the
    // surface plane, in order to gain some extra speed.
    lDist = (.5 - ro.y)/rd.y;
    
    
    gRd = rd; // Global ray direction.
    gDir = step(0., gRd) - .5; // Step direction.


    // Max shadow iterations - More iterations make nicer shadows, but slow things down. 
    // Obviously, the lowest number to give a decent shadow is the best one to choose. 
    for (int i = min(0, iFrame); i<48; i++){

        float d = map(ro + rd*t);
        shade = min(shade, k*d/t);
        //shade = min(shade, smoothstep(0., 1., k*d/t)); // Thanks to IQ for this tidbit.
       
        
        // Early exit, if necessary.
        if (d<0. || t>lDist) break;       

        // So many options here, and none are perfect: dist += clamp(d, .01, stepDist), etc.
        t += clamp(min(d*.8, gCD), .01, .25); 
        
    }

    // Shadow.
    return max(shade, 0.); 
}



// I keep a collection of occlusion routines... OK, that sounded really nerdy. :)
// Anyway, I like this one. I'm assuming it's based on IQ's original.
float calcAO(in vec3 p, in vec3 n){

	float sca = 2., occ = 0.;
    for( int i = 0; i<5; i++ ){
    
        float hr = float(i + 1)*.15/5.;        
        float d = map(p + n*hr);
        occ += (hr - d)*sca;
        sca *= .75;
    }
    
    return clamp(1. - occ, 0., 1.);  
}


void mainImage( out vec4 fragColor, in vec2 fragCoord ){

    
    // Screen coordinates.
	vec2 uv = (fragCoord - iResolution.xy*.5)/iResolution.y;
    
    // Screen space warping. It's a bit hacky, but it always works.
    uv *= .85 + dot(uv, uv)*.3;
 
    
	// Camera Setup.
 	vec3 lk = vec3(iTime/6., 0, iTime/16.);//vec3(0, -.25, iTime);  // "Look At" position.
    vec3 ro = lk + vec3(-.1, 1, -.1); // Camera position, doubling as the ray origin.

    // Light positioning. One is just in front of the camera, and the other is in front of that.
 	vec3 lp = ro + vec3(.75, 0, 1.5);// Put it a bit in front of the camera.

    float FOV = TAU/6.;//tan(radians(30.)/2.)*4.; // Field of view.
   
    // Camera.
    vec3 camDir = normalize(lk - ro); 
    vec3 worldFwd = vec3(0, 0, 1);
    vec3 camRight = normalize(cross(worldFwd, camDir));
    vec3 camUp = cross(camDir, camRight);

    //mat3 mCam = mat3(camRight, camUp, camDir);
    // rd - Ray direction.
    // vec3 rd = mCam*normalize(vec3(uv, 1./FOV));//
    vec3 rd = normalize(camRight*uv.x + camUp*uv.y + camDir/FOV);
    
    // Twisting the camera a bit for a more interesting angle... or
    // a more annoying one. I'm not quite sure which. :)
    //rd.xz *= rot2(PI/18.);
    
     
    // Raymarch to the scene.
    float t = trace(ro, rd);
    
    vec2 svP = gP;
    vec2 svCntr = cntr;
    int svPID = pID;
    
    /*
    // Save the object ID.
    int objID = 0; 
    
    float minDist = 1e5;    
    for(int i = 0; i<4; i++){
       if(vObj[i]<minDist){
           minDist = vObj[i];
           objID = i;
       }
    }
    */

	    vec3 ld = lp - sp;

	    float lDist = max(length(ld), .001);

	    ld /= lDist;

        
        
        // Shadows and ambient self shadowing.
    	float sh = softShadow(sp, ld, sn, lDist, 16.);
    	float ao = calcAO(sp, sn); // Ambient occlusion.
        //sh = min(sh + ao*.25, 1.);
        
 	    
	    // Light attenuation, based on the distances above.
	    float atten = 1./(1. + lDist*.05);

            
        // Obtaining the texel color. 
	    vec3 texCol = vec3(.6); 
        
        // Smoothing factor and edge width.
        //float sf = 1./iResolution.y;
        //float ew = .005;
        
        // Outside rim determination.
        int rim = 0;

        // The extruded grid.
        if(objID>0){
            
            // The 2D boundary that separates the silver rim
            // from the color.
            rim = svVal.x<-.012 - .0025/2.? 0 : 1;
            
            // Polygon ID-based color.
            vec2 iid = svVal.yz;
            float rnd = hash21(iid + .1);
            // IQ's cosine palette formula. 
            //texCol = .5 + .45*cos(TAU*rnd/3. + vec3(0, 1.5, 2.5) - .3);
            texCol = .5 + .45*cos(TAU*rnd/4. + vec3(0, 1, 2));
            
            //if(hash21(iid + .3)<.35) texCol = texCol.xyz;
            //else texCol = texCol.yxz;
            
            // Sky and grass color scheme.
            texCol = mix(texCol.zyx, texCol.yxz, smoothstep(-.6, .6, -uv.y));
            
            // Silver rim, and colored on the inside.
            if(rim==1) texCol = vec3(.05);
            else texCol /= 4.;
            
            /*
            // Dark face rim. Not applicable here.
            float d2 = svVal.x;
            d2 = abs(d2) - ew;
            float h = svVal.w; // Object height.
            d2 = max(d2, abs(txP.y - h) - ew);
            texCol = mix(texCol, vec3(0), 1. - smoothstep(0., sf, d2)); 
            */
 
        }
        else {
        
            // The floor is only sporadically seen between the cracks
            // here, but can be seen in other examples.
            
            // Floor color.
            texCol = vec3(.05);
 
            /*
            // Ground rim.
            float d2 = svVal.x;
            d2 = abs(d2) - ew*1.5;
            texCol = mix(texCol, vec3(0), 1. - smoothstep(0., sf, d2)); 
            */
          
        }

        
        // Backscatter.
        float bac = clamp(dot(sn, -normalize(vec3(ld.x, 0, ld.z))), 0., 1.);
        texCol += texCol*vec3(1, .97, .92)*bac*8.;
       
        // Ambient light.
        //
	    // Quick Lighting Tech - blackle
        // https://www.shadertoy.com/view/ttGfz1
        // Studio and outdoor.
        //float amb = pow(length(sin(sn*2.)*.5 + .5)/sqrt(3.), 2.);
        float amb = length(sin(sn*2.)*.5 + .5)/sqrt(3.)*smoothstep(-1., 1., sn.y); 
        
        // Bit more faux ambient light.
        float af = rim==1? 3. : 1.; 
        amb += amb*af/(1. + t*t);
      
       
        ///////////////
        
        // Material properties.
        float type = .8; 
        float rough = .25;//ns*.4 + .1;
        float fresRef = .5;
        

        // Standard BRDF dot product calculations.
        vec3 h = normalize(ld - rd); // Half vector.
        float ndl = dot(sn, ld);
        float nr = clamp(dot(sn, -rd), 0., 1.); // Leaving it here.
        float nl = clamp(ndl, 0., 1.);
        float nh = clamp(dot(sn, h), 0., 1.);
        float vh = clamp(dot(-rd, h), 0., 1.); 
        // Fresnel related.
        vec3 f0 = vec3(.16*(fresRef*fresRef)); 
        // For metals, the base color is used for F0.
        f0 = mix(f0, texCol, type);
        vec3 FS = f0 + (1. - f0)*pow(1. - vh, 5.); // Fresnel-Schlick reflected light term.

        // BRDF style specular and diffuse calculations. There is so little
        // extra work involved, but the lighting quality is much better.
        vec3 spec = getSpec(FS, nh, nr, nl, rough);
        vec3 diff = getDiff(FS, nl, type);
        float speR = pow(nh, 5.);
        
        
        //////////////
          
        
        // Combining the above terms to produce the final color.
        col = texCol*(diff*sh + spec*sh + amb*(sh*.5 + .5));
        
      
        // Shading.
        col *= ao*atten;
        
             
        // Faux specular environmental reflection.
        vec3 rf = reflect(rd, sn); // Surface reflection.
        vec3 rTx = texture(iChannel0, rf).xyz; rTx *= rTx;
        float rF = objID==0? 0. : rim==1? 16. : 8.;//.5;
        col = col + col*speR*rTx*rF; 
        
        
        // It's sometimes helpful to check things like shadows and AO by themselves.
        //col = vec3(ao);
 	
	}
    
    // Horizon fog. Not visible here, but provided for completeness.
    col = mix(col, vec3(0), smoothstep(0., .99, t/FAR));
    
    
    // Subtle vignette.
    uv = fragCoord/iResolution.xy;
    col *= pow(16.*uv.x*uv.y*(1. - uv.x)*(1. - uv.y) , 1./16.);

    
    // Sigmoid toning.
    //col = tanh(col*1.1);
    
    // Rought gamma correction.
	fragColor = vec4(pow(max(col, 0.), vec3(1)/2.2), 1);
	
}

// Commutative smooth maximum function. Provided by Tomkh, and taken 
// from Alex Evans's (aka Statix) talk: 
// http://media.lolrus.mediamolecule.com/AlexEvans_SIGGRAPH-2015.pdf
// Credited to Dave Smith @media molecule.
float smax(float a, float b, float k){
    
   float f = max(0., 1. - abs(b - a)/k);
   return max(a, b) + k*.25*f*f;
}

// Hash without Sine -- Dave Hoskins
// https://www.shadertoy.com/view/4djSRW
// 1 out, 2 in...
float hash21(vec2 p){

    p = fract(p*vec2(223.547, 256.483));
    p += dot(p, p + 145.627);
    return fract(p.x*p.y);
}


// A slight variation on one of Dave Hoskins's hash functions,
// which you can find here:
//
// Hash without Sine -- Dave Hoskins
// https://www.shadertoy.com/view/4djSRW
// 1 out, 3 in...
float hash31(vec3 p3){

	p3  = fract(p3*vec3(.6031, .5030, .4973));
    p3 += dot(p3, p3.zyx + 43.527);
    return fract((p3.x + p3.y) * p3.z);
}


// Standard circumcircle formula -- It returns the center and radius.
vec3 circumcircle(in vec2 a, in vec2 b, in vec2 c){
    vec2 cb = c - b, baT = (b - a); baT = baT.yx*vec2(-1, 1);  
    vec2 p = (a + b + baT * dot(c - a, cb)/dot(baT, cb))/2.;
    return vec3(p, length(a - p));
}

// Hexagonal grid coordinates. This returns the local coordinates and the cell's center.
// The process is explained in more detail here:
//
// Minimal Hexagon Grid - Shane
// https://www.shadertoy.com/view/Xljczw
//
vec4 getGrid(vec2 p){
    
    // The two mutually offset coordinate systems. One for each hexagon.
    //
    // Two sets of repeat hexagons are required to fill in the space, and the two 
    // sets are stored in a "vec4" in order to group some calculations together. 
    // The hexagon center we'll eventually use will depend upon which is closest to the 
    // current point. Since the central hexagon point is unique, it doubles as the unique
    // hexagon ID.
    vec4 h = vec4(p, p - s/2.);
    // Their respective IDs. iC*s.xyxy represent the cell centers.
    vec4 iC = floor(h/s.xyxy) + .5;
     
    // Centering the coordinates with hexagon centers above to
    // produce respective local coordinates.
    h -= iC*s.xyxy;
 
    // Determine the nearest hexagon cell, then return the local coordinates
    // and the integer IDs. Multiplying the ID by "s" will give you the
    // position based hexagon center.
    //
    // The ID is multiplied by 12 to account for the inflated neighbor IDs above.
    return dot(h.xy, h.xy)<dot(h.zw, h.zw)? 
           vec4(h.xy, iC.xy*12.) : vec4(h.zw, iC.zw*12. + 6.);
    //return getHex(h.xy)<getHex(h.zw)? 
    //       vec4(h.xy, iC.xy*12.) : vec4(h.zw, iC.zw*12. + 6.);

}

// Bidirectional Reflectance Distribution Function (BRDF). 
//
// If you want a quick crash course in BRDF, see the following:
// Microfacet BRDF: Theory and Implementation of Basic PBR Materials
// https://www.youtube.com/watch?v=gya7x9H3mV0&t=730s

// Surface geometry function.
float GGX_Schlick(float nv, float rough) {
    //float r = rough; // original
    float r = .5 + .5*rough; // Disney remapping.
    float k = (r*r)/2.;
    float denom = nv*(1. - k) + k;
    return max(nv, .001)/denom;
}

// Specular calculation.
vec3 getSpec(vec3 FS, float nh, float nr, float nl, float rough){

    // Microfacet distribution... Most dominant term.
    // Microfaceted normal distribution function.
    float alpha = pow(rough, 4.);
    float b = (nh*nh*(alpha - 1.) + 1.);
    float D = alpha/(3.14159265*b*b);    
    
    // Geometry self shadowing term.
    // G_Smith calculations.
    float g1_l = GGX_Schlick(nl, rough);
    float g1_v = GGX_Schlick(nr, rough);
    float G = g1_l*g1_v;
    
    // Combining the terms above.
    return FS*D*G/(4.*max(nr, .001))*3.14159265;
}

vec3 getDiff(vec3 FS, float nl, float type){

    // Diffuse calculations.
    vec3 diff = nl*(1. - FS); // If not specular, use as diffuse (optional)
    return diff*(1. - type); // No diffuse for metals.
}

// Ray origin, ray direction, point on the line, normal. 
float rayLine(vec2 ro, vec2 rd, vec2 p, vec2 n){

   // "1./dot(rd, n)" can be precalculated outside the loop. However,

   //return max(dot(p - ro, n), 0.)/max(dot(rd, n), 1e-8);
   float dn = dot(p - ro, n)/dot(rd, n);
   return dn<0.? 1e8 : dn;   

} 



// IQ's circle intersect function: I have my own, but IQ's functions are 
// known to people, and tend to be more reliable. I can't remember the 
// exact example that I referred to, but IQ's nicely presented shader,
// here, will give you the general idea:
//
// Complex Intersection Points - iq
// https://www.shadertoy.com/view/Dt3SDH
//
// I've substituted in a lot of comments, for anyone interested.
float circleIntersect(in vec2 ro, in vec2 rd, in vec2 ce, float ra){

    // Standard quadratic solution to the ray circle intersection.
    // Ie. Solving the circle equation, "x*x + y*y - ra*ra = 0", where
    // "x = (ro - ce).x + rd.x*t", and "y = (ro - ce).y + rd.y*t". 
    // Substituting produces a quadratic that can be solved for "t". 
    
    vec2 oc = ro - ce; 
    float b = dot(oc, rd);
    //if(b > 0.) return 1e8;
    
    // The factor of 4 has been taken out of the discriminant.
    vec2 qc = oc - b*rd;
    float h = ra*ra - dot(qc, qc); // Squared discriminant: b*b - 4*a*c.
    
    // No real roots, so no intersection... Not on the real plane, anyway.
    if(h<0.) return 1e8; //if(b<0. || h<0.)
    
    // Interpreting the results, below:
    //
    // Real roots, so there are, at most, two solutions -- In the rare case of 
    // the direction ray running perpendicular to the circle normal at the hit
    // point, there'd be two equal values (so techniqally, one solution), but 
    // it shouldn't affect the following logic.
    
    // If the second (larger value) is negative, then it follows that both values 
    // will be negative, so there'll be no intersection points.
    
    // If the second value is positive, but the first value is negative, then
    // we're inside the circle, so we'll need the positive distance in front of us.
    // Ie. The second value.
    
    // If both values are positive, then we're outside the circle, so we'll need the
    // lesser distance, or the first one.
    
    h = sqrt(h);
    
    // Two real roots. Return the correct one based on the above information.
    vec2 pI = vec2(-b - h, -b + h); 
    
    return pI.y<0.? 1e8 : pI.x<0.? pI.y : pI.x;

}
