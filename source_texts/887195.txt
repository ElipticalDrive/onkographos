Currently AaConfig have three different modes for how to calculate AA, but I'm missing one which is perhaps the simplest: Don't do any anti-aliasing.
My need for this is in creating an ID-buffer to power a hitmap. Each object is rendered to the buffer with a color corresponding to the id and a look-up allows you very fast information on what you are hovering over.
The issue is that AA "makes up" ids along the edges of the rendering and thus it needs to be turned off

For Vello Classic, this usage does not match the design because you would have to readback (and wait on the readback for) the pixel intersections from GPU memory.
In Vello Hybrid, the pixel intersections are calculated on the CPU and it should be fairly straightforward to add a side car to store this data during normal rendering (so you don't have to run the pipeline a second time just to get the pixel intersections).

Yes, I don't think we should encourage use that is anti-design. In Vello Classic's case the pipeline is meant to be fire-and-forget all GPU.
My other concern is that you really don't want to run the pipeline a second time. For Vello Classic, this becomes a much more difficult problem because you can't malloc in a compute shader, so to be safe you would have to overallocate and allocate enough intersection bits for pixels on the screen. Clipping and blending would also be tricky.

I apologize as well; I didn't explain pixel intersections clearly enough either.
By "pixel intersections," I also meant "rasteriser with binary coverage;" "pixel intersections" is confusing because it implies ignoring the fill.
What I meant was that, only pixels crossed by the line need AA, and so when you ignore AA, all you need to do is find which pixels the line intersects in addition to the fill you would have done otherwise.
Going back to adding the feature, implementation details aside, my primary concern is intent: Are we adding non-AA rasterization because users actually want aliased rendering? In your case, you want to use for hit detection. I agree this is a clever usage, but will the feature be used for its intended use case? e.g. aliased rendering?
I believe the answer is no, but I do think that convenient pixel perfect hit detection could be useful. But given the implementation constraints I described above, the correct place to do it is Vello Hybrid.

Can you elaborate a bit more on why you're using a hitmap?
