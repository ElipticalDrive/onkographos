feat(v2-render): R-2 hex-voxel terrain mesh — WorldView → flat-top hex columns + cliff quads, biome-colored, with a minimal 3D iso view (render-lane, out of CI)
Context
R-1 landed the render foundation (merged #220): the v2/crates/render macroquad crate, Sim::observe_render → RenderSnapshot, a worker-thread snapshot-driver (ArcSwapOption double buffer), the determinism firewall, and a
proof-of-life loop (naive creature dots + live tick/pop HUD). R-2 is the first REAL view: render the world
terrain as a hex-voxel field. It reads the WorldView trait (sim-core/traits.rs: height/biome/is_solid)
and builds a hex-column mesh — each world cell becomes a flat-top hexagonal column at its terrain height, colored
by biome, with cliff-side quads where neighbouring heights differ. Grounded in RnD rendering/01
(hex-isometric: axial coords, flat-top orientation, height-as-Y + cliff quads) + rendering/02
(det-orthogonal render, per-chunk mesh, hidden-face removal).
Decision already fixed (world-gen phase): hex is a render-space VISUAL over the existing SQUARE Vec2Fixed
sim grid — the sim grid is NOT re-gridded. So R-2 projects each square world cell (x,z) onto a flat-top hex
lattice and draws a hex prism; the sim data stays square. W-6 independence: R-2 reads the WorldView TRAIT,
which today resolves to NoiseWorld (W-6 is on HOLD) and will resolve to ProcgenWorld once W-6 lands — R-2
works on both with zero change (crude NoiseWorld terrain now, rich landscape free when W-6 merges).
Honest scope
R-2 delivers: the hex-voxel terrain mesh (WorldView → hex columns + cliff quads + biome color) and a MINIMAL
fixed 3D iso camera just sufficient to SEE the terrain in perspective/ortho — enough to prove the mesh renders.
Creatures stay R-1's naive dots. OUT: the full interactive IsoCam (pan/zoom/rotate) + box-frustum culling +
zoom-LOD (R-3); creature LOD tiers / morphology (R-4); the cube-voxel toggle (R-5); the full HUD/inspector/
minimap/field-overlays (R-6); day-night lighting, water, shadows, baked AO, greedy meshing (perf polish, later).
Render crate is OUT of CI (verified locally per CLAUDE.md / the animata-ui skill).
Acceptance criteria
Hex-voxel terrain mesh from WorldView (RnD 01). Build a mesh where each world cell (x,z) in the
visible grid (world_dim × world_dim) is a flat-top hexagonal column: a top hexagon face at world Y =
WorldView::height(x,z) (scaled), plus cliff-side quads on the sides where a neighbouring cell's
height is LOWER (the exposed vertical faces — hidden-face removal: do NOT emit a side quad where the
neighbour is equal-or-higher, RnD 02). The square (x,z) grid maps to a flat-top hex lattice by a
documented offset/axial scheme (RnD 01 axial q+r+s=0; e.g. odd-row offset) — the hex is a VISUAL layout,
the underlying data stays the square WorldView. Pure render-side; no sim mutation.
Biome coloring (WorldView::biome → u8). Each hex top face (and optionally cliff shading) is colored
from WorldView::biome(pos) via a documented u8 → Color palette. The palette MUST cover the FULL biome
range of BOTH world impls: NoiseWorld's 0/1/2 (lowland/upland/rock — today) AND ProcgenWorld's
BiomeId variants (8 zonal + the azonal overrides — after W-6), so R-2 does not need re-touching when W-6
lands. Unknown/out-of-range indices fall back to a documented default color (no panic).
Minimal 3D iso view (just enough to SEE the mesh). Add a basic fixed 3D camera (macroquad Camera3D,
orthographic or a fixed perspective at an iso-ish angle) positioned to frame the terrain — enough to render
the hex field visibly. This is NOT the real interactive IsoCam (that is R-3: pan/zoom/rotate + box-frustum
culling); R-2's camera can be a fixed vantage. Creatures continue to render as R-1's dots (project their
Vec2Fixed positions into this view; a rough mapping is fine — R-4 does real creature rendering).
Reads the world via a PINNED-param contract, stays behind the R-1 firewall (critic F3). The render's
WorldView MUST resolve to the SAME terrain the sim runs on. Since the world is a pure deterministic fn of
(world_dim, hmax, seed) (NoiseWorld::new/ProcgenWorld::new take exactly these; build_sim uses
econ.world_dim, the HMAX const, and config.seed ^ WORLD_SALT), the render builds its OWN WorldView
from those SAME params — captured ONCE at startup from the same SimConfig/consts the driver used, and
NEVER recomputed with different params — so the mesh matches the sim's terrain exactly (OR the driver
exposes the world as a shared Arc<dyn WorldView> — either is fine, but the (dim,hmax,seed) provenance
MUST be the single source, not two independent guesses). Document the chosen path. The mesh is built ONCE
(cold terrain is immutable for the run), NOT per frame. Creature positions come from the R-1
RenderSnapshot. The render NEVER mutates the sim (R-1's read-only firewall holds).
Strengthen the R-1 determinism-firewall trace (R-1 carry-forward F1). R-1's firewall test compares
(state_hash, population), but state_hash does NOT fold the conserved field (own conserved_field_hash)
nor SpeciesId — so a mutation touching ONLY those would slip. Extend the firewall trace (in
cli/tests/render_firewall.rs) to ALSO fold conserved_field_hash() (the R14 conserved-field digest,
exists on Sim) and a species digest (fold the species census / a hash over live SpeciesIds — build
it from what Sim already exposes; no new tick state) so the observe-vs-no-observe trace is a TRUE
whole-state fence. This is a test-only change (golden-NEUTRAL — no tick logic touched). Keep ci-report.sh
green.
Local verify (render OUT of CI). cargo build + cargo clippy on the render crate clean; the app
RUNS and visibly draws the hex terrain (record a note / screenshot path in the PR per the animata-ui
skill). No panic on startup, no per-frame mesh rebuild stutter, runs stable for a sustained session.
GOLDEN-NEUTRAL — no sim behavior change. The only CI'd-crate edit is the firewall-trace strengthening
(test-only). No change to sim-core tick logic, WorldView, config, or the 6 goldens. ci-report.sh
exits 0. The render crate stays a leaf bin out of CI.
Out of scope (→ later R-slices)
❌ Interactive IsoCam: pan / zoom / rotate + box-frustum culling + zoom-LOD (R-3). ❌ Creature LOD tiers /
morphology / dot-vs-mesh by px_per_m (R-4). ❌ Cube-voxel toggle / port of v1 cube mesh (R-5). ❌ Full egui
HUD / inspector / minimap / field overlays (R-6). ❌ Day-night lighting, water, shadows, baked AO, greedy
meshing, chunk-streaming (perf polish, later — the world_dim grid is small enough for one mesh now, RnD 02
"40K hexes one draw-call"). ❌ Any sim-grid / determinism change (hex is render-space only).
Verification
Render crate: cargo build/cargo clippy clean, app runs and draws the hex terrain (biome-colored columns +
cliff faces), creatures as dots over it, live HUD — note the manual run in the PR (render out of CI by design).
Firewall: ci-report.sh exit 0 with the strengthened whole-state trace (conserved + species hashes added).
Golden-NEUTRAL: 6 goldens untouched, only the test-file trace changed.
Lane
render / agent:C — the render crate is OUT of CI (local verify); the one CI'd-crate touch (firewall-trace
strengthening in cli/tests) is golden-NEUTRAL. Self-merges once ci-report.sh is green AND the local render
run is confirmed. Runs in PARALLEL with world-gen (B, on HOLD for W-6 recalibration) and #37 (A, idle) — different
crates, no overlap, neutral.
Depends-on
R-1 MERGED (#220, main) — v2/crates/render (crate + driver + RenderSnapshot), Sim::observe_render,
cli/tests/render_firewall.rs (the trace this slice strengthens). WorldView trait (sim-core/traits.rs:
height/biome/is_solid) — resolves to NoiseWorld today, ProcgenWorld after W-6 (R-2 is trait-agnostic, does
NOT depend on W-6). RnD: rendering/01 (hex geometry: axial, flat-top, height-Y + cliff quads), rendering/02
(det-orthogonal, hidden-face removal, per-chunk mesh). Second slice of the render R-ladder; followed by R-3
(interactive IsoCam + culling). PM memory animata-worldgen-workstream (render-lane).
