Summary
This PR fixes two defects in the same rendering workflow:
--accum-type alpha produced an all-black image, while beerLambert
silently produced a mean.
VC3D's “Also write TIFF slices” option passed the nonexistent
--include-tifs flag and aborted before rendering.
Fix
readCompositeFast now routes layer-based methods through the shared
compositeLayerStack() implementation already used by the viewer.
methodRequiresLayerStorage() remains the source of truth, the hot loop reuses
a per-thread buffer, and isoCutoff follows the existing per-layer semantics.
For dual output, VC3D derives Zarr mode from the .zarr suffix and emits the
supported --tif-output <sibling>_layers argument. TIFF-only renders do not
receive a duplicate output.

accumulator and the output was a mean labelled Beer-Lambert. alphaMin/Max/
Opacity/Cutoff, the bl* parameters and isoCutoff were read from the command
line and never used.

needsLayerStorage() now defers to methodRequiresLayerStorage(), the shared
table in Compositing.cpp, keeping only "median" and "minabs" named locally
since they are fast-path reducers with no entry in utils::CompositingMethod.
The reduction calls compositeLayerStack() for everything else, the same
compositors the VC3D viewer runs. The per-pixel buffer becomes a per-thread
LayerStack, so nothing allocates in the loop.

isoCutoff is applied per layer, dropping sub-threshold layers from the stack
rather than zeroing them, matching SurfaceCache.cpp and CChunkedVolumeViewer.
cpp. Layers are counted for max/min/mean too, so a pixel whose layers are all
cut keeps its incoming value instead of min returning 255.
