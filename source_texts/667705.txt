Implemented a robust hashed brick voxel system for volumetric rendering. The system uses a hybrid approach with an SSBO for safe atomic accumulation of density and direction vectors, which is then normalized into a 3D texture for hardware-accelerated sampling. A dynamic voting and proposal mechanism in compute shaders handles sparse brick allocation. The rendering is implemented as a post-processing effect using a DDA-based raymarching algorithm that skips empty space for performance. Integrated with the particle system and demonstrated in a new example scene.

This commit introduces a world-pinned, sparse voxel system utilizing a hashed brick pool for efficient density and direction tracking of particles. Key features include:

- Hashed Voxel Architecture: Sparse grid with hardware-interpolated sampling texture and SSBO-based accumulation.
- Dynamic Voxel Management: Compute-driven allocation and voting mechanism for on-demand brick instantiation based on particle presence.
- Optimized Raymarching: DDA-based algorithm with empty-brick skipping for fast volumetric rendering.
- Particle Integration: Real-time density and direction splatting from the fire particle system.
- Volumetric Post-Processing: Customizable post-processing effect for raymarched volumes, including direction-based coloring.
- Demonstration: Example scene 'voxel_demo' showcasing fire, smoke, and explosion emitters with volumetric effects.

This commit stabilizes and extends the hashed brick voxel system to support
multiple independent volumetric effects and resolves stability issues:

- Parallel GPU Clearing: Fixed system lock-ups by replacing CPU-side buffer
  mapping with 'voxel_clear.comp' for asynchronous parallel clearing.

  each with its own particle style mask. VoxelVolumeEffect can sample from

  handling hash collisions.

  frames of inactivity to prevent resource exhaustion.

  modular compute passes, with density and direction averaging corrected.
