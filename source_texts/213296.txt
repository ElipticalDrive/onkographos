# rgbd-neural-sdf

Turn a posed RGB-D recording into a continuous **neural signed distance field**
and a colored triangle mesh, fully offline.

```
RealSense camera (or any RGB-D source)
        |
        v
aligned RGB + raw depth + intrinsics on disk        (capture)
        |
        v
one camera-to-world pose per frame                  (Open3D odometry or ORB-SLAM3)
        |
        v
depth-ray SDF samples  ->  coordinate MLP  ->  zero-level-set mesh + color   (train)
```

Capture, pose estimation, and mapping are **separate programs**. A recording
stays reusable when the network, its settings, or the pose source change — you
never have to record the same room twice to try a new idea.

The mapper learns **geometry from depth** and, optionally, a **diffuse RGB
appearance** supervised at the observed surface, producing a per-vertex colored
mesh.

---

## Contents

| File | Purpose |
|------|---------|
| `capture_realsense.py` | Record aligned RGB + raw depth from an Intel RealSense camera. |
| `estimate_poses.py` | Sequential Open3D RGB-D odometry → `poses.json`. |
| `import_tum_poses.py` | Convert a TUM trajectory (e.g. from ORB-SLAM3) → `poses.json`. |
| `train_neural_sdf.py` | Train the 3D neural SDF (+ color) and extract the mesh. |
| `make_synthetic_dataset.py` | Tiny synthetic plane for testing without a camera. |
| `rgbd_dataset.py` | Shared dataset readers / validators. |
| `sdf_supervision.py` | Build projective TSDF + color samples from depth rays. |
| `run.sh` | One command: record → poses → map. |

## 1. Install

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-capture.txt   # camera side (pyrealsense2)
python -m pip install -r requirements-mapping.txt   # mapping side (torch, open3d, ...)
```

- On Debian/Ubuntu, `python3 -m venv` needs the stdlib venv package:
  `sudo apt install python3-venv`.
- `requirements-mapping.txt` installs the default PyTorch wheel (CUDA-enabled on
  Linux). Verify the GPU is visible before a long run:
  `python -c "import torch; print(torch.cuda.is_available())"`.
- If a ROS distribution is sourced, its `site-packages` can shadow this
  environment's NumPy. If an import misbehaves, run from a shell **without** ROS
  sourced.
- Only recording needs `pyrealsense2`. If you only map existing datasets (for
  example from ORB-SLAM3), you can skip `requirements-capture.txt`.

## 2. Quick start

`run.sh` builds the environment, records a scan, estimates poses, and trains the
neural SDF. Scans land in `rgbd_sessions/scan_NNN`.

```bash
./run.sh                         # record a new scan, then map it
./run.sh --frames 1200           # record a longer scan
./run.sh --latest                # skip recording, re-map the newest scan
./run.sh --dataset rgbd_sessions/scan_003
./run.sh --setup-only            # only build the virtual environment
```

Re-mapping an existing scan is cheap, so change a setting and re-run rather than
re-recording.
