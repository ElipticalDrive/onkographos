readSignedDistanceFieldNVDB returned garbage, or a misleading domain error, for NanoVDB files from real producers. The vendored tinyvdb snapshot (c0ecb7d) predates upstream's rewrite of its NanoVDB reader, and one of our local patches to it was itself wrong:
Blosc was never compiled in, and the fallback reported success for data it could not decode.
The grid and tree headers were parsed before decompression, i.e. from the compressed bytes.
Our local patch skipped a name terminator that libnanovdb already counts in the name size, misaligning every field after the name.
Re-vendor tinyvdb from syoyo/tinyvdb d63a8f5, whose reader handles all three and treats the grid buffer as authoritative, and drop both local reader patches. Only the sources the build compiles and the headers they include are kept; the reader now needs tinyvdb_tree.c, tinyvdb_sdf_tree.c and tinyvdb_thread.c, built with the serial task backend so no thread library is needed. Link Blosc when it is found.
Reading the grid buffer exposed a writer bug that the old reader hid by trusting the file's metadata: tvdb_grid_to_nanovdb_float wrote node-extent bboxes, so a 7x6x5 SDF written by writeSignedDistanceFieldNVDB read back as 128^3. The vendored writer carries the fix from this tinyvdb PR.
BREAKING CHANGE:
NanoVDB files written by Tesseract before this change used tinyvdb's old, non-standard name layout and are now rejected; libnanovdb misreads them too. Without Blosc a BLOSC-compressed file is rejected. Adds a small fVDB-written fixture and a test that checks its domain and every sample, or the rejection when Blosc is unavailable.
