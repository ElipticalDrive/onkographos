This adds a simple Gaussian splats renderable object and layer, plus a PLY loader. This PR only supports standard 3DGS splats (reference implementation PLY layout). It does not include support for Luxar-shaped splats.
GaussianSplatSource.fromPly(url) loads splats. new GaussianSplatLayer({ source }) renders them. Layers on the same source share its data and GPU texture. Splats are drawn on instanced screen-space quads and composited back to front. A performant radix sort runs on the main thread, and only when the view direction rotates more than 1°.
This requires Float16Array, available in all modern browsers. We can work around this requirement with our own toHalf function if that's too restrictive.
Public splat data with permissive CORS is hard to find. Here I'm using data I added to the vispy demo-data repo as part of my splat PR for that project.
Future work plan:
add support for orientation-dependent colors with higher-order spherical harmonics
add support for Luxar-shaped splats:
chunked loading, caching, integration with ChunkManager
load only chunks in view
add prefetching policy
per-splat intensity rendered with color maps
additional rendering modes (volumetric, max, etc.)
There are many other potential optimizations:
move the depth sort to a worker
upload the order index in chunks
skip the depth sort depending on rendering mode
density guard for significant overdraw
adaptive level budget (Luxar)
off-screen targets (no MSAA for splats, MSAA on for other layers)
