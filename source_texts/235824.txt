The current design of the Camera type and the related RenderSpec trait still has some problems:
The RenderSpec is the actual working part of the Camera and defines the type of the camera (pinhole/lens etc). The Camera type only holds some camera-independent tracing logic. So it requires reading the code before understanding how to use both of them and need to dive into definitions and implementations before being able to implement a new RenderSpec.
The missing and exception logic is currently hard-coded to the Camera type and cannot be customized.
The ray_color method cannot be customized for different sampling methods.
The new design should be a Camera trait, which requires a ray_generation method and provides several other methods based on it, where the major one would be render. The ColorMixer and the miss/exception logic are orthogonal to the type of camera so there should be a way to get them externally. Two default implements for Pinhole and defocus blur should be provided.
