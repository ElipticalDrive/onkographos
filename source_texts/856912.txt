Why
The sphere-grasp TSR's roll/pitch/yaw box covers SO(3), but ParallelJawGripper.grasp_sphere claimed that sampling it produces uniformly distributed approach directions. TSR.sample draws roll, pitch and yaw independently and uniformly. In the ZYX convention R = Rz(yaw) Ry(pitch) Rx(roll), the Haar density is ∝ cos(pitch), so uniform pitch concentrates approach directions near the poles. It was also unclear what a restricted angle_range represents.
What
Coverage and distribution are documented separately (grasp_sphere in the base and concrete classes, ARCHITECTURE.md, README). A restricted angle_range bounds Euler yaw: the represented approach directions form the lune azimuth ∈ angle_range, not a spherical cap, with any spin about the approach axis.
New tsr.sampling.sample_haar / sample_haar_xyzrpy (exported from tsr). Roll and yaw are drawn uniformly and sin(pitch) uniformly, which gives exactly the Haar measure restricted to the rotations the Bw box represents. Translation is uniform. Pitch bounds must lie within [-π/2, π/2] so the box maps one-to-one onto rotations. This is checked exactly on the raw Bw, and anything else raises ValueError. The sampler is reproducible under an explicit rng. TSR.sample is unchanged.
Sphere template descriptions say "full SO(3)" only for full yaw, and "azimuth lune a°–b°" otherwise.
Review follow-ups (33f9001)
Reject degenerate pitch intervals at ZYX gimbal lock in the Haar sampler #116: a pitch fixed exactly at ±π/2 (ZYX gimbal lock) now raises ValueError. At that pitch roll and yaw are coupled, so sampling them independently gives a triangular effective angle, not a uniform one. Nonzero intervals that touch ±π/2, including the full sphere-grasp interval, remain valid because the singular set has measure zero.
Make the README Haar-sampling example executable #117: the README snippet imports sample_haar and uses an explicit rng. The complete snippet runs and returns a transform that tsr.contains accepts.

Careful review of 2b1cac0 is complete. The main construction is correct: for the nonsingular ZYX chart, uniform roll/yaw together with uniform sin(pitch) produces the Haar density; fixed left and right frame transforms preserve it. The sphere-grasp lune interpretation is also correct.
I found two bounded items to address before merge:
Reject degenerate pitch intervals at ZYX gimbal lock in the Haar sampler #116 rejects pitch intervals fixed exactly at a ZYX gimbal-lock endpoint. At pitch = ±pi/2, roll and yaw are coupled, so independently sampling both can produce a nonuniform distribution over the unique represented rotations. A point interval with roll and yaw each in [0, 1] gives a triangular effective-angle distribution. Nonzero pitch intervals that merely touch the endpoints remain valid because the singular set has measure zero.
Make the README Haar-sampling example executable #117 makes the README example executable. In the current surrounding snippet, tsr names a TSR instance rather than the package, so tsr.sampling.sample_haar(tsr, rng) fails, and rng is undefined.
