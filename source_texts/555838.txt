First, I'm super excited about the idea of a Houdini -> pbrt exporter;
please don't hesitate to send along other questions / issues you run into
along the way. It'd be really great to get some great scenes via Houdini
for the scenes distribution.
It took me a while to track down what's going on (which suggests that there
are some usability issues with pbrt's volume support), but in the end, it
was very simple: pbrt assumes that the surface normals of geometry that
bounds a volume are pointing outside the volume's boundary, but it looks
like your PLY mesh has the normals pointing inside. If you add a
"ReverseOrientation" before the ply mesh, things come out much better:
[image: Inline image 1]
(That was with the camera moved back a bit.) It does look like there's an
issue with indexing/ordering of the volume density values, but presumably
that'll be easy to chase down.
Note that I rendered that image with 16 samples per pixel--reducing your
number of pixel samples may be helpful for quick tests.
Finally, as a heads up: at one point I thought the issue might have been
that the camera was inside the bounds of the volume. If that is the case,
you'll want to specify the named medium before WorldBegin and also specify
a MediumInterface before you specify the camera, so that the camera knows
that its rays are starting out in the volume.

Yep, that's what I was seeing!
Voxels are laid out with x=y=z=0 as the first density value. The next one is (0,0,1), and so forth up to (0,0,xres-1). Then come (0,1,0) up to (0,1,xres-1), and so forth. (And then once the y coordinate hits yres-1, it goes back to 0 and z is incremented.)
Regarding OpenVDB: I looked into that a year or so ago--the main issue is that it pulls in so many additional dependencies--boost, TBB, glfw, etc. We try to make it as easy as possible to build pbrt in general; this is especially important for making it easy to use in the university setting with students. So I don't think OpenVDB makes sense in that respect.
That said, maybe it would make sense to have a "pbrt-tools" repository (or somesuch) that included useful additional stuff, but wasn't strictly necessary to build and use the core system. There we could be a bit more relaxed about additional dependencies. I guess it would depend what the benefit was, etc..
