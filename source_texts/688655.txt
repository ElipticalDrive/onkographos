Owner
A high-fidelity pipeline for converting isometric pixel art to 3D voxel models.
Core features:
2:1 dimetric projection mathematics for pixel-perfect accuracy
Multiple depth estimation modes (EDT, luminosity, explicit)
Greedy Meshing with Numba JIT (80-95% vertex reduction)
sRGB to Linear color conversion for proper rendering
Coordinate system transforms for Godot/Blender
Export formats:
MagicaVoxel (.vox) for voxel editing
glTF 2.0 (.glb) for game engines
Wavefront (.obj) for universal compatibility
Includes CLI tool, Python API, demo script, and unit tests.
Note
Introduces a complete isometric pixel-art→voxel pipeline with multiple depth modes, greedy meshing, and glTF/VOX/OBJ export via Python API and CLI.
Core Pipeline (src/voxel_generator/):
generator.py, voxelizer.py, ingestion.py: Image loading, depth estimation, voxelization, and mesh generation orchestration.
greedy_mesh.py: Numba-accelerated greedy meshing plus naive mesher and stats.
depth.py: Multiple depth modes (flat, distance_transform, luminosity, explicit, gradient_x/y, symmetry) and utilities.
projection.py: 2:1 dimetric math and coordinate system transforms.
color.py: sRGB↔Linear conversion, quantization, and palette management.
Exporters (src/voxel_generator/exporters/):
gltf_exporter.py (.glb), vox_exporter.py (.vox), obj_exporter.py (.obj, optional MTL), plus PLY support inside OBJ module.
CLI (src/voxel_generator/cli.py):
voxgen command for single/batch/sprite-sheet processing with depth/extrusion/format options.
Examples & Docs:
examples/demo.py demo script; comprehensive README.md with usage and architecture.
Packaging:
pyproject.toml, requirements.txt, package __init__.py, and .gitignore.
Tests (tests/):
Unit tests for grid, depth estimation, meshing, color conversion, projection, and integration of VoxelGenerator.

Bug: Double scaling applied to vertex positions in exports
Vertex positions are scaled twice by voxel_scale. The generate_mesh() method passes voxel_scale to the mesher which scales vertices during mesh generation. Then export_glb() and export_obj() pass the same voxel_scale to their respective exporters which scale the already-scaled vertices again. For example, with voxel_scale=0.1 (as used in the demo), the final scale becomes 0.01 instead of 0.1.

Bug: Z-face quad dimensions swapped in greedy meshing
For Z-face directions (4 and 5), the quad dimensions are stored with width and height swapped compared to other directions. The slice stores [d1, d2, slice_pos, width, height, direction] where width is expansion along the d2 axis and height along d1. But _quad_to_vertices uses d1 for x-extent and d2 for y-extent, which is reversed since d1=width was expanded along y (d2) and d2=height was expanded along x (d1). This causes incorrectly shaped quads for top and bottom faces.

Bug: Material names mismatch between OBJ and MTL files
When exporting with vertex_colors_mode="mtl", material names in the OBJ file don't match the MTL file definitions. In _export_with_materials, unique colors are obtained via list(set(face_colors)) which has arbitrary ordering, while _write_mtl uses np.unique() which returns sorted colors. Material indices are based on enumeration order, so material_0 in the OBJ references a different color than material_0 defined in the MTL, causing incorrect colors when the model is loaded.
