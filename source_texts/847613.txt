# 4dgs-viewer

A method-aware adapter and browser viewer for Gaussian Splatting research outputs.

[Try the public viewer](https://gs-viewer.zionhuang.chatgpt.site/) · [中文](README.zh-CN.md) · [Papers](PAPERS.md) · [Format reference](FORMATS.md) · [Contributing](CONTRIBUTING.md)

Open a trained Gaussian asset, inspect its representation, play its time-dependent content, and export a view or diagnostic report. The viewer supports several explicit 4DGS representations, plus static 3DGS PLY and `.splat`.

**Status: alpha.** Format support is specific to the schemas below. Rendering is a browser preview, not a promise of pixel-identical output from the original research renderer. The npm package has been built and tested locally; this project has not published it to a registry.

## Why adapters? Original papers and method support

The methods below do not share one interchangeable “4DGS file format.” PLY is a container: identical extensions can hold different motion, time, covariance, and appearance semantics, sometimes with additional neural-network weights. This project provides explicit adapters for selected method/export profiles and a common inspection/playback interface. It does not introduce a universal 4DGS standard or convert models between methods.

| Original paper | Role in this viewer | Adaptation boundary |
| --- | --- | --- |
| Kerbl et al., [3D Gaussian Splatting for Real-Time Radiance Field Rendering](https://arxiv.org/abs/2308.04079), SIGGRAPH / TOG 2023 | Static Gaussian foundation; `static-3dgs` adapter | Gaussian PLY preview with supported SH; static, not a dynamic method |
| Yang et al., [Real-time Photorealistic Dynamic Scene Representation and Rendering with 4D Gaussian Splatting](https://arxiv.org/abs/2310.10642), ICLR 2024 | Native 4D Gaussian / conditional-covariance foundation of the 4C4D line | Representation lineage, not a separately validated upstream-checkpoint adapter |
| Li et al., [Spacetime Gaussian Feature Splatting for Real-Time Dynamic View Synthesis](https://arxiv.org/abs/2312.16812), CVPR 2024 | OPPO `oppo-spacetime` adapter | Explicit motion/time/rotation and raw-DC preview; no full neural appearance decoder |
| Zhou et al., [4C4D: 4 Camera 4D Gaussian Splatting](https://arxiv.org/abs/2604.04063), CVPR 2026 | `4c4d-gaussian` adapter | Documented Gaussian PLY export profile; not the full training/checkpoint pipeline |

Another early work, Wu et al.'s [4D Gaussian Splatting for Real-Time Dynamic Scene Rendering](https://arxiv.org/abs/2310.08528) (CVPR 2024), uses a neural deformation representation. **Its dynamic checkpoint inference is not implemented here.** It must not be confused with Yang et al.'s native 4D Gaussian representation.

The observed 4DV packed layout and antimatter15 `.splat` are implementation-format references; the scene JSON is this project's import wrapper. They are not three additional research methods. Full authors, original papers, official code, support boundaries, and [BibTeX](references.bib) are collected in [PAPERS.md](PAPERS.md).

## Try it

1. Open the [viewer](https://gs-viewer.zionhuang.chatgpt.site/).
2. Drag in a supported model, or choose files / a folder. Import the trained Gaussian output, not a reconstruction input point cloud.
3. Press **F** to frame the object, then **Alt + left drag** to orbit it.
4. Use the timeline for dynamic assets. Open Asset Summary for the detected format, loaded point count, and limitations.

Files selected from your device are read by the browser; the viewer has no model-upload endpoint. Built-in demos and URL-backed assets make network requests to their hosts. Models are not bundled with the application.

Use a desktop browser with WebGL2. The optional WebGPU preview also requires an available GPU adapter and a secure context (HTTPS or localhost). Our recorded browser checks use desktop Chrome; other browsers, mobile devices, and touch controls do not have equivalent validation.

## Supported formats

“Supported” means the matching schema can be inspected and decoded. Preview fidelity and optional renderer features are separate.

| Input | Representation / behavior | Current support |
| --- | --- | --- |
| 4DV packed `.ply` / `.4dv` | Chunk-quantized Gaussians, packed motion/time, segmented playback | Supported for the observed 4DV schema; `.4dv` must contain that PLY layout |
| OPPO SpacetimeGaussians `.ply` | Temporal Gaussian opacity, cubic position motion, time-varying rotation | Supported raw-DC/lite-style preview; no full neural appearance decoder |
| 4C4D Gaussian `.ply` | Temporal opacity and conditional 4D covariance when `rot_r_*` is present | Supported preview; missing `rot_r_*` uses a reduced 3D covariance path |
| Static 3DGS `.ply` | Anisotropic scale/rotation, opacity, SH DC and recognized higher-order SH | Supported; no intrinsic animation |
| antimatter15 `.splat` | 32-byte rows: position, linear scale, RGBA, byte quaternion | Supported static RGB preview; no SH or time |
| Scene JSON + referenced files | A manifest describing one of the above formats, camera, and timing | Supported import wrapper, not an additional Gaussian representation |

PLY **decoding requires `binary_little_endian`**. ASCII/big-endian headers can sometimes be inspected but cannot be rendered. Mesh PLY, COLMAP `points3D.ply`, `.ksplat`, `.spz`, SOG, generic compressed PLY, and training checkpoints such as `.pt` / `.pth` are not supported.

See [FORMATS.md](FORMATS.md) for exact field requirements, renderer differences, time and coordinate conventions, unsupported variants, and source pointers.

## Import forms

| Form | How to use it |
| --- | --- |
| Single file | Drop or select `.ply`, `.4dv`, or `.splat` |
| Model + camera | Select the model together with `settings.json` or a supported research `cameras.json` |
| Folder / multiple files | Choose a folder or drop it; use a manifest to select the intended model and segment order |
| Local scene package | Drop `scene.4dgs-viewer.json` together with all referenced files, or their containing folder |
| Remote assets | Import a demo-style JSON manifest with HTTP(S) asset URLs; the hosts must allow CORS |
| JavaScript integration | Pass a URL or browser `File` to the package API |

A folder containing several training iterations is not automatically recognized as “pick the latest checkpoint.” Without a manifest, matching files are sorted by path and treated as segments. Prefer a small export folder containing only the desired files.

Local scene example:

```json
{
  "schema": "4dgs-viewer.scene.v1",
  "title": "My dynamic scene",
  "segments": ["point_cloud.ply"],
  "timeline": { "start": 0, "duration": 1, "startTime": 0 }
}
```

The one-unit duration above is illustrative; use the time interval expected by your asset. The manifest does not infer FPS or convert training time units. See [import examples](examples/manifests/README.md).

## Run locally

Use **Node.js 24** and **Rust 1.91.1 + wasm32-unknown-unknown** for source builds. See [WASM.md](WASM.md) for Rust setup and Windows/WSL support. The installed Vite version requires Node `^20.19.0 || >=22.12.0`; the package's lower runtime engine declaration is not the development-tool requirement.

Clone the standalone repository and run:

```bash
git clone https://github.com/hzx829/4dgs-viewer.git
cd 4dgs-viewer
npm ci
npm run dev
```

Open the local URL printed by Vite. To start without fetching a demo's model, append `?source=builtin&autoload=0`, then choose your own file.

```bash
npm test
npm run preview
```

`npm test` builds the source WASM, app, library/types and CLI, then runs sorting, worker lifecycle, format and cache tests. `npm run test:wasm:browser` and `npm run test:wasm:production` run separate Chrome/GPU checks. Default tests need no research assets; optional local samples require an explicit path or `GS_WORKSPACE_ROOT`.

For a build without tests, run `npm run build`. Output:

| Directory | Purpose |
| --- | --- |
| `dist/app` | Static browser app; serve this directory over HTTP(S) |
| `dist/lib` and `dist/types` | ESM package API and TypeScript declarations |
| `dist/cli` | Bundled asset-inspection CLI |

This source release builds its own exact/quantized WASM sorter and retains full JS sorting on failure. It excludes local demo caches and official 4DV WASM/bindings. Deploying `dist/app` does not upload your models. See [source-release boundaries](SOURCE_RELEASE.md) and the [release checklist](RELEASE_CHECKLIST.md).

## Inspect from the command line

After building:

```bash
node dist/cli/4dgs-viewer.mjs inspect /path/to/point_cloud.ply --pretty
node dist/cli/4dgs-viewer.mjs inspect /path/to/a.ply /path/to/b.splat --pretty
```

Use your actual absolute path; quote paths containing spaces. The bundled CLI also accepts paths relative to the current working directory. It reads local files, not URLs or scene manifests.

Reports include the detected family, point count, field mapping, time/motion/covariance semantics, and warnings. Inspection is not a full decode or renderer validation: a recognized header can still describe an incomplete or unsupported payload.

The development shortcut `npm run inspect -- /path/to/asset.ply --pretty` is also available. Both CLI entry points resolve relative paths from the current directory.

## Embed in an application

The package exposes `inspectGaussianSource`, `loadGaussianPointCloud`, and `WebGlGaussianRenderer`, along with data types and provider contracts. See the [embedding example](examples/minimal-three/README.md) and [public API boundary](PUBLIC_SURFACE.md).

For local package evaluation, run `npm pack` and install the resulting tarball in your application. A registry installation command will be added after the first verified publication; do not assume the registry name currently resolves to this project.

## Rendering, exports, and limits

Render settings → **WASM sorting** selects **Exact depth** (default) or
**Quantized · fast**. Exact preserves complete depth order; quantized uses one
counting pass and can change local compositing, especially for moving splats.
Switching these algorithms keeps imported files loaded. `?sortAlgorithm=quantized`
selects the fast path initially and is retained in the copied session URL.
Metrics and Asset reports record the requested algorithm and actual backend.
The separate **Sort mode → JS full (reference)** remains available for comparison;
choose that mode before importing local files. Provider-specific OPPO splatv and
4C4D/WebGPU sorting use their own paths. See [WASM.md](WASM.md) for details.

WebGL2 is the baseline. The `renderPipeline=4dgs-webgpu` option enables experimental OPPO/4C4D preview. GPU-resident 4C4D requires conditional covariance; that path currently uses DC color rather than higher-order SH. A fallback can change the active backend—check the on-screen result and metrics.

- **Rendered**: a preview is available under the current settings.
- **Limited**: a preview is available with a reported constraint, such as a point limit or backend limitation.
- **Cannot render**: the format, data, or required capability could not be used.

These labels are operational results, not a quality score or an author-renderer equivalence certificate.

**Snapshot** saves the current visible canvas as PNG. **Asset report** exports diagnostic JSON, including runtime state when available. **Copy session URL** copies the current address only: it does not upload local files or serialize subsequent camera movement and UI changes. Reopen local files when revisiting a session. There is no model conversion/export or video export workflow.

Prepared frames use a 512 MiB LRU budget by default. `cacheBudgetMiB` adjusts it, and `prefetch=adjacent` is the default. This is a prepared-frame budget, not a cap on all browser/GPU memory. Reduce the point limit for large assets.
