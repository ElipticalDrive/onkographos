Loading
src/obj.js parses Wavefront OBJ. The face grammar is where these quietly
fail, because a file using an unhandled form yields a mesh with missing
triangles rather than an error, so all of it is covered: f a b c, f a/b,
f a//c, f a/b/c, n-gons by fan triangulation, and negative indices, which
count back from what has been read at that point in the file rather than from
the final total.
Meshes arrive at whatever scale they were authored in, so normalizeMesh sits
the model on y = 0 and scales it to a given size. Without it a model a
thousand units across either fills the frame or vanishes, with nothing in
between that looks like a mistake worth investigating.
Drag an OBJ onto the viewport to render it. Parsing happens in the tab and the
file is never uploaded, which is worth stating plainly given what is being asked
of the visitor.
The sample mesh
tools/make_mesh.py generates a (2, 3) torus knot swept as a tube, with
analytic vertex normals, following the same approach as Lodestone: generate the
sample rather than commit someone else's asset, so no third party licence enters
the repository and the geometry is defined by parameters instead of a binary.
A knot is a better test than a subdivided sphere because it passes through its
own bounding box repeatedly. Nodes high in the tree enclose large volumes of
empty space, so the surface area heuristic has a real decision to make.
It is 2.7 MB, 780 KB over the wire once gzipped, and it is committed so the demo
works without anyone running Python.
Smooth normals
Flat shading was clearly visible on the tube, because refraction amplifies every
normal discontinuity: a facet that would pass unnoticed on a diffuse surface
bends light visibly through glass.
Vertex normals are interpolated from the barycentric coordinates of the hit.
They live in their own buffer rather than in the primitive, since packing them
inline would grow every primitive by 36 bytes including the spheres and floor
quads that never use them, and the primitive buffer is the one thing every ray
touches.
A shading normal is a lie told for smoothness, and two consequences are handled.
It is not flipped independently of the geometry, or a ray entering glass and one
leaving it disagree about which side is inside. And it is kept on the same side
as the geometric normal, since interpolation near a silhouette can tip it past
the surface and leave a black rim.
Firefly clamping, on by default and indirect only
A caustic is found by chance. A shadowed floor point can only be lit by a
diffuse bounce that happens to refract through glass and land on a sun 1.6
degrees wide, so the rare path that succeeds carries an enormous weight and
appears as a bright speck that takes thousands of samples to average away.

Applied to the whole path it would also cap what the camera sees directly, and
the ceiling lamp is brighter than the limit, so the light itself would render
dimmer with the toggle on. The clamp now applies only to indirect light, and a
test asserts the lamp is unchanged either way. It is, to 0.00%.
A flaw in the previous measurements
The noise tool rendered a scene twice and treated the two as independent draws.
They were not: reset() zeroes the frame counter that seeds the RNG, so both
replayed the same sequence and differed only where frame pacing happened to
diverge. It reported exactly zero noise for any scene that converged quickly,
which is what gave it away.
renderTo now takes a seed offset. Re-measuring the dispersion change from the
previous pull request gives 2.05x lower noise and 4.19x fewer samples,
against the 1.94x and 3.75x reported there. That description understated the
result rather than overstating it, so it stands as a conservative claim.
