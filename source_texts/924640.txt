Issue body actions
Goal
Connect camera/player interest to actual native World residency: demand → immutable generation proposals/cache → owner-mediated admission → simulation → durable mutation/state storage → eviction/reload. Support deliberate recipe evolution without overwriting player or simulation changes.
Ownership rule: procedural generation owns untouched baseline content; player/simulation mutations retain their authority. A modified or merely resident chunk must never be treated as disposable fresh terrain.
Programme and dependency order
GEN-003 #190 → GEN-004 #191 → GEN-005 #192 → GEN-007 #193 → GEN-006 #194.
This order is deliberate: establish spatial language, structured places and coherent depth, qualify authoring/content quality, then add persistent runtime streaming.
Prerequisite and quality gate: GEN-007 #193, consuming GEN-003 #190, GEN-004 #191 and GEN-005 #192.
Implementation position: 5 of 5 — intentionally after GEN-007. Architecture exploration can occur earlier; runtime integration/acceptance consumes the qualified content and diagnostics.
Reconcile the existing boundaries first
Read world storage and interest regions, generation, ownership/lifetimes, level saves/replay, ADR-004 and current depth contracts.
Current native storage is sparse, but desktop/Web adapters are finite 1024×1024 views. The existing installer admits only absent chunks and refuses even empty residents. Interest exclusion pauses phased work without elapsed-time catch-up; it is not eviction. CYSD1 is a finite level reconstruction format, not a general sparse-world continuation serializer. Explicitly update these statuses only as capabilities become implemented and verified.
Required scope
Interest-driven runtime and bounded lifecycle
Implement an opt-in playable/native host or production adapter integration with real camera/player demand, prefetch margins, hysteresis, coalescing, prioritization and cancellation. Use a finite presentation window over signed world coordinates; do not cap the stored world at 1024×1024 or silently clip out-of-capacity demands.
Define explicit requested/generating/ready/admitted/dirty/saving/evictable states and ownership transitions. Bound resident chunks, queued jobs, proposal cache, semantic plans, admission work, snapshot leases, persistence backlog and temporary buffers. Specify deterministic priority/tie-breaking and observable pinning/backpressure when capacity is exhausted.
Support cross-chunk semantic features and dependent plane/fixture bundles without assigning duplicate owners. A preview cache or interest-filter toggle alone does not satisfy this issue.
Immutable proposals and safe admission
Workers never mutate live World, Godot scene-tree or Rapier objects. Proposal/cache receipts bind world/session identity, coordinates, seed, recipe/schema/algorithm, field graph, grammar, semantic region, layer and baseline content identity. Include residency/incarnation and mutation generations where needed to prevent stale reuse.
Validate receipts again at the actual owner commit boundary, not only when a job is queued. Cancellation is advisory; late results still need rejection. Recipe changes, reset, eviction/reload and new local edits invalidate incompatible pending results.
Keep fresh-chunk installation strict. Replacement/reconciliation requires a separate validated owner transaction, with worker/lease draining where necessary. Define an atomic or coherently staged boundary for related chunks/layers/features so no partial incompatible bundle becomes active.
Baseline, mutations and resumable state
Version a storage model that distinguishes:
Reproducible immutable baseline, including old recipe/module versions or retained baseline data needed to recover it.
Persistent mutation overlay/journal with explicit air/Empty tombstones and mutation provenance.
Authoritative simulation state and feature/link lifecycle needed to resume admitted content.
Inventory actual native mutable state before coding: material-specific state, optional fields, clocks/deadlines/activity, pending boundary work, and generated fixture/event counters as applicable. A material-ID overlay alone cannot preserve moved liquids, reactions or meaningful continuation.
Track both player and simulation changes, including departures and arrivals across boundaries. Destroyed cells/features, consumed reactants and retired emitters must not respawn. Do not classify a cell as untouched merely because its current material happens to equal its old baseline.
Persist all state required by the declared supported domain. Where an actor/body/transient domain cannot yet be serialized safely, pin its dependent regions and expose the limitation rather than dropping or reconstructing it silently. This issue must still demonstrate real eviction/reload of dynamic cellular worlds. Whole-game replay or arbitrary actor-state support is not implied.
Durable eviction and reload
Save dirty state successfully before discarding the only live copy. Restore mutations, simulation state, feature/link registrations and clock policy before activating a reloaded chunk. Handle neighbor halos, boundary transfers and generated sources so neither mass nor events are duplicated/lost.
Use crash-consistent, versioned persistence with validated lengths/coordinates/material/state domains, content checksums and an atomic publication or journal strategy. An older asynchronous save cannot replace a newer mutation generation. Corrupt/truncated records, incompatible schemas, missing historical baselines and storage errors produce explicit recovery/failure outcomes; never silently regenerate modified content.
Retain the current no-wall-time-catch-up policy unless an explicit versioned alternative is implemented and qualified. Reset/reload must preserve failed-world quarantine and owner lifecycle rules.
Recipe revision reconciliation
Provide an inspectable three-way comparison between old baseline, new baseline and persisted/live mutations.
Untouched regions may adopt the new baseline.
Existing mutations and explicit edit intent remain authoritative.
Non-overlapping changes can rebase; identical changes can converge under a declared rule.
Ambiguous overlaps default to retaining the mutation or rejecting the rebase, with an explicit conflict receipt.
Feature additions/deletions, socket compatibility, fixture lifecycles and interlayer links participate in reconciliation.
A baseline hash alone is insufficient to reconstruct the old content: retain reconstructible versioned inputs or the necessary baseline data.
Provide a bounded dry-run preview with affected chunks/features, conflict samples, decisions and cost; then a validated commit with revision receipts. Recheck mutation generations if simulation or editing advances after preview. Cancellation, repeated reconciliation and restart/recovery must be idempotent and safe. Define treatment of connected feature/layer groups and retained older revisions so mixed recipes cannot silently break their shared boundaries.
Operational diagnostics
Extend GEN-007 with demand/residency states, job/admission receipts, dirty/pinned chunks, save backlog, bounded resource use, revision differences and reconciliation conflicts. Distinguish deterministic baseline generation from live simulation: different real-time admission schedules do not automatically imply identical physical outcomes.
Deliverables
Real camera/player-driven native streaming with an explicitly supported adapter/host and lifecycle state machine.
Versioned durable sparse-world baseline/mutation/continuation storage with crash recovery.
Owner-mediated eviction/reload and transactional recipe reconciliation.
Workbench/runtime diagnostics and reproducible lifecycle/failure fixtures using the GEN-007 scene.
Updated storage, ownership, depth/event, save/migration, configuration, roadmap and RAG contracts.
Acceptance gates
Traverse a documented route through and beyond the 1024×1024 qualification area, crossing signed-coordinate boundaries and exceeding the resident budget. Observe actual generation, admission, eviction and reload within declared limits.
Baseline semantics/materials remain invariant under varied request/completion order, worker counts, budget slices and cold/warm caches.
Erasure to air, placed material, moved liquid, native reaction products, destroyed fixtures and supported rear/effects state survive eviction/reload and process restart without resurrection or duplication.
A fixed-input/fixed-tick continuation fixture compares an admitted save/load sequence against an uninterrupted control for the declared state domain. Record deliberate pause behavior separately from full replay claims.
Stale jobs, cache results, save completions and reconcile previews cannot overwrite a newer world/session, chunk incarnation, recipe or mutation generation.
Whole supported semantic/plane bundles install or reject consistently; unsupported actor/transient eviction pins safely with visible diagnostics.
Reconciliation covers untouched content, disjoint edits, identical edits, overlapping conflicts, explicit same-value edits, deleted features, changed sockets and invalid layer links; a repeated commit is idempotent.
Interrupt save/rebase operations at publication boundaries and inject disk/backlog failure, corrupt/truncated records and unavailable old baselines. Preserve the last valid durable state and report unresolved work.
Rapid camera changes, cancellation storms, boundary activity and slow persistence keep resident/proposal/save memory and per-tick work within measured declared bounds.
The existing exclusive ownership, failed-world quarantine, strict fresh installer and pause/re-entry controls remain enforced.
Reproducible commands, evidence, runtime diagnostics, canonical/RAG updates and applicable repository gates are complete.
Agent execution prompt
Implement GEN-006 after the GEN-007 quality checkpoint. Start with an explicit authoritative-state inventory and lifecycle/ownership design grounded in current native World and finite adapters. Implement vertical slices covering real admission, dirty-state persistence, safe eviction and exact supported restoration before adding recipe rebase. Use the qualified four-plane recipe as the integration workload. Exercise stale-generation races and interrupted persistence throughout development. Deliver an operational camera-driven lifecycle and inspectable three-way reconciliation; a proposal cache, save of material IDs alone, or forced regeneration of modified chunks is incomplete. Keep networked worlds, untrusted executable hotloading, unbounded global regeneration and unrelated full replay work outside this issue.
Shared implementation and completion requirements
This is an implementation issue in the owner-approved GEN-003–007 programme. Preserve the existing GEN-001/002 contracts unless an intentional, versioned change is documented and tested. Keep routine world design declarative; registered native modules remain trusted, versioned extensions. Separate semantic planning, rasterization, live World admission, and presentation.
Before coding, reconcile current main, relevant open work, AGENTS.md, the development handover, roadmap, and subsystem contracts. Preserve unrelated material, actor, depth, ownership, dependency-pin and CI-provider work. Use the repository's GitHub-hosted validation policy. Run focused tests while iterating; complete applicable exact-head documentation/provenance, native, GDExtension/Godot and scoped apparatus gates before implementation acceptance. Source-sensitive native changes require source-matched Linux/Windows runtime publication and provenance under the current repository rules. Required skips or script errors do not count as passes.
Update the canonical subsystem/ownership/interface/configuration/roadmap documents and affected RAG indexes/retrieval questions together. Retain dated source/runtime/platform evidence, reproducible commands, relevant failure controls and explicit limitations. Record recoverable checkpoints in the implementation PR. Close this issue only when its required deliverables and acceptance gates are satisfied; staged PRs do not silently remove requirements.
