Does a function exist to convert a BVH into a webGPU compatible storage array data that could be uploaded to the GPU so that it could be queried inside a compute shader?
I'm not aware of a tool that can be used directly for this. A BVH can be very individual.
Do I understand this correctly? Do you want to store the vertex positions of A and B in a buffer and then use these vertex positions to perform your distance calculations in a compute shader?
You can change areas of a buffer at any time on the CPU side and load only these changed areas collectively into the GPU in one update. This is very efficient. This is a big advantage over data textures, where the entire texture always has to be updated. This means you can selectively update buffers on both the CPU and GPU sides.

@Spiri0 - the BVH is already stored in a flat buffer. The complicated part in WebGL was transforming the data (BVH and geometry) into a format that could be represented with texture formats since different portions of the BVH buffer use different memory layouts (floats for box definitions, uint16s for triangle offsets, etc. It could use some better documentation inline but the structure should look like so:
```
boundingBoxMin: float[3]
boundingBoxMax: float[3]

// if not leaf
rightChildPointer: uint32
splitAxis: uint32

// if leaf
triangleOffset: uint32
triangleCount: uint16
isLeafNode: uint16
```
It's possible the buffer could be uploaded and used directly, as-is, and accessed as an array of structs. In practice this should be significantly more simple than performing raycasting in a fragment shader with textures but I'm not familiar with WebGPU compute shaders, yet.

@GavinLobo Your struct and the associated buffer look like this. This compute shader currently doesn't do anything at the moment except access the individual elements during execution.
```
const BVHNodeStruct = struct( {
	bboxMin: 'vec3',
	count: 'uint',
	bboxMax: 'vec3',
	leftFirst: 'uint',
}, 'BVHNode' );


const size = 2 ** 18;
const BVH_StructSize = 16;
const BVH_Buffer = new THREE.StorageBufferAttribute( new Float32Array( size * BVH_StructSize ), BVH_StructSize );



const compute_BVH_shader = wgslFn(`
	fn compute(
		bvh_nodes: ptr<storage, array<BVHNode>, read>,
		index: u32
	) -> void {

		let bboxMin = bvh_nodes[ index ].bboxMin;
		let count = bvh_nodes[ index ].count;
		let bboxMax = bvh_nodes[ index ].bboxMax;
		let leftFirst = bvh_nodes[ index ].leftFirst;

	}
`);


const computeShaderParams = {
	bvh_nodes: storage( BVH_Buffer, BVHNodeStruct, BVH_Buffer.count ).toReadOnly(),
	index: instanceIndex,
}

const computeShader = compute_BVH_shader( computeShaderParams ).compute( size );

renderer.compute( computeShader );
```
This only runs with three.webgpu.js. Three.webgpu.js is not the same as three.module.js.
Three.webgpu.js is a standalone threejs, so there are two threejs, one for WebGL and one for WebGPU.
The buffer does not have to be initialized empty, I can also assign the data directly to it when creating it.
