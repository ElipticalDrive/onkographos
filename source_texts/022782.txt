Les ressources R-nerf, R-spark, R-imm, R-tvm couvrent directement cette lacune. Le geste fondateur NeRF (2003.08934) est la brique 1 ; les Gaussian Splats (R-spark, Spark + 3D Gaussian Splatting paper 2023) sont la brique 2 (état de l'art actuel pour view synthesis temps réel) ; IMM (2503.07565) et TVM (2511.19797) ferment la boucle « génération sans diffusion » qui peut être enseignée avant les modèles plus lourds.
2. ML foundations — le pont spectral
R-ffn et R-learnit sont des fondations que les notebooks ML actuels (3.0, 3.2, 3.6) survolent :
Spectral bias des MLP (R-ffn §3) : la découverte qu'un MLP standard ne peut pas apprendre de hautes fréquences en basse dimension est absente de notre série. C'est pourtant la raison pour laquelle NeRF a besoin de positional encoding, et la raison pour laquelle les Transformers utilisent RoPE / ALiBi / sinusoidales (cf. [ML/DeepLearning] Variantes Transformer modernes from scratch : ViT, Decoder-Only, GQA #16058).
Meta-learning d'initialisations (R-learnit) : la technique learn an init, then fine-tune per signal est une brique fondamentale pour traiter des tâches à instance unique (NeRF, optimisation d'un réseau par scène) — c'est un pont direct avec la série In-Context Learning (GenEFT : théorie effective de la généralisation — statique et dynamique #16743 GenEFT) et la série Fourier.
FGD-adaptatif (R-fgd) : la descente de gradient dans l'espace des fonctions, avec garanties de convergence, est l'outil mathématique qui sous-tend à la fois la paramétrisation NeRF et les méthodes variationnelles en neurosymbolique.
3. Neurosymbolique — la différentiation fonctionnelle
R-fgd est l'article le plus neurosymbolique du lot :
La preuve de convergence (smooth loss → stationary point ; smooth + Polyak-Lojasiewicz → global minimizer) rejoint directement la veine Lean ICT ([ICT] Cartographie de la tresse (Thom/Grothendieck/Schmidhuber/Friston) + hiérarchie de sobriété Dissociation→Score→Classe→Stack→Gerbe + deux ponts Conway #7738) : on peut formaliser en Lean 4 la convergence de FGD, comme contrepartie de la formalisation T11 GenEFT dans le Tegmark Epic (GenEFT : théorie effective de la généralisation — statique et dynamique #16743).
L'« adaptative representation » est l'analogue fonctionnel de l'attention adaptative dans les Transformers : choisir la base dans laquelle on optimise.
Pourquoi un origami et pas une simple liste d'issues
Ces ressources se déverrouillent en cascade : R-ffn est un pré-requis conceptuel pour R-nerf (spectral bias → positional encoding → NeRF), qui est un pré-requis pour R-spark (Gaussian splats héritent de NeRF), qui ouvre la voie à R-imm / R-tvm (génération sans diffusion dans un latent NeRF-like). R-learnit est transverse (méta-apprentissage applicable à chaque étape), et R-fgd est un approfondissement théorique qui peut être pioché indépendamment à la fin.

Pli 1 — R-ffn : Spectral bias & Fourier Features [ML foundations, socle]
Pré-requis théorique sans lequel R-nerf ne se comprend pas. Crée le vocabulaire (NTK, bandwidth, Fourier feature mapping) qui sera réutilisé dans R-nerf et R-learnit. S'insère naturellement dans MyIA.AI.Notebooks/ML/DataScienceWithAgents/03-DeepLearning/ à côté de 3.0 (théorie de l'information / Fourier) ou en extension d'un notebook sur les Transformers / positional encoding.
Livrable : notebook 3.x-Fourier-Features-Spectral-Bias.ipynb exécutable, avec :
Démonstration empirique : un MLP tanh échoue à fitter sin(20πx) sur [-1, 1] (spectral bias) — expérience en 20 lignes PyTorch, figure matplotlib.
Théorie NTK : la bande passante du kernel tangent est nulle aux hautes fréquences → démontre le biais.
Le mapping γ(x) = [cos(2πBx), sin(2πBx)] avec B ~ N(0, σ²) libère la bande passante : courbe d'apprentissage qui descend en 100× moins d'itérations.
Choix de σ : grid search sur un toy 2D image regression, montrer la transition « trop petit = spectral bias, trop grand = aliasing ».
Pont avec NeRF : le même mapping γ(x, y, z) → (cos, sin) à 5D est exactement ce que NeRF utilise.
Pont avec Transformers : la même intuition explique pourquoi positional encoding sinusoïdal (3.4) marche et pourquoi RoPE est nécessaire pour les longues séquences ([ML/DeepLearning] Variantes Transformer modernes from scratch : ViT, Decoder-Only, GQA #16058).
Verdict SOTA attendu : SOTA-OK (paper publié, code MIT, démo Colab disponible) ou RECOVERABLE-LOCAL (PyTorch + matplotlib suffisent, pas de GPU requis).
Ancrage corpus : bmild/nerf/tiny_nerf.ipynb et tancik/fourier-feature-networks/Demo.ipynb (lecture critique, pas fork).

Addendum R-gsplat (2026-09-30, user note : « nerfstudio-project/gsplat est plus récent pour la partie nerf »)
Suite à la remarque user en session du 2026-09-30, ajout d'une ressource manquante et révision du Pli 3 :
Nouvelle source
R-gsplat : nerfstudio-project/gsplat (repo)
Métadonnées mesurées le 2026-09-30 : 5 742 ⭐, 975 forks, Python + CUDA, Apache-2.0, dernière MAJ main 2026-09-30T08:20Z (jour même), topics gaussian-splatting, non archivé.
Description officielle : CUDA accelerated rasterization of gaussian splatting.
Rôle dans la distillation : c'est le binding CUDA de référence pour 3D Gaussian Splatting (3DGS, Kerbl et al. SIGGRAPH 2023). Il est maintenu par l'équipe Nerfstudio (UC Berkeley / Tyler Chang, Matthew Tancik co-auteur originel — convergence intéressante avec R-ffn / R-learnit, même écosystème).
Pourquoi c'est mieux que bmild/spark-physics pour la partie NeRF/3DGS : Spark/Three.js est une démo interactive navigateur (bon pour la lecture, mauvais pour la reproduction numérique). gsplat est la lib de calcul CUDA qu'on importe réellement dans un pipeline PyTorch — c'est elle qu'on enseigne, c'est elle qu'on profile, c'est elle qu'on optimise.
Distinction des rôles :
gsplat (nerfstudio) — lib de référence, optimisation 3DGS dans PyTorch, dtype forward/backward, INT8/FP8 quantization, batching distribué, intégration nerfstudio.
bmild/spark-physics — démo interactive, splats rendus dans Three.js + physique Rapier dans le browser. Lecture, pas calcul.
bmild/nerf — code original NeRF (TF1.15, pré-historique, à ne plus utiliser comme référence ; remplacé par nerfstudio/nerfstudio côté industrial et gsplat côté calcul).
Implication pour Pli 3 : la cible d'enseignement devient l'écosystème Nerfstudio + gsplat (Python/CUDA), pas Spark. Spark reste en annexe pour la dimension « démo navigateur / interaction », mais n'est plus le livrable principal.
