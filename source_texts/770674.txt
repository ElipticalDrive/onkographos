Thread-owned scan segments can recompute terminal results that are already available from the inter-warp totals scan. This PR reuses each segment’s inclusive total for its terminal value and applies the exclusive carry only to its earlier local prefixes. Register-resident and grouped inter-warp scans share prefix selection and segment completion helpers. Reverse scans preserve combiner operand order, and boundary combines remain guarded without requiring an identity.

This PR is stacked on #12308 (`keren/linear-layout-scan-tuple-barrier`). It includes terminal-only lane scans, consumer-requested register carries, and register placement for totals sequences of up to four elements. Layouts requiring intra-warp carry propagation retain exclusive-carry handling. Layout-conversion scratch allocation is unchanged from the parent PR.

Validation:
- `make` and targeted pre-commit checks passed.
- Four lit files passed: scan, reduction, conversion, and allocation.
- 279 GPU tests passed, including noncommutative scans, side-effectful boundary predicates, mixed-width tuples, and CTA ownership.
- All 90 benchmark reference checks passed on the candidate and main; neither recorded spills.

Performance was measured on physical GPU 2 (GB200), using `do_bench_cudagraph_proton`, against remote main `e6f4c919fb18a99ed08f1cf3713ae15c686790d3`. The original 74 cases have a geometric-mean runtime change of **−0.22% versus main**, which is approximately parity. The 16 additional multi-value cases improve **1.18% versus the preceding single-value implementation** and **1.09% versus main** in the full sweep.

Focused repeats show that 128×32 tuple sums with two-value segments improve **8.63% forward** and **4.51% reverse** versus the single-value implementation. The reverse 32×32 two-value tuple case regresses **1.49%** versus that implementation. Existing gaps remain against main, including **+4.43%** for the forward 32×32 one-value tuple scan and **+4.23%** for the forward 128×32 two-value integer sum. This draft retains those measured tradeoffs.

The earlier local full-scratch barrier experiment is excluded. It interacts favorably with terminal reuse in the forward 32×32 tuple case; its measurements are shown separately below so that baseline changes remain visible.

## Implementation

Register-resident and grouped inter-warp scans retain both the accumulator before combining a segment total (exclusive carry) and the accumulator afterward (inclusive total). Thread-owned segments copy the inclusive total to their terminal value and apply the exclusive carry to earlier local prefixes. One-value segments use only the inclusive total. Boundary predicates remain on combines; reverse scans preserve traversal and operand order.

`selectPrefix` and `completeThreadSegment` are shared by the two inter-warp paths. Layouts needing intra-warp carry propagation retain the existing exclusive-carry handling. The PR also includes the preceding terminal-only lane scan and register-resident consumer-carry changes needed by this implementation.
