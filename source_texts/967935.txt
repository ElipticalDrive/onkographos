Why
Rendering became very slow after a LUT was selected in the pipeline on the OpenCL and CUDA paths.
The suspected cause was a failed LUT cache that needed investigation and a fix.
Changes
Grade LUT pack
Design: Each grade execute asked for a freshly parsed cube file. The design now keeps one packed copy for each cube file version. A file stamp made of the file size and the last write time validates the cached copy. All three GPU backends share the same packed copy and the same content key.
Implementation: A mutex-guarded map keyed by the normalized path stores the file stamp and an immutable packed result. An unchanged file returns the stored instance after one stat check. The loader parses a changed file again and replaces the entry. The map keeps up to 16 entries and evicts the least recently used one. The packed result also carries its content key so callers do not hash the packed bytes again. The pack header includes the grade node model header directly in place of a forward declaration.
Grade executor LUT binding
Design: The backend passes take the content key from the packed LUT instead of hashing the packed voxels on each execute.
Implementation: The CUDA, OpenCL, and Metal grade passes read the key, the packed bytes, and the edge size from the shared packed result and pass them to the device LUT cache. A grade without a LUT path still binds the dummy LUT.
