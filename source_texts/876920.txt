I hope this isn't a complete duplicate - I did a search of the open and closed issues, and issue #4411 comes close to what I have in mind, but it's closed, but browser support for this has also changed since it was closed. Also only specifically looks at image-rendering: crisp-edges, which is not exactly the same thing.
Example use-case: we're using leaflet in our genomic data viewer to display a heatmap of gene expression of the full data matrix. Here is an old gif, from before we implemented the UI (and switched to a better color map):
GIF
Since each of those pixels represents an individual cell with a specific heat map value, they should remain square when zooming in far enough.
I've been using this tweak to the leaflet CSS with decent enough success for that, although I haven't thoroughly tested every possible browser:
```
/* Leaflet crispness override */
.leaflet-container .leaflet-overlay-pane svg,
.leaflet-container .leaflet-marker-pane img,
.leaflet-container .leaflet-shadow-pane img,
.leaflet-container .leaflet-tile-pane img,
.leaflet-container img.leaflet-image-layer {
  max-width: none !important;
  /* Preserve crisp pixels with scaled up images */
  image-rendering: optimizeSpeed;             /* Legal fallback */
  image-rendering: -moz-crisp-edges;          /* Firefox        */
  image-rendering: -o-crisp-edges;            /* Opera          */
  image-rendering: -webkit-optimize-contrast; /* Safari         */
  image-rendering: optimize-contrast;         /* CSS3 Proposed  */
  image-rendering: crisp-edges;               /* CSS4 Proposed  */
  image-rendering: pixelated;                 /* CSS4 Proposed  */
  -ms-interpolation-mode: nearest-neighbor;   /* IE8+           */
}
```
See also the support table in the image-rendering entry on MDN, and the page linked from there describing a canvas-based fall-back option

I think we can do a little more than nearest-neighbor -- pixel-art scaling algorithms could make sense for a good number of map tiles, especially those with CJK text. Take this example from amap (Chinese):
(for more, try https://wprd04.is.autonavi.com/appmaptile?style=7&x=54870&y=26789&z=16&lang=zh_cn)
Given the complexity of the writing system, the text rendering is basically pushing pixel-art boundaries. The lines are obviously aliasing at this point. If we borrow a page from the retro gaming people and use a little bit of hq2x (or maybe something simpler like 2xsai or EPX), we might just have a way to scale map tiles better than NN -- quite desirable for non-retina maps on retina screens, I might add.
