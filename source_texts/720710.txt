Introduces crates/sampler, a new workspace crate providing a Sampler
trait with two implementations:
SobolSampler backed by sobol_burley (Burley 2020 Owen-scrambled
Sobol), seeded per pixel via a PCG-style hash of (x, y, frame) so
neighbouring pixels get decorrelated sequences.
RngSampler fallback for tests.
Every per-ray random draw now routes through this sampler:
Material::scatter / scatter_importance take &mut dyn Sampler;
every impl (lambert, metal, dielectric, cook_torrance, disney,
emissive, blinn_phong, openpbr) rewired accordingly.
brdf::sample_vndf_ggx / sample_vndf_ggx_aniso_local take explicit
[f32; 2] uniforms instead of pulling their own random2().
Camera::get_ray takes an explicit lens_uv; DOF now uses a
concentric-disk warp instead of rejection sampling.
LightList::sample takes the sampler for its uniform light pick.
Volume free-flight and Henyey-Greenstein phase sampling in the tracer
consume dimensions from the sampler.
ray_color constructs a per-pixel Sobol sampler, calls
advance_bounce at each recursion (no-op today, hook for future
padded-Sobol reseeding), and threads it into every downstream call.
Deletes the old crates/crust-core/src/sampler.rs (per-hit-reallocated
4x4 CMJ grid — was reused across all NEE lights per bounce and thus
correlated their samples).
Adds explicit-sample warp helpers to utils::common
(cosine_hemisphere, uniform_sphere, uniform_ball,
concentric_disk) alongside the existing RNG-based variants, which
remain in use for scene generation in world.rs.
All 20 existing unit tests pass, plus 3 new tests covering Sobol
determinism, per-pixel decorrelation, and sample-interval bounds.

High-Level Assessment
The following are alternative approaches to this PR:
1. Keep RNG for most dimensions; use Sobol only for pixel jitter
➕ Much smaller API churn; fewer signature changes across materials/BRDFs
➕ Less risk of exceeding Sobol dimension budget in complex paths
➖ Leaves major variance sources (BRDF/phase/light sampling) on pure RNG
➖ Harder to get consistent decorrelation guarantees end-to-end
2. Sampler with typed dimension layout (e.g., per-bounce struct of named samples)
➕ Makes dimension usage explicit and stable (e.g., jitter/lens/light/bsdf)
➕ Easier to audit dimension count and avoid accidental reordering
➖ More boilerplate and larger refactor than the current trait approach
➖ Less flexible for materials that need variable numbers of dimensions
3. Implement padded-Sobol / per-bounce reseeding now
➕ Avoids the current dim % 256 wrap behavior in deep/complex paths
➕ More predictable convergence when dimension usage grows
➖ More complex sampling logic and more tuning needed
➖ Harder to validate correctness quickly without additional rendering/regression tests
Recommendation: The PR’s approach (a single Sampler trait threaded through all sampling sites) is the right architectural direction for consistent QMC and decorrelation. The main follow-up worth considering is moving from dim % 256 wrapping to a padded-Sobol or per-bounce reseeding scheme once real scenes approach the dimension limit; the existing advance_bounce() hook is a good forward-compatible seam.

### Issue description
`ray_color` samples the exponential free-flight distance using `-(sampler.next_1d().ln()) / sigma_t_max`, but the sampler contract allows returning `0.0` (range `[0,1)`). `ln(0.0)` produces `-inf`, which turns into an infinite travel distance and causes the code to incorrectly skip volume scattering for that sample.

### Issue Context
This is especially important for deterministic/QMC samplers where exact endpoint values (like 0.0) can occur reproducibly.

### Fix Focus Areas
- crates/crust-core/src/tracer.rs[203-218]

### Suggested fix
Use an open-interval uniform for the log/inversion step. For example:
- Prefer `u = 1.0 - sampler.next_1d()` (so `u` is in `(0,1]` when the sampler is in `[0,1)`), then clamp away from 0:
 - `let u = (1.0 - sampler.next_1d()).max(1e-7);`
 - `let t_scatter = -u.ln() / sigma_t_max;`
- Alternatively clamp the direct sample: `let u = sampler.next_1d().max(1e-7);` (but the `1-u` form maps the exact 0 endpoint to distance 0 instead of `inf`).

2. Sobol dimension aliasing 🐞 Bug ☼ Reliability
Description
```
SobolSampler::next_1d silently wraps Sobol dimensions via d % 256, so after 256 1D draws within
a single pixel/sample, it reuses low dimensions again. The tracer consumes sampler dimensions across
recursive bounces and per-light sampling; with deep paths this can exceed 256 draws and reintroduce
strong correlation/structured artifacts instead of switching to a true fallback when the dimension
budget is exhausted.
```
Code
crates/sampler/src/lib.rs[R99-108]
```
+    fn next_1d(&mut self) -> f32 {
+        let d = self.dim;
+        self.dim = self.dim.wrapping_add(1);
+        // sobol_burley caps at `NUM_DIMENSIONS` (256). Wrap gracefully once
+        // we exceed that — very high dimensions get low-discrepancy-lite
+        // behaviour rather than a panic; callers should not exceed the
+        // budget in normal renders, but shallow-bounce heavy paths can.
+        let dim = d % sobol_burley::NUM_DIMENSIONS as u32;
+        sobol_burley::sample(self.sample_idx, dim, self.pixel_seed)
+    }
```

```
The sampler explicitly aliases dimensions after 256 via modulo. The tracer consumes dimensions
repeatedly across recursive bounces and also inside the per-light direct-lighting loop, and default
settings allow deep recursion, making it possible to exceed 256 1D draws within one path.

The issue below was found during a code review. Follow the provided context and guidance below and implement a solution

### Issue description
`SobolSampler::next_1d` wraps the Sobol dimension index modulo `sobol_burley::NUM_DIMENSIONS` (256). Once a path consumes more than 256 1D samples within a single pixel/sample, the sampler reuses earlier dimensions, which can reintroduce correlation and structured artifacts.

### Issue Context
The tracer consumes multiple sampler dimensions per bounce (per-light `next_2d()` and `scatter_importance(..., sampler)` inside the light loop, plus an additional `scatter_importance` for the indirect bounce). With sufficiently deep paths (e.g., the default max depth is 32), exceeding 256 1D draws is possible.

### Fix Focus Areas
- crates/sampler/src/lib.rs[99-117]
- crates/crust-core/src/tracer.rs[181-195]
- crates/crust-core/src/tracer.rs[233-260]

### Suggested fix
Implement a real “dimension overflow” policy instead of modulo aliasing:
1. **Deterministic fallback RNG after 256 dims**:
  - Keep the Sobol stream for `dim < NUM_DIMENSIONS`.
  - For `dim >= NUM_DIMENSIONS`, generate a deterministic pseudorandom float from a hash of `(pixel_seed, sample_idx, dim)` (or embed a `SmallRng` seeded in `start_pixel/start_sample`) and return that.
  - This preserves determinism and avoids repeating low Sobol dimensions.

2. **Use `advance_bounce()` to partition dimensions**:
  - Track bounce index and reseed/scramble per bounce (or implement padded-Sobol) so each bounce gets a fresh 0..256 window.

Also consider reducing unnecessary sampler consumption in direct lighting: the current loop calls `scatter_importance` per light, which samples a new BRDF direction even though direct lighting needs BRDF evaluation/PDF for the *light direction* (this extra sampling burns dimensions and pushes you toward overflow sooner).
```
