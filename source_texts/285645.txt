Validate strut spacing before modulo operations
The strut infill path uses x % spacing/y % spacing/z % spacing without checking that spacing is finite and strictly positive, so inputs like --infill-strut 0,0.4 (or negative/NaN spacing via API) produce NaN intermediates and force all on_* tests to false, silently dropping essentially all interior voxels. This yields empty or badly corrupted volumes instead of a clear user error, so these parameters should be validated before the modulo math runs.

Require integer label IDs before assigning label_sphere
label_sphere parses the label ID as f64 and then casts with as u32, which silently truncates/saturates (3.9 becomes 3, negatives become 0, very large values clamp), so a malformed CLI value can silently relabel particles to the wrong class. Because label IDs are semantic identifiers, this should reject non-integer/out-of-range values rather than coercing them.
