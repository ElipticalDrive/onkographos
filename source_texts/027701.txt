# Segment-Based Tetrahedral Meshing and Rendering

Ralf Sondershaus∗ WSI / GRIS, University of Tubingen ¨

Wolfgang Straßer WSI / GRIS, University of Tubingen ¨

### Abstract



We present a meshing and rendering framework for large unstructured tetrahedral meshes which is based on a collection of segments that form a multi resolution model. Each segment contains several thousand tetrahedra and covers either a part of the original tetrahedral mesh or a simplified version of the mesh. The mesh can be adapted locally at run time to viewing and classification parameters by replacing segments with other segments. Dependencies between segments are stored in a hierarchical graph and ensure a consistent mesh at any time. So, we extend the concept of multi-triangulations from triangle meshes to tetrahedral meshes and show how hierarchical segments can be constructed easily for huge tetrahedral meshes.

The segments are stored in a simple, but efficient compressed format which not only saves disc space but also allows for an easy calculation of the incidency information between segments at decompression time. A visualization system exploits the multitriangulation to increase the interactivity of direct volume rendering, isosurface extraction and vector field visualization such that large meshes can be explored on standard PCs.

## 1 Introduction

Unstructured tetrahedral meshes are often used as finite element meshes that discretize a volumetric domain for scientific simulations like computational fluid dynamics (CFD). Modern simulation environments typically use meshes that contain millions of tetrahedra.

The simulations carry data along with a tetrahedral mesh. The data values are usually scalar values like temperature or pressure, or vector values like velocity, and can be attached to the vertices, edges, border faces or to the tetrahedra.

The emerging need to visualize simulation data has introduced tetrahedral meshes to volume visualization. Typically, scalar values are visualized by direct volume renderers or by isosurfaces whereas vector values are shown as streamlines or texture advected images.

Although modern algorithms can process several million tetrahedra per second for both direct volume rendering [Kraus et al. 2004] and

isosurface extraction [Kipfer and Westermann 2005], it is beneficial to store the mesh as a multi resolution model in order to increase interactivity and to decrease consumpted memory space. Especially for huge meshes like the Earthquake dataset of figure 1 which contains more than 13 million tetrahedra, multi resolution models are an important tool to adapt the complexity of those meshes and enable interactive visualizations without loss of visual quality.

Many previously published multi-resolution models steer the complexity of a mesh by edge collapses and vertex splits which coarsen and refine the mesh. The collapses (and splits) are normally precomputed and stored in a binary vertex hierarchy. At run time this hierarchy is traversed and some of the precomputed collapses and splits are performed to adapt the mesh to viewing or classification parameters. But for large meshes that contain hundreds of thousands of points this update can become time-consuming even if priority queues are used.

Additionally, these vertex-based multi-resolution models do not work efficiently with GPUs. Many modern GPU-based rendering techniques load the mesh into the memory of the GPU and run vertex and fragment shaders on it [Kipfer and Westermann 2005]. Because vertex-based models store the mesh in core memory and adapt it on the CPU, the whole mesh needs to be tranferred onto the GPU even if only a small part of the mesh has been changed.

Multi resolution models that work with segments instead of vertices have proven their efficiency for huge triangle meshes [Yoon et al. 2004]. Segments consist of parts of the mesh and contain typically hundreds of points and triangles. The mesh can be coarsened by replacing segments with segments that contain simplified parts of the mesh. Conversely, the mesh can be refined by replacing segments with segments that contain higher resolution parts of the mesh. The models differ in how the segments are created from the mesh and how the consistency of the mesh is ensured. A mesh is consistent if it does not contain any cracks or intersecting tetrahedra, i.e. neighboring segments must match exactly along their borders.

Because the segments can be treated independently of each other, they can be efficiently processed by the GPU. However, meshes that are adapted by segment-based models tend to contain more triangles than meshes that are adapted by vertex-based models. But the adaptation of the mesh can be performed rapidly which makes these models very efficient for huge meshes.

Contributions. We use a multi triangulation as multi-resolution data structure which ensures a high-quality simplified mesh because the tetrahedral simplifier is only restricted to leave the borders between segments unchanged. We iterate several times over the mesh where each iteration produces a simplified version of the mesh of its previous iteration. We change the kind of segmentation from one iteration to the next by a simple rotation of the mesh which can be computed very easily by just a vector-matrix multiplication. Furthermore, our segments are compact and balanced (as much as possible) such that every segment contains a similar number of tetrahedra which supports the memory management of the operating system.

The segments of the mesh do not only form an efficient multiresolution data structure but enable the simplifier to process the mesh segment-wise which can be easily implemented out-of-core. So, the memory needs are decreased drastically and large meshes can be handled efficiently.

Because the segments are stored on disc as tetrahedral meshes, the file sizes of multi-triangulations can become large. For instance, the file of the Earthquake dataset grows to 1.2 GB. These large file sizes are mainly caused by the connectivity information of a mesh which exceeds the geometry information by a factor of about 6 for typical tetrahedral meshes [Gumhold et al. 1999]. We introduce a compression scheme that encodes the connectivity information and additionally allows for restoring the adjacency information between tetrahedra of different segments. Furthermore, the compression scheme leaves the vertex ordering (and thus the so-called mesh layout) unchanged. It encodes the vertex indices as they are given in the tetrahedral mesh. So, any mesh layout that has been precomputed for the mesh is restored.

We embed the multi triangulation into a visualization system that supports direct volume rendering (projected tetrahedra), isosurfaces, and vector field visualization (stream lines). The adaptation of the mesh is steered by a maximal attribute error that is given by the user. Because the segments themselves are tetrahedral meshes and can be processed independently of each other, any existing visualization system (or even simulation system) can be extended easily to support our multi-resolution model by a simple iteration over all segments that the adapted mesh consists of.

## 2 Related Work

Tetrahedral Simplification. Among the numerous algorithms that have been developed to simplify tetrahedral meshes [Kraus and Ertl 2000; Cignoni et al. 2000; Chopra and Meyer 2002; Chiang and Lu 2003], the edge collapse based algorithms are the most effective ones. Edges are iteratively collapsed where each edge has a cost assigned to it and the edge with the lowest cost is collapsed. The most popular approaches include progressive meshes [Popovic and Hoppe 1997], quadric error metrics [Garland and Zhou 2005], and streaming simplification [Vo et al. 2005].

Tetrahedral Multi Resolution Models. Many multi resolution representations [Cignoni et al. 2003; Danovaro et al. 2005] have been proposed for tetrahedral meshes that work with a binary vertex hierarchy. As mentioned in the introduction, these approaches work well for medium-sized meshes but often fail to work efficiently for huge meshes because of the sheer size of the hierarchy. [Cignoni et al. 2004a] give an overview to multi resolution representations of tetrahedral meshes. Out–of–Core data structures [Danovaro et al. 2005] can be combined with the multi-resolution techniques to render large models.

[Sondershaus and Straßer 2006] introduced recently a segmentbased algorithm that constructs a binary hierarchy of segments by merging pairs of segments into new segments which are simplified. The boundaries of the segments are left unchanged and form a special segment that handles the updates of the incidendy information between neighboring segments. Note that leaving the borders between segments unchanged strongly the quality of the simplification.

Surface Multi Resolution Models. Recently, several algorithms have been published that use segment-based hierarchies to render huge polygonal models interactively [Cignoni et al. 2004c; Yoon et al. 2004; Cignoni et al. 2005]. They can be further optimized by taking special vertex orderings into account that consider the cache behaviour of modern memory hierarchies [Yoon et al. 2005].

One of the fastest algorithms exploits the concepts of multi triangulations [Cignoni et al. 2005] which is described detailled in the following section because our multi resolution data structure is basically a multi triangulation.

Volume Rendering. A standard technique for direct volume rendering of unstuctured tetrahedral meshes is the projected tetrahedra algorithm of [Shirley and Tuchman 1990] that has been greatly enhanced by the pre-integration technique of [Max et al. 1990; Kraus et al. 2004]. For isosurface extraction, several GPU based algorithms have been proposed [Kipfer and Westermann 2005] that load the mesh onto the GPU and run fragment shaders to compute the isosurface. For vector field visualization, stream lines are computed and rendered using different rendering modes [Mallo et al. 2005]. The rendering of a lot of stream lines usually leads to severe occlusion problems which has only be partially been adressed in literature yet.

### 3 Multi Triangulations for Tetrahedral Meshes

We review the basics of multi-triangulations before we describe how a tetrahedral mesh is partitioned into balanced as well as compact segments and how our particular multi-triangulation is constructed from these partitions.

### 3.1 Basic Multi Triangulations

Multi Triangulations are a powerful tool to build multi resolution representations of simplicial complexes [Klein and Gumhold 1998; Puppo 1996]. [Cignoni et al. 2005] extended them to not only support simplicial complexes but also parametric surfaces or point clouds, and applied them to render huge polygonal models interactively. This section gives a brief overview of how multi triangulations for simplicial complexes work.

Given an input mesh (triangular or tetrahedral), a multi triangulation is built by a sequence of partitions Π1,Π2,...,Π*n* of the mesh. Each partition Π*i* divides the mesh into a number of segments Sk i , k = 1,...,|Π*i*| that may only overlap at their boundaries as shown in figure 2 (left). We assume that the segments cover the whole mesh.



Figure 2: A 2D example. (Left) The multi triangulation is constructed by a sequence of partitions Π*i*. Each partition consists of segments Sj i that cover the whole mesh. The segments between two consecutive partitions are cut to form the patches Pj,k i . (Right) A directed acyclic graph (DAG) describes the dependencies between the segments. The resulting segmentations of three different cuts through the DAG are shown. Note that the segment S*1 *i+1 may not be subdivided anymore in the third cut without additional subdivisions of its parent S*1 *i+2. Otherwise, the patch P*1,1 *i+1 would overlap the segment S*1 *i+2.

A multi triangulation consists now of patches Pj,k i which are defined as cuts between the segments of two consecutive partitions Π*i* and Π*i*+1:

$$\Pi_i \cap \Pi_{i+1} = \bigcup_{j \in 1 \dots |\Pi_i|, k \in 1 \dots |\Pi_{i+1}|} (S_i^j \cap S_{i+1}^k) \\ = \bigcup_{j \in 1 \dots |\Pi_i|, k \in 1 \dots |\Pi_{i+1}|} P_i^{j,k}.$$

A directed acyclic graph (DAG) describes which segments cut each other. The nodes of the DAG are the segments Sj i while all patches Pj,k i define the directed edges. Thereby, an edge exists between a so-called ceiling segment Sj i+1 and a floor segment Sk i if both segments overlap.

A consistent mesh is assembled by a list of patches that do not overlap (except on their boundaries) and cover the whole mesh. It can be expressed as a list of edges in the DAG, i.e. by a graph cut. Because the patches may not overlap, every path from the roots to the leaves must contain at most one cut edge. In order for the patches to cover the whole mesh, every path from the roots to the leaves must contain at least one cut edge. Combining both, every path must contain exactly one cut edge.

A segment Sk i+1 can be replaced by all patches Pj,k i , j = 1,...,|Π*i*|, that have this segment as ceiling segment:

$$S_{i+1}^j \leftarrow \bigcup_{j \in 1..|\Pi_i|} (S_i^j \cap S_{i+1}^j) = \bigcup_{j \in 1..|\Pi_i|} P_i^{j,k} \quad (1)$$

On the other hand, if all patches Pj,k i , j = 1,...,|Π*i*|, are on the graph cut, they can be replaced by their ceiling segment Sk i+1 as shown in figure 2 (right).

This concept works for a sequence of partitions that was constructed for just one mesh as well as for a sequence of partitions that is constructed by consecutively simplified versions of the mesh as described next.

The partitions are constructed iteratively starting at a partition Π0 of the full-resolution mesh. Given a partition Π*i*, we construct its consecutive partition Π*i*+1 as follows. The vertices and tetrahedra of the segments Sj i in Π*i* are distributed to the consecutive partition Π*i*+1 resulting in segments Sk i+1. These segments are simplified whereby their borders are left unchanged. Afterwards, the iteration continues and the next partition Π*i*+2 is constructed from Π*i*+1.

Because the borders of the simplified segments of one partition are left unchanged, the vertices and tetrahedral faces (triangles) on these cross-segment borders are contained in both the partition Π*i* and its consecutive (simplified) partition Π*i*+1. So, the refinement and coarsening operations of (1) can be performed and the constructed multi-triangulation forms a valid multi-resolution model.

### 3.2 Partitioning a Tetrahedral Mesh

The density of points inside a tetrahedral mesh can vary significantly especially if the mesh is used for CFD simulations (see colorplates). We choose an octree as space partitioning scheme because its leaves reflect the density distribution of the points. The octree creation is steered by the number of vertices that a leaf can maximally contain. If this maximal number is exceeded, the leaf is subdivided at its center. The leaves of the octree are compact boxes that could be used as compact segments. Nevertheless, the number of points that are sorted into the leaves varies strongly due to the great variation of the point density.

In order to balance the segments, we merge the leaves of the octree. The leaves of the octree are nodes in an undirected graph whose edges describe the neighborhood between the leaves. The graph contains an edge between two leaves if they are neighbors (i.e. their boxes are neighbors in the octree) and if their volumes do not differ by a factor of more than 2. We call a graph partitioning algorithm (we use Metis 4.0) to find a partition of the graph. Every part of this partition consists of a number of leaves of the octree and forms a segment. Until now, only the vertices have been segmented. In order to segment the tetrahedra, we iterate over all tetrahedra and for every tetrahedron, we consider the segment indices of all its four vertices and assign it to the segment with the smallest index. We do not need to compute the center of the tetrahedron (as it is done by [Cignoni et al. 2003; Gumhold and Isenburg 2003]) and still create well-shaped boundaries between segments that are sufficient for the purposes of multi-triangulations.

#### 3.3 Sequence of partitions

We need to design a sequence of partitions that creates balanced and well-shaped patches. Additionally, the border of a segment of one partition must be mostly contained in the segments of its consecutive partition because the simplification leaves the borders of segments unchanged. So, border vertices that have been left unchanged in one partition will be simplified in the consecutive partition.

Inspired by the bintree hierarchy [Duchaineau et al. 1997] and √ 2 subdivisions, we construct the sequence of partitions iteratively by rotating the segmenting octree from one partition to the next. The iteration starts with partition Π0 of the original mesh M = *M*0 and works as follows.

Given a partition Π*i* and its mesh Mi, the subsequent partition Π*i*+1 is found by rotating Mi whenever i is odd and constructing the partition of the rotated mesh as described in the previous section. When i is even, the partition is constructed with the non-rotated mesh.

Next, the cuts that describe the DAG between partitions Π*i* and Π*i*+1 are computed by looking at how the tetrahedra of the floor segments Sj i spread over the ceiling segments Sk i+1. The segments of partition Π*i*+1 are simplified (leaving their borders unchanged) which results in the approximated mesh Mi+1 of the mesh Mi.

The rotation is chosen to include as many borders of the segments into the segments of the consecutive partition. We use a heuristic that is experimentally varified. The mesh is rotated by an angle of 45 degrees around the axis a which is chosen such that the mesh is rotated around the two shortest axis of its bounding box as shown in figure 4. The center of rotation is the centroid of all vertices.

Note that the fixed border is the only restriction of our simplifier. In contrast to [Sondershaus and Straßer 2006; Yoon et al. 2004] we do not overrestrict the simplifier or need to decide when the borders shall be simplified. Based on the selection of the partitions, the border elements that are left unchanged in the simplification of one partition are simplified automatically in the consecutive partition.

It is important that the leaves of the octree are merged. Otherwise (if, for instance, a simple √ 2-subdivision would be used), the segments as well as the patches are highly un-balanced and would produce a large number of patches with few vertices and tetrahedra. A

### 4 Compression

We store the segments one after the other in a single binary file. For every segment, we store its patches in any order. Because every patch stores its tetrahedral mesh, the file size can become large and we implemented a compression scheme that encodes the meshes of the patches and still supports the multi-triangulation with all its coarsening and refinement operations.

The cut-border machine [Gumhold et al. 1999] is a well-known compression scheme for tetrahedral (and triangle) meshes that achieves good compression ratios and performs very fast. But the cut-border machine treats the tetrahedral mesh as a non-segmented mesh and cannot restore adjacency information between segments as it is needed by the multi-triangulation. Additionally, it changes the order of the vertices during encoding, i.e. each vertex gets a new index. So, a pre-computed mesh layout is destroyed and replaced by the mesh layout that the encoder introduces. Recent works [Yoon et al. 2005] have shown that a well-computed mesh layout can drastically improve the rendering performance.

We extend the cut-border machine to support cross-segment incidencies and to respect any mesh-layout. We will shortly describe the principles of the cut-border machine for tetrahedral meshes followed by a description of our extensions.

#### 4.1 Basic Cut-Border Machine

The cut-border machine (CBM) is a region-growing compression scheme which starts at an arbitrary tetrahedron. The border of the region is called cut-border and divides the mesh into an inner part and an outer part which contain the already encoded tetrahedra and the still-to-be-encoded tetrahedra, respectively. The cut-border is a (sometimes non-manifold) triangle mesh that consists of faces of the tetrahedra. Tetrahedra are added to the inner part at a specific triangle face which is called the gate. After a tetrahedron has been added to the inner part, the cut-border is adapted to include the new tetrahedron and the gate is relocated to another face on the cutborder. The CBM stops when the outer part is empty, i.e. when all tetrahedra are encoded.

When a tetrahedron is added to the inner part, three of its vertices are determined by the gate while one vertex is free. Three basic cases describe how this free vertex can be located with respect to the gate: (1) the gate can be a border (there is no tetrahedron and thus no free vertex), (2) the free vertex is already on the cut-border, or (3) the free vertex is not on the cut-border and is hence a new vertex. Basically, the encoder determines which of the three cases applies to the current tetrahedron at the gate and encodes the case as a symbol. In order to achieve good compression ratios, case (2) is subdivided into several sub-cases as shown in figure 5: Flip, Top, Close, and Join. The mesh is traversed and tetrahedra are added

The new vertex (black circle) together with the gate forms the new tetrahedron. The Flip is a Flip1 operation because the new tetrahedron is created by (something like) a flip of edge 1 of the gate.

to the inner region which creates a stream of symbols that is arithmetically encoded. The geometry of the vertices may be interleaved with the stream of symbols or may be encoded in a single block. So, the vertices are encoded in the order of their appearance due to the traversal order. The traversal order is chosen such that the vertices are inserted into a fifo buffer in the order of their appearance starting with the four vertices of the first tetrahedron. The first vertex of the fifo is fixed and all its incident tetrahedra are traversed and encoded (or decoded). Then, the next vertex of the fifo is fixed and processed.

Each triangle of the cut-border mesh stores its three edgeneighbors. As long as the cut-border is manifold, this neighboring information can be easily updated during the traversal. But the subcases Flip and Join can introduce non-manifold edges which need to be detected. The edge-neighbors must be set correctly even for non-manifold edges. [Gumhold et al. 1999] propose a data structure that stores for each vertex of the cut-border a set of all its incident triangles. To detect a non-manifold edge, the sets of both end vertices of the edge are cut. If the cut is not empty, the edge is already in the cut-border and the edge-neighbors of the newly added triangles are adapted correctly using either the geometry information (if known) or the (possibly) encoded triangle indices.

#### 4.2 Cut-Border Machine for Multi Resolution Meshes

Our multi triangulation consists of segments each of which has several patches. We encode the segments one after another and for each segment we encode its patches one after another. The basic entity that we compress is the tetrahedral mesh of a patch.

Basically, the vertices are enumerated segment-wise. Vertices that lie on segment boundaries (i.e. tetrahedra of different segments reference the vertex) are copied in each segment. So, the tetrahedra of a segment always reference points whose geometry is also stored in the segment. For every such border vertex, an additional index is stored that is unique for all segments of the multi-resolution mesh. So, a vertex can be identified uniquely although it might have several copies in different segments.

We start with an arbitrary tetrahedron of a patch and grow the region that is bounded by the cut-border. Every time when a tetrahedron is added to the inner part, an opcode describes the position relative to the cut-border. We have a total of 11 opcodes that fully determine all possible positions.

- Border (B): the gate is a border of the (whole) tetrahedral mesh.
- The free vertex has not been visited yet.
  - New Shared Vertex (S): The free vertex lies on a border between patches or segments (i.e. there are tetrahedra of different segments or patches that share this vertex).
  - New Vertex (N): The free vertex is not on a border between segments or patches.
- The free vertex has been visited yet.
  - Flipi (F*i*): The free vertex is incident to exactly one adjacent triangle of the gate. i determines which of the three adjacent triangles has the free vertex in common.
  - Topi (T*i*): The free vertex is incident to exactly two adjacent triangles of the gate. i determines which of the three adjacent triangles is not incident to the free vertex.
  - Close (C): The free vertex is incident to all three adjacent triangles of the gate.
  - Join (J): The free vertex is incident to none of the adjacent triangles of the gate.

The N, S, and J operations get the index of the new vertex as parameter. The index of the new vertex can be encoded with at least log(n) bits where n is the number of vertices of the segment. For performance reasons, we encode the index always with 16 bits. Note that T*i* and F*i* do not need this parameter because the free vertex is located at an edge-incident triangle of the gate which is fully determined by the index i. The S operation needs an additional parameter which describes the unique index of this shared vertex and is encoded with additional 32 bits (theoretically, we would need at most log(m) bits where m is the number of vertices of whole multi resolution mesh). As example, the connectivity of a cube that is subdivided into 6 tetrahedra could be represented as 0236BBBN1BBN4BN7BN5BBTBB. The first four vertices define the first tetrahedron. We store the opcodes as 4-bit-words and did not implement arithemtic coding because the reduction of the file sizes was sufficient for our purposes. But of course the compression ratios could be additionally improved by an arithmetic coder.

In contrast to [Gumhold et al. 1999] we detect non-manifold edges with a hash map that stores for every edge of the cut border all its incident triangles. An edge is uniquely defined by both its end vertex indices. So, we avoid the cut of two sets of triangles and can immediatly lookup which triangles are incident to an edge. We only allow non-manifold edges that are incident to four triangles. If the encoder detects a non-manifold edge that is incident to more than four triangles, it outputs a Skip symbol (increasing the number of symbols to 12), discards the current gate and proceeds to the next gate without doeing any action. Note that if four triangles are incident to an edge, the adjacency information is uniquely defined by the order of the vertices in the triangles and no geometry tests must be performed which easies the implementation a lot but decreases the compression ratio.

The traversal order is crucial for the efficiency of the algorithm. We follow [Gumhold et al. 1999] and traverse the mesh point-wise starting with the four points of the first tetrahedron.

The decoder traverses the stream and constructs the mesh based on the arrival of the opcodes. Because we distinguish between in-patch vertices (opcode N) and shared vertices (opcode S) we can reconstruct each of the four face-incidencies of a decoded tetrahedron as follows. If all three vertices of a face are shared vertices, it must be a cross-patch (or cross-segment) face. Otherwise, the face is an in-patch face. Two hash maps store pairs of triangles which represent the face-incidencies. One hash map handles in-patch faceincidencies while the other hash map handles cross-patch incidencies. An in-patch face registers to its in-patch hash map. If their is no triangle registered yet, it stores its own face incidency information. If there is a triangle already, the face-incidency information is updated for both the stored face and the own face and the hash entry can be deleted.

A cross-patch face looks up the cross-patch hash map with the triangle that is formed by the unique indices. If there is no triangle registered yet, the face inserts itself into the hash map. If there is just one face registered yet, the face updates its incidency using the stored face and stores itself as second face into the hash map. If there are already two faces stored, the patch must have replaced a different patch by a coarsening or refinement operation. This other patch must either consist to the ceiling or floor segment. So, this patch can be identified and its according face in the hash map which can be replaced with the current face.

The geometry and attribute values are stored in a single table per segment. Note that our scheme also supports a compression that does not respect the mesh layout. The opcode N would get no parameter and the vertices are enumerated in the order of arrival. The incidency information could be restored by the unique index of opcode S.

### 5 View-dependent Rendering

We integrated the multi triangulation into a visualization system that supports interactive direct volume renderings, isosurface extraction and vector field visualization. We first describe how the mesh can be adapted followed by the particular visualization techniques.

#### 5.1 Updating the cut

As described in section 3.1, a consistent mesh is represented by a graph cut through the DAG. Moving this cut down refines the mesh while moving it up coarsens the mesh. The cut may not be moved freely but needs to fulfill the conditions for a consistent mesh as shown in figure 2.

The edges of the cut represent patches, so we represent the cut as a list of active patches. A patch is refined by activating all outgoing patches of its floor segment whereby the graph cut moves down and the patch itself is deactivated. But in order to get a consistent mesh, every path from the roots to the leaves must contain exactly one active patch. So, a patch can be refined only if all its ceiling segments do not have active patches that precede the ceiling segment on the way from the roots to the segment. If there are such active preceding patches, they must be forced to refine. Otherwise, patches would overlap and the mesh is not consistent.

A patch can be coarsened and replaced by all incoming patches of its ceiling segment if all its siblings (i.e. all outgoing patches of the ceiling segment) are active. If they are not, the patch cannot be coarsened.

Two queues maintain the cut, a coarsening queue and a refinement queue [Cignoni et al. 2004b]. The refinement queue contains all patches that are active and can be refined by activating all patches of their floor segments. The coarsening queue contains all patches that can be activated because all of their siblings are active. After each refinement or coarsening, the queues are updated. The queues are sorted by an error value that is precomputed and stored with each segment. The kind of the error value depends on the rendering technique and is described in the following sections.

We first try to coarsen as many patches as possible and refine afterwards as many patches as necessary. The user can specify the number of tetrahedra that the adapted mesh can maximally contain. A refinement is performed only if the so-refined mesh does not contain more tetrahedra than the given maximal number (including the tetrahedra that are created by forced refinements).

We choose a simple but effective caching scheme to keep track of the patches in the core memory. First of all, only complete segments are loaded or discarded. Second, a segment is discarded only if all its incoming and outgoing patches are deactive.

### 5.2 Direct Volume Rendering

We normalize all scalar attribute values of the mesh to the unit interval [0,1]. Every segment stores an error histogram H for every attribute channel. H contains for each of its attribute slots the largest error within the segment, measured to the original tetrahedral mesh. These errors increase from the leaves of the DAG to the roots.

The attribute error of a segment is weighted by the (user-chosen) classification. Assuming that the classified opacity is stored in a lookup-table C of a given resolution N and that the error histograms have the same resolution, the attribute error Ea can be computed by the simple scalar product

$$E_a = V \sum_{i=1..N} H(n)C(n).$$

So, every error value H(n) is weighted with its classified opacity C(n) which ranges from 0 (not visible) to 1 (fully visible). Attribute values that are classified as visible and that have a large error, will strongly contribute to Ea. Otherwise, attribute values that are classified as not visible will not contribute to Ea even if their attribute error is large. The V term is zero if the segment is outside of the view frustum and one otherwise. So, segments that are not visible have a zero error and will be coarsened. The segments in the queues are sorted by the attribute error Ea.

The direct volume renderer uses projected tetrahedra with a preintegration technique. Note that the normalization of the attribute values is necessary for the preintegration technique and for a quadricbased simplificiation algorithm during the construction of the multtriangulation.

### 5.3 Isosurfaces

Isosurfaces can be easily computed because the tetrahedral mesh is consistent. We implemented the extraction of isosurfaces on the CPU as well as on the GPU. Regardless which algorithm is chosen to implement the isosurface extraction, the algorithm can operate on a per-patch basis. The isosurface can be extracted from each patch independently of neighboring patches. The multi triangulation ensures that the border of the patches are connected consistently and hence the isosurfaces of different patches match perfectly at the patch borders.

In addition to the attribute error of the direct volume renderer, every segment stores a histogram of spatial errors for all attribute channels. Using these histograms, the mesh can be refined at those areas where the isosurface passes through.

### 5.4 Stream Lines

We compute stream lines by placing seed points and start a forward and backward integration of the vector field. Each step uses a second-order Runge Kutta integrator.

The seeds are placed within a regular grid that overlays the mesh. Each center of a grid cell is a seed point. Every grid cell might be traversed by at most one stream line. So we mark the cells that a stream line passes through and do not place seed points in cells that are marked.

This results in a coarse sampling of the vector field but might miss critical points, i.e. points that have a vector of length 0. In order to visualize the vector field near these critical points, we center a sphere in every such point and place seeds uniformly on the sphere. (This can easily be achieved by subdividing the triangle mesh of a tetrahedron at the triangle centers.)

Stream lines do not show the actual direction of the flow which can be either forward or backward along the stream line. We visualize the direction by a special halo technique. Every stream line is rendered with a halo, i.e. we first render the line as a line strip and render in a second pass a slightly broader line strip as halo. The second pass uses a stipple pattern of the line strip which is a simple bit masking and fully supported by graphics hardware. The stipple pattern is chosen to leave a one-bit (i.e. one-pixel) gap, see colorplates. The position of the gap is changed by one pixel from frame to frame. When the stream line is integrated, its points are stored in the order of the flow direction. The strip is rendered in exactly this order and the stipple pattern is applied to the halo and thus perfectly coincides with the flow direction.

Normally, when many stream lines are rendered, a lot of visual cluttering happens and it is difficult for the user to perceive the spatial relationship of the stream lines. To avoid this, we illuminate the stream lines and use a ghosting technique. The user moves a small box and only those stream lines that pass this box are rendered. All other stream lines are rendered semi-transparent and with a single ghost color. So, the user sees all lines of his box while the complete vector field is hinted as semi-transparent lines.

The vector values are normalized before simplification. Our extraction method runs on the normalized vectors. For normalization, we find the largest vector, scale all vectors such that the largest vector has length 1 and shift the vectors to the unit interval by 1 2 v+0.5.

#### 5.5 Hybrid Rendering

In order to support all visualization techniques by just one renderer, we extend the multi triangulation to store different resolutions of the tetrahedral mesh in one data structure. For each of the three techniques we store one DAG that steers the refinement and the coarsening. Additionally, each tetrahedron stores not just one faceincidency per face but three, one for every rendering technique. The cross-patch face hash map is also tripled. So, the renderer can adapt the mesh to each of its visualization techniques and can render the direct volume rendering with fewer tetrahedra than it uses to extract the isosurfaces.

We load the coded stream of a segment into main memory and can decode about 300K tetrahedra per second. If we use a raw data format without compression, the performance increases to about 500K tetrahedra per second. Because we exploit memory mapped files for the raw mode, the performance depends mainly on the caching capabilities of the underlying OS file system.

The mesh gets adapted to a maximal attribute error which is given by the user. Furthermore, the user specifies the maximal number of tetrahedra for the mesh. We examined that a maximal number of tetrahedra is mandatory to be defined because otherwise too many tetrahedra are created for a low error threshold. This is due to the fact that our system currently does not take occlusion by the segments into account and considers attribute errors only. Nevertheless, the system runs with a performance that is mainly bound by the direct volume renderer which currently in our implementation has a peek performance of about 800.000 tetrahedra per second and supports pre-integration in vertex and fragment shaders. The isosurfaces are extracted as triangle meshes and rendered using the standard triangle graphics pipeline.

Caused by the dependencies of the segments in the DAG, some regions of the tetrahedral mesh are refined although their error is smaller than the given maximal attribute error which results in a mesh that contains more tetrahedra than necessary. Typically, these segments lie outside of the view frustum. In order to counterbalance this effect, segments that lie outside of the view frustum need to be rejected as early as possible in the rendering pipeline.

## 7 Conclusion

We presented a multi-resolution system that enables interactive visualizations of large unstructured tetrahedral meshes. It exploits the features of multi triangulations and operates on segments instead of vertex hierarchies which makes the approach GPU friendly. The created segments are balanced as much as possible with respect to the number of tetrahedra that they include by sampling the mesh with an octree and merging the leaves afterwards.

Future work should examine the best sizes of segments that operate well with the caching behaviour of the operating system. The DAG could also be updated in such a way that the occlusion of segments with respect to the current classification is considered. Finally, the coarsening steps of the system are crucial. Maybe it is sometime more valuable to flush and refill the queues starting at the roots.
