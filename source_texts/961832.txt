Contributor
Rust renders acquired images, reconstructed planes, PET fusion and surgical 3D on Metal and Direct3D 12. Electron displays the completed frame. The engine also measures ROIs, SUVpeak, MTV and surgical surfaces using source voxels, and writes STL in patient coordinates.
This is the native imaging branch from the private repository, squashed onto this main. Its review history stays there, and it stays a draft here as it was there. The four small fixes taken from it went in first, as #9.
Ported onto public main
Main had moved under the branch: catalog revisions and source-file checks, Copy for the report, and SUV only with the engine's calibration. Fifteen files conflicted. Each resolution keeps both changes.
Revisions. Pixel requests carry the catalog revision from main and the source revision from this branch, and the broker checks both. The engine's frame and volume replies check the catalog revision and report the source revision.
Changed files. The viewer's frame request reads the file, as on main, instead of the shared frame cache. A file changed since its import is refused with file.sourceChanged instead of shown from memory. Measurement and GPU uploads still use the cache. Two of main's protocol tests failed without this.
PET records. Main's storage keys and older-record locations stay. This branch saves after native measurement, so a restored older record moves with that first save, taking its glucose and limited-view flag, and its old location is removed then.
Copy for the report. It reads the lesion table's sphere measurements (useMeasuredSpheres), so a PET without pixels in the renderer still has values. The button waits while a sphere is being measured.
SUV. Native sphere, region, probe and window values go through the engine's Normalization::quantity and stored_unit, which already need the engine's SUV factor. Fusion's relative scale follows petHasSuv.
Cancel. Main's wake_cancelled from Keep video size, cancel waiting measurements, and harden picture export and test gates #9 also wakes this branch's GPU and mesh queues on macOS and Windows, as this branch's own cancel hooks did.
Windows workflow. Both inputs stay: keep_installer from main and benchmark_base from this branch. The branch's tag-run installer upload now runs only on tag pushes, so a dispatch on a tag with keep_installer doesn't upload the same artifact twice.
.gitleaksignore stays removed, as on main. The fuzzer cache key is a plain version.
Cargo.lock holds every version either side pinned, normalised by cargo. tools/dependency-names.txt and the usage schema take both sides' names.
Dependencies
Against main, this PR adds 66 distinct Rust registry package names. Of these, 63 appear in the app workspace lock and three only in the DICOM fuzz lock. Both npm lockfiles match main. There are 10 newly direct Rust crates, including cc, which main already compiled transitively. Mac normal/build adds 42 names and Windows normal/build adds 51. CI builds the pinned cargo-fuzz executable separately and caches it.
bytemuck — Casts typed vertex, voxel, and uniform slices into bytes with checked layout requirements.
cc — Builds the repository’s Metal and Mach receive-right bridge using the system compiler. Already present transitively on main.
libfuzzer-sys — Instrumented mutation engine for the DICOM input and codec guard fuzz target.
naga — Parses and validates WGSL. Direct test code validates every checked-in shader without a GPU.
napi-sys — Declares Node-API functions for a tagged receiver and a Node-owned handle buffer. Electron main and the compositor release each native surface exactly once.
objc2 — Retains the Objective-C Metal texture while Rust imports it.
objc2-metal — Declares the exact MTLTexture protocol and texture kind wgpu accepts.
pollster — Waits for wgpu futures on the engine worker. It has zero enabled registry dependencies here.
wgpu — Single rendering API used for source frames, MPR, fusion and 3D on Metal and D3D12.
windows — Typed Windows COM/D3D12 calls create the shared resource and duplicate the handle into Electron.
No standalone FFmpeg executable or Playwright recorder is installed. MP4 export uses WebCodecs. The stock Electron Mac runtime contains Chromium’s libffmpeg.dylib.

The 1,000-slice CT removes a 500 MiB copy from the Electron renderer. On this run the first visible middle slice arrived sooner, while steady source paging took about 8 ms longer at p95. The small CT took longer to open. The native renderer can allocate one scalar texture up to 512 MiB and a separate carving mask up to 512 MiB.
With the bitmap driver and the 1,000-slice CT used in review, the first reconstructed plane took 1,480 ms (862 ms on the reviewed build). Subsequent coronal frames were 2–5 ms over 64 pages, including tile boundaries where the reviewed build took 561–585 ms. Full-volume 1024×768 repeated 3D took 31 ms (previously 1,436 ms), and 1600×1000 took 66 ms (previously 2,929 ms). These 3D draws follow the reconstructed-plane upload. These timings are separate from the end-to-end desktop results.
On the PET follow-up fixture, the first sphere measurement took 6.70 → 5.11 ms and the median of 30 warm measurements took 0.227 → 0.141 ms. Main additionally transferred the volume in 9.00 ms. Both builds measured the same 228 voxels, mean SUV 7 and MTV 14.592 mL.
