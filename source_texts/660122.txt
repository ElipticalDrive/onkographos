Context
All resources load synchronously and stay fully resident: Engine/Runtime/ResourceManager.h does path/GUID-based loading with refcounts, every texture keeps its full mip stack in VRAM, and vertex/index buffers are immutable after load. Verified gaps: "single full-res mip stack per texture, all resident" and "no sparse virt-tex feedback or resident-set streaming." Big worlds multiply asset counts past what load-everything-up-front can sustain — and level streaming volumes need assets to arrive without stalling the 1/60s fixed-timestep loop.
Goal
A background streaming layer in the native runtime: textures and meshes load on a worker thread with residency states (NotLoaded → Loading → Resident) and distance-based priority, so distant assets arrive as low mips / LOD meshes first and refine as the player approaches — the groundwork for v4.0 virtual texturing.
Acceptance Criteria
ResourceManager gains async load requests with completion states; renderer draws placeholder (existing fallback) until resident
Texture mip streaming: low mips resident first, high mips streamed by camera distance priority
Mesh streaming reuses the existing geometric LOD chains (decimated LODs load before LOD0)
No main-thread file I/O during gameplay after initial scene activation (verify with profiling)
Works from loose files (editor/Debug) and .vpak via AssetVfs (Release)
Budget setting: max upload bytes per frame to avoid copy-queue spikes
Technical Notes
GPU uploads should go through a dedicated upload ring; fence against the render loop in Engine/Runtime/RenderLoop.h
Priority metric: same squared-distance math as the LOD thresholds (lodT1sq...) in DX12Renderer.h
Keep the API shape compatible with sampler-feedback streaming planned for v4.0
Dependencies
core: level streaming volumes + async scene chunk loading (shared worker/priority infrastructure)
