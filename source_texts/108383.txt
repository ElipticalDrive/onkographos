Owner
Splats swim under FSR2 because the projection uploaded to the splat GPU pipeline never carried the engine's temporal jitter. This lands the fix, the cache-key change that would otherwise have silently neutered it, a QA oracle that is red on the unfixed tree, and the scoped disclosure of the half that remains.
Base: b915afc51c5 (origin/master at the time of writing; top commits #999 and #1009).
Why one PR and not a stack. The plan this follows is four ordered steps — rig, cache key, jitter, disclosure — and the rig is deliberately red on the unfixed tree. A blocking QA scene that fails on master cannot land on its own, so splitting the rig out would either red master or require landing it disabled, which is the opposite of the point. The four steps are still separable in review: §4.1 is the rig, §3 change 2 is the cache key, §3 change 1 is the jitter, §5 is the disclosure, and §4.3 shows each production change failing its own test in isolation.
Risk class: R2 — python scripts/agentic/classify_change.py returns R2 for this path set (renderer/**). Note that interfaces/output_compositor.{h,cpp}, which this PR also touches, classifies R1 under the misclassification filed as #1017; it is treated as R2 here regardless and carries the GPU evidence below.
1. The defect, re-verified at the base
gaussian_splat_renderer.cpp:2400-2402 built the GPU projection by copying p_render_data->scene_data->cam_projection (:2373) and flipping one sign:
```
// Apply flip_y only; gaussian pipeline uses linear view-space depth.
Projection render_projection = cam_projection;
if (... scene_data->flip_y) { render_projection.columns[1][1] = -render_projection.columns[1][1]; }
```
grep -c taa_jitter modules/gaussian_splatting/ returned 0 — not one reference in the module.
Meanwhile every mesh in the same frame is rendered through RenderSceneDataRD::get_cam_projection() (servers/rendering/renderer_rd/storage_rd/render_scene_data_rd.cpp:40-45), which left-multiplies taa_jitter via Projection::add_jitter_offset() (core/math/projection.cpp:932-935), and FSR2 is handed the same vector immediately below the splat pre-upscale hook (render_forward_clustered.cpp:2699, params.jitter at :2713). FSR2 then un-jitters its input — ComputeHrPosFromLrPos() at thirdparty/amd-fsr2/shaders/ffx_fsr2_common.h:431-437 and InitParams() at ffx_fsr2_accumulate.h:219-220. A layer that was never jittered is therefore reconstructed displaced by +jitter, moving every frame along the Halton sequence.
Godot's TAA never receives the jitter at all — the whole push constant at servers/rendering/renderer_rd/shaders/effects/taa_resolve.glsl:50-55 is {vec2 resolution; float disocclusion_threshold; float disocclusion_scale;} — so under TAA splats do not swim; they are bit-stable and simply never antialiased. The issue title is half wrong and the §11 entry is updated to say so.

2.2 Why the colour delta is reported and not gated
Look at the BASE FSR2 rows: the broken splat region measures 1.089 mean LSB while the correct mesh control beside it measures 2.365. The broken layer scores better. Mean |LSB| between consecutive frames confounds displacement with local contrast, and a 2 px checker has a far larger gradient than a soft scan. Gating it in either direction would be gating content.
2.3 Why the periodicity is reported and not gated either
The assessment attributed the defect by periodicity: the splat signal repeats with period 8 at scale 1.0, autocorrelation +1.00 at lag 8, which is the engine's jitter phase (renderer_viewport.cpp:252-260). That attribution is sound and I reproduced it.
It is not an oracle, and this is the one place my verification contradicts the assessment's plan, which proposed it as the QA rig's oracle ("the splat-region signal's autocorrelation at the engine's jitter-phase lag … is the oracle"). Measured on the same captures, the mesh control autocorrelates +1.000 at lag 8 as well. FSR2's resolve is phase-periodic under a static camera whether or not the layer feeding it is jittered, so the statistic cannot separate a correctly integrated layer from a broken one, and a gate built on it would have been red before and after. The QA rig records both autocorrelations and gates on neither; the reasoning is written into the scene header so the next reader does not rediscover it as a good idea.
2.4 What does separate: sub-pixel displacement
The defect is a statement about position, so measure position. A first-order (Lucas–Kanade) estimate divides the temporal difference by the spatial gradient and returns pixels, so contrast cancels:
```
[Sxx Sxy; Sxy Syy] d = [bx; by],  Sxx = sum gx^2 ... bx = sum gx * dI
```
evaluated for each frame of the converged window against that window's own mean frame. Those are the SPLAT px / MESH px columns above.
3. The change
1. GaussianSplatRenderer::build_render_projection() (renderer/gaussian_splat_renderer.cpp, declared beside build_cull_projection()). Static and free of RenderData, so the contract is unit-testable without a GPU. It applies flip_y and, when the jitter is non-zero, the same identity-plus-translation correction the engine uses. It deliberately does not apply the engine's depth correction — the gaussian pipeline carries linear view-space depth.
Zero jitter short-circuits and returns the flipped matrix, so the non-temporal path is bit-identical to the pre-#929 matrix by construction rather than by a floating-point argument about multiplying by an identity. It is self-gating: scene_data->taa_jitter is exactly (0,0) unless a temporal stage is active (renderer_scene_cull.cpp:2681-2696 only assigns it when the jitter phase count is non-zero; renderer_viewport.cpp:252-260 leaves that at 0 unless temporal upscaling or TAA is on). The shadow pass (gaussian_splat_renderer.cpp:1981-1987) builds its own projections locally and is untouched.
2. The render cache reuse key now carries the GPU projection (interfaces/output_compositor.{h,cpp}, call sites at renderer/render_pipeline_stages.cpp:1909 and :2603). The key was p_input.projection, the unjittered camera projection, compared exactly at output_compositor.cpp:176. The jitter appears nowhere else, so wherever reuse is live — a static camera, which is exactly the case this fix is about — the raster stage is skipped (render_pipeline_stages.cpp:1835) and one frozen jitter phase would be re-composited every frame. Change 1 would silently do nothing while still looking correct to any test that only inspects the matrix the renderer built. The new parameter is required and has no default, so a caller cannot reintroduce the trap by forgetting an argument.
3. Three false comments. gaussian_splat_renderer.h:377, interfaces/rasterizer_interfaces.h:34 and interfaces/painterly_renderer_interfaces.h:88 all read // GPU projection with depth/jitter correction applied. The code had never applied either.

Three gates run before any displacement is scored, and each fails the scene rather than degrading:
Rig determinism — with no temporal stage both regions must be bit-identical frame to frame (0.000 LSB mean and max). Measured exactly 0 in every run.
Region discrimination — hiding the splat node must move the splat rectangle by ≥ 1.0 LSB and the mesh rectangle by ≤ 0.5, and vice versa. Without it both rectangles could be pointing at background and every number below would be noise compared with noise.
Stage engaged — the mesh control must move during each temporal config's engage window. A viewport that silently refuses TAA or FSR2 leaves both layers perfectly stable, which is indistinguishable from perfect integration; this is Every in-repo painterly test exercises the baseline fallback, not painterly: the test project contains no PainterlyMaterial #997's shape and it is directly reachable here.
A region whose gradient energy or structure tensor cannot support the 2×2 solve is reported UNMEASURABLE and fails; it is never recorded as 0.0 px, which would read as flawless stability.
4.2 Unit tests — both in the STRICT [ViewTransform] lane, both without a GPU
[GaussianSplatting][ViewTransform] Render projection carries the engine TAA jitter (tests/test_view_transform.h), four subcases — zero jitter is bit-identical to the flip-only matrix in all 16 entries (and to the raw matrix with flip_y = false); a non-zero jitter composes exactly as J · (flip · P); the result is a depth-independent NDC translation of exactly +jitter at three depths spanning 0.5 to 100 m, with w unchanged and columns[0][0] / columns[1][1] untouched; and two different phases produce different matrices. It carries its own discrimination check — that the jittered and unjittered matrices differ at all — so a no-op implementation cannot satisfy the equalities.
The fourth subcase uses an off-axis frustum (set_frustum(2.0, 16/9, Vector2(0, 0.3), …), which writes a non-zero columns[2][1]) and REQUIREs that entry is really non-zero before asserting, per column, that the jitter contribution is exactly +jitter × w_row and that zero jitter is still bit-identical. It exists because the symmetric perspective is precisely the case where the module's single-entry flip and the engine's whole-row flip agree, so on its own it could not pin down what the jitter does for any other projection type. The jitter term is the engine's for all of them; the flip is not, and that divergence is pre-existing, unchanged here, and now named in the docblock rather than papered over (self-review finding 1).
[GaussianSplatting][ViewTransform] Render cache reuse is refused when only the GPU projection's jitter differs (tests/test_renderer_pipeline.h) — drives OutputCompositor before initialize(), so with p_require_valid_depth = false the two cache functions are pure functions over the cache state and need no RenderingDevice; RIDs come from a local RID_Owner. It asserts reuse is granted for an identical key in both directions before asserting it is refused when only the jitter moves, so it cannot be satisfied by a cache that never grants reuse. It is tagged [ViewTransform] deliberately: [Renderer] is an advisory lane (run_module_tests.py, strict=False) and a fail-closed proof that cannot fail CI is not a proof.
Lane counts on the same filter (--test-case=*GaussianSplatting*][ViewTransform]* --test-case-exclude=*][RequiresGPU]*): 5 cases / 5 assertions at base → 7 cases / 78 assertions after, 7 passed, 0 failed. The two new cases contribute 73 assertions, so they are not empty shells.
4.3 Mutation proofs
Each mutation reverses exactly one production change and leaves the tests in place, so the failure attributes to that change rather than to "something broke". The edits are exact-string patches that refuse to apply unless the anchor is found exactly once — a mutation that silently did nothing cannot be mistaken for "the test still passed". Each is a full optimize=speed_trace rebuild, ~35 s incremental, and the binary's link time was checked before each run.
Mutation 1 — drop the GPU-projection compare from the reuse key (removes the five added lines in OutputCompositor::can_reuse_cached_render; the jitter itself is still applied).
```
[doctest] test cases:  7 |  6 passed | 1 failed | 2121 skipped
[doctest] assertions: 60 | 57 passed | 3 failed |
[doctest] Status: FAILURE!
```
The failing case is Render cache reuse is refused when only the GPU projection's jitter differs, at all three CHECK_FALSEs — CHECK_FALSE( true ): the cache hands back a frame rendered with a different jitter phase. The jitter case still passes, which is the isolation that makes this a proof of the cache-key change specifically.
Mutation 2 — make build_render_projection() ignore the jitter (restores the cache key first, then forces the zero-jitter short-circuit to be taken always).
```
[doctest] test cases:  7 |  5 passed |  2 failed | 2121 skipped
[doctest] assertions: 60 | 45 passed | 15 failed |

```

The splat pipeline built its GPU projection from the raw camera projection with
a flip_y and nothing else, while every mesh in the frame is rendered through
RenderSceneDataRD::get_cam_projection(), which left-multiplies the engine's
per-frame taa_jitter. FSR2 -- handed that same jitter immediately below the
splat pre-upscale composite hook -- un-jitters its whole input by it. A layer
that was never jittered therefore came out displaced by +jitter, changing every
frame along the Halton sequence.

Measured on a real scan (31,208 splats) with a static camera, FSR2 scale 1.0:
the splat region displaced 0.2525 px against its own window mean while the
in-frame, correctly-jittered mesh control displaced 0.0100 px -- 25x. At scale
0.5, 0.3603 px vs 0.0046 px, 78x. With no temporal stage both are exactly
0.0000 px. After this change the splat figures are 0.0900 px and 0.0927 px --
2.8x and 3.9x reductions -- with the mesh control unchanged at 0.0099 and
0.0046 px. The remaining ~0.09 px is NOT the jitter: splats also publish no
depth write-back, no motion vectors and no reactive mask, so FSR2 reconstructs
them with less information than it has about the mesh. That residual is
disclosed under release-acceptance-bar 8.1 and tracked as #1025.

Three changes, in dependency order:

1. GaussianSplatRenderer::build_render_projection() -- a static, RenderData-free
   helper beside build_cull_projection(). It applies flip_y and, when
   scene_data->taa_jitter is non-zero, the same identity-plus-translation
   correction the engine uses. It deliberately does NOT apply the engine depth
   correction: the gaussian pipeline carries linear view-space depth. Zero
   jitter short-circuits and returns the flipped matrix bit-identically, so
   every non-temporal configuration -- Godot's default -- is untouched by
   construction rather than by a floating-point argument. Self-gating:
   taa_jitter is exactly (0,0) unless a temporal stage is active
   (renderer_scene_cull.cpp:2681-2696, renderer_viewport.cpp:252-260). The
   shadow pass builds its own projections locally and is not routed through it.

2. OutputCompositor's reuse key now carries the GPU projection. The key was the
   UNJITTERED camera projection, and the jitter appears nowhere else, so
   wherever reuse is live the raster stage is skipped and one frozen jitter
   phase would be re-composited every frame -- change 1 would silently do
   nothing while still looking correct to any test that only inspects the
   matrix the renderer built. The new parameter is required and has no default,
   so a caller cannot reintroduce the trap by omitting an argument.

3. The three header comments that claimed "GPU projection with depth/jitter
   correction applied" described a correction the code had never applied.

Tests:

* [ViewTransform] "Render projection carries the engine TAA jitter" -- pure
  math, no GPU, in a STRICT lane: zero jitter is bit-identical to the flip-only
  matrix; a non-zero jitter equals the engine's own J * (flip * P); the result
  is a depth-independent NDC translation of exactly +jitter that leaves
  columns[0][0] / columns[1][1] -- the focal entries tile_binning.glsl derives
