Expose Octree creation, point operations and nearest-neighbor searches, plus triangle rasterization in color, depth and combined forms. Tests cover point-cloud-initialized search and rendered color/depth buffers.

New Features
Added point-cloud octrees with point insertion and removal, bounds checks, and radius or nearest-neighbor searches. Search results can include colors and squared distances.
Added triangle-mesh rasterization to produce color and depth buffers, or update either buffer independently, with options for shading, face culling, and OpenGL-compatible depth.

Retained concerns
Medium · reliability · inferred: The new empty Octree factories expose a factory-to-operation transition affected by the reported native initialization defect. They return wrappers without verifying initialized resolution, permitting subsequent mutation and search. The cloud-initialized test does not resolve readiness of empty objects. This leaves native failure containment uncertain; the actual failure mode and security impact are not verified.
Security review details
Security Blast Radius
inferred — If a host application passes attacker-controlled geometry or point clouds to these APIs, that data reaches native computation in the host process. A native memory fault would therefore affect the hosting process, not merely an isolated managed operation. Network reachability, host privileges and tenant exposure were not established.
Trust Boundaries and Controls
observed — The new entrypoints preserve smart-pointer ownership and retain managed proxy sources across normal native calls. They use the existing C++ exception boundary, whose exclusion of non-C++ faults predates this PR. The PR adds new native sinks without changing that containment model.
Resilience and Maintainability Implications
observed — The added tests assert cloud-initialized insertion/search and successful combined color/depth rendering. They do not establish empty-factory readiness or recovery after native output-write failures. Exception translation alone does not establish atomic restoration of caller-owned buffers.
Hardening Proposals
proposed — Make availability of empty Octree factories conditional on verified initialization guarantees for the supported OpenCV version, or reject the affected construction path. Define post-failure validity of mutable Octrees and rasterization buffers before relying on them in security-sensitive processing.
