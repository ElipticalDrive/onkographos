Issue body actions
All these classes live in jzy3d-native-jogl-core and cast the painter to NativeDesktopPainter to use the JOGL GL (or JOGL utilities such as TextureIO, Buffers, GLBuffers):
VBO: DrawableVBO, DrawableVBO2, ScatterVBO, BarVBO, PolygonVBO, TriangleVBO, TriangleStripVBO, SphereVBO, CubeVBO, VBOBufferLoader*, VBOBuilder*
Shaders: GLSLProgram, ShaderFilePair, ShaderMeshDrawableVBO, ShaderWaterfallDrawableVBO, ColormapTexture
Volume: Volume, Texture3D
Textures: TextureFactory, SharedTexture, TexturedCube, TranslucentQuad, TexturedCylinder, NativeDrawableImage, TextureGraph2d, MaskImageSymbolHandler, PickableTexture
Others: FeedbackBufferAxisBox, OBJFileLoader, MatlabVBOLoader, GPUInfo
Module jzy3d-depthpeeling (FBO + shaders)
Plan:
Neutral interfaces in jzy3d-core for buffer objects, vertex arrays, shader programs and textures (texture loading through AWT BufferedImage, not TextureIO), implemented by NativeDesktopPainter and PanamaGLPainter
Migrate the drawables above to these interfaces so they no longer depend on JOGL
Depth peeling on PanamaGL
Port the matching JOGL tests (TestDrawableVBO2_*, TestVBOBufferLoader, TestTexture3D) so they run on both painters
Depends on panama-gl/panama-gl#12 for Linux and Windows.

Done on branch claude/focused-noether-v1a0bb :
f8505fa GPU resources API in IPainter (buffers, client arrays, draws, multi draws, primitive restart, shaders, uniforms, 1D/2D/3D textures, FBO, queries, read pixels), constants in GLConstants, implemented by NativeDesktopPainter and PanamaGLPainter. PainterGPUConformance (jzy3d-tester) checks both painters against a real GL context.
e93a180 VBO, shader and volume drawables, GLSLProgram, OBJFileLoader moved to jzy3d-core (same packages). Methods taking a JOGL GL now take an IPainter. DrawableVBO2 multi element drawing stores indices in an element buffer and gives byte offsets instead of a JOGL PointerBuffer. Depth peeling algorithms use IPainter.
d7d7efe Textures loaded through IPainter (ImageIO instead of TextureIO), TextureCoords replaces JOGL's. Textured drawables, FeedbackBufferAxisBox, NativeDrawableFactory, GPUInfo moved to jzy3d-core. AWT textured drawables, text textures and contours moved to jzy3d-core-awt. jzy3d-native-jogl-core now only holds the JOGL painters, canvas, renderers and animator.
9f628f5 New module jzy3d-depthpeeling-panamagl (no JOGL dependency) : PanamaGLDepthPeelingRenderer3D, PanamaGLDepthPeelingChartFactory. Algorithms render to the framebuffer bound before they execute instead of framebuffer 0.
Tests (Linux, Mesa llvmpipe, Xvfb)
ITTest_GPUDrawables : DrawableVBO2 (elements, multi arrays), ScatterVBO, SphereVBO, shader mesh, shader waterfall, Texture3D, textured image, textured cube render the same with JOGL and PanamaGL (< 1% pixels, text antialiasing only). JOGL images are identical to the ones rendered before the migration.
ITTest_DepthPeeling : the 4 peeling methods render the same with JOGL and PanamaGL.
JOGL tests TestDrawableVBO2_*, TestVBOBufferLoader pass. They remain JOGL tests : the PanamaGL side is covered by ITTest_GPUDrawables and PainterGPUConformance.
Bugs found and fixed on the way
Texture3D crashed the JVM (also with JOGL) : texture names were taken from uniform locations, overwriting existing textures, and a 1 texel border let GL read out of the buffer. TestTexture3D is enabled again.
SphereVBO shared its VBO ids between charts, hence between GL contexts.
Drawables added from a non GL thread were never mounted by ChartView.
NativeDrawableImage invoked glTexEnvf with an invalid target.
JOGL text rendering invoked glOrtho(0,0,0,0) on empty viewports.
API changes to mention in release notes
DrawableVBO.setData(GL, ...), doLoadArrayFloatBuffer(GL, ...), GLSLProgram methods, TextureFactory.init now take an IPainter.
DrawableVBO2.setData(IPainter, IntBuffer, PointerBuffer, ...) becomes setData(IPainter, IntBuffer count, LongBuffer offsets, IntBuffer indices, ...).
SharedTexture.getTexture(IPainter) is replaced by bind(IPainter) / getTextureId(IPainter).
GPUInfo.load() / load(GL) are now NativeGPUInfo.load() / load(GL), GPUInfo.load(IPainter) works with any painter.
Known limitation : axis labels are not rendered properly by depth peeling shaders, with JOGL as well as with PanamaGL.
