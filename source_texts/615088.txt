Stage 8c of the voxel roadmap (report §8), the last one: the clay's section of the scene file packs its bricks, so a voxel object's file is about half the size. Versions 1 and 2 (raw bricks) still read.
Best of all worlds (which idea came from where)
Measured before chosen: six encodings were run over the bricks of a plain and a 60-dab 256-across sphere (saved by the app, parsed in Python) against zlib as the reference. Plain run-length encoding, the roadmap's first idea, only reaches 62 % (just 57 % of a brick's voxels are the clamp; the band itself has no runs). Second differences with run tokens reach 46 %, zlib at level 6 48 %, so the hand encoding beats the general compressor at a fraction of the code and with no dependency.
Delta coding of a smooth field, as OpenVDB's and Houdini's volume compression lean on the field's smoothness (and as audio and image codecs predict each sample from its neighbours): along a row of voxels the difference between neighbours changes little, so each value is sent as the change of its difference, zigzag and LEB128 as protobuf does, mostly one byte.
Runs for the clamp, as OpenVDB's inactive-value compression stores a tile's constant once: equal values go as one token with a count.
Raw fallback and self-describing lengths, as PNG's filter bytes and ZIP's stored entries: a brick that would not shrink is written raw, and each brick carries its byte count, so a damaged stream is refused on its own without trusting the rest of the file.
What changed
src/voxel/pack.odin (new): pack_brick/unpack_brick (the first value, then tokens: 0 is a run of the last value with a count byte, any other token less one is the zigzag second difference), pack_mask/unpack_mask (count and value runs); each after a u16 byte count, 0 for raw; every count, run and value range is checked, and the stream must end exactly on the 512th voxel.
file.odin: SVOX_VERSION 3; the writer packs each brick and mask; the reader reads versions 1 and 2 raw and 3 packed, refusing a damaged stream; clay_write_estimate stays the raw upper bound (the autosave reserves it).
Tests (pack_test.odin): five bricks and three masks round-trip bit for bit (a plane packs under 128 bytes, a ramp to a byte a voxel, random values go raw, the ends of the range survive); damaged streams are refused (short, a run past the brick, a count past the bytes, raw with nothing after, a byte left over, bad mask runs); hand-built version 1 and 2 files read with their values and mask; a sculpted 128 sphere's file is under 65 % of its raw bricks and reads back to the same hash. The existing file round trips (voxel and mask tests, the app's scene files) run on version 3 now. README (Voxel sculpting: the file) and the sm-sdf skill.
