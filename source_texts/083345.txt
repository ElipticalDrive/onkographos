Scope
Add an isolated CPU execution flow under cpu/, plus a separate CPU validation workflow. No existing source, film, player, root README, or research branch is changed. Do not merge automatically. Based on master 280770daa8b78274339d26ad45a58f62aeeda39b.
Implementation
Fire/air use the adopted PyTorch solver and volume renderer on CPU. AST checks preserve all five numerical functions and the production render function. Production remains 896×56×504 cells and 1920×1080 / 30 fps; smoke mode is explicitly separate.
Earth, ice, lava and native APIC/FLIP water use their original geometry/materials/motion with Cycles CPU. CPU OpenImageDenoise replaces OptiX denoising.
Lightning preserves Eevee via Linux Mesa CPU software rasterization, and refuses execution without a successful llvmpipe/softpipe render probe.
Original water solve → mesher → renderer stay concurrent to respect the bounded cache protocol. Only manifest publication is made atomic in generated copies.
New output directory outside the checkout; copied inputs; selective SHA-256-verified asset restoration; immutable source locks; CPU-only device policy; logs/receipts; peer-process cleanup on failure, timeout or disk exhaustion; full video decode validation.
No fabricated visual approval; each candidate remains pending review.
Editing provenance
Earth uses the same original 300-frame reverse-arrival edit on newly CPU-rendered source frames. Default water reproduces the published edit by retaining the first 102 frames of the historical r7 opening and crossfading a fresh 240-frame segment. --native-water instead produces only the fresh eight-second segment with no old footage. The original rigid-fracture lava is deliberately preserved; this is not an unmerged lava-solver upgrade.
Executed locally
43/43 contract tests passed.
Original-source CPU-only fire and air simulation, rendering, software encoding, and full decode completed: 144 frames each, 288 frames total, at diagnostic 320×180 / 128×16×72.
Original source hashes unchanged; exact tested workflow and output hashes recorded in cpu/verification.json.
CPU-only PyTorch 2.10.0+cpu; no Blender available in the 4 GiB local environment.
Not yet validated
Complete production-resolution films, full native water pipeline, full Blender production scenes, and CPU/GPU visual parity have not been executed/established. CPU/GPU floating point and OIDN/OptiX denoising can differ. The original gas receipt lacks a complete launch command, so exact historical timebase matching also needs reference comparison.
The new GitHub Actions workflow runs contract/gas integration and actual Cycles/software-Eevee probes on CPU-hosted runners. Its results must be checked separately; no remote CI success is pre-claimed.
Usage
See cpu/README.md.
```
python cpu/run.py plan --elements all
python cpu/run.py run --elements all --output ../elements-cpu-01 \
  --restore-inputs --blender /path/to/blender --threads 8
```
All seven require Linux + Mesa/Xvfb for the unchanged Eevee lightning renderer. Windows/macOS can select the other six; those complete production runs still require validation.
