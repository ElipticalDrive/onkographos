Summary
restackOverlay updates the overlayStack z order, but volumeCanvas is inserted after dataCanvas at load time and never re-derived. Raising volume above the candles changes the model without changing the painted order.
Environment
Repository: LuxAlgo/Vela
Target commit: 24ade79da804b0b3fea2f678c82326e58806f4eb
File: src/renderers/native/NativeRenderer.ts:3809-3832
Runtime: Node.js 22; TypeScript renderer
Steps to reproduce
Instantiate the real NativeRenderer with a scene reporting volume=10, vpvr=20, ema=30, candles=50.
Call restackOverlay("volume", raisedZ) three times.
Compare the resulting overlayStack() z values with canvasPile().
Expected behavior
For every overlay included in the legend price-pane stack, a restack must change the actual paint order; canvas stacking must consume the same z relative to candleZ.
Actual behavior
NativeRenderer includes volume/VPVR in the legend overlay stack and restackOverlay updates their z keys, but volumeCanvas and vpvrCanvas are fixed after dataCanvas, so restacking those overlays changes the reported order without changing the actual paint order.
```
    /**
     * The price pane's layers back to front, as the legend restacks them: every indicator
     * with a legend row, in paint order, plus the candles. The same layers and order the
     * object tree lists (see `indicatorZOrder`).
     */
    private overlayStack(): StackEntry[] {
        const painted = this.scene
            .orderedIndicatorsForPane(PRICE_PANE_ID)
            .filter((m) => m.legend !== false)
            .map((m) => ({ id: m.id, z: this.scene.zOf(m.id) }));
        return priceStack(painted, this.scene.candleZ);
    }

    /** Apply a legend restacking step: shared keys are spread apart first (the order stays),
     *  so the step lands exactly one layer over. No-op when there is nothing to step over. */
    private restackOverlay(id: string, step: (stack: StackEntry[], id: string) => number | null): void {
        for (const fix of untie(this.overlayStack())) this.scene.setIndicatorZ(fix.id, fix.z);
        const z = step(this.overlayStack(), id);
        if (z === null) return;
        this.scene.setIndicatorZ(id, z);
        this.scheduler.invalidate(InvalidateLevel.Full);
        // The stacking is part of the config: host chrome mirroring it (an object tree) follows.
        for (const cb of this.configChangedCbs) cb();
    }
```
Root cause
The renderer maintains z ordering in overlayStack and paint ordering in canvasPile. restackOverlay updates the former, while volumeCanvas is inserted after dataCanvas at load time and is never re-derived from the updated ordering.
Suggested fix
Derive canvasPile and the canvas slots from the overlayStack z values, recomputing them after each restack rather than fixing the volume and vpvr canvases at data-load time.
Impact
The legend action that raises the volume overlay has no visible effect. The model and the legend state report one order while the canvas is painted in another, producing a persistent discrepancy between state and rendering.
