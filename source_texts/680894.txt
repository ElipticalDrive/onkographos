Rendering with multiview-enabled bokeh effect of a highly detailed scene with 170 million points, with hybrid 3D cursor.
ABSTRACT
Accurate exploration of large 3D datasets — such as highly detailed geospatial point clouds — requires input
methods that let users reliably target objects in depth, something conventional 2D cursors cannot provide. This need
motivates stereoscopic rendering and, with it, cursor representations that exist as true 3D entities. We present an
analysis of geometry-based and shader-based 3D cursors, and show how these designs enable interaction modes not
achievable with 2D cursors, such as depth-aware camera navigation and accurate distance measurement in threedimensional world space. Datasets too large to fit in RAM require on-demand handling and benefit significantly
from the single-pass multiview rendering technique. This technique generalizes stereoscopic rendering and enables
artifact-free bokeh for enhancing depth perception even on monoscopic displays. The presented design allows
efficient coexistence with legacy code, providing a basis for immersive exploration of terabyte-scale point clouds.

Big Data: Large Coordinates
Real-world geoscientific coordinates frequently exceed
the numeric range of single-precision GPU arithmetic,
causing visible spatial jitter when large values differ
only slightly. The established remedy is a “floating origin” [Tho19]: any coordinate A requiring double precision is decomposed into single-precision components
A = Ab + Ao (“base” and “offset”). Shader code must
keep bases and offsets separate when computing sums
and differences to preserve precision.

MULTIVIEW RENDERING
Our primary framework, HydroVish[BRH07], uses
a minimalistic microkernel that loads independent
plugin-based modules at runtime. It scales across
application domains and allows new technologies to
be integrated without major rewrites. All functionality
is encapsulated in objects with defined inputs and
outputs. Render Objects form a dedicated category
and define their traversal order during frame rendering:
camera and lens first, followed by opaque geometry,
transparent geometry and finally overlay objects.
While earlier work such as [AC10] modified only a
single point-based rendering routine with one shader,
our framework intends to support a broad range of
techniques for scientific visualization. These include
multiple topologies — points, triangle meshes, and
others — and several shader variants per topology, such
as opaque and transparent rendering. Supporting this
diversity leads to the organization scheme presented in
Section 3.1.
Multiview OVR is an extension to OpenGL that allows rendering multiple views simultaneously. Fragment shader output is sent to multiple framebuffers,
each with their own depth buffer, from a single draw
call. However, GPU and driver must support it.
Integrating single-pass rendering with conventional
multipass techniques is challenging because existing
OpenGL rendering paths cannot simply be rewritten.
Fixed-pipeline OpenGL and shaders using global
matrices in compatibility profile cannot use multiview
features. Existing rendering libraries thus require the
traditional per-eye multipass approach unless they
explicitly support the singlepass mode. Mixing both
methods in one pipeline demands explicit framework
support. Previous work on immersive point cloud
rendering [DMS+ 18] has addressed the performance
requirements of VR headsets, but assumes a homogeneous rendering pipeline that can be adapted
wholesale. A central constraint within a heterogeneous
framework is the ordering of opaque and transparent
objects: Opaque geometry must be rendered first
to populate the depth buffer and establish correct
occlusion. Translucent objectsmust be drawn afterward
to blend correctly. Rendering them too early leads to
failed depth tests or incorrect blending. This ordering is
standard in OpenGL transparency handling. However,
it prevents rendering all multiview objects strictly
before (or after) all single-view objects, because that
would place transparent multiview objects ahead of
opaque single-view geometry.

3.2.1
Dynamic Camera
Modelling the interocular distance e as a constant value
of 6.3cm according to a human face cannot work over
the wide span of size scales occurring in graphical
scenes. Rather we need a camera shift that adjusts
dynamically to the view volume and the location of
the camera therein. A parallax angle below 1.5◦ is
comfortable for viewing, which requires a camera shift
e = d tan 1.5◦ ≈ d/38 as a rule of thumb [Bou99]. In order to limit negative parallax occurring at close objects,
it may be appropriate to cut off such objects by setting
the near distance relative to the focus distance.

Scene Sampling
An alternative is to sample the depth buffer via e.g.
a 3 × 3 stencil around the viewport center and to select the minimum, corresponding to the nearest visible surface. This approach provides a stable reference distance that is independent of mouse position and
changes only when the camera moves or new geometry enters the view. It is therefore well suited for navigation through cluttered environments where cursorbased convergence would be too confusing. As a major
drawback, it ignores what the user may actually focus
on, since it always measures toward the screen center.
3.3.4
Limitations of Depth-Based Approaches
Both cursor-based and sampling-based methods rely
on values written to the depth buffer. Scenes composed predominantly of semi-transparent elements —
e.g. stars represented by translucent billboards — write
no depth information at all, rendering both strategies ineffective. In such cases, a fixed convergence distance
derived from the bounding volume of the dataset remains the only viable fallback (though an infinite far
plane yields an unbounded volume, limiting this heuristic as well).
3.3.5
Distance Factor and Smoothing
Regardless of the sampling strategy, the raw distance
to the nearest object is scaled by a user-defined distance factor k before being used as convergence distance: d = k · dsampled . Values of k < 1 push the zero
parallax plane closer to the camera, causing more of
the scene to appear behind the screen (positive parallax), while k > 1 shifts it farther away, increasing the
amount of negative parallax and the “pop-out” effect.
In practice, k ≈ 1 provides a neutral starting point.

3.4
A geometric cursor inherently participates in stereoscopic rendering: each eye sees it from a different angle, producing correct disparity without special treatment. The challenge is visibility: a solid object occludes the scene behind it, potentially hiding what the
user wants to inspect. We therefore explored several
primitives, each providing different benefits.
Artifact-free Bokeh via Multiview
Bokeh is the quality of out-of-focus parts of the rendered image. Some real-time implementations approximate this effect in screen space as a post-processing
step, blurring pixels based on their depth buffer values.
By generalizing the stereo projection of Section 3.2 to
multiple views with fractional camera shifts and optional vertical offsets, the effect can be simulated geometrically: the OVR Multiview extension renders up to
32 views in one pass, each with a fractional asymmetric frustum shift, sampling the scene as a finite aperture would. After generating the layered framebuffers,
a screen-quad shader composites them into the final image, where the weighting of views defines the bokeh
style, much as a photographer’s choice of lens yields the
visually most pleasing bokeh. Because this approach
operates on actual multi-perspective geometry rather
than on a single depth image, it naturally handles transparency, overlapping surfaces, and incomplete depth —
all cases where screen-space approximation methods
produce artifacts. Monoscopic and stereoscopic displays both benefit from this depth cue, though the cost
scales with the number of views.
4
3D MOUSE CURSOR
With stereoscopic display devices a conventional 2D
on-screen mouse cursor becomes more distracting than
useful, making a true 3D cursor necessary for consistent depth perception and interaction. A 3D cursor offers far more design freedom than a 2D pointer, shaped
by both artistic and technical considerations. We explore two contrasting yet complementary solutions —
geometric and shader-based cursors — and show representative implementations of each. Inferring depth
from a 2D cursor is only possible where geometry exists
behind the sampled pixel, making sparse regions problematic. Devices such as Space Mice avoid this issue
entirely by providing true 3D input. The 3D cursor display techniques introduced here are input-agnostic and
work equally well with either device type.
The ultimate choice of 3D cursor type depends on
the characteristics of the scene, whether it is dense,
sparse, volumetric, surface-based, or dominated by line
elements. Heterogeneous scenes composed of mixed
topologies naturally call for a corresponding combination of cursor types.
Geometric Cursors
Representing the 3D cursor position with a geometric
object is straightforward and non-intrusive, as it does
not require modifying existing scene elements. However, it demands careful choices of shape and color such
that the cursor remains clearly visible without introducing distracting visual interference.

4.1.2
Tripod / Compass
A tripod cursor displays three orthogonal axes emanating from the cursor location. Colorization (red for x,
green for y, blue for z) enables the user to read off spatial orientations. Tick marks along each axis turn the
tripod into a measurement tool. The orientation may be
distinct from the coordinate system used for rendering
to honor specific application-specific coordinate systems. For instance, one axis can align with a sphere’s
local surface normal while the other two span the tangent plane. The numerous geoscientific coordinate systems, such as WGS84 and EPSG variants, benefit from
such a chart-aware cursor.
4.1.3
Box
Particularly in the medical domain using a 3D cursor in
the shape of a box is favored [DDW+ 18] because this
kind of geometry works well for selecting a region of
interest within commonly used volume rendering.
4.1.4
Disc
Displaying the mouse cursor as a disc requires additional knowledge of the scene beyond its world coordinates, but also a normal vector because ideally such
a cursor disc would be oriented parallel to the surface
normal of the object that is hit by the cursor. While for
triangular meshes such a normal vector is always available, this is not necessarily the case for point clouds.
On point clouds a normal vector can be computed by
considering the neighborhood of the point of interest
and then computing the eigenvectors of the local covariance matrix at this location. Under certain circumstances (dominant planarity, see [WPG+ 97, RBC+ 12]
for explanation of shape factors), the dominant eigenvector will be suitable for interpretation as a normal
vector. This dominance of the computed normal vector, and thus its significance, crucially depends on the

point as the tensor origin avoids bias in non-uniformly
sampled regions.

Size
The “best” size of a 3D cursor is a trade-off between
depth perception and visibility at varying distances. A
cursor with constant world-space size maintains a fixed
diameter rworld regardless of camera distance. This preserves stereoscopic depth cues and can serve as a measurement reference, but the cursor inevitably becomes
too small to see at large distances under perspective
projection (under orthographic projection this limitation does not apply).
The screen-space branch additionally accounts for the
field of view (wider FOV causes faster shrinkage with
distance) and falls back to pure world-space sizing under orthographic projection where this correction vanishes. Configurable minimum and maximum radii prevent the cursor from becoming invisible or distractingly
large; these limits apply to all cursor types.

Cursor “Glow”
The geometric and shader cursors complement each
other. However, as discussed in Section 4.3, a fixed cursor size becomes problematic when navigating detailed
scenes with large spatial extent. To mitigate this, we
introduce a glow effect that keeps the cursor identifiable even from distant viewpoints. The glow is inspired
by the appearance of a light source, but its illumination
footprint, with intensity decreasing exponentially with
radial distance from the cursor position, is kept constant
in screen-space size. From a distance, the glow dominates and marks the cursor’s position; up close, the disc
and ring colors take over and the glow is mostly hidden
beneath the disc.

5 INTERACTIVE VISUALIZATION
5.1 Camera Navigation
Because the 3D cursor provides a continuous worldspace position at every frame, it can serve as an implicit
rotation pivot — no explicit user action is needed to define one. This mode of navigation is fundamentally impossible with a conventional 2D screen cursor, which
provides only pixel coordinates (x, y) without depth.
Figure 8: “Cursor Glow” in practice: with the sphere
cursor set to a radius of 1m for precise measurements,
it becomes barely visible in large-scale, complex scenes
such as forests. The added glow, mimicking a light
source, makes the cursor easy to spot even from afar.
We implemented three orbit modes to accommodate
different workflows. In standard mode, the orbit pivot
is placed at the viewport center at the depth of the
cursor, providing a compromise between traditional
lookat-based navigation and cursor-based navigation.
In orbit around cursor mode, the pivot is set directly
to the 3D cursor position; the camera rotates around
this point while the cursor remains stationary in world
space. This is particularly useful when inspecting a
specific feature from multiple angles. In follow cursor
mode, the view first centers on the cursor position via
an animated transition, then orbits around that centered
point. This combines the benefits of explicit centering
with cursor-based pivot selection.
Zooming benefits similarly from cursor depth information. Rather than moving the camera along its view direction (which may miss the object of interest entirely
if the geometry is off-center), the camera can move toward the 3D cursor position. This ensures that zoom
operations converge on the point the user is actually
looking at, not merely the geometric center of the view.
Both navigation and stereo parameterization are enhanced by knowing the actual view distance from camera to object, rather than using fixed parameters or
guessing. To get a precise measurement we employ an
“Autofocus” object, which is implemented as a transparent render object such that it is invoked at the end
of the frame generation. However, instead of actual
rendering, it reads from the depth buffer and provides
world coordinates as output. The Camera Navigation
object uses these coordinates as input, thereby essentially constituting a conditional render loop: once the
Autofocus object senses a change of depth information,
the camera is triggered to re-render the scene.
Which pixel defines the “view distance to the object” is
a matter of choice, corresponding directly to the convergence strategies of Section 3.2: sampling the entire
scene yields a constant autofocus for a given camera
setup, whereas sampling around the cursor makes the
focus track the user’s point of attention — analogeous
to the vergence of human eyes.

With world-space-aware cursor and navigation techniques in place, distance measurements directly in
three-dimensional space are straightforward. Rather
than “guessing” where the 2D mouse cursor may be
in world space, measurement locations are placed
by adding control points at the current 3D cursor
position. Consecutive control points are connected by
segment lines, rendered as (optionally multi-colorized)
3D tubes. The length of each segment displayed as
3D text completes the measurement with quantative
annotations. This geometric representation participates
in depth testing and occlusion instead of appearing as
flat overlays composited in screen space.

DISCUSSION
8.2
Generality of the Approach
The framework has been developed and tested primarily on large airborne LIDAR point cloud data, none of
the individual components are specific to geoscientific
content. The hybrid multiview rendering strategy (Section 3.1) makes no assumption about the underlying
topology of render objects: any combination of points,
triangle meshes, lines, or other primitives can participate, provided each render object honors the ordering
constraint of opaque before transparent. The 3D cursor designs likewise depend only on properties that are
available — or can be computed on the fly — for the
scene at hand: a depth value for the geometric cursor,
an optional surface normal for the disc cursor, and a surface position for the shader cursor. The floating-origin
treatment (Section 2.3) is relevant whenever world coordinates exceed single-precision range, which arises in
any application where the data extent is large compared
to the desired resolution. Astronomical data, mentioned
as an example of a translucent-billboard scene in Section 3.3.4, fits the framework in this respect, though
the depth-based convergence strategies do not apply to
such scenes (see Section 8.2). Rather, using a constant
zero convergence is the required in such scenes without
depth information.
Limitations
Several limitations of the current approach are worth
stating explicitly. First, as outlined in Section 3.3.4,
both cursor-based and sampling-based convergence
strategies rely on depth-buffer information. Scenes
composed primarily of semi-transparent elements —
e.g., star fields rendered as translucent billboards —
fail to produce depth values, rendering these strategies
ineffective. In such cases, a fixed convergence distance
derived from the dataset’s bounding volume is the
only practical fallback, though this approach is further
constrained when the far plane is set to infinity. Second,
as described in Section 3.4, the computational cost of
the bokeh effect scales with the number of views, necessitating careful performance tuning for high-quality
results. Third, switching or blending between focusing
strategies is not yet automated and currently requires
user selection based on scene characteristics.

CONCLUSION
We have presented a framework for interactive exploration and measurement within large datasets. It combines a hybrid multiview rendering strategy that accommodates both modern single-pass and legacy multipass
render objects, a set of geometric and shader-based 3D
cursor designs suited to heterogeneous scene topologies, and cursor-driven interaction modes — including
187
WSCG 2026, CSRN Vol. 3601
ISSN 2464-4617 (print)
ISSN 2464-4625 (online)
Computer Science Research Notes - CSRN
depth-aware navigation and accurate 3D distance measurement — that are not achievable with conventional
2D pointers.
The multiview infrastructure serves double duty: it provides the single-pass stereo rendering needed for consistent imagery on big out-of-core datasets, and generalizes naturally to a bokeh effect that enhances depth
perception even on monoscopic displays. The convergence strategies developed for stereo parameterization demonstrated that no single approach handles all
scene types; cursor-based convergence excels on dense
surfaces, while scene sampling proves more stable on
sparse or cluttered data. The 3D measurement tool
demonstrates the practical utility of the cursor infrastructure: control points placed in world space yield
Euclidean distances independent of screen projection,
with a dynamic scale system introduced to achieve sustained visibility across a wide range of viewing scales,
which is essential when navigating and exploring huge
data sets.
Future Work
Extension toward volumetric point-cloud selection using the same cursor infrastructure is a direction for future work. A 3D point-cloud selection tool based on
the same cursor infrastructure is currently under development. Switching between the diverse focusing strategies, or blending them, is a direction worth pursuing.
