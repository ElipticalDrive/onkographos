Summary
A NIfTI vector field is stored as a (X, Y, Z, 1, C) array. _field_to_model in nifti/_views.py dropped the fourth axis only when it had length one, and returned every other array unchanged. A (X, Y, Z, T, 3) file with T > 1 therefore reached the data model as a four-dimensional grid of 3-vectors, which is wrong and raised no error. The VECTOR and SPM y_ coordinate-field readers and the FSL FNIRT reader were affected. The writers also accepted such an array, whether it was assigned as data or read from a file.
A file like this holds one field for each volume of a time series. The data model cannot represent that yet (batched transformations, #576), so this pull request refuses such an array in both directions:
_field_to_model raises ParserContentError, and _field_to_disk raises WriterError. Both use a new helper, _check_single_field, whose message gives the shape and says that a field per volume is not supported yet (Batched transformations: one transformation per element of an axis #576). Every reader that goes through the helper refuses the file: VECTOR, SPM, DISPVECT, FNIRT (through _raw_field), NiftyReg and AFNI.
The encoders of these six formats check the stored array when they write it as it is. A field whose chain was assigned is not blocked by its old rawdata.
The "nothing pending" shortcut of each consolidate checks rawdata too. Without that check, a plain save() would copy such a file unchanged, while save(description=...) would refuse it.
The sniffs are unchanged on purpose. Such a file is still dispatched to the coordinate, SPM, displacement or FNIRT reader, so the user gets this specific error and not a generic "no parser could read it". Loading stays lazy, so the error is raised when the data or the field is first used.
Tests
New tests write a synthetic (4, 4, 4, 2, 3) NIfTI file. All 15 fail without the fix and pass with it.
tests/test_io_nifti_fields.py:
VECTOR files (with and without an intent), SPM y_ files and DISPVECT files: the data and the view that samples it raise ParserContentError.
A field read from such a file refuses to be saved, with and without options, and no file is created.
An array of this shape assigned to each of the three classes is refused on save.
tests/test_io_fsl.py: the FNIRT chain refuses such a file, and the FNIRT writer refuses to save it, whether the field was read or assigned.
ruff check ., ruff format --check . and codespell on the changed files are clean. The NIfTI, SPM, FSL, FNIRT, NiftyReg, AFNI, ITK NIfTI and conformance suites pass (2308 passed, 313 skipped).
