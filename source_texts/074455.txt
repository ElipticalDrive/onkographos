Converts a volume grid into a point cloud. This is useful for debugging
volume grids and for visualizing grid topology more accurately than current
viewport display methods.

Each point represents a grid voxel, or a larger grid node if _Use Tiles_ is
enabled. The grid values are converted into a point attribute.

The resulting point cloud can be inspected as-is, or can be used to create
more advanced representations such as meshes or instances. Attributes can be
inspected in the spreadsheet in lieu of grid values which are not directly
accessible at this point.

@mod_moder I was planning on implementing 3 modes:
Voxels: Outputs single voxels, all larger tiles with values are voxelized first. No "Level" and "Bounds" outputs needed here.
Tiles: Outputs larger tiles as a single node, with the bounds min/max outputs.
Grid Nodes: Output only the grid node hierarchy, but no final voxels or tile values. (The naming of "nodes" is a bit unfortunate but that's just what OpenVDB calls them. Maybe "Levels"?)
The Tiles and Grid Nodes modes can be useful for debugging. For example during development bugs can happen due to incorrect handling of values across grid node boundaries, in those cases it can be useful to be able to visualize the grid structure. Since this node is primarily intended to help with further volume node development i think it's valid to have these more technical options.

Yes, right now it computes point position as the minimum corner of the voxel, by just applying the transform to the coordinate. Can be changed to the voxel centers by adding 0.5 to the coordinates.
```
positions[points_range[i]] = math::transform_point(transform, point_data.coords[i]);
```
The meaning of the transform is actually somewhat up to interpretation, since OpenVDB doesn't really care about what "object space" the transform targets. But if you assume that coordinate (0,0,0) maps to the minimum corner of the grid bounds then this would yield the minimum corner of each voxel too.
I'm not 100% certain we are consistent in our interpretation of the grid transform, especially when it comes to GPU code. The fuzzy nature of the current viewport display and the wonky outline computation makes that a bit difficult to verify.
