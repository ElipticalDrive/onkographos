Follows #9733, which added Compute#setupDispatchThreads. This moves the engine's and the examples' dispatches of a thread per element over to it, so their workgroup counts come from the workgroup size the shader declares.
Changes:
The gsplat projector and the gsplat shadow cull dispatch a thread for each splat. Large dispatches are spread over rows of workgroups by setupDispatchThreads, and the shaders index their threads using the dispatchThreadsCS chunk, replacing the hand-written tiling and the workgroup size repeated in JavaScript.
The gsplat interval cull dispatches a thread for each interval.
Dispatches where each workgroup processes a block or an interval (radix sorts, prefix sum, interval scatter) and the single-thread argument writers keep using setupDispatch.
Examples:
histogram, texture-gen, edge-detect, scene-maps, vertex-update and indirect-dispatch set up their dispatches using setupDispatchThreads.
histogram and texture-gen use 8x8 workgroups instead of a single thread per workgroup, and skip the threads beyond the image.
vertex-update no longer dispatches a workgroup of 64 threads for each vertex.
The indirect-dispatch tile scan uses 8x8 workgroups instead of a single thread per workgroup.
