Closes #106.
Ray-traced volumes
A cube can now be drawn as light, as the particles of #101 are. Each voxel emits and, optionally, absorbs; the light along each ray is summed in floating point, without a ceiling, and graded by the same tone curves. A cube with a large dynamic range keeps both its faint diffuse emission and its bright cores, with no opacity curve to tune by hand. The analysis rendering (Composite, MIP, MinIP, threshold, colour bar) is unchanged; this is a presentation style switched on with Ray-traced light in the cube viewer's Display, 3D section.
Two styles:
3-D light: emission and grey absorption in perspective;
Projected map: the column along each line of sight, without perspective, optionally within a slab, brightness from its logarithm.
Colour from a second quantity:
another field of a VBT volume (a simulation's density lit and coloured by its temperature);
for a spectral cube, each channel's velocity in km/s (a frequency axis as optical velocity from RESTFRQ), on a linear scale over the velocities holding 98 % of the light, with Coolwarm seeded. Seen along the spectrum, a projected map coloured by velocity is the intensity-weighted mean velocity.
Dark below the threshold: values under the 3-D view's threshold emit nothing. A ray sums every channel it crosses, so a radio cube's noise otherwise veils the source. On by default for a cube with negative values, off for a simulation's grid.
In the window:
drawn on the desktop's GPU, ray-marched through a grid the backend prepares once (at most 256³, strided from a larger cube);
while it is on, the analysis controls that draw nothing in it are hidden; the threshold stays when it darkens;
its map starts from the 3-D view's, and its colour bar is drawn exactly as the 3-D view's (same place, size, type, labels);
without a GPU view (remote desktops, old drivers) the backend draws the frames from the same grid, with the box and colour bar drawn over them on the desktop.
Output: stills up to 8K, orbit movies, PNG and floating-point FITS of the light, rendered by the backend from the full cube, with box and colour bar.
Remote backends:
the view starts from the remote (EGL) view's camera and hands it back with set_camera when it is switched off, so the remote view goes on from where the ray-traced one was turned to;
the grid is gzipped for a client on another machine: below the brightness floor it is zeros, and through a tunnel a WALLABY grid goes from 34 MiB in 8 s to 0.4 MiB in 0.4 s. The desktop lifts Qt's decompression safety threshold for that one request (a floored grid expands about 130×).
Backend
app/volume_raytrace.py (numba): ray march, projected maps, emission with a brightness floor, colour index, light-weighted velocity range.
app/routers/volume_render.py:
POST /v1/tasks/volume_render: stills and movie frames (frames, tone, light and deletion through the particle-render routes);
POST /v1/volume_render/grid: the GPU view's grid;
POST /v1/volume_render/preview: a JPEG frame for a desktop without a GPU view.
Request fields: brightness_floor, colour_by: velocity.
New header X-Visivo-Colour-Table (contract regenerated).
Cube render sessions accept set_camera; its validation is shared with point sessions.
Smaller changes
Colour-bar labels: values of a thousand or more are written out (1232, not 1.23e+03) when every tick stays distinct; shared by both bars (ColourBarTicks.h, tested).
A finished still reports its voxels, not "0 particles".
Tested
Tests: backend 2042 passed; C++ 538 passed.

Add backend and desktop support for ray-traced volume rendering (issue #106).

Backend: numba ray-marcher (volume_raytrace.py) for emission/absorption with a second-field colour index and projected maps. New /v1/tasks/volume_render task (stills and movies, reusing the particle render result routes via a shared run_frames/start_render_task) and /v1/volume_render/grid, which prepares grids for the GPU view. Render sessions now report their camera in /levels. A process-wide numba lock (numba_parallel.py) serialises parallel kernels, since the workqueue threading layer aborts on concurrent use.

Desktop: ParticleGLView gains a grid ray-march shader; RaytraceViewport and RaytraceOutput are generalised to support grids and a configurable task path. New VolumeRaytracePanel and a "Ray-traced light" option in the cube viewer.

Also adds new response headers, tests, and docs.

Match ray-traced colour bar and hide classic controls

1d936b2
```
The ray-traced colour bar now reuses VolumeColorbar's layout and painting (placement/paint, Look struct), so it looks the same as the 3-D view's bar. It uses the window's font and scales with the output picture size relative to the view.

While "Ray-traced light" is on, the analysis rendering's controls (mode, blend, lighting, threshold, colour map, 3-D layers) are hidden because they draw nothing in it. They return when the check is cleared or when no camera is available.

The ray-traced panel now shows the basic settings first, with the rest under "More settings", and its map starts from the 3-D view's colour map. The user guide is updated.

Add brightness floor to ray-traced volume light
…
b94ce02
```
Radio cube noise, summed over every channel along a ray, veils the source in ray-traced renders. Add a `brightness_floor` request field so values at or below the 3-D view's threshold emit nothing.

Backend: `emission_from` applies the floor on the logarithms themselves (avoids rounding and overflow of 10**floor) and never lights negatives. The floor is part of the grid cache key.

GUI: add a "Dark below the threshold" checkbox, on by default for cubes with negative values. The threshold control stays visible in the ray-traced view when it darkens, and a threshold change re-prepares the grid after a debounce. The colour bar title is now shared via `volumeBarTitle()`, and the render summary counts voxels for volumes.

Tests and docs are updated.
