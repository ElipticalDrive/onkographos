Issue body actions
For a fixed rig, most of the scene is static yet pays full 4D cost. Split: pretrain background as pure 3D gaussians with 3D SH (16 vs 48 channels — SH is 89% of the 644 B/gaussian footprint), freeze or slow-update it, spend 4D capacity on the performer.
Literature: Splatography (arXiv 2511.05152) reports up to +3 dB at half model size on sparse filmmaking rigs; Ex4DGS and QUEEN use similar splits. Natural hook: the temporal mask already built at gaussian_renderer/init.py:66-68 — cov_t spanning the whole clip ~= static. Also kills background flicker. Biggest combined speed+quality structural change available.

Full version measured. Negative on every arm — the lite freeze's +0.6–0.7 dB does not extend, and the evidence says it worked for the opposite reason to the one assumed. PR #41 (stacked on #40), write-up in docs/experiments/2026-08-16-issue-20-static-dynamic-split.md.
Step 2 answered — why the frozen set was only 2.5%. Two structural causes, measured with a new scripts/temporal_stats.py:
The whole-clip criterion is unreachable at init: scaling_t starts at duration/5, giving a half-width of 2.448 against the 2.500 a centred gaussian needs. The static set can only ever contain gaussians that grew their temporal extent.
densify_and_split divides scaling_t by 0.8N per generation, so temporal support shrinks geometrically — median cov_t 1.0 → 0.022, median gaussian covering 7% of the clip. The logged 19% → 1% collapse spans exactly the densification window.
Raising the static fraction works, and makes things worse. A persistent label carried through prune/clone/split takes it from 2.5% to ~30%. Held-out then falls monotonically with background share:

The split is not broken: background carries more weight than the dynamic layer (mean opacity 0.611 vs 0.326), train PSNR is within 1 dB of control, and background rows are bit-exactly frozen (302,970 rows, zero drift — the e52a797 Adam-drift bug does not reach this path). What moves is the train/held-out gap, 6.15 → 10.42 dB, with the best checkpoint at iteration 1,500 of 7,500.
Reading: the lite freeze won because its set was small and self-selected. Freezing gaussians that already earned whole-clip support through the loss is a mild regulariser on genuinely static content; imposing whole-clip support makes broad temporally-constant primitives explain a 5 s clip from 8 viewpoints, and they fit the time-averaged training views in a way that does not transfer.
Step 1 (background pretrain) tested as specified and also negative: −2.82 dB. After 1,500 iterations against per-camera medians, 28.4% of gaussians are already below the prune threshold — fitting 75k gaussians to 8 median images is badly under-constrained here, and the main run inherits that geometry. Since L1 already pulls a temporally constant gaussian toward the per-pixel temporal median, the pretrain buys a worse version of something the main objective does for free.
bg_static_frac also does not control the background share (0.2 → 28.5%, 0.5 → 29.8%): background gaussians are temporally visible every frame and win densification consistently. So the approach cannot be rescued by tuning it down.
Step 3 (3D SH for the static subset) not attempted, per the "only if 1–2 pan out" condition. Scoping note in the write-up: force_sh_3d exists but is global; per-gaussian routing needs a branch inside the rasterizer's SH evaluation plus a ragged feature buffer.
Separate defect found on the way. readColmapSceneInfo normalises the frame index to [0, 10) regardless of clip length, so this config's time_duration: [0.0, 5.0] describes only the first half of its own 150-frame data — cameras span [0, 9.933]. Gaussian init, the rasterizer's temporal SH period and every whole-clip test read time_duration. Correcting the gaussian side costs 1.0–1.5 dB held-out on both seeds, so the accidental narrow init is acting as a regulariser. Worth its own issue, but explicitly not a naive fix — happy to file it if you want.
Recommendation: close #20 as tested-negative and keep the lite --freeze_static_temporal as shipped. Three independent levers here all traded held-out for train fit, which is a capacity/regularisation signature rather than a representation one — that argues for Tier 2.2 (depth supervision) and 2.3 (pose deltas / colour affine) ahead of more structural work on the 4D representation.
Caveat: all eight runs predate e52a797, so they are internally consistent but the control's absolute numbers were measured with a freeze that only partly held. Re-running the lite A/B on the fixed base is worth doing on its own.

One no-freeze run cannot settle that, and both seed-44 runs predate e52a797 (so they measure the partly-holding freeze). But it should be resolved before #40 merges — two or three more --no-freeze_static_temporal runs re-scored on the full set would do it. I have not run those; flagging rather than acting since it is #40's scope, not this issue's.
If it holds, the premise of this issue — "the lite freeze won +0.6–0.7 dB, so raising the static fraction should amplify it" — rests on a measurement artifact, which would also explain why every attempt to amplify it made things worse.
