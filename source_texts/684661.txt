Hardware textures, steps T2a–T2d of the texture plan: every image the materials read becomes a GPU texture. On CUDA that is a cuArray with texture objects; on Vulkan, a bindless VkImage. Linear reads are filtered in hardware.
The stack renders 7–9% faster than main on both backends. Every step before T2d is exact.

T2a: images apart
Each image the materials read is piped as its own array and found through a table, by its index (bit 31 of the texture's height).
The SCENE header gains an eleventh count, the number of images, after instancing's ten. The record grows to 608 bytes (RECORD_STRIDE).
An empty texel entry, such as a UV-space bake's empty tile list, shares its first slot with the next entry. It is classed as no image.
T2b+c: textures
CUDA: one cuArray and texture object per image: FLOAT×4 or UNSIGNED_INT8×4, read as integers, point-filtered and clamped. texel() fetches the texel at its centre and decodes it as main does.
Vulkan: the shim stands in for the same driver calls with a VkImage per array (R32G32B32A32_UINT or R8G8B8A8_UINT), uploaded through the staging buffer.
One bindless descriptor set holds up to 65536 sampled images.
renderer.slang reads them with an exact Load through NonUniformResourceIndex.
Device creation requires runtimeDescriptorArray, shaderSampledImageArrayNonUniformIndexing and descriptorBindingPartiallyBound, and fails plainly without them.
The exporter pipes each image's width and height; the loader frees textures with the scene and counts them in the memory stats.
Lookup
An image read looks its texture up once, in its filter, instead of once per tap.
Linear and cubic reads no longer fetch the closest texel first. Main fetched it and then overwrote it.
T2d: hardware linear
CUDA: each image gets a second texture object, filtering linearly with normalized coordinates and an address mode by its extension (wrap, clamp, border, mirror). RGBA8 is read normalized, and decoded from sRGB in hardware before filtering where the image is sRGB.
Vulkan: mutable-format images get a float view (UNORM or SRGB for RGBA8, SFLOAT for floats) in a second bindless array, with four immutable samplers by extension.
Both: linear reads of images take one hardware fetch. Tables and bake-only images keep the software path.
Test change: make test's node check 'Image Texture' reads a 1×1 image linearly under CLIP and compares it with Cycles. The hardware's 8-bit filter weights give 0.3203125 where the exact value is 0.4 × 0.8 = 0.32. Its four linear reads of that test image are now compared at 2^-8, one step of those weights; nothing else was loosened.

Finding, robustness, not blocking on NVIDIA: the shim samples an R32G32B32A32_SFLOAT view with a linear
sampler. The Vulkan spec doesn't require VK_FORMAT_FEATURE_SAMPLED_IMAGE_FILTER_LINEAR_BIT for 32-bit float formats,
and cuCtxCreate doesn't check it. On a device without it, the result is undefined rather than the plain failure the
three descriptor features get. Suggested: check optimalTilingFeatures for that format in cuCtxCreate, and fail
plainly or keep float images on the software path. Unmeasured on non-NVIDIA hardware, which is out of testing.
