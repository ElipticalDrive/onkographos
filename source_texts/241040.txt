modules/highgui/src/window_gtk.cpp:909
These dimensions are scaled to physical framebuffer pixels for GTK's HiDPI viewport, but Window::draw still passes the unscaled getWindowImageRect().size() to the splat shader as its viewport. The focal-length and pixel-covariance uniforms consequently mix logical and physical units, so splats have the wrong projected size on scaled GTK displays. Propagate the same physical dimensions to View::setViewport (or keep the viewport calculation in one backend-aware path).
```
        const int scale = gtk_widget_get_scale_factor(GTK_WIDGET(area));
        glViewport(0, 0,
                   gtk_widget_get_allocated_width(GTK_WIDGET(area)) * scale,
                   gtk_widget_get_allocated_height(GTK_WIDGET(area)) * scale);
```
modules/ptcloud/include/opencv2/ptcloud.hpp:82
The ply_properties documentation promises that a renamed copy can load exporters with differently named properties, but this path calls parseHeader, which unconditionally requires literal x, y, and z vertex properties before the name mapping runs. A PLY with renamed position fields therefore still fails; either make the required-position checks honor the supplied names or narrow the documented contract.
```
 * The order of the names is the column order cv::decodeGaussianSplats expects. Pass a renamed copy
 * of this list to cv::loadGaussianSplats to read a scene whose exporter spells the properties
 * differently, keeping the same order.
```
modules/ptcloud/src/splat.hpp:56
toRotMat3x3(QUAT_ASSUME_NOT_UNIT) normalizes the quaternion and throws when its norm is below CV_QUAT_EPS. Thus one zero/tiny raw rotation makes decodeGaussianSplats fail, while the packed decoder explicitly treats the same degenerate rotation as identity. Normalize this input consistently or substitute an identity quaternion before constructing the covariance.
```
    Matx33f rs = Quatf(rot[0], rot[1], rot[2], rot[3]).toRotMat3x3(QUAT_ASSUME_NOT_UNIT);
```
