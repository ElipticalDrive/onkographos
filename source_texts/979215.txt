Add template-selected Morton key storage:
```
cuBQL::cuda::radixBuilder<uint32_t>(bvh,boxes,numBoxes,config);
cuBQL::cuda::radixBuilder<uint64_t>(bvh,boxes,numBoxes,config);
```
The 32-bit variant sorts its populated 30/30/28 bits in 2D/3D/4D. The higher-precision 64-bit variant uses 62/63/60 populated bits and sorts all 64 bits. Existing calls remain supported; centroid bounds retain the input scalar type. Original commented code is preserved.
The self-contained generator creates 2,097,152 deterministic float2 boxes (32 MiB), fingerprint 889bf680e24ea901. tests/data/sample.jpg previews 4,096 rectangles from the same generator.
A100 80GB PCIe, CUDA 12.4, commit e380aa9: legacy uint64 storage/full-64-bit sort versus actual uint32 storage/30-bit sort at equal quantization. Each run uses six alternating pairs, one warmup per mode, leaf threshold 16, and complete-builder CUDA-event intervals.

Median build time decreased by 18.5-19.4% (1.227-1.241x) across three runs. All 27 cases and benchmark CPU query checks passed on A100, including the higher-precision uint64 mode. Existing-call compatibility and precompiled library linkage also passed validation.
Reproduce on A100:
```
git clone --branch cuBQL/morton_change https://github.com/Nakul1322/cuBQL.git cuBQL-morton
cd cuBQL-morton
cmake -S . -B build-morton -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=80 -DCUBQL_BUILD_TESTS=ON
cmake --build build-morton --target cubql_morton_sort_range -j
ctest --test-dir build-morton --output-on-failure
for run in 1 2 3; do ./build-morton/cubql_morton_sort_range --benchmark 256 256; done
```
