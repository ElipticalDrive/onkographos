Description
Follow-up to #912. PointCloudMaterial's adaptive sizing (the uActiveNodes octree walk) is only fed by PotreePlugin. Any other ADD-refined point cloud gets one size per tile, so points of a parent tile stay large next to a loaded child and overlap it, and the cloud looks blotchy wherever two levels meet.
Implicit OCTREE tilesets already carry what the Potree driver computes: (level, x, y, z) is the octree key, the tile's geometricError is the spacing, availability comes from the subtree.
Test tileset (implicit ADD octree, geometric error = spacing halving per level):
https://jo-chemla.github.io/3dtiles-samples/lion_takanawa/implicit-octree/tileset-x100.json
Solution
Drive the same active-nodes texture from the loaded implicit tiles, so the material sizes points for them exactly as it does for Potree. Rough shape:
move the texture encoder out of PotreePlugin into a shared helper keyed by an octant path (for implicit tiles, octant = 4·dx + 2·dy + dz per level from implicitTilingData, which is already the convention the shader walk uses);
turn uNodeMinOffset into a mesh-to-root matrix, since glTF content is rotated relative to the root box (Potree points are not);
have PointCloudEffectsPlugin assign the texture, uNodeSize and the matrix for tiles whose implicit root is an ADD OCTREE, and re-encode when the active set changes.
Root boxes assumed cubic, as in Potree. Happy to do the PR; tell me if you would rather see it as its own plugin or in a base PotreePlugin extends.
Alternatives
Sizing by loaded child bounding boxes: pass each tile's up-to-8 loaded child boxes as a uniform and shrink points that fall inside one. Works for explicit ADD tilesets too (no octree key needed) but caps at one level of children and costs 8 box tests per vertex. That is what we run locally today.
Leaving it per tile and relying on the error target: avoids the overlap only by refining further than needed, which is more points for a worse result.
Additional context
The same tileset shows the ADD-skip regression tracked in #1781 / #1782; load it close (under about 1 km on the x100 version) until that lands.
