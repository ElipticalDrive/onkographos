Description
This pull request replaces the previous CPU-bound ImmediateMesh grid with a high-performance, GPU-driven shader implementation. The new grid is conceptually infinite, offers superior visual quality with anti-aliasing, and features an adaptive Level of Detail (LOD) system that smoothly adjusts to camera zoom.
The Problem with the Old Grid
The former grid implementation, which used ImmediateMesh to draw lines on the CPU, had several key limitations:
Performance: It was computationally expensive, requiring the generation and submission of a large number of vertices every time the camera moved or zoomed significantly.
Finite Size: The grid was confined to a fixed grid_max_render_size, which meant it would abruptly end, breaking the sense of an expansive 3D world.
Complex Redraw Logic: It required stateful logic in world_3d_view.gd to track camera movement and decide when a costly redraw was necessary.
Visual Artifacts: The grid lines suffered from aliasing and would "pop" in and out of view as the LOD changed, creating a jarring user experience.
Key Changes & Implementation
This PR addresses all the above issues by moving the grid rendering entirely to the GPU.
1. New grid_shader.gdshader
A new spatial shader has been created to render the grid. It employs a modern, efficient technique:
Full-Screen Quad & Ray-Plane Intersection: Instead of drawing a massive mesh on the ground, the shader is applied to a simple 2x2 QuadMesh that always covers the screen. The vertex shader calculates a direction vector (a "ray") from the camera through each pixel. The fragment shader then calculates where this ray intersects the conceptual y=0 plane.
Infinite Appearance: This technique means the grid is drawn wherever the ground plane is visible, regardless of camera position or orientation, creating a truly "infinite" grid.
Anti-Aliasing: The shader uses fwidth() to calculate the world-space size of a pixel. This allows for rendering perfectly crisp, anti-aliased lines that remain a consistent visual width and don't shimmer or break apart at sharp viewing angles.
2. Adaptive Level of Detail (LOD)
The logic for managing the grid's detail has been rewritten in world_3d_view.gd's _process loop to control the new shader.
Logarithmic Scaling: The major and minor grid spacing are now calculated based on a logarithmic scale of the camera's distance from its target. This provides a natural and intuitive scaling of the grid as the user zooms in and out.
Smooth Fading: To eliminate the "popping" of grid lines, a fade_factor is calculated and passed to the shader. It uses smoothstep() to gently fade the minor grid lines in and out as the camera approaches the next LOD threshold, ensuring a seamless visual transition.
3. GDScript Simplification & Cleanup
The world_3d_view.gd script is now significantly cleaner and more efficient:
Removed _update_grid(): The entire ImmediateMesh generation function has been deleted.
New _setup_grid(): A new one-time setup function creates the QuadMesh and ShaderMaterial, assigning the new shader.
Simplified _process(): The complex logic for checking when to redraw the grid is gone. The _process() loop now only performs the lightweight task of calculating the LOD parameters and passing a few floats to the shader as uniforms each frame.
Removed Obsolete Properties: All @export variables related to the old grid (grid_max_render_size, axis colors, etc.) have been removed and replaced with new ones that directly control the shader's uniforms.
Summary of Benefits
Performance: Massively improved rendering performance by offloading all grid drawing to the GPU.
Visual Fidelity: The grid is now infinite, anti-aliased, and features smooth LOD transitions.
Code Maintainability: The rendering logic is now cleanly encapsulated within the shader, and the controlling GDScript is simpler and more focused.
