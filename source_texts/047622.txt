What changed
This PR hardens the voxelization pipeline and expands the MultiBunny scene set used for mesh/voxel comparisons.
adds generation prechecks and explicit failure handling for high-resolution voxelization
adds GPU solid-voxel overflow guards instead of allowing out-of-bounds writes
moves the CPU clipAll() stage onto a background task with status reporting and cancellation hooks
adds a High Memory Mode switch plus finer voxel-resolution steps in the UI
updates the current MultiBunny layout to a denser 1.5x arrangement and renames the mesh launcher from run_HybridMeshVoxel.bat to run_MultiBunny_Mesh.bat
adds Scene/MultiMultiBunny.pyscene as a denser follow-up scene
records the implementation and investigation notes in docs/memory and docs/handoff
Why
High-resolution voxelization was stalling or crashing because dense voxel index volume, CPU clipping cost, and GPU solid-voxel capacity were all allowed to scale into unsafe territory.
The MultiBunny scenes also needed denser variants and consistent launcher/cache naming so mesh and voxel comparisons stay aligned after layout changes.
Impact
high-risk voxelization requests now fail early with actionable messages instead of hanging or overrunning buffers
CPU voxel generation no longer blocks Mogwai for the full clipping stage
high-memory machines can intentionally opt into a larger dense-voxel safety envelope
MultiBunny comparisons now have denser scene variants and updated launch entry points/cache prefixes
