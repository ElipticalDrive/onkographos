Hey, thanks for trying out this repo!
Are there any future plans for this?
ReSTIR is a powerful sampling algorithm, but since the lights in SSPT (initial rays) are rendered via rasterization, it may not be suitable for this repo AFAIK.
However, I know there are still some sampling improvements that could be considered:
1. Environment Importance Sampling
For any point on a surface, we can get its lighting conditions in different directions from reflection probe. (By sampling the probe along a given direction)
Darker areas require fewer samples. For example, if the reflection probe shows pure black (indicating no lighting in the scene), rendering just 1 sample produces the same result as 1,000 samples.
By using an environment importance map to bias the random sampling directions, we can reduce the samples needed for the image to converge.
Check this for details: Environment map importance sampling - Karim Naaji
2. Reuse nearby samples if valid (similar to ReSTIR)
I'm not familiar with its details yet, maybe I can look into it when I have time.
Hoping these improvements could be easy to implement in Unity.
... and does not need to build a BVH.
I don't have plans to add BVH tracing yet, but this is possible since Unity has already done the most challenging part for us. (Unified RT package)
One problem is that BVH only stores the UVs of hit points. So for compute-based ray tracing, we need to collect & update the objects' material data into texture atlases or arrays, which makes adding it more complicated.
