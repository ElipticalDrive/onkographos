Implements docs/superpowers/specs/2026-08-12-volume-raymarch-acceleration-design.md via docs/superpowers/plans/2026-08-13-volume-raymarch-acceleration.md (8 tasks, subagent-driven).
Why: 95.2% of the scalar-volume raymarch's samples are provably zero under the shipped transfer function; the pass is cheap today only because it runs at 1/3 resolution with a hard 128-step cap.
What:
generateMipChain3d — new gpu/lib primitive filling 3D-texture mip chains via depthSlice render passes (box variant for display mips, deviation-space max variant for skipping)
Per-field max pyramid (dims/8) stored in deviation space — skip cutoff derived in-shader from live contrast/trim uniforms, so slider changes retune skipping with nothing to rebuild, correct for sequential (MCPM) and divergent (CF-4) palettes
Cone-footprint LOD + step sizing from the LOD'd voxel size — sample density tracks screen content, not camera distance; attacks the stationary-shimmer/aliasing at its cause
volume-inside perf scenario as the measurement gate; volume target raised 1/3 → 1/2 res only if the harness numbers allow
Wire compression (spec Stage 0) is separate: #554.

…volume march

Replaces stepLength = (tMax-tMin)/STEP_COUNT (sample density ∝ camera
distance, the aliasing/shimmer source) with sample density ∝ what's
actually on screen: coneLod(t) picks the mip whose texel size matches
one pixel's footprint at march distance t, textureSampleLevel samples
at that LOD, and stepLength tracks the LOD'd texel size (voxelSizeLocal
* 2^lod * STEP_QUALITY). STEP_COUNT (128->256) is now an iteration
safety cap only. The pyramid skip check is throttled to every 4th
iteration (SKIP_CHECK_STRIDE) since near-camera LOD-0 steps are
voxel-sized and re-testing membership every step is redundant; the
skip jump now lands directly on the cell's exit point since there's no
fixed step-grid left to stay phase-aligned to.

Visual: volume-inside and local-group match Task 5's look (no LOD
popping, near-camera detail unchanged); captures in task-6-visual/.

…skip re-jitter

Addresses task-6-review's three Important findings against the cone-LOD
scalar-volume march (0218c61):

1. volumeSampler omitted mipmapFilter (WebGPU default 'nearest'), so the
   fractional cone-LOD snapped between mips instead of blending -- hard
   detail-shell edges that slide with the camera. Set mipmapFilter: 'linear'.

2. STEP_COUNT=256 could truncate a ray mid-cube at tier large: honest
   LOD-driven steps near the camera are voxel-sized, and 256 of them fall
   short of a large-tier cube's diagonal, silently dropping the far half of
   the cosmic web. Added a per-iteration step floor,
   stepLength = max(lodStep, (tMax - t) / (STEP_COUNT - i)) -- a no-op
   whenever the LOD step already fits the remaining budget, growing only as
   the cap approaches, guaranteeing every ray reaches tMax.

3. The skip-jump's direct t = skipExitT + eps re-synchronised every ray that
   skipped the same pyramid cell onto that cell's exit plane, undoing the
   entry jitter's decorrelation -- stationary banding at MCPM's
   densityScale=18. Re-jitters on resume with the ray's own hash, salted by
   iteration count so consecutive skips on one ray don't repeat an offset.

Visual: volume-inside and local-group (tier medium) match the prior build;
no new popping or banding. New tier-large volume-inside capture shows no
obvious "missing far half" wall (consistent with the review's own
prediction that the truncation reads as dimming, not a hard edge).

Perf: paired A/B vs Task 5 base (34d6127), --tier large --scenario
volume-inside, 8 rounds. Base is stable at 2.16-2.23 ms volume-COSMO
every round. The fix ranges 1.38-3.77 ms (median 2.13, mean 2.24) --
bimodal/trimodal rather than noisy-continuous, consistent with the
step-floor's early-completion break interacting with the entry-jitter
phase. Net: recovers the pre-fix build's clean +27% regression (2.2 -> 2.8
ms, stable) into a wider-variance cost that averages back to parity with
baseline -- sometimes better (3/8 rounds ~1.4 ms), sometimes matching the
old regression (4/8 rounds ~2.8-3.8 ms). Not a clean win at this pose/tier,
but the ray now provably reaches tMax at every tier instead of silently
truncating.

Covering tests: scalarVolumeLayer + volumeFieldRenderer suites (17/17),
npm run typecheck green, full npm test green (1023 files / 6903 tests).
