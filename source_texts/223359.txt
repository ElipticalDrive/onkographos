What changed
RenderFrameContextManager no longer keeps HlodViewSlot[4] histories. gs_hlod_runtime::ViewSet is the single owner of per-view cut state. The manager keeps only a thin lifetime binding per view (buffers id, render target, lifetime epoch, snapshot owner, LRU clock); no cut state is duplicated.
View key = mix(RenderSceneBuffersRD id, lifetime epoch). A view is dropped and re-admitted exactly where the old slot reset: epoch change, render-target change, new snapshot object, LRU eviction at 4 views (HLOD_MAX_VIEWS). ViewSet::remove_view releases the reservation on every drop, so nothing leaks from an old epoch.
Policy-hash invalidation is delegated to ViewSet (tau, tile area, caps are in its policy hash; same inputs as the old renderer hash). A snapshot or caps that outgrow the reservation are repaired by one re-admission against the current snapshot, otherwise an explicit refusal.
prepare_hlod_frame builds a SelectionSnapshot from the publisher inputs: one asset, one identity-placed instance holding the view caps (single-asset scope; no multi-asset world). The snapshot is a reused member, refilled in place per frame. Budget = remaining route headroom (route_limit - route_bytes); GPU-side sort/record/draw buffers and payload are already inside the route ledger, so ViewSet charges only the CPU histories and draw records it allocates (no double count). The 80% admission factor and every cap are untouched.
Fallback mapping (hlod_fallback_for_view/admission/snapshot): only a READY view is active. LOADING, NOT_ADMITTED, FAILED, every admission refusal and snapshot over-budget map to the canonical route with an explicit hlod_reason. READY with zero records is the selector's EMPTY status (everything culled), a complete empty cut, as before.
Telemetry: hlod_budget_bound_frames, hlod_root_dropped_frames, hlod_reason keep their meaning and the old reason strings where the cut status is still known (hlod_bootstrap_*, cut_unavailable, complete_view_history_unavailable). New reasons: hlod_view_budget_refused, hlod_view_limit_refused, hlod_view_caps_refused, hlod_view_resources_refused, hlod_view_key_conflict, hlod_view_admission_invalid, hlod_snapshot_over_budget, hlod_snapshot_invalid, hlod_view_reservation_exceeded, hlod_view_not_admitted, hlod_view_failed. The old cut_status_unmapped cannot occur any more. Consumers grepped (tests/runtime GDScript and python): they match only active, unsupported_view_or_material and resource_ledger_warmup_or_unavailable, all unchanged. hlod_cpu_cut_usec now also covers a first-frame or re-admission admission.
ViewSet::ViewResult gained visited_nodes (telemetry hlod_visited_nodes).
Publish order: draw entries are now in NodeKey order instead of CutHistory order. Verified downstream: the list is a lookup table (depth_compute.glsl stores the chunk index per splat from an atomic append; tile_binning.glsl reads entries[index]); splat order comes from the atomic append plus the depth sort, so no sort key, fade pair or telemetry depends on entry order (hlod_selected_parents is a count). GPU confirmation is part of the end-of-stack run.
Deleted
HlodViewSlot, hlod_views[4], acquire_hlod_history, hlod_history_bytes (unused), clear_hlod_histories, the renderer-side tau/capacity/records policy hash and the per-status switch in prepare_hlod_frame. No dead old slots remain.
Intended behavior changes versus base
Selection is not identical to base: the NodeKey tie rank is now passed to the selector, so tied priorities under a binding budget can choose a different (array-order independent) cut.
node_budget is clamped to the asset node count (slot.node_count); where base fell back on node_budget > capacity, the head goes active.
CutHistory::INVALID now maps to hlod_view_failed (was cut_unavailable).
Review-fix round
Headroom shrink no longer flaps: ViewSet::select withdraws a view only when shared payload plus that view own reservation exceeds the budget, not when the total of all views dips under it (SNAPSHOT_OVER_BUDGET is reported only then). Test: headroom below the total but above each reservation keeps both views READY with no re-admission; below one reservation the view is withdrawn with hlod_view_budget_refused.
Tie ranks are cached per (asset key, snapshot object, content revision, node count) and shared by slots (tie_rank_builds() counter); re-admission of unchanged content computes nothing, a new revision builds one table. The cache is pruned on admit/remove, never per frame.
Stale bindings: before every admission, bindings whose buffers no longer resolve in ObjectDB or whose token epoch/target is stale are evicted (evict_stale_hlod_bindings, injectable liveness check). Test: a freed most-recently-used view is evicted while the LRU view is kept, and a freed view releases budget.
acquire_hlod_identity: the pure part (hlod_identity_from_token) and the token epoch behavior (configure, free_data, configure(null)) are unit-tested, as are the no-target and null-buffers refusals. NOT unit-tested: the success path through a live RenderSceneBuffersRD with a valid render target and the custom-data slot (needs a device); the GPU gate covers it.
The reusable snapshot releases its runtime data Ref after every prepare_hlod_frame (scope guard); test checks the reference count.
Mutants, each failing its case: total-based affordability, no rank cache, no stale eviction.
