Owner
Implements M5 tasks T3–T6 of the SOTA roadmap, adding five new example applications that demonstrate advanced rendering features with GPU-backed proofs.
Summary
This PR adds comprehensive examples and infrastructure for:
HDR exposure control with persistent rgba16float scene buffers and post-stage tonemapping
Image-based lighting (IBL) via split-sum BRDF, irradiance convolution, and equirectangular projection
Refractive transmission with IOR-driven Snell refraction and Beer-Lambert attenuation
Screen-space ambient occlusion (SSAO) that attenuates only indirect lighting
Each example includes GPU readback proofs that verify the rendering pipeline produces correct intermediate values.
Key Changes
New Examples (5 total)
hdr-exposure: Demonstrates HDR scene buffer + exposure-driven tonemapping post effect
ibl-brdf: Proves split-sum environment-BRDF (DFG) LUT integration for specular IBL
ibl-irradiance: Compares raw vs. cosine-convolved diffuse irradiance maps
ibl-equirect: Auto-derives cubemap IBL from a single equirectangular HDR texture
transmission-ior: Proves IOR-driven refraction and Beer-Lambert volume attenuation
ssao-indirect: Verifies SSAO attenuates only indirect (ambient/IBL) lighting
Core Rendering Infrastructure
post-tonemap.ts: New HDR→swapchain post effect with baked exposure + operator + sRGB encode
brdf-lut-compute-pipeline.ts & brdf-lut-resource.ts: GPU compute pipeline for split-sum BRDF integration
irradiance-convolution-compute-pipeline.ts: Cosine-weighted hemisphere convolution for diffuse IBL
equirect-to-cube-compute-pipeline.ts & equirect-to-cube-resource.ts: Equirectangular→cubemap projection
standard-indirect-channel-shader.ts: Emits indirect lighting to a separate color attachment (M5-T6)
Material & Pipeline Updates
Extended StandardMaterialAsset with IOR, thickness, attenuation color/distance fields
Added applyStandardSpecularIblBrdfSampling() for split-sum specular IBL sampling
Updated standard-shader-extension-sampling.ts to apply transmission IOR refraction
Modified post-ssao.ts to optionally use indirect color channel instead of whole-image multiply
Added indirectColorFormat support to post-processing pipeline
Test Coverage
E2E tests for all five examples with GPU readback pixel validation
Unit tests for BRDF LUT, irradiance convolution, and equirect-to-cube compute pipelines
Tests for indirect color channel shader variant and post-tonemap WGSL generation
Implementation Details
HDR Scene Buffer: When enabled, the lit pass renders to rgba16float and skips in-material tonemap; the post stage applies exposure and final tonemap once
Split-Sum IBL: BRDF LUT integrates over (NdotV, roughness); specular term becomes prefilteredColor * (F0 * scale + F90 * bias)
Irradiance Convolution: GPU compute pass integrates incoming radiance over cosine-weighted hemisphere; result stored as irradiance/π
Equirect Projection: Maps cube directions to equirect UV via u = atan2(dir.x, dir.z) / (2π) + 0.5; v = asin(clamp(dir.y, -1, 1)) / π + 0.5
SSAO Indirect-Only: Lit pass emits indirect channel to second attachment; SSAO multiplies only that channel by visibility, preserving direct + emissive

…
64eb481
```
…or emissive

Stop SSAO from darkening direct lighting + emissive. Approach A (the roadmap's
in-scope slice): the lit pass writes its indirect (ambient+IBL) term to a second
color attachment, and SSAO removes only indirect * (1 - visibility) — so
`scene - indirect*(1-ao)` leaves direct + emissive exact.

- standard-indirect-channel-shader.ts (new): wraps the assembled standard
  fragment to emit a two-target StandardIndirectFragmentOutput — @location(0)
  the lit color, @location(1) the split-out indirect (ambientDiffuse + diffuse
  IBL + specular IBL). The final return expression (incl. a tonemap/sRGB-wrapped
  form) is re-applied to the indirect channel so both live in the same space;
  variants without a separable indirect term (shadowed) emit zero (AO no-ops).
  Mutually exclusive with the motion-vector second attachment (both @location(1)).
- Threaded indirectColorFormat alongside motionVectorColorFormat through
  standard-pipeline(-descriptor), pipeline-resources (cache key), queued-built-in
  -frame (enabled only when an effect requiresIndirectColor, MSAA off, and motion
  vectors are not in use), frame-boundaries, and post-processing (creates the
  indirect texture, attaches it as the scene's second color target, passes it to
  effect.prepare via the new WebGpuPostEffect.requiresIndirectColor / prepare
  indirectColor inputs).
- post-ssao.ts: requiresIndirectColor; when the indirect texture is supplied,
  samples it (binding 3) and composites scene - indirect*(1-visibility); falls
  back to the legacy whole-image multiply otherwise (e.g. MSAA on), so the
  existing ssao path is unchanged.
- examples/ssao-indirect.* + test/e2e/ssao-indirect.spec.ts: a diffuse
  floor/wall crease + an EMISSIVE cube in the same high-AO corner. SSAO darkens
  the diffuse crease (~30 pixelDistance) while the emissive cube is preserved
  (~7) — the old whole-image multiply would have darkened it comparably. status
  reports ssao.appliesTo:'indirect' and the lit cacheKey carries the
  indirect-channel shader variant. Unit test covers the shader transform.
- The existing ssao spec's hardcoded scene draw-call count (environment/skybox
  dependent) is no longer pinned.
```
