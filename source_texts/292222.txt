Exists in TF: https://www.tensorflow.org/api_docs/python/tf/scan (or some variant inspired by scan), JAX/LAX: https://jax.readthedocs.io/en/latest/_autosummary/jax.lax.scan.html, (old theano: https://theano.readthedocs.io/en/rel-0.6rc3/library/scan.html). There is also an ONNX op: https://github.com/onnx/onnx/blob/master/docs/Changelog.md#Scan-11
Related feature request on parallel fast associative scans: #95408
Could possibly be a way for coding of custom RNN that is guaranteed/confident for correct tracing/export. + the code becomes more functional style + easier to analyze/transform
Currently we would be writing for loops, but it's not sure, how different flavors of scripting / tracing handle the bounds and if it stays unrolled or not. A more constrained scan/reduce/map ops could give users extra confidence. Also memory could be economized at backprop if shapes are guaranteed to match: #46168
This may also be interesting for differntiating through optimization loops, since training loop may be represented as such ops as well.

Thank you, @bohnstingl ! Here's a small version: (dependencies are torch and torch.compile)
```
import torch
import torch.nn as nn
from torch._higher_order_ops import scan
from torch.func import functional_call, jvp


class Model(nn.Module):
    def __init__(self, n_steps: int):
        super().__init__()
        self.w = nn.Parameter(torch.tensor([0.5]))
        self.xs = torch.ones(n_steps)
        self.n_steps = n_steps
 
    def forward(self):
        def step_fn(carry, x):
            state, w = carry
            new_state = state + w * x
            return (new_state.clone(), w), new_state.clone()
 
        init = (torch.zeros(1), self.w)
        final_carry, _ = scan(step_fn, init=init, xs=self.xs, dim=0)
        return final_carry[0]
 
 
@torch.compile(fullgraph=True)
def forward_step(model, target):
    params = {name: p.detach() for name, p in model.named_parameters()}
    tangents = {name: torch.ones_like(p) for name, p in params.items()}
 
    def f(p):
        return functional_call(model, p)
 
    out, jvp_out = jvp(f, (params,), (tangents,))
    return out, jvp_out
 
 
if __name__ == "__main__":
    model = Model(n_steps=10)
    target = torch.tensor([5.0])
    out, jvp_out = forward_step(model, target)
    print(f"out={out}, jvp={jvp_out}")
```
The issue I'm running into is that torch._higher_order_ops.scan seems to expect fake tensors, but gets real ones.
