這個 Issue 提議給 AlgorithmConfig 添加一個建議 Balancer 實作使用的 Random Number Generator。
這個意圖背後的目的：
java.util.Random 實作是 linear congruential generator，這種類型的亂數產生器的 Period 比較弱，相對其他 PRNG，產生重複結果的風險較高。有些學者在審視隨機演算法的框架或研究時，第一步是跳進去看他們是不是用 java.util.Random 這種 linear congruential generator，如果是的話那個東西產生的結果都先打一個問號。
java.util.concurrent.ThreadLocalRandom 本身有比 java.util.Random 更好的統計性質，但是他不支援賦予 seed，這對我們要重複產生結果或是除錯有非常大的阻礙。因此也不建議使用。
Java 17 之後 Java Standard Library 有一些比較新且統計性質較好的 PRNG，但是我們專案在 Java 11。
基於上面的理由，我覺得我們有必要給 AlgorithmConfig 添加一個建議 Balacner 演算法使用的 PRNG。否則 Balancer 的實作可能會踩到上面的地雷。提供一個建議 Balancer 使用的 PRNG 同時有下面這些好處。
我們可以控制 PRNG 的 seed，使 Balancer 算法結果有機會被重現（當然還需要內部算法邏輯的支援），這些資訊可以被暴露到 API 上面，方便使用者重現或除錯。
可能的修正
使用 Apache Common RNG 裡面實作的 PRNG。寫一個專案自己的 RNG 界面包裝他。
我做了一些研究，感覺可以使用 PCG 系列的 PRNG，這邊一段整理和比較 https://www.pcg-random.org/index.html 。 PCG 本身有被預測的爭議，不適合用在資安相關的情境，但我們只需要他的統計性質，所以應該還好。
