Abstract
Packing a 3D volume into a token sequence is not merely long-sequence modeling.
Once the volume is packed, sequence order no longer encodes the geometry of
the sample — so a positional mechanism indexed by sequence position can learn
the memory layout rather than the object. This is a general failure mode for
attention over packed geometric data. We introduce PACK3D, a local–global
attention operator that separates memory layout from attention geometry. PACK3D
keeps local neighborhood attention exact, compresses only distant context into
contiguous 3D block summaries, and indexes every query–key interaction with
axial RoPE on true token-grid coordinates rather than packed positions. Because
the rotation is applied before a block is summarized, the query-to-summary logit
remains a weighted sum of query-relative 3D displacements; compressed global
context therefore stays spatially interpretable after packing, instead of collapsing to
anonymous pooled content. We measure the failure mode directly. On a controlled
synthetic task—train on one packing, change only the memory order of the tokens,
hold the physical labeling rule fixed—learned positional embeddings and packedsequence RoPE solve the training layout perfectly yet collapse under Morton, blockcontiguous, and random repacking, while axial grid-coordinate RoPE stays exact
throughout. The same coordinate system carries to real data: on Allen WTC–11
hiPSC microscopy, PACK3D improves over a parameter-matched 3D U-Net on the
15-structure joint task and over a matched learned-position local–global baseline,
with controls isolating the coordinate system, not encoder capacity, as the source
of the gain. A fused Triton implementation matches windowed-attention latency
at 65k tokens while supplying the long-range context windowing cannot—so the
operator is not only correct but trainable at scale.
1
Introduction
High-token 3D fields arise across volumetric domains: live-cell microscopy [Viana et al., 2023],
medical imaging [Fang et al., 2025], learned image compression for microscopy [Zhou et al., 2024],
and spectral-spatial sensing cubes such as hyperspectral methane detection [Kumar et al., 2023]. In
each, a volume is patchified and linearized into a token sequence for processing. But linearization
discards something physical: once a 3D field is flattened, physical geometry no longer coincides
with token order in memory. Tokens may be packed in raster, Morton, or block-contiguous order for
systems efficiency, yet those layout choices are not coordinate systems. When a positional mechanism
reads the layout as if it were geometry, attention learns the memory order rather than the object. This
is the packed-geometric attention problem.
Dense and window attention fail in opposite ways. Dense attention preserves global access but scales
quadratically with token count; window attention scales but sees only locally. Local–global attention
is the natural compromise — exact nearby, compressed far away — and it is exactly where the
problem bites, because the compression step inherits whatever coordinate the positional mechanism

uses. If that coordinate is sequence position, a packed operator can reduce the attention graph
correctly and still attend over the wrong geometry. Reducing the graph and fixing the geometry are
independent requirements, and a method can satisfy the first while failing the second.
Three-dimensional microscopy is where this is unavoidable, and it is our claim-grade domain. A
single live-cell crop holds tens to hundreds of thousands of tokens, while the signal spans puncta,
membranes, cytoplasmic networks, nuclear geometry, and cell-scale organization. The Allen WTC–
11 hiPSC Single-Cell Image Dataset v1 contains more than 200,000 live cells in 3D across 25
tagged structures, and its analysis framework is built on cell shape, intracellular coordinates, average
structure locations, variability, and pairwise structure interactions [Viana et al., 2023]. When the
scientific objects are themselves spatial, a model that confuses storage order with location is not
merely inefficient; it is answering the wrong question.
We introduce PACK 3D, a geometry-aware local–global attention operator for packed high-token
3D fields. PACK 3D keeps local neighborhood attention exact, compresses only distant context into
contiguous 3D block summaries, and indexes every query–key interaction with axial RoPE on true
token-grid coordinates rather than packed positions. The mechanism that makes this more than a
renaming of position is that compression preserves query-relative geometry: for a block B with

The systems contract is part of the method, not an afterthought to it. A sparse pattern that materializes
dense route tensors or gathered local-neighbor tensors is sparse only on paper, not as a trainable hightoken operator. PACK 3D is a fused forward/backward block with Triton local attention, contiguous
block summaries, and explicit backend reporting, following the lesson of natively trainable sparse
attention: useful sparsity must align with accelerator memory movement and the backward pass, not
only with asymptotic complexity [Yuan et al., 2025].
We are deliberate about what we do and do not claim. The Allen task predicts Allen-generated
masks from target fluorescence, brightfield, and DNA channels; it is neither label-free prediction nor
manual-label segmentation. We claim neither segmentation state of the art, nor universal superiority
over U-Nets, nor a general speed law for sparse attention. The finding is architectural and narrower
than any of these: for packed 3D fields, local–global attention over compressed summaries is reliable
only when positional geometry is tied to physical coordinates rather than to memory order.
Our contributions are:
1. A design principle and an operator. We formulate PACK 3D and elevate the separation
of memory layout from attention geometry into a design principle for packed geometric
attention: packing is a systems decision, coordinates are a modeling decision, and the two
must not be conflated.
2. The geometry of compressed attention. We show that applying RoPE before block
compression makes query-to-summary logits preserve query-relative 3D displacement, so
compressed summaries remain spatially interpretable rather than merely pooled. A summarycenter variant is a competitive approximation in short ablations, so the supported principle
is coordinate-aware compression, not the necessity of one specific placement.
3. A hardware-aligned realization. We implement the operator as a fused forward/backward
training block: Triton local attention avoids local-neighbor materialization, contiguous
summaries preserve locality, and the sparse graph is trainable without materializing dense
route tensors on the main path.
4. Evidence that the coordinate system, not capacity, drives the gain. On a controlled
synthetic repacking benchmark, learned and packed-sequence positional encodings solve
the training layout yet collapse under Morton, block-contiguous, and random repacking,
while axial grid-coordinate RoPE stays exact. On Allen WTC–11 microscopy, PACK 3D
improves over a parameter-matched TokenGrid 3D U-Net on the 15-structure joint task

attribute the gain to the coordinate system rather than to position-encoding parameters.
The operator is reusable beyond the domain we test. Any task whose tokens carry physical coordinates — volumetric medical segmentation, density-field and NeRF-style representations, spatial
transcriptomics — inherits the same packing invariant: the attention should be built in the coordinates
of the sample, not in the sequence used to store it. What we do not study here is equally explicit:
label-free prediction, U-Net replacement, and transfer across imaging modalities are out of scope and
left to future work.
2
Related Work
Attention for 3D vision. Attention-based vision models are attractive because they can couple local
evidence with long-range context without fixing the interaction range in advance. Vision Transformers
and subsequent scaling and self-supervised results showed that attention-based visual backbones can
learn strong representations when given sufficient data and compute [Dosovitskiy et al., 2021, Zhai
et al., 2022, Dehghani et al., 2023, He et al., 2022]. For dense 3D prediction, this flexibility is useful
because local structure often depends on larger spatial organization. Our question is not whether
attention should replace convolution everywhere, but what geometry local–global attention should
use once a 3D field is patchified, packed, and processed as tokens.
Efficient and sparse attention. A large literature reduces the cost of attention either by changing
the implementation of dense attention or by changing the attention graph. FlashAttention preserves
exact scaled dot-product attention while improving memory movement through IO-aware tiling [Dao
et al., 2022]. Low-rank and kernelized methods such as Linformer, Performer, and Nyströmformer
reduce sequence cost through projections, random features, or landmark approximations [Wang
et al., 2020, Choromanski et al., 2020, Xiong et al., 2021]. Patterned sparse methods such as
Longformer and BigBird replace dense all-pairs attention with structured local and sparse long-range
connections [Beltagy et al., 2020, Zaheer et al., 2021]. Native Sparse Attention is closest in systems
motivation: it emphasizes that sparse attention should be trainable and hardware-aligned rather than
merely sparse on paper [Yuan et al., 2025].
Our setting adds a geometric constraint. In packed 3D fields, the difficulty is not only reducing the
number of query–key pairs; the positional mechanism must also avoid treating memory order as
sample geometry. PACK 3D keeps exact local attention, compresses nonlocal context into blockcontiguous summaries, and indexes query–key compatibility by physical 3D token-grid coordinates
rather than packed sequence position.
Position encodings and geometry under packing. Transformers require positional information
because self-attention alone is permutation equivariant [Vaswani et al., 2017]. Absolute learned or
sinusoidal embeddings attach position to token features, while relative methods modify query–key
compatibility as a function of displacement [Vaswani et al., 2017, Shaw et al., 2018]. RoPE encodes
relative position through query/key rotations [Su et al., 2023]. Coordinate-based representations also
appear in spatial models such as NeRF and Fourier-feature networks, where explicit coordinates help
represent geometry directly [Mildenhall et al., 2020].
Packed 3D attention differs from ordinary sequence modeling because sequence position is not
the geometry of the field. Raster, Morton, and block-contiguous orderings are useful layouts, not
physical coordinate systems. The key distinction in PACK 3D is that neighborhoods, block summaries,
and attention logits are defined on true 3D token-grid coordinates. This places the work closest to
coordinate-aware relative-position methods, but with a specific focus on how compressed local–global
attention preserves spatial meaning after packing.
Volumetric transformers and biomedical segmentation. U-Net, 3D U-Net, and V-Net established
strong convolutional baselines for dense 3D prediction [Ronneberger et al., 2015, Çiçek et al., 2016,
Milletari et al., 2016]. More recent biomedical models combine transformer-style context with
U-shaped decoding or convolutional feature extraction, including CoTr, UNETR, Swin UNETR, and
nnFormer [Xie et al., 2021, Hatamizadeh et al., 2022b,a, Zhou et al., 2023]. These architectures show
that long-range context can help 3D segmentation, especially when paired with mechanisms that
preserve spatial detail.
3
Our contribution is complementary to this literature. We do not present PACK 3D as a universal
replacement for U-Nets. Instead, we isolate an operator question: when a high-token 3D field is
packed into a sequence, should local–global attention use packed sequence position or physical 3D
coordinates?
Microscopy, Allen cellular organization, and task scope. Allen WTC–11 hiPSC microscopy is a
natural validation domain because intracellular organization is explicitly spatial: structure location,
morphology, and inter-structure arrangement are central scientific objects [Viana et al., 2023]. Prior
Allen pipelines, including the Allen Cell Structure Segmenter, focus on producing or analyzing
structure masks from fluorescence microscopy [Chen et al., 2020]. We use target fluorescence,
brightfield, and DNA to predict Allen-generated masks, making Allen a high-token 3D setting for
testing whether packed attention should preserve physical coordinate geometry.
Memory layout and systems realization. High-throughput attention depends on how tensors are
tiled, streamed, and revisited during forward and backward passes. FlashAttention and NSA show
that wall-clock behavior depends on memory movement and executable kernels, not only asymptotic
sparsity [Dao et al., 2022, Yuan et al., 2025]. PACK 3D follows this systems view while separating
layout from geometry: packing and block-contiguous summaries are used for memory movement,
whereas attention logits are indexed by physical coordinates. In packed 3D attention, memory order
is a systems choice; attention geometry is a modeling choice. They should not be conflated.
3
Methods
PACK 3D is a geometry-aware local–global attention operator for packed high-token 3D fields. A
flattened volume may be stored in raster, Morton, or block-contiguous order, but those layouts encode
memory order, not physical coordinates. PACK 3D therefore enforces three contracts: local attention
is exact, because microscopy carries high-frequency morphology that block summaries would erase;
only nonlocal context is compressed, into contiguous block summaries; and query–key compatibility
is parameterized by true 3D coordinates rather than by packed sequence index. The rest of this section
makes each contract precise and shows that the executed operator realizes it.
3.1
Packed token fields and coordinate geometry

3.4
Systems realization of the local–global graph
The systems goal is to make the mathematical sparse graph the executed training graph: local
neighborhoods fixed on the token lattice, summaries built over contiguous coordinate blocks, and the
global branch attending to summaries rather than raw remote tokens. The main Allen rows in §4 all
run the two-level block-Morton layout described below; Proposition 1 is what licenses treating that
layout as a free systems choice, and Appendix C.3 certifies the specific repackings we test.
The implementation separates physical coordinates from memory packing: local neighborhoods
are computed from token-grid coordinates, while compressed summaries are built over the configured packed blocks. The reported Allen rows use the raster_block layout; the implementation
also supports a two-level native_block_morton layout used for layout and systems diagnostics.
Proposition 1 is what makes the layout a free choice for coordinate-indexed operators: any coordinatepreserving repacking yields the same operator up to permutation. Appendix C.2 verifies this at task
level on a controlled synthetic field, where sequence-indexed encodings collapse under repacking
while axial grid-coordinate RoPE remains exact.
The technical contribution is the co-design of operator, layout, and kernels around these invariants:
coordinate-defined neighborhoods, contiguous summaries, and a backward pass that follows the
same streamed access pattern as the forward pass. The main path is summary construction, exact
local attention, and query-to-summary attention. An optional selected-refinement branch routes over
candidate-block tiles and can share one route decision across a native block, but it is a reach extension
(Appendix D.1), not part of the main claim. We report backend status explicitly, so executed Triton
paths, fallbacks, and branches skipped by design are never conflated.

and dense token-to-summary score matrices — and yields a trainable forward/backward block whose
executed operator matches the local–global graph the method claims.
4
Results
The experiments test an attention-method claim, not a segmentation-leaderboard claim: packed
high-token 3D attention should encode physical coordinates, not memory order. The controlled
result is on the Allen-15 joint task, where PACK 3D improves over a parameter-matched TokenGrid
3D U-Net by +0.0094 best and +0.0135 final macro Dice (Table 1). A second comparison runs
against a much larger learned-position local–global model: at 262k/depth8 PACK 3D improves on it by
+0.0978 best and +0.1248 final macro Dice. That baseline carries 158.5M parameters to PACK 3D’s
24.3M, so we do not read the large gap as a clean measurement of coordinate geometry — it measures
mainly that a learned-position local–global operator is weak at this scale. The coordinate effect is
isolated instead by the identical-capacity controls of §4.3 and the architectural decomposition of
§4.2. The section follows that order: we fix the Allen task contract, present the controlled result
and decompose the headline, isolate the positional mechanism at matched capacity, ask whether the
trained model relies on its compressed pathway, and measure systems scaling. Transfer gates and
lower-priority controls are deferred to the appendix.
4.1
Allen contract
We predict Allen-generated 3D structure masks from target fluorescence, brightfield, and DNA;
the task is neither label-free prediction nor manual-label segmentation. The six-structure runs
use TOMM20, LMNB1, ST6GAL1, GJA1, LAMP1, and ATP2A2; the Allen-15 joint comparison
expands the label set to 15 tagged structures. At 262k tokens, Dice is computed on the fixed central
target region, and we report best macro Dice (best validation checkpoint) and final macro Dice (last
checkpoint) over three seeds, at 10k training steps for headline attention cases. Because the input
includes the target fluorescence channel, we audit thresholding directly: the strongest tuned threshold
baseline reaches 0.5582 macro Dice, far below every neural row, so the task does not collapse to
intensity thresholding. Reproducibility and threshold controls are in Appendices A.1 and A.2.

4.3
Positional controls
These gates isolate the positional mechanism at matched parameter count, which the depth-8 headline
above cannot do. The cleanest comparison is packed-sequence RoPE versus axial grid-coordinate
RoPE at identical capacity: at 262k/depth1 and 3.06M parameters, axial RoPE reaches 0.7375 best
Dice against packed-sequence RoPE’s 0.7142, and at 65k it leads 0.7346 to 0.7099 (Table 2). Because
the two differ only in whether the rotary coordinate is physical or sequence-index, this gap isolates
the coordinate system from both capacity and rotary machinery — packed-sequence RoPE has the
same rotary features yet tracks no-PE behavior on final Dice.
Across the compact learned-coordinate and bias-based alternatives at matched scale, axial RoPE
has the highest best Dice. The conclusion we draw is deliberately bounded: separable learned 3D
PE stays competitive on final Dice in the short gate, so the robust signal is physical-coordinate
geometry, not the unique superiority of one rotary scheme. The depth-8 rows (158.5M learned-PE
vs. 24.3M axial RoPE) differ in capacity and we include them only to show the effect persists at
depth, not as a matched coordinate control. Coordinate-scaling and additional bias comparisons are

4.6
Claim boundaries
We close by stating the boundary of the evidence directly. The Allen-15 comparison shows PACK 3D

matched-capacity positional gates, not by the headline number.
Lower-priority boundary evidence is deferred to the appendix: summary-center RoPE is competitive
in short gates (Appendix B.7), collar controls show external collar content is not the clean driver of the
gain (Appendix C.6), and external transfer is mixed (Appendix C.7). Taken together, the main-paper
evidence supports a specific, bounded conclusion: at matched capacity, physical-coordinate geometry

improves packed high-token local–global attention; the trained model’s compressed pathway is
functional rather than vestigial; and the resulting sparse graph is trainable on GPU hardware. The
contribution is not a state-of-the-art segmentation model. It is a geometry-aware, hardware-aligned
local–global attention operator for packed 3D fields, together with evidence that the coordinate
system, not the memory layout, is what the attention should be built on.
5
Conclusion
Packed 3D attention fails when it treats storage order as geometry. For packed geometric fields,
query–key compatibility should be indexed by physical coordinates rather than sequence positions.
PACK 3D instantiates this principle with exact local attention, compressed global summaries, and
coordinate-aware query-relative geometry. Synthetic repacking exposes the failure mode: learned or
sequence-index positional mechanisms can fit one layout and fail under another, while coordinateindexed attention remains invariant. The operator lesson is simple: memory layout is a systems
decision, not an attention coordinate system. Compressed global attention over packed 3D fields
should be built in the coordinates of the sample, not the sequence used to store it.

Mathematical Details and Theory for Geometry-Aware Packed 3D
Attention
This appendix develops the theory of PACK 3D around a single controlling distinction: in a packed
3D field every token carries two indices — a memory position and a physical coordinate — and a
correct attention operator must depend only on the second. We make that distinction formal, then
trace it through five results of distinct logical kinds. Two are exact identities (Lemmas 3 and 7), one
is a symmetry (Corollary 4), one is an equivariance theorem for the full operator (Theorem 5), one
is an impossibility-and-separation result (Theorem 8), and the remainder are quantitative bounds
controlling the one approximation PACK 3D admits (Lemmas 9 and 10). Throughout we separate
what is exactly invariant to repacking from what is only approximately coordinate-aware, so the
reader always knows the logical status of the statement in hand.

Proof. We exhibit one instance. Take three physical tokens a, b, c under packings π = (a, b, c) and

B.10
Attention-graph complexity
The reduction is in the graph, indexed by κ, not in the coordinate system itself. Dense attention
computes N 2 token–token interactions. With neighborhood size w = |N (x)|, block volume v = |Bj |,
and M = N/v summaries, PACK 3D computes N w exact local interactions, N M = N 2 /v query–
summary interactions, and M v = N summary-construction terms. The nonlocal graph thus changes
from token–token to token–block, cutting global pairings by a factor v. This is block-compressed
global attention with explicit coordinate geometry — linear only in the degenerate case v ∝ N , and
otherwise strictly between window and dense.

B.12
Summary of the theory
The theory supports four claims.
First, coordinate-indexed local–global attention is a well-defined operator on a packed 3D field:
repacking the same physical field only permutes the output.
Second, sequence-index positional attention is not a geometric operator on packed 3D fields, because
changing memory layout changes the positional coordinate.
Third, coordinate-aware compressed summaries preserve query-relative geometry. A query-tosummary logit is not just a content similarity to a pooled token; it is a weighted sum of content
interactions modulated by relative 3D displacement.
Fourth, coordinate-aware compression is strictly more expressive than coordinate-blind compression
for relative-spatial selection. If two remote blocks have identical content but different relative positions, content-only compressed attention cannot distinguish them, while coordinate-aware compressed
attention can.
These statements are independent of Allen microscopy and segmentation. They formalize the general
principle behind PACK 3D: packing is for memory movement; coordinates are for attention geometry.
The central empirical lesson is therefore the same as the mathematical one: once a 3D field is
packed into a sequence, positional encoding becomes part of the attention operator’s geometry.
For compressed global attention to work in high-token 3D microscopy, it must encode physical
coordinates rather than memory order.

C.2
Task-level synthetic repacking benchmark
The invariance diagnostics above are operator-level: they show the logits transform correctly. This
subsection measures the consequence at the level of a task. We construct a controlled synthetic 3D
labeling problem with a known geometric rule, train each positional mechanism on raster-packed
tokens, and then evaluate the same trained model on the same physical task after changing only the
memory order of the tokens. The physical coordinates and the target rule are held fixed; the sole
intervention is the packing. This is the task-level form of Proposition 6: if a mechanism has learned
the memory layout rather than the geometry, repacking should destroy its predictions.
It does, and cleanly (Table 9). Learned positional embeddings and packed-sequence RoPE both solve
the raster layout perfectly — 1.000 Dice — and both collapse under repacking, to 0.449 (Morton),
0.418 (block-contiguous), and 0.378 (random). Axial grid-coordinate RoPE stays at 1.000 Dice under
every repacking. A no-positional baseline is flat at 0.554 across all packings but never solves the task,
confirming the task genuinely requires position: the sequence-indexed mechanisms do not merely
lose their advantage under repacking, they fall below position-blindness (0.378–0.449 vs. 0.554),
because they have learned to read a signal that repacking has made actively misleading.
Two features of the table are worth reading deliberately. First, the learned-PE and packed-sequenceRoPE rows are identical at every packing. This is expected, not a coincidence: both mechanisms
key on sequence position, so a given repacking scrambles the same information for each, and both
land on the same wrong label overlap. The shared failure is the point — it is the property of being
sequence-indexed, not any detail of the encoder, that repacking breaks. Second, the degraded values
are exact rationals on the synthetic grid (for instance 0.449 = 22/49), reflecting the controlled
finite-grid construction rather than measurement noise. The benchmark therefore converts the paper’s
central claim from an operator identity — “axial-RoPE logits are invariant under repacking” —
into a task measurement: “sequence-indexed position learns a memory layout that does not survive
repacking, while coordinate-indexed position learns the geometry that does.”

the coordinate-aware branch is more shuffle-robust [VERIFY: state whether this control was run;

expressive gap.

NeurIPS Paper Checklist
1. Claims
Question: Do the main claims made in the abstract and introduction accurately reflect the
paper’s contributions and scope?
Answer: [Yes]
Justification: Contributions are summarized in the abstract and are explicitly stated in a
bulleted list. Assumptions and contribution claims are present in all sections of the paper
(reg. comparison to existing methods, etc).
Guidelines:
• The answer [N/A] means that the abstract and introduction do not include the claims
made in the paper.
• The abstract and/or introduction should clearly state the claims made, including the
contributions made in the paper and important assumptions and limitations. A [No] or
[N/A] answer to this question will not be perceived well by the reviewers.
• The claims made should match theoretical and experimental results, and reflect how
much the results can be expected to generalize to other settings.
• It is fine to include aspirational goals as motivation as long as it is clear that these goals
are not attained by the paper.
2. Limitations
Question: Does the paper discuss the limitations of the work performed by the authors?
Answer: [Yes]
Justification: We accurately represent the claims throughout the paper and explicitly lay out
what we are not claiming (unproven claims at this time)
Guidelines:
• The answer [N/A] means that the paper has no limitation while the answer [No] means
that the paper has limitations, but those are not discussed in the paper.
• The authors are encouraged to create a separate “Limitations” section in their paper.
• The paper should point out any strong assumptions and how robust the results are to
violations of these assumptions (e.g., independence assumptions, noiseless settings,
model well-specification, asymptotic approximations only holding locally). The authors
should reflect on how these assumptions might be violated in practice and what the
implications would be.
• The authors should reflect on the scope of the claims made, e.g., if the approach was
only tested on a few datasets or with a few runs. In general, empirical results often
depend on implicit assumptions, which should be articulated.
• The authors should reflect on the factors that influence the performance of the approach.
For example, a facial recognition algorithm may perform poorly when image resolution
is low or images are taken in low lighting. Or a speech-to-text system might not be
used reliably to provide closed captions for online lectures because it fails to handle
technical jargon.
• The authors should discuss the computational efficiency of the proposed algorithms
and how they scale with dataset size.
• If applicable, the authors should discuss possible limitations of their approach to
address problems of privacy and fairness.
• While the authors might fear that complete honesty about limitations might be used by
reviewers as grounds for rejection, a worse outcome might be that reviewers discover
limitations that aren’t acknowledged in the paper. The authors should use their best
judgment and recognize that individual actions in favor of transparency play an important role in developing norms that preserve the integrity of the community. Reviewers
will be specifically instructed to not penalize honesty concerning limitations.
3. Theory assumptions and proofs
Question: For each theoretical result, does the paper provide the full set of assumptions and
a complete (and correct) proof?
28
Answer: [Yes]
Justification: Proof of claims are included in the main text (or proof sketches). Full proofs
are present in the appendix.
Guidelines:
• The answer [N/A] means that the paper does not include theoretical results.
• All the theorems, formulas, and proofs in the paper should be numbered and crossreferenced.
• All assumptions should be clearly stated or referenced in the statement of any theorems.
• The proofs can either appear in the main paper or the supplemental material, but if
they appear in the supplemental material, the authors are encouraged to provide a short
proof sketch to provide intuition.
• Inversely, any informal proof provided in the core of the paper should be complemented
by formal proofs provided in appendix or supplemental material.
• Theorems and Lemmas that the proof relies upon should be properly referenced.
4. Experimental result reproducibility
Question: Does the paper fully disclose all the information needed to reproduce the main experimental results of the paper to the extent that it affects the main claims and/or conclusions
of the paper (regardless of whether the code and data are provided or not)?
Answer: [Yes]
Justification: Full details of experiments are present in the appendix. Code will be made
available after publication.
Guidelines:
• The answer [N/A] means that the paper does not include experiments.
• If the paper includes experiments, a [No] answer to this question will not be perceived
well by the reviewers: Making the paper reproducible is important, regardless of
whether the code and data are provided or not.
• If the contribution is a dataset and/or model, the authors should describe the steps taken
to make their results reproducible or verifiable.
• Depending on the contribution, reproducibility can be accomplished in various ways.
For example, if the contribution is a novel architecture, describing the architecture fully
might suffice, or if the contribution is a specific model and empirical evaluation, it may
be necessary to either make it possible for others to replicate the model with the same
dataset, or provide access to the model. In general. releasing code and data is often
one good way to accomplish this, but reproducibility can also be provided via detailed
instructions for how to replicate the results, access to a hosted model (e.g., in the case
of a large language model), releasing of a model checkpoint, or other means that are
appropriate to the research performed.
• While NeurIPS does not require releasing code, the conference does require all submissions to provide some reasonable avenue for reproducibility, which may depend on the
nature of the contribution. For example
(a) If the contribution is primarily a new algorithm, the paper should make it clear how
to reproduce that algorithm.
(b) If the contribution is primarily a new model architecture, the paper should describe
the architecture clearly and fully.
(c) If the contribution is a new model (e.g., a large language model), then there should
either be a way to access this model for reproducing the results or a way to reproduce
the model (e.g., with an open-source dataset or instructions for how to construct
the dataset).
(d) We recognize that reproducibility may be tricky in some cases, in which case
authors are welcome to describe the particular way they provide for reproducibility.
In the case of closed-source models, it may be that access to the model is limited in
some way (e.g., to registered users), but it should be possible for other researchers
to have some path to reproducing or verifying the results.

7. Experiment statistical significance
Question: Does the paper report error bars suitably and correctly defined or other appropriate
information about the statistical significance of the experiments?
Answer: [Yes]
Justification: We include error bars and accuracy information in our tables and figures,
where applicable and practical (given compute constraints)
Guidelines:
• The answer [N/A] means that the paper does not include experiments.
• The authors should answer [Yes] if the results are accompanied by error bars, confidence
intervals, or statistical significance tests, at least for the experiments that support the
main claims of the paper.
• The factors of variability that the error bars are capturing should be clearly stated (for
example, train/test split, initialization, random drawing of some parameter, or overall
run with given experimental conditions).
• The method for calculating the error bars should be explained (closed form formula,
call to a library function, bootstrap, etc.)
30
• The assumptions made should be given (e.g., Normally distributed errors).
• It should be clear whether the error bar is the standard deviation or the standard error
of the mean.
• It is OK to report 1-sigma error bars, but one should state it. The authors should
preferably report a 2-sigma error bar than state that they have a 96% CI, if the hypothesis
of Normality of errors is not verified.
• For asymmetric distributions, the authors should be careful not to show in tables or
figures symmetric error bars that would yield results that are out of range (e.g., negative
error rates).
• If error bars are reported in tables or plots, the authors should explain in the text how
they were calculated and reference the corresponding figures or tables in the text.
