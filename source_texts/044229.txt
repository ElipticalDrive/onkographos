X-RAY 3.0 — experimental GPU fluid milestone
X-RAY 3.1 visual visibility patch — Oct 25, 2026
User screenshot review: the 3D mercury looked almost black and the old heat map resembled copper dot outlines. Addressed on branch head 976825ea6d33e2862109f99cb328554f4b776c7b:
The 3D volume now renders behind the accurate, unchanged calibrated FFT contour instead of being clipped to its filled region; the old CPU fallback keeps its conservative clipping.
Stronger transported chroma/oil-film reflectance, corrected linear-to-display output curve, faster cold-start phase formation, and 60 Hz repaint when the weather/SONAR overlay is off.
Replaced detached circular HEAT MAP markers with continuously shaded, intensity-gated frequency-colour glow. Silence still outputs no heat.
Added a visible in-graph X-RAY 3.1 | GPU LIVE / fallback diagnostic to reveal stale VST3 installs or unsupported hardware.
Latest validated build: Windows GitHub Actions run #35 SUCCESS. All 24/24 CTest suites passed, including revised pink-noise heat visibility/silence checks and six HLSL compile gates. pluginval strictness 8 successful (GUI tests skipped). Download artifact Windows x64 VST3, SHA256 d8223a57046a5d63417c8e16ab7248f65b86a375e5f6dc0886de7874750f507e.
Still gated: actual GPU-run screenshot, true 60 FPS performance, and FL Studio unload regression must be verified on the user's desktop GTX 1650. This work is still a cinematic physically inspired fluid prototype; not a physically exact validated multiphase CFD solver.
Implemented
Isolated Windows D3D11 compute pipeline with a 64×40×32 true 3D velocity/pressure field and 24 Jacobi pressure-projection iterations.
Advected multiple material-phase fractions, pigment and bubble fields; ray-marched 640×224 output. These are physically inspired preliminary two-phase numerical fields, not a validated conservative VOF/multiphase CFD solver.
Audio-only visual forcing from Scalpel's existing 256 calibrated analyzer bins plus bass/transient/weather interpretation. Added confidence-gated 12-class chroma influence on internal pigment colours.
Separate 30 Hz fixed-timestep simulation target and 60 Hz UI rendering target; no work added to processBlock.
GPU resources are editor-owned and torn down on X-RAY mode off/editor destruction, with the existing CPU X-RAY renderer retained as fallback.
Headless Windows CI disables real GPU execution while compiling all six HLSL shader kernels and exercising existing GUI/DSP regressions.
Verified
Windows GitHub Actions run #33: SUCCESS
24/24 CTest passed, including xray chroma test and HLSL compile gate.
pluginval strictness 8: success (GUI tests skipped).
Windows x64 VST3 packaged: artifact SCALPEL-EQ-0.1.0-Windows-x64-VST3, ID 12590520223, SHA-256 5d088508d31aeca947f68318cc48d9e91c97e26756e1bbcc490d756da5a98ebe.
Explicit release blockers
Validate D3D11 GPU initialization and real runtime shader execution on the user's desktop GTX 1650. Headless CI cannot prove this.
Compare full-motion X-RAY screenshots with canonical reference; refine volumetric lighting/geometry/colors and check no fallback was used.
Measure actual 60 Hz delivery, GPU usage, VRAM cost, stability in FL Studio with several instances, and add/remove editor lifecycle on real hardware.
Improve and formally validate multi-phase fluid numerics (volume/mass conservation, interface tracking, convergence and timestep stability). Not scientifically exact yet.
Review compatibility and safe fallback on non-NVIDIA GPU systems.
Keep draft. Do not merge or ship as the fully-polished X-RAY 3.0 release until the gates above pass.
