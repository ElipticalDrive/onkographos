G118 (Documentation/FINDINGS.md in the parent): voxel.Mesh.MCBoundaryMorphWidth and UVoxelWorldsSettings::MCBoundaryMorphWidth changed no mesh the world draws or cooks. The Marching Cubes geomorph read them only for a whole-chunk mesh with transition faces and no MorphWidthOverride. Streaming makes no such mesh:
chunk meshes use the interior domain;
every seam frame sets its own band-confined width (VoxelCPUMarchingCubesSeams.cpp);
a collision cook gives every neighbour the chunk's own LOD.
Change
The ramp width moves onto the request. FVoxelMeshingRequest::MorphWidthOverride (default -1, meaning "use the cvar") becomes MorphWidth, in coarse cells, with a default of 2.0.
The seam frames set it to their band exactly as before: zero at the band's inner edge, so the morphed band vertices stay coincident with the unmorphed interior mesh. A wider ramp would crack that junction, so the width stays a function of the band.
A whole-chunk mesh with transition faces keeps the old default of 2 coarse cells. Only the LOD-boundary tests and the mesh digests make one.
The cvar is removed, along with the UVoxelWorldsSettings property (and its empty "Meshing" category) and the setting's row in VoxelSettingsOverrideTests.
No CoreRedirect. No config file wrote the property (config = Engine, absent from DefaultEngine.ini); a stale ini line is ignored.
The morph path stays. The tests and the digests reach it, so only the dead fallback width goes.
Docs: the "LOD Seams" section of MARCHING_CUBES_MESHING.md is updated.
