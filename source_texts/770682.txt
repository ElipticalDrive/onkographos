Performance Issue
The Mamba implementation's selective scan (SSM recurrence) computes the state update sequentially:
`python
Sequential O(L) loop ? reference implementation pattern
h = torch.zeros(B, D, N)
for t in range(L):
h = A_bar[:, :, t] * h + B_bar[:, :, t] * x[:, :, t]
y[:, :, t] = (C[:, :, t] * h).sum(-1)
`
The parallelism problem:
This sequential loop cannot be parallelised across the sequence length dimension L. For a sequence of length 4096, this requires 4096 serial multiply-accumulate operations per batch element, which is the bottleneck that made RNNs slow compared to Transformers.
The Mamba paper's key contribution is using a parallel prefix scan (also called associative scan) to compute the same recurrence in O(log L) parallel steps:
Each step doubles the range of the computed prefix
After log?(L) steps, all L output states are computed
The official Mamba implementation uses a CUDA kernel for this. A pure PyTorch version using orch.jit.script + the associative scan formulation can achieve ~10x speedup on GPU even without custom CUDA.
Questions:
Does the current implementation use sequential scan or parallel prefix scan?
Is there a benchmark comparing throughput (tokens/sec) between the two approaches?
For the educational purpose of the repo, would adding both implementations (sequential for clarity, parallel for performance) with a side-by-side benchmark be in scope?
The parallel scan is the algorithmic heart of why Mamba is practical ? implementing it would make this repo significantly more valuable as a learning resource.
