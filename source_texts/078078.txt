Issue
Closes #183 (ENG-F22-16, mixed smooth and blocky chunks mesh with valid indices and aligned geometry)
Summary
Before: a chunk mixing smooth (material < 100) and blocky (≥ 100) blocks emitted blocky indices past the end of its vertex array, and its smooth part sat half a block off. Blocky cubes were centred on the block corner, spanning [V−0.5, V+0.5].
After: every index of a mixed chunk is in range, its smooth part lands where an all-smooth chunk's would, and every blocky cube fills [V, V+1], matching the smooth path, the coarse LOD path and moho_game raycasting.
How:
Index offset: append_mesh_with_offset added the smooth vertex count on top of target.vertices.len(), which already includes it. Deleted it; mixed chunks use append_mesh.
Smooth alignment: the mixed path had its own copy of "density field → marching cubes → world space" and skipped the -0.5 density-to-world shift. generate_smooth_mesh(.., only_smooth) is now the one pipeline both paths use, so the shift can't drift between them (removes create_density_field_for_chunk and the per-attribute copy loop).
Blocky shift: FaceDirection::vertices_and_normal now uses 0/1 corners. The fix is in the source table, so both the all-blocky and mixed paths get it. Winding and AO corner order are unchanged.
Heads-up for #173: blocky vertex positions moved by +0.5 on every axis. Block V now spans exactly [V, V+1]; any test pinning blocky positions should expect that.
Spec deviation: none in scope. The design bullet "the mixed path applies the same density-to-world shift" is implemented by sharing the smooth pipeline rather than copying the constant.
