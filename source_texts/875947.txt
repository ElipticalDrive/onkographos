Closes #29 (sub-issue of #28).
Summary
The CPU decimate_qem path — the only one on Metal builds, and the run-time fallback for CUDA/HIP/Vulkan — was single-threaded and rebuilt a 27M-entry unordered_map of edges every round. On the cyclops MV 1024 mesh (18.37M → 1M faces) that was 128.7 s (E2E [post] lap: ~118 s), of which cost 62 s / edge hash map 29 s (+11 s freeing it) / propagate 18 s.
This PR keeps the algorithm (quadrics, cost, independent-set collapse, threshold ladder, λ) and every float accumulation order unchanged, and:
extracts unique edges per vertex from the v→f CSR (local insertion sort + RLE) so edge ids come out in (a,b) order — the same order the CUDA port gets from cub sort + RLE; boundary flags fall out of the run counts;
runs qem / cost / propagate / collapse with parallel_for (std::thread; serial under Emscripten). propagate min-reduces the packed (cost,id) key with an atomic CAS (plain array on Emscripten); collapse writes are disjoint per winner by the independent-set ownership rule;
splits decimate_qem into the GPU dispatch and decimate_qem_cpu (exposed for tests), with a shared entry check that drops out-of-range / degenerate faces;
moves remesh_dc.cpp's parallel_for into include/parallel_for.h and shares it;
adds trellis-test-decimate-cpu (regression), trellis-test-decimate-bench (--legacy / compare / dist) and post-replay --decimated for A/B GLBs.

Correctness:
Output is bit-identical to the previous implementation with its edge ids sorted (src/test_decimate_qem_legacy.inc), over all 45 rounds of the real fixture and in trellis-test-decimate-cpu (closed/open torus, degenerate / non-manifold / high-degree / duplicate-face inputs, pass-through, thread counts 1/2/3/8/16 × 3 runs; TSAN clean; em++ -c compiles).
Versus the old hash-order ids only tie-breaks on flat regions differ: two-sided sampled surface distance mean 3e-6 (p99 6e-5), an order of magnitude below the decimation error itself (mean 2.6e-5, identical to 3 digits for both); silhouette IoU ≥ 0.9999 in five fixed views (docs/results/2026-09-20-qem-decimate-ab-grid.jpg).
Design / reviews: docs/design/2026-09-20-qem-decimate-cpu-perf.md (with both codex review-response tables), docs/reviews/2026-09-20_qem-decimate-cpu-perf_review.md, docs/reviews/2026-09-20_qem-decimate-cpu-perf_impl_review.md.
