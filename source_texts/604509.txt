This PR emulates the GXM mask bit in the Vulkan renderer, then makes the region clip tile-granular as on hardware. The second change depends on the first.
Mask bit (first commit)
Mask update fragment programs (sceGxmShaderPatcherCreateMaskUpdateFragmentProgram) write a per-pixel mask: 1 with the front stencil function ALWAYS, 0 with NEVER. Later draws only keep fragments where the mask is 1. Each scene starts from the depth-stencil surface's background mask. vitaGL builds glScissor on it, and some homebrew call it directly.
Until now Vulkan compiled mask update programs as normal shaders. Their 0/1 output went into the colour surface and nothing was masked. One visible effect: vitaGL's mask pass at the start of each scene painted over its glClear.
How it works:
Storage: the mask is a second R8 colour attachment.
Mask updates write it, with depth/stencil tests off and the colour attachment untouched.
The other fragment shaders read it as input attachment 1 and discard where it is 0, before writing anything.
No cost for games that never use the mask:
The test sits behind a specialization constant. It turns on at the first mask update of a scene, and it is part of the pipeline key.
The attachment is DONT_CARE until a render target uses the mask.
Initialisation: the mask is cleared to the background mask in the pre-render command buffer, so the clear runs before the scene's draws.
Visibility: the first draw that tests the mask after mask updates starts a new render pass.
An in-pass barrier (ColorAttachmentWrite → InputAttachmentRead, by region) is valid Vulkan, but MoltenVK still returns the value loaded at the start of the pass. That is what I observed: writes only became visible after restarting the pass.
The restart keeps the depth-stencil. Render targets that use the mask store it from then on.
Shared fixes:
Stencil functions set while a mask update program is bound now reach the stencil state. Before, they were dropped, and since SceGxm only resends changed values, the next draws kept a stale state.
Vertex shaders are never compiled as mask updates.
The mask update fragment stage is no longer dropped for having no colour output.
The mask discard now runs before the colour is written, including the shader interlock storage write.
Not covered: shader interlock (high accuracy). Its render pass has no colour attachment, so the mask is not emulated there (a warning is logged).
Tile-granular region clip (second commit)
GXM region clipping works on whole 32×32 tiles:
OUTSIDE keeps every tile the region touches;
INSIDE drops them.
Both backends clipped at pixel precision, and INSIDE was a stub. The pixel-precise clip used to hide the missing mask, because vitaGL's glScissor relies on the mask for the pixels between the scissor edge and the tile edge. With the mask emulated, the clip can follow the hardware. INSIDE is drawn once per band around the dropped tiles, at most four scissors.

Not tested:

Real hardware: the semantics come from the SDK and from how vitaGL uses the API. The SDK's DF32M formats reserve "one bit for mask update", and sceGxmDepthStencilSurfaceSetBackgroundMask sets its initial value. The probes write their results to a file on a real Vita; I can share them.
