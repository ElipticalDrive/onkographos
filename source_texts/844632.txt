User Story
As a player joining a Voxelheim server
I want the world around my spawn point to be generated and streamed to me
So that there is a place to stand before there is anything to do
Acceptance Criteria
internal/world defines a cubic Chunk of 32x32x32 uint16 block ids, Y-up, with a documented index order
A block id enum covers the skeleton palette: Air, Stone, Dirt, Grass, Snow
A deterministic value-noise + fBm terrain generator is seeded by the world seed: the same (seed, cx, cy, cz) produces byte-identical chunk contents, pinned by a golden test
An RLE codec encodes/decodes (id, run) uint16 pairs, with a roundtrip test and an assertion that a representative terrain chunk encodes to under 4 KB (raw is 64 KB)
On join, the server streams every chunk within view distance ordered nearest-first
Crossing a chunk border streams the newly visible chunks and sends ChunkUnload for the ones that left the radius — no chunk is ever sent twice to the same session
Generation runs on a bounded worker pool and a chunk cache keyed by coordinate; the tick goroutine never generates terrain
gofmt, go vet, go build, go test and golangci-lint stay clean, and go test -race passes
Technical Context
Files to Modify
server/internal/world/chunk.go — chunk type, indexing, block enum
server/internal/world/noise.go — deterministic value noise + fBm
server/internal/world/generate.go — terrain generator, heightmap to voxels
server/internal/world/rle.go, rle_test.go — RLE codec
server/internal/world/cache.go — coordinate-keyed cache and bounded worker pool
server/internal/session/streaming.go — per-session loaded-chunk set, radius diffing, send ordering
server/internal/world/testdata/ — golden chunk fixture
Patterns to Follow
The generator is a pure function of (seed, coord) — it reads no clock, no global rand, no map iteration order, and holds no mutable state between calls.
The per-session loaded-chunk set is a plain set of coordinates; streaming is set arithmetic (new radius minus old radius, and the reverse for unloads).
Encode a chunk once per coordinate and reuse the buffer for every session that needs it; the cache stores the encoded payload next to the chunk.
Follow the layering established by the scaffold: world knows nothing about sessions, session knows nothing about noise.
Constraints
Determinism is a gameplay requirement, not a nicety: the GDD's weekly Fimbulvetr storm regenerates every unprotected chunk to its original procedural state, so the generator must reproduce a chunk exactly, years later, from the seed alone. Use float64 math only, avoid math functions whose results are unspecified, and document the "same server build" caveat in server/AGENTS.md.
MUST NOT add a noise library — determinism under our own control is the whole point, and the generator is a few dozen lines.
MUST keep the encoded chunk payload within the frame size limit set by the transport layer.
MUST NOT block the tick loop on generation.
Out of Scope
Do NOT implement caves, ores, biomes, trees, structures, ruins or runic inscriptions
Do NOT implement water, lighting or block metadata
Do NOT implement ward stones or the Fimbulvetr storm regeneration itself (this issue only guarantees the determinism they will need)
Do NOT implement disk persistence or a save format
Do NOT implement player movement — the streaming trigger for this issue is the spawn point and, once movement exists, the chunk the server says the player is in
Do NOT touch schemas/, the transport layer or the client
Dependencies
Requires #3 (Go server scaffold) to be merged first.
Code Pointers
schemas/world.fbs — ChunkData and ChunkUnload, including the RLE pair layout
schemas/handshake.fbs — ServerWelcome.chunk_size and view_distance, which this issue must actually honor
server/internal/session/session.go — the session state this issue extends with a loaded-chunk set
server/internal/game/loop.go — the tick loop that must stay free of generation work
docs/GDD.md:53 — the storm's regeneration requirement that forces determinism
Test Strategy
Golden test: generate a fixed (seed, coord) and compare against committed testdata bytes — this is the determinism contract
Determinism test: generate the same chunk twice in two goroutines and compare; run under -race
RLE roundtrip: uniform chunk, terrain chunk, and the worst case of alternating block ids (which must still be correct, even if larger than raw)
Border continuity: sample the height column at a shared border from both neighbouring chunks and assert they agree — a seam here is a generator bug
Streaming: table test over a synthetic movement path asserting the exact set of ChunkData and ChunkUnload messages, and that no coordinate is sent twice
Size: assert the encoded representative chunk stays under the documented ceiling, so a regression in RLE efficiency is caught
