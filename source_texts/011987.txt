Description
The only spatial acceleration structure in the raytracer is Grid (include/raytracer/primitives/Grid.h). There is no abstraction (base class or interface) for acceleration structures, so Grid is used directly.
For scenes with large triangle meshes (PLY files) or complex CSG operations, a uniform grid is one of the weakest acceleration structures available. Modern raytracers typically use Bounding Volume Hierarchies (BVH) or kd-trees because:
BVH: O(log n) average traversal, adapts to scene geometry, easy to build incrementally.
kd-tree: Very fast traversal for static geometry, good with triangle meshes.
Grid: Good for uniformly distributed scenes, degrades badly with large empty spaces or non-uniform distribution.
Missing features
No AccelerationStructure base class or interface
No BVH implementation
No kd-tree implementation
No way to swap acceleration structures at runtime or configure per-scene
Suggested Approach
Define an AccelerationStructure interface:
```
class AccelerationStructure {
public:
  virtual void build(const std::vector<std::shared_ptr<Primitive>>& primitives) = 0;
  virtual const Primitive* intersect(const Rayd& ray, HitPointInterval& hitPoints, State& state) const = 0;
};
```
Implement BVH and Grid as subclasses.
Allow Scene to configure which acceleration structure to use.
Effort
Large — implementing a production-quality BVH is a substantial undertaking.
