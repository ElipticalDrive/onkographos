Context
The GPU LOD path (#115, shaders/lodselect.comp, renderer/gpulod.go) culls per instance against the frustum, picks a level, and writes indirect commands with a stable prefix-sum scatter. It never asks whether an instance is hidden behind something already drawn, so a forest behind a hill or terrain patches behind a ridge are selected, scattered and shaded. UniverseBuild's showcase scene is exactly that shape: dense procedural terrain and props under an expensive custom LitFrag, where hidden work is paid in full.
#152 evaluates reordering opaque draws front-to-back inside state groups. Reordering helps only on hardware early-Z and only for pixels that are drawn later; occlusion culling removes the hidden draws before they reach the queue. This is the next step after #152's numbers, ahead of a depth prepass, because it costs nothing on pixels that are drawn.
Proposal
A hierarchical-Z test in the GPU LOD and indirect path, opt-in per InstanceSetLOD (and later per arena batch from #96):
Build a depth mip chain from the previous frame's depth each frame (the engine already keeps SceneDepth() as an R32F copy; a compute node in the frame graph reduces it to a max-depth pyramid under reverse-Z, so a coarser mip is conservative).
In lodselect.comp, after the frustum test, project the instance's bounding sphere to a screen rect, pick the mip whose texel covers the rect, sample the four texels, and reject the instance when its nearest depth is farther than the stored depth. Previous-frame depth with a one-frame reprojection error is the standard trade; a camera cut or a fast pan may show a one-frame pop at the edge of newly revealed geometry, documented.
Rejected instances count in Stats so the saving is visible, and GLYPHENGINE_STATE_TRACE records the pyramid hash and the cull count per set.
Measurement, written before building
cmd/bench scene: a terrainfield ridge with a dense InstanceSetLOD forest on both sides, camera low so most of the far side is hidden, interleaved with and without the test. Ship if GPU opaque time on that scene falls by more than the within-mode scatter, the pyramid pass costs less than it saves, and an open-field control (nothing hidden) moves by less than the scatter. Report the numbers either way.
Correctness
Captures under GLYPHENGINE_FIXED_FRAME_TIME with and without the test must be byte-identical after the first frame on a static camera (a correctly conservative cull removes only invisible instances); a control that uses a min-depth pyramid instead of max must differ, so the gate proves the conservativeness.
task syncvalidate silent across the new node; task lod unchanged; task determinism byte-identical.
The first frame, where there is no previous depth, culls nothing.
Related: #152 (ordering), the visibility-buffer proposal filed alongside this, ADR 0008 (buffer resources and GPU draw generation).
