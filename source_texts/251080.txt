`IndirectDispatchLayout` (renderer/pipeline_io_contracts.h:11) is the 24-byte
GPU-driven dispatch/count header the tile prefix scan writes and binning, both
rasterizers and the instance-count clamp read. It is declared eight times in
GLSL, and before this change only two of those declarations were pinned to
anything: a regex ABI contract in shaders/compile_shaders.py:1380-1412
(key="indirect_dispatch_layout") covering tile_prefix_scan.glsl and
compute/instance_count_clamp.glsl. check_gaussian_layout_sync.py did not
mention the struct at all.

So the six other copies could drift from the host struct with nothing failing.
Swapping two fields in one rasterizer would make it read `unclamped_total` as
`overflow_flag` and `element_count` as a dispatch dimension -- rasterizing a
wrong record count off a buffer the host wrote in the other order, with no
compile-, link- or load-time signal.

Binding numbers were unpinned on both sides as well. check_gaussian_layout_sync.py
parses no `binding` qualifier anywhere (every occurrence of the string in it was
inside a comment), and the reader-side numbers -- 6 in both rasterizers, 9 and 15
in tile_binning.glsl -- appear nowhere else. A binding that drifts on one side
binds a *different* buffer into the block, and a field-layout check cannot see
that, because the layout is not what changed.

This extends the existing guard the way OVERFLOW_STATS_SHADER_MIRRORS covers
OverflowStats, and pins three things per declaration:

  * field layout, field-by-field against the host struct (names, std430
    signatures, offsets, total size), plus the host struct's own
    sizeof/offsetof static_asserts;
  * the `layout(set = S, binding = B, std430)` qualifiers;
  * the host C++ that wires the same slot -- for every
    `X.append_id(...indirect_dispatch_buffer)` / `...indirect_count_buffer` the
    nearest preceding `X.binding = N;` must equal the pinned number, and the
    number of such sites is pinned too. A shader-only pin would just let the C++
    move instead.

Coverage of WHICH declarations exist is derived from the tree, not enumerated:
a ninth buffer block declaring the same field set fails the guard rather than
escaping it. The set/binding each one must use stays explicit, because that is
policy, not description.

Two spellings of the leading dispatch triple exist in the tree (`uint
dispatch_xyz[3]` and three scalars). Both are the same 12 bytes in std430, so
one documented alias maps the array form onto the host's three scalar names
before comparison. It is a spelling equivalence only -- a reorder that swaps a
dispatch component with `element_count` still fails (proved by M2 below).

Known gap, stated rather than left implicit: the host side of

helper that takes the binding as a parameter
(interfaces/gpu_sorting_pipeline.cpp:2656, `contract.binding = p_binding`), so
there is no literal to anchor at the call site. Both GLSL declarations are

Two independent reviews (Codex and /code-review high) found the first version of
this guard was narrower than its own comment claimed. All six findings are
closed, each with a mutation.

F1 (HIGH) -- the sweep globbed `*.glsl` only, and a NINTH declaration of the same
24-byte layout already existed outside that glob: renderer/gpu_sorter.cpp:2356
embeds GLSL in a C++ raw string literal declaring
`layout(set = 0, binding = 0, std430) readonly buffer IndirectCount` with the
full field set, bound to the very `global_sort_resources.indirect_dispatch_buffer`
this guard pins (tile_renderer.cpp:1127). The comment claiming "all eight" and
"a ninth copy cannot quietly escape the pin" was therefore false as written. Fixed
by scanning INDIRECT_DISPATCH_EMBEDDED_GLSL_FILES alongside the .glsl roots and
pinning that block; the count is now nine.

F2 (MEDIUM) -- only the FIRST declaration of a block name per file was parsed, and
the sweep skipped anything whose (path, block) was already listed. A second
declaration of an already-pinned name -- the `#ifdef`/`#else` variant-pair shape,
which tile_binning.glsl's EMIT-pass block is already one half of -- was exempt
from both. Fixed by inverting the structure: the sweep is now the ENUMERATOR.
Every occurrence is validated on its own body and its own layout qualifiers, then
matched against the pinned list; a duplicate of a listed name fails, and a pinned
entry the sweep does NOT find exactly once fails too (that direction catches a
rename or a reformat past the parser, which silently shrinks what is checked).

F3 (MEDIUM) -- the host binding walk scanned text[0:append_id] and took the last
`var.binding = N;`, crossing function boundaries. DELETING an assignment therefore
passed: it fell back to the identically-named variable in the previous function.
RD::Uniform::binding defaults to 0, a real slot, so the compute rasterizer would
have bound the buffer at slot 0 while the guard reported the ABI pinned. Fixed by
anchoring the window to this uniform's own `RD::Uniform <var>;` declaration.

F4 (LOW) -- the sweep's marker test was the whitespace-exact substring
`"uint element_count;"`, so `uint  element_count;` hid a declaration entirely.
Fixed: discovery is now by PARSED FIELD NAME via _parse_fields_from_body, and an
unparsable block that mentions any marker field raises instead of being skipped.

F5 (LOW) -- `_SCALAR_BASE_TYPES[...][1]` is the ALIGNMENT slot, not the size slot.
Inert today because every entry has alignment == size; fixed to [2].

F6 (LOW) -- renderer/tile_render_prefix_scan.cpp:441 declares a local C++
`struct IndirectDispatchReadback` with the same four fields and reinterpret_casts
mapped readback bytes through it instead of using the canonical struct. A
canonical reorder would leave it reading the wrong word with nothing failing.
Pinned via INDIRECT_DISPATCH_HOST_STRUCT_MIRRORS.

Codex additionally found that BOTH C++ scans parsed comments as code, so

    indirect_uniform.binding = 7;
    // indirect_uniform.binding = 6;
    indirect_uniform.append_id(...indirect_dispatch_buffer);

passed -- a binding drift hidden behind nothing but a comment. Fixed by blanking
comments to same-length spaces (offsets stay valid) before every C++ and GLSL
scan.

Mutation proof is now 15, each applied alone and restored, tree GREEN after every
one. The eight original mutations still go RED, plus:

  R1 reorder fields in the embedded GLSL in gpu_sorter.cpp      -> RED  (F1)
  R2 add a second declaration of an already-pinned block name   -> RED  (F2)
  R3 DELETE a .binding assignment (would default to slot 0)     -> RED  (F3)
  R4 hide a declaration behind whitespace-only reformatting     -> RED  (F4)
  R5 reorder the host duplicate struct IndirectDispatchReadback -> RED  (F6)
  R6 hide a binding drift behind a commented-out assignment     -> RED  (Codex)
  R7 rename a pinned block so the sweep stops finding it        -> RED  (new)

R3, R6 and R7 are the ones that matter most: each is a way to make the guard
report agreement that does not exist.

Still not covered, stated rather than left implicit: gpu_sorter.cpp also holds
three 16-byte PREFIX views of the layout (:1823, :1909, :2038, `dispatch_xyz[3]`
plus `element_count`) which depend on element_count staying at offset 12 but do
not carry the full field set, so the marker-based sweep does not see them. They
need a prefix-mirror concept rather than a list entry.

Guard-only; no runtime, shader or host behaviour changes.

`guard failed`/`FAILED (` lines, "Guard-only mode complete".
