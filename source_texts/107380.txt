Please describe the problem you are trying to solve.
Combining time-interpolation with volume coupling and high-dimensional data can result in a lot of data to exchange.
This can overburden the communication backend and/or the network between participants.
Describe the solution you propose.
Inspired by python-blosc2 who provides compression of numpy arrays, preCICE could implement a compression step for exceptionally large amounts of data.
This compression threshold could be hard-coded or configurable, maybe even per m2n.
blosc2 defaults to the modern zstd.
We implemented profiling #2328 compression using lzma as it's supported in the python version used by our users. Otherwise, zstd would have been a better fit.
Steps for evaluation
implement a compression in the m2n send and measure the compression delay using the profiling library
log the compression ratio but don't send the compressed data
run some real cases such as tutorials and how this compression ratio looks in practice.
Gather findings and report in this issue
Describe alternatives you've considered
The alternative could be a lossy method, which reduces the amount of samples needed to compute the bspline on the receiving side.

@fsimonis I implemented a dry-run compression measurement as described in the evaluation steps.
What I did:
Added DataCompressor (src/m2n/Datacompressor.cpp/hpp)— a codec-agnostic compression class supporting ZSTD, LZ4, LZMA, and ZLIB with built-in timing.
Added M2NCompressor (src/m2n/M2ncompressor.cpp/hpp) — wraps DataCompressor for the m2n send/receive path with a 9-byte header protocol and a dry-run mode that measures compression ratio without changing what gets transmitted.
Hooked into M2N::send() — on every send call, data is compressed to measure the ratio and overhead, but the original uncompressed bytes are still what gets sent.
Stats are printed automatically when closeConnection() is called at the end of the simulation.
I basically ran it on tutorial "elastic-tube-1d" and got these results.
```
Pack calls             : 845
Compression skipped    : 0
Total original         : 1,364,712 B  (~1.36 MB)
Projected ratio        : 1.101x       (~10% savings, 125,608 B saved)
Compress time total    : 17.630 ms
Codec                  : ZSTD level 3, threshold 4 KB
```
Conclusion
Compression overhead is negligible (17.6 ms over an entire simulation run).
A 10% saving on this small 1D tutorial case is a promising baseline — larger volume coupling cases with high-dimensional data are expected to show significantly better ratios.
Ready to enable live compression (flip dryRun = false) and run volume coupling tutorials for further benchmarking.
Link to my branch - https://github.com/san-rizz-777/precice/tree/feature/compression-dry-run

@stefano2734 The results in the readme are for a generic benchmark suite, though. The usage in preCICE is very specific:
double only
compressed sections are either:
one large data block for coupling two serial solvers
many small to mid-sized data chunks for parallel solvers.
We are interested in the full chain where we aim for t(compression + send + decompression) < t(send)
Another complication is that sends are asynchronous, so we need to buffer either data somehow.
So, a good start would be to use this benchmark suite and run it on realistic data. So a dump of binary data representing doubles of send data. Then, we can benchmark t(decompression(compression(input)) and estimate the send using the size of compressed and uncompressed data for some common bandwidths.
I'm adding the thesis label as it could be enough for a hands-on bachelor's thesis.

Ndzip by TU Vienna: https://github.com/celerity/ndzip
ndzip compresses and decompresses multidimensional univariate grids of single- and double-precision IEEE 754 floating-point data. We implement
a single-threaded CPU compressor
an OpenMP-backed multi-threaded compressor
a SYCL-based GPU compressor (currently hipSYCL + NVIDIA only)
a CUDA-based GPU compressor
All variants generate and decode bit-identical compressed
Summation: Scientific lossless compression to cpu and gpu
Modern compressors here also for gpu are:
nvCOMP for cuda: last free version 2.2 https://github.com/NVIDIA/nvcomp
HipComp for AMD - clone of nvComp 2.2: https://github.com/ROCm/hipCOMP-core
