Goal
Prepare the codebase for flexible terrain height modifications, enabling future tasks like:
Adding undulations to specific areas
Creating foothills between zones
Adding terrain features (dips, hills, ridges)
Modifying elevation at specific grid points
Current Architecture
Heightmap.luau - Single source of truth for terrain height
TerrainGenerator.luau - Visual terrain from heightmap
Various spawner services query Heightmap:GetHeight(x, z) for positioning
Requirements
DRY/SOLID/APIE Principles
Single Responsibility: Height calculation vs height modification vs object placement should be separate
Open/Closed: Easy to add new terrain modifiers without changing core heightmap
Interface Segregation: Services should depend on minimal height query interface
Robustness Requirements
Objects must NEVER spawn underground or floating in sky
Height modifications should automatically update all dependent objects
Support for terrain "patches" that can be added/removed dynamically
Height queries must always return valid values (even at boundaries)
Research Areas
General Game Development Strategies
Research heightmap layering systems (base + modifiers)
Study procedural terrain modification patterns
Look at voxel engine terrain modification approaches
Roblox-Specific
Roblox terrain WriteVoxels performance considerations
Best practices for updating terrain at runtime
Terrain streaming with dynamic modifications
Our Game Specifics
Impact of terrain changes on existing objects
Integration with earthquake system (terrain deformation)
Zone boundary transitions with height blending
Implementation Ideas
Terrain Modifier System
```
-- Example: Add height modifier layer
Heightmap:AddModifier("foothills", {
    region = { xMin, zMin, xMax, zMax },
    heightFunc = function(x, z, baseHeight) return baseHeight + noise * 20 end,
    priority = 1,
})

-- Example: Local height adjustment
Heightmap:SetLocalHeight(x, z, newHeight)

-- Example: Area modification
Heightmap:ModifyArea(centerX, centerZ, radius, deltaHeight, blendMode)
```
Object Relocation on Terrain Change
When terrain is modified, all objects in the affected area should be automatically repositioned:
```
-- After terrain modification
for _, object in CollectionService:GetTagged("TerrainAnchored") do
    local pos = object.Position
    local newY = Heightmap:GetHeight(pos.X, pos.Z)
    object.Position = Vector3.new(pos.X, newY + offset, pos.Z)
end
```
Acceptance Criteria
Can add terrain modifiers without modifying Heightmap core
Can remove terrain modifiers and terrain returns to base
Objects automatically reposition when terrain under them changes
No Z-fighting or floating objects after terrain modifications
Terrain transitions between modified and unmodified areas are smooth
Performance remains acceptable (terrain gen < 10 seconds)
Notes
This is a preparatory refactor - no actual terrain changes needed yet, just the infrastructure to support them easily in the future.
