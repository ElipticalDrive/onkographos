# Voxel Cloud Lab

Offline Python **3D point-cloud downsampling** learning tool. Group supplied XYZ points into origin-anchored voxels and replace retained groups with their centroids. Explore spatial reduction before studying robot-perception pipelines.

![Computed synthetic XY projection](projection.svg)

## Run

Python 3.10+; no packages or network required:

```sh
python voxel.py sample.json --size 1 --min-points 2 --out cloud-report
python -B -m unittest -v
```

Open `cloud-report/projection.svg`. Review voxel counts, centroids, maximum within-cell radius and input bounds in `report.json`; import `centroids.csv` for downstream analysis. Existing output directories are refused. Invalid data exits with code 2.

```json
{"points":[[0.1,0.1,0.1],[0.3,0.2,0.2]]}
```

## Geometry and configuration

Cell index = floor(coordinate / size), independently along X,Y,Z. Cells are half-open: [i·size,(i+1)·size). Negative coordinates use floor, not truncation toward zero. Floating-point values extremely close to boundaries may reflect representation rounding; no epsilon snapping is applied.

Centroids are arithmetic means of all observations in a voxel. Duplicate points count as repeated observations, not deduplicated samples. `min-points` filters voxels with insufficient observations; this is a density rule, **not proof of noise**. Output cells are sorted lexicographically. Maximum radius measures the farthest member's distance to its centroid, not an uncertainty estimate. Input/output units are whatever consistent units the caller supplies; no metres claim is inferred.

Input cap 2 MB, 1–20,000 points. Coordinates finite numeric XYZ within ±1,000,000; booleans rejected. Size finite from 0.000001 to 1,000,000, minimum point count positive integer. All-filtered output is valid and produces header-only CSV.

## Visual and architecture

`voxel.py`: validation → grouping → centroid/radius measurement → JSON/CSV/SVG and CLI. `test_voxel.py`: geometry, negative/boundary behavior, Z separation, density filtering, repeated observations, invalid values, ordering, XML and overwrite protection.

`sample.json`: original synthetic fixture, 13 points. At size1/min-points2, four centroids retained and one singleton filtered. Published `projection.svg`, `report.json`, `centroids.csv` are executed outputs. The 1600×1000 graphic is a computed **XY projection**, not a camera screenshot or 3D rendering; Z is omitted and distinct XYZ points can overlap visually.

## Limitations and provenance

No sensor driver, PLY/PCD parsing, RGB attributes, normals, registration, SLAM, obstacle detection or robot control. Voxel reduction loses detail and can erase thin structures. Density filtering can remove valid sparse objects. No physical robot or real-dataset accuracy claims. Next steps: explicit coordinate-frame metadata and color-preserving reductions.
