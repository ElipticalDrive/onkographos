決定 (2026-10-16・メンテナ同席の棚卸し)。 この Issue は B (4 次元の noise(x, y, z, w) を CPU と断片の両方に足す) だけで閉じる。A (値として持てる揺らぎ) は、種を値で持つ型の形を乱数源とそろえるため #2418 で決め、この Issue の範囲から外す (作例の Quarry・Grain は #2418 へ引き継ぐ)。C (中心 0・simplex) は作例待ち。完了条件は「完了条件 (確定)」が正本。
レビューの記録: #2409 (2026-10-12 の書き味レビュー)。main 58eea05c のコードを読んだ静的なレビューで、手元でスケッチや GPU の検査は走らせていない。
現状
揺らぎは 1〜3 次元の value noise である。
CPU の側: Sources/MokumeCore/Random/ValueNoise.swift:39, 84, 162
断片の側: mokume_noise が同じ式で 3 次元まで (Sources/MokumeCore/Drawing/Shaders/Common.metal:472-494)
種と細かさはスケッチに 1 つで、断片にも同じものが届く (Sources/MokumeCore/Sketch/Sketch+Random.swift:278-290, 358-363)
ここから 3 つの詰まり方が出る。
1. 2 次元の場をループさせられない。 継ぎ目の無いループ (GIF や展示の繰り返し) は、時刻を円周に載せて揺らぎを引くのが定番である。
1 次元の場なら、noise(x, cos θ, sin θ) と 3 次元で書ける
2 次元の場には 4 次元が要る
```
let a = TWO_PI * mod(time, 2) / 2
let n = noise(x * 0.01, y * 0.01, cos(a), sin(a))   // 4 つ目の座標が渡せない
```
2. 呼び出しごとに種を変えられない。 別の模様が欲しいだけでも、全体の状態を書き換えることになる。
noiseSeed は断片にも及ぶ。形の組み立て (createShape) の出入口でも戻す決まりがある (fix(shape): createShape の中で noiseSeed() / noiseDetail() を呼ぶと、同じフレームに先に図形があれば形が空になる #1855・design(shape): 本体の組み立ての中で描き場所自身の noiseSeed を書くと、出口でその描き場所の置き場が戻らない #2090)
作品は自前で書いている (mokume-metal/works ff682c2)
Quarry は塩つきのハッシュを 19 か所で引く (Quarry/Sources/Quarry/Tiles.swift:59-134, 189)
Grain は板ごとの種で自前の揺らぎを引く (Grain/Sources/Grain/Plank.swift:28-56)。Grain の自前の揺らぎは mokume の揺らぎが入った日に書かれ、そのまま残っている
3. 値が 0.5 のまわりに寄る。 重ねた枚の合計で割るので、枚数を増やすほど幅が狭まる (ValueNoise.swift:182-199)。参照スケッチは引いた後で広げている (Sketches/NoiseAndSeed.swift:121-124)。
```
// 揺らぎは 0.5 のまわりに寄るので、広げてから使う
let glow = constrain(map(noise(x * 0.02, y * 0.02, time * 0.8), 0.3, 0.7, 0, 1), 0, 1)
```
スケッチの外の型から noise() を呼べない件 (Quarry は揺らぎを閉包で受け渡している・Quarry/Sources/Quarry/Terrain.swift:5-7) は #2412 が扱う。
他のツールでは
openFrameworks: ofNoise(x, y, z, w) は 1〜4 次元 (simplex)。中心 0 の ofSignedNoise もある
OPENRNDR: Random.simplex は 4 次元まで。orx-noise の fbm(seed, x, y, …) は種を引数で受ける
Cinder: ci::Perlin(octaves, seed) はインスタンスごとに種と枚数を持つ。傾きも返す dfBm がある
nannou: noise crate の Perlin・Simplex・Worley・Fbm はインスタンスごとに種を持つ
three.js: SimplexNoise (examples) は 4 次元まで
Processing・p5: 1〜3 次元で、種と細かさは全体で 1 つ (noiseSeed・noiseDetail)
選択肢
A. 揺らぎを値として持てる型を公開する (採らなかった案。この Issue の範囲の外 — design(random): 乱数の列を値として持てず、Swift 標準の randomElement・shuffled・Float.random が種を無視して決定論を黙って破る #2418 で乱数源と形をそろえて決める) (仮名 Noise(seed:octaves:falloff:)。中身は既存の ValueNoise)。
スケッチの noise() は、スケッチの設定でこれを引く形のまま残す
値なので、部品ごとに別の種で引け、struct の中や design(concurrency): 値だけを扱う数と色の関数 (map・lerp・color・noise) を nonisolated にし、並列に回せるようにするか #2389 の nonisolated とも衝突しない
代償: 公開の型が 1 つ増える。断片の mokume_noise は全体の種を読むので、値で作った揺らぎを断片で揃えるには、種を値として渡す口が別に要る (作例が来てから)
B. 4 次元の noise(x, y, z, w) を、CPU と断片の両方に足す。 (2026-10-16 に採った)
代償: CPU と断片の一致を検査 (NoiseParityTests) で見ている (ADR-0001 原則 9) ので、MSL の口と突き合わせの検査も足す
4 次元は格子の隅が 16 で、3 次元の 2 倍かかる
既存の 1〜3 次元の値は変えない
C. 中心 0 の版や勾配ノイズ (simplex) を足す。 (採らなかった案。作例待ち) 代償: アルゴリズムが 2 つになり、断片との一致の検査も 2 倍になる。作例が来てから
推奨
A と B。B は継ぎ目の無いループという作例がはっきりしている。A は作品の自作 (Quarry・Grain) と、#2418 の乱数源の値型と同じ形で揃う。C は作例待ち。
作例
2 秒で継ぎ目なく巡る流れ場。格子の矢印の向きを 4 次元の揺らぎで決め、時刻を円周に載せる。
```
func draw() {
    background(15)
    stroke(230)
    let a = TWO_PI * mod(time, 2) / 2
    for y in stride(from: Float(10), to: height, by: 20) {
        for x in stride(from: Float(10), to: width, by: 20) {
            let angle = noise(x * 0.01, y * 0.01, cos(a) * 0.8, sin(a) * 0.8) * TWO_PI * 2
            line(x, y, x + cos(angle) * 8, y + sin(angle) * 8)
        }
    }
}
```
(TWO_PI は #2421、mod は #2416 の口)
完了条件の案
noise(x, y, z, w) が import mokume だけで呼べる。同じ種・同じ座標で、CPU と断片 (mokume_noise(in, float4)) が NoiseParityTests の許容の内で一致する
円周に載せた座標 noise(x, y, cos θ, sin θ) で引くと、θ = 0 と θ = 2π の場が一致し、θ = π の場はそれと違う (場が巡りながら変わる)。いまの 3 次元では、2 次元の場をこの形で引けない
w = 0 のときの値が、いまの noise(x, y, z) と同じ (既存の絵が動かない)
値の型を採るなら、Noise(seed: 11).value(x, y) が noiseSeed(11) の後の noise(x, y) と一致し、スケッチの種を書き換えない
確かめ方: ValueNoiseTests・NoiseParityTests に並びを足し、実装を一時的に壊して赤くなるのを見る。専用機の render の台帳が動かないこと。make ci-check が緑

着手時のプラン (origin/main a6994dd3)
決定のとおり B (4 次元の noise(x, y, z, w) を CPU と断片の両方に足す) だけを扱う。A (値の揺らぎ・種) は #2418。
完了条件と現行コードの突き合わせ
条件
判定
1. noise(x, y, z, w) が import mokume だけで呼べる・some ScalarConvertible・置き場は Canvas と SketchPart
まだ有効。noise は 3 引数まで (Canvas+Noise.swift:32・Sketch+Random.swift:242)。4 つ目の引数を同じ形 (some ScalarConvertible = 0) で足す
2. CPU と断片の mokume_noise(in, float4) が NoiseParityTests の許容の内で一致
まだ有効。断片は float3 までで float4 は無い
3. 円周に載せた座標で θ = 0 と 2π が一致し、θ = π は違う
まだ有効。ただし ビット単位ではなく許容の内の一致になる: Float の sin(2π) は 0 でなく −1.7e-7 なので、θ = 2π の座標は w がわずかに 0 から外れる。値は w について連続なので、差は 1e-6 の桁に収まる (検査はこの許容で縛る)
4. w = 0 で今の noise(x, y, z) とビット単位で同じ
まだ有効。value(x, y, z, w) は w == 0 (-0 も) なら今の 3 次元の入口へそのまま渡す。4 つ目の軸の格子が 0 の所では隅を引かない (#1788 と同じ扱い) ので、今の 1〜3 次元の経路は 1 行も通る道が変わらない。断片 (float3 の経路) も触らない
5. noiseSeed・noiseDetail が 4 次元にも効く・軸が 0 なら隅を引かない扱い
まだ有効。同じ ValueNoise の設定を読む。軸が 0 の扱いは 4 つ目の軸にも当てる (w == 0 は 3 次元へ)
6. 検査・作例・make ci-check
まだ有効。参照スケッチへ足すと専用機の絵の台帳が動くので、作例は説明文 (noise の doc) に書く。TWO_PI・mod は main に無いので Float.pi・truncatingRemainder で書く
7. changelog.d/ の .feature.md
まだ有効
変更点
ValueNoise.hash に 4 つ目の整数の軸を足す: h ^= UInt32(bitPattern: w) &* 0xC2B2AE3D。w = 0 なら 0 を xor するだけなので、3 次元の格子点の値はビット単位で変わらない。3 引数の hash は 4 引数へ渡す形にして、混ぜ合わせを 1 本に保つ。corner も同様
ValueNoise.layer(x, y, z, w, seed) (格子の隅は 16。w の 2 つの面を今の 3 次元の繋ぎ方で引き、w の繋ぎで混ぜる)。value(x, y, z, w) は有限でなければ 0・w == 0 なら今の value(x, y, z)
Common.metal: mokume_noiseHash・mokume_noiseCorner に w の口、mokume_noiseLayer(float4, uint)、mokume_noise(Fragment, float4) を足す。float3 / float2 / float の既存の経路は変えない (専用機の台帳が動かない)
Canvas.noise と SketchPart.noise に _ w: some ScalarConvertible = 0。説明文に 4 つ目の座標と、2 秒で巡る流れ場の例 (時刻を円周に載せる) を足す
Documentation/mokume.docc/mokume.md の noise(_:_:_:) のリンクを 4 引数の形へ。ほか共有点 (scripts/api-surface.py・Sketches/Catalogue.swift) は触るものが無いか確かめる
確認方法
NoiseTests: 4 次元の揺らぎが 0…1・同じ座標で同じ値・w で連続・w に依存して変わる
継ぎ目の無いループ: noise(x, y, cos θ, sin θ) を θ = 0 と 2π で比べて許容の内で一致し、θ = π では違う (CPU)
w = 0 (と -0) のとき、今の noise(x, y, z) とビット単位で一致する (NoiseFlatAxesTests に並びを足す。種・枚数・極端な座標を混ぜる)
NoiseParityTests: 断片の mokume_noise(in, float4) と CPU を、w ≠ 0 の代表点・種・細かさで突き合わせる。GPU を通るので触った suite を 1 度だけ走らせ、全段は CI に任せる
4 つ目の軸の混ぜ合わせ (hash の定数・w の繋ぎ) を一時的に壊して、赤くなるのを見る
