Using https://github.com/bashtage/ng-numpy-randomstate might make this much easier. The performance of (that implementation of) PCG64 is disappointing (slower than numpy's MT), PCG32 is a bit faster than np.MT, the provided MT is mostly the same as np.MT (even though they claim to be faster), however the performance of dsfmt (MT optimised for SIMD) is very interesting: 2x as fast as MT.
But apart of performance, other generators support independent streams or "jump" (which can be used to emulate them), which would be super useful to implement #16. See.
http://bashtage.github.io/ng-numpy-randomstate/doc/build/html/parallel.html#independent-streams
```
>>> %timeit np.random.random_sample(size=1000000)
100 loops, best of 3: 11.9 ms per loop
>>> mt = randomstate.prng.mt19937.RandomState()
>>> %timeit mt.random_sample(1000000)
100 loops, best of 3: 11.2 ms per loop
>>> p32 = randomstate.prng.pcg32.RandomState()
>>> %timeit p32.random_sample(1000000)
100 loops, best of 3: 9.79 ms per loop
>>> p64 = randomstate.prng.pcg64.RandomState()
>>> %timeit p64.random_sample(1000000)
100 loops, best of 3: 15.7 ms per loop
>>> dsfmt = randomstate.prng.dsfmt.RandomState()
>>> %timeit dsfmt.random_sample(size=1000000)
100 loops, best of 3: 5.63 ms per loop
```
There is a BIG FAT gotcha though: all those generators (except randomstate.prng.mt19937) are marked as "No Compatibility Guarantee".
pcg64.RandomState does not make a guarantee that a fixed seed and a
fixed series of calls to pcg64.RandomState methods using the same
parameters will always produce the same results. This is different from
numpy.random.RandomState guarantee. This is done to simplify improving
random number generators. To ensure identical results, you must use the
same release version.
