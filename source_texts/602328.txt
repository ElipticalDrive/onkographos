Problem
The .preview.slang convention was not a real USD path and the separate preview iterations obscured the useful next architectural step. Before OpenUSD mesh data can render, Render Toy needs a real-geometry consumer contract rather than assuming every Scene shader is a three-vertex fullscreen SDF raymarch.
Change
Removes the fake USD-open/.preview.slang product contract and fixture sidecar.
Replaces Render Toy's default SDF scene with a packaged six-vertex, UV-mapped raster material card. Slang owns positions, UVs, normals, and base-color/roughness/metallic evaluation.
Preserves the previous SDF studio as the separate Samples > Scene — SDF studio entry.
Adds explicit main/scene vertex counts to SlangRhiWidget; C++ owns draw submission while provider Slang owns geometry. Existing fullscreen samples remain three-vertex draws.
Marks the packaged base Scene shader read-only and [generated]; Material controls remain inspectable while Render Toy's Post shader stays editable and controls the final viewport.
Retains the pinned usd-wg/assets test-only submodule and third-party license inventory from the prior revision.
Documents exactly which USD mesh data must later cross the edge: topology, points, normals, UV primvars, transforms/orientation/subdivision, material bindings, composed MaterialX/UsdShade inputs, and resolved textures.
CI fixes
The prior Windows failures are removed rather than papered over:
the action/method name-shadowing path is deleted with the fake USD loader; and
the invalid boolean use of RenderToySession::bindScene() (which returns void) is deleted.
Focused Python checks, fixture validation, Ruff, clang-format, and diff checks pass locally. The native matrix will validate Slang compilation and QRhi draw behavior.
Why this is the USD starting point
The next native OpenUSD slice can turn one selected mesh into the same explicit scene draw product, initially rebuilding it on a whole-stage identity change. It does not need to convert geometry into an SDF, invent a shader sidecar, change the Post pass, or add another viewport.
Public API
SlangRhiWidget gains vertexCount/setVertexCount and sceneVertexCount/setSceneVertexCount. A native contract verifies defaults and overrides. The earlier unmerged openUsdAsset/usdAsset proposal is removed.
Deliberate non-goals
This PR still does not claim to open Houdini USD directly. It does not add a Python-owned stage, handwritten USDA parser, scene database, Hydra replacement, or generic geometry framework. Native OpenUSD ownership and GPU mesh buffers are the next bounded implementation slice.

### Motivation

- Provide an evidence-led, bounded USD/MaterialX authoring preview that treats generated Slang as a read-only derived product rather than authored scene meaning.
- Allow Render Toy to explicitly open a USD asset by binding its accompanying `.preview.slang` derived shader while keeping the editable Post shader separate.
- Record third-party test assets, licenses, and a pinned, test-only `usd-wg/assets` submodule so research fixtures are reproducible without packaging them into runtime artifacts.
- Capture the experiment, fixture, and outcome in documentation and a small probe so follow-up native integration work can be ordered and validated.

### Description

- Added a test-only Git submodule (`third_party/usd-wg-assets`) and `THIRD_PARTY.md` documenting third-party licensing, provenance and a quick `git submodule update --init` command.
- Implemented an explicit derived-preview flow in the UI by adding `WorkbenchWindow::usdAsset`, `WorkbenchWindow::openUsdAsset()`, a menu entry, and logic to open a `.preview.slang` sidecar, bind it into Render Toy, and mark the document as read-only.
- Introduced `ShaderDocument::readOnly` property with `setReadOnly()` and enforcement in `setSource()` and `save()` so generated/derived documents are immutable in the editor; emitted `readOnlyChanged()` and updated `WorkspaceEditor` to respect the read-only state and annotate tabs with ` [generated]`.
- Added the `spikes/usd_materialx_probe` fixture and probe script plus generated Slang stages and supporting USD/MTLX fixture files, expanded documentation (`src/docs/research/usd_materialx.rst`, `src/docs/using/material_preview.rst`, `ARCHITECTURE.md`, `CHANGELOG.md`, `VISION.md`, `README.md`) and updated tests to assert the new API and read-only behavior.

### Testing

- Ran the dependency-free probe check `spikes/usd_materialx_probe/probe.py check` to validate fixture layout, MaterialX XML structure, texture bytes and preserved SHA256 sums, which succeeded.
- Executed the updated Python-installed API test `tests/installed/test_package_contract.py` to assert `WorkbenchWindow` exposes `openUsdAsset/usdAsset` and `ShaderDocument` read-only immutability, which passed in the CI run.
- Built and ran the updated C++ unit `tests/test_shader_workspace.cpp` to validate read-only enforcement and workspace session behavior, which passed locally in the development build.
- Note: native OpenUSD and MaterialX native-linked tests (`usd-roundtrip` and `generate`) remain guarded by missing native bindings and are intentionally blocked by the probe when the environment lacks those dependencies.
