Description
This PR implements two optional, related features that improve the usability of bitmaps, particularly when they are used for segmentation or to indicate the boundary of a volume:
Smoothed rendering of bitmap surfaces
Clip planes that clip bitmaps and all volumes, not just the first one
Screenshots
These were taken with the "Drawing User Interface" demo page with the volume it loads by default. I applied an Otsu with 2 segmentation classes and switched the view to "Render" only.
Before
This is Niivue's current behavior in this scenario (and continues to be the default after this change).
Note how the jagged/blocky appearance of the bitmap makes it difficult to see the border of the volume or inside it.
With surface smoothing
Surface smoothing is enabled by setting nv.opts.smoothDrawing to a nonzero value. In this example, it is set to 2.0. This can be done in the demo page at Draw --> Smooth Drawing 3D.
Note how the smoothing makes it possible to see the surface of the gray matter, even where the volume is not rendered because of the location of the clip plane.
With surface smoothing and global clipping
Global clipping is enabled by setting nv.opts.isClipAllVolumes = true. This can be done in the demo page at View --> Clip All Volumes.
Note how the clipping makes the clip plane even more visible. It effectively cuts a hole into the bitmap, allowing the user to look inside to see the volume.
Users who are familiar with the Hyperfine Swoop system user interface will recognize this as the "3D 2" view mode.
Implementation
Smooth bitmap surface rendering
This is implemented in three phases:
A blurred version of the bitmap is created on the CPU. To do this efficiently, it is implemented as box blurs instead of a Gaussian blur. To avoid unresponsiveness, this is done on a Web worker (much like Brainchop).
The blurred bitmap is sent to the GPU as a R16F 3D texture with LINEAR filtering for additional free smoothing.
The render shader uses the blurred bitmap texture to find the isosurface and calculate the surface normal, which it then uses to apply Phong shading.
Global clip planes
When rendering volumes and isClipAllVolumes is set, the shader simply skips over voxels that are behind the clip plane, regardless of which volume it is rendering.

@aarma this is a really interesting idea—thanks for putting it together. It might be helpful to start this as an issue so we can get broader community input on the use case, potential overlap, and implementation options.
There does seem to be some overlap with the setRenderDrawAmbientOcclusion() option, so it would be good to clarify how this extends or differs from that behavior.
Since the blurred data ultimately needs to live on the GPU, this could be a nice opportunity to leverage GLSL shaders rather than round-tripping through the CPU. One possible starting point is the blurFragShader() fragment shader, which might fit well with what you’re proposing.
