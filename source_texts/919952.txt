Problem
Pulsar issue Far-Beyond-Pulsar/Pulsar-Native#461 reports the default VoxelMesh pass occupying GPU timestamp range 643-1686. The default Helio graph installs VoxelMeshPass even when the scene has no mesh voxels.
The pass currently always returns a full-resolution color/depth render-pass descriptor and submits VOXEL_MESH_MAX_BRICKS indirect draws every frame. Zero-count indirect entries do not make the attachment load/store or command submission free, so non-voxel editor scenes pay for the pass.
Correct engine-wide fix
Track CPU-visible occupied brick slots as upload/edit contracts are applied.
Keep dirty empty bricks eligible for compute re-extraction so stale indirect draws are cleared.
Return no render descriptor when no occupied mesh bricks exist, avoiding the color/depth attachment pass entirely.
Bound native multi-draw and WebGPU fallback loops to the highest occupied slot instead of the full capacity.
Update every native and web voxel-mesh caller to provide the occupancy result produced while baking a brick.
Ensure clearing the final occupied slot disables the render portion again.
Validation
Unit coverage for empty, occupied, deactivated, and trailing-slot draw bounds.
Helio voxel mesh demo visual validation after edits and regeneration.
Pulsar editor GPU timing validation against #461 with no mesh voxel volumes.
Check all affected Helio crates and examples before the Pulsar pin is updated.
