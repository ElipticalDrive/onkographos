The GPU-sort renderer culls splats whose screen contribution (opacity × projected area) is below GSplatParams#minContribution. At the default of 3 this removed a visible part of distant scenes: far views lost up to 29% of their image energy and looked darker and thinner than the same scene with CPU sorting, which has no contribution cull. supersplat-viewer already uses 1.
Changes:
GSplatParams#minContribution defaults to 2 (was 3), and the render.gsplatMinContribution scene setting the same.

API Changes:
GSplatParams#minContribution: default 3 → 2. Apps that want the previous culling set it back:
```
app.scene.gsplat.minContribution = 3;
```
Performance:
More splats survive the cull, mostly in distant views: in the scenes above, near views keep 15–20% more splats and far views 70–103% more, about half the increase a value of 1 gives. The examples that set the value explicitly (billions, downtown, vr-lod, streamed-lcc2, relighting) keep 3.
