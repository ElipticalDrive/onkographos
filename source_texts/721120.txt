Summary:
CUDA rendering previously materialized full-frame triangle-index, barycentric-coordinate, and normal images for every mesh before running Phong shading as a sequence of Torch kernels. This extends the existing second raster pass to compute perspective-correct barycentrics and eye-space normals transiently, interpolate device-resident colors and textures, evaluate built-in Phong lighting, and write directly into caller-owned RGB storage.
The Torch API now follows the established in-place rasterization model: callers provide the required depth target and any optional RGB, triangle-index, vertex-index, or surface-normal targets. Supplying RGB enables shading; omitting it performs depth and requested-attribute rasterization only. Rasterizers allocate no output buffers, mutate supplied targets, and return None. Unbatched and batched geometry remain supported, with topology, camera, material, textures, colors, and lights shared across each batch.
The public barycentric image is removed because barycentrics remain transient kernel values. CPU rendering stays on the established direct-shading path, while CUDA uses one batched depth launch and at most one batched output or shading launch per mesh call. Character shading computes smooth vertex normals only when RGB or normal output is requested. Skeleton RGB rendering preserves separate joint and bone materials; Torch-only skeleton index outputs remain available in depth/attribute mode.
