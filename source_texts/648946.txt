Contributor
What: TripoSplat as a second image-to-3D family behind LibreGen: LibreGen("triposplat")("chair.jpg").save("chair.ply").
Why: TripoSplat (TripoAI, MIT code and weights, SIGGRAPH 2026) is the model Speridlabs Idol builds on; same call, same Gaussians output, no new task or payload.
libreyolo/models/gen/triposplat/: nn.py (denoiser, octree and Gaussian decoders, upstream config constants), pipeline.py (Euler sampler with upstream's diffusers-style guidance), model.py (LibreTripoSplat, size 0.6b, knobs steps 20, guidance 3.0, shift 3.0, gaussians 262144 in 32,768..262,144, margin 1.2), NOTICE.
libreyolo/models/gen/image3d.py: the steps both families share, moved out of the Idol pipeline unchanged (background removal, crop, DINOv3 + FLUX.2 VAE tokens, camera decoding, encoder loading); Idol re-exports them under the old names.
Weights: redistributed as LibreYOLO/LibreTripoSplat0.6b (MIT, with LICENSE and NOTICE): the denoiser, decoder and BiRefNet files, byte-identical (SHA-256 checked) to the pinned VAST-AI/TripoSplat@56a96e6 snapshot, in its folder layout. Upstream's DINOv3 and VAE copies are not mirrored; the encoders are the ones Idol uses (LibreYOLO's bf16 DINOv3 mirror, klein VAE). Nothing gated.
fp16 networks on CUDA and MPS as upstream, fp32 on CPU; no compiled path (compile=True raises). Octree sampling and leaf jitter draw from the seeded generator (upstream uses the global one), so a seed reproduces the whole object. Quaternions normalised (upstream writes the raw biased ones).
Wiring: aliases triposplat, triposplat-0.6b; exports, registry group s, inventory, CLI help, smoke surface; regenerated reports/export_inventory.json and docs/export_support.md.
Docs: docs/libregen.md, ADR 0031, nomenclature, checkpoint schema, CHANGELOG, NOTICE, THIRD_PARTY_NOTICES, weights/LICENSE_NOTICE.txt; README and README.zh-CN "3D generation" row gains the family name (per AGENTS.md this needs maintainer approval).
Tests: tests/unit/test_triposplat.py (24 tests: factory, pins, knobs, full-size state-dict schema, sampler guidance convention, decoder counts, end to end at a tiny size, BiRefNet loading); weights/parity_triposplat.py for the CUDA stage-by-stage gate.
Check: image3d.py is a move, not a rewrite (Idol tests unchanged and green); the guidance convention differs from Idol's on purpose (s here is Idol's 1 + w); _network_dtype per device.
Verified: parameter names and shapes of all three networks equal the published safetensors headers (559, 388 and 754 tensors); 73 tests in the gen suites plus export support, registry, CLI and task tests pass offline. On an M4 Pro (MPS, fp16, torch 2.14): three example images at the defaults (20 steps, 262,144 Gaussians) take about 175 s each; plot() previews from the inferred camera match the inputs (lily, butterfly), so the shared camera decode holds. Downloading from the mirror through LibreGen("triposplat") works. Greptile pre-review: one finding fixed (the tiny test's octree depth patch); the other (sample_probs rows below 1 after fp16 softmax) is upstream's arithmetic, kept for parity.
CUDA parity (weights/parity_triposplat.py, Modal A10G, torch 2.11.0+cu128, upstream at d8db9e0 with its own weights): ALL PASS on four cases (defaults; 65,536 Gaussians; steps=10, guidance=1.0; shift=2.0, gaussians=32768). Bitwise equal to upstream: the preprocessed image, the FLUX.2 VAE tokens, the sampled latent and camera from the same tokens, and every Gaussian attribute from the same latent. The DINOv3 tokens differ at bf16 noise level (mean 0.006, max 0.84) between transformers and upstream's hand-written ViT on identical weights; gated by mean error and documented in ADR 0031. The first run exposed a port bug (Sobol positions rounded to fp16 with the weights), fixed in 9237465.
Not verified: CPU end to end at full size.

Code provenance
Ports TripoSplat (https://github.com/VAST-AI-Research/TripoSplat, commit d8db9e018b413dd9c4a9fe22463781bf98e8e68d, MIT) into libreyolo/models/gen/triposplat/nn.py and pipeline.py, with unchanged parameter names. libreyolo/models/gen/image3d.py is code moved from libreyolo/models/gen/speridlabs_idol/pipeline.py, itself ported from the Apache-2.0 Idol SDK (commit 4702a7f00850e34b6e83a2170cc123c3e9570744). Attribution in the family NOTICE, the root NOTICE and THIRD_PARTY_NOTICES.txt. All other code is original. The image encoders load through the public transformers and diffusers APIs (Apache-2.0). Weights are VAST's (MIT), Black Forest Labs' (Apache-2.0) and Meta's DINOv3 mirror (DINOv3 License), all downloaded at pinned revisions. No GPL/AGPL/LGPL, non-commercial-licensed or unknown-license code is involved.
