Opt-in Object V4 selects sparse encoding for eligible typed JSON paths using ratio_of_defaults_for_sparse_serialization. Selection is fixed per part from the retained first-block statistics and recorded in the Object structure prefix, so reads always use the encoding stored in the part rather than the current table settings. Dynamic paths keep their existing Variant encoding, without an outer Sparse wrapper. V3 remains the default; V1–V3 layouts are unchanged.
The wide part reader re-evaluates streams that were provisionally marked as partially read once the deserialization prefix reveals the actual encoding, since a sparse Nullable typed path has offsets instead of a null-map stream.
Covered by 04339_json_columnar_sparse, a Jinja2 SQL test that renders the part-type / threshold / block-size matrix into a single script: Wide and Compact parts, several threshold values, mixed V3/V4 merges, mutations, nested typed JSON, dynamic paths, subcolumn .null reads, and nonzero-offset reads, with assertions that dynamic paths never gain sparse streams. The Jinja2 form avoids one client process per statement, which keeps the merge/mutation-heavy test within the timeout on slow builds.

Harden sparse typed path statistics and serialization selection

```
Fix several robustness issues found in review:

- `ColumnObject::getOrCalculateStatistics`: the validity guard for typed
  path estimates was unsound. A size-only comparison, an `empty()` bypass,
  and a first-entry `num_rows` probe could accept stale disk statistics or a
  partial-block estimate copied from a single merge source, and the fill loop
  could leave `{0,0}` stubs for missing paths. Either way the per-part sparse
  decision could be driven by data that does not describe the first full
  output block. Now the estimates are only reused when they cover exactly this
  column's typed paths with a non-zero row count, and recomputation drops
  stale/incomplete entries instead of inserting stubs.

- `MergeTreeWriterSettings::object_paths_sparse_default_ratio`: change the
  default from `0.9375` to `1.0` (disabled) to fail closed, matching the
  serialization settings. A writer constructed without setting the ratio no
  longer silently enables sparse typed path encoding under V4.

- `SerializationSubObject::enumerateStreams`: resolve the per-path
  serialization once in the prefix and reuse it for enumeration, so a subobject
  read answers stream existence with the actual (possibly sparse) on-disk
  layout instead of always probing the dense layout.

- `MergeTreeReaderWide`: document that the partially-read-stream recheck is
  load-bearing for V4 sparse typed paths.

- Slim down the `04339_json_columnar_sparse` test so it fits within the
  timeout on slow builds: drop the redundant `max_block_size=7` sweep and the
  `ratio=0.5` case (identical boundary behavior to `0.9375`), and tag it
  `no-msan, no-tsan` since memory/thread sanitizers make this
  merge/mutation-heavy test exceed the test timeout without adding coverage.
```

Add sparse encoding for JSON typed paths with Object V4
…
f9d158d
```
Add a new Object serialization version V4 that can store typed paths with
sparse encoding, selected per part from the first-block statistics using the
existing `ratio_of_defaults_for_sparse_serialization` threshold.

Sparse encoding applies only to typed paths (declared in the JSON type) whose
types can be inside sparse columns (scalars, and `Nullable` scalars when
`nullable_serialization_version = 'allow_sparse'`, as for ordinary `Sparse`
columns). `SHARED` typed paths are stored in the typed shared data of a part
and are never sparse. Dynamic
paths are untouched: their `Variant` encoding already omits absent rows, so an
outer sparse wrapper gains nothing. V4 stores one sorted list of sparse typed
paths in the Object structure prefix after the dynamic path list; readers use
the encoding recorded in the part, independent of the current table settings.
Nested JSON in shared data keeps V3, because shared data holds only dynamic
paths.

V1/V2/V3 are unchanged and the default remains V3. Sparse is selected when a
typed path's default ratio strictly exceeds the threshold;
`ratio_of_defaults_for_sparse_serialization = 1` disables it.

A sparse typed path is read into a `ColumnSparse` whose offsets start at the
beginning of the column, as required by the subcolumns sharing them through
the substreams cache, and only the rows read by the current call are converted
to a full column, so a scan stays linear in the number of rows.

A typed-path subcolumn tells whether its path is sparse in the part by the
presence of the sparse offsets stream, instead of reading the structure of the
whole `Object` column, so reading one typed path from many parts costs the same
as before V4. Compact parts without substream marks have no list of streams and
read the structure instead.

A sparse typed path has sparse offsets instead of the streams that
`MergeTreeReaderWide::addStreams` expects before reading the prefix (a sparse
`Nullable` path has no null map stream), so a column missing a typed-path
stream is classified again after the prefixes are read. With the columns cache
enabled the prefixes of such columns are read before classifying the columns of
a range; otherwise the `.null` subcolumn was treated as partially read or
absent and filled with defaults.

Without a column or a structure prefix, `enumerateStreams` of a V4 `Object`
also lists the possible sparse offsets of every eligible typed path, so that
`checkColumnFilenamesForCollision` sees all file names a part can contain.

Like V3, V4 is a MergeTree-only layout: it is rejected in `Native` format
(covered by `05056_json_dynamic_native_malformed_structure`).

The test `04339_json_columnar_sparse` checks which paths get sparse streams,
that a sparse part reads back identically to the source (including the
`.null` subcolumn of a `Nullable` typed path and a typed path of the nested
sub-object `j.^obj`, from the first row and from a nonzero offset, with and without the columns cache), that reads use the
encoding recorded in the part, that a mutation rewrite keeps the layout and
values, and that a merge of a sparse V4 part and a V3
part reads consistently.
```

⚠️ Major: exercise the per-part choice across writer blocks
The central V4 invariant is that the first output block fixes the encoding for the entire part, even when later blocks would select a different layout. This insert only feeds 512 rows with a uniform default distribution, and the threshold matrix contains only 0 and 1. It therefore does not distinguish retained first-block statistics from recomputing the choice on later blocks; the merge and mutation cases reuse the same small, uniform fixture.
Please add one focused case that writes multiple output blocks into one part, with the first block mostly defaults and a later block mostly non-defaults at an intermediate threshold such as 0.5. Verify the selected streams and complete readback for both Wide and Compact parts. This would protect the statistics propagation that keeps stream creation and later serialization consistent.
