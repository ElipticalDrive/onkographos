Closes #3140.
Why
The WebGL vs WebGPU study measured 10M normal-blend splats about 24% slower on WebGPU (render gate gpuMs, RTX 3070). A control run showed the gap wasn't specific to normal blending:
case
WebGL
WebGPU
10M normal
56.6 ms
69.5 ms
10M volumetric
58.0 ms
70.3 ms
10M additive
60.1 ms
61.5 ms
The density guard thins half of each 10M scene (uDensityDrop = 0.5). GLSL returns before any texel fetch for a dropped splat; the TSL vertex stage fetched and projected every splat and only then chose the reject position. With depth-sorted order those wasted fetches are scattered.
What
In materials/gsplat/shader-tsl.ts:
Vertex early-out: density thinning, then the label filter, then the near/coverage fade each nest in an If(), so a rejected splat does no fetch or covariance work. The body is split into helpers for the lint caps.
Flat varyings: the per-splat varyings are flat, as in GLSL. vClipZW stays interpolated for the glass partition.
Fragment guard: the work after the truncation test sits in the non-discard branch. WGSL discard only demotes the invocation, so that work used to run anyway.

Attribution:
The early-out gives nearly all of the 10M gain.
Flat varyings give about 4–5% on 5M volumetric and nothing measurable on 10M normal.
The fragment guard gives about 1.3–1.5% on 10M normal in two separate comparisons, within overlapping CIs. I kept it because it is small and exact.
Testing
Exact suite: ULP class, all 8 splat cases on webgl, webgpu and webgpu-gl, both pixel densities, every pose. 162 rows, 0 px different, zero drift. No GLSL changed.
New wgsl-codegen.test.ts: builds the real material through WGSLNodeBuilder and pins the structure (flat varyings, no fetch before the density test, projection inside the fade block). Each partial variant fails it.
Other checks: materials unit tests, typecheck and lint pass. lint:prune lowered two suppression counts.
WebGPU frame time on the sorted 10M cases is still above WebGL's (about 93 vs 66 ms). That is CPU/sort-side and outside this change.

Review of 16bbdb1
This brings the TSL gsplat vertex stage in line with the GLSL twin's early returns. Density thinning, then the label filter, then the near/coverage fade each nest in an If(), so a rejected splat skips the fetch and the projection. The per-splat varyings become flat, and the fragment work past the truncation test moves into the Else of the discard. The perf case in the body is convincing. The restructure itself is equivalent: I diffed the generated WGSL before and after across 24 material variants and found nothing to change in it. One varying qualifier does need changing.
Findings
major: @interpolate(flat) breaks the gsplat pipeline on WebGPU compatibility-mode devices
packages/luxar-viewer/src/rendering/materials/gsplat/shader-tsl.ts:698-706. setInterpolation('flat') with no sampling argument emits @interpolate( flat ). WGSL defaults that to flat, first, and Dawn rejects first sampling on a compat device. I checked this in Chrome by creating a pipeline with a two-stage module on requestAdapter({ featureLevel: 'compatibility' }) (device without core-features-and-limits):
flat → The interpolation sampling (First) of the vertex output at location 0 is not supported in compatibility mode (ValidateInterStageMatching)
flat, first → same error
flat, either → ok
on a core device, all three are ok
We can reach that path. renderer-setup.ts hands three a device only when it gets a core adapter and requestDevice succeeds. Otherwise it falls through to three's own init, which asks for featureLevel: 'compatibility' (WebGPUBackend.js:213). That covers compat-only hardware (D3D11, GLES) and a failed requestDevice. Before this PR gsplats rendered there. After it, every gsplat material's pipeline fails to build, so gsplat layers disappear. Points, lines and mesh are unaffected.
Fix: use .setInterpolation('flat', 'either') on all five varyings. That is exact, not an approximation: every value is per-splat, and every reject decision is per-splat, so all four quad vertices carry identical values and the choice of provoking vertex can't matter. Three uses flat, either for its own auto-flat integer varyings for the same reason (WGSLNodeBuilder.js ~2002). Update the comment above the declarations to say why it is either.
minor: the codegen test would accept the compat-breaking qualifier
packages/luxar-viewer/src/tests/unit/rendering/materials/gsplat/wgsl-codegen.test.ts:97. The filter is v.includes('@interpolate( flat )'), so it pins exactly the spelling that fails on compat devices. Once the fix above is in, it would also stop matching. Assert @interpolate( flat, either ) for the five varyings, and update the header comment's point 1.
nit: the component count is 10, not 12
shader-tsl.ts:695 ("interpolates 12 constant components") and changelog.d/3140.md:16 ("twelve constant components"). vColor 3 + vAmplitude2D 1 + vAlpha 1 + vL2D 3 + vCenterScreen 2 = 10. Fix the number in both places.
Considered and dropped
The changelog's numbers differ slightly from the PR body's (57.1 vs 57.2 ms, 50.8 vs 50.9 ms). This is rounding, it isn't in shipped code, and it isn't worth a round.
On rejected splats the varyings now keep their prologue defaults instead of computed values. That doesn't matter, because the primitive is clipped at z = -2 either way, and vClipZW is still assigned outside the blocks.
What I checked and found clean
WGSL validity: I built the real GSplatTSLMaterial through WGSLNodeBuilder for additive/normal/volumetric/max/luminous/opaque × {plain, colormap, colormap+gamma, gain/offset/gamma}, at this head and at 25be026. All 48 modules pass naga --validate, uniformity analysis included. That matters here because the fragment work now sits inside non-uniform control flow, and the shaded fragment path has no implicit-derivative texture samples. The vertex colormap LUT read lowers to an explicit textureLoad, so it is legal inside the nested If.
Equivalence: I compared the before/after WGSL by hand.
The reject set is the same: density, label and fade are now hoisted, and invalidAmp || invalidCov || footprintCulled is still evaluated at the end.
NaN handling is unchanged. A NaN fade isn't rejected early, as before. A NaN mahalSq still takes the non-discard side, because the test is still >.
Every value read past a block boundary (clipOut, mahalSq) is a .toVar() emitted before the block.
The uDensityAlphaExp If in normal mode emits correctly inside the new Else.
The glass partition guard still runs first in the fragment, on the interpolated vClipZW.
GLSL twin: it does have the matching flat qualifiers and returns (shader-glsl.ts:84-90, 131-308), so the README paragraph is accurate.
Tests and static checks: vitest run src/tests/unit/rendering/materials/gsplat passes (8 files, 165 tests). pnpm typecheck is clean, and eslint is clean on both touched files at the lowered suppression counts.
