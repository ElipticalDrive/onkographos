Six-component diffusion tensor NIfTI files previously displayed only as separate scalar frames. This adds an explicit Tensor · FSL / SimNIBS or Tensor · NIfTI symmetric matrix display with direction-coloured ellipsoids on slice planes, selectable coordinate conventions, glyph spacing and minimum FA. Scalar display remains the default, and tensor settings persist in saved scenes.
Tensor computation stays in the dataset worker. Synthetic NIfTI-1/2 fixtures and independent nibabel/NumPy references cover component order, scaling, orientation and invalid tensors. The supplied Ernie T1 and DTI_coregT1_tensor.nii.gz were tested together. This supports tensor glyphs on slices, including slice planes in the 3D pane; it does not add tractography or free-standing 3D glyph clouds. No new dependencies or lockfile changes.
Validation:
Rust NIfTI suites; four tensor tests with the Ernie data; Clippy.
Protocol/WASM/engine unit tests: 676 passed; focused app/serialization tests: 97 passed.
Ten rendering checks, including SwiftShader/ANGLE tensor tests and scalar regressions; analytic pixels and a new golden.
Real Electron tensor controls, application build, and screen/focus checks.
Workspace lint and typechecking. A separate whitespace-only commit fixes an existing formatting failure in the module-menu test.

Six-component NIfTI volumes previously displayed only independent scalar
frames, including Ernie's FSL tensor image with no declared tensor intent.

source samples or moving geometry work onto the UI thread.

Visually, opted-in tensor layers show direction-coloured, shaded ellipsoids
on slice planes, including those in the 3D pane. Spacing and minimum FA
control their density and visibility. The new SwiftShader golden records
these silhouettes; analytic pixels establish the expected radii and colours
before the golden. Returning to scalar mode restores identical pixels.
