This commit introduces a procedural Gyroid infill feature to `voxelizer-rs`.

By providing the `--infill gyroid`, `--infill-scale`, and `--shell-thickness` arguments, users can automatically hollow out solid meshes and replace their interior with a lightweight, mathematically continuous Gyroid lattice structure, while preserving a solid outer shell.

The gyroid equation `sin(x/s)*cos(y/s) + sin(y/s)*cos(z/s) + sin(z/s)*cos(x/s)` is evaluated efficiently during the multi-threaded voxelization process based on the computed SDF.

Added unit test `test_voxelize_gyroid_infill` and updated integration tests and benchmarks.

Reject unsupported infill modes
Because this is parsed as an unconstrained String and the voxel loop only applies the lattice when it exactly equals Some("gyroid"), a typo such as --infill gyriod or any unsupported mode exits successfully and writes the normal solid voxelization. That silently discards the requested infill, so this should be restricted to the supported value or rejected before voxelization.

Validate gyroid scale before division
When callers or CLI users pass --infill gyroid --infill-scale 0 (or NaN/inf), this unvalidated parameter is used as a divisor. Floating-point division yields inf/NaN rather than an error, so the gyroid expression becomes NaN and val.abs() > 0.5 never removes the interior voxels; the command succeeds with effectively solid infill. Validate the scale as finite and > 0 before the loop.
