Currently cubic interpolation is too bug-prone: callers must remember to prefilter with calculate_spline_coefficients before passing to slice_volume. The PPCA E-step was missing this prefilter (issue #90), causing a 173x magnitude error in cubic projections.
Proposal: Create a light VolumeRepr class (or similar) that tracks:
disc_type: nearest / linear_interp / cubic
half_volume: bool
prefiltered: bool (whether spline coefficients have been computed)
slice_volume would accept this class and either:
Assert that prefiltering has been done for cubic
Or automatically prefilter if needed
This prevents the class of bugs where raw volume data is passed to cubic interpolation expecting prefiltered coefficients.
Context: Discovered during contrast marginalization integration. The covariance_estimation.py correctly prefilters before cubic projection, but ppca.py did not. The 173x error was masked by the EM's centering cancellation but broke contrast estimation.
Related: #90
