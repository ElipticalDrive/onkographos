When AABBs intersect or are fully contained within another there is potential for the order of ray->AABB distances to not be the same as the order of ray->shape distances.
In this example tris[1].aabb() is contained in tris[0].aabb():
```
use bvh::{
    aabb::{Aabb, Bounded},
    bounding_hierarchy::BHShape,
    bvh::Bvh,
    ray::Ray,
};
use nalgebra::{Point3, Vector3};

struct Triangle {
    verts: [Point3<f32>; 3],
    node_index: usize,
}

impl Bounded<f32, 3> for Triangle {
    fn aabb(&self) -> bvh::aabb::Aabb<f32, 3> {
        Aabb::empty()
            .grow(&self.verts[0])
            .grow(&self.verts[1])
            .grow(&self.verts[2])
    }
}

impl BHShape<f32, 3> for Triangle {
    fn set_bh_node_index(&mut self, index: usize) {
        self.node_index = index;
    }

    fn bh_node_index(&self) -> usize {
        self.node_index
    }
}

fn main() {
    let mut tris = [
        Triangle {
            verts: [
                Point3::new(-0.5, -0.5, -1.0),
                Point3::new(1.5, -0.5, 1.0),
                Point3::new(-0.5, 1.5, 1.0),
            ],
            node_index: 0,
        },
        Triangle {
            verts: [
                Point3::new(-0.371737, -0.371737, -0.128263),
                Point3::new(0.628263, -0.371737, 0.871737),
                Point3::new(-0.371737, 0.628263, 0.871737),
            ],
            node_index: 0,
        },
    ];

    let bvh = Bvh::build(&mut tris);
    let ray = Ray::new(Point3::new(-1.0, -1.0, 1.0), Vector3::new(1.0, 1.0, -1.0));

    for tri in bvh.nearest_traverse_iterator(&ray, &tris) {
        let aabb_distance = ray.intersection_slice_for_aabb(&tri.aabb()).unwrap().0;
        let intersection = ray.intersects_triangle(&tri.verts[0], &tri.verts[1], &tri.verts[2]);
        let shape_index = tris
            .iter()
            .position(|t| t.node_index == tri.node_index)
            .unwrap();
        println!(
            "aabb distance {}, shape index: {}, shape distance: {}",
            aabb_distance, shape_index, intersection.distance
        );
        // aabb distance 0.86602545, shape index: 0, shape distance: 1.7320508
        // aabb distance 1.0881835, shape index: 1, shape distance: 1.3768586
    }
}
```

This issue is unsolvable in terms of AABB distance resolving. To solve this issue I see the next way:
Create DistanceTraverseIteratorRaw that will be return unpacked leafs AABB with contained shapes.
Create trait Intersectable for shapes that will allow to find the intersection with the ray.
Create secondary iterator for sorted AABB outputs from DistanceTraverseIteratorRaw, that will be store it to heap as the traverse continues, and fires comparing of shapes distance when any of incoming AABB will be not intercepted to any previous (This algo is sketch so should be developed more deeper).
The worst case when shapes and bvh cofigured like matryoshka doll. Time and space complexity is O(n*log(n)) and O(n).
In case when aabb is not intersects it will be constant complexity.
Visualised case in 3d: https://www.desmos.com/3d/hof0krvmul
