Slab method for ray-box intersection gives false positives for opposite direction vector
up vote
0
down vote
favorite
I have tried to implement the ray-box intersection method described by Tavian Barnes on this page in Go and simply cannot understand why it does not seem to take the direction vector into account. Here's the simple function:
```
func (me *TBox) Intersects (ray *TRay) bool {
    var tx1 = (me.Min.X - ray.Pos.X) * ray.invDir.X
    var tx2 = (me.Max.X - ray.Pos.X) * ray.invDir.X
    var tmin = math.Min(tx1, tx2)
    var tmax = math.Max(tx1, tx2)
    var ty1 = (me.Min.Y - ray.Pos.Y) * ray.invDir.Y
    var ty2 = (me.Max.Y - ray.Pos.Y) * ray.invDir.Y
    tmin = math.Max(tmin, math.Min(ty1, ty2))
    tmax = math.Min(tmax, math.Max(ty1, ty2))
    var tz1 = (me.Min.Z - ray.Pos.Z) * ray.invDir.Z
    var tz2 = (me.Max.Z - ray.Pos.Z) * ray.invDir.Z
    tmin = math.Max(tmin, math.Min(tz1, tz2))
    tmax = math.Min(tmax, math.Max(tz1, tz2))
    return tmax >= tmin
}
```
Now I have a tester function with a "box" that is set at min=[0,0,0] and max=[4,4,4]. Now I shoot various rays from various positions, but with their direction vectors always normalized.
The problem: the function returns false positives. If the ray position "sits atop the box" (with a Y set > 4) and "looks down" (Y of direction set at -1), it counts an intersection as it should. But "looking up" (Y of direction vector set at 1), the function is still giving me an intersection. Now I could add a manual extra if (branching check) to the method checking direction and tmin/tmax signs but I don't think this is the solution as I understood the method to be a generalized intersection tests working with all numbers positive and negative in a consistent way.
Now I'm wondering if this is an as-yet undiscovered bug with +Inf/-Inf in Go... looking for ideas here, as I ran out of them by now.
