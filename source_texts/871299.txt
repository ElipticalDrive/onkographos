Why
Part of #850 (invalid artifacts fail safely). On main:
Metal training passes the selected COLMAP submodel to msplat's native loader without parsing it. A missing, truncated or empty cameras.bin / images.bin / points3D.bin reaches native code unchecked.
The COLMAP BIN readers let struct.error escape on a truncated record, and they silently accept a file whose last record is cut short (images.bin / points3D.bin skip 2D points and tracks by offset arithmetic without a bounds check). struct.error is not a ValueError, so it gets past the except (OSError, RuntimeError, ValueError) fallbacks in GET /calibration-drift-report (a 500) and in georeferencing _correspondences.
The exported-PLY gate counts zero float32 quaternion norms, but a finite quaternion whose float32 norm overflows to inf (e.g. [1e30, 0, 0, 0]) passes validation. write_splat then normalises it to a zero rotation.
This ports the intent of b99b969 and the preserved WIP 9c9eed3 from codex/v3-metal-correctness, rewritten for current main: #855 replaced that branch's _staged_colmap_model with _selected_model_view, and #851 put export validation in metal_msplat.validate_exported_ply.
Change
colmap_io: _unpack turns struct.error into ValueError("truncated COLMAP binary record"). Each of the three BIN readers raises ValueError if the file doesn't end exactly on a record boundary. read_points3d_bin also rejects a point count the file can't hold before it allocates arrays for it.
metal_msplat._selected_model_view: before building the loader view, parses the selected cameras.bin, images.bin and points3D.bin with those readers and requires at least one record in each. OSError / ValueError map to Metal selected COLMAP model N requires binary X; re-run COLMAP or convert the selected model to BIN format. The reconstruction: Metal trainer loads sparse/0 instead of the selected COLMAP submodel #855 points3D.ply fallback is kept: points3D.bin is only required when it exists or when there's no points3D.ply. With no numbered model, the function still returns None, same as before.
metal_msplat._cloud_invalid_counts: computes the float32 quaternion norm once, the same way write_splat normalises. It keeps zero_norm_quaternions and adds non_finite_quaternion_norms for finite rows whose norm overflows.

The COLMAP BIN readers now raise ValueError when a record is truncated
(struct.error from _unpack, or a points3D count larger than the file can
hold) and when a file does not end on a complete record boundary.
Previously struct.error escaped the graceful-degradation handlers in the
calibration-drift route and georeferencing, and a short final record was
silently accepted.

Metal training parses the selected submodel's cameras.bin, images.bin and
points3D.bin with those readers before building the loader view and
requires at least one record in each, so a missing, truncated or empty
model fails the job with a clear message instead of reaching the native
loader. The points3D.ply fallback from #855 is kept.

The exported-PLY gate also rejects rows whose float32 quaternion norm
overflows to inf on finite components, which write_splat would normalise
to a zero rotation. The existing zero_norm_quaternions diagnostic is kept.
