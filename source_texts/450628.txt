Summary
This PR adds full 3D WebGL visualizations to the console, replacing the vector-based fallbacks with raymarched and rasterized 3D scenes. The reactor core is now rendered as a volumetric distance field, and the boot sequence displays a procedurally-generated geodesic lattice assembling itself in a receding corridor.
Key Changes
Core Reactor (3D)
New raymarched reactor (src/components/CoreVisualization/three/core.frag.ts): A 497-line fragment shader implementing the reactor as a signed distance field with:
Volumetric emitter with procedural plasma using Perlin noise
Rotating coil arrays with sector folding for efficient geometry
Containment rings, fine cell bands, and outer trim
Three orbiting nodes on tilted planes
Dynamic lighting based on system state (spin, orbit, pulse, energy, turbulence, accent)
Proper sRGB to linear color space conversion for accurate lighting
Core scene manager (src/components/CoreVisualization/three/scene.ts): Manages the WebGL context and animation loop with:
State-driven profiles for idle, listening, processing, orchestrating, and attention modes
Frame-rate independent exponential easing for smooth transitions
Pointer parallax tracking
Graceful fallback to vector core if shader compilation fails
React integration (src/components/CoreVisualization/Core3D.tsx): Mounts the 3D scene with lifecycle management and fallback handling
Boot Sequence (3D)
Wake corridor scene (src/components/Boot/three/scene.ts): A 449-line scene manager implementing:
3200 particles that scatter in a slab and converge to a geodesic lattice
Procedurally-generated corridor with rings and spokes receding into distance
Phase-driven animation tied to boot sequence stages (dark-wake, system-wake, core-assembly, system-check, interface-activation, ready, complete)
Check sweep visualization showing subsystem verification progress
Particle separation between lattice (2400) and dust (800)
Geodesic shell builder (src/components/Boot/three/geodesic.ts): Constructs a subdivided icosahedron at configurable frequency for the lattice landing zone
Boot shaders (src/components/Boot/three/shaders.ts): Rasterized geometry shaders for particles and corridor lines with:
Perspective-correct point sizing
Heat-based coloring for formation and check sweep
Distinction between lattice particles and dust
React integration (src/components/Boot/BootScene3D.tsx): Mounts the boot scene with phase and check progress tracking
WebGL Infrastructure
Context management (src/system/gl/context.ts): Safe WebGL2 acquisition with pixel ceiling and device pixel ratio constraints
Render loop (src/system/gl/loop.ts): Frame-rate independent loop with visibility and intersection observer support, pointer tracking with easing
Program compilation (src/system/gl/program.ts): Shader compilation with detailed error reporting including line numbers
Matrix math (src/system/gl/mat4.ts): Column-major 4×4 matrices for perspective and view transforms
Integration
CoreVisualization (src/components/CoreVisualization/CoreVisualization.tsx): Now attempts 3D core first, falls back to vector core if unavailable
BootSequence (src/components/Boot/BootSequence.tsx): Integrates 3D boot scene with phase and check progress
Styling (src/components/Boot/boot.css, src/components/CoreVisualization/core.css): Added dimensional scene styling with proper layering and contrast management
Notable Implementation Details
No time-based animation: Both scenes drive motion through accumulated angles (uSpin, uOrbit) integrated by the CPU, allowing state changes to alter tempo without snapping geometry
Deterministic particles: Boot sequence uses seeded random generation

The server suite reported 533 passing, 15 failing and 8 skipped. Most of
that was the suite testing itself rather than the backend:

- The API tests read JARVIS_TOKEN from the environment. It is optional and
  the backend generates one per run when it is unset, so on any machine
  that had never set it every authorised path was skipped and the one
  assertion that did not skip failed. They now read the token the process
  actually validates against.
- Host actions are off by default, which is right for a machine and wrong
  for the suite: the properties worth proving — a consequential action
  stops for a human, the phone that asked cannot approve it, a denial
  leaves it unrun — are unreachable while the feature is off. It is on
  under the test runner, where the runtimes are fakes.
- Two tests asserted the shape of the machine they were written on: a
  Windows path is not out of bounds on Linux, and this project is a
  checkout, so a checkpoint records a real git head.

Underneath them was a real defect. `execute()` bounded a run with a
timeout it could not enforce on POSIX: the shell was not detached, so it
had no process group of its own, `kill(-pid)` named nothing, and the
fallback killed the shell while its children held the pipes open. A
command that would not finish ran until it finished. The shell is now the
leader of its own group and the timeout takes the tree.

Also: a live ElevenLabs key and a stray Devin key were sitting in
server/.env.example. Redacted. The ElevenLabs key is in this repository's
history and should be rotated.

556 tests, all passing, none skipped.

The core was a flat stack of SVG rings. It reads as a diagram of a reactor
rather than as one, because everything it is trying to show — a housing
with thickness, a coil array that occludes itself as it turns, light
inside the emitter that the housing is lit by — is volume, and SVG has
none.

It is now a raymarched distance field on WebGL2. An SDF was the right
choice over a mesh: the distance the field already knows is what the glow,
the contact shading and the volumetric plasma are all built from, so there
is no lighting rig and no bloom pass to approximate them with.

What the scene actually does:

- A standing twelve-degree tilt, so the ring is never seen square on. Head
  on, a ring of revolution projects to a circle and the depth is thrown
  away.
- Light is linear. The palette is squared on the way in and the frame is
  converted back on the way out; without that, everything is brightened
  twice and a saturated cyan reactor comes out pale grey.
- Housing lit by the core it contains — the inner face of each slot is lit
  and the outer face is not, which is what gives the band its mass.
- Emission accumulates along the ray only near what emits, so the glow has
  the shape of the hardware rather than being a radial gradient.
- Sixteen bounded samples of 3D noise inside the emitter shell, so the
  light in the middle has structure.

Every bearing is integrated from a rate rather than multiplied by the
clock, so a change of system state alters the tempo without the rings
snapping to a new angle — the same principle the CSS core follows through
playback rate.

The vector core has not been thrown away. It is the fallback, whole, for a
machine with no WebGL2 or a driver that will not compile the shader, and
the console looks finished either way. The legend ring and hub markings
stay in SVG over the top of both: engraving has to stay upright and crisp,
which is what SVG is for and what a perspective projection is not.

Reduced motion gets the reactor without the animation — one still frame,
redrawn only when the state changes.

The boot screen was the console's own vector core assembling itself in
front of a flat grid. It made the wake sequence look like a rehearsal for
the screen it hands over to, rather than an arrival at it.

It is now a place rather than a picture, and it is drawn a different way
from the reactor on purpose: ordinary rasterised geometry — three thousand
point sprites and a couple of thousand line segments through a perspective
matrix — where the core is a single raymarched volume. They share the
context, the loop and the shader plumbing, and nothing else.

The sequence:

- A corridor of dashed rings receding into the dark, wrapped in the vertex
  shader so it is endless for the cost of what is on screen. The camera
  sits off its axis: dead centre, a tunnel of rings projects to concentric
  circles and reads as a flat target rather than as somewhere with a far
  end.
- A cloud of motes, each starting on its own beat. Moving them together
  looks like one object being scaled; staggered, it reads as a few thousand
  separate things arriving.
- They land on a geodesic shell — a subdivided icosahedron, so every vertex
  has five or six neighbours and the spacing does not collapse at the
  poles. Its edges fade in only once the particles have somewhere to be;
  drawn earlier they give the shape away before it is assembled.
- During the check, a band of light sweeps the shell as subsystems report.
  It follows how many have actually answered, not a timer.
- On handover the shell opens out and the console comes through it.

Additive blending throughout: three thousand sprites have no useful depth
order, and sorting them every frame would cost more than the whole scene.

The skip button is gone, along with the Escape/Enter/Space shortcut behind
it. The sequence is nine seconds, it is bounded by a hard ceiling whatever
the backend does, and the check running behind it is the real one — the
single thing it exists to say is that a subsystem did not come up. A
control that dismisses it is a control for dismissing that. The ceiling is
now the only way out, which is what it was always for.

Reduced motion gets each phase as one still frame, redrawn when the boot
moves on rather than sixty times a second. No WebGL2 keeps the vector
assembly, whole.

Also fixes a pre-existing one: boot.css positioned the grain SVG with
`inset: 0` but never sized it, leaving it at the replaced-element default
of 300×150. Invisible against a black screen; a pale rectangle in the
corner the moment there was a scene behind it.
