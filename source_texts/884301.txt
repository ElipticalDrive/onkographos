Two things a scan of a real place makes obvious were missing. There was no lighting at all — a point's colour was its palette entry times the scan's own RGB times a distance fade, and nothing in the pipeline knew where a light was. And the camera could orbit a point but not travel through a space, because the only positional control was a pan, which is defined as the move that keeps the subject centred.
Light
Lamps light a volume, the sun lights surfaces. Two movable lamps with position, reach, level and colour, falling off as r²/(d²+r²) — the same curve a gravity well uses, so a lamp and a well set to the same reach reach the same distance. Those work on anything with a position, which is everything. The sun needs to know which way a point faces, and /light/shape is the dial between the two readings. /light/torch puts lamp 1 on the camera, which is what makes moving through a scan read as moving rather than as the scan fading up.
Off means unchanged. Ambient defaults to 1 and every level to 0, so the lighting term is exactly vec3(1.0) and the picture is bit-for-bit what this renderer drew before. Every preset ever saved and the whole shipped set depend on that being exactly true, so it is a named constant (Uniforms::UNLIT) that the parameter defaults are tested against and a GPU test renders.
Lamps are white until you colour them. Hue and tint, because hue alone has no value meaning "no colour" — hue 0 is red, so a lamp described by hue alone turns the scan red the moment you raise it to see what it does.
Normals — read, estimated, or absent, never invented
nx/ny/nz come out of a PLY that has them; a neighbourhood plane fit works them out when it does not, which is most files. A cloud with no surface reports the zero vector and every directional term stands down, because a made-up normal lights a wall the wrong way round.
Shading is two-sided: a plane fit cannot tell n from -n, and resolving that across a whole cloud still comes out backwards for a room, where the surfaces you want lit face inwards.
Estimation was going to be threaded. Then it was measured — a tenth of a second for a full slot in a debug build, beside a file read that costs more — so it is not.
Camera moves
Ten canned paths — orbit, sway, push, pull, crane, spiral, look around, fly through, walkthrough, drift — added to the camera the faders already describe, never written back, so switching one off returns you exactly to your framing. Rate in bars. Phase starts when you engage it rather than from absolute bar count: bar-locked is tidier and whips, because engaging an orbit mid-cycle asks for half a turn immediately.
/camera/at_* aims at a point in the world, which is the piece that made a walkthrough possible at all.
Three defects found by rendering rather than by testing
The walkthrough rendered a black frame. The paths were written in units suiting a scanned room; every cloud is normalised to about a unit across, so the camera walked three widths from a one-width object. Now guarded by a test that walks every move through its cycle and fails if the aim leaves a bounded box — and by a named WORLD constant, so the paths are multiples of the thing you are looking at rather than numbers that happened to work.
The walk travelled along the heading it had already turned into, so the square was not a square and the loop teleported once a cycle. Walking and looking are two headings; that is the whole of turning a corner.
The square started at the origin instead of being centred on it, so the walk toured the empty space beside the subject.
The bug that made the sun do nothing
The shader looked a normal up by shape mode where the mapping wanted a cloud slot. Mode 7 means "the cloud pair"; read as a slot it asks for slot 7, which is empty. Every normal came back zero, nothing errored, and the whole of surface shading was silently absent.
No unit test can see it — the mapping only exists inside the shader — so it is pinned by a GPU test that renders a sheet with the sun in front and behind. Probed against the old code it reports the symptom exactly: facing it 5.57, backing it 5.57.
Two things fixed on the way
load_slot used the first 65,536 points of a cloud, not a sample of it. points[i % len] is just points[i] for anything bigger than a slot, and scanners write in scan order — so a five-million-point room showed one corner and the rest had never been on screen. Now strided. This changes what an existing look built on a large scan renders: the whole thing rather than a slice. Deliberate.
WGSL is now validated in cargo test, through naga, the same compiler wgpu hands it to. A shader typo was previously not a build failure, not a test failure, and not a failure on the machine that wrote it — it was a black screen on somebody else's laptop.
The doc-table expander also stopped assuming every /N/ family numbers 0–3. That was true while gravity was the only one and silently wrong the day the lamps arrived numbering from 1; it now reads the range the table states.
Verification
Workspace tests and clippy -D warnings green. Both new GPU tests probed against the old code and confirmed to fail on it. Lamp falloff, the world-space aim, the walkthrough and the sun on a room scan with estimated normals all checked by rendering real frames.
Docs: README sections for light and for moves, docs-site sections, the OSC table, and docs/light-and-camera.md.
