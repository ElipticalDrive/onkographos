Ray-primitive intersection and brute-force queries per INTERFACES §5 and §6:
src/trace/intersect.hpp: intersect_sphere (stable quadratic with PBRT v4's accurate
discriminant, so distant spheres don't cancel to "tangent") and intersect_triangle (watertight,
PBRT v4 6.5.3, including the double edge-function fallback). Both report hits in
(tmin, t_hi].
src/trace/brute.hpp: brute_closest, brute_any, BruteQuery, and detail::accept (the
frozen acceptance rule, reusable by BVH traversal so the two match exactly).
docs/CONTRACT_NOTES.md: note W4, .cu sources for CUDA-only test targets in tests/.
Deliberate departures from PBRT's triangle test, worth a close look (details in the commit message):
explicit fmaf in the shear and scaled distance; an exact interval test on the returned t
instead of PBRT's scaled range test (which can reject by one ulp a distance it just returned,
breaking the t_hi tie rule); no conservative deltaT rejection (our contract uses the open
interval, and offset_ray_origin handles self-intersection).
Unblocks Po's brute-force CPU image (render_pixel<BruteQuery, NormalShading>) and the GPU smoke
image once NormalShading lands.
Closes #19

trace: add sphere and watertight triangle intersection
…
41f4307
```
Add src/trace/intersect.hpp with intersect_sphere and
intersect_triangle per INTERFACES section 5. Both report a hit iff a
root lies in (tmin, t_hi], so callers can pass t_hi = best.t and let
equal distances reach the tie rule.

The sphere test uses the contract's stable root formula with PBRT v4's
accurate discriminant, 4a(r - |f|)(r + |f|), because b*b - 4ac cancels
to zero for distant spheres (a unit sphere 1e4 away looks tangent).

The triangle test follows PBRT v4 6.5.3 (Woop et al. 2013), including
the double recomputation when an edge function is exactly 0, with
three deliberate changes for reviewers:
- The shear and scaled distance use explicit fmaf, so a shared vertex
  transforms to identical bits on every compiler, CPU and GPU.
- The interval is tested exactly on the returned t instead of PBRT's
  scaled range test, which can reject by one ulp a distance this same
  function just returned and so break the t_hi tie rule.
- PBRT's conservative deltaT rejection is dropped. Our contract defines
  hits by the open interval alone, and offset_ray_origin handles
  self-intersection.

Signed-off-by: Mikail Sadic <mikail.sadic@utexas.edu>
```

```
Add test_trace_device, built only with RT_ENABLE_CUDA. One kernel runs
intersect_sphere, intersect_triangle, brute_closest, brute_any, and
BruteQuery on fixed rays and compares every result with the host. Hit
flags and prims must match exactly; t and barycentrics get small
absolute tolerances for FMA contraction differences.

A second kernel generates camera rays with camera_ray and traces them
with brute_closest in the same kernel, covering the camera-plus-trace
half of the GPU smoke path. A host-only test guards that the sampled
pixels stay clear of silhouettes and edges, so the tolerances cannot
change which primitive is hit.
```
