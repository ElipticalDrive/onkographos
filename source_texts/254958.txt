Streaming and depth sorting were blocking camera navigation. In a live capture, building picking bounds accounted for about 96% of page admission CPU time. Later profiling isolated repeated synchronous GPU readback transfers; resource review also found generated shader materials retained as bays left the scene.
Paged decode RPCs return required LoD data and compact bounds built in decode workers. Admission installs bounds with matching geometry and clears stale blocks when shorter pages replace them. Label and instance textures allocate storage first and upload populated layers.
A dedicated readback resource snapshots every depth layer into one reusable pixel buffer before yielding, waits asynchronously for one fence, and transfers the complete snapshot once. Sorts remain coalesced; immutable mapping metadata and disposal checks prevent stale ordering publication. Cancellation releases pending GPU resources, including on context loss. A single transfer avoids repeatedly paying the driver's synchronous round-trip cost; it does not make that final transfer asynchronous.
Each SparkRenderer owns a generated-program registry shared by its accumulator ring. Programs retain separate generator uniforms and output-format identities. Existing scene traversal retains invisible and layer-excluded residents, while replaced or removed generators release their materials. Target resizing preserves programs, renderer disposal releases them, and fullscreen draws restore their material binding.
Validation:
21 focused Rust raycast tests pass, covering both encodings, transformed picking, partial pages and replacement isolation.
Four JavaScript picking integration tests pass.
Seven depth-readback tests cover coherent layered snapshots, one complete transfer, binding restoration, reuse, cancellation, context restoration, concurrency and failure cleanup.
Six generated-program ownership tests cover sharing, graph replacement, output-format isolation, target growth, resident visibility and failed-draw cleanup.
WASM and production/development bundles rebuilt; distribution files, types and source maps included. Standalone TypeScript still reports 22 existing Three.js nullable-texture diagnostics, with none introduced here.
CPU-only page admission benchmark: 1.04 ms median / 1.64 ms maximum for 1.25M synthetic splats, versus approximately 4.1 ms per page previously. Active browser captures show worker-built bounds replacing main-thread geometry decoding.
In Chrome, a 5 MB complete depth transfer took about as long as each 1 MB partial transfer. The final active-pan capture still contains occasional synchronous driver stalls (about 81 ms maximum readback); no bounded-latency claim is made. Combined frontend measurements and further context are recorded in cropvision-workspace#308.
Stacked on #2. Browser rendering and panning are validated through the pinned frontend staging build; this change preserves point count and scene quality.
