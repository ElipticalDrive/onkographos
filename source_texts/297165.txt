Summary
Replaces the single VolumeVisual with six concrete visual types, one per rendering algorithm. Each only exposes the parameters that apply to its mode rather than having a fat enum visual with mode-specific fields most users have to ignore.
DirectVolume — front-to-back composite (Beer-Lambert). Exposes density_scale, early_exit_alpha, debug modes.
AdditiveVolume — additive accumulation, no occlusion. Just density_scale.
MipVolume — Maximum Intensity Projection with optional attenuation (0 = plain MIP).
MinipVolume — Minimum Intensity Projection.
AverageVolume — mean intensity.
IsosurfaceVolume — first-hit isosurface with Phong shading; LOD-aware trilinear bisection + gradient stencil so the surface isn't voxel-aligned even with a Nearest-filtered VT atlas.
Internally, VolumeCore owns the shared state (atlas binding, geometry, colormap, uniforms) and each concrete type owns one RenderPipeline for its mode. Bindings use local declarative macros (py_volume_class! / js_volume_class!) to keep per-type boilerplate tight.
Bug fixes layered on top of the refactor
Edge tiles now zero-pad into their atlas slot before upload, fixing the "chunks in (very) wrong places" artefact where a slot's previous tenant's data leaked into the new tile's padding region.
write_tile_to_atlas clamps source extents to the atlas slot, so oversized chunks are cropped instead of overflowing.
lru_map now tracks only resident tiles — previously every visible-but-not-yet-loaded tile got an entry that was never removed, leaking under long exploration sessions.
Iso surface no longer ties its colour to colormap[iso_threshold] (which made it mysteriously dark at low thresholds); uses a fixed near-white base.
MIP attenuation switched to pure distance-based with below-floor sample skipping. Earlier density-weighted formulation let sparse data bleed through at high attenuation values.
VRAM dropdown trimmed to actually-allocable sizes.
Test plan
uv run python examples/volume_renderer/python/volume_ome_zarr.py and cycle the Mode dropdown across each algorithm on beechnut / marmoset_neurons.
WASM example builds and runs (./build_wasm.sh; serve examples/ and open volume_renderer/).
No regression in slice_viewer Python or WASM examples.
Iso surface visible at default threshold and a wide range of iso_threshold slider values.
MIP attenuation suppresses far structures as the slider increases (cap at 20 on slider ≈ exp(-20)).

```
Several follow-up fixes after the per-mode volume refactor.

- Edge tiles (chunks smaller than the atlas slot) now zero-pad to slot
  size before upload, so a slot's previous tenant can no longer leak its
  data into the new tile's padding region. This was the root cause of
  the "chunks in (very) wrong places" artefact on marmoset / pawpawsaurus.
- write_tile_to_atlas clamps source extents to the atlas slot, so an
  oversized chunk (e.g. a coarse LOD shipped as a single mega-chunk) is
  cropped instead of overflowing into adjacent slots or panicking.
- lru_map now tracks only resident (slot_map) tiles. Previously every
  visible-but-not-yet-loaded tile got an lru_map entry that was never
  removed, leaking under long exploration sessions.
- Removed an `eprintln!` debug line that was running on every chunk load.
- Isosurface no longer ties its surface colour to the colormap at the
  threshold position — that coupled brightness to threshold position
  and made the surface mysteriously dark for low-threshold values.
  fs_iso now uses a fixed near-white base; per-iso colour can be exposed
  via a setter later.
- VRAM dropdown trimmed to options that actually correspond to allocable
  atlas sizes (256 MB – 2 GB). The combined "atlas + Dawn dynamic upload
  staging" must stay under Chrome's 4 GiB per-resource cap.
```

MIP attenuation: pure distance, skip below-floor samples
…
353c2a7
```
Replaces the previous vispy-style density-weighted accumulation with simple
distance attenuation (scale = exp(-attenuation * t_norm)) so the slider has
predictable, monotonic behaviour regardless of how sparse the data is.

The earlier density-weighted approach was elegant in theory but failed on
sparse data: rays passing through mostly empty space barely accumulated
sumval, so far-side bright points stayed visible even at very high
attenuation values. With distance attenuation, exp(-attenuation) at the
ray's far end is the same regardless of what's in between, matching the
"fog" intuition the user expects.

To avoid the "dark floor" failure mode (an empty ray's brightest near
sample is raw≈0, which the colormap maps to the floor colour), we now
skip below-floor samples (`adjusted > 0.001`) inside the attenuation
loop — they never compete for maxval, and pure-empty rays discard. The
contrast-ceiling early termination is retained.

Slider trimmed to 0-20 (200 / 10) since exp(-10) ≈ 5e-5 is already
visually "fully suppressed", and 0-100 was mostly dead range.
```
