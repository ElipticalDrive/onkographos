Issue body actions
With each visible surface voxel, we should know the exact cut "position" ID that "uncovered" that voxel. That metadata should be used in the renderer to color the voxel side appropriately. At display time, we could color the voxel surface for example by material removal speed, by tool used, by time of uncover, or by "operation" i.e. larger contiguous partitions of all cut positions (usually be a subpartition of all cut positions partitioned by tools used)

The first implementation is in PR #19.
Attribution is per voxel face: a surviving face gets the ID of the operation that removed its adjacent voxel. Different sides of the same voxel can therefore have different IDs. This avoids incorrectly using the last operation that touched the surviving voxel.
Implemented:
Optional "export_provenance": true job output.
Final-surface operation/tool coloring in the macOS viewer.
Picking reports the exact operation string ID and tool index.
Initial/prehistory surfaces remain neutral; section interiors are not assigned a cutting ID.
An independent cell-by-cell replay oracle agrees on all 5,393 exposure-neighbor records in the small general fixture. The actual 25 µm pocket produces 630,564 records (10.09 MB); extraction/export took 0.109 s in one M5 Max run. Its render was inspected, and picking identifies e.g. Layer 2 / 197.
Keeping this open: this increment indexes the final surface only. Arbitrary playback-frame attribution, larger operation groupings, rate/time heatmaps and Windows coloring remain unfinished. Earlier frames deliberately do not reuse final labels. IDs currently identify continuous cutting segments, not isolated stamped poses; physical time/rates require supplied feed/time data. Colors are categorical, not quantitative or guaranteed unique—picking provides the exact identity.

Merged #25 extends final-surface exposure coloring to the Windows D3D12 viewer. Enable export_provenance in the job, then use --color-operation, --color-tool, or press C to cycle modes. It uses the removed face-neighbor's operation/tool, with full 36-bit cell keys for 4096³ grids. Initial/prehistory faces and section interiors remain neutral; earlier playback frames explicitly disable final labels.
Actual MSVC batch/project builds and WARP rendering passed Windows CI. The portable reader passes real replay plus ten malformed metadata/buffer cases; the independent exposure oracle still agrees on 5,393 records. I downloaded and inspected the Windows render. Evidence is being preserved in #27.
Keeping this open for attribution throughout playback, operation groupings and physical time/rate maps. Windows picking is also not implemented. Current colors are categorical identities, not quantitative removal-rate claims.
