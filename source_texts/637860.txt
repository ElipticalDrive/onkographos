Functional 3D deliverable — portable glTF 2.0 point-cloud GLB from verified Gaussian splats
Base PR #240 (feature/v2l18-3-gsplat-rgb-centers-preview, fd472164d5065a40bc488b6de296c1593fcbcdc2), not main. The base already validates and exports actual gsplat Gaussian PLY XYZ + SH0 color as a standard binary RGB PLY. This distinct capability creates a self-contained .glb that generic glTF 2.0 viewers can display without CUDA, Torch or a gsplat native rasterizer.
New export_verified_gsplat_rgb_centers_glb reuses the existing verified PLY SH0→RGB converter (no duplicate Gaussian parsing/color mathematics), checks the temporary preview's exact SHA-256, streams XYZ and normalized uint8 RGB as interleaved 16-byte glTF POINTS attributes, derives real XYZ extrema, writes standard glTF 2.0 JSON/BIN GLB chunks with bounded 32-bit length, computes output hash and cleans temporary files. The Gaussian model remains unchanged, the GLB is a separate derived visualization artifact. CPU tests parse actual output binary header, JSON and vertex bytes; also reject malformed Gaussian source. Public export in reconstruction __init__.py.
Scope: three V2L18.3 allowlisted paths (src/wre/reconstruction/static_appearance_baseline.py, focused src/wre/reconstruction/__init__.py, tests/test_static_appearance_baseline.py). No new dependency, workflow, model, solver, cloud API, router or runtime. The output is a COLORED POINT CLOUD of Gaussian centers; it is NOT true splat rendering, opacity/occlusion/SH view dependence, physically correct lighting, photorealism, a trained model proof, or 4D. The real-stereo photo GLB in separate PR #251 is another input route, not a Gaussian artifact.
Gates: verify exact HEAD fast-ci Pyright, Ruff and focused CPU artifacts, applicable native builds; one independent READ-ONLY L2 on the stable published functional SHA, after CI and SHA confirmation. Stacked ancestors #240/#234 and vulnerability scan Dependency Graph HTTP404 in #226 remain merge blockers. No GPU training claim.
