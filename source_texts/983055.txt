CesiumJS checks the tileset-level 3DTILES_content_gltf extension to
decide whether GLBs should be routed through the Gaussian Splatting
pipeline or the standard Model pipeline. Without this declaration,
SPZ-compressed GLBs fail with "t.value.slice is not a function"
because the Model pipeline cannot handle SPZ virtual accessors.

Fix SPZ coordinate conversion mismatch with CesiumJS decoder
…
32e3435
```
Remove from_coord=spz.RUB from _compress_to_spz_bytes() and
to_coord=spz.RUB from _decompress_from_spz_bytes().  CesiumJS's
@spz-loader/core WASM decoder outputs raw positions without any
coordinate conversion, so storing positions in a transformed
coordinate space causes tiles to render at wrong locations (invisible).

Also use canonical colon-prefixed attribute names (e.g.
KHR_gaussian_splatting:SCALE) instead of underscore-prefixed (_SCALE),
and clean up the SPZ extension block to only contain kernel, projection,
and the SPZ sub-extension reference.

Signed-off-by: Masaya Kataoka <ms.kataoka@gmail.com>
Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
Signed-off-by: Masaya Kataoka <ms.kataoka@gmail.com>
```
