Summary
Meshes now draw in the render system's single draw order with sprites and text, and terrain uses the same path. A mesh can sort between two sprites, which a ship's trail (#785) needs. This is the approach Unity, Godot and Bevy share: every 2D renderer sorts in one order, and a mesh breaks the batch where it lands.
The design is design/meshes-in-the-draw-order.md, committed in this PR.
Meshes
MeshEcsComponent / addMeshComponent(world, entity, { geometry, material, layer, category }) puts a Geometry and a MeshMaterial on an entity.
The render system adds one fixed query, [meshId, positionId].
It knows nothing about what produced the mesh.
addMeshComponent throws for a geometry without an a_position attribute of size 2 or 3 (Geometry.getAttributeSize).
RenderCommand is now QuadRenderCommand | MeshRenderCommand.
Meshes are sorted with sprites and text by layer, world order, root Y (for ySort cameras) and hierarchy order.
Within one entity, a mesh draws before its sprite, and the sprite before its text (sub-key hierarchyIndex * 3 + kind).
When the draw loop reaches a mesh, it ends the current instanced batch, draws the mesh with one draw call, and starts a new batch.
Meshes follow the same rules as sprites:
the camera's cullingMask against the mesh's category
VisibilityEcsComponent
view-bounds culling, from the new Geometry.bounds, recomputed after update changes a_position or vertexCount
masks
the straight-alpha blendFuncSeparate state
no drawing while the context is lost
MeshMaterial / createMeshMaterial(renderContext, vert, frag) mirrors SpriteMaterial.
The vertex shader must include the new meshVertex include (meshWorldPosition, meshClipPosition, forwardMeshMask).
The fragment shader must include mask.
u_model, u_viewProjection and the mask uniforms are set only by the render system.
Mesh shaders get a Y-up view-projection, so they never see the sprite path's internal Y-down space. The mask data writer is shared, with a Y sign.
The spriteMask include is renamed mask, and spriteMaskCoverage() is now maskCoverage(), since sprites, glyphs and meshes all use it. The export spriteMaskShaderInclude becomes maskShaderInclude. spriteMaskVertex, forwardSpriteMask and spriteMaskVertexShaderInclude keep their names.
Terrain on the mesh path
createTerrainMesh builds the mesh in the entity's local space, with no position, angle or Y negation, and returns { geometry, material: MeshMaterial } for addMeshComponent.
terrain.vert and terrain.frag follow the mesh shader contract.
Deleted: createTerrainRenderEcsSystem, TerrainMeshEcsComponent, addTerrainMeshComponent, terrainMeshId and the TerrainMesh type. The engine no longer writes renderContext.clearStrategy.
Terrain now:
sorts with sprites
follows its entity
blends like a sprite (opaque textures look the same)
can be masked
defaults to category 1
Tests, docs and demos
Unit tests cover:
mesh and sprite interleaving, and a mesh splitting a same-texture batch
layer, ySort, and an entity's own mesh, sprite and text order
category, visibility, view culling (with rotation and scale) and masks
the model matrix, the Y-up view-projection, blending and context loss
MeshMaterial, addMeshComponent, Geometry.bounds and the local-space terrain mesh
A new e2e spec, mesh-draw-order, draws a mesh between two same-texture sprites. It measures pixel extents relative to a frame with the mesh hidden: the mesh covers A, B covers the mesh, and with order 3 the mesh covers B.
