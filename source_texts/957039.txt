Issue body actions
The normal build supports native-resolution DLAA only. Quality, Balanced and Performance are deliberately rejected because the experimental reduced-resolution path is not visually correct.
Earlier experiments produced a 1600×900 color surface paired with a 1066×600 depth surface, white output, and camera/input-coordinate problems. A later clean native 5120×1440 borderless restart resolved the observed startup clipping; that does not validate reduced-resolution rendering.
Baseline: Last Epoch 1.5.3 / Unity 6000.4.8f1 IL2CPP, D3D11 built-in pipeline with PPv2, RTX 5080. The tested native build is managed E841 / native 257A / backend 571C. See current limits and candidate provenance.
Acceptance checks:
Make camera color, depth, motion vectors and PPv2 temporary targets consistent at the intended internal resolution.
Reconstruct to native 5120×1440 while preserving aspect ratio, projection, full-width HUD, mouse targeting and UI hit testing.
Validate Quality first, then Balanced/Performance, including scene changes and history resets.
Verify actual lower-resolution input and correct displayed output, not only successful NGX evaluation.
Verify late HUDless capture, FG and NR with the scaled path; compare raw images and inspect motion/UI.
Pass complete paired Unity/backend log checks and clean fallback to native/original rendering before lifting the normal-build guard.
Keep experimental adapters isolated from the user's current playing installation. This issue establishes rendering correctness; the 240 FPS performance target is tracked separately.
7 November 2026 runtime session — update added 8 November
No reduced-resolution rendering was tested or fixed in the 7 November session; all runs used native-resolution DLAA. This issue remains the first implementation priority. The next isolated candidate targets 90% linear render scale (4608×1296 input reconstructed to 5120×1440 output), with consistent color/depth/motion resources and native HUD/input coordinates. It must pass visual and paired-log validation before being enabled in the normal build.
Evidence: bounded runtime report at commit 91265a2. This update records partial evidence; it does not close this issue or certify a release.
8 November 2026 — implementation ready for runtime validation
Implemented an isolated experimental SR candidate in 9732f9c, with configurable percentage in d20cec0.
[Upscaling] RenderScalePercent=90 in the existing managed config; accepts 50–100, requires restart. At the target display, 90 means 4608×1296 scene input; 100 selects native DLAA. The first validation target remains 90%.
Keeps the camera/shared PPv2 context and depth at scene resolution. Uses separate full-resolution targets/context for builtin postprocessing instead of resizing the shared TAA temporary mid-stack. Guards unsupported custom effects and final presentation; permits at most three startup spatial-fallback frames.
Both experimental and normal managed variants compile with zero warnings/errors. Native WARP checks passed, including 90% resource extents, mismatch rejection and context restoration. Software tests do not execute NVIDIA SR or Unity presentation.
Final experimental managed SHA256: 1F9830C7A5EF561532A4B45966FB87D40693D2D26064385D5DF1E06FBF04153E. Requires the experimental build and process opt-in LE_EXPERIMENTAL_SR90=1, with ProbeOnly=false. Stable installed E841/257A/571C and settings remain unchanged; no game was launched.
Next: validate 90% output orientation/color, matching guides, full-width HUD and mouse targeting with NR/FG off; then NR/FG on and scene transitions. Only after correct output, compare 100% versus 90% performance on normal Reflex. All runtime acceptance checks remain open.
8 November 2026 offline runtime test
Tested Last Epoch 1.5.3 offline at 5120×1440, D3D11, with FG and NR disabled. The d20cec0 candidate (managed SHA prefix 1F9830C7) allocated 4608×1296 and then stopped before evaluation because the active custom AfterStack effect was LE.Effects.OutlinePostEffect.
A local diagnostic build (8F07A077) omitted only that effect when it was the sole active AfterStack effect. DLSS then reported successful evaluations with matching 4608×1296 color/depth/motion and 5120×1440 output. The Old Road and character selection had a white 3D scene with the HUD/UI visible. A second diagnostic build (B1DFFF35) used a plain final blit and pixel readbacks. It sampled nonuniform RGB in both the reconstructed frame and the bound display buffer at the copy point, but character selection still appeared white with either dedicated or main camera ownership. Across the four Unity logs there were zero tracked color/depth mismatch, RenderTexture.Create, or DXGI device loss messages.
Next check the buffer actually presented after later camera/UI work and preserve the outline effect in the supported path. World targeting and visual correctness remain open. Restored and hash-verified the original managed DLL and three configuration files with the game stopped.
White-screen lead from another Unity D3D11 DLSS mod
WotR Upscaler hands reconstructed color back through the game's own post-process target, prepares output-sized color and depth targets, and updates screen-size shader constants for the normal final blit, outlines, and UI. Its pipeline differs from Last Epoch's PPv2 path, so use the handoff as a reference.
Our readbacks found nonuniform RGB in the reconstructed texture and the bound display buffer at the copy point, while the visible scene was white behind the HUD. A later pass may overwrite the copy, or the copied buffer may differ from the swap-chain buffer that reaches Present.
Trace a distinctive color marker and texture identity within one frame at the display copy, after UI camera rendering, and at the actual swap-chain buffer immediately before DXGI Present.
Run a bilinear upscale through the same presentation path to check whether the white screen reproduces without DLSS.
If the trace points back to the upscaler output, check exposure inputs. OptiScaler documents white screens from exposure texture incompatibilities, particularly with XeSS.
Runtime follow-up deferred.
Additional references for the PPv2 handoff
The Valheim mod author describes replacing the game's existing bilinear render-scale pass with NGX upscaling. That gives the reconstructed image an existing route back into the game's pipeline. The core rendering hook was not verified from public source. Valheim Universal Upscaler
A Unity PPv2 fork adjusts the viewport for reduced-resolution rendering, dispatches DLSS in the post-process command buffer, and blits the output to context.destination. Inspect how that destination is allocated and consumed when adapting the pattern to Last Epoch. PPv2 DLSS source

Verify the destination's actual extent, then follow a same-frame marker through the UI camera and into the swap-chain buffer just before DXGI Present. Record whether the scene and HUD remain visible. Compare with the bilinear control through the existing experimental display-copy path to isolate the handoff.
