bulk_sources.resample: separable matrix-product passes (e3101fd)
The output points form a tensor-product grid, so trilinear interpolation factors into three 1-D linear passes (η, y, x). Each pass is one matrix product over all features of a source frame.
This replaces ~1,700 single-threaded scipy.ndimage.map_coordinates calls per pair event.
It uses the same arithmetic as before: float64, rounded to float32 per frame, then linear in τ in float32. Only the order of summation differs.
The writers no longer need scipy; the README says so.
tests/test_h5_bulk.py gets a new test that keeps the old scipy version as a reference and requires agreement to 2 ulp.
Docs (prod_AuAu_0_10_jet/BENCHMARK_GB10.md and README.md)
The re-profile after these changes, with before/after per stage.
Per-event times, and what sets an event's runtime: its lifetime (number of hydro steps), not the number of strings.
The next candidate, the CPU source fill in MUSIC4GPU. It's ~15 s per event and runs at every sub-step, although the strings are deposited only at τ = 0.40–0.42 fm/c.
README "Potential next steps": what switching off MUSIC's momentum-anisotropy output would entail (on hold).
Validation
