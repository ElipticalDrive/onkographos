Summary
Fewer barriers in two Vulkan kernels, keeping their stable ordering.
```
 radix scatter, per 128-key row
-  clear every mask word, atomicOr, popcount fold over 256 digits, 16-barrier digit scan
+  keys and values in registers up front; the last key of each digit carries the running count
+  3 barriers per row, chunked digit scan with 2
 LOD selection (classify, allocate, both group scans)
-  128-lane Hillis-Steele scan: 14 barriers, every one of 22 rounds
+  16 serial chunks of 8 plus a chunk prefix: 2 barriers
```
Vulkan 1.1 does not guarantee full compute subgroups or their order, so neither scan uses subgroup ops; ballot also loses keys on Adreno 640.
Evidence
Before: Mi 9 kitchen flat sort 3.3/3.3 ms, GPU 23.9/23.9 ms, 40.6 fps; as a 300k hierarchy select 3.05/3.18 ms, GPU 18.6 ms.
After: sort 2.2/2.2 ms, GPU 22.9/22.9 ms, 42.4 fps; select 2.89/2.89 ms, GPU 18.4 ms.
Tests: radix 152 cases at 4M pass; dropping the carry or the clear fails them; LOD and frame compute tests with a mutation that fails.
Where it ran: Xiaomi Mi 9, Adreno 640, Vulkan 1.1.128, Android 11, kitchen 500k at high.
Checks: device suite --large 9/9, validation runs passed, scripts/lint-cpp.sh clean. No iPhone run: Metal is untouched.
Merge Danger
Door: Two-way.
Blast Radius: Sort
A barrier mistake would show as wrong order or flicker on Vulkan only; the stable-sort device tests cover 63/64/65 tails through 4M.

The scatter keeps its stable atomicOr bitmask, since ballot loses keys on
Adreno 640, but drops the per-row clear of every mask word and the
256-digit popcount fold: the last key of each digit carries the running
count, and the lowest bit of each set word clears it. Keys and values
load into registers up front, as Metal's scatter holds its keys, and the
digit base is a chunked scan with 2 barriers in place of 16.

Mi 9 kitchen 500k, high, two runs each: sort 3.3 -> 2.2 ms, GPU 23.9 ->
22.9 ms, 40.6 -> 42.4 fps. An unstable shared-atomic rank, the floor for
these scattered writes, measured 2.0 ms. Variants with a second mask
buffer or 256-key rows saved barriers but lost more to occupancy (2.7 and
4.3 ms). Radix 152 cases at 4M pass, dropping the carry or the clear
fails them, and validation is clean.
