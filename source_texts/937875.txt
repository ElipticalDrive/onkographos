What
A new in-app experiment, Voxel World (voxel-world), that uses ARKit world tracking to rebuild the space around you as Minecraft-style colored blocks:
Voxelization: every ~0.2 s one frame is integrated. On LiDAR devices, the (smoothed) scene-depth map is unprojected pixel-by-pixel into world space; without LiDAR it falls back to ARKit's sparse tracked feature points. Points are quantized onto a world-aligned voxel grid, so blocks persist as you move and sweeping the phone gradually fills in the world.
Color: each voxel keeps a capped running average of the camera pixels that observed it (full-range BT.601 YCbCr → RGB), and at mesh time that color snaps to a fixed 28-entry Minecraft-style block palette — stylization, not real-world fidelity, is the goal.
Free-space carving: each integration also projects every existing voxel into the current depth map; a voxel the camera can now see through (observed surface well behind it) accrues misses and is removed after 3 consecutive misses. Moved objects and depth-noise floaters clean themselves up instead of leaving trails, and carved voxels free budget for new ones. (LiDAR only; re-observation resets the counter.)
Block size dial: a log-scale slider from 10 cm to 50 cm (default 25 cm) — deliberately chunky, since the 256×192 depth map can't support crisp small voxels. Changing size clears the grid and it rescans as you look around.
Extras: Freeze (stop scanning, walk around what you built), camera-feed toggle (see only the voxel world), Reset, live voxel count, and an 80k-voxel budget.
Rendering: chunked SceneKit geometry (8³-voxel chunks) with interior faces culled against the whole grid and per-face-direction shading baked into vertex colors (unlit material), rebuilt incrementally with a per-tick budget.
Permissions
No signing bootstrap re-run needed. ARKit uses the existing camera permission; the only change is the NSCameraUsageDescription Info.plist string in project.yml (updated to also mention Voxel World), which per ios/AGENTS.md never requires re-bootstrap. No new Bundle ID, entitlement, or App ID capability.
Structure
ios/Sources/Experiments/VoxelWorld/ — one directory per experiment, registered in ExperimentCatalog
Plain testable types (VoxelGrid, VoxelMesher, VoxelProjection, VoxelCarver, VoxelColorConversion, VoxelPalette, VoxelSizeMapping) kept separate from the ARKit/SceneKit plumbing (VoxelWorldSession)
Unit tests in Tests/PlaygroundTests/VoxelWorldTests.swift (grid quantization incl. negative coords, chunk floor-division, color averaging, budget/invalid rejection, carve classification and miss-threshold removal, palette quantization, mesher face culling incl. across chunk boundaries, face shading, pinhole unproject/project round trip, YCbCr conversion, slider mapping)
UI smoke test opens the experiment and checks the controls; on the Simulator ARKit is unsupported and the view shows a placeholder with the same controls
Testing
Swift can't be compiled in this Linux environment; CI (ios.yml) runs XcodeGen + fastlane test on macOS for this PR.
