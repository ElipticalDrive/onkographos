The planet renderer was generating textures on the CPU in 2D UV space (DataTexture + FBM), producing a flat, banded disc rather than a 3D world. Vine animation CSS/component also persisted as dead code.
Planet rendering — full rewrite (Planet.jsx)
Replaced meshStandardMaterial + DataTexture with a custom THREE.ShaderMaterial using GLSL vertex + fragment shaders:
3D noise on object-space surface — FBM (fbm5 + fbm3) runs per-fragment using the sphere's local position (normalize(position)). Terrain is pinned to the surface and has no UV seams or polar compression.
Correct world-space bump mapping — modelMatrix is unavailable in ShaderMaterial fragment shaders. Solved by passing uModelMat3 (upper-left 3×3 of matrixWorld) as a custom uniform updated each frame, then transforming the object-space gradient before projecting onto the world-space tangent plane.
```
vec3 worldGrad = uModelMat3 * localGrad;
vec3 tangGrad  = worldGrad - dot(worldGrad, vNormal) * vNormal;
vec3 bn = normalize(vNormal - tangGrad * 2.0);
```
Per-type materials:
ocean — dark specular ocean, layered land elevation (grass → rock → snow), polar caps, night-side city lights
gas — turbulent latitude bands, storm oval
volcanic — dark igneous rock with self-illuminating lava cracks
ice — crystalline surface, polar aurora emission
Blinn-Phong specular, atmospheric rim glow, filmic tonemapping + γ correction
Sphere tessellation bumped to 128×128
Vine animation removal
VineGrowth.jsx deleted (was never imported)
@keyframes vine-grow, .vine-container, .vine-svg removed from index.css
GalaxyIntro
No changes needed — it already imports Planet with planetType="ocean", so the intro zoom-in automatically renders the same HD shader.
