Summary
Before: a shared Session of an OpenGL game read every frame back to the CPU, converted it to YUV there and uploaded it again to NVENC. At 8x internal resolution that is a 2048x3072 readback plus a CPU conversion per frame.
After: on an NVIDIA GPU the core's frame goes from its OpenGL texture straight to h264_nvenc through CUDA-GL interop. NVENC converts RGB to YUV on the GPU, so the encoder needs no readback and no CPU conversion. The diagnostics host line ends with · GPU-direct. Without NVIDIA, with a software core or after any GPU problem, the Session uses today's readback path, and viewers see no difference.
The roadmap item "GPU-direct hardware encoding (NVENC first)" is done in code. CI has no GPU, so the real driver path can only be verified on an NVIDIA card.
How:
Emulation thread (hw_render, libretro_backend): each finished core frame is blitted into a Player-owned GL_RGBA8 encode texture, fitted into 1280x1920. The texture size does not depend on the window. The CUDA copy runs at the start of the next frame, so the GPU has a frame of slack; duplicate frames repeat the last blit.
CUDA side (cudadriver, cudaglcapture): nvcuda.dll / libcuda.so.1 is loaded at runtime through an 18-function shim, so no CUDA SDK and no new build dependency are needed. The CUDA context is created off the emulation thread. Each frame is copied into an FFmpeg CUDA frame (RGB0) and the copy is synchronised before the frame reaches the encoder.
Encoder (VideoEncoder::openGpu, SessionHost/EncodeWorker): a second encoder instance opens next to the CPU encoder. The CPU encoder closes only after the first CUDA frame is encoded.
Fallback: every GPU-path problem switches that Session back to readback frames and never sets the sticky encoder failure. The problems covered are interop, copy, open, encode, and no GPU frame for 60 frames and 1 s. Fatal CUDA errors also drop h264_nvenc from the CPU order until restart.
UI (GpuEncodeBridge, SessionController): the bridge hands frames from the emulation thread to the UI thread through a one-slot mailbox. A live-save restart keeps the bridge.
Switches: FRAMEBEAM_DISABLE_GPU_ENCODE=1 is a kill switch. A forced FRAMEBEAM_H264_ENCODER keeps readback, so it can serve as the A/B baseline.
Separate fix: BindingGuard restores the read and draw framebuffer bindings separately.
Docs: new ADR 0019 (amends ADR 0013 D3). Also updated: roadmap, architecture 04 and index, player guide env table, features, design (host-line suffix), client/CLAUDE.md, and the missing ADR 0018 entry in the docs index.
How tested
CI=1 xvfb-run -a make check-client on Linux (Mesa llvmpipe): all 65 tests pass. media_cuda_gl_hw skips here (no NVIDIA GPU).
New tests run the real GL side and the real CudaGlCapture against a fake CUDA API that enforces GL-current, context push, map/unmap pairing and texture liveness: media_cuda, media_cuda_gl_capture, ui_gpu_encode and the new cases in emulation_hw_render.
Loopback cases cover the fallback, the watchdog and the config switches. ui_diagnostics holds the 32-row plan truth table.
scripts/e2e-session.sh passes.
A six-lens adversarial review checked GL/CUDA sync, teardown, threading, fallback, Windows portability, and colours and strings. Each finding went to an independent verifier. Four findings were confirmed and are fixed here: the restart window, the watchdog on a burst of queued frames, a warning on Optimus laptops, and the hardware test size being below NVENC's minimum width.
Not verifiable in CI: CUDA-GL interop on WGL and NVENC with CUDA frames on real hardware. These need a local check on an NVIDIA GPU (driver 570 or newer); the log lines to look for are in ADR 0019 D11.

While a Session is shared and the game renders with OpenGL on an NVIDIA GPU,
SessionController creates a GpuEncodeBridge that hands CUDA frames from the
emulation thread to SessionHost. EncodeWorker opens a second, CUDA-input
h264_nvenc next to the CPU encoder and closes the CPU encoder only after the

the bridge; the new runner gets the target again.

The diagnostics host line gains " · GPU-direct" or
" · readback (GPU-direct off)", the frame row shows the GPU copy time.
