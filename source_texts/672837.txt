The HDF5 path of run_with_samples now accumulates the evidence sums per
batch and, with top_k, keeps only the running best top_k rows, so memory
no longer grows with the library. The selection is identical to one top-k
over the whole library.

stop_at_ess stops reading once the running evidence ESS reaches it (and
at least top_k rows are in). The rows read are a smaller i.i.d. library,
and every output, n_prior_samples included, describes it. Sources the
data constrain never reach the threshold and read the whole library.

- Reject stop_at_ess below min_evidence_ess (or NaN): stopping there leaves
  a run the resolution check flags as under-resolved.
- Prune the running top-k only once more than top_k rows are read, avoiding
  quadratic copying and per-shape recompiles when top_k > batch_size.
- _read_padded pads along rows (axis=0), so 2-d datasets work.
- Docs: with stop_at_ess the selection depends on read order and key;
  ignore_non_finite matters on the top_k path (NaN evidence, and a NaN ESS
  never stops); the ESS stopping rule is a heuristic that cannot see
  unsampled high-likelihood regions, and its bias is not bounded by
  ln_Z_int_mcse.
- Spec: note streaming-loop performance costs under planned features.
