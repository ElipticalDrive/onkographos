Owner
This adds source-level reverse-mode autodifferentiation.
Usage
```
import workspace/crucible

proc axpy(dst, a, b: ptr UncheckedArray[float32], alpha: float32) {.global, workgroup: (1, 1).} =
  for i in 0 ..< 8:
    dst[i] = alpha * a[i] + b[i]

const axpyPair = bkMetal.bwd_diff(axpy)

proc runTest() =   # private: engines are destroyed at return
  var engine = newEngine(runMetal)
  let ad = engine.setupAutoDiff(axpyPair)

  # [...]

  ad.forward(outDev, aDev, bDev, alpha)
  ad.backward(dOutDev, dADev, dBDev, dAlphaDev, outDev, aDev, bDev, alpha)
```
with convenience caching for the dADev, dBDev, dAlphaDev, outDev, so they can be skipped
Summary by CodeRabbit
New Features
Added automatic and hand-written backward-kernel support for Metal and Vulkan GLSL, including forward and backward execution and gradient results.
Added gradient support for common math operations, conditional logic, buffer indexing, and scalar parameters.
Improved generated shader code for logarithms and floating-point literals.
Bug Fixes
Corrected type resolution for indexed pointers to fixed-size and unchecked arrays.
Documentation
Documented and enabled a Nim linter rule that flags use of the identifier pair.

# The AST in Nim

This section describes how the AST is modelled with Nim&#39;s type system. The AST consists of nodes (`NimNode`) with a variable number of children. Each node has a field named `kind` which describes what the node contains:
    
    type

        nnkEmpty,            ## empty node
        nnkIdent,            ## node contains an identifier
        nnkIntLit,           ## node contains an int literal (example: 10)
        nnkStrLit,           ## node contains a string literal (example: &quot;abc&quot;)
        nnkNilLit,           ## node contains a nil literal (example: nil)
        nnkCaseStmt,         ## node represents a case statement
        ...                  ## many more
      
      NimNode = ref NimNodeObj
      NimNodeObj = object
        case kind: NimNodeKind           ## the node&#39;s kind
        of nnkNone, nnkEmpty, nnkNilLit:
          discard                        ## node contains no additional fields
        of nnkCharLit..nnkUInt64Lit:

This is a sketch of a plan for a new internal IR for through review.

## Motivation

The v1 IR is an abstract syntax tree, kept close to Nim AST so that conversion is simple. Nim might migrate to a new IR from Nimony:
- https://github.com/nim-lang/nimony/blob/29a73ff763d06110f87b8ef0a7a2715aba43adb4/doc/internals/multi_join_ir.md
- https://github.com/nim-lang/nimony/blob/29a73ff763d06110f87b8ef0a7a2715aba43adb4/doc/internals/leng-spec.md

We want to make sure we can keep as close as possible to future development of Nim so porting Crucible to the new compiler-plugin architecture is simplified.

It also has the following direct concrete benefits. The new IR made the compiler ~~2.25x~~ 25% faster. It seems also possible to make optimization passes easier to implement for SPIR-V emission.

There might also be side benefits on Lean 4 and autograd (#158, #161)

* crucible: while loops register their exit and continue labels on the loop stack

lowerWhile allocated its exit label but never pushed (exitL, contL) onto

* crucible: exportc overrides the kernel entry-point name, cudaName is gone
