Why
Compare native instanced rasterization with the tiled compute backend while retaining the existing fast GPU radix sorter, GaussianStore, LOD, and TSL customization.
Implementation
Add GaussianHardwarePass / gaussianHardwarePass, implemented with Three.js WebGPURenderer, an instanced oriented quad, a node material, and GPU-written indirect draw arguments. No CPU visible-count readback is needed for rendering.
Reuse ProjectionStage, ObjectFrameState, visible scan/compaction, and the existing subgroup/workgroup RadixSorter. Disable tile intersection counting in hardware projection; do not allocate/run intersection emission, tile sorting or chunk rasterization.
Read the ascending depth-sorted list backwards and use native premultiplied alpha blending. Keep projection slots and raster color/alpha/discard customization; omit compute-only cached-pixel, break and transmittance controls.
Render opaque meshes, splats, and transparent meshes into one owned target with a native depth attachment. Splats test depth but do not write it. No depth texture copying. Preserve renderer state in a finally block.
Support the LOD color helper in both backends, add &renderer=hardware sandbox selection, preserve hover marker/overlay, and hide inapplicable tile diagnostics.
Include rebuilt distribution output for GitHub dependency installation.
Try it
Run npm run sandbox and append &renderer=hardware to the existing PLY URL. Omit the parameter or use &renderer=tiled for the original backend. Compare the same pose, resolution/DPR, LOD and AA settings without profiling first; &profile=kernels remains available for GPU preparation timings.
For a small GPU correctness check, run npm run dev and open /test/browser/hardware.html. It checks blending order, a blue opaque plane between two splats, a zero-visible indirect draw, resize and WebGPU validation errors.
Validation
113 unit tests passed, including actual Three.js generation of compute/vertex/fragment WGSL, rejection of unsupported context nodes, no-count-readback preparation, material rebuilds, and render-target/state restoration.
npm run typecheck, npm run build, npm run sandbox:build, npm run format:check, and git diff --check passed.
Runtime GPU rendering and performance are not yet verified: the cloud browser blocked access to the local test server. The GPU check page is provided for local validation; unit shader generation is not a substitute for device validation.
First-backend limits
Perspective cameras with standard WebGPU depth only; no reversed/logarithmic depth or XR. Scene transparent meshes draw after all splats rather than participating in a global sort. Depth output is mesh depth, not a reconstructed Gaussian surface. Hardware blending uses working-linear colors; the tiled backend currently converts its accumulated color, so canonical sRGB clouds may show color differences. No speedup is claimed before target-GPU measurements.
