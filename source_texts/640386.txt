Observed pain point
stat_montage(..., zlevels=c(...)) used voxel slice indices in our workflow. Labels resembling z = 28 are easy to read as MNI millimetres unless the report explicitly explains otherwise. We manually documented the voxel-index versus world-coordinate distinction.
Current R/montage_stat_montage.R documents zlevels, along, ncol as slice selection arguments passed through.
Request
Document index origin and coordinate semantics explicitly. Consider an explicit selection-space option (index versus world mm), plus independently configurable labels that include units. If a lower-level API already supports this, expose/document its report-level use.
Checks
Use synthetic images with nonzero origin, nonunit spacing and nontrivial orientation. Verify requested world positions map to the intended slices, labels reflect the actual selected planes, and out-of-range requests fail clearly. Do not imply that resampling or a coordinate label establishes registration between MNI template variants. Preserve existing index-based behavior for compatibility.
Environment
Observed while assembling ROI and volume-map reports with neuromosaic 0.2.0 / R 4.5.0. Current source reviewed at e877258c7050fe5f5cd0a0ed7a98b3ee336eba77. No participant data are needed for the proposed examples or tests.
