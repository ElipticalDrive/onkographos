For mesh formats and also for supporting voxel formats (like qubicle) (see cvar voxformat_qbsavelefthanded)
see CoordinateSystemUtil.h
we need a generic way that not every mesh format class has to implement on it's own - but e.g. in the Mesh class to do a conversion for all MeshFormat classes - so the transforms in the scene graph node, as well as the vertices in the Mesh instances need to be flipped. For voxel formats we could add a tool to the voxelutil module that performs the flipping - but MeshFormat implementations should directly modify the Mesh itself after it was transformed by the scene graph node transform data (if that is possible with the current code) - that would be way less memory intensive. For the voxel volume axis flipping approach - we could extend the CoordinateSystemVolume maybe? or some kind of CoordinateSystemVolumeView class, which just changes coordinates internally according to the math::CoordinateSystem enum value in the ctor e.g.
