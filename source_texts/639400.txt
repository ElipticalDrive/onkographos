User Story
As a player who has just connected to a server
I want to actually see the Norse landscape the server generated around me
So that Voxelheim stops being a protocol and starts being a world
Acceptance Criteria
Received ChunkData is decoded from RLE into a dense u16 array and stored in a resource keyed by chunk coordinate
A greedy mesher merges coplanar quads per axis across all six face directions and returns one mesh per chunk
Meshing runs on AsyncComputeTaskPool and its result is applied on a later frame — the main schedule never meshes
Each chunk mesh spawns as an entity translated to the chunk's world origin, and despawns on ChunkUnload
Block ids map to base colours (Stone grey, Dirt brown, Grass green, Snow white) through a StandardMaterial or vertex colours — no texture atlas
A camera at the spawn point renders the streamed terrain, and a debug overlay shows loaded chunk count, total quad count and last mesh duration
The mesher is a pure function with no Bevy world access, unit-tested on synthetic chunks
cargo fmt --check, clippy -D warnings, build --locked and test --locked stay clean
Technical Context
Files to Modify
client/src/world/mod.rs — chunk store resource, RLE decode, ChunkData/ChunkUnload handling
client/src/world/mesher.rs — the greedy meshing algorithm and its tests
client/src/world/render.rs — task spawning, mesh application, entity spawn/despawn
client/src/world/palette.rs — block id to colour mapping
client/src/ui/status.rs — extend the debug overlay with chunk/quad/timing counters
client/AGENTS.md — document the mesher's purity rule and the border limitation
Patterns to Follow
Greedy meshing sweeps each of the three axes, building a 2D mask per slice and merging maximal rectangles — the standard two-pass sweep, kept in one file with no ECS types in its signature.
Chunk data arrives over the channel from NetPlugin; the world module owns decoding, exactly as the net module owns framing.
One task per chunk, keyed by coordinate, with in-flight tasks tracked so a re-sent chunk never meshes twice concurrently.
Constraints
Faces interior to a chunk MUST be culled; faces on a chunk border are treated as exposed. This is a deliberate limitation for this issue (extra quads, no visual artifact) and MUST be documented in client/AGENTS.md with a follow-up issue noted.
The mesher MUST stay pure and deterministic: same chunk in, same vertex buffer out — this is what makes it testable.
MUST NOT add crates (no meshing or noise library).
MUST NOT decide anything about the world: the client renders exactly the voxels the server sent, and never generates or predicts terrain locally.
Out of Scope
Do NOT implement cross-chunk face culling, ambient occlusion or lighting
Do NOT add a texture atlas, UVs, normals maps or any art asset
Do NOT implement LOD, frustum-driven chunk requests or client-side chunk prediction
Do NOT implement transparency, water or block-breaking visuals
Do NOT implement player movement or camera control — a fixed camera at spawn is enough here
Do NOT touch schemas/, server/ or CI
Dependencies
Requires #5 (Bevy client scaffold) and #4 (chunk streaming) to be merged first — the mesher needs real ChunkData arriving over the wire.
Code Pointers
client/src/net/mod.rs — the channel this module drains for ChunkData
client/src/gen/world_generated.rs — the generated accessors for the RLE payload (read, never edit)
server/internal/world/rle.go — the encoder whose format this decoder must mirror
server/internal/world/chunk.go — the chunk index order the mesher must agree with
docs/GDD.md:12 — greedy meshing is a GDD-level performance commitment
Test Strategy
Unit: all-air chunk produces zero quads
Unit: a single solid block produces exactly six quads
Unit: a fully solid 32x32x32 chunk produces exactly six quads (one merged face per direction) — the strongest greedy-merge assertion
Unit: a flat solid plane one voxel thick merges to one quad per visible direction
Unit: RLE decode roundtrip against bytes produced by the server's encoder format, including the alternating worst case
Unit: determinism — meshing the same chunk twice yields identical vertex and index buffers
Perf smoke: a worst-case checkerboard chunk meshes under a generous documented ceiling (no tight timing assertion in CI)
Manual: connect to a running server and confirm terrain appears with no holes at chunk borders and no seams in the heightfield
