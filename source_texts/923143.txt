Is your feature request related to a problem? Please describe.
When surfaces are parallel but offset, it can be difficult to interpret the 3D view:
The problem can be mitigated using ambient occlusion to produce previews like this:
This technique is widely used in other CAD software, for example Fusion 3D:
Describe the solution you'd like
SSAO is a technique for simulating ambient occlusion.
It is "screen space" which means that it uses the depth buffer rather than the geometry. That makes it a good fit for OpenSCAD previews, where full geometry may not be available during rendering. It only needs the depth and normal buffers from the existing framebuffer. The resulting AO buffer is then multiplied by the existing colour buffer.
It can be implemented entirely in a shader which could be turned on or off as desired by the user.
It would require very few changes to the code. Mainly just adding an extra shader to the existing GL views.
Here is a primer on SSAO: https://learnopengl.com/Advanced-Lighting/SSAO
Here is a real time example: https://www.shadertoy.com/view/Ms33WB

I think implementing this would be much easier than the people in the previous discussion realised.

I have a working proof of concept for this. I adapted the shader from the link in previous post. Screenshots:
Now the bad news: there's a bunch of things that need to be fixed or refactored before this can properly work:
OpenSCAD generates inconsistent normals. For renders, all normals point into the surface. But for previews, normals for subtractive objects (ie the cut surface for difference, usually drawn in green) point outwards. The SSAO shader I am using requires all normals to point away from the surface. This can be worked around in the shader: if a face is visible on screen then its normal must point towards the camera. So if normal.z < 0, flip it. Ideally the shader would know whether the object being drawn is positive or negative, then it could adjust the normals as appropriate.
I re-used the edge shader for this. It isn't used to draw the background and axes etc. Those are drawn by the fixed function pipeline, which puts colour data into all attached buffers. So those things don't render properly, and you can't render edges at all - turning on edge rendering in the GUI now enables SSAO instead.
I also re-used the FBO code. It requires a width and height for the constructor, but I don't know those when I need to create it. It also creates a colour render buffer which is unnecessary for this as I attach my own buffers.
Not entirely necessary but the code for loading and managing shaders could be improved to make using more shaders easier.
My implementation is really noisy and has artefacts. A better implementation (like the one I adapted) would have more stages that eg render the AO to yet another texture, blur it, and then render that to the screen. But that needs more shaders and more buffers.
