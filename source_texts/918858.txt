This pull request introduces a new 3D Bresenham line tracing utility for integer grid traversal, ports and documents its Unity algorithm semantics, and significantly enhances the AR depth sampling logic for occupancy grid use. The depth sampler now emits the capturing view's projection matrix in each sample, supports a denser default sampling grid, and includes robust configuration and validation. Comprehensive property-based and unit tests have been added for both the Bresenham tracer and depth sampler, ensuring correctness and Unity parity.
3D Bresenham Line Tracer Addition:
Added a new bresenham3d implementation (src/ar/bresenham3d.ts) for integer grid cell traversal, directly ported from Unity's occupancy grid helper, with strict parity to its semantics, error handling, and stop-distance logic. Includes a detailed markdown doc (bresenham3d.ts.md). [1] [2]
Registered the new tracer and related files in the build config (tsdown.config.ts).
Added comprehensive property-based and unit tests for bresenham3d, covering known traces, invariants, stop-distance behavior, and error cases. [1] [2]
Depth Sampler Improvements:
Depth samples now include the capturing view's projection matrix (if available), enabling correct 3D unprojection for occupancy grid use; back-compat is maintained for samples without the matrix. [1] [2] [3]
Introduced wrapXRDepthInfo to robustly wrap and validate browser XRDepthInformation objects, ensuring safe matrix copying and correct getDepthInMeters binding. [1] [2]
Increased the default sampling grid size from 3×3 to 16×16, providing sufficient density for on-device occupancy grid verification. [1] [2]
Depth Sampler Configuration and Testing:
Added and improved tests for partial config updates, defensive validation of input values, and correct application of user settings to the sampler.
Enhanced tests to verify correct sample emission, projection matrix handling, and grid size effects, ensuring round-trip JSON compatibility and robust behavior. [1] [2] [3] [4]
File/Config Registration:
Registered new AR utility files (bresenham3d.ts, depth-unprojection.ts, occupancy-grid.ts) in the TypeScript build config.
These changes collectively lay the groundwork for robust AR occupancy grid operations, matching Unity's semantics, and enabling future on-device correctness verification.

This pull request implements an AR-space occupancy grid system ported from Unity, which includes a 3D Bresenham line tracer, depth unprojection math, and an OccupancyGrid class to manage voxel occupancy and free-space carving. It also integrates these components into the WebXR session, recorder app, and replay mode, supported by an instanced-cube visualizer (OccupancyCubesVisualizer) and denser depth grid configurations. In addSample, processing carving and incrementing in a single loop can lead to order-dependent bugs within the same depth sample. If a shorter ray (e.g., endpoint at 5m) is processed before a longer overlapping ray (e.g., endpoint at 10m), the carving of the longer ray will delete the newly added occupied cell of the shorter ray.\n\nTo ensure correctness and determinism, perform all carving in a first pass, and then increment all occupied cells in a second pass.
```
  addSample(sample: DepthSample): number {\n    if (!isFiniteTriple(sample.cameraPos)) {\n      return 0;\n    }\n    const cameraCell = this.cellForPosition(sample.cameraPos);\n    const validCells: GridCell[] = [];\n\n    for (const point of sample.points) {\n      const world = unprojectDepthPoint(\n        point,\n        sample.cameraPos,\n        sample.cameraRot,\n        sample.projectionMatrix\n      );\n      if (!world) {\n        continue;\n      }\n      const cell = this.cellForPosition(world);\n      validCells.push(cell);\n\n      if (!cellsEqual(cameraCell, cell)) {\n        this.carve(cameraCell, cell);\n      }\n    }\n\n    for (const cell of validCells) {\n      this.increment(cell);\n    }\n\n    return validCells.length;\n  }
```

Avoid using mat4.fromValues with the spread operator on projectionMatrix. Since gl-matrix functions like mat4.invert accept any ArrayLike<number> (which matches Matrix4), you can pass projectionMatrix directly to mat4.invert. This avoids the overhead of the spread operator and creating an intermediate matrix.
```
  const invProj = mat4.invert(mat4.create(), projectionMatrix as unknown as mat4);
```
