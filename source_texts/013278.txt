Optional dynamic-GI mode: RCGI (radiance-cached global illumination), modeled on the GI architecture id Software presented for idTech 8 at SIGGRAPH 2025 ("FAST AS HELL", Tiago Sousa). Off by default — RenderSettings::rcgi / RX_RCGI=1 / debug-overlay checkbox. When enabled it replaces the single DDGI volume + SSGI as the indirect-diffuse path; when disabled there is zero behavior change (no passes scheduled, no history copies).
Design + implementation notes live in RCGI.md.
Pipeline
```
Light Grid -> Probe Visibility Rays -> World Radiance Cache -> Irradiance Cascades
     (world side, async compute)                                     |
                                                                     v
        Final Gather (1/2 res, 1 rpp, 2-band SH) -> Bilateral Denoise -> Upscale + SH eval + Temporal
```
Cascaded world-space light grid — 16³ cells × 4 cascades (32 m doubling), camera-snapped, single dispatch with a two-phase hierarchical cull (groupshared coarse bitmask → per-cell test). Lets ray hits outside the frustum be lit by point/spot lights; the existing froxel cluster grid is frustum-tied.
World radiance cache — 1M-slot spatial hash (25 cm base cells, distance LOD, linear probing). Probe rays register hit cells; an indirect dispatch shades only the active cells through the bindless tables: sun (shadow ray) + emissive + light-grid lights + previous-frame cascade bounce (multi-bounce). Entries are reused across frames.
Cascaded irradiance volumes — 16³ probes × 4 cascades (2 m spacing doubling), octahedral irradiance + Chebyshev visibility atlases, one cascade updated per frame, hysteresis + snap reconvergence (DDGI-style, generalized to cascades).
Final gather — half-res, 1 cosine-weighted ray/pixel, zero shading at the hit: three-level cache fallback (previous-frame screen radiance → world radiance cache → cascades; sky on miss), projected into 2-band SH per pixel.
Denoise + upscale — separable bilateral gaussian (depth/normal/hitT weights) on the SH at gather res, then a 4-tap bilateral upsample that evaluates the SH with the full-res normal (restores normal-map detail) + temporal filter with per-pixel sample counter and neighborhood clamp.
World-side passes run on async compute (join before the gather), mirroring the DDGI wiring.
RX_RCGI_PROBES_ONLY=1 keeps a cascade-only resolve as an A/B debug path.

All 10 findings addressed in d0b1c35. Per finding:
Shutdown order — rcgi_.reset() now sits with the other GPU-owning systems in Renderer::Shutdown, before device_.reset() (light_grid_ was already torn down earlier). Every RX_UI_SHOT run exercises this path (RequestQuit → Host::Shutdown → renderer_.Shutdown); all verification runs exited 0.
TLAS gating — the frame's needs-TLAS predicate now includes rcgi_active.
Torn cache payloads — exactly one ray per cell per frame owns the multiword payload: ownership is claimed via InterlockedExchange on the queued-frame stamp; losers write nothing, so words can no longer interleave across rays. The active-list append stays gated on staleness (≥4 frames), preserving the re-shade amortization. The shade pass additionally bounds-checks instance/geometry/material indices via GetDimensions before any bindless fetch.
Clear→atomic visibility — added BarrierScope::kComputeReadWrite (types.h + vulkan backend; the scope enum isn't a bitmask, so a combined scope over two barriers) and switched both post-FillBuffer barriers (state_, active_meta_) to it. Audited the light grid: it has no clear→atomic pattern, these were the only two sites.
Undefined cascade blends — per-cascade validity: each cascade's first blend after creation/teleport runs with reset=true, a validity bitmask travels in RcgiGlobals so SampleRcgiIrradiance returns zero from not-yet-valid cascades (covers the cache-shade bounce term sampling before first blend too), and the atlases are now created with TRANSFER_DST and cleared to black up front.
Frame-zero sentinel — stamps are frame+1 encoded everywhere (RcgiStampEncode, 0 = never); RcgiCacheLookup rejects key-matched entries whose shaded stamp is still 0, so inserted-but-unshaded cells fall through to the cascade/sky level.
Eviction — age-based reclamation during the insertion probe: a slot whose queued stamp is older than kRcgiEvictAge (256 frames) is reclaimed via key CAS; the winner zeroes the shaded stamp so stale radiance can't leak. Never-queued (stamp 0) slots are not evictable, to avoid stomping a same-frame half-insert. ABA is documented as tolerated (cache semantics). This matches the RCGI.md design text now.
Memory when disabled — RCGI + light grid are lazily created on first activation (settings.rcgi && rt_available && !rcgi_ in the settings-apply path); creation failure is non-fatal (logged, feature stays unavailable, failure latched). Created-once — toggling off does not thrash the 85 MiB. Verified via creation log: unset RX_RCGI allocates nothing.
Partial screen-resource failure — EnsureScreenResources returns bool, tears down partial allocations and clears the cached extent (retry possible); on failure the frame falls back to the probes-only resolve, so no null images are imported.
Inverted temporal clamp — the all-sky-taps case (weight sum ~0 / mn > mx) is treated as disocclusion: zero irradiance, history counter reset, clamp skipped; final history write is scrubbed through a finite non-negative clamp. Denoise audited — its center tap always contributes, so no equivalent path there.
Verification: build green, 11/11 ctests, and on the GB10 via vkrun: RX_RCGI unset is bit-identical to the pre-fix baseline (cmp); RCGI-on cornell/materials/lights converge with the bleed intact and no speckle; --no-rt clean; --validation shows zero errors with async off in both states. With async on, the one remaining message is the pre-existing rcgi_args INDIRECT_COMMAND_READ-under-compute-queue issue documented in RCGI.md — it reproduces without these changes and looks like an engine-wide RHI gap (the compute-only stage filter drops DRAW_INDIRECT while keeping the access flag); happy to take that as a follow-up outside this PR. 120-frame temporal sequence stays flat (MAD ≈ 2.4/255, same as baseline).
RCGI.md gained a "Review fixes" section covering the stamp encoding, eviction policy, lazy creation, per-cascade validity and the async caveat.
