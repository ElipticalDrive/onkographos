M3b ships a brute-force per-triangle Möller-Trumbore over every live face for pluton::ray_intersect_mesh. That's O(N) per pick — fine for M3b scenes (≤ a few hundred triangles) but doesn't scale.
A BVH (bounding-volume hierarchy) lands at the M10 perf milestone. CGAL has AABB_tree which would be natural to plug in once CGAL is on board (post-M3c).
Acceptance:
Pick latency on a 100k-triangle scene < 1 ms.
pluton::ray_intersect_mesh signature stays stable (M3b's API contract).
C++ tests for the BVH path mirror the brute-force test cases plus a perf regression test.
Spec reference: docs/2026-05-23-M3b-push-pull-design.md §6.3, §7 (out of scope for M3b).
