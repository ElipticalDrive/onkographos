Part of #415.
Two places would profit from a fast sort on a device:
The order of the tuples (The tuple kernel adds the values of a block in block memory (D[tuple-block-sums]) #412's follow-up). Sorting the tuples by their first member would leave 0.10 distinct particles per member in a block of 128 tuples, instead of 0.24 (Cellulose). That means fewer slots and atomics for the block sums of The tuple kernel adds the values of a block in block memory (D[tuple-block-sums]) #412, and better locality for the reads. The sort is static per topology, at the start or at each reordering of the particles (D44, D86).
Binning by key, for the sorted strategy of Accumulation by sort and run-length reduction, without atomics: a fast path for the deterministic mode #417 and possibly for the bins of PME on a device: spreading through tiles of bins, chosen by the size of the grid (D[pme-tiles]) #410.
CUB has a block radix sort (block/block_radix_sort.cuh, block_radix_rank.cuh) and a device radix sort, whose onesweep variant is described by Adinets and Merrill, "Onesweep: A Faster Least Significant Digit Radix Sort for GPUs" (arXiv:2206.01784, 2022).
Work
(1) first. It is a host or device sort once per topology order, so it does not need a fast device sort. Measure the tuple kernel of The tuple kernel adds the values of a block in block memory (D[tuple-block-sums]) #412 with and without it, per system and node.
(2), if Accumulation by sort and run-length reduction, without atomics: a fast path for the deterministic mode #417 shows a gain. A block radix sort in the lowering, as a lowering of a sort op of md_exec.
Results are unchanged in the deterministic mode, which orders its sums explicitly.
