### Summary

Add a physically‑plausible, configurable sky that animates through the day/night cycle, drives sun direction and scene lighting, and supports *zone‑local weather overrides*. This is the basis for a full weather system (later phases: clouds, precipitation, storms).

We’ll start with an analytic clear‑sky model (Hosek–Wilkie) for visual quality + speed, drive a directional light from the sun position, compute ambient sky lighting (Spherical Harmonics L2) for “fill,” and expose settings so designers can scrub time‑of‑day and author per‑zone weather. Hosek–Wilkie is widely used and robust at low sun elevations; it improves upon Preetham at sunset/turbid skies. ([[Computer Graphics Group](https://cgg.mff.cuni.cz/projects/SkylightModelling/HosekWilkie_SkylightModel_SIGGRAPH2012_Preprint.pdf?utm_source=chatgpt.com)][1])

---

## Goals (Phase 1)

* **Dynamic sky** rendered as a background pass (fullscreen triangle) or skydome using an **analytic model**.
* **Sun motion** over time with **configurable time‑of‑day** (pause/speed/scrub).
* **Scene lighting driven by the sun:**

  * Directional light from sun vector.
  * Optional single‑cascade shadow map (CSM in Phase 2).
  * **Ambient skylight** via SH‑L2 (9 coefficients) generated from the sky model each update. ([[Computer Science](https://cseweb.ucsd.edu/~ravir/papers/envmap/envmap.pdf?utm_source=chatgpt.com)][2])
* **Per‑zone weather overrides** (turbidity/haze, fog density/color, cloud coverage placeholder).
* **Designer controls:** debug UI + data‑driven JSON in `data/`.
* **Tooling:** sky visible in `tools/model-viewer` for quick iteration.

### Non‑Goals (defer to later phases)

* Volumetric clouds, aerial perspective with multiple scattering LUTs, precipitation, moon/stars parallax, HDR pipeline polish (tone‑mapping can be basic in Phase 1; ACES fit optional). For reference, Hillaire/UE Sky Atmosphere and Bruneton LUTs are strong paths for future phases. ([[sebh.github.io](https://sebh.github.io/publications/egsr2020.pdf?utm_source=chatgpt.com)][3])

## High‑level Approach

1. **Sky model (CPU coefficients, GPU evaluation).**
   Use the Rust crate **`hw-skymodel`** (pure Rust Hosek–Wilkie) to compute per‑frame coefficients (RGB) and sun radiance. Upload compact params to a `@group(…)` WGSL uniform and evaluate the sky color per pixel in `sky.wgsl`. ([[Docs.rs](https://docs.rs/hw-skymodel?utm_source=chatgpt.com)][4])

2. **Sun position & time‑of‑day.**
   Provide two drivers:

   * **Game‑relative** (simple azimuth/elevation from [0..1] day fraction), and
   * **Geographic** (optional, uses **`solar-positioning`** SPA/Grena3 or `suncalc` for latitude/longitude/calendar inputs). Expose both; default to game‑relative. ([[Crates](https://crates.io/crates/solar-positioning/0.3.0?utm_source=chatgpt.com)][5])

3. **Lighting the world.**

   * **Directional light**: feed `sun_dir`, `sun_illuminance_lux` (or normalized intensity) to `gfx/shader.wgsl` and apply a **Lambert** term on existing materials (start simple; PBR later).
   * **Ambient skylight**: sample the sky model on CPU (e.g., 64–196 directions) and project to **SH‑L2** (9×RGB). Upload `sh_coeffs[9]` to shaders for diffuse ambient. ([[Computer Science](https://cseweb.ucsd.edu/~ravir/papers/envmap/envmap.pdf?utm_source=chatgpt.com)][2])

4. **Shadows.**
   Phase 1: single directional shadow map (1×2k).
   Phase 2: **Cascaded Shadow Maps (CSM)** (3–4 cascades) following common practice. ([[Learn OpenGL](https://learnopengl.com/Guest-Articles/2021/CSM?utm_source=chatgpt.com)][6])

5. **Fog / aerial perspective (starter).**
   Height‑ and distance‑based exponential fog (parameters come from zone weather). (Advanced aerial perspective and multi‑scattering later; see Hillaire for future work.) ([[sebh.github.io](https://sebh.github.io/publications/egsr2020.pdf?utm_source=chatgpt.com)][3])

6. **Tone mapping (optional toggle).**
   Basic Reinhard by default; optional **ACES filmic fit** (K. Narkowicz) for nicer sunsets. ([[Krzysztof Narkowicz](https://knarkowicz.wordpress.com/2016/01/06/aces-filmic-tone-mapping-curve/?utm_source=chatgpt.com)][7])

7. **Zones & weather.**
   Add `WeatherZone` components with AABB/sphere volumes. On camera/actor inside a zone, blend defaults with zone overrides (turbidity, fog density/color, ambient tint, wind, cloud coverage placeholder).

pub struct TimeOfDay {

    pub rate_scale: f32, // 1.0 = realtime, 60.0 = 1 minute == 1 hour

#[derive(Clone, Copy)]
pub struct SunLight {
    pub dir_ws: glam::Vec3,
    pub illuminance_lux: f32, // or normalized and let exposure/tone-map handle range
    pub color: glam::Vec3,    // usually white; slight tint optional
}

#[derive(Clone)]
pub struct SkyConfig {
    pub turbidity: f32,        // [1..10]
    pub ground_albedo: glam::Vec3,
    pub exposure: f32,         // if tone mapping enabled
    pub fog_density: f32,
    pub fog_height_falloff: f32,
    pub ambient_boost: f32,    // multiply SH ambient
    pub model: SkyModelKind,   // HosekWilkie | Preetham (fallback)
}

// ecs/components/weather_zone.rs
pub struct WeatherZone {
    pub aabb_min: glam::Vec3,
    pub aabb_max: glam::Vec3,
    pub profile: WeatherProfile,
}
pub struct WeatherProfile {
    pub turbidity: Option<f32>,
    pub fog_density: Option<f32>,
    pub fog_color: Option<glam::Vec3>,
    pub ambient_tint: Option<glam::Vec3>,
    pub exposure: Option<f32>,
    pub cloud_coverage: Option<f32>, // placeholder for Phase 2
}

@fragment
fn fs_main(in: VSOut) -> @location(0) vec4<f32> {
    let n = normalize(in.normal_ws);
    let Ld = max(dot(n, -globals.sun_dir_ws), 0.0);
    let diffuse = material.base_color * (Ld * globals.sun_illuminance);
    let ambient = material.base_color * sh_irradiance_L2(n, globals.sh9_ambient);
    let color = fog_apply(diffuse + ambient, in.world_pos);
    return tonemap(color, globals.exposure);
}

## Integration Notes

* **Model choice:** Hosek–Wilkie handles sunsets and high turbidity better than Preetham; good “Phase 1” target. Keep interfaces abstract so we can swap in Hillaire or Bruneton later for volumetrics/aerial perspective. ([[Computer Graphics Group](https://cgg.mff.cuni.cz/projects/SkylightModelling/HosekWilkie_SkylightModel_SIGGRAPH2012_Preprint.pdf?utm_source=chatgpt.com)][1])
* **Sun computation:** Support both lightweight day‑fraction math and real solar position via `solar-positioning` (SPA/Grena3) or `suncalc`. ([[Crates](https://crates.io/crates/solar-positioning/0.3.0?utm_source=chatgpt.com)][5])
* **Ambient lighting:** Use SH‑L2 (9 coeffs) from the sky model for diffuse fill (classic technique). ([[Computer Science](https://cseweb.ucsd.edu/~ravir/papers/envmap/envmap.pdf?utm_source=chatgpt.com)][2])
* **Shadows:** Start with single map; plan CSM next (common approach; LearnOpenGL article for splits/filtering rationale). ([[Learn OpenGL](https://learnopengl.com/Guest-Articles/2021/CSM?utm_source=chatgpt.com)][6])
* **Tone mapping:** Optional ACES filmic fit curve by Narkowicz; otherwise Reinhard. ([[Krzysztof Narkowicz](https://knarkowicz.wordpress.com/2016/01/06/aces-filmic-tone-mapping-curve/?utm_source=chatgpt.com)][7])

## Acceptance Criteria

* [ ] Setting `day_frac` from 0.00 → 1.00 moves the sun smoothly from dawn → noon → dusk → night; the sky color changes accordingly.
* [ ] The sun direction **lights geometry** (Lambert) and **casts shadows** (single shadow map).
* [ ] Ambient **skylight** visibly fills shadowed faces (SH‑L2), matching sky tint at different times.
* [ ] Designers can **pause**, **scrub**, and **speed up** time and see lighting/sky update live.
* [ ] Entering a `WeatherZone` **blends** turbidity/fog/ambient tint within 0.5–2.0s (configurable).
* [ ] `tools/model-viewer` shows the sky and allows time scrub.
* [ ] All new code is behind `gfx.sky` feature flags and passes CI: `cargo clippy --all-targets -D warnings`, unit tests for SH projection/math and sun position.
