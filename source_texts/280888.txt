Summary
Adds a Bounding Volume Hierarchy (BVH) intersection backend for the OpenCL propagation kernel. The existing flat per-solid AABB path is preserved and still used as the default for small scenes; a cost-based heuristic in CLScene decides which path to use. Measured 2.9×–5.4× end-to-end speedup on sphere-rich scenes (Apple M4 Pro, OpenCL 1.2).
No behavior change for users who do not opt in: scenes that fall below the heuristic threshold (and any scene with useBVH=False) take exactly the same code path as before this branch.
What is the BVH and why add one?
The flat path tests every ray against every solid's bounding box, then — if a hit is plausible — against every triangle of every relevant surface. Cost grows roughly with O(nSolids² + nTriangles) per ray. On a scene with ~1000 triangles each ray pays for all of them.
A BVH is a binary tree of bounding boxes: each internal node's box encloses both of its children's boxes; each leaf holds a small handful of triangles. A ray descends the tree, skipping any subtree whose box it misses, and only does triangle-level tests at the leaves it reaches. Cost drops to roughly O(log(nTriangles) + leafSize) per ray.
The CPU FastIntersectionFinder already used the same SpacePartition data structure; this PR makes that structure available on the GPU.
How the pieces fit together
End-to-end data flow when BVH is enabled:
CLScene.__init__ (opencl/CLScene.py:41) processes the scene's triangles into the flat-list buffers (unchanged), then calls _buildBVH which:
Calls _bvhWorthwhile() (CLScene.py:81) to decide based on solid count vs. polygon count — see Heuristic below.
Builds a SpacePartition (the same CPU tree used by FastIntersectionFinder) with NoSplitThreeAxesConstructor, maxDepth=20, minLeafSize=6.
Flattens it into two GPU-friendly buffers via flattenSpacePartition (buffers/treeCL.py:80).
flattenSpacePartition emits a DFS pre-order array. Each TreeNodeCL entry carries (xMin, yMin, zMin, xMax, yMax, zMax, polygonCount, offset):
polygonCount > 0 → leaf. offset is the start index in LeafPolygonsCL, which is a flat uint array of triangle IDs.
polygonCount == 0 → internal node. offset is the index of the right child (or NO_CHILD = 0xFFFFFFFF). Left child is implicitly idx + 1. Triangles that straddle a split plane appear once per leaf they belong to (matching what the no-split CPU constructor does).
CLPhotons._propagate (opencl/CLPhotons.py:87) passes scene.nNodes, scene.treeNodes, scene.leafPolygons to the propagate kernel.
propagation.c kernel (opencl/src/propagation.c:247) stuffs those into the Scene struct and forwards to findIntersection.
findIntersection (opencl/src/intersection.c:498) dispatches:
scene->nNodes > 0 → _findIntersectionBVH (intersection.c:371)
otherwise → existing flat per-solid AABB loop (unchanged)
_findIntersectionBVH does an iterative DFS over the flat node array using a 32-deep private stack (BVH_STACK_SIZE). For each leaf it visits, it calls _testPolygonIntersection on each triangle — the same helper the flat path uses, refactored out for reuse.
Heuristic
_bvhWorthwhile() (CLScene.py:81) compares model costs:
```
flatCost = nSolids² + nPolys
bvhCost  = BVH_KERNEL_PENALTY × (log2(nPolys) + BVH_MIN_LEAF_SIZE)
```
BVH_KERNEL_PENALTY = 5 accounts for the BVH path being more expensive per operation on the GPU (branchy memory access, private traversal stack). The user can override with CLScene(scene, nWU, useBVH=True/False).
Why surfaceID was added to TriangleCL
The flat path's outer loop holds the current surface index in a local variable, so the surface a polygon belongs to is implicit context. BVH leaves contain polygons from any surface in any order, so that context is gone — the polygon test needs the surface lookup during the test (back-catch skip, photon-on-side filter). Storing surfaceID on each triangle is O(1) on the same cache line, vs. O(log nSurfaces) reverse lookup. Costs 4 bytes per triangle.
See triangles[polygonID].surfaceID use at intersection.c:281.

Tests
testCLTree.py — flatten algorithm, topology invariants, empty-tree guard.
testCLIntersection.py — kernel-level parity: 64 rays through a 3-sphere scene (~960 polygons) on both paths; asserts agreement on hit/miss, position, normal, surfaceID, distanceLeft. Stacked-cuboid case specifically exercises the per-triangle surfaceID lookup.

testCLPropagationStuckPhotons.py — five regression tests covering two historical failure modes (Fresnel reflection loops, silent photon loss). Each runs on both flat and BVH paths under a 30 s wallclock.
Risk and opt-out
Default heuristic is conservative — small scenes stay on the flat path automatically.
CLScene(..., useBVH=False) forces the legacy path.
BVH construction time can dominate for small scenes / short runs (see benchmark breakdown). The current heuristic does not model build cost; for very short runs the user may want useBVH=False.

```
Introduces a DFS pre-order flattening of the existing scene
SpacePartition so it can be uploaded to the GPU as two buffers:
```

Build BVH inside CLScene with cost-based heuristic
…
751a7f0
```
CLScene now optionally constructs a SpacePartition over scene
polygons and exposes the flattened tree (treeNodes, leafPolygons,
nNodes) alongside the existing flat-list buffers. The two paths
coexist - the kernel selects one based on nNodes (>0 means BVH).

Selection is auto by default and uses a worst-case kernel-cost model
that depends on both solid count and polygon count:

    flatCost = N_solids^2 + N_polys
    bvhCost  = K * (log2(N_polys) + minLeafSize)
    useBVH   = flatCost > bvhCost

K (BVH_KERNEL_PENALTY) charges BVH traversal for branchier memory
access and the per-WU traversal stack vs. the flat path's tight inner
loop. With K=5 and minLeafSize=6 the heuristic correctly keeps small
scenes (single cuboid, layered phantom) on the flat path and switches
to BVH once either the solid count grows (bubble-sort dominated) or
any single solid is dense (linear scan dominated).

The decision can be overridden via CLScene(..., useBVH=True/False).
```

```
intersection.c gains _findIntersectionBVH(), an iterative DFS over the
flat TreeNode array using a 32-deep private-memory stack. The Scene
struct is extended with nNodes/treeNodes/leafPolygons; findIntersection
dispatches to the BVH path when nNodes > 0, else to the existing flat

and its layout is verified to match.

_testPolygonIntersection learns to skip polygons whose owning solid
matches an ignoreSolidID (matching the flat path's per-solid skip).

A new test kernel findIntersectionsBVH is added so kernel-level parity
can be verified in Python: testBVHFindIntersectionMatchesFlatPathOnDenseScene
fires 64 rays through a 3-sphere scene (~960 polygons) on both paths
and asserts they agree on hit/miss, polygon ID, and distance.

The production propagate kernel is not yet plumbed to pass the BVH
buffers; that wiring is the next chunk. Behavior for existing users
is therefore unchanged in this commit.
```

Tighten BVH tests and add defensive guards (QA review)
…
b40d586
```
Three fixes from the BVH self-review:

1. flattenSpacePartition now raises ValueError on an empty partition.
   An empty root would have been emitted as a leaf with polygonCount=0
   and offset=0, which the kernel parses as an internal node pointing
   to a non-existent left child (out-of-bounds read at index 1).
   CLScene._buildBVH already short-circuits on empty scenes; this is
   defense-in-depth so the host API can't be misused. Covered by
   testFlattenRejectsEmptyPartition.

2. testRootLeafTreeProducesSingleLeafNode previously contained a
   tautology - filtering nodes by `polygonCount > 0 or polygonCount == 0`
   on a uint field always matches every node. Replaced with the
   intended `assertEqual(1, len(nodes))`.

3. The findIntersections / findIntersectionsBVH test kernels now take
   photonSolidID and ignoreSolidID as kernel arguments instead of
   hard-coding -1 / 0. Three new parity tests exercise the previously
   dead code paths in the BVH backend:

     - photonSolidID != -1 (photon already inside a solid - the >99%
       production case; tests the same-solid back-catch and surface
       environment filter)
     - ignoreSolidID != 0 (used in propagation to skip the last
       detector hit; previously dead from a test perspective)
     - stacked Cuboids (interface polygons split across multiple
       SurfaceCL entries - exactly where an off-by-one in the new
       triangles[p].surfaceID lookup would bite)

The parity check itself was thin: it compared exists/distance/
polygonID only. It now also compares position, normal, surfaceID,
and distanceLeft. polygonID equality is intentionally relaxed
because two adjacent triangles sharing an edge can both produce
equal-distance hits, and the path that visits one first wins;
surfaceID equality + position equality is the firmer invariant.
```

Add stuck-photon and escape-photon regression suite
…
783ca17
```
Prior versions of this codebase have produced two failure modes that
the existing test suite cannot catch:

  1. Photons stuck in a Fresnel-reflection loop without scattering
     between bounces - the kernel exits each batch when the per-WU
     log fills, but the photon's weight is never set to 0, so the
     CLPhotons orchestrator's `while photonCount < N` loop spins
     forever waiting for one to die.

  2. Photons silently escaping the simulation domain (or being
     dropped by a numerical bug) without their energy being
     accounted for.

testCLPropagationStuckPhotons.py builds the kinds of scene that have
historically stressed these failure modes - very small geometry,
very high mu_s, high refractive-index contrast for total internal
reflection - and runs propagation under a 30s wallclock timeout on
both the flat and BVH intersection paths. A regression that
introduces stuck photons will hang and trip the timeout; one that
silently loses photons will push absorbance below the 80% floor in
the energy-conservation tests.

Five tests, each covering both useBVH=False and useBVH=True:

  - testSmallSphereHighDiffusionCompletes
  - testSmallCubeHighDiffusionCompletes (axis-aligned faces stress
    corner numerics that spheres mask)
  - testHighIndexContrastTIRCompletes (forward-peaked scattering +
    n=1.6 produces many TIR events between scatters)
  - testEnergyConservationSmallSphereHighAbsorbance
  - testEnergyConservationSmallCubeHighAbsorbance

Measured baseline absorbance on the conservation tests is 93-95%;
the 80% floor leaves comfortable margin for Monte Carlo noise while
still catching any regression that loses 10%+ of photons.
```
