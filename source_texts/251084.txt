Refs #1054 (audit GS-AUDIT-SHD-002, P1) and #1063. Slice 1 of the accepted ADR docs/architecture/adr-splat-colour-encoding.md (#1059), option E.
Base: 522a212ef3a (origin/master) · Head: d2e0661f798 (round 1 f6b0ea08c2e, then a CodeFactor split 434c8252071, then round 2 d2e0661f798, on top of 54897156423) · Risk class: R2 (renderer / shaders / tests) · Status: evidence complete; maintainer visual sign-off given; ready for review.
Problem
Negative spherical-harmonics coefficients are clamped to zero by the unsigned RGB9E5 packing on every production path #1054: Both GPU packers stored each SH coefficient triplet as unsigned RGB9E5, which clamped every negative channel to 0 on every path. Trained SH has zero mean, so view-dependent colour was wrong on every real scan. The audit runtime probe showed negative band-1 SH rendering bit-identical to zero SH.
SH view direction is inverted against the 3DGS reference: bands 1 and 3 of view-dependent colour are sign-flipped on every real scan #1063 (found in review round 1): tile_binning.glsl evaluated the SH basis with dir = camera − splat. The reference, Inria 3DGS computeColorFromSH (forward.cu), uses dir = pos − campos. The basis is odd in dir for bands 1 and 3, so every trained band-1 and band-3 coefficient rendered with the opposite sign. The clamp had partly hidden this, so fixing only the clamp would have made the flipped term fully visible. By maintainer decision both land together.
Change
Encoding (renderer/gaussian_gpu_layout.*):
Each triplet is three 10-bit two's-complement integers (bits 0-9 / 10-19 / 20-29; bits 30-31 zero).
They are scaled by one per-splat magnitude, the largest stored |component|, carried in the unused sh_dc.w lane. No shader reads sh_dc.w as colour; ADR §2 verified this, and the round-1 review re-checked it.
+0 bytes per splat: PackedGaussian and PackedGaussianQuantized stay 128 B / 80 B.
Max error per component is scale/1022. Non-finite components count as 0. A non-finite inverse step (scale below about 1.5e-36) stores zero words instead of converting inf or NaN to int.
New id GS_SH_ENCODING_SNORM10_SPLAT_SCALE = 2; the RGB9E5 id 1 is retired and never reused.
SH words are uint end to end: PackedSphericalHarmonics.encoded, and GLSL sh_encoded[12] in tile_binning, both rasterizers, depth_compute and the embedded mirror in gpu_sorting_pipeline.cpp. Many SNORM10 words are float denormals, and a float array would leave them at the mercy of a driver's denormal handling.
Shader (shaders/includes/gs_sh_binning.glsl, shaders/tile_binning.glsl):
decode_sh_snorm10() does sign extension through bitfieldExtract on a signed int.
The quantized metadata synthesiser uses the new id.
The view direction is now the reference normalize(g.position − camera) (SH view direction is inverted against the 3DGS reference: bands 1 and 3 of view-dependent colour are sign-flipped on every real scan #1063).
An unsupported SH encoding still renders DC-only, but is now counted: debug counter sh_unknown_encoding_count, appended to DebugCounters / TileDebugCounterSnapshot and exported in the binning stats. This includes encoding 0 with a non-zero coefficient count. The counter counts evaluations, not splats; on the SH-cache path it counts refreshes.
Guard (tests/ci/check_gaussian_layout_sync.py):
A mirror check pins TileDebugCounterSnapshot to the binding-6 DebugCounters SSBO (sizeof anchor 132 B).
The SNORM10 contract check pins, between the host encoder/decoder mirror and the GLSL decoder:
the id, max and field offsets;
sign extension, via the signed int word;
the encoder shifts and the signed clamp;
the scale lane (dst.sh.dc[3] / dst.sh_dc[3] written, g.sh_dc.w read);
the quantized metadata id, and that nothing emits RGB9E5.
The view direction is deliberately not pinned by source spelling (round 2): the GPU test asserts it as a rendered property.
Checks are scoped to function bodies with comments stripped.
Release gate manifest: the RequiresGPU snapshot goes 163 → 164, recomputed with the repo's own functions. RendererSceneTree minimum_test_cases goes 1 → 2.
Waived by the maintainer, not changed: the second RGB9E5 decoder in gaussian_splat_common_inc.glsl. Its only user, gaussian_splat.glsl, is compiled but never drawn. Deletion is tracked in gaussian_splatting: delete the dead gaussian_splat.glsl shader and its RGB9E5 SH decoder #1064.
