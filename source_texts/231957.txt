背景
shaders/model/raster.slang の fragment は ambient 0.2 / diffuse 0.8 を、shaders/postprocess/composite.slang は ambient 0.3 と距離減衰係数 (0.01, 0.001) をハードコードしている。MaterialUBO は base_color / metallic / roughness を持つが fragment は base_color しか読まない。マテリアルの一般的な扱いを設計し直す (PR #188 レビュー指摘)。
現状
箇所
ハードコード
model/raster.slang fragmentMain
ambient 0.2、diffuse 係数 0.8、texColor * vertex color * base_color の乗算
postprocess/composite.slang fragmentMain
ambient 0.3、減衰 1 / (1 + 0.01 d + 0.001 d^2)、albedo のみ (metallic / roughness 未使用)
MaterialUBO
base_color, metallic, roughness, padding。glTF の他の PBR 入力 (normal / emissive / occlusion / metallic-roughness texture) なし
設計方針 (検討項目)
glTF 2.0 metallic-roughness を SSoT にする: 入力は baseColor / metallicRoughness / normal / occlusion / emissive の 5 テクスチャ + factor。Blender Principled BSDF、Maya Standard Surface、Unreal Material の共通部分がこれ
照明モデル: composite の Lambert + ambient 定数を Cook-Torrance (GGX / Smith / Schlick) に置き換え、ambient は環境光 (IBL または定数 irradiance) を FrameUBO 側のパラメータにする。Unreal / Filament / bevy の StandardMaterial を参照
定数の置き場: ambient 強度、減衰係数は shader の literal ではなく FrameUBO (シーン) か MaterialUBO (マテリアル) のどちらが持つかを決める。値そのものはユーザが決める (エンジンは parameter を提供するだけ)
gbuffer レイアウト: metallic / roughness / emissive を gbuffer に載せる (現状 position / normal / albedo / object id)
model pass と gbuffer pass の統一: model/raster.slang の forward 照明と composite の deferred 照明が別実装なので、照明関数を shaders/include/ の 1 モジュールに集約し両方から呼ぶ
参考
glTF 2.0 spec Appendix B (BRDF implementation)
Filament: Physically Based Rendering in Filament (material model, parameterization)
bevy bevy_pbr::StandardMaterial / pbr_functions.wgsl
Unreal Engine: Material Inputs (Base Color / Metallic / Specular / Roughness / Emissive / Normal / AO)
Blender Principled BSDF、Maya Standard Surface (Autodesk Standard Surface spec)
完了条件
shader 内に照明の magic number が残らない (ambient / diffuse 比、減衰係数は UBO のパラメータ)
MaterialUBO の全フィールドが照明に使われる
照明関数は shaders/include/ の 1 モジュール、model / composite が共有

PR #205 で以下を対応しました。
照明の magic number (ambient / 減衰係数) を shader から撤去し、LightingParams → FrameUBO.lighting / SceneData.lighting の UBO パラメータに移動
照明関数を shaders/include/lighting.slang (Cook-Torrance: GGX / Smith-Schlick-GGX / Schlick) の 1 モジュールに集約し、model/raster と composite が共有
MaterialUBO の base_color / metallic / roughness をすべて照明に使用 (gbuffer に metallic = albedo.a、roughness = normal.w を追加)
SceneData を shaders/include/scene.slang に集約
今回対応できなかった点 (別 issue 化を推奨):
glTF の metallic/roughness factor の import: IBL が無い状態で glTF の既定値 metallic = 1 をそのまま入れると、金属は拡散色を持たないため鏡面ハイライト以外が黒くなる。IBL (または環境光の鏡面成分) を入れてから import する方が安全なので、今回は MaterialUBO の既定 (metallic 0 / roughness 0.5) のまま
normal / occlusion / emissive / metallicRoughness の 4 テクスチャ: 現状の material descriptor set は baseColor 1 枚のみで、binding の追加と importer 側の読み込みが必要
IBL (環境光 irradiance / prefiltered specular): 現状の ambient は定数 ambient * baseColor
照明パラメータの UI: LightState.lighting はコード上の既定値のみで、inspector からは編集できない
