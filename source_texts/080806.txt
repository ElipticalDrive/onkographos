Summary
Adds a sky drawn by a shader instead of from image files. It is opt-in: a world still shows its clear color unless it sets this sky.
core: adds ProceduralSky3dOpts with { type: 'PROCEDURAL', timeOfDay, sunAzimuth, sunPeakElevation, sunSize, haze, exposure, groundColor, clouds: { coverage, density, scale, wind } | null, cirrus: { coverage, density, scale, wind } | null, stars, moon, moonSize, mode, bakeResolution }. Every field is optional (PROCEDURAL_SKY_DEFAULTS). The cirrus layer is off unless given, and {} turns it on with PROCEDURAL_SKY_CIRRUS_DEFAULTS.
Environment3dOpts.background and environmentMap accept it, and so does the "Environment" level class, which passes it through without loading anything.
proceduralSkyBodies(sky) returns the sun and moon directions, the sunlight's color and intensity (dimmed at dusk and under overcast) for a directional light, and the rotation of the star field.
three: adds ThreeProceduralSky.
The shader does single-scattering Rayleigh/Mie with an air-mass optical depth and a twilight glow.
It draws one fbm cloud layer with self-shadowing, sunlit edges and darker thick parts when overcast.
It draws an optional cirrus layer above that: streaks along its wind, with a warp for wisps and fine fibres. It is lit through less air, so it stays colored after sunset.
It also draws hashed stars (sized to the pixel, twinkling) and a moon.
'DYNAMIC' mode draws it every frame as a far-plane box, so clouds drift and stars twinkle.
'BAKED' mode draws it into a cube render target only when a setting changes.
As an environment map it is baked at 128 px per side and prefiltered with its own PMREMGenerator.
Baking happens in ThreeSceneComponent.prepareFrame(renderer), which both renderer components call before rendering.
examples: adds 3d/sky, with a free camera (click to look, WASD/E/Q to fly) and sliders for every setting, including the cirrus layer (on/off, coverage, density, scale, wind speed and direction).
It has animate-time, dynamic/baked and light-the-scene toggles.
Presets: clear noon, sunset, winter overcast and night.
A directional light follows the sun (the moon at night) through proceduralSkyBodies.
The shader is our own code. It is written from the published scattering formulas and uses no third-party engine code. The hash functions are David Hoskins' "Hash without Sine" (MIT), credited in the shader.

How it was tested
npm test passes in packages/core and packages/three. New specs cover:
defaults, including the cirrus layer, which is off by default
sun and moon positions, and the sunlight values
level JSON passthrough
scene mesh and uniform updates, including turning cirrus on and off and its streak axis
baked background and environment assignment, and disposal
I rendered the sky in headless Chromium (SwiftShader) for noon, sunset, dusk, full overcast, night with moon and stars, high haze and large cloud scale. Cirrus was rendered alone, with clouds, overhead, at sunset and dusk, and with a diagonal wind.
I also ran 3d/sky built against the local packages. A baked sky matches the dynamic one, 'standart' meshes are lit by the environment map, and the presets and cirrus controls work.
Cost in SwiftShader at 400x260: a dynamic sky is about 14-18 ms, against 1.4 ms for a trivial full-screen shader. Cirrus adds about a sixth to that. A baked sky is 3-5 ms, against 0.5 ms for a plain color. Real-GPU numbers are still to be checked on hardware.
npm run lint:examples, bash examples/prettier.sh --check and npm run check:agents-md all pass.
