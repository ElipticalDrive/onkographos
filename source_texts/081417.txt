I am really impressed of the various features that you added to the volume renderer!
I started using the slices geometry with the same volume that I do volume rendering on.
Since the transfer function for volume rendering and the slices is the same, I am somewhat restricted.
I would require an extra transfer function for the slices. Or is there a "cheap" way of copying the volume and setting a different transferfunction?
The same applies to the "isovalus" feature, I think it would be better to provide either an extra transferfunction for it, or to provide a list of colors with the isovalues, one color per isosurface.

Hi,
We are tracking this feature request, but it hasn't been prioritized yet. We have limited resources to be able to handle all the feature requests we get, which is not limited to the list here posted on Github. I'd like to point out that we have made good progress on and will continue to support the ability to extend OSPRay within client applications, either through using the OSPRay SDK (found in the OSPRay include/ dir from an install) or by writing an "OSPRay module".
An example of a simple OSPRay module can be found here: https://github.com/jeffamstutz/module_nanort
The example implements a triangle mesh which forwards ray intersection calls to a small, header-only ray tracing library called NanoRT. While the geometry type itself is not related to this topic, it is a fairly small example of how to extend OSPRay in the source tree and use it in the sample viewer. Any object type (including the implicit isosurfaces geoemtry type!) which doesn't meet your needs, you can substitute your own instead.
As always, of course, pull requests are welcome. :)
Cheers,
Jeff
