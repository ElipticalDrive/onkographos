Missing capability
Only a loaded EXR environment is available; there is no authored plain/gradient sky, atmospheric scattering, aerial perspective, geolocated sun or sky preset workflow.
Suggested priority: P2.
Current implementation
src/renderer/lighting/EnvironmentManager.cpp (loadHdrEnvironment), shaders/environment_sky_common.slang, and src/utility/GuiManager.cpp.
Reference implementation
Bruneton atmosphere LUT generation — src/sky_bruneton.cpp
solar position — src/sun_position.cpp
atmosphere and time-of-day controls — src/ui_environment.cpp#L690
authored sky serialization — src/gltf_environment_sky.cpp
sky presets — src/sky_preset.cpp
Scope
Add plain/gradient environments and a bounded physical atmosphere with Rayleigh/Mie/ozone, planet/observer and solar controls, including aerial perspective.
Bake analytic environments into the shared lighting/background pipeline; keep sun energy and directional-light contribution consistent.
Expose latitude/longitude, date/time and UTC offset with deterministic sun placement, plus save/load sky presets.
Import supported environment-sky metadata with an explicit provisional policy for draft/vendor formats.
Acceptance criteria
Both raster techniques and DDGI consume consistent sky radiance and orientation; changing sky/sun invalidates affected histories.
Validate sunrise/noon/sunset, below-horizon and observer-height cases, finite outputs and energy consistency.
Disabled sky and existing EXR rendering continue to work; record GPU cost, LUT memory and packaged resources.
Audit baseline
Source comparison on 2026-10-24: F:\Nvidia\vk_gltf_renderer at 174625d5c621 and F:\Projects\Container at HEAD cb8406a937ce, including its current uncommitted work. Findings are from source inspection; runtime parity has not been measured. Implement in the project's Vulkan-Hpp RAII/VMA/Slang architecture and follow docs/coordinate-conventions.md where rendering is affected.
Plain and gradient skies
Scene Controls → Environment → Procedural Sky and the capture CLI now support plain and elevation-gradient skies with scene-linear colors. The Vulkan compute pass evaluates their radiance directly into the shared cubemap, then runs the same IBL generation and fenced publication used for HDR files.
Renderer 14644f31 passed 196 convention tests and 24 sampled Vulkan captures. Both raster paths matched independently encoded EXR references within two sRGB code values. Live EXR → plain → gradient → EXR transitions reset temporal and async probe history, and each path published ten DDGI updates under synchronization validation. The bundled EXR still matched the original output. Logs are in out/feature-parity/procedural-sky-runtime.log and procedural-sky-hdr-regression.log.
Atmosphere mode now evaluates spherical Rayleigh and Mie single scattering, ozone absorption, and sunlit ground radiance. The panel and capture CLI expose solar azimuth and elevation, observer height, planet radius, atmosphere thickness, irradiance, and density multipliers. The fenced Vulkan bake uses a 128×128 cubemap and no extra atmosphere LUTs.
Renderer 885a86b3 and shader c8708bbe passed 196 convention tests and 44 sampled Vulkan captures. The atmosphere cases matched 90 CPU-reference sky samples within one sRGB code value. Live transitions reset history in both raster paths with actual asynchronous DDGI. Map generation and IBL filtering took 1.75–2.60 ms on the RTX 2080 SUPER. Logs are in out/feature-parity/physical-sky-runtime.log, physical-sky-live.log and physical-sky-hdr.log.
The visible solar disk and linked directional light now use the same RGB atmospheric transmittance, orientation and planet occlusion. The disk stays out of the cubemap bake. Scene Controls can disable the link to preserve independent directional lighting.
Renderer da64eefe passed 196 convention tests and 56 sampled Vulkan captures. Both raster paths checked disk color, irradiance, yaw, opt-out, and planet occlusion against the CPU reference. The live async DDGI sequence installed and cleared the linked sun on environment transitions. Logs are in out/feature-parity/solar-link-runtime.log, solar-atmosphere.log, solar-link-live.log and solar-link-hdr.log.
Location and time controls now derive the geometric solar position from latitude, longitude, Gregorian local date and time, and a signed UTC offset. The result drives atmosphere scattering, the disk and the linked scene light. North is +Z and east +X before environment yaw.
Renderer d4c64dc1 passed 196 convention tests and 22 Vulkan captures. Both paths checked a published reference position, pixel-identical UTC rollover, midnight sun, and polar night, then passed the manual-sun regression. Logs are in out/feature-parity/solar-time-runtime.log and solar-time-manual.log.
The Procedural Sky panel and capture CLI now share versioned JSON presets for plain, gradient and atmosphere settings, including manual or geolocated sun controls. Preset loads validate before applying and saves replace the destination atomically.
Renderer 43fbfa51 passed 196 convention tests and 14 Vulkan captures. Presets reproduced explicit sky flags pixel for pixel in forward and deferred raster. Unicode paths, override order, malformed inputs and failed replacement were covered, and both the shared display preset and solar-time regressions passed. Evidence is in out/feature-parity/sky-preset-runtime.log and sky-preset-solar-time.log.
Aerial perspective now applies the shared atmosphere's finite-distance extinction and single scattering to opaque and transparent scene surfaces before tone mapping. The scale is expressed in metres per scene unit and defaults to zero. Version 2 sky presets store the scale, and version 1 presets load with zero scale.
Renderer eaaaa377 passed 196 convention tests and 34 sampled Vulkan captures. Both raster techniques matched opaque and transparent CPU references within three sRGB code values, and zero scale matched all four pre-change baselines. Preset migration, enabled preset equivalence, and the atmosphere-sky regression also passed. Logs are in out/feature-parity/aerial-runtime.log, aerial-preset.log and aerial-sky-regression.log.
The optional OMI_environment_sky draft now has an explicit opt-in preview for the selected scene's plain and gradient skies, including curves and tilt. Unsupported types and malformed entries retain the existing environment or startup fallback. Required declarations still fail the capability gate. Sky preset version 3 preserves the gradient shape and orientation.
Renderer 094b9e66 passed 196 convention tests and 36 sampled Vulkan captures. Both raster paths matched the authored plain sky pixel-for-pixel and the tilted gradient within one sRGB code value of the independent EXR. Fallback, required-extension diagnostics, preset migration and async DDGI transitions passed. Logs are in out/feature-parity/authored-sky-runtime.log, authored-sky-presets.log and authored-sky-regression.log.
Atmosphere mode now offers an opt-in Multiple Scattering checkbox and the --sky-multiple-scattering capture flag. The shared sky, image-based lighting, and opaque and transparent aerial perspective use the same 16×8 radiance table. The approximation uses isotropic higher orders and a bounded geometric series. Version 4 sky presets store the option. Versions 1–3 load with it disabled. Atmosphere rendering paper
Renderer 7db734b9 passed 196 convention tests and 84 Vulkan captures. Both raster paths verified higher-order sky and aerial haze, dark and zero-scattering controls, preset equivalence and live temporal and asynchronous DDGI invalidation. The single-scattering CPU references and the bundled EXR baseline passed. The environment bake and IBL filtering took 1.95–2.60 ms on the RTX 2080 SUPER. The CPU table took 9.47 ms per call in a standalone Release benchmark. It uses 2 KiB of bake texture payload and 2 KiB per lighting uniform buffer. The existing packaged SPIR-V paths carry the shader changes. The lookup table is generated at runtime.
Evidence is under out/feature-parity/multiple-* and in docs/feature-parity-progress.md. The implementation is validated locally. This issue stays open pending integration.
