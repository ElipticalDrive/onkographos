Owner
On a device with ray query, the main pass can now ask the scene whether the sun is visible instead of reading the cascades or the virtual shadow map: one ray per shaded pixel, from the fragment shader, against a top-level acceleration structure rebuilt each frame from the draw items that cast. Off by default (rayTracedShadows.enabled). The shadow maps stay as the fallback, and on a frame that traces the cascades are skipped unless something else still reads them.
On Sponza, tracing is 13.0% cheaper per frame than the cascades with the camera still, and skipping the cascades takes off another 9.9% on frames where they would have redrawn (numbers below).
Full write-up: docs/ray_traced_shadows.md.
Commits
Negotiate ray query and wrap acceleration structures. VK_KHR_ray_query, VK_KHR_acceleration_structure and VK_KHR_deferred_host_operations join the optional-extension table, with their feature structs chained into device creation and a row in the capability report. --disable-ray-query declines all three, so a GPU with ray tracing can be created exactly as one without it. A decline is its own outcome in the selection policy. rhi::VulkanAccelerationStructure owns a structure and its storage buffer.
Trace sun shadows with ray queries. One BLAS per mesh primitive at LOD 0, built at startup; one TLAS, bound once at set 0 binding 16 and rebuilt in place. What casts follows the cascades' rules: opaque items are FORCE_OPAQUE instances, cutouts run the masked shadow pass's own alpha test on each candidate, and blended items cast nothing. The ray-query fragment shader is a second compile of simple_bindless.frag.
Cast from the skinned mesh by refitting its BLAS. A compute pass skins the demo mesh's positions each frame that traces, and its BLAS is built once and refitted after that.
Skip the cascades on frames that trace when nothing else reads them. The main pass, the phase-two re-draw, the transparent pass and the skinned draw all run the ray-query shader, so CSMShadowPass and its caster cull are neither declared nor recorded unless volumetric fog, probe capture, the ray-traced comparison view, the VSM cascade-depth view or the new rayTracedShadows.renderCascades setting needs them. The decision is taken once per frame and answers both the graph declaration and the recorder, so the two cannot disagree. The cascade cache commits a resident key only when a cascade is drawn, so turning tracing off redraws only what changed meanwhile. renderCascades exists for the A/B that separates what tracing costs from what skipping saves.
Bound shadow rays by the scene's extent, not the camera's far plane. The far plane limits which receivers are drawn, not how far away their occluders are, and the TLAS holds casters outside the view: a tall caster further than the far plane along the sun direction would have left a visible receiver lit. The ray now runs the diagonal of the union of every drawn item's world bounds plus the skinned mesh's, with a margin, and invalid bounds fall back to a long ray rather than a zero-length one.
Sample every frame when measuring, and let a run freeze the scene. The measurement tooling the numbers below depend on. Sponza's MainHDRPass is bimodal frame to frame, and that made the drift gate fail at 11.7% and 4.9%. A per-frame diagnostic showed every frame doing identical work: the slow ones carry about 0.6 ms of GPU time from another process, charged to whichever pass is running. That cannot be fixed in the renderer, so the statistic has to cope with it. --gpu-timings-every-frame (and measure_gpu.py --every-frame) prints timings for every frame, about 11000–12000 samples per 75-second run instead of ~64, with the warm-up dropped by an elapsed stamp on each block. --freeze-animation holds the demo lights, skinned pose and animated transforms still; the scene line then reads sponza+frozen, so a series cannot pool frozen and animated runs. The investigation is in docs/profiling.md.

Synchronization
The graph orders build -> trace through two new buffer accesses on the TLAS storage buffer. Its write mask had no acceleration-structure write bit, so that edge would have emitted no barrier; a test pins it.
The previous frame's traces and builds are ordered by an explicit barrier at the top of the build, because the graph rebuilds buffer state every frame.
BLAS writes reach the rays through global barriers, since a ray reads every BLAS the TLAS references and the graph's barrier names only the TLAS buffer.
Skipping the cascades removes passes from the graph rather than adding any edge.
Synchronization validation does not see any of these edges. Removing each one and running under --sync-validation reported nothing while the layer's self-test fired. The barriers are pinned instead by an api_dump of the recorded frames and by the graph tests.

The skinned mesh skins in its vertex stage and keeps nothing, so rays had
no deformed triangles to hit and it cast no ray-traced shadow. A compute
pass (skin_positions.comp) now writes its skinned positions each frame
that traces with it shown, from the same half of the same palette as
simple_skinned.vert, and its BLAS is built from them once and refitted
after that (ALLOW_UPDATE). It joins the TLAS under the cascades' own
condition for it, as an opaque instance on the reserved object slot.

Order inside RayTracingSceneBuild: the entry barrier, the pre-skin
dispatch, a barrier from its writes to the build's reads, the build or
refit, a global barrier from it to the TLAS build and the rays, then the
TLAS build. The positions buffer and the BLAS are single and rewritten
in place, like the TLAS; the entry barrier now names the compute stage
so the previous refit's reads are ordered against this pre-skin.

That barrier also names the fragment stage now. The graph's barrier
before the rays covers the TLAS buffer only, while a ray reads every
BLAS the TLAS references, so the BLASes built at startup were formally
unordered against the rays in the previous step. Global barriers cover
them, and the refitted one, instead.

The layout constants move into ray_traced_shadows.glsl, shared by the
fragment shader's alpha test and the pre-skin dispatch.

Verified on an RTX 3080 Ti Laptop, validation on, zero errors: the
default scene with tracing off still matches the previous build at
0/921600 pixels. With only the skinned mesh casting and exposure pinned,
the traced frame differs from the virtual shadow map on 1572 pixels and
the cascades on 4078, and the three regions that differ read the same
under the ray and VSM. An api_dump shows a full build on the first
traced frame and MODE_UPDATE after it, each after the pre-skin dispatch.

On Sponza at the 800 MHz pin the drift gate failed a cascades-against-
traced series at 11.7% and 4.9%. MainHDRPass there is bimodal frame to
frame, and p10 over ~64 once-a-second samples is the 6th or 7th lowest,

histogram and occlusion state, and frame slot did not matter. The slow
frames carry about 0.6 ms of wall-clock time that lands in whichever pass
is running: when it misses MainHDRPass, the rest of the frame carries it
instead. It arrives at the same rate under MAILBOX, IMMEDIATE and FIFO,

removing it. It is another process sharing the GPU, so there is nothing
in the renderer to fix; the statistic has to cope with it.
