macOS 27.0.1, Apple M4 Max, MoltenVK 1.4.2. Read on main f035e4b.
MoltenVK has no VK_EXT_conditional_rendering, so pred_init (query.c) fails and render_enable_update (engines.c) reads each count with gmem_read, which waits for the GPU to run everything recorded. With #775 and #776 applied, that is 15% of the GPU thread in one game.
Drawing without the count is worse (35.4 to 23.7 fps): the game's occlusion culling saves more GPU time than the wait costs. Using the stale value in memory gave the same 23.6. Two ways to keep the culling without the extension: the vertex shader reads the predicate the compute jobs already make (g_pbuf) and collapses the positions, or indirect draws whose counts a dispatch zeroes.
