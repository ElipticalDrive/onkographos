Summary
Complete the higher-ceiling follow-up to #280's indexed-indirect foundation with real compute-driven visibility refinement, GPU compaction, and temporal hierarchical-Z occlusion.
Architecture
CPU portal connectivity remains authoritative. The compute stage only receives persistent room packets that already survived the existing portal/frustum walk, so GPU culling can reject additional work but cannot make disconnected geometry visible.
The frame graph treats Hi-Z as temporal history. Before WorldSetup clears the scene target, the visibility pass consumes the previous frame's pyramid:
uploads retained room AABBs + mesh index counts to GPU storage
performs a conservative current-camera AABB frustum test in compute
applies temporally guarded Hi-Z occlusion only when projected bounds are stable between frames
writes the exact 20-byte DrawIndexedIndirect record for each candidate
uses instanceCount = 0/1 as the GPU visibility decision
atomically compacts visible packet IDs into a dense GPU buffer
feeds those GPU-written indirect records directly to retained World and deferred-PBR replay with no CPU visibility readback
Immediately after the six-pass World graph, a dedicated compute node rebuilds the R32F max-depth pyramid from current World depth for the next frame, before outlines/HUD/post-processing can contaminate the history.
Conservative Hi-Z guards
Occlusion is skipped when:
there is no valid previous depth history
the depth target changed or resized
a projected corner crosses behind the camera
projected center motion exceeds the temporal pixel threshold
projected extent changes beyond the conservative threshold
The Hi-Z chain stores maximum standard depth over each 2x2 region, so a packet is rejected only when its nearest projected depth is beyond the conservative hierarchy sample plus bias.
Fallbacks / platform policy
compute or resource setup failure refuses GPU visibility for the session and falls back to Optimize retained renderer after core migration #280's retained CPU visibility + indirect/direct path
shadow is explicitly fenced from visibility args because it executes before the compute pass
desktop DX12/Vulkan enable the compute path initially
Android remains disabled until physical-device testing proves that readable-depth + Hi-Z bandwidth wins on tile renderers
Metal remains disabled until its indirect path beats the existing direct submission benchmark
Compaction scope
The visible-ID list and atomic visible count are genuinely GPU compacted. It is not yet emitted as one multi-draw because retained packets still use different vertex/index buffers, bind groups and material/pipeline state. Shared state-bucket geometry/bind tables are a separate optimization.
Validation / metrics
Renderer benchmark output now records:
GPU visibility enabled/refused
compute dispatches
candidates processed
Hi-Z builds
indirect draws consuming GPU visibility
candidate high-water
-rendergraphcheck validates that GPU visibility runs between shadow and WorldSetup and owns the Hi-Z/visibility graph resources.
