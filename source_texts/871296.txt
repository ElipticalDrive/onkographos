Summary
Clean rebuild of the Cyclone Studios Scan-to-3D pipeline on rebuild/clean-pipeline. It turns photographs (or video frames) into a textured 3D mesh that opens in Blender. Each stage is independent, logged and resumable from saved results. The pipeline has been validated end to end on a 128-photo dataset of a house (front facade only), reconstructing a textured mesh and exporting it to OBJ and GLB.
Architecture, chosen after evaluating COLMAP incremental vs global mapping on identical features:
photos/video → validate → COLMAP features/matching (CPU) → incremental sparse → undistort → dense PatchMatch + fusion (Colab T4, CUDA) → Poisson mesh → simplification → texture atlas → OBJ/GLB export + Blender check
Changes made
Project skeleton: src/scan3d package, pyproject.toml, CLI (scan3d doctor | run | status | report | remote-probe), YAML configs with defaults and --set key=value overrides.
Pipeline framework: stage runner with a per-run manifest.json (config + input fingerprints), automatic skip of up-to-date stages, --force, per-stage logs, and timing/peak-memory capture.
Stages: ingest (photos and video frames via ffmpeg, one camera group per source), validate (blur, exposure, resolution), features, sparse (incremental or global mapper, per-group registration metrics), undistort, dense (remote), mesh (Poisson, simplification, texturing), export.
Remote GPU execution: Colab executor on top of the colab CLI. Files go through chunked, checksum-verified 4 MB transfers (the Colab file API rejects large single uploads), with retries, GPU fallback, and an upload copy of the images re-encoded at JPEG q85. CUDA COLMAP is installed on the VM through micromamba.
Export and validation: converter from COLMAP's textured PLY to OBJ + MTL (Blender's PLY importer does not read COLMAP's per-face UVs), GLB export, and a headless Blender check that imports the mesh and renders six axis views.
Reporting: scan3d report writes runs/<id>/report.md (stage metrics, renders, limitations).
Tests: unit tests for fingerprinting and resume/invalidation, config overrides, COLMAP stats parsing and per-group registration counting.
Testing performed
Automated checks pass. 6 unit tests pass. There are no automated tests yet for ply_to_obj, the remote executor, or the stages that call external tools.
Manually tested where applicable (see results below).
Documentation updated where necessary. README.md and docs/ are still to be written.

Incremental was chosen as the default over the global mapper because it had the lower error with equal registration and similar runtime. This comparison is for this dataset only.
Video input: ingest, validate, features and sparse were run on two test clips of a computer. Frames registered (57/60 and 121/121), but the subjects were glossy and low-texture, with motion blur and thin sparse clouds (about 8.5k points). The dense and mesh stages were not run on video, so the video path is not validated end to end.

Reviewer notes
Please look closely at
remote/colab_entry.py: runs on the Colab VM (standard library only) via colab exec, installs COLMAP with CUDA, and runs PatchMatch and fusion.
utils/ply_to_obj.py: assumes COLMAP's exact textured-PLY layout and fails loudly if the layout differs.
export.flip_v: texture V orientation. [author: state which value was verified in Blender; the screenshot of the textured house used ___.]
Setup and reproducibility gaps
configs/house.yaml contains an absolute path to a COLMAP 4.2.1 binary in a separate conda env (colmap4). This should become documented setup or an environment variable.
Requires an authenticated colab CLI and Colab compute units. A 125-photo dense run used about 82 minutes of T4 time.
numpy, OpenCV and PyYAML come from the conda environment, not pyproject.toml.
Known limitations
The house dataset covers only the front of the building. The roof is missing, many windows are holes, edges are ragged, and small floating fragments remain.
Scale is arbitrary (up-to-scale SfM) and accuracy against ground truth has not been validated. Reprojection error measures internal consistency only.
The 0.05 simplification ratio was chosen for file size and has not been measured against the full mesh. The full 18M-face Poisson mesh is kept in the run folder.
Matching is exhaustive (quadratic in image count). Bundle adjustment, meshing and texturing run on CPU, so the pipeline is not GPU-only.
COLMAP's coordinate frame is arbitrary, so models may import rotated.
Video frame selection is naive (fixed rate, then blur filtering), with no sharpest-frame or near-duplicate selection.
Suggested follow-ups: remove small disconnected fragments, tune Poisson trimming, export two levels of detail, sequential matching and better frame selection for video, GPU matching, tests for ply_to_obj, README and docs/limitations.md.
