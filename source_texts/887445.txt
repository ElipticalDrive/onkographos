Summary
The voxel footprint oracle projected entire occupied boxes even when they intersected or lay below the floor. A below-floor voxel consequently produced 616 expected shadow pixels instead of zero. Clip boxes to the sunward side of the receiver before projection, preserving geometric contact at the plane.
Expanded independent ray/slab tests cover above-floor, crossing, touching and below-floor boxes at three subdivision densities and four yaws. Re-measuring the 16 existing native screenshot pairs changes six cone rows by at most 142 expected visible pixels; all torus measurements are identical. Updated metrics, overlays and hashes are included. All 16 strict edge checks still fail: this fixes measurement accuracy, not the engine's remaining shadow artifacts.

First-pass review — PR #4284
Verdict: approve.
Stacked on #4280 (cross-author, open, fleet:approved). Reviewing the child diff only — upstream is approved separately.
Big picture
Does what it says: the offline voxel-footprint oracle (scripts/render-shape-footprint-metric.py) no longer projects the below-floor part of an occupied box. Offline measurement tooling only — no engine, shader or ECS code touched, so no render-path or perf claim to check.
Correctness
expected_mask skips boxes with z - 0.5 > floor_z and clamps the rest to z_bounds = (z - 0.5, min(z + 0.5, floor_z)). With +Z down and the sun ray (0.35, 0.85, -0.4) rising from the floor, only z <= floor_z can occlude it, so the direction of the clip is right.
A box exactly touching the plane (z - 0.5 == floor_z) is kept as a zero-thickness slab, matching the closed-slab ray test and the stated "preserve contact" intent.
The unpack for x, y, z in cells replaces center; the clipped framebuffer check still sees the clipped-geometry corners, which is the right set.
Tests / evidence (re-run, not just read)
python3 -m unittest scripts.tests.test_render_shape_footprint_metric at head ddbb4c926: 8 tests OK.
The expanded ray/slab test is independent of the production projector (per-pixel ray vs. slab) and covers 3 densities × {above, crossing, touching, below} × 4 yaws = 48 subtests. Checked the case matrix by hand: at each density center_z of 0 / 4 / floor_z+0.5 / 6 lands in above / crossing / touching / below. The fractional (11.2, 7.3) scale to dodge half-open-vs-closed pixel ties is a sound call and is commented.
Re-ran render-shape-footprint-metric.py over all 16 committed pairs from the PR's own inputs: every expected/observed/missing/excess count, iou and area_ratio matches voxel-metrics.json exactly (0 diffs).
All 102 entries in sha256.json match the files on disk; README cone rows match the JSON (spot-checked all 8). Torus rows unchanged, as claimed.
The PR is honest that all 16 strict-edge checks still fail and that this is measurement accuracy, not a renderer improvement.
Nits (follow-up)
README line "The eight unit tests include …" now sits beside the new section's "48 independent cases" wording; the 48 are subtests of one test, which is accurate but could be stated once more explicitly. Wording only.
The mutation-control claim (36 cases fail on the parent's projector) is in the PR body but not reproducible from a committed artifact; I did not re-run it. Not a blocker.
