Summary
Adds a new, tool-agnostic pdrtpy/regularization/ module (neighbor-graph builder, Regularizer base class, FISTA proximal-gradient solver, isotropic/anisotropic Total Variation, and Tikhonov regularizers) for suppressing spurious pixel-to-pixel oscillation in map fits without blurring genuine multi-pixel structure.
Adds LineRatioFit.regularize(method="tv"|"tikhonov", lam, mode, ...): a separate post-run() step that stores results in new density_regularized/radiation_field_regularized attributes without mutating the original fit.
Full design rationale (why isotropic TV over Tikhonov, log-space penalty choice, ExcitationFit reuse-cost analysis for a future integration) is in goals/regularization_design_options.md.
Adds Sphinx docs page (docs/source/pdrtpy.regularization.rst) and plain-language algorithm explainers (docs/chambolle.md, docs/ista.md).
Unit tests in pdrtpy/regularization/test/test_regularization.py (21 tests, including the core scientific claim that TV preserves a multi-pixel edge better than Tikhonov at matched lambda) and integration tests in pdrtpy/tool/test/test_lineratiofit_regularize.py (9 tests against the real SMC/n22 map fixture).
Test plan
uv run pytest -n auto pdrtpy/regularization/test/test_regularization.py pdrtpy/tool/test/test_lineratiofit_regularize.py — 30 tests pass
uv run pytest -n auto — full 361-test suite passes, no regressions
uv run ruff check . / uv run ruff format --check . — clean
uv run sphinx-build docs/source /tmp/build -b html — docs build cleanly, new page renders
More intensive tests of LineRatioFit.regularize() against SMC N22 maps with a known oscillation problem show issues with divergence due to step_mode='per-pixel'. These will be investigated in a different branch/PR. For now, the basic regularization code is algorithmically correct.

Per-pixel stepping avoids a handful of stiff pixels near a degenerate
solution boundary throttling the shared step for the whole map. Fixing
that surfaced a second bug: once unthrottled, weakly-constrained pixels
could drift outside the model's phase-space bounds, where the clipped
data-fidelity gradient is exactly zero, causing unbounded drift. Now
project the proximal-gradient iterate back onto the model bounds after
every step.

Direct A/B test (identical map, same lambda scan) showed step_mode='per_pixel'
diverging by up to -859% at lam=80 while 'global' stayed stable and monotonic
across the same range, saturating at ~43% correction. Root cause traced and
documented in goals/synthetic_regularization_test_findings.md: the TV proximal
solve is not separable across pixels, so one badly-behaved pixel's trial point
can contaminate its neighbors' joint solution in a way the per-pixel descent
check doesn't catch. 'per_pixel' remains available but is now documented as
experimental/unsafe at the lambda values real degenerate data needs, pending a
trust-region or monotone-FISTA-style fix.
