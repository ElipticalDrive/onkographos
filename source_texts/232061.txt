Summary
The two demo_gsplats_2d_* demos render real 2D microscopy images as tiled 2D Gaussian splats. Splatting a flat image amplifies WSI tile-stitching seams (reported in #2910) and isn't the natural representation for a 2D image. These should be re-authored as textured mesh tiles (a tiled surface), which renders a 2D image faithfully — no splat amplification of the seams — and is the representation the viewer gained after these demos were written.
This is a tracking issue for that small programme. Every other gsplats demo is genuinely 3D/4D volumetric data where splats remain the right tool; only these two are 2D images.
Scope
demo_gsplats_2d_cmu1_pathology — CMU-1 H&E whole-slide image (RGB, OpenSlide SVS). Symptom report: CMU-1 demo example has artifacts? #2910. Mesh tiles with a baked RGB texture; mesh LOD for the gigapixel extent.
demo_gsplats_2d_codex_pancreas — 12-channel CODEX multiplexed immunofluorescence (Zenodo). Same idea, but 12 scalar channels rather than RGB: mesh tiles per channel with colormap/scalar texturing, preserving the per-channel layer toggles the current demo exposes.
Approach notes
Textured tiled mesh surface (one quad grid per tile, or a single gridded mesh) carrying the image as a texture / per-vertex-or-texel scalar.
Tile layout should follow the source image tiling so seams render where they actually are, faithfully, instead of being amplified.
Mesh substitutive LOD (luxar mesh lod) for the WSI's scale range.
Open questions (decide during scoping)
Convert in place vs. keep a 2D-splat showcase. The 2D Gaussian-splat authoring path is itself a first-class feature (these demos double as its showcase). Decide whether to convert these two in place, or keep a small synthetic 2D-splat showcase and move the real-image demos to mesh tiles.
CODEX per-channel texturing: colormap-per-channel parity with the current layer behaviour.
Linked symptom: #2910.

I checked this against dev (9308633). The direction makes sense, but two things in the plan are wrong as written, and the scope needs to change before anyone picks this up.
1. The root cause in #2910 is disputed. Draft PR #2920 traced the grid and says the SVS is continuous across the 4096 px fitting-tile boundaries. By that account the seams aren't real stitching that splats amplify. They come from a global post-fit amplitude cull, which removes the low-amplitude Hann-tapered contributions on both sides of each 512 px overlap. With cull_retention=None, a two-tile fit keeps every splat and the overlap MSE drops from 0.0191 to 0.0121. If that holds, moving to mesh tiles is a choice about representation, not a bug fix. It also means the 2D-splat path has a real tiled-fit defect: any 2D tiled fit with default culling will hit it, whatever happens to these demos. That should stay tracked under #2910/#2920 either way.
2. The pipeline this assumes doesn't exist for textured meshes yet:
No textured-mesh LOD. add_mesh refuses texture together with partition / substitutive_lod / additive_lod (core/group/adders/mesh.py:695, tests at core/tests/test_mesh.py:3746-3753). luxar mesh lod drops textures and UVs with a warning (cli/mesh_ops/lod_commands.py:24, :437, :954). So the "mesh substitutive LOD for the WSI's scale range" step can't be done today.
Size limits. Each texture is capped at 16384 px per axis and by the decode budget (validation/base.py:1255, MESH_TEXTURE_DECODE_BUDGET_BYTES). CMU-1 at full resolution is around 46k×33k RGB, so it needs dozens of separate textured nodes. Without LOD or streaming, all of them stay resident at once. The precedent ("tiled globe textures" in the ocean-currents demo) is a few independent nodes, not a pyramid.
No colormaps on scalar textures. A single-channel texture is replicated to grey (materials/mesh/shader-glsl.ts:303, shader-tsl.ts:359). It doesn't go through the colormap/contrast-window path, and meshes default to opaque blending, not additive. The CODEX part can't match the current per-channel colormap + additive layer behaviour without viewer work. Baking RGB per channel would lose interactive contrast.
Proposed split (this issue stays as the tracker):
(a) Textured-mesh LOD: either a texture pyramid on a tiled quad grid, or a way to let substitutive_lod carry per-level textures. This is the real feature and blocks (c) at full resolution.
(b) Colormap + scalar window for single-channel mesh textures, plus additive blending for stacked channel layers. Blocks (d).
(c) CMU-1 on mesh tiles (also fix the H&E colouring noted in CMU-1 demo example has artifacts? #2910).
(d) CODEX on mesh tiles.
Not a duplicate of anything open. #2920 is the only PR that touches this, and it fixes the splat route rather than replacing it. Importance: medium. It's demo and showcase quality, with no correctness or data risk, so I'm not adding priority.
Questions:
Given Preserve CMU-1 tile overlap during refits #2920's finding, do we still convert CMU-1/CODEX in place, or land Preserve CMU-1 tile overlap during refits #2920 (plus a refit and Zenodo repin) and keep the real-image 2D-splat demos as the showcase? A third option: keep a synthetic 2D-splat showcase and add mesh-tile versions as new demos.
Are (a) and (b) in scope as viewer features? Or should (c) settle for a reduced-resolution, non-LOD mesh version (for example ≤16k on the long axis, a handful of tiles) as an interim step?
For CODEX, is baked per-channel RGB acceptable for now, or is interactive per-channel colormap/contrast parity required?

Decision: land #2920 and keep the 2D Gaussian-splat demos — do not convert to mesh tiles.
Your analysis here is the deciding factor: the CMU-1 grid is a post-fit amplitude-cull artifact, not splat-amplified stitching, so this is a bug fix (#2920: cull_retention=None), not a representation problem. Textured-mesh LOD / scalar-texture colormaps don't exist yet, and building them to "fix" a non-bug isn't worth it. The splat path stays.
What happens now:
Preserve CMU-1 tile overlap during refits #2920 marked ready → green → merge (fixes the recipe).
Follow-on (gated on publish-go + compute): refit CMU-1 with the new setting → republish → repin the manifest, so the live demo loses the grid. Until then the published archive is unchanged.
Generalize the cull fix. As noted, any 2D tiled fit with default culling drops the Hann-overlap contributions — a latent defect beyond this demo. Preserve CMU-1 tile overlap during refits #2920 fixes it for CMU-1 via a param; worth a follow-up to change the default behaviour in the tiled-fit path. Tracking that under CMU-1 demo example has artifacts? #2910/Preserve CMU-1 tile overlap during refits #2920.
Closing this tracker — the mesh-tile conversion is not happening; (a)/(b) textured-mesh viewer features are out of scope unless we later want meshes for their own sake. CODEX keeps its per-channel splat layers.
