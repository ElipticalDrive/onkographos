Fix
Forward angular GetColor(phi, theta) to vector GetColor, not GetRadiance. It now returns the model's display color for the converted direction, matching the vector overload. Built-in color output is sRGB, not linear RGB or physical radiance.
Signatures, angular conversion, radiance forwarding and model calculations are unchanged. Model-specific limits and exceptions still apply; no angle validation is added.
Performance
Compared forwarding with explicit direction conversion followed by the corresponding vector method, using a dispatch probe and four sky models. The formerly returned radiance is different behavior, not an equivalent-output baseline.
Across 20 color workloads, paired elapsed/CPU changes initially ranged −13.9% to +9.3%/−16.0% to +12.0%. Eight selected longer repeats ranged −2.2% to −0.8%/−3.7% to −0.6%; conflicting initial results remain. Identical-reference color controls ranged −15.1% to +5.1%/−5.2% to +4.0%; identical-angular controls reached +2.3% elapsed/+5.8% CPU. Radiance controls were also variable.
Every allocation pair matched: probe/CIE/Preetham/XYZ-Hosek 0 B; AlienWorld 2,872 B/query from existing model work. No allocation-saving or stable speedup claim. Kept draft for timing uncertainty.
