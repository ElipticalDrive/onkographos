Emissive & Physical Based Rendering.
Emissive material intensity and value in older generation render engines used to be a basic
color/texture value of 0-1 with an extra multiplier. While this is still somewhat true, the final
rendered pixels are not as straightforward in Exposure driven Physical Based rendering.
Unity HDRP renderer, at the base level, renders the scene in linear HDR with the output
dictated by the exposure system and finally remapped by a tonemapper to produce the final
pixel value.
There are multiple variables that affect emissive rendering:
1. Emissive Intensity.
2. Exposure.
3. Bloom.
4. Tonemapper and various post processes.
This document is targeted to give a clear understanding in achieving predictable emissive
rendering with those first 3 variables taken into account. Any additional post processes are
excluded as they sit on top of the first 3 and can differ significantly from project to project.

Intensity.
Emissive intensity is defined by texture input in material and the Intensity multiplier Unit.
NOTE: All emissive values output here are considered pre tonemapper values.
Texture input
Texture input for emissives is divided into 2 types. LDR 8bit/channel and HDR texture.
HDR texture will always be imported as Linear in Unity and there’s no difference when
enabling/disabling sRGB option in the texture importer as most Image editors store their HDR
image in Linear fashion.
LDR Texture have 2 options for sRGB import settings:
● Checked = Useful to match the look of emissive texture painted in an sRGB painting
software such as photoshop.
● Unchecked = Useful when painting emissive values by the numbers and users expect
linear multiplication between the value you paint in your painting software such as
Photoshop and unity shader intensity.
Disabling sRGB allows direct multiplication of texture value (e.g. 128 value = 0.5).

Intensity Multiplier Unit.
Emissives in HDRP Shaders typical settings.
The higher the number the more energy the emissive output.
Intensity Multiplier or Emission Intensity in HDRP shader can be set in 3 ways:
1. With HDR color picker.
HDR Color Picker allows the user flexibility in specifying each individual channel of RGB
intensity for the emissive color multiplier.
2. Use Emission Intensity with Nits Unit.
This mode utilizes LDR Color picker (0-1 value) which in general is considered to be
easier to understand by the artist with the unit of Nits a linear brightness intensity unit.
3. Use Emission Intensity with EV100 Unit.
Similar to the previous Intensity Multiplier with the difference of EV100 unit, a logarithmic
scale unit.
Which Unit to be used is up to the user(s). In general when Emissive color texture is involved, it
is best to use the Emission intensity to adjust its brightness (Option 2 and 3)..
Unit Conversion.
The two Physical units being discussed here are Nits and EV100:
1. Nits a luminance unit based on a SI Unit of candela per square meter (cd/m²). It is a
measure of light emitted per unit area.
More information about the luminance unit: https://en.wikipedia.org/wiki/Luminance
2. EV100 on the other hand is an exposure number for lighting conditions and its relation
with ISO speed (in EV100 case it’s related to ISO 100).
More information can be found here:
https://en.wikipedia.org/wiki/Exposure_value#Relationship_of_EV_to_lighting_conditions
While both units are based on a different thing, however it is possible to convert it from one unit
to another.
/
Example of a table to convert Nits to EV100 and vice versa:
Nits would be a simple linear multiplication, while EV100 it’s more convenient to adjust emissive
in matching exposure value since it adds up in logarithmic steps.
Example of matching intensity scenario:
A scene exposure is adjusted +2 from the original exposure and emissive intensity is expected
to match the adjusted exposure:
● For Nits, the user is required to multiply the existing value by 2 to the power of 2EV = 4
times.
(e.g. 1 Nits *4 = 4 Nits).
● For EV100, the user simply required to add the existing EV100 unit by 2
(e.g. 3 EV100 + 2 = 5 EV100).
Exposure.
In Physically based lighting rendering Exposure plays a big role for how bright a scene gets
rendered. Similar to lighting, emissive value output is affected by Exposure Value.
We’re not going to deep dive exposure in this doc, but there’s 2 important information need to
be understood in Unity rendering with Exposure value:
1. HDRP Below version 10 exposure system follows the standard of lens imperfection with
constant of 0.65. For more information on film speed saturation
https://en.wikipedia.org/wiki/Film_speed#Saturation-based_speed.
What this means is in a scene with Post process Exposure set 0 and fixed:
a. 1.0 Nits pure white emissive will output a value of 0.8333
b. 1.2 Nits pure white emissive will output a value of 1.0.
This value is relevant in determining the emissive threshold for bloom.
2. Each Fixed Exposure EV step down (-1 stop) doubles the value output of the emissive
and each Fixed Exposure EV step up (+1 stop) half the value of the emissive.

Emissive and Exposure Weight.
In some cases Emissive brightness dictated by Exposure value might not be desirable, such as
certain VFX, UI or other special purposes emissive.
To ignore Exposure altogether, the emissive shader can be set to have a Exposure weight 0
and the emissive output of the material will always maintain its brightness.
Because Exposure weight 0 ignores the exposure system completely, it will bypass the lens
imperfection 0.65 attenuation in rendering the outputting value.
With this in mind an Exposure weight 0 of 1 Nits emissive It will output a value of 1
regardless of Exposure Value.
There are two caveats when setting Exposure weight to 0:
1. Lighting bake will follow the original Emission intensity with lens imperfection calculation
and will not follow the Post Process exposure adjusted emissive value.
NOTE: The lighting bake follows exposure however the emissive remains identical in
any exposure value.
2. If Automatic Exposure is enabled and the “Exposure Weight 0” emissive surface covers
a big portion of the screen, it will pull the exposure to max cap.
NOTE: In general emissives with Exposure weight 1 is the norm when working with physical
based emission.
/
Setting the Exposure weight:
1. HDRP Lit/UnLit.
Shader exposure weight can be set under the material’s emission section.
2. Specific to Unlit shader, a weightless emissive can also be defined directly as base
color, however the color picker is limited to LDR range and emission set in color surface
input will not get taken into account in emission light baking.
It is recommended to work with only one of the input (either Color or Emissive Color) and
not both.
3. Shader Graph.
“Emission node” allows the user to control exposure weight.
/
4. Decal.
HDRP Decal shader comes with Exposure weight when Emissive is enabled.
Alternatively decal can use the Shader graph method.
5. VFX Graph.
By default Unlit Particle VFX nodes behave similar to HDRP Unlit material base color
(Exposure weight 0).
/
For Lit Particle output and other scenarios, please refer to the shader graph method
using the emissive node.

For the bloom post process to work there’s 2 components required,
1. Bloom Filter Post process settings (Threshold and Intensity),
2. The intensity of the pixels on screen itself and the Bloom filter settings.
/
Bloom Filter Settings.
In this Doc we’ll focus on the Threshold and Intensity aspect.
More info for the rest of the options can be found here in the HDRP doc.
Intensity property is pretty straight forward and is used to fade out the amount of resulting
bloom rendered on screen. Threshold however is slightly more complicated.
Threshold for Bloom by default is set to 0.
This takes every value on the scene into account and calculates the bloom effect based on an
energy conservative lens reflection model.
Whether it’s for sharpness reasons or aesthetics, sometimes art direction demands a specific
threshold to mask the bloom based on a value limit on screen that does not follow the energy
conservation rule.
Threshold property works by filtering out any value on screen that are below the threshold to not
be included in the bloom effect rendering.
For example a threshold set to value of 1, requires a pixel on screen to be equal or brighter
than 1 in gamma space to bloom.

Bloom with nonFixed Exposure.
Adaptive/automatic exposure will throw a curveball to pre-defined emissive value and blooms.
Value on the screen just like lighting is governed by the exposure value settings. Final pixel
output will get dimmer and brighter as exposure changes.
It is best to lay out the emissive surface with varied brightness and test it out on all possible
exposure ranges allowed in the project to manage expectation of how each tier behaves in a
given exposure.

Full understanding of the emission and bloom characteristic for each exposure range is useful in
avoiding over blooming of a material due to the tendency of artists to compensate due to
exposure changes.
One final note for adaptive/automatic exposure is to be aware that depending on the size on the
screen, bright emissive surfaces can pull up the exposure darkening the scene.
/
Known issues:
1. Due to some precision issues in HDRP Lit shader, Emissive value will not output exactly
the same number as HDRP Unlit Emissive.
2. Lens attenuation constant 0.65 is not adjustable in HDRP 9 and earlier. In the future it
can be adjusted to 0.78 allowing 1 nits value to output a value of 1 at exposure 0.
3. At the moment emission value is taken into account by the Adaptive/Automatic Exposure
system and there’s no option to remove it..
