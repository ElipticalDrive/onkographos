Summary
Comprehensive visual quality upgrade implementing physically-based rendering (PBR) for environments while maintaining cel-shaded character aesthetics. Introduces procedural noise generation, triplanar terrain mapping, and environment ambience systems across all maps.
Key Changes
Texture & Material System
New src/world/texgen.js: Auto-generate normal maps and roughness maps from canvas textures using Sobel filtering
New src/world/noise.js: Procedural noise toolkit (fBm, ridged, Worley, value noise) with tileable support for texture generation
New src/world/terraintex.js: Shared rock texture generation for consistent cross-map appearance
Enhanced texMaps() function to bundle color, normal, and roughness maps together
Terrain Rendering
New src/world/triplanar.js: Triplanar texture mapping to eliminate stretching on steep slopes by sampling from three world axes instead of UV projection
Automatic material blending based on slope angle (grass on flat terrain, rock on steep slopes)
Quality-aware: triplanar only applies at medium/high quality settings; low quality reverts to single-axis UV
Environment & Ambience
New src/world/ambience.js: Four cheap idle animations (smoke, birds, drifting leaves, banner flutter) using instanced meshes
New src/world/midground.js: Mid-distance scenery layer (terraces, hamlets) to bridge gap between playable area and distant silhouettes
New src/world/imperfect.js: Subtle object perturbation to break up repetitive placement patterns
Color Grading
New src/world/lut.js: Procedural color lookup table generation with temperature, lift/gamma/gain, shadow/highlight tinting, and saturation controls
Per-map color grading without external assets
Character Model Enhancements
New texture-based eye system in src/entities/model.js: Replaces sphere-based eyes with 2D textured planes supporting blink animation
Detailed iris rendering with radial fibers, limbal rings, and dual-layer specular highlights
System Integration
Updated all 8 map files to use new texture and material systems
Enhanced src/entities/villagers.js with schedule-based AI using attractors (markets, lanterns)
Extended src/core/GameCore.js with LUT support and full post-FX chain configuration
Updated src/combat/combat.js and src/world/environment.js for extended functionality
Documentation
Added comprehensive upgrade guides:
專案書/材質與畫質升級書.md: Material system and PBR implementation details
專案書/地圖品質升級書.md: Map quality improvements (7 upgrades)
專案書/角色模型精緻化升級書.md: Character model refinement roadmap
專案書/共用系統整合書V2.md: GameCore unification architecture
專案書/效能優化任務清單.md: Performance optimization priorities
Implementation Details
Procedural generation: All textures generated at load time with deterministic seeding (no external assets)
Performance: Triplanar mapping disabled at low quality; ambience uses fixed-size instanced meshes with object pooling
Compatibility: Canvas texture context now uses { willReadFrequently: true } for better performance
Tileable noise: All noise functions use modulo wrapping for seamless texture tiling
Material consistency: Shared texture generation ensures visual coherence across all 8 maps
Visual Impact
Terrain surfaces now show proper depth and detail at all viewing angles
Character eyes significantly more expressive with procedural iris detail
Environment feels lived-in with subtle ambient motion and mid-distance scenery
Consistent color grading per map region enhances atmosphere
Reduced "tiling" artifacts through multi-octave noise and world-space sampling

新檔 src/world/noise.js —— value noise / fBm / ridged / Worley，全部平鋪安全。
舊的 noise() 是逐像素白噪音，每個像素跟鄰居無關，放大看是「顆粒」不是
「材質」。fBm 有尺度，才像表面。

實作上踩到的兩個坑（都有數值驗證）：

1. hash2 裡寫 `h >> 13` —— 帶號位移會把符號位灌進 bit31，XOR 之後 bit31
   永遠是 0，整個雜湊的值域只剩 0~0.5（實測平均 0.2498、直方圖後半段全空）。
   改成 >>> 之後平均 0.5031、十等分直方圖平坦。
2. period 只決定「在哪重複」，拉長條紋要靠取樣座標的格數不同。
   valueNoise 的 period 因此擴充成可以給 [px, py]，木紋才做得出直向長條
   （實測橫向變化是縱向的 5.16 倍，且貼圖邊界誤差仍為 0）。

各材質依升級書 §2 逐項升級：
- 木 512²：ridged fBm 拉長成年輪、三個節疤把座標往外推成同心圓、
  縱向細裂紋用 2D API 畫（noise 做出來會糊）
- 石 512²：fBm 斑駁 ＋ Worley 顆粒（「一顆一顆」fBm 做不出來）
- 疊石牆 512²：底色改成縫的顏色、磚砌在上面、圓角、每塊磚色調微差
- 瓦 512²：一列之內用 sin 做弧面明暗 ＋ 上緣壓瓦陰影 ＋ 苔痕只長在瓦溝
- 草地 512²：補一層大尺度乾濕斑塊，平鋪時才不會看出一格一格
- 玉砂利：Worley 把散點收成砂礫；榻榻米：藺草粗細不均；
  障子紙：透光不均 ＋ 兩向纖維交織
- 畫法一律改用 rng(seed) 而非 Math.random()，A/B 才有意義

亮度校正（這是重點，用程式讀 canvas 平均亮度比對，不靠眼睛）：

效能：modulate 加 step 選項，512² 只在半解析度粗網格上算 fBm 再雙線性
補回（最後一排取樣 size＝下一塊的 0，平鋪處才不會留縫）。

【4.4 LUT】新檔 src/world/lut.js
不讀 .cube（專案不下載外部資產），改用一組看得懂的參數（色溫、
lift/gamma/gain、飽和、陰影／高光染色）程序烘出查找表。八個地區的
預設值集中在 LUT_PRESETS，改的時候看得到彼此的關係 —— 分散在各張圖裡
的話，調完這張忘了那張，整個世界的色調就散了。

用 2D 條狀 LUT 而不是 Data3DTexture：sampler3D 要 GLSL3，而後製鏈那支
ShaderPass 是 GLSL1。條狀圖用 texture2D 就能取樣，代價只是自己做一次
藍色軸內插。查表時紅色軸要內縮半個像素，否則會滲到隔壁切片，畫面上
會出現一格一格的色塊。

GameCore.gradePass 加 tLut / lutSize / lutMix 三個 uniform 與 core.setLUT()。
gradePass 接在 OutputPass 之後，所以確實是「ACESFilmic 之後再套一層」。

關鍵驗證：**中性 LUT 必須與關閉 LUT 逐像素相同** —— 這是條狀查表寫對了
沒有的唯一硬證據。實測兩者都是 (8,17,28)，完全一致；神社預設則位移到
(11,17,24)（偏暖、藍減少），符合設計。

【4.3 aoMap】texgen.js 新增 aoFromCanvas()
把高度場模糊一次當「周圍的平均高度」，比周圍低的就是凹陷（磚縫、木紋
的溝、瓦楞的谷）。跟 GTAO 互補：GTAO 算幾何之間的遮蔽，這張算表面自己
的細微凹凸，尺度小到 GTAO 的取樣半徑看不到。

兩個必要的細節：
- aoMap.channel = 0。three.js 預設 aoMap 讀 uv1，這個專案的幾何沒有第二組
  UV，不指定的話整張圖會是黑的。
- 依各自的凹陷分佈正規化（取 98 百分位當最深）。原本用固定係數，亮度
  梯度小的貼圖（木、漆）算出來平均 253/255 幾乎全白等於沒做，梯度大的
  （疊石牆）又過頭。正規化後每張都用滿同樣的動態範圍，最暗一致落在
  115，木從 252.9 降到 228.7。

驗證：神社 8 個材質全部掛上 aoMap 且 channel 全對；資料貼圖 16→24 張、
GPU 貼圖 62→71 張，載入時間沒有可測得的變化。aoMap 只影響間接光（three.js
的定義），所以日照處差 1~2、陰影處明顯：強度 0/1/2 分別是
(28,44,56)/(25,39,50)/(21,35,45)。

postFX 天空色那件事。

tapered() 預設 10 → 18；呼叫端顯式段數 14→24、10→20、8→14。
手指（5）、翼骨（6）、羽毛（7）維持不動 —— 那是一公分級的零件，
加段數只是白花面數。球體 18×12→24×16、16×10→20×14、12×8→16×12、
10×8→14×10；8×6 的小飾件維持。裙子圓柱 16→24，滾邊環的徑向 6→10。

視線設計（第 3 點）：三個口的正前方各立一組「門」。

竹林的問題是它**到處長得一樣** —— 一整片等距的垂直線，眼睛沒有地方
可以落。實測從獸道走進來的第一眼就是滿畫面的竹竿，最近的紅布條竹在

兩條窄的。往內傾是必要的 —— 兩根平行的竹子讀起來是柵欄，微微內傾才是
「門」。布幔 2.6×0.75，比沿途路標用的 0.5×0.34 大得多：沿途那些是走近
才讀得出的路標，這一組是隔著距離就要看得見的焦點，工作不一樣。

              上半截倒下去卡在別的竹子上沒有落地 —— 竹子太細太密，
              斷了也倒不下來，這是竹林最典型的樣子。
