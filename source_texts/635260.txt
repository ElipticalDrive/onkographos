Requested by Charles · project thread
Before: GameSdfMotion deformed 2D shapes with a standing wave and pluck packets. That took an extra tick in every host, two vec4s in every material raster entity, and a separate warped custom-shape path that Studio drew.
After: the component and both deformations are gone, and shapes always draw their exact silhouette. Projects saved at version 17 open at version 18 without it.
Merge waldnercharles/chibi-studio#27 first. This PR deletes render/sdf_motion.h and render/sdf_shapes.h, which Studio's main still includes.
How:
Engine. Removed the component, its tick and the hook through world, engine, player_prepared, the player host and the preview runtime. Deleted render/sdf_motion.{c,h}, render/sdf_shapes.{c,h} and their tests.
Selector. Deleted the sdf-coverage GPU selector, which only tested the warped custom shape. Its policy, agent and docs entries went with it.
Raster layout. The material raster entity is now 19 vec4s (it was 21). Draw order moved from wobble[3] to a CPU-only layer field after the parameters, and entity_raster.frag, the fragment-program path and sg_entity follow the new offsets.
Shader graphs. They always receive the shape's object frame, so the "warped means no frame" branch in sg_dispatch_2d is gone.
Migration. Version 18 removes GAME.GameSdfMotion from components, detached, entity and retained components. It stops, leaving the project unchanged, on a .chibi script that names the component or holds its name in a string (has_component(Component: "GAME.GameSdfMotion", ...), struct<"GameSdfMotion">, escaped spellings included, since literals are decoded with yyjson as the analyzer decodes them), and on any other asset that still mentions it once scenes and prototypes drop it. chibi_project_document links chibi_json for that decoding. program_version_17_sdf_motion_is_removed covers each case. All 11 fixture projects are migrated, and Enemy loses its unused motion line.
Studio and Celeste projects don't use the component. Drafts Migrate Studio's projects to version 18 chibi-studio#28 and Migrate the project to version 18 chibi-celeste#4 bump them to 18 after this merges.
Checks run on this branch's head:
make test-short: 6/6.
make test-language-program: 55/55 (2681 asserts), including the migration case.
make test-tools: 87/88. The one failure is the known container case portable_nested_cleanup_preserves_sibling (test_policy.c:179).
make package-sdk, then chibi-studio#27 built against that SDK with make studio-build.
make agent-gpu-test passed for --interior-border, --sdf-visibility, --material-ramps, --scene3d and --scene3d-gles on lavapipe and Mesa GLES under Xvfb (on the first commit; later commits only touch the migration).
tool render-resources: 10/10.
A preview of the sprites fixture renders as before.
The unbuilt test/sdf_spatial.c and test/mesh_material.c were syntax-checked against the new layout.
Full native and render suites stay quarantined and were not run.
