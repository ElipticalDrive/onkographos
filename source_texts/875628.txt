**This PR changes the output of DomainWarpSimplex and DomainWarpSuperSimplex for every seed.** It covers both Vectorization Schemes in 2D, 3D and 4D, except GradientOuterProduct 3D, which stays bit-identical. Everything built on these nodes changes too. Every other node, DomainWarpGradient included, is bit-identical to the base branch. There is no API, metadata or node layout change: encoded node trees still load, they just generate a different warp. **It builds on the domain warp PR** and is one commit on top of it (see Dependencies). Target branch: `perf-seeding`.

## What changes in the noise

The domain warp PR builds each simplex vertex's warp vector from a few hash bits: table indices, sign flips and matrix choices. Those bits came from `HashPrimes`, which is `h ^ ( h >> 15 )` with `h = ( seed ^ primed position ) * A`, and in 3D/4D mostly from its low end (bits 0-9). The low bits of a product only depend on the low bits of its input, and the xorshift only partly fixes that.

This PR changes two things:
- **The vertex hash is `HashPrimesHB`**, which is `h` itself (no xorshift).
- **Every consumed bit comes from bits 21-31**, the well-mixed top of the product.

The vector sets, the scaling constants and the warp strength are unchanged. Only the choice of vector at each vertex changes.

| Warp | bits before (of the xorshifted hash) | bits after (of `h`) |
|---|---|---|
| OrthogonalGradientMatrix 2D (D8) | rotation 28-30, reflection 0 | rotation 28-30, reflection 31 |
| GradientOuterProduct 2D | gradient 28-30, outer vector 25-27 | gradient 29-31, outer vector 26-28 |
| OrthogonalGradientMatrix 3D | z sign 0, mix 4, output signs 1-3, axis rotation from `( hash >> 1 ) * 3` | z sign 21, mix 22, output signs 23-25, axis rotation from two signed compares of the whole hash (thirds of the range) |
| OrthogonalGradientMatrix 4D | w sign 0, mix 5, output signs 1-4, pair swap 29, adjacent swap 30 | w sign 21, output signs 22-25, mix 29, pair swap 30, adjacent swap 31 |
| GradientOuterProduct 4D | gradient 0-4, outer vector 5-9 | gradient 27-31, outer vector 22-26 |
| GradientOuterProduct 3D | unchanged: keeps `HashPrimes`, its decode multiplies the hash | unchanged |

Bits are moved down with a right shift before any left shift (`( hash >> 21 ) << k`). This keeps the compiler from turning a left shift of `hash * A` into an extra multiply (except in SSE4.1 2D, see Speed). The AArch64 TBL lookups mask their 3-bit indices, because TBL reads 0 past the table.

Changed output:
- DomainWarpSimplex: OrthogonalGradientMatrix (the default) 2D/3D/4D, GradientOuterProduct 2D/4D.
- DomainWarpSuperSimplex: the same configs.
- Everything built on them:
  - DomainWarpFractalProgressive and DomainWarpFractalIndependent over a (Super)Simplex warp.
  - Node trees such as the MountainTerrain demo.
  - `GenTileable2D` output of these nodes, because tileable 2D samples the 4D warp.

For the same seed and source, the output after this change correlates with the output before it at r = 0.49-0.86 (16 seeds). The source is the same and the warp is different. Every output stays within the source's range ([-1, 1] for the Simplex source used in the tests).

## Why

**Quality.** Three things, all measured below:
1. **The 4D GradientOuterProduct warp no longer reuses its source's gradients.** With the base, this warp takes its gradient from `GetGradientDotPerlin( HashPrimes( seed, vertex ) )`. That is exactly the gradient term of a Simplex 4D source at the same vertex whenever the warp and the source share seed and feature scale, which is the default setup. The warp vector is then built from the source's own per-vertex contributions. With a Simplex source this lowers the output sd from 0.293 to 0.268 (DomainWarpSimplex) and from 0.297 to 0.280 (DomainWarpSuperSimplex). With this PR the gradient comes from different hash bits. The output sd is 0.292 / 0.297, the same as an ideal hash gives.
2. **No more dead or weak seed bits in 3D/4D.** With the base, the 4D GradientOuterProduct warp ignores seed bits 25-31 completely. In the 3D/4D orthogonal matrix warps, seed bits 23 and 24 change only 29-85% of the samples. After this PR every seed bit changes at least 91% of the samples in 3D and 4D.
3. **Less structure in the consumed bits.** The lattice correlation of the bit windows the warps read drops to near the independent level (below).

**Speed.** One integer xorshift (shift + xor) less per vertex hash. With clang-cl 23 nearly every changed Warp function has fewer instructions, and the 32-bit multiply count per point is unchanged except in SSE4.1 2D (see Speed).

### Seeds

| Simplex / SuperSimplex GradientOuterProduct 2D | 95% / 98% | 84% / 92% (bit 1) | 99% / 100% |
| Simplex / SuperSimplex OrthogonalGradientMatrix 3D | **29% / 38%** (bits 23-25) | 91% / 98% | 100% / 100% |

| GradientOuterProduct 3D (unchanged) | 99% / 100% | 99% / 100% | 100% / 100% |

2D loses a little on a few seed bits. Seed bit k moves the product by 2^k·A mod 2^32. For a few k that step is close to a multiple of 2^32 in the top bits, so the top 4 bits rarely change. The seeding PR premixes the API seed with fmix32 before it reaches any hash. On a merge of the two branches, every seed bit changes 99-100% of the samples in every config.

### Hash bits

Bit-window test on the integer lattice, as the generators feed the hash. It uses the bits each warp reads, in sliding 4-bit windows. The pair statistic is the chi²/dof of the joint distribution of a lattice point and an offset neighbour, as the worst and average over offsets. About 1 means independent. FFT max is the largest bin of the 2D lattice power spectrum (about 15 for white noise).

| Warp | pair worst, before → after | pair average | FFT max |
|---|---|---|---|
| OrthogonalGradientMatrix 2D | 22.7 → 3.5 | 2.07 → 1.23 | 17.3 → 15.1 |
| GradientOuterProduct 2D | 3.1 → 3.6 | 1.21 → 1.28 | 14.4 → 14.9 |
| OrthogonalGradientMatrix 3D | 68.7 → 35.9 | 5.10 → 1.52 | 19.0 → 14.4 |
| OrthogonalGradientMatrix 4D | 68.7 → 33.2 | 4.45 → 1.41 | 19.4 → 14.6 |
| GradientOuterProduct 4D | 68.7 → 4.4 | 3.94 → 1.33 | 21.3 → 15.0 |

With offsets along a third lattice axis, the worst pair is 170-210 both before and after, at offsets of 64 and 256. That comes from the lattice key (the xor of the primed coordinates), not from which bits are read.

**One known imperfection: OrthogonalGradientMatrix 3D.** Its axis rotation is the hash's third of the 32-bit range, and its other five choices sit in bits 21-25. 2^32 / 3 is not a multiple of 2^26, so the 96 combinations of rotation and those five bits are not exactly equally likely: each is within -1.6% / +3.1% of uniform (exact count over all 2^32 hashes). The joint-histogram test shows this (5.4-6.5 against about 1 before). It is a fixed property of the decode, not of the hash, and none of the warp or output statistics below can see it.
