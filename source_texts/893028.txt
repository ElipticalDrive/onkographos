A "small" PR containing changes made during some tests with EA FC27. Hi everyone, sorry for the delay. My earlier explanation wasn't detailed enough.
I was testing the Kick Off mode on EA FC27 on SteamOS.
After selecting Kick Off and trying to enter the mode, the game would close. During the investigation I also encountered problems with the main menu rendering, the pre-match events and so on.
The changes accumulated while investigating those failures. With the combined changes, I eventually played a full match, but I can't claim that every remaining change is necessary.
Here is the reasoning behind the changes:
S_SETPC selector reuse: the shader translation rejected a jump-table pattern where the table load overwrites its selector register. After that fix, the previously failing shader completed SPIR-V emission. Thanks @Nmzik for integrating it and crediting me.
UMax and OR reductions: I extended the existing UMin matcher to cover the equivalent maximum and OR sequences, avoiding dependence on endpoint lanes that may be absent during fragment execution. At that stage of the investigation, the branch progressed past the previously hanging pipelines and then encountered a separate mip-count validation error involving a 64×64 texture. (This was mainly happening after clicking on "Kick-Off", during the loading of the next menus)
Mip views: the change represents selected guest mip levels within Vulkan's limits while preserving their original memory offsets, array strides and mip-tail layout.(This was happening mainly before the rendering of the match or right after the teams were selected)
Texture-cache identity: this concerns cached texture images, rather than the shader cache. While reviewing the mip-view changes, I added a regression where two different extra mips become 1×1 host images. The cache considered them interchangeable despite their different physical layouts. That test failed before the fix and passed afterward, but I haven't demonstrated that this collision caused the Kick Off crash.
BDA handling: these changes reject invalid guest addresses before page-table lookup and initialize the page-table and fault storage before GPU use. They address memory-handling cases found during the investigation, but I haven't isolated their individual effect on FC27.
Compressed 3D textures: this adds a fallback when a driver supports sampled compressed volumes without extended usage. This also needs an isolated reproduction against current main before I can justify it as an FC27 requirement.
@Nawid3333, thanks for pointing out the overlap with #1570. I'm fine with separating the reduction changes and using your broader implementation if that's preferred.
I am far from being a C++ developer, but I am curious enough to try to put some code together, test and compare between the attempts.
Let me know if you need more clarification.

```
Recompiler changes from the NHL 27 (PPSA34063) investigation:

- Translation speed (SPIR-V output unchanged, checked per shader hash):
  constant propagation keeps a location table on a borrowed per-instruction
  slot, ReplaceUsesWith detaches whole use lists, SSA rewrite uses per-block
  flag values and open-addressing definitions, ValidateProgram uses a
  dominator tree with DFS intervals and can be skipped with
  KYTY_IR_VALIDATE=0, IR nodes come from a thread-local pool
  (ir/PoolAllocator.h). Translation about -33% on NHL 27's shaders.
- Dense SRT walker: each resource plan is compiled once into a compact node
  array and walked with the same lazy algorithm (memo, contexts, fixpoint,
  short-circuits). KYTY_SRT_DENSE=1 enables it; KYTY_SRT_DENSE_VERIFY=full
  runs dense and the old walker on every control-flow refresh and compares
  every output (verified exact over ~5 M refreshes in game).
  KYTY_SRT_DENSE_ALTERNATE=<s> switches it per time window for in-match A/B
  measurements (~7-9% shorter frame intervals in NHL 27). Mirrors upstream's
  removal of IAddCarry32/IMul64/UndefU8/16/64 and the saturating
  ConvertU32F32.
- SRT experiments kept behind switches: branch conditions on GPU-written
  bytes may take both successors (KYTY_SRT_BRANCH_BOTH), slot cache and
  context index, diagnostics ([srtcf], [walkkind]).
- Includes parts of open pull requests KytyPS5#1288 (GPU indirect draws), KytyPS5#1693
  (SPIR-V reductions, BDA safety, mip views) and KytyPS5#1733 (depth-compare sampler
  variants) where they touch the recompiler.

The dense walker was first written by GLM 5.3 and fixed/validated with
Claude; intermediate commits on this branch are not built individually.
```
