What changed
Every view that runs motion blur now gets a per-object velocity buffer: an Rg16Float texture at full view resolution, written by the opaque forward pass as a second colour attachment. Each pixel holds ndc_now.xy - ndc_prev.xy for the surface under it, built from the drawing camera's last-frame view-projection and the entity's last-frame world matrix and joint palette. This is the groundwork #1436 (the blur that reads it) builds on.
render::motion (new module): MotionVectors (the target, allocated only while active; lives in PostFx, so it is per view and render-texture cameras keep their own) and MotionHistory (each stacked camera's last view_proj, kept by the camera's entity, and each drawn entity's Pose { model, palette }; an entity with no opaque draw keeps none). A frame reads last frame's poses and records its own, swapped at the end of the stack, so every camera of a stack reprojects one entity from the same pose.
Shaders. shader.wgsl gains vs_velocity / fs_velocity. The fragment body moved into fn surface_color(in) -> vec4 that both fs_main and fs_velocity call, so authored surface variants (whose blocks are spliced into that body) carry their look into the velocity pipeline. forward::bindings::vertex_to_world_prev skins with last frame's palette under last frame's matrix. CameraUniforms gains prev_view_proj. The two sky shaders write sky::motion::sky_velocity, the camera rotation alone (a direction reprojected, w = 0), into location 1. The new sky/motion.wgsl module holds that and the SkyTargets output struct.
Instance data. InstanceData gains prev_model_matrix, prev_bone_base and a motion flag (+80 bytes). motion == 0 (InstanceData::IDENTITY, every mesh particle, any first draw) moves the vertex with the camera only, so a constructor that forgets the field can't produce garbage motion.
Pipelines. The standard forward pipeline, each surface variant and both sky pipelines get a velocity twin. All are LazyPipelines listed in Renderer::lazy_pipelines, so headless tests compile them only when they draw them and a windowed renderer warms them. A surface module now needs vs_velocity / fs_velocity as it needs vs_main / fs_main: one without them is logged once and drawn with the standard pipeline (every bake of the forward shader has them).
Stacks. Each camera writes velocity with its own matrices. The velocity attachment clears where the colour clears and loads where a DepthOnly camera composites, so the nearest camera's velocity wins the way its colour does. A viewmodel camera's gun, turning with its camera, writes ~0.
Cuts. The history is keyed by HistoryKey::new(scene, base): (SceneId, base camera entity, play state). A scene load, a base-camera switch, Play or Stop (Stop restores the edit scene under the same SceneId, so the play state is what marks it) starts over, and so does a resize (PostFx::resize). Each camera's last matrix is kept by its entity, not its place in the stack, so a viewmodel camera swapped in at the same place (a weapon switch) has no last frame. A camera with no history uses its current matrix as last frame's. StackPass now carries entities (each camera's entity: ScreenStack::entities, None for the editor's free camera) and base_id (main_camera in either mode; a render texture's own camera id).
Gating. motion::wanted = the stack's full_post_fx && postfx::params::motion_blur_enabled (the camera has motion blur on and the tier allows it). build_post_params now reads the same predicate. A view with a forward override (the Inspector shader preview) writes none. On any other frame the forward pass draws through the unchanged pipelines and the target is freed: Low pays nothing.
Debug.Stats().velocity_passes: opaque passes that wrote velocity (one per stacked camera of each such view). Documented in docs/api/Debug.md; docs/api/Graphics.md gains a Motion vectors paragraph.
Post-FX's existing camera-only motion blur now takes last frame's matrix from the same history, replacing PostFx::prev_view_proj.
Why
Motion blur is camera-only today. Anything that moves while the camera is still (an enemy sprinting past, a melee swing, a ragdoll) never blurs. And because post-FX runs once over the composited stack, a first-person viewmodel smears like world geometry whenever the player turns. Trepang2-class shooters keep the weapon crisp and blur the world and the enemies; a per-object velocity buffer is the standard way to get that.
Effect
No pixel change on any frame that does not run motion blur: fs_main returns the same surface_color body, and the sky shaders' colour output is unchanged. With motion blur on, two behaviours change (both fixes):
The first frame of a view no longer reprojects through an identity matrix. prev_view_proj used to start as IDENTITY, which smeared the first blurred frame.
A cut (scene load, camera switch, resize) no longer smears.
Nothing reads the velocity target yet; Per-object motion blur: reconstruction filter (TileMax/NeighborMax) over the velocity buffer #1436 binds it.
Decisions
Teleports follow Unity: no distance heuristic. History resets only on a first draw, a scene load, Play or Stop (as Unity's scene reload), a camera cut (base-camera switch, a camera entity new to the stack), a resize, or an explicit MotionVectors::reset (Rust). The script-facing reset (Renderer.ResetMotionVectors-like) is left out because it would add to the API surface. File it when a game needs it.
No history for entities that weren't drawn last frame (frustum-culled, hidden). An enemy stepping into view moves with the camera only for its first visible frame. Tracking every entity, drawn or not, would cost a world-matrix walk per mesh entity per frame.
Mesh particles ride the opaque pass, so they write camera-only velocity. Sprite particles, ribbons, transparents, decals and UI write none (Unity's default).
An orthographic camera's sky writes 0 (directions don't move under an ortho lens).
A surface variant's velocity pipeline is built on first use, not warmed. Turning motion blur on mid-game compiles one per variant on screen (the standard and sky velocity pipelines are warmed).
No compatibility shim for surface modules baked before this change (CLAUDE.md, No backward compatibility): the old empty-mask fallback left an opaque wall's pixels holding the velocity of whatever was drawn behind it. Such a module falls back to the standard shader until re-baked.

Tests
render::motion::gpu_tests (lavapipe):
A cube moving past a still camera writes its exact projected step, ±0.01 NDC; got 0.4023 vs 0.4024. The sky beside it writes 0.
A still scene under a turning camera matches camera-only reprojection on the cube (−0.09491 vs −0.09489) and on a sky pixel (±0.005).
No motion blur, or the Low tier: no target, velocity_passes == 0.
render::motion::stack_gpu_tests (lavapipe):
A skinned mesh with two boxes on two joints: the still bone writes 0; the moved bone writes its projected step (0.1016 vs 0.1017).
Viewmodel: a world camera plus a DepthOnly overlay camera with a child cube, turned together. The gun writes ~2e-7 and the world −0.154; velocity_passes == 2.
The first frame after a scene load (renew_id) writes no object motion.
render::motion::cut_tests (adapter-free): Play and Stop are cuts though the SceneId is kept; a camera swapped in at another's stack place gets no last frame.
render::camera_tests: ScreenStack::entities in play and edit mode.
render::motion::tests (adapter-free): camera history and cuts, pose lifetime, track (last palette appended; a palette of another length keeps this frame's skin), the gate, and InstanceData's size.

Seam (for #1436)
view.post_fx.motion.active_target() -> Option<&PfxTarget> is the velocity texture written this frame (TEXTURE_BINDING | COPY_SRC, motion::VELOCITY_FORMAT = Rg16Float, NDC units, now - prev). It returns None when the view runs no motion blur. target_view() returns its view.
The target is written in each camera's scene pass, before run_post_fx, so post-FX can bind it.
postfx::params::motion_blur_enabled(post, quality) is the one predicate for "this view blurs"; the target exists exactly when it holds (and full_post_fx, and no forward override).
motion::HistoryKey::new(scene, base) is the one place a cut is defined; MotionVectors::reset() forces one.
CameraCtx::base_prev_view_proj holds the base camera's last-frame matrix, reset on cuts. Camera-only reprojection (PostParams::prev_view_proj) already reads it.

A fresh reviewer at medium level (renderer; no stored format or determinism). 8 findings, each checked against the code. All were sent back to the coder (re-brief on the issue):
A compatibility shim for surface variants without velocity entries, which also writes stale velocity under an opaque wall.

Stop isn't treated as a cut: a one-frame smear on the first edit frame.
base_id / HistoryKey::base docs describe None wrongly.
Stale shader-function names in module docs.

Per-frame map regrowth and palette clones.
