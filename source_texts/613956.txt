First render of the forest is about 2× faster, and chunk baking no longer touches the DOM or per-voxel objects. This is the data layout a later worker or Rust/WASM port needs.
Changes
VoxelGrid (new src/lib/voxel-grid.ts): one material id byte per cell of a box, 0 for empty, laid out z-major. A slice is one contiguous range, and neighbours are fixed offsets. The forest generates straight into it. A Voxel[] list is built only on request (reference viewer, tests).
bake.ts works on flat typed arrays only:
sliceSurface: a slice's surface voxels as int records, grouped by chunk cell, far to near.
chunkFaces: walks the cell and its eight neighbours one z at a time, so painting order needs no sort.
fillFaces / fillQuad: fill pixels from a per-material, per-face palette instead of parsing a colour string for every face.
renderer.ts: only creates and positions canvases. Layer.voxels becomes Layer.voxelCount.

The scene is pixel-identical to main (UI panel excluded). Frame time while moving is bound by compositing ~1,100 canvases, not by JavaScript. The next step for that is WebGL compositing.
The one visible difference: overlapping side faces at the same depth are now painted in a different order. This changed 7 pixels in one layer thumbnail, and those faces are hidden in the composited view.
Tests
New brute-force reference test for sliceSurface. I checked that it fails when the near-plane rule is broken.
The leak-bound ray-cast test now runs on the real sliceSurface / chunkFaces instead of a copy of the old face logic.
Removed the test for World.getVoxelsInZRange, which no longer exists.
pnpm lint, typecheck, test (491), knip, knip:production and build pass.
Docs updated: DESIGN.md (sections 3 and 6), TESTING.md, AGENTS.md (source layout), PRD.md (open ideas).
