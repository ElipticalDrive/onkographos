Summary
This is primarily an engine capability PR: it builds out a first-class compute subsystem on the Vulkan backend and integrates it into the render graph. Froxel volumetric fog in the VulkanSponza demo is the first real consumer that proves the path end-to-end — but the durable value is the compute layer, not the fog visual.
Engine capabilities
Compute shader programs + pipelines — CreateComputeShaderProgramFromSpv and CreateComputePipeline (vkCreateComputePipelines, compute stage, shared pipeline-layout builder with the graphics path).
Compute passes in the command model — DispatchCommand, RenderCommandList.ComputePass, and a Compute flag on RenderPassDescription. Executed outside a render pass with explicit storage-image barriers and bind-point-aware descriptor binding (storage in GENERAL, sampled in SHADER_READ_ONLY).
Graph-native compute — RenderGraph.Dispatch(passHandle, DispatchCommand) records a compute pass's work; Execute emits it in declaration order, so a compute pass declared before a graphics pass that samples its output runs first. Graphics subpass dependencies now include ComputeShaderBit on both edges, so a downstream compute pass can sample a pass's colour/depth output (and a prior compute read is ordered ahead of a rewrite) with no manual barrier.
Storage images + 3D textures — CreateStorageTexture2D/3D, CreateTexture3D (ImageType.Type3D). No-upload storage targets are left in ShaderReadOnlyOptimal so they're valid to bind as sampled before their first compute write.
Contract enforcement — the OpenGL backend rejects compute passes with a clear error; compute passes may contain only DispatchCommands and graphics passes none; compute pipelines can't be bound for a draw and graphics pipelines can't be bound for a dispatch; RenderGraph.Dispatch rejects a non-compute pass handle.
Demo: froxel volumetric fog (VulkanSponza)
A 128×72×48 RGBA16F view-aligned grid (3D storage texture). A single fused compute pass — declared between the cascade passes and the lit pass — marches each screen column front-to-back, accumulating shadow-aware sun in-scattering (samples the cascade maps, Henyey-Greenstein phase) and Beer-Lambert transmittance. Each slice stores the integrated result, so the lit pass composites with one trilinear fetch: color·transmittance + inScatter. World reconstruction via the camera inverse view-projection, so the clip-Y flip is handled for free and the grid aligns with gl_FragCoord.
Off by default (it adds a per-frame compute pass): launch with --fog, or toggle live in the overlay Fog scope (density / scatter / phase g / ambient / far). --fog-stress auto-toggles fog to exercise the enabled↔disabled barrier transitions under validation.
Validation
Run via tools/run-vulkan-sponza.sh (macOS/MoltenVK; the window can't be screenshotted, so correctness is verified via validation-layer-clean logs). Clean (frame-errors 0, no VUID) in all configurations: fog off (default), fog on, and the on/off stress toggle. Resize is correct by construction — the grid is a fixed resolution independent of the swapchain, and the composite uses the live frame dimensions for screen-UV.
Known limitations (v1, marked in code)
Depth slices are linear in world distance; logarithmic/exponential distribution would give better near-camera quality per slice.
Shadow lookup in the fog is a single cascade texel with a fixed bias (no PCF) — fine while validating the pipeline; widen to a small PCF kernel if shafts shimmer.
Grid resolution is fixed; it should become a renderer quality preset (quarter/half/full) since the z-march cost scales with it.
The sky doesn't receive fog (lit geometry only), so there's a faint boundary at the atrium opening.

…

```
The shadow pass allocated ~1100 push byte[]s + ~600 mask binding objects
every frame; the resulting gen0 GC showed up as build-commands spikes
(1.6ms baseline → 3.5-7.6ms on ~quarter of frames) and stretched the
correlated execute time. Reduce hot-path allocations from ~1700 to ~35/frame:

  record time, so a buffer frees once the frame's commands are recorded).
- Cache passBindings + identityPush as load-time fields.

Functionally identical; validation-clean. Average FPS remains GPU-bound
(Intel Sponza ~11.5M tris drawn 4x/frame) — addressed separately.
```

vulkan-sponza: cache shadow cascades, skip redraw when VP unchanged
…
52d7d4c
```
The 3 shadow cascades redrew the full ~11.5M-tri scene every frame even
when nothing moved — the dominant GPU cost and the source of the frame-time
swing. Cache each cascade's depth map: a texel-snapped cascade VP is
bit-identical frame-to-frame while the camera + sun + splits hold (and for
sub-texel camera moves, thanks to the snap), so skip re-recording an
unchanged cascade's pass entirely. The depth target is persistent and stays
in ShaderReadOnlyOptimal, which is exactly what the lit pass samples; when a
cascade does change, its attachment InitialLayout=Undefined accepts the
prior layout, so re-rendering is hazard-free. Shadows-off also skips the
passes (the lit shader early-outs) and invalidates the cache.

Measured (static camera, headless): execute 26-46ms -> 19.5-22.9ms,
build-commands 1.6-7.6ms -> ~0.4ms, frame ~30ms -> ~22ms, validation-clean
(frame-errors 0). Moving re-renders only the cascades whose snapped VP
actually shifted (near changes most; far often stays cached).

Overlay shows a per-cascade cache indicator (R = rendered, · = cached).
```
