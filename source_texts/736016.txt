# Godot 2D World Generator

A performant, seed-based infinite world generation system for Godot 4, built around weighted Voronoi biome placement, domain-warped noise, and chunk streaming.

![Map Generation](map%20generation.png)

---

## Features

- **Infinite procedural world** — chunks generated on demand as the player moves
- **Weighted Voronoi biomes** — organic biome shapes with configurable size and frequency
- **Domain warp** — single-layer FBM warp for natural, non-grid biome borders
- **Neighbor restrictions** — per-biome control over which biomes can appear adjacent
- **Terrain variation** — optional secondary tile mixed into any biome via noise threshold
- **Object spawning** — noise-driven object placement with per-biome spawn tables
- **Mob spawning** — configurable mob tables per biome with passive/aggressive behavior
- **Drop system** — items dropped by mobs and destructible objects with min/max amounts and chance
- **Multi-layer caching** — ping-pong biome tile cache, nearby-points cache, and Voronoi region cache for consistent frame times
- **Deterministic** — same seed always produces the same world

---

## File Overview

| File | Description |
|---|---|
| `world_generator.gd` | Core generation logic: Voronoi placement, noise warp, chunk building, object spawning |
| `world_manager.gd` | Chunk streaming: load/unload queue, render distance, per-frame budget |
| `biome_resource.gd` | Resource definition for a biome: tiles, size, weight, neighbors, objects, mobs |
| `object_resource.gd` | Resource definition for a spawnable object: scene, HP, tool, drops, respawn |
| `mob_resource.gd` | Resource definition for a mob: stats, aggro, spawn chance, drops |
| `drop_resource.gd` | Resource definition for a single drop: item ID, amount range, chance |

## Setup

1. Add a `WorldManager` node to your scene.
2. Attach the following child nodes with the exact names:
   - `TileMap` — a `TileMapLayer` with your TileSet configured
   - `Player` — a `CharacterBody2D`
   - `ObjectsLayer` — a `Node2D` for spawned objects
3. In the `WorldManager` inspector, set `tile_size` to match your TileSet tile size (e.g. `16`).
4. Create `.tres` files for each biome using `BiomeResource` and add them to the `biomes` array.
5. Set a `world_seed` (any integer — same seed = same world).

## Creating a Biome

Right-click in the FileSystem → **New Resource** → select `BiomeResource`.

| Property | Description |
|---|---|
| `biome_id` | Unique lowercase string, e.g. `"forest"`. Used by `allowed_neighbors`. |
| `weight` | Relative spawn frequency. Higher = more common. |
| `min_biome_size` / `max_biome_size` | Radius range in tiles for each biome zone. |
| `allowed_neighbors` | Leave empty to allow any neighbor. Add biome IDs to restrict. |
| `ground_tile` | Atlas coordinates of the main tile in your TileSet. |
| `has_terrain_variation` | Mix a second tile into the biome via noise. |
| `objects` | Array of `ObjectResource` — trees, rocks, etc. |
| `mobs` | Array of `MobResource` — animals, enemies, etc. |

## Creating an Object

> ⚠️ **Work in progress.** The resource definition exists but the object interaction system (harvesting, HP, tool check, respawn) is not yet implemented. The fields below are defined and ready to be wired up.

Right-click → **New Resource** → `ObjectResource`.

- Assign a `.tscn` scene (must have `Node2D` as root with sprite and collision).
- Set `spawn_chance` (e.g. `0.05` = roughly 1 in 20 tiles).
- Set `max_hp` to `0` for indestructible decor.
- Add `DropResource` entries to `drops`.

---

## Creating a Mob

> ⚠️ **Work in progress.** The resource definition exists but the mob AI (movement, aggro, combat, death) is not yet implemented. The fields below are defined and ready to be wired up.

Right-click → **New Resource** → `MobResource`.

- Assign a `.tscn` scene (must have `CharacterBody2D` as root).
- Set `aggro_range` to `0` for a fully passive mob.
- Set `is_passive = true` for mobs that only fight back when hit.
- Add `DropResource` entries to `drops`.

---

## Drop System

> ⚠️ **Work in progress.** `DropResource` is defined but the inventory and item system that receives drops is not yet implemented.

Right-click → **New Resource** → `DropResource`.

- Set `item_id` to match your inventory system (e.g. `"wood"`, `"stone"`).
- Set `min_amount` / `max_amount` for a random quantity range.
- Set `chance` between `0.0` and `1.0` (`1.0` = always drops, `0.1` = 10% chance).

## WorldManager Properties

| Property | Default | Description |
|---|---|---|
| `tile_size` | `16` | Tile size in pixels. Must match your TileSet. |
| `render_distance` | `3` | Chunks loaded in each direction. 3 = 7×7 grid. |
| `chunks_per_frame` | `3` | Max chunks generated per frame. Lower = smoother. |
| `world_seed` | `12345` | World seed. Same value always generates the same world. |

## Performance Notes

- `render_distance` of 3–5 is recommended for most cases.
- `chunks_per_frame` of 2–4 avoids frame spikes on chunk transitions.
- The biome cache holds up to 4096 tiles (ping-pong eviction). The Voronoi region cache holds up to 512 regions (~50 KB). Both are cleared and rebuilt deterministically — no data loss.
- Region size is automatically snapped to the nearest power of two based on average biome size, enabling fast bitwise region lookups.
