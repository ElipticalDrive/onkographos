概要
SceneSync Web側では、各種3DGS形式を KHR_gaussian_splatting を含むGLBへ正規化し、Editor / Export Viewerで描画できるようになった（#534, #535）。
次の段階として、Unity版 / Godot版SceneSyncでも KHR_gaussian_splatting GLBを3DGSの共通受け渡し形式として扱えるようにする。
対象はRuntimeでのロードだけではなく、Unity Editor / Godot Editorでの読み込み・配置・編集も含む。
各エンジン側で .sog / .spz / .lcc2 / .splat / .ksplat などのparserを個別実装するのではなく、SceneSync側で正規化済みのGLBを受け取り、各エンジンのGaussian Splat renderer / loaderへ渡す方針とする。
```
PLY / SPZ / SOG / LCC2 / LCC / SPLAT / KSPLAT
                    ↓
              SceneSync Web
                    ↓
       KHR_gaussian_splatting GLB
              ↙             ↘
           Unity            Godot
         Editor/Runtime   Editor/Runtime
```
方針
SceneSyncの3DGS交換形式は KHR_gaussian_splatting GLB に統一する
Unity / Godot側に元3DGS形式ごとのparserは持たせない
Editor-time importとRuntime loadの両方をサポートする
Editor / Runtimeで可能な限り同じGaussian Splat表現・rendererを利用する
SceneSync経由のRuntimeロードは既存のGLB同期・asset cache・SceneDocument経路をそのまま利用する
GLBロード時に KHR_gaussian_splatting を検出した場合のみGaussian Splat用rendererへ渡す
Transform / visibility / delete / Undo / Redo /同期は通常GLBと同じSceneSyncオブジェクトとして扱う
Web / Unity / Godotで同一GLBを共有できることを目標にする
Editorでの読み込み
Editor上でも KHR_gaussian_splatting GLBを読み込み、その場でGaussian Splatとして確認・配置できるようにする。
期待するUX:
GLBをProject / File dialog / D&D等から読み込める
読み込み直後からScene/Game相当のビューでGaussian Splatとして表示できる
position / rotation / scale / visibilityをEditor上で編集できる
保存・再オープン後も参照が維持される
通常Mesh GLBとGaussian Splat GLBを同一シーンで扱える
SceneSyncへ接続した場合、そのオブジェクトを通常GLBと同様のSceneSyncオブジェクトとして扱える
ネイティブAssetImporterにするか、SceneSync専用のImport UI / component経由にするかは、各ライブラリの構成に合わせて決める。「Editorで確認するために一度Runtimeを起動する必要がある」状態にはしない。

godot-gsplat 本体は MIT License。
直接依存している godot crate（godot-rust / gdext）は MPL-2.0。
MPL-2.0はfile-level copyleftなので、通常の依存利用によってScene-Sync-Godot全体へcopyleftが伝播するものではない。
方針:
godot-gsplatのcopyright / MIT noticeを保持する
godot-rust / gdextのMPL-2.0 noticeを配布物に含める
godot-rust本体は原則fork / 改変せずupstreamをそのまま利用する
やむを得ずMPL対象ファイルを改変して配布する場合、その改変したMPL対象ファイルについてソース提供義務を満たす
Scene-Sync-Godot独自コードとMPL対象コードの境界を維持する
dependency追加時はGPL / AGPL等の強いcopyleftが混入していないか再確認する
配布時
Unity / Godotともに、実装完了時点で実際にbundle / packageへ含まれる依存関係を再度棚卸しし、THIRD_PARTY_LICENSES / Third Party Notices 相当のファイルへ集約する。
