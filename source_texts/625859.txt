Motivation
Replace coarse bounding-sphere TLAS nodes with tight AABBs to reduce unnecessary traversal for closed rooms, large walls, and many static meshes.
Compute per-object AABBs that reflect mesh transforms and oriented/scaled cubes so TLAS culling is much tighter than the previous sphere approximation.
Speed up TLAS construction by avoiding repeated allocations/sorts and by partitioning ranges in-place to reduce GC/CPU overhead when many objects are present.
Keep the per-mesh triangle BVH implementation separate for now while adopting the same in-place, preallocated pattern later.
Description
Replaced GpuBvhNode.center_radius with bounds_min: [f32;4] and bounds_max: [f32;4] and preserved the children fields in vetrace_engine/src/scene/bvh.rs.
Added object bound computation that handles spheres (position ± radius), cubes (oriented & scaled cube AABB), and meshes (transformed triangle bounds) and produces ObjBounds used by the TLAS builder.
Rewrote TLAS builder to preallocate node storage, build parent nodes by unioning child AABBs, and partition object ranges in-place with select_nth_unstable_by to avoid per-subtree cloning/sorting.
Updated shading code to use AABB tests: replaced GPU BvhNode layout and traversal checks in WGSL (sphere_hit -> aabb_hit) and matching changes in the OpenGL compute shader (center_radius -> bmin/bmax and boundsIntersect -> aabbIntersect).
Updated camera-relative BVH shifting and debug logging to operate on bounds_min / bounds_max fields and left triangle BVH nodes unchanged.
Testing
Ran cargo fmt --all to apply formatting (succeeded).
Attempted cargo check -p vetrace_engine but the build is blocked in this environment due to a missing system dependency (wayland-client pkg-config / system libs), so full compile verification could not complete.
Attempted cargo check -p vetrace_engine --no-default-features which is also blocked by the same system pkg-config error in this environment.
No additional automated unit tests were added or executed as part of this change.

Remove the duplicate aabb_hit definition
When the WGPU renderer compiles this shader, this newly added aabb_hit redeclares the existing helper with the same signature earlier in the file, and WGSL does not support overloading/redefinition. That makes raytrace.comp.wgsl invalid for any WGPU raytracing path before rendering starts; remove this duplicate or reuse/rename the existing AABB helper.
