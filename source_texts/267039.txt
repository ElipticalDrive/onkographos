This change introduces neural, an opt-in light selection mode that predicts per-light visibility using a small neural network, as an experiment to measure whether it beats the learned grid at equal time on a CPU.
Summary
Adds a new light selection mode (neural) alongside the existing power, uniform, and learned modes. The mode weights the power table by predicted visibility from a multi-resolution hash-grid encoding feeding a small MLP, trained deterministically on the same receiver walk that learned uses. The experiment is gated by a benchmark (nvc_bench) that measures inference cost before integration work begins.
Key Changes
New crate crust-nn: A tiny, dependency-free, forbid(unsafe_code) neural-network kit with:
HashGrid: multi-resolution hash encoding with trilinear interpolation
Dense: fully-connected layers with forward and backward passes
ReLU, sigmoid, and binary cross-entropy loss
Adam optimizer with per-group learning rates
Gradient checking for verification
Deterministic training via openqmc draws and fixed loop order
New module crust-core/src/light_visibility.rs: Handles training and inference:
Splits the receiver walk from light_cache::train to report per-light visibility labels
Trains the network on "delivered light" fractions (nonzero radiance + clear shadow ray)
Implements the D2 formula: pℓ(x) = (1 − D) · πℓ · V̂ℓ(x) / Σw + D / n_live
Provides a pure p ↦ (pmf, cdf) function with thread-local memoization for MIS consistency
Integration into light selection:
Adds LightSelection::Neural variant
Routes pick_index_at, pmf_at, find_index_by_geom_at, infinite_at through the network
Falls back to power silently for <2 lights or no receivers; logs WARN for >64 lights
Installs over the power table, sharing the defensive uniform share (0.3)
Benchmark gate (nvc_bench example): Times one inference, one shadow ray, and one learned lookup on the same receivers to measure cost before full integration
Documentation: Adds design record, task list, and spec delta covering:
Unbiasedness and MIS consistency requirements
Determinism across tiles/scanlines and thread counts
Fallback behavior and light limits
Equal-time measurement plan against learned and power
Implementation Details
Determinism: All randomness comes from openqmc under a new K_NVC key; training uses fixed epoch count (8), fixed mini-batch order (256 samples, 32-sample chunks summed in order), and plain f32 arithmetic with no mul_add to ensure bit-identity across thread counts and SIMD codegen.
MIS consistency: The bounce side recomputes the pmf at prev.pos from the same pure function, giving identical bits. A single-entry thread-local memo keyed on exact Vec3A bits makes the bounce lookup free when it follows NEE at the same vertex.
Network shape: 8-level hash grid (L=8, F=2, T=2¹⁴, ~1 MiB) → 16 → 32 → 32 → N logits, ReLU hidden, sigmoid output. Supports up to 64 lights.
Labels: Reuse the shadow rays NEE would cast; a label is the fraction of LIGHT_SAMPLES samples that delivered light (nonzero radiance + clear ray), folding in backfacing and below-horizon.
Existing modes unchanged: power, uniform, and learned render bit-identically before and after this change (verified by check_images.sh).
The experiment is additive and opt-in; rollback is removing the variant and crate. No scene or file format changes.
