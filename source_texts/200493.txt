Hi @benmkent
hi @jbytecode @dannys4 @fverdugo
nice to meet you (again)!
I've played around with the package for a little while and I have some questions and remarks as well as a little example.
I should mention that I am the author of DistributedSparseGrids (thanks for mentioning my work in the paper)
The SparseGrid struct is not typed at all. But the result of a function call -- as far as I can see -- is assumed to be a scalar, or in other words of type Number.
Why can the result of a function call not be of type Vector{RT} or Matrix{RT}, RT:<Number?
All function derived from that should be type-unstable, and thus, slow. Why would you want that?
=> In my example below: if I put adaptive_sparsegrid(fun1, ndims, maxpts=10_000, proftol=5e-6), the sparse grid construction takes ages albeit only approximately 1500 points are generated.
=> Interpolation on the sparse grid is very slow as well. 40_000 interpolations interpolate_on_sparsegrid(sg, f_on_Z, zvals[:]); take 16 seconds with a sparse grid with 161 collocation points. As a reference: for an adaptively refined sparse grid created with DistributedSparseGrids.jl with 5165 collocation points 40_000 interpolations take 0.16 seconds.
In my example below, I took a function where global sparse grids will fail. Maybe you want to include the prerequisites a function has to fulfill for your sparse grid construction to work into the paper?
I upload a picture where both results from the example below are visualized (for some reason, I can only upload pdfs, all other image formats will fail).
i1.pdf
Lastly, in the paper you claim that the SparseGridsKit.jl implementation offers a more complete set of functionality. Maybe you could elaborate on what features you have been adding which are not available in the other packages?
Example:
```
using SparseGridsKit
using GLMakie
using DistributedSparseGrids
using StaticArrays 

GLMakie.activate!()
ndims = 2
fun1(x,ID="") =  (1.0-exp(-1.0*(abs(2.0 - (x[1]-1.0)^2.0 - (x[2]-1.0)^2.0) +0.01)))/(abs(2-(x[1]-1.0)^2.0-(x[2]-1.0)^2.0)+0.01)

function sparse_grid(N::Int,pointprops; nlevel=6,RT=Float64,CT=Float64)
	# define collocation point
	CPType = CollocationPoint{N,CT}
	# define hierarchical collocation point
	HCPType = HierarchicalCollocationPoint{N,CPType,RT}
	# init grid
	asg = init(AHSG{N,HCPType},pointprops)
	#set of all collocation points
	cpts = Set{HierarchicalCollocationPoint{N,CPType,RT}}(collect(asg))
	# fully refine grid nlevel-1 times
	for i = 1:nlevel-1
		union!(cpts,generate_next_level!(asg))
	end
	return asg
end

(sg, f_on_Z) = adaptive_sparsegrid(fun1, ndims, maxpts=10_000, proftol=1e-3)
pcl = precompute_lagrange_integrals(7)
integral_result = integrate_on_sparsegrid(sg, f_on_Z, pcl)

asg = sparse_grid(2, @SVector [1,1])
init_weights!(asg, fun1)
for i = 1:20
	cpts = generate_next_level!(asg, 1e-3, 20)
	init_weights!(asg, collect(cpts), fun1)
end

nptsperdim = 200
xs = LinRange(-1.0, 1.0, nptsperdim)
zvals = [[x,y] for x in xs, y in xs];
@time zs1 = interpolate_on_sparsegrid(sg, f_on_Z, zvals[:]);
@time zs2 = [interpolate(asg,[x,y]) for x in xs, y in xs];

cpts_x_1 = [DistributedSparseGrids.coord(hcpt,1) for hcpt in asg]
cpts_x_2 = [DistributedSparseGrids.coord(hcpt,2) for hcpt in asg]
cpts_x_3 = zeros(length(cpts_x_1))


fig = Figure();
ax3d1 = Axis3(fig[1,1]);
ax3d2 = Axis3(fig[1,2]);
surface!(ax3d1, xs, xs, reshape(zs1, nptsperdim, nptsperdim));
cpts_sg = get_grid_points(sg)
scatter!(ax3d1, map(x->x[1], cpts_sg), map(x->x[2], cpts_sg), zeros(length(cpts_sg)), markersize=2)

surface!(ax3d2, xs, xs, zs2);
scatter!(ax3d2, cpts_x_1, cpts_x_2, cpts_x_3, markersize=2)

fig
```
