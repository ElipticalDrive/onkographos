This should do the following:
the implementation is able to efficiently store and access data in the tree
there are methods to serialize generic octree, most likely this is specialized in inheriting classes
the nodes of an octree can be easily reorganized in memory
finding out if a point lies within an octree and in wich subnode it can be found (bounding box lookup)
finding points within a range from a given center point
point insertion at a given position
there has to be testing code for extreme cases
Since this is a .NET implementation, make use of .NET strategies and best practices. Also keep in mind that this has to be working on Mono, so always try it there too.
Assumptions:
an octree is a sparse structure, that means a node may have 0 to 8 children
a node child may point to data for a point, or to another node
data in octrees may lie at a deep level, thus the composition of the object may have to be guessed or calculated for the higher levels.
all nodes have a center point where all dividing planes meet.
every node has a bounding box
Literature:
https://mediatech.aalto.fi/~samuli/publications/laine2010tr1_paper.pdf
http://http.developer.nvidia.com/GPUGems2/gpugems2_chapter37.html
http://maverick.inria.fr/Publications/2011/Cra11/CCrassinThesis_EN_Web.pdf
