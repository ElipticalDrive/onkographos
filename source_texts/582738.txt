This change enables block-based CPU prediction for sparse DMatrix inputs when the per-thread feature-vector block remains small.
Previously, inputs below the existing 12.5% density threshold were predicted one row at a time. That prevents the predictor from using the block path even when the feature-vector buffer is modest.
The change:
- keeps the existing density-based block decision
- also uses blocked prediction when a 64-row feature-vector block is at most 512 KiB
- this corresponds to up to 2048 float features
- wider sparse inputs keep the existing row-by-row path
Correctness:
- predictor tests passed
- full C++ suite passed
- all paired A/B benchmark workloads produced bit-identical predictions
Standalone paired A/B against upstream/master:
| Sparse DMatrix workload | Change |
| --- | ---: |
| 512 features, 3% density, 10k rows, 1T | -30.56% |
| 1000 features, 3% density, 10k rows, 1T | -28.95% |
| 2048 features, 3% density, 10k rows, 1T | -28.57% |
| 4096 features, 3% density, 10k rows, 1T | -0.12% |
The 512/1000/2048-feature workloads were faster in every paired group. The 4096-feature workload remains on the existing path and was effectively unchanged.
