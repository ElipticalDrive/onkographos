Contributor
D3D12 currently expands each supported DEC3N field into appended SNORM16 data on the CPU. This adds 8 bytes per packed field per vertex on an eligible fill. This change adds an opt-in, default-off path (SFR_GPU_DEC3N=1) that retains the packed source stride and decodes typed uint inputs in the vertex shader. Unsupported declarations and Vulkan/Metal keep the CPU path; gathering, guest reads, byte swapping, cache behavior and GPU retirement remain in place.
The numerical result reproduces the CPU SNORM16 conversion, including the -512 clamp and W=1. The raw/legacy VS pair, mode-aware layout/cache identity, mask-aware pipeline identity, prewarm and prepared-draw reconstruction are connected together.
Shader packs move from ABI12 (five u32 fields) to ABI13 (six fields). The prior source-only rebuild tool remains unchanged; new packs require complete legacy/raw vertex pairs. New pipeline recipes use format2/ABI13; historical format1/ABI12 recipes retain the legacy mask-zero path. README documents the opt-in switch and pack migration. No generated game code, proprietary shaders, binary packs, saves or dependencies are included.
Confirmed effect and limits
Eligible fills bypass the CPU SNORM16 append loop and avoid its 8 widened bytes per packed field/vertex. Existing warm whole-stream cache hits already skip conversion, so this is not work saved on every draw.
Vertex-shader decode work, shader-pair storage/compilation and pipeline variants are added, including shader-tool costs when the runtime switch is off.
No net current-upstream performance improvement is established. The matched target pair below exercised the path but had worse mean frame time with GPU decode enabled. Historical measurements from a different custom fork are intentionally not used as evidence here.
Validation against official main 640bf6f
Windows Release, clang-cl, pinned public dependencies: full current-official-derived diagnostic/game link passed, including the actual three PUBLIC draw entries. An owned 468-record source-only title pack was rebuilt into ABI13 (283 complete legacy/raw VS pairs and 185 PS records); no private sources or binaries are included in this PR.
35 unique Python tests passed across shader-pack, shader-preparation and release packaging tests. Initial default-TEMP sandbox ACL errors were preserved; only the three affected cases were rerun with private writable TEMP.
11 native CPU/format/manifest/negative-pack processes passed.
Real RTX 3080 Ti D3D12 numerical readback: 3,104 numerical values, nine semantic routes, 23 cases; Vulkan CPU fallback: 3,104 values, nine routes, 22 cases. Includes exact SNORM behavior, W=1, ordinary fields beside packed fields, stride/offset/alignment fallbacks and queued old/new versions.
Actual-device ABI selection, D3D12/Vulkan prewarm reconstruction and the existing legacy Vulkan resolution regression passed (six device/readback processes in total; no D3D12 skip).
Official unmodified ABI12 producer generated a two-record five-field compatibility fixture from existing owned ABI11 original sources. The unchanged rebuild tool translated those sources into ABI13; source/stage/mask identities and the raw VS lib_6_3 profile were checked. This is a constructed compatibility fixture, not a claim of testing a shipped release12 pack or all game shaders.
Additional target calibration: real RX480 D3D12 numerical readback completed with 3,104 values, nine routes and 23 cases. Local full-render race endpoints show the course, player and advancing HUD; they are scene-readiness evidence, not performance evidence. The matched target game pair is reported below. Default remains off. This same-image OFF/ON comparison measures opt-in activation, not all fixed PR/ABI13 overhead against unmodified upstream.
Diagnostic clarification
The numerical readback checks do not establish DRED activation. The current upstream renderer does not implement the older custom fork's SFR_D3D12_DRED diagnostic switch; passing that environment variable is not evidence of DRED. No net current-upstream title speedup is established.

Two normally completed runs on the same current-upstream-derived diagnostic image; D3D12, 1280x720, render scale100, VSync/frame cap off, full rendering, vertex cache enabled. Each used its own initially fresh cache, the same private save seed, the same 17-word Free Race route, and the predeclared final1500-present window of4200 presents after the last injected word. The selected ON window recorded729811 raw-route draws and1081 eligible fills, representing26984664 logical widened append bytes omitted. This confirms real work removal, not bandwidth saved or GPU completion. With current upstream whole-stream reuse, the OFF repack contribution was already small. Both windows recorded23 pipeline creations; ON creation wall time was higher (maximum1904.660 ms versus23.383 ms). These aggregate observations do not establish the precise driver/shader cause or prove the maxima occurred on the same frame.
The reported main-thread CPU estimates also did not improve:18.236 to20.295 ms, averaged over12 versus11 fully contained120-present diagnostic rows (1440/1500 and1320/1500 coverage). These are coarse estimates, not exact per-frame CPU measurements; CPU p99 is unavailable. Nested wall timers must not be summed.
Decision: keep this PR draft and default-off; this pair does not support a net speedup or default promotion. The observed throughput delta is-9.972%, with a2.05-second maximum frame in ON; it is not a general causal slowdown estimate. One sequential pair, Free Race AI/items, workload differences (1369492 versus1360944 draws), fresh-cache behavior and mode-dependent counter overhead limit attribution. It is not an unmodified-official-versus-PR comparison, clean normal-play FPS acceptance, a GPU bottleneck diagnosis or stable60Hz evidence. Only anonymous aggregate results are included here; owned game assets, saves and raw logs remain private.
