Goals
Resolve Mercator/Globe billboard collisions using the actual host cameras, and support per-eye terrain intersections without introducing terrain loading or rendering into the core.
Changes
Retain external-camera point/text candidates and repeat groups in workers, then run the existing camera-space annotation pass for Mercator, Globe and CPU-projected views. Classic camera-driven scenes keep their planar layout.
Reconstruct native packed positions and curved text attributes; preserve priority, padding, repeat distance, linked labels, proxy ownership, and one shared collision mask across stereo eyes.
Reject occluded globe anchors before collision and deduplicate wrapped globe copies while preserving separate Mercator worlds and elevations.
Add typed TerrainSurface, TerrainMeshSurface, TerrainRay, TerrainMeshOptions and hit contracts. The immutable reference mesh uses the existing math.gl bounds/triangle query leaf, two-sided nearest hits, physical altitude, normals and barycentric coordinates.
Export pickTerrainAt, Renderer.getTerrainAt and TangramLayer.getTerrainAt, with active/named-eye or whole-canvas routing and finite camera clipping. Uninitialized/loading/failed/disposed layers safely return null.
Allow pickXRSurface to query an explicit terrain surface after room-placement transforms, preserving bounded-tabletop limits. Terrain holes never fall back to the analytic plane/sphere.
Keep public declarations and all generated package entries aligned; audit the new exports in the artifact smoke check. Add the direct pinned math.gl dependency and browser pre-optimization.
Add Node/Chromium conformance and actual WebGL/WebGPU regressions; update renderer, layer, WebXR and roadmap documentation.
Verification
Immutable dependency resolution, full build, strict typecheck, license/format lint and whitespace checks pass. No new unchecked TypeScript directives or generated files are committed.
Node and Chromium coverage tests pass. Merged report: 88.35% lines, 82.90% branches, 90.98% functions; both independent module gates and the 185-file source inventory pass.
New terrain surface implementation: 100% statements, lines, functions and branches. Geographic annotation pass: 98.11% lines, 92.05% branches.
Focused real-device collision restoration and terrain-camera queries pass on WebGL 2 and WebGPU.
Final full suites pass: 606 Node, 1,374 Chromium, 135 WebGL 2 and 132 WebGPU tests (three existing WebGPU-only skips). The production website and rendered documentation build pass.
All CI checks pass on fc43f196. The worker repeat-culling review finding is fixed with tile/collision and both-GPU worker-to-renderer regressions; the loading-state guard also has focused coverage.

The terrain kernel imports @math.gl/culling/queries, not the full analytic shape entry. No deck.gl or WebXR state enters the renderer HostFrame contract.
Limits
Applications supply the terrain mesh or their own indexed TerrainSurface; no DEM loading, terrain displacement/rendering, terrain occlusion or worker feature-ID association is added.
The reference mesh traverses triangles linearly after a bounds rejection; large datasets should supply a spatial index.
Terrain accepts absolute Mercator meters or radius-256 globe common coordinates, not experimental CPU-projected coordinates.
Collision bounds are conservative screen rectangles, not glyph-outline/alternate-anchor fitting or evaluation of custom billboard shader displacement.
Headset hardware validation and synchronous deck.gl picking remain separate work.
Related roadmap: #49, #48. Independent of #176; both can land in either order.
