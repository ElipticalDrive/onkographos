This PR introduces three new creative volumetric tools to voxelizer-rs:
Hollow (--hollow <thickness>): Instead of filling the entire interior of a solid mesh, this option retains voxels only within a specified depth from the surface (sdf <= 0.0 && sdf >= -thickness), effectively leaving a hollow shell.
Porosity (--porosity <fraction>): Simulates porous, sponge-like materials by dropping a specified percentage of solid voxels. It uses a deterministic, sine-based spatial hash (common in shaders) based on the voxel coordinates to decide which voxels to keep, avoiding the overhead of generating new random numbers in the inner loop or adding external dependencies.
Mold (--mold): Inverts the voxelization logic by retaining voxels outside the mesh (sdf >= 0.0), creating a negative space or mold of the original object within the bounding box.
All features directly manipulate the existing Signed Distance Field (SDF) values evaluated during raycasting, making them both powerful and performant. The CLI Args, MeshProcessor::voxelize signature, unit tests, and benchmarks have all been updated. Documentation in README.md was added to instruct users on these new capabilities.

Reject invalid hollow and porosity values
These new options are parsed as unconstrained f64s, unlike resolution and narrow_band, so callers can pass NaN/infinity, negative hollow thickness, or porosity outside the documented 0.0–1.0 range. In those cases the voxel filters silently produce nonsensical results (for example --porosity 1.5 drops every kept voxel, and --hollow -1 yields an empty shell) instead of rejecting invalid input, so the CLI/library should validate the new parameters before voxelization.
