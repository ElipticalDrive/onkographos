# NeRF Image Distortion Analysis Using SSIM, MS-SSIM, and NIQE

This project investigates how image distortions influence Neural Radiance Field (NeRF) reconstruction quality using structural and perceptual image quality assessment (IQA) metrics. Controlled distortion experiments were performed using the LLFF Pinecone dataset with Gaussian blur, Gaussian noise, impulse noise, and JPEG compression applied to the training images.

The project extends the original PyTorch NeRF implementation with:
- image distortion pipelines
- offline IQA evaluation
- automated experiment logging
- metric visualization tools
- CUDA-enabled NeRF training support

The primary goal of the project is to analyze how different image degradations affect NeRF learning behavior, structural reconstruction quality, and perceptual realism over long training durations.

---

# What is NeRF?

Neural Radiance Fields (NeRF) are neural networks designed to learn continuous 3D scene representations from multiple 2D images. Instead of storing explicit geometry such as meshes or voxels, NeRF learns a volumetric scene function that predicts color and density values at arbitrary points in 3D space.

A NeRF model represents a scene using a continuous function:

```text
F(x, y, z, θ, φ) → (RGB, σ)
```

where:
- `(x, y, z)` represent 3D spatial coordinates
- `(θ, φ)` represent viewing direction
- `RGB` represents predicted color
- `σ` represents volumetric density

These inputs form a 5D coordinate system:
- 3 spatial dimensions
- 2 viewing direction dimensions

During rendering, NeRF samples points along camera rays and performs differentiable volume rendering to synthesize novel scene viewpoints.

# Metrics Used

## SSIM (Structural Similarity Index)
Measures structural similarity between rendered validation images and ground-truth images.

## MS-SSIM (Multi-Scale SSIM)
Extends SSIM across multiple image resolutions/scales.

## NIQE (Natural Image Quality Evaluator)
No-reference perceptual image quality metric based on natural image statistics.

# Dataset

## LLFF Pinecone Dataset

This project uses the LLFF (Local Light Field Fusion) Pinecone dataset:
- real-world forward-facing scene
- multi-view image capture
- calibrated camera poses
- held-out validation viewpoints

Training images are distorted while validation and test images remain clean for evaluation.

# Recommended Hardware

NeRF training is computationally expensive. A CUDA-capable NVIDIA GPU is strongly recommended.

Recommended:
- NVIDIA GPU with at least 8 GB VRAM
- 16 GB system RAM or higher
- Windows, Linux, or WSL2
- Conda environment
- CUDA-enabled PyTorch installation

The project can technically run on CPU, but training will be extremely slow.

# CUDA / GPU Setup

## 1. Confirm NVIDIA GPU Driver is Installed

Run:

```bash
nvidia-smi
```

If CUDA is available through the NVIDIA driver, this command should show:
- GPU name
- driver version
- CUDA version supported by the driver
- current GPU memory usage

If `nvidia-smi` is not recognized, install or update the NVIDIA GPU driver before continuing.

---

## 2. Install CUDA-Enabled PyTorch

Install the CUDA-enabled PyTorch build that matches your system.

Example using CUDA 12.1:

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

If your system uses a different CUDA-supported PyTorch build, use the command generated by the official PyTorch install selector:

```text
https://pytorch.org/get-started/locally/
```

Important:
- You usually do not need to install the full CUDA Toolkit separately for PyTorch.
- The PyTorch CUDA wheel includes the CUDA runtime libraries needed by PyTorch.
- You do need a compatible NVIDIA driver installed.

---

## 3. Verify PyTorch Can See CUDA

Run:

```bash
python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'No CUDA GPU found')"
```

Expected output should include:

```text
True
<your NVIDIA GPU name>
```

If this prints `False`, PyTorch is not using CUDA.

Common fixes:
- Install the CUDA-enabled PyTorch wheel instead of the CPU-only build.
- Update NVIDIA drivers.
- Restart the terminal after installing drivers.
- Make sure the conda environment is activated.

---

## 4. Optional: Check CUDA Memory During Training

While training is running, use:

```bash
nvidia-smi
```

This helps confirm that the GPU is being used.

# Configuration

The main experiment configuration is stored in:

```text
configs/pinecone.txt
```

Example stable configuration:

```text
expname = pinecone
basedir = ./logs
datadir = ./data/pinecone

dataset_type = llff
factor = 8
llffhold = 8

N_rand = 256
N_samples = 64
N_importance = 64

chunk = 4096
netchunk = 8192

use_viewdirs = True
raw_noise_std = 0.5

precrop_iters = 500
precrop_frac = 0.5

lrate = 5e-4
lrate_decay = 250

white_bkgd = False
no_batching = True
```

Notes:
- `N_rand` controls rays sampled per training iteration.
- `N_samples` controls coarse samples per ray.
- `N_importance` controls fine samples per ray.
- `chunk` and `netchunk` help control GPU memory usage.
- Lower values improve stability on laptop GPUs.

# IQA Evaluation Pipeline

During training:
- validation renders are periodically saved
- clean ground-truth images are saved
- training loss, validation loss, PSNR, timing, and file paths are logged

After training:
- SSIM is computed using `scikit-image`
- MS-SSIM is computed using `pytorch-msssim`
- NIQE is computed using `pyiqa`

Metrics are stored in:

```text
logs/<experiment>/results/combined_metrics.csv
```

Plots are saved in:

```text
logs/<experiment>/results/
```

Summary plots across all experiments are saved in:

```text
logs/summary_results/
```

# Key Findings

- Gaussian blur produced the largest degradation in reconstruction quality.
- Impulse noise strongly disrupted structural consistency.
- Gaussian noise was less destructive than expected.
- JPEG compression remained surprisingly robust.
- NeRF appears highly sensitive to loss of high-frequency structural information.
