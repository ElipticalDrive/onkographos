16 function outputs differ only in the frame: Lean saves x28, and stock does not (CI snapshot: main 60188b47, run 42181236069). These are 8 functions, each compiled under 2 settings variants:
runtests/atomic-rmw-little.clif: %atomic_rmw_xchg_i32, %atomic_rmw_xchg_i32_no_res, %atomic_rmw_xchg_i64, %atomic_rmw_xchg_i64_no_res
runtests/atomic-rmw-subword-little.clif: %atomic_rmw_xchg_little_i8, %atomic_rmw_xchg_little_i8_no_res, %atomic_rmw_xchg_little_i16, %atomic_rmw_xchg_little_i16_no_res
```
stock                       Lean
stp x29, x30, [sp, #-16]!   stp x29, x30, [sp, #-16]!
mov x29, sp                 mov x29, sp
                            str x28, [sp, #-16]!
stp x26, x27, [sp, #-16]!   stp x26, x27, [sp, #-16]!
stp x24, x25, [sp, #-16]!   stp x24, x25, [sp, #-16]!
```
The loop is the same. Lean's code is 8 bytes longer (one save, one restore). In the subword functions, one temporary also differs (stock mov x8, sp, Lean mov x9, sp).
Cause. Cranelift's AtomicRMWLoop defines the scratch register x28 only when op != Xchg (isa/aarch64/inst/mod.rs:486, pinned 46c23a8). An xchg loop does not write x28. Lean defines x28 for every op (FV/Backend/RegallocOps.lean:232-241). The comment there records this deviation: it keeps visitOperands total in op for the rename-commutation proofs. So regalloc2 sees x28 as clobbered, and the prologue saves it.
Fix. Do not define x28 for xchg, and adapt the rename-commutation proofs.
Not in scope. runtests/atomic-cas.clif %atomic_cas_i32 differs on purpose. Lean compares x27 with w26, uxtw, because Cranelift's 64-bit compare of an i32 value is an upstream bug (FV/Backend/Asm.lean:383, recorded in #59). This output stays different.
Expected: up to +16. Overview: #557.
