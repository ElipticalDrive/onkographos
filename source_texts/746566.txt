Closes #610.
Adds support for the AssetContentMap data type (binary type ID 0x23), and updates the reflection database to v745 so that Terrain.VoxelGridAssetContentMap is a known property.
Places using Expanded Terrain store their voxels in Terrain.VoxelGridAssetContentMap. In those places, Terrain.SmoothGrid only holds a short header. rbx_binary skips the unknown 0x23 PROP chunk with a warning, and rbx_xml ignores the property because the database doesn't know about it. Either way, reading and re-writing such a place (for example through a Rojo or Lune publish) silently produces a place with no terrain.
Format
The binary and XML formats are documented in docs/binary.md and docs/xml.md. In short:
Binary: values are not interleaved. Each value is a u8 flags byte. Bit 0 means a bundle asset ID follows, as a decimal string. Bit 1 means an i64 entry count follows, then that many (String key, String data) pairs.
XML: a JSON array of {"key", "data"} objects, with base64 data. XML has no form for a bundle asset ID, so writing a value that has one returns an error instead of silently dropping it.
Entry data is treated as opaque bytes. Key order doesn't matter to Roblox, so entries are written sorted by key. Repeated keys follow Roblox: in binary the first value wins, and in XML the value is rejected.
Changes
rbx_types: new AssetContentMap type and Variant::AssetContentMap, appended last.
rbx_binary: Type::AssetContentMap = 0x23. Adds read/write support, a fallback default, and the debug text format.
rbx_xml: AssetContentMap reader and writer. This adds a serde_json dependency to rbx_xml.
rbx_dom_lua: values are passed through as-is, since Luau can't access this property.
rbx_reflector: maps the API dump type name AssetContentMap and adds it to allValues.json.
Reflection database updated to Studio 0.745.0.7451137 with ./gen-reflection, in its own commit. The API dump lists the property as DataType/AssetContentMap, CanLoad/CanSave. The commit also brings in other API changes since v741.
Docs, README table and changelogs.
Testing
Unit tests for the binary codec. They cover the exact bytes from Preliminary support for AssetContentMap DataType #610 for an empty map, both flags, bundle-only values, a zero bundle ID, duplicate keys, invalid IDs, negative counts and truncated input.
Unit tests for the XML codec. They cover round trips, [], line-wrapped base64, reordered entries, duplicate keys, non-array input and writing a bundle.
End-to-end round trips of a Terrain with VoxelGridAssetContentMap through both rbx_binary and rbx_xml with default options.
New test-files fixtures, added in Add Expanded Terrain model and published place rbx-test-files#38. The submodule is bumped to that commit.
models/expanded-terrain: a Terrain saved from Studio with "Save to File", as both binary and XML. Its voxels are stored inline. Read from either format, the AssetContentMap is the same.
places/expanded-terrain-published: a place downloaded after publishing. Here the map only holds a bundle asset ID with no entries. This is the case from Preliminary support for AssetContentMap DataType #610: today this value is dropped when the place is re-published, and the terrain is lost.
cargo test --all-features, cargo clippy --workspace --all-targets --all-features and cargo fmt -- --check pass.
Not done: Lua tests run in Studio.
