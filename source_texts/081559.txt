Scope and Review Anchor
HLOD S1a: format v2 and bake core, implementing accepted ADR docs/architecture/adr-hlod-streaming.md sections 6.1-6.3, 7 and tests 3-4. Risk R3 (persistence, format and importer). Immutable base 64cb1fee056c195ab9ba5c8347245e766deec8c4; original branch base f98243887a7; current head 8a452150d47 (round 8 8a452150d47: fallible HLOD interior-merge allocations, see below; round 7 23b22da93e2: fallible HLOD bake allocations, see below; round 6 98a2c85fed9: editor reimport now reloads the complete world state via a GaussianSplatWorld::copy_from() override, with a both-direction reload-equality test that is revert-proven by 28 assertions failing; round 5 0103adeeb43 on top of round 4 fd93368e59c, master merged at 8bbcb1f2e92). Human maintainer R3 approval remains required. This is not S1b representation selection, S2a runtime cuts or alpha acceptance.
Implementation
World-aligned lattice octree, origin-centred root for origin-plane crossings, grouped/index-split leaves, no node over 16,384 splats. Importance-ordered leaf payload; breadth-first interior payload.
sat moment matching, bounded inflation, node-relative positions, single-child bit identity and DC-encoding-aware merge cells. Explicit all-pass-through exit preserves payload and SH unchanged.
World format v2: HLOD flag, 80-byte header extension, 128-byte node/instance records and bounded non-overlapping sections. Disjoint noncanonical ordering is allowed; v1 reading and tree-less saving remain intact. World importer version is 4 (3 for the v1 -> v2 bake, 4 for the header-bounds rule); PLY/SPZ importer versions are unchanged. The header world AABB must enclose the root node's world AABB.
Public bake_hlod(), has_hlod_tree(), get_hlod_info(). No implicit export bake. Failed bakes preserve state; successful publication installs payload, chunks, tree and revision before notifications. Snapshot saving captures payload/SH/2D metadata/revision under one read lock and rejects stale pre-capture edits before writing.
Active file-backed source replacement invalidates its old tree and leaf chunk addresses. Bake captures the full resident count/payload/SH/2D/revision under the existing data lock, retains the original strongly, and revalidates revision plus publishes under that same lock before notifications. Intervening GaussianData edits are retained and reject the bake, not overwritten. World setters retain their existing main-thread ownership assumption; this is not arbitrary concurrent World-setter safety.
Normal source loading follows actual Godot import metadata through the module-owned import-aware loader. Raw direct loader calls stay raw for importer prevalidation. Source v1 reimport produces a v2 copy without changing source bytes; invalid v2 cannot overwrite an earlier successful import. Recovery keeps the documented plain-copy fallback, not a silent changed rendering interpretation.
QA preparation performs bounded editor import and native ConfigFile sidecar/artifact verification before selected scenes. Nonzero exit, malformed/invalid metadata, absent required sidecars/remap/destinations, non-string entries and no verified imports fail closed. Keep/skip and ignored-directory semantics remain supported. No baseline, capture requirement or threshold was relaxed.
Reject node spheres below any stored half-axis extent and parent spheres that cannot enclose child spheres. Bake uses the same rounded bounds and upward radius rounding. Valid isotropic Gaussian spheres smaller than the AABB diagonal remain valid. The current resident leaf-chunk adapter bounds precise/runtime AABB corners about its emitted float centre and pads the serialized sphere for centre displacement, rounding the runtime radius upward. This prevents false resident culls even at the tested 1e6 offset.
Remove ten PR-owned redundant virtual declarations on override methods without changing dispatch.
The ADR records the origin-root local-edit caveat (root growth may re-address direct leaf children, depth >= 2 remains stable), preserves the 2D flag without inventing new rendering semantics, and rejects unimplemented proxy payloads. Today's renderer still consumes absolute float32 leaf positions; no runtime consumer reads interior representations yet. Changed chunk partition/order can change image bits: this is not an unchanged-rendering guarantee. Subsequent DC-encoding work must use the next format/importer versions.

Round 5 (0103adeeb43), Codex P2 PRRT_kwDORquMSc6rCD79: a baked world whose metadata held a non-finite float saved successfully, but JSON::stringify writes nan/inf, which the v2 loader rejects. The v2 saver now applies the loader's own metadata acceptance rule (shared _decode_v2_metadata_json) and refuses with ERR_INVALID_DATA before the atomic write. Files that do save are byte-identical to before, and the importer sets no world metadata, so the world importer version stays 4. New case review-r3 save refuses metadata that cannot round-trip as JSON, revert-proven (36 of 38 checks fail without the check). All 58 WorldIO/HLOD cases pass (430863 assertions), and the guard-only suite passes on a Windows dev/tests build of this head. Only CPU tests were run this round; no GPU evidence is re-claimed.
Round 7 (23b22da93e2), Codex P1 PRRT_kwDORquMSc6rDEHb: LocalVector::reserve() aborts on a failed memrealloc. As a result, a valid large world baked under memory pressure terminated the editor, and the importer's plain-copy fallback never ran. Every splat-count-sized allocation in the bake path is now proven available first with gs_hlod::bake_allocation_probe(), the memalloc probe from the OOM-probe row of adr-import-input-hardening.md. That covers 18 bake_world scratch/table/payload resizes, plus bake_hlod()'s snapshot and baked copy. A failed probe returns ERR_OUT_OF_MEMORY before publication, through bake_world's new optional r_code and bake_hlod(). The author is right that §6.1's "smallest lattice cell that contains the content" has no answer for content that straddles a plane through O.
The fix is sound and consistent with the lattice. The root is a virtual cube [O−2^e, O+2^e), and its children (e, {−1,0}³) are ordinary lattice cells. When the root grows, the old children keep their addresses: floor_half(−1) = −1.

The origin cube is not a lattice cell, so it disappears when it grows. Its leaf children are then re-addressed from (e,s) to (e+1,s), which changes their frame and payload bytes.
