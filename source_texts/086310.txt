# Streaming Binary Greedy Meshing

**A cache-friendly variant of the Binary Greedy Meshing algorithm that pipelines visibility and meshing together.**

Streaming Binary Greedy Meshing (SBGM) is a performance-oriented variant of the Binary Greedy Meshing (BGM) algorithm that combines face visibility generation and greedy merging into a streaming traversal, retaining two rolling face data slices instead of six full chunk face arrays.

This repository contains the SBGM implementation, the reference BGM implementation used as a baseline, a terrain generator, a benchmarking harness, and a validator that compares both meshers to a brute force visibility algorithm.

**Project status:** This repository is an experimental implementation to demonstrate the algorithm and is not production ready. It intentionally stores chunks as 62³ voxels with a 1-voxel padding halo (64³) for algorithmic simplicity.

## How it works
Traditional BGM first builds six exposed face mask arrays, one per direction, then meshes each direction in its own pass. These masks alone are 180 KiB, do not fit in L1 data cache (most consumer CPUs have 32/48 KiB L1D), and consequently get evicted before they are consumed in the meshing pass.

SBGM instead traverses a chunk one x-slice at a time, maintaining two rolling buffers of x-slices and per-direction merge state, and emits quads for all six directions as runs terminate. This reduces exposed face data down to two 11 KiB slices that are immediately consumed for meshing, improving cache locality.

## Algorithm comparison
<table>
<tr>
<th>BGM</th>
<th>SBGM</th>
</tr>
<tr>
<td>

```
build six full-chunk face masks

for each face direction:
    find and merge compatible face runs
    emit a quad for each completed rectangle
```

</td>
<td>

```
build face data for x-slices 1 and 2

for each interior x-slice:
    for each z-column:
        process visible X faces
        process completed Y merge runs
        process visible Z faces
        emit a quad whenever a compatible run cannot continue

    discard the previous slice
    build the next x-slice into the freed buffer
```

</td>
</tr>
</table>

## Results
Caveat: benchmark numbers are on a single machine and a single benchmark terrain type and will vary.

Benchmarking is done using a deterministic sinusoidal heightmap terrain and may not be representative of all workloads.
A single untimed warmup pass is done before measurement to ensure cache and branch predictor are warm.

Ryzen 5 5600x, Windows 10, MSVC 19.44.35221.0, 64x64 grid at 8 iterations:
```
mesher                   median          min          max      avg quads           throughput
BGM              100.27 us/chunk     98.83 us    100.67 us         2011.6        9,973 chunks/s
SBGM              37.52 us/chunk     37.33 us     38.53 us         1973.9       26,650 chunks/s

speedup: 2.67x
```
<sup><sub>Quad counts differ as SBGM merges adjacent faces in a different order; the benchmark validator confirms functionally equivalent coverage</sub></sup>

## Requirements
- CMake 3.20+
- C++17 compiler
- A "modern" (2013 or newer) x86-64 CPU supporting AVX2/BMI/BMI2

## Build and run

```sh
cmake -S . -B build
cmake --build build --config Release

# Windows
.\build\Release\sbgm_benchmark.exe [grid_width] [grid_depth] [iterations]
# Linux
./build/sbgm_benchmark [grid_width] [grid_depth] [iterations]
```
