Adds a self-contained texture toolchain under tools/ (all pure C11 libraries
with strict -Werror gates; CLIs do the I/O) plus the vendored Arm astcenc
backend. 83 commits, ~95 files. Squares with the repo conventions
(include/+src/+test/, _init() options, Makefile targets).
What's included
tools/texcomp — texture block compression
BC1 / BC3 / BC5 / BC6H / BC7 encoders (BC7: all 8 modes, quick + exhaustive,
decoder-driven windowed RDO, a public BC7 decoder; optional weighted-PCA
endpoint seeding). ETC2 / EAC.
ASTC LDR: all fourteen 2D footprints, 1–4 partitions, dual-plane,
CEM 0/4/6/8/10/12, integer LSQ refinement, SSE2/SSE4.1/AVX2/NEON kernels
bit-identical to scalar; the constrained UASTC LDR 19-mode subset.
ASTC HDR (UASTC HDR 4x4): void-extent + CEM 7 / 11 (single / dual-plane /
2-subset) + CEM 15 (HDR RGB + HDR alpha), all LSQ-refined.
xbc7 (supercompressed BC7 = windowed RDO + zstd) and uni (universal
transcodable intermediate → BC7/BC1/ASTC/ETC2, optional codebook + Zstd KTX2
mip chain).
Optional Arm astcenc backend (--encoder arm) — vendored at deps/astcenc
(Apache-2.0) — also used as the conformance oracle for the ASTC gates.
tools/resize (tir) — content-aware image resize
Separable float32 resampling; box/triangle/b-spline/gaussian/mitchell/
catmull-rom/lanczos2-3/kaiser filters; SSE2/SSE4.1/AVX2/NEON/SVE dispatch;
HDR anti-ringing/hicomp, normal-map renormalize, mean-preserving heightmaps.
tools/texpipe — resize-aware texture compression
Ties tir + texcomp into content-aware mip chains → multi-mip DDS/KTX2; seam-free
cube + octahedral fixup, Toksvig roughness, per-channel packing, array/volume.
tools/envmap — IBL projections & lighting representations
equirect/cube/octahedral resampling, real SH, spherical gaussians, split-sum IBL
bake, and a PBR validation harness.
Testing
make tools-test runs every self-contained pure-C gate (texcomp/resize/texpipe/
envmap); make tools-test-all adds the astcenc conformance cross-checks. All
green, including the ASTC LDR/HDR decoders validated bit-exact against astcenc.
Licensing
Our code under tools/ is Apache-2.0 (tir is BSD-3-Clause); third-party use is
credited in each tool's NOTICE.md/README.md and file headers — Arm astcenc
(Apache-2.0), bcdec (MIT), Basis Universal concepts (Apache-2.0), zstd (BSD),
stb_image (public domain), and the published algorithms (Karis, Toksvig,
octahedral survey, SH, spherical gaussians).

Adds a self-contained reference ASTC LDR block decoder
(tools/texcomp/test/astc_ref_decode.h): ISE decode, spec C.2.18 bilinear
weight infill, partition hash, CEM 0/4/6/8/10/12 decode including the
endpoint-swap + blue-contract rule. Validated against Arm astcenc-native
(55-99 dB agreement, i.e. within 1 LSB interpolation rounding).

The decoder exposed and this commit fixes three encoder bugs:
- CEM 8/12 endpoint pairs could be emitted with sum(lo) > sum(hi); a
  conformant decoder then swaps + blue-contracts, corrupting the block.
  Pairs are now emitted in ascending quantized-sum order with exact
  weight mirroring (weight unquant tables are symmetric).
- Dual-plane weights were emitted concatenated per plane; the spec
  requires per-texel interleaving.
- Partition/dual paths returned unconditionally, overriding better
  single-partition encodings (e.g. 9.6 dB garbage on two-cluster content
  that the single path encodes exactly). All paths now compete on
  reconstruction error; the partition path fits the shared weight grid
  against per-partition endpoint lines and reports the true quantized
  reconstruction SSE (verified to match the reference decoder exactly).

New tests: ISE decode(encode(x)) == x property test over all quant
levels, weight-unquant symmetry, encode->reference-decode round trips
with per-configuration PSNR floors, solid-image exactness. Partition
structural tests now use content shaped by actual partition patterns.
New tools: bench/texcomp_psnr.c + `make texcomp-astc-psnr` quality table.

astc quality (128x128, PSNR dB, reference decoder):
image      block      fast   medium   normal
gradient   4x4       43.74    43.98    43.97
gradient   6x6       43.00    43.37    43.58

clusters   8x8       21.28    54.15    54.15
photo      8x8       32.29    32.34    31.54
alpharamp  6x6       36.65    31.18    30.55

Known bias (next: quantization-aware single-partition scoring + LSQ
endpoint refinement): medium/normal can still lose to fast on smooth
content because the single-partition model ignores color quantization.

Single-partition pass 2 now scores every candidate with the endpoints as
they will actually decode (round-tripped through the color quantizer with
the emitted CEM's semantics, including base+scale reconstruction) and
tries replacing the axis-extreme endpoints with the integer least-squares
solution for the fitted weights (2x2 normal equations, exact rounded
int64 division; worst-case term < 2^47). The dual-plane path gets the
same treatment per plane. This makes all encoding paths compete on
honest reconstruction error, fixing the medium/normal-below-fast
inversions on smooth content.

After the shared weight grid is fitted, each partition's endpoints are
re-solved by least squares over that partition's texels and accepted
individually when the quantization-aware reconstruction error improves
(CEM 8/12 orientation guarded: a refit that would decode blue-contracted

…
7996079
```
- Per-block axis extremes are computed once (5 axes) instead of a
  144-texel scan inside every tc_astc_try_endpoint_axis call (~440

texcomp: hoist ASTC projections out of candidate loops + SIMD kernels
…
f56c6db
```
The per-texel ideal weights depend only on the endpoint line, never on a
candidate's weight grid or quantization, so they are now computed once
per block per axis (pass 1 previously re-projected ~245 times per block,
the partition and dual paths once per candidate) and each candidate only
quantizes them onto its grid and scores the reconstruction.

The two dominant loop shapes get SIMD kernels with scalar fallbacks:
- project: per-texel dot product onto the endpoint line + fixed-point
  reciprocal weight (SSE2 pmaddwd/pmuludq, NEON vmull)
- recon+SSE: interpolate/diff/square-accumulate in 16-bit lanes, in a
  uniform-endpoint form (single-partition scoring) and a per-texel
  endpoint form (partition fit and scoring)
All kernels are bit-exact with the scalar forms; a new parity test
compares whole compressed images byte-for-byte across every available
backend, and the PSNR corpus is unchanged.

512x512 bench: normal 0.12 -> 0.20 MPix/s, medium 0.23 -> 0.33, fast
2.05 -> 3.37 (2.2-2.5x over the quality-phase baseline).

Closes most of the single-thread speed gap to Arm astcenc at matched
quality tiers (1024x1024 photo-like, 6x6, pure coding time, -j 1):

              coding     PSNR      astcenc ref
  fast    0.30->0.17 s   47.30 dB  (-fastest 0.045 s / 47.78 dB)

Changes:
- Block-mode candidates are ranked by weight_bits + weight_count (budget
  utilization x grid resolution); fast/medium scan only the top 12/32
  viable candidates (candidates whose color budget cannot fit no longer
  consume cap slots - that bug cost 5 dB on 12x12 two-color content).
- Two-partition search: RGBA 2-means (farthest-point init, two Lloyd
  iterations) produces a block bitmap; seeds are ranked by XOR+popcount
  mismatch (hardware POPCNT when SSE4.x is present) and only the closest
  32..96 (scaled by footprint) are exactly variance-scored.

  shortlist entries; the rest rely on least-squares refinement of the
  luma-axis fit. Fast skips the redundant identity-quantizer evaluation.
- Ideal-weight quantize/unquant collapsed to per-quant-method LUTs.

(e.g. alpharamp 12x12 medium 27.9 -> 26.8 dB); normal quality is
unchanged or better (gradient 8x8 normal +1.4 dB from the ranking).

9774c0b

The normal-equation sums (Saa/Sab/Sbb and per-channel Sap/Sbp) are
pmaddwd-shaped: quadratic terms accumulate 8 texels per madd, the mixed

Ports the architecture of astcenc's compute_error_of_weight_set: at the

Real BasisLZ (KTX2 supercompressionScheme = 1) is the Basis ETC1S codec and its

data would produce files no transcoder can read. So this does NOT claim scheme=1;

    fields into codebooks; when distinct patterns exceed the cap, the most
    frequent are kept and every block is remapped to its nearest entry (byte SSE
    for endpoints, per-texel 16-weight SSE for selectors). The "UBAS" codebook
    layer is nested inside the Zstd frame and auto-detected on read, so it uses
    the zstd already vendored in tinyexr.

1024 -> 50 KB @ 24 dB, 256 -> 23 KB @ 21 dB; a cap above the distinct-block count

texcomp: RDO for the uni codebook (Lloyd refinement + optional rate t…
…
8219447

The codebook was seeded with the most-frequent patterns and assigned nearest --
good but not optimal. This adds rate-distortion optimization:

  - Lloyd / k-means refinement (8 iters): after seeding, iterate assign-to-
    nearest then recompute each centroid as the mean of its assigned blocks

Review
Heads up on methodology first: this PR is 56,907 additions across 95 files / 83 commits, adding an entirely new texture toolchain (tools/texcomp, tools/resize, tools/texpipe, tools/envmap) plus a vendored copy of Arm's astcenc. That's roughly on the same order as the entire existing codebase. A true line-by-line audit of that volume isn't realistic in one review pass, so I focused on architecture/integration risk, build/CI wiring, and spot-checks of representative files (bit-packing in texcomp_astc.c, overflow helpers in texcomp.c, Makefile wiring, licensing docs) rather than exhaustively reviewing every codec.
Scope (the main thing worth discussing before merging)
Per AGENTS.md, this repo's charter is "the pure-C11 EXR loader/writer under include/exr.h + src/*.c". Everything added here — BC1/3/5/6H/7, ETC2/EAC, ASTC LDR/HDR encoders, a separate image resizer, a texture mip/packing pipeline, and an IBL/envmap baker — has no interaction with EXR reading or writing at all; it's a general-purpose texture-compression project that happens to live under tools/. That's a legitimate, well-engineered body of work on its own merits, but it roughly triples the surface area maintainers of an EXR library now need to reason about (license mix, vendored third-party code, SIMD kernels per ISA, its own CLIs). Worth an explicit maintainer decision on whether this belongs in tinyexr long-term vs. a standalone sibling project, rather than landing as a fait accompli in one PR. If it's going to live here, I'd suggest merging the four tools (texcomp/resize/texpipe/envmap) as separate, smaller PRs so each can actually be reviewed on its own.
CI gap
The new Makefile targets (tools-test, tools-test-all, texcomp-*, resize-*, texpipe-*, envmap-*) are extensive and, per the commit messages, were run locally with ASan/UBSan/LeakSanitizer and are "all green." However, none of them appear wired into .github/workflows/*.yml, .travis.yml, or .drone.yml. As it stands, the PR description's test results are a one-time snapshot — nothing will re-run these ~29K lines of new C automatically on future pushes/PRs. Please add at least tools-test to CI in a follow-up, otherwise regressions here will go undetected indefinitely (and the "all green" claim can't be independently verified by reviewers today).
Things done well
Build integration is non-invasive: make/make all (the default target) is untouched — every new target is opt-in, so this can't break existing consumers who just build the core library.
Vendored/ported code is well attributed: tools/texcomp/NOTICE.md clearly documents provenance for astcenc, bcdec table transcriptions, Basis Universal concepts, zstd, and stb_image, each with license and specific-function attribution. That's a good model for a PR this size.
Overflow-safety discipline carries over from the core library's convention (exr_mul_ovf/exr_add_ovf) — tc_mul_ovf_size in texcomp.c gates the block-count multiply before allocation.
Real correctness engineering: a from-scratch ASTC reference decoder was written specifically to catch encoder bugs (and per the commit log, did catch three real ones — CEM 8/12 endpoint ordering, dual-plane weight interleaving, and a partition path silently overriding better encodings). SIMD kernels are tested for byte-identical parity against scalar fallbacks, and multithreaded encode is tested for byte-identical output across thread counts (and a real data race in the shared decimation cache was caught and fixed).
Smaller items
tools/texcomp is licensed Apache-2.0 while the rest of the repository is BSD-3-Clause (documented as an intentional, compatible choice in NOTICE.md). That's fine legally, but it's worth the maintainer explicitly signing off on carrying a second license in the tree, since it affects downstream redistribution obligations.
deps/astcenc is vendored as a plain in-tree copy rather than a git submodule, unlike deps/ZFP which is a submodule (.gitmodules). That's an inconsistent vendoring strategy for third-party C++ code and means future upstream security/bug fixes in astcenc have to be manually diffed in rather than tracked via submodule bump.
The core library has a fuzzing target (make fuzz, libFuzzer + corpus replay under ASan/UBSan/LSan) for hostile EXR input. The new tools' CLIs accept untrusted image files too (PNG via stb_image, DDS/KTX2 output paths) — consider whether an equivalent fuzz target is warranted for texcomp/texpipe given they're new, large, and handle external file formats, even though stb_image itself is already used elsewhere in the repo.
Given the size, I'd lean toward requesting this be split into reviewable increments (or at minimum getting explicit maintainer agreement on hosting this scope here) before merging as-is, and closing the CI gap so the extensive test suite that was clearly built for this actually runs on an ongoing basis.
