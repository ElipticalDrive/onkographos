Summary
Fork-wide review of vdb_mapping. Each finding was adversarially verified, and every change is covered by a regression test. The full suite was built and run against OpenVDB 10 / PCL 1.14 on Ubuntu 24.04 (20 → 24 tests passing); the two subtle tests were confirmed to fail without their corresponding fix. Headers are warning-clean under -Wall -Wextra -Wshadow -Wconversion and clang-format-clean.
Correctness
Half-voxel offset in fast-mode raytrace — the VolumeRayIntersector branch was missing the +0.5 cell-centered shift that every other DDA in the library uses to match worldToIndex's nearest-lattice-point rounding. Off-axis fast-mode queries traversed the lattice half a voxel off and missed obstacles lying on the ray, and returned answers that differed from the DDA fallback for the same query. Axis-aligned tests couldn't catch it.
Stale VolumeRayIntersectors after in-place mutation — addPointsToGrid, removePointsFromGrid, loadMapFromPCD, applyMapSection*, transformAndApplyMapSection*, and restoreMapIntegrity mutate the grid but never invalidated the intersectors' construction-time topology snapshot. A fast-mode raytrace before the next integration walked the stale snapshot and missed new obstacles. They now call resetVolumeRayIntersectors(), mirroring resetMap/loadMap.
OccupancyVDBMapping::setConfig — require the clamp bounds to strictly enclose the activation thresholds. clamp == threshold let a saturated voxel sit exactly at the threshold and never cross the strict activation comparison, so a saturated obstacle stayed inactive (invisible map).
Robustness / thread-safety
addPointsToGrid / removePointsFromGrid reject calls before setConfig (they wrote uninitialized log-odds otherwise).
raytrace guards zero-length / non-finite direction and ray length (NaN would propagate into the DDA / intersector), matching raycastPointCloud.
getGrid() takes a shared lock around the m_vdb_grid read so it no longer races resetMap/loadMap rebinding the shared_ptr; the caller-side locking contract is documented.
m_resolution made atomic (loadMap may overwrite it while other threads read).
applyMapSectionUpdateGrid falls back to the section's active bounding box when bb_min/bb_max metadata is absent, instead of throwing under the map lock.
byteArrayToGrid takes the buffer by const& (was copied by value).
OccupancyVDBMapping log-odds members zero-initialized in-class (defense in depth).
Build / packaging / docs
CMakeLists — use ZSTD_INCLUDE_DIR / ZSTD_LIBRARY (what FindZSTD actually defines). The plural names were undefined, so explicit zstd linkage was a silent no-op that only worked via OpenVDB's transitive zstd. zstd now links explicitly.
Add a GitHub Actions CI workflow (.github/workflows/ci.yml); the FZI GitLab CI is unreachable/inert on this fork.
package.xml: drop the redundant libpcl-all runtime meta-package.
README: fix deve/setup.bash → devel/setup.bash.
Tests
Added RaytraceFastModeOffAxisHit, AddPointsInvalidatesIntersector, DirectGridEditsRequireConfig, and ClampMustStrictlyEncloseThresholds.
Deliberately not changed
m_map_directory_path string race (low; config is set once at startup — a clean fix needs a dedicated config mutex).
Artificial-area voxels stored with value 0 + force-active is intentional so restoreMapIntegrity can drop them; changing it would break restore.
transformAndApplyMapSectionUpdateGrid additive semantics — documented as additive-only rather than silently changing merge behavior.
Notes for the vdb_mapping_ros2 wrapper
getGrid() is now lock-on-read but still returns the live grid; consumers iterating it must hold getMapMutex() in shared mode for the pointer's lifetime (or copy).
Add/remove-points and apply-section paths now correctly invalidate fast-mode intersectors; a fast-mode raytrace right after such a call falls back to exact DDA until the next integration.
