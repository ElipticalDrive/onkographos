Raised from GameTools Phase 1 planning
(docs/phase-1-map-and-space-plan.md §10). com.spartanlabs.geometry is the geometry layer both GeneralTools and WebTools consumers build on; GameTools' physics and line-of-sight work needs primitives it doesn't yet have.
Problem
com.spartanlabs.geometry (GeneralTools 2.0.1) ships only Point, Dimensions, Square
and the TwoDoubles base. It has no:
line segment or ray type;
intersection tests — segment/segment, segment/AABB, ray/AABB;
vector algebra on Point — dot, cross, length, normalized, projectedOnto.
These are geometry-generic, not game-specific. GameTools Phase 1 needs all of them for swept
collision resolution and for tile-grid occlusion raycasts, and is currently going to carry a
private com.spartanlabs.gaming.world.geometry copy as a stopgap. Better to have them where
every SpartanLaboratories/* and SpartanLabsGaming/* project can share one implementation.
Separately: Square's KDoc calls its location the top-left corner, while GameTools
treats a box's location as its centre (VisibleObject.collidesWith). Worth resolving the
intended convention here, or adding a distinct centre-origin Aabb so there is no ambiguity.
Proposed API
com.spartanlabs.geometry:
```
class Segment(val a: Point, val b: Point)
class Ray(val origin: Point, val direction: Point)          // direction need not be unit
class Aabb(val center: Point, val halfExtents: Dimensions)  // centre-origin, unambiguous

// free functions, Result-returning for degenerate input (house style)
fun segmentIntersectsSegment(s1: Segment, s2: Segment): Result<Point?>
fun segmentIntersectsAabb(s: Segment, box: Aabb): Result<Boolean>
fun rayIntersectsAabb(r: Ray, box: Aabb): Result<Double?>   // t of entry, or null

// Point / TwoDoubles vector ops
infix fun Point.dot(other: Point): Double
infix fun Point.cross(other: Point): Double
val Point.length: Double
fun Point.normalized(): Result<Point>
infix fun Point.projectedOnto(axis: Point): Point
```
Exact shapes open — this is the capability request, not a final signature set.
Alternatives & open questions
Add an Aabb vs pin down Square's corner-vs-centre semantics in its KDoc and add the
intersection helpers against Square.
Whether the vector ops belong on Point or on the TwoDoubles base.
Result vs plain returns for the degenerate cases (zero-length segment, zero vector).
Downstream follow-up
GameTools: replaces the private world.geometry stopgap with these types once released
(source-compatible — they are value types). Not a blocker — GameTools Phase 1 ships the
fallback and migrates later.
Any other consumer doing collision or LOS math benefits.

Resolved by #5 (merged to master as fc2635f), released in 2.2.0.
What shipped in com.spartanlabs.geometry
Segment(a, b), Ray(origin, direction) — line primitives. Ray.direction need not be unit length; Ray.pointAt(t) / Ray.unit() help with the t-in-units-of-|direction| convention.
AxisAlignedBox interface (min / max / center / size / contains) — the corner-vs-centre ambiguity is resolved by making the convention explicit per type rather than picking one. Square now implements it (its location is documented as the top-left / min corner; additive, no field or constructor change). CenteredBox(center, halfExtents) is the new centre-origin implementation. Convert with Square.toCenteredBox() / AxisAlignedBox.toSquare().
Vector algebra on Point (extensions in Vectors.kt): dot, cross (2D perp-dot), length, lengthSquared, normalized(): Result<Point>, projectedOnto. Shared EPSILON = 1e-10.
Intersections (Result-returning, degenerate input -> failure):
segmentIntersectsSegment -> Result<SegmentIntersection> — sealed None / Touching(point) / Overlapping(segment) (the collinear-overlap case the original Result<Point?> sketch could not express).
segmentIntersectsBox(s, box: AxisAlignedBox) -> Result<Boolean>.
rayIntersectsBox(r, box: AxisAlignedBox) -> Result<Double?> — null on miss / box-behind, 0.0 when the origin is inside, else the entry t. NaN-safe slab method.
70 Level-2 component tests. Full design writeup: docs/issue-3-geometry-primitives.md.
Also folded in
Pre-existing defect: TwoDoubles overrode equals but not hashCode, so Point / Dimensions / Square were broken as hash-based-collection keys. Fixed here (hashCode consistent with the type-sensitive equals), since the new primitives are meant to be usable as map keys.
Downstream follow-up
SpartanLabsGaming/MyGameTools can now drop its private com.spartanlabs.gaming.world.geometry stopgap and depend on 2.2.0 — tracked separately.
