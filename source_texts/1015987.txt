Motivation
Replace static prebuilt region rendering with an on-demand streaming system so terrain is generated and meshed around a moving anchor and chunks can be unloaded to save memory.
Provide an in-editor block editing tool with persistence controls to save and load chunk data from disk.
Make the region meshing code operate on a block snapshot interface to enable safe multithreaded mesh generation.
Description
Introduce WorldStreamer component that streams chunk generation, unloading, region dirty-tracking, asynchronous region meshing, and scene node management, and wire it into EditorScene via setupStreaming.
Add VoxelEditTool component with raycast-based block placement/removal, block selection hotkeys, and persistence shortcuts (F5 to save, F9 to load) that notify the streamer about edits.
Add VoxelWorldIO utilities to save/load chunk files and bulk load/save loaded chunks under a configurable path format.
Add BlockAccess interface and adapt RegionMesher to accept a BlockAccess snapshot and client overloads, plus implement SnapshotBlockAccess inside WorldStreamer to provide thread-safe block reads for meshing.
Refactor VoxelWorld and Region to track chunks/regions more robustly, add chunk removal (removeChunk), presence checks (hasChunk), region lookup (getRegion), world-space block setters (setBlockWorld/removeBlockWorld), and expose a stable key function for coordinate packing.
Update RegionRenderSystem to properly handle interrupted waits by restoring the interrupt flag instead of printing stack traces.
Clamp heights in NoiseTerrainGenerator to the valid voxel range to avoid out-of-bounds heights.
Add single-thread executor for async mesh builds in WorldStreamer, plus queueing logic for generation, unloading, mesh submissions, and applying built meshes to the scene.
Wire new components into EditorScene creating scene nodes for the streamer and voxel edit tool.
Testing
Ran automated project build and unit tests with ./gradlew build and ./gradlew test, and the test suite completed successfully.
