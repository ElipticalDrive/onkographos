I have creatively brainstormed and implemented two new features to the voxelizer engine without needing any external dependencies:
Procedural Porosity (--porous <threshold>): This introduces organic, sponge-like generation. By seeding a custom Linear Congruential Generator (LCG) with the spatial 3D grid coordinates (ix, iy, iz), we compute a stable pseudo-random value for each voxel. If this value exceeds the threshold, the voxel is discarded. This creates interesting, complex internal structures that resemble bone, sponges, or aerogels.
Concentric SDF Phasing (--concentric-phases <step>): This allows users to generate multi-material outputs (like "jawbreakers"). By taking the absolute value of the Signed Distance Field (SDF) and dividing it by a user-defined step distance, we can dynamically assign phase IDs in concentric shells mirroring the mesh surface.
Both features have been wired up through the CLI (src/main.rs) into the core parallel voxelization loop (src/lib.rs), and the test suite has been updated and verified to ensure everything works smoothly.

Reject zero/invalid concentric phase step before division
Using concentric_phases without validating it allows 0, negative, NaN, or infinite values to flow into sdf.abs() / step, which produces NaN/inf and then saturates when cast to u32 (often 0 or u32::MAX). In practice this can generate nonsensical phase IDs across the output instead of meaningful concentric shells. Please add an input check (finite and > 0) similar to the existing resolution/narrow_band guards.

Normalize porous hash to an actual pseudo-random range
The porous filter computes rnd as hash / u64::MAX, but hash is only a lightly mixed product/xor of small grid indices, so for typical voxel grids it stays many orders of magnitude below u64::MAX. That makes rnd almost always near zero, so thresholds like 0.3 or 0.8 keep nearly every voxel and the porosity feature effectively does not work. A proper hash/PRNG mixing step is needed before normalization.
