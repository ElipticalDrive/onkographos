Motivation
Ensure Flow procedural AABBs participate in the same ray visibility paths as primary opaque geometry by using the standard opaque mask.
Make Flow volumes renderable when a valid sparse AABB exists even if NanoVDB CPU import/mapping is not available on the same frame.
Provide a safe fallback world->index transform for voxelization and surface-level diagnostics when NanoVDB buffers or mapping fail.
Description
Changed the TLAS instance mask for Flow volumes from 0x02 to OBJECT_MASK_OPAQUE so Flow AABBs follow opaque object ray masks.
Kept offscreen defaults when not using the fallback 2D path and clarified the intent in a comment so offscreen metadata is preserved for Flow internals.
Replace immediate invalidation of m_volumeData.valid with a hasValidAabb check and defer NanoVDB import readiness; always mark the volume valid when a valid sparse AABB is present and log NanoVDB availability instead of turning the volume off.
Added logging for failed NanoVDB buffer acquisition and map failures, and introduced a fallback worldToIndex transform computed from m_volumeData.worldMin/cellSize used when CPU mapping of NanoVDB is unavailable.
Testing
Rebuilt the project after the changes and the build completed successfully with no compile errors.
No automated unit tests were executed as part of this rollout, and no automated test failures were observed.
