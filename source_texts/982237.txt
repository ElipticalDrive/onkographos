1. API usage
k nearest neighbours over a sampled point set.
```
import torch
from conquer3d._C import KDTree
from conquer3d.data.assets import StanfordBunny
from conquer3d.data_structure import TriangleMesh

v, f, _ = StanfordBunny().get()
mesh = TriangleMesh(v.cuda(), f.cuda().int())
mesh.fix_normals()

pts = mesh.sample_points(24_000)[0].contiguous()   # (N, 3) float32 CUDA
tree = KDTree(pts)

queries = pts[:5].contiguous()
dist, idx = tree.query(queries, k=8, exclude_self=True)
# dist: (M, k) float32 SQUARED distances -- take sqrt for a radius
# idx : (M, k) int64 indices into `pts`
radius = dist.max().sqrt()
```
Recovering a mesh whose orientation was destroyed.
```
tris = mesh.triangles.clone()                      # keep an independent copy
flip = torch.rand(tris.shape[0]) < 0.5
broken = tris.clone()
broken[flip] = broken[flip][:, [0, 2, 1]]          # reverse those windings

snapshot = broken.clone()                          # see the caveat below
bad = TriangleMesh(mesh.vertices.contiguous(), broken.int().contiguous())
bad.fix_normals()

reoriented = int((bad.triangles != snapshot).any(dim=1).sum())
recovered  = int((bad.triangles == tris).all(dim=1).sum())
```
2. Advantages
fix_normals recovers the original winding exactly, not merely a
consistent one. With half of MaxPlanck's 99,991 faces reversed at random, it
reoriented all 49,805 and matched the shipped winding on 99,991 / 99,991
faces — it picked the outward global orientation, not the flip.
KD-tree build is cheap and sublinear in practice — 400,000 points build in
3.62 ms, and query cost is nearly flat in cloud size (0.198 ms at 24k points
vs 0.293 ms at 400k for the same 4,096 queries).
Queries are batched: one call handles an (M, 3) block rather than a loop.
3. Disadvantages & trade-offs
TriangleMesh aliases the triangle tensor it is given, and fix_normals
rewrites it in place. This is the sharpest edge here. Comparing
mesh.triangles against the tensor you passed in compares it to itself and
always reports zero changes — my first measurement reported "0 reoriented"
alongside perfectly repaired normals, which is self-contradictory. Any
before/after comparison needs .clone() taken before construction. It also
means calling fix_normals() silently mutates the caller's face array.
query returns squared distances, so a radius needs a square root. The
first row I checked came back [1.2e-5, 3.8e-5, ...] against true Euclidean
[0.0035, 0.0062, ...].
The usable k is 31, not 32. The binding checks search_k <= 32, but
exclude_self=True reserves a slot internally, so k=32, exclude_self=True
raises Requested K exceeds the hardware register limit (MAX_K = 32) while
k=32, exclude_self=False succeeds. The message names a limit the call did
not exceed.
Reversed windings are invisible under normal shading. The renderer shades
two-sided, so a destroyed mesh looks correct; only encoding normal direction
as colour exposes it. Anything relying on winding for culling would be caught
out the same way.

5. Technical insights
The aliasing defect is the kind that produces a confident wrong answer.
The measurement did not error or look suspicious; it reported a plausible
"0 reoriented" that happened to contradict the normals in the same run. Worth
either documenting on the binding or having the constructor clone.
Zooming a point cloud needs the cloud filtered, not just the camera moved.
Points are drawn as world-scale cubes, so magnification enlarges every point
equally and distant ones become foreground blocks. The zoom panels render only
points inside a ball of 3.2x the k=31 radius, at 0.42x point size.
The zoom target is chosen, not hand-picked: the query with the tightest
k=31 neighbourhood, so the growth from k=4 shows against the densest sampling
rather than getting lost in sparse noise.
Column flow is the right layout for heterogeneous figures. A grid row is
as tall as its tallest member; with figures ranging from a wide 3-panel strip
to a tall 3x2 block, that guarantees dead space. columns: 3 340px also
reflows to one column without a single media query — though it fills
top-to-bottom then across, so reading order is column-major.
