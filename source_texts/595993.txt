Why
PR #284 proved the depth-4 GPU consumer is a real net slowdown on the maintained authored-Perlin witness. PR #288 then falsified the simple "proof density is too low; use depth 5" hypothesis.
Before another renderer mutation, this PR measures the geometry of the tax.
What changes
Production renderer change: none.
The native webgpu_sdf_range_perf_test now performs an untimed CPU-side census of the exact fixed-depth positive-proof bitmaps for depths 3–6 over the same horizon and 45-degree cameras.
It mirrors the shader's:
regular proof-cell ownership;
direction-sensitive boundary ownership;
selected-cell exit calculation;
192-cell horizon;
positive-bit meaning.
It reports:
sampled rays and proxy-box hits;
proof-cell classifications;
positive versus clear classifications;
positive run count and run distance;
rays that actually cross at least one positive-proof cell;
rays that pay the proxy traversal but cross no positive proof at all;
rays intersecting the single AABB enclosing all positive-proof cells;
the precision/selectivity of that possible one-AABB prefilter;
an explicit upper envelope on candidate calls if the exact marcher reached every regular-cell boundary;
classifications per hit;
useful-classification ratio and positive ray-distance fraction.
Important limitation
This is deliberately not presented as an exact runtime rangeCandidate() counter. The authored marcher can leap across clear-cell boundaries between consultations, so the geometric census is an opportunity/tax envelope.
That distinction is intentional: no shader atomics, no extra diagnostic GPU bindings, and no instrumentation contaminates the existing paired AB/BA wall-time measurements.
Decision target
The output should discriminate between three materially different next architectures:
Proof is too sparse per ray. Most proxy-hit rays never cross a lawful positive cell. Then the consumer needs a cheap admission gate before it consults the grid.
A one-AABB admission gate is selective enough. The positive-proof bounding box rejects most useless rays while retaining all possible useful ones. Then a macro-gate is a narrow, falsifiable next A/B.
Useful rays are common but successful runs are too short. Then the problem is consultation/classification cadence or proof representation, not just admission.
If this geometry still leaves ambiguity about actual runtime consultation frequency, the next rung should be a separate test-only shader-counter diagnostic, so exact counters do not contaminate the production A/B lane.
#288 remains rejected and closed; this PR does not change kSdfRangeGpuProofDepth, proof authority, or global enablement.

Architectural correction from Zach — use Prophetic Rete / Law-Direct as the precedent
Zach's direction: the proof is ahead-of-time derived state. Do not rebuild it because a frame passed. Rebuild/repair it only when a semantically relevant authored change can invalidate it.
Important source audit: the current SDF implementation already satisfies part of this doctrine.
MemoizedProgram::rangeHierarchy/rangeProofWords are revision-cached.
The theorem rebuild condition is currently bounded by !rangeReady || rangeParameterRevision != memoParameterRevision || extentChanged.
The GPU proof buffer is persistent; unchanged proof bytes are not re-uploaded after warmup.
Therefore the observed Harden SDF renderer A/B measurement with paired sampling #284/[REJECTED] Measure depth-5 SDF positive-proof traversal #288 slowdown is not evidence that Earthcall is rebuilding the range theorem every frame.
The remaining mismatch with Prophetic/Formation Rete is on consumption.
Law-side precedent:
```
Law graph
 -> ahead-of-time Prophetic abstract interpretation
 -> retained relevance/provenance
 -> Law-Direct crystallized road
 -> hot path follows the already-known road
 -> relevant semantic delta repairs/invalidate only the affected proof frontier
```
Current SDF side:
```
authored SDF/OntoMath
 -> ahead-of-time range theorem
 -> retained positive bitmap
 -> every fragment/ray still calls rangeCandidate()
 -> rangeCandidate still rediscovers profitable positive runs cell-by-cell
```
That is the key architectural distinction. We cached the theorem, but have not necessarily compiled away enough of the search required to consume the theorem.
Do not respond by resurrecting the rejected 3D DDA; that experiment already proved correct and slower. Use #292's geometry/cost evidence to decide what direct derived execution artifact can be crystallized ahead of time from the stable theorem (for example a very cheap admission structure or a sound coalesced/direct region representation), and let the shader consume that without repeated general traversal/search.
Also distinguish “Law changed” from “relevant semantic delta.” An unchanged Law can execute and change an SDF parameter; that must invalidate any proof depending on that parameter. The target invalidation rule is the same as Formation Rete's: only a relevant change should make a proof uncertain, with fail-open fallback when dependency completeness is unknown.
One additional frame-driven residue worth separating from the GPU tax: _sdfRangeNodeBatches[sp] is rebuilt in instance order each frame and then compared against its persistent GPU mirror. That is not the theorem rebuild, but it is still repeated CPU assembly of stable derived state and is a later candidate for stable GPU slices/handles.
For this PR, keep the production renderer unchanged and finish the diagnostic. The next production experiment should be chosen from the measured evidence under this AOT-crystallization rule.
