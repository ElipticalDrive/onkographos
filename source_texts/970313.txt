Second slice of molgpu-sept-mqo: marching cubes on the GPU, producing the same mesh as @molgpu/geo's marchingCubes.
How it works
Passes: a classify pass counts each cube's vertices and indices; two exclusive scans place each cube's output; an emit pass writes positions, normals and indices.
Fidelity: cube order, vertex order, winding and normals follow the CPU builder. Normals are interpolated clamped central differences, mapped through the inverse-transpose cofactor; a mirroring transform swaps the winding.
Readback: only the two totals (8 bytes) are read back, to size the output buffers.
Shared scan: internal/gpu-scan.ts is a new fold-safe exclusive scan. The SES cell list now uses it as well.
New geo export: @molgpu/geo exports marchingCubesTables() (experimental), so the GPU port uploads exactly the CPU's tables. api.txt, README and CHANGELOG are updated, with a unit test checking that the tables are consistent.
Evidence (deno task test:viewer:ses, findings updated in docs/findings/2026-10-02-gpu-ses-field.md)
