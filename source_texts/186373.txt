Flow Noise
One method for achieving a ”flow” in computer generated surfaces representing fluids is to use so-called
flow-textures which are usually based upon Perlin- or
Simplex noise. These textures are used to animate
a generated fluid surface to improve the visual realism.
While these provide the random appearance exhibited by a fluid surface they lack the basic traits of a
true fluid surface; advection and swirl.
Flow Noise [1] was introduced as an extension to Perlin noise and allows the flow-textures to be animated
over time to produce a swirling effect as well as providing the means to visually approximate advected
flow within the textures.
Simplex Noise
Simplex Noise, introduced by Ken Perlin in 2001 [3],
was presented as an improvement and replacement
to the classical Perlin Noise. It was presented to
overcome some of the difficulties the classical noise
algorithm and holds several advantages over the
classical noise, the most important being; A lower
computational complexity which scales to higher dimensions with considerably lower increase in computational cost.
The most obvious difference between classical noise
and simplex noise are the grids. The classical noise
algorithm utilizes a regular square grid in 2D and
regular cubes in 3D, while these are easy to work
with they are not optimal computational wise. Simplex noise on the other hand is operates on a space
defined by simplex grids. A simplex grid is defined as
the simplest and most compact shape which can be
repeated to fill the entire space. In 2D the simplest
shape is a triangle and this formal simplex shape for
2D is an equilateral triangle, in 3D the simplex shape
is a somewhat skewed tetrahedron [2].
The use of simplex grids as opposed to a regular
grid reduces the amount of computations needed; in
2D the evaluation of a regular grid cell requires the
lookup and evaluation of the four grid points which
make up the square. When a simplex grid is used
this reduces to evaluation of the three grid points
which make up the simplex triangle.
Generally speaking the regular shape in Ndimensions is a N-D hypercube which has 2 N corners while the simplex shape in N-dimensions is a
N-D hypercube squashed along its main diagonal,
having N + 1 corners. Thus the computational complexity of evaluating a simplex shape compared to
a regular shape decreases exponentially as higher
dimensions are used.
1.3.1
Swirl
The Perlin- or Simplex noise function can be
described as a sum of wiggle functions [2] centered
at different integer points (i, j, k). Such a wiggle
function is illustrated in 2 dimensions in figure 1.
Figure 1: Wiggle function centered at (i, j, k)
Each wiggle function, centered at a specific integer
point (i, j, k) consists of a product between a weight
kernel K and a linear function ( a, b, c) : (i, j, k). K
drops away smoothly from (i, j, k), reaching zero in
both value and gradient at unit distance from (i, j, k)
and each function ( a, b, c) : (i, j, k) has a zero value
at (i, j, k).
The sum of all overlapping wiggle function produces the noise value at a specific point ( x, y, z).

The swirling quality in flow noise is achieved
by rotating the linear vectors associated with each
function ( a, b, c) : (i, j, k ) over time. This will
effectively cause each wiggle function to rotate in
place; at any given time the result will look like
Simplex noise yet over time the rotation will give a
swirling quality to the noise.

Volume Rendering
For the purpose of this report volume rendering simply defines a volume in 3D space within which multiple samples of the flow noise function will be taken,
these will then be combined into a single pixel value.
The volume defines entry and exit points of a ray
which for each pixel of the final image will be cast
through the volume and thus define the points
( x, y, z) where samples of the noise function will be
taken.
The raycaster implemented is a so-called composite
ray caster; defining the way in which samples are
combined to form the final intensity and color value.
The use of direct ray casting through the volume also
allows for the definition of implicit objects which the
noise field can be made to interact with.

In order to perform the rotations of the underlying gradients of the simplex noise, two gradient
textures are created and sent down to the flow noise
shader. Both of the textures are made to be 256 by
256 elements and a permutation table is used as an
index into two arrays containing gradients. The
( x, y, z) - values of the gradients are stored in the
r,g,b channels of the texture and the permutation
index is stored in the alpha component. The need for
two gradient textures comes from a desire to define
a rotation plane which the rotated gradient will
lie in. Therefore two perpendicular gradients are
chosen to define the rotation plane. The permutation
table is just a random array containing the numbers
0-255 and the two gradient arrays can be seen in
appendix A.

The use of procedural flow noise textures for
simulation of turbulent flow provides a highly
customizable animation framework. The appearance of the simulated surfaces/volumes are fully
determined by a set of few parameters; amplitude,
frequency, color blending and weighting functions.
With some effort put into parameter tweaking the
procedural textures can be made to resemble, to a
high degree, physically based simulations of fluids.
On the other hand, by using flow noise textures it is
possible to define flow fields which do not in any
way resemble true fluids. These unrealistic flow
textures may provide for highly desirable visual
effects, especially since most people do not actually
experience phenomena such as explosions in real
life but rather through movies or games.
The use of a volume render as the means of visualizing the flow noise function also allows for almost
any object to be placed inside of the flow field with
little changes to the program.
Unfortunately the evaluation of 3D flow noise,
especially combined with a volume renderer, is
very expensive computational wise. As table 1
shows even at only one octave and one sample
of the volume the FPS is as low as 60. For most
applications the 2D version of flow noise is probably
enough to give the desired visual effect. It is really
only when one wants objects inside of the flow
field, interacting with the flow field, that volume
rendering would prove the better solution.
I have also found that the flow noise behaves in an
unexpected way when a higher amount of samples
are taken within the volume; figures 5 and 6 should
appear very similar but display different visual
characteristics.
