Enhancement over the twin MVP (#13). Scope note: docs/spikes/digital_twin_feasibility.md.
Theory: the Goedel/Context paper + docs/future_work_semantic_context.md.
1. Hierarchical octree occupancy (occ-trees) with distance-adaptive LOD
Represent the voxel twin as an octree, not a flat grid, and resolve
context-relevantly by distance: near objects fine, far objects coarse. This
saves compute (tree abstraction avoids paying full resolution everywhere), and
is not just an optimization, it is the same principle as the theory: "an event
announces itself abstractly at a distance, sharply up close" and physical
sub-complexity (influence de-resolves with distance). The geometric LOD is the
spatial twin of HOWC's semantic taxonomy depth.
So the system carries two coupled hierarchies on the same context principle:
semantic axis: taxonomy abstraction depth (HOWC), and
geometric axis: octree resolution depth (this issue).
Both descend deeper where the context (proximity / evidence) justifies it, and stay
coarse otherwise. Abstraction depth = a function of context relevance.
octree occupancy backend (OctoMap-style) instead of the MVP's flat/sparse grid
distance-adaptive (and optionally uncertainty-adaptive) LOD policy
measure the compute saving vs flat grid at matched near-field fidelity
2. Static vs dynamic object separation
Split the world into:
Static (road, buildings, poles, parked objects): a stable background
occupancy that does not need per-step physical prediction; can be accumulated
and cached, refreshed slowly.
Dynamic (traffic participants: vehicles, cyclists, pedestrians): the set that
actually needs the physics stepper, the forward prediction, and the
predicted-vs-observed divergence metric of Spike: physics-bounded digital-twin (voxel) MVP — the deferred 'simulation case' #13.
Benefits: big compute saving (only the dynamic set is stepped/predicted), and it is
conceptually cleaner, prediction is about what moves. HOWC's taxonomy already carries
the mover distinction (Living Being / Vehicle vs Static Object), so the static/dynamic
label can come from the semantic layer.
classify voxels/objects static vs dynamic (seed from the taxonomy + motion)
cache/accumulate the static background; step only the dynamic set
per-class dynamics priors (pedestrian vs vehicle motion models)
Relation
Builds on #13 (twin MVP). Depends on metric 3D (#1/#2). Motion/dynamic detection
overlaps #10 (Doppler/4D-LiDAR motion indicator). Semantic labels from hpercept/.

Link to sensing/redundancy (branch: digital-twin)
The static/dynamic split here is fed directly by the LiDAR-sampling mechanism now
documented in docs/spikes/digital_twin_feasibility.md sec. 7: temporal accumulation
hardens static voxels (rising confidence -> cached background), while inter-frame
displacement isolates moving objects without classification. Doppler (4D LiDAR or
radar radial velocity) is the physically independent second motion source. So the
static/dynamic label is not just semantic (taxonomy mover class) but also
sensor-derived and redundant.
