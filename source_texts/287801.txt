Addresses #71
Summary
This PR introduces rectilinear grid support and removes the scalar SimulationConfig.resolution path. The main design choice is that uniform grids are treated as a special case of rectilinear grids, not as a separate solver mode.
The solver-facing representation is now RectilinearGrid, which stores explicit physical edge coordinates:
x_edges
y_edges
z_edges
Uniform grids enter through UniformGrid(spacing=...), which is a lightweight grid policy. During placement, it resolves to a concrete RectilinearGrid. After that point, simulation code consumes one realized grid representation.
Philosophy
The goal is to avoid having two competing discretization models:
one scalar-resolution path for uniform grids
one metric-aware path for non-uniform grids
That split would make future work fragile because new code could accidentally keep using scalar spacing assumptions. Instead, this PR makes the grid itself the source of truth for physical metrics.
Uniform grids still stay efficient and simple, but they now follow the same API and data model as non-uniform grids. This should make future grid work easier to reason about and easier to test.
Key Design Choices
One realized solver grid
RectilinearGrid is the concrete grid used by solver internals. It owns:
edge coordinates
cell widths
cell centers
physical extents
face areas
cell volumes
CFL time-step calculation
coordinate-to-index snapping helpers
This keeps placement, detectors, sources, PML, exports, and update equations from each inventing their own grid math.
Separate grid policy from realized grid
UniformGrid(spacing=...) represents user intent before the final simulation shape is known.
It resolves to:
```
RectilinearGrid.uniform(shape=..., spacing=...)
```
during setup.
This leaves room for future policy objects such as AutoGrid, QuasiUniformGrid, refinement overrides, or wavelength-aware meshing, while keeping the solver backend unchanged.
No backwards-compatible scalar resolution path
This PR intentionally removes SimulationConfig.resolution.
That is a breaking API change, but it avoids maintaining two sources of truth. The replacement is explicit:
```
SimulationConfig(
    time=...,
    grid=UniformGrid(spacing=50e-9),
)
```
or:
```
SimulationConfig(
    time=...,
    grid=RectilinearGrid.custom(
        x_edges=...,
        y_edges=...,
        z_edges=...,
    ),
)
```
Physical reductions by default
Reduced detector outputs now use physical weights:
energy reductions use cell volumes
Poynting flux reductions use face areas
mode overlap uses detector-plane face areas
The old raw-sum behavior was grid-dependent and becomes misleading on non-uniform grids. A refined region should not change total energy or flux just because it contains more cells.
What Changed
Added UniformGrid as the uniform-grid policy
Made RectilinearGrid the concrete solver-facing grid model
Removed SimulationConfig.resolution
Updated placement to resolve grid policy before objects are placed
Updated real-coordinate and real-shape placement to use grid edge coordinates
Added local metric handling for Yee curls and CFL calculation
Updated field interpolation for stretched cells
Updated PML grading and Bloch phase calculations to use physical distances
Updated sources and mode solver wrappers to pass/use physical coordinates where available
Updated detector reductions to use area/volume weights
Updated geometry masks for spheres, cylinders, and polygons to sample physical cell centers
Added VTR export for rectilinear grids and kept VTI limited to uniform image-data grids
Updated examples, checks, tests, and docs-facing API usage to the new grid model
Tradeoffs
Breaking API change
Removing SimulationConfig.resolution means existing scripts must change to grid=UniformGrid(spacing=...).
This is intentional. Keeping resolution as a compatibility alias would preserve an attractive nuisance: new code could continue depending on scalar spacing and silently break non-uniform behavior.
More metric plumbing
Some code now asks the grid for physical areas, volumes, centers, and extents. This is more explicit than scalar arithmetic, but it makes assumptions visible and testable.
Performance considerations
Metric-aware code can allocate more intermediate arrays, especially for broadcasted curl scales, area weights, volume weights, and source coordinate grids.
This PR keeps the implementation correct and modular first. Follow-up optimization opportunities include:
caching common solver metric arrays
using separable 1D weights where possible instead of full 3D arrays
precomputing source/detector metric coordinates at placement time
profiling JIT-compiled update loops for metric broadcast overhead
Validation

full FDTD run on a mildly stretched grid matches uniform-grid observables
Future Work
This PR does not implement automatic meshing.
The intended future direction is to add grid policy objects that resolve to RectilinearGrid, for example:
AutoGrid
QuasiUniformGrid
wavelength-aware refinement
material-interface refinement
user mesh override regions
Those policies should stay outside the solver. The solver should continue consuming realized RectilinearGrid coordinates.

📝 Walkthrough
Walkthrough
This PR introduces a grid-based spatial discretization API, replacing scalar resolution parameters with UniformGrid and RectilinearGrid policy objects. The change enables support for non-uniform rectilinear grids throughout the FDTD solver while maintaining backward compatibility for uniform-grid simulations. Core data structures, physics calculations, object placement, detectors, sources, boundaries, and plotting utilities are updated accordingly.
Changes
Grid API Migration & Non-Uniform Grid Support
Layer / File(s)
Summary
Grid Policy Classes & Resolution
src/fdtdx/core/grid.py, src/fdtdx/config.py
UniformGrid and RectilinearGrid replace scalar resolution in SimulationConfig. New classes handle grid construction, metric computations, coordinate conversion, and CFL time-step calculation from per-axis minimum spacing. SimulationConfig adds resolve_grid(), resolved_grid, has_nonuniform_grid, uniform_spacing(), and updates time_step_duration to use grid-aware logic.
Physics & Grid Metrics
src/fdtdx/core/physics/curl.py, src/fdtdx/core/physics/metrics.py, src/fdtdx/core/physics/modes.py
Curl operations (curl_E, curl_H) gain per-axis metric scaling via _metric_scale and distance-weighted interpolation via _backward_edge_average. normalize_by_poynting_flux accepts optional area_weights for non-uniform integration. compute_mode accepts transverse_coords for non-uniform grids and passes area weights into normalization.
FDTD Initialization & Placement
src/fdtdx/fdtd/initialization.py
Grid resolution is delegated to config.resolve_grid(shape) during place_objects and _init_arrays. Conductivity scaling switches from config.resolution to conductivity_spacing computed from time-step duration. Non-uniform grid helpers (_real_length_to_grid_size, _center_to_bounds_for_grid, _real_coord_to_edge_index) support physical-coordinate constraint resolution. Index-space (GridCoordinateConstraint) and margin-based constraints are rejected on non-uniform grids.
Detector Grid Awareness
src/fdtdx/objects/detectors/*.py, src/fdtdx/objects/detectors/plotting/*.py
Detectors cache cell volumes and face-area weights during placement. New helpers (_plot_axis_centers_um, _plot_axis_edges_um, _plot_resolutions, _plot_coordinate_edges_um) provide physically-aware coordinates for plotting on uniform and non-uniform grids. plot_2d_from_slices and video plotting accept coordinate_edges_um to render non-uniform cell widths via pcolormesh. Volume-weighted spatial means replace unweighted averaging when reduce_volume is enabled.
Boundary & Source Non-Uniform Support
src/fdtdx/objects/boundaries/bloch.py, src/fdtdx/objects/boundaries/perfectly_matched_layer.py, src/fdtdx/objects/sources/linear_polarization.py, src/fdtdx/objects/sources/mode.py, src/fdtdx/objects/sources/tfsf.py
Bloch phases use physical grid extents when a resolved grid is available. PML thickness and depth computation support non-uniform grids via _compute_nonuniform_pml_depths. Source types gain transverse-edge and center-coordinate helpers (_local_edge_coordinates, _transverse_edge_coordinates, _source_resolution, _source_center_physical) for grid-aware Yee time-offset and mode-solver invocations. Bilinear interpolation (_linear_interpolate_rectilinear_2d) enables smooth source profiles on non-uniform grids.
Static Material & Device Voxel Handling
src/fdtdx/objects/static_material/cylinder.py, src/fdtdx/objects/static_material/polygon.py, src/fdtdx/objects/static_material/sphere.py, src/fdtdx/objects/device/device.py
Material voxel masks switch from discrete grid indices to continuous physical coordinates derived from grid edges. polygon_to_mask_at_points enables explicit-coordinate polygon masking for non-uniform grids. Device voxels support physical-design sizing on uniform grids and index-based sizing on non-uniform grids; overlap-weighted resampling maps design parameters to simulation cells.
Plotting & Utilities
src/fdtdx/utils/plot_material.py, src/fdtdx/utils/plot_setup.py, src/fdtdx/utils/sparams.py, src/fdtdx/conversion/vti.py
Plotting helpers compute axis edges in micrometers using RectilinearGrid.edges or uniform-spacing fallback. Material and setup plots use pcolormesh for non-uniform grids. VTI/VTR export functions accept optional grid parameters for grid-aware coordinate generation. S-parameter utilities switch to grid-based config.
Public API & Re-exports
src/fdtdx/__init__.py
UniformGrid, RectilinearGrid, and export_vtr are added to the public API and re-exported from their origin modules.
Test Coverage & Migration
tests/**/*.py
~100+ test files updated to use SimulationConfig(grid=UniformGrid(spacing=...)) instead of resolution=.... New test modules and assertions cover non-uniform grid initialization, physics calculations, detector behavior, source placement, and plotting. Integration tests validate uniform-grid equivalence and non-uniform grid physics (e.g., test_nonuniform_grid.py).

* keep grid edges as JAX arrays; convert to numpy only inside tidy3d callback

Grid edge arrays are dynamic JAX leaves (field(), not frozen_private_field()),
so under jax.jit they become abstract tracers.  The original non-uniform grid
PR passed them through np.asarray() outside the jax.pure_callback that wraps
the tidy3d mode solver, which would raise TracerArrayConversionError in any
jitted inverse-design sweep that varies the grid.

Fix: compute c0_um / c1_um in micrometres using jnp ops (fully traceable),
pass them as explicit jax.pure_callback arguments so JAX materialises them
to concrete numpy arrays before calling mode_helper, and do np.asarray()
inside the callback.  Use jnp.diff instead of np.diff for the normalisation
area weights, which are needed outside the callback.

Shape validation still works because .shape is always concrete for JAX
arrays even when the values are traced.
