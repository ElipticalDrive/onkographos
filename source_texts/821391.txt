Finding: GS-AUDIT-GPU-001 · P1 · runtime-confirmed (Phase 0). Audit record: findings.jsonl line 1 in the audit archive (snapshot 55bd3953475).
Splats are ABSENT at bilinear viewport scale 0.75 and under FSR2 at scale 1.0 whenever composite/depth_test = true — the shipped default — while every internal counter reports success. Root cause (per the audit): the ordering contract and the target contract contradict each other — the GS hook runs after _render_scene() returns, but tonemap (and FSR2, which consumes the internal texture even earlier) has already consumed the buffer the depth-tested compute composite writes. depth_test=false escapes via the framebuffer-copy branch, which is why the QA pin (GS-AUDIT-TEST-008) masks the defect in CI.
Phase-0 runtime evidence: six-config pixel matrix (c1–c6), baseline c4 (bilinear 0.75 / depth_test=true) and c5 (FSR2 1.0 / true) ABSENT; all other configs PRESENT. Harness: Z:\wt-phase0, ~80 s against any binary.
Contract decided by the maintainer, 2026-08-16: Option B — pre-tonemap/pre-upscale hook (the composite writes before every downstream consumer; the hook must precede the upscaler, not merely tonemap). Decision memo with binding conditions (a)–(d): C:\Projects\godotGS-remediation\phase2\composite-contract-decision-memo.md (local program archive). Conditions: define the splat source encoding for linear-HDR injection; scope multiview explicitly; human-eyes visual validation on real-scan content incl. the exhibition recipe and an FSR2-motion ghosting check; name the mobile-parity delta up front.
Acceptance: all six oracle configs PRESENT on both depth_test values, c1/c3 in the healthy discrimination band, TAA/MetalFX-temporal named residual risk. Fix in progress on branch gs/gpu001-composite-pre-upscale.
