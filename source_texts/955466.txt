Problem Statement
The photo renderers only offer Preetham-family skies. Preetham is a closed-form fit with turbidity as its only input; it has no atmosphere simulation, so it gives unnatural sky lighting near the horizon, weak dawn/dusk colours, and no way to add multiple scattering (it cannot be extended; a new model is required). Users rendering low-sun scenes, sunsets or interiors lit mostly by horizon sky get results that look less realistic than other tools' physically based skies (e.g. Blender's multi-scattering Nishita).
Background research (source references, unverified items marked) is in docs/research/nishita-sky-model.md, to be added to the repo.
Solution
Add a user-selectable sky model to the photo settings. "Preetham" remains the default and behaves exactly as today. A new "Nishita" model renders a physically based atmosphere (Rayleigh + Mie scattering), delivered in two phases: single scattering first, then multiple scattering using a precomputed-LUT approximation. The sun and the sky come from the same atmosphere model, so sun colour, sky colour and interior lighting stay consistent. Files saved before this change open unchanged as Preetham.
User Stories
As a user rendering a sunset, I want a physically based sky, so that horizon and twilight colours look natural.
As a user, I want to choose the sky model in the photo settings, so that I can compare models for the same scene.
As an existing user, I want Preetham to stay the default, so that my renders do not change unexpectedly.
As a user opening an old file, I want it to load as Preetham, so that nothing breaks or changes.
As a user saving a file with the Nishita model, I want the choice remembered on reload, so that I do not have to reselect it.
As a user, I want the sun colour and brightness to match the sky model, so that sun and sky do not look like they come from different atmospheres.
As a user rendering an interior lit by low-angle sky light, I want realistic horizon sky lighting, so that rooms do not get unnatural blue or washed-out light.
As a user, I want the horizon not to show the Preetham stretched/faded artefacts, so that the sky meets the ground convincingly.
As a user, I want multiple scattering, so that shadowed parts of the sky and twilight are not too dark or saturated.
As a user, I want the default Nishita view to have brightness comparable to Preetham, so that I do not need to re-tune exposure.
As a user, I want the time of day and compass north to orient the Nishita sun correctly, so that shadows match the plan.
As a user, I want sensible atmosphere controls (at least dust/aerosol density mapped from the existing turbidity setting), so that I can make hazier or clearer skies.
As a user, I want the sky-transparent and sky-through-glass options to keep working with the new sky, so that existing workflows still apply.
As a user who uses a sky texture with an observer camera, I want that behaviour to stay as it is, so that sky textures still light the scene.
As a user choosing the Sunflow renderer, I want to be told (or have the option disabled) when Nishita is unavailable, so that I am not given a silently wrong render.
As a user, I want rendering time to stay close to Preetham, so that the new sky does not make renders slow.
As a user at night or deep twilight, I want a defined, non-broken result, so that no NaN/black-or-bright artefacts appear.
As a developer, I want the sky to be a self-contained background that I can test without the renderer, so that physics regressions are caught early.
As a developer, I want old files without the new setting to deserialize and import correctly, so that compatibility is guaranteed.
As a maintainer, I want the new setting to be an optional XML attribute, so that older readers degrade gracefully.
As a maintainer, I want the saved-file version policy applied consistently, so that upstream Sweet Home 3D warnings stay accurate.
As an installer maintainer, I want any new native library to ship on all platforms, so that Nishita works everywhere Preetham does.
As a translator, I want the new labels to be in the resource bundles, so that the UI can be localised.
Implementation Decisions
Add a sky-model setting to the home environment, enumerated, with "Preetham" as value zero so that absent data in old serialized files means Preetham.
Persist as an optional XML attribute read with an optional parser; old files and old readers fall back to Preetham. Whether upstream Sweet Home 3D's reader ignores the unknown attribute is unverified and must be checked.
Whether to bump the saved-file version for the new serialized field follows the existing policy comment on the version constant; decide during Phase 0.
Expose the setting through the photo controller and a combo box in the photo panel, following the existing turbidity pattern; add localised labels.
Phase 0 (plumbing only): land the setting, persistence, UI and renderer branching with only "Preetham" selectable, to prove the round trip before any new physics.
Phase 1: a new YafaRay background of type "nishita". At construction it precomputes a transmittance table and a sky-view radiance table by marching Rayleigh and Mie scattering through a spherical atmosphere; per-sample evaluation is a table lookup, never a per-sample march. Camera-ray and light-sample evaluations are on the hot path and must be O(1).
The existing background-light mechanism is generic: it only calls the background's evaluation function and tabulates the sky once on a latitude/longitude grid for importance sampling. No change to the light core is needed, but the new background's factory must create and attach the background light itself, as the Preetham factory does.
The sun is created by the new background's factory as a sun light using the same transmittance as the sky, rather than using the Java-side Preetham sun colour. This avoids sun/sky mismatch and removes the dependency on the Preetham sun colour for this model. The ambient-occlusion tint currently derived from that colour needs a decision (see Further Notes).
The sun disc is kept out of the sky radiance and treated only by the separate sun light, to avoid under-sampling in the importance table.
Parameters flow from Java through the existing parameter-map bridge; supported value types (string, int, boolean, float, double, 3/4-element float arrays) are enough, so no bridge change is needed.
Phase 2: add the multiple-scattering LUT (isotropic-phase geometric-series approximation) folded into the sky-view table; ground albedo becomes a parameter.
Turbidity is mapped to aerosol density unless the new controls decision says otherwise.
The Sunflow renderer keeps Preetham only; selecting Nishita with Sunflow is disabled or falls back to Preetham, and must never crash.
The existing rule that a sky texture with an observer camera replaces the sky applies equally to the new model.
Implement the model fresh from the published papers rather than copying reference code, to avoid licence questions.
Calibrate default brightness to Preetham so that existing power constants stay valid.
Testing Decisions
Good tests assert externally observable behaviour only (sky colour for a direction and parameters; saved/loaded setting values), not internal table layout or step counts.
Highest seam: the new native background's evaluation function, driven directly with fixed parameters and a grid of directions, with no renderer or Java. Checks: finite and non-negative everywhere; brighter toward the sun; plausible horizon colour at several sun elevations; deterministic; sun-light transmittance agrees with the sky's; Phase 2: multi-scatter is not darker than single-scatter in shadowed regions.
Second seam: the Java home-environment persistence round trip (serialization and XML). Checks: old data without the setting loads as Preetham; the new value survives save and reload; an unknown value does not crash the renderer selection.
Rendered-image comparison, brightness calibration and sunset/twilight look are validated visually with the daylight/sunset/twilight triplet from the research notes, not by automated tests.
Prior art: existing tests under the project's test tree (to be identified when implementing); the native library has no test target today (to be confirmed), so Phase 1 may need to add one.
Out of Scope
Changing or removing the Preetham models.
A Nishita sky for the Sunflow renderer (a new Sunflow light source), unless decided separately.
Aerial perspective / atmospheric haze on distant geometry, and observer-altitude dependence (the sky is direction-only).
Volumetric clouds, stars, moon and night-sky rendering.
Fixing the unrelated null-check-after-use in the existing Preetham background factory (separate issue).
Further Notes
Open questions from the research: reuse the turbidity spinner for aerosol density or add new controls (albedo, air/dust density); new plugin library versus adding to the existing sunsky plugin (packaging versus tidiness); whether sun transmittance is also computed in Java to tint the ambient-occlusion colour; whether physically accurate night/twilight below the current sun cutoff is wanted; and whether to bump the saved-file version.
Unverified in the research (no web access): paper details, licences of reference implementations, upstream XML-reader tolerance of unknown attributes. Verify before relying on them.
Packaging scripts that list plugin libraries were not checked.
Rough effort: Phase 0 small, Phase 1 moderate, Phase 2 moderate; no estimate has been validated.
Full research notes: docs/research/nishita-sky-model.md.
