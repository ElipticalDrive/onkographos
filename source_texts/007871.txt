This document covers the ray casting and ray marching rendering techniques implemented in the repository. These systems demonstrate different approaches to 3D-style rendering: basic 2D ray casting with wall collision detection, optimized DDA (Digital Differential Analyzer) grid-based ray casting, and 3D ray marching using signed distance functions.
For 3D model loading and traditional rasterization techniques, see 3D Model Loading. For ray tracing implementations, see Ray Tracing.
System Overview
The repository implements three distinct ray-based rendering approaches, each with different use cases and performance characteristics:
```

```

Basic Ray Casting Implementation
The basic ray casting system implements a 2D raycaster with wall collision detection and dynamic lighting effects. This approach is similar to classic games like Wolfenstein 3D.
Core Data Structures
StructurePurposeKey Fields
rayRay definitionstart, dir, length
wallWall segmentstart, end
Rendering Pipeline
```
rl.GetMousePosition()cast_rays()Ray Loop (360 degrees)angle_to_direction()rl.CheckCollisionLines()Triangle GenerationMask Render TextureGame Screen RenderShader CompositionFinal Output
```
The system uses a dual-texture approach where game elements are rendered to one texture and lighting masks to another, then composited using the screenspacemask.fs shader.
Key algorithm in 3D/ray/casting/basic/main.odin143-202:
```
cast_rays :: proc(center_point: rl.Vector2) {    // Cast 360 rays from center point    for i := 0; i < 360; i += 1 {        ray := ray{            start = center_point,            dir = angle_to_direction(f32(i)),            length = RAY_LENGTH,        }        // Check wall collisions and build triangulated light mask    }}
```
Sources: 3D/ray/casting/basic/main.odin14-33 3D/ray/casting/basic/main.odin143-202 3D/ray/casting/basic/assets/shaders/screenspacemask.fs
DDA Ray Casting Implementation
The DDA implementation provides an optimized grid-based raycasting algorithm that efficiently traverses a 2D grid to detect wall intersections.
Algorithm Components
```
NoYesRay Setupray_dir = normalize(target - start)ray_unit_step_size calculationStep Direction CalculationInitial ray_length_in_1dDDA Traversal LoopCompare X vs Y ray lengthStep to next grid cellCheck grid[map_check.y * MAP_SIZE.x + map_check.x]Tile Found?End Ray
```
Key constants and variables:
CELL_SIZE: rl.Vector2 : {16, 16}
MAP_SIZE: IVector2 : {32, 32}
grid := [i32(MAP_SIZE.x * MAP_SIZE.y)]int{}
The DDA algorithm efficiently steps through grid cells by comparing accumulated ray lengths in X and Y directions, implemented in 3D/ray/casting/dda/main.odin89-110
Sources: 3D/ray/casting/dda/main.odin13-19 3D/ray/casting/dda/main.odin50-110
Ray Marching Implementation
Ray marching uses signed distance functions (SDFs) to render complex 3D shapes entirely in a fragment shader. This technique enables procedural geometry and complex Boolean operations.
Signed Distance Functions
The system implements several primitive SDFs:
FunctionPurposeImplementation
sdPlaneInfinite planereturn p.y;
sdSphereSphere primitivereturn length(p)-s;
sdBoxBox primitiveComplex distance calculation
Boolean Operations
```
SDF Object 1opU() - UnionSDF Object 2SDF Object 3opS() - SubtractionSDF Object 4Combined SceneRay Marching LoopFragment Color
```
Shader Uniforms
The ray marching shader receives several key uniforms:
viewEye - Camera position
viewCenter - Look-at target
runTime - Animation time
resolution - Screen resolution
The main ray marching loop in 3D/ray/marching/assets/raymarching.fs167-190 steps along rays, sampling the scene's signed distance function until surface intersection or maximum distance.
Sources: 3D/ray/marching/assets/raymarching.fs44-75 3D/ray/marching/assets/raymarching.fs167-190

The three systems demonstrate different trade-offs:
Basic Ray Casting: Simple implementation, good for learning, supports dynamic lighting
DDA Ray Casting: Optimized for grid-based worlds, efficient traversal, interactive editing
Ray Marching: Most flexible, supports complex shapes and operations, GPU-intensive
