"I used the BSP tree for rendering things, but I didn’t realize at the time that it could also be used for environment testing." — John Carmack, DOOM source release README (1997) "With ‘unlimited’ CPU power, modern ‘node builders’ don’t build REJECT anymore." — Fabien Sanglard, Game Engine Black Book: DOOM (2018) ___________________________________________________________ Abstract In December 1993, id Software released DOOM. This paper presents a structural analysis of its engine as the first working real-time autonomous system. The engine contains three spatial reasoning systems, each built offline from environment geometry and consumed at runtime: a BSP tree for hierarchical perception, a blockmap for collision detection, and a REJECT table—a precomputed bit array that encodes, for every pair of regions, whether any line of sight between them is geometrically possible. The REJECT table is the critical distinction between a reactive system that processes everything and an autonomous system that knows what to skip. The paper traces the implementation through the released source code, demonstrates that the original was the only geometrically correct REJECT implementation, and documents how the architectural insight was subsequently abandoned by the toolchain that depended on it.
