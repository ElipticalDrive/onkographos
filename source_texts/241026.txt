Current scope — 2026-10-05
Multiple ownership/helper extractions have merged, including the W0 inventory and streaming/state seams; the historical pending_renderer/static-cache recipes must not be repeated. The renderer frame-entry, public TileResourceController state and broad resident publisher remain live boundaries. Old file-size and “open PR” claims are snapshots rather than current status.
Remaining / next action: Use the current leaf tasks (#108, #223–#228) and refreshed ownership inventory. Preserve the recorded requirement that behavior-sensitive/GPU decomposition starts only behind executable, failure-capable evidence; coordinate outstanding lane enforcement with #519/#1166.
Source anchors: modules/gaussian_splatting/renderer/gaussian_splat_renderer.cpp:2359; modules/gaussian_splatting/renderer/tile_render_resources.h:111.
Reviewed by source inspection at ab74e332aa8264ab6d0bfb2dc45ee83778a9e293; runtime/GPU evidence was not re-executed. The original report below is retained for provenance; its old file positions and absence claims are historical.
Render engine goal
GodotGS should be a production-realistic Gaussian Splatting renderer for Godot: explicit stage contracts, deterministic GPU resource ownership, debuggable route/fallback behavior, and performance claims backed by repeatable GPU/runtime evidence. The target is reliable rendering under real projects, not happy-path screenshots or green checks that hide skipped coverage.
Issue goal
Reduce renderer architecture risk by splitting giant orchestration around real ownership boundaries: frame route selection, stage execution, resource lifetime, diagnostics, streaming, compositor, and editor/runtime integration.
Problem
The codebase has made progress toward staged ownership, but the live module still contains very large orchestrators and hidden mutable state. That raises review cost, makes failure paths hard to reason about, and turns every feature addition into a risk of touching unrelated state.

Done when
Renderer facade methods delegate to small owned services with explicit input/output contracts.

Out of scope

Proposal: Renderer Ownership Decomposition
Render engine goal
GodotGS should be a production-ready Gaussian Splatting renderer: explicit contracts at every render stage, deterministic GPU resource lifetime, behavior preserved under editor/runtime/world-submission paths, and changes accepted only with real GPU/runtime evidence plus maintainable ownership boundaries.
Current code reality
High confidence: the issue goal is valid, but parts of the linked ownership inventory are stale. The live tree is already past some W1 items. GPUSortingPipeline now exposes set_sort_result_sink() / set_sort_buffer_host_context() and stores those seams at modules/gaussian_splatting/interfaces/gpu_sorting_pipeline.h:62-64,247-248; ensure_sort_buffers() uses the host context instead of taking a renderer pointer at modules/gaussian_splatting/interfaces/gpu_sorting_pipeline.cpp:1187-1319. TileRenderer also now owns subgroup_support_cache and adaptive_overlap_budget_runtime_state as members, not process-global maps, at modules/gaussian_splatting/renderer/tile_renderer.h:423,430-431. Do not implement the old pending_renderer / process-global-cache cleanup literally.
High confidence: GaussianSplatRenderer remains the composition root and facade bottleneck. It still exposes public mutable state buckets and owns the orchestrator graph at modules/gaussian_splatting/renderer/gaussian_splat_renderer.h:621-651, while FrameStateProvider can hand out broad mutable access to sorting, streaming, debug, config, resource, frame, performance, and subsystem state at modules/gaussian_splatting/renderer/gaussian_splat_renderer.h:483-529. Constructor wiring still passes this, runtime ports, and state pointers into many orchestrators at modules/gaussian_splatting/renderer/gaussian_splat_renderer.cpp:866-1013. This is decomposition progress, but not an ownership inversion yet.
High confidence: render-thread dispatch has already been extracted to a real service, but the facade still owns call-site policy. IRenderThreadDispatcher owns mutex/semaphore/request state at modules/gaussian_splatting/interfaces/render_thread_dispatcher.h:10-25,44-51, and the facade delegates through _dispatch_call_on_render_thread_blocking() / _notify_render_thread_dispatch_completed() at modules/gaussian_splatting/renderer/gaussian_splat_renderer.cpp:785-794. Remaining work is call-site ownership and teardown/data-submit policy, not moving mutex fields out of the renderer again.
High confidence: render_scene_instance() is still the largest runtime decision knot. It owns per-frame cleanup, no-device reset, camera source selection, debug statics, route-policy diagnostics, resident/streaming route choice, and typed skip publication in one function at modules/gaussian_splatting/renderer/gaussian_splat_renderer.cpp:2208-2427. Related refactor: separate debug logging from render routing in gaussian_splat_renderer #226 is correct in spirit, but the fix should be a route/frame-entry seam, not just extracting debug logging.
High confidence: RenderPipelineStages is the right stage boundary, but it still carries broad renderer dependency. prepare_frame_context() builds RenderFrameContext::FrameDeps by reaching back into the renderer and mutable state buckets at modules/gaussian_splatting/renderer/render_pipeline_stages.cpp:727-814; execute_frame_entry() mutates stage state and handles cull-sort cascade behavior at modules/gaussian_splatting/renderer/render_pipeline_stages.cpp:818-997; render_sorted_splats_with_context() resets raster/GPU metrics and output cache state at modules/gaussian_splatting/renderer/render_pipeline_stages.cpp:2537-2604. The stage API is useful, but the implementation is still a broad orchestrator.
High confidence: sorting has residual renderer ownership leaks even after the sink/host seam. InstancePipelineInputs still carries owner_renderer at modules/gaussian_splatting/interfaces/gpu_sorting_pipeline.h:21-41, and RenderSortingOrchestrator binds the pipeline sink/host directly to the renderer at modules/gaussian_splatting/renderer/render_sorting_orchestrator.cpp:120-126. The sort frame context still publishes raw pointers into renderer-owned state at modules/gaussian_splatting/renderer/render_sorting_orchestrator.cpp:128-155, and instance buffer validity/generation still comes directly from the renderer at modules/gaussian_splatting/renderer/render_sorting_orchestrator.cpp:719-735.
High confidence: scene ownership and node integration are real external contracts, not incidental plumbing. The scene director owns shared renderer creation and world-submission restore/apply sequencing at modules/gaussian_splatting/core/gaussian_splat_scene_director.cpp:392-433, generation domains at modules/gaussian_splatting/core/gaussian_splat_scene_director.cpp:2028-2044, visible/shadow-pruned vs registered asset collection at modules/gaussian_splatting/core/gaussian_splat_scene_director.cpp:2960-3021, and world-submission instance rows at modules/gaussian_splatting/core/gaussian_splat_scene_director.cpp:1627-1687. Node-side renderer settings ownership is guarded by a process-global owner map at modules/gaussian_splatting/nodes/gaussian_splat_node_helpers.cpp:33-78 and applied through renderer-wide setters at modules/gaussian_splatting/nodes/gaussian_splat_node_helpers.cpp:1284-1428. Any decomposition that breaks shared renderer arbitration is a regression.
Medium confidence: related tickets should be sequenced as leaf cleanups, not treated as the architecture spine. refactor: extract shared lighting/effector settings reader from render_pipeline_stages #221, refactor: decompose publish() in resident_instance_contract_publisher #223, refactor: extract buffer sizing and sort dispatch from tile sort pipeline #224, refactor: separate debug logging from render routing in gaussian_splat_renderer #226, and refactor: simplify render_tile_fallback parameter setup #228 are useful because they reduce concrete complexity in hot renderer files. Follow-up: encapsulate TileResourceController state and document ownership delegation #108 is still relevant for resource-controller encapsulation, though the tile resource seam already exists. Rename show_performance_hud property to reflect telemetry semantics #129, Retain get_render_stats() Dictionary API through alpha #130, and Add explicit renderer/viewport selection to performance monitors #132 are public API/monitoring constraints that should shape tests. Refactor tile_binning.glsl into focused helpers #57, Reduce GaussianData responsibility growth #62, and LOD system uses std::unique_ptr for octree children — inconsistent with Godot patterns #66 are maintainability notes but not blockers for this renderer ownership plan.
Proposed solution
W0: refresh the ownership map before code movement. Update docs/architecture/stage-first-ownership-inventory.md and docs/architecture/gaussian-renderer-refactor-memory.md against the live tree. Mark as already done: IRenderThreadDispatcher, ISortResultSink, ISortBufferHostContext, member-owned tile overlap/subgroup state. Mark as still open: broad mutable FrameStateProvider, route/frame-entry ownership, residual instance-buffer sorting seam, node settings ownership, resident publisher complexity. This should be a docs + characterization PR only.
PR 1: pin behavior with characterization tests. Before moving code, add/strengthen tests around: route UID/stage cascade invariants, no silent resident/streaming fallback bounce, sort fallback route semantics, instance pipeline generation/reset semantics, shared renderer owner blocking, render-thread dispatcher timeout/recovery, and resource-owner rejection. Existing anchors include modules/gaussian_splatting/tests/test_renderer_pipeline.h:735-768,2621-2650,4075-4199, modules/gaussian_splatting/tests/test_scene_director_submission_scaffolding.h:102-120, and modules/gaussian_splatting/tests/test_render_device_manager_ownership.h:28-120.
PR 2: extract frame entry / route control from GaussianSplatRenderer without changing routing. Introduce a small RenderFrameEntryController or RenderRouteController that owns per-frame housekeeping, no-device reset, camera/view extraction, FrameBackendPlan evaluation, and typed skip publication. It should call the existing resident/streaming/stage APIs through explicit ports. Invariant: render_scene_instance() becomes facade glue; route UIDs, get_render_stats() keys, and skip reasons stay byte-for-byte compatible unless a test update proves an intentional correction.
PR 3: narrow frame state access contracts. Keep FrameStateProvider as an adapter temporarily, but stop handing broad IFrameMutationAccess into stages that only need one bucket. Split stage inputs into read-only snapshots plus explicit command/sink interfaces for metric publication, output-cache invalidation, and cull/sort state writes. Invariant: each stage gets the minimum write surface needed for that stage, and no new stage receives GaussianSplatRenderer * just for convenience.
PR 4: finish the sorting ownership seam. Replace InstancePipelineInputs::owner_renderer and direct renderer->has_instance_pipeline_buffers() / generation reads with an IInstancePipelineStateView or immutable InstancePipelineSnapshot supplied by the frame context. Keep ISortResultSink and ISortBufferHostContext; add only the missing execution/context interface if needed. Invariant: GPUSortingPipeline public API must not need GaussianSplatRenderer; sort output, route UID, readback, and cross-device ownership behavior remain unchanged.
PR 5: decompose resident contract publishing (refactor: decompose publish() in resident_instance_contract_publisher #223) around owned products. Split asset collection, atlas build, buffer allocation/tracking, instance/grading build, and final contract validation. Preserve the generation split at resident_instance_contract_publisher.cpp:235-271 and the owner checks at :273-295. Invariant: visibility and shadow-caster flips must not repack the resident atlas; instance-only generation changes must not upload atlas buffers.
PR 6: finish resource and tile cleanup as bounded leaf work. Encapsulate TileResourceController state (Follow-up: encapsulate TileResourceController state and document ownership delegation #108), then handle refactor: extract shared lighting/effector settings reader from render_pipeline_stages #221/refactor: simplify render_tile_fallback parameter setup #228/refactor: extract buffer sizing and sort dispatch from tile sort pipeline #224/refactor: deduplicate common binning uniform construction #225 as local extractions. These are worthwhile only after the core route/state seams are pinned, because otherwise they can produce churn without reducing ownership risk.
PR 7: node/director boundary cleanup only after renderer seams are stable. The node settings owner map and renderer-wide setter behavior should not be pulled into renderer refactors prematurely. Later work can move settings authority toward the scene director or explicit per-instance config, but only with compatibility tests for saved scenes and shared-renderer peers.
Implementation invariants:
One mutable owner per state bucket per frame.
GPU RIDs are allocated, tracked, and freed through one declared owner/service.
Route decisions produce explicit route_uid, cull_route_uid, sort_route_uid, stage status, and fallback reasons.
No silent fallback-for-fallback paths.
No public facade/API break unless covered by a migration issue.
No extraction PR may change visual output, buffer ownership, or route semantics without GPU/runtime proof.
Tests, benchmarks, and docs
Add a current ownership-map doc PR first; the existing inventory is useful but no longer fully current.
Keep C++ characterization tests close to the changed seam: test_renderer_pipeline.h, test_gpu_sorting_pipeline_readback.h, test_scene_director_submission_scaffolding.h, test_render_device_manager_ownership.h, test_gaussian_splat_node.h.
Add focused tests for each new seam: route controller emits identical stats, frame-state access does not expose unrelated mutators, sorting snapshot reset clears instance inputs/readback state, resident publisher generation split avoids atlas repack on visibility/shadow-only changes.
Run module tests plus GPU-tagged lanes for ownership/RID lifetime. Do not accept CPU-only green checks for PRs touching RenderDeviceManager, TileRenderer, GPUSortingPipeline, OutputCompositor, or resident publisher buffers.
Runtime validation should include the existing Godot runtime probes that read get_render_stats() / route UIDs: tests/runtime/test_mixed_residency_routing.gd, tests/runtime/test_world_streaming_gate.gd, streaming churn/stress probes, and benchmark lanes that reject forbidden CPU sort routes.
Benchmark evidence should compare before/after get_render_stats() snapshots and production metrics, including gpu_tile_overlap_sort_time_ms, raster timings, visible/sorted counts, route UIDs, and resident/streaming backend fields.
Docs to update with each slice: docs/architecture/stage-first-ownership-inventory.md, docs/architecture/render-pipeline.md, and docs/architecture/gaussian-renderer-refactor-memory.md. The docs should state what remained intentionally coupled, not just what was extracted.
Risks and unknowns
The current branch is dirty and multiple agents are active; line evidence above is from the current checkout, not necessarily a stable merge base. Freeze/refresh W0 before assigning implementation PRs.
Stale docs can cause duplicated work. The old inventory says pending_renderer and process-global tile caches are live; current code says otherwise.
Route and diagnostics fields are downstream contracts. Retain get_render_stats() Dictionary API through alpha #130 confirms get_render_stats() still has consumers, and runtime scripts read route UIDs directly, so renaming/removing fields during decomposition is high risk.
Multi-instance monitoring (Add explicit renderer/viewport selection to performance monitors #132) is still unresolved. Avoid baking a new single-active-renderer assumption into any extracted diagnostics or route-controller service.
Sorting and resident publisher changes are GPU-lifetime sensitive. CPU doctests can prove structure, but they cannot prove RID ownership, async readback ordering, or visual equivalence.
Node settings ownership remains global and renderer-wide in places. Moving it during renderer decomposition would broaden scope into saved-scene/editor compatibility and should be a later explicit issue.
Go / no-go recommendation
Go for implementation only after a W0 refresh + characterization PR lands. The architecture direction is ready: decompose around live ownership seams, preserve the facade externally, and land small proof-backed PRs. No-go for a broad rewrite or for implementing the old inventory literally. The first coding PR should be route/frame-entry extraction with behavior pinned; sorting/resident publisher work should follow only after tests prove current route, generation, and GPU ownership contracts.

Review: Renderer Ownership Decomposition Proposal
Verdict
APPROVE WITH REQUIRED CHANGES
What is strong
The proposal is grounded in the live code, not just the stale ownership inventory. It correctly calls out that pending_renderer and the old process-global tile caches should not be implemented literally anymore.
The decomposition target is the right ownership seam: keep GaussianSplatRenderer as the external facade while moving frame-entry routing, frame-state mutation, sorting inputs, and resident publishing behind narrower contracts.
The staged PR order is production-oriented: W0 inventory refresh, characterization tests, then route/frame entry, state-access narrowing, sorting seam, resident publisher, and only then leaf cleanups.
It explicitly protects external contracts: shared renderer arbitration, world-submission restore/apply behavior, node settings ownership, get_render_stats() fields, route UIDs, and GPU/RID lifetime evidence.
Required changes before implementation
Treat W0 and the characterization PR as hard prerequisites, not advisory setup. The first PR must refresh docs/architecture/stage-first-ownership-inventory.md against the live tree and remove stale implementation anchors for pending_renderer, static tile overlap state, static subgroup cache, and renderer-owned render-thread dispatch fields.
The characterization PR must land before the route-controller extraction. At minimum it should pin route UID/stage cascade behavior, no silent resident/streaming fallback bounce, sort fallback semantics, instance generation/reset behavior, shared-renderer settings ownership, render-thread dispatcher timeout/recovery, and resource-owner rejection.
Define the RenderFrameEntryController / RenderRouteController contract before moving code: inputs, outputs, state it may mutate, who publishes typed skip metrics, who owns output-cache reset, and who calls streaming end_frame() on early exits. Do not let the new controller receive GaussianSplatRenderer * as a convenience escape hatch.
Add an explicit acceptance rule for stats compatibility: route_uid, sort_route_uid, cull_route_uid, missing flags, backend policy fields, and route/fallback reasons remain stable unless a PR states and tests an intentional contract change.
Implementation risks to watch
The checkout is dirty and multiple agents appear active; line anchors and “already done” claims can drift. Refresh W0 against the branch/commit actually used for implementation.
FrameStateProvider can easily become a renamed god-object. Each extraction should replace broad IFrameMutationAccess with a small sink/snapshot for the specific stage.
Sorting still has renderer lifetime and instance-buffer coupling. Replacing owner_renderer without proving async readback ordering, generation reset, and cross-device buffer ownership would be a regression risk.
get_render_stats() and route UID fields are live runtime/test contracts, not internal debug strings. Renaming or normalizing them during decomposition will break downstream probes.
Scene director and node settings ownership are real external contracts. Moving them in the same PR as renderer decomposition would broaden scope into saved-scene/editor compatibility.
CPU-only tests are insufficient for PRs that touch RenderDeviceManager, TileRenderer, GPUSortingPipeline, OutputCompositor, or resident publisher buffers; GPU/runtime evidence is required.

Each ADR's behavior-preservation evidence reduces to "the existing suites stay green" — and in every case those suites are satisfiable by executing nothing. This is the repo's documented dominant failure mode, sitting directly under the evidence gate of its largest planned refactor.
Consequence for this issue
No decomposition slice touching gated or GPU-dependent behavior should start until its tests can fail. Refactoring the most subtle logic in the module behind a green light that means nothing is strictly worse than leaving it alone: it converts an unknown risk into a confidently mis-measured one.
Concretely, three prerequisites — all R1, none of them refactors:
GPU harness v1 cannot run [SceneTree]+[RequiresGPU] tests (26 cases deferred) #329 — land the deferred [SceneTree]+[RequiresGPU] batch. Acceptance must be executed count > 0, attached as evidence. A green run with zero executed cases is a failure.

Independent review of my own summary: blocker HOLDS, but three of my supporting details were wrong
I sent a review agent to attack the four decomposition plans and my summary of them. It confirmed the program blocker and refuted or corrected four specific claims, including one I amplified myself. Corrections first, since wrong details in a blocking recommendation are worse than no details.
Correction 1 — my prerequisite 3 is a NO-OP
I recommended "drop --skip-cpp from the R2 streaming evidence command, or add a C++ lane that fails on skip." The first half does nothing. .agentic/policy.json:64,:88 does carry --skip-cpp --fail-on-skip, but the streaming-gpu-ci profile has "cpp_tests": [] (tests/runtime/runtime_scenarios.json), and should_run_cpp_harnesses (run_runtime_validation.py:1078) is already false on an empty list. Removing the flag changes nothing.
The prerequisite is only the second half: a C++ lane must be added.
Correction 2 — the skip-guard claim was overstated
I wrote "21 early-return guards that report green having asserted nothing, inside a strict lane." Actual: 19 bare returns, of which only 8 are in tests that run in the strict [SceneTree] lane. The other 11 are in [World]/[RequiresGPU] tests that run in no lane at all — so "inside a strict lane" does not apply to them.
And they do not assert nothing: each executes 5–7 CHECK/REQUIREs before the guard, then skips 3–25 downstream assertions. That is partial vacuity. Still a real defect — the skipped assertions are the ones covering the hazards a decomposition must preserve — but I overstated both the count and the severity.
Correction 3 — "#609 contains an already-merged slice" is only PARTIALLY true
#627 (merged today, closes #528) covers S1's metric-reset half plus the parity guard, but not S1's diagnostics-dict / route-label key-set guards — which the ADR makes its exit criterion R9. Neither render_diagnostics_orchestrator.cpp nor render_route_labels.cpp was touched. It also shipped 5 composable reset_*() helpers rather than the single PerformanceMetrics::reset() S1 specifies.
So S1 should be re-scoped, not deleted.
Correction 4 — a claim I amplified is flatly REFUTED
My "#608's flagship matrix test would be vacuous on default node state" is wrong. painterly/enabled is explicitly exempted from the shadowing rule (gaussian_splat_node_3d.cpp:540), and the debug/ rule is #ifndef DEBUG_ENABLED — compiled out under CI's dev_build=yes. 5 of 7 names discriminate on defaults. Full correction on #608.
Where the plans UNDERSTATED — the blocker is sharper than I reported
Streaming skip sites: 96, not 29. My narrower grep undercounted by 3.3×. 33 of 54 cases carry a skip guard.
46 of 54 streaming cases sit in a strict=False lane (run_module_tests.py:136) — their failures do not fail CI at all. That is a sharper finding than "they skip."
[SceneTree]+[RequiresGPU] is now 28 module-wide, not the 26 the harness comment claims — and deferred_requires_gpu_waivers in docs/reference/renderer_release_gate_manifest.json is an empty list, so GPU harness v1 cannot run [SceneTree]+[RequiresGPU] tests (26 cases deferred) #329's deferral is recorded only in a code comment, not in any live manifest. The deferral is invisible to tooling.
Embedded sorter GLSL (radix/bitonic/remap) is invisible to the C5 shader-permutation compile CI #525 needs more than a paths: entry. The shader-validation step drives compile_shaders.py over .glsl files; adding gpu_sorter.cpp to paths: would trigger the job but still not validate GLSL embedded in a C++ string literal. The GpuSorting batch also matches 0 test cases today.
Coverage that does exist, which the plans missed
The streaming-gpu-ci profile runs 3 blocking GDScript GPU scenarios with fail_on_skip: true — GPU Streaming Stress, World Streaming Gate, Streaming Residency API. R2 streaming evidence is not entirely inert. There is also a non-strict [requires-RD] catalogue lane.
Net position
The blocker holds. Four independent mechanisms; three confirmed as stated or stronger; one (matrix vacuity) refuted. The recommendation is unchanged: no decomposition slice touching gated or GPU-dependent behavior should start until its tests can fail — with prerequisite 3 restated as "add a C++ streaming lane," not "drop a flag."
Verification method worth noting: the reviewer re-implemented doctest wildcard semantics rather than using fnmatch (only */? are special; [tags] are literal — the repo warns about this at run_gpu_harness.py:75-79). Lane-coverage claims computed with fnmatch are unreliable, which is likely how the [World] orphan survived earlier audits.
