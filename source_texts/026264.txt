Goal
Implement visually convincing, interactive, voxel-density volumetric smoke using the existing strict-WebGPU/Three.js TSL renderer. This is a local smoke feature, not the return of the current far-distance atmospheric fog. The smoke must be visibly three-dimensional, light-aware, and respond to bullets/air movement without scaling cost linearly with overlapping alpha billboards.
Architecture / integration
Use bounded world-space 3D density volumes (or a more efficient equivalent after a measured spike); GPU storage/compute update if supported by the pinned Three.js build, with bounded memory, dispatches, and active volumes. Start with one volume; scale only after profiling. Validate actual Storage3DTexture/TSL API support before committing to it; no runtime network dependency.
Drive density from reproducible emission + advection + dissipation. Start with an analytic/static voxel-density visual baseline, then add evolving density; expensive full Navier–Stokes simulation is not required.
Render with depth-terminated volumetric integration (extinction and in-scattering), approximate directional lighting, and reuse existing CSM shadow information where practical. Avoid double-blending alpha sprite smoke and voxel smoke at the same location; preserve non-smoke sparks, dust, haze, decals, and other FX.
Reuse the world linear-depth contract and integrate into src/render/webgpu-pipeline.ts after world TAA and before heat haze / separate first-person view, consistent with ARCHITECTURE.md. If rendering at reduced resolution, explicitly plan depth-aware upsampling and dedicated temporal stability; world TAA resolves before volumetrics today and cannot automatically stabilise a new smoke pass.
Prefer one reusable FX smoke-emitter API so normal grenade/explosion FX can demonstrate the system, plus a deterministic test/demo spawn. Do not add a new smoke-grenade shop item or overhaul weapon economy in this issue.
Interaction
Consume reached-path bullet:segment events (src/core/events.ts), not inaccurate muzzle-to-target rays, to cut transient, visible channels through smoke; recover density naturally. Repeated hits should not grow unbounded work.
Smoke advects with authored wind/turbulence; explosions/impulses can visibly perturb a bounded region, with seeded/deterministic replay controls.
Avoid glaring smoke-through-wall leaks. Start with a bounded/coarse obstacle representation backed by the existing authored collision/BVH when feasible, document limits and provide representative doorway/wall checks. Do not accidentally mutate navigation/collision data.
Ensure lighting changes with time of day / existing sun/moon, and nearby lights if feasible with a bounded budget. Preserve opacity and compositing against world geometry and the first-person weapon.
Reset/clear simulation on restart; respect paused time, allocation limits, active-volume lifetime, resize and device loss. Do not introduce per-frame CPU readbacks or runaway CPU uploads.
Quality and performance
Provide an optional quality-controlled smoke density/resolution/step budget (and safe disabled mode); budget is independent of the old atmospheric fog.
Measure smoke-disabled, 1 cloud, multiple clouds and bullet-intensive scenes on identical browser/hardware settings (warmup, GPU pass costs where available, CPU render/submission, frame pacing and overdraw). Do not promise the video-demo's frame-time gains.
Compare final-output frames against existing particle smoke and against a clean scene, including daylight/backlit/night, cover/doorways, moving camera, and bullet-cut passages; inspect flicker, ghosting and banding.
Investigate shared ray march vs extra volumetric pass, half-resolution integration, and compute vs material TSL based on measurements rather than building a speculative renderer rewrite.
Done when
Normal gameplay or a reproducible in-game scenario visibly produces a voxel smoke cloud, with documented spawning API.
Smoke has depth-aware extinction, illuminated volume and stable motion; bullets produce temporary visible holes/trails along real reached trajectories.
Adequate wall/occlusion handling; no obvious clipping through the player weapon, geometry or sky; existing sparks/haze unaffected.
Deterministic test scenario, debug controls/telemetry, screenshots or video comparison, correctness and resource-lifecycle tests, and matched performance report.
npm test, npm run typecheck, npm run lint, npm run format:check, npm run build pass from clean install.
Reference: Digital Foundry Infinity Ward engine deep-dive: https://youtu.be/VVSw3qgy3Nc . Inspiration only: do not claim to reproduce a proprietary smoke algorithm.
