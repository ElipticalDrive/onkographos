Context
Guest stdlib already provides immutable Vector2f/Vector3f geometry and portable math. Programs rendering 3D geometry currently have to implement transformation and projection arithmetic themselves.
Goal
Provide reusable immutable Matrix4f and homogeneous Vector4f mathematics in kotlin.math, executed through ordinary Guest library bodies.
Scope
Matrix4f with 16 row/column-named Float components, identity, indexed reads, transpose, matrix multiplication and homogeneous vector multiplication.
Translation, scale and right-handed axis rotations in radians; right-handed perspective and orthographic projection with normalized clip depth [-1, 1].
Vector4f arithmetic, explicit perspective divide and clip-volume predicate, plus point/direction lifting from Vector3f.
Additive stdlib module-version update, documentation, VM conformance and IDE analysis/completion with sources and metadata.
Acceptance Criteria
Guest programs can compose transformations and project vertices with documented multiplication order.
Noncommuting/dense compositions, homogeneous point/direction behavior and projection boundaries execute correctly in the Rust VM.
Invalid projection parameters, out-of-range matrix indexing and invalid perspective-divide w produce catchable exceptions; zero vectors retain existing normalization behavior.
Matrix/vector values retain nominal equality/hash and managed-box behavior across Any and collection boundaries.
IDE diagnostics and completion resolve the API with both source-attached and metadata-only platform inputs.
Existing runtime and wire formats are reused; dependent libraries rebuild against the updated stdlib identity.
Verification
Focused canonical-platform and IDE tests, Guest matrix and geometry Kotlin-to-VM conformance, affected lint and integrated verification proportional to this source-only library addition.
Links
Related portable math foundation: #708.
Implemented in 90805ed; locally integrated into dev at 2c58e69. Five focused VM scenarios, 26 IDE diagnostic tests, six canonical platform tests and affected lint passed. Full IDE suite retains one pre-existing short-type-name assertion failure in StandaloneSmokeTest; no release-readiness claim.
