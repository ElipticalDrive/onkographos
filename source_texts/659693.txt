Outcome
Render larger models with bounded GPU memory and scalable geometry cost by extending the existing BIM visibility/meshlet residency/LOD work across scene providers and adding texture mip streaming. Preserve semantic BIM filtering and existing GPU indirect drawing.
Priority: Scene-scale milestone; can proceed alongside image-quality work.
Work breakdown
Define shared geometry/texture asset IDs, residency records, GPU-memory budgets, and provider contracts across glTF, BIM, and USD.
Generate or import geometry LODs with screen-space error selection and stable transitions; preserve object/material identity, picking, and semantic visibility.
Integrate LOD and residency decisions with current frustum/Hi-Z culling and compacted indirect draws without requiring per-frame CPU visibility readback.
Add bounded background asset loading/transcoding/upload queues and explicit synchronization/lifetimes for resource replacement or eviction.
Add texture mip residency requests, valid fallback mips, and supported compressed texture formats while preserving sRGB, normal-map, alpha, and material semantics.
Cache processed assets with source/version invalidation and expose geometry/texture residency, upload traffic, memory use, and LOD debug views.
Acceptance criteria
Large representative glTF and BIM/USD scenes respect configured memory/upload budgets and remain interactive during asset loading.
Missing or evicted detail has a valid fallback; no uninitialized textures, broken material indices, or use-after-free GPU resources.
LOD transitions remain stable under motion and retain correct picking and semantic filtering.
Scene reload/cancellation/resize does not leak memory or leave stale asynchronous requests.
Record import/startup time, peak memory, upload stalls, culling/draw GPU cost, and visual differences against full-resident rendering.
Unsupported compression formats fall back cleanly, and the current indirect raster route remains supported. A mesh-shader backend is a separate optional follow-up.
Dependencies
No other epic is a hard prerequisite. Coordinate geometry/asset revision changes with shared acceleration structures (#41) so ray-traced effects do not reference evicted or stale resources.
Existing implementation to extend
BIM GPU visibility and draw compaction
Implementation constraints
Use Vulkan 1.4, Vulkan-Hpp RAII for engine-owned Vulkan resources, VMA for allocations, and Slang for engine-owned shaders. Integrate through the existing render graph and focused managers. Preserve reverse-Z, the negative-height scene viewport, and column-major matrices; follow coordinate conventions. Keep forward and deferred behavior consistent where the feature applies, expose capability/quality controls, and document memory and GPU timing costs. Include new runtime assets in the Windows release package.
