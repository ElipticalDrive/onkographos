Closes #211. Implementation: #307 (RPN tree). Edit baker: #309.
Summary
Design doc at `docs/research/sdf-csg-composition.md` analysing six approaches to the order-dependent blend bug in `eval_scene` and recommending Approach D — postfix RPN tree as the foundation for the destructible-terrain + planet-scale rendering roadmap.
Why postfix RPN, not 3-pass roles
Three-pass roles (Approach A in the doc) is order-independent within each pass — fixes the bug — but throws away the tree structure that the rest of the roadmap requires. Shipping A means rewriting half of `eval_scene` again the moment we add chunking or runtime CSG edits. RPN ships the same bug fix and is the endgame:
Same data model powers chunking (World streaming básico #54), BVH culling (feat(core): Spatial Acceleration Structure — BVH/Octree compartido #115), sparse SDF storage (feat(sdf): Sparse SDF Storage #136), and the edit baker (feat(render): RPN edit baker — bridge runtime CSG edits into sparse SDF chunks #309 — new).
Equivalent expressiveness to a real CSG tree.
Flat array, GPU-driven idiom, single linear loop in the shader.
16-slot stack covers any balanced tree up to 65k leaves; validated CPU-side at upload.
Cost intermediate (4–7 days) and result is the foundation, not throwaway MVP.

How `SdfBlend` (smooth blending) maps to RPN
The current `SdfBlend { mode, smoothness }` semantics are preserved end-to-end. Per-instance smoothness migrates to operator-edge attributes (where binary smin mathematically belongs). Existing scenes load via a canonical default tree: `smooth_subtract(smooth_intersect(smooth_union(adds), intersects), subs)`. Render output of migrated scenes is byte-identical to Approach A's output — A is literally the static-tree degenerate case of D.

Design doc evaluating five approaches to fix the directional / order-dependent
blend semantics in eval_scene (the bug in #211: first entity's blend_mode is
a no-op, last entity dominates).

Approaches surveyed:
- A — three-pass union → subtract → intersect (role-based, per-instance k)
- B — role-based with global k (single pass, less expressive)
- C — CSG tree, Dreams-style (long-term endgame)
- D — switch to associative smin (exponential / circular geometric — partial fix)
- E — additive Blender-style field (incompatible with sphere-tracing)

Recommendation: A as MVP, C as future when scale or expressiveness demands it.
Approach A makes role explicit per entity, swaps the flat loop for three
filtered loops sorted by role on the CPU. Solves all three operators (union,
subtraction, intersection) commutatively with per-instance smoothness preserved.
Cost is 3× per ray-march sample (acceptable for the typical sub-100-instance
scene; BVH or segment tracing closes the gap when scenes grow).

Implementation issue filed as #307. Closes #211.

References: IQ smin (associativity analysis), IQ distfunctions (canonical
operators), Media Molecule's Dreams (Operationally Transformed CSG trees,
SIGGRAPH 2015 — Alex Evans), Blender meta-objects (additive field model,
discarded for the ray-march path).

Rewrites the design doc to recommend Approach D (postfix RPN tree)
instead of Approach A (3-pass roles). The pivot is driven by the
broader roadmap: destructible terrain + planet-scale rendering.

Approach A is order-independent within passes but throws away tree
structure — so the moment chunking, runtime edits, or nested groupings
are needed, A becomes a rewrite. Approach D ships the same bug fix
(order-independent semantics on user intent) AND is the foundation
the rest of the roadmap is built on.

D linearises the CSG tree to a flat array of tokens in postfix order.
CPU walks the tree DFS once and emits tokens; GPU iterates the array
once with a 16-slot stack. Equivalent expressiveness to a real tree,
single linear loop in the shader, no GPU recursion. Stack size is
bounded (16 covers any balanced tree up to ~65k leaves), validated
CPU-side at upload.

- Section "How SdfBlend (smooth blending) maps to RPN" — preserves

  cross-references #54 (chunking), #115 (BVH), #136 (sparse SDF),
  #309 (edit baker, new), plus #91 / #90 / #248 / #53 / #117 as
