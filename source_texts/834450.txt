Parent Epic: #85
Objective
Prove that ChimeraX application behavior is equivalent for legacy OME-Zarr 0.4 / Zarr v2 and OME-Zarr 0.5 / Zarr v3 inputs, including noncanonical supported v3 layouts.
Prerequisites
The prerelease/test seam is established.
The environment contains published copick==2.0.0a1, published copick-shared-ui==2.0.0a1, and checksum-verified ChimeraX-OME-Zarr==1.0.0a1 on ChimeraX Daily 1.13 / Python 3.14.
Work
Add independent small fixtures for:
OME-Zarr 0.4/v2 with numeric paths;
OME-Zarr 0.4/v2 whose first metadata path is s0;
canonical copick-alpha OME-Zarr 0.5/v3;
OME-Zarr 0.5/v3 with nonnumeric paths;
unsharded alternate chunks;
multiple shards and default v3 chunk keys; and
alternate codec pipelines supported by declared dependencies.
Run the v3 matrix at Zarr 3.1.6 and the maintained Zarr 3.3.0 endpoint, matching the reader and shared-UI alpha bounds.
Test tomogram loading and existing initial resolution choices 0, 1, and 2 without assuming array labels.
Test object density maps with and without stored data, including attachment, region/step behavior, and threshold.
Test single-label and multilabel segmentations, colors, surface settings, show/hide, reload, and coordinates.
Test volume switching, deletion, undo-history cleanup, and absence of stale entity/store references.
Smoke picks, meshes, scores, transformations, instance IDs, URI commands, project reload, and shared-UI gallery/info behavior against copick 2.0 models.
Exercise shared-UI 2.0.0a1 thumbnail selection, read-only behavior, worker errors, and concurrent reads through the chimerax-copick integration.
Compare decoded data and application models, not compressed bytes.
Snapshot source keys before and after read-only workflows and require no mutations.
Verify invalid metadata and unsupported codec errors remain visible through the existing ChimeraX logger/worker surface.
Acceptance criteria
Equivalent v2 and v3 fixtures produce the same visible volume values, physical coordinates, colors, thumbnails, and annotation behavior.
Numeric and nonnumeric metadata-defined paths open without a chimerax-copick fallback.
Readers accept supported alternate chunks, shard grids, key encodings, and codecs.
No test or implementation requires 128-cube chunks, one shard, v2-style keys, or the canonical codec pipeline.
Application code does not materialize a full tomogram merely to display it.
Source stores are unchanged after read-only application workflows.
Missing/invalid metadata and decode failures are actionable rather than presented as an empty project.
