Summary
add real video/image-directory ingest with FFmpeg/FFprobe or Pillow normalization and deterministic frame QA
add dedicated out-of-process local/Docker COLMAP sparse camera recovery and strict binary parsing
preserve raw databases, sparse candidates, exact commands, logs, diagnostics, and typed artifacts
isolate attempts and transactionally promote validated output sets with backup/rollback
keep production colmap*.yaml configs scoped to ingest and camera recovery; provide an explicit mock-downstream integration config
Phase 1.1 correctness
represent raw COLMAP output as world_frame=colmap_arbitrary, alignment_status=unoriented, OpenCV camera axes, arbitrary linear units, and ambiguous scale
serialize unit-neutral translation values while accepting legacy coordinate/translation fields
propagate coordinate metadata through Scene IR and trajectory export; roadmap canonical metric alignment as a later stage
apply EXIF orientation 6/8 before image resize and RGB conversion
never retry KeyboardInterrupt or SystemExit; preserve the attempt, mark it interrupted, and terminate process groups with TERM/KILL escalation
exclude execution_count from content/cache signatures
make adapter healthchecks config-aware and harden Docker UID/GID, CPU validation, in-container health, and image identity handling
add a manual Docker build/health workflow without changing the CPU-only CI gate

generated Scene IR validation
fault-injected promotion rollback, stale-output rejection, interrupted-attempt, identical-byte forced-rerun, EXIF 6/8, fake FFmpeg/COLMAP, model parsing/selection, and configured healthcheck tests
Real-tool smoke
A real FFmpeg 4.4.2 smoke generated a four-second H.264 test video and ingested 120 decoded frames, selecting twelve normalized 640x480 frames at 3 FPS with typed QA and logs. This smoke also found and fixed relative --run-dir output handling, now covered by regression test.
A real COLMAP 3.7 CPU reconstruction ran on 20 consecutive images from COLMAP's official South Building dataset. The real executable completed feature extraction, sequential matching, and mapping; produced cameras.bin, images.bin, and points3D.bin; and Reconevery parsed them into typed camera artifacts. All 20 frames registered (1.0 ratio), with 5,107 sparse points and 0.3581 average reprojection error. The output correctly remains colmap_arbitrary, unoriented, arbitrary_units, and scale_ambiguous. A subsequent --resume run was a cache hit for ingest and camera recovery.
The real-COLMAP draft prerequisite is now satisfied. The PR remains draft pending maintainer review state selection.
Known limitations
raw monocular COLMAP remains unoriented and scale-ambiguous; it is not a canonical metric robot frame
Phase 1 supports one COLMAP camera and rejects multi-camera models
Docker Phase 1 is CPU-only; compatible local COLMAP supports CPU or GPU flags
production Phase 1 configs stop at camera recovery
segmentation and later reconstruction remain out of scope; the explicit integration demo uses Phase 0.1 mocks
Recommended Phase 2
After the alignment contract is defined, add a narrowly scoped SAM 3 segmentation/tracking adapter that consumes selected frames and registered camera poses and emits typed masks/tracks. Keep global/object reconstruction, SceneSmith, physics, and simulator export out of that task.
