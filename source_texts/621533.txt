Coding Plan
Summary
Extend the noise library with Worley, ridged, and billowed noise plus domain warping and fBm composition to enable varied terrain features
Introduce a biome system that drives terrain generation parameters and object placement density through continuous weight blending
Generalize the foliage placement algorithm into a standalone PlacementSystem with abstract surface providers, enabling procedural placement of any object type with constraint-based rules
Integrate with editor and scripting systems following established patterns to maintain consistency with the existing codebase architecture
Design Choices
Design Choice 1: Should the biome system use discrete biomes or continuous blending?
Options Considered:
Discrete biomes with hard boundaries using Voronoi-based assignment
Continuous biome blending using noise-based weight maps with smooth interpolation
Chosen Option: 2
Rationale: Continuous blending provides more natural-looking transitions and aligns with the existing terrain splatmap blending approach used for materials.
Design Choice 2: Should procedural placement support runtime generation or be editor-only?
Options Considered:
Editor-only with baked placement data serialized to scene files
Runtime deterministic generation using seed-based placement (no storage needed)
Chosen Option: 2
Rationale: Runtime deterministic generation follows the existing foliage pattern, enables streaming, and avoids storing large instance datasets.

Implementation Steps
Phase 1: Noise and Biome Foundation
Establish the mathematical foundation for varied terrain and biome generation by extending the noise library and creating a biome data system that drives terrain characteristics and object distribution.
Task 1: Extended Noise Library
Create a unified noise utility module with additional noise functions beyond the existing SimplexNoise to enable more varied terrain features.
Create OloEngine/src/OloEngine/Procedural/NoiseUtilities.h/cpp with noise generation functions
Implement Worley (cellular) noise for natural patterns like rock formations and river networks
Implement ridged multifractal noise for mountain ridges and sharp terrain features
Implement billowed noise (absolute value of simplex) for rolling hills
Add domain warping function that distorts noise coordinates using another noise layer
Create fBm compositor that combines multiple noise layers with configurable blend modes (add, multiply, max, min)
Ensure all functions are deterministic with seed parameter for reproducibility
Task 2: Biome Data Structure
Define the biome system data structures that specify terrain and placement characteristics for different environmental zones.
Create OloEngine/src/OloEngine/Procedural/Biome.h with biome definition structures
Define BiomeData struct containing: ID, name, terrain noise parameters (base height, amplitude, noise type, frequency), material layer weights, temperature/moisture ranges, and placement layer references
Define BiomeMap class that generates and stores biome weights per-cell using temperature/moisture noise maps
Implement biome weight sampling with smooth blending based on configurable falloff distance
Add serialization support following existing component YAML patterns
Task 3: Biome-Aware Terrain Generation
Extend TerrainData to generate terrain using biome-driven parameters instead of single global noise settings.
Modify OloEngine/src/OloEngine/Terrain/TerrainData.h/cpp to accept optional BiomeMap reference
Add GenerateProceduralWithBiomes() method that samples biome weights and interpolates noise parameters
Blend terrain heights based on biome weights at each heightmap texel
Generate splatmap weights automatically from biome material preferences
Maintain backward compatibility with existing GenerateProcedural() for non-biome workflows

Phase 2: Procedural Object Placement System

Research
OloEngine has a mature terrain system with procedural heightmap generation using fBm simplex noise, chunk-based rendering with quadtree LOD, voxel overrides via marching cubes, and a foliage placement system. The engine uses EnTT for ECS, has established patterns for components, editor panels, and scripting APIs (C# via Mono, Lua via Sol2). The foliage system's grid-based deterministic placement algorithm and the existing SimplexNoise implementation provide strong foundations to extend. However, there's no biome system, limited noise variety, and the placement system is tightly coupled to foliage/terrain rather than being generalized for arbitrary objects.
