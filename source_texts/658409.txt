Functional, optional 3D interoperability
Stacked on PR #349 experiment/v2l18-3-offline-webgl-png-export (immutable parent head cae08d75fd8c5b6d220df44c0bf50bad855c0fa7). The optional VIEW-IN-BROWSER.html already displays real 16-photo COLMAP-derived untrained Gaussians and lets an operator swap local .splat scenes. This PR adds a useful cross-tool handoff from exactly the active file: button Export 3D RGB points (PLY) creates a standard binary little-endian PLY with original XYZ float32 positions and original RGB uchar colors for every record, preserving exact values. No new renderer, geometry estimator, dependency, network service or paid API. It is a colored point cloud, not a physical mesh, not a trained 3DGS scene, not guaranteed metric and not 4D.
For straightforward browser memory bounds, export input is limited to 32 MiB (display-only file cap stays 256 MiB); the user sees a clear error if over limit. Nonfinite XYZ refuses export rather than producing a corrupt point cloud. Source photography attribution/CC BY-NC 4.0 noncommercial is printed in a PLY comment for the original WRE scene; imported operator scenes instead explicitly require independent license review. Existing .splat download, A/B scene selection, camera bookmark and actual WebGL PNG buttons remain unchanged.
Real browser acceptance test: under Chromium ChromeDriver with WebGL2 SwiftShader on file:///VIEW-IN-BROWSER.html, click the new button using native WebDriver, wait for actual .ply file on disk; parse its binary header and every 15-byte XYZ/RGB vertex and compare every source coordinate/color bit-for-bit to the original photographed 6917-record .splat. Then upload/drop an actual 1024-record operator scene into existing vendor FileReader/WebGL and repeat the real button/download/file validation for the currently active 1024-record file; record SHA256 of both PLY outputs in evidence JSON. No CUDA training claims. Only the one existing optional experimental workflow .github/workflows/gsplat-real-photo-viewer-handoff.yml changes; production runtime viewer/LOD/4D code stays untouched and is outside the active lot.
New commits: 1cdb8223fa41a7e327eaeddbdf6a490de22456de functionality and 7dba360362337cb1f584d57f25441c6f853c820d real Chrome acceptance tests.
