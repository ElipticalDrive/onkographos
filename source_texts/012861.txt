What
Continues the allocation/performance cleanup: removes boxing from chunk meshing, replaces the brute-force block-picking ray with an exact voxel traversal, and stops re-saving untouched chunks on unload.
Changes
Chunk meshing (\Chunk.rebuildMesh\ + emit helpers) now accumulates vertices/indices into \FloatArray/\IntArray\ instead of \ArrayList/\ArrayList, eliminating millions of boxed \Float/\Integer\ objects per chunk rebuild.
Raycaster rewritten as an Amanatides-Woo DDA traversal: exact (no step size to tune) and ~an order of magnitude fewer iterations than the old 0.02-unit step march. Water is still pass-through; every other non-air block stops the ray; \�lockPos/\placePos\ semantics are preserved.
ChunkStorage.load no longer marks a just-loaded chunk as player-modified, so an untouched chunk isn't redundantly re-saved on unload (its data is already on disk; edits still trigger saves via \setLocalFromPlayer).
Testing
\mvn compile\ passes; headless smoke test (90 frames) runs and exits cleanly.
Raycast DDA verified against a brute-force reference over 200,000 random rays (agreement except for ~0.01% corner/edge-grazing rays, where the DDA is the more precise of the two), plus targeted straight-down/up, inside-block, and pass-through-water checks.
Notes
No README change needed - internal performance/cleanup only, no user-facing behavior change.

Finding #7: BlockType log constructors had bark tile in top/bottom slot instead of
the side slot. Fix all four new logs to BIRCH_LOG(8, 276, 8), JUNGLE_LOG(8, 277, 8),
PINE_LOG(8, 278, 8), CHERRY_LOG(8, 285, 8) — matching the WOOD_LOG(8, 7, 8) pattern

Finding #5: Pine trees used BlockType.LEAVES (oak leaf tile, tile 9) for their
canopy, causing broken pine leaves to drop oak saplings instead of pine saplings.
Add PINE_LEAVES (id 540, tile 287) with its own dark blue-green needle texture;
update Farming.growPineTree and TerrainGenerator.placePineTree to use PINE_LEAVES;
add Mining, CreativeCatalog, and PINE_SAPLING leaf-drop entries; extend isLeaves()
and the SaplingGrowthTest coverage.

Finding #6: hasClearance() never checked whether y + needed would exceed Chunk.HEIGHT,
so trees near the top of the world could silently over-write blocks or read nulls.
Add guard: if (y + needed >= Chunk.HEIGHT) return false.

Finding #4: growJungleSapling() removed all four saplings before checking clearance
for the large tree, meaning the saplings disappeared even when the tree could not
grow. Pre-flight all four 2×2 trunk columns with the minimum large-tree height
(20 + 3 buffer) before touching any block; return early if any column is blocked.
