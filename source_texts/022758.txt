*NIPS 2020* 

## Motivation

- Surface Rendering : Surface prediction has to be **accurate** for multi-view consistency (often very hard)
- Volume Rendering : Has to sample **many** points along the ray -> time consuming

## Key Idea

- Employ hierarchical structure of SVO to avoid sampling *empty space*.
- Local properties of a spatial location only depend on a local neighborhood. (Feature Interpolation)

## Previous Approach

- NeRF : sample fixed number of points along a ray - lot of waste in time / compute

## Method

- Neural Implicit Fields (NeRF-like) + Explicit Sparse Voxel Structure = Faster + Finer

### Voxel-bounded implicit fields

![image](https://user-images.githubusercontent.com/46308407/127810647-484c7eff-040b-4887-ad3d-d24af58698e9.png)

- MLPs are voxel-bounded, but share parameters in practice.

![image](https://user-images.githubusercontent.com/46308407/127810684-cbb6209e-c326-4aa7-980e-8db87fc270e0.png)

- For each coordinate query, 8 corners features are interpolated and positional embedded before being fed to query MLP along with ray direction.

### Volume Rendering

- Ray-voxel Intersection + Ray Marching (inside voxel)
- AABB: Axis Aligned Bounding Box intersection test -> Ray-voxel Intersection
- Define transparency and learnable background RGB in case a ray misses object in a voxel.
- Better sampling efficiency compared to NeRF's coarse + fine framework.
![image](https://user-images.githubusercontent.com/46308407/127812088-bdf75942-3d05-4b77-9037-88fc8c905587.png)

![image](https://user-images.githubusercontent.com/46308407/127811943-67a8b94a-7009-45e2-bd86-e54f5a66eb22.png)

- For efficient modeling of hard surface, when transparency drops below *certain threshold(=0.01)*, the volume accumulation terminates.

### Objective

![image](https://user-images.githubusercontent.com/46308407/127812268-110e326b-c596-422d-9eb5-cbdcb1d8554e.png)

- Omega is the Beta distribution regularization, to ensure that transparency sticks between 0 and 1.

### Voxel Initialization and Self-Pruning

- If no coarse geometry is provided, initialize voxel so that 
![image](https://user-images.githubusercontent.com/46308407/127812611-504fa5a5-e196-4d0e-96bb-2b5fad1506c6.png)
![image](https://user-images.githubusercontent.com/46308407/127812656-7b2a2652-0097-407e-aed0-29e4f345fe22.png)
- If all uniformly sampled points have very low volume density, the voxel is *pruned*.

### Progressive Training
![image](https://user-images.githubusercontent.com/46308407/127812799-9dbe0240-e060-456d-a9e1-7c34afb89ea9.png)
- After certain steps, halve both voxel size and ray-marching step size. A voxel is sub-divided into 8 sub-voxels, and each vertex features are trilinearly interpolated.

## Experiments

### Dataset

### Baseline
- SRN
- Neural Volumes

### Details
- 32-dim vertex feature embedding
- batch size = 4
- Halving at every 2500 steps
- 2048 rays for each image

## Comments
- Sparse voxel representation that captures local geometry and enables efficient sampling is pure gold compared to NeRF in this work.
- However, their embedding is not light as well, as they have 32-dim embedding with additional sinusoidal positional encoding, which leads to relatively large GPU time.
- The progressive learning framework was improved in #84 by incorporating a feature pyramid in a sense. It considered many levels of coarse/fine details in one pass, instead making the network and embedding itself lighter.
