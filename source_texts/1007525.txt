Part of #602 (step 2's first part: ambient occlusion from hardware ray queries on desktop Vulkan).
What it is
A new opt-in value, display.ambient_occlusion = "ray_traced" (Video Setup > Advanced Graphics > Ambient Occlusion: OFF / WORLD / RAY TRACED). It is "world" in every part but one: the dynamic objects' rays in the occlusion pass are cast by the GPU's ray queries (VK_KHR_ray_query) through the objects' own collision meshes, instead of stepping through the distance-field scene. Off by default. Where the device has no ray queries, and on Metal for now, it draws as "world" and logs the reason once.
Design
The scene (port/linux/game/world_rt.c, world_rt_game.c, world_rt.h):
The loaded structure BSP's collision geometry is one mesh, built once per BSP.
Each definition gets one mesh per node from that node's collision BSP, turned to face out by the sign of its volume.
An item with no collision geometry (a grenade) gets a box about its bounding sphere. Anything else with none (emitters, wires, the sky's ring) gets no mesh.
Each frame's instances are the structure plus every dynamic object's node meshes, placed with the drawn (interpolated) node matrices.
Left out, as the proxies leave them out: the static scenery that the field and its pages hold, and held weapons.
Why collision meshes rather than the proxies' shapes: they are the objects' own shapes and rigid per node. So each BLAS is built once and only the TLAS changes; there is no skinning and no refit. The proxies are already fitted to these meshes, and they have about a tenth of the render models' triangles. Capsules and boxes suit a distance field, not a ray tracer.
The structure only stops rays. A ray that hits it counts as a miss, because the lightmaps (level pixels) and the field with its reference (models) already hold the level's own occlusion. So "the level doesn't darken itself" still holds, and objects behind a wall or floor no longer shade through it, as they could in the distance-field scene.
The command stream (version 21):
WORLD_AO_MESH carries a mesh; id 0 releases all of them.
WORLD_AO_INSTANCES carries the frame's instances.
ray_queries is in the backend's INITIALIZE answer.
Each draw's owner among the instances goes in world_ao[2] of the uniforms, and the pre-pass twins write it into the inputs' spare word so that a pixel's own instances are skipped.
The pass's history[3] is 2 for ray queries. A backend without them treats it as 1, so Metal is unchanged.
The decoder checks the sizes, ids and counts. The backend checks each instance's mesh, owner, kind and that its transform values are finite.
The network protocol is unchanged.
The Vulkan backend (port/linux/vulkan/xgpu_vulkan_rt.c):
The core enables the acceleration structure and ray query extensions and buffer device addresses where the device has them. It skips them on CPU devices and with HALO_VULKAN_NO_RAY_QUERIES=1.
BLASes use prefer-fast-trace and are built once, all of a frame's new ones in one call, into 16 MB buffers of their own.
The TLAS uses prefer-fast-build and is rebuilt each frame before the first pass that reads it. There are three in turn, each reused only once the GPU is done with it.
All builds go in the early command buffer, so no render pass is ended for them.
Binding 8 of the occlusion set names the latest TLAS, or an empty one.
The ray-query pipeline is prepared with the map's pipelines. Until it and the scene are ready, the pass falls back to the distance-field rays.
The rays (SPIR-V emitter, world_ao_traced_rays):
The same 4 cosine-weighted rays per pixel as "world": 0.1 to 2 wu, quarter resolution, the same history blend (temporal accumulation).
Back faces are culled. Object instances are non-opaque, so each candidate except the pixel's own object is committed.
The vehicles' occlusion fields are not walked here, because their meshes are traced. The static scenery's shapes and fields are walked as before.
The emitted module passes spirv-val --target-env vulkan1.3.
Measurements
RTX 4090, release build, a10's start held still (fixed-step frames, offscreen, unpaced, windowed). Values are medians of 600-frame windows: GPU time per frame from HALO_GPU_STATS, and the pass's own draw from HALO_VULKAN_DRAW_TIMES=10 in separate runs.

The pass costs 0.05 ms (1080p) and 0.12 ms (4K) more than the distance-field step.
The rest of the frame difference, about 0.14 ms, is the per-frame TLAS rebuild of 931 instances and its barrier. a10's start has 154 meshes (96,388 triangles); Blood Gulch has 45 meshes and 89 instances.
Spark GB10: it builds and traces the scene (the pass runs with ray queries), but the timing runs were cut off when the machine dropped off the network. Those numbers are still to come.
Images (the same frames)
These are in the scratchpad on the machine I worked on, not attached here:
a10: shaded and occlusion-only (shaded frame divided by off's), world vs ray_traced. Doors in their frames get contact shade from the doors' real meshes. World's soft halo on the wall behind the first crewman and consoles is mostly gone with 2 wu rays. The mean occlusion over the frame is 0.947 (world) vs 0.945 (ray_traced).
b30: world darkens the whole beach by about a fifth (mean 0.79 vs 0.94). Most likely that is the vehicles' long-reach occlusion fields, which world walks and ray_traced does not.
Checks
Vulkan validation layers on the 4090 (a10, a30 and Blood Gulch, including the map changes between them): 0 messages.
Facing, checked on the GPU: a box wound counterclockwise seen from outside, placed around the camera, shades nothing inside it as instanced, and does shade the floor inside it with HALO_VULKAN_RT_FLIP=1.
tools/harness/tests/test_world_rt.py (new, 9 negative controls) and test_world_ao.py (a new rays case, 5 more controls): pass on the Mac and on x86-64 Linux.
tools/test_render_stream.py (new checks that malformed mesh and instance records are stopped): passes on x86-64 Linux. The display-pacing check fails on this Mac, as it does on master.
tools/test_vulkan_passes.py (the fake GPU builds xgpu_vulkan_rt.c), tools/test_world_trace.py and tools/test_port_settings.py: pass.
Builds: ninja linux_x86_64 (debug and release), ninja linux_arm64 (Spark), ninja macos, ninja android and ninja ios_sim all succeed.
Not done yet
The models' structure term by rays. It needs the reference found by rays too, for example a small pass at each object's lighting point; with it, "ray_traced" would no longer need the field bake.
A TLAS refit when only transforms change.
The vehicles' long-reach occlusion: their fields have it, 2 wu rays do not.
Metal's intersector (M3, A17 Pro).
Steam Deck (RADV), the Frame and phones, each to be measured first, per Measure ambient occlusion's real cost on tile GPUs (Android, iOS, iPad, Steam Frame) before keeping it off there #432's rule.
llvmpipe (Mesa 25 on the Spark) crashed inside its own code when the TLAS was rebuilt each frame, even with no BLAS. I did not find the cause, so CPU devices are left without ray queries. RADV shares Mesa's BVH builder and is untested.
One existing test threshold changed: the render stream's "vertices kept" count depends on where waits for room fall (6 with 580 bytes of uniforms, 5 with 584, confirmed by changing the size alone), so it now asks for at least 5.
