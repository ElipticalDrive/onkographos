Context
The async chunk worker (processJob in async_chunks.zig) calls mesher_mod.generateMesh: the naive mesher. It ignores --meshing, so the native default (async on, greedy) draws naive meshes. The sync path and the web build use generateMeshForMode.
Hilly fly-through: 455 103 quads over 482 chunks (about 944 per chunk). bench_mesher's greedy meshes have 367 quads per chunk. The greedy mesher is also 16 times faster since #593, and the async path does not use it.
Acceptance Criteria
The job carries the meshing mode, and the worker calls generateMeshForMode.
The goldens CI passes. A pixel change needs new goldens and a reason in the PR.
The PR states the quads, the GPU mesh bytes and the frame time before and after.
