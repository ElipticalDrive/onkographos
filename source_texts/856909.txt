At the end of each bulk-sampling run, the vertex confinement now reports the volume and mass of the region where vertices were generated, estimated with the rejection method, including the statistical uncertainty:
```
Stats: sampled region (estimated with the rejection method) has volume 113068 ± 2.4e+02 cm3 and mass 1283.32 ± 2.7 kg
```
This is useful for regions whose volume is hard to compute analytically, e.g. intersections and subtractions of physical volumes and geometrical solids.
For each sampled volume, the estimate is the volume of the solid in which candidates are drawn uniformly (the solid itself if natively sampleable, otherwise its bounding box) times the fraction of candidates that lie inside the volume and pass the intersection/subtraction checks. The mass is obtained in the same way, weighting each accepted vertex by the density of the material at its position (one navigator lookup per event). Nothing is reported for surface sampling.
Changes in behavior:
The sampling statistics are summed over all threads and printed once by the master thread. Before, each worker printed its own line and the master printed a meaningless 100% efficiency.
The efficiency line now counts the first (accepted) candidate, which was previously missed, so e.g. a 50% acceptance is no longer reported as 100%. Its wording changed from "iterations" to "candidate points".
SampleableObject::Sample() takes a SamplingCounters& instead of size_t& n_trials.
python -m remage now exits with the remage return code (it was always 0), so the new test detects failed runs.
Verification:
New test confinement/sampled-volume checks the volume and mass against analytic values (within 5σ) for an intersection, a subtraction and a box with a daughter volume, running on 2 threads.
Ran the default confinement / confinement-mt tests and the extra-labeled surface, depth-profile and LAr confinement tests locally: all pass.
Not run: the full test suite and the docs build.
