Context
Ticket number: 12989432126
Volume3D interactive fidelity (Target FPS + fixed sample-distance LOD)
Target: Improve interaction of Volume3D on all hardware classes.
Adds an adaptive resolution feature that is managed by the renderer - not by the tools.
Kept backward compatibility for tool based interactive resolution configuration
Target FPS is an opt-in interactive quality mode for legacy Volume3D.
While the user is dragging, the viewport measures present-frame time (EMA), maintains a pixel budget (budgetPx), and maps that budget to LOD: prefer cutting ray-cast steps first, then reduce present scale (down to ~0.35) so ContextPool draws a smaller GL rect and blits it up to the full on-screen size.
Sample distance is adjusted to match the step LOD.
On interaction end, full-quality sample distance is restored and the last good budget can be reused on the next drag.
Configure with setVolume3DTargetFpsEnabled / setVolume3DTargetFps (default target 10 FPS, clamped 1–60).
When disabled, policy falls back to fixedSampleDistance.
Changes & Results
Adds viewport-owned interactive LOD for legacy VolumeViewport3D with two policies:
fixedSampleDistance (default): multiplies baseline sample distance during drag
targetFps: adaptive budget LOD (ray steps, then present scale) steered toward a Target FPS
Tools arm LOD via armVolume3DInteraction → beginVolume3DInteraction (TrackballRotate, VolumeCropping, Pan, Zoom). ContextPool renders/blits a smaller present rect while Target FPS is active.
Under fixed policy, TrackballRotateTool / VolumeCroppingTool configuration.rotateSampleDistanceFactor is applied when it is a finite number > 0; otherwise default ×2. Under Target FPS, that tool key is ignored. Pan/Zoom use the default ×2 with no tool factor.
Target FPS is clamped to 1–60; state is unregistered on viewport disableElement so the same viewportId does not reuse stale budgets/mappers.
Updates the volumeViewport3D example (2×2 MPR + 3D, IFD checkbox/slider, LOD overlay). Documents policy vs rotateSampleDistanceFactor in 5.x migration notes.
Testing
volume3d example, IFD off: rotate → fixed ×2 (or configured rotateSampleDistanceFactor); full quality on mouseup
Enable Interactive fidelity degradation + change Target FPS: overlay updates; tool factor does not drive LOD
Pan/zoom on 3D still arms interactive quality; disableElement + re-enable same id does not keep stale Target FPS state
