Summary
Adds a playable smooth mineable procedural terrain prototype built from chunked voxel density data.
Adds MineSomething.SmoothTerrain runtime and Editor test assemblies.
Implements deterministic density generation, chunk storage, coordinate conversion, Marching Cubes meshing, mesh/collider chunk views, density-based mining rewards, resource accumulation, and JSON modified-voxel save/load.
Adds Assets/Scenes/SmoothMineableTerrainDemo.unity with camera controls, mining input, debug UI, save/load/regenerate controls, and terrain material/shader assets.
Adds folder manifests for the new world/terrain/material areas.
Root Cause / Notes
The first terrain surface pass used a tetrahedral shortcut that produced visible striping. This PR uses the standard Marching Cubes cube-index, edge-table, and triangle-table path adapted from Eldemarkki/Marching-Cubes-Terrain's MIT-licensed lookup-table approach. Boundary density writes are mirrored into loaded neighbor chunks so mining does not create cracks between overlapping chunk samples.

Preload saved chunks before replaying boundary edits
When a save contains a modified voxel on a chunk boundary, this loop applies that edit immediately via SetVoxelWorld, but boundary mirroring only updates neighbors that are already present in world.Chunks. If the neighboring chunk is also in saveData.ModifiedChunks but appears later in the list (or is generated after load), the mirror is skipped and the neighbor keeps its procedural shared density, so rebuilt meshes can show seams or lose the mined boundary on one side. Create all saved chunks before applying voxel modifications, or force-create the boundary neighbors during load.

Restore the saved seed before applying modifications
For saves created with a different seed than the currently configured world, ApplySaveData regenerates missing chunks with world.CreateGeneratedChunk(...) using the current world.Seed and only logs saveData.Seed later. That means all unmodified voxels come from the wrong procedural terrain while the saved edits are overlaid on top, so loading an older/different-seed save cannot reproduce the saved world. The load path should set/regenerate from saveData.Seed before creating chunks or reject mismatched seeds.
