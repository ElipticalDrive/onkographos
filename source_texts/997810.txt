# Point Cloud Compression
Analyzing the effectiveness of various point cloud compression algorithms on 3D point cloud data. Point cloud compression (e.g. [draco](https://github.com/google/draco)) is a technique used to decrease the memory footprint of point cloud data on-device. As explored in [goel24](https://dl.acm.org/doi/10.1145/3675373) it can even be used with real-time software rasterization techniques to great effect. However, as the limitations of this approach is not well understood or documented, the work presented here aims to bridge that gap.

For the analysis, the following kinds of data are tested:
- Lidar/laser scans
- Scientific simulations
- Mathematical functions
- Random distributions

The analysis pipeline looks like the following:
1. Load/generate point cloud data
2. Compress point cloud data
3. Analyze effectiveness of compression

Various compression algorithms are tested:
- Real-time:
  - [goel24](https://dl.acm.org/doi/10.1145/3675373): Huffman-based attribute compression designed for real-time decompression and rasterization directly on the GPU
- Non-real-time (baseline):
  - [draco](https://github.com/google/draco): geometry-aware point cloud compression from Google, designed for efficient transmission over the web
  - [LZ4](https://github.com/lz4/lz4): general-purpose compressor optimized for decompression speed
  - [Zstandard (zstd)](https://github.com/facebook/zstd): general-purpose compressor with a tunable tradeoff between speed and compression ratio
  - [LZMA](https://www.7-zip.org/sdk.html): general-purpose compressor optimized for maximum compression ratio
  - [Brotli](https://github.com/google/brotli): general-purpose compressor from Google combining dictionary-based and entropy coding

## Generator

Synthetic LAS files can be generated using `generate.py` with a config file that enumerates distributions and parameters. This is useful for testing compression on data with known spatial structure.

```
uv run generate.py --config generate_config.json
```

Output files are written to the directory specified by `output_dir` in the config. Filenames are derived automatically from the distribution type and its key parameters (e.g. `terrain_s150o4_1M.las`).

The top-level config keys are:

- `output_dir`: directory to write generated LAS files
- `num_points`: default number of points per file; can be overridden per distribution with a local `num_points` key
- `default_bounds`: the coordinate space for generated points, as `{"x": [min, max], "y": [...], "z": [...]}`; individual distributions can override this with a `bounds` key

Each entry in `distributions` has two sub-objects: `distribution` (spatial layout) and `color` (coloring scheme).
