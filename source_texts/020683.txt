Abstract
Regulated financial and analytical platforms increasingly require browser-based user interfaces capable of visualising millions of data points in real time while remaining responsive, memory efficient, and auditable. Conventional rendering stacks based on SVG or the HTML Canvas API typically degrade beyond tens of thousands of primitives, leading to frame drops, excessive heap consumption, and unresponsive dashboards. Prior benchmarking indicates that SVG and Canvas performance begins to degrade around 10,000 graphical elements, while WebGL sustains higher throughput at substantially larger element counts by leveraging GPU parallelism and instanced rendering [1, 2]. In regulated environments, UI state itself can become part of the record that must be captured and preserved in a tamper-evident form under frameworks such as SEC Rule 17a-4 and FINRA Rule 4511 [3, 4]. This paper presents and evaluates a hybrid, multi-stage frontend architecture combining (i) WebGL for core geometry, (ii) a Canvas overlay for axes, labels, and interaction affordances, (iii) progressive streaming through GraphQL subscriptions, (iv) Web Worker + WebAssembly downsampling using the Largest-Triangle-Three-Buckets (LTTB) algorithm, and (v) React-based virtualization for bounded DOM complexity. Using controlled synthetic benchmarks up to 1.5 million points, the architecture sustains near-60 FPS interactions while maintaining heap memory below an 800 MB target and keeping time-tointeractive under two seconds. Beyond performance, the design integrates audit-aware observability by logging the rendered viewport, filters, and interaction context per render cycle to support reproducibility and retention requirements.
Keywords: WebGL, Canvas, Real-time Dashboards, Streaming UI, GraphQL Subscriptions, WebAssembly, Web Workers, Downsampling (LTTB), Virtualization, Performance Engineering, FINRA, SEC Rule 17a-4, Auditability
