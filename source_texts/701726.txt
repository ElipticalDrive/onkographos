What does this pull request do?
Without center, Affine.forward built the default centre with the input's batch size and left the angle, translation, scale and shear at their own batch size. get_affine_matrix2d then raised ValueError: Inputs must have same batch size dimension whenever the two differed. So a batch-1 parameter set could not warp a batch of images, although Rotate, Translate and Affine with an explicit center all accept that. The reverse case was blocked by the same mismatch: B parameter sets warping one image, which Affine with center accepts.
The fix. The default centre is the same for every image, so forward now builds it at the parameters' batch size, as the issue suggests. Without center, Affine then runs exactly the path it runs with the image centre given explicitly:
one parameter set warps every image;
P parameter sets warp one image into (P, C, H, W).
The case @ducha-aiki added on the issue: a parameter batch that differs from the input batch, neither being 1, has no sensible pairing. With center given it failed in a tensor expansion inside affine with a raw RuntimeError. It now raises a ValueError that names both batch sizes, with or without center: "Affine has 2 parameter sets for an input batch of 3: the two must match, or one of them must be 1." The check runs after get_affine_matrix2d, so a center whose batch differs from the parameters' keeps its existing error.
Docs. #6432 documented the current behaviour with links to #6395 in the class paragraph and under Raises. Both now describe the contract: the parameter and input batches are equal, or one of them is 1. The RuntimeError entry for the with-center mismatch is gone, Returns covers one image under B parameter sets, and the Rotate See Also no longer contrasts it with "this module without center". grep -rnE "#6395|issues/6395" kornia/ tests/ finds nothing.
#6413 changes the batch check of get_rotation_matrix2d, a separate contract decision. This fix does not depend on it, and whichever of the two lands second rebases.

Every combination: 6,000 combinations of one parameter kind or all four together, parameter batch 1/2/3, center (none, (1, 2), matching, mismatched, the image centre) and input ((C, H, W) or a batch of 0/1/2/3), bilinear and nearest.
All 2,480 results that work on main are bitwise unchanged.

Every error main raised for a center that disagrees with the parameters is unchanged.
The 960 batch mismatches now raise the new ValueError. Before, they raised a RuntimeError from the expansion or the generic batch-size message.
Gradients: the gradient of a shared batch-1 parameter equals the sum of the per-image gradients (difference 6e-17), and gradcheck passes for one parameter set on three images.
Compile and TorchScript: torch.compile(fullgraph=True) (static and dynamic, aot_eager) traces the new cases and matches eager bit for bit. Affine does not script with TorchScript on main either, and that is unchanged.
Not changed here:
With more than one angle or scale and one image, Rotate and Scale raise a RuntimeError, while Translate and Shear broadcast the image. That is the same kind of gap in the sibling modules, so I have left it for its own issue.
Run on Windows 11, Python 3.11.14, torch 2.14.0, CPU and CUDA (RTX 3050).
