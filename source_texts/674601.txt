Follow-up to a read-through of the whole codebase. The ray-tracing maths was all correct — I checked every formula against the book (the h = -b/2 form of the quadratic, reflect/refract, Schlick, the u/v/w basis, viewport_v's sign, pixel00_loc, defocus radius, gamma + the 255.999/clamp interaction). What this PR fixes is three latent bugs plus a pile of C++-isms the translation carried over.
The rendered image is bit-identical to main. Verified by rendering the same scene at 200x112 / 20 samples / depth 10 before and after (cmp clean). Every change below is behaviour-preserving except the three fixes, which are unreachable from the current scene config.
Bugs
Metal.fuzz was unclamped (material.zig). The book enforces fuzz <= 1 in a constructor; a Zig struct literal has no constructor, so nothing held the invariant. Above 1 the jitter dominates the reflection, dot(scattered, normal) > 0 fails for nearly every ray, and the metal silently renders black instead of rough. Clamped with @min(self.fuzz, 1) on use. Not hit today because main.zig feeds randomDouble() ∈ [0,1).
@intFromFloat ran before its guard (camera.zig:63). image_height was computed from image_width / aspect_ratio and only then clamped with @max(1, ...) — but a zero, negative or NaN aspect_ratio is illegal behaviour at the cast, so the guard on the next line could never fire. aspect_ratio is a public field. Now std.math.lossyCast(u32, ...), which saturates and maps NaN to 0, with the @max(1, ...) still after it.
const rand = prng.random() at container scope (util.zig:7). This works — I checked, 1M samples give mean 0.50013 — but only because &prng on a container-level var happens to be a comptime-known address. It's a comptime pointer into mutable global state, and it breaks confusingly the moment the global moves into a struct or becomes const. Now called per use; the global is documented as the reason the renderer can't be threaded.
Idiom
Vec3 is now @Vector(3, f64). + - * /, @abs, @sqrt, @select and @reduce work directly, so most of the method bodies in vec3.zig disappear and call sites read as arithmetic instead of a.subtract(b.multiply(t)).
hit() and scatter() return optionals instead of writing through out-params and returning bool. That was the C++ shape; it's also what forced every var rec: HitRecord = undefined in the render path, all of which are now gone.
Deleted rtweekend.zig. A literal translation of the book's umbrella header — it gave every type a second name (rtweekend.Sphere vs hittable.Sphere) and re-exported infinity/pi that already live in std.math. main.zig was its only consumer and now imports its four types directly.
Added build.zig / build.zig.zon, moved sources to src/. zig build run -Doptimize=ReleaseFast > image.ppm replaces the raw build-exe line in the README, and zig build test comes free.
var x = undefined + if/else replaced with if-expressions (ri and direction in Dielectric, sphere_material in the scene builder); manual a += 1 at the bottom of a 45-line while body replaced with for (0..22); the three identical world.add(...) calls hoisted out of their branches.
getRay took *Camera without mutating and was called as a free function; rayColor never touched self at all. Both fixed. if (depth <= 0) on a u32 is now == 0.
Dead code removed: Interval.size/contains/empty/universe, HittableList.clear, Vec3.randomOnHemisphere, rtweekend.infinity/pi, color.zig's duplicate Color alias. Zero references each.
Stale comments fixed: camera.zig said "forward by focal_length" (it's focus_dist, and focal_length hasn't existed since the defocus chapter) and described center as "at the origin" (it's lookfrom); rayColor's doc claimed the depth cap "models energy loss from repeated bounces" — it doesn't, it truncates and biases deep paths dark.
Tests
28 tests, none previously (zig build test). They cover vector math, gamma/quantisation incl. the NaN and out-of-range paths, interval bounds, sphere intersection incl. inside-hits and misses, closest-hit selection across overlapping spheres, each material's scatter behaviour, camera basis orthonormality, sub-pixel jitter staying inside its pixel, and regression tests for the fuzz clamp and the degenerate aspect_ratio.
Not done
render() is still single-threaded — 1200x675x500 is 405M primary rays. Row-parallel std.Thread is the obvious next win, but it needs per-thread PRNG state first, which is exactly what the util.zig global blocks. Left a ponytail: marker there rather than widening this PR.

  works today but breaks confusingly if the global ever moves or becomes
