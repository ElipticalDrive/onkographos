UNION, SUBTRACT and INTERSECT currently reject 2D regions whose boundaries cross or touch. This supports crossing, touching and coincident line/arc boundaries while preserving circular arcs above the geometric resolution, holes and disconnected pieces. Two 10×10 squares overlapping by 5×5 produce areas 175 (union), 75 (subtract) and 25 (intersect).
The geometry kernel:
Sweeps conservative edge bounds, with chord/sagitta separation tests, to find candidate crossings. Candidate visits, geometric work and split storage remain bounded.
Splits boundaries at crossings and coincident ends, then classifies each continuous run between cuts once. Original vertices do not restart classification; an untouched loop needs one classification. MAX_WORK remains 10 million.
Evaluates arc points, projections and ray crossings in chord/bulge coordinates to avoid cancellation at distant centers. A sagitta at or below the normalized tolerance (1e-10) is treated as straight. Center/radius precision checks apply only to potentially intersecting edge pairs.
The result retains the first region's handle and properties, with one undo step. Errors return before the drawing is edited. Regions do not refill from hatch sources handles, so rebuilt region loops clear them; this is documented at the command adapter. No dependencies, lint settings or CI configuration change.
Addresses the overlapping-region boolean subitem of docs/gaps.md F21; the other F21 items remain. Related: #510.
Validation
Added 18 geometry tests and 8 engine integration tests for crossings, shared edges, coincident arcs, tangencies, holes, concave outlines, disconnected results, translated/scaled coordinates, hostile input, budgets, JSON/command-line invocation, undo/redo, failure atomicity, EXPLODE and DXF round trips.
Reviewer regressions: disjoint 1,000-, 2,000- and 6,000-vertex polygon contours retain their analytic areas. A 2,000-vertex contour crossed by a square yields the analytic polygon half-area for INTERSECT and SUBTRACT and the corresponding UNION area. Engine checks cover both 1,000 and 2,000 vertices and all three commands.
Shallow bulges ±1e-6, ±1e-8 and ±1e-10 work when disjoint, nested or away from actual crossings, with known-area checks. Rotated/reversed nested loops are covered; resolvable bulges remain curved and sub-tolerance bulges become straight.
Confirmed the large-contour and distant-shallow-arc regression tests fail on the previous PR head. The earlier missed-crossing/data-loss regression still returns a precision error and preserves the drawing, selection, revision, undo and pending redo.

Limits
Inputs are closed, non-self-crossing line/arc loops. Unresolved potentially intersecting arcs, excessive geometric work or split storage return an error. Existing REGION serialization remains unchanged; this does not add native ACIS output. No AutoCAD black-box validation was run for this change.

Tested on Windows 10 Pro x64 (stable Rust), with this PR merged onto current main (a655cee) together with #2444, #2870 and #2876, which touch other files. cargo xtask ci on this batch: all 7 steps pass (fmt, clippy, 3629 tests, i18n, assets, layers, wasm), including this PR's new tests.
The overlapping cases now run. Your tests pass, and a 400- or 1000-vertex region unions with a square across its edge, which main refuses (I checked that it succeeds, not the resulting area). Two changes would make it ready, because each one breaks a case that works on main today.
1. Regions with more than about 800 vertices fail, even when they don't touch
main combines regions whose boundaries don't meet: it only tests whether boundaries cross (up to 50 million segment pairs), then keeps or drops whole loops. With this PR every boolean goes through retain for every piece. Each piece charges a.len() + b.len() for the clearance search, plus four contains calls of a.len() or b.len() each. That is about 3·N² work units for N edges in total, against MAX_WORK of 10 million, so the limit is reached at roughly 1,800 edges in total.

A 2000-vertex region and a square overlapping it also fails ("too complex"). Outlines from splines, imported contours or exploded text reach these sizes easily.
A suggestion that keeps the budget as it is: a piece's verdict (keep, keep reversed, drop) can only change at a split point from cuts. Between two split points on the same input loop, every piece has the same verdict, original vertices included. Classify one piece per run of unsplit edges and give the rest of the run the same verdict. A loop that nothing crosses is then one retain call, as on main, and the cost grows with the number of crossings instead of N². A bounding-box check in the cuts pair loop would also skip most pairs cheaply.
2. A very small bulge anywhere fails the whole operation, even with no overlap
Edge::new rejects an arc when 32·ε·(|center| + radius) exceeds TOL (1e-10, normalized). A nearly flat arc has a large radius, so this triggers for bulges below roughly 1e-5. The exact limit depends on the edge's length relative to the drawing. Bulges like that are common in imported DXF files as round-off. The disjoint column is the regression: main combines those regions, and the arc is nowhere near the other square.
Two ideas, either or both:
An arc whose sagitta (|bulge|·chord/2) is at or below TOL is indistinguishable from its chord at the kernel's resolution. Treat it as a line, which covers round-off bulges like 1e-10.
Check the precision only where it matters. Run the check in cuts, for a pair whose bounding boxes overlap, instead of in Edge::new. Then a flat arc far from the other region doesn't fail the operation. For flat arcs that do meet the other boundary, line/arc intersections computed in the chord's own frame (from the endpoints and bulge) avoid subtracting large center coordinates.
Each probe above is a few lines in crates/engine/tests/it/region.rs, and they would make good regression tests for whichever fix you choose.
Smaller notes
combine in regions.rs builds every loop with sources: Vec::new(). On main, loops that come through unchanged keep their sources. If nothing reads sources on a region that's fine, but it's worth a sentence in the doc comment.
The nonminimal_bool lints you hit in cargo xtask ci don't appear on the current stable toolchain here: the gate's clippy step passes on this batch. A newer clippy probably added them. Fixing them would be a separate PR.

Moving it alone would still expose cancellation in classification queries, so arc evaluation, projection and ray crossings now use chord/bulge coordinates. Arcs above resolution keep their bulges; sagitta at or below normalized TOL is treated as straight. Tests cover positive/negative 1e-6, 1e-8 and 1e-10 bulges in disjoint, nested and otherwise crossed regions, plus rotated/reversed nested loops. The earlier near-straight-arc missed-crossing regression still fails safely and keeps the drawing, selection and history unchanged.
