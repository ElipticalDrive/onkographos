Summary
Adds automatic detection of docs/local-refinement/PROBLEMS.md's Проблема 2 — a coarse voxel can physically touch two topologically disconnected pieces of the imported body (the motivating tooth-root example: two roots with an air gap between them, both touching one grubby voxel). Naively snapping that voxel's boundary onto the nearest STL point later produces a self-intersecting/inverted element.
This is deliberately scoped to marking + visualization only — "an instrument that marks which voxels need splitting, so I can actually see them." It does not build the T1/T2/T4 local-refinement engine itself (a separate, later feature), and does not touch ZonePaintingService/SurfaceZonePaintingService.
Backend (Solvix.Voxelization): IsCubeIncluded now reports whether a triangle genuinely touched the cell (not just the center-inside fallback). For touched cells, HasConnectivitySplit samples a uniform 4×4×4 grid of points and flood-fills the "inside" ones by this same fine grid's own face-adjacency — more than one connected group means the cell straddles a real gap. An earlier recursive-octree version of this had a real bug (octants adjacent by index aren't necessarily adjacent in the sense that matters, silently merging disconnected pieces) — the fixed-resolution sampling approach avoids that class of bug entirely. VoxelizationResult gains a second bitmask, MarkedForRefinement, same shape as Occupancy.
Frontend: decodes the new bitmask, and VoxelCell carries its own markedForRefinement flag so scene-objects/voxels.ts can tint a marked cell's fill a distinct red-orange — no click-to-refine interaction yet.
New tests: a synthetic two-prong fixture (two thin boxes with a gap, both fitting inside one voxel) marks exactly that voxel; a plain solid box marks nothing.

```
Adds automatic detection of docs/local-refinement/PROBLEMS.md's
Проблема 2 - a coarse voxel can physically touch two topologically
disconnected pieces of the imported body (the motivating tooth-root
example: two roots with an air gap between them, both touching one
grubby voxel). Naively snapping that voxel's boundary onto the
nearest STL point later produces a self-intersecting/inverted
element.

IsCubeIncluded now reports touchedByTriangle (true whenever any
triangle genuinely intersects the box, regardless of which branch
ultimately decided inclusion) - only cells the surface actually
passes through are worth checking; a cell included purely via the
center-inside fallback sits deep in solid material with nothing to
split internally.

HasConnectivitySplit samples a uniform 4x4x4 grid of points inside a
candidate cell via the existing IsPointInsideViaGrid (already general
enough for any point, not just cell centers - no new primitive
needed), then flood-fills the "inside" samples using THIS SAME fine
grid's own face-adjacency: more than one connected group means the
cell straddles a real gap. Deliberately NOT a recursive octree split
(divide into 8, recurse into each inside child on an inconclusive
result) - an earlier version of this method did exactly that and had
a real bug: octants adjacent BY INDEX (agree on 2 of 3 axes) aren't
necessarily adjacent in the sense that matters - a gap narrower than
one octant can sit entirely between two "inside" centers without
either landing in it, silently merging two disconnected pieces into
one group forever. Sampling everything at one fixed resolution up
front avoids that class of bug entirely.

VoxelizationResult gains a second bitmask, MarkedForRefinement, same
shape/indexing as Occupancy - purely diagnostic today, nothing yet
consumes it beyond the wire format and (next commit) a visual
highlight; local refinement itself remains a separate, not-yet-built
feature.

New tests: a synthetic two-prong fixture (two 0.3-wide boxes with a
0.2-wide gap, both fitting inside one unit voxel) marks exactly that
voxel; a plain solid box marks nothing.
```
