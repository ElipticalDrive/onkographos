Summary
Adds a robust ray–mesh intersection that classifies hits exactly with respect to the mathematical ray defined by the floating point inputs source and dir, using only exact sign predicates and no exact constructions. No intersection point or ray parameter is ever built for the exact result (constructing them would be inexact).
The key observation: because the ray direction is a free vector, the 3×3 determinants needed to test a ray against a triangle (and to order two hits) have a raw-direction row and therefore cannot be reduced to Shewchuk's point-based orient3d without first forming source+dir, which would round and perturb the exact ray. The exact sign is instead evaluated directly from the original coordinates with adaptive-precision expansion arithmetic. Because that arithmetic is self-contained (it does not call the Shewchuk predicates library), everything lives in core igl/ / namespace igl::.
What's added (all in core igl/)
exact_ray_triangle_intersect — exact per-triangle boolean. Transverse hits (including edge/vertex grazing) are decided exactly; a ray coplanar with the triangle plane (det(dir,B−A,C−A)==0) is reported as a non-hit (documented measure-zero degeneracy where the intersection is a t-interval).
exact_ray_triangle_hit_compare — exact -1/0/+1 ordering of two triangles' (unconstructed) hit distances, evaluated as the sign of a difference of products of determinants.
exact_ray_mesh_intersect / exact_ray_mesh_intersect_all — first hit / all hits sorted near-to-far. Core overloads return face indices only (no constructed location); convenience overloads post-process an approximate igl::Hit{t,u,v} for the winning face(s).
eytzinger_aabb_ray_intersection — generic Eytzinger-AABB traversal (mirrors eytzinger_aabb_sdf) taking hit / before handles. Carries no exact-valued state — only the current best primitive's index propagates. Box culling and front-to-back ordering use ordinary floating point made conservative (inflated boxes + a distance-pruning safety margin, slack derived from numeric_limits<Scalar>::epsilon()), so a genuine hit is never skipped; the closest hit and final ordering are decided by the exact comparator.
ray_triangle_intersection_parameters — an ordinary (inexact) Möller–Trumbore parametric solve returning (t,u,v) with no culling. Distinct from igl::ray_triangle_intersect (which takes (V,F,face) and culls to a Hit), so it is not an overload.
Internal exact_ray_triangle_kernel.h holds the shared expansion-arithmetic + exact 3×3-determinant helpers (fma-based two_product, fast_expansion_sum, scale_expansion, expansion×expansion) behind a conservative float filter with an always-correct exact fallback.
Templating / precision
The exact_* entry points static_assert float/double coordinates (IEEE-double arithmetic is required for exactness; float promotes to double exactly) and compute in double.
ray_triangle_intersection_parameters and eytzinger_aabb_ray_intersection are fully templated on the scalar.
Testing
exact_* leaf predicates vs. an independent __int128 reference on tiny-coordinate (heavily degenerate: coplanar, edge, vertex) integer configurations;
AABB traversal (first + all) vs. an exact brute-force scan on random meshes;
agreement with the double-precision Möller–Trumbore reference (igl::ray_mesh_intersect) on a real, well-separated mesh;
unit test for ray_triangle_intersection_parameters (double + float).
All tests pass under static-library linking (which exercises every explicit instantiation).

```
The proposed ray_triangle_intersection_parameters duplicated the existing
corner-based igl::ray_triangle_intersect(O,D,V0,V1,V2,epsilon,t,u,v,parallel)
(an Eigen Möller–Trumbore rewrite). Remove it and have exact_ray_mesh_intersect
build its approximate convenience Hit / pruning-t via that existing overload.

Performance regression testing showed the corner-based overload is ~1.3× slower
than raytri.c's intersect_triangle1 (Eigen overhead + no cross-TU inlining), so
igl::ray_mesh_intersect is intentionally left on intersect_triangle1 to avoid a
~30% regression in brute-force and AABB ray casting. (The exact path is dominated
by the exact predicates, so the choice is immaterial there.)
```

First-hit: provably-exact traversal with no distance-pruning fudge
…
4777048
```
Replaced the approximate-t first-hit pruning (a heuristic margin) with a
provably-exact strategy. Two exact options were implemented and benchmarked:

  1. no distance pruning — box cull + exact `before` ordering only
  2. exact pruning — skip a subtree when its box's entry parameter provably
     exceeds the current best hit's t (rational cross-multiplication sign test)

Both matched exact brute force on all randomized/degenerate tests. Benchmarks
(1k and 22k-face meshes) showed them within ~1%: the conservative box cull
already confines traversal to the ray's neighborhood, so the exact box-vs-best
predicate costs about what it saves. Option 1 is therefore chosen for being
simpler and equally fast, and option 2's machinery (kernel box_after, the prune
callback, the num/den caching) is removed.

The first-hit result is now decided entirely by exact predicates (classification
via exact_ray_triangle_intersect, ordering via exact_ray_triangle_hit_compare);
the only floating point left in the traversal is the conservative box cull and
the nearer-child-first visit order, neither of which can change the result.
```
