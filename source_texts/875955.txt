Goals
Render independently animated glTF crowds at mesh detail appropriate to each actor's projected screen size.
Support both interoperable authored MSFT_lod assets and real automatic mesh decimation without adding an unpublished math.gl package or a runtime WASM dependency.
Keep independent animation clips, transforms, skinning, and instanced draw batching correct on both WebGPU and WebGL 2.
Changes
Add reusable @luma.gl/engine simplifyMesh() with deterministic quadric-error endpoint collapses, original typed index preservation, winding/degeneracy checks, configurable boundary preservation, UV/normal weighting, and hard skeletal-joint domain protection.
Add getGLTFNodeLODs() and generateGLTFLODLevels() for validated authored MSFT_lod node alternatives, exact MSFT_screencoverage hints, immutable source documents, and generated index-only meshes that retain original attributes, skins, materials, morph accessors, and animations.
Extend GLTFAnimatedCrowd with optional authored/generated screen-space detail levels, offscreen/tiny-actor culling, hysteresis, configurable detail bias, dense independent transform and joint-palette buckets, and one real instanced draw per occupied primitive/detail group.
Add an optional global submitted-vertex budget: preserve each actor's screen-space preferred LOD, then deterministically demote the smallest/farthest visible actors until total indexed geometry fits. Count real submitted index references across every source primitive, preserve independent skin palettes, expose demotion/budget diagnostics, and never hide actors merely because a budget is impossible.
Add crowd.update(deltaSeconds, view) so animation advancement, camera classification, and GPU uploads occur exactly once per frame. Existing setLODView(), runtime enable/disable, and full detail statistics remain available.
Add Animation Studio Auto LOD, Detail Bias, and Vertex Budget controls, authored/generated indicators, live bucket histograms, visible/culled actor counts, triangle and submitted-vertex totals, demotion counts, unsatisfied-budget warnings, and actual draw counts. Auto LOD defaults off, zero budget means unlimited, and inactive prepared models are skipped.
Document the public engine/glTF APIs, backend/resource boundaries, authored extension behavior, decimation tradeoffs, and current CPU-selection limitations; register node-level MSFT_lod as supported.
Measured result
Real Robot Expressive with 12 independently animated actors:
Full detail: 38,844 triangles, 19 instanced draws.
Automatic screen-space LOD: 11,794 triangles, 38 occupied detail-group draws — 69.6% fewer triangles.
Individual generated character levels: 3,237 → 1,617 → 856 triangles.
Increasing detail bias changes the occupied groups and triangle budget immediately without resetting actor animation or allocating new models.
With detail bias increased, setting a 32,000-vertex budget demotes 11 farthest actors and lowers submitted work from 80,229 → 30,816 vertices while keeping all 12 actors visible. An impossible 20,000-vertex budget truthfully reports budgetSatisfied: false without silently culling anyone.
Confirmed interactively on both real WebGPU and WebGL 2 with zero browser errors.
Verification
All 19 TypeScript package project references build successfully using the same tspc -b compiler used by the package build.
74 focused Node tests across mesh decimation, authored/generated LOD parsing, crowd grouping/culling/hysteresis/lifetime, deterministic farthest-first budgets, impossible-budget behavior, native extensions, capabilities, and SPDX provenance.
47 real native Chromium/WebGPU/WebGL browser tests, including visible framebuffer readback for authored and automatically generated independently skinned LOD crowds plus budgeted actor demotion.
36 CI-like SwiftShader browser tests covering both backends, generated levels, and live Studio controls.
Real production Docusaurus build plus normalized LLM documentation validation; all 480 raw docs pass.
Bundle budgets pass; all touched TypeScript sources pass scoped Biome checks.
Scope and follow-up
This PR is intentionally stacked on feat(gltf): document animated GPU crowds and add authored LOD fixtures #3039 so its review contains only the auto-LOD implementation. Retarget to master after feat(gltf): document animated GPU crowds and add authored LOD fixtures #3039 merges.
The stacked base also fixes an inherited animation-loop browser timing race that previously made both otherwise-green workflows flaky.
Classification and decimation are currently CPU-side; vertex deformation and instanced rendering remain GPU-side. Compute-driven classification, GPU-generated indirect commands, progressive asset streaming, material LOD, and per-actor GPU morph deformation are explicitly outside this tranche.
simplifyMesh() is format-independent and intentionally lives in the existing engine package; its typed-array contract can later move to a published @math.gl/geometry package if one is created.

Distinguish normalized attributes from discrete joint IDs
When a glTF uses normalized Uint8Array or Uint16Array accessors for UVs or weights, this classifies every such attribute as discrete, and any difference between adjacent vertices makes the collapse cost infinite. Quantized texture coordinates normally differ along nearly every edge, so autoGenerate may produce no LOD levels at all for otherwise simplifiable meshes. Preserve the accessor's normalized/semantic metadata and reserve the discrete comparison for attributes such as JOINTS_0.

Cull actors against the depth clip planes
When the supplied projection is orthographic, clipW is always 1, so this test cannot identify actors behind the camera; actors beyond the near or far plane also survive because the subsequent frustum check only considers X and Y. Such actors are packed into instance buffers, charged against the vertex budget, and reported as visible even though the GPU clips them by depth. Compute clip-space Z and test the bounding sphere against the projection's depth range as well.

Count triangles according to the primitive mode
When an authored LOD primitive uses TRIANGLE_STRIP or TRIANGLE_FAN, its triangle count is indexCount - 2, while point and line modes contribute no triangles; dividing every primitive's index count by three is only valid for TRIANGLES. Consequently lodStats.triangles, per-level statistics, and the Studio status readout report incorrect submitted work for valid non-triangle-list glTF assets. Derive this value from primitive.mode.
