Goal
Add a grid-based raycaster rendering mode alongside the existing sector/portal renderer (#169). The raycaster targets Wolf3D-style level geometry (uniform-height walls on a 2D grid, flat floors/ceilings) but with modern per-pixel dynamic lighting, shadows, and volumetrics.
Motivation
A raycaster world is structurally simpler than sector/portal geometry, making it ideal for certain game styles (dungeon crawlers, horror, retro shooters). The grid constraint makes shadow computation trivially fast (DDA traversal), enabling high light counts and real-time shadows that would be expensive in arbitrary 3D geometry. This gives us a visually striking combination: chunky grid-world geometry + physically-motivated lighting (think Doom 3, Resident Evil, BioShock atmospherics).
This is a separate rendering mode from the sector/portal renderer — different world representation, different visibility solver, shared lighting and post-process infrastructure where practical.
Proposed architecture
Primary path: GPU (compute/fragment shader)
Raycaster visibility pass → outputs G-buffer (world position, normal, albedo, depth, material ID)
Light accumulation pass → per-pixel point/spot/directional lights with grid-based shadow rays (DDA in shader)
Volumetric pass (optional) → ray-march camera rays through grid, accumulate in-scatter for god rays / fog
Post-process → bloom, SSAO (depth already available), tone mapping, color grading
Composite → final framebuffer
Software fallback: CPU raycaster
Classic DDA raycaster produces the same G-buffer data into a CPU-side buffer
Upload to GPU for lighting passes, or fall back to simplified CPU lighting
Key features
Axis-aligned grid walls → normals are free (±X, ±Z, ±Y for floor/ceiling)
Shadow rays via DDA → O(grid_size), no BVH needed, supports dozens of dynamic lights
Normal mapping on wall/floor textures for surface detail
Colored dynamic point lights, spot lights, flickering/pulsing
Emissive surfaces + bloom
Volumetric light shafts through doorways and openings
Thin doors, push walls, variable-height sectors (optional extensions beyond classic Wolf3D)
Relationship to existing work
Shares authored world data format patterns with the sector/portal renderer (Define generalized world model abstraction for 3D game types #169)
Should reuse the engine's existing light, camera, and post-process infrastructure
World kind would be something like "kind": "raycaster_grid" alongside existing "fixed_screen" and sector/portal kinds
Visual references
Prodeus — raycaster aesthetic + modern lighting/particles
HROT — retro geometry + colored dynamic lights
Doom 3 — few lights, all dynamic, all casting hard shadows
Ion Fury — Build engine + modern color grading
Work slices (rough)
Grid world representation and authored JSON format
GPU raycaster visibility pass (DDA in compute shader, G-buffer output)
Deferred lighting pass with grid-based shadow rays
CPU software fallback raycaster
Normal mapping and material system integration
Volumetric lighting / fog pass
Post-process integration (bloom, SSAO, tone mapping)
Doors, push walls, and interactive grid elements
Documentation and demo scene

Scope clarification
This renderer should stay true to classic raycaster constraints:
In scope:
Uniform wall height — all walls are the same height, no variable floor/ceiling
Flat floors and ceilings
Axis-aligned grid walls only
Dynamic geometry: push walls, sliding doors, destructible walls (grid cell mutations)
Modern per-pixel dynamic lighting with shadow rays
Volumetric fog and light shafts
Particle effects
Normal mapping on surfaces
Bloom, SSAO, tone mapping
Billboarded sprites for objects/enemies
Explicitly out of scope:
Variable height floors/ceilings
Stairs, pits, platforms, elevators
Sloped surfaces
Rooms over rooms
Non-orthogonal walls
Any extension that moves beyond a flat uniform-height grid
The goal is a pure Wolf3D-style world with dramatically better lighting, atmosphere, and effects — not a Doom/Build-style renderer with height variation. Keep it simple and lean into what the grid does well.
