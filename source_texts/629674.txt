Goal
Create one inspectable orbital-to-local navigation experience for near-field
gameplay and simulation. A Moon surface location marker should lead into the
base view, whose UI can select local objects and return to orbit without
recreating the renderer.
Ownership boundary
sagan-render owns reusable scene, marker, camera-transition, picking, UI,
mesh, material, depth, and native-backend contracts.
A demo may use deterministic renderer-neutral fixtures to prove those
contracts.
Physics reference frames and authoritative body orientation come from
sagan-physics or an application-owned adapter.
Construction, resources, power, storage, economy, and other game-specific
base behavior remain in sagan-space-game.
Mini roadmap
1. Local surface foundation
Add a separate close, oblique top-down lunar surface demo.
Add reusable unit-typed cuboid geometry to the shared indexed scene pass.
Render a renderer-neutral landing pad, lander, habitats, power array,
communications tower, and nearby objects.
Exercise the same camera-relative precision, material, lighting, depth,
D3D12, Vulkan, and Metal contracts as the orbital scene.
Tracked in PR #66.
2. Moon location marker and unified entry
Define a stable surface-location marker with marker ID, parent body ID,
latitude, longitude, altitude, label, and local-view destination ID.
Convert body-fixed latitude/longitude into a measured Moon-relative
position without embedding orbital or geodetic policy in the renderer.
Render a KSP-like marker and label above the near-side surface.
Hide markers behind the Moon and provide deterministic hover, selection,
and pointer picking by stable ID.
Consolidate orbital and local presentation into one process and enter the
existing base view by clicking the marker.
3. Reference-frame and camera transition
Define the local tangent basis (east, north, up) from an application- or
physics-owned Moon reference frame.
Transform local metre-scale base geometry through the tangent frame into
camera-relative world geometry near the existing distant origin.
Smoothly center the marker, decrease measured camera distance, align
camera up toward the surface normal, and hand off detail without a jump,
orientation flip, blank frame, or obvious scale discontinuity.
Fade orbital marker presentation out as surface UI becomes active.
Establish shared body-fixed albedo identity with NASA-derived Earth Blue
Marble and Moon LRO grids.
Remove the local subscene and ground plane; render tangent-frame buildings
directly above the same depth-tested Moon mesh throughout the descent.
Replace the bootstrap per-cell albedo grid with native GPU sampling of
1024x512 Earth and 2048x1024 Moon textures on the shared UV sphere.
Select and feather-blend a 0.8-metre-per-pixel LROC Shackleton rim tile
below 100 km altitude without replacing the Moon mesh or base frame.
Generalize the demonstrated global/local LOD path into a regional tile
catalog and application-supplied body-fixed tile metadata.
4. Base-management UI and return to orbit
Add a base header, reusable tabs/panels, selected-object summary, and a
keyboard- and pointer-accessible Return to Orbit action.
Let the demo select structures and vehicles through renderer-owned stable
presentation IDs without implementing game rules.
Return through the same navigation state machine to the prior orbital
framing without recreating the window or renderer.
5. Cross-platform closure evidence
Test marker conversion, near-side visibility, far-side occlusion,
picking, tangent-frame handedness, and precision near 1e15 metre.
Capture orbital, selected-marker, mid-transition, surface/UI, and returned
orbital frames on D3D12, Vulkan, and Metal.
Document remaining terrain/texture level-of-detail limitations and the
application handoff required for shared Moon asset identity.
Acceptance criteria
An accepted coordinate and transition design is tied to an explicit
physics/application reference-frame boundary.
One demonstration displays the orbital Moon, a surface location marker, a
base, a ship, and nearby objects.
Clicking the marker reaches the local base presentation; its UI can select a
local object and return to orbit in the same process.
Moon identity, measured marker location, lighting direction, and renderer
contracts remain continuous across navigation modes.
D3D12, Vulkan, and Metal evidence exercises the same public renderer
contracts.
Game-specific content remains in the Space Game repository.

The raw Shackleton NAC crop is no longer bound as albedo in a10e546. Supplied screenshots and source statistics confirmed its finite square footprint was the reported rectangle. NASA describes the observation as extreme-Sun-angle imagery; it contains baked illumination and is photometrically incompatible with the global Moon map. A future high-resolution local-detail milestone must use a normalized product or a separate detail/reflectance contract rather than direct albedo replacement.
