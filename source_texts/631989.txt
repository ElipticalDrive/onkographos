Change summary
Aggregating point verification statistics across an observation network over-emphasizes data-rich regions: where stations are densely clustered, many nearly redundant observations dominate the result. This PR adds kernel density estimation (KDE) point weighting to MET, following the station density weighting of Rodwell et al. (2010) and Haiden et al. (2012), so that each station's weight reflects how densely its neighborhood is sampled.
The weight for station k is the inverse of its station density:
```
w_k = 1 / rho_k,  where  rho_k = sum_l exp(-(a_kl / kde_ref_angle)^2)
```
The sum is over all stations l, including l = k, and a_kl is the great circle angle between the stations. Since a_kk = 0, rho_k ≥ 1 and the weights always fall in the range (0, 1], where a weight of 1 indicates an isolated station. This is consistent with grid_weight_flag = COS_LAT grid weights.
High-level summary of changes:
Add the point_weight_flag = KDE option to Point-Stat, Ensemble-Stat, and Pair-Stat.
Add two new configuration options:
kde_ref_angle (default 0.75 degrees) defines the kernel reference angle and must be greater than 0 for KDE.
write_weights (default FALSE) writes the SID or KDE point weights to ASCII output files that can be reused as mask.sid station ID files.
Compute point weights separately for each verification task, using only the stations whose observations that task uses, so adding or removing a task never changes the results of any other task. For example, adding TMP/Z2 versus ADPSFC does not change the weights applied to TMP/P850 versus ADPUPA.
Write one point weight file per verification task, named ..._NAME_LEVEL_TYPE_point_weights.txt using the forecast variable name and level, with the 1-based task index appended if two tasks share a name and level.
Treat each unique station ID as a single point in the density calculation, located at the first location encountered for that station within each task.
Add the new PointWeightInfo class to the vx_util library and the new gc_angle() function to the vx_nav library. Since vx_util now calls vx_nav, update the library link order for the affected tools.
Add 5 new unit tests to unit_point_weight.xml, including a Pair-Stat test that reads Point-Stat MPR output and reproduces its KDE weights and weighted contingency table counts.
Update the documentation for the new options and output files, and correct the outdated statement that SEEPS density weighting is not implemented.
Clean up the ordering and whitespace of existing configuration files, and fix a few small unrelated issues found along the way (listed below).

@KathrynNewman I'm marking this PR as ready for review again. A review of the changes revealed some issues:
The weight computation for each point should include comparing against itself which is what the references do. That basically means initializing the weight sums to 1.0 rather than 0.0. The good news is that this solves the whole divide by zero = infinite weight problem. That makes it much easier for users.
Rather than computing the KDE weights once for each run, they're now computed separately for each vx task. Previously verifying against both ADPSFC and ADPUPA in one run would produce different results from verifying against them in separate runs. Now, the weights are computed from their locations separately.
You'll notice a lot more detail in the PR body. AI really helped summarize a large set of changes.
