This is an old library with a single version release 1.0.0 >10 years ago, but OrcaSlicer added it as a dependancy earlier this year.
It seems the original Makefile build is broken, and others have forked it to build with CMake.
See:
https://github.com/SoftFever/Orca-deps-libnoise

But void won't package a fork that just changes the build style, so I'm trying to see if I can patch the original source to work.
But if someone else wanted to try to take a stab at it, you're welcome to.

Hello, thanks for the info but yes, the sourceforge is the original source and is what I was trying to get working.
You might notice that the AUR package and all the other various forks are just taking the original source code and adding a cutsom CMake, which will fix the build process.
I spoke about this with maintainers on the Void IRC and my understanding from that is that the requirement to package a fork on void is that the fork has a histrory of '"independant devlopement". And just changing the build style of a package, done by the would-be maintainer, or someone else, does not meet that, that would not be accepted as a package.
So as far as I'm aware, any void maintainer please correct me if not, is the only way to make this work is to patch the original make to work, which is beyond my abilities, and as all other fixes for it just change the build style, I have nothing go base a fix on.
