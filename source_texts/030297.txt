## Description

Add opt-in SteadySplats rendering to reduce stochastic splat shimmer through spatial resampling and temporal accumulation. Supported views avoid depth sorting on WebGPU and capable WebGL2 devices. Stationary views refine for 16 frames by default, then retain the reconstructed image until it changes.

- Use per-primitive spatiotemporal blue noise, four spatial neighbors and a four-entry foreground occluder history.
- Preserve temporal history during camera motion and progressively converge after the camera stops.
- Integrate native picking, shadows, CameraFrame color settings, render scale and sorting fallback.
- Keep automatic renderer selection and the native sorted rendering algorithms unchanged.
- Add controls and comparison modes to the Gaussian Splatting / SteadySplats example.

## Credits and LichtFeld-Studio integration

Based on [SteadySplats: Resampling of Low-Variance Gaussians for High-Fidelity Stochastic Rendering](https://arxiv.org/abs/2610.05576), by Felix Windisch, Thomas Köhler, Lukas Radl, Chris Wyman, Georgios Kopanas, Bernhard Kerbl and Markus Steinberger (2026). The authors' [project and original viewer](https://derthomy.github.io/SteadySplats/) provide the rendering reference.

Related LichtFeld-Studio integrations by Yehe Liu, verified October 23, 2026:

- [#3726: color-variance training](https://github.com/MrNeRF/LichtFeld-Studio/pull/3726) **merged into `master`** on October 23. It implements the paper's separate training objective.
- [#3728: viewport resampling](https://github.com/MrNeRF/LichtFeld-Studio/pull/3728) is **still open**. It is the companion native rendering integration.

This PR covers PlayCanvas rendering; it does not add model training.

## Public API changes

All additions are beta and opt-in, with no breaking changes. Add `GSPLAT_RENDERER_STEADY`, three `GSplatParams` settings and `resetHistory()`:

Before:

    app.scene.gsplat.renderer = pc.GSPLAT_RENDERER_AUTO;

After:

    app.scene.gsplat.renderer = pc.GSPLAT_RENDERER_STEADY;
    camera.camera.jitter = 1; // Existing API: animate samples.
    app.scene.gsplat.steadyHistoryWeight = 0.7;
    app.scene.gsplat.steadyConvergence = true;
    app.scene.gsplat.steadyConvergenceFrames = 16; // Range: 1–1024.
    app.scene.gsplat.resetHistory(); // After a camera cut or external shader input change.

Zero history weight disables temporal color reuse while preserving spatial reuse. Pending refinement uses the existing `frame:request` event for applications rendering on demand.

## Technical details and performance

WebGPU uses compute reconstruction; WebGL2 uses render targets. Supported views require a full viewport, mono perspective camera, standard Gaussian coverage, depth independent of projected x/y, and no opaque mesh occluders. Unsupported views retain native sorting. WebGL2 requires floating-point render targets and four color attachments. CPU fallback retains native center-data requirements.

Stationary averaging uses eight spatial estimates followed by raw visibility samples. WebGPU compaction splits large intervals only for SteadySplats and reuses unchanged projection data. Frame resources require approximately 136 bytes per render pixel on WebGPU or 220 on WebGL2 with convergence enabled, excluding shared splat data, the WebGPU projection cache and the 64 KiB STBN volume.

Local moving-camera median GPU times at 1920 × 1080 on RTX 5090 / Dawn D3D12:

| Scene | Splats | SteadySplats | Native GPU sorting |
| --- | ---: | ---: | ---: |
| Biker | 152,746 | 0.269 ms | 0.394 ms |
| Garden, lambda-var = 1 | 3,211,894 | 1.045 ms | 1.523 ms |

Each condition used 40 warmup and 192 measured frames with matching models and camera paths. These GPU measurements exclude CPU work, presentation and vsync. Stochastic reconstruction and deterministic sorting have different image quality; these results are specific to the tested hardware and scenes.
