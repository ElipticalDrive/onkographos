Owner
Plan PR RE12 of the calib views plan (plan PR 3). Based on main, not stacked; it needs no other PR. calib's GPU depth checks (CA8b) include it.
Summary
recon publishes the pinhole projection its kernels already use, so calib's kernels include it rather than copy it.
src/volumetric_kit/recon/core/shaders/pinhole.glsl, beside color_common.glsl:
vec3 vr_world_to_camera(mat4 cam_to_world, vec3 world), the rigid inverse R^T (world − t);
vec3 vr_unproject_pinhole(vec2 px, float z, vec4 k);
bool vr_pinhole_pixel(vec3 p_cam, vec4 k, out vec2 px), the divide wherever the pixel lands (refuses only z ≤ 0 or a NaN depth);
bool vr_project_pinhole(vec3 p_cam, vec4 k, uvec2 size, out vec2 px), the same within [0, W) × [0, H);
uvec2 vr_nearest_pixel(vec2 px, uvec2 size).
k is (fx, fy, cx, cy). The functions take values, not structs, so recon's scalar-layout cameras and calib's std430 ones both pass theirs. Today's rules hold: every test negated so a NaN fails, the domain [0, W) × [0, H), and the last half pixel clamped to the edge pixel. Nothing assumes a camera count: each call takes one camera's values, so a kernel over N cameras calls it per camera.
recon's kernels go through it.
tsdf_common.glsl's project_pinhole and nearest_pixel are thin wrappers.
hash_allocate_depth.comp unprojects with vr_unproject_pinhole.
texture_common.glsl's world_to_camera and camera_to_image call vr_world_to_camera and vr_pinhole_pixel, keeping texture's extrapolating, NaN-only acceptance.
undistort_depth.comp's colour test unprojects with vr_unproject_pinhole and divides with vr_pinhole_pixel, keeping its rounded-pixel bounds.
tsdf, volume and texture keep their order of operations, so they change no bit. The sensor prep's colour test changes order (rounding level); its tests pass unchanged.
Exported and installed. recon_core carries the property VR_SHADER_INCLUDE_DIR, the root a consumer passes its shader compiler:
in the build tree (FetchContent), a generated directory holding the exported GLSL alone, so a kernel that compiles against a fetched recon cannot include recon's internal GLSL and then break against an install;
installed, <prefix>/include, which the package config sets on the imported volumetric_kit::recon_core.
```
get_target_property(vr_glsl volumetric_kit::recon_core VR_SHADER_INCLUDE_DIR)
vkc_embed_shaders(calib_depth SYMBOL_PREFIX vc_ INCLUDE_DIRS "${vr_glsl}" SHADERS ...)
```
Docs: README (how a consumer includes it), DESIGN (end of core), a dated DECISIONS entry ("A shared GLSL pinhole for recon and its consumers", amending the 2026-08-11 texturing entry's per-tier copies, with an amendment line there), CHANGELOG.
Notes
Only acceptance rules stay with callers. The plan kept texture's variant. After review, the variants are only the two acceptance rules; the arithmetic is shared.
texture extrapolates past the image (2026-08-11) on vr_pinhole_pixel.
The sensor prep's colour test bounds the rounded colour pixel, [−0.5, W − 0.5), as the colour pass marks coverage, on vr_pinhole_pixel.
The first push left undistort_depth.comp's unprojection and divide as copies. Its body called them part of the lens path; they work on pinhole pixels, so they now go through the shared file.
lens.glsl's source_pixel normalizes at z = 1 inside the lens model, the device mirror of camera::distort_rational. It stays with that mirror.
Volume's unprojection is in scope. The plan names only tsdf's wrappers. hash_allocate_depth.comp restated the same unprojection, though, and the family rule is one home per function.
Why recon's core tier. The core locks "No camera or sensor tier". recon's camera tier builds without Vulkan, and volume and tsdf do not depend on it, so they could not include it. gfx depends on no recon, so GF5's point shader restates the in-image test and the nearest-pixel rule on its own; its tests must hold that copy to recon's rule (DECISIONS says so).
There is no host pinhole in recon's camera tier for the test to call. The camera tier holds only what a caller uses (2026-10-06), so the test computes the host reference in double, from camera_model.hpp's conventions, rather than add a camera function with no caller.
The package config finds the root from its own directory. The build writes the include directory relative to the config's install directory, and the config resolves it against CMAKE_CURRENT_LIST_DIR after every return(). Two problems go away:
On CMake 3.29 and older, a dependency's package config resets PACKAGE_PREFIX_DIR; ubuntu-24.04's Assimp gave /usr, which failed CI on the first push. Planting set(PACKAGE_PREFIX_DIR "/usr") before the targets include still gives the right root.
The previous fix expanded the root at the top of the config, so a refused package left _vr_shader_include_dir in the caller's scope. A refused package now leaves no _vr_ variable behind.
A target property, not a variable. It reaches both a FetchContent consumer and a find_package consumer, as the core's VKC_CORE_VERSION does on core_base.
Test plan
Apple M5 Max (MoltenVK), Release, VR_WARNINGS_AS_ERRORS=ON, tests and examples on, DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib, VKC_REQUIRE_VULKAN_DEVICE=1.
ctest -j 4 with VKC_TEST_VALIDATION=1: 87/87 pass, none skipped; 87/87 again with VKC_TEST_SYNC_VALIDATION=1.
recon_core_pinhole_gpu (new) runs the five functions in a std430 kernel (tests/shaders/pinhole_cases.comp), each case with its own camera, against the host in double:
28 edges in exact arithmetic, each with its answer written out: u = 0, u = −0.25, the right and bottom edges, 63.5 and the last half pixel clamped, round half up and down, z = 0, −0 and behind, NaN in x, y, z and each intrinsic, ±∞, and a 1 × 1 image;
8 unbounded projections written out, for vr_pinhole_pixel: past the right edge, before the first pixel, far outside, behind the camera, z = 0, NaN z refused, a NaN x passed through, +∞;
2 rigid poses in exact arithmetic (identity; 90° about Z plus a translation, so R^T ≠ R) and a general rotation, for vr_world_to_camera;
3 unprojections in exact arithmetic;
2420 grid cases (928 accepted) around five cameras (640×576, 3840×2160, 1280×720, 320×240 and 1×1) at four depths. Every pixel sits a quarter pixel from any boundary, so decisions and nearest pixels must match exactly, pixels within 2e-3 px and points within 2e-6 relative.
recon_subproject_glsl and recon_package_glsl (new) compile that kernel through the fetched and the installed root with the core's vkc_compile_shaders, after checking that the root holds pinhole.glsl and none of recon's internal GLSL.
recon_package_quiet_not_found (new) finds the package QUIET against a core without the vulkan tier and checks that it is not found and leaves no _vr_ variable behind. recon_package_found checks the same when found.
The tsdf, volume, mesh, texture and sensor suites pass, with four cases added:
recon_tsdf_integrate: an 8 × 2 colour image, so the nearest pixel's clamp is checked against the width (every image was square before).
recon_volume_allocate: fx 40, fy 120 and principal point (2.5, 0.5). The host checks that swapping either pair changes the expected band. At fx 100, fy 120 a swapped pair moved no point out of its block.
recon_sensor_gpu_frame_prep: colour principal points shifted by −0.25 and +0.6 px. The first row and column must be kept and the last dropped, which pins the rounded bounds.
recon_texture_projective: a vertex past the left border carries the clamped coordinate, as one past the right does.
Mutation checks. Each mutation below was planted alone, the affected targets were rebuilt, and the tests ran under validation. The file was restored from git after each one, and the tree was clean at the end. Every row, the first push's included, was run against the final code.

core/shaders/pinhole.glsl holds recon's one GLSL pinhole:
vr_unproject_pinhole, vr_project_pinhole and vr_nearest_pixel. They take
values (vec4 k, uvec2 size), not structs, so recon's scalar-layout
cameras and a consumer's std430 ones both call them. The rules are
tsdf's: negated tests so a NaN fails, the domain [0, W) x [0, H), and the
last half pixel clamped to the edge pixel.

tsdf_common.glsl's project_pinhole and nearest_pixel become thin
wrappers, and hash_allocate_depth.comp unprojects through it, each in the
order of operations it had, so neither changes a bit. texture keeps its
extrapolating variant.

recon_core's VR_SHADER_INCLUDE_DIR property names the include root a
consumer compiles against: in the build tree, a copy of the exported GLSL
alone; installed, the include directory, which the package config sets
on the imported target.

Tests: recon_core_pinhole_gpu (a std430 kernel against the host's double:
written-out edges in exact arithmetic and a grid around five cameras up
to 3840x2160), and recon_subproject_glsl and recon_package_glsl, which
compile that kernel through the fetched and the installed root.

Plan PR RE12 of the calib views plan.
