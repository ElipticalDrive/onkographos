Sprites now use zero-based row-major atlas-cell indices. setSpriteAtlas(image, grid) installs shared cell dimensions, column count, and populated cell count; the vertex shader computes source coordinates from each index. The solid fill uses the same formula while retaining arbitrary destination dimensions.
Closes #33. Stacked on #42 (binary visibility masks); merge that first. Editor adoption: 8f4e/8f4e#1264.
The change removes the RGBA16UI rectangle texture, retained rectangle array, upload/binding/release/restore code, named/sparse identifier resolver, and packed-rectangle public types. Grid validation runs during installation, including partially populated final rows, device texture limits, and the 65,536-cell ID limit. Failed replacements preserve the installed atlas. There is no legacy resolver or arbitrary-packed-atlas fallback.
The fragment shader, premultiplied blending, palette buffer, insertion order, 20-byte instance records, per-sprite size writes, and one instanced draw are retained. Default destination dimensions come from the shared grid; #32's separate fixed-size submission optimization is not implemented.
Validation: build, typecheck, Biome, and 46 standalone renderer unit tests pass. The companion editor passes 63 sprite-generator, 103 web-ui, and 98 editor-core unit tests and their type checks, plus the production website build. All six renderer, four sprite-generator, and 79 web-ui browser checks pass without screenshot updates. The 18 new font checks cover every glyph and fill cell, odd widths, control glyphs, spaces, fallback glyph, clipped/scaled glyphs, mixed-size fills, palette/destination alpha, font replacement, resize, release/restore, and raw-hook corruption of grid uniforms and atlas bindings. Pixel expectations use a CPU reference; restored/hook rendering matches initial output exactly.
Performance: Apple M1 Pro, Chrome 156 ANGLE/Metal, 1024×768, actual default-editor 129-cell R8 atlas. Compared the #42 rectangle-lookup shader, grid arithmetic, an identical-shader control, and float32 precomputed UV rectangles (#26's alternative). The binary fragment shader and identical instance bytes stay constant. GPU queries run sequentially after warming, with 32 baseline/candidate/baseline triplets per variant/scene, alternating comparison order, and disjoint or >=10% baseline-drift rejection. Opaque and translucent palettes run in fresh browsers with reversed order. All 60 whole-frame RGBA8 comparisons over opaque and transparent destinations match exactly.

Negative means less GPU time. The unchanged-shader control ranged from -7.05% to +3.86%, so these results do not establish a reliable GPU win. Earlier short-batch runs were substantially noisier and were not used for this table. Grid addressing is chosen for its simpler contract and resource lifecycle; precomputed UVs retain arbitrary source layouts but still require metadata storage and texture management.
Actual old/new Engine modules were also compared separately using 60 alternating warmed CPU pairs with GPU completion outside the timed blocks. Default-size submission was about 6% faster (12k sprites: 0.267→0.250 ms; 48k: 1.064→0.999 ms). Explicit-size submissions were essentially unchanged (12k: 0.223→0.223 ms; 48k: 0.886→0.884 ms). Atlas installation fell from approximately 0.0495 to 0.0365 ms. These are one-platform renderer measurements, not whole-editor frame rates.
For the 129-cell editor atlas, the grid removes 1,032 bytes of GPU rectangle texels and the same-sized retained CPU typed array, plus the per-cell coordinate objects and resolver map. Precomputed RGBA32F UV rectangles would use 2,064 bytes of texels instead; grid addressing needs only shared uniforms.
