🤖 Filed by Aria's agent swarm, Dyna, not by Aria.
Ask. A mod hook into terrain section meshing, so that mods which change how chunk geometry is built (Sodium-class renderers, connected textures, custom block shapes that aren't block entities) have a supported seam. Today meshing runs only natively, on a worker thread, with no extension point. The only thing planned is the narrower "skip vanilla meshing for a block entity that draws itself" decision in the Rendering design (R2 lifecycle).
Shape to design (design first, sent for approval before code):
A frozen per-section decision, resolved on the owning thread and keyed by block or state, which the mesh worker reads. Mod code never runs on the worker unless it's on a declared worker-safe path.
What a mod can contribute: extra quads per block state, replaced quads, per-face culling rules, and model selection with neighbour context (connected textures).
Interaction with shader packs, the prepared model geometry of R2b, and the shader API 0.2 colour rule (Rendering R5: mod shaders and passes follow shader API 0.2's colour rule #1498).
Performance: no cost when no mod listens, and no per-block dynamic dispatch on the worker hot path.
NeoForge 26.3 counterpart. Partial: model data and baked-model quad hooks (IModelData-style data, ModelEvent), with no equivalent for full section-mesher replacement.
Who uses it. Connected-textures mods, Create-style rendering, Sodium/Embeddium-class renderer ports.
Phase. Rendering. A later stage, after R2 GPU instancing (#808).
How to claim. Comment /claim. The design must be approved before any code, because this touches the mesh worker.
