This page provides a detailed explanation of the Digital Differential Analyzer (DDA) algorithm used for raycasting in the ts-raycasting library. The raycasting algorithm is the core component that enables the creation of pseudo-3D perspectives from 2D grid-based worlds. For information about the higher-level API functions that use this algorithm, see Core API and specifically the castRay Function and castRays Function pages.
What is Raycasting?
Raycasting is a rendering technique that simulates a 3D perspective by casting rays from a viewer's position into a 2D map and calculating the distance to walls or obstacles. Unlike full 3D rendering, raycasting is computationally efficient while still creating a convincing 3D-like perspective, making it suitable for real-time applications on limited hardware.
The ts-raycasting library implements raycasting using a Digital Differential Analyzer (DDA) algorithm, which is an efficient grid traversal method particularly well-suited for raycasting in grid-based environments.
```
Basic Raycasting ConceptViewer Position (x,y)Cast Multiple RaysCalculate Wall DistancesRender 3D-like View
```

DDA Algorithm Overview
The Digital Differential Analyzer (DDA) algorithm is a line-drawing algorithm adapted for raycasting. In the context of raycasting, it efficiently determines where rays intersect with the grid-based world map.
The key advantages of DDA for raycasting include:
It always steps exactly one grid cell at a time
It requires minimal computation per step
It can determine exact intersection points with grid lines
It can differentiate between horizontal (WE) and vertical (NS) wall hits
```
DDA Raycasting AlgorithmNo Wall HitWall HitCalculate Ray DirectionDetermine Grid Step SizesFind First Grid IntersectionsStep Through GridCalculate Hit Properties
```

Algorithm Implementation
The raycasting algorithm in ts-raycasting is primarily implemented in the castRay function. This function takes a 2D world grid, a position (x, y), an intersection test function, and a ray rotation angle as inputs, and returns detailed information about the ray's intersection with the world.
Initialization Phase
The algorithm begins by initializing several variables and calculating the parameters needed for grid traversal:
```
Input: world, x, y, intersection, rayRotCalculate sin/cos of rayRotDetermine quadrant of rayInitialize current cell position (row, column)Calculate horizontal and vertical slopesCalculate step sizes based on quadrantCalculate initial intersections with grid linesCalculate initial distances to intersectionsInitialize side and distance variablesBegin stepping loop
```
During this phase, the algorithm:
Calculates the sine and cosine of the ray angle for direction calculations
Determines which quadrant the ray is pointing to (TOP, RIGHT, BOTTOM, LEFT)
Finds the current cell position by flooring the x and y coordinates
Calculates horizontal and vertical slopes using tangent and cotangent
Determines step directions and sizes based on the quadrant
Calculates initial intersections with horizontal and vertical grid lines
Calculates initial distances to these intersections
Determines which side (NS or WE) will be hit first

Ray Stepping Phase
The heart of the algorithm is the stepping loop, which moves the ray through the grid one cell at a time until a wall or obstacle is encountered:
```
Test passes (no hit)Test fails (hit)Yes (horizontal)No (vertical)Start stepping loopCall intersection test functionsideDistX < sideDistY?Exit loop, return ray infoStep horizontallyStep verticallyUpdate sideDistX, column, side=NSUpdate sideDistY, row, side=WE
```
During stepping:
The algorithm tests if the current cell represents a hit using the provided intersection test function
If no hit is detected, it determines whether to move horizontally or vertically based on which intersection is closer
It updates the appropriate distance variable and cell position
It sets the side variable to indicate whether a NS or WE wall was hit
The loop continues until the intersection test fails (a wall is hit)
This approach ensures that the ray always moves to the next cell that it would intersect with, minimizing the number of steps required to find a wall.

Multiple Ray Casting
While castRay handles a single ray, the castRays function casts multiple rays in a fan pattern to create a field of view:
```
YesNocastRays(world, x, y, rot, intersection, config)Create ray casting function with angle normalizationApply fisheye correction if configuredCalculate center angle and angle incrementInitialize rays arrayLoop through rayCountCalculate ray angleCast ray and store resultMore rays?Return array of rays
```
The castRays function:
Creates a wrapper around castRay that normalizes the rotation angle
Optionally applies fisheye correction to the rays
Calculates the center angle based on the viewer's rotation and the field of view
Calculates the angle increment between rays based on the ray count and field of view
Casts rays at regular angular intervals across the field of view
Returns an array of ray information
This function is typically used to create the data needed for rendering a full field of view.

Core Mathematical Principles
The DDA algorithm relies on several key mathematical principles:
Ray Direction Calculation: Uses sine and cosine to determine the ray's direction vector
Quadrant Determination: Identifies which quadrant the ray is pointing to using the getQuadrant function
Slope Calculation: Uses tangent (sin/cos) and cotangent (cos/sin) to calculate slopes
Distance Calculation: Uses the Pythagorean theorem to calculate distances to grid intersections
Step Direction: Determines the sign of the step based on the quadrant
These principles allow the algorithm to efficiently traverse the grid along the ray's path.

Performance Considerations
The DDA algorithm is highly efficient for raycasting purposes for several reasons:
Minimal Computation: Each step requires only a few simple arithmetic operations
Predictable Grid Traversal: Always moves exactly one grid cell at a time
Early Termination: Stops as soon as a wall is encountered
Exact Intersection: Calculates the exact intersection point, useful for texture mapping
Quadrant Optimization: Uses quadrant information to optimize step calculations
The library also provides optional fisheye correction to create a more visually accurate perspective, which can be enabled or disabled via configuration.

The raycasting algorithm interacts with other components of the library:

The castRay function relies on the getQuadrant utility function to determine which quadrant the ray is in
The castRays function uses castRay to cast multiple rays
The castRays function uses normalizeAngle and potentially removeFisheye utility functions
Configuration options from IRayConf affect how castRays operates
Client code provides the intersection test function that determines when a ray has hit something
This modular approach allows for flexibility in how the raycasting algorithm is used in various applications.
