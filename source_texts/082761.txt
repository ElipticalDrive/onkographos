Problem and repository evidence
Add world-sphere/domain description contracts, filtered angular sources and deterministic depth-ordered cloud radiance/transmittance layers. Camera/direct/secondary radiance and PDFs share the same environment snapshot.
Scope and technical approach
Add world-sphere/domain description contracts, filtered angular sources and deterministic depth-ordered cloud radiance/transmittance layers. Camera/direct/secondary radiance and PDFs share the same environment snapshot.
Approved design: docs/Design/combined-adaptive-renderer-qualification.md (7 September 2026). The current white paper is v1.2, renderer evidence 0.2.41; latest observed renderer release is 0.2.44. gpu-lighting#85 / PR #94 remains a physical baseline prerequisite; historical schema-1 captures are rejected evidence.
Parent and dependencies
Parent: https://github.com/Plasius-LTD/plasius-ltd-site/issues/2169
Epic: https://github.com/Plasius-LTD/plasius-ltd-site/issues/2113
Feature control: renderer.environment.domains.enabled, default off. Environment baseline qualification precedes adaptive comparison; audit/noise fixes and provenance-bound fixed baseline precede both.
Explicitly out of scope
Three.js and all dependency graphs reaching it; fly-through volumetric clouds, unrestricted environment GI, hardware queries, stereo/eye tracking, general dynamic-world acceleration, temporal radiance accumulation, variance stopping and reprojection. No performance or publication completion without retained evidence.
Transport, visual and GPU risks
Preserve world material BSDF/PDF/MIS, complete-camera-sample identity/counting, energy, normals, offsets, HDR and termination. Validate classifier/environment cost, dispatch/divergence, allocation admission, queue overflow, timeout and device loss. Fewer rays do not prove lower allocated memory; the adaptive cap defaults to 128 MiB. Environment changes are qualified at fixed SPP first.
Acceptance criteria
No duplicated sunlight; PDF normalization/support and energy/reflection/transmission tests.
Document layered approximation; validate fixed-SPP sun/stars/cloud/distant-object reference scenes and cost.
Requirements-derived unit/integration tests run; assembled WGSL and physical WebGPU tests cover GPU changes; HDR/image tests cover visual changes.
Benchmark evidence records exact source/packages/device/flags, actual SPP, rays/segments, GPU and total job time, allocations and failures. Freeze image tolerances before adaptive runs; combined gain lower 95% bound >= max(5%, 2 x baseline CV).
README, Unreleased CHANGELOG, ADR/design, rollout and evidence documentation are current; public paper omits internal dependency-policy discussion.
Relevant lint/typechecks/tests, >=80% coverage including changed-source LCOV, package/zero-Three gates, post-push CI and applicable approved main/CD pass before completion.
Rollback and permanent prohibition
Disable the relevant default-off GPU-native child/parent flag; adaptive rollback preserves the independently qualified expanded scene. Reference correctness fixes are not optional optimization gates. Three.js is prohibited in source, dependencies, peers/optionals, tooling, artifacts and workspace and can never be a fallback. No local publishing.
