Summary
First step on the resolution goal (#16): a chunk whose voxels all hold one material (all Air above the surface, all Rock deep below) is stored as that single value with no voxel array.
Chunk::IsUniform(), UniformMaterial(), Compact(); Data() returns nullptr while uniform.
New chunks start uniform Air. The first SetRaw/Modify that breaks uniformity allocates the dense array; writing the same material is a no-op that allocates nothing.
Compact() runs after generation and after deserialization. Chunks made uniform by edits are not compacted until reload (noted in Docs/status.md).
Hashing and serialization produce the same bytes as the dense form (a uniform chunk is one RLE run), so snapshots, journals and state hashes are unchanged.
BuildMeshInput fills a uniform chunk and uniform neighbours from the single value.
Stacked on #16 (resolution-sweep); retarget to main after that merges.
Benchmark (default preset, chunk 32, MSVC Release, same Windows 11 machine)
Baseline beba6bf (resolution-sweep), candidate this branch. State hashes match on every workload.

Latency (bench_compare.py, two runs each):
boundary_crater apply: 24 µs → 67 µs (2.7×) in both runs. This is a real cost, not noise. The crater cuts into solid uniform chunks, so each one pays a 32 KB allocation and fill on its first edit. It happens once per chunk, and flush (1.5 ms) still dominates the crater.
generation: about 6 % slower in both runs (a branch per SetRaw plus the Compact scan).
resolution apply/flush/mesh rows flagged in one run flip direction in the other (e.g. 12.5 cm mesh 1.07 → 0.79, 3.125 cm apply 0.84 → 1.15). They are single-iteration samples and read as noise.
reconstruction, artillery, stress: within ±7 %.
