Zstd Copies Compressed Blocks Verbatim, Silently Producing Garbage
In decompress_blocks and decompress_blocks_bounded (zstd.rs:271-328, 330-375), Compressed_Block (type 2) and the reserved type 3 are copied straight to the output instead of being decoded or rejected. Block size is computed as (header >> 3) + 1 (zstd.rs:346), but RFC 8878 §3.1.1.2 defines it as header >> 3. RLE blocks advance the input by block_size bytes instead of 1 (zstd.rs:324). There's no literals section, no Huffman/FSE tables, no sequence execution, no repeat offsets, no dictionary IDs and no xxHash64 content-checksum check.
Real Content-Encoding: zstd responses will decode to corrupted bodies without any error. Implement RFC 8878 decoding: FSE, Huffman, sequences, the window, and checksum validation. Reject block type 3.
Files to edit:
zstd.rs, compression/utils.rs
