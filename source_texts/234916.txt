Owner
Closes #682.
Problem
VirtualClusterCull.comp Hi-Z-tested a pyramid built mid-frame from ScenePass's depth — which structurally can only contain classic-path occluders, because ScenePass draws no virtual geometry. So a VG cluster could never be culled by other virtual geometry, and raster/shading cost scaled with the selected cluster count rather than the visible one.
Approach
The cull now runs twice, mirroring InstanceOcclusionCull.comp's reprojected test:
Phase 1 — full DAG cut + frustum + cone, then a Hi-Z test against the retained previous-frame pyramid. That one is built at the tail of EndScene from the final depth, so it does contain virtual geometry — the whole fix. Bounds reproject through the prior VP (made relative to this frame's render origin, World: large-coordinate support — camera-relative rendering / floating-origin to kill far-from-origin jitter #429) and the instance's PrevTransform. A hit is appended to a compacted reject list (SSBO_VIRTUAL_REJECTED = 44, header + one record per cluster, same shape as the SW work list) rather than dropped.
Phase-1 survivors draw; BuildCurrentOcclusionHZB rebuilds the pyramid from the now-current depth.
Phase 2 — one dispatch over the reject list only (2D-flattened, bounded by the GPU-side count), re-testing with the current VP + transform. Frustum/cone/cut are not re-run (UE's bSkipCullFrustum in CULLING_PASS_OCCLUSION_POST). Survivors emit into a second command region and replay through a second MDI.
The software rasterizer still runs once, after both phases, over the union work list — one dispatch, one resolve, no added cost versus single-phase.
The safety property, stated plainly: phase 1 may be arbitrarily wrong in the reject direction — reprojection error, camera cut, viewport resize, disocclusion — with no visible consequence, because only a phase-2 reject is final.
Two design points worth a reviewer's eye
Phase 2 needs its own command region, not an append. The phase-1 MDI has already read its parameter word by the time phase 2 culls, and the count is absolute with no "start at draw N" parameter — so a shared segment would make the second replay re-issue every phase-1 draw (double raster, doubled overdraw counters). The command / visible / args buffers are sized for two regions, offset by constants the CPU already knows (frame cluster count, frame instance count), so the second MDI names its region with no GPU readback. Pinned by PhaseCommandRegionsAreDisjointAndInBounds.
Ordering is load-bearing. BuildCurrentOcclusionHZB regenerates s_Data.OcclusionHZB in place — it overwrites the very texture phase 1 reads. VirtualGeometryPass being registered before DeferredGPUOcclusionPass is what keeps previous-frame depth available to it; GetRetainedOcclusionHZB() carries that warning in its declaration.
Fallbacks
No retained pyramid (frame 0, HZB culling just enabled, force-disable-culling) → phase 1 degrades to frustum + cone and phase 2 does not run. If the phase-2 pyramid fails to build, phase 2 runs with occlusion off so every reject draws — a reject nobody re-tests is exactly the hole this must not have. Shadow cascades untouched (every new uniform defaults to single-phase). Visible counts stay GPU-side; no new readback on the render path.

One trap worth recording
The live occlusion-on/off diff came back at 1.24% of pixels — 300x the measured frame-to-frame noise floor, which reads exactly like an over-cull. It wasn't. The compute software rasterizer's bit-identical depth ties race benignly and its payload encodes the swList record index, so changing the culled set reshuffles record ordering and flips which triangle wins each tie: thin single-pixel outlines on every silhouette, no missing geometry. Re-running the A/B with swRasterMode=disabled collapsed the diff from 1123 pixels over threshold to 10 (noise floor 5) — a real over-cull would have survived that switch.
