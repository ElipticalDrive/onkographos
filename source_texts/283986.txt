What
Three changes from the voxel-compression evaluation (measured live: the AVMR brick merge earns 3.1–4.3x on real storm data and stays):
1. surface_phase joins the merge key (services/runtime-rs/src/weather/encoding.rs)
Bricks previously grouped on {phase, quantized dBZ} only, so a low-dBZ brick spanning up to ~29 NM could carry the first cell's surface precip type across a rain/snow boundary — user-visible in the default Surface Precip Type phase mode on web and native. Runs, rectangles, and vertical signatures now all key on {phase, surface_phase, quantized dBZ}. Cost is a lower merge ratio only in mixed-phase events.
2. Bricks ship the true max dBZ, not the quantized bucket
Grouping still quantizes to 5 dBZ, but each merge stage now tracks the maximum dbz_tenths over its cells and that maximum goes on the wire — a core is never rounded down. Wire format unchanged (same column, better value).
3. Web volume renderer: instanced boxes → raymarched 3D texture
Instance count was the biggest bottleneck: the old base+glow instanced meshes drew ~2 translucent GPU instances per brick (>1M instances for a Miami-scale event, before this PR's merge fidelity changes make bricks slightly finer). The volume now renders as one box mesh whose fragment shader raymarches a dense RG8 3D texture — draw cost is per-pixel, independent of voxel count.
New build_volume_texture in crates/approach-viz-core/src/mrms_render.rs rasterizes the declutter-selected bricks in Rust (strongest-return-wins on overlap; phase bled into adjacent empty texels so trilinear filtering doesn't tint snow edges toward rain; curvature baked into corrected-feet altitudes; ≤256 cells/axis via whole-footprint coarsening, ~500 ft bins ≤96 deep; fails loudly on bad footprints).
The WASM binding returns volumeTexture instead of flat render columns; the dual-index join still never reaches TypeScript.
NexradVolumeRaymarch.tsx renders back faces depth-read-only (camera can sit inside the storm), marches front-to-back with resolution-aware jittered sampling, integrates optical depth over unscaled NM (vertical exaggeration changes shape, not opacity; opacity slider maps to extinction), and colors samples from a nearest-filtered band×phase LUT built from the shared band tables — legend bands stay crisp.
Native iOS/macOS keeps the instanced path via build_render_volume (UniFFI); porting the raymarcher to Metal is a follow-up.
Verification
cargo test — 232 tests pass, including new coverage: surface-phase split, max-dBZ propagation through run/rect/vertical merges, texture rasterization/overlap/declutter/bleed/coarsening/fail-loud cases.
npm run lint, npm run typecheck, npm run format:check, npm run test (all 6 suites), npm run build:sw && npx next build — clean.
WASM rebuilt (npm run build:wasm, binaryen 117) and exercised end-to-end against a live Miami payload in headless Chromium: decode+prepare+rasterize 188 ms, 196×191×96 texture from 114k bricks; oblique, top-down, and camera-inside views all render correctly with cores reading through the green shells.
Notes
Server changes are wire-compatible (same AVMR v5 columns); deploy the runtime whenever convenient to pick up the merge fidelity fixes — clients need nothing.
Known limitation of the raymarcher (documented in docs/rendering-weather-volume.md): a ray is depth-tested where it exits the volume box, so opaque geometry standing inside the box (a ridge in satellite mode) hides the whole ray rather than only the weather behind it. Fixing this properly needs a scene depth texture.
