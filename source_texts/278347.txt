The renderer's point-cloud rasterizer (rasterizer/cuda/point_cloud_raster.cu) exists only for CUDA. Without it, renderSoftwarePointCloud returned "CUDA point-cloud rasterization is unavailable in this build", which broke several features on Macs:
Video export in point-cloud mode, or of a scene that is only a COLMAP sparse cloud. That is the state right after loading a dataset.
The independent split view / PLY comparison in point-cloud mode.
Python render_asset_preview for point-cloud assets.
The main viewport was unaffected; it uses PointCloudVulkanRenderer.
Changes
lfs::core::rasterize_points (tensor_spatial.hpp), backed by a new rasterize_points backend op:
Metal kernel raster.metal; Vulkan shader point_raster.slang; CUDA stubs the op, since it keeps the renderer's kernel.
The per-point math is ported from the CUDA kernel: transforms with per-point indices, node visibility, the deleted mask, crop box or ellipsoid (inverse, desaturate), and perspective, orthographic and equirectangular projection. Each point splats a disk whose radius comes from voxel size and depth.
Depth test: CUDA picks each pixel's winner with a 64-bit atomicMin over packed (depth, color). Metal has 64-bit atomic min only on newer GPUs, and MoltenVK's is limited. So this takes two 32-bit passes with the same winner: the nearest depth, then the smallest color among the points at exactly that depth. Clear and unpack passes surround them.
The matrices and crop parameters travel in a small uploaded Float32 block, which keeps the Vulkan push constants within 128 bytes. The caller allocates the scratch buffer, so neither backend manages its own.
renderSoftwarePointCloud keeps its tensor preparation, which was already backend-agnostic. It takes raw CUDA pointers only in the CUDA branch, and every non-CUDA backend calls rasterize_points. On CUDA builds, Vulkan tensors now take this path instead of reaching the CUDA kernel.
Verification (M5 Max, macOS)
TensorMetal.PointRasterSplatsTheNearestPoint: two points on the optical axis, on Metal and Vulkan. It checks the nearer point's color and depth, the one-pixel radius at depth 1, and the background.
TensorMetal.PointRasterMatchesVulkan: 20k points, with and without transforms, indices, hidden nodes and deleted points. It covers perspective, orthographic, equirectangular with a transparent background, a crop box, an inverse desaturated crop box, and an ellipsoid.
Metal and Vulkan agree to within 0.2% of pixels. MoltenVK's fast math can move a boundary point by a pixel, and it divides colors by 255 one ULP off.
lichtfeld_tests passes on Metal and Vulkan (213/213 each). That run needed Link the macOS test binary against FFmpeg once #2464's link fix, which this PR doesn't include. lfs_core builds for the macOS 15.7 target.
In the app on Metal:
lf.render_asset_preview of a point-cloud PLY renders it.
Video export of the garden dataset in point-cloud mode completes, and the frames show the sparse cloud.
The CUDA branch keeps its kernel unchanged, but I can't build CUDA here, so the Linux and Windows CI jobs check that side.
