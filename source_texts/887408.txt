Summary
Replace per-recursion sphere-expanded triangle bounds with exact vertex AABBs for BVH leaves and internal bound unions.
Precompute each triangle AABB and centroid once during mesh construction, avoiding repeated bounding-sphere calculations at every recursion level.
Keep the existing deterministic longest-axis median-split policy; this PR isolates the effect of tighter bounds and cached construction data rather than mixing in SAH/LBVH strategy changes.
Strengthen the seeded differential test so query_overlap must exactly match the independent brute-force triangle-AABB oracle for the current query semantics.
Add an explicit test that each leaf AABB equals the exact min/max of its triangle vertices.
Expand the reproducible benchmark from planar grids to grid, clustered, and long-thin triangle layouts, each with queries centered on populated geometry.
Why this experiment
The prior builder derives every leaf bound from a triangle bounding sphere, expanding a triangle's actual AABB. This is conservative but can substantially increase broadphase candidate counts—especially for long-thin triangles. The change targets that avoidable slack and removes repeated centroid/bounding-sphere work from recursive construction.
Evaluation
Run:
```
cargo test -p symtropy-mesh --test bvh_query_correctness
cargo bench -p symtropy-mesh --bench bvh_queries
SYMTROPY_BVH_BENCH_LARGE=1 cargo bench -p symtropy-mesh --bench bvh_queries
```
The benchmark emits single-sample build time, repeated query batch-mean p50/p95/p99, mean candidate count, and checksums. Build time requires repeated fresh-process runs. Query percentiles are batch means, not per-query tail latency.
Validation status
The code and tests are committed but have not been compiled or executed in this session. No speedup or test pass is claimed. Compare this exact head against the parent benchmark branch on the same CPU/toolchain, preserve raw output, and retain the per-family candidate/correctness evidence.
