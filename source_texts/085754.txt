With OME-NGFF rfc 5, non-linear transforms by means of displacement and coordinate fields will be introduced. Currently, vispy does not support this. In order for napari to be OME-NGFF compliant it would be necessary to introduce this in vispy.
Both should share a common transform implementation where possible.
Reading up and looking into the codebase, I was broadly thinking of something like this:
Allow BaseTransform implementations without an inverse. Currently the BaseTransform depends on map / imap etc, but there is no guaranteed inverse for a non-linear transform.
Add an in-memory 2D DisplacementFieldTransform with CPU + GLSL forward mapping.
Support forward-only rendering through ImageVisual(method="subdivide").
Add explicit inverse fields and method="impostor".
Add method="auto" and adaptive subdivision. For adaptive subdivision a cheap coarse way for calculating the error would be required.
Add optional numerical inverse estimation.
Add lazy/chunked field loading for very large datasets.
Extend to 3D fields, slices, and eventually volume rendering.
Things might change as I go through it.
