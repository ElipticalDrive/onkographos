ABSTRACT
In this work, we present L3GS, a framework for efficient
3D scene delivery with 3D Gaussian splats [5]. While 3D
Gaussian splats achieve a balance between visual fidelity and
rendering efficiency, their massive data size still limits realtime deployment. L3GS addresses this by leveraging scene
layering, predictive viewport and bandwidth estimation, and
priority-based scheduling to progressively deliver the most
essential splats first. This demo will showcase L3GS’s 3D
scene delivery performance under controlled network conditions and compare it with various baselines.

INTRODUCTION
The increasing demand for immersive digital experiences
in applications like Virtual Reality (VR) has highlighted the
limitations of traditional 3D representations like dense point
clouds, which often require substantial data and high network bandwidth. The emerging 3D Gaussian Splats (3DGS) [3]
representation is a generalization of point clouds, where each
splat has several associated features (e.g., position and color).
3DGS can strike a balance between high visual fidelity and
efficient rendering, but still faces delivery and scalability

To address these challenges, we designed L3GS, a system
for layered 3D Gaussian splats scene delivery [5]. L3GS first
trains a custom layered splats representation offline, then
incorporates redundancy analysis and scheduling strategies
during online operation to ensure that the most essential
splats are transmitted first under constrained bandwidth.
The purpose of this demo is to enable users to experience
the enhanced visual quality of 3D scenes delivered by L3GS
under different network conditions.

SYSTEM DESIGN
L3GS is designed to enable efficient delivery of 3DGS repre-
sented scenes in bandwidth-constrained environments. As
shown in Figure 1, L3GS comprises two main components:
a server that schedules the delivery of splats and a client
responsible for real-time interaction and rendering of the 3D
scene. The client and server communicate through a local
link modulated by toxiproxy [4] to simulate variable network conditions. Users control the network and view the 3D
scene through a web GUI shown in Figure 3, described later.
Server design. As shown in Figure 1, the server hosts our
custom pre-trained layered 3D Gaussian splats. These splats
are organized into a base layer and multiple enhancement

layers, which enable progressive scene delivery. By incrementally loading higher layers, the layering mechanism enables progressive improvements for visual quality within the
user’s viewport, ensuring efficient use of bandwidth while
enhancing the rendering experience.
During online operation, the server runs a Scheduler to
schedule the splat delivery sequence. To maximize the visual quality in the user’s viewport, the Scheduler decides the
downloading priority of different splats based on a viewport
dependent utility score. To aid the Scheduler, the server also
runs a Viewport Predictor module and a Bandwidth Predictor module to predict the future viewport and bandwidth,
which are used to periodically compute the utility score for
all splats. Both predictors are located on the server side to
accommodate the potential computational limitations of the
client devices. Further details are in the full paper [5].
Algorithms. The user can choose between different Scheduler algorithms to see the resulting visual quality differences.
The two main algorithms implemented in the demo are:
• L3GS: We implement several scheduling algorithms [5].
With these, the user will experience a high visual quality of splats in the user viewport, since L3GS employs
bandwidth-thrifty layered splats and prioritizes those
splats in the predicted user viewport. The scenes are
based on those from the original 3DGS paper [3] and
custom trained to separate the splats into layers.
• Sorting baseline: A sorting baseline is provided based
on a per-splat global significance score [2]. This score
is viewport-independent, so it does not adjust to where
the user is currently looking. Splats are progressively
retrieved from the server with higher scores first. The
scenes are pre-trained from the original 3DGS paper [3].
Client design. The 3DGS renderer on the client is a web
front-end based on [1]. We implemented several functions
(e.g., trace recording and replay) to enable repeatable evaluation. We also enabled the progressive rendering option
so that the viewer can incrementally render parts of the 3D
scene as splats are delivered.
