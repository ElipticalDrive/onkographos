Design
tools/stack2mesh.py SHEET.png -o OUT.bmm --size W H -n N [--at X Y] [--dir h|v] [--step S] [--kernel-limits] [--max-tris T].
Each opaque pixel of a slice is a voxel (alpha 0, or black when the PNG has no alpha, is transparent). Greedy meshing: same-colour rectangles in a slice, then equal rectangles on neighbouring slices join into one taller box. Boxes use bm-forge bm_core (8 verts, 12 tris each) and are written with export_bmm. Model faces -z, stands on y=0, slice spacing = --step. --dir h is the stack layout; --dir v is a vertical sheet layout (stackv is not in bm-core, so the direction is an argument).
Limits
Default 4096 vertices / 16384 triangles = 512 boxes; --kernel-limits = 8191 boxes. A bigger stack exits 1 and prints the voxel count, box count and the limit. Not done: outer faces only, UI button, Pi check (not verified on hardware).
Tests
python tests/tools/test_stack2mesh.py (10 tests): synthetic 4x4x3 stack with 25 voxels and 3 boxes, checker not merging (16 boxes), h and v layout, step, limit message, round trip mesh -> slices == source (also through the written .bmm), CLI plus bm_forge.py check on the output. unittest discover tests/tools: 108 OK. docs_audit score and consistency.py check clean.
