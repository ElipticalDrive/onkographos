Water and waterlogged blocks were rendering too opaquely or appearing dry, bubble columns lacked their bubbles, and several block models were incorrect. This change makes water transparent around the host geometry, renders animated bubbles, and fixes double chests and scaffolding.
Build shared water/lava surfaces for batched and GPU-pull rendering, cull internal fluid faces, preserve texture alpha, and draw waterlogged host blocks before the water surface. Reuse the existing fluid pass and reduce water shader texture sampling.
Animate bubble-column particles on the GPU in one instanced mesh per schematic, with a particle cap and visibility-aware idle rendering.
Correct chest halves and facing, implicit model UVs, root-mesh extraction and child transforms, and the chain/iron_chain resource fallback.
Give playground and block-models the same Vanilla + Redstone Tweaks setup. Wait for cached pack restoration, reconcile priority order, and reuse a matching atlas. Keep Three.js objects outside Alpine's reactive state to prevent file-loading render errors.
Add focused water and block-model demo pages, including waterlogged scaffolding and stair inspection, plus regression tests.

🚀 Performance & Scalability | 🟠 Major | 🏗️ Heavy lift
Read fluid states from palette indices, not two WASM calls per cell.
buildFluidMeshes calls this getBlock callback once for every cell in the sx*sy*sz volume. That includes air cells.
For each cell, the callback calls w.get_block(x, y, z). Air returns a bare name like "minecraft:air" with no [, so the callback then also calls get_block_with_properties. The result is two WASM boundary crossings per cell. The BlockStateWrapper objects returned by get_block_with_properties are never free()d. test/pages/scripts/block-models.ts does call state?.free() on the same API.
The batched build path now runs buildFluidSurface (Line 2287). Before this change, only the GPU-pull path ran a scan like this. With any water in the palette, a large schematic (for example 256³ ≈ 16.7M cells) now does about 33M synchronous WASM calls on the main thread. It also allocates millions of wrappers that are never freed. The palette early exit only skips schematics with no fluid at all.
Fix: build the state lookup once per palette entry. Then fill a palette-index grid from the lazy chunk iterator, the same way extractGpuGrid does. getBlock then becomes an array lookup.
