PR Summary
Adds a gyroid implicit surface generator that evaluates the scalar field sin(x)cos(y) + sin(y)cos(z) + sin(z)cos(x) on an N³ voxel grid and extracts the isosurface via marching cubes. The generator supports configurable cell size, period count, and voxel resolution, and integrates with the existing registry, pipeline, and export infrastructure.
Key Changes
New generator gyroid (src/mathviz/generators/implicit/gyroid.py) — registered implicit surface generator with cell_size, periods, and voxel_resolution parameters; uses shared marching_cubes.extract_mesh for isosurface extraction
Input validation — rejects non-positive cell size, zero periods, and voxel resolution below 4
Bounding box computation — spatial extent scales with periods × cell_size × 2π, centered at origin
Default representation — SURFACE_SHELL, appropriate for a minimal surface
Comprehensive test suite (tests/test_generators/test_implicit.py, 275 lines) — covers manifold output, period/cell-size scaling, low-res validity, full STL pipeline roundtrip, metadata/seed recording, registry discovery, determinism, input validation, and vertex-within-bounds checks

🔍 Design Review
Missing voxel_resolution in recorded parameters — src/mathviz/generators/implicit/gyroid.py, generate() method. The merged dict (which becomes MathObject.parameters) only contains cell_size and periods. The voxel_resolution used to actually generate the mesh is not recorded. This means a downstream consumer cannot reproduce the exact mesh from the stored MathObject metadata alone — two objects with identical .parameters and .seed could have completely different geometry if generated at different resolutions. Fix: Add voxel_resolution to merged (or to a separate resolution metadata field on MathObject) before constructing the return value.
Dead parameter: seed — src/mathviz/generators/implicit/gyroid.py, line 108. The seed parameter is accepted and stored on the MathObject, but it has zero effect on generation — the gyroid field is fully deterministic with no random component. This is misleading: callers may believe changing seed produces a different surface. If seed is required by the GeneratorBase interface, the docstring or class-level documentation should note that seed is unused for this generator. If it's optional, it should not be accepted. Fix: Add a note in the class docstring (e.g., "Seed has no effect; the gyroid is fully deterministic") so callers don't waste time varying it expecting different outputs.

🔍 General Review
Tautological manifold assertion in test (tests/test_generators/test_implicit.py, line ~52):
```
assert tri_mesh.is_volume or len(tri_mesh.faces) > 0
```
This assertion can never fail — len(obj.mesh.faces) > 0 was already asserted a few lines above, so len(tri_mesh.faces) > 0 is guaranteed true regardless of is_volume. The test name claims to check for a manifold mesh, but it doesn't actually verify that. If the intent is to assert manifoldness, this should be assert tri_mesh.is_volume (or assert tri_mesh.is_watertight). If manifoldness isn't guaranteed at low resolution, the test name and docstring are misleading.
