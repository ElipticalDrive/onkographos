What changed
Gaussian cache format. GaussianCache is a new cooked asset for animated gaussian splat previews. It holds:
a splat LOD tree whose merges are moment-matched;
nested driver meshes, built with meshopt_simplify;
temporal levels T0–T3;
driver motion, stored as prediction residuals on a 16-bit grid and compressed with the meshoptimizer vertex codec;
per-attribute splat streams with meshoptimizer filters.
The cache is split into progressive chunks. Chunk 0 is at most 256 KB for avatars and items, and at most 1 MiB for worlds, so a viewer can render while the rest downloads.
GPU splat renderer.
Compute passes pose the driver meshes, choose the LOD cut and pose the splats.
A GPU radix sort orders the splats by depth.
Splats draw as EWA quads with the standard 3DGS Jacobian clamp.
GaussianSplatComponent and GaussianCacheComponent render caches, and a streaming loader accepts chunks as they arrive.
Draw order is deterministic when the renderer can hold every node, which bakes always can.
Bake command. A new library, XREngine.GaussianBaking, plus the editor command --bake-splat-preview. It:
loads a cooked prefab or world from a pak;
samples surfaces;
bakes lit-projection color from 32 views (64 for worlds);
builds the tree, the drivers, the splat bindings and the cache;
writes the cache with stable asset IDs and reads it back to check it;
records loop videos (VP9 and H.264 OpenH264, 1080p and 480p) and WebP posters through an external ffmpeg;
writes report.json. Each failure kind has its own exit code.
meshoptimizer. The Meshoptimizer.NET package is replaced by native meshoptimizer v1.3, built from source at a locked commit by Tools/Dependencies/Build-Meshoptimizer.ps1 and called through P/Invoke. The ExecTool bootstrap runs the script. The dependency report generator now encodes spaces and parentheses in local license links, so its output reproduces the committed, encoded rows.
Opaque deferred pass. State buckets used to be ordered by object hash codes. They are now ordered by first insertion at each grouping level (shader, material, render options, mesh renderer). The grouping is the same as before, but the order is now the same in every process, and the sort does not allocate after warm-up.
Merge with master. The branch merges master 4cb65968b. Both new CI steps are kept: master's Streamline staging and this branch's meshoptimizer build. Master split the Windows Editor publish job into parallel jobs, so the meshoptimizer build now runs in their shared prepare-windows-editor action. docs/work is removed, as master moved work docs out of this repository. The validation below was done after the merge of dea102234; the later master changes touch only CI workflows and browser smoke scripts.
Breaking changes
GaussianSplatComponent is no longer a ModelComponent. Older cooked content that holds it as a model component fails to load, with CookedBinary.UnknownMember under the runtime read budget.
ShaderHelper.GaussianSplatVertex and ShaderHelper.GaussianSplatFragment are removed. The splat renderer has its own shaders.
GaussianCache.AcceptChunk now returns bool. When two components share one cache, a chunk that has already been accepted returns false; it no longer throws.
Gaussian cache format version 0 is rejected. Only CurrentFormatVersion = 1 loads.
In each chunk, triangle sections are decoded before the other sections, and splat bindings are checked against the decoded triangle count. Any other reader of the format, such as a future WGSL port, must decode in the same order.
A loose cooked cache root cannot load through Engine.Assets.Load in a non-published build, because that path uses the YAML reader. A runtime viewer must load the cache from a published archive or add a direct cooked read. The bake's read-back uses PublishedCookedAssetReader.
Why
The web app's world, avatar and item previews should come from the engine's own renderer instead of three.js, and they should animate. This PR is the engine side of the first two rollout steps: the cache format, the renderer, and an offline bake that turns a cooked prefab or world into a streamable cache plus loop videos. The browser viewer comes in later steps.

Risks and follow-ups
Build prerequisite. A normal build now needs the native meshoptimizer DLL. Run Tools/Dependencies/Build-Meshoptimizer.ps1, or the ExecTool bootstrap, which needs git, CMake and a C++ toolchain. Design-time builds do not fail without it. The same script should build linux-x64, but that has not been tried. Build the DLL once in CI so that every bake machine gives the same output.
ffmpeg. ffmpeg is an external tool and is not shipped. The code never selects libx264. The local bakes used a GPL ffmpeg build; a production worker should use an LGPL build if GPL obligations matter.
Black worlds after engine start. A cooked world that loads after the engine has started captures black. The bake avoids this by loading its input first, but a live viewer will load worlds at runtime, so the root cause must be found before that.
Skinned prefabs in cooked worlds. These do not animate: the engine rebinds their bones incorrectly. So world bakes come out still, with the warning clip-static.
glTF import. The native glTF importer may store one joint's inverse bind matrix transposed. It was seen on the skinned-morph-animated fixture.
Untrusted uploads. The bake is not yet hardened for them. It needs a read budget, a type allow-list, decompression limits, input caps, an overall timeout and sandboxing before it may process uploads.
Draw order from several threads. If a pass with bucket sorting gets render commands from several threads at once, the bucket order follows which thread takes the lock first.
Not checked by eye:
the bake shows no window or taskbar entry;
orbit and "frame selected" on splat components in the editor;
the loop videos themselves.

…
26f2ae9
```
When the renderer has a slot for every node (the default and every bake), the cut pass writes each node at the slot of its global node index and marks unchosen nodes as empty slots (opacity -1). The depth key pass then reads all slots and gives empty slots the culled key, so the stable sort orders equal-depth splats by node index and the same frame renders the same pixels in each run. With fewer slots than nodes the atomic slot path stays, and its tie order is not fixed.
```

Draw opaque state buckets in first insertion order

```
The opaque state-bucket sort ordered buckets by identity hash codes of the
shader list, material, render options, and mesh renderer. These codes come
from per-thread generators, so they change with load and thread timing. The
draw order of the opaque pass then changed between processes, and coplanar
surfaces gave different pixels, which made multi-mesh gaussian preview bakes
non-deterministic.

The snapshot collection now uses the bucket keys only to put the entries of
a bucket together, then puts the buckets in the order of their first
insertion. The order inside a bucket does not change.
```

Bound the gaussian cache reader by format limits
…
8c25094
```
The reader trusted header sizes, so a header under 1 KB could ask for
gigabytes, and it did not range-check the format version, motion codec
version, loop mode, grid bits, frame rate, color scale, or chunk table.
GaussianCacheHeader now has named format limits that are well above the
bake budgets, and Validate checks every field on read, on decode, and in
the builder. A bound splat can name only a decoded triangle, because the
triangle sections of a chunk decode first. Chunk asset paths must be
relative and stay in the folder of the root asset. Read errors in the
decode become a GaussianCacheFormatException with a diagnostic code, and
DecodeIndexBuffer rejects a count that is not a multiple of 3 before the
native decoder writes past the destination.
```

Serialize chunk acceptance when components share one cache
…
1a913b2
```
The asset manager gives the same cached root asset to every component
that loads it, so two components accepted the same chunks: the second
one failed with ChunkOutOfOrder, or both decoded into the runtime arrays
at the same time. The cache now owns a decode lock. The first decode,
each accept, and the next-chunk lookup run under it, and a chunk that is
accepted already counts as accepted without a second decode. The new
GaussianCacheChunkLoader runs the load loop for the component, and the
component copies decoded data under the same lock.
```
Keep the grouping of opaque state buckets in first insertion order
…
f49bbc7
```
Ordering whole buckets by first insertion let buckets that share a
material interleave in scene order, which defeats the skip of a repeated
material upload. The collection now orders the groups of the bucket key
one level at a time by first insertion: passes, shader lists, materials,
render options, and mesh renderers, with the near-to-far order inside
each bucket. The order stays deterministic and moves only whole runs, with
lists that the collection keeps.
```
