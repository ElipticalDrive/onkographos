Summary
Add voxelization — convert a solid CCShapeId into a regular volumetric occupancy grid (and optionally a signed-distance field), exposed as cc_voxelize(...). This is a net-new subsystem: OCCT's old Voxel package was dropped long ago and there is nothing volumetric in the kernel today (zero references to voxel / SDF / marching-cubes / distance-field in the repo).
This is filed for planning / prioritization, not as immediate work. Voxelization is an application-level / manufacturing capability rather than a core exact-B-rep feature, so it should be scheduled only against a concrete product driver (see below) — it does not sit on the drop-occt critical path.
What it would provide
```
typedef struct {
  double   origin[3];     /* grid origin in mm */
  double   spacing;       /* isotropic voxel size in mm (or per-axis if needed) */
  int      dims[3];       /* nx, ny, nz */
  uint8_t *occupancy;     /* dims[0]*dims[1]*dims[2], 1 = inside solid */
  float   *sdf;           /* optional signed distance (mm); NULL if not requested */
} CCVoxelGrid;

/* Voxelize body at the given voxel size. mode selects occupancy-only vs occupancy+SDF. */
int  cc_voxelize(CCShapeId body, double spacing, int mode, CCVoxelGrid *out);
void cc_voxel_grid_free(CCVoxelGrid *grid);
```
Core algorithm options (to be evaluated in the proposal):
Inside/outside test per cell — ray-stabbing or generalized winding number against the tessellated mesh, or point-in-solid classification; naturally data-parallel (a good fit for the Metal compute backend as fp32-tolerant throughput work).
Signed distance field — distance to the surface mesh per cell (narrow-band or full), enabling smooth booleans, offsets, and lattice/infill generation.
Optional inverse (marching cubes) to get a mesh back from the grid — only if a driver needs it.
Must respect the project rule: CPU is the source of truth (fp64), GPU is throughput (fp32) — so the exact classification stays defensible on CPU with the grid as a discretized derivative.
Why this matters (and when)
Voxelization is valuable only with a concrete driver. Candidate drivers, in likely order:
3D-print lattice / infill generation (SDF-based) — a real CAD-app manufacturing feature.
FE simulation meshing — voxel/immersed grids feed structured or octree FE meshes; relevant to the downstream CalculiX++ pipeline (cf. tet meshing Tetrahedral volume meshing (CadMesher::tet_mesh) — the mesh-tetting keystone blocking CalculiX++ FE meshing #1, adaptive refinement Field-driven adaptive tet refinement (sizing field + sliver removal) — unblocks CalculiX++ *REFINE MESH #2).
Collision / spatial queries, generative design, medical/CT import.
Without one of these committed, this stays a backlog item. It is called out explicitly so the roadmap records that it is not an OCCT feature we're inheriting and not on the native-rewrite critical path.
Acceptance / validation (when scheduled)
Voxelizing a unit box / sphere at spacing s yields an occupancy count whose implied volume converges to the analytic volume as s → 0.
SDF sign is correct (negative inside, positive outside) and |value| matches distance-to-surface within tolerance on analytic primitives.
Deterministic for a fixed body + spacing + grid origin.
Memory + timing characterized; large grids stream/tile rather than OOM.
If GPU-accelerated: fp32 GPU result matches the fp64 CPU reference within tolerance (parity, per the compute-backend contract).
References
No OCCT inheritance: OCCT's historical Voxel package was removed; this is new code (build on cc_tessellate mesh + point-in-solid classification, or native BVH).
Compute-backend rules: openspec/project.md (CPU source-of-truth fp64, GPU throughput fp32; Metal first).
Related meshing / downstream FE work: Tetrahedral volume meshing (CadMesher::tet_mesh) — the mesh-tetting keystone blocking CalculiX++ FE meshing #1 (tet meshing), Field-driven adaptive tet refinement (sizing field + sliver removal) — unblocks CalculiX++ *REFINE MESH #2 (adaptive refinement).
Techniques: ray-stabbing / generalized winding number for inside-outside; narrow-band SDF; marching cubes for grid→mesh.
Environment
CyberCadKernel main (C++20). New subsystem; additive cc_*. Prioritize against a named product driver before implementation.
