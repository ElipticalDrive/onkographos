Pages 19 and 20 gain an Isosurface, a Slice and a Volume toggle, so both renderers are tested on the two remaining scientific views over the animated field.
What changed
Isosurface (off / precomputed / live): pressure = −100 Pa, the vortex cores, with gradient normals. vtk.js: vtkImageMarchingCubes. Three.js: marching-cubes.ts, a line-for-line port. marching-cubes.test.ts requires identical points, triangles and normals on a test field (4 option combinations) and on shipped frames 0 and 12. Both pages draw 16,692 triangles on frame 0.
Slice (off / fixed / sweep): a plane across x in the volume's colours. vtk.js: vtkImageResliceMapper on the volume's image. Three.js: a shader sampling the volume's own 3D texture.
src/vtkjs-untyped.d.ts types the vtk.js modules that ship without types, retiring page 11's @ts-expect-error.

Precomputed isosurfaces and slices are about free on both. Live isosurfaces are ~3x faster with our port. vtk.js's slice sends the data a second time per swap.
A vtk.js texture leak, found and worked around
The first vtk.js slice leaked one GPU texture per data swap (8 → 280 live textures in one run, no resize involved). Creation stacks: ImageResliceMapper.buildBufferObjects → create2DFromRaw, the opacity texture. Without a piecewise function there is no cache key, so every rebuild makes a new one and drops the old. Setting an explicit constant opacity function keeps the count flat. Still present in vtk.js 37.4.0; upstream issue drafted, not posted.
Proof
212 unit tests pass, tsc clean.
Both pages render the same isosurface and slice (screenshots compared), no console errors.
