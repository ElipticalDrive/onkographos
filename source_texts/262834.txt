Part of the SDF volume plan: docs/frapx_sdf_volume.md (decisions 2 and 6).
Problem
frapx textures are 2D images only. A baked 3D volume (a mesh SDF from the Blender 3dsdf-texture extension, or any sampler3D data) cannot be passed to a shader without writing texImage3D by hand in onReady. This issue adds a generic 3D data texture input to core, so fx-canvas and fx-passes get it at once. Nothing SDF-specific goes into core.
What exists
Types: packages/core/src/types.ts:32-42 (TextureSource, TextureOptions, TextureInput, TextureMap); fx-canvas's own copy at packages/fx-canvas/src/types.ts:41-51 (owned by fx-canvas after fx-canvas: own the public types and deprecate the re-exported WebGL helpers #67).
Upload: packages/core/src/internal/textures.ts:14 loadTexture, :25-39 fixed texImage2D(TEXTURE_2D, …, RGBA, UNSIGNED_BYTE), wrap S/T only; LoadedTexture at :5-12 has no target or depth.
Bind: packages/core/src/internal/textureSet.ts:127-141 binds TEXTURE_2D unconditionally; units from reserveUnit (:56-74).
Size uniform is a vec2: packages/fx-canvas/src/createShaderBackground.ts:575-593, packages/fx-passes/src/createPasses.ts:854-857.
Context restore re-runs loadTextureInputs (createShaderBackground.ts:174-179, createPasses.ts:210).
WebGL2 detection: isWebGL2Context (packages/core/src/internal/webgl.ts:27). fx-canvas asks for WebGL2 only for #version 300 es or float feedback (createShaderBackground.ts:107-142).
Precedent for raw uploads: fx-particles' LUT (packages/fx-particles/src/createParticles.ts:524-541, outside the texture set).
Proposed change
Add a data form to TextureOptions:
{ data: Uint8Array | Uint16Array | Float32Array, size: readonly [nx, ny, nz], format: "r8" | "r16f" | "r32f", filter?: "nearest" | "linear" (default "linear"), wrap?: "clamp" | "repeat" | "mirror" (default "clamp") }.
data is x-fastest ([z][y][x]), Uint16Array for r16f holds half-float bits. Validate length = nx·ny·nz and the array type against format (TextureLoadError otherwise).
Upload with texImage3D(TEXTURE_3D, 0, R8 | R16F | R32F, nx, ny, nz, 0, RED, UNSIGNED_BYTE | HALF_FLOAT | FLOAT, data), UNPACK_ALIGNMENT = 1, no flipY, wrap S/T/R, no mipmaps.
LoadedTexture gains target and depth; textureSet.bind binds the right target. u_<name>Size becomes a vec3 [nx, ny, nz] for 3D inputs (2D unchanged).
WebGL1 context: reject with TextureLoadError("3D textures need WebGL2"). A 3D input does not by itself switch fx-canvas to WebGL2; the shader using sampler3D is #version 300 es, which already does.
r32f + linear without OES_texture_float_linear: fall back to nearest and warn under debug.
Context loss: the input keeps its data, so the existing restore path re-uploads it.
Expose the type in fx-canvas (its own declaration, fx-canvas: own the public types and deprecate the re-exported WebGL helpers #67) and fx-passes. Works with textures, setTexture and setTextures.
Tests
core unit (GL mock gains texImage3D / TEXTURE_3D / TEXTURE_WRAP_R): upload parameters per format, length / type mismatch errors, WebGL1 rejection, bind target, vec3 size uniform, the r32f linear fallback.
GPU e2e (fx-canvas, #version 300 es): a 4×3×2 r16f volume, read back chosen voxels through texelFetch into the canvas and compare.
Context loss: lose and restore, the volume is sampled again.
Release notes
core (minor), fx-canvas (minor), fx-passes (minor): 3D data textures ({ data, size: [x, y, z], format }), WebGL2 only.
Depends on / Order
After fx-canvas 1.0 (fx-canvas / react-canvas 1.0: breaking changes, migration guide and release #70); it touches the types fx-canvas: own the public types and deprecate the re-exported WebGL helpers #67 moves into fx-canvas.
New package @frapx/glsl-sdf-volume: load and sample baked 3D SDFs #72 depends on this.
