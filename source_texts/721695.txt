Problem description
From the FreeCAD Day 2024 Complaint Session:
Lack of ambient inclusion shading makes it difficult to perceive orientation and details
The lack of ambient occlusion shading or the appearance / rendering in the 3D view makes it difficult to perceive orientation and details depending on complexity and person.
This includes material display, lightning options (shadows, multiple lights, HDRI, environment illumination), and display of the geometry. There is no way to display textures.
Example:
Currently there is one light in FreeCAD, with the default setting it is always head on in the direction of the camera. Shiny objects appear totally white, whereas if you rotate the light there will be areas which are totally black.
Demo: #11166 (comment)
Another point that came up which would be fixed with a better render in the 3D view:
Want a simple button for a quick lofi render
Renders are difficult but I just want to have a vague image to show someone. I tend to sit there turning lines off and changing the background and screenshoting because that's easier than making sort of a hard time

I firmly believe, and have been bringing this up every time this comes along, that FreeCAD's 3d shaded views need to include an optimized ambient occlusion shader. Fusion360 has probably the best implementation of this listed above. The shadow mode in Link is really just a hack and the screenshots from the original issue report showing pleasing renders are also from a highly tweaked parameters to give a fake ambient occlusion effect.
OnShape has ambient occlusion shading and uses OpenGL ES to do it and renders this with excellent performance within a web browser.

I am trying to move from onshape to freeCAD and noticed the essential omission of ambient lighting. Since we are not used to looking at objects in outer space (where indeed there is no ambient light) we expect even the shaded sides of an object to be lit by a certain amount. This can sort of be simulated by adding emissive light to objects (see pictures) but of course that is a hack and has other adverse effects.
Adding a minimum amount of uniform ambient light would also remove the need for X-point light sources as onshape's view seems to do just fine with one directional light. The Link branch looks really nice but I think simple lighting with no self-shadowing is preferable since the shadows again can lead to poor visibility, hence no other CAD software that I know has self-shadowing by default in modeling view.
I have just started reading the freeCAD github and only checked 5-10 issues so far, let me know if I missed this point in previous discussions.
Onshape (left) has a more usable contrast between directly lit and shaded areas.
Emmissive object properties help, sort of simulating ambient light. However, it affects the general look as normal materials clearly shouldn't glow.
Edit: adjusted wrong terminoligy: global illumination -> ambient lighting

My 2 cents here:
direct shadows are immediately doable (Link branch + several other tests done in the past), everything for it in coin already. An interesting preliminary step would be to compare these solutions and set up a plan for discussion
One still need to define how a "virtual ground plane" should be done
Global illumination is probably out of reach for now. Too complex scene redesign and heavy calculations which are not our speciality
Ambient occlusion might be doable with GLSL shaders. This would require more research. If it turns out yes, that might be not such a far goal, as GLSL is supported by Coin
