# BEVFusion 体素化算子 SYCL 移植 — 工作说明与使用指南

> 本文件说明：做了什么、文件夹里是什么、怎么编译运行。

## 1. 这是什么

把 NVIDIA BEVFusion 的 PointPillars 激光雷达体素化 CUDA 算子（hash-table + scatter + reduce_mean，half 精度，XYZ/ZYX 坐标序）移植到 Intel SYCL，在 Intel Arc Graphics [0xb080] GPU 上跑通并优化。

- **平台**：Intel Arc Graphics [0xb080] (B390, ~29GB)，oneAPI 2025.3.3，OpenCL 后端。
- **源算子**：CUDA-BEVFusion 的 `lidar-voxelization.cu`。
- **工作目录**：`/work/bevfusion_migration/`。

## 2. 做了什么

1. **移植**：CUDA → SYCL，忠实保留 half 精度 + XYZ/ZYX 坐标序 + hash-table 开放寻址算法。3 个 kernel：`build_hash_table`（插点入 hash 表）/ `voxelization`（lookup + scatter 点特征）/ `reduce_mean`（每体素求均值输出 half）。
2. **正确性验证**：合成小数据逐 bit 对 CPU 参考（`ALL TESTS PASSED`）+ 真实 24 万点 ±1 邻接边界分析（`REAL-DATA TEST PASSED`）。
3. **性能对比**：同平台对比 hash-table 版 vs Intel dense 版 → BEVFusion 细参数下 dense OOM，只有 hash-table 能跑。
4. **性能优化**：4 项优化（relaxed 原子 / 去 host sync / 去 memset / reduce_mean 寄存器累加），累计 wall **3.5-3.8×**（240k 真实点云 1.938→0.530ms）。
5. **性能极限**：瓶颈 voxelization 是 memory-latency-bound（hash 表随机访存，算法固有），不改算法已近实用极限。

## 4. 怎么编译

宿主机有 `icpx`（容器里没有，**必须宿主机编译**）：

```bash
cd /work/bevfusion_migration
bash build.sh
```

编出 6 个二进制，自动放到对应 `test/` 子文件夹。默认 4 个目标是 seq_cst baseline，2 个 `_relaxed` 目标加 `-DVOX_RELAXED_ATOMICS`（opt4）。

## 5. 怎么运行

> **必须**带 `ONEAPI_DEVICE_SELECTOR=opencl:gpu` —— Level Zero 后端在这台机器有 bug 会段错误。
> 建议每个 SSH session 先 export 一次，后面就不用每次写了：
> ```bash
> export ONEAPI_DEVICE_SELECTOR=opencl:gpu
> ```

下面命令都假设你在 `/work/bevfusion_migration` 根目录（注意路径前缀）。
