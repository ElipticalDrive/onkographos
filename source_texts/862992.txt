Stacked on #25 (#23 -> #24 -> #25 -> this); retarget as those merge. One commit. Items 2-4 of the ranking in docs/reports-for-human/2026-10-15-vk-shader-profile.md.
The speed-ups are device dependent, so each was measured on the phones (3 rounds interleaved, 20 s between runs; the profiler was not run on rocky). Base = the commit before this one.

Dense conv picks its path from SUBGROUP_SIZE (spec constant 0, the algorithm is now subgroup_size_dependent): >= 32 gets clamped no-branch loads and a subgroup-uniform weight base (guarded by subgroupAllEqual, per-lane fallback); < 32 keeps the previous kernel verbatim. The profile's prototype (OC_TILE 8) was -52 % on the 780M but +9 % on the Samsung; OC_TILE 4 with the same code is -45 % on the Samsung but +12 % on the Pixel (Mali has no scalar unit), hence the split.
linear_bt: two output features per row-group and a remapped workgroup grid. 32 features per workgroup now (was 16); kiss_vk::kLinearBtFeaturesPerGroup / kLinearBtBatchTile live in platform/engine/vulkan/shaders/linear_bt_contract.hpp and both apps' dispatchers use it. Known regression: FC3 (10 outputs) is slower because only 5 of 16 row-groups have work. A one-feature-per-row-group variant for out_features <= 16 would fix it; not done (0.15-0.3 ms against 1.5-9 ms gains).
Radix sort: kRadixNumWorkgroups 256 -> 64.
The same measurements show PR #25's sparse conv change: Samsung -42 %, Pixel unchanged (now noted in the report, section 8).
Tests
New: DenseConvK3S1P1 (6x6 maps force the per-lane fallback, 8x8 the uniform path; fails with an unguarded broadcast) and LinearBt.RaggedFeatureBatchAndChunkEdges (odd feature count, ragged batch tile and input chunk; fails if the dispatcher constant disagrees with the shader). Both mutation-checked.
local: dense 15/15, sparse 16/16, tree 17, e2e 5
rocky (native build): kiss 29, tree 17, cifar-dense 15, cifar-sparse 16, e2e 5 and 3
Pixel 7a and Samsung: kiss 28, tree 17, cifar-dense 15, cifar-sparse 16; exit 0
Not run: sync-val, Jetson (CUDA untouched), a Mali device with subgroup 32.

new_cifar_sparse_conv2d_k3s1p1 takes a fast path in a subgroup whose active lanes share one
output channel (subgroupAllEqual): the CSR row bounds come from subgroupBroadcastFirst, so the
decode and the col_idx/weight loads are scalar; taps load on a clamped index with no divergent
branch; four accumulators. Any other subgroup runs the previous per-lane walk, so correctness
does not depend on the subgroup size or on out_h*out_w -- no dispatcher guard needed.

- new_cifar_dense_conv2d_k3s1p1: with subgroup >= 32 (Radeon 780M, Xclipse) every tap loads on
  a clamped index with no divergent branch and the weight base is subgroup-uniform when all
