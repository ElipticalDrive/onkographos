Kind: quality · Effort: medium
Problem
Exact parts - barrel, muzzle device, rails, sights, magazine body, bolts, knobs - come out of the mesher soft (oval bores, rounded rail slots, wavy edges), and the boolean kit (blender/hskit.py) that built them in code breaks topology and cannot blend a moulding. A signed distance function describes such a part exactly and in text: smooth_union(box, cylinder, r=2mm), subtract(bore), repeat(slot, pitch=10mm); edges are as sharp as written, round is round.
What to build
mastersmith/sdfkit.py (numpy): primitives (box, rounded box, sphere, cylinder, capsule, cone, torus, wedge), operators (union, subtract, intersect, smooth_union, smooth_subtract, shell, elongate, mirror, repeat), transforms (translate, rotate, scale) and mesh(sdf, box_min, box_max, voxel_mm) via marching cubes (scikit-image) to a GLB.
ms sdf <job> <Part> part.py: runs the script (a restricted namespace exposing only the kit), meshes it inside the part's plan box, writes parts/<Part>/registered.blend in the asset frame (no registration needed) and seed_render.png; the plan entry gets method: sdf so the assembler tints/details it like a code part.
A sdf-kit reference in AGENTS.md / the build skill with the idioms (a rail: box + repeat(subtract slot); a barrel: cylinder - bore; a muzzle brake: cylinder with repeated side ports).
Done when
The bullpup barrel, muzzle brake and top rail authored in SDF assemble with a round bore and crisp slots, and the pure tests cover every primitive/operator by sampling.
