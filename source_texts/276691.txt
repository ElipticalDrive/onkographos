Generating conformal mesh for polycristalline material with Multi Material Marching Cubes¶
Citing vox2tet¶
Sinchuk and al ; X-ray CT based Multi-layer Unit Cell Modeling of Carbon Fiber-Reinforced Textile Composites: Segmentation, Meshing and Elastic Property Homogenization Composite Structures, 2022. [sinchuk2022]
Context¶
Image-based modelling have wide range of different important applications in fields such as material science, medicine and computer graphics. Also the problem is closely related with surface reconstruction problem, which is very attractive for today due to rapid developing of reverse engineering based on the modern 3D scanning/printing technologies. In material science the image-based modelling is a key to get realistic model and perform a simulation in case the corresponding experimental measurements are very difficult or impossible. Also, as others modelling approaches, it can be considered as additional verification of the experimental result.
Usually a material microstructure is presented as set of voxels (pixels in 2D case) where color of each voxel identifies a material phase. Such kind of voxel data can be generated from micro computed tomography (μ-CT) scanning or obtained based on microstructure geometry model (e.g. Voronoi diagrams used as model of polycrystalline material). In case of μ-CT data the material phases are not represented perfectly and required additional image processing step that can be quite challenged itself. 2D images can be obtained from optical microcopy measurement and it is useful in case the microstructure does not change significantly in 3rd dimension like unidirectional fiber composites.
The easiest way to get a microstructure model is using so called “voxel-mesh” model. In this approach a voxel is considered as a brick element. The main disadvantage of the approach is possible solution inaccuracy at material interface region that cannot be acceptable for some kind of simulation. Beside this, the voxel-mesh approach can lead to extremely heavy models (in terms of degree of freedom) that could be difficult to manage even using modern computing resources. Examples of application and some details of voxel-mesh modeling can be found in [1].
The main challenge of this study is obtaining an image-based model with smooth material interface for polycrystalline material with complex microstructure geometry. The model will be used for finite elements (FE) simulation so the corresponding mesh elements must satisfy the quality criteria and the model must not be too heavy for simulations.
This problem is closely related with such problems of computational geometry as surface reconstruction from 3D scan [2] and mesh optimization [3]. Most available methods for this problem are oriented on manifold surface (bi-material case). The existed solutions for multilaterals data are not always able to produce good quality mesh. Some approaches proposed to medical images [4] could be difficult to generalize to geometry where more than 3 interfaces have a common boundary line.
In the current study an existed surface reconstruction approach [5] from Marching Cubes family methods [6] has been developed and successfully applied for the given microstructure image. For the following mesh optimization the remeshing algorithm [7] has been extended to the non-manifold surface and implemented in parallel.

This example correspond to fiber-glass composite micro-scan tomography dataset, with polymer resin. 2 separate phases are considered here. Vox2tet¶
March, 2018
Vox2Tet module is part of S2M library developed in Endo (Endommagement et durabilité) team from pprime institute ISAE-ENSMA.
Coded by Yuriy Sinchuk as part of the image-based modeling polycrystal materials project supervised by Carole Nadot in collaboration with Loic Signor and Mikael Gueguen.
The initial development has been done as part of image-based modeling composite materials project supervised by Marco Gigliotti and Yannick Pannier.
Goal¶
The primary goal of the tool is generation finite element mesh from multi-label 3D images of polycrystal materials without limitation on the count of phases and complexity of microstructure geometry.
Main features¶
The code implements multiple materials marching cubes algorithm with following smoothing and remeshing of the resulting surface. It includes:
modification of multiply material marching cubes algorithm (Wu, Z., Sullivan, J. M. Int. J. Numer. Meth. Engng., 2003)
Laplacian smoothing with minimum dihedral angle control for non-manifold surface
non-manifold surface remeshing based on edge split/collapse/flip operation with sizing field
In the end it call TetGen for the volumetric tetrahedral meshing.

In addition to required dependency needed by S2M, vox2tet module need :

USAGE¶
After installing S2M from the setup.py, all modules will be installed in python site-packages (in global or user directory), and vox2tet.py will be installed in the binary directroy of the installation (for instance /Users/Login/Library/Python/X.Y/bin/ on MacOS user install for pythonX.Y). Add it to PATH environment variable, then just call in command line:
```
> vox2tet.py -i input_image_or_json_file -o output_path -n 4
```
Where input_image_or_json_file is path to the image or JSON file with Vox2Tet settings. The default settings are
used if the argument is an image.
Supported input image formats: TIFF, NPY, and RAW. Take care about shape, size and data type in case of using RAW format input.
The process is parallelized for local mesh operations (remeshing) by dividing interfaces along boundary edges. So in case of absence boundary edges (single-interface structure) only 1 CPU is used.
Example call with 4 CPUs:
Example usage in command line:
```
> vox2tet.py -i ./tests/data/JMA_10.tif -o ./tests/out/JMA_10/JMA_10 -n 4
```
or just simple
```
> vox2tet.py -i ./tests/data/JMA_10.json -o out_vx2tet
```

Most important parameters are :

Lmax which control upper limit of edge length in voxels. This value is important for the volumetric pattern found in image (inclusion, pores, defects…) and need to be sufficiently small to capture the size of these patterns.

Output description¶
The main workflow includes 5 steps – image preparation, generation initial surface, preremesh step, remeshing and tetrahedral meshing.
Initially all settings are stored into IMG_NAME.json file of the output folder. Log output of the print function can be redirected
to file IMG_NAME_OUT.txt. Consider shortly the each step and its output data.
Image Preparation¶
On this step optionally can be removed small region and fixed diagonally connected voxels.
The output folder can contain following resulting data:
IMG_NAME_L_C3.tif - image of labels for connectivity 3. This image is used for the removing small regions.
IMG_NAME_L_C3.txt - array for mapping the labels to the initial image
IMG_NAME_C3_R64.tif - image with removed regions less or equal 64 voxels. This image is used for the creation initial surface.
IMG_NAME_C3_R64.txt - array for removed label indexes
IMG_NAME_L_C3_R64.tif - labels image for the image with removed region. This image is not used in the following workflow.
IMG_NAME_L_C3_R64.txt - array for mapping the labels to the initial image
Generation Initial Surface¶
On this stage the initial surface is created using modification of multiply material marching cubes algorithm
(Wu, Z., Sullivan, J. M. Int. J. Numer. Meth. Engng., 2003).
The output data:
IMG_NAME_ALL0.stl - the initial surface as binary STL. It is used for the following workflow.
IMG_NAME_ALL.stl - the same as IMG_NAME_ALL0.stl but with region attributes. Note, binary STL
allows only 16 bit per triangle attribute. The attributes will be duplicated for an image with many grains
(materials). So the information can be used only for visualization propose.
MID.inp - (not by default) set of surface meshes for each material stored in Abaqus INP format. MID here is a material id number.
The files can be overwritten by the surfaces from smoothing or remeshing step.
IMG_NAME_G_MID.stl - (not by default) the same as MID.inp but in STL format.
IMG_NAME_I_MID1_MID2.stl - (not by default) the surface is interface between MID1 and MID2 materials.
IMG_NAME_xyz.npy - numpy array with nodes coordinates of the initial surface.
IMG_NAME_tr.npy - numpy array with triangles nodes of the initial surface.
IMG_NAME_att.npy - numpy array with information about interfaces. It has following structure:
[interface_code, start_index_in_triangle_array, triangle_count, 1st_material_ID, 2nd_material_ID].
IMG_NAME_ntp.npy - numpy array with 6 boolean attributes for each node that characterizes node type.
The node attributes are following [surface, edge, corner, external, external edge, external corner].
IMG_NAME_EXT.xyz - coordinates of external boundary nodes.
IMG_NAME_MML.xyz - coordinates of multiply material lines (boundary edges) nodes.
IMG_NAME_FIX.xyz - coordinates of fixed nodes (common for more than 2 edges).
Pre-remesh Step¶
The step includes following operation: extraction boundary edges form the initial surface, smoothing the initial surface,
calculation of the surface normal in each node, creation half-edge data structure for the following remeshing, local
sizing field calculation based on the distance to the boundaries. On this stage following files can be generated:
IMG_NAME_E.ply - boundary edges extracted extracted from the initial surface.
IMG_NAME_S_E.ply - smoothed boundary edges.
IMG_NAME_S_ALL.stl - resulting smoothed surface (all materials).
IMG_NAME_sz_fld.npy - numpy array with sizing field values in each nodes (used for control of edges length locally).
IMG_NAME_xyz_s.npy - numpy array with nodes coordinates of the smoothed surface.
IMG_NAME_hedges.npy - half-edge data structure. It is based of remeshing algorithms as the data structure provides
efficient manipulation of the topological mesh information.
IMG_NAME_norm.npy - smoothed surface normals (in each nodes).
MID.inp - (not by default) set of smoothed surface meshes for each material stored in Abaqus INP format. MID here is a material id number.
The files can be overwritten by the surfaces from the remeshing step.
IMG_NAME_S_G_MID.stl - (not by default) the same as MID.inp but in STL format.
IMG_NAME_S_I_MID1_MID2.stl - (not by default) the smoothed surface is interface between MID1 and MID2 materials.
Remeshing¶
On this step the smoothed surface is remeshed with fixed boundary edge nodes. The remeshing process based on local mesh
manipulation (edge collapse/split/flip and tangential smoothing). For the process parallelizing the surfaces are
split along boundary edges. So the parallelization can not be applied for surface without boundary edges (single-interface surface).
Following resulting files can be generated on the remeshing stage:
IMG_NAME_RE_ALL.stl - resulting remeshed surface (all materials)
MID.inp - set of remeshed surface meshes for each material stored in Abaqus INP format. MID here is a material id number.
IMG_NAME_RE_G_MID.stl - the same as MID.inp but in STL format.
IMG_NAME_RE_I_MID1_MID2.stl - (not by default) the remeshed surface is interface between MID1 and MID2 materials.
Tetrahedral Meshing¶
For generation tetrahedral mesh from the obtained on the previous step surface mesh TetGen software is used.
On this step the remeshed surface is converted to TetGen input and resulting Abaqus INP file is generated from
TetGen output data. Optionally the resulting mesh can be verified by Abaqus functionality. Following files
are created on this step (see TetGen manual for more details):
IMG_NAME_RE.smesh - the remeshed surface converted to TetGen input format
IMG_NAME_RE.1.node - node coordinates of the resulting tetrahedral mesh generated by TetGen
IMG_NAME_RE.1.ele - tetrahedral elements node of the resulting mesh
IMG_NAME_RE.1.edge - edges of the tetrahedral mesh.
IMG_NAME_RE.1.face - faces of the tetrahedral mesh. It used for the creating elements sets according to the material ID.
IMG_NAME_RE.1.neigh - 4 neighbors of the elements.
IMG_NAME_RE.inp - the resulting tetrahedral mesh in Abaqus format (converted from TetGen output).
IMG_NAME.vtk - the resulting tetrahedral mesh in VTK (legacy) format.
IMG_NAME_RE_VERIFY.txt - result of the resulting mesh verification by Abaqus. If there no triangle
elements and error elements the mesh can be used for FEM simulation.
Limitations¶
The resulting material volume fraction can be inaccurate for an input image with small isolated single-interface regions and high-curvature interfaces, mainly because of the limitation of smoothing and sizing field calculation algorithms.
The resulting mesh remains dependent on the initial image resolution which can be an issue for some images.

Study : Meshing robustness in some material types¶
The study in this part focuses on how reacting some parameters on marching cubes algorithm.
This study is shared into two categories. For that, we report mesh size panel by giving
the number of nodes, faces, and cells.
The first one consists in creating and analysing the initial surface using modification of each parameter.
The second one includes the investigation about surface during remeshing process. The inquiry is to know
if this obtained surface is well smoothed by varying each parameter.

connectivity:
Connectivity determines which elements of the output array belong to the structure. It
ranges from 1 (no diagonal elements are neighbors) to 3 which means that voxels with
common edge or vertex are in the same grain, and consequently neighbors. In other words, it is
voxel parameter for region identification settings (labelizing). Few points are earned when
this labelizing is set to 3, improving then the surface quality during the smoothing process. By default, that explains
why this parameter takes 3 as value.

smooth_alphas:
This parameter is controling the Laplacian smoothing, and is involved in modifying automatically
the volume of a small isolated regions. It varies between two values 0 to 1. The mesh quality is well,
when this coefficient is near from 0 and 1, compared to average value 0.5 for a composite material. On other hand,
the behavior of polycrystalline microstructure is different. Indeed, rising this coefficient, implies
decreasing the number of nodes and cells, and consequently the mesh quality.

Lmax is defined as the upper limit of the resulting sizing field. In order to take into account
the curvatures outside the edges, this parameter Lmax must be changed as shown in this figure:
Left diagram with sizing field equals 2, and right diagram with sizing field equals 40
