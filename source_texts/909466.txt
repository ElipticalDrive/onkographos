Summary
Adds the gravity field of the central body (BODIES[0]) as spherical harmonics of arbitrary degree and order, following the HighFidelityEphemerisModel.jl formulation.
It is available in every N-body propagator:

The field is off unless sh_file is given. Without it, results are bit-identical to before this change: the output was compared with the previous commit by SHA-256 for all propagators.
Full documentation is in docs/spherical_harmonics.md.
Usage
```
prop = campanella.PropagatorNbody(
    GM=[4.902800582147760e+03, 398600.432896939, 132712197035.766],
    BODIES=["MOON", "EARTH", "SUN"], frame="J2000", LU=1.0, TU=1.0,
    sh_file="gggrx_1200a_sha.tab",  # PDS .tab or ICGEM .gfc
    sh_nmax=50, sh_mmax=-1,          # -1: min(nmax, order of the file)
    frame_bf="MOON_PA",              # body-fixed frame of the coefficients
    sh_rho_min=1.0,                  # smallest |r|/R allowed
)
```
PropagatorNbodySrp and PropagatorGve take the same keyword arguments, and so do the matching C++ constructors in include/campanella.hpp.
Implementation
Recursion (src/perturbations/spherical_harmonics.{h,cpp}): fully normalized Cunningham / Montenbruck–Gill V/W recursion.
It works in Cartesian coordinates, so nothing breaks at the poles.
One table to degree nmax+2 gives the potential, the acceleration and the 3×3 gradient.
Recursion factors are precomputed when the file loads, and each propagation allocates its workspace once, so an RHS evaluation allocates nothing.
Coefficient files: the format is detected from the content.
PDS SHADR .tab: GRAIL GRGM1200A, GL0660B.
ICGEM .gfc: EGM2008, EGM96.
The loader truncates to nmax/mmax, accepts Fortran D exponents and converts m to km. It rejects truncated files, non-finite values, non-normalized files and duplicate header keywords.
Loaded models are cached, keyed on path, nmax, mmax and the file's size, timestamps and inode.
Frames: T = pxform(frame, frame_bf, et), then r_bf = T r, a = Tᵀ a_bf, G = Tᵀ G_bf T.
Moon: MOON_PA, with moon_pa_de440_200625.bpc and moon_de440_250416.tf.
Earth: ITRF93, with earth_latest_high_prec.bpc.
GM and units:
The harmonic terms use the file's GM and radius, scaled to LU/TU. The point mass keeps using GM[0].
Setup raises if GM[0]·LU³/TU² and the file's GM differ by more than 1e-5 relative.
Degrees 0 and 1 are not evaluated.
Inside the reference sphere: positions with |r|/R below sh_rho_min are refused.
A rejected trial step makes the integrator retry with a smaller one.
If the trajectory itself goes below the limit, a ValueError (C++: std::domain_error) is raised instead of returning a truncated trajectory.
Other integration failures behave as before.
Python helpers for testing: load_spherical_harmonics, sh_accel_bf, sh_accel_inertial.
Other changes:
examples/solve_sh.cpp: a 100 km lunar orbit, with the STM checked against finite differences.
test-python/data/: degree-10 heads of the four coefficient files. .gitattributes keeps the CRLF line endings of the .tab files.
CI downloads the Moon and Earth PCK/FK kernels and runs solve_sh.
README, docs/basic_usage_python.md and docs/gve_mee.md §5.5 are updated.

Limitations
nmax ≤ 1200. EGM2008's full degree 2190 would need extra rescaling.
The cost grows as nmax². With the default build (no CMAKE_BUILD_TYPE), degree 50 adds about 75 µs to each GVE RHS + Jacobian evaluation.
No full-size coefficient file was tested. Degree 50 was tested with the first 200 kB of GRGM1200A (degree 56).
The Earth inertial-frame test uses a tolerance of 1e-9. New releases of earth_latest_high_prec.bpc move the ITRF93 rotation by about 1e-10.
ThreadSanitizer could not be linked here. Thread safety was checked by reading the code and by an AddressSanitizer run with 8 threads.
