NEX-M06-S04-WO-001 · Occlusion Mapper: frustum e occlusion culling por cenário
STATUS: PLANNING_ONLY / NOT_ADMITTED / NOT_EXECUTABLE. CLASS: NECESSARY; RISK: STANDARD. PARENT: M06 #11. Related: GEF #1, M00 #5, M01 #6, M02 #7, M03 #8, M04 #9, M05 #10, M11 #16, contracts #19, orchestrator #4, roadmap #18, Bug Hunter #20, final compendium #35. Version candidate: Godot 4.7.2 stable until pin in M00 (do not assume ABI).
OBJECTIVE
Occlusion Mapper: frustum e occlusion culling por cenário. Determine whether a narrowly-scoped change improves the performance of the NEX Engine's native desktop isometric scenes without compromising legibility or visual quality. No invented speedups or monster counts.
CONTEXT / REAL SOURCES
Reference user machine Windows, Ryzen, 24GB RAM, RTX 5050 with 8GB VRAM; no benchmarks performed. Read latest promoted AGENTS.md, .engineering/ source pack/DoD/checkpoint/security/ADRs, exact Context Lock, Godot pin and accepted M01 base traces before execution. Godot official resources:
https://docs.godotengine.org/en/4.7/tutorials/3d/mesh_lod.html
https://docs.godotengine.org/en/4.7/tutorials/3d/visibility_ranges.html
https://docs.godotengine.org/en/4.7/tutorials/3d/occlusion_culling.html
https://docs.godotengine.org/en/4.7/tutorials/performance/using_multimesh.html
https://docs.godotengine.org/en/4.7/classes/class_resourceloader.html
Note some official tutorials may say not updated for 4.7; runtime/version-specific capability must be verified before implementation.
SCOPE
Mapear Godot frustum/occlusion culling, occluders opacos e custo CPU de occlusion buffer, em corredor/dungeon/arena/cidade. Compare ON/OFF por câmera/seed; destacar que culling para desempenho difere de tornar personagem legível por paredes. Não eliminar renderização de perigo/inimigos visíveis e não trocar occlusion core; runtime flag/test via scene presets isolados.
OUT OF SCOPE / MODULE OWNERSHIP
No executable implementation, branches, PR, merge or GPU measurement now. M06 ONLY optimizes culling/LOD/instancing/streaming/frame budget within owned folder; M02 #7 controls camera & gameplay visibility, M03 #8 GI/light, M04 #9 material/texture presets, M05 #10 VFX, M11 #16 global import, M09 #14 editor. Physics/damage authority belongs gameplay, not particle graphics. Do not modify Godot core or shared APIs without separate admitted ELEVATED/single-writer WO, no paid service or unauthorized PC changes.
DEPENDENCIES / DAG
GEF + M00 #5, M01 #6 dungeon/city/stress scenes e contrato #19. M02 Sightline #29 trata visibilidade jogável e não pode ser editada por M06.
All coding requires GEF #1 REALLY completed, Source Pack/ADRs promoted, M00 baseline accepted, M01 scenes/performance measured, contracts #19 frozen, specific WO Owner admission and fresh exact BASE_SHA + canonical fingerprints / Context Lock, independent FILES_ALLOWED paths. Consumer-only contracts shouldn't introduce irrelevant dependency on entire upstream module implementation; use mocks for independence. Drift -> STALE, conflict/high severity -> BLOCKED.
OWNERSHIP / LOCAL CODEX DISPATCH
FILES_ALLOWED PROPOSED ONLY: nex_modules/performance/occlusion/**; tests/performance/occlusion/**, exact paths freeze after M00/Git tree verify.
READ_ONLY: nex_bench/** M01, contracts/**, Godot core, every other M06 S-WO, M02/M03/M04/M05/M11, .engineering/Source Pack/checkpoints and shared CI.
FORBIDDEN: direct main commits, other agent worktree, shared cache and binaries, secrets, project.godot, CI, public schemas/SDK without explicit single-writer contract.
LOCKS: CORE_RENDERER, PUBLIC_PERF_API, PROJECT_CONFIG, GLOBAL_IMPORT, CI, GPU-BENCH all require Integration Steward stewardship; only one RTX GPU heavy run at once.
Future worktree ../nex-engine-wt/NEX-M06-S04-WO-001, branch feat/nex-m06-s04-wo-001-<slug>, PR 1:1, only after ADMITTED. Initially 2 Codex Desktop LOCAL executors max independent write globs and no concurrent GPU timings.
ACCEPTANCE CRITERIA / DONE
Melhoria ON/OFF reproduzida somente em cenários com oclusores efetivos; desligar se custo CPU > benefício; ausência de object popping e false occlusion, especialmente durante câmera rápida.
M01 goals Quality 1080p/60 FPS (~16.67ms/frame) and experimental 120 FPS (~8.33ms/frame) are future benchmarks, never achieved now. Evidence: BASE/HEAD SHA, Godot renderer/version, Windows driver, scene/seed, resolution, warm/cold, Vsync, repeats, GPU/CPU time source, VRAM when available, frame times p50/p95/p99, 1% low defined, screenshot/temporal visual diff separate from FPS capture. Missing metric => INCONCLUSIVE; when no improvement or quality regressions unacceptable => NO_GO. HIGH/CRITICAL bug => BLOCKED.
TEST PLAN
static wall, door movable, thin occluders, object AABB partially visible, occluder CPU cost, open arena sem paredes, fast camera, transparency; energy/perf comparable.
Prove controlled A/B/A against same Godot/M01 baseline; native Windows GPU sequential, CI headless tests not substitutes. Bug Hunter #20 independent regression review with repro; CodeRabbit/Socket/CI where applicable; exact HEAD auditor and Steward serial merge, rechecks on HEAD drift, no self-merge.

NEX Occlusion Mapper: mapa de regiões com potencial de descarte para orientar level designers, baseado em controles Godot existentes antes de custom renderer.
