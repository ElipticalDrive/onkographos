What to do
Extract the burning surface as a triangle mesh from the 3D SDF using marching cubes.
Steps
Create srm_burnback/surface/extraction_3d.py
Use skimage.measure.marching_cubes(phi.cpu().numpy(), level=0.0, spacing=(h, h, h))
Returns: vertices (Nx3 array), faces (Mx3 index array), normals, values
Convert vertices from grid coordinates to physical coordinates
Key details
Marching cubes only works on CPU (numpy) — move $\phi$ to CPU before calling
The spacing parameter ensures the mesh has correct physical dimensions
The resulting mesh can be saved as STL, OBJ, or PLY for external viewing
For visualization, we also want the mesh normals and potentially scalar values (burn rate) on the surface
Done when
extract_surface_3d(phi, h) returns a triangle mesh
The mesh represents the current burning surface
The mesh is watertight (no holes) for a BATES grain
Dependencies
Add CUDA support #92 — CUDA support (3D phi tensors)

Why does marching cubes only work on CPU?
skimage.measure.marching_cubes is a scikit-image function that operates on NumPy arrays, not PyTorch tensors. There's no built-in GPU marching cubes in the standard Python scientific stack. GPU implementations do exist (NVIDIA CUDA samples, PyTorch3D mesh utilities), but the scikit-image version requires .cpu().numpy() to convert the tensor first.
In practice this is fine because surface extraction only happens every N steps for visualization — it's not in the hot simulation loop. One CPU transfer per snapshot is negligible compared to the hundreds of GPU timesteps between snapshots. If it ever becomes a bottleneck (unlikely), we could swap in a GPU marching cubes implementation later.
