Dear Niivue team,
I was tracking down a degraded ray-marching performance issue on RAVE 3D viewer when I realized that in Safari 27 (latest version) the fragment shader was per sub-pixel. That means, if MSAA is on, the volume rendering could be 4x slower. Chrome-based browsers, Firefox, and Safari (26.x) don't have such an issue (roughly x1.2 slower).
Currently this was only tested on WebGPU, not WebGL2. However, it's worth taking a look if you haven't...

@dipterix thanks for reporting and tracking down the problem. I have also investigated this (with the help of LLMs) and came to the same conclusion.
The bug is actually in safari, probably via WebKit. It’s not a NiiVue issue and can be replicated with other packages such as threejs or any bare webgpu context setup in a similar way.
The bug is tracked in this issue in the monorepo. Did you mean to post there? The monorepo contains the version of Niivue that has a webgpu backend.
The bug is also apparent on iOS devices.
We have recently updated the latest release candidate version of Niivue to make the webgl backend the default going forward. All webgpu features are still developed alongside the webgl features and should have feature parity. When the WebKit/safari issue is resolved then performance should be restored in that browser.

@dipterix can you provide a minimal demo? Our experience is that Safari WebGPU has issues with MSAA, but not WebGL2. Can you provide a simple way to replicate your issue (ideally without NiiVue, see our example below). You created an issue on the legacy version of NiiVue (0.6x) which only supports WebGL2. The new NiiVue 1.0rc mono repo allows you to force WebGL2, WebGPU or use WebGPU with a WebGL2 fallback. The 1.0 desktop app medgfx which uses the Safari-like WebKit explicitly notes that WebGPU is worse for MSAA than WebGL2, and uses this as rationale to only use WebGL2. I created a minimal demo lean web page with no dependencies to illustrate the issue is not specific to NiiVue.
Browser
WebGL2 off → 4x
WebGPU off → 4x
Chrome 155
6.6 → 5.3 (0.8x)
5.9 → 5.6 (0.9x)
Firefox
7.5 → 6.1 (0.8x)
6.8 → 6.7 (1.0x)
Safari 26.6.2
6.9 → 5.3 (0.8x)
5.8 → 23.2 (4.0x)
Findings:
WebGPU: 4x MSAA runs the fragment shader per sample, not per pixel (macOS/iOS)
With multisample: { count: 4 }, a render pipeline whose fragment shader uses no sample_index, no @interpolate(..., sample) and no sample_mask costs 4.0x the single-sample pipeline. Chrome and Firefox
WebGPU, and Safari WebGL2 with a 4x renderbuffer, cost 0.8–1.0x on the same machine. Repro page: one HTML file with no dependencies. Safari 26.6.2, macOS 26.6.2, Apple M4 Pro: WebGPU 5.8 ms → 23.2 ms; WebGL2 6.9 → 5.3 ms. Also seen on iPad Pro (M4). This makes volume ray-casting about 4x slower with MSAA on. Related: bug 326660.
