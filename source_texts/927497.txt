What to build
Replace the flat 2D projection (the FLAT = 0.60 y-squash) with real 3D positioning and perspective.
Camera struct (lives in sim.rs, stays testable on host target):
yaw: f32 — current rotation angle around the vertical axis
focal_length: f32 — controls perspective strength (scale = f / (f + z))
auto_spin_speed — one full revolution per ~90 seconds
Camera yaw increments each frame by auto_spin_speed * dt
3D body positioning:
place() returns (x, y, z) instead of (x, y)
Each body's orbital position is computed in its own inclined plane using inclination and ascending_node (already defined in data.rs)
A world rotation matrix (rotation around Y by camera.yaw) is applied to all positions
Perspective divide: proj_scale = focal_length / (focal_length + z), screen coords = (cx + x * proj_scale, cy + y * proj_scale)
Shell = kind semantics (already in data.rs):
Employment bodies: inclination ~0.38–0.50
Product bodies: inclination ~1.15–1.20
Origin: inclination ~0.79
Capture: inclination ~1.40
Different kinds occupy visually distinct orbital planes
Skill cloud rotates with the atom — skills go through the same world rotation matrix as bodies. Give each skill a fixed (x, y, z) position on the outer shell, transformed identically.
Acceptance criteria
place() returns (x, y, z) — all callers updated
Bodies orbit on inclined planes; different kinds are on visually distinct planes
The whole system auto-rotates around the vertical axis (~90s per revolution)
Perspective divide produces visible size variation between near and far bodies
Skill stars rotate with the atom, not fixed in screen space
FLAT constant is removed or unused — no y-squash hack
sim.rs has no web_sys imports; cargo test passes on host target
trunk build --release succeeds

None (can start immediately).

Review note (agent-review pass, 2026-09-09) — this is labelled agent-implemented but none of it is on v2.
Checked the tip of v2 (40dd89d, the #14 merge):
src/sim.rs:7 still defines pub const FLAT: f32 = 0.60, and place() (:74-79) and step() (:89-93) still use the y-squash. There is no Camera struct, no yaw, no focal_length, no perspective divide anywhere in the crate.
src/data.rs does carry inclination (:48) and ascending_node (:50), populated for all nine bodies. Nothing reads either field — grep -rn "inclination\|ascending_node" src/ returns only the declarations and the nine literal values.
PR #15 (fix/2-camera-model) was closed without merging.
So the shape of the data model from this ticket landed and the maths did not, which leaves data.rs asserting a shell-per-kind geometry that the renderer ignores. Worth either re-opening the work or reverting the two fields, so the next agent reading data.rs is not misled into thinking the 3-D positioning already exists.
Everything downstream of this (#3, #4, #5, #6) carries the same label and has the same problem.
