This PR adds a flag --pos_encodingwith the following positional encoding methods:
nope: NoPE (No Positional Encoding, see The Impact of Positional Encoding on Length Generalization in Transformers)
alibi: ALiBi (Attention with Linear Biases, see Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation)
learned: Learned positional embeddings, as previously integrated with this repository and used in GPT2.
(Also fixes a minor issue introduced with #277 and adds out to .gitignore.)
Remark: The implementation of ALiBi here differs slightly from the description in the paper. In the paper the original scaling factor is omitted and only the linear biases are applied for scaling. However, the PyTorch method scaled_dot_product_attention, which we use if available, currently does not allow to omit the original scaling factor. Hence, I kept the scaling factor in addition to the linear biases. In fact, this does seem to produce slightly better training results. (Also note that using scaled_dot_product_attention with a custom attention mask will currently slow down the computation, but will hopefully soon be optimized. See pytorch/pytorch#96099 for more details on this.)

Converted to draft because of a curious observation:
The results from the "adapted" AliBi method I implemented using PyTorch's current interface to Flash attention (a.k.a. scaled_dot_product_attention) are somewhat puzzling! (The adaption is that because we can't tell the PyTorch flash attention to omit the original scaling factor math.sqrt(Q.size(-1)), we just leave it in and combine it with the AliBi linear biases on top.)
I tested the different positional encoding implementations by running a few training runs on CPU (with the CPU parameters from the README) on the shakespeare dataset tokenized with tiktoken(gpt2). The results are as follows:
using the adapted flash alibi method: Run arrives at val loss 1.4785 after 3000 iterations.
using the original learned embeddings: Run arrives at val loss 4.7188 after 3000 iterations.
using standard alibi (without flash): Run arrives at val loss 4.7991 after 3000 iterations.
The results with adapted alibi seemed kind of too good to be true, hence I ran the sampling to see what magical text the model would produce. However, in fact, it only produces gibberish.
How can it be that the val loss is at ~1.5 but the sample output is trash? (I didn't change any of the validation code.)
