💡 What:
Replaced Vec::new() with Vec::with_capacity(nx as usize) inside the inner loop of MeshProcessor::voxelize. Also added a basic criterion benchmark suite to track performance.
🎯 Why:
The inner loop of the voxelization parallel iterator was dynamically allocating new Vec instances that would predictably grow up to (at most) nx times. By pre-allocating the vector using with_capacity, we eliminate the dynamic reallocation overhead in a highly parallel, performance-critical code path.
📊 Measured Improvement:
A criterion benchmark was added (benches/voxelize_bench.rs) targeting a basic cube primitive. Results from cargo bench show a reliable improvement:
Baseline: ~562.71 µs - 590.66 µs
After Optimization: ~515.61 µs - 527.11 µs
Change: ~5% to 6% performance improvement.

Avoid worst-case preallocation for each scanline
Preallocating local_particles to nx for every (iy, iz) task reserves the maximum possible row length up front, even when the row contains few or no interior voxels. With large nx this multiplies into very large transient allocations across Rayon workers (threads * nx * size_of::<ParticleData>()), which can trigger allocator failures or OOM before useful work is done; the previous Vec::new() only grew with actual occupancy.
