Why
The path tracer is the route to a Cycles-like still, but it skips things the rasterizer draws, so the same recipe can look worse when traced. The parity ledger row Rendering > Render Engines > Cycles says the path tracer "does not trace volume fog, translucent leaves, occlusion or emissive maps", and that it scores worse than the rasterizer against Cycles on fog (no volume fog) and equal on foliage (bench/reference/path-tracer.json).
Emissive maps are how screens, signs, windows at night and lit panels are authored; without them a night scene loses its light sources when traced.
Volume fog is already in the rasterizer and in recipes, so an agent that switches settings.renderer loses it without a warning.
Cycles traces all of these by default.
Subsurface and leaf translucency are in their own issue.
Scope
Emissive maps (and emissive strength) in the path tracer.
Homogeneous volume fog in the path tracer, using the same recipe fields as the rasterizer, with a bounded step count.
A warning in the render job result when a recipe uses something the path tracer still ignores, so an agent knows before it reads the picture.
Done when
fog scores better against Cycles with the path tracer than with the rasterizer, at the samples used in path-tracer.json.
A reference scene with an emissive-mapped screen or sign is added and scored.
A traced render of a recipe that uses an unsupported feature reports it in the job result.
The Cycles row of the parity ledger is updated.
