Motivation
pydynopt exposes complete 1D and 2D linear interpolation APIs, but no 3D equivalent. Downstream Numba models therefore maintain local trilinear evaluators and cannot consolidate interpolation behavior upstream.
Proposed scope
Add public 3D counterparts following the established 2D API structure:
interp3d_locate for lower-bound indices and lower-grid-point weights.
interp3d_eval for evaluation from previously located indices and weights.
interp3d for combined locate-and-evaluate calls.
Scalar-point and broadcast/array variants where they can preserve the existing output-buffer and dtype conventions.
Python validation/debugging paths and Numba overloads with matching behavior.
Extrapolation behavior consistent with the 1D and 2D implementations.
Exports and API documentation under pydynopt.interpolate.
Keep scalar-component input design separate and consistent with #5 rather than coupling the base 3D implementation to downstream-specific calling conventions.
Implementation considerations
Preserve the existing interpolation arithmetic tree; do not use relaxed floating-point semantics.
Specialize C-contiguous scalar evaluation with a single flattened base offset and eight row-adjacent corner loads.
Retain a correct arbitrary-strided implementation rather than assuming C layout.
Reuse the optimized 1D locate kernel independently along each axis, while benchmarking search order and inlining instead of assuming one universal order.
Keep cold search loops and large array loops out of line to avoid code-size regressions.
Tests
Compare against explicit trilinear reference calculations.
Cover C-contiguous and arbitrary-strided values, float32 and float64, boundaries, extrapolation, supplied output buffers, and non-finite values within the existing contract.
Exercise all public functions from outer @numba.njit kernels.
Verify scalar and array results against repeated 1D interpolation or another trusted reference.
Performance requirements
Add balanced scalar and array benchmarks rather than optimizing only one layout.
Include repeated-field evaluation at fixed located coordinates, matching downstream model usage.
Inspect generated LLVM/assembly and compare selective inlining policies; cross-module calls can inline, but always-inlining the public boundary may increase caller code size.
Non-goals
Precomputed inverse-grid-spacing or uniform-grid descriptor APIs.
Downstream model-specific dimensional dispatch.
