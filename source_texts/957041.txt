Summary
TAA flickers on every geometry edge. The cause is the history depth test in src/renderer/shaders/taa.frag.
The test rejects the history when the current depth and the history depth differ by more than 1–2%:
```
float rel = abs(curr_depth - history_sample.a) / max(curr_depth, 1.0);
float trust = 1.0 - smoothstep(DEPTH_TRUST_MIN, DEPTH_TRUST_MAX, rel);
```
At an edge, the jittered current fragment and the reprojected history sample land on different surfaces. The depth gap is large, so trust is 0 on exactly the pixels TAA must smooth. Those pixels show the raw jittered color and flip between foreground and background every jitter phase.
Evidence
Static camera, 60 fps capture:
TAA off: consecutive frames are identical.
TAA on: only geometry edges change. An edge pixel flips full contrast with an 8-frame period (7.5 Hz), the same period as the 8-sample jitter.
The debug trust image shows trust 0 on every geometry edge and trust 1 elsewhere.
The debug weight image shows weight 0 on the same edges.
Forcing trust to 1 removes the full-contrast flips. The maximum frame delta drops from 107 to 30.
Forcing the history weight to 1 makes the image static.
The color clip and the 0.9 history weight add a smaller residual ripple, but they do not cause the heavy flicker.
Fix
Replace the single-pixel relative depth test with a test against the 3×3 current depth neighborhood. At an edge, the neighborhood contains both surfaces, so the history stays valid. A real disocclusion still falls outside the neighborhood range and is rejected. Keep the YCoCg variance clip.
Acceptance
Static camera: no full-contrast edge flips. Edge flicker drops to the forced-trust level.
Walking and crate pushing: no new ghosting.
make check, make check-spirv, and make test pass.
make validate has no validation errors.
Notes
The diagnostic debug modes and environment overrides used to isolate the cause are temporary and must not ship.
