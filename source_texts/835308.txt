💡 What: Replaced the partition_point binary search with a rolling index (hit_idx) inside the scanline voxelization inner loop (for ix in 0..nx).
🎯 Why: In MeshProcessor::voxelize, after sorting the raycast intersections (hit_xs) for a given scanline, the code previously used hit_xs.partition_point(|&hx| hx <= x) to count the number of intersections to the right for parity checking. Because x strictly increases during the loop, this $O(N \log K)$ operation can be reduced to an amortized $O(1)$ operation by simply advancing a rolling index over hit_xs as x increases.
📊 Impact: This micro-optimization removes redundant binary searches inside the most performance-critical inner loop of the voxelizer, eliminating unnecessary CPU cycles and branch prediction overhead for complex meshes with multiple self-intersections. The benchmarks show a minor change on a small cube mesh, but this algorithmic shift from $O(\log K)$ to $O(1)$ reduces the theoretical complexity scaling factor.
🔬 Measurement: Verified by running cargo test to ensure solid voxelization parity behavior remains completely unmodified, and cargo bench to measure impact on standard mesh structures.
