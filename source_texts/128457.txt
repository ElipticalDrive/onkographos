Epic: #25 - 2D/3D target geometry and layout cross-sections
Phase: 1 of 2
Phase Goal: Particles can move through non-1D targets
Description
Targets built from closed triangle meshes (STL/OBJ), each solid tagged with a material, with ray–surface intersection accelerated by a BVH. The target implements the existing pub trait Geometry in lindhard/src/geometry.rs, which VoxelGrid from #26 already implements.
CSG primitives and their boolean combinations are split out to #194, so each issue is one buildable piece.
Acceptance Criteria
Mesh loading (STL ASCII/binary, OBJ) with a watertightness check: every edge is shared by exactly two triangles with consistent orientation. A mesh that fails is rejected with an error naming a bad edge.
A BVH for ray intersection; point-in-solid queries for the material at the current position.
Implements Geometry (lindhard/src/geometry.rs), like VoxelGrid.
Overlap, boundary and tolerance rules match [Epic #25] CSG primitives and boolean combinations on the Geometry trait #194 (first listed solid owns an overlap; directional ownership on a surface; no re-hit of the surface just crossed). A ray through a shared edge or vertex crosses the surface once. Each rule has a test.
Tests: a meshed box gives the exact chord lengths; a meshed sphere gives chord lengths within its tessellation error; a mesh box and the equivalent VoxelGrid give identical results; benchmark against the voxel equivalent.
Dependencies
[Epic #25] Voxel-grid geometry #26: the shared Geometry trait exists (closed).
Phase 1 of this epic. Independent of #194 (CSG); whichever lands second adds the test that a mesh box and a CSG box give identical results.
Implementation Guidance
Checked against pub trait Geometry (lindhard/src/geometry.rs:184). Required methods to implement: n_materials, material, n_regions, material_index, locate, entry_point, exit, and in_vacuum (no default). flight has a default that is correct only when every region is a whole material run along a flight; if two solids of the same material can abut, override it to report the end region.
Regions are solids (one region per mesh solid, each tagged with a material index); locate returns the owning solid or None in vacuum, exit returns ExitOutcome::Enter { region, pos } at an inter-solid surface and ExitOutcome::Escape { face, normal } when leaving the target. Face has only Front/Back/Side: map a hit with outward normal along -x to Front, +x to Back, otherwise Side (document the choice), and return the triangle's outward unit normal.
Because [Epic #25] CSG primitives and boolean combinations on the Geometry trait #194 (CSG) is open and independent, this issue defines the overlap/boundary/tolerance rules first and states them in the module docs; [Epic #25] CSG primitives and boolean combinations on the Geometry trait #194 must match them. Rules: the first listed solid owns an overlap; on a surface the solid the ray is heading into owns the point (directional ownership, as VoxelGrid does for faces); the surface just crossed is not re-hit (skip hits at t <= tolerance along the ray from an on-surface start); a ray through a shared edge or vertex crosses once (resolve by treating hits within tolerance as one crossing, or by a consistent watertight tie-break).
Point-in-solid: cast a ray and count crossings (parity), or use generalised winding number; pick one, make it deterministic, and handle rays that graze edges by the same tie-break.
Watertightness: weld vertices by exact coordinates (STL repeats vertices), then every undirected edge must occur in exactly two triangles with opposite directed orientation. Error variant (add to the geometry error enum, thiserror) names a bad edge by its two vertex positions or indices. Reject degenerate (zero-area) triangles. Check orientation gives outward normals (positive signed volume).
BVH: binned surface-area-heuristic or median-split build over triangle AABBs, flat node array, stack-based nearest-hit traversal with a Moeller-Trumbore (Tomas Moeller and Ben Trumbore, J. Graphics Tools 2 (1997) 21) or watertight (Woop, Benthin, Wald, J. Comput. Graph. Tech. 2 (2013) 65) ray-triangle test. Cite the source of every algorithm in a doc comment. Build must be deterministic (no thread-count dependence; construction single-threaded or order-stable).
Parsers: STL ASCII and binary (detect binary by the 84 + 50*n length check, not just the solid prefix), OBJ (v, f with v/vt/vn forms, polygon faces fan-triangulated, negative indices). Hand-written parsers, no new dependency unless justified. Units: lengths in metres at the API; state how file units are scaled.
Data/provenance: tests should use meshes generated in code (box, UV/icosphere); do not commit third-party meshes. If any data file is added, add a docs/data-provenance.md row.
Update docs/architecture.md geometry row (line 26) and the module docs of geometry.rs.
Affected Files
lindhard/src/geometry.rs (module docs; re-exports; Face mapping note) or a new submodule lindhard/src/geometry/mesh.rs (loaders, watertightness, BVH, Geometry impl); if converted to a directory module, keep the existing public paths unchanged
lindhard/tests/mesh.rs (new; modelled on lindhard/tests/voxel.rs)
lindhard/benches/mesh.rs (new) plus a [[bench]] name = "mesh" harness = false entry in lindhard/Cargo.toml
docs/architecture.md (geometry row)
Test Plan
Meshed box: exact chord lengths for axis-aligned and oblique rays; meshed icosphere: chord within the tessellation sagitta bound; mesh box vs VoxelGrid equivalent: identical locate/exit distances and materials; one test per rule (overlap, directional surface ownership, no re-hit, shared edge/vertex single crossing); non-watertight, inconsistently oriented and degenerate meshes rejected with the bad edge named; STL ASCII = STL binary = OBJ for the same solid; determinism of BVH build and queries. Criterion bench compares mesh vs voxel box.
