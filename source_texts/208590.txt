Summary
Upgrades the volume renderer from a 1D to a 2D transfer function, adding gradient magnitude as a second dimension for distinguishing tissue boundaries from interiors.
Problem with 1D TF
Soft tissue, muscle, blood and organs all share the same density range (t ≈ 0.25–0.27, ~2% of the full scale). A 1D transfer function cannot differentiate them because it only maps density → colour+alpha.
Solution: 2D Transfer Function
The second dimension is gradient magnitude — how fast density changes around a voxel:
Low gradient (≈ 0) = voxel is inside a homogeneous region (organ interior)
High gradient (≈ 1) = voxel is on a tissue boundary/surface
Changes
VolumeRendering-Basic.shader
Added _GradStep property (default 0.01) — step size for central-difference gradient estimation
Per raymarching step: compute gradient magnitude via central differences in all 3 axes (6 extra texture samples)
transferFunction(density, gradMag) now samples the transfer texture at float2(density, gradMag) instead of float2(density, 0)
Fixed _Intensity range from 0–1 to 0–10 (old max of 1.0 was too dim for most scenes)
VolumeRenderingWithTransferFunction.cs
Transfer texture resized from 100×1 to 100×64 (X = density, Y = gradient magnitude)
New Inspector slider Gradient Influence (0–1):
0 → all rows of the 2D texture are identical → backward-compatible 1D TF behaviour
1 → row alpha scales with Y (gradient magnitude) → surface-only rendering
How to test
Open the project in Unity (auto-recompile)
On the VolumeRenderingWithTransferFunction component, enable Update Texture In Every Frame
Ensure Intensity ≥ 1.0 and Iteration ≥ 50 on the material
Slide Gradient Influence from 0 → 1 and observe tissue boundary extraction
Tune Gradient Step on the material if edges look too sharp or too soft
Reviewer notes
gradientInfluence = 0 is the default, so existing scenes are unaffected on first open
The 6 extra texture samples per raymarching step add GPU cost; reduce _Iteration if performance drops
Next step candidates: pre-computed gradient texture in DicomImporter (faster), or a 2D TF editor widget

Add _GradScale to amplify gradient magnitude signal
…
b663acf
```
CT data has small per-voxel density differences (~0.01-0.05) so raw
gradient magnitude rarely exceeds 0.1-0.2, meaning the 2D TF Y axis
was never sampled past the bottom rows. _GradScale (default 5.0) stretches
the signal to use the full 0-1 range of the transfer texture.

Fix DicomCodecException: add JPEG fallback via Unity LoadImage
…
ad71573
```
fo-dicom 5.x does not ship a JPEG Baseline decoder for Unity. When
RenderImage() throws DicomCodecException, Path B extracts the raw
JPEG bytes from DicomPixelData and decodes them with Unity's built-in
Texture2D.LoadImage(), which supports JPEG natively.

DICOM JPEG Baseline stores a valid JPEG stream directly in the pixel
data fragment, so LoadImage() works without any additional processing.
