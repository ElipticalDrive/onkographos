Measured before starting (HEAD 4142e31, release, 1280x720, render distance 32, vsync off, still route, 3820 sections, vanilla test server; the world still held about 1000 leftover entities, so absolute numbers are not the clean spawn scene):
Work per frame: mean 2.8 ms, p50 2.2 ms. CPU parts p50: mesh 1.67 ms (entities), extract 0.17, backend 0.32 of which record 0.28 ms, submit/present 0.03.
GPU scene 1.0 ms p50, of which terrain 0.73 ms, translucent 0.12, clouds/weather 0.12.
So everything #23 can remove from the CPU is the terrain share of record, at most about 0.28 ms (13% of this frame) at 3820 sections; at render distance 20 it is less. #24's vertex packing and face grouping would act on the GPU's 0.73 ms, but the frame is CPU bound (work 2.2 ms against GPU 1.0 ms), so a GPU-only gain does not shorten frames at this size. It would matter at higher resolutions or on weaker GPUs, which I have not measured.
Why I have not started #23: the section vertex and index buffers are already arena blocks, but each draw also pushes a per-section fade constant (bind_section). An indirect draw needs that value per draw (instance data or a storage buffer), which means a shader and vertex-input change, with the render parity cases and validation layer as the check. The gain is bounded by about 0.28 ms. Recommendation: do #23 after the entity CPU work (mesh 1.67 ms is six times larger) and only if you want the draw-call count down for its own sake; #24 waits for #23 and a measurement at a GPU-bound size. No change to the issues' acceptance text.
Side effect, stated: to read the report I ran bench --save --name terrainprobe, which also wrote .data/runs/bench/baseline-still.json (machine-local, under .data/) with this probe run. Any earlier saved baseline for the still route is replaced; re-save one on a clean world before a --compare.

Slice 1 (measurement, no commit, temporary counters reverted): perf-still at 261580d averages about 846 section binds (one push-constant write plus a vertex and an index buffer bind each) and about 1830 indexed draws per terrain pass, so about 2.2 runs per section. Per pass, not per frame: a frame has one pass per terrain layer.
