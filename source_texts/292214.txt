Port of the HeCBench scan workload to a single portable alpaka source. It splits the input into independent chunks and computes an exclusive prefix sum inside every chunk with a shared-memory Blelloch/Harris scan, in both the plain and the bank-conflict-aware variant. One kernel source drives the host CPU backend and the CUDA backend, with no native CUDA/HIP/OpenCL kernel and no backend branch.
An independent review confirmed the code is safe. The earlier publish attempt was missing the raw performance data the README refers to; this revision commits that data as benchmark/scan/results.json and the underlying raw CSVs (see Reproduction).
What it computes
For an input of nelems = ceil(n / N) * N elements split into chunks of N, the reference (src/scan-cuda/main.cu, OpenMP twin src/scan-omp/main.cpp) produces a chunk-local exclusive prefix sum
```
out[i]   = sum(in[cN], ..., in[i-1])   for i inside chunk c, i > cN
out[cN]  = 0
```
Chunks do not carry into each other: the reference resets the running total at every chunk boundary. It exercises chunk sizes N = 128, 256, 512, 1024, 2048 and element types char, short, int, long, generated with srand(123) and rand() % 5 + 1.
The port keeps the reference semantics exactly: the same chunk-local exclusive scan and chunk-boundary reset, both kernel variants (plain scan<T,N> and bank-conflict-aware scan_bcao<T,N> with shared memory padded by x >> 5), the same element types and chunk sizes, a grid-stride loop over chunks matching the reference's 16 * multiProcessorCount grid, and an independent sequential host exclusive scan with an exact element-wise comparison.

Self-validation and tolerance rationale
src/helper.hpp reproduces the reference input generator (srand(123), rand() % 5 + 1) and an independent sequential host exclusive scan with identical chunk semantics. After a fresh device run the result is copied back and compared element-wise against the host reference. The first mismatch prints index, expected and got, and returns a nonzero exit code.
Tolerance: the comparison is exact (tolerance 0). A chunk-local prefix sum over a fixed integer set is an exact reduction, and the reference itself compares with memcmp/!=. For narrow types the reduction can wrap, and the host reference adds in the same type, so wrap-around matches bit for bit. Widening the tolerance would hide real ordering bugs.
Validated element counts, including boundary and irregular sizes and values not a multiple of the chunk size: 0, 1, 2, 3, 7, 15, 63, 127, 128, 129, 255, 256, 257, 511, 512, 513, 1000, 1023, 1024, 1025, 2047, 2048, 2049, 4095, 4096, 4097, 65537, 1048575, 1048576, 1048577. All element types and both variants pass on CPU and CUDA; a size-0 input runs zero chunks and passes.
