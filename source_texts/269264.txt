Why this, why now
ADR 0001 Phase C and closed epic #165 / #178 promised a quality-gated FFT ocean. What shipped is:
buildOceanFFTNode() in src/shaders/lightShowNodes.ts — a storage-texture write of normalized UV, used only as a 4×4 compute probe in computeDiagnostics.ts. Not a spectrum, not a displacement map, not sampled by water.
Water.tsx — 4-layer Gerstner GLSL (getWaveHeight in a shader string), CPU/WASM heights via WaveSystem / dsp_wave_height_batch.
C++ dsp_fft_r2c — 1-D packed real-to-complex FFT, N ≤ 4096. Ocean needs a 2-D FFT (typically 128²–256², two passes of 1-D, or a dedicated kernel).
gpu-chores (gpu-chores: blur/hist helpers — ocean FFT and god-rays stay domain #193) are explicitly not ocean FFT.
Do this after WebGPU-native water (#198) and device feature negotiation (#199). Otherwise FFT textures have nowhere to bind and float32-filterable may be missing.

What to change
Spectrum — Phillips (or JONSWAP) H0(k) from wind dir/speed already on the store (windDirection, windStrength, storm intensity). Seed from SimContext.rng so replays stay deterministic (docs/systems/DETERMINISM.md).
GPU path (when computeShaders === passed and granted float32-filterable if filtering the displacement): WGSL/TSL butterfly passes → StorageTexture height + normal. Execute with renderer.computeAsync, same device as the probe (adopt, never requestDevice).
CPU/WASM path — new exports e.g. dsp_fft2d_r2c / dsp_ocean_displace_batch in harborglow_dsp.cpp, wired in wasmDSP.ts + scripts/wasm-exports.mjs. Used when compute is unsupported (SwiftShader, Firefox-without-WebGPU, ?no_gpu_compute=1 does not kill ocean — that switch is helpers-only).
Buoyancy contract — Tugboat.tsx / foam must sample the same field the shader displaces. Document: readback vs dual evaluation of the analytic IFFT at probe points. Prefer evaluating the spectrum at hull points in WASM (no GPU readback bubble).
Kill the UV-stub buildOceanFFTNode or rename it to buildStorageTextureProbeNode so it cannot be mistaken for an ocean.
Libraries / C++
No new JS engine. Optionally KissFFT or a tiny in-tree radix-2 (already have 1-D). Do not pull FFTW (GPL) into the public repo.
If SIMD 2-D is hard, scalar WASM first; SIMD as a follow-up (-msimd128 artifact already built).
Non-goals
Babylon ocean.
Cinema tessellation if it misses frame budget — document deferral.
Replacing Rapier.
Acceptance
Low tier matches current Gerstner look/perf.
High tier: water mesh samples an FFT texture (Leva / quality preset); GPU path skipped cleanly without compute.
Headless determinism harness still hashes identical for same seed with FFT CPU path (determinism.harness.test.ts). GPU path is not in the headless hash.
Only Water.tsx mounted; docs/ARCHIVE.md updated.
Frame-time notes + chunk gzip in the PR. ?no_gpu_compute=1 still shows Gerstner/WASM ocean.
Suggested first PR
CPU/WASM 2-D FFT + Water sampling a DataTexture. GPU butterflies as PR 2 once #199 grants features.
