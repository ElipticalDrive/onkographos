Hi Jerome,
thank you for your interest in the framework. When you mention that "you wonder whether images in the paper underwent an intensity correction", it would be good if you could point out which Figure exactly you are referring to? The reason I am asking is because, as per its caption, the images shown in our paper (Fig. 3) are in fact real X-ray images acquired using a Simenes Cios Fusion C-arm system with flat panel detector. Exemplary images that were generated with DeepDRR are included in the readme, and some examples of log-domain transformed images can be seen here: https://arxiv.org/pdf/1901.06672.pdf.
Some additional comments:
The in-plane resolution of the CT scans used is fairly low with 0.9mm. This is notable in the images you show, but is not your main concern for now if I understand correctly.
Images in the DeepDRR framework are output in intensity domain, e.g. highly attenuating structures are dark. This is what a C-arm imaging system would provide. However, it is very true that these images are difficult to window/level due to the high difference in attenuation of bone/air. This is indeed a problem you will have in practice with real systems.
Converting to line-integral domain via log transform is encouraged. In fact, when we train CNNs on DeepDRRs we always train on log-transformed images since the dynamic range is easier to handle.
Scatter is a complicated topic. You want your generated images to be as close to real X-ray as you can get. Images that you get from a real scanner will have undergone a vendor specific and proprietary pre-processing pipeline that also consists of scatter reduction/removal. E.g. the dynamic density optimization as it is applied in Siemens products. This means that the real X-ray images you target will likely not have scatter, which is why for training set generation you may want to include images with both scatter turned on and off. This is briefly mentioned in the read-me.
The benefit of DeepDRR is not only in the integration of deep learning based method, it is one of the few, if not the only, simulation pipeline that allows fast simulation of material and energy dependent X-rays from voxelized representations with compromises regarding the accuracy of scatter.
To clarify: There is no heuristic log transform applied anywhere. The log transform can be used to transform from intensity to line-integral domain as per the Beer-Lambert law.
I hope this helps.
Please let us know if you have further questions or whether this issue can be closed.
Kind regards,
Mathias

Hi Jerome.
Another pointer I can give you regarding the appearance of the images is the following: Have you checked that the material decomposition is as you would expect? As you may know from the paper, the current V-net used for material decomposition was trained on a fairly small database since manual labeling was required. As a consequence, it works reasonably well for similar CT scans but we did observe compromised performance when different-looking CT scans were used (this unfortunately can happen easily due to different reconstruction filters, etc). If the V-net does not give you good performance, you can always go back and adjust the thresholds of threshold-based material decomposition (also implemented in DeepDRR) so that it best fits your CT volume (or even provide manual segmentations).
Regarding scatter: I understand the need for scatter, that is why we tried to also include it. In comparison to other work on machine learning based scatter estimation, we go the "harder way" i.e. trying to estimate what scatter there would be from a scatter-free image. This is more complicated than scatter correction, because scatter is known to be low frequency: If there is scatter signal in the image, a simple low pass filter will already do quite well. In our direction this will not work though, because this low pass signal that we would like to have is not yet in the image. This was just a handwaving argument why our scatter estimation may not perform to your needs.
The scatter as we model it does not consider any antiscatter grid. If you need reliable scatter signals, I would suggest you rely on low-resolution, variance reduced, forced detection Monte Carlo (e.g. as in [1]) which can be based upon our material decomposition.
Regarding X-ray spectra: See link in [2], it also allows to model filters.
Let me know if this answers your questions.

Hi,
Various things to consider:
properly define your projection and transformation parameters. Projection parameters model the intrinsics of the projection "camera pinhole model" of the X-ray generation process expressed as a K matrix, while transformation parameters express how your CT model is positioned and oriented with respect to your x-ray source ("camera eye") and detector ("image plane"), i.e. a rotation matrix R and a translation vector t. Based on K, R and t you can compute a projection matrix computed by DeepDRR projection matrix module: proj_mat = projection_matrix.ProjMatrix(R,K,t). DeepDRR code will then use this projection matrix in the projector:
```
proj_mats = []
proj_mats.append(proj_mat)

#forward project densities
forward_projections = projector.generate_projections(proj_mats, ....)
```
DeepDRR does not model the behavior of a detector in terms of response. Typically radiography has some kind of log conversion (see previous comments in this thread) and you should do the same if you want nicer intensities. In my case for instance I model a 12 bits image as follow:
```
images, photon_prob = mass_attenuation.calculate_intensity_from_spectrum(....)

if logarithmic_response:
	      max_intensity = 2**12
	      images = log_negative_response(images, max_intensity)


def log_negative_response(images, max_intensity_value):
	    
	  for i in range(0, images.shape[0]):
	    image = images[i,:,:]
	    
	    # shift image to avoid invalid values
	    minv = np.min(image)
	    epsilon = 0.000001
	    if minv < epsilon: image += epsilon + minv
	    
	    # take log response
	    image = np.log(image)
	    
	    # negate it and shift it so that log_max_signal_value
	    # is the min
	    image = np.negative(image)
	    
	    min_log_negated_image = np.min(image)
	    max_log_negated_image = np.max(image)
	        
	    # rescale it to be in image dynamic
	    log_negated_image_range = max_log_negated_image-min_log_negated_image
	    images[i,:,:] = (image - min_log_negated_image) * max_intensity_value / log_negated_image_range
	  
	  return images
```
Regardless of 2), images may need a final intensity windowing, which should be the responsibility of the user and which is performed via image viewer controls. You can save a preferred windowing in an image format supporting the feature, allowing a viewer to consider it and applying it directly to the image. For instance the medical DICOM image format can do that, although the DICOM format is a little cumbersome to use IMHO.

@schmidje thank you for your detailed response, this is pretty much exactly what I would have answered, too.
Pose parameters: Check that your dicom origin is read properly and that the volume is centered on the pelvis. This is critical to be able to use the diminished theta / phi coordinate system. The other option is to use proper matrices right away. We are working (and have nearly finished) a complete overhaul to the interface that is, in part, designed to make this much easier. @benjamindkilleen has been leading this effort and may be able to comment when it will be available.
Dynamic range is a huge issue in X-ray simulation. Before modifying too much, save your images in a floating point format and inspect them with a viewer made for such images, such as ImageJ as a lightweight option. Use the contrat/brightness or window/level tool to inspect different intensity ranges of the image to check whether information is there (it should be!)
The above may still not be enough to get proper looking images after log conversion. We've been working on a detector module that can deal with this, simulating automatic exposure control compensation. @gaocong13, do you have information when we will release this?
Finally, the one image I saw seems to be simulated from a CT scan with low resolution. I would advise to use CT scans with the highest possible resolution.
