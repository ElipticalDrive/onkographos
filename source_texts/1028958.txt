Summary
Upgrades ome_zarr_writer from OME-NGFF v0.5 to v0.6 (branched from mobi) and adds oblique stage-scan deskewing support, both via native OME-NGFF 0.6 AffineTransform metadata (for zero-copy on-the-fly GPU deskewing in Neuroglancer) and via fast, exact 1D 2-tap linear slice/volume/dataset deskewing into an orthogonal multiscale OME-Zarr 0.6 pyramid.
Why OME-NGFF v0.6?
In google/neuroglancer (src/datasource/zarr/ome.ts), Neuroglancer explicitly gates RFC-5 coordinate transformation behavior on version !== "0.4" && version !== "0.5-dev" && version !== "0.5":
In 0.5, Neuroglancer forces baseTransform = Identity, discarding non-diagonal affine shear/rotation transforms and misaligning downsampled pyramid levels by half a voxel per level (voxel_size * (2^L - 1) / 2).
In 0.6, Neuroglancer parses coordinateSystems and SequenceTransform (scale $\to$ translation $\to$ affine), surfacing the oblique light-sheet shear (baseTransformWithoutScale) directly as the Neuroglancer layer transform while keeping all pyramid levels (L0..L7) registered via makeAffineRelativeToBaseTransform.
Our existing Neuroglancer viewer container (55f2fa501f20f79fa8a9cbe1ef00a394ee7e22e1) already supports OME-Zarr 0.6 out of the box with zero changes to Neuroglancer base code.
Key Changes
OME-NGFF v0.6 Metadata Schema (omezarr/src/ome_zarr_writer/dataset.py)
Upgraded OmeMeta.version to Literal["0.6"] = "0.6".
Added CoordinateSystem, TransformEndpoint, AffineTransform (including AffineTransform.from_shear(shear_xz=..., shear_yz=..., ndim=4)), SequenceTransform, and Omero / OmeroChannel / OmeroWindow.
Updated Multiscale to emit coordinateSystems: [{"name": "physical", "axes": [...]}] and Dataset to emit SequenceTransform(input={"path": level.path}, output={"name": "physical"}, transformations=[ScaleTransform, TranslationTransform?, AffineTransform?]), while still accepting flat axes and flat [ScaleTransform, ...] lists at construction time for ergonomic backward compatibility.
Updated Zarr3GroupMeta.multiscale() to include half-voxel center-of-voxel pyramid translations (voxel_size * (f - 1) / 2 for f > 1), optional stage origin, optional shear_xz / shear_yz AffineTransform, and default omero channel display metadata.
Added OmeZarrDataset.read_metadata(), .voxel_size, .voxel_unit, and .shear_xz helpers.
Writer & Camera Stack Wiring (omezarr/src/ome_zarr_writer/writer.py, src/vxl/devices/camera/base.py, src/vxl/devices/camera/handle.py)
Added optional origin: Vec3D | None = None, shear_xz: float = 0.0, shear_yz: float = 0.0, channel_label: str = "channel 0", and channel_color: str = "FFFFFF" to WriterConfig and CameraController.open_stack / CameraHandle.open_stack.
Fast, Exact 1D 2-Tap Linear Deskewing (omezarr/src/ome_zarr_writer/deskew.py)
Added Numba-JIT parallel deskew_slice(plane, shift_x, cval=0.0, out=...) that writes directly into preallocated 2D buffers (such as OMEZarrWriter.new_frame()) with zero intermediate frame allocation.
Added deskew_volume(volume, shear_factor, cval=0.0) for in-memory 3D (Z, Y, X) arrays.
Added deskew_dataset(source, storage, ...) which streams L0 slabs from an acquired OME-Zarr 0.6 dataset (automatically reading shear_xz from its AffineTransform metadata unless overridden) through OMEZarrWriter to write an orthogonal, sharded multiscale OME-Zarr 0.6 pyramid without materializing the full volume in RAM.

Load both .ome.zarr volumes simultaneously into Neuroglancer and verify that their SequenceTransform translations place both strips at their expected physical stage coordinates in the shared "physical" coordinate system.
