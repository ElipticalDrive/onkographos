On our computer, the crash occurs when BabelBrain voxelizes the SimNIBS STL skin/skull mesh, because we have only 4 GB of GPU memory available with CUDA on Ubuntu.
We updated the code to make BabelBrain process the voxelization in smaller GPU chunks. This is a software workaround for the memory limitation. The error occurs because BabelBrain tries to send a very large array to the GPU at once:
points_section_gpu = clp.asarray(points_section)
We also ran the same participant on a system with 8 GB of GPU memory without modifying Voxelize.py, and the simulation results were the same as those obtained with the patched version on the 4 GB GPU.

Thanks for looking into this! So normally for the CUDA pipeline, we try to calculate a step size based on available GPU memory, however with the voxelization, it looks like we weren't properly accounting for the memory needed to run the voxelization step which explains why it was failing for you since there's not much wiggle room on 4GB GPU.
I made some edits to fix this, I also reworked the step size calculation to be a bit more conservative so hopefully these changes will get it working on your system. We would like to keep using the calculated step value instead of a capping it at a small value since we don't want performance on higher end GPUs to be impacted. However, we will now default to your suggested value for low-VRAM GPUs if issues arise with the calculated step value.
Let me know if it works!
