Summary
Extend the existing coordinate iterator without creating another grid engine.
Inventory ownership: Boustrophedon / Serpentine; Hilbert Curve; Morton Order / Z-order Curve; Rectangular Grid Permutation.
Existing capabilities
Reuse immutable image::Image, explicit physical channels/palette expansion, checked Region, bounded codec provenance and existing lossless PNG export; existing operations are in image/{analyze,transform,traversal}.rs and verified by corresponding Rust/CLI/native-Python test fixtures.
Audited baseline: 96bd2b3. Extended inventory traceability; prior cipher ownership stays in #150.
Technical contract
Add serpentine (even y left-right, odd y right-left), Hilbert 2D order n square side 2^n with canonical bottom-left-origin xy2d convention explicitly reflected to image top-left, and Morton bit-interleaving x at bit 2i/y at 2i+1. Hilbert/Morton require square power-of-two side<=2048; reject rectangles rather than pad silently. Rectangular Grid Permutation accepts explicit row-major destination->source index bijection for exact region shape; return/reuse index sequence without new matrix API. Existing corner/reflection/reverse behavior composes explicitly and remains unchanged. <=1 Mi coordinates/permutation entries, <=16 Mi visits, <=16 MiB scratch; serpentine/curves lazy where possible, permutation validation bitset O(n). Expose concrete Rust functions, CLI JSON/exclusive new-file output where relevant, native Python types/bytes and accurate stubs plus module-owned operation metadata. Structured numeric/image/audio outputs stay direct APIs with pipeline=null; do not introduce arbitrary JSON or image/audio pipeline values. Existing engine API1, recipe format1 and old adapters remain compatible. Reject nonfinite parameters, malformed shapes, overflow and exhausted budgets with typed errors before allocation/work; lower caller limits only. Integer results are exact; f64 comparisons use stated absolute/relative tolerances and fixed iteration order, without cross-platform bit-identity promises. Preserve the public exhaustive Traversal enum and existing LsbOptions/LsbResult layouts. Expose new curve/permutation functionality through additive concrete functions/options rather than silently adding enum variants that break downstream exhaustive matches.
Any parameter without an explicit default in this contract is required. Unsupported combinations fail explicitly rather than being guessed.
Rust cube-core owns ordinary functions/concrete types; CLI and native Python call the same Rust implementation. Add accurate module-owned descriptors, exports/stubs, binary-safe transport, typed errors and concise English documentation. Preserve current public APIs, engine API 1, recipe format 1 and existing adapter contracts.
Algorithm/specification references (pin exact revision/profile during implementation or the research decision):

https://fgiesen.wordpress.com/2009/12/13/decoding-morton-codes/
Acceptance criteria
Independent known-answer fixtures and invalid inputs cover the exact selected profile and numerical conventions.
Rust, CLI and native Python agree; metadata, exports/stubs and concise existing guides match the implemented contract.
Checked input/output/work/scratch limits reject exact one-over/adversarial requests; existing behavior and recipe compatibility remain unchanged.
Required formatting, lint, locked workspace tests and real native-Python tests pass; retain the 80% core line threshold and verify examples before closing the issue or marking Project Done.
Tests
Explicit2x2/4x4 Hilbert/Morton vectors, one-row serpentine, all visits unique, inverse permutation, repeated/missing/out-of-range indices, reflected corners and existing LSB/export compatibility.
Use independent known answers/fixtures, edge and invalid inputs, exact/one-over limits, old-behavior regressions and cross-interface compatibility. Follow CONTRIBUTING.md: Rustfmt, Clippy with warnings denied, locked workspace tests, Ruff, rebuilt native-extension pytest and the unchanged core coverage gate. Research records a reproducible verification plan and observed feasibility; no unrun tests are claimed passed.
Dependencies
Add configurable image traversal patterns #66 — completed reuse/context.
Out of scope
No implicit I/O, automatic hidden-message inference, new runtime framework or duplicate SDK algorithms.
Operation contract Definition of Done
For every operation added or changed by this issue:
Ship/update its canonical versioned descriptor and complete input, parameter, output and error schemas, named ports, defaults/constraints, exact representations, limits and sensitivity/availability policy in the same logical change.
Keep the operation in the complete discoverable catalog and generated reference documentation; update verified examples and applicable Rust/CLI/native Python contracts compatibly.
Verify actual results against schemas with positive, invalid/boundary and compatibility fixtures. Required catalog-completeness, reference-drift and contract-conformance CI gates pass; name-only/placeholder contracts do not count.
Provide/update the required safe typed Play execution adapter and compatible input/output/viewer handling. A null pipeline adapter does not exclude a direct operation. Missing integration remains open; do not hide the operation or mark coverage complete.
Preserve explicit capability authorization, bounded processing, secret redaction and no implicit uploads. Contract metadata never grants execution privileges or proves result correctness.
