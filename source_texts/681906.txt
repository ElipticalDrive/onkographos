What
The first half of Track W's W1: DrawCommandKind.FillAnnularSector as an exact SDF across all three backends, plus the local-NuGet consumer path that validated it end-to-end, and the feed-determinism fixes that validation surfaced.
The primitive
Sdf.AnnularSector(p, rIn, rOut, a0, a1, rounding) in Sdf.cs (normative) — rotate by −mid, fold |qy|, perpendicular distance to the edge line; inside the wedge it is max(rIn−r, r−rOut, ρ−w), outside it is distance to the inset edge segment. Rounding bends only the corners: straight runs stay on the same line (inset + subtract cancel), which the tests pin explicitly.
sdAnnularSector transliterated in Sdf.slang; Sdf.metal/Sdf.spv/Sdf.metallib regenerated by ./scripts/generate-shaders.sh (never hand-edited). The shadow-coverage guard is tightened to flags.x ∈ (1.5, 2.5) so the new kind (flags.x = 3) never takes the shadow path.
Builder FillAnnularSector(center, rIn, rOut, a0, a1, paint, rounding = 0) with guards (sweep ≤ 2π, rounding ≤ band/2); the command is not normalized — Radii carries [inner, a0, a1, rounding]. Plus FillCircle(center, radius, paint) sugar, because the consumer's hub was detouring through a 2π sector.
Judged like every command before it: 6 hand-computed distance pins (corner point √500 included) and the annular-sunburst golden scene under Reference goldens + Metal parity + Vulkan (MoltenVK) parity.
The consumer proof (F0)
The eQuantic OS Cleaner spike consumed this via local packages only — no pipeline, no version cut: dotnet pack -p:PackageVersion=1.0.0-dev -o artifacts/local-feed, consumer on global.json msbuild-sdks + nuget.config with the local feed. Its sunburst re-rendered a real 5.38M-file scan byte-identical (cmp clean, 277,699 bytes, 268 commands) between source-reference and package builds at the same HEAD. Angular-gap question closed at the call site; feedback registered in docs/DESKTOP-PLAN.md.
What the validation surfaced (fixed here)
ClearEQuanticCache had a stale hand-written list that missed every native package, Sdk.Native, and the arm64 runtimes — now reactive (GetDirectories('equantic.*')), so the repack loop actually clears.
samples/ were packing into the feed (PhotonDesktop, WalletMobile as nupkgs) — samples/Directory.Build.props sets IsPackable=false.
eQuantic.UI.Native.Shell.iOS and eQuantic.UI.Runtime were never in the solution, so solution-level pack omitted them — an iOS consumer of the feed would have failed restore on a package Sdk.props itself references. Both added; the feed is deterministic at 49 packages, all product, confirmed independently by both sides.
What W1 still holds open (by design)
The FillConvexPolygon-vs-dynamic-texture decision for blob-like art stays open until the consumer's 16-point blob benchmark runs on the W2 frame clock — the plan spells out the constraint and both routes.
Tests
Full suite green on the branch tip: 3,937 passed, 0 failed (engine 1,029 including the new pins + golden; conformance 1,146).

One more shape in the SDF family, NOT a path engine: DrawCommandKind.FillAnnularSector
(center, inner/outer radius, start/end angle, corner rounding) with the flat-command slot
reuse StrokeWidth already set — Shape.Rect is the bounding square and Radii carries
[inner, a0, a1, rounding]. Angles in radians, 0 along +X, increasing toward +Y: y grows
down, so clockwise on screen.

The SDF is EXACT and derived, not borrowed: fold to the sector's symmetric half; a point
angularly inside the inset wedge sees max(rIn−r, r−rOut, ρ−w) — the three boundaries it
can touch — and a point beyond it sees the inset edge SEGMENT whose endpoints sit where
the inset line meets the inset arcs (s = √(r²−ρ²)). Rounding is an euclidean inset plus
subtract, so along an edge's straight run the rounded boundary IS the sharp one and only
the corners bend — a pin proves exactly that, after the first draft of the pin assumed
otherwise and the formula corrected the test.

Sdf.cs is normative; Sdf.slang transliterates it; the generated Metal/SPIR-V/metallib are
regenerated by the pinned toolchain. The shadow-coverage guard tightened from
flags.x > 1.5 to (1.5, 2.5) — kind 3 is not a shadow. The Reference rasterizer reuses the
rrect loop (the bounding square keeps its AABB math); radial gradients shade sectors with
no new uniform, since Paint already carries them.

Judged three ways from the first commit: six hand-computed distance pins (edges zero,
interior −10, the corner point at √500, rounding bending only corners), the shared
"annular-sunburst" golden (rounded slices, an angular gap, a radial-gradient arc, a full
ring), and the SAME scene through Metal and Vulkan parity — 48 parity tests, zero skips.

Unblocks the OS Cleaner F0 spike (docs/DESKTOP-PLAN.md W1); stroke/shadow variants and
the convex-polygon decision stay with W1 proper.
