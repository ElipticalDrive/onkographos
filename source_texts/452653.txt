Summary
Brings the editor up to parity with the renderer, and moves the scene's look onto volumes that later features, such as wind, can use too.
Volumes (lib/engine/volume): a Volume component makes its entity global, a box or a sphere, with a weight, a blend distance and a priority. Settings components on the same entity blend at a point with volume.sample. Each setting is a Value(T) that a volume overrides or leaves to the volumes below it. A scene that sets a field overrides it, so the scene format does not change.
Render settings on volumes:
Anti_Aliasing, Exposure, Tone_Mapping, Bloom, Ambient_Occlusion, Global_Illumination, Environment (background and ambient light), Fog (now with an absolute base_height) and Shadows (cascade reach and split).
resolve_settings blends them at the camera, in place of the old Frame_Desc fields. The sample scene gets a Global Volume.
Post effects: register_post_effect runs a game's effect before temporal AA, after it, or before tone mapping, where a volume with its settings reaches the camera. Bloom is composited into the scene first when an effect runs before tone mapping. The sample's chromatic aberration and vignette are now a Lens effect.
Debug views: 17 views, from the forward template (lighting only, direct or indirect light, fog, albedo, light complexity, shadow cascades) and from the frame's textures (normals, depth, velocity, AO, GI, shadow mask, entity IDs, luminance). The viewport can also turn features off and offset the exposure.
Editor:
Fields: the editor tag is now a list of words. Colors get a picker, ranged numbers get sliders, and [2]f32 fields are shown.
Volumes: each volume setting has an override check box.
View tab: a Rendering group (debug view, feature toggles, exposure) and a Helpers group.
Viewport: lights, volumes and cameras get shapes (ranges, cones, bounds and frustums), and clickable icons that pick them.
New Volume command.
Project settings: samples/mygame/project.settings, plus an untracked project.user.settings that overrides it on one machine. The first key is output (Auto, SDR, HDR10, scRGB).
The game reads both files at startup and again when they change.
The editor's Game Window group sets both, and Run Game opens the game in its own window. The viewport is always SDR, so HDR only shows there.
In the sample, F8 cycles the output mode.
This fixes the standalone game looking blown out on an HDR display.
Design notes are in docs/world.md#volumes, docs/rendering.md (Settings, Debug views, Post effects) and docs/architecture.md#project-settings. Each phase is its own commit.
Notes
Every material recooks once, because the shared material shader file gained the debug view.
The shadow depth bias stays a constant: it is part of the shadow pipelines' description.
A split_lambda of exactly 0 means the default, under the zero-means-default rule.
Icons are hidden behind walls rather than drawn on top of everything.
Testing
just lint is clean.
just test passes: every Odin package and 210 editor tests. The host link tests run on the real GPU: a volume's background, the raw albedo view, every debug view, and a pick on a light's icon.
I checked every debug view, the icons and the shapes on the Cornell box with temporary captures, which are not committed.
The live switch from HDR10 to SDR works in a running game window.
