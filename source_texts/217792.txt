Summary
The current ops.Boolean(Intersect, box, sphere) returns a solid with 63% too little volume for a box that almost wholly contains a sphere.
Repro
Box: [-2,2]³ (via brep.SolidBlock)
Sphere: centre (1,1,1), radius 1.5 (via brep.SolidSphere)
Operation: Intersect
The sphere spans [-0.5, 2.5] on each axis, so it is almost entirely inside the box — only three small caps poke out past x=2, y=2, z=2. The intersection is therefore close to the full sphere.
Volume
Existing engine (ops.Boolean(Intersect, …))
4.06
True value (numerically integrated, 8M samples)
11.01
Full sphere
14.14
The true value = sphere − 3 caps (each cap height 0.5, ≈ 1.047) + pairwise overlaps ≈ 11.01. The existing engine's 4.06 is not explained by any facet bias.
How it was found
The ADR-0052 mesh-arrangement engine (feat/exact-boolean-core) shadow-validation (TestShadowValidateAgainstExistingEngine) flagged the divergence. The new engine returns 10.89 (0.9% low, facet bias) — correct. That test currently gates this case against the true value with the existing engine's answer logged as a known defect.
Fix
This is one of the defects the exact mesh-arrangement boolean removes; the planned cutover in ops.booleanGeneral resolves it. Filing so the divergence is tracked independent of the cutover branch.
