Descripción
Implementar una estructura de aceleración espacial (BVH u Octree) en GPU, compartida entre múltiples sistemas del engine: ray marching, collision detection, light culling y frustum culling.
Motivación
Múltiples sistemas necesitan responder la misma pregunta: "¿qué objetos hay cerca de este punto/ray?" Sin aceleración espacial:
Ray marching (Ray marching básico (fragment shader) #22): evalúa TODOS los SDFs por paso → O(n)
Collision detection (Collision detection con SDF #40): chequea TODOS los pares → O(n²)
Light culling (Point lights (radiales) #27): itera TODAS las luces por fragment → O(n)
Frustum culling (Hybrid Rendering Pipeline (SDF + Mesh) #91): chequea TODOS los objetos → O(n)
Con BVH/Octree, todo esto baja a O(log n).
Arquitectura
```
┌─────────────────────────────────────────────────────────────────┐
│              SPATIAL ACCELERATION STRUCTURE                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  BUILD (compute shader, per-frame o cuando cambia la escena)    │
│  ├── Input: AABBs de todos los objetos (SDF bounds, meshes)     │
│  ├── Algoritmo: LBVH (Linear BVH) — GPU-friendly, O(n log n)   │
│  └── Output: BVH buffer (nodos internos + hojas)                │
│                                                                 │
│  QUERY (usado por múltiples sistemas)                           │
│  ├── Ray query  → Ray marching, shadows, physics raycast        │
│  ├── AABB query → Broadphase collision, frustum culling         │
│  ├── Point query → Nearest neighbor, spatial lookup             │
│  └── Sphere query → Range queries, light influence              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
Opciones de Implementación
Opción A: BVH (Binary Volume Hierarchy)
Pros: Mejor para ray queries, GPU-friendly (flat array), bien estudiado
Contras: Rebuild costoso si la escena cambia mucho
```
struct BvhNode {
    aabb_min: vec3<f32>,
    left_or_first: u32,   // si es interno: índice hijo izq. Si es hoja: primer objeto
    aabb_max: vec3<f32>,
    count: u32,           // 0 = nodo interno, >0 = hoja con N objetos
}

// Traversal iterativo (sin recursión, GPU-friendly)
fn bvh_ray_query(ray: Ray, bvh: ptr<storage, array<BvhNode>>) -> HitResult {
    var stack: array<u32, 32>;
    var stack_ptr = 0u;
    stack[0] = 0u; // root
    stack_ptr = 1u;
    
    var closest_hit = HitResult();
    
    while stack_ptr > 0u {
        stack_ptr -= 1u;
        let node_idx = stack[stack_ptr];
        let node = bvh[node_idx];
        
        if !ray_aabb_intersect(ray, node.aabb_min, node.aabb_max) { continue; }
        
        if node.count > 0u {
            // Hoja: test objetos individuales
            for (var i = 0u; i < node.count; i++) {
                test_object(node.left_or_first + i, ray, &closest_hit);
            }
        } else {
            // Interno: push hijos
            stack[stack_ptr] = node.left_or_first;
            stack_ptr += 1u;
            stack[stack_ptr] = node.left_or_first + 1u;
            stack_ptr += 1u;
        }
    }
    
    return closest_hit;
}
```
Opción B: Octree
Pros: Natural para datos volumétricos (voxels, SDF), LOD implícito
Contras: Más overhead de memoria, traversal más complejo en GPU
Recomendación
LBVH (Linear BVH) para la primera iteración:
Construcción en GPU via Morton codes + radix sort
Flat array layout (cache-friendly)
Traversal sin recursión (stack-based)
Rebuild completo cada frame es viable para escenas dinámicas (~0.5ms para 100K objetos)
Octree se evalúa después si los datos volumétricos (voxels, SDF 3D textures) lo justifican.
Tareas
Estructura BvhNode en GPU buffer (PR-1: layout shipping next subtask)
Compute shader: calcular Morton codes de los AABBs
Compute shader: radix sort de Morton codes
Compute shader: construir BVH desde sorted Morton codes
Funciones de query: ray, AABB, point, sphere (librería WGSL)
Integración con ray marching (Ray marching básico (fragment shader) #22) — usar BVH para skip de objetos lejanos
Integración con broadphase collision (Broadphase con SDF bounds #42)
Integración con frustum/occlusion culling (Hybrid Rendering Pipeline (SDF + Mesh) #91)
Refit (actualizar AABBs sin rebuild completo para movimiento pequeño)
Criterios de Aceptación
BVH se construye en GPU en <1ms para escenas de 10K objetos
Ray queries son correctas (same results as brute force)
Múltiples sistemas usan la misma estructura
Rebuild vs refit funciona correctamente
