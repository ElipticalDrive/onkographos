Description
I added support for tiled rendering when doing rendering in the engine. Tiled rendering is always enabled with a default tile width and height of 2048. The reason for always being enabled is that Mesa stops working properly somewhere between an image width and height of 8192 and 16384. This avoids that issue.
The tiled rendering width and height can be controlled with the tiledRenderingWidth and tiledRenderingHeight fields in the RenderingAttributes. For example:
```
renderAtts = RenderingAttributes()
renderAtts.tiledRenderingWidth = 512
renderAtts.tiledRenderingHeight = 512
SetRenderingAttributes(renderAtts)
```
sets the tiled rendering width and height to 512.
Tiled rendering is only used when saving images. It is not used when displaying images in the viewer. The main driver for tiled rendering is to work around the image size limitation in Mesa and this accomplishes that. Tiled rendering is currently only supported for images of 3D geometry. For images or 2D geometry, the image is only rendered in the viewport and tiled rendering doesn't support this case yet.
There are a few limitations of tiled rendering.
Anti-aliasing doesn't work properly with tiling. When using FXAA (Fast Approximate Anti-Aliasing), each tile will be independently anti-aliased resulting in artifacts along tile boundaries. Typically, those artifacts are not visible.
Points may not extend across tile boundaries when using the "Point" point type. All other point types should work fine.
Horizontal or vertical lines that align exactly with tile boundaries may not be visible.
Points that are exactly on tile boundaries may not be visible.
Any rendering that involves OSPRay doesn't work properly with tiled rendering since neither panning or zooming is currently supported with OSPRay.
I added documentation for tiled rendering to the Preferences section of the "Using VisIt" chapter.
Internally, a fixed tile size is used that just covers the image being rendered that is smaller than the user selected size. For example, if the image size is 1024x1024 and the user selects a 512x512 tile size, then it uses the user selected tile size. If the tile size doesn't exactly divide the image size, then the tile size is chosen such that last tile in each direction will minimally extend beyond the image. For example, if the image size is 1021x1021 and the user selects a 512x512 tile size, then it uses a tile size of 511x511 and discards a row and/or column in the tiles along the right and bottom edges.
Tiled rendering is handled in NetworkManager::RenderTiledInternal. The View3D is zoomed and then panned as the tiles are looped over.
This handled most of the plots. The exceptions were the "Label" and "Volume" plots. The "Label" plot has a mode where it restricts the number of labels so that the labels are legible and it doesn't take too long to render in the case of large meshes. It does this by creating a 2D grid of bins over the entire image. This occurred over tiles instead of the entire image until the plot was enhanced. The volume plot had a parallel resampling mode that had a bug with panning. Since the tiling relies on tiling, it didn't work until the panning bug was fixed.
In order to add support for tiled rendering for annotations, the background and foreground views were changed as follows in NetworkManager::RenderTiledInternal.
```
    vtkCamera *cam = viswin->GetBackground()->GetActiveCamera();
    cam->SetFocalPoint(0.5 - foregroundPan[0], 0.5 - foregroundPan[1], 0.);
    cam->SetPosition(0.5 - foregroundPan[0], 0.5 - foregroundPan[1], 1.);
    cam->SetViewUp(0., 1., 0.);
    cam->SetParallelProjection(1);
    cam->SetParallelScale(0.5 / zoomTile);
    viswin->GetBackground()->SetActiveCamera(cam);

    vtkCamera *cam = foreground->GetActiveCamera();
    cam->SetFocalPoint(0.5, 0.5, 0.);
    cam->SetPosition(0.5, 0.5, 1.);
    cam->SetViewUp(0., 1., 0.);
    cam->SetParallelProjection(1);
    cam->SetParallelScale(0.5);
    foreground->SetActiveCamera(cam);
```
3D annotations worked fine with this change, but 2D annotations were all rendered in NormalizedViewport coordinates. The 2D annotations were all modified to use World coordinates.
The baselines were primarily updated for the following reasons.
Any image that had an annotation potentially changed since the rendering of annotations was changed from NormalizedViewport to World coordinates.
Any images with a gradient background were changed because the rendering of the background was changed from NormalizedViewport to World coordinates.
Any images associated with the label plot because the a subtle bug affecting how the bins that the labels are placed in was fixed.
Mode specific baselines were added for plots where large points were rendered near tile boundaries.
Mode specific baselines were added when either points or lines were exactly on tile boundaries.
Images that involved OSPRay rendering were added to the "scalable,tiled" mode skip list.

How Has This Been Tested?
The test suite was run in serial mode and all the tests passed. The testing mode "scalable,tiled" was added to the test suite that runs the test suite with tiled rendering. All the tests pass in this mode as well.
