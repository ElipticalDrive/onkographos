Summary
Adds gauss_splat_mvp.ipynb — a single, self-contained Jupyter notebook that implements the core of 3D Gaussian Splatting (Kerbl et al., SIGGRAPH 2023) in pure PyTorch, with no custom CUDA kernels. It is intended as a teaching / "grind on the math" reference rather than a production renderer.
What's in it:
Camera model: pinhole PinholeCamera + look_at (OpenCV/COLMAP convention).
Gaussian parameterization: mean, scale (log-space), rotation (unit quaternion), per-Gaussian RGB color, opacity. Covariance built as Σ = R S Sᵀ Rᵀ so it's automatically symmetric PSD.
Forward rasterizer:
World→camera transform of means.
3D covariance transformed into camera frame.
2D screen-space covariance via the EWA / Zwicker-style projection Jacobian: Σ_2d = J W Σ Wᵀ Jᵀ plus a small isotropic dilation/blur for stability.
Depth sort and per-pixel front-to-back alpha compositing (same volume-rendering equation as NeRF, with anisotropic 2D Gaussian weights).
Demo: 5 hand-placed colored 3D Gaussians rendered from 4 training cameras + 1 held-out novel camera. We then init 40 random Gaussians and fit them to the training images by Adam on photometric L1 + MSE for 600 iterations. Final mean training loss is ~5e-4 and the held-out novel view matches the GT cleanly.
Closing markdown: explicit list of what's intentionally skipped vs. real 3DGS (tile-based CUDA rasterizer, spherical-harmonics view-dependent color, adaptive density control, real captures, SSIM losses).
The notebook is committed with outputs already executed (loss curve + before/after grid embedded), so it renders nicely on GitHub without re-running.
End-to-end run takes ~30 s on CPU on a 64×64 image.
Review & Testing Checklist for Human
Open gauss_splat_mvp.ipynb and skim the math sections — sanity-check the projection-Jacobian formula and the alpha-compositing recurrence match what you expect.
Run all cells top to bottom in a fresh kernel and confirm the loss curve is monotonically decreasing and the final fit/novel-view grid roughly matches the embedded one.
Confirm the notebook fits how you want this kind of tutorial material organized in this repo (it's a standalone topic from the diffusion-world-model work). Happy to move it into a subfolder, add it to the README, or split it into multiple notebooks if you'd prefer.
Notes
Dependencies are already in requirements.txt (torch, numpy, matplotlib).
argsort for the depth sort is non-differentiable across order changes — gradients flow through values given the ordering. This is also true of the production 3DGS rasterizer and is fine for a fit-from-scratch demo.
I deliberately kept the rasterizer as a for i in range(N) Python loop over Gaussians rather than vectorizing over all (H, W, N) at once — easier to read, and 40 Gaussians × 64×64 image is plenty fast on CPU. Easy to vectorize later if useful.
If you'd like the next step (e.g. add adaptive densification / pruning, swap to spherical-harmonics color, or scale up to a real COLMAP scene), just say the word and I'll layer it on top.
