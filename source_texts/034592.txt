Moving least squares
threecrate-reconstruction/src/moving_least_squares.rs:209-211, 331, 452-462
Without normals every fit target is 0, so the field is 0 everywhere and marching cubes finds no surface. moving_least_squares_auto on a 2000-point sphere returns "No isosurface found". Python moving_least_squares_reconstruct always errors, and the pipeline's MovingLeastSquares and MarchingCubes options always fail on clouds without normals.
With normals, sample points with no neighbors return 0, which creates a fake outer shell. On a 5000-point sphere, 37,632 of 68,928 vertices are more than 0.08 off the surface.
Public marching cubes
threecrate-reconstruction/src/marching_cubes.rs:474-624
Each cube makes its own edge vertices, so every seam is open: a 40³ sphere volume gives 12,960 open edges.
Every face points inward.
Poisson already has a correct shared-vertex extractor (poisson.rs, extract_surface).
Fix
Make extract_isosurface reuse Poisson's extractor with the winding reversed, and delete the duplicate.
Make moving least squares return an error up front without normals (or estimate and orient normals first), and treat "no neighbors" as outside.
Size the support radius from the point spacing instead of a fixed 0.1.
Found in a repo audit.
