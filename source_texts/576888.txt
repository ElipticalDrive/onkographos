The cost
The cave culling search (gfx/occlusion.rs, Horizon's SectionOcclusionGraph) ran on the render thread whenever a section was meshed or the camera entered another section. At render distance 32 that is a breadth-first walk over about 124,000 cells. While exploring, new sections arrive every frame, so it ran nearly every frame. In whole-game benchmark runs on main (tools/perf_bench.py, RD 32, 4 scenes) the occlusion span took at least 0.5 ms in 35% of frames, averaging 5.6 ms in those frames on the loaded Mac mini.
The change
Vanilla 26.3 runs this search on a background executor (scheduleFullUpdate) and updates its graph on the render thread only for sections that changed (runPartialUpdate). Horizon now does the same:
A worker thread keeps its own copy of every section's face connectivity, fed the changes with each job, and runs the full search over dense arrays around the camera.
Frames use the last finished graph and never wait for the next one. The search starts at the top of Game::render, as soon as the camera is known, so it usually lands before the frame builds its visible list.
A section meshed in between propagates into the graph the frame already has (vanilla's partial update). A wall that opens shows what is behind it in the same frame. A wall that closes takes effect at the next full search; until then the hidden sections are still drawn, behind the depth buffer.
A graph that never reached the camera's section (after a teleport, say) is not used. Until the next one lands, every section in the frustum is drawn, so nothing goes missing.
If the worker thread cannot start or dies, the search runs on the render thread as before.
The search itself is unchanged: the same box, steps and first-entry rule. A test checks it cell for cell against main's code over random worlds.

For example, RD 32 village-n differs in 11,304 pixels between modes and 14,817 between two captures in the same mode.
Not in this PR: vanilla's graph rules
Vanilla's Node.sourceDirections keeps every face a section is reached through; Horizon keeps the first only. Vanilla also drops sections more than 60 blocks away when a ray towards the camera crosses a section the search has not reached. I measured the first rule: it draws 5–15% more sections (RD 32: 3,707 → 4,110, 3,943 → 4,540) with no visible difference in the same 18 views. So it is left out here, and filed as #782 for a decision together with the ray test.
