What
Adds the segmentation + 3D slicing workflow behind a new 4-tab workspace shell (Visualize / Segment / 3D / Export). Activates the deferred roadmap items: threshold/region-grow segmentation, marching-cubes surface reconstruction, and binary STL export.
Stacked on #1 (feature/yash-visualization-patient-library). Until #1 merges, this PR also shows its 2 commits (window/level drag + metadata inspector, notarized DMG). Merge #1 first; this then reduces to the 4 commits below.

```
Restructures the segmentation core around OOP and design patterns, and adds
newcomer-oriented engineering docs. Behaviour is identical (SegTest 15 groups
pass; MeshShot end-to-end output unchanged: 109528 voxels -> 89984 triangles).

OOP / patterns:
- SegmentEditor (Facade): one class owns the mask + segment table + undo stack
  and a non-owning pointer to the loaded volume. All segmentation domain logic
  (active label, "remove clears voxels", undo capture) now lives here instead of
  leaking into the C bridge. Encapsulation + Single Responsibility.
- SegmentationEffect (Strategy): every editing operation is a polymorphic class
  (ThresholdEffect, PaintEffect, RegionGrowEffect, ClearEffect, KeepLargestEffect,
  RemoveSmallEffect, GrowMarginEffect, ShrinkMarginEffect, SmoothEffect) behind a
  single apply(). The editor dispatches any of them through one method; adding a
  tool is a new subclass, not an edit to existing code (Open/Closed). The pure
  numeric kernels stay as free functions the effects delegate to.
- Bridge split by concern into lumen_bridge_volume/segment/mesh.cpp sharing a
  private lumen_handle.hpp; the 410-line monolith (over the 400 cap) is gone and
  every file is now well under the limit. The bridge is pure marshalling again.

Tests:
- New SegTest groups for the Strategy effects (polymorphic apply through the base
  interface) and the SegmentEditor facade (undo round-trip, remove-clears-voxels).

Docs (new docs/engineering/, linked from README):
- ARCHITECTURE.md  - three layers, data flow, module map, "where do I fix X?".
- CPP_ONBOARDING.md - C++ idioms (RAII, smart pointers, headers, the bridge)
  explained for developers who do not write C++ daily.
- DESIGN_PATTERNS.md - the patterns in the code and a recipe for adding a new
  segmentation tool without touching existing logic.
```

feat(io): decode compressed DICOM + select largest series per folder
…
9fc8d83
```
Real-world series (e.g. clinical CT) ship JPEG/JPEG-LS/RLE-compressed pixel
data, which the loader previously rejected wholesale ('compressed or unsupported
pixel format'). Register DCMTK's JPEG/JPEG-LS/RLE decoders and decompress
encapsulated datasets to native LE before reading pixels; link the codec libs
(dcmjpeg/dcmjpls/charls/ijg) statically.

A folder also commonly holds more than one series (the CT plus a scout/dose
report at the same 512x512 dims), which the dimension lock can't separate and
which corrupts spacing/Z-order when merged. Group parsed slices by Series
Instance UID and keep only the largest series; guard against absent in-plane
spacing.

Verified on a 2668-file JPEG-Lossless CT: was unusable, now loads 1774 slices,
spacing 0.91/0.91/0.70 mm, HU [-1024, 3071]. Phantom + Meta/Seg/unit tests pass.
```
