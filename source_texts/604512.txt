Depends on: #83, #85
Goal
Deliver Phase 1 programmable rendering: keep gCanvas geometry/coverage/vertex semantics controlled by the renderer while allowing custom fragment/material behavior.
Conceptual usage:
```
Shader& effect = context.create_shader(asset);
Material& material = context.create_material(effect);

context.draw_image(x, y, w, h, image, material);
```
Initial effect domain
Support effects over existing gCanvas quads/content such as:
image filters
color grading
brightness/contrast/hue/saturation
procedural/noise fills
UV distortion/wave
transitions
custom mask/alpha operations
custom text/image/path coloring where compatible with coverage semantics
Contract
Define the renderer-provided fragment inputs clearly, e.g.:
local UV
source UV
canvas/framebuffer metrics
coverage/source color
material parameters/textures
Custom effects must not be able to corrupt gCanvas stencil/path ownership contracts.
Acceptance
at least one custom image effect renders identically enough for pixel-qualified OpenGL/OpenGLES/Vulkan tests
Android emulator runs the custom effect
clipping/stencil behavior remains correct
no custom vertex pipeline is required for Phase 1
