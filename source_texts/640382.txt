On current master (6ef3582), index_to_coord() called with a NeuroVol and a linear index fails:
```
library(neuroim2)
v <- read_vol(system.file("extdata", "mni_downsampled.nii.gz", package = "neuroim2"))
index_to_coord(v, 100L)
#> Error in trans(x) %*% t(cbind(grid[, 1:d], rep(1, nrow(grid)))) :
#>   non-conformable arguments
```
The same index works through the space after converting it to a grid coordinate:
```
grid_to_coord(space(v), arrayInd(100L, dim(v)))   # works
```
It looks like the NeuroVol method passes the volume (or an index vector) where the space's matrix path expects a grid matrix, so trans(x) and the grid end up with different dimensions.
Expected: index_to_coord(v, idx) returns the world (mm) coordinates of each linear index, the same as grid_to_coord(space(v), arrayInd(idx, dim(v))).
Found while building peak readouts for statistical maps (the peak voxel's index converted to mm).
