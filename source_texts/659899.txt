This is a master issue to keep track of the standardization work for tile sizes + also keep track of the coverage holes in tile size support across ops. The work will be divided into 4 phases.
Step 0 [Affects all ops]: Add the skeleton for the new TensorShape/TileShape/RowMajorShape wrappers, and initialize it once at kernel start for all 32 CircularBuffers, this initialization can happen in the hw_configure/compute_hw_startup function calls
Step 1 [Per each operation]: Pass this new TensorShape wrapper to all of the llk* functions per op where it is needed, remove all of the previous tile size descriptor flags such as num_faces, partial_face, etc. In tt_metal, LLK api wrappers need to change to pass in TensorShape.
llk_unpack_A.h
llk_unpack_AB.h ✅
llk_unpack_reduce.h ✅
llk_unpack_matmul.h
llk_unpack_tilize.h
llk_math_eltwise_unary_datacopy.h
llk_math_eltwise_binary.h ✅
llk_math_matmul.h
llk_math_reduce.h ✅
llk_pack.h
llk_pack_untilize.h
Step 2 [Per each operation]: For each llk operation, find all of the tile size coverage holes. Not every operation has full coverage for all of the following tile sizes: [1x32, 2x32, 4x32, 8x32, 16x32, 32x16, 32x32]. Either add explicit LLK_ASSERTs, or add the missing coverage if simple (eltwise binary for example just has a hardcoding that can be removed). Here is a list of all the different variations of the flags: https://docs.google.com/spreadsheets/d/1JcGOwGmLdT49i4sssr-tZamS1dtPOzk4hYXKOvAgurs/edit?usp=sharing

llk_unpack_tilize.h
llk_math_eltwise_unary_datacopy.h
llk_math_eltwise_binary.h ✅
llk_math_matmul.h
llk_math_reduce.h ✅
llk_pack.h
llk_pack_untilize.h
Step 3 [Per each operation]: Run a performance analysis to see how increasing tile shapes affects the BW of the operation, it is expected that smaller tile sizes should be causing operations to be more compute-bound, but that is often not the case due to partly the following issues: [WH/BH] Replay buffers + unpack instructions #816 [Blackhole] CFGSHIFTMASK instruction #55 Unpack 32x32 tiles #57 , etc. The hope is that in Step 2 while implementing some of the coverage holes, to also do some of these low hanging fruit issues

unpack reconfig geometry: [Wormhole/Blackhole] Math/pack/unpack LLK bugs and LLK test-coverage gaps #1702 item 2 (no PR yet)
Would you be OK with me taking these over? Most of these bugs come from the old flags being unclear. partial_face means "tile shorter than 32 rows", not "face shorter than 16 rows", and a flat num_faces == 2 can't tell 16x32 from 32x16. TensorShape carries that information directly, so the fix and the migration end up being the same change. It would also save us both from rebasing on top of each other in the same MOP code. I'd keep your tests and keep you as co-author on the commits. If you'd rather finish some of them yourself, that's fine too, just tell me which.
Two more things:
The first PRs are up as a stack: [LLK] Pass TensorShape to math unary datacopy (WH/BH) tt-metal#61645 (datacopy), [LLK] Pass TensorShape to unpack and math matmul (WH/BH) tt-metal#61665 (matmul), [LLK] unpack_A: assert tile shapes that are not supported (WH/BH) tt-metal#61640 (unpack_A broadcast). #61665 changes function signatures in the BH experimental/2_0 matmul files that your [LLK][BH] no-mop matmul: fall back to the unthrottled replay on non-full tiles; reject transpose with a 32x16 in1 tt-metal#61079 and [LLK][BH] 2.0 compute API: reject unsupported matmul/tilize shapes at compile time and keep the id-free pack Dst-capacity assert tt-metal#61129 also touch. It's signatures only, no logic, but whichever lands second will need a small rebase.
[Wormhole/Blackhole] Math/pack/unpack LLK bugs and LLK test-coverage gaps #1702 item 15 (within-face transpose with unpack-to-dest): #61640 adds the assert for it, so you can tick it off once that merges.

(Work in Progress) Plan for the FPU side (WH/BH)
There are two kinds of PRs here:
TensorShape PRs move one LLK to TensorShape. They don't change behaviour: shapes that work today keep working the same way, and shapes that don't work now hit an LLK_ASSERT.
Coverage PRs make more tile shapes work, each one with tests. Each goes in after the TensorShape PR for the same LLK, so the fix is written against TensorShape.
