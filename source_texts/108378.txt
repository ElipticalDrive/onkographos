What each feature adds
Gaussian splats: the GaussianSplat object and the SPLAT, KSPLAT, SPZ and splat PLY loaders #247 Gaussian splats: GaussianSplat, drawn by both rasterizers through shared arithmetic. Also the SPLAT, KSPLAT, SPZ and splat PLY loaders, the KHR_gaussian_splatting glTF extension, and GaussianSplatUtils. The renderer does not draw splats by itself: you call draw_gaussian_splat after render_into.
USD import: USDZLoader with the USDA and USDC parsers #248 USD import: reads USDA text, USDC crates (with LZ4 and integer compression) and USDZ archives. It composes layers, references, payloads and variants, and reads meshes, transforms, and UsdPreviewSurface materials and textures. This replaces the older, partial USD loader.
Lighting addons: SunLight, LightProbeGrid, IESSpotLight, ProjectorLight and ColorEnvironment #249 Lighting addons: SunLight with its two blended cascades, LightProbeGrid with its bake, lookup and helper, IESSpotLight, ProjectorLight and ColorEnvironment. They were checked against the r186 source.
Voxel global illumination (VXGI) #250 VXGI: voxelization, light injection, and cone tracing of occlusion and indirect light, on the host and in a new kernel module, render/gpu_vxgi.mojo.
More post-processing from r186's display nodes: upscaling, SSGI, screen-space shadows and OIT #251 More display nodes: FSR1, sharpen, TAAU, SSGI with the temporal reprojection and recurrent denoise, SSS, OIT, retro, CRT, radial blur, the bilateral and depth-aware blurs, and ImportanceSampledEnvironment.
The TSL function library: triplanar, sprite sheets, oscillators, curl and Voronoi noise, raymarching #252 TSL function library: triplanar mapping, sprite sheets, oscillators, noises, exact 32-bit hashes and bit packing, raymarching, soft particles and the GGX helpers. All of them are built on NodeGraph.
Compute nodes: ComputeNode, storage buffers and textures, atomics, and GPU sorts #253 Compute nodes: compute programs on the node bytecode over storage buffers and textures. They support barriers, workgroup arrays, atomics and subgroups, and run on the host and as a kernel. Also BitonicSort and CountingSort.
Procedural generators: city, forest, terrain and tree #254 Procedural generators: the city with its ten sub-generators, and the forest, terrain and tree generators, seeded as three.js seeds them.
Sculptor: sculpting tools on a mesh #255 Sculptor: all eight tools with adaptive topology. A stroke comes from a ray or from a pointer.
Geometry and helper leftovers: LoftGeometry, WireframeGeometry2, ClippingGroup and more #256 Leftovers: LoftGeometry, WireframeGeometry2, ClippingGroup on both backends, AnimationPathHelper, colors from a temperature in kelvin, AnimationLoader and CubeDepthTexture.
Three.js's node JSON: NodeLoader, NodeMaterialLoader and NodeObjectLoader #257 Node JSON: node materials saved by three.js are read into a NodeGraph and compiled.
Node material models: MeshSSSNodeMaterial and VolumeNodeMaterial #258 Node material models: MeshSSSNodeMaterial and VolumeNodeMaterial on both rasterizers.
Each wiki page lists what is not ported, under "What is not ported".
Shared layout changes
GPU vertex: 127 floats. LANE_VOLUME was added.
Directional light record: 15 floats. It now carries the cascade blend.
Light buffer: new spot-profile records and a probe-grid header.
Node kinds: 108 to 110 are new, for compute.
Node outputs: now 25.
Material kinds: VOLUME (12) is new.
Makefile: generators/ is added to the library sources. render/gpu_vxgi.mojo is a GPU library source, and COVERAGE_EXCLUDE is now $(GPU_LIB_SOURCES).
Checks
CI is green, including 100% line, branch and MC-DC coverage over every measured module.
Built: tests/test_gpu.mojo, bench/raster_bench.mojo and tools/gpu_status.mojo, all with --Werror --target-accelerator sm_80. No GPU was available, so the device parity tests have not run.
Fixes found on the way
Coverage instrumenter: it wraps each condition in a probe that takes a Bool. Conditions that tested an Optional directly are now converted with Bool(...), as helpers/arrow.mojo does.
Grid helper shader: the string in helpers/light_probe_grid.mojo now closes on the shader's last line. A line holding only the closing triple quote read as a docstring opening to the coverage scanner.
Scene optimizer: its material key now includes the volume step count, which main's new field check requires.
Coverage gaps: new tests close the gaps in the new modules. A few conditions that could never be false are removed, each with its reason in a comment. Loops that a check just above keeps from being empty carry the no-branch pragma.
TAAU: postprocessing/taau.mojo hit the second pattern in "The Mojo compiler hang": a FloatColor summed in two nested loops. That made every suite that imports the composer hang. It now sums Float32 values.

…Loader

three.js writes a node material as a list of nodes, each with its class,
its inputs and the fields its class serializes. This port wrote only its
own compiled program, so a node material made in three.js could not load.

loaders/node_loader.mojo reads that list into a NodeGraph: the value,
uniform, attribute, operator, math, select, swizzle, join, conversion,
facing, screen and texture node classes, each checked by NodeJsonType.
NodeLoader.material connects the material's inputNodes to the outputs,
converting each to its type and turning three.js's replacing normal and
position nodes into this port's offsets. read_object_json and
read_material_json now read *NodeMaterial types as the class they extend,
compile their graph, and set the texture and cube each texture node reads.

Port three.js's src/nodes/gpgpu compute nodes on the node bytecode. A
ComputeKernel keeps statements (stores, atomic functions and held
values) beside a NodeGraph; NodeGraph.compile_roots lays out their
roots and run_code runs them. A barrier ends a step, a read sees the
step's start plus the invocation's own stores, and workgroup arrays
hold one copy a workgroup. Subgroups are one invocation.

Both backends call run_statements on a ComputeSource: HostCompute on
the host, GpuCompute on the device with compare-and-swap atomics.
BitonicSort and CountingSort from examples/jsm/gpgpu run on either.

Merges the integration branch; the new node kinds are 108 to 110, so
the invalid-kind tests move to 111.

Closes #253
