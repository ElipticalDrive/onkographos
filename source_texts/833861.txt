What & why
Luxar scenes are composed in Python by design — the CLI's job is the other
half: turning a fitted splat set into the right renderable representation tree.
A scene-authoring review found the CLI couldn't build the two most useful
large-data gsplat topologies at all, and exposed LOD as three disconnected
subcommands. This unifies them and adds the missing topologies.
luxar gsplat lod is now one command driven by a required --recipe flag:
recipe
tree
scale
flat
single leaf
small
additive
one leaf + additive (prefix-sum) ladder
medium
partitioned
BSP kind=partition, each part with its own additive ladder
large
multiscale
unbalanced kind=lod: coarse substitutive cap + a partitioned fine branch
huge
substitutive / pyramid
the absorbed primitives
—
partitioned and multiscale were previously unbuildable from the CLI (the
old partition collapsed each part to a single level). multiscale is
unbalanced by design: a cheap coarse cap for the far view, deep partition→LOD
only on the fine branch — detail structure exists only where you look closely.
Design (avoids the god-file)
Pure builders in new gsplats/lod/recipes.py (GSplatData → GSplatNode): only
composes existing make_additive_lod / make_substitutive_lod /
make_lod_pyramid / to_spatial_partition — no new algorithms.
Thin CLI wrapper in new cli/lod.py (registered onto app_gsplat); removes
the ~700-line app_lod block from the 5.4k-line gsplat_commands.py (net -718).
stats→fitting_info extraction factored into save_gsplats.split_fitting_info,
shared by GSplatData.save and the composed-recipe write path (DRY).
Matrix recipes return GSplatData written via .save (byte-identical to the
absorbed subcommands); composed recipes write the node tree via write_gsplats_tree.
The .gsplats.zarr format and the Python builders are unchanged. Output stays a
standalone v3.0 .gsplats.zarr to graft into a scene via add_gsplats_from_file /
gsplat convert.
Behavior notes
--recipe is required (clear error listing the choices).
Options irrelevant to the chosen recipe are rejected (e.g. --max-elements
with --recipe additive), not silently ignored.
Auto recipe-selection by N is intentionally deferred (out of scope for v1).
Tests & gates
New gsplats/lod/tests/test_recipes.py — tree shape per recipe, splat-count
conservation, ladder-clamping on tiny parts, and an absorption regression
proving additive/substitutive/pyramid match the old builders.
Rewrote TestLODCommand — required-recipe, option-relevance, round-trip per
recipe, and the partitioned/multiscale on-disk trees.
Full suite: 3846 passed, 0 failed. ruff clean; mypy clean (242 files).
Propagation
Updated gsplat_commands.py, CLI tests, CLAUDE.md, cli/gsplats/gsplats/lod
READMEs, docs/api/gsplats.rst, docs/tutorials/gaussian_splatting.rst,
CHANGELOG.md, TODO.md, and scripts/add_additive_lod_to_demos.py. Also fixed
the stale gsplat convert help text (.zarr → .luxar.zarr).
Not gated (per plan)
The viewer rendering the multiscale lod→partition nesting is exercised by a
manual smoke (convert → serve); the serializer half is covered by round-trip
unit tests.

…d + multiscale topologies

Replace the three `gsplat lod additive|substitutive|pyramid` subcommands with a
single `luxar gsplat lod --recipe {flat,additive,partitioned,multiscale,
substitutive,pyramid}` command. `--recipe` is required; options irrelevant to
the chosen recipe are rejected with a clear error.

Two large-data topologies that were previously unbuildable from the CLI:
- partitioned: a spatial BSP `kind=partition` where each part carries its own
  additive ladder (the old `partition` collapsed parts to a single level).
- multiscale: an unbalanced-by-design `kind=lod` — a single coarse substitutive
  cap for the far view above a `partitioned` fine branch, so detail structure
  exists only where you look closely.

Organization (avoids the 5.4k-line `gsplat_commands.py` god file):
- Pure builders in new `gsplats/lod/recipes.py` (GSplatData -> GSplatNode; only
  composes the existing make_*_lod / to_spatial_partition; no new algorithms).
- Thin CLI wrapper in new `cli/lod.py` (registered onto app_gsplat); removes the
  ~700-line `app_lod` block from `gsplat_commands.py`.
- Extract the stats->fitting_info split into `save_gsplats.split_fitting_info`,
  shared by `GSplatData.save` and the composed-recipe write path (DRY).

Matrix recipes (flat/additive/substitutive/pyramid) return GSplatData written via
`.save` — byte-identical to the absorbed subcommands; composed recipes write the
node tree via `write_gsplats_tree`. The `.gsplats.zarr` format and the Python
builders are unchanged.

Tests: pure recipe-shape + conservation + absorption-regression tests
(`gsplats/lod/tests/test_recipes.py`) and rewritten CLI tests
(`TestLODCommand`) covering required-recipe, option-relevance, round-trip, and
the partitioned/multiscale on-disk trees. Docs propagated (CLAUDE.md, READMEs,
rst, CHANGELOG, TODO); `gsplat convert` help fixed to `.luxar.zarr`.

Deep-double-check pass 3 (multi-agent fan-out, fresh angles) surfaced 2 confirmed
minor issues; the fan-out also positively confirmed compress round-trip for
composed recipes, determinism, encoding-mode coverage, 40k-scale tree integrity,
and idempotency are all clean.

- `fitting/n_splats` was inherited verbatim from the source-fit stats, so for
  count-growing recipes (multiscale synthesises a coarse cap; substitutive
  synthesises representative levels) the persisted value was STALE and
  contradicted the file's own leaf arrays (e.g. fitting/n_splats=6000 while the
  leaves total 7495). Corrected at the single write chokepoint:
  write_gsplats_tree now overwrites fitting_info['n_splats'] with the true leaf
  total (total_splats(node)) — fixing both the new composed path and the
  pre-existing substitutive `.save` path uniformly. (n_splats means "count in
  this artifact" per fitting/results.py.)
- Out-of-range `--breakpoints` (`energy:1.5`, `counts:999999`) dumped a raw
  traceback. Now: energy fractions are range-checked to (0,1] and counts to
  positive at parse time (clean BadParameter, no N needed), and the N-dependent
  case (counts > N) is caught around build_recipe and re-raised as BadParameter
  — matching the command's clean-error style.

Regression tests added (all fail on pre-fix code, verified via baseline swap):
fitting/n_splats == true leaf total after a count-growing recipe; out-of-range
breakpoints error cleanly without a traceback.

…er (path escape)

Deep-double-check pass 4 (+creative) found a pre-existing tar.gz symlink-escape in
the compressed-archive loader: the tar.gz branch validated only `member.name`
(which resolves inside the temp dir) but never `member.linkname`/link type, then
`extractall` faithfully recreated a symlink — so a crafted archive (symlink `d` ->
/outside + file `d/x`) wrote arbitrary files outside the extraction dir. Reachable
from any command that loads a compressed input (`gsplat lod/convert/info/cull/...`),
including the new `gsplat lod --recipe`. (zip path is already safe — zipfile does
not recreate symlinks.)

Fix: a legitimate `.gsplats.zarr` archive contains only regular files and
directories, so reject any sym/hard-link member in the validation pre-loop —
before `extractall`, so a malicious archive cannot write a single byte. Keeps the
existing name-escape check; raises the same ValueError style.

Pre-existing (load_gsplats.py is unchanged at the branch base; folded into this PR
per request rather than a separate security PR). Regression test
`TestCompressedLoadSecurity::test_targz_symlink_escape_rejected` fails on the
pre-fix loader (writes outside the temp dir) and passes after (baseline-verified).
