Stacked on #17 (Flutter 3.47.7 + flame_3d 0.3.2). Retarget to main once #17 merges. This is step 3a of the flutter_scene plan. It adds no new behavior.
What changed
Rendering now goes through an engine-neutral port, app/lib/render/voxel_renderer.dart:
VoxelRenderer exposes chunk passes, voxel material controls, the target outline, block particles, first-person camera controls and per-frame counters.
ChunkPassFactory / ChunkPassHandle create and remove chunk passes. ChunkRenderManager keeps the revision, render-distance, retained-count and budget bookkeeping, but no longer touches engine types.
RendererInitializationException replaces flame_3d's GpuInitializationException in ShowcaseBootstrap. Startup guidance (e.g. "WebGPU is unavailable") still keys on the failure kind.
The flame_3d implementation moved to app/lib/render/flame3d/ with git mv. That covers PackedSurface, the voxel materials, TargetOutline, BlockParticlePool, packed primitives and the new Flame3dVoxelRenderer, Flame3dChunkPasses and Flame3dCameraControls.
MinedartGame stays a FlameGame3D host: Flame still owns the loop, lifecycle and input. It now builds Flame3dVoxelRenderer in onLoad and otherwise talks to the port. Outside the adapter directory, flame_3d is imported only for the host base class. test/render/renderer_boundary_test.dart enforces that. docs/architecture.md gains a "Rendering port" section.
The tests follow the split:
ChunkRenderManager and ChunkMeshCoordinator tests use a recording FakeChunkPasses instead of a real World3D.
The flame_3d-specific bounds checks moved to test/render/flame3d/flame3d_chunk_passes_test.dart.
The GPU failure mapping has its own test.
Validation (Flutter 3.47.7)
app: format check, flutter analyze, flutter test: 382 passed. Chrome suites (pointer lock, gzip): 8 passed.
bash tool/build_web_release.sh: passed.
Before/after on the same scene. Same live scene: seed 0x5eed, islands, RD 10, headless Chromium with SwiftShader WebGPU. Both builds carried the spike's temporary telemetry patch. Pre-refactor (build: move to Flutter 3.47.7 and flame_3d 0.3.2 #17) and this branch reported identical renderer state: 306 draws, 909 retained components, 100,997,720 retained mesh bytes. Neither build destroyed a GPU buffer. Frame timings were within noise.
Not covered
macOS / Metal was not run. The native path changes only where components are constructed.
In this headless setup the full game's 3D canvas does not appear in Playwright screenshots, before or after the refactor (only the sky and HUD). That is why the before/after comparison above relies on telemetry rather than pixels.
