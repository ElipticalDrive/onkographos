What
FilterDecimateVoxels served every decimate_method except FirstPoint from
PointCloudToVoxelGrid, which keeps the index list of every voxel. Building
those lists costs a second hashed pass over the cloud plus a relayout of the
whole index array, and walking them gathers x/y/z by index. The average-based
methods never need the list, only a summary of the voxel.
New PointCloudToVoxelGridAverage serves ClosestToAverage and
VoxelAverage. One hashed pass accumulates the per-voxel sums and records
which voxel each point fell into, so the second pass (needed only by
ClosestToAverage) finds the closest point to the average without hashing
again. Both passes read the coordinate buffers sequentially.
PointCloudToVoxelGridSingle (which serves FirstPoint) kept its three
members in std::optional, making voxel_t 56 bytes. It is the value type of
the hash map, so that size is paid once per input point. Storing the fields
bare brings it to 24 bytes.
RandomPoint still uses the index-list grid, unchanged.

Relative to FirstPoint, ClosestToAverage goes from 1.07-1.74x down to
1.02-1.42x, and VoxelAverage is now at or below it (0.74-1.06x) everywhere.
Output is unchanged
1280 scan/parameter combinations over both datasets (4 resolutions x both
average methods x minimum_points_per_voxel 0 and 3) produce byte-identical
output clouds, in the same order, as the point-list implementation.
test-mp2p_FilterDecimateVoxels now asserts that property directly against a
reference built from PointCloudToVoxelGrid's index lists. It includes
coordinates one ULP away from a voxel boundary at lidar-scale ranges: voxel keys
must keep dividing by the resolution, since multiplying by a precomputed
reciprocal puts such points in a different voxel whenever the resolution is not
a power of two. Verified that the test fails if that substitution is made.
All 136 tests pass.
API note
PointCloudToVoxelGridSingle::voxel_t no longer uses std::optional: test an
occupied voxel with pointCount != 0, and resolve the cloud a voxel refers to
with sourceCloud(vxl.sourceIdx). FilterDecimateVoxels was the only user in
this repo or the wider workspace.
Possible follow-up
RandomPoint is now the slowest method (1.33-1.67x FirstPoint), since it is
the only remaining user of the index-list grid in this filter. Reservoir
sampling would let it run on a single-entry grid too, but it would pick
different points than today, so it is left out of this PR.

…

```
Each decimate_method needs something different from a voxel, but all of
them except FirstPoint were served by PointCloudToVoxelGrid, which keeps
the index list of every voxel. Building those lists costs a second hashed
pass over the cloud plus a relayout of the whole index array, and walking
them gathers x/y/z by index. The average-based methods never need the
list itself, only a summary.

New PointCloudToVoxelGridAverage does that summary directly: one hashed
pass accumulates the per-voxel sums and records which voxel each point
fell into, so the second pass (only needed by ClosestToAverage) finds the
closest point to the average without hashing again, reading the
coordinate buffers sequentially in both passes.

PointCloudToVoxelGridSingle, which serves FirstPoint, kept its three
members in std::optional, making voxel_t 56 bytes. It is the value type
of the hash map, so that size is paid once per input point. Storing the
fields bare, with pointCount == 0 marking an empty voxel and the source
cloud referenced by a small index, brings it to 24 bytes.

Measured over 300 KITTI-00 and 300 Oxford Spires scans, per scan:

  ClosestToAverage  2.90 -> 2.21 ms (KITTI, 0.5 m), 1.67 -> 1.32 (Spires)
  VoxelAverage      2.51 -> 1.57 ms (KITTI, 0.5 m), 1.38 -> 0.93 (Spires)
  FirstPoint        3.85 -> 2.94 ms (KITTI, 0.25 m), 3.47 -> 2.48 (Spires)

Output is unchanged: 1280 scan/parameter combinations produce byte-identical
clouds, in the same order. The new test asserts that against the point-list
implementation, and covers coordinates one ULP away from a voxel boundary,
since voxel keys must keep dividing by the resolution: multiplying by a
precomputed reciprocal assigns such points to a different voxel whenever
the resolution is not a power of two.
```
