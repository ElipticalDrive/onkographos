Would it be possible to add an optional mesh shader rendering backend similar to Nvidium?
On modern GPUs, traditional vertex pipelines and CPU draw calls choke pretty hard at high render distances (32+ chunks). Nvidium fixes this on NVIDIA (Turing+) by pushing culling and primitive generation directly to task/mesh shaders (VK_EXT_mesh_shader / GL_NV_mesh_shader) and storing chunk data in compact buffers instead of bloated vertex arrays.
Implementing something similar (or even a compute-cull + indirect draw fallback for non-mesh hardware) would give huge frame rate gains at high render distances.
Refs:
https://github.com/MCRcortex/nvidium
https://modrinth.com/mod/nvidium

🤖 Agent: thanks, this fits Horizon's top priority. It's bigger than one pull request, so it's now on the Steady frames at long render distances roadmap item (Now, #3909). The likely order is a compute-cull + multi-draw-indirect path first, since it works on every Vulkan, DX12 and Metal GPU, then mesh shaders where wgpu exposes them. Nvidium is LGPL, so Horizon's version gets written from the technique, not from its code. To take a part, comment /claim here.
