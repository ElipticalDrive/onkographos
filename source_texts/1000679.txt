Summary
Adds two rendering bonuses that together fix a long-standing gap in our
direct-lighting path:
Ambient occlusion as a multiplicative pass on primary rays, with
cosine-weighted hemisphere sampling.
Universal Phong reflection model in AMaterial::brdf plus a
Principled BSDF direct-lighting override using Blinn-Phong +
Schlick, which repairs the bug where PointLight could not produce
highlights on Glossy/Glass/PrincipledMaterial (all three were
invisible-under-PointLight before).
Closes #
Changes
AO (bed83b1): new HemisphereSampler (thread_local mt19937,
cosine-weighted), AmbientOcclusionSettings on World, CFG parsing
in CFGSceneLoader, multiplicative AO factor on primary-ray radiance
in WhittedIntegrator::castRay. Disabled by default to keep existing
scenes pixel-identical.
Phong universal in AMaterial (e776882): two new pure virtuals
specularAlbedo() / shininess() on IMaterial. AMaterial stores
both with neutral defaults (0,0,0) and 1.0 and composes
diffuseAlbedo()/π + ks·max(0,R·V)^α inline. Integrator gate widened
to fire on diffuseAlbedo > 0 || specularAlbedo > 0.
Concrete materials (fb0d501): Diffuse, Textured, Glossy,
Glass all accept two optional ctor params and forward them to the
AMaterial base ctor. Defaults are no-op. Glass/Glossy ctor bodies
moved from .hpp to .cpp (R1 cleanup).
Factory parsing (23edfd3): each create*FromCfg reads optional
specular = {…} and shininess keys; parsePhongParams helper in
the anonymous namespace. PrincipledMaterial intentionally does
not expose CFG keys for Phong — it computes its own.
Principled override (4ec969d): PrincipledMaterial overrides
specularAlbedo() (Schlick F0 = lerp(0.04, baseColor, metallic)),
shininess() ((1 - roughness)^4 · 255 + 1, Karis 2013 mapping),
and brdf() (Lambert diffuse weighted by (1-metallic)*alpha +
Blinn-Phong specular via half-vector H = normalize(-L + V)).
scatter() is untouched — the indirect chain still drives
environment reflections.
Tests (f1622b0): 19 new cases in AMaterialBrdfTest (6),
PrincipledBrdfTest (8), and MaterialFactoryTest (5).
Type of Change
Bug fix (Principled invisible under PointLight)
New feature (AO + Phong universel)
Refactor (IMaterial contract widened, Glass/Glossy R1 cleanup)

fix(material): Principled direct-lighting BRDF (Blinn-Phong + Schlick)
…
4ec969d
```
PrincipledMaterial used to be invisible under PointLight when
metallic >= 1: diffuseAlbedo collapses to zero, the integrator
gate skipped it, and scatter() rays could never see a zero-volume
light source. Pure metal spheres rendered black where their
highlight should be.

The fix overrides three virtuals from the IMaterial contract:

- specularAlbedo(): Schlick F0 interpolated between the dielectric
  baseline (0.04) and baseColor by `metallic`.
- shininess(): roughness mapped to a Blinn-Phong exponent via
  `(1 - roughness)^4 * 255 + 1` (Karis 2013 mapping).
- brdf(): Lambert diffuse (weighted by (1 - metallic) * alpha) plus
  Blinn-Phong specular using the half-vector
  `H = normalize(-L + V)` and the Schlick F0 above.

scatter() is untouched — the stochastic metallic/Fresnel/transparent
sampling still drives indirect bounces and alpha transparency. The
override only fills the direct-lighting gap so primary PointLight
rays produce a deterministic, roughness-modulated highlight.

CFG schema for `principled` blocks is unchanged: the new specular
parameters are computed automatically from metallic, roughness, and
baseColor — Principled doesn't accept user-supplied `specular` or
`shininess` keys, which would double-count.

Tests: 352/352 pass (visible behaviour for non-Principled materials
remains identical; Principled tests are added in the next commit).
```

```
Three new test surfaces validate the refactoring:

AMaterialBrdfTest (6 cases) — uses a local TestableMaterial
subclass to exercise the universal Phong formula in
AMaterial::brdf:
- Neutral defaults produce a zero BRDF.
- ks=(0,0,0) reproduces pure Lambert.
- Reflection-vector alignment yields a unit Phong term.
- Out-of-cone geometry zeroes the specular contribution.
- High alpha narrows the highlight to a tight spike.
- Lambert + Phong compose linearly.

PrincipledBrdfTest (8 cases) — exercises the new
PrincipledMaterial overrides:
- specularAlbedo Schlick interpolation: pure metal returns
  baseColor, pure dielectric returns the 0.04 constant,
  metallic=0.5 linearly mixes.
- Roughness-to-shininess mapping: 0 -> 256, 1 -> 1.
- Pure mirror metal produces a deterministic highlight under
  PointLight (this is the regression fix).
- Full roughness collapses the Blinn-Phong term to a flat 1.
- Alpha proportionally scales the diffuse term, leaving the
  specular term untouched.

MaterialFactoryTest (5 new cases) — verifies CFG round-trip
of `specular`/`shininess` keys on Diffuse, Glossy, Glass and
Textured types, plus a negative test confirming neutral
defaults survive a CFG block without those keys.
```

fix(rendering): address PR review on AO + Phong refactor
…
95f5324
```
Five reviewer-flagged issues:

1. AMaterial::shininess validation. The constructor used to store
   `shininess` verbatim while the contract said "strictly positive".
   A zero exponent collapsed Phong to flat-ks-everywhere; a negative
   one blew up to infinity at zero-alignment. Now validated in the
   member initializer via a small `validateShininess` helper that
   throws `std::invalid_argument` on `shininess <= 0`. Bad CFG values
   surface as a parse-time error instead of silent NaN downstream.

2. AO settings clamping in `World::setAmbientOcclusion`. The setter
   accepted any input, so an out-of-range `intensity > 1` produced
   negative AO factors and `intensity < 0` brightened the image.
   Negative `radius` / `samples` were also accepted. The setter now
   clamps `intensity` to [0, 1], `radius` and `samples` to >= 0.
   Same single point of entry from CFG, builder, and tests.

3. `raytracer_integrator` link-time dependency. Adding the Logger
   member introduced a hidden dependency on `raytracer_helper` that
   the integrator CMake target did not declare. Now PUBLIC-linked so
   downstream consumers can link `raytracer_integrator` alone.

4. AO early return on `intensity <= 0`. With intensity at zero the
   factor was guaranteed to be 1.0 but the function still cast every
   hemisphere sample. The early-return gate now also checks
   `settings.intensity <= 0.0`, saving the full AO cost for a setting
   that is documented and tested as disabling darkening.

5. Integrator-level regression test. The PR shipped BRDF unit tests
   and factory parsing tests, but nothing exercised the path
   `WhittedIntegrator -> material.brdf -> PointLight highlight` for a
   specular-only material. Added
   `tests/rendering/WhittedIntegratorHighlightTest.cpp` with four
   cases: Glossy / Glass / Principled-metallic each produce a
   non-trivial radiance at the apex under a PointLight, and a fourth
   case that asserts the integrator gate fires on `specularAlbedo > 0`
   even when `diffuseAlbedo` is black.

Tests: 386 -> 390, all pass.
```

refactor(material): throw MaterialException instead of std::invalid_a…
…
1be720f

```
…rgument

The shininess validator in AMaterial used std::invalid_argument, which
sits outside the project's exception hierarchy. The rest of the codebase
defines a domain-specific subclass of raytracer::core::RaytracerException
per layer (ShadingException, RendererException, ImageException,
SceneLoaderException, etc.) so that a single catch site at the
application boundary handles every internal failure uniformly.

This commit follows that pattern:

- New `components/material/MaterialException.hpp` derives from
  `raytracer::core::RaytracerException` via the standard
  `using base::base` ctor inheritance.
- AMaterial::validateShininess now throws MaterialException with the
  same message format. The validation logic and contract are unchanged.

Tests: 390/390 still pass.
```

fix(rendering): include <algorithm> directly in HemisphereSampler.cpp
…
aeaca0d
```
`sampleCosineHemisphere` calls `std::max` but the translation unit
included only <cmath> and <random>. The build worked on macOS/libc++
through transitive includes, which is not portable — libstdc++ and MSVC
can drop those transitives at any point and break the build.

Added the explicit include. Audited the rest of the PR's TUs for the
same pattern; all other files that use std::max/std::min/std::clamp
already include <algorithm> directly.
```
