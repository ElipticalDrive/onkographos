Ports the find-exterior-faces.ts greedy meshing pipeline to a Rust WASM module for performance.
Rust crate (wasm/)
find_exterior_faces.rs — core face detection + greedy meshing
ambient_occlusion.rs — per-corner AO sampling
texture_coords.rs, mesh_arrays.rs, voxel_constants.rs — supporting data structures
lib.rs — wasm-bindgen API surface (WasmExteriorFacesFinder) + 12 unit tests mirroring the TS suite
TypeScript integration
find-exterior-faces-wasm.ts — wrapper matching the existing ExteriorFacesFinder interface, handles wasm init and data marshaling
chunk.ts — uses WASM finder when loaded, falls back to TS implementation seamlessly
```
const finder = isWasmReady() ? this.wasmFacesFinder : this.facesFinder;
finder.findExteriorFaces(voxelData, textureWidth, mapping, size, meshArrays, selectionFrame);
```
WASM init is fire-and-forget with a silent catch so it degrades gracefully in environments without fetch (e.g., Node/vitest).

Both produce identical output (same vertex/index counts).
The Rust native numbers represent roughly what you'd see from WASM in-browser — WASM typically runs within ~10-20% of native Rust performance. The polka dot worst case shows a ~3x speedup, and the solid cube shows a ~1.8x speedup. The actual browser WASM numbers will also include some data marshaling overhead for copying arrays across the JS/WASM boundary, but for large volumes the computation dominates.
