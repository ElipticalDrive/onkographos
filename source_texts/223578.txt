Closes #6869 (charter #6868). Third of three stacked PRs. It is based on #6875 (LOD selection), which is based on #6874 (COPC reader); review only the top commit.
What
A COPC file opened in the viewer streams octree nodes in and out with the camera. Resident points never exceed the budget (default 10 M, versus the old 25 M whole-file cap with stride thinning), at any file size.
One canonical load path. ingestPointCloud calls streamPointCloudOrCopc. For a LAS/LAZ blob it reads the first 589 bytes and takes the LOD path only when the first VLR is copc/info, so detection is by the VLR, not the name: the e2e opens the fixture as renamed-scan.las. Everything else streams exactly as before. Alignment, CRS, map units, federation relabel, visibility and lifecycle are the LAS/LAZ ones, because COPC is LAZ.
Renderer: removable chunks in one asset. Renderer.appendPointCloudChunk(handle, chunk, key) and removePointCloudChunk(handle, key), built on point-cloud-keyed-chunks.ts.
A keyed chunk gets its own snap index, because PointCloudSpatialIndex cannot remove. buildRayQuerySources emits one source per key, so measurement snapping covers exactly the resident nodes.
Draw, GPU picking and deviation iterate the asset's chunks. Crop box, section plane, colour modes, class mask and EDL are per-asset uniforms. All of them cover the resident nodes with no further change.
To stay inside the module-size budgets, the section-plane resolution moved into point-cloud-uniforms.ts; point-cloud-renderer.ts went from 473 to 465 lines and its allowlist row was lowered.
Residency (copcLodController.ts, pure and unit-tested):
The full-budget selection is the keep set. The pacer's passes (a time-boxed first pass, then the full budget) load missing hierarchy pages, then fetch missing nodes parents-first, 4 at a time.
Budget ceiling: room is made by LRU eviction outside the keep set, then from over-allocated keep nodes.
No holes: a view is retired only after a complete pass for the new one (shouldReplacePass).
A superseded update is aborted and its in-flight worker reads are cancelled (copc-cancel).
Strides are powers of two, so small budget shifts do not refetch.
Camera: an rAF watcher re-selects when the view-projection, the asset placement or the viewport has been still for 150 ms.
copcLodCamera.ts moves the camera into the decoded frame (viewProj · model · ZUP_TO_YUP) instead of re-boxing node bounds.
It folds the placement scale into orthographic spans. Autzen is in US feet, scale 0.3048, and is handled correctly.
Side channels (copcLodSink.ts):
The scan cache is fed once per coarse node (levels 0-2, an even subsample), so the section scan layer and alignment workbench keep a stable, representative sample.
The class histogram counts each node once, scaled by its stride (an estimate).
When a deviation run is live, each settled pass re-runs it (the BVH is cached).
Lifecycle: model removal and the superseded-load paths call stopCopcLodStream. The watcher also stops when the renderer is no longer ready (viewport torn down or device lost).
Diagnostics: __ifc_lite_render_stats__().pointCloudPoints and __ifc_lite_copc_lod__() are read-only hooks following the __ifc_lite_* convention.
Docs: docs/architecture/copc-lod-streaming.md.

Known gaps (follow-ups, not filed)
Software WebGPU: under SwiftShader, rendering millions of splats makes GPUQueue.writeBuffer block on GPU-process back-pressure. This was profiled: 53 s of blocked writeBuffer in a 40 s window, against 42 ms in insertRange. Hardware GPUs stream at full rate. A budget scaled to the adapter (e.g. lower on fallback adapters) would help.
No remote COPC in the viewer: the viewer opens COPC from a File only. HttpRangeSource exists in the reader, but there is no URL-source UI. The ?model= autoload downloads the whole file first (66 s for SoFi over localhost).
Fixed budget: the point budget is a constant (10 M), with no UI setting yet.
Bounds only grow: asset bounds only grow as nodes arrive, as for every streamed scan.
Last-model removal: removing the last model tears down the viewport before the point-cloud lifecycle runs. This is pre-existing for every scan. The COPC watcher stops itself via renderer.isReady().

Review fixes in a1a0be9, on the rebased stack (main 8dd47a0). Each fix began with a failing test, and reverting it makes that test fail again.
A camera move during a hierarchy page load no longer wipes the cloud. select treats a page-load rejection after an abort as superseded, and update resolves when aborted. In the host, only real failures stop the stream, through the ingest's onError. The old catch → stop → dispose is gone. Test: "a camera move during a hierarchy page load neither rejects nor wipes the cloud".
Fat eviction requeues. A keep-set node evicted as a last resort is requeued into the running pass at its share's stride. The reviewer's repro (budget 1,200, first pass 1,000, root + 8 children of 1,000 points) now settles on all 9 nodes at 1,125 points, root included. Test: "a fat keep-set node evicted to make room is reloaded at its share".
Incomplete passes. A pass is complete only if every selected node is resident at its stride or denser. An incomplete pass for a new view does not retire the old one, and it retries at most 3 times, 1 s apart, through an injectable scheduler. Tests: "an incomplete pass for a new view keeps the old view on screen", "a pass with a failed node … retries", "a node that never loads stops retrying after a bounded number of attempts".
Snap cost (measured). On a scratch benchmark (synthetic terrain octree, 400 rays, mean per queryPointClouds call), per-node sources cost about +0.5 ms. Most of that was the per-source matrix inverse: queryPointClouds now rewrites the ray once per placement matrix. After the change: 448 node indexes 2.00 ms vs one index of the same 1.36 M points 1.99 ms; 1,840 indexes 2.1 ms vs 1.7-1.9 ms. Hits are identical. A test guards that the cached rewrite is never reused across assets with different placements. GPU picking was not separately timed; it draws the same per-chunk buffers as rendering.
Gates as on #6874. COPC + LAZ e2e: 2 passed on the rebased build.

Merge-shepherd verification. #6874 merged as 9e5487b and #6875 as 2cb6753. This PR is rebased with --onto origin/main c6edeee75 and retargeted to main. The only conflict was playwright.config.ts, where both sides edited the e2e testMatch lists; I kept main's assistant-context and this PR's copc-lod.
Review findings 1, 3, 7 and 8 (fixed in a1a0be9). I read the fix diff, ran the repro tests, and mutation-checked each fix:
Finding 1, camera move during a page load. Two layers catch a superseded abort: select returns null, and update swallows an error once its own signal is aborted. Either one alone is sufficient, so reverting them one at a time survives. Reverting both fails a camera move during a hierarchy page load neither rejects nor wipes the cloud (unwanted rejection).
Finding 3, fat eviction requeue. Removing this.requeue?.(r.node) fails a fat keep-set node evicted to make room is reloaded at its share.
Finding 7, pass always complete. Forcing complete = true fails three tests: the retry test, an incomplete pass for a new view keeps the old view on screen, and the bounded-retry test. Removing the MAX_RETRIES bound fails a node that never loads stops retrying after a bounded number of attempts.
Spin check: retries are capped at 3 per non-retry update, and each is 1 s apart. A retry runs only while its epoch is current, so a camera move cancels the chain and restarts the count. update runs only on a settled camera change, never per frame. * perf(deviation): exact radix-select statistics in yielding slices, export lock restored (#6872)

The summary ran on the main thread in one block: 662 ms at the 25M point
cap on this machine, plus 165-184 ms per range-slider tick for the
histogram and 52 ms per tolerance keystroke, and the export recomputed
per-asset and pooled statistics synchronously on click.

Percentiles of |d| now come from a two-pass radix select on the float32
bit patterns (non-negative IEEE floats order like their bits): exact
nearest-rank, O(n) worst case, no scratch copy (about 1 MiB of count
tables instead of 4 B/point). The passes run in 8 ms slices that yield
through a MessageChannel and take an AbortSignal. Longest main-thread
task at 25M: 662 ms to under 10 ms; sync total 255-289 ms.

while exporting) is restored with its test, and an export whose readback
is invalidated mid-run is aborted. A readback that outlives its run is
dropped. The clip count compares against Math.fround(clipRange), since
the shader pegs in float32. The inclusive-tolerance test now uses
binary-exact values; f32(0.01) < 0.01 could not tell <= from <.
