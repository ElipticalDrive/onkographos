2. Problem Statement — Why ADC Fails
The original 3DGS Adaptive Density Control (ADC) decides clone/split based on positional gradient magnitude τ_k. This has three critical limitations:
Blind to absolute error: A region covered by few large Gaussians over high-frequency patterns (e.g., grass, gravel) produces near-zero gradients — densification never triggers despite high reconstruction error.
Non-intuitive thresholds: Gradient magnitude thresholds are sensitive to model changes, loss terms, and hyperparameters.
Uncontrolled growth: No mechanism to limit total primitive count → out-of-memory in resource-constrained settings (especially SLAM).
2.1 Illustration: Why gradient ≈ 0 even when error is high
Consider a region of grass covered by two large Gaussians:
```
  Ground Truth (high-frequency)          3DGS Reconstruction (blurry)
  ┌─────────────────────────┐            ┌─────────────────────────┐
  │▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓│            │                         │
  │▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒│            │    ╭──── G_A ────╮      │
  │▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓│            │    │  (large,     │      │
  │▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒│            │    │   blurry)    │      │
  │▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓│            │    ╰─────────────╯      │
  │▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒│            │         ╭── G_B ──╮    │
  │▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓▒▓│            │         │ (large)  │    │
  └─────────────────────────┘            └─────────╰──────────╯────┘
        Per-pixel error = HIGH                 Only 2 Gaussians
```
Step-by-step failure of ADC:
```
  Step 1: Error is HIGH at every pixel
  ┌──────────────────────────────────────────────────────────────────┐
  │  |GT(u) - Render(u)| is large at every pixel in the grass       │
  │  because 2 blurry Gaussians cannot reproduce checkerboard       │
  └──────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
  Step 2: But when we shift μ_k slightly...
  ┌──────────────────────────────────────────────────────────────────┐
  │  G_A covers a HUGE area. Shifting μ_A by δ barely changes       │
  │  which pixels it covers → rendered image almost identical        │
  │                                                                  │
  │  Before shift:  ╭──── G_A ────╮     After shift: ╭──── G_A ───╮ │
  │                 │     •μ      │                   │     •→μ'   │ │
  │                 ╰─────────────╯                   ╰────────────╯ │
  │                                                                  │
  │  ΔL ≈ 0  →  ∂L/∂μ_A ≈ 0  →  τ_A ≈ 0                           │
  └──────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
  Step 3: ADC checks τ_A against threshold
  ┌──────────────────────────────────────────────────────────────────┐
  │  τ_A ≈ 0  <  threshold (0.0002)                                 │
  │                                                                  │
  │  ⚠ ADC decision: DO NOT densify                                  │
  │  ⚠ Grass stays blurry FOREVER                                    │
  │                                                                  │
  │  KEY INSIGHT: gradient measures SENSITIVITY (how error changes   │
  │  when μ moves), NOT absolute error.                              │
  │  High error + low sensitivity = ADC is blind.                    │
  │                                                                  │
  │  Rota Bulò proved: even with 10M primitives, the flowers scene  │
  │  stays blurry because gradient never triggers densification.     │
  └──────────────────────────────────────────────────────────────────┘
```
Our work (TriaGS + Photo-SLAM) faces the same problems, compounded by the online, sequential nature of SLAM where primitives must be managed incrementally.
3. Paper 1: Revising Densification (Rota Bulò et al.)
3.1 Core idea — Error redistribution to per-Gaussian scores
Instead of gradient τ_k, they directly use pixel reconstruction error to decide which Gaussians need densification.
Problem: Error is per-pixel, but densification decisions are per-Gaussian. How to convert?
Solution: Redistribute pixel errors to Gaussians proportionally to their alpha-compositing weight ω_k^π(u).
```
  PIXEL SPACE                              GAUSSIAN SPACE
  ┌─────────────────────┐                  
  │ Error map E_π(u)    │                  
  │ ┌───┬───┬───┬───┐   │     Redistribute     ┌─────────────────┐
  │ │0.1│0.3│0.2│0.1│   │  ──────────────────►  │  G_A:  E_A = ?  │
  │ ├───┼───┼───┼───┤   │                       │  G_B:  E_B = ?  │
  │ │0.2│0.9│0.8│0.3│   │     Using weights     │  G_C:  E_C = ?  │
  │ ├───┼───┼───┼───┤   │     ω_k^π(u)          └─────────────────┘
  │ │0.3│0.8│0.7│0.2│   │                  
  │ ├───┼───┼───┼───┤   │                  
  │ │0.1│0.2│0.3│0.1│   │                  
  │ └───┴───┴───┴───┘   │                  
  └─────────────────────┘                  
```
Detailed computation:
```
  For Gaussian G_A with weights ω_A^π(u) at each pixel:
  
  Error map E_π(u):          Weights ω_A^π(u):           Contribution:
  ┌────┬────┬────┬────┐      ┌────┬────┬────┬────┐       
  │0.1 │0.3 │0.2 │0.1 │      │0.8 │0.5 │0.1 │0.0 │      E_A^π = Σ_u E(u)·ω_A(u)
  ├────┼────┼────┼────┤      ├────┼────┼────┼────┤       
  │0.2 │0.9 │0.8 │0.3 │  ×   │0.9 │0.7 │0.2 │0.0 │      = 0.1×0.8 + 0.3×0.5 + ...
  ├────┼────┼────┼────┤      ├────┼────┼────┼────┤         + 0.2×0.9 + 0.9×0.7 + ...
  │0.3 │0.8 │0.7 │0.2 │      │0.7 │0.5 │0.1 │0.0 │      
  ├────┼────┼────┼────┤      ├────┼────┼────┼────┤      = 2.14 (HIGH → densify!)
  │0.1 │0.2 │0.3 │0.1 │      │0.3 │0.2 │0.0 │0.0 │       
  └────┴────┴────┴────┘      └────┴────┴────┴────┘       

  Then: E_A = max over all views π ∈ Π of E_A^π
  
  ┌───────────────────────────────────────────────────────┐
  │  View 1: E_A^1 = 2.14                                │
  │  View 2: E_A^2 = 1.87                                │
  │  View 3: E_A^3 = 3.05  ← max                        │
  │  ...                                                  │
  │  E_A = max(2.14, 1.87, 3.05, ...) = 3.05             │
  │                                                       │
  │  If E_A > threshold (0.1 on SSIM scale):              │
  │  → DENSIFY G_A                                        │
  │                                                       │
  │  Advantage: threshold 0.1 is intuitive (SSIM scale)   │
  │  vs ADC's 0.0002 (gradient magnitude — what unit?)    │
  └───────────────────────────────────────────────────────┘
```
3.2 Implementation trick — Auxiliary loss for free per-Gaussian error
This is the most elegant part. They compute E_k^π without modifying the rasterizer, using only the existing backward pass:
```
  ┌─────────────────────────────────────────────────────────────────┐
  │  SETUP                                                          │
  │  ------                                                         │
  │  For each Gaussian G_k, attach a NEW scalar parameter e_k = 0  │
  │  Define a new decoder: Φ_ERR(G_k, u) := e_k                    │
  │  This means: render e_k using same alpha-compositing as color   │
  │                                                                 │
  │  rendered_e(u) = Σ_k  e_k · ω_k^π(u)                           │
  │                                                                 │
  │  Since all e_k = 0:  rendered_e(u) = 0 for all pixels           │
  └─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │  AUXILIARY LOSS                                                  │
  │  --------------                                                  │
  │  L_aux = Σ_u  stop_grad[E_π(u)] · rendered_e(u)                │
  │                                                                 │
  │  stop_grad means: treat E_π(u) as a CONSTANT (no gradient       │
  │  flows through it). Only e_k receives gradient.                 │
  │                                                                 │
  │  Since rendered_e = 0:  L_aux = 0                               │
  │  → Does NOT affect training at all!                             │
  │  → No change to any other Gaussian parameter!                   │
  └─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │  THE MAGIC: Gradient of L_aux w.r.t. e_k                       │
  │  ────────────────────────────────────────                       │
  │                                                                 │
  │  ∂L_aux     ∂                                                   │
  │  ────── = ────  Σ_u  E_π(u) · Σ_j e_j · ω_j^π(u)              │
  │  ∂e_k     ∂e_k                                                 │
  │                                                                 │
  │         = Σ_u  E_π(u) · ω_k^π(u)                               │
  │                                                                 │
  │         = E_k^π    ← This is EXACTLY the per-Gaussian error!    │
  │                                                                 │
  │  RESULT: Just read the gradient of e_k after backward pass.     │
  │  No custom CUDA kernel. No rasterizer changes. Brilliant.       │
  └─────────────────────────────────────────────────────────────────┘
```
3.3 Opacity correction after cloning
When a Gaussian with opacity α is cloned (duplicated at same position), the alpha-compositing is affected:
```
  BEFORE CLONING                    AFTER CLONING (no fix)
  ═══════════════                   ══════════════════════
                                    
  Ray → [G_A (α)] → rest            Ray → [G_A (α)] → [G_A' (α)] → rest
          │                                   │            │
          │ weight for G_A: α                 │            │
          │ weight for rest: (1−α)            │            │
          ▼                                   │ weight for G_A:  α
                                              │ weight for G_A': α(1−α)
  Example α = 0.7:                            │ weight for rest: (1−α)² 
  G_A gets 0.7                                ▼
  rest gets 0.3                    
                                    Example α = 0.7:
                                    G_A  gets 0.70      
                                    G_A' gets 0.21    (= 0.7 × 0.3)
                                    rest gets  0.09   (= 0.3²)  ← was 0.30!
                                    
                                    ⚠ rest weight dropped from 0.30 → 0.09
                                    ⚠ Cloned region now dominates rendering
                                    ⚠ Other Gaussians behind are suppressed

  ─────────────────────────────────────────────────────────────────────

  AFTER CLONING (WITH FIX)
  ════════════════════════
  
  Find α̂ such that: (1−α̂)² = (1−α)
  Solution: α̂ = 1 − √(1−α)
  
  Example α = 0.7:
  α̂ = 1 − √0.3 = 1 − 0.5477 = 0.4523
  
  Ray → [G_A (0.45)] → [G_A' (0.45)] → rest
  
  G_A  gets 0.4523
  G_A' gets 0.4523 × (1−0.4523) = 0.2477
  rest gets  (1−0.4523)² = 0.3000  ← exactly same as before! ✓
  
  ┌──────────────────────────────────────────────────┐
  │  FORMULA:  α̂ = 1 − √(1 − α)                     │
  │                                                    │
  │  Proof:  (1 − α̂)² = (√(1−α))² = 1−α      ✓      │
  │                                                    │
  │  This is ONLY for clone. Split moves offspring     │
  │  away from center → different geometry → keep α.   │
  │                                                    │
  │  Impact: LARGEST single improvement in ablation    │
  │  (Table 4 of paper). Free to implement.            │
  └──────────────────────────────────────────────────┘
```

4. Paper 2: ConeGS (Baranowski et al.)
4.1 Core idea — Replace clone/split entirely
Instead of cloning existing Gaussians (which limits exploration to vicinity of current geometry), ConeGS:
Uses a fast iNGP model as depth proxy
Identifies high-error pixels
Places NEW Gaussians at estimated depth
Sizes them to match the pixel's viewing cone
4.2 Pipeline illustration
```
  ┌──────────────────────────────────────────────────────────────────┐
  │  PHASE 1: Initialization (once)                                  │
  │                                                                  │
  │  Training images ──► Train iNGP (20k iter, ~1.6 min)            │
  │                          │                                       │
  │                          ▼                                       │
  │  Sample 1M random pixels from training set                      │
  │       │                                                          │
  │       ├── For each pixel (I, u, v):                              │
  │       │     ray = camera_center + t · direction(u,v)             │
  │       │     query iNGP along ray → transmittance τ_k             │
  │       │     t_med = depth where τ crosses 0.5                    │
  │       │     Gaussian center = camera + t_med · direction         │
  │       │     Gaussian scale = kNN of 3 nearest neighbors          │
  │       │     opacity = 0.1, color from iNGP                      │
  │       │                                                          │
  │       ▼                                                          │
  │  Initial scene: 1M Gaussians uniformly covering visible surfaces │
  └──────────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │  PHASE 2: Optimization with error-guided densification           │
  │  (30k iterations, densification active for first 25k)            │
  │                                                                  │
  │  Every iteration:                                                │
  │  ┌────────────────────────────────────────────────┐              │
  │  │ 1. Render image I with current Gaussians       │              │
  │  │ 2. Compute L1 error: E(p) = |I(p) − I*(p)|    │              │
  │  │ 3. Sample N pixels ~ Multinomial(E/ΣE)         │              │
  │  │    (high error → high probability of selection) │              │
  │  │ 4. For each sampled pixel:                      │              │
  │  │    • Shoot ray through pixel                    │              │
  │  │    • Query iNGP → get median depth t_med        │              │
  │  │    • Create Gaussian at ray(t_med)              │              │
  │  │    • Scale = 2 · r_cone(t_med)  ← PIXEL CONE   │              │
  │  │ 5. Accumulate new Gaussians in buffer           │              │
  │  └────────────────────────────────────────────────┘              │
  │                                                                  │
  │  Every 100 iterations:                                           │
  │  ┌────────────────────────────────────────────────┐              │
  │  │ 1. Prune: remove Gaussians with opacity < 0.005│              │
  │  │ 2. Merge accumulated buffer into scene          │              │
  │  │ 3. Joint optimization continues                 │              │
  │  └────────────────────────────────────────────────┘              │
  └──────────────────────────────────────────────────────────────────┘
```
4.3 Pixel-cone scaling — Detailed explanation
This is inspired by Mip-NeRF's cone casting. Each pixel defines a cone in 3D:
```
  SIDE VIEW: One pixel's viewing cone
  
  Camera ──────────────────────────────────────────► depth
    •╲                                                
    │ ╲  ←── cone edge                               
    │  ╲                                              
    │   ╲        r_cone(t)                            
    │    ╲──────────┤                                 
    │     ●═════════● New Gaussian                    
    │    ╱──────────┤ (diameter = 2·r_cone)           
    │   ╱                                             
    │  ╱                                              
    │ ╱  ←── cone edge                               
    •╱                                                
  Camera                                              
  
  
  r_cone(t) = t × (‖d_x − d‖ + ‖d_y − d‖) / 2
  
  Where:
  • t = depth along ray
  • d = ray direction through pixel center
  • d_x, d_y = ray directions through neighboring pixels
  • The term (‖d_x − d‖ + ‖d_y − d‖)/2 ≈ pixel angular width
  
  Gaussian scale:  s_i = 2 · r_cone(t_med)
  (λ_scale = 2 converts radius to diameter)
  
  
  WHY THIS IS GOOD:
  ┌────────────────────────────────────────────────────────────────┐
  │                                                                │
  │  CLOSE object (small t):                                       │
  │    r_cone small → small Gaussian → captures fine detail        │
  │    ╭─╮                                                         │
  │    │●│ ← pixel-sized, can represent sharp edges                │
  │    ╰─╯                                                         │
  │                                                                │
  │  FAR object (large t):                                         │
  │    r_cone large → large Gaussian → less detail needed          │
  │    ╭───────╮                                                   │
  │    │       │                                                   │
  │    │   ●   │ ← covers more area, fewer Gaussians needed        │
  │    │       │                                                   │
  │    ╰───────╯                                                   │
  │                                                                │
  │  This is EXACTLY the right inductive bias!                     │
  │  Same principle as Mip-NeRF's anti-aliasing cone integration.  │
  └────────────────────────────────────────────────────────────────┘
```
4.4 Why ConeGS beats cloning — Exploration capability
```
  CLONING (3DGS, MCMC, etc.)              ConeGS
  ═════════════════════════               ═══════
  
  Clone creates new Gaussian              ConeGS places Gaussian 
  NEAR the parent:                        ANYWHERE there's error:
  
       ╭─── G_A ───╮                     Error map:
       │            │                     ┌──────────────────┐
       │  •───→•    │                     │ ░░░░▓▓▓▓▓▓░░░░░ │
       │  parent→clone                    │ ░░░░▓▓▓▓▓▓░░░░░ │
       ╰────────────╯                     │ ░░░░░░░░░░░░░░░ │
                                          │ ▓▓▓▓▓▓▓░░░░░░░░ │ ← high error here
       Problem: if no Gaussian            │ ▓▓▓▓▓▓▓░░░░░░░░ │
       exists in a region,                └──────────────────┘
       cloning CAN'T reach it.                    │
                                                  ▼
       Empty region with no                New Gaussians placed
       Gaussians nearby:                   directly in high-error
       ┌────────────────┐                  regions, regardless of
       │                │                  where existing Gaussians are.
       │   (nothing)    │                  
       │    ← cloning   │                  ╭●╮  ╭●╮  ╭●╮
       │    can't help   │                  ╰─╯  ╰─╯  ╰─╯ ← pixel-cone sized
       │                │                  
       └────────────────┘                  

  This is why ConeGS excels at LOW primitive budgets:
  Every Gaussian is placed where it matters most.
  
  At 100k Gaussians on Mip-NeRF 360:
  ┌──────────────────────────────────────┐
  │  3DGS:    23.61 PSNR  (wastes many   │
  │            Gaussians in easy areas)   │
  │  MCMC:    27.06 PSNR                 │
  │  ConeGS:  27.74 PSNR  (+4.13 over   │
  │            3DGS with same budget!)    │
  └──────────────────────────────────────┘
```
4.5 Opacity penalty comparison
```
  3DGS original:       Hard opacity reset every N iterations
                       ┌───────────────────────────────────┐
                       │ α_k ← 0.01 for ALL Gaussians     │
                       │ → training shock, misleading error│
                       └───────────────────────────────────┘

  Rota Bulò:           Gradual opacity decrease
                       ┌───────────────────────────────────┐
                       │ α_k ← α_k − 0.001 per densify    │
                       │ → smoother, but constant push     │
                       └───────────────────────────────────┘

  MCMC:                Post-activation penalty
                       ┌───────────────────────────────────┐
                       │ L_o = ‖σ(o_pre)‖₁                 │
                       │ Gradient: σ(o)(1−σ(o))             │
                       │ → strongest at σ(o)=0.5            │
                       │ → WEAK near 0 (pruning threshold!) │
                       │                                    │
                       │  gradient                          │
                       │  ▲                                 │
                       │  │    ╭──╮                         │
                       │  │   ╱    ╲                        │
                       │  │  ╱      ╲                       │
                       │  │─╱────────╲──► opacity           │
                       │  0   0.5    1.0                    │
                       │    weak↑      ↑weak                │
                       └───────────────────────────────────┘

  ConeGS:              Pre-activation penalty (BETTER)
                       ┌───────────────────────────────────┐
                       │ L_o = λ_o · ‖o_pre‖₁  (λ=0.0002) │
                       │ Gradient: λ_o · sign(o_pre)        │
                       │ → CONSTANT across full range       │
                       │ → effective at pushing low-opacity  │

6. Direct Implications for Our Research
6.1 Immediately Adoptable Techniques
A. Opacity correction after cloning (zero-cost improvement)
```
# Before: clone preserves opacity
alpha_new = alpha_original

# After: corrected opacity  (1 line of code!)
alpha_new = 1 - sqrt(1 - alpha_original)

# Example: alpha = 0.7  →  alpha_new = 0.4523
# Rest weight preserved: (1-0.4523)^2 = 0.30 = (1-0.7) ✓
```
No architectural change required. Largest single improvement in Rota Bulò's ablation (Table 4).
B. Pixel-cone sizing for dense initialization
Our dense initialization from triangulation gives 3D position but needs a principled scale. Currently using k-NN (expensive, outlier-sensitive). With SLAM, we already have camera intrinsics and depth:
```
# For each newly triangulated Gaussian at depth d_i:
pixel_angular_width = 1.0 / focal_length   # approximation
r_cone = d_i * pixel_angular_width
s_i = 2 * r_cone                           # diameter = 2 × radius

# Advantages over k-NN:
# • O(1) per Gaussian vs O(N log N) for k-NN
# • Independent of other Gaussians' distribution
# • Principled: matches pixel footprint at that depth
# • No outlier sensitivity
```
C. Growth control / budgeting
Essential for SLAM:
```
# Option 1: Rota Bulò style — cap at X% growth
max_new = 0.05 * current_count              # 5% per step
if candidates > max_new:
    keep top max_new by confidence score     # rank and cut

# Option 2: ConeGS style — balance add/prune
N_sample = max(0.2 * N_GS, 1.2 * N_last) / 100
# Keeps count stable near budget even under aggressive pruning
```

  (all views available upfront)           (sliding window of last W keyframes)
  
  ┌─────────────────────────┐            ┌─────────────────────────┐
  │ View 1   View 2   ...   │            │ KF_t  KF_{t-1} KF_{t-2}│

  │                         │            │                         │
  │ E_k = max(all)          │            │ E_k = max(window W)    │
  └─────────────────────────┘            └─────────────────────────┘
  
  Also: auxiliary loss trick works with ANY differentiable renderer
  → compatible with Photo-SLAM's Gaussian rasterizer
```

9. Open Questions for Discussion
Should we fully replace clone/split (ConeGS approach) or improve it (Rota Bulò approach)?
ConeGS shows clone/split can be removed entirely with good initialization + error-guided placement
But in SLAM, clone/split may still be useful for quick local refinement between keyframes
Proposal: use error-guided placement as PRIMARY, keep split as SECONDARY for large Gaussians
How to define confidence score that combines triangulation quality + photometric error?
Option A: Weighted combination → simple but needs tuning
Option B: Use triangulation confidence for position, photometric error for densification priority → cleaner separation
Option C: Triangulation parallax angle as confidence for position quality, then Rota Bulò's error redistribution for when to trigger densification
Experimental validation plan:
Ablate each adopted technique independently (as Rota Bulò does in Table 4)
Compare on TUM RGB-D and Replica: our method vs. Photo-SLAM baseline vs. Photo-SLAM + individual improvements
Report PSNR, SSIM, LPIPS, ATE, and primitive count
Critical: show improvement at FIXED primitive budget (like ConeGS's strong result at 100k)
