Issue body actions
Identify sprites by their position in a uniform atlas grid and calculate their source texture coordinates in the vertex shader. This would remove the per-sprite rectangle lookup texture and the code that prepares, uploads, binds, and restores it.
The editor's atlas now consists of 128 glyph cells plus one solid fill cell, all with the active font's shared dimensions, arranged in 16 columns. Its background is rendered separately. The current vertex shader still fetches each source rectangle from u_spriteRectangles; the regular layout makes that lookup redundant.
Proposed behavior
Define GPU sprite IDs as zero-based, row-major atlas-cell indices. For example, with 16 columns, cell 17 is column 1, row 1; the editor's fill cell 128 is column 0, row 8.
Configure the shared cell dimensions and column count when installing the atlas. Validate grid dimensions and cell count on this cold path, including a partially populated final row.
Derive the source coordinates once per vertex:
```
uint cellId = a_spriteAndPalette.x;
uvec2 cell = uvec2(cellId % u_columns, cellId / u_columns);
vec2 atlasPixel = (vec2(cell) + corner) * u_cellSize;
v_textureCoordinate = atlasPixel / u_atlasSize;
```
Pass the resulting UVs to the fragment shader through normal interpolation. The fragment shader retains its existing mask sampling and palette behavior.
Address the solid fill with the same grid formula. Its destination rectangle can still have arbitrary dimensions; atlas-cell coordinates and destination dimensions are independent.
Remove the GPU rectangle lookup sampler, texture, upload, binding, and release/restore bookkeeping. Remove CPU per-cell source rectangles where the grid contract makes them unnecessary.
Make identifier semantics explicit in the public API. The current atlas preparation assigns dense IDs from lookup-entry order; those IDs must not silently be treated as grid positions. If public string/number identifiers remain, resolve them to the actual cell index at installation time.
Document that atlas cells have uniform dimensions and row-major placement, including the implications for callers using arbitrary packed source rectangles.
Scope and expected benefits
The main simplification is eliminating a metadata texture and its lifecycle, plus replacing a vertex texture fetch with a small coordinate calculation. A GPU speedup is not established: the current table contains only 1,032 bytes of texel data for 129 entries and may already be efficiently cached.
This is separate from #32, which skips glyph destination-size lookups and instance writes. The benchmarks in #32 retained the rectangle lookup texture, so their CPU improvements must not be attributed to grid addressing. The two changes can be combined after measuring them independently.
This is also an alternative to #26's proposal to precompute UV rectangles while retaining a lookup texture. Keep the fragment behavior from #30/#31 consistent between benchmark variants.
Validation and measurement
Verify all 128 glyph cells and the fill across all supported fonts, including odd cell widths, control-character glyphs, spaces, the fallback glyph, and the last populated atlas row.
Check source-texel boundaries and nearest-neighbor sampling with exact image comparisons. Include clipped glyphs, interleaved fills of different sizes, translucent/transparent palette entries, and opaque/transparent destinations.
Cover atlas/font replacement, resizing, resource release/restore, and state restoration after trusted raw WebGL hooks.
Keep destination-size handling, palette storage, mask format, discard/blending behavior, the 20-byte instance layout, insertion order, and draw-call count constant while comparing grid addressing with rectangle lookup. Test Skip per-glyph size lookups and instance writes for fixed-size glyphs #32's size optimization separately before a combined measurement.
Measure warmed GPU draw time separately from CPU submission and atlas setup. Use sequential GPU timer queries, identical controls, repeated paired comparisons, and reject disjoint/drifting samples. Include representative editor content and larger mixed glyph/fill batches.
Record texture storage, bindings, and code/lifecycle simplification alongside timing results. A performance-neutral result may still justify the simpler uniform-grid contract; record any regression and the tradeoff explicitly.
Run the package build, typecheck, unit tests, and screenshot regressions for the implementation.
Issue relationships
Complementary to Skip per-glyph size lookups and instance writes for fixed-size glyphs #32, with no blocking dependency in either direction. Shared cell dimensions can serve both changes, but grid addressing does not require skipped size writes, and skipped size writes do not require removing the rectangle lookup.
Alternative to Investigate precomputing sprite UV rectangles at atlas installation #26: this issue removes the rectangle lookup using a uniform grid; Investigate precomputing sprite UV rectangles at atlas installation #26 retains a lookup and precomputes UV rectangles for arbitrary source layouts. Compare their contract and timing tradeoffs before choosing the production approach. Neither is a prerequisite for the other.
Related independent fragment changes: Discard fully transparent sprite fragments to reduce GPU draw time #30 and Make sprite atlases explicitly binary and simplify fragment color output #31. Hold their behavior constant while measuring source-coordinate calculation.
