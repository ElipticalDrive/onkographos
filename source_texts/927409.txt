Players joining a server see an endless flat empty expanse. The server generates and streams terrain correctly, but the client discards all received chunk data and never refreshes the world map after initial (empty) construction.
Three broken links in the pipeline:
handleChunkData was a no-op stub (sync.go) — Received ChunkData messages were logged and discarded. Now stores them via Manager.StoreNetworkChunk() and invalidates the LOD cache.
rebuildWorldMap skipped all non-ready chunks (main.go) — The !ok guard on GetChunkLODAsync treated placeholders as errors, leaving the entire WorldMap at zero. Placeholders are now sampled as temporary terrain.
updateChunkMap never re-evaluated (main.go) — World map only rebuilt on chunk boundary crossings. Added chunksPending tracking and HasNewChunks() dirty flag so rebuilds fire when async workers or the network deliver real chunks.
New StoreNetworkChunk on chunk.Manager converts network-format data (uint16 heights, uint8 biomes) back into a full Chunk using the same helpers as local generation:
```

    // Stores in loaded map and clears any pending async generation

```
StateSynchronizer now takes chunkManager and lodManager references to close the integration gap. Chunk receipt logging is throttled (first chunk + every 10th) to avoid high log volume during streaming.
Unit tests added for StoreNetworkChunk: round-trip payload verification (elevation curve, wall height range), chunk size mismatch rejection, and incomplete data handling.

Pull request overview
This PR fixes the client-side chunk rendering integration so network-received terrain chunks actually update the raycaster’s WorldMap, avoiding the “endless flat empty expanse” when joining a server.
Changes:
Client now stores received ChunkData into the local chunk.Manager, invalidates LOD cache entries, and exposes a “new chunks arrived” dirty flag.
Client world map rebuild now samples placeholder LOD chunks (instead of skipping them) and rebuilds when async/network chunks replace placeholders.
Added Manager.StoreNetworkChunk() to reconstitute chunks from network height/biome payloads and replace pending local generation.

StoreNetworkChunk accepts an arbitrary size from the network message and stores a Chunk with Size: size into cm.loaded, even though Manager has a fixed ChunkSize. Mixed chunk sizes in the same manager can break callers that compute local coordinates assuming cm.ChunkSize (e.g., Chunk.GetHeight returns 0 for out-of-bounds when Size is smaller). It would be safer to validate size == cm.ChunkSize (or resample incoming data to cm.ChunkSize, or store it in a separate LOD-specific structure) before replacing the cached chunk.

Since the network protocol does not appear to include the authoritative world/chunk seed, a client with a different cm.Seed than the server will generate different detail/barrier spawns for the same received height/biome data.
