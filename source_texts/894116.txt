Summary
Hi Kevin,
Thanks for the detailed guidance. This draft PR follows the narrower first-pass scope we discussed.
It introduces TIN-based contour generation while preserving the separation between the host-independent geometry engine and the CAD plugin.
Implementation
Added crates/landsurvey/src/contours.rs for per-level triangle slicing and contour chaining using shared TIN edges.
Reused the existing Surface structure and triangle intersection helpers.
Added LS_CONTOURS <surface> [minor-interval=0.5] [major-every=5].
Generates Polyline3D entities on LS-CONTOUR-MAJ and LS-CONTOUR-MIN.
Uses LANDSURVEY_SURFACE XDATA with the surface name, CONTOUR kind and elevation.
Uses Batch for entity creation.
Added Ribbon integration and selective contour regeneration.
Testing
Validated on Ubuntu using Rust 1.99.1:
196 automated tests passed, 0 failures.
cargo +1.99.1 build --release --locked passed.
Tests cover shared-edge chaining, closed loops, exact vertices, saddles, degenerate triangles, UTM coordinates, negative elevations, partial insertion failures and DWG persistence.
DWG round-trip tests verify exact XYZ preservation.
Independent Civil 3D reference
We obtained an independent reference from a corrected 260-point survey in Gualaca, Panama.
Civil 3D results:
260 vertices and 502 TIN triangles.
Minor contour interval: 2 m.
Major contour interval: 10 m.
20 contour polylines across 12 elevation levels.
Independent reconstruction using Civil 3D's exported TIN reproduces the contour counts and lengths within numerical precision.
The direct Rust-engine golden comparison remains pending. The original survey data is not included in this public PR.
Known limitations
Entity deletion through the host API is not transactional. A rejected deletion can leave duplicate contours; the command reports this situation.
A regeneration producing no contours does not yet clear previously generated contours.
Large-surface performance validation in a real OpenCAD Studio host remains outstanding.
Deferred features
Smoothing, labels, QA/preview commands, spatial indexing and custom R12 DXF export changes are deliberately excluded.
Review request
I'd appreciate your feedback on the shared-edge chaining, engine/plugin separation and Batch integration before finalizing the contribution.
I've also prepared the requested 3-D illustration of a TIN intersected by horizontal contour planes.
Thanks again for your guidance.

Hi Oscar, thanks. This is a solid first pass, and the Civil 3D comparison on the same TIN topology is exactly the evidence I was hoping for.
What I like
Chaining by shared TIN edge rather than by matching XY positions. That's the right call, and disconnected_tins_with_coincident_xy_are_not_stitched proves it.
The next_up() convention for levels that land exactly on a vertex. I hit it on purpose with survey data rounded to whole metres (5k points, 91 levels, many vertices exactly on a level): no topology errors.
Insertion order and rollback: all geometry is computed before the drawing changes, and old contours are only removed after every new one has been accepted. The partial-batch and blocked-removal tests are good.
The engine/plugin split: contours.rs stays host-free, and the plugin side reuses Batch and the existing push_undo / remove_entity pattern from LS_FINISH and LS_POINTLABEL.
Needed before merge
Rebase on main. v0.4.26 moved the plugin to host v2026.44 / Plugin API 14. The codec is now the opencaddocument facade, and the test module imports codec::Document instead of CadDocument. GitHub shows #70 as mergeable, but the merged result doesn't compile: contour_replacement_targets_only_own_surface calls CadDocument::default(). Changing that to Document::default() is the only fix needed. With it, all 198 tests pass on top of main.
Document the command in PLUGIN.md. LS_HELP points users there, so LS_CONTOURS <surface> [minor-interval=0.5] [major-every=5] needs a row: layers LS-CONTOUR-MAJ/MIN, the [name, CONTOUR, elevation] tag, rerun replaces, and what the vertex-level convention does.
Make the error readable. contour geometry error at {level}: {err:?} prints NonManifoldEdge, which a surveyor can't act on, and that's exactly what the Civil 3D export with duplicate faces produces. Please give ContourError a Display impl with a plain-language message, e.g. "a TIN edge is shared by more than two triangles (duplicate or overlapping faces); check or rebuild the surface".
On duplicate faces: please handle them separately, in a TIN import/QA PR. Removing duplicate faces belongs where meshes come in (surface_from_mesh / the LandXML import), so every surface command benefits. The contour engine should keep refusing invalid topology, as it does now.
Not blocking, for a later pass
Performance. contours_at_level rebuilds the edge-incidence map and re-checks the topology across all triangles at every level, so cost grows with levels × triangles. On a 40k-triangle synthetic TIN with 90 levels that's about 1.9 s in a release build. Building the incidence map once and sorting triangles by their elevation range, so each level only visits the triangles it crosses, would make it close to linear.
Canonical name in the tag. The tag uses the name as typed, so LS_CONTOURS eg tags contours eg while the TIN is tagged EG. Replacement still works because matching ignores case, but the stored tags end up inconsistent. find_surface_in_document already returns the canonical name, and resolve_named_surface could pass it through.
Near-zero-area triangles (area2 <= 1e-12) are skipped, so a contour that crosses one splits into two open chains. Delaunay output shouldn't produce these, but imported meshes can. A comment saying so would be enough for now.
ids[0] != ids[1] and BranchingTopology can't trigger once the non-manifold check has passed. They're fine as defensive checks.
I'll squash-merge, so don't worry about the commit history. The CI run on this PR is waiting for my approval as a first-time contributor run; I'll approve it once you've pushed the rebase.
Thanks again. Looking forward to labels and smoothing in follow-ups.
