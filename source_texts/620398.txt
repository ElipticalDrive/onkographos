Fixes #10325.
On a smart object, warp_layer stores the document-space warp in source space. For a custom warp it mapped the mesh's points through the placement's inverse and stored the mesh over sb, the bounding box of the warp box's image in source space. That works when the placement only scales and moves, because the warp box then lands exactly on sb. When the placement is rotated, flipped, skewed or distorted, the warp box lands on a tilted quad inside sb. Warp::map normalises by bounds, so the render stretched sb onto the warp box and cancelled the placement. This is the shrink and shift in the report.
The fix: when the warp box does not land on sb corner for corner, the stored warp is a mesh fitted over sb that sends each source point x to inv(W(place(x))). That is exactly what the warp does in the document, expressed in source space, so the render (warp, then the placement) gives W applied to the placed object. The fit has at least 4x4 patches, or more if the warp's own mesh has more. Outside the warp box, the warp's mesh is evaluated by continuing its edge patches rather than clamping. Patches that cross the box's edge then stay smooth, and the fit inside the contents stays exact for polynomial warps.
The cylinder had the same bug: on a rotated smart object, cylinder_in_source falls back to the inverse-mapped mesh over sb. That fallback now uses the same fitted mesh. It is still stored as a custom warp, as before. smart_object_cylinder_is_stored_in_source_space now expects the fitted 4x4 mesh (13x13 control points) instead of the cylinder's 4x1 mesh.
What does not change:
Placements that only scale and move: the custom and cylinder warps are stored exactly as before, and a scaled cylinder stays a cylinder.
The mesh parameter path (content_frame_warp, layer.smartObjects.warp: on a skewed smart object the mesh is mapped onto the bounding frame, not the contents, so an identity mesh shrinks the contents #4113).
Preset styles (arc, flag, ...): they are still stored as the preset over sb and keep the placement.
Test: warp_on_a_sheared_smart_object_keeps_the_placement shears a smart object, commits a custom warp with a bulge and then a cylinder through warp_layer, and checks at four points inside the contents that the stored warp sends the source point to inv(W(place(x))). Without the fix, the custom warp is off by about 4.7 px and the test fails.

Use the clamped warp mapping when fitting the stored mesh.
place_source applies Warp::map to every source coordinate. For custom and cylinder warps, Warp::map calls m.eval, whose locator clamps coordinates outside 0..=1 to the edge. placed_warp instead calls eval_extended, so source content outside the document warp box follows cubic extrapolation after commit.
The fallback does not prevent this. It runs only when the fitted mesh is invalid.
Suggested fix
```
-        hom_apply(inv, eval_extended(&m, (p[0] - b[0]) / bw, (p[1] - b[1]) / bh))
+        hom_apply(inv, m.eval((p[0] - b[0]) / bw, (p[1] - b[1]) / bh))
```
