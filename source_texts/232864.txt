Claim
I'm claiming this. It is a follow-up under #96, found while converting real placement content.
Problem
Some content ships projection meshes. These are closed hulls, usually boxes, and they should not render as ordinary surfaces. Each hull marks a volume: wherever a receiver surface (terrain or a mesh) lies inside it, the decal's material is blended onto that surface. Typical uses are dirt, debris and puddle patches.
Real content has 18 such mesh levels, and their entities appear in about 2,000 placements. The engine has no way to describe a projected volume, and an ordinary mesh descriptor cannot project onto receiver depth.
Reference model
Rasterize the hull.
Reconstruct each receiver's world position from scene depth.
Transform that position into the decal's local space and reject it if it falls outside the unit volume.
Derive projected UVs from the local coordinates.
Sample the decal material: albedo, normal and roughness/metal.
Blend the result into the receiver's surface attributes before lighting, using the decal's alpha and an edge or angle fade.
Implement this inside the existing renderer:
add a decal draw category that runs after opaque depth and before lighting composition, or in the forward path, wherever the engine's surface data is available;
do not add a second renderer;
select which receivers can take decals, for example by excluding water, through an explicit flag.
Scope
A validated SceneDecal description:
hull geometry, or a unit box plus a transform;
material;
projection axis;
fade parameters;
receiver mask.
Retained add, replace and remove.
Visibility culling by hull bounds.
Correct behaviour at both 1x and 4x MSAA.
Default scenes are unchanged.
Tests
Coverage: an independent CPU oracle for a decal on a plane and on a slope.
Rejection: receivers outside the volume are untouched.
Fading: edge and angle fade.
Materials: material channels blend before lighting.
Receiver mask: masked receivers are unchanged.
MSAA: 1x and 4x.
Defaults: default bytes unchanged.
Refs #96.

Slice 2 scope, from real content
I inspected every projection volume in a converted content set: 18 box hulls, all projecting along local +Z, covering 2,013 placements. Slice 1, merged in #218, can express the hulls, the alpha-over blending, receiver categories and hard box clipping. These decals also need the following.
Projected normal maps. 13 levels, 1,982 placements. The map uses compressed XY that is decoded, rotated to (ny, −nx, nz) into decal space, and then corrected against the receiver's geometric normal before it is blended. Average alpha-weighted tilt is 15–51°, so leaving it out removes visible relief.
Packed roughness/metalness maps. Same 13 levels and placements. Roughness in R and metalness in B, blended into the receiver's RM. Crop means range from 0.16 to 0.90 with real variation, so a scalar loses the structure of wet puddle highlights.
UV transform. 10 levels, 1,816 placements. A per-decal UV scale and offset applied to the projected local UV, independent of hull size. This is the reference's UV × scale + offset crop.
Angle fade curve. All levels. The reference multiplies alpha by min(angle / 0.70, 1)^2.4, where angle = max(0, dot), or abs(dot) for double-sided decals. Double-sided projection is indicated for all of them. Slice 1 uses a linear ramp, so this needs to be a selectable curve.
Per-channel write masks. One level, with 0 placements, writes albedo only and keeps the receiver's RM and normal. It also needs an alpha test at 128/255. This is low priority.
Texture formats are BC3 sRGB albedo, BC5 normals and BC1 RM, each 2048² with 12 mips. The normal and RM layers should share the visible-material palette, the same way albedo does.
