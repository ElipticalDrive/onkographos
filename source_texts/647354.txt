Contributor
Creates the Euclid.BVH project from scratch: a Bounding Volume Hierarchy over static 3D lines built on Euclid types (Line3D, BBox), for finding pairs of closest lines among thousands of unevenly distributed lines in ~O(n log n) instead of O(n²). Repo structure and CI mirror the Euclid repo.
Why a BVH
A BVH over the lines' bounding boxes partitions objects, not space — it adapts to clustered input without cell-size tuning (unlike grids/octrees), keeps each line in exactly one leaf (no splitting), and box-to-box distances give cheap lower bounds for branch-and-bound pruning. Since input is static, the tree is built once and is then immutable.
Library (Src/LineBvh.fs)
Flattened array-based tree; built top-down with median splits along the longest axis (LineBvh.create, configurable leaf size)
ClosestLine (query, ?skipIdx) — branch-and-bound nearest line, closer child visited first; skipIdx enables self-excluding NN queries
ClosestPair () / NearestNeighbors () — globally closest pair / nearest neighbor per line, using exact segment-segment distance (XLine3D.getSqDistance)
ClosePairs maxDistance — dual-tree traversal reporting each pair within tolerance exactly once
LinesInBox (box, ?tolerance) — box proximity query
```
let bvh = LineBvh.create lines               // Line3D[], built once
let pair = bvh.ClosestPair ()                // pair.IdxA, pair.IdxB, pair.Distance
let close = bvh.ClosePairs 0.5               // all pairs closer than 0.5
let struct (j, d) = bvh.ClosestLine (lines.[42], 42)  // NN of line 42
```
Project scaffold (Euclid template)
Euclid.BVH.fsproj: net6.0/net472, RootNamespace Euclid, KeepAChangelog-driven versioning, SourceLink, Fable-ready packaging, same warning flags
Src/ + Test/ + Docs/ layout, .slnx, CHANGELOG.md, .gitignore/.gitattributes, dependabot, dotnet-tools.json (fsdocs)
Tests (Test/)
Expecto console project; all queries verified against brute-force implementations on clustered random input, plus leaf-size invariance and edge cases
CI (.github/workflows/)
build, test, docs (fsdocs → GitHub Pages), releaseNuget (tag-driven with changelog/tag version check), cleanup, checkLinks — adapted from Euclid; Fable/JS test steps omitted (no Fable test setup here); explicit permissions: contents: read added per CodeQL
