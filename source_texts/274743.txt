Describe the Bug
When loading a NIfTI volume using @cornerstonejs/nifti-volume-loader, the image appears as a solid gray square on certain Android devices. Lesion volumes (also NIfTI) render correctly and are colorized, but the base image does not render — it shows as a gray canvas.
The problem seems to be related to WebGL texture format support. On the affected devices, the test page at https://ohif-assets-new.s3.us-east-1.amazonaws.com/renderingTest/renderDebug.html reports no support for floatLinear, which appears to be required.
Steps to Reproduce
Load a NIfTI volume in a React app using CornerstoneJS.
Use @cornerstonejs/nifti-volume-loader to load both a main volume and one or more lesion overlays.
Test on a Samsung A13 (Android 13) using Chrome or a WebView (e.g., Microsoft Teams in-app browser).
Observe that the lesion is displayed but the main image appears as a gray square.
The current behavior
Lesion NIfTI volumes load and are displayed correctly.
The main NIfTI image appears as a solid gray canvas (not rendered).
This only happens on some Android devices with limited WebGL texture support (e.g., no OES_texture_float_linear).
The expected behavior
The main NIfTI image should render properly on all supported devices, with a fallback for texture formats that are not available on the device (e.g., use halfFloat instead of floatLinear when unsupported).
OS
Android 13 (Samsung Galaxy A13, fully updated) Also tested on iPhone and Samsung Galaxy S21 (working fine there)
Node version
v18.20.8
Browser
Chrome for Android, Microsoft Teams in-app browser (WebView on Android)

Hi @sedghi
I also had this issue on an S25 FE device, which does not support OES_texture_float_linear. The images were displayed either black or gray, and the problem was resolved by adding this line:
stackViewport.setProperties({
interpolationType: Enums.InterpolationType.NEAREST
});
Shouldn’t CornerstoneJS detect this automatically?
Or am I supposed to manually detect devices that don’t support OES_texture_float_linear and then switch to nearest?
Also, OHIF displays images correctly on the S25 FE, but I couldn’t find where InterpolationType is configured in the OHIF code. How does OHIF handle this issue?
