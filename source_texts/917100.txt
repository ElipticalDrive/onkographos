Problem
The .spz (Niantic Gaussian SPlat) reader in strands_robots.rendering.backgrounds — _load_spz_splats and _decode_spz_rotations — is a hand-rolled binary parser: a gzip container, a 16-byte header, a struct-of-arrays body, and a bit-packed smallest-three quaternion codec for version 3. It is the format the curated MuJoCo-GS-Web scenes ship in (e.g. the tabletop skybox), yet it was entirely uncovered by tests. A wire-format regression (a wrong bit shift, a swapped field offset, a broken quaternion decode) would silently corrupt every Gaussian-splat backdrop without a single test turning red.
Change
Add a focused TestSpzGaussianSplatReader suite that pins the format by round-tripping known inputs through the parser. A small _encode_spz_rotation_v3 helper (the exact inverse of the v3 smallest-three decode) and a _build_spz byte-layout builder let the tests construct valid .spz bytes in-memory:
v3 quaternion decode — encode/decode round-trip for identity and general quaternions; recovered values match within the 9-bit magnitude quantisation bound (~1.4e-3) and stay unit-norm.
v2 quaternion decode — first-three-plus-reconstructed-w (w = sqrt(1 - |xyz|^2)), WXYZ order.
full v3 parse — asserts every field transform: 24-bit little-endian signed fixed-point means, exp(scl/16 - 10) scales, alpha/255 opacity, SH-DC-to-linear color, and the WXYZ quaternion block.
v2 three-byte rotation path — exercises the rot_bytes = 3 branch of the loader.
error paths — a bad magic and an unsupported version both raise ValueError.
The tests need only numpy + torch (no gsplat/CUDA and no plyfile), so they run in the standard test environment.
Coverage
rendering/backgrounds.py: the SPZ reader block (_decode_spz_rotations + _load_spz_splats, ~77 statements) goes from 0 covered to fully covered; module coverage rises from 25% to 44% (measured from tests/rendering/test_backgrounds.py).
Testing

Full suite unaffected (additive, one test file).
Pure test addition — no library behavior changes.

Summary
Pure test addition: a TestSpzGaussianSplatReader suite (+189 lines, one file) that pins the hand-rolled .spz binary parser in strands_robots.rendering.backgrounds. The tests build valid .spz bytes in-memory via a _build_spz layout helper and a _encode_spz_rotation_v3 inverse of the v3 smallest-three quaternion codec, then round-trip through _decode_spz_rotations / _load_spz_splats, covering the v3 bit-packed rotation decode (with quantisation-bound tolerances and sign-flip handling), the v2 reconstructed-w path, every field transform in a full v3 parse (24-bit LE signed fixed-point means, exp(scl/16-10) scales, alpha/255 opacity, SH-DC color), the v2 3-byte rotation branch, and the bad-magic / unsupported-version error paths. I verified the encoder/builder against the production decoder line-by-line (bit order, sign bit at bit 9, largest-index in the top 2 bits, header offsets, body field order) and ran the suite at the head SHA: all 6 new tests pass, and the full tests/rendering/test_backgrounds.py file passes (15/15). No library behavior changes, no host paths, no non-ASCII characters.
What's good
Test imports use the same module path as production (strands_robots.rendering.backgrounds), per AGENTS.md > Review Learnings (#85) > Testing.
Round-trip construction (encode then decode) pins the wire format rather than asserting on implementation internals.
Tolerances are derived from the actual 9-bit quantisation bound and quaternion sign ambiguity is handled explicitly, so the tests won't flake.
pytest.importorskip("torch") gates the loader tests correctly; the decode-only tests need just numpy.
