Closes #355 — second measured top lever from the 2026-07-16 performance analysis (medium tier). First of three stacked perf PRs (next: preset GPU tiers #357/#358, then RLE chunk payload #356).
What
The collision mesh gets its own vertex list; its cube faces are greedy-merged into maximal rectangles per direction + slice (classic voxel greedy meshing, collider-only — the collision mesh carries no UVs/AO, so merging is lossless there while the render mesh keeps all per-face attributes).
Correctness guarantee: the main mesher loop stays the single source of which faces exist — it records per-cell direction bits exactly where it used to emit a per-face collider quad, and the greedy pass merges those bits. The merged collider covers the identical surface; render geometry, AO, fluids, shapes and cross plants are untouched.
Shaped blocks (spheres/ramps/solid flora) append their custom geometry to the collider vertex stream as before.
One deliberate delta: collider quads use the full unit face instead of the render mesh 0.06 bevel-inset corners — the bevel is render-only decoration; the block still occupies its whole cell (this restores the pre-bevel collision footprint).
Why
Fewer collider tris cut exactly the two costs the baselines flagged: the synchronous MeshCollider.sharedMesh cook on WebGL (single-threaded) and Physics.BakeMesh time on desktop.
Verification
1035 + 129 tests green; local Unity Windows build green
PerfProbe High/VD8 (with perf(mesher): pool geometry buffers in ChunkMesher.BuildGeometry #354 pooling + this): walk 48 FPS, max frame 26.2 ms, zero >33 ms frames, ~0.9 GC/s (baseline perf: capture profiling baselines (desktop planet walk + browser session) #353: 41 FPS, max 61.3 ms, 47 frames >33 ms, ~25 GC/s)
The 60 s scripted walk doubles as a collision smoke test; manual playtest of the stacked build done locally

* perf(net): RLE-compress the chunk Blocks payload (browser-focused)

ChunkDataMessage gains BlocksRle — flat (value, runLength) ushort pairs
via the new ChunkBlocksRle codec. The server ships whichever
representation is smaller (terrain almost always RLE; a degenerate
unrunnable chunk stays dense); the client and the test harness accept
both via ChunkDataMessage.DecodeBlocks, and a malformed RLE stream drops
the chunk exactly like a wrong-length dense payload always has.

Decisive on the browser JSON path: ~15-25 KB of JSON numbers per chunk
collapse to usually a few hundred bytes — an initial VD4 view fill is
~390 chunks, so this dominates glitch.fun join time and VPS egress.
Native MessagePack payloads shrink too.

Protocol.Version 1 -> 2: older clients cannot decode BlocksRle, so the
existing join-time version check keeps them off newer servers (the fleet
pins client/server versions in lockstep).

Tests: RLE round-trip (terrain-like + awkward payloads), degenerate
fallback, malformed-stream rejection, wire-size assertions (JSON >20x
smaller). 1039+129 green; PerfProbe walk on the local build doubles as a
live socket-streaming smoke.

Closes #356
