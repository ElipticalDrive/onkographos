OBS-ready VMAFx API in 0.1.0: the import and window-score features a live-production plugin needs, proven by a test. The OBS Studio plugin itself is planned for 0.10.0, #2239.
A live plugin scores the encoder's output against the source while streaming. It holds the source as GPU textures (Direct3D 11 on Windows, Metal on macOS, OpenGL on Linux) and decodes the encoded stream back to frames, so it needs:
Texture import: D3D11 shared textures and Metal textures through the Device frames, fences and import per backend (CUDA, SYCL, HIP, Metal, GL, Vulkan, 4:2:2/4:4:4) #2470 backend lanes. OpenGL interop is new: GL textures or pixel buffers imported through the backend's GL interop (CUDA–GL, SYCL/Level Zero via DMA-buf export from EGL, HIP–GL), with a GL sync object as the acquire fence. That fence kind is added to VmafxFence additively, per ADR-1897.
Async window scores (RC4 WP4 — Asynchronous window scores, window clock and in-flight bound #2471) at a fixed latency budget, so the plugin can show a rolling score without blocking its render thread.
Bounded queues: a documented maximum of frames in flight, with backpressure instead of unbounded growth.
Acceptance: a headless test harness imitates the plugin's call pattern (texture import per frame, window scores polled from another thread, 60 fps pacing). On every backend with a device here, window scores are identical to the offline CLI on the same frames, the host-copy counter stays at 0, and latency stays within the budget.

Harness evidence, measured on master 2c88b8c23:
test_vmafx_live_pacing: 6 of 6 pass, including both planted pacing defects, which are refused.
test_vmafx_window_live: 10 of 10 pass. It covers 0 and 2 worker threads, an unpaced producer that is held back, and window scores polled from another thread.
test_vmafx_window_cli: 56 windows, 448 pooled values, all equal to the offline CLI's frames.
The host-copy counter stays at 0.
Still open: the harness runs on the CPU device, with host buffers standing in for the textures. GPU-texture runs on the CUDA, SYCL and HIP devices, plus the latency budget under make test-timing, are still needed before this closes.
