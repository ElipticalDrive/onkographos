Summary
Everything the game draws today is procedural Three.js geometry: the ship is a handful of primitives, planets are flat-tinted spheres, atoms are octahedra, the sky is a point cloud. That was right for the prototype. This issue proposes replacing those placeholders with a small, curated set of real 3D assets (a ship model, planet textures, crystal models for atoms, a star map, an environment map, particle sprites), lists verified free sources for each, and lays out a phased plan that keeps the procedural versions as fallbacks.
Inventory of what we ship today
Only asset file: assets/space-drift-hero.svg, and assets/ is excluded by .vercelignore, so the deployed app ships zero art files. public/ is 392 KB, all code and CSS.
Ship (public/main.js): two wings built from a hand-written BufferGeometry, cylinder pods, sphere tips, an octahedron cockpit, cone plumes and a Points engine glow, using three MeshStandardMaterials (ivory, dark, accent).
Space layer (public/render-space.js): planets are SphereGeometry(1, 28, 18) with a single tint and no texture; albedo patches are partial spheres; the belt and the overflow body are instanced octahedra and spheres; landing rings are line circles; the curvature sheet is a line grid with a ShaderMaterial.
Surface layer (public/render-planet.js): atoms are one InstancedMesh of OctahedronGeometry(1, 0) with a per-instance emission attribute; molecule shells are hemispheres; bonds and the hex grid are LineSegments; the disc is a CircleGeometry.
Sky (public/render-common.js): a Points star shader. There is no skybox, no environment map, so MeshStandardMaterial surfaces have nothing to reflect and look flat.
Probes (public/render-shot.js): a cylinder bolt and a sprite.
Loaders: the server only exposes three.module.js and three.core.js through VENDOR_FILES in server.mjs, and scripts/build.mjs copies the same two files. node_modules/three/examples/jsm already contains GLTFLoader, KTX2Loader, DRACOLoader, RGBELoader, EXRLoader, the basis and draco decoders and meshopt_decoder.module.js, so no new dependency is needed to load glTF, KTX2 textures or HDR maps.
Goals and constraints
Progressive enhancement. Every asset has a procedural fallback. If a model or texture fails to load (offline static build, slow device), the current look remains. Tests never depend on binary assets.
Licenses. CC0 preferred. CC BY 4.0 is acceptable with attribution in a public/assets/CREDITS.md that ships with the build and is linked from the flight manual. No "free for personal use" packs.
Size budget. The static build deploys to Vercel and the local server serves public/ verbatim. Target at most 6 MB of assets on the wire (Brotli), no single file over 1.5 MB, and lazy loading per layer so the space layer does not download surface assets and vice versa.
Style. Low-poly, flat-shaded, readable at 390x844. Palette must sit on the #080b18 background and the seven element colors in public/constants.js. The quirq mark (Replace the Space Drift mark with the quirq.ai logo (header and favicon) #23) is the only brand element.
Performance. Atoms stay a single InstancedMesh (up to 2,500 per body). Planet meshes under 3k triangles at the far LOD. Point light budget unchanged (8 per layer). Mobile frame time within the budgets set in Spacetime 7: space rendering, sheet, rings, bodies with albedo patches, star points, transitions #15 and Spacetime 8: surface rendering, disc, clusters, bonds, atoms, sky dome #22.
Privacy. Assets are ordinary application files, which the README already allows. Nothing here touches mapped folders or file contents.

Plan of action
Phase 0: pipeline (no visible change)
Add GLTFLoader.js, KTX2Loader.js, RGBELoader.js, meshopt_decoder.module.js and the basis transcoder files to VENDOR_FILES in server.mjs and to the copy list in scripts/build.mjs, under /vendor/addons/.... Add an import map entry for three/addons/ in public/index.html.
Create public/assets/ with manifest.json (id, path, bytes, license, source URL, credit line, layer, fallback flag) and CREDITS.md generated from it. npm run check fails if a manifest entry is missing a license or if the total exceeds the size budget.
Add public/asset-loader.js: loadAsset(id) returning a promise, per-layer preload lists, a cache, and withFallback(id, buildProcedural) so every render module asks for an asset and gets the procedural mesh when it is missing or fails.
Add an offline optimization script (scripts/assets.mjs) using @gltf-transform/cli as a dev dependency: dedupe, prune, weld, quantize, meshopt compression, texture resize to 1K or 2K, KTX2 where supported. Raw downloads live under assets/source/ (already ignored by the deploy) and only the optimized output goes in public/assets/.
Expose getState().assets with loaded, failed and pending counts so browser tests can assert the fallback path.
Phase 1: ship and engine
Pick one Quaternius hull. Recolor to the current ivory, dark and accent materials so the HUD palette does not change. Replace the primitives in main.js with the loaded model; keep the old builder as the fallback.
Engine plume and boost trail from Particle Pack sprites on Points with additive blending. Landing and take-off get a short dust or exhaust burst.
Phase 2: sky and environment
Space: the NASA 4K star map as an equirectangular scene.background; the Points star shader stays as the fallback and for star points of far bodies.
Surface: the same map on the sky dome from Spacetime 8: surface rendering, disc, clusters, bonds, atoms, sky dome #22 so the other bodies of the system sit on a real sky.
A 1K Poly Haven night HDRI through PMREMGenerator as scene.environment in both layers. Keep intensity low so the dark-planet rule from the light model still reads.
Phase 3: planets, belt, structures
Texture families from Solar System Scope by dominant element and mass band; per-planet tint stays as a multiply so hot and cold bodies are still distinguishable. Albedo patches move from partial spheres to an emissive overlay texture generated at runtime from patches.
ambientCG normal and roughness maps for the bodies that keep the procedural material.
Belt: instanced Quaternius asteroids. Overflow body: a cluster of Kenney station modules. Launch point and constellation markers: small Kenney structures.
Phase 4: surface
Seven crystal meshes from the Crystal Pack, one per element, each an InstancedMesh sharing the existing emission attribute and instance colors. Bond lines unchanged.
Molecule shells get a thin MeshPhysicalMaterial with transmission so clusters read as glass under the environment map; temperature drives emissive.
Flash, cooling and probe impacts use Particle Pack sprites.
Phase 5: polish and docs
Two LOD levels for planets and the ship; the far LOD is the current procedural mesh.
Mobile pass at 390x844 with draw calls and frame time recorded.
README gains an Assets section (what ships, budget, how to add one, how the fallback works) and links CREDITS.md; the flight manual links the credits.
A screenshot of each layer in the README.
Each phase is a separate PR against main, with the size budget printed in the PR description.
Acceptance criteria
public/assets/manifest.json and CREDITS.md exist; every entry has a license and a source URL; npm run check fails on a missing license or on exceeding the budget.
The static build and the local server both serve the assets and the addon loaders; npm run build copies them.
With every asset request forced to fail, the game renders exactly as today and getState().assets.failed reports the count; a browser test covers this.
Ship, planets, belt, atoms, sky and particles use the loaded assets when available, with the procedural versions as fallback.
Total assets on the wire at most 6 MB (Brotli), no file over 1.5 MB, surface assets not requested until the first landing, recorded in the PR.
Atoms remain a single InstancedMesh per element; a 2,500 atom body stays within the frame budget of Spacetime 8: surface rendering, disc, clusters, bonds, atoms, sky dome #22.
Point lights stay within the budget of Spacetime 10: light rendering per layer #17; the dark-planet look from the light model still reads with the environment map on.
Clean console and stable frame time at 1280x800 and 390x844 in both layers.
README Assets section and credits are in place; the flight manual links the credits.
Out of scope
Audio (a separate issue).
Character or crew models.
Custom modeling or commissioning art; this issue is about curated free packs.
Changing the physics or layout; only what is drawn changes.
Related: #9 (the two-layer epic), #15 and #22 (space and surface rendering), #17 (light rendering), #6 (probes), #23 (quirq mark).
