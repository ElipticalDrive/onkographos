Capability-first execution acceptance — 2026-11-08
SM4 D3D10 native shader milestone now requires geometry-shader stream output implemented as a bounded GPU state production operation alongside conventional VS/GS/PS. Freeze cooked stream-output semantic layout, stride, primitive budget and input/output buffer lease. Native SO-to-next-pass rebind and unbind/ordering; image reduction still pixel shaders, no compute/UAV. Test GPU particle ping/pong against fixed CPU reference, missing SO support, overflow, broken capture layout and deviceloss.
Revised native and cross-era contract: https://docs.google.com/document/d/11gjy0c3G5gCgWm9QLK5dmyPyWzQnXiOinxF2u9Zy8oQ/edit and https://docs.google.com/document/d/1Dz3eQx-DlN9WLCAo2B6Sf6lPVDhnsAgqAWlQ94LZRcQ/edit. Status PLANNED; no new branch or implementation claim.
Parent roadmap: #239
Branch target: dedicated renderer/d3d10-native (create at implementation start from then-current develop).
First-party C++17, SIREngine formatting, no namespaces in public headers, <=4 function parameters, shared ABI v1.0 unchanged. Native driver owns only Source/Renderer/Drivers/D3D10/**; tests Tests/Renderer/D3D10/**. Do not modify ABI/ShaderCooker shared contracts here; coordinate #130 / #77 / #89.
Proof before closure: exact commit SHA and changed paths; Windows CMake compile and relevant native tests (CPU mocks run on Linux where feasible), negative test evidence, runtime or NOT_RUN markers.
Scope and completion
Depends D10-01 and shader #77/#89, and model+geometry/stream-output contract in #130. Accept offline cooked DXBC; create native VS/PS/GS, stream-output GS when admitted, input layouts, shader resource/sampler/constant slots, immutable raster/depth/blend states and hash caches. D3D10.1 optional capabilities tested separately. Deny DXIL, SM5/compute, stage mismatch, unsupported GS/SO declarations, invalid PS output formats and oversubscribed registers. Test successful color/depth rendering with cooked shaders, shader signature invalidation and cache cold/warm reuse.
Cooked SM4.0/4.1 and native state-bundle acceptance — 2026-11-07
ShaderCooker #77/#89 owns offline FXC/D3DCompiler DXBC SM4.0 (D3D10.0) and SM4.1 (D3D10.1) artifacts and target fingerprints. Native D3D10 driver must validate bytecode version, VS/PS/GS stage signature, reflection/register/sampler/constant limits, stream-output declaration and exact feature tier before Create*Shader/CreateInputLayout. Reject DXIL/SM5 and SM4.1 on D3D10.0; never substitute a D3D11 device. State/layout cache keys include content/recipe/adapter/profile/generation; shader stage/link contracts remain with ABI #130.
Tests: separately qualified D3D10.0/10.1 colored indexed/textured native render and depth readback, valid/invalid GS and input linkage, negative wrong profile/fingerprint, cold/warm state-cache reuse and native lifetime.
