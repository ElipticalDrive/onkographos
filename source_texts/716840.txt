User Story
As a user examining a paused or slowly-playing N-body simulation
I want to switch to a marching cubes render mode
So that I can view a geometrically accurate 3D isosurface of particle density — with correct silhouettes from all camera angles — suitable for close-up inspection and high-quality recording
Depends On: #123 (Screen-Space Metaballs — for RenderMode enum and Render Mode sub-panel)
Acceptance Criteria
The MarchingCubes entry in the render mode selector becomes active and selectable on systems where OpenGL 4.3+ compute shaders are available (runtime check via GLAD_GL_VERSION_4_3)
On systems where compute shaders are unavailable (GL < 4.3), MarchingCubes remains greyed out with a tooltip explaining the requirement
In MarchingCubes mode, a 3D voxel density field is computed on GPU via compute shader, accumulating each particle's influence into a GL_TEXTURE_3D (GL_R32F)
A second compute shader pass runs the Marching Cubes algorithm and outputs a triangle mesh into an SSBO
The mesh is rendered with Phong lighting; each vertex carries an interpolated color from the weighted average of contributing particle category colors; category 500 (rainbow) contributes position/index-derived color using the same derivation as the sphere shader
The isosurface mesh is cached: recomputed only when particle positions change (new timestep). Camera movement does not trigger a recompute.
A live/freeze toggle controls whether the mesh updates on each new timestep (Live) or holds the last mesh until manually refreshed (Freeze); toggle state tracked in MenuState
Runtime parameters tunable via the Render Mode sub-panel: Grid Resolution (default 128³, options 64³/128³/256³), Iso-value (default 0.5), Particle Influence Radius (default 2.0 world units). Values persisted to window.cfg via windowConfig.hpp.
If 256³ is selected and GPU VRAM is insufficient, the 256³ option is greyed out / auto-downgraded to 128³ and a visible UI notification is shown; auto-downgrade logic is unit-testable independently of ImGui rendering
Screenshots and frame recording produce correct marching cubes output; M key is disabled during recording (no mid-recording mode switch)
Unit tests cover the RGB color blending math (weighted average formula, category color mapping including cat 500) independently of rendering
Visual regression test using the shared 64-particle 4×4×4 grid fixture passes on Mesa/Xvfb in CI; test uses GTEST_SKIP if GL 4.3 compute shaders are unavailable at runtime (same pattern as existing capability-gated tests)
No performance regression in Spheres or ScreenSpaceMetaballs modes (manual verification; frame-time measurements documented in PR description)
Technical Notes
GLAD is generated at GL 4.6 level (GLAD_GL_VERSION_4_3 is defined). GL 4.3 capability check via GLAD_GL_VERSION_4_3 at runtime — no context version bump required.
CI uses Mesa llvmpipe on Ubuntu 22.04+ (xvfb); Mesa 22+ exposes GL 4.5 via llvmpipe, so compute shaders should be available in CI. VR test uses GTEST_SKIP as fallback if runtime check fails.
New shaders: density_field.comp, marching_cubes.comp, mesh.vert/frag
Marching Cubes 256-entry lookup table stored as UBO or GL_TEXTURE_1D (uploaded once)
SSBO triangle output requires atomic counter for variable-length mesh
Bounding box for grid derived from actual particle extents (min/max of translations) per recompute
Settings persistence target: window.cfg via windowConfig.hpp — NOT settingsIO.hpp
Depends on Story 1: RenderMode enum, Render Mode sub-panel infrastructure, glReadPixels post-composite fix
Story 2 Dependencies on Story 1 (beyond enum)
The Render Mode sub-panel built in Story 1 must be designed for extensibility — Story 2 adds its own items to it
The glReadPixels post-composite fix from Story 1 is required for correct MC recordings
Sub-panel infrastructure (PanelLayer enum, MenuState field) is defined in Story 1 and extended here
