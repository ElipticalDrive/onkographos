Summary
The extractor exports each block state's collision shape as vanilla stores it: the sorted coordinates of each axis and the bitset of full cells in that grid. The client collides against this grid cell by cell, so a server that wants to agree with the client's collision needs the grid, not the merged boxes.
```
 blocks.json
+  voxel_shapes: [{ x: [..], y: [..], z: [..], cells: bitset }]   # deduplicated
   blocks[].states[]
     collision_shapes
+    collision_voxel_shape: <index>
 BlockState
   collision_shapes()          # unchanged
+  collision_voxel_shape() -> &'static VoxelShape
+    coords(axis), size(axis), is_full(x, y, z), is_empty()
```
Lines inside a solid region matter: a box moving through the bottom of a stair stops at the internal x = 0.5 line, and snow layers keep their 1/8 grid lines. toAabbs() merges those cells away. ChunkEdge only exposes the data and runs no collision itself.
Evidence
Unit tests compare the grids to vanilla's structure: air, stone, a bottom slab, north-facing bottom stairs, and snow with 2 and 4 layers.
blocks.json is regenerated from the 26.3 extractor. Apart from the new fields it matches the file on main.
cargo test --workspace passes.
Merge Danger
Door: two-way
Blast Radius: none
Additive: new JSON fields and a new accessor. blocks.json grows by about 1.5 MB.
