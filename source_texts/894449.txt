Motivation
Reduce per-frame CPU overhead and GPU fragment work to increase FPS for dense/large terrain meshes.
Move expensive work out of the fragment stage (avoid derivative-based normal reconstruction) and reduce state updates performed every draw.
Avoid repeated GL uniform lookups and lower overdraw by using GPU-friendly raster state for an opaque terrain pass.
Description
Replace dynamic light storage with a fixed-size buffer by changing RenderState to use std::array<Light, 8> plus an int lightCount, and copy only active lights each frame from the scene (Terrain Generator/renderstate.h, Terrain Generator/scene.h).
Pass render state by reference in the hot path by changing Object::Draw to accept RenderState& and update calls accordingly (Terrain Generator/object.h).
Compute per-vertex normals at mesh-build time and include them in the vertex format, reserve vertex buffer capacity to avoid repeated reallocations, and upload normal attribute at location 1 (Terrain Generator/geometry.h).
Update the terrain shader to consume a vtxNormal input and use the interpolated normal instead of dFdx/dFdy derivative-based normal construction, and read the active light count from state.lightCount (Terrain Generator/terrainshader.h).
Add a uniform location cache to Shader using std::unordered_map<std::string,int> to avoid calling glGetUniformLocation repeatedly and clear the cache when a program is created (Terrain Generator/shader.h).
Enable back-face culling and disable blending for the opaque terrain pass to reduce fragment workload (Terrain Generator/main.cpp).
Minor API and type improvements (use float suffixes, pass mesh/grid data by const&, small refactors to reduce temporaries).
Testing
Attempted to configure and build with CMake via cmake -S . -B build && cmake --build build -j4, but the build failed because the environment could not fetch the GLFW repository (network fetch returned HTTP 403), so a full compile/run validation could not be completed.
