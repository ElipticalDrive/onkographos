Greptile Summary
Sprint 13 integrates procedural content generation (L-system vegetation, WFC structures) into the terrain pipeline and adds order-independent transparency rendering with weighted blended OIT.
Major changes:
Rendering pipeline: FrustumCuller switched to BVH-accelerated culling, two-pass rendering (opaque + transparent with back-to-front sorting), OIT compositor with MRT accumulation and composite passes
Content generation: VegetationPlacer voxelizes L-system trees onto terrain surfaces with grid-based spacing, WFCTerrainGenerator creates dungeon/building structures with socket-based tile adjacency
UI/Input: ContentBrowser panel (F7 toggle), ToastManager for notifications, InputRouter key callbacks for quicksave/load (F5/F9), InputRecorder wired for capture/playback
Architecture: Both vegetation and WFC follow the TerrainGenerator/CaveCarver pattern (config + class + generate), composing naturally in the density/essence pipeline
Critical issues:
FrustumCuller::cull() rebuilds the BVH every frame (lines 218-220 in Rendering.cc), defeating the performance benefit of spatial acceleration
Vegetation placement probability logic is broken (line 280 in LSystemVegetation.cc) - simplified expression prob > 1.0f is always false, so all grid cells place trees instead of sparse placement
OIT revealage buffer cleared to 0 instead of 1.0 (line 167 in OITCompositor.cc), breaking the weighted blended algorithm when combined with multiplicative blend mode
Confidence Score: 3/5
Safe to merge with fixes required for BVH rebuilding, vegetation placement, and OIT revealage
Three critical logic errors affect runtime correctness: BVH performance overhead, broken vegetation density control, and incorrect OIT rendering. The architecture is sound (90 new tests, follows existing patterns), but these bugs need resolution before the features work as intended
src/core/Rendering.cc (BVH rebuild), src/core/LSystemVegetation.cc (probability logic), src/core/OITCompositor.cc (revealage clear)
