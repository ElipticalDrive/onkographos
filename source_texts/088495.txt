The volume rendering code currently assumes that the volume and all the chunks are axis aligned. This means that there is no way to rotate the volume itself. If you rotate the volume itself via changing the volume.transform, on the individual pieces of the full volume, e.g. with setRotation then you may see an incorrect result because it doesn't consider them to be parts of a more extensive volume. To be clear, rotating the camera is fine, it's just if the volume is rotated. For example:
Related to this is the PR to introduce clipping planes #616. That PR also assumes the planes are axis aligned, and the volume is axis aligned. The question came up for 616 about doing oblique slicing. I think we might be able to support that but have not fully dug into it.
I think there are two different things to solve depending on what would be desired.
To allow rotating volumes, the changes needed should be in the volume layer. The volume layer would need information about the bounding box of the full volume (similar to the request in The dimensions and voxel spacing should be accessible from the VolumeLayer #575). Using this bounding box information, we could correctly compute the translation to apply to the sub-volume/chunk of the full volume to correctly position it after a rotation. There shouldn't need to be any other changes to the shader since it already moves the camera into normalized model space for ray calculation.
feat: volume rendering axis aligned clipping planes #616 I think two main things would be needed for oblique clipping. The first is to decide on how to define the region, I guess maybe center+extent+rotation or something like this as opposed to the current bounds. Then after that we'd have a few operations to perform. The first is to update the proxy geometry bounds to match. The second is a few changes in the logic with the renderer and the shader so that we can transform the rays into clipped region space and also change the UVW calculation, or do some kind of non-axis aligned ray testing (which sounds a bit trickier).
The reason why I mention these two together is that it could be worth thinking about together so that if both are planned to be supported that a rotated volume and oblique slicing together don't get tricky to manage.
