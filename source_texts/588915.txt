Owner
Adds live widget trees on scene surfaces, scene raycasting with interpolated hit attributes, and programmatic scene pointers.
Scene raycasting
Scene.raycast/raycastAll test the rendered meshes directly (no colliders or physics setup) and return typed hits: distance, world point, geometric normal, barycentric weights, triangle index, and the texture coordinate interpolated from the vertex data, so a hit on any shape carries the surface UV.
Filtering: invisible subtrees skipped by default, a layer mask against Node.layers, the new Node.raycastable flag, and an optional predicate. Distinct from the physics queries, which test collision shapes.
The base Geometry retains the uploaded vertex/index data (a reference, not a copy), so procedural, imported, and payload-backed geometry all participate.
Widget surfaces
WidgetComponent places a live widget subtree on a surface: the widget keeps running (state, tickers, animations) while SceneView hosts it invisibly and streams its output into a texture. Zero-config use creates an aspect-correct alpha-blended quad; bring your own geometry or material (implicit binding for built-ins, a bind callback otherwise), or bindOnly for surfaces that already exist (a screen inside an imported model). Dialogs and dropdowns render inside the texture.
Captures default to once per frame (WidgetUpdatePolicy.everyFrame), throttled to one in flight; recording reuses the child's retained layers, so the steady cost is rasterizing content that actually changes. Per-frame is the only trigger that observes repaints inside the child's own repaint boundaries (scrollable items, progress indicators), which update their layers without notifying ancestors. interval and manual policies throttle further. Captures round-trip through the CPU today (a few ms at panel sizes); a future engine API moves them to the GPU with no change to this surface.
WidgetTexture is the low-level capture primitive underneath.
Input
Automatic by default: platform pointers raycast into the scene and presses, drags, and scrolls (mouse wheel and trackpad pan-zoom) forward into the widgets at the hit UV, on any geometry, blocked by occluding geometry, with pointer capture keeping drags alive at surface edges. The forwarding never enters gesture arenas.
ScenePointer for programmatic input (crosshairs, gamepad cursors): point it along any ray or screen position (Camera.screenPointToRay), then press/release/scroll. Occlusion filtering and interaction filtering are independent masks, and pointers carry independent capture and hover.
SceneView.debugWidgetInput overlays the pointer's hit node, UV, and distance.
Supporting changes
MaterialInputs.normal (the lit .fmat surface) now defaults to the interpolated surface normal instead of a constant (0, 0, 1); a Surface() that never assigned it previously shaded flat, silently.
UnlitMaterial.alphaMode (opaque/blend) routes unlit surfaces through the translucent pass.
Surface.lastSwapchainColorTexture exposes the previous frame's color texture for one-frame feedback effects.
Fixed vertically flipped texturing on the cuboid and wedge primitives (face UVs had v = 0 on the bottom edge; the engine convention puts v = 0 at the top of the image). This is the one behavior change existing users might notice, and the golden screenshot diffs on textured primitives are this fix landing.
Example
The widget-texture example is a CRT television: a dome-curved screen (raycast input through real interpolated UVs), a VHS .fmat effect (tape wave, crease, head-switching noise, chromatic bloom, AC beat, each a parameter) consuming the live capture as emissive light on black glossy tube glass, and a scrollable in-screen control panel whose sliders drive the effect distorting it, plus brightness/gloss controls and a one-frame-feedback "recursive" toggle.
The stress tests' environment menu and lighting panel (skybox, exposure, IBL intensity, environment rotation) moved to shared example helpers used by both scenes, and the examples share a free-look camera helper (the stress tests' control scheme).
Guide: WIDGETS.md. All 504 tests pass; verified interactively on macOS.

Add WidgetComponent with SceneView hosting and update policies
…
97bcb02
```
WidgetComponent places a live widget subtree on a scene surface with
one component: it owns the capture controller and the binding of the
captured texture to a material, and SceneView hosts the subtree
invisibly (discovered through the render scene's registry), wrapped in
its own Overlay so dialogs and dropdowns render inside the texture.

Three setup tiers share the component: zero config (an aspect-correct
unlit alpha-blended quad is created), custom geometry (any surface with
0..1 UVs), and custom material via implicit binding for the built-in
materials or a bind callback for everything else. bindOnly creates no
mesh at all, for screens that already exist in imported models. The
texture object is stable across captures and replaced only on capture
size changes; bind re-fires exactly on replacement.

Captures follow a WidgetUpdatePolicy: onRepaint (default), interval, or
manual via the controller's requestCapture. UnlitMaterial gains an
alphaMode (opaque or blend) so unlit surfaces can route through the
translucent pass. The widget-texture example moves onto the component.

Add ScenePointer and automatic widget-surface input
…
bfb16de
```
ScenePointer is a programmatic pointer into a scene (a crosshair, a
gamepad cursor, a VR laser): the caller supplies the ray (pointAt from
a screen position via the new Camera.screenPointToRay, or pointAlong),
and the pointer owns the raycast, UV mapping, event forwarding,
capture, and hover state. Filtering has two axes: the occlusion set
(layerMask, predicate, reach) controls what the ray hits, and
interactionMask controls which widget surfaces respond, so a wall
blocks a press without ever being interactive. While pressed, the
interaction is captured to the pressed surface (moves route to it even
when the ray slides off, holding the last UV at the edge), and
pressTravel exposes the down-to-up travel for click-versus-drag
discrimination. Pointers are independent: each carries its own
forwarding id, capture, and hover.

WidgetComponent gains an input mode, and SceneView forwards platform
pointers automatically through a built-in ScenePointer behind a
translucent Listener (presses forward only when the nearest hit is an
automatic-input widget surface; everything else passes through). The
forwarding state machine is now per-pointer-id, so concurrent pointers
never share capture, and the controller gains pointerScroll for
scrollables. SceneView.debugWidgetInput overlays the pointer's hit
node, UV, distance, and a marker at the pointer position.

The example drops its manual forwarding for automatic input, gates the
camera-look drag to off-panel starts, and enables the debug overlay.
