Scope
Builds the separate planet-wide foundation for the spherical globe: coordinates, gravity, day/night, ocean, atmosphere, procedural terrain tiles, renderer sky integration and one-call environment sampling. Region work stays on region/khoruun-reach.
Included
Geodetic latitude/longitude and altitude validation with dateline-safe projection
WGS84-style Somigliana normal gravity with a bounded altitude correction and globe-center direction
Axial-tilt seasons, solar declination, subsolar longitude, solar elevation/azimuth, daylight and civil twilight
Planetary ocean: tides, coastal classification, fetch-limited wind waves combined with swell, breaking and foam, currents, water temperature/salinity/density and gravity-aligned buoyancy
Stylized deterministic atmosphere: temperature, pressure, humidity, cloud, precipitation, air density and wind
Procedural equirectangular terrain tiles with elevation, bathymetry, slope and moisture
Renderer sky integration: sun and moon direction and irradiance, sky and ambient colours, fog, stars, shadow parameters and a bounded exposure hint, all consumed from the single planet clock
Unified environment sample returning gravity, ground, atmosphere, sun, sky and water in one call
Regression smoke tests for every module
Validation
22/22 native C++ tests pass in a Debug build with asserts enabled, warning-free
World validators pass: canonical world data, regional baselines, UE5 manifest, Avarra baseline
CI now runs the native engine tests and the world data validators on pushes and pull requests; both jobs are green on this branch
Notes
indoru::sky consumes planet::SunState instead of re-deriving solar geometry, so terrain, weather, ocean and lighting stay on one time model.
The moon is a phase-shifted view of the same clock; its declination is a bounded stylization, not an ephemeris.
indoru::environment clamps the gravity altitude to the documented gameplay range so deep bathymetry tiles still yield gravity.
Colours are bounded to the 0..1 linear range, and invalid input returns a safe default state rather than NaN values.

Point gravity down toward the globe center
For every valid coordinate these components form the radial vector from the globe center to the surface point, rather than the documented direction toward the center. For example, sample(0.0, 90.0) returns +Z; a physics caller applying acceleration along the returned down vector will therefore push bodies away from the globe. Negate this normalized vector (or construct the inward radial vector) before returning it.

Reject or normalize overflowing finite longitudes
The finite check accepts values such as std::numeric_limits<double>::max(), but converting that longitude to radians overflows to infinity and the trigonometric calls produce NaNs. Since length <= 1e-12 is false for NaN, sample() returns a nonzero acceleration with NaN direction components instead of the documented safe zero sample, allowing a malformed but finite coordinate to contaminate physics state. Normalize or bound longitude before conversion and reject non-finite intermediate results.
