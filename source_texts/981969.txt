Blocked by [Ray marcher] Add an AST-based Python frontend for device control flow #5: [Ray marcher] Add an AST-based Python frontend for device control flow
Scope
Provide a small reusable device library built from supported native operations/helpers, not a family of tunnel-specific gfx operations.
Vector dot/cross/length/normalize and a 2D rotation helper; a general matrix API is not a prerequisite.
clamp, mix, smoothstep, fract, and floor-based floating modulo with explicitly tested negative-coordinate behavior (not truncating remainder).
Basic sphere/box/2D-box SDFs, repetition/folding helpers, and finite-difference normal estimation.
Compose helpers through typed device functions or deliberate small-function inlining. Do not evaluate device data with host Python math.
Define zero-length normalization and invalid-domain behavior consistently with the math contract.
Expose immutable vector reconstruction or well-defined SSA lowering for component updates.
Acceptance
CPU-reference/frontend/native tests cover helpers, negative repetition coordinates, normalization, and boundary cases.
Helper compositions compile and validate on both native backends and Metal conversion.
A reusable SDF can be called inside a device loop and normal estimation without flattening the loop itself.
Diagnostics identify unsupported types/domains clearly; documentation distinguishes host and device utilities.
Baseline reference
src/mlir_gpu/init.py at the verified graphics foundation commit 1415f58 (71 passing unit/native/GPU/window tests).
