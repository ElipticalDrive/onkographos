메일 요청사항에 따라 두 가지 작업을 수행했습니다.
procams_render.py에 가상 표면(synthetic surface)에 패턴을 투영하는 신규 분기 render_gs_to_surface() 추가

기존에는 depth로부터 복원된 실제 형상에만 투영 결과를 시뮬레이션할 수 있었으나, 이제 구(sphere) / 반구(hemisphere) / 곡면(curved) 위에 투영한 결과도 확인할 수 있습니다.
freeform은 요청에 따라 이번 범위에서 제외했습니다.
```
procams_render.py
├── 기존 render()
│   └── GaussianRasterizer(...)
└── 신규 branch
    └── render_gs_to_surface(...)
        ├── sphere
        ├── hemisphere
        └── curved
            ├── cylindrical
            ├── sinusoidal
            └── parabolic
```

```
Add a new rendering branch that projects the trained ProCams pattern onto
analytic virtual surfaces (sphere / hemisphere / curved) instead of only the
real, depth-reconstructed geometry. This lets users preview how a projection
would look on a hemisphere or curved screen.

Changes:
- utils/point_utils.py: add make_surface_points() and helpers
  (_camera_rays, _surface_center, _ray_sphere_intersection, _make_sphere,
  _make_curved). Generates per-pixel world-space surface points + normals in
  the same (H,W,3) layout as depths_to_points, so the existing procams
  pipeline (warp_points -> grid_sample -> BRDF) is reused unchanged.
  Curved sub-types: cylindrical, sinusoidal, parabolic (solved by ray marching;
  normals via implicit-field finite differences).
- gaussian_renderer/procams_render.py: add render_gs_to_surface(); reuses the
  GaussianRasterizer setup of render() but swaps the depth-based surface for the
  analytic one, then masks pixels that miss the surface.
- gaussian_renderer/__init__.py: export render_gs_to_surface.
- render.py: add CLI args --surface_mode, --curve_type, --curve_radius,
  --curvature, --surface_res; branch the relighting and test_fps loops on
  --surface_mode. When --surface_mode is omitted, the original render() path is
  used unchanged (fully backward compatible).

freeform surface intentionally excluded per request.
Coordinate-frame consistency with depths_to_points verified numerically.
```

fix(surface): scene-aware auto-scaling so the surface fills the view
…
92241bb
```
The synthetic surface used a fixed radius (curve_radius=1.0) placed 2.0
units in front of the camera, ignoring the dataset's coordinate scale.
On the nepmap synthetic scenes the object sits far from the camera at a
large scale, so a radius-1 sphere projected to a tiny dot in the center
of an otherwise blank frame (the reported 'relit' result).

point_utils.make_surface_points:
  - Add optional scene_points + auto_scale (default on).
  - New _scene_stats() estimates, from the trained Gaussian centers, the
    scene depth (median along the optical axis) and a FoV-based frustum
    half-width at that depth (depth * tan(min(FoVx,FoVy)/2)).
  - In auto mode the surface is centered at the scene depth and sized to
    max(scene_extent, 0.8 * frustum_half), so it reliably fills the view
    at ANY coordinate scale. curve_radius/curvature become relative
    multipliers (1.0 -> ~60% coverage, 1.5 -> full frame).

procams_render.render_gs_to_surface:
  - Pass means3D (Gaussian centers) as scene_points + new auto_scale arg.

render.py:
  - Add --no_auto_scale flag (treat curve_radius/curvature as absolute
    world units) and thread auto_scale through both call sites.

Verified: scale-invariance simulation shows constant ~60.4% image
coverage across scene depths 2/5/10/50/100; curve_radius sweep
0.5/1.0/1.5 -> 13%/60%/100% coverage; all three files parse cleanly.
```

fix(surface): anchor surface on object so projector pattern maps (Ip_…
…
83031dc
```
…out)

After the previous frustum-based sizing, the synthetic surface was placed
on the optical axis and sized to ~80% of the view frustum. On nepmap that
made the sphere far larger than the actual object and offset from it, so
its points fell OUTSIDE the projector's illuminated region. warp_points ->
grid_sample then sampled out-of-range coords (padding_mode='zeros'),
producing an all-black Ip_out.

point_utils:
  - _scene_stats now also returns the true 3D scene centroid.
  - Auto mode centers the surface on the object centroid (so it lies inside
    the projector coverage) and sizes the radius to the scene EXTENT (the
    object's size), capped by the frustum half-width so it still fits the
    view. If the object is closer than the radius, shrink the radius so the
    camera stays outside the sphere.

Verified by simulation (camera + offset projector): with object-anchored
sizing, 100% of the rendered surface points map inside the projector
frustum (z>0) at scene depths 5 and 50 -> Ip_out receives the pattern
instead of rendering black. All modified files parse cleanly.
```

fix(surface): give analytic surface a uniform virtual screen material
…
4e72562
```
The relit output showed only a tiny dot because brdf_factor was computed
from render_base_color/render_roughness produced by the Gaussian rasterizer,
which only has material where the real object is. Over the rest of the
analytic surface the material (and thus brdf_factor) was ~0, so
render = brdf_factor * Ip_out collapsed to a dot even though Ip_out
correctly filled the screen.

- render_gs_to_surface: add surface_albedo (0.8), surface_roughness (0.6),
  ambient (0.0) params; override the rasterized material with a uniform
  virtual projection-screen material so the whole synthetic surface is lit;
  scale the rasterized scene term render_shs by ambient (0 => pure
  projection). surface_albedo<0 keeps legacy rasterized-material behaviour.
- render.py: expose --surface_albedo / --surface_roughness / --ambient CLI
  args and pass them at both render_gs_to_surface call sites (relight loop
  and test_fps loop).
```
