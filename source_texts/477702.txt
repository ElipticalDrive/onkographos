Abstract
Graph-based Approximate Nearest Neighbor (ANN) indexes, such
as HNSW, are the backbone of modern vector search. However,
their massive memory footprint creates a severe infrastructure bottleneck. While vector quantization is widely adopted to reduce the
memory required to store data vectors, the graph’s edge structure
increasingly dominates total memory usage. Compressing these
adjacency lists for online search presents a critical system challenge: because decompression occurs during query processing, i.e.,
while navigating the graph, memory savings cannot come at the
expense of query latency. In this paper, we present a compression
technique explicitly tailored for live HNSW routing. By applying
offline graph permutations to artificially induce structural locality,
we enable the use of SIMD-accelerated integer compressors, such
as Stream VByte, for rapid on-the-fly decompression. Evaluated
across diverse real-world workloads, we significantly outperform
the current state of the art in both compression ratio and query latency. Our experimental results show that we achieve compression
ratios up to 52.7% with negligible penalties in latency compared to
the uncompressed baseline. Furthermore, our technique has been
effectively deployed in production at eBay, achieving up to 44.3%
reduction in edge storage with no degradation in query latency.

Introduction
Modern retrieval systems represent data such as text, images, and
products as high-dimensional vector embeddings generated by
neural models, including Large Language Models. Retrieval then
consists of finding the vectors in a large collection that are most
similar to a given query under metrics such as Euclidean distance,
dot product, or cosine similarity [33, 53]. Since exact nearest neighbor search requires comparing the query against all indexed vectors,
its computational cost becomes prohibitive at large scales. Approximate Nearest Neighbor (ANN) methods trade exactness for faster
retrieval, and are now a fundamental component of large-scale retrieval systems [4, 53]. Among the many ANN indexing strategies
proposed in the literature, proximity graph methods—most notably
Hierarchical Navigable Small World (HNSW) [41]—have emerged
as one of the dominant approaches due to their strong trade-off between retrieval accuracy and query latency [4, 53]. These methods
construct a graph over the vectors by connecting nearby points,
enabling efficient graph traversal during query processing. However, they introduce two main sources of memory overhead: storing
the vectors and the graph structure. These indexes are typically designed to reside entirely in main memory to guarantee low-latency
query processing, making memory consumption a primary bottleneck in large-scale deployments [51]. While vector quantization
techniques [1, 25, 34] are widely adopted for vector compression,
the graph structure itself can account for a large fraction of the
overall index size, especially when compact vector representations
are used [51]. As a result, graph compression is particularly relevant
for modern ANN systems. At the same time, compressing graph

connectivity is particularly challenging in the online in-memory
setting, where adjacency lists must be decoded during query execution, and any additional decompression overhead directly affects
retrieval latency. In this line, recent work has begun to explore
lossless compression of ANN indexes across a wide spectrum of
settings, including online and offline scenarios, inverted file (IVF)
indexes [33], graph indexes, and quantized vector codes [51]. However, the current literature still lacks an in-depth exploration of
graph compression, which we address here.
In this work, we provide a thorough exploration of the structural
properties of proximity graphs and graph compression techniques
for online in-memory ANN search. We focus on HNSW [41], one
of the most widely adopted graph-based ANN indexes [4, 5]. It
is available in research libraries such as FAISS [18], hnswlib [40],
and kANNolo [15] (that we employ here), and deployed in production by vector database companies including Elasticsearch, Qdrant,
Weaviate and Pinecone.
Our contribution revolves around two key components. First, we
employ offline node permutation techniques [29, 39] to improve the
compressibility of adjacency lists (Section 2.3). Second, we apply
Stream VByte [36] compression, which at query time achieves negligible decompression overhead thanks to its byte-aligned layout
and SIMD decompression (Section 2.2). We evaluate our proposed
technique on a broad set of workloads, distinguishing our work
from prior studies that present evidence on small, dense vector
datasets (Sift1M [38], Deep1M [6], and FB-ssnpp [47]). Our benchmarks comprise both classical and neural datasets, over dense and
sparse vectors, using Euclidean distance and inner-product similarity, and focus on both compressed and uncompressed vector
representations, across datasets ranging from 1M to ≈9M vectors.
The proposed system is currently deployed in production for
large-scale ANN retrieval at eBay, whose in-house search engine,
Cassini [52], uses HNSW for vector retrieval. We integrated our
graph compression framework into Cassini’s production pipeline to
relieve its memory constraint. Since its deployment in early 2025 we
measure a 44.3% smaller HNSW graph at identical ANN recall, with
no measurable latency degradation under live workloads, which
lets eBay extend HNSW to more search use cases.
Our main contributions are as follows:
• We provide a deep empirical exploration of the HNSW graph
structure over three public datasets and a private products dataset
from eBay (eBayProducts7M) to ground the choice of the adjacency list compression algorithms. Our analysis finds that
reference-based compressors such as WebGraph [9] are not suitable for compressing ANN graphs, and that node IDs do not
reflect the graph’s structural topology, highlighting the need to
adopt graph permutation techniques [29, 39] before compressing
adjacency lists.
• We introduce a compression framework that effectively reduces
edge storage while incurring negligible to zero slowdown. We
then experimentally show the effectiveness and efficiency of our
proposed technique across a wide range of datasets. Our approach
reduces edge space by up to 52% (Sift1M) while maintaining
query latency within a few percent of the uncompressed baseline
and achieving up to 11% lower latency on eBayProducts7M at
98% Accuracy@10.

2 Background and Related Work
2.1 ANN Search
Given a dataset of 𝑁 vectors in a 𝐷-dimensional vector space, the
𝑘-Nearest Neighbors (kNN) problem consists of retrieving the 𝑘
closest points to a query vector under a given similarity measure
[14]. Exact solutions quickly become computationally prohibitive
as both 𝑁 and 𝐷 grow. In particular, classical data structures such as
kd-trees [7] suffer from the curse of dimensionality [31], leading to
a degradation toward linear scan in high-dimensional settings. To
overcome these limitations, Approximate Nearest Neighbor (ANN)
methods trade small accuracy losses for huge efficiency gains [22],
significantly reducing query time and memory access costs [4].
HNSW. The most effective class of ANN indexes is represented by
graph methods [4, 5, 53], which organize the dataset as a proximity
graph by connecting nearby points to facilitate space exploration.
The search for a query vector follows a greedy strategy [5].
Among graph-based methods, the Hierarchical Navigable Small
World (HNSW) graph [41] has emerged as one of the most effective and widely-adopted ANN indexes due to its robustness and
the strong trade-off between accuracy and efficiency that it offers.
HNSW organizes vectors into a multi-level proximity graph where
higher, sparser levels provide long-range connections to facilitate
navigation, while lower levels improve local search accuracy. The
lowest level, referred to as the ground level, contains all the dataset
points. During the search for a query, higher layers are used to
quickly locate the query neighborhood, and the ground level is
then used to refine the results.
Three standard parameters regulate the effectiveness and efficiency of HNSW: 𝑀 controls the maximum number of graph
connections per node, efConstruction regulates the size of the candidate pool during index construction, and efSearch controls the
exploration breadth during query processing. In our implementation, query processing is further controlled by a distance-adaptive
early-termination threshold 𝜆 [2].
Vector Quantization. ANN indexes require storing the dataset
vectors and typically operate in-memory to enable low-latency responses. Therefore, scaling these methods to large, high-dimensional
datasets poses a challenge. To overcome this limitation, much of the
literature has focused on quantization methods [1, 25, 27, 34] that
reduce the space required for vector data by mapping continuous
values to discrete ones.
Product Quantization (PQ) [34] is one of the most widely adopted
quantization techniques [18] in ANN search. It divides vectors into
subspaces, quantizing each independently via 𝜅-means, achieving
compression ratios above 90% at modest accuracy cost.
2.2
Graph Compression
In ANN graph indexes, adjacency lists can be arbitrarily ordered.
However, by enforcing a sorted order and treating them as monotonically increasing sequences of integers, we can leverage powerful
encoding algorithms to significantly reduce memory footprints.

Integer Compression. Elias-Fano [20] is a quasi-succinct encoding that splits each integer into high and low-order bits: the lower
bits are stored explicitly, while the upper ones are stored in a compact unary representation. It compresses sorted adjacency lists and
supports direct access through a Select operation, which is necessary for decompressing adjacency lists during query routing, since
neighborhood lookups are unpredictable and are served on the fly.
Alternatively, a sorted list of integers 𝑆 = [𝑥 1, . . . , 𝑥𝑛 ] can be
transformed via gap encoding (or delta encoding), yielding 𝑆e =
[𝑥 1, 𝑥 2 − 𝑥 1, . . . , 𝑥𝑛 − 𝑥𝑛−1 ], i.e. by storing the differences between
consecutive elements [46, 56]. Ideally, gap encoding shifts the distribution of integers toward much smaller values, reducing the overall
entropy of the sequence.
Entropy coders such as Huffman [30], Arithmetic coding [43,
48, 49] and Asymmetric Numeral Systems (ANS) [19, 51] are near–
optimal in space, but due to bit-by-bit decompression introduce
unacceptable latency that real-time systems cannot afford. Traditional universal codes (e.g., Elias Gamma or Delta [21], Fibonacci [3],
Zeta [10]) assign fixed, short bit sequences to small integers, yet
are not byte-aligned, which slows decoding. Consequently, modern latency-sensitive compression pipelines typically adopt bytealigned or word-aligned integer compressors, which sacrifice a
small amount of compression ratio in exchange for faster decoding.
Variable Byte (VByte) [54] encodes each integer in a variable
number of bytes, with continuation bits marking whether more
bytes follow. It benefits from gap encoding, since the resulting small
integers often fit in a single byte. However, its decoding process
involves data-dependent branches and byte-by-byte control flow,
limiting instruction-level parallelism and efficient SIMD utilization.
Stream VByte (SVB) [36] redesigns the layout of VByte to better
match modern hardware. Instead of interleaving control information with the data, it separates the compressed sequence into two
streams: a control stream and a data stream. Each control byte encodes the lengths of multiple consecutive integers; for instance,
encoding 32-bit values, a single control byte describes four integers using 2 bits per value, where each 2-bit pattern specifies the
number of bytes required to represent the corresponding integer
(from 1 to 4 bytes). The data stream then stores the concatenated
variable-length representations. The decoder therefore reads control bytes independently and access the data stream branch-free.
With block-level indexing the layout also supports partial decoding
and efficient skipping, which fits graph-based ANN search, where
only a subset of overall neighbors array is accessed per query.
List-level Compression. Another dimension along which redundancy can be exploited is at list level, by representing significant portions of one list as a reference to another. Boldi and Vigna observed
that this type of redundancy is pervasive in web graphs, where
many websites share a large portion of outgoing links [9]. They
proposed WebGraph, an algorithm that leverages both intra-list
and inter-list redundancies to achieve state-of-the-art compression
ratios. To mitigate decompression costs, they bound the reference
chains by restricting copies to a fixed window of preceding lists.
While list-level reference compression has become the de facto
standard for archiving web and social graphs, its applicability to
proximity graphs remains largely unexplored. The distinct topological properties of such graphs—combined with the strict latency

requirements of their routing algorithms—raise open questions regarding whether exploitable list-level redundancies exist in this
domain, and whether the decompression overhead of reference
chains can be tolerated during online search.
Previous Work. A recent work by Severo et al. [51] from Meta
investigates lossless compression techniques tailored to ANN data
structures, representing the first systematic study of vector identifier compression for ANN indexes. They show that a substantial
fraction of the memory footprint of ANN structures is due to identifiers and graph links rather than vectors, and that these components
can be significantly compressed without affecting retrieval accuracy,
while highlighting the tension between compression effectiveness
and online decoding costs, especially in graph traversal workloads
where adjacency lists must be accessed frequently during search.
Their approach rest on the observation that, in both IVF [33]
and graph-based indexes, IDs ordering within lists is irrelevant to
search correctness. This invariance enables additional compression
opportunities by treating adjacency lists and posting lists either
as sorted sequences or directly as sets, allowing the use of succinct representations and entropy coding techniques. For the online
graph scenario bit-packing (i.e., storing each identifier of 𝑁 total elements using ⌈log2 𝑁 ⌉ bits) and Elias–Fano [20] provide the best compression and fast random access. On IVF indexes, more advanced
entropy-oriented approaches, including Asymmetric Numeral Systems (ANS) [19, 51], further exploit the statistical distribution of
identifiers and gaps, achieving stronger compression ratios.
2.3
Graph Permutations
Default ordering of vertices in real-world graphs, dictated by ingestion order, rarely aligns with topology, masking redundancies
and leading to suboptimal compression. By finding an opportune
bijection of the vertex IDs—a process known as graph permutation
or reordering—we can artificially induce structural locality and
significantly improve the effectiveness of encoding algorithms.
Formally, optimizing for gap encoding can be formulated as
the NP-hard minimum linear arrangement (MLA) problem, which
seeks a node permutation 𝜙 : 𝑉 → 𝑉 that minimizes the sum

partitioning heuristics. These algorithms cluster the graph into
densely-connected regions and assign consecutive IDs to the nodes
within each block [8, 17, 37].
In the broader graph partitioning literature, two primary paradigms
exist, which we leverage to enable effective gap compression:
• Recursive Bipartitioning (RB): Algorithms in this family repeatedly divide the graph into two balanced partitions until the
desired number of blocks is reached. The most prominent algorithms in this class include Metis, PaToH, and Scotch [12, 35, 45].
Enhanced Graph Bisection (EGB) [39] is a specialized variant of
RB algorithms that employs a gain-based refinement procedure
explicitly designed to optimize the distribution of adjacency-list
entries for compression.

family partition the graph into 𝑘 blocks directly. Recent advances

Consistent with our focus on practical deployments, we restrict our
analysis to low-degree HNSW configurations. In our benchmarks,
low-degree graphs already achieve high recall; increasing 𝑀 beyond
this regime buys little accuracy while costing memory and, through
longer adjacency lists, query latency. Furthermore, HNSW pruning
rules keep the edge count well below the cap. Prior work evaluates
degrees from 16 to 256 [51]. Low-degree graphs are therefore a
more challenging and practically relevant target: adjacency lists
are shorter, leaving less redundancy to exploit, and the per-list
decompression cost is more pronounced relative to the work done
per query.

Graph Compressibility. The feasibility of any compression strategy is shaped by the structural properties of the underlying graph.
In this section, we examine two such properties that motivate our
compression choices: (i) the overlap between adjacency lists, which
determines whether reference-based compression is profitable; and
(ii) the distribution of values within adjacency lists, which dictates
the choice of integer encoders. Table 1 reports some statistics on
node and edge counts of the HNSW graphs under evaluation.
Both properties rest on one structural constraint: HNSW enforces a strict degree bound on every node to balance routing efficiency, memory consumption, and graph navigability. This sharply
contrasts with web and social networks, whose power-law degree
distributions produce high-degree hubs that reference-based compressors exploit for list overlap. As shown in Figure 2, nodes in
CoCondenser and eBayProducts7M concentrate near this cap of
64 edges per node, with a substantial fraction of nodes saturating it
entirely. These short, bounded adjacency lists yield two immediate
consequences: first, the absolute maximum number of edges that
any two lists can share is intrinsically small; second, any per-list
metadata overhead must be amortized over only a few dozen values.

enabling branch-free SIMD decoding. The remaining codecs occupy
unfavorable positions on both axes and are not considered further.
Auxiliary Structures. kANNolo employs a variable-degree representation for adjacency lists, where neighbors are stored contiguously in a flat array, and an auxiliary offset vector off identifies
the boundaries of each neighborhood. In particular, the neighbors
of node 𝑖 are stored in positions off[𝑖], . . . , off[𝑖 + 1] of the array.
Since offsets form a monotone sequence whose gaps correspond
to adjacency-list lengths, we compress them using Elias–Fano encoding [20], which stores a monotone sequence
of 𝑛 integers drawn

from a universe of size 𝑈 in 𝑛 2 + log2 𝑈𝑛 + 𝑜 (𝑛) bits. In off, the
ratio 𝑈 /𝑛 corresponds to the average gap between consecutive
offsets, which is 𝑈 /𝑛 ≤ 2𝑀, yielding 2 + log2 𝑈𝑛 ≤ 2 + log2 (2𝑀).
In our setting (2𝑀 = 64), this translates into barely 8 + 𝑜 (𝑛)
𝑛 bits
per element, a large reduction from the 64 bits per element of the
original array. Furthermore, Elias-Fano allows us to efficiently perform random accesses and decompress single values of off, which
is exactly what we need during query processing.
The analysis above fixes our pipeline. First, we apply the EGB
algorithm to permute the node IDs, storing the compacted permutation mapping. Second, we gap-encode the adjacency lists, compress
them using Stream VByte and compress the index’s offset array
using Elias–Fano to guarantee maximum overall memory efficiency.

and not masked by inefficiencies in the underlying implementation.

Experiments
We conduct our experiments on four datasets spanning a diverse
range of settings: image descriptors, text passages encoded with
both dense and sparse models, and product embeddings (Table 1).
• Sift1M [38] is arguably the most adopted dataset for ANN benchmarking [4], consisting of 1M 128-dimensional image descriptors
produced using the Scale-Invariant Feature Transform (SIFT) [38]
algorithm. It is evaluated with Euclidean distance on 10K queries.
• Ms Marco-v1 [44] is a collection of ≈ 8.8M text passages widely
adopted in Information Retrieval benchmarks, with a query set of
6,980 queries (dev.small). We produce two different embedding
sets and evaluate both under inner product similarity.
– SnowFlake [55] is a lightweight state-of-the-art dense encoder producing 1024-dimensional vectors. As its encoding of
MsMarco exceeds 30 GB, we compress it via Product Quantization (PQ) with 𝑀 = 128 subspaces, achieving a 32× reduction
in storage. Since heavy compression degrades accuracy, we
adopt a two-stage search: the top-𝑘 ′ (𝑘 ′ > 𝑘) candidates are
retrieved using PQ-encoded vectors, then reranked with the
uncompressed representations to select the final top-𝑘. This
mimics the practical scenario in which the reranking step accesses uncompressed data from disk, while the compressed
vectors and the graph structure are kept in main memory.
– CoCondenser [23] is a sparse encoder built on the BERT [16]
vocabulary, resulting in output vectors that live in an ≈ 30Kdimensional space. The vectors have 120 non-zero components
on average, while queries have 42. We employ the dotvbyte
algorithm [11] to store the components and 8 bits floating
point values to store the values.
• eBayProducts7M: this is a set of roughly 7M 96-dimensional
product embeddings from eBay. The embedding model was finetuned for product search from an in-house variant of BERT specialized for the e-commerce domain. The query set consists of
10K query embeddings.

Results. Table 2 reports our evaluation across the four datasets.
Plain represents the uncompressed baseline. Bitpacker provides a
lightweight compromise, reducing memory usage by 1.3×–1.6×
while keeping latency close to the uncompressed baseline across all
datasets. Elias–Fano is dominated on both axes: it is consistently the
slowest method while compressing no better than Bitpacker. Zeta
achieves the smallest memory footprint across all datasets, with
reductions from 1.7× (CoCondenser) to 2.3× (Sift1M) compared
to Plain. However, we pay this compactness with slow downs up
to ≈ 27% on Sift1M and ≈ 14% on eBayProducts7M. Stream
VByte yields the best operating point across all four benchmarks,
combining strong compression with efficient decoding. Its memory footprint remains close to that of Zeta, within roughly 4–10%,
while its query latency matches or even improves over Plain on
CoCondenser, eBayProducts7M, and SnowFlake, with only a
marginal overhead on Sift1M. Stream VByte is therefore the only
method that simultaneously approaches the compression ratio of
Zeta and the query performance of the uncompressed baseline.
Considering the graph permutation as a fraction of the total
build time (graph construction plus permutation), reordering accounts for just 3.5% on CoCondenser, 7.8% on SnowFlake, 15%
on eBayProducts7M, and 30% on Sift1M. Permutation time depends on the number of edges and their distribution, while graph
construction time depends on efConstruction and on vector dimensionality. Sift1M is where this fraction peaks: low dimensionality
and no need for a high efConstruction. Because index construction
is a one-time, offline procedure, permutation’s overhead represents
a highly favorable trade-off for the memory reductions and latency
improvements demonstrated by our system.
5
Conclusions and Future Work
In this work, we study the problem of compressing the adjacency
lists of proximity graphs for ANN search. An offline node permutation induces structural locality in adjacency lists, substantially
lowering their entropy under gap encoding. We then compress the
reordered, delta-encoded neighbor sequences with Stream VByte,
organized into adjacency-list-aligned blocks for fast SIMD decoding at query time. We evaluate our framework on four diverse
benchmarks spanning images, dense and sparse text embeddings,
and product embeddings. Across all datasets, Stream VByte provides the best operating point, with a compression ratio up to 2.1×
with zero to negligible penalties in latency compared to the uncompressed baseline. Beyond public benchmarks, the framework
has been deployed in production at eBay, reducing HNSW graph
memory by 44.3% with no measurable degradation in query latency.
As per future work, we plan to extend our framework beyond
HNSW to other graph-based ANN indexes such as Vamana [32] or
NSG [24], assessing how the compression-latency trade-off shifts
across different graph structures. A second direction is to co-design
graph and vector compression in a unified, compression-aware
index, jointly optimizing edge encoding and vector quantization
to unlock further memory savings, particularly in regimes where
both components contribute comparably to the overall index size.
