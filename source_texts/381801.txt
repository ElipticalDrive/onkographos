```
Adds a combined workspace: a row of orthogonal slices over a 3D surface
view, both driven by the same activation-map layers. The overlay volume
is sampled directly by the slice renderer and projected onto the cortex
via the get_volume_for_projection GPU path; an ActivationMapBinding keeps
the volume layer's display props (colormap, intensity window, threshold,
opacity, visibility) mirrored onto every projected surface overlay that
references it.

- ActivationMapBinding service + useActivationMapBinding hook: one-way,
  ref-counted, self-settling store sync (volume -> projected surface).
- HybridOrthoSurfaceWorkspace: Allotment row of axial/sagittal/coronal
  over SurfaceViewPanel, with in-panel maximize/restore that collapses a
  pane (keeping GPU contexts alive) and a one-click 'Project' action.
- Register workspace type + factory + launcher preset across ViewRegistry,
  workspace types/metadata, workspaceStore, GoldenLayoutRoot and presets.
```

…
8b4660e
```
Implements the remaining projection backend commands so the shared
activation-map model also works on the CPU path:

- project_volume_to_surface: samples an overlay volume at each surface
  vertex (world-space, matching the GPU path convention) via nearest or
  trilinear interpolation, stores per-vertex values in the surface
  registry, and reports coverage + data range.
- create_surface_sampler / apply_sampler: precompute per-vertex voxel
  coordinates against a template grid once, then re-project any matching
  volume frame in O(vertices) for fast 4D time-series scrubbing. Sampler
  storage added to BridgeState.

Shared sampling/summary helpers; honest fallbacks for not-yet-implemented
options (thickness/normal-line sampling, KNN/sigma). Registered across
generate_handler!, build.rs, transport.ts and permissions.
```

Validate sampler affines before reuse
When a sampler is created from one template volume and later applied to another volume with the same dimensions but a different affine/space, this guard passes even though the precomputed voxel coordinates are only valid for the original affine. That silently samples every surface vertex from the wrong anatomical locations, which can corrupt volume-to-surface projection results for common same-shape/different-registration inputs. Store and compare the template affine/space (or otherwise bind the sampler to the exact grid) before applying it.

63fdfa9

```
)

Both the mosaic batch path (BatchRenderService) and the patch-layer path
(LayerApiImpl) used hand-written colormap name->id maps that disagreed with the
Rust BuiltinColormap enum: viridis was sent as 4 (=Plasma), jet as 3 (=Cool),
hot as 1 (=Viridis); LayerApiImpl even mapped turbo->14 and listed nonexistent
winter/summer/spring slots. Mosaic slices therefore rendered the wrong colormap
for nearly every selection.

Add a single canonical `colormapNameToId` in colormapOptions.ts mirroring the
Rust `colormap_by_name` resolver (gray=0,viridis=1,hot=2,cool=3,plasma=4,
inferno=5,magma=6,turbo=7,pet=8,fmri=9,jet=10,parula=11,hsv=12,phase=13) and
route both call sites through it. New unit test locks the mapping and asserts
the 14 UI names cover all 14 enum slots.
```
