Owner
Adds RaySurface, a way to find every intersection of a ray with an implicit
surface F(x, y, z) = 0 at arbitrary precision, alongside Solver and Number.
It rests on one reduction: substituting a ray r(t) = O + t·d into F = 0
collapses the surface to a single-variable g(t) = F(O + t·d), so every
intersection is a real root of g on [t_min, t_max]. formula already
evaluates F and its partials symbolically at any precision, so g(t) and
g'(t) = ∇F·d come straight from Solver.evaluate / get_derivative — no new
symbolic machinery. The rest is univariate root-finding behind one contract.
API
```
from formula import RaySurface

rs  = RaySurface("x*x + y*y - 1", precision=24)
ts  = rs.intersect((-2, 0, 0), (1, 0, 0), t_max=10)   # sorted [Number, ...] of t
pts = rs.points((-2, 0, 0), (1, 0, 0), t_max=10)      # the same hits as (x, y, z)
```
direction is normalized internally, so t is arc length (distance for a unit
d); t_min defaults to 0.
Backends
Pick one with method=; auto is the default.
method
how
best for
auto
dispatch per surface
unsure / default
sturm
interpolate → square-free → Sturm chain → bisect
algebraic surfaces (quadrics, cones, tori); exact root count
chebyshev
Chebyshev fit → monomial proxy → isolate → Newton polish
smooth analytic (sin, exp, log)
subdivision
adaptive derivative-bound exclusion
general / oscillatory surfaces
sampling
grid sign-change + safeguarded Newton
quick checks; not rigorous (oracle/baseline)
auto routes algebraic surfaces to sturm and everything else to the deduped
union of chebyshev and subdivision, so one method's blind spot can't drop a
root; if sturm raises (e.g. degree over the cap) it falls back to the general
backends.
Complex-valued surfaces are handled by sturm (real hits are the common roots of
Re g and Im g); the other backends are real-only.
Supporting changes
Number gains the small public API the backends need: wrap, __neg__,
.precision, .is_complex, .parts().
Shared root-finding helpers live in _roots/utils.py (sign, rtsafe,
merge_close_roots); polynomial ops in _roots/_poly.py; Sturm isolation in
_roots/_isolate.py.
Docs (each with an RU mirror)
doc/ray-surface-intersections.md — usage reference: every backend, worked
examples, and the limits of applicability with reproducible failure/workaround
cases.
doc/ray-surface-design.md — the design decisions and why each backend exists.
README gets a "Finding all ray–surface intersections" section.
Tests
tests/test_intersect*.py — 132 tests covering quadrics/conics, transcendentals,
oblique/arc-length geometry, endpoint roots, tangent/even-multiplicity cases, the
degree cap, complex surfaces, and the documented limits. Full suite: 809 passed,
2 xfailed.
Known limits (documented, not bugs)
sturm is exact only up to a moderate algebraic degree (default cap 16);
equally-spaced interpolation degrades at high degree.
chebyshev self-validates the fit, not the root isolation; its
Chebyshev→monomial step is ill-conditioned, so it can undercount densely
oscillatory surfaces — prefer subdivision/auto there.
subdivision is practically reliable, not a formal proof: its exclusion test
is only as good as the estimated bound on g''.
