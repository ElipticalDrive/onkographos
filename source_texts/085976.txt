Summary
Fix SparseVolume test array undersize: array was 6 elements for a 7-height volume, masked by 4-byte voxel adjacency
Increase MAX_VOLUMES from 2048 to 4096: scenes with >2048 nodes were silently force-merged into one volume on load (potentially causing 100GB+ allocation). Nodes with IDs exceeding the limit were silently skipped for rendering. Added Log::warn for both cases
Add compile-time compact 1-byte voxel mode (cmake -DUSE_COMPACT_VOXEL=ON): 4x memory reduction for large models. Compact layout: bit 7 = outline flag, bit 6 = solid flag, bits 0-5 = color index (64 colors max). Normals, bone indices, and VoxelType::Transparent are not supported. Default mode (OFF) preserves all original behavior byte-for-byte
Motivation
Loading a model with 2800 nodes and 60GB+ voxel data. The MAX_VOLUMES limit caused silent merge on load (7GB model exploded to 100GB during merge). The compact voxel mode reduces the base memory from 60GB to 15GB.
Test plan
All 114 voxel tests pass in default mode (USE_COMPACT_VOXEL=OFF)
All 113 voxel tests pass in compact mode (1 transparent test excluded by design)
Both modes build cleanly
Manual test: load large scene with >2048 nodes, verify no merge and all nodes render

Add cmake option USE_COMPACT_VOXEL for 4x memory reduction. Compact
mode stores voxels as a single byte: bit 7 = outline flag, bit 6 =
solid flag, bits 0-5 = color index (64 colors max).

Normals, bone indices, and VoxelType::Transparent are not supported
in compact mode. Default mode (OFF) preserves all original behavior.

Bulk flag operations (hasFlags, removeFlags, toggleFlags, setFlags)
use uint64_t processing for both modes. Allocations are padded to
8-byte boundaries via allocSize() to support safe bulk reads.
