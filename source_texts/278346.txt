Closes #90.
Adds fixed-snapshot VXL geometry and HVA matrix readers for runtime object presentation. VXL validates every table/span/range and aggregate column/run/voxel budget before coordinate allocation, then returns sparse owned [x,y,z,color,normal] records per section. Raw palette, section/header data, normal-type bytes and float bits are retained. HVA returns owned raw 3×4 matrix values/bits under a required caller-selected frame-major or section-major interpretation. Neither decoder chooses source files, rasterizes voxels, expands normals, matches sections or applies world-space transforms.
Pinned OpenRA/XCC GPL provenance is included. OpenRA and Voxel Section Editor support frame-major ordering; pinned XCC uses section-major. The API and docs preserve that uncertainty rather than claim both are native formats. The observed supplied members are single-frame/single-section, where the formulas coincide. A bounded survey of 234 existing dependency request names found 108 physical members, all similarly single-frame/single-section.
Validation with Node 24.20.0: 13 focused original synthetic tests; full npm run check passed all 373 tests, 68 Markdown files/330 links, 240 publication paths, M0 evidence and the actual 21-file/19-input code-only build. git diff --cached --check passed. A separately implemented Python oracle rehashed both retail roots and compared every geometry byte, palette byte, raw name and float word across 13 VXL + 13 HVA inputs: 128,600 voxel records and 403 scale/transform/bounds words matched. Only source/member hashes, ranges and counts are published; retail geometry/transforms stay ignored under local/.
Independent exact-head COMMENT review and hosted checks are required before coordinator merge. Six issue-owned paths only; no dependencies/shared configuration changed. Voxel rasterization, native lighting/animation behavior and multiframe native ordering remain later integration work.
