Summary
Priority: P1. BSDF::Sample (Gyunity/src/bsdf/BSDF.cpp:74–104) picks a lobe with rand[0] and then passes the same, un-remapped rand[0] to the chosen lobe. For a BSDF with more than one lobe, each lobe samples directions from only a slice of its distribution, but the PDF it reports assumes the whole distribution. Sample and PDF don't match, so any multi-lobe material renders with bias.
```
int sampleIndex = rand[0] * mBsdfCnt;                                   // lobe choice uses rand[0] ...
BxDF* bxdf = mBxdfs[sampleIndex];
Vec3 f = bxdf->Sample(woLocal, &wiLocal, pdf, Vec3(rand[0], rand[1], rand[2]));   // ... and so does the lobe
```
With 2 lobes, lobe 0 only ever receives rand[0] in [0, 0.5) and lobe 1 only [0.5, 1). A diffuse lobe that maps rand[0] to an angle then never samples half of its hemisphere range, while Pdf() still reports the full cosine-weighted density.
Related problems in the same function
Out-of-range lobe index. sampleIndex = rand[0] * mBsdfCnt equals mBsdfCnt when rand[0] == 1, which reads past the last lobe. It needs std::min(..., mBsdfCnt - 1).
flags is ignored. Sample chooses among all lobes and divides by mBsdfCnt, while Pdf(wo, wi, flags) only counts lobes matching flags and divides by matchingComps. With any flags other than BSDF_ALL the two disagree.
Delta lobes. When the sampled lobe is specular, the PDFs of the other lobes are still added to *pdf. pbrt only combines PDFs when the sampled lobe is not specular, because a delta lobe's PDF and the others' densities are not comparable.
Which materials are affected
Every material that adds more than one BxDF to its BSDF, e.g. PlasticMaterial (diffuse + microfacet reflection). Single-lobe materials (DiffuseMaterial, MirrorMaterial, GlassMaterial, RoughnessMaterial) are not affected, since with one lobe rand[0] is used once.
Proposed fix (as in pbrt-v3 BSDF::Sample_f)
Choose among the lobes that match flags: comp = std::min((int)(rand[0] * matchingComps), matchingComps - 1).
Remap the first random number for the chosen lobe: u0 = std::min(rand[0] * matchingComps - comp, ONE_MINUS_EPSILON), and pass (u0, rand[1], rand[2]).
If the sampled lobe is not specular and more than one lobe matches, add the other matching lobes' PDFs and divide by matchingComps; otherwise keep the lobe's own PDF divided by matchingComps.
Evaluate f over the matching lobes only, as now (reflection vs. transmission).
Testing
This changes rendering for multi-lobe materials, so the byte-identical check doesn't apply:
Add a scene with a multi-lobe material (e.g. a plastic object in the Cornell box) to the render test.
Compare before/after at high spp with the block heatmap, and against a reference that doesn't depend on BSDF::Sample (e.g. light sampling only, or a very high spp render).
A unit test that checks, for a two-lobe BSDF, that the histogram of sampled directions matches Pdf() would catch this class of bug directly.

Fixed in #81 (merged into feature/refactor): lobe choice among matching lobes, rand[0] remapped for the chosen lobe, index clamped, delta lobes not mixed with other lobes' PDFs. A new unit test (TestBsdfSample.MultiLobeSampleMatchesPdf) compares importance-sampled and uniformly sampled albedo of a plastic-like BSDF: 0.5617 vs 0.5527 before, 0.5524 vs 0.5527 after. This issue will close when feature/refactor is merged into main.
