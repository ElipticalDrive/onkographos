These are some upstream mesh changes i needed when getting multiscale meshes rendering:
uv run --with 'zarr-vectors @ git+https://github.com/kephale/zarr-vectors-py@ca77de173c2ed973b3e70522c68e85680685e6b5' https://raw.githubusercontent.com/kephale/lodstone/refs/heads/feat/zarr-vectors-mesh-streaming/examples/biological_mesh.py
🤖 ----
Viewers need complete triangles when loading part of a mesh. read_mesh(chunks=...) filters vertices and can drop boundary faces; selecting every endpoint chunk still reads unrelated connectivity.
This adds building.MeshReader, which reads selected face owners and fetches their referenced vertex chunks. Existing read_mesh behavior and the storage format stay unchanged.
Returns complete faces with preserved winding and conservative bounds.
Checks dependency sizes before fetching vertices. Budgeted reads require a verified fragments_tile layout; other layouts are rejected before vertex payloads load, and remain available without a budget.
Reuses metadata in an independent snapshot. Closing releases its handles and index without changing the caller's cache lifetime.
Try the independent fixture from this checkout:
```
uv run --extra dev python examples/mesh_read_reproducer.py --output mesh-read-results.json
```
It returns the same oriented boundary triangle while reading 272 payload bytes versus 2,320 for the existing complete endpoint query. Discovery costs 12,476 metadata bytes separately. This is a small local fixture, not a latency benchmark. The standalone script also pins the corrected reader.
Usage and limits · Recorded measurements · Biological viewer demo
Experimental scope: raw spatial 3-D meshes with canonical ownership. Draco, attribute chunking and duplicate ownership are rejected explicitly. No object filtering, mesh generation or format changes. Discovery lists all cells; the read budget is not a whole-process memory cap.
Validation:
Full non-integration suite, Python 3.13: 1,340 passed, 9 skipped.
All 14 reader tests pass on Python 3.11 and 3.12 and are included in the full suite. Regressions cover unindexed vertex tails, attribute chunking, snapshot release and shared-handle lifetimes.
Lodstone consumer checks against this reader: 31 passed, 2 public-cache checks skipped.
Checkout and isolated Git-pinned reproducers exactly match the recorded JSON. Changed reader/example/test files pass Ruff; HTML docs build succeeds with warnings in existing pages.
Hosted CI awaits maintainer approval for this fork. Draft for feedback: is building.MeshReader the right home for this interface?
