Summary
A new dependency-free slice operation — the planar cross-section of a mesh (3D volume ∩ plane → triangle/quad surface; 2D surface ∩ plane → line mesh), distinct from crop in that it computes the actual intersection and lowers the dimension.
Algorithm (cpp/src/operations/slice.{hpp,cpp}): robust marching tetrahedra — the input is convert_cells(Simplexify)-ed first, then a fixed sign-mask case table gives each cut simplex's crossing-edge ring, with a runtime Newell-normal flip orienting every face toward +normal. Cut points are keyed by the sorted simplexified-edge pair and deduped in a serial first-seen sweep (surface.cpp/refine.cpp phase-split idiom), so shared edges yield one node (watertight). The d >= 0 degeneracy rule makes the sign mask total → a grazing shared face emits exactly once.
Every surface wired and tested:
pybind _core.slice + numpy fallback _slice.py (byte-parity pinned) + __init__ export
C API mio_slice, Fortran m%slice, WASM slice (3 files + smoke)
both CLIs (slice IN OUT --origin --normal)
single-header amalgamation regenerated (CI --check clean)
Verification passed:
1943 Python tests (16 new in test_slice.py, incl. test_cpp_matches_python byte-parity + determinism)
537 C++ tests incl. 7 new Slice.* with the marching-tet Newell winding invariant, across MESHIO / NATIVE / KRATOS backends
WASM smoke test (through the wrapper + exhaustive reflection guard)
native CLI binary end-to-end; black/flake8/isort/clang-format clean
Extras (both fuller-scope options you chose):
Slice demo cell in both example/python and example/cpp/03_mesh_operations.ipynb, re-executed with figures (PyVista + xeus-cpp SVG)
Browser viewer rewired: the "Section" op now calls slice (a true cross-section) instead of crop-half-space + re-skin — cleanly, since a surface isn't skinnable so the shared tail writes the section directly
