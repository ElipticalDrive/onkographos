Fixes #26962.
Enable CPU cubic and Lanczos interpolation for C>4 in remap, warpAffine, and warpPerspective. Cubic gains a dynamic-channel sampler with channel SIMD for interior pixels; Lanczos reuses its existing channel-safe implementation. C1–C4 kernels are retained. Expanding SIMD loads use padded local inputs so tightly packed integer images are not overread. Scalar border components repeat every four channels, as in the existing linear path.
Validation: Release build on Apple M4 Max / clang 21; 491 affected regression tests pass. The new channel-reference test covers uint8/uint16/int16/float32/float64, C5/C9/C20/CV_CN_MAX, unit-sized images, six border modes, affine/perspective warps, float/fixed/relative maps, and strided arrays. Integer results agree within 1; floating results within 3e-5 for inputs in [0,64]. Tight external source buffers and nonfinite coordinates have focused regressions. Permanent performance cases are included.
One thread, baseline 3b79188917, 17° rotation, median of 5×20 calls after warmup. The baseline splits into C≤4 groups and includes input/output copying:

Performance boundary: uint8 cubic at C5 is slower than the optimized C4+C1 workaround: 0.563→0.888 ms at 256² and 2.049→3.441 ms at 512². This adds a previously unsupported native operation; downstream routing should retain its benchmark-based choice. The full local comparison covers both sizes, C3/C5/C20, uint8/float32, and both interpolations.
Hosted CI: current-head run is awaiting repository-admin approval (action_required; no jobs started). New performance cases use SANITY_CHECK_NOTHING() and need no new golden data.
