Closes part of #490 -- see What this does not do below; the issue stays open.
What happens today
RayCastOcclusion tests every ray against every triangle with no early exit and no spatial structure, so a receiver mask costs n_receivers x n_facets x n_triangles. On the Sozzi reactor (1.6M cells, 7,516 lamp facets, 53,500 wall triangles) that is 6.6e14 intersections -- weeks at the measured 120-150 Mtest/s. The Sozzi comparison only avoids it because that fluid is three convex cylinders and a bespoke Occluder answers visibility analytically, which is a description of one reactor rather than a method.
What this adds
TriangleGrid (aquaflux/radiation/grid.py): each triangle registered in the voxels its bounding box spans, each segment walked through the voxels it crosses (Amanatides & Woo's 3D-DDA), only what those voxels hold tested, stopping at the first blocker. Selected with RayCastOcclusion(grid=True), an integer, or a per-axis triple.
False is the default. This changes cost, not answers, and the answers are what the shipped path is trusted for -- so the default is not touched here.

Why it is host code, not a traced kernel
Under a trace the trip count and the per-voxel triangle count must both be static, so every ray pays the longest walk against the fullest voxel whether or not it finds anything: 183 x 36 = 6,588 tests a ray, an 8x saving rather than 1,000x, with none of the early exit. The mask is frozen and built from geometry alone, so nothing about it has to be traceable. Only the intersection test itself is traced, on the compacted (ray, triangle) pairs, through the same predicate the unaccelerated path uses.
Correctness
A grid decides what is worth testing, never what counts as a hit, so the tests are exactness tests rather than tolerances:
bit equality against segment_is_cut at resolutions None, 1, 3, 16, (2,7,5) over 3,000 segments (one voxel is the brute force; a rectangular grid catches an axis transposed in the flattening);
exclusions and the near margin re-checked on the grid's own candidates;
no segment from inside a closed drum reaches outside -- an under-registered triangle leaks exactly there, as a bright spot rather than an error;
RayCastOcclusion(grid=...) against the ungridded strategy, facet to facet on a self-shadowing drum, at three resolutions.
Watertightness is unchanged: both paths go through _watertight_hit, and the window-and-exclusion rule is now one shared _counts_as_hit so they cannot drift.
Mutation pass, 5 mutations, 4 red. Registering by centroid instead of bounding box, stopping after the first voxel, dropping the exclusions, and sizing the grid per axis rather than by extent all go red. One survived and is dismissed rather than patched: forcing every ray to start inside the grid. Rays entering diagonally through a far face were constructed deliberately and gave 0 disagreements -- the walk's stepping comes from the ray, so a clipped start still covers the true path. The entry point saves steps; it does not decide correctness. The separate early-out for a segment that misses the box entirely is load-bearing and has its own test.

What this does not do
The ray count is untouched, and at mesh scale it is the binding cost: 1.6M cells against 7,516 facets is 1.2e10 segments however cheaply each is answered. The grid makes scenes up to a few times 1e8 rays practical; beyond that the facet count has to come down, or the mask has to be built on a coarser emitter than the gather uses. That option is worth more than the grid at full scale and is noted on Radiation: accelerate the segment-triangle test, or arbitrary geometry cannot be shadowed at all #490.
Radiation: accelerate the segment-triangle test, or arbitrary geometry cannot be shadowed at all #490's first acceptance criterion is NOT met here: the accelerated mask has not been run end to end against compare_fluence.py's analytic-opening field on the full reactor. That is hours of machine time and belongs in its own run; the issue stays open for it. What is established here is exactness against the unaccelerated test, and the per-ray cost on the real geometry.

The local fast tier has not been run yet -- another session's validation case holds the machine, and the gate refuses to start beside one; it will be run and reported here.

`ray_acceleration_probe.py` measures the specification's "~20 triangles tested per
ray", which was an assumption and had never been measured. At 128-cubed it is 52

pay -- 183 steps times 36 triangles, 6,588 tests a ray -- which is what decided the
implementation.

`lamp_resolution.py` measures what the emitter's facet count buys, against an
analytic lamp refined to 270,336 facets. The tutorial's 7,516-facet STL lands at
1.95% near the lamp and 1.08% elsewhere; error falls about in proportion to the
facet count, and the near-lamp band sets the requirement, because absorption is
evaluated once per facet along the centroid path. The mesh's own lampWall patch
carries 48,550 faces for about what 25,728 analytic facets buy.

geometry-independent only without a grid (the grid's early exit is exactly what
breaks that), and `_bucket` is now `triangles.padded_length`.

Local fast tier: 2497 passed, 1 skipped (12:10), and the three CI failures are fixed.
The failure was in this PR's own strategy-level test, and the guard inside it is what caught it: the fixture was closed_drum, which is convex, so every sight line between two of its interior facets stays inside the body and meets nothing. Both paths returned a hidden fraction of zero for every pair, and the bit-equality assertion was comparing zero against zero -- a test that could not have failed. assert 0.2 < blocked.mean() < 0.9 is the only reason it did not ship as false coverage.
