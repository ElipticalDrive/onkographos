Feature
Feature request
I would like to propose native COPC (Cloud Optimized Point Cloud) support for CesiumJS.
COPC is a cloud-optimized point cloud format based on LAS 1.4 and an octree-based spatial hierarchy. It is designed for efficient progressive access to large point cloud datasets over HTTP and cloud object storage.
Currently, a common workflow for visualizing COPC data in CesiumJS is:
COPC → conversion/tiling → 3D Tiles → CesiumJS
However, direct COPC access could enable:
COPC → CesiumJS
without requiring a separate preprocessing or 3D Tiles conversion step.
Existing prototype
I recently implemented a working COPC point cloud provider for CesiumJS:
copc-cesium: https://github.com/DrawingProcess/copc-cesium
The implementation is based on the existing CesiumJS point cloud rendering pipeline and currently supports:
Direct loading of COPC files from HTTP URLs
COPC header parsing
COPC hierarchy and spatial hierarchy traversal
Progressive point loading
Selective loading of spatially relevant nodes
LAS point attribute decoding
Support for standard point attributes such as position, color, intensity, classification, and other LAS dimensions
Coordinate reference system handling and transformation
Point cloud rendering using CesiumJS
Integration with CesiumJS camera-based visibility and point loading logic
The implementation also includes support for common projected coordinate systems and has been tested with real COPC datasets.
Motivation
COPC is becoming an increasingly useful format for distributing large-scale LiDAR and point cloud data because it allows spatially organized data to be accessed progressively without requiring the entire file to be downloaded.
Native COPC support in CesiumJS could be useful for:
Large-scale LiDAR visualization
Geospatial and surveying applications
Cloud-hosted point cloud datasets
Direct visualization of existing COPC archives
Applications that do not need a separate 3D Tiles conversion pipeline
Discussion
I would be interested in feedback from the CesiumJS maintainers and community on whether direct COPC support would be considered a good fit for CesiumJS.
In particular, I would like to understand whether this functionality would be better suited as:
A native provider within CesiumJS,
A separate official/community-supported extension, or
A conversion workflow into 3D Tiles.
The current implementation is a prototype and is not intended to propose an immediate merge into CesiumJS. I would first like to discuss the architectural direction and whether native COPC support would be valuable for the CesiumJS ecosystem.
I would be happy to continue improving the implementation and adapt it based on feedback from the CesiumJS maintainers and community.
