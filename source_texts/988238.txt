Rendering chunk (lighting, post-processing, render textures). Everything is on the Babylon backend (ADR 0075/0081). Three ADRs are proposed: 0109, 0110 and 0111.
What was done
Render textures and scene depth (ADR 0109)
New asset type *.rendertexture.json, with width, height, ldr/hdr format, depth on or off, filter and wrap.
New field Camera.targetTexture: a camera draws into the asset instead of the canvas.
Anything that takes an image can show it: material textures, shader-graph textures, sprites and UI images. Each asset has one shared Babylon render target.
Cameras that draw into textures draw after the canvas cameras, so what shows the texture is one frame behind. They also draw in edit mode.
Scene depth texture for soft particles. This is internal, not public API:
The geometry pass now runs before the render pass.
requestSceneDepth(scene, consumer) and sceneDepth(scene, camera) in render/babylon/frameGraph.ts give each camera's linear view-space depth in metres, cleared to the far plane.
Editor: a Render Texture asset kind, a "New Render Texture" menu item, an inspector, and pickers.
Lighting (ADR 0110)
Cascades for several lights: new tier field cascadedLights (Low 1, Medium 1, High 2, Ultra 4). It drops to 1 on devices with only 16 inter-stage shader values, where more would fail to compile.
ReflectionProbe gains:
boxProjection
blendDistance: near a box's faces, a mesh fades to the next probe through a material plugin that samples the second cube. Only the specular part blends.
refresh: "baked" with bakedMap, a prefiltered .env file.
The editor's Bake button writes probes/<scene>-<node>.env and sets those two fields (undoable).
Fog gains height fog: heightFog, heightFogDensity, heightFogBase, heightFogFalloff, plus mode: "none" for height fog alone. It is exponential height fog added along the view ray, through a plugin on every PBR material (built-in, graph, sprite and water materials).
Post-processing and tiers (ADR 0111, amends 0050 and 0051)
LUT colour grading: PostProcessing.lut and lutIntensity, taking .cube files (new "Colour LUT" asset kind and Assets.text). The LUT is applied after tone mapping in the finish pass.
Ambient occlusion runs at half resolution on low and medium. Ultra AO used to fall back to 16 samples; it now gets 48.
The editor's own view shows its background colour as set, instead of tone-mapping it with the scene.
Per-platform default tiers: graphics.platformDefaults with desktop, web and mobile, plus detectPlatform, Graphics.platform, and selects in the Project panel.
0111 records what 0051's three.js-era text (N8AO, postprocessing, SMAA, composer) means on Babylon. 0051 itself is left as written.
Warm-up (0080)
Probe material copies are now warmed.
Everything already warmed is warmed again when the quality tier changes and when probes capture after a load.
Docs
ADRs 0109–0111 written and added to the README table.
implementation-status.md: the stale 0004 and 0051 rows are corrected for the Babylon-only renderer; 0050, 0053, 0054, 0056, 0071 and 0080 are updated; rows added for 0109–0111.
The rendering follow-ups plan is updated.
New browser check page: spikes/babylon/rendering.html.
Not done
Particles: they don't take height fog and aren't warmed up. The GPU particles session owns them; it should use requestSceneDepth/sceneDepth for soft particles.
World-space UI warm-up: not done.
Shared preprocessed-shader cache across Worlds: still shelved (see the plan).
Clustered lighting tile mask for split screen and render textures: still follows the canvas size. Noted in the plan.
Blend copies of reflection probes aren't warmed.
Neighbour's diffuse light (spherical harmonics) isn't blended between probes.
Skies and the Environment component: left alone for the skybox session.
Tests
Unit: npx vitest run src/engine src/editor → 1810 passed, 3 failed. All three also fail on master in this container: one in warmUp ("expected 28 to be less than 20", same on master) and two in websocket.test.
New and extended tests: renderTextures, heightFog, lut, probeBake, renderTextureAssets, plus additions to babylonFrame, babylonLighting, babylonProbes, reflectionProbes, postEffects, warmUp and graphics.
e2e: Chromium only, 2 workers. WebKit can't be downloaded in this container, so it wasn't run. Result: 173 passed, 29 failed, 4 did not run.
Every failure but one is on the coordinator's master baseline list of 37.
The exception, sample:52, passes when run alone (a load flake).
9 tests on the master list pass on this branch: assetbrowser:157, menubar:57, multiworld:56/141, particles:52, projects:78, spriteeditor:89/140, three-d:215.
The master failures that remain include cameras:35/56/66, lighting:39/55 and postprocessing:21/52. Several of them read three.js-era hooks (meshRenderers, stackCount, cameraPreviewComposed), so the post-processing, probe and cascade e2e coverage doesn't run until those tests are fixed (claude/e2e-master-fixes).
Please check by hand (WebGPU)
Render textures: they come out upright on WebGPU. This was only checked on the WebGL2 fallback, where meshes and sprites were upright for both LDR and HDR.
Reflection probes: box projection and blending look right. In headless Chromium, probe captures read black on the WebGL2 fallback, on master too, so only shader compilation was checked here. Also try the editor's Bake button, and a blend between a baked probe and a captured one, which may sample one of them upside down.
LUT: apply a real .cube file and check the look.
Editor background: check it with AO, bloom and depth of field on. It relies on those effects passing alpha through.
Height fog: checked in the browser on WebGL2 only (spikes/babylon/rendering.html?case=probes&fog).
Two directional lights on High: check that both get cascades.
