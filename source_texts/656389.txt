Issue body actions
Build our own geometry kernel instead of depending on OCCT — a Rust-native, mesh/SDF (implicit) kernel aimed at AI authoring + these personas: hobbyist 3D-printer, resourceless small-shop engineer, first-time CAD/print learner, game designer sketching an idea, first-time game-design explorer. Metric (mm) throughout.
Architecture
declarative implicit CSG op-tree (source of truth) → SDF evaluation → feature-preserving polygonization → mesh → export. The AI authors the op-tree via a bsc cad CLI (KitNode-style: describe what the part is, not matrices/vertices). Fillets = SDF smooth-min. Prior art: nTop, Womp, Substance 3D Modeler.
Accepted trade-offs vs B-rep/OCCT
Given up (mostly only the machine-shop engineer persona feels these): true STEP/IGES, exact editable B-rep, named topology (select-a-face), 2D dimensioned drawings, assemblies/mates, class-A surfacing. STEP is a bounded later addition (bind OCCT for STEP I/O only, or a limited writer for analytic-primitive parts — so we keep primitives analytic in the tree).
Foundation spike (this slice — crates/bsc-cad)
SDF primitives (box / sphere / cylinder, mm) + transforms (translate/rotate/scale).
Booleans (union / difference / intersect) + smooth_union (fillet).
Surface-nets polygonizer (dual-contouring upgrade for sharp edges is the follow-up).
Binary STL export; a bsc-cad CLI (spec.json → STL + stats); unit tests + an example spec.
Next
Dual contouring (sharp edges) · sketch→extrude/revolve · shell/pattern/fillet-op · glTF preview in the Design Studio right pane · fold into the unified bsc cad subcommand · then the icebox package split.
