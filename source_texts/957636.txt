Parent
Scene plugin: declarative 3D rendering
What to build
The bounding-volume and ray types that scene culls with and that a caller picks with. All of it is pure arithmetic, so all of it is testable with no GPU and no engine.
Two consumers shape the surface. Culling needs a frustum extracted from a view-projection matrix and a sphere test against all six planes — far included, which is why Far is a required camera field rather than an optional one. Picking needs a ray with a unit-length direction, because every intersect's t is a world distance only if it is.
IntersectBox3 pairs with an AABB that is local space post-re-rooting, so the correct test transforms the ray into local space rather than the box into world space — a rotated AABB re-fitted into world space is looser and reports hits on empty space. Box3.Transform is for growing bounds, not for testing them.
Acceptance criteria
Plane, Frustum, FrustumFromMat4 and Frustum.ContainsSphere testing all six planes
Sphere.Transform, and a Box3 → Sphere conversion for glTF accessor min/max bounds
Ray{Origin, Dir} with NewRay normalising, plus At, Ray.Transform and Mat4.TransformRay
IntersectSphere, IntersectPlane, IntersectBox3
A hit behind the ray origin is rejected
A ray starting inside a sphere or box returns t = 0, ok = true
A ray parallel to a plane returns false, including when it lies in the plane
t is asserted to survive a rigid transform unchanged, and documented as not surviving a scaling one, since Dir is re-normalised
No IntersectTriangle — m has no triangle type and nothing in scope feeds one

Landed in m/geometry.go (commit 0228770, tests in m/geometry_test.go).
Plane with Normalize and SignedDistance; Frustum [6]Plane in the order left, right, bottom, top, near, far, all pointing inwards.
FrustumFromMat4 extracts by row combination, taking the near plane from row 2 alone rather than row 3 plus row 2, because the projections write 0..1 clip depth.
Frustum.ContainsSphere(center, radius) tests all six planes, far included.
Sphere.Transform scales the radius by the largest axis scale (exact under uniform scale, conservative otherwise); Box3 gains Sphere(), Union and Transform.
Ray{Origin, Dir} with NewRay normalising, plus At, Ray.Transform and the one-line Mat4.TransformRay delegation.
IntersectSphere, IntersectPlane, IntersectBox3. No IntersectTriangle.
The rules are all pinned by test rather than by comment: a hit behind the origin is rejected, a ray starting inside a sphere or box returns t = 0, ok = true, and a ray parallel to a plane returns false including when it lies in the plane. t is asserted unchanged through a rigid transform and asserted to double through a 2x scale, which is the documented consequence of Ray.Transform renormalising Dir.
Box3.Transform carries a doc comment saying it is for growing bounds rather than testing them, pointing at the ray-into-local-space form instead. The zero Box3 is documented as a point at the origin rather than an empty box, so a Union fold has to start from its set's first member.
Also added the small Vec3.Min / Max / Abs / Vec4(w) and Vec4.Vec3() helpers these lean on.
