Adding batched merge path sort as described in #2845.
Subgroups may only work on a single segment, and are padded out accordingly.
Each work-item stable sorts its elements in registers, and the sorted runs are then merged in SLM, with several segments packed per work-group. It accepts any work-group size, needs no temporary global memory, and does not require the extensions of the radix sorts. Keys are compared through the order-preserving bit transform of radix sort, so the output matches the other sort configurations.
The range pack helpers move from the ESIMD utilities to the common radix sort utilities.
It would be great to get this into 2022.15.0 but its not explicitly required.

Batched stable sort: merge on encoded keys with cached merge heads
…
01da768
```
Encode keys into order-preserving unsigned bits once on the SLM load and
decode once on the final store, so the leaf sort, co-rank search and merge
compare integers instead of re-running __order_preserving_cast. Floats use
the invertible variant of the transformation; -0.0 and +0.0 are made equal
by a cheap rank adjustment.

Keep the heads of both runs in registers during the merge, so each output
reads a single key from SLM instead of three.
```
