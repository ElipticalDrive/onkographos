Problem
Nothing proves that the visualization backends respect ghost cells. A backend that drops or double-counts boundary cells still renders something plausible.
Done when
tests/test_ghost_volume: each enabled backend computes, inside its own pipeline, the number of cells (and the volume) where U < 0.3 at a fixed step of the seeded 64^3 run: ParaView via Catalyst (threshold then integrate), Ascent (a query), ADIOS2 and PVTI via their readers, Kombyne where possible.
The cell count on 2, 4 and 8 ranks equals the 1-rank count exactly (an integer); the volume agrees within 1e-12 relative. All backends agree with each other.
Runs under CTest for every backend that is built; CI (backends off) skips them, the workstation runs them.
Out of scope
Performance; GPU.
Risk
Needs each SDK built; 8 ranks run on the workstation only (64 cores), CI stays at 4.
Docs
README testing section; docs/in-situ-backends.md seam debugging section uses this test.

Added 2026-11-08 (local commits 38fc3b2 and 2be0b61, not pushed yet):
Ascent in the ghost volume test. Ascent's threshold keeps a cell if any corner is in range; this Ascent has no all-corners option. Ascent counts 2460 owned cells on 1, 2, 4 and 8 ranks, which equals the ADIOS2 reference count under the same rule. Its extracts keep ghost cells; Ascent strips them only before rendering.
Render check (tests/render/render_check.py, CTest label render). Each backend renders the same views on 1 and 4 ranks, headless through EGL, and fails if more than 0.1% of pixels differ by more than 24/255. Results at 4 vs 1 ranks: Catalyst volume 0.002%, Kombyne iso 0.012%, everything else 0.000%. The pre-Catalyst adaptor on the shared mesh builder, without the shifted-domain workaround #21 shifting build fails it (volume 2.1%, contour 15%).
Full suite on the stack tip: 12/12 in the ADIOS2 + Kombyne + Catalyst build and 12/12 in the ADIOS2 + Ascent + Catalyst + reader build (ADIOS2 rebuilt, see the backend doc).
