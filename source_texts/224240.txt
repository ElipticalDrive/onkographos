Roadmap phase
Phase 3 — Features and nodes.
Dependency
Build after [Feature] Add analytic SDF Primitive node so the API can be exercised with native analytic sources.
Complexity / dispatch
Complexity: S–M
Estimated effort: ~1–2 focused engineering days.
Recommended dispatch: Medium reasoning effort.
Risk: Low.
Goal
Add the compositional operators that make signed-distance fields useful as a graph vocabulary.
Node 1: SDF Boolean
Inputs:
A — Numeric
B — Numeric
Smoothness — Numeric, default 0.
Modes:
Union
Intersection
Subtract A-B
XOR (optional if formula is well-defined/tested)
Smooth Union
Smooth Intersection
Smooth Subtraction.
Output:
Numeric, following normal scalar/field promotion.
The node should be a lowerable scalar math-style node. Constants stay constants; fields remain fields.
Node 2: SDF Stroke / Contour
Input:
Distance — Numeric
Width — Numeric
Softness — Numeric
Modes or outputs:
Fill (inside mask)
Stroke/outline around zero
Inside contour
Outside contour.
Output:
Numeric mask in [0,1].
If keeping modes makes the node simpler than multiple outputs, use an Enum.
Semantics
Maintain repository SDF sign convention: negative inside.
Softness must be numerically safe at zero; use an epsilon or branch to hard-step behavior.
Acceptance criteria
Boolean operations preserve signed-distance sign semantics.
Smoothness=0 reduces to hard boolean behavior within numeric tolerance.
Stroke produces a centered band around distance=0.
Float inputs yield Float; any Scalar Field input yields Scalar Field.
Nodes lower in root and simulation bodies.
Fused and solo output agree.
Suggested tests
Use simple analytic values and a tiny primitive composition:
circle union box
circle subtraction
smooth union at k=0 and k>0
fill/stroke exact inside/boundary/outside cases.
Likely files
new focused SDF operator node source
registration manifest
tests/gpu_tests.cpp
docs/nodes.md
Non-goals
No SDF transforms/repeat yet.
No normals/bevel shading yet.
No mask-to-SDF conversion changes.
