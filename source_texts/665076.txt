Files ONE new package spec: .astroray_plan/packages/pkg120-two-sided-mis-spectral.md.
Finding (pkg55 Phase C Session C2 MIS audit, 2026-07-18): Astroray's spectral integrator uses one-sided MIS — it applies the light-side power-heuristic weight lightPdf²/(lightPdf²+bsdfPdf²) to NEE (gpu_nee.cuh:207-210) but drops the complementary BSDF-ray-hits-emitter term for diffuse bounces via the bounce==0||wasSpecular gate (stage_advance.cu:201; CPU pathTraceSpectral same). This is faithfully mirrored CPU/GPU/wavefront, so the three agree with each other — but all three are biased dark relative to ground truth. The expected value is short of the true direct-light integral by exactly the BSDF-weighted portion ∫ w_B·f·Le dω: negligible for compact/distant lights (why it went unnoticed), but O(0.3–0.5) for large/near area lights — a real Cycles-parity gap for common softbox lighting.
The only two-sided bsdf_mis branch (path_trace_kernel.cu:348-372) is RGB-only and is deleted by pkg55 Phase C, so after Phase C the production spectral path has no two-sided MIS at all.
Scope: add the BSDF-side MIS term to pathTraceSpectral (CPU first) + the wavefront emissive-hit handling (GPU mirror), reconstructing the light-sampling pdf (selection × solid-angle + light-tree traversal pdf) at the emitter hit and applying powerHeuristic(bsdfPdf, lightPdf_hit). Ground-truth gate on a large-near-light scene proves fix direction (one-sided reads dark) and magnitude (two-sided matches a high-spp NEE-no-MIS oracle). Cite Veach 1997 §9.2 + Cycles shade_light.h/light_sample_from_intersection/light/sample.h.
Depends on: pkg55 Phase C completion (single CPU + single GPU spectral pipeline first — otherwise the doomed MW megakernel would also need patching). Track A, not Codex-paste-ready, effort M. Full technical detail in the C2 audit note (.astroray_plan/docs/pkg55-phase-c-plan-2026-07.md §4).
