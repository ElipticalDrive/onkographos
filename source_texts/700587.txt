Depends on #2059. This branch contains the two commits of #2059 followed by one new commit; please review only the last commit, Clip box triangles as polygons in box3d_overlap.
Summary
Problem 1 (accuracy, CPU and CUDA): Faces of the two boxes are matched as coplanar when their normals are within ~2.5 degrees (dEpsilon on cos) and only if a matching triangle exceeds an absolute 1e-4 area. Nearly parallel but distinct faces are therefore removed or left unclipped, and for boxes smaller than ~0.01 coincident faces are never deduplicated. The intersection's surface ends up with missing or double counted faces, so the volume is wrong, sometimes by tens of percent; small boxes with shared planes can give IoU above 1 or inf.
Problem 2 (cost): Clipping keeps splitting triangles, up to 768 per side, which forces Fix CUDA box IoU triangle buffer capacity #2059 to use a global workspace and makes large batches slower.
Fix: Each box triangle is clipped by the other box's planes as a convex polygon (at most 3 + 6 vertices). Because a triangle is planar, the vertices inside a plane form one contiguous run, so the output is bounded even when rounding misclassifies vertices close to the plane. Two faces count as coincident only if their boxes are on the same side and each face lies within dEpsilon of the face size (plus the faces' measured non-planarity) of the other's plane; only the inner face is kept. Faces on opposite sides, which bound a thin slab, are clipped normally.
Scope: The CPU and CUDA paths share the same algorithm and agree to within 7e-7 IoU on all inputs below. The global workspace from Fix CUDA box IoU triangle buffer capacity #2059 is removed. The public API and input validation are unchanged.
Accuracy
Compared with float64 halfspace intersections (scipy) on ~17k box pairs: 300 random pairs per scenario, plus every pair where any two implementations disagree by more than 1e-4 in IoU.

Validation
Environment: Linux, Python 3.12.13, PyTorch 2.11.0+cu130, CUDA 13.0, NVIDIA B200 (sm_100).
New tests: test_iou_coplanar_faces_{cpu,cuda} checks coincident, nearly coincident (within 1e-3), nested, thin-slab and touching faces at scales 1 and 0.01 against analytic overlaps, in a random common rotation. test_iou_rotated_exact_{cpu,cuda} checks two rotated pairs against float64 halfspace intersections. All four fail on main and on Fix CUDA box IoU triangle buffer capacity #2059 and pass here.
Module suite: All 22 tests in tests/test_iou_box3d.py pass. The Fix CUDA box IoU triangle buffer capacity #2059 tests are kept and renamed where they referred to the removed workspace.
Memory checking: The 16 regression tests and the stress inputs run under compute-sanitizer --tool memcheck with 0 errors.
Formatting: clang-format, black, usort, flake8 and git diff --check pass on the changed files.
Evidence and reproduction
Accuracy summary and per-pair results: every implementation against float64 halfspace intersections on the same pairs.
GPU benchmark and CPU benchmark: latency and first-call memory for main, Fix CUDA box IoU triangle buffer capacity #2059 and this PR; raw samples are in the JSON files.
Module suite and memcheck run on this PR.
Reproduction instructions: revisions, scenario generator (make_cases.py, with cases.pt included), evaluation and benchmark scripts, and limits.
Storage: Evidence is maintained on the fork's pr_assets branch; figure and data links pin commit b2acafe.
Verification limits
One GPU model and one software stack; the full repository test suite was not rerun.
Coincident faces are now decided by a distance tolerance of dEpsilon times the face size. Faces closer than that are treated as one plane, so the volume can differ from the exact intersection by up to about that fraction for such inputs.
The box3d_overlap_naive Python reference in the tests still follows the old triangle algorithm and is unchanged.

```
Each triangle of one box is now clipped by the planes of the other box as
a convex polygon (Sutherland-Hodgman, at most 3 + 6 vertices) instead of
being split into ever smaller triangles. This bounds per-thread storage,
so the CUDA kernel needs no global workspace, and both the CPU and CUDA
paths are faster.

Two faces are treated as coincident when their boxes are on the same
side and each face lies within dEpsilon of the face size (plus the
faces' non-planarity) of the other's plane; only the inner face is kept.
The previous per-triangle test matched planes up to ~2.5 degrees apart
and relied on an absolute 1e-4 face area threshold, so faces of the
intersection were double counted or dropped: rotated boxes could be off
by tens of percent, and boxes smaller than ~0.01 with shared planes by
up to 100%.

New tests check coincident, nearly coincident and thin-slab faces at two
scales against analytic overlaps, and two rotated pairs against float64
halfspace intersections.
```
