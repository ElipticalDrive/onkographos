Problem
shaders/tile_binning.glsl is the largest shader file at 1,177 lines. It handles Gaussian projection, eigenvalue decomposition, FlashGS opacity-aware bounds, tile assignment, debug rejection counters, subpixel hysteresis, and SH amortization — all in a single file.
While the code is well-organized with clear sections, the file size makes it difficult for new contributors to navigate and increases merge conflict risk.
Current Structure
The shader already includes helpers from:
includes/gs_eigen_binning.glsl (118 lines)
includes/gs_sh_binning.glsl (199 lines)
includes/color_grading_binning.glsl (84 lines)
includes/tile_projection_common.glsl (170 lines)
The extraction process has started but the main file is still large.
Proposed Fix
Consider extracting:
Debug rejection counter logic into includes/binning_debug_counters.glsl
Subpixel hysteresis and culling logic into includes/binning_culling.glsl
The main binning kernel body into clearer pass functions
Impact
Maintainability only. No runtime impact.
Effort
~1 day
