Цель: довести culling в ornis до полного набора: включить существующее по умолчанию и реализовать недостающие виды.
Текущее состояние (master)
CPU frustum culling по сферам (crates/render/src/extraction/cull.rs, cull_frame_upload) — opt-in, по умолчанию выключен.
GPU frustum culling + draw_indexed_indirect (crates/render/src/gpu_culling.rs, RAT-35) — opt-in (RenderBackendConfig::indirect_draw), только gbuffer; тени идут прямым проходом без отсечения.
Backface: Face::Back в forward и shadows; deferred/composite — None (полноэкранные проходы, так и надо).
1. Включить по умолчанию
GPU frustum culling (indirect_draw = true по умолчанию) с fallback на прямой draw при CapacityExceeded и без поддержки indirect.
CPU frustum culling по умолчанию там, где GPU-путь недоступен (WebGL/без compute).
Флаги отключения для отладки и бенчей (по аналогии с ORNIS_NO_VSYNC).
2. Реализовать
Shadow culling: отдельная компакция по фрустуму каждого источника/каскада (сейчас помечено как future work в gpu_culling.rs).
Occlusion culling: Hi-Z пирамида из depth предыдущего кадра + двухфазный тест (с перепроверкой новых видимых).
Distance culling и LOD-выбор (дистанция/экранный размер на инстанс).
Small-object / screen-size culling.
Кластерное/meshlet-отсечение (frustum + backface cone + occlusion на кластер) — отдельным этапом, можно отдельный issue.
Порталы/ячейки для интерьеров — низкий приоритет, по необходимости.
Критерии
Пиксельное совпадение с прямым путём (как indirect_draw_gpu сейчас) и тесты паритета CPU/GPU на каждый новый вид.
Замер на M1: время кадра и число отправленных инстансов до/после на сцене с большим количеством объектов; отчёт в issue.
CI полностью зелёный, rustqual без регрессий и без бампа baseline.
Рукописный путь DSL→WGSL не трогать без решения владельца; новые compute-кернелы нужно писать на wasm2gpu (CPU-путь остаётся запасным).
Мерж только по команде владельца.
