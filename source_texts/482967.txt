# 3D Gaussian Splatting in Streaming

Research code for view-dependent Gaussian subset selection in AR/VR
streaming of 3D Gaussian Splatting (3DGS) scenes: which Gaussians actually
matter from a given viewpoint, and does switching subsets as the viewer
moves cause visible discontinuity — and if so, can it be fixed cheaply?

Full write-up: [`docs/PROJECT_OVERVIEW.md`](docs/PROJECT_OVERVIEW.md).
Discontinuity-metric derivation: [`docs/gaussian_centric_discontinuity_metric.md`](docs/gaussian_centric_discontinuity_metric.md).
PUP single-view adaptation: [`docs/pup_style_discontinuity_framing.md`](docs/pup_style_discontinuity_framing.md).
Full CLI flag reference for every script below: [`docs/SCRIPT_PARAMETERS.md`](docs/SCRIPT_PARAMETERS.md).

## Repository layout

```
analysis/            nerfstudio-based experiments (this project's main code)
pup_view_specific/    our additions on top of the PUP fork — single-view Fisher scoring
docs/                 write-ups + full parameter reference
```

`analysis/*.sh` files are example invocations for the matching `.py` — copy
one and edit `--config` to your own checkpoint path.

## 1. Environment setup

Two separate environments are involved, since `analysis/` and
`pup_view_specific/` build on two different upstream codebases.

**`analysis/` (nerfstudio + gsplat)** — install [nerfstudio](https://docs.nerf.studio/)
per its own install guide (pulls in `torch` + `gsplat`), then add:
```bash
pip install numba pytorch-msssim
```
This project was built against nerfstudio 1.1.5, gsplat 1.4.0, torch
2.9.1+cu128, numba 0.66.0, on a Blackwell (sm_120) GPU. Two environment
variables matter for that GPU generation — export them before running
anything:
```bash
export TORCH_CUDA_ARCH_LIST="12.0"   # gsplat's CUDA JIT target
export TORCHDYNAMO_DISABLE=1         # avoids a torch.compile hang in
                                      # nerfstudio's get_viewmat() on some GPUs
```
On an older/non-Blackwell GPU these likely aren't needed — try without them
first if you hit no errors.

**`pup_view_specific/` (PUP)** — clone the [PUP fork](https://github.com/j-alex-hanson/gaussian-splatting-pup)
(3D-GS + Fisher-based pruning) and follow its own `environment.yml` /
README to build the CUDA rasterizer submodules. Then drop the four files
from `pup_view_specific/` into that repo's root — they extend it with
single-view (rather than PUP's original multi-view) Fisher sensitivity
scoring, needed to compare against this project's `max_pixel_weight` score
at a single viewpoint.

## 2. Get a trained checkpoint

You need a trained 3DGS scene before running anything here. Either:

- **nerfstudio** (used by everything in `analysis/`):
  ```bash
  ns-train splatfacto --pipeline.model.background-color white blender-data --data /path/to/your/scene
  ```
  gives you `outputs/<name>/splatfacto/<timestamp>/config.yml` — that's the
  `--config` value every `analysis/*.py` script expects.
- **PUP** (used by `pup_view_specific/`): train per the PUP repo's own
  instructions, producing a `.ply` — that's the `--ply` value the
  `pup_*.py` scripts (in `analysis/`) expect, alongside `--fisher-dir`
  (produced by `pup_view_specific/run_epre_fishers.sh`).
