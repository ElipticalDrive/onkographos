The "fundamental bit-identity ↔ tightness tension" framing is wrong for these holes. A correctly-anchored conservative test cannot false-cull: the 3×3 max-window centered on the voxel's own canvasPixel >> 1 necessarily contains the voxel's own last-frame depth write if it was visible (its recorded value is e_v + faceSlot ≥ e_v), so e_v > hiZMax + 4 cannot fire on it. Holes therefore mean the depth image is stale relative to the tested frame — and it is, structurally:
COMPUTE_DISTANCE_HIZ builds hiZMips_ after raster, consumed by next frame's compact — one-frame lag by construction (same as the chunk pre-pass).

Why the anchoring argument doesn't cover these holes (two animation-independent gaps)
Your argument — "the 3×3 max-window centered on the voxel's own canvasPixel>>1 necessarily contains the voxel's own last-frame depth write if it was visible, so e_v > hiZMax + 4 cannot fire" — is sound for a surviving voxel. But:
(a) Footprint vs sample-window mismatch (leading seed hypothesis). stage-1 does not write the voxel's depth at the single anchor pixel. emitDeformedFace(base, D, …) spreads it over the trixel-diamond FACES at base + roundHalfUp(D · localID) for localID ∈ {(0,0)…(1,2)} (Z/X/Y faces), and only exposed faces write. The compact samples ONE fixed ±1 half-res window centered on base>>1. At a silhouette / upper edge the voxel's Z (top) face is often unexposed (no write at the anchor) and its exposed X/Y faces sit at the +iso extreme of the diamond — which, through the >>1 half-res parity + the D deform, can land outside the ±1 window. The window max is then dominated by a nearer neighbour surface and the voxel is false-culled. This is a per-frame spatial-coverage bug → hence it appears on a static scene.
(b) Self-reference amplifies it. Once (a) drops a voxel, its depth is absent next frame (point 3), so nothing re-anchors it — the hole self-sustains and can bloom along an edge even though the geometry never moves.

std140 binding-7 layout across CPU + GLSL + Metal (Sonnet flagged, now confirmed three-deep)
occlusionCullMipCount_ reuses the first resolveMode tail pad
(resolveModePad0_) in the CPU FrameDataVoxelToCanvas, and the two shader
mirrors declare the matching field at offset 196 (resolveMode at 192).
The compact's newly-declared binding-7 tail (offsets 76→204) is std140-correct —
faceDeform[3] lands on the 16-aligned offset 80, the ivec4/vec4 run stays
16-aligned through visibleIsoBounds (176), and the trailing pads hold sizeof
at the 16-byte stride. Because the change only renames an existing pad, every
other field offset is untouched and the full-struct subData upload stays
layout-identical to master. This is the safest possible way to land the field.
Metal image-shadows-sampler fix — sound, and now structurally (not just empirically) verified
Sonnet reproduced the positive-fire numbers, which proves the Hi-Z read now
lands. I checked the remaining half — that binding the Hi-Z as a READ_ONLY image
at unit 1 every frame (unconditional, guarded only by hiZMipCount()>0 for
which texture) can't perturb the default (cull-off) path. It can't:
The compact reads hiZLevel0 only when occlusionCullMipCount > 0 (0 on the
default path), so the bound image is ignored when the cull is off.
On origin/master, stage-1/stage-2 re-bind getTextureDistances() as the
image at unit 1 downstream of the compact dispatch
(system_voxel_to_trixel.hpp:1281-1282 READ, 1301-1305 WRITE), so the
transient Hi-Z bind is overwritten before any later pass reads unit 1. No
downstream state leaks.
The bindAsImage(READ_ONLY) (vs bind() sampler) is the correct fix and matches
the Metal access::read declaration; the root-cause writeup in
engine/render/CLAUDE.md + the design doc states the durable invariant ("bind
compute texture reads as images"), not just the investigation history, and
correctly scopes the pre-existing #1294 chunk-cull victim out to the #2360
follow-up rather than scope-creeping it here.
Emission-hull window + voxelPos hoist — correct
voxelOccludedByHiZ derives its sampled Hi-Z window from faceDeform (the
same deform stage-1's emitDeformedFace uses), so it stays a conservative
superset of the emit write set by construction. The paired KEEP IN SYNC
comments on both emitDeformedFace twins are load-bearing and correctly
placed. All texel reads are clamped to imageSize-1, so the widened window
can't read OOB.
The ivec3 voxelPos = voxelPosRaw; hoist (out of the else into the outer
scope, both GLSL + Metal) is behavior-preserving: the rotating branch never
referenced voxelPos (it uses voxelPosRaw directly), and the cardinal branch
gets the same rotated value it computed before. No shadowing regression.

The append gate becomes (<existing predicate>) && !voxelOccludedByHiZ(...).

the predicate is identical to master, and the && short-circuit means the Hi-Z
helper is never even called for a fully-interior voxel already dropped — it can
never re-add one. Shadow-feeder safety is preserved: a voxel whose isoPos is
outside the un-widened visibleIsoBounds returns false (kept), mirroring
dispatchChunkOcclusion's fully-inside-visible eligibility, so an off-screen
caster keeps its sun shadow.
