Enhanced Compression Scheme
Observation of Octree
Consider a decomposed 16x16x16 unit block, which is a level-two multi-resolution
representation of the original unit block. A large portion (for instance,
more than 95%) of wavelet coefficients, whose L2 norms
are less than a threshold value, has already been replaced by zero values.
Considering the usual spatial coherence in the data, it is very probable
that the null coefficients form thick clusters.
We can reform the unit block to a set of decomposed
4x4x4 subblocks, called cell (Figure
4). To reconstruct a specific voxel in a cell included in the reformed
unit, the proper reconstruction formulae are computed twice repeatedly.
It is the same step as traversing octree of level-two. Figure
5 illustrates an octree for a 4 x 4 x 4 cell. The coefficient c0
at root node represents the average of all voxel values in the cell and
the d0i (i=1,2, ... ,7) on level 0
are detail coefficients used in calculating eight average values of the
children nodes on level 1 (These eight values c1j
(j=1,2, ... ,8) are the average values for each 2 x 2 x 2 subblock).
After the average values c1j
(j=1,2, ... ,8) of each node on level 1 are calculated, these values
and the detail coefficients d1ji(j=1,2,...,8,
i=1,2,...,7) included in each node on level 1 are used to reconstruct
the 2 x 2 x 2 voxel values for corresponding subblocks. Consider reconstructing
a specific voxel. First of all, 8 coefficients, c0 and
d0i (i=1,2,...,7), must be retrieved
on level 0 and seven addition/subtraction operations are needed by a reconstruction
formula. By the operations, we get c1j which
is an average of a child node on level 1. Similarly, for some j
on level 1, seven decoding operations are required for detail coefficients
d1ji (i=1,2,...,7). And we can reconstruct
the expected voxel by using c1j and d1ji.
In this process, we need seven addition/substraction operations. At the
end, 15 decoding and 14 addition/substraction operations are needed for
reconstructing one voxel.
But, as mentioned before, most of coefficients~(more
than 95 percent) are already zero and there is the spatial coherency in
the data. From these properties, we can find out a good characteristic
embedded in the hierarchical structure. That is, the ratio of nodes whose
all of the seven coefficents are zero is fairly high (Table
1 and Table 2). It means that if we have the information that the coefficients
included in the node are all zero, we need not to decode the seven coefficients
and not to apply reconstruction formula to get the average of its child
node either. By appending these information to the previous scheme, we
can improve the performance of random access speed and compression ratio.
We call this enhanced encoding scheme zerobit encoding. In particular,
the scheme can be very effectively used in interactive visualization system.

Enhnaced Encoding Scheme
When an encoding scheme is designed, we take into consideration the tradeoff
between compression ratio, reconstruction speed, and image quality. To
design an encoding technique appropriate for our goal, we have compromised
between a good compression ratio and fast random access. As emphasized
before, when compressed volume data are loaded in the main memory for run-time
processing, it is important to be able to reconstruct quickly the value
of an individual element whose access pattern changes in somewhat complicated
ways.
Consider a 16 x 16 x 16 decomposed unit block (Figure
4), which is a set of reformed 4 x 4 x 4 cells. Each cell\footnote{In
this case, the meaning of cell included in unit block is different
from that in the previous encoding scheme ([9, 10]) is a level-two multi-resolution
representation of a 4 x 4 x 4 original subblock and can be represented
in a hierarchical structure. Figure
6 illustrates how the set of reformed cells is encoded by the zerobit
encoding scheme. First, the cells are enumerated one-by-one in front-to-back,
top-to-bottom, and left-to-right fashion, tagging with zero the cells whose
coefficients are all zero, and with positive integers in increasing order,
the cells that contain at least one non-zero coefficient. When a tag is
presented in one byte, 64 bytes of storage are necessary for the cell
tag table. It is same as the previous method in that we maintain the
cell tag table to encode information of the non-null unit blocks. However,
the left-most two bits of each entry in the cell tag table have different
meaning. As explained, we have to encode whether the seven detail coefficients
in each node involved in a cell are all zero or not. Since a cell has nine
nodes in octree structure as Figure 5,
we need at least 9 bits for maintaining these information~(In this paper,
we call these 9 bits the zerobits.). For efficient encoding, the
left-most bit of each entry in cell tag table has a zerobit of node on
level 0. Note that to encode the other eight zerobits of node on level
1, we allocate one byte in cell information.
We can find following possibilities to improve the compression
ratio in the previous encoding scheme.
Although there is only one non-zero coefficient in a cell, it uses significance
map of 8 bytes for represneting the coefficient's position.
Even if there exists only one coefficient which cannot be stored in ono-byte
stream in a cell, the others non-zero coefficients also have to be stored
in two-byte stream.
In fact, these inefficencies appear in some cells, so
we solve the problems in the zerobit encoding scheme by following methods.
As described, since the nodes whose zerobit is 0 have all zero detail coefficients,
we don't need to maintain significance map for their positional information.
So, the number of bytes for significance map is the same as the number
of zerobits whose value is 1. If nine zerobits are all 1, we store significance
map of 9 bytes. It seems that the zerobit scheme use more bytes than the
previouse scheme which used 8 bytes. But, we can see that the average number
of bytes for significance map used in non-null cell is less than 8 bytes
from following experimental results. It means that the encoding method
is more effective than previous scheme in compression ratio.
Since each significance map includes positional
information of only seven detail coefficients of the corresponding node,
it leaves one unused bit of eight bits. We can observe that the ratio of
coefficients have to be represented by two bytes is fairly low. Thus, we
use the unused left-most bit in the significance map to indicate existence
of coefficients stored in two-byte stream~(in the our implementation, the
0 means existence). If there exist those coefficients, we preserve a bytetag
in order to represent which coefficients among those have 1 in significance
map are stored in two-byte stream~(in the zerobit scheme, the 1 in bytetag
means that its detail coefficient is stored in two-byte stream.). If all
coefficients are represented by one byte without two bytes, all of the
coefficients which have 1 in significance map are stored in one-byte stream.
The detail coefficients in nine nodes included in octree for a cell are
classified and encoded in this way. The coefficient c0
on level 0 has to be classified by its corresponing byte type also. To
keep this, we use a bit which is adjacent to the left-most bit used to
encode zerobit of level 0 in cell tag table. But, since there is no significance
map for the coefficient c0, the c0
has to be stored in one-byte stream even if its value is zero. It seems
that this unnecessary storing makes worse encoding performace. But, in
fact, since the c0 means the average value of the cell
which involves the coefficient, the cell itself may be null in almost case
when the c0 is zero. So it is not so much serious.
To store coefficients, the encoding scheme has two
byte stream type and maintains the offset values for each byte stream in
the cell. It is similar to the previous scheme. But since the coefficients
in the same cell are classified by two type, each cell has a burden to
keep the two offset values.
The reconstruction process consists of two stages:
First, all the necessary wavelet coefficients are retrieved from appropriate
byte-stream using the information in encoded unit blocks. Then the reconstruction
formulae are applied to the coefficients. Notice that all 15 coefficients
must be retrieved in order to reconstruct a specific voxel. Now,

encoded data. To extract a coefficient with index (i,j,k), we look
up the tag of the cell that contains it in the cell tag table. If it is
zero, the coefficient is simply zero([case 1]). Otherwise, we access
its cell information for further processing. Let (i',j',k') be the
index of the coefficient in the cell. If the zerobit for the index (i',j',k')
is 0, then the coefficient is zero( [case 2]). Otherwise, we check
the bit-flag for the index (i',j',k'). If the bit-flag is 0, then
the coefficient is zero( [case 3]). If not, the coefficient is non-zero,
and it is in the appropriate byte-stream( [case 4]). To extract
the coefficient value, its address in the stream must be calculated. It
can be computed by adding its displacement value to the offset value. The
displacement is the number of non-zero coefficients with flag 1 that precede
it in the enumeration. To count the number quickly, we use a precomputed
indexing table T(*) with 28 = 256 entries. Given a one-byte
word, corresponding to 8 bit flags, the table returns the number of bit
1 in the byte. The correct number can be counted by accessing the table
only a few times.

Algorithm1: Wavelet Coefficient Decoding Algorithm
We can understand the decoding process by the example
in Figure 6. Consider the 33rd cell
(counting from zero) in the set of decomposed cells. As we look up the
cell tag table, we can get the tag 10000111 for the cell. We see
that its cell information is found in 6th block (counting from zero). Note
that in our implementation, the left-most bit is used to indicate if the
zerobit of level 0 is zero, and the bit adjacent to the left-most bit is
used to represent the bytetag of c0. Since the zerobit of level
0 is 1, the first byte of significance map in the cell information with
index 6 is the flag for the node on level 0. Also, the bytetag of c0
is 0, which means that the coefficient was stored in one-byte stream. (if
the bytetag is 1, the c0 was stored in two-byte stream.) Because
the one-byte offset in the cell information is 41, we can retrieve the
c0 from 41th value in the one-byte stream. The zerobits of the
coefficients on level 1 were maintained in the cell information. From the
zerobits, we know that the only 2nd and 5th nodes on level 1 have at least
one non-zero coefficient. Thus we look up significance map to decode the
coefficients of d13j and d15j.
At this time, we check both the 2nd and 3rd byte of the significance map
to find the position information of the d13j and
d15j, respectively. Assume that we are retrieving
the circled coefficients in the 3rd byte of the significance map. Note
that the left-most bit of each byte in the significance map is used to
represent whether there are two-byte coefficients or not. Since the left-most
bit is the 1, we know that at least one coefficient of the three details,
d151, d152, d155,
was stored in two-byte stream. To find out which detail coefficients are
stored in two-byte, we check the corresponding byte in bytetag which maintain
information for two-byte coefficients. From the information, we know that
only the d155 was stroed in two-byte stream
and the others in one-byte. After all, the first circled coefficient, d152,
can be retreived from one-byte stream with index 47(=41+6), and the second
circled coefficient, d155 from two-byte stream
with index 7(=6+1).
When we apply the zerobit encoding scheme to the
RGB data, the scheme has to be somewhat modified. Since each component
of average coefficient vector c0, (r,g,b), has
a range [0, 255], it can be stored in three-byte stream with unsigned
char type. Similarly, in the case of detail coefficient vectors
the each component has a range [-128, 127], thus it can be also encoded
in three-byte stream with signed char type. Moreover, the
coefficient vector c0 always has index (0,0,0)
and need not to use the bytetag information used in the CT data encoding
scheme. So we can modify the meaning of the bit in each entry of the cell
tag table. (In Figure 6, it represents
the bytetag of c0 when the CT data is encoded.) In other
words, we use the bit to indicate whether the coefficient vector c0
is (r,g,b) = (0,0,0) or not. It reduces the waste which may
happen to store c0 with zero value when the CT data is
encoded. The rest of encoding scheme for RGB data is the same as the CT
data.
Finally, the zerobit encoding scheme shows much
more effective performance compared with previous method ([9, 10]) in that
it supports fast random access and high compression ratio without image
quality loss (Figure
7).
