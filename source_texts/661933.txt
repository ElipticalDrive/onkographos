Contributor
Clouds were embedded in DayNightSkybox.shader as a surface projection — no real volumetric depth, flat self-shadowing, and all cloud/weather uniforms routed to the same material as stars/atmosphere. This PR strips all cloud code from the skybox and moves it into a dedicated fullscreen render pass with proper volumetric raymarching.
New files
Assets/Shaders/VolumetricClouds.shader — Fullscreen URP shader using SV_VertexID fullscreen triangle. Reconstructs world-space ray directions from inverse camera matrices. Marches 32 shell layers (L1) / 24 (L2) using Beer-Lambert transmittance accumulation. Henyey-Greenstein phase function for forward scattering. Depth-based self-shadowing (outer shell lit → inner shell shadowed). All existing uniform names preserved exactly (_CloudScale, _Cloud2Coverage, _CloudDissolveOffset, etc.).
Assets/Scripts/Rendering/VolumetricCloudRenderPass.cs — ScriptableRendererFeature + ScriptableRenderPass injecting at RenderPassEvent.AfterRenderingSkybox. Sets _InvProjectionMatrix / _InvViewMatrix per frame; draws via DrawProcedural.
Modified files
DayNightSkybox.shader — Removed all cloud Properties, uniforms, CalculateCloudLayer(), CalculateClouds(), cloud compositing in frag(), cloud-tinted horizon haze, and unused Hash2D/ValueNoise helpers.
WeatherManager.cs — Added public Material cloudMaterial field. All _Cloud* SetFloat/SetColor/SetVector calls rerouted from _skyboxMaterial to cloudMaterial. Non-cloud skybox properties (_DayAtmosphereStrength, _HorizonHaze*, _StarBrightness) remain on _skyboxMaterial. Null-guarded with actionable warning.
DayNightCycle.cs — Added public Material cloudMaterial field. UpdateSkyboxMaterial() pushes _TimeOfDay, _SunDirection, _MoonDirection to both materials each frame.
WEATHER_SETUP.md — Added Step 7: create material, add renderer feature, assign to WeatherManager + DayNightCycle.
Routing summary
```
Before: WeatherManager → _skyboxMaterial (all cloud + atmosphere uniforms)
After:  WeatherManager → cloudMaterial   (_Cloud* uniforms)
        WeatherManager → _skyboxMaterial  (atmosphere, haze, stars only)
        DayNightCycle  → both materials   (_TimeOfDay, _SunDirection, _MoonDirection)
```
All WeatherProfile fields and transition logic are unchanged — only the material target changed.

RenderPassEvent.AfterRenderingSkybox runs after opaque geometry in URP, and this pass draws with ZTest Always (and doesn’t sample depth). As a result, clouds will render over scene geometry instead of being occluded by it. To match the intended behavior (“clouds can be occluded by game objects”), either (a) keep this event but render only where the depth buffer is at far plane (set fullscreen triangle depth to far and use an appropriate ZTest), or (b) sample _CameraDepthTexture and discard/attenuate where scene depth is closer.

// Build inverse projection/view matrices so the shader can reconstruct
// world-space ray directions from screen-space coordinates.

// GL.GetGPUProjectionMatrix accounts for platform-specific clip-space

Matrix4x4 invProj = gpuProj.inverse;
Matrix4x4 invView = cam.cameraToWorldMatrix; // camera → world (rotation + translation)
_material.SetMatrix("_InvProjectionMatrix", invProj);
_material.SetMatrix("_InvViewMatrix", invView);

_material.SetMatrix(...) mutates the shared material asset at runtime, so in multi-camera scenarios (camera stacking, SceneView + GameView, minimap cameras) the matrices can be left in the wrong state between cameras/passes. Prefer setting per-camera values via a MaterialPropertyBlock passed to DrawProcedural, or via cmd.SetGlobalMatrix (and read globals in the shader), to keep the material immutable.
