This 'per-feature' test is entirely unnecessary (I recently had the same argument with someone else in this very forum).
In fact, the OP had the right idea from the beginning in his original post. The OBB vs. plane test is the simplest 'separating axis test' of them all, as there is only one axis to test: the plane normal. Simply compute the projection of the box center and the projected radius (4 dot products and a few adds) and you're good to go (you also get penetration depth 'for free').
Testing each corner of the box is redundant and unnecessary.

@The OP: for the ray-OBB test, the axes to test are the box axes and the cross products of the ray direction (it's not called a 'normal' in this case) and the box axes, for a total of 6 tests in all. Remember to account for the fact that the ray projection is unbounded on one end.

OBB stqnds for Oriented Bounding Box.
AABB stands for Axis Aligned Bounding Box.
For ray-box, I prefer not to use the SAT, since most of the time, what you would be intrested in when doing a ray test, are the points and time of intersection, and the SAT isn't very good at that.
What I prefer to use, is the standard ray-axis aligned box test. For an OBB, you can simply translate the test into an ABB test, by applying the inverse-transform of the box to the ray.
so now, it's just a ray-ABB test. This is relatively easy, and I like the axis-interval reduction agorithm, which is an algo I discovered doing ray-tracing.
Basically, it's similar to the SAT, because it redce the problem into a series of 1D problems, and works on interval intersections. But it is used differently.
First of, imagine you reduce your box-ray test on the X axis alone, and you try to find the intersection interval.
the test becomes
```
bool RaySlabIntersect(float start, float dir, float min, float max, float& tfirst, float& tlast){    if (fabs(dir) < 1.0E-8)    {        return (start < max && start > min);    }    float tmin = (min - start) / dir;    float tmax = (max - start) / dir;    if (tmin > tmax) swapf(tmin, tmax);       if (tmax < tfirst || tmin > tlast)        return false;    if (tmin > tfirst) tfirst = tmin;    if (tmax < tlast)  tlast  = tmax;    return true;}Copy
```
then the full 3D test is simply
```
// Ray : [Start, Dir, 1.0f]// Box : [Min, Max]// t   : intersection parameter.bool RayAABBoxIntersect(Vector Start, Vector Dir, Vector Min, Vector Max, float& t){    float tfirst = 0.0f;    float tlast = 1.0f;   if (!RaySlabIntersect(Start.x, Dir.x, Min.x, Max.x, tfirst, tlast)) return false;   if (!RaySlabIntersect(Start.y, Dir.y, Min.y, Max.y, tfirst, tlast)) return false;   if (!RaySlabIntersect(Start.z, Dir.z, Min.x, Max.z, tfirst, tlast)) return false;    t = tfirst;    return true;}Copy
```
This test can then be extended to do OBB tests (either, the inverse rotation trick, or using the box's projection axes). Then the test can be extended to find swept OBB-OBB collisions, as well as sept OBB-triangle collisions (or any convex polygons and convex polytopes).
if you want the code it's simple, but for another time.

ok, for the OBB, I am not gonna use the transformation trick, but use the OBB planes directly.
```
// Ray : [Start, Dir, 1.0f]// Box : [P, H[3], E] (H[...] normalised).// t   : Intersection parameter.bool RayOBBoxIntersect(Vector Start, Vector Dir, Vector P, Vector H[3], Vector E, float& t){    float tfirst = 0.0f, tlast = 1.0f;   if (!RaySlabIntersect(Start * H[0], Dir * H[0], P * H[0] - E.x, P * H[0] + E.x, tfirst, tlast)) return false;   if (!RaySlabIntersect(Start * H[1], Dir * H[1], P * H[1] - E.y, P * H[1] + E.y, tfirst, tlast)) return false;   if (!RaySlabIntersect(Start * H[2], Dir * H[2], P * H[2] - E.z, P * H[2] + E.z, tfirst, tlast)) return false;    t = tfirst;    return true;}Copy
```
So, it's simply projecting the box and ray onto the three axes of the box, and reducing the intersection interval.

To transfer the algo onto a OBB-OBB test, it will be simpler to explain the AABB-AABB test first.
Imagine two boxes A and B of size 'a' and 'b' colliding.
Now imagine the box A shrunked by 1.0f (call it A'), while box B is expanded by the same amount (call it B'), but the velocities do not change. It can be proven that the time A and B collide is the same that the time A' and B' collide. This is because the distance separating the boxes hasn't changed, so the time of collision wil remain the same.
It's easy to see if you had the two boxes sliding on a table.
Now, if you reduce box A to a point, then box B' will have size 'b - a'. A is reduced to a ray, which we can test against B', and the time the ray intersect B' will be same as the time A collided with B.
```
// A : [Apos, Aext, Adir, 1.0f]// B : [Bmin, Bmax]// t : intersection parameter.bool RayAABBoxIntersect(Vector Apos, Vector Aext, Vector Adir, Vector Bmin, Vector Bmax, float& t){    float tfirst = 0.0f;    float tlast = 1.0f;   if (!RaySlabIntersect(Apos.x, Adir.x, Bmin.x - Aext.x, Bmax.x + Aext.x, tfirst, tlast)) return false;   if (!RaySlabIntersect(Apos.y, Adir.y, Bmin.y - Aext.y, Bmax.y + Aext.y, tfirst, tlast)) return false;   if (!RaySlabIntersect(Apos.z, Adir.z, Bmin.z - Aext.z, Bmax.z + Aext.z, tfirst, tlast)) return false;    t = tfirst;    return true;}Copy
```
the box A in described as a position-extent, as it makes it easier to explain. Note that, I am considering the Box B as being static. If it is moving, the test is exactly the same (just replace (Adir) by (Adir - Bdir)).
this is for the AABB test.
for the OBB test, it is similar in many respects. All those tests are the same, the trick is to decompose the boxes along the axes of projection.
to simplify the test, I'll need to projection functions.
```
void ProjectOBBoxOnAxis_PosExt(Vector Axis, Vector C, Vector H[3], Vector E, float &pos, float& ext){    pos = C * Axis;    ext = fabs(H[0] * Axis) * E.x + fabs(H[1] * Axis) * E.y + fabs(H[2] * Axis) * E.z;}void ProjectOBBoxOnAxis_MinMax(Vector Axis, Vector C, Vector H[3], Vector E, float &min, float& max){    float pos, ext;    ProjectOBBoxOnAxis_PosExt(Axis, C, H, E, pos, ext);    min = pos - ext;    max = pos + ext;}Copy
```
now, the OBB-OBB is simple...
```

   ProjectOBBoxOnAxis_PosExt(Axis, PA, HA, EA, pos, ext);    ProjectOBBoxOnAxis_MinMax(Axis, PB, HB, EB, min, max);    return RaySlabIntersect(pos, dir, min - ext, max + ext, tfirst, tlast);}// Box A : [PA, HA[3], EA, DA, 1.0f]// Box B : [PB, HB[3], EB, DB, 1.0f]bool OBBOBBCollide(Vector PA, Vector HA[3], Vector EA, Vector DA, Vector PB, Vector HB[3], Vector EB, Vector DB, float& t){    float pos, ext;    float min, max;    float tfirst = 0.0f, tlast = 1.0f;    if(!OBBOBBCollide_Axis(HA[0], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[1], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[2], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HB[0], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HB[1], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HB[2], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[0] ^ HB[0], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[0] ^ HB[1], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[0] ^ HB[2], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[1] ^ HB[0], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[1] ^ HB[1], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[1] ^ HB[2], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[2] ^ HB[0], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false;    if(!OBBOBBCollide_Axis(HA[2] ^ HB[1], PA, HA, EA, DA, PB, HB, EB, DB, tfirst, tlast)) return false; tfirst and tlast track, respectively, the greatest of all values of t where the linear component enters a slab, and the least of all values of t where the linear component leaves a slab. If after intersecting with all slabs tfirst is >= tlast, the component has been entirely clipped away and there is no intersection.
As far as intersection of linear components goes, the approach can be generalized to work with a variety of convex shapes. Also, as oliii has pointed out the method can be leveraged for intersection testing between moving objects, where it becomes an expression, more or less, of CSO raytracing.

I'm on a 56k modem, so I am a bit slow for explainations :)
the fastest method would be to transform the point into the box's space, ans then test containement with a unit axis-aligned box. This is very quick if yo uhave the whole box stored in a 4x3 matrix form.
But realistically, the SAT is fine (and is kinda what the inverse transform does anyway).
about the code. The 'slab' method is relatively simple to understand. A box is the intersection of three slabs. When you test intersection with a ray, the ray will intersect the box if each slab intersection interval intersects too.
Each ray-slab intersection generates an interval [t0, t1]. The ray intersects the box if the three intervals themselves intersect. By tracking and reducing the [tfirst, tlast] interval, you effectively make sure that those 3 intervals intersect, and the result of those 3 1D intersections gives you the time the ray enters the box, and the time the ray exits the box (which isn't really that intresting in general).
't' tells you when the ray hits the box.
Then you can use 't' in a test against another box, to find which object is intersected first (the test that returns the smallest t).
If the ray starts from inside the box, t will be automatically set to 0.0f.
the initial range [0, 1] is used to make sure the box is in front of the ray, and not too far away.
The 'Dir' component is not normalised. The ray I use is in a parametric form, where the start point is Start, and the end point is (Start + Dir). In fact, this is the reason why the max bound is set to 1.0f.
If you use a normalised ray, with a maximum length, you simply change the tlast's initial value from 1.0f to the ray's length (that you can pass as a parameter in the intersect function).
The slab intersect function is the basic 1D intersection method, which is the simplest element you can use to reduce the test.

There's no nagic, an OBB is a transformed AABB, an AABB is an inverse-transformed OBB.
If you don't have a matrix representation, and your OBB is in the form [P, D[3], E], where P is the position, D[3] are the 3 axes of the OBB (it's orientation), and E the extent along each axes, and given a point V' (say, your ray position) in world coordinate, you get V in local coordinates like so...
Matrix inverse_rotate = Matrix(D[0], D[1], D[2]).Transpose();
Vector inverse_scale = Vector(1 / E.x, 1 / E.y, 1/ E.z)
Vector inverse_translate = Vector(-P.x, -P.y, -P.z)
V = ((V' + inverse_translate) * inverse_rotate).Scale(inverse_scale);
using matrices...
V' = V * [Ms] * [Mr] * [Mt]
Ms = Scaling matrix of the OBB
Mr = Rotation matrix of the OBB
Mt = Translation matrix of the OBB
=> V = V' * [Mt]' * [Mr]' * [Ms]'
([]' = inverse of the matrix).
