Finding
A v4→v5 module parity scan (weighted by usage across 434 shipped v4 example networks) turned up one gap that is not scattered attrition but a single coherent user-facing capability: v4's texture/volume-rendering pipeline.
All seven modules are dormant, not missing — the source is still in the v5 tree, commented out of the build.

Why this one stands out
Of the ~69 modules in the actionable v4→v5 gap, these seven are unusual on three counts at once:
They form a complete capability. Not seven unrelated utilities — a pipeline: build a texture from nrrds/fields, edit a 2D transfer function, render it as volume/slices/surface.
They were widely used. The top two appear in 6.5% of all shipped v4 networks, which puts them among the most-used modules absent from v5. CreateAndEditColorMap2D (2D transfer function editing) at 18 networks has no v5 equivalent at all.
The code is still here. Dormant, not deleted — so this is a revival problem, not a from-scratch reimplementation.
If any single missing capability contributed to v4 users not upgrading, this is the strongest candidate the data produces. It also lines up with volume rendering having its own long-running thread (#851) and the Ospray work.
Suggested work
Assess how much of the dormant code is salvageable against the v5 renderer versus how much assumes v4's texture/spire-era infrastructure. Realistically the algorithm/transfer-function side ports more cleanly than the rendering side.
Decide the target renderer before writing anything — this intersects the OSPRay work (Placeholder for volume rendering--was: Test Tuvok with SCIRun 5 #851) and the VTK renderer direction. Reviving these against a renderer we are moving away from would be wasted effort.
Treat CreateAndEditColorMap2D as potentially separable — a 2D transfer function editor has value independent of which backend does the rendering.
Caveat
This is an inventory finding, not a behavioural one. "Dormant code exists" does not mean it still compiles or works; it means the starting point is source rather than a blank file.
