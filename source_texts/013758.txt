Hi RaC,
again thank you for informing us about this bug. The problem has to do with the fact that matlab's imagesc command will show the first array dimension along the vertical axis (intuitive y axis) and the second array dimension along the horizontal axis (intuitive x axis). As we wanted to have the other behavious (first dim along x, second dim along y) we usually interchange those dimensions in the code. In the ray tracer we forgot to do so.
We decided to fix this problem by changing line 67 to
% Save the numbers of planes.
[yNumPlanes, xNumPlanes, zNumPlanes] = size(cubes{1});
Your bug report also made me realize two more problems ydd night:
we had issues with anisotropic vixel resolutions in x and y direction
we had an offset of 0.5 voxels in the calculation of the geometrical distance of voxels from the virtual radiation source
However, this problem could be fixed by adjusing the functions matRad_calcParticleDose and matRad_calcPhotonDose in line 124 and 128 respectively
% generate meshgrid with CT position [mm]
[X_geo,Y_geo,Z_geo] = meshgrid(ct.resolution(1)(1:size(ct.cube,2)),...
ct.resolution(2)(1:size(ct.cube,1)),ct.resolution(3)*(1:size(ct.cube,3)));
Besides that I tried to clean some of the code so it might make sense for you to update your source to the latest version at some point. The changes are already live in the dev and master branch.
Again thank you very much for pointing this out. It helped a lot to improve the ray tracing algorithm.
