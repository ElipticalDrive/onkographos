The fourth occurrence of the trap TriangleTree was the third of, found by the sweep
#415 asked for.
Core/Vixen.Core.Mathematics/Ray.cs:135 is Möller–Trumbore with an absolute epsilon on the
determinant:
```
var perpendicular = Vector3.Cross(Direction, edge2);
var determinant = Vector3.Dot(edge1, perpendicular);

// Parallel to the triangle's plane.
if (MathF.Abs(determinant) < MathUtil.ZeroTolerance) {
    return false;
}
```
The determinant is edge1 · (Direction × edge2), so it carries the model's units squared and the
direction's once. MathUtil.ZeroTolerance is 1e-6f and absolute, so this is not "the ray is
parallel to the triangle" — it is "the triangle is smaller than one millimetre of edge, so it cannot
be hit at all". That is the identical mistake TriangleTree.Raycast carried, fixed in
TriangleTree.cs:601 by testing determinant² <= ZeroTolerance² · |edge1|²·|across|² — a squared
cosine, dimensionless.
⚠ This one is in the editor's hands rather than in a bake. The four callers are all picking:
Editor/Vixen.Editor.SceneView/ScenePicker.cs:487 and :516
Editor/Vixen.Editor.SceneView/SubObjectPicker.cs:413
Editor/Vixen.Editor.SceneView/SceneProbe.cs:590
So the symptom is a small prop that cannot be clicked, or a sub-object selection that goes through
a mesh authored in centimetres, with no error anywhere — which is the shape of bug this repository
loses days to. Whether it bites depends on |edge1| · |Direction × edge2| at the scales the editor
actually sees; a ray direction that is unit and a triangle whose edges are ~1e-3 puts the determinant
at ~1e-6 and straight into the refusal.
Occurrence history, all the same class — a cross product's magnitude scales as the square of the
model and MathUtil.ZeroTolerance is an absolute length:
EditMesh.Normal — fixed
ManifoldMesh.TriangleNormal — fixed
TriangleTree.Raycast — fixed, and it is where the relative predicate is written down
Ray.Intersects(Vector3, Vector3, Vector3, out float) — this
Done looks like the relative predicate TriangleTree.cs:601 already carries, plus the same
treatment for the returned distance (which TriangleTree also fixed: distance is in units of
Direction, so an absolute epsilon on it is a metric statement) — and a scale sweep over a picking
ray that is red before the change. ⚠ TriangleTree's fix was measured, not asserted: at 1/1024
scale five of nine shapes charted differently. The same measurement is what would make this one
credible rather than plausible.
Not fixed here deliberately. Found while checking #415's sweep; widening that change into a
second assembly with four editor call sites is the thing the working agreement says to file rather
than do.
