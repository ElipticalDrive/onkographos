Shapes:
- Ray/Box: axis-parallel rays missed every box, as a zero direction
  component resulted in a zero inverse direction instead of infinity.
  Rewrite the slab test in double precision with explicit handling of
  parallel slabs. This also fixes CompositeShape, HeightMap and Octree.
- Box::intersect(Box): fix z-axis typo (c1.y instead of c1.z).
- Box::getMaxRadius: use the farthest corner instead of max(|min|, |max|).
- Box::enclose: clear the mesh before regenerating it.
- Shape::intersect(Ray): implement Moller-Trumbore instead of throwing,
  so CompositeShapes with mesh children support ray queries.
- Shape::intersect(sphere): use the exact closest point on each triangle
  with a plane-distance early-out; the old projection was wrong for
  points behind a face.
- Shape::contains: use the generalized winding number, which is robust
  for duplicated vertices and rays hitting edges/vertices.
- HeightMapNode::intersect: return the nearest hit, not the first child.

Sensors:
- LaserRangeFinder: do not cull by range when range_max is 0 (no limit),
  floor beam indices, and support angle ranges beyond +/- pi.
- DepthCamera: fix heap corruption when the image height changes between
  calls (resize vs assign), clamp interpolated inverse depth to avoid
  negative/huge depths on slivers, render pixel row/column 0, and add
  bounding sphere vs view frustum culling.

Add test_collision and test_sensors covering all of the above.

Float-cast pruning bound rejects closer hits
src/​HeightMapNode.cpp:77
Casting the nearest double distance to float can round the pruning bound downward and reject a closer child. With grid {{1,0},{1,0}}, resolution 1, a ray from (100000011,0.5,0.5) along (-1,0,0), and t1=2e8, the first hit at 100000010 rounds to 100000008. The nearer hit at 100000009 is then rejected. Round the bound upward conservatively, or pass the original t1 and compare distances as doubles. The suggested fix uses the latter approach, sacrificing nearest-hit pruning for correctness.
Quantized beam indices incorrectly cull visible lines
src/​sensors/​LaserRangeFinder.cpp:74
The normalized indices can make the half-circle test below select the wrong interval and cull a visible line. With angle limits [-1,1], 21 beams, and ordered unit-circle endpoints at angles 0.05 and -3.12, the indices are (11,42). Their difference equals i_half_circle_, so the wrap-around branch rejects the line as back-facing, even though beam 11 intersects it at distance 0.22137. The previous implementation renders this hit. Determine wrapping and facing from unquantized angles or segment orientation rather than rounded beam-index differences, and add this regression test.

Use cross products to preserve precision in thin triangle queries
src/​Shape.cpp:103
The dot-product differences used for va, vb, and vc lose precision on nonzero-area slivers, causing false negatives in both contains() and sphere intersection. For triangle (0,0,0), (1,0,0), (1,1e-6,0) and interior point p=(0.75,5e-7,0), the calculated closest point is about 6.94e-6 away, so contains(p) and intersect(p, 1e-6) both return false. With a thinner triangle, cancellation can also make vc zero and incorrectly select this edge branch. The zero-area fallback does not cover either case. Compute all three area weights using cross products, as suggested, and add regression tests for both queries.

The weights va, vb and vc were calculated as differences of products of
dot products (Ericson), which cancel for thin triangles. For the sliver
(0,0,0), (1,0,0), (1,1e-6,0), a point on it was calculated to be 6.9e-6

which is the same value by Lagrange's identity.
