For debugging purposes (e.g. comparing two caches) it would be great to have an option where the random number generators are made deterministic.
A part of the story is the actual random number generators. They can be seeded using srand(), srand48[_r](), seed48[_r](), lcong48[_r](), initstate(), setstate() etc. Since we have a hashing algorithm in the supervisor but not in the interceptor, scproc_query could respond with the seed value to use (based on process args etc.), if any. This kind of random is probably not widely used by compilers, though.
Another part of the story is mktemp() and friends. In glibc they rely on the pid and current time, rather than pseudo-random. So they need to be reimplemented, presumably on top of the seeded rand() family. It looks quite easy to reimplement them. Just replace XXXXXX with random characters up to a hardwired maximum number of attempts, try to create with O_EXCL and see if it succeeds. Continue trying if it fails with EEXIST, bail out immediately if it fails with anything else (e.g. parent directory does not exist, or permission problems).
