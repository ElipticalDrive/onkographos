v0.12.000
Engine: the full VO refinement ladder (implemented)
Frame-to-frame ICP (default, shipped in v0.11).
D1: global pose-graph optimization + loop closure (Open3D multiway) — opt-in LIDAR3D_OWN_GLOBAL=1.
TSDF volumetric fusion (KinectFusion-style denoised surface) — opt-in LIDAR3D_OWN_TSDF=1.
Correlation pose head (RAFT/TartanVO-style) as a --pose_head corr option.
Honest findings (documented)
D1/TSDF need sub-voxel pose accuracy; at ~0.37 m monocular ATE they over-constrain / fuse sparsely, so ICP-refined accumulation stays the default (they are one flag away).
The correlation pose head is a negative result (better per-pair pose, worse accumulated ATE); archived, not deployed.
More TUM data (5 -> 11 seq) did not beat the 0.37 m ceiling; the model is at its architectural limit.
Fixed a checkpoint-clobbering bug (unique per-run timestamped archives) after it cost us the 0.37 m weights (deployed artifacts were safe).
Documentation (repo + web), always the whole flow
Web: Methodology "Our model" tab, Implementation "Our model pipeline" tab, Benchmark now shows OUR model in the ladder + D1/TSDF marked IMPLEMENTED + an "8 scenes + real held-out ATE" table.
Repo: a local usage guide (train -> bake -> refinement ladder -> add scene -> verify), a datasets page (formats, real intrinsics, licenses, bigger-data roadmap), the real 14-scenario cases matrix (replacing the template placeholder), a layer-by-layer architecture reference, and the full R1-R5 experiment record.
Scenes are unchanged (the verified 0.37 m model's baked artifacts); this release ships the VO stack + the documentation depth.
