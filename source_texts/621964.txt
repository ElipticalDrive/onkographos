🔬 💻 🚀 Feature
Hi all,
following up earlier discussions (with @sofroniewn, @tlambert03, @GenevieveBuckley, @jni and @VolkerH ), to improve performance when processing 3D image data, I'd like to send GPU-backed 3D arrays into vispy without turning them into a numpy-array on the way.
Motivation
Vispy is based on OpenGL and thus, does the heavy computing on the GPU anyway. If we use GPU-accelerated image processing, we should not transfer image data between CPU and GPU memory while processing and viewing to get maximum performance. Thus, it might make sense to "bypass" napari and making vispy handle GPU-backed arrays. This should be relevant for users of CUDA and OpenCL based image processing libraries such as cupy, pyopencl and pyclesperanto.
Pitch
There might be at least two ways for implementing this:
Either we prevent lines like this one where image data is explicitly turned into a numpy array. We could then pass GPU-backed arrays through napari into vispy. Also the thumbnail generation might need to be changed then. This solution has the pre-requesite that vispy accepts CUDA/OpenCL-backed arrays. If so, memory management is on our side.
Alternatively, we use the memory management from vispy and get access to GPU-backed array pointers and pass them to the outside
I've no preference for one of the two alternatives though.
Furthermore, we need to make sure that OpenGL is compatible with OpenCL and CUDA. Links provided by @tlambert03 in this image.sc thread appear to me like this should be feasible. We nevertheless might want to offer some convenience layer for this stuff. If we are clever engineers, we could make all this stuff happen in a napari-plugin named e.g. "napari-gpu-backed-layers".
Additional context
To demo the current state, I implemented a small realisitic use-case script that loads 200 MByte 3D data (355x710x213 voxels, float32), segments nuclei and shows intermediate results + final labels in napari. It does some basic time measurements:
```
# process the image
intermediate = cle.top_hat_box(input, radius_x=5, radius_y=5, radius_z=5)
result = cle.voronoi_otsu_labeling(intermediate, spot_sigma=1, outline_sigma=2)
stopwatch("image processing")

# add it to napari
viewer.add_image(cle.pull(intermediate))
stopwatch("Showing background subtracted input in napari")
viewer.add_labels(result)
stopwatch("Showing the result in napari")
```
Output:
```
image processing  takes time:  0.4350242614746094  s
Showing background subtracted input in napari  takes time:  0.5765478610992432  s
Showing the result in napari  takes time:  1.2743096351623535  s
```
As you can see, processing takes 0.4 seconds while visualizing results takes 1.8 seconds. I assume that bypassing some numpy-conversions could speedup the viewing.
Last but not least: I'm aware this project will take time. As soon as vispy and other libraries work on the same pointers, we will see napari crashing whenever we hit memory limitations. I'm happy to actively support/maintain code in this context. But I'm also clearly saying: My python/napari skill-level doesn't allow me to implement this alone. Nevertheless, I think it's worth to drive down that road and there is a 3D real-time image processing wonderland waiting for us ;-)
