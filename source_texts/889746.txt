Summary
Two implementations of the 3D-scanner idea from ideas/tony-stark-tech.md:
live_scan.py — Intel RealSense depth camera + Open3D TSDF volumetric fusion. Closest to Tony Stark's real-time "scan the object and spin it" workflow: RGB-D odometry aligns consecutive frames (no turntable/markers needed), fused live into a TSDF volume, exported to .ply (point cloud, optionally a mesh).
photogrammetry.py — classic structure-from-motion from an ordered photo sequence: SIFT feature detection → matching → essential matrix (RANSAC) → pose recovery → triangulation, chained frame-to-frame. Needs no special hardware, just photos.
test_photogrammetry.py — end-to-end test with no hardware required: builds a synthetic 3D scene, renders it into fake photos (each 3D point becomes a unique high-contrast textured patch at its true projected pixel), runs the real detection/matching/pose pipeline on those images, and checks recovered geometry against ground truth.
requirements.txt / requirements-photogrammetry.txt and README.md covering setup, usage, and known limitations for both approaches.
Test plan

Fix jarvis-web.html: mic never restarted for the spoken command
…
5fb4dca
```
Root cause of "hears jarvis but never shows what I said": the recognition
restart after saying "Ja?" created a brand-new SpeechRecognition instance
while the previous one was still asynchronously releasing the microphone
(recognition.stop() -> onend is async). Chrome's mic lock race meant the
new instance's start() would sometimes fail silently - no crash, no
result event, nothing to log - exactly matching the reported symptom
(wake detected, but the "Ti: ..." transcript line never appeared).

Fixed by keeping a single persistent SpeechRecognition instance for the
whole session (initRecognition(), called once) and a safeStart() guard
that only calls .start() when not already active, instead of
constructing a fresh instance on every restart.

Verified with a scripted flow simulation (fake SpeechRecognition/
SpeechSynthesis/fetch that model the real async start/stop timing):
wake-word -> "Ja?" -> command transcript logged -> Claude call -> reply
spoken -> back to listening, with zero start/stop race errors.
```

```
"nič ne zazna" (nothing detected at all) traced to two silent-failure
paths:
- startBtn's click handler went straight to SpeechRecognition without
  ever explicitly requesting the mic, so a permission denial or missing
  device just left the page sitting at "listening" forever with nothing
  actually captured and no visible error.
- safeStart()'s catch swallowed every start() failure, not just the
  expected InvalidStateError race, so a real problem (permission,
  no device) never reached the user either.

Fixes:
- startBtn now calls navigator.mediaDevices.getUserMedia() first, tied
  directly to the click; a rejection shows a clear Slovenian error
  instead of silently proceeding.
- onerror/safeStart now only swallow the two expected/benign cases
  (no-speech, InvalidStateError) and surface everything else (not-allowed,
  audio-capture, service-not-allowed, network, or anything unexpected)
  as a visible status error.
- Added a "Testiraj glas" button that speaks a fixed test phrase,
  independent of the microphone/recognition path, so voice output can be
  verified on its own.

Verified with scripted simulations (fake SpeechRecognition/
getUserMedia/SpeechSynthesis): the full wake -> command -> reply loop
still works with zero races, a denied-permission run now surfaces a
visible mic error instead of sitting silently in "listening", and the
test-voice button speaks independently of recognition state.
```
