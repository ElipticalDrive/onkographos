Owner and source contract
The original Sc static-plane contact path has no finite PxgIntegerAABB and therefore cannot appear in GPU SAP volumes or its found/lost report stream. Finite box pairs remain exclusively authored by GPU SAP; infinite-plane/dynamic candidates enter the same authoritative Sc pending-pair/EdgeIndex publication that the native scene already uses, without giving planes synthetic AABB bounds or an independent GPU pair registry. Original Gu plane/box narrowphase and Sc/Dy friction, island and solver work remain unchanged.
Runtime cost and scheduling
For scenes without static planes, the GPU pair stream follows its existing sparse found/lost processing and incurs no plane scans. For scenes with static planes, an actual Sc geometry/shape edit or finite pair-set change rebuilds the eligible plane/dynamic candidate membership alongside GPU-owned finite reports. The existing GPU PCM candidate/EPA, Dy GPU normal/friction row preparation, and source task partitioning remain unchanged. The mixed-contact fixture runs a CPU-origin Gu plane manager and GPU PCM box manager through one GPU Dy submission. Plane candidates have no finite GPU SAP endpoint transfers, GPU bitmap entries or descriptor allocations. No second broadphase implementation, speculative PCM path or CPU SAP fallback is introduced.
Integration evidence
The mixed-source test admits the same plane and box pairs in both actor creation orders, advances four physical frames, and checks that CPU Gu geometry and GPU PCM contact rows coexist in one GPU Dy task. It also disables and reenables the source plane simulation shape, verifies Sc contact-edge retirement/readmission, then retires the plane actor without leaving stale GPU-side finite pair membership. It verifies the existing single-span transfer, compact friction anchors, matched Sc contact identity, normal impulses, correlated friction patches and body motion against CPU PGS. Full independent Vulkan, D3D12, Linux and Windows CI is required before merger.
Redundancy and retirement
Retains the single Sc EdgeIndex and Gu manifold owner. Infinite planes are not admitted to the finite GPU AABB manager, so GPU shape admission, pose/offset dirties, simulation-flag toggles and retirement operate only on shapes with source AABB volumes. The GPU SAP finite overlap hash is reconstructed independently of Sc-only plane pairs during rollback, and GPU full-rebuild/refilter/delta paths all converge on the same Sc pair publication.
Source fidelity and deviations
Fidelity classification: semantics-preserving-lowering
PhysX source: Sc static-plane candidate admission, ScShapeInteraction/EdgeIndex ownership, Gu plane/box contact generation, Bp finite-volume found/lost report fetch, and DyContactPrep/PGS contact and friction solve.
Departures: infinite plane contacts are admitted by the original Sc special-case candidate path alongside GPU-fetched finite SAP overlaps; an infinite plane has no manufactured integer AABB or GPU shape handle. Device-only SAP remains authoritative for finite overlaps. The original Gu and Dy computation and persistent source EdgeIndex lifetimes are unchanged.
Parity evidence: mixed CPU plane Gu + device PCM box contacts, in both source actor admission orders, matched normal/friction impulses and rigid-body motion, plus existing independent Vulkan/D3D12 finite SAP and GPU PCM suites.
