Refs #69. The issue stays open: shadow, picking, collision, reversed/log depth and async sort remain.
What changes
Builder::splats returns early when the splats' bounding sphere misses the view volume, like X3DRenderObject.addDisplayShape. It reuses Builder::bbox_in_view.
A declared bboxSize/bboxCenter decides the culling.
The bboxDisplay box is a separate child and is not culled with the splats (already implemented).
4 CPU-only tests in crates/x3d-render/tests/splat_culling.rs: in view drawn, behind the viewer culled, far to the side culled, declared bbox decides both ways.
Author's run: cargo nextest -p x3d-render 108 passed, 0 failed, including the GPU test render_rea_b08_gs (the GS oracle comparison is unchanged). Required CI on the exact head is the merge gate.
Remaining parts of #69
castShadow / shadow bbox: needs a splat depth pass (GPU oracle) and an owner decision on the castShadow default quirk.
Picking and collision: need pick-probe oracles and a decision.
Reversed/log depth: needs the GPU depth-shader path and an oracle.
Async sort: owner decision on timing, large change.
