Two things cellmap-flow's browser app ran into, each its own commit.
Neuroglancer precomputed volumes in the browser reader. openSource (web/src/sources.ts) read zarr v2/v3, N5, xarray-style zarr and GeoTIFF, so a pasted precomputed://gs://flyem-male-cns/em/em-clahe-jpeg gave nothing. It now takes precomputed://…, or finds a volume by its info after zarr and N5. Each scale is a level, the x-first lists reversed to C order, voxel 0's centre at (voxel_offset + 0.5) × resolution nm as the Python reader places it (not the corner), channels first. Chunks are read unsharded (<key>/x0-x1_y0-y1_z0-z1) or sharded (neuroglancer_uint64_sharded_v1 with the identity hash: compressed Morton code → shard index entry → gzipped minishard index, read once per minishard → the chunk's byte range), encoded raw, jpeg (a chunk's z planes one tall image, decoded by createImageBitmap on an OffscreenCanvas with colour management off) or compressed_segmentation (uint32 and uint64); a chunk not stored is zeros. The parts that need no browser are in web/src/precomputed.ts so Node's tests run them. gs:// and s3:// sources of any format are read through their buckets' https URLs. Not done: the murmurhash3_x86_128 sharding hash (refused with an error; volumes use identity).
Checked against em-clahe-jpeg from Node: the sharded chain returns JPEG chunks, and edge chunks at scale 8 have exactly their clipped sizes (48 × 4096, 64 × 3200, 64 × 896, 48 × 3200), which pins the Morton order. The JPEG decode itself was not run (no browser in the sandbox).
The service worker leaves a store's metadata to the page. On a public site, a volume on a private-network host (10.x) failed with a bare "Failed to fetch": Chrome's Local Network Access refuses a service worker's fetch to such a host unless the visitor already allowed it, and only the page's own request can ask. metadata(url) (web/src/relay.ts) names .zattrs, .zarray, .zgroup, .zmetadata, zarr.json, attributes.json and info; sw.ts leaves those to the network, so the question comes up on the volume's first read, and caches only chunks. cellmap-flow's own service worker can import the same metadata.
Docs: docs/concepts/formats.md (what the browser engine reads), docs/concepts/caching.md (metadata not in the store cache), docs/design.md (metadata beside fromStore) and CHANGELOG.md. Checks on the branch: npm run check (typecheck, 31 node tests of which 3 are new, the Vite build), tests/test_docs.py and mkdocs build --strict.
