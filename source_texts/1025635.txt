Summary
Add a procedural pattern generation module that provides:
reusable math functions for pattern/noise sampling
2D texture generators built on top of those functions
3D volume generators built on top of those functions
Goal
Create a shared foundation for procedural asset generation so rieul3d can produce textures and volumes such as noise fields, masks, and debug patterns without relying on external image assets.
Motivation
This would be useful for:
example scenes and demos
test fixtures and debugging textures
procedural materials
future volume examples
renderer experiments that need generated source data instead of checked-in assets
Scope
add a math-focused layer for reusable pattern functions
support both 2D and 3D sampling where it is naturally defined
build 2D texture generators on top of that layer
build 3D volume generators on top of that layer
expose a small initial set of patterns/noise functions that can grow later
add tests for determinism, dimensions, value ranges, and basic output structure
document how the math layer differs from texture/volume baking APIs
Suggested Initial Coverage
Math / sampling layer:
value noise
Perlin noise
Simplex noise or a similar gradient-noise alternative
Worley / Voronoi noise
fBm
turbulence
ridged noise
domain warping helpers
2D-oriented generators:
checkerboard
gradients
UV/debug textures
noise-backed grayscale or color textures
3D-oriented generators:
noise volumes
Worley/cellular volumes
density-field style outputs for smoke/cloud experiments
Notes
not every pattern needs both 2D and 3D forms, but the architecture should make that distinction explicit
the main design goal is separating reusable math from baked output resources
CPU generation is a fine first milestone; GPU generation can be a later follow-up
