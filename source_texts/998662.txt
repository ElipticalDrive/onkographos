error log | 日志或报错信息 | ログ
On master c15904bb8918187ec100f1ebe708942af83b84be, CPU GridSample in nearest mode uses floor(coordinate + 0.5). PyTorch uses nearest-even rounding, so exact half-pixel coordinates can select a different pixel after successful PNNX conversion and native loading. This occurs with small finite coordinates entirely inside the input image; integer-coordinate controls match.
model | 模型 | モデル
```
import torch
import torch.nn.functional as F

class Model(torch.nn.Module):
    def forward(self, image, grid):
        return F.grid_sample(image, grid, mode="nearest",
                             padding_mode="zeros", align_corners=True)

image = torch.arange(5, dtype=torch.float32).repeat(5, 1).reshape(1, 1, 5, 5)
grid = torch.tensor([[-.75, 0.], [-.25, 0.], [.25, 0.], [.75, 0.]]).reshape(1, 1, 4, 2)
model = Model().eval()
print(model(image, grid))  # samples pixel coordinates .5, 1.5, 2.5, 3.5
# tensor([[[[0., 2., 2., 4.]]]])
torch.jit.trace(model, (image, grid)).save("grid.pt")
```
how to reproduce | 复现步骤 | 再現方法
Run pnnx grid.pt inputshape=[1,1,5,5],[1,1,4,2] fp16=0.
Feed the exact image and grid above to the generated PNNX model and the native Net inputs in0/in1 (omitting batch axis0 for native Mat). PNNX matches the PyTorch reference; native nearest sampling instead selects pixel indices 1,2,3,4.
Integer pixel coordinates remain correct. The same half-tie discrepancy is reproduced for both align_corners settings and for 2D/3D sampling.
Eight small Float32 TorchScript models give four matching integer controls and four incorrect half-tie cases; all PNNX outputs agree. Checked Windows CPU/PyTorch2.11/CPython3.14 with current converter and cached native binding whose relevant GridSample/runtime source inputs match master. No GPU, full suite, other hardware, ONNX or performance claim.
The generic and optimized CPU nearest-coordinate paths should use nearest-even rounding consistently. This is separate from the author-owned Vulkan implementation in #6474; it does not request a new sampling mode or change bilinear/bicubic behavior. Original GridSample work in #4288/#4373 remains credited to its authors.
