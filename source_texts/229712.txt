Hi, thanks for releasing PAGAS.
I was reading the code to understand how the Gaussian rendering path is chosen.
From what I can see:
PAGAS imports and calls the generic gsplat.rendering.rasterization(...) entrypoint in pagas/splat_ops.py.
The PAGAS config exposes scales_to_optimize_and_type_of_gaussians with options such as one_2d and two_2d, which seem to make the Gaussian effectively 2D by fixing the third scale to zero.
At the same time, the patched gsplat dependency appears to contain dedicated 2DGS-specific kernels/files such as rasterize_to_pixels_2dgs_fwd.cu and rasterize_to_pixels_2dgs_bwd.cu.
My question is: was it a deliberate design choice to use the generic/3DGS rasterization path in PAGAS rather than the dedicated 2DGS path in gsplat?
More specifically, I would like to understand:
Whether the current PAGAS code path already internally benefits from gsplat's 2DGS implementation in some implicit way, or whether it is strictly using the standard 3dgs rasterization path.
If it is strictly using the standard path, what was the reason for preferring that over the dedicated 2DGS path?
Was this choice made for correctness, stability, compatibility with the opacity/depth-threshold modifications, or simply implementation convenience?
Do you expect any accuracy or efficiency difference if PAGAS were adapted to use the dedicated 2DGS rendering path directly?
I m asking because PAGAS seems conceptually close to a constrained 2D Gaussian parameterization, so I wanted to better understand the renderer choice.
Thanks.

Thanks for the careful reading!
Yes, this was deliberate. PAGaS uses our modified 3DGS gsplat rasterizer, not the 2DGS one. The 1DoF PAGaS Gaussians are still 3D, just with reduced degrees of freedom: spheres whose radius depends on the pixel depth.
The scales_to_optimize_and_type_of_gaussians options were used for ablations. We found that one_3d (one optimizable scale, three total dimensions, i.e. spheres) gave the best quality and compute efficiency. An elegant simplification.
The 3DGS rasterizer also lets us ablate different Gaussian shapes, including near-2D ones by making one dimension almost zero. In contrast, the 2DGS rasterizer is limited to flat 2D Gaussians, such as disks or ellipses.
Hope this clarifies!
