Part of #68, part 2. Changes rendering on purpose: the regression baseline is regenerated after this PR.
Changes
math/Ray.h: the constructor no longer moves the origin by RAY_EPS along the direction (mOrig(orig + dir * RAY_EPS) → mOrig(orig)). Spawned rays already move their origin off the surface with OffsetRayOrigin (based on the hit point's error bound), so this second offset was redundant.
shape/Triangle.cpp: hit tests reject tHit <= 0 instead of tHit < 0 (as in pbrt), so a hit at exactly the ray origin is not reported. This was split out of Triangle: stop using Ray::mTmin; mark mTmin deprecated #69, which kept < 0 to stay byte-identical.
GyunityTest/tests/TransformTest.cpp: two expected ray origins included the constructor offset twice (2.0002 = 2 + 2×RAY_EPS). They now expect the exact values ((2,4,6) and (1,4,9)).
Not changed: the light tracer (LT.h) offsets its own rays by RAY_EPS. Switching it to SpawnRay is a separate step in #68.

BVH: only noise. The heatmap has no structure, so no acne and no light leaks along edges or corners.
kd-tree: the old renders were biased darker (most visible on the floor around the bunny's shadow and caustic). The new ones match the BVH.
BVH and kd-tree now agree. At 64 spp the two accelerators' images used to differ in 125,865 (mesh) and 25,618 (slope) pixels; now it is 431 and 295. The old double offset made the kd-tree return different hits than the BVH for some rays.
Testing
Rebuilt Gyunity, GyunityApp and GyunityTest in Debug|x64 and Release|x64 (VS 2026): no errors.
GyunityTest: 45/45 tests pass in both configurations (after updating the two TransformTest expectations above).
Renders: not byte-identical by design; see Results. The regression baseline is regenerated from this change.
