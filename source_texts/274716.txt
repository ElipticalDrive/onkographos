Summary
This PR improves @cornerstonejs/nifti-volume-loader for OHIF-style DICOM-derived NIfTI workflows.
The goal is to make NIfTI-backed studies behave closer to the original DICOM presentation and provide better feedback while large volumes are loading.
Why
In our workflow, NIfTI volumes are generated from source DICOM studies. Before these changes, several practical issues remained in the loader path:
window/level values were not preserved from source DICOM metadata
slice order along the Z axis could appear reversed relative to the original series
presentation could appear mirrored / visually incorrect
large NIfTI volume loads could leave the viewport blank for several seconds
viewer overlays had incomplete series/image metadata for NIfTI-backed stacks
What changed
Loader UX and download behavior
add a dedicated loading overlay with progress text and transferred size
keep the overlay visible until the first slice is actually ready
add optional parallel HTTP range fetching for large files, with fallback to the existing single-request path
Stack presentation / orientation
reverse frame mapping so the visible stack order matches the source DICOM Z-order more closely
apply a per-slice vertical flip to correct mirrored presentation issues seen in DICOM-derived NIfTI workflows
Metadata preservation
allow createNiftiImageIdsAndCacheMetadata(...) to accept optional dicomMetadata
register generalSeriesModule metadata from the provided DICOM context
register generalImageModule.instanceNumber for NIfTI-backed stacks
register voiLutModule and modalityLutModule metadata
expose windowCenter, windowWidth, slope, and intercept on created image objects so stack viewports can initialize VOI from preserved metadata instead of histogram defaults

Related OHIF integration
On the OHIF side, we also opened a small integration PR that passes DICOM metadata into the loader:
RadicalImaging/OHIF-FUBerlin#264
That integration PR is intentionally small; this PR carries the loader-side behavior.
Testing
validated locally in an OHIF-based viewer integration using DICOM-derived NIfTI studies
no dedicated upstream automated test was added in this PR
no full cornerstone3D package test/build run was executed yet in this local preparation, so this PR is opened as draft
