Proposed: 7 | Recommendations: 12 | Suites: cpp 760/760, py 737/737, rust 703/703
Proposed
C++ ray_mesh(Line, find_all=false) returned the first hit in FACE order, not the closest its header promises — session_cpp#16
polyline_plane lost (Rust) or duplicated (Python) any plane crossing landing on a polyline vertex — session_py#24, session_rust#19
polyline_plane_to_line now spans the extreme crossing pair, so a non-convex patch stops yielding an arbitrary sub-chord — session_py#24, session_rust#19
closed_and_open_paths_2d dropped joint runs collinear with a plate edge, which the winding number cannot classify — session_py#24, session_rust#19
Rust ray_box turned a grazed axis into NaN (INFINITY * 0) that f64::min then silently dropped — session_rust#19
Python used 1e38 for DBL_MAX, 1e-15 for DBL_EPSILON, and inverted the degenerate-normal verdict of _vectors_nearly_parallel — session_py#24
line_line_classified was untested in C++ and Python; ray_mesh, ray_box, polyline_plane and flush-joint edge cases now pinned in all three — session_cpp#16, session_py#24, session_rust#19
Review and merge: session_cpp#16, session_py#24, session_rust#19
then bump the parent submodule pointers.
Recommendations
C++'s stable two-step corner formulation never reached the ports: plane_4planes_open (intersection.cpp:5734 vs intersection.py:3806, intersection.rs:5366) and quad_from_line_top_bottom_planes (intersection.cpp:6211 vs intersection.py:4004) still use the 3-plane determinant C++ blames for 2-40 mm drift.
orthogonal_vector_between_two_plane_pairs uses the CGAL-canonical anchor in C++ (intersection.cpp:6243) and the midpoint-bisector anchor in both ports (intersection.py:4042, intersection.rs:5587) — the 0.5 mm top_to_side_box drift C++ fixed.
Fit tolerances run 10x-2000x looser in both ports: circle_tol 1e-4 vs 1e-5 (intersection.py:1395 vs intersection.cpp:1986), ell_tol 5e-3 vs 1e-5 (intersection.py:1537 vs intersection.cpp:2141), fit_tol missing the 5e-4 factor (intersection.py:1570 vs intersection.cpp:2179), fit_tol_uv step vs step*2e-3 (intersection.py:2189 vs intersection.cpp:4673).
Surface/plane tracer: coincident-chart guard (intersection.cpp:1615), Newton halve-retry and the 3-stage repair pass (intersection.cpp:1834) are C++-only; neither port has any of them.
Nine analytic-SSI capabilities are C++-only: coaxial cylinder/cone/sphere-torus, torus-torus (intersection.cpp:4059), plane-parallel-to-cylinder rulings, cone and torus pullbacks, exact hyperbola/parabola arcs, drop_point_sections (intersection.cpp:4750).
plane_plane_plane is OpenNURBS solve_3x3 with a pivot-ratio gate in C++ (intersection.cpp:453) and Cramer with |det|<1e-10 in both ports (intersection.py:248, intersection.rs:256).
curve_plane_algebraic and curve_plane_production are different algorithms in the ports (intersection.py:854, intersection.py:931 vs intersection.cpp:1239, intersection.cpp:1345).
Python adjacency_search is O(N^2) AABB-only (intersection.py:4700) where C++/Rust use a SpatialBVH broad phase plus OBB SAT (intersection.rs:7846), so it reports adjacencies the others reject.
Python and Rust ray_mesh_bvh rebuild a full BVH on every call (intersection.py:546) where C++ reuses the mesh's cached per-triangle BVH (intersection.cpp:807).
Rust Tolerance::ZERO_TOLERANCE is 1e-7 against 1e-12 in C++/Python (tolerance.rs:51), widening every on-plane band here by five orders of magnitude.
ssi_plane_plane, the finite-face-clipped plane/plane section, exists in C++ and Rust (intersection.rs:3313) but not Python.
Smaller drifts: closed_and_open_paths_2d projects on base1/base2 in C++ (intersection.cpp:5912) and x_axis/y_axis in the ports (intersection.py:4102); ray_sphere gates tangency on exact float equality in C++ (intersection.cpp:613) and 1e-10 in the ports (intersection.py:414); Python ray_mesh defaults find_all=True against C++'s false (intersection.py:513); Python face_to_face needs numpy (intersection.py:4366); Rust face_to_face clamps a negative coplanar_tolerance for the box gate but not the coplanar test (intersection.rs:6227).
Audit
PERFORMANCE: Python/Rust ray_mesh_bvh rebuild a BVH per call (intersection.py:546) against C++'s cached one (intersection.cpp:807); Python adjacency_search is O(N^2) (intersection.py:4700); the new extreme-pair scan is O(k^2) in crossings, k<=4 in practice (intersection.cpp:6188).
MEMORY: Rust cloned every vertex into a fresh triangle list twice per ray cast, now built once (intersection.rs:1097); C++ face_to_face bounds faces straight off flat coords with no Point copies (intersection.cpp:6610), which neither port does.
TESTS: line_line_classified had no C++/Python test (added); curve_plane, curve_plane_bezier_clipping, curve_plane_algebraic, curve_plane_production, curve_closest_point, plane_plane_to_line_canonical, line_two_planes, polyline_boolean, polyline_boolean_2d_in_plane, offset_in_3d, face_to_face, adjacency_search and cut_curves_on_surface are untested in all three (intersection.h:391).
READABILITY: C++ states its constraints inline — intersection.cpp:5812 explains the on-plane-vertex rule both ports were missing — while Python annotated polyline_plane_to_line(align_start: bool) then indexed it as a Point (fixed).
MINIMAL VERBOSITY: Rust duplicated 15 lines of triangle flattening between ray_mesh and ray_mesh_bvh (fixed, intersection.rs:1097); Python keeps legacy aliases get_quad_from_line_topbottomplanes (intersection.py:3842) and get_orthogonal_vector_between_two_plane_pairs (intersection.py:3896) with no C++ counterpart.
ALIGNMENT: the ports track C++ across the ~20 primitive entry points but miss nine analytic-SSI capabilities (intersection.cpp:4059), the tracer repair pass (intersection.cpp:1834), four tightened fit tolerances (intersection.cpp:2179) and three stable plane formulations (intersection.cpp:5734).
