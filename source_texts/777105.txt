The viewer twin of the Qt PrincipalDirectionDiagram (src/apeGmsh/viewers/diagrams/_principal_glyph.py). A new Principal card draws, at each Gauss point of a .ladruno stress or strain field, an arrow along each principal direction. The length follows |p|, and the colour is the signed value on a diverging map (RdBu_r over −max..max), so tension and compression read apart.
It needs lock:types.ts, lock:reduce.ts and lock:app.ts, which T will place.
Data path
A .ladruno Gauss group is one RESULT × one element class (stress/31-FourNodeQuad[…] with stress/sigma11, sigma22, sigma12). One tensor field is one RESULT's groups.
state/tensor.ts maps the fork's spellings to Voigt slots (sigma12, eta12, eps23, sigma_xy, gamma_xy, stress_xx, case-insensitive). These are Python's _CONTINUUM_DIGIT_RE/_AXIS_RE, restricted to stress and total strain. A group needs xx, yy and xy; otherwise the card refuses it by name.
main/results.ts: the step request gains tensor?: string[], answered as tensor[component][groupId]. It has the same verified-file gate as element, so a contour's element read is untouched. effects.ts asks for it only while the card is on.
Positions come from the Gauss-marker layout (GaussLayoutBuilder, shownElementOf, now shared with gaussLayoutOf). Hidden and inactive elements are left out, and each point keeps its (group, row) for the value join. The arrows follow the deformed shape through gaussDisplacements.
Math (eigenSym3, cyclic Jacobi). It follows Python's principal_frame:
strain shear is halved (the file's is engineering);
a zz the element does not record is 0 (plane=None: plane stress for σ, plane strain for ε), and the card says so;
values are sorted p1 ≥ p2 ≥ p3;
each eigenvector is flipped so its largest component is non-negative (_canonicalize_eigvec_sign).
No plane/ν recovery in this PR.
Glyphs
They use the shared arrow engine. The record gains anchor (ARROW_STRIDE 15, ANCHOR.tip | ANCHOR.tail, index 14), and the shader moves a tail-anchored tip by the drawn shaft L. The Vectors card (branch claude/vectors-card-f29996) adds the identical field and constant, so whichever lands second takes the other's engine hunks.
axis draws two tail records ±v, a head each way, centred on the point (the default; the sign isn't physical). arrow draws one along the canonical v, as in Qt.
Length is |p|/max × 0.1·radius × scale, inside the shared pixel band. Principals below 1e-6·max are noise and dropped, which removes a plane element's zz.
Thinning is per Gauss point: all of a point's arrows show and hide together.
A group recording both stress and strain feeds both fields; a field whose every group is refused stays on the card with its reasons.
State/UI
s.principal {on, field, show[3], head, cmap, scale, headSize, thin, measured}.
One event, setPrincipal (98 → 99), plus cmd:toggle-principal in Spotlight.
The #principal card follows the Reactions template: field, p1/p2/p3, axis/arrow, cmap, scale, head, thin-out, and a compression … tension ramp over −max..max of the step. Its CSS twins sit beside #reactions, and panelIds and the left-rail test are updated.
Tests (no native .results.h5; all .ladruno):
test/tensor.test.ts: closed forms (diagonal; Mohr's circle values and tan 2θ; pure shear; R·diag(5,2,−1)·Rᵀ with an Euler R; hydrostatic orthonormality), naming, field grouping and refusal, strain halving.
test/results/ladrunoPrincipal.test.ts: every Gauss point of fixtures/ladruno_quad2d.ladruno (stress and strain, step 1) against Python's principal_frame. The committed oracle ladruno_quad2d.principal.oracle.json is written by tests/fixtures/ladruno/make_viewer_principal_oracle.py. Points are matched by (element, natural coords), because Python's slab is GP-major while the app is element-major. Also covers the record counts, anchors, ± axis pairs, per-point thinning, and red tension against blue compression.
test/principalCard.test.ts: reducer validation, the step fetching tensor only while on, the layer (24 points × 2 in-plane × 2 heads, scrub keeps, off hides), deformed tails, and the card's dispatches.
Known limit: points skipped because a tensor value is not finite, or a corner node is not in the node table, draw nothing and are not counted on the card. With a single event (setPrincipal), no measured count reaches the state.
Gates: tsc --noEmit clean, npm run lint clean, npm test 1456 pass / 0 fail (at ee164de), check_app_wall ok.
Stills (ladruno_quad2d, step 2/2, driven over CDP) are in the shared notes folder: principal-stress-axis.png (top view, axis heads) and principal-strain-arrow-orbit.png (strain, one head, orbited).
Review: Opus "changes" on 54e39b2, fixed in ee164de (see the comment); delta re-review pending.

The viewer twin of the Qt PrincipalDirectionDiagram. A new Principal card
draws, at each Gauss point of a .ladruno stress or strain field, an arrow
along each principal direction. Its length follows |p|, and its colour is the
signed value on a diverging map (RdBu_r over -max..max), so tension and
compression read apart. The card offers axis (a head each way) or arrow (one
head along the sign-canonical direction), p1/p2/p3 switches, the field, cmap,
scale, head size and thin-out, and it follows the deformed shape.

- state/tensor.ts: the fork's component spellings (sigma12, eta12, eps_xy,
  gamma_xy, stress_xx) mapped to Voigt slots, one field per RESULT, and a
  Jacobi eigen decomposition of a symmetric 3x3. It follows Python's
  principal_frame: strain shear halved, a missing zz taken as 0, values
  descending, and each vector's largest component made positive.
- state/principal.ts: the field's points placed by the Gauss-marker layout
  (hidden and inactive elements left out), the value join by (group, row),
  and the arrow records, thinned per point.
- main/results.ts: the step request gains `tensor` (several Gauss components
  by component, then group), under the same verified-file gate. effects.ts
  asks for it while the card is on.
- Arrow engine: the record gains `anchor` (ARROW_STRIDE 15, ANCHOR.tip |
  ANCHOR.tail), the same field the Vectors card adds. A tail-anchored tip
  moves by the drawn shaft L in the shader.
- State: s.principal, setPrincipal and principalMeasured (events 98 -> 100),
  the Spotlight toggle, and the #principal card with its CSS twins.

Tests:
- tensor.test.ts: closed forms (Mohr's circle, pure shear, a rotated 3-D
  tensor, hydrostatic) and the naming.
- results/ladrunoPrincipal.test.ts: every Gauss point of ladruno_quad2d
  against Python's principal_frame (a committed oracle from
  tests/fixtures/ladruno/make_viewer_principal_oracle.py).
- principalCard.test.ts: the reducer, step fetch, layer, deformed tails and
  card.

No native .results.h5 fixture is used.

Review-verdict: opus changes 54e39b2
The Opus review checked eigenSym3 against numpy's principal_frame on 3,003 random, near-degenerate, 2-D and extreme tensors: worst value error 1.7e-15 relative, with no direction or sign mismatch where the values are distinct. It confirmed the Gauss join by probe (hiding 2 of 6 elements: 24 → 16 points, each row exact). The fork's spellings, the step read, the stale-request keys, the engine stride and the layer cache keys came out clean.
How each finding was handled, in ee164de:
A group recording both tensors was refused, and a field whose every group was refused disappeared silently. Fixed: tensorFields splits a group by family, a slot named twice refuses only that family's group, and fully refused fields are kept so the card shows their reasons. Not fixed: points dropped for a non-finite tensor or an unplaced corner are still not counted on the card, because the only channel for that count was the principalMeasured event (see 2).
Stale measured range and point count. Gone. The orchestrator's one-event rule removed principalMeasured (99 events), so the card no longer shows a measured range. The ramp reads compression … tension over −max..max of the step.
Units on the ramp numbers. Gone with 2: the card shows no numbers.
Two untested load-bearing changes.
Sign canonicalisation: new principal_random.oracle.json (Python's principal_frame of 300 seeded random 3-D tensors), checked as signed vectors in test/tensor.test.ts. Mutating the canonicalisation to return v; fails it.
Shader anchor: the field comes from [V] apeGmshViewer: an arrow record can anchor its tail at the point #2815 (the Vectors card's anchor PR), whose hunks this branch will take on merge, so its test belongs there.
The fork's BezierTet10 sigma_zx/gamma_zx are dropped by Python (continuum_canonical gives stress_zx, which _derived._SUFFIX_SLOTS never reads), while the viewer maps them right. This is an upstream Python bug, to be filed as a follow-up.
Gates at ee164de: tsc clean, lint clean, npm test 1456 pass / 0 fail.
