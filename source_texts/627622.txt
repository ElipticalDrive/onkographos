This PR adds two new creative features to voxelizer-rs:
SDF Noise (--sdf-noise): Integrates 3D Perlin noise to procedurally displace the Signed Distance Field. This allows users to generate bumpy, organic, or textured variations of their input meshes.
Voxel Slicing (--slices): Exports the generated 3D voxel grid as a sequence of 2D image slices (PNGs). This is extremely useful for visual inspection and debugging of the voxelized output without needing specialized point cloud viewers, and aligns with common SLA printing/volumetric display formats.
Dependencies on noise (v0.9) and image (v0.25) were added to Cargo.toml. The MeshProcessor::voxelize method was refactored to streamline particle addition logic.

Write PNG slices incrementally to avoid OOM
The slice export path allocates every z layer in memory at once via vec![RgbaImage::new(width, height); depth as usize], so peak memory scales with the full 3D volume instead of a single 2D image. For larger grids this can consume gigabytes and fail before any PNG is written, making --slices unusable for high-resolution runs; generating and saving one slice at a time would avoid this.

Validate sdf noise amplitude before applying it
Noise is added to SDF values without any finiteness check, so passing a non-finite value like --sdf-noise NaN propagates NaNs into sdf and causes keep comparisons to fail in volume mode, yielding an empty voxel output with no explicit error. This should be validated similarly to resolution/narrow_band to prevent silent data loss.
