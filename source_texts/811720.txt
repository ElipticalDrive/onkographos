Summary
Adds Game.raycast()/Game.raycastAll(), casting a ray from an origin/direction and returning collider intersections (BGE.RaycastHit: entity, collider, point, distance, normal) across 2D (CircleCollider/RectangleCollider) and 3D (SphereCollider3d/BoxCollider3d) colliders alike.
Replaces the previously-unused raycastVector/raycastAngle stubs (confirmed no callers anywhere in the engine or examples).
Each collider type implements a new Collider.raycastCheck() override, mirroring the existing confirmCollision() extension point, delegating to pure ray-vs-shape math in colliders/Raycast.bs (sphere/circle quadratic, AABB slab method).
BGE.RaycastHit is a BrighterScript interface (pure data, no instantiation cost) rather than a class, with entity/collider typed as their real classes.
Game.raycastAll() walks the current room plus all entities' colliders (mirroring the existing per-frame room-first pattern), honors enabled/collidableFlags filtering, and returns hits sorted by ascending distance (a manual insertion sort — roArray.SortBy() has a confirmed descending-sort bug under this project's pinned CI test runner, issue Pinned brs-node@2.6.0: roArray.SortBy sorts numeric fields descending by default (should be ascending) #230).
CLAUDE.md documents the new API in the Collision section.
Built via subagent-driven-development: 6 planned tasks, each independently implemented and reviewed, plus a mid-implementation design correction (RaycastHit class → interface) and a final whole-branch review that surfaced and fixed 5 cross-cutting integration gaps (room colliders being invisible to raycasts, disabled entities not excluded, a 2D-collider renormalization bug for non-planar rays, an origin-inside-shape inconsistency between spheres and boxes, and an under-tested sort path).
See specs/2026-09-21-raycasting-design.md and docs/superpowers/plans/2026-09-21-raycasting.md for the full design/plan.

…d entities, 2D renormalization, origin-inside-shape consistency, sort test coverage (#225)

Whole-branch review of #225 surfaced integration gaps individual task
review couldn't see:

- Game.raycastAll() never tested m.currentRoom's colliders (it's not in
  sortedEntities) - now mirrors processEntitiesPreDraw()/
  processEntitiesCollisions()'s "process current room first" pattern.
- raycastAll() ignored entity.enabled, unlike the per-frame collision
  pass.
- intersectRayCircle()/intersectRayAabb2d() flattened direction to z=0
  without renormalizing, silently breaking intersectRaySphere()'s
  unit-vector assumption whenever the caller's direction had a nonzero
  z component - now renormalize and rescale maxDistance/distance to
  compensate.
- intersectRaySphere() returned the far exit point for an origin inside
  the sphere, inconsistent with intersectRayAabb3d()'s t=0 convention
  and the design spec - now returns t=0 like the box does.
- The insertion sort's reordering path in raycastAll() was untested
  (existing test's input happened to already be sorted).
- Zero-length direction was unhandled - now returns no hits explicitly.
- Fixed a misleading test title (asserted a hit, said "misses").
