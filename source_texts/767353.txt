.dcm files were silently ignored — CImage::loadFromFile() had no DICOM branch, and there was no way to scan a directory for files by extension. Dixon MRI series (arbitrary-named .dcm slices) couldn't be loaded at all.
Core library changes
CFileImageDCM.h/.cpp — Minimal DICOM parser: Explicit/Implicit VR Little Endian, 8-bit (direct copy) and 16-bit (min-max normalised to 8-bit GL_LUMINANCE). cGetDCMSlicePosition() extracts Z from tag (0020,0032) with fallback to Instance Number (0020,0013).
CImage.cpp — Hook .dcm into loadFromFile().
CMultiImage::loadFromDirectory(dir, ext="dcm") — Cross-platform directory scan (Win32 FindFirstFile / POSIX opendir), sorts slices by DICOM Z-position before calling the existing loadFromFiles(vector<string>) pipeline. Files missing position metadata get a large fallback value so they sort to the end without conflicting with real positions.
New scene
scenes/dicomvolume.h — DicomVolume scene loads a Dixon directory as a cVoxelObject 3D texture. Provides WorldToVoxel() with the FleX↔CHAI3D↔DICOM axis mapping:
```
FleX X (up)      = CHAI3D Y  →  DICOM row
FleX Y (forward) = CHAI3D Z  →  DICOM slice
FleX Z (right)   = CHAI3D X  →  DICOM column
```
Usage — load an arbitrary Dixon directory:
```
// In main.cpp / scene list
g_scenes.push_back(new DicomVolume("Dixon DICOM Volume", "/path/to/dixon"));

// Or use the default path (../../data/dixon) and reload via in-scene GUI
g_scenes.push_back(new DicomVolume("Dixon DICOM Volume"));
```
