@jni I think it is wasteful indeed, regionprops.image return a bool image, so it should make a copy use gray[slice] == lab, the second, marching every sub block should also do a copy, and marching algorithm need a float dtype, (If I guess rightly).
now what I do is below:
resize the 3d image 2-4 times bigger, then find_boundaries, and fill the boundaries with a value far-bigger then the max lable value, such as 1e8, then march on 1e8/2 level. and get (vts, faces, norms, values), use the values to group the vts. count the area, and multiply (1/scale)^2.
resize to make sure no small segment will be killed when find_boundaries
find_boundaries make sure each object atleast has a 8-connect gap, else the march algorithm would go though one to another.
use a big enough value as the boundaries, because the march algorithm would interpolate between pixels, if the boundaries value is not big enough, the level would be effected by the object's label value.

I look the find_boundaries again, there is 'outer' and 'subpixs' mode, So there is no need resize, subpixs mode is what I say befor, and use the outer mode, the single platform will not be killed, so there is no need to double size.
about the marching level interpolate, I tested we can give 0, then any lable get the same result, which lies on the outer pixes, because background is 0.
So the code is:
```
lab, n = ndimg.label(arr)
lab[find_boundaries(lab, mode='outer')] = 0
vts, fs, ns, cs = marching_cubes_lewiner(lab, level=0)

lst = [[] for i in range(n+1)]
for i in fs: lst[int(cs[i[0]])].append(i)
areas = [0 if len(i)==0 else mesh_surface_area(vts, i) for i in lst]
```
very simple, even there is no need to implements in cython, but we can add it to regionprops, or give a demo tell users we can use like this.

vts, fs, ns, cs = marching_cubes_lewiner(lab, level=0)
