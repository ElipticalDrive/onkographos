can expand rapidly during traversal [4]. In such high-density

Abstract Ligra, a lightweight shared-memory multi-core
graph processing framework, uses EDGEMAP with a static
threshold (ρ = |E|/20) to switch between sparse and dense
traversal modes. However, this static threshold does not account for edge-density differences among input graphs, which
may cause delayed switching for low-density graphs and
premature switching for high-density graphs. We propose
Ligra-DAT, a graph-level edge-density-based threshold selection mechanism: after graph loading, it selects ρ × 1.5 for
high-density graphs (δ > 0.1) to delay dense-mode switching
and ρ × 0.7 for low-density graphs (δ ⩽ 0.1) to accelerate
dense-mode switching. The selected threshold is then reused
during EDGEMAP execution and is not retuned at each traversal iteration. Experiments on a 64-core server with 8 datasets
and 6 core algorithms show that Ligra-DAT achieves up to
42.4% runtime reduction, preserves compatibility with Ligra
applications, has O(1) threshold-selection complexity, and
incurs overhead less than 0.1% of the corresponding Ligra
execution time.
Keywords Graph Processing, Shared Memory, Ligra, EdgeDensity-Based Threshold Selection, Edge Density

Recent graph-processing research has advanced adjacent

direct Ligra threshold extensions. Representative work includes MST’s topology-aware aggregation [14]; the survey of

[25].

GPU co-execution in CGCGraph [28], and a recent survey of
dynamic graph processing [29]. These methods establish the
current graph-processing context, but they change algorithms,

hardware assumptions. Their reported runtimes are therefore
not interchangeable with a threshold-only modification inside
Ligra. We use them as recent related systems and reserve the
controlled experiment in Section 5.6 for Ligra-compatible

• Analytical and empirical contribution: Through analysis of 119 graphs (19 random-local + 2 dedicated datasets
with 50 graphs each), we show that edge density is correlated with the preferred mode-switching threshold. The
calibration results identify the practical boundary and

data structures, requires no changes to user-level Ligra

threshold is graph-specific but remains fixed during one

8 datasets (5 synthetic + 3 real-world including SNAP

6 core graph algorithms, covering traversal, ranking,
centrality, and connectivity tasks. The results show consistent performance across graph types, edge densities,
and the evaluated Intel Xeon hardware configurations

Edge density is a standard global graph statistic, but its
use as a direct signal for sparse/dense mode switching in
lightweight shared-memory frameworks remains underexplored. R-MAT provides a recursive model for generating
synthetic graphs at controlled vertex and edge scales [38],
which supports evaluation across a broad density range.
Biological-network studies likewise use dense and sparse
substructures to characterize functional organization [12]. In
adjacent optimization layers, PowerGraph demonstrates the
value of degree-aware computation placement [34], while
multilevel graph partitioning uses graph structure to balance
computation [39]. Direction-optimizing BFS [4], distributedmemory parallel BFS [40], scalable multicore traversal [41],
push/pull selection [32], and multicore graph-processing analysis [33] separately show that traversal direction and execution
strategy benefit from workload-aware selection. These methods do not constitute density-based Ligra threshold policies,
but together they motivate evaluating global edge density
as a lightweight graph-level structural signal. Ligra-DAT
addresses this narrower mode-switching problem without
claiming that density replaces frontier-, degree-, partition-,
or hardware-aware optimization.

Design of Ligra-DAT: Graph-Level EdgeDensity-Based Threshold Selection
To address the limitations of Ligra’s static threshold, we
propose a graph-level edge-density-based threshold selection mechanism (Ligra-DAT) that selects the threshold according to the edge density of each input graph. Instead of
using one universal threshold for all graphs, Ligra-DAT computes the selected threshold once after graph loading from
|V |, |E|, and δ, and then reuses it during EDGEMAP
traversal. The term “graph-level” indicates that selection is
performed once for each input graph through a global structural signal; it does not imply online threshold retuning across
iterations within one execution. Finer-grained frontier-level
or local-density-aware adaptation is left to future work. The
design follows the lightweight design philosophy of Ligra
[1] and energy-efficient graph processing research [44], with
analytical support from graph algorithm complexity studies
[8, 40, 43].

4.3 Edge Density Calculation
Edge density δ quantifies the ratio of actual edges to the
maximum possible edges (excluding self-loops) in a graph.
For undirected graphs, the maximum number of edges is
|V |(|V |−1)

We compared our O(1) calculation method with two alternative approaches (full traversal and sampling) to validate its

The results show that the O(1) method adds very small
overhead in the tested cases, while the other methods add
significant runtime overhead (especially for large graphs),
making them unsuitable for lightweight frameworks like
Ligra.

4.6 Interpretation of Scaling Factors
While Section 4.4 empirically identifies the optimal scaling
factors (0.7 and 1.5), we further connect these values to the
direction of the mode-switching bias induced by different
edge-density regimes. The purpose of this analysis is not
to introduce a second runtime model, but to explain why
the empirically selected coefficients move the threshold in
opposite directions for sparse and dense graphs.

dataset, and thread settings; it does not reproduce CoroGraph’s

cache/work signal achieves the lowest runtime on Components, PageRank, and Bellman-Ford. The results confirm that
no single decision signal dominates every algorithm.

Discussion
6.1 Core Reasons for Effectiveness
Ligra-DAT’s performance gains stem from targeted optimization of mode switching based on edge density, addressing
the core limitations of Ligra’s static threshold and building
on prior traversal and locality studies [1, 4, 32, 36]:
• High-Density Graphs: For δ > 0.1, the adjustment
logic ρ′ = 1.5ρ delays dense-mode switching relative to
Ligra’s default threshold. The larger threshold avoids entering dense mode before the frontier is sufficiently large,
thereby reducing unnecessary full-graph incoming-edge
scans. For random-local-dense graphs with δ = 0.15,
BFS reaches RR = 42.3%, and redundant edge processing is reduced from 35% to 12%.
• Low-Density Graphs: For δ ⩽ 0.1, the adjustment logic
ρ′ = 0.7ρ accelerates dense-mode switching relative to
Ligra’s default threshold. The lower threshold prevents
sparse traversal from continuing beyond the empirically
preferred switching point in low-density graphs. For
3D-grid graphs with δ = 0.000058, PageRank reaches
RR = 42.4%, and memory bandwidth utilization increases from 62% to 89%. On public Twitter and rMat27
datasets, Table 6 further shows BFS RR values of 33.3%
and 31.0%, respectively, under the same Ligra-static
baseline definition.

6.2 Limitations
Ligra-DAT’s effectiveness aligns with the edge density
characteristics of real-world scenarios:
• Social Networks (δ = 0.0000008 − 0.0000760): Consistent with Table 6, the Twitter graph (δ = 0.0000008)
achieves BFS RR = 33.3% and PageRank RR =
19.6% under the Ligra-static baseline. For the Facebook
graph (δ = 0.0000760), the controlled Ligra-versusLigra-DAT evaluation reports BFS RR = 38.6% and
PageRank RR = 31.2%. These results support the use
of Ligra-DAT for social-network workloads without
introducing an additional framework migration cost.
• Biological Networks (δ ≈ 10−4 ): For biological networks where edge density is a key structural metric
[12, 50], the PPI graph (δ = 0.000117) achieves BFS
RR = 34.2% and Connected Components RR =
34.6% in the controlled evaluation. We therefore present
the biological-network result as evidence of acceleration
on low-density protein-interaction workloads, without
introducing additional unreported application-level latency numbers.
• Web-Style Graphs: Building on web graph processing
research [5, 38], the rMat27 graph in Table 6 (δ =
0.0000005) achieves PageRank RR = 28.7%, and the
rMat24 graph in Table 5 has density δ = 0.0640000. We
use these R-MAT datasets to evaluate web-style sparse
traversal behavior, while keeping the density values
consistent with Table 5.
• High-Density Synthetic Graphs (δ > 0.1): The
random-local-dense graph (δ = 0.15) is used to validate

• Global-density granularity: Ligra-DAT uses one global
edge-density value to select a threshold. Graphs with
the same global density can still differ substantially
in degree skew, local community density, and core–
periphery structure, and the active frontier can change
across iterations. Because the selected threshold is not
retuned during execution, the current method does not
distinguish these cases. This design keeps the overhead
at O(1) and preserves compatibility with Ligra, but it
cannot fully capture runtime frontier size, active-vertex
degree distribution, local community structure, or powerlaw skewness in social and web graphs. We therefore
regard global density as a lightweight first-order signal
rather than a complete replacement for frontier-aware
adaptation.
• Evolving Graphs: Current design assumes static graphs.
For evolving graphs (e.g., real-time social network updates), a practical extension would maintain an incremental edge counter that updates |E| in O(1) time when
edges are added or removed, and would re-compute δ
periodically or when the density changes beyond a preset
margin. This extension is compatible with evolvinggraph processing frameworks [16, 57], but it remains
future work rather than a claimed component of the
current implementation.
