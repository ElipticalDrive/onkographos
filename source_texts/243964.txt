The C++ library has loadSpzPacked(), which returns the quantized attribute streams (PackedGaussians) without unpacking to floats. The WASM/TypeScript bindings, however, only expose loadSpzFromBuffer(), which returns a fully unpacked float32 GaussianCloud.
For web renderers this is a significant limitation. SPZ's quantized encodings (24-bit fixed-point positions, 8-bit log scales, smallest-three rotations, 8-bit color/alpha/SH) decode trivially on the GPU, so an efficient renderer wants to upload the packed streams to textures/buffers directly and dequantize in the shader — keeping GPU memory at ~20 bytes per splat instead of ~230 bytes for the float expansion. With loadSpzFromBuffer() this is impossible without re-quantizing, and for scenes with tens of millions of splats the intermediate float expansion (gigabytes in the wasm heap) is itself prohibitive.
We recently added SPZ support to the PlayCanvas engine this way (playcanvas/engine#9018), and had to re-implement the NGSP container parsing and ZSTD decompression in JS to get at the packed data. We'd much rather consume the official decoder so we automatically stay compatible as the format evolves (e.g. the v4 extension system, or per-splat fractional bits mentioned in the code comments).
Proposal: add a loadSpzPackedFromBuffer(data) binding that returns the header fields (numPoints, shDegree, fractionalBits, antialiased, usesQuaternionSmallestThree) plus TypedArray views (or copies) of the raw streams: positions, scales, rotations, alphas, colors, sh — i.e. the direct contents of PackedGaussians. A saveSpzFromPacked counterpart would be nice for symmetry but the load path is the important half.
Happy to contribute a PR for the emscripten bindings if this direction is acceptable.
