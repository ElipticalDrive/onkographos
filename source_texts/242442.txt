Owner
Prototype of hatching a raymarched SDF scene with a light-driven flow field, following Jobard & Lefer, Creating Evenly-Spaced Streamlines of Arbitrary Density. The PR also adds three jali-window forks: hatched, hatched with volumetric light shafts, and volumetric light shaded directly with no hatching.
VITE_SKETCH="sketches/sdf-hatch/flow-field" npm run dev
VITE_SKETCH="sketches/sdf-hatch/jali" npm run dev
VITE_SKETCH="sketches/sdf-hatch/jali-shafts" npm run dev
VITE_SKETCH="sketches/sdf-hatch/jali-volumetric" npm run dev
How it works (flow-field)
pix(x, y) is a GLSL function. It runs camera → SDF raymarch (a ground plane, a sphere, a tilted torus and a rounded box) and returns { light, normal }. Light is diffuse × soft shadow plus AO, and it fades to paper toward the horizon.
The fragment shader computes the flow field. It writes flow_dir = normalize(world2scr2D(cross(normal, hatch_dir))), plus light and object id, to an offscreen WebGL2 canvas, which is read back as a G-buffer. Because a direction projects differently at each depth, world2scr2D is applied to a short world-space segment anchored at the hit point.
Jobard–Lefer runs on the CPU. Streamlines are traced with RK2 in both directions. A line stops when it comes within d_test = testRatio · d_sep of another line, crosses onto a different object, or enters a highlight. New seeds are placed d_sep to either side of each finished line, breadth-first. A shuffled seed grid is the fallback for regions the queue never reaches.
Spacing follows the light. min_line_dist = line_width / (1.0001 - light ** gamma), so ink coverage is 1 - light ** gamma and the hatching reproduces the shaded tone. Spacings above maxSeparation are left blank.
A Tweakpane exposes line width, gamma, the separation cap, d_test ratio, hatch_dir, light, camera, and a showField debug view of the G-buffer.
Jali fork (jali)
This rebuilds jali/truchet.ts as an SDF on top of the same hatching pipeline:
Wall and window. The wall has a pointed-arch opening, built from a box plus the lens of two discs (archRise sets the point). A moulded frame sits around it.
Truchet screen. The screen in the opening is pierced by the four stepped-diagonal truchet tiles. Each cell's tile is a capsule polyline, evaluated over the cell and its three nearest neighbours and then extruded. cells, barWidth and seed choose the pattern.
Lighting. The sun is outside the wall, so the lattice is backlit against sky, and its light falls on the room's floor through the soft-shadow march.
Fixes against banding. The G-buffer renders to an RGBA32F target. d_test is raised to 0.75 · d_sep, so hatch lines that converge under perspective on the flat wall don't bunch into dark bands before they stop.
Volumetric fork (jali-shafts)
Single scattering. Each camera ray marches the room's air in 32 steps, jittered with interleaved gradient noise. It sums the sunlit length (× density) into the light that sets the hatch spacing, so the shafts read as paler air.
Analytic sun visibility. Instead of marching a shadow ray, the sun direction is followed to the wall's two faces and the screen's mid-plane, and the arch and lattice SDFs are evaluated there. Samples the wall already blocks skip the lattice lookup. The same test lights the floor, which gives it a crisp truchet light pattern.
beamFlow. Inside a shaft, the flow direction blends toward the sun's rays projected at the shaft's depth, so the hatching there runs along the light.
Shaded fork (jali-volumetric)
No hatching. This is jali-shafts without the flow field: the same scene and analytic sun test, shaded straight to a WebGL2 canvas.
96 scatter steps per ray, then exposure (1 - exp(-k·L)) and a two-tone ramp from the palette's ink to its paper, with 1/255 dither.
The shafts and the floor's light pool carry the truchet pattern exactly.
Fix
Ink fallback. randomPalette(7) can return an empty ink list for a paper (seed 7 does). ink() was then undefined, and the stroke silently stayed the canvas default. The sketches now fall back to black explicitly, so the existing renders don't change.
Verification
npm run test && npm run typecheck pass.
The hatched sketches were rendered headlessly with cloud:render.
jali-shafts takes about 9 s to compute its G-buffer in the software-WebGL headless browser, which fits within cloud:render's 15 s ready timeout.
jali-volumetric takes about 17 s there, longer than that timeout. I checked it with a Playwright canvas screenshot taken after a longer wait. On a GPU it should be near-instant.
