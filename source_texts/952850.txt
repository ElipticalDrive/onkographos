# Numerical Stability in Least Squares

A numerical experiment comparing the **Normal Equations** with **Conjugate Gradient for Least Squares (CGLS)** under changing matrix dimensions, conditioning, iteration counts and noise distributions.

The project investigates a practical numerical-analysis question:

> When does a mathematically valid least-squares formulation become numerically unreliable, and how much can an iterative method improve the solution?

The experiments use repeated synthetic least-squares problems to analyse recovery error under both **Gaussian** and **heavy-tailed Cauchy noise**.

---

## Overview

For a linear model

$$
y = Xw_{\text{true}} + \varepsilon
$$

the goal is to recover the true parameter vector $w_{\text{true}}$ from noisy observations.

In the experiments:

- $X$ has iid standard Gaussian entries
- $w_{\text{true}}$ is the all-ones vector
- recovery quality is measured using squared parameter error
- each configuration is repeated across **1,000 independent trials**
- the matrix dimensions are varied to move from poorly conditioned to better-conditioned systems

The two solvers compared are:

1. **Normal Equations**
2. **Conjugate Gradient for Least Squares (CGLS)**

---

## Why Numerical Stability Matters

The Normal Equations solve

$$
X^T X w = X^T y
$$

through the explicit expression

$$
w = (X^T X)^{-1} X^T y
$$

This formulation is mathematically correct, but forming $X^T X$ can worsen numerical conditioning.

A key relationship is

$$
\kappa(X^T X) = \kappa(X)^2
$$

so an already ill-conditioned design matrix can become substantially more sensitive when the Normal Equations are formed.

CGLS instead works through iterative matrix-vector operations involving $X$ and $X^T$, avoiding the explicit formation and inversion of $X^T X$.

---

## Experiment Design

The main problem dimensions are:

| Observations $m$ | Parameters $N$ | Interpretation |
|---:|---:|---|
| 100 | 100 | Square system |
| 101 | 100 | Nearly square, slightly overdetermined |
| 400 | 100 | Strongly overdetermined |

Gaussian noise is tested at:

```text
sigma = 0.5
sigma = 0.1
```

CGLS is tested using:

```text
K = 5
K = 50
```

where $K$ is the number of CGLS iterations.

Each configuration is evaluated across:

```text
1,000 independent trials
```

The same trial seed is used for the two solution methods so that solver comparisons are made on the same generated systems.

## Solver 1: Normal Equations

The implementation intentionally follows the explicit Normal Equations formulation:

```python
def normal_equations(X, y):
    XtX = X.T @ X
    Xty = X.T @ y
    XtX_inv = np.linalg.inv(XtX)
    return XtX_inv @ Xty
```

Using the explicit inverse is deliberate because the purpose of the project is to examine the numerical behaviour of this formulation rather than replace it with a more numerically stable production solver.

The key issue is that the condition number is effectively squared when $X^T X$ is formed.

As a result, errors and perturbations can be amplified substantially when $X$ is already poorly conditioned.

---

## Solver 2: CGLS

Conjugate Gradient for Least Squares is an iterative alternative.

CGLS starts from a zero parameter vector and repeatedly updates:

- the residual
- the transformed residual
- the search direction
- the parameter estimate

Rather than explicitly forming and inverting $X^T X$, the method uses repeated matrix-vector operations involving $X$ and $X^T$.

The experiments compare:

```text
K = 5
K = 50
```

to study how the number of iterations affects recovery accuracy.

A small value of $K$ can leave the solution under-converged, while a larger value can improve recovery at the cost of additional computation.

---

## Recovery Metric

For every trial, solver accuracy is measured using:

$$
\|w - w_{\text{true}}\|_2^2
$$

A value close to zero means that the true parameter vector has been accurately recovered.

The error distributions are displayed using categorical histograms with:

- fine bins between 0 and 5
- a `(5,50]` category
- a final `>50` category

This makes severe solver failures easy to identify.
