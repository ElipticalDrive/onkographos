Hi thanks for your interest in our work!
Our spatial gradient during the forward propagation is the same as the bilinear interpolation (as the three steps listed above). Our main motivation is that the naive implementation will result in this error, and in particular, it will prompt up during the backward process at the sampling operation. We thus devise our cuda implementation for tracking the spatial gradient during the forward process (here). We found training using per-query-point occupancy label of the real-scan data (without using the gradient loss) seems to be somewhat difficult engineeringly, and not generalize well to external unseen test scenes (e.g. the demo videos).
We later following one of the reviewers' hint to obtain a way to achieve closed-form gradient training without cuda implementation via this, where one can use these functions to replace torch.nn.functional.grid_sample. No error will prompt up here. But it can only be applied to one-dimensional output scenario (e.g. occupancy is OK, rgb / semantics is not OK). There is also some other scenarios where this has limitation for use.
Hope this help.
