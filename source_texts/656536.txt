Found by Terra review of lane au-coords (#1006). Object (#1006) and Generated (#847) coordinates are per-vertex attributes baked at the shutter-open pose; CPU Triangle::interpolateAt (include/astroray/shapes.h) and GPU gpu_objectCoord / gpu_generatedCoord (src/gpu/wavefront/stage_advance_device.cuh) recompute barycentrics from the hit point against the STATIC (shutter-open) vertices. For a motion-blurred object (add_triangles_bulk_motion) the hit at time t lies on the interpolated triangle, so the barycentrics and hence the pattern slide with the motion instead of staying attached (Cycles: object_inverse_position_transform with the motion-interpolated object transform, svm/tex_coord.h). Fix: barycentrics from the motion-interpolated vertices at the ray time (or carry the hit barycentrics), CPU + GPU. Currently reported as an APPROXIMATED degradation by the addon for Object coordinates. Test: a translating object with Object-coordinate noise renders the same pattern as the static object at shutter centre.
