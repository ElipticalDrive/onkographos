Currently the camera can be controlled by directly editing various intrinsic variables in viewer.core. These intrinsics have unclear and undocumented relationship to each other and to the view matrix; higher-level user-friendly API for programmatic camera control (panning, rotating, zooming) and queries (for the camera location and look/up/left directions in world coordinates; unprojecting screen pixels to world rays, etc) would be helpful.

camera_base_translation is the default translation of the camera to fit a model into the view (when you call align_camera_center()), and is added to the camera_translation which is controlled by the user/UI when interacting with the mouse. You can see the actual operation here. Think of the base translation + rotation as kind of a model matrix (although Alec doesn't want to call it that way, so conceptually it's lumped into a single view matrix). camera_eye is the position of the camera after user scaling/zoom/translation has been applied, and typically wouldn't need to be touched.
