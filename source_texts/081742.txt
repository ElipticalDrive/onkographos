Context
tetrahedron.h (kernels + fastfields-cpu-impl/tetrahedron.h) is present but was never working and is unwired (not in any MODULES list, no test). It rasterizes a field defined on a tetrahedral mesh into a dense (nx, ny, nz, nc) grid (an "inverse field" / scatter of per-tetrahedron values into the voxels they cover).
Reference implementation
There is a working Python reference to port from:
https://github.com/neuroscales/brainhops/tree/main/src/brainhops/_ext/invfield
The Python version uses batched array operations (vectorized over tetrahedra/voxels) because that's what's fast in Python. For fastfields, the implementation should instead be structured as per-element thread / CUDA kernels (one thread per tetrahedron or per output voxel, following the fastfields kernels → impl → lib layering and the teeny-based launcher pattern the rest of the project now uses), not a transliteration of the batched Python ops.
Scope (full stack, when picked up)
kernels: the single-element rasterization math (barycentric coords / point-in-tetrahedron test / value splat), ported from the brainhops reference.
cpu-impl (+ cuda-impl): teeny-based launchers over tetrahedra / output voxels.
cpu-lib / lib: dtype/device dispatch; add to MODULES.
A correctness test vs. the brainhops reference (or a brute-force check).
Priority
Low / deferred — pick this up only after the rest of the teenification + jitfields integration is fully done. Filed now to track it so it isn't lost.
Filed from the fastfields teenification work, per maintainer request.
