Two more orb variants alongside fractal / nebula / crystal / particles / tetra / lattice. Both ported from shadertoy-style sketches via the same playbook the earlier additions used (sphere-mounted, no envelope, mesh.rotation handles drag + auto-rotate, in-march click boost).
spectrum
Volumetric raymarch through two smooth-min-blended SDFs with nested sine-wave turbulence. Cosine-palette emission per ray-step gives the rainbow gradient through the volume; soft fade between `uFadeInner` / `uFadeOuter` is the silhouette. Distinct from the other volumetric variants by its rainbow palette identity and soft-halo boundary.
Palettes: Rainbow, Sunset, Tide, Halo.
Tunables: fractal scale, fade-outer/inner, smoothing, RGBA phase offsets, glow.
Audio: `dBot` → glow boost, `dUser` → smoothing perturbation (blob breathes), state crossfade lightly tints (25% mix) so the rainbow stays intact, click → in-march directional boost.
liquid
The only ORBIS variant that's a hard-surface raymarch — finds a single surface hit, computes a normal, shades with diffuse + fill + specular + rim. Reads as mercury / oil-puddle: a physical "skin" rather than a glowing field. Surface is a sphere displaced by a domain-warped value-noise height field.
Palettes: Mercury, Copper, Oil, Silver.
Tunables: sphere size, height-field amp, 6 domain-warp params (amp / falloff / start-freq / steps / velocity / noise contrast), 4-stop procedural skin palette (separate from voiceState tint), Phong lighting (ambient / diffuse / fill / specular power + intensity).
Audio: `dBot` → height-amp boost (surface bulges as orb speaks), `dUser` → warp-amp bump (skin agitates during listen), state crossfade tints, click → surface luminance boost.
Skipped from sources
Liquid's image-upload texture path (ShaderMaterial sampler2D + DOM file picker). No UI affordance fits the variant pattern; the procedural palette is enough on its own. Re-add as a separate authoring panel if image mapping becomes a real need.
Liquid's camera-locked lighting (the source rotates lights through the same matrix as the camera so they track the view). Lights stay in object space here so shading rotates with the orb — close enough to the original feel without rebuilding the transform pipeline.

* fix(orb): drop liquid variant + raise spectrum t-cap for ORBIS camera distance

Two issues from the live look on PR #139:

liquid was too heavy. The hard-surface raymarch (96-step inner +
4-call estimateNormal at every hit + Phong shading) wasn't worth
the perf cost — every voice session pays for the orb the moment it
mounts, regardless of which variant is active during browse. Pull it
entirely; if we need a "physical surface" feel later we can revisit
with a lighter SDF or pre-baked normal map.

spectrum wasn't rendering. The ported shader carried the source's
``if (t > 10.0) break;`` ray budget, but the source ran with a camera
at z=-4.5 while ORBIS's mesh sits in front of a camera at z=13. The
bounding-sphere fast-forward was correctly jumping the ray from
distFromCenter ~13 to uFadeOuter (~2.56) — that adds 10.4 to t — and
the cap fired immediately, so no scene evaluation ever ran. Raise to
25 (camera distance + sphere diameter + slack) so the ray reaches the
volume.

Removes:
  web/src/plugins/orb/variants/liquid/{shaders,...}/
  web/src/plugins/orb/variants/index.ts ← drop ./liquid import

Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>

* fix(orb/spectrum): canonical smoothstep so Rainbow palette renders

The radial fade used `smoothstep(uFadeOuter, uFadeInner, dist)` —
edge0 > edge1 is undefined per the GLSL spec. M1 / WebGL2 drivers
"do something reasonable" most of the time, but Rainbow's 0.01-thin
fade band (outer 2.56, inner 2.55) hits a precision cliff that the
wider bands (Sunset 0.2, Tide 0.2, Halo 1.0) just walk through
cleanly — every other palette renders, Rainbow returned blank.

Rewrite as `1 - smoothstep(uFadeInner, uFadeOuter, dist)`. Same
intent (1 inside fadeInner, 0 at fadeOuter, smooth between),
spec-defined behaviour, no driver luck required.
