Summary
Take the per-segment files out of the multires step for sharded output. Builds on #64.
After #64, a small segment's meshing costs little, but everything after assembly still went through one file per segment per step on the shared filesystem: a PLY per level from each meshing pass, read back by the multires step; an <id> and <id>.index written per segment, read back by the shard packer and deleted; and the level PLYs deleted at the end. For a prediction with millions of tiny segments, that is several million file creates, reads and deletes.
Meshing passes hand their meshes on in packs. In a multires run that is sharded, uses the downsample strategy, deletes both its level meshes and its unsharded files, and runs no analysis, the block workers and assembly batches write their finished meshes into one pack file per block or batch, with an offset manifest, instead of a PLY per segment. The bytes are the PLY bytes the file would have held. When assembly redoes a segment a block finished early, it lists it as superseded, so the index takes assembly's mesh, as #64 does with files.
Small segments are built in batches on each worker's own disk. Segments whose LOD-0 mesh is at most 1 MiB are batched by the LOD-0 pack they sit in, so a batch's coarser levels come from the few packs covering the same region and its reads stay sequential. A batch copies its segments' level meshes to local scratch, runs the unchanged per-segment multires writer there, and writes the shard-ready chunks into one pack with a manifest. A retry skips batches whose manifest exists; an earlier run's batches are cleared first.
Large segments keep the per-segment route. Their level meshes are written out as PLYs and go through generate_all_neuroglancer_multires_meshes as before, which can spread one segment over several workers.
The shard packer joins both. It reads small segments' chunks from the batch packs, in offset order through one open file per pack, and large ones from their files. Segment properties are written from the ids that got a chunk instead of a scan for .index files.
Every other configuration keeps the file route, since something reads those files. The code that builds a segment's chunk is the same on both routes, so the output is the same.
