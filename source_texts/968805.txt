Context
Cornerstone 5.6.8 constructs dynamic-volume requests with the active phase first, then its inherited loadImages() reverses them before queueing. A three-phase WATER series therefore loads phases 3 → 2 → 1 while displaying phase 1, leaving the viewport black during most of the download.
Upstream history for bookkeeping:
Cornerstone3D PR #522 — fix dynamic-volume loading order added a compensating reversal so time points load first to last.
Cornerstone3D PR #779 — progressive image loading/rendering removed that compensation during the progressive-loading changes, while the inherited reversal remained.
Changes & Results
Add a scoped dynamic-loader adapter at both registration sites. It compensates for the inherited reversal only during loadImages()'s synchronous queue construction, then restores getImageLoadRequests() in finally, before the load promise settles. The default queue follows Cornerstone's active-phase-first ordering, while direct callers—including MPR's nthLoader, interleaveCenterLoader, and interleaveTopToBottom—retain their original ordering. The adapter preserves the load promise, cancellation and disposal handlers; static-volume loading is unchanged.
This change corrects phase ordering only. It does not prioritize the middle slice, change rendering, or reprioritize requests after a phase switch once loading has started. Remove the adapter when the upstream reversal is fixed; the regression test exercises the installed loader and request pool to catch that change.

Testing
The 20-test regression suite covers the upstream reversed queue, all three active phases, uneven groups, static ordering, loader lifecycle forwarding, and creation failures. It also checks direct request ordering, synchronous restoration on success and failure, load-promise identity/rejection, and the actual queues from all three custom strategies for every active phase. For the 258-frame MPR case, the active phase completes at request 200, preserving the original strategy behavior. The existing Jest CI run includes the Cornerstone project, so these tests appear in the normal test summary and coverage report.
```
pnpm exec jest --config extensions/cornerstone/jest.config.js \
  --runTestsByPath extensions/cornerstone/src/utils/dynamicVolumeLoader.test.ts \
  --ci --runInBand
```
For a browser check, open a multi-phase series with phase 1 selected. Confirm phase 1 requests precede the other phases, the image appears during loading, and every phase loads completely.

Review
Cornerstone 5.6.8 lists the shown phase first, then reverses the list before loading. So the shown phase loaded last. The fix works in ODELIA's normal layout.
One problem: the fix also reverses the order for three other loaders, and those don't reverse it back.

Suggestion
The fix changes getImageLoadRequests on the volume for good. Three load strategies also call it: nthLoader.ts:51, interleaveCenterLoader.ts:87 and interleaveTopToBottom.ts:86. The MPR layout uses nthLoader, and users can pick MPR in labeling mode. There, the shown phase now finishes loading last: on a 3-phase series, at request 258 of 258 insteadof 200. That's the same bug this PR fixes, moved to MPR. Fix: reverse the list only while loadImages runs. Add a test that getImageLoadRequests() keeps its original order.
