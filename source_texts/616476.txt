# Sculpting with distances

A real-time CPU ray marcher and 3D sculpting tool. No meshes, no GPU: every object
is a signed distance function, and shapes are combined with arithmetic instead of
topology.

Built by Lancelot Doucet and Thomas Scheepers for *Introduction à la Synthèse d'Image* cours (EPITA, promo 2027).
[You can access the presentation slides](https://docs.google.com/presentation/d/1hYh5Z2vf0Jh406fjJZ57Vop1zHKFyXCAf8uv4Gt0TuA/edit?usp=sharing)

## Context

An SDF returns, for any point in space, the distance to the nearest surface. To
render, we shoot one ray per pixel and step forward by that distance until we hit
something. Nothing is tessellated, so the scene can be edited while the renderer
runs.

C++17, OpenMP, GLFW. Renders at 320x180 and upscales to the window.

<img src="docs/realtime.gif" width="520" alt="Application window showing a box, torus and sphere rendered in real time with an FPS counter">

*Early unoptimised version, before OpenMP and adaptive supersampling: 7 FPS.*

## Modelling

Six primitives (sphere, plane, box, torus, cone, ellipsoid), using the analytic
formulas from [Inigo Quilez](https://iquilezles.org/articles/distfunctions/).

CSG comes for free from the distance field:

| Operation | Formula |
|---|---|
| `SIMPLE_UNION` | `min(d1, d2)` |
| `SMOOTH_UNION` | [smooth minimum](https://www.desmos.com/calculator/c8o2y832ol) |
| `INTERSECTION` | `max(d1, d2)` |
| `SUBSTRACTION` | `max(d1, -d2)` |
| `MATERIAL_SWP` | repaints the overlap, geometry untouched |

A plain `min` leaves a crease where two fields cross. A smooth minimum interpolates
between them, and the surface flows from one shape into the other. That is the
difference between assembling and sculpting.

Scenes export to plain text, one object per line, in CSG evaluation order. The file
is the model, so export/import is lossless.

## Rendering

- Blinn-Phong, diffuse and specular, one directional light.
- Normals are the gradient of the distance field, from three central differences.
- Triplanar projection for textures (SDFs have no UVs). Boxes use a single-axis
  projection.
- Live preview: the shape under the cursor is rendered into the scene, with the
  active CSG operation applied, before you commit it.

## Optimisations

Marching 320x180 rays single-threaded is not real-time. What got us there:

- OpenMP on the pixel loop, with a serial fallback when `_OPENMP` is undefined.
- Early termination: 64 steps max, hit at 0.02, give up at 20. Most of the cost is
  rays that graze a surface and never converge, so capping them is where the time
  is saved.
- Adaptive supersampling: render low-res, detect edges, supersample only those
  pixels (3x). Interior pixels are flat and gain nothing.

After all that, the same scene runs at around 60 FPS, though it varies a lot with the number of objects, the operations used, and the machine.

## Build and run

Needs a C++17 compiler with OpenMP, and GLFW.

```sh
sudo apt-get install libglfw3 libglfw3-dev
make
./main [-i <import_path>] [-e <export_path>]
```

On Windows, GLFW is resolved through a static vcpkg triplet (`x64-mingw-static`).
Set `VCPKG` in the Makefile to your own vcpkg root and build under MSYS2/MinGW.
