Known bug: Clearing corner cases can lead to underflow / overflow of the clearing which then leads to actually marking
So on hold till I find a fix which does not take up too much computation
AlexReimann
commented
Dec 22, 2014
Copy link
Copy Markdown
Author
The issue is the accuracy and it only happens when the end point is directly on the z- axis border of voxel grid cells. Also occurence depends on the accuracy.
One fix would be to check if the end point is on the border and add / subtract a little offset, might be computational "heavy".
The other one would be to remove corner clearing for the last cleared cell. Basically it does this right now: https://docs.google.com/drawings/d/1YeeKCFF7LxVRLOkIBawkwEzePvb2JeTrjfjLt8b18Bk/edit?usp=sharing
So if we skip the clearing of additional corner cells after clearing the last cell it fixes it. But might under clear? I will do some more testing on that again.. if it works we might want to go with that.
Opinions on that?
Third option would be to check for underflow /overflow and don't clear in this case. But this is even more computational heavy with the current implementation than the first proposed fix.
I have another pull request incoming after this which changes the way updating is handled. It makes the whole thing around 30% faster (with a kinect) and also allows to visualize which cells are cleared (which is really nice for debugging). It would also allow an underflow detection without slowing it down much (maybe 1% ?).
Non-optimized version, which is actually slower but has the visualisation, is here AlexReimann@e20243d

I introduced a cached updating scheme of the costmap which fetches overflows / underflows in case of corner case clearing.
It also makes the code faster than the original implementation in the case that number of voxels << number of cleared voxels (e. g. 3d sensor where most voxels get cleared a few hundred times depending on the resolution).
When using corner case clearing it now runs at around the same speed as the original implementation or faster (depends on the length of rays).
Also adds visualization of the cleared voxels.
This needs some serious testing.
