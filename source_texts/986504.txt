For a 200^3 grid, this is the difference between minutes and seconds.
Proposal
Accept vectorized callables when the user opts in. Two viable shapes:
```
# option A: explicit flag
level_set(f, bounds, edge_length, vectorized=True)
# f(xs, ys, zs) -> ndarray, where each input is shape (N,)

# option B: separate entry point
level_set_batch(f, bounds, edge_length)
```
I lean option A for API surface, with a clear docstring spelling out the contract (1D float arrays in, 1D float array out, same length).
Notes
manifold3d.Manifold.level_set calls the Python callable directly. Going vectorized means we sample on our side and hand manifold3d a precomputed scalar field, which manifold3d doesn't currently take. Need to check whether their API exposes a grid-based path, or whether we build the voxel grid here and call level_set with a closure that just looks values up. The closure-lookup version still pays per-voxel Python overhead but the body is a single array index instead of an arbitrary user function.
Worth benchmarking the closure-lookup against the user-vectorized callback before committing to an API shape.
