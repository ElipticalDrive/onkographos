Follow-on from #222 / PR #223
Camera control (#222, merged via #223) lets get_frame render from any viewpoint, not just the three orthographic planes — but FrameRaster still splats every point as a flat, hard-edged, uniformly-lit disc (Graphics2D.fillOval, one solid Color). Chromatik's actual on-screen preview renders each LED as something softer — round, glowing, blended bulbs rather than flat circles. The gap is visible immediately once you shoot from an actual interior viewpoint (the motivating case for #222): a real installation photographed from inside reads as soft points of light, not a field of solid dots.
Two related asks
General fidelity. get_frame's render should look more like what a person actually sees in Chromatik or in front of the installation — softer, glowing points rather than flat filled circles — for any camera/view, not just as a screenshot special-case.
Screenshot quality specifically. When the render is meant to be shown to a human (a PR image, a demo screenshot) rather than consumed as a cheap numeric loop-and-check, it should look genuinely good — this may want its own quality tier (bigger radial gradient, soft falloff, maybe simple bloom) distinct from the fast default used for tight mutate→look→adjust loops.
These might end up as one implementation (a nicer disc — radial gradient with soft falloff, replacing the flat fillOval) or two (a default "fast" bulb style plus an opt-in "pretty" style for include_image screenshot calls) — worth deciding once someone's looking at the actual rendering code.
Where to look
package/src/main/java/chromatikmcp/render/FrameRaster.java — Graphics2D.fillOval calls for both the orthographic-plane path and the camera path (PR Camera control: aim the 3D view, and save/recall named angles #223 added the latter, with far-to-near depth sorting and near-camera size falloff already in place — this issue is purely about what each disc looks like, not where it's placed).
Chromatik's own point-cloud renderer (heronarts.glx.ui.component.UIPointCloud, referenced from UIPreviewWindow.pointCloud in the glx/glxstudio jars) is the actual on-screen bulb look this should approximate, if worth reverse-engineering further than "soft radial gradient."
Scope note
Purely a rendering-quality change inside FrameRaster — no new tools, no wire-shape changes. Small PR.
