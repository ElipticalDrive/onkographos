Implements report row A-4 (Wave 5): the sky occlusion volume, and the fog's sky light occluded by it. Rust sources: #47, #55, #59, #61 (shadows/sky_occlusion.rs, run_sky_occlusion_pass, VolumetricFogEffect::set_sky_occlusion).
What
src/shadows/SkyOcclusion.ts: a port of Rust's SkyOcclusion that uses its WGSL unchanged (sky_occlusion_build.wgsl and sky_occlusion.wgsl imported with ?raw). It has the same options and defaults (extentM, resolution, volumeSize, min/maxHeightM, recenter, canopyExtinction, frames, depthTiles, lodDistanceScale, layerMask). The rebuild follows Rust's state machine: it starts when the camera has moved far enough or on refresh(). The top-down depth pass draws one tile per frame, then the cover/height pyramid is built, then the visibility volume one slab per frame into a back buffer, which is copied in when it is complete. Each dispatch has its own 256-byte parameter slot, written in one writeBuffer. SKY_OCCLUSION_WGSL is exported for materials.
Renderer.enableSkyOcclusion(options) / renderer.skyOcclusion:
_planShadowViews places the top-down view.
Instance culling gets a cull view for it (castersOnly, the option's layerMask and lodDistanceScale), after the directional shadow view. It is null unless a tile is due. The stats report it as the new CullViewKind 'skyOcclusion'.
After the other shadow passes and before voxel GI (Rust's order), Renderer/SkyOcclusionPass draws the visible castShadow renderables on the mask. It uses each material's getDepthPipeline (depth32float, slope bias 2, the cascades' settings) and a scissor per tile, then calls SkyOcclusion.build.
Renderables with the TS-only shadowVertexCode are skipped, because their material's vertex stage is not what they cast with.
VolumetricFogEffect.setSkyOcclusion(sky) binds the volume and its parameters at bindings 18-20, in place of the stand-ins.
The TS fog has no sky lighting yet (that is A-2), so the binding has no visible effect until then.
Checked on a scratch page by putting a constant SH into the fog's sky-lighting stand-in: with the occlusion bound, the fog only gets darker (mean luma 28.5 → 22.6, no pixel brighter), most under the test canopy. No validation errors.
examples/index_occlusion_culling.html gets skyocc=1|show|rebuild, as in the Rust example: trees on layer 1 << 1, Rust's options, and materials dimming their sky hemisphere by skyVisibility.
Verified
tsc && vite build pass, after rebasing on ts-rust-alignment (A-1 and G-2 included).
TS vs Rust: compared in headless Chrome (chrome-devtools-axi, WebGPU) against the Rust occlusion-culling example built with wasm-pack, at 1280x720. The visibility in skyocc=show matches for the edge, valley, high and fly&t=40 cameras, and the skyocc=1 shading matches at edge and forest. Rust has TAA and occlusion culling on, so the edges differ slightly.
Look-neutral without sky occlusion: before and after screenshots, baseline origin/ts-rust-alignment against this branch:
index_occlusion_culling (cam=edge, and cam=valley&shadows=1): a mean absolute difference of 0.45/255, which is the HUD text.
index_volumetric_fog, index_curl_volumetric, index_film_look, index_particles and index_postpro look the same apart from their animation.
No console errors on any of these pages.
skyocc=rebuild / fly: no errors. The HUD lists the skyOcclusion cull view. In skyocc=rebuild&cam=edge&profile=1, the first frame of a rebuild costs Renderer/SkyOcclusionPass 0.53 ms. At that camera, tile 0 covers only meadow, so it draws 0 trees, as the stats show.
Not ported
lod_error_scale (cluster LOD cuts of the top-down view): TS has no cluster LOD yet.
Rust's GPU tests (visibility_follows_the_canopy_height_field, the tile and slab schedule): they still guard the shared WGSL through cargo test -p kansei-core. On the TS side, the volume was compared visually against Rust (above).
