Implements #1078 — 补齐双级缓存的显存层。
What
geoviz_seismic/vram_cache.py — process-wide VramTextureCache singleton (VRAM): all texture types in one byte ledger, default 1 GiB, clamped 512 MiB–2 GiB (GEOVIZ_VRAM_BUDGET_MB env or set_budget()), global-LRU eviction with explicit GPU release (direct glDeleteTextures / deferred queue) via owner callbacks that leave the item re-uploadable. Paint-time touch() keeps on-screen textures MRU. stats() exposes hits/misses/evictions/releases, bytes_now/peak, per-kind breakdown.
Registered kinds: slice2d (2D profile Indexed8 content), ortho3d (3D orthogonal/stratal R8 index textures + content), overlay/lut (volume + wiggle LUTs), horizon (sculpt R32F), volume/normal (3D bricks), wiggle (R32F slices — mock-GL path counts identically), curtain (arbitrary-line RGBA planes).
L2-hit fast path: ProfileVD.render_indexed + SeismicView caching keyed on (segy_generation, slice_type, position, attr, clip) — colormap excluded by design, so a colormap switch is an O(1) recolour that never re-reads L1 nor rebuilds L2 content. Renderer3D._slice_index_l2 does the same for 3D planes (slider revisit skips the normalize pass).
SEG-Y 直读路径受益（L1 = RamSliceCache 未动）；不依赖 zarr 链路。
Acceptance criteria
重复浏览已见切片 < 16 ms（L2 命中） — benchmarks/vram_l2_hit_benchmark.py: hit path 2.1–4.3 ms (cold 44–88 ms, 18–28×) at 0.56M/1.6M/4M-sample slices; widget-level median assertions in tests.
VRAM 有界 + 最久未用释放（诊断计数可验证） — eviction tests assert LRU order, release invocation, bytes_now ≤ budget, counters; paint-time keepalive and oversized-single-entry rules covered.
预算可配置；切换 colormap 不触发 L1 重读 — default/clamp/env tests; SeismicView toolbar colormap switch asserts zero renormalize calls, L2 entry retained (same key), L1 .get never invoked.
多视图共享同一全局预算 — two SeismicViews share the singleton; identical slices dedup across views (entries don't grow with view count); cross-view global LRU eviction.
Verification
New suite tests/test_vram_texture_cache.py — 18 passed.
Seismic regression subset (cache/LUT, 2D3D consistency, view panel, attribute panel, workflow, well-seismic scene, preview cache, prediction flow …) — all green.
Full-suite failures in mapping/canvas tests (unified_map*, scalar_raster_mirror, …) reproduce identically on clean main baseline — environmental (native C++ extensions fail to load in this sandbox), unrelated to this change.
Contains a geo-viz-engine submodule bump to feat/1078-vram-texture-cache (engine commit 2b9eee68).

Two-axis review response (f6fbd3c4 + 3efc8a9)
Ran the repo's /code-review (Standards + Spec, parallel reviewers). Findings addressed:
Spec — cross-view key collision (real bug): _l2_texture_key carried only the per-view SEGY generation (both views start at 0), so two views on different files could collide keys and serve each other's index textures. Keys now carry a volume identity (SEGY path for surveys; CPU preview array id for demo volumes) — same-file views still dedup into one entry, different-file views never cross-serve. _render_l2_hit also refuses shape-mismatched entries. Two regression tests added.
Spec — benchmark scope: the script now also times the end-to-end SeismicView revisit pipeline (key build + VRAM.get + panel refresh), not just the renderer half: 2.2–6.2 ms at 0.56M–4M-sample slices. The structurally vacuous l1_reads == [] assertion was dropped.
Standards: hit-or-store dance extracted into _render_profile_with_l2 (3 sites); the four identical wiggle VRAM.put blocks collapsed to one per method; dead API surface removed (register alias, resident_kinds, touch_count); test spy scaffold deduped into a count_normalize fixture.
Left as-is (explicit > clever): the seven per-texture eviction hooks in renderer_3d.py and the cache.py re-export (the latter follows the design doc's §4.1 single-import-site intent and is contract-tested).
All 20 L2 tests + seismic regression subset green after the fixes.
