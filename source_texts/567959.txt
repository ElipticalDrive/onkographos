Blender 5.0: Cycles¶
Volumes¶
Unbiased Sampling¶
A new volume rendering algorithm based on null scattering has been added as the default. It is unbiased, removes blocky artifacts in overlapping volumes, and eliminates the need for step size, max steps, and homogeneous volume settings. (PR#134460, PR#146317)
The performance and noise level can be different than before and is scene-dependent. If the volume renders slower and looks different than before, it's usually because the step rate was too large and the result was biased. Simple scenes and heavily tuned volume shader may be faster with biased rendering, while unbiased eliminates the need for manual tuning and can better handle mixed dense and thin volumes.
For more control over rendering quality, the previous biased ray marching algorithm can be enabled with the Render -> Volume -> Biased option; this also restores the previous step size and max steps options.

Grids & Interpolation¶
Smoke and fire simulations are now rendered with NanoVDB. This reduces memory usage at the cost of some performance. (PR#132908)
Cubic and linear interpolation now uses stochastic sampling when possible, to improve performance. This adds a typically very small amount of noise, while performance is similar to closest interpolation. Depending on the volume shader, render results may be somewhat different. (PR#132908, PR#144451)

Subdivision and Displacement¶
Adaptive subdivision is no longer an experimental feature, and always available in the Subdivision Surface modifier. (PR#146723)
New adaptive subdivision Object space option, to specify an edge length in object space rather than a pixel size. This is needed for object instancing to use little memory, by subdividing the mesh once independent of camera size and then instancing it many times. (PR#146723)
When using displacement, the Normal Map node now uses the undisplaced normal and tangent. This matches EEVEE behavior, and is the right behavior using a matching normal and displacement map. (PR#143109)
The undisplaced normal and tangent attributes are now available through undisplaced_n and undisplaced_tangent. The N and tangent attributes now always include displacement. (PR#143109)
Custom Cameras¶
Improve the user interface of parameters for the OSL Camera. (PR#146736)
Add support for the following metadata:
Distance inputs (string unit = "m")
Translation inputs (string vecsemantics = "POINT")
Angle inputs (string unit = "radians")
Normal inputs (string vecsemantics = "NORMAL")
Time inputs (string unit = "s" or string unit = "sec")
File inputs (string widget = "filename")
Enum inputs (string widget = "mapper", string options = "left:0|right:1")
Breaking Change¶
The aperture position does not depend on the camera’s focal length any more. (PR#147346)
This allows getting consistent depth of field, independent from the Blender camera focal length.
However it means the aperture position must now be multiplied by the OSL focal length parameter inside the shader:
```
 getattribute("cam:aperture_position", position);
 position *= focal_length * 1e-3;
```
GPU¶
The minimum supported compute capability is sm_50 now (~GeForce 900 cards). (PR#142212)
The minimum required Windows AMD GPU driver has increased to Adrenalin version 24.9.1 or Radeon Pro driver 24.Q4 (PR#148305)
The OptiX denoiser result quality is improved by flipping the image vertically to have a top-left origin before processing. (PR#145358)
Other Features¶
Add Linear 3D Curves, a new option in the curves panel in the render properties. This renders curves as linear segments rather than smooth curves, for faster render time at the cost of accuracy. (PR#139735)
Add Render Time pass, which visualizes the time spent to render each pixel (PR#125933)
Add Portal Depth light pass information (#143107)
The default material when the object has no material assigned now matches Blender and EEVEE, adding a specular component. (#142703)
Remove Use Tiling option, it is now always assumed to be on. The tile size can be increased to disabled tiling. (PR#146031)
