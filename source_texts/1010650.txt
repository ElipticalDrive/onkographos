Summary
Replaces the analytic height-fog background blend with real volumetric fog: a froxel-grid raymarching pipeline (Inject → Integrate → Apply) with sun/light in-scattering, shadow sampling in the volume, and noise-based density, implemented on Metal, OpenGL, Vulkan, D3D11 and D3D12.
Adds host-side FogVolume data, env/inspector fields, serializer support (with old-scene backward compatibility), weather-system hooks (fog bank/noise driven by presets), and a volumetric default for new scenes.
Keeps the existing analytic fog as the fallback for backends/hardware that can't run the volume (supportsVolumetricFog capability, gated per backend).
Changes
Design/docs: docs/volumetric-fog-plan.md and per-backend acceptance docs (Metal, Vulkan, D3D11, D3D12) recording the froxel approach, data formats, performance budget and hardware witnesses.
Core data: src/HE_Rendering/include/HorizonRendering/FogVolume.h, RenderExtractor/RenderWorld wiring, EnvironmentSettings.h/EnvironmentComponent.h fields, editor InspectorPanel/EditorHelp/HcNodeDocs entries, ProjectManager default for new scenes.
Metal: compute Inject/Integrate, Apply split from the scene encoder, heApplyFogT on texture 17 (MetalRenderer.mm/.h).
OpenGL: fragment-path Inject/Integrate/Apply (OpenGLRenderer.cpp/.h).
Vulkan: SPIR-V compute kernels, Apply split, binding 34 (VulkanRenderer.cpp, VulkanMaterialLayout.h).
D3D11: HLSL compute Inject/Integrate (giShadowCS pattern) + fullscreen Apply, own shadow fill for Inject, HE_FOG_VOLUME define and t34 binding for forward graph materials (D3D11Renderer.cpp, D3D11MaterialBindings.h); Inject moved to run after the shadow pass so it reads current-frame shadows.
D3D12: same Inject/Integrate/Apply wiring plus root-signature/t34 support for graph materials (D3D12Renderer.cpp, D3D12MaterialRootSignature.h).
Shared shader source: src/HE_Rendering/src/material/FogVolumeShaderSource.h, MaterialShaderLibrary HLSL cross-compile path (via SPIRV-Cross) for all three kernels.
Weather/scene: WeatherSystem.cpp drives fog bank/noise from presets; EngineApi/EnvironmentPush expose the new fields.
Tests: tests/test_fog_volume.cpp (new, 724 lines), plus updates to test_scene_serializer.cpp, test_weather.cpp, test_material_graph.cpp, test_engine_api.cpp, test_third_person_template.cpp.
Testing
Metal: witness captures (sun shafts, fog bank, point light, with/without lights) under docs/volumetric-fog-metal-2026-11-02/.
OpenGL: headless-dump witnesses on macOS.
Vulkan: MoltenVK syntax check locally, lavapipe CI image test.
D3D11 + D3D12: hardware-verified on NN-WS03 (RTX 4070) — HorizonEditor builds clean, full he_tests green (6159/6159), HE_DUMP_FOGTEST run on both backends in both fog modes (mode 0 vs 1), fallback confirmed both in code (supportsVolumetricFog false by default) and in pixels (zero byte diff in the ground/fog region between modes, aside from known D3D11 sky-cloud time drift).
Not verified: HE_FOG_PARITY=1 pixel-tolerance measurement against mode 0 (plan §9) was not run; deeper pixel characterization of the mode0/mode1 diff beyond raw byte-diff count was not done; a test_physics_threading.cpp SEH crash seen in one full he_tests run was not confirmed pre-existing (unrelated code, no baseline comparison done); CI run 42239434867 was triggered but its result was not observed.
An internal code review (step review-225-1) approved the weather hooks, new-scene default, and FogVolume/extractor wiring, with two minor findings noted: Vulkan's capability gate should also check m_postFxReady, and WeatherSystem::drive() can overwrite authored fog-bank/noise values even while fogMode is 0.
Notes
D3D12 root-signature binding is strict (a missing binding rejects the whole PSO), so it was deliberately scoped as its own careful pass after D3D11 was proven out, per agreement with the topic owner.
The two minor review findings above (Vulkan capability gate, weather overwrite at fogMode 0) were not fixed in this branch and may be worth a follow-up.

Four correctness bugs an advisor review found, all GL-only:

1. m_fogViewProjFlip (heApplyFogT, the material-facing read) was set to
   flipY*viewProj, copied from Metal. heApplyFogT's uv = clip.xy/clip.w
   *0.5+0.5 has no mirroring built in, and the rows Inject actually wrote
   (raw, unflipped gl_FragCoord) already line up with a PLAIN viewProj's
   uv — Metal needs the flip because ITS rows run the other way. Every
   translucent-material fog read would have come out vertically mirrored.
   Fixed: m_fogViewProjFlip = viewProj (no flip) for GL.

2. kApplyMain (shared, unchanged) feeds the raw depth-buffer texel
   straight into fv.invViewProj's z. Metal's depth buffer already stores
   NDC z in [0,1] == its own clip convention; GL's depth buffer stores
   (ndc.z+1)/2 (same reason the underwater pass' depthParams use scale 2,
   bias -1). Fixed: compose a depthRemap (z' = 2d-1) into fc.invViewProj
   before the flipY*viewProj inverse — harmless for heFogRayDir's fixed
   z=0.5 probe (same (ndc.x,ndc.y) traces one ray regardless of ndc.z, and
   that call only wants the direction).

3. UBO binding point 0 ("HeLighting" on every GL program) was left on
   m_fogLightUBO (real CSM, fogVol.x=0) after Inject/Integrate — nothing
   between there and the first graph-material draw rebinds point 0 itself
   (the deferred G-buffer pre-fill only calls glBufferSubData), so a
   material would have read the fog pass's lighting fill and double-
   applied the analytic fog on top of Apply. Fixed: save/restore with
   glGetIntegeri_v(GL_UNIFORM_BUFFER_BINDING, 0, ...).

4. GL_CULL_FACE was disabled for the fullscreen Inject/Integrate quads
   and never restored. Fixed: save/restore with glIsEnabled.

Verified: he_tests --source-file=test_fog_volume.cpp,test_material_graph.cpp,test_scene_serializer.cpp
still 178/178, 15713/15713 (these bugs are in render-time matrices/state
the test suite doesn't exercise — only a rendered witness would show
them, which is why they survived the last round).
