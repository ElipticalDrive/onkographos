Goal
Investigate and repair the requested per-element image compositing system. Draft for CI and review, not a release. Based on published experimental.73 for its validated Inspector layout; does not depend on/unpublish experimental.74 Windows identity PR #35.
Findings
Multiply white over white does nothing by mathematics; Multiply/Screen do not remove white pixels from alpha. Off-white paper can leave rectangular seams even when visual blend looks close.
Existing blend_mode is already saved per scene, though displayed in the main Inspector. The Element Editor did not expose it.
Real hand bug: Canvas single-scene preview applied the composition mode to the FULL hand+art frame; multi-scene scenes.stack and exported overlapping frames did the same. A separate hand overlay is required.
Changes
Element Editor APPEARANCE & BLENDING: existing per-element Blend Mode, opacity 0–100%, optional Clean white / paper background with tolerance and edge softness. Scrollable settings and backdrop test picker.
Optional edge-connected near-white neutral background alpha cleanup operates on a detached render QImage. Source/project PNG data untouched; conservative fail-safes and enclosed-white protection, though edge-connected legitimate whites require caution.
Shared export options and frame renderer support artwork opacity while retaining hand normal. Board, multi-scene preview/export and Canvas render hand separately under non-default composition; Normal/100 legacy path preserved.
Older projects and undo snapshots default opacity=100, cleanup disabled. All settings remain per-scene.
Automated Qt/pixel tests on Linux and Windows full suites; candidate version 0.5.3-experimental.75.
Release hold
DO NOT merge/publish/update the installed app without exact-head green checks, verified installer artifact, and hands-on Windows and Filmora preview/export acceptance. Current prototype installer identity .74 remains independent. This is a sizeable change and may need more commits if CI finds an issue.
