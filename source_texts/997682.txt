Summary
On main 3fd5b9548d19aa8c12c29bc9637a96d42a06f8a5, SmApiBoolean can return success with incorrect material/void classification and volume when UNION fills a cavity. Reversing operands changes the result.

H = A - I: volume 784, one material region and one void.

Inputs pass level-2 AssertValid and manifold/census checks immediately before consuming calls. The reproducer uses deep copies, checks result ownership and retained originals, and applies no healing/reclassification. Result validity can still pass despite the wrong census/volume.
Reproducer and proposed fix
https://github.com/CC-David-CC/usd-brep/tree/fix/union-material-survivor
Regression-only commit 761974f979ff61d6df2492146967fd3bf3687edc can be applied to the upstream base without kernel-fix commit 03b5adf9dca5041b14177bf802dde38e2968eca0. It registers TestSmUnionMaterialSurvivor in the existing SM_API runner. Standard native reproduction after applying the test:
```
./repo.sh build
./tests/SM_API_test/SM_API_test.sh linux-x86_64
```
The proposed fix preserves an adjacent finite, unattributed material region during ordinary postprocessed manifold UNION face deletion. Other operations and specialized modes retain their existing policy. Please review that assumption.
Validation
The exact focused C++ test compiled to WASM with Emscripten 4.0.10 fails on upstream at the first exact-fill census assertion and passes with the fix. The fixed test covers both orders of exact/enclosing/composite fills and overlap/disjoint controls; later baseline cases are not claimed to have run.
Native g++ syntax checks pass; native CPU execution and the full upstream suite were not run. A separate bounded 48-expression box corpus found 6 corrected, 34 passing on both builds, 2 unchanged partial-fill failures and 6 boundary-only cases outside scope, with no new regressions. This is not general Boolean qualification.
