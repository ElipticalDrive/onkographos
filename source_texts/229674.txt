Add a parallel AMD ROCm (gsplat) rasterization backend for the static-3DGS training path of Mobile-4DGS. The native CUDA extension remains the primary choice; the gsplat backend is selected only when the extension is not compiled, so the CUDA workflow is unchanged.
Design (CUDA-safe)
gaussian_renderer/__init__.py (the only pre-existing file touched): try: <original CUDA import> / except ImportError: <gsplat backend>. Verified both directions — with diff_gaussian_rasterization_fluxgs built, the original module wins (byte-identical behavior); without it, rocm_adapter/ loads and training runs.
Everything else is new files: rocm_adapter/ (adapter, one-shot setup script, docs). train.py, scene/, utils/, submodules/ are untouched.
Verified on AMD Instinct MI300X (ROCm 7.0, gsplat 1.5.3 ROCm wheel)
Full static-3DGS training loop runs end-to-end: forward/backward, multi-view alpha densification (clone/split/prune active — counts move), model save at each saving iteration, ~100 it/s.
Gradient contract: means2D.grad per-gaussian viewspace gradients are finite and non-zero on the rows the Inria kernel would mark visible; all five attribute gradients (means/scales/quats/opacities/colors) finite on the synthetic-scene smoke run.
A one-gaussian rendering probe on this wheel (fixed focal, 128px) — scale 0.05→10px blob, 0.5→99px, symmetric, monotonic — documents that this ROCm kernel consumes raw linear scales, which the adapter now respects (the upstream gsplat Python API assumes log-space for the CUDA build; applying log() here is a 10⁵× magnification). Note in rocm_adapter/IMPLEMENTATION.md §3 + fix commit.
Known scope boundaries (upstream Mobile-4DGS features, not covered)
Neural-attribute / SH-compression stage (step ≥3000, apply_attribute_stage_transition → tcnn.NetworkWithInputEncoding): tiny-cuda-nn is CUDA-only and does not build for ROCm, so runs past ~3000 iters with the SH-aggregator path target NVIDIA. Static path before that stage, plus the full rasterizer + densification contract, is covered here.
4D dynamic path (velocity field / time axis / SVQ / N3DV): still targets the CUDA extensions; not covered by this backend.
Verified training runs therefore use the pre-net_itr window (≈2000–3000 iters on synthetic data, real PSNR-style fidelity requires the full 30k schedule which is out of scope here).
Install & run
```
bash rocm_adapter/setup_rocm_env.sh   # venv @ ./gs210venv: torch 2.10.0+rocm7.0 + gsplat 1.5.3 wheel + shims
source ./gs210venv/bin/activate
python train.py --source_path <scene> ...   # identical CLI to the CUDA path
```
Full record: rocm_adapter/IMPLEMENTATION.md — ABI matrix (torch/gsplat), the three contract-gap fixes with kernel-source citations, the scales-convention probe, the tcnn boundary, and the reproduction steps.
