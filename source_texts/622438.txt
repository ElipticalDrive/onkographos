Fixes #60. Fixes #59.
#60: vol[i] returned slices
The [ methods guessed between x[i, , ] and linear indexing from the values of i. On DenseNeuroVol, vol[which(mask)] returned whole first-dimension slices whenever every index was ≤ dim(vol)[1]. SparseNeuroVol and ClusteredNeuroVol (the ArrayLike3D method) never did linear indexing at all; sv[c(6, 8)] returned 48 values including an NA.
The choice is now made from the shape of the call, as in base R:
x[i] and x[i, drop = FALSE] are linear indexing (drop is not an index).
x[i, ], x[i, , ], x[i, , k] index the first dimension.
nargs() is only reliable if the method has the generic's formals: declaring k makes R wrap the body in .local(), where x[6] and x[6, ] both give nargs() == 4. The three methods now take (x, i, j, ..., drop) and recover k from .... Sparse volumes return plain values rather than a sparseVector.
The same bug also broke conn_comp() on first-row clusters ("argument lengths differ"), split_fill() (wrong values) and as.sparse(<DenseNeuroVol>, <numeric>) (error). All three are now covered by tests.
One test changed: test-array-like.R expected vol[1, drop = FALSE] to be a 1×2×2 slice. On master that held only because 1 fit the first dimension (vol[3, drop = FALSE] was linear), so it recorded the #60 heuristic. It now asserts the base-R result; slicing with drop = FALSE is still tested via vol[1, , , drop = FALSE].
#59: single-cluster warning
ClusteredNeuroVol() no longer warns "clustered volume only contains 1 partition". A single cluster is an ordinary conn_comp() result.
Evidence
Full suite (NOT_CRAN=true): 1377 tests, 0 failures, 0 errors.
test-linear-index-dispatch.R run against master: the linear-indexing, which(mask), split_fill tests fail and the conn_comp/as.sparse tests error; all pass on this branch.
An independent review probed named arguments, NA/negative/zero-length indices, sapply(vols, "[", 6), every inheriting subclass and internal [ callers; nothing relied on the old slicing.

Preserve explicitly empty third-dimension selections
When the third index is explicitly NULL, such as vol[1, , NULL, drop = FALSE], extract_k() returns NULL and this branch treats it as an omitted index, returning every z-slice instead of an empty selection. Previously, the explicit NULL reached the backing array and produced dimensions c(1, dim(vol)[2], 0). This can silently include unwanted voxels when a programmatically constructed slice selection is empty. Distinguish a missing third index from an explicitly supplied NULL in both dense methods and the shared ArrayLike3D method.
