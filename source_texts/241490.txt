Descripción
Pipeline de rendering híbrido que combina ray marching SDF para el mundo con rasterización tradicional para personajes/objetos animados. Lo mejor de ambos mundos.
Motivación
SDF es excelente para mundos procedurales, terreno, colisiones. Pero es problemático para personajes animados. La solución es usar ambos.
Arquitectura
```
┌─────────────────────────────────────────────────────────────────┐
│                   HYBRID RENDER PIPELINE                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Pass 0: GPU Culling & Preparation (compute)                    │
│  ├── Frustum culling (meshlets y SDF instances)                 │
│  ├── Occlusion culling (HiZ)                                    │
│  ├── LOD selection                                              │
│  └── Output: indirect draw buffers                              │
│                                                                 │
│  Pass 1: SDF Ray March                                          │
│  ├── Input: Camera, SDF Scene                                   │
│  ├── Process: Ray march mundo completo                          │
│  └── Output: Color buffer + Depth buffer                        │
│                                                                 │
│  Pass 2: Mesh Rasterization                                     │
│  ├── Input: Skinned meshes, Depth de Pass 1                     │
│  ├── Process: Vertex skinning + Fragment shading                │
│  ├── Depth test contra Pass 1 (oclusión correcta)               │
│  └── Output: Color buffer (composited)                          │
│                                                                 │
│  Pass 3: Transparency (opcional)                                │
│  ├── Partículas, efectos, vidrio                                │
│  └── Order-independent transparency                             │
│                                                                 │
│  Pass 4: Post-processing                                        │
│  ├── Bloom, Tonemapping                                         │
│  ├── Anti-aliasing (TAA/FXAA)                                   │
│  ├── Screen-space effects (SSAO, SSR, SSGI)                     │
│  └── Output: Final frame                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

Meshlet Pipeline (Nanite-inspired)
Qué es meshopt y por qué usarlo
meshopt (crate meshopt) es una librería de optimización de meshes que provee:
Meshlet generation: divide un mesh en clusters de ~64 verts / ~124 tris
Vertex cache optimization: reordena índices para mejor cache hit rate
Overdraw optimization: reordena meshlets para minimizar overdraw
Simplification: genera LODs con error bounds garantizados
Quantization: comprime vertex data
Pipeline de Virtual Geometry
```
                    OFFLINE (Asset Pipeline)
┌──────────────────────────────────────────────────────┐
│  Mesh → meshopt::simplify() → LOD chain              │
│  LOD chain → meshopt::build_meshlets() → Meshlets    │
│  Meshlets → Cluster DAG (parent-child relationships)  │
│  Cluster DAG → GPU buffers                            │
└──────────────────────────────────────────────────────┘

                    RUNTIME (Per Frame)
┌──────────────────────────────────────────────────────┐
│  Compute Pass 0: Instance culling                     │
│  ├── Frustum cull instances                           │
│  └── Output: visible instance list                    │
│                                                       │
│  Compute Pass 1: Cluster/meshlet selection            │
│  ├── Per-instance: traverse LOD DAG                   │
│  ├── Screen-space error metric → select LOD level     │
│  └── Output: visible meshlet list                     │
│                                                       │
│  Compute Pass 2: Meshlet culling                      │
│  ├── Per-meshlet: frustum + backface + HiZ occlusion  │
│  └── Output: indirect draw args                       │
│                                                       │
│  Render Pass: Draw visible meshlets                   │
│  ├── Uses indirect draw (GPU-driven)                  │
│  └── No CPU readback needed                           │
└──────────────────────────────────────────────────────┘
```
Integración con SDF
El depth buffer del SDF pass se usa como HiZ (Hierarchical-Z) para occlusion culling de meshlets:
El terreno SDF oculta meshlets detrás de él → se descartan en GPU sin dibujar
Reducción dramática de overdraw en escenas con terreno complejo
Ejemplo de Código
```
pub struct HybridRenderer {
    sdf_pass: SdfRenderPass,
    mesh_pass: MeshRenderPass,
    post_pass: PostProcessPass,
    depth_texture: Texture,
    color_texture: Texture,
}

impl HybridRenderer {
    pub fn render(&mut self, world: &World, camera: &Camera) {
        let mut encoder = self.device.create_command_encoder(&Default::default());
        
        // Pass 1: SDF world
        self.sdf_pass.render(
            &mut encoder, &self.depth_texture,
            &self.color_texture, world, camera,
        );
        
        // Pass 2: Mesh characters (reads SDF depth for occlusion)
        self.mesh_pass.render(
            &mut encoder, &self.depth_texture,
            &self.color_texture, world, camera,
        );
        
        // Pass 3: Post-process
        self.post_pass.render(
            &mut encoder, &self.color_texture, &self.output_texture,
        );
        
        self.queue.submit([encoder.finish()]);
    }
}
```

Consideraciones
Sombras cruzadas
Personaje proyecta sombra en terreno SDF
Terreno SDF proyecta sombra en personaje
Requiere shadow map híbrido o screen-space shadows
Performance Budget
GPU culling + LOD selection: ~0.3ms
SDF pass: ~4-6ms (depende de complejidad de escena)
Mesh pass: ~2-3ms (con virtual geometry, sin overdraw)
Post-process: ~1-2ms (SSAO + bloom + TAA)
Target: <16ms total (60 FPS)

The hybrid pipeline already exists (3 pipelines coexisting in the same render target since #129 / #235 / #237). What this issue gates is the Surface Nets compute bake that takes a chunk's sparse SDF (#136) + delta tree (#307) and produces vertex / index buffers consumable by the existing MeshPassRenderer. No new pipeline, no rewrite of mesh / raymarch — just routing per chunk: near → raymarch SSBO, far → mesh draw indirect.
Surface Nets, NOT Dual Contouring — simpler, no Hermite data, no sharp-feature edge cases, supported in Rust (fast-surface-nets crate). Reference: Nick Gildea's chunked terrain work + bonsairobo's deep-dive (https://bonsairobo.medium.com/smooth-voxel-mapping-...).
No SDF puro raymarching for horizon. Confirmed by research: Dreams, Claybook, no shipping engine ever scaled this way. Sphere tracing collapses past 5 km (f32 precision); mesh bake is the only documented path to planet-scale.
GPU-driven retained. Meshlet pipeline + indirect draw + HiZ occlusion remain. Surface Nets bake itself is a compute pass — no CPU job.
