Simplifications to improve computational throughput
• Hexahedral elements (sparse, tensor product operator)
• Polynomial range 1-7 (small static matrix sizes)
• 5 or more field variables (parallelize over fields)
• Point-by-point works well for small NcellsN(p+1)Nvars
• Expose as much parallelism – N3(p+1)
Data requirement: A line of data is
required to compute a derivative
• Computing full line/plane works better for large NcellsN(p+1)Nvars
• Utilize cache hierarchy (shared memory) to increase arithmetic intensity
Matrix-Multiplication: (p+1) derivatives can be computed on all NcellsNvars for all lines in a cell 3N2(p+1)

Discussion
• Performance portable implementations are essential to meet DOE missions
• Library support from Trilinos/Kokkos offers an efficient way to meet this challenge for
large scale, high-fidelity simulations
• SIMD performance portable libraries offer a means to perform explicit vectorization on
a variety of different architectures
• Performance portable kernels for higher order operators are still a work in progress
• End-to-end performance is promising but more R&D is needed to improve robustness
and performance for high-order methods and hypersonics
Future Work
• Additional data layout testing (strided or AoSoA)
• Full integration of Kokkos SIMD
• Improve performance portability of nonlinear operator
• Assess and improve end-to-end performance of solvers
• More preconditioner testing (Polynomial & Reduced Basis)

Exascale computing
Challenges:
• Diverse set of HPC vendors and architectures
•
•
Intel, AMD, NVIDIA, IBM, ARM-based
CPUs with vector processing; GPUs
• Software life cycle is much longer than hardware
Different architectures, trend remains the same
• Need algorithms with high arithmetic intensity (total ops/byte)
• Need fundamental abstractions during code development
Performance portability: A reasonable level of performance is achieved across a wide variety
of computing architectures with the same source code.
Approaches:
• Libraries – High-level abstractions with specified input/output (e.g. BLAS)
• Task-based – Data-centric abstractions for mapping tasks to resources (e.g. Legion)
• MPI+X – Algorithmic-level abstractions for distributed (MPI) and shared (X) memory
parallelism (e.g. Directives: OpenMP, OpenACC; Frameworks: Kokkos, RAJA, OCCA)
