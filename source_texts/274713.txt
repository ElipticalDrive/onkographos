Our serialization of DTI to nifti is deviating a bit from the nifti spec, which does have things to say about DTI in particular.
Fixing it would remove a lot of surprises, and allow loading DTIs into Slicer without needing any tricks.
AI generated issue description
Summary
Dti.save() writes diffusion tensors using a NIfTI layout that does not conform
to the NIFTI_INTENT_SYMMATRIX specification. As a result, 3D Slicer does not
recognize the saved file as a diffusion tensor volume.
Current behavior
Internally, kwneuro represents a DTI as an array with shape:
```
(X, Y, Z, 6)
```
with components in the correct NIfTI lower-triangular order:
```
Dxx, Dxy, Dyy, Dxz, Dyz, Dzz
```
During estimation, the header is configured with:
```
intent_code="symmetric matrix"
intent_params=(6,)
intent_name="DTI"
```
The resulting NIfTI header therefore contains approximately:
```
dim = [4, X, Y, Z, 6, 1, 1, 1]
intent_code = NIFTI_INTENT_SYMMATRIX
intent_p1 = 6
```
When loaded in 3D Slicer, this file is loaded as a
vtkMRMLScalarVolumeNode with one scalar component per voxel, rather than as a
vtkMRMLDiffusionTensorVolumeNode.
Expected behavior
According to the NIfTI specification, a 3×3 symmetric matrix must be stored as:
```
shape = (X, Y, Z, 1, 6)
dim[5] = 6
intent_code = NIFTI_INTENT_SYMMATRIX
intent_p1 = 3
```
intent_p1 specifies the matrix dimension (N=3), not the number of stored
lower-triangular components.
Reference:
https://nifti.nimh.nih.gov/nifti-1/documentation/nifti1fields/nifti1fields_pages/group__NIFTI1__INTENT__CODES.html/document_view.html
ITK also reads symmetric-matrix components from dim[5]:
https://github.com/InsightSoftwareConsortium/ITK/blob/main/Modules/IO/NIFTI/src/itkNiftiImageIO.cxx
Suggested fix
Keep the convenient internal (X, Y, Z, 6) representation, but use a
DTI-specific disk conversion:
When saving, insert a singleton fourth dimension to produce
(X, Y, Z, 1, 6).
Set intent_params=(3,).
When loading a DTI, remove the singleton dimension to restore the internal
(X, Y, Z, 6) representation.
Consider supporting existing kwneuro-generated (X, Y, Z, 6) files as a
legacy input format.
Tests could verify:
The saved header has dim[0] == 5, dim[4] == 1, and dim[5] == 6.
intent_code is NIFTI_INTENT_SYMMATRIX.
intent_p1 == 3.
A save/load round trip preserves the internal tensor array and metadata.
I verified that changing the disk layout to (X, Y, Z, 1, 6) and setting
intent_p1=3 causes 3D Slicer 5.10 to load the file as a
vtkMRMLDiffusionTensorVolumeNode, with the tensor components reconstructed
correctly.
