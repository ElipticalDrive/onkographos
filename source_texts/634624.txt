Summary
complete the VOX + DIGS v0.0.1 vertical slice with a strict C89 mini-voxel/material oracle, C++98 fixed-point collision, versioned Rust host boundary, optional NASM parity leaf, and CPU RGB Lightfield renderer
add the SDL2 graphical host with title/setup/options/Foundry/pause/results/QA screens, 0–3 bots, three seeded maps, ten weapons, procedural audio, six frame-cap choices, fullscreen, and debug overlay
add authoritative projectiles/effects, health/damage/death/gore/respawn/scoring, rising lava, water/lava cooling, fire/smoke, sand, and firedamp reactions
add reproducible XLSX QA generation, a multiline-safe xleak testing cockpit, structured GitHub feedback form, easy Linux x86-64 launchers, Corresponding Source, raw package evidence, SPDX 2.3 SBOMs, and checksummed bundles
make CI run the extension-free strict C89/C++98 + NASM + SDL2 + Rust gate and upload the tester/source bundles
Why
This turns the initial engine foundation into the first genuinely playable and testable statement of intent for VOX and DIGS while keeping simulation deterministic, CPU-authoritative, bounded, and portable behind C interfaces.
Tester impact
After CI completes, download the vox-digs-v0.0.1-linux-x86_64 artifact, verify SHA256SUMS, extract it, and run ./run-digs.sh. The bundle also provides smoke-test.sh, benchmark.sh, qa-cockpit.sh, four binaries, the feedback workbook, raw test evidence, licenses, source, and SPDX inventories.

xleak multi-workbook export/merge, smoke, benchmark, both headless proofs, Markdown report, and evidence packet
clean-commit Linux binary/source packaging, checksum verification, extracted launcher smoke, and separate SPDX 2.3 inventories
Claim boundary
This is a Linux x86-64 CPU-software-rendered demo candidate. Rust and NASM are versioned/optional contract probes, not gameplay accelerators. The GTX 1660 Ti is not used by v0.0.1. Windows, macOS, historical adapters, GPU rendering, networking, Havok-scale rigid bodies, and full manual desktop acceptance remain evidence-gated roadmap work.

Wake neighbors after clearing terrain
When terrain is removed through vox_world_set(..., VOX_MAT_AIR)—for example the pick/exact-cell tool path—this returns after clearing only the target cell. Any structural cell above it can still be asleep, and vox_step_structures only scans active/awake chunks, so a supported soil/stone block whose support was picked away never becomes unstable or falls until some unrelated blast/move wakes it. Clearing a cell should wake the cells that may have depended on that support before returning.
