SDFs and their relation to voxels?
Question
Hello! Wasn’t sure where to post this question so posting it here. To edit and render SDFs, do we need to use voxels? Isn’t the whole point of using SDFs so that we can have exact values for distance? Using voxels means interpolation is required, producing non-smooth surfaces. However, it seems like in videos that people use voxels to represent SDFs.
Really the question is for rendering are we using signed distance fields or signed distance functions?

You can use a voxel-based system to store distance fields. However, you’re limited to the resolution of the voxel grid, and the voxel data can take up a lot of space.
Isn’t the whole point of using SDFs so that we can have exact values for distance?
In practice, the values will often not be exact. They will be close enough.
Using voxels means interpolation is required, producing non-smooth surfaces.
You can get smooth surfaces using interpolation and voxels. It’s fine.

The most popular alternative to using a voxel grid is to write a formula for your distance field. This is… not easy. You’re basically writing a mathematical formula for your distance field—I hope you like staring at equations for hours at a time. Distance fields also suffer from poor performance, which is why they are generally not used in games (not counting 2D).

All uses of SDFs evaluate them in some sort of "grid". For sdfs in shaders, the grid is the grid of pixels on your display.
For sdfs that you convert to models, you're using some possibly adaptive resolution grid like an octree to nail down the sdf at discrete points in space.
But voxels in the classical sense are little cubes. For sdfs, you evaluate the SDF at discrete points in space and you can use an algorithm like marching cubes to triangulate that field into a continuous surface.. so they don't Have to be "voxels" in that sense.

To get something out of them you pretty much have to have a grid of some kind (pixels, sampled cells/edges, etc).
You might have a BVH or something for the SDF evaluation that does a really basic bytecode evaluation or is generated code. It's not really anything special to walk a BVH in a shader these days.
In a project that's limited in scale I just generate the code for the compute shader from the CSG Tree of the SDF shapes.
