Member
Point clouds can now hide the points seen "from behind", e.g. a wall of a LiDAR map viewed from its back side.
Changes
mrpt_viz: VisualObjectParams_Points gets an optional per-point direction buffer (setPointDirections()), plus enableHideBackFacingPoints() and setBackFacingMaxAngle() (degrees, default 90). All serialized (points params serialization v1).
mrpt_opengl: new POINTS_HIDE_BACK_FACING shader (vertex attribute 2 = direction). PointsProxy::requiredShaders() selects it only while the feature is enabled and the direction count matches the point count; every other point cloud keeps the plain POINTS shader and uploads no extra buffer. Hidden points are moved out of the clip volume in the vertex shader; orthographic cameras are handled.
mrpt_maps: CPointsMap::getPointDirectionsForRendering() returns directions from normal_{x,y,z} if present, otherwise view_{x,y,z}, reporting which one was used. TRenderOptions gets hide_back_facing, back_facing_max_angle_normals_deg (90) and back_facing_max_angle_view_deg (120), used by getVisualizationInto(). View vectors are a rough proxy of the surface side, hence a wider default angle.
Docs: new section in the 3D scenes tutorial.
Python bindings are intentionally not updated yet.
Used by mm-viewer and the MOLA LiDAR odometry GUI (companion PRs in mp2p_icp and mola_lidar_odometry).
Summary by CodeRabbit
New Features
Point clouds can hide points facing away from the camera when per-point directions are available; this option is off by default.
Set the maximum visible angle. Surface normals default to 90°, while sensor-view directions default to 120°.
Direction data and visibility settings are preserved when saved, with older saved settings remaining compatible.
Documentation
Added tutorial guidance covering direction sources, angle thresholds, and when back-facing point filtering applies.

Point cloud objects (VisualObjectParams_Points) can now hold one direction
vector per point, pointing to the side from which the point should be
visible (e.g. a surface normal, or the direction towards the sensor). When
enabled, points whose direction is farther than a given angle from the
direction towards the camera are not rendered.

- mrpt_viz: setPointDirections(), enableHideBackFacingPoints() and
  setBackFacingMaxAngle(); all of them serialized.
- mrpt_opengl: new POINTS_HIDE_BACK_FACING shader, selected by PointsProxy
  only while the feature is enabled and directions are valid, so other point
  clouds keep the plain POINTS shader at no extra cost. Hidden points are
  moved out of the clip volume in the vertex shader.
- mrpt_maps: CPointsMap::getPointDirectionsForRendering() takes directions
  from the normal_{x,y,z} fields or, otherwise, view_{x,y,z}; new
  TRenderOptions hide_back_facing and per-source max angles, used by
  getVisualizationInto().

Walkthrough
Point rendering now supports optional GPU filtering of back-facing points. It uses per-point normals or view directions and configurable angle thresholds. The changes add point-object controls, CPointsMap integration, serialization support, and a dedicated shader.
Changes: Back-Facing Point Filtering

Summary
Point direction and filtering state

VisualObjectParams_Points stores per-point directions, a filtering flag, and a maximum angle. Serialization reads versions 0 and 1. Clearing point clouds also clears their direction buffers.
CPointsMap rendering integration

CPointsMap adds filtering options and selects complete normal fields before view-direction fields. It applies the corresponding angle limit and directions to single-color and colormapped point clouds. Direction fields rotate when points are inserted with a non-identity pose.

The rendering proxy selects the dedicated shader when filtering is enabled and direction data matches the point count. The shader compares each direction with the camera direction and clips back-facing points. The tutorial documents the feature and its defaults.
