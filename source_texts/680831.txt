Issue description
I recently wanted to port a volumetric raymarching shader which renders voxel objects from Unity to Godot.
The workflow is:
Use a 3D texture which stores voxel data (i.e. color as RGBA or just one byte for color palette index)
Render a volume (box) in the size of the voxel object with faces flipped
For each fragment, execute a raymarch function which searches for a ray - voxel intersection
When no voxel could be found
discard fragment
When a voxel was found
Calculate depth of the found coordinate and write to gl_FragDepth in a depth prepass shader so depth testing works
Calculate the fragments world position, normal, etc. and use this instead of the original position passed from vertex to fragment shader so lights, shadows, reflections etc. look correct - otherwise
And on the last step I got into trouble because there is simply no way to output the raymarched position to the generated shader code.
Also, in some sections the geometric normal is being used instead of the normal which might come from a normal map and that one can also not be altered as the normal_interp varying is directly used for those.
My proposal to fix this issue would be to simply add two new parameters like SURFACE_POSITION and SURFACE_NORMAL so custom shaders can override a fragments surface position and normal.
I think this would also be very useful for other volumetric shaders, i.e. volumetric smoke and SDF (signed distance fields) shaders which are affected by lights and shadows.
Steps to reproduce
Create a new Godot project
Create a directional light
Set rotation to [-38, 145, 0]
Enable shadows
Create a camera
Set position to [0.85, 1.8, 0.65]
Set rotation to [-33, 32, 0]
Create a ground plane
Set scale to [100, 1, 100]
Create a raymarch volume (MeshInstance3D, set to BoxMesh with flipped faces)
Set position to [0, 0.5, -1.0]
Create a new shader material and set as material of the raymarch volume
Create a new spatial shader for the material
Enter the following code:
```
shader_type spatial;

const float MIN_HIT_DISTANCE = 0.001;
const float MAX_TRACE_DISTANCE = 1000.0;
const int MAX_RAYMARCH_ITERATIONS = 256;

float sdSphere(vec3 pos, vec3 center, float radius)
{
    return length(pos - center) - radius;
}

void fragment() {
	vec3 rayOrigin = CAMERA_POSITION_WORLD;
	vec3 positionWS = (INV_VIEW_MATRIX * vec4(VERTEX, 1.0)).xyz;
	vec3 rayDir = normalize(positionWS - CAMERA_POSITION_WORLD);

	vec3 objectPos = NODE_POSITION_WORLD;

	vec3 pos;
	float radius = 0.499f;
	float dt = 0.0f;
	bool hit = false;

	for (int i = 0; i < MAX_RAYMARCH_ITERATIONS; ++i) {
		pos = rayOrigin + dt * rayDir;
		float dist = sdSphere(pos, objectPos, radius);
		
		if (dist < MIN_HIT_DISTANCE) {
			hit = true;
			break;
		}
		
		if (dt > MAX_TRACE_DISTANCE) {
			break;
		}
		
		dt += dist;
	}
	
	if (!hit) {
		discard;
	}
	
	vec3 worldPos = pos; // (modelViewMatrix * vec4(pos, 1.0)).xyz;
	vec4 projPos = PROJECTION_MATRIX * vec4(worldPos, 1.0);
	vec3 normal = normalize(pos);
	
	ALBEDO = vec3(1.0, 0.0, 0.0);
	NORMAL = normal; // (mat3(modelViewMatrix) * normal);
	DEPTH = (projPos.z / projPos.w);
	
	// TODO: Implement this
	// SURFACE_POSITION = worldPos;
	// SURFACE_NORMAL = normal;
}
```
Position the camera so you can clearly see the raymarched sphere (yes, I know, the shader code needs some optimization but it works good enough as a proof of concept).
While you can now see a sphere instead of a box, the shadows and lighting looks really off because it's actually using the original fragment position and normal of the box and there is no way to override this.
I've already created a fork and added the functionallity do set surface position and normal in the spatial shader which then results in correct lighting and shadowing:
