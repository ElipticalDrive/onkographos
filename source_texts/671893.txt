What this does
ChunkCuller.CullInvisibleChunks decides which chunks are visible by casting up to three sub-rays from the camera to every view-distance shell position and marching them chunk by chunk. That cost grows with shell positions times rays times march length, so it scales badly as view distance rises. This replaces the walk with a breadth-first flood over the same per-chunk face-connectivity graph (the "cave culling" technique from Minecraft and Sodium), which is linear in loaded chunks and visits them front to back.
The behaviour is gated by OptimumConfig.BfsChunkVisibility (default on). When it is off, the original vanilla raycast runs unchanged.
Correctness
The flood reuses the existing ClientChunk traversability bitmask (the same data the raycast reads), so it consumes Vintage Story's own opacity model rather than inventing one. A chunk is culled only when every path of mutually-open faces from the camera to it is blocked, which is the conservative criterion: if no open-face path exists, no straight sightline can reach it either. To stay safe against the classic flood false-negative (MC-70850, where a biased single incoming direction hides a chunk that is actually visible), reachability is tested across all incoming faces, not just the one the flood arrived from. The camera chunk and its immediate neighbourhood are always marked visible, the first ring mirrors the vanilla num2 > 1 pass-through, and the flood is bounded by view distance so it cannot run into never-loaded space. In testing the visible chunk set matched the raycast.
Measured cost
Measured in a running client on Linux, piloted through the same fixed-seed world, occlusion culling on:
View distance
Raycast walk
BFS walk
256
~12.7 ms per recompute
~2.4 ms per recompute
1024
~90 ms per recompute
~19.7 ms per recompute
The visibility walk gets roughly five times cheaper, and the gap widens with view distance because the raycast's cost is superlinear while the BFS stays close to linear. The walk recomputes only when the camera crosses into a new chunk, so this is CPU work removed from the chunkculling thread, largest on high-view-distance and CPU-bound setups.
Tests
Optimum.Tests/BfsChunkVisibilityTests.cs covers open-field visibility, a solid wall culling only what is fully occluded behind it, the never-over-cull invariant against a brute-force reachability oracle, the frustum-last and occlusion-off paths, the camera-chunk-always-visible case, the first-ring exemption, and a patch-contract test that pins the inlined walk in the ChunkCuller patch to the unit-tested reference so the two cannot drift. Local gates: dotnet build clean, full Optimum.Tests suite green, make check-patches reports 0 conflicts, make check-compat reports 0 cast divergence against the vanilla donor. The IL patcher transplants the walk and its helpers with 0 self-reference errors, and the patched client boots and runs in world with no exceptions or missing-chunk artifacts.
