Context
vtk.js has no counterpart to VTK's
vtkPointGaussianMapper.
Drawing a point cloud needs verts cells, and there is no way to draw points as
Gaussian splats or to show 3D Gaussian splatting data (scale and rotation per
point).
Results
Point clouds render without cells, as simple points or as Gaussian splats,
including anisotropic 3D Gaussian splats. For the same inputs it draws what
VTK 9.6's vtkPointGaussianMapper draws, apart from the differences listed
below.
Changes
Adds vtkPointGaussianMapper (Rendering/Core) with VTK's API and defaults:
scaleArray, scaleArrayComponent, scaleFunction and scaleTableSize;
opacityArray, opacityArrayComponent, scalarOpacityFunction and
opacityTableSize; scaleFactor (0 draws simple points); splatShaderCode;
emissive; boundScale; and the 3D Gaussian splatting additions
anisotropic, rotationArray and lowpassMatrix. When the polydata has
verts cells, only the points they reference are drawn. Hardware selection
returns point ids, and for cells the verts cells that draw the points.
Adds vtkOpenGLPointGaussianMapper and glsl/vtkPointGaussianVS.glsl.
WebGL2 has no geometry shaders, so each splat is an instance of a
four-vertex triangle strip whose corners the vertex shader places around
the projected Gaussian, with the same EWA projection as VTK's shaders. The
per-point buffers are shared with the simple-point mode rather than
duplicated per corner, and a buffer is uploaded again only when its own
source changes.
Adds an example, Rendering/Core/PointGaussianMapper.
Differences from VTK:
The opacity array applies without scalar colours too, and an opacity array
that goes below one makes the prop translucent.
Non-emissive splats with the default Gaussian falloff render with the
translucent geometry. VTK draws them with the opaque geometry, where the
faded corners of each splat write depth and hide what is behind them
(ParaView #20148).
A splat centred outside the view still draws the part that reaches into
the view. As in the current 3D Gaussian Splatting rasterizer, the
projection is linearized no further out than 30% beyond the view, where
VTK drops the splats centred there.
Scalar colours are always per point: interpolateScalarsBeforeMapping
does not switch them to a texture, which VTK's mapper cannot sample.
Cell scalars colour only the points drawn by verts cells.
Splat sizes do not pick up the VBO shift and scale, so data far from the
origin keeps its splat size.
Every splat keeps one winding, so face culling treats rotated splats like
the others. VTK's eigenvector basis mirrors some of them.
Emissive splats add their coverage to the alpha channel, so they composite
correctly over a transparent background.
Composite datasets are not supported, since vtk.js mappers take polydata.
The last commit adds vtkPointSpriteMapper, a subclass for dense point
clouds that defaults to opaque simple points and adds a point size
multiplier, round points, point sizes in model units, and a draw limit for
progressive loading, with the one extension point it needs in the OpenGL
mapper. It can be dropped from this PR if it is better proposed separately.
Usage:
```
const mapper = vtkPointGaussianMapper.newInstance({
  scaleFactor: 0.1,
  emissive: false,
});
mapper.setInputData(polyData); // points only, no cells needed
mapper.setScaleArray('radius');
mapper.setOpacityArray('opacity');
```

```
Port VTK's vtkPointGaussianMapper with its API and defaults: scale and
opacity arrays with optional piecewise functions, a scale factor where 0
selects simple points, custom splat shader code, emissive blending, the
bound scale, and anisotropic splats from scale and rotation arrays with a
low-pass filter.

The points need no cells. When the polydata has verts, only the points they
reference are drawn. Simple points are one vertex per point drawn as
gl.POINTS. Splats are one instance of a four-vertex strip per point: the
vertex shader projects each 3D Gaussian to a screen-space ellipse, as VTK's
geometry shader does, so the per-point buffers are shared by both modes and
nothing is duplicated per corner. Selection returns point ids in both modes,
and for cells the verts cells drawing the points.

Where VTK drops data, this applies it: the opacity array also works without
scalar colours, and scalar colours never switch to texture colouring. Cell
colours reach points only through their verts cells. Splat sizes ignore the
VBO shift and scale, so distant data keeps its size.

Non-emissive splats with the default Gaussian falloff render with the
translucent geometry, so their faded corners do not hide what is behind
them. Splats centred just outside the view still draw their visible part:
the projection is linearized no further than 30% beyond the view, as in 3D
Gaussian Splatting, instead of dropping those splats. All splats keep one
winding, so face culling treats rotated ones like the others, and emissive
splats add their coverage to the alpha channel, for transparent backgrounds.
```
