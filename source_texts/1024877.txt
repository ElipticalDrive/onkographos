This PR refactors VoxelWorld in reality-engine/src/voxel.rs to add a get_voxel_at(x, y, z) helper method.
Changes:
Implements pub fn get_voxel_at(&self, x: i32, y: i32, z: i32) -> Option<Voxel> using integer Euclidean division to safely map world coordinates to chunk properties without float conversion overhead.
Refactors the ray_cast function's spatial traversal loop to utilize get_voxel_at, centralizing voxel access logic.
Adds test_get_voxel_at to comprehensively cover out-of-bounds, negative coordinates, and empty/unallocated chunk scenarios.
Performance Impact: The performance of ray_cast should remain unaffected as get_voxel_at replicates the previous optimized Euclidean coordinate mapping, avoiding expensive $O(N)$ f32 cast bounds checking and loop unrolling inside the method.

This commit introduces `get_voxel_at` to `VoxelWorld` in `reality-engine/src/voxel.rs` as a counterpart to `set_voxel_at`. It abstracts the coordinate conversion logic (using `div_euclid` and `rem_euclid`) and is designed to return `Option<Voxel>` if the corresponding chunk exists.

This method was used to refactor the hot loop within the `ray_cast` function, centralizing voxel lookups. It includes unit tests to verify behavior with negative coordinates and missing chunks.

Performance impact: Minimal. The inner Euclidean division in `get_voxel_at` avoids float conversions, maintaining the performance optimization achieved in earlier commits, while simplifying the `ray_cast` read logic.
