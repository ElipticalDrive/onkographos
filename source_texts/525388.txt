Issue body actions
Priority P2; F10/F11 and slicing in F13. After baseline instrumentation, decouple histogram work from image submission and use a dedicated image path where measurements justify it. Account for callers that currently depend on ImageView state.
Use one deliberate VTK render policy while preserving persistent actors and camera interaction. Coalesce before expensive point-cloud slice extraction, use bounded detail while dragging and refine on release. Keep render mutations on their owning thread. Share interaction transforms with #144 without altering stored HKL or quantitative slice semantics.
Acceptance: camera, resize, LUT, overlays, picking and slice controls repaint correctly; idle and data-driven render work is measured; stale slice results are discarded; no full-cloud extraction for every intermediate drag event. Depends on #149 and bounded products from #152/#153. No presumed GPU speedup without measurements.
Work already implemented
Existing cumulative actor reuse should be preserved. The proposed renderer work remains measurement-gated; local 2D curve reuse is already implemented.
The local performance implementation passed 14 focused tests and Ruff during the 8 September review; this is not proof of complete issue acceptance. No code from those uncommitted changes has been published as part of this planning batch.
Completion policy
Use Refs for partial PRs. Close only when all acceptance criteria have linked merged code and verification; keep hardware-dependent criteria open until exact-SHA results exist. Retain the closed issue history.
