When raycasting a volume with non-uniform basis the result is depending on the view direction. This is not correct!
This is most likely due to the fact that the step length tIncr in the raycasting shader is computed from entry/exit points within texture coordinates [0,0,0]-[1,1,1] not considering the real extent of the volume.
Example:
Volume (10, 20, 10), contains a sphere created with Volume Creator
Basis (1, 0, 0), (0, 2, 0), (0, 0, 1) -> uniform voxels
View along x
View along y
Side-by-Side - from x (left), from y (right)

I have this issue with my heart dataset and need it fixed. I did some investigation and localized the error to be in the opacity correction part of compositeDVR (compositing.glsl).
The existing opacity correction is based on tIncr which depend on the ray-length in texture space. I tried using the ray-length in model spaces instead (see ea85373). This works and has close to no visual impact on the cube-volumes that I have tried and fixes the issues in the volumes with non-cube voxelssize/basises, for example the sphere from above and my heart dataset.
The commit above is just for testing/proof of concept. I didn't want to do any real changes in the api before I get feedback from you (@martinfalk @ResearchDaniel @petersteneteg).

The suggestion above needs to scale the modelStepSize using the size of the basis to get the same result as before, these three evaluates to the same value for basises on were each axis has same length. For the volumes where we before had the issue, these gives a consistent opacity when rotating, though each of the 3 gives slightly different. For the sphere-example the middle one gives the most similar view as to the sphere with cube-voxels (There is only a numeric difference, no visual difference).
```
    basisSize = (b.x + b.y + b.z)/3;
    basisSize = max(b.x,max(b.y,b.z));
    basisSize = length(b)/sqrt(3);
```
