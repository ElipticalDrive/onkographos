Outcome
Radiologists can review large CT DICOM Series efficiently: measure distances, view DICOM images at the best available source quality, select multiple slices, apply bulk review decisions, complete a review without permanently locking it, and safely produce a consistent label snapshot for ML dataset preparation.
This is an implementation-sized child task of #5.
Context
The workflow was reviewed with radiologists.
A CT Series may contain 300+ slices, so doctors must not be required to manually mark every normal image.
The agreed review semantics are:
doctors primarily mark exceptions as Abnormal or Not sure;
images not marked as Abnormal / Not sure resolve to Normal when the doctor completes the review;
Normal remains an explicit vote option so a doctor can disagree with another doctor's Abnormal / Not sure vote;
completing a review does not make it permanently read-only;
doctors may return later and change their own decisions;
voting/label mutations must be briefly frozen only while a consistent immutable dataset snapshot is captured, not during long-running ML preparation.
Implementation must build on the current canonical DICOM Study / Series / Instance and review/dataset architecture already integrated into the repository. Do not recreate the older cluster-based architecture or duplicate DICOM identity fields.
Scope
1. DICOM ruler
Add a Length / Ruler tool to the existing DICOM viewer.
Requirements:
use the existing DWV capabilities where possible;
measure physical distance from DICOM spacing metadata when available;
zoom/pan must not change the physical measurement;
preserve the existing Area/Rectangle measurement behavior;
handle missing/insufficient spacing safely without inventing millimetres.
2. DICOM display quality
Audit and improve the main DICOM viewport without altering diagnostic content.
Check at minimum:
original DICOM pixel data path;
Window/Level behavior;
viewport/canvas sizing;
high-DPI/devicePixelRatio behavior;
browser scaling/interpolation;
transfer-syntax support;
Fit-to-screen and zoom behavior.
Do not use AI upscaling, sharpening, or synthetic enhancement.
If appropriate for the current viewer, add an Actual Pixels / 1:1 option.
Document the actual root cause of any confirmed display-quality loss.
3. Gmail-like multi-selection
Add checkbox selection to the Series image/slice list.
Requirements:
checkbox selection must be independent from the active/open slice;
clicking a checkbox must not navigate;
clicking the slice/row must continue normal navigation;
support selecting multiple images;
show a clear selected state and selected count;
add Select all where appropriate;
preserve acceptable performance for large Series.
4. Bulk review actions
When one or more images are selected, expose bulk actions:
Normal
Abnormal
Not sure
Use a backend bulk operation rather than uncontrolled one-request-per-image behavior.
The backend must:
operate on stable DICOM/image IDs;
validate Study/Series membership;
enforce authentication/authorization;
update only the current doctor's vote;
preserve other doctors' votes;
apply the bulk mutation atomically where practical;
reject label mutations during the short dataset-snapshot freeze.
After success, synchronize UI state and clear selection. On failure, do not present unsaved state as successful.
5. Normal-by-default review semantics
Do not require a doctor to create Normal votes for hundreds of routine slices.
For a doctor who completes a Series review:
explicit Abnormal remains Abnormal;
explicit Not sure remains Not sure;
all remaining images resolve to that doctor's implicit Normal.
Do not automatically create hundreds of explicit Normal vote rows merely to represent review completion unless the current canonical schema requires it for correctness.
An explicit Normal vote remains distinct and is used when the doctor intentionally selects Normal, including disagreement with another doctor's Abnormal / Not sure vote.
Do not collapse individual doctor opinions into one mutable global label.
6. Complete Review
Provide a Series-level Complete Review action.
It means:
I completed a full review of this Series; every image I did not mark Abnormal or Not sure is Normal according to my review at this point.
Record review completion using the current canonical review model, including the relevant reviewer and completion/image-set revision metadata.
Important:
Complete Review must not permanently lock the doctor out;
no mandatory Reopen action is required before editing again;
the doctor may later change Normal ↔ Abnormal ↔ Not sure;
other doctors' votes must remain untouched;
if the image set itself changes after completion, the system must be able to distinguish the earlier completed image set from the changed one.
7. Multi-doctor conflicts
Preserve independent doctor votes and existing conflict semantics.
Examples that must remain representable:
Doctor A: Abnormal / Doctor B: Normal;
Doctor A: Not sure / Doctor B: Abnormal;
completed implicit Normal from one doctor / explicit Abnormal from another doctor.
Do not treat a cached boolean such as isAbnormal = false as proof of consensus.
8. ML dataset snapshot freeze
Keep the current immutable DatasetSnapshot architecture as the source of truth.
The required lifecycle is:
live review state
→ short consistency/freeze phase
→ immutable label snapshot
→ release mutation freeze
→ long-running sorting/preparation/training-data work from that snapshot
Requirements:
freeze only review/label mutations relevant to the snapshot scope;
do not globally block unrelated Studies/Series;
viewing, navigation, zoom, pan, Window/Level, ruler and area tools remain available;
do not keep a long-lived SQL transaction or lock during DICOM copying/preprocessing/training preparation;
once created, an existing snapshot must not change when doctors later edit their votes;
snapshot failure must not leave stale voting locks.
Reuse the current DatasetSnapshot implementation and extend it only where this workflow requires it. Do not build a separate parallel MLOps/versioning system in this task.
Preconditions
Before implementation:
work from the latest canonical main containing the current DICOM Study / Series / Instance, review-state and DatasetSnapshot work;
re-check the old radiologist audit against the current architecture;
remove any obsolete recommendations based on PatientImagesCluster if that model has already been replaced;
do not duplicate Study/Series/SOP UID storage that already exists.
Acceptance criteria
Ruler/Length tool is available and uses valid DICOM physical spacing where available.
Existing Area measurement still works.
Confirmed display-quality issues are fixed without synthetic enhancement.
Slice/image list supports checkbox multi-selection.
Active slice and selected slices are separate UI concepts.
Bulk Normal / Abnormal / Not sure works through validated backend logic.
Bulk operations preserve independent doctor votes.
Doctors do not need to manually mark every routine slice Normal.
Complete Review resolves remaining images to implicit Normal for that doctor's completed review.
Complete Review does not make the review permanently read-only.
A doctor can later change their own vote without a mandatory Reopen action.
Explicit Normal remains available for deliberate disagreement/reclassification.
Existing multi-doctor conflict behavior is preserved or adapted consistently to the canonical review model.
Dataset snapshotting briefly prevents conflicting label mutations only for the relevant scope.
Voting becomes available again immediately after the immutable label snapshot is captured.
Later doctor edits do not mutate an existing dataset snapshot.
No regression in DICOM navigation, zoom, pan, Window/Level or existing measurements.
Relevant backend/frontend tests, lint and typecheck pass.
Validation
Automated:
ruler integration/calibration tests where application logic exists;
multi-selection tests;
bulk Normal / Abnormal / Not sure tests;
authorization and cross-Series validation tests;
Complete Review and later-edit tests;
two-doctor disagreement/conflict tests;
dataset-snapshot consistency/freeze tests;
regression tests for existing individual voting.
Manual:
review a representative de-identified CT Series with hundreds of slices;
verify display quality at fit/zoom/high-DPI conditions;
select and bulk-label multiple slices;
complete the review and confirm unmarked slices resolve to Normal;
return to the completed review and change votes successfully;
verify another doctor's contrary vote remains visible/preserved;
verify viewer remains usable during the short dataset snapshot lock.
Out of scope
Production ML inference UX.
Probability/threshold presentation.
Suspicious-slice ranking.
Heatmaps.
Replacing DWV unless a separate validated viewer decision is made.
Full MLOps redesign beyond the existing DatasetSnapshot requirements.
