Context
PR #56 exposed a real finite-volume geometry defect: CFDX stores each internal face once with an owner-to-neighbour area-vector orientation, while several geometry consumers call compute_cell_geometry() without providing cell-local face orientation.
The immediate Poiseuille failure was fixed in build_fv_geometry(), but the same architectural mismatch exists in other call sites and must be audited systematically.
Objective
Make cell geometry orientation explicit and consistent throughout CFDX. No caller should silently assume that a global face area vector is outward for every adjacent cell.
Required work
A. Define the contract
Document and enforce:
global face area vector: owner -> neighbour;
boundary face area vector: outward from owner;
for a cell that is the neighbour of an internal face, the local outward vector is -Sf;
cell volume must be reconstructed from cell-local outward vectors;
signed-volume validation must retain enough information to detect genuinely inverted cells rather than masking orientation errors.
B. Audit every compute_cell_geometry() caller
Known callers include:
finite_volume_transport.h
dynamic_mesh.h
divergence.h
pressure_velocity.h
integrate.h
gradient.h
laplacian.h
temporal.h
geometry_cache.h
mesh_validator.h
laplacian_assembly.h
source_term.h
scalar_diffusion.h
For each caller determine whether it has:
owner/neighbour information;
only cell-local face IDs;
boundary-only meshes;
internal shared faces.
C. Implement one authoritative orientation mechanism
Prefer a single reusable API rather than duplicating owner/neighbour sign logic in individual solvers.
The API must support:
centre;
signed volume;
positive geometric volume;
local outward face orientation;
internal and boundary faces.
D. Regression tests
Add tests for:
single hexahedral cell;
two cells sharing a face;
1D chain of 2/4/8 cells;
structured 3D multi-cell mesh;
owner/neighbour face orientation;
reversed/inverted cell detection;
volume conservation;
geometry cache consistency;
FV diffusion manufactured solution;
Poiseuille grid convergence.
E. Cross-module consistency
Compare the volumes/centres returned by:
build_fv_geometry();
geometry cache;
pressure/velocity geometry;
transient/integration geometry;
diffusion geometry.
They must agree to tight numerical tolerance on identical meshes.
F. CI gate
Add a dedicated geometry-orientation validation target and make it required before merge.
No tolerance relaxation is acceptable as a solution to an orientation mismatch.
Acceptance criteria
no production caller relies on implicit global face orientation;
multi-cell Cartesian mesh has exact expected cell volumes;
inverted-cell tests remain capable of detecting inversion;
Poiseuille observed order is >= 1.90 on the established refinement sequence;
all existing unit, validation, Release and sanitizer jobs pass;
no benchmark is disabled or weakened to obtain a green CI.
