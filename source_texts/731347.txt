This PR extends the in-memory space-partitioning index (quad-tree and k-d tree) to the tpcbox bounding box of the temporal pgpointcloud types, completing its coverage of the MEOS bounding box types alongside the R-tree, which already supports tpcbox.
Design: a tpcbox tree is internally an STBox tree. A TPCBox carries the same spatial and temporal bounds as an STBox plus a trailing pcid, so no new partitioning geometry is needed: every incoming box and query is projected to an STBox on entry through the existing tpcbox_to_stbox, and the existing STBox adapters (quadrant assignment, node regions, consistency tests, distances, deferred 2D/3D dimensionality) are reused unchanged. The engine gains a single optional project function pointer; when unset (every other box type) the behaviour is byte-identical.
sptree_create_tpcbox(SPTreeKind) is in the public API after sptree_create_stbox, guarded by #if POINTCLOUD like rtree_create_tpcbox.
The temporal insert/search paths accept tpcpoint and tpcpatch values on a tpcbox tree (single-box path; the multi-entry path falls back to the single minimum bounding box, as for tcbuffer, tnpoint and tpose). The kNN cursor works on a tpcbox tree through the same projection.
The temporal insert and search paths of both this index and the R-tree use a bboxunion stack buffer, sized for any MEOS bounding box type: the bounding box of a pointcloud temporal value is larger than an STBox, so a fixed STBox-sized buffer overflows on the R-tree tpcbox path.
The test program has a pointcloud section (compiled only when POINTCLOUD is enabled) that inserts random tpcbox values and checks overlaps / contains / contained-by searches against a brute-force oracle using the native tpcbox predicates, for both tree kinds — proving the projection loses nothing. The section compiles out cleanly in the POINTCLOUD-less meos workflow build.
