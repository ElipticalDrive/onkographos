Supersedes #58 by @vnredmon.
This finishes Nobie Redmon's marching cubes / implicit surface work, rebased onto current main. Nobie's eleven WIP commits are squashed into a single commit that keeps Nobie as the author. The second commit completes the feature.
What's here
emmy.mathbox.marching-cubes (new, .cljc). This is a pure marching-cubes extractor:
isosurface samples f(x, y, z) exactly once per point on a regular nx × ny × nz grid spanning :x-range, :y-range and :z-range.
It returns {:vertices [[x y z] ...] :triangles [[i j k] ...]}, with one shared vertex per grid edge that straddles :level, placed by linear interpolation.
Corner and edge numbering match the Bourke triangle table, which moves to emmy.mathbox.marching-cubes.triangle-table/triangle-table.
triangle-coords turns the mesh into the :items 3 shape that MathBox's Array expects.
emmy.mathbox.plot/implicit-surface plots the level set f(x, y, z) = level of a function.
f goes through the same emmy.mathbox.compile/compile-3d path as parametric-surface and vector-field.
A small adapter, scalar->state-fn, turns the scalar f into the [[x y z]] -> [v] shape, so ev/with-params works too.
emmy.mathbox.components.plot/ImplicitSurface runs the extractor on the client. It recomputes the mesh only when :f, :level, the ranges or :samples change, and draws it with mb/Array + mb/Face.
dev/examples/mathbox/implicit.clj shows a sphere, a torus, and a "tangle cube" whose level and coefficient are driven by Leva sliders.
A CHANGELOG entry, and org.clojure/test.check in the :test alias.
Fixes compared with the original WIP
The original extractor had several bugs:
The edge→point mapping did not match the triangle table: edge 10 returned two coordinates, and edge 9 interpolated over y + yInc.
The grid step was 1/resolution whatever the range, and the grid did not reach the max of each range.
f was evaluated eight times per cell.
Triangles were lazy nested seqs with no shared vertices.
ImplicitSurface called the extractor with mismatched arguments and rendered points instead of a surface.
Tests
clojure -X:test:runner: 11 tests, 52 assertions, plus two defspec properties (25 trials each). All pass. They cover:
The table: 256 cases, and each case uses exactly the edges whose corners differ in sign. cube-index, and every edge joining two corners that differ along one axis.
A sphere (r = 0.75, 20³ grid):
The vertex count equals an independent count of straddling grid edges.
Every mesh edge borders exactly two triangles, so the mesh is closed.
The Euler characteristic is 2.
Every vertex lies within one grid spacing of the sphere.
Empty meshes for a grid all above, all below, or a level set outside the box. A single-cell grid, where linear fields are interpolated exactly.
Option handling: one evaluation per grid point, ranges, and invalid :samples.
Properties:
Random spheres are closed, have genus 0 and lie on the level set.
On random planes, vertices are exact.
implicit-surface emits a js/Function. compiled form and the ImplicitSurface component call.
clj-kondo reports 0 errors and 0 warnings on src and test.
Relation to #83
#83 reworks the compile seam (emmy.viewer.compile/compiled-fn). implicit-surface only calls mc/compile-3d, which #83 re-points at compiled-fn with the :primitive calling convention and wraps through frame. So the implicit plot picks up #83's backend selection, including :raster, with no changes. A scratch git merge-tree against #83 conflicts only in CHANGELOG.md, where both add entries under [unreleased]. deps.edn and components/plot.cljs auto-merge.
Caveat
I did not view the dev notebook in a browser. On JDK 25 the pinned Clerk fails to load (NoSuchMethodError sun.misc.Unsafe.ensureClassInitialized, from old GraalJS). That is being fixed with a Clerk bump on #84. CLJS tests do exercise the component namespace.
