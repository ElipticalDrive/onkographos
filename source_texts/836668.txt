Contributor
Issue
Relates to #1327 and #1339. Both PRs add their own discrete curl to turn a vector potential into B (#1327: IExternalFieldUpdater::curlOnGhostBox_; #1339: curl_edges_to_faces). Each is a line-for-line copy of the component algebra already written in Faraday, and Ampere writes it a fourth time. There is no operator layer above GridLayout::deriv/GridLayout::laplacian, so every caller spells out curl/div/grad by hand with its own 1D/2D/3D if constexpr blocks. This PR adds that layer so both PRs can rebase onto it and drop their copy.
What this implements
One header, src/core/numerics/differential_operators.hpp, with partial, curl, grad, div and laplacian, usable on any Yee staggering (hybrid and MHD layouts) in 1D/2D/3D. Existing callers move onto it in this PR:
Ampere and Faraday use curl;
Ohm's pressure term uses grad; Ohm's hyper-resistive terms and DissipativeElectricField use laplacian;
GridLayout::deriv and GridLayout::laplacian are removed (no forwarders), and the gridlayout derivative/laplacian tests use the new functions with their numpy references unchanged;
the dead ConstrainedTransport class (never included anywhere) is removed.
Results are unchanged: Ampere, grad (Ohm's pressure term) and laplacian are bitwise identical to master; Faraday differs only in 2D Bz and in 3D, by round-off (B - dt*a + dt*b becomes B - dt*(a - b), measured ≤ 4.4e-16).
Not in this PR: adoption inside #1327/#1339 (they rebase onto it), the finite-volume divergence, the Balsara div-B touch-up, the tagger, derived-quantities, and Python (pharesee and the test reference generators will get their own Yee-aware operators in a separate PR).
For #1327/#1339: both can call curl over the full ghost box (edge→face is primal→dual in every derivative direction, so it only reads i and i+1). curl only needs v[k], so #1339's std::array<Field, 3> works as is.
Design
partial, curl, grad and div are small objects built from (layout, source) just before the caller's loop; the call operator evaluates one point. They work out where their result lands from the source centering, and the caller keeps choosing its loop box. curl and grad are vectors: one object whose .x, .y, .z are the component operators.
```
auto const curlE = curl(layout_, E);
layout_.evalOnBox(Bxnew, [&](auto const&... ijk) {
    Bxnew(ijk...) = Bx(ijk...) - dt_ * curlE.x({ijk...});
});
```
The destination follows from the source, resolved once at construction: along dir the centering flips, every other direction is unchanged. So curl(E) lands on B, curl(B) on J, grad(Pe) on E, div(B) on cell centres (including the hybrid layout, which has no cell-centred quantity). Each operator exposes it as centering().

These are exactly the old deriv.
Checks at construction, once per loop: the source must have data, and the derivatives inside curl and div must land on the same centering; both throw. A collocated (all-nodal) vector fails the second check: its curl and div are not supported.
Non-simulated directions are a compile-time 0. whose result stays on the source centering, so callers have no per-dimension branches. partial is the only place that knows the dimension, with one exception: a curl component returns -∂k vj at compile time when only its first term is non-simulated, so Ampere stays bitwise identical even for the sign of an exact zero (master computes Jy = -∂x Bz in 1D/2D).
Per point the object does only the stencil: it keeps a copy of each operand's array view (data pointer and shape), so there is no centering lookup, no branch and no TensorField::_check() in the loop. laplacian stays a plain function (its result always lands on the operand's own centering).
Performance. The old deriv looked up the operand's centering at every point, which no compiler hoisted and which blocked vectorisation. Tests
New tests/core/numerics/differential_operators/ (ctest test-differential-operators), typed over 1D/2D/3D × {hybrid interp 1, hybrid interp 3, MHD Constant, MHD WENOZ}:
partial exact on quadratic fields for every direction, from a primal and from a dual source, at every index the stencil can reach (the full ghost box for primal→dual), and its destination is the flipped source centering; quadratics rather than linears, so a half-cell offset is caught;
curl(E), curl(B), grad(nodal scalar), MHD grad(cell-centred scalar), div(E) and div(B) land on the Yee quantity in every dimension;
laplacian exact on cubic fields;
discrete identities to round-off: div(curl A) = 0 (edge→face→cell, face→edge→node), curl(grad φ) = 0 (nodal and cell-centred φ), div(grad φ) = laplacian(φ);
non-simulated directions give exactly 0, including the sign of zero for the 1D curl;
curl and div of a collocated vector throw, and so do operators on a field without data;
a VecField and a std::array<Field,3> operand give bitwise identical results.
test-GridLayout's derivative tests now also check that each partial lands where the old explicit destination was.
Ampere.grownPhysicalBoxIsExactOnQuadraticB: pins Ampere in AmpereMode::GrownPhysical (the hybrid solver's mode), written and passing before the rewrite.
Existing numpy-reference tests unchanged and passing: test-GridLayout (derivative and laplacian, interp 1–3, 1D–3D), test-ampere, test-faraday, test-ohm.

Count the points visited by each benchmark loop.
updatedPoints reports 3 * n^dim, but the registered fields are staggered. evalOnBox visits inclusive component-specific ranges, so primal axes contain n + 1 points while dual axes contain n points. Faraday does not update 3 * n^dim points.
The benchmark instantiates the default Ampere<Layout>, which uses evalOnShrinkedGhostBox. Its count includes the configured ghost ranges after trimming one point from each end. It also does not equal 3 * n^dim.

```
… Faraday, PHAREHUB#1327 and PHAREHUB#1339, 3-4x faster (PHAREHUB#1468)

feature(numerics): shared staggering-aware differential operators

Add src/core/numerics/differential_operators.hpp with partial, curl,
grad, div and laplacian, for any Yee staggering (hybrid and MHD
layouts) in 1D/2D/3D. The discrete curl was written by hand in Ampere
and Faraday and copied again in PHAREHUB#1327 (external field prescription)
and PHAREHUB#1339 (B from vector potential); all of them can now share one.

- partial, curl, grad and div are small objects built from
  (layout, source) just before the caller's loop; the call operator
  evaluates one point.
- The result's centering follows from the source: along the
  derivative direction primal becomes dual and dual becomes primal,
  so curl(E) lands on B, curl(B) on J, grad(Pe) on E and div(B) on
  cell centres. Each operator exposes it as centering().
- curl and grad return one object with members x, y, z:
  Bxnew(ijk...) = Bx(ijk...) - dt_ * curlE.x({ijk...}).
- Construction throws if the source has no data, or if the
  derivatives inside curl/div land on different centerings
  (e.g. a collocated vector).
- Non-simulated directions are a compile-time zero, so callers no
  longer branch on dimension.
- laplacian stays a function returning one value; its result lands on
  its operand's centering.

Callers: Ampere and Faraday use curl; Ohm's pressure term uses grad;
Ohm's hyper-resistive term and DissipativeElectricField use laplacian.
GridLayout::deriv and GridLayout::laplacian are removed, and so is the
unused ConstrainedTransport class (constrained_transport.hpp), which
nothing included.

Results: Ampere, grad and laplacian are bitwise identical to master;
Faraday differs only by round-off in 2D Bz and in 3D.

Performance: the centering lookup now happens once per loop instead of
at every point, so the Ampere and Faraday kernels run 3.5-4x faster
(benchmark in tools/bench/core/numerics/differential_operators/).

Tests: new test-differential-operators (exact on quadratic and cubic
fields, results land on the Yee quantities, div curl = 0,
curl grad = 0, div grad = laplacian, error cases); the GridLayout
derivative tests now use the new operators, and a new Ampere test
covers the grown-physical-box mode.
```
