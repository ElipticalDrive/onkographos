Batch vs Instacing when rendering?
I am making a simple voxel renderer where I will draw thousands of voxels. Trying to plan this out I have started to look into batch rendering. A technique I have used before in OpenGL 2D simulations. I found there aren't many resources covering batch rendering in Vulkan, although I suppose it would be very similar to what I have done before.
However while reading some repositories and other projects I found an instancing example that explains it can use the same drawcall for many instances but some slightly different data. I have never used this technique before. (In this example they render 8000 meshes with one call two vkCmdDrawIndexed(drawCmdBuffers[i], models.rock.indices.count, INSTANCE_COUNT, 0, 0, 0);)
My questions are:
Does it make sense to use any of this for a voxel renderer?
Which apprach might be better for a voxel renderer?
Are there any resources I can use?

Generally, instancing is only sensible if your instances have enough vertices. If your geometry is just a cube, instancing it is gonna be very suboptimal since a wavefront usually cannot operate on multiple instances.

Thanks for replying - In reading the discussion you linked, it sounds like most of the limitation surrounds MultiDraw*. It appears that using regular instancing with a single draw call (eg vkCmdDrawIndexed) does allow multiple instances in a single wavefront?
"...gl_DrawID is explicitly stated to be dynamically uniform, but gl_InstanceID is not. Combined with the fact that SPIR-V/GLSL specifically allow invocation groups to contain multiple instances, that strongly suggests that there are at least some GPU vendors do allow instances to run in the same warp/wavefront."
"...GPUs do not pack multiple draw calls to the same wave. The same is true for MultiDraw (or ExecuteIndirect). These are also counted as multiple draws. If the draws are small, there will be partially empty waves.
Instanced draw (DrawInstanced) will count as a single draw. The GPU will pack vertex shader invocations of multiple instances to the same wave (and the same is true for pixel shaders and other shader stages). …"
Interesting stuff for sure
