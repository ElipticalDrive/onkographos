The more I look at it the more I think this might be actually expected behavior of the original code. As it's implemented based on an algorithm for collision detection you would probably like to get the point 'just before the object penetrated the obstacle' and that's what's happening.
As the package is called intersection not collision that is though misleading.
Test Case:
```
var origin = [0,0,0];
var dir = [1,0,0];
var bbox1 = [[-1,-1,-1], [1,1,1]];
var bbox2 = [[ 3,-3,-4], [4,4,4]];
```
I tried in ThreeJS and got [1,0,0] and [3,0,0] as expected: JSFiddle
ray-aabb-intersection returns
```
intersection([], origin, dir, bbox1); // [-1,0,0] Hmm
intersection([], origin, dir, bbox2); // [ 3,0,0] OK
```
