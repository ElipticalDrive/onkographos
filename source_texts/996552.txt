Closes #105.
Summary
The raw voxel type was already the canonical per-cell occupancy source (type != AIR, and ChunkManager::isVoxelActive used it directly). On top of it, every chunk maintained a std::bitset<CHUNK_VOLUME> activeVoxels (8 KiB) that generation rebuilt with a full 65,536-voxel pass, and every full remesh copied all voxel types into a 64 KiB typeScratch and rescanned it through computeOccupancyY() just to find the occupied Y range. This PR removes both redundant representations and replaces them with 32 bytes of per-section occupancy metadata, leaving the canonical voxel type as the only per-cell truth.
Update — review pass applied (commits 0629107 + 77f9596): the first cut had prepareVoxelStorageForGeneration() air-fill the borrowed block, which silently doubled the pre-generation CHUNK_VOLUME clear and re-opened #93. That fill is removed: generateChunkInto() is again the sole authoritative reset, and the lifecycle is now an explicitly documented three-state contract. Benchmark re-measured with clean provenance; see the updated table below.
Data model
std::array<uint16_t, 16> m_sectionNonAir — non-air voxel count per vertical section (16 sections × 16 voxels). ~8 KiB → 32 B per chunk.
generateTerrain() populates it with one canonical read-only pass after generateChunkInto() (the issue explicitly allows "one cheap canonical pass"; the removed pass existed solely to rebuild the bitset).
setVoxel() maintains the count incrementally with explicit ++/-- guarded by Debug underflow/overflow asserts (a desync is a hard failure, not a silent uint16 wraparound). Type→type rewrites leave counts untouched.
Chunk::isVoxelActive() point queries answer from the voxel type itself (still O(1)).
Occupancy lifecycle contract (documented on prepareVoxelStorageForGeneration() and ResetMode)
No storage — m_storage == nullptr, occupancy metadata == 0.
Prepared for generation — storage borrowed ownership only, bytes stay stale/unspecified (prepareVoxelStorageForGeneration() does not initialize voxel bytes), metadata == 0, no consumer may inspect voxel contents. Edits targeting the chunk answer "logically empty": a placement defers while generation is in transit, a deletion is refused.
Generated/editable — backing valid, metadata exactly matches it; generateChunkInto() remains the sole authoritative initialization; edits keep both in lockstep.
effectiveVoxelType() implements state 2: it never reads stale backing for edit no-op decisions (issue #115 review item 3). The invariant m_storage == nullptr ⇒ metadata == 0 is restored everywhere backing changes, including both move operations zeroing the moved-from side after the transfer.
Mesher integration
buildMesh() derives the occupied Y span from the metadata — section-granular, then refined to byte-exact layer bounds inside the two boundary sections — so the 64 KiB copy + scan per remesh is gone (computeOccupancyY() removed).
Empty Y slices between occupied sections are skipped outright (no vertical neighbor borders exist).
buildLODMesh() starts each column scan at the last occupied section (Debug-asserted bound).
buildMeshRanged/buildLODMeshRanged are probe-testable so tests force a full [0, CHUNK_HEIGHT−1] range and prove byte-identical meshes.
Telemetry
New telemetry::StageSample single-stage scope measures the real occupancy prepass (occupiedSpanY + refineOccupiedSpanY), including empty chunks that early-return. One recorded sample per full build attempt: mesh.occupancy n == MeshBuild n in the report.
The empty Occupancy phase marker inside the greedy body is removed; Skylight → Blocklight → FacesGreedyAO now measure real work only. MeshSample stays untouched for the sequential chain.
Tests (test_chunk_lifecycle)
checkActiveCacheInSync renamed checkOccupancyMetadataInSync; brute-force validation of counts, derived mask and span after every lifecycle step.
Deterministic property-style section: metadata vs brute force across 3,000 randomized mutations (per-edit shadow count + isVoxelActive agreement), full drain to zero, first/last-block transitions at every seam class, all-air inner section, empty-chunk meshing.
Mesh equivalence: generated terrain and a synthetic layout (interior run of empty sections, both seam classes y=15/16 & y=239/240, isolated water section) — greedy and LOD builds via metadata bounds vs forced full range, byte-for-byte, covering the d==1 slice skip and the water path.
New lifecycle sections: moved-from chunks carry empty metadata (ctor + assign); poison-backing proof that prepare() does not clear a recycled block while generation over poison stays deterministic ([Terrain/Performance] Avoid redundant pooled voxel clearing before generateChunkInto #93 locked); ForGeneration desync-window lifecycle; edit decisions never consult stale backing.

The raw voxel type is the canonical per-cell occupancy source; the
per-chunk std::bitset<CHUNK_VOLUME> duplicate (8 KiB, ~69 MiB across
~8.9k pooled chunks) only mirrored it and cost a full-volume pass to
rebuild after every generation, plus per-edit bit maintenance.

Replace it with one std::array<uint16_t, 16> counting non-air voxels per
vertical section (16 sections of 16 voxels, 32 B per chunk):

- generateTerrain() fills it with one canonical read-only pass (16
  counters, no bitset writes) after generateChunkInto();
- setVoxel() applies an incremental +/-1 delta on air<->solid flips
  (type->type rewrites leave counts untouched);
- isVoxelActive() point queries now answer from the voxel type itself
  (ChunkManager::isVoxelActive already did);
- empty storage invariants are pinned wherever backing changes
  (prepare/ensure/retire/reset/moves).

Meshing: the full-quality mesher no longer copies all 65,536 voxel types
into a 64 KiB typeScratch and rescans them through computeOccupancyY()
(removed) on every build. buildMesh() derives the occupied Y span from
the metadata (section-granular, refined to byte-exact layer bounds inside
the two boundary sections) and skips empty Y slices outright; the LOD
mesher starts each column scan at the last occupied section. Byte-exact
mesh equivalence is enforced by tests against forced full-range builds.

Tests (test_chunk_lifecycle): the probe/snapshot state now carries the
section counters, sync is verified against a brute-force voxel scan after
generation and edits, and a new deterministic property-style section
compares metadata against brute force across 3,000 randomized
place/delete/type mutations, a full drain back to zero, first/last-block
section transitions at every seam class, and empty-chunk meshing.
test_stream_opt drops the removed helper's unit test; telemetry doc and
engine-architecture reflect the new occupancy.bytes scale.

Last #115 review blocker: a chunk loaded but not yet generated (or
recycled back to UNLOADED) took direct edits as soon as no job owned it,
writing into stale pool bytes and marking it GENERATED behind the
generation pipeline's back.

- New gate mustDeferVoxelEdit(): an edit defers when the chunk is
  missing, UNLOADED (regardless of transit state), or in transit.
- queueOrApplyEdit() uses it for the queue/apply decision and asserts on
  the apply path that the backing is readable and unowned.
- applyPendingEdits() keeps entries whose chunk is not yet generated;
  the generation-stamp staleness check still runs first, so a recycled
  chunk drops its queued edits exactly as before.
- scheduleLogicalEdit() computes the group deferAll from the same gate:
  an UNLOADED target defers its mirrors with it (transaction semantics
  from #114), while a GENERATED target applies immediately and each
  mirror decides on its own chunk's state.
- effectiveVoxelType() now expresses its UNLOADED = logical-AIR rule via
  the new Chunk::isVoxelBackingReadable() helper.

Tests: the deferred-edit suite (13e) generates its five manager chunks
synchronously, matching the contract its immediate-apply expectations
rely on. New section covers the loaded-not-generated flow end to end:
delete refused without queueing, place accepted but queued (state and
stale backing untouched), coalescing while waiting, identical deferral
for UNLOADED+inTransit, generation landing in full before the queued
edits apply, and a boundary edit whose mirror waits for the UNLOADED
neighbor's own generation (shell write, revision bump, metadata sync).
