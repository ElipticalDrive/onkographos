PR ini bertumpuk di atas #2 (yang bertumpuk di atas #1). Urutan merge: #1 → #2 → #3, lalu base diganti mengikuti.
Ringkasan
Panel keempat di layout 2×2 MPR sekarang berisi volume rendering 3D dari volume yang sama dengan MPR, memakai VolumeViewport3D Cornerstone3D. Di baliknya, rendering-nya adalah ray casting vtk.js (vtkVolume, shared volume mapper, transfer function).
Fitur baru: volume-render
Preset lewat dropdown di panel:
CT: Tulang (default), Jaringan lunak, Otot & kulit, MIP
MR: Default, T2 otak, MIP
MIP dibuat sendiri dengan vtk.js: blend mode MAXIMUM_INTENSITY di mapper aktor 3D, plus ramp abu-abu linear (CT 0–2000 HU, MR rentang voxel) dengan opasitas konstan.
Interaksi (tidak memengaruhi MPR): kiri / 1 jari = putar, roda / kanan / pinch = zoom, tengah / 3 jari = geser.
Reset 3D mengembalikan arah pandang awal (tampak depan) dan zoom.
Progres pemuatan volume tampil di panel 3D.
Catatan teknis
Memori: viewport 3D berada di rendering engine yang sama dengan MPR, sehingga tekstur volume dipakai bersama tanpa salinan tambahan. Mapper dibuat per aktor, jadi blend mode MIP di 3D tidak memengaruhi MPR.
Mengapa MIP dibuat sendiri:
Preset CT-MIP bawaan Cornerstone sudah putih penuh sejak −637 HU, sehingga dengan blend MIP hasilnya hanya siluet.
VolumeViewport3D.setBlendMode di Cornerstone 5.14 tidak melakukan apa-apa, jadi blend mode diatur langsung di mapper vtk.js.
Opasitas MIP dibuat konstan 1, karena keluaran MIP = warna × opasitas. Dengan ramp opasitas, nilai tengah ikut gelap secara kuadratik (terukur 76 alih-alih 153).
Reset 3D: resetCamera() bawaan hanya mereset zoom/pan, sehingga orientasi awal (viewPlaneNormal, viewUp) disimpan dan dipulihkan manual.
Performa: preset, reset, dan oblik di MPR kini memanggil renderViewports(<tiga bidang>), bukan render(), supaya panel 3D tidak ikut di-ray-cast ulang. Interaksi crosshair dan W/L memang hanya menggambar viewport yang ditandai (sudah diverifikasi di kode rendering engine).
Pengujian
npm run build lolos di setiap commit (diverifikasi di worktree bersih).
Data uji baru: phantom kepala sintetis 256×256×64 berisi tempurung 1200 HU, otak, ventrikel, dan satu penanda tulang 1500 HU di kanan-anterior-superior. Data hanya ada di scratchpad, tidak di-commit.
E2E 3D (Playwright/Chromium, build produksi dan npm run dev, 27/27 lolos di keduanya):
Render & orientasi: volume ter-render dan tempurung terlihat. Penanda muncul di kiri atas tampak depan, sesuai kanan-superior pasien.
Interaksi: drag kiri memutar, roda dan drag kanan zoom; semuanya tidak mengubah irisan maupun W/L MPR. Reset 3D kembali ke tampilan awal (beda piksel 0,22/255).
Preset: preset W/L di MPR tidak mengubah 3D. Keempat preset CT menghasilkan render berbeda, dan kembali dari MIP ke Tulang memulihkan render semula.
MIP: tempurung tampil abu-abu ≈153 (= 1200/2000) dan penanda lebih terang. Ini membuktikan blend MIP benar-benar aktif, bukan composite opak.
MR: preset Default/T2 otak/MIP tampil dan series MR ter-render.
Crosshair MPR tetap berfungsi, tidak ada error/warning console, dan nama/ID pasien palsu tidak tampil.
Emulasi iPad Pro 11: 1 jari memutar, pinch zoom, pilih preset, dan Reset 3D bekerja; kontrol muat di sel.
Regresi: MPR dari Mode MPR 2×2: crosshair sinkron, oblique, W/L tersinkron, toggle 1×1/2×2 #2 (29 + 11 cek), 1×1 dari Viewer DICOM dasar: folder loader, Study → Series dengan thumbnail, stack viewer, preset window #1 (27 + 8 cek), dan transfer syntax semuanya lolos.
Belum diuji: iPad Safari asli dan GPU nyata. Headless memakai GPU software (SwiftShader); di sana satu render 3D butuh beberapa detik, sehingga tes perlu menunggu frame. Performa interaktif di iPad perlu dicek di perangkat.
Known issues
Di GPU software, render 3D terakhir setelah volume selesai dimuat menahan frame beberapa detik. Di GPU nyata diperkirakan tidak terasa, tetapi belum diukur.
Jendela MIP CT tetap 0–2000 HU (belum bisa diatur pengguna).
Rencana lanjutan
Atur jendela MIP/opasitas dengan drag, clipping/crop volume, tampilkan posisi crosshair di 3D, slab/MIP di bidang MPR.
