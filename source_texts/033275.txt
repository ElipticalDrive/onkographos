T012 — Renderer Unification and Large-Scene Performance
Priority: P2
Milestone: M3 — Product completion
Depends on: T010
Provenance: Explicit pending M4/M5 work in spec/rust/rendering.md, spec/rust/voxel-spec.md, and spec/rust/bridge.md.
Gap
The specs explicitly mark renderer unification, dirty-state caching, and
LOD/chunking as incomplete. Headless rendering duplicates logic in PyO3, while
the interactive app and replay workflows need consistent visual output.
Outcome
Interactive viewing, trajectory replay, and headless rendering share one tested
rendering pipeline that remains responsive on representative imported scenes.
Scope
Extract the common RgbaBuffer rendering pipeline.
Remove duplicate projection/rasterization from bindings.
Add dirty-state caching for unchanged camera/world state.
Add chunking, instancing, or an appropriate LOD strategy above 10k voxels.
Define and benchmark supported scene-size tiers.
Preserve agent, trail, start, goal, and selection overlays.
Add structural rendering tests and non-empty GIF/PNG tests.
Acceptance criteria
App, replay, and headless output call the same core renderer.
Static scenes do not re-project/re-sort unchanged geometry.
A documented >10k-voxel fixture remains interactively usable.
Overlay semantics match across interactive and headless consumers.
Rust format, Clippy, unit, and integration tests pass.
Performance measurements are recorded against spec targets.
