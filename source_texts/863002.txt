Intent: remediate performance regressions introduced by our port, without rewriting PhysX
Pinned source and identified departure
physx/source/gpucommon/src/CUDA/RadixSort.cuh::radixSortCalculateRanks: source uses packed per-thread bin counters and warp-local rank scans, keeps 4-bit LSD radix, 32 × 3 × 1024 launch and 32-block digit histogram.
Prior port physx_radix_scatter_arena.hlsl scanned all 16 digits separately, each through ten 1024-thread shared-memory rounds, at least 160 full-group scan barriers per iteration. That is our introduced performance risk, not an upstream algorithmic problem.
Corrective implementation
New native physx_radix_scatter_wave_arena.hlsl uses source-like two 16-bit packed digit counters per 32-bit wave scan: 8 paired passes, WavePrefixSum/WaveActiveSum and short shared wave subtotal scan. 16-bit packing is safe even for wave64 and all 1024×4 keys per block chunk (maximum 4096 in any bin); cross-chunk carries remain separate 32-bit counters.
Each wave atomically claims one logical contiguous range once per workgroup, so the exact original stable input ordering is maintained without assuming physical subgroup→group thread IDs.
Same source buffers, digit count layout, stable payload permutation, work partition and dispatch sequence. Device capabilities select SM6.6/WaveOps or Vulkan compute subgroup arithmetic; original full shared-scan version is retained only as test/software fallback.
Independent existing full 8-pass CPU stable-sort radix oracle now tests both implementations, empty/nonaligned/large workloads and adversarial skewed digit distributions; both native Vulkan and Windows D3D12 WARP test targets.
Product policy update
Binding docs/GPU_PORT_PERFORMANCE.md sets SM6.6 for D3D12 / Vulkan 1.4 for Vulkan, with feature-probed optional extensions.
Architectural reference RX5000/RDNA1, practical performance reference Radeon 680M; optional Linux RADV Polaris/Vega only with verified capabilities. Treat these as proposed tiers, not unverified per-driver support guarantees.
WMMA/cooperative matrix is optional and probed; do not lock out GPUs without it. SM6.8+ optimized variants (e.g. ranged WaveSize, prospective Work Graphs where source scheduling permits) retain the SM6.6/Vulkan1.4 baseline. Hardware release admission still needs implementation; CI software adapters are not production targets.
Review boundaries
This PR is a targeted native-kernel performance restoration, not a redesign of PhysX radix sort or GPU task orchestration. No performance speedup is claimed without target GPU timestamps. Follow-up audit should address radix-count LDS atomic contention and other full-group scan lowerings; inherited PhysX dense region allocations remain documented but deferred. Both CI backends and Codex must pass before merge.
