Closes #2400
#2400 reports that the uniform generators can return 1.0. For float and double this was fixed earlier: next_float() and next_double() now divide a 24-bit or 53-bit integer by 2^24 or 2^53, and the result is exact and below 1. half can still reach 1.0. next_half() (in both PhiloxGenerator and PCGenerator) converts next_float() with __float2half, which rounds to nearest. Every float in [1 - 2^-12, 1) becomes 1.0, so about one uniform<half> sample in 4096 equals the upper bound. In 2^20 samples from uniform(handle, rng, half*, n, 0, 1) I counted 272 values equal to 1.0.
The fix uses __float2half_rd (round toward −inf, host and device). Each half value h then gets the floats in [h, next(h)), so the result stays in [0, 1). Unlike building the value from 11 random bits, this keeps the full resolution near zero.
Test: Rng.UniformHalfExcludesEnd in cpp/tests/random/rng.cu draws 2^20 halves in [0, 1) with both Philox and PCG and checks that every value is in range.
How I tested (RTX 5070 Ti, nvcc 13.0, -std=c++20 -arch=sm_120): I built cpp/tests/random/rng.cu and cpp/tests/random/rng_pcg_host_api.cu standalone against this branch's headers. RMM, CCCL and rapids_logger came from the 26.10 librmm/libraft wheels; I did not use the full CMake build.
Without the fix, the new test fails (272 values out of range for Philox).
With the fix, all 90 tests in rng.cu and all 13 in rng_pcg_host_api.cu pass.
