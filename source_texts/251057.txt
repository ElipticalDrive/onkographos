Independent experiment against default dev/dc
Implements and records the CUDA blog's visibility-indexed two-stage sorting idea, independently of PR11. Baseline is merged PR9 a7050c6; no PR11 color-staging changes are included.
Draft / experimental / default off. This preliminary implementation reduces radix-kernel time on the measured workload but is slower for the complete binning API. It is not presented as an end-to-end speedup or a change ready to enable by default. The investigation is recorded here and stopped without a larger sweep.
Code
Stable visibility compaction → unsigned32-bit depth sort on visible Gaussians → existing compact-box emission in that order → stable16-bit camera/tile sort.
Reconstructs the existing public64-bit intersection IDs and retains full32-bit Gaussian IDs and original flatten order for depth ties.
Checks the encoded camera/tile namespace (including power-of-two camera stride); ineligible namespace, dtype, live depth/camera data, unsafe sizes and unsorted mode fall back to the original path.
Separate CUDA binding preserves the existing entry point. Opt in through isect_tiles(..., two_stage_sort=True) or rasterization(..., two_stage_sort=True); False remains the default.
Adds exact-output contract tests and a standalone benchmark using unchanged PR9 image/gradient gates.
Recorded smoke result — RTX4090, water2 view1247,1280×720
All1,932,132 Gaussians,1,049,168 visible,2,909,623 intersections. One job per variant,10 warmups/20 timed samples; separate five-call profiler diagnostic for radix kernels.

The extra compaction, validation, gathers, sorted scan,64-bit key reconstruction and CPU/GPU synchronization can erase the radix saving. M/N is about54%, not M ≪ N. These are hypotheses from the operation graph, not independently timed stage attribution; profiler radix time cannot simply be subtracted from API time. The baseline also already limits sorting to45 key bits here rather than necessarily eight passes over64 bits. The blog's79% sorting reduction is not reproduced.
Verification / limits
47 CUDA contract tests pass, including stable ties, packed/interleaved cameras,16-bit encoding boundaries, empty/single inputs, live/dead invalid-depth fallback, float64 fallback, both CUB buffer modes, non-default stream and Gaussian IDs above24 bits.
96 existing CPU protocol/default tests pass:143 selected tests total.
Measured scene intersection counts, keys and flatten IDs are exactly equal to the original baseline binary. Full image/alpha are exact; all six gradient comparisons pass PR9's unchanged gates (maximum relative-L2 1.39e-6).
Not run: sanitizers, repeated multiview/4K sweep, convergence or full-repository suite. No broad performance claim.
Explanation and reproducibility
Detailed report explains the source changes, why radix improvement differs from total latency, reproduction commands, and limitations. It retains both raw smoke reports and a compact verification/source-hash manifest—about40KB, without large intermediate artifacts or compiled binaries.
Parent Gaussian-splatting, original gsplat checkout and PR11 are unchanged.
