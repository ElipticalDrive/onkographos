Closes #257
Why
A DDS mip holds one image per cubemap face, array element and volume slice. Only plain textures and single cubemaps had a PNG; volumes and arrays and two formats were counted as unsupported. The decisions are in ADR-0113.
One PNG per image: <name>_layerN for an array element, a cubemap face's name for a face, <name>_sliceN for a volume slice (in that order, padded to the width of the last number). A cubemap array writes per element and face, or one cross per element with --cross. A volume's slices are those of the exported mip, as the depth halves per mip.
The preview shows one image, so the GUI and Texture::decode_preview tile the images on one sheet (smallest square number of columns, a cubemap stays a cross). DdsHeader::preview_size gives the size without decoding, so the mip selector and the pixel cap judge the sheet. The facts bar gets a Layers fact. A layer selector would need a second request axis through the decoding thread for few, small images.
Untrusted headers: more than 2048 slices or array elements (the Direct3D 11 limits) and a volume that is also a cubemap or an array are InvalidHeader, so a header names at most 12,288 images (file names, sheet). Every image's data is still read from the Archive and checked against the header's size (TailMismatch/TruncatedPart), so no allocation follows a header's claim alone; the sheet's size is the sum of the decoded images.
Array alpha tail mismatch: the cause is the test, not the merge. A tail in A8_UNORM keeps its value in the alpha channel of the decoded tail and merge_alpha takes it from there; the real-Archive test compared the red channel. Verified on TECH-PREVIEW: all 91 array and volume textures with an alpha tail merge per image once the test picks the channel by the tail's format.
Acceptance criteria
Array textures decode per layer and export as one PNG per layer, in the GUI preview and in the Extraction. Mip::decode_surfaces, Texture::png_to_file_as, the Extraction's write_images; the preview tiles the layers (decode_preview, TextureInfo). Tests: images::an_array_mip_holds_one_image_per_element_from_its_part_or_the_header, texture_conversion::layers::an_array_is_exported_as_one_png_per_element, texture_preview::an_array_previews_its_elements_on_a_sheet, image_preview_layers::an_array_is_shown_as_a_sheet_and_the_layers_are_counted.
Volume textures decode per slice and export as one PNG per slice. read_mip no longer refuses volumes. Tests: images::a_volume_mip_holds_one_image_per_slice_and_the_slices_halve_per_level, images::every_slice_of_a_volume_decodes_to_an_image_of_the_mips_size, layers::a_volume_is_exported_as_one_png_per_slice, layers::a_volume_halves_its_slices_per_mip, texture_preview::a_volume_previews_its_slices_on_a_sheet, image_preview_layers::a_volume_is_shown_as_a_sheet_of_its_slices_in_german.
Array alpha tail mismatch found and fixed in the test, which no longer skips arrays and volumes (cubemap_alpha::real_alpha_tails_are_found_merged_and_decoded_into_alpha also checks every array or volume with a tail). Synthetic: layers::the_alpha_tail_of_an_array_is_merged_per_element.
R16G16_FLOAT (red, green) and R32_UINT (grey, scaled by u32::MAX like the other unsigned integer formats) decode. Tests: images::r16g16_float_decodes_to_red_and_green, images::r32_uint_is_scaled_by_its_largest_value.
Synthetic tests per new case (above, plus images::sheets_are_the_smallest_square_that_holds_the_images, images::the_preview_of_a_texture_is_its_mip_cross_or_sheet, images::images_are_tiled_row_by_row_with_transparent_cells_left_over, the header limits images::a_header_with_a_depth_or_array_size_beyond_the_limits_is_invalid, images::a_volume_that_is_also_a_cubemap_or_an_array_is_invalid, images::an_array_header_larger_than_its_data_is_a_mismatch_not_an_allocation, the cubemap array layers::a_cubemap_array_is_exported_as_faces_or_as_one_cross_per_element, and the file names in texture_names). The survey (texture_survey.rs) now decodes and exports every such texture instead of sampling them, and asserts it. No cubemap array exists in any Channel; that path is covered synthetically.
GUI: no new colour, size or component; the facts bar reuses FactsStrip with one more fact (new Fluent keys image-layers in de-DE and en-GB). Verified with a headless wgpu render of an array texture: the facts bar reads LAYERS 5 and the five elements are tiled in three columns and two rows.
Notes
Changelog fragment changelog.d/257.md; no catalog change and no new dependency.
The p4kx model texture test used R32_UINT as its "format without a decoder"; it now uses R11G11B10_FLOAT.
Item::output_paths, which detects two textures of one run writing the same file, still lists <stem>.<ext> and the face names only. An array a.dds and an unrelated a_layer0.dds in one run would both write a_layer0.png without being flagged; not handled here.
