Part of #204. Phase C — after Phase B.
Problem
The graphics path currently asks ChunkManager to run CPU meshing/LOD/light-cache jobs and also to record uploadPendingMeshes(VmaAllocator, StagingRing, VkCommandBuffer, ...). Chunk exposes VkDrawIndexedIndirectCommand, mesh arenas and GPU replacements. GPU resource lifetime and authoritative voxel lifetime are too tightly coupled.
Goal
Introduce a renderer-owned derived projection of CPU voxel world state (name flexible: RenderWorldBridge / ChunkRenderCache):
receive bounded world change/streaming notifications or revision-based views;
schedule existing CPU mesh/LOD/light-cache work using safe read-only chunk snapshots/leases;
preserve cross-chunk borders, sky/RGB light halos and incremental section rebuild decisions;
keep the Vulkan upload, mesh arena, retire, draw/visibility and camera-based prioritization entirely on the graphics side;
expose the same draw/shadow/lighting data to WorldRenderer, avoiding reimplementation of rendering passes.
Critical correctness invariants
World owns voxels; renderer owns meshes/GPU buffers. An unready/slow GPU cannot change simulation truth or block authoritative edits indefinitely.
Content and chunk incarnation/revisions validate every async result. Late results from unloaded/reused chunks are safely discarded.
Preserve previous committed mesh while replacement is pending (fix(renderer): keep previous GPU chunk mesh visible during voxel remesh/upload #177) and retain cross-chunk geometric atomic-commit groups (fix(chunk): keep border mesh replacements visible and atomic (issue #177) #178), including transitive overlapping edits; avoid temporary seams.
Preserve the current async worker limits, stage budgets, staging ring, deferred retirement, frames-in-flight and zero-device-idle steady state.
A headless process never schedules visual-only jobs (meshes, GPU caches, draw visibility).
Clear view/camera-dependent rendering decisions belong to the runtime/bridge, not CPU simulation.
For entities, CPU mob state is not Vulkan state; lighting sample/cache and model draw remain render-derived.
Tests / acceptance
CPU world can run with no render bridge registered.
Visual runtime uses the bridge for mesh jobs, GPU upload and draw/shadow lists without a duplicate source of authoritative voxel truth.
Chunk unload/reload, teleport, high-rate border edits, worker race/stale-result, multiple edit commit groups and GPU staging exhaustion remain safe.
No new CPU/GPU spikes or persistent GPU/CPU resource leaks when crossing chunk boundaries.
Existing GPU upload/mesh and visual regression tests pass; compare baseline profiler, draw/mesh workload and streaming metrics.
Core world/physics headers and compiled CPU library no longer require Vulkan/volk/VMA/SDL/ImGui.
Dependencies
After Phase B. Closely coordinate with Phase E Engine rewiring. Prefer small migration PRs (CPU mesh jobs, GPU commit state, final API cleanup) inside this issue if necessary.
