Hypothesis
Node positions (x, z) (dims 0–1 of the input) enter the Transolver as plain floats. For irregular CFD meshes, MLPs struggle to represent high-frequency spatial patterns from raw coordinates (Rahaman et al., 2019, "On the spectral bias of neural networks"). Random Fourier features (Tancik et al., NeurIPS 2020) replace the 2D coordinates with a multi-scale sinusoidal encoding, helping the model distinguish fine boundary-layer patterns from far-field flow without needing deeper layers.
The encoding is: for each of L log-spaced frequencies ω_l:
[sin(ω_l x), cos(ω_l x), sin(ω_l z), cos(ω_l z)]
This appends 4L extra dims to x before the preprocessing MLP; fun_dim must be updated accordingly.
Predicted delta: −3% to −6% on val_avg/mae_surf_p, with the biggest gains on surface nodes.

Change 2: add a Fourier encoding function in train.py (add after imports / before model definition)
```
def fourier_encode_positions(x: torch.Tensor, L: int, min_freq: float, max_freq: float) -> torch.Tensor:
    """Replace dims 0-1 (node x,z) with Fourier features, keep dims 2+ unchanged.
    
    Input:  x  [B, N, 24]
    Output: x' [B, N, 24 - 2 + 4*L]
    """
    pos = x[..., :2]   # [B, N, 2]  — (x_coord, z_coord)
    rest = x[..., 2:]  # [B, N, 22]
    freqs = torch.logspace(
        math.log10(min_freq), math.log10(max_freq), L, device=x.device
    )  # [L]
    # [B, N, 2, L] → sin/cos each
    angles = pos.unsqueeze(-1) * freqs  # [B, N, 2, L]
    enc = torch.cat([angles.sin(), angles.cos()], dim=-1)  # [B, N, 2, 2L]
    enc = enc.flatten(-2)  # [B, N, 4L]
    return torch.cat([enc, rest], dim=-1)  # [B, N, 4L + 22]
```
Also add import math at the top if not already present.

```
fourier_extra = 4 * cfg.fourier_L - 2   # replaces raw 2D coords with 4L dims
```

Change 4: apply Fourier encoding before normalisation in the training loop and evaluate_split
In the training batch loop (approx. line 487), before normalisation:
```
x = fourier_encode_positions(x, cfg.fourier_L, cfg.fourier_min_freq, cfg.fourier_max_freq)
x_norm = (x - stats["x_mean_fourier"]) / stats["x_std_fourier"]
```
Wait — the stats tensor has shape [24] and won't match the new input dimension. Simpler approach: apply Fourier encoding in-place before normalisation and recompute only the position dims, OR (easier) normalize only dims 2+ with the existing stats and don't normalize the Fourier position channels (they're already bounded to [-1, 1]):
```
# In training loop and evaluate_split, replace the normalization block:
x_enc = fourier_encode_positions(x, cfg.fourier_L, cfg.fourier_min_freq, cfg.fourier_max_freq)
# Only normalize the non-position channels (dims 4L+ of the encoded tensor = dims 2+ of original)
n_fourier = 4 * cfg.fourier_L
# x_enc: [B, N, n_fourier + 22]
# stats["x_mean"] has shape [24]; use mean/std for dims 2..23 only
x_pos = x_enc[..., :n_fourier]   # already in [-1, 1], no normalization needed
x_rest = x_enc[..., n_fourier:]  # [B, N, 22] — normalize with stats[2:]
x_rest_norm = (x_rest - stats["x_mean"][2:]) / stats["x_std"][2:]
x_norm = torch.cat([x_pos, x_rest_norm], dim=-1)  # [B, N, n_fourier + 22]
```
Apply the exact same block in evaluate_split as well (replace the x_norm = (x - stats["x_mean"]) / stats["x_std"] line there too).

What happened — honest analysis
Fourier positional encoding did not help; it appears to have hurt slightly and introduced numerical instability on test.
Worse val metric. val_avg/mae_surf_p = 123.10 vs baseline 113.86 (+8% worse). With only 14 epochs available within the 30-min cap, training may not have fully converged, so part of the gap might reflect undertraining rather than a fundamental issue with the encoding. Without Fourier the same training budget should produce a comparable curve, but I didn't run an isolated control here.
NaN on test_geom_camber_cruise. The cruise val split was healthy throughout (best surf_p=92.13). At test time, vol_loss=inf and surf_p=NaN on this split alone, while Ux/Uy stayed finite. This implies a small number of test samples (which has 2× more samples than val: 200 vs 100) produced extreme pressure predictions. The Fourier basis with max_freq=1000 may cause the model to over-amplify rare position outliers in held-out cruise geometries (M=2-4 camber).
Coordinate range matters. I didn't inspect the actual (x, z) range in stats.json before launching. If positions span e.g. ±10, then max_freq=1000 yields angles up to ±10,000 rad — extremely sensitive to mesh variation, which is consistent with the localized NaN.
Suggested follow-ups
Lower max_freq. Tancik et al. found max_freq should match the inverse of the smallest meaningful spatial scale. With min/max coords in [-1, 5] or similar, max_freq ≈ 32-64 is the standard NeRF recipe, not 1000. Re-run with --fourier_max_freq 32 --fourier_L 6.
Normalise positions first. Currently positions are raw. Apply (x - x_mean) / x_std to dims 0-1 before computing Fourier features, then choose max_freq ≈ 2π × (n_freq_octaves).
Try L=4 arm as PR instructions suggested, but with the lower max_freq fix above; otherwise this arm would likely show the same NaN pattern.
Concatenate rather than replace. Keep raw (x, z) and append Fourier features. Loses no information; gives the model both representations.
I'd recommend a fix-and-retry on the encoding scale before declaring Fourier positional encoding dead on this dataset — the implementation followed instructions exactly, but the chosen max_freq=1000 looks too aggressive for raw coordinates.

Suggested follow-ups
Push L higher cautiously. L=8 with max_freq=32 might extract a bit more (diminishing returns expected), but at some point too many features will add noise without information; the marginal cost is small so it's worth one screening run.
Tune min_freq upward. Frequencies near min_freq=1 correspond to very large spatial wavelengths that may be redundant with raw position encoding. Trying min_freq=2 or min_freq=π could give cleaner coverage of the useful band with the same L.
Concatenate (don't replace) raw positions. Keeping raw (x, z) alongside Fourier features costs 2 dims and lets the model use either representation; might help fine-tune the trade-off automatically.
Combine with other winners. This Fourier encoding seems likely complementary to architectural / loss-side ideas (e.g. fern's dropout=0.2). A merged ablation would test that.
