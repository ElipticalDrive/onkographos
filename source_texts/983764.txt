I am not using RGB data for fusion. I have fused depth data only and saved the mesh to an .stl file using roo::saveMesh. To obtain the image above I have extracted the connected components of the graph formed by the edges in the mesh. The points in the cloud above are coloured according to the connected component they belong to. As you can see there are multiple connected components that are disjoint but should be connected (for example patches on the wall).
My guess is that these patches are somehow linked to the blocks of memory storing the SDF in the GPU. On the other hand the whole SDF volume is copied to host memory here before running marching cubes on it, so GPU memory partitioning should not be an issue.

I figured out what the problem is. Marching cubes outputs a set of connected polygons for each of the voxels in the TSDF. However the polygons for adjacent voxels are not connected i.e. none of the vertices are "reused" between two adjacent voxel polygons. Instead the polygon vertex coordinates at the boundary between two voxels are very close to each other, but still are distinct vertices. In order to connect the adjacent voxel polygons you need to simplify the mesh by merging the vertices that are closer than some threshold to each other. vtkCleanPolyData will do this for you.
