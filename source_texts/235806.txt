Summary
Corrects surface-normal orientation for calibrated fisheye cameras.
compute_normalmap() currently decides whether a normal faces toward or away from the camera using the pinhole approximation
[(u - cx) / fx, (v - cy) / fy, 1].
The Oxford Spires sensor configuration uses OPENCV_FISHEYE, and the distortion coefficients are already passed to compute_normalmap() but were not used. Away from the image centre, the pinhole approximation can differ materially from the actual calibrated camera ray and can therefore flip a valid normal in the wrong direction.
Changes
back-project occupied pixels to calibrated camera-frame rays
use cv2.fisheye.undistortPoints() for OPENCV_FISHEYE
use cv2.undistortPoints() for the standard OPENCV model
pass the active camera_model from the depth-generation pipeline into normal-map generation
reject unsupported camera models explicitly
add regression coverage demonstrating a fisheye ray for which the previous pinhole approximation would choose the opposite normal orientation
Why this matters
Surface-normal maps are used as geometric supervision and evaluation data. Their sign should be determined in the same calibrated camera geometry used to project the LiDAR points. Using an inconsistent pinhole ray model for fisheye images can introduce orientation errors that are strongest toward the image periphery.
The change affects only normal orientation. Depth projection, point selection, normal magnitude, and the existing nearest-depth pixel selection are unchanged.
Validation
The new test supplies a calibrated fisheye back-projection whose ray differs from the pinhole approximation and verifies that the normal retains the physically correct orientation. A second test verifies explicit handling of unsupported camera models.
