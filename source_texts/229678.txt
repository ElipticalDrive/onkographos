Summary
add rasterize_mode="analytic" to the public and low-level standard 3DGS rasterizers
approximate each projected Gaussian's integral over the pixel footprint with the Analytic-Splatting tanh-CDF formulation
implement compile-time-specialized CUDA forward and backward paths for dense and packed layouts
preserve the classic and antialiased public behavior and the existing direct operator signatures
Why
Classic 3DGS samples a Gaussian at the pixel center. That is fast, but it aliases and substantially overestimates very small Gaussian footprints. Analytic mode integrates an analytical approximation over the pixel area, giving sub-pixel Gaussians a much more faithful response without supersampling.
The mode derives its eigen-frame once per Gaussian/tile in shared memory, so it does not add global preprocessing buffers or change projection/intersection formats. Classic and analytic behavior are selected through gsplat's runtime-to-compile-time dispatch rather than through a branch in the inner pixel loop.
User impact
```
render_colors, render_alphas, meta = rasterization(
    ...,
    rasterize_mode="analytic",
)
```
Analytic mode defaults eps2d to 0.0; classic and antialiased modes retain 0.3. Callers can override it explicitly. The implementation currently targets the standard 3DGS pixel rasterizer; 3DGUT and the standalone sparse-pixel renderer remain classic-only and unsupported combinations fail loudly.
This is an analytical approximation matching the Analytic-Splatting formulation, not an exact closed-form integral of a rotated Gaussian over an axis-aligned box.
