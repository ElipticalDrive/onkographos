Description
Fix #4774: ray_intersect_box computes a valid hit using direction components >= MINVAL, but reconstructs normals only for components > EPSILON. The mismatch returns a zero normal for some genuine face hits. Use >= MINVAL in the normal phase as well; slab distance, face bounds and tied-face handling are unchanged.
This is a clean 3-file port onto main bd69b56d of the previously executed donor fix and regressions. Commits on the upstream target are 3 ahead, 0 behind. No wholesale stale branch merge.
Checklist
New regression tests cover this (two registered tests, 52 subcases).
No new documentation necessary for this internal numerical correction.
Towncrier changelog fragment included.
Test plan
Historical native Linux CPU (Python 3.12.14 / Warp 1.18.0): 2 tests with 16 failing subcases before, 20/20 raycast and 16/16 adjacent CPU tests pass after; 72 independent boundary/geometry probes pass, pre-commit passes. Test commands: uv run --extra dev -m newton.tests -k test_ray_intersect_box and uv run --extra dev -m newton.tests -k test_intersect_ray_box_small_direction on a suitable current checkout.
Current-port hosted/Warp CPU/CUDA tests have NOT RUN. The source was read back from the remote fork and the final diff checked; do not mistake old-base results for current CI. No GPU/contact solver or throughput claim.
Bug fix
Steps to reproduce: box half-extents (1,1,1); origin (1+2**-23,0,0); direction (-2**-22,1,0). Public newton.intersect_ray returns t=0.5, with zero normal on the original source instead of expected (1,0,0). The newly added test_intersect_ray_box_small_direction reproduces via the actual public ray query with both fast-math modes. This does not duplicate thin-box contact normals in #4526.
Original raycast source credit: nvtw, Daniela Hase, Mustafa H and Alain Denzler; original downstream CPU tests/fix and independent critic factory queue #66. GPT-6 assisted this current-main port at the contributor's request. No human CLA signature is claimed; allow EasyCLA to assess.
Summary by CodeRabbit
Bug Fixes
Box ray intersections now return the appropriate face normals when rays have small, nonzero direction components. This applies to rays starting inside or outside the box and to intersections where multiple faces are reached at the same distance. The fix ensures the reported normal corresponds to a face considered during the intersection calculation.
