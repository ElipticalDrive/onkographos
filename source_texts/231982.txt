🔴 Existing mesh pipelines lose varyings
neo_mesh.vert moves normal and UV outputs, but existing fragment shaders still consume locations 0 and 1. The resulting interface is invalid, so existing mesh pipelines can fail creation or render corrupted inputs.
Learn more
The shared vertex shader previously exported normal at location 0 and UV at location 1. Both the mesh fragment shader and the material fragment shader retain that interface. The changed vertex shader instead exports world position at location 0, normal at location 1, and UV at location 2. Location 1 also changes from a vec2 consumer to a vec3 producer. Vulkan3DRenderer still constructs a pipeline from neo_mesh.vert and neo_mesh.frag, so this affects the current renderer rather than only the new PBR path.
Example: The standard renderer loads neo_mesh.vert.spv with neo_mesh.frag.spv. The fragment shader requests a normal from location 0 and UV coordinates from location 1, while the vertex shader supplies world position and normal there. Pipeline validation can reject the pair; otherwise shading reads the wrong values.
Recommended fix: Preserve the existing location 0/1 interface in the shared shader and use a separate PBR vertex shader, or migrate every fragment consumer and pipeline as one atomic interface change. CI must link each supported vertex/fragment pair, not only compile stages independently.

🔴 Spotlights face the opposite direction
EvaluateSpot negates the configured direction before comparing it with the light-to-fragment vector. Fragments inside the configured cone receive zero spotlight radiance.
Learn more
l points from the fragment toward the light, so -l points from the light toward the fragment. directionInnerCos.xyz also represents the light's configured forward direction. Negating that direction compares the cone axis against its opposite.
Example: A light at (0, 3, 0) points down with direction (0, -1, 0). For a fragment directly below it, -l is (0, -1, 0), but the current first operand is (0, 1, 0). Their dot product is -1, so coneFade becomes zero instead of one.
Recommended fix: Compare normalized light.directionInnerCos.xyz directly with -l.
Suggested change
float cone = dot(normalize(-light.directionInnerCos.xyz), -l);
float cone = dot(normalize(light.directionInnerCos.xyz), -l);

🟡 Nonuniform scaling distorts surface normals
outNormal uses the instance matrix directly for nonuniformly scaled instances. Their normals lose perpendicularity, producing incorrect diffuse and specular lighting.
Learn more
A normal must use the inverse-transpose of the position transform. Direct multiplication only remains correct for rotations and uniform scales. Instance transforms are arbitrary matrices, and the renderer does not restrict them to uniform scaling.
Example: Scaling an angled surface by (2, 1, 1) changes its tangent direction. Directly scaling its normal no longer leaves the normal perpendicular to that tangent, so BRDF dot products use the wrong angle.
Recommended fix: Apply transpose(inverse(mat3(instanceTransform))) to inNormal, then normalize the result.
Suggested change
outNormal = normalize(mat3(instanceTransform) * inNormal);
outNormal = normalize(transpose(inverse(mat3(instanceTransform))) * inNormal);
