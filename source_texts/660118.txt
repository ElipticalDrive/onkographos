Context
.vpak files are read into memory completely when mounted (AssetVfs.Mount → VortexPak.Read); per-scene paks are mounted when their scene loads. Textures are decoded from their source format (PNG/JPG via stb_image) at load time. Streaming has to read part of an asset — one mip, one LOD — straight from disk, without decoding and without holding the whole pak in RAM.
Goal
Cooked, GPU-ready asset data inside paks with a table of contents that points at every mip / LOD, read through asynchronous file I/O.
Acceptance Criteria
Cooked texture: header + BCn mips stored smallest-first, each mip at a known, upload-aligned offset
Cooked mesh: LOD chain stored per level (coarsest first), skinned data included
.vpak v2 with a TOC (offset/size per chunk), mounted via file handle or memory map instead of a full read
Async I/O queue with priorities (overlapped I/O on Windows, dispatch_io on macOS, worker threads on Linux), interface ready for DirectStorage
The export pipeline writes v2 paks; v1 paks still load
Cooking is cached by the asset's SHA-256 content hash (assets: SHA-256 content hashing on every import (+ backfill tool) #54)
Dependencies
rendering: BCn texture compression at import (BC1/BC3/BC5) + compiled-texture cache #179 (BCn compression)
assets: SHA-256 content hashing on every import (+ backfill tool) #54 (SHA-256 content hashing)
