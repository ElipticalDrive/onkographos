Summary
Tutorial 03 in the dasVulkan ladder, slot 3 (between Mandelbrot's 2D field and the synthwave cube's vertex+depth pipeline). Completes the fragment/compute-shader-as-renderer arc at higher complexity.
A [compute_shader] fires one invocation per pixel, builds a camera ray, marches it through a scene of smooth-blended SDFs (sphere smin torus on a checkered plane), shades the hit with key + ambient + soft-shadow + fog, then writes RGBA8 to a storage image. The whole rendering is math — no vertex buffer, no triangles, no textures.
Exercises dasSpirv rails the prior tutorials didn't: user-defined helpers via OpFunctionCall (smin / sd_sphere / sd_torus / sd_plane / rot2 / map / get_normal / march / soft_shadow / sky_color / ground_color / blob_color / tonemap) and GLSL.std.450 breadth (Length / Normalize / Cross / Dot / Floor / Pow / Exp / Cos / Sin / Clamp / FAbs / FMix).
30s @ 30fps voiced+captioned recording, single camera orbit (period chosen so the loop closes seamlessly), torus rotates around the sphere, IQ cosine palette pulses the blob hue (cream → blue → copper across the orbit).
Test plan
Pixel-oracle gate (test_sdf.das): sky-blue top corners, mid-tone non-saturated ground row, warm-toned hero blob in central band — passes locally (real GPU).
Lint clean.
Recording: 30s mp4 @ 1.2MB rendered locally; 3 voiced captions, daStrudel ambient bed.
CI: lavapipe pixel-oracle gate + Sphinx docs build.
Commits

tutorials/03_sdf: drop lerp3/pow3 helpers, use daslang's built-in lerp + pow — cleanup after the audit confirmed lerp(TT,TT,TT) and pow(TT,TT) already exist as templates over float/float2/float3/float4 in module_builtin_math.cpp (addFunctionPow<TT> / addFunctionOp3<TT>). The workaround helpers were unnecessary; switched to the vec-vec-vec lerp(a, b, float3(t,t,t)) form which the typer resolves to the TT-templated overload (lowered to OpExtInst FMix).
Surfaced finding (out of scope for this PR; recorded for the follow-up math-breadth PR)
The scalar-t overload lerp(vec, vec, float) (registered in module_builtin_math.cpp:lerp_vec_float) does typecheck against the daslang typer, but dasSpirv's emitter currently passes the scalar operand to FMix without broadcasting to the vector width — the resulting SPIR-V is invalid and crashes vkCreateComputePipelines. Two paths to fix in a follow-up:
Emit-side fix: detect the scalar third arg in FMix dispatch and broadcast via OpCompositeConstruct before passing to OpExtInst. Same shape needed for any future scalar-broadcast intrinsic (e.g. mad(vec, scalar, vec) would have the same issue).
Conservative: add lerp_vec_float to a per-name rejection list with a clean error telling the user to splat to vec at the call site.

```
…p + pow

The audit for the upcoming daslang math/dasSpirv breadth PR confirmed both
overloads already exist:

  pow(TT, TT)  for TT in {float, float2, float3, float4}  (math.cpp addFunctionPow<TT>)
  lerp(TT, TT, TT)  same TT set                            (math.cpp addFunctionOp3<TT>)

The dasSpirv emitter already dispatches `lerp` -> GLSLstd450.FMix (and `pow` ->
Pow); the workaround helpers were unnecessary. Switched the three lerp sites to
the vec-vec-vec form (`float3(h, h, h)` broadcast) which the typer resolves to
the TT-templated overload and the emitter handles correctly.

Caveat (out of scope for this commit; will be revisited in the math PR): the
scalar-t overload `lerp(vec, vec, float)` (math.cpp's `lerp_vec_float`) does
exist as a daslang signature but dasSpirv's emit currently passes a scalar
operand to FMix without broadcasting -- so calling that overload from a shader
produces invalid SPIR-V and crashes pipeline creation. The explicit float3(t,
t, t) form sidesteps it for now.

tutorials/03_sdf: fix march step-budget-exhaustion miss tracking
…
09999ba
```
Copilot round 4: a real bug, not a nit. The original `march` loop had three
exit paths but only two -- HIT_EPS satisfied and far-plane escape -- explicitly
set return state. If the marcher consumed MAX_STEPS without satisfying either
condition (rare but real, e.g. a near-tangent grazing trajectory that
asymptotically approaches a surface without crossing HIT_EPS), it returned
whatever `dist` had accumulated to AND mat=0, and the caller's
`if (hit.x >= MAX_DIST) sky else shade` branch shaded garbage at the blob
material at whatever world position the marcher gave up at.

Fix: track a `hit` flag (int 0/1 -- dasSpirv emit currently rejects
`ExprConstBool` in shader bodies, so int substitutes), force dist past
MAX_DIST when the loop exits without hit.

Surfaces an emitter gap worth a separate ticket: bool consts / bool locals
should work in shader bodies per GLSL semantics. Out of scope here.
