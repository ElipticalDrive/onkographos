Summary
Includes #90 and #95, so it lands all three together.
Multiscale (#90)
Commands that write a volume (connected components, clean CC, contact sites, MWS, fill holes, filter ids, label with mask, morphological operations, split narrow bridges) pyramid their output, and their _filled copy, when they finish. multiscale: false in the run-config skips this; compute-edt builds one only with multiscale: true. A standalone multiscale command does the same for any zarr v2/v3 dataset.
Levels are computed blockwise with tensorstore's downsample: mode for integer data, mean for floats. Factors follow wa.level_factors, so anisotropic axes wait for the finer ones. Each level's OME translation is the centre of its voxel 0, so every level covers s0's box. A level is listed in the group only once its data is complete.
Writes through worldarray (#95)
Outputs are created with wa.create in the container's zarr version (OME 0.5 for v3 groups, 0.4 in a v2 container) and carry only OME metadata, no funlib voxel_size/offset.
zarr_io.py, cellmap_array.py, precomputed_io.py, the driver detection, the URL/kvstore helpers and get_multiscales are deleted.
Voxel-index grids; ImageDataInterface removed
Every operation works in the voxel indices of one grid (a wa.Grid). Blocks are worldarray Blocks on it, every input is read onto it with read_onto (resampled when a voxel size or corner differs), and every output is created on it. This replaces the integer-scaled frame: funlib Coordinate/Roi in nm × a scale factor, rescale_to_factor, the LCM alignment between datasets, and the shape-guessing trims that rounding made necessary.
ImageDataInterface is deleted; datasets are plain wa.WorldArrays. zarr_util.open_dataset() applies cellmap's read defaults (padding, method, retries, capped concurrency, first level or voxel_size level), and create_multiscale_dataset(path, dtype, grid) returns the new level opened for writing. Workers write with write_index. util/grid_util.py makes, crops and intersects grids, and rescale_concurrency reopens handles per worker. voxel_size_utils and the funlib.geometry dependency are removed. Requires worldarray 0.4.
A run-config roi is in nm (README). Blocks, block counts and the output now all cover the voxels whose centres lie in it; before, several commands counted blocks over the roi but walked them over the whole input.
Fixed along the way:
mask erosion/dilation and label-with-mask surface padding are whole voxels on every axis;
the skeletonize and split-narrow-bridges memory estimates paired x with z's voxel size;
assign-to-organelles no longer doubles its search box forever when no organelle exists;
consensus inputs and per-channel affinities may sit on different grids;
a precomputed EDT with the wrong voxel size is rejected up front.
Outputs are unchanged. I ran a pipeline on anisotropic, non-integer voxels (3.54 × 4 × 4.5 nm, and 2× that for the second dataset) with offset corners: connected components with hole filling, contact sites across the two voxel sizes, measure, erosion, EDT, a roi run and the pyramids. Every array and its placement, plus the CSVs, match the code before this PR.

multiscale: add downsampled levels to an existing segmentation
…
3f63445
```
A new `multiscale` command adds s1, s2, ... beside an existing zarr v2 or
v3 level, until a level fits in one chunk or `num_levels` are written.
Each level is computed blockwise from the one below with tensorstore's
downsample driver, by mode by default so label ids are kept. Per-axis
factors follow mesh-n-bone's rule: an axis is halved while its voxel size
is within 1.5x of the finest, so anisotropic data moves toward isotropic.

Each level's OME translation is its voxel 0's centre, the centre of the
finer voxels it summarises: translation_0 + voxel_size_0 * (F - 1) / 2 for
a total factor F, so every level covers the same physical box as s0. A
level is listed in the group's multiscales only once its data is written.
Existing levels are rebuilt only with overwrite=True.
```
