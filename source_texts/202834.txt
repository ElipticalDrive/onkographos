Compute and cache properties derived from cell-facet adjacency data on meshes:
cell_facet_neighbours: maps each cell to its neighbouring cells across each of its local facets
cell_facet_coord_transforms: stores affine reference-coordinate transforms between neighbouring cells across interior facets
cell_facet_exterior_mask: marks cell-local facets lying on the exterior domain boundary (distinguishes exterior facets from rank partition boundaries)

The data can be derived from the DMPlex, but DMPlex does not return the arrays in Firedrake’s local facet numbering.
Neighbouring cells: DMPlex’s facet support gives the incident cells. Firedrake already uses that data in local_facet_number (firedrake/cython/dmcommon.pyx:357)
and _support_dat (firedrake/mesh.py:1635). To build Cache cell-facet topological data on meshes #5298’s per-cell, per-local-facet arrays, the code still has to map DMPlex point IDs to Firedrake cell numbers and
match each facet to its FIAT local facet number. The current cell-closure data supplies that ordering; DMPlex support order should not be treated as local facet order.
Exterior-facet mask: Read the exterior_facets DMLabel. Firedrake creates it with DMPlexMarkBoundaryFaces and already uses it to classify cell-local facets in
cell_facet_labeling (firedrake/cython/dmcommon.pyx:1479). Don’t infer physical exterior facets from support size alone, since a partition boundary can also have
incomplete local support.
Coordinate transforms: DMPlex stores incidence and orientation, not the affine reference-coordinate matrices. Those can be derived from DMPlex’s oriented cones or
closures plus the reference-cell facet maps, then cached.

@pbrubeck For neighbouring cells, my updated code already uses the DMPlex information. Same for exterior facet masks .
For the cell-facet coordinate transforms, I need to go through the FIAT local numbering (that is store the arrays in FIAT local facet ordering) because my particle tracing algorithms are implemented in the reference cell. The mesh entity collision algorithm figures out which facet was crossed based on the barycentric coordinates of the point at the crossing:
```
crossed_edge = int(np.argmin(abs(bary_cross[i])))
```
Which is why the arrays used by the cell-crossing algorithm, namely to figure out which cell is the neighbour across the crossed facet and to map the coordinates of the point to that cell, have to be filled using the same numbering as the crossed facet index (which is FIAT local ordering).
