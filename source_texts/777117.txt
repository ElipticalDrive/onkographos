Motivation
The direction-field glyphs are deliberately normalized to roughly constant length in public/pplane/app.js, so the phase portrait communicates direction but largely hides local flow speed. Add an optional visual channel for the magnitude of the field.
For F(x, y) = (ẋ, ẏ), the quantity to encode is |F| = sqrt(ẋ² + ẏ²) in the mathematical coordinate system (not pixel-space arrow length).
Proposed scope
Add a Color by magnitude toggle in the Vector fields Display controls, off by default; the existing quiet monochrome appearance remains available.
When enabled, color direction-field arrows/glyphs by local |F(x,y)| using a legible sequential color map, consistent in dark/light themes. Do not alter arrow direction or make glyph length depend on magnitude.
Show a compact labeled legend with numerical low/high values and explicitly identify it as field speed / vector magnitude; magnitude is not automatically energy or stability.
Select and document sensible automatic scaling/clipping for wide dynamic ranges, with meaningful behavior for zero/constant fields, non-finite values, and extreme outliers. Recompute when equations, parameters, bounds, or density change.
Keep trajectories, axes, and nullclines readable; use the existing show-field visibility setting coherently. No expensive per-frame re-evaluation beyond the current field sampling.
Acceptance criteria
Toggle works with bundled presets and user-entered ODEs; it is disabled/off by default and does not regress existing controls.
A field with varying speed visibly distinguishes near-stationary and fast regions; a constant-magnitude field does not produce misleading variation.
Legend values match the field quantity and its active scaling; colors stay interpretable after zoom, resize, parameter edits, and theme changes.
Zero/invalid/singular samples are handled without crashes or spurious high-intensity colors.
Add targeted checks for magnitude computation, normalization/edge cases, and UI redraw behavior.
Out of scope
A filled heatmap background, streamlines, and physically normalized cross-system speed comparisons can be evaluated later. Start with color-coded existing glyphs to keep this a focused QoL enhancement.
Priority: Backlog / non-blocking UX improvement.
