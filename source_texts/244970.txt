Problem
docs/architecture/render-pipeline.md:32-48 documented an "Execution Modes
(Single-Pass vs Serial)" control surface —
rendering/gaussian_splatting/instance_pipeline/true_single_pass_enabled,
rendering/gaussian_splatting/instance_pipeline/benchmark_allow_serial_multi_asset,
and modes single_pass / serial / single_pass_forced — that PR #326
(b153169114a, 2026-05-12) deleted from the renderer. Verified before
touching anything: grep -rn single_pass modules/gaussian_splatting/ returns
zero hits (confirmed again on this branch after the edit — still zero).
Both project-setting names also have zero hits anywhere in
modules/gaussian_splatting/ (no GLOBAL_DEF, no reader) — they are pure
residue with no C++ consumer.
Fix
(a) Doc rewrite — replaced the fictional section with a truthful
"Backend Route Policy (Resident vs Streaming)" section, grounded in the
actual code path: GaussianSplatRenderer::render_scene_instance →
build_frame_backend_plan → should_prefer_resident_backend, driven by
rendering/gaussian_splatting/streaming/route_policy
(GS_ROUTE_RESIDENT/GS_ROUTE_STREAMING), with GaussianSplatNode3D always
requesting the resident hint and a single_route_per_frame invariant
(no same-frame fallback between backends).
(b) Dead-setting cleanup — removed the writes/reads tied to the two dead
settings:
tests/examples/godot/test_project/scenes/benchmark_suite/benchmark_suite_lane.gd:
removed the INSTANCE_SINGLE_PASS_SETTING / INSTANCE_BENCH_SERIAL_MULTI_ASSET_SETTING
constants, their entries in PROJECT_SETTING_KEYS (snapshot/restore list),
their entry in RENDER_TELEMETRY_KEYS
(instance_pipeline_true_single_pass_enabled, mirror of the same dead
setting — always reported null, see
docs/assets/data/benchmark_suite_report.json:65,493,580), and the
_apply_lane_project_settings branch that wrote both settings based on
instancing_mode. Left an explanatory comment in place of the removed
block.
tests/runtime/run_benchmark.py: removed the
instance_pipeline_true_single_pass_enabled report field (init, extraction
via _report_renderer_metric, and output-dict entry) — same dead metric,
always null.
A/B lane flag (per task instructions: flag, don't redesign)
instance_pipeline_ab_serial / instance_pipeline_ab_single_pass in
run_benchmark.py's LANES list were meant to exercise "serial vs
single-pass" behavior via these two settings. Since PR #326 removed the only
C++ reader, both lanes were already producing identical renderer behavior
before this change — the setting write was inert. This PR does not change
that outcome; it only removes the now-pointless write. The instancing_mode
variable/CLI flag (--benchmark-instancing-mode) is left in place (still
threaded through as a report/label field and validated against a separate,
also-currently-dead instance_pipeline_execution_mode/path/reason telemetry
family that this issue did not name) — reworking that broader mechanism would
be a redesign, out of scope here.
Other flagged (out of scope, not touched)
tests/examples/godot/test_project/scripts/benchmark_metrics.gd:258 still
lists instance_pipeline_true_single_pass_enabled in
RENDER_PERF_STATS_FIELDS (a separate CSV-row field list, not named in
render-pipeline.md 'Execution Modes' documents settings deleted by #326; benchmark scripts still write the dead knob #561). Same dead-metric family; flagging for a follow-up rather than
expanding this PR's scope.
docs/assets/data/benchmark_suite_report.json (a captured historical
report artifact) still contains the dead field/setting as null/false
entries — left untouched as evidence data, not code.
