Overview
Adds SmoothGraphics, a drop-in alternative to Graphics that uses Half-plane Half-Axis Anti-Aliasing (HHAA) in the fragment shader for analytical per-pixel coverage. This produces smooth edges without requiring MSAA, making it ideal for high-quality vector rendering at any scale.
The existing graphics pipeline is refactored into abstract base classes so both Graphics and SmoothGraphics share ~90% of pipe/system/adaptor logic. BatcherPipe gains multi-batcher support so smooth and standard graphics can coexist in the same render group.
Features
Add SmoothGraphics class with shader-based anti-aliased rendering (HHAA) for circles, lines, fills, and polygons
Add DashLineShader for smooth dashed line rendering via graphicsContext.customShader
Add SmoothBatcher with 14-float-per-vertex format supporting line width, alignment, and scale mode packing
Support all cap types (butt, square, round), join types (bevel, miter, round), and stroke alignment
BatcherPipe now supports multiple batcher types per instruction set, enabling mixed standard/smooth graphics in a single scene

Implements shader-based anti-aliasing for vector graphics via the SmoothGraphics class and related rendering pipeline. Uses half-plane, half-axis techniques to produce resolution-independent smooth edges for fills and strokes.

Key additions:
- SmoothGraphics class with HHAA shader pipeline
- Custom geometry packing (10-float vertices) with joint types for line caps/joins
- Separate batchers and adaptors for WebGL/WebGPU
- DashLineShader for dashed line patterns
- Circle/ellipse/rounded-rect optimized builders
- Shared batch execution utilities to reduce duplication

Gradients, patterns, and canvas rendering are not supported.

refactor: improve type safety and optimize build

Removes unsafe `as any` casts by adding proper type declarations for the smooth graphics system in renderer mixins. WebGL and WebGPU renderers now properly expose `smoothGraphicsContext` property through TypeScript module augmentation.

Optimizes geometry building by:
- Caching build data instance to reduce allocations
- Hoisting epsilon calculation outside inner loop
- Removing redundant variable assignments in collinear point detection

Improves shader management by reusing shader instances when max textures hasn't changed instead of destroying and recreating. Exports helper functions from SmoothShader for reuse in DashLineShader, eliminating code duplication.

Removes unused `batched` property from GPU data.

refactor: extract shared graphics context system

Pulls common lifecycle logic (get/update/init) from GraphicsContextSystem and SmoothGraphicsContextSystem into a new AbstractGraphicsContextSystem base class. Subclasses now implement four hooks for the parts that differ: creating GPU contexts, building batches, counting geometry, and creating render data.

Also renames GpuGraphicsContextBase → AbstractGpuGraphicsContext to match the new naming pattern.

Significant changes:
- Adds AbstractGraphicsContextSystem with template method pattern
- Eliminates ~150 lines of duplication between the two systems
- Moves vertex/index counting logic into overridable hooks
- Simplifies SmoothGraphicsContextSystem to just hook implementations

GraphicsContext GPU data is keyed only by renderer.uid (e.g. context._gpuData[this._renderer.uid]). With the introduction of a second context system (SmoothGraphicsContextSystem), a single GraphicsContext can now be used by two pipelines (e.g. new SmoothGraphics(existingGraphics.context)), causing the smooth system to overwrite the standard graphics GPU context (and vice versa). Consider namespacing the key (e.g. ${renderer.uid}:graphicsContext / ${renderer.uid}:smoothGraphicsContext) so both systems can coexist safely for the same context.

This GPU draw loop always binds only groups 0 (global), 2 (localUniforms), and 1 (textures). Custom shaders that introduce additional bind groups/uniform blocks (e.g. DashLineShader’s WGSL @group(3) uniforms) will not render correctly on WebGPU because those groups are never bound. Consider extending this helper to bind any extra uniform groups required by shader.gpuProgram (or provide a hook/parameter so callers can bind additional groups).

Since this PR has been quiet for a while, I repackaged its SmoothGraphics implementation as a plugin in pixijs-userland/graphics-smooth#49. It turns out no core changes are needed anymore: the BatcherPipe change is already in PixiJS since 8.19, so the abstract base classes now live in the plugin.
Along the way I found and fixed several issues that also apply to this PR, for example:
WebGPU renders a black screen (textureSample in non-uniform control flow)
the sampler uniform is named uSamplers instead of uTextures, so batches with several textures sample the wrong one
fills are never anti-aliased
alpha is applied twice on the non-batched path
The full list is in the PR description, in case it's useful here too. Thanks @Zyie and @ivanpopelyshev for the groundwork!
