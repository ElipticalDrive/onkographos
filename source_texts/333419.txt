When attempting to run volume rendering in VisRTX (commit dea643b) using OptiX SDK 7.7, 8.0, or 8.1 and the NVIDIA GPU Computing Toolkit v12.6 on Windows 11, I encounter the following error:
```
[FATAL] error (D:\xxxx\VisRTX\devices\rtx\optix_visrtx.cpp: line 103): invalid configuration argument
```
The same client code works correctly when using the Helide renderer included with the ANARI SDK or using an older version of VisRTX.
This is the CMake configuration I used to build dea643b
```
cmake -G "Ninja" `
       -DCMAKE_INSTALL_PREFIX="../../anari_install/Debug" `
       -DCMAKE_BUILD_TYPE=Debug `
       -Danari_DIR="../../anari_install/lib/cmake/Debug/anari-0.14.0" `
       -DOPTIX_FETCH_VERSION="8.0" `
       -DCMAKE_CUDA_COMPILER="D:/Work/ovito-pro-deps/NVIDIA GPU Computing Toolkit/CUDA/v12.6/bin/nvcc.exe" `
       -DVISRTX_BUILD_GL_DEVICE=OFF `
       -DCMAKE_CUDA_ARCHITECTURES=native `
       ..
```
I suspect the issue may be related to the recent change from using an externally installed OptiX SDK to fetching it on-the-fly from GitHub.
When building an older version of VisRTX (commit d8c3e5c) with this CMake configuration:
```
cmake -G "Ninja" `
       -DCMAKE_INSTALL_PREFIX="../../anari_install_old/Release" `
       -DCMAKE_BUILD_TYPE=Release `
       -Danari_DIR="../../anari_install_old/lib/cmake/Release/anari-0.14.0" `
       -DOptiX7_ROOT_DIR="../../NVIDIA Corporation/OptiX SDK 7.6.0" `
       -DCMAKE_CUDA_COMPILER="D:/Work/ovito-pro-deps/NVIDIA GPU Computing Toolkit/CUDA/v12.6/bin/nvcc.exe" `
      -DVISRTX_BUILD_GL_DEVICE=OFF `
       -DCMAKE_CUDA_ARCHITECTURES=native `
       ..
```
Volume rendering works as expected without any errors.
Additional Details
The error occurs in optix_visrtx.cpp at the following code block:
```
OPTIX_CHECK_OBJECT(optixAccelBuild(
    state.optixContext,
    state.stream,
    &accelOptions,
    buildInput.data(),
    buildInput.size(),
    (CUdeviceptr)tempBuffer.ptr(),
    tempBuffer.bytes(),
    (CUdeviceptr)outputBuffer.ptr(),
    outputBuffer.bytes(),
    &traversable,
    emitDesc,
    2),
    obj);

CUDA_SYNC_CHECK_OBJECT(obj);
```
I investigated the inputs to optixAccelBuild() but could not identify any significant differences between the inputs used for:
Cases without volume rendering (which work in dea643b), and
Cases with volume rendering (which produce the error).

Is this using the same driver version that you reported on the other issue (566)? There always could be latent bugs in OptiX that get fixed in newer driver versions -- FWIW, OptiX is packaged as a part of the driver, so the headers used + experience will always be tied to driver version.
It's also advisable to just use the OptiX 7.7 headers all the time, as we aren't (yet) using any newer OptiX features. That may change in the future, but using a newer driver is 99.9% the best way to get a better OptiX.
