The 2D table calculator builds one RegularGridInterpolator when its table is set, the way the 1D one builds its interp1d, and keeps it for every lookup. Flat extrapolation looks up with a NaN placeholder and fills the Outside value afterwards, evaluated on each call as before. reverse_lookup holds its own body and docstring, and the unread _z copy of the table is gone. No user-visible effect.
Why
_set_table built a closure that called interpn on every lookup, which constructs a fresh RegularGridInterpolator each time. The closure held two copies of the interpn call, one for scalar and one for array inputs, and a five-line comment defending the state a deep copy shared through it. #743 aligned the parts this file shares with _table1d.py and left the closure for its own pass; this is that pass, so the two table classes now have the same shape.
Decisions
A NaN input still gives NaN under FLAT, even where the other input lies outside the table. interpn set NaN points after filling, so the outside mask excludes NaN inputs to keep that.
Scalar lookups are not converted: the interpolator answers two scalars with a 0-d array, and _transform's arithmetic returns np.float64, as interpn(...)[0] did.
A deep copy of a built table now holds its own interpolator and Outside value instead of sharing the source's closure. Nothing in navigate/ deep-copies a node, so no run is affected.
