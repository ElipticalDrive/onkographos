Change
CPU and GPU renders can use frosted Glass, chromatic dispersion, thin-film coatings, and caustics from hard lights.
Changes a default: no
For the Glass-only change, material-model, photon-map and quality-option defaults remain unchanged. Advanced materials and photon maps require explicit authoring. Jobs without active models, selected scattering or photons retain their preceding smooth-Glass normal and sampling route. Existing authored selected-medium scattering gains hard-light connections and the shared geometric optical facet model.
Add isotropic GGX reflection/transmission, visible-normal sampling and matched radiance/importance weights.
Add Abbe/Cauchy dispersion at three representative RGB wavelengths, retained through nested paths.
Add one coherent lossless dielectric film with separate s/p Airy responses, evanescence and critical-angle limits.
Connect rough interfaces, virtual rough-sheet sides and selected HG collisions to directional, point and spot sources.
Trace bounded photon caustics to rough interfaces, virtual-sheet sides, HG collisions and the first opaque receiver. Uniform receiver selection preserves the expected visit sum and launched-path normalization.
Partition camera estimates at the first sampled continuous event, preserving mixed delta transmission and opaque lighting.
Use reciprocal geometric optical facets for advanced transport and retain supported opaque shading-normal density corrections.
Resolve GPU optical hard lighting in a separate compute pass with at most 2 MiB of prepaid tile scratch in the existing accumulation binding.
Preserve the covered family of the existing closed-shadow approximation and refuse unrepresentable optical arithmetic explicitly.
Save material and caustic controls through stable bindings, temporary requests, CPU/GPU jobs and native files. Add native editors and eight-language translations.
Extend CPU Path sheets to certified planar tessellations, including concavity and holes. Certify retained GPU geometry after f32 conversion, preserving redundant sphere-pole compatibility.
Correct contained-medium Beer/HG light connections and safely prove vacuum for distant outside origins.
The material-model guide documents equations, units, admission, ownership and limits. The Glass matrix records supported geometry and feature combinations. One pending format descriptor covers the new saved fields. The Glass-only diff preserves the pinned rendering parent's kernel, SDK, dependency and application sources.

* Design tabs: double-click a tab to rename the design

A double-click on the selected design's tab opens a name field in the tab
with the name selected, so typing replaces it. Enter or a click anywhere
else keeps the new name; Escape keeps the old one. The tab grows with the
name while it is typed (up to the tab's usual 200 pt). The rename goes
through component.rename with component 0, so it is undoable, marks the
design unsaved and is what Save As offers next. A name left as it was or
left blank changes nothing, and names are cut to the 128 characters the
command takes.

On desktop the bar is the window's title bar, and a double-click on a tab
used to maximize the window. Double-clicking the bar's empty space still
does; the tabs now rename. The preference tab_double_click_renames
(Preferences > Interface, "Double-click a design tab to rename it") brings
the old behaviour back.

Changes a default: yes - a double-click on a design tab renames the
design, old behaviour (maximize the window) kept behind preference
tab_double_click_renames.

Strings in assets/locales/pending/design-tab-rename.json (en, ar, de, he,
ja, ko, vi, zh). Docs: the UI tour and the preference list in
control-protocol.md (handle tab:rename).

Tests in documents.rs: Enter renames and undo restores; a click elsewhere
keeps the name and the tab grows while typing; Escape, a blank name and

* Agents and scripts: the view navigation and layout commands describe their exact parameters and reply (tangency-labs#12278)

describe_command now gives the exact parameters and reply of view.navigate,
view.layout, view.history_layout, view.graphics_preset and
view.ambient_occlusion, and the warn and strict parameter checks use them.

The handlers still read their parameters from the raw JSON, so the new types
read each key as its handler does and give its message. Keys the handlers
refuse when left out (mode, preset, enabled, camera) are required in the
schema but left to the handlers' messages. The replies are built from typed
values instead of json! literals, with the same JSON as before.

* view.navigate: the contract reads only the keys of the form the handler takes (tangency-labs#12278)

The handler reads a motion's keys when motion is given (each motion its own), else direction, else degrees and action, and never the keys of another form. The contract is now read by hand in the same order, so a key of another form is not checked in warn or strict either, and a call that works with the check off works in both.
