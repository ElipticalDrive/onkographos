Hi @mikedh,
I have a cup.binvox (or binvox volume array) and cup.obj.
I also have the scale, dims and translate outputs from binvox.
It seems I can load the two in trimesh and create a voxelized_cup_mesh.
main Q is--- Is there a function/support that given a vertex coordinate from cup.obj can allow me to determine which voxel element in the voxel 3D array model it corresponds to?
Here are a few considerations from my understanding:
binvox applied a normalisation(via translate and scale) which maps vertex coordinates from cup.obj to another coordinate in the normalised coordinate space before voxelization (https://www.patrickmin.com/binvox/binvox.html).
alternatively, given the coordinate from cup.obj, if we determine the normalised coordinate (in binvox), can we determine the closest voxel element it is contained in the 3D voxel array? also, I assume you apply the translate and scale from binvox before rendering the voxelized mesh object?
I looked at VoxelGrid and base.py where you have bounds, is_filled function which have some implementation, but I don't think those function exactly fit my usecase.
reverse of what I am looking for-- but also looked at marching_cubes, which returns the vertices and faces given a voxel array, but I don't think that has any strict mapping to the passed 3D array and returned vertixes. Also, the values and number of vertixes don't match those from cube.obj so I assume it there is some preprocessing.
Let me know if my question is unclear. Thanks.

Hey, I think to find the corresponding voxel element the easiest way is probably to just divide vertex positions by the pitch and round it to an int, once you've transformed the points/voxels to the same frame:
```
In [1]: import numpy as np

In [2]: points = np.random.random((10, 3))

In [3]: pitch = 0.1

In [4]: index = (points / pitch).round().astype(int)

In [5]: points
```
