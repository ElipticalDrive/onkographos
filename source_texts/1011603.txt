Closes #1459.
#1527 carries the FlyWire half of this issue (opacity 0.79 + luminous on every layer, Neutral → ACES). This is the sweep the issue's implementer notes asked for: the five other demo modules that still pinned tone_mapping="Neutral".
What I found
Every one of those pins justified itself the same way — colour here is an exact encoding, ACES shifts hues — and for a scene that already fits inside [0, 1] that reasoning doesn't survive contact with the operator. Khronos PBR Neutral is not an identity anywhere: it subtracts an offset (0.04 once the channel minimum reaches 0.08, x - 6.25x² below that, which crushes near-black hardest) and, from peak 0.76 up, compresses the peak and mixes toward the grey equal to it. So the answer is decided by range, and over range it inverts: Neutral holds the HSV hue angle exactly (its offset, compression and mix are all "scale every channel, then add the same amount to all") but sheds chroma, while a hard clamp keeps saturation and shifts hue whenever several channels clip unequally.
What changed
Flipped to tone_mapping="None" — both provably in gamut, so the clamp is exact and Neutral was dulling the encoding the comment set out to protect:
demo_ocean_currents_earth — Blue Marble texture and the blue→white speed LUT are both [0, 1], both nodes blending_mode="normal" at LINE_INTENSITY = 1.0, bloom off.
demo_gsplats_recipes_tribolium — hsv palette in [0, 1] over six volumetric gsplat nodes. Working the shader through, emitted RGB is color·(1 − e^−τ)/absorption with τ = absorption·opacity·intensity, so opacity cancels and absorption=1.0 is what bounds it.
Kept Neutral, with the comment now stating the real reason — all three run over range with colour as a hue encoding, which is exactly where Neutral's hue-exactness is worth its chroma cost:
demo_nd_transforms (C_LIT peaks 1.9, CH_LIT 2.4), demo_biodiversity_planetary_scale (GLOBE_INTENSITY 4.88, OCCURRENCE_INTENSITY 100.0), demo_gsplats_3d_tribolium_embryo (exposure=1.97).
Left alone deliberately: the _interop_common.build_interop_scene default. Five of its six callers are in gamut, but demo_gsplats_interop_sog_matrixcity builds recipe="overview", whose substitutive merge emits amplitudes with no bound of 1 that the gsplat normal shader feeds straight into RGB. That one needs a render check before it can claim to be in gamut, so the default stays and the docstring now says why.
New guard — demos/tests/test_demos_tone_mapping_policy.py AST-scans the demo package (via the existing _scanned_modules denylist, so new demos join automatically) and requires "ACES" unless the module has a row, with a reason, in an exceptions table. It reads inline literals, signature defaults and module-level string constants, and its docstring is explicit about the dynamic spellings it cannot see (none occur today).
Docs — the surfaces that were teaching the old rule now say to pick by range: CLAUDE.md, the HDR guide, gsplat convert's option help and docstring (they were about to contradict each other on one --help screen), the compiler's LUT notice, ViewerConfig.tone_mapping, the gsplat-ops and _compiler READMEs, the skill reference, and the viewer's tone-mapping tooltip + config comments. Worth noting None and Linear compile to the same shader mode in our mega-shader, so either spelling is the passthrough — None is just the clearer name.
