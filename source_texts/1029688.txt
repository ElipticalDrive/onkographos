Description of how you validated changes

Local render harness (built viewer served on loopback by a server that requires a bearer token; not the deployed app): with the header, a point cloud from a public LAS sample loaded and drew; every metadata, hierarchy and octree request carried the header. Playwright (on the shared harness from #1191): "Potree Viewer renders" cases for .las, .laz, .e57 and .ply. The four Potree cases (.las, .laz, .e57, .ply) are renderCases of kind
"potree" on PR-1's seeded-sample harness. Each skips with the pipeline's name
while the file has no Potree preview, then asserts Potree.lru.numPoints > 0
and point pixels on the Potree canvas by red channel, since Potree's blue
gradient background defeats canvasStats' most-common-colour measure. The
shared console, CSP and third-party-host checks apply as for every case.

The samples are viewer-samples.json entries: PDAL autzen_trim.las and .laz
(BSD-3-Clause), libE57Format-test-data ColouredCubeDouble.e57 (CC0-1.0,
7680 coloured points; replaces the E57 this branch derived with pye57), and
autzen_trim.ply derived by a new stdlib-only las-to-ply transform in
seed_viewer_samples.py. The manifest guard knows the transform and requires a
.las source and a .ply output; web/e2e/CLAUDE.md and the examples README
document it.

Potree 1.8.2 vendors libs/copc, which potreeInstall.js copies into
public/viewers/potree_libs and the build copies into workers/: a webpack
bundle of copc 0.0.5-alpha.1 (MIT) with the cross-fetch 3.1.5 browser
ponyfill (MIT, identical code in 3.1.5-3.1.8), and laz-perf 0.0.5
(Apache-2.0) as WebAssembly. Versions were identified by comparing the files
with the npm releases (laz-perf.wasm is byte-identical to 0.0.5). NOTICE.md
lists each one, and the install checks the files' SHA-256 so a commit move
that changes them stops until the rows are re-checked. A unit test ties
bundledLibraries to the NOTICE rows.
