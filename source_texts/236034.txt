Acceptance Criteria
Construct a right-handed orthonormal camera basis and transform camera -Z toward look_at for arbitrary valid poses.
Generate unit rays at documented pixel centers with horizontal FOV and consistent downward raster Y, including rectangular and single-pixel rasters.
Own pose data and return independent ray/matrix arrays so caller mutations cannot desynchronize origins and directions.
Validate finite complete pose vectors, nondegenerate viewing/up axes, FOV/raster parameters and generated camera-path parameters before publishing results.
Add independent geometric projection/orientation and camera-path regressions, full changed-file lint, a focused native Linux gate and convention/migration/limitations documentation.
Impact & Side Effects
Corrected orientation and pixel sampling deliberately change previously wrong rays. Pose properties now return copies and reject assignment: construct a new pose to move it. Existing method/default/dictionary contracts remain. Invalid/degenerate geometry raises ValueError. Path/raster memory remains proportional to caller-selected counts; no new quota. Existing route consumes poses, but full rendering/service boot is not claimed because the separate model fix #17183 remains open. No real-camera calibration, lens distortion, navigation-control or rendering-quality guarantee.
Reference: original NeRF ray helper supports -Z/downward raster Y; explicit pixel-center offset here is documented separately.
