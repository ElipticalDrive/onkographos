Summary
Replace voxel-based LOD (step ≥ 4) for distant terrain with 3D Gaussian Splatting rendered via a neural encoder on the Apple Neural Engine (ANE). This eliminates blocky distant terrain and reduces memory by ~70x.
Background
Current LOD system at step=8 produces 2³ = 8 effective voxels per chunk — extremely blocky. Gaussian splats provide smooth, detailed landscape silhouettes at any distance.
Architecture
```
ChunkManager: chunk enters LOD ≥ 4 zone
  ↓
[CPU] Generate low-res 32×32 heightmap + biome map for region (4×4 chunks)
  ↓
[ANE] Core ML model: heightmap → 3D Gaussians
  Input:  32×32×3 (height + biome + normal)
  Output: N×14 (pos, scale, rotation, color, opacity), N = 64-256
  ↓
[GPU] Gaussian Splat Renderer (new render pass)
  Depth-sort → rasterize → depth-test against voxel geometry
```
Key Benefits
Memory: 64 chunks region ≈ 0.5 MB → 128 Gaussians = 7 KB (70x savings)
Visual quality: Smooth landscape silhouettes vs blocky voxels
Parallelism: ANE runs alongside GPU, no resource contention
Implementation Plan
NeuralLODManager.swift — Core ML lifecycle, async ANE inference, region cache
GaussianSplatRenderer.swift — Metal render pipeline for splats
GaussianSplat.metal — vertex/fragment shaders
Core ML model training via self-supervised pipeline (render own terrain as ground truth)
Integration with ChunkManager.swift — delegate LOD ≥ 4 to NeuralLODManager
New render pass in Renderer.swift after deferred lighting
Reference: MetalSplatter — open-source Swift/Metal Gaussian Splatting
Requirements
macOS 15+ (Core ML + ANE)
M1+ (Neural Engine)
