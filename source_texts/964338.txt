Is your feature request related to a problem? Please describe.
Texture3D type currently only supports Gaussian Cube (.cube) file format. This format is very niche in that it is used primarily for computational chemistry, and generating these files for other purposes is not accessible to the average user.
Describe the solution you'd like
Add support for OpenVDB (.vdb) file format for Texture3D volumes.
Describe alternatives you've considered
Blender, Unity, Unreal, and Houdini all have implementations for volumes, however none have the ability to export or convert to the .cube format.
Gaussian, Inc. offers an academic license for their 32-bit software for $1000 USD, or a commercial license for $2500 USD, for one year of use. Does not include tools useful for creating 3D environment or VFX.
VDM (Visual Molecular Dynamics) is a free and open source program that can open and generate .cube files, but does not include tools useful for 3D environment or VFX.
PyMOL, same as above.
NWChem, same as above.
Additional Context
OpenVDB is an open source C++ library for the efficient use of volumetric data. The source can be found at this Github repo.
OpenVDB files can be easily generated by the user with Blender, Houdini, Python, and other various methods. They can also be converted from existing .cube files using the various tools that educational and commercial users have access to.
Impact:
This greatly reduces the barrier to entry for users to create content using the new Texture3D_Force component as part of PhotonDust particle systems. This likely will also allow for better use of VolumeUnlitMaterial, opening up options for baked volumetric lighting.
See also:
NanoVDB
Signed Distance Fields(SDF) in Unity
VectorField (.vf) file is another open source specification that can be natively read by Unity alongside several other 3D programs, however is less user friendly as the only way to export from a 3D program is via the VFXToolbox Volume Exporter tool for Houdini.

The .cube format that we support isn't "Gaussian Cube" format, it's a Cube LUT format and has nothing to do with computational chemistry:
https://kono.phpage.fr/images/a/a1/Adobe-cube-lut-specification-1.0.pdf
https://resolve.cafe/developers/luts/
This is pretty widely used and supported by Adobe software, DaVinci Resolve and bunch of other industry multimedia software. I wouldn't call it very niche.
However can look into adding support for additional formats. The OpenVDB library however seems to be quite large on itself, with tons of functionality beyond just the format. We're not really likely to integrate something like that.
Are there libraries specifically just for the format? And ideally are there either C# implementations or C# wrapper? Those would make it much easier to prioritize something like this, otherwise we have to take on the burden of either porting the format to C# or making a wrapper for native library, which can substantially increase the amount of work required and make this less likely to be prioritized.
