Contributor
Monochrome Add Noise uses the same channel-zero noise value for every color channel, but previously recalculated that value inside the channel loop. Calculate it once per pixel and reuse it. The colored path still calculates a separate value for each channel. The noise expression, coordinate hashing, seed handling and alpha skip stay the same.
Extend the existing noise tests to cover both distributions in monochrome mode, alpha preservation, deterministic seeds and the shared tiling/selection checks. A 3×2 RGB8 regression also checks two in-source golden byte arrays generated from the original 799e1296 implementation, one per distribution, and verifies that colored noise still produces different channel values.

Validation
On 44bc8880, combined with official main 655295b2, strict dependency-inclusive all-target Algo Clippy, the canonical test build, formatting and whitespace checks pass with installed Rust 1.97.1. Both exact noise tests pass: uniform/Gaussian RGB8 golden bytes and colored-channel variation, plus determinism, alpha, shared-channel, centering and seed controls.
The CI repair changes only one test iterator to the equivalent as_chunks::<3>() form, preserving all assertions and golden arrays. The production noise code remains byte-identical to the preceding PR head.
Earlier revisions passed 757 unit and 13 integration tests (26 ignored), eight focused noise tests, 864 bit-exact kernel comparisons and Surface fingerprint controls. Those results retain their original inputs and do not establish a full-suite result on this newer main.
Fresh successor CI must verify the newer Rust 1.99 Clippy rule and the full workspace/platform gates. No lint suppression, assertion weakening or new benchmark was added.
