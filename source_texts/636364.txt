What changed
Faster chunk construction
materialize the complete bounded 46×32×46 build volume once per chunk
cache all 67,712 block IDs in a compact byte array
reuse that cache for direct sky light, block light, flood propagation, and greedy meshing
avoid repeatedly evaluating terrain noise, caves, ores, and tree placement for the same voxel coordinates
Lower lighting overhead
replace grow-heavy JavaScript number queues with compact reusable Int32Array queues
stop seeding every directly lit sky cell into the flood fill
only enqueue sky cells that can actually improve a neighboring cell, concentrating work around cave mouths and shadow boundaries
preserve the existing 0–15 sky light, block light, transparent-leaf, and emitter behavior
Smoother browser fallback
when module Workers are unavailable, execute one synchronous chunk build per macrotask
yield to input, animation, and rendering between fallback builds instead of running the whole render window as back-to-back microtasks
retain priority, keyed cancellation, and runtime Worker-error fallback behavior
Smoother streaming and backtracking
upload at most one completed chunk mesh per frame instead of two
keep the twelve most recently unloaded chunk meshes disabled in a bounded LRU cache
restore cached chunks immediately when the player walks back instead of rebuilding and re-uploading them
bias same-distance chunk priorities toward the player's smoothed travel direction
invalidate and dispose cached meshes safely when world revisions change
Validation
strict TypeScript passed
strict ESLint passed
all 125 Vitest tests passed across 32 test files
new cache regression proves the complete 67,712-cell build volume is sampled exactly once and repeatedly read without new terrain calls
existing terrain, greedy mesh, sky light, block light, furnace light, cancellation, and Worker runtime-fallback tests passed
production Vite build passed, including the optimized terrain/light Worker
both Chromium software-WebGL smoke tests passed, including persisted survival/crafting/camera behavior and forced module-Worker failure
no page or console errors
CI performance comparison
These are directional comparisons between separate GitHub-hosted CI runs, not a deterministic device benchmark:
ChunkBuildTask suite: about 1.90 s → 0.58 s, roughly 70% lower
ChunkWorkerPool suite: about 2.19 s → 0.62 s, roughly 72% lower
complete Vitest run: 5.95 s → 4.69 s despite adding two tests
Chromium smoke run: 32.2 s → 20.2 s, roughly 37% lower
Intentional limits
a single Babylon mesh upload can still cost one frame on very low-end GPUs; this change bounds uploads to one per frame rather than attempting unsafe partial vertex-buffer construction
the twelve-mesh recent cache trades a bounded amount of GPU memory for smoother short-distance backtracking
first-time exploration still needs real terrain generation; it now performs substantially less repeated CPU work but is not zero-cost
exact FPS and frame-time improvement on the player's browser still requires live-device observation
