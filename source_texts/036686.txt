Parent program: #238. Scope and acceptance of #238 are authoritative and are not reduced here.
Scope and ownership
Implement genuine volumetric illumination and scene-depth atmospheric effects. Existing subsystem contracts must be consumed rather than duplicated.
Dependencies / integration
Cinematics 02 Blender adapter; #15 physical lighting and #16 renderer
Implementation tasks and subtasks
1. Implement true scene/world/local volume materials for fog, haze, mist, animated dust atmosphere, volumetric light shafts and attenuation; integrate actual lights/shadows.
2. Validate scattering, absorption, anisotropy, density, height falloff, local volume transforms, noise/turbulence, range, sample budgets and backend settings.
3. Implement camera-distance atmospheric perspective using actual scene depth and documented interactions with native mist passes.
4. Expose keyframed volume/atmosphere parameter changes and clear unsupported/performance behavior; do not substitute 2D overlay for 3D scattering.
Executable acceptance and evidence
A1. Render depth-staggered 3D environment with volume on/off, multiple densities and moving camera/light; actual volumetric shafts and distance response are visible.
A2. CPU headless Blender effects persist through correct EXR passes, compositor and encoded video frames.
A3. Verify bounds/invalid parameters, memory/sample caps, alpha and shadow interactions, and record true engine/version/performance.
Add and execute unit, negative/boundary, deterministic/recovery and real backend integration tests appropriate to the feature; record commands, actual results, tool versions, SHA, rendered artifact hashes and limitations.
PR includes code, schemas/migration where applicable, docs, executable fixture/demonstration and a reviewer-verifiable evidence receipt. Resolve independent review/CI findings before merging.
Non-negotiables
No Codex coding delegation. Preserve existing 2D formats and legacy audio-capable workflows. For cinematic final video enforce zero audio streams. Unsupported/approximate/editor-only features must be reported honestly; no illustrative mockups count as production validation.
