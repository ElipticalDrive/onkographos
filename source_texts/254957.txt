On the M4 Max the CPU gap is similar in ratio: cpuMs is 0.4 on WebGL and 1.0 on WebGPU for 10M normal.
So the remaining gap is on the CPU and sort side, not in the shaders.
What we know
Each landing depth sort uploads the whole order buffer (aSortedIndex / aSortedIndexB, 40 MB at 10M elements) with one writeBuffer. That costs about 12–28 ms of main thread on Chrome/Dawn. Splitting it into 4 MB or 16 MB slices made things worse (WebGPU: upload the depth-sort order in slices #3142, closed with numbers).
The sort is GPU-independent CPU work in a worker (rendering/depth-sort-coordinator/). On WebGPU the extra renders per frame come partly from sort results landing while the frame waits for the GPU, which WebGL's blocking readPixels sync hides (see Render gate: write missing gate stores and record host load #3155).
three's per-object WebGPU bookkeeping (render objects, bind groups, NodeMaterialObserver checks) runs every frame and costs more than WebGLRenderer's.
Ideas
Profile first. Take a Chrome performance trace of a 10M normal orbit on both backends. Attribute main-thread time to: the sort-result commit (writeBuffer), three's renderObject / bindings updates, Luxar's per-frame work (LOD, density guard, sort scheduling), and Dawn submit.
Sort cadence. If sort commits dominate, land a new sort at most every N frames while the camera is moving, or skip a commit whose permutation barely changed (small view delta).
GPU-side indexing. If the 40 MB upload dominates, stop shipping the whole permutation. Ship a compact key array and let a WebGPU compute shader build or scan the order. WebGPU is the only backend that can do this, and the depth-sorting spec lists GPU sort as a future option (docs/guides/specs/GSPLAT_DEPTH_SORTING_SPEC.md).
three overhead. If render-object or bind-group updates dominate, check for per-frame uniform writes that could become one uniform buffer per node, and for bind groups rebuilt every frame.
Measure with the render gate's perf-splats-10m-normal and perf-splats-5m-volumetric cases (frameMs, throughputMs, cpuMs), on both backends.
