Overview
Replaces tactical voxel line-of-sight in crates/tactics/src/los.rs with 3D Bresenham integer raycasting (dominant-axis stepping and error accumulators) instead of the prior Chebyshev-step linear interpolation along the segment.
Behavior is still endpoint-exclusive (only voxels strictly between from and to can block), but intermediate cells are walked on a proper grid line without floating-point rounding. The change adds a large los test module (clear/blocked paths, diagonals, endpoint solids, symmetry, edge cases) on top of the existing FR-CIV-TACTICS-020 check in crates/tactics/src/lib.rs.

The 3D Bresenham implementation is not symmetric for diagonal lines due to the directional nature of the error accumulator and starting coordinates. For example, if we check LOS between (0, 0, 0) and (2, 1, 0) with a blocker at (1, 0, 0):
line_of_sight(A, B) checks (1, 0, 0) (blocked -> false)
line_of_sight(B, A) checks (1, 1, 0) (clear -> true)
This violates the expected symmetry contract LOS(A -> B) == LOS(B -> A).
To guarantee perfect symmetry, we can sort the from and to endpoints lexicographically at the beginning of the function so that the traversal always runs in the same direction regardless of the argument order.

The dominant axis check (ax >= ay && ax >= az, etc.) is loop-invariant because ax, ay, and az do not change during the traversal. Evaluating these conditions inside the loop on every iteration adds unnecessary branching overhead.

High Severity

It then treats off-segment cells as the path and returns clear. War-bridge LOS uses y = 0 with both x and z from grid coords, so diagonal engagements hit this case.
