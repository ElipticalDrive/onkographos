Part 2 of #171 (nodes).
Noise Type on the noise node: Value / Perlin / Simplex, sharing scale, octaves and persistence. Value is untouched (pinned by output hashes taken before the change). Perlin and Simplex use per-octave seeded tables (no global state), depend only on absolute cell position (ready for chunked generation), and run on the worker threads.
Poisson Scatter (new node, poisson_scatter): Bridson's algorithm over cells, with radius, attempts (30) and an optional mask; masks in separate pieces get points in each piece. A separate node rather than a Scatter mode, because its settings don't line up with Scatter's chance and spacing.
Format: no bump. type is an optional param; a missing one reads as value.
Timings at 256x256 (-o:speed): value 0.3 ms, Perlin 0.5 ms, Simplex 0.8 ms, Poisson r=4 1.8 ms; the whole bench graph 1.64 ms.
Tests: 454 pass (new level_gen_nodes_test.odin: value unchanged, determinism, range, continuity across origins, Poisson minimum distance, mask, coverage). Drives: new levelgen_nodes; levelgen_shapes and level_generator pass. Docs: engine/docs/level_generator.md.

The noise node gets a Type (value / perlin / simplex), all with the same
fBm settings. Value stays the default and gives bit-identical grids
(pinned by hash in a test). Perlin and Simplex use a permutation table
per octave shuffled from the node's seed and depend only on the absolute
cell, not the level's size, so a later chunked mode can use them.

Poisson Scatter is a new node (Bridson's algorithm): radius, attempts
(30), seed, an optional mask; every two points at least radius apart,
walks restarted in mask areas no walk reached. Each point stamps the
cells near it, so a try is one look-up (about 2 ms on 256 x 256, r 4).

The type is an optional choice parameter (saved by name, missing =
value): an additive field within format 1, like frames, so no bump.
