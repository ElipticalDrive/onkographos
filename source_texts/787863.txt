Context
Compute programs sampling 3D volume textures (e.g. Assassin's Creed Black Flag cs 0x407ed7a300 32x32x32 LUT view) are rejected with [t#] unsupported BASE_LEVEL N (last=N max_mip=5) for type=10, causing sampling instructions (MIMG) to drop as unresolved resource descriptors.
In image_base_level_view(), the condition (!thin_2d && !thin_2d_layered) previously excluded 3D textures (type == 10), causing any 3D descriptor with BASE_LEVEL > 0 to fail closed under unshifted_view_supported().
Higher Goal
Allows compute shaders sampling 3D volume textures with non-zero mip levels / base levels (such as color-grading LUTs or volumetric density textures) to materialize resource descriptors, unblocking compute passes in Black Flag and other titles.
Acceptance Criteria
3D volume descriptors (type == 10) with base_array == 0 can derive shifted base-level views via tiled_mip_level_layout().
Layered 3D UAV views (base_array != 0) remain rejected fail-closed as unmodelled slice stride.
Architecture ratchet check passes with 0 rows raised.
Out of Scope
3D UAV arrayed views with non-zero base_array (which require custom slice/block stride modelling).
Summary of Changes
prosper/src/gpu/agc/agc_shader_layout.cpp: Recognized volume_3d (d.type == 10) alongside thin_2d in image_base_level_view(), allowing single-volume 3D descriptors to compute mip offsets while keeping base_array != 0 fail-closed.
prosper/tests/gpu/agc/test_build_shader_resources.cpp: Added unit test confirming that a 3D texture descriptor (TYPE 10) with non-zero BASE_LEVEL materializes with shifted extents.

REJECTED at head 88d5c62. Not merged.
This admission would bind wrong texels silently. With volume_3d admitted, image_base_level_view() places a 3D level using the thin-2D mip layout: tiled_mip_level_layout(element_width, element_height, ...), which has no depth term. That causes two errors:
The level offset is wrong. Every level of a 3D chain spans w*h*d bytes, not w*h, so the byte offsets that the 2D helper computes from the per-level sizes do not describe a 3D chain. 3D swizzle modes also use thick blocks, which the helper does not model.
The depth is not shifted. Level 1 of a 32^3 volume is 16x16x16, but the view keeps depth 32. The new test asserts depth == 32 at BASE_LEVEL 1, so it pins the defect instead of catching it.
The result is a supported view that reads level-0 texels for any shader selecting a smaller level. That is a silent wrong picture, which is worse than today's visible refusal.
#4833 pins the correct current behaviour: the nonzero-BASE_LEVEL 3D views stay refused until a 3D mip layout exists. That PR is being merged. Admitting these views needs a real 3D (thick) mip-level layout that takes depth as an input and a halved depth per level, tested against a known placement. That is a larger change than this one.
