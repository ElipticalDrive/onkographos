Currently, textures are just a single image from the point of view of the render module. Sprite components consider texture as regular grid of tiles, which allow some batching an the sprite shader tries to be a bit smart about texture filtering to avoid color bleeding.
We should support texture atlas in the render module. A texture atlas give access to several "virtual" textures, that can themselves be composed of several images. Atlas images don't need to have the same size. That way, we can simplify sprite and bitmap font rendering, make code more generic, implement smarter texture filtering and put images of different size in a single atlas to improve batching.
This raises questions about texture filtering. Lair already contains a script to pack several images together. It is able to add a 1px margin around the image so that we don't need complicated tricks for filtering while supporting transparent border, clamp and repeat texture. However, this approach do not work with mipmapping.
It is not clear that supporting mipmapping with texture atlas is necessary. Their main use is to display 2D graphics that are generally at the right size. Anyway, mipmapping usually give poor result in this use case. For 3D graphics, textures have generally power-of-two sizes and we could just group them by size in texture arrays.
