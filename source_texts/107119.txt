Transmission samples the opaque scene copy at the refracted exit point without checking depth, so anything between the camera and a glass surface gets pulled into the glass as a ghost.
Live demo (source modules via jsDelivr, WebGPU): issue on dev vs this PR.
getIBLVolumeRefraction() now reads viewportDepthTexture() at the refracted coordinates and falls back to the unrefracted coordinates when that depth is closer than the surface, with a short blend (a tenth of the transmission distance) to avoid seams. Godot uses the same guard. Side effects: objects inside a double-sided volume are refracted once instead of twice, and in webgpu_loader_gltf_transmission and webgpu_caustics the olives and the duck's head no longer bleed into the glass next to them (screenshots updated).
Cost: one depth sample per fragment, three with dispersion, plus one depth copy per frame while a transmissive material is visible.
This also fixes a pre-existing bug the change exposed: standalone depth textures took their sample count from currentSamples, which is 0 while the frame buffer target is active and stale during async pipeline creation after compileAsync(), so the texture could end up multisampled while the binding was not (bind group validation error, e.g. in webgpu_loader_materialx). Renderer.framebufferSamples now reports the sample count of the framebuffer that copyFramebufferToTexture() reads from.
WebGLRenderer is not covered, its transmission target has no resolved depth.

The solution does not work with enabled stencil buffer: https://jsfiddle.net/2voyq561/
A runtime error occurs:
THREE.WebGPUBackend: copyFramebufferToTexture: Source and destination formats do not match.", "depth24plus-stencil8", "depth24plus"
That's because viewportDepthTexture() is just a default depth texture meaning depth24plus. As soon as the the default framebuffer uses a different depth texture configuration, transmission would fail:
Post-processing with reversed depth buffer because pass node switches to depth32float.
Rendering straight to the canvas (no tone mapping, linear output) with reversed depth buffer.
Any render target set via setRenderTarget() whose user-provided depth texture is not UnsignedIntType.
The copy in viewportDepthTexture() must be adaptive. That was previously a limitation but now it is exposed for each transmissive material and that introduces a regressions.

Every time during the precompilation the control goes back to the event loop, the renderer state is not correctly restored.
