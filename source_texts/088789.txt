What this is
An opt-in presentation inside the native emulator window, driven by the running ROM—not the previous authored HTML scene. libmGBA remains authoritative for game state and inputs. Main remains unchanged until this draft is reviewed/merged.
Decode the live standing-sprite list, OBJ VRAM and palette into cached voxel reliefs; retain the ROM's silhouettes, colors and idle-frame changes.
Generate raised houses, castles, forts and trees from the live terrain grid and decoded palette, with stepped roofs, masonry, timber and blocky foliage. No chapter-specific placements or bundled models.
Keep the original decoded ground texture; add a depth buffer, directional face lighting and contact shadows.
Use the existing full-resolution native overlay, with the original HUD and camera-correct ground/raised-unit picking.
Invalidate caches on state changes; preserve queued world-tile clicks across presentation transitions.
Intentional prototype boundaries
This is local procedural generation, not AI image-to-3D reconstruction. Unit models are sprite reliefs, not fully sculpted 360-degree characters. Terrain/object inference is heuristic and can require profile overrides for unusual hacks.
Voxel presentation currently applies to eligible idle tactical views. Selection/movement ranges, moving-unit rendering, action menus, combat, dialogue, inventory, unsupported HUD layouts and allocation failures use the native presentation, then restore voxels automatically. Full moving-unit/native-effect integration remains follow-up work. CPU cold builds can hitch. This is not a production-ready all-scenes 3D replacement.
Try it
Build this branch normally, then press F7, or launch with --voxel.
[ / ]: orbit. Wheel: zoom. Shift-left-drag: pan. C: focus the real game cursor. Home: overview. Existing emulator inputs remain unchanged; prototype keys do not override existing bindings.
Full controls, generation details, limits and reproducible validation are in docs/voxel-renderer.md.
