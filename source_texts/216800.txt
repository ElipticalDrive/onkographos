Hi, I think the most critical parameters should be the number of training steps and the hash table size. Two fit larger scenes, I would first try to increase those two parameters. And if larger iteration steps are used, those step-related parameters can also be correspondingly increased. (e.g., subdivision milestones of octree)
Reconstructing thin objects is challenging, aliasing could be one of the reasons though I personally would not think it is the main cause. Decreasing the sampling step size or using L2 loss for the color reconstruction loss may help reconstruct thin objects. (In the default setting of f2-nerf, we use something like smooth-L1 loss)
Regarding anti-aliasing, my current idea for that is very naive, and I haven't thought out specific implementation details. The basic idea is to learn a 4D field (XYZ + volume size) instead of 3D field (XYZ) for volume rendering. But I am not sure if it can work well.

Hi, decreasing the sampl_l can reduce the final sampling size.
Also decreasing the train.ray_march_init_fineness (it is a number greater or equal to 1) can reduce the sampling size in the initial stage.
The current implementation performs a coarse-to-fine sampling, i.e., it takes s * sampl_l as the sampling step size, where s is a number initially as ray_march_init_finess as decreases to 1 along the training progression.

Hi, besides decreasing the sampling steps, I think making the culling condition of the octree node more strict may help preserve the thin structures.
Specifically, you can try to increase the constant OCC_ALPHA_BASE in PtsSampler/PersSampler.cu from 32 to 64 or more to make the culling logic of the octree nodes not so aggressive.
The culling logic of the octree can be briefly described as follows: During training, we maintain a counter for each node; for each training iteration, if a ray intersects this octree node, we will first check if the maximal alpha value of the sampled point in this node is less than ABS_ALPHA_THRES. If it is less than the threshold, we decrease the counter by 1, otherwise, we set the counter to OCC_ALPHA_BASE. If the counter is less than zero, we cull out that node.
This is a parameter I would not usually tune, so I made it hard-coded. But for reconstructing very thin structures, I think this parameter OCC_ALPHA_BASE can be increased for a less aggressive culling operation.
