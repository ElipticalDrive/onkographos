An indirect command has the same layout in all three APIs: five words with indices, four without.
Refusals and behaviour changes
A draw is refused, with the stream named, when a stream it reads is unbound or shorter than the vertices or instances it draws.
A draw is refused when a dynamic window has no buffer bound or runs past its buffer.
Setting an offset on a binding that isn't dynamic is refused, and so is an offset that isn't a multiple of the device's alignment.
Compute passes refuse dynamic uniforms.
Behaviour change: a second vertex stream used to be refused at pipeline creation. It is now accepted, and layout_binding instead refuses a stream past 7 or one declared twice, in all three modules. The three *_resources specs are updated to match.
Vulkan internals:
The dispatch barrier now covers DRAW_INDIRECT and INDIRECT_COMMAND_READ, so commands written by a compute pass are visible to the draw that reads them.
buffer_create adds INDIRECT_BUFFER usage.
The dispatch list gains the indirect-draw and query commands, regenerated from registry 1.3.204. vk/module.ae is unchanged.
GPU time ordering: each module records which submission a frame slot holds. Waiting on slots out of order with frames in flight therefore never reports an older frame's time.
Tests
test_{vulkan,d3d12,metal}_draws.ae check every feature against pixels read back. They cover:
instances landing in their own quarter of the target;
a batch drawing instances 2 and 3 only;
a per-vertex stream;
an indirect draw whose instance count a compute pass sets, and then zeroes;
two indirect commands, the second starting at first instance 3;
a non-indexed indirect draw;
two draws reading different blocks of one uniform buffer;
GPU time for a frame, with three frames in flight, and for a dispatch.
The refusals listed above are tested too. CI asserts that each spec ran rather than skipped on Linux lavapipe, Windows lavapipe, WARP, macOS Metal and MoltenVK.
Local results
Vulkan (lavapipe on Windows): passes. Under the Khronos validation layer with synchronisation and best-practices validation on, it reports only the usual small-dedicated-allocation advisories.
Direct3D 12: passes on the GPU and on WARP with 0 debug-layer messages, including with GPU-based validation (AETHER_D3D12_DEBUG=2).
Metal: compiles for arm64 and x86_64 macOS with -Wall -Wextra and no warnings (zig cc). The macOS CI leg is its first run on a device.
Follow-up
Comparison sampling of a target's depth, for hardware shadow-map filtering, is the last item on #2198's acceptance list. It is filed as #2373 and listed under "Not here yet".

contrib.vulkan, contrib.d3d12 and contrib.metal gain the same calls:

- vertex_stream binds a buffer as stream 1..7 at the rate the layout
  declares; target_set_instances and batch_add_instanced set the
  instances drawn. A stream the pipeline reads that is unbound, or
  shorter than the vertices or instances drawn, refuses the draw.
- batch_add_indirect draws commands read from a buffer when the frame
  runs (vkCmdDraw[Indexed]Indirect, ExecuteIndirect, Metal's indirect
  draws), so a compute pass can write them; the dispatch barrier now
  covers the indirect-command read.
- bindings_uniform_dynamic declares a window of one buffer whose offset
  batch_set_offset chooses per draw (dynamic descriptors, a root CBV
  address, a buffer offset); uniform_offset_alignment reports the step.
- target_set_timing / target_gpu_ms and compute_set_timing /
  compute_gpu_ms report the GPU milliseconds of the newest waited frame
  or dispatch (timestamp queries, a timestamp query heap, the command
  buffer's GPUStartTime..GPUEndTime), ordered by submission so waiting
  on slots out of order never reports an older frame.

layout_binding now refuses a stream past 7 or one declared twice in all
three modules; a second stream is no longer refused at pipeline creation.
The Vulkan dispatch list gains the indirect and query commands,
regenerated from registry 1.3.204.

CI asserts it ran on lavapipe, WARP, Metal and MoltenVK.
