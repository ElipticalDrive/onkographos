Closes #1327 (and the requests folded into it from #1497 and #4523: game and modding textures, a compression choice, optional mipmaps, alpha kept).
DDS files have opened since #4255, read-only. This adds the writer, so a texture can be opened, edited and saved back as DDS without a round trip through PNG.
Writing
2D textures, legacy header. Every format written here has a legacy DDS_PIXELFORMAT description, so no DX10 header is needed (or written). The reader still reads both.
Uncompressed (the default, lossless): RGBA as A8R8G8B8 (BGRA), RGB as X8R8G8B8 (BGRX, X written as 255), grayscale as L8, and grayscale with alpha as A8L8. These read back exactly through the existing reader.
BC1 (DXT1), BC2 (DXT3), BC3 (DXT5). The block encoder is our own, written from Microsoft's public block-compression documentation, in the new crates/codecs/src/codecs/dds_bc.rs:
Colour: the two RGB565 endpoints are fitted along the block's principal axis (power iteration on the covariance), then refined twice by least squares on the chosen indices. Each candidate is scored against the exact palette the reader rebuilds, so the indices are the best ones for what a decoder shows.
BC1 keeps alpha as on/off: texels under half opacity become BC1's transparent black (three-colour mode). An opaque BC1 block takes whichever of the four- and three-colour modes fits better. BC2 and BC3 colour blocks are always written in four-colour order (c0 > c1), because older decoders read c0 <= c1 as three colours.
BC2 alpha: 4 bits per texel, rounded. BC3 alpha: whichever of the two modes fits better (eight values between the extremes, or six plus exact 0 and 255).
Edge blocks of a texture whose size is not a multiple of four ignore the texels outside the image.
The palettes are shared with the reader (colour_palette, alpha_palette): the reader's palette code moved into the new module unchanged, and the reader calls it from there. The existing reader tests still pass.
Mipmaps (optional): the full chain down to 1×1, each level a box filter of the level above. On an odd-sized level the last column and row average three pixels, so no pixel is dropped. The header gets DDSD_MIPMAPCOUNT and DDSCAPS_COMPLEX | DDSCAPS_MIPMAP.
Header fields: dwPitchOrLinearSize is the row pitch (DDSD_PITCH) for uncompressed data and the top level's size (DDSD_LINEARSIZE) for BC data.
Fidelity warnings: BC1–BC3 report LossyCompression, and BC1 with translucency reports AlphaBinarized. A 16-bit or float document reports DepthReduced, as for other 8-bit formats. Grayscale and RGB sources are written as RGBA blocks.
Encoding runs one row of blocks per rayon task on native targets, and single-threaded on wasm (the same cfg split as orientation.rs).
DDS is removed from ASYMMETRIC_EXCEPTIONS, and its caps now say write: true.
Where it's exposed
Save As and Save a Copy ask with a small DDS Options dialog, modelled on Targa Options. It offers Compression (None, BC1 / DXT1, BC2 / DXT3, BC3 / DXT5) and a Generate Mipmaps checkbox. It starts at uncompressed without mipmaps. The answer is recorded in actions and replayed without asking. .dds is added to the desktop Save As file types.
Scripts pass ddsCompression (none, bc1, bc2, bc3, or the DXT names) and ddsMipmaps (bool). Either one skips the dialog. They work on:
file.saveAs, file.saveACopy, the batch, Image Processor and Export Layers commands;
control app.save, RPC doc.save;
MCP doc_save/doc_export, headless and through the bridge.
CLI: --dds-compression <none|bc1|bc2|bc3> and --dds-mipmaps on convert, run and batch.
Bad values are refused before anything is written.
The offscreen snapshot example's exporter passes the DDS options too.
To carry the DDS answer through the Save As flow without a second loose parameter next to tga_bits, the Option<TgaBits> threaded through save_as_with / save_to / write_save / write_copy / save_automation_with became FormatChoices { tga_bits, dds }. Targa behaviour is unchanged, and the existing Targa tests pass.

Not in this PR
BC4, BC5, BC7, sRGB DXGI formats, cubemaps, texture arrays and volume textures are out of scope. They need the DX10 header and, for BC7, a much larger encoder. The reader still refuses them, as before.
Export As does not list DDS. Its format list is a curated six, and DPX/FITS aren't on it either.
Save keeps the source compression: a BC3 file opened and saved again starts DDS Options at uncompressed, not BC3. Keeping it would need a new document field (and a .pcraft manifest entry), like the JPEG/WebP source encoding.
Mip filtering averages the stored (gamma-encoded) values, channel by channel, with straight alpha. Linear-light or alpha-weighted filtering would suit colour textures better, but would be wrong for normal maps and data textures, so it would be a choice in the dialog.
The encoder favours correctness over speed and quality extremes: no exhaustive endpoint search.
