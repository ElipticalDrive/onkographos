Level == volume.max() triggers RuntimeError
When the user supplies a level equal to volume.max() (a value that passes the range check on line 179), np.any(volume == level_f32) is True, so the nudge runs and produces a value strictly above volume.max(). Every voxel then satisfies v - level < 0, all cube indices collapse to 0 (no-triangle case), and line 213 raises RuntimeError: No surface found — a regression on valid input.
The nudge direction should be chosen so that the result stays within the volume's range:
```
level_f32 = np.float32(level)
if np.any(volume == level_f32):
    if level_f32 < np.float32(volume.max()):
        level = float(np.nextafter(level_f32, np.float32(np.inf)))
    else:
        level = float(np.nextafter(level_f32, np.float32(-np.inf)))
```

Inaccurate comment about classification direction
The comment says "corner with value == level produces 0.0 which is classified as 'inside'", but the Cython code shows the opposite: a corner's index bit is set only when v - isovalue > 0.0 (lines 440-447 of _marching_cubes_lewiner_cy.pyx). A zero difference is not > 0, so the corner is classified as below the surface (bit NOT set), not "inside". The comment should describe the actual mechanism — that an equal-valued corner is treated as "below", and when the resulting cube index selects a case that generates edges expected by neighbours who do produce triangles, gaps appear at those cube boundaries.
