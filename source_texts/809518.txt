Why
Per user feedback (2026-05-09): "i also need a section box command/agent invokable function/button on the leftside tool palette. i need an equivalent clipping plane set as well."
Two CAD/BIM-standard view-cropping primitives that are currently absent. Both need three entry paths: (1) palette button, (2) dispatch verb (`SdSectionBox` / `SdClippingPlane`), (3) agent-callable few-shot examples in agent-harness.
Scope
A — Section box (axis-aligned 3D crop)
Standard architectural workflow: drop a 3D box around a region; geometry inside is visible, outside is hidden (or alpha-clipped). User drags box edges to refine.
`commands/spatial-api.yaml` — declare `SdSectionBox` canonical:
Args: `min: point3` (required), `max: point3` (required), `enabled: bool` (default true).
Companion: `SdSectionBoxOff` (no args) to disable.
`web/src/main.ts` — `registerHandler('SdSectionBox', args => viewer.setSectionBox(args.min, args.max, args.enabled))` and `SdSectionBoxOff`.
`web/src/viewer/viewer.ts` — implement `setSectionBox(min, max, enabled)`:
Use THREE.js `renderer.clippingPlanes` with 6 axis-aligned planes (one per face of the box).
Persist current section box state on viewer for re-application after view changes.
Also render a translucent wireframe of the box itself so user sees the crop volume.
`web/src/viewer/create-mode.ts` — palette tool entry `section` with `clicks: 2`:
Click 1: corner1 of section box (XY plane).
Click 2: opposite corner. Z range inferred from scene bounds (or default 0..ceiling-height).
Inline numeric chip for fine-tuning min/max + enable/disable toggle.
`web/src/agent-harness.ts` — add 1-2 few-shot examples ("section box around the kitchen" / "crop to floor 2").
B — Clipping plane set (per-axis half-space cuts)
More flexible than section box: arbitrary number of clipping planes, each with its own normal direction. Standard for floor-plan cuts, sectional views, exploded inspections.
`commands/spatial-api.yaml` — declare `SdClippingPlane`:
Args: `origin: point3`, `normal: vector3`, `enabled: bool` default true, `label: string` optional.
Companion: `SdClippingPlanesClear` (clear all), `SdClippingPlaneRemove({label})`.
`web/src/main.ts` — handlers wire to viewer.
`web/src/viewer/viewer.ts` — `addClippingPlane(origin, normal, label?)`:
Push a `THREE.Plane` onto `renderer.clippingPlanes`.
Store labeled set so `SdClippingPlaneRemove` can target by label.
`web/src/viewer/create-mode.ts` — palette tool entry `clip` with `clicks: 2`:
Click 1: origin of plane.
Click 2: target point — vector (target - origin) becomes the plane normal.
Or: 1-click + popover with axis selector (X+/X-/Y+/Y-/Z+/Z-) for axis-aligned cuts.
`web/src/agent-harness.ts` — few-shot examples ("cut a vertical section through the model" / "add a horizontal clipping plane at floor 1").
C — Sidebar listing (for cumulative state)
Both features add view-state that the user needs to manage. Sidebar entry under SCENE / VIEW grouping listing active section box + clipping planes with eye-toggle + edit button + remove.
Acceptance
A — Section box
Palette → "section box" tool → 2-click → translucent wireframe box visible at click region; geometry outside box clipped via THREE clippingPlanes
cmdk → "SdSectionBox min=[...] max=[...]" works
Agent prompt "crop the model to a 5m x 5m x 3m box at the origin" → emits SdSectionBox with correct args → box applied
`SdSectionBoxOff` removes the box
Section box persists across mode switches (model ↔ layout) and across view changes (top/iso/perspective)
gemma-verify-raw.mjs new surface `section-box` asserts box state via `window.__viewer.getSectionBox()` (or equivalent inspection API)
B — Clipping plane
Palette → "clip" tool → 2-click OR 1-click+axis-popover → plane visible (translucent grid quad at plane location); half-space culled
Multiple planes coexist (3 cuts simultaneously work; intersection of half-spaces)
cmdk → "SdClippingPlane origin=[...] normal=[...]" works
Agent prompt "add a horizontal clipping plane at z=2.5" → emits correct dispatch
`SdClippingPlanesClear` removes all
gemma-verify-raw.mjs new surface `clipping-planes` asserts active plane count
C — Sidebar
Active section box + clipping planes appear in sidebar (SCENE tab subsection or new VIEW subsection)
Eye-toggle disables/enables without removing
Remove button per entry
