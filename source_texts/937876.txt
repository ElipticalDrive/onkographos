Summary
Initial Stage 0 prototype implementation of Drawn Deep — a 2.5D voxel dungeon-crawler. This establishes the core architecture and rendering pipeline with a hand-authored test floor, player movement with collision, and voxel destruction.
Key Changes
Voxel grid system (sim/voxels.js): Uint8-backed voxel grid with materials (stone, dirt, wood, water, lava, ice), chunked rendering with revision tracking for efficient updates, and exposure culling for mesh generation.
Simulation state & reducer (sim/state.js): Pure functional reducer implementing fixed-timestep movement with per-axis sliding collision, voxel destruction, and chunk invalidation. Player is an AABB with configurable radius and height.
Three.js rendering (render/voxel-mesh.js, render/scene.js): One InstancedMesh per 16³ chunk, rebuilt only when chunk revision changes. Chunks carry world coordinates directly in instance matrices. Height-based color tinting. Raycasting for voxel picking.
Hand-authored test floor (sim/floor.js): 96×16×96 voxel dungeon with perimeter walls, partition wall with doorway, pillars, crate stacks, altars, statue, and water pool. Placeholder for Stage 1 procgen.
Input handling (input/touch.js, input/desktop.js, ui/dpad.js): Touch support with floating virtual d-pad (analog movement) and tap-to-destroy. Desktop: WASD/arrows + mouse click. Shared input state feeds into fixed-timestep Tick actions.
Billboarded player sprite (render/sprites.js): Procedural canvas-drawn wizard character, 10 voxels tall, anchored at feet with smooth camera follow.
Game loop (main.js): Wires simulation, rendering, and input. Fixed 60Hz timestep with variable frame rate. HUD shows floor number, voxel count, and FPS.
Notable Implementation Details
Architecture: /sim is pure and imports nothing outside itself — enables future server portability. All state mutation through reducer(state, action) => newState. Actions are serializable.
Chunking strategy: Voxel destruction touches 1–7 chunks (own + face neighbors) instead of rebuilding the whole world. Frustum culling disabled for now (wrong bounds on unit cube geometry); acceptable for current floor sizes.
Collision: Full-body AABB check iterating every voxel level the player occupies, with per-axis sliding so the player slides along walls rather than stopping dead.
Seeded RNG: sim/rng.js provides deterministic randomness for future procgen. Seed threaded through state.
No build step: Static site with ES modules and Three.js via importmap. Runs on any HTTP server.

Doc revision: drop the 'logical cell' framing throughout. There is no
intermediate cell grid the runtime sees — the world is a 3D voxel grid
end to end, procgen carves directly into it, movement and spell shapes
are continuous floats. New "Voxel scale" subsection anchors the
established dimensions (10-tall character, 14-tall walls, 3-thick
walls, 4+ wide corridors). Floor target rephrased as 200-400 voxels
per side rather than 60-100 cells.

Chunked meshing: split the world into 16^3 chunks, one InstancedMesh
per chunk. The reducer now bumps a per-chunk revision counter
(state.chunks.revisions) for the chunk containing each modified voxel
plus any chunk-neighbours sharing a face with it (their edge voxels'
exposed-face status depends on the change). The renderer keeps a
parallel lastChunkRevisions array and rebuilds only chunks whose
counter advanced.

Net result: a single voxel destruction touches 1-7 chunks (typical 1-2)
instead of rebuilding the whole grid. AOE that destroys 50 clustered
voxels still touches only a handful of chunks. Mesh rebuild cost is
now constant per voxel changed, not O(grid).

Raycast picking moved from a single InstancedMesh to per-chunk meshes
via a shared Group; voxelFromHit() decodes 4-bit chunk-local coords
packed into a Uint16Array on each chunk handle.

Frustum culling left off for now — chunk InstancedMeshes have wrong
default bounds. Cheap to fix when floor sizes pass ~256 per side.
