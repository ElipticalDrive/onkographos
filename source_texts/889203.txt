SIR-HIZ-001 — GPU-driven Hi-Z visibility roadmap
Canonical tracker for SIREngine's renderer-neutral Hi-Z occlusion subsystem, GPUScene culling/compaction, native indirect draws and rendering-method integration. Tasks are issue-linked below; completion requires source-bound evidence rather than the existence of this plan.
Baseline and evidence
Development branch: feature/hiz-00-visibility-foundation, commit ad13fa0c, forked from develop 51666fad.
Existing: SIRVisibilityFoundation.{h,cpp} provides reverse-Z CPU mip generation, conservative projected-rectangle tests, history eligibility, API/mode validation and bounded reference compaction. CTest is registered as renderer.visibility.foundation.
Still to verify: genuine full repository CMake object/link/CTest and authentic source/configuration coverage on the committed candidate. Previously reported local 100% coverage was for the isolated reference implementation, not the engine or GPU shaders.
Not implemented: FrameGraph, rendering-method compiler, GPU Hi-Z shaders, GPUScene/indirect draw execution, temporal two-phase recovery, virtualized cluster hierarchy, native hardware tests.
Branch design: FrameGraph is deliberately deferred as a separately scheduled project. The Hi-Z contracts must remain graph-independent until that integration is authorized.
Required architecture
Render method / pipeline compiler: declarative method recipes and visibility policies, not duplicated culling ownership.
SIRVisibility: shared depth-pyramid algorithms, frustum/LOD/Hi-Z, temporal recovery, GPU candidate compaction and visibility result ABI.
GPUScene / SceneCooker: stable instance IDs, bounds, transforms, cluster hierarchy and cooked/dirty GPU records.
FrameGraph (future): pass edges, depth producers, barriers, queue waits and transient aliasing, consuming visibility pass declarations.
GRDG: canonical persistent identity/revision, residency and publication. Native device: sole GPU allocation, descriptor, PSO and execution owner.
Backend lowering: D3D12 ExecuteIndirect, Vulkan indexed indirect count, GL 4.6 qualified multi-draw indirect. Fallbacks obey the same cooked semantics.
Common coordinate contract: reverse-Z depth, conservative Hi-Z reduction of all source texels, viewport/NPOT/MSAA/format treatment, safe history invalidation, sealed-memory resource lifetimes, no CPU visibility readback in the standard GPU path.
Dependency-ordered stages
HIZ-00 — independently compile, validate and freeze the reference foundation (already partially implemented).
HIZ-01 — rendering-method + FrameGraph declaration contracts (deferred / separately scheduled).
HIZ-02 — shared native GPU capability/indirect/synchronization primitives.
HIZ-03 — canonical reference GPU reverse-Z depth pyramid and history backing.
HIZ-04 — cooked GPUScene candidates and instance/frustum/LOD pass.
HIZ-05 — conservative GPU Hi-Z tests, visible/rejected queues, indirect argument compaction.
HIZ-06 — temporal two-phase disocclusion recovery and final history publication.
HIZ-07 — Forward+, Deferred and one fully custom rendering-method integration (requires HIZ-01).
HIZ-08 — profile-driven optimized variants: SPD/fused Hi-Z, subgroup compaction, cluster hierarchy and optional mesh tasks.
HIZ-09 — cross-platform production acceptance, correctness, source/coverage and hardware performance.
Dependency rule: HIZ-02/03/04 and offline shader tests may progress without FrameGraph. GPU end-to-end method composition waits for HIZ-01; no alternative embedded pseudo-FrameGraph is authorized.
Release gates
Functional: reference and GPU kernels match under randomized/NPOT, reverse-Z, depth edge, moving camera/occluder, camera cut, resize, origin shift and scene revision.
Safety: zero false-occluded geometry in oracle scenes; no out-of-capacity writes; invalid or missing history fails open.
Resource: generation-checked GRDG/provider references, no in-flight reuse, correct per-queue completion, bounded resident backing and explicit device-loss recovery.
Performance: timestamped pyramid/cull/compaction and full-frame p50/p95/p99 across urban, terrain and open scenes; optimize only after comparing complete frame time with an uncullled reference.
Source quality: SIREngine global-namespace C++17/style contract, pinned formatter, native CMake object/link/CTest, GoogleTest where enabled, 100% line/branch/function coverage for locally compilable owned CPU logic, shader differential and native integration tests. CI and real GPU verification tracked separately.
References: HIZ-00 committed architecture contract · shared rendering device · shared graphics types.

HIZ-03 — GPU depth pyramid and history — [HIZ-03] GPU reference Hi-Z pyramid, depth imports and history images #59
HIZ-04 — GPUScene candidates and frustum/LOD — [HIZ-04] Cooked GPUScene candidate records, stable IDs and frustum/LOD culling #60
HIZ-05 — conservative Hi-Z, compaction, indirect results — [HIZ-05] Conservative GPU Hi-Z tests, compaction and indirect draw argument output #61
HIZ-06 — temporal disocclusion recovery — [HIZ-06] Two-phase temporal occlusion, disocclusion recovery and history lifecycle #63
HIZ-07 — Forward+/Deferred/custom method integration — [HIZ-07] Integrate visibility service with Forward+, Deferred and custom rendering methods #65 (depends on HIZ-01)
HIZ-08 — measured shader/hierarchy optimizations — [HIZ-08] Benchmark and qualify optimized Hi-Z reduction, compaction and hierarchy kernels #73
HIZ-09 — coverage and native production acceptance — [HIZ-09] Production verification, coverage closure and cross-backend acceptance #74
Implementation waves and handoffs
Wave A (current): #56 (freeze/verify) → #58, #59 and #60 (native primitive, Hi-Z and scene contracts with gated dependencies).
Wave B (GPU behavior): #61 → #63 (reference parity first, then temporal recovery).
Wave C (deferred integration): #57 → #65 (rendering-method/FrameGraph integration on the separate approved schedule).
Wave D (qualification): #73 → #74 (measured optimization and production acceptance).
Do not merge HIZ phases solely on issue status; require the per-issue acceptance evidence and compare exact branch ancestry.
Virtualized geometry capability seam (2026-11-04)
Shared virtual geometry core is #36; universal hierarchy/LOD/draw plan #269. This Hi-Z roadmap owns only the qualified GPU occlusion acceleration, not the canonical cluster hierarchy or page demand. Fixed-function and CPU-driven GL1.2/1.5/2.x/3.3 or D3D7–10/11 downlevel use conservative CPU cull/BSP/PVS/optional legacy hardware occlusion queries; no modern Hi-Z is mandatory for complete-group LOD selection. GPU outputs must preserve surface coverage and legal root fallback when Hi-Z history is stale/invalid; no second streaming/scene/page registry.
