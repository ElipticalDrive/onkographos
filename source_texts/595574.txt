This pull request adds three new creative volumetric features to voxelizer-rs:
Hollowing (--hollow <thickness>): Instead of a solid object or just the immediate surface, this creates a shell of the specified thickness. It does this by keeping voxels where the SDF is between 0.0 and -thickness.
Molding (--mold): This generates a negative space representation of the mesh. It keeps voxels that are outside the mesh (SDF >= 0.0), effectively creating a mold.
Porosity (--porosity <factor>): This introduces a procedural sponge-like texture. It uses a deterministic, fractional sine-based hash of the voxel's coordinates to randomly discard particles based on the provided probability factor (0.0 to 1.0).
These features are implemented directly in the core voxelization loop by filtering the computed SDF values and coordinates, ensuring high performance. All existing tests have been updated, and new unit tests have been added to verify the specific behavior of each new feature. The code has been formatted, linted, and benchmarked to ensure no regressions.

Pad bounds when voxelizing molds
When --mold is used without --narrow-band, the grid remains the tight mesh AABB because only narrow_band expands bounds_min/bounds_max. For a watertight convex mesh such as a cube, all sample centers inside that AABB are inside the mesh, so this sdf >= 0.0 filter keeps zero particles and formats like .vox then fail on an empty export; the mold mode needs its own exterior padding/thickness or should require one.

Reject invalid hollow and porosity parameters
The public voxelize API accepts the new hollow and porosity values without the validation used for resolution and narrow_band (and the CLI also accepts invalid --hollow values). A negative or NaN hollow thickness silently produces no hollow particles, while porosity values outside 0.0..=1.0 can drop every particle or none, so typoed experiment parameters can generate corrupt outputs instead of a clear error.
