Adds splat train <project>, an end-to-end 3D Gaussian Splatting trainer running entirely on Vulkan compute (GLSL → SPIR-V), vendor neutral, no CUDA.
Loads project/sparse/0 and images/, undistorts images on load so M3's SIMPLE_RADIAL cameras work, and initialises Gaussians from the sparse points.
Forward: depth-sorted splats (existing radix sort) binned into 16×16 tiles; each tile composites its own pixels with transmittance, no blending hardware.
Loss: 0.8 L1 + 0.2 D-SSIM.
Backward: hand-derived gradients for position, scale, rotation, opacity and SH. Float atomics where available (VK_EXT_shader_atomic_float), fixed-point integer atomics as the fallback.
Optimiser: Adam with the 3DGS paper's learning rates.
--holdout N keeps views out of training and writes preview_holdout.png (render left, ground truth right). Output is project/splat.ply, viewable with splat view.
No densification yet (M5), so results are blurry by design.
Testing
55/55 tests pass on the Steam Machine (RADV NAVI33, GCC 16).
Gradient checks:
CPU reference vs finite differences: cosine 1.000000 for all five parameter types (checked in a mode without the 3σ / alpha 1/255 cutoffs, which break finite differences; threshold 0.999).
GPU vs CPU reference: cosine 1.000000, length ratio 1.00000 with float atomics; fixed-point path cosine ≥ 0.9996, length within ~2.3% (forced on this GPU, not tested on hardware that lacks float atomics).
Compute forward vs the existing graphics renderer: mean difference 0.19/255.
End to end on 40 synthetic 800×600 views, 3000 iterations, 1934 Gaussians: 24.68 dB PSNR on training views, 24.02 dB on 8 held-out views, 18 it/s (165 s total). Overfit test at 128×96: loss 0.295 → 0.042 in 400 iterations.
Not tested: real footage, resolutions above 800×600 (SSIM is likely the main cost; a separable filter is the obvious optimisation), Vulkan validation layer (not installed on the machine), Windows and CI. cli_train needs a GPU or lavapipe.
Known limits
Gaussians never split or multiply until M5.
For SH degree > 0 the gradient ignores the view-direction change from moving a splat (default degree is 0, so not yet relevant).

`splat train <project>` starts from the sparse points and runs, in compute
shaders only: tile-binned forward compositing, L1 + D-SSIM, a hand-derived
backward pass down to every parameter, and Adam. Gradients use float atomics,
or fixed-point integer atomics on GPUs without them.

src/train/reference.cpp holds every kernel again on the CPU. The tests check
it against finite differences, and the GPU against it. No densification yet.
