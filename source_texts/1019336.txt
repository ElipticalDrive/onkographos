# Training-Time Gaussian Merging for Compact 3D Gaussian Splatting

Reference implementation of **training-time Gaussian merging**: instead of merging splats
*after* a model has converged (the usual simplification pipeline), pairs of splats are
merged **inside the optimisation loop**, and the model keeps training for thousands of
iterations afterwards. The later iterations absorb the error introduced by merging, which
is what makes aggressive compression survive.

Two integrations are provided:

| path | trainer | status |
|---|---|---|
| `fastgs/` | [FastGS](https://github.com/fastgs/FastGS) (CVPR'26, accelerated 3DGS) | integrated, measured |
| `vanilla/` | [3DGS](https://github.com/graphdeco-inria/gaussian-splatting) (Kerbl et al. 2023) | integrated, measured |

Both share the same merge operator: kNN candidate pairs → pairwise merge cost → budgeted
disjoint matching → **MPMM** (moment-preserving Gaussian mixture merge) → in-place write-back
plus Adam-state compression. Merging is implemented as a *row overwrite + prune*, so no new
parameters, no extra storage layout, and no change to the rasteriser are needed.

## Results

All numbers below are measured on the same `--eval` test split with the official
`render.py` / `metrics.py`. Post-hoc baselines start from the **same trained checkpoint**;
ours is trained from scratch (a training-time method cannot consume someone else's
checkpoint — this is stated explicitly rather than hidden).
