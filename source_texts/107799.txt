Summary
API (vgpu): adds gpu.texture() for standalone 2D/3D/array textures with sampled + storage usage defaults, and teaches set() to bind texture_storage_* declarations from core Textures with usage, format and dimension validation. Documented in texture.docs.md, gpu.docs.md and compute.docs.md; covered by mock tests and a Dawn regression that writes a 3D storage texture from compute and samples it from a fragment shader.
Docs example atmosphere: a physically based sky after Hillaire 2020 (transmittance, multi-scattering, sky-view and aerial-perspective LUTs; the last two as compute passes writing 2D/3D storage textures through the new API), ozone, a limb-darkened sun with transmittance-tinted glare, a raymarched terrain with aerial perspective and cloud shadows, haze/exposure/altitude controls, AgX/ACES/neutral tone mapping.
Volumetric clouds in the same example: tileable Perlin-Worley shape and Worley detail noise generated by compute into 3D storage textures, a weather map, a half-resolution raymarch with coarse/fine stepping, a six-octave multiple-scattering approximation, planet shadow and sun transmittance from the atmosphere tables, aerial perspective at the mean cloud depth, and a depth-aware bilateral upsample in the present pass.
Verification: apps/docs/scripts/render-atmosphere.mjs renders any preset/override headless with LUT debug views; thumbnail metrics validate the noon zenith is blue, the golden-hour horizon is warmer than noon, and moving the sun changes the sky; a mock-adapter test exercises the frame graph and the LUT rebake phases.
Test plan
pnpm typecheck, pnpm test:fast, pnpm docs:verify-snippets

render-example-thumbs.mjs --check --only atmosphere reproduces the committed thumbnails on lavapipe
Follow-up planned on this branch: make target.depth sampleable (small API change) ahead of a mesh-based terrain experiment.

…
d5895cf

Depth attachments are created with texture_binding usage so later passes can
read them. A texture_depth_* binding accepts target.depth or the Target itself,
rejects targets created without depth with a fix-it, and binds depth-stencil
formats through a depth-only view. Samplers paired with depth textures are
declared non-filtering in the bind group layout, which WebGPU requires. Docs
describe the compatibility-mode restriction to comparison sampling; covered by
mock tests and a Dawn test that writes depth with a draw and reads it back with
textureSampleCompare.

The cloud pass now re-marches one texel per 4x4 block each frame (Bayer order)
and reprojects the other fifteen from the previous frame's buffer using the
previous camera basis, with ping-pong targets from gpu.pingPong(). The step
budget falls from 128 near the horizon to 64 near the zenith. Stills and
thumbnails render sixteen frames so every texel converges; output is unchanged
and the cloud pass drops about 3x on lavapipe (118 -> 39 ms at 960x540).
