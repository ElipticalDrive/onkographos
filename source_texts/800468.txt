Splits Stage 2 in two. This PR is the half that doesn't need object identity or a sparse SDF: profile-based cookie cutters and live mirror symmetry. The harder half (wire cutter → cut into multiple objects → merge → sparse SDF migration) lands in a follow-up PR stacked on this one.
Base branch is the Stage 1 branch so the diff is Stage 2's first half only.
What's in this PR
Profiles (DESIGN §2.7 made concrete). A Profile is a 2D SDF. Four analytic profiles ship with Stage 2:
Circle { radius }
Square { half_side }
Hexagon { radius } (inradius; standard IQ hex SDF)
Star5 { outer, inner_ratio } (five-pointed, IQ formula)
extrude_profile(profile, origin, axis, half_length, p) turns a profile plus an extrusion axis into a proper 3D SDF with exact euclidean distance outside. This is the tool geometry underlying the cookie cutter, and it's the base primitive rollers and scrapers will use in later stages (revolve and sweep just swap the operator).
Cookie cutter tool. CookieCutter is a profile extruded along the surface normal at the click point, applied as CSG subtraction. Unlike the finger, it does not displace material — cookie cutters remove cleanly (DESIGN §5 decision 1). apply_cookie_cutter_with_callback follows the same shape as apply_sphere_brush_with_callback so the existing undo journal picks it up without changes.
Tool palette. ToolKind is now an enum. Number keys pick the tool: 1 finger, 2..5 cookie cutter (circle, square, hexagon, star). [ / ] adjusts size regardless of tool. Cookie cutter is one-shot on just_pressed — a slow drag doesn't chain cutter stamps.
Mirror symmetry. SculptSymmetry resource with enabled = true by default (matches DESIGN §9 decision 5). Every stamp is applied twice: once at the primary contact, once at the reflection across the piece-local X = 0 plane. Both position and press direction are mirrored so the magic-clay bulge behaves symmetrically. Toggle with S.
Verified end-to-end
Scripted mouse/keyboard on the cloud VM's TigerVNC display. Debug logging (removed before this commit) confirmed each frame's press produces one primary contact and one mirrored contact in piece-local coordinates.

Profiles: a 2D signed distance function is a first-class object.
Four analytic profiles for Stage 2:

  Circle    { radius }
  Square    { half_side }
  Hexagon   { radius }              inradius; standard IQ hex SDF
  Star5     { outer, inner_ratio }  five-pointed, IQ formula

Each carries an exact euclidean 2D SDF (negative inside, positive
outside), a bounding_radius() for AABB culling, and a short label
for the tool-name display.

extrude_profile(profile, origin, axis, half_length, p): the general
'profile extruded into 3D along an axis' SDF. Basis for the plane
perpendicular to the axis is chosen deterministically and stays
well-conditioned when the axis is near ±X. Combines the 2D profile
SDF with the axial clip via the standard finite-extrusion formula
(IQ), preserving exact euclidean distance outside.

CookieCutter: the first tool built on top of the profile system.
Applied as a CSG subtraction. Unlike the finger brush this does
NOT displace material — cookie cutters remove cleanly, matching
DESIGN §5 decision 1 ('displacement vs. removal is per-tool'). It
does honour the same workbench_y clip as SphereBrush, which is
mostly defensive since subtraction can't create material anyway.

apply_cookie_cutter and apply_cookie_cutter_with_callback follow
exactly the same shape as apply_sphere_brush / _with_callback so
the app can treat cutter strokes the same as brush strokes when
feeding the undo journal.

Tests:
  circle_sdf_is_zero_on_the_boundary
  square_sdf_is_negative_inside_positive_outside
  hexagon_sdf_is_symmetric (6-fold check at ±60°)
  star5_has_inner_corners_negative
  extrude_matches_profile_along_axis
  extrude_clips_beyond_the_axis_range
  circle_cutter_removes_a_cylindrical_channel
  square_cutter_removes_a_square_channel
  cutter_workbench_clip_is_respected

19 sculpt-core tests total, all passing.

Not in this commit:
- Revolve and sweep operators (for rollers and scrapers, later).
- Cutter tool integration into the app (next commit).
- Symmetry, wire cutter, weld, sparse SDF migration (Stage 2
  continued, in follow-up PRs).

Two Stage-2 features that don't need object identity or a sparse
SDF, so they land ahead of wire cutter / merge / migration.

sculpt-core:
- Profile::resized(size) — return a profile of the same family
  with a fresh characteristic size. Lets the app share a single
  'current size' knob across all cutter shapes.
- Small clippy fix on a star SDF coefficient literal.

sculpt-app::sculpt (rewritten):
- ToolKind enum: Finger or Cutter(CutterFamily). CutterFamily
  covers Circle, Square, Hexagon, Star5 for now; adding more
  shapes is just adding a variant.
- SculptTool: kind + shared size knob + finger-specific advance
  and displace. [ / ] adjusts size regardless of active tool.
- SculptSymmetry resource with enabled=true default (matches
  DESIGN §9 decision 5). Piece-local mirror plane at X = 0.
- Number keys 1..5 pick the tool: 1 finger, 2 circle, 3 square,
  4 hexagon, 5 star. Selection is logged.
- Cookie cutter is one-shot on LMB just_pressed rather than
  continuous on LMB pressed, so a slow drag doesn't accidentally
  chain cutter stamps.
- Cookie cutter axis = surface normal at the click; half_length
  spans the grid so the cut goes all the way through the piece,
  matching how a real metal cookie cutter works.
- apply_at() helper encapsulates 'stamp at this position with
  this tool, feed the stroke recorder'. Called once for the
  primary contact and once mirrored when symmetry is on.

sculpt-app::main:
- Log filter tuned to keep wgpu / naga chatter down (wgpu=warn,
  naga=warn).
- Help block updated with the tool palette and symmetry toggle.

README:
- Split the controls table into 'camera', 'sculpting', and 'tool
  palette' groups now that we have more than one tool.

Not in this commit:
- Wire cutter / cut into multiple objects / merge (needs object
  identity — next PR).
- Sparse SDF migration (needs the above and its own PR).
- Ghost tool preview (Stage 2 UX polish; nice-to-have).

The wgpu OpenGL-ES backend logs several 'assumed view dimension'
messages at ERROR level during renderer initialisation. They're
informational, not actual errors — but they scare people running
the app on any headless / software-rendered display (cloud VMs,
Wine, some Linux setups without a real GPU).

Targeted filter: 'wgpu_hal::gles=off' silences only the gles
target. Real wgpu warnings from other backends still surface.
macOS (Metal) and Windows/Linux with Vulkan never emitted these
in the first place.

Tune magic clay: stronger press bulge + recruitment-based pull
…
8d44a19
```
Field feedback from a real user session:
  'push/pull feels more like eraser and add-material than clay'

Stage 1 parameters were on the conservative side and Pull had no
displacement at all, so pull literally WAS 'add material from
thin air'. Two changes here:

1. Bump the press bulge constants:
   BULGE_THICKNESS_FACTOR   0.45 -> 0.60   (wider ring)
   BULGE_INTENSITY_FACTOR   0.18 -> 0.32   (~1.8x taller pile-up)
   Both live inside a single frame's stamp; repeated stamps still
   compound, so the perceived rate of pile-up scales.

2. Give Pull the inverse of Press's bulge. Same ring, same weights,
   opposite sign:
     Press: new -= bulge   (material squeezes OUT of the tool into
                            the ring)
     Pull:  new += bulge   (material is RECRUITED from the ring
                            into the pulled bulge)
   This turns Pull from 'grow material from nothing' into 'smear
   material from the surrounding surface', which is what real
   clay does when you lift material outward.

New test: pull_with_displacement_recruits_from_surrounding_surface
verifies that repeated Pull stamps make a nearby-surface probe's
SDF grow (surface retreats) rather than stay put.

20 sculpt-core tests total, all passing.

Tool size: add Shift+scroll and -/= as alternatives, log on change
…
3f7acd9
```
Field report: '[' and ']' are not discoverable and (worse) may not
live at reachable physical positions on non-US keyboards. Bevy's
KeyCode is physical, not logical, so a Danish or German keyboard
maps 'BracketLeft' to whatever key is where '[' sits on US — often
a language-specific letter like 'A ring'.

Three equivalent size-adjustment paths now, so no keyboard layout
leaves anyone stranded:

- '[' / ']' — the classic brush-size convention (US).
- '-' / '=' — same behaviour, on physical keys that are outside
  the alphabetic range on most European layouts.
- Shift + scroll wheel — universal; works with mouse and Mac
  trackpad, and doesn't fight zoom because the orbit-camera plugin
  now yields the scroll wheel when Shift is held.

Every size change logs the new value (e.g. 'tool size: 14.1 mm')
so you get immediate feedback that the input took, without needing
a UI badge. A proper on-cursor ghost preview lands in a following
PR and will show the size directly.

Constants extracted so they can be tuned in one place:
  SIZE_MIN, SIZE_MAX, SIZE_STEP_DOWN, SIZE_STEP_UP,
  SIZE_SCROLL_SENSITIVITY.

STEP_UP = 1 / STEP_DOWN, so 'smaller then bigger' returns you to
exactly the same size.

Camera: orbit_camera_control now checks Shift and skips zoom while
it's held, so Shift+scroll cleanly routes to the sculpt module.

README + main.rs help block updated.
