The entire test rendernig/compositing.py is in the skip list. I am not sure why this would fail in parallel.
Comments:
I looked into this and the test crashes in parallel. It's from a bug that Gunther reported to me a long while back. I wanted to make sure there was a test case in there to record that VisIt crashed, but somebody wanted to get a full pass && didn't want to put in the time to fix it, so it just got skip listed. I've started looking at this. The test crashes the engine when in parallel. Serial, scalable works fine as well as serial nonscalable. The problem is that the zbuffer on nonroot processor is zero after BroadcastImage. I think BroadcastImage is not working where zbuffering is concerned. It broadcasts color and zbuffer info fine. But, when marrying color and zbuffer to produce the output avtImage object, something is going wrong. In looking at the code that constructs the output avtImage object, it just looks like things are done in such a way zbuffer never makes it into the output. The set of classes involved does not make this easy to track down; avtImage, avtImageRepresentation, vtkImageData, avtSourceFromImage, etc. It seems nearly impossible to use these classes to construct an avtImage object from color AND zbuffer data. RenderTranslucent uses avtTiledImageCompositer which does nothing to handle the 'shouldOutputZBuffer' case. No Zbuffer data can be output from RenderTranslucent. When RenderShadows is called next. It fails because the input image is lacking a zbuffer.
