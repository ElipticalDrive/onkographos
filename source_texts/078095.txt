Summary
The current voxel-to-mesh pipeline converts each visible face of every block into triangles and merges block geometry into a per-chunk mesh (VoxelChunk::from_grid). This produces correct geometry but can create many small quads/triangles, increasing vertex/index counts and GPU upload bandwidth. The repository contains a TODO in engine_core/src/scene_builders.rs: "Implement proper greedy meshing before re-enabling smoothing" which remains outstanding.
Why it matters
Greedy meshing (merging adjacent coplanar faces with identical attributes into larger quads) greatly reduces vertex and index counts for voxel terrains, reducing CPU work, GPU upload time, and draw cost.
This is especially important for large worlds and streaming many chunks.
Current state
Face culling is implemented: hidden faces are removed at block level (VoxelGrid::should_render_face, VoxelChunk::extract_visible_faces).
However, there is no greedy meshing / rectangle merging pass. VoxelChunk::from_grid appends extracted block faces directly; grid_to_chunks simply collects chunk meshes without merging.
Goal (what to implement)
Implement a greedy meshing pass that operates per-chunk (intra-chunk) to combine adjacent coplanar faces that share the same merge key (material, double-sided flag, UV mapping, transparency). The pass should be conservative about attributes that affect final shading (normals, UV transforms, AO) to avoid visual artifacts.
Requirements / Acceptance criteria
Correctness
Visual parity: small test cases (islands, plateaus, cliffs) must render without incorrect seams or shading artifacts.
Transparent materials must not be merged with opaque neighbors; transparency must be part of the merge key.
Performance
Achieve a significant vertex/index reduction (typical target: 4×–10× reduction on natural terrain). Measure on representative chunks and report before/after counts.
Tests
Unit tests for rectangle packing (maximal rectangle detection) on synthetic 2D masks.
Integration test: For a small heightmap, compare indices/vertices before/after; assert reduction and expected values for a golden fixture.
Non-regression
Keep pipeline deterministic and add regression test(s) that validate packed geometry for a known input.
Design notes and implementation plan (incremental)
Stage 0 — Prep (refactor)
Introduce a mesh_builder module (or voxel::mesher) with a MeshBuilder trait and two implementations: NaiveMeshBuilder (current) and GreedyMeshBuilder (new). This lets you toggle behavior for testing.
Stage 1 — Face extraction (already present)
Use VoxelGrid::get_visible_faces and the existing per-face extraction to produce a sliceable representation per-block. Optionally convert these into a Face struct (axis, dir, x,y,z, material_id, flags, uv_index).
Stage 2 — Greedy meshing pass (single-chunk)
For each axis (X, Y, Z):
For each slice perpendicular to that axis, build a 2D mask / grid where each cell holds an optional face_key or None.
Run maximal-rectangle detection in the 2D mask to find contiguous runs of identical keys (the "greedy" step).
Emit MergedFace entries for each rectangle (origin, size, axis, dir, key).
Stage 3 — Finalize geometry
Convert MergedFace entries into vertices/indices (triangulate quads), compute UVs, and generate per-vertex normals.
Optionally compute simple ambient occlusion per-vertex (corner-occlusion approximation) if desired.
Stage 4 — Tests and measurement
Add unit tests for the rectangle finder with edge cases (holes, L-shapes, single cells).
Measure vertex/index counts and time for representative chunks before/after.
Edge cases & cautions
UV mapping: If a material uses non-uniform UV transforms per-block, include UV transform index in the merge key. Merging faces with different UV transforms will produce incorrect texturing.
Smoothing/normals: If smoothing changes per-vertex normals, compute normals after merging (i.e., mesh then smooth) rather than attempting to merge based on smoothed normals.
Chunk boundary merging: Implement only intra-chunk merging at first. Cross-chunk merging can be added later (requires coordination and streaming-aware updates).
Follow-ups
Add a benchmark harness that builds a few representative chunks and prints vertex/index counts and generation time.
Investigate optional cross-chunk merging once intra-chunk is validated?
References & resources
Original greedy meshing article / implementation (Mikola Lysenko): https://0fps.net/2012/07/07/meshing-in-a-minecraft-game/
Example implementations in Rust (search public repos) for reference algorithms.
Use C++ algorithms and convert as a backup?
