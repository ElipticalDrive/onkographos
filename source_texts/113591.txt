Legacy ID: SLAM-5
(proposed).
Replace Open3D VoxelBlockGrid with standalone C++ NVIDIA nvblox (CUDA TSDF/ESDF + Marching Cubes). Bypasses Open3D's ~260k block crash ceiling (BUG-053), uses dynamic voxel hashing with spatial VRAM pruning, releases the Python GIL during mesh extraction, and exposes zero-copy DLPack / __cuda_array_interface__ pointers to roomscan-web. See references/software/frameworkExploration/researchResults.md.

Design spec written + spike run (2026-08-19, Refs #206): docs/superpowers/specs/2026-08-19-slam-native-engine-design.md covers #113 + #114 + #116 as staged gates, no cutover commitment.
#113 measured on 100 real frame pairs (roomSweepFull20260730.bin, median 2200 pts, matched knobs; small_gicp 1.0.1 pip wheel, left installed in host/.venv): at 8 threads small_gicp GICP is ~4× faster end-to-end than the shipped registration (2.19 ms incl. covariance prep vs 9.38 ms) and agrees with Open3D 6dof to 1.9 mm median / 5.9 mm p95; single-threaded, per-frame covariance estimation eats the whole win (11.0 vs 9.7 ms). Open3D's tensor ICP gets slower under default threading at this size (7.4→15.8 ms). Three reframing facts: the shipped translation mode never calls Open3D registration (it's a hand-rolled hybrid_search + numpy solve, odometry.py:278-330); the small_gicp wheel has no rotation-prior/translation-only mode (masks need a from-source build + custom pybind, per the research report's own §7.1) — and this project has measured free 6-DoF rotation losing to the SFLP IMU (17 m vs 0.63 m); and ICP is only ~10 ms of the ~35 ms frame, Amdahl-bounding any win.
Stages: N1 = small_gicp-with-IMU-init inside the real Mapper, ensembles with the null capture as assassin (killed if it fabricates path, or if the real in-Mapper win is <2 ms after the mask work); N2 = nvblox only if the mesh-ceiling spec's chunked path is killed (its VRAM story must beat the free CPU-grid fallback on our actual 8 GiB card — the research report sized against a nonexistent 16 GB); N3 = roomscan-native only if N1 ∧ N2 pass ∧ profiling (tick_share, slam_icp_bench what="ab") blames Python orchestration itself.
