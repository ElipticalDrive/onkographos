The result is intentionally reported as a negative performance result: Metal ordering is exactly correct, but the current synchronous wrapper is slower end-to-end on this runner because wall time includes transient allocations, command encoding, synchronization, readback, and sanity validation.
Performance-aware authority
The interactive viewer now performs three local validation passes per scene/device:
exact CPU/GPU order/depth parity must pass;
comparable end-to-end CPU and GPU-candidate paths are measured;
GPU authority is granted only when median GPU/CPU time is <= 0.95;
otherwise the viewer locks to deterministic CPU sorting for the session and reports the reason;
CPU fallback executes only one sorted visibility pass—no duplicate unsorted culling pass.
This prevents a correct-but-slower GPU implementation from regressing the viewer.

Scientific boundary
This is presentation/runtime infrastructure only. It does not modify captured/rewrite state, Gaussian stable-identity semantics, MPM state, calibration, evidence, certificates, verification, proposal/commit, or rollback contracts.
Research conclusion
The checkpoint establishes a correctness and performance baseline. The next optimization target is GPU residency and synchronization overhead, not depth-key arithmetic: persistent sort buffers, render-command-stream integration, no CPU readback after trust, and tile/radix ordering can now be measured against this baseline.

Research conclusion
GPU ordering is correct at every benchmark size, but the current synchronous Metal wrapper is slower end-to-end on the hosted paravirtual device. The runtime therefore uses a performance-aware authority policy: three parity/performance validation passes are required, and GPU sorting is promoted only if median GPU/CPU time is <= 0.95. A correct-but-slower GPU path remains on deterministic CPU ordering.
This establishes the stable baseline for the next research stage: persistent GPU buffers, render-command-stream integration, removal of trusted-path readback/synchronization, and tile/radix ordering.
Scientific capture/rewrite/evidence/verification contracts remain unchanged.
