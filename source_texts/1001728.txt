What changed
New bartorch.io.read_series(path, *, series=None, phase_range=None) -> Series(image, affine, acquisition, header) for DICOM or NIfTI.
Each image is assigned a part: magnitude, phase, real or imaginary. The checks run in this order: ComplexImageComponent, GE private (0043,102F), Philips private (2005,1011), then ImageType (M/P/R/I, plus Philips values like M_FFE). For NIfTI the order is sidecar ImageType, then the BIDS part- entity, then the file name.
Magnitude and phase (or real and imaginary) are paired into a complex64 image. Siemens stores magnitude and phase as separate series; these are read together when no two series hold the same part.
The parts must agree on geometry, slices, and every timing that both of them state. A timing one part lacks is taken from the other.
Phase is scaled from the span of stored values that equals one turn:
phase_range=, if given.
Otherwise the narrowest common span that holds the data: ±π, ±180, ±1000π, [0, 4096), [-4096, 4096).
Otherwise the span of the stored integer type after rescale.
Otherwise the data's own span.
A warning is raised when the values fill less than 80% of the span used, or overrun a given phase_range. Its purpose is to flag custom reconstructions whose scaling no rule can infer.
New Acquisition record:
per-contrast timings
voxel size and B0 direction in the image's (z, y, x) axes; B0 is assumed to lie along the patient's head-foot axis
field strength, vendor and body part
the phase span used
read_dicom now reads enhanced (multi-frame) MR DICOM frame by frame from the per-frame and shared functional groups, instead of refusing it. The sorting code moved into _stack and is otherwise unchanged.
read_nifti: when a 4D file's sidecar has a scalar EchoTime, it now uses a matching per-volume EchoTimes list if one is present (as in the MGH exports below).
Why
This adds a shared IO layer for downstream packages: fast-qsm's planned CLI, and relaxometry fitting toolboxes built on bartorch. QSM needs:
complex data with correctly scaled phase
echo times
the B0 direction relative to the voxel grid
the body part, so masking can be chosen by anatomy
The user-stated phase range and the low-coverage warning are there because custom reconstructions can scale phase their own way.
Validation
./scripts/lint.sh: ruff, format and codespell are clean.
pytest tests/test_io.py tests/test_io_series.py tests/test_docs.py tests/test_docstrings.py tests/test_namespace.py: all pass, except one skip because lightning is missing. These ran against src/ using the compiled library from the 0.0.17 wheel.
Synthetic tests:
Siemens: separate series, 12-bit, slope 2 / intercept −4096
GE: real and imaginary in one series, told apart by the private tag
Philips: phase in radians, part from ImageType
custom [0, 1000) scaling, with and without phase_range, plus the warnings
phase spanning all of int16
an enhanced dataset compared against its classic frames
BIDS NIfTI files given out of echo order
a 4D dcm2niix-style magnitude with per-echo phase files
an oblique B0 direction
refusals for mismatched parts
Real data from OSF gkemr (ISMRM EMTP harmonization):
MGH dcm2niix exports (Siemens Prisma, local runs 1–3 and bridge runs 1–3). These have heterogeneous file naming, int16 phase that is raw [0, 4095] in one run and [-4096, 4094] in the others, and magnitude without sidecars. All six read with the scaling detected automatically and no warnings. The correct echo times were recovered. Phase matches the QSM-CI packed inputs to 3.6e-7 rad at most, and magnitude to 1e-7 relative. These exports first failed on timings, which led to the second commit.
EMTP QSM-CI packs: Philips Achieva and Elition (KKI, oblique), GE MR750, Philips Ingenia and Siemens Skyra. The complex image matches magnitude·exp(i·phase) to 2.4e-7 relative. b0_direction matches each pack's params.json B0_dir to 1e-4, including the 5–6° oblique KKI scans.
Not covered: the published EMTP and MGH data have no DICOMs, so GE and Philips DICOM part pairing and enhanced DICOM are tested only on synthetic data. The GE odd-slice π phase quirk that qmr-py corrects is not handled.
./scripts/build_docs.sh: the only warning is the missing external/bart/LICENSE, because submodules are not checked out here.
Documentation impact
docs/api/io.md now lists read_series, Series and Acquisition, with a paragraph on how vendors store the parts and how phase is scaled. The read_dicom docstring covers enhanced DICOM, and the read_nifti docstring covers per-volume sidecar lists.
