Part of #68, part 2 ("Light tracer" step). Also fixes a light-tracing regression introduced by #71.
Changes
integrator/LT.h built its rays by hand. All three now use Intersection::SpawnRay (OffsetRayOrigin, based on the hit point's error bound), like the other integrators:
The light ray and each bounce: Ray(isect.mPos + dir * RAY_EPS, dir) → isect.SpawnRay(dir).
The camera connection: Ray(pos, dirToCamera, length) → vertex.mIsect.SpawnRay(dirToCamera), with mTmax set to the distance from the offset origin to the camera.
RAY_EPS is no longer used and is removed from common/Core.h; SHADOW_RAY_EPS stays.
The regression from #71
The camera-connection ray had no offset of its own; it relied on the one the Ray constructor added. After #71 removed that, the ray started exactly on the surface and could hit it again, so the visibility test wrongly reported "occluded". #71 was only tested with the path tracer, so this wasn't caught there.

The light tracer consumes the same random numbers in all three versions, so "before #71 → this PR" being this close means the paths match. BVH and kd-tree give identical light-tracing images.
Testing
Rebuilt Gyunity, GyunityApp and GyunityTest in Debug|x64 and Release|x64 (VS 2026): no errors.
GyunityTest: 45/45 tests pass in both configurations.
Path-tracing render regression (Release x64, 512×512, 64 spp, max depth 8): CornellBoxMesh, CornellBoxMeshWithSlope and EnvironmentMapScene, each with BVHAccel and KdTreeAccel. All six images are byte-identical to the baseline (the path tracer doesn't use LT.h).
Light tracing: see Results.
