Part of #2259 and #2261. Cesium parity roadmap, tier 3.
Problem
I3S scene layers, LiDAR / point clouds (USGS 3DEP, COPC, EPT), and Gaussian splats render through the shared deck.gl overlay on MapLibre and have no globe path. deckgl-viz layers likewise.
Proposal
I3S: the pinned @cesium/engine ships I3SDataProvider, so arcgis-i3s-tiles gets a native branch in CesiumLayerSync with no loaders.gl involvement.
Point clouds: sources already in 3D Tiles form load as a Cesium3DTileset; decoded EPT / COPC / LAS points go into a PointPrimitiveCollection (or are re-tiled into pnts), with pointCloudShading for eye-dome lighting.
Gaussian splats: @cesium/engine 26.2 supports 3D Tiles with the KHR_gaussian_splatting extension (GaussianSplattingExt), so a splat tileset renders through the existing createTileset branch once the layer carries a tileset URL.
deck.gl viz: deck.gl has no Cesium interop; leave it 2D-only, keep the "2D only" badge accurate, and gate the Deck.gl Layer builder on customLayers, which currently has zero consumers.
