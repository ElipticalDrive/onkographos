Saving a 3.3M-splat model to .spz took 11 seconds. It now takes 4.
What changed:
The zstd compression step now uses multiple CPU cores. If zstd has no multithread support it silently falls back to the old path.
The per-splat packing loops run across cores, chunked so the result stays deterministic.
A few large attribute copies became plain memcpys.
Compression level and format are unchanged; the file is within 1% of its previous size and loads back bit-identical (verified tensor-by-tensor against an export from master). SPZ tests pass. The legacy v3 gzip path is untouched.

Exporting 3.34M gaussians (SH3) to SPZ v4 drops from 10.9s to 4.15s in-app.

- compressZstd in the vendored spz library now enables up to 16 zstd
  workers (falls back silently to single-threaded when zstd lacks
  multithread support); level stays 12, file size within 1%.
- packGaussians quantization loops run as deterministic chunked

  previous implementation (verified by hash).

  parallel loop for the wxyz->xyzw rotation swizzle.

all six attributes. SPZ gtests: 24 passed, 1 pre-existing skip. The v3
gzip path is untouched.

Pull request overview
This PR speeds up SPZ export by parallelizing CPU-heavy packing work and switching large per-attribute copies to memcpy, while also enabling multi-worker zstd compression when available.
Changes:
Added a chunked std::thread helper to parallelize per-splat packing loops deterministically.
Replaced several large std::copy loops with std::memcpy for contiguous CPU tensors/vectors.
Enabled zstd multi-worker compression via ZSTD_c_nbWorkers (with fallback behavior when unsupported).
