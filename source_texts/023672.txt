Context
Phase 1 of the voxel destruction roadmap. No simulation yet — just visualize any CSG mesh or analytic primitive as a Minecraft-style voxel chunk pile. Lays the data structures everything else builds on.
Goals
Voxelization algorithm:
For each "object" (analytic primitive or CSG mesh), determine its world-space AABB
Sample a 3D grid at user-specified voxel size (default 0.1 m)
For each voxel center, query SDF (use existing renderer: SDF primitive type (Phase 1 of #96) -- analytic SDFs in AnalyticBvh #97 SDF infrastructure where possible, or build a quick triangle-mesh-to-SDF helper for non-SDF sources)
Voxels with SDF < voxel_size/2 are "inside" the object
Voxel storage:
New VoxelGrid struct: object_id, voxel_size, AABB, packed bitmap of occupied voxels
On-disk format: ad-hoc binary file for caching voxelization results (key: object hash + voxel_size)
Rendering:
Each occupied voxel becomes an analytic box primitive in the renderer's primitive list
Inherit the source object's material at voxelization time
Render via the existing path tracer — no shader changes needed
Cvars + commands:
r_voxel_size — voxel side length in metres (default 0.1)
r_voxelize_demo — when 1, voxelize the current scene's CSG meshes and render them as voxels instead of the original mesh (toggle for A/B comparison)
Console command voxelize_object <id> — voxelize a specific object
Console command voxelize_save <path> — dump current voxel cache to disk
File ownership
NEW: src/destruction/Voxelizer.cpp/h, src/destruction/VoxelGrid.cpp/h, src/destruction/CMakeLists.txt
MODIFIED:
top-level CMakeLists.txt, src/CMakeLists.txt — add subdirectory
src/engine/Engine.cpp — register cvars + commands + integration with primitive list. Surgical.
Do NOT touch: shaders/, src/rhi_, anything outside engine integration
MVP discipline
NO simulation. The "voxelized" object just renders differently — no fracture, no rigid bodies. That's Phase 2.
Single voxel size per object. Adaptive resolution is Phase 3.
No GPU voxelization. CPU job system OK for now; SDF queries are cheap and voxelization is a one-time precompute.
No animation. Source object positions are read once at voxelization time; if the source moves, the voxel grid doesn't follow until re-voxelized.
Acceptance criteria
voxelize_object + r_voxelize_demo 1 renders the source object as a chunky-box pile in the path-traced scene
A 1m³ cube at 0.1m voxel size produces ~1000 voxel boxes that the path tracer renders correctly
Voxelization cache hits speed up repeated voxelization (timer logs delta)
r_voxelize_demo 0 reverts to original mesh rendering — no regression
Hard dependencies
This phase alone has no hard physics dependency (no simulation yet)
Phase 2 of THIS roadmap requires physics Phase 2 (rigid body) to be merged first
What this WON'T do
Actually destroy anything (Phase 2)
Optimize chunk merging (Phase 3)
Fracture patterns (Phase 4)
VFX (Phase 5)
Variable voxel resolution (Phase 3 polish)
Real-time voxelization of moving objects (would need GPU sweep)

Triage 2026-08-26: voxelization + rendering landed; the disk cache is write-only. Leaving open for the cache half.
Landed: src/destruction/Voxelizer.{cpp,h} + VoxelGrid.{cpp,h} (delivered in commit e7f6fa8 "voxelize CSG mesh + render as analytic-box pile (Phase 1)", Copilot follow-ups in 935230f). Cvars r_voxel_size (default 0.1 m) and r_voxelize_demo (default 0) at src/engine/Engine.cpp:782/792. Console commands voxelize_object <id> (CSG root, SDF cluster or sphere prim), plus voxelize_list, voxelize_clear, voxelize_save <dir>. SyncVoxelDemoState swaps the source geometry for the voxel set and back, and is idempotent per generation so the accumulator can still converge while the demo is on. voxelize_object logs dims + occupied count, so the "1 m^3 cube at 0.1 m -> ~1000 boxes" check is directly observable.
Remaining - acceptance criterion 3 ("Voxelization cache hits speed up repeated voxelization, timer logs delta"):
VoxelGrid::LoadFromFile is defined at src/destruction/VoxelGrid.cpp:137 and never called from anywhere in the tree. The only SaveToFile call site is inside voxelize_save (Engine.cpp:22034), and MakeCachePath is likewise only reached from there. So the on-disk format round-trips in principle but nothing ever reads it back - the cache is write-only dead code today.
voxelize_object does not consult the cache at all, and there is no timing instrumentation to log a hit-vs-miss delta.
Also worth noting: there are no unit tests and no golden cell for the destruction subsystem, so nothing pins this behaviour in CI.
Everything else in the acceptance list is met.
