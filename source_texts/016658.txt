Abstract
Scientific visualization enables a deeper insight into the data structure and properties. For Gas and fluid simulations, particularly those resulting from real-world gas captures or Computational Fluid Dynamics (CFD) models, this requires the analysis
and integration of multivariate attributes alongside dynamic temporal variations. We present an ongoing work to develop a
scalable, Out-of-core volume rendering application designed for massive 3D temporal multivariate datasets. Our rendering
framework, called FRIGAS (Fluid Rendering Infrastructure for Gas and Atmospheric Simulations), introduces a novel pipeline
which leverages improvements in Direct Volume Rendering (DVR) techniques for large scale visualizations, addressing constraints regarding temporal structured data and multivariate analysis for interactive spatial and temporal navigation without
HPC resources.

1. Introduction
Nowadays, scientific visualization tools, particularly those for volume rendering, are outpaced the exponential growing size of data.
In the context of computational fluid dynamics (CFD), tools like
Paraview [Aya15] and VTK [SML06] remain widely used, offering
intuitive UIs and robust statistical analysis. However, their rendering engines lack scalability without HPC resources, making them
less suited for 3D temporal multivariate datasets or simultaneous
visualization of large-scale correlated variables on one machine.
Recent works [WBDM23, HHK∗ 24, ABDS∗ 23] have explored
improving accessibility to graphical information without compromises, even on consumer-grade hardware. This poster presents our
ongoing work on developing a scalable, Out-of-core visualization
pipeline designed for large-scale 3D temporal multivariate gas and
fluid datasets. Our approach aims to enhance both visualization and
interactivity, ensuring efficient handling of complex datasets while
maintaining high-performance rendering.

2. Related Works
Volumetric rendering has evolved with advances in GPU computing [Nic07], enabling real-time visualization of large datasets
[SZD∗ 23]. Hierarchical data structures, such as KD-Trees
[VMD08, ZSL18] and octrees [LK11, HHK∗ 24], improve efficiency by subdividing voxel grids, while bricking techniques
[SCRL20] optimize spatial partitioning. Another approach, Dynamic Scheduling [FBM∗ 15], leverages R-Trees [Gut84] to optimize data queries both before and during processing. Out-ofcore rendering provides an effective strategy for managing largescale data uploads using virtual page tables. Initially demonstrated
for 3D datasets on GPUs [SCRL20], this method has since been
adapted for Adaptive Mesh Refinement (AMR) data in 3D + t contexts [ABDS∗ 23]. While these implementations are designed for
single-variable datasets, they rely on a fixed 128-bit per voxel brick
structure due to memory bandwidth constraints. We note that none
of the previous state-of-the-art handle large temporal multivariate
(3D + t + w) datasets, i.e. 3D (x, y, z) grid with t timesteps, where
each voxel is associated with w variables, which can store either
scalar (e.g., temperature or pressure), vectors (e.g., velocity fields)
or tensors. Our contribution aim at extending these approaches
to support efficient simultaneous multivariate temporal access, enabling broader applications and analysis in scientific visualization.

3. Contributions
We propose an adaptive pipeline composed of independent modules for better flexibility, directly implemented into our application called FRIGAS. This approach allows us to contribute on
the Out-of-core while supporting existing improvements made by
[SCRL20]. Indeed, we provide a novel implementation with 3D +t
support on structured grids as in [ABDS∗ 23], as well as providing
multivariate data support for an improved and robust Out-of-core
structure. During our bricking process, the 3D + t + w input data is
subdivided into structured bricks, grouping voxels into fixed-size
blocks (643 as in [SCRL20, ABDS∗ 23]). For multivariate datasets,
we added a step for the user to select d from the w variables to be
visualized. However, the pipeline remains format-agnostic. Thus,
bricks are normalized, converting values into a standardized range.
A Rendering Interface then receives the preprocessed and normalized bricks, loaded onto the CPU and GPU for traversal by the Rendering Engine. Our pipeline is versatile due to its modular conception, through additional rendering modes variants and data preprocessing.
If the Rendering Engine takes advantage of a cache system, it
still shall not directly manage the data. Instead, it receives tasks
as specific rendering and memory requests handled by the CPU
request manager. This distinction is crucial for GPU memory management as an added d dimension can quickly exceed VRAM capacity. The challenge is to join brick-based rendering with GPUefficient data access, while maintaining independence from data
structures and formats, as well as accommodating visualization
modes. This abstraction layer also facilitates external connections,
such as APIs or integration in other applications.
4. FRIGAS: An application of our pipeline
FRIGAS (Fluid Rendering Infrastructure for Gas and Atmospheric
Simulations) implements the aforementioned pipeline and allows
us to experiment with both the Out-of-core architecture and visualization pipeline in Fig.1. The Out-of-core system proposes for
now a set number of variables constrained by the 128 bits memory
bandwidth limit to be loaded dynamically, thus either 4 f loat32
or 8 uint16. Bricks and Page tables retain flags from [SCRL20] to
indicate their state in memory and description. It should be noted
that Bricks are not constrained to a 128 bits limit and preprocessing
uses its own configuration as an independent module. The current
visualization system relies on various rendering modules to handle the variables. These modes are maximum (minimum, mean)
intensity projection MIP (minIP, meanIP), MIDA [BG09], Volume
Rendering (notably joint DVR with 1 to N simultaneous variables),
IsoSurface and 3D properties related projections (Positions, Depth,
Normals...). Frame-by-frame updates are on-demand, by user interactions or temporal requests for interactive temporal and spatial
navigation.
Preprocessing supports custom 3D datasets (BVD, DAT), the
NSDF format [Kla16] and NetCDF files with 3D + t + w data.
Dataset sizes range from GB to TB, with the number of variables
and timesteps varying. Our first dataset consists of 10 ( f loat32)
variables per voxel, which are stored in a NetCDF format with
2005 timesteps on a {61, 61, 81} grid representing smoke evaporation through CFD simulations [BLS15]. A second dataset, derived
from camera-LiDAR methane-based gas captures [YLC∗ 24], contains 8 ( f loat32) gas concentration per voxel on a {72, 32, 44} grid
with 488 timesteps. Our third dataset is a {1536, 512, 512} volume
with 600 timesteps, with memory limits even without the multivariate analysis and up to 3 Gigabytes per variable per timestep.
5. Conclusion and On-going works
In this poster, we showcased our application FRIGAS with its
pipeline. Through its conception, we aim for better flexibility
and scalability in visualization of temporal multivariate large-scale
data. At the moment, FRIGAS handles an Out-of-core temporal navigation of 3D + t + w data processing and visualization,
as well as 3D + t and 3D + w, albeit with a 128 bits limit for
multivariate bricks. Building on [SCRL20], we are enhancing the
multi-resolution page directory’s (MRPD) structure as introduced
in [ABDS∗ 23] with a new format that enables parallel brick loading
with a shared id across d variables. Key areas of experimentation
include loading performance and benchmarking using Out-of-core
and CUDA Zero Copy [NVI00]. Finally, we actively collaborate on
preprocessing support for data formats and welcome discussions on
dataset integration.
