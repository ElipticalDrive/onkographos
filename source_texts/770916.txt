Part of #173 (step 2: per-token cost; the sampler share).
With top_k off (the speech endpoint's default, as in vLLM), sample() sorted every candidate with std::sort: 9.3 ms per token at Orpheus's 156,940-token vocab, about 20% of a 45 ms Vulkan token. It now uses sort_by_logit_desc, an LSD radix sort on the float bits (four 8-bit passes), which gives the same descending order in O(n).
Benchmark (scratch, 200 calls with the endpoint's settings and a 300-token history): sample() 9.3 ms -> 1.6 ms.
The order is std::stable_sort's: equal logits keep their input order. std::sort left that order unspecified, so only exact ties can draw a different token than before. The seed-42 speech WAV is byte-identical on neon and Vulkan.
Independent of perf(audio): batch the speech prompt prefill; report stage timings #201 / perf(audio): threaded conv1d kernels for the SNAC decode #202 (base main). Measured on top of them, the 3.84 s clip on m2 Vulkan: generate 14.3 s -> 11.8 s (22 -> 27 tokens/s), total 15 s -> 13 s.
Test: sort_by_logit_desc equals std::stable_sort (descending, -0 below +0) on 0, 1, 7 and 156,940 candidates with negatives, signed zeros, infinities and many exact ties.
m2 (clang, arm64): build 0 warnings; [sampling] 10 cases, 284 assertions; ~[e2e] 373 cases, 391,081 assertions, all pass.
