Summary
replace the native FastNoiseLite demo-world runtime with the deterministic terrain/chunk streaming stack
synchronously prime and mesh the spawn chunk so player collision exists before gameplay begins
derive the native player spawn height from the loaded terrain instead of a hard-coded Y coordinate
stream surrounding 16×16×64 chunks through ChunkStreamRuntime while keeping SceneTree/MeshInstance3D/StaticBody3D work on the main thread
keep a deduplicated dirty mesh queue and bound chunk installs / mesh rebuilds per frame
remesh horizontal neighbors when chunks arrive or unload so shared boundary faces remain correct
mutate loaded dense chunk bytes in place and dirty only the owning/boundary-neighbor chunks
add headless integration coverage for synchronous spawn-chunk data, mesh, collision, spawn height, mutation, and bounded dirty-mesh processing
Stacked dependency
This PR is intentionally stacked on refactor/godot-chunk-streaming (PR #149). Relative to that base it is two commits / five files: the runtime integration plus a test-lifecycle correction that moves integration assertions after SceneTree activation.
Threading boundary
WorkerThreadPool tasks remain data-only. They generate PackedByteArray terrain and publish it through the mutex-protected streaming runtime. All Node creation, mesh construction, collision shape creation, material/texture work, queueing, and removal happen on the main thread.
Spawn safety
The (0,0) chunk is synchronously generated before the native world becomes playable, immediately receives mesh/collision, and the player is moved above the highest solid/liquid cell at the spawn column. This avoids the common streamed-world failure where the player falls before the first collision chunk arrives.
Validation
The current exact head ed1458a3ee625cf1326947836411b86a7fd6c80f passes native headless smoke, block-state parity, JS↔Godot terrain parity, WorkerThreadPool chunk streaming, streamed VoxelWorld mesh/collision integration, and both Chromium E2E shards.
Current rendering scope
This layer meshes/collides solid blocks only. Water and non-solid vegetation retain their data identities; their dedicated transparent/cross-plane render pass is layered separately in PR #151.
Non-goals
no water/translucent vegetation render pass in this PR
no greedy meshing yet
no persisted edit/state-sidecar restore yet
no multiplayer terrain transport yet
