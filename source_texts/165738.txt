# ABSTRACT

In recent years, Neural Radiance Fields (NeRF) have been used as a map of 3D scene to estimate the 6-DoF pose of new observed images —given an image, estimate the relative rotation and translation of a camera using a trained NeRF. However, existing NeRF-based pose estimation methods have a small convergence region and need to be optimized iteratively over a given initial pose, which makes them slow and sensitive to the initial pose. In this paper, we propose PI-NeRF that directly outputs the pose of a given image without pose initialization and iterative optimization. This is achieved by integrating NeRF with invertible neural network (INN). Our method employs INNs to establish a bijective mapping between the rays and pixel features, which allows us to directly estimate the ray corresponding to each image pixel using the feature map extracted by an image encoder. Based on these rays, we can directly estimate the pose of the image using the PnP algorithm. Experiments conducted on both synthetic and real-world datasets demonstrate that our method is two orders of magnitude faster than existing NeRF-based methods, while the accuracy is competitive without initial pose. The accuracy of our method also outperforms NeRF-free absolute pose regression methods by a large margin.

# 1 INTRODUCTION

The goal of camera pose estimation is to calculate the six degree-offreedom (6-DoF) camera pose from an image captured by the camera. The 6-DoF pose includes the orientation �� and the 3D position �� of the camera relative to a 3D scene. Camera pose estimation is the basis of many tasks, including robot manipulationn[22, 33], simultaneous localization and mapping (SLAM)[6, 27, 37], autonomous driving[9] and virtual reality[12]. Traditional approaches for camera pose estimation usually consist of the following steps: detecting keypoints in the image and matching them with a map represented by a set of images or image features in the 3D scene, and then estimating the 6-DoF pose through Perspective-n-Point (PnP)[10, 14]. However, such methods require a set of images or the pre-computed image features to be stored as a map of the 3D scene, which requires a large amount of storage space and is sensitive to keypoint detection and matching algorithms.

Neural Radiance Fields (NeRF) [23, 25] represents a 3D scene using a multi-layer perceptron (MLP) based network, and has the ability to synthesize the novel view image with a given pose. This makes it possible to store a scene more efficiently and opens up the possibility of using NeRF as a map for camera pose estimation[20]. Pose estimation is the inverse problem of view synthesis in NeRF, and the key issue is how to utilize NeRF for solving this inverse problem. Recently, there have been several attempts of using NeRF for pose optimization[5, 16, 32, 42, 43, 49, 50], and they can be divided into two categories. The first category iteratively optimizes the pose by maximizing the similarity between the rendered image from a trained NeRF and the given observed image[43, 48]. For example, iNeRF[43] takes an initial pose as input and iteratively optimizes the pose by minimizing the loss between the given image and rendered image. The second category utilizes NeRF in the Monte Carlo optimization framework[17, 20]. For example, Loc-NeRF[20] and pNeRF[17] use a trained NeRF to render images around a given initial pose and weight the sampled poses by the

Actually, no existing methods successfully invert NeRF for pose estimation and instead they all rely on synthesizing images from a number of poses, from which the optimal pose are calculated. This brings two problems. First, a large number of image pixels are needed to be rendered to estimate the pose, which is very time-consuming and can not meet the requirements of real-time applications. Experiments in [17] show that pNeRF takes more than 5 seconds to estimate an ideal pose, while iNeRF is slower and tends to fall into local optima. Second, it is impossible to sample the entire 6-DoF pose space, so they all rely on an initial pose as input and find an optimal pose near the initial one.

In this paper, we "invert" NeRF for direct pose estimation. To this end, we propose a framework that integrates NeRF with invertible neural network (INN) so that it can directly output the pose of a given image. INN has been used to solve many inverse problems[2, 19, 40], such as image rescaling[15, 40] and robot localization[45]. Inspired by these works, we propose to integrate INN into the existing NeRF process to make NeRF partial-invertible, and the whole framework is denoted as PI-NeRF. In PI-NeRF, we successfully invert the process of generating image from a given pose and achieve the goal of directly estimating the pose from a given image without iterative optimization or pose initialization. Compared to existing methods[17, 20, 43] based on iterative optimization, PI-NeRF can achieve global camera pose estimation two orders of magnitude faster.

Specifically, we first modify the existing NeRF[25], inspired by [28, 35], which generates an RGB value at each pixel, to generate a high-dimensional feature at each pixel. In the modified NeRF, we use MLP to map each 3D point to a high-dimensional feature instead of the original RGB color, and apply the volume rendering function as a weighted feature aggregation method to a set of features along the ray, so as to obtain a high-dimensional feature for each ray. We call this modified NeRF NeRF-Feat. Then we design an Invertible Neural network Module (INM) consisting of two INNs that can input and output in two directions. In the forward path of INM, it takes the ray feature from NeRF-Feat and a representation of the ray as input, and outputs a pixel feature. If this pixel feature is fed into the reverse path of INM, it can recover the corresponding ray feature and ray representation. In model training and inference, we use ResUNet[35] to extract pixel features for the given observed image whose pose is to be estimated, and feed these pixel features into the reverse path of INM. During model training, we compute the Barlow Twins (BT) loss[46] between the corresponding pixel features produced by INM in the forward path and the features extracted by ResUNet, so that the ResUNet can learn to generate features suitable to be fed into INM in the reverse path to recover the ray representations. During reference, we use ResUNet to extract a feature map from the observed image, and then sample a set of features and feed them into INM in reverse path to obtain ray representations. Based on these ray representations, we can directly use the PnP algorithm to calculate the camera pose. Our contributions can be summarized as follows:

- We propose a framework, PI-NeRF, to directly estimate the pose of a given observed image by integrating NeRF with invertible neural networks. PI-NeRF is two orders of magnitude

faster than existing NeRF-based pose estimation methods and does not rely on the initial pose. This is the first work that uses NeRF for direct pose estimation.

- We utilized a high-dimensional NeRF that outputs a feature for each pixel instead of simple color, which enables the inverting of NeRF in the proposed framework and has the potential to be used in other downstream tasks.
- Experiments conducted on both synthetic and real-world datasets show that our approach is two orders of magnitude faster than state-of-the-art NeRF-based pose estimation methods and it is superior or on par with existing methods in terms of accuracy while without the need of an initial pose. Further experiments show that our method is more accurate than existing learning-based absolute pose regression (APR) methods.

### 2 RELATED WORKS

# 2.1 Neural Radiance Field (NeRF)

NeRF[25] is a milestone work that fits 3D scene into a continuous 5D (3D position and 2D direction) radiance field parameterized by MLP, demonstrating excellent novel view synthesis and scene representation capabilities. Many subsequent works improved NeRF in terms of rendering quality[4, 34, 39], training and rendering speed[13, 26, 41] and generalization ability[18, 35, 44], etc. Mip-NeRF[4] proposes a new positional encoding method and renders an anti-aliasing cone instead of a ray to prevent aliasing in NeRF and improve its detail representation ability. Instant-NGP[26] accelerates the training and rendering speed of NeRF by using multiresolution hash encoding. GNT[35] uses Transformer to achieve neural representation and rendering with cross-scene generalization ability. GNT generates a feature instead of physical properties such as transparency and color for each point, based on the feature maps from nearby view images and epipolar geometry, so that the feature of each point contains more abundant information such as material and lighting. Inspired by GNT, we propose NeRF-Feat based on the original NeRF[25] to generate pixel features, which will be introduced in detail in the Sec. 4.

### 2.2 Pose Estimation with NeRF

NeRF has achieved significant success in many fields, such as novel view synthesis, object geometry representation[36], image super-resolution[34], and deformable registration[38]. Recently, some work has explored the possibility of utilizing NeRF for pose estimation[5, 16, 20, 43]. iNeRF[43] is the earliest NeRF-based work on pose estimation. It takes an initial pose as input, and updates the pose parameters through backpropagation to minimize the same photographic loss as in NeRF training[25] between the input image and the image synthesized by the trained NeRF. iNeRF demonstrates a mesh-free, RGB-only pose estimation method based on NeRF by "inverting" it through gradient descent. Recent NeRF-based SLAM studies such as iMAP[32] and NICE-SLAM[50] have used this gradient descent method to optimize the pose of the current frame based on the poses of the previous frames. However, directly optimizing the pose with gradient descent as in iNeRF has a small convergence region, making it sensitive to initial poses. LATTITUE[48] proposed

a Truncated Dynamic Low-pass Filter (TDLF) to enlarge the convergence region and a CNN-based place recognition network to generate initial poses. However, LATTITUE still suffers from the local minima problem when the initial pose is relatively far away from the target pose, and the place recognition network needs to be trained with a large number of images (some of the training images are obtained from trained NeRF). Another line of work uses Monte Carlo sampling to achieve NeRF-based pose estimation, such as Loc-NeRF[20] and pNeRF[17]. They iteratively sample a set of poses and at each iteration, they use the pre-trained NeRF as a function to update the weights of the sampled poses and generate new poses based on these new weights. The final estimated pose is the weighted average of all poses after multiple iterations. Both gradient descent-based methods and Monte Carlo sampling-based methods estimate the pose in an iterative manner and require a good initial pose and significant computation. In contrast, our method can estimate the pose directly from an image without the need for an initial pose in a single-step manner by integrating INN with NeRF. This allows our method to achieve global pose estimation at a speed two orders of magnitude faster than existing NeRF-based methods.

### 2.3 Invertible Neural Network

An INN consists of several invertible blocks that have the same dimension of input and output, enabling direct computation of the input from the output. Based on this property, it can use a constant amount of memory to compute the gradients during training, thus saving memory consumption when training wider and deeper networks, such as Rev-ResNet[8], Rev-ViT[21]. Some works leverage the invertibility of INN to solve inverse problems[2, 40, 45]. Local\_INN[45] is the one most related to our work, which regards the task of estimating a robot’s pose from a radar scan as an inverse problem of obtaining a radar scan from a map with a given pose. It utilizes an INN to provide implicit map representation in the forward path and localization in the inverse path. The main difference between Local\_INN and our method is that Local\_INN uses INN to build a conditional normalized flow that directly builds a map between pose and radar scan, resulting in a weak implicit representation and requiring a large number of images to train a scene. Our method, on the other hand, by introducing the idea of ray rendering in NeRF and using INN to build a map between pixel features and rays, can be trained with fewer samples compared to Local\_INN and has a good scene representation capability.

## 3 PRELIMINARIES

### 3.1 Vanilla NeRF

The vanilla NeRF[25] first uses an MLP to map any 3D point  $\mathbf{x} \in \mathbb{R}^3$  in the scene with a direction  $\mathbf{d} \in \mathbb{R}^3$  to an RGB color  $\mathbf{c} \in \mathbb{R}^3$  and a density  $\sigma \in \mathbb{R}$ . The color  $\mathbf{c}_u$  at the pixel coordinate  $u \in \mathbb{R}^2$  can be generated by a weighting function on the colors and densities predicted by the MLP for a set of 3D points on the corresponding ray  $\mathbf{r}_u$ .

We describe in detail below how NeRF generates the corresponding  $\mathbf{r}_u$  based on the given  $u$  and camera pose  $T = [R, t]$ , where  $R \in \mathbb{R}^{3 \times 3}$  represents the orientation of the camera and  $t \in \mathbb{R}^3$  represents the position of the camera, and obtains the rendered

pixel color  $\hat{\mathbf{c}}_u \in \hat{I}$  and depth  $\sigma_u \in \hat{D}$ , where  $\hat{I}$  is the rendered image and  $\hat{D}$  is the corresponding depth map.

We first define the ray as  $\mathbf{r}_u(z_k) = \mathbf{o}_u + z_k \mathbf{d}_u$ , where  $\mathbf{o}_u = t$  represents the origin of the ray,  $\mathbf{d}_u = R\bar{u}$  represents the direction of the ray,  $z_k$  represents the distance from the origin of the ray along its direction, and  $\bar{u} = [u; 1]^T \in \mathbb{R}^3$  is the homogeneous coordinate of  $u$ . For convenience, we denote  $\mathcal{W}(u, T)$  as the ray corresponding to pixel coordinate  $u$  under camera pose  $T$ .

NeRF samples a set of sorted depth  $z$  along ray  $\mathbf{r}_u$  between pre-defined near plane distance  $z_n$  and far plane distance  $z_f$ . For each  $z_k \in z$ , it computes a 3D point  $\mathbf{x}_k = \mathbf{r}_u(z_k)$  and feeds the point with  $\mathbf{d}_u$  into MLP to obtain the color  $\mathbf{c}_k$  and volume density  $\sigma_k$  for that point on  $\mathbf{r}_u$ :


$$[\mathbf{c}_k; \sigma_k] = \text{MLP}(\gamma_x(\mathbf{x}_k), \gamma_d(\mathbf{d}_u); \Theta) \quad (1)$$

where  $\Theta$  is the weight of MLP and  $\gamma(\cdot)$  is a positional encoding function. With a set of colors and densities on  $\mathbf{r}_u$ , NeRF uses volume rendering to generate the pixel color at  $u$  and the depth along the  $\mathbf{r}_u$ :


$$\hat{\mathbf{c}}_u = \hat{I}(u) = \sum_k \tau_k (1 - \exp(-\sigma_k \delta_k)) \mathbf{c}_k \quad (2)$$

$$\sigma_u = \hat{D}(u) = \sum_k \tau_k (1 - \exp(-\sigma_k \delta_k)) z_k \quad (3)$$

where  $\tau_k = \exp(-\sum_{k' < k} \sigma_{k'} (z_{k'+1} - z_{k'}))$ ,  $\delta_k = z_{k+1} - z_k$ . We can regard volume rendering as a weighted aggregation of the color and depth over all 3D points on the ray.



### 3.2 Invertible Neural Network

The basic unit of an INN is invertible block. Following[2], each of our invertible blocks consists of two complementary affine coupling layers. For the input vector  $\mathbf{g}$  of one block, we first divide it into two parts  $\mathbf{g}_1$  and  $\mathbf{g}_2$ , and then compute their outputs respectively:

$$\begin{aligned} \mathbf{g}'_1 &= \mathbf{g}_1 \odot \exp(a_2(\mathbf{g}_2)) + b_2(\mathbf{g}_2), \\ \mathbf{g}'_2 &= \mathbf{g}_2 \odot \exp(a_1(\mathbf{g}'_1)) + b_1(\mathbf{g}'_1) \end{aligned} \quad (4)$$

where  $\mathbf{g}' = [\mathbf{g}'_1, \mathbf{g}'_2]$  is the output of the block,  $\odot$  is an element-wise multiplication,  $a_i$  and  $b_i$  can be arbitrarily complicated functions as long as their output dimensions are the same as the input. For a given output  $\mathbf{g}' = [\mathbf{g}'_1, \mathbf{g}'_2]$ , we can easily reverse Eq. 4 to obtain the input:

$$\begin{aligned} \mathbf{g}_1 &= (\mathbf{g}'_1 - b_2(\mathbf{g}_2)) \odot \exp(-a_2(\mathbf{g}_2)), \\ \mathbf{g}_2 &= (\mathbf{g}'_2 - b_1(\mathbf{g}'_1)) \odot \exp(-a_1(\mathbf{g}'_1)) \end{aligned} \quad (5)$$

We stack a sequence of these invertible blocks to form an INN. The forward path of INN is  $\mathbf{g}' = \text{INN}(\mathbf{g})$  and reverse path is  $\mathbf{g} = \text{INN}^{-1}(\mathbf{g}')$ .



## 4 METHODS

We provide an overview of the PI-NeRF framework in Fig. 1 (a), which consists of three parts: NeRF-Feat, Invertible Neural Module (INM), and ResUNet. INM is the key to achieving reversibility, serving as a bidirectional converter between ray feature with a ray representation and pixel feature. In the forward path, a ray  $\mathbf{r}_u$  is transformed into its corresponding pixel feature  $\mathbf{f}_u^p$  through NeRF-Feat and INM. Here NeRF-Feat is a high-dimensional NeRF that maps the input ray into a high-dimensional ray feature  $\mathbf{f}_u^r$ .



Figure 1: Overview of our method. (a) Shows the three main components of our method, a high-dimensional NeRF called NeRF-Feat, an Invertible Neural Module called INM, and an image encoder called ResUNet. Our method has two directions, the forward path ( $\rightarrow$ ) works like NeRF, rendering each ray to a pixel color with an additional pixel-wise decoder, and the reverse path ( $\dashrightarrow$ ) restores the ray representation from a pixel via ResUNet and INM. (b) The proposed NeRF-Feat. (c) The subnetworks used in INN1 and INN2.

INM consists of two INNs and in the forward path, it takes the ray feature  $f_u^r$  and a ray representation  $\bar{r}_u$  parameterized with  $r_u$  and  $\sigma_u$  as input and outputs a pixel feature  $f_u^p$  at coordinate  $u$ . In the reverse path, INM takes a pixel feature  $f_u^{p'}$  as input and outputs a ray representation  $\bar{r}_u'$  and a ray feature  $f_u^{p'}$ . The red dashed arrows represent the reverse path, which starts from a given image  $I_{4 \times}$  whose pose is to be estimated. We use an image encoder ResUNet to extract a feature map  $F_I'$  from  $I_{4 \times}$ , where each pixel feature  $f_u^{p'} \in F_I'$  can be used as input to INM's reverse path to obtain its corresponding  $\bar{r}_u'$ , from which we can obtain a 3D endpoint  $e_u'$  of the ray that corresponds to  $f_u^{p'}$ . During training, we compute the BT loss between the pixel features from forward and reverse path to supervise NeRF-Feat coupled with INM to produce pixel features consistent with that of ResUNet. We also add a pixel-wise decoder to decode each pixel feature  $f_u^p$  and  $f_u^{p'}$  to their corresponding RGB values and supervise them via MSE loss with the input image  $I_{4 \times}$ . During inference, we first use ResUNet to extract the feature map  $F_I'$  from a given observed image. For each  $f_u^{p'} \in F_I'$ , we can obtain  $e_u'$  through INM, and finally these 3D points are used in PnP algorithm to estimate the image pose. We will introduce NeRF-Feat, INM and ResUNet in Sec. 4.1, 4.2, 4.3, respectively.



#### 4.1 High-Dimensional NeRF

The original NeRF and most of its subsequent works use MLPs to map the 5D parameters of each 3D point to color and density, which are the basic visual attributes, while some other works generate higher-dimensional features for each 3D point[35, 47]. Inspired by [35, 47], we argue that each point in a scene can contain not only

simple visual attributes but also richer information by representing it as a higher-dimensional feature. This allows it to contain semantics, materials, and other information that is difficult to model explicitly. Based on this idea, we lift NeRF from color space to higher-dimensional feature space by making modifications to existing NeRF methods, and we call this NeRF in feature space as NeRF-Feat. To this end, we first modify Eq. 1 as follows:

$$[f_k; \sigma_k] = \text{MLP}(\gamma_x(x_k), \gamma_d(d_u); \Theta) \quad (6)$$

Here, we replace  $c_k \in \mathbb{R}^3$  with  $f_k \in \mathbb{R}^{dim}$ , where  $f_k$  is the feature of 3D point  $x_k$  and  $dim$  is the dimension of the  $f_k$ .

As stated in GNT[35], we can consider the volume rendering as a weighted sum of colors for each point on the ray to obtain the final color of the ray. Similarly, we can obtain the feature  $f_u^r$  of the ray by weighting on all  $f_k$  outputs from MLP of 3D points on the ray. We use volume rendering to aggregate ray's feature and rewrite Eq. 2 as follows:

$$f_u^r = \sum_k \tau_k (1 - \exp(-\sigma_k \delta_k)) f_k \quad (7)$$

Here, we replace  $c_k$  with  $f_k$ . Unlike GNT using Transformer to replace the original volume rendering function, our modification to Eq. 2 allows us to make minimal changes to the existing NeRF without increasing computational burden.

While NeRF[25] in color space optimizes the network with loss in color space, we propose a method to supervise our NeRF-Feat in both feature and color space so that it can produce features with consistency to features from ResUNet as well as having good expressiveness. This will be discussed in detail in Sec. 4.3.



## 4.2 Partial-Invertible NeRF

Since INN requires that the dimensions of inputs and outputs should be consistent as introduced in Sec. 3.2, some works [2] have pointed out that INN can perform better in higher-dimensional space. Thanks to our proposed NeRF-Feat that lifts NeRF output from the 3D color space to the high-dimensional feature space, we can seamlessly integrate INN and NeRF-Feat to make it partial-invertible, as we can recover a ray representation from a pixel feature via INNs.

As shown in Fig. 1, we design the INM module that contains two INNs. In the forward path, we use INM to map the ray feature from NeRF-Feat and ray representation into pixel feature. Specifically, INM takes the ray feature  $f'_u$  and the ray representation  $\bar{r}_u$  as input, and outputs a pixel feature  $f'_u$ .  $\bar{r}_u$  is defined as follows: we first convert the ray  $r_u$  into Plücker coordinate representation  $r_{plu} = [d_u, m_u] \in \mathbb{R}^6$ , where  $m_u = o_u \times d_u$  ( $\times$  denotes cross product). Intuitively,  $r_u$  and the origin form a plane, and  $m_u$  is a vector perpendicular to this plane with length equal to the distance from the origin to the ray. For more details about Plücker coordinates in NeRF, please refer to [31]. Then we calculate the endpoint  $e_u = r_u(\sigma_r)$  of the ray  $r_u$  and define  $\bar{r}_u = [r_{plu}, e_u, e_u]$ . We first feed  $\bar{r}_u$  into INN1:

$$\varkappa_u = \text{INN1}(\bar{r}_u) \quad (8)$$

where INN1 is used to encode the ray, with  $\varkappa_u$  being the result of the encoding. INN1 consisting of three invertible blocks, each of which contains two sub-networks serving as  $b_1$  and  $b_2$  in Eq. 4. Each sub-network consists of a SIREN layer [30] and two MLP layers as shown in Fig. 1 (c). As introduced in Sec. 3.2, the invertible block will split the input in half and then compute their outputs through mapping functions. Therefore, we repeat  $e_u$  twice in  $\bar{r}_u$  so that the two parts after splitting are  $r_{plu}$  and  $[e_u, e_u]$ , each of which has a clear meaning. Then we concatenate  $\varkappa_u$  with  $f'_u$  and feed them into INN2 to obtain the pixel feature  $f'_u$ :

$$f'_u = \text{INN2}([\varkappa_u, f'_u]) \quad (9)$$

where INN2 is an INN consists of 3 invertible blocks, each of whose sub-networks are MLPs as shown in Fig. 1.

In the reverse path, INM takes a pixel feature  $f''_u$  as input, which is the feature at position  $u$  on the feature map extracted from a given observed image, and outputs the  $\bar{r}'_u$ :

$$[\varkappa'_u, f''_u] = \text{INN2}^{-1}(f'_u), \bar{r}'_u = \text{INN1}^{-1}(\varkappa'_u) \quad (10)$$

where  $\bar{r}'_u = [\bar{r}'_{plu}, \bar{e}'_u, \bar{e}'_u]$  and  $\bar{e}'_u$  will be used for subsequent pose estimation, which will be introduced in Sec. 4.4.



## 4.3 Barlow Twins Loss for Bidirectional Consistent Feature Map

NeRF-Feat with INM can generate a pixel feature  $f''_u$  for each ray  $r_u$  in the forward path, and we can also obtain  $e'_u$  by using the pixel feature  $f''_u$  extracted from the image as the reverse input of INM. We expect  $e'_u = e_u$  so that we can use  $e'_u$  to restore the pose corresponding to a given image. According to the principle of INN, if the pixel feature  $f''_u = f''_u$ , we can easily obtain  $e'_u = e_u$  through the reverse path of INM. Here,  $f''_u$  and  $f''_u$  are respectively from the feature map  $F_p$  and  $F'_p$  generated in opposite directions.

We can regard NeRF-Feat and INM as an encoder  $E_r$ , which maps a ray at pixel coordinate  $u$  to a feature  $f''_u$ . In the forward path, we can leverage  $E_r$  to obtain a feature map  $F_p \in \mathbb{R}^{H \times W \times n}$  from a given  $T$ , where  $n$  is the dimension of each feature:

$$F_p(u) = f''_u = E_r(\mathcal{W}(u; T)) \quad (11)$$

In the reverse path, we use an asymmetric ResUNet as an image encoder  $E_I$ , which generates a feature map  $F'_p$  from the image:

$$[F'_p, I] = E_I(I_{4 \times}) \quad (12)$$

where  $I_{4 \times} \in \mathbb{R}^{4H \times 4W \times 3}$  is the original image, and  $E_I$  extracts image features from  $I_{4 \times}$  to produce a feature map  $F'_p \in \mathbb{R}^{H \times W \times n}$ . At the same time,  $E_I$  downsamples  $I_{4 \times}$  by four times to obtain  $I \in \mathbb{R}^{H \times W \times 3}$ , which is coordinate-aligned with  $F_p$  and  $F'_p$ . With ResUNet, a large perceptual field is available for each pixel to avoid ambiguity of pixel features.

For a pair of pose and image, we can obtain a feature map pair from two directions. The elements  $F_p(u)$  and  $F'_p(u)$  in this bidirectional feature map pair represent the feature of the same pixel corresponding to  $I(u)$ . To maximize the consistency between these two feature maps and make  $E_r$  and  $E_n$  extract the same feature representation for each corresponding ray and pixel, for each pixel feature  $f''_u \in F_p$  and  $f''_u \in F'_p$ , we use the modified Barlow Twins loss [46], which was originally proposed for representation learning [3], to compute their loss:

$$\begin{aligned} \mathcal{L}_{pf} &= \text{Barlow}(f''_u, f''_u) \\ &= \sum_i (1 - C_u^{ii})^2 + \lambda_{red} \sum_i \sum_{i \neq j} (C_u^{ij})^2 \end{aligned} \quad (13)$$

where  $\lambda_{red}$  is the weighted coefficient of the redundant loss,  $C_u$  is the cross-correlation matrix between  $f''_u$  and  $f''_u$ . We directly use  $f''_u$  and  $f''_u$  to calculate  $C_u$  instead of using their high-dimensional projections in the original paper [46]. Based on our observations, since the two feature maps are generated with different encoder respectively, the network tends to degrade without a proper loss function. The BT loss can effectively prevent network degradation by requiring the two features to be close in feature space while maintaining inter-dimensional independence among each feature.

Since we have the feature maps corresponding to the image  $I$ , we use a single-layer MLP as a pixel-wise decoder to restore the color of each pixel:


$$\hat{c}_u = D_{pix}(f''_u), \hat{c}'_u = D_{pix}(f''_u), \quad (14)$$

where  $D_{pix}$  is a pixel-wise decoder,  $\hat{c}_u$  and  $\hat{c}'_u$  are the colors decoded from  $f''_u$  and  $f''_u$  respectively. We compute the loss of decoded color and target color  $c_u = I(u)$ :

$$\mathcal{L}_{pix} = (c_u - \hat{c}_u)^2 + (c_u - \hat{c}'_u)^2 \quad (15)$$



## 4.4 Pose Estimation

As introduced in Sec. 4.3, for each feature  $f''_u$  at pixel coordinate  $u$  in the feature map  $F'_p$  extracted from the observed image, we can reverse the INM module to find the  $e'_u$ , which is a 3D point on the corresponding ray  $\mathcal{W}(u; T')$ , where  $T'$  is the camera pose to be computed.  $\{u, e'_u\}$  is a 2D-3D correspondence, and we can obtain a set of  $\{u, e'_u\}$  by sampling a feature set on  $F'_p$  and computing the

3D point set. Finally, we estimate the pose  $T'$  from these 2D-3D correspondences with the PnP algorithm.

## 4.5 Implement Details

Optimization: Following Local\_INN[45], the invertibility of INN allows us to perform bidirectional training by optimizing the loss on both sides of the network. We compute the loss between  $\boldsymbol{\kappa}_u, f_u^r$  and their reversed versions  $\boldsymbol{\kappa}'_u, f_u'^r$  with BT Loss:


$$\mathcal{L}_r = \text{Barlow}(\boldsymbol{\kappa}_u, \boldsymbol{\kappa}'_u), \mathcal{L}_{rf} = \text{Barlow}(f_u^r, f_u'^r) \quad (16)$$

We also compute the loss between  $\mathbf{e}'_u$  predicted by INM and  $\mathbf{e}_u$  calculated from NeRF-Feat:

$$\mathcal{L}_e = (\mathbf{e}_u - \mathbf{e}'_u)^2 + (\mathbf{d}_u \times \mathbf{e}_u - \mathbf{d}_u \times \mathbf{e}'_u)^2 \quad (17)$$

where  $\mathbf{d}_u$  represents the direction of ray  $\mathbf{r}_u$ , and  $\times$  denotes cross product. Intuitively, the first term minimizes the distance between two points  $\mathbf{e}_u$  and  $\mathbf{e}'_u$ . The second term minimizes the distance between  $\mathbf{e}'_u$  and ray  $\mathbf{r}_u$ , which is a more relaxed constraint than the first term but also meets the requirement for solving pose using PnP.

Overall, the training loss is:

$$\mathcal{L}_{total} = \mathcal{L}_{pf} + \mathcal{L}_{pix} + \mathcal{L}_r + \mathcal{L}_{rf} + \mathcal{L}_e \quad (18)$$

Networks. We modify Mip-NeRF to implement our NeRF-Feat as described in Sec. 4.1. For details of Mip-NeRF, please refer to [4]. We employ the ResUNet from GNT as the image feature encoder and utilize the FrEIA library[1] to implement the INNs.

Training. We employ the recently proposed optimizer Lion[7] with a learning rate of 0.0001 for our method in all experiments. We conducted all training and testing on a single computer equipped with an RTX3090 GPU and an Intel i5-12600k CPU.

### 6 CONCLUSION

In this work, we propose PI-NeRF, which is the first NeRF-based direct camera pose estimation framework. In PI-NeRF, we incorporate invertible neural networks with NeRF, distinguishing it from existing NeRF-based methods that iteratively optimize pose using gradient-based or Monte Carlo-based techniques. Experiments on synthetic and real-world datasets demonstrate that our method achieves pose estimation with comparable accuracy at a speed two orders of magnitude faster than the existing NeRF-based methods. In addition, our method achieves global pose estimation without the need of initial pose, while existing NeRF-based methods requires an initial pose and can only returned an optimized pose near the initialization. Further experiments show that our method outperforms the absolute position regression methods in terms of accuracy. In future work, we will validate the effectiveness of our method in larger and more challenging scenarios (e.g., indoors) and integrate this process into existing NeRF-based SLAM methods to improve their real-time performance.

# A TRAINING DETAILS

For NeRF synthetic, which has 100 training images per scene, we trained each scene with 60,000 steps for a training time of approximately 300 minutes on a single 3090 GPU. In each iteration, we randomly selected two images and chose 2,000 random rays for

each image. Each training image was sampled 1200 times evenly throughout the training process.

For LLFF, since each scene contains a different number of images, we trained them with a different number of iteration steps. We used the same sampling strategy as NeRF synthetic, ensuring that each training image was sampled equally 2000 times throughout the training process, with 1000 rays sampled on each sampled image.
