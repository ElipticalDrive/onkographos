Add FieldNode::gradient() with analytic derivatives for all 37 variants.
Recursive traversal matches the evaluate.rs pattern. Chain rule through
booleans (smooth ops use h·∇a + (1-h)·∇b), transforms (Jᵀ·∇child for
Twist/Bend/Rotate), and domain ops. LogSpiral includes a candidate-set
correction term for the theta-dependent discrete search. UserFn falls
back to central finite differences.

- gradient.rs: ~1050 lines, 37 variant handlers + duplicated helpers
- Solid::gradient() public API in solid.rs
- 37 new tests (analytic vs FD, component-wise ≤1e-4)
- 567 total tests pass, clippy clean

Add dual contouring mesher as a drop-in alternative to marching cubes.
DC places one vertex per sign-changing cell via QEF minimization of
hermite data (edge-crossing positions + analytic gradients), preserving
sharp features (edges, corners) that MC rounds off.

- dual_contouring.rs: mesh_field_dc() with interval pruning, QEF solver
  (SVD of 3×3 AᵀA with mass-point bias + cell clamping), quad-to-tri
  face generation from sign-changing grid edges
- Solid::mesh_dc(tolerance): public API parallel to Solid::mesh()
- 8 tests: manifold/winding checks, sharp corner preservation vs MC,
  flat face coplanarity, boolean pin-hole, sphere regression, pruning

Add batched evaluation (4 points per tree walk) and rayon-parallelized
adaptive dual contouring. The batch evaluator carries [f64; 4] through
every FieldNode variant, eliminating 3/4 of dispatch overhead and enabling

construction (top 3 levels) and Phase 1 cell processing.
