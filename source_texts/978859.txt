# Opt-in asynchronous ray preview: current position and evidence

This is the single public project index for the Coin/FreeCAD ray-preview work. The long-term objective is default-quality ray tracing through Coin for FreeCAD and other hosts. **The submitted change remains an opt-in CPU reference preview, in draft for design review.** Default enablement and a production ray-tracing backend remain unqualified.

## Submitted implementation and renderer evidence

The GUI thread captures supported geometry, instance transforms, materials and camera state into owned memory. A CPU reference renderer traces that snapshot on a worker. Before publishing the result, Coin compares it with the current input. During camera motion and for unsupported passes, the viewer continues drawing with OpenGL. A host opts in through `SoRenderManager::setCpuRayTracingEnabled(TRUE)`. Background execution also requires the experimental `COIN_CPU_RAY_ASYNC=1` setting.

The review covers snapshot ownership, cancellation, publication and composition with retained OpenGL. The CPU implementation gives future backends a reference for pixel and depth comparisons. The separate FreeCAD adapter, experimental swap settings and default enablement are outside this change.

## Known limits

One focus-loss error path logged an access violation and required the 300-second supervisor timeout. All owned processes were retired. Direct injection into the Qt widget also reproduced duplicate selection handling on both tested DLLs. Native stacks placed the first face addition on an overlay-forwarded path and the subsequent whole-link addition on a path without that overlay frame. Physical mouse input remains untested in this comparison.

The FreeCAD adapter was private. This packet reproduces the native Coin tests. A second driver, physical display latency, tearing, macOS, sanitizers and compatibility with already-built applications remain open. A separate instrumented successor also showed repeated snapshot capture and presentation in stationary views. Idle CPU cost remains a reason to keep preview opt-in.

**Legacy OpenGL measurement, November 6.** Compared upstream base cd6377b1 with Dikluwe's 20f21e60 on the #722 Windows orbit (150 meshes, 2.16 million triangles, automatic separator caching). **Inside the indexed draw on the RX 6700 XT.** On the same 2.16-million-triangle orbit, each of 120 sampled warm frames (four fresh processes × 30 frames) issued one element-buffer bind, zero index uploads, one indexed draw and one unbind in the live indexer. ### Radeon test of direct submission on a cache miss

On an RX 6700 XT, we orbited a static 150-sphere fixture (2.16 million triangles, 700 × 700 offscreen). After eight warm-up frames, each measured orbit frame reused 149 display lists and submitted one indexed mesh. A diagnostic switch deferred compiling a new AUTO list for that miss, either once or for 60 frames. We then restored normal compilation for 30 frames.

| Coin configuration | Median render call during 60-frame orbit | First frame after test | Median over 30 recovery frames |
|---|---:|---:|---:|
| Pristine coin3d/coin #833 | 12.340 ms | 10.688 ms | 13.145 ms |
| Instrumented, ordinary compilation | 17.298 ms | 11.677 ms | 13.545 ms |
| Defer once | 14.496 ms | 13.069 ms | 17.761 ms |
| Defer for 60 frames | 1.565 ms | 17.414 ms | 12.966 ms |

Each entry is a median across four sessions. Sustained deferral beat both controls in every timing block. Ordinary compilation varied widely (8.042–47.989 ms instrumented). The first recovery frame cost more in the aggregate, and the 30-frame recovery median was close to the controls. The measurements cover CPU elapsed time in the offscreen render call. Displayed frame rate and GPU completion remain unmeasured.

Separate runs verified the expected submission route on all 60 test and 30 recovery frames. For both deferral policies, full-frame RGB and depth hashes matched pristine #833 on all 98 frames, covering 30 distinct camera poses. This supports testing selective deferral in a live FreeCAD assembly. Geometry edits, visibility changes, displayed latency and other drivers still need qualification before proposing a default. Credit for the underlying indexed rendering work belongs to Dikluwe (coin3d/coin #833).

### Shared-source edit phase profiling

The large edit pause lies in GUI-attached Shape assignment and recompute. One source edit on the same accepted VBO fixtures measured:

| Stage | 1024 crankcase links | 256 flange links |
|---|---:|---:|
| Boolean construction | 27.5 ms | 8.3 ms |
| Shape assignment | 2581.3 ms | 620.8 ms |
| Document recompute | 9473.5 ms | 2218.8 ms |

Restoring the original shape avoids the Boolean yet still costs approximately 2.58 + 9.11 seconds for crankcases and 0.62 + 2.13 seconds for flanges. In a separate crankcase diagnostic, recompute took 8.51/9.48 seconds for edit/restoration; 27 viewport paints in each operation accounted for only 145/166 ms, under 2%.

A headless App/Part control recomputed the same links in 13–15 ms for crankcases and 3–4 ms for flanges. Separately reading and validating every linked Shape.Volume cost 2.8–2.9 seconds and 0.6 seconds respectively. All 2560 linked volumes matched the GUI source results. This localizes substantial cost to GUI-induced work, while leaving GUI bookkeeping versus induced geometry queries unresolved. It does not establish that GUI callbacks make these exact volume queries.

Suppressing only shared-source Coin-root notifications during assignment/recompute demonstrated no improvement: the trial took 18.86 seconds for edit and 20.58 seconds for restoration. Session variation prevents attributing the entire difference to batching. The strategy has no basis for promotion. It also needs a reentrancy contract: the matching [ProgressBar implementation](https://github.com/FreeCAD/FreeCAD/blob/4fd3bf320d9566a27e60069fc8387448aaa3a094/src/Gui/ProgressBar.cpp) can process GUI events during recompute, and viewport paints were observed inside ordinary recompute. Restored flags and settled images alone cannot establish safe intermediate rendering under notification suppression.

Four GUI trials passed 32 face/edge selections and 48 exact image comparisons with prior controls. Timing-accounting and restored-notification corruptions were rejected. All five GUI/headless processes cleaned up with zero residual owned processes. This remains bounded R0 component evidence.

Next instrument native GUI document-change handlers, link view-provider updates and geometry queries reached from them. A production change needs that attribution and must preserve cancellation and coherent updates during native event-loop reentry.

### Overlay-cache prototype — November 7

The process-local prototype caches the four link-overlay SVG variants, preserving native rendering on misses/bypasses and all document notifications. Eight-entry LRU; at most 64 KiB SVG input and 64 logical pixels per dimension. Lookup rechecks exact source bytes, resolved path, size, theme/search-path context and screen DPRs. These measurements include the Python/native adapter and repeated file-read overhead; this is a diagnostic, not an upstream C++ implementation.

| Fixture / operation | Shape assignment, native → cache | Recompute, native → cache |
|---|---:|---:|
| 1,024 crankcase links, edit | 2.692 → 1.075 s | 9.288 → 4.045 s |
| Crankcase restore | 2.565 → 0.898 s | 9.192 → 3.970 s |
| 256 flange links, edit | 0.683 → 0.358 s | 2.263 → 0.971 s |
| Flange restore | 0.664 → 0.238 s | 2.255 → 0.915 s |

Combined assignment/recompute fell **11.98 → 5.12 s** for crankcase edits and **2.95 → 1.33 s** for flange edits. These are individual operations in separate processes on FreeCAD 1.1.4 / Qt 6.8.3 / RX 6700 XT, using the same hook/observers and isolated VBO setting. The first flange candidate measured 0.348/0.966 s, consistent with the repeated 0.358/0.971 s. No universal performance claim or renderer-throughput claim follows.

Native link-touch counts matched controls for edit and restore: crankcase **1,024 assignment / 3,072 recompute**, flange **256 / 768**; source Shape notifications also matched. Root notifications stayed enabled. Crankcase edit overlay requests fell from 9,216 to 5,202; all 5,202 candidate requests in that interval hit the cache. These counters do not directly count icon-change signals.

Verification passed **40 native face/edge selections, 60 exact viewport image comparisons and nine full link-icon states**, including retargeting, array on/off, nested/subobject/subelement links and source geometry propagation. Native/cached icons matched after same-path SVG rewrites, search-path changes/removal, theme-name changes, same-path Qt resource replacement, size changes and eviction. Unsupported/color-mapped inputs bypassed; injected cache failure returned native output. A deliberately broken cache key produced stale pixels and was rejected. Two independent corrupt-evidence controls were also rejected.

The first trial failed in the verifier's handling of a deliberately null pixmap; the failure is retained. All seven owned processes cleaned up. Accepted helper cleanup restored original function bytes and emptied caches. Representative highlights and link icons were visually reviewed.

Remaining gates: production C++ implementation; key derived from the exact byte buffer rendered (concurrent/ABA resource writes during a miss remain untested); actual screen/DPR migration rather than a simulated key change; allocation/lifecycle/concurrency hardening and broader models/drivers.
