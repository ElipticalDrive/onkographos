Problem
The current checkpoint reports low sampled-query UDF error but reconstructs a swollen, non-airplane shape. The existing validator only measures the 512 sampled query points, while mesh extraction operates on a separate dense grid. That gap can conceal a field that is wrong where the mesh is extracted.
Changes
Add exact reference UDF evaluation on the same regular grid as the decoded field, with overall and near-surface MAE/RMSE in report.json.
Export a mesh/geometry report for each UDF extraction level in the default threshold sweep (0.005, 0.01, 0.02, 0.03).
Default validation to UDF level 0.01 and expose dense-reference near-band and chunk-size options.
Increase VAE training query supervision from 512 to 2,048 points per object, retaining near-surface weighting.
Avoid generating unused occupancy/UDF query targets during latent export; encoding only needs surface features and coordinates.
Add regression tests for dense-grid metric behavior and shape validation.
How to validate
Run:
```
python -m py_compile validate_triplane_vae.py train_triplane_vae.py encode_triplane_latents.py
pytest -q test_validate_triplane_vae.py test_triplane_pipeline.py
```
Then retrain a fresh UDF VAE checkpoint with 2,048 query points and inspect the dense-grid metrics and threshold-sweep meshes before encoding latents for DiT.
Status / limits
Changes are committed to this branch. I have not executed the Python test suite or GPU training in this GitHub editing environment; runtime validation is still required before treating the checkpoint as improved.
