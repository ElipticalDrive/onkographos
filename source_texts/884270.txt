Fixes NVIDIAGameWorks/rtx-remix#1110.
The bridge client returns block counts as D3DLOCKED_BOX pitches instead of byte strides. Games that fill a locked volume using those pitches overwrite rows and slices. In Transformers: War for Cybertron, this corrupts the 32×32×32 A8R8G8B8 colour-grading LUTs and gives the image a blue/purple tint even with ray tracing disabled.
This change:
Returns RowPitch = blocksPerRow * bytesPerBlock and SlicePitch = RowPitch * blockRows.
Keeps the upload packet dimensions in blocks and walks the source data using the byte pitches. The server protocol is unchanged.
Frees the lock buffer with delete[], matching its allocation.
Adds Kevin 'HANsoA-KevinO' to the GitHub contributor credits.

```
Direct3DVolume9_LSS::lock() returned RowPitch and SlicePitch as block
counts (blocks per row, block rows) instead of bytes, and unlock() walked
the locked data with those values as byte strides while iterating
SlicePitch rows per slice. A game that writes a locked volume using the
returned pitches therefore overlaps its rows and slices, and the server
receives a scrambled box.

Pitches are now returned in bytes. unlock() sends blocks per row and
block rows, which is what the server's IDirect3DVolume9_UnlockBox handler
reads as width and height, and walks the data with the byte pitches. The
lock buffer is freed with delete[] to match new[].

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```
