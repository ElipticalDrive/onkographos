Summary
This PR completes the chunk meshing pipeline by implementing a full 3D greedy mesher running in a dedicated Web Worker, with proper separation of opaque and translucent geometry. The renderer now dispatches mesh jobs to the worker with zero-copy buffer transfers, receives completed render buffers, and uploads them to separate Three.js geometries per render pass.
Key Changes
Core Meshing Pipeline
WorldRenderer.ts: Completely refactored to manage the worker lifecycle, dispatch mesh jobs with padded section data (centre + 26 neighbours), and handle opaque/translucent geometry separately. Now maintains two material slots and two mesh maps (opaque/translucent per section).
GreedyMesher.ts: Implemented full 3D greedy meshing algorithm that sweeps across all 6 face directions, merges adjacent identical faces into maximal rectangles, and separates results into opaque and translucent quad lists.
MeshBuilder.ts: Converts greedy-mesher quads into flat typed arrays (position, normal, uv, ao, tintColor) suitable for Three.js BufferGeometry. Handles UV tiling for merged quads and per-vertex AO baking.
MeshWorker.ts: Dedicated worker thread that receives INIT_REGISTRIES, UPDATE_BAKED_CACHE, and MESH_REQUEST messages. Owns the opaque ID set and baked quad cache, runs the mesher, and transfers completed buffers back to main thread.
SectionSampler.ts: New utility providing padded read access to a section plus its 26 neighbours via a sparse map. Handles coordinate routing and treats missing neighbours as uniform air.
Data-Driven Architecture
BakedModelRegistry integration: WorldRenderer now calls initWorkerFromRegistry() to walk all cached blockstates, convert BakedModels to simplified MeshSampleQuad form, and push to worker. Rebuilds the opaque ID set from the same data for consistent face culling.
MeshSampleQuad type: Simplified quad representation (face, texture atlas ID, UV bounds, tint index, opacity flag) that the worker uses instead of full BakedModel objects.
No block-specific logic: All opacity and face geometry flows through BakedModelRegistry → MeshSampleQuad → worker. New blocks (vanilla or modded) automatically work.
Opaque/Translucent Separation
Two BufferGeometry objects per section: one for opaque pass, one for translucent pass.
Two material slots: opaqueMaterial and translucentMaterial (currently both use the block shader; translucent variant with alpha blending + no depth write is a future enhancement).
Greedy mesher separates quads at generation time based on BakedQuad.isTranslucent flag.
MeshBuilder produces separate RenderBuffers for each pass.
Worker Protocol
INIT_REGISTRIES: Send opaque blockstate ID set (once at startup, refreshed on registry growth).
UPDATE_BAKED_CACHE: Push [stateId, MeshSampleQuad[]][] entries when BakedModelRegistry updates.
MESH_REQUEST: Dispatch a job with centre section + sparse neighbour map (both Uint32Array, transferred for zero-copy).
MESH_RESPONSE: Receive completed opaque + translucent RenderBuffers (transferred back).
Type & Infrastructure
meshing.ts: Comprehensive wire-format types with detailed ownership rules and index layout documentation.
global.d.ts: Window augmentation for window.electronAPI (Electron IPC bridge).
tsconfig updates: Added rootDir to desktop configs, fixed composite builds, updated all packages to use tsc -b for incremental compilation.
.gitignore: Added comprehensive ignore patterns for build artifacts, Electron, and cache.
Minor Fixes
AOGenerator.ts: Added as const to offset arrays for stricter typing.
ModelBaker.ts: Added unreachable default case in face direction switch.

AssetPipeline: re-populate raw data on cache hit
…
1b1ba9a
```
Diagnostic histogram in the renderer confirmed the AssetIndex was
correct end-to-end: 1168 blockstate entries, 3517 texture entries,
3673 model entries, all with the right 'type' field. Yet
BlockstateLoader compiled 0 and AtlasBuilder packed 0 sprites.

Root cause: AssetRegistry.restoreFromCacheIndex() is a no-op. On a
cache hit we returned the metadata index but the in-process rawData
Map stayed empty, so every getBlockstateJson() / getModelJson() IPC
call returned null, downstream consumers found nothing to compile,
and the world stayed empty.

This is why everything worked the one time the cache was wiped
(forced a cache miss → ran the extractJar loop → populated rawData)
and broke on every reimport afterwards (cache hit → metadata only,
no raw data).

Fix: on cache hit, iterate jarPaths and call extractJar() on each
purely for its side-effect of storing raw buffers into the registry.
We discard the returned metadata entries since the cached index is
authoritative and JAR hashes matching guarantees byte identity.

The full raw-data-on-disk persistence path remains a future
optimisation; this restores correctness without that infrastructure.
```

```
Diagnostic confirmed: red-debug shader renders the platform, atlas-
direct shader renders the platform solid black → atlas texture wasn't
reaching the GPU sampler.

AtlasBuilder was creating an OffscreenCanvas, painting all sprites
into it, then snapshotting it as ImageBitmap (correctly) but then
constructing THREE.CanvasTexture from the original OffscreenCanvas
and DISCARDING the bitmap. CanvasTexture + OffscreenCanvas interop in
Three.js is inconsistent across versions (sometimes the canvas is
uploaded before all draws have flushed; sometimes the upload silently
fails on the worker boundary) so the sampler was reading from the
default 1×1 black texture instead.

Fix: use the already-created ImageBitmap as the texture image source
via plain THREE.Texture. ImageBitmap is universally supported as a
TexImageSource and uploads deterministically. flipY=false because
ImageBitmap is already top-down (the default flipY=true would mirror
every sprite vertically and break UV mapping).
```
