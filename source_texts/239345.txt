Context
Verified gap: culling is frustum + distance + LOD only (Engine/Graphics/DX12/DX12Renderer_3DScene.cpp, 2-pass MT cull at lines 290–369). In indoor horror scenes — the engine's primary target — walls hide almost everything, yet every instance behind them is still drawn. There is no Z-pyramid or software occlusion of any kind. The building blocks exist: a depth buffer (D32_FLOAT), motion-vector reprojection machinery (Engine/Shaders/motionvector.hlsl reprojects via prev view-projection), and per-instance bounding spheres cached for the frustum test.
Goal
Hierarchical-Z occlusion culling: build a Hi-Z mip pyramid from the previous frame's depth, then conservatively test each instance's screen-space bounds against the pyramid inside the existing 2-pass MT cull, rejecting instances fully behind occluders — with a one-frame-latency reprojection guard so disocclusions never cause visible popping.
Acceptance Criteria
Depth pyramid built each frame (compute or mip-chain downsample) from scene depth
Conservative sphere/AABB-vs-HZB test integrated into cull Pass A; frustum+distance still run first
Indoor test scene (rooms behind walls) shows >50% reduction in instances_drawn with zero visible popping
Telemetry: occlusion-culled count exposed alongside existing get_instances_tested/drawn()
Toggleable at runtime (debug compare mode) and disabled automatically for the first frame after camera cuts/scene switch
Works correctly with render-scale (pyramid from the scaled RT depth)
Technical Notes
Previous-frame depth + m_prev_view_projection (already tracked for motion vectors) enable reprojected tests
This is likely the engine's first compute-shader dispatch — keep the pyramid pass simple and self-contained; the v4.0 GPU-culling work (ExecuteIndirect) will consume the same pyramid
Watch the BGRA/viewport traps documented from the render-scale work when adding the new pass
Dependencies
None (pairs with, but does not require, "core: spatial partition (octree/BVH) for culling & queries")
