Why
With the per-object velocity buffer (#1435), motion blur can blur what actually moves (enemies, swings, ragdolls) and keep the viewmodel crisp. The naive approach, a gather along each pixel's own velocity, only blurs inside a moving object's silhouette: the edges stay sharp, which reads worse than no blur. The standard reconstruction filter fixes that and is what shipping shooters use.
What
Replace the camera-only motion_blur in engine/shaders/postfx.wgsl with a reconstruction filter (McGuire et al. 2012, "A Reconstruction Filter for Plausible Motion Blur", as refined in Jimenez's CoD: Advanced Warfare talk, 2014):
TileMax: downsample the velocity buffer to tiles (≈20 px) keeping the longest vector.
NeighborMax: each tile takes the dominant velocity of its 3×3 neighbourhood, so blur spreads past a silhouette onto the background behind it.
Gather: per pixel, motion_blur_samples taps along the neighbourhood velocity, weighted by depth (foreground over background) and by each tap's own velocity, plus a little per-pixel jitter from a screen-space hash (not time-based, so a still frame is stable) to hide banding.
One path: camera motion is already in the velocity buffer, so the old reconstruct-from-depth path is deleted, not kept beside it.
Knobs on CameraComponent (Unity's motion blur override):
motion_blur_active, motion_blur_samples as today (2..=32, default on / 32 per Camera card forces motion blur on at 64 samples: no toggle, no slider, and it overwrites scripts #1433).
Decision, recommendation yes: add motion_blur_intensity (Unity's Intensity, the shutter fraction, default 0.5 ≈ a 180° shutter) and a max blur length in screen fraction (Unity's Clamp, default 0.05). The intensity is what a developer actually tunes; the clamp keeps a 180° flick from smearing the whole screen. Both get the editor slider + Graphics.* getter/setter + doc row in the same PR (the parity gate).
The quality preset keeps gating it (off on Low).
Acceptance
Lavapipe screenshot tests: a cube moving past a static camera shows blur extending past its silhouette; the same cube static under a static camera is pixel-identical to motion blur off; a viewmodel child of an overlay camera stays sharp while the world blurs under camera rotation.
Debug.Stats / frame timing shows the cost of the two tile passes; record it on Medium and High in the PR.
docs/api/Graphics.md describes per-object motion blur and its knobs.

Decisions: the independent review of PR #1458 found these. Fix them in this branch:
The editor's Scene view never blurs (Unity's Scene view doesn't). Gate blur_params and motion::wanted on the view not being the edit-mode Scene view, so flying the editor camera writes no velocity and blurs nothing. The Game view and Play keep blurring.
Depth ordering under a DepthOnly overlay is the standard FPS setup and must work. The blur reads the stack's depth after an overlay cleared it, so every world pixel decodes to the far plane and world-vs-world ordering is lost (an enemy passing a wall blends into it at half strength). Have each camera write its own linear view distance beside its velocity: widen the velocity target to carry it (e.g. Rgba16Float, .b = view distance through that camera's own projection), kept by the same "nearest camera wins" compositing the velocity already follows. fs_gather then reads that instead of decoding the stack's depth through the base camera's projection, which also fixes an overlay with a different near plane or FOV. Add a lavapipe test: world + DepthOnly gun camera, an enemy cube moving past a still wall cube, and the wall behind it gets the full-strength foreground blur (compare against the same scene without the overlay camera).
Bloom reads the blurred scene: PostFx::run_bloom's bright-pass reads scene_color(), as URP/HDRP run motion blur before bloom.
TileMax reduces in two steps (e.g. a horizontal pass then a vertical one, or 8×8 then the rest), so a 216 px tile at 4K with Clamp 0.2 isn't one fragment's 46k-tap loop.
The full-resolution blurred target is keyed by size only, not by tile size, so a clamp ramp rebuilds only the tile textures. (Folding the passes into PostFx::run's encoder is optional.)
docs/api-faithfulness.md's motion-blur row: add the two new setters and fix its dead render/postfx_params.rs path.
With no screen camera, the motion-blur getters disagree (intensity 0.5, samples 0) and the page says "neutral". Make the group consistent and say exactly what they return in docs/api/Graphics.md.

A render-texture slot drawn every N frames (update_every = N) blurs N frames of motion: scale its velocity (or its streak) by 1/N, so a monitor's blur matches one frame's shutter.
