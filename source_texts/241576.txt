Abstract Since its first presentation at ICCR 2013, the Reconstruction Toolkit (RTK) has become a reference software for tomographic
reconstruction of computed tomography (CT) images. In this period,
RTK has become a remote module of the Insight Toolkit (ITK), thus
enabling improved continuous integration and Python wrapping. New
functionalities have also been developed, including simulation of Forbild phantoms, handling of cylindrical detectors and new iterative
reconstruction algorithms for conventional CT, single photon emission
CT (SPECT), four-dimensional (4D) CT and spectral CT. This article
summarizes these eleven years of developments to today’s RTK v2.

RTK compilation has to be activated during ITK compilation
by turning on the CMake option Module_RTK.
1 Introduction
2.2
The Reconstruction Toolkit (RTK) was first presented at the
XVII-th international conference on the use of computers in
radiotherapy (ICCR 2013) in Melbourne, Australia [1]. Initially, RTK was an open-source and cross-platform software
for fast circular cone-beam CT reconstruction based on the
Insight Toolkit (ITK) [2], “an open-source, cross-platform library that provides developers with an extensive suite of software tools for image analysis” (https://www.itk.org).
RTK has been and keeps being a tool for researchers working
in radiotherapy and radiology as well as a sofware used by
companies for their cone-beam CT scanners. This paper summarizes the new features of RTK which have been developed
in the past eleven years.
More recently, in June 2022, the modular architecture of ITK
has also enabled the extraction from RTK of the code to manage ITK images on the graphics processing unit (GPU) using
the Compute Unified Device Architecture (CUDA, NVidia).
The CudaCommon module, available at https://github.
com/RTKConsortium/ITKCudaCommon, can now be used
by all users without RTK even if it is still managed by the
RTK consortium. The main feature of this module is to offer
an itk::CudaImage class which inherits from itk::Image.
An itk::CudaImage object has a GPU buffer, in addition
to the inherited central processing unit (CPU) one, to or from
which the image data is transferred depending on which processing unit is used for the calculation. The data transfer
from one unit to the other is automatically managed by triggering a data synchronization when calling a class member
which may modify the data buffer.

2.4 Python wrapping
3.2
ITK offers the infrastructure to wrap selected parts of remote
modules for their use in Python software. Since ITK heavily relies on templates to be able to, e.g., manage images
of any dimension using pixels of any type (int, float, etc.),
the wrapping code specifies which image types are compiled
for Python. A large part of the CudaCommon and RTK
modules has been wrapped. The user can either compile
the wrapping or download pre-compiled binaries distributed
via the Python Package Index (PyPI, https://pypi.org/).
Both CPU only and CPU+GPU packages of RTK are distributed. The distributed CUDA packages are wrapped
for a specific CUDA version number which is appended
to the package name. Currently, the distributed packages
are itk-rtk, itk-rtk-cuda116 and itk-rtk-cuda121
and the latter depends on itk-cudacommon-cuda116 and
itk-cudacommon-cuda121. New versions of the packages
are distributed after every release of ITK base packages to
ensure compatibility. The last ITK version is v5.4.0 and the
corresponding CudaCommon and RTK releases are v1.1 and
v2.6, respectively.

acquiring treatment planning CT images, use cylindrical detectors with an axial axis (Figure 2). RTK is now capable of
simulating and reconstructing projection data of cylindrical
detectors, as illustrated in, e.g., [4].

3.1 Forbild phantoms
Tomographic reconstruction is often evaluated on numerical
phantoms which are described by simple geometric shapes
(ellipsoids, cones, parallelepipeds, etc.). The most famous
one is the Shepp-Logan phantom, made of ellipsoids only,
which was already available in RTK v1. RTK has since
implemented the use of a larger set of geometrical shapes described by the Forbild file format. A separate GitHub repository (https://github.com/RTKConsortium/Forbild)
pre-process the original Forbild files using gcc’s preprocessor (to apply #include and #define directives) and
Python (to calculate mathematical expressions), thus producing a single file understandable by RTK. These files (currently
Abdomen, Thorax and Head) can be input to RTK to compute projection and reference CT data, as used for example
in [3] to evaluate several reconstruction algorithms. Figure 1
illustrates the Forbild head and thorax phantoms.

Several iterative reconstruction algorithms have been developed in RTK since v1. Those include conventional least
square minimization with quadratic Tikhonov regularization
using conjugate gradient minimization as well as less smooth
regularizers, e.g., total variation, L1-norm of the image or
L1-norm of the wavelet decomposition of the image. Several
of these algorithms are also used by four-dimensional (4D)
CT reconstruction algorithms to improve image quality, as
illustrated in Figure 4.

Single photon emission CT (SPECT)
RTK has also been extended to handle projection data acquired with a SPECT scanner. New projectors (and adjoint
backprojectors) have been implemented to model the patient attenuation (given a known attenuation map) and the
resolution of the collimator [5]. For example, these projectors have been used to reconstruct respiration-correlated 4D
SPECT images using ordered subset expectation maximization (OSEM) in [6]. Figure 3 shows sinograms of a sphere in
the left lung of the Forbild thorax phantom without and with
attenuation, where the attenuation map has been scaled such
that the attenuation of water is 0.2 cm−1 .

3.5
Four-dimensional CBCT
Four-dimensional (4D) CBCT has been a major axis of development of RTK since its debut. Early versions included
filtered backprojection respiration-correlated 4D CBCT using the breathing signal extracted from the projections [7].
Several reconstruction algorithms have been developed since
RTK v1 for reconstructing higher quality 4D CBCT images
using iterative reconstruction techniques. The most advanced
algorithms are the RecOnstructiOn using Spatial and TEmporal Regularization (ROOSTER) [8] and its motion-aware
version [9]. The two algorithms alternate between conjugate
gradient minimization and several constraints or regularizations: positivity, time-averaging outside a motion mask, 3D
spatial total variation (TV) denoising and one-dimentional
(1D) temporal TV denoising. The motion-aware version used
a priori knowledge of breathing motion to improve the 1D
TV denoising. Figure 4 shows coronal slices of several 4D
CBCT images reconstructed with RTK.
Spectral CT
Spectral CT is becoming increasingly popular in diagnostic CT. Dual-energy CT scanners are commercialized by all
major vendors and scanners with photon counting detectors
are also commercialized by some vendors. Spectral CT images can be processed in many ways. The first solution is to
reconstruct each energy bin CT image and do image-based
processing. However, the bin CT images will suffer from
beam-hardening. An alternative is to process the acquisition
in the projection domain if projection images are acquired
with the same geometry, e.g. with a dual-layer detector or a
photon counting detector. For example, material decomposition [10] can result in decomposed sinograms (Figure 5) and
each sinogram can be reconstructed separately in material CT
images using filtered backprojection or iterative algorithms.

Alternatively, projection images can be decomposed and reconstructed jointly, in one-step. Such processing has a high
computational cost but can significantly improve image quality, particularly if the number of energy bins of the scanner is
larger than the number of sought material CT images. Twostep and one-step reconstruction algorithms have been implemented in RTK and evaluated on patient images obtained
on a prototype photon counting scanner [11], as illustrated
in Figure 6. Image quality improvement is a trade-off between spatial resolution and image noise can be improved
depending on the selected regularization parameters.

Conclusion
Since its first public release in 2012 and its presentation
at ICCR 2013, RTK has become a reference software for
tomographic reconstruction of CT images. Thanks to funding
from research projects and industrial partners, RTK keeps
being improved and will remain an open-source research and
development tool used and developed by an ever-growing
international community.
