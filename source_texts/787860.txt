## Handoff:

For **v3d-qpu-array-3d** (backend upload and the refusal's removal):

- **Nothing new to link.** texture.rs calls only C functions the backend already links and the tests already fake or trampoline. The four new C functions serve tex_check and the real-C test; the backend need not call them.
- **Upload.** `texture::layout(b)` is the layout for a 2D array (one layer's tree) or a 3D texture (the whole stack); `texture::image_bytes(b, &layout)` the image size; `texture::tile(b, &layout, image, src)` does the whole upload for both kinds from the GL core's storage (`gl_bytes(b)` bytes at `b.base_gpu`): arrays layer by layer at the tree stride, 3D slice by slice at `k * slices[level].size`, GL's `max(depth >> level, 1)` slices a level. The backend's existing `texture::layout` / `texture::tile` call sites (backend.rs around lines 4295-4372) should work unchanged once the refusal arm goes. `texture::image_offset(b, &layout, level, layer)` gives one layer's or slice's byte offset for any sub-image path.
- **Record.** `texture::state(b, &layout, image_gpu)` sets Image Depth (layer count, or level 0 depth) and the right Array Stride (tree stride for arrays, level 0 slice size / 64 for 3D). The record has no dimension field: 3D versus array is the TMU config's coordinate count, the compiler's job.
- **Refusal.** Remove the `_ =>` arm in `refusal_for` (texture.rs:136), adding type-specific checks if wanted. The unit tests `an_array_and_a_volume_are_still_refused_by_name` and the array assertion in `a_cube_is_sampled_whole_and_square` pin the refusal and must change with it.
- **`layers(b)` now returns `b.layers` for arrays and 3D.** It feeds the backend's `TexKey`, `rt_texture` and `tfu_tile` guards; after the removal the TFU path correctly stays off for layered images (`texture::layers(b) != 1`), and the depth-buffer and render-target paths are 2D-only by their own type checks.
- **Caveats.** `stack_3d` reads whether Mesa's level-1 page rule hit from the 2D layout (`offset[0] - offset[1] != size[1]`); the proof is in its doc comment. GL's 3D chain can outlast the 2D one (4x4x16 has 5 levels): the layout gives those 1x1 levels their own depth and `gl_level_layered` matches the GL core's one-texel-a-row pitch. Nothing is board-measured; the rules are Mesa 26.2.1's.

The C reference of the V3D 4.2 textures (driver/src/v3d/v3d_tex.c) gains
the 3D arm of Mesa 26.2.1's v3d_setup_slices, after the design in
docs/notes/v3d-tex-layout-es3.md (sections 2 and 3):

- `layout` takes a depth. A level's slices are tiled by the level's width
  and height alone (v3d_resource.c:646-698), so each level's stride,
  padded_height, size (ONE slice) and tiling are the 2D layout's; a level
  holds `level_depth` slices one size apart (:722), the level-1 page
  alignment applies to the level's total (:729-734), and the whole stack
  is moved to a page (:749-755). The totals are summed in 64 bits and a
  stack past 32 bits is refused with the layout untouched.
- `v3d_tex_level_depth`: the depth at level 0, then
  u_minify(2 * next_pow2(u_minify(depth, 1)), level), at least 1
  (v3d_get_dimension_mpad with block 1, :609-611, :636-639): a depth of 6
  has 4 slices at level 1, 5 has 2, 9 has 4.
- `v3d_tex_layout_3d(w, h, depth, levels, cpp)`: the stack; depth 0 or
  16384 and more is refused (Image Depth is 14 bits). With a depth of 1
  it is v3d_tex_layout's layout, byte for byte.
- `v3d_tex_slice_offset`: v3d_layer_offset's 3D arm (:776-777),
  slices[level].offset + slice * slices[level].size, refusing a slice at
  or past level_depth.
- `v3d_tex_state_from_layout_3d`: array_stride_64 = level 0's slice size
  / 64 (:765-766, v3dx_state.c:961) where the array/cube path programs
  the tree stride (:761-763).

v3d_tex_layout and v3d_tex_layout_msaa pass a depth of 1 and produce the
same bytes as before (tex_check's parts 1 to 10 are unchanged and pass).

tools/v3d/tex_check.c part 11 checks the 2D arrays (the cube path with
another layer count: 64x32 x7 with 4 layers and the non-power-of-two
13x7 x3 with 3, their tree stride, size and layer offsets by hand, every
layer x level tiled against Mesa's v3d_store_tiled_image at Mesa's
offsets, the depth-4 record against V3D42_TEXTURE_SHADER_STATE_pack) and
the 3D textures (32x32x8 x6, 13x7x6 x4, 4x4x16 x5 where the depth
outlasts the sides, 80x656x3 x2 where level 1's total is page-aligned:
offsets, sizes and level depths derived by hand from v3d_setup_slices;
level_depth values; depth 1 equal to the 2D layout; slice offsets; every
allocated slice x level tiled against Mesa's store at v3d_layer_offset's
place; the record with level 0's slice stride against Mesa's packer; a
control that the array's tree stride on a 3D record is detected; and the
refusals). Measured: `tex_check: 530 checks run (planned 530), 0 failed`
(486 before).

src/v3d/texture.rs gives a 2D-array and a 3D binding their V3dTexLayout,
image size, per-(level, layer) offset, TMU record and tiled copy, after
docs/notes/v3d-tex-layout-es3.md; `refusal_for` still refuses both by
name ("a 2D array or 3D texture is not sampled yet"), so no draw reaches
them until the look-ups exist (v3d-qpu-array-3d).

The host tests of this crate link Rust fakes of the C texture functions
(src/v3d/backend_tests.rs) and every V3D integration test its own
trampolines, so this file reaches no new C symbol: the layered placing
is done here over the levels the C lays out for one slice, by Mesa's
rules, and tests/es3_formats_v3d.rs pins it against the real C
(driver/src/v3d/v3d_tex.c built by the test) and Mesa's numbers.

- `layers(b)`: 6 for a cube, the binding's `layers` for a 2D array (the
  layer count) and a 3D texture (the level 0 depth), 1 otherwise; it is
  the record's Image Depth (v3dx_state.c:935-939) and the slots the GL
  core stacks at every level (`gl_level_layered`, `gl_bytes`).
- `level_depth(depth, level)`: Mesa's per-level slice count
  (v3d_resource.c:609-611, :636-639), the C's v3d_tex_level_depth.
- `layout(b)`: for a 3D texture of depth > 1, `stack_3d` recomputes the
  offsets and size of the 2D layout as v3d_setup_slices does for
  PIPE_TEXTURE_3D (:722, :729-734, :749-755, :765-767): a level's total is
  size * level_depth, level 1's total is page-aligned when the 2D layout
  shows the page rule hit it (read off offset[0] - offset[1] != size[1],
  exact: when size[1] is a page multiple so is its multiple), level 0 to
  a page. A depth of 1 is the tree as laid out.
- `image_offset(b, layout, level, layer)`: Mesa's v3d_layer_offset
  (:770-780): slice * slices[level].size for 3D (a slice at or past
  level_depth is None), layer * v3d_tex_layer_stride otherwise.
- `image_bytes`: the stack's size for 3D (:739, no tree stride added),
  v3d_tex_layers_size for the layered kinds.
- `state`: depth = layers(b); a 3D record's array_stride_64 is level 0's
  slice size / 64 (:765-766, v3dx_state.c:961), the C's
  v3d_tex_state_from_layout_3d.
- `tile`: a 3D texture's level L has max(depth >> L, 1) slices in the GL
  core's first slots (gl::texture::depth_at), each stored k * size after
  the level as Mesa's own upload does one z at a time (:136-150,
  :398-412); the padding slices are left alone.

Unit tests (on the fakes: the rules, and the fake-derived arithmetic
