What
Implement preliminary MLX octree traversal and anchor sampling using the systematic allocation primitive. Closes #32 once merged.
Why
The octree decoder predicts child probabilities; generating a requested number of 3D anchors requires variable-size descent, count-preserving allocation and jitter within selected leaf cells.
How
For each level, evaluate child logits, allocate counts using explicit local MLX random keys, and stably pack non-empty cells per batch. Expand final leaf cells into the requested anchors and add uniform jitter. Dynamic cell packing synchronizes with the host; the implementation uses FP32 conditioning and enforces documented count, level and seed limits.
```
flowchart LR
  C[Parent cell centers and counts] --> M[Octree model logits]
  M --> R[Systematic child allocation]
  R --> P[Pack nonempty children]
  P -->|next level| C
  P -->|final level| E[Expand counts and jitter leaves]
  E --> A[3D anchors]
```

How to test
IDOL_REFERENCE_SOURCE=../idol-sdk-reference python -m unittest discover -s tests -v: 95 passed locally using Python 3.13.14.
IDOL_REFERENCE_SOURCE=../idol-sdk-reference IDOL_TEST_MLX_DEVICE=cpu python -m unittest tests.test_octree_traversal -v; repeat with gpu on Metal. Controlled PyTorch parity, multiple batches, levels 0–3, count/distribution, reproducibility, validation and synthetic checkpoint diagnostic pass.
With trusted local trained files and the pinned source on PYTHONPATH, run python -m scripts.validate_octree_traversal --config /trusted/config.json --checkpoint /trusted/decoder.safetensors --device gpu; repeat with cpu. For 32 anchors at level 2 and fixed offset/jitter 0.375, all 96 coordinates matched exactly on both devices.
This single trained-weight case uses synthetic conditioning and controlled randomness. It does not establish full-scale memory/runtime, arbitrary-input parity, mixed precision or end-to-end inference.
