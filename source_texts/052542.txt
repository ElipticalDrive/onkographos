Fix voxel GI/AO cone tracing
…
d1ba2a6
```
Rework the voxel path to trace cones directly in the mesh shaders instead
of resolving GI into screen-space buffers, and drop the parts that this
makes redundant.

Renderer:
- Trace diffuse/specular/AO/refraction from conetrace.glsl in the forward
  base pass, removing the voxels_diffuse/voxels_specular/voxels_ao
  screen-space resolve round trip and its pre-clear bookkeeping.
- Remove the voxelsLight bounce pass (voxel_light.comp.glsl) and the
  voxel_resolve_refraction/voxel_resolve_shadows compute shaders.
- Remove the _VoxelShadow path: it is not emitted any more, so drop the
  voxels_shadows target, its sampleLight/cluster plumbing and the UI
  toggle.
- Bind the shadow map before drawMeshes("voxel") so voxelization sees
  direct light; add sampleLightVoxels() for it.
- Weight voxel diffuse by cone coverage and by Fresnel (F), and feed the
  Bayer dither with the screen-space motion vector so the temporal pass
  has something to reproject.
- Use standard texture formats (R8/R16/R32) for the voxel targets and
  split gbuffer_refraction out of the rp_ssrefr block so voxel refraction
  can share it.
- Add std/aabb.glsl and std/constants.glsl (cone directions, apertures),
  replacing std/voxels_constants.glsl.

Fixes found while separating these changes out:
- Restore the sun term in make_forward_base: direct += lambertDiffuseBRDF
  + specularBRDF was dropped, silently removing sun lighting from the
  forward renderer.
- Declare a zero velocity fallback when _Veloc is absent. traceSpecular
  and traceRefraction always take it, so Voxel GI without TAA or object
  motion blur failed to compile.
- Keep indirect = envl for Voxel AO. The condition tested '_VoxelAO',
  which only matches as a substring of '_VoxelAOvar', so AO mode zeroed
  indirect and discarded the AO-attenuated ambient.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

Support Blender 5.x sky models (single/multiple scattering)
…
c0f6680
```
Blender 5.0 removed the 'NISHITA' sky type and split it into
'SINGLE_SCATTERING' and 'MULTIPLE_SCATTERING'; a 5.2 node reports
sky_type enum items ['SINGLE_SCATTERING', 'MULTIPLE_SCATTERING',
'PREETHAM', 'HOSEK_WILKIE']. parse_tex_sky() matched only 'NISHITA',
so every Blender 5.x world using the default sky fell through to
"Unsupported sky model!" and returned black. World shader generation
then aborted, leaving no World_<name> shader for the render path to
load.

Route both new identifiers to the existing Nishita parser, keeping
'NISHITA' so the file still works on Blender 4.x. Both models are
approximated by the one implementation.

Blender 5.0 also renamed the node's 'dust_density' property to
'aerosol_density' ('dust_density' no longer exists), so read whichever
is present when filling arm_nishita_density.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

Use float formats for the voxel radiance atlas and SDF
…
887052c
```
The render target formats in Inc.initGI did not match the layout()
qualifiers the compute shaders declare for the same images. In OpenGL
an image unit's declared format must match the texture's internal
format, so these accesses were undefined.

- voxelsOut / voxelsOutB (Voxel GI) were RGBA32, which iron maps to
  RGBA8, while voxel_temporal and voxel_offsetprev declare them
  rgba8. Both move to RGBA64 / rgba16f: the atlas stores radiance,
  which is HDR and must not be clamped to [0,1].
- voxelsOut / voxelsOutB (Voxel AO) were R8 against an r8 declaration;
  both move to R16 / r16f.
- voxelsSDF / voxelsSDFtmp were R8, which iron maps to L8 (8-bit
  normalized), while voxel_temporal and voxel_sdf_jumpflood declare
  them r16f. The SDF holds a world-space distance (voxelSize * 2 *
  res) that cannot be represented in [0,1]. Restored to R16, as
  upstream had it.

Only traceSpecular and traceRefraction pass use_sdf = true, so the SDF
format corrupted specular and refraction cone marching while leaving
diffuse untouched.
```
