Purpose
An isosurface is the surface on which a scalar field defined over a volume takes a given value: the three-dimensional counterpart of a contour line. It shows the shape of a region of a volume, such as a vortex core identified by a Q-criterion, a density shell in a simulation, an organ boundary in a CT scan or a concentration front in a reacting flow. Several translucent isosurfaces at different values, or one isosurface with end caps where it meets the edge of the volume, are common in scientific figures.
IronLAB currently has no volumetric data: its grids are two-dimensional. This issue therefore also proposes the volume grid that #141, #142, #143, #138 and #139 would share, and that should be designed once.
Example
Source: Plotly documentation.
Examples in other libraries
matplotlib: No native chart type. The usual route is to extract a triangle mesh with scikit-image's marching cubes and draw it with Axes3D.plot_trisurf or a Poly3DCollection.
MATLAB: isosurface extracts the mesh, isocaps computes end caps where the isosurface meets the volume's boundary, and isonormals computes vertex normals from the field's gradient for smooth lighting; the result is drawn as a patch.
Chart.js: No three-dimensional charts and no widely used plugin that provides them.
Plotly: 3D isosurface plots (the isosurface trace), with isomin, isomax and surface_count choosing the values, and optional caps and slices.
Typical API
isosurface takes a volume grid, a three-dimensional array of values and one or more iso-values, and converts the axes to three dimensions. Colour is uniform per iso-value or mapped from a second field sampled on the surface.
```
let x = fig.data("x", xs); let y = fig.data("y", ys); let z = fig.data("z", zs);
let q = fig.data("q", q_values);              // shape [nz, ny, nx]
let mut ax = fig.axes3(0, 0);
ax.isosurface(&x, &y, &z, &q)
    .iso_values([0.1, 0.5])
    .face_opacity(0.4)
    .caps(true)
    .color_data(&pressure).color_scale(scale);
```
Sketch of the IR, for review and not a decision:
```
pub enum VolumeGrid {                         // shared by all volumetric artists
    Rectilinear { x: NodeId, y: NodeId, z: NodeId },   // [nx], [ny], [nz]
}
Artist::Isosurface(Isosurface {
    id, label, visible,
    grid: VolumeGrid,
    values: NodeId,               // [nz, ny, nx]
    levels: Vec<f64>,
    caps: bool,
    face: ColorSpec, color_data: Option<NodeId>, color_scale: Option<NodeId>,
    edge: ColorSpec, face_opacity: f64,
})
```
Levels: one or more iso-values, or a count spread between limits as Plotly's surface_count does.
Caps: whether the surface is closed where it meets the boundary of the volume.
Colour: per level (through the colour scale, as filled contours are), uniform, or by a second field interpolated onto the vertices.
Normals: computed from the field's gradient, as isonormals does, for smooth shading; this depends on Add interpolated (Gouraud) shading with PDF mesh shadings #5.
Opacity: translucent nested surfaces are the usual way to show several levels, which raises the ordering problem described below.
The data array type is already n-dimensional, so a [nz, ny, nx] array needs no change to DataArray; what is new is the volume grid and validation of its shapes.
Isosurfaces are closed, curved and often nested, so the painter's order will rarely match the depth-tested picture, and translucent nested surfaces need order-independent transparency to be correct in the viewer at all (see the consequence about translucent faces in ADR 0013 and #34). The export report must record the raster fallback with its typed reason whenever this happens.
Possible duplicates and overlaps
contour: an isosurface is the volumetric analogue of an isoline and should follow the same rules for levels and colour by level.
Add triangulated mesh chart type #134: the extracted surface is a triangle mesh; if the mesh is extracted in the facade, an isosurface is simply a triangulated mesh artist with no new variant.
Add patch chart type #103: MATLAB draws isosurfaces as patches; a general 3D patch artist could also hold the extracted mesh.
Add volume slice chart type #141, Add volume rendering chart type #142, Add voxels chart type #143: these share the volume grid and the three-dimensional value array.
Add interpolated (Gouraud) shading with PDF mesh shadings #5: smooth shading of an isosurface needs vertex normals and lighting.
Let artists share a data array through the facade #26: the volume and its grid are large and will often be shared by an isosurface, slices and cones in one figure.
Alternative approaches
Extract the mesh in the facade (marching cubes) and store a triangle mesh: the IR stays small and the compiler does no extraction, but the figure loses the volume, so the viewer cannot change the level and the stored mesh may be much larger than the volume.
Store the volume and the levels, and extract in the scene compiler, as sketched: the level becomes an editable property and the figure holds the data rather than a derived product, at the cost of marching cubes in the compile path and its cost on every recompile.
Support curvilinear volume grids from the start, or only rectilinear ones: rectilinear grids cover most simulation and imaging output, and a curvilinear variant can be added later as a new variant of the tagged grid.
