Motivation
Add support for Dynamic Diffuse Global Illumination (DDGI) sampling in the hybrid GI resolve pass so the renderer can read probe-volume atlases and improve dynamic indirect lighting quality.
Expose DDGI volume parameters, atlas layout and visibility tuning to the GPU-side resolve pass so sampling can be biased/filtered and blended with existing light-probe / sky fallbacks.
Description
Extended the WGSL ABI by adding DDGI-related fields to GiResolveParams (ddgi_origin_blend, ddgi_spacing_bias, ddgi_probe_counts_flags, ddgi_atlas_layout, ddgi_visibility) and a GI_RESOURCE_DDGI flag.
Added new bindings in gi_resolve.comp.wgsl for the DDGI irradiance atlas, distance/depth atlas, probe-state storage and relocation offsets, and implemented DDGI sampling helpers: oct_encode, ddgi_probe_index, ddgi_atlas_coord, ddgi_sample_probe, and resolve_ddgi which: reconstructs world position, applies normal/view bias, computes base probe cell and trilinear weights, samples up to eight probes, evaluates octahedral irradiance, weights by probe state and distance-based visibility, and gracefully falls back to light probes/sky if DDGI is unavailable.
Added a params.selected_method == GI_RESOLVE_METHOD_DDGI branch in the shader main to call resolve_ddgi.
Mirrored all layout/struct-size and bind-group changes in Rust by updating GiResolveParams in vetrace_engine/src/rendering/wgpu_renderer/types.rs, adding the size assertion, adding DDGI availability to gi_resource_flags, and updating WGPU bind group layout and bind group entries in renderer_impl.inc.rs to include the new DDGI resources with safe fallback resources when absent.

let probes_per_row = max(atlas_dims.x / max(probe_texels.x, 1u), 1u);
let tile = vec2<u32>(probe_index % probes_per_row, probe_index / probes_per_row);
let oct = oct_encode(normalize(dir));
let texel = vec2<u32>(clamp(oct * vec2<f32>(probe_texels - vec2<u32>(1u)), vec2<f32>(0.0), vec2<f32>(probe_texels - vec2<u32>(1u))));
return vec2<i32>(min(tile * probe_texels + texel, atlas_dims - vec2<u32>(1u)));
Use DDGI tile strides with border texels
When resolving atlases produced by the DDGI update passes, this address math treats params.ddgi_atlas_layout.xy/zw as the full tile stride. The update shaders write inner texels at probe_tile_origin(probe, inner + 2, ...) + id.xy + 1 (for both irradiance and distance), so with the default 8/16 inner sizes the resolver samples the border/previous probe texels and computes too many probes per row for multi-probe volumes. That makes DDGI irradiance/visibility come from the wrong atlas locations whenever the generated atlases are used.

@group(0) @binding(14) var<storage, read> ddgi_probe_state: array<vec4<f32>>;
Match DDGI probe-state buffer layout
This binding is read as array<vec4<f32>>, but the classifier shader writes the same probe-state buffer as array<u32> (ddgi_classify.comp.wgsl binding 2). In DDGI mode that changes the stride from 4 to 16 bytes and reinterprets 0u/1u state bits as floats, so most probes read the wrong slot (or robust OOB zero) and state.x >= 0.0 treats inactive probes as active. Use the same array<u32> layout in the resolve shader or write matching vec4 state records.
