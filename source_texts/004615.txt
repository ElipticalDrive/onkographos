Abstract
Direct volume rendering using volume ray-casting and indirect volume rendering using the Marching Cubes isosurface extraction are popular techniques for volume visualization. Surface ray-tracing is a popular graphics technique for rendering scenes composed of well-defined surface primitives. However, these techniques are relatively computationally intensive. Thus, near-real-time computational performance is a difficult goal. This paper presents approaches to these rendering and volume visualization techniques that are tuned for efficient performance on a vector-parallel supercomputer. The approaches decompose and reconstruct the techniques to exploit inherent data parallelism and the specific characteristics of the CPU. Experimental results for several datasets are also exhibited.

Introduction
Volume visualization has great potential for improving understanding of complex datasets in many application domains. However, achieving acceptable computational speed for interactive visualization has been a challenging goal. It is also challenging to achieve reasonable computation time for certain graphics techniques. A large number of parallel approaches have been developed to enable reasonable performance for visualization and rendering. Many of the approaches have focused on load-balancing to allow efficient utilization of processors in multi-processing environments. However, there has been much less attention focused on approaches to visualization that exploit powerful vector processing capabilities. A number of limitations of vector processing must be carefully addressed in order to achieve optimal algorithm performance. In this paper, we present reconstructed approaches to three popular visualization and rendering techniques and demonstrate that the approaches can deliver efficient performance in a vector processing environment.
A number of multiple instruction multiple data (MIMD) approaches for visualization and/or rendering have been described in the literature. Nieh and Levoy [1], for example, developed a task queueing scheme for efficient volume ray-casting on MIMD machines. Law and Yagel [2] have presented an efficient distributed memory volume ray-casting method that carefully exploits coherency to achieve good scalability. Lacroute [3] has balanced the performance of shear-warp factorization for volume ray-casting in an MIMD environment. Köse and Chalmers [4] have presented a parallel approach to volume ray-casting for a network of transputers that utilizes load-balancing based on processor cache profile. Singh et al. [5] have demonstrated efficient shared memory multiprocessor implementations of a few visualization and rendering algorithms. Green and Paddon [6] and Horiguchi et al. [7] have explored efficient surface ray-tracing in a multi-processor environment. Highfield and Bez [8] have investigated hidden surface elimination algorithms using MIMD parallelism on a network of transputers.
Some efficient single instruction multiple data (SIMD)-parallel approaches for visualization and rendering have also been presented in the literature. Smith et al. [9], for example, have developed a SIMD-parallel method for experimental interactive visualization. Schröder and Salem have presented a technique for rotating volume data quickly using data-parallel SIMD computation [10]. Hansen and Hinker [11] have developed an isosurface extraction method that is tuned for a SIMD computer. Ogata et al. [12] have described a systolic array structure for efficient object-order volume ray-casting. Hsu [13] has demonstrated a data-parallel SIMD approach for ray-casting. A parallel polygon rendering method for SIMD machines has been described by Whitman [14]. Progressive radiosity has also been computed using a massively parallel approach by Renaud and Rousselle [15].
However, we are aware of only a small number of research efforts that have explored SIMD vector- or pipeline-parallel computation for visualization or graphics. (In other image-related application areas, approaches that effectively exploit vector-parallelism have been more common. For example, Heras et al. [16] have recently demonstrated a reconstructed approach to the image processing's principal component analysis.) Efforts for vectorized rendering include the surface ray-tracing approach of Plunkett and Bailey [17]. In addition, Machiraju and Yagel [18] have presented a feedforward volume rendering method and reported results for a multiple-processor machine with hierarchical shared memory and pipelined processing elements. Schneider and van Welzen [19] have investigated optimization of polygon clipping for SIMD pipeline computation.
Crockett [20] has presented an excellent recent survey of parallel rendering, and the reader is directed to that survey for additional background information about the topic.
The vector-parallel supercomputer available to us was a Cray C94A with two CPUs. This machine has 64 MWords (i.e., 512 MB) of main memory1 with access bandwidth of 1200 MB/s, a 256 MB solid-state storage device with 1000 MB/s bandwidth, and a 50 GB disk subsystem. Each CPU of the C94 operates at approximately 240 MHz (the CPU clock period is 4.2 ns) and has two vector processing pipelines that yield a peak performance of approximately 1 GFLOP. Each CPU has 15 functional units, including 3 integer add units (that together can perform a single vector add or 3 scalar adds), 1 scalar integer multiply unit, 3 shift units, 3 logical units, 1 floating point add unit (usable for either scalar or vector operation), 1 floating point multiply unit, 1 reciprocal approximation unit (usable for either vector or scalar operation), and 2 population count units. Each CPU also has 8 vector registers, each of which can contain up to 64 64-bit elements. A single vector operation can produce a vector of up to 64 results from one or two vector operands (some vector operations can involve one scalar operand).
In practice, the main operations that can be vectorized on vector-parallel computers are calculations — especially calculations on elements of arrays — within loops. However, there are some limitations on loop vectorization. One important requirement for optimal vectorization is that there should be no dependence between the inputs or between the outputs. For example, Loop 1 below could be vectorized on a vector-parallel machine. However, Loop 2 cannot be vectorized because the operation on one element of the array depends on the calculation result from the previous element. This is called a flow dependence [21], [22]. Other factors that limit vectorization include memory contention and certain branchings (including some conditionals). Optimal vectorization generally requires a constant (and usually a small) stride of memory access as well. Thus, the time improvement of any application on a vectorized computer will depend on the structure of the data and the arrangement of the execution flow.
Although vector-parallel CPUs are extremely powerful, directly using modules that were developed for conventional machines generally will not take full advantage of the vector capabilities. The compilation tools available on many vector-parallel computers (including the C compiler we used on the Cray C94) can do some optimization automatically, however the optimization is generally quite limited if the program is not restructured in both data structure and execution flow. A rule of thumb is that code ported directly to a vector-parallel machine and compiled with vector-optimization will yield an execution time improvement of only two or three times over a non-vectorized executable. Through careful restructuring of computations and data, improved performance may be possible, however. There are particular difficulties with mapping visualization and rendering techniques to SIMD environments. Lacroute [3] has observed, for example, that the special cases associated with volume rendering make it difficult for the algorithms to map well onto SIMD arrays. In fact, the best SIMD performance for rendering often occurs for “brute-force” approaches with uniform communication patterns [3]. Drebin et al. [23] have also noted that ray-casting approaches require random access (or access along an arbitrary line) to a voxel array, which is a serious obstacle for vector-parallel computation.
Support for SIMD-style parallelism has become more ubiquitous recently with the introduction of SIMD instructions in widely available microprocessors, including Sun VIS, Intel MMX, AMD 3D-Now, and Intel Streaming SIMD Extensions (SSE) instruction sets. The techniques that we present also offer insight into how efficient performance could be achieved for visualization and rendering techniques implemented on current and forthcoming commodity microprocessors.
This paper is organized as follows. In Section 2, our reconstructed approach to the Marching Cubes isosurface extraction is presented. In Section 3, our vector-efficient approach for surface ray-tracing is presented. Section 4 introduces our reconstructed approach to the volume ray-casting. The paper concludes in Section 5.

An efficient and scalable parallel algorithm for out-of-core isosurface extraction and rendering
Wang Q., …, Varshney A.
Journal of Parallel and Distributed Computing • Volume 67 • 2007
Show abstract
We consider the problem of isosurface extraction and rendering for large scale time-varying data. Such data sets have been appearing at an increasing rate especially from physics-based simulations, and can range in size from hundreds of gigabytes to tens of terabytes. Isosurface extraction and rendering is one of the most widely used visualization techniques to explore and analyze such data sets. A common strategy for isosurface extraction involves the determination of the so-called active cells followed by a triangulation of these cells based on linear interpolation, and ending with a rendering of the triangular mesh. We develop a new simple indexing scheme for out-of-core processing of large scale data sets, which enables the identification of the active cells extremely quickly, using more compact indexing structure and more effective bulk data movement than previous schemes. Moreover, our scheme leads to an efficient and scalable implementation on multiprocessor environments in which each processor has access to its own local disk. In particular, our parallel algorithm provably achieves load balancing across the processors independent of the isovalue, with almost no overhead in the total amount of work relative to the sequential algorithm. We conduct a large number of experimental tests on the University of Maryland Visualization Cluster using the Richtmyer–Meshkov instability data set, and obtain results that consistently validate the efficiency and the scalability of our algorithm.

Approaches to achieve high performance for volume visualization via the popular Marching Cubes algorithm on commodity x86 personal computers are described. The approaches utilize Single Instruction Multiple Data (SIMD) Within A Register (SWAR) capabilities available in the streaming media extensions of recent-generation x86 CPUs. The SWAR capabilities are exploited in a manner that enables simultaneous processing of multiple volume data points, edges, and cells. In addition, the approach maintains the rendering quality of a standard serial implementation of the Marching Cubes. An average overall speedup of nearly four times is achieved (compared to an unoptimized standard implementation that uses conventional serial processing).
