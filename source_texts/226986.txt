Changes visible to existing users
Normals change for every case, so incidence angles (and possibly placements) shift by a few degrees. No test pins the normals; the legacy bit-for-bit golden test still passes.
Report / render_transparency_surface now draw meshes (needs scikit-image; falls back to dots without it). Writing the report takes ~20–40 s longer.
Mirrored registrations (e.g. Halle, voxel i = Left) were culled on the wrong side by the old 3-D dot code; fixed.
Notebook
Skull built with shell_speed_map at the solver pitch. The six sinus/mastoid cavity shells in the ITRUSST outer STL are still filled as bone (fill_cavities=True, matching the benchmark's surf2vol 'fill').
SMOOTH_MM = 1.0 on the map itself (replaces the 2 mm display-only smooth).
Ran end to end locally with nbclient on GPU 0: all cells OK. dACC: incidence 4.4°, window near AF3.
The interactive widget (section 6) still draws dots, to keep slider redraws fast.
Tutorial
Only Figure 5 (Halle brain-center map) depends on the changed code: regenerated with a 2-voxel smooth (0.56 mm) and surface drawing; the command and caption mention it. The solves are CT-based and unchanged. The positioning-tool screenshot comes from the manuscript-era tool, which doesn't call this code. PDF built with the manuscript animation frames linked in.
Pre-existing caption issue, not changed here: Figure 5's caption says the orbits read dark, but they render bright in both old and new figures.
Tests
New test_rasterize.py, test_surface_smoothing.py. Full suite: 131 passed, 2 skipped (before the final renderer-orientation fix); after it, the renderer/report/brain-center/CLI subset passes (36).

The map showed rings and fine stripes. Traced to four stages:

- drawing: patches sit on the voxel lattice, and as dots they leave gaps
  along the terraces that read as rings. New surface_render.patch_surface
  meshes the patch sheet (bin, blur, marching cubes); report and render
  draw it as a solid surface. Directions are carried through the
  registration, so a mirrored grid no longer culls the wrong side (a
  latent bug in the old dot code too).
- field: about half of the sub-3 mm texture depends on how the bone
  boundary is voxelized (rotating the skull 12 deg against the grid
  before rasterizing changes it; r = 0.55). New
  TransparencyOptions.smooth_mm / --smooth-mm smooths along the surface;
  ~2 voxels removes it (two voxelizations then agree to 0.23 dB median).
  Default 0, so existing results are unchanged.
- input meshes: new rasterize.shell_speed_map rasterizes closed meshes
  straight onto the solver grid with partial-volume edges (crossing
  parity + plane cut; matches exact signed distance, 12 s for ITRUSST).
- normals: bone_occupancy ramp instead of a hard threshold; median error
  vs the true surface 3.4 -> 1.8 deg on the ITRUSST skull. This shifts
  incidence angles slightly for every case.
