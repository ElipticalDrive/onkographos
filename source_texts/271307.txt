In the kernel:
```
__kernel void buildRadixTree(__global struct BVHNode* nodeBuffer,__global uint2* mortonBuffer, uint leafCount)
{
	uint idx = get_global_id(0);
	if (idx < leafCount-2)
		constructNode(nodeBuffer,mortonBuffer,leafCount, get_global_id(0));
} 
```
it seems it should be "leafCount-1".
Otherwise there will be crash when you have one triangle on certain big distance in positive direction. In that case this triangle will be last element in morton code array.

Hi Timur
I have some crashes on machine with Nvidia Quadro K5000, but I blame driver set or corrupted memory. Other experiments I do on Intel integrated GPU or Intel CPU - and in general I don't have any crashes.
I read your master thesis already - it is really great review of pretty useful techniques. Unfortunately, some pictures with test results are in low resolution and not readable.
I implemented this linear BVH for my particle system, and performance is not too great with big particle systems (above 100000 points). Each point with variable radius can be leaf. The construction time is ok (also there is room to make it even faster with optimize sort algorythms). It is worse with traversing: there are a lot of tests with inner (not leaf) nodes. For 2^17=131072 particles we have about 200 or more tests for each particle with inner (not leaf) nodes - because we have intersections of these nodes and tested particle that has some radius. Theoretically we could have 17 + 17-1=33 inner tests for ideal case when we test particle with zero radius.
How could we solve this issue? May be combine grid approach with BVH: introduce fake primitive which will contain set of particles in small cell. It will decrease height of BVH hierarchy.
Or convert it to kd or octree - where intersections of nodes are more predictable (or we don't have them at all).

Hi,
I think that with the KD trees you will achieve much better results.
As a matter of fact, by using KD trees you will have the advantage of fast
and efficient construction algorithm,
and much faster traversal compared to BVH trees.
In my work I've noticed the differences between construction and traversal
times, and what I got is that
Grid -> Slow construction,fast traversal
BVH -> Fast construction, slow traversal.
In the article about the BVH construction the author mentions the
applicability of the algorithm to construct KD trees. It might even be
worth contacting the author of the article for advice about traversal
algorithm for KD tree which was created with his algorithm.
In my opinion, this may yield a considerable performance gain compared to
the algorithms I used, or a combination between them.
