Context
Decision D2: greedy is the only mesher. Naive meshing exists only for updateForBlockChange, and greedy quads cannot use that path.
Today the mesher makes 4 VoxelVertex (48 bytes each), 6 indices, quad_block and quad_highlight for each quad. That is about 221 bytes. The upload then packs each quad into a PackedQuad of 16 bytes. Workers will send meshes through postMessage, so the mesher must make the GPU format directly (C5).
Scope
Remove MeshingMode.naive, the --meshing flag, updateForBlockChange, quad_block and the code that only these use.
Make the mesher write a list of PackedQuad and the y range of the mesh. Remove the VoxelVertex and index lists from Mesh.
Change uploadChunkMeshToGPU and the async result (async_chunks.zig) to use the packed quads.
--depth-stencil=off uses sortByDepth for a back-to-front order. Keep it working with packed quads.
Replace the debug highlight for each quad (quad_highlight) with one value for each chunk, "rebuilt at time t". The shader tints a chunk orange after a rebuild and the tint fades in about 0.5 s. Cmd+G and Ctrl+G still toggle it.
Remove examples/voxel/tests/greedy_vs_naive.sh and greedy_vs_naive.tas. Update the docs and the rules file.
Out of scope
The choice between keeping --depth-stencil=off and removing it. Ticket perf: the voxel web main thread never copies mesh bytes swindowzig#12 asks Sean.
Acceptance Criteria
bench_mesher gives the same quad hash as before: 4b4f00654f783b36. Hash the new mesher output with the same algorithm.
The PR states the bytes for each quad before and after the change.
The lavapipe goldens do not change.
The headless framespike.tas exits 0.
Nothing refers to naive meshing.
The on-machine session checks the dig, the place and the Cmd+G tint in a browser.
