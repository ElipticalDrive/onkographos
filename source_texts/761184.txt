Perhaps we need to write vvvv node that copies the texture while integrating the locking mechanism.
Also found this: [http://stackoverflow.com/questions/3249279/copy-texture-to-texture]
Shared surfaces are tricky: because rendering commands (including Copy*()) are queued by DX, you need to somehow make sure the queue is flushed and commands completed before reading from the shared surface. Disposing the texture probably does this implicitly. In C++ you'd use the IDXGIKeyedMutex interface to accomplish this without destroying and re-creating the source texture; I don't know whether this is available in SlimDX.
