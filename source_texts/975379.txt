Part of #326 (its unchecked Streaming item). The Blender pipeline already writes a scene as tiles (docs/pipeline.md), and every tile is loaded at start.
Where it fits: the pipeline and the scene layer.
The pipeline writes each cell's file (meshes, materials, props, colliders, nav), plus a coarse stand-in for when it is far (HLOD: merged, simplified geometry with baked textures).
At run time a streamer keeps resident the cells within a loading radius of the camera, and on a host of each player.
It reads and decodes on the job system, uploads to the GPU within a per-frame budget in megabytes, and adds colliders to aephysics and nav cells to ae3d.nav as each cell arrives.
It frees a cell once it leaves the radius plus a hysteresis margin. Far cells draw their HLOD.
Each cell is a small state machine (unloaded, loading, resident, unloading), readable through the agent channel.
How others do it: UE5's World Partition (a grid with a loading range per cell, HLOD layers, data layers); Unity's addressable scenes loaded additively. RAGE streams a grid of map sections around the camera.
Done when, on a test world of stated size built from the pipeline's tiles and driven across at 30 m/s:
resident memory stays under a stated ceiling;
no cell inside the loading radius is ever missing;
streaming adds no frame over a stated time (p99 frame time against the same drive with everything loaded);
colliders are in place before a body reaches them.

Answers from the code (2026-11-02), and how this fits.
Today: nothing streams.
zombie_city builds its 7 modelled street copies at start-up (add_tile, zombie_city:518, 1402-1409). Around them it re-places 209 instanced blocks when the camera changes block (city_follow, 923-946). Nothing is loaded or unloaded at runtime.
There is no cell or tile concept in src (voxel keeps one flat grid).
Uploads are all on the main thread: Vulkan textures through a one-off submit (vktexture:219-246), Vulkan meshes batched and flushed before the frame (vkhost:427-490), GL's gl_texture_from_image directly (gl:3898-3909).
Off the main thread: image decode only, through std.worker while a scene loads, which waits for all of it (core:355-410, scene:1741-1745).
There is no per-frame upload budget, and the job system does no loading.
Fit: #326 needs it, in three parts.
Cells: the world partitioned in xz, each cell a scene file (the format scene and persist already read and write), loaded and dropped by distance and priority. A street block is a cell as it stands.
Work: decode and mesh building on the job pool.
Uploads: on the main thread within a per-frame byte budget (on Vulkan a staging ring, a transfer queue later; on GL, PBOs later).
Done when:
zombie_city's blocks load as cells while the camera crosses the city, with no frame over its upload budget and memory bounded by the cells in range, both measured.
