Security Architecture Review
Security architecture risk: 🟡 Moderate · up to bbf65
A multi-series image export uses one look-up table for the whole selection, even though display choices belong to individual series. This could produce images that do not reflect each series’ chosen appearance. Raw DICOM export remains separate, and no attacker-driven security exploit was established.
Retained concerns
Medium · architecture · inferred: A multi-series PNG/JPG selection receives one request-wide LUT rather than resolving each selected series’ LUT. When series have different choices, exported appearance may not match their respective display state; whether a uniform export appearance is intended remains unresolved.
Low · reliability · inferred: Selection commits the series LUT before refreshing the view and thumbnail. If refresh fails, stored state can differ from the image still visible; the focused callback has no rollback.
Security review details
Security Blast Radius
inferred — The identified LUT propagation affects local rendered images and raster exports, including batch selections. The inspected raw-DICOM export path does not consume it.
Trust Boundaries and Controls
observed — The inspected export code keeps dataset saving in a separate DICOM branch and sends LUT settings through the rendered-image branch.
Resilience and Maintainability Implications
inferred — A refresh failure after a series-state write could leave the visible image and subsequently read LUT state out of step; higher-level recovery behavior was not established.
Hardening Proposals
proposed — Make the intended multi-series export policy explicit: either resolve display settings for each selected series or clearly designate the request-wide LUT as a uniform export override.
