Stacked on #22. Spec 0009, slice 3: map viewer vertices back to source points.
What
getMesh(path, { vertexToPoint: true }) (and the async variant) returns vertexToPoint: Uint32Array, the source point of every vertex: the identity for layout 'points', the corner's face index for 'corners'. groupByFaceSet reorders triangles, not vertices, so the map is unchanged.
buildThreeScene(file, THREE, { vertexToPoint: true }) stores it as a plain array in userData.alembic.vertexToPoint (it survives GLTFExporter, like triangleToFace). AbcPlayer rebuilds keep it.
getVertexToPoint(node) in alembic-js/stream (and the main entry) returns it as a Uint32Array.
applyFrame(): a mesh record (changed topology) drops the node's vertexToPoint, since the scene's map doesn't fit the new vertices. The next deform record restores it, like triangleToFace. This is recorded in Decisions.
Tests (test/compare.test.ts)
Only returned when asked; identity for 'points'.
For a corners layout, positions[v] == pointsLayout.positions[vertexToPoint[v]] for every vertex, and the map equals the raw face indices.
The same holds for the face-varying cube (with and without groupByFaceSet) and the Blender subd asset, checked against .geom/P.
Scene storage survives a JSON round trip; a mesh record drops the map and a deform record restores it.
Testing (what ran here, what didn't)
The npm registry is blocked by network policy in the cloud workspace, so yarn install --frozen-lockfile couldn't run. Tests ran against dependencies assembled by hand:
Alembic 1.8.12 + Imath 3.2.3 built from source with scripts/ci/build-alembic.sh (same versions as CI); the addon built with plain CMake 3.31 + Node 22 headers + node-addon-api 8.3.1 (no cmake-js).
TypeScript 5.9.3, three r170 and @types/three r170 (from GitHub), esbuild 0.28.2 (lockfile: 0.25.11), @types/node 26.
yarn test equivalent (tsc -p tsconfig.test.json && node scripts/run-tests.js) on Linux x64, Node 22: all tests pass, including the existing suites.
Prettier 3.8.1 --check: clean. clang-format: 18.1.3 (CI pins 22.1.8): clean.
Not run here: ESLint (typescript-eslint not installable), the sandbox smoke test, Windows/macOS builds, prebuild packaging. GitHub Actions CI runs on this branch and covers them; check it before merging.
How to merge this stack (one release)
Every push to main runs semantic-release, and main requires squash merges, so merging these four PRs one at a time would publish a partial 1.2.0 and then 1.3.0. To ship spec 0008 + 0009 together as 1.2.0:
Review each PR in the stack, but don't merge feat: topology info and hash for meshes (spec 0009) #22, feat: vertexToPoint map for meshes and scenes (spec 0009) #23 or feat: attribute records in the frame format (spec 0009) #24 on their own.
When all four are approved, change the base of the last PR (feat: velocities in encodeFrames and spec 0009 docs #25) to main and squash-merge it with a feat: title. That is one push to main and one feat: commit, so semantic-release goes from v1.1.0 to 1.2.0 (minor; there are no BREAKING CHANGE footers).
Close feat: topology info and hash for meshes (spec 0009) #22–feat: attribute records in the frame format (spec 0009) #24 as included in feat: velocities in encodeFrames and spec 0009 docs #25.
