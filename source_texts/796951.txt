Change
2026-10-14 kernel review finding HC-8 (roadmap row B101).
Point classification built its ray BVH from face_aabb, which bounds a NURBS face by evaluating a 9×9 parameter grid. A ridge whose support fell between two grid columns lay outside the box, so the BVH pruned the face from every ray that crossed the ridge, and a point inside the ridge classified Outside.
The classifier now builds its BVH from a new pub(crate) face_ray_bound: face_aabb unioned with a NURBS face's control points. This covers all three paths: one-shot classify_point, PreparedSolid and ClassificationCache. With positive weights, which NurbsSurface::new enforces, the convex-hull property makes the control net a guaranteed bound.
face_aabb itself is unchanged, and so is the public properties::bounding_box built on it. My first attempt changed face_aabb directly. That broke regress_check_bounding_box_curved_edges::extruded_rotated_ellipse_keeps_exact_analytic_box: on a rational NURBS the control net bulges past the surface, so the measured box loosened from -9.2915 to -10.196.
Verification
New crates/check/tests/regress_nurbs_face_box_bulge.rs. The cube's top face is a degree-2 30×30 NURBS patch carrying a 0.0075-high ridge between the old sample columns. On main a point under the crest classifies Outside; here it reads Inside, and a point above the crest reads Outside.

Not run locally: workspace-wide tests. CI covers them.
Known, not fixed here:
face_aabb still under-bounds a narrow NURBS bump in measured boxes. Making it both tight and guaranteed needs subdivision.
intersect_line_nurbs drops the forward exit of a slanted ray through a steep, narrow bump. The test keeps its ridge shallower than the classifier's rays, and this is tracked as a separate task.
Compatibility and risks
No API, format, unit or tolerance changes; the new helper is pub(crate). Performance: BVH boxes for NURBS faces can be looser, so a ray may test a few more candidate faces. Building the bound adds one pass over each NURBS face's control points.

Cache conservative bounds once per one-shot query
For NURBS faces with large control grids, this full control-net scan now runs once for every voting ray because classify_point_with_source calls count_ray_crossings at least twice and that function rebuilds every face bound each time. This changes the one-shot classifier from fixed-size 9×9 surface sampling to at least two O(total control points) passes—and up to one pass per recovery ray—so imported low-degree surfaces with millions of control points can incur repeated document-sized scans for a single point query. Build these conservative bounds/BVH once before entering the vote loop, as the prepared paths already do.

Not changing this in this PR. The per-ray rebuild is real, but here is the cost I traced.
What already happens per ray: the one-shot path rebuilds every face bound and the BVH on each vote ray. That predates this PR, and it is the documented contract: "exactly the work the pre-PERF-Q01 classify_point always did". prepared.rs pins it with oneshot.face_aabb_evals >= 2 * queried * 6.
What it already costs for a NURBS face: face_aabb makes 81 surface evaluations and samples every boundary edge. Each candidate face then builds trim polygons and a 20×20 ray seed grid, about 400 more evaluations.
What this PR adds: one O(n) min/max scan over the control net, about 6 comparisons per point. That only overtakes the existing per-ray work above roughly 10⁴ control points on a single face.
The supported path for heavy queries is PreparedSolid and ClassificationCache. Both build the bound once.
Hoisting the BVH out of the one-shot vote loop is a reasonable follow-up, but it changes that path's work contract and its perf test, so I'm keeping it out of this fix.
