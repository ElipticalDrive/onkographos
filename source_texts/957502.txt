Phase 2 (World explorer review). Size: M–L. Line numbers are as of main 4ffa8f01.
Problem
Terrain is unlit and drawn one triangle per instance:
The stream shader draws each triangle as a 3-vertex instance with no chunk culling (rendering-bgfx/src/main/shaders/world-stream/vs_model.sc:10-21, INSTANCE_BYTES 48, rendering-bgfx/src/main/java/com/vibeminer/rendering/bgfx/WorldStreamPackedTile.java:138-166). The review estimates 10–15x more vertex work than an indexed mesh, and triple the upload bytes (inferred from code, not measured).
There is no normal attribute, so no terrain lighting. MCNR normals, MCCV vertex colours and MCSH shadows aren't used (MCNR and MCSH parsing lands in World terrain: read and hash each root ADT once, cache the WDT, parse MCNR and MCSH #359).
Objects use one fixed light direction (rendering-bgfx/src/main/shaders/world-wmo/fs_model.sc:15-21), separate from terrain and water.
Proposed approach
A static indexed mesh per tile (145 vertices per chunk, shared across the chunk's triangles), with per-chunk index ranges and per-chunk frustum culling.
Vertex attributes: position, MCNR normal, MCCV colour. MCSH as a per-chunk 64x64 shadow mask sampled in the fragment shader.
One shared light uniform block (sun direction, diffuse, ambient, fog) used by terrain, objects and water, filled from World explorer: add source-qualified sky, lighting, fog and time of day #177's light tables (PR Work out sky colours and fog from the recorded light tables (177-1) #350). Until those land, today's fixed values.
Keep gamma-space lighting (the classic client look).
Acceptance criteria
Tests: mesh index layout and holes match today's triangles; normals and colours reach the vertex stream; chunk culling; the light block is shared by all passes.
Native GPU proofs on D3D11 and Vulkan; recompile all shader backends and keep the D3D11 instance-semantics rule.
Vertex count, upload bytes and fps before and after (World explorer: measure tile timings, refusal reasons, draws per frame, fps and GC #353).
Owner check: hills show shading and baked shadows like the client; no seams between chunks.
Refs
World explorer review (renderer F3, F5; terrain data F2). Depends on #359. #177, PR #350, #174, #171. Roadmap #186.

Part 3 (MCSH baked shadows): plan. I estimate it at M–L, so here's the plan before any code.
Data on build 70862 (refusals probe on the library copy, every 4th tile of maps 0 and 1, aggregate only): 12 of 426 sampled tiles have any MCSH in their tex0 chunks. No root ADT in the sample carries MCSH. The reader already parses it: WorldTextureFormats.ShadowState and decodeShadow, with the root "do not fix" flag for the last row and column. So on this build the visible change is small.
Where the shadow goes
Atlas alpha (the default path, so splatting can stay off). The 512² atlas has 32 texels per chunk, and alpha is only coverage today (0 or 255). The composer would write alpha = 255 - strength * shadowed, where shadowed is the 2 x 2 mean of the 64² MCSH bits for that texel, and coverage would become alpha >= 64.
Needs TerrainAtlasComposer, a TerrainTileAtlas.RECIPE bump (new cache keys), and the atlas pixel rule in TerrainTextureBinding.validatePixels.
Splat mask A (the channel reserved by World terrain: MCNR normals, vertex MCCV and the shared World light (#373 part 2) #487): the same shadow at the mask's resolution, 32 texels per chunk at STANDARD and the native 64 at HIGH, so near ground gets crisp edges. The shader reads mask A where the splat is drawn and atlas alpha elsewhere.
Shader (fs_model.sc): a shadowed texel keeps the ambient term and loses the diffuse term (ambient + diffuse * lambert * (1 - shadow)). Whether that's right, and how strong the darkening is, should be pinned from the client. The light tables (World explorer: add source-qualified sky, lighting, fog and time of day #177) carry a shadow opacity; until they're wired in, it's a stated constant.
All four blob profiles get rebuilt, with DX11 from the Windows shader job.
Untextured (height-fallback) tiles get no shadow; they have no atlas.
Tests and proofs
Composer: a known MCSH pattern bakes into the atlas alpha with the right orientation and edge fix, and coverage is unchanged.
Packet validation accepts the new alpha values and still refuses malformed ones.
Owner proof: a lit oracle and a shadowed oracle pixel.
Splat proof: mask A carries the shadow.
All World stream and terrain GPU proofs.
Real data: before/after counts of shadowed chunks per map.
Order: after the splat fixes (#581) and the atlas pool bound (#583), because it touches the same composer and shader.
