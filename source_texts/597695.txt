Summary
Phase 3 of the CGAL removal (docs/cgal_audit.md). Stacked on Phase 2 (#5).
geom::RayMeshQuery (behind Geometry::MakeAABBTree / Geometry::SearchMesh) now builds an Embree 4 (Apache-2.0) triangle scene and finds the nearest hit with rtcIntersect1, replacing the CGAL AABB tree (GPL). Embree traverses in single precision, so the hit point is recomputed in double precision on the reported triangle (ray/plane intersection) and vertices are stored relative to the mesh bounding-box centre. One Embree device is shared per process; each query owns its scene. The Embree 3 API is also supported (RTC_VERSION_MAJOR guard), so Ubuntu Jammy's libembree-dev 3.13 works as well as Noble's 4.3.
One commit: geom: Embree backend for ray/mesh first-hit queries (+ CMake find_package(embree 4) with fallback to 3, linked PRIVATE into the core library; the header stays opaque).
This is the only new dependency added by the whole series, as planned in the task. Note that the audit found no production caller of this path (it is used by tests and available to users of Geometry::SearchMesh); it is replaced because the task asked for Embree to take over all AABB-tree queries.
Golden values
tests/geom/test_geom_baseline.py: 4/4 pass. The six ray/mesh hit points match the CGAL goldens to 1.6e-15 relative (worst component); everything else is untouched by this phase.
Build and tests
Same conda-forge Gazebo Harmonic environment plus embree 4.4.1: library, plugins and tests build; UNIT_Geometry_TEST (8, includes the SearchMesh cases), UNIT_Physics_TEST (6), UNIT_CGAL_TEST (13) pass; ldd libgz-waves1.so shows libembree4.so.4.
