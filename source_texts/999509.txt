Closes #1464.
What
CFBORender::render_RGB() can now simulate a real camera, entirely on the GPU:
setLensDistortion(const TCamera&) / clearLensDistortion() / getLensDistortion(): output images with the camera's lens distortion. Any model supported by camera_geometry::undistort_point() works (plumb_bob, kannala_brandt).
setRGBNoise(float std, uint32_t seed = 0) / getRGBNoise(): independent Gaussian noise per pixel channel, in intensity levels (0-255).
How
setLensDistortion() runs on the CPU, once, and needs no GL context. It undistorts every output pixel into a lookup table, and computes an enlarged ideal pinhole camera that covers the whole distorted field of view, so there are no black borders. If the undistorted field of view is more than 3 times the image size, it throws a "too strong" error.
While distortion or noise is enabled, the scene is rendered into a second FBO (m_fbScene). With distortion, that FBO has the enlarged ideal size and uses the ideal intrinsics; only the camera pose comes from the scene camera or the override.
A full-screen pass (DefaultShaderID::FBO_RGB_POSTPROCESS) then writes the output into the usual FBO:
It samples the scene texture through the RG32F lookup table, with hardware bilinear filtering.
The scene texture is GL_SRGB8, which is decoded when sampled, so the shader re-encodes it and the stored 8-bit values are kept, with or without gamma correction.
It adds noise generated with a PCG hash and Box-Muller.
Depth is read from the scene FBO before the post-processing pass. Lens distortion is not supported for depth yet: render_RGBD() and render_depth() throw while it is set. Noise only affects the RGB image.
The lookup table follows the convention of the existing pinhole projection, where image coordinate (u,v) is the corner of pixel (u,v), not its center. Rendered objects appear 0.5 px up-left of camera_geometry projections, with or without distortion. I added a note about this to agents.md, since it is easy to trip over in tests.
Also refactored: the creation of the color texture of the FBO is shared between both framebuffers.

Tests
New CFBORender_LensDistortion_unittest.cpp:
A marker appears where projectPoint_with_distortion() projects it, with the same offset as the pinhole render.
No black borders with barrel distortion.
Clearing the distortion gives back the exact pinhole image.
Invalid uses throw: too strong distortion, a wrong image size, and depth rendering.
Noise has mean ~0 and the requested std, changes in each frame, is reproducible for a given seed, and can be disabled again.
Distortion and noise work together.
All 72 mrpt_opengl tests pass locally under xvfb-run. The first user is MVSim (MRPT/mvsim#142). Its camera test also passes against this branch.
Summary by CodeRabbit
New Features
Added optional lens-distortion correction and per-channel RGB noise to rendered color images. Noise can be seeded for repeatable results and used alongside distortion; it is disabled by default.
Compatibility
Lens distortion is available for RGB rendering only, not depth or RGB-D rendering, and the distortion camera must match the renderer’s image dimensions.
Documentation
Clarified the pixel-coordinate convention for pinhole cameras and lens-distortion rendering, including the half-pixel offset from camera_geometry projections.

New setLensDistortion() and setRGBNoise() make render_RGB() simulate a real
camera:

- Lens distortion: the scene is rendered with an enlarged pinhole camera
  that covers the whole distorted field of view, and then warped into the
  output image in a second GPU pass, with a lookup table computed once from
  camera_geometry::undistort_point() (any model it supports). Distortion
  strong enough to need more than 3 times the image size is rejected.
- Pixel noise: independent Gaussian noise per pixel channel, generated in
  the same pass (PCG hash + Box-Muller), different in each frame and
  reproducible for a given seed.

Depth rendering does not support lens distortion yet: render_RGBD() and
render_depth() throw while it is set.
