Goal
Add fBm (Fractal Brownian Motion) based procedural terrain generation to the editor, using Perlin noise layers to produce smooth, natural-looking landscapes.
Background
The terrain system stores heightmaps as uint16_t row-major buffers in TerrainData. The editor already has an import pipeline (ApplyImportedHeightmap) that accepts a decoded std::vector<uint16_t> and handles both same-size and resize cases. Procedural generation should feed through this same path.
stb_perlin.h is already present in external/stb-src/ and provides stb_perlin_fbm_noise3().
New class: terrain::TerrainGenerator
Create src/terrain/TerrainGenerator.h / TerrainGenerator.cpp (terrain module, no editor dependency).
```
namespace terrain {

struct FbmParams {
  int     seed        = 0;
  float   scale       = 300.f;   // world-space noise period in metres
  int     octaves     = 6;
  float   persistence = 0.5f;    // amplitude falloff per octave
  float   lacunarity  = 2.0f;    // frequency multiplier per octave
};

class TerrainGenerator {
 public:
  // Generates a width×height fBm heightmap. Output values span [0, 65535]
  // mapped linearly to [min_height, max_height].
  static std::vector<uint16_t> GenerateFbm(
      int width, int height,
      float meters_per_texel,
      float min_height, float max_height,
      const FbmParams& params);
};

}  // namespace terrain
```
One .h / .cpp pair; follow src/CLAUDE.md conventions.
UI: Generate floating window in TerrainEditorPanel
Add a Generate button in the toolbar area of TerrainEditorPanel that opens a floating "Generate terrain" window (same Open/Render pattern as the existing Import window).
The window must expose all of the following parameters:
Section
Parameters
Terrain size
World width (m), world depth (m), metres per texel
Height range
Min height (m), max height (m)
Algorithm
fBm (this issue) — dropdown extended by future issues
fBm parameters
Seed (int), Scale (m), Octaves, Persistence, Lacunarity
Controls:
Randomize seed button — picks a new random seed without regenerating, so the user can then hit Generate to audition it
Generate button — calls TerrainGenerator::GenerateFbm and feeds the result into ApplyImportedHeightmap; if dimensions changed, the existing resize-confirmation modal is reused
The window stays open after generation so the user can tweak parameters and generate again without reopening it
Acceptance criteria
TerrainGenerator::GenerateFbm produces a deterministic uint16_t heightmap for a given seed and parameters
The Generate window is accessible from TerrainEditorPanel and lists all parameters above
Generating with the same seed and parameters twice produces identical results
Generating with a different seed produces visibly different terrain
Terrain size and height range parameters are respected (world extents match input, height values within [min, max])
Resize-confirmation modal appears when the generated dimensions differ from the current terrain
The window stays open after generation for parameter iteration
Guidelines
TerrainGenerator lives in src/terrain/ — no editor or gldevices headers
One class per .h / .cpp pair; add to src/terrain/CMakeLists.txt
Google C++ style guide; no comments beyond non-obvious invariants
