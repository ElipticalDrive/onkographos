Summary
add reusable graph-native GPUFiniteDifference2D and GPUFiniteDifference3D primitives for gradient, divergence, curl, and Laplacian
add reusable StructuredVolumeRenderer support for scalar, vector, and hybrid WebGPU volume rendering from storage buffers or 3D textures
expose focused scene renderer facades at @luma.gl/scene/forward, /deferred, /raytrace, and /raymarch
add shared Shadertools WGSL for ray-box intersection, trilinear interpolation, transfer functions, front-to-back compositing, and solid shaft-plus-cone arrow SDFs
migrate Vector Field Lab to four synchronized StructuredVolumeRenderer instances consuming the five-node GPUCommandGraph directly
make all six mathematically verified presets evolve over time, with Taylor–Green as the animated default, linked orbit navigation, sparse 3D glyphs, and a center probe
Architecture
StructuredVolumeRenderer is implemented in @luma.gl/experimental while the new @luma.gl/scene/raymarch facade provides the application-facing renderer taxonomy without introducing a scene/experimental dependency reversal. The same pattern now exposes the existing forward, deferred, and ray-tracing renderers. A future retained ANARI SpatialField/Volume object can delegate to this renderer.
The renderer accepts float32 scalar buffers, WGSL-aligned float32x4 vector buffers, and matching float 3D textures. Both backing variants use manual eight-corner trilinear interpolation. Dimensions, backing type, and channel format are construction-time invariants; compatible sources can be rebound. prepare(commandEncoder, options) and draw(renderPass) never submit internally.
Numerical and rendering method
regular 2D/3D samples with explicit spacing and documented units
second-order centered differences in the interior
selectable second-order one-sided or periodic boundary handling
fixed-step jittered ray marching with premultiplied front-to-back transparency and early opacity termination
sequential/signed scalar transfer functions, direction/constant vector colors, model transforms, local bounds, viewport/scissor control, and optional 3D arrows
40³ showcase volume, 72 ray samples per selected view, 6³ glyph lattice, and 30 Hz field/derivative updates without volume readback

On adapters without the optional float32-filterable feature, the documented r32float and rgba32float sources cannot be bound because omitting sampleType defaults this layout to float, while those formats require an unfilterable-float binding. The shader only uses textureLoad, so specialize the texture binding layout to unfilterable-float for the 32-bit formats; otherwise model pipeline/bind-group creation fails even though validateSource accepts the texture.

Align storage-buffer offsets to the device limit
When a caller uses a documented subrange such as a scalar offset of 4 bytes or a vector offset of 16 bytes, this check accepts it and getSourceBinding passes that offset directly into the WebGPU storage-buffer binding. WebGPU requires this offset to be a multiple of device.limits.minStorageBufferOffsetAlignment (commonly 256), so bind-group creation fails for most accepted nonzero offsets. Either enforce the device alignment or bind from an aligned base and add a shader-side element offset.

Start rays from the unprojected near plane
When inverseViewProjectionMatrix represents an orthographic projection, using the single camera position as every ray origin makes the rays converge instead of remaining parallel; it also ignores near-plane clipping when a perspective camera is close to or inside the volume.
