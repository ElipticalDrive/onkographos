Depends on: #108564 I have opted for another not-so-radical solution that consists of creating a new built-in define, WORLD_VERTEX_COORDS, to detect if the world_vertex_coords flag is active.
This PR simply adds a new node to the visual shader editor that allows for transformation of a Vector3 from one coordinate space to another.
From spaces: Model to..., World to..., View to..., Tangent to..., Screen to...
To spaces: Model, World, View, Tangent, Screen
Vector types: Position, Direction
Normalize: True or False
All space conversions in vector position type:
In addition to being able to change the position vector type to direction when you're in direction mode, you can normalize the result for improved performance, or not normalize it if you don't need to.
As you can see, this PR implements two new spaces, Tangent space and Screen space. These are based on the approach Unity took for its Transform Helper node. Therefore, the best way to test if this PR is working correctly is by using Unity. I've performed several comparisons with Unity, and it should mostly function the same, with the exception of a few cases.
Unity flips the Y-axis in screen space, but Godot does not:
ScreenUV(Godot)
ScreenPosition(Unity)
Some transitions involving tangent space might show this result:
This also used to happen in Unity, but it seems they've found a way to fix it:
Important Notes:
I've replaced "clip space" with "screen space" as Unity does, since it returns a Vector3. However, it's possible that only the X and Y axes are necessary, and the Z-axis might be redundant, but I'm not certain.
I'm also open to any suggestions that provide a better solution than what's currently implemented.
Additionally, if someone could please test all possible combinations to see if I've made any errors in the conversions, that would be greatly appreciated.
