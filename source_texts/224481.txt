What
Gap loop phase-2 round 10 (the final backlog item): analytic narrow-band ray intersection for baked SDF grids, after Pujol & Chica (CEIG 2024). New standalone module abrash_core::analytic_sdf_grid on trunk, plus an analytic_sdf_grid_demo example.
How it works
Trilinear interpolation is degree-1 in each axis separately, so restricted to a ray the interpolant inside one cell is a cubic polynomial in t. Instead of sphere-tracing the field:
A 3D DDA walks the grid cell by cell — each cell at most once, so cells_visited ≤ nx+ny+nz for any ray, however tangent.
Cells whose eight corners all lie above the narrow band are skipped exactly: the interpolant is a convex combination of the corners, so it cannot dip below their minimum. No samples, no solve.
Band cells solve their cubic: split the cell's t-interval at the cubic's critical points (quadratic derivative), bisect the one sign-changing segment. A tangent ray's double root sits at a critical point and is found there.
The narrow band only decides how many cells pay for a solve, never the answer — the cell containing a crossing always straddles zero. A test pins that band 0 and band 10 return the same hit.
Also in the module: SdfGrid::bake/sample (trilinear, border-clamped), the analytic per-cell gradient (derivative of the same polynomial, not finite differences), cell_ray_polynomial / eval_cubic / first_root_in_interval as public building blocks, and sphere_trace — the classic marching baseline on the same grid, kept so the comparison is measurable.
Verification
26 unit tests + 4 doctests; full crate gate: 1720 lib + 501 doc tests green, cargo fmt clean, zero clippy warnings in the new files (crate baseline unchanged).
Exactness pinned where it should hold: head-on sphere hit on a grid axis is exact to 1e-3 (field is linear along the ray), slab entry for an oblique ray exact, cell polynomial checked against the independent trilinear sampler, fan of 49 rays agrees with the marching baseline on every hit/miss and distance.
The grazing-ray stall is pinned as a test: a ray 0.05 above the sphere terminates as a miss within the DDA cell bound while the marcher takes strictly more samples than the analytic path visits cells.
Honest limitations, pinned in tests rather than smoothed over: the per-cell trilinear gradient is only approximately radial (cross-terms from neighbouring nodes are real), a double root's location is ill-conditioned in f32 (~5e-4, not 1e-5), and a ray entering the grid already inside the solid reports the grid-entry distance by convention.
Demo verified: sphere+box scene baked to 25³ nodes (62,500 bytes — the sample array is the method's whole memory cost), 6,912 orthographic rays, analytic and marched agree on every pixel (asserted in the demo): 1,190 hits; analytic visited 147,969 cells (135,455 skipped by the band, 12,514 cubics solved, 0 field samples) vs 43,082 marched field samples. For this mostly-empty scene the DDA walks more, cheaper, units than the marcher samples — the analytic win is per-cell cost, the bounded tangent-ray behaviour, and root accuracy instead of a march tolerance, not a universal step-count win.
Notes
Built standalone on origin/trunk (afd181c), like every round — no dependency on earlier unmerged gap-loop branches.
