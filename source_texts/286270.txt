Adds a new DEVICE_KERNEL_INTEGRATOR_SHADE_SURFACE_NRC kernel variant that enables neural radiance caching (NRC) during bake operations. When enabled via the UI, indirect lighting is cached and reused to accelerate light ray tracing during texture baking.

Kernel layer
New SHADE_SURFACE_NRC enum in DeviceKernel (kernel/types.h)
Extended KernelBake struct with use_nrc, nrc_max_bounces, nrc_training_samples fields
integrator_shade_surface_nrc() template instantiation in shade_surface.h
Dispatch logic updated at all 6 integrator dispatch points:
init_from_bake.h — initial bake kernel selection
intersect_closest.h — 4 dispatch sites (shadow catcher bg, shadow catcher volume, main path, after-volume)
subsurface.h — subsurface scattering re-dispatch
Megakernel case added
Device backends
GPU kernel wrapper (kernel/device/gpu/kernel.h)
OptiX: raygen program group, pipeline wiring, queue dispatch
oneAPI: kernel call dispatch, feature filtering, HW raytracing compat
HIPRT: full kernel wrapper with stack buffer
HIP: kernel loading
Metal: feature-gated kernel skip logic
BakeManager & sync
scene/bake.h/.cpp: NRC property getters/setters, device_update() copies to KernelBake
blender/session.cpp: reads RNA properties in BlenderSession::bake()
UI / RNA
addon/properties.py: bake_use_nrc (bool), bake_nrc_max_bounces (1–64), bake_nrc_training_samples (1–4096)
addon/ui.py: CYCLES_RENDER_PT_bake_nrc panel under Bake settings, with header toggle and two int fields
Path trace GPU work
path_trace_work_gpu.h/.cpp: NRC sort counter allocation, zero-on-reset, sorting/shadow/AO kernel predicates"

🔴 NRC baking kernel unavailable on GPU when scene lacks raytrace shader nodes, causing crash
The NRC kernel loading is gated on KERNEL_FEATURE_NODE_RAYTRACE ((device->kernel_features & KERNEL_FEATURE_NODE_RAYTRACE) == 0 at intern/cycles/device/metal/kernel.mm:266), but the integrator unconditionally routes all surfaces to the NRC kernel when kernel_data.bake.use_nrc is true (intern/cycles/kernel/integrator/intersect_closest.h:275), so baking with NRC on a scene without AO or Bevel shader nodes will dispatch to an unloaded kernel.
Impact: NRC baking crashes on Metal, OneAPI, and OptiX GPU devices when the scene has no raytrace shader nodes.
Kernel loading vs routing mismatch across all GPU backends
The NRC kernel availability check uses the wrong feature flag in multiple backends:
Metal: device/metal/kernel.mm:265-270 skips loading NRC if KERNEL_FEATURE_NODE_RAYTRACE is not set
OneAPI: kernel/device/oneapi/kernel.cpp:182-187 skips compiling NRC if KERNEL_FEATURE_NODE_RAYTRACE is not set
OptiX: device/optix/device_impl.cpp:271,681 only creates the NRC program group when use_shader_raytrace (derived from KERNEL_FEATURE_NODE_RAYTRACE) is true
However, KERNEL_FEATURE_NODE_RAYTRACE is only set when shaders contain AO or Bevel nodes (intern/cycles/scene/shader_nodes.h:840,1803,1869). There is no code in intern/cycles/scene/scene.cpp that sets this feature when NRC baking is enabled.
Meanwhile, the routing code at intern/cycles/kernel/integrator/intersect_closest.h:275-281 unconditionally checks kernel_data.bake.use_nrc and dispatches to DEVICE_KERNEL_INTEGRATOR_SHADE_SURFACE_NRC for ALL surface hits. The same pattern appears in init_from_bake.h:323-331, subsurface.h:223-236, and the shadow catcher split in intersect_closest.h:152-159.
The fix should either add a dedicated kernel feature flag for NRC, or ensure KERNEL_FEATURE_NODE_RAYTRACE is set when NRC baking is enabled (e.g. in scene/scene.cpp around line 620-622 where KERNEL_FEATURE_BAKING is set).
Prompt for agents
```
The NRC kernel loading is gated on KERNEL_FEATURE_NODE_RAYTRACE across Metal (device/metal/kernel.mm:265-270), OneAPI (kernel/device/oneapi/kernel.cpp:182-187), and OptiX (device/optix/device_impl.cpp:271,681). But the integrator routing at intersect_closest.h:275 dispatches to NRC based on kernel_data.bake.use_nrc, which is independent of raytrace nodes.

The cleanest fix is to ensure KERNEL_FEATURE_NODE_RAYTRACE is set when NRC baking is enabled. In scene/scene.cpp around line 620 (where KERNEL_FEATURE_BAKING is set), add logic like:

  if (bake_manager->get_use_nrc()) {
    kernel_features |= KERNEL_FEATURE_NODE_RAYTRACE;
  }

Alternatively, all the kernel loading checks could be updated to also check a new NRC-specific feature flag.
```
