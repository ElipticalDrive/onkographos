This is the first of a series of PRs for inline compression of values
(issue #3423). The first version compresses string values only; other
types (lists, hashes, sets, sorted sets) can use the same frame and
interface later. This PR adds the design doc and a small compressor
library. Nothing calls the library yet, and no behavior changes.
design-docs/inline-compression.md: the full design. Later PRs add the
code step by step.
src/compressor/compressor_alg.{c,h}: a replaceable compressor
interface. Each instance belongs to one thread. Algorithm ids, shared
error codes, and loaded dictionaries.
src/compressor/compressor_alg_lz4.c: the LZ4 backend, with the LZ4
block API from deps/lz4.
src/unit/test_compressor_alg.cpp: unit tests for the interface and
the LZ4 backend.
Build: the two new objects in src/Makefile and CMake, and src/ as the
include root in CMake, so files in src/compressor/ can include
"server.h".

It is one reason, not the only one:
We store one small value at a time, not a stream. compression_lz4.c wraps lz4frame for a byte stream (the RDB and the replication stream): it keeps a context and has the begin, feed and flush steps. For one value of a few hundred bytes we need one call in and one call out, and that is exactly the LZ4 block API.
Size overhead on every value. An lz4frame frame has a header of 7 to 19 bytes (LZ4F_HEADER_SIZE_MIN / LZ4F_HEADER_SIZE_MAX), a 4-byte block header, and a 4-byte end mark. That is at least 15 bytes, and 23 with the content size, which we need to allocate the exact output buffer. We pay it for every stored value. Our own 10-byte header already holds the plain length, the algorithm and the format version, so the frame fields would only repeat them. Next to a 256-byte value, 15 to 23 extra bytes is a large part of the saving.

Inline compression: remove the dictionary from the block compressor API
…
49a6e27
```
This PR adds LZ4 block compression without dictionaries, so the API does
not need dictionary support yet. It will come back with the dictionary
registry in a later PR.

- Remove the dictionary limits, blockCompressorDict, and the train,
  dict_load, dict_free and release entries.
- compress() and decompress() no longer take a dictionary.
- The LZ4 backend resets its working stream before each value and
  decompresses with LZ4_decompress_safe().
- Remove the dictionary tests. The round trip and two-instance tests stay.
- Remove references to the design doc from the comments, because the
  doc changes often.

Signed-off-by: Eran Ifrah <eifrah@amazon.com>
```
