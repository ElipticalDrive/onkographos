Summary
napari-js has no way to turn a voxel mask into a mesh. Its only mesh builder is heightField. SIV builds every region's 3D surface (atlas structures, hand-drawn regions) from a stack of slice outlines, which it fills into a binary mask and then meshes. The meshing is a general algorithm that any napari-js user rendering labels or segmentations in 3D would need.
What SIV does today
geometry/surface-nets.ts (164 lines, pure, runs in a worker):
surfaceNets(mask: Uint8Array, nx, ny, nz): { vertices: Float32Array; faces: Uint32Array }: Gibson surface nets on a binary mask, x fastest.
smoothMesh(mesh, iterations = 2, lambda = 0.5): Laplacian smoothing.
It's used by geometry/reconstruct.ts, which stays in SIV (the outlines, the union of features, and the volume calculation).
Proposal
Add these to napari-js/geometry (pure, GPU-free, safe in workers):
surfaceNets(mask, [nx, ny, nz], { voxelSize?, origin? }) → { vertices, faces }, ready for addSurface.
smoothMesh(mesh, { iterations, lambda }) (optionally Taubin, which doesn't shrink the mesh).
Optionally, labelsToMeshes(labels, ...): one mesh per label value, for a future 3D Labels layer.
Done when
The algorithm is verified against a sphere and a box (watertight, triangle orientation consistent), with timings for a 256³ mask.
SIV imports it from napari-js/geometry and deletes surface-nets.ts.
