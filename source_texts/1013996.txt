Follow-up to base-writer v2 (RLE_DICTIONARY + choose-smaller encoding). Measured on the gene corpus (888,949 quads): v1 DLBA 133.84 B/quad → v2 RLE_DICTIONARY 13.90 B/quad (9.63x smaller), vs pycottas-ZSTD 1.139 B/quad. The remaining ~12x is the missing compression layer, not encoding.
Scope:
Wire ZSTD_compress through the existing zstd boundary: experimental_ocaml_glue/parquet_zstd_stubs.c already links real libzstd and exposes ZSTD_decompress; the compress entry point is in the same linked library — no new dependency.
New assume val for the compress call (rule Enrich ARCHITECTURE.md with detailed verification precedents #3: stub patch + this issue as its open tracker; rule Promote ASK and CONSTRUCT into core architecture layers #11(a) pure byte-transform realisation — all page framing stays in the F* Tot byte assembly).
Thread compressed-vs-uncompressed page sizes through the writer's pure serialization (total_compressed_size / total_uncompressed_size in the column chunk metadata must diverge once compression is on; today the v1/v2 writers emit UNCOMPRESSED so they are equal).
Acceptance unchanged from v2: DuckDB parquet_scan byte-exact row content on the three benchmark corpora, W3C floors (SPARQL 631 pass 0 fail, RDF 1031 pass 0 fail), and measured bytes/quad on sample/medication/gene, labeled v2 vs v3 vs pycottas-ZSTD.
Context: the v2 encoder work found the s/o columns dictionary-encode profitably even at high cardinality (SPOG adjacency runs + corpus-wide IRI repetition), so v3 compression applies on top of already-deduplicated pages — expect the gap to close to low single digits rather than fully, since pycottas compresses whole row groups with different framing.
