Summary
Work that gets Marvel's Wolverine (PPSA03671) running, as 54 single-topic commits so any subset can
be cherry-picked. Each commit keeps its own author. The branch is rebased on current upstream/main
(e51de54) and no longer depends on #780. The research diagnostics are stripped out.
Mac: 27 commits
Senaxx: 24 commits
Ali Almohaya: 3 commits (integer render-target exports, DRAW_INDIRECT_MULTI draw index,
ShaderFunctions scalar-call expansion)
Earlier versions of this PR carried about 30 more commits (bindless, mesh culling and clip/cull
distances, GPU-read indirect draws, the software BVH path and others). They were dropped in this
rebase because upstream now has an equivalent or conflicting implementation. See "Not included".
Commits, by area
Renderer and GPU thread
Command buffers are submitted from a queue thread and recorded on a recording thread
New graphics pipelines are compiled on worker threads
Images and buffers are released between guest command buffers only after the GPU is done with
them, which fixes sampling of freed memory after a guest unmap
A dispatch marks only the bytes its stores can reach as GPU-written
A scalar read that overlaps its own dispatch's write is logged once per shader pair instead of
exiting
The GPU and recording threads prefer the fast cores of hybrid CPUs
Unmapped buffer descriptors and guest page 0 bind as null; uploads and unreadable image backing
read as zero
Integer render targets export uint/sint; R32 image atomics go through an R32Uint view
Device loss is reported with VK_EXT_device_fault and NV checkpoints; a symbolized host stack is
printed on fatal errors
Texture cache: per-frame eviction budget, with write-back of GPU-written tiled images
Buffer cache: entries age by presented frames
Vulkan: images fall back to host memory when device memory is exhausted; GPUs that cannot report
surface capabilities are skipped
Video out: extra 10-bit and FP16 format policies on top of upstream's HDR table
EOP labels published once the GPU has executed the work (opt-in)
Shader recompiler
IEEE float min/max, denormal flush on output modifiers, ordered LDS accesses, gather LOD, constant
vertex fetches
Wave64 branches, wave-size pipelines, device-clock S_MEMREALTIME, coherent loads and
block-compressed volumes on AMD
Scalar calls expanded before translation (ShaderFunctions)
Native subgroup reductions for DPP scans; DPP16 leaves the destination alone for missing or
inactive sources
SRT reads only from committed pages; reads past num_records return zero
The decoder gives up on the shader instead of exiting on unmodelled scalar operands; CDBG branches;
SDWA byte destinations
Programs the recompiler cannot translate are skipped instead of exiting
NGG shaders with fewer than 3 GS/ES input VGPRs are accepted
Dominators are solved in reverse postorder (structurizing 2k-block shaders drops from 21-84 s to
0.8 s)
IMAGE_SAMPLE*_CL applies the LOD clamp: MinLod where supported, otherwise a raised explicit LOD
Kernel, memory, libraries
Memory tracker: per-region clean bitmap, lazy direct-memory commit, cached mapping and range
lookups
AMPR: map commands, counters, async engines, per-unit locks, cheap APR destination check
AJM: ATRAC9 config checks, partial superframes and vibration configs; Opus mapping family 1
AvPlayer file-replacement callbacks, savedata Convert, NpEntitlementAccess, sceAcmBatchJobPriority,
fsync, equeue timeouts, timed condition waits
Not included

change depends on code that was removed:
Bindless textures and samplers (--bindless)
Mesh primitive culling, clip/cull distances, subgroup passes
GPU-read DrawIndirect and GPU-side indirect thread counts
Software IMAGE_BVH_INTERSECT_RAY, 64-bit compare/arith opcodes
FLAT shared/private apertures, GPU-selected buffer descriptors through BDA, bound-length storage
buffers
Dispatch rollback on unmapped BDA pages and the other opt-in env switches
(KYTY_IGNORE_WRITTEN_OVERLAP and similar)

🩺 Stability & Availability | 🟠 Major | ⚡ Quick win
Deferred label callbacks can run after GuestGpu is destroyed.
Two callbacks run on the scheduler priority thread and use GuestGpu:
PublishLabelAtCompletion calls renderer.GetGpu().Wake().
DeferLabelWrite (Lines 179-188) captures this and calls TrySendCommand.
RenderContext::ShutdownGpu (src/graphics/host_gpu/renderer/renderContext.cpp, Lines 37-49) calls m_gpu->Shutdown() and then m_gpu.reset(). It calls m_command_scheduler.DrainPriorityOperations() only after that. ThreadRun stops with BufferWait() → Finish(), and Finish() does not wait for priority operations.
A label callback that is queued or running when m_gpu.reset() executes has two outcomes:
GetGpu() exits because m_gpu == nullptr.
TrySendCommand runs on a freed GuestGpu (use-after-free).
This happens at shutdown whenever KYTY_LABELS_AFTER_GPU or KYTY_LABELS_AT_COMPLETION is set. Drain the priority operations after the GPU thread joins and before m_gpu.reset(). TrySendCommand already returns false once m_accepting is false, so a late label write is dropped safely.
🐛 Proposed fix (src/graphics/host_gpu/renderer/renderContext.cpp)
```
 void RenderContext::ShutdownGpu() {
 	if (m_gpu != nullptr) {
 		m_gpu->Shutdown();
+		// Label publications capture the GuestGpu; finish them before it is destroyed.
+		m_command_scheduler.DrainPriorityOperations();
 		m_gpu.reset();
 	}
```

```
A graphics pipeline that is neither in the pipeline cache nor in the
driver cache is built on the GPU thread at its first draw. On NVIDIA the
large modules of open-world titles take 1-65 s each, during which the
picture freezes while the game (and its audio) runs on. Building them
unoptimized first does not help there: it costs as much as the optimized
build.

--skip-pending-draws true (default false, so nothing changes unless it is
asked for) lets such a draw leave the whole optimized build to the
background compile queue and be skipped until the pipeline is installed.
Only a draw whose only effect is the picture is skipped
(PendingDrawSkipBlocker, a pure function with its own unit test):

- no stage writes memory: no buffer or image stores or atomics (GPU-
  selected stores included), no device-address writes, no GDS;
- no guest query counts it (occlusion counters are synthetic today, so
  this is always false until host queries land);
- no color target is linear and no depth/stencil write goes to a linear
  target: the CPU reads such images back as data;
- it is not a DB_RENDER_CONTROL depth/stencil clear.

Every other draw, and every dispatch, waits for its pipeline exactly as
before. Skipping is bounded: 2 s after a build was queued its draws wait
for it (PipelineCompileQueue::Expedite runs it on the GPU thread if it
has not started), so a slow build cannot hide geometry for long.

The pipeline is looked up before the draw prepares its bindings, vertex
and index buffers or render targets, so a skipped draw records nothing,
uploads nothing, consumes no HTile clear state and marks no GPU writes;
target discovery has already run, as for any draw. The finished pipeline
is installed by the existing InstallOptimizedPipelines path at the next
lookup. The cache logs once per pipeline when its draws are first
skipped, when a draw has to wait for it, and when it is ready (with the
time since it was queued and the number of skipped draws); the
performance overlay shows skipped draws per second.

The same policy (compute never skipped, graphics skipped only when they
change nothing but the picture) was proposed upstream in KytyPS5#937 (Senaxx,
b804a66) and KytyPS5#1469, and is used by TheCruZ/KytyPS5-GTA 15c8f43; KytyPS5#718
dropped an asynchronous compute path because a skipped dispatch is never
replayed. Here it is opt-in and on top of the existing background queue.
```
