Found while fixing #862. Citations read at origin/master = 5dfeb44b5b41.
Mechanism
GaussianSplatWorld::set_gaussian_data()
(modules/gaussian_splatting/core/gaussian_splat_world.cpp:107-121) derives
bounds from the payload only while bounds has no volume:
```
if (!bounds.has_volume()) {
    bounds = gaussian_data->get_aabb();     // :115-117
}
```
GaussianData::get_aabb() (core/gaussian_data.cpp:1130-1153) expands each
splat by a 3-sigma scale extent, so any non-degenerate payload produces an AABB
that does have volume. The first set_gaussian_data() on a fresh world
therefore installs bounds, and every later set_gaussian_data() leaves them
exactly where the first payload put them.
Both downstream consumers fall back to the payload's own AABB only when the
resource's bounds are volumeless, so neither recovers:
GaussianSplatWorld3D::_register_shared_renderer()
(modules/gaussian_splatting/nodes/gaussian_splat_world_3d.cpp:497-500 at
master): submission.bounds = world->get_bounds(); then
if (!submission.bounds.has_volume() && ...) submission.bounds = gaussian_data->get_aabb();
GaussianSplatWorld3D::_update_bounds() (:536-555): same shape, feeding
local_aabb → rs->instance_set_custom_aabb() and
storage->gaussian_set_aabb().
What a user sees
Replace an applied world's payload with one at a different location and the
render instance keeps the first payload's culling volume. With #862 fixed the
content now reaches the renderer, but the instance's AABB still describes where
the content used to be, so a large relocation can leave the world frustum-culled
— visible as "the new payload renders only when the camera looks at where the old
one was".
Measured indirectly while writing the #862 cases: the M1 case (payload A at
x≈0 replaced by payload B at x≈100) sees the director's record carry B while
record.bounds stays at A's AABB. That is why the #862 M1 case deliberately does
not assert on bounds — pinning the current behaviour would pin this bug.
Why it is not part of #862
Changing when bounds is re-derived changes the resource's contract: an author
who sets bounds explicitly expects it to survive a payload write. The fix needs
a decision about how an explicitly-authored AABB is distinguished from one the
resource inferred (a bounds_is_explicit flag set only by set_bounds(), most
likely), which is a design change rather than a bug fix.
Proposed work
Track whether bounds was authored or inferred, and re-derive an inferred one on
every payload write. Test: apply a world with a payload at the origin, replace it
with a payload 100 units away, flush, and assert the director's record bounds and
the node's local_aabb follow the new payload; and assert an explicitly
set_bounds() AABB is not overwritten.
