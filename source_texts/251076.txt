Filed from the 2026-10-04 audit double-check (record N-19 and plan item Q-1), audited at ae5554978ed86a24e2a7331a9a188ce381a01482 (master). Competitive reference: PlayCanvas GSplatParams.antiAlias ("compensation for splat data generated with anti-aliasing during training"), gsplat rasterize_mode="antialiased", SPZ header flag 0x01.
What exists
tile_binning.glsl:680-695 adds the 2D low-pass floor (params.low_pass_filter, shipped 0.35) to cov2d and rescales alpha by sqrt(det_raw / det_filtered) (alpha_rescale_proj, :1208-1211), unconditionally. That is the Mip-Splatting 2D filter with opacity compensation, applied to every asset.
What is wrong
Models trained classic (plain 3DGS, 0.3 px dilation without compensation) and models trained with the Mip-Splatting 3D filter (SPZ flag antialiased, gsplat antialiased mode) expect different renderer behaviour; applying the compensation to both changes the energy of one of them. The SPZ loader parses the flag (spz_loader.cpp:862) and the importer stores spz_antialiased in import metadata (resource_importer_spz.cpp:555), but nothing in materialisation, the GPU flags or the shader consumes it, and no warning says so. The Mip-Splatting reference uses a 2D variance of 0.1 for antialiased models; gsplat keeps eps2d = 0.3; the epsilon therefore needs to be configurable per convention.
Evidence
modules/gaussian_splatting/shaders/tile_binning.glsl:680-695, :1208-1211
modules/gaussian_splatting/io/spz_loader.h:84 -- SPZ_FLAG_ANTIALIASED = 0x01
modules/gaussian_splatting/io/resource_importer_spz.cpp:555 -- metadata only
Direction (not a patch recipe)
Plumb an asset-level antialiased flag from import metadata into gs_pack_asset_gpu_flags, make the alpha rescale (and the epsilon) conditional on it, expose it on the importer for PLY, and A/B both model classes against reference renders (0.5 dB PSNR acceptance).
