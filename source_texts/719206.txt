What to build
The core fly camera: a new Camera::Fly variant with quaternion-based orientation, the fly_tick command for per-frame updates, and the input layer that drives it. After this slice, a user can press F to enter fly mode, move with WASD/QE, look around with mouse drag, and see the volume rendered correctly from the fly camera's perspective.
Rust:
Fly struct with position, orientation (quaternion), fov, near, far, viewport, speed_multiplier
Quaternion math: multiply, from_axis_angle, to_rotation_matrix, normalize, rotate_vector
fly_tick(dt, forward, right, up, yaw, pitch, roll) — applies orientation-relative translation and rotation
view_proj(), eye_position(), inv_view_proj() dispatch on Camera enum to handle Fly variant
camera_mode() returns "fly" for the new variant
Arcball → Fly state conversion (derive position + orientation from current view)
TypeScript:
useFlyCameraInput hook: RAF loop, reads key state, computes dt (clamped to 100ms), calls fly_tick via applyViewportCommand
Pointer handler strategy pattern in VolumeViewer: arcball handlers vs fly handlers (mouselook)
Auto-focus canvas on mode switch (F key triggers switch)
See "Fly Camera State", "Mode Switching", "Input Strategy Pattern" sections in #139.
Acceptance criteria
Camera::Fly variant exists with quaternion orientation, serializes with serde tag "fly"
fly_tick correctly translates position based on orientation, direction inputs, speed, and dt
fly_tick correctly rotates orientation based on yaw/pitch/roll inputs
view_proj() and eye_position() return correct values for Fly camera
Pressing F switches from arcball to fly mode preserving approximate view position
WASD/QE keys move the camera in the correct directions relative to orientation
Mouse drag in fly mode applies yaw and pitch (mouselook)
Movement is frame-rate independent (dt-based)
Movement pauses when tab is backgrounded (RAF stops)
Canvas auto-focuses on mode switch
Volume renders correctly from fly camera perspective
Rust unit tests for quaternion math, fly_tick position/orientation, and view_proj validity
Quaternion stays unit-length after many successive rotations (normalization test)
