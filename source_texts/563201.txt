I re-audited this against current origin/master (75169bf) while working through the sweep. This still looks like a broad renderer architecture ticket rather than a small implementation PR.
Concrete current state:
the renderer is still OpenGL raster/shadow-map based via RendererManager, VisualRenderer, MeshRenderer, and DrawMesh
shader support is GLSL vertex/fragment/geometry/compute/tessellation, but there is no ray-generation/miss/hit stage model
I found no acceleration-structure builder, BVH data model, Vulkan/OptiX/DXR backend, GL ray-tracing extension path, render-mode abstraction, or ray-traced output pipeline
the only direct ray-tracing mention in source is the future-feature FIXME in Source/Main.cpp
I do not think a RayTracingEnabled settings stub or menu toggle would be useful yet because there is no backend for it to control. The smallest useful next step is likely a renderer architecture note or acceptance-criteria issue that chooses a backend target (Vulkan RT, OptiX, CPU/reference, or OpenGL compute fallback), defines the scene/mesh/material data path into acceleration structures, and names the first validation target.
