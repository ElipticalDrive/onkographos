Type: Performance / allocations · Area: encoding
Evidence
Reviewed current default-branch source at commit 0602b572b542ee18203e6dbbd07c21ffe3063f35.
encode_i64_with allocates a full Vec of zigzag-mapped values on its Rle and plain fallback branches.
encode_plain_u64 writes that vector once; encode_rle consumes it to build a separate run vector.
FOR's signed encoder already fuses the mapping and avoids the full-column temporary. The public integer encode path calls encode_i64_with.
For N signed values on the affected branches, mapped holds 8N bytes plus any capacity overhead, alongside the original column and output; RLE additionally holds its run list. The mapped values need not survive encoding. This is separate from bounded transform-selection sampling.
Proposed fix
For PlainU64/fallback, emit the current u32 row count then zigzag each borrowed value into the output. Compare scalar put_u64 emission with bounded stack chunks passed to put_u64_slice, choosing the approach that preserves bulk-write throughput without full-column heap scratch.
For RLE, let the existing run builder consume a concrete iterator of u64 codes (or a borrowed signed specialization), passing values.iter().copied().map(zigzag). Retain its owned run vector and existing serialization initially; eliminating that run vector is a separate optimization. Share the run logic with the u64 path where practical to avoid duplicated behavior.
Preserve identical counts, zigzag mapping, empty-input behavior, run boundaries, count overflow behavior and the existing fallback dispatch. Leave FOR/DELTA, candidate scoring, trailing compression, decoder and wire format unchanged. Do not reinterpret signed bits as zigzag codes or use unsafe code.
Validation
Force Rle and PlainU64 in unit tests and compare exact bytes against the old map-then-encode reference; public automatic selection alone may never exercise both.
Cover empty/singleton inputs, long runs, alternating signs, all-distinct values, i64::MIN/MAX and counts around stack-chunk boundaries. Verify full and range decoding.
Retain repeated_values_choose_rle, signed integer tests and existing fused bitpack parity tests in src/encoding/test/mod.rs.
Benchmark forced encoders with prepared input and preallocated Writer output at 64/8,192/65,536 values, including incompressible plain and repeated RLE input. Separately measure public encoding with transform selection and compression.
Report time, allocation count/bytes and peak live bytes. Require removal of the full 8N-byte mapped buffer; RLE run/output buffers and selection sampling remain. Assess scalar-versus-bulk throughput before accepting.
Run cargo test --features write and cargo fmt --check.
Scope/status
Reviewed all 57 returned repository issues, the returned PR and targeted zigzag searches; no equivalent proposal found. #49 concerns shared dictionary code translation, not signed encoding. Source analysis only; no implementation, executed tests or measured gains.
