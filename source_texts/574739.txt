Features
bounding_sphere_of(shape): optional shape method, a solve skips the shape for rays that miss its sphere
SingleBoundingSphere, MultiBoundingSphere, NoBoundingSphere: sphere of one shape, of several parts, or none
All SDFs and meshes have a sphere, multi-shape objects and groups one around their parts
render_bounding_sphere!, render!(...; show_bounding_sphere = true): draw the spheres the solver tests
intersect3d(parts, ray): closest intersection with a tuple or vector of shapes or objects
Bugfixes
Breaking: GaussianBeamlet: a support not orthogonal to the direction gave a smaller, shifted waist; now an ArgumentError
AstigmaticGaussianBeamlet: the support check depended on the length of the vector; now an ArgumentError as well
Doc changes
New sections: "Bounding sphere pretest" in the core docs, bounding spheres in the visualization docs
Agent skill: API.md, VISUALIZATION.md, components/beams-and-sources.md updated
Internal changes
Spheres are computed once per solve_system! into a task-local table, not stored in the shapes
Solves measured 3 to 25 times faster, depending on how many objects the rays miss
intersect3d(group, ray) reports the object that was hit, not the group
SDF ray marching stops where the ray leaves the bounding sphere
src/Render.jl split into src/Render/, one file per file of the Makie extension

Bounding spheres: optional shape interface, solver pretest, rendering
…
0f450cd
```
bounding_sphere(shape) is an optional part of the AbstractShape interface
(default: nothing). The solver tests a ray against the sphere first and
skips the shape on a miss; an SDF is marched up to the exit of its sphere
only. Shapes without a sphere are tested as before.

- All 20 SDF types have a bounding sphere. The spheres of the
  acylindrical surfaces, MeniscusLensSDF and DifferenceSDF did not
  enclose the shape resp. used the wrong frame and are corrected; the
  5 cm margin of ConicSDF is gone.
- bounding_box probes the SDF by default; the types whose SDF is not
  exact far away use the box around their sphere, as before.
- render_bounding_sphere!(ax, x) and the keyword show_bounding_sphere of
  render! draw the spheres as wireframes.
- Skill files updated: API.md, VISUALIZATION.md.
```

Bounding spheres: sphere types, table per solve, main spheres of groups
…
8374a91
```
The bounding sphere code now lives in src/AbstractTypes/AbstractBoundingSphere.jl.

- bounding_sphere_of(x) computes the sphere of a shape or object and returns a
  SingleBoundingSphere (center in world coordinates, radius) or NoBoundingSphere().
  It replaces bounding_sphere, which returned a tuple in the local frame or nothing.
- solve_system! computes the spheres once per call into a table that is held in a
  ScopedValue. The intersection code looks them up via bounding_sphere_of(table, x),
  hence no field in the shapes and no change of the intersect3d interface. Outside
  of a solve there is no table and objects are tested without a sphere.
- MultiShape objects and object groups have a main sphere around the spheres of
  their parts. A ray that misses it is tested against none of them.
- Meshes get a sphere from their vertices.
- trace_all tests the objects at the top level of the system, groups test their
  objects themselves. intersect3d(group, ray) returns the object that was hit.
- intersect3d(parts, ray) returns the closest intersection with a tuple, a vector
  or the Leaves of shapes or objects.
- render_bounding_sphere! draws the main spheres in main_color (orange).
```

Gaussian beamlets: the support vector must be orthogonal to the direc…
…
9376e6a
```
…tion

GaussianBeamlet accepted any support vector. One that was not orthogonal to the
direction gave a beamlet with the waist radius w0 * sin of the angle between both
and a shifted waist, without an error. The constructor now normalizes the support
vector and throws an ArgumentError if the dot product of the unit vectors exceeds
get_orthogonality_threshold().

AstigmaticGaussianBeamlet uses the same test. Before, it compared the dot product
with the support vector as given against eps(), which depended on the length of
the vector, and threw an ErrorException.
```
