What
Closes the last texture gap in the README: Texture variants goes from 9 of 10 to 10 of 10.
The one unread variant was textures\effects\noisevolume.dds, the only volume texture in the vanilla archives. Its header showed two gaps:
Volume layout. DDSCAPS2_VOLUME (0x200000) is set and dwDepth is 128. Each mip level stores max(1, d >> i) slices, one after another.
8-bit luminance (L8). DDPF_LUMINANCE (0x20000), 8 bits, R mask 0xff.
Changes
DDSFile reads dwDepth. A volume parses only when the caller passes allowsVolume, the same way cubemaps need allowsCubemap.
New members: depth, depth(level:) and bytesPerImage(level:).
The full mip chain now counts depth.
A DX10 header with resourceDimension 4 (TEXTURE3D) is read as a volume too.
L8 texels widen to xRGB8888 grey (L, L, L, 255), the same way 24-bit RGB is already widened. So the asset cache, the CPU decoder and the texture loader need no new format.
The gap census, openskycli dds and the Preview panel accept volumes and print each level's depth. The Preview panel shows text only for a volume, with no flat image.
Docs: docs/formats/dds.md and docs/tools/gaps.md.
Gaps checked in the same area and left alone: luminance with alpha (A8L8) and 16-bit luminance. No vanilla file uses them, so they still throw unsupported.
Spec
Microsoft DDS programming guide: DDS_HEADER, DDS_PIXELFORMAT, DDS_HEADER_DXT10, and "DDS file layout for textures". On the real install, the size of noisevolume.dds (2,396,873 bytes) is exactly the 128-byte header plus the sum of n³ for n = 128 down to 1.
Tests

Context: the gaps report listed one texture variant OpenSky could not
read: textures\effects\noisevolume.dds, the only volume texture in the
vanilla archives. Its header shows two gaps at once: a volume layout
(DDSCAPS2_VOLUME, dwDepth 128) and the legacy L8 pixel format
(DDPF_LUMINANCE, 8 bits, R mask 0xff).

Change: DDSFile reads dwDepth and, when the caller passes allowsVolume,
slices a volume mip chain where each level holds max(1, d >> i) slices.
A DX10 header with resourceDimension 4 (TEXTURE3D) is a volume too. L8
texels widen to xRGB8888 grey (L, L, L, 255). The gap census, the
openskycli dds command, and the Preview panel accept volumes and print
the depth per level. The Preview panel shows no flat image for a volume.

Rationale: L8 widens to the existing xrgb8888 layout, the same way 24-bit
RGB already does, so the asset cache, the CPU decoder, and the texture
loader need no new format. Volumes stay opt-in, like cubemaps, so a 2D
texture slot still gets a placeholder rather than a 3D texture.
Source: Microsoft DDS programming guide (DDS_HEADER, DDS_PIXELFORMAT,
DDS_HEADER_DXT10, "DDS file layout for textures"). The file size of
noisevolume.dds matches the slices-per-level layout to the byte.

Impact/Risk: 2D textures ignore dwDepth as before. A DX10 TEXTURE3D file
now reports "volume texture" instead of "resource dimension 4". No
renderer path loads volumes yet.
