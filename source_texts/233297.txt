Background
3D Gaussian Splatting (3DGS) has become the dominant representation for the export products of world-model and radiance-field pipelines (e.g. World Labs Marble, Luma, Polycam, Scaniverse, and the reference Inria trainer). These tools output a cloud of anisotropic 3D gaussians — each with a position, covariance (orientation + scale), opacity and color — rather than a triangle mesh. Rendering them requires a dedicated splatting pipeline; a triangle-mesh renderer cannot represent them.
Goal
Add native, pipeline-level 3D Gaussian Splatting rendering to the engine — including view-dependent (spherical-harmonic) color — together with a single loader that ingests the three formats these tools commonly export (.ply / .splat / .spz, all SPZ versions).
Value
Render world-model / radiance-field captures (large-scene scans, photoreal 3DGS assets) directly in the engine — a major new content category.
Full-fidelity color: view-dependent spherical harmonics (degrees 0–3), not just flat DC color, for the formats that carry it.
Used like any other renderer and asset, consistent with the rest of the engine:
entity.addComponent(GaussianSplatRenderer).splat = splat.
One loader covers the formats produced across the ecosystem, so users do not need to pre-convert their exports.
Implementation
packages/core — pipeline-level renderer (built in, not a plugin)
GaussianSplat (asset, AssetType.GaussianSplat): builds the GPU data textures (centers, covariance, color, and spherical-harmonic coefficients) from the decoded splat data, addressed by linear splat index. Covariance is precomputed on the CPU and stored half-float to halve texture bandwidth; SH goes in its own RGBA16F texture only when the splat carries it.
GaussianSplatRenderer: draws instanced, camera-facing quads, depth-sorted back-to-front each frame (off the main thread on a Web Worker, re-run only when the view changes) and composited with alpha "over".
GaussianSplatMaterial + a ShaderLab shader: EWA splatting — each 3D covariance is projected through the perspective Jacobian into a screen-space ellipse with a 2D gaussian falloff — plus view-dependent color: when a splat carries SH, the vertex shader rebuilds its color from the coefficients and the view direction (standard 3DGS basis, degrees 0–3).
packages/loader — one loader, every format, full fidelity
GaussianSplatLoader sniffs the content by magic bytes and decodes .ply, .splat and .spz into a common structured form (positions, covariance inputs, opacity, DC color and higher-order SH).
SPZ — every version, gzip v1–3 and the current ZSTD v4 — is decoded by the official SPZ reference decoder, an inlined-WASM module fetched from the CDN on first use: no baseline weight, byte-exact with the spec, and it exposes the spherical harmonics the previous DC-only parser dropped.
PLY reads the f_rest_* SH bands (channel-major in the file, transposed to the renderer's coefficient-major layout) and detects the degree from the property count.
.splat is DC-only by format.
Unit-tested across every container; the PLY path cross-checks its SH against the SPZ decoder.
examples — demo
A demo with a format switcher (to load and compare each format) and a performance panel.

References
3D Gaussian Splatting for Real-Time Radiance Field Rendering — Kerbl et al., SIGGRAPH 2023. The splatting model, anisotropic covariance and EWA screen-space projection this renderer implements. https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/
glTF KHR_gaussian_splatting (Release Candidate) — the standardizing glTF representation for 3D Gaussian splats. It informs the renderer's internal splat attribute layout; the base extension is designed to be extended by compressed encodings, with SPZ the leading candidate. https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_gaussian_splatting

fix(core): derive splat focal from the render projection
…

```
- Galacean flips projection Y when rendering to a framebuffer (camera_ProjMat[1][1] < 0); deriving focal from camera.projectionMatrix gave it the wrong Y sign
```

fix(core): build splat covariance as R^T*D*R
…
cff3c1f
```
- R is built from the w-negated (conjugated) quaternion, so R^T is the splat's true orientation; the textbook R*D*R^T applied the inverse rotation
- rotated splats were sheared into screen-spanning spikes (the "broken" surfaces at certain angles); axis-aligned splats nearly coincided, which is why head-on views looked fine
- matches the convention of the ported Babylon EWA projection
```
fix(core): treat the splat color texture as sRGB
…
6c2bdf4
```
- Texture2D defaults isSRGBColorSpace to true, but the data textures were all created with it false; the color texture (RGBA8 sRGB) was therefore read as linear and over-brightened
- the over-bright color made near-edge-on splats' low-opacity tails read as bright streaks instead of fading; data textures (center/covariance) stay linear
```
fix(core): run splat color through the engine sRGB color management
…
6ccfbf2
```
- the splat shader read color with a bare texture2D and output it bare, bypassing the engine color pipeline
- now linearizes the sRGB color on read where sRGB textures are unsupported (ENGINE_NO_SRGB) and applies the linear->sRGB output correction when rendering to the gamma screen (ENGINE_OUTPUT_SRGB_CORRECT), so splats composite in the same space as every other material
```
fix(core): reflect the splat ellipse Y for the flipped offscreen target
…
e4d8df2
```
- Galacean's sRGB final pass forces the splat pass to render to a Y-flipped offscreen target (camera_ProjMat[1][1] < 0); the previous signed-focal handling was not a correct Y-reflection — it negated the major axis' X component and sheared rotated ellipses into streaks at grazing angles
- build the ellipse with positive focal in standard screen space, then reflect only the offset's Y; this is provably the reference's render reflected in Y, the form the flipped target needs
```
