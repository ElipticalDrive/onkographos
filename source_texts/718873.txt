Context
The GPU compute-culling path (cull.comp frustum culling → atomic compaction → one vkCmdDrawIndexedIndirect for the instanced scene) is host-tested at 50k-scale for dispatch planning and indirect packing (culling.cpp, 61 native host checks), and it runs on-device — but the on-device run only exercised 3 instances (the mini arena scene).
Anno-1800-scale claims (single-draw-call instancing for thousands of visible assets) are not yet demonstrated on a device.
Tasks
Generate/export a stress scene with thousands of instanced meshes (e.g. harness/build/scene_exporter.py + a scenario or script that emits 10k–50k instance records)
Run it through apk_builder.py --tier2 on the emulator (or physical device)
Measure: frame time, compute dispatch time, culled vs visible counts, draw calls
Confirm the 100-draw mobile budget still holds (terrain + instanced draws)
Record telemetry in harness/runs/RUNS.md
Acceptance criteria
≥10k instances rendered via a single indirect draw call on-device
Steady ≥60 FPS at 10k (or documented achievable budget)
Culling removes off-frustum instances (visible < total)
Results recorded with exact numbers

On-emulator characterization (commits d5394ac, 823bd4c; Run Block 6 in harness/runs/RUNS.md):
What is verified:
Exporter: a 10,000-instance stress scene exports to 1 indirect draw, 66 total draws (budget 100, within budget). stress_scene_gen.py (5 tests) + apk_builder --tier2 --scene <path> make this reproducible.
Host-side scale logic: dispatch planning + indirect packing verified at 50k (61 native host checks).
On-device correctness at small scale: the canonical scene (3 instances + 64 terrain leaves) runs indefinitely with clean telemetry and frame readback.
Emulator limit found (environment, not renderer logic):
500 instances: the emulator host process dies within ~60s.
2,000 / 10,000 instances: the emulator host process dies within seconds (the app process also dies).
No validation output (the layer is not in the system image), no host OOM (38 GB free); the emulator log ends right after Created VkDevice … for application 'Heretek Tier 2'.
Conclusion: the software Vulkan emulator (lavapipe/gfxstream) cannot sustain multi-hundred-instance workloads, so this issue's acceptance criterion (≥10k instances on-device at ≥60 FPS) can only be validated on physical hardware — tracked in #1. Keeping this issue open with the characterization; the export/budget half of the criteria is satisfied.
