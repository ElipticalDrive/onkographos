Summary
Adds an isolated camera/mesh alignment stage that audits the full COLMAP-to-GenRecon transform chain, prepares distortion-consistent sparse observations, evaluates bounded robust global Sim(3) candidates on disjoint held-out evidence, and applies a transform to object lifting only when conservative gates accept it.
The original COLMAP cameras, GenRecon mesh bytes/topology, PBR GLB, arbitrary coordinate convention, and scale ambiguity remain unchanged. The implementation does not add camera bundle adjustment, local/non-rigid deformation, hidden-surface completion, physics, or simulator export.
Architecture
lightweight typed core adapter, CLI, schemas, Scene IR root-transform references, and Phase 4.2 validator;
isolated NumPy/SciPy/PyTorch/nvdiffrast worker plus optional CUDA Docker image;
selective attempt inputs only; no raw COLMAP database/logs, SAM raw output/checkpoints, or GenRecon checkpoint/tensor materialization;
exact pre/post nvdiffrast render equivalence for working and COLMAP coordinate paths;
deterministic training/validation frame and sparse-point split;
identity, centroid, robust-extent, and right-handed PCA initializations;
robust correspondence updates, Cauchy loss, plausibility bounds, held-out gates, candidate ambiguity detection, and per-camera/per-chunk residual diagnostics;
alignment_policy: use_if_accepted integration with original global face IDs preserved;
before/after object-lifting comparison and deterministic previews.
Real H100 smoke
Reused the Phase 4.1 real lineage: 16 normalized frames, 12 registered cameras, approximately 2,461 sparse points, four SAM tracks, 50 canonical masks, and the same 3,642,276-vertex / 7,677,700-face global mesh.
GPU: NVIDIA H100 NVL
split: 6 training frames / 6 validation frames; 3,355 / 3,416 declared observations
transform-chain coordinate round trip: below 1.4e-14
independent working/COLMAP render equivalence: depth error 9.14e-8, silhouette IoU 1.0
candidate: scale 0.926493, rotation 11.7756 deg, translation 0.141018 scene diagonals
validation median residual: 0.662246 -> 0.372986
validation p90 residual: 0.787134 -> 0.530112
validation inlier fraction at 0.10: 0.011430 -> 0.140841
mesh coverage: 0.998527 -> 0.958830
point-to-surface median / scene diagonal: 0.041253 -> 0.019086
runtime: 30.89 s
peak GPU memory: 308,771,840 bytes
peak host memory: 2,094,710,784 bytes
Result: global_sim3_insufficient. Although every configured improvement/plausibility gate passed, the absolute inlier fraction remained low and residuals stayed structured across seven GenRecon chunks. The candidate is retained as diagnostic evidence but is not applied to canonical object lifting. Before/after object metrics are therefore intentionally identical: 0 accepted, 1 ambiguous, 3 unresolved, 4 assigned faces.
The 21-check Phase 4.2 consistency report passed. Camera and original mesh hashes remained unchanged. The identical resumed command cache-hit alignment, object lifting, and both Phase 4 validators.

Known limitation
The reused Phase 3 run predates preservation of mesh_working.ply, so the audit reconstructed the working-frame mesh from the immutable final mesh and recorded inverse transform. It still performed independent GPU renders of both coordinate paths. Fresh Phase 3 runs preserve immutable working-frame PLY/GLB diagnostics.
A global Sim(3) is not sufficient for this real scene. The evidence points to local/chunk-level or generated-geometry inconsistency, which is diagnosed but intentionally not corrected here. Cameras were not rewritten. Metric scale, gravity alignment, hidden-surface completion, and simulation readiness remain false.
