Implements the reusable-library scope of #12. Part of #1.
Stacked on #18 to isolate this review to device library code, examples, and tests. The AST/GPU-loop acceptance item in #12 still needs #4–#7; this PR intentionally does not claim to implement or unroll a ray-marching loop.
Changes
shader_math: dot/cross/length/normalize, 2D rotation, clamp/mix/smoothstep, fract, and floor-based modulo.
sdf: sphere, 3D/2D box, centered repetition, square folding, and four-sample finite-difference normal estimation.
Compose existing typed arithmetic/vector/math primitives; no native dialect, conversion-pass, resource, or runtime changes.
Explicit shape/known-domain checks; zero vectors/flat gradients normalize to zero. Dynamic input-domain and representability limits are documented.
New visual examples
examples/distance_fields.py: repeated rotated box slices, smooth edges, and glow.
examples/surface_normals.py: sphere normals mapped to RGB.
```
LLVM_BIN="$PWD/.toolchains/llvm-build/bin" PATH="$PWD/.tools/bin:$PATH" \
  .venv/bin/python -m mlir_gpu examples/distance_fields.py \
  --target metal --output build/distance-fields-metal
PATH="$PWD/.tools/bin:$PATH" \
  .venv/bin/mlir-gpu-view build/distance-fields-metal/pipeline.json -frames 0
```
Use the second source with a fresh output directory for the normal visualization. Both compile for all three targets.
Validation
95 tests passed, including native compiler/DXIL/Metal conversion, GPU/API validation, window tests, and unchanged old graphics baselines.
CPU tests cover vector identities, zero normalization, signed-distance values, negative modulo/repetition, normals, and shape/domain errors.
GPU diagnostic shaders check normalization, sphere normals, repetition, folding, interpolation, inverse rotations, and distance values on Vulkan, DXIL-to-Metal, and preconverted Metal.
Both new examples match sampled CPU-reference pixels and cross-target colors within 2/255.
Both 400x300 native Metal PNGs and a bounded live normal preview were rendered successfully.
This is deliberately small helper inlining during the existing expression trace. Four normal samples are fixed expressions; no dynamic ray-march loop is flattened.
Final integration evidence
The remaining AST/device-loop acceptance is now verified in #32 (shared SDF helpers in the bounded gallery loop and finite-difference normal estimation) and #33 (unchanged loop bodies under a fourfold cap, independent CPU hit/miss oracle, all three GPU paths). These checks refer to the completed stacked implementation, not to this isolated library diff. All prerequisites and this PR remain pending review/merge.
Closes #12.
