Stacked on #96 (formerly #90; only for a shared tests.py; the library changes are independent). Rebased after #86/#87 landed; #89 became unnecessary — main now guards string columns itself. Ports the block cache from jpc/audio-fetch-perf onto main's async/presigned S3 reader.
What it does
"cache": true in an S3 .wsds-link turns on a local block cache. Every 128 KiB block a read touches is persisted in a sparse mirror <partition>/<subdir>/<shard>.wsds.sparse next to the shard's other column files, so the next read of those bytes — by this process, another worker, or another node — is a pread, not a range GET. The mirror is sized to the object but only physically holds fetched blocks (footprint = working set; a 10.7 GB shard with one 5 s segment read costs 2.5 MB on disk).
WSS3Shard decides per shard at open:
a full local .wsds at the shard's column path under the dataset root is always preferred;
with cache on, CachedS3FileReader: mirrored blocks served locally, a run of missing blocks fetched as one coalesced range and persisted in the background;
otherwise plain S3FileReader (unchanged).
Pieces
pupyarrow/block_cache.py — mirror format (data blocks + presence bytes + footer), BlockCache.read_range, one process-wide persister thread with group commit, fcntl-locked exactly-once fills across nodes, fsync before the presence byte; per-worker access logs; offline compaction helpers. The reader owns its mirror fd (closed with the reader), so fd count tracks live shards.
pupyarrow/file_reader.py — CachedFileReader(inner_factory, size_fn, root, name): a cache in front of any FileReader; the inner reader is built lazily on the first miss. CachedS3FileReader(client, bucket, key, root, …) is the S3 spelling, over main's S3FileReader (presigned/aiobotocore) so it inherits its retries and the presigned fast path. Also mirror_name(), FileReader.close() dropping the read buffers, LocalFileReader.path, and _IOLoop.run raising instead of deadlocking when re-entered from its own thread (found while porting: building a client from inside a read coroutine hung forever).
ws_s3_shard.py — _LazyS3Client: a fully mirrored or local shard never builds an S3 client (dominant cost of opening a cached shard; ~0.3 MB retained per client otherwise). WSDS_SKIP_S3=1 refuses S3 outright (train from the local cache only). WSS3Shard.close() — without it, evicting a shard from the open-shard cache freed nothing.
ws_shard.py — WSShardInterface.close() no-op default so WSDataset.close()/eviction work for every shard class (on main today WSDataset.close() raises AttributeError on a WSS3Shard).
cache_evict.py / cachectl.py (wsds-cache entry point) — global-LRU eviction to a target size from the access logs (cold mirrors unlinked, partially hot ones compacted via atomic rename), per-dataset policy files, a systemd user timer.
Async path (found while rebasing onto the current main)
main's _locate_batch now gathers all batch headers of a shard concurrently (WSS3Shard._batch_row_counts → FeatherFile.async_record_batch → reader.async_read) on any random access past the verified prefix. With the cache reader inheriting the base _async_read_impl (sync _raw_read in the loop's default executor), every one of those reads parked an executor worker on _IOLoop.run, and aiohttp's DNS lookup — which uses the same executor — could never run: every connect timed out (reproduced: 186 s of timeouts on a deep read; a fresh process read the same range in 0.6 s). CachedFileReader now implements _async_read_impl natively (BlockCache.async_read_range: hits served inline, misses awaited on inner._async_read_impl; the one-off HEAD / client build moved to a worker thread). Verified cold against B2: a deep access gathering 50 batch headers = 52 fetches / 8.5 MB, warm re-read 0 fetches, identical audio; unit test with a fake async inner.
Testing
BlockCacheTest (fake backend, no S3): coalesced cold fetch → mirror hit from a second reader; read_end + object size from the mirror footer (no HEAD); inner reader never built when mirrored; eviction scan of the mirror layout; CachedS3FileReader surface.
Real B2, 10.7 GB shard, temp cache root: cold 5 s segment = 3 GETs / 2.46 MB, client built; warm re-read = 0 GETs, no client built, identical samples; delivery-index catalog partitions (already mirrored) read with 0 fetches.
Full suite: the 6 doctest failures are pre-existing on main (need local datasets).
Overlaps #87 only in intent (client sharing): _LazyS3Client defers create_s3_client, so it composes with #87's per-process sharing when that lands.
