Important
Do not merge until luma.gl 9.4.3 is on npm. This needs visgl/luma.gl#3398 (release PR visgl/luma.gl#3463). Until then this repo patches @luma.gl/splats 9.4.2.
Adds RAD and static scene support to SplatLayer (URL, Blob, or {type: 'rad' | 'splats', url}). Scenes render through an internal SplatSceneLayer with off-thread loading, bounded residency, one sort order per viewport, and a splat budget shared with prepared layers. The Coit example is in #815.
New props: maxResidentSplats, maxConcurrentLoads, and maxActiveSplats (an alias for maxSplats).
Default: transparency becomes 'auto'. Prepared assets stay weighted; scenes sort.
Behaviour change: with transparency: 'sorted', Cartesian rows go through the scene renderer, which has no shadows, selection pulse, wind or hierarchy blending.
When luma publishes: bump @luma.gl/splats, then delete the patch and its resolutions entry.
Verified with yarn build, yarn test-types, yarn lint, the node suite and headless scene specs on WebGL2/WebGPU.
Note
High Risk
Large new async/GPU rendering path (workers, RAD paging, shared global sort, budget coupling) with strict Cartesian/RAD view constraints; publishing depends on upstream luma compatibility.
Overview
SplatLayer gains a composite “scene” path for RAD and static splat files (URLs/Blobs, worker decode), alongside the existing prepared Gaussian pipeline. transparency defaults to auto, routing prepared assets to weighted blending and scene inputs to globally sorted rendering; Cartesian owner rows can join shared sortDomain ordering with file/RAD scenes.
The scene stack adds off-thread RAD/static workers (bundled dist exports + workerFactory), RADScene with paged residency, PageScheduler download admission, and a deck SplatSceneRuntime effect that shares sources, budgets with prepared layers (setSceneDemands), per-viewport/domain sorting (WebGPU GPUPagedSplatRenderer / WebGL2 CPU sort), picking, and onStatusChange diagnostics. SplatLayer delegates to internal SplatSceneLayer when scene data is detected; new props include maxResidentSplats, maxConcurrentLoads, and maxActiveSplats as a maxSplats alias.
Package/docs/CI: @luma.gl/splats / @loaders.gl/splats dependencies, worker sideEffects, esbuild worker build script, expanded API/upgrade docs, and CI WebGPU run includes splat-scene.browser.spec.ts.

feat(layers): add RAD and static scene support to SplatLayer
…
5609304
```
Port the scene work from #814 (d04038f and its follow-up fixes) onto
master's per-owner SplatLayer architecture from #949, instead of replaying
the stale codex/remove-three-module stack.

SplatLayer now accepts URL/Blob scene assets, explicit
{type: 'rad' | 'splats', url} descriptors and owner rows that resolve to
them. Scenes delegate to an internal SplatSceneLayer backed by a shared
SplatSceneRuntime effect: off-thread RAD range loading with bounded page
residency and retained camera refinement, worker-decoded SPLAT/KSPLAT/SPZ
files, one global order per viewport and sortDomain, affine/SH instance
transforms, owner picking and host-pass presentation on WebGL2 and WebGPU.

Integration with master:
- transparency defaults to 'auto', which keeps prepared assets weighted.
  Direct prepared assets with 'sorted' stay on the prepared compositor;
  sorted Cartesian owner rows without opticalDepths join scene ordering.
- maxActiveSplats is an alias for maxSplats across master's demand
  retention, settled-budget and joint-grant paths.
- SplatRuntime.setSceneDemands charges scene grants against the host cap
  and nested parent groups, using master's resolveSplatBudget ('auto'
  budgets) and SETTLED_SPLAT_BUDGET_FRACTION.
- Keep master's primary-world-copy rendering for repeated MapViews (#962)
  and its highlight, coverage-range and slot handling.
- TreeLayer canopies request weighted transparency explicitly, so they do
  not depend on the SplatLayer default.
- Scene layers do not draw the deck.gl shadows added in #969; shadow
  casting and receiving stay on the prepared path, which the docs note.

@luma.gl/splats 9.4.2 lacks the host-pass GPUPagedSplatRenderer API and
retained RAD refinement this needs. Those are merged on luma's
9.4-release branch (visgl/luma.gl#3398) but unpublished, so the repository
keeps the Yarn compatibility patch from #814. Publishing requires the
upstream 9.4 release and removal of the patch.

Not ported: the three-workspace removal (landed in #953), the Tree Lab
canopy-shadow iterations and the old foliage shadow pipeline (removed in
#949), and docs that described the pre-#949 SplatLayer.

fix(layers): budget shared splat scene sources by canonical key
…
77b0ee1
```
acquireAsset shares equivalent URL/Blob descriptors through a canonical
key, but preRender counted RAD sources and keyed its active-splat caps and
download limits by descriptor identity. Two rows with separate
{type: 'rad', url: '/capture.rad'} objects counted as two sources, which
halved the shared grant and resident cap, and each owner then called
setBudget on the same RADScene, so the last layer could overwrite a
stricter maxConcurrentLoads.

Count sources, build budget and concurrency maps, and report
splatStats.sourceCount by the same canonical key that acquireAsset uses.

Also classify unmarked Blobs as RAD in one place. A Blob's MIME `type`
made isRADAsset treat it as a static descriptor while acquireAsset opened
it as RAD, so Blob scenes skipped the RAD projection check and were
budgeted as static coverage.

Addresses the Greptile "Shared sources use wrong limits" thread on #814.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```
fix(layers): keep splat scenes out of deck.gl shadow passes
…
4d20858
```
#969 changed SplatPrimitiveLayer's shadowEnabled default to true, and
SplatSceneLayer inherits SplatPrimitiveLayer.defaultProps. Under a
LightingEffect light with _shadow: true, deck.gl's ShadowPass would then
draw every scene layer, and the scene renderers would write
camera-ordered color into the light's shadow map.

SplatSceneLayer now defaults to shadowEnabled: false, SplatLayer forces it
off on its scene child, and draw() skips shadow-map passes as a backstop.
Scenes neither cast nor receive deck.gl shadows, as the SplatLayer docs
state; prepared rendering keeps #969's shadows.
