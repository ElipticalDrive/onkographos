Bug Description
RegisteredGLBuffer(..., device="cpu") can register its OpenGL buffer with CUDA when a CUDA context is already current. map() then wraps the CUDA-mapped pointer as a CPU array. Reading that array in a CPU kernel can access device memory as host memory.
I encountered this during an independent CPU/OpenGL correctness investigation while validating configurable primitive resolution. This is a separate defect from #1110, and I do not have downstream production impact to report. Historical CPU rendering support in #344 is related context, not this defect report.
The following self-contained probe was run in an isolated process against 0382a97e2c72911c1f6bba45274e12833a19d8e2. It initializes a CUDA context, selects CPU for Warp, then registers and maps a small OpenGL buffer. It deliberately asserts before reading a potentially mislabelled device pointer.
Save as cpu_gl_repro.py and run with the checkout's dependencies and built native libraries:
```
CUDA_VISIBLE_DEVICES=0 uv run cpu_gl_repro.py
```
```
"""Run in its own process: CUDA_VISIBLE_DEVICES=0 uv run cpu_gl_repro.py."""

import ctypes
import unittest

import numpy as np
import pyglet

import warp as wp

pyglet.options["headless"] = True
pyglet.options["headless_device"] = 0

from pyglet import gl  # noqa: E402  (headless mode must be selected first)

wp.init()
with wp.ScopedDevice("cuda:0"):
    wp.zeros(1, device="cuda:0")
    wp.synchronize_device("cuda:0")
    with wp.ScopedDevice("cpu"):
        window = pyglet.window.Window(width=16, height=16, visible=False)
        buffer_id = gl.GLuint()
        gl.glGenBuffers(1, ctypes.byref(buffer_id))
        registered = None
        mapped = None
        try:
            data = np.arange(8, dtype=np.float32)
            gl.glBindBuffer(gl.GL_ARRAY_BUFFER, buffer_id)
            gl.glBufferData(gl.GL_ARRAY_BUFFER, data.nbytes, data.ctypes.data, gl.GL_DYNAMIC_DRAW)
            gl.glBindBuffer(gl.GL_ARRAY_BUFFER, 0)
            registered = wp.RegisteredGLBuffer(int(buffer_id.value), device="cpu")
            mapped = registered.map(dtype=wp.float32, shape=(len(data),))
            print("CUDA registration succeeded:", registered.resource is not None, flush=True)
            print("Mapped array device:", mapped.device, flush=True)
            # Never dereference a potentially mislabelled CUDA device pointer.
            unittest.TestCase().assertIsNone(registered.resource, "CPU buffer unexpectedly registered with CUDA")
            np.testing.assert_array_equal(mapped.numpy(), data)
        finally:
            if mapped is not None:
                registered.unmap()
            mapped = None
            registered = None
            gl.glDeleteBuffers(1, ctypes.byref(buffer_id))
            window.close()
```
Observed on the baseline:
```
CUDA registration succeeded: True
Mapped array device: cpu
```
The probe exits with code 1 without dereferencing the suspect pointer. An earlier separate OpenGLRenderer CPU pixel-read run using the same baseline context/render implementation terminated with SIGSEGV (outer exit code 139) before completing a frame. That crash is a retained historical observation, not the outcome of the safe probe above.
Expected: CPU buffers use ordinary host storage and the OpenGL copy path regardless of ambient CUDA state; they must not attempt CUDA/OpenGL registration. fallback_to_copy=False should reject CPU explicitly. CUDA interoperability and its pinned copy fallback should retain their behavior.
A focused local fix is prepared: restrict CUDA registration to CUDA devices and share the ordinary host buffer directly with CPU GL transfers. The safe probe passes on that local fix. This report does not claim maintainer assignment or approval.
