Part of #356. Needs the mesh input (#372). Used by the ray provider (#358) and the depth query (#359).
Goal
Nearest-hit ray–triangle intersection fast enough for pupil-sampled captures, and deterministic: the same scene and request give the same bytes on every run, worker split and region tile.
Scope
Build: a bounding volume hierarchy over all triangles (and, optionally, analytic primitives as leaves), built once per scene digest.
Deterministic construction: binned SAH or median split with a fixed bin count and fixed tie-breaks (by primitive index); no randomness, no dependence on thread count or worker split.
Pure function of the scene bytes; the build can be cached by digest and transferred to workers as typed arrays.
Traversal: nearest positive hit, ordered child traversal, with the hit's triangle index, barycentrics and t returned.
Ray–triangle test: a watertight formulation (Woop, Benthin and Wald, "Watertight Ray/Triangle Intersection", JCGT 2(1) 2013) so rays do not slip through shared edges; float64 on the CPU reference path. Möller–Trumbore (JGT 1997) is acceptable only if the watertightness tests pass.
Tie-break and epsilon policy: documented; coincident triangles resolved by a fixed rule (lower primitive index), reported in assumptions.
Diagnostics: nodes visited and triangle tests per site, so cost can be attributed.
Performance budget notes:
The pupil path already costs 3.6–13× the default per site (docs/QUICK_START.md, Cost of each option). Every pupil ray now also traverses the BVH, so cost per site ≈ rays × (traversal + texture lookup).
Measure and publish cost-table rows for 1×4, 2×8 and 8×32 pupil rays on a reference mesh scene at 10⁴, 10⁵ and 10⁶ triangles, plus BVH build time and memory.
Memory estimate to verify: roughly 32–64 bytes per node and about 2 nodes per triangle, so about 64–128 MB at 10⁶ triangles (estimate; measure).
A later WebGPU traversal belongs to Fast image-formation capture path on WebGPU, with today's per-site engine as the accuracy reference #277 as a labelled approximation; the float64 CPU path stays the reference.
Non-goals
Dynamic or refitted BVHs (scenes are static), GPU builds, instancing (TLAS/BLAS), any-hit shadow rays (no shading in v1).
Acceptance
Exactness: on random rays against random triangle soups (fixed seed), BVH nearest hit equals brute-force nearest hit (same triangle index and bit-identical t) for every ray.
Watertightness: rays aimed at shared edges and vertices of closed meshes (tessellated sphere, cube) never miss.
Determinism: identical BVH bytes and identical capture bytes across repeated builds, whole frame against region tiles, and different worker counts.
Precision: a mesh placed at 1000 m still matches brute force.
Measured cost rows added to "Cost of each option".
Risks
Large scanned meshes (10⁶+ triangles) dominate memory and build time. Consumers should be told the measured limits and decimate offline.
SAH builds have many equal-cost ties; tie rules must be fixed for determinism.
Related: #358, #359, #277, #236.
