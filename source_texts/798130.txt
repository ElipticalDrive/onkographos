🤖 How to review this PR
This pull request was created and is maintained entirely by an automated agent — no human wrote these changes. You can drive it from this page; there is nothing to check out.
To request changes: leave inline comments on the diff and submit your review. Pending comments do nothing until the review is submitted. The agent then works through them and replies in each thread.
To ask it to take another look (say, after discussing something below): comment /compat-sync on this tab. Plain comments without that command are ignored, so you can talk freely here. This re-examines this PR — it does not pull in new upstream changes.
Expect minutes, not seconds. Comments are picked up on a 5-minute poll, and a pass takes anywhere from a few minutes to a couple of hours.
It may disagree with you. If it judges a comment mistaken, or that following it would break the compat conventions, it replies explaining why instead of complying. Push back if you disagree — it will answer again.
It comes back to you. Once it has answered everything you raised — with a fix, an argument, or both — it re-requests your review. GitHub tells you nothing when the changes you asked for actually land, so without this a CHANGES_REQUESTED would sit there indefinitely with the work already done.
Humans resolve human-authored threads. The agent never resolves a thread itself. The poller resolves answered threads opened by an allowlisted automated reviewer, but a human-authored thread stays open until that human has verified the reply.
It opens ready for review. The pull request is not a draft, but it still needs human review before merging.
Reaction markers and troubleshooting
👀 on your comment means it has been picked up; a reply follows when the pass finishes.
🚀 on your review means it has been answered and your review re-requested — the ball is back with you.
👀 with no reply means that pass failed. Comment /compat-sync to retry it — removing the 👀 yourself requires repository admin, which most reviewers do not have.
Only one pass runs at a time. Comment while one is in flight and it is picked up next cycle.
Avoid pushing commits to this branch while a pass is running — the agent's push may fail.
If this PR conflicts with master, just close it. The next sync regenerates it from scratch; hand-resolving is wasted effort.
