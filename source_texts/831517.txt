Goal
Make the first real Physics simulation state visible through Visualize as soon as an authoritative output contract is available. This is the shared visualization vertical slice for the independently developed water and fire domains; it is not a new physics implementation.
First visible result
Start with the smallest deterministic, replayable scene from existing Physics outputs. Water is the first candidate because the current BathymetricShallowWaterBasin2D API exposes row-major depth, bed elevation, free-surface elevation, depth-averaged velocity, and simulation time. Verify current model/branch status before locking to that API. Render a 2D scalar-field view with a legend and a few time steps, then reuse the field-display foundation for combustion fuel, temperature, oxygen, and reaction outputs when those observations are ready.
Ownership
Physics owns authoritative state, equations, units, timestep, model identity/version, and diagnostics.
Visualize owns conversion of observations into a scene, scalar/vector field presentation, legends, inspection, and static/replay artifacts.
Experiences owns scenario setup and visitor controls.
Do not add a solver or mutate physics state from Visualize. Do not fabricate missing fields, infer water/fire behavior from colors, or describe illustrative values as model output.
Implementation path
Audit the current Physics output APIs and handoff contract, including units, grid order, coordinate frame, simulation time, and model/run identity.
Add a small adapter/sample that snapshots a real model state into a Visualize-owned frame and produces a deterministic SVG artifact.
Show depth/free-surface values with units and legend; add velocity vectors only when the mapping and scale are explicit.
Step/replay a short deterministic run and ensure the visual frame and displayed numbers correspond to the same logical step.
Reuse the same observation-to-field presentation path for combustion fields; keep heat vision and the mathematics panel synchronized to the exact same run/tick.
Add tests for field ordering, finite values, deterministic output, units/metadata preservation, and clear unsupported-field behavior. Document exactly what the sample does and does not prove.
Acceptance criteria
At least one genuine Physics run produces a visible artifact through the Visualize-owned path.
The artifact changes in accordance with successive Physics snapshots; it is not a separately simulated browser animation.
Units, grid dimensions/order, time, and model identity are preserved and inspectable.
Visualize core remains independent of Physics solver implementation details and does not duplicate model equations.
Static SVG/CPU output is labeled honestly; no GPU, interactive-host, or physical-fidelity claims without evidence.
No package publishing, release, or master changes.
Related: Visualize fire demonstration, Physics fire experiment, and Physics-to-Visualize math/coordinate boundary.
