💡 What
Added an early exit in MeshProcessor::voxelize to skip the self.mesh.distance_to_local_point() BVH query for exterior voxels (!is_inside) during solid voxelization when narrow_band is not used.
🎯 Why
The distance_to_local_point method performs a costly bounding volume hierarchy (BVH) traversal to compute the exact distance to the mesh surface. For exterior points in standard solid voxelization, the exact positive distance is irrelevant because any point with sdf > 0.0 is discarded. By assigning a dummy constant of 1.0, we avoid significant computational overhead for empty space.
📊 Impact
Measurable reduction in voxelization time, particularly for models with large bounding boxes where many sampled points lie outside the mesh boundary. Benchmarks indicate a ~6-8% performance improvement on the standard test cube scale.
🔬 Measurement
Verified via cargo bench. Performance improved reliably: change: [−8.1341% −7.3539% −6.6243%] (p = 0.00 < 0.05). Evaluated for correctness via cargo test, ensuring standard output invariants and narrow band functionalities remained unaffected.

Preserve boundary voxels classified as exterior
When solid voxelization runs without narrow_band, this branch assumes every !is_inside point has a positive distance and can be discarded, but the previous sdf <= 0.0 behavior also kept points whose center lies exactly on the mesh surface even if the parity test classifies them as outside. For example, using --crop can shift the grid so a cube's max-X face is sampled at the voxel center; partition_point(|hx| hx <= x) makes that point !is_inside, while distance_to_local_point would return 0 and keep the boundary voxel. Replacing the query with 1.0 drops those boundary particles in solid mode.
