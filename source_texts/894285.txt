🔍 Design Review
Broken math at boundary — escape at iteration 0 indistinguishable from non-escape (src/mathviz/generators/fractals/_escape_kernel.py, _iterate_quaternion)
When a point escapes on the very first iteration (i=0), the function returns float(0) which is 0.0 — the same value returned for points that never escape. This means points whose initial norm already exceeds the escape radius are misclassified as interior points rather than exterior. Depending on the ESCAPE_ISOLEVEL used in marching cubes, this can produce spurious surface patches at the grid boundary.
Fix: Return float(i + 1) on escape (so the minimum escape value is 1.0), keeping 0.0 as the unambiguous "did not escape" sentinel. Alternatively, use a sentinel like -1.0 for non-escape.
Interface mismatch — validate_fractal_params called with a dummy power argument (src/mathviz/generators/fractals/quaternion_julia.py, lines ~113–115)
_DUMMY_POWER = 2.0 is passed to validate_fractal_params solely to satisfy its signature. This means: (a) the power validation runs on a meaningless value, silently passing; (b) if validate_fractal_params ever tightens its power bounds, it could reject this generator for no reason; (c) readers must understand a comment to know why power is there.
Fix: Either split validate_fractal_params into composable validators (e.g., validate_iteration_params(max_iter, voxel_resolution, extent) separate from validate_power), or add a power: float | None = None optional parameter that skips the power check when None.

🔍 DRY Review
Duplicated mesh-difference assertion pattern in tests — tests/test_generators/test_quaternion_julia.py lines ~65-71 (test_different_c_values_produce_distinct_shapes) and lines ~181-187 (test_slice_w_changes_shape) contain an identical 6-line block:
```
vertices_differ = len(obj_a.mesh.vertices) != len(obj_b.mesh.vertices)
if not vertices_differ:
    vertices_differ = not np.allclose(
        obj_a.mesh.vertices, obj_b.mesh.vertices,
    )
assert vertices_differ, "Different ... should produce distinct shapes"
```
Extract a helper like assert_meshes_differ(mesh_a, mesh_b, reason: str) at the top of the test module. This pattern is likely to recur in other fractal generator tests too.
validate_quaternion_c_params duplicates the core logic of validate_c_params — Both functions in src/mathviz/generators/fractals/_common.py iterate over (name, value) pairs, check abs(val) > MAX_C_MAGNITUDE, and raise a ValueError with an identical message format. The only difference is the number of components (3 vs 4). Unify into a single function that accepts a list of (name, value) tuples:
```
def validate_c_components(components: list[tuple[str, float]]) -> None:
    for name, val in components:
        if abs(val) > MAX_C_MAGNITUDE:
            raise ValueError(...)
```
Then validate_c_params and validate_quaternion_c_params become thin wrappers (or callers just pass the tuples directly).

🔍 General Review
Bug: Escape at iteration 0 is indistinguishable from "did not escape" — src/mathviz/generators/fractals/_escape_kernel.py, _iterate_quaternion
The function returns float(i) when a point escapes and 0.0 when it does not escape. When i == 0 (i.e., the initial point's norm already exceeds the escape radius), float(0) == 0.0, making these exterior points look like interior (non-escaping) points. This can cause marching cubes to produce spurious geometry at grid boundaries if any initial grid coordinates lie outside the escape radius.
```
for i in range(max_iterations):
    norm_sq = a * a + b * b + c * c + d * d
    if norm_sq > escape_radius_sq:
        return float(i)        # ← returns 0.0 when i == 0
    ...
return 0.0                     # ← same value as "did not escape"
```
A common fix is to return float(i + 1) for escapes (so the minimum escape value is 1.0) or return -1.0 / max_iterations for the non-escape case — whichever convention the existing mandelbulb_escape_field uses. Check that the fix aligns with how ESCAPE_ISOLEVEL is defined.
