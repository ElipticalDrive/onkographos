Summary
Issue #36 / E7-2: voxelize_mesh(..., fill=True) no longer builds a trimesh.Trimesh and calls .contains() (ray-cast point-in-mesh parity) to detect interior voxels. It now runs a pure voxel-grid exterior flood-fill (6-neighbor BFS from outside the surface-voxel AABB, treating surface voxels as walls) and fills whatever cells the flood-fill can't reach.
Real-data investigation on files/ToyodaLab.ifc showed trimesh's watertightness check false-positives on 71% of elements (an artifact of weld-vertices=False's per-face vertices) and, more importantly, that mesh.contains() itself gives ray-direction-dependent disagreements on real non-manifold furniture geometry (up to 182/3375 sample points). Flood-fill is insensitive to both issues since it only depends on the surface-voxel shell having no gaps.
Documented (and tested) the one real limitation: a shape with a genuine hole (true boundary edge, e.g. a box missing a face) leaks exterior flood-fill through the hole, so its interior stays unfilled — this is the correct outcome for a shape that isn't actually closed, not a robustness gap.
Removed now-dead trimesh/logging imports and the is_watertight warning from voxel.py.
Issue #38 / E7-4: voxels.json's per-element indices (a naive flat list of Morton codes) is now delta + run-length encoded (encode_morton_indices()/decode_morton_indices()), since sorted storage (already mandated by spec.md §2) makes consecutive deltas small and repetitive.
Measured on synthetic large voxel grids: ~99.8% smaller for a solid-filled cube (typical of fill=True walls/floors/slabs), ~73% smaller for a surface-only shell (the default, less regular case).
viewer.js's decodeMortonIndices() mirrors the Python decoder but passes a plain array straight through unchanged, so older v2-shaped indices (and the client-side v1-conversion path) still load with no special-casing.
Bumped voxels.json to v3 (only the indices representation changed from v2) and updated docs/viewer/spec.md §2 accordingly.
Also refreshed CLAUDE.md's stale "Planned work" section: Epic E7 is now fully done, and Epic E8 (previously listed as unimplemented there) was actually completed and merged in an earlier session (PRs #47/#48).

```
trimesh.contains() ray-parity was unreliable on real ToyodaLab.ifc data:
weld-vertices=False means every face has its own vertices, so trimesh's
edge-sharing watertightness check always reports non-watertight (71% of
converted elements), and for multi-body touching geometry (furniture,
building-element proxies) the ray-cast itself disagreed across ray
directions on the same points. Structural elements (walls/columns/slabs)
were already fully watertight and unaffected; windows/doors are
legitimately non-volumetric and have no consistent "interior" to begin
with.

_fill_voxels now floods the voxel grid's exterior via 6-neighbor BFS from
outside the surface-voxel AABB and fills whatever it can't reach, instead
of asking trimesh whether a point is inside the mesh. This depends only
on the surface voxel shell having no gaps, not on mesh topology or ray
numerics, so it's robust to unwelded per-face vertices and non-manifold
touching bodies. It still can't fill through a genuine hole (a real
boundary edge, e.g. IfcWindow) — that's an inherent limitation of any
surface-based fill and is now covered by a regression test documenting
it, alongside a synthetic touching-cubes test reproducing the
non-manifold defect class found in the real data.
```

…

```
)

Each element's `indices` in voxels.json was a flat sorted JSON array of
Morton (Z-order) codes, which grows linearly with voxel count and, since
codes can be large 63-bit integers, dominates output size on big models.

encode_morton_indices()/decode_morton_indices() replace it with a
{"base": ..., "deltas": [[delta, run_length], ...]} encoding: since
spec.md already mandates sorted storage, consecutive deltas are small
and often repeat (long runs of the same delta are common in filled
regions), so delta + run-length coding compresses well. Measured on
synthetic grids: ~99.8% smaller for a solid-filled cube, ~73% smaller
for a surface-only shell (the default, less regular case) -- both
covered by a dedicated size-reduction test.

viewer.js's decodeMortonIndices() is the JS-side mirror, and passes a
plain array straight through unchanged, so v2-shaped indices (older
files, or the client-side v1-to-current converter's output) still load
without any special-casing.

Bumped voxels.json to v3 (indices encoding is the only change from v2)
and updated spec.md, all affected tests, and CLAUDE.md accordingly.
Also refreshed CLAUDE.md's stale "Planned work" section: Epic E7 is now
fully done and Epic E8 (previously listed as unimplemented) was actually
completed and merged in an earlier session (PRs #47/#48).
```
