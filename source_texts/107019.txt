Summary
While auditing the vtk.js API surface (the rendering backend used by ts/renderer.ts), I noticed that vtk.js provides vtkRendering.Core.vtkVolume, vtkRendering.Core.vtkVolumeMapper, and vtkRendering.Core.vtkVolumeProperty, but pyvista-js has no equivalent of PyVista's Plotter.add_volume(). This issue proposes adding volume rendering.
vtk.js modules
Sources/Rendering/Core/Volume
Sources/Rendering/Core/VolumeMapper
Sources/Rendering/Core/VolumeProperty
Note: volume mappers take vtk.Common.DataModel.vtkImageData as input, so this depends on the ImageData data object (tracked separately).
Proposed API (mirroring PyVista)
```
grid = ImageData(...)
plotter = Plotter()
plotter.add_volume(grid, cmap="viridis", opacity="linear")
```
Implementation notes
ts/renderer.ts needs a new actor type that creates a volume with a mapper and property (color transfer function mapping can reuse the existing vtkColorTransferFunction plumbing used for scalar colors).
In Python, rendering.py serializes the volume configuration into the scene data, consistent with the existing actor/scalar-bar flows.
Update ts/vtk.d.ts with the type declarations for the new factories.
Add a test named test_add_volume() (may live in the Playwright browser tests because the renderer is required).
