The texture, texture view and sampler descriptor-handle getters dropped getDescriptorHandle's result and returned a null handle when slang-rhi could not make one. The buffer getters already check it. On a device without bindless (Metal today), a shader then read nothing through the handle, and every texture sample came back zero with no error. The getters now go through SLANG_RHI_CALL, as the buffer getters do, so the slang-rhi error is raised.
Changed: Texture::descriptor_handle_ro/_rw/_combined, TextureView::descriptor_handle_ro/_rw/_combined, Sampler::descriptor_handle. On devices that support these handles nothing changes. Code that asked for a combined texture-sampler handle on a backend that has none now gets an exception instead of a null handle.
Fixes #1241.
Test
New test_descriptor_handle_without_bindless in slangpy/tests/device/test_bindless.py: on a device without Feature.bindless, each of descriptor_handle_ro and descriptor_handle_rw on a texture and on a texture view, and sampler.descriptor_handle, must raise. The combined getters are not asserted, since combined-handle support is separate from bindless. It is skipped where bindless is supported.

after: passed. test_bindless.py and test_descriptor_marshall.py together: 1 passed, 3 skipped (no bindless), 4 xfailed, as before.

Thanks for the merge and the heads-up. This was the first full CI run on the PR, and it caught a real gap in my change.
What failed: test_bindless_texture[DeviceType.cuda] raised SLANG_E_NOT_AVAILABLE from Sampler::descriptor_handle.
Why: CUDA has no separate sampler objects. The texture view carries the sampling state (the test already creates its CUDA views with sampler=), and Slang's CUDA prelude lowers SamplerState to an unused pointer (prelude/slang-cuda-prelude.h). slang-rhi's CUDA SamplerImpl doesn't override getDescriptorHandle, so the base Sampler::getDescriptorHandle in src/rhi-shared.cpp returns SLANG_E_NOT_AVAILABLE. Before this PR that result was ignored and the null handle went unused. With the PR it raised, so portable bindless code that writes a sampler handle on every backend broke on CUDA.
What changed (3042f7c): on CUDA, Sampler::descriptor_handle now returns an undefined handle (type undefined, falsy) without asking slang-rhi. That is the correct answer there, since there is no sampler handle to give. Every other backend still raises when a handle can't be made, so the Metal case this PR is for is unchanged. I documented this on the getter and added test_sampler_descriptor_handle: an undefined handle on CUDA, a valid sampler handle elsewhere.
What I ran (Windows, RTX 4060 Ti, d3d12/vulkan/cuda): test_bindless.py and test_descriptor_marshall.py gave 11 passed, 4 skipped (no non-bindless device here, and test_bindless_buffer on CUDA, which was already skipped), 4 xfailed. test_bindless_texture[cuda] passes now. With --runxfail, test_sampler_descriptor[cuda] gets past the handle and stops at the #922 marshalling error, so its strict xfail still holds for the original reason.
