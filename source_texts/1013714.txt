Problem
VertexFormat describes every element as a component count times one of the TYPE_* component types, TYPE_INT8 to TYPE_FLOAT16 (constants.js). The element size is the component count times the per-component byte size (vertex-format.js). Both backends map a type to a per-component format (WebGPU, WebGL).
There is no way to describe a packed element, so these formats cannot be used:
WebGPU unorm10-10-10-2 and unorm8x4-bgra, both part of core WebGPU.
WebGPU snorm10-10-10-2, added in Chrome 155-156 (What's New in WebGPU 155-156, gpuweb#6491).
The WebGL2 vertex attribute types UNSIGNED_INT_2_10_10_10_REV and INT_2_10_10_10_REV.
As a result, a normal or tangent stored in 4 bytes is limited to 8 bits per component (TYPE_INT8 x 4, normalized). 10 or more bits per component take 8 bytes (TYPE_INT16 x 4), or a custom decode in the shader.
Browser support for snorm10-10-10-2
It is a core GPUVertexFormat value, not an optional feature, so there is no features.has() check. A browser without it rejects the value when the render pipeline is created.
Chrome 155-156. Chrome 152 throws a TypeError from createRenderPipeline() for it.
Safari: listed in WebKit's GPUVertexFormat.idl. The Safari release that ships it has not been checked.
Firefox: not in WebGPU.webidl, which lists only unorm10-10-10-2.
