Hi,
Currently I am trying to extract the yaw, pitch and roll rotation of a Vive using openVR to send to another program via OSC.
As far as I understand, this can be achieved by calling the GetCurrentViewProjectionMatrix() and calculating yaw, pitch and roll from the rotation matrix. It seems, however, that rotation is not correct and two issues occur.
The first issue is that when the Vive performs a yaw-only rotation, as it approaches +-90 degress the pitch and roll values increase drastically by 180 degres, giving the effect of a shift from looking straight left/right to the opposite.
The second issue is that head rotation on one axis-only seems correct, but combinations of yaw, pitch and roll rotation is not correctly calculated/displayed. e.g. when your head is rolled 90 degress and you proceed with a pitch motion (initial up/down) this is still percieved is up/down movement, while it obviously is a left/right movement due to the preceding roll.
I have tried to obtain the yaw, pitch and roll from the hellovr_opengl example. This is my code:
```
    Matrix4 matMVP = GetCurrentViewProjectionMatrix(vr::Eye_Right);

    float orientationMat[4][4];
    for (int j = 0; j < 4; j++) {
        for (int k = 0; k < 4; k++) {
            orientationMat[j][k] = matMVP[(j * 4) + k];
        }
    }
    yaw = (float)atan2(orientationMat[2][0], sqrt(pow(orientationMat[2][1], 2) + pow(orientationMat[2][2], 2)));
    pitch = (float)atan2(orientationMat[2][1], orientationMat[2][2]);
    roll = (float)atan2(orientationMat[1][0], orientationMat[0][0]);


    //subtract new center and convert to degrees
    headYaw = (yaw - centerYaw)*(180 / M_PI);
    headPitch = (pitch - centerPitch)*(180 / M_PI);
    headRoll = (roll - centerRoll)*(180 / M_PI);
```

The method GetCurrentViewProjectionMatrix is not an OpenVR API call, it is a utility function from the demo app. You cannot extract world space rotation from a view projection matrix. You can probably get a single pitch, yaw, roll representing the entire Vive from the HMDPose matrix.

@Hellgringo83, I never got the rotation matrix to act properly with the openVR by using this approach. Not even with the quaternion conversion that @bjornbytes suggested (Thanks for the suggestion though!).
What I did was to use Unity3D for extraction of HMD rotation. In the unity_keyboard_sample you can use the x,y and z rotation of the camera used for the HMD. It was so much easier to use - at least to me - since no translation is needed.
In an update function I extracted the rotation from the main camera - which has the "Steam_VR_Camera" script acttached - and it works perfectly for me. To get the rotation values attach a script to the main camera which includes the following code (also included is a method for recentering):
```
yaw = Camera.main.transform.rotation.eulerAngles.y;
pitch = Camera.main.transform.rotation.eulerAngles.x;
roll = Camera.main.transform.rotation.eulerAngles.z;

if( Input.GetKeyUp( KeyCode.Home ) ){
yawCenter = yaw;
//Debug.Log("RECENTER!");
}

yawHead = -1.0f * (yaw - yawCenter);
pitchHead = -1.0f * pitch;
rollHead = -1.0f * roll;
```
