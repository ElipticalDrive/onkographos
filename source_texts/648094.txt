目的
rounded rectangleを最初のprimitiveとして、analytic SDF → height field / bump map のpipelineを実装する。
ここがUkibori rendererの最初の視覚的PoC。
必須実装
1. Analytic rounded-rectangle SDF
screen-space point p に対してsigned distanceを返す。
期待する符号規約を固定すること。
例:
inside: negative
boundary: zero
outside: positive
標準的なrounded-box SDF式を使用してよい。
2. SDF → height profile
SDFをそのまま色として使うのではなく、surface elevationへ変換する。
概念:
```
distance = sdf(shape, p)
localHeight = profile(distance, bevelWidth, thickness)
H = baseElevation + localHeight
```
profileは少なくとも以下を満たすこと。
surface中央はほぼ一定高さ
edge付近は連続的に高さが変化
edge外ではbaseへ落ちる
0次/1次連続性を意識し、目立つ折れを避ける
silicone-likeな丸い立ち上がりを作れる
profile関数をSDF実装へベタ書きせず、独立した概念として扱う。
Bump / height mapは必須成果物
このIssueでは最終shadingだけを見せて完了にしてはいけない。
デモ/デバッグ表示として最低限:
shape mask
signed distance visualization
height / bump map visualization
surface中央を横切るheight cross-section graphまたは数値fixture
を確認できるようにする。
Cross-sectionで確認したいこと
```
height
  ^
  |             __________
  |           /
  |         /
  |_______/
  +------------------------> x
```
edgeが単なるstepではなく、滑らかな曲面profileになっていること。
CPU reference + GPU path
可能なら同じSDF/profile式について小さなCPU reference実装を持ち、GPU出力との比較に使う。
最終的なrenderer pathはWebGPU/WGSLを想定するが、数学的意味論をshaderに閉じ込めない。
非目標
normal map
BRDF
cast shadow
multiple surfaces
DOM integration
React API
box-shadowによる代替
禁止
以下はこのIssueの完了条件を満たさない。
CSS border-radius を付けただけ
box-shadow で縁を丸く見せただけ
linear-gradientで擬似bumpを描いただけ
SDF値を生成せずmask blurだけで済ませる
height bufferを生成せず直接最終色を出す
Acceptance Criteria
rounded rectangleのanalytic SDFが実装される
inside / boundary / outsideの符号をtestできる
SDFからheight fieldを生成する独立profile関数がある
radius / elevation / bevel width変更がheightへ反映される
heightは非有限値を生成しない
SDF debug viewがある
bump/height debug viewがある
cross-sectionでedge profileを確認できる
CSS shadowなしでheight geometry自体を確認できる
Definition of Done
「rounded rectangleの物理的な盛り上がりがpixelごとのheightとして存在する」こと。
DeepSeek / 実装担当への進行ルール
このIssueを実装するときは以下を厳守する。
このIssueのscopeだけを実装する。 後続Issueの機能を先回りして作り込まない。
実装前にParent / Depends onのIssueを読み、そこで固定された座標系・buffer意味論・禁止事項を変更しない。
Acceptance Criteriaを別手段で「それっぽく」満たしたことにしない。特にSDF / height / normal / visibility等、明示された中間表現は実際に生成する。
禁止事項に書かれたCSS近似やshortcutをrenderer coreへ持ち込まない。
debug viewが要求されているIssueでは、最終見た目だけでなく中間bufferを人間が確認できる出力を残す。
完了時は必ず以下を報告して停止する。
変更ファイル
主要な設計判断
実行したtest/typecheck/build
Acceptance Criteriaごとの対応状況
debug viewの確認方法
未解決事項
次のIssueへ自動で進まない。レビュー待ちで停止する。
既存コードとの互換性より、このIssueとArchitecture Issueで固定されたrenderer semanticsを優先する。
