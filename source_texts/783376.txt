S2S scalability follow-up
Closes #412.
This PR starts the S2S scalability work identified in the audit after merging the thermal/radiation validation PR.
Implemented now
Add a CPU AABB/BVH hierarchy for radiation triangles.
Replace per-ray full target/blocker triangle scans with BVH nearest-hit traversal.
Keep the existing deterministic ray sampling and public S2S API unchanged.
Add a regression test comparing BVH nearest-hit results against the brute-force intersection path.
Document the complete staged architecture for dense, sparse, matrix-free, CPU and CUDA execution.
Why this matters
The existing dense view-factor path is O(N²) memory and cannot be the industrial default. The ray-traced path also previously had O(N_triangles) visibility work per ray. BVH acceleration removes that second bottleneck without changing the numerical estimator.
Planned phases
BVH acceleration — implemented here.
Dense/CSR/matrix-free view-factor operator abstraction, reciprocity and closure diagnostics.
CPU parallel and memory-aware execution.
CUDA-resident surface/BVH and batched ray traversal, with explicit hardware gating and no silent CPU fallback.
Dense/sparse/matrix-free equivalence, memory scaling and CPU/GPU V&V.
This PR deliberately does not claim that CUDA acceleration or matrix-free storage is already implemented; those are the next stages and are documented with explicit validation gates.
