What changed
raise the mobile starting DPR from 1.6 to 1.7 while keeping the existing pixel budget
replace the stock full-resolution Three.js Bokeh pass with an adaptive low-resolution Bokeh pipeline
cached 40%/25% packed-depth buffer
7-sample / 4-sample circular blur modes
sharp full-resolution composite and sky protection
make dynamic quality reduce Bokeh cost before lowering scene resolution
improve voxel LOD selection with projected voxel size plus projected building diameter guards
increase greedy-mesh merge spans for terrain and generated buildings
add spherical horizon chunk culling and use front-face terrain rendering
add focused tests for adaptive Bokeh sizing, mobile quality policy, and LOD preservation
Why
The previous mobile optimization was technically active, but it did not produce a convincing visual or performance improvement. Resolution still looked soft, distant buildings collapsed to secondary LOD too early, and the stock Bokeh pass duplicated an expensive full-resolution depth render.
Impact
macro terrain triangles drop from about 1.65M to about 299K (approximately 82%)
generated building LOD geometry drops by approximately 22%
the acceptance camera keeps all visible recognizable buildings on near LOD
iPhone-class devices start at DPR 1.7 and only sacrifice resolution after lowering Bokeh quality
Bokeh remains visible under normal load and is disabled only under severe sustained frame pressure
Validation
pnpm build
pnpm test: 173 passed, 1 skipped, 0 failed
mobile Chromium/SwiftShader visual smoke test at fixed DPR 1.7
adaptive-quality stress smoke test with no console or WebGL errors
Real iPhone Safari profiling is still required after deployment to confirm the 60 Hz target on hardware.
