Description
Currently, we cannot display a 3DT GS with a custom shader to modify the color of a splat : doing so does not have any effect, at best.
As we are working on change detection between gaussian splats and point clouds, we need to provide a custom shader to 3DT GS and display their classification. The classification is stored in the gltf/glc (featureid_0) and is obtained through a Reality Analysis change detection job https://qa-developer.bentley.com/apis/reality-analysis/operations/jobs-create/
0 = no change, we display the original color
1 = change, we blend the original color with an arbitrary color (blue).
Expected result :
The goal of this PR is to make 3DT GS support custom shaders, so we can display changes. It will also allow other Cesium users to display 3DT GS with custom shader for other purposes.
Issue number and link
https://github.com/iTwin/platform-engineering/issues/370?reload=1?reload=1?reload=1%3Freload%3D1?reload=1%3Freload%3D1%3Freload%3D1%3Freload%3D1?reload=1%3Freload%3D1%3Freload%3D1%3Freload%3D1%3Freload%3D1%3Freload%3D1%3Freload%3D1%3Freload%3D1
Testing plan
I'm not an expert of CesiumJS, however I think we should test at least those cases :
Display classified 3DT GS with custom shader (I will make a sandbox example)
Display classified 3DT GS without custom shader (should display the 3DT with the original colors)
Display unclassified 3DT GS with custom shader (trying with another custom shader. For instance, color the splats based on elevation?)
Display unclassified 3DT GS without custom shader (should display the 3DT as usual)

Minor mit (base on you preference):
color_0 is being set to baseColor, which is already pre-multiplied by alpha (rgb * B). This means if a user writes material.diffuse = fsInput.attributes.color_0.rgb in their fragmentMain, they'll get a darker/washed-out result because the value hasn't been un-pre-multiplied yet.
material.diffuse is correctly un-pre-multiplied before fragmentMain is called, but color_0 is not, so the two are inconsistent. This also differs from how color_0 works in Model custom shaders, where it holds a linear color.
Maybe:
```
fsInput.attributes.color_0 = vec4(
    baseColor.a > 0.0 ? baseColor.rgb / baseColor.a : vec3(0.0),
    baseColor.a
);
```
