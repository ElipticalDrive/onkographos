Summary
A forward-only CPU-vs-CUDA Gaussian splatting map-renderer comparison
(src/comparison_gaussian_splatting.cu). A synthetic LiDAR-like map is
represented as colored 3D Gaussian surfels and rendered from a moving camera;
the demo runs the same scene two ways — a CPU sparse-surfel renderer and a CUDA
dense splatting kernel (one Gaussian per thread, projected to screen space with
atomic additive accumulation into color/opacity buffers) — and reports a
correctness check plus an animated throughput sweep.
The implementation is intentionally small and self-contained: not a training
pipeline, no external Gaussian Splatting codebase copied. The relevant robotics
hook is the CUDA pattern (one Gaussian per thread, atomic accumulation).
Relationship to the existing renderer (honest framing)
master already has src/gpu_gaussian_splatting.cu (PR #59, "GPU 3D Gaussian
Splatting renderer, isotropic alpha-composite", ~1k Gaussians, 0.94 ms/frame) in
the showcase table and headline benchmarks. This PR is a separate file and a
different angle: a head-to-head CPU-baseline-vs-CUDA comparison demo in the
repo's comparison_* idiom, scaling to 65,536 Gaussians, with a numerically
verified CPU↔CUDA match. It is additive (a second Gaussian-splatting demo on the
comparison axis), not a replacement of #59. Reviewer call on whether a second
Gaussian-splatting demo is wanted.
This branch was created 2026-05-21 on a since-stale master and never opened as
a PR; it has been rebased clean onto current master (8a32521) — additive
only, no stale reverts.
