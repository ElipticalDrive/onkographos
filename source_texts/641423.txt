Summary
Replaces the explicit WCSPH solver (Tait-EOS pressure force, CFL-limited substeps) with Position Based Fluids (Macklin & Muller 2013): predict under gravity, run a fixed number of Jacobi density-constraint iterations, derive velocity from the resulting position change. The density constraint is unconditionally stable on its own, so substeps are now bounded only by a free-fall/diffusion limit instead of a stiffness-driven CFL term.
Adds the s_corr tensile-instability correction to resist particle clustering under tension.
Adds Morris-style (2000) color-field curvature surface tension, computed in a new pass and applied as a cohesion force alongside gravity at predict time. Reuses the existing Poly6/viscosity-Laplacian kernels rather than introducing a new kernel family (e.g. Akinci-style cohesion). Defaults to 0 (no-op) so existing scenes/caches are unaffected until enabled.
Removes the now-unused stiffness domain property; adds Solver Iterations, Constraint Relaxation, Anti-Clustering Strength, and Surface Tension in its place.
Updates config_hash() so any change to the new PBF/tension parameters correctly invalidates stale disk caches.
Extends scripts/smoke_test.py with a PBF-specific convergence check (mean particle density vs. rest density), which the old smoke test had no equivalent for since WCSPH never had a density constraint to check.
Test plan
python3 scripts/test_marching_cubes.py passes (pure-Python regression gate, unaffected by the solver change)
ruff check . passes
blender --background --python scripts/smoke_test.py (needs a GPU-enabled Blender 5.2+ environment to actually exercise the compute shaders and the new PBF convergence check)
Manual run in Blender via scripts/dev_link.py + scripts/reload_on_save.py: confirm stability over a few hundred frames, settling behavior vs. the old WCSPH solver, and (with Surface Tension > 0) visible meniscus/beading behavior with no change at 0
Confirm the disk cache invalidates correctly on a PBF/tension parameter change (resimulates instead of silently replaying stale frames)

Correctness — removed viscosity force with no replacement.
None of the new PBF shaders read f_sim.x (viscosity) — I grepped all of shaders/*.glsl for f_sim\. and only .y (dt), .z (gravity), and .w (boundary_damping) are ever referenced. The old sph_force.glsl applied an explicit viscosity force (f_viscous += viscosity * mass * (vj - vi) / dj.x * w_visc_lap(...)); that file is deleted and nothing in the new pipeline (predict/lambda/delta/velocity/xsph/finalize) reproduces it. XSPH damping remains, but XSPH's coefficient is a hardcoded constant (XSPH_EPSILON = 0.5), not driven by the user's viscosity value.
Meanwhile domain/__init__.py's viscosity property ("Dynamic viscosity coefficient; higher is thicker and more damped") is still exposed in the UI panel, still baked into config_hash(), and still fed into f_sim here — it's now silently dead as a physical parameter. It still affects substep_dt()'s viscous_dt limit, but that only changes substep granularity, not the fluid's actual damping/thickness the description promises.
Failure scenario: a user raises Viscosity from 0.1 to 5.0 expecting a visibly thicker/more damped fluid (per the tooltip) and sees no change in the simulated motion, because no shader force ever reads that value.

Efficiency — sph_normal dispatches unconditionally every substep, even though surface tension defaults to 0 (off).
sph_normal runs a full 3x3x3 neighbor-loop compute pass over every particle each substep regardless of config.surface_tension. Its own docstring already argues that this is affordable ("a small fraction of the substep's cost next to the grid build"), but that means every scene created with the new default settings (surface tension off) still pays for this pass forever, for a normal_img value that sph_predict.glsl explicitly skips using when sigma <= 0.
Since this is a Python-orchestrated dispatch loop (_substep(), line 480), gating it costs nothing at the GLSL level — no branch is needed in the shader itself:
```
if config.surface_tension > 0.0:
    dispatch_1d(_bind("sph_normal", dt), config.particle_count, LOCAL_GROUP_SIZE)
dispatch_1d(_bind("sph_predict", dt), config.particle_count, LOCAL_GROUP_SIZE)
```
normal_img is zero-initialized in _allocate(), and sph_predict.glsl already guards on mag > 1e-4, so leaving it un-updated when tension is off is safe.
