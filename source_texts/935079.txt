💡 What: Changed polygonize_tetrahedron in src/experimental/isosurface.rs to group elements into [usize; 3] arrays inline and push them directly into a Vec<[usize; 3]>, rather than building a flat Vec<usize> and then mapping over it with .collect().
🎯 Why: Generating a flat list only to immediately transform it with .chunks(3).map(|c| [c[0], c[1], c[2]]).collect() forced the system to perform a completely unnecessary per-frame O(N) memory allocation and copy pass for the indices, violating zero-cost principles.
📊 Impact: Eliminates one intermediate Vec heap allocation per isosurface extraction and removes the O(N) mapping iteration pass, yielding faster surface generation and lower memory pressure.
🔬 Measurement: Run cargo test --no-default-features --features "backend-tui nova parallel" -- isosurface to verify identical mesh structure and behavior without the allocation.

Removed a completely unnecessary heap allocation in the Marching Tetrahedra `extract_isosurface` algorithm. Previously, the algorithm pushed individual `usize` indices into a flat `Vec<usize>` and then performed an O(N) mapping pass with `.chunks(3).map(...).collect()` to generate the final `Vec<[usize; 3]>` required by the `Mesh` struct.

By slightly refactoring `polygonize_tetrahedron` to group indices inline using a state counter and a temporary array, we can safely push `[usize; 3]` arrays directly into the final `Vec<[usize; 3]>`. This eliminates the intermediate vector allocation, the iteration over the chunks, and the memory copy pass entirely while producing the exact same mesh topology.
