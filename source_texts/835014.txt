Description
Implement a debug rendering subsystem that allows the editor and renderer to draw debug primitives (lines, meshes, points) for visualization purposes. These are rendered via the GizmoPass pipeline (shared outline-based gizmo infrastructure) to overlay debug information on the rendered scene.
Requirements
Debug Primitives
DebugLine: Render a 3D line segment (start, end, color) with configurable width. Support line lists and line strips.
DebugMesh: Render a wireframe overlay of a mesh (position, color). Uses the existing vertex/index buffer infrastructure plus a dedicated wireframe pipeline in GizmoPass.
DebugPoint: Render a 3D point (position, color, size). Support point lists with configurable point size.
Rendering
Immediate-mode API: DebugRenderer::DrawLine(start, end, color, duration), DebugRenderer::DrawMesh(meshId, color), DebugRenderer::DrawPoint(pos, color, size).
Duration: Primitives can be persistent (until explicitly cleared) or single-frame.
GizmoPass integration: Debug primitives are rendered by the GizmoPass as additional overlays alongside selection outlines.
Depth-aware: Lines and points use depth testing (occluded lines are hidden behind geometry). Optional x-ray mode (always-on-top) for debug visualization.
Line width: Use VK_EXT_line_rasterization for wide lines if available; otherwise fall back to triangle-based thick lines.
Use Cases
Physics collider visualization (AABB, OBB, sphere, capsule)
Light frustum visualization (shadow camera frustums)
Camera frustum visualization
Path visualization (spline, bezier)
Skeleton/joint visualization (bone lines)
Navmesh overlay
Trigger zone / volume visualization
Architecture
New files:
src/editor/debug/DebugRenderer.h/cpp - immediate-mode debug draw API (owned by Editor, consumed by GizmoPass via RenderContext)
src/editor/debug/DebugPrimitive.h - structs for line, mesh, point draw commands
Modified files:
src/render/passes/GizmoPass.h/cpp - extend to consume debug primitive lists and render them
src/render/RenderContext.h - carry debug draw list from Editor to Renderer
Pipeline: GizmoPass gets additional sub-pipelines (wireframe, line, point) with appropriate rasterization state.
Descriptor: Per-frame debug data uploaded via UBO (color, transform matrices for each primitive type).
Integration flow: Editor populates DebugRenderer -> RenderContext::debugDrawList -> GizmoPass reads and renders.
Acceptance Criteria
DrawLine(start, end, color) renders a visible line in the viewport.
DrawMesh(meshId, color) renders a wireframe overlay on the specified mesh.
DrawPoint(pos, color, size) renders a visible point.
Depth testing works (lines behind geometry are hidden).
X-ray mode renders primitives on top of all geometry.
Single-frame primitives disappear after one frame; persistent primitives stay until cleared.
No Vulkan validation errors.
Performance: 10,000 debug lines < 0.5ms overhead.
References
src/render/passes/GizmoPass.h/cpp (planned - see Viewport Selection issue)
src/render/RenderContext.h - per-frame scene data
src/editor/Editor.h - editor orchestrator owns DebugRenderer
src/render/buffers/ - vertex/index buffer infrastructure
src/render/DeferredRenderer.h/cpp - render loop integration
Unreal DrawDebugLine / Unity Debug.DrawLine APIs
Vulkan VK_EXT_line_rasterization extension specification
