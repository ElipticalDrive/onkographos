Add a generic (private) NonUniformBSpline class, which is then used to define Quadratic, Cubic and Quintic splines.
In addition, added Hermite splines for Cubic and Quintic.
Note: To achieve this, the .hpp and .cpp file are both placed in the src folder.
Under the hood for each interpolator, if the grid spacing is uniform, we interpolate using the Cardinal variants which are O(1) lookup. Otherwise, we use the non-uniform variants for each case.
The Hermite splines cannot be instantiated via the generic GenerateInterpolator helper as they require derivative information.

feat: add cubic and quintic Hermite interpolators
…
56c5e60
```
Add the four Boost.Math Hermite interpolators, in both the regular
(arbitrarily spaced) and cardinal (uniformly spaced) variants:

- CubicHermite            (x, y, dydx)
- CardinalCubicHermite    (x, y, dydx) / (y, dydx, x0, h)
- QuinticHermite          (x, y, dydx, d2ydx2)
- CardinalQuinticHermite  (x, y, dydx, d2ydx2) / (y, dydx, d2ydx2, x0, h)

All four implement the Interpolator interface. The quintic pair also
expose computeSecondDerivative, since they carry second derivative data.

Interpolator::Type gains four values, appended rather than inserted
alphabetically so that the existing values keep their integer identity.
GenerateInterpolator cannot build these from x and y alone, so it throws
a RuntimeError saying as much.

Unlike the existing interpolators, the Hermite ones do not extrapolate:
out-of-domain queries throw, as documented on each evaluation method.

CardinalQuinticHermite works around an upstream bug: Boost's
cardinal_quintic_hermite::double_prime omits the 1 / h^2 factor on its
first derivative terms and is therefore only correct for a unit spacing
(e.g. it returns 579 instead of 102 for a quartic sampled at h = 2). The
interpolant is built over the normalized abscissa s = (x - x0) / h and
the results are scaled back, which is exact for any spacing. The bug is
unfixed from Boost 1.82 through 1.92 and on develop, and appears to be
unreported; CardinalQuinticHermite.NonUnitSpacing guards the workaround.
```

```
Add the two remaining Boost.Math cardinal B-spline interpolators,
alongside the existing CubicSpline:

- CardinalQuadraticSpline  (x, y) / (y, x0, h)  -- C1, >= 3 points
- CardinalQuinticSpline    (x, y) / (y, x0, h)  -- C4, >= 8 points

Both fit a B-spline through the given data over a uniform grid, and
estimate the endpoint derivatives from the data. CardinalQuinticSpline
also exposes computeSecondDerivative.

Unlike the Hermite interpolators these need only x and y, so they are
wired into GenerateInterpolator and are constructible through the
factory.

Verified against analytic derivatives at spacings of 0.5, 1 and 2: the
quadratic spline reproduces quadratics exactly, and the quintic spline
reproduces polynomials up to degree 5 to roundoff, including through the
endpoint derivative estimation. Neither exhibits the spacing-dependent
second derivative defect found in cardinal_quintic_hermite.
```
