Summary
Adds a true 3-D voxel geometry so the scattering path transports through a patient-like Nx×Ny×Nz grid at arbitrary incidence — the remaining Stage-3 Voxelized geometries capability (beyond the slab/layered phantoms the V3 gates used), and a Stage-4 prerequisite (decision 0020).
Approach
VoxelGrid3D — lab-axis-aligned, per-voxel mass density, single material (density-only first cut); flat index (i·Ny+j)·Nz+k; a from_voxel_slab reduction constructor and a uniform factory.
Amanatides-Woo voxel DDA, per-step recompute, phrased as a strict generalization of the beam-frame 1-D limiter: the material coordinate u = n̂·p and its step limit become three lab-axis coordinates u_k = p0[k] + mᵏ·q (mᵏ = rows of the beam-frame R) with a per-axis distance to the next voxel face; the step is clipped to the nearest face. Axis-parallel rays → infinite face distance; on-face ties → direction-aware s_tie = 1e-4 mm nudge. Geometry state is recomputed each step, so no float state drifts between backends. The grid is not rotated (an oblique beam already exercises full 3-D traversal).
Parallel drivers (_run_scattering_reference_grid3d, csda_scattering_grid3d_kernel + ScatteringGrid3DKernel), dispatched on geometry type — the 1-D VoxelSlab path is untouched and stays bit-exact.
Files
src/ionmc/transport/geometry.py (VoxelGrid3D), src/ionmc/transport/engine.py (constructor branch + grid reference driver + dispatch), src/ionmc/backend/warp_transport.py (grid kernel + launcher), src/ionmc/transport/__init__.py
decisions/0020-voxelized-3d-grid-dda.md, validation/v3_voxel_grid_3d.py, tests/ionmc/test_voxel_grid_3d.py
docs: physics, validation, roadmap (DEV-014 → completed at f9e3c90, V3 closed; DEV-015 added)

Note on the cross-backend tolerance: the reference(float64)-vs-Warp(float32) depth-dose cumulative is ~1e-3 (looser than the 1-D path's ~1e-4) because the DDA clips at every voxel face (~160 z-crossings + lateral crossings per history), so float32-vs-float64 near-corner face-decision flips decorrelate proportionally more histories. This is a genuine, understood property of the accelerated DDA, not a bug: the same-precision CUDA-vs-CPU depth dose is tight (6.1e-5), a deterministic (scattering-off) grid run stays tight (~3e-6), and σ_x (the physics metric) agrees. Documented in decision 0020.
