Owner and source contract
Translate aggregate.cu::sortAndUpdateAggregateProjections into a native GPU stage for Vulkan and D3D12. Each logical 32-lane source warp builds an aggregate's X-projection keys and local start/end handles, performs eight stable four-bit radix passes, and writes the original per-member SAP index pairs and start masks. The original PxgAabbSourceMembersNative manages two independently allocated GPU history slots, stable reserved member indices and the source heap. Each slot grows independently, preserving previous-frame data when aggregate member capacity increases.
Runtime cost and scheduling
One four-logical-warp GPU dispatch per aggregate slot batch, appended after member-history invalidation on the original post-SAP source stream. All projection, handle, index, mask and member-history buffers are persistent in their own current/previous allocations and grow independently with reserved source aggregate membership. Successful fetch alone rotates current/previous slots. The single native workgroup uses explicit group barriers rather than assuming 32-lane hardware subgroups, with no CPU sorting, host pair enumeration, extra queue or synchronization fence. The stable radix lowering uses per-lane digit rank comparisons within each logical warp, leaving hardware optimization for measured performance passes.
Integration evidence
A Vulkan/D3D12 GPU fixture checks multiple aggregate slots and inactive slots, more than one logical warp of member endpoints, equal-key stable radix ordering, original start/end handles and index mappings, start masks, empty and invalid dispatch arguments, shared-root alias canaries and two frames of independent historical slots. The AABB-owner regression additionally grows aggregate member capacity between frames and checks that the previous GPU slot remains unchanged. The source AABB owner integration additionally creates original aggregate membership and GPU heap buffers, executes union bounds, bitmap promotion, integer-history invalidation and projection sorting in a single source stream batch, and verifies original descriptor/member output through fetch. Backend CI validation is pending.
Redundancy and retirement
Original PxgAggregate::updateBoundIndices, source AABB aggregate records and PhysX heap-backed GPU buffers own membership and storage. The new GPU views are pointer lowerings of the original double-buffered arrays, not a replacement aggregate registry, standalone broadphase, scene scheduler or CPU contact solver. Retired aggregate slots are excluded; source GPU retirement remains at the existing fetch boundary.
Source fidelity and deviations
Fidelity classification: semantics-preserving-lowering
PhysX source: aggregate.cu::sortAndUpdateAggregateProjections; RadixSort.cuh::radixSortSingleWarp; PxgAggregate::boundIndices/sortedProjections/sortedHandles/sapBox1D/startMasks.
Departures: Source warp synchronization is lowered to device-independent group barriers; per-aggregate pointer arrays become stable GPU source-heap slices. Mask slices reserve one word per maximum member. Current/previous slot selection swaps independently allocated PhysX heap-backed GPU buffers at successful report fetch; growth preserves each slot's history without relocating its logical offset.
Parity evidence: GPU-side stable radix output and SAP history arrays are checked against independently sorted original member endpoints across multiple frames and source-owned GPU aggregate admissions. Aggregate self-collision, persistent aggregate-pair transitions and Sc member-pair reports remain subsequent N2 gates.
