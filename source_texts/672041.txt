Abstract
In this paper we present a new approachto volume rendering in
which curves of constantintensity in image space,or iso-contours,
are computed directly for each view. The generatediso-contours
can be used to drive various visualization and feature-detection
algorithms. The approachimposesno restriction on the organization
of the data points and can accommodatea large class of radiallysymmetric filter functions. The technique works well for both
perspectiveandorthographicviewing projections. Eachiso-contour
is delined by an ordinary differential equation, which is solved
numerically using a predictor-corrector method. A key element
of the algorithm is the use of image intensity gradients, which
we compute by means of a closed-form expression that holds at
every point on the image plane. A caching algorithm is described
that dramatically acceleratesthe gradient computations on large
datasets.The algorithm is demonstratedon emission-only datasets.
We conclude by describing a number of possibleenhancements.
1 Introduction
Current paradigmsfor direct volume rendering are oriented toward
fixed-resolution images. In this paper,we introduce a new approach
to volume rendering based on the direct computation of imagespacecurves of constant intensity, or iso-contours. Our approach
is motivated by the observation that it is not always necessary
to processan entire datasetor sample the entire image plane at
a high level of detail to identify salient features of the resulting
image. The iso-contour method of volume rendering can be used
to efficiently extract one class of image-spacefeatures: curves of
constantintensity.
The principal application of directly-computed iso-contours is
the rapid computation of high-level imagefeatures.Other potential
applications include the steeringof computationto regionsof interest, generation of families of contours for resolution-independent
rendering, and progressiverefinementof volume-renderedimages.

Iso-Surfaces vs. Iso-Contours
The iso-contour approachdiffers fundamentally from iso-surface
extraction. Iso-surfacetechniquesconvert volume datainto surface
data,basedon analysesof the volume data in local neighborhoods.
Thesetechniquesoften operatein a totally view-independent manner [l I]. During rendering, it is the extracted surface rather than
the original volume data that is illuminated and projectedonto the
image plane. In contrast,the iso-contour method operatesdirectly
in continuous imagespace,driven by featuresof the final 2D image
rather than thoseof a 3D surface. The contours thus dependon the
viewing projection of the volume data as well as the line integrals
usedto mapthe 3D datato image intensities.
A similar object spaceversus screenspacedistinction can be
madebetweenour approachand that of Helman and Hesselink [7].
Their approachgeneratescontour lines and other indicators of vector field topology in object space, which are later projected. In
contrast,our contoursexist in screenspaceand are useful in understandingthe intensity variation of the dataafter a volume projection
model has beenapplied.

Locating Important Curves
Thus far our discussion has not addressedthe problem of finding
starting points for generatinguseful iso-contours. One approachis
to generatecontours starting from interactively specified points in
the image plane. In this way, useful contours can be discoveredby
trial and error; each new contour revealing more about the image
and guiding subsequentrials. To further assistthe user, we have
implementedseveralsemi-automatictools aspart of our interactive
iso-contour exploration environment.
The first tool is an image extremum locator. Extrema provide
a quick impressionof image topology, since the final contours will
encircle these points. Using an extremum locator, we can detect
the border betweendataand background,as well as data hot-spots.
Extremal values are stored as single-point contours in our data
structuresfor use in subsequentrendering. Our current algorithm
employs the gradient as part of a descentmethod to locate local
extrema. Efficiency and accuracycan be enhancedby using other
numeric techniques such as more sophisticated line searches[l].
Ultimately, second derivatives should be used to acceleratethe
convergenceof the searchalgorithm, as simple descentmethods
convergeslowly at extremaand perform poorly in flat regions.
The magnitudeof the image intensity gradient is often used as
an “edge strength” operator in image processingapplications. In
volume rendering, a three-dimensionalanalog to this idea has been
used to find surfacesin object-space[5, 91. We make use of this
by generatingmore contoursin regions where the gradient is large,
since theseare likely to be important feature boundariesin image
space.We have implementeda tool that allows the user to examine
the gradient magnitudealong lines in screen-space.By choosing a
peak gradient value, a contour through the corresponding screenspacepoint is traced.

the two nested contours with maximal value difference and creates a new contour with intensity midway between them. The

As we saw in Section 2, the intensity and the intensity gradient
at each point in screen space can be affected by any or all of the data
samples; this is evident in the summations in equations (4) and (5),
which are taken over all data points. For filters with finite support,
however, the summations need only be taken over data points whose
spheres of influence are intersected by the given ray. If this subset
of points were known a priori for each ray, the savings could be
considerable. For uniformly-distributed data points, the averagecase complexity of computing $ and 04 would drop from O(n) to
0( fi). A practical means of approaching this is to associate with
each ray a substantially reduced subset of data points, or candi&zte
set, which is guaranteed to contain all relevant data.
There are two classes of algorithms for quickly generating candidate sets: those that operate in screen-space, and those that operate
in object-space. Screen-space algorithms generate candidate sets
that are valid for a given view. During image or iso-curve generation, a candidate set is retrieved from the screen-space regi.on
pierced by a given ray. All candidate sets are invalidated whenever
the view changes.
In contrast, object-space approaches classify the data points into
3D regions, which remain valid for all views. For a given ray, the
candidate set of data points can be constructed using any ray tracing
acceleration scheme for locating the regions pierced by the ray [4];
for instance, the data may be organized into an octree, kd-tree, or
a uniform lattice. While the object-space organization need only
be computed once, the candidate set must be created anew for ea.ch
ray by tracing it through the volume. Consequently, object-space
methods do not fully exploit image-space coherence.
We have employed screen-space algorithms because they very
naturally exploit the coherence in the data access pattern that results
from following a curve. Aside from the seed point, each evaluation
of 4 and 04 occurs at a point very near the previous point. Topdown subdivision of the screen into regions can be done using a
Warnock-style divide-and-conquer approach [ 161. If used to lazily
create candidate sets, this approach is essentially a 2D version of
the ray-classification algorithm [3].
One disadvantage of the screen-space approach is that each
data point typically belongs to multiple candidate sets. For small
datasets, this replication poses no problem. For large datasets,
however, it is often impractical to store all the candidate sets at once.

Given any set of iso-contours the underlying image can be rendered
in several ways, then updated progressively as more contours are
added. Because the contours are not associated with any particular
rasterization of the image plane, the rendering may be performed at
any resolution.
The simplest method of rendering iso-contours is to sort them
by inclusion and draw them in back-to-front order, filled according
to the corresponding intensity level. An example of this technique
is shown in Figure 7. While this method is very simple, the value
discontinuities can be visually distracting. Smoother renderings
may be produced by first meshing the iso-contour grid into triangles,
then rendering the triangles by interpolating the vertex values. We
use Delaunay triangulation [6] to create the triangle mesh from the
set of points defining the contours. The segments along the contours
are constrained to be edges of triangles, which guarantees that no
triangle will cross an iso-contour. This constraint method was used
earlier by Lischinski et al. [lo] in connection with discontinuity
meshing for radiosity. An example of a mesh generated in this way
is given in Figure 8. Images of the “urchin” and pelvis datasets
made by linearly interpolating the triangular meshes are shown in
Figures 9 and 10. Note that Figures 7 and 9 were computed using
the same set of iso-contour data. Comparing the two images, the
benefits of interpolation become apparent.
The image generation methods presented in this section are
useful for generating images based on a sparse sampling of the
data. Yet, unless the contours are spaced at intervals approximating the gray levels of the display device, the detail falls short of
that attainable via traditional volume rendering techniques based
on pixel-by-pixel reconstruction. We anticipate that this disparity
can be lessened by more intelligent placement of the iso-curves
coupled with better interpolation of the resulting triangular mesh.
Currently, the gradient information this is available at the vertices of
the triangles is ignored; this information could be used to advantage
with higher-order interpolation methods.

tested against the cache; if it is within the 9 cells, only the cached

To be effective, it is essential that the cache lists be computed
quickly. The process can be streamlined by associating a bit vector
with each data sample as a view-dependent preprocess. This bit
vector indicates which screen-space cells are affected by the data
sample. The cache lists can then be quickly computed as needed
using both the bit vectors and the cache mask. The process still
requires an O(n) search, but a distance comparison is completely
avoided except for the relatively small number of points whose
masks indicate a potential hit.

Conclusions
and Future Work
We have presented a method for computing screen-space curves of
constant intensity, or iso-curves, for emission-only projections of
volume data. The method operates by computing intensity gradients
at discrete points in the image plane. The gradients are computed
analytically for quadratic radially symmetric filter kernels, with
arbitrary radii, and applied to data with any spatial organization.
The curves are solved using a predictor-corrector method that can
maintain any given tolerance along arbitrarily long iso-contours.
The computed contours can be used to locate specific features of
the image, or to create resolution-independent renderings.
The most severe limitation of the current implementation is
its restriction to emission-only rendering, which can be likened to
X-ray imaging. While absorption rendering is a minor extension,
requiring the application of an exponential function to the final intensities, combining both emission and absorption within a single
model is significantly more difficult. Use of both emission and
absorption implies that the data points cannot be processed independently: both ordering and overlap of neighboring filter kernels
must be accounted for. These complications make the analytic
computation of the intensity gradient a significant challenge.
More general filter kernels are another avenue to pursue. While
it may be impractical to compute intensity gradients for some recon-

There are many efficiency schemes that have yet to be investigated. The curve-following algorithm would benefit greatly from a
higher-order predictor and corrector. A multi-step predictor, such
as Milne’s method [ 1, 21 could greatly reduce the number of corrector steps needed. A look-ahead cache could reduce the number
of cache updates by using the current direction and curvature of
the contour. A hierarchical cache structure could further reduce
the number of O(n) cache updates by using a nested sequence of
cache regions. Finally, inexact- and quasi-Newton methods could
be employed in the corrector step to reduce the number and cost of
the gradient computations, especially while the predicted point is
relatively far from the curve.
Our current algorithms start with a seed point and find either
individual iso-contours or local intensity extrema. Ideally, the algorithm would automatically produce global information, such as
a list of all level curves for a given value or a list of all image
extrema. With appropriately chosen contour intensities, this would
result in truly resolution-independent images. One way to obtaining this information is by means of interval arithmetic [8, 141. As
demonstrated by Snyder [ 141, interval arithmetic can also be used
to produce a more robust curve follower, eliminating the need for
the user-supplied step-size parameter that we currently employ.
