Context
Verified: the back buffer is R8G8B8A8_UNORM — SDR only. ACES RRT+ODT filmic tone mapping already runs per-pixel in standard.hlsl (lines ~317-321), mapping HDR lighting to [0,1] before gamma, so the shading pipeline is internally HDR; it just clips at an 8-bit output. On an HDR display, a horror game gains exactly what the genre needs: truly dark blacks that stay detailed and a flashlight/emissive highlight range that SDR crushes. The swapchain infrastructure is modern (flip-model, ALLOW_TEARING, IDXGIFactory5 in DX12Swapchain.h), making format/colorspace extension straightforward.
Goal
Add an HDR output mode: FP16 (scRGB) or 10-bit (HDR10/PQ) swapchain with the correct DXGI color space, HDR metadata, tone-map adjustments (ACES output targeting display nits instead of [0,1]), and a brightness/paper-white calibration screen — with automatic fallback to the current SDR path on non-HDR displays.
Acceptance Criteria
Swapchain supports R16G16B16A16_FLOAT (scRGB) and/or R10G10B10A2_UNORM + SetColorSpace1 (HDR10)
HDR capability detection per monitor (IDXGIOutput6) with clean SDR fallback; handles monitor moves
Tone mapper switches: SDR = current ACES-to-[0,1]; HDR = scaled output with user paper-white/max-nits
VUI overlay (D3D11On12/D2D) renders correctly on the HDR back buffer (UI stays at paper-white)
Calibration screen in the template Options menu (classic min/max luminance test patterns)
Settings API: Settings.SetHdr(bool) persisted; F12 back-buffer capture still produces a usable SDR-encoded BMP
Verified no regression with DLSS SR/FG paths (Streamline buffer formats)
Technical Notes
Watch the documented render-scale trap: BGRA-format/viewport hardcodes in the scaled-RT → upscale → UI chain
Key files: Engine/Graphics/DX12/DX12Swapchain.h, DX12UpscalePipeline.h, Engine/Shaders/standard.hlsl, upscale.hlsl
Dependencies
rendering: post-processing framework (pass chain between scene and UI)
