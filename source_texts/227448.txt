What
New effect effects/surfnets: the demo's first dynamically-generated indexed 3D mesh. It polygonises an implicit surface in real time with Naive Surface Nets (a port of Mikola Lysenko's algorithm, MIT).
The 32³ scalar field is resampled every frame on the VFPU from two moving, rotating toruses. Each torus contributes a finite-support metaball potential P_i = max(0, R - d_i)² of its sdTorus; the field is kIso - (P_A + P_B), so as the toruses approach, their fields sum and the surfaces bulge together and fuse into one skin — while each torus stays solid when apart.
How
Field: fused VFPU sdTorus kernel (no libm), sampled into a 32³ grid. Sample points are rotated into each torus's local frame (gumFastInverse → vfpu_transform3).
Mesh: faithful Surface Nets port (edge tables, 2-slice rolling index buffer, mask&1 winding). A packed sign-bit prescan skips the 8-corner gather + edge walk on non-boundary cells. Per-vertex normals from the field-grid gradient (central differences on samples already taken — near free) drive one GE directional light + ambient. T8 leopard-skin textured (GU_NEAREST + CLUT).
UV seam: spherical UVs wrap at the atan2 longitude seam; the GE interpolates that the long way on straddling triangles. Fixed with raycast's fround/GU_REPEAT trick — which needs unshared vertices, so the indexed mesh is un-shared into a flat triangle list (ExpandSeam) before drawing.
Animation: camera orbit + torus transforms are time-driven (frameTime) but isolated in SceneState/ComputeScene, so a Blender-authored params path drops in later.
Notes / follow-ups
Standalone only — not yet wired into demo/demo.json.
Perf (PPSSPP, 32³): down from the initial ~26 ms/frame to ~13.6 ms/frame median (81% of the 16.67 ms budget — hits 60 fps), via two follow-up passes: fusing the VFPU field kernel with the sign-bit mesh prescan, then replacing BuildMesh's two per-cell div.s with VFPU vrcp.s (docs/4-cpu-and-vfpu.md §6: never DIV in a hot loop). field is now the dominant cost (~50%) vs. mesh (~30%); GE draw is ~0.3%. A further lever, if ever needed: vfpu_atan2's internal div.s (shared with raycast/polar_light) still runs twice per emitted vertex inside BuildMesh.
Spherical UVs still pole-pinch at the y-axis (inherent; triplanar would remove it).
The upstream MarchingTetrahedra/ reference dump is intentionally not committed.
Test
make (CI gate) and make -C effects/surfnets both green.
Ran in PPSSPP; mesh ~1150–1550 verts / ~2300–3100 tris, no clamping/overflow. Seam gone after the ExpandSeam fix.
Re-profiled after each perf pass with make TIMEOUT=... -C effects/surfnets run + tracec analyze to confirm the measured gains above.
