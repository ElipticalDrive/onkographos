Codex round 2 raised two new findings; a local review of the just-merged #838
raised a third. All three are cases where a debug control exists in state but
never reaches the screen, and all three are permanent (not merely deferred).

Thread B -- the 1 -> 0 node transition. When the LAST GaussianSplatNode3D leaves
while a GaussianSplatWorld3D submission keeps the shared renderer alive,
_on_renderer_peer_set_changed() ran with p_include_self=false and an empty peer
set: it dropped the per-renderer memo and nothing else. A memo is only consulted
by the next push, and with zero nodes left there is no next push, so the departed
node's tile-grid / heatmap / HUD request stayed rendered on the world submission
indefinitely. This is distinct from the round-2 3 -> 2 fix, which still had a
peer to delegate the recompute to. Fixed with
GaussianSplatNodeDebugHelper::reconcile_debug_overlay_union_for_renderer(): a
renderer-addressed push seeded from nothing rather than from a node, so the empty
node set yields the all-false union that is the correct answer. Memoized, so when
peers do remain and have already pushed the identical union it costs one compare.

Thread C -- a renderer-side HUD write never reaches the node.
GaussianSplatRenderer::set_debug_show_device_boundaries() /
set_debug_show_texture_states() (and their perf/residency siblings) are bound to
script, so node.get_renderer().set_debug_show_device_boundaries(true) is a
supported way to turn a HUD section on. The write landed in the renderer's
DebugState and stopped there: those setters have no node callback, and the node
is what creates the GaussianSplatDebugHUDLayer. Under UPDATE_MODE_MANUAL the
node's per-frame apply never runs either, so the HUD lines existed in renderer
stats with nothing on screen, forever. Fixed with
GaussianSplatSceneDirector::notify_renderer_debug_hud_sources_changed(), a
callback the node layer installs at module init -- renderer/ deliberately does
not include nodes/, and the director is the only layer that already maps a
renderer to its nodes. It fires when GaussianSplatRenderer::is_debug_hud_source_active()
flips; that predicate is new and is now the SINGLE definition of "this renderer
wants a HUD", read both by the four setters and by
GaussianSplatNode3D::_update_debug_hud_visibility(), which used to restate the
same four-way OR inline.

Inspector debug suppression -- fail-safe instead of name-based. #838 replaced a
drifted hand-written list with `begins_with("debug/")`, which ate
debug/overlay_opacity (no replacement control exists for it), then patched that
by special-casing the one name. The instance was fixed; the shape was not. The
predicate still asserted "suppressed" from the property's NAME with no connection
to whether a replacement control exists, so a 13th debug/* property would have
silently lost its inspector UI -- and #838's test would still have passed,
because it encoded the same name predicate. parse_property() now suppresses only
what parse_begin() actually built a control for: every control in the Debug
Visualization block is created through _add_debug_toggle() /
_add_debug_option_button(), which take the replaced property as a required
argument and record it. The default is therefore VISIBLE. debug/overlay_opacity
is no longer a special case; it simply has no entry, for the same reason any
future property without a control has none. This is much simpler here than it was
on #838 because this branch already removed the shared-renderer conditional
omission, so the built-control set is unconditional.

mutation-proven RED against the unfixed tree and GREEN with the fix:

* gaussian_splatting: make debug overlays work on a shared renderer instead of silently forcing them off (#831, #832)

Four of the six user-reachable debug overlays -- tile grid, density heatmap,
performance HUD, residency HUD -- were forced false whenever the renderer was
shared, which is every scene with more than one splat node. The checkbox stayed
ticked, the project setting stayed true, the node property read back true, and
the renderer reported false, with no warning anywhere. Measured on a frozen
baseline (Engine.time_scale = 0) at 8 nodes / 1 shared renderer: 0.00 % pixels
changed for all four.

WHY THE SUPPRESSION EXISTED
85c7e1a ("scope node debug overlays to sole renderer owners") added it because
the push was last-writer-wins across peers: N nodes each believed they owned one
renderer-wide debug state. #667 later found the follow-on bug -- a legally
written flag survived a peer joining while _validate_property hid the property
on BOTH nodes, so the user could not turn it off -- and fixed convergence, but
kept the forced-false writes.

WHY UNION INSTEAD
These four are whole-frame diagnostics owned by the renderer, not per-node
appearance. Their node-local default is READ FROM and WRITTEN BACK TO a single
project setting (rendering/gaussian_splatting/debug/show_*), so they were never
per-node values; there is nothing to arbitrate. The push is now the union over
every node bound to the renderer, which is order-independent and idempotent, so
any peer may compute it and the settings-owner lease is not needed for them.
Painterly stays gated -- it IS per-node appearance -- and _validate_property
still hides painterly/* and the renderer-wide quality knobs.

The HUD control is the one genuine per-node conflict: with the flag unioned,
all N nodes would spawn a control and stack N identical overlays in the same
corner. _update_debug_hud_visibility now also requires the settings-owner lease,
which is already unique per renderer, so exactly one node draws it. Measured:
the perf HUD costs the same 19.20 % at 1 node and at 8.

ROOT CAUSE OF THE BOUND-SETTER NO-OPS (#831, second half)
Isolated, not inferred: reading the flag back in the same frame and again one
frame later shows same_frame=true, f+1=false. apply_renderer_debug_settings()
re-asserted the node's four flags from update_splats() on EVERY frame, so any
GaussianSplatRenderer::set_debug_show_*() call was reverted one frame after it
was made. show_tile_bounds was unaffected precisely because the node does not
re-assert it. The push is now edge-triggered against the last union pushed to
that renderer, so an unchanged node leaves a renderer-side write alone. The memo
is keyed by renderer ObjectID, NOT per node: a per-node memo goes stale the
moment a peer -- or this node re-entering the tree after a detach -- writes a
different union, and would then suppress a push that is genuinely needed (both
failure modes were caught by the GPU harness before this landed).

- show_projection_issues reached the UBO but tile_rasterizer_compute.glsl read
  only debug_flags.x/.z, never .w, and compute raster is the DEFAULT path. The
  diagnostic color is extracted into gs_projection_debug_color() in
  tile_raster_common.glsl and used by both raster paths so they cannot drift
  apart again. 0.00 % -> 100.00 %.
- show_device_boundaries / show_texture_states emitted their HUD sections from
  INSIDE the show_performance_hud block, and were wired to the overlay (not HUD)
  invalidation variant so toggling them never set hud_dirty. Both fixed; they
  also count as HUD sources for the control's visibility, otherwise un-nesting
  them would still render nothing.

* gaussian_splatting: drive the debug-overlay union from the peer-set change, not from the shared-ness boolean (#831, #832 round 2)

Codex filed two findings against c5b5db4. Both are REAL, and both are worse
than the caveat the PR body flagged: that caveat said such cases "self-heal
within one frame". Under UPDATE_MODE_MANUAL they never self-heal, because
update_splats() -- and therefore the whole per-frame apply -> push route -- is
gated off (process_gaussian_render's UPDATE_MODE_MANUAL arm sets should_update
= false, and set_update_mode does set_process(false) on the no-manager path).
The PR body has been corrected.

FINDING 1 -- the HUD owner was never told a peer changed a HUD flag
The four overlay flags are unioned across the renderer's peers, but the HUD
CONTROL is deliberately drawn by exactly one node -- the settings-owner lease
holder -- so that N peers do not stack N identical overlays in the same corner.
A NON-owner peer that enabled show_performance_hud / show_residency_hud
therefore did all of: set the renderer-wide flag, call
_update_debug_hud_visibility on ITSELF, and get refused by the very ownership
check that keeps the control unique. The lease holder was never notified. Flag
enabled, nothing on screen.

Fix: push_debug_overlay_union() now fans HUD reconciliation out to every node
bound to the renderer -- and only when the union actually CHANGED, so the
memoized per-frame path stays free and the #831 edge trigger is untouched. The
holder among the peers creates the control; the rest are a no-op.

* gaussian_splatting: project the debug HUD into viewports that render the shared world but hold no splat node (#831, #832 round 9, #847)

Round 6 elects one debug-HUD owner per VIEWPORT rather than per renderer, so
every viewport on a shared World3D can show the HUD. But the candidate set it
elects from is `director->collect_instance_node_ids_for_renderer()` -- the
renderer's SPLAT NODES -- and a node is only ever considered for the viewport it
itself lives in. A SubViewport that inherits its parent's World3D
(Viewport::find_world_3d() walks to the parent) and holds only a Camera3D
therefore RENDERS the splats -- their render instances live in the world's
scenario, so any camera on that world sees them -- while electing ObjectID() for
its own HUD. That is the ordinary secondary-camera / minimap case, and it had no
HUD and no way to ask for one.

Fix: keep the round-6 election exactly as it is and fill only the gap it leaves.
A viewport that HAS an eligible splat node keeps its own elected owner and is
never projected into; a viewport with none gets a HUD from a single
renderer-wide PROJECTOR, elected by the same function with the viewport
constraint dropped. Native and projected HUDs are therefore mutually exclusive
per viewport BY CONSTRUCTION -- a non-empty election is the skip condition -- so
"exactly one HUD per viewport" is preserved rather than re-derived.

The HUD is projected, not re-homed: CanvasLayer::set_custom_viewport() lets a
layer parented under the projector attach itself to another viewport's canvas.
Ownership stays where rounds 2-8 put it (a GaussianSplatNode3D owns, updates and
destroys the control) and no node is added to anybody else's subtree. The
alternative shape -- HUD ownership on the renderer or the viewport -- was
rejected: GaussianSplatRenderer is a RefCounted with no place in the scene tree,
so it would still need a node-side agent to host the CanvasLayer, and it would
have to re-derive the per-viewport uniqueness round 6 already establishes. A
strictly larger diff for the same result.

"Renders the world" is required to mean "has an active Camera3D", not merely
"resolves that World3D": every default-configured SubViewport inherits the
parent's World3D, including the ones used purely to render 2D/UI into a texture,
and those draw no splats at all. The tree walk is gated on
GaussianSplatRenderer::is_debug_hud_source_active(), the same short-circuit
_update_debug_hud_visibility() already uses before can_own_debug_hud().

Lifetime: a projected CanvasLayer holds a raw Viewport* (CanvasLayer::vp) that it
dereferences on its own NOTIFICATION_EXIT_TREE, so the layer must go down while
its target viewport is still alive. Node::tree_exiting fires before the
viewport's own EXIT_TREE (scene/main/node.cpp _propagate_exit_tree), which is the
last moment that holds; the projector connects there one-shot. Leaving the tree
tears every projected HUD down, and the collection requires
is_inside_tree() && is_inside_world(), so a node on its way out can only ever
remove projected HUDs, never create one.

* gaussian_splatting: park projected debug-HUD layers under a host node so teardown never unparents from a blocked node (#831, #832 round 10, #847, #848)

Round 9 tears a projected HUD down from its target viewport's `tree_exiting` and
parented the CanvasLayer to the projector node. Both halves are individually
correct and together they are a use-after-free.

Node::_propagate_exit_tree() (scene/main/node.cpp) raises data.blocked on a node
BEFORE recursing into its children and lowers it only after that loop, so at the
instant a node emits `tree_exiting` every STRICT ANCESTOR of it is blocked.
Node::remove_child() ERR_FAIL_CONDs on data.blocked > 0 -- and so does the
remove_child() that NOTIFICATION_PREDELETE performs on memdelete()'s behalf. When
the target SubViewport is a DESCENDANT of the projector (a minimap or secondary
camera parented under the splat node is the ordinary case), the unparent AND the
free are both refused while the layer is freed anyway, leaving a pointer to freed
memory in the projector's data.children -- which the rest of the teardown then
traverses (_propagate_exit_tree walks that same map) or memdeletes a second time
(PREDELETE's kill-children loop).

The same shape is reachable without any nesting: _destroy_projected_debug_hud()
and _destroy_debug_hud_control() also run from a peer's exit-time reconcile
fan-out (_notify_debug_hud_dirty_for_renderer,
GaussianSplatNodeDebugHelper::reconcile_debug_overlay_union_for_renderer), where
this node can be a strict ancestor of the peer that is leaving. That second path
predates round 9 on the native HUD control.

Fix, safe by construction rather than by ordering: the projected layers hang off
a dedicated child node, `GaussianSplatProjectedDebugHUDs`, whose only children
are CanvasLayers this node creates. No Viewport and no peer node can ever be a
descendant of it, so it is never a strict ancestor of anything whose
`tree_exiting` reaches the teardown, so it is never blocked when that teardown
runs, so remove_child() on it always succeeds. The one operation that still
touches `this` -- adding and removing the host -- is confined to a creation path
that checks whether add_child() was refused (and then records nothing, so the
next reconcile retries) and to NOTIFICATION_EXIT_TREE, where
_propagate_exit_tree() has already lowered this node's own data.blocked.

Rejected alternatives: deferring the free (queue_free) still needs the layer
severed from the dying viewport first -- CanvasLayer dereferences its raw
Viewport* on its own EXIT_TREE -- and rebinding it to this node's viewport in the
meantime attaches a second HUD canvas to a viewport that already has one, which
is a transient violation of the round-6 invariant. Re-homing the layer into the
target viewport's own subtree injects a node into somebody else's scene.

Ownership is unchanged: a GaussianSplatNode3D still owns, updates and destroys
every HUD control, and the projected layer still lives in the projector's own
subtree -- one level deeper.

Additionally, _detach_and_free_debug_hud_node() is now the single free path for
every debug-HUD node (native layer and control included). It refuses to memdelete
a node whose parent declined to unparent it and reports loudly instead, so a
future mistake in the structure above degrades to a leak rather than to a silent
use-after-free.

Finding 2 (reconcile reach) is deliberately NOT fixed here and is filed as #848,
with the limitation stated at collect_debug_hud_projection_viewports(). The
obvious trigger, SceneTree::tree_changed, is emitted from inside
_propagate_enter_tree()/_propagate_exit_tree() -- precisely the data.blocked
windows this commit had to make the teardown safe against -- so it needs a
deferred, coalesced reconcile point, which is a design change to the trigger and
not a patch.

Mutation-proven by
"[GaussianSplatting][Node][SceneTree][RequiresGPU] A projected debug HUD
unparents safely when its target SubViewport is nested under the projector".
It asserts the safety property, not the implementation: (1) the parent that
remove_child() will be called on is not an ancestor of the target viewport --
that being exactly the condition under which it is blocked -- and (2) taking the
nested viewport out of the tree emits no engine error, observed through a scoped
ErrorHandlerList, because a refused remove_child() is an ERR_FAIL_COND_MSG and
its emission can be read without touching the freed memory it leaves behind.
Restoring round 9's `add_child(projected.layer)` fails exactly those two
assertions (2 captured errors) while the other 8 of 10 still pass -- including
the round-6 per-viewport counts and the round-9 "the nested viewport HAS a
projected HUD" premise, so the RED run demonstrably reaches the branch -- and the
unmutated RED run additionally segfaults during teardown, which is the corruption
itself. 10/10 pass with the fix. All resolve/repair calls (get_renderer(), which
runs _ensure_renderer()) are ordered BEFORE the HUD is enabled (round-8 vacuity
trap), and HUD counts are taken from the viewport's side (CanvasLayer::get_viewport()
RID).

* gaussian_splatting: keep the debug-HUD pointer when the unparent is refused so blocked teardowns stop accumulating layers (#831, #832 round 11)

Round 10 made _detach_and_free_debug_hud_node() return false instead of
memdelete()ing a node whose parent refused to unparent it, which turns a
use-after-free into a recoverable refusal. But four of its five callers then
nulled their pointer unconditionally, so the refused node was stranded: still
parented, still bound to the viewport's canvas, owned by nobody.

For the node's own HUD that is reachable, not hypothetical.
Node::remove_child() does data.blocked++ around p_child->_set_tree(nullptr), so
a node is blocked for the whole of a departing child's _propagate_exit_tree() --
including the NOTIFICATION_EXIT_TREE in which that child runs
_unregister_shared_renderer() ->
GaussianSplatNodeDebugHelper::reconcile_debug_overlay_union_for_renderer() ->
_update_debug_hud_visibility() on every remaining peer. When the remaining peer
is the departing node's own parent, and the departing node was the only holder
of the HUD request, the parent tears its HUD down while it cannot unparent
anything. The control's parent is the layer (not blocked) so it goes down; the
layer's parent is the node itself, so it does not. Dropping the pointer there
meant the next enable built a SECOND GaussianSplatDebugHUDLayer beside the
abandoned one -- once per blocked teardown, unbounded.

_destroy_projected_debug_hud_host() already kept its pointer on refusal, so this
was an internal inconsistency. All five call sites now share one contract:
`false` means "still parented, still yours".

  - _destroy_debug_hud_control(): keeps control and layer on refusal, and only
    attempts the layer once the control is gone -- the control is parented UNDER
    the layer, so freeing the layer while a retained control is still its child
    would free that control through PREDELETE's kill-children loop and dangle
    the retained pointer.
  - _destroy_projected_debug_hud(): same, and it only erases the map record once
    nothing survived. The record is what makes a retry possible;
    _update_projected_debug_huds() drives both directions off that map, so a
    retained entry comes back through the teardown on the next reconcile
    (unblocked by then), and an entry whose viewport is still wanted is rebuilt
    from scratch rather than re-armed on top of leftovers whose tree_exiting
    connection the refused pass already dropped. Unreachable by construction via
    the round-10 host; changed so a mistake in that construction cannot compound.
  - _destroy_projected_debug_hud_host(): now declines while the map is non-empty,
    because the projected layers are the host's children and freeing it would
    take a retained one with it.

No deferred retry is needed. The retained layer is reused by the next enable
(so the residue never exceeds one node) and freed by the next teardown that runs
outside a blocked window, which the test asserts explicitly.

Also corrects the fail-safe's own ERR_PRINT, which said "leaking it": with every
caller retaining, that is no longer what happens.

Test: "[GaussianSplatting][Node][SceneTree][RequiresGPU] A refused native HUD
teardown reuses its layer instead of accumulating abandoned ones". The peer is
deliberately DATA-LESS -- the director never registers such a node (round 7) and
_elect_debug_hud_owner() enumerates the director's instances, so the peer can
never win the HUD election while still counting in the overlay union, which pins
"the peer requests, the parent draws" without depending on iteration order. It
counts the node's CanvasLayers on the viewport (CanvasLayer::get_viewport() RID)
rather than its HUD controls, because an abandoned layer is EMPTY and
Node::_validate_child_name() renames the duplicate to
"@GaussianSplatDebugHUDLayer@N" -- so both existing observables report healthy
while the leak grows.
