# Compression of Voxelized Vector Field Data by Boxes is Hard

Simon Zhang∗

#### Abstract

Voxelized vector field data consists of a vector field over a high dimensional lattice. The lattice consists of integer coordinates called voxels. The voxelized vector field assigns a vector at each voxel. This data type encompasses images, tensors, and voxel data.

Assume there is a nice energy function on the vector field. We consider the problem of lossy compression of voxelized vector field data in Shannon's rate-distortion framework. This means the data is compressed and then decompressed up to an error bound on the energy distortion at each voxel.

Our first result is that under certain conditions, lossy compression of voxelized vector fields is undecidable to compute. This is caused by having an infinite number of Euclidean vectors. We formulate this problem instead in terms of clustering the finite number of indices of a voxelized vector field by boxes. We call this problem the (k, D)-RectLossyVVFCompression problem.

We show four main results about the (k, D)-RectLossyVVFCompression problem. The first is that it is decidable. The second is that decompression for this problem is polynomial time tractable. This means that the only obstruction to a tractable solution of the (k, D)- RectLossyVVFCompression problem lies in the compression stage. This is shown by the two hardness results about the compression stage. We show that the compression stage is NP-Hard to compute exactly and that it is even APX-Hard to approximate for k, D ≥ 2.

Assuming P ̸= NP, this shows that when k, D ≥ 2 there can be no exact polynomial time algorithm nor can there even be a PTAS approximation algorithm for the

(k, D)-RectLossyVVFCompression problem.

# 1 Introduction

In 1959 Shannon formulated rate-distortion theory S+[59]. In this theory we are given a domain X equipped with a distortion function ρ : X × X → R≥0. The distortion function on a pair (x, y) ∈ X × X , denoted ρ(x, y), determines the cost of replacing an element x ∈ X with the element y ∈ X . In rate-distortion theory the goal is lossy compression of a random variable X to an estimated random variable Xˆ. The random variable Xˆ is called the reconstruction and differs from X up to a bound on its distortion. The reconstruction is still supported on the support X . Shannon formulates this as minimizing the rate R, or bits of information per sample from X needed for the reconstruction Xˆ [Cov99]. A robust formulation for a sequence of random variables is expressed by the following optimization problem. We call this the lossy indexed compression problem (LossyIndexedCompression):

Given an error bound ε > 0 and n non-i.i.d. random variables X1, ..., Xn, find the optimal rate R∗ n satisfying:

#### 1.1 Voxelized Vector Field Data

The image compression problem was our original motivation for the lossy indexed compression problem. We would like to formulate this problem in terms of an arbitrary indexed set of vectors.

We call an enumerable set of fixed-length real valued vectors that can be stored, retrieved and managed a vector database. When this enumeration can be multi-indexed, its storage format is a tensor data type, or multi-indexed array of real numbers. This data type includes traditional images [ahm06], matrices [Str22], as well as voxel data [LH06, ZDL+20] etc.

When the index size scales, the compression problem is known to be hard for tensors. It is known that compressing a sparse matrix is NP-Hard [GJ]. It is also known that compressing a 0-1 rectilinear polygon by rectangles is NP-Hard [GJ]. We would like to investigate the hardness of a closely related compression problem involving multi-indexed vector databases.

In the following, we formulate a data type to represent multi-indexed vector database in the form of a discretized vector field.

Let n ∈ N be the total number of vectors in a vector database X. As a vector database, each vector in X can be enumerated as Xi ∈ R D, i ∈ [n] where D ∈ N is the length of each fixed-length vector. This is called flat-indexing. We call the integer i the primary key in the flat-index for the vector record Xi . The flat index up to set bijections is also called the support of X, denoted supp(X).

Throughout this exposition, we can assume that the numerical inputs r ∈ R to all algorithms are from the rationals. These must have a finite bit string representation.

Let Bit(•) denote the map from a number to a single bit string representation. For a number r, let size(r) denote the number of bits returned by Bit(r). We assume that rational numbers q < 1 have size(q) = Θ(log( 1 q )) and that for all n ∈ N, size(n) = Θ(log(n)). These include delimiters to denote the start and end of the numerical representation.

We will make the following assumptions on X:

Definition 1. A vector database X is a (k, D)-dimensional Voxelized Vector Field, or (k, D)- Voxelized VF if the following properties hold:

- 1. (Underlying Vector Field Geometry) The vector database represents finite samples from an injective vector field V : R k → R
  - D. Each record Xi of X is a vector V (x) = Xi ∈ R D representing some unique point x ∈ R k .
- 2. (Compactness of the Range) We will assume that each Xi ∈ R D belongs to a hypercube denoted as ΠD j=1[aj , bj ] ⊆ R
  - D.
- 3. (Voxel Domain) X is supported on a k-dimensional voxel grid M, see Appendix Section A.6. Thus, the index i ∈ [n] for each Xi is in one-to-one correspondence with a unique coordinate, or voxel, I(x) = (i1, ..., ik) in [n1] × · · · × [nk] where V (x) = Xi for some x ∈ R k .
  - We use the integer i and the integer tuple I(x) interchangeably due to the one-to-one correspondence.

Corollary 1. (Undecidability of LossyIndexedCompression on Voxelized VVF data)

Let ρ : R D × R D → R≥0 be a nontrivial metric so that

$$\forall x, y \in \mathbb{R}^D : x \neq y \Rightarrow \rho(x, y) > 0 \quad (14)$$

Lossy Indexed Compression with a Kolmogorov decoder and instances (ε,(X1, ..., Xn)) restricted to (k, D)-Voxelized VF X with distribution P(Xi) = δXi and ε > 0 is undecidable.

Proof. Since ρ is a nontrivial metric, Bx(ε) ⊆ R D is infinite. The result thus follows by Theorem 1.

We would like to understand the data vectors Xi = (x1, ..., xD) from X in terms of a multivariate continuous objective function f : R D → R of its "units" xj ∈ R.

We require this function f to be a piecewise multivariate polynomial in the D variables expressible as a string of symbolic input to an algorithm. This symbolic input should be interpretable as an algebraic expression consisting of a composition of binary sum (+) and binary product (·) arithmetic operations. For example f(x, y) = x · y + y · y · y.

Assume the symbolic string representation of a piecewise multivariate polynomials can be computed in polynomial time in the length, denoted len(f) of the string. We can assume that the degree of f satisfies: deg(f) ≤ len(f). For the definition of the degree of a piecewise multivariate polynomial, see the Preliminaries in Section 1.2. The number of bits to represent f satisfies: size(f) = 8len(f), assuming an 8 bit ASCII code alphabet.

Example 1. For example, the multivariate polynomial objective function over the vector space of 7-dimensional vectors could be a kinematic energy function f : R 7 → R, as the following algebraic expression:

$$f(m, v_x, v_y, v_z, x_x, x_y, x_z) \triangleq \frac{1}{2} \cdot m \cdot v_x \cdot v_x + \frac{1}{2} m \cdot v_y \cdot v_y + \frac{1}{2} m \cdot v_z \cdot v_z + m \cdot g \cdot x_z; g \triangleq 9.8 \text{ m/s} \quad (15)$$

This expression can be stored as a string of floating points, functional relations, floating point operations, and variable symbols. It can also be evaluated to compute the kinematic energy function in time linear in the string length.

#### 1.3 Voxelized Vector Field Compression

In the lossy indexed compression problem, we can define a distortion function df as the Euclidean distance between the energy, defined by the piecewise multivariate polynomial f, of a vector and its reconstruction:

$$d_f(X_i, \hat{X}_i) \triangleq |f(X_i) - f(\hat{X}_i)|_2 \quad (26)$$

This distortion function naturally measures the change in energy between a vector and its reconstruction at a common index i. We call this the energy gap distortion function.

We would like to define computable encoders and decoders for the lossy indexed compression problem. We will thus understand the encoders and decoders in terms of index consistent compression and decompression algorithms respectively. As discussed in Lemma 2, the output codeword involves clustering assignments i 7→ Xi atmost at the granularity of n individual assignments. We can thus define this compression-decompression process in the following:

Definition 5. A clustered indexed algorithmic compression scheme M over (k, D)-voxelized vector fields is a pair of algorithms (C, D), called the compression and decompression algorithms. They are governed by the following three step protocol:

Given a (k, D)-voxelized vector field X, a piecewise multivariate polynomial objective function f : R D → R, and an error bound ε.

- 1. The compression algorithm C takes a triple (X, f, ε) as input and outputs a codeword C(X, f, ε) from the codebook {1, ..., 2 Rn } with

- C(X, f, ε) a function of the following clustering:

$$\{\{(i, X_i) : i \in S\} : S \in \mathcal{S}(X, f, \varepsilon)\}; \mathcal{S}(X, f, \varepsilon) \subseteq 2^{supp(X)} \quad (27)$$

where S(X, f, ε) is called an index clustering of supp(X).

2. C(X, f, ε) is sent over a "noiseless channel" [Sha48] from C to D.

3. C(X, f, ε) is then decompressed by the decompression algorithm D into a (k, D)-voxelized

vector field.

$$\hat{X} = \mathcal{D} \circ \mathcal{C}(X, f, \varepsilon) \quad (28)$$

where the two algorithms C, D must satisfy:

- (Index Consistency) (X, Xˆ) are index consistent for distortion df at error bound ε.
- (No Learning) M cannot self update from the data (X, f, ε).

Remark 1. This definition is a direct instantiation of the power set expansion encoder of Lemma 2. The index subsets S ⊆ {1, ..., n}, or cluster indices belong to S(X, f, ε).

Remark 2. The lossy indexed compression problem is inherently a learning problem. This is because the encoder-decoder pair can use the input data (X, f, ε) in the optimization problem.

A clustered indexed algorithmic compression scheme cannot learn over data. This means that the program size of the compression and decompression algorithms C and D are O(1).

A sufficient condition for the no learning criterion is an asymmetric causal relationship from the encoder to the decoder. A learnable encoder would then no longer be able to update its code over samplings (x1, ..., xn) ∼ P(X1, ..., Xn) since it cannot check for index consistency from the decoder.

Remark 3. This definition is a generalized variant of a labeled-compression scheme [LW86] from classical learning theory. Let:

$$\mathcal{S}(X, f, \varepsilon) := \{\{i\} : i \in S, S \subseteq \text{supp}(X)\} \quad (29)$$

be a collection of singletons.

The "labeled samples" of a labeled-compression scheme for X are of the form (i, Xi), i being a primary key on the flat index on X and the "kernel" of the labeled samples is the codeword C(X, f, ε) determined by the subset of labeled samples (i, Xi) : ∀{i} ∈ S(X, f, ε).

As discussed in the introduction, the goal is to minimize the rate Rn. This can be converted to a maximization of the compression ratio of the codeword C(X, f, ε). This is defined as:

$$\text{CR}(\mathcal{C}(X, f, \varepsilon), X) \triangleq \frac{\text{size}(X)}{\text{size}(\mathcal{C}(X, f, \varepsilon))} \quad (30)$$

where the "size" of a database X is measured by the number of bits needed to store it with flat-indexing.

Similarly, the "size" of a codeword is the number of bits to store it as part of the codebook {1, ..., 2 Rn } of the outputs of the compression algorithm C. This is the (not necessarily optimal) rate Rn of the clustered indexed algorithmic compression scheme. We can check that CR(C(X, f, ε), X) is maximized when size(C(X, f, ε)) is minimized since size(X) does not change.

#### 1.4 Voxelized Vector Field Compression as a Box Covering Problem

Let us understand a clustered indexed compression scheme through the energy gap distortion function df .

We make the following observation about the energy gap distortion function df :

Observation 1. For a (k, D)-dimensional voxelized vector field X with objective function f : R D → R, the energy gap distortion function df : R D × R D → R≥0 is a metric and the Indexed Vietoris-Rips complex iVRdf r (X) over metric df is well defined for any r < ∞.

Proof. The map (Xi , Xj ) 7→ |f(Xi)−f(Xj )|2 is a metric. Furthermore, no two vectors are equivalent in vector database X by definition of a (k, D)-dimensional voxelized vector field. Thus the Indexed Vietoris-Rips complex can be constructed for any diameter threshold.

In Observation 1, we have that iVRdf r (X) for any r < ∞ is well defined. According to the definition of an Indexed Vietoris-Rips Complex, the clusters in this case must consist of a collection of connected components on supp(X). These consist of orthogonal polyhedra, boxes etc. see Section A.6.1 for definitions of connected shapes on voxel grids.

Let us specify a restriction on the power expansion of the compression algorithm belonging to a clustered indexed algorithmic compression scheme. This restriction chooses exact closed forms for the maps Λ, κ, ϕ. In particular, these are chosen to restrict the compression algorithm to an index clustering. These restrictions isolate the clustering for the assignments i 7→ Xi for i ∈ supp(X).

Definition 6. A collection of boxes R ⊆ 2 supp(X) covers the indices of a (k, D)-dimensional voxelized vector field X if for every i ∈ supp(X), there is a R ∈ R that has i ∈ R.

Such a collection of boxes is called a box cover.

# 3 Decompressing is Easy

The data structure C(X, f, ε) is a box cover over the indices of a (k, D)-dimensional voxelized vector field. Our objective in the (k, D)-RectLossyVVFCompression is to maximize the compression ratio. In order to achieve this, we must find redundant indices up to the inequality constraint from Problem 2. This can be achieved by finding large clusters of vectors Xi whose indices can be jointly summarized up to the lossy constraint.

Let us study the space of all possible clusters formed by the metric inequality constraint of Problem 2. An Indexed Vietoris-Rips Complex is defined by such an inequality constraint. The following observation says that any clustering of a vector database X up to a distortion bound of ε ∗ is contained in some Indexed Vietoris-Rips Complex of threshold 2ε ∗ .

Proposition 3. Let ε ∗ > 0 and let there be a (k, D)-dimensional voxelized vector field X with objective function f : R D → R.

For any cluster C ∈ iVRdf 2ε ∗ (X), each vector Xi : i ∈ C can be replaced by the mid-range summary value:

$$\text{mid-range}(f, C) \triangleq \frac{\max_{i \in C} f(X_i) + \min_{i \in C} f(X_i)}{2} \quad (46)$$

on C without affecting the ε ∗ distortion bound:

$$|f(X_i) - \text{mid-range}(f, C)|_2 \leq \varepsilon^*, \forall i \in C \quad (47)$$

Proof. By Observation 1 the Indexed Vietoris-Rips Complex iVRdf 2ε ∗ (X) is well defined.

Certainly, for any C ∈ iVRdf 2ε ∗ (X)

$$|\text{mid-range}(f, C) - f(X_i)|_2 = \left| \frac{(\max_{j \in C} f(X_j) + \min_{j \in C} f(X_j))}{2} - f(X_i) \right|_2 \quad (48a)$$

$$\leq \left| \frac{(\max_{j \in C} f(X_j) + \min_{j \in C} f(X_j))}{2} - \min_{j \in C} f(X_j) \right|_2 \quad (48b)$$

$$= \left| \frac{\max_{j \in C} f(X_j) - \min_{j \in C} f(X_j)}{2} \right|_2 \leq \varepsilon^*, \forall i \in C \quad (48c)$$

# 5 (k, D)-RectLossyVVFCompression is APX-Hard

In order to prove that the (k, D)-RectLossyVVFCompression problem is APX-Hard, we need to find a PTAS reduction from an APX-Hard problem. A potential candidate problem is the rectangle cover problem, also known as the "geometric set cover problem by rectangles" in the computational geometry literature [HW86].

In the rectangle cover problem, the instances are range spaces, which are pairs consisting of a set X and a collection of subsets of X. The range space for the rectangle cover problem is a set of points on the plane and a collection of rectangles on the plane. The goal is to find the minimum cardinality rectangle cover of the points. It is known to be APX-Hard [CG14].

In fact, this is APX-Hard even when the collection of rectangles on R 2 only intersect either emptily or at their boundaries at exactly 4 points. We call this problem the 2-DimSpecialBoxCover problem. We would like, however, an even more simplified version of the problem to fully exploit planarity.

We can start from a combinatorial set system problem, unrelated to geometry, known to be APX-Hard [CG14]. It is called the Special-3SC problem. It is a special case of the minimum vertex cover problem on graphs of degree at most three and can be reduced from the minimum vertex cover problem on degree 3 regular graphs (3VC). The 3VC problem is known to be APX-Hard [CG14].

## 5.2 A Sweep-Line Algorithm to Cover the Complement

As Lemma 4 shows, we can embed a range space instance (X, R) of SpecialRect-3SC into [2N] 2 . This, however, is not an instance of 2-DimIntVGridBoxCover. It is only a cover of the union of all boxes in R. We need a covering of all of [2N] 2 .

We can define the set of integer coordinates that are missing. Assuming a collection of boxes R in a 2-dimensional voxel grid [q] 2 . Let us define the complement of the union over R:

$$C \triangleq [q]^2 \setminus \bigcup_{R \in \mathcal{R}} R \quad (95)$$

We would like to compute a covering of this complement by boxes. Taking the union of R and such a covering of the complement would give an instance to 2-DimIntVGridBoxCover.

If we can compute a box covering H that satisfies:

$$\exists K \in \mathbb{R}_{\geq 0} : |H| \leq K|\mathcal{R}|, \quad (96)$$

then we will show in Theorem 10 that the constant K can be used to preserve a PTAS for SpecialRect-3SC to a PTAS for 2-DimIntVGridBoxCover.

We show this explicitly in Algorithm 4. It is a kind of sweep-line algorithm [SH76] over a 2D voxel-grid. In such an algorithm, a horizontal "sweep-line" scans from bottom to top of the 2D voxel grid. The goal is to record rectangles that fully cover the partial voxel grid


$$C_k = \{(i, j) \in C : j \leq k\} \quad (97)$$

of C scanned up to height k until the entire voxel grid is scanned.

The algorithm requires sweep-line events. At each of these events, the algorithm records an update to the collection of rectangles H covering the complement C. These events can be represented by key-value pairs where the key determines an integer height at which the sweep-line performs an update and the value is the rectangle which is intersecting with the sweep-line.

We define our sweep-line events as the following key-value pairs:

1. (Bottom Event): (min((R)2), R)

2. (Top Event): (max((R)2), R)

We will have two events that always occur in our sweep line, the first is an initial starting event and the second is the final ending event:

1. (1, [q] × 1) is a starting Top Event

2. (q, [q] × q) is an ending Bottom Event

These are the bottom and top of the voxel grid and thus are considered as not being a part of the complement C.



Figure 3: Illustration of a Sweep Line Algorithm with its Top Events and Bottom Events

The algorithm, similar to the sweep-line algorithm for the planar point location problem [ST86] and the rectilinear polygon cover problem [Fra89], requires tracking intervals covering Ck from Equation 97 that close up later to form rectangles in C.

This is an example of a persistence algorithm, [ELZ02]. The intervals tracked from Ck at each sweep line height form "1-dimensional homology generators" that close up to form 2-dimensional rectangles during an event.

In [ST86], these "1-dimensional homology generators" are tracked with a partially persistent search tree data structure. A data structure is called partially persistent [DSST86] if it can update its present state and query any of its past states. In the case of sweep-line algorithms, the state is indexed by the events ordered by height. The partial persistence is necessary to look back in time to the past homological generators.

We show in Lemma 5, that Algorithm 5.2 has an output size bound up to a constant factor with the number of boxes N.

Lemma 5. Let R be a collection of N boxes, each box a subset of [q] 2 . There is a box cover of C with at most 4N boxes consisting of boxes contained in C.

This can be computed in time O(N log N) by implementing Algorithm 5.2 with an interval tree, see Algorithm 4 and Section A.8, Section A.5.1 in the Appendix.

### Proof. Correctness of Algorithm 4:

The algorithm forms horizontal "sweep segments" at every sweep-line event. We define our sweepline event by the value of the second dimension (vertically) of the upper and lower sides of the rectangles in R.

For each sweep-line event in order from low to high, it must "create" atmost two intervals which must be closed up to form a 2D rectangle at a later event.

Certainly each created interval must eventually have some sweep-line event above it. Such sweepline events destroy a created interval.

Say that there are still created intervals that do not have a sweep-line event above them. We know, however, that the last sweep-line event destroys all remaining created intervals. This proves the claim.

#### There are Atmost 2N Creation Events:

Since there are N rectangles and each can create atmost 2 intervals, this proves the claim.

Algorithm 4 is an implementation of Algorithm 5.2 using an interval tree. The interval tree acts as the storage data structure to track the created intervals. When an interval is created it is inserted into the interval tree. When an interval is destroyed, it is deleted from the interval tree. This is a direct correspondence between the memory requirements of the algorithm and the operations on the data structure. Thus, it does not change correctness.

#### Complexity of Algorithm 4:

Algorithm 4 requires two sorting operations and O(N) number of query/insert/delete operations on the interval tree. These operations are log(N) in complexity, see Section A.8 in the Appendix. Thus the algorithm runs in time O(N log N).

$$\mathcal{U}(\mathcal{R}'') \triangleq \bigcup_{R \in \mathcal{R}''} R \quad (112)$$

The rectangle cover of minimum size for U(R′′) has the cardinality of the subcover O of R′′ consisting of rectangles whose corners are not covered by any other rectangle in R′′ .

Proof. We state here Property 2b for an instance (X, R) of SpecialRect-3SC. It states that the collection R satisfies the following property:

Property 2b: "Every pair of rectangles R, R′ ∈ R : R ̸= R′ , either intersect at exactly four points between their boundaries or not at all."

In the definition of an instance of VGridSpecialRect-3SC, because of the box collection embedding ϕ we must have that R′′ = {ϕ(R) ∩ Z 2 : R ∈ R} of the instance ([2N] 2 , R′′ ∪ H(R′′)) satisfies Property 2b of a SpecialRect-3SC instance.

If a corner is covered, then in order to satisfy Property 2b, R must be a strict subset of another rectangle R′ ∈ R′′ .

We have just shown that pairs of rectangles in R′′ either:

- 1. Do not intersect.
- 2. Have one strictly contained in the other.
- 3. Intersect at 4 points between their boundaries.

We show that the collection O : O ⊆ R′′ consisting of all rectangles whose corners are not covered by any other rectangle in R′′ is a cover of U(R′′).

Since the collection O satisfies that all rectangles in O have their corners uncovered, we must have that it cannot have any rectangle satisfy Property 2 for pairs of rectangles in R′′. In fact, since we want to minimize the size of the cover, the smaller of the two rectangles R, R′ ∈ R′′ : R ⊆ R′ cannot belong to O.

#### Minimality:

We prove that there is no rectangle cover of U(R′′) of smaller cardinality than O.

Say that the subcover O : O ⊆ R′′ is suboptimal in size. This means some rectangle R∗ ∈ O is not in any of the true optimal covers of U(R′′).

Since R∗ does not belong to a true optimal cover, all the points x ∈ R∗ must now be covered by some alternative rectangles (which may or may not be in R′′).

None of the four corners of R∗ are covered by any other rectangle in R′′ besides R∗ . Consider without loss of generality one of the corners c ∈ R∗ with:

| $c = \min_{x \in R^*} \max_{j \in [2]} (x)_j$ | (113) |
|-----------------------------------------------|-------|
|-----------------------------------------------|-------|

We notice that the rectangle R∗ is maximal. This means that the largest rectangle, with respect to the inclusion operation, that contains corner c ∈ R∗ is R∗ itself.

In order to form a rectangle in U(R′′) with c as a bottom left corner, we must consider all points above and to the right of c. We notice the following:

$$(c)_j \leq (y)_j, \forall j \in [2] \Leftrightarrow y \in R^*, \forall y \in \mathcal{U}(\mathcal{R}) \quad (114)$$

Thus, we can say:


$$\text{BB}(c, y) \subseteq R^*, \forall y \in \mathcal{U}(\mathcal{R}) \text{ s.t. } (c_j)_j \leq (y_j)_j, \forall j \in [2] \quad (115)$$

In fact, if we maximize over all such y, there is a unique maximum. This maximum is R∗ itself.

This means that any rectangle that covers the corner c ∈ R∗ , can be replaced by R∗ without increasing the size of the cover.

By symmetry, all such corners have this property. Thus, R∗ belongs to the optimal cover of U(R). Since R∗ was arbitrary from O, it must be that any optimal cover of U(R) has size atleast |O|.

We have just shown that the optimal covering of U(R′′) is a subcover of R′′. Since the complement H(R′′) of U(R′′) with respect to [2N] 2 consists of disjoint rectangles, the optimal subcover of R for [2N] 2 is O ∪ H∗ where H∗ is an optimal subcover of H(R′′).

#### A.5.1 Terminology and Notation for Algorithms and Complexity Theory

Definition 30. An optimization problem P = (I, S, c) is determined by a space of input instances IP , a space of feasible solutions SP , and a cost function cP : SP → N.

The maximization/minimization objective is for every instance x ∈ IP to find some solution sP (x) ∈ SP where:

- 1. sP : IP → SP is some (nonunique) solution map from instances to solutions and
- 2. cP (sP (x)) is maximized/minimized.

Definition 31. A decision problem P = (IP , SP ) is determined by a space of input instances IP and a space of feasible solutions SP where every x ∈ IP has some (atleast one) corresponding solution sP (x) ∈ S for a (nonunique) map sP : IP → SP .

The decision objective is for every instance x ∈ I to decide (true or false) whether there is a solution sP (x) ∈ S corresponding to x.

|-----------------------------------------------------|-------|

For any instance x ∈ IP , any membership oracle for LP decides the decision objective of P.

For any input string x, membership in LP can be decided by a membership oracle for the decision objective P.

We discuss the terminology for algorithms and complexity theory. For notations such as asymptotics and problem formulations, see Section A.5 and Section A.5.1 in the Appendix.

Definition 37. We say a function f : A → B is polynomial time computable if there exists a deterministic algorithm running in polynomial time that computes f.

A problem can also be verified. This means for a given instance-feasible solution pair (x, s) ∈ I×S, we check (true/false) if s is a corresponding solution to x according to the problem.

Definition 38. A problem P = (I, S, •) is in nondeterministic polynomial time (NP) if there is a polynomial time deterministic algorithm that can verify whether for a pair (x, s) ∈ I × S that there is some solution sP (x) with sP (x) = s.

We call the set of all such decision problems the complexity class NP.

The set of all such optimization problems forms the complexity class NPO.

For any minimization/maximization problem P = (I, S, c) in NPO there is a corresponding decision problem of the form (I × N, S) where true solutions to instances (x, k) ∈ I × N satisfy:

- 1. c(s(x)) ≤ k for a minimization problem
- 2. c(s(x)) ≥ k for a maximization problem.

Proposition 15. If the corresponding decision problem PD of an NPO problem P is NP-Hard, then P is NP-Hard.

For Proof, see Section A.5.1 in the Appendix.

Definition 39. A Karp reduction [GJ] from decision problem A = (IA, SA) to decision problem B = (IB, SB), denoted A ≤p B is a polynomial time algorithm that computes a function m : IA → IB that takes instances of A to instances of B so that the following diagram commutes:

$$\begin{array}{ccc} I_A & \xrightarrow{m} & I_B \\ s_A \downarrow & & \downarrow s_B \\ S_A & \xleftarrow{i} & S_B \end{array} \quad (150)$$

where i : SA → SB is an injection and sA : IA → SA, sB : IB → SB are the (nonunique) solution maps.

This means:

$$\exists i : S_A \rightarrow S_B \text{ injective } , \forall x \in I_A : s_B(m(x)) = i(s_A(x)) \quad (151)$$

We can define two more complexity classes. These are of importance for determining the theoretical intractability of a problem.

Definition 40. The decision problem P is NP-Complete if any problem in NP can be Karp reduced to P.

A decision problem P is NP-Hard if there is a Karp reduction from a NP-Complete problem to P.

It is conjectured that NP-Hard problems are not feasible in practice to compute.

We can also design algorithms that approximate problems. We formalize this in the following:

Definition 41. For a problem P = (IP , SP , cP ) in NPO, a deterministic algorithm A approximates a maximization/minimization problem P with approximation factor f(n), n ∈ N if for every x ∈ I with size(x) = n :

$$\frac{c_P(s_P(x))}{c_P(\mathcal{A}(x))} \leq f(n) \tag{152}$$

If such an algorithm A exists, then we say that P is f(n)-APX. The algorithm is called an approximation algorithm.

Definition 42. A problem in NPO is approximable (APX) if there is a polynomial time deterministic algorithm with constant approximation factor.

If we introduce a parameter ϵ > 0 so that the approximation factor of an approximation algorithm is (1 + ϵ), we form another complexity class:

Definition 43. A problem in NPO having a polynomial time deterministic algorithm with an approximation factor (1 + ϵ) is called a polynomial time approximation scheme (PTAS).

Proposition 16. The following tower of complexity classes holds:

| $PTAS \subseteq APX \subseteq NPO$ | (153) |
|------------------------------------|-------|
|------------------------------------|-------|

Proof. Check the definition of the classes.

We define a reduction for the APX complexity class that is used analogously to the Karp reductions for the complexity class NP.

Definition 44. Let P = (IP , SP , cP ), Q = (IQ, SQ, cQ) be two problems in NPO.

A PTAS reduction from P to Q, denoted: P ≤P T AS Q has:

- 1. (Reduction Map) A polynomial time computable function m : IP → IQ.
- 2. (Approximation Factor) α : R>0 → R>0
- 3. (Solution Map) A polynomial time computable function g : IP ×SQ → SP so that the following diagram:

$$\begin{array}{ccc}

 S_P & \xleftarrow{g} & I_P \times S_Q & \nearrow_{\Diamond \times id} S_Q
 \end{array} \tag{154}$$

has the following relationship:

$$\begin{aligned} \forall x \in I_P, \text{ If there is an Algorithm } \mathcal{A} \text{ satisfying:} \\ |\mathcal{A}(m(x))| \leq (1 + \alpha(\epsilon))|s_Q(m(x))| \\ \text{Then } |g(x, \mathcal{A}(m(x)))| \leq (1 + \epsilon)|s_P(x)| \end{aligned} \tag{155}$$

for sQ, sP (nonunique) solution maps for P, Q and where ♦ is a placeholder map (any map can go here), and id is the identity map.

It is known that a composition of PTAS reductions is a PTAS reduction.

Definition 45. We say that a problem is APX-Hard if any problem in APX PTAS reduces to it.

A problem is APX-Complete if it is APX-Hard and belongs to APX. It is known that if P ̸= NP then any APX-Hard problem cannot be in PTAS by using the PCP theorem [Din07] in a reduction from 3-SAT to the APX-Complete problem MAXSAT.

#### A.6 The Voxel Grid Index Space

We define here an integer index space in k-dimensions.

Definition 46. A k-dimensional voxel grid M is a set of points with the following Euclidean properties:

- 1. All points x ∈ M can be given a unique coordinate via the injective coordinate map:

$$I : x \mapsto (i_1, \dots, i_k) \in \mathbb{Z}^k \quad (156)$$

- 2. Each point x ∈ M with coordinate I(x) = (i1, ..., ik) has a neighborhood of coordinates

$$N_{f(x)}^M \triangleq \{(i_1, \dots, i'_j, \dots, i_k) : i'_j = i_j + s, s \in \{-1, 1\}, j = 1, \dots, k\} \quad (157)$$

Example 4. A simple example of a 2-dimensional voxel grid M is [n1] × [n2] ⊆ N 2 .

Each point (i, j) ∈ [n1] × [n2] is its own coordinate. It has a neighborhood:

| $\{(i, j), (i - 1, j), (i + 1, j), (i, j - 1), (i, j + 1)\}$ | (158) |
|--------------------------------------------------------------|-------|
|--------------------------------------------------------------|-------|

The points (0, •2),(n1, •2),(•1, 0),(•1, n2), •1 ∈ [n1], •2 ∈ [n2] are virtual points not on the grid but belonging to the neighborhood of each point on the boundary of the grid.

Definition 47. In a k-dimensional voxel grid M, we denote

$$e_q \triangleq (\overbrace{0, \dots, 0, 1, 0, \dots, 0}^q, q \in [k]) \quad (159)$$

as a standard generating vector of Z k in k dimensions.

We have shown that Z k is a Z-module. In particular, the vectors in Z k can be added together just like those from R k .

#### A.6.1 Connected Shapes In Voxel Grids

We define a connected shape in terms of a sequence of points.

Definition 48. Let M be a k-dimensional voxel grid.

A sequence of points (x1, ..., xn) ∈ Mn , n ∈ N is a walk on M if

| $I(x_{i+1}) \in N_{I(x_i)}^M, \forall i = 1, \dots, n-1$ | (160) |
|----------------------------------------------------------|-------|
|----------------------------------------------------------|-------|

For a set of points, we can use walks to define connectivity in j dimensions for j ≤ k:

Definition 49. Let M be a k-dimensional voxel grid.

A nonempty set of points S ⊆ M is connected in j dimensions, j ≤ k, if for any pair of points x, y ∈ S there are j sequences of integer coordinates (I(z p i ))np i=1, p = 1, ..., j, np ∈ N satisfying the following:

- 1. (Endpoints at x, y) z p 1 = x, z p np = y, z p i ∈ S, ∀p ∈ [j]
- 2. (Connected) The sequence (z p i ) np i=1 is a walk on M for all p ∈ [j].

3. (Distinguishable) No pair of sequences intersect by sharing any points except x and y.

We identify a connected set in one dimension and parameterize it by the dimension it has a nontrivial range in:

Definition 50. A line segment L in dimension q in a k-dimensional voxel grid M is a nonempty set of points connected in one dimension where all of its indices only differ in a single dimension q ∈ [k].

Since a line segment in dimension q can be parameterized by only a single variable, we can denote a line segment by its two endpoints:

$$[a, b]_q = \{x \in M : (I(a))_q \leq (I(x))_q \leq (I(b))_q\}, a, b \in M; \quad (161a)$$

| s.t. $I(b) - I(a) = d_e, d \in \mathbb{N}$ for some $q \in [k]$ | (161b) |

|-----------------------------------------------------------------|--------|

#### A.6.2 Bounding Box

Given a set of points, we can define a simple set that covers all of these points through maximizing its size along all the dimensions.

Definition 51. Let S be a subset of a k-dimensional voxel grid M.

A bounding box of S is the following region:

$$BB(S) \triangleq \{x \in M : \min_{s \in S} I(s)_q \leq (I(x))_q \leq (\max_{s \in S} I(s)_q), \forall q \in [k]\} \quad (162)$$

A bounding box can also be defined by the same construction in Euclidean space R k .

The dimensions of nontrivial length for the bounding box of a set of points S ⊆ M are called the axes of S, denoted J(S). More formally:

Definition 52. Let S be a subset of a k-dimensional voxel grid M.

| $J(S) = \{q \in [k] : (\max_{s \in BB(S)} I(s))_q < (\max_{s \in BB(S)} I(s))_q\}$ | (163) |
|------------------------------------------------------------------------------------|-------|
|                                                                                    |       |

Definition 53. We say that a j-dimensional box is a set of points connected in j dimensions whose bounding box is itself.

Definition 54. A 2-dimensional box is called a rectangle.

We define a "corner" on a subset of a voxel grid.

Definition 55. Let P be a set of j-connected points in a k-dimensional voxel grid M.

A point x ∈ P is called a j-dimensional corner if there is another unique point y ∈ M, called the witness point, whose index is reachable by a sum of j independent unit vectors from I(x) ∈ Z k satisfying:

$$\exists! y \in M$$
 with  $I(y) = I(x) + \sum_{q \in J(P)} v_q e_q; v_q \in \{-1, 1\}$  (164)

- 1. The corner x ∈ P is convex if BB({x, y}) ⊆ P and
- 2. The corner x ∈ P is concave if BB({x, y}) ⊆ P but y /∈ P.

We can now recover the usual definition of a corner from a three dimensional cube:

Example 5. A three dimensional cube, which can be defined by the voxel grid C := ({0, 1}) 3 , has all of its 2 3 points as corners where for corner (c1, c2, c3) ∈ C its witness is (1−c1, 1−c2, 1−c3) ∈ C

Generalizing the three dimensional cube to j dimensions in a voxel grid of dimension k, we can define unit boxes:

Definition 56. We call a j-dimensional box with exactly 2 j convex corner points a j-dimensional unit box.

This allows us to define a more general shape:

Definition 57. For voxel grid M, a union of j-dimensional unit boxes P ⊆ M connected in j dimensions is called a j-dimensional general orthogonal polyhedron.

We denote dim(P) as the dimension j of the general orthogonal polyhedron.

In two dimensions, we call these orthogonal polygons. When the dimension j is arbitrary, we just say general orthogonal polyhedron.

A general orthogonal polyhedron may have partial disconnections such as "holes." These can be defined formally in the sense of homotopy [Mun00], namely through the "fundamental group." We will not define this in general and will allow for such partial disconnections.

We can show the following hardness relationship amongst the parameter pairs (k, D), namely that both the (k, D)-RectLossyVVFCompression problem and the (k, D)-RectLossyVVFCompression problem are atleast as hard as their lower dimensional version.

Similarly, this relationship is true between the (k, D)-RectLossyVVFCompression problem and the (k ′ , D′ )-RectLossyVVFCompression problem if k ≥ k ′ , D ≥ D′ .

#### A.8 Interval Tree Data Structure

An interval tree [Ede80] is a dynamic data structure that stores a collection of intervals on the real line. It has three operations that can be performed on it. Let T denote an interval tree. The three operations and their complexity are shown below:

- 1. (Insert): Insert(T , I) : I = [a, b], a, b ∈ R
  - (a) Adds an interval to the collection of intervals stored by T .
  - (b) This takes time O(log(n)).
- 2. (Delete): Delete(T , I) : I = [a, b], a, b ∈ R
  - (a) Delete an existing interval from T . If there is none, then do nothing.
  - (b) This takes time O(log(n)).
- 3. (Query) Query(T , I) : I = [a, b], a, b ∈ R
  - (a) Queries for all possible intervals in T intersecting with I an existing interval from T .
  - (b) This takes time O(log(n) + k) where k is the number of intervals returned by the query.
