Context
Refs #4814. Slice-1 (#4833, open) pinned Black Flag's 32x32x32 R8 3D mip pyramid
(six single-level T# views, levels 0..5, one shared base) as decode-exact but
refused past level 0. This slice places them: thick-3D (SW_64KB_S) chains pack
every level into the allocation's first 64 KiB block, and the recompiler admits
explicit-LOD 3D sampling with the guest LOD.
The placement is not derived from first principles. AMD's AddrLib
(ComputeSurfaceInfoMacroTiled thick branch: halved-width tail dims, 10 tail
levels, alternating-bit origins) predicts per-level tail coordinates, and a
ps5debug-NG carve of the live pyramid (base 0x4066a90000) confirms each one:
detiling every level through its predicted coordinates reproduces the level
above at correlation 1.0000 down the whole chain (L5 byte-exact, means
86.0-86.2 throughout). The naive disjoint-block model is refuted by the same
bytes (level 1's block holds 5884 nonzero bytes for 4096 texels; level 2's holds
16; blocks 3-5 are unrelated allocations).
Higher Goal
The six views bind and upload their proven texels, unblocking the 3D looks the
counts attribute to this pyramid. The rule is generic across thick-3D titles.
Acceptance Criteria
All six levels admit with exact tail coordinates and unshifted base
Tail texels upload through the translated-region detile (live_compute)
image_sample_l dim:3D compiles with the guest LOD (not const 0)
Live route A/B: the pyramid renders (owner — see Verification)
Chain views (BASE!=LAST): refused, tracked below
Out of Scope
Multi-level chain views stay refused: per-level materialization needs volume
support in mip_chain_plan, which does not exist yet (slice-3).
Sw4KbS, thin modes, chains whose level zero is not itself in the tail: same
silent-wrong-texels hazard, still fail-closed with named arms.
3D-tail STORAGE writeback: admitted views flow through the existing
tail-declining retile/CPU paths fail-visibly; no silent mis-write, no proven
write path either.
image_sample_b/_d/_c 3D: still refused (no lowering exists).
Summary of Changes
prosper/src/gpu/texture/tile.{hpp,cpp}: tiled_volume_tail_layout (the
AddrLib thick rule, Sw64KbS-only) + detile_volume_tail_level (translated S3
equation; zero-translation is byte-identical to the proven whole-block detile).
prosper/src/gpu/agc/agc_shader_layout.{hpp,cpp}: admit type-10 single-level
tail views (base unshifted, extent shifted incl. new view.depth); all four
view→resource sites carry view.depth (zero-net; 2D values unchanged).
prosper/frontends/shared/live/live_compute.cpp (+3, noted row): route 3D
tail views to the translated detile in the sampled-upload branch.
prosper/src/gpu/recompiler/rdna2_emit_alu.cpp (+1 arm, under its row):
admit is_sample_l in the dim3d branch with the LOD VGPR (cvg(3),
NSA-aware like the 2D-array path).
Tests: BuildShaderResources.VolumeTail{Layout,View,DetileMechanism} (exact
coords, admission fields, hand-computed equation spots) +
test_3d_sample_l.cpp (admission, guest-LOD operand scan, _lz control, _b
refusal).
arch_ratchet_baseline.txt: live_compute 14594 -> 14597 with reviewer note.
Relationship with #4833
#4833's single-level refusal arms assert the OLD behavior and will redden once
this lands. Merge #4833 first; this PR then rebases onto it and flips those
arms to the admitted form (the flip is mechanical: same words, supported +

Security Blast Radius
inferred — The demonstrated exposure is guest-controlled image descriptors and shader operands reaching host-side texture materialization and GPU execution. The inspected evidence does not establish a tenant, service, credential, or environment authority expansion.
Security Findings and Attack Paths
observed — The new translated volume detiler does not add a depth-dependent macroblock address. Its computed offsets remain within the first 64 KiB, and unavailable source elements are zero-filled. A larger validated backing span is therefore not evidence that this detiler exposes neighboring allocations.
Trust Boundaries and Controls
observed — Before sampled materialization, the caller limits expanded and source backing sizes to 512 MiB and requires sufficient host backing or a readable guest range. The detiler additionally bounds individual source copies.
Resilience and Maintainability Implications
observed — A false return from tail detiling marks image preparation unsuccessful and stops the current dispatch before subsequent execution setup. This supports dispatch-scoped failure containment, but does not establish complete cleanup or interrupted-execution recovery.
Hardening Proposals
proposed — Make the shared-block invariant explicit across admission and consumers: validate complete 3D tail geometry, use an authoritative tail source span, and preserve volume-tail semantics at depth one. Keep unmodeled mutable uses refused until their writeback and sibling-preservation contracts are established.

APPROVED on head 57980608407d505c7db8710812e2810ab08e42be (the contributor's e5bef7fb5 plus one reviewer commit on top).
Unlike #4831, this places levels by the thick-3D rule. Per-level width, height and depth all shift by BASE_LEVEL. view.depth replaces the descriptor's allocation-wide depth at all four view-to-resource sites. Tail origins come from the S3 Block256_3d geometry with z starting at 0, and detile_volume_tail_level runs the 3D S3 equation at translated (x, y). Shapes it can't place (Sw4KbS, thin modes, a level zero outside the tail, too many levels) return supported = false and drop visibly. The # note #4814 on the +3 live_compute.cpp row names the guest-visible result, so it is justified.
Findings, all fixed in 579806084:
The 1^3 level still reached the 2D tail detile, which is the #4831 failure. Level 5's view has depth == 1, so it missed r->tile_mode && dim_3d && r->depth > 1 in live_compute and fell through to detile_surface_level. That is the 2D swizzle evaluated at a 3D tail origin, which gives silent wrong texels. Both the backing-size and upload branches now take dim_3d && (r->depth > 1 || r->in_mip_tail), so every in-tail 3D view goes through detile_volume_tail_level. The PR's tests exercise the tile helpers directly, so they could not see this routing.
No depth check on tail admission. tiled_volume_tail_layout compared only width and height with the tail. A level zero of 32x32x64 R8 would place, and its z >= 32 would alias onto the lower slices through the in-block equation. It now refuses when depth > kSw64kbS3Dims[el][2]. I added a VolumeTailLayout arm for this case; it goes red with the guard removed (checked).
Block-compressed volumes went into the tail rule with texel extents against element tail dims, and there is no BCn volume-tail reader on the upload side. They now keep the base-level-only rule.
Non-blocking: image_sample_l 3D now lowers with the guest LOD. For a single-level view that clamps to the selected level, which is correct. A base-level-0 multi-level 3D view, which has no volume mip materialization yet, would clamp a nonzero LOD to level 0. That gives the wrong detail level, not garbage, and it matches the 2D path. Worth tracking with the chain-view slice.
Gates: test_build_shader_resources (4) and test_3d_sample_l (4) pass. The live_compute.cpp object compiles. git diff --check is clean. The arch ratchet delta prints ok; I left the two neighbouring long lines unreflowed so the live_compute.cpp row does not rise. clang-format 22.1.8 was applied to the other touched lines. No game runs.
