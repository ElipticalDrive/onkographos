Part of #415.
CUB's BlockHistogram has a second algorithm besides shared atomics (specializations/block_histogram_sort.cuh): sort the keys of the block, find the runs (BlockDiscontinuity), and add each run. It uses no atomics, and its order of addition is fixed by the sort.
Why it matters here
The deterministic mode refuses the tiles of #410 and the block sums of #412 and keeps the older paths: fixed-point bricks, ordered loops. A sort-based accumulation could give the deterministic mode a faster path with results that are the same to the bit for any number of blocks.
Work
A sorted strategy of the scatter-accumulate of Privatized scatter-accumulate as a lowering strategy (dense tile, hash table, atomics), unifying #410 and #412 #416: sort the (index, value) pairs of a block or of a tile by index, then reduce each run in a fixed order, then write or atomically add one value per index. A fixed-point atomic keeps determinism across blocks.
Where to try it:
the tuple kernel in the deterministic mode (against today's path);
PME spreading in the deterministic mode (against the fixed-point bricks).
Validation. Bitwise equality run to run and across block counts. Timings against the deterministic paths of today, per system and node.
The sort itself can take #421's radix sort.
