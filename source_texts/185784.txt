Two methods of generating mipmaps: which one is better?
"There are two different ways of generating the mip-chain. The first one is to blit down the whole mip-chain from level n-1 to n, the other way would be to always use the base image and blit down from that to all levels. This example uses the first one."
From Vulkan documentation: https://docs.vulkan.org/samples/latest/samples/api/texture_mipmap_generation/README.html
So I think the latter is easier than the former: it requires only one pipeline barrier (transfer src for level=0, transfer dst for the rest levels) and each blitting can be done in parallel. But Vulkan tutorial also choosed the former one (https://vulkan-tutorial.com/Generating_Mipmaps#page_Generating-Mipmaps).
Are two methods different for quality or performance?

For quality you can try the first method but instead of blits, I suggest you use a shader and a proper downsampling filter like gamma corrected averages or Lanczos.
Performance, in general is not important unless you need to do it every frame. Most people just do it while loading. If you need to do it every frame then just do the first method and use blits.

Gamma correction averages is pretty simple, you take a quad (4 pixels) do multiply each of their coordinates on themselves, sum them all together, get the square root and divide by 4. It's a common function out there.
Looks like this: 'sqrt(aa + bb + cc + dd)/4'
For more interesting approaches, here's a nice read https://bgolus.medium.com/sharper-mipmapping-using-shader-based-supersampling-ed7aadb47bec
