Solid Rendering & Lighting for 3D Flames
Renders 3D fractal flames as opaque, lit, shadowed objects instead of
transparent ghosts — occlusion, directional lighting, ambient occlusion,
splat-resolution shadow maps, and depth-of-field, all working across the
interactive viewport and every export path. Plus a general 2× antialiasing
export option that applies to 2D, 3D, and solid renders alike.
56 commits · 68 files · +8.7k/−0.2k · 297 unit tests passing · merges into main.
What you get
Solid occlusion — a solid_strength dial (0 = classic transparency,
1 = hard surface, blendable between) turns the front surface opaque via
per-pixel nearest-depth culling. A surface_thickness shell controls how
deep "the surface" reaches.
Deferred lighting — up to 4 directional lights (azimuth / elevation /
intensity / color) with Blinn-Phong diffuse + specular, screen-space
normals, and screen-space ambient occlusion, all computed in a post-pass
from the depth buffer. Lighting edits don't restart accumulation.
Shadows — 4 light-space shadow maps at splat resolution (1024²),
auto-fit to the measured attractor bounds, giving fine per-filament
shadows a voxel grid could never resolve.
Depth of field — a proper post-process gather blur from the depth
buffer (at-splat DoF is incompatible with solid mode by construction),
matching the look of the classic at-splat DoF.
2× Antialiasing — an export checkbox that renders the whole pipeline
at double resolution and box-filters down with a firefly clamp. Works for
every render mode because the pipeline never knows it's happening.
JWildfire interop — solid rendering + lighting round-trips through the
.flame XML sld_render_* block, so JWF solid flames import lit and
shadowed, and ours export back to JWF.
Its own dockable panel — Solid Rendering & Lighting moved out of the
View panel into a first-class panel (Window → 💡 Solid & Lighting).
Architecture (the "splat-native" pipeline)
Everything keys off data the chaos game already produces — no meshing, no
voxel grid, no second spatial structure:
Occlusion is a 5th u32 per pixel appended to the histogram buffer:
an inverted-ordered-float nearest depth, written with atomicMax at plot
time. Samples behind the surface shell have their density weight faded by
solid_strength.
Normals / AO are screen-space, reconstructed from that depth field in
a dedicated normals pass, then edge-aware smoothed by an à-trous chain
(the sparse chaos game leaves depth noise that must be denoised before
lighting).
Shadows are 4 ortho depth maps riding the histogram's tail, splatted
by the same main pass that plots samples, read back in the shade pass with
4-tap PCF. Their placement is frozen per accumulation run from measured
attractor bounds.
Lighting is a deferred shade pass between accumulate and tonemap,
consuming the accumulator (albedo + density) + depth + normals + shadow
maps, emitting an HDR image the tonemap then maps. Fog, when lighting is
active, is applied inside this pass (post-lighting) so highlights and
shadows fade into the atmosphere instead of drawing on top of it.
DoF is a 4-dispatch chain after shade (CoC prepass from smoothed
depth → separable max-dilate for adaptive loop bounds → dense 2D disk
gather).
Zero-cost when off: the SOLID shader-builder flag produces byte-identical
WGSL when solid rendering is disabled, and the whole shade/DoF chain is
simply not dispatched. It's supported on all export routes — the direct
FlameRenderer path, the tiled GPU exporter, and the CPU-histogram
fallback for very large images (with shadow maps on the two GPU paths).
Notable problems solved along the way
The branch went through a real design pivot and several field-reported bugs
worth flagging for reviewers:
The density volume was tried and removed. An earlier phase splatted a
world-space voxel grid for volumetric normals/AO/shadows. It could not
represent sub-voxel fractal filaments as visible geometry without
inflating them into lumpy tubes, and its "Volume Extent" dial was the
single largest performance drain. It was removed wholesale (commit
9490ceb) in favor of the splat-native pipeline above; volume-off scenes
verified byte-identical before/after. The historical design log lives in
docs/projects/solid-rendering.md (Phase 2/3 sections marked RETIRED).
Shadow auto-refit reset loop — the shadow fit re-measured attractor
bounds and could ping-pong into an infinite accumulation reset (~250M
iterations then restart). Fixed with growth-only refits, outlier-clamped
bounds, and a hard one-refit-per-run cap.
2× AA dimming — supersampled renders came out dark. The tonemap
constants are scale-invariant, but 4× the buckets at fixed iterations sit
lower on the concave log curve (Jensen's inequality). Fixed by scaling
iterations ×4 for the supersampled render — exact brightness parity, and
the advertised ~4× cost.
Depth-effects audit — the brightness renormalization (which cancels
occlusion dimming) was folding artistic per-sample weights (far-fade,
depth-density compensation) into its "culled" fraction, so those dials
shifted global brightness. Replaced with dedicated occlusion-only
survival counters on all three render paths.
Config loader skipped migrations — a latent bug (not solid-specific):
batch/directory config loads used raw serde, bypassing version
migrations, so pre-v3 3D scenes loaded as 2D through the CLI batch
exporter. Fixed to route through FractalConfig::from_json.
DoF quality iterations — the gather went through three revisions
(sparse jittered spiral = sand → separable Gaussian = axis streaks →
dense 2D disk = correct) before matching the at-splat reference.
Testing

3D flames render as additive transparent ghosts — far structure bleeds
through near structure. This adds the occlusion foundation from
docs/projects/solid-rendering.md:

- Depth region: one u32/pixel appended INSIDE the histogram buffer (offset
  W*H*4) — zero new bind-group entries (the main pass already runs ~10
  storage buffers against a spec floor of 8). Encoding is inverted
  ordered-float bits: larger = nearer, 0 = "no sample", so plain zero
  clears initialize it and atomicMax tracks the nearest depth. The
  per-batch histogram clear is range-limited to the RGBD words; depth
  persists across batches and the occlusion test tightens progressively.
- Splat gating: samples deeper than nearest + surface_thickness get
  density_weight *= (1 - solid_strength) — 0 is today's transparency,
  1 drops them (and skips the histogram atomics), between is a translucent
  solid. Rides the existing per-sample density_weight channel, so all
  accumulation paths honor it unchanged.
- Depth priming: the first batch after any reset records depth only, so
  the accumulator never ingests interior samples gated against an empty
  depth buffer.
- SOLID shader-builder flag (from ShaderConstants::solid_enabled, set when
  config.solid_strength > 0 in 3D): solid-off builds are BYTE-IDENTICAL to
  before (enforced by solid_off_is_byte_identical) and the depth region
  isn't allocated. 2D and sample-emit builds self-gate off (>128 MB tiled
  exports render without solid until the tiled path carries depth). At-splat
  DoF is compiled out in solid mode (its position jitter would corrupt the
  depth buffer); post-DoF from depth is the planned replacement.
- Config solid_strength/surface_thickness (serde skip-default,
  ConfigPath -> IterationReset, undo/history, en.yml), View-panel sliders,
  renderer plumbing (update_flame/load_config/resize/reset + histogram
  region toggle with bind-group recreation).

Verified: deterministic baselines pixel-identical with solid off (zero-
impact requirement); pentatope A/B shows the front-surface structure with
per-cell palette colors and occlusion gaps where the transparent render
washes to white. 291 lib tests pass; bins + wasm clean.

solid rendering: brightness renormalization for occluded renders
…
64cc413
```
Hard occlusion culls most dispatched samples, but the tonemap normalizes
brightness by DISPATCHED iterations — solids rendered dark by exactly
the culled fraction (a >99% cull rendered near-black at any setting).

Fix by measurement, not estimation: a one-workgroup GPU reduction
(density_stats.wgsl, 256 threads striding the accumulator) sums the
alpha channel = total ACCEPTED density. survival_fraction =
sum / samples_in_buffer scales the tonemap's sample_density (k1/k2
normalization), restoring the brightness the surviving samples deserve.
Self-calibrating for any solid_strength — partial occlusion measures
its own partial fraction; pure-lighting mode (no culling) measures ~1.

- Interactive: async 4-byte readback every 16 frames with an EMA (map
  state machine spans encode -> submit -> map -> callback frames; no
  stalls). Fraction forced to 1.0 whenever occlusion isn't culling.
- CLI export: one exact blocking measurement before the final tonemap.
- Clamped to [0.005, 1] — at most a 200x boost.

Verified: the Phase 0 "dark cloud" hard-solid scene now renders at full
exposure; transparent renders are pixel-identical (fraction-1 path);
solid visual-regression baselines regenerated at the corrected
brightness. 291 lib tests pass.

solid rendering: à-trous normal smoothing (normal_smoothing 0-3)
…
02193d4
```
The nearest-depth field carries Monte-Carlo noise on the order of the
surface shell, and the single-pass 9x9 slope fit left visible speckle in
lit renders on sparse/thin structure. Proper multi-scale denoising:

- normals.wgsl: extracts the bilateral slope fit into a full-image pass
  writing (normal.xyz, depth) to an Rgba32Float texture.
- atrous.wgsl: one edge-aware smoothing iteration — 5x5 B3-spline kernel
  sampled at a power-of-two stride, weights = depth-gaussian (sigma_z
  tied to the surface shell) x normal-similarity^8 — so smoothing
  crosses noise but not silhouettes or creases.
- ShadePass orchestrates normals -> N atrous iterations (strides 1,2,4,
  ping-pong; per-iteration uniform buffers since queue writes flatten
  before dispatches) -> shade consuming the smoothed texture (new
  binding, use_normal_tex param). The strip-tiled export path keeps the
  inline estimator (full-image normal textures + apron logic aren't
  worth it at those sizes); interactive and single-shot exports get the
  full chain.
- Config: normal_smoothing (0-3, default 1) on SolidShadingSettings —
  ConfigPath + UI slider + i18n + string roundtrip; ShadingOnly channel,
  so it tunes LIVE on a converged render.

Verified: the noisiest test case (sparse solid sphere, grazing light) at
3 iterations renders a coherent lit hemisphere with a clean terminator
vs. speckle at 0; the lit regression scene stays within tolerance of its
baseline at the default (mean 0.96/255). 291 lib tests; bins clean.

solid DoF v2: dense 2-D disk gather (quality blur; kills sand + streaks)
…
d97f34e
```
Field feedback across two rounds: v1 (32 jittered spiral taps) read as
"blobs of sand" — Monte-Carlo undersampling of an up-to-3000 px^2
kernel on flame-range data; a separable H+V rewrite still streaked,
because a VARIABLE-radius blur is not separable and a flat 1-D kernel
run twice has a square, axis-aligned point spread.

Final architecture — four dispatches:
1. CoC prepass: per-pixel CoC from bilaterally smoothed depth (the
   raw nearest-depth field carries shell-scale Monte-Carlo noise that
   otherwise modulates the blur disk pixel-to-pixel).
2+3. Separable running-max dilate of the CoC field (max IS separable)
   minus distance -> how far any light can reach INTO each pixel.
4. Dense TRUE 2-D disk gather, loop bound per pixel from the dilated
   field: sharp regions cost a few taps, only defocused areas pay the
   full disk. Zero random sampling -> zero noise; isotropic disk ->
   no axis streaks.

Kernel matches the at-splat reference (uniform disk via
sqrt(rand)*coc): flat profile with a soft rim, energy-normalized by
disk area. Renormalization only when overcomplete — at coverage
boundaries the spread light partially fills the pixel and alpha fades
with it, so the log tonemap melts silhouettes like at-splat does.
Background suppression uses raw depth with a distance-lenient margin
(sloped surfaces don't suppress their own far taps). Max CoC 32 px.

Verified against the same scene rendered through real at-splat DoF
(solid off): matching blur character; sharp focus plane, progressive
near/far blur, soft silhouettes.

export: 2x supersampled antialiasing + firefly clamp (2D/3D/solid)
…
a5d9005
```
Render the ENTIRE existing pipeline at 2Wx2H — histogram, accumulate,
occlusion, shadows, shade, DoF, density effects, tonemap — and
box-filter the final TONEMAPPED image down to the requested size.
Nothing in the pipeline knows supersampling exists, so every feature
and both engines (FlameRenderer direct, HighResExporter tiled/CPU)
work unchanged; the routing thresholds see the doubled dimensions and
fall back exactly as for any big render.

Downsampling after the tonemap is the load-bearing choice: the tonemap
is logarithmic, so averaging histogram/accumulator densities instead
(mean-then-log vs log-then-mean) shifts brightness density-dependently
— the failure mode that sank the earlier attempt at this feature.

The 2x2 downsample kernel doubles as the firefly clamp: each output
pixel sees exactly its 4 source samples; any sample whose luminance
towers over the quad's median (>4x + offset) is scaled down before
averaging. Single lucky buckets die; legitimate bright detail spans
the quad, keeps the median high, and passes untouched (unit-tested).
Alpha is coverage and never clamped.

Plumbing: CLI `export --supersample`; export panel "2x Antialiasing"
checkbox (desktop; pixel budget /4, per-axis ceiling /2); both in-app
paths (sync GPU + background HighRes) and both headless CLI engines;
config.filter_radius doubles for the supersampled render (it's in
histogram pixels — everything else is world/relative units).

Documented trade-offs: ~4x render cost for full quality (4x buckets
share the iterations, dim regions want more), DoF's 32 px CoC cap
halves in FINAL pixels at 2x.
