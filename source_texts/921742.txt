When a parser populates ModelSystem.positions without corresponding ModelSystem.particle_states, the simulation structure payload becomes incomplete.
Of course downstream paths to identify particles, derive symbols/composition, classify atomistic systems, and convert the model system to ASE atoms are not possible.
But visualization of the system is still possible in principal. We could populate with some unknown bead type ... Do we want to do this in Simulation.normalize() or rather let the visualizer break as an indication that the parsed info is incomplete?

Good point, though having the visualizer crash is quite inelegant. Under the assumption that a missing particle_states almost always points back to a bug in the parser or the normalizer, so I'd log it as an error — something we actively follow up on, not quietly tolerate.
Then we overwrite particle_states with unknown particles of the same length as positions. This becomes the representation for everything downstream. It means that we can still search by composition, though it would be "unknown_x". Likewise, we can then compute symmetry ( purely geometrically) too, but might end up with a higher symmetry than a heterogeneous systems.

On a tangential note, you might want to extend the semantics of particle types to also cover:
Ghost atoms — basis-function centers with no nucleus or charge (BSSE counterpoise, embedding). No representation at the particle level today; only a passing type='PC' ("point charges / ghost basis centers") hint in basis_set.py. Needs: an explicit flag or subclass on the particle state (e.g. is_ghost) so a ghost is distinguishable from a real atom while still carrying a chemical_symbol for its basis.
Fractional / partial occupancy — a single crystallographic site occupied by a statistical mixture of elements (e.g. 50% Fe / 50% Ni), fractions summing to ≤ 1. Currently unrepresentable — a regression from the legacy Atoms schema, which had per-site concentrations plus free-form species/labels; occupation in the new schema is orbital-level only. Needs: a per-site (element, fraction) list (or an occupancy array) allowing one position to map to multiple species.
Virtual / massless sites — off-atom interaction sites in force fields (TIP4P M-site, dummy charge sites). Only implicit today (detected by mass ≈ 0 in MD utilities). Needs: an explicit is_virtual marker rather than inferring from mass.
Point charges — standalone electrostatic sites (QM/MM, explicit-solvent embedding). Only present as a basis-function field (point_charge), not as a particle. Needs: a first-class point-charge particle carrying charge without element identity.
Core–shell / Drude particles — polarizable-model shells attached to a core. No representation today. Needs: a way to link a shell particle to its parent core (and mark it as such).
Lone pairs / pseudo-atoms — model-specific off-nucleus sites. No explicit representation; only expressible via free-form labels. Needs: at minimum a documented labelling convention, or dedicated markers if we want them queryable.
