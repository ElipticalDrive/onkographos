Stacked on #92 (meshes; it adds the shared MeshObjectsLayer), which is stacked on #90. Retarget to main once those are merged.
Summary
Segmentations in the 3D view are now smoothed surfaces instead of a cloud of boundary voxels. A new control in the 3D bar (bottom right, "Segs · mesh / points") brings the points back. It defaults to mesh and is remembered with the layout.
Computed in the browser; the server is unchanged:
Reading: the segmentation level is read through idetik's chunk loader, the same contract ChannelViewSource uses. So it uses the same store, proxy/data_url, zarr v2/v3 and codecs as the 2D label layers.
It reads the finest level with at most 32M voxels.
A single-level store is coarsened by block maximum, so structures one voxel thin survive.
For 10521, a full-resolution store is 1.7–2.6 MB compressed. The same membrane meshed on a server would have been 6.4 MB gzipped.
Meshing: a worker meshes each value with vtk.js: a label, an instance, or a panoptic (label, instance) pair.
Marching cubes on the value's padded mask, so surfaces close at the volume edge.
Windowed-sinc smoothing, as 3D Slicer smooths segment surfaces.
Point normals, oriented outward by signed volume.
Above 1M triangles the volume is coarsened 2× and meshed again.
Bundle: vtk.js lives only in the worker chunk (149 kB). The main bundle grows by about 5 kB.
Colour: meshes are coloured like the 2D layers (hidden/solo IDs; panoptic objects / instances / both) and merged by colour, so draw calls stay bounded by the number of colours. Hide/solo regroups the meshes without computing them again.
Drawing: idetik's MeshRenderable through MeshObjectsLayer, from our own arrays in the layout idetik's GLB loader produces. Geometry isn't exported; this is noted in NOTICE.md with the other idetik contracts.
Lighting. idetik's one fixed mesh light leaves faces turned away from it at ambient brightness, so surfaces were flat and dark from below. Surfaces in 3D now share one lighting: a key light from above and a fill light from below. No direction falls below 0.45 brightness; facing up gives 0.86 and facing down 0.75.
The segmentation points use it directly.
For meshes it's folded into the normals passed to idetik's shader (ambient 0, diffuse 1). Each normal becomes the unit vector whose dot product with idetik's light is the brightness wanted, so positions are untouched.
Copick meshes get the same lighting.
Licences. vtk.js is BSD-3-Clause, so its notice has to ship with the minified worker. The build now writes THIRD_PARTY_LICENSES.md at the root of its output, with the licence text of every bundled package:
Vite's build.license covers the main bundle (33 packages).
client/workerLicenses.ts covers the workers, which Vite builds separately and leaves out: vtk.js, fast-deep-equal, gl-matrix and seedrandom.
The file ships in the wheel (copick_web/static/, checked with uv build) and in the nginx image.
Convention. Vertices are x/y/z in world units, with voxel i at i·spacing. Cross-check against 10521 run 35962's boundary-clean_0_valid-sample:
