Motivation
Reduce draw calls by aggregating per-chunk meshes into larger fixed-size region meshes so rendering scales with visible regions instead of chunks.
Introduce a region ownership/invalidation model so edits, uploads and unloads mark affected regions dirty and trigger region rebuilds.
Preserve functional parity with existing streaming/meshing pipeline while keeping streaming budgets and meshing flow intact.
Description
Added RegionCoord and mapping helpers with a 4x4 chunk footprint (src/voxel/RegionCoord.h) and wired the header into the build list in CMakeLists.txt.
Extended ChunkEntry to keep a per-chunk CPU mesh (cpuMesh) and a cpuMeshReady flag, and updated meshing/upload flow so worker threads push CPU mesh payloads and streaming stores them per-chunk (src/voxel/ChunkRegistry.*, src/core/WorkerPool.cpp, src/voxel/ChunkJobs.h).
Implemented region mesh management in ChunkStreaming by adding RegionMeshEntry, tracking regions_, marking regions dirty on chunk events, concatenating resident chunk CPU meshes into merged region GPU meshes, and exposing CollectDrawableRegions / DrawRegion APIs (src/voxel/ChunkStreaming.h / src/voxel/ChunkStreaming.cpp).
Updated edit/invalidation and rendering: BlockEdit now marks owning (and neighbor) regions dirty on edits, and world rendering switches from per-chunk draws to per-region draws with region-level frustum/distance culling (src/voxel/BlockEdit.cpp, src/app/AppMode.cpp).
Testing
Attempted to configure and build with cmake -S . -B build && cmake --build build -j4, but the build failed during FetchContent because the environment could not clone https://github.com/glfw/glfw.git (network/403), so runtime execution and rendering validation could not be performed.
No automated unit tests were present for this feature; changes were exercised via static code inspection and compilation attempt as described above.
