Two default changes the user asked for after trying the viewport on an iPhone, plus an arcball fix that turned up while measuring them.
Drag direction
I measured it with a test that drags, then projects a model point through the new camera to see which way it moves on screen.
Before, in every rotation style:
Horizontal: dragging right moved the camera right, so the model turned against the finger. The router negated X.
Vertical: dragging up turned the model with the finger.
Arcball: it composed its screen-space axis in world space. From the front view, a horizontal drag rolled the picture instead of turning the model. From an isometric view it turned the model diagonally.
Navigation cube: the reverse mix (horizontal with the finger, vertical against it).
After:
With the default, GestureConfiguration.dragRotation = .rotateObject, both axes turn the model with the finger in turntable, arcball and first-person. Dragging right carries the near side right; dragging up carries it up.
.orbitCamera reverses both axes.
invertOrbitHorizontal/invertOrbitVertical still flip single axes on top, for source compatibility.
The viewport drag (iOS one finger or two-finger-as-orbit; macOS primary drag), its momentum and the navigation cube all use one signed path (orbitDrag/endOrbitDrag).
Arcball now composes in camera space.
Presets: all presets use .rotateObject. Blender's and Fusion 360's orbit carry the near side with the pointer on both axes, so I picked the same for both.
First-person: in this library first-person still places the camera at pivot + distance, so it turns about the pivot like the other styles. The convention applies unchanged: .rotateObject gives "drag the scene", and .orbitCamera gives mouse-look. This is documented.
X-ray
DisplayMode.defaultXRayOpacity goes from 0.4 to 0.2. Live and offscreen rendering both derive from it. The demo slider binds to the controller, so it needed no change. The x-ray render test now compares green's share of red rather than absolute levels, because the whole centre is dimmer at 0.2.
Tests
New DragRotationTests: 4 styles × 4 views × both conventions, momentum direction, invert flags, presets, two-finger and cube parity, and the arcball no-roll check.
Full suite: 514 tests pass. swift-format/swiftlint --strict are clean on touched files, and so is the style-manifest check.
CHANGELOG
Changed default: one-finger / mouse drag now rotates the object on both axes. A new GestureConfiguration.dragRotation: DragRotationConvention (.rotateObject, the default, or .orbitCamera) sets the direction. Previously the horizontal drag orbited the camera, so the model turned against the finger, while the vertical drag turned the model. invertOrbitHorizontal/invertOrbitVertical remain per-axis flips on top. Apps that set invertOrbitHorizontal = true to get the grab feel should remove it. Momentum and the navigation cube follow the same convention; the cube's vertical drag direction changes.
Changed default: DisplayMode.defaultXRayOpacity is now 0.2 (was 0.4), for live (ViewportConfiguration/ViewportController.xrayOpacity) and offscreen (OffscreenRenderOptions.xrayOpacity) rendering.
Fixed: an arcball drag turned the model about a world axis instead of a screen axis. From the front view a horizontal drag rolled the view.
