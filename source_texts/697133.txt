Description
Adds an optional output.compressor to the gridded output, next to chunking and dtype, to choose the codec of the data array. The value is a numcodecs codec configuration, resolved with numcodecs.get_codec:
```
output:
  compressor: {id: blosc, cname: zstd, clevel: 3, shuffle: 2}
```
What problem does this change solve?
New feature. The data array is always created with Blosc lz4, and choosing another codec currently needs a code change. When compressor is not set, the Blosc codec that #806 passes explicitly is kept, so existing recipes produce the same datasets as before. The id is resolved by numcodecs, so codecs from other packages registered through the numcodecs.codecs entry point work too, which is the main use case: a codec tailored to a dataset, for example lossy quantization with per-variable settings. The configuration is validated when the recipe is parsed, so an unknown codec or option fails before any data is loaded.
The option is only accepted with output.format: zarr2. With zarr-python 3, Zarr format 3 arrays take zarr v3 codecs rather than numcodecs codecs, so supporting zarr3 would need a separate configuration; this can follow once format 3 output is no longer experimental.
Changes: GriddedOutput.compressor and get_compressor() in create/recipe/output.py, the data array creation in create/gridded/creator.py, a test in tests/create/test_output.py, and the recipe docs (docs/building/syntax.yaml, docs/overview.rst, docs/building/zarr-format.rst).
What issue or task does this change relate to?
Closes #815. Related to #792 and #806: it makes the codec that #806 passes explicitly selectable from the recipe, and builds on the zarr_format option from #786.
Additional notes
filters could be exposed the same way, and the trajectories layout could get the same option; both are left out to keep this change small.

Author
The option is now output.compressors, a list of bytes-to-bytes codecs written as in Zarr format 3 metadata ({name: blosc, configuration: {cname: zstd, clevel: 3, shuffle: bitshuffle}}), passed to zarr as given for format: zarr3. For zarr2 the single codec is translated to numcodecs: blosc, zstd and gzip with the zarr-python 3 defaults, and numcodecs.<id> through numcodecs.get_codec, so codecs from other packages still work; several codecs or a codec without a numcodecs equivalent are rejected when the recipe is parsed. The mapping is in a new compat/codecs.py, which the copy command now uses too instead of its own translation. Tests cover both formats, run with zarr-python 2 and 3, and the docs are updated.
