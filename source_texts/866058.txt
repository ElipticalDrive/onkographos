axiolid/kernel#325: the reference compiler sizes a BoundedHalfSpace's depth at 2× the boundary's extent (axiolid-construct 0.3.18 half_space.rs:97-108, axiolid-mesh-compile 0.3.26 compiler.rs:1043), not by the subject. So an IfcPolygonalBoundedHalfSpace with a small boundary over a tall subject is cut too little, silently. This affects the along/against cases that ifc-geometry lowers to BoundedHalfSpace today (lower/halfspace.rs, build_polygonal). The fix is kernel-side; nothing in the bridge sizes the clip (ADR 0004).
Done when:
the kernel release with openbim-ifc-capi: ship a pkg-config file in the install tree and release archives #325 is adopted (compile-feature floor raised);
a test pins a small polygonal boundary clipping a subject taller than 2× the boundary's extent to the analytic volume, in the mesh and exact paths.
Found while working on #515.
