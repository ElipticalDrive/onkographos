Summary
Explore a statistics-aware auto-ranging system for WAVEZ volume fields so scientific channels with very different numeric scales are immediately visible without manually guessing color and opacity ranges.
This idea comes from real owner testing of WAVEZ volume rendering where channels such as:
density_excess
pressure_excess
radial_velocity
divergence
speed
vorticity
often occupy radically different ranges.
Some late-time channels may be on the order of 1e-3, 1e-6, or smaller while the UI still uses a generic 0 → 1 color/opacity range. This can make scientifically valid fields appear invisible, nearly black, or visually misleading depending on the colormap.
WVZ1 already stores field statistics for volume arrays, so WAVEZ should investigate using those authoritative statistics to provide useful scientific defaults.
Goal
Make volume-field inspection substantially easier while preserving raw scientific values.
The user should be able to select a channel and get a sensible initial visualization without playing “which combination of six zeros makes the field visible?”
Do not modify the underlying data.
Proposed auto-range modes
Explore at least the following:
Per-frame auto range
Derive the useful display range from the currently visible sample's stored/decoded statistics.
Useful for channels whose amplitudes evolve strongly over time.
Global/capture auto range
Derive a stable range over the complete object/channel timeline, where practical.
Useful when comparing absolute amplitudes between frames without the color scale changing continuously.
Signed symmetric-about-zero mode
For physically signed fields such as:
density perturbation / density excess;
pressure perturbation;
radial velocity;
divergence;
signed velocity/current-like channels.
Use an authoritative magnitude estimate and map approximately:
[-M, +M]
rather than a default positive-only range.
This should work naturally with appropriate diverging colormaps.
Magnitude auto range
For nonnegative magnitude fields such as:
speed;
vorticity magnitude;
density;
scalar concentration;
other norm/magnitude channels.
Map:
0 → useful upper value
where the upper value may be based on max or a robust percentile/statistic to avoid one extreme voxel washing out the entire volume.
Robust statistics
Investigate which existing WVZ1 field statistics can safely drive these modes.
Potential inputs include:
min/max;
finite counts;
mean/RMS where available;
percentiles/histogram-derived estimates if already stored or inexpensive to derive;
absolute maximum for signed symmetric ranges.
Prefer metadata/statistics already stored in WVZ1 rather than rescanning large decoded volumes merely to establish the initial transfer function.
If the current WVZ1 statistics are insufficient for robust percentiles, document what additional statistics would be useful before changing the format.
Do not change WVZ1 casually as part of this exploratory issue.
Opacity / transfer-function interaction
Color auto-ranging alone may not be enough.
Investigate whether the same statistics should help initialize:
zero-opacity threshold;
full-opacity threshold;
opacity strength;
signed/magnitude opacity mapping.
For weak late-time fields, a useful color range with an inappropriate opacity range can still make the field effectively invisible.
Any automatic opacity behavior must remain inspectable and user-overridable.
UX expectations
Potential presentation:
Range policy
Automatic per frame
Automatic global
Symmetric about zero
Manual
or an equivalent design consistent with the current WAVEZ field controls.
Important:
users must always be able to switch to Manual;
current manual min/max behavior remains available;
auto-derived values should be visible in the UI so the user can understand the active scale;
channel switching should select an appropriate scientific range policy without silently changing scientific data;
avoid visually unstable/flickering ranges during playback.
Channel semantics
Do not guess signed-vs-magnitude semantics solely from channel names if a stronger source of truth exists.
Investigate whether channel metadata/descriptors can carry or already carry useful semantics such as:
signed;
magnitude/nonnegative;
phase/cyclic;
normalized;
categorical.
If semantics are absent, define a safe fallback policy rather than hard-coding WAVEZ-specific names.
Acceptance / research questions
This issue is initially an Idea / design investigation, not an instruction to immediately implement a large renderer rewrite.
Answer:
What volume statistics are already available in WVZ1 and the current reader/viewer path?
Can per-frame auto-range be implemented without extra full-volume scans?
Can a stable global range be computed cheaply from stored statistics?
What is the best policy for signed fields?
What robust upper bound should magnitude fields use?
How should opacity defaults interact with color range?
How can WAVEZ avoid temporal flicker when per-frame ranges change?
Should channel semantic metadata be extended?
What behavior should occur for nearly constant fields, zero fields, NaN/Inf exclusions, or extreme outliers?
What is the smallest coherent implementation path?
Validation direction for a future implementation
Use representative channels spanning very different scales:
signed perturbation around zero;
small velocity/divergence values;
very small vorticity magnitudes;
ordinary positive density/scalar fields;
nearly uniform fields;
one field containing isolated extreme outliers.
Check:
immediate visibility after channel selection;
scientifically correct sign/color mapping;
stable playback;
useful opacity;
manual override;
no modification of source values;
consistent behavior across renderers.
Scope boundary
Do not:
normalize or rewrite scientific arrays;
force every channel into 0..1;
infer physical meaning that is not declared;
hide the actual numerical range from the user;
silently discard outliers without documenting the policy;
change WVZ1 format unless the investigation demonstrates that existing statistics are insufficient.
Document findings and propose the smallest implementation plan before coding a broad solution.
Do not merge or enable auto-merge automatically.
