Meshes currently export flat gray — the README notes color baking isn't supported on MPS. This adds color, all portable (no CUDA rasterizer), in three selectable modes.
Kids' table reconstruction: white flower-top + natural-wood legs (spatially correct vs the input photo), and the baked UV atlas.
What & why
The mesh decoder already predicts per-vertex color (use_color: true), but to_glb dropped it: postprocess_mesh re-indexes vertices during decimation/hole-fill, and the only branch that attached colors required post-processing to be off — so the exported mesh had visual=None.
Mode
Flag
Color source
Per-vertex color (default)
(none)
mesh decoder RGB, transferred through the postprocess remap by KD-tree (nearest original vertex)
UV bake from vertex color
--bake --bake-source vertex
vertex colors → texture atlas
UV bake from Gaussian (default source)
--bake
decode the Gaussian appearance rep; each texel's 3D surface point takes the nearest Gaussian's SH-DC color
Both bake paths are pure-Python/Metal: xatlas UV unwrap + a small barycentric software rasterizer + cv2 Telea seam inpaint. No nvdiffrast, no gsplat, no diff_gaussian_rasterization.
Usage
```
# per-vertex color (default; fast, full-res geometry)
python main.py --mesh -i <image> --mask-dir <dir> --mask-index <n> -o out.glb

# baked UV texture from the Gaussian appearance field (higher fidelity)
python main.py --mesh -i <image> --mask-dir <dir> --mask-index <n> --bake -o out.glb

# baked UV texture from mesh vertex colors (no Gaussian decode)
python main.py --mesh -i <image> --mask-dir <dir> --mask-index <n> --bake --bake-source vertex -o out.glb
```
New flags: --bake, --bake-source {gaussian,vertex} (default gaussian), --texture-size (default 2048). --simplify now defaults to 0.9 when --bake (the pure-Python rasterizer is slow on full-res meshes) and 0.0 otherwise; pass an explicit value to override.
Enabling fixes (CUDA path preserved)
Gaussian decode is forced to fp32 (convert_to_fp32) — the fp16 config trips a hard Metal matmul assertion — and runs on MPS.
A few .cuda() hardcodes in the Gaussian representation became .to(self.device), and decoder_gs constructs the Gaussian on the SLAT's device. On CUDA machines self.device is cuda, so behavior there is unchanged.
Design note
This is an MPS-native albedo bake, not a port of a multi-view Gaussian-render + texture-optimization pipeline (which would need a Metal Gaussian rasterizer). The nearest-neighbor transfer reuses the same UV rasterizer as the vertex bake, uses the Gaussian's denser color field (~300–500K Gaussians vs ~180K mesh vertices), and is fully verifiable on Apple Silicon.
Testing
tests/test_texturing.py — 10 tests, no model weights, no CUDA: color resample (identity + nearest), UV rasterizer partition-of-unity, portable bake color correctness, to_glb color attach.
End-to-end on MPS: per-vertex-colored GLB, and gaussian-baked GLB with a real baseColorTexture (tabletop bakes white, legs bake wood-brown — the transfer is frame-aligned, not a uniform tint).
Changes are additive and gated: the default output is now vertex-colored (was gray); the existing CUDA render+bake path in to_glb is untouched (reached via bake_backend="render"). Known limitation: the UV rasterizer is pure-Python per-face (hence the --simplify 0.9 bake default); a vectorized/Metal rasterizer is a natural follow-up.

Meshes previously exported flat gray. This adds color, all portable (no CUDA
rasterizer), in three selectable modes:

- Default: carry the mesh decoder's per-vertex RGB (use_color:true) through the
  postprocess vertex remap via KD-tree position transfer, attached
  unconditionally. Previously these colors were decoded then dropped.
- --bake --bake-source vertex: a pure-numpy barycentric UV rasterizer bakes
  vertex colors into a texture atlas (xatlas UVs, cv2 seam inpaint).
- --bake (default source gaussian): decode the Gaussian appearance rep and bake
  by 3D nearest-neighbor — each texel's surface point takes the nearest
  Gaussian's SH-DC color. Denser than vertex bake; no Gaussian renderer.

Enabling fixes (upstream CUDA path preserved): Gaussian decode forced to fp32
(the fp16 config trips a Metal matmul assertion) and run on MPS; .cuda()
hardcodes in the Gaussian representation made device-agnostic (.to(self.device)),
which is identical to .cuda() on CUDA machines.

New CLI: --bake, --bake-source {gaussian,vertex}, --texture-size. --simplify
defaults to 0.9 when baking (the pure-Python rasterizer is slow on full-res
meshes) and 0.0 otherwise; pass an explicit value to override.

Tests: tests/test_texturing.py (10 tests, no model/CUDA) covers the color
resample, UV rasterizer, portable bake, and to_glb color attach. Verified
end-to-end on MPS (per-vertex color + gaussian-baked GLB with a real texture).
