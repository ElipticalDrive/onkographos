Closes #1381
What and why
The DDS parser reads volume textures, but no renderer path loaded one. This PR uploads volumes as Metal 3D textures and binds the one vanilla volume where the data uses it.
Where the game uses the noise volume
A byte search of every vanilla archive (meshes decompressed), every plugin, and SkyrimSE.exe found one consumer:
meshes\dlc02\effects\mq03skaalvilliagebarrier02.nif and ...03.nif name textures\effects\NoiseVolume.dds as the BSEffectShaderProperty source of the shape CloudsReversed01:0, a layer of the Skaal village storm barrier.
No vanilla record places either mesh. The placed barrier MQ03SkaalVillageBarrier01 uses mq03skaalvilliagebarrier.nif, which does not use the volume.
The game program does not name the file.
So the real game never shows it. How the game samples a 3D texture in a 2D effect slot is unconfirmed; #1656 tracks it.
Changes
TextureUsage.volume: 3D upload with every level and slice; a broken volume gets a mid-grey 1 x 1 x 1 volume placeholder.
TextureUsage.effectSource: the texture library returns the volume for an effect shape whose source file is a volume. Every 2D consumer (particles, lit meshes, sky) keeps the 2D placeholder.
The static mesh fragment samples a volume source from its own slot (25) at the shape's UV and depth 0.5. A grey volume fills the slot for every other draw.
openskycli dds <path> --out <folder> [--level <n>]: uploads the texture as an effect source, prints the uploaded type, size, and levels, and writes each slice as a PNG. tools/probe.sh checks the noise volume.
Docs: docs/formats/dds.md "Volume textures", docs/formats/nif-materials.md, docs/tools/cli.md.
Specs: Microsoft "DDS file layout for textures" (volume textures), DDS_HEADER, DDS_HEADER_DXT10; NifTools nif.xml for BSEffectShaderProperty.
Acceptance gate
Real data: openskycli dds 'textures\effects\noisevolume.dds' --out ... prints uploaded: 3D 128x128x128, 8 levels, ... placeholder: no, and writes 128 slice PNGs that show the noise. Local: .logs/issue-1381/slices-top/.
Visual: openskycli preview --mesh 'meshes\dlc02\effects\mq03skaalvilliagebarrier02.nif', before (main) .logs/issue-1381/before/ and after .logs/issue-1381/after/. The two match byte for byte. The reason is in the data: the shape's vertex colours are black over almost all of it, and its colour is vertex colour x texture x 0.196, so the texture does not reach the frame; an L8 texel has alpha 1, like the placeholder. Temporary shader edits (not committed) showed that every pixel of the shape takes the volume path (.logs/issue-1381/debug-red/), that the volume sample varies across it (debug-alpha/, blue), and that its vertex colours are near zero (debug-colour/, red). Captures are game content and are not committed.
Unit tests with synthetic L8 volumes: TextureVolumeTests (upload of every level and slice, the volume placeholder, effect-source routing, the material flag) and DDSVolumeTests.declaresVolumeReadsOnlyTheHeaders.
Preview panel: the app's Preview panel no longer exists (removed with the developer view). openskycli dds --out and openskycli preview take its place.
