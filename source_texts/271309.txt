Summary
Background
This PR fixes audit finding BVH-10 [MINOR] from PORTING.md. PackedBVH had four constructors that build from a primitive list, and the argument types alone decided which one ran:
Trailing argument
Build it selected
size_t (plus an SFC::X{} tag value to pick the curve, since a constructor template cannot take explicit template arguments)
SFC
partitioner
top-down
ClusterSpec
ClusterSAH
none
default top-down
So PackedBVH(pool, prims, K) and PackedBVH(pool, prims, BinnedSAHPartitioner<...>) were completely different builds that read alike. Separately, TreeBVH::pack()/packWith() returned a shared_ptr, even though PackedBVH is a trivially copyable handle into its pool. The mesh SDFs only ever dereferenced and copied it.
Solution
Named static builds: each one returns the PackedBVH by value.
buildBottomUp<S = SFC::Morton>(pool, prims, targetLeafSize) names the curve as a template argument; there is no tag value.
buildTopDown(pool, prims, partitioner[, stopCrit]).
buildClusterSAH(pool, prims, spec).
PackedBVH::build(pool, prims, Construction, options = defaultConstructionOptions()): calls the matching named build for every BVH::Construction value. It checks the chosen method's leaf setting and aborts on an unknown value. BVHUnion/BVHSmoothUnion now call it, so their own copy of that dispatch (CSGDetail::buildBoundedBVH) is gone.
defaultConstructionOptions(): {K - 1, K, ClusterSpec{}}. A top-down leaf therefore stops where DefaultLeafPredicate stops.
pack()/packWith(): return PackedBVH<T, P, K>/PackedBVH<T, Q, K> by value.
Unchanged: the constructors that pack a TreeBVH, the adopt constructor and the layout constructor keep their signatures.
Callers: tests, the BuildBVH example, the mesh SDFs and the BVH unions all moved to the new names. Every tree they build is unchanged.
New test: for every Construction value, build() makes the same nodes as the named build it should call. With no options it matches buildTopDown() with the default leaf predicate, and a zero setting for the chosen method aborts.
Docs:
ImplemBVH.rst: the direct-construction section, the presets section (which now shows build()), and the pool and index notes.
ExampleBuildBVH.rst, the BuildBVH README and its comments, and CLAUDE.md's header-layout note.
The TestingLocally.rst row for the new test.
PORTING.md: the BVH-10 bullet is removed, and the "What is not" row and the index note are updated.
Test titles that said "constructor" now name the build function.
Side-effects
Source-incompatible for direct PackedBVH builders:
PackedBVH(pool, prims, …) becomes PackedBVH::buildX(pool, prims, …) or PackedBVH::build(…).
tree.pack(pool)-> becomes tree.pack(pool)., and *tree.pack(pool) becomes tree.pack(pool).
Nothing in Integrations/ used either.
Abort message: an unknown Construction passed to a BVH union now aborts with PackedBVH: unknown BVH::Construction value, the function that checks it, instead of BVHUnion: …. TestCSG expects the new text.
Rebased onto dev after PackedBVH: store every box once (BVH-8) #194, Performance harness: time builds as a first build; visible acceptance; no receipt with skipped cases (#212) #219 and TreeBVH: fold interior boxes with merged(), no vector per union (BVH-11, host part) #195 (acdd07f): the builders now return PackedBVH(a_pool, nodes, boxes, prims) (PackedBVH: store every box once (BVH-8) #194's boxes with this PR's named builds); PackedBVH: store every box once (BVH-8) #194's box-storage test builds through Packed::buildBottomUp (the same tree); PORTING.md drops BVH-8, BVH-10 and BVH-11 (all fixed); the ImplemBVH.rst and TestBVH-row conflicts keep both PRs' text.
Alternative solutions
Only build(Construction), with no named builds: this would leave no way to pass a custom partitioner or a curve outside the enum without going through TreeBVH.
Keep the constructors, make them private, and forward: this would keep the tag value internally. Named static functions say what each call does at the call site.
Tested locally:
the debug preset passes 493/493;
TestBVH and TestCSG also pass with both precisions;
the BuildBVH example runs;
the HIP device compile of TestBVH and TestCSG passes;
Doxygen and the pre-commit hooks pass;
the Sphinx HTML build is clean except for the 8 TikZ figures, which need pdflatex (not installed in this environment; CI renders them).

What I checked
Dispatch in PackedBVH::build (Source/EBGeometry_BVHBuildImplem.hpp:~322):
All 7 Construction values map to the same builds as the removed CSGDetail::buildBoundedBVH.
The leaf-setting check happens first, so a zero setting for the chosen method aborts before any work.
An unknown value reaches the EBGEOMETRY_REQUIRE(false, …) after the switch. The trailing return only keeps the compiler quiet.
buildBottomUp<SFC::Morton>(…) needs no template keyword here, because it is a member of the current instantiation.
Move semantics: each case moves a_primsAndBVs once and returns straight away, so nothing is used after a move.
pack()/packWith() by value: PackedBVH is a trivially copyable handle, so returning it by value is fine. The ->pack(a_pool) calls in buildBVH stay because buildDCELTreeBVH and buildTriTreeBVH still return shared_ptr<TreeBVH>.
Stale references: a grep over Source, the Sphinx sources, README, Examples, Integrations, Tests, CLAUDE.md and PORTING.md found no leftover SFC::X{} tag values, pack(...)->, buildBoundedBVH or "SFC-build constructor" wording.
InstantiateAll.cpp: the PackedBVH explicit instantiations (lines 91–92) are whole-class, so the new static members are covered for both precisions. No new class was added.
Docs: the Doxygen @param/@return comments were updated alongside the signatures, and the parameter order is now consistent (a_pool first).
Nits (non-blocking)
Duplicated defaults. defaultConstructionOptions() is now defined three times with the same body: PackedBVH (EBGeometry_PackedBVH.hpp:~282), BVHUnion and BVHSmoothUnion (EBGeometry_BVHUnion.hpp:~149 and ~441). Since BVHUnion now calls PackedBVH::build, it could forward to PackedBVH<…>::defaultConstructionOptions(). That way the "top-down leaf stops where DefaultLeafPredicate stops" rule lives in one place.
K == 1 default. K - 1 is 0 for K == 1, so build() with default options would abort for any top-down method. This is probably unreachable, since K >= 2 is presumably already required for a K-ary tree. If it is not enforced, a static_assert(K >= 2) would make the failure clear.
Merge note
You already noted the overlap with #194 (BVH-8). I agree the resolution is small: the builds now end in return PackedBVH(a_pool, nodes, prims).
