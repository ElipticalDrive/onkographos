Adds the integer topology prerequisite for tiled terrain preparation: two fixed q = 32 triangle trees, ordered source-grid corners, checked tree/node access and leaf-only quad lookup. Allocation is bounded and fallible; callers cannot mutate the stored trees.
Review follow-up:
A named fixed grid dimension ties the root coordinates and node/leaf bounds together. This remains a 32-by-32-quad topology, with no source input or generic dimension parameter; source admission belongs to a later caller.
Each constructor still builds its own immutable hierarchy. The requested triangle payload is 49,128 bytes (4,094 records of 12 bytes), excluding vector/allocator overhead and any excess capacity the allocator may grant. No measured bottleneck justifies a global cache or a replacement computed-corner API in this prerequisite.
Midpoint exactness is explicit: the internal P/Q endpoint sums are even, and coordinates stay within the fixed grid. Development assertions and a new all-depth geometry/parity regression guard the invariant; the established ordered construction is preserved.
Construction remains fallible and closed. An empty derived Default would violate the valid-tree invariant; allocating Clone/Default would add an infallible allocation path. No current caller needs Debug or Clone, so these optional derives remain absent. Unwrapping construction errors requires the error type's Debug, which it already provides.
Clockwise winding is described in source XY with X right and Y up, before world scaling or output-basis conversion. The leaf determinant is negative one (signed twice-area); a screen-space Y-down convention reverses that orientation.
Each tree stores 2,047 nodes, including 1,024 leaf triangles. Both trees store 4,094 all-level records; their 2,048 leaf triangles partition 1,024 quads. These are topology counts, not a claim that all stored levels are emitted together.
Validation: 282 all-target tests passed, 35 ignored; four hierarchy integration tests passed. A real compiled internal-only corner fault passed the original three tests and failed the new all-depth regression, followed by exact restoration. Independent acceptance uses a separately derived full-node oracle and a distinct compiled fault. Ordinary Clippy/documentation, scoped formatting, privacy and whitespace checks passed with existing unrelated warnings retained.
This helper does not admit source data, prepare heights, refine triangles, link neighbors, emit GLB geometry or activate rendering/collision routes. Parser pins and common GLB contracts remain unchanged. Closes #102; preparation fidelity remains tracked in #100 within #51. Human review is required before merging to main.

Acceptance test
Rebased onto current origin/main: cargo test --all-targets gives 281 passed, 0 failed, 35 ignored. The reviewer also traced the node numbering, midpoint arithmetic and leaf-quad lookup by hand against the first test's expected values and found no correctness bug.
Findings
Constants not tied to a quad count. The tree is built from fixed 32x32 constants (FIRST_LEAF, NODE_END, roots) with no link to a source tile dimension, so Q32Hierarchy has no guard against reuse with other dimensions.
Rebuilt per call. try_new heap-allocates ~98 KB and reconstructs the same 4094-triangle tree on every call; a static/lazy instance or computing corners from the node id would avoid the allocation and the TryReserveError path.
Midpoints use truncating (p+q)/2 in u16 with no assertion that edges are even-length. Exact today for depths 0-9, but a constant change would corrupt the tree silently.
Usability: no Debug/Clone/Default derives, so tests rely on TryReserveError: Debug to unwrap.
Winding convention ("clockwise", signed area -1) is asserted in tests but the axis convention (y-up) is not stated; a y-down consumer would read it as the opposite.
Docs: the plan cites "4094 triangles", but a tree has 2047 nodes (2048 leaves counted as 2 triangles for each of 1024 quads); clarify to avoid conflating node and triangle counts.
