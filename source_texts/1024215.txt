What happened?
The Sample.computeQuantile method wrongly interpolates in the data.
How to reproduce the issue?
The script:
```
# %%
import openturns as ot

# %%
SAMPLE = ot.Sample.BuildFromPoint([5, 3, 6, -1, 3])

# %%
SAMPLE.computeQuantile(0.8)[0]  # Exact = 5.0
```
prints:
```
5.5
```
but the exact value is 5.0.
The full script is:
```
# %%
import openturns as ot
import openturns.viewer as otv

# %%
print(ot.__version__)


# %%
SAMPLE = ot.Sample.BuildFromPoint([5, 3, 6, -1, 3])

# %%
x = SAMPLE.computeQuantile(0.8)[0]  # Exact = 5.0
print(x)

# %%
# To get 5.0
epsilon = 1.0e-5
alpha = 4 / SAMPLE.getSize() + epsilon
print(f"alpha = {alpha}")
SAMPLE.computeQuantile(alpha)[0]  # 5.0

# %%
ud = ot.UserDefined(SAMPLE)
# Add points of continuity of the sample CDF
graph = ud.drawCDF()
graph.setLegends(["Sample CDF"])
quantiles_ordered = SAMPLE.sort()
sample_cdf = ot.Sample.BuildFromPoint([ud.computeCDF(x) for x in quantiles_ordered])
cloud = ot.Cloud(quantiles_ordered, sample_cdf)
cloud.setPointStyle("o")
cloud.setLegend("Data")
graph.add(cloud)
otv.View(graph)

# %%
```

Additional Context
The sample CDF is defined by (see 1 eq. 4.3 page 78):
$$
\widehat{F}(x) = \frac{n_x}{ n}
$$
for any x, where $n_x \in \textbf{N}$ is the number of observations lower or equal to x:
$$
n_x = \text{card} \left( \lbrace i | x_i \leq x, i \in {1, ..., n} \rbrace \right).
$$
The next figure is the empirical CDF. Let us analyze this plot in detail.
There are n = 5 observations in the sample. Hence, all probability shifts are multiples of 1 / 5 = 0.2
We see that this CDF has a jump at x = -1, with a probability shift equal to 0.2. This is because x = -1 is the minimum in the sample and this observation is unique.
There is another CDF jump at x = 3, with a probability shift equal to +0.4, which makes the CDF equal to 0.6. This is because -3 appears 2 times in the sample.
The jump of the CDF at x = 5 is because this observation is the 3d observation in the sample and this observation is unique. The jump is then equal to 0.2 and the value of the CDF is equal to 0.2 + 2 x 0.2 + 0.2 = 0.8.
The final jum of the CDF is at x = 6, which is the largest observation in the sample (it is unique). This makes the sample CDF go up to 1.
Figure 1. The empirical Cumulative Distribution Function of the sample {-1, 3, 3, 5, 6}.
The quantile of probability level equal to 0.8 + ε is equal to 5. But OpenTURNS returns 5.5, which is wrong.

@MarieTemple-Boyer: This might explain why you felt the need to implement your own version of computeQuantile() 😃
Here is a workaround, based on a script provided by @MarieTemple-Boyer.
```
import math

def quantile(sample, alpha):
    """Compute the empirical alpha-quantile of the sample.

    Parameters
    ----------
    sample : ot.Sample
        A 1-dimensional sample of data.
    alpha : float
        The quantile level, must be in the interval [0, 1].

    Returns
    -------
    float
        The empirical alpha-quantile of the sample.

    Raises
    ------
    AssertionError
        If the sample is not 1-dimensional.

    Examples
    --------
    >>> quantile(sample, 0.8)[0]
    5.0
    >>> quantile(sample, 0.0)[0]
    -1.0
    >>> quantile(sample, 1.0)[0]
    6.0
    """
    if sample.getDimension() != 1:
        raise ValueError(
            f"The sample must have dimension 1, "
            f"but the current dimension is {sample.getDimension()}"
        )
    sample_sorted = sample.sortAccordingToAComponent(0)
    n = sample.getSize()
    index = max(0, math.ceil(n * alpha - 1))
    return sample_sorted[index]
```
