Ports the PPLL (per-pixel linked list) + bounded depth-peeling order-independent transparency runtime from the archive onto the interleaved-alpha baseline. GL-only for now; the host-side GL plumbing is confined to named methods so it can be swapped for a Vulkan backend later.
What this adds
Two selectable alpha-sorting methods (in addition to the existing legacy/interleaved path), chosen via RenderAlphaSortMethod (Preferences → Graphics → Rendering 2):
0 — Legacy sorted (default; unchanged — the interleaved path stays byte-identical)
1 — PPLL: per-pixel linked lists. R32UI per-pixel head image + std430 SSBO node pool (packed half-float RG/BA + depth + next) + atomic counter. GL 4.4+ (Windows/Linux). Order-correct alpha independent of CPU sort order.
2 — Depth peeling: bounded multi-pass, GL 4.1+, with a per-frame CPU submission budget and a legacy-sorted tail so nothing disappears.
Both are restricted to the main post-water world view; mirrors/hero probes, cube snapshots, HUDs, impostors, and pre-water alpha keep the legacy path. Unsupported methods fall back to legacy without changing the saved setting.
Implementation
pipeline.cpp/h: OIT buffer management (allocateAlphaOITBuffers/beginAlphaOITCapture/compositeAlphaOIT, depth-peel target ping-pong), hooked into allocateScreenBufferInternal/releaseScreenBuffers. All direct-GL calls are isolated in the named OIT methods.
lldrawpoolalpha.cpp/h: EAlphaOITPhase layered orthogonally onto the existing EAlphaStream model — forwardRender(stream, oit_phase); renderPostDeferred dispatches PPLL → depth-peel → interleaved → legacy. Residual/particle filtering and glow preservation in the residual pass.
Shaders: ALPHA_OIT/ALPHA_DEPTH_PEEL defines gated on GL version in llshadermgr; new deferred/alphaOITResolveF.glsl resolve pass; capture blocks in fullbrightF/alphaF/pbralphaF/materialF.
Settings: 9 new RenderAlpha* settings (PPLL/depth-peel params + availability flags + stats debug).
UI: Preferences → Graphics split into "Rendering 1" / "Rendering 2"; Rendering 2 carries the alpha-sort radio + PPLL/depth-peel parameter controls (en + it).
Also fixed (uncovered during validation — NOT caused by PPLL)
viewer_manifest.py failed to stage each theme's textures.xml (the name→file map at textures/ root) for both build-tree and packaged runs. Texture-mapping themes (e.g. firestorm/ctrlaltstudio) therefore couldn't resolve custom textures/link colors → magenta chat/toast/name-tag backgrounds and unskinned hyperlinks. Fixed for both paths. This same bug exists on master and should be offered upstream separately.
Validation
Builds clean: 0 errors / 0 warnings (ReleaseFS_open).
In-world: legacy, PPLL, and depth-peel all render the 3D scene and UI correctly.
