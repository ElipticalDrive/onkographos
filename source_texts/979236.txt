Part of the "backend duplication → common/" item. The omp, mpi and cuda backends each carried the same bitwise Morton neighbour computation (get_neighbor_code), and the +boundary fix (520dad4) had to be applied to all three copies. morton::neighbor_code<DIM> now lives once in common/core.hpp as an AMR_HD (host/device) function:
omp and mpi call it from their thin get_neighbor_code wrappers;
cuda calls it directly from its kernels.
The three copies were equivalent. The only textual difference was that cuda used MASK2_Y where the others used its literal, 0xAAAA….
Review fixes
The sentinel cannot collide. max_level_limit(dim) is 31 in 2D and 21 in 3D, so every cell code stays below 2^63 and UINT64_MAX is never a cell. The 2D limit was 32 before, where a corner cell's code was UINT64_MAX.
Out-of-range input gets the sentinel: a level outside [0, max_level] or a tree deeper than the limit. LinearTree and DistributedTree throw invalid_argument outside [0, limit], and cuda's validate_config uses the same limit.
The axis is walked as kAxis << k, with no per-axis special case. The clang-format of core.hpp is its own style: commit.
Adversarial verification
(a) Oracle, independent of the bit tricks: decode the cell, move one cell along each axis, check the domain, re-encode.
Exhaustive: every aligned cell of every level of a 2⁵×2⁵ (2D) and a 2³×2³×2³ (3D) domain, in all 3^d directions.
Random: 20 000 cells at the deepest supported trees (31 levels in 2D, 21 in 3D), including both boundaries and level 0.
"Rejects what it cannot answer": the deepest corner's neighbour is not the sentinel, and out-of-range levels and trees are.
(b) The existing suites are unchanged: cross-backend parity, the neighbour and boundary cases, and the active-front balance parity. CI runs them (gcc-14/clang-18, Debug and Release, MPI, CUDA compile).
Local verification (2026-09-30, after the report benchmark)
Debug build with ASan/UBSan, MPI on: ctest passes (omp, mpi, simplex suites), with UBSan set to halt on error.
(c) Mutations, each rebuilt and run against the [neighbor] tests. All 6 are caught:
the level-0 guard removed;
the +domain boundary test removed;
the −domain boundary test removed;
the level/limit range check dropped;
the carry no longer filling the other axes' bits;
the borrow running through the other axes' bits.
