With rotationMethod='quaternion', GLViewWidget.cameraPosition() returns a point that does not match the view matrix. For example, after setCameraPosition(elevation=30, azimuth=45, distance=10) the camera is at (6.12, 6.12, 5) according to viewMatrix(), but cameraPosition() returns (0, -8.66, -5).
viewMatrix() translates by -center, rotates by rotation, then translates by -distance along z. So the camera sits at center + rotation⁻¹ · (0, 0, distance). The old code used center - rotation · (0, 0, distance).
User-visible effect: middle-button drag uses pan(..., relative='view-upright'), which uses cameraPosition(). In quaternion mode the scene moves in the wrong direction. With the same camera, pan(10, 5, 0, relative='view-upright') now moves the center to (0.10, -0.31, 0) in both modes. Before the fix, quaternion mode moved it to (-0.29, 0.14, 0). pixelSize() and the GLPainterItem example also use cameraPosition().
Tests:
New tests/opengl/test_GLViewWidget.py checks cameraPosition() against the inverted viewMatrix() for both rotation methods. The quaternion case fails on master and passes with the fix.
Also checked locally against 200 random quaternion/center/distance/orbit combinations: the max error went from 39.3 to 8.5e-6.
pytest tests/opengl and pytest pyqtgraph/examples -k GL pass locally (Windows, PyQt6, Python 3.12).
I found this while working on #3629.
