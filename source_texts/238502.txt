Owner
Fixes #831, and the two cheap correctness items from #832. Base 3737b038345. Risk class R2 (renderer + shader).
Unblocks the owner's deferred decision on debug-property placement (#836): reorganising a surface whose controls mostly did nothing would have been premature.
Why the suppression existed — established before removing it
git log -S → 85c7e1a "fix: scope node debug overlays to sole renderer owners" (Apr 4). The reason was real: the push was last-writer-wins across peers — N nodes each believing they owned one renderer-wide debug state. #667 later found the follow-on bug (a legally written flag survived a peer joining, while _validate_property hid the property on both nodes so the user could not turn it off), fixed convergence, and kept the forced-false writes.
The fix: union over the renderer's peers, not suppression
The decisive evidence that there is nothing to arbitrate: these four flags' node-local defaults are read from and written back to a single project setting (rendering/gaussian_splatting/debug/show_*). They were never per-node values — they are whole-frame diagnostics owned by the renderer. Union is order-independent and idempotent, so any peer can compute it and no ownership lease is needed.
Painterly stays gated: it genuinely is per-node appearance.
One real per-node conflict did surface and had to be solved: with the flag unioned, all N nodes would each spawn a HUD control and stack N identical overlays. _update_debug_hud_visibility now also requires the settings-owner lease (already unique per renderer). Measured: the perf HUD costs the same 19.20 % at 1 node and at 8.
The setter no-ops — root-caused, not inferred
A probe reading the flag back in the same frame and at +1/+2/+10 frames gave same_frame=true f+1=false f+2=false f+10=false.
apply_renderer_debug_settings() re-asserted the node's four flags from update_splats() every frame, reverting any set_debug_show_*() one frame after it was made. show_tile_bounds was unaffected precisely because the node never re-asserts it — which is why it was the one API flag that appeared to work.
Fix: the push is edge-triggered against the last union pushed to that renderer. After: f+1=true … f+10=true.
The memo has to be keyed by renderer, not per node. My first attempt used a per-node memo and the GPU harness caught it (2 failures): a stale per-node memo suppresses a needed push once a peer — or the node's own re-entry after a detach — writes a different union.

Round 2 — both findings are REAL, both fixed and mutation-proven
Head efc8c62a7d0 (was c5b5db4f45d).
First, a correction to my own PR body. It said these cases "self-heal within one frame". That was false, and I have edited the body to say so rather than quietly deleting it. The next-frame apply that was supposed to rescue them is update_splats() → apply_renderer_settings() → push_debug_overlay_union(), and under UPDATE_MODE_MANUAL update_splats() never runs — process_gaussian_render's UPDATE_MODE_MANUAL arm sets should_update = false, and set_update_mode does set_process(update_mode != UPDATE_MODE_MANUAL) on the no-manager path. The per-frame route is also lease-gated upstream (apply_renderer_settings returns early at !can_apply_renderer_settings()), so only the settings owner would ever have reached it. Both findings are permanent, not deferred. Codex was right on both counts, and right that the caveat understated them.
Finding 1 (:2152) — Notify the HUD owner when a peer toggles a HUD flag — REAL
Verified. The four flags are unioned across peers, but the HUD control is deliberately drawn by exactly one node — the settings-owner lease holder — so N peers do not stack N identical overlays. A non-owner peer enabling show_performance_hud / show_residency_hud did all of: set the renderer-wide flag via push_debug_overlay_union(), call _update_debug_hud_visibility() on itself, and get refused by the very ownership check that keeps the control unique (gaussian_splat_node_3d.cpp:2152). The holder was never notified. Flag enabled, nothing on screen.
Fix. push_debug_overlay_union() now fans HUD reconciliation out to every node bound to the renderer, via a new GaussianSplatNode3D::_notify_renderer_peers_debug_hud_dirty() — and only when the union actually changed, so the memoized per-frame path stays free and the #831 edge trigger is untouched. The holder among the peers creates the control; the rest are a no-op. The lease itself is unchanged: _claim_renderer_settings_owner still refuses to displace a live holder, so this cannot make two nodes draw the HUD.
Finding 2 (:2565) — Recompute the overlay union on every peer-set change — REAL
Verified. The union is a function of the set of nodes bound to the renderer. The only thing that recomputed it on a peer change was _converge_shared_renderer_state, edge-triggered on _is_renderer_shared_with_other_content — a boolean. A set going 3 → 2 (or 2 → 3) leaves that boolean at true, so every remaining peer returned early at :2555 and nobody dropped the departed node's request.
Fix — driven from the peer-set change, as you asked, not from another special case on the boolean. A new _on_renderer_peer_set_changed(renderer, include_self) is now the single place that reacts to "the node set for this renderer changed", called from both _register_shared_renderer and _unregister_shared_renderer. It drops the edge-trigger memo once, up front, addressed by renderer rather than by node — the observer may be the node that is leaving, which is no longer allowed to push (push_debug_overlay_union early-returns on !is_inside_tree()), so the invalidation could not be tied to a node still bound to the renderer. Every remaining peer then recomputes; the first writes the fresh union and the rest memoize against it, so this costs exactly one renderer write, not one per peer.
_converge_shared_renderer_state keeps its own invalidation for the shared-ness flips that are not peer-set changes (a world submission appearing/disappearing on the renderer); its comment now says so instead of claiming to cover peer changes.
