This PR eliminates the Blosc dependency entirely from OpenVDB.
Here are the fundamentals of how we use Blosc:
Blosc is only ever used with LZ4 (even if Blosc is built with zstd, blosclz, etc those are unused)
Both OpenVDB and NanoVDB use Blosc. NanoVDB can be built independently of OpenVDB.
Blosc is never used threaded (we use the _ctx non-threaded methods)
Blosc SIMD is only ever used for 4-wide byte shuffling in VDB (ie SSE2).
The four methods used from Blosc are - blosc_init(), blosc_compress_ctx(), blosc_decompress_ctx(), blosc_cbuffer_sizes() (some additional methods are used, but only in the unit tests)
This PR puts blosc into the ext/ vendor folder and puts lz4 as a child of blosc. Blosc is directly built into the OpenVDB library. The blosc object file is built such that only those four methods above are exposed. All other Blosc implementation and LZ4 implementation is hidden in the blosc object file. This Blosc object file is both included in OpenVDB and in NanoVDB and this is wrapped in simple headers to be included (#include <openvdb_blosc.h> and #include <nanovdb_blosc.h>). NanoVDB uses Blosc in the header files, so these Blosc headers are installed with NanoVDB. The symbols are prefixed to avoid clashes (for example built as openvdb_blosc_init() and nanovdb_blosc_init()).
This fork of Blosc was taken from Blosc 1.21.6. I have stripped out all unused functionality from Blosc to substantially simplify the implementation (to ~1000 lines). There is one SIMD method for shuffling and unshuffling each that only requires SSE2. This is not used on ARM/NEON, so falls back to the non-vectorized shuffle/unshuffle implementation.
I ran some benchmarks and this implementations runs within a 5% tolerance of the external library. In many cases, it is proving faster although hard to draw firm conclusions from that:
Shape

A consequence of this change is that Blosc becomes mandatory in OpenVDB and NanoVDB. All the conditional macros disappear and all the Blosc CMake implementation is removed as a consequence. I have removed Blosc from all of the CI and updated the docs.

[P2] Reject unsupported bitshuffle buffers
The decoder ignores the bitshuffle flag (0x04), so it accepts bitshuffled LZ4 data without reversing the transformation. I reproduced this with upstream Blosc 1.21.6: the new decoder returns the expected 4,096 bytes, but their contents are wrong. OpenVDB's bloscFromStream also returns normally with corrupted output. Although OpenVDB's writer uses byte shuffle, unsupported input should fail explicitly. Please reject bitshuffled compressed blocks or retain their decoding support.

[P2] Initialize install directories for standalone NanoVDB builds
NANOVDB_INSTALL_INCLUDEDIR is initialized by the repository's top-level CMakeLists, but remains unset when configuring nanovdb/nanovdb directly. Since Blosc now defaults to ON, this install rule causes that documented build path to fail with 'install FILES given no DESTINATION!'. I reproduced the failure; disabling Blosc allows configuration to complete. Please initialize the standalone installation directories from GNUInstallDirs before using them.
