What
Restore depth perception to flat line drawings — the add_polyline fallback for toolpaths too complex to extrude as shaded beads, where a single line through a dense, self-overlapping path reads as a flat ball of yarn with no front-to-back ordering.
Two composable cues, owned by a new in-file DepthCueController (alongside ShadingDebugController):
D → distance fog — classic CAD depth cueing; distant lines dim toward near-black via THREE.Fog whose near/far track the scene bounds + camera distance.
Shift+D → eye-dome lighting (EDL) — screen-space post-process (Potree/CloudCompare style) via an EffectComposer; darkens each fragment in proportion to how much farther it sits than its screen-space neighbours, sculpting bundles into legible 3D.
Both also drive from Python: ViewerClient.set_depth_cue(fog=None, edl=None) (each bool toggles its cue, None leaves unchanged) — so a script can open straight into fog + EDL.
Plus add_polyline(..., fat=False) — a native THREE.Line (one vertex per point, one draw call, ~1px) instead of the fat Line2 instanced-quad path. Keeps million-point toolpaths interactive. WebGL ignores native line width, but fog and EDL need none. Per-vertex colors/colormaps, set_draw_range, the draw_ranges animation channel, update_polyline_colors, and query_scene all handle native lines.
Why the fog-in-EDL detail
scene.fog does not reach line fragments once the scene routes through the composer's RenderPass (it dims them in the direct render but is lost through EffectComposer), so a fog cue washed out entirely under EDL. The EDL fragment shader therefore re-applies linear fog from the depth it already samples — mix(edlShade(color), fogColor, smoothstep(fogNear, fogFar, viewZ)), matching three.js's linear-fog math — with uniforms driven each frame from scene.fog.
Exposing to consumers (e.g. an embedder)
set_depth_cue is a plain message that relays untouched through an embedder's scene broadcast (it sends every type). The desktop path can call v.set_depth_cue(fog=True, edl=True) after building the scene, and switch line-mode toolpaths to fat=False.
Verified
Headless browser: set_depth_cue(fog=True, edl=True) and the D / Shift+D keys both produce fog + EDL on a rainbow native line (background blackens, rainbow preserved, far windings dim); set_depth_cue(fog=False, edl=False) restores baseline; set_draw_range / draw_ranges channel reveal the native line progressively. No JS console errors.
npx tsc --noEmit clean, ruff check + ruff format --check clean, full pytest suite (223) green.
viewer.html rebuilt from sources via build.py; 0.0.0-dev version placeholder intact.
Demo
examples/20_line_depth_cues.py — a ripply spiral-vase toolpath (1M points) drawn as one rainbow (turbo) native polyline, opening straight into fog + EDL.

fat: ``True`` (default) renders fat lines (``Line2``) honoring
``line_width``. ``False`` renders a native ``THREE.Line`` —
one vertex per point, ~1px, one draw call. The native path is
far lighter for very large toolpaths (millions of points) but
WebGL ignores line width, so the perspective-width and haloed
depth-cue modes don't apply (fog / cool-warm / auto-rotate /
eye-dome lighting still do). Per-vertex ``colors`` work in both.
