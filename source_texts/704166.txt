Summary
Implements phases 0, 1, and 2 of issue #64: multi-resolution voxel grid interface.
Phase 0 — Protocol definition (voxel_manager.py)
Define VoxelGrid Protocol abstracting storage strategy (uniform grid → octree swap without changing call sites)
Rename current class to UniformVoxelGrid, keep VoxelManager as backward-compat alias
Add query_overlap(center, radius) — find all cells within a spherical footprint
Add walk_layer(layer, callback) — sparse iteration over existing cells only
Phase 1 — Engine adoption (behavior-preserving refactor)
SoilEvaporationHandler: replaced O(grid²) full scan with walk_layer() — now only visits cells that exist in the sparse dict
WaterReplenishHandler: uses query_overlap() for water source footprints instead of manual bounding-box iteration
SoilDrain/Deposit handlers: distribute drain/deposit across all footprint cells when radius is set; fall back to single-cell without it
Engine autotroph effects: pass canopy_radius as the drain footprint radius (trees now drain from all cells under their canopy)
apply_rain(): uses walk_layer() for soil moisture/nutrient boosts
_init_water_source_moisture(): uses query_overlap() for initial seeding
Phase 2 — Effect-based world processes (already done via #63/#65)
Handlers already dispatch through EffectBus at their own frequencies
SoilDrain/SoilDeposit effects now carry optional radius: float | None field
All handlers depend on the VoxelGrid protocol, not the concrete class
Tests
New test_voxel_grid.py with 28 tests covering:
Protocol conformance (isinstance checks, required attributes/methods)
query_overlap() correctness (bounding box early-out, cell center distance, edge clamping, different cell sizes)
walk_layer() sparsity (only visits existing cells, skips defaults)
Backward compatibility (VoxelManager alias works identically)
Handler integration (drain with/without radius, deposit with radius, evaporation walk_layer usage, rain suppression)
What's next (phases 3-4)
Phase 3: OctreeVoxelGrid implementation (~300-500 lines, same protocol interface)
Phase 4: Refinement policy (configurable triggers, periodic coarsening)
