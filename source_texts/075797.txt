Hello!
Bonne année
🚀 Feature
lt could be very useful for us to have rudimentary support to render multiple channels volume images in Napari.
Specifically the rendering depends on the values in multiple channels and cannot be achieved easily with blending modes.
Motivation
This issue came up in the context of my brainbow data. It is a multichannel 3D fluorescence data that we have currently trouble rendering in 3D.
Pitch
Specifically, we would like to define a custom function which takes the output of the raycasting value in each channel and turns it into a rendered color.
It is different from a blending solution. In brainbow the information is stored in several channels and it is the ratio of intensity that is determinant.
Here is an example of brainbow from institut de la vision
A toy example would be able to render a defined ratio of color from a RGB cube.
--> How to render only purple-ish areas?
Additional context
This issue came up in the Napari hackathon. We didn't find a quick solution but it seems possible to modify the Vispy Volume Visual.
And thank you @alisterburt for already taking time to discuss this subject during the hackathon.

Hi @ClementCaporal - thanks for making an issue, it was great to meet you in the hackathon!
I think we can solve this for your specific application but it's unlikely to become a general purpose feature in napari.
Before we discuss a path forward for this, could you confirm my outline of the problem below?
you have a dataset with shape (c, d, h, w)
you want a ray to be cast which samples each of the channels at each 'step' along the ray
you want to use a custom function to map those values to a color
you need to be able to change this function quickly to see different aspects of the data (i.e. precomputing an array of values for one 'custom function' is not an adequate solution)
Does this 'raycasting loop' look correct to you
go to start point of ray (same as normal 3D rendering)
sample c independent channels
combine values with custom function
step along step vector
repeat 2-4
keep track of max of combined values
map that value to color for pixel
What are the specific problems you have run into when trying to precompute the results of applying your custom function across the channel dimension?

thanks for the extra explanation @ClementCaporal - it's really useful!
This is a really interesting use case but will require quite a lot of work and I'm not sure if it would be something general enough to be made available in napari straight away
The 'on the gpu' solution will involve modifying the vispy volume visual to accept multichannel 3D images (4D arrays]
The values in each channel will need to be made available to the shader - currently one channel is made available as a GPUScaledTexture
the texture is created here
https://github.com/vispy/vispy/blob/8a44e2def171fdcaa79b8394f31673ea8d454d5a/vispy/visuals/volume.py#L702-L715
then the data in it is updated in this method
https://github.com/vispy/vispy/blob/8a44e2def171fdcaa79b8394f31673ea8d454d5a/vispy/visuals/volume.py#L717-L762
the data is made available in the shader here
https://github.com/vispy/vispy/blob/8a44e2def171fdcaa79b8394f31673ea8d454d5a/vispy/visuals/volume.py#L666
You will then have to modify the shader so that it samples your channels then passes them through the transfer function - a good explanation of how the rendering currently works can be found here
https://almarklein.org/volume_rendering.html
Once we have a custom MultiChannelVolumeVisual hooking it up to napari shouldn't be too bad - I won't have time to implement a solution for you myself but am happy to help you to push this yourself in whatever way I can :)
