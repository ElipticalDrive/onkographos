Context
Everything in Vortex is single-precision and single-scene: transforms, PerFrameConstants view-projection, and the motion-vector reprojection in Engine/Shaders/motionvector.hlsl all assume world coordinates near the origin, and verified gaps list "World Partition: no large-world coordinates, automatic scene tiling, or seamless streaming." Beyond roughly 10 km from the origin, float32 precision visibly degrades (jittering meshes, z-fighting, broken physics). The horror game likely never needs this — but the UE5-class goal (UE5's World Partition + Large World Coordinates) and any future open-world project do, and retrofitting origin rebasing later touches every system, so the decision must be made before one is built.
Goal
A research spike, not an implementation: evaluate automatic grid-based world partitioning (auto-assigning entities to streamable cells) and camera-relative rendering / periodic origin rebasing versus double-precision transforms, and produce a design doc recommending an approach, its blast radius across Vortex systems, and a staged adoption plan.
Acceptance Criteria
Wiki design doc comparing: origin rebasing, camera-relative rendering, and float64 CPU transforms with float32 GPU deltas
Precision test scene: measurable artifact catalog at 5/10/50 km from origin in the current engine
Impact analysis for each approach on: DataSerializer scene format, PhysicsSystem, motion vectors/DLSS, streaming volumes, and the editor gizmo/raycast path
Recommendation on grid-cell partition size and how cells map onto streaming volumes + .vpak layers
Explicit go/no-go criteria for when implementation should start (i.e., which game project triggers it)
Technical Notes
Camera-relative rendering only touches the render path (subtract camera position CPU-side before matrix upload) and is the cheapest partial fix — quantify how far it alone gets us
Note DLSS constraint: Streamline motion vectors must stay consistent across any rebase event (skip FG for one frame, like scene switches)
Dependencies
core: level streaming volumes + async scene chunk loading (partition cells stream through the same mechanism)
