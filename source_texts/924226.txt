Done: 1D LUTs and shapers (#971), matte denoise in matte finesse (#1839), Rec.2020 SDR export (#1856), and the measurement the cache needed (#1862).
Left: the per-node cache. Only whole-frame render caching exists, so a heavy node upstream of the node being edited runs again on every downstream tweak. Measured at 3840x2160 on a parked PQ frame (#1862), a slider step takes 9 ms with a plain grade, 560 ms below temporal noise reduction and 234 ms below an OFX node, well over the 16 ms a 60 fps drag allows.
The design is in the comment above. In short:
One cut point per clip, while parked: the output of the deepest heavy node above the node being edited (source-boundary nodes such as temporal NR and frame blend, OFX, frei0r, heavy effects, large-radius denoise), confirmed by its measured time on the last run.
Key: the upstream subgraph resolved at the evaluated time, the source frame's identity and pre-grade generation, the render environment, and the CPU or GPU path. No invalidation beyond the key.
A cut point that a node below it reads around (a key reading the source, an ungraded ApplyMatte port) is kept in the cache too or refused.
Full-float buffer in VRAM or RAM, a 512 MB default budget, least recently used; emptied when playback starts, on project close and on a render-size change. Playback and export never read it.
A "held" mark on the node in the Nodes dock, hit/miss and saved ms in the perf overlay, a budget in Preferences.
Done when:
A 16-step drag below a temporal NR node and below an OFX node runs that node once, and each step's picture equals an uncached run byte for byte, on the CPU and the GPU.
An upstream edit, a keyframe added above the cut point, a time change, a seek, a working-space change, a proxy toggle or a plate file change is a miss with the right picture.
A branch reading from above the cut point is refused or correct; the budget evicts least recently used; playback start empties the cache; export does not use it.
paused_regrade_perf shows the step below temporal NR and OFX back under 16 ms.

Per-node cache: design
Design only; nothing is built yet. It is written against main at 4278e02e4.
What exists today
Whole-frame caches (klipp-engine/src/render_cache.rs). A hot cache and an LZ4 disk cache hold post-grade frames, keyed by clip, frame, grade hash and size, plus the render environment. They help playback and scrubbing over frames that have not changed. They do not help a frame whose grade is being edited.
Caches of parts, inside the executor:
the compiled plan
LUTs, and curve tables per node
decoded and resized plates
static Mask mattes per node
It keeps no intermediate picture between runs.
The parked-drag fast path (regrade_parked_on_gpu). The parked pre-grade goes to the GPU once, and each slider step re-runs the whole graph on the GPU chain and reads back only display bytes. At 4K PQ a typical grade costs about 6 ms a step. Because the chain fuses nodes and keeps the frame in VRAM, re-running cheap upstream nodes costs almost nothing.
Where it would pay
Only a heavy node upstream of the one being edited, while parked on a frame:
A source-boundary node (temporal noise reduction, frame blend). It reads one or two neighbouring source frames and runs on the CPU. A frame that blends re-seeks on every step today (parked_clip_frame_blends).
OFX and frei0r nodes. They run on the CPU, cost depends on the plug-in, and the frame crosses the bus both ways.
Spatial Denoise at a large radius. It is a GPU bilateral, but its kernel cost rises with the radius times the render scale.
Effect nodes with heavy effects (large blurs, glow).
It does nothing for playback. Every frame is a new time, so every key misses, and the whole-frame cache and warm-ahead already serve that case.
What gets cached
One cut point per clip: the output of the deepest heavy node on the path from the source to the node being edited. The next run starts from that buffer and skips the nodes above it. Caching every node's output would cost a full-frame copy per node, which is more than most nodes cost to run.
Which nodes count as heavy: a static hint per node kind (the source boundary, Ofx, Frei0r, Effect with a heavy effect, Denoise), confirmed by the node's measured time on the last run being over a threshold of about 4 ms at the current render size. Nodes below that threshold are not worth the copy.
A cut point must not reach outside its own branch. If a node beyond the cut point also takes an input from above it, that input is either kept in the cache too or the cut point is refused. For example, a key that reads the source, or the ungraded port of an ApplyMatte. The same rule decides whether a group's path counts as one unit or not.
Key
The node's upstream subgraph, resolved at the evaluated time: for each ancestor its kind, whether it is on, its parameters with keyframes evaluated at this time (not the keyframe tracks themselves), and the edges between them. An animated parameter above the cut point still hits on a parked frame and misses when the time moves.
The source frame's identity: media, the frame's time stamp, proxy or original, the log format, and the parked pre-grade's generation (the seek epoch it was decoded under). A seek, or a decode that came back late, can then never match an old entry. For a source-boundary node it also covers the neighbours it read, and whether any neighbour was missing.
The environment (the existing render_environment_hash inputs plus a few more):
working colour space
grade encoding
LUT interpolation
render size and render scale
plates and external mattes, by path and file modification time
The path the picture was made on, CPU or GPU. The two agree within the parity tolerance but are not bit-identical, so an entry is never served across paths.
Where it lives and how big
On the GPU path: a VRAM buffer of the cut point's linear RGBA float output. That is 133 MB at 4K and 33 MB at 1080p. It is kept at full float precision, because a half-float copy would change the pixels, and the cached result has to be exactly what a fresh run gives.
On the CPU path: a Vec<f32> of the same size.
Cap: a budget of 512 MB by default, which is 3 entries at 4K. Eviction is least recently used, at most one entry per clip, and only the parked frame's. If the budget is too small for one entry at the current size, nothing is cached.
When it is emptied: when playback starts, so warm-ahead gets the VRAM back; on project close; and on a change of render size.
Invalidation
There is no invalidation logic beyond the key. An edit to a node below the cut point leaves the upstream key the same, so it hits. An edit above it, a keyframe added there, a moved time, a seek, or an environment change gives a different key, so it misses, recomputes and replaces the entry. There are no edit hooks to keep in step, so nothing can go stale silently.
Playback, warm-ahead, seek epoch
Playback: the cache is not consulted and nothing is stored, and starting playback empties it. Warm-ahead is unchanged.
Seek epoch: it is part of the key through the pre-grade generation, so a frame from before a seek can never be returned as the current one.
Export: export never reads the cache. Viewer-equals-export holds by construction, because a hit is the same path's own result for the same key.
What the user sees
In the Nodes dock: a small "held" mark on the node whose output is cached. Its tooltip says something like: "Output held for this frame: edits after it skip N ms of work". It is greyed out while playing.
In the perf overlay: a hit/miss counter and the milliseconds saved.
In Preferences, under Playback: a "Node cache" memory budget, using the shared row style.
Tests it would need
Edit downstream of a temporal-denoise or OFX node while parked: the upstream node runs once across a 16-step drag, with run counters on the node. Each step's picture equals an uncached run, compared byte for byte on CPU and on GPU.
An upstream edit, a keyframe added above the cut point, a time change, a seek, a working-space change, a proxy toggle or a plate file change: each is a miss, and the picture is right.
A branch that reads from above the cut point: refused, or correct.
Budget exceeded: least-recently-used eviction. Playback start empties the cache. Export does not use it.
Value now
Low for most grades. The all-GPU parked drag is about 6 ms a step, and the cache's copy alone, around 1–2 ms of VRAM traffic at 4K, is a large share of that. The win is real only below the heavy nodes listed above, and none of those has been measured on the parked path yet.
The first step would be to measure, not to build: extend paused_regrade_perf with a temporal-denoise node and an OFX node upstream of the edited Corrector. Build this only if a step comes out well above the 16 ms a 60 fps drag allows.
