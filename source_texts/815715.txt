Parent: #130. Build on existing height/noise, terracing/island shaping, heightfield mesh and scatter/projection operations instead of reimplementing #71/#73. Consume #131–#133 where useful; one simple terrain recipe can start with current primitives.
Deliver
Generate editable heightfield/terrain patches with explicit seed, world origin, dimensions, sample spacing, height range/precision, roughness and shaping parameters. Expose height, slope/material masks and mesh outputs separately.
Provide a small flat/rolling/island or terrace preset set, plus exclusion/paint masks and exact controls for flattening a selected footprint or preserving an explicit path. Add only operations proven missing by these recipes; do not introduce a universal world generator or erosion research project.
Generate cosmetic instance sets with explicit density, minimum spacing, slope/height limits and exclusion masks. Use stable coordinate-derived identities so chunk order/rebuilds do not reshuffle unaffected detail.
Prove adjacent equal-resolution patches share sampled boundaries and compatible derived normals. Define chunk origin, sampling/quantization and border handling. Defer mixed-LOD stitching until an actual consumer requires it, keeping that implementation with the geometry owner.
Keep asset generation distinct from game terrain policy. Real traversable height changes require the consumer's authoritative terrain/physics path to ingest the same declared height source. A flat-grid game may instead use surface textures or explicitly non-traversable scenery; never render a displaced playable floor above unchanged collision.
Acceptance
Generate one patch and two adjacent patches in different execution orders; compare shared edges, masks, detail IDs and full-versus-incremental results. Check negative coordinates, extreme/invalid height ranges, all-excluded scatter, slope limits and stable unrelated detail after localized edits. Show a consumer use of surface/detail assets without changing crop rules, path legality or collisions.
Before adding reusable terrain or streaming algorithms, inspect the existing domain foundations and reuse a suitable authority. Runtime world streaming, gameplay map generation and physical collision remain outside asset-tooling. Follow #130, retain independent simple sampling/scatter references, and include technical plus visual evidence.
