Summary
add the installable addons/foundation editor plugin with explicit generation and dirty-rebuild controls
add packed, renderer-independent terrain data with named deterministic seeds, quantized heights, explicit surfaces and flags, stored cell diagonals, semantic modifications, and dirty chunk tracking
add chunk-local smooth/flat visual meshing, matching separable collision, a renderer-independent sampler, and independently rebuildable chunk views
add a four-chunk runtime demo with a visible seed and three generated surface appearances
add Phase 0 assertions, architecture/setup documentation, and gd-retroterrain attribution
Why
Issue #1 requires the terrain subsystem to establish Foundation's deterministic, data-first architecture before later city-generation stages. This keeps authoritative state independent of scene nodes so future roads, parcels, buildings, editor tools, persistence, and streaming can consume the same terrain model.
User and developer impact
Foundation can now be enabled as a Godot addon, generated explicitly in the editor or at runtime, queried without renderer dependencies, modified semantically, and rebuilt per dirty chunk. The demo provides a small inspection workflow without introducing gameplay or post-Phase-0 city systems.
Validation
Godot_v4.6-stable_win64.exe --headless --path . --script res://tests/run_phase_0_tests.gd — all Phase 0 assertions pass
headless editor startup — plugin loads, all Foundation global classes register, and the demo scene imports without project script errors
headless project startup — the flat-normal demo generates and runs without project script errors
git diff --cached --check
Godot 4.6 stable was the newest local validator available; the addon targets Godot 4.7 and uses compatible Godot 4 APIs.
Scope
This PR intentionally stops at Phase 0. It does not implement roads, districts, blocks, parcels, buildings, interiors, vegetation, traffic, or the full streaming/LOD state machine.

Roadmap update after Phase 0
Phase 0 scope remains unchanged. Please do not add the next-stage work to this PR.
The project roadmap has been revised so the next milestone is now Issue #3: Foundation spatial data model, coordinate system, stable IDs, spatial layers/indexing, serialization seams, and the Foundation Debug View. Terrain-aware road topology moves to Phase 2, after that architecture is merged.
Locked scale decision for current and future work:
terrain cell: 4 m × 4 m
default elevation step: 1 m
chunk: 32 × 32 cells
chunk world size: 128 m × 128 m
shared chunk vertex region: 33 × 33 vertices
Finish PR #2 independently against Issue #1. Phase 1 should begin from updated main after this PR is reviewed and merged, using Issue #3 and a fresh branch such as codex/foundation-phase-1-spatial-model.
