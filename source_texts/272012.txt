Changes proposed in this pull request:
Grain maps (anri.fwd.render.grain_entries): entries hold each voxel's "grain" [N] and a table "grain_ubi" [G, 3, 3] instead of "ubi", e.g. a DCT label volume and one UBI per grain. render_row gives the same peaks and pixels as giving every voxel its grain's UBI (tested). It finds the peaks that reach a row grain by grain: a peak's omega does not depend on where its voxel is. Selection is up to 13x faster. Per-voxel maps take the old path, unchanged, and the indexer and calibration don't use these entries.
Splat (render_row(..., splat=True), grain maps only): each (grain, hkl, branch) spot is rendered whole. Every voxel's peak in a spot has the same omega and covariance, so each voxel's per-frame weight is shared bilinearly onto a tile at its own (sc, fc). Each frame is then convolved once with one peak's window cells. Against the per-voxel render, totals agree within 0.15%, pixels within 2% of the brightest, and frame centroids within 0.01 px (tested). It runs 11-23x faster on DCT-like maps. Every shape is fixed, so a scan compiles once per window class and tile shape, not once per batch. sig_rot must be the same over each grain.
python -m anri.simulate, box beams:
prepare --beam box lights the whole sample in one rotation at y0, with cubes for a 3D map. --beam-size H V sets the beam size (default: the sample plus two voxels). --beam pencil stays the default and is unchanged.
render --splat renders grain maps spot by spot.
render --frames-per-call N renders each row in chunks of frames (write_rendered_rows). It is tested on a scanning row and on a box-beam scan.
Grain-map .npz files go through prepare, render and assemble.
DCT tutorial: the map is built with grain_entries and rendered with splat, in 136 s instead of 784 s on 4 CPU cores. A new section renders 10 deg both ways (5 s against 60 s) and compares them. The stored run was re-executed, with the notebook metadata kept as before.
Skill (references/simulate.md) and CHANGELOG updated.
Tested locally (Python 3.13, JAX 0.12, 4 CPU devices): pytest tests/unit/fwd tests/unit/simulate tests/unit/io tests/unit/test_skill.py (69 passed), ruff check ., ty check .. Not tested locally on Python 3.9 / JAX 0.4.30; CI covers that.

Split the splat kernel into three jitted steps: every spot's kernel, once per
window class in fixed chunks (kept on the host, they are small); voxel peaks
added onto the tiles in fixed chunks of 2^15 per device (tiles donated); then
the convolution. The number of voxels and spots no longer sets a shape. On the
DCT tutorial's map, cold chunks take 14-16 s instead of 22-23 s, warm ones
2-3 s instead of 2.6-5 s.
