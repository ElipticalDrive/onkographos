Implements the locked design (grill session 2026-06-11) for the image → voxel model pipeline: a fresh-start replacement for the VoxelGenerationPipeline generation stages, reusing the existing Assembler.Voxels data/IO layer (VoxelModel, VoxWriter/VoxReader, GoxelTextWriter/Parser, GoxelCoordinateConverter, VoxelBuilder + VoxelScriptExecutor). The old window/stages are untouched for now; retirement is M6.
New assembly: Assembler.Voxelization
Format (M0) — the part-based *.vmodel.yaml is the working representation; .vox/Goxel text are exports:
Records: VoxelRigModel / VoxelPart / PartData (layers | script | mirror | planned) / Pose / SetManifest / ReferenceBrief (+ silhouette).
Hand-mapped YamlDotNet read/write for vmodel, manifest, brief; layered-ASCII codec; VoxelGridConvert.SwapYZ is the single Y-up ↔ Z-up storage boundary.
One format addition over the doc: per-part offset places grid cell (0,0,0) in the part's pivot-local frame, so geometry can centre on its joint.
Mirror convention: point reflection through the local origin (p → -p on the axis); an omitted mirror pivot is derived by reflecting the source pivot.
Assembly + validation (M1/M2, pure code) — ModelAssembler (codec/script/mirror resolution, pivot accumulation, script-colour remap into the locked palette, compose), ModelValidator (scale vs manifest, floating chunks within parts, child-touches-parent connectivity, palette legality, declared-size bounds, and brief palette + silhouette-IoU checks), VoxelProjector, pure-code front/iso preview PNGs, ModelExporter (rig yaml + per-part .vox + flattened .vox/goxel text), RigInstantiator + naive culled-face vertex-colour mesher behind IPartMeshProvider (swappable for the future runtime greedy mesher).
LLM stages (M3–M5) — all Claude-facing content standardised on Y-up:
IAnthropicGateway with per-stage model selection (default Sonnet) and TokenUsageTracker accounting from day one.
ManifestGenerator (Stage 0), ModelPlanner (Stage 1 — the only vision call when a reference image is attached via IReferenceImageSource; code re-anchors scale to the manifest and demotes over-budget layers parts to scripts), PartAuthor (Stage 2 — fenced layers blocks decoded immediately with error-fed retries; scripts via the run_voxel_script tool loop with a Y-up description override).
SetOrchestrator: batch over the manifest, assemble → validate → re-author only the offending parts for bounded rounds, then export; failures land as Failed/NeedsReview instead of aborting the batch.
Editor — Assembler > Voxel Set Review: brief → manifest → batch run → preview gallery with per-model accept / regenerate / refine (note), and per-stage token usage.
Additive changes to existing assemblies
Assembler.Anthropic: AnthropicMessage images (base64 blocks built via FromRawUnchecked for SDK-version stability) and an onUsage callback on SendAsync reporting per-request token usage.
Assembler.Voxels: IVoxelScriptExecutor.RunScriptAsync (deterministic re-run of stored part scripts, shared limits) and an optional tool-description override.
Tests (39 passing, Tests.Voxelization)
Codec round-trips + error cases, Y/Z swap involution, mirror geometry/pivot conventions, pivot-chain math, palette-breach remapping, validator failure modes (scale drift / floating chunk / disconnected part / size exceeded / brief palette / silhouette IoU), vmodel/manifest/brief yaml round-trips, per-part .vox round-trip through VoxReader, rig instantiation + pose application, mesher face culling, a hand-written oak-tree script through the real expression compiler, and fake-gateway tests for fence parsing, retry feedback, scale re-anchoring, budget demotion, and the orchestrator end-to-end (incl. failed-plan handling).

The manifest's symmetry now rides on the model, the planner prompt forbids authoring both sides (one side + mirror: parts only; centre parts must be symmetric about the x plane, side-part pivots exact reflections), and there's a new rigorous check: the validator mirrors the composed occupancy across the bbox-centre x plane and flags Asymmetric below 97% IoU. Resumability (questions)
Honest answer: a run is not resumable mid-asset today — orchestration state is in memory, so an API failure, dropped connection, or domain reload loses the in-flight asset. What this commit does give you: assets are independent and auto-export on completion, so finished models survive anything, and recovery is per-asset (Regenerate just the ones that didn't finish) rather than per-batch. True mid-asset checkpointing (persisting the plan + each authored part as it lands, then resuming from the last part) is a natural follow-up since the vmodel yaml can already represent a half-authored model — happy to do that as its own PR if you want it.

One shape per line, later lines overwrite earlier, centres/radii may be fractional (a 4-wide wheel is a cylinder centred at x=1.5), round R gives rounded cuboids, and half clips give hemispheres and half-cylinders. It's rasterized deterministically in code (no LLM tool loop, no compile step), clipped to the declared part window, and validated like layers. The planner is told to pick primitives for geometric parts — car bodies, wheels, trunks, poles, walls — keeping layers for organic detail and script only for parametric patterns primitives can't express. The shape lines are stored verbatim in the vmodel yaml, so exported models stay rebuildable/hand-editable.
