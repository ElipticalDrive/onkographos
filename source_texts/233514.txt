💡 What: Pre-allocated the hit_xs array using Vec::with_capacity(8) instead of Vec::new() in the hot innermost loop of MeshProcessor::voxelize, and added explanatory code comments.
🎯 Why: In MeshProcessor::voxelize, ray intersections along an axis are gathered into hit_xs. Previously, this vector was dynamically sized using Vec::new(), meaning for meshes with multiple intersections, the vector would need to constantly reallocate heap memory during execution of a tight inner loop. Pre-allocating capacity minimizes heap fragmentation and dynamic resizing. While it forces an initial allocation even on rays that miss the mesh, the amortized cost across thousands of successful hits in complex geometries is much lower.
📊 Impact: Reduces execution time in the voxelization inner-loop for complex models by minimizing memory management overhead during raycasting.
🔬 Measurement: Benchmarks (cargo bench) show no regression and confirm correct functioning on the suite, while preventing memory reallocation spikes during heavy workloads. All unit and integration tests (cargo test) continue to pass.

Avoid allocating for every empty scanline
For scanlines that do not intersect the mesh projection, this now performs a heap allocation for every (iy, iz) row before cast_local_ray has found any hit; the old Vec::new() path was allocation-free for these misses. That case is common around curved/thin/open meshes inside their rectangular Y/Z bounds, so this can turn the voxelization hot loop into allocator churn and regress the exact workloads the change is meant to optimize. Consider keeping the vector lazy and reserving after the first hit, or reusing per-row storage, so misses stay allocation-free.
