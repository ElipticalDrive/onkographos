Raster <image> content with image-rendering auto, optimizeQuality or high-quality is now resampled with the Mitchell-Netravali cubic (B = C = 1/3) on both backends. This is the kernel resvg applies by default, and the one Donner's feImage already used on TinySkia and Geode. smooth stays bilinear, crisp-edges and optimizeSpeed stay nearest, and pixelated keeps its two-stage path. A single mapping in ImageSampling.h picks the <image> kernel for both backends.
optimizeQuality is a deliberate choice. CSS Images aliases it to smooth; Donner follows resvg, which renders it with the Mitchell cubic.
TinySkia: drawn with tiny-skia FilterQuality::Bicubic, which was already linked into the renderer. It samples premultiplied sRGB texels with edge clamping, then clamps each channel to [0, 1] (tiny-skia's Clamp0 and ClampA). Premultiplied color may therefore exceed alpha.
Geode: the image blit gains a fourth sampling mode, a 16-tap cubic over the source rectangle with the same weights and the same per-channel clamp.
Translation-only draws: like tiny-skia, Geode samples the nearest texel for any translation-only image draw, fractional translations included. The blit's nearest mode reads the containing texel with textureLoad, as the feImage nearest path does.
Compositor blits: bitmap blits resolve auto to smooth, so layer, tile and pattern composites keep bilinear sampling.
The vendored raster-image references came from several historical upscalers:
a browser rendering whose bilinear filter uses 4-bit subpixel weights;
an older resvg that first resampled each image to its user-space size;
the Mitchell cubic that current resvg uses.
None of the old pixel-art reference sets could be matched without emulating an obsolete pipeline. At resvg v0.49.0 every raster-image reference is drawn with the Mitchell cubic, except optimizeSpeed, which uses nearest. This change replaces 24 structure/image references, painting/image-rendering/optimizeSpeed and masking/mask/with-image with their 300x300 v0.49.0 renderings. no-height.svg and no-width.svg are replaced too, because upstream redrew them. Provenance is recorded in third_party/resvg-test-suite/BUILD.bazel, following the earlier font-family refresh.
Results:
The twelve kernel skips and the optimizeSpeed skip are removed.
The nine raster threshold allowances and the masking/mask/with-image allowance are dropped. Every one of these cases now compares at default settings, with 0 to 12 differing pixels.
optimizeSpeed stays disabled on Geode only. At 3.75 device pixels per texel, every second texel boundary falls on a pixel center. Geode's interpolated texture coordinate lands just below the boundary, where tiny-skia's float inverse transform lands on it, so Geode picks the previous texel. All 564 differing pixels are inside the image; TinySkia matches.
The Geode opacity golden documented bilinear sampling of its image, so its fixture now sets image-rendering="smooth". The committed macOS and Linux goldens keep covering the isolated-layer composite they were captured for.
Outside structure/image, optimizeSpeed and masking/mask/with-image, every row in structure/*, masking/* and painting/* is unchanged on default_text, max and Geode. The renderer Wasm module measures 871,434 gzip bytes against the 872,000 ceiling, and the editor Geode package 3,518,862 against 3,520,000.
Tests:
ImageQualityRenderingUsesMitchellCubicSampling renders an upscaled checkerboard <image> and the same placement through feImage, for an unspecified value, auto, optimizeQuality and high-quality.
Three regressions compare the active backend with tiny-skia drawing the same image directly:
a translucent checker upscaled with the cubic;
an image at intrinsic size under a fractional translation (interior pixels);
a smooth upscale against tiny-skia's bilinear filter.
TinySkia must match these oracles, and the feImage one above, exactly. Geode is held to the canonical default comparison, because GPU sampling evaluates in float on the device:
the shader cubic lands at most one 8-bit step away in one channel (28 and 612 pixels on an Intel Vulkan device);
hardware bilinear filtering differs by low bits on 684 pixels on Metal.
The translated nearest case stays at identity on both backends.
Native image-blit cases, opaque and translucent, compare the cubic mode against an independent CPU Mitchell reference on Metal and Vulkan.
They use the native blur cascade's approved allowance of two pixels at one 8-bit step.
A Vulkan device differs from the reference by one step in one channel of one pixel.
All of these were committed failing first.
Unit tests pin the image-rendering to kernel mapping, the auto-to-smooth bitmap-blit policy, and a scaled TinySkia drawBitmap.
Follow-up: route feImage sampling through the same image-rendering kernel mapping. Today feImage keeps its own mapping and samples smooth with the cubic on both backends.

Builds on the shared `<image>` kernel mapping `ImageSamplingKernelFor`
from #2097.

`feImage` chose its own resampling kernel. `image-rendering: smooth`
resampled with the Mitchell cubic, while `<image smooth>` is bilinear.
The software renderer's rotated placement also resampled bilinearly and
then filtered the result again with the cubic. resvg renders an
`feImage` raster as an image, so every `feImage` placement now goes
through `ImageSamplingKernelFor` on both backends.

- A placement-aware `ImageSamplingKernelFor(imageRendering,
deviceFromImage)` encodes tiny-skia's rule that a pure translation
samples the containing texel. Geode `<image>` draws use it as well.
Before this change, Geode `pixelated` draws at their intrinsic size kept
interpolating while the software renderer sampled the texel.
- Software filter graph: a bilinear `feImage` kernel, plus a Mitchell
kernel in the procedural rasterizer. Rotated `feImage` is resampled once
with the selected kernel and then copied texel for texel.
- Geode: the `feImage` shader gains a bilinear mode. The Metal and
Vulkan native shader tests now cover all four modes against their host
reference.
- Nested-SVG `feImage` rasters are rendered at their device size, so
their one-to-one placement now copies texels instead of filtering them
with the cubic. The two Donner-generated `filters/feImage/svg` goldens
are refreshed from the new renderings.
`filters/feImage/with-subregion-5`, previously skipped, now matches its
reference exactly on every lane and is compared again.

## Tests

- `FeImageSamplesLikeImageForEachRendering`: `feImage` with each
`image-rendering` value (unspecified, `auto`, `optimizeQuality`,
`high-quality`, `smooth`, `optimizeSpeed`, `crisp-edges`, `pixelated`)
against the same raster drawn as `<image>`. The comparison is identity
on TinySkia and the `ImageSamplingOracleParams` default on Geode.
- `FeImageTranslatedAtIntrinsicSizeSamplesLikeImage` (identity) and
`FeImageRotatedSamplesLikeImage` (`ImageSamplingOracleParams`) cover the
same values for translated and rotated placement.
- `ImageTranslatedAtIntrinsicSizeSamplesNearest` now covers every value.
- Red at the test commit, software renderer: `smooth` 2176 pixels;
translated 49 pixels for the quality values, `smooth` and `pixelated`;
rotated 920 pixels for the quality values and 80 for `smooth`.
- Red at the test commit, Geode: `smooth` 378 pixels; translated 49
pixels for the quality values and `smooth`; rotated `smooth` 138 pixels;
`<image pixelated>` translated 49 pixels.
- Green: all seven sampling tests pass on both backends.

| with-subregion-5 | skipped (5969) | 0, compared |

Other `filters/*` rows and `painting/image-rendering/*` are unchanged.
