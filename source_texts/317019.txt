Summary
BC blocks cover 4×4 texels in a single depth slice. Volume layouts previously rounded depth to groups of four, which also made DDS mip offsets and payload lengths incorrect.
Count BC blocks as 4×4×1, retaining the scalar blockSize API and CompressionMode.None behavior.
Round XY without overflowing at Int32.MaxValue, and widen block-count operands before multiplying byte sizes.
Reuse the shared helper in DDS metadata, retaining uint64 payload accounting, removing the unused block-count entry, and storing the remaining metadata in compact value-tuple arrays.
Use inline-friendly unsigned XY rounding, avoiding a small-DDS slowdown found during benchmarking.
Document the layout contract without changing codecs, uploads, resource validation, header interpretation, mip/array/cube ordering, or WantMipMaps.
Coverage
119 new backend-independent tests cover every BC mode, both block-byte sizes, non-aligned XY dimensions, depth boundaries, representable large counts, and 1D/2D compatibility. Synthetic legacy/DX10 DDS fixtures check exact sizes, distinct mip/depth payloads, stream consumption, every truncated prefix, array/cube ordering, and both mip policies.
The minimal 4×4×4 three-mip fixture now consumes 56 bytes for BC1 (32, 16, 8) and 112 bytes for BC3 (64, 32, 16), instead of the previous 24/48 bytes.
Before the fix, 54 new cases fail and 65 compatibility cases pass. After the fix, 215 selected CPU tests pass in Debug and Release. The 119 new tests also pass 100 consecutive Release runs, and the 167-test broader CPU selection passes 20 consecutive runs. The full non-Windows solution builds in both configurations with warnings treated as errors. The existing unaligned mirror-copy tests emit the same 15 intentional diagnostics as the baseline. GPU execution is outside this validation scope.
Performance
Compared with a3e75744, using warmed Release code on 64-bit .NET 8. Layout measurements use seven alternating process pairs with mixed BC modes and dimensions. Block-count throughput improves 4.16–4.25× and byte-count throughput 5.20–5.42×, with 0 B allocated before and after.
For ordinary in-memory 2D DDS loading, 63 alternating in-process pairs per case keep GC conditions matched. Throughput is unchanged to modestly better, while allocation decreases in every case:
