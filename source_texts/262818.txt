WIP / experimental. A prototype that explores the texture items of #506 and measures them, shared as an example for discussion rather than for merging as is.
Summary
This implements the texture items of #506 that the rest depend on: 2D-array and 3D textures in the public API, sampler2DArray / sampler3D in .fmat, both texture types in the WebGL2 and WebGPU backends, data formats beyond RGBA8, and device limits. It also adds examples/volume_bench, which compares them with the slices-in-an-atlas workaround. It does not close the issue; the remaining items are listed below.
Public API
```
final layers = Texture2DArray.fromLayers(
  slices, // one Uint8List / Float32List per layer
  width: 256,
  height: 256,
  format: gpu.PixelFormat.r8g8UNormInt,
); // also .empty(...) + writeLayer(i, data), byteSize

final volume = Texture3D.fromVoxels(voxels, width: 256, height: 256, depth: 256,
    format: gpu.PixelFormat.r8UNormInt); // web only, see Texture3D.isSupported

final lut = Texture2D.fromData(texels, 64, 1, format: gpu.PixelFormat.r32Float);

material.parameters.setTexture('layers', layers.gpuTexture,
    sampler: layers.sampledSampler);

gpu.gpuLimits.maxTextureSize; // maxArrayLayers, max3DTextureSize, ...
```
```
parameters: [
  { type: sampler2DArray, name: layers, hint: default_black },
  { type: sampler3D, name: density },
]
```
Data formats: r8, rg8, rgba8, r32Float, rgba16Float, rgba32Float (dataTextureBytesPerTexel). TextureSampling.data (bilinear, no mips, clamped) is their default.
gpu.dart exports PixelFormat, TextureType, GpuLimits, and gpuLimits.
setTexture throws when a texture's type does not match the sampler's (Metal rejects that at draw time, and WebGL2 samples black). An unset array or 3D sampler binds a 1x1x1 placeholder of its own type.

impellerc already compiles sampler2DArray and sampler3D for Metal, Vulkan, and GLSL ES 3.00, so the generated .fmat shaders needed only the new types and a vec3 keep-alive fetch.
Also in this PR
Fix: the WebGL2 backend never set UNPACK_ALIGNMENT, so r8 and rg8 textures whose rows are not a multiple of four bytes uploaded skewed (2D textures included). It is now 1, matching flutter_gpu's tightly packed uploads.
timeGpuWork (shim-internal, used by the benchmark) times a batch of command buffers: EXT_disjoint_timer_query_webgl2 on WebGL2, onSubmittedWorkDone on WebGPU, and completion callbacks on Flutter GPU. It submits each buffer as the next one opens, because a Metal queue holds at most 64.
Benchmark
examples/volume_bench generates a synthetic 16-bit density field and times two workloads over a 1024 x 1024 target: an oblique reslice (one trilinear sample per pixel) and a ray-marched MIP (one sample per voxel step). It draws through the shim directly, so only the fetch path differs between variants:
atlas: the workaround. Slices are tiled on RGBA8 pages of at most 4096², two 16-bit voxels per texel, and filtered by hand with eight texelFetch per sample.
2D array in r8 (8-bit), rg8 (16-bit, high byte in red; filtering is linear, so the filtered pair still decodes to the filtered value), or r32Float: hardware bilinear within a layer, two reads blended across layers.
3D in the same formats (web only): one hardware trilinear read.
Each variant's image is read back and compared with the atlas's: every variant is within 1 gray level of it (mean difference 0.01 for rg8, about 0.27 for r8).
Apple M1 Pro, macOS 27.0.1, Flutter 3.50.0-0.2.pre (beta), Chrome 156. The values are the median ms per full-screen draw over 7 samples.
WebGL2 uses the GPU timer query, so it measures GPU time only.
Metal uses wall time from submission to the last command buffer's completion, because Flutter GPU has no timestamp queries. An empty pass measures 0.058 ms that way.
Reslice draws 16 additive draws per pass so it rises above that floor.

What the numbers show:
Hardware filtering makes the reslice 6x faster on Metal and 5 to 9x faster on WebGL2, at the same 16-bit precision and memory.
At 256³ the MIP is 9x faster on Metal with a 16-bit 2D array, and 3x faster on WebGL2. A 3D texture saves another third on WebGL2.
At 512 x 512 x 400 the MIP is bound by memory bandwidth, so bytes per voxel decide the time. 16-bit arrays are 1.7x faster than the atlas on Metal and about level on WebGL2. 8-bit arrays are 3 to 8x faster, and r32Float is the slowest. That is the case for a single-channel 16-bit format.
The atlas MIP costs 33 ms on Metal through Flutter GPU but 10.6 ms on WebGL2 (ANGLE on the same GPU), from the same GLSL source. The array variants cost about the same on both backends. I did not investigate further; the atlas shader's integer division, modulo, and four-way sampler branch are the likely cause.
Tests
test/data_texture_gpu_test.dart (needs --enable-impeller --enable-flutter-gpu; compiles a sampler2DArray shader with impellerc at test time). Covers:
r8, rg8, and r32Float layers sampled and read back, and layer rewrites.
Size and format validation, and Texture2D.fromData.
Runtime-compiled .fmat materials binding an array, refusing a 2D texture, and a sampler3D material refusing to load on native.
gpuLimits on macOS.
test/fmat_test.dart: parsing (including the lowercase aliases), emitted uniforms and keep-alive fetches, sidecar types, and the hint rule.
test/gpu/data_texture_webgl_browser_test.dart (WebGL2, against an impellerc-built bundle embedded under test/fixtures/data_textures/): array layers, 3D linear filtering across depth slices, slice rewrites, and limits.
test/gpu/webgpu/webgpu_data_texture_browser_test.dart: the same for WebGPU.
Run locally:
All of the above pass, as do the existing WebGPU browser tests and dart analyze packages examples (the editor's window API names aside, which CI patches on non-stable channels).
flutter test --enable-impeller had no failures apart from one test that compiles every lit shader with impellerc. It timed out while another suite ran in parallel and passes on its own.
With --enable-flutter-gpu, 24 tests fail identically on master here: the test runner cannot load the engine's shader bundle.
Not in this PR (from #506)
Needs Flutter GPU changes:
r16 / r16Float formats.
3D textures on native.
GPU timestamps.
Texture size limits on Vulkan and OpenGL ES.
Region (sub-rectangle) writes; this PR writes whole layers and slices.
Explicit disposal.
Not attempted: .fmat #include, pipeline pre-warm, render scale, GPU time in render stats, compute, and depth/blend control for unlit materials.
Not benchmarked: WebGPU (it is covered by the tests).

…, and GPU limits

- Texture2DArray.fromLayers / .empty and Texture3D.fromVoxels / .empty, plus
  Texture2D.fromData for raw texels in r8, rg8, rgba8, r32Float, rgba16Float
  and rgba32Float; layer and slice writes; byteSize.
- .fmat parameters of type sampler2DArray and sampler3D: emitted as
  top-level uniforms with vec3 keep-alive fetches, recorded in the sidecar,
  bound through MaterialParameters.setTexture, which now checks the texture's
  type and binds a placeholder of the matching type when unset.
- GPU shim: TextureType.texture2DArray, createTexture(layerCount:) and
  doesSupportTextureArrays on WebGL2 (TEXTURE_2D_ARRAY, texStorage3D,
  texSubImage3D, framebufferTextureLayer) and WebGPU; createTexture3D on both
  web backends (TEXTURE_3D / '3d'); native reports 3D as unsupported, since
  Flutter GPU has no 3D texture type.
- gpuLimits / GpuLimits: max texture size, array layers, 3D size, samplers
  per stage, float32 filtering (WebGL2 and WebGPU from the device; Metal from
  Apple's feature set tables; null elsewhere on native).
- timeGpuWork: GPU timing of a batch of command buffers (WebGL2 timer
  queries, WebGPU onSubmittedWorkDone, Flutter GPU completion callbacks).
- WebGL2: set UNPACK_ALIGNMENT to 1, so r8/rg8 rows that are not a multiple
  of four bytes upload correctly.
