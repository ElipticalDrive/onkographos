摘要
在本技术报告中，我们探讨了在虚幻引擎5 (UE5) 中对大型体素数据集进行核心内存渲染的几种方法。我们研究了以下方法：TBRayMarcher 插件、Niagara 流体插件，以及使用稀疏体素纹理 (SVT) 的各种方法，其中特别关注异构体 (HV)。
我们发现 HV 方法是最有前途的。我们在其他方法中遇到的最大挑战是需要对数据集进行分块，以使每个分块都能适应小于1吉体素的体素纹理。尽管这使得以合理帧率显示整个数据集成为可能，但由于不正确的照明，它会在分块边界处引入明显的伪影，因为每个分块都缺乏其邻居的信息。
在通过将引擎 SVT 相关源代码中一些 (有符号) int32 溢出转换为 (无符号) uint32 或 int64 后，基于 SVT 的 HV 系统使我们能够渲染高达 32k x 32k x 16k 体素的稀疏数据集，前提是压缩的瓦片数据 (包括 MIP 数据和用于正确插值的填充) 不超过 4 吉体素。将来，我们打算扩展现有的 SVT 流式传输功能以支持核外渲染，以期最终克服显存限制、图形 API 约束以及 GPU 着色器中与 64 位算术相关的性能问题。

引言
可视化大型体积数据集对科学应用提出了重大挑战，这些应用需要对复杂3D数据进行交互式探索和分析。德国亥姆霍兹基尔海洋研究中心GEOMAR的研究人员对在虚幻引擎5（UE5）中渲染大型体积数据集的方法进行了全面调查，评估了它们在科学可视化方面的能力和局限性。
图1：使用具有稀疏体积纹理的异构体积在虚幻引擎5中渲染的Kolumbo地震数据集的可视化，显示了具有不同颜色映射的地质层。
该研究将海洋研究与可视化技术相结合，研究了UE5（一种具有高级渲染功能的现代游戏引擎）如何适应处理科学数据，这些数据在大小和复杂性上通常超过典型的面向游戏的体积。这项调查的特别动机来自于ARENA2可视化穹顶设施的需求，该设施为协作数据探索提供了沉浸式环境。
背景与动机
大型体积数据集的科学可视化传统上是专门为研究应用而设计的专业软件工具的领域。然而，像UE5这样的游戏引擎具有引人注目的优势，包括高性能、先进的照明和渲染功能以及完善的开发生态系统。
图2：GEOMAR亥姆霍兹中心的ARENA2可视化穹顶，展示了沉浸式协作环境中3D体积数据的交互式可视化。
这项研究的动机源于以下几个因素：
蓝色健康科技（BHT）项目将海洋研究与医疗创新相结合，需要可视化大型体积医疗数据。
GEOMAR现有的ARENA2可视化设施需要交互式探索复杂数据集的解决方案。
地震学、地球物理学和海洋学等科学学科处理的体积数据集超过了典型的游戏开发规模。
UE5的先进渲染功能在科学可视化方面的潜力尚未得到充分探索。
作者旨在确定在UE5中进行大型体积数据集核内渲染的合适方法，长期目标是扩展到真正的核外渲染，以处理更大的数据集。
体积渲染基础
体积渲染是一种允许可视化3D标量场的技术。与仅表示对象边界的表面渲染不同，体积渲染通过为体积内的点分配诸如颜色和透明度之类的光学属性来实现内部结构的显示。
图3：体积渲染中光线步进过程的图示，显示了光线穿过体积时如何累积。
用于体积渲染的基本算法是光线步进（也称为光线投射），其工作原理如下：
对于输出图像中的每个像素，都会从相机投射一条光线，穿过该像素并进入体数据。
该光线在其穿过体数据的路径上以规则的间隔进行采样。
在每个采样点，查询体数据以确定颜色和不透明度值。
这些值根据体绘制方程，沿光线从前到后累积：

其中 CiC_iCi​ 是采样点 iii 处的颜色，αi\alpha_iαi​ 是该点的不透明度，nnn 是采样点的总数。
此过程允许可视化基于表面渲染方法中会被隐藏的内部结构和特征。
Unreal Engine 5 中的方法
作者评估了 UE5 中体绘制的几种方法：
自定义光线步进着色器
使用 UE5 材质编辑器中的材质表达式节点创建了一个自定义实现。 这种方法可以完全控制渲染过程，但需要手动实现整个光线步进算法。
TBRayMarcher 插件
TBRayMarcher 插件为 UE5 中的体绘制提供了一种更结构化的方法。 它为体绘制提供专用节点，并支持诸如用于颜色映射的传递函数和渲染参数的实时操纵等功能。
图 4：UE5 中不同体绘制方法的比较：（a）SparseVolumeTextureViewer，（b）体积雾，（c）异构体，和（d）体积云。
该插件将大型体数据分成块以克服纹理大小的限制，但在块边界处面临挑战，由于梯度计算的不连续性，可能会出现光照伪影。
Niagara 流体
Niagara 是 UE5 的视觉效果系统，包括流体模拟和渲染功能。 虽然并非专门为科学可视化而设计，但可以对其进行调整以进行体绘制：
```
// HLSL 中简化的 Niagara 体数据采样
float densityValue = VolumeTexture.SampleLevel(VolTextureSampler, UVW, MipLevel).r;
float4 colorValue = TF_Texture.SampleLevel(TFSampler, float2(densityValue, 0), 0);
```
图 5：UE5 中的 Niagara 流体界面，显示了密度曲线调整和地震数据的体绘制预览。
Niagara 方法提供了与 UE5 粒子系统的良好集成，但由于 VRAM 消耗高，因此可以处理的体数据大小受到限制。
不同的体纹理格式
UE5 支持多种用于表示体数据的纹理格式：
图 6：不同的纹理格式及其在 Unreal Engine 中的表示形式：页表（顶部）和物理 3D 切片（底部）。
每种格式在内存使用、访问模式和渲染性能方面都提供了不同的权衡。 作者发现，UE5 中的传统 3D 纹理限制为 2048³ 体素，这对于许多科学数据集来说是不够的。
稀疏体纹理
作者确定的最有希望的方法是使用带有异构体数据的稀疏体纹理 (SVT)，这是 UE5 中引入的一项功能。 SVT 通过仅为非空区域分配内存来有效地存储大型体数据，使其特别适合科学数据。
异构体
UE5 中的异构体为渲染具有复杂内部结构的体数据提供了一个框架。 它们支持：
体数据范围内的照明效果
具有基于物理的散射的光线步进
与 UE5 全局照明系统集成
可自定义的采样和渲染参数
作者发现这种方法最适合他们的需求，特别是与 SVT 结合使用来处理大型数据集时。
技术实现
为了使用 SVT 和异构体积实现体积渲染，作者开发了一个自定义工作流程：
数据准备：将科学数据格式（地震数据的 SEG-Y）转换为兼容的体积纹理
体积纹理创建：从源数据生成具有适当 mip-map 级别的 SVT
材质设置：创建采样体积并应用传递函数的材质
异构体积 Actor：使用适当的渲染参数配置 Actor

图 7：材质图实现，显示了用于处理分割成多个块的大型体积数据集的自定义坐标变换。
这涉及到仔细管理块索引和每个块内的局部坐标之间的坐标变换，该变换在材质编辑器中实现：

```
return SampleVolumeTexture(volumeTexture, offsetCoord);
```

克服引擎限制
在他们的实现过程中，作者遇到了并解决了 UE5 中的几个限制：
整数溢出问题
研究人员发现 UE5 在处理大型纹理时存在整数溢出问题。通过修改引擎源代码以使用 uint32 而不是 int32 进行某些索引操作，他们能够克服寻址限制：
C++
```
// 原始 UE5 代码（对大型纹理有问题）
int32 LinearIndex = X + Y * Dimensions.X + Z * Dimensions.X * Dimensions.Y;

// 修改后的版本
uint32 LinearIndex = X + Y * Dimensions.X + Z * Dimensions.X * Dimensions.Y;
```

未来方向
基于他们的发现，作者概述了未来研究的几个有希望的方向：
真正的核外渲染：扩展 UE5 以按需从磁盘或网络存储加载体数据
压缩技术：实施特定于体积的压缩以减少内存需求
高级传递函数：开发更复杂的方法来将数据值映射到视觉属性
与科学分析集成：将可视化与交互式数据分析工具相结合
多场可视化：同时渲染多个重叠的体积场
研究人员指出，真正的核外渲染对于超过可用 VRAM 的科学数据集尤其有价值，并建议通过 UE5 的虚拟纹理系统实现可能的实施方法。
结论
该调查表明，虚幻引擎 5 可以有效地用于大型体数据集的科学可视化，其中稀疏体纹理和异构体提供了最有希望的方法。研究人员成功地以交互式帧速率渲染了一个 5.9 吉体素的地震数据集，证明了使用游戏引擎技术进行严肃的科学可视化应用的可行性。
这项工作解决了重要的技术挑战，并为处理大型体数据的科学家提供了实用的解决方案。通过利用 UE5 的高级渲染功能，同时通过自定义实现和引擎修改克服其局限性，该方法能够更方便地交互式探索复杂的科学数据集。
本研究中开发的技术在海洋研究、医学可视化以及处理大型体数据集的其他科学领域具有直接应用。更广泛地说，这项工作有助于弥合游戏技术和科学研究之间的差距，从而可能在科学界更广泛地采用交互式可视化技术。
