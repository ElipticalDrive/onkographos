What does this pull request do?
create_intrinsics accepts tensor principal points but converts them to Python lists before filling the camera matrix. This detaches cxs and cys, so a projection loss cannot differentiate with respect to them.
Iterate those inputs directly and keep the existing matrix construction. Tensor assignment preserves their gradients, including through PinholeCamera.project. Matrix values, dtype/device selection, list inputs and both camera factories stay unchanged. Add a projection-gradient regression, numerical gradcheck and a changelog fragment.
Related issue or discussion
Self-contained fix for the existing tensor inputs of create_intrinsics; no related issue found.
What did you check?
The five new CPU regression cases fail on pristine main for detached gradients and pass with the fix. Each projected point has the expected unit derivative with respect to its principal point.
Full camera test module, CPU/CUDA float32/float64: 425 passed, two skipped. PyTorch 2.5.1 CPU: 215 passed, one skipped.
Factory tests in float16/bfloat16: 12 passed on CPU and 12 passed with per-test CUDA isolation.
128 existing-input compatibility groups give identical bytes on base and patch, covering lists, tensors, noncontiguous inputs, repeated calls, dtypes and both factories. Sixteen mixed-device/dtype gradient groups pass.
Full repository pre-commit and type checking pass. Full-graph aot_eager compilation preserves the principal-point gradients.
Geometry conformance: 825 ONNX cases and 419 Inductor cases passed.
Local validation used Windows, Python 3.13.3 and PyTorch 2.11.0+cu130, plus the explicit PyTorch 2.5.1 CPU environment. I did not run the full library suite, Linux CPU half profiles or MPS tests.
