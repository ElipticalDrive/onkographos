The nonuniform layers are useful, and the coordinate ordering, plotting and round-trip coverage look good. I would like the equality issue addressed before approval, along with the precision edge case below.
Important — array-aware equality (dtcc_core/model/geometry/grid.py:165). I reproduced the existing review finding at 1fd06d1:
```
from dataclasses import replace
from dtcc_core.model import VolumeGrid

grid = VolumeGrid(width=1, height=1, z_levels=[0, 1, 3])
grid == replace(grid)
```
This raises ValueError: The truth value of an array with more than one element is ambiguous. The equivalent comparison works for a uniform grid. Please implement array-aware equality for the layer boundaries and add tests for matching and differing boundaries. Simply excluding z_levels from comparison would let grids with different interior layers compare equal.
Nit — precision loss for large integer elevations (dtcc_core/model/geometry/grid.py:181–182 and dtcc_core/model/exchange.py:849–850). This round trip silently changes an interior boundary:
```
import numpy as np
from dtcc_core.model import VolumeGrid
from dtcc_core.model.exchange import dumps, loads

grid = VolumeGrid(width=1, height=1, z_levels=[0, 1, 3])
grid.z_levels = np.array([0, 2**53 + 1, 2**54], dtype=np.int64)
restored = loads(dumps(grid))
int(grid.z_levels[1]), int(restored.z_levels[1])
```
Result: (9007199254740993, 9007199254740992). Construction also accepts z_levels=[2**53, 2**53 + 1, 2**53 + 2], then converts the first two boundaries to the same float; coordinates() subsequently rejects the constructed grid. Please reject precision-losing values before conversion/serialization, consistently with the existing coordinate checks, and validate the normalized boundaries.
Validation at 1fd06d1: CI passed, and 194 focused geometry, plotting and serialization tests passed locally. Please add regression coverage for these cases and complete the PR description with Testing, Risk and How to revert sections.

Reviewed f4eaa14 against develop (a7296ed). The feature is in good shape: uniform grids behave exactly as before, the codec round-trips the new field with validation, plotting honours the layers, nothing in builder or io assumes uniform spacing, and the new tests assert real contracts (coordinate values and order, wire round trip, equality, each validation error). Lint and format pass on the head, and it merges cleanly. Two things need fixing before merge, then four nits. Line numbers refer to the PR head.
1. important — dtcc_core/model/geometry/grid.py:247-250 and :303: two float comparisons reject ordinary input.
The agreement check between z_levels and explicit vertical bounds is exact, but from_zsteps builds the levels with np.cumsum. Ten layers of 0.1 sum to 0.9999999999999999 that way, and [0.1, 0.2] to 0.30000000000000004, so a grid from from_zsteps raises "z_levels must match vertical bounds" as soon as the domain is assigned from outside, which is the existing pattern (scripts/generate_fields.py:53 does grid.bounds = bounds.copy()), either at assignment or at the next coordinates() or to_proto().
zstep accepts layered grids only when the thicknesses agree within rtol=1e-12, but the thicknesses are differences of absolute elevations, whose rounding grows with the elevation. from_zsteps([0.1]*10, zmin=1000).zstep raises "nonuniform z spacing"; so do 0.01 m layers at 100 m and 0.1 m layers at 5000 m. At 0, 10 and 100 m with 0.1 m layers it passes.
Both raise rather than produce wrong geometry, but both make the new helper unusable for ordinary decimal thicknesses. Scale the tolerance to the elevation magnitude in both places (for example atol = k * eps * max(abs(levels))), and add tests for from_zsteps([0.1]*10) with explicit zmax=1.0 and for from_zsteps([0.1]*10, zmin=1000).zstep.
2. important — the description against AGENTS.md. It is one sentence; Testing, Risk and How to revert are absent. The PR changes dtcc_core/schemas/dtcc.proto:214-215 and dtcc_core/model/dtcc_pb2.py, a sensitive path, which adds the manual check (one demo end to end) to Testing, needs approval from a human other than the operator, and needs Risk to say so. Risk should also state what older readers do with a .dtcc file carrying z_levels: every build since 2026-09-12 raises "Canonical payload contains unsupported fields" (the guard at dtcc_core/model/exchange.py:1190-1196), older builds silently read a uniform grid, and reverting the merge commit does not make such files readable again. The description should also name the new public API (z_levels, from_zsteps, zsteps) and that zstep now raises for nonuniform layers. CI ran on Ubuntu only; the change is floating-point handling, so add the full-ci label before it is marked ready.
Nits:
grid.py:165 and :194: subclass equality. z_levels is compare=False and the layer comparison lives only in the hand-written __eq__, so a @dataclass subclass regenerates __eq__ without the layers: two subclass grids with levels [0, 1, 3] and [0, 2, 3] compare equal. And fields(self) makes an eq=False subclass compare its own extra fields, which the generated base __eq__ did not. No subclass exists in this repository. Dropping compare=False makes a generated subclass __eq__ raise on the arrays instead of ignoring them, and fields(VolumeGrid) keeps the compared set as before.
grid.py:178 and :228: the precision guard at :241-244 runs after conversion. A mixed list such as [0.0, 2**53 + 1, 2**54] is promoted to float64 first and accepted with the middle level stored as 253, and from_zsteps([2**53 + 1] * 2) accumulates in float and stores [0, 2**53, 2**54], while the homogeneous integer case the guard targets raises. No real elevation is near 253, so either check before converting or drop the guard.
dtcc_core/model/dtcc_pb2.py:5: the regenerated module declares protoc 5.28.1 where the previous one was 5.29.0; scripts/build_proto runs whatever protoc is on PATH. The descriptor itself is right (the old descriptor plus field 5, repeated double) and loads under the pinned runtime. Regenerate with 5.29 or newer, or accept the header moving backwards.
docs/design/model-inventory.md:81 lists VolumeGrid's native state as width, height, depth and bounds; the layers are now native, wire-carried state.
Pre-existing, not introduced here: two independently constructed grids cannot be compared at all, because Transform is a dataclass whose generated __eq__ compares the affine arrays and raises. The new equality tests share the transform through replace, which is why they pass.
Verified: ruff check and ruff format --check on the head; a clean merge with develop, and no commit on develop since the merge base touching the seven files; the numbers above with the PR's own expressions under NumPy 2.5; the head's dtcc_pb2.py loaded under protobuf 5.29.6 with field 5 present and round-tripped; the decoder's unknown-field guard and the commit that introduced it; a search for every consumer of VolumeGrid and vertical spacing in dtcc_core and scripts. Not run: the test suite, a demo, macOS or Windows, or an exact regeneration with scripts/build_proto; this machine cannot build the extension.
