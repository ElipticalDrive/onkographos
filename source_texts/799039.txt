Owner
Closes #665.
Problem
The classic Metal shadow pre-pass (metal_shadows 1 with no studio rig) loaded lightProj * lightView as the PROJECTION and kept the camera MODELVIEW. VBO geometry was correct. Sphere and cylinder impostors, however, build their billboard or box and cast their ray in camera eye space. When light is far from the view axis, a sphere billboard is nearly edge-on from the light. Spheres then cast a sliver or no shadow, and sticks cast a ragged strip and speckle themselves (see the evidence comment).
Fix
SceneBuildLightViewProjEye (layer1/SceneRender.cpp) now returns the light view and the orthographic light projection separately. The classic pre-pass opens with beginShadowPass(glm::value_ptr(lightView)), then loads lightProj and the camera modelview. The post pass still gets lightProj * lightView, so receivers sample the map exactly as before.
RendererMetal::beginShadowPass(view) stores the view in _lightShadowView and sets _classicShadowViewOpen. endShadowPass and beginFrame clear it. loadMatrixf and loadIdentity premultiply the view while shadowCasterViewOpen() is true, which covers a studio slice or the classic map. This is the studio-map mechanism from Lighting 6/17: Per-light shadow maps #616.
Impostors ray-cast with u.ortho = 1 in the classic map, because its projection is glm::ortho. Studio slices keep 0 because they are perspective. The issue suggested 0, but that only fits the studio maps.
Renderer::beginShadowPass takes the view. The GL default is still a no-op.
Found in code review: SceneBuildLightViewProjEye chose lookAt's up from Ldir.z alone. For a light straight above or below (light [0, -1, 0]), up was parallel to the light, the view was NaN and the frame had no classic shadow. Up is now +x when |Ldir.y| > 0.95, the rule the studio maps use (LightShadows.cpp). Every other light keeps its old up, so those maps are unchanged.
Tests
New XCTest ClassicShadowImpostorCasterTests (appended to LightsAtmosphereLiveTests.swift). The light is along +x (light [-1, 0, 0.1]), nearly perpendicular to the view. Each test checks that a box on the light-facing side of a big sphere is at least 30 levels darker with metal_shadows 1 than with 0. The box is located from the sphere's silhouette.
Sphere caster: master gives 221 vs 221 (fails). This PR gives 221 vs 122.
Stick caster, orthographic camera, stick nearly along the view axis, boxes 2-3 Å above and below the axis strip: master gives 156 vs 156 in both boxes (fails). This PR gives 156 vs 86.
Light straight above (light [0, -1, 0]), a sphere above the big sphere: without the up fix 224 vs 224 (fails). With it, 224 vs 123.
The first two were run against a master core and fail there. The overhead test was run against this branch's core without the up fix and fails there. All 3 pass on this branch, as do ClassicShadowMapLazyTests and StudioShadowMapCacheTests (11/11).
Full macOS unit suite on this branch's core, before the up fix: 1637 tests, 4 skipped, 1 failure. The failure is SurfacePickTests.testLiveGeometryOnlyTheAppBuilds ("no interior cap down the open bond"). It fails the same way on a master core, so it is not caused by this PR.
Embedded Python tests: all 70 raymol files in the CI list, 1804 tests OK (3 skipped), on a pymol built from this branch. Source pins were updated on purpose:
lighting_shadow_msl.py: MASTER_CLASSIC re-pinned. The premultiply and u.ortho pins now cover the classic map. New class TestClassicShadowCastersFaceTheLight.
lighting_msl.py and lighting_air_msl.py: the beginFrame and SceneRenderMetal digests.
iOS simulator build (own iOS core): BUILD SUCCEEDED.
Not covered: the GL renderer (no classic Metal pass) and grid mode (the classic pass is skipped there, as before).
Notes
The Copilot review quota was used up, so the code-review skill reviewed the PR instead.
Fixed after the first review: the NaN light view (above) and the 80-column lines.
Fixed after the second review: the overhead scan's run end (image height, not width), a one-row offset in its box, the long comment lines, and the helper's failure messages.
Not changed, because they predate this PR and no path triggers them today: beginShadowPass's encoder is not Load-safe if something reopens it mid-pass.
Not changed, by choice:
Deriving u.ortho from _projectionMatrix[15], or using _shadowMode in place of the explicit caster-view flag. The explicit flags follow Lighting 6/17: Per-light shadow maps #616's _lightShadowSlotOpen design and its pins.
Reducing the up rule to |Ldir.y| alone. That would rotate the existing maps of lights near the view axis.
Sharing a PNG-decode helper across the test files. That is a separate cleanup.
The implementation was drafted by Gemini 3.8 Flash (via claude-gemini), then reviewed and verified by Claude.
Unrelated, found while writing the test: in an orthographic camera, a stick exactly parallel to the view axis is invisible in the camera pass. Its impostor rays run parallel to the axis. The test tilts the stick slightly.
