Why
Gaussian Splatting is the dominant new 3D asset format of 2024–2026 (Polycam, Luma, Postshot, Scaniverse, every recent phone). PolyFlow's tagline is "WebGPU-powered in-browser asset viewer and optimization sandbox" — splats belong here.
Three reasons this is uniquely a PolyFlow win:
WebGPU compute sort. Every existing browser splat viewer was WebGL until very recently and fakes the per-frame depth sort. WebGPU compute shaders do bitonic/radix sort 5–10× faster. Starting from a WebGPU base, we'd ship one of the fastest browser viewers as a structural advantage.
Engine integration nobody has done. Every existing splat viewer is just a viewer. PolyFlow already has DDGI lighting, Jolt physics, scene editor, blueprint authoring, UE-style scripting (BeginPlay/Tick), multiplayer, and first-person mode. "Walk through your phone scan with friends, in VR, with NPCs and physics" does not exist anywhere — and we're set up to be first.
Real commercial and viral pull. Real-estate tours, retail showrooms, location scouting, museum exhibits, training sims — every one is splat-plus-interactivity. Anyone with an iPhone can scan their kitchen in 90 seconds; the resulting demo writes its own tweet.
Phased plan
Phase 1 — MVP loader + renderer ✅ shipped in bdef357
src/world/splat/splatRenderer.js — .splat parser, InstancedBufferGeometry builder, TSL vertexNode (3D→2D covariance + eigendecomposition + quad expansion) and colorNode (2D Gaussian alpha). ~190 lines.
src/world/splat/README.md — architecture, byte layout, test instructions, roadmap.
(Phase 1.5 / Phase 2 wire-up) init.js + ?splat=<url> URL hook. Two-line drop-in for main.js.
Test against huggingface.co/cakewalk/splat-data/nike.splat (~250K splats).
Validate TSL syntax under Three.js 0.184. Most likely friction: mat3.element(0) for column access — fall back to JS-side helper uniforms if needed.
Performance target: 1M splats @ 60fps on M2 / RTX 4060 (sort-free).
Phase 2 — Editor + persistence integration 🟡 mostly shipped in cbbd683
SplatComponent extends ActorComponent with async load lifecycle, dispose-on-endPlay, PCA-fit bounds, toJSON.
createSplatActor factory — mirrors createPhysicsActor pattern (Actor with kind='splat' + TransformComponent + SplatComponent).
serializeSplatActor / deserializeSplatActor — module-local round-trip working; produces { kind, id, name, transform, userData, components } JSON.
Renderer transform fix: W = mat3(view·model) so SplatActors with non-identity transforms produce correctly-shaped ellipses.
addSplatActorToSceneSystem convenience.
Wire serializeSplatActor into src/world/sceneSerialization.js so splats round-trip with the rest of the scene.
Show in Library / asset browser.
Selection outline that uses the PCA bounds.
Phase 3 — Performance pass
WebGPU compute depth sort (bitonic for ≤1M splats; radix for larger). Per-frame.
Frustum + tile-based culling.
Distance-based LOD with meshoptimizer clustering (already a project dep).
Hook into perf-toggle PR Performance toggle: pause DDGI / volumetric fog / post-process FX #14 (cap splat count under "Performance mode").
Web Worker sort fallback for browsers without WebGPU compute (Safari).
Performance target: 5M splats @ 30fps, < 1GB GPU memory.
Phase 4 — Physics collision proxy
Voxelize splat positions on a configurable grid (default 5–10cm).
Marching cubes → mesh → physics/core.js::createStaticMeshBody.
Optional companion .glb mesh path (when the photogrammetry pipeline produces one).
"Generate Collision" button in the inspector; cache proxy mesh next to splat.
Phase 5 — DDGI lighting integration (research)
Genuinely novel — nobody has shipped splat-DDGI yet. Two candidate approaches, ship Approach B by default:
A. Runtime probe sampling in fragment shader. Cheap; breaks splats' baked-in lighting unless capture-time conditions can be subtracted.
B. SH bake-down: at load time, modulate splat SH coefficients against DDGI probe grid. Slow to bake (one-time), correct at runtime.
"Use scene lighting" toggle (off = captured lighting, on = relit by DDGI).
Test scenes: outdoor capture in studio, indoor capture outdoors, neutral-lit hero asset.
Phase 6 — Capture-to-walk loop
Embedded "How to capture" guide pointing at Polycam / Luma / Scaniverse.
Drag-drop ingest in the file browser via objectLoader.js integration.
Optional cloud handoff to nerfstudio / Postshot endpoint.
