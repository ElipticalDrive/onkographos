The @ModifyVariable injection is misconfigured and will likely cause the mixin to fail at runtime.
Incorrect Index: With argsOnly = true, index = 6 targets the boolean checkSides parameter. You are trying to modify the VertexConsumer parameter, which is at index = 5. This type mismatch will cause a ClassCastException. It's safer to use ordinal = 0 to target the first VertexConsumer argument.
Incorrect Handler Signature: The handler method colorvariants$wrapConsumer has an extra VertexConsumer consumerArg parameter. A @ModifyVariable handler receives the variable to be modified as its first parameter, and can optionally receive any of the original method's arguments after that. The current signature has 11 parameters, but the target method only has 10.
Here is a corrected implementation that only captures the arguments it needs, making it more robust:
Suggested change
@org.spongepowered.asm.mixin.injection.ModifyVariable(
method = "tesselateBlock",
at = @At("HEAD"),
argsOnly = true,
index = 6 // VertexConsumer consumer is the 6th arg (1 level, 2 model, 3 state, 4 pos, 5 poseStack, 6 consumer)
)

The current implementation of putBulkData creates a new BakedQuad and a new vertex array on every call. This leads to unnecessary object allocations and can impact rendering performance, especially when many colored blocks are on screen.
You can avoid this by falling back to the default VertexConsumer logic which decomposes the quad into individual vertex calls. Since you've correctly overridden color() and other methods to delegate, this will work as intended and be more performant than the current approach.
