```

        'type': 'perspective',

                up=[0, 1, 0]
        ),
        'emitter': {
            'type': 'area',
            'radiance': {
                'type': 'rgb',
                'value': 10.0,
            }
        }
    },
    'plane': {

apply_transformation(params, opt)
```

Hi @XiaomingY,
We can specify a smaller proj_seed_spp to avoid running out of memory in the guiding initialization stage.
```
integrator.proj_seed_spp = 128  # or even 4
```
Internally, we have some hardcoded hyperparameters for the octree data structure. In this simple scene, where all primal rays are projected as valid and high-contribution boundary rays, the default parameter leads to excessive storage usage.
Sorry for the misleading error message.
Aside:
It's a bit overkill to run projective / PSDR algorithms on this scene.
To optimize a moving emitter, we can apply a change of variable to avoid the discontinuity issue. That is, with some small changes, we can make a normal direct integrator unbiased for such optimization.
The main challenge of the discontinuity problem lies in the occluded background from visibility changes --- in the case of an evolving emitter, the background is simply dark (0 radiance).
