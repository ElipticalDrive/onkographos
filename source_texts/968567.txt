Summary
This PR adds geometry and tessellation stages to vio_shader, then builds layered rendering on top of them. Layered rendering gives single-pass cube shadows and cascaded shadow maps; it covers phases 1–4 of GEOMETRY-STAGES-PLAN.md.
It runs on OpenGL, D3D11, D3D12, Vulkan and Metal. Metal has no geometry stage, so layers and viewports are picked from the vertex stage there.
On the way, the PR closes the remaining backend gaps:
Vulkan: texture updates, storage images and async compute.
Metal: stencil, layered targets and multiple viewports.
D3D: gl_in[].gl_Position / gl_InvocationID in GLSL geometry stages.
Geometry / tessellation stages
API:
vio_shader() takes 'geometry', and 'tess_control' + 'tess_eval' as a pair.
vio_pipeline() gets 'patch_vertices' and VIO_PATCHES. Tessellation stages imply it; without them it is refused.
vio_shader_reflect() reports the extra stages.
Refusal: A stage is refused (warning + false) when the backend reports VIO_FEATURE_GEOMETRY / _TESSELLATION as 0. Audit gate 099 is unchanged.
OpenGL: All stages go into one program. The program-binary cache key covers all five stages.
Vulkan: Native SPIR-V stages.
Varyings are matched along VS → TCS → TES → GS → FS.
The clip-space fixup goes only into the last stage that writes the position (GS: before every EmitVertex()).
Extra stages keep their default uniform blocks on dynamic bindings 30–32; pipelines use a patch list plus tessellation state.
D3D11/D3D12: gs/hs/ds_5_x are built from SPIR-V and compiled through the cached path (DXIL under shader_model => 6).
The flags come from a SPIRV-Cross + FXC probe.
Geometry works. Hull/domain do not: SPIRV-Cross has no HLSL tessellation backend, so on D3D tessellation goes through the HLSL override (phase 3).
Fix: SPIRV-Cross placed the GS depth remap after every Append. GS output therefore kept GL depth, and everything with z < 0 was clipped. Each appended vertex is now converted.
New: SPIRV-Cross's HLSL backend rejects gl_in[i].gl_Position and gl_InvocationID. vio rewrites the module before transpiling: the position becomes an SV_Position input, and gl_InvocationID comes from SV_GSInstanceID + [instance(N)]. Plain GLSL geometry shaders and GS instancing now work on D3D without an override, so VIO_FEATURE_GEOMETRY_INSTANCING is 1 there.
Metal tessellation (phase 4):
The vertex stage runs as a compute kernel, one thread per vertex × instance.
The control stage runs as a kernel with one threadgroup per patch. It writes the control points, patch constants and half-precision tessellation factors.
The evaluation stage becomes a [[patch]] vertex function after drawPatches.
The kernels run in a command buffer committed ahead of the frame. After an async dispatch in the same frame they go into the frame buffer instead, and the draw's textures and viewports are restored.
Indexed draws are de-indexed on the CPU. vio_draw_indirect reads the records on the CPU, and vio_draw_instanced_from_buffer binds the SSBO in the vertex kernel.
Not supported: isolines and point_mode.
The SPIR-V → MSL transpiler moved into the plain-C header vio_metal_msl.h, so its output can be checked against SPIRV-Cross without a Mac.
Layered rendering (phase 1)
1a – array targets: vio_render_target(['layers' => N]) creates 2D array targets (colour or depth_only); 'cube' + 'depth_only' creates a depth cube.
Each layer can be bound, read back, and sampled through sampler2DArray / vio_render_target_cubemap.
Flag: VIO_FEATURE_RENDER_TARGET_LAYERED.
1b/1c – all layers: vio_bind_render_target($ctx, $rt, VIO_RT_ALL_LAYERS) binds every layer at once.
gl_Layer from the GS, or from the VS with VIO_FEATURE_VERTEX_LAYER, picks the destination.
vio_clear clears all layers.
Flags: VIO_FEATURE_LAYERED_RENDER / _VERTEX_LAYER.
1d – viewports: vio_viewports($ctx, [[x, y, w, h], …]) sets up to 16 viewports, picked with gl_ViewportIndex.
Flag: VIO_FEATURE_MULTI_VIEWPORT.
Vulkan sets all of a pipeline's max_viewports viewports before each draw.
Metal:
2DArray colour + depth, Depth32Float cubes; colour cubes now get a cube depth.
renderTargetArrayLength plus [[render_target_array_index]] / [[viewport_array_index]] from the vertex function, and setViewports:count:.
Requires the Mac2 / Apple5 GPU family.
vio adds the #extension that SPIRV-Cross omits for gl_ViewportIndex in the VS.
Phase 2 – GS instancing and adjacency
GS instancing: VIO_FEATURE_GEOMETRY_INSTANCING covers layout(invocations = N) on OpenGL (4.0 / ARB_gpu_shader5), Vulkan, and now D3D (see above).
Adjacency topologies: VIO_LINES_ADJACENCY / _LINE_STRIP_ / VIO_TRIANGLES_ADJACENCY / _TRIANGLE_STRIP_ on every backend with a geometry stage.
Adjacency index buffer: vio_mesh(['adjacency' => true]) builds it.
Edges are matched by vertex position, so meshes that duplicate vertices per face still find their neighbours.
An open edge repeats the triangle's own opposite vertex.
Phase 3 – HLSL stage overrides (D3D tessellation)
vio_shader(['hlsl' => ['tess_control' | 'tess_eval' | 'geometry' => src]]): D3D11/D3D12 compile the given HLSL instead of the transpiled GLSL stage. New flag: VIO_FEATURE_HLSL_STAGE_OVERRIDE.
The GLSL stage stays required: GL, Vulkan and Metal use it, and it defines the uniform layout. D3DReflect warns when the HLSL register(b0) cbuffer does not match those uniforms.
The override also compiles under shader model 6 (DXIL).
Backend gaps closed
Vulkan:
vio_texture_update: staging buffer + transient command buffer into level 0.
Storage images: the compute descriptor layout comes from the kernel's reflection, and 'storage' => true images live in GENERAL.
['async' => true]: the dispatch is recorded into the frame command buffer; the pass is closed, fenced by barriers, and resumed with LOAD. Every dispatch gets its own descriptor set and a params snapshot. vio_compute_wait inside a frame submits the frame so far and reopens it.
Vulkan render targets: re-binding a target used to clear it (loadOp CLEAR, depth DONT_CARE). Passes now LOAD/STORE with steady image layouts, as on GL/D3D.
Metal stencil: the swapchain and colour targets use Depth32Float_Stencil8. Pipelines build a stencil state plus a stencil-less one for targets without the plane.
OpenGL comparison sampling: sampler*Shadow was undefined (no GL_TEXTURE_COMPARE_MODE) and returned the raw depth. A comparison sampler object (LEQUAL, linear) is now bound per draw. D3D11 depth cubes and Metal cubes get one for samplerCubeShadow.
OpenGL batch: vio_submit_batch never bound a record's pipeline (it compared backend_pipeline, which is always NULL there).
OpenGL indirect: vio_draw_indirect now uses the pipeline topology instead of GL_TRIANGLES.
CI
macOS runs brew update before installing and stops if spirv-cross is older than 1.4.363.0. The runner image had installed 1.4.357.0 from stale metadata.
Test 094 runs again (the MSL struct-array stride fix, MSL: Fix layout of struct arrays whose ArrayStride exceeds the packed struct size KhronosGroup/SPIRV-Cross#2678); the skip env and deps-patches/ are removed.
Test 143 joins the WARP list.

vio_shader() takes three optional stages next to vertex/fragment:
'geometry', and 'tess_control' + 'tess_eval' (always a pair). vio_pipeline()
gains 'patch_vertices' (1..32, default 3) and the VIO_PATCHES topology; a
pipeline whose shader has tessellation stages always draws patches.
vio_shader_reflect() reports the extra stages under the same keys.

The stage is refused up front (warning + false) when the backend reports
VIO_FEATURE_GEOMETRY / VIO_FEATURE_TESSELLATION as 0, so no backend ever sees
a stage it cannot compile and php_vio.c grows no backend branch (audit gate
099 unchanged).

OpenGL: all stages link into one program (vio_opengl_compile_program). Mesh
draws now use the bound pipeline's topology instead of a hard-coded
GL_TRIANGLES, so VIO_POINTS / VIO_LINES / VIO_PATCHES take effect on GL too
(the topology is stored as vio_topology, not GLenum: GL_POINTS is 0). A
uniform declared in several stages is emitted by SPIRV-Cross as one struct
uniform per stage (_19.u_mvp, _27.u_mvp); set_uniform now writes every match.

D3D11/D3D12: SPIR-V -> HLSL gs/hs/ds_5_0|5_1. The GL->D3D depth fixup is
applied only in the last position-writing stage (vio_spirv_to_hlsl_ex),
otherwise SPIRV-Cross converts once per stage. Each extra stage has its own
constant block (vio_shader_stage_cb) bound through the new vtable slot
bind_stage_constants (D3D11: GS/HS/DSSetConstantBuffers b0; D3D12: a root
CBV slice from the per-frame ring). The D3D12 root signature grows by
per-visibility mirrors of the CBV, SRV table and sampler table for
GEOMETRY/HULL/DOMAIN (VIO_D3D12_RP_*), re-pointed at flush time; D3D11
mirrors texture binds into the extra stages. bind_pipeline explicitly
unbinds absent stages so a previous pipeline's GS cannot linger.

The D3D flags are honest: they are 1 only when the linked SPIRV-Cross emits
HLSL for the stage AND FXC accepts it (vio_hlsl_stage_supported +
d3d1x_stage_supported, probed once per process; VIO_DEBUG_STAGE_PROBE=1
prints the reason). SPIRV-Cross main (2026-09) emits geometry shaders only
when input positions come from user varyings - gl_in[].gl_Position leaves an
unresolved gl_in behind - and has no hull/domain emission at all, so on
Direct3D geometry works with the varying pattern (verified on D3D11/D3D12
WARP against a SPIRV-Cross main build) and tessellation reports 0. The
Vulkan SDK 1.3.296 on the Windows CI predates both, so tests 109/110 skip on
D3D there; tests/core/074 no longer pins these two flags for D3D.

Tests: tests/render3d/109 (point -> quad via GS, GS uniform, unbind
regression) and 110 (quad patch -> disc whose edge count follows the TCS
uniform u_level) iterate over opengl/d3d11/d3d12/metal. Gallery scenes
geometry_shader and tessellation added to examples/gallery.php.

feat(vulkan): geometry and tessellation stages
…
1362f9c
```
The Vulkan 3D pipeline accepts the optional vio_shader stages that OpenGL
and D3D already had. Vulkan consumes the SPIR-V natively, so it has none of
the SPIRV-Cross HLSL limits: geometry shaders may read gl_in[].gl_Position
and tessellation works. VIO_FEATURE_GEOMETRY / TESSELLATION follow the
device features geometryShader / tessellationShader, which are now enabled
at device creation (plus shaderTessellationAndGeometryPointSize when
available).

- Shader round trip: every stage goes SPIR-V -> Vulkan GLSL -> SPIR-V in
  pipeline order VS -> TCS -> TES -> GS -> FS. Varying locations are matched
  by name along the whole chain instead of only VS -> FS.
- The clip-space fixup (y = -y, z = (z + w) / 2) moves to the last stage that
  writes gl_Position: in front of every EmitVertex() in a geometry shader,
  at the end of main in a tessellation-evaluation shader, otherwise in the
  vertex shader as before.
- The default uniform blocks of the extra stages get dynamic bindings 30..32
  in the per-frame upload ring; the new bind_stage_constants slot uploads
  them like push_cbuffers does for VS / FS.
- Pipelines carry all stages, use PATCH_LIST plus a tessellation state
  (patch_vertices) when tessellation stages are present, and keep the stages
  in every render-pass / format / sample-count variant.
- Samplers that only an extra stage declares are appended to the GL-unit map
  in the same order php_vio.c merges them.
- Shader-cache keys of each stage hash the SPIR-V of all earlier stages and
  whether the stage carries the fixup: the same vertex SPIR-V compiles
  differently with and without a geometry stage.

Tests 109 and 110 now iterate over Vulkan as well; 074 no longer pins the two
device-dependent flags for Vulkan. Both tests pass on an RTX 2080 with the
Khronos validation layer enabled and no messages.

DXBC cache that VS / PS use since the shader-cache feature. On D3D12 with

feat(render-target): array and depth-cube render targets
…
df29559
```
vio_render_target(['layers' => N]) creates a 2D array target (2..64 layers,
colour or depth_only, every layer with its own depth), and 'cube' together
with 'depth_only' now creates a depth cube instead of being refused. Both are
gated on the new VIO_FEATURE_RENDER_TARGET_LAYERED. They are the building
blocks for single-pass point-light and cascaded shadow maps
(GEOMETRY-STAGES-PLAN Phase 1a); for now one layer is bound at a time.

- vio_bind_render_target($ctx, $rt, $layer) and vio_read_render_target($rt,
  $layer) take an array layer where they took a cube face.
- vio_render_target_texture() hands an array out as sampler2DArray
  (is_array); a cube target is refused there and goes through
  vio_render_target_cubemap(), which now also wraps a depth cube.
- Arrays are single attachment, single-sampled and have no mip chain;
  vio_generate_mipmaps() returns false for them.

OpenGL: cube and array targets share one path. Colour and depth both carry
the layer structure (GL_TEXTURE_2D_ARRAY / cubemap with DEPTH24_STENCIL8), and
a layer is attached with glFramebufferTextureLayer or the cube-face target.
The colour cube's depth changes from one shared 2D texture to a depth cube,
so every face has its own depth, which a later layered bind needs.

Test 090 now expects a depth cube to be refused only when the backend lacks
the feature.

feat(shader): GS instancing flag and adjacency topologies
…
b2c573b
```
VIO_FEATURE_GEOMETRY_INSTANCING says whether layout(invocations = N) works,
running the geometry stage N times per primitive (gl_InvocationID), e.g. one
invocation per cube face together with gl_Layer.

- OpenGL: GL 4.0 or ARB_gpu_shader5.
- Vulkan: implied by geometryShader (maxGeometryShaderInvocations >= 32).
- D3D11/D3D12: a new probe variant (VIO_PROBE_GS_INSTANCED) runs a canonical
  instanced GS through SPIRV-Cross and FXC. SPIRV-Cross cannot emit
  gl_InvocationID for an HLSL geometry shader ("Unsupported builtin in HLSL:
  8"), so the flag is 0 there today and turns on by itself once it can. On
  D3D a loop in the GS covers the same cases (test 137).

VIO_LINES_ADJACENCY, VIO_LINE_STRIP_ADJACENCY, VIO_TRIANGLES_ADJACENCY and
VIO_TRIANGLE_STRIP_ADJACENCY hand the geometry stage each primitive with its
neighbours (4 / 6 vertices) for silhouettes, outlines and shadow volumes. They
map to GL_*_ADJACENCY, D3D *_ADJ (PSO type LINE / TRIANGLE) and Vulkan
*_WITH_ADJACENCY. vio_pipeline refuses them without a geometry stage, because
only that stage sees the extra vertices.

vio_mesh(['adjacency' => true]) turns a triangle list, indexed or not, into the
TRIANGLES_ADJACENCY index buffer: per triangle a, n(ab), b, n(bc), c, n(ca).
Edges are matched by vertex position (sorted canonical ids and sorted edge
records, O(n log n)), so meshes that duplicate vertices per face still find
their neighbours. An open edge repeats the triangle's own opposite vertex.

fix(vulkan): re-binding a render target keeps colour and depth

```
Vulkan render-target passes used loadOp CLEAR with an UNDEFINED initial
layout, and the depth of colour targets was stored with DONT_CARE. Every bind

feat(metal): tessellation stages via compute kernels and drawPatches
…
33002eb
```
Metal has no hull or domain stages, so VIO_FEATURE_TESSELLATION was 0
there. A shader with tess_control + tess_eval now compiles into three
parts:
- the vertex stage as a compute kernel (SPIRV-Cross
  vertex_for_tessellation), one thread per (vertex, instance), with a
  stage-input descriptor per mesh stride;
- the control stage as a kernel (multi_patch_workgroup), a threadgroup
  per patch, writing control points, patch constants and half-precision
  tessellation factors;
- the evaluation stage as a [[patch]] post-tessellation vertex function
  that reads the control points from those buffers
  (raw_buffer_tese_input).

ahead of the frame's, into ring slices, then calls drawPatches on the
open render encoder, so bound textures, viewport and scissor stay.
Indexed draws are de-indexed on the CPU (mesh buffers are Shared).

- The control kernel writes the factor struct of the evaluation
  stage's domain, so the TES domain is set on the TCS compiler. The TES
  gets the TCS output vertex count.
- gl_TessCoord keeps the GL lower-left origin, with the winding
  mirrored to match.
- Isolines, point_mode, indirect draws and storage-instanced draws of
  tessellation pipelines are refused with a warning.
- The stage constant blocks reach Metal through bind_stage_constants.

SPIRV-Cross without a Mac. Test 074 pins TESSELLATION = COMPUTE and

feat(vulkan): texture updates, storage images and async compute in th…
…
39652e8
```
…e frame

Vulkan was the only backend without vio_texture_update and storage
images, and its async dispatches ran synchronously.

- vio_texture_update copies a region into level 0 of a 2D texture
  through a staging buffer on the transient command buffer. Queue
  order and a shader-read -> transfer -> shader-read barrier cover
  frames in flight; every draw of the open frame sees the new texels.
- Compute pipelines take their descriptor-set layout from the kernel's
  reflection (storage buffers, storage images and the params UBO at
  their own bindings) instead of the fixed SSBO 0/1 + UBO 2 contract.
- 'storage' => true textures get STORAGE usage, start zeroed and live
  in GENERAL, so imageStore and sampling need no layout changes.
  vio_compute_bind_image binds them; VIO_FEATURE_STORAGE_IMAGE = 1.
- ['async' => true] inside a frame records the dispatch into the frame
  command buffer:
  - the open pass is closed, the dispatch is fenced by memory barriers
    on both sides, and the pass resumes with LOAD on the same target
    and layer, viewports restored;
  - every dispatch gets its own descriptor set from per-frame pools and
    a params snapshot in the frame upload ring.
- vio_compute_wait inside a frame submits the frame so far, waits and
  reopens it (vio_vk_flush_frame); after vio_end it drains the queue.
  vio_storage_buffer_read waits implicitly.
- Compute pipelines freed while a dispatch may be pending go through
  the frame graveyard.
