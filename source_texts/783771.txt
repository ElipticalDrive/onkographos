Description
Brings image color grids and placeholders closer to BlurHash, and adds BlurHash strings encoded from the grids we already store.
Linear-light averaging
Each grid region's colors are now averaged in linear light, weighted by opacity, so a region of fine black and white detail averages to the gray it reads as (#bcbcbc) instead of a darker one (#808080).
The server reads the scaled-down image's pixels itself (new ColorGrid::average()) instead of resampling it down to the grid size with the image driver. GD, Imagick, and libvips now produce the same grid, which matches the browser's. This also stops the grid from depending on Imagick's resampling, which is the likely source of the partly transparent cell in an opaque image that CI turned up.
The browser sampler in image-colors.ts averages the same way, so uploads send the same colors the server would find.
ImageColors' edge colors (left(), right(), top(), and bottom()) average in linear light too, so they, and the asset edit sidebar's gradient between the left and right edges, come out slightly brighter. Hex parsing and the sRGB and linear-light conversions now live in ColorGrid, which Blurhash and ImageColors share.
Smoother placeholders
Asset::getPlaceholderDataUrl() now scales the grid up three times with Catmull-Rom interpolation between the regions' centers (new ColorGrid::interpolate()), so browsers can scale it the rest of the way without visible seams between regions. That's a 12×9 PNG for a 4×3 grid, about 510 characters as a data URL, up from about 200.
Interpolation works on premultiplied colors, so transparent regions blend without tinting their neighbors.
BlurHash
New Asset::getBlurhash(), and a blurhash GraphQL field, return a BlurHash encoded from the smoothed color grid, with one component per region (4×3 for landscape and square images, and 3×4 for portrait ones). They're computed on request rather than stored.
CraftCms\Cms\Image\Blurhash is a port of the reference encoder, rather than a new dependency. It produced identical strings to the official blurhash package for landscape, portrait, random, 9×9-component, and single-pixel images, and the tests use fixed vectors from it.
BlurHash has no alpha channel, so transparent regions are blended over white.
Assets sampled before this change keep their existing grids until their files are sampled again.
