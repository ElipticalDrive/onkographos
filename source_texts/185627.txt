Octree Subdivision within Dual Contouring
While I know of the the octree simplification that is outlined here and additionally in the original Dual Contouring Paper. I wonder if anyone has any approach to octree subdivision without having to go through the separate process of simplification. What kind of heuristic do you use to determine whether the octree should be split or not?
I have the meat of the logic contained within one method called computeDirectly(OctreeNode octree) and the current approach I'm taking is as follows:
I first check to see if there are any intersections by calculating the cubeIndex (same as Marching Cubes from Paul Bourke), if the cube index is neither 255 or 0 then I proceed to generate the vertex
Vertex generation is done using Leonardo Augusto Schmitz's iterative method.
If the Vertex is not null (vertex ) then I proceed to check two conditions:
Is the current octree at a max depth
Does the current octree contain the vertex and is it within an acceptable distance to the surface:
Following code for two conditions:
```
if (octreeNode.getDepth() == maxDepth || (octreeNode.boundingBox.contains(vertex) && Math.abs(source.getValue(vertex)) < octreeNode.getCubeDiagonal() / 1000))
```
If either of those two conditions are met then I proceed to add the vertex to a list of vertices and also save the index of the vertex
If neither of these two conditions are met then vertex is set to null (vertex is not ok or above max depth) and then I go to the next stage.
The next stage is checking to see if the vertex is null (if the previous section determined that the vertex doesn't exist, or is not ideal).
Then I will proceed to check if the current octree node depth is still less than the maxDepth.
If the current octree node is less than the maxDepth I will subdivide and then recursively call the computeDirectly method for each of the children.
If the current octree node is greater than the max depth than I do nothing.
While I'm able to generate a surface I seem to be generating artefacts in the process or doesn't quite work at all:
Donut
Goursat Surface
Contoured result seems to be off
