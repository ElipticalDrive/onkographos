# Alien Landscape Lab

**▶ Live demo: https://andrifr.github.io/alien-landscape-lab/**

A visually-impressive, procedurally-generated **alien landscape rendered entirely on the GPU** with raw **WebGPU** + **WGSL** — no Three.js, no Babylon, no WebGL, no engine. The whole planet (terrain, sky, sun, stars, atmosphere, reflective liquid, glowing minerals) is computed mathematically in a single fragment shader by ray-marching a procedural height field.

## Running

```bash
npm install
npm run dev      # open the printed http://localhost:5173/ URL
npm run build    # type-check + production build into dist/
```

Requires a browser with WebGPU (recent Chrome or Edge desktop) and a working GPU. If WebGPU, an adapter, a device, or shader compilation is unavailable, a clear in-page error overlay explains what failed.

## What the GPU is doing

There is no 3D geometry. A single full-screen triangle runs the fragment shader once per pixel, and each pixel:

1. **Builds a camera ray** from the camera position/orientation.
2. **Ray-marches a height field** — steps along the ray comparing its height to `terrainH(x,z)`, a sum of value-noise octaves (fractal Brownian motion) with **domain warping**. An empty-air "ceiling" skip and a linearly-interpolated surface crossing keep it fast and artifact-free.
3. **Lights the surface** — approximates the normal by finite differences, then applies diffuse + specular sun light, a soft ray-marched shadow, sky ambient, glowing mineral veins, biome tinting, and distance fog that dissolves terrain into the sky.
4. **Intersects a liquid plane** in the low areas — water, mirror-like mercury, or emissive lava, with animated ripples and a sky reflection.
5. **Draws the sky** where no surface is hit — a gradient, a sun/celestial disc with glow, procedural twinkling stars, and horizon scattering.

Performance is kept reasonable on integrated GPUs via **dynamic resolution scaling** (the app measures its own frame rate and adjusts the internal render resolution) and reduced noise-octave counts during marching/shadowing.

## Reproducibility

A planet is fully described by a seed + a handful of scalar parameters + a preset id. Colours are a *pure function* of `(preset, seed)`, so the whole world is stored compactly in the URL hash. The same link always reproduces the same planet — use **Copy Link** to share one.

## Controls

- **Drag** the scene to look around · **mouse wheel** to change travel speed
- **Space** pause/resume · **F** fullscreen · **R** random planet
- Control panel: presets, seed, liquid type, terrain/liquid/fog/atmosphere/sun sliders, and Screenshot / Copy Link / Full Screen / Reset buttons.

## Source layout

| File | Responsibility |
|------|----------------|
| `src/main.ts` | boot, render loop, resize/DPR, dynamic resolution, input, wiring |
| `src/gpu.ts` | WebGPU init, adapter/device, device-loss, shader compilation + diagnostics |
| `src/renderer.ts` | render pipeline + per-frame draw |
| `src/camera.ts` | camera state and automatic movement |
| `src/params.ts` | parameters, seed, presets, palette generation |
| `src/uniforms.ts` | packs params/camera into the uniform buffer (vec4-slot layout) |
| `src/ui.ts` | the control panel DOM + wiring |
| `src/urlstate.ts` | URL-hash serialization / reproducibility |
| `src/screenshot.ts` | PNG capture of the WebGPU canvas |
| `src/errors.ts` | fatal-error overlay |
| `src/shaders/scene.wgsl` | **the entire scene** — noise, terrain, lighting, liquid, sky |
