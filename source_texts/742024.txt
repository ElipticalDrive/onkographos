Stacked on #191 (then #190); merge those first. This is step 3 of the 2026-10-06 plan: marching cubes is culled to the viewing camera. Fusion is already culled to the scanning cameras (#191).
Change
mesh: a new overload extract_device(grid, iso, const DeviceBlockList&, timings) meshes exactly the listed blocks.
The list is bound in place, so only its count reaches the host.
Cells at the edge of the view still read their unlisted neighbours through the hash table, so the visible region has no holes.
An empty list gives an empty mesh.
volume: a frusta list gets its own serial. A new check_device_block_subset refuses a list that a later frustum compaction rewrote (the integrator's, say), or one from another map, before a ring slot is claimed. check_device_block_list still refuses a frusta list as "the active set".
viewers: fuse_viewer and rig_viewer publish the render camera's view_proj with a serial that moves only with the view. The fuse thread:
compacts make_frustum_planes(view_proj, 0.25 m) (no margin on the near plane) and meshes that list;
re-meshes after a fuse, respecting --remesh-every, and whenever the view moved while nothing fused: orbiting a static map, fuse_viewer's replay, and rig_viewer when idle or after --sets.
Density: a culled pass now records its triangle density. The old guard only mattered while incremental and full passes shared one extractor; with the viewers only culling, the plan would have sat on the seed and refit on every extract.
Removed because only tests used them: the host-list extract_device(…, const BlockList&) overload, both host compact_active_blocks_in_frustum overloads, and ExtractTimings::input_upload_ms, since nothing is uploaded any more. BlockList, block_list and check_block_list stay for the codec, which gains a test of the refusal the removed overload used to cover.
Testing
Partition test: two frusta split a sphere grid's 216 blocks into halves of 108. Each half is meshed through the device list, and the two triangle multisets must merge back into the full mesh exactly: no holes, no duplicates at the seam.
Refusals: a rewritten list, a list from another grid, a list made stale by an allocation, and an empty list.
Density: the second culled extract does not refit.
Mutations: each failed its test: meshing the whole map whatever the list, skipping the subset check, recording no density, and never bumping the frusta serial.
M5 Max, Release, warnings as errors, viewers built, Orbbec and FFmpeg: 56/56 pass. Sync validation is clean on the marching-cubes and frustum tests.
The viewers were built but not run: there was no interactive session.
Measured
A scratch bench, not in the repo: room0 replicated along x, 12 m apart; 60 frames streamed into room 0, then the view of the last frame's camera meshed. Apple M5 Max, Release, alone on the machine, one run each. "Before" is the same bench built at #190, without either cull. Fusion is integrate's device-time median; meshing is the wall-time median of 15 extracts, including the compaction.

Two findings from the review of #192:

- The frustum compaction tested each block's voxel bounds, but a block's
  marching-cubes cells reach the next block's first voxel, a half-voxel
  past them. With the near plane unpadded, a block whose voxels lay behind
  it lost its in-view boundary triangles (all 162 of a plane at 1 cm, on
  both kernels). The box's upper corner now covers the cells, which stays
  a superset for fusion. A regression test meshes that plane through the
  view list and requires every triangle; with the old box it fails.
- rig_viewer skipped the post-fusion view loop after any failure, so a
  capture that failed after fusing left only the last culled region
  drawable. It now keeps re-meshing the view unless a frame prep or fuse
  failed; the exit code still reports the failure.
