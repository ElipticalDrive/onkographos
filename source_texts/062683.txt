Abstract
Feed-forward 3D Gaussian Splatting (FF3DGS) reconstructs 3D scenes from images in a single forward pass, making it well-suited to applications that must operate within limited resource budgets. To further improve its practicality, recent
budget-controllable FF3DGS methods allow the number of Gaussians to be adjusted at inference, so that the output meets a given storage limit or renderinglatency constraint. However, these methods overlook the cost of inference itself:
to produce a representation with the target number of Gaussians, they first predict a dense set of Gaussians and then prune or select from it, requiring nearly
constant latency and peak memory regardless of the budget. We therefore propose RLSplat, a resource-linear budget-controllable FF3DGS framework whose
representation size, inference latency, and peak memory all decrease linearly as
the Gaussian budget is reduced. Instead of pruning or selection, RLSplat learns a
Gaussian allocation policy that distributes the budget across local scene regions,
so that exactly the requested number of Gaussians is generated. These Gaussians
are then refined through resource-linear Gaussian decoding, in which each Gaussian attends only to nearby Gaussians found via an efficient hierarchical neighbor
search, so that the decoding cost decreases linearly with fewer Gaussians. In zeroshot evaluation, RLSplat outperforms prior budget-controllable methods at every
budget, surpassing the strongest baseline even with 4× fewer Gaussians, while
running up to 4.1× faster with 9.6× less peak memory at low budgets. Code is
available at https://github.com/mlvlab/RLSplat.

Introduction
3D Gaussian Splatting (3DGS) (Kerbl et al., 2023) has become a leading representation for photorealistic, real-time novel view synthesis, supporting applications from AR/VR (Qian et al., 2024;
Jiang et al., 2024) to robotics (Keetha et al., 2024; Matsuki et al., 2024) and digital content creation (Tang et al., 2024; Chen et al., 2024b). Its explicit form further allows it to serve as a 3D scene
representation for downstream models, such as 3D vision-language models (Li et al., 2025; Thai
et al., 2025). Since per-scene optimization of 3DGS takes minutes to hours and requires many calibrated views, feed-forward 3DGS (FF3DGS) methods instead predict Gaussians in a single forward
pass (Charatan et al., 2024; Chen et al., 2024a), and recent variants even operate directly on uncalibrated images (Jiang et al., 2025). Owing to this fast and readily available reconstruction, FF3DGS
has become a practical choice for applications that build 3D scene representations on the fly.

Early FF3DGS methods (Charatan et al., 2024; Chen et al., 2024a; Ye et al., 2025) simplify the problem by allocating a fixed number of Gaussians to each input pixel, which allows the feed-forward
network to be trained effectively. However, this pixel-aligned design produces many redundant
Gaussians, since Gaussians from overlapping views become increasingly redundant as more views
are added. To address this redundancy, query-based methods (An et al., 2026; Itkin et al., 2026)
decode a fixed set of learnable query tokens into Gaussians. Yet neither approach can adjust the
number of Gaussians without retraining. This lack of controllability makes it difficult to adapt to
the diverse resource budgets encountered in real-world deployment. To address this, recent works
have proposed Gaussian budget-controllable methods. Given a Gaussian budget B, EcoSplat (Park
et al., 2026) first predicts one Gaussian per pixel and keeps the B Gaussians with the highest opacity.
F4 Splat (Kim et al., 2026) instead predicts Gaussians at multiple scales and selects the B Gaussians.
However, these methods overlook the computational cost of inference itself. Both methods first predict a much larger set of candidate Gaussians before reducing them to B, so their inference latency
and peak memory remain nearly constant regardless of the budget, as shown in Fig. 1(b) and (c).
We therefore propose RLSplat, a budget-controllable FF3DGS framework that is resource-linear:
both its representation size and inference cost scale linearly with the budget B. Given uncalibrated
images and a budget B, a geometry backbone encodes the images into anchor tokens, each representing a local 3D region of the scene. To obtain a compact representation, we formulate Gaussian generation as an allocation problem rather than pruning or selection: we predict how many Gaussians to
assign to each anchor’s region, summing to B. Since these discrete allocations are non-differentiable
and can only be evaluated by rendering the resulting Gaussians, we model this prediction as a Gaussian allocation policy and train it with policy optimization, using Group Sequence Policy Optimization (GSPO) (Zheng et al., 2025) with rendering quality as the reward. Given the allocation, each
anchor token spawns as many Gaussian tokens as its allocated count, yielding a total of B Gaussian
tokens. To efficiently decode these tokens into the final Gaussians, we introduce a resource-linear
decoder. It refines each Gaussian token through local cross-attention over its Kgs nearest Gaussian
tokens, which we find with an efficient hierarchical neighbor search. Whereas global self-attention
over all B tokens costs O(B 2 ), each token here attends to only Kgs neighbors, so the decoding
cost is O(BKgs ) and scales linearly with the Gaussian budget (Fig. 1(c)). As a result, RLSplat
achieves higher quality than prior budget-controllable methods at every budget (Fig. 1(a)), while its
peak memory and latency decrease with the budget. At 2K Gaussians, it achieves higher PSNR than
F4 Splat while using 9.6× less peak memory (Fig. 1(b)) and running 4.1× faster (Fig. 1(c)).
In summary, our contributions are as follows:
• We identify that existing budget-controllable FF3DGS methods control only the size of
the output, not the cost of producing it, and introduce RLSplat, a resource-linear FF3DGS
framework in which the number of Gaussians, inference latency, and peak memory all
decrease linearly as the budget B is reduced.
2
• We formulate Gaussian generation as an allocation problem and learn a Gaussian allocation policy via policy optimization that places exactly B Gaussians where the scene needs
them, together with a resource-linear decoder whose cost decreases linearly as the budget
decreases through local cross-attention and an efficient hierarchical neighbor search.
• RLSplat consistently outperforms prior budget-controllable methods across all budgets. At
a budget of 2K Gaussians, it improves PSNR by 0.9 dB over F4 Splat while using 9.6× less
peak memory and running 4.1× faster.

Related Work
Feed-Forward 3D Gaussian Splatting. 3D Gaussian Splatting (3DGS) (Kerbl et al., 2023) represents a scene with explicit Gaussian primitives and achieves real-time rendering, but requires timeconsuming per-scene optimization from many calibrated views. Feed-forward 3DGS (FF3DGS)
methods instead predict Gaussians in a single forward pass, from a single image (Szymanowicz
et al., 2024) or from a few posed views (Charatan et al., 2024; Chen et al., 2024a; Xu et al., 2025;
Zhang et al., 2024). Building on 3D foundation models (Wang et al., 2024; Leroy et al., 2024; Wang
et al., 2025), recent methods further remove the need for known camera poses (Ye et al., 2025; Smart
et al., 2024; Huang & Mikolajczyk, 2025; Jiang et al., 2025). Most of these methods predict one
Gaussian per pixel or per voxel, so the number of Gaussians is determined by the input resolution
and the number of views rather than by the scene content. This leads to redundant Gaussians in
overlapping and textureless regions, and the number of Gaussians cannot be specified directly.
Compact and Gaussian budget-controllable FF3DGS. For per-scene 3DGS, many works aim
to represent a scene with fewer Gaussians without sacrificing quality, either by pruning redundant
Gaussians (Fan et al., 2024; Lee et al., 2024; Papantonakis et al., 2024) or by deciding where to
place Gaussians under a fixed or constrained budget during densification (Fang & Wang, 2024;
Mallick et al., 2024; Kheradmand et al., 2024). These methods, however, rely on iterative per-scene
optimization. In FF3DGS, C3G (An et al., 2026) and GlobalSplat (Itkin et al., 2026) decode a
fixed set of learnable query tokens into compact sets of Gaussians, whose size is determined by
the architecture. EcoSplat (Park et al., 2026) and F4 Splat (Kim et al., 2026) instead accept a target
count at inference, by keeping the Gaussians with the highest budget-conditioned opacity and by
selecting one of multiple scales per region, respectively; both derive the output from a dense set
of candidates. ZipSplat (Veicht et al., 2026), developed concurrently with our work, controls the
number of Gaussians by clustering visual tokens at inference. In contrast, we learn to allocate
exactly the requested number of Gaussians and decode only those, so that our inference cost scales
with the budget.
Policy optimization. Policy gradient methods (Williams, 1992; Schulman et al., 2017) optimize
non-differentiable, discrete decisions from a scalar reward, and have been applied to generative
vision models, e.g., to align diffusion models with reward functions (Black et al., 2024). Grouprelative variants such as GRPO (Shao et al., 2024) and GSPO (Zheng et al., 2025) remove the
need for a learned value function by normalizing rewards within a group of samples, and have
become standard for fine-tuning large language models. In particular, GSPO defines the importance
ratio from the likelihood of the whole sequence rather than of individual tokens, and clips it at the
sequence level. We adopt this approach to learn Gaussian allocation, treating an allocation as a
sequence of B Gaussians and using rendering quality as the reward.

Method
We present RLSplat, a feed-forward 3DGS framework whose Gaussian count and inference cost are
both controlled by a single budget B. Rather than pruning or selecting from a dense set of Gaussians,
RLSplat formulates Gaussian generation as allocation: a Gaussian allocation policy decides how
many Gaussians each local region of the scene receives (Sec. 3.2), and a resource-linear decoder
generates the allocated Gaussians and efficiently refines them with local cross-attention (Sec. 3.3).
We begin with an overview (Sec. 3.1) and conclude with the training procedure (Sec. 3.4).

3.4
Training
We train RLSplat in two stages: base training trains the geometry backbone and decoder with
random allocations, and policy training introduces the Gaussian allocation policy and fine-tunes the
entire model with policy optimization.
Objectives. To supervise view synthesis, we apply a reconstruction loss Lrecon , combining pixelwise MSE and LPIPS between the rendered and ground-truth target views. For geometric alignment, a camera loss Lcam supervises the translation, rotation, and field-of-view of the predicted
context cameras. Additionally, a projection loss Lproj reprojects each anchor’s Gaussians toward
their source image patch. Incorporating a cheirality penalty to prevent Gaussians from landing behind the camera, Lproj effectively ties an anchor’s allocation to a specific scene region and prevents
arbitrary drift. These terms are combined with the locality regularizers (Lvor and Loffset ) previously introduced in Sec. 3.3. Finally, during the policy training stage, we activate the policy loss
Lpolicy = −Jpolicy (Eq. (4)) to optimize the discrete allocations via GSPO. The overall training
objectives are detailed in Sec. E.
Two-stage training. We train RLSplat in two stages. In base training, we train the encoder and
decoder with random allocations, and sample budgets over the full supported range. This exposes
the decoder to widely varying per-anchor counts, so that it learns to render diverse allocations before
the policy is introduced. In policy training, we add the policy head, initialized to output uniform
probabilities (Sec. B), and fine-tune the entire model with the policy loss Lpolicy . Since base training
involves no policy, there is no reference policy to regularize toward, and unlike typical RL finetuning, we do not apply a KL penalty. During this stage, budgets are sampled with a skew toward
the lower end of the range, where the choice of allocation matters most for rendering quality.

Experiments
Datasets and evaluation. We train on RealEstate10K (RE10K) (Zhou et al., 2018) with V ∈
{2, 3, 4, 6, 8, 12, 24} uncalibrated context views. To assess generalization, we evaluate the RE10Ktrained model zero-shot on ACID (Liu et al., 2021) (249 test scenes), which consists of aerial footage
of coastal and natural scenes. We follow the evaluation protocol of F4 Splat (Kim et al., 2026) at a
resolution of 256 × 256 and report PSNR, SSIM, and LPIPS together with the number of Gaussians
(#GS). To measure inference cost, we report the latency and peak VRAM of Gaussian generation,
excluding data loading, pose alignment, and rendering. All methods are run on a single RTX A6000
with a batch size of one. For each budget, we discard the first scene as warm-up, reset the peakmemory counter before each timed run, and report the mean over the test scenes.
Baselines. We mainly compare with budget-controllable methods, EcoSplat (Park et al., 2026) and
F4 Splat (Kim et al., 2026), which take a target Gaussian count as input at inference time. We evaluate
all methods at the same requested Gaussian budgets, with particular focus on the low-budget regime.
For a broader comparison, we also include budget-fixed methods, which place Gaussians uniformly,
either one per pixel (NoPoSplat (Ye et al., 2025), SPFSplat (Huang & Mikolajczyk, 2025)) or one
per voxel (AnySplat (Jiang et al., 2025)). Their Gaussian count is therefore determined by the input
resolution and the number of views, or by the voxel size, rather than chosen by the user.

4.1
Novel-view Synthesis Results
Table 1 compares RLSplat with budget-controllable methods at matched budgets of 1K, 2K, and
4K Gaussians per context view. RLSplat achieves the best LPIPS, SSIM, and PSNR at every budget
and view count. Importantly, its advantage becomes increasingly pronounced as the Gaussian budget
decreases. For example, with 8 context views, the PSNR advantage over F4 Splat grows from 0.74
dB at 4K Gaussians per view to 0.99 dB at 2K and 1.22 dB at 1K. This trend is consistent across 16
and 24 context views, demonstrating that RLSplat preserves reconstruction quality particularly well
under tight representation budgets. This robustness is consistent with how the final B Gaussians are
decoded: the baselines predict a dense set of Gaussians and then prune or select from it, whereas
RLSplat directly decodes the requested number of Gaussians and refines them through resourcelinear decoding.
For a broader comparison, Table 2 includes budget-fixed methods whose output size is determined
by the input. Despite using substantially fewer Gaussians, RLSplat outperforms all of these methods
on LPIPS, SSIM, and PSNR across all view counts. In particular, with 24 context views, RLSplat
achieves 25.58 dB PSNR using only 24K Gaussians, compared with 25.00 dB for SPFSplat using
1536K Gaussians, corresponding to 64× fewer Gaussians.

Conclusion
We presented RLSplat, a budget-controllable feed-forward 3DGS framework whose inference cost
scales linearly with the requested number of Gaussians B. A Gaussian allocation policy, trained
with GSPO, distributes exactly B Gaussians across anchors, and a resource-linear decoder refines
them through local cross-attention with a hierarchical neighbor search. On ACID, RLSplat achieves
the best rendering quality among budget-controllable methods at every tested budget. Its latency and
peak memory decrease linearly with B, and it matches or exceeds the quality of the baselines at a
fraction of their memory and latency.

A
Limitations and Future Work
Image encoding remains a fixed cost independent of B, which bounds the achievable speed-up at
small budgets. We also evaluate at a resolution of 256 × 256 and in a single cross-dataset setting.
RLSplat controls both the size of the representation and the cost of producing it. It can therefore
serve as a 3D scene representation for downstream tasks that have their own resource limits, such as
3D vision-language models and robot learning. Evaluating it on such tasks is a natural next step.
B
Allocation Policy Details
Policy head. The policy head predicts a logit ln for each anchor token, and the allocation probabilities are obtained as p = softmax(l) with l = {ln }N
n=1 . The head is LN(d) → Linear(d, h) →
SiLU → Linear(h, 1), applied per anchor token. The last linear layer is zero-initialized, so p starts
uniform.
Budget conditioning. The head is modulated by FiLM parameters (γ, η). They are predicted from
a single scalar, the log-ratio of the requested budget to the number of anchors, u = log2 (B/N ), by
Linear(1, h) → SiLU →Linear(h, 2d). The modulation is applied after the layer norm: hidden ←
hidden ⊙ 1 + tanh γ(u) + η(u). The last layer of the FiLM generator is also zero-initialized. The
ratio B/N is floored at 1/64 so that u stays finite for very small budgets.
Policy initialization at the start of policy training. The policy head does not exist during base
training. It is created with zero-initialized output layers when policy training begins, so it outputs
exactly 0 for every anchor and p is uniform at the first policy-training step. Base training’s random allocation already covers this regime, so the transition introduces no distribution shift for the
decoder.
Deterministic integer allocation. At inference, and for the reconstruction loss during policy training, the expected counts Bp are converted into an integer allocation k⋆ by systematic rounding
with a fixed phase. Anchors are laid out on a line

Training Details
Context views are loaded at 256 × 256 and bilinearly upsampled to 504 × 504 immediately before
the backbone, while target views, losses, and evaluation remain at 256 × 256. The DVLT (Burzio
et al., 2026) backbone runs 12 inference steps. Each training step draws the number of context views
V from the divisors of 24, V ∈ {2, 3, 4, 6, 8, 12, 24}, and sets the batch size to 24/V , so that every
step processes 24 context views in total regardless of V .
Base training. The encoder and decoder are trained for 40K steps with allocations drawn uniformly at random, which exposes the decoder to a wide range of per-anchor counts before any
policy is learned. The per-sample budget is sampled from a Beta distribution over [2048, 16384V ].
We use AdamW with a learning rate of 10−4 (0.1× for the backbone), 1,000 warm-up steps, and
cosine decay on 4 GPUs. The loss weights are 1.0 for MSE, 0.05 for VGG-LPIPS, 0.1 for the reprojection term and 0.05 for the cheirality term of Lproj , and 1.0 for Lvor . The offset loss Loffset is
weighted λoffset = 0.01.
Policy training. Starting from the pretrained model, all parameters are fine-tuned for 5K steps with
C = 5 rollouts per step and a rollout temperature of τ = 1.0; the render used for the reconstruction
loss is produced from the deterministic allocation of Sec. 3.2. The learning rate is reduced to 10−5 ,
with a 30× multiplier on the allocation head, and Loffset is disabled. The policy loss Lpolicy is
weighted 1.0. Each sample’s budget is drawn independently from Beta(1, 4) over the same range,
which biases training toward low budgets where allocation matters most. The total budget of a step
is capped, so that peak memory is bounded independently of the per-sample maximum.

Ablation Protocol
Each ablation changes a single component relative to its reference, except for the variant that removes both locality regularizers. Pretraining ablations (Table 3) are trained from scratch for 5K
steps, one eighth of the full schedule, with all step-dependent schedules (cosine horizon, optimizer
warm-up, view-sampler warm-up, and validation and checkpoint intervals) scaled by the same factor. We compare the full recipe with variants that remove the local refinement module, the projection
loss (both its reprojection and cheirality terms), the offset loss, or both the offset and Voronoi losses.
The neighbor match rate without the Voronoi loss is measured with the same schedule. Allocation
ablations (Tables 4 and 6) fine-tune for 1K steps from a single shared pretrained checkpoint and
vary the group size C ∈ {3, 5, 7}, the temperature τ ∈ {0.8, 1.0, 1.2}, and the allocation rule, replacing the learned policy with a uniform split or a learning-free Sobel-energy heuristic. Since a
shorter run anneals on its own cosine schedule, each variant is trained for its own horizon rather than
truncated from a longer run. All ablations are evaluated on ACID with 8 context views (249 scenes).
Allocation ablations are evaluated at B/V = 1024.
