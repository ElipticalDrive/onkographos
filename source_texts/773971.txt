Parent: #125. Priority: P0. Depends on basic pointer events for live demo; the pure math can be implemented/tested independently.
Gap
LibGibson already has ViewportState, BrailleCanvas (2×4), HalfBlockCanvas (1×2), RgbRaster, Node::canvas, layout and 3D cameras, but no shared 2D interactive world-space camera that exactly transports locations between app-owned coordinates, display pixels, subcells and terminal cells. Every scientific editor otherwise duplicates conversion math and introduces click-versus-draw skew. This is not the closed list-scroll #39 / responsive #42 problem.
Contract
Public 2D WorldViewport/coordinate-transform primitive (naming flexible) with finite invertible transform, pan, scale, viewport dimensions, pixel aspect and optional axis orientation.
Explicit mappings: world ↔ view-pixels, view-pixels ↔ cell/subcell, view rectangle ↔ visible world bounds. State 0-based origins, center-vs-edge rounding and quantization uncertainty. No false claim of precision finer than the available mouse cell.
Cursor-anchored zoom (the chosen world point stays under the same display location within quantization); geometry-local wheel or keyboard zoom; responsive resize without silently shifting world origin.
Clip before raster work; validate NaN/Inf, zero dimensions, negative/extreme scales, overflow and large coordinates; bounded work independent of enormous offscreen extents.
Grid/measurement tick hints are geometry, not a unit library; data units stay owned by consumer. A water-cell size need not be decided by LibGibson.
Tests
Property-based forward/inverse and viewport composition tests, with numerical error bounds on roundtrips and with exact integer semantics where applicable.
World-position stability under changes between Braille/half-block/ASCII and color depth; display realization changes but canonical world targets don't.
For randomized zoom/pan/resize streams, the selected world coordinate remains correct; clipping never creates a stray far-edge hit.
Tiny 1×1, 40×15, normal 80×24, ultrawide; verify negative coordinates, far-plane offsets and large finite cases don't run unbounded loops.
One public minimal Node::canvas app overlays a grid, world marker and cursor and reports coordinate/quantization discrepancies.
Non-goal: physics units, camera navigation gestures or an actual world simulator.
