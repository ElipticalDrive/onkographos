Why
The voxel primitives format (box / sphere / cylinder) could only add voxels — later shapes overwrite earlier ones, but nothing removes them. Because the grid is a sparse Dictionary<Vector3Int, byte>, there was no way to make a hole: hollow shells, windows, bores, sockets, and mouths were all unreachable.
What
Adds a cut verb that reuses any shape's geometry but removes the voxels it covers instead of filling them:
```
cut SHAPE ...          # same args as box/sphere/cylinder, but no palette KEY
```
Cuts remove voxels entirely (voxels.Remove(cell)) — they never leave a black/colour-0 cell.
Applied in document order like every other line: a cut removes whatever a prior line placed, and a later fill can refill a cut. No special end-of-pass semantics.
A cut carries no palette key, so it splices a placeholder into the key slot and dispatches through the existing box/sphere/cylinder parsers unchanged — no new geometry code, no parser signature churn.
Example now possible:
```
box W 0 0 0 6 6 6
cut box 1 1 1 4 4 4      # hollow it out
cut box 2 0 -1 2 3 8     # bore a doorway through
```
Changes
PrimitivesCodec.cs — cut dispatch + remove-vs-fill apply loop; grammar doc updated.
VoxelizationPrompts.cs — teaches the LLM the verb: grammar line, an order-dependence rule with use cases, and a hollow-box-with-doorway example.
PrimitivesPartTests.cs — 5 new tests: removal-not-recolour, hollowing a shell, sphere/cylinder carving, empty-space no-op + refill, and the missing-shape error.
Testing
Tools/run-tests.sh Tests.Voxelization — 146 passed, 0 failed. Tools/check-format.sh clean on the changed files.
