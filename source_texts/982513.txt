Alex: "can we use diffusion for the random gen". He chose both, staged:
Procedural diffusion (diffusion-limited aggregation, diffusion smoothing and erosion) in the new Rust generator, [World] New Rust terrain generator: random but realistic, nicer, chunkier (both maps) #109. In progress.
This issue: a small learned diffusion model that adds realistic relief detail, trained on real-world elevation data.
Design
Role: a detail diffusion model. Input: the coarse procedural heightmap from moc-terrain (plates, continents, DLA ranges). Output: realistic mountain, valley and coast detail at full resolution. The procedural stage keeps the guarantees (continent count and sizes, wrap, poles, playable sites); the model adds realism.
Model: a small conditional UNet trained as a DDPM, sampled with DDIM in 10–20 steps, on 64×64 or 128×128 patches. Seams are stitched with overlap and blending, and the map is cylindrical east–west.
Data: real elevation tiles from an official public source (e.g. NOAA ETOPO or NASA SRTM-derived global DEMs), normalised. Training pairs are (blurred / procedural-like coarse → real detail).
Training: PyTorch, offline tooling under rl/terrain_diffusion/ (or tools/). It uses the local NVIDIA GPU if available (needs a CUDA build of PyTorch) and falls back to CPU.
Runtime: inference in Rust (wasm), with the weights shipped as a compact file, run in a worker so generation stays off the main thread. Report the generation time per map size. Fallback: the procedural detail.
Hook: moc-terrain's "coarse heightmap → detailed heightmap" function ([World] New Rust terrain generator: random but realistic, nicer, chunkier (both maps) #109). The model plugs in there.
Approvals needed before any download or install
The dataset: exact files, URLs, sizes and licence.
A CUDA build of PyTorch: the install command and download size.
Ask Alex for each, with those details, before fetching anything.
Done when
Before/after images on several seeds show visibly more realistic relief than procedural alone.
In-browser generation fits the budget: home world under ~0.5 s, civ planet under ~5 s, both in a worker.
?seed= reproduces a map (seeded sampling).
Tests cover the Rust inference matching PyTorch outputs within tolerance, the fallback, and determinism.

Diversity: training draws classes evenly (ocean at half weight), then scales evenly within the class. So the 130 plateau patches and 458 basin patches get as much weight as the 5,335 coast patches, and flat plains and open sea cannot dominate. Each sample also gets a random crop and one of 8 rotations/flips.
Measured normalisation (game units): residual std 0.0170, coarse std 0.405, uplift reference 0.262, roughness reference 0.0352. These are stored in the weights file.
