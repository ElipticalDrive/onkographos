cod @ inversed_transform_matrix treats coordinates as row-vectors, but the provided transform matrices (e.g., translation with offsets in the last column) follow the standard column-vector convention. As a result, translations won’t be applied correctly (and rotations will be transposed). Consider clarifying the convention and changing the multiplication to match it (e.g., use cod @ inversed_transform_matrix.T when cod is [row, col, 1] row-vectors), and for general 3x3 transforms normalize by the homogeneous component before computing masks/indices.
Suggested change
remapped_cod = cod @ inversed_transform_matrix
valid_height, valid_width = image.size
valid_mask = (remapped_cod[...,0] >= 0) & (remapped_cod[..., 0] < valid_height) & \
(remapped_cod[...,1] >= 0) & (remapped_cod[..., 1] < valid_width)
remapped_cod = remapped_cod.astype(np.uint)[:, :, :2] # (x, y, pos)
safe_rows = np.clip(remapped_cod[..., 0], 0, height - 1)

remapped_cod = cod @ inversed_transform_matrix.T
homogeneous = remapped_cod[..., 2]
normalized_cod = np.zeros(remapped_cod[..., :2].shape, dtype=remapped_cod.dtype)
nonzero_homogeneous = ~np.isclose(homogeneous, 0)
normalized_cod[nonzero_homogeneous] = (
remapped_cod[nonzero_homogeneous, :2]
/ homogeneous[nonzero_homogeneous, np.newaxis]
)
valid_height, valid_width = image.size

assert_transform_matrix_valid doesn’t actually validate invertibility and always returns np.linalg.pinv(...), which can silently succeed for singular matrices and produce unexpected warps. Consider either (a) renaming it to reflect that it computes an inverse, or (b) switching to np.linalg.inv with an explicit singularity check / clearer assertion message about non-invertible transforms.
Suggested change
inversed_transform_matrix = np.linalg.pinv(transform_matrix)
try:
inversed_transform_matrix = np.linalg.inv(transform_matrix)
except np.linalg.LinAlgError as exc:
raise AssertionError('transform_matrix must be invertible.') from exc
