GOAL / WHY
Query the nearest original planar face of a polygon prism shell from a world-space ray, retaining actual native face/Surface/edge identities. Native selection foundation for #529/#540 and commercial goal503. #569 already connects actual face Models and original shared edges to display packets; this step queries original geometry rather than picking mesh triangles. It is one executable CAD feature, not a generic research task or GUI duplicate.

FROZEN FUNCTIONAL API
Add queryXYPolygonPrismShellRay(shell, { originMM, direction, maxDistanceMM }) -> result. Validate the actual unchanged567 shell first. Strict owned input/options with explicit budgets; origin finite XYZ within +/-10000 mm, direction finite three-component unit vector within norm tolerance1e-9, maxDistance finite positive<=50000 mm. Do not normalize, snap, heal or silently clamp authored/query input. This is a bounded display-selection query on the existing3..12 integerXY/+Z shell family, not arbitrary curved B-Rep or a solid classifier.
Numerical display policy is explicit: linear boundary/coincident-distance comparison1e-7 mm, parallel cosine threshold1e-12. These are query tolerances, not native construction/manufacturing tolerances or geometric certification. Invalid/nonunit/degenerate inputs reject atomically; previous shell/results remain usable. Limit/direction/tolerance policy is reported. Existing integer planar-face classification and shell validators stay unchanged.
SCOPE / OBSERVABLE ACCEPTANCE
Resolve actual world cap or lateral Model/Surface by qualified native face ID. Derive supporting plane/oriented outward normal and affine UV basis from actual Surface/D1, intersect the unit ray at distance0..maxDistance and verify actual Surface evaluation agrees with the computed point within the stated display tolerance. Lateral natural face UV domain bounds govern inclusion. Cap containment follows the original local trim-loop/edge geometry in its explicit placement, including the concave missing quadrant; implement bounded floating query containment with linear near-edge distance and winding. Do not use a bounding box as the cap region, substitute mesh triangles/563 packets, or widen566's integer-only classifier.
Return deterministic owned nearest hit data: native body/face/Surface IDs, tMM, actual pointMM, face UV, outward normal and any original global edge IDs whose qualified native Curve lies within boundary tolerance. Resolve edge association through actual567 incidence, not matching display indices. Sort by distance then native face order; return all co-nearest faces within1e-7mm instead of arbitrarily choosing a unique face at an edge/corner. Expose explicit miss, unique hit or ambiguous nearest status. A ray parallel to a plane has no isolated plane hit; report supporting-plane coplanarity separately and mark ambiguity when no isolated selection can be justified. Do not fabricate a finite hit for an infinitely coplanar ray.
Actual short demo builds real triangle/L/CW shells and calls new API. For L height6, ray origin[0.5,3,8], direction[0,0,-1] hits the original top cap at t2/Z6; origin[2,2,8] down through the missing quadrant misses. Ray[-1,3,3] in +X hits the actual lateral face at x0/t1 with outward -X normal. Ray[0,3,8] down to a top shared edge returns co-nearest cap/side boundary identity or explicit supporting-plane ambiguity, never a false unique face. A parallel/coplanar example is explicitly diagnosed. CW authored profile remains unchanged with equivalent geometric hits. Show one invalid direction or corrupted qualified reference rejecting while prior shell/result remains usable.
