What feature would you like to be added?
A native scan (prefix scan) op on Spyre. A scan op takes a tensor and a binary associative operator (e.g. add, multiply, max, min) and computes the running cumulative result along a given dimension — each output element is the result of applying the operator to all input elements up to that index.
Why is this feature needed?
Several PyTorch ops are scan ops under the hood:
torch.cumsum — prefix sum
torch.cumprod — prefix product
torch.cummax, torch.cummin — prefix max/min
torch.logcumsumexp — prefix log-sum-exp
None of these are currently supported natively on Spyre — they all fall back to CPU, which means tensor data must be moved off Spyre → CPU → back to Spyre on every call. This is expensive and breaks the compiled graph path.
Without a native scan op, each of these must be implemented individually as a workaround using existing spyre primitives.
Any alternative solution that you may want to share?
NA
Anything else we need to know?
The scan op is one of the classical parallel primitives (alongside reduce and map) and is widely used in sequence models, attention masks, and autoregressive decoding. Having it as a first-class spyre op would unblock the entire cum* family and any future op that reduces to a prefix computation.
