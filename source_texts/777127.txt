Context
pyramids' UgridDataset needs to render a 2-component vector field on an unstructured mesh — the canonical
hydrodynamic results visual. D-Flow FM writes exactly that: mesh2d_ucx / mesh2d_ucy per face and mesh2d_u1
per edge.
pyramids delegates all plotting to cleopatra and owns no matplotlib drawing code, so the capability has to exist
here before the pyramids facade can forward to it.
Problem / Current Behaviour
MeshGlyph (checked on cleopatra 0.43.0) exposes no vector-field entry point. Its public surface is:
```
DEFAULT_OPTIONS, add_features, add_labels, add_north_arrow, add_reference_map, add_relief, add_scale_bar,
add_tiles, adjust_ticks, anim, animate, apply_style, create_categorical_legend, create_color_bar,
create_figure_axes, crs, default_options, filter_kwargs, get_ticks, n_edges, n_faces, n_nodes, node_x, node_y,
nodes_per_face, option_keys, plot, plot_outline, save_animation, stamp_mark, stamp_watermark, style,
triangulation, vmax, vmin
```
ArrayGlyph has no vector/quiver method either — but VectorGlyph
(cleopatra/glyphs/gridded/vector_glyph.py, shipped in #121 / #117) already renders a (u, v) field at
arbitrary (x, y) positions as quiver / barbs / streamplot, coloured by magnitude through the shared
scalar-mapping pipeline, with thin= decimation and compose=True overlay onto a host axes. It works on
scattered 1-D points: composing a quiver anchored at face centroids over a live MeshGlyph render already
works today, including thin= and barbs. The missing piece is only the mesh-side entry point — computing the
anchors (face centroids / nodes) from the mesh topology and delegating.

Motivation Example
```
from cleopatra.glyphs.gridded.mesh_glyph import MeshGlyph

glyph = MeshGlyph(node_x, node_y, face_node_connectivity=faces)
# desired: arrows anchored at face centroids, scaled/decimated for a large mesh
glyph.plot_vector_field(u=ucx, v=ucy, kind="quiver", thin=4)
```
Proposed Solution
Add a vector-field method to MeshGlyph, consistent with the existing plot / plot_outline conventions:
```
def plot_vector_field(
    self,
    u,                      # (n_face,) or (n_node,) component
    v,
    *,
    kind: str = "quiver",   # "quiver" | "barbs"
    thin: int | None = None,
    location: str = "face", # where the components live
    ax=None,
    **kwargs,
):
    ...
```
Notes:
Anchor arrows at face centroids for face-located components, and at nodes for node-located ones.
thin=n draws every nth element so a large mesh stays legible.
Implement by delegating to VectorGlyph (or its render helpers) rather than introducing a parallel quiver
path: decimation, barbs, magnitude colorbar, and compose-over-host behaviour all exist there already. The new
work is the anchor computation and the MeshGlyph-side API/validation.
Compose with the existing backdrop helpers (add_tiles, add_relief) and the shared style/colorbar machinery.
Accept the same ax / overlay behaviour as plot, so a field can be drawn over an outline or a filled mesh.
Out of Scope
streamplot on an unstructured mesh — raise a clear error if it cannot be supported rather than approximating
it silently (consistent with VectorGlyph, whose streamplot path needs a regular grid).
Edge-located components: resolving u1 on edges to a per-face vector is the consumer's job (pyramids), unless
it is trivial to support here.
Animated vector fields (the existing animate / save_animation path can be extended separately).
Effort Estimate
Size: S–M
Rationale: a single new glyph method. Decimation, barbs, the magnitude colorbar, compose-over-host, and the
streamplot-refusal pattern are already implemented and tested in VectorGlyph; what remains is centroid/node
anchoring, the location validation, and keeping the API consistent with plot / plot_outline.
Definition of Done
MeshGlyph.plot_vector_field renders face-located (u, v) as quiver, and barbs where applicable
thin= reduces arrow density; a large mesh stays legible
works over an existing ax, and composes with add_tiles / add_relief
node-located components supported, or refused with a clear message
tests cover the new behaviour (headless / Agg)
docstrings and an example updated
all existing tests continue to pass
