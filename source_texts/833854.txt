Summary
A resident world with a baked hierarchy currently submits its flat leaf list. This change connects an opt-in, bounded HLOD cut to the actual main-view instance, depth/sort, tile COUNT/EMIT and raster path. The real Holzbank pilot selects 96,218 splats, including four parent nodes, from 252,326 leaves under an effective 120,000-splat cap. This establishes bounded submission; equal-quality speedup and large-world streaming acceptance remain open.
The implementation owns detached source snapshots and complete canonical/node-relative GPU bundles, with explicit admission, fallback and generation-aware restoration. The review fixes prevent an obsolete prepared bundle from being republished after a source/context change, preserve cleared/unapplied World3D membership when changing tau, and honor LOD-off by submitting canonical leaves. The HLOD sidecar uses binding 23, preserving binding 21 for record-loss diagnostics and 22 for draw lists. The feature remains disabled by default.

Reject stale canonical bundles when replacement admission fails
When an already-prepared world receives a new valid snapshot and the replacement exceeds the memory limit, this branch republishes the previous snapshot's canonical atlas and returns success, preventing the ordinary resident publisher from uploading the current payload. prepare_hlod_frame() subsequently detects the snapshot mismatch, but only after binding that same old canonical bundle, so its fallback still renders obsolete geometry. The allocation/readiness failure branches have the same problem. Only reuse a canonical bundle whose source and instance generations still match; otherwise invalidate the prepared route and let the current payload use the ordinary resident path.

Resubmit threshold changes only for an applied world
For a node already inside the tree with auto_apply_on_ready=false, or after clear_world(), changing the HLOD threshold calls _register_shared_renderer() directly and submits the world even though it was intentionally not applied. This can unexpectedly make the world visible or participate in scenario arbitration merely from editing a quality setting. Use _resubmit_world_submission_if_registered(), as the neighboring quality setters do, so changing the threshold updates an existing submission without creating one.
