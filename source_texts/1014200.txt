This adds gridSpatialIndex at @tanstack/charts/spatial/grid-index, an opt-in factory for the existing spatialIndex option. It returns exactly the point the default linear scan returns:
smallest squared distance
earliest point on a tie
the same maxDistance rules
the same handling of non-finite anchors
It looks up the nearest point center; it does not hit-test shapes, and the docs say so. Only the default 'nearest' focus mode reaches the hook. The axis and group modes resolve before it.
Default bundles do not change. bundle:check budgets the subpath at 1.2 KiB gzip; it measures 1.01 kB. nearest.ts is untouched, so this should not conflict with #42 or #153. If either changes point-anchor semantics, this index and its tests should follow.
Verification:
Seeded property tests compare it with nearestPoint on uniform, lattice, clustered, strip and non-finite layouts, including ties across cells.
A cell-visit counter keeps one-column and one-row grids cheap. An earlier version of this branch degraded badly on vertical strips, and this test would catch that.
A separate adversarial probe ran 129,600 queries across 16 layouts and many maxDistance values, with zero mismatches against nearestPoint. It was not committed.
pnpm performance:pointer checks every index against the linear result before timing.
typecheck, test, docs:check, bundle:check and format:check pass.

New Features
Added an optional spatial index for nearest-point lookups in dense charts. It returns results consistent with linear search, including tie-breaking and distance limits, and searches point centers rather than chart shapes. Charts remain unchanged unless the index is explicitly used.

Thanks @greglum, I found an optional improvement to the clustered-point case at 7d8c7708107ed7ed677cf5fc05bf6fc9fb8870e1.
Inlining the distance comparison inside visitCell, instead of calling visit for each member, improved my isolated query tests without changing the grid search or adding a density heuristic:
```
const index = members[slot]!
const dx = xs[index]! - x
const dy = ys[index]! - y
const distance = dx * dx + dy * dy
if (
  distance < bestDistance ||
  (distance === bestDistance && (best < 0 || index < best))
) {
  best = index
  bestDistance = distance
}
```
For 4,096 queries over 100,000 points, with half the points in a 2-pixel cluster, seven paired trial medians were 135.9 → 46.2 ms in Chromium, 192 → 57 ms in Firefox, and 58 → 42 ms in WebKit. Queries mixed near-cluster and uniform positions. These are lookup-only measurements, not chart frame times.
The prototype matched the linear scan on 22,056 edge-case queries in each browser. I also checked multiple cluster densities and positions, plus radii 0, 1, 48 and Infinity. The standalone production ESM entry changes from 1.076 to 1.110 kB gzip and 0.970 to 0.989 kB Brotli, still below the proposed new-entry gzip ceiling. Existing-entry isolation and full repository validation are not covered by this prototype.
This is a suggestion, not another correctness blocker. The documented clustered-data caveat should stay, and CI approval and full packed-consumer validation are still pending.
