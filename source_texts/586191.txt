Stacked on #61 (merge that first; this PR then retargets to master).
Storage layer. All voxel access goes through a crate-private Storage (cells, row segments, bulk ops). It picks its layout by size: one dense buffer up to 16M cells, 16³ chunks above that, where an empty or uniform chunk costs one value. A dense box that outgrows the limit converts once. Small and mid-size regions keep the dense fast path. Pure 16³ chunks everywhere cost 10–100× on thin shapes (a line of blocks makes every chunk dense), so they're only used where a dense box would be huge.

Dense paths (set_block, copy_region, rotate, flip, export) time the same as #61 in a warmed-up harness.
API (breaking, 0.12): region_block_indices now copies a window of the region's bounds into a caller buffer, with no 65,536-cell cap. JS and Kotlin keep their owned-array shape (regionBlockIndices(name, start, count)), Python's region_array fills one NumPy array, and render_regions_json reports the bounds. Region::coords_to_index/index_to_coords are gone (use bounds_cell / get_block_index).
Tests: the existing suites pass with the new layer; new tests check that chunked storage matches a reference model through writes, clears, flips, a translate and compaction, cover row crossing and growth, and cover the dense-to-chunked switch. The full release pipeline passed on this branch, including the WASM render-stream test.
