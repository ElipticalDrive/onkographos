Summary
The visible-band CPU/GPU SSIM gate (test_visible_band_cpu_gpu_ssim) renders the naive multiwavelength_path_tracer route (enableNEE=false). pkg120 (#534) added a two-sided-MIS BSDF-ray-hits-emitter w_B leg to the GPU wavefront intersectPathSlot that was not gated on enableNEE, so it fired in naive mode. The w_B leg is only valid as the complement of the NEE light-sampling leg (Veach 1997 §9.2); with no NEE it diverged the GPU bright from the CPU oracle (MultiwavelengthPathTracer::pathTrace, which accumulates emission only on bounce==0||wasSpecular).
Fix: gate the emissive else branch on enableNEE, threaded through intersectPathSlot / stageIntersectQueuedKernel / launchStageIntersectQueued and the dense / restir / snapshot callers. Naive mode now matches the CPU oracle and the pre-pkg120 wavefront. The NEE path (path_tracer, enableNEE=true) is byte-unchanged.

This is pkg153's R-drift shared mechanism (same scene family, own quarantined bisect). This fix does not move it (it only removes the light-quad w_B term, which is zero under the black-bg control).
