EdgeExtractor.extractEdges (packages/drawing-2d/src/edge-extractor.ts) keys its adjacency map by vertex buffer index (registerEdge: ${minIdx}:${maxIdx}). Meshes that repeat a vertex per triangle or per face never share an index across adjacent triangles, so every edge has exactly one face and is classified boundary. extractSilhouettes keeps all boundary edges, so they show as silhouettes in any view, and the crease-angle classification is never reached.
Repro (unit): a flat quad as two triangles with 6 vertices (duplicated per triangle) returns 6 boundary edges; with 4 shared vertices it returns 4. Expected: 4 in both cases.
Repro (real data, upstream/main ed3c6cb49b): GeometryProcessor.process() output, which is what drawing-generator.ts passes to extractEdges:
tests/models/ara3d/IfcOpenHouse_IFC4.ifc, IfcSite: 1710 vertices, 299 unique positions. extractEdges returns 1710 edges, all boundary; matching by position gives 26 boundary edges.
AC20-FZK-Haus.ifc, IfcStair meshes: 7100 edges returned, where matching by position gives 0 boundary edges.
A closed box (24 vertices, 8 positions) returns 24 boundary edges, where 12 outline edges are expected.
Suggested fix: key edges by quantised position (weld) before building adjacency. I have a small fix with tests and can open a PR once this is marked ready.
