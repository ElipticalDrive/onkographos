What
The Inspect cube now draws cells as shaded 3D meshes built in the browser from the store's per-slice cell polygons, instead of raycasting a label image.
Python finds a shapes element with cell_id, Z_um and polygon geometry (or takes shapes=). It sends volume.cells = {url, bytes} and volume_cell_rows, the table row of each polygon cell. The parquet goes over the existing volume comm and is allowlisted under shapes/<name>/. Python does no meshing.
Browser: an inline Web Worker (?worker&inline, so there is no extra asset to serve from a notebook) reads the parquet with hyparquet in 4 MB range reads. It lofts only the cells reaching into the window: rings are resampled and aligned slice to slice, branches are matched by overlap, the wall is Taubin-smoothed and the caps are triangulated with earcut. The meshes are cached in an LRU of 2M vertices, about two 300 µm windows, so panning back is instant.
Rendering: one deck layer with fresnel rims, soft lighting and back faces at a floor opacity. Cut planes clip the meshes in the shader. Under the meshes the image draws with a mild contrast boost; the settings and the 2D view keep their own values.
UI: the Labels pill toggles the meshes. Its menu has a single Opacity slider (default 0.9); label projection and outlines are gone. Category, gene-expression and Selection colouring use the same LUT as before.
Harness: the DialKit Mesh folder has live opacity, fresnel, shine, flat and image-boost sliders. The defaults are fresnel 0.15, shine 0, flat 0.6 and imgBoost 0.75.

Public API changes
peek(..., labels=) / LandmarksWidget(..., labels=) is now shapes=: a per-slice polygon element instead of a label raster.
The volume trait: labels_url is replaced by cells: {url, bytes}.
The volume_label_ids trait is replaced by volume_cell_rows (base64 int32, one table row per polygon cell, -1 for none).
CubeLoadState.channels is removed (frontend).
Removed
The label-image path: cell-volume.ts, cut-rim-mask.ts, the label textures, outlines and label MIP/Additive projection in cell-lut-extension.ts, and the label prefetch in the hover preview.
The data-channels, data-label-format and data-label-mode attributes, plus the e2e tests for label projection and outline rims.
No prototype files, server-side meshing or numba/mapbox-earcut dependencies landed on this branch.
Tests
Harness e2e: landmarks-volume.spec.ts + smoke, 91/91 passed locally. New: "a cut clips the cell meshes": two toy cells render from polygons, and an X cut removes the one past it while keeping the other. The colour, highlight and image-off tests now run against the meshes.
marimo e2e (api.spec.ts, landmarks-inspect.spec.ts), 4/4: the cube loads image and polygons through a real kernel's volume_get.
pytest 158 passed: volume inference from shapes, volume_cell_rows and the shapes/ allowlist.
typecheck, unit tests and the build pass; the bundle carries the worker inline.
Open questions
Inline (blob) workers need worker-src blob: under strict notebook CSPs (VS Code/JupyterLab defaults allow it).
Stores without per-z polygons (e.g. Xenium/CosMx 2D boundaries) now open the cube image-only.
With several 3D images, inference no longer uses the label grid to pick one; pass image=.
The small-bench fixtures (export-landmarks-volume-bench-fixture.py outputs) are stale and not regenerated.
