Description
This PR adds a GPU path tracer as a third shading model of the realistic view, next to Gouraud and Phong. It works in Prepare and in the G-code Preview. It replaces #16820, which I closed because the code changed too much after its review started.
Users can see how a print will look: the plastic, its gloss, translucent filaments, soft shadows and the layer lines of the toolpaths. It is off by default. It runs only when "Path tracing" is chosen as the shading model, and the option is shown only on OpenGL 4.3 or newer.
How it works
OpenGL 4.3 compute shaders (resources/shaders/430/pathtrace.comp, pathtrace_denoise.comp).
A two-level BVH: one bottom-level BVH per object (binned SAH, built with TBB) and a top level over the instances. Moving or rotating an object does not rebuild its BVH.
Filaments are plastic with a glossy coat (GGX). Opaque filaments get subsurface scattering. Translucent walls are thin slabs: light goes straight through, tinted by the dye, or is diffused in the filament color. It does not refract. Inside a translucent print, only the outer wall reflects, because the beads behind it are fused to each other.
Toolpaths in Preview are meshed as simple beads and shaded with a rounded bead profile, so layer lines and the lines of top surfaces are visible. Ironing shades flat. Meshes in Prepare use smooth normals that follow the "Smooth normals" preference.
Modifiers and unprintable parts are not path traced. They are drawn over the image by the rasterizer, as in the plain view.
Owen-scrambled Sobol samples, a Gaussian pixel filter and an edge-aware a-trous denoiser that follows the variance of each pixel.
The image refines in tiles within a GPU time budget measured with timestamp queries, so the UI stays responsive. While the camera moves, a low-resolution pass runs the same path tracer and reuses earlier frames (reprojection).
The design is documented in docs/HLSD/path-tracer.md.
Settings
Preferences > Graphics > Realistic View: the "Phong shading" checkbox becomes a "Shading model" list: Gouraud, Phong, Path tracing. Existing users keep what they had: Phong stays Phong, and Gouraud stays Gouraud. The value is stored in a new key, opengl_realistic_shading, because the existing opengl_shading_model key was written as "gouraud" for everyone but never read.
"Path tracer quality" (Low, Medium, High) right below. It is active only with path tracing.
"Glossy toolpaths", "Translucent filaments" and "Dim lower layers" also apply to the path tracer. Seen from below, the bed is see-through as in the plain view.
With "Show FPS overlay", the overlay also shows the samples so far and the GPU time of the path tracer.
Not in this PR
This PR is kept to the path tracer itself. Ideas for later, in separate PRs if they work out:
Toolpaths as analytic beads instead of triangles: round silhouettes and real shadows in the grooves between beads, with far fewer primitives.
The bed path traced too, with its texture and its surface (textured PEI, smooth PEI, glass), instead of the rasterized bed it is now.
More materials: silk, matte and carbon filled filaments.
Adaptive sampling: more samples where the image is still noisy.
Other changes
libvgcode: Viewer::get_vertex_alpha() is public, and it no longer reads past the color tables when they are empty. Viewer::get_layer_shading() returns how the layers around the sliders are greyed or dimmed, the values its toolpath shaders already used, so that the path tracer applies the same rule.
The scene benchmark report shows the shading model instead of the old Phong checkbox.

Tests
Windows 11, NVIDIA RTX 4090 (driver 616.92), Release build.
By hand in Prepare and Preview with Benchy, a cone, a sphere and a thin plate. Opaque and translucent filaments (15 %, 45 %, 95 % opacity), Glossy toolpaths on and off, ironing, unprintable parts.
Quality Low, Medium and High; Smooth normals on and off; the quality list turns grey with Gouraud and Phong.
A config saved by the current main (opengl_shading_model = gouraud, opengl_realistic_phong = 1) opens with Phong.
Speed: on a G-code scene with 3 million triangles at 1440x880, one sample takes about 70 ms with quality Medium (one bounce) and about 105 ms with High (two bounces). Orbiting stayed smooth in these tests, because the moving camera uses a reduced resolution.
Automated: libslic3r_tests "[PathTracer]" (8 test cases): BVH building and packing for the GPU, cancellation, the 32 bit normal encoding, and smooth normals with and without the preference. libslic3r_tests "[AppConfig]": a new test checks that the shading model keeps the choice of the old Phong checkbox. It fails with the old key and passes with the new one.
scripts/run_clang_tidy.ps1 passes.
Not tested: AMD and Intel GPUs, macOS, Linux. Help with these is welcome.

Path tracer: match cached meshes to instances by ID
…
d472322
```
An arrange sorts the objects of the model, and reload_scene keeps the
GLVolumes and only renumbers them. The geometry signature stayed the
same, so each BLAS kept its old object and instance indices and took
the transformation of another object. Each BLAS now knows its instance
by the ModelInstance ID in GLVolume::geometry_id.

The transformations are looked up once per update, from the first
active volume of each instance, so hiding the first part of an object
no longer drops the whole object. The explosion ratio of the Assemble
view is part of the geometry signature, because the BLAS holds the
parts moved apart.
```
