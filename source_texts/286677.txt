Closes #723.
Volumetric media now shadow themselves. A shared light-space volume holds the
optical depth accumulated from the light through the participating medium,
as two cascades in one R32F 3D texture, written by a single compute dispatch:
Cloud cascade — the cloud layer slab, CloudscapeCommon's density field.
Fog cascade — the height-fog slab plus every enabled FogVolume shape.
One thread owns one light-space column and marches it once, writing the running
total into every slice as it passes, so the accumulation is free and no slice is
undersampled the way an independent per-cell march would be.
Binding space: UBO slot 83 was NOT consumed
The handover assigned me the last free UBO binding. I didn't need it.
The two cascade transforms ride AtmosphereShadingData (54) — the block both
volumetric consumers already read, and which was already carrying a dead
64-byte u_CloudShadowViewProj mat4 (declared "reserved", never written by the
CPU, never read by any shader). Reclaiming that plus an append covers it. The
UBO namespace still has one slot left against the GL 4.6 minimum.
Cost: one texture slot, TEX_VOLUMETRIC_SHADOW = 66, pushing
TEX_SHADER_GRAPH_0 to 67 — which also moves HEAP_IMAGE_SLOT_BASE, so
OLO_HEAP_IMAGE_BASE in BindlessHeap.glsl and its BindlessHeapGpuTest
mirror move with it (the drift BindlessShaderPipeline.HeapImageBaseMatchesTheBindingLayout
exists to catch; #723 is the third slot to land in that blind spot, so the
table comment now says so).
Also documented at the binding table: cross-namespace numeric uniqueness is
no longer achievable above ~62 — UBOs run to 82 and textures must stay under
80, so every remaining texture number collides with some UBO or SSBO
(TEX_VSM_PHYSICAL already did). The rule that still holds, and the only one
the A2 renumber was ever really about, is the within-shader one.
How the two consumers use it
Fog had no self-occlusion at all — a dense volume was lit identically at
its sunward face and fifty metres inside it. The sun in-scatter term is now
attenuated by the medium's own optical depth. Applied to the sun term only: the
ambient term is the fog's own colour, and attenuating that too would just
darken the volume uniformly, which is the failure mode, not the feature.
Clouds already self-shadowed via a per-sample cone march — but it was capped
at 1400 m, so density above that height darkened nothing and the interior of a
kilometre-thick deck was lit exactly like its top. The light path now splits at
cloudLightNearRange(): the cone owns [0, near] and the map owns everything
beyond. They compose rather than overlap — the map stores optical depth
measured from the light, so sampling it where the cone stops is exactly the
remainder, with no double count.
No temporal term, by construction
The march is a fixed midpoint quadrature over a fixed slice grid: a pure
function of the frame's settings, no jitter, no history. Issue #723's third
acceptance criterion ("no golden-test flicker from the added temporal term") is
therefore satisfied structurally rather than by tuning a history weight —
and confirmed: all 13 AtmosphereVisualEvidenceTest goldens pass unchanged
across three consecutive runs, no rebake needed.
Running pre-graph (in UploadExecutionState, beside CloudShadowMap) rather
than as a render-graph pass also side-steps the fingerprint-cache trap the
handover flagged — a Setup() that branches on a runtime toggle is frozen in,
and enable-after-first-frame then silently does nothing. VolumetricShadowMapMath.PrepareFrameGatesEachCascadeIndependentlyAndReversibly
flips every toggle after a frame that ran with it off, so that stays true.
Verification
Headless — 18 new tests, all green. 16 L1 (VolumetricShadowMapMathTest)
pin the cascade geometry and the accumulation; 2 L8 A/B evidence tests render
the real pipeline and write 19 committed PNGs.
The map itself, over MCP. The volume is imported into the render graph so
olo_render_capture_target can slice it — the same affordance #607 added for
the froxel volumes, and the one probe that separates "the volume is flat" from
"the consumer dropped it". Cloud cascade slice 2 comes back near-uniform and
slice 62 a crisp cloud-shaped field: the running integral building along the
light ray.
Live, in the editor. Cloud self-shadowing tracks the sun through the day
cycle — deck underside, enabled vs disabled, from a driven sweep:

That two-orders-of-magnitude swing is the signature: at a high sun the light
path leaves the layer inside the cone's 1400 m reach, so the map correctly has
nothing to add. A uniform veil would sit flat across that row.
Honest limitation: the stock cloud look barely moves
Worth stating plainly rather than burying. With the cloudscape's shipped
balance the same correct change moves the frame by ~0.3%, because two engine
facts squeeze the term self-shadowing modulates from both sides:
the ambient term (u_CloudAmbient * mix(0.25, 0.75, heightFrac),
unshadowed by construction) dominates the composite;
at the stock Density of 1.0–1.6 the cone march alone already reaches an
optical depth of ~20, so exp(-od) is ~1e-9 and there is nothing left to
remove.
Measured, same scene, same frame, only AmbientScale differing: 1.0 → 0.34
grey levels, 0.1 → 1.62, 0.0 → 2.68. I did not rebalance the cloud shading to
make this look better — that would be changing the art direction to flatter
the code. The L8 test authors the isolating configuration and says why; the
stock magnitude is reported here.
Fog is unaffected by this: its differential is large at stock settings, which
is why that test needed no special configuration.
Format versions
Save game → v15. CloudscapeComponent's three fields are gated at 15
per binary-format-versioning.md.
FogSettings' matching fields are deliberately NOT in the save archive,
and this found a real precondition missing from that doc: gating only
resynchronises if something downstream can recover the reader's position. For
components that is the per-component length prefix. The scene-settings
section has none — it is a flat run between the "SETS" and "ENTS"
markers — so a gated field there desyncs everything after it. Every
previously gated field happened to sit inside a component block, so the
precondition had never been exercised;
SaveGameVersionMigration.FullSaveWithPreV3TerrainRestoresThroughRestoreSceneState
caught it immediately.
The values are not lost: RestoreSceneState now seeds its settings structs
from the live scene instead of default-constructing them, so a field the
archive does not carry keeps the value the scene was loaded with rather than
snapping to a global default. That is the right behaviour for every settings
field a save game does not own.
.scenebin sidecar → v2 (MinSupportedVersion too). The generated
CloudscapeComponent binary block grew mid-payload and component payloads
are not length-prefixed, so a v1 sidecar would have been read as if it had
the new fields. The bounds and finiteness checks would probably have caught
it, and "probably" is the wrong bar for a cache that is invisible when it
works. Rejecting it costs one YAML load and a rewrite.
Ride-along fix, in its own commit
f0c67c3 — fix(renderer): invalidate the froxel fog history when the chain
is off (#435). Not part of #723; found by it, and fixed here rather than
worked around.
VolumetricFogPass's scatter ping-pong is pass state and outlives the scene,
but its only invalidation site was FogRenderPass::Execute's else branch —
unreachable when fog is off entirely, because that pass does not run either.
A valid history from the previous scene survived, so the next frame that turned
fog back on reprojected against it at the 0.9 history weight and spent several
frames rendering another scene's fog while converging. Reachable in a shipped
game through a runtime scene switch, not only in tests.
What pinned it, and why it is history rather than settings: the affected test's
fog-disabled baseline was BIT-IDENTICAL across both orderings while its
fog-enabled frame moved 3.2%. Scene, settings, lights and camera are therefore
provably pristine, and history is the only state left.
I did not restore the froxel state in the new test instead. That would have
made the test green and left the engine bug in place for the next person.
Docs
volumetric-cloud-debugging.md gains two causes and a third observation trap,
all paid for in this change:
Cause 7 — a spatially constant term inside a light-path integral is a
veil that also moves when the volume is refitted. AbsorptionCoefficient
is exactly such a term; the generator deliberately excludes it and says so,
because the omission looks like an oversight to the next reader.
Cause 8 — the term you changed is not the term the pixel shows, with
the ambient/phase/saturation tables above and the rule that saved me:
capture the intermediate, not the frame. One call splits "broken" from
"correct but hidden".
Observation trap — "toward the light" is the darkest direction through
a medium, not the brightest, and more so the lower the sun. This inverted an
assertion I wrote ("the underside must darken more than the sun side"): the
correct implementation measured 9.43 on the sun side against 6.48 on the
underside and failed the test.
binary-format-versioning.md gains the framing precondition above.

…annot serve (#723)

Two self-review findings, both of which read as correct code.

The enable lane the atmosphere UBO uploads came straight from PrepareFrame's
CPU state with no check that the map is actually serviceable. If Dispatch()
latches a creation failure — a missing or uncompilable generator shader — it
returns before it can ever publish the sampler, yet both consumers still passed
their `u_VsmParams[c].x < 0.5` gate and sampled texture unit 66 forever. That
only LOOKS right because an incomplete GL texture reads (0,0,0,1), which
happens to mean "no shadowing"; nothing guaranteed it. The latch now disables
both cascades at the source, the way cloudShadowActive gates on
CloudShadowMap::IsReady().

The fog domain then defeated its own texel snap. FitCascade snaps the
light-space origin to a grid whose cell size is derived from the domain's
EXTENT, which is stable only while the extent is. XZ was always fine — a box's
projected width does not depend on where the box is — but the vertical extent
followed min(cameraY, HeightOffset) continuously, so once the camera dropped
below HeightOffset every frame produced a slightly different cell size, the
floor() landed on a different grid, and every sample slid sub-texel. That feeds
the froxel scatter's 0.9-weight history, where it surfaces as shimmer with
nothing pointing back here. Quantizing the camera to one XZ texel before
deriving anything from it fixes the slab and the fog-volume clip window
together — the discipline CloudShadowMap already uses for its centre.

The existing snap test passed throughout, because it exercises FitCascade in
isolation. The new one drives the real domain builder and asserts both
transforms are bit-identical under centimetre nudges.
