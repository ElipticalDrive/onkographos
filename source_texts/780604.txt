Issue body actions
Canvas.look_at(target, viewpoint=...) calls camera.set_viewpoint(viewpoint) (which writes rotation_euler) and then camera.frame_points(...), which reads camera.basis, built from matrix_world. matrix_world only updates when the depsgraph is evaluated, so the fit can run against the previous camera orientation.
For entity and object targets this happens to work: blender_utils.evaluated_points calls bpy.context.view_layer.update() to read evaluated geometry, and that update sits between the two calls. For an (N, 3) array target nothing triggers the update, so the camera is placed for the old orientation and the render is empty or off-centre. The same applies to camera.set_viewpoint(...) followed later by look_at(...) without a viewpoint.
Measured on main (2026-09-18) with 200 random points and viewpoint=(90, 0, -45):
```
array target  : camera at [  4.053 -27.249  15.333]   after explicit view_layer.update(): [-13.447 -21.28   0.92 ]   -> stale
entity target : camera at [ -6.965 -10.199   1.206]   after explicit view_layer.update(): [ -6.965 -10.199   1.206]  -> fine
```
Script:
```
import os, tempfile
os.environ.setdefault("BLENDER_USER_EXTENSIONS", tempfile.mkdtemp())
import bpy, numpy as np, molecularnodes as mn
canvas = mn.Canvas()
pts = np.random.default_rng(0).normal(size=(200, 3)) * 2 + np.array([5.0, -3.0, 2.0])
canvas.look_at(pts, viewpoint=(90, 0, -45)); a = np.array(canvas.camera.camera.location)
canvas.camera.set_viewpoint((0, 0, 0)); bpy.context.view_layer.update()
canvas.camera.set_viewpoint((90, 0, -45)); bpy.context.view_layer.update()
canvas.camera.frame_points(pts, margin=0.05, scene=canvas.scene); b = np.array(canvas.camera.camera.location)
print(a, b)
```
Proposed fix: call bpy.context.view_layer.update() at the end of Camera.set_viewpoint (or at the start of Camera.frame_points, before reading self.basis), so the basis always reflects the rotation just written regardless of target type. Plus a regression test in tests/test_canvas.py that frames an array with a custom viewpoint and asserts the camera location matches the entity-target path.
Found while writing the mn-render skill (#1226), which documents the workaround (view_layer.update() between the two calls) until this lands.
