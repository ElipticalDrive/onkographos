Summary
Add SDF-to-mesh extraction support, with initial implementations of Marching Cubes and naive Surface Nets.
Goal
Allow signed distance field content to be converted into triangle meshes so SDF-authored shapes can be baked, exported, inspected, or rendered through the mesh pipeline when desired.
Motivation
This would be useful for:
turning SDF content into static mesh assets
comparing SDF rendering against extracted mesh geometry
offline export workflows
debugging SDF fields and thresholds
giving examples a bridge between implicit and explicit geometry
Scope
add an SDF sampling/extraction path that can evaluate a scalar field over a regular grid
implement Marching Cubes as an initial mesh extraction algorithm
implement naive Surface Nets as a second extraction algorithm for comparison
output MeshPrimitive-compatible geometry so extracted results can flow through existing mesh paths
expose controls for grid resolution / bounds / iso level
add tests for deterministic extraction, expected topology properties, and basic mesh validity
document tradeoffs between Marching Cubes and Surface Nets in this codebase
Notes
first version can target a bounded regular grid over supported SDF primitives
it is acceptable to start with sphere/box or similarly narrow SDF coverage if that matches current execution support
normals can be approximated from field gradients as a first step
this issue is about extraction, not runtime dual rendering or dynamic remeshing performance work
