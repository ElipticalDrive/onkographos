The current translation must recover SURFER's ray, transform, gradient, normal, and shading behavior from the original Java/jsurf program before choosing new types or target representations.
This is a source-preservation obligation within the whole-program translation, not a request to redesign the renderer around later geometry experiments.
What the current application does
RendererEngine uses the orthographic camera, changes camera height for zoom, and supplies composed yaw/pitch rotation matrices through renderer.setTransform.
RayCreator constructs related rays in camera, clipping, and surface coordinates.
Ray direction magnitude is part of the origin + t * direction parameterization and therefore affects clipping intervals and root parameters; it is not merely an S² direction.
The polynomial gradient is evaluated in surface coordinates at the selected root.
The inherited code transforms that value using its stored normal matrix, then normalizes it during shading only when its length is nonzero.
The wider jsurf code contains more general transform machinery than the Android app currently exercises.
Work during the whole-program translation
Read the parser, algebra, ray construction, transforms, root selection, gradient evaluation, normal handling, lighting, and Android view controls together. Record:
the exact coordinate spaces and composition order used by the executable path;
which direction scalings alter the shared ray parameter;
the current transform matrix used for normals, including behavior outside the Android app's orthogonal-rotation subset;
singular zero-gradient behavior;
which results are precomputed per draw, row, column, ray, or hit;
observable fixtures that preserve the current Double/F64 pixels and intermediate values.
Use distinct names or types only where the recovered program semantics require them. Do not mandate vector/covector/orientation type machinery in advance, and do not choose matrices, quaternions, compact directions, Givens chains, Householder products, or a shader representation merely because another repository studies them.
A later lowering may change carriers or algorithms only after the original behavior and any deliberate corrections are explicit. This issue does not impose a separate implementation order on the whole-program translation.
