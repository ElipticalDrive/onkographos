1536 cascade reached decode
example_1536.py dragon.png sampled and decoded at 1536³. CUDA died in o_voxel.to_glb → remove_small_connected_components because the mesh was tiny (1885 verts / 1042 faces) after integer-scaled occupancy. That is a cuMesh kernel launch (error 9), not the DiT.
This revision:
Snapshots vertices/faces on CPU before cuMesh, then writes a plain sample_1536.glb if PBR export crashes
Cheap 2× occupancy fill (not the VAE C2S that TDRs) so the next 1536 mesh is denser
Skips remove_small_connected_components on tiny meshes in the local o-voxel copy
After the last crash, CUDA may be dead. PowerShell: wsl --shutdown, then:
```
conda activate trellis2
cd ~/TRELLIS.2
git fetch fork cursor/low-vram-block-offload-3548
git pull fork cursor/low-vram-block-offload-3548
TRELLIS_MAX_TOKENS=8192 python example_1536.py dragon.png
```
You should get sample_1536.glb even if PBR baking fails (untextured fallback). example_low_vram.py remains the proven 512 path.
