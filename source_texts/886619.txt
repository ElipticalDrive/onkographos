Summary
add a focused video_to_3d_core::colmap module for sparse COLMAP scene-data contracts and text parsing
keep the reusable COLMAP camera/image/point representation in video-to-3d-core, preserving one Rust scene-data authority
parse only cameras.txt, images.txt, and points3D.txt; COLMAP execution remains reference/evidence tooling rather than product implementation
preserve the full u64 point-ID domain while treating only literal -1 as COLMAP's missing-point sentinel
add deterministic parser coverage for normal sparse input, filenames with spaces, empty observations, u64::MAX, invalid negative IDs, and malformed tracks
Migration boundary
This is the first implementation slice of moritzbrantner/rust-packages#179. It provides the exact sparse COLMAP surface needed to move spatial-media-explorer off historical moenarch-video-analysis-radiance-io without absorbing radiance-field, Nerfstudio, Gaussian-splatting, or unrelated legacy 3D semantics.
The large reconstruction implementation is split into reconstruction.rs and included at the crate root so all established video-to-3d-core public paths remain unchanged while lib.rs becomes the composition point for the new core-owned contract.
Acceptance
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
existing golden pose/COLMAP reference evidence remains green
no Cargo.lock dependency expansion is required
