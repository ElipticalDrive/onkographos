Avoid successful return with empty .vox output
This early return exits with Ok(()) when no particles are generated, but the output file has already been created/truncated before the format match, so the command can report success while leaving a 0-byte .vox file that MagicaVoxel cannot load. This occurs for valid inputs that voxelize to zero particles (for example, very coarse --resolution or restrictive cropping), so the .vox branch should either emit a valid empty VOX structure or fail explicitly (and avoid leaving an invalid file behind).
