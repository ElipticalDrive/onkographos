Contributor
build_explicit_octree_metadata_from_leaf_partitions was allocating N × 22 buffers (N leaves × 22 Morton levels) to enumerate ancestor nodes, an ~11× overallocation relative to the true node count upper bound for a compressed octree.
Changes
Tighter buffer bound: max_candidates = N * 22 → max_nodes = 2*N - 1. For N Morton-sorted leaves, the complete node set is exactly the N leaves plus the N-1 pairwise LCAs of consecutive leaf pairs; deduplication yields ≤ 2N-1 unique nodes.
Candidate generation without the broadcast grid: replaced jnp.broadcast_to((N, L)) grids with _common_depth_from_codes(leaf_codes[:-1], leaf_codes[1:]) to compute N-1 LCA depths/codes directly, then concatenate with the N leaf entries.
Range computation via searchsorted: replaced scatter min/max over the flattened (N×L) grid with two jnp.searchsorted calls on the sorted leaf_codes array using the subtree mask C | ((1 << (BITS - 3d)) - 1) to find first/last covered leaf per node. O(N log N), O(N) peak storage.
Iterative parent lookup: the single depth-1 probe was replaced by a loop over steps 1..MAX_MORTON_LEVEL, assigning each node its deepest existing ancestor. Required because compressed octrees can skip depth levels. Each iteration stays O(N).
