Implements #2 (parent #1; repo TODO #6, seeds TODO #4's demo command). Only the human merges.
What shipped
python Ex0.py file.nrrd file.csv file.mp4 runs end-to-end on the provided corpus (FR-1): NRRD volume loader → CSV row count → one black placeholder frame per row at a uniform canvas → mp4 (FR-17/FR-19; the real canvas/copies of frames arrive with the renderer ticket, FR-18). User-fixable problems exit non-zero with one-line stderr errors naming the problem file (FR-2).
load_volume (FR-3..FR-6): pynrrd, index_order='F' pinned so array axis 0 is the NRRD's axis 0=x — M[x][y][z] reading is reproduced by a hand-written ASCII NRRD (value on disk ↔ index mapping). Dtype contract per FR-4: uint8/uint16/uint32 pass, signed integer types (MRHead_1's short) tolerated; floats/uint64 rejected naming the type. Dimensions 1 <= s < 2^10 enforced with the rejecting message naming the axis and limit (FR-5). World-space space* header fields are read but deliberately unused — docstring + inline comment + a header-with-space-fields test all point at ADR 0002 (FR-6).
count_planes (FR-17 groundwork): data-row count (header excluded); tolerant of the corpus's missing trailing newline and int/float cells (FR-9). Full row parsing/validation is the next ticket (Ticket 2: CSV plane-list parsing + per-row plane validation #3, FR-7..FR-11).
Write video (FR-19 container contract final from this ticket): 30 FPS container rate, mp4, genuine H.264 (avc1), even canvas. See Decision for owner review below.
Decision for owner review (ADR 0003, status Proposed)
The SRS cites OpenCV's VideoWriter for FR-18's same-size constraint, but pip opencv-python cannot encode H.264 on this machine: avc1/H264 fourcc never opens (its bundled ffmpeg build lacks a software H.264 encoder; only mp4v works — MPEG-4 Part 2, not FR-19's "H.264-compatible fourcc"). docs/adr/0003-video-encoding-via-ffmpeg-cli.md trades that for the system ffmpeg CLI (-c:v libx264), which satisfies FR-19 literally. README's build/run section and requirements.txt note the resulting system prerequisite. Please adjudicate at review (swap back to mp4v+OpenCV is a one-constant change if you prefer pip-only deps over a literal FR-19 reading).
Sub-judgement decisions, flagged rather than buried
uint64 rejected (FR-4's "8/16/32-bit" contract); signed integers of any width tolerated. Message names the offending dtype.
Zero-data-row CSV currently writes an empty container (ffmpeg exits 0). FR-20 covers all-rows-errored, not zero rows; ADR 0003's consequences flag it for the plane-list ticket to settle.
Blank CSV rows are skipped by the row count (not planes); pinned by test, formalized in ticket Ticket 2: CSV plane-list parsing + per-row plane validation #3.
Placeholder canvas is a named constant PLACEHOLDER_CANVAS=(256,256) — no plane geometry feeds it this ticket (AC: "CSV still only used for row count").
Happy-path stdout prints one summary line (wrote N placeholder frames ...); errors go to stderr only.
Acceptance evidence (AC 1–6)
```
$ python Ex0.py assets/nrrd/MRHead_1.nrrd assets/csv/lecturer_example.csv out.mp4
wrote 4 placeholder frames (256x256, H.264 @30 fps) to 'out.mp4'   (exit 0)

```
uint8/uint16/uint32/short fixtures load (test-verified; the corpus itself spans all four).
$ python Ex0.py variants: 0/1/2/4 args → exit 2, single-line usage message; missing file → exit 1 naming it; directory-as-file (volume or plane list) → exit 1 naming it.
$ ... bigdim.nrrd (sy=2048) → Ex0.py: volume '...' has sy=2048; every dimension must satisfy 1 <= s < 2^10 (FR-5).
Testing: 47 pytest cases (loader contract/mapping/bounds/dtype, corpus row counts incl. all six files, writer container checks via ffprobe decode of the produced bytes — never re-rendered, CLI incl. the real python Ex0.py process); mypy --ignore-missing-imports Ex0.py tests clean. Reproduce: pip install -r requirements.txt -r requirements-dev.txt, needs ffmpeg on PATH, then python -m pytest (ffmpeg-absent machines skip the video tests).
