Requested by Sami · project thread
Before: every MeshRef was its own draw per submesh in the main pass, the SSAO and velocity prepasses, every sun cascade and every local-light shadow tile, however many copies of the same crate the scene held.
After: copies of one rigid submesh with the same material and tint collapse into one instanced draw per pass, with the same pixels. On by default, because all 28 existing goldens stay byte-identical on linux-gl and linux-sdlgpu with it on. Showcase main-pass draws fall 54 to 36 and shadow draws 329 to 236; a crate-grid test scene goes from 40 to 4 main draws and 261 to 39 device draws. -r.instancing 0 turns it off.
How: Scene3D::build() buckets the sorted opaque list and each caster list by an instancing key (mesh, submesh, LOD, material pointer, bitwise tint and emissive tint; casters key on less) and exposes opaque_runs() / caster_runs(). Forward3D uploads per-copy matrices with one transient storage block per pass (bank::kInstances) and draws each run with instance_count; five instanced pipeline twins and three vertex shaders do the same math as the single-draw ones. Skinned, blended, transmissive and terrain draws, and copies that move while the velocity prepass runs, stay single draws. A per-record() budget of 512 KiB (the data lands in the geometry ring, not the uniform ring the plan named) makes runs past it draw singly.
Counters for the M-CONTENT draw-call report (also in 08-3d.md section 8.6):
Scene3D::Stats: runs_instanced, draws_instanced, not_instanced_blended, not_instanced_terrain, not_instanced_skinned, not_instanced_moving, not_instanced_single, not_instanced_disabled. draws_instanced plus the six not_instanced_* equal draws().size().
Forward3DStats: runs_instanced, draws_instanced, shadow_runs_instanced, shadow_draws_instanced, instancing_overflow, instancing_bytes. main_draws counts a run once.
Measured: 13 to 20 KB of instancing data per frame on the showcase and the crate scene, no overflow. Tests: scene tests for run coverage and run breakers, GL and SDL GPU pixel-equality of instancing on vs off (3 cascades, a shadowed spot, SSAO, depth of field), overflow fallback, new golden instanced_props.
Risks: pixel identity is verified on Mesa llvmpipe (GL) and lavapipe (SDL GPU) only, not on Metal, WebGPU or real GPUs. Grouping reorders draws within a material segment, so an exact depth tie between different coplanar meshes could resolve differently (none seen). Posed rigid submeshes are instanced; only skinned meshes are not. The perf_run counters (runs_instanced, draws_instanced in captures) come in a stacked follow-up PR because they touch four other modules.
This touches the render draw path and shaders, so it waits for the coordinator's review before merging.

…cratch reuse, run split (SBA-199)

- The frame's instancing budget is min(instancing_budget, geometry_ring_bytes / 4), shared by all views of
  the frame (reset on the frame's first view) and charged at the device's storage alignment, so the uploads
  never overrun the geometry ring (GL and sdlgpu both drop an overflowing set_storage_data without binding).
  Forward3DDesc::geometry_ring_bytes mirrors the device's.
- Each view reserves its share for the main pass first, then the SSAO prepass, then the velocity prepass;
  the shadow passes take the rest; unused shares return to the frame for later views.
- group_runs reuses Scene3D's member scratch instead of allocating per call.
- caster_runs groups on mesh, submesh and level only; alpha-masked casters stay single.
- kMaxInstancesPerRun (65536) via InstancingSettings::max_count splits longer runs.
- Tests: small-ring overflow (equal pixels, instancing_overflow > 0), max_count split, masked casters;
  docs and changelog fragment updated.
