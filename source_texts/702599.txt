Two small proposals that should go in one interface PR.
1. AABB::empty(). Today the empty box {+inf, -inf} is built by hand in the tests, and a plain AABB b; is uninitialized. Jett's bounds stage is the main consumer. Proposal: static AABB empty() returning {{inf,inf,inf},{-inf,-inf,-inf}}, with a test. This adds a member to a §1 type, so it needs Jett's approval and a version bump (v1.0 to v1.1).
Fallback: Jett defines a local helper in bvh/.
2. Move RT_EPS / RT_GAMMA3 from aabb.hpp to math.hpp. Mikail's triangle and sphere error bounds need the constants without pulling in the box header. aabb.hpp already includes math.hpp through ray.hpp, so existing code keeps compiling. §1 doesn't name a header, so this may not need an INTERFACES edit; it needs Arek's and Mikail's OK.
Done when: the owners agree, and the change lands via one PR that updates INTERFACES.md and the code together.
cc @jettVanbrocklin, @Mikail-Sadic-UT

Correction to the description: the constants move is lower priority than I wrote. I said Mikail's triangle and sphere error bounds need RT_EPS/RT_GAMMA3, but the frozen §5 rules don't use them (sphere: stable quadratic; triangle: watertight with a double fallback). In the spec the only user is the far-bound widening inside intersect_aabb, which already lives next to the constants in aabb.hpp. So the move is optional cleanup, not something another owner is waiting on. AABB::empty() is still useful for Jett's builders; until it lands he can use a local {+inf, -inf} helper in bvh/.
