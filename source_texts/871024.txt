Summary
This PR makes procedural textures (noise-based) deterministic and reproducible across renders by seeding Perlin noise instances with object seeds. Previously, all textures shared a single Perlin instance, causing non-deterministic patterns when the same scene was rendered multiple times. Now each unique object seed gets its own cached Perlin instance, ensuring bit-identical results across renders.
Key Changes
Perlin noise seeding: Added Perlin(int seed) constructor and Perlin.GetOrCreate(int seed) factory method with process-wide ConcurrentDictionary caching. Two Perlin instances built from the same seed are bit-identical, enabling deterministic procedural textures while saving memory.
Seed propagation in composite objects: Updated CsgObject, Group, and Mesh to propagate the same seed value to all children/operands (rather than deriving unique seeds per child). This ensures procedural textures appear uniform across the entire logical object.
Texture updates: Modified NoiseTexture, MarbleTexture, and WoodTexture to use Perlin.GetOrCreate(objectSeed) instead of a shared _noise instance, making patterns reproducible per object.
Scene loader: Added seed assignment for CSG objects in SceneLoader, using explicit YAML seed or a deterministic hash of entity index, type, and name.
Local RNG in Perlin: Replaced global MathUtils.Rng with a local Random(seed) instance in Perlin construction, isolating procedural texture randomness from other rendering randomness.
Notable Implementation Details
The Perlin default constructor now delegates to Perlin(0), establishing a canonical seed for reproducibility.
Seed caching is thread-safe via ConcurrentDictionary, supporting concurrent texture evaluation.
Composite objects (CSG, Group, Mesh) now treat themselves as single logical units with uniform procedural patterns, rather than giving each child a unique derived seed.
Backward compatibility is maintained: objects without an explicit seed default to seed 0, which uses the canonical Perlin instance.

The Seed property on container entities was inconsistent and partially broken:

- Group.Seed and Mesh.Seed getters always returned 0 (no backing field).
- Group propagated seeds to children with HashCode.Combine(value, i),
  giving each child a different derived seed and thus different procedural
  texture patterns.
- CsgObject did not propagate seeds to Left/Right at all, and SceneLoader
  never assigned a seed to CsgObject on creation (defaulted to 0).

New semantics: a Group, Mesh or CsgObject represents one logical object.
Setting Seed stores the value in a backing field and propagates the SAME
value to every child / triangle / operand, so procedural textures appear
uniform across the whole composite as if it were a single solid. SceneLoader
now assigns a deterministic fallback seed to CsgObject using the same
convention as primitives, meshes and groups.

Container types that represent scene-level groupings (BvhNode, HittableList)
are intentionally left untouched — they aggregate independent entities,
each with its own seed.

Perlin noise tables (gradient vectors and permutation arrays) were built
using MathUtils.Rng, whose underlying global seed comes from
Environment.TickCount. Every render therefore produced different Perlin
output, and the per-object Seed had no effect on the actual Marble / Wood
/ Noise pattern — only on the optional offset/rotation randomization in
TextureTransform.

Changes:

- Perlin: add Perlin(int seed) constructor that uses a local Random(seed).
  The default parameterless constructor now delegates to Perlin(0) so even
  unseeded scenes are reproducible across renders.
- Perlin: add Perlin.GetOrCreate(int seed), a thread-safe ConcurrentDictionary
  cache that returns the same instance for the same seed. Two Perlin
  instances built from the same seed are bit-identical, so caching avoids
  duplicating ~3 KB of tables per texture instance.
- NoiseTexture / MarbleTexture / WoodTexture: in Value(), pick the Perlin
  instance via Perlin.GetOrCreate(objectSeed) when objectSeed != 0,
  otherwise fall back to the texture's local default Perlin. This means:
    * same object seed → same procedural pattern across renders (deterministic)
    * different object seeds → different but reproducible patterns
    * Group / Mesh / CSG (which propagate one seed uniformly) → uniform
      pattern across the whole composite, consistent with treating them as
      a single logical object.

Combined with the previous commit on Group/Mesh/CSG seed propagation,
this gives the raytracer fully reproducible procedural textures, matching
the determinism guarantees expected from PBRT/Mitsuba/Cycles-class engines.
