Summary
Adds a Triton kernel for _sparse_semi_structured_tile (aten::_sparse_semi_structured_tile(Tensor input, str algorithm="", bool use_cutlass=True) -> (Tensor, Tensor, Tensor, Tensor, Tensor)). The op prunes a dense 2-D fp16/bf16 tensor to the 2:4 semi-structured sparsity pattern and returns the five tensors of the CUTLASS compressed representation: packed (rows_r, cols_r/2), the int16 CUTLASS metadata, the transposed pair (packed_t, meta_t) and the per-thread 8x8 selection bitmasks used by the sparse pointwise backward path (rows_r = ceil(rows/32)*32, cols_r = ceil(cols/64)*64; the transposed representation is sized for the swapped problem). Selection follows the aten CUDA kernel: each 4x4 tile is sorted ascending with the CUTLASS StaticSort compare-exchange network (equal keys exchange too) and scanned from the largest, keeping a value when its tile row and tile column each still have capacity. The main Triton kernel processes one 32x32 input block per program (the aten warp footprint of 8x8 4x4 tiles) and writes the packed values, the transposed packed values and the per-thread 8x8 selection bitmasks directly at their aten layout; a second kernel applies the CUTLASS ColumnMajorInterleaved<2> reorder producing the int16 metadata matrices. For tile rows with fewer than two selections the aten kernel leaves the unused 2-bit metadata field holding stale register contents; this implementation emits the canonical sibling-slot encoding, which decodes to the same dense tensor. use_cutlass=False (cuSPARSELt metadata layout) and the causal1122 algorithm are not part of this PR and raise NotImplementedError.
Testing
Validated against the aten CUDA kernel elementwise: packed, packed_t (defined width) and threads_masks are bit-exact; meta/meta_t are validated functionally by decoding through torch.sparse._semi_structured_conversions.sparse_semi_structured_to_dense_cutlass and comparing with an independent StaticSort-network reference of the greedy selection
16 test cases across 4 shapes (32/64/96/16 x 64/128, covering pad rows), 2 dtypes (fp16/bf16) x 2 algorithms ("", largest_abs_values_greedy); all pass in default, --ref cpu and --quick modes
KernelGen end-to-end: catalog flaggems_sparse_semi_structured_tile (7 correctness + 8 timing workloads), reference solution 15/15 PASSED (is_hack=False), SimpleOpt E2E PASSED (9 rounds, best geo_mean 283.9 at round 6 vs the Python reference)
Tested on: Nvidia
Performance
Test command: pytest benchmark/test_sparse_semi_structured_tile.py --level core --mode kernel (NVIDIA H20-3e)
The aten baseline is a heavily-optimized warp-shuffle CUDA kernel (single fused pass with 128-bit loads); the Triton implementation here is a first cut whose scalar compare-exchange network does not yet reach it:

Review: Request Changes
Thanks for the contribution. The core computation is implemented in Triton (_ssst_kernel + _meta_reorder) and there is no aten.* on the hot path. However, the operator is a substantial performance regression with real dead code and doc/code mismatches.
P0
Large performance regression — the arithmetic mean is 0.157x (up to 9.3x slower), worsening with size. ops/_sparse_semi_structured_tile.py:161-170,178-185 performs ~63 tl.sum reductions per 4x4 tile plus 16x4 for the greedy step — roughly 400 cross-lane reductions per program — which explains 0.107x at 4096². Please vectorize (lane slicing / tl.sort) or restructure to a per-thread 8x8 layout, and provide an optimization plan (or get an explicit maintainer waiver). Do not merge at this performance level.
P1
Dead torch fallback — :307-348 _causal1122 is a full torch implementation that is never called (:376 raises), i.e. dead code plus a disallowed fallback. Delete it.
Missing @libentry() — _meta_reorder (:280-281) lacks it, unlike _sparse_semi_structured_mm.py:39.
Unused parameter — ncols2 (:281,425-432) is never used inside the kernel.
Doc/code contradictions — :52-53 says causal1122 is computed by a host fallback, while :376-380 raises NotImplementedError; :29 says threads_masks is cols_r/16, but :393 uses /8 (ATen also uses /8).
Signed-zero tie-breaking — :159 gives -0.0 and +0.0 different keys, while ATen treats them as equal; pruning weights contain many exact zeros, so tie order can differ. Normalize (x + 0.0) before keying. The tests only use randn.
Wasted memset/traffic — :394-395 allocates qbuf/qbuf_t with torch.zeros, but the kernel fully overwrites them (extra ~25% traffic).
Zero grid — rows == 0 gives a zero first grid dimension (:397).
Test issues — ALGORITHMS is assigned twice (:44-47, :65), so --quick still runs two algorithms; private marker construction (:32-39); :187 has no dispatch test; :254/:268 filter out non-matching cases, weakening the assertions.
Wrong kind — conf/operators.yaml:18503 sets kind: BLAS, but there is no matmul; use Sparse or Math.
Verified-compliant
The schema _sparse_semi_structured_tile is real and plain CUDA is the correct dispatch key (native_functions.yaml:3388-3390). logger.debug("GEMS ..."), exports, _FULL_CONFIG, conf/operators.yaml, and pytest markers are in place. Host validation (2D/stride/dtype/cols%32/algorithm) and row/column padding (32/64) match ATen. The benchmark baseline is on-device (fair). Only 6 files, no use_gems().
