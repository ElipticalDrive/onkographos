Decisions already made
1. Eligibility
The Updraft Lens is available only when the persisted result identifies the canonical Trade Cumulus/BOMEX case through either:
```
result.scenario_id == "bomex_trade_cumulus_baseline_v0"
```
or:
```
result.run_configuration.case_id == "bomex_trade_cumulus_baseline_v0"
```
Do not infer eligibility from the presence of w and ql alone.
For ineligible results, the existing generic visualization behavior remains unchanged and no Updraft Lens control is shown.
2. User activation
Explore retains the base 3-D cloud-water view as the initial experience.
For an eligible result, add one visible Updraft Lens activation control. Activating it must:
keep ql as the 3-D cloud field;
select w as the slice field;
switch the active slice to vertical_x;
apply the backend-selected default time and y-plane;
use the fixed Lens range and palette;
show the black cloud boundary;
show horizontal-wind arrows by default;
default wind mode to perturbation wind.
Turning the Lens off removes Lens-specific slice/arrow behavior without deleting or mutating the result.
3. Dedicated backend contract
Create a case-specific backend module and two GET endpoints. Do not overload the generic slice contract with hidden Trade Cumulus behavior.

4. Scalar-grid vertical velocity
ql is on scalar vertical levels. If w is on vertical faces with one extra level, calculate scalar-centered vertical velocity as:
```
w_center[k] = 0.5 * (w_face[k] + w_face[k + 1])
```
If w is already on the scalar vertical grid, use it directly. Reject unsupported grid relationships rather than silently truncating or shifting arrays.
This interpolation is visualization/evidence plumbing only. It does not change CM1 output.
5. Default time
Use output frames in the final three hours (time >= 10800 s).
Select the frame with the highest finite domain-mean cwp. Break ties by choosing the earlier frame.
Fallback order:
the supported time of maximum cloud liquid from result diagnostics;
the latest final-three-hour frame;
the latest available frame.
Record the selected method in provenance/caveats.
6. Default x-z plane
At the selected time:
form a cloud mask from ql >= 1e-6 kg/kg;
for each y-plane, identify four-connected x-z cloud components;
retain components with at least 10 cells;
within retained components, calculate:
```
plane_score = sum(max(w_center, 0) * ql)
```
choose the y-plane with the greatest finite score; break ties with the lower index.
Fallback order:
plane containing the largest coherent cloud component by cell count;
domain midpoint.
Do not choose the plane from one absolute-maximum w cell.
7. Fixed vertical-velocity scale
Across all available frames, calculate the 99th percentile of finite abs(w_center) values.
Set:
```
range = max(0.5 m/s, ceil_to_0.1(percentile_99_abs_w))
minimum = -range
maximum = +range
```
Use this one range through playback. Do not rescale per frame.
Palette anchors are fixed:
```
-range → #2166ac
0      → #f7f7f7
+range → #b2182b
```
Clamp values outside the range to the endpoint colors. Missing/non-finite values use the existing missing-data treatment and must not be presented as zero.
8. Dedicated slice renderer
Create UpdraftLensSlice.tsx as a dedicated canvas-based or SVG-based renderer; do not continue the current button-grid/gutter implementation for this Lens.
The renderer must:
render one native/scalar-grid cell as one contiguous colored rectangle;
use no gap between cells;
use no default smoothing or interpolation;
preserve the physical x:z aspect ratio using coordinate extents;
display x and z axes in km;
display the fixed color legend in m/s;
support click-to-inspect by mapping the pointer to native x/y/z indices;
draw a black boundary along every cloud-mask edge adjacent to clear air or the slice boundary;
allow the user to hide/show the cloud boundary, default shown;
expose an accessible text summary of field, time, plane, range, and threshold.
Do not alter generic slice rendering for other fields/results except for shared bug fixes strictly required by this component.
9. Horizontal wind arrows
The Updraft Lens provides an optional sparse horizontal-wind overlay in the 3-D cloud view. It is shown by default while the Lens is active and may be hidden by the user.
At the scalar model level nearest 600 m:
center u on scalar x positions by averaging adjacent x faces where required;
center v on scalar y positions by averaging adjacent y faces where required;
reject unsupported stagger relationships rather than silently misaligning arrows;
sample every eighth scalar point in x and y, yielding at most 64 arrows for the canonical 64 × 64 domain;
place arrows on the selected level using physical x/y/z coordinates.
Perturbation mode subtracts the horizontal domain mean separately from u and v before creating arrows.
Total mode uses the centered total u and v values.
Calculate one stable reference speed per mode across all frames at the selected level:
```
reference = max(0.5 m/s, ceil_to_0.1(percentile_95_horizontal_speed))
```
Map the reference speed to an arrow length equal to 8% of the horizontal domain width. Keep the reference and geometry fixed through playback. Show a scale legend.
Render arrows in dark charcoal. Do not color arrows by a second scientific variable.
10. Controls
While the Lens is active, provide exactly these Lens-specific controls:
cloud boundary shown/hidden, default shown;
horizontal wind shown/hidden, default shown;
wind mode: Local departures (perturbation) or Total wind, default Local departures;
existing synchronized time control;
existing vertical-plane position control.
Do not add a free-form palette editor, arbitrary arrow density control, arbitrary arrow-height control, or generic Lens editor in this issue.
11. Performance and caching
Defaults may scan all result frames once. Frame requests must open only the requested model frame plus the minimum coordinate/context data required.
Use bounded in-process caching keyed by result identity/source-file state for the full-run defaults and stable wind-scale calculation. Cache invalidation must follow the existing result/output source state; do not create a persistent database or cache directory.
The frontend must cancel or ignore stale frame requests during rapid time/plane changes.
