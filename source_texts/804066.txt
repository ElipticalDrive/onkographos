Making pixels smoother. ~Marching Squares method~
Making pixels smoother. ~Marching Squares method~Making pixels smoother. ~Marching Squares method~
Yuta Yamamoto
-
03.26.2025
idea
We are a company that is constantly exploring "shapes". While understanding shapes that already exist in the world, we also continue to research how to create shapes that do not yet exist. In the process of investigating computer-based shape generation as a way to create such new shapes, we came across a method called marching cubes.
Marching cubes[1] is a computer graphics algorithm introduced by Lorensen and Cline in 1987 that extracts a polygonal mesh of isosurfaces from a 3D discrete scalar field. This algorithm is primarily used in medical visualization of CT and MRI scan data images.
Also, although marching cubes is an algorithm intended to be used in 3D, it is possible to apply this algorithm in 2D, in which case it is called marching squares.
A typical use case for marching squares is drawing isobars on weather charts and contour lines on maps. Based on discrete information mapped in a grid on a map, it estimates smooth changes in atmospheric pressure and displays them overlaid on the map. Marching squares is lightweight in calculations, so it can instantly convert measurements of ever-changing atmospheric pressure and deliver images that are intuitively easy for observers to understand.
Marching squares is a technology that is already in wide use, but this time I will be implementing the marching squares process from scratch on Grasshopper in Rhinoceross, understanding the algorithm while having fun processing and generating various images.
Research
First, let's start by understanding the marching squares algorithm.
Wikipedia[2] provides a very clear explanation, so I will quote it here with some additional information.
Algorithm steps
1) Binarization of data
The values ​​of a 2D scalar field are binarized using a reference value (threshold) to produce a black and white pixel image.
If it is above the standard value, it is set to "1".
If it is less than the standard value, it will be set to "0".
② Creating contour cells
For each 2x2 block of the binarized image, we construct one "contour cell". This grid of contour cells is one cell smaller in each direction than the original 1D scalar field. (In the image below, we originally had a 2*1 discrete scalar field, but this process turns it into a XNUMX*XNUMX grid.)
[From here, we will process each cell]
③Determining cell index
A cell index is created by going clockwise around each of the four corners of the outline cell (which hold a binary value of 4 or 1). This index is a 0-bit value that can have 4 possible states, from 0 to 15.
④Lookup table reference
The generated index is used to reference a lookup table that has been prepared in advance. The lookup table specifies which side of the cell the contour should pass through. The marching square only uses the 16 basic shapes listed in this lookup table.
⑤Linear Interpolation
On the edges of the cell, the exact position of the contour is corrected by linear interpolation using the original 2D scalar field values, which allows us to obtain a smoother boundary line by modifying the basic 16 types.
After executing ① and ②, steps ③ to ⑤ are processed in order for each cell to draw the boundary lines representing the contour lines.
The cute part is the process of processing the 16 different shape patterns into 4-bit binary data.
Build
As confirmed in the steps of the marching squares algorithm, there is a slight difference between state ④, which uses 16 basic shapes to represent the boundary line, and state ⑤, where linear interpolation is applied, so we will divide the execution stages of marching squares into the following three states.
state
name
Description
1
marching squares threshold
The state after binarization using a threshold value. The state of pixelated images.
2
marching squares 16 pattern
16 basic shapes are assigned to the cell index. Borders can be set at 45 degrees to the grid, improving expressiveness.
3
marching squares linear interpolation
Linear interpolation is applied using the scalar field values ​​before decomposition into thresholds. Smooth boundaries can be expressed.
16 basic shapes
I modeled 16 basic shapes as solid polysurfaces on Rhino. Since I'm assuming 2D image processing, I've temporarily unified the height to 1. Looking at the image below, it looks like there are only 15 types, but the "empty space in the upper left" is also counted as one of the states that represent the shape, so there are a total of 16 types.
In state 2, the shape is recreated by arranging these 16 blocks like building blocks.
Binary Operations
Binary operations on Grasshopper were processed as Python code in the Python Script component. The binary values ​​(4 or 10) of the four nodes around the cell are lined up, read as a 0-bit number, and output as a decimal number between 15 and 0. A block corresponding to this number between 15 and XNUMX is selected from the group of shapes mentioned earlier and placed at the cell's position to create a shape with marching squares applied.
Python 3 Script
```
# n: 正方形ピクセル画像の縦横ピクセル数
# p: 各ノードの値(0or1)(ex n=64のときpは1024個のリストデータ)

def convert_to_matrix(n, p):
    matrix = []
    for i in range(n):
        row = p[i*n:(i+1)*n]
        matrix.append(row)
    return matrix

def calculate_p_values_as_int(n, p):
    # 一次元リストを二次元行列に変換
    p_matrix = convert_to_matrix(n, p)

    results = []
    for i in range(n-1):
        for j in range(n-1):
            # 4ビットのバイナリ数値を文字列として取得
            binary_str = f"{p_matrix[i][j]}{p_matrix[i][j+1]}{p_matrix[i+1][j+1]}{p_matrix[i+1][j]}"
            # バイナリ文字列を整数に変換
            int_value = int(binary_str, 2)
            results.append(int_value)
    return results

#各輪郭セルのバイナリ値（0~15）
results = calculate_p_values_as_int(n, p)
print(results)
```
Linear Interpolation
By applying linear interpolation in step ⑤ of the algorithm, the output image can be made smoother. As an example of linear interpolation, the processing of a certain cell (4-bit binary value "0110") is shown in the figure below.
First, the leftmost figure shows the state after the value of each node has been converted to a binary value of 0.5 using a threshold value of 01 for a scalar field. For this cell, reading the binary value of the nodes clockwise from the top left gives "0110". Since "0110" corresponds to the block "10" when read in decimal, this block is placed. This is represented by the shape of A in the center of the image, and in terms of the execution stage of the algorithm, this is state 6.
After obtaining the shape of A, for the corners between 0 and 1, we use the scalar values ​​(here, 0.1, 0.6, 0.9, 0.4) before classifying with the threshold to estimate the coordinates of the threshold (0.5) through linear interpolation, and perform an operation to deform the shape. The resulting shape of B becomes state 3 in the algorithm execution phase.
Run test
By combining the elements constructed above, we created an execution environment for the Marching squares method on Grasshopper.
Below are some examples of its use: 1) smoothing the boundaries of a pixel image, and 2) visualizing the contour lines of a randomly generated scalar field.
① Smoothly convert pixel image boundaries
Here we show the process of applying marching squares to various 64x64 pixel images at three execution stages, listed from left to right as state1, state2, and state3.
The further to the right you go in each image, the smoother the boundaries become, and the more beautiful the image looks. The pixel art on the far left cannot express shapes thinner than the size of a single cell, but the image on the far right can properly express even the thin parts (the Nemuro Peninsula in Hokkaido is beautifully expressed). Also, the round tire shape of a car or the curved shapes of penguins can sometimes look unnatural when expressed in pixels, but by applying marching squares, you can create a natural smoothness.
From top to bottom, "Hiragana no nu," "Hokkaido main island," "F1 car," and "Penguin."
Comparison with grayscale image
In the above image processing, when converting from state 2 to state 3, a scalar value between 0 and 1 is given to each node as information on the original image. Let's compare a grayscale image drawn by corresponding this scalar value to luminosity with the result of extracting the boundary by applying marching squares.
The image below shows a close-up of a penguin's fin. In the grayscale image on the left, the right-angled pixel boundaries are prominent and the fin shape does not look natural. On the other hand, the image overlaid with marching squares on the right has the same amount of information, but the smooth shape is easier for the human eye to observe.
② Contour visualization of randomly generated scalar fields
Next, I'll show an example of constructing a scalar field by giving random values ​​to a 64x64 grid, and then running marching squares on that scalar field. An averaging filter is applied to the scalar field, and I made a gif to show how the random value changes are smoothed out by gradually increasing the filter strength.
It starts with the most minute patterns and gradually changes to larger and larger clumps. The image itself has no physical meaning, but if we give meaning to the scalar field, we can hopefully generate useful shapes.
Next, I made a gif of the original random seed value using a constant averaging filter, which gives a variety of images with similar shape granularity.
To me it looks like I'm generating countless maps of continents that don't exist, but what will you create?
Extra
At the beginning, I explained that marching squares is a 2D version of marching cubes. Here, I will briefly summarize the results of my trial of marching cubes.
In marching cubes, one cell of marching squares is expanded to a cubic lattice with eight vertices. The basic shapes expressed by the 0 and 1 points are 30 shapes obtained by rotating the 256 shapes shown below on the XYZ axes and removing duplicates. This number is equal to the total 8 possible combinations of 0 to 255 that can be expressed by the 256-bit binary value created by the binary values ​​of the eight vertices.
Below we have listed for several shapes the correct data we want to represent, a voxel representation using only cubes, and a representation using 2 basic shape blocks, which corresponds to state 256 of maching cubes.
Even when using 256 blocks for 2D shapes, it was difficult to achieve a smooth expression. Linear interpolation is possible in XNUMXD space, just like in XNUMXD, but implementing it in Grasshopper seems to be quite complicated, so this time I only worked up to state XNUMX, but I think you can get a glimpse of the effect of marching cubes.
Review
This time, I used the marching squares method to create smooth boundaries from pixel images and new boundaries from randomly generated scalar fields. The marching squares method itself can be said to simply process a grayscale image to make the boundaries easier to see, but when people see the smooth output shape, their perception and impression changes significantly, so I think this will lead to differences in the information and ideas that can be obtained from it.

matrix = []
for i in range(n):
row = p[i*n:(i+1)*n]
matrix.append(row)
return matrix

def calculate_p_values_as_int(n, p):
# Convert one-dimensional list to two-dimensional matrix
p_matrix = convert_to_matrix(n, p)

results = []
for i in range(n-1):
for j in range(n-1):
# Get 4-bit binary value as string
binary_str = f"{p_matrix[i][j]}{p_matrix[i][j+1]}{p_matrix[i+1][j+1]}{p_matrix[i+1][j]}"

int_value = int(binary_str, 2)
results.append(int_value)
return results
# Binary value of each contour cell (0~15)
results = calculate_p_values_as_int(n, p)
