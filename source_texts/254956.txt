Context & Objectives
3D Gaussian splat scenes in the Peoria Desktop application contain between 40,000 and 50,000 splats. Sorting these splats synchronously on the main JavaScript thread during camera motion consumed 8 to 15 ms per frame, causing potential CPU spikes and frame drops on lower-end hardware.
This PR offloads 3D Gaussian splat depth sorting to a dedicated Web Worker thread (src/js/splatSortWorker.js) using zero-copy Transferable ArrayBuffers to ensure smooth 60 FPS rendering without main-thread CPU jank or visual depth inversion artifacts during camera motion.
Implementation Summary
Web Worker Module (src/js/splatSortWorker.js):
Implemented worker module to handle off-thread back-to-front depth sorting.
Receives initial splat positions via init message.
Calculates squared Euclidean distances from camera coordinates to splat positions.
Sorts splat indices back-to-front (descending distance).
Uses zero-copy Transferable ArrayBuffers (postMessage({ type: 'sortComplete', indices: sortedIndices.buffer }, [sortedIndices.buffer])).
Exports functions (initSplats, sortSplats) so logic can be imported and tested in Node.js unit tests.
Renderer Integration (src/js/splatRenderer.js):
Initialized splatSortWorker.js in GaussianSplatRenderer.
Added camera motion thresholding (cameraMotionThreshold = 0.01): sends camera updates to worker when camera moves, avoiding redundant calculations when stationary.
Implemented reusable index buffer transfers (reusableIndexBuffer) between main thread and worker thread.
Non-blocking render fallback: if worker calculation is in flight, renderer draws using existing instanced attributes without blocking render frames.
Synchronous fallback: if Web Worker context is unavailable, falls back cleanly to local sorting.
Automated Tests (tests/splatWorker.test.js):
Added 5 unit tests covering splat initialization, distance math, back-to-front index ordering, reusable ArrayBuffer transfers, and renderer camera motion thresholding.
