What
ca_core::octree:
build_partial(cloud, params, split_level) builds the levels above split_level and returns every node there that still needs splitting as a PendingSubtree.
build_subtree builds one pending subtree over its own point slice and cube.
graft attaches it, rebasing point ranges and node indices.
WASM: Cloud.startIndex / subtreePositions / subtreeColors / finishSubtree / endIndex on the owning worker, and buildSubtree for pool workers.
Worker: clouds with at least 1M points build the top two levels locally and then run up to 64 subtree jobs on the pool, largest first. Smaller clouds use the single-threaded build as before.
Pool:
Dynamic scheduling: each idle worker takes the next slice. This keeps uneven jobs balanced, for example flat terrain yields 16 subtrees of different sizes.
Slices are created lazily, so large buffers are not all copied out at once.
This also applies to the C2C and C2M pools.
The status line shows index … on N workers.

Breakdown (warm run): the serial top two levels take 1.7 s; subtrees on 8 workers take 0.7 s, including 0.4 s of copying; write-back takes 0.25 s. The serial top-level passes now dominate. Parallelising those would mean moving the whole cloud between workers, so it is left for later.
A 1M-point cloud now indexes in 215 ms on 8 workers.
Verification
New Rust test: a partial build plus built and grafted subtrees gives a valid octree. It checks that every point appears once, positions and colors agree with order, points lie in their node cubes, child levels and sizes are consistent, and the root matches a plain build. All 56 tests pass.
Browser: C2C results are unchanged (sample mean 0.022061; 1M-point pool run mean 0.055383).
