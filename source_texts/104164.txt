WebGPU Benchmark for Browser GPU Performance
Volume Shader BM runs a real WGSL ray-marching pipeline when WebGPU initialization succeeds and records the backend that completed the timed frames. It is free, needs no installation, and reports FPS, frame time, min/max FPS, duration, and stability. A failed WebGPU request is shown and stored as a WebGL2 fallback, never as a WebGPU result.
Start WebGPU-capable testRead methodology
WebGPU availability depends on browser, operating system, driver, and adapter. A fallback uses the versioned WebGL2 path and clearly labels the requested API, actual backend, renderer version, and fallback reason.
What this benchmark measures
The workload renders a ray-marched fractal and records FPS, frame time, min/max FPS, duration, stability, requested API, actual backend, renderer version, preset, and browser environment. It does not measure temperature, power, clocks, or system-wide utilization.
How to compare results fairly
Use the same preset, keep background tabs closed, let the device cool down before testing, and compare against the matching desktop or mobile leaderboard. API labels help separate WebGPU and WebGL2 runs.
Where the result goes
Submitted samples can create public result pages and contribute to live GPU benchmark rankings when they pass quality checks. Low-quality, unstable, or duplicate samples should not be treated as leaderboard-grade evidence.
FAQ
Is this a native WebGPU benchmark?
No. It runs in the browser. That makes it useful for real browser GPU behavior, but native tools may expose lower-level driver and hardware details.
Why might WebGPU fall back to WebGL2?
Browsers gate WebGPU by platform support, driver policy, and adapter availability. The result remains auditable because the requested API and actual WebGL2 backend are stored separately with a fallback reason.
