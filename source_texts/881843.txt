Summary
Follow-up to #2. Step 1 there was a single-bounce raycast preview - no shadow rays, no indirect lighting, one material. This turns the same standalone gpu/metal/metal_poc.mm/.metal proof-of-concept into an actual minimal Monte Carlo path tracer:
Shadow-ray occlusion against the directional light (real next-event estimation, not an unoccluded dot(N,L) term)
Multi-bounce indirect lighting via cosine-weighted hemisphere sampling with Russian-roulette termination after depth 3 - the same unbiased early-termination shape the CPU integrator (path_integrator.h) uses
A second material (mirror / perfect specular) to prove per-primitive material-type branching works, not just per-primitive colour
Multi-sample antialiasing via jittered primary rays, with SPP/max-depth as CLI arguments
Visually confirmed: correct reflections in the mirror, a real contact shadow cast onto the floor, and subtle red/green colour bleeding onto the back wall near the corresponding walls (genuine diffuse GI, not direct lighting alone). 600x600 @ 256 samples/pixel @ depth 8 renders in ~2.2s wall-clock (including acceleration-structure build and runtime shader compile) on an M2.
A real bug found and fixed along the way
MSL's float3 inside a struct is 16-byte aligned but only 12 bytes in size - a host-side simd::float3 and device-side float3 at the same struct offset aren't guaranteed to agree on where the next field starts. This is a silent host/device layout mismatch: compiles fine, runs fine, renders wrong data in the wrong field, no error anywhere. Fixed by using packed_float3 (size 12, align 4, zero padding) on both sides of every struct shared across the host/device boundary (Uniforms, TriangleMaterial), with explicit float3(...) conversions at math call sites. Documented as a rule to carry forward into the real port in docs/METAL_GPU_FEASIBILITY.md section 9.
Scope
Still a standalone spike, not wired into CMakeLists.txt or the launcher. One light, two materials, no textures, no area lights. This is deliberately still proving pipeline shape (now one level deeper - a real path integrator, not just primary-ray shading) rather than building toward feature coverage.
Test plan
Compiles cleanly
Renders correctly on real Apple Silicon (M2): mirror reflections, shadows, GI colour bleeding all visually confirmed
Noise at low sample counts (32spp) converges to a clean image at higher counts (256spp), matching expected Monte Carlo behaviour
