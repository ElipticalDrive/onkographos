This PR adds new GaussianSplatVisual (scene node scene.visuals.GaussianSplat) and an example, examples/scene/gaussian_splatting.py, that loads a 3DGS .ply file. Each splat is drawn as an instanced, screen-aligned quad (like the instanced Markers visual), so this needs the gl+ backend. Splats are depth-sorted on the CPU and blended back-to-front. The sort only re-runs when the view direction rotates beyond a small threshold. The per-splat data lives in a texture that is uploaded once, so only the draw order is re-uploaded.
I relied on Claude Code for a few key bits of math in the shader, but overall I think it is pretty understandable and readable.
API
GaussianSplat(positions, covariances, colors, opacities=None, *, antialias=False)
Argument
Shape
Notes
positions
(N, 3)
Gaussian centers
covariances
(N, 3, 3)
symmetric positive-definite 3D covariance per Gaussian
colors
single color, (N, 3) RGB, or (N, 4) RGBA
a single color is anything Color accepts, broadcast to every splat
opacities
(N,) or scalar
peak opacity per splat; required with RGB, comes from the alpha channel for RGBA (passing both raises), and overrides a single color's alpha
antialias
bool
scale opacity to offset the screen-space low-pass dilation, for scenes trained with anti-aliasing (Mip-Splatting, gsplat "antialiased")
Next steps
View/orientation-dependent color
For now this only supports a single color per-splat. Gaussian splats often provide colors as spherical harmonics to create orientation-dependent colors (specular highlights, pearlescent or color-shifting pigment, etc.). The current example just extracts the 0th spherical harmonic term and uses that as the color. We can add this later without breaking the API
colors would also accept (N, K, 3) SH coefficients, where K = 1, 4, 9 or 16 (degree 0–3).
A new sh_degree= keyword and property would let you set the rendered degree at runtime, plus max_sh_degree (based on K) and sh_coeffs properties.
Plain colors become the degree-0 case and render the same. colors still returns RGBA unless you pass higher-order SH coefficients.
Luxar splats
This adds a few things, but importantly it adds a per-point intensity. I still need to get more familiar with this, but it looks useful for microscopy data and lots of scientific data in general. I think the API should be purely additive (non-breaking):
new values= / cmap= / clim= / gamma= keywords, named like ImageVisual and VolumeVisual, with colors becoming optional;
a method= keyword ('translucent', the current default, plus 'additive' and max). Those last two are order-independent and can skip the sort entirely.
Example
For the example here, I uploaded some data to a fork of the vispy demo data repo. You can find more demo data at https://superspl.at/.
