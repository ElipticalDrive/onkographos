Background
MRPT/mrpt#1490 fixes two problems in the MRPT-GTSAM covariance conversions:
mrpt::gtsam_wrappers::to_gtsam_se3_cov6() (MRPT (x,y,z,yaw,pitch,roll) covariance to GTSAM Pose3 tangent (rx,ry,rz,tx,ty,tz)) was wrong:
It reordered the rotation block as if it were still (yaw,pitch,roll) after converting it into a rotation vector, so the x and z rotation axes were swapped, even at the identity pose. A roll-only variance ended up in GTSAM RZ.
It did not express the translation block in the body frame.
It now uses the exact first-order Jacobian of xi = Logmap(mean^-1 * pose), validated against GTSAM 4.2.
mrpt::gtsam_wrappers::to_mrpt_se3_cov6() (GTSAM marginal to MRPT covariance) only reorders entries, so it is exact only at the identity rotation. Elsewhere it leaves the translation block in the body frame and the rotation block as a rotation vector instead of yaw/pitch/roll. In the test poses, the reordered and exact covariances differ by up to 0.15. The PR adds mrpt::gtsam_wrappers::to_mrpt_se3_pdf(pose, cov), the exact inverse of to_gtsam_se3_cov6().
Changes needed in this repo
Behavior change, no code change needed: all GTSAM noise models built with to_gtsam_se3_cov6() will change once MRPT includes MRPT/mrpt#1490. Re-validate the tuning (sigma floors, gates) that depends on them:
StateEstimationSmoother.cpp#L671: T_enu_to_map prior.
StateEstimationSmoother.cpp#L1271: wheel-odometry anchor.
StateEstimationSmoother.cpp#L1328: odometry increments.
StateEstimationSmoother.cpp#L2043: pose observations.
StateEstimationSmoother.cpp#L2145: relative pose increments.
Code changes: convert GTSAM marginals with to_mrpt_se3_pdf() instead of to_mrpt_se3_cov6():
StateEstimationSmoother.cpp#L3528: T_enu_to_map covariance.
StateEstimationSmoother.cpp#L3538: latest pose covariance, used to check the MAP to BASE_LINK position uncertainty. Its diagonal entries 0..2 are currently body-frame tx,ty,tz, not global x,y,z. A trace-based check is unaffected; per-axis checks are.
StateEstimationSmoother.cpp#L3669: T_map2_odom_i covariance. Note that the mean may come from liveRelativeFrame() instead of T_map2_odom_i. Use the pose the covariance refers to.
StateEstimationSmoother.cpp#L4351: ns.pose.cov_inv. Convert first, then invert. Also note that inverse_LLt() does not check positive-definiteness; the determinant check above it is the only guard.
mola_georeferencing/src/simplemap_georeference.cpp#L529: T_enu_to_map covariance of the georeferencing result.
These need MRPT with MRPT/mrpt#1490 merged.

2. recenter_georeference() uses the inverse of the T_enu_to_map convention
simplemap_georeference.cpp L570 computes map to ENU as T_enu_to_map^-1, i.e. p_enu = T^-1 * p_map. The rest of the code uses p_enu = T_enu_to_map * p_map: FactorGnssMapEnu, sm2mm, mm2las, mm-viewer, BridgeROS2, and the other georeferencing tests (T_enu_to_sensor = T_enu_to_map + T_map_to_veh + ...).
Re-datuming moves the map's geodetic placement by 16 m, 8.8 m and 196 m in three test cases.
test_recenter_georeference.cpp encodes the same inverse convention (inverseComposePoint), so it passes.
The patch fixes the function, its header doc and the test property. It is exact to 5e-9 m.
