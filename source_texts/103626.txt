Lecture 10 (Part I): Raytracing (Part I)
Emmanuel Agu
Raytracing
n Global illumination-based rendering method
n Simulates rays of light, natural lighting effects
n Because light path is traced, handles some effects that are
tough for openGL:
n Shadows
n Multiple inter-reflections
n Transparency
n Refraction
n Texture mapping
n Newer variations… e.g. photon mapping (caustics,
participating media, smoke)
n Note: raytracing can be whole semester graduate course
n Today: start with high-level description
Raytracing Uses
n Entertainment (movies, commercials)
n Games (pre-production)
n Simulation (e.g. military)
n Image: Internet Ray Tracing Contest Winner (April 2003)
How Raytracing Works
n OpenGL is object space rendering
n start from world objects, rasterize them
n Ray tracing is image space method
n Start from pixel, what do you see through this pixel?
n Looks through each pixel (e.g. 640 x 480)
n Determines what eye sees through pixel
n Basic idea:
n Trace light rays: eye -> pixel (image plane) -> scene
n If a ray intersect any scene object in this direction
• Yes? render pixel using object color
• No? it uses the background color
n Automatically solves hidden surface removal problem
Case A: Ray misses all objects
Case B: Ray hits an object
Case B: Ray hits an object
§ Ray hits object: Check if hit point is in shadow, build
secondary ray (shadow ray) towards light sources.
Case B: Ray hits an object
§If shadow ray hits another object before light source: first intersection
point is in shadow of the second object. Otherwise, collect light
contributions
Case B: Ray hits an object
§First Intersection point in the shadow of the second object is
the shadow area.
Reflected Ray
§When a ray hits an object, a reflected ray is generated which is
tested against all of the objects in the scene.
Reflection: Contribution from the reflected ray
Transparency
§If intersected object is transparent, transmitted ray is generated and
tested against all the objects in the scene.
Transparency: Contribution from transmitted ray
Reflected Ray: Recursion
Reflected rays can generate other reflected rays that can generate
other reflected rays, etc. Case A: Scene with no reflection rays
Reflected Ray: Recursion
Case B: Scene with one layer of reflection
Reflected Ray: Recursion
Case C: Scene with two layers of reflection
Ray Tree
n Reflective and/or transmitted rays are continually generated until
ray leaves the scene without hitting any object or a preset
recursion level has been reached.
Ray-Object Intersections
n So, express ray as equation (origin is eye, pixel
determines direction)
n Define a ray as:
R0 = [x0, y0, z0] - origin of ray
Rd = [xd, yd, zd] - direction of ray
n then define parametric equation of ray:
R(t) = R0 + Rd * t with t > 0.0
n Express all objects (sphere, cube, etc) mathematically
n Ray tracing idea:
n put ray mathematical equation into object equation
n determine if real solution exists.
n Object with smallest hit time is object seen
Ray-Object Intersections
n Dependent on parametric equations of object
n Ray-Sphere Intersections
n Ray-Plane Intersections
n Ray-Polygon Intersections
n Ray-Box Intersections
n Ray-Quadric Intersections
(cylinders, cones, ellipsoids, paraboloids )
Writing a RayTracer
n The first step is to create the model of the objects
n One should NOT hardcode objects into the program, but instead use
an input file.
n This is called retained mode graphics
n We will use SDL
n Ray trace SDL files
n The output image/file will consist of three intensity values (Red,
Green, and Blue) for each pixel.
Accelerating Ray Tracing
n Ray Tracing is very time-consuming because of intersection
calculations
n Each intersection requires from a few (5-7) to many (15-20)
floating point (fp) operations
n Example: for a scene with 100 objects and computed with a
spatial resolution of 512 x 512, assuming 10 fp operations per
object test there are about 250,000 X 100 X10 = 250,000,000 fps.
§ Solutions:
§ Use faster machines
§ Use specialized hardware, especially parallel processors.
§ Note: ray tracing does not use 3D graphics card (new drn)
§ Speed up computations by using more efficient algorithms
§ Reduce the number of ray - object computations
Reducing Ray-Object Intersections
n Adaptive Depth Control: Stop generating reflected/transmitted
rays when computed intensity becomes less than certain threshold.
n Bounding Volumes:
n Enclose groups of objects in sets of hierarchical bounding volumes
n First test for intersection with the bounding volume
n Then only if there is an intersection, against the objects enclosed by
the volume.
n First Hit Speed-Up: use modified Z-buffer algorithm to determine
the first hit.
Writing a Ray Tracer
n Our approach:
n Give arrangement of minimal ray tracer
n Use that as template to explain process
n Minimal?
n Yes! Basic framework
n Just two object intersections
n Minimal/no shading
n Paul Heckbert (CMU):
n Ran ray tracing contest for years
n Wrote ray tracer that fit on back of his business card

Setting RC-th pixel to Calculated Color
n Break screen into blocks (fat pixels)
n Ray trace only top-left pixel of block
n 1 calculation, set entire block to calculated color
n E.g. BlockSize = 3, ray trace, top-left pixel, set entire block to green
n Affects resolution of picture
n Initially use large blocksize to verify code, then set to 1
