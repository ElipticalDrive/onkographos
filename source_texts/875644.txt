Owner
Adds FractalDamped, a fractal sum where each octave is damped by 1 / (1 + d·d). d is the sum of the earlier octaves' gradients (Inigo Quilez, "Value Noise Derivatives" and "Gradient Noise Derivatives"). It also adds analytic value-plus-gradient functions for Simplex, SuperSimplex, Perlin and Value in 2D, 3D and 4D, plus native builds from one commit.
Commit built: 7e78eb50d63df97c85bf2a7662b0a848b23162bc, branched from upstream 721400f (project(FastNoise2 VERSION 1.1.1)). The binaries are in draft release fractaldamped-7e78eb5, which supersedes drafts fractaldamped-5d55103 and fractaldamped-cc98a3c.

The analytic gradients use the matching derivatives, 30t²(t−1)² and 6t(1−t).

Analytic + Auto: one call to the source's GenGradient. A source without a gradient (an operator, a warp, a chain) uses ApproximateFast.
Analytic + explicit formula: the value comes from the source's Gen and the slope from the formula at the Slope Feature Scale and Slope Seed Offset. This costs a second noise evaluation. It equals Auto only when both settings match the source's own.
ApproximateFast: forward differences, ε = cell / 256, N extra samples per octave. A forward difference measures the slope half a step ahead of the sample, so its damping lands ε/2 = 1/512 of each octave's cell toward −x and −y (and −z, −w). Use ApproximateAccurate when the result has to line up with Analytic. The Mode tooltip says so.
ApproximateAccurate: central differences, ε = cell / 64, 2N extra samples per octave.
Both approximate modes divide by the realised step, (p + ε) − p. The Mode tooltip says both lose accuracy beyond about 1e5 cells of the highest octave.
Implementation notes:
DispatchClass<Generator, SIMD> gains GenGradient (2D/3D/4D; by default it returns false) and SlopeCellSize. There is no RTTI in Gen, and the public headers are unchanged apart from Fractal.h.
Each override applies its own mSeedOffset, ScalePositions and ScaleOutput, and the gradient is per noise cell in output units.
Gradient vectors are decoded once per vertex from the same hash bits and tables the dot products use.
FractalDamped is registered last. The metadata vector sizes go to 48 / 102 / 100 / 33 / 61, and DebugCheckVectorStorageSize is quiet (tested).
Deviations from the brief, all agreed
1. Value vs Gen
With relaxed floating point the compiler orders the same source differently in Gen and in the gradient function.
GenGradient (the route the node uses): |value − Gen| ≤ 4 × ulp(max(|Output Min|, |Output Max|)) at every point, ±1e6 world included, with non-default seed offset, Feature Scale and Output Min/Max.
Static functions: 4 range ulps + k × |∇n| × ulp(largest lattice coordinate). k counts the roundings from the input coordinate to the vertex offset: Simplex and SuperSimplex 8/10/12 (2D/3D/4D), Perlin and Value 2. GCC orders the skew additions differently in the test's separately compiled copy.
Measured on GCC at ±1e6 under the plain 4-ulp bound: Simplex 2D 25458, Simplex 3D 19704, SuperSimplex 2D 14922 and SuperSimplex 3D 14987 range ulps.
ClangCL and Apple Clang stay within 4 on both routes. Test 7 (Constant source equals FractalFBm) is exact.
2. Approximate: ApproximateFast (forward, cell / 256) and ApproximateAccurate (central, cell / 64) in place of central differences at cell / 8
Folding fix: fast-math folded (p + ε) − p back to ε in ApproximateFast. At 1e5 cells, where p + ε rounds (realised step 2.0 against ε = 1.5625), that put ApproximateFast 0.019 off a hand-built realised-step result. An XOR with a zero the compiler cannot see (a volatile read) now keeps the rounded position, in both modes.
Proof on every compiler: the hand-built check at 1e5 cells matches to ≤ 1.2e-7 at every SIMD level, on every compiler (table below).
Step floor: at ±1e6 cells a 1/64-cell ε is below float spacing, so the step is floored at |p| / 2²¹, a few ulps of the position.
