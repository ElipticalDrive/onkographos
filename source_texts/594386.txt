Summary
PR-02 implements a dense immutable spk::Voxel::Volume, packed 32-bit cells, and JSON-loaded, immutable Shape and Definition registries. Branch: impl/v0.1.4/02-voxel-volume → V0.1.4.
Confirmed architecture
Shape::Registry::Builder extends spk::JSON::Catalog<Shape, std::string>. load(file) and add(string, Shape) construct named Shapes; build() publishes Shape::Registry.
Shape and Definition Builders (Shape::Builder, Shape::Registry::Builder, Definition::Builder, Definition::Registry::Builder) expose only default construction. Volume::Builder is the exception: its fixed grid dimensions are mandatory and supplied through explicit Builder(spk::Vector3UInt dimensions); there is no default constructor or setDimensions(). Shape::Builder::addFromJSON(value) replaces its JSON constructor, and Definition::Registry::Builder::bind(shapes) replaces its constructor taking a Shape registry. Definition::Builder uses bind(shapes) and std::optional<Shape> to represent explicit Shape selection. Both Builders hold a default-empty Shape::Registry. Definition::Builder uses std::optional<Shape> to represent explicit Shape selection; there is no separate _hasShape flag. Definition::Builder::build() throws until a Shape was selected explicitly; Air remains available only as Definition::air(). A deliberately selected empty Shape is still valid. Rebinding resets the optional.
Both published Registry types own shared_ptr<const Data>; copying either Registry is O(1), no further mutation is possible. Builders remain reusable and never mutate previous snapshots.
Published Registry storage uses unordered_map (expected O(1) ID lookup), with no speculative sorted set, huge dense array, or mesher-specific performance cache. JSON::Catalog supports an optional explicit ID type and exposes its entries to subclasses for publication.
Definition::Registry reserves numeric ID 0 for Definition::air(). at(0), operator[](0), contains(0), and tryGet(0) agree. Explicit IDs are limited to the upper 29 bits. Shape Registry IDs are strings.
Unregistered IDs throw descriptive spk::Exception from at and operator[]; tryGet returns null. Both JSON registries use the existing {"elements":[{"id":...,"data":...}]} format.
Volume and packed file
Each packed cell remains 32 bits: upper 29 bits contain the registry's numeric Definition ID directly, lower 2 bits describe horizontal orientation, and one bit describes vertical inversion. Volume::PackedCell remains declared in include/voxel/volume.hpp, but all four codec functions (encode, definitionId, horizontal, vertical) are now defined out of line in the dedicated src/voxel/volume_packed_cell.cpp translation unit; their behavior is unchanged. Decoder methods remain noexcept but are no longer constexpr, while the compile-time constants Air and MaxDefinitionId stay in the header. The existing core source glob picks up the new file automatically. Public Volume::at(position) and operator[](position) return a reconstructed Cell by value; atRaw(position) returns the packed uint32_t word directly. All three perform bounds checks and throw spk::Exception for invalid positions. The former cell(position) method was removed.
Volume::Data is a private struct defined in include/voxel/volume.hpp, holding fixed dimensions, a copied immutable Definition::Registry, and a contiguous vector<uint32_t> cell grid.
There is no Volume-local Definition table, ID remapping, or set(position, Cell). Volume::Builder::set(position, id, orientations) requires an ID registered in its bound snapshot; erase resets a cell to canonical Air.
Volume::at(position) and operator[](position) reconstruct Cell values, while atRaw(position) returns the original packed storage word by value. Volumes and their Definition registries are cheap to copy; old Volumes are unaffected by later Builder edits.
Volume::Builder(dimensions) validates dimensions and creates an Air-filled dense grid immediately. Dimensions never change over the Builder's lifetime. bind(registry) binds a snapshot separately; load(const Volume&) copies only a same-dimension Volume's registry and cells, rejecting mismatched dimensions without modifying the Builder. Explicit loadPacked(filename) imports with the dimensions fixed at construction. The former constructors combining dimensions, registry and filename remain removed. bind preserves used non-Air IDs.
Packed files remain headerless raw little-endian 4-byte words with caller-provided dimensions; the importer validates all IDs and file length without any ID conversion. Failures leave the Builder unchanged, including after partial decoding.
Dimensions and offsets are checked against overflow; Builder publication is consuming while exception failure leaves it usable.
Tests and scope
55 dedicated PR-02 voxel GoogleTest cases: voxel_volume_test.cpp (19), voxel_packed_file_test.cpp (15), voxel_registry_json_test.cpp (21), plus existing Shape JSON fixture tests updated for default construction.
Covers snapshots, immutable Registry publication and sharing, Air and sparse IDs, JSON catalogs, orientation encoding, external-ID preservation, malformed binary inputs, illegal rebinds, old snapshot stability, Builder failure atomicity, and consuming builds.
One additional generic JSON Catalog test ensures missing lookup errors include the requested ID; other pre-existing unit tests remain unchanged.
The test-only VolumeTestAccess friend structure is removed from the public header and unit tests. Snapshot tests use observable behavior; packed tests inspect the public atRaw result, and Builder consumption is verified by thrown exceptions.
No mesher, occlusion cache, Model, Assembly, GPU logic, chunking, sparse grids, or streaming.
