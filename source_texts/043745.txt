Context
research-architecture needs a visualization layer for architectural collections, CAD geometry, meshes, point clouds, spatial measurements, and comparative experiments. PyVista is a strong core choice because it provides Python-native 3D visualization and mesh analysis on top of VTK, with support for points, surfaces, volumes, datasets, filtering, interactive plotting, and readers/writers. citeturn0search0turn0search4
The research stack should not depend on a single visualization library. Different research objects require different representations: CAD/mesh, point cloud, scientific volume, 2D statistical plots, interactive web graphics, and graph/network views.
Decision
Adopt a polyglot visualization stack with PyVista as the primary 3D scientific/engineering layer, while evaluating complementary libraries by research purpose rather than forcing one library to handle every visualization problem.

Architecture
```

       ↓
CAD / BIM / Image / Point Cloud / Mesh / Tabular Data
       ↓

       ├── Point Cloud → Open3D

       ├── Interactive Web → Plotly
       ├── Graph Relations → NetworkX
       └── High-performance Rendering → VisPy (evaluation)
       ↓
Visualization Experiment
       ↓
Observation / Measurement
       ↓
Evidence
```
Research questions
Which representation best preserves architectural information from CAD and scanned geometry?
When should geometry processing be separated from visualization?
Can the same architectural object be rendered consistently across PyVista, Open3D, and web visualization?
Which visualization operations produce measurable research evidence rather than merely presentation images?
What is the minimum interoperable data model between CAD, mesh, point cloud, and analytical visualization?

Important distinction
Visualization is not Evidence by itself. A rendered image is an artifact. A visualization becomes research evidence only when it is derived from a defined observation/measurement procedure with provenance and evaluation criteria.
Initial recommendation
Start with:
PyVista + Open3D + Matplotlib + Plotly + NetworkX
Then test trimesh, Altair, VisPy, and vedo only where a concrete research requirement justifies them.
PyVista should remain the default 3D research renderer because its data model explicitly covers geometry/topology and its API supports mesh analysis and interactive plotting. citeturn0search11turn0search9 Open3D is complementary for point-cloud/geometry workflows and can bridge geometry into Plotly figures. citeturn0search6turn0search13
Acceptance criteria
Visualization libraries are registered by capability, not popularity.
At least one CAD/mesh example is rendered with PyVista.
At least one point-cloud example is tested with Open3D.
The same dataset is compared across at least two visualization backends.
Visualization artifacts retain dataset, transformation, library/version, and parameter provenance.
Research observations are separated from presentation artifacts.
Results are recorded as evidence and linked to an RQ/experiment.
