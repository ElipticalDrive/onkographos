Summary
This PR replaces the previous voxelization-based reconstruction pipeline with a production-grade TSDF (Truncated Signed Distance Field) volumetric fusion system. The new pipeline uses OpenChisel for CPU-side chunk management and a GPU compute shader for per-voxel TSDF integration, enabling efficient real-time 3D reconstruction from ARCore depth data.
Key Changes
Core Reconstruction Pipeline
ChiselManager (chisel_bridge/): New wrapper around OpenChisel that manages TSDF integration on a worker thread. Handles frame queueing, mesh extraction, and inter-thread communication via event queues.
TsdfFusionOp: GPU compute shader operation that fuses depth frames into a 256³ R32_UINT TSDF volume. Each thread processes one voxel, computing signed distance and updating the weighted running average.
TsdfVolume: Vulkan 3D image resource (256³, R32_UINT) storing packed TSDF distance (int16, biased to [0,65535]) and weight (uint16) per voxel.
Marching Cubes Integration
Updated marching_cubes.comp.glsl to read from TSDF volume instead of occupancy grid. Extracts surface geometry at zero-crossings of the signed distance field.
Modified MarchingCubesOp to work with the new TSDF format and volume dimensions.
Rendering
OpaquePhongConfig: New pipeline for rendering reconstructed geometry with fixed material color (no texture). Includes two-sided lighting and proper normal handling for backfaces.
MutableMesh: Enhanced with configurable max vertex/index counts and pre-allocated ring buffers for streaming geometry updates.
ARCore Integration
Added getSensorViewMatrix() to ARSessionManager for retrieving the physical (sensor-oriented) camera pose, required for correct TSDF integration in world space.
Optional torch/flash mode support for AR in low-light conditions.
Build System
Added Eigen (header-only math library) and OpenChisel as FetchContent dependencies in CMakeLists.txt.
Created chisel_bridge/CMakeLists.txt with aggressive optimizations (-O3) for the ProjectionIntegrator template code.
Documentation
Architecture.md: High-level system overview and component descriptions.
TSDF.md: Explanation of signed distance fields, truncation, and fusion principles.
OpenChisel.md: Guide to OpenChisel's chunked architecture and key classes.
ChunkPagingProposal.md: Design proposal for future memory-efficient chunk paging (Tier 1: GPU slab allocator, Tier 2: CPU/RAM, Tier 3: Disk).
CLAUDE_CODE_READ_THIS_WHEN_YOU_DO_CHUNK_PAGING_PLS.md: Implementation notes for chunk serialization and reload logic.
Implementation Details
TSDF Packing: Distance values [-1, 1] are biased to [0, 65535] for storage in uint16. Weight is capped at 200 for stable reconstruction.
Worker Thread: ChiselManager runs integration and mesh extraction on a dedicated thread, decoupled from the render loop. Latest-wins frame queueing prevents backlog.
Compute Shader: tsdf_fusion.comp.glsl uses 8×8×4 workgroups for efficient voxel processing. Supports configurable truncation distance and voxel scale.
Frustum Culling Ready: Architecture prepared for future GPU slab allocator with frustum-based chunk visibility (documented in ChunkPagingProposal.md).
Testing Notes
Verify TSDF integration produces correct signed distance values at surface boundaries.
Confirm mesh extraction via Marching Cubes generates watertight geometry.
Test with various truncation distances and weight caps for reconstruction quality.

Implement TSDF volumetric reconstruction pipeline
…
189e4b0
```
Replace the occupancy-based voxelization with a proper TSDF (Truncated
Signed Distance Function) pipeline for accurate 3D surface reconstruction.

New pipeline: TSDF Fusion → Marching Cubes (2 stages instead of 3).
The deprojection step is no longer needed — TSDF fusion performs per-voxel
camera projection directly from the depth buffer.

Key components:
- TsdfVolume: 256³ R32_UINT 3D image, each voxel packs TSDF distance
  (biased int16) and weight (uint16) into a single uint32
- TsdfFusionOp: Per-voxel compute shader that projects each voxel to the
  camera, reads depth, computes signed distance, and fuses via weighted
  running average. Includes free-space carving for dynamic scenes.
- Modified MarchingCubes: Extracts surfaces at TSDF zero-crossings instead
  of occupancy thresholds. Adds minWeight filter to reject under-observed
  voxels. Normals derived from TSDF gradient (smooth, not face-based).

Parameters tuned for plush toy scanning at 0.5cm voxel resolution:
- Scale: 200.0 (0.5cm voxels, covering ±64cm from origin)
- Truncation distance: 4cm
- Weight cap: 32 (sliding memory window)
- Min weight: 2 (requires multiple observations before meshing)
```

```
  accumulated geometry when the camera moved, since voxels in front of
  surfaces were being pushed back to free-space every frame.

- Throttle TSDF fusion to every 3rd frame (scene is static, camera
  moves slowly — fusing every frame was redundant work).
- Throttle marching cubes to every 5th frame (mesh reused between runs).
- Increase TSDF fusion workgroup from 4x4x4=64 to 8x8x4=256 threads
  for better GPU occupancy on Adreno 730.
- Add early depth range exit (skip voxels > 3m from camera).

Parameter tuning:
- Truncation distance: 4cm → 6cm (12 voxels at 0.5cm scale, better
  surface coverage and smoother fusion).
```

```
Root cause: ProjectionIntegrator was constructed with an empty centroids
list. Open Chisel's integrator iterates over these centroids to visit
each voxel in a chunk during raycast integration. With an empty list,
zero voxels were ever updated, so all newly created chunks were

cause IntegrateDepthScan to create a frustum spanning thousands of
chunks, leading to OOM (malloc failure in Chunk::AllocateDistVoxels).
```

Fix camera pose convention: ARCore (OpenGL) → Open Chisel (CV)
…
3d91734
```
ARCore's view matrix uses OpenGL convention (forward = -Z, up = +Y).
Open Chisel uses computer vision convention (forward = +Z, up = -Y).
When Open Chisel unprojects depth pixels, it sets z_cam = +depth,
expecting the camera's +Z axis to point forward. With the raw
OpenGL camera pose, +Z points backward, placing all integrated
geometry behind the camera (gl_Position.w < 0, fully clipped).

Fix: right-multiply the camera-to-world transform by a Y/Z flip
matrix so Open Chisel's +Z aligns with the camera's forward direction.

Confirmed via RenderDoc: VS output showed all W values negative
(-0.18, -0.17, etc.), proving vertices were behind the camera.
```

```
ArCamera_getViewMatrix returns a display-oriented view matrix (axes aligned
with the screen), but the depth image and intrinsics from
ArCamera_getImageIntrinsics are unrotated (sensor coordinates). This mismatch
caused voxels to be projected to wrong depth image pixels, resulting in a 90°
```

```
The previous fix tried to undo display rotation with Rz(r*90), but
gDisplayRotation=0 in portrait mode made it a no-op. The real issue is that
ArCamera_getViewMatrix is the inverse of getDisplayOrientedPose (axes aligned

guarantees the view matrix matches the depth image coordinate frame regardless
of display rotation or sensor mounting orientation.
```

Reduce kFarPlane from 3.5m to 1.5m to fix 24s integration time
…
06f3b21
```
OpenChisel builds its frustum from the actual depth range in the image
(via GetStats), NOT from camera.SetFarPlane(). So the previous
effectiveFar clamping was a no-op — the frustum was still sized to the
max observed depth (up to 2.4m).

The real fix: reduce kFarPlane so depths beyond 1.5m are zeroed BEFORE
OpenChisel sees them. This directly limits the frustum:
- At 2.4m max depth: ~2000 frustum chunks → 24s integration
- At 1.5m max depth: ~600 frustum chunks → ~7s integration
```

```
The main library was compiled at -O0 (Debug), which means Eigen's
header-only matrix math (used by OpenChisel's inner loop template
ProjectionIntegrator::Integrate) ran completely unoptimized — no
inlining, no NEON/SIMD. This caused ~100μs per voxel instead of <1μs.

for crash stacks. OpenChisel's own target already had -O2, but since
the integration template is in a header, it compiled at the caller's
optimization level (-O0).
```
