Random points on a sphere cluster at the top and bottom, and random points inside a sphere cluster near the middle. The docs don't promise an even spread, but the circle version is even, so this is probably unintended.
Fix: use the standard formulas for an even spread. Worth raising as a question.
Technical details: Brutal.Maths/RandomExtensions.cs:165, :203.
Branches
Recommended fix, combined with related bugs: fix/random-sampling
Repro test and fix for this bug only: bug/random-sphere-sampling-not-uniform
Detailed report
Packages and versions: Ahwoo.Brutal.Maths 2026.10.1 (reproduced against source at ahwootech/BRUTAL@a25cdf8, which the 2026.10.1 packages were published from; not separately re-run against the package)
Environment: .NET SDK 10.0.102, macOS 26.6.2 (arm64)
Minimal repro
```
[Fact]
public void NextSingleUnit3_IsUniformOnSphere()
{
    // uniform on the sphere => z is uniform in [-1, 1] (Archimedes), so P(|z| > 0.5) = 0.5
    var r = new Random(12345);
    const int n = 200_000;
    var count = 0;
    for (var i = 0; i < n; i++)
        if (MathF.Abs(r.NextSingleUnit3().Z) > 0.5f) count++;
    Assert.InRange(count / (double)n, 0.49, 0.51);
}

[Fact]
public void NextSinglePointInSphere_IsUniformInVolume()
{
    // uniform in the unit ball => P(r < 0.5) = 0.5^3 = 0.125
    var r = new Random(12345);
    const int n = 200_000;
    var count = 0;
    for (var i = 0; i < n; i++)
        if (r.NextSinglePointInSphere().Length() < 0.5f) count++;
    Assert.InRange(count / (double)n, 0.12, 0.13);
}
```
Expected vs actual
The XML docs say only "a random 3D unit vector" and "a random point within a 3D sphere". They do not promise a uniform distribution. The tests treat uniform sampling as the contract, because that is what callers usually assume. This is a quality bug, not a crash.
Expected: about half of the unit vectors have |z| > 0.5, and about 12.5% of the in-sphere points lie within radius 0.5.
Actual:
```
NextSingleUnit3_IsUniformOnSphere:
Assert.InRange() Failure: Value not in range
Range:  (0.48999999999999999 - 0.51000000000000001)
Actual: 0.66771499999999995

NextSinglePointInSphere_IsUniformInVolume:
Assert.InRange() Failure: Value not in range
Range:  (0.12 - 0.13)
Actual: 0.24918999999999999
```
These are the values the current formulas predict: 2/3 for a uniform phi, and 0.25 for a sqrt radius.
Cause
Brutal.Maths/RandomExtensions.cs:203 (and :211 in the double version) samples the polar angle phi uniformly in [0, pi). The surface area element is proportional to sin(phi), so this clusters vectors at the poles.
Brutal.Maths/RandomExtensions.cs:165 (and :175) scales the radius by sqrt(u). That is correct for a disc, as in the 2D methods at :140 and :150, but not for a ball. Enclosed volume grows as r^3, not r^2, so points cluster towards the centre.
Sampling z = 2u - 1 for the unit vector and using a cube-root radius would make both methods uniform.
