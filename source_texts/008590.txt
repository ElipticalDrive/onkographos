This document covers the ray model and voxelization system that converts sparse LiDAR point clouds into dense 3D occupancy grids. This is a critical component of the OCF (Occupancy Completion and Forecasting) pipeline that transforms raw point cloud data into structured voxel representations suitable for neural network training and inference.
For information about dataset conversion and preprocessing steps that occur before ray model processing, see Dataset Conversion. For details on the final OCFBench dataset structure and formats, see Dataset Structure and Formats.
Overview
The ray model system implements a sophisticated voxelization pipeline that uses ray traversal to determine the occupancy state of 3D voxels. The core algorithm traces rays from LiDAR sensor origins to detected points, classifying voxels along each ray as either free space (traversed by rays but containing no points), occupied space (containing LiDAR points), or unobserved space (never traversed by any ray).

Ray Traversal Algorithm
Algorithm Overview
The ray traversal implementation uses a 3D Digital Differential Analyzer (DDA) algorithm to efficiently traverse voxels along rays from sensor origins to detected points. This is implemented as a CUDA kernel using NVRTC for high performance.

CUDA Kernel Implementation
The core ray traversal is implemented as an inline CUDA kernel that processes rays in parallel:
VariablePurpose
ray[3]Ray direction vector
step[3]Step direction per axis (+1 or -1)
tDelta[3]t increment to move one voxel
tMax[3]Next voxel boundary in t units
current_voxel[3]Current traversal position
target_voxel[3]End point voxel (LiDAR hit)
The algorithm implements several optimizations:
Ray stopping distance of 1 voxel to prevent over-traversal
Distance threshold of 1.0m to ignore voxels too close to sensor/target
Atomic operations for thread-safe voxel count updates

Frame Aggregation Strategy
Ground truth generation uses extensive temporal aggregation to create dense occupancy labels:
PhaseFrame RangePurpose
Input[index-p_pre, index]Sparse observations for model input
Ground Truth[index, index+p_post]Dense labels for each future frame
Aggregation Window[i-a_pre, i+a_post]Multi-frame accumulation per GT frame
This creates temporally dense ground truth while maintaining sparse inputs to simulate real-world partial observability.
