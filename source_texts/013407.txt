Program: Developer experience. Tracker: #55.
Depends on: #69 (DX-06), #72 (DX-09), #73 (DX-10), #54 (ENG-01)
Release: v0.4. Size: M.
Problem
Collision checking, ray casting and nearest-neighbour search need tree structures, but today only a sorted voxel grid exists.
Planners and perception code in the robotics stack (v02-robotics-language.md section 1.1) need exact, deterministic BVH and kd-tree queries on every engine.
Current state
Opaque VoxelGrid with built-in Neighbors and Knn records, a sort-backed grid runtime, exhaustive traversal for exact queries (src/spatial/, src/native_spatial.rs, spec/bootstrap.md line 259 region); checking comment at spec/grammar.ebnf line 3.
Merged stable sort runtime already exists (src/spatial/, explicit_sorts in explain v5).
Language pieces this needs: Vec3-style FixedArray<T,3> (DX-06 - Const generics: integer parameters, fixed-size arrays and constant items #69 (DX-06)), Vec (DX-09 - Growable owned collections: Vec, Map, Set, Deque, Heap under byte budgets #72 (DX-09)), iterators (DX-10 - Slices over every element type and the iterator protocol with method-call sugar #73 (DX-10)).
Frontier and gather families (src/frontier_source.rs, M4-05) handle traversal-shaped loops.
Decision
Thin pack lib/std/spatial/{aabb,bvh,kdtree}.inv, written in Invar.
Aabb<T>, Ray<T>, Triangle<T> records; aabb_overlap, ray_aabb, ray_triangle (Moller-Trumbore with a specified op order, no FMA).
bvh_build(read boxes) -> Bvh as an LBVH: Morton codes by the specified quantization, the existing stable sort with index tie-break, Karras-style hierarchy emission; same bytes on every engine.
Queries return results in a canonical order (distance, then index): bvh_overlaps, bvh_raycast_first, bvh_nearest; kdtree_build (median split by a specified selection rule, ties by index) with kdtree_knn and kdtree_radius.
kdtree_knn equals the existing Knn grid result on the same cloud (a cross-check that ties the pack to the shipped runtime).
Acceptance
Test binary issue_dx_29_spatial_pack, nonzero count, Debug and Release.
Result-set equality with bvh and parry3d (ray and overlap) and kiddo (kNN) crates as dev-dependency oracles on 10^4 random scenes including degenerate cases (coincident points, zero-area triangles, rays parallel to faces); canonical ordering makes ties comparable.
Reference, MIR, native-serial, cpu-parallel 1 and 8 workers produce identical trees (hash of the node array) and identical query results.
A 10^6-point kNN throughput report beside kiddo (reported, not gated).
Negative: empty input (defined result), NaN coordinates (Err), query count above budget (RESOURCE_LIMIT).
Dependencies
#69 (DX-06), #72 (DX-09), #73 (DX-10), #54 (ENG-01).
Out of scope
Dynamic BVH refit, GJK or mesh-mesh collision, SLAM structures, GPU traversal kernels beyond what #54 (ENG-01) admits.
Implementation notes
Entry files: src/spatial/, src/native_spatial.rs, docs/design/v02-robotics-language.md.
Study: Karras 2012 (BVH), Moller-Trumbore; oracles only: bvh, parry3d, kiddo.
Ported from the pre-open-source tracker.
