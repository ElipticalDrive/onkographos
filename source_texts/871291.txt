What
Speed up binary model reading and allow callers to skip data they do not need.
Changes
Bulk decoding: read fixed-size blocks with memoryview.cast + iter_unpack
instead of per-record struct.unpack; pause GC during parsing.
On-demand reading: read_images_bin / read_points3D_bin (and the txt
readers) accept options to skip 2D observations / tracks, so callers that only
need poses and point attributes avoid building tens of millions of Python objects.
read_model gained a passthrough for the same options.
Why
colmap4d remains stdlib-only (no numpy, no pycolmap). The previous per-record
struct.unpack loop dominated runtime at scale: 43M points took ~389s, and
building per-observation tuples pushed peak memory to ~49.5 GB in the consumer.
Profiling showed GC alone accounted for over half of the parse time, which is why
pausing it during the parse is included.

Compatibility
New options default to current behavior; existing callers are unaffected.
Tests

```
read_images_bin / read_points3D_bin now decode from one in-memory buffer:
2D observations are sliced with memoryview casts and tracks with
struct.iter_unpack instead of one struct call per element, and the cyclic
GC is paused while the acyclic records are built. Still standard library
only; returned types and values are unchanged.

New keyword-only switches (default True, so existing callers are
unaffected): include_observations on the images readers and
include_tracks on the points readers, forwarded by read_model,
read_base_model and load_model_view. Skipped fields are None, and the
binary writers refuse such records. validate_full only needs id sets and
now reads without them.

Real 80-image / 864,625-point frame (3 runs each): full read 6.5 s ->
2.0 s, read without observations/tracks 0.94 s with peak RSS
968 -> 494 MiB. Merged 4,000-image / 43,247,897-point model: 389 s ->
93 s full, 47 s without observations/tracks (peak RSS 49.5 -> 23.3 GB).
Field-by-field identical to the previous reader, text readers included.

Bump package version to 1.0.3 (spec unchanged).
```
