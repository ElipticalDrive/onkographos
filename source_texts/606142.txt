Task: M2-I1. Decision records: D-40 (the method), D-22 (the preset rows).
What it does
WebGPU skips opaque objects that marked occluders hide, in the same frame, so no object shows a frame late.
First phase: the culling shader keeps the marked occluders that showed last frame and look large on screen (at least a sixteenth of the render's longer side). Their depth draws alone, at one sample per pixel.
A compute pass builds a depth pyramid in a storage buffer, four levels per dispatch. Level 0 keeps the farthest depth of 4 x 4 pixels, so one-sample depth stays safe for MSAA.
Second phase: every object in view tests against the pyramid and writes its history. The single opaque pass draws what shows.
A frame with no marked occluder culls once, as on main, and records none of the extra passes.
Off on every preset. createEngine({ gpuOcclusion: true }) or ?occlusion=on turns it on.
The render graph gains "reads so far": a pass that reads a resource as its earlier writers left it, before a later writer.
The core marks an object changed when its occluder flag changes, as it does for bounds, so the GPU table sees a mark set after the object was created.
Shaders that load on first use (D-56)
The two phases (the culling shader's OCCLUSION build, early and late) and the depth pyramid form the occlusion feature's shader file, 3.8 KB after Brotli. The start files keep only the plain culling entry point, so a page that never marks an occluder downloads none of it.
The WebGPU builder asks for the three compute pipelines once GPU occlusion culling is on and the scene has a marked occluder. Until they are built, each camera view culls once, into the draws that the opaque pass reads.
preload: ['occlusion'] builds the three pipelines before the first frame.
Tests
Rust: 11 occlusion tests, 3 of them new (no occlusion pipeline before the first marked occluder; one cull per view until the pipelines are built; marking and unmarking). 27 of 27 no-allocation tests pass.
Engine test: marked occluders download the occlusion shader file once with ?occlusion=on, and none with ?occlusion=off, on WebGPU.
The GPU occlusion page compares six views, culled against unculled. The local image and occlusion browser runs on both GPU sets are queued on the Mac.
Shared numbers
Render templates 24 and 25 (the two phases), template 28 and bind layout 14 (the pyramid). Compute pipeline ids 9 to 11 (main's skinning builds took 6 to 8).
For the coordinator
Clash: M2-K1 (feat(engine): add a test switch for vertex shaders that read instance data by index #378) changes the same culling files (cull.rs, cull.wgsl, mod.rs, opaque.rs, shaders.toml, null3d-wasm).
Prototype G1 on the Mac, quiet and loaded, waits for a quiet window (script ready). D-22 and D-40 get its figures. The iPad gpu-occlusion plan fills D-22's iPad row.

On WebGL2 the job workers draw the meshes that setOccluder(true) marks into a
small masked depth buffer each frame, nearest first, and the camera's culling
skips every object whose bounding sphere lies wholly behind them. Each blocker
clears the pixels its outline touches, so the buffer never hides an object that

during play, and engine.measure reports occludedEntries. D-41 records the
