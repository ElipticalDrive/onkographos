Question
Which engine foundation and language best fit an AI-agent-built, path-traced, micro-voxel Planet engine with a headless dedicated server, on native desktop with a cross-platform GPU API?
Compare at least these options: a custom engine in Rust + wgpu, Rust + raw Vulkan (ash), Bevy, Godot 4 with compute shaders / GDExtension, Unreal 5, and a custom engine in C++ + Vulkan. For each, cover:
Access to compute shaders and hardware ray tracing (ray queries / acceleration structures)
Support for running headless as a server
Ecosystem for networking and physics
How mature, well documented and represented in training data it is, since agents will write most of the code
Iteration speed, and how well the build and tests can be automated
Prior voxel projects built on it
End with a ranked recommendation for a graphics beginner who steers AI agents.

Resolved. Gist:
No engine provides the hard parts (micro-Voxel Planet, voxel path tracer, orbit LOD); those are custom on compute shaders in every option, so engines mostly save glue.
Recommended: custom Rust + wgpu. Compute is first-class, experimental HW ray queries are available (incl. procedural AABB BLAS in v30), the headless server is just a second Cargo binary, and Cargo makes the build easy for agents to automate. Fill the gaps with winit, rapier3d, renet/quinn, kira, egui.
Close 2nd: Bevy 0.20. Gives you the glue and a headless mode, but has quarterly breaking changes and stale agent knowledge. Then C++/Vulkan, then Rust+ash, then Godot 4 (ray queries broken until 4.8), then Unreal 5 (poor fit).
Hardware RT is a bonus: Octo (Rust/WebGPU) gets path-traced micro-Voxels with compute ray marching.
