What
A throwaway, standalone Unity editor window (Assembler → Voxel Spike (3-View)) that reconstructs a voxel model from three orthographic images (front / right / top) and exports it to Goxel plain-text format, so it can be opened directly in the Goxel editor.
This is a disprove-the-theory spike: can a supersampled silhouette/visual-hull approach over three (AI-generated, mutually inconsistent) orthographic views produce usable voxel assets?
How it works
Segment each image by a near-white luminance key (threshold slider), then crop to the foreground bounding box — this is the per-view scale normalization.
Derive grid dimensions from the crop aspect ratios: you set height in voxels (Y); width comes from the front view, length (depth) from the right view.
Occupancy = supersampled silhouette AND across all three views (the visual hull), with a majority vote per voxel to soften view disagreement.
Colour by multi-view back-projection — mean of foreground views, front-priority, or most-saturated.
Export to Goxel text (# X Y Z RRGGBB), remapped to Goxel's Z-up so the model stands upright.
After a run it renders the three segmentation masks so you can sanity-check the key and spot views that need flipping.
Knobs
Height resolution, supersample rate, solid-vote fraction, segmentation threshold, silhouette dilation, per-view U/V flip toggles (handedness), sub-voxel grid offset (X/Y/Z), colour mode, output path.
Reviewer notes
Standalone: own editor-only asmdef (VoxelSpike.Editor) with no references to the project's Voxels/Voxelization assemblies, so the result can't be confounded by the real pipeline. Easy to delete wholesale if the theory doesn't pan out.
Handles non-readable source textures via a RenderTexture blit fallback, so image import settings don't matter.
Avoids records / init / nullable annotations per this project's editor-asmdef constraints.
Not yet compiled in batch mode — intended to be picked up by the open editor. Known limitation: interior colour bleeds along the projection axis (whole-column smearing), which is irrelevant for judging the occupancy theory but would need a best-view rule for colour quality.

```
Replace the flat whole-column 3-view average (which muddied every voxel)
with occlusion-correct, visibility-based colouring:

- Pass 1 builds the occupancy grid (unchanged supersample + vote).
- Pass 2 computes per-column first-hit extents along each axis, so a view
  only colours the surface voxels it can actually see.
- Pass 3 colours each voxel from the view(s) that see it: one view -> that
  colour, several -> their average. Interior/unseen voxels fall back to the
  flat mean so there are no holes.

Add per-view "opposite side is a mirror" toggles (front<->back, right<->left,
top<->bottom): when set, a view also colours its far-facing shell, giving
full surface colour on symmetric objects from just three images.

Colour mode is now VisibleViews (default) or FlatMean (old behaviour, kept
for comparison). Drops the per-sample FrontPriority/MostSaturated modes.
```

```
Decompose the voxel model into parts from coarse AI-supplied 3D boxes

  legend. Quantise and unseen-fill skipped in box mode (every voxel assigned).

segment the blob into sensible parts.
```

Add volume-utilisation box fit mode
…
3bb2f15
```
The growth strategy races each box outward until it meets a neighbour, and
the AABB refit lets a winning box balloon (a leg that steals body voxels gets
a taller box, then steals more) — so boxes grab as many voxels as possible
rather than the ones they best contain.

Add a "Utilise" fit mode (now the default) alongside "Grow":
- Assignment: each voxel joins the box with the smallest box-normalized
  (Chebyshev) distance to centre, i.e. the box it sits most snugly inside
  relative to that box's size. A belly voxel near the top edge of the short
  leg box loses to the body box it sits well within; a neck voxel near the
  front face of the long body box loses to the head box.
- Refit: boxes shrink to the percentile spread of their voxels (hug the dense
  bulk, drop sprawl outliers), removing the AABB ballooning feedback.
- New "Box coverage (pct)" slider (default 0.9) controls refit tightness.

SegmentByBoxes now branches into UtiliseAssign / GrowAssign; the original
geodesic growth is preserved as Grow for comparison.
```

```
Reframe box segmentation as a minimum-volume set cover: each cube must
contain its anchor point (known to be in that part), the cubes together must
cover every voxel, and the objective is minimal total cube volume. Cubes
grow/shrink freely from their anchors.

- Parts JSON now takes "anchor":[x,y,z] (must-contain point) and/or a
  "min"/"max" seed box. Shrinkwrap uses the anchor; Grow/Utilise use the box.
- ShrinkwrapAssign: coordinate descent — assign each voxel to the cube whose
  AABB expands by the least volume to include it, refit each cube to the tight
  AABB of its anchor + assigned voxels, keep the lowest-total-volume pass.
- New "Shrinkwrap" fit mode (now default); Utilise/Grow kept for comparison.
  Iterations raised to 0-20.
```
