Context
The 3D pane currently renders a full-volume Maximum Intensity Projection (raycaster in src/render/raycast-shader.ts, driven by src/render/slice-renderer.ts, controlled in src/app/viewer/viewer.ts). Add the two other standard projection modes and a thick-slab option. These are small extensions of the existing march, not a new renderer.
Goal
Let the 3D pane project as MIP (max — current default), MinIP (min), or Average (mean) along the ray, and optionally limit the projection to a thick slab of N mm instead of the whole volume.
Tasks
Projection modes. Add a mode (MIP / MinIP / Avg) as a uniform field to the raycast params. In raycast-shader.ts, accumulate accordingly: MIP = max, MinIP = min, Avg = running sum ÷ sample count. Apply the same DICOM window/level transform to the projected value as today.
Thick-slab. Add a slab thickness (mm). The camera is orthographic, so all rays are parallel — the slab is two clip planes perpendicular to the view direction, centred on the volume centre, at ±half-thickness. Clamp each ray's marched segment to the slab. Compute the slab parameters CPU-side from the camera + volumeBounds (in src/render/reslice.ts) and pass as uniforms. Default thickness covers the whole volume (== current behaviour).
UI + state. Add a projection-mode selector and a slab-thickness control for the 3D pane, following the existing toolbar control patterns (the WL/WW number inputs and the swap/flip buttons). Wire projectionMode and slabThicknessMm signals in viewer.ts, thread them into MipPaneView and the uniform. Reset to defaults (MIP, full slab) on new volume load, like the camera.
Keep the Optimize the 3D MIP raycaster (interactive performance) #28 perf path. Route the new uniform fields through the existing param packing and the interactive-LOD / requestAnimationFrame render path; don't regress that optimization.
Acceptance criteria
The 3D pane can switch between MIP / MinIP / Average and set a slab thickness.
Default (MIP, full-thickness slab) reproduces the current behaviour exactly — the new paths are additive / opt-in.
Window/level still applies to all modes; the MPR panes, cursor probe, pan/zoom/scroll are unaffected.
Unit tests for new pure logic (slab-range computation, mode mapping, etc.) in the style of src/render/reslice.spec.ts / src/render/slice-renderer.spec.ts. The WGSL itself isn't unit-testable.
ng build --configuration production and ng test --watch=false both pass; existing tests stay green. Do not modify package-lock.json.
Out of scope (follow-ups)
DVR / transfer functions, iso-surface, anchoring the slab to a specific MPR slice/plane (this version centres it on the volume along the view direction), per-axis slab orientation.
