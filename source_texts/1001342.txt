Context
Part of the terrain edit storage series, which replaces the dense voxel grid with generated terrain plus recorded edits and removes the grid's vertical cap. Supersedes #1078.
Today each level's terrain is a dense 3D array of fixed height sizeY (gridY in src/core/campaign/Level.ts), about 19 bytes per voxel, allocated full-height per 16×16 chunk (src/core/world/VoxelGrid.ts:420-443). Terrain generation is deterministic and already computes any column on demand (generateColumn, src/core/world/TerrainGen.ts:78-111), so only what play changed needs storing. Target model, decided by the project owner:
Edit record — per (x, z) column, ordered non-overlapping segments with continuous bounds: dug (generated rock removed) or added (rock with its own material, e.g. ramp fill). Rock a blast weakened but left standing is recorded separately (fracture).
Generator identity — seed, climate bias, base site size, mixed rock hardness, datum, and a generator version. Pre-release the version stays at 1 and old saves are not kept loadable.
Chunks are a cache — dense voxel chunks are materialised on demand from generator + edit record and can be dropped and rebuilt at any time.
No vertical cap — rock exists at every depth, and a site keeps the world's full relief.
Series: #1180 edit record → #1181 saves → #1182 cubic chunks → #1183 rock at every depth, chunks as cache → #1184 column queries → #1185 change regions, #1186 blast and survey, #1187 console readers, #1188 renderer → #1189 real relief → #1190 explicit datum in generation → #1191 datum in levels and game state → #1192, #1193 grids lose their height.
Today a chunk is a full-height column of 16 × sizeY × 16 voxels (src/core/world/VoxelGrid.ts:420-443), indexed lx + y·16 + lz·16·sizeY (:351-355), and writes outside [0, sizeY) are silently dropped (:336). At about 19 bytes per voxel that is ~31 MB for treranium_depths (160×64×160), mostly air above the surface or buried rock nothing reads. Site expansion allocates the same full-height column per claimed chunk (src/core/world/PlayableArea.ts:435-441). The density summary the renderer uses to skip marching is already kept per 16-tall slab (VoxelGrid.ts:179-195; chunkDensityRange at :469, read at src/renderer/TerrainMesh.ts:613, :641).
Task
Voxel storage is split into 16×16×16 chunks keyed by (cx, cy, cz). A chunk is allocated only when something other than air is written into it; reading an unallocated chunk returns air. Reads and writes are accepted at any y, negative or above sizeY. sizeY remains only as a generation input and as the loop bound consumers still use — later issues in this series remove both uses. Density summaries per cubic chunk keep answering chunkDensityRange. The public read/write API, and new VoxelGrid(sizeX, sizeY, sizeZ) which ~55 test files use to build synthetic grids, keep working.
Files
src/core/world/VoxelGrid.ts — modify — cubic chunk storage, owned x/z rect per chunk column, dirty tracking and density summaries per cubic chunk
src/core/world/PlayableArea.ts — modify — claiming a chunk column allocates only what generation writes
src/renderer/TerrainMesh.ts — modify — only if chunkDensityRange's signature changes
Test
tests/unit/world/VoxelGrid.test.ts — modify — writes and reads at y = -10 and at sizeY + 10; unallocated chunks read as air; per-chunk density summaries
tests/unit/world/PlayableArea.test.ts — modify — a claimed chunk column allocates only chunks generation wrote into
tests/unit/world/VoxelGridMemory.test.ts — create — generating treranium_depths at its own height and at four times that height allocates the same number of chunks
tests/unit/benchmarks/benchmarks.test.ts — modify only with a stated reason — blast, NavGrid rebuild, survey and TerrainMesh timings hold
Blocked by

Conventions
No gameplay change; generated terrain is identical.
Hot paths (marching cubes, nav scans, blast energy fields) keep reading typed arrays at today's speed.
Verification
npm run scenarios passes with no expectation changed.
Raising a level's vertical size allocates no extra chunks: air above the surface costs no memory.
A voxel written at y = -10 or at sizeY + 10 reads back.
The benchmarks in tests/unit/benchmarks/benchmarks.test.ts pass at their current thresholds.
Screenshots of the four campaign levels match today's, since the renderer reads the new summaries.
