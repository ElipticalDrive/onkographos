Summary
Woby can reject adjacent 10-node quadratic tetrahedra because boundary extraction determines each cell's orientation from its four corners alone. For curved cells, the corner-only orientation can disagree with the quadratic geometry.
Observed on Windows with woby 0.30.0 using the native tetrahedral importer API:
```
Tetrahedra have duplicate, overlapping or non-manifold faces.
```
The exact 14-node, two-cell geometry below reproduces this rejection in woby 0.30.0.
Minimal geometry
The following two cells share exactly one six-node face. Node numbering is local to this reproduction. All coordinates below are actual geometry, not an idealized synthetic example.
The first cell is the problematic tetrahedron: corners 0-3, followed by its six edge nodes in VTK order (01, 12, 20, 03, 13, 23). The second cell supplies one neighbour that triggers the rejection.

To reproduce through the importer API, use these 14 positions as WobyImportVertex entries and the two connectivity rows as WobyImportTetrahedron entries with node_count = 10. Return both cells in the same cell group. In builds with the built-in VTK reader, the block above also describes the equivalent legacy ASCII VTK input.
Why the corner-only check is misleading
For the first cell:
Signed corner volume: approximately -0.02502347887795534.
Corner determinant (six times the volume): approximately -0.1501408732677321 using high-precision arithmetic on the stored doubles.
Quadratic Jacobian determinant at the reference-cell center: approximately +13.87131940324.
The corner determinant's negative sign is not floating-point round-off. However, it does not represent the orientation of the quadratic mapping at the cell center.
appendTetrahedralBoundary currently uses the corner determinant's sign to reverse faces before checking shared-face parity. In this case that makes the shared face appear to have the same orientation in both cells, so the import is rejected.
Expected behavior
Determine quadratic-cell orientation from the quadratic mapping rather than the corner-only tetrahedron. Preserve all source nodes, coordinates, and connectivity. For this two-cell example, remove the shared internal face and emit the six exterior quadratic faces as 24 triangles.
Retain rejection of duplicate cells, genuinely conflicting shared-face orientations, and faces with more than two incident cells. Linear tetrahedra should retain their corner-volume checks.
Using the quadratic center Jacobian is a possible orientation fix, not a claim that one Jacobian sample validates the entire curved cell.
Regression coverage
The real two-cell geometry above.
Curved quadratic cells whose corner-only volume is negative or zero.
Reversed connectivity and large coordinate translations.
Degenerate quadratic center Jacobians, duplicate cells, and overlapping cells.
Unchanged linear tetrahedron behavior.
