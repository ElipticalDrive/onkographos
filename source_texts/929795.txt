What and why
ATOMS.INC / ATOMS.DEC (operations 3 and 4, CUDA's atomicInc / atomicDec): AAtoms hands them to EmitAtomicOp, which has no case for them; it logs "Invalid atomic operation" and gives the constant 0, with no access to shared memory. They are now a compare-and-swap loop (INC: old >= b ? 0 : old + 1; DEC: old == 0 || old > b ? b : old - 1), Rd the old value.
ATOMS.CAS's result. AAtomsCas gave every compare-and-swap CAST.SPIN's 1 / 0. nvdisasm names the forms by bit 87: clear is CAS (CUDA's atomicCAS, PTX atom.cas: Rd the old value); set is CAST, and CAST.SPIN with bit 88 too. CAST and CAST.SPIN keep 1 / 0, so Fire Emblem Fortune's Weave's retry loop is unchanged.
Reference entry: docs/reference/shaders.md, "ATOMS.INC / ATOMS.DEC, and ATOMS.CAS's result".
Checked
Tests: DMSH_TEST_XLATE=<translator> python3 dm/gfx/tests/test_dmsh_ampere_alu.py, new SharedAtomics (3, all fail on main). All test_dmsh_*.py pass.
GPU cross-check: 400 LDS / STS / ATOMS / ATOMS.CAS from the corpus, each as a one-thread compute shader (inputs and outputs through an NVN2 storage buffer, LDC.64 c[0][0x10] then LDG.E / STG.E; only the 16-byte block the access touches is set and compared), production options, MSL 2.3: 84 mismatches on main, all INC, DEC and CAS, to none; the same on encodings from real compiled code (CUDA sm_80 / sm_75 binaries). Everything else (LDS of every size, STS, ADD / MIN / MAX / AND / OR / XOR / EXCH) already matched.
Devices and OS: MacBook, Apple M5, macOS 26.6.2, Xcode 27.2.
Games run: none (no game files were used).
Docs
The finding is in its docs/reference/shaders.md entry, and python3 dm/tools/docs_symptoms.py was run (the symptom index)
