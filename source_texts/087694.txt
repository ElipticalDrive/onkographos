In the old Model pipeline based splatting, setting renderStateOptions.depthTest.enabled to true got us part of the way there.
Here's an example using a sphere primitive with some transparency intersecting a splat model. Splats overlapping causes ellipsoid cutouts that are incorrect.
The new GaussianSplatPrimitive based SPZ pipeline needs this support plus better handling of overlapping.

I think we'll get most of the way there if we
Enable depth test
Render splats between OPAQUE and TRANSLUCENT pass
Downsides are:
Translucent objects will always render above splats.
Depth testing against opaque geometry is only as accurate as the splat shader's interpolated gl_Position. It works, but it's a fairly coarse representation of the splat ellipsoid.
To solve this properly I think we'll need to figure out how to recover depth. E.g. when does the pixel's opacity get fully saturated? Separate framebuffer needed maybe? Once the depth is recovered we would need to set gl_FragDepth. And then depth testing against opaque/translucent geometry shouldn't be a problem.
