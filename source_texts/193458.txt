Abstract
Digitization techniques now makes it possible to produce precise and dense textured 3D point clouds. Therefore, 3D surveys of
monuments or archaeological sites can easily reach several billions of points. To ensure a smooth virtual visit and to manipulate
these point clouds, we have developed the ESILab software (Enhanced Scan Immersion Lab). Thanks to a dedicated 3D model
converter using an octree partitioning of the point cloud and the accessibility of rendering engine parameters, ESILab can
load a 3D model containing several billion points in just a few seconds. It also makes it possible to load multiple point clouds,
superimpose them and extract slices for relevant comparisons and visualizations. The point clouds of six famous and very large
French Gothic monuments were used simultaneously to demonstrate the software’s potential† . This software can be shared free
of charge upon request right now and will be made available to the public as soon as possible.
1. Introduction
Digitization techniques such as photogrammetry and lasergrammetry now make it possible to produce precise and dense textured
3D point clouds. This results in a significant gain in the quality
and realism of the renderings. To achieve this realism, the software
used to exploit the point clouds thus obtained must be able to manage billions of points. Several existing software were initially designed as toolboxes consisting of powerful algorithms to apply processing, meshing and comparisons on point clouds. Unfortunately,
these softwares cannot manage clouds beyond a few billion points.
We briefly describe these softwares in section 2. To overcome this
limitation, we developed the ESILab software (Enhanced Scan Immersion Lab), dedicated primarily to the manipulation of very large
point clouds, as well as a tool for converting point clouds into structured clouds that are quick to load and manipulate. It was developed
to meet our internal needs for the exploitation of point clouds from
major and very large monuments in France and abroad, such as
Gothic cathedrals and archaeological sites. It was then enhanced
through the numerous multidisciplinary collaborations we conduct
with the aim of studying, understanding, and establishing diagnostics of these monuments, and creating usable deliverable. ESILab
was designed by computer vision and robotics researchers to meet
the many needs of archaeologists, architects, and architectural historians. Thanks to the octree organisation of the point cloud (see
section 3) and the accessible settings of the rendering engine parameters, ESILab allows to load a 3D model having several billion
points in a few seconds. It also allows to load multiple point clouds
and superimpose them, making full use of the native resources of

2. Existing softwares solutions
Numerous software solutions are available to visualize and handle the dense point clouds obtained after digitization of large structures. Three of these programs are regularly mentioned in the literature [BU21, CPRDL24], are still being developed and can be freely
used: MeshLab, CloudCompare and Potree. MeshLab [CCC∗ 08]
enables the visualization and editing of meshes constructed from
point clouds. Numerous proofs of concept have recently been added
to extend the capabilities of this tool. The software is powerful
while not optimized for large models. CloudCompare [Clo25] can
be used to visualize and perform various operations on point clouds
(editing, registration, computation of metrics). It features spatial
octree partitioning, which limits the number of points displayed
while moving around, thus reducing cost of rendering the cloud.
Octree cells are then displayed gradually when the viewpoint is
stationary, until the computer’s graphics resources are saturated.
Potree [SOW20] enables the remote visualization and exploration
of large point clouds in a web browser. Before being rendered, the
point cloud must be converted to the format supported by Potree
via the PotreeConverter software: a spatial octree partitioning is
performed. In version 2.1.1, PotreeConverter handles point clouds
with a maximum of 216 points, due to a limitation of the LAS1.3
standard. This limitation can be overcome by splitting the cloud
into two sub-clouds, but the resulting multi-resolution clouds will
not be strictly equivalent to the multi-resolution version of the full
cloud. When the cloud is displayed, the octree cells are progressively displayed until the budget point is saturated: we tested this
with a cloud of 1 billion points, and the browser became unstable,
but the screen was updated. Table 1 compares the solutions listed
with the tool introduced in this article on two criterias: the maximum number of points per cloud and the requirement to convert
the point cloud before rendering it. These tools offer the first steps
towards editing and rendering point clouds comprising several billion of them. However, to increase the number of points supported
or displayed, to apply a simple rigid transformation to a huge cloud
and quickly check the result, to explore it in virtual reality or, for
example, to simulate panoramic images from it, a more specific tool
is required.
3. Software presentation
In this section, we present ESILab and its dedicated converter,
which enables point clouds to be loaded and explored very quickly
and efficiently. Both tools have been developed in C++ language
and tested on Android, Linux and Windows.
3.1. 3DModelConverter: pre-processing of large point clouds
Enabling the visualization of high-resolution point clouds in applications such as virtual tours, where user immersion is paramount,
requires optimizing on-screen rendering. This ensures that only
the necessary data is displayed, allowing for efficient processing
and real-time interaction without overwhelming computational resources. Levels of Detail (LoD) play a critical role in optimizing memory and rendering efficiency in point clouds. By dynamically adjusting resolution based on the user’s viewpoint, LoD ensures that only the most relevant regions are displayed with high
detail, while peripheral or occluded areas are represented with
fewer points. This significantly reduces computational overhead
and memory footprint, enabling real-time interaction with largescale point clouds. QSplat [RL00] employs a hierarchical, spherical representation of the point cloud, allowing for progressively
coarser representations as the distance from the viewer increases.
This adaptive refinement tailors the level of detail to the user’s perspective, minimizing unnecessary computations in out-of-focus areas. Building on this concept, the use of octrees in Sequential Point
Trees [DVS03] introduces an efficient spatial partitioning scheme,
where each node recursively subdivides space, enabling selective
rendering of regions at varying levels of detail. The hierarchical
nature of octrees is particularly well suited for large-scale point
clouds, as it allows for scalable data loading according to zoom
level and view frustum constraints. Instant Points [WS06] extends
this approach by integrating LoD within a nested octree structure,
leveraging GPU optimizations to distribute rendering tasks. This
reduces CPU workload and enhances interactive rendering of extremely large point clouds. Further advancements have been made
with Modifiable Nested Octrees (MNO) [Sch14], which optimize
point cloud editing for massive datasets. Unlike traditional nested
octrees that store points within internal octrees, the MNO employs
a regular grid to manage points within each node. This simplifies
editing operations such as insertion and deletion by eliminating the
need for complex internal reorganization. Additionally, MNO retains the benefits of interactive rendering by integrating LoD, efficiently managing memory, and culling points outside the viewing
frustum. Potree [SOW20] adopts a similar strategy, but maintains a
minimum distance between points at each level thanks to a Poissondisk approach, guaranteeing homogeneous distribution in the cloud
and improving rendering quality. The result is a uniform subsampling strategy that preserves spatial consistency, providing an optimized and non-redundant representation of the point cloud.
To overcome the limitations and constraints of existing converters, we introduce 3DModelConverter, a software tool that converts
a point cloud into an octree and provides three methods for distributing points across its LoD: random distribution, voxel gridbased sampling, and KD-tree-based selection. The number of LoD
levels is user-defined, with each level representing a subsample of
the point cloud—sparser near the root and increasingly denser toward the leaves.
Random distribution quickly determines whether a point is retained at a level or moved to the next. While time-efficient, it does
not guarantee a uniform distribution. In fact, denser regions typically closer to the sensor, retain more points, whereas distant areas
become sparser.
Voxel grid distribution involves a voxel filter that divides the
point cloud into equal-sized cubes, called voxels, retaining only one
point per voxel. The choice of this retained point can vary: it can be

selected at random, or chosen as the point closest to the center of the
voxel, which is more costly in terms of computation but provides a
more structured representation of the cloud. Compared to the random distribution method, voxel filtering produces a more uniform
point distribution, as distant regions of the cloud are proportionately represented. This ensures that all parts of the cloud maintain a
similar density of points, offering a consistent LoD throughout the
structure.
KD tree distribution relies on a KD tree to identify neighboring
points within a defined radius around a search point, transferring
these neighbors into more detailed octree layers. This approach is
comparable to Poisson-disk sampling used in [SOW20] and produces the most uniform distribution. However, it is also the most
computationally intensive. Building a KD tree for the entire cloud
and finding neighbors for each selected point becomes more expensive as the size of the cloud increases. Despite its computational requirement, this method achieves a balanced spacing between points, guaranteeing an extremely consistent and accurate
representation.
These three strategies, also available in CloudCompare [Clo25],
are applied to the Arch dataset‡ and the figure 1 shows the obtained
results with our 3D model converter. The differences induced by
the three strategies have very little impact on human perception
of the renders. However, they strongly impact automatic descriptor
extraction algorithms. Finally, and as an indication, the conversion
time for 2.2 billion points in OCTI, a custom file format detailed
below, is approximately one hour and three hours for 7.12 billion
points ( 268Go).

In its version 2.8.0, ESILab can read three different input file formats: Leica Cyclone PTS, Wavefront OBJ, and a custom file format called OCT(I). This last format has two variations depending
on the presence or absence of the measurement intensity for each
3D point. In the file pointcloud.octi, each 3D point is defined by its
coordinates in space (X,Y, Z), its color in RGB format as well as
the intensity measured at this point. In the file pointcloud.oct, the
measured intensity is not present. Each of these two files is accompanied by a file listOctree.txt which lists all the non-empty cells.
The cells of the octree partitioning are managed by an adapted version of the source code of PotreeConverter 1.7 [Sch14]. For each
level of the partitioning, the points of the cloud are attributed using
one of the sub-sampling methods presented in section 3.1. The rigid
transformation matrix describing the transformation between each
object frame (point cloud, mesh) and the world frame is stored in a
text file. It also contains all the saved camera poses. Several other
rendering parameters are adjustable for each object, like visibility,
color, opacity, point size and resolution (octree level). The graphic
rendering can be done using an usual perspective camera, an orthographic camera, or an equirectangular projection, which simulates
the spherical cameras now widely used for virtual tours. Moreover,
the immersive experience is possible. All these cameras have adjustable classical parameters (field of view, focal length, image size,
etc.) and also their equivalent used in computer vision applications
(intrinsic parameters). ESILab offers also the possibility to extract
massive slices of the 3D models included in a given interval with
a certain thickness and a step of slicing. Any slice direction can be
chosen by positioning the camera perpendicular to the slice plan.
The slices poses are exported along with the images and allow them
to be located relatively to the 3D model frame.

ESILab has been primarily designed for visualizing very large point
clouds. Thanks to its developed 3D model converter, loading multiple point clouds takes just a few seconds. This also allows loading clouds whose sizes are limited only by memory and graphics
capacity of the used computer. But, the 3D engine’s settings allow
rendering to be adapted to the limitations of the used computer. The
numerous settings (via the interface or text files) make the use of
multiple clouds flexible and efficient. The ability to retrieve poses
via files allows for the use of registration or automatic positioning results. We have demonstrated its usefulness and effectiveness
through the use cases presented in section 4. In the interests of interoperability, we will soon support the Potree 2.x file format for
the conversion and rendering. ESILab will be shared along with its
3D rendering core, Engine3D. This core component is intended for
users who wish to benefit from the implementation of the rendering
engine in their own software.
