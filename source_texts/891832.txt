Summary
Extend cubemap capture so SDF and volume scene content can render correctly for each cubemap face instead of being rejected as mesh-only.
Motivation
Issue #103 now introduces forward-renderer cubemap capture for mesh scenes, but the current SDF and volume raymarch shaders still assume one fixed camera origin/direction. That makes hybrid cubemap capture incorrect unless those passes become face-camera aware.
Scope
add face-specific camera uniforms for SDF cubemap capture
add face-specific camera uniforms for volume cubemap capture
preserve the current mesh cubemap face ordering and output contract
add tests for hybrid cubemap capture once raymarched content is supported
update rendering and cubemap capture docs to remove the current mesh-only limitation
Notes
this is a follow-up to Add cubemap scene capture support #103
issue Add cubemap reprojection and export outputs #102 should continue to consume cubemap captures without needing renderer-internal camera logic
correctness matters more than forcing reuse of the current fixed-camera raymarch shader entrypoints
