What
Adds VoxelBlockGrid — a structure-of-arrays (SoA) per-voxel attribute store in the volume tier, the foundation the TSDF (and later colour) integrators write into and meshing reads from.
Design (Open3D VoxelBlockGrid model)
The VoxelHashMap keys only a block index; each per-voxel channel is its own flat device array of num_blocks · voxels_per_block elements, keyed by BlockIndex::ptr, declared at create() and allocated + zeroed independently:
```
AttributeSpec attrs[] = {{"tsdf", 4}, {"weight", 4}};   // name + per-voxel byte size
auto vbg = VoxelBlockGrid::create(dev, alloc, grid, attrs, 2);
vbg.map().allocate(coords, n);                            // block index
auto tsdf = vbg.attribute("tsdf").value();               // buffer + size to bind/read
```
A consumer materialises only the channels it needs, so a volume-only user (pure spatial hashing) allocates zero per-voxel memory — instead of forcing the full SDF volume (~6 GB at prod defaults) onto every map. This diverges from the monolithic prior engine (a single AoS Voxel{sdf,weight} buffer inside the hash-table struct); recorded as the 2026-07-05 locked decision in CLAUDE.md.
Move-only (rule of zero over the owned map + attribute Buffers); attribute() returns a non-owning view (buffer + element_size + element_count).
Proof
volume_block_grid_test verifies two independent float attributes are distinct, correctly-sized buffers; that writing one leaves the other untouched; that the composed map still allocates/compacts and its BlockIndex::ptr keys into the attributes; the error paths (null list, empty name, zero size, duplicate name); a bare zero-attribute grid; and the move-only trio.
✅ 14/14 ctest on MoltenVK · ASan clean · -Werror clean
Next
feat(tsdf): classic projective integration — a new tsdf tier that binds attribute("tsdf")/("weight") + the compacted block list + a uint16 depth SSBO + camera params, and runs the faithful classic kernel (sdf = depth − Zc, node-centred voxels, inverse-square weight, running average capped at max_tsdf_weight).

  buffer, not the live map grid, so a later map().resize() cannot inflate

  with the attributes gone). The self-move test now runs on a grid that
  still owns its attributes, exercising the guard.
- Strengthen the ptr-keying test: probe two distinct blocks for
  voxel-granular, disjoint ranges instead of a tautological same-index
  round-trip; drop the heap-order-coupled weight==0 assertion.
- Hoist attribute-spec validation ahead of the map + buffer allocations,
  so a malformed spec is rejected allocation-free (the test's "before any
  buffer is allocated" claim now holds).
- Mark the host-visible attribute buffers' device-local follow-up with a
  greppable TODO.

pinned clang-format. Confirmed the strengthened self-move test fails

Introduce VoxelBlockGrid: a VoxelHashMap block index composed with a set of
named, independently-allocated per-voxel attribute arrays (structure-of-
arrays), mirroring Open3D's VoxelBlockGrid. Each attribute ("tsdf", "weight",
"color", ...) is its own flat device buffer of num_blocks * voxels_per_block
elements, keyed by BlockIndex::ptr, declared at create() with a per-voxel byte
size and allocated + zeroed independently.

A consumer materialises only the channels it needs, so a volume-only user
allocates zero per-voxel memory rather than the full SDF volume (~6 GB at prod
defaults). Diverges from the monolithic prior engine's AoS Voxel{sdf,weight}
buffer inside the hash table (see the 2026-07-05 SoA decision in CLAUDE.md).
The TSDF / colour integrators and meshing will bind attribute("tsdf") etc.

Move-only (rule of zero over the owned map + attribute Buffers); attribute()
returns a non-owning view (buffer + element_size + count) to bind or read.
