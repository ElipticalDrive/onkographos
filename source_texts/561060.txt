Discoverability — shafts silently require soft-shadow marching.
The volumetric in-scatter only casts terrain shadows into the fog (= actual god-ray SHAFTS) when ShadowSteps > 0 (gated in ShadingPipeline.AddVolumeScatter: sh = shOn ? SoftShadow : 1.0, shOn = ShadowSteps>0, key light in ShadowLightMask; mirrored in the GPU ReliefRaymarchKernelSource.InScatterWalk). With ShadowSteps == 0 (the default) the medium scatters uniformly — a flat brighten/darken, no shafts. VolumeSteps alone is not enough.
This is non-obvious from the Fog / Volumetric sliders: a user sets Fog density + Volume steps, sees only a glow, and concludes volumetric "doesn't work" (it does — the shadow term is just off). Confirmed by the #305/#306 preset bug report; the presets now set ShadowSteps themselves, but hand-tuning still hits this.
Ask. Surface the dependency in the Lighting & FX dialog:
On the Volume steps slider tooltip (and/or an inline note in the Fog / Volumetric expander): "God-ray shafts also need Shadow steps > 0 (Shadow expander) and a directional key light with something to occlude it."
Optionally: when VolumeSteps > 0 && FogDensity > 0 && ShadowSteps == 0, show a small yellow (#FFCC00, colorblind-safe) advisory near the Volume steps row — "fog is uniform glow; raise Shadow steps for shafts."
Do NOT auto-change ShadowSteps on the user (perf cost is real, and silent mutation is worse than a hint).
Context: VolumetricGodrayOcclusionTests proves the mechanism (ShadowSteps=0 -> occluder ignored <1%; ShadowSteps=24 -> in-scatter dimmed >40%). See also VolumetricFxPresets.
Deferred from the #305/#306 work (branch feat/vl-defaults-presets, PR #308).
