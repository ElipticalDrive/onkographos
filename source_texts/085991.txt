Engine 2.23.0 (picked up in #325) removed AppBase#drawTexture, leaving a no-op in its place in release builds. The pick depth overlay (the debug panel's "Show depth") and the voxel collision overlay both drew through it, so both silently stopped rendering. The only other sign was two type:check errors.
The engine's suggested replacement, TextureRenderer, only draws opaque previews with its own shader. Both overlays need their own shader, and the voxel overlay also blends with premultiplied alpha. So each overlay now keeps a fullscreen quad MeshInstance with its existing material in app.scene.defaultDrawLayer, the same layer drawTexture drew into.
The quad is shown only on frames where drawTexture used to be called. The pick depth overlay still skips offscreen renders (captureFrame).
The node gets scale (2, -2), so the existing vertex shaders and orientation are unchanged. The node is outside the hierarchy, so its fixed transform is synced once when the quad is created.
destroy() removes the quad from the layer and destroys it. The engine's teardown never destroys a layer's mesh instances.
Also removes gsplat.lodMode = GSPLAT_LODMODE_DISTANCE, which 2.23 deprecates as a no-op now that LOD is always chosen by distance.
The mount loop's &overlay pass now also checks that the voxel overlay's quad is released on destroy, alongside the compute shader and storage texture it already checks.
Testing
npm run type:check, npm run lint, npm run fmt and npm test pass.
Pick depth overlay: colour-mapped depth is back on WebGPU and WebGL2, the right way up, and turning it off restores the scene.
Voxel overlay: checked on screen. With it enabled, the quad is drawn once per frame, and never when disabled.
Mount loop, 20 iterations each, all released=true removed=true and "done, no leaks detected":
/mount-loop?content=./shoe.ply&iterations=20
the same with &webgl
&collision=<voxel.json>&overlay (WebGPU), overlay=true on every iteration
The new quad check fails (overlay=false) with the overlay's quad.destroy() commented out.

Le moteur seul, sur la base 1.28 : l'interface amont n'est pas fusionnée.
Les LOD se chargent par priorité, et les requêtes devenues inutiles sont
retirées. Mesuré dans le salon de Saint-Germain, face au build 2.20.6,
dans la même session : premier affichage en 0,6 s au lieu de 3 s, et
détail complet à 20 M en 11 s au lieu de 14 s.

Adaptations au moteur :
- scripts XR déplacés dans scripts/esm/xr/ (2.21) ;
- drawTexture retiré : la surcouche voxel passe par un quad dans la couche
  de dessin (amont playcanvas#326). Toutes les surcouches sont mises à jour à chaque
  image, pour que celle de la collision quittée se masque ;
- la file de chargement est servie par priorité : les fichiers « au plus
  fin » de la planéité et de la coupe passent devant le streaming (1,2 s
  au lieu de 8 s, file pleine) ;
- setParameter et setWorkBufferModifier se propagent d'eux-mêmes aux
  fichiers LOD : markPlacementsDirty ne fait plus que demander une image ;
- lodReady() (bascule intérieure) : champs internes inchangés, vérifié.

Réglages gsplat posés avant le début du streaming (amont playcanvas#284, playcanvas#288,
playcanvas#289) : minContribution, alphaClip, antiAlias, debug et LOD. L'aperçu
grossier est imposé dès la création du modèle, sans attendre le ciel ni
la collision. colorUpdateAngle reste à 4 / 2 : le 0 de playcanvas#284 recalcule
les couleurs de tous les splats à chaque image (corrigé par l'amont
en playcanvas#287).
