Motivation
Reduce loss of significance for deep-zoom fractal rendering by preserving the camera center ray with extra precision when sent to the GPU.
Use perturbation theory to evaluate per-pixel SDFs as small offsets from a high-precision central ray so the shader can compute accurate distances with fewer precision artifacts.
Description
Extend the GPU camera buffer layout in shaders/includes/shared_data.gdshaderinc to include center_ray_hi and center_ray_lo vec4 entries to carry a double-single split central ray.
Update scripts/renderer_controller.gd to resize the camera buffer to 28 floats, compute the CPU central ray, split each component into hi/lo via _split_double, and upload those values into the new buffer slots.
Replace the AR ray generation/march in shaders/includes/rayMarcher/ray_marcher_AR.gdshaderinc to reconstruct the center ray from hi+lo, form per-pixel rays as perturbations from that center, and evaluate SDFs using sdf_perturbation which linearizes with sdf_gradient and adaptively blends to the exact sdf for larger deltas.
Keep existing pipeline and push-constant usage unchanged while computing final hit position by adding the ray delta to the high-precision reference position before shading.
Testing
Attempted runtime shader validation via godot --version, but this command failed because the godot executable is not installed in the environment, so runtime verification could not be performed (failed).
