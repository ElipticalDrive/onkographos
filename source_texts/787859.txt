Feature level 12_2 needs tiled resources tier 3: 3D textures as reserved resources. Mullion reported tier 2. This PR reports tier 3, with one deviation from the specification that I'd like you to decide on, described first below.
Based on main, now that #36 is merged. It's independent of the conservative-rasterization PRs. Only the last two commits are new here.
The deviation: 3D tile shapes
D3D11.3 (5.9.4) gives fixed standard tile shapes for 3D tiled resources, for example 32×32×16 texels at 32 bits per texel. Metal's sparse 3D texture maps memory by a tile one texel deep instead. I probed the M4 with sparseTileSizeWithTextureType: at the 64 KB page Mullion uses:

The 2D shapes match D3D's, which is why tier 2 works. A D3D 3D tile can't be assembled from Metal's, since a mapping covers whole Metal tiles. Matching the standard shapes would need a layer that remaps every texel address, with filtering done by hand.
So this PR reports Metal's 3D shape through GetResourceTiling, which already did so for reserved 3D textures. Applications that ask for the shape (which the API is built around) work. Applications that hard-code the standard 3D shapes would map other texels. If you'd rather Mullion stay at tier 2 until it can provide the standard shapes, that's a one-line change.
What changed
The tier. The device reports D3D12_TILED_RESOURCES_TIER_3 when placement sparse textures are available. Reserved 3D textures were already created as placement sparse 3D textures; only the reported tier was holding them back.
What works. Tiles map by box. NULL tiles read 0 and drop writes. CheckAccessFullyMapped reports them. Two volumes mapped to one heap tile alias. 3D packed mips are Metal's mip tail, as for 2D.
Tests
tests/d3d12/d3d12_tiled3d (DXBC and DXIL):
The shape: the reported 3D shape is a whole 64 KB tile.
Aliasing: a tile of each of two reserved volumes is mapped to the same heap tile, and every texel of the first is written from a compute shader.
Read-back: every texel of both volumes is read back with its residency, in a separate submission. Mapped texels hold the written value; unmapped ones read 0 and report as unmapped. The second volume sees the first's texels at the same place in its tile.
Mip chain: a 512×512×8 chain's standard and packed tiles add up.
Two break patches each make the test fail: tiles counted at the wrong depth, and tier 2 reported.
What was run
On an Apple M4, macOS 27.2, MetalSharp Wine 2.0, with GRAPHICS_BACKEND=wine and tests/run.py --family native,9:
Builds: the ARM64X, ARM64EC and win32 builds compile.
Tests: d3d12_tiled3d passes. These related tests also pass, 42 in all with 2 skips (the DXBC variant of d3d12_feedback): d3d12_tiled, d3d12_tilemap, d3d12_tile_unmap, d3d12_copytiles, d3d12_sparse_remap, d3d12_sample_residency, d3d12_residency, d3d12_obligations, d3d12_levels, d3d12_feedback.
