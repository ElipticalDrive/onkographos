This PR optimizes the rasterize_sphere function by replacing the brute-force bounding box iteration with analytically derived loop bounds.
Optimization Details
The original implementation iterated over the entire bounding box $(2r+1)^3$ and checked the distance for every voxel.
The new implementation:
Calculates exact Y bounds based on X: $y_{lim} = \sqrt{r^2 - x^2}$.
Calculates exact Z bounds based on X and Y: $z_{lim} = \sqrt{r^2 - x^2 - y^2}$.
For hollow spheres (fill=False), it calculates the inner "gap" $z_{gap}$ and iterates only the valid shell segments $[-z_{lim}, -z_{gap}]$ and $[z_{gap}, z_{lim}]$.
Performance Results (r=100)
Fill=True: 9.0s -> 4.6s (~2x speedup)
Fill=False: 3.8s -> 0.06s (~60x speedup)
Verified with tests/integration/test_stdlib_features.py and custom benchmark.

Optimized `rasterize_sphere` in `src/rrs/stdlib/geometry.py` to use exact loop bounds derived from the circle equation ($x^2 + y^2 + z^2 \le r^2$).

*   **Impact:**
    *   **Fill=True:** ~2x speedup (4.6s vs 9.0s for r=100) by avoiding empty bounding box corners.
    *   **Fill=False:** ~60x speedup (0.06s vs 3.8s for r=100) by iterating only the shell volume instead of scanning the full interior.
*   **Change:** Replaced naive bounding box iteration with calculated `isqrt` bounds for Y and Z loops.
*   **Fix:** Changed return type to `list` (from `list(set)`) to ensure deterministic iteration order, as per standard library guidelines.
