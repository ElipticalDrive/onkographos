Summary
Depth peeling (that makes semi-transparent models appear correctly in 3D views) seems to be incompatible with shadows option. Semi-transparent models may appear incorrectly (backface occlude frontface, kind of appearing inside out) if "Shadows visibility" option is enabled in the 3D view.
Environment
Slicer version: Slicer-5.7.0 2024-06-02
Operating system: all

The problem is caused by some limitations in VTK, which should be fixed.
To give some background, VTK offers two different ways to enable SSAO and Depth peeling. Either by creating render pass objects and then calling vtkRenderer::SetPass, or by using the public API of vtkRenderer to call UseDepthPeelingOn / UseSSAOOn.
The rendered results should be the same, but internally the two code path are very different and incompatible.
Slicer uses the SetPass approach for shadows. This is required to enable SSAO for volumes because the UseSSAOOn public API only supports opaque geometry in its current state ([1]).
Using SetPass ignores the UseDepthPeelingOn option as it never calls vtkRenderer::DeviceRenderOpaqueGeometry ([2]). In addition, the vtkRenderStepPass used as delegate of vtkSSAOPass uses vtkTranslucentPass internally which does not produce correct rendering of transparent geometries.
Here is a quick status on the different fixes that could be considered:
Removing the SetPass approach in Slicer to combine UseDepthPeelingOn and UseSSAOOn should be supported, but shadows will not work on volumes.
To enable shadows on volume with this approach, VTK should be improved by adding a volume pass in addition to the existing opaque pass in [1]. The volume SSAO parameters should also be exposed at the renderer level, as it is done for vtkRenderer::SetSSAOBlur for instance.
Improving the SetPass approach in Slicer to use a depth peeling pass instead of the default translucent pass in vtkRenderStepPass.
This raises a FBO error which should be fixed in VTK. My guess is that the vtkSSAOPass does not clear its resources correctly and gives an unexpected OpenGL state to the depth peeling pass.
Approach 1. should be easier than 2. from a VTK perspective, but maybe we should make sure that UseDepthPeelingOn and UseSSAOOn can be combined first (it looks OK in an example with very simple geometries, but it might be worth investigating more)
