IsoSurface uses a C port of Thomas Lewiner's Marching Cubes’ cases with topological guarantees. However, the implementation generates some triangles with incorrect triangle winding. You can observe this by running the command
```
IsoSurface -input bet.nii.gz -isorange 128 255 -o_PLY isorange64_255
```
and displaying the results with a tool that discriminates between front and back faces like MeshLab or Surfice. These artifacts also frustrate mesh simplification routines. This appears to reflect using Lewiner's tables dated 13/07/2002, whereas other C++ implementation use tables dated 12/08/2002.
I have created a repository with two releases: 1.0.20020713 is the AFNI code, while 1.0.20020812 updates the tables. Updating the AFNI files MarchingCubes.h, MarchingCubes.c and LookUpTable.h should resolve the issue. As a bonus, if you compile MarchingCubes.c with the directive -DMC_SELF_TEST you will create a standalone executable (when you integrate this into AFNI you can delete the main.c demo and update that make file).
Therefore, you can check the old implementation:
```
git clone --depth 1 --branch 1.0.20020713 https://github.com/neurolabusc/LewinerMarchingCubes
cd LewinerMarchingCubes
make
./MarchingCubes bet.nii 128
```
And the patched version:
```
git clone --depth 1 --branch 1.0.20020812 https://github.com/neurolabusc/LewinerMarchingCubes
cd LewinerMarchingCubes
make
./MarchingCubes bet.nii 128
```
