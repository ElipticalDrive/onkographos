Owner
Adds an isolated /lab/meshlets/ experiment with a self-hosted, lockfile-pinned Three.js r187 alias. The existing r182 R3F and World Builder renderers stay on their current dependency. Links live in the Lab index and World Builder More menu.
The lab uses the actual experimental MeshletDrawingPipeline on a deterministic field of shared-geometry procedural brains using individual meshes in a static BundleGroup. It offers cluster colouring, occlusion and pixel-error LOD, a standard WebGPU comparison and an explicitly capped lower-detail WebGL fallback. Scene totals are calculated; GPU counters are read from the pipeline, include cluster padding and exclude regular-pipeline draws. No fixed 60 FPS or billion-triangle speed claim is shown.
Local self-contained GLBs stay in the browser, with SHA-256, object names and display-normalization disclosures. Remote resources are rejected before parsing. Source bytes, BIM exports and collision/planning geometry are unchanged. A fixed-camera 2 s warmup / 10 s measurement downloads raw animation-frame intervals, cadence summaries, settings, viewport, source and limitations. This measures browser frame cadence, not GPU execution timestamps or physical accuracy.
Validation:
Typecheck, production build, lazy Three import guard and 11 existing Arena HTTP checks passed locally.
1,096 app tests and 73 analysis tests passed locally, including cadence semantics and remote/oversized GLB rejection.
Hosted desktop/phone-sized WebGL rendering, exact authored local GLB identity, receipts and missing-feature fallback passed. The full World Builder browser suite passed after preserving the existing /lab URL.
Strict dense WebGPU qualification failed. A tiny native meshlet control passed 16 clusters / 1,024 padded triangles, but native 25-object approximately 24k-triangle controls lost their device on SwiftShader in both instanced and static individual-mesh modes, independently of our app. Changing to native node materials, full Chromium and awaited async renderer cleanup did not establish a dense GPU pass. Root driver/library cause remains unproven; these are negative results, not a benchmark reproduction.
Local browser downloads were truncated. No physical GB10/RTX 4090 or phone-browser qualification was executed. The runbook includes MESHLETS_GPU_BACKEND=native and an optional system Chromium path; the runner retains adapter information and strict failure diagnostics.
Separate WebGPU test results must not be reported as GB10/RTX 4090 or physical-phone measurements. No complete real scan or BIM/robot accuracy claim.
Primary source correction: r187 was released October 30; its current meshlet utility uses 64 triangles per cluster. The API is experimental and unsupported materials use regular draws. Guide and sources: docs/meshlets-lab.md.
The lab is not deployed. No production service, credentials or public worker activation are changed by this PR.
Status: draft, not released. Preserve the failed strict GPU gate. The new lab must not be marketed as a validated dense-mesh renderer or as reproducing the reel's billion-triangle / 60 FPS claim. Known negative controls: instanced, individual meshes. Existing production replay export was released separately in PR277 and remains independent.
Latest exact head: b8c6a59be82c23efc99a4c90eb3edc5a3afd5495.
Core CI passed.
Local typecheck, production build, focused cadence/GLB checks and syntax checks passed; working tree is clean.
Final browser run passed actual desktop and phone-sized WebGL views, authored local GLB identity and downloaded receipts, including runtime manifest equality and actual applied WebGL settings. Changing controls disables measurement until Start applies them.
Strict GPU qualification remains failed. On this exact head the independent control reported that WebGPU was unavailable and fell back to WebGL2, then failed while accessing the absent native device. This is a GPU environment/control failure, not an application GPU pass. Earlier conservative control ce6cf54 did obtain a native software adapter but lost it after six frames with multisampling and occlusion off.
No physical RTX 4090, GB10 or phone GPU result exists. Do not merge or deploy this experiment as a qualified dense viewer. Other long-running repository checks were still pending at the final status read and are not asserted as passing.
Receipts now retain runtime asset hashes and actual applied settings. WebGL records multisampling enabled and meshlet-only controls inactive. The native workstation reproduction command and suggested scene acceptance target are in the runbook. The next experiment requires an accessible physical GPU/browser, not additional invented performance figures.
