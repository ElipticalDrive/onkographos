What changed
keeps gameplay terrain data strictly 2D: Terrain[x][y]
each occupied cell now renders as a real 0.25 × 0.25 × 0.25 m 3D cube volume
still exactly one block of Z thickness; no Minecraft-like second/deeper gameplay layer
replaces the flat front-face chunk mesher with exposed-face culling + greedy face merging
uses chunk-local BufferGeometry coordinates for large-world precision
uses repeated per-block UVs so merged surfaces still visibly read as individual cubes
adds Lambert lighting so block thickness is obvious in the debug free camera
adds 3D block cursor/selection
desktop: left-click dig, right-click place
touch: explicit 挖 / 放 buttons, then tap the target cell
border edits invalidate adjacent chunks so side faces stay correct
adds dig + place persistence regression coverage
Technique references studied
The implementation follows current voxel-engine practice rather than one-Mesh-per-block: greedy meshing / face culling, chunk-local coordinates, and dirty-chunk rebuilds. It is specialized for Paperchalk's unique X/Y × one-cube-thickness world, so no third voxel coordinate is introduced.
