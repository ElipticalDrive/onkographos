Basic noise and random nodes are available, but common procedural patterns still have to be assembled in each script or function. Add reusable helpers above the existing noise() and random_value() APIs:
```
fbm(position, scale=1, octaves=4, lacunarity=2, gain=0.5)
ridged_noise(position, scale=1, octaves=4)
domain_warp(position, scale=1, strength=1)
voronoi(position, scale=1)
```
A terrain workflow could then read:
```
p = position()
h = fbm(p, scale=4, octaves=5)
geo = grid(64, 64)
geo = set_position(geo, vector(p.x, p.y, h))
output("Geometry", geo)
```
The helpers should return field values usable in positions, attributes, materials, and masks. Patterns expressible in pure DSL should be importable package functions; Python/backend implementation is appropriate when DSL cannot express the behavior.
