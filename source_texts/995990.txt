Why and outcome
Mountains, hills and dunes need compact silhouette descriptions and stable contours that can also place decorations. Add named profile operations to surfaces, reusing the existing deterministic Noise algorithm.
Proposed format and API
```
surface terrain 320x180 palette=world seed=7
  profile ridge key=m baseline=132 amplitude=44 cell=32 octaves=3 roughness=60 seed=11
```
Expose immutable profile heights through Surface::profile(name), plus a validated typed Profile specification. Each profile stores one integer y boundary per x. Its key fills pixels y >= height[x] to the surface bottom. Other cells are untouched, so earlier sky/shape operations can remain visible.
Noise and geometry contract
For width W, create the existing Noise with width=W, height=cell, and the given cell/octaves/roughness. Sample value(x,0), without stretched() normalization. Preserve current Noise's cell divisibility and octave checks. Compute:
```
height[x] = baseline - floor(amplitude * value(x,0) / 65535)
```
baseline is an integer boundary in 0..=surface_height; amplitude is 0..=baseline. Heights therefore remain in bounds, including an empty column when height==surface_height. More amplitude makes peaks rise. Horizontal periodicity follows the existing wrapped Noise field; equal first/last samples are not required because x=W repeats x=0.
Store the original height vector even if a later primitive paints over its visible pixels. Baseline references address this authored profile, never infer geometry from final RGBA or palette alpha. The surface's final raw key grid remains the source for mask references.
Define the shared stable seed derivation used by #47 here: length-prefixed UTF-8 identity components plus little-endian u64 seeds, hashed with fixed FNV-1a-64 and then the existing SplitMix64 finalizer. Profile identity includes kind, surface name and operation name; scatter includes kind, background name, layer name and operation name. Default owner/op seeds are zero. Publish exact byte ordering/constants and small seed vectors. Reordering/inserting unrelated definitions or operations does not perturb the result; renaming an identity intentionally does. Do not use DefaultHasher or change existing texture seed behavior.
Dependencies, errors and limits
Depends on #44. Reuse Noise validation; reject invalid baselines, amplitudes and unknown keys with positioned InvalidArgument/UnknownName. Profile vector entries count toward max_scene_pixels, while octave sampling and fill visits count toward max_scene_work. No hidden dense 2D noise image is required. Named profile records share the surface operation namespace.
Acceptance
Golden heights/key grids cover amplitude zero, multiple octaves, baseline at bottom, seed changes and horizontal wrapping.
Seed vectors prove order/import independence, intentional rename effects and parity across integer platforms.
Themes, including alpha changes, leave heights and raw mask occupancy identical.
Diagnostics cover non-divisible widths, bad octave counts, duplicate operation names and low budgets.
Document how baseline/height boundaries work, and provide contrasting mountain/hill/dune examples using the same algorithm.
Out of scope
New Perlin/Simplex algorithms, erosion, terrain meshes, hand-edited splines, vertical profiles and infinite world generation.
