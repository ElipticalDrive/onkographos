Context
Mesh format v3 already separates the transfer representation from the GPU representation:
vertex wire data is stored as SOA;
indices use meshopt when it is smaller;
the runtime reconstructs the chosen GPU layout before upload.
The game already chooses that GPU layout explicitly through NtStreamLayout: FLOAT32, FLOAT16, normalized or unnormalized INT8/UINT8/INT16/UINT16.
That ownership is intentional. The builder must not infer semantics and silently choose a "mobile", "quality" or other automatic profile. Different games and shaders have different precision requirements.
Problem
Explicit packing is supported, but it is not sufficiently observable or strict:
integer conversion silently clamps values outside the representable range;
FLOAT16 rejects overflow but does not reveal the precision loss introduced by conversion;
the build does not report the resulting GPU vertex stride or error per stream;
a game therefore has to inspect pack sizes and visual output manually to determine whether its chosen layout is safe.
Silent clamping is especially inconsistent with the engine policy of rejecting invalid content instead of repairing it invisibly.
Goal
Keep format selection entirely in game code, while making an explicitly selected packed layout safe and measurable at build time.
Proposed scope
1. Reject invalid conversion input
For every converted component:
reject NaN and infinity;
reject values outside the selected integer representation instead of silently clamping them;
retain the existing FLOAT16 overflow rejection;
report the mesh, stream, source value and target format in the error.
Normal quantization inside a valid normalized range remains ordinary conversion, not an error.
2. Produce packing diagnostics
Expose or print deterministic per-mesh/per-stream diagnostics suitable for local optimization work:
source and packed type;
component count;
bytes per vertex and final vertex stride;
source min/max;
maximum absolute round-trip error;
optionally RMS round-trip error if it remains cheap and useful.
The builder reports facts; it does not decide whether a given error is visually acceptable.
3. Optional game-owned error limit
Investigate a builder-only, opt-in maximum round-trip error for a stream. When supplied by the game, exceeding it fails the build.
Do not add semantic defaults. A position, UV, normal or custom attribute receives no special policy merely because of its name.
Only add this field if real game usage shows that the diagnostics alone are insufficient.
Acceptance
Existing explicit layouts continue to produce deterministic packs.
Out-of-range and non-finite values fail loudly with an actionable message.
A build can show the actual GPU stride and conversion error of each packed stream.
Runtime uploads the selected packed representation directly; no CPU expansion or additional runtime metadata is introduced.
Native and WebGL2 layout/alignment validation remains unchanged.
Builder/runtime tests cover FLOAT16, normalized integer and unnormalized integer conversions.
Existing game layouts are checked before enabling stricter rejection so an intentional clamp is not changed accidentally.
Non-goals
automatic semantic-aware packing profiles;
automatically selecting formats for the game;
position scale/bias metadata or shader decode policy;
mesh decimation, topology changes or LOD generation;
changing mesh wire compression;
UI size or debug-code work;
adding a runtime quality setting;
trading runtime performance for download size.
Related work
Mesh format v3 / SOA + meshopt already addresses transfer compression: mesh format: separate the wire layout from the GPU layout - measured -942 KB gz across one game's packs, zero frame cost #345 / mesh format v3: wire layout separated from GPU layout (SOA + meshopt index codec, C port) #348.

The remaining engine responsibility is narrow: the game chooses the packed layout; the builder proves what that choice does and rejects invalid conversion.
