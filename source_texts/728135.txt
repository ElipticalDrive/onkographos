What to build
Port Compression (Bad Stream) (badStream and its block, detail, smear, chroma, darkness fields) into @artifact/runtime. Tier C — baked into plates by default until this lands.
Plan: https://github.com/shchilkin/artifact/blob/experiment/runtime/docs/runtime/README.md. Work on experiment/runtime; open the PR against experiment/runtime.
Today: CPU main thread with getImageData in apps/web/app/utils/render/layers/index.ts (see also render/layers/textureEffects.ts). Port to GLSL in the runtime; the editor keeps its CPU path.
Time binding: Bursts.
Pointer binding: Burst on click.
Why: Heaviest effect (block analysis); Data Mosh covers most of the look on GPU.
Acceptance criteria
Registered in the runtime with a uniform mapping from the authored fields.
Static statistical parity (per-channel mean, variance, histogram distance) with the editor's renderDocument on the harness fixtures at 540px.
Motion goldens for the time binding and input goldens for the pointer binding.
Catalogue entry in /dev/runtime with live controls and a measured GPU time under 2 ms at 540px.
The editor CPU path is unchanged; the runtime shader matches it within the harness tolerance.
