What
VoxConversion.Run is now async Task<Summary> and runs the heavy voxelization on a background thread, so the Mesh → Voxels editor window stays responsive during a conversion instead of freezing.
The work splits into:
Main thread (before/after): mesh import + texture readback (ObjToVoxConverter.LoadScene) up front, and the closing AssetDatabase.Refresh — these touch Unity APIs that are main-thread-only.
Background thread (Task.Run): voxelization, the VoxPipeline, and the .vox write — all pure CPU now.
Why it needed a texture refactor
The blocker to backgrounding the compute was texture sampling: SampleTexel/SampleColor called Texture2D.GetPixelBilinear, which is main-thread-only and sits deep in the hot loops. So this adds TextureSnapshot — a Unity-free, linear-space pixel buffer captured on the main thread during load, with a managed repeat-wrapped bilinear sampler. It interpolates in linear space and the call sites re-encode to gamma, matching the old GetPixelBilinear-in-a-linear-project + .gamma behaviour. ColorSource.Texture now holds a snapshot rather than a Texture2D, and Convert is split into main-thread LoadScene + off-thread Convert(LoadedModel, …).
Progress & cancellation
Progress is marshalled back to the main thread via the captured SynchronizationContext (fire-and-forget Post), and cancellation flows back through a CancellationTokenSource the main-thread callback trips — so the editor's cancelable progress bar still works.
Batch / headless
Added RunSynchronous — a blocking inline variant for headless/batch use, where there's no UI thread to protect and awaiting (or blocking on) the async form under -batchmode would risk a deadlock. VoxelsFromMeshSpikeBatch uses it. The editor window now awaits Run (async void handler, full body in try/catch) and gains a re-entry guard — the button disables to "Converting…" while a run is in flight.
Notes for the reviewer
Color fidelity: the managed bilinear sampler won't be bit-identical to Unity's GetPixelBilinear (sub-texel center conventions may differ slightly), but since samples are averaged per voxel the output should be indistinguishable in practice. Worth a visual spot-check on a textured .obj/.fbx.
Files: ObjToVoxConverter.cs, VoxConversion.cs, VoxelsFromMeshSpikeWindow.cs, VoxelsFromMeshSpikeBatch.cs.
