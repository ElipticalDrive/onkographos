Abstract
As the volume of data generated by scientific instruments continues to grow, efficient timeseries compression has become a key challenge in applied computing. Existing lossy scientific
compressors (e.g., the SZ family and ZFP) primarily focus on limiting pointwise error (e.g.,
RMSE, error bounds), which does not necessarily guarantee preservation of scientifically
relevant signal characteristics such as long-term trend slope, dominant frequency, or the
behavior of transients and the error-tail distribution.
This paper presents SZYRYNGO v5, a standalone and cryptographically verifiable
1D lossy compression codec designed to maximize scientific fidelity while achieving high
compression. The codec employs block-wise removal of a slow-varying component (trend/baseline models: none, linear2, poly2, asinh4), transient detection (event coding), adaptive
quantization, reversible integer-domain delta coding, and entropy compression (e.g., LZMA).
On public datasets SWPC/CO2/GHCNwe demonstrate compression ratios of 2.46–
11.44× (depending on dataset and configuration), with high correlation and preservation of
the dominant frequency (DomFreqErr = 0% in our tests). In addition to standard metrics
(NMAE, correlation, trend slope error), we report error-tail metrics (P99 and P99.9 |e|)
and exceedance fractions with respect to thresholds Tα = α · span.
Keywords: data compression, time series, SZYRYNGO, lossy compression, scientific data,
signal integrity, event detection, arcsinh.

Introduction
In 2026, the amount of data produced by scientific instruments often exceeds storage and
transmission capabilities. Satellite missions, climate monitoring networks, and physics experiments
generate petabytes of data annually. Lossless compression is frequently insufficient—for floatingpoint data, the compression ratio is typically only 1.5–2×.
Existing lossy compressors can be broadly divided into:
• Error-bounded: e.g., ZFP [1], SZ [2]—guarantee an absolute or relative error bound
(depending on mode).
• Fixed-rate: e.g., ZFP in constant bit-rate mode.
Note: FPZIP [3] is not a fixed-rate codec.
Many compression-quality evaluations focus on minimizing pointwise error (RMSE). However,
low RMSE does not necessarily ensure preservation of signal characteristics relevant to scientific
analysis [4, 5], such as trend slope, dominant frequencies, and the behavior of the error tail (rare
events). SZYRYNGO v5 develops an integrity-preserving compression perspective: in addition
to amplitude error, it reports and controls selected invariants and tail metrics.
1.1
Positioning and related work
This paper targets 1D compression (a single variable over time, i.e., a time series). In HPC
settings, the largest compression gains often occur for 2D/3D/4D fields due to strong spatial
correlation. For 1D series, the most critical aspects are frequently: preservation of signal features
(trend, transients, error tail), interpretability of distortion, and reproducibility.
Accordingly, our evaluation emphasizes integrity metrics (including tail and invariant-like
properties), not just RMSE or declarative pointwise error bounds. Specialized approaches for
time-series and streaming compression exist; recent directions and references can be found, for
example, via DOI pointers: [6, 7, 8].

Scope and reference implementation
2.1
Scope
SZYRYNGO v5 is a lossy codec for 1D scientific data (time series). We provide:
• a specification of the compression pipeline (trend → events → quant → delta → entropy),
• formal integrity metrics (including tail/rare-event metrics),
• results on public datasets and artifacts to reproduce experiments.
2.2
Reference implementation and experiment artifacts
A reference Python implementation performs the full workflow: download → validation/cleaning
→ compression → decompression → metric computation → reports and plots. The implementation
is intended as a reference (correctness, validation, and reporting) rather than a maximally
optimized production version.
In benchmark mode, the following artifacts are generated (under out_dir):
• environment.json — environment metadata (CPU, cores, RAM, library versions),
• datasets_summary.json — dataset summaries (N, range, dtype, parse statistics),
• realdata_report.json and realdata_report.txt — per {dataset, configuration} results,
including wall_time_s,
• figs/<dataset>/*.png — diagnostic plots (time series, error, zoom, spectrum, tail CCDF),
• figs/pareto_*.png — global plots (e.g., Ratio vs NMAE, Ratio vs P99.9|e|).
2.3
CLI interface and flags
The script provides modes:
• –mode benchmark — run tests on public datasets,
• –mode encode — compress a .npy file to .szy,
• –mode decode — decompress .szy to .npy.
Key flags:
• –plots — generate plots,
• –no-cache — disable download caching,
• –out-dir <dir> — output directory,
• –block-size <N> — block size (default 5000),
• –model {none,linear2,poly2,asinh4},
• –qbits {8,16},
• –entropy {none,zlib,lzma},
• –events and –no-delta.

3.3
Why trend modeling still helps for periodic data
Many real-world time series contain components at different time scales: (i) a slow-varying
baseline/drift, (ii) quasi-periodic components (e.g., seasonality), and (iii) fast components and
transients. In SZYRYNGO v5, the trend model M (n) primarily aims to remove the slowvarying component, so that the residual has reduced dynamic range and becomes more
amenable to quantization and entropy coding.
Periodic components do not need to be explicitly parameterized by M (n); they can remain
in the residual, which (after centering and delta coding) can still be effectively compressed. In
practice, the choice of trend model balances: (i) model-fitting cost, (ii) parameter overhead, and
(iii) reduction of slow-varying dynamics within a block.

Invariance analysis
The reference implementation includes an ablation test verifying that lossless components (delta
coding and the choice of entropy codec) do not affect reconstruction quality, only the stream size.
This follows from the fact that after quantization the stream is discrete, and delta coding and
entropy coding are fully reversible.
Consequently, quality metrics (NMAE, correlation, SlopeErr, DomFreqErr, tail metrics) are
identical under such ablations, while container size changes depending on whether delta coding is
applied and which entropy codec is chosen.

8
Performance
Encoding performance depends primarily on the trend model. asinh4 is computationally expensive
due to per-block grid search for (k, b). Decoding is linear in N and, in the reference implementation,
significantly faster than encoding.
8.1
Notes on timing measurements
The execution times reported in realdata_report.json and realdata_report.txt come from
a CPU-based Python reference implementation and include the full workflow: container encoding,
verification decoding, and metric computation. Therefore, they should not be interpreted as the
maximum achievable throughput of a production implementation.
In particular:
• asinh4 fitting (grid search) dominates the encoding time,
• the pipeline is block-based and naturally parallel (blocks can be processed independently),
• a production-grade implementation can substantially accelerate encoding using, e.g., reduced
grids, parameter caching, vectorization, Numba/Cython/C++, and parallel block processing.
Environment metadata and timing data are saved to environment.json and realdata_report.json
to support reproducibility.
9
Limitations and future work
SZYRYNGO v5 is focused on 1D and integrity-oriented metrics. Natural extensions include:
• trend models that more directly address seasonality (e.g., a compact harmonic component)
while keeping parameter overhead low,
• adaptive per-block model selection (e.g., choosing linear2/poly2/asinh4 based on MDL/AIClike criteria),
• a production implementation (C++/SIMD, multithreading) and throughput evaluation on
large-scale datasets,
• extension to multi-dimensional data (2D/3D) while preserving tail-metric and invariancetesting methodology.
10
Conclusions
SZYRYNGO v5 is a 1D lossy compression codec designed for scientific time-series data with an
emphasis on integrity preservation. On public datasets:
• the 16-bit mode (linear2/16) achieves extremely small errors at compression ratios of
about 2.46–6.93×,
• the 8-bit mode (asinh4/8) reaches up to 11.44× compression with high correlation,
• DomFreqErr = 0% in our tests, and explicit reporting of P99/P99.9 |e| and exceedance
fractions Fα enables rigorous analysis of error-tail behavior.
