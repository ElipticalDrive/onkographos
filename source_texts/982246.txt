Summary
Adds a CPU-only mesh-aligned point-cloud geometry foundation for future point-cloud style-transfer work. The branch ports the narrow mesh, KD-tree, surface sampling, surface geodesic, and preprocessing behavior needed by the Python reference flow without changing WebGPU execution, worker protocol, UI controls, dependencies, or generated assets.
What changed
Added shared src/ml/geometry/ primitives for typed vector math, mesh analysis, triangle areas/normals, edge adjacency, vertex-to-face maps, and scipy-like 3D KD-tree queries.
Moved point-cloud preview KD-tree usage onto the shared geometry module while preserving the existing preview import path through a compatibility re-export.
Added surface sampling utilities for weighted triangle sampling, even-radius rejection, UV interpolation, bilinear texture lookup, textured point-cloud samples, and GLTF mesh extraction.
Added mesh point batches and CPU surface geodesic helpers for barycentric interpolation, eight surface-aware directions, adjacency-based gradient: "none" tracing, and endpoint reshaping.
Added prepareMeshPointCloudData-style preprocessing for multi-resolution point clouds, pooling maps, KNN interpolation weights, sample distances, and taus.
Added focused geometry tests and updated docs/code-map.md for the new shared CPU geometry layer.

Notes / Risks
This is a CPU foundation only. It does not wire point-cloud preprocessing into the worker, WebGPU kernels, VGG, optimizer flows, or the UI.
Real-world DiGeo/trimesh parity is still bounded by the available tests: deterministic tiny meshes cover primitives, sampling, UV/color lookup, one/two-triangle geodesics, and finite end-to-end preprocessing shapes, but there is no committed non-planar textured GLB oracle fixture yet.
No dependency changes, protocol changes, cache migrations, generated assets, or runtime Python coupling were added.
Follow-ups
Add an approved tiny Python parity probe or committed non-planar mesh fixture when an oracle asset is available.
Wire the CPU preprocessing foundation into future point-cloud VGG or worker flows in a separate task.
