Now. The distance-estimator raymarchers (User Bulb, KIFS, Mandelbox, Mandelbulb-family, CPU and GPU) step by exactly the DE each step. User Bulb has a cone-march prepass (UserBulbCalculator.ConeMarchTileHints); the others don't.
Idea (Keinert et al. 2014, "Enhanced Sphere Tracing"). Step ω·DE with ω ≈ 1.2–1.6. If the new sphere doesn't overlap the previous one (DE_new < (ω−1)·step), the step overshot: go back and step by DE (ω = 1) from there. The hit point is unchanged, so this changes speed only.
Watch. Numeric (non-Lipschitz) DEs such as UserBulb's user DE (see the UserBulb DE notes) can make the overlap test unreliable. Fall back to ω = 1 for those, or make ω a tunable parameter with 1.0 meaning exactly today. CPU and GPU must stay in lockstep (the #1197 KIFS lesson).
Verify.
Invariant: per ray, the over-relaxed hit distance equals the plain march's within ε (the hit epsilon) for every family on its smoke views. The image differs only at ε-level depth.
Step count drops; mutation: no overshoot fallback produces holes, which the hit-distance test catches.
Measure steps per pixel and frame time, CPU and GPU.
Batch parity: this changes what gets rendered. Any new option needs the region snapshot / --param / flag, the Command builder, and a parse round-trip test (CLAUDE.md), and the default stays byte-identical.
Win. Typically 20–40% fewer DE evaluations, so 3D renders are that much faster on all hardware.
From the 2026-10-15 GPU / rendering performance survey (ideas borrowed from games, offline renderers and GPU computing), filed as Phase 3b of #1298. Gains are estimates until measured.
