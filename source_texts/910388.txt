Welcome - and thanks for your interest
I was thinking about splitting the RawVolume implementation based on the region size
if region size below certain threshold use pimpl of the current implementation
otherwise use something as the PagedVolume as an internal pimpl (587fd3b)
and RawVolume itself just stays the facade - that wouldn't change any interface - but the method call overhead is something we would have to measure here. there are quite a lot of google benchmarks for the voxel package available
run them with make benchmarks-voxel-run if you are on linux or mac
we are accessing the RawVolume for reading only loops in an unlocked manner. This might also be a problem when we have to maintain chunks internally - as this would need locking for sure - but doing a lock on each volume.voxel(x, y, z) call wouldn't be the best way to handle this performance wise.
Regarding any other unclaimed tasks, if you find something in the existing tickets you would like to work on... feel free to pick one - but maybe add a note to the ticket. Maybe you also have some ideas or missing features that would like to see in the application(s) - then create tickets and lets discuss about them.
