Simply setting visibility=false will not 'remove' the pointclouds, it will simply tell threejs to omit them from being rendered. All information in memory will still reside in memory. To delete the cloud you have to do:
window.viewer.scene.pointclouds.forEach(function(layer) {
window.viewer.scene.scenePointCloud.remove(layer);
});
window.viewer.scene.pointclouds = [];
Additionally, threeJS will do frustum culling with visibility already. Furthermore, Potree behind the scenes will intelligently (as in actually save memory and performance) cull any clouds that are outside the frustum.
If you still want to implement this, I suppose you can access the pointclouds bounding box with
viewer.scene.pointclouds[i].boundingBox
compute the center from that, then just simply use the distance formula to find your distances (simple google search will find you that one lol). From there, find potree's render loop in the potree.js file, and test your distances and set your clouds visible or not visible.

Sure, so threeJS will test against the bounding box/sphere. If the box is within the frustum, even a small portion of it, it will not cull it. This is ideal because there is a high likelyhood that the user will need to see the thing on the edge of the frustum again. In terms of performance, Potree is already saying, hey this pointcloud is far away/almost outside the frustum/meets screen space error, so I am only going to load in the root nodes of the octree to save memory. Removing the pointclouds far away and then adding them will actually slow down performance because you are deleting the entire thing from memory, javascript has to garbage collect, info has to be removed from gpu, and then you have to do the opposite of that to get your pointcloud back in the scene. You will only see a minor performance benefit from making pointclouds far away visible/invisible to the point that it is probably not worth it. Again, you COULD absolutely have some threshhold and make a cloud visible or not based on that, but your going to have to do it programatically.
