Summary
This PR fixes several issues with domain bounds calculations in SDF operations and improves numerical stability in repetition logic.
Key Changes
RepeatSDF improvements:
Simplified the _compute method to use a cleaner symmetric folding approach: q = queries - spacing * torch.round(queries / spacing)
Fixed finite repetition logic to properly clamp grid indices before computing folded coordinates
Changed _get_domain_bounds for infinite repetition to return single-period bounds instead of arbitrary large bounds, improving visualization
RevolveSDF domain bounds fix:
Corrected the 3D bounds calculation to properly account for the radial distance from the revolution axis
Now correctly computes max_radius from the 2D profile's first coordinate and uses it symmetrically for x/y bounds
Improved documentation explaining that the 2D profile's first coordinate represents radial distance
TaperSDF numerical stability:
Changed hardcoded 0.0 to torch.zeros_like(r) in clamp operation for better tensor shape consistency
Test and benchmark updates:
Updated generate_sdf_showcase.py to use count=3 for RepeatSDF example, changing from infinite to finite repetition (3x3x3 grid)
Removed trailing EOF marker from test file
Build configuration:
Added *.vtk to .gitignore to exclude VTK output files
Implementation Details
The RepeatSDF refactoring uses torch.round to determine which period a query point belongs to, then folds it back symmetrically into the base domain. For finite repetition, grid indices are clamped before folding, ensuring only the specified number of copies are active.
