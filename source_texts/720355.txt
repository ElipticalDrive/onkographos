Hi,
Big thanks to the team for sharing these super useful tools.
I want to point out that frgs mesh-basic and frgs mesh-dlnr work using vanilla gaussian splatting trained .ply files.
The issue with output from different tools (e.g. LichtFeld-Studio, https://superspl.at/editor , WorldLabs, etc.).
This is an example from worldlabs:
```
frgs mesh-dlnr /mnt/e/Downloads/tschumi01_marbleworldlabs_expanded01.ply 0.25 -o tschumi01_marbleworldlabs_expanded01.mesh-dlnr.ply
2025-11-15 21:51:15,130 - fvdb_reality_capture.cli.frgs._mesh_dlnr - INFO - Loading Gaussian splats from from /mnt/e/Downloads/tschumi01_marbleworldlabs_expanded01.ply

  File "/usr/local/bin/frgs", line 7, in <module>

    cmd.execute()
  File "/usr/local/lib/python3.10/dist-packages/fvdb_reality_capture/cli/frgs/_mesh_dlnr.py", line 110, in execute
    raise ValueError("Gaussian splats file must contain 'camera_to_world_matrices'")
ValueError: Gaussian splats file must contain 'camera_to_world_matrices'
```
Is there a tool that can "fix" existing .ply file to compute and add the camera_to_world_matrices property ?
What can I do so I can make my files compatible with fvdb for further editing ?

Thanks for posting this issue @orgicus and sorry for missing it. There is not a current tool to do this but one could be implemented. The key issue is that to do mesh reconstruction, you need the camera poses and intrinsics for the images used to train the original splats. If you have access to these, it's as simple as amending the PLY. Could you describe your setup in more detail? Do you have access to the original camera information? Are the poses in the same coordinate space as the gaussians?
