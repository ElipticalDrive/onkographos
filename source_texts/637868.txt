Currently, the tile generation process uses high-resolution LiDAR point clouds regardless of zoom level. This results in unnecessary data processing and slower response times for lower zoom levels where high detail is not needed.
Feature request:
Implement logic to download and use coarser (lower resolution) point clouds for generating tiles at lower zoom levels
This will optimize performance and reduce compute costs while maintaining appropriate detail based on zoom level
Benefits:
Faster tile generation for zoomed-out views
Reduced data transfer and processing costs
Better user experience with responsive map loading

Proposed: derive both readers.ept resolution and writers.gdal cell size from the tile's Web Mercator span at each zoom — full resolution at z18/19, progressively coarser below that.
This also requires loosening tileRequestValidator.js, which currently hardcodes zoom 18/19, and thinking about cache keys/versioning. Closely related to #36 (Gaussian width) and #21 (speed).
