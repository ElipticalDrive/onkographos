Problem
HashedVoxelPointCloud, NDT, SparseTreesPointCloud and HashedSetSE3 computed voxel indices with a plain integer cast, which rounds toward zero: the voxel straddling each axis plane was twice as large as the rest, e.g. (-1, 1) for unit voxels. Besides uneven decimation:
HashedVoxelPointCloud and NDT: boundingBox() treats globalIdxToCoord() as the voxel's minimum corner, which only holds for floor(). It did not contain points with negative coordinates. For example, a point at x = -1.5 (voxel -1) got the box [-1, 0].
NDT: fitted a Gaussian over twice the volume around each axis plane.
SparseTreesPointCloud: same double-size grid. Separately, the comment of outerIdxToCoord() said "center" but it returns the minimum corner (which is what the wireframe boxes need); comment and variable name fixed.
Fix
HashedVoxelPointCloud, NDT, SparseTreesPointCloud: std::floor (same as TSDF already does).
HashedSetSE3 rounds to the nearest index instead (voxels centered at i*size, globalIdxToCoord() now documented as the center). Its only user, RelocalizationICP_SE2, bins 3D ICP solutions, whose z, pitch and roll only jitter around zero for a planar robot. With floor a bin edge would sit exactly at zero and split one pose across up to 8 voxels.
Maps saved before this change: serializeFrom() of the three maps stored and trusted the voxel index next to the points, so an old file would load with points under indices the new rule never produces (missed by radius searches, double-size NDT cells). They now put each point into the voxel its coordinates map to, not the stored index. The file format is unchanged; new files load exactly as before.
Tests
New test-mola_metric_maps_voxel_indexing. For each map type and axis it checks:
10 voxels (9 grids for SparseTreesPointCloud, whose grids are centered) holding exactly 5 points each;
every point inside its own voxel's box;
boundingBox() contains every point;
a map built with the former, truncated indices comes back consistent after a save and load.
New test-hashed-set-se3: same-size voxels along all six dimensions, and poses jittering around zero staying in one voxel.
Both fail on develop. The legacy-file check also fails with the new indexing but the old serializeFrom(). All tests of mola_metric_maps (28), mola_pose_list (4) and mola_relocalization (4) pass, including the NDT reference-scene comparison.
Companion of MOLAorg/mp2p_icp#139, which fixes the same rounding in mp2p_icp's voxel grids and FilterPoleDetector.
Summary by CodeRabbit
Bug Fixes
Corrected voxel and grid assignment for negative coordinates, preventing points on opposite sides of an axis from being grouped into the same cell.
When loading saved point-cloud maps, points are now placed according to their coordinates rather than potentially outdated stored cell indices.
Corrected the positioning of inner-grid boxes in sparse-tree visualizations.
Improvements
Pose collections now assign values to the nearest voxel, consistent with their centered-voxel layout.

Major · Data Integrity & Integration · Heavy lift
Preserve points when legacy voxels merge during reload.
If an old index-0 voxel contains 32 points with -1 < x < 0 and an old index-−1 voxel contains a point at x = -1, this reassignment sends all 33 points to new voxel −1. VoxelData::insertPoint() silently drops the 33rd point. The same operation in NDT::serializeFrom() at Line 165 can merge 17 points into a 16-point voxel. A saved map therefore loses points when it loads. Add an overflow policy that preserves archived points, or reject a reload that cannot preserve them. The new tests use only five points per cell, so they do not exercise this case. (raw.githubusercontent.com)
