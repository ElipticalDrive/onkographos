Problem
A clear and concise description of what the problem is.
ie: Why is this needed?
For now we have a hard edged AABB collision system which works pretty well with the map, but when it comes to entities colliding with one another, this becomes an awkward and frustrating problem. Multiple mobs in one space standing on one another. Mods which adds in physical entities that get stuck on one another in a pile. The ability to push a minecart or boat fluidly with the player's position relying on weird server side hacks which the client is unaware of until it sends the packets over. This can result in completely broken server side magnetic collision. For example: A player has a ton of mobs in a pen, with physical collision AABB style this suddenly becomes an extreme limitation and no longer does the pen allow for a lot of mobs to be stored in it, along with trying to access specific mobs becomes an extreme hassle if the player falls between them. Lua implemented magnetic collision suddenly allows this to work semi-smoothly on a local server, but breaks with even the slighted lua vm lag. A minecart can be pushed smoothly in singleplayer with magnetic collision lua side, but on a server pushing the cart with your body could result in a delay, with you missing out on getting your minecart as it rolls away.
Solutions
Magnetic collision detection is a relatively simple concept: Two entities colliding each other, let's say with "use_magnetic_collision = true" in their entity registration, act like two positive magnets near each other. The closer they are together, the greater the push back force is. For ease of use I've devised a way (in lua) to implement this roughly. This is extremely rough, as I do not have access to deep collision implementations as this being built into the game would have allowed me to. The implementation essentially builds a cylinder collision boundary out of the entity's collision box, taking the top, bottom, then widest from the center outer edge and utilizing this simple shape to be able to quickly compare two cylinders to each other in a 2D plane and push them away from each other. Magnetic collision detection is a purely 2D correction force, as entities should not be able to stack on top of each other when this is enabled, this is quite literally a solution for this happening.
As per my statement above, this is a rough sketch of what I am talking about:
This is implemented as such:
```
local math_random = math.random

local integer_test = {-1,1}

mobs.collision = function(self)
				
	local pos = self.object:get_pos()

	--do collision detection from the base of the mob
	local collisionbox = self.object:get_properties().collisionbox

	pos.y = pos.y + collisionbox[2]
	
	local collision_boundary = collisionbox[4]

	local radius = collision_boundary

	if collisionbox[5] > collision_boundary then
		radius = collisionbox[5]
	end

	local collision_count = 0

	for _,object in ipairs(minetest_get_objects_inside_radius(pos, radius*1.25)) do
		if object and object ~= self.object and (object:is_player() or object:get_luaentity()._cmi_is_mob == true) then
			--stop infinite loop
			collision_count = collision_count + 1
			if collision_count > 100 then
				break
			end
			local pos2 = object:get_pos()
			
			local object_collisionbox = object:get_properties().collisionbox

			pos2.y = pos2.y + object_collisionbox[2]

			local object_collision_boundary = object_collisionbox[4]


			--this is checking the difference of the object collided with's possision
			--if positive top of other object is inside (y axis) of current object
			local y_base_diff = (pos2.y + object_collisionbox[5]) - pos.y

			local y_top_diff = (pos.y + collisionbox[5]) - pos2.y


			local distance = vector.distance(vector.new(pos.x,0,pos.z),vector.new(pos2.x,0,pos2.z))

			if distance <= collision_boundary + object_collision_boundary and y_base_diff >= 0 and y_top_diff >= 0 then

				local dir = vector.direction(pos,pos2)

				dir.y = 0
				
				--eliminate mob being stuck in corners
				if dir.x == 0 and dir.z == 0 then
					--slightly adjust mob position to prevent equal length
					--corner/wall sticking
					dir.x = dir.x + ((math_random()/10)*integer_test[math.random(1,2)])
					dir.z = dir.z + ((math_random()/10)*integer_test[math.random(1,2)])
				end

				local velocity = dir
				
				--0.5 is the max force multiplier
				local force = 0.5 - (0.5 * distance / (collision_boundary + object_collision_boundary))

				local vel1 = vector.multiply(velocity, -1.5)
				local vel2 = vector.multiply(velocity,  1.5)

				vel1 = vector.multiply(vel1, force)
				vel2 = vector.multiply(vel2, force)
			
				self.object:add_velocity(vel1)
				object:add_velocity(vel2)
			end
			
		end
	end
end
```
As you can see, since I cannot utilize move_to or set_position because an entity would begin clipping into voxels, completely breaking everything, the ability to have this done in the engine would remove the need for this to be implemented server side at all. This implementation also uses the add_velocity call, which instead of being able to statically move things away, requires the usage of pushing them utilizing the velocity of the entity. This is a rough prototype but it does work as per the feature request, just not even close to as cleanly as it would be built into the engine.
