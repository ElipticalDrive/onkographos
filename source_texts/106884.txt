TorchTomo currently supports 2D parallel and fan beam operators. This adds an experimental ConeBeam API that integrates 3D volumes along explicit source-to-detector segments, including helical trajectories and curved detectors, with a matched discrete adjoint and gradients through source/detector coordinates.
The optional torchtomo.ctpd reader decodes CT-PD geometry, detector storage order, projection scaling, and focal-spot offsets. Synthetic checks and a measured TCIA L213 pilot cover the path from DICOM projections to native 3D CGLS reconstruction. CI installs the tcia extra so reader tests execute.
Validation:
Full CPU suite: 142 passed, 90 device-dependent skips.
Colab T4: 13 targeted CPU/CUDA tests passed, including explicit transpose and geometry-gradient checks.
Lint, formatting, source/wheel builds, and an isolated wheel import passed.
Measured L213 pilot: 20 CGLS iterations, 123 training and 123 held-out views, 2.318% training error and 3.044% held-out projection error. Runtime was 67.97 seconds including validation, with 357.74 MiB peak PyTorch allocation.
This is a PyTorch reference backend. It does not add fused CUDA kernels, FDK, or statistical regularization. The measured test uses a coarse grid and evaluates only the central 16 mm slab; axial margins are partly observed. Eight training views and vendor CT select the planar coordinate frame. Image agreement peaked before the final iteration, so regularization and broader scanner validation remain necessary. Reproduction commands, data attribution, and pilot results are recorded in benchmark/README.md.
