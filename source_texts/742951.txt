OpenPFC can evaluate a signed distance for a static implicit shape (Plane, Sphere, Circle, and the ellipsoid family in kernel/geometry/implicit.hpp). It does not build a Euclidean distance field from a periodic binary mask.
That transform is a generic grid primitive. A caller that already has a mask, rather than a closed-form shape, needs the distance to the mask inside the periodic cell. Hamilton–Jacobi redistancing (issue #436) is a different operation: it restores unit slope of an existing level set and does not replace a mask distance.
WoodLab's core–shell experiment carries a CPU Felzenszwalb transform for this. It should not grow into an application-owned numerical library. This issue is the place for the generic primitive. WoodLab's current virtual-laboratory loop uses analytic fibre distances and does not need the transform in order to run.
Acceptance
A CPU function on a uniform periodic Cartesian grid maps a binary mask to the Euclidean distance to that mask.
State the sign convention and the voxel-centre convention in the header.
Tests cover a single seeded voxel, a flat interface away from the boundary, and a feature that wraps a periodic face.
No material model, shell thickness, or scattering code.
Non-goals
Do not implement issue feat(level-set): GPU Hamilton–Jacobi interface evolution and redistancing #436 here.
Do not port a WoodLab density or core–shell composition into OpenPFC.
