Goal
Add generic, deterministic post-transform half-space clipping to Geometer illustration pipelines. This is geometry policy only: no PCB, board, Altium, KiCad, or Toon semantics belong in Geometer.
Downstream coordination: altium_cruncher issue 67 needs to render the portion of a placed component body on one side of a board surface without rebuilding or clipping tessellation in Python.
Compatibility and public contracts
Preserve every strict A0 request, result, operation identity, and behavior. Add generated B0 successors for model illustration, model illustration geometry, mesh illustration, mesh illustration geometry, and Fast mesh HLR. Each B0 request has optional clipping; absence selects unclipped legacy geometry semantics with the unambiguous B0 result shape. cap_policy is required only inside clipping.
Version the renderer-neutral payload as geometry.mesh_illustration.geometry.b0 and the B0 linework payload as geometry.hlr_projection.result.b0. B0 attachment descriptors name those schemas; their empty state, fragment metadata, optional bounds, stats, and warnings agree with the outer B0 result. All A0 payloads remain unchanged.
Version only complete serialized roots. Nested plane, clipping, limits, normalized-plane, fragment-metadata, and empty-state models are ordinary members of the B0 request/result namespace and have no independent generation identity. B0-aware clients select the root codec from the complete operation identity and the exact catalog declaration.
The executable IPC frame format, Worker message protocol, operation-catalog format, generic operation ABI, unchanged mesh-collection input, and unchanged packed formats remain A0. Add geometer.ipc.request.b0 and geometer.operation.outcome.b0 roots where the closed JSON unions change; do not widen strict A0 roots. Advance the date-based package version and C ABI generation, regenerate all clients, and require catalog digest plus request/result identity checks before invoking B0.
The B0 root inventory includes both model operation request/results, both composed-mesh operation request/results, geometry.mesh_illustration.input.b0, geometry.mesh_illustration_geometry.input.b0, a dedicated geometry.mesh_hlr_projection.request.b0, geometry.hlr_projection.result.b0, geometry.mesh_illustration.geometry.b0, geometer.ipc.request.b0, and geometer.operation.outcome.b0. The dedicated mesh-HLR request does not widen geometry.hlr_projection.options.a0; the unchanged composed-mesh attachment remains geometry.mesh_collection.a0.
For executable IPC, boundedly extract exactly one valid operation member with duplicate-key rejection, resolve its verified catalog declaration, select exactly the A0 or B0 request root, then strictly decode the complete envelope and verify the embedded identity. Never probe or fall back between generations. Clients select the A0 or B0 outcome root from the outstanding operation and verified catalog declaration.
A0 is implemented as a strict compatibility adapter into the shared B0-capable internal operation: decode the A0 root, normalize it with clipping absent while preserving A0 presence/default semantics, execute the same geometry/HLR/renderer pipeline, then project the result back to the exact A0 result root. This is internal conversion only?never accept B0 fields in A0 JSON or return a B0 outcome for an A0 identity. Differing carriers, especially A0 indexed-mesh HLR versus B0 mesh_collection, retain separate strict input adapters and converge only on shared internal Fast HLR structures.
Preserving A0 operation contracts does not promise that a previously released client will connect to a newer executable/library: exact catalog-digest and C ABI-generation validation may reject that pairing. The new release's generated clients expose both unchanged A0 operations and B0 successors.
B0 becomes the canonical unqualified illustration API. Migrate all maintained first-party consumers?browser and native labs, Worker pages, Rust/Python/TypeScript examples, direct-static and executable demos, SDK/WASM smoke programs, benchmarks, promotion manifests, documentation snippets, and primary end-to-end tests?to the B0 identities. Keep A0 calls only in an explicit reviewed compatibility-test allowlist. Release tests must assert the executed operation and decoded result identity, and a repository scan must reject accidental live A0 illustration callers outside that allowlist.
A point survives a canonical world-space plane when:
```
dot(normal, point) - distance_mm >= -tolerance_mm
```
Accept one to sixteen ordered planes. Validate finite nonzero normals, finite distance and nonnegative tolerance, and required cap_policy: "none". Independently bound output triangles to 2,000,000, generated vertices to 6,000,000, intersections to 8,000,000, and edge-plane tests to 32,000,000; these defaults are also hard ceilings and callers may only lower them. Validate before allocation or work. Normalize and canonically quantize planes and transformed world-space source positions before the first classification and before identity.
Pipeline order
Apply clipping:
after STEP root placement and the complete supplied model, occurrence, or mesh affine transform;
after STEP tessellation or analytic lowering;
before source bounds, Fast HLR, outlines, visibility/fusion, shaded projection, SVG, and renderer-neutral geometry; and
consistently for direct model/analytic B0 operations and composed mesh B0 operations.
For composed meshes, B0 mesh HLR consumes the same governed colored mesh_collection as B0 illustration. Preserve raw attachment SHA-256 separately and correlate supplied HLR with a canonical geometry-only clipped-fragment digest. A0 indexed-packet HLR remains unchanged. B0 mesh HLR is Fast-only and rejects poly/exact selection.
Geometry semantics
Preserve surviving mesh IDs/order, complete material tables, triangle material identity, opacity, and double-sided policy.
Apply inverse-transpose normal transforms and correct winding for negative affine determinants.
Interpolate boundary positions and available normals deterministically.
Compact unused geometry without merging normal or material seams.
Remove duplicates and degenerates with an exact documented geometry epsilon unrelated to view or pixel scale.
Bound output triangles, generated vertices, intersections, and edge-plane tests independently; never return partial geometry.
cap_policy: "none" creates no section faces or materials. The cut is an ordinary mesh boundary for HLR and outlines.
Empty and identity semantics
Every B0 result has a required top-level empty flag meaning source-fragment emptiness before view culling. Model 3D bounds and projected geometry bounds are absent, never null or fabricated zeros, when empty. Required geometry attachments and requested HLR views remain present with empty arrays. Empty clipping is successful expected control flow and emits no warning.
Return normalized clipping metadata, input/output triangle counts, a full fragment digest, and a separate geometry-only linework digest. Use versioned canonical binary serialization and cross-platform identity vectors. Preserve raw attachment identity separately.
Demonstration and release
Extend the direct-static Rust illustration example into a packageable demo. It must use GeometerDirectClient through a relocated SDK with no geometer executable discovery. Retain STEP input and add a built-in analytic clipping specimen plus plane, distance, and tolerance options. Produce unclipped/clipped SVGs and a self-contained comparison HTML page showing normalized planes, triangle counts, optional bounds, fragment digest, and empty state.
The shared Geometer release publishes versioned windows-x64 and macos-arm64 demo archives, with notices, canonical inventory, checksums, provenance, draft verification, and public redownload verification. Linux remains a source-level portability/VM check, not a prebuilt demo target. The core SDK platform matrix is unchanged.
Acceptance
Exact native tests cover one/multiple planes, canonical numerics, transformed/mirrored meshes, interpolation, normals, materials, adjacency, degenerates, limits, invalid planes, empty success, and deterministic repeatability.
Model tests prove STEP and analytic clipping occurs before bounds and internal Fast HLR.
Composed-mesh tests use the same mesh collection for B0 HLR and illustration, prove digest correlation, and reject mismatched/legacy HLR.
Compatibility vectors prove A0 bytes and strict behavior remain unchanged; generated B0 bindings cover every maintained language.
Identity vectors agree on Windows x64, macOS ARM64, and browser WASM.
The Rust demo passes relocated-SDK smoke tests with an empty PATH on Windows and macOS.
Full Rack, native CTest, contract generation, static SDK validation, WASM validation, L99, release-mode standards audit, and shared public release verification pass.
Downstream examples and non-goal
For a normalized rigid board with top z=0 and bottom z=-T:
```
top fragment:    normal=(0, 0,  1), distance_mm=0
bottom fragment: normal=(0, 0, -1), distance_mm=T
```
Opposite-side edge overhang visibility remains out of scope because outside board footprint OR beyond surface is not representable by one half-space.
