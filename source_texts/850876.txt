Owner
Alison saw three WebGL warnings in Firefox on macOS while listening to music, plus what looked like a page refresh that set the volume back to full.
Cause
The "refresh" and the volume reset (B450). Each track remounts WatchScreen and its Player, so the listen screen, the visualiser and the <audio> element are all built again. A new media element starts at volume 1, and the volume was stored only on the old element.
WebGL context was lost. This is the old visualiser releasing its context on that remount (WEBGL_lose_context on drop). When a real loss happened, the handler never called preventDefault, so the browser could not restore the context and the screen stayed on its CSS look.
WEBGL_debug_renderer_info is deprecated. glow::Context::from_webgl2_context requests every extension it knows. The UI never reads the renderer string.
drawArraysInstanced: Drawing without vertex attrib 0 array enabled. The fullscreen triangle was built from gl_VertexID with no attribute array enabled. Firefox implements drawArrays through drawArraysInstanced, which is why the warning names that call.
Fix
Volume. Volume and mute are stored in localStorage (pharos.volume). Each new player applies them before its stream attaches, so autoplay never starts at full volume. Video uses the same setting.
glow removed. render/webgl.rs calls WebGl2RenderingContext directly. The only extension it requests is WEBGL_lose_context; I checked the built wasm and no other WEBGL_* string is left. Recorded in ADR-0049, which supersedes part of ADR-0039.
Attribute 0. The vertex shader reads a_corner from a static buffer enabled at location 0.
Lost context. A lost context is now preventDefaulted, frames are skipped, and on restore the program, buffer and texture are rebuilt. It falls back with context_lost only if the context has not come back after 5 s.
Release on drop is kept. Firefox will still log "WebGL context was lost" once per track change. That line is the intended release of the old canvas's context, and ADR-0049 explains why it stays.
Signals:
pharos: volume restored volume=<v> muted=<bool>
pharos: webgl context lost program=<p>, waiting for restore
pharos: webgl context restored program=<p> waited_ms=<n>
Tests
Unit: the volume setting round-trips, a garbled setting is ignored, and the vertex shader declares the location-0 attribute.
Playwright (new): turn the volume to 0.3, leave and replay the song, and expect 0.3 on the new <audio>. With WebGL2, also expect attribute 0 to be enabled, and a context lost and restored through WEBGL_lose_context to log the restore without a context_lost fallback. This passed locally against swiftshader Chromium; it skips the GPU half where no WebGL2 is available.
cargo clippy -p pharos-ui --features web --target wasm32-unknown-unknown --all-targets -D warnings is clean.
Not tested in Firefox itself, because no Firefox is available on this machine.
Bugs B450, B451. Invariants V390, V391.

fix(ui): wait for a lost WebGL context to come back
…
6d7663f
```
A lost context switched the visualiser or backdrop to its CSS look for
good: the lost handler only set a flag, never called preventDefault, so

skips frames while the context is gone, and on webglcontextrestored

that has not come back after 5 s still falls back as before.

The listeners are also registered only after the program builds, so a
shader failure no longer leaves a dropped closure attached to the
canvas. Loss and restore each log a `pharos: webgl context` line.
```
