Summary
Restore the historical Cook-Torrance vs GGX distinction. Before this PR both models shared the same kernel (GGX NDF + Smith-GGX G), making them mathematically identical. Now:
Cook-Torrance (1982) uses Beckmann NDF + V-cavity geometric attenuation min(1, 2·NH·NV/VH, 2·NH·NL/VH) — narrower, sharper highlights.
GGX (Walter et al. 2007) keeps GGX/Trowbridge-Reitz NDF + Smith-GGX G — longer highlight tails.
Add anisotropic variants for both families:
CookTorranceAnisotropicModel: anisotropic Beckmann + V-cavity G.
GGXAnisotropicModel: anisotropic GGX + anisotropic Smith-GGX (Heitz Λ form).
Both parameterized by (roughness_x, roughness_y, F0, albedo) with Disney remap per axis.
Changes
src/models/_microfacet_utils.jl: new helpers _beckmann_d, _vcavity_g, _ggx_d_aniso, _smith_g1_aniso, _beckmann_d_aniso.
All four Cook-Torrance variants (plain, specular, fresnel_diffuse, scaled_diffuse) updated on both the Julia and GLSL sides.
New files: cook_torrance_anisotropic.{jl,glsl}, ggx_anisotropic.{jl,glsl}.
levenberg_marquardt.jl: new _fit_microfacet_aniso_diffuse (8 parameters) with fit_brdf methods for both anisotropic models.
BRDFPlatform.jl: export new model types; auto-discovered by the UI dropdown.
The CT-equals-GGX model correctness test was inverted to assert the two families now meaningfully differ.
Reviewer notes
The anisotropic GLSL shaders derive their tangent frame in-shader (placeholder until per-vertex tangent attributes are wired into the Three.js renderer). The frame is aligned so that N = +Z maps to T = +X, B = +Y to match the Julia shading-frame convention used by evaluate().
The Disney roughness remap (α = roughness²) is preserved across all variants, so existing fit bounds and initial guesses still apply.
One pre-existing error in test/validation.jl (the GGX block calls GGXModel(roughness, F0::RGB), which doesn't match any constructor) is unrelated to this PR and left in place.

GLSL validation passes for Lambertian, Cook-Torrance (5/5), and energy conservation (13/13)
