Closes #94. Part of #95.
Summary
One projection for the CPU and GPU. viewProjection(camera, width, height) in src/simulator/renderer.js builds the matrix every shader receives as a uniform. Vertices now go to the GPU in world millimetres.
Clip x and y give the existing 60° perspective, and clip w is the view depth.
Clip z is filled from w with the existing linear depth mapping (depthNdc, depth bias in mm included). This keeps line depths exactly as before.
projectPoint and projectSegment (used for wheel-zoom picking and tests) apply the same matrix and mapping on the CPU, so the two cannot drift.
Lines are still clipped at the 1 mm near plane on the CPU (clipSegment) before upload.
Solid render mode. A Render select next to the mouse mode chooses Wireframe (the default) or Solid. In Solid mode a second, Lambert-lit program draws the accepted pose's display volumes from the new src/simulator/bodies.js:
base and platform plates, extruded just off the anchor plane;
a cylinder for each horn and rod;
a box for each servo.
Unit cylinder and box meshes are drawn with drawArraysInstanced, with per-instance transforms and colours in an attribute buffer (vertexAttribDivisor 1). The full wireframe scene and every overlay are drawn over the bodies with the same depth buffer. Failure colours and the loads overlay's graded rod colours carry over to the bodies. Blending stays off, because the ghost dims rather than uses alpha. Context restore rebuilds both programs, all buffers and the vertex arrays.
Guardrails from the issue. Body sizes are display constants (multiples of horn length, with a 1 mm floor), not layout fields, so the export contract is unchanged. The docs call the bodies display volumes with no physical meaning. docs/FEATURES.md section 12 keeps "No collision detection" and adds that the solid bodies are never checked against each other.
Saved state. The mode is saved as simulator.renderMode. A file without it keeps the current mode, and an unknown value rejects the file, naming the field.
Docs. A new Render modes section in docs/SIMULATOR.md, plus updates to its Rendering checks section (the old text said the vertex shader passes positions through), docs/FEATURES.md, docs/architecture.md, docs/IMPLEMENTATION_CONTRACTS.md and the README.
Tests
tests/simulator/projection-oracle.test.js
New acceptance test: the shader's matrix path matches projectPoint for several cameras, aspect ratios and depth biases. It holds to 1e-12 in doubles and 1e-5 with the matrix in 32-bit floats.
The upload test now projects the world-space line buffer with the uploaded matrix and checks it against the independent pinhole camera.
tests/simulator/bodies.test.js
Body counts, endpoints, radii and placement, including the case without an accepted pose.
Failure and load colours carry over to the bodies.
Instance transforms place the unit meshes correctly, and all mesh normals point outward.
Plate prism geometry.
Solid mode issues 12 cylinder, 6 box and 2 plate instanced draws before the lines, and wireframe mode issues none.
tests/simulator/helpers.js has a shared WebGL2 fake (createFakeGL), now used by the renderer and oracle tests.
View, snapshot and UI tests cover the render select, the redraw on change and the renderMode round trip.
scripts/browser-geometry-check.mjs switches the app between Wireframe and Solid in real WebGL and requires:
gl.getError() stays 0 in every mode and after a pose request in Solid mode;
Solid draws more pixels than Wireframe;
switching back restores the wireframe image exactly.
All of these passed locally:
npm test: 357 tests
npm run smoke
npm run test:browser
npm run test:browser:geometry
npm run test:browser:diagnostics
npm run test:browser:render: still finds every rod, horn and world axis at its pinhole position, now through the GPU matrix path
I also checked Solid mode by hand in the browser, static and while a wobble animation played, with no WebGL or console errors.
