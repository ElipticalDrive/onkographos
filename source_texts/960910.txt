My initial comment was that using pitch, yaw and roll for the traces would be more interpretable in real time than quaternion values.
Bradon then mentioned he was planning to add the 3D model. I do think both are helpful.
The issue is the same: how the user mounts the miniscope on the head matters.
So, I see a couple options: 1. don't show the head in the visualization, changing camera view will suffice for the user to view the scope as intended (camera panning is already available in what Aarón coded for the 3d model visualizer). 2. Let the user define what is pitch and roll with some sort of offset parameter. This would make more sense to make the traces interpretable relative to the animal, which is what ppl think about. tbh, polar plots might even make more sense.
I think any changes should only change the visualization, not the underlying data.
Even though I love the 3D visualizer, I would be wary about the amount of resources it takes up. It is immensely helpful for demos, maybe not so much for real time data acquisition.

Euler angles are trivial to add in with another tab, I've already got that working using the QuaternionToEuler transform [check out the changes in this commit].
I started working on the 3D model using Hexa.NET.ImPlot3d, but ran into a pre-existing issue. The underlying cimplot3d binding did not specify the initialization functions correctly, leading to generator errors in v2.2.9. There is a pre-release version (2.2.9.1-prerelease) that adds the necessary methods, but there are still issues with cimplot3d as discussed in this comment that would require re-compiling it from source. For now, I am working on plotting the orientation using the built-in plotting function, but if these projects ever release updates that fix these issues we can easily pivot and bring them in to make use of the 3D plotting.
I have a working prototype of the orientation plotting here with axis lines instead of any plane or other visualization. I will need to test this with live data to 1) confirm the axes / signs are correct, and 2) that it updates smoothly.
