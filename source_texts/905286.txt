# vossvolvox-rust

A memory-safe Rust implementation of the vossvolvox molecular voxel toolkit that reads PDB files directly and reproduces the C++ reference's volumes, surfaces, channels, PDB files, and density maps.

## Status

The Rust implementation covers every C++ analysis frontend. The published 2LYZ and 1BL8 suite
matches its C++ oracle for numeric summaries, PDB HETATM hashes, line counts, channel counts, and
the complete MRC byte stream. Additional parity cases cover paired volumes, RNA/protein maps,
fractional solvent volume, fractal dimension, and the 1JJ2 ribosomal exit tunnel.

The C++ `pdb_to_xyzr.exe` converter is intentionally absent. Rust always parses PDB directly,
applies the embedded radii table and filters, and rasterizes atoms without an intermediate XYZR
file.

## Build

Rust 1.85 or newer is required because the crate uses the Rust 2024 edition.

On macOS, install the Rust toolchain manager declared by the repository:

```bash
brew bundle
rustup default stable
```

The `Brewfile` intentionally excludes compilers used only to benchmark the C++ reference.

```bash
cargo build --release --bins
```

The optimized binaries are written under `target/release/`.

## First calculation

```bash
target/release/volume \
  -i 2LYZ.pdb \
  --exclude-ions \
  --exclude-water \
  -p 2.1 \
  -g 0.9 \
  -o 2LYZ-volume.pdb \
  -m 2LYZ-volume.mrc
```

This reference case reports a volume of `18550.861 A^3`, a surface area of `4982.054 A^2`, and
`1001` atoms.

## Resolution choices

The coarse `0.8-1.2 A` grids in the parity suite keep routine verification fast. Publication
calculations use a `0.1 A` grid and require substantially more time and memory. Rust keeps both the
primary grid and parallel raster/contraction scratch at one bit per voxel; the supported voxel
domain matches the signed 32-bit indexing used by the C++ reference and density-map formats.

## Programs

| Rust binary | C++ reference | Purpose |
| --- | --- | --- |
| `volume` | `Volume.exe` | Molecular volume and surface area |
| `volume_no_cav` | `VolumeNoCav.exe` | Volume with enclosed cavities filled |
| `vdw` | `VDW.exe` | Van der Waals volume |
| `cavities` | `Cavities.exe` | Enclosed cavity extraction |
| `channel` | `Channel.exe` | Seeded solvent channel extraction |
| `solvent` | `Solvent.exe` | All-solvent extraction |
| `all_channel` | `AllChannel.exe` | Accessible channel enumeration |
| `all_channel_exc` | `AllChannelExc.exe` | Excluded channel enumeration |
| `fsv_calc` | `FsvCalc.exe` | Fractional solvent-volume sweep |
| `frac_dim` | `FracDim.exe` | Fractal-dimension calculation |
| `two_vol` | `TwoVol.exe` | Shared-grid volumes for 3D printing |
| `protein_rna_volume` | `ProteinRNAVolume.exe` | RNA/protein shared-grid volumes |
| `tunnel` | `Tunnel.exe` | Ribosomal exit-tunnel extraction |

Every binary accepts `--help`. The single-grid surface tools share surface PDB (`-o`),
half-resolution EZD (`-e`), MRC (`-m`), and CCP4 (`-c`) outputs. `two_vol` uses `-m1` and `-m2`;
`protein_rna_volume` writes `rna.mrc` and `amino.mrc`; the channel enumerators write one map per
selected channel. `fsv_calc` and `frac_dim` report tabular results only. Shared PDB filters match
the C++ options.

## Verification

Run the fast Rust checks:

```bash
cargo test --all-targets
cargo clippy --all-targets --all-features -- -D warnings
```

Run the complete reference parity suite, including the 1JJ2 tunnel case:

```bash
python3 tests/e2e/e2e_parity.py --extended
```

The E2E runner builds release binaries and downloads 2LYZ, 1BL8, and optionally 1JJ2 from RCSB
into a temporary directory. It records no credentials and removes all fixtures and outputs when
the run finishes. For offline reruns, keep those PDB files in one directory and pass
`--fixture-dir /path/to/pdb-fixtures`.

## Performance

For a publication-resolution 2LYZ calculation at `0.1 A`, Rust used 46.9 MiB peak RSS versus
275-278 MiB for C++, while running 2.06 times faster than the shipped C++ binary and 1.32 times
faster than a separately compiled GCC/OpenMP build. All implementations produced the same volume
and surface. See [docs/BENCHMARKS.md](docs/BENCHMARKS.md) for the method and complete results.

## Design

The primary storage is a bit-packed `Grid3D`. Parallel rasterization assigns disjoint Z slabs while
workers monotonically set one shared packed atomic grid. Exclusion contraction follows the same C++
design with one shared packed atomic clear mask. Repeated writes are harmless in either direction,
and scratch memory remains one bit per voxel regardless of worker count. The implementation uses no
`unsafe`.
