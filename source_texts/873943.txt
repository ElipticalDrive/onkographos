Summary
Brings the Numos physical-atmosphere path to a full procedural volumetric cloud
system with physically-based lighting, cloud-on-terrain shadows, a unified
cloud-motion model, and several perf passes. The entire atmosphere/cloud stack is
gated behind rtx.skyMode = 1 (default 0 = legacy skybox), so it is inert for
existing content until opted in. Behaviour changes outside Numos are listed under
"Global changes."
43 commits · 56 files · ~+5,900 / −2,700.
Volumetric clouds (Numos)
Procedural field from a prebaked 3D Perlin/Worley-FBM noise volume (tile-wraps at
cloudNoiseTileKm, 12 km) — no cloud assets.
Per-frame D_sun / D_ambient 256×256×32 optical-depth voxel grids; screen-space
cloud render RT with Nubis Cubed 2023 lighting; secondary-ray cloud dome LUT so
indirect/PSR/reflection rays see clouds without a per-ray march.
Per-column cloud model (baked placement map → coherent towers, not stacked puffs);
hex de-tiling of the noise (Heitz–Neyret, kills the tile period); edge detail via
coverage-threshold modulation; cloud height LUT; optional second high-altitude
deck ("layer 2" echo deck); ghost-rejecting cloud history smoother.
Cloud & sky lighting
Physical Hillaire multiscatter as the default; multiscattering LUT switched to a
full-sphere 8×8 quadrature (fixes a single-azimuth gather that washed out the
sunset horizon) — magnitude-neutral.
Bidirectional sky↔cloud coupling, energy-conserving dual-lobe direct, Mie/aerosol
extinction in cloud+moon sun transmittance, widened daytime-light rolloff through
sunset, artistic sunset-colour knobs.
Cloud-on-terrain shadows
Cloud shadow folds per-pixel onto the SUN's radiance pre-denoise: on the surface
via the real atmosphere-sun distant light in the direct/indirect integrators
(gated on atmosphereCloudShadowed + cloudVoxelShadowsEnable), and in fog via
sampleAtmosphereSunLightVolume. This replaced an earlier screen-space
PrimaryCloudShadowFactor texture (and its geometry-compensation stack) — it is
automatically correct indoors / viewmodels / decals. Default
cloudShadowStrength = 0.5, contrast via cloudShadowFactorStrength.
Cloud motion
Unified per-frame integrator for wind advection + in-place field-evolution morph +
edge boil (offset += velocity·dt), fixing a stateless speed·timeSeconds that
snapped the field when wind changed. Clouds form/dissolve in place instead of an
earlier ~30 s global "breathing." Weather-parameter drift de-pulsed and renamed
"Weather Variation"; __weather.drift_* plugin keys unchanged.
Sun & moon as real distant lights
The sun and each enabled, above-horizon moon are injected as real RtDistantLights
driven by the atmosphere model and lit through the standard NEE/RTXDI path — the
sole sun/moon path in Numos. SSS / decals / viewmodels are handled correctly by the
unified pipeline; cloud-on-terrain shadows fold onto these lights (above). The older
bespoke atmosphere sun/moon NEE shader path was removed (~760 LOC). Also: thin-opaque
subsurface translucency (backlit glow outdoors); soft-shadow cone + physical sun/moon
angular size; directionalLightRadianceScale tuning multiplier.
Performance
Split sky-LUT cache keys; sky-view + voxel-grid re-bake granularity (re-bake on
motion step, not every frame); NEE shadow-ray budget clamps; half-res cloud render
RT; secondary-ray cloud LUT. Validated defaults pinned, workstream toggles retired.
Global changes (all sky modes)
Overlay: fixes doubled keyboard input (gates the game-wndproc keyboard fallback
on raw-input recency) — independent input fix.
Volumetrics: new volumetricConsumerGain (default 0.008) so the froxel cache
lights alpha-blended particles/decals/PSR/SAB consumers that were previously unlit;
fogSunVisibilityGain default 5.0 → 1.0; physical-atmosphere sun NEE +
cloud-occluded sky-ambient wired into the RTXDI volume integrator (submodule bump);
new "Atmosphere Sun Fog Scale" UI.
Docs & submodule
New docs/CloudSystem.md; updated weather-preset guide, fork-touchpoints.md,
regenerated RtxOptions.md. submodules/rtxdi bumped to the fork's volumetrics
commits (physical-atmosphere sun NEE, cloud-occluded sky-ambient, fog/gain knobs).

atmosphere: hex de-tiling of the cloud noise field (stage A)
…
6db68fb
```
Root-cause fix for the prebaked noise volume's periodic repeat -- the
artifact the anti-tile warp was added to hide. The horizontal plane is
partitioned into an equilateral-triangle lattice (golden-ratio multiple
of the tile period so lattice and texture can't resonate); each vertex
carries a hash-derived random texture-space XZ offset, and samples
blend their triangle's three offset taps with Heitz & Neyret 2018's
variance-preserving operator:

  G = mean + sum(w_i (x_i - mean)) / sqrt(sum(w_i^2))

Mean and variance of the field are preserved, so the cloud look is
unchanged -- but two world positions one tile apart land in cells with
decorrelated offsets, so the repeat can never show. Weights are pow-4
sharpened: triangle interiors (~70% of area) take a 1-tap fast path
(tricubic in the view sampler), only edge bands pay 3 trilinear taps.

Applied identically in sampleCloudDensityTextured and
sampleCloudDensityForShadow so the baked D_sun / D_ambient grids
shadow the same de-tiled field; the vertical-coherence footprint slice
follows the dominant vertex's offset in both. The detail-erosion tap
stays single-tap (its sub-3 km repeat is not the visible artifact).

Gate: rtx.atmosphere.cloudHexTilingEnable (default on, "Seamless
Cloud Field" checkbox; off = legacy periodic field, live A/B). Rides
the former padCloudLook0 CB slot; layout unchanged.

Stage A ships with the anti-tile warp UNCHANGED. Stage B (separate
build, after in-game validation) walks the warp down with
bake-frequency compensation -- the warp's frequency-multiplying
Jacobian is load-bearing for the tuned look and must be replaced
deliberately, not just removed.

and half-rate secondary paths both inherit:

  rtx.atmosphere.sunShadowMaxSamples   (0 = legacy uncapped, default)

The rays are already blue-noise jittered inside the sun/moon cone, so
the denoised pipeline (NRD / DLSS-RR) temporally converges one ray per

With a continuously-animating time-of-day sun, the sky-view LUT re-baked every frame: its cache key saw a new sunDirection each frame. The frozen-cascade bisect read an objective frame-time improvement, so the re-bakes were the last reducible chunk of the sky cost (the freeze itself is not shippable -- sky colors stop tracking the sun).

skyViewRebakeGranularityDeg quantizes the sun and moon directions INSIDE the sky-view cache key (component snap at the granularity step in radians), so continuous motion flips the memcmp only when a direction crosses a step -- one re-bake per ~granularity degrees of travel instead of one per frame. The bake itself always uses exact current values: every re-bake is exact, staleness between re-bakes is bounded by the step. Default 0 = legacy every-frame behavior in this commit; in-game validated at 0.1 (sky tracks the sun smoothly, no visible stepping, objective frame-time win). Default pinned to 0.1 in the follow-up defaults commit. ImGui: Atmosphere > Advanced > Sky Re-bake Granularity (removed in the follow-up; conf-tunable).

atmosphere: per-column cloud model (column-shaping rework)
…
7c51ea0
```
Root-cause rework of the "stacked separated layers" read that made the
volumetric cloud system look like flat 2D planes. Previously every
vertical shaping signal -- the height-LUT density envelope (which at
cumulus types even baked TWO density peaks separated by a thinner
neck), the coverage-threshold scale band, the anvil pow gate, the Nubis
dim profile and the bottom-darkening gradient -- keyed on the GLOBAL
slab height fraction: one vertical recipe pinned to absolute altitude
across the whole sky, every cloud cut by the same two global base/top
planes, lighting painted in horizontal bands. Meanwhile the thresholded
isotropic 3D noise placed mass independently per altitude, so a single
column could hold vertically disconnected stacked puffs. The eye
integrates all of it as stacked flat layers.

The column model gives each cloud its own identity:

* New baked 512x512 RGBA8 cloud placement map
  (cloud_placement_map_baker.comp.slang): R = Worley-cell cluster field
  (where clouds are, at cloud scale), G = per-cloud top-height jitter,
