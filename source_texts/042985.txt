# Pickasso

Pickasso is a local workbench for grayscale scientific images and volumes. Inspect linked slices and 3D views, build a voxel selection, assign it to materials, review coordinates and connected objects, and preserve named label snapshots. A Python process serves the application to your browser at `http://127.0.0.1:8787`.

Images and annotations stay on your machine. The browser assets are bundled locally; ordinary viewing, editing, picking, and export do not require a cloud service or CUDA. ETSAM inference is an optional, separately configured GPU workflow.

![Pickasso segmentation workspace with a synthetic phantom](docs/screenshots/segment.png)

## Start on Windows

1. Install **64-bit Python 3.11 or newer**, including the Python launcher.
2. Open **Start Pickasso.cmd** in this folder.
3. On first use, the launcher runs **Setup Pickasso.cmd**, creates `.venv-windows`, and installs the application requirements. This step needs access to Python package downloads. Subsequent launches reuse that environment.
4. Keep the terminal open while using Pickasso. Press **Ctrl+C** in it to stop the server.

You can run **Setup Pickasso.cmd** directly to install or repair dependencies. Setup only installs into this repository's `.venv-windows`; it does not install ETSAM or modify an existing ETSAM environment. An incompatible existing environment produces a repair message rather than being deleted.

If the browser does not open, visit `http://127.0.0.1:8787`. To choose another port, run this from PowerShell:

```powershell
.\run_pickasso.ps1 -Port 8790
```

## Start on Linux, macOS, or WSL

From this folder, with 64-bit Python 3.11 or newer and its `venv` module installed:

```bash
bash run_pickasso.sh
```

The launcher creates `.venv` when needed, installs application requirements there, and opens the browser. Windows and WSL use separate environments. If first-time environment creation reports that `venv` or `ensurepip` is unavailable, install your distribution's Python venv package and rerun the launcher.

For a different port or workspace location:

```bash
bash run_pickasso.sh --port 8790 --workspace /path/to/pickasso-workspace
```

The equivalent direct command, once dependencies are installed, is:

```bash
.venv/bin/python -m pickasso --open --port 8787
```

## A first session

Open **Import** to choose a file or enter a local path. The sample workspace contains an explicitly identified synthetic microscopy phantom; it is useful for learning the controls.

The left dock combines datasets, label objects, materials, and the current tool's properties. **Project** contains display controls; **Four views** shows linked XY/XZ/YZ slices and a real 3D scene together. Each slice has its own slider, pan, zoom, and maximize control. The dock can be resized, and display settings can be opened separately.

In **Segmentation**, choose a material and build the yellow selection with the brush, eraser, polygon, freehand outline, rectangle, connected-component tool, region grow, or intensity threshold. Refine the preview, then explicitly **Add**, **Subtract**, or **Replace** that material in the chosen scope. Selection history is separate from label undo. Lock materials whose voxels must be protected.

Use **Picking** for manual coordinates or generated candidates, with a searchable, paginated list covering every pick. **Analysis** lists connected components and label statistics. The 3D controls offer label surfaces, linked slice planes, a sampled scalar-volume preview, and maximum-intensity projection. Materials have separate 2D/3D visibility and 3D opacity.

Save a **label snapshot** to keep an immutable result alongside editable **Working labels**. View or export the saved object, or explicitly restore its labels as an undoable edit. Current picks, measurements, and calibration are kept on restore. Range selection calculations run in the background with progress, cancellation, and elapsed time in Activity.

Completed changes are saved locally. Export a `.pickasso` project to keep a portable copy of the source image, working labels, annotations, and named label snapshots.

See the [user guide](docs/user-guide.md) for tool behavior, coordinate conventions, storage requirements, and export details.

## Supported data and geometry

| Input | Behavior |
| --- | --- |
| MRC, REC, MAP | Real-valued 2D or 3D grayscale data. Axis mapping, voxel spacing, and origin are read from the header. MRCS is also accepted through local-path import. |
| TIFF / OME-TIFF | Grayscale image or first image-stack series, including supported compressed TIFFs. Multichannel/color data must first be reduced to a single grayscale volume. |
| NumPy `.npy` | Real numeric 2D or 3D arrays; object arrays and pickled data are not loaded. |
| `.pickasso` | Portable project containing the source-image copy, mask, materials, picks, measurements, notes, and named label snapshots. |

Array order is **Z, Y, X**. Coordinate tables use **zero-based X, Y, Z voxels**. Voxel spacing and physical coordinates use **nanometres**; MRC ångströms are converted on import and export. When geometry is missing, Pickasso assumes 1 nm per voxel and marks it as assumed. Set the correct voxel spacing before interpreting distances or volumes.

Mask exports are MRC, OME-TIFF, or NPY. Select Working labels or a named snapshot before exporting labels; snapshot exports use the saved geometry. Pick exports use Working data and offer CSV or a RELION-style STAR coordinate table. STAR is a generic coordinate table, **not a RELION 5 tomography optimisation set**; check coordinate base and downstream metadata requirements. JSON exports metadata. `.pickasso` includes named label snapshots, but not temporary selection state, undo history, raw job artifacts, or external model files.

## Storage and practical limits

The default `workspace/` sits beside the launchers. Importing creates a project-owned NPY copy of the image plus a `uint16` mask, which needs **2 bytes per voxel**. The original file remains unchanged. For example, a 1024³ float32 image requires roughly 4 GiB for the image copy plus 2 GiB for its empty mask, before history and exports.

Large files can be memory-mapped and browsed by slice. The source RAM cache defaults to 64 slices and a 1 GiB limit per process, shared across datasets. Load all places raw source slices and compressed label slices in browser memory for local scrolling, contrast, averaging and overlays. Linked 3D planes use the same source cache; the server maintains its own source cache. Pause, Resume, and Clear control loading. Labels have a separate 128 MiB browser budget by default. These source caches survive label edits and panel changes and are separate from processing and inference memory. Full-volume operations have no fixed voxel-count cutoff; actual memory and disk requirements depend on the algorithm. Staged masks, temporary selection history, named snapshots, imports, and exports need additional disk space; see the [storage guidance](docs/user-guide.md#storage-memory-and-history).

Browser file transfer is limited to **32 GiB per file**. Use local-path import for larger inputs. 3D previews require WebGL 2 and are bounded independently of full-resolution data. The volume/MIP preview is sampled and quantized to 8 bits; it is for visualization, while exports retain stored data precision.

## Optional ETSAM inference

Use an existing ETSAM checkout, its required checkpoints, and a separate Python environment containing its dependencies and CUDA-enabled PyTorch. Pickasso's application environment intentionally has no PyTorch dependency. The inference controls report whether the configured worker is available; installing Pickasso alone does not make ETSAM ready.

The default checkout is `~/.cache/jev-cell/ETSAM`. Worker discovery first checks `~/.cache/jev-cell/etsam-env/bin/python`; on Windows it next checks a sibling `JEV_cell_segmentation/.venv-windows/Scripts/python.exe`, then falls back to the current interpreter. These are compatibility lookup locations, not installations created by Pickasso. The ordinary application interpreter will need a separate configured worker for CUDA inference.

Pass explicit paths when your ETSAM installation is elsewhere:

```powershell
.\run_pickasso.ps1 -WorkerPython "C:\path\to\etsam-env\Scripts\python.exe" -EtsamRepo "C:\path\to\ET-SAM"
```

```bash
bash run_pickasso.sh --worker-python /path/to/etsam-env/bin/python --etsam-repo /path/to/ET-SAM
```

Keep the worker interpreter and repository paths in the same operating-system environment as the server. See the [ETSAM workflow](docs/user-guide.md#etsam-jobs) for availability and result handling.

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```
