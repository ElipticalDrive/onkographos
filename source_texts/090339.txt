Summary
Adds the isosurface theory pages, replaces the old Unit Sphere page (5.1.1) with a version that uses automesh's native marching cubes, and removes the scikit-image dependency. The change is documentation only. No Rust source changes.
Isosurface Pages
theory/isosurface/introduction.md defines isosurfacing and describes the cuberille method that mesh tri uses by default. It links to the Marching Cubes page for how marching cubes handles multiple materials.
marching_cubes.md covers the original method, its ambiguous cases, and the Lewiner variant that automesh uses. It describes how mesh tri --cubes marching builds its field, and states the caution for binary masks: at the level 0.5 tie, the Lewiner method can pinch an edge. The unit sphere does not create that case.
dual_contouring.md and the introduction spell out "Marching Cubes". The draft Status page is folded into the Marching Cubes page.
Unit Sphere
The page is now unit_sphere.md, titled "Unit Sphere". The old 5.1.1 page and its 140 supporting files are deleted.
Surfaces come from automesh mesh tri --cubes marching. For the five test spheres, the triangles are identical to the scikit-image surfaces they replace.
The page documents the transform: the translation is $-(n+0.5)/n$, because voxel $i$ spans $[i, i+1]$.
The Taubin Smoothing section is redone. The best minimum scaled Jacobian is 0.613 at 260 iterations for the uniform mesh and 0.564 at 11 iterations for the adaptive mesh. A new Quality After Smoothing figure and table compare them with the Sculpt baseline.
The Control Study compares Octa-Loop level 4 (2,048 triangles) against those best smoothed meshes. It does not beat them: the Octa-Loop minima are 0.518 uniform and 0.558 adaptive. The text notes that the smoothed results are the maximum over 135 iteration counts.
The convergence figure now comes from unit_sphere_convergence.py, which uses automesh. The Sculpt outputs, unit_sphere_sculpt_*.e.1.0, are not in the repository, as the page states.
Reproducibility
Every script was rerun in a clean directory with only its documented inputs. The five segmentations are byte-identical to the committed ones, and 14 of 15 figures are pixel-identical. The convergence figure showed the same curves with small layout shifts, and I replaced it with the clean run.
The key results reproduce on released conspire 0.8.0 with the committed code: Sculpt 6,912 hexes at 0.388, uniform 6,024 at 0.161, adaptive 8,243 at 0.086, the four control rows, and both Taubin peaks.
Verification
mdbook build finishes with no errors. All images on the page resolve, and the footnotes and figure anchors resolve.
No changed page uses cmdrun, so the CI build does not need the new Python scripts' dependencies.

Tests whether the octree's poor quality on marching-cubes surfaces comes
from automesh reading the voxel staircase as full of sharp features.
Reading conspire's octree sizing code shows curvature/crease detection is
off by default (no --tolerance), so the real signal is shape-diameter-
function local thickness. Meshing two smooth Octa-Loop surfaces with the
same default octree produces zero inverted elements at either resolution,
against 23 inverted elements at n=160 on the marching-cubes surface.

Also documents a second finding along the way: the Octa-Loop level 3
control mesh isn't symmetric despite a perfectly symmetric input STL,
traced to orthonormal_basis's Gram-Schmidt seeding from the fixed global
axes rather than the local surface, in the shape diameter function's
ray-cone sampling.

Collapses the Source section's script listings behind <details>, matching
bone.md's existing convention.

0.7.7 values until the fix ships.

The Octa-Loop level 7 mesh refines more near one pair of opposite poles
than near the other two, although the surface is symmetric under every
swap of the axes.  The cause is a second defect in conspire, separate
from the fit fix of Update 2.  The shape diameter function loses its

conspire 0.7.8 has the defect.
