That's quite true about Noise2D.
my thinking was if there is visual noise. why not audible noise.. This is not a convincing argument though.
So, why a noise resource makes sense from my perspective:
First of all there are many different colors of noise and while they may sound "indistinguishable" from one another, they have totally different EQing and applications. Pink noise could sound more like rain, where as white noise is balanced along all frequencies.
Granted this could all be done with a single white noise audio, and AudioEffectEQ to make different "colors". but adding another bus just to process white noise seems unnecessary, when it could be built into the AudioStreamNoise directly. Also, AudioEffectEQ has hard-coded bands. you cannot change the frequencies.
There are also different temporal characteristics of noise, how they are generated over time:
periodic noise: repeats after a certain interval, in godot this would be a preloaded buffer (most common)
aperiodic noise: has no repeating pattern, totally random and generated "on the fly"
impulse noise: using ADSR envelopes you can create a "one-shot" or a "swoosh" effect.
There are quite a lot more parameters that could be included with AudioStreamNoise that would have a lot of benefits over having a unique sample. It all depends on the implementation.

So I began trying to make this as an asset, but I'm already running into an issue.
To make this a custom resource, I might have to extend from one of the 3 AudioStreamPlayers. This is really not ideal.
Preferably it should all be contained in the resource. If I do:
class_name AudioStreamNoise extends AudioStreamGenerator
There is no way to access the generator playback resource from inside, which I need to push audio frames to the buffer.
I don't know how else to generate the buffer from inside the resource itself without extending a node instead. This means I will have 3 identical scripts, a regular player, and for 2D and 3D.
When it should just be 1 resource that plugs into the stream player.
this example code sort of shows how you do all this from the player, not the resource itself.
```
extends AudioStreamPlayer # added by yankscally for clarity

var playback # Will hold the AudioStreamGeneratorPlayback.
@onready var sample_hz = $AudioStreamPlayer.stream.mix_rate
var pulse_hz = 440.0 # The frequency of the sound wave.

func _ready():
	$AudioStreamPlayer.play()
	playback = $AudioStreamPlayer.get_stream_playback()
	fill_buffer()

func fill_buffer():
	var phase = 0.0
	var increment = pulse_hz / sample_hz
	var frames_available = playback.get_frames_available()

	for i in range(frames_available):
		playback.push_frame(Vector2.ONE * sin(phase * TAU))
		phase = fmod(phase + increment, 1.0)
```
