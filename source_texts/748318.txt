What
PR 4 of the Minimal Contour (MC) memory/freeze plan (after #87 bench harness, #88 gate on MC mode, #89 no image copy). FeatureManager/FeatureExtractor precomputed two float64 memmaps of the full image shape for every slice on activation (8x the image on disk, ~11x RSS, a GUI busy-wait, a new pair of files per display order). A gradient pair costs only a few ms per plane, so it is now computed lazily for the displayed plane and kept in a small LRU cache.
Three commits:
minimal_contour/plane_features.py (no Qt/napari imports) + unit tests: compute_gradients (cv2 Sobel float32, bit-identical to skimage sobel_v/sobel_h on integer data; RGB uses the existing gaussian code, moved unchanged), to_float64_pair for the Cython calculator, and a thread-safe byte-bounded PlaneFeatureCache (default 64 MB, NAPARI_ND_ANNOTATOR_FEATURE_CACHE_MB overrides; an oversize entry is returned but not cached).
MinimalContourWidget._set_image uses it (_get_gradients); cache key = (layer id, displayed dims, slice indices, data version); invalidated on layer.events.data and on layer removal. No threads, no temp files, no busy-wait.
feature_manager.py/feature_extractor.py and their exports are deleted. A small guarded clean_legacy_tmp() (minimal_contour/_legacy_tmp.py, the PID-tagged sweep of Fix persisting the Annotation Toolbox state with a Points layer #86) still removes *_nd_annotator folders left behind by older versions once at _initialize; it never raises.
Feature-mode semantics are unchanged (SYM = magnitude alone, ASSYM/intensity = image + gradients as before, CUSTOM script untouched, blur applied once to the gradient maps). ndisplay 3 and out-of-range slices still give no features; a layer that is no longer in the viewer now gives none either.
Behaviour change: transposed display orders
Gradients are computed from the plane as displayed (image_layer._data_view, raw dtype), so grad_x == sobel_v(displayed plane) and grad_y == sobel_h(displayed plane) in every dims.order. The legacy code computed them from the stored volume and then transposed, so in transposed orders grad_x was sobel_h of the displayed plane (roles swapped relative to the display). Contours in transposed orders can therefore differ slightly from before (they are now consistent with the display). Tests cover all 6 orders of a 3D array and 6 orders of a 4D array.

Disk: 0 bytes (was 8x the image per displayed-dims pair); far jump and order switch cost the same as a normal step; no CPU burst on activation; the cache is a constant 8 MB at 1024² (64 MB limit).
Warm step is +0-8 ms (features are now computed instead of read from a hot memmap), still well under 80 ms.
The remaining RSS delta is not MC feature work: selecting a labels layer touches the pages of the whole (zero) labels array (+320 MB for 150x1024², +640 MB for 300x1024², measured with MC off; the interpolation/bbox code, outside this PR), plus roughly 230 MB of plane-size working memory (float64 image, gradients and the calculator's copies; independent of Z). That is why the activation RSS delta stays above the 150 MB target on the large volumes.
Tests
test_plane_features.py (no viewer): gray gradients equal skimage sobel_v/sobel_h on uint8/uint16/float, non-square and transposed planes; RGB equals the reference math (incl. empty channels/all-zero); LRU hit/miss/eviction/byte bound/oversize/invalidate/clear/env var/read-only entries; thread-safety smoke.
test_mc_plane_features.py (headless viewer): no *_<pid>_nd_annotator temp folder; cache bounded while scrolling 100 slices; cache hits when scrolling back; feature modes reach the calculator (SYM/ASSYM/HIGH/LOW/CUSTOM script); gradients follow the display order (all 6 orders 3D, 6 orders 4D); RGB; dask and np.memmap; blur on/off (gradients blurred once); replaced image data; layer removal; ndisplay 3/out-of-range; MC contour identical for float32-derived vs float64 gradients.
test_legacy_tmp.py: dead-PID and old PID-less folders are swept, live ones kept, never raises.
test_mc_gating.py/test_mc_no_copy.py adapted (spy on PlaneFeatureCache.get, no FeatureManager).
Full suite on napari 0.9.2/py3.13: 215 passed, 2 failed in the run before the last fix-up: the pre-existing test_shortcuts.py::test_every_dialog_entry_is_actually_bound (also fails on main) and a removal test that I then fixed (a removed layer could be cached again through the labels layer's source_image_layer). On napari 0.5.6/py3.12 the full run had 142 passed, 5 skipped and only the 4D tests failing (the Minimal Surface widget is None there; fixed in the test). After the fixes I re-ran the MC test files (test_mc_plane_features, test_mc_gating, test_mc_no_copy): 49 passed on both versions. I did not re-run the whole suite after the fix-ups, and napari 0.5.0 is only covered by the CI matrix.
tools/bench_minimal_contour.py now reports a 0-file temp folder for versions without feature files.
