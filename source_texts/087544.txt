Summary
Implements clip box, Directional Occlusion Shading, gradient-magnitude opacity modulation, and TF detail controls for the WebGPU volume renderer:
Axis-aligned clip box restricting raymarch traversal to a sub-region of the loaded volume, reset to the full AABB on every volume load
Directional Occlusion Shading: a few short secondary samples toward the light per raymarch step, approximating self-shadowing far more cheaply than a full self-shadow ray march
Gradient-magnitude opacity modulation, reusing the shading gradient to suppress homogeneous-region noise and emphasize boundaries -- a scoped-down stand-in for a full 2D transfer function (the pre-integrated LUT already uses the second axis for front/back sample pairs)
Extinction and density scale turned from fixed constants into real setters, plus a new threshold cutoff
A fifth, user-defined "Custom" colormap (independent of window/level), refactoring the existing per-preset LUT bake functions into shared color-parameterized helpers so both the fixed presets and Custom go through the same code path
Stacked directly on the previous raymarch-quality PR (#45, now merged) -- rebased onto main after that merge. See engine/docs/RENDERING_SPEC.md (updated in this PR) for the full current rendering spec and this change's own entry in its history section.

Review notes
writeLutPreset/writePreintegratedLut (from the previous PR) were split into thin per-preset wrappers over new writeLutColors/writePreintegratedLutColors helpers, shared with setCustomColormap -- avoids duplicating the LUT-baking logic for a 5th, non-indexed preset. ColorRGB moved from WebGPUDevice.cpp's anonymous namespace into WebGPUDevice.hpp so both the fixed-preset table and the new helpers' signatures can reference it.
UI bug found while adding the new panel sections (not by visual inspection -- a new e2e test failed with "element outside of the viewport"): the control panel had grown tall enough (Rendering, Window & Level, TF Detail, Clip) to exceed the viewport height on shorter screens with no way to reach the lower controls. #control-panel now scrolls internally (max-height/overflow-y: auto) instead of overflowing uncontactably past the bottom edge.
Deliberately out of scope: path tracing, full self-shadow ray-marching (Directional Occlusion Shading covers the same need at much lower cost, per the gap-analysis document's own note), a full 2D transfer function with gradient magnitude as a genuine second classification axis -- see engine/docs/RENDERING_SPEC.md §1.4a/§1.10 for why.
