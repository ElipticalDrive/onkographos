Context
The streaming substrate already exists: shipped games use per-scene .vpak layers with MountLayer/UnmountLayer in Editor/Core/Services/AssetVfs.cs, and GameExporter produces a core Assets.vpak plus lazy Scenes/*.vpak (Editor/Core/Services/Build/VortexPak.cs). But mounting is synchronous and scene-granular — verified gap: "no async level-chunk unloading/streaming for seamless world traversal." SceneManager (Engine/Runtime/SceneManager.h) handles create/destroy/activate but nothing loads in the background. A horror mansion where the east wing loads while you walk the corridor is impossible without a loading screen today.
Goal
Streaming volumes: box triggers placed in the editor that asynchronously load/unload scene chunks (entity sets + their pak layers) on a background thread, with activation fenced to frame boundaries so the world streams in without hitches or half-initialized entities.
Acceptance Criteria
StreamingVolume component (box extent, target chunk, load/unload distances) editable in the editor with gizmo visualization
Scene chunks authored as sub-scenes; exporter packs each into its own .vpak layer
Background thread performs pak mount + deserialize; main thread only activates (fence at frame boundary)
No frame longer than 2x average during a chunk load (measured with existing FPS telemetry)
Unload frees chunk entities + unmounts the layer; re-entering the volume reloads correctly
Works in editor play mode and shipped Release builds
Technical Notes
Fixed 1/60s timestep loop (StepRuntime in VortexAPI/Api/RuntimeApi.cpp) is where activation fences belong
Reuse the on_scene_switch() GPU-flush hook pattern in DX12Renderer.h for resource-safe activation
Script hook: OnChunkLoaded event for gameplay (spawn logic per wing)
Dependencies
core: async asset streaming — textures & meshes on demand (shared background-load infrastructure; can land in either order but should share the worker design)
