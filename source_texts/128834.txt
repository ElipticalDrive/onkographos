Summary
UsdGeomCamera.projection was never read, so a camera with projection = "orthographic" rendered as a perspective camera with the same lens, and nothing warned.
An orthographic camera now generates primary rays parallel to its −Z axis (Camera::orthographic). Each ray starts on a window whose size is the conformed horizontalAperture × verticalAperture in tenths of a scene unit. The window is centred on the camera's position, moved by horizontalApertureOffset / verticalApertureOffset, which are also in tenths of a scene unit. focalLength, fStop and focusDistance play no part, so there is no depth of field. A projection token other than orthographic reads as perspective, as in USD.
Every reader of the projection follows it:
CameraFrame::proj drops the perspective divide, and motion_vector skips its near clip, which an affine projection does not need. A non-finite hit still reads zero.
The primary ray cone is one pixel wide and does not spread (Camera::primary_cone).
Adaptive dicing and implicit-shape sizing use a pixel rate that doesn't change with distance and a box-shaped view volume (Frustum::orthographic). The box moves with a shifted window, and lens shift's off_axis_gain doesn't apply to it.
Camera clipping (UsdGeomCamera clippingRange and clippingPlanes are ignored #391) needs nothing of its own. clippingRange is measured along the view axis from the camera's position, which is the plane the orthographic rays start on.
depth and distance keep their documented meanings: depth is measured along the view axis, and distance is Euclidean from the camera position. Off axis, an orthographic hit's distance is therefore larger than its depth.
The branch is rebased onto main (at e4a9a114) as two commits:
The feature, composed with Unauthored verticalAperture frames narrower than USD on wide images #388's conformed vertical aperture, lens shift (UsdGeomCamera aperture offsets are ignored #390, Honour UsdGeomCamera aperture offsets (lens shift) #399) and clipping (UsdGeomCamera clippingRange and clippingPlanes are ignored #391).
The fixes from the Qodo review.
Perspective cameras take main's code unchanged.
Closes #389
Capability
usd-scene-import, aovs, rendering (ray cones). I updated openspec/specs/usd-scene-import/design.md: a new "Orthographic projection" entry, including how it combines with lens shift and clipping, plus the adaptive-dicing note that said orthographic "does not arise". I also added an "Orthographic projection" requirement, with an offset scenario, to its spec.md. The spec was edited in place, as a bug fix, rather than through openspec/changes/. Say if you want it moved into a change.
Image impact
Bit-identical for perspective cameras. Partial evidence: I did not run scripts/check_images.sh. samples/cornellbox.usda at -s 16, rendered with release builds of main and the first version of this branch, gives crust diff: 0/230400 differing pixels, max abs diff 0. That comparison was made before the rebase onto lens shift and clipping. The perspective arithmetic in get_ray, the ray cone, proj and motion_vector is unchanged, the frustum test >= -0.0 is equivalent to >= 0.0, and the perspective lens-shift and clipping code is main's as is.
Orthographic cameras change intentionally (they were wrong before). A 200×200 render of a 10 × 10-unit window shows two unit spheres at the same 20 px radius, 35 units apart in depth.
Performance
No claim made. Perspective adds one well-predicted branch in get_ray and in the cone construction per camera ray. Not measured.

Description
```
The new orthographic branch of motion_vector projects both ends of the path with cam.proj and
returns the difference directly. The perspective branch returns (0, 0) for a hit point that is not
finite, but the orthographic branch never checks and passes the NaN through to the motion-vector
AOV.
```
Code
crates/crust-core/src/aov.rs[R817-821]

+    if cam.orthographic {
+        // An affine projection: every depth projects, and nothing is clipped.

+        return ((s1 - s0) * cam.width, (t1 - t0) * cam.height);
+    }
```
Evidence
```
The perspective branch returns (0, 0) when the depth is NaN. The orthographic branch has no
equivalent guard and returns the raw projection difference.
