Use curvature-aware surface intersections for surface-array lookup, navigation-stream candidates, and stepper target checks, so bending tracks can reach sensors missed by ray estimates. Plane, disc, and cylinder implementations reuse ray calculations and check bounds at the corrected crossing.
First order is the default; an internal compile-time switch selects a quadratic local-parabola solve against the seed tangent plane. Both share correction math and guards, with shape-specific helpers in Acts::detail and exact radial projection for cylinders. Neither mode is an exact helix intersection. Unsupported surfaces and unreliable corrections fall back to rays; neighbor-window sizing is unchanged.
Stacked on #6401 (API plumbing); merge that first, then retarget to main.
Validation: all 9 curvature tests pass (253 assertions), and the surface-intersection benchmark builds and runs against the production API. Integration validation also included navigation/propagation tests and 480,000 comparisons with the benchmark prototypes. Cylinder/disc merging tests require a logging-threshold build option absent from the local configuration.

```
…oject#6401)

Extend the curvature wiring from acts-project#6371 through the navigation
intersection interfaces. This is the prerequisite for acts-project#6400; the
intersection geometry in this PR remains straight-line based.

- Carry curvature through the surface-array lookup arguments and
navigation-stream query points.
- Add an optional curvature argument to single-stepper
`updateSurfaceStatus` methods. The shared implementation accepts it but
still runs the existing ray intersection.
- Add error-returning target checks for MultiStepperLoop and
RiddersStepper, with curvature queried independently for each component.
Update propagator call sites to propagate lookup errors, retaining
compatibility with custom steppers using the original status API.

The new API is exercised before the correction algorithm is introduced:
tests record the dispatched curvature, cover field failures and legacy
signatures, and confirm that a bounded ray miss stays a miss. Existing
intersection/lookup behavior remains unchanged, though the new
target-check path can perform additional curvature queries and report
their errors.
```
