Summary
The editor gizmo's Points preview drew a crosshatch of long white lines over every GaussianSplatNode3D, selected or not (#1220). Three changes, each removing one cause:
Selection gate. GaussianSplatGizmoPlugin::redraw() draws the Wireframe/Points/Heatmap preview only while the gizmo is selected, through the new should_draw_splat_preview(node, selected).
Default Off. debug/debug_draw_mode now defaults to DEBUG_DRAW_OFF instead of DEBUG_DRAW_POINTS.
Robust cross size. The cross half-arm is 1 % of the longest axis of the 5th–95th percentile box of the sampled preview points (compute_preview_cross_half_extent()), not 1 % of the floater-inflated node AABB.
The starter template no longer sets debug/debug_draw_mode = 2, and scripts/main_scene.gd sets DEBUG_DRAW_OFF to match the scene.
Linked task / issue
Refs #1220 #1213
#1213 (robust bounds for the template camera) is the same floater problem in another consumer. This PR does not touch it: the gizmo computes its own percentile box from its at most 1000 sampled points, which is cheap and local. A shared robust-bounds helper, if #1213 adds one, could replace it later.

Design and evidence (at base ab74e332aa8)
Cause. editor/gaussian_splat_gizmo_plugin.cpp:131-134 drew the preview whenever preview_enabled was set and the mode was not Off, with no selection check. :354 set cross_size = MAX(0.01, aabb.longest_axis * 0.01). :356-376 drew up to 1000 three-axis crosses. Defaults were preview_enabled = true and debug_draw_mode = DEBUG_DRAW_POINTS (nodes/gaussian_splat_node_3d.h:275,284), and the template set mode 2 (templates/gaussian_splat_template/scenes/main.tscn:44). On the maintainer's 8M-splat scan the AABB is 2937 × 5255 × 2567 m, which made every arm 52.5 m.
1. Selection gate. This follows upstream practice: GeometryInstance3DGizmoPlugin, the particle gizmos and LightmapGIGizmoPlugin draw their helpers only when p_gizmo->is_selected() is true (editor/scene/3d/gizmos/geometry_instance_3d_gizmo_plugin.cpp:53, gpu_particles_3d_gizmo_plugin.cpp:64, lightmap_gi_gizmo_plugin.cpp:83). This plugin already gated the bounds box the same way (gaussian_splat_gizmo_plugin.cpp:117). Node3DEditor::edit() calls set_selected() and update_gizmos() on both the old and the new selection (editor/scene/3d/node_3d_editor_plugin.cpp:6947-6984), so the preview appears and disappears on selection change with no extra wiring.
2. Default Off. A scene file stores a property only when its value differs from ClassDB::class_get_default_property_value(), which instantiates the class. What changes for users:
A scene saved while Points was the default has no debug_draw_mode line, so it now opens with Off. To get the old preview back, set Debug > Debug Draw Mode to Points (or Wireframe or Heatmap) and select the node.
A scene that stores an explicit value keeps it. That includes mode 2 in an older copy of the template, and debug/debug_draw_mode = 3 in tests/examples/godot/test_project/scenes/testlevel.tscn.
Runtime rendering does not change. The node forwards the mode to GaussianSplatRenderer::set_debug_preview_mode(), but the renderer only acts on DEBUG_PREVIEW_DEPTH (renderer/render_debug_state_orchestrator.cpp:813), which the node enum cannot select. get_statistics()["debug_draw_mode"] now reports 0 for a default node.
runtime_preview_restore_mode defaults to Off as well, so its fallback matches the new default.
The alpha carries no API stability promise (docs/development/api-stability.md, maintainer decision 2026-09-27, documented by docs: state the no-API-promise where the API and settings references live (#1010) #1070), so there is no migration shim.
doc_classes/GaussianSplatNode3D.xml already says default="0" for this member. It was stale before this PR and is now correct, so the XML is not touched (gaussian_splatting: harden audited render, streaming and CI contracts #1195 also edits that file).
No project-settings manifest entry is involved, because this is a node property, not a project setting.
3. Robust size. The new half-arm is the per-axis 5th–95th percentile of the same strided ≤1000 points the loops draw: after sorting each axis, count / 20 samples are dropped at each end (since 73530d6b3e8; before it, ceil(0.95 * (count - 1)) kept one floater when exactly 5 % were on one side). Non-finite points are skipped, and the size is never below 0.01. Predicted from the PLY's stride sample of the real scan: 0.086 m instead of 52.5 m (robust extent 8.6 m). Its allocation goes through gs_resize_or_fail(), which the unchecked-resize guard requires.
User-visible behavior
A new or default node draws no preview crosses, selected or not.
With Wireframe, Points or Heatmap chosen, the preview draws only while the node is selected. Points and Heatmap crosses are sized to the scan's core, not its floaters.
Existing scenes that relied on the old default open with Off (see above).
Godot upstream delta
None. Only module files change. The upstream gizmo API (EditorNode3DGizmo::is_selected()) is used as-is.
