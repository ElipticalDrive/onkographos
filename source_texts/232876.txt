Part of #79
Brings the GPU scene renderer much closer to the software rasterizer, which remains authoritative. Lavapipe uses the same llvmpipe code as the software path, so most of this work feeds the GPU exactly the inputs the software path feeds its rasterizer. Where that holds, the output is now bit-exact.
What changed
Near plane and culling (gap 1)
mesh.vert receives all four corners of each packet. Every vertex of a packet computes the same per-object view transform as the software path (render::object_view, i.e. RefProjection).
The whole packet is dropped when any corner is inside the near limit max(2·fov, 1).
The packet is culled on its first three corners using the software's screen-space area test. The mirror pass stays unculled.
The rasterizer's back-face culling is no longer used.
Projection and depth
Positions use the software's exact screen formula, including shake.
Depth uses the software's linear ramp (z − 1) / 131071 instead of a perspective depth.
Shading (gap 2)
UVs are now normalised and interpolated perspective-correct, with PSXObject_Store's degenerate-corner nudge and the software's texel clamp.
Shade is passed in 0..1 and interpolated perspective-correct. Colours are rounded like unorm8.
The blend alpha is rounded to unorm8.
Shadows are sampled with llvmpipe's 8.8 fixed-point bilinear filter.
Effect colour and alpha come from the same EffectQuad::colour the software uses.
Mesh lights honour light_pos.
Blending
The palette alpha now means "this entry blends under a blending packet". That is every entry unless the row has a knock-out twin, in which case only STP entries blend, matching rasterize.
Transparent records (blend_weight) override the per-packet blend and are full-bright, as in software.
Visibility vs painter's sort (gap 3)
Masks no longer write scene depth. A depth-only D16 pass first stores the nearest mask's painter's key for each pixel.
mesh.frag and sprite.frag then discard a triangle or shadow whose key is at or behind that mask key, and an effect whose key is strictly behind it. This is exactly the painter's rule from the software sort.
Each mesh triangle's key (its corners' mean view Z, rounded) is computed in the vertex shader.
Measurement test
gpu_scene_matches_software_in_real_rooms now also reports how many pixels are not exact.
It accepts ARKLAY_GPU_TEST_ROOMS=<room>,<room>,… to measure other rooms.
Its budget is tightened from 10% to 0.5% of pixels.

What's left (why this is "Part of")
Shadows and effects vs meshes. Software paints a shadow over farther mesh triangles, and paints effects in painter's order against meshes. The GPU uses the depth buffer for both (1000-2 near the hand, 106's feet).
Overlapping blended meshes. These blend in mesh order rather than in sorted order. Overlapping water layers in 3010, 5130 and 7000 come out ±1.
4110. A full-frame tint overlay is not part of the scene comparison. Saturating overlays (gap 4) are not addressed.
Unhandled mesh features. The GPU path still ignores complex_object, per_joint_light, aliased_light, light_rotation and joint_colours. Meshes using them still differ.
MSAA mask edges. Mask keys are per pixel, so with MSAA on, a mask's edge is not antialiased against what it hides.
Performance
Mesh vertices grow from 48 to 84 bytes.
The vertex shader does four view transforms per vertex.
Each frame adds one small depth-only pass that draws only the masks.
Each mesh and sprite fragment does one extra texelFetch.
Per-mesh uniforms are now built once per frame instead of once per blend pass.
None of this should be noticeable.
The SPIR-V was regenerated with src/gpu/shaders/build.sh.
