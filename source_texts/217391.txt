Thanks for raising this @imagejan
Maybe also offer projecting along x or y? (Generalize to "select one or multiple axes".)
There has been initial work by @clacrow on more complex projections e.g. along Y or X in this PR: #1016
We've ruled this to be out-of-scope for the fractal-tasks-core version of the task, as it introduces significant additional complexity to the task for a feature where we don't yet understand the common use-case. Nothing against tasks like this existing of course, but it goes beyond what we'd intend to cover in tasks-core.
For time series, allow projecting along z or t axis or both.
That's an interesting feature. Are time projections a common need? Nothing against having time project tasks.
One complexity here: The current design of the task includes that it only handles 3D inputs and its outputs are always 2D, as part of the task list & task manifest. That's a static setting and Fractal currently doesn't have a feature to make dynamic output type filters based on task parameters anymore, as it added major complexity and was barely used. Would be interesting in future Fractal V3 discussions to see if this would have a space.
For now, I'd suggest making this a standalone task if there is demand for it. I'd be open to include a time projection task in tasks-core in a PR.
For multi-channel data, we'd like to create maximum intensity projections for fluorescence channels, but minimum intensity projections for transmitted light, for example. Offer an optional (channel => method) mapping.
I understand the use-case. Here, I think it's mostly a UI/UX question. Can we offer such flexibility without making the interface much more complex for the regular case? The newer task models, e.g. the discriminator union models for different project modes, could allow for this. We could introduce a new "mixed" projection mode. In that mixed projection mode, we'd specifically ask for channel => method mapping.
It would need significantly more complex handling to ensure edge-cases are covered (e.g. can channels be selected just by label or also by wavelength id? Do all channels need to be specified? Handling e.g. double specification etc.)
Depending on the complexity such an approach would add to the regular golden path, I'd be open to have this in tasks-core as a PR or would suggest putting this into a standalone task package.
