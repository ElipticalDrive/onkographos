Add rendering, audio and persistence
…
fa7dc12
```
The world you can see and hear, plus the world that survives closing
the tab.

Rendering:
- Height-field mesher with voxel ambient occlusion and baked cliff
  shading, an order of magnitude lighter than full voxel meshing
- Season tinting done in a shader via a per-vertex response weight, so
  a whole year passes without re-meshing the island
- Water that samples the height field as a texture to draw its own
  shallows and a foam line along the beach
- Instanced props, one draw call per kind, trunks and foliage split so
  autumn recolours the leaves and not the bark
- Buildings assembled from boxes, clipped at their build height so they
  rise out of the ground, with an unlit glow pass for windows and fire
- Villagers as Y-billboarded pixel sprites drawn to canvas at runtime:
  four facings by six poses, generated per villager from six integers
- Sky dome, orbiting sun, drifting voxel clouds, stars, and seasonal
  particles (leaves, snow, rain, fireflies)
- Touch camera: one finger orbits, two pinch/pan/twist, tap selects

Audio: fully synthesised. A generative pentatonic pad with a sparse
pluck line, noise beds for wind and surf, and birds, crickets, chatter
and fire that fade up as the camera pushes in.

Persistence: seed plus deltas in localStorage, and offline catch-up that
replays up to eight hours when you come back.
```

```
Completes the game: everything the player actually touches, plus the
bugs that only show up once it is running on a screen.

Interface (hand-rolled DOM, no framework):
- HUD with resources, storehouse capacity, clock, season and speed
- Build drawer and Favor drawer, thumb-sized and inside the safe area
- Villager inspector: portrait, traits, needs, friendships, and the two
  things you can do about it
- Title card, settings sheet, welcome-back summary, toasts
- Pixel icons drawn as merged SVG rects, sharp at any density

iPad shell: viewport-fit=cover with safe-area insets, touch-action none,
standalone Home Screen meta, web manifest, generated icon set, and a
service worker so an installed haven opens with no network.

Fixes found by running it:
- Terrain top faces were wound clockwise, so the whole island was being
  backface-culled and you were seeing sky through the ground
- The ocean drew over the land; it now discards above the waterline and
  fades its foam into the sand
- Villager billboards took their light from a camera-facing normal, so
  everyone turned into a black silhouette when backlit; normals are now
  pinned to +Y and they take the same light as the grass
- Touching the canvas collapsed the build drawer, which also cleared the
  armed blueprint, making building impossible
- Blueprints were placed blind on touch: a single finger now aims the
  ghost and lifting places it
- Autumn barely registered as a multiply, so seasons gained a blend
  target; night was near-black and is now moonlight you can see by
- Heights are blurred before quantising, so terraces read as carved
  steps instead of corduroy; forests thinned and spaced so villages have
  somewhere to go and villagers can path through the woods

Also: a full-storehouse nudge, since that is the one state where
everybody visibly stops working.

Tests: 31 unit and integration tests, plus a headless-Chromium smoke
test that boots the built game, places a cottage by press-and-drag, runs
it, and checks the save survives a reload. CI runs all of it; a second
workflow publishes to GitHub Pages.
```

```
The deploy workflow only triggered on main, so with everything sitting
on a feature branch it had never run once and there was nothing to open.
It now also runs on this branch, and configure-pages enables Pages
itself, so the first deploy needs no settings toggle found first.

The browser smoke test failed on the pull_request run and passed on the
push run at the identical commit, which is the signature of a test that
depends on timing rather than behaviour. Two causes, both real:

- It pressed at one fixed screen point and hoped the ground there took a
  3x3 cottage. Which patch of ground is under that point depends on
  where the camera had eased to, and the camera eases one rendered frame
  at a time - on a software-GL runner there are very few of those. It
  now waits for the camera to arrive and tries a spread of spots, still
  through the real press-slide-release path.
- It slept a fixed 22 seconds and assumed a gather cycle would finish.
  How much world time a wall-clock second buys also depends on frame
  rate, so it now polls for the cycle to complete instead.
```

…
2507542
```
`npm run build:single` inlines the bundle, the stylesheet and the icons
into one ~650 KB .html with no external requests, verified: a fresh
load makes zero network requests after the page itself.

It exists because getting the game onto a tablet should not require a
host, an account or two repository settings. The file runs from a file
share, a mail attachment, or anything that will serve a single page.

Building with SINGLE_FILE=1 drops code splitting so there is one chunk
to inline, and defines __SINGLE_FILE__ so the service worker
registration is skipped - there is no sw.js beside a standalone file,
and nothing to cache that is not already in the page.
```

Let the village mature: trails, skills, tools, smoke
…
da5ffbe
```
Four systems, each one a way the haven visibly changes the longer you
leave it running.

Desire paths. Every step wears the ground a little and wear fades, so
routes that get walked often enough turn into trails: quicker to cross,
cheaper for A* to route along, and therefore walked more. Paths appear
between the storehouse and the woods because that is where people
actually go, and the grass grows back over the ones they abandon.
Rendered as decals laid above the terrain rather than baked into it -
re-meshing the island whenever a patch of grass darkened would hitch,
and a decal can fade in, so a path arrives as thinning rather than a pop.

Skills. Every job has a proficiency that grows with practice and slows
as it rises, paying out in speed, in yield, and in what a villager
chooses to do next. After a few in-game weeks the haven has a forester,
a mason and a builder nobody assigned, and the inspector names them.

Tools. The Workshop finally has a job: wood and stone in, tools out. The
Longhouse and the Shrine need them, and a stocked toolshed makes
everyone quicker at everything, capped so it never becomes the only
thing worth doing. The Storehouse and the Well deliberately do not need
tools - you want both long before you have a workshop, and gating them
would strand a new haven.

Smoke, and grass. Chimneys smoke only in houses somebody lives in, so
the skyline tells you how full the village is. Tufts of grass over the
open ground, which thin out where a path has been worn.

Also hardens the resource ledger: a resources object missing one line
used to turn every total, every demand figure and every villager's
decisions into NaN. It now degrades to zero and heals on first write.
```

Make the player a god rather than a foreman
…
262998b
```
Placing blueprints made you a site manager. You now move earth, and the
village reads the result and decides for itself what to build.

The build menu is gone. In its place are three earth-moving tools -
raise, lower, flatten - with a brush size, paid for in Favor, which a
contented village earns faster than a miserable one. Heaving ground
uproots whatever was rooted in it, and the timber and stone go to the
stockpile, so reshaping the land is also clearing it.

A planner decides what the village wants next - somewhere to sit of an
evening, beds, food that will stretch, shelves that are not overflowing
- and then looks for somewhere to put it. Site selection is where the
player's influence actually lands: they will only build on flat, dry,
unoccupied ground near where they already live, so flattening a shelf is
an invitation and raising a ridge is a refusal. Each site carries its
reason into the event log, so you can see what they think they need.

Two things fell out of building it:

Climbing is capped at one voxel but dropping is not. Without that, a
spire pulled up under somebody's feet stranded them there for good. With
it, raised ground is a wall in one direction only, which is both
physical and a better mechanic than a wall in both.

The island is meshed in chunks. Sculpting is a continuous gesture and a
full re-mesh measured 25ms, a visible hitch on every stroke; only the
chunks an edit touches are rebuilt now, with a per-frame budget so a
wide brush spreads over a few frames instead of dropping one.
```

Fix a broken single-file build, and stop it shipping again
…
2191de7
```
The published build did not boot. The cause was in build-single.mjs: it
inlined the bundle with a *string* replacement passed to String.replace,
where `$&`, '$\`', `$'` and `$<` are references to parts of the match. A
minified JavaScript bundle is full of those sequences, so inlining it
spliced the surrounding document back into itself - the script tag ended
up in the output four times, and a `${t}` from the icon helper's template
literal leaked out of the bundle and into the markup as an SVG attribute.

A replacement function receives the text verbatim, so everything now
goes through one, including the icon data URIs.

This was latent from the day that script was written and only fired when
the bundle grew a `$` sequence in the wrong place, which is exactly the
kind of bug that ships. So the build now checks its own output and exits
non-zero if anything external is still referenced, if the bundle appears
more than once, or if a template placeholder has escaped into markup -
and CI runs it.

The verifier looks at markup with script bodies stripped, because the
bundle legitimately contains things that look like markup: the icon
helper builds SVG out of a template literal.
```
