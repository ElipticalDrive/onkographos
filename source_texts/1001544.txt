Is your feature request related to a problem?
Currently, mipmapping is only supported for static textures and does not work with dynamic textures (surfaces), which is where it would be most useful in VFX.
In a fragment shader, we can't set the mip-level manually with texture2DLod, so we have to use the bias in texture2D(tex, uv, bias). It's not ideal, but it works. Yet this still doesn't work with surfaces.
Describe the solution you'd like
With proper mipmapping support, we can do a Depth of Field effect like this with just one texture sample!

That's one way to do it. Another possibility is to have an "updated" bool which is set to false every time you draw the surface and regenerates the mipmap chain anytime you try to access the surface through directly drawing it, or using it as a sampler (only necessary when mipmapping is enabled). Based on how engines like Unity and Unreal Engine successfully handle dynamic texture mipmapping, I'd like to propose a solution that offers developers explicit control.
The most robust and common approach in these engines is to provide a dedicated API call for mipmap generation.
Introduce a surface_generate_mipmaps(surface_id) Function:
This function would allow developers to manually trigger mipmap generation for a specified surface.
This mirrors Unity's RenderTexture.GenerateMips() and similar functionalities in Unreal. It puts the control to developer's, allowing to decide the precise moment to generate mipmaps after they've finished drawing to the surface. This eliminates synchronization issues and ensures the mipmaps are based on the final, up-to-date content, while also avoiding unexpected performance costs from automatic generation.
Example Usage: After rendering your scene onto my_scene_surface, you would simply call
surface_generate_mipmaps(my_scene_surface). When my_scene_surface is then used as a texture in a shader for post-processing effects (like bloom or Depth of Field), its mipmaps would be correctly available and optimized.
Optional Mipmap Flag During Surface Creation:
When creating a surface (e.g., with surface_create()), an optional argument could indicate whether that surface should support mipmapping. This allows to allocate the necessary additional memory only for surfaces that will actually utilize mipmaps, optimizing resource usage.
Example: my_surface = surface_create(width, height, true); (where true enables mipmapping support for this surface).
