# Controlled evaluation of loss reweighting under adaptive density control in 3D Gaussian Splatting

Training patches, experiment drivers, and analysis code for a study of how a modified
training loss interacts with gradient-threshold density control in 3D Gaussian Splatting,
and of the controls available for separating the two.

This repository contains code and aggregated statistics only. Raw training outputs
(hundreds of gigabytes of checkpoints and renders) are not included; every number the
analysis scripts produce can be regenerated from them.

## Layout

| Path | Contents |
|---|---|
| `code/train_cvar.py` | Trainer with the gradient-routing controls, the per-view and per-pixel reweighting recipes, and the density-controller probe |
| `code/aggregate_*.py` | Scene-clustered BCa aggregation for each experiment grid |
| `code/verify_adam_equivalence.py` | Numerical verification that the controls reproduce the weighted objective under the trainer's own per-attribute Adam configuration |
| `code/densification_trace.py`, `code/densif_fidelity.py` | Growth-schedule reconstruction from controller event logs |
| `code/gen_*.py` | Result tables, generated from the frozen analysis JSONs |
| `scripts/sched.py` | VRAM-aware job scheduler for two devices |
| `scripts/*.sh` | Experiment grid drivers |
| `figures/` | Figure-generation code |
| `analysis/` | Frozen aggregate statistics the tables and figures are built from |

## Requirements

Python 3.10, PyTorch 2.0.1 (CUDA 11.8), `gsplat` 1.5.3, and the Mip-NeRF 360,
Tanks and Temples, and Deep Blending datasets.

## Configuration

Scripts read their paths from the environment rather than hard-coding them:

```bash
export PROJECT_ROOT=/path/to/this/checkout
export DATA_ROOT=/path/to/datasets        # expects 360_v2/ and tandt_db/ beneath it
export GSPLAT_EXAMPLES=/path/to/gsplat/examples
export CUDA_HOME=/usr/local/cuda-11.8
export PYTHON=python
```

## Reproducing the analyses

With training outputs under `outputs_main/`:

```bash
bash scripts/finalize.sh      # runs every aggregation, regenerates every table
```

Individual grids:

```bash
python code/aggregate_main.py --base outputs_main \
    --arms mixed:pixel_mixed decoupADC:pixel_decoupADC --resources
python code/aggregate_adc_probe.py --base outputs_main \
    --arms probeVanilla probeMixed probeDecoup probeCompmatch
python code/verify_adam_equivalence.py     # CPU only, no training required
```

## Scheduling

`scripts/sched.py` reserves each job's measured peak VRAM, charges trainings it did not
start against the same budget, and gates launches on measured free memory. Peak estimates
come from `analysis/mem_table.json`, which `code/build_mem_table.py` rebuilds from
completed runs.

```bash
python scripts/sched.py --jobs jobs.tsv --out outputs_main
```
