Follow-up to #46, which adds AtmosphereSkyMaterial, a physically based sky. That PR doesn't apply atmospheric haze to scene geometry (aerial perspective), so distant objects don't pick up the in-scattering and extinction the sky shows.
Proposal
Follow Hillaire 2020, section 5.6:
Each frame, compute a small camera-aligned froxel volume (for example 32×32×32) holding in-scattered luminance and transmittance. It reuses the material's transmittance and multiple-scattering lookup tables and the same integrate_scattering model.
Sample it in the Forward+ and Mobile scene shaders, the same way volumetric fog is applied, as color * transmittance + inscatter.
Enable it only when the Environment's sky uses AtmosphereSkyMaterial, possibly with a toggle or strength on the material.
Scope notes
Unlike Add AtmosphereSkyMaterial, a physically based atmospheric sky #46, which only adds new files, this has to touch upstream renderer code: the scene shaders and the render passes for both renderers. Keep those edits small, as hooks into new files, so upstream merges stay easy.
Compatibility renderer: not needed.
Workaround until this lands: enable Environment fog with fog_aerial_perspective = 1.0. Objects then take on the sky's color with distance, but it isn't physically matched.
