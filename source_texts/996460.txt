Description
The code and this description were written by an AI agent (Claude Code, Claude Opus 5.5) while porting a LAN BedWars server to Pumpkin. The combined branch bedwars-pvp-fixes was play tested with real clients.
Block reads in unloaded chunks return air and writes are lost, so a plugin that inspects or edits an area without players nearby fails silently (BedWars on a map whose lobby is 380 blocks from the beds: no bed found at round start, no shops, no drops). /forceload cannot help for plugin-created worlds, which all use the dimension name minecraft:overworld and cannot be targeted by commands. This adds world.set-chunks-forced(corner-a, corner-b, forced) and world.is-chunk-loaded(chunk-x, chunk-z). Besides World::forced_chunks, which only marks chunks as simulated, it adds a force ticket for each newly forced chunk and removes it on release, like the TicketType.FORCED ticket of vanilla ServerLevel.setChunkForced. Loading stays asynchronous, so the plugin polls is-chunk-loaded.
The /forceload command has the same missing ticket and is left unchanged here.
Testing
cargo fmt, cargo clippy --all-targets --all-features and cargo test on the affected crates (CI package selection).
tests/specs/03-map-mansion.test.js (through map-smoke.js) on the combined branch: the plugin forces the arena chunks at load and waits for them. The spec checks the beds at their configured positions, the shop villagers and the spawner drops on the Mansion map.
Not checked: the branch on its own; the specs and the play test ran on the combined branch.
In game: force an area far from every player, wait until is-chunk-loaded is true, set a block there, fly over, expect the block.
