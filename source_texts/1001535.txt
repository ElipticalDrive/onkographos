Summary
Separate follow-up to #2025, tracked in #2027. Resolving an MRT base level must not regenerate caller-authored higher mips when automatic generation is disabled.
Append optional autoGenerateMips: boolean[] after the existing layers and explicit-depth arguments. Each entry controls its corresponding color attachment. Omitted flags preserve legacy automatic generation, and single-framebuffer behavior remains unchanged. Invalid flag types and attachment counts throw explicit errors.
Using per-attachment flags avoids overwriting an authored chain when another attachment legitimately needs automatic generation. Mip allocation and the existing format/base-level capability checks remain separate.
Companion Babylon.js PR: BabylonJS/Babylon.js#19120
Both changes are needed to forward and honor the intent. This PR does not pin an unpublished Babylon.js revision.

## Summary

Coordinated follow-up for
BabylonJS/BabylonNative#2027.

Forward each color texture's `generateMipMaps` intent through the
optional ninth native MRT argument. Preserve authored mip storage
without automatic regeneration in regular and layered MRTs, frame graph
targets, explicit-depth attachment, and sample-count reconstruction. The
legacy single-target fallback forwards the first color's flag without
shifting layer/mip arguments.

Include generation policies in layered and shared frame graph
framebuffer compatibility checks, so changing intent cannot reuse a
framebuffer with stale generation flags. Existing argument positions and
older-runtime behavior remain compatible.

Companion BabylonNative PR:
BabylonJS/BabylonNative#2028

Honoring the new MRT argument requires the companion Native runtime
change; older runtimes continue their existing behavior.

## Verification

- Added focused mip-policy regressions, including nine review-follow-up
cases; all **101 ThinNativeEngine tests** pass. The initial regressions
fail without the forwarding change.
- All required repository commands pass: `format:check`, `lint:check`,
`build:source`, `lint:advisory`, and `test:unit`.
- Full unit suite: **551 files passed; 8,272 tests passed**, one
expected failure and 34 skips.
- Built and exercised a focused devhost scene in a real browser,
checking mixed attachment flags and legacy fallback argument positions.
Removed the temporary scene changes and stopped the server.
- Built the changed Babylon.js 9.34.0 bundle and ran it with the paired
Native build on real Metal: **180 post-render readbacks passed**,
covering RGBA8/RGBA32F, disabled/enabled/mixed generation, regular/frame
graph/layered MRTs, explicit depth, and MSAA reconstruction.
- Replayed 13 previously recovered Native rendering cases with the
paired runtime: **13 passed**, no missing references.

No image references, tolerances, or test exclusions changed. This is not
a full Native or iPhone sweep.

## Review follow-up

- Forward intent through both volume slice paths, including explicit
depth and sample-count reconstruction.
- Revalidate retained shared frame graph wrappers on rebind without
changing reference counts for unchanged bindings.
- Restore physical mip storage before per-attachment policy during
context cloning, then rebuild with the correct mixed flags.
- Encode the optional ordered Native `COMMAND_GENERATEMIPMAPS` for
explicit storage-only generation. Older runtimes retain their previous
resolve/no-op behavior, with a warning when this command is unavailable.
Executing storage-only generation requires the companion Native runtime.
- **60 additional real-Metal readbacks pass** across RGBA8/RGBA32F
retained wrappers, both mixed-policy context rebuilds, volumes
with/without explicit depth, and the actual
`FrameGraphGenerateMipMapsTask`. The previous **180 GPU controls** and
**13 recovered rendering cases** remain passing.
- A focused devhost browser app exercised the actual explicit-generation
bridge path with automatic generation disabled; temporary changes and
server were removed. All five required quality commands pass on the
final code.

## Native CI compatibility follow-up

Commit 1785e61 restores legacy automatic frame graph mip resolves
only when the runtime lacks `COMMAND_GENERATEMIPMAPS`. Only textures
with allocated mips opt into that fallback; their logical
`generateMipMaps` flags remain unchanged. Supported runtimes still
preserve authored mip chains and generate explicitly on request.
Framebuffer cache metadata tracks the effective resolve policy.

Azure build 62163 repeatedly failed only **FrameGraph nrge
transmission**: 705/706 passed, with a stable 30.566% pixel difference
in that case. Disabling the new Native command locally reproduces
30.562%. With this fix, both command-enabled and legacy variants pass at
0.744% using the unchanged 2.5% comparison allowance.

Verification: 103 focused tests; all five mandatory quality commands;
full unit suite **8,274 passed, one expected failure, 34 skipped**
(`--maxWorkers=2` without competing builds); 60 paired real-Metal review
controls; devhost actual bridge checks for single/multiple attachments,
mixed mip storage, and cache reuse. Fresh CI is pending. No reference,
tolerance, exclusion, or dependency changes.
