**This changes the output of DomainWarpSimplex and DomainWarpSuperSimplex for every seed.** Nothing else changes: all other nodes, DomainWarpGradient included, give bit-identical output. Target branch: `perf-seeding`.

## What changes in the noise

The seeding and the lattice hash stay the same. What changes is how each simplex vertex's hash is turned into its warp vector, and the constants that scale the summed warp to the node's documented maximum warp distance (Warp Amplitude).

Changed output:
- DomainWarpSimplex: both Vectorization Schemes, 2D, 3D and 4D.
- DomainWarpSuperSimplex: OrthogonalGradientMatrix (the default) 2D, 3D and 4D, and GradientOuterProduct 2D and 4D. GradientOuterProduct 3D stays bit-identical.
- Everything built on them: DomainWarpFractalProgressive / DomainWarpFractalIndependent over a (Super)Simplex warp, and node trees such as the MountainTerrain demo. `GenTileable2D` output of these nodes changes too, because tileable 2D samples the 4D warp.

It is the same kind of warp as before: isotropic, with no visible creases or axis artefacts, and 2D spirals are kept (images below). The warp strength changes in these cases:
- **DomainWarpSuperSimplex, OrthogonalGradientMatrix, 3D and 4D: about 2x stronger at the same Warp Amplitude.** The old scaling constants only reached half of the documented maximum (max warp length 0.50 of the amplitude in 3D, 0.74 in 4D; now 0.99 and 0.95). To keep the old look, halve Warp Amplitude.
- **DomainWarpSimplex, GradientOuterProduct, 3D (bug fix).** The orientation transform used `kReflect3D = -2/2`, which scales the (1, 1, 1) component by -2 instead of reflecting it. The x and y warp components were 0.51 correlated and the warp reached 1.73x the amplitude. With the proper reflection (-2/3, as DomainWarpSuperSimplex already uses) the correlation is 0.009 and the max length 0.997. On average this warp is about 30% weaker than before (sd 0.36 -> 0.25).
- **Simplex and SuperSimplex OrthogonalGradientMatrix 4D (bug fix):** x/y correlation 0.16 -> -0.01, and the Simplex 4D warp no longer overshoots its amplitude (max length 1.58 -> 0.94).
- Everything else keeps its strength within 1-2% (component sd), and every config now stays within the documented maximum warp distance (max length <= 1.000).

## Why

Speed: the per-vertex vectors were built with 32-bit multiplies, two-table lookups and a full n x n matrix product. Now they come from selects, sign flips, a few adds and small permute tables. On the changed rows the geomean time is 0.896 of the base with clang-cl 23 and 0.871 with MSVC 19.51 (VS 2026). The default-scheme 4D warps take 0.553-0.854 of the time. Details, and earlier Apple M1 numbers, under Speed.

Quality: the two bugs above, and exact bounds. Each scaling constant is now the exact maximum warp length for its vector set (found by a numerical search over positions and directions), so a warp never exceeds Warp Amplitude and the full range is used.

## What each commit does

1. **OrthogonalGradientMatrix 3D/4D: cheaper hashed orthogonal matrices.** The matrix is M = S·P·Mx: Mx is a hashed choice between the identity and a fixed orthogonal matrix that only needs adds ((2, 2, -1)/3 row permutations in 3D, Hadamard/2 in 4D, with one input sign optionally flipped), P a hashed axis permutation (cyclic in 3D, pair swaps in 4D) and S hashed per-axis sign flips. The outer signed permutations act irreducibly, so the warp covariance is isotropic by construction, and the inner choice keeps the rows from all being axis aligned. Plain signed permutations alone were faster but gave axis-aligned dipoles and creases, so they were not used. 4D still runs per native register half below AVX-512 and skips halves with no contribution. Constants: Simplex 3D 39.88 / 4D 43.67, SuperSimplex 3D 184.38 / 4D 138.03.
2. **GradientOuterProduct 3D: the reflection fix** described above (one constant).
3. **OrthogonalGradientMatrix 2D: dihedral group D8.** Rotations by multiples of 45 degrees (3 hash bits into an 8-entry cos/sin table) plus a hashed reflection, instead of 12 + 12 matrices that needed a multiply by 3. Constants: Simplex 99.2043, SuperSimplex 18.2335.
4. **GradientOuterProduct 2D: 8 direction tables.** The gradient and the outer vector each come from 8 unit directions at 22.5 + 45k degrees, indexed by 3 hash bits, with no hash multiplies. Constants: Simplex 100.040, SuperSimplex 18.553.
5. **GradientOuterProduct 4D: the 4D Perlin vector set.** The gradient and the outer vector come from the 32 vectors (0, ±1, ±1, ±1): the dot product is `GetGradientDotPerlin` on hash bits 0-4, the outer vector uses bits 5-9 with the same layout. This replaces the 20-vector skewed set (three 32-bit multiplies and 8 two-table lookups per vertex on AVX2). Constants: Simplex 15.719, SuperSimplex 51.047.

The 8-entry tables use `vpermps` on AVX2, `vpermps zmm` on AVX-512 and TBL on AArch64, with select-based paths elsewhere. The small helpers are force inlined. The two 4D helpers stay out of line on MSVC AVX-512, as before: inlining them there makes SuperSimplex 4D too large for MSVC's inliner (2-3x slower).

**Seed bits (please read).** The table gives the share of samples that change when one bit of the seed is flipped (100% = the bit is fully used).

| Warp | base, lowest bit | this PR |
|---|---|---|
| Simplex / SuperSimplex GOP 4D | 99% / 100% | bits 25-31: **0%** (all other bits 100%) |
| Simplex / SuperSimplex OGM 4D | 100% | bit 23: 34% / 59%, bit 24: 58% / 85% |
| Simplex / SuperSimplex OGM 3D | 97% / 100% | bit 23: 29% / 38%, bit 24: 49% / 63%, bit 25: 75% / 87% |
| Simplex / SuperSimplex OGM 2D | 82% / 91% | bit 23: 61% / 73% |
| other configs | 97-100% | 95-100% |

The new constructions read low hash bits: bits 0-9 for GOP 4D, and bits 0-5 for the sign flips and matrix choice of OGM 3D/4D. Master's `HashPrimes` derives its low bits only from the low bits of seed ^ primed position (hash bits 0-9 from bits 0-24). On its own, this PR therefore makes seeds that differ only in their top 7 bits give identical GradientOuterProduct 4D warps. Merged with the seeding PR (`seed/seeding-free`), which premixes the API seed with fmix32 before it reaches any hash, every seed bit changes 99-100% of the samples in every (Super)Simplex warp config (measured on the merge of the two branches). The two PRs are best merged together. The follow-up domain warp top-bits PR builds on this one and takes every consumed bit from the top of the hash, which removes the weakness at the source.

## Speed

Measured on a Ryzen 9 7950X, one pinned core, nothing else running: clang-cl and MSVC under Windows, GCC and Linux clang under WSL 2 on the same machine. Both builds use FastSIMD 7aff025 and run interleaved in one process, in 3 processes with the A/B order alternating; each figure is the median of the per-process new/old time ratios (lower is faster). Two identical builds give feature-set geomeans of 0.998-1.001 and 99% of single rows within 1.5% (worst 9.1%) under Windows, and 0.999-1.005 and 2.4% under WSL, where a few single rows were 8-26% off in every process, so a lone Linux row is not evidence on its own.
