What and why
The path tracer could fill a closed shell with fog, but only fog of one thickness throughout. That ruled out smoke, clouds and fog that thins at its edges. The roadmap's §4 left "heterogeneous density fields, ratio/delta tracking" as an explicit gap. This PR closes it with a public DensityGrid, passed as MeshPhysicalMaterial(density=...):
```
puff = DensityGrid.from_function(
    lambda p: (1 - p.norm(dim=-1)).clamp(min=0) * DensityGrid.noise(p) * 4
)
cloud = Sphere(radius=1.5)
cloud.set_material(MeshPhysicalMaterial(
    color=WHITE, transmission=1, ior=1, roughness=0, sigma_s=4, density=puff,
))
```
How it works:
The grid scales extinction only. It multiplies the material's sigma_s and absorption. Albedo and g stay the material's.
The box follows its Mob. The samples fill a box in the frame of the Mob set_material was called on: its bounding box by default, or explicit bounds. The box moves, turns and scales with that Mob, and a clone carries its own field.
Free flights use spectral tracking. They run over a coarse piecewise-constant majorant walked by a 3-D DDA.
Shadow connections, and flights that may not scatter, use ratio tracking with Russian roulette.
Fails closed past the step cap. A segment that would need more than 4096 tracking steps is cut off, and the cut is counted in RenderPlan.truncations.medium_tracking.
The deterministic renderer refuses density grids, as it already refuses homogeneous scattering.
Two fixes found while building the demo:
Scatter points inside every volume were being moved, homogeneous fog included. This dates from the distant-camera fix (8048952, Oct 14). The walk's hit_p snap sent everything that wasn't a triangle down the circuit branch, and that included the medium vertex (htype == 3). The vertex's prim is the shell triangle the path entered through. Read as a circuit index, it projected the vertex onto an unrelated plane, so each entry facet's fog came out at its own brightness and the shell's tessellation showed through. The fix is one line: only htype == 0 projects. The slab closed-form tests missed it because a cube's few triangle indices happened to read harmless rows. The new test_a_scatter_point_stays_where_it_was_sampled adds sixteen circles so those indices read real circuit planes. Without the fix it gets 0.004 against a closed form of 0.069; with the fix it is within 0.004.
DensityGrid.noise overflowed int64 for most seeds, seed 11 for one. The seed is now reduced to 32 bits.
Rendered output
Scenes without a density grid render the same as before, except for the scatter-point fix above. Without a grid, the kernel gets an empty volume table and runs the homogeneous code unchanged. A homogeneous fog sphere rendered bit-identically to master before the scatter-point fix went in.
Homogeneous scattering scenes change on purpose. Their scatter points now stay where they were sampled. No baseline in tests/fast or tests/full_renders contains a scattering medium, so no baseline was regenerated.
Demo, on CPU at 960×540 and 256 spp with no denoiser: a noise-eroded cloud, a swaying smoke plume and a fog bank thickest at the floor, all lit by one directional light. Each casts a soft shadow, computed by ratio tracking through its grid. The demo is attached in the project thread.
Verification
All on CPU (x64, no CUDA here):
pytest -q --group pre-pr: 2405 passed and 5 failed.
Two failures were this PR's: the MPS guards flagged the grid's host-side float64 and one clamp below float16's floor. The second commit fixes both, and both now pass.
The other three are in test_orthographic_render.py, which this PR doesn't touch. Each hit a std::bad_cast launching _compute_samples_per_segment, a stroke kernel. The container had restarted partway through an earlier run, so a half-written kernel cache is the likely cause. All three pass on rerun, as does the pre-PR selection of both files.
tests/unit_tests/test_pt_volumes.py -- 38 pass. These cover:
the kernel's interpolant against grid_sample
the majorant bounding it everywhere, cell walls included
ratio and spectral tracking against closed-form optical depth for flat and ramped profiles, per RGB channel
the collision distribution, box clipping, per-frame transforms and the step-cap truncation
binding, clone and key semantics
full renders: slab single scattering against the closed form (flat and ramp), absorbing-only extinction, a half-filled cube's fog turning with its Mob, and a turned clone carrying its own field
tests/unit_tests/test_pt_media.py -- all pass except test_dense_conservative_cube_recovers_constant_environment[1.35]. It gets 0.141 against 0.25 ± 0.015 on master too, with and without this PR. It is not in the pre-PR group and is left for a separate fix.
Compile time: pt_shade_arena takes about 57 s to compile on CPU, up from about 53 s. There is no template gate, just two more arena arguments.
Not checked here: CUDA.

CPU before widening it, and the kernel only ever sees float32 tables, so the
module joins the MPS guard's host-only list. The default box's sliver pad is
a Python max rather than a clamp below MPS's float16 floor.
