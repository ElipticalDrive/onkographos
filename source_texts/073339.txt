What this is
Eternity — Voxel Realms, an open-world voxel action RPG that runs entirely in the
browser. No build step, no asset downloads, no server: everything is generated at
runtime, so it works offline once loaded.
```
npm install
npm run dev      # http://localhost:5173
npm run build    # production bundle in dist/
```
Controls are keyboard and touch from the same code path; the game targets landscape
and will ask for fullscreen on entry, with a manual Full Screen button as well.
What's in it
A hand-authored world. 384×384 columns, 144 named regions laid out by hand in
src/game/data/Regions.ts — no procedural terrain to speak of. Procedural noise is
used only for local surface detail and never decides where a biome, dungeon or boss
arena sits. 12 biomes, 9 boss arenas, 12 dungeons.
Engine. Custom voxel engine over three.js: greedy chunk meshing with per-face
culling, a tile atlas, per-biome lighting, weather and atmosphere, particle pools,
a camera rig, and a 42-sound Web Audio synth. src/engine is ~5,600 lines.
Systems. 521 items, equipment with affixes and set bonuses, a smelting/enchanting
forge, 45 enemies plus 12 bosses, 4 skill trees × 11 skills, quests, achievements,
6 AES-256-GCM encrypted save slots, and a full settings suite with a live key remapper.
World memory. Entering a region, dungeon, boss arena or structure records it
persistently; the map renders unexplored tiles as .unknown and remembers the last 12
structures entered, with one-click travel back to them. Discovery can be toggled per
category, and memory is stored as flat bitmasks rather than per-coordinate records so
logging a large world does not cost frames.
~12,300 lines of game code (src/game), plus ~5,600 lines of engine.
Bugs fixed while verifying this change
Three defects that a casual playtest would not surface, because the game keeps working
while the numbers are quietly wrong:
RNG.next() never produced a full-range number. The state mixing forced the top
eight bits of every output to zero, capping nextFloat() at roughly 0.004. Every
chance(p) above that was always true, int(0, 3) always returned 0, and every
weighted() table collapsed onto its first entry — and that engine drives loot rolls,
affix rolls, enemy drops, spawn picks and potion effects. Replaced with a canonical
xorshift128+ XORed with a second xorshift32 stream, and added a distribution
regression test that fails if the range is ever narrowed again.
gearDef() returned null for every base item. It only resolved named sets and
legendaries, so equip() refused every base sword, pickaxe and chestplate in the
game — the entire starter-through-netherite progression was unwearable, and weapon
damage never entered flatDamage. Added gearSlotFor(), which derives the slot from
the item's name (the one place it is recorded for hand-written items).
The starter kit was wrong. It granted a tier-5 Netherite Axe, a Book, Nether Brick
Stairs and a shovel. Rebuilt from the verified item ids: Wooden Sword, Bow with 16
arrows, 2 Potions of Healing, a wooden shield and 32 planks.
Also fixed: the enchanting screen opened on "Pick an item first" instead of preselecting
the first enchantable item.
Verification
npx tsc --noEmit clean. Four headless suites pass — smoke (now including the RNG
distribution checks), data-check (81), world-check (21), runtime-check (165),
covering the forge data, smelting, enchanting, fuel, tiered chest loot, base-item
equipping, and both new overlay screens rendered and inspected. npx vite build succeeds
with 44 modules.
One caveat worth stating plainly: the headless DOM stub has no selector engine, so screens
built from innerHTML templates are verified by reading the markup back rather than by
live layout. Those screens are covered for structure and rendered content; the browser is
the only place the visual result can be judged.
