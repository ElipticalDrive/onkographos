PARALLEL EXECUTION OF VERTEX, GEOMETRY, AND FRAGMENT
SHADERS IN PARALLELIZED RENDERING PROCESSES
Abstract. The article examines methods and architectural approaches to the parallel
execution of the three key software stages of the graphics pipeline – vertex, geometry,
and fragment shaders. The levels of parallelism employed in modern GPU architecture
are analyzed, along with the interaction between shaders, synchronization mechanisms,
internal pipeline processing, and practical optimization strategies. An analysis of
bottlenecks, load balancing approaches, and new mechanisms such as mesh shading is
provided. The results may be useful for graphics engine developers, GPU architects,
and researchers in the field of computer graphics.
Keywords: 3D rendering, GPU, parallelism, vertex shader, geometry shader, fragment
shader, mesh shaders, Vulkan API, SIMD/SIMT, multi-GPU rendering.
Relevance and Novelty: In modern three-dimensional rendering, shaders –
vertex, geometry, and fragment – are executed with an exceptionally high degree of
parallelism on the graphics processing unit (GPU). The primary goal of parallelization
is to ensure the efficient utilization of hardware resources, including arithmetic units,

ones. The fragment shader processes each pixel or fragment, forming the final
appearance of the scene. These stages work in close interaction yet independently,
which allows the GPU to overlap them in time to achieve maximum throughput.

identification of bottlenecks.
The concept of pipeline design with flexible execution organization is presented
in the Piko framework2, which allows the explicit specification of the graphics pipeline
structure while controlling parallelism at the task and tile levels. This approach
emphasizes the need for precise control over resource allocation, which is critical for
building efficient low-level API implementations. In combination with the Vulkan
API, Piko demonstrates an approach to implementing multithreading in the context of
GPU command queues, which is particularly valuable for parallel scene construction,
shadow processing, lighting, and texturing.

Parallel Execution of Vertex, Geometry, and Fragment Shaders. Parallel
execution of the vertex shader is based on the decoupling of processing each vertex.
The scene is provided as an array of vertices, which are grouped into batches and
passed to the GPU’s computational units. Thanks to the SIMD/SIMT architecture, each
shader processes a set of vertices simultaneously. For example, with 10,000 vertices,
the GPU can process 32 vertices in parallel within each warp or wavefront. The
geometry shader processes a single primitive – point, line, or triangle – and, if
necessary, generates additional ones. Each instance of the geometry shader is launched
independently. However, due to the smaller number of primitives compared to vertices
or fragments, parallelism is limited here. Geometry shaders often exhibit lower
performance and create a bottleneck, which is why modern engines attempt to
minimize their use or replace them with more flexible solutions.

fragment forming a pixel on the screen is processed independently. For a Full HD

Fragment shaders are the most resource-intensive, as they often include computations

Modern-generation GPUs employ a unified shader architecture – the unified
shader model. This means that computational units are not rigidly assigned to a specific
stage but can dynamically change their role. Thus, under excessive load on the
fragment stage, some resources from the less loaded vertex stage can be reassigned. In
addition, pipeline optimizations are used, allowing vertices from one part of the scene,
geometry from another, and fragments from a third to be processed simultaneously.
Such pipeline overlap minimizes idle time and ensures high throughput.
In the new NVIDIA architectures (Turing, Ampere) and AMD architectures
(RDNA 2, 3), mesh shaders have been introduced – an innovative approach that
combines the vertex and geometry stages into a single program. This allows processing
not individual vertices but entire batches (meshlets), which helps to avoid duplication
and improves visibility control. In addition, amplification shaders are employed,
enabling selective activation of only those meshlets required for the current frame,
thereby reducing the workload. Such mechanisms demonstrate significant efficiency
improvements when working with massive scenes.
Parallelization is also supported at the API level. For example, in Vulkan,
multiple command buffers can be used and executed in different queues – graphics,
compute, and transfer. This enables the parallel execution of subtasks such as
background texture updates, asynchronous shadow generation, or lighting. In
frameworks like Piko, the user can explicitly define which tasks should be executed in
parallel, how binning (scene partitioning into tiles) is performed, how computations
are scheduled across tiles, and which queues are utilized.

Bottlenecks in the parallel execution of shaders include memory overload
(especially in the fragment stage), buffer access conflicts, inefficient caching,
excessive vertex duplication, and suboptimal geometry generation. To avoid these
issues, several methods are applied: early depth testing, adaptive LOD, dynamic task
scheduling, limiting the use of geometry shaders, and reducing excessive access to
global memory. For example, using local buffers or registers decreases traffic to video
memory, while regrouping fragment workloads within a single tile improves caching.
Scientific studies also consider the possibility of performing rendering on
multiple GPUs simultaneously. In this case, the frame is divided into regions, each
processed by a separate GPU, or different pipeline stages are distributed across GPUs
– for example, one handling the vertex stage and another the fragment stage. Such an
approach requires complex synchronization but can be beneficial for high-performance
tasks or the visualization of large volumes of data.
Finally, promising directions for further research include automatic load
balancing among shaders based on machine learning, heterogeneous rendering using
CPU+GPU, adaptive shaders with priorities, the integration of mesh shading into
WebGPU, and new models of shader scheduling in cloud environments. The
application of these approaches will make it possible to extend the boundaries of image
realism while maintaining performance.
