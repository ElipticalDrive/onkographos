Parent: #231. Depends on #233 (validated custom shader rendering path). See Potree adaptive point-size and Cesium point-cloud shading for conceptual behavior; don't copy their UI.
Goal
Avoid visually sparse near-camera point clouds and excessive overdraw in distant views by allowing the adapter to choose a screen-space point size based on camera projection and node spacing.
Design
Expose optional pointSizeMode: 'fixed' | 'attenuated' (exact naming via API review); preserve current fixed-size default for compatibility.
Derive a bounded projected point size using node-local spacing/LoD and camera-to-node/point distance; validate ortho/perspective behavior if supported. The feedback's suggested factor/sqrt(distance) is only a tuning hypothesis, not a proven universal formula.
Use shader-side gl_PointSize where the renderer supports it, otherwise document/retain a safe fixed-size path.
Define minimum/maximum pixel size, viewport/retina handling, nonfinite inputs and any classification filtering interaction.
EDL, circular splats and clipping are separate features.
Additional implementation requirements
Derive nominal node spacing from COPC metadata and octree level.
Convert source spacing to metres using validated CRS semantics.
Never treat geographic degrees as metres.
Keep the fixed-size rendering path backward-compatible.
Compute projected point sizes in the batched vertex shader.
Avoid geometry recreation during camera-only changes.
Keep CPU point-picking footprints consistent with GPU point sizes.
Support perspective projection and either validate orthographic
projection or explicitly document its limitations.
Validate CSS pixels, devicePixelRatio, and rendering resolution scale.
Bound point sizes and reject non-finite or invalid configuration.
Preserve classification filters, original point identities,
streaming budgets, and renderer-owned cleanup.
Add deterministic spacing/projection tests and real browser E2E.
Compare close/far views using the same camera and dataset
configurations for fixed and attenuated modes.
Validate packed Cesium consumers and supported Cesium versions.
Do not claim FPS improvement without measured frame-time evidence.
Acceptance
A close-vs-far fixed-camera screenshot/video comparison demonstrates sensible coverage without extreme giant splats.
Point budget, selection identity, classification colors/filtering and GPU cleanup are unchanged.
Deterministic tests cover varying spacing, perspective, height, DPR and edge cases.
Browser E2E and packed consumer work; default remains backward compatible.
