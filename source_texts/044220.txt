Modernize rendering in measured stages: eliminate redundant frame transfers, then evaluate and implement GPU composition where it delivers a demonstrated benefit for HD artwork, high-refresh presentation or richer effects.
The desktop currently CPU-composes an RGB frame. Its CRT upload path updates both the SDL streaming texture and the CRT renderer's own OpenGL texture. HD artwork can increase composition work and transfer volume substantially.
Scope
Establish representative frame-time and transfer-volume baselines for original artwork, HD packs, widescreen/ultrawide and CRT presentation at 1080p, 1440p and 4K.
Remove redundant uploads in the active presentation path. Ensure switching between CRT and ordinary presentation uploads current content before it is displayed.
Prototype GPU tile/sprite batching, texture atlases, palette lookup and layer composition against the existing CPU renderer.
Select and document the backend based on measurements, platform coverage and integration cost. Consider wgpu; an API migration is a decision to justify rather than a prerequisite.
Integrate the beneficial GPU path incrementally while retaining the CPU renderer as a fidelity reference and fallback.
Acceptance criteria
Publish reproducible baselines separating CPU composition, palette/RGB resolution, uploads, submission and presentation; include frame-time distributions and uploaded bytes.
The active path avoids duplicate full-frame uploads, and toggling CRT or resizing/fullscreen never displays stale frames.
A GPU composition prototype is compared with the CPU path for both performance and image correctness; document backend choice and migration milestones.
Adopted GPU composition preserves sprite/plane priority, transparency, clipping, flips, palette fades, mid-frame palette changes, scrolling and wave effects.
HD replacements preserve alpha, tinting, atlas boundaries and output-scale behaviour.
Validate supported Windows, Linux and macOS configurations, including shader failure/device-loss handling and a usable fallback.
Existing screenshot capture, overlays, display modes, save/replay verification and 60 Hz simulation behaviour remain correct.
Headless/reference comparisons and representative visual regression checks cover every migrated rendering feature; performance claims include hardware and test conditions.
Starting points
native/src/render.rs, native/src/render/art.rs, native/src/render/sat.rs, native/src/game/draw.rs, native/src/desktop.rs, native/src/desktop/crt.rs, native/src/desktop/performance.rs.
Backend reference: https://github.com/gfx-rs/wgpu
Related: #21 (performance instrumentation), #25 (shader options), #2 (feature roadmap). Coordinate shared presentation work with the scaling, multipass CRT and high-refresh issues.
