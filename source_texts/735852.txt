Pull request overview
This PR improves voxel processing scalability for large scenes by replacing JS Map/Set-style collections with typed-array-backed maps, introducing a faster direct “voxel buffer → sparse octree” path when mutable grid operations aren’t needed, and adding guards/errors around format and memory limits.
Changes:
Add typed hash-table utilities for large block indices (including >2^32) and use them in voxel queries / cleanup paths.
Add buildSparseOctreeFromBuffer() and integrate it into writeVoxel() to avoid building a mutable SparseVoxelGrid when not required.
Expand tests for large indices, adjacency correctness, mixed-leaf limits, and direct sparse-octree output.

maxNodes can be larger than the allocated nodes.length (it’s clamped to MAX_24BIT_OFFSET + 1). When emitPos === nodes.length, this still takes the slice() path and copies the entire nodes array, which is avoidable extra memory/time on large outputs.

    return {
        gridBounds,
        sceneBounds,
        voxelResolution,
        leafSize: 4,
        treeDepth,
        numInteriorNodes,
        numMixedLeaves,
        nodes: emitPos === maxNodes ? nodes : nodes.slice(0, emitPos),
        leafData: leafDataLen === leafData.length ? leafData : leafData.slice(0, leafDataLen)
