Goals
Provide a reusable, renderer-independent way to reconstruct packed vertex attributes after mesh subdivision, without unpacking every record into JavaScript objects or adding GPU dependencies.
This complements #239's source-edge subdivision policy but is independently based on master. Neither PR switches Tangram's production implementation.
Changes
Add interpolatePackedAttributes to @math.gl/geometry-utils, with a dependency-free @math.gl/geometry-utils/interpolate-packed-attributes subpath and a convenience root export.
Support eight integer/float storage formats, explicit byte stride/offset/endianness, offset views, and whole-field or per-component linear/flat policies.
Consume original-vertex index/weight provenance from the existing polygon subdivision API without a runtime dependency on polygon.
Preserve identity record bytes and padding; reject conflicting categorical values, invalid layouts/provenance, nonfinite values, and output allocations exceeding the configurable 64 MiB default.
Add 47 Vitest cases covering every encoding, public entrypoints, real subdivision output, mixed Tangram-style records, seams/flat IDs, allocation limits, invalid inputs, and quantization differences.
Document the API and its renderer responsibilities: integer rounding occurs once at final output, not at successive midpoints; normals and GPU-normalized/bitfield formats require application-specific handling.
Compatibility and bundle size
Existing APIs and dependency versions are unchanged; there are no new runtime dependencies.
This is not a bit-exact replacement for Tangram's recursively rounded integer midpoint records. The difference is documented and tested explicitly; adopting it requires separate seam/error conformance work.
esbuild minified ESM measurement: standalone helper 3,267 bytes raw / 1,294 bytes gzip, with exactly one source input and no runtime imports.
Existing encodeRGB565 root-import bundle stays 9,699 bytes raw, with zero helper bytes retained. Gzip is 2,939 → 2,941 bytes because minifier identifier choices change; it is not claimed byte-identical.
Importing the new helper through the existing broad root costs 12,753 bytes raw / 4,021 bytes gzip. The dedicated subpath avoids those existing unrelated root dependencies.

Note
Low Risk
Additive geometry-utils API with no new runtime dependencies; behavior is isolated behind explicit layout descriptors and strict validation, though adopters must validate integer rounding vs existing renderer quantization.
Overview
Adds interpolatePackedAttributes to @math.gl/geometry-utils so interleaved vertex buffers can be rebuilt from polygon-style original-vertex index/weight provenance (e.g. subdivideTriangleMesh) without unpacking records or pulling in a renderer.
The helper works on Uint8Array stride views, supports eight scalar encodings with per-field or per-component linear / flat policies, respects endianness and offset views, copies padding from the first contributor, and enforces a 64 MiB output cap with RangeError on bad layouts, weights, flat conflicts, and nonfinite values. Integer linear paths round once at the end (documented as not matching repeated midpoint quantization). A dependency-free @math.gl/geometry-utils/interpolate-packed-attributes subpath is added alongside the root re-export; docs and broad Vitest coverage (encodings, Tangram-style mixed records, polygon integration) ship with the API.
