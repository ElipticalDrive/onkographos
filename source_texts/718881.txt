First-playable slice (2026-10-01): Using the current renderer and the #8/#58 render-list work, expose explicit instanced batches for simulation-owned objects, per-instance transforms/colors and dirty-range updates. Require a measured 10,000-instance sample with correct selection/bounds. GPU-driven indirect drawing is a follow-up if CPU instancing meets the budget; it is not a mandatory first milestone.
Current State
Every ModelComponent submesh is its own draw with its own push constants. Repeated meshes (props, foliage,
particles, tiles, sprites) cost one draw each.
Tasks
Automatic batching of identical mesh + material pairs into instanced draws with a per-instance data buffer
Follow-up if measured: indirect draw buffers built from the cached render list (Bistro E2: draw-loop hot path — cached render list and material sort #58), after explicit CPU-submitted instancing meets the initial sample.
Explicit instanced rendering API for systems that own many instances (particles Particle system: emitters, modules and billboard rendering #65, grass, tilemaps, sprites)
Per-instance properties (colour, custom data) without breaking the batch
Acceptance Criteria
10,000 identical props render in a handful of draw calls, verified in the stats HUD (Bistro E5: frame statistics HUD (draw calls, triangles, ms) #59).
Related
Bistro E2: draw-loop hot path — cached render list and material sort #58, Bistro E1: AABB bounds and frustum culling #8, Particle system: emitters, modules and billboard rendering #65, Epic: terrain system #107
