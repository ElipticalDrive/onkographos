Summary
Path tracing and ray traced GI now trace with inline ray queries instead of Unity ray tracing shaders, so their cost no longer grows with the number of instances in the scene.
Inline ray tracing: each tracing stage is a native ray generation program. Materials are evaluated from their own PathTracing passes through generated evaluators and a bindless resource table; the shader table holds one record per material evaluator instead of one per instance.
Shader Execution Reordering: on supported NVIDIA GPUs, rays are regrouped by the material they hit.
Standard coverage: Hybrid Lit, SpeedTree and ASE passes that declare it share one alpha-test and blend routine, sampled at the texture's finest level.
Opacity micromaps: alpha-tested static geometry gets micromaps generated on the GPU in Play Mode and players, so rays skip or accept clearly clear or solid parts of foliage without running coverage. Images are unchanged.
UnityRHI: top.kuanmi.unityrhi and top.kuanmi.unityrhi.native are replaced by com.kurisu.unityrhi, which ships its native plugins and the D3D12 Agility SDK runtime that opacity micromaps need.
SpeedTree7: hybrid lighting and path tracing support.
Fixes: skinned meshes no longer freeze during path tracing, emissive meshes without Read/Write no longer break path tracing in players, and the RTGI denoiser no longer waits for the render thread every frame.

🔴 Refresh descriptors when a render texture is recreated
RenderTexture objects are skipped unconditionally, but Release/Create or resizing can replace their native resource while retaining the same Texture instance. AcquireTexture also returns the cached slot without checking its pointer, so even a later scene rebuild cannot repair it. Materials then sample the old resource rather than the current render texture (or retain an obsolete allocation indefinitely). Track native-resource replacement separately from frequent content updates, allocate a new descriptor, and invalidate the scene records while retiring the old slot behind the fence.

🔴 Re-register mesh buffers after uploads replace their resources
An existing MeshEntry is returned forever without checking its native vertex/index resources or layout. A mesh reimport or runtime Clear/SetVertexBufferParams/SetIndexBufferParams can replace those resources while preserving the Mesh instance. Rebuild acquires the cached entry before releasing the previous reference, so it never reaches Register again; inline hit evaluation continues reading the old buffers while Unity's acceleration structure uses the new geometry. Detect buffer/layout replacement, publish fresh slots and advance Generation, retiring the previous slots only after GPU completion.
