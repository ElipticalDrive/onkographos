When using alignWorldToPath, the 2D gameplay ground line must align with where the 3D GameplayPath appears on screen. Previously, CONFIG.groundY was computed from ratios/offsets, causing misalignment. The value must remain stable when the camera tracks player vertical movement.
Changes
World-to-screen projection (visualsmapLoader.js)
Added projectWorldToScreen() using Three.js Vector3.project() for 3D→2D coordinate conversion
Handles NDC transformation and Y-axis flip: screenY = (-(vector.y * 0.5) + 0.5) * height
GroundY synchronization (visualsmapLoader.js)
Added syncGroundYFromGameplayPath() to project path position (world y=0) to screen space
Supports configurable Z offset via pathProjectionZOffset to project from tile edge instead of center
Default offset is 0.5 (half tile forward, projecting from tile edge)
Sets CONFIG.groundY from projection result and locks with CONFIG.groundYSource = 'camera'
Called after setCameraParams() when alignWorldToPath is true
Exposed window.resyncGroundYFromCamera() for manual re-sync from current camera view
Overwrite protection
computeGroundY() in ground-utils.js: Early return if groundYSource === 'camera'
syncConfigGround() in map-bootstrap.ts/.js: Skip recalculation if camera-locked
Debug UI (app.js)
Added "Sync groundY" button to 3D/Runtime Debug panel header
Re-runs groundY sync logic from current camera view for testing
Shows success/error status messages
Configuration
Add to visual map JSON to configure projection offset:
```
{
  "alignWorldToPath": true,
  "pathProjectionZOffset": 0.5,
  "gameplayPath": { ... }
}
```
Offset values:
0 = project from tile center
0.5 = project from tile edge (default)
1.0 = project from opposite edge
Example
```
// After visual map loads with alignWorldToPath=true:
// Path center at world (0, 0, 0) + Z offset (15) projects to screen (400, 322)
CONFIG.groundY = 322;
CONFIG.groundYSource = 'camera';  // Locked

// Later, camera moves to follow jumping player:
camera.position.y = 12;  // Camera tracks vertical movement

// groundY remains 322 - computeGroundY() and syncConfigGround() 
// detect the lock and skip recalculation

// Manual re-sync from debug panel button or console:
window.resyncGroundYFromCamera()
```
The lock ensures 2D entities spawn at the correct visual ground level regardless of camera movement. The configurable offset allows projection from the tile edge for accurate alignment on maps where the gameplay path should align with tile boundaries.
