Change
Short-circuit misses in the existing cpBBSegmentQuery: for a non-vertical segment, evaluate the y interval before x divisions and return early only if it lies wholly outside [0,1]. Keep the original vertical handling, division formulas, x-then-y interval combination, endpoint inclusion and bit-identical returned fractions.
No public API/layout changes, allocations, additional traversal pruning or new inlining hints. The existing function declaration stays unchanged. Both zero and positive-radius segment queries use this calculation; the radius correctness fix from #55 remains intact.
The older private BBTree-helper prototype did not perform consistently after integration with #55. That port and a separate-predicate variant were rejected. This PR instead changes the existing box calculation and adds permanent regression coverage and a supplementary benchmark.

132 primary cases include five shape types, six ray patterns, both APIs/radii and128/1024/8192 sizes. Twelve additional translated/reindexed, warmed snapshots retain roughly7–11% short-query gains.
Not universally faster: outside-scene misses add roughly2–3ns/query (~15–19% for the displayed mixed cases). At8192 mixed shapes, short first/all improves10.66/9.43%, but long all-hit regresses2.76%, fan first/all1.13/2.65%. Some other all-hit cases regress around1%. No Python/FFI, cold-cache, moving-frame or general stepping improvement is claimed.
