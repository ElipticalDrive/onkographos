Summary
The library graphs ambient_occlusion/ambient_occlusion and ambient_occlusion_2/ambient_occlusion_2 were rendered with MaterialCraft's own ao node through the generic mapping, which dropped every one of their parameters. The audit (cargo test --lib unmapped_parameters -- --nocapture) listed:
ambient_occlusion -> ao: AO_Spread, AO_Levels, Light_Intensity, Light_Angle, Light_Distance
ambient_occlusion_2 -> ao: spreading, equalizer, levels
Both graphs now have adapters, and the ao node has new parameters for these settings, on the CPU and on the GPU. The audit no longer lists either graph.
What changed (per parameter)
Neither legacy graph has its own page in the public documentation. The meanings below come from the documented AO parameters of the same names on the Bitmap to Material Light page ("Ambient Occlusion Spread / Light Distance / Light Angle / Levels"), from the declared defaults and ranges in src/sbs_library.txt, and from what the parameter names say where nothing is documented.
ambient_occlusion
Parameter
Documented meaning
Mapping
AO_Spread (0.5, 0..1)
"Sets how far generated AO spreads."
blur radius = AO_Spread * 12 px. The default 0.5 gives our default radius of 6.
Light_Distance (0, 0..1)
"Sets AO 'depth' interpretation."
depth intensity = 2 + 8 * Light_Distance. The default gives our default depth of 2.
Light_Angle (0, 0..1)
"Sets fake lighting AO cast angle."
new light_angle, in turns, measured the same way as Emboss's angle.
Light_Intensity (0, 0..1)
no page; the strength of that fake light
new light_intensity: the neighbourhood is read light_intensity * 2 * radius pixels towards the light, so the floor beside a wall that faces away from the light gets darker. 0 means no light.
AO_Levels (0 1, f2)
"Modifies AO output levels."
new out_low / out_high.
ambient_occlusion_2
Parameter
Meaning
Mapping
spreading (0.15, 0..1)
how far the AO spreads
radius = spreading * 40 px. The default gives radius 6.
equalizer (0 0 0, -1..1, f3)
not documented; read as a three-band equalizer, with lanes taken as fine / medium / large
new band_fine, band_mid, band_large. The occlusion is split into a fine band (the blur at radius/4), a medium band (radius/4 to radius/2) and a large band (radius/2 to radius). Each band is scaled by 1 + weight: -1 removes the band, +1 doubles it. With all weights at 0 the sum is exactly the plain blur AO.
levels (0 0.5 1, f3)
input levels: low, midpoint, high
new levels_low, levels_mid, levels_high. The midpoint is a position inside the low..high range and becomes a gamma: above 0.5 darkens, below 0.5 lightens.
Implementation
src/sbs_adapt.rs: new ambient_occlusion and ambient_occlusion_2 adapters (mode = 0, the blur method). Their entries in the ADAPTERS table use the exact package/graph ids.
src/ops.rs: new ambient_occlusion_ex adds the detail bands and a whole-pixel light shift with wrapping, so tiling is kept. With neutral settings it falls back to the existing ambient_occlusion, bit for bit. New helpers ao_light_shift and ao_levels are shared by the CPU and GPU paths.
src/graph.rs and src/graph_gpu.rs: the ao node reads the new parameters. Levels apply to both methods (blur and HBAO).
GPU: new opa::AO_BANDS (26) op in src/kernels/parts/ops_a.wgsl, regenerated with tools/gen_kernels.py; generated files whose only change was line endings were reverted. When the bands are used and radius/4 is below the GPU blur's 2.5 px minimum, the node falls back to the CPU, like the plain blur AO already does at small radii.
src/params.rs: new parameters with neutral defaults, so existing graphs render as before. Labels: "Light intensity (legacy)", "Light angle (legacy)", "Fine detail / Medium detail / Large shapes (legacy)", "Levels low / midpoint / high", "Output low / high".
No library .sbs content or vendor code was used. .sbs identifiers and parameter names are unchanged.
Tests
cargo test --test core blur_ao_spread_light_bands_and_levels (new) passes. It checks that:
neutral extras give identical pixels;
a larger spread gives a wider occluded area;
a larger depth gives darker AO;
a light from the right darkens the right side of a pit, and angle 0.5 darkens the left side;
each band at +1 or -1 gives darker or lighter AO, and the fine band alone stays close to the walls;
the output range is respected;
a midpoint above 0.5 darkens, a raised low point darkens and a lowered high point lightens.
cargo test --lib: 32 passed. This includes the new sbs_adapt::tests::library_ambient_occlusion_parameters, which checks the default and changed values through both adapters, and unmapped_parameters, whose output no longer lists either AO graph (537 unmapped parameters in 84 graphs remain).
cargo test --test core: all 60 passed.
cargo test --features gui --test gpu_graph every_gpu_node_matches_the_cpu_and_runs_resident: 5 new CPU-vs-GPU cases (blur AO, light, bands, levels, HBAO with levels) all match and stay on the device. The test as a whole still fails, but only on the 11 existing cases (directional_blur, warp, vector_warp, slope_blur, bent_normal, x_rt_shadows, ...), which all predate this change.
How to test
Import an .sbs that uses the library Ambient Occlusion or ambient_occlusion_2 node with non-default values. The ao node should show the carried-over spread, depth, light, bands and levels.
Or add an ao node, set Method to "Blur (legacy)" and change Light intensity / angle, the detail bands, Levels and Output on a height map.
cargo test --lib unmapped_parameters -- --nocapture | grep ambient_occlusion prints nothing.
The UI was not tested by hand.

ambient_occlusion and ambient_occlusion_2 now have adapters onto our ao
node instead of the generic mapping that dropped all their values:

- AO_Spread / spreading -> blur radius (defaults land on our radius 6)
- Light_Distance (AO depth) -> depth (intensity)
- Light_Intensity / Light_Angle -> a fake light: the neighbourhood is read
  towards the light, so the sides facing away from it darken
- equalizer -> weights of the fine / medium / large detail bands
- AO_Levels -> output range; levels -> input low / midpoint / high

The ao node gains these parameters (neutral defaults keep existing graphs
unchanged), on the CPU and on the GPU (new ops_a AO_BANDS op; levels via
levels_g, for both AO methods).
