The gap
.NET has no way to draw from a weighted discrete distribution. Random.GetItems and Random.Shuffle (.NET 8) are uniform only, and nothing in Celerity.Statistics or Celerity.Primitives covers it either: ReservoirSampler is uniform over a stream, and the struct PRNGs give uniform integers.
So the idiom everyone writes is a prefix-sum array plus Array.BinarySearch: an O(log n) search per draw. Each probe is a dependent load, so once the cumulative array falls out of cache, every draw pays about log₂ n cache misses.
Workloads include weighted load balancing and traffic splitting (A/B/n by percentage), Monte-Carlo and agent simulations, procedural generation and loot tables, negative sampling in word2vec-style training, weighted bootstrap resampling, and sampling the next token or state from a categorical distribution.
Proposal
AliasTable in Celerity.Statistics is Vose's alias method. An O(n) build turns n non-negative weights into n packed (threshold, alias) entries. After that, each draw costs O(1): one 64-bit random value, one multiply and one table load, whatever the size of n.
Immutable after construction, so concurrent readers are safe. The generator is passed per call (Sample<TRng>(ref TRng rng) over IRandomSource), the same constrained-generic shape the struct PRNGs already use.
Sample(ref rng, Span<int>) fills a buffer in bulk.
Zero-weight outcomes are never drawn. Weights that are negative, NaN or infinite, an all-zero set, or a sum that overflows are rejected.
8 bytes per outcome.

Kill criteria (pre-registered, BDN)
Sample must be at least 3x the prefix-sum + BinarySearch baseline at 10,000 outcomes.
Sample must be at least 1.5x that baseline at 100 outcomes.
The build must cost no more than 10x building the prefix-sum array, at 10,000 outcomes.
If 1 or 2 misses, the type does not ship. A miss on 3 is published.
Not proposed
A dynamic weighted sampler (update a weight in O(log n)) is a Fenwick-tree walk, a different structure. It is out of scope here.
