Summary
New splat blender <gaussian-cloud> CLI command: renders a GaussianCloud using Blender strictly as a render engine, via blender --background --python.
v1 render fidelity (confirmed with the user before building): each Gaussian becomes a flat-colored point splat - native Blender PointCloud object, positioned by means, sized by a per-point radius attribute, colored by the flattened SH DC term through a vertex-color-driven Emission material. No ellipsoid orientation from the rotation quaternion, no opacity blending, no view-dependent SH - enough to inspect a reconstruction's shape/orientation at a glance, not a differentiable-rasterizer replacement.
The import technique was validated interactively against a live Blender instance over the blender-mcp MCP server (added in gaussian: normalize reconstruction output orientation and scale #51's stack) before being committed to a standalone script (adapters/render/_blender_script.py) that the adapter shells out to - same rendering path, no third-party plugin dependency, just bpy + Blender's bundled numpy.
Follows the ReconstructionBackend/MeshPredictionBackend shape (ports/render.py → adapters/render/blender.py → run_blender in pipeline.py) but deliberately skips the ModelDescriptor/catalog machinery those use - there's exactly one render backend and no HF weights to catalog.
Wired directly to the CLI rather than through SplatClient/SPLAT_URL, following the same precedent already documented for splat tools displace.height: it needs an actual Blender install on whichever machine renders, so it doesn't assume the remote-execution model fits unexamined yet.
