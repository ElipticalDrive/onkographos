Related issue: #25264 (follow-up to #31097)
Description
Octree.split() creates children with default settings, so a custom maxLevel or trianglesPerLeaf is lost during recursive subdivision. Copy both settings to each child.
For example, building from new Mesh(new SphereGeometry(2, 12, 8)) with maxLevel = 1 currently creates a tree 17 edges deep with 347 nodes. With the fix it stops at 2 edges and 65 nodes, preserving the existing split(0) level convention. Using trianglesPerLeaf = 32 likewise stops unnecessary deeper subdivision. Default tree structure and triangle order remain unchanged.
Added regressions for both settings through fromGraphNode(), including ray-hit checks. The two new tests fail before the fix and pass afterward.
Validation: npm test (1,524 core tests pass, 1 existing TODO; 435 addon tests pass), changed-file ESLint, and npm run test-e2e-cov pass. Additional controls cover 15 geometry/settings combinations and 1,920 ray queries. Independently checked another 960 rays against a naive full-triangle scan using addTriangle() / build(). The games_fps.html browser example renders, including its octree debug view, without console errors. Headless unit tests do not exercise GPU backends; the new regressions use CPU math only.
AI assistance was used to implement and test this change; the patch received a separate review.
