Motivation
Reduce draw cost and CPU work for chunk meshing and rendering by improving occlusion handling and meshing efficiency.
Prevent visible popping/x-ray artifacts near the player and at extreme camera pitch while still enabling aggressive occlusion when safe.
Prioritize chunk generation to improve perceived streaming responsiveness in the player’s forward view.
Description
Introduce an opt-out flag ENABLE_ANGULAR_OCCLUSION_CULLING and add camera-forward checks to disable angular occlusion at steep pitch angles, and keep a local neighborhood always visible to avoid holes.
Implement a lightweight angular occlusion culler using azimuth/elevation bins and nearest-depth per bin with a MAX_OCCLUSION_DIST and DEPTH_MARGIN.
Replace the previous greedy meshing loops with a binary-mask based greedy mesher that buckets faces by (id|materialKey) and emits rectangular quads via bit operations and helper routines (ctz32, rectWidthFromBit, buildBinaryGreedyMasksForSlice, emitBinaryGreedyFaceRect, runBinaryGreedyFace) to reduce CPU and VBO churn.
Disable per-mesh frustum culling (mesh.frustumCulled = false) and rely on chunk-group visibility to avoid per-mesh angle artifacts.
Prioritize chunk creation by always enqueuing the 3x3 player ring first and biasing remaining candidates toward the forward-facing direction based on yawObject.rotation.y.
Reorder the chunk pipeline in animate to ensureChunksAroundPlayer -> processMeshUpdateQueue -> maybeUpdateChunkFrustumCulling to better sequence load/generate -> mesh/VBO upload -> cull -> render.
Clean up duplicated remesh requests and other minor code organization tweaks.
Testing
Ran the project build with npm run build which completed successfully.
Executed the test suite with npm test and linting with npm run lint; both returned passing status in CI.
No automated rendering regressions were reported by CI smoke checks after the changes.
