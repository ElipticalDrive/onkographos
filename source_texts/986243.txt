Dev Engineer Review
The PR adds CausalKVCacheManager for a pinned prefix, rolling history, staged tokens, and causal-block layouts. The cuDNN and TRTLLM backends add paged cached-attention paths. Unsupported backends report no cache support, and Attention._attn_impl rejects cache use with those backends.
The cache API separates pool construction from rollout configuration in open(). It retains device state across close and reopen, and cleans up after a failed open. The CUDA operators add in-place row rotation, K/V slot scatter, the device-side block layout and a pool-to-pool slot copy.
The cache and backend paths have different limits. TRTLLM requires 32-token pages, while cuDNN accepts unquantized cache attention for a single video. Callers must provide the real-token seq_len when using a cache. Verify that callers check backend cache support and pass consistent sequence lengths. Description
Autoregressive video models generate a few latent frames at a time. Every chunk
attends to a fixed prefix (the text prompt), a sliding window of finished frames
and itself, through several denoising forwards and one frame-causal "clean" forward
whose K/V become history. Finished frames never change, so their K/V should be
computed once and kept. VisualGen has no K/V cache today; this PR adds one, plus
the attention paths that read it. No model uses it yet; the first consumer is a
follow-up PR.
Cache. BlockCausalKVCacheManager (visual_gen/cache/block_causal_kv_cache.py) is a
subclass of KVCacheManagerV2, driven as one long-lived sequence:
[fixed region | rolling history window | staged tokens], where the staged tokens
are what forwards have written and not yet committed. The constructor owns the
pool (pool_tokens); open(spec, pin_tokens) owns a rollout, described by a frozen RolloutSpec. "Block-causal": attention
is full within a causal block and causal across causal blocks and against history.
Terms (also the class docstring's glossary): a page is the pool's storage unit (V2's
"block"); a causal block is a run of staged tokens with full attention among
themselves, one request in the TRTLLM metadata; a chunk is the frames one forward
processes. "Block" alone is never used.
One pool and one page table for all layers; a page holds the same tokens in every
layer, so eviction is one decision, not one per layer.
open(spec, pin_tokens) starts a rollout inside the pool. The RolloutSpec holds the
window, the most tokens a forward stages, each causal block size with the most causal
blocks of that size one forward uses ({chunk: 1, frame: 4} at Cosmos), and a bound on
the pinned tokens; private pages and the TRTLLM metadata are sized from those counts.
The first pin_tokens committed tokens become the fixed region and are never evicted.
A spec's kernel-facing tensors are allocated the first time it is opened and kept at
fixed addresses, so a graph captured over it replays when it is opened again, with any
pin_tokens up to the bound (a new resolution is a new spec on the same pool). write_range writes K/V at a logical position;
commit(n) turns the n staged tokens into history and slides the window.
Eviction is an in-place rotation of the page table on the device (new op
trtllm::rotate_rows_), not a reallocation. Commit runs entirely on the device:
a layout kernel (trtllm::block_causal_layout_) reads the table and rewrites every
per-causal-block tensor in place, and one pool-to-pool copy (trtllm::copy_kv_slots_)
fills the private pages; no bytes cross from the host, no sync. The K/V pool and
the cache's device tensors are reused across forwards.
Frame-causal attention needs no mask: the staged tokens are cut into causal blocks
that run as one ragged batch over the same table, each with its own key count.
Each forward is a plan, cache.plan(num_tokens, causal_block_size), which
attention takes as kv=.
Exact window: a page table can only start a key sequence at a page boundary, so
each causal block gets a page list (causal_block_pages(size)) ending in a few
private pages that hold the visible slots of the up to three partly visible pages
(fixed-region tail, window-start page, earlier causal blocks' tokens in the causal
block's start page), then its own tokens. Both kernels read exactly the window in one launch, no mask,
no duplicated key: reading the page-aligned resident window instead deviates from
the fp32 exact-window reference by up to 0.006 (denoising) / 0.016 (clean pass);
this layout shows an observed 0.0002, at the scale of bf16 rounding. The layout
works for both backends because each causal block's new tokens stay the last keys
of its page list, which trtllm-gen requires (it writes them itself right after the
cached length); cheaper layouts that end a page list on prefix tokens work for cuDNN
only.
CUDA-graph safe: everything a kernel reads lives in persistent device tensors
rewritten in place at commit; device state survives close()/open(). The host
keeps a mirror of the page table (page_table()) for host-addressed edits and never reads the GPU back;
commit itself uploads nothing. A captured
forward is keyed on plan.graph_key (cache, spec, real token count, causal block
size) besides tensor shapes; commits change device contents and reuse the
graph, so the staging offset and the commit count are never part of a key.
Chunk K/V write: one kernel, new op trtllm::scatter_kv_slots_, reads the source
once with any token/head stride (no copy for K/V sliced from a fused QKV
projection) and writes each token to one or two pool slots.
pool_tokens_for / pool_bytes_for (static) and pool_bytes give the pool a
spec needs and the device memory it takes, before anything is built, so a
caller can size the pool for its largest spec or against a memory budget. The pool asks V2 for no resume headroom (nothing is ever
suspended), and the figure includes the allocator's chunk rounding; a test
measures the real allocation with the driver's free-memory counter. zero_values zeroes V of a logical range. Edits through
write_range / zero_values to committed tokens also update the private copies
the causal blocks read, so an edit takes effect on the next forward, not the next
commit.
Batch size 1 by construction; the cache knows nothing about parallelism (built
with the K/V heads this rank holds).
Attention.
cuDNN (_run_paged): cuDNN paged SDPA over the causal block page lists. Any
power-of-two page size.
TRTLLM (_forward_with_kv_cache): fused paged context kernel over the same page
lists; accepts separate q/k/v or one packed QKV tensor (no split copies). The page
sizes it takes are the ones the build has a kernel for:
support_kv_cache_page_size() asks the build, and the forward refuses others
(on H200, 16/32/64/128 all pass). Attention inside a causal block is FULL by
design. Its attention metadata is built once per (cache, spec, causal block
count and size), kept on the cache and released by shutdown(), and bound to the
cache's own tensors (causal_block_offsets(size), the per-causal-block key
counts), so like cuDNN it needs no refresh between a commit and a graph replay.
The plan's num_tokens is the global number of real query tokens of this forward,
before sequence sharding; seq_len keeps one meaning everywhere, the padded row count
the module derives from q.shape[1]. Under Ulysses a shard may carry padding rows the
sharder added so the sequence splits evenly. Without a cache those rows are attended
and their outputs dropped; with a cache a padding row staged as history would be
attended by every later forward of the rollout, and the tensor carries no marker of
where the real tokens end. So padding rows past the plan's count are neither staged nor
attended and come back zero, and commit() takes the planned count by default and
refuses another.
Backends declare support_kv_cache(); the Attention module and Ulysses refuse a
cache on any backend without support instead of silently dropping it through
**kwargs.
Ulysses: the plan is passed through untouched; the
cache path and grouped-query models use the per-tensor all-to-all (the fused path
stacks q/k/v and needs equal head counts). Async Ulysses refuses a cache.
attention/attention.py: the fused packed QK norm + RoPE wrapper passes the
rank-local head counts, so it runs under tensor parallelism with per-head norm
weights. Full-dim norm weights under TP raise.
KVCacheManagerV2._remove_kv_cache(request_id): the counterpart of
_create_kv_cache. V2's request teardown and guard-page bail-outs call it, and so
does the block-causal cache for its rollout sequence; a repeated call is a no-op.
Depends on [None][fix] Keep a one-rank DeviceMeshTopology off the job-wide device mesh #20021 (device_mesh.py: a one-rank Mapping must not borrow a
dimension of the job-wide mesh). The cache hands KVCacheManagerV2 a one-rank
Mapping; without [None][fix] Keep a one-rank DeviceMeshTopology off the job-wide device mesh #20021, rank 1 under Ulysses with MPI disabled read pipeline
rank 1 from the job's mesh.
