Summary
Stage 2 of the depth-sorting Phase 4 partial-upload work (Stage 1 = #607, merged). A progressive-LOD commit that merely extends an already-committed prefix — the common 4D-timelapse ladder-refinement case — now writes & uploads only the new [prevCount, count) suffix of the splat texture instead of the whole capacity-sized RGBA32F image.
Key design finding: no projection-kernel change needed
My earlier notes assumed Stage 2 required changing the WASM/TS project_gsplats_nd_to_3d return contract to expose an outputPrefixCount (with parity-harness blast radius). It doesn't. The nD→3D projection is per-splat-independent and order-preserving, and the loader appends LOD levels in order, so under an unchanged view state the (k+1)-level projection's first prevCount visible outputs are byte-identical to the previous commit's entire output. Therefore outputPrefixCount === prevCount (the committed visibleSplatCount) is deducible, not measured — collapsing the blast radius entirely.
The one genuine hole — truncate is a material uniform (uTruncate) outside viewStatesEqual — is closed by gating on a stamped committedTruncate.
What changed
types/gsplats-lineage.ts (new): a forward-chained prefix-lineage WeakMap, stamped in the loader's concatenateMemoized, checked in commit by identity against getCommittedData(mesh). Identity match proves same generation (a view change bumps the loader reset generation → no parent → append rejected), genuine extension, and that the GPU still holds that parent's projection.
commit-gsplats-geometry.ts: the append gate — hadCommittedData && !attributesRebuilt && geometry === prevGeometry (in-place pool reuse, which also bounds count ≤ capacity) && gpuPrefixIntact && splatCount > prevCount && lineage === committedData && committedTruncate === readTruncate. Stamps committedTruncate + gpuPrefixIntact on every full commit (self-healing).
gsplat-geometry.ts: writeSplatTexels(…, { fromSplat }) skips the prefix write loop and registers only the suffix dirty range; new writeSortedIndexIdentityRange extends aSortedIndex with identity for the appended range, preserving the prefix permutation.
gsplats-adapter.ts / gpu-buffer-pool.ts: thread fromSplat through updateGeometry.
node-factory.ts: rebuildAfterContextRestore now marks every splat texture + aSortedIndex full-dirty and clears gpuPrefixIntact, so a WebGL context restore never leaves a stale prefix under a following append (a dual mark+flag mechanism — the mark covers the no-commit case, the flag the following-commit case).
Pixel-identical; classic WebGL only (WebGPU re-uploads the whole image, Stage 3). Points/Lines symmetry (writeInterleavedAttribute(…, fromInstance)) is a documented follow-up, pending independent verification of their projection order-preservation.
Tests
suffix write + writeSortedIndexIdentityRange + pool append branch (splat-texture-storage.test.ts)
append gate: positive + 6 negatives — no lineage, context-restore, attribute rebuild, equal count, truncate mismatch (commit-gsplats-geometry.test.ts)
lineage forward-chain / view-change reset / memoized-noop identity (gsplats-progressive-loader.test.ts)
context-restore full-dirty (node-factory.test.ts)
Full rendering + data unit suites green (179 files, 3282 tests); typecheck, eslint, check:layers clean.

Double-check finding (empirically proven with a FinalizationRegistry
experiment): a WeakMap holds its VALUE strongly while the key is
reachable, so the forward-chained prefix-parent map pinned EVERY
intermediate concat of a generation for as long as the newest stayed
committed — ~(n-1)/2 x the final CPU arrays on an n-level ladder,
indefinitely on a static view (hundreds of MB on 10M-element datasets).
Pre-existing: shipped with the gsplat Stage 2 in #613, inherited by
Points/Lines here.

- setPrefixParent now deletes the superseded parent's own entry when
  linking a child (chain capped at depth 1); an in-flight older commit
  reads undefined and degrades to a full rewrite (safe).
- All three commits consume-and-clear the entry right after the gate
  check, releasing the parent as soon as the append/full-write decision
  is made; a retry after a throwing write full-rewrites.
- New direct test suite for the shared module (chain cap, clear-on-null,
  self-link guard) + consumption assertions in the three commit suites.
- Docs: retention contract in the module header + spec §7 + CHANGELOG;
  concatOptionalField now documents its coupling to the gates' presence
  conjuncts.

3512 unit tests green; typecheck/eslint/check:layers clean.

Third double-check (feature-wide: #613 + #617 as one unit) finding: the
gsplat append gate has NO optional-field presence conjunct — unlike the
points/lines gates added in this PR — and that asymmetry is correct but
rested on an UNDOCUMENTED exactness invariant: a null→colored ladder
transition re-fills the concat prefix with 255/65535/1.0 white fills
whose coercion (fill × (1/fill)) is bit-identical to the colorless
projection's fillColorsWhite 1.0 (verified: exact in f32 for both 255
and 65535). Documented in the gsplat gate comment and pinned with a
mutation-proof 'append-gate invariant' test in coerce-colors.test.ts —
if a future normalization change breaks the exactness, the test fails
and names the gate that then needs a presence conjunct.

Full unit tree green (8936 tests); typecheck/eslint/check:layers clean.

* perf(viewer): Points & Lines append fast path — depth-sorting Phase 4 Stage 2, three-geometry symmetry

A progressive-LOD commit that merely EXTENDS the committed prefix now
writes & uploads only the new [prevCount, count) instance suffix for
Points and Lines too (gsplats landed in #613):

- types/gsplats-lineage.ts -> types/prefix-lineage.ts: the forward-chained
  prefix-parent WeakMap is geometry-agnostic and now shared by all three
  loaders/commits.
- writeInterleavedAttribute(..., { fromInstance }): full-length source,
  suffix-only copy, min-start/max-end dirty-range union; threaded through
  writePooledAttribute, both pool adapters, and the pool facades.
- Append gates in commit-points/lines-geometry mirror the gsplat one
  (lineage identity vs committedData, in-place pool reuse, gpuPrefixIntact,
  strict count increase) minus preserveOrdering/committedTruncate, plus an
  optional-field presence conjunct: the all-or-nothing concatOptionalField
  means a Float32<->absent flip re-fills a column with a constant the
  committed prefix need not match (invisible to the pool's dtype matching).
- Pre-existing fix: concatenateLinesData filled missing-part sharpness with
  0.0 while the projection defaults null sharpness to 0.5 — mixed-sharpness
  ladders popped razor-sharp; now fills 0.5 (mirrors the white color fill)
  and makes the Lines prefix-identity contract hold.
- NodeFactory.rebuildAfterContextRestore now marks points/lines interleaved
  instance buffers (and plain attributes on the non-pool points layout)
  full-dirty and clears gpuPrefixIntact, same dual mark+flag contract.

Order-preservation verified for both projections: the Points zero-radius
drop is a pre-concat per-level forward scan; Lines clipping is an
order-preserving drop + in-place endpoint clip (never splits/reorders).

Tests: 6 fromInstance writer tests, 6 gate tests each for points/lines,
lineage forward-chain/view-reset/memoized-noop for both loaders, the
mixed-sharpness 0.5-fill, and context-restore full-dirty for points/lines.
