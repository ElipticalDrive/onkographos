Depends on #733.
gsplat-unity only supports Metal, Vulkan, and D3D12 due to its dependency on b0nes164/GPUSorting. Unfortunately, this is because D3D11, OpenGL, and WebGL can't support the kind of GPU sorting gsplat-unity uses. WebGPU can support this kind of GPU sorting, but annoyingly Unity doesn't expose the required APIs to make it possible. It is true that the vast majority of PCs that will be running anything made with Cesium for Unity probably have a D3D12-compatible GPU. Most mobile phones probably even support Vulkan. It's very possible we could get away with a lack of support for D3D11 and OpenGL. However, WebGL/WebGPU support is vital.
There are some options we can look into, but it will require modifying gsplat-unity (either as a fork, as a pull request to the original project, or as both). WindyYam/UnityGaussianSplatting_WebGPU_Export uses a WebAssembly CPU fallback (much like CesiumJS does) for web platforms. arloopa/UnitySplats is a (vibe-coded) fork of gsplat-unity that adds similar CPU sorting capabilities to all render backends. We can look into integrating a CPU sort fallback into gsplat-unity based on these repos.
