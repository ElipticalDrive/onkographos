Issue body actions
🤖 由 JasonGu 的 AI agent（DeepSeek V4.1 Flash / OpenCode）提交。
现象
渲染管线没有任何规模化手段：
没有视锥剔除：scene_render_system_into 只按 Active 过滤，相机完全没参与；
没有包围盒数据：DrawItem 里没有 bounds，网格管理层也不算 AABB —— 想剔除也没数据；
没有实例化 / 合批：每个实体一次 cmd_draw_indexed(..., instanceCount = 1, ...)；
没有 LOD（全仓库 grep -i lod 只命中 MaterialAsset::occlusion 之类无关词）。
结果：场景里 1000 个箱子 = 2000 次 draw（主通道 + 阴影通道），
每次还带一次 cmd_bind_vertex_buffers + 一次 cmd_push_constants + 一次
cmd_bind_index_buffer；其中一半还在相机背后。
证据
（1）提取阶段不看相机。 crates/prism-engine/src/scene/systems/render.rs:53-81：
```
pub fn scene_render_system_into(world: &World, out: &mut Vec<DrawItem>) {
    out.clear();
    out.extend(
        world
            .query2::<LocalToWorld, MeshRef>()
            .filter(|(e, _, _)| world.get::<Active>(*e).map(|a| a.0).unwrap_or(true))
            .map(|(entity, wt, mr)| DrawItem { ... }),
    );
}
```
函数体里没有 view_proj、没有相机实体、没有任何距离/包围体判断。
lights.rs / ui/render.rs 同理。
（2）没有可用来剔除的数据。 crates/prism-render/src/render_graph.rs:351-372：
```
pub struct DrawItem {
    pub mesh: MeshHandle,
    pub model: [[f32; 4]; 4],
    pub material: Option<u32>,
    pub cast_shadow: bool,
    pub visible_in_main_pass: bool,
    pub cast_shadow_two_sided: bool,
    pub state: DrawState,
}
```
网格句柄只有 MeshHandle，而
```
$ grep -rni "aabb\|bounds\|min_extent\|max_extent" crates/prism-render/src/managers/*.rs crates/prism-render/src/mesh.rs
（无输出）
```
也就是说导入的网格连 local AABB 都没算。（编辑器点选之所以能工作，是因为它拿
单位立方体当代理 —— 见 #438。）
（3）每个实体一次 draw，且带完整状态重设。 crates/prism-render/src/forward_pass.rs:1595-1652：
```
if item.state != bound_state { cmd_bind_pipeline(...); }        // 只在状态变时
cmd_bind_vertex_buffers(ctx.cmd, 0, &vertex_buffers, &offsets); // 每个 item 都做，且是同一个 buffer
cmd_push_constants(ctx.cmd, pipeline.layout, ..., &pc);         // 每个 item 一次
cmd_bind_index_buffer(ctx.cmd, ib, 0, vk::IndexType::UINT32);
cmd_draw_indexed(ctx.cmd, uploaded.index_count, 1, 0, 0, 0);    // instanceCount = 1
```
阴影通道同样逐项（crates/prism-render/src/shadow_map_pass.rs:494-496），
所以一个实体一帧至少要 2 次 draw。
全仓库 grep draw_indexed_indirect|instance_count|cmd_draw_indirect 在渲染侧
只命中离线烘焙代码（bake_common.rs:70,321），运行期一次间接绘制都没有。
对照
Unity 里 LOD 是一等公民，有专门的编辑器与运行期切换：
Editor/Mono/Inspector/LODGroupEditor.cs:20 [CustomEditor(typeof(LODGroup))]，
:32-36 直接编辑 m_FadeMode / m_AnimateCrossFading / m_LODSize /
m_GlobalIlluminationLOD。剔除与实例化在原生层（C# 侧只有 Renderer.isVisible
这样的读写口），参考树里没有对应 C# 实现，所以这条只对比「有没有这个能力」。
影响
移动端最痛：Android 上典型的 tile-based GPU，一个 300 万面的 Sponza
缩到手机上，prism-sponza 这种场景的 draw call 数会先撞上限；
阴影通道把 draw 数翻倍，而阴影贴图通常只覆盖相机附近一小块区域；
静止场景也每帧全量提交（editor-egui 声称「静止视口零 GPU 工作」只对编辑器成立，
游戏里 Engine::update 每帧都重建绘制列表）；
加一个物体性能就掉一截，没有「用更远的模型 / 更小的 LOD」这种调节手段。
建议（按性价比排序）
先补 AABB：网格导入时算 local AABB（managers 里 RenderMeshManager 存一份），
DrawItem 加 bounds: [f32; 6]（或中心 + 半径）；这一步顺带让 bug(editor): selection proxies ignore rotation and box-select containment #438 的点选
从「单位立方体」变成精确命中，也能给编辑器加「显示包围盒」；
视锥剔除：scene_render_system_into 加相机参数（或改成
scene_render_system_into(world, &CameraPlanes, out)），对 world AABB 做
正/负顶点 测试；这条几十行代码，收益最大；
实例化：同一 MeshHandle + material + DrawState 的连续项合并成一次
cmd_draw_indexed(..., instance_count)，模型矩阵走 per-instance SSBO
（push constant 只留材质槽 / debug_flags）；先做「相邻同类合并」就够，
不必立刻上 VK_EXT_multi_draw_indirect；
LODGroup 组件（prism-scene 新组件 + 提取阶段按屏幕占比选级），
对齐 Unity 的 LODGroup；
阴影通道只提交阴影相机视锥内的投射者，别用主相机列表。
区域
area/render；crates/prism-engine/src/scene/systems/render.rs、
crates/prism-render/src/{render_graph.rs,forward_pass.rs,shadow_map_pass.rs,managers/}，
新组件落在 crates/prism-scene/src/components.rs。

🤖 Agent: 建议里的前两项已合并（PR #638 → 7e86f92）。issue 保持 open，剩余部分说明如下。
已实现
网格局部 AABB：prism-render::culling::Aabb，MeshUploadInput::bounds() 用解析器已解出的顶点位置算包围盒；CPU 段（prepare_requests）在发请求前算好，句柄回来后写进 MeshBounds（MeshHandle → Aabb 的 World 资源）。同一个网格多实体复用只存一份。
主相机视锥剔除：Frustum::from_view_proj（列主序、Vulkan 深度 [0,1]：近平面 row2、远平面 row3 - row2），scene_render_system_into_with_frustum 按世界 AABB 做保守相交测试（p-vertex），extract_frame_packet_into 每帧用 view_proj 建视锥。
保守退化：没有包围盒（程序化网格 / 标定球 / gizmo / 未解析）、包围盒无效、模型矩阵非有限、view_proj 退化 → 不剔除。旧的 scene_render_system_into / SceneReadView::draw_items_into 行为不变（等价 frustum = None）。
阴影通道与主通道共用一份 DrawItem 列表，所以相机外的投射者也不再进阴影贴图（Unity 同样是「只为可见物体渲阴影」）。
没做 / 建议的下一步
阴影通道按光源视锥剔除：需要 DrawItem 带世界 AABB 或让 shadow_map_pass 自己测；目前复用主相机剔除。
实例化 / 合批：仍然每实体一次 cmd_draw_indexed(instanceCount = 1)，完整状态重设（bind vertex/index/push constants）。先做「相邻同 MeshHandle + material + DrawState 合并」即可，per-instance 模型矩阵走 SSBO。
LODGroup 组件：prism-scene 新组件 + 提取阶段按屏幕占比选级；有了 AABB 之后屏幕占比只差一个投影半径计算。
编辑器侧：包围盒数据已经可用 → 可以直接接 bug(editor): selection proxies ignore rotation and box-select containment #438 的精确点选、「显示包围盒」开关、以及视口统计里的「提交 / 剔除」计数。
剔除目前只按主相机：正交相机、多相机（feat(engine): only one camera is rendered; extra cameras are ignored #461 的多相机合成）需要按相机分别剔除。
验证与限制
新增 22 个单测（数学层 15 + 网格包围盒 2 + 提取层 4 + 解析链路 1），覆盖相机前后 / 远近平面 / 侧向 / 跨平面 / 包含相机、平面单位化、退化矩阵、无效包围盒、模型变换、Active 过滤以及 frustum = None 与原行为一致。
没有端到端画面验证：本机 3D 场景加载坏着（只有清屏灰，stash 本会话改动后依旧，怀疑是未提交的 loader.rs WIP），所以帧数/draw call 的实际下降没能实测。合并后建议在一台能正常加载的场景上抓一次 draw_items.len() 或 Render Graph 报告对比。
（顺带：MeshBounds 只增不减，等做网格 unregister / 热重载时一并清理。）
