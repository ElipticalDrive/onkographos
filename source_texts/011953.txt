What kind of idea is this?
A brand-new experiment
The idea
A split-panel experiment: the left panel is a top-down 2D grid map the user can edit by toggling walls; the right panel renders the first-person 2.5D view produced by casting one ray per screen column. The player moves through the map with WASD + mouse look (pointer lock), or arrow keys on mobile.
The algorithm used is DDA (Digital Differential Analysis) - the same technique as the original Wolfenstein 3D engine. A toggle overlays the ray grid on the 2D map, drawing each column's ray as a colored line that stops at the first wall it hits, with the step increments shown as small dots on the grid cells the ray passes through. Slowing the frame rate to 2-5 fps via a speed slider makes each column scanline's ray visible as it sweeps left to right, showing exactly how the wall heights in the right panel are computed from ray lengths in the left.
Wall colors vary by face (N/S darker than E/W) to preserve directional depth cues. A distance-fog overlay darkens walls by reciprocal distance.
Why is it worth building?
The Wolfenstein/DOOM-era ray casting trick - projecting a 2D grid into a faux-3D view with a single pass of cheap ray-grid intersections - is historically and technically fascinating. It demonstrates how a 2D pathfinding-style grid can be rendered at interactive framerates long before hardware 3D acceleration existed, and it makes the connection between 2D spatial data and a rendered image concrete and traceable.
The DDA overlay is the educational centerpiece: every column in the 3D view maps back to exactly one ray in the 2D map. Seeing both simultaneously collapses the "how does this even work" mystery into something a viewer can follow column by column. It pairs naturally with the pathfinding experiment, since both operate on the same tile-grid abstraction.

We're on this.
The 2D-3D split with the column-by-column DDA sweep is the experiment - the 3D view is evidence that a flat grid is enough. Making each screen column traceable back to a specific ray on the map, at interactive speed, is the kind of demystification this repo exists for. The slow-frame mode that lets the scanline sweep be watched in real time is the differentiator.
Ray casting is the first move in a rendering algorithms track:
Path tracer - recursive ray-triangle intersection with BVH traversal shown on the geometry. Progressive sample accumulation per frame so the image builds from noise into clarity in real time. The jump from ray casting (2D grid, one bounce) to path tracing (3D mesh, arbitrary bounces) is a single conceptual step made visible.
Rasterization pipeline visualizer - vertex transform, near-plane clipping, and scanline fill shown stage by stage as a triangle is processed. The GPU pipeline as a step-through animation rather than a black box.
If the question of how images are made from geometry interests you, the full thread is coming.
