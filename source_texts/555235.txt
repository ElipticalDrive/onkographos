Summary
donut_median_fill now takes the median over the unmasked donut neighbours only. Before, every neighbour's original value entered the median, so at a 5 % Bernoulli mask about 74 % of held-out voxels leaked their value into a neighbour's replacement and the fitted volume was not independent of the held-out set that blind-spot cross-validation scores against. The filled volume is now invariant to the values at masked positions; voxels whose donors are all held out expand one Chebyshev shell at a time until a local unmasked donor is found. gsplat cal inherits the change (K* may shift marginally; the paper's fill-ablation experiment quantifies it).
New tests: invariance to held-out values, masked-neighbour exclusion (hand-built 3×3×3 case), nearest-shell expansion, genuine-NaN propagation, bounded-chunk equivalence, and all-masked error.
Docs: amplitudes are background-relative image intensities, not calibrated fluorophore concentration (README, VOLUMETRIC_BLENDING_SPEC); unsupported super-resolution/upsampling bullets removed; GSPLATS_DIMENSION_MAPPING states the displayed covariance is the marginal (not the conditional) and documents the shipped joint-Mahalanobis, shifted-Gaussian hidden-axis attenuation; GSPLATS_ZARR_FORMAT calls the Q·e(k) stamps a heuristic estimate rather than a committed quality.

Reviewed at 913a1cc. I read the full masking.py, both consumers (calibration/driver.py:204 and the cal CLI in cli/gsplat_ops/fitting/calibrate.py), and checked every substantive claim in the docs edits against the shipped kernels. The core change is right — the leak is real and the fix is the correct one — but the branch is red and the fill got materially more expensive, so this needs another pass.
What it does. donut_median_fill now medians only the unmasked donut neighbours (mask reflect-padded alongside V, held-out donors marked with NaN and dropped by nanmedian), with a global-unmasked-median fallback when every donor is held out and a hard error on an all-True mask. Four new tests. Plus a batch of doc corrections: amplitudes described as background-relative intensities rather than fluorophore concentration, the super-resolution bullets replaced, the displayed covariance documented as the marginal (not the conditional), the hidden-axis attenuation documented as it is actually implemented, and the Q·e(k) stamps re-labelled a heuristic estimate.
I agree with the premise. The old fill let a held-out voxel's value into a neighbouring held-out voxel's replacement, so the fit target was a function of the values being scored — at 5 % Bernoulli that is 1 − 0.95²⁶ ≈ 74 % of held-out voxels, which matches the number in the PR body. Excluding them restores the invariance the blind-spot argument needs.
critical / major
major — test_sparse_volume_selects_on_foreground_weighted_curve fails at this head. packages/luxar/src/luxar/gsplats/tests/test_calibration.py:927. The test plan says 110 passed; I get 109 passed, 1 failed (hatch run pytest packages/luxar/src/luxar/gsplats/tests/test_calibration.py), deterministically, both in-suite and run alone. python-tests will go red.
The failure is caused by this change, not flake. A/B on the same volume/grid, with only the fill swapped:
```
OLD fill: minmax [39.607, 40.823]  fg_weighted [26.007, 27.257]
          selected signal_limited k*=60 conf=1.2501 / default conf=1.2160  -> PASS
NEW fill: minmax [40.502, 39.894]  fg_weighted [26.922, 26.316]
          selected plateau       k*=20 conf=0.0    / default conf=0.0     -> FAIL
```
At mask_fraction=0.2 on a 16³ sparse-blob volume the new fill flips both curves from rising to falling, so find_k_star returns plateau with confidence_db == 0.0 on both metrics and the last assertion (selected.confidence_db != approx(default.confidence_db)) can no longer hold. The test's intent — "the fg-weighted curve is genuinely a different curve" — is still worth keeping; it just needs a K grid / mask fraction where neither curve is degenerate (or an assertion on the curves themselves rather than on confidence_db being non-equal). Please re-tune it in this PR rather than loosening the assertion to nothing.
major — the fill is ~2× slower and ~3× peak memory, and the docstring understates it. packages/luxar/src/luxar/gsplats/calibration/masking.py:123-134. Measured (5 % cv_mask, float32, tracemalloc peak):
```
128³  masked 104,599   old 0.30 s /  34.8 MiB    new 0.66 s / 107.6 MiB
192³  masked 353,965   old 1.29 s / 117.3 MiB    new 2.49 s / 363.6 MiB
256³  masked 837,631   old 3.04 s / 277.2 MiB    new 5.71 s / 860.0 MiB
```
Peak ratio is 3.10× at all three sizes and linear in masked count, so a 512³ volume extrapolates to ~6.9 GiB in this one call (vs ~2.2 GiB before) — and cal defaults to --no-auto-region (cli/gsplat_ops/fitting/commands.py:232), i.e. the whole volume, so that is the default path, not a corner. Two causes: the gather is now unconditionally float64 (2× the old V.dtype buffer), and np.nanmedian with a.shape[0] = 26 < 600 routes through numpy's _nanmedian_small, which builds a masked-array copy — that is the extra factor, and it is also where the 2× time goes.
masking.py:74 claims the cost is "(2r+1)^D - 1 float64 values per masked voxel", which is 166 MiB at 256³ — five times under the measured 860 MiB. Fix direction: drop the NaN sentinel and keep the gather at V.dtype (or float32), pushing invalid donors to the end of a np.sort along axis 0 and selecting at (count-1)//2 / count//2 — exact median semantics, one copy, no nanmedian, no catch_warnings; and/or chunk the masked positions (e.g. 10⁶ at a time) so peak memory is bounded by chunk size instead of volume size. Either way, correct the docstring to the real figure.
minor / nit
minor — NaN is now overloaded as the held-out sentinel, so a genuine NaN in the data is silently dropped. masking.py:127-128. On a 3×3×3 volume of ones with V[0,0,0] = nan and only (1,1,1) held out: old fill gives nan at the centre, new fill gives 1.0. Dropping a real NaN donor is arguably nicer behaviour, but it is undocumented and it means the function can no longer distinguish "held out" from "not a number". A separate boolean validity array (which the sort-based rewrite above wants anyway) keeps the two apart and lets you decide explicitly.
minor — "practically unreachable" is only true for an i.i.d. Bernoulli mask, and the fallback is a global constant. masking.py:67-70. The f^26 estimate assumes independent hold-outs; mask is a caller-supplied argument on a public entry point (luxar.gsplats.donut_median_fill, documented with a usage example in calibration/README.md:83). With a contiguous block mask on a 10³ volume, 29.6 % of held-out voxels landed on the fallback in my run — i.e. filled with the median of the whole unmasked volume, a large silent quality cliff. Cheapest fix that keeps invariance: widen the donut radius for just those voxels until an unmasked donor is found (still a function of unmasked values only); at minimum, note in the docstring that the estimate assumes an independent mask and warn when the fallback covers a non-trivial fraction.
minor — the new ValueError on an all-True mask is undocumented. masking.py:113-114. Behaviour change: a fully-masked input used to return reflect-derived medians (donut_median_fill(np.ones((1,1)), np.ones((1,1),bool)) returned [[1.]], now raises). The error is the right call, but the docstring has no Raises section and the two README summaries (gsplats/README.md:702, calibration/README.md:15) do not mention it.
nit — test_calibration.py:277 can't fail. assert 0.0 <= filled.flat[flat[-1]] <= 1.0 on a volume whose values are all 0 or 1: any median of any subset satisfies it. Assert the actual expected fill for that voxel instead, or drop the line — the useful assertion is the one above it.
nit — masking.py:127 relies on advanced indexing always copying. V_pad[shifted].astype(np.float64, copy=False) is safe today only because shifted is a tuple of index arrays; if that ever becomes basic slicing, vals[...] = np.nan writes through into V_pad. A one-line comment (or an explicit copy=True) would pin the assumption. I confirmed no write-through happens today, including for a float64 input.
checked and clean
Invariance is complete, not just on the donut path: the all-donors-masked fallback also reads unmasked voxels only, so donut_median_fill output is a strict function of the unmasked set. Verified with a 30 % random mask (the new test) and independently with a contiguous block mask.
Reflect-padding the mask alongside V is index-consistent. Hand-checked in 1D (V=[a,b,c], both mask patterns) — a reflected copy of a held-out voxel carries True, so it stays excluded. This is also implicitly gated by the new invariance test, which would fail at the volume edges if the mask weren't padded.
Integer volumes round-trip identically to before (uint8 3³ case: 13 both ways); size-1 axes and radius >= axis length behave exactly as on the base commit; no write-through into V or V_pad.
warnings.catch_warnings() scope is tight enough (one nanmedian call, restored on exit) — no cross-test filter leakage.
Docs: I checked the GSPLATS_DIMENSION_MAPPING.md step 3/4 rewrite line by line against src/wasm/rust/src/gsplats_processing.rs:339-488. What changed since 913a1cc. The float64/nanmedian gather is gone. _masked_donor_medians now gathers donors into a preallocated (n_offsets, chunk) buffer in the input dtype, stamps held-out donors with a sortable-high sentinel (+inf / iinfo.max / True), sorts along the donor axis and reads the median at (count-1)//2 / count//2 — exact median semantics, one buffer, no masked-array copy. Chunking is bounded by _MAX_DONUT_BYTES (16 MiB). Genuine NaN donors are tracked in a separate has_nan flag so they stay distinct from held-out donors and still propagate. The global-median fallback is replaced by per-voxel Chebyshev-shell expansion (donut_median_fill:121-133), which keeps the fill local and keeps the invariance.
