Owner
Label-occlusion raycasts repeatedly allocated column tuples and tile-key strings, dominating short-lived main-thread allocations. This change caches column resolution by finest-tile footprint and reuses scratch storage across visibility, navigation, and streaming updates.
Changes
Bounded, versioned world-query cache, including missing tiles; remove per-step column tuples while preserving finer-tile precedence and eviction invalidation.
Reuse label ordering, rectangles, and vectors; avoid rewriting unchanged transform strings. Stop settled layout/occlusion work, with camera, world, active visibility, UI, fonts and selected-place invalidation.
Replace repeated tile-candidate sorting with a stable priority heap and compact leaf arrays in place. Reuse a bounded metadata-only descriptor workspace and lazily cached tile keys.
Use a dense active-LOD lookup for label/light gating; reuse selection sets and eviction buffers.
Reuse navigation and shadow-fit math objects.
Skip unchanged daytime scene/post-processing draws after settling. Keep the lightweight update loop for input, streaming, labels and diagnostics; F3 explicitly reports idle. Precompute water-only bounds on mesh admission and keep potentially visible water and nighttime beacons animated.
Add allocation profiling and differential/integration checks.
Measurements
Desktop Chromium 156, GTX 1080 Ti, 1600×1000 DPR 1. Eight-second main-thread allocation captures include objects collected during sampling.

The fixed-LOD comparison used identical 72 tiles / 3,196,522 triangles. Recorded GC time fell from 127.4 → 7.3 ms stationary and 102.7 → 16.7 ms moving over each capture. Frame time remained approximately 6.06 ms.
These are sampled allocation estimates, not exact allocated bytes or retained heap. Worker heaps are excluded. Profiling adds overhead; adaptive timing varied between captures, including an initial Civic regression. No general FPS improvement is claimed. Remaining allocations include Three.js, N8AO, moving-label CSS strings, and streaming results.
Profiling captures and validation reports stay local under ignored artifacts/profiling/. Reusable profiling and validation scripts remain in web/tools/; measured results are summarized here.

Exact comparisons against previous code: 24 selector cases, 32 pooled-selector transitions, 770 label frames including settled/invalidation, 120 navigation frames.
Packed/expanded day/night pixel comparisons passed.

Baseline: cf1c7e1. Implementation: 98283fe and d328345. Measurements use the same local dataset on both revisions, including separately uncommitted vegetation changes; those data changes are excluded from this PR.
Near-zero follow-up
A controlled 1,000-selection Node/V8 microbenchmark against 98283fe reduced sampled allocations from 124,948 to 37,885 bytes per selection (69.7%), and measured 0.647 → 0.551 ms per selection. Workspace construction is excluded; the pool is bounded to 1,304 metadata descriptors and retains no mesh/query payloads. Settled labels stop repeating raycasts and layout until invalidated.
Whole-renderer follow-up captures were mixed, with materially different frame cadence. They do not establish a broad allocation or FPS gain. Three.js/N8AO remain prominent allocation sites; dependencies are unchanged. Production build, streaming/context recovery, eight shadow cases, and 5,712 UI gating comparisons passed.
Stationary rendering
Loaded, unchanged daytime views without water intersecting the frustum now skip scene/post-processing draws. Camera/target/projection, active tile visibility, lighting, resize, F4 and context restoration wake rendering; unused tile eviction does not. Water bounds are computed once from emitted quad records, retain no duplicate geometry, and conservatively cover water faces. Nighttime rendering remains continuous for beacons. The animation/update callback still runs; this is not a full event-driven scheduler or a zero-allocation guarantee. Current AO accumulation is disabled, so no temporal AO convergence is interrupted. ?continuous=1 retains continuous drawing for diagnostics.
In a five-second sampled capture of the same close downward Civic view, continuous drawing issued 829 composer draws and sampled 12,850,212 bytes; idle issued zero draws and sampled 287,336 bytes (97.8% lower). This is a single local main-thread allocation comparison with diagnostics hidden, not an FPS gain or a guarantee for animated/streaming views. Workers are excluded.
Production build and differential checks passed. Browser checks passed for idle/forced-redraw image equality, F3 idle statistics, camera/keyboard/hour/date/resize/F4 wake-up, water/night animations, and tinted-water animation. Streaming/context recovery and eight shadow scenarios also passed. Run node tools/check-idle.mjs from web; set PROFILE=1 for the optional allocation comparison. Captures remain local.
