Owner
This PR repairs the loader boundary bugs and quadratic work found in the audit, then integrates Gaussian splats with the scene renderer. It includes the original repair batch and the follow-up fixes in one branch.
Changes
Check glTF accessor/buffer ranges, declared lengths, alignment, strides and allocation counts. Share checked layouts with the main glTF loader and support sparse splat attributes without losing UInt32 precision.
Reject malformed SPZ headers/stream ranges and compressed KSPLAT bucket tables. Move owned output arrays instead of copying them.
Use stable O(n log n) sorting for large unordered render lists; preserve ordered and small-list fast paths.
Replace selection's repeated full-list scans with node indexes, and fracture's vertex-squared Boolean storage with directed edge pairs.
Add scene-owned splats, transparent object ordering, CPU worker-band drawing, viewport projection, glTF node placement and independent cloned geometry.
Add mixed GPU draw packets and a CPU/GPU parity test. Include splats in tone-mapped data/blend validation and preserve splat-bearing nodes during optimization.
Extract render-list ordering and isolate the pinned private Mojo task-runtime import.
Record 33 fixture families, generator commands, version evidence and artifact hashes; pin the benchmark to its existing three.js 0.170.0 lock.
Publish the node JSON compatibility table and fail fast when Xvfb cannot start.
Refs #247. Detailed findings, timing evidence and remaining work: audit report.
Validation
615 CPU tests passed across 16 suites, including renderer, rasterizer, hooks, visibility, geometry tools, selection, glTF, splat loaders, scene optimization and new regressions.
40 GPU host-layout tests passed; these do not use a physical GPU.
22 changed production modules passed Mojo documentation/type checks with warnings treated as errors.
The full GPU suite compiled for nvidia:sm_75. A fresh smoke build of the mixed-splat parity case also compiled against the final source.
Formatting, documentation checks, all 18 Python tooling tests, fixture hash checks and git diff --check passed.
All 209 compile-fail cases were rejected.
Scene JSON and glTF exports explicitly reject registered splats instead of silently omitting them; the regression checks both exporters and valid empty scenes.
Uploaded tree verified identical to the local staged tree.
Why this is a draft
This is not a claim that every audit item or three.js feature is complete. Full make check, final repository-wide 100% coverage, and physical GPU parity remain merge gates. This host has no GPU, and Xvfb cannot open its required local sockets. The original repair pass had 100% focused loader/sort coverage; that is not coverage of this expanded final change.
The report explicitly leaves volume scene-depth termination/rectangle lights/ray shadow graphs, unsupported TSL/material storage-buffer classes, GPU tile-list profiling, further pipeline extraction, and splat serialization open. Unsupported scene-splat exports now fail explicitly. Historical sRGB-generator and VTK XML-dependency versions remain unknown rather than being invented. Mesh naming still uses file order after reserving node names.
The separate upstream renderer-performance branch is unchanged.

Keep a frame's triangles as slim corners and a surface a draw
…
017dd23
```
A RasterVertex is 1024 bytes, and every corner of every triangle carried
its draw's whole material: 61 of its 84 fields. Preparing a frame of
spheres wrote tens of megabytes, and was over half the frame.

Corner holds the 23 fields that differ from corner to corner, 256 bytes,
and names a Surface, which holds the rest once a draw. The renderer's
emitters still build whole corners, on the stack, and _Slim splits each
as it is appended. rasterize_frame has an overload for slim corners: it
asks each surface its checks once, and joins each triangle's corners to
their surface as it draws it, where they stay in the cache. The overload
on whole corners keeps its checks and draws through the same path.

Frame holds the slim lists, and whole_corners() gives them as prepare
returns them, for the GPU and the tests. The GPU's kernel and layout are
unchanged. All 61 benchmarked examples draw byte-identical images;
layers draws 1.85 times as fast and coats 1.75 times.
```

```
draw copied the frame's whole list so far, and a scene of many meshes
paid quadratically. On a 97-mesh arm of two million triangles the vertex
```
