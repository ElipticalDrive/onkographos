I have added a new teleportation strategy called SPIRAL that is entirely deterministic and therefore allows server admins to know exactly where bingo games will take place; predominantly for the purpose of pre-generation. The reason I did this is because I host bingo events with many players and we have struggled with slow chunky generation with 10-15 players all running in different directions simultaneously, and has issues with the spawn taking a while to appear after teleportation.
I see this as a more efficient approach than GRID since it allows you to know for sure that the spawn points are far away from each other (20k blocks by default, preventing cheating / item stashing between rounds), and also being able to pre-generate say a 2k block radius around each spawn point (either manually, or with the new command that integrates with the Chunky API). If you tried to do this approach with GRID, you would have to pre-generate an impossible amount of chunks, most of which would never be used.
The new config settings are very similar to GRID, specifying the centre of the spiral (the first round position) and the step size of the spiral, as well as whether to skip ocean spawns.
A new command has been added as well, similar to GRID, at /bingo spiral with some sub-commands:
status, which outputs the current spiral step and where the next spawn will be.
reset, which resets the spiral step back to 0, making the next spawn (0,0). Useful if the world has been reset.
pregen <rounds> <radius>, which calls on Chunky to pre-generate the overworld and nether for <rounds> many rounds in advance for a block radius of <radius> (The nether is pre-generated at 1/4 the radius of the overworld). The command is also programmed to gracefully error if Chunky is not present on the server. The pre-generation is setup to also skip ocean spawns if the config specifies, to increase efficiency by not pre-generating a spawn that will not be used.
It should be noted that I have not implemented the Chunky API on fabric, only paper. If the command is run on fabric, it simply displays a message saying it is not implemented yet.
