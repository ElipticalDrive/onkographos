Summary
Fix two silent quality regressions in 3D volume rendering:
Blank-frame GPU-fallback false positive: A legitimately empty 3D view (e.g., CT Bone on a bone-free scan) was misclassified as a GPU failure and locked to CPU ray casting. Now uses transfer-function-aware occupancy analysis to distinguish expected blanks from genuine GPU failures; expected blanks remain on GPU and do not suppress auto-refinement.
~8× memory amplification in volume build: Peak RSS reduced by eliminating intermediate copies (in-place calibration), using shallow VTK references, and automatic pre-allocation downsampling. A synthetic 512×512×800 test case with smoothing measures 1438 MiB peak vs. 3274–3276 MiB baseline.
Changes
New src/core/volume_data_preparation.py: VTK-free preparation of volume data, split from renderer for testability and background-thread safety. Includes automatic integer downsampling based on available system RAM (20%, capped at 2.5 GiB).
Enhanced src/core/volume_render_quality.py: Full-coverage scalar histogram binning, transfer-function evaluation helpers, and downsampling policy (pure, deterministic, no OS probing).
Refactored src/core/volume_renderer.py: Three-way GpuFallbackOutcome enum replaces bool; tracks occupancy and downsampling state; uses numpy_to_vtk(deep=False) with explicit backing-array ownership.
Updated src/gui/volume/first_paint.py: Conditional refinement and user messages based on fallback outcome; added interactive re-probing after transfer-function changes.
New src/gui/volume/render_status.py: Pure formatting for downsampling factor and memory-budget disclosures.
Enhanced src/gui/dialogs/volume_render_dialog.py: Screen-aware initial sizing; visible downsampling notice for large volumes.
Comprehensive test coverage: 68 tests covering occupancy evaluation, downsampling policy, in-place calibration safety, shallow-reference lifetime, and interactive fallback re-probing.
