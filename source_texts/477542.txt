Closes #63.
Adds a Points primitive for large unconnected point clouds (voxel fields, metrology/deviation clouds, LiDAR scans), where add_polyline would wrongly connect points and one box/sphere per point is far too heavy.
API
```
v.add_points(
    "cloud",
    positions,                 # (N, 3) float32
    colors=signed_dev,         # (N,) scalar -> colormap, or (N,3) RGB, or None
    colormap="viridis", cmin=None, cmax=None,
    color=0xFFFFFF,            # used when colors is None
    size=2.0,                  # base point size (px)
    size_attenuation=True,     # perspective shrink with distance
    parent=None,
)
```
Implementation
client.py — add_points mirrors add_polyline's binary transfer (positions + optional colors packed into one HTTP blob, JSON header over WS). Reuses the existing _apply_colormap path: scalar (N,) → colormap (e.g. a signed-deviation heatmap), (N,3) RGB, or a flat color fallback when colors=None.
viewer.js — new add_points_binary handler builds a native THREE.PointsMaterial (size / sizeAttenuation / vertexColors) → a single THREE.Points draw call. Chose native PointsMaterial over a custom shader: viewport-aware size attenuation, and it composes with the existing set_color / disposal / fog-scoping paths for free. Added isPoints branches to _setDrawRange (reveals the leading frac*N points of the buffer) and query_scene draw-range reporting.
Regenerated viewer.html (version placeholder 0.0.0-dev preserved). tsc clean.
examples/25_point_cloud.py — a machined "cut surface" coloured by signed deviation (turbo), revealed by a draw_ranges animation sweeping a serpentine raster like a material-removal pass.
README feature bullet + CLAUDE.md object-types/examples docs.
Tests
7 unit tests in test_protocol.py (header type, parent, vertex-colour flag, scalar→colormap, RGB payload, size/attenuation, bad-shape ValueError).
2 browser tests in test_browser.py (cloud lands as type: "Points"; set_draw_range applies end-to-end).
Full suite: 302 passed; ruff check/format clean.
Visual verification
Rendered headless via Playwright (turbo deviation heatmap; set_draw_range(0.45) cuts the serpentine sweep off mid-surface as expected). Screenshots confirm one-draw-call rendering, per-point colormap, and size attenuation.
Scope / non-goals
Flat THREE.Points covers ≤~10M points comfortably. Octree/Potree LOD for larger clouds is a separate later tier. Point picking is not wired (the arc-length PolylinePickController is spine-based) — noted in the docs.

* Review follow-ups: falsy-zero guards, add_points color validation, swept-tool cap fixes + draw_ranges-channel test

Mechanical fixes from the post-merge reviews of #64/#69:

- Falsy-zero guards (`?? ` not `||`): a flat black point cloud or swept tool
  (color=0x000000) now renders black instead of the default; add_points size=0
  is honored instead of becoming 2px.
- add_points: validate len(colors) == n_points (a mismatch silently packed a
  misaligned blob → NaN vertex colors in the browser).
- buildSweptToolGeometry: emit the START cap before the side loft so the origin
  end is closed from the first draw_range frame (only the far/frontier cap
  appears last); fix the end-cap fan over-allocation (sections-2)*3 so the
  index buffer has no trailing zero-index degenerate triangles and
  totalIndexCount is exact.
- Tests: regression test for the binary `draw_ranges` animation channel
  (set_draw_range_data) on a swept tool AND a point cloud — the channel applier
  is a separate path from the set_draw_range message and previously drifted
  out of sync; plus a black-color test and a colors-length-mismatch unit test.
