This would allow resource pack creators to adjust the look of fog based on specific parameters via a properties file, akin to Custom Skies and CTM.
NOTE 1: I honestly may not fully understand the exact way fog is supposed to work in this game, so just bare with me here.
NOTE 2: I've now done a third major rewrite of this idea. This one should be much more detailed than the first two combined, which includes an implementation concept.
The main fog properties would be color, blend, density, start distance, and end distance, all based on GL_FOG_COLOR, GL_FOG_MODE, GL_FOG_DENSITY, GL_FOG_START, and GL_FOG_END respectively. (see: fixed function fog calculation: https://www.khronos.org/registry/OpenGL-Refpages/gl2.1/xhtml/glFog.xml )
Fog Properties
Color
```
color=FFFFFF
```
Fog color would be input as a simple hex RGB color code.
Blend
```
blend=<linear, exp, or exp2>
```
This sets the fog blend mode. This can be either linear, exp, or exp2.
Density
```
density=<any decimal number>
```
This sets the density of the fog. This only applies when blend is set to exp or exp2. This property can use decimals.
Start Distance
```
start=<0-1016>
```
This sets the starting distance of the fog. This only applies when blend is set to linear. This property is measured in meters, and can only use whole numbers. To deal with the starting distance option in video settings, resource packs using Custom Fog would take first priority. Finally, in the event that this conflicts with the end distance, the starting distance will be reduced by 8 meters.
End Distance
```
end=<4-1024>
```
This sets the end distance of the fog. Like the starting distance, this is measured in meters, only uses whole numbers, and only applies when blend is set to linear. The lowest this value can be is 4, and is ultimately limited to the current maximum possible render distance with OptiFine, being 1024 (64 chunks).
Transition
```
transition=<seconds>
```
This determines the transition period between different fog effects.
Fog Render Distance Limiting Methods
There is an issue of all this, which is dealing with render distances. For this, I suggest an additional property, method, which accepts any one of the following values:
Limiting Method
```
method=limit
```
The end distance value could be limited by the players render distance. For example: If the end distance is set to 256, and the players render distance is set to 8 chunks, the end distance will be set to 128.
However, this poses an issue for players who use much larger render distances. Some players could play with 64 chunks render distance, but only be able to see up to 16 chunks. This may be useful for certain effects, such as rain or snow.
Reduction Method
```
method=reduce
```
This method simply takes the players current render distance (in meters) and subtracts it by the end distance value. This could be used to push the world border further out of sight without sacrificing many resources.
Scaling Method
```
method=scale
```
This method is slightly more complex than the other two, but may work best for most effects.
This dynamically scales the end distance relative to the players render distance. This involves a little bit of math, but I came up with a small equation for it already.
(Custom end distance × Player render distance in meters) ÷ Max render distance in meters.
To get the players render distance in meters, simply multiply the chunk render distance by 16. Same for max render distance. In this case, the full equation would be:
(Custom end distance × (16 × Player render distance)) ÷ (16 × Max render distance)
Fixed Method
```
method=fixed
```
This method will set the end fog distance regardless of the players render distance. I personally can't think of many uses for this, but I imagine at some point, someone down the road will want to ignore the render distance limit for whatever reason. Plus, having as many options as possible is always good in my opinion.
Triggers & Events
These fog properties can be dynamically adjusted by certain in-game events, such as player heights, water submersion, lava submersion, submersion depth, status effects, biome, weather, and current time. ALL of these properties are optional, but at least one is required to actually function. If multiple properties are provided, all of them must return true to activate the fog effect.
Player Height
```
heights=<height ranges>
```
This activates when the players eye height is within specified ranges. There can be multiple ranges, separated by a space. These can be anywhere between 0 and 1024.
Water Submersion
```
underwater=<true|false>
```
This activates when the players view is underwater.
Lava Submersion
```
underlava=<true|false>
```
This activates when the players view is under lava.
Liquid Depth
```
liquidDepth=<0-15>
```
I'm not sure if this is practically possible to do, but it would help to make water look even better.
Status Effects
```
effects=<status effect IDs>
```
This activates when the player is under the specified status effects. You can enter multiple IDs to only trigger when all of the specified effects are active.
Underneath Block
```
underBlock=<true|false>
```
This activates when the player is below a solid block. This would be used, for example, to remove that odd effect where the sky seems to get darker when you enter a house or walk under trees.
Biomes
```
biomes=<biome list>
```
This activates when the player is in any one of the specified biomes, separated by spaces.
Weather
```
weather=<clear|rain|thunder>
```
This activates when the active weather is either one of the specified.
Times
```
times=<hh:mm-hh:mm>
```
This activates when the in-game time is within the ranges specified. There can be multiple time ranges for this property.
And finally, this is our full list of properties.
```
color=FFFFFF
blend=exp
density=0.03
start=0
end=1024
method=limit

heights=0-512
underwater=true
underlava=true
liquidDepth=0-15
effects=1 3 5
biomes=ExtremeHills DesertHills ForestHills ExtremeHillsEdge JungleHills IceMountains
weather=rain
times=12:00-18:00 1:00-6:00

transition=2
```
Files and Directories
To be honest, I'm not sure what would be the best way to implement this for all resource pack creators. This is the best thing I have:
For each effect AND event trigger, there is a single file. There can be as many of these as you want, as long as it's in the following directory:
```
resource_pack/assets/minecraft/optifine/fog/
```
There can be as many subfolders as you wish. Makes it a bit easier to organize.
Finally, the filename. I believe it should be called fog_X.properties, where X can be anything the resource pack maker so wishes. This will help further with organization and avoiding losing files in large resource packs.

The fog start is controlled by video settings option.
The fog end is generally at the render distance to avoid seeing the end of the loaded chunks.
The fog color can be controlled by custom colors: https://github.com/sp614x/optifine/blob/master/OptiFineDoc/doc/color.properties#L351
There is no such thing as for density. The fog starts at a certain distance (0%) and ends at another distance (100%). The only parameter that can be changed is linear vs non-linear fog.
In the real world the fog always starts at 0 and the fog density controls the fog end distance (how far in the fog is visible).

The vanilla fog is there not to create atmosphere, but to hide the edges of the world and to simulate that the world is unlimited (just not visible yet). In older MC versions it was also used to reduce the texture flickering due to missing texture filtering (mipmaps).
If the resource pack wants to add athmospheric fog, then it usually means visibility X meter. For example in a swamp the player should see 50m, in a snow storm he should see 30m, etc. This would only work with fixed fog distance. Otherwise if the fog is set to 50% relative, when the user has render distance 64 chunks, it would allow him to see 32 chunks (512m) which is barely noticeable.
