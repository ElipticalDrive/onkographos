Summary
Dense Adam is the largest phase of a room1 training step after the backward: 9.60 ms at 600k gaussians. Each view sees only part of the scene, and a hidden gaussian's colour gets no gradient from it. This PR makes --selective-adam fast and quality-neutral:
adam_step_rows: SelectiveAdam's update as one Metal kernel per parameter. A hidden row costs one mask byte, with no host sync and no gather/scatter. The torch paths stay as the CPU fallback and as the test oracle.
New defaults for --selective-adam: skip only sh_dc/sh_rest (48 of 59 floats per gaussian), bias-corrected with the global step count, as gsplat does. Geometry and opacity stay dense, through FusedAdam's kernel.
Separate commit: adam_step computed 1 - b2 in float, which put the second moment 1.3e-5 off torch. The host now rounds it from double, and the test checks both moments.
Still opt-in. The default stays dense Adam, because flipping it changes every published table. That decision is yours.

Two things explain the losses:
Per-gaussian bias correction. MCMC resets a relocated gaussian's step count to 0, so its first steps come out ~3× smaller than dense Adam's. Dense Adam keeps the global count over freshly zeroed moments.
Skipping geometry. It freezes momentum and the MCMC opacity/scale regularisers while a gaussian is hidden.
The dense control reproduces the README table: mean 30.33 vs 30.37. All three sweeps are committed under bench/results/. NEGATIVE_RESULTS.md records the variants that lost.
room1: where the speed win is
NeRF-synthetic sees most gaussians in every view, so selective Adam barely changes anything there. room1 hides ~77% per view, which is exactly where freezing a hidden gaussian's SH could matter. step: 9.60 ms of a room1 training step at 600k gaussians, the largest phase
after the backward. A training view sees only part of the scene, and a
hidden gaussian's colour gets no gradient from that view.

adam_step_rows is SelectiveAdam's update as one Metal kernel per parameter:

paths stay as the CPU path and as the reference the kernel is tested against.
