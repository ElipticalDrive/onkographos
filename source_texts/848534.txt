Summary
New isolated Solvix.Voxelization project: converts an uploaded triangle mesh into a unit-cube voxel grid (SAT triangle-vs-box test + grid-accelerated ray-parity inside test), exposed through a single IVoxelizer seam
(everything else internal).
Wired through Solvix.MeshBuilder's existing facade pattern and a new POST /api/meshes/voxelize endpoint in Solvix.Api.
Both request (mesh) and response (voxel grid) use a packed binary wire format (grid dims + 1-bit-per-cell occupancy bitmask) instead of JSON, since a dense grid's cube-center list would run into tens of MB for realistic
imports.
FE: upload the currently-displayed imported reference, decode the binary grid, and render it as an instanced-cube preview (fill + wireframe outline), each with its own opacity slider and a show/hide toggle. Auto re-runs
(debounced) whenever the underlying reference geometry changes.
Hardening pass: input validation on the mesh body, integer-overflow-safe cell-count math, cancellation support, and a fix for a false-positive "ghost cube" bug where a flat triangle face landing exactly on a grid boundary
could register as touching cells on both sides of it (generalized across all 13 SAT axes, not just the 3 box axes, so it also holds for a rotated mesh).

… fix, disposal-ordering fix

  Backend:
  - Fix int32 overflow in cell-count math (countX*countY*countZ) that could wrap past
    the MaxCells safety check on an attacker-scaled mesh; guard the double->int cast too.
  - Validate mesh body length and index bounds against the declared vertex/index counts
    BEFORE allocating (an 8-byte body claiming vertexCount=0xFFFFFFFF used to attempt a
    ~48GB allocation) - new MalformedMeshException -> MeshBuilder's InvalidMeshException -> 400.
  - Thread CancellationToken through the whole facade chain + wrap the CPU-bound algorithm
    in Task.Run, so a disconnected client actually stops a large voxelization early instead
    of tying up a request thread to compute a response nobody reads.
  - Fix DIP violation: MeshBuilderFacade depended on the concrete Voxelizer class instead of
    an abstraction. Added IVoxelizer (public), Voxelizer/MeshBuilderFacade are now internal,
    both wired via AddVoxelization()/AddMeshBuilder() DI extensions - restores testability
    (MeshBuilderFacadeTests now uses a fake IVoxelizer instead of double-invoking the real
    algorithm just to know what to assert against).
  - Extract TriangleSpatialGrid out of VoxelizationService (SRP) - spatial indexing is a
    separable concern from deciding cell inclusion.
  - Named constant for the request-size cap, structured logging around the endpoint
    (request/response size, duration, rejection reasons).

  Frontend:
  - voxel-preview.ts: single grid pass instead of two (count then fill).
  - mesh-contract.ts: drop an Array.from identity-array allocation for non-indexed geometries.
  - voxel-grid-contract.ts: validate the occupancy buffer is long enough for the declared grid
    dimensions, instead of silently reading a truncated/corrupted response as "empty".
  - mesh-api.service.ts: recognize InvalidMeshException's { message } body (new 'invalid-mesh'
    status), not just the too-large shape - previously fell through to a generic, detail-free error.
  - Fix a real ordering race: VoxelizationService/ImportedReferenceRenderService used to dispose
    a preview's shared geometry/material the instant a replacement was built, before
    WorldCanvasComponent's change-detection-driven swap actually removed the old clone from the
    scene - a render-loop frame could land in between and draw already-freed GPU buffers.
    Disposal now happens in WorldCanvasComponent itself, exactly when it removes the clone
    (fixed for dimensionLines/ruler too, since they shared the same pattern).

…e rendering z-fight

Show/hide toggle for the voxel cube overlay in ImportedReferenceDisplayService
(voxelPreviewVisible), same pattern as dimensionsVisible/rulerVisible - the result
stays computed/cached while hidden, this only gates whether RenderWindowComponent
hands it to WorldCanvasComponent.

Auto re-run voxelization instead of just hiding a stale result: ImportedReferenceRenderService
emits referenceChanged$ whenever refreshScaledReference actually rebuilds a live clone
(density change, rotation commit, reset, new import); VoxelizationService subscribes to
it grouped+debounced per session (500ms) and re-runs automatically. A run-generation
guard discards a superseded response instead of letting a stale run clobber a newer result,
now that runs can overlap (auto + manual).

Fixed a rendering bug this surfaced: the cube fill and the imported reference mesh are
both transparent and literally overlapping (conservative voxelization touches/encloses
the surface). Three.js sorts transparent objects by camera distance, and that sort order
between the two can flip as the camera orbits - whichever draws first wins the depth test
and the other doesn't draw there at all, reading as the reference mesh randomly vanishing.
Fixed via a fixed renderOrder (mesh always draws first, cubes blend over it) rather than
disabling depth writes on the cubes outright - that alternative stopped neighboring cube
faces from occluding each other too, making the fill's color drift with camera angle.
