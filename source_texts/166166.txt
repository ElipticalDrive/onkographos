Surfaced by the S9 MC validation slice (MeshValidator on UserBulbMeshExporter).
When the DE isosurface exits the export cube (range too small to enclose the set), Marching Cubes leaves the mesh open where the surface meets the cube faces — the validator reports boundary edges (e.g. a sphere r=1.8 in a half-extent-1.6 cube → 648 boundary edges, IsWatertight = false). An open mesh isn't print-ready (slicers need a closed shell).
Current mitigation
UserBulbMeshExporter.ProbeBoundingRange auto-sizes the cube so the set is enclosed → interior → closed 2-manifold. The regression test McMeshValidationTests.ProbeBoundingRange_AutoSize_Yields_PrintReady_Mesh locks that path. So the recommended flow already yields watertight output; the gap is only when a user forces a too-small range.
Fix
Cap the boundary: for each of the 6 cube faces, triangulate the cross-section polygon(s) where the surface intersects the face (the field is already sampled on the face — run a 2D marching-squares contour per face and fill the interior/exterior region below iso), welding to the MC boundary vertices so the result is a single closed 2-manifold. Then assert IsClosedManifold in McMeshValidationTests.Undersized_Cube_* (currently asserts the open state).
Interior-surface exports are already closed 2-manifold + outward (verified) — this only affects the exceed-cube case.
Parent: #389. Slice: #391 (S9, isosurface hardening).
