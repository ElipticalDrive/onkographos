Which graphic card do you have?
There's already such a feature. By default it activates above 10M. points (per cloud), but this can be lowered (if you have a very light GPU, or many clouds). See the 'Decimate clouds over XXX point' option in the Display settings.
Mind also that this feature can take some time to activate itself as we need to compute an octree to do that. You can see the progress of this computation in the console.
Once activated, the clouds are automatically decimated when the user interacts with the 3D view. And the missing points are displayed progressively when the user stops interacting with the view.

The LoD mechanism works more or less as you describes (but without the need to split the cloud - however it will also work on split clouds if their size is bigger than what is defined in the preferences). It will only display the necessary points when you zoom in. And it will first display the top level points.
There's also in the TODO list (and for a long time now) the idea to implement 'out of core' management of point clouds. It's maybe even more ambitious than what you suggest because it's not only for display, but even to not load in memory a part of the cloud which is not used. However this is a huge task and it has been postponed du to the lack of time.

The 50G point cloud is divided into 25 blocks, each block is 2g point cloud file, and an index file is created. The index file contains information about each block and octree information about each block.
When loading point cloud, to create thread pool and memory pool, only need to open index file and load part of 2g point cloud file (file memory mapping), load and unload all 2G point cloud file (in thread mode) by index file, viewport and memory pool size.
With the above method, you can realize the real-time display of 50G point cloud files.
