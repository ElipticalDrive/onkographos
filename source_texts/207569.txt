Summary
Shape::intersect(Ray), Shape::intersect(point, radius) and Shape::contains loop over every triangle of the mesh. This PR adds MeshBVH, a bounding volume hierarchy: a tree of axis-aligned boxes over the triangles, split at the median, with at most 4 triangles per leaf. It makes these queries O(log N). Box, CompositeShape, HeightMap and Octree have their own implementations and are not affected, but CompositeShape children that are plain meshes do benefit.
Design
Lazy and cached: Mesh::getBVH() builds the tree on first use and caches it until the mesh is changed. Every mutating Mesh method clears the cache, now including filterOverlappingVertices, which did not clear the caches before.
Thread-safe: the tree is immutable, and the cache is a shared_ptr accessed with std::atomic_load/std::atomic_store. Threads that query a fresh shape at the same time each get a valid tree. Copies of a mesh share the tree, which keeps its own copy of the triangles, so it stays valid when the original mesh is destroyed.
contains: a winding number needs every triangle, so the tree alone does not speed it up. For closed meshes, the signed number of ray crossings equals the winding number exactly, and counting them only visits nodes along the ray.
Closedness is checked on vertex positions rather than indices, so triangle soups work. Positions are snapped to a grid of 1e-9 × the mesh size, because "duplicated" vertices are often not bit-identical; for example, a UV sphere's pole is a ring of vertices about 1e-16 apart. Merging vertices that close only leaves gaps far too small to change the crossing count.
A crossing near an edge or vertex, or a ray lying in a triangle's plane, is detected. The query then retries with another ray direction and finally falls back to the solid-angle winding number.
Open meshes always use the solid-angle winding number, so their results are unchanged from Fix and improve collision checking of shapes and sensors #89.
The root box of the tree serves as a bounding-box early-out for all queries.

Known limitation
Mesh's other caches (getMaxRadius, getTriangles) are still lazily filled without synchronization, as before. Copying a Mesh while another thread builds its tree is also unsynchronized. Neither is new to this PR.

MeshBVH: address review on closedness, ray pruning and open meshes
…
5edbd49
```
- Quantize vertex positions relative to the bounding box of the triangles,
  and only for vertices used by triangles. Absolute coordinates overflowed
  for meshes far from the origin, which could map all vertices to the same
  key and report an open mesh as closed. Non-finite meshes are open.
- Mark triangles which collapse when snapping their vertices to the grid.
  A ray crossing such a triangle is handled as degenerate (other direction,
  then winding number), as its edges are ignored in the closedness check.
- Use the exact-zero aware inverse direction for the ray traversal, instead
  of the one from Ray, which treated components below 1e-9 as zero.
- Only use the bounding box early-out in contains for closed meshes; the
  winding number of an open mesh can be above 0.5 outside its bounding box.
```

```
- Ray-box test of the hierarchy nodes: use a small relative tolerance.
  Roundoff made rays through edges or vertices, or through flat nodes
  (common for axis aligned geometry), miss nodes: 3799 of 40000 rays aimed
  at vertices, edges and faces of 200 boxes were lost or got a farther hit.
- countCrossings: skip zero area triangles instead of treating every ray
  near them as degenerate (which disabled the fast path), and treat nearly
  parallel crossings as degenerate instead of skipping them (which could
  miss a crossing far along the ray, giving a wrong contains result).
- Thread safety: Shape queries only use the immutable hierarchy, which now
  provides the bounding sphere radius, instead of the unsynchronized
  max radius cache of Mesh (reported as data race by ThreadSanitizer).
  Copying a Mesh loads the hierarchy atomically, and copies only the
  geometry, so it does not read caches another thread might be filling.
- invalidateCache: plain reset instead of an atomic store, which took a
  lock on every addPoint/addTriangle (building a mesh is 45% faster).
- Ray traversal visits the nearest child first and uses the inverse
  direction of the Ray (44% faster ray queries in the benchmark).
```
