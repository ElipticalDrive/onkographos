Closes #71
Changes
New texture input form DataTextureOptions: { data, size: [nx, ny, nz], format: "r8" | "r16f" | "r32f", filter = "linear", wrap = "clamp" }. TextureInput widens to TextureSource | TextureOptions | DataTextureOptions; TextureOptions itself is unchanged, so code reading .source keeps compiling. Declared in core and (as its own copy, fx-canvas: own the public types and deprecate the re-exported WebGL helpers #67) in fx-canvas; fx-passes re-exports core's.
loadTexture (packages/core/src/internal/textures.ts): data inputs skip image loading and upload with texImage3D(TEXTURE_3D, 0, R8|R16F|R32F, nx, ny, nz, 0, RED, …). UNPACK_FLIP_Y_WEBGL is set to false first (image uploads leave it true, and texImage3D from an ArrayBufferView fails with it on), UNPACK_ALIGNMENT is 1 during the upload and restored to 4. Wrap S/T/R, no mipmaps.
Validation before creating the texture (TextureLoadError): WebGL1 context, unknown format, size not three positive integers, array type not matching the format, length ≠ nx·ny·nz.
r32f + linear without OES_texture_float_linear → nearest, reported through a new createTextureSet(inputs, { warn }) option; fx-canvas / fx-passes print it only under debug.
LoadedTexture gains target and depth (null for 2D); textureSet.bind binds texture.target. getTextureSizeUniform() gives vec2 / vec3 and replaces the hard-coded vec2 in fx-canvas and fx-passes.
Context restore: the input keeps its data, so the existing loadAll path re-uploads it.
README (fx-canvas, fx-passes), docs site pages, Unreleased CHANGELOG entries for core, fx-canvas, fx-passes.
Decision from the 2026-10-30 grill: the outside-the-box value of frapx_sdVolume is settled for #72 (max(b, e − b)); nothing in this PR depends on it.
Tests
core unit (test/textures.test.ts, new): upload parameters per format, wrap/filter, WebGL1 rejection, type / length / size errors (no texture created), the r32f fallback and warning (and no fallback for r16f), vec3 vs vec2 size uniform, bind to TEXTURE_3D, re-upload of the kept data on loadAll.
fx-canvas public type parity: DataTextureFormat / DataTextureOptions equal core's.
GPU e2e (packages/fx-canvas/e2e/textures3d.spec.ts, Chrome): a 4×3×2 volume in r8, r16f and r32f read back voxel by voxel through texelFetch (within 1/255), u_volumeSize checked; lose and restore the context, the readback is identical.
pnpm build, pnpm typecheck, pnpm test pass; test:e2e passes for every package. (Port 5174 was taken by another project's dev server locally, so fx-canvas e2e ran through a copy of its config on another port; the config in the repo is unchanged.)
No new example: this is exercised in a browser by the e2e above, and New package @frapx/glsl-sdf-volume: load and sample baked 3D SDFs #72 adds examples/vite-sdf-volume on top of it.
Release notes
core (minor), fx-canvas 1.1 (minor), fx-passes (minor): 3D data textures ({ data, size: [x, y, z], format }), WebGL2 only. To be published together with New package @frapx/glsl-sdf-volume: load and sample baked 3D SDFs #72 / fx-particles: attract to, collide with and spawn from a baked SDF #73.
