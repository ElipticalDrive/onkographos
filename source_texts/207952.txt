Summary
Voxel worlds (planets, planes, asteroids) now support smooth shading via a smoothness property on VoxelTerrainComponent. The geometry is still voxel-stepped: silhouettes, hit positions and secondary-ray geometry follow cells. This epic makes the drawn geometry smooth too, for AAA-grade sculpted terrain and asteroids, without changing the voxel truth (collision, edits, CPU ray casts) and with zero cost at smoothness = 0.
This issue is written so a fresh agent with no prior conversation can pick up any sub-issue. Read "Shared context" at the bottom first.
Why
A voxel ray tracer draws exact cell faces. Even with smooth normals (done), a mountain ridge or asteroid limb shows cell-sized stair steps in its outline and in the terminator/shadow edges. At 0.1 to 0.3 m voxels this is small, but it is visible close up and on small bodies (asteroids), where cells are large relative to the body.
Chosen approach
Keep the voxel field as the only truth. Add a visual-only smooth surface: the iso-surface (level 0.5) of a separable quadratic B-spline density of the solid cells (smooth_normal in chunk_draw.wgsl already evaluates its gradient). The GPU refines each hit onto that surface, so position, normal and silhouette are consistent with each other.
Why this surface: the quadratic B-spline is a partition of unity (a flat voxel wall keeps its exact normal and position), is C1 across cells, and its kernel spans exactly the 3x3x3 cells around a point, so it needs only 27 occupancy lookups, all already available through solid_near (which handles chunk and cube-face borders).
Rejected alternatives (for the record):
Meshing (marching cubes / dual contouring): the system has no meshes; it streams a GPU 64-tree and ray traces it. A mesh path would duplicate residency, LOD, edits, shadows and GI.
Making the field itself smooth (SDF): would break CPU/GPU bit identity, collision and edit semantics (integer, exact, mirrored).
Shading-only smoothing: already shipped; it cannot change silhouettes.

Hard constraints (do not violate)
CPU/GPU bit identity of the field and edits. No floats in the field. Smoothing is rendering only. CPU raycast/drawn_hit/collision stay on voxels (they may differ from the drawn surface by about half a cell; document it).
smoothness == 0 must be bit-identical and free (pipeline override or dispatch-uniform branch; existing tests must pass unchanged).
Performance. Terrain budget under 6 ms GPU at 1440p (TSR 0.75) on an RTX 3060 (pass README "Goals"). Measure with the voxel_flight harness; agree a smoothing-1 budget with the maintainer.
No visible refinement / popping. Levels, fades and residency must not pop when smoothing is on.
Stage-gated. The maintainer verifies renderer changes by running the app and looking. After the spike, stop for a visual review before continuing.
Phases
Spike: refine primary hits onto the iso-surface, flag-gated.
Shell-cell tracing: rays that graze past voxels must still hit the bulge of the surface in air cells (the real silhouette change), with a conservative empty-space skip.
Coarse levels (trace_exact): decide and implement or fade out.
Secondary-ray and temporal consistency (shadows, sky, local lights, GI, denoiser, feedback, meshes).
LOD fade, thin features, natural heightfield terrain, partial-smoothness semantics.
CPU parity decision, tests, performance gate, docs.
Open decisions for the maintainer
Performance budget for smoothness = 1.
Thin-feature rule (per-material "stay voxel" flag vs min density vs iso tweak).
Whether editor picks/sculpt cursor snap to the smooth surface (default: no).
Whether natural heightfield terrain refines against its analytic slope (cheaper, likely nicer) instead of the density.
Whether smoothness becomes per-material or per-object beyond the per-world slider.
Definition of done
Silhouettes of ridges, bowl rims and sphere asteroids are smooth in captures at smoothness = 1, with no cracks at chunk, level or cube-face seams.
Shadows, AO, sky, GI and temporal accumulation show no new artifacts.
Smoothing 0 unchanged and free; smoothing 1 within the agreed budget.
Tests and docs updated; Helio PR merged first, then the submodule re-pinned in a Pulsar PR.
Shared context (read this first if you are a fresh agent)
Repo layout. This is Far-Beyond-Pulsar/Pulsar-Native. The renderer lives in the crates/renderer/helio git submodule (its own repo, Helio). Submodule changes merge dependency-first: merge the Helio PR into Helio main, re-pin the submodule here, then merge the Pulsar PR (see AGENTS.md and .agents/CRATES.md "Submodule pins"). .agents/ has subsystem docs; relevant: .agents/VOXEL_STREAMING.md, .agents/MEMORY.md.
The voxel system. Voxel worlds (cube-sphere planets, finite planes, infinite planes, asteroids = small planets) are drawn by crates/renderer/helio/crates/passes/3d/helio-pass-voxel-planet. Read its README.md and docs/chunk-octree.md first. Key facts:
Not meshed. 64³-cell chunks generated on the GPU, streamed as a cut of an octree per cube face, drawn by ray tracing: chunk boxes are rasterized, each pixel's ray walks the cut (walk() in shaders/chunk_draw.wgsl), inside a chunk through a 64-tree (trace_chunk), at coarse levels through exact grid cells (trace_exact, from exact_level, level 13 on an Earth).
Invariant: CPU/GPU bit identity. The terrain field, noise and edit containment are integer maths mirrored on CPU (src/planet.rs, Planet::raycast, drawn_hit) and GPU. Gameplay, collision, ray casts, picks and sculpting use the CPU voxel world. Never introduce floats into the field. Any smoothing must be visual-only.
Voxels are 0.1 to 1 m. Level L cells are 2^L base cells. Cell frames are affine maps (cell_frame, ChunkDraw with m0..m2 cell->world and i0..i2 inverse rows, .w offsets).
Frame flow (see README "Chunk octree"): residency planner -> drawn cut -> trace_pixel (writes hit_visibility, hit_distance via store_hit) -> shadow_sample/shadow (hit_face computes the shading normal, written to hit_normals) -> sky/local-light samples -> temporal denoise -> publish (gbuffer; calls surface_look for albedo/AO) -> Helio deferred lighting.
Component. VoxelTerrainComponent (crates/renderer/helio/crates/helio-component/src/components/voxel_component.rs, script methods in voxel_world.rs) -> VoxelSceneEntry (crates/core/engine_backend/src/scene/voxel_frame.rs) -> PlanetVoxelBackend::configure_appearance (crates/core/engine_backend/src/subsystems/render/helio_renderer/voxel_backend.rs) -> ChunkPass::set_smoothing / set_appearance (src/chunks/pass.rs) -> per-volume Materials uniform (ChunkMaterials in src/chunks/mod.rs, Materials in chunk_draw.wgsl, built by engine::material_table).
What already exists (shading-only smoothing, done). Helio commit 3ea02d06 "Added smooth voxels" (verify it is on Helio main and pinned here) plus Pulsar-side plumbing added:
Component property smoothness (0..1, "Surface smoothing", default 0 = unchanged look), script methods smoothness()/set_smoothness().
TerrainAppearance::smoothing (#[serde(skip)], src/terrain.rs), uniform field Materials.shape.x.
WGSL spline_weights + smooth_normal(slot, key, cell, local, c) in chunk_draw.wgsl: normal = minus the gradient of a separable quadratic B-spline density over the 3x3x3 solid cells around the hit (cell centres at cell + 0.5; kernel spans exactly 3 cells; partition of unity so flat faces keep their normal; C1 across cells). Used by hit_face for hits that are not natural heightfield steps (those keep the exact stored slope from leaf_ground). The sun-ray skip (Face.skip) scales with how far the smooth normal leans from the face. surface_look fades pigment mosaic (x(1-0.6s)) and edge darkening (x(1-s)).
GPU test smooth_surfaces_are_lit_not_moved in crates/renderer/helio/crates/passes/3d/helio-pass-voxel-planet/tests/chunks.rs (hits identical, lighting differs).
Limit that motivates this work: only shading changes. Silhouettes, hit positions, shadows' geometry and AO still follow voxel cells, so outlines step at voxel size.
Goal of the whole effort: make the geometry the GPU draws smooth too (for AAA sculpted terrain, asteroids), by refining hits against the same implicit surface (B-spline density, iso-level 0.5), gated by smoothness, with zero cost at 0.
How to build/test (Windows). From crates/renderer/helio/crates/passes/3d/helio-pass-voxel-planet: cargo test --release --test chunks -- --test-threads=1 <name> (GPU tests; they silently return if no GPU), cargo test --lib chunk_shaders_validate (naga validation of all shader variants: plane/sphere, counting). From the repo root: cargo check -p helio-pass-voxel-planet -p helio_component, cargo test -p engine_backend --test voxel_component_schema. Note -p helio-pass-voxel-planet tests only run from inside the Helio workspace. Cargo may rewrite Cargo.lock at the root; do not commit that. Measuring: cargo run -p helio-default-passes --release --example voxel_flight -- OUT [W H] with env vars in the pass README "Measuring" (HELIO_VOXEL_FLIGHT_HOLD=ground|mountain_slope|cave|..., HELIO_VOXEL_CHUNKS_ENGINE=1, HELIO_VOXEL_CHUNKS_COUNT=1). Compare interleaved A/B runs and minima (GPU clocks drop when idle).
Working agreements. The maintainer tests renderer changes by running the app and looking; do not claim a visual result is good from tests alone. Report what you verified and what you could not. Tests prove consistency, not appearance. Match surrounding code style (dense // comments explaining invariants). Do not edit the vendored/other submodules.
