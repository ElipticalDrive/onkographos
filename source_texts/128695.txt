Stage 10: scene intelligence and spatial queries (v0.10.0)
Read-only, exact answers about where things are in a scene: bounds, object discovery, ray casts, nearest points, containment, overlaps, regions, camera picking and projection, lines of sight, visibility and spatial relations. They work from Python (Scene methods and aether3d.spatial), as JSON requests, from the command line (aether3d query) and in scene scripts. Objects gain tags and metadata (project format 6). Documentation: docs/SPATIAL.md.

Design
Reuses the Stage 8 two-level BVH.
Closest hits are SceneAccel.closest_hit.
all_hits walks the same structure with the same watertight test on the same object-space rays (the same arithmetic), so the first of all hits is the closest hit.
A ray through a shared edge or vertex reports one hit per object.
Rendered surfaces use PathScene.trace.
Per-object world BVHs serve nearest-point branch and bound, pair walks for distance and intersection, and region and frustum candidates.
Triangle intersection. Separating axes prove a pair disjoint; the remaining pairs are decided constructively (edge crossings, zero vertex-triangle or edge-edge distances). Correctness therefore does not depend on the completeness of the axis set, and degenerate triangles are handled.
Caching only where measured.
One index per scene revision, in a weak cache. On the castle, the first query after a change takes 21 ms (it evaluates and indexes), later ones 1.3 ms.
Every change bumps scene.revision, undo and redo included. During an open transaction (history.in_progress) a fresh index is built, so rollbacks and uncommitted changes are always seen.
Queries never mutate the scene or record history; tested for every query.
Change to Stage 8 code: closed BVH boxes (commit b43ebc2)
While testing grazing rays I found a robustness bug in the shared slab test.
The bug: a ray with a zero direction component that lies exactly in the plane of a box face missed the box on one side ((hi - o) * inv = 0 * inv = 0 makes the slab empty for t > 0). For example, a ray straight down along the side of a cube missed the top face's edge that it passes through.
The fix: SceneAccel.build now grows every node and instance box by one ulp, so such rays are strictly inside the slab and the watertight triangle test decides. Traversal cost is unchanged, and the GPU path tracer reads the same boxes.
Test: test_axis_parallel_rays_on_a_box_face_plane_still_reach_its_edges. I checked that it fails without the fix.
Effect on renders: they change only for such rays. No golden image, reference or assertion changed. The CPU and GPU (NVIDIA and lavapipe) render tests pass unchanged.

Limitations (also in docs/SPATIAL.md)
Sampled where stated:
visible_from's fraction is estimated from fixed surface samples (each sample is exact).
The bounding sphere encloses all geometry but is not minimal.
Box-based where stated: above/below compare world-box heights and XY footprints.
Alpha masks (surfaces="rendered") are evaluated at the exact hit point at full texture resolution. At a cut-out's edge, a filtered raster pixel may disagree.
Containment is only claimed for closed solids. Welding is by exact position, so near-miss seams make a mesh open.
Zero-scale objects are never hit by rays (as in renders), but still have bounds and closest points.
No physics: overlaps and distances are geometric tests on static geometry.
Performance: Python/NumPy, meant for tools, editors and agents rather than per-frame game logic on large scenes.
Threads: not thread-safe; use one thread per scene.

did not have yet.

A ray with a zero direction component that lies exactly in the plane of a
box face missed the box on one side: the slab test inverts the zero as a
tiny stand-in, and on that side computes (hi - o) * inv = 0 * inv = 0, so
the slab looked empty for t > 0 (on the other side it was unbounded, as it
should be). Straight-down rays along a mesh's side, or orthographic camera
rays that land exactly on a bound, therefore skipped triangles whose edges
they touch.

SceneAccel.build now grows every node and instance box by one ulp
outward, so such rays are strictly inside the slab and the watertight
triangle test decides as for any other ray. Traversal costs nothing more;
the GPU path tracer reads the same boxes.

New test: axis-parallel rays exactly on a cube's face planes hit the top
and bottom edges (it fails without this change). The rest of the suite,
golden images included, is unchanged.

Stage 10's read-only questions about where things are, answered exactly
from the scene's triangles in world space (hierarchies, rotations,
non-uniform and mirrored scales, shared meshes and evaluated procedural
geometry included):

- bounds: world/local axis-aligned boxes (exact: from the vertices), the
  oriented box (the local box through the world matrix), an enclosing
  sphere, and aggregates over descendants (children=True).
- find_objects: by name (glob), kind, tags, metadata, parent/ancestor,
  visibility, material and region.
- raycast / raycast_all: position, distance, geometric and shading
  normals, front/back, triangle, face group, barycentrics, UVs, material
  and instance identity. Rays use the Stage 8 two-level BVH and its
  watertight test; all-hits walks the same structure, so the first of all
  hits is the closest hit, and a ray through a shared edge or vertex
  reports one hit. surfaces="rendered" lets rays through alpha-mask
  cut-outs and backs of single-sided materials (the path tracer's rules).
- closest_point, nearest_objects: exact point-to-surface distances
  (Ericson's closest point on a triangle, BVH branch and bound).
- contains_point: inside/outside/surface for closed meshes by the winding
  number; "undefined" (with the fractional winding number and a reason)
  for open, non-manifold or inconsistently oriented meshes.
- distance, overlaps: exact surface distance and intersection between
  objects (broad phase on world boxes, then triangle pairs: separating
  axes prove pairs apart, edge crossings and zero distances prove them
  touching); containment of one closed solid in another. Box overlap is
  only ever reported as such (exact=False).
- query_region (box, sphere), objects_in_view (frustum), camera_ray, pick
  (bit-for-bit the path tracer's camera rays), project, line_of_sight,
  visible_from (deterministic area-weighted surface samples), relation
  (near, above, below, inside, contains, in front of, behind, nearer to a
  viewer, with tolerances), describe (compact JSON scene summary).

Queries never change the scene, its revision or its history. The spatial
index is cached per scene revision (a weak cache, not scene state) and
rebuilt while an operation or transaction is open (new public
History.in_progress), so edits, undo, redo and rollback are always seen.

Results are frozen dataclasses with to_dict(); errors are QueryError
(code, location, hint). The same queries run as JSON requests
(aether3d.run_query), from the command line (aether3d query QUERY PATH
KEY=VALUE..., or query run PATH --request FILE) and in scene scripts (a
read-only "query" operation).

Tests compare with independent references (Moller's interval test,
polygon clipping, brute-force ray casts and closest points, analytic
cases, rasterizer object ids for picking) and check determinism, cache
invalidation, history neutrality and CLI/script/Python parity.

A procedural object whose geometry fails to evaluate made every spatial
query fail, even when it was hidden or left out, while renders only fail
for objects they draw. The index now records the failure per object
(QueryError GEOMETRY_EVALUATION_FAILED, location objects[NAME]) and
raises it only when the object takes part in a query: selected,
visible or included with include_hidden, or named as a subject.
describe() reports such objects with an "error" instead of failing.

Also: rendered-surface queries turn a RenderError of the scene
extraction into a QueryError with the same code; an unused helper is
gone; the Khronos validator corpus now includes an export with tags and
metadata (nested JSON, non-ASCII text), which validates with no errors
or warnings.
