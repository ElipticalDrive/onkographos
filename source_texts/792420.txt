Update (2026-11-03)
Better title: Add PLY mesh import/export as a Field plugin
Better description
No PLY support on master: nothing in src/ (outside Externals) or docs/ references the format, and the Superbuild has no PLY library. The thread recalls Moritz as the requester, but with no recorded use case.
Plugin path is clear. Formats are registered in src/Core/IEPlugin/IEPluginInit.cc:50, and AutoReadFile has its own extension map (src/Modules/DataIO/AutoReadFile.cc:196). Closest templates are OBJ (src/Core/IEPlugin/IEPluginInit.cc:52, reader builds a TriSurfMesh at src/Core/Algorithms/Legacy/DataIO/ObjToFieldReader.cc:68) and STL, which has separate ASCII and binary plugins (src/Core/IEPlugin/IEPluginInit.cc:94). PLY needs both encodings in one format. Scale reference: the whole OBJ reader/writer is 159 lines including licence, so ASCII PLY should be small; binary and vertex properties add to that.
Do not copy the OBJ tests as they stand: both are disabled (src/Core/IEPlugin/Tests/ObjToFieldPluginTests.cc:40, src/Core/IEPlugin/Tests/ObjToFieldPluginTests.cc:45). #1239 (open) tracks OBJ parser gaps separately.
Concrete steps
Ask Moritz whether anyone still needs this and which flavour, since that sets the scope. Assume triangle surfaces if there is no answer.
Add a PlyToFieldReader in src/Core/Algorithms/DataIO/ and Ply_Plugin.h/.cc in src/Core/IEPlugin/, with the matching CMakeLists.txt entries: ASCII and binary little/big endian header parsing, triangles to TriSurfMesh, quads to QuadSurfMesh, clear errors on anything else. Hand-written is enough for this scope.
Add scalar vertex properties to field data, as a separate commit, only if step 1 asks for them.
Register *.ply in IEPluginInit.cc, and add .ply to the AutoReadFile map.
Add enabled, data-free round-trip tests in src/Core/IEPlugin/Tests/ writing a small temp file per encoding.
Status: still valid - no PLY code exists; demand needs confirming before building.
