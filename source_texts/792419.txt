Binary PLY decoding does not currently match the format declarations in several valid cases:
big-endian scalar payloads are rejected rather than decoded;
legal integer list-count types can fail through invalid casts;
CRLF headers can leave the line-feed byte in the payload;
malformed counts and truncated values are not rejected consistently before allocation.
Decode all supported numeric scalar/list values according to the file byte order while preserving the native-endian fixed-record fast path. Normalize list counts through checked nonnegative integer conversion, align binary payload starts for LF and CRLF headers, and add end-to-end malformed-input and attribute-alignment coverage.

Implemented in #58. Binary parsing now follows the declared byte order for all supported scalar and list values, validates every integer list-count width before allocation, consumes LF/CRLF header framing exactly, and rejects truncated payloads consistently. The native fixed path is preserved, while buffered native list parsing reduces allocations.
