Found in pscat 0.6.2 (aarch64-apple-darwin, macOS 15, no font packs installed) while building ArtColony/fractal_clouds, a ray-marched landscape library in PostScript. The 0.6.3 release notes don't mention a change here.
Kind: feature request (performance)
Found: 2026-10-22, gallery: 3D fractal clouds, mountains (and trees) rendered to look real ArtColony/fractal_clouds#1 and lib: shared landscape scene (fc_landscape.ps), settings reference, technique guide ArtColony/fractal_clouds#11
Noise is the inner loop of every procedural texture and terrain, and in
pscat it is interpreted PostScript, both in fractal_clouds' own
libraries and in pscat's lib/artkit.ps (noiseinit / noise2).
Measured in fractal_clouds (spikes/bench_noise3.ps):
call
µs per call
empty loop iteration
0.25
3D value noise (fc-noise3)
1.8
3D fBm, 4 octaves
8.5
3D fBm, 6 octaves
12.4
In the forest render, height evaluations (each one several octaves of
noise) were 86 of the 92 terrain calls per pixel.
Suggested feature: native operators with a seedable, documented
algorithm, so results are the same on every platform and a PostScript
fallback can reproduce them exactly. For example:
```
seed noiseseed -                       % build the lattice / permutation tables
x y noise2  n      x y z noise3  n     % gradient noise
x y vnoise2 v      x y z vnoise3 v     % value noise
x y noise2d n dx dy                    % with analytic derivatives
x y oct gain lacunarity fbm2 v         % and fbm3, ridged2
```
A native call should cost about as much as an empty loop iteration, which
would make noise-bound renders several times faster. That's an estimate,
not a measurement.
Logged as entry 8 of fractal_clouds' pscat issues log. Paths such as lib/fc_*.ps and scripts/ are in that repo.

Triage: queued for 0.7.0 (opus, p2). This is the best speed-up in the batch, and it doesn't hurt reproducibility.
Design limits for the agent:
Names: lib/artkit.ps already defines noise2 and noiseinit. The native operators need names that don't collide, so existing art and gallery renders don't change. artkit switches to the native code only where the output is bit-identical.
Algorithm: documented and seedable, using only floor, multiply and add (no libm). Results are then identical on every platform and in WASM, and a PostScript fallback can reproduce them exactly.
Scope: 2D and 3D gradient and value noise, plus fBm. Derivative and ridged variants are welcome if they're cheap to add.
It ships in 0.7.0 if it merges before the cut.
Triage of the ArtColony/fractal_clouds report batch (#727–#742).

Summary of work (PR #748)
Delivered
src/ops/noise.rs adds these operators: noiseseed, gnoise2, gnoise3, gnoise2d, vnoise2, vnoise3, fbm2, fbm3, vfbm2, vfbm3, ridged2, ridged3, and the internal .permnoise2. The noise table lives in a new Interp::noise_perm field. Registration is one line in src/ops/mod.rs.
lib/noiseref.ps is the PostScript reference (nr*). It reproduces each operator bit for bit on pscat and also runs under Ghostscript.
lib/artkit.ps: noise2 becomes { Perm .permnoise2 } when the operator exists. Output is bit-identical.
tests/noise.rs has 10 tests. Docs are updated in plugin/skills/pscat/SKILL.md, plugin/skills/psart/SKILL.md, docs/guides/artkit.md, docs/dev/HANDOFF.md and notes/734-native-noise.md.
To try it: pscat --headless -e '42 noiseseed 1.3 2.7 gnoise2 = 0.3 0.6 0.1 5 0.5 2 fbm3 ='
Decisions
Names. gnoise2/gnoise3 instead of the suggested noise2/noise3, which collide with artkit. No name collides anywhere in the repo.
One algorithm, two implementations. The 2D gradient noise is artkit's exact formula, so artkit could switch without any visible change. The 3D noise is Perlin's improved noise. Value noise uses the exact binary constants (h-127.5)*0.0078125. Everything is f64 add/sub/mul in a fixed order, plus floor and table lookups.
Seed. A private LCG drives the Fisher-Yates shuffle, so rand is untouched. --sweep-seed does not reach noiseseed; that is a possible follow-up.
fBm is unnormalized, with an exact-binary per-octave domain shift. oct must be 0..32, otherwise rangecheck.
artkit's native path is a dot-named operator taking Perm, not a type-overloaded public gnoise2. The advisor recommended this. It mirrors PostScript's int/real promotion, so integer lattice inputs keep their old 0 vs 0.0 result types.
No demo render. Nothing visible changes, so this is tier (a).
Review record
Plan review: the advisor flagged int/real typing and the shape of the public API. Both were addressed before coding.
Implementation review: the advisor's points were addressed. The reference seed step is now Ghostscript-safe, the catalog summaries point at the native operators, the documented value-noise range is fixed, WASM is verified, and the PR body has a marginal-cost column.
Codex round 1: clean, no findings.
CI's docs job failed on rustdoc intra-doc warnings (P[i] read as a link, and a link to a private fn). Fixed in 3368678.
Codex round 2: clean, no findings.
Whole-corpus two-binary identity check: 154 of 154 page renders identical across 128 files.
Known deviations / open points
The capabilities catalog cannot list interpreter operators, so --capabilities shows only the nr* reference procedures, whose summaries point at the native operators. An operator kind is a possible follow-up.
--sweep-seed does not vary noiseseed.
