Resubmission of #722 (merged 2026-07-08, reverted in 771f88b), rebased on master with a further hardening pass. The mechanism is unchanged; what changed since the revert is listed at the end.
What it does
Gamebryo's raytest (NiTriBasedGeom::FindIntersections) and swept collision leaf (FindCollisionsTriVsABV) test every triangle of every mesh they reach. This caches a small in-tree bounding volume hierarchy per NiTriBasedGeomData (about 250 lines, no dependencies) and runs the engine's own exact tests over only the triangles the query can reach. Results are identical to the exhaustive loop by construction: candidate sets are conservative, candidates are tested in ascending index order, and skinned geometry and meshes under 64 triangles keep the exhaustive path.
Two related per-frame walk eliminations ride along, both in the collider update path: the per-actor collision probe's Update + UpdateCollisionData pair is skipped when the node's world transform already equals its local pose, and colliders whose collision volume sits on the scene node root only (all actors, per MobileActor::setupCollision) refresh that volume directly instead of walking the subtree.
Everything is behind one toggle, UsePhysicsOptimizations (MCM "Enable physics optimizations", default on). Off means the vanilla calls, not a degraded custom path.
Where the time goes
In dense modded interiors the exhaustive loop is the top engine row in VTune.

Verification
Ray path: in-game A/B harness casts 2000 rays (fibonacci sphere, findAll, accurateSkinned = true) with the toggle off, on-cold, and on-warm, and compares every hit of every ray for identical object, distance, and intersection point. All runs pass with zero mismatches, including with actors moving between passes.
Collision path: identical-by-construction (candidate set is a superset; the engine's FindIntersectBVGeom and collision callbacks run unchanged per candidate) plus gameplay; VTune shows CollideBoxTri down ~57% and the collider update walk from ~3x UpdateControllers to negligible.
Debug builds run a bounded self-check on the first 4096 BVH-backed raytests that asserts every exhaustive-loop hit is in the candidate set.
mwse.getPhysicsOptimizationStats() reports cache entries, bytes, builds, and evictions for measuring memory on a real load order.
Changes since #722
Cache entries are released by the geometry data destructor: NiTriBasedGeomData::~NiTriBasedGeomData (an 11-byte body every subclass destructor chains through) is reimplemented as TriBasedGeometryData::dtor. The previous pointer-plus-content validation and the 4096-entry wholesale clear are gone; a recycled address can never match an old tree, and memory is bounded by the live meshes.
Ray queries are clipped by the tree root instead of the model bound sphere, so a stale or zero model bound cannot drop hits.
One tree per mesh over the full triangle list; the ray query filters to the active triangle count afterwards, so the two query kinds cannot rebuild over each other.
Engine calls moved behind class wrappers per AGENTS.md (BoundingVolume::updateWorldData/findIntersectGeom, AVObject::runCollisionCallbacks/updateCollisionData/updateWorldCollisionVolume, Node::updateCollisionData/updateForCollisionProbe, CollisionGroup::updateWorldData); PatchUtil.cpp holds only the install lines. CollisionGroup::Intersect is hoisted to NI::CollisionIntersect (alias kept) so AVObject can name it.
TriangleBVH extracted to SharedSE/NITriangleBVH.{h,cpp}.
Box ABV bounds use the verified NiBoxBV basis convention (axes as rows) instead of a row/column hedge.
Collider tracking is evicted when the engine removes a collider (RemoveCollider/RemoveAll call sites routed through the wrappers) instead of relying on a periodic rescan alone; rescans are counted in walks rather than GetTickCount; the probe skip also requires the parent to be absent or identity.
Debug-only candidate self-check and mwse.getPhysicsOptimizationStats() (autocomplete + docs regenerated).

further hardening pass.

Caches a small in-tree bounding volume hierarchy per NiTriBasedGeomData and
runs the engine's exact triangle tests over the candidates only, in ascending

collider tracking is evicted through the RemoveCollider/RemoveAll wrappers;

vs off in every run; 15x warm in a dense interior, 1.3-2.2x in exteriors.

 1. static_assert(sizeof(Point3) == 12) in NITriangleBVH.cpp
    Dropped. NIPoint3.h already asserts the size.
 2. buildCandidateCacheEntry helper
    Inlined into getUsableCandidateCacheEntry (single call site).
 3. Point3(0, 0, 0) in NINode.cpp isIdentity
    Moot: the helper is gone (see 10).
 4. Magic 1.0f sweep margin in findCollisionsTriVsABV
    Named sweepPadding, with a comment on what it absorbs.
 5. Per-component min/max in findCollisionsTriVsABV corner loop
    Replaced by BoundingBox::merge(Point3); firstCorner flag removed.
 6. Per-component min/max in BoundingVolume::computeBoundingBox (union)
    Replaced by BoundingBox::merge(BoundingBox).
 7. "Reimplements NiNode::UpdateCollisionData" comment in NINode.h
    Dropped.
 8. "Non-deleting destructor" comment in NITriBasedGeometryData.h
    Dropped, along with the identical one in NIGeometryData.h.
 9. char bCalcNormals in findCollisionsTriVsABV
    Now bool calculateNormals. All three hooked engine call sites
    push a literal 1 into a 4-byte slot, so the change is ABI-safe.
10. Transform::IDENTITY instead of a local isIdentity()
    Added Transform::operator==/!= and Transform::IDENTITY. IDENTITY
    is built from literals so static initialization does not call
    the engine or depend on statics in other translation units.
    operator== compares scale, translation, rotation in that order
    so the engine testEqual call stays last.
11. Use NI::BoundingBox instead of a private AABB in TriangleBVH
    Done. Added Point3::operator[] (inline) and BoundingBox::merge
    (box and point overloads). Node size is unchanged at 32 bytes.
12. BoundingBox::contains for the box overlap test
    Added as BoundingBox::intersects (the test at that line is
    box-vs-box overlap, not point containment). Written as the
    negated separation test so NaN stays conservative; inline
    because it sits on the BVH query hot path.
13. roundingPadding taking const float* arguments
    Now takes const BoundingBox&.
14. Should findCollisionsTriVsABV return bool?
    Kept int. The engine returns the value in the full register
    (xor eax,eax at 0x6f12fd, mov eax,1 at 0x6f1309), the callers in
    NiTriBasedGeom::FindCollisions pass EAX straight through, and the
    vtable slot is already declared int findCollisions. A bool
    replacement would set only AL.
15. out_candidates -> outCandidates
    Renamed in TriangleBVH and TriBasedGeometryData.
16. camelCase arguments on BoundingVolume::findIntersectGeom
    out_time/out_point/out_normal0/out_normal1 renamed to camelCase.
    fTime kept: already camelCase, mirrors the engine argument and
    AVObject::update.
17. Why a static candidateScratch?
    Removed. Both candidate getters now return bool and fill a
    caller-owned vector. findIntersections keeps a file-static
    scratch beside deformVertices (no per-query allocation);
    findCollisionsTriVsABV uses a local and drops its defensive copy.
18. mwse.getPhysicsOptimizationStats as public API
    Un-documented: autocomplete definition deleted, docs and meta
    stub restored. The binding stays as a developer tool, like
    mwse.validateReferenceTracker.

Traversal only tests node boxes, and buildNode already merges the
per-triangle boxes into one. Pad the merged box there and leave the
per-triangle boxes exact. The node's largest coordinate is at least as
big as any of its triangles', so every node covers what it did before.
Padding is the same on all axes, so the split axis does not change.

bvhtest: 3/3 runs bit-identical on vs off, The Garden 18.7x and 37.7x
warm, Charach exterior 1.3x.
