I have identified the issue.
Internally, we create a coarse near/far range buffer (similar to OpenGL's depth clipping) to speed up ray casting. By default the range map's resolution is 1/8 of the original input. For your case, however, this configuration results in a non-integer range buffer (10x7.5) that leads to imprecise clipping distances. It can be resolved by changing this parameter.
I exposed this parameter in #4670 and the code snippet will look like:
```
result = vbg.ray_cast(block_coords=frustum_block_coords,
                              intrinsic=intrinsic_down,
                              extrinsic=extrinsic,
                              width=cols_down,
                              height=rows_down,
                              render_attributes=[
                                  'depth', 'normal', 'color', 'index',
                                  'interp_ratio',
                              ],
                              depth_scale=config.depth_scale,
                              depth_min=config.depth_min,
                              depth_max=config.depth_max,
                              weight_threshold=1,
                              trunc_voxel_multiplier=8.0,
                              range_map_down_factor=1)
```
