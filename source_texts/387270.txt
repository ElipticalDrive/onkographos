Summary
Add early ray termination (stop marching when alpha >= 0.95)
Further commits will add: jitter/anti-banding, pre-computed gradient texture, Phong lighting
What changed and why
Early ray termination (VolumeRendering-Basic.shader): When a ray accumulates enough opacity (95%), continuing to march through the volume produces no visible change. Adding if (output.a >= 0.95) break; cuts wasted GPU work, most noticeably on dense structures like bone where rays saturate early.
Planned for this branch (Faza 1)
1A Early ray termination
1B Jitter (anti-banding noise texture)
1C Pre-computed gradient Texture3D
1D Phong lighting (requires 1C)
Notes
No visual difference expected -- pure performance optimization. The 0.95 threshold leaves a small margin to avoid subtle artifacts at nearly-opaque surfaces.

Add jitter anti-banding via noise texture
…
6769c76
```
Each ray start position is offset by a random value sampled from a 64x64
noise texture, so adjacent rays no longer sample at identical relative
positions. This breaks up the concentric banding rings that appear at
lower Iteration values.

NoiseTextureGenerator.cs creates the texture at runtime and passes it
to the material. The shader uses it to shift localPos before marching.

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>
```
Bake gradient magnitude into Texture3D G channel (pre-computed gradient)
…
37fae3d
```
Converter now runs a second pass after loading density slices: central
differences across all voxels compute gradient magnitude, stored in the
G channel of an RGBA32 Texture3D. Shader reads .r (density) and .g
(gradMag) in a single tex3D call, replacing the previous 6 additional
samples per step. GPU work per ray step drops from 7 tex3D samples to 1.

Existing Texture3D assets need re-Convert to populate the G channel.
```
