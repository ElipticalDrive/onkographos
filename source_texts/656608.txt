MiniMax-M3.1-Flash QA
Findings
[P1] Validate XR viewports before indexing the target buffer
render_file_xr assumes that every viewport is inside the output image:
```
let n = (vw.min(width - vx) * 4) as usize;
let y = height - (vy + row) - 1;
let at = ((y * width + vx) * 4) as usize;
```
If vx > width, width - vx underflows. In debug builds this panics; in release builds it can produce an enormous length and then panic during slicing. A similarly invalid vy can underflow the y calculation. WebXR viewport data normally lies within the framebuffer, but this is a public Rust API and can also receive synthetic or malformed input.
Validate all viewports before rendering and return a descriptive error. This should also check that x + width and y + height do not overflow and are within the target:
```
let [x, y, w, h] = view.viewport;
let x_end = x.checked_add(w).ok_or("XR viewport overflow")?;
let y_end = y.checked_add(h).ok_or("XR viewport overflow")?;

if x_end > width || y_end > height {
    return Err(format!(
        "XR viewport ({x}, {y}, {w}, {h}) does not fit in {width}x{height}"
    ));
}
```
The checked multiplication used for the output allocation should also be addressed:
```
let byte_len = width
    .checked_mul(height)
    .and_then(|n| n.checked_mul(4))
    .ok_or("XR output dimensions overflow")?;
let mut rgba = vec![0u8; byte_len as usize];
```
[P2] Use path-component-aware containment in the oracle server
Both checks use lexical startsWith:
```
if (!world.startsWith(ROOT))
   throw new Error(...);

if (!path.startsWith(ROOT)) {
   res.writeHead(403);
   return res.end();
}
```
This accepts sibling paths such as oracle-evil/ and can permit traversal to a similarly prefixed directory. Because the server subsequently calls readFile(path), this is not just a validation inconsistency—it can expose files outside the intended oracle directory.
Compare resolved path components instead, for example:
```
const relativePath = relative(ROOT, path);
const insideRoot =
   relativePath !== ".." &&
   !relativePath.startsWith(`..${sep}`) &&
   !isAbsolute(relativePath);

if (!insideRoot) {
   res.writeHead(403);
   return res.end();
}
```
Apply the same component-aware check to the world path, and preferably resolve and validate the world before starting the server.
[P3] Ensure the temporary XR renderer state is always restored
render_file_xr temporarily mutates shared renderer state:
```
gpu.renderer.set_xr_eye(Some(eye));
let part = gpu.render(&view_frame, width, height);
gpu.renderer.set_xr_eye(None);
```
A panic during rendering leaves xr_eye set on the shared Renderer, affecting subsequent unrelated renders. An RAII guard would make this robust:
```
struct EyeGuard<'a>(&'a mut Renderer);

impl Drop for EyeGuard<'_> {
    fn drop(&mut self) {
        self.0.set_xr_eye(None);
    }
}
```
Alternatively, keep the eye matrix in the Frame/draw data so it does not need to be stored as mutable renderer state at all. The latter would also avoid potential state leakage if multiple render paths are added later.
