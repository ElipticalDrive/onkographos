Task objective
Implement a robust voxel-based model hollowing system in the Rust backend, including:
Hollowing of printable models
A brush-driven hollow blocking system (mark regions that must remain solid)
Hole generation using boolean subtraction for drainage/venting
Performance-safe rendering/processing assumptions (instancing + frame-rate efficiency)
Why this approach
Voxel workflows are typically more stable for complex hollowing and masking than pure mesh-offset pipelines. Rust backend is the right place for this due to heavy geometry/boolean computation and determinism/performance requirements.
Important reference note
We may reference RuneBrace behavior/workflow as design inspiration, but we must not copy proprietary code directly.
Only adopt concepts/algorithms that are permissible and re-implement cleanly in this codebase.
Scope (v1)
A) Voxelization + Hollow Core
Convert mesh to voxel representation at configurable resolution.
Generate hollow interior using target wall thickness.
Convert result back to mesh for downstream slicing/export.
Ensure watertight output for standard valid input meshes.
B) Hollow Blocking System (Brush-based)
Add a block-mask layer where brush strokes mark voxels as protected/solid.
During hollow generation, protected voxels are excluded from cavity creation.
Support at least:
add-to-block-mask brush
erase-from-block-mask brush
configurable brush size
Persist mask through operation pipeline so repeated edits are stable.
C) Hole Creation via Boolean Ops
Define hole primitives (position, direction, diameter/shape).
Apply boolean subtraction against hollowed mesh to create drainage/vent holes.
Validate hole placement and surface intersection before operation.
Return explicit errors for invalid booleans/intersections.
D) API Boundary
Expose backend endpoints/commands for:
hollow config (thickness, voxel resolution)
block-mask updates (brush actions)
hole definitions
final mesh generation/export
Keep frontend as orchestration/UI only; geometry logic remains in Rust.
Performance requirements
All voxel visualization should use instancing (no per-voxel draw calls).
Interaction and preview must be frame-rate efficient for practical model sizes.
Add guardrails:
max voxel count thresholds
adaptive/preview resolution options
cancellable long-running operations
Measure baseline timings for representative mesh sizes.
Acceptance criteria (Definition of done)
Hollowing works on representative closed meshes with configurable wall thickness.
Brush-based block mask correctly preserves selected regions as solid.
Hole booleans work with configurable hole parameters and produce valid output.
End-to-end flow works: request → Rust processing → mesh result returned.
Errors are actionable (invalid mesh, failed boolean, out-of-range params).
Voxel rendering path uses instancing and meets acceptable interaction performance.
Regression tests exist for:
hollow-only
hollow + block-mask
hollow + holes
hollow + block-mask + holes
invalid geometry/failure paths
Dependencies / blockers
Decision on voxel resolution strategy (fixed vs adaptive by model bounds).
Boolean engine robustness on edge cases.
Confirm legal/clean-room boundary for RuneBrace-inspired behavior.
Agreement on v1 parameter set (thickness, resolution, brush radius, hole specs).
Out of scope (for this issue)
Full advanced sculpting toolset beyond block-mask brushes
Full auto-repair suite for severely broken meshes
Final UX polish for professional-grade tooling
