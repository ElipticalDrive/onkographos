Found during the 2026-10-09 coverage diagnosis (godotGS vs gsplat 1.4 reference, per-pixel accumulated alpha). Audited at ab74e332aa8 (origin/master); measured with the optimized speed_trace editor build of PR #1226 (762fbe1282e, renderer code identical to master).
What happens
project_gaussian_2d() rejects a splat outright when any world-space scale axis is below 1e-6 (or above 100):
```
// modules/gaussian_splatting/shaders/tile_binning.glsl:497-500
if (any(lessThan(g.scale, vec3(1e-6))) || any(greaterThan(g.scale, vec3(100.0)))) {
    GS_DEBUG_INCREMENT(scale_reject);
    return vec3(0.0); // Invalid scale
}
```
The caller then drops the splat (tile_binning.glsl:820-823). A flat splat (a disk: two normal axes, one ~0 axis) is a valid 3DGS primitive. Optimizers produce them in large numbers, and gsplat/Inria render them normally: the 2D covariance stays well-conditioned, and eps2d is added on screen. Nothing reports the drop at runtime. The binning reject counters read 0 from GDScript in this test, even with set_debug_binning_counters_enabled(true).

A minor cause next to the always-on AA rescale (#1173) and the large-splat cap and fade (#1222), but a real one, with no setting and no signal.
Direction (not a patch recipe)
Clamp tiny axes to a floor (as core/gaussian_data_io.cpp:41,56 already does on save) instead of rejecting the splat. Revisit the > 100 upper bound the same way (no splat in these three scans exceeds it). Then re-run the flat probe and a real-scan coverage A/B.
