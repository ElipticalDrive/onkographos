Coding Plan
Summary
Fix three frustum culling gaps (foliage, particles, instanced meshes) by adding proper bounding volume tests before draw submission
Build GPU occlusion query infrastructure following the existing GPUTimerQueryPool pattern, with double-buffered queries to avoid stalls
Add an optional depth prepass to accelerate occlusion query completion
Implement temporal occlusion culling that uses frame N-1 results for frame N decisions, with conditional rendering as a fallback for unpredictable objects
Design Choices
Design Choice 1: Which occlusion culling approach should be implemented?
Options Considered:
Hardware Occlusion Queries (HOQ) - Use GL_ANY_SAMPLES_PASSED queries with bounding box proxy geometry and temporal reuse of results
Hierarchical-Z (Hi-Z) Culling - Generate a depth pyramid and perform GPU-side visibility tests via compute shader
Chosen Option: 1
Rationale: Hardware occlusion queries with temporal coherence provide a simpler initial implementation that integrates cleanly with the existing command bucket system, while the infrastructure can later support Hi-Z as an optimization.

Implementation Steps
Phase 1: Frustum Culling Gap Fixes
Address the three identified gaps where frustum culling is missing or incomplete: foliage rendering, particle systems, and instanced mesh draws.
Task 1: Enable Foliage Frustum Culling
Implement frustum culling in the foliage renderer, which already accepts but ignores a Frustum parameter.
Extend FoliageLayer in OloEngine/src/OloEngine/Terrain/Foliage/FoliageRenderer.h to store a precomputed BoundingBox covering all instances in that layer
In FoliageRenderer::Render(), test each layer's bounding box against the frustum parameter before issuing draw calls
Skip DrawIndexedInstanced entirely for layers that fail the frustum test
Update m_VisibleInstances counter to reflect actual visible count rather than total count
Task 2: Add Particle Emitter Bounding Volumes and Culling
Compute bounding volumes for particle emitters and integrate frustum testing into the particle render path.
Add BoundingSphere member to ParticleSystem in OloEngine/src/OloEngine/Particle/ParticleSystem.h, computed as emitter position with radius derived from LODMaxDistance plus a velocity-based expansion factor
Update ParticleSystem::Update() to recompute the bounding sphere when emitter position changes
Modify the particle render callback registration (in ParticleRenderPass) to accept and test the emitter's bounding sphere against the view frustum before invoking the batch renderer
Track culled emitter count in renderer statistics
Task 3: Fix Per-Instance Culling for DrawMeshInstanced
Replace the single-instance frustum test with per-instance filtering to avoid drawing invisible instances.
In Renderer3D::DrawMeshInstanced(), iterate the transforms array and test each instance's transformed bounding sphere against the frustum
Build a filtered transforms array containing only visible instances before upload
Update transformCount in the command packet to reflect actual visible instance count
Skip the draw call entirely if all instances are culled
Add a visibility count to stats alongside the existing culled mesh count

batch renderer
- Add a culled emitter count to the renderer statistics

infrastructure required for occlusion culling. The goal is to establish all the

**Task 2.2 – Extend RendererAPI with Occlusion Query Methods (`RendererAPI.h`,

- Add the following pure virtual methods to `RendererAPI.h`:
  - `BeginOcclusionQuery(u32 queryID)`
  - `EndOcclusionQuery()`
  - `GetOcclusionQueryResult(u32 queryID, bool wait)`
  - `BeginConditionalRender(u32 queryID)`
  - `EndConditionalRender()`
- Implement each method in `Platform/OpenGL/OpenGLRendererAPI.cpp` using the

`glBeginConditionalRender`, `glEndConditionalRender`
- Add static forwarding methods for all new API methods in `RenderCommand.h`

**Task 2.3 – Depth Prepass Option (`Renderer3D.h`, `SceneRenderPass`, shader

- Add an `EnableDepthPrepass` boolean flag to `Renderer3DData` in `Renderer3D.h`
- Create a minimal depth-only shader in the shader library: vertex stage
performs the standard MVP transform; no fragment output
- In `SceneRenderPass::Execute()`, when `EnableDepthPrepass` is true:
1. First pass: iterate the command bucket with depth-write-only state using the
depth-only shader
2. Second pass: normal color rendering with depth test enabled but depth write
disabled
- Rely on the existing `DrawKey` sort order for front-to-back ordering in the
prepass to maximize early-z efficiency

Phase 3: Occlusion Culling Integration
Integrate the query infrastructure with the rendering pipeline using temporal coherence to avoid GPU stalls.
Task 1: Add Per-Object Visibility State Tracking
Track visibility state per renderable object to enable temporal occlusion culling.
Add OcclusionState struct to OloEngine/src/OloEngine/Renderer/Renderer3D.h containing: queryID, wasVisibleLastFrame, framesSinceVisible, and pendingQuery flag
Create a map from entity ID (or mesh pointer) to OcclusionState in Renderer3DData
Initialize new objects as visible to avoid popping artifacts
Clean up stale entries for destroyed entities at frame boundaries
Task 2: Implement Bounding Box Query Submission
Render bounding box proxies with occlusion queries after the depth prepass.
Create a simple box mesh in Renderer3D::Init() for use as the occlusion proxy geometry
After the depth prepass completes, iterate objects marked for occlusion testing and render their world-space bounding boxes with queries active
Use the OcclusionQueryPool to manage query allocation and submission
Apply conservative bounding box expansion (similar to the 1.3× factor used for frustum culling) to handle animation and transform imprecision
Task 3: Implement Temporal Occlusion Culling
Use previous frame query results to cull objects in the current frame, avoiding GPU readback stalls.
In Renderer3D::DrawMesh() / DrawMeshParallel(), check the object's OcclusionState.wasVisibleLastFrame before submitting draw commands
Objects invisible last frame skip rendering but still submit a bounding box query to detect re-visibility
Objects visible last frame render normally; their query results update wasVisibleLastFrame for the next frame
Implement a "grace period" (2-3 frames) where recently-invisible objects continue rendering to handle fast-moving cameras and prevent popping
Add occlusion culling enable/disable flag (EnableOcclusionCulling) and expose via Renderer3D API alongside existing EnableFrustumCulling
Task 4: Integrate Conditional Rendering for Dynamic Objects
Use OpenGL conditional rendering to let the GPU skip draws without CPU readback.
For dynamic objects where temporal prediction is unreliable, wrap draw commands in BeginConditionalRender/EndConditionalRender using the previous frame's query
Add UseConditionalRender flag to DrawMeshCommand and DrawAnimatedMeshCommand POD structs in OloEngine/src/OloEngine/Renderer/Commands/RenderCommand.h
Update CommandDispatch.cpp to check this flag and wrap the draw call in conditional render state when set
Default to conditional rendering for animated meshes (which have the 2.0× bounding sphere expansion already)

Implement Phase 3 to wire the occlusion query infrastructure from Phase 2 into
the rendering pipeline using temporal coherence, avoiding GPU stalls. The goal
is a complete, functional temporal occlusion culling system with conditional
rendering support for dynamic objects.

**Task 3.1 – Per-Object Visibility State Tracking (`Renderer3D.h`,
`Renderer3D.cpp`)**
- Define an `OcclusionState` struct in `Renderer3D.h` with fields: `queryID`,
`wasVisibleLastFrame`, `framesSinceVisible`, and `pendingQuery` (bool)
- Add a map from entity ID (or mesh pointer) to `OcclusionState` inside
`Renderer3DData`
- Initialize all new entries as visible (`wasVisibleLastFrame = true`) to avoid
popping artifacts on first appearance
- At frame boundaries, remove stale `OcclusionState` entries for entities that
no longer exist

**Task 3.2 – Bounding Box Query Submission (`Renderer3D.cpp`)**
- In `Renderer3D::Init()`, create a simple unit box mesh to serve as the
occlusion proxy geometry
- After the depth prepass completes each frame, iterate all objects marked for
occlusion testing
- For each object, transform the proxy box to the object's world-space bounding
box and render it with an active query from `OcclusionQueryPool`
- Apply a conservative bounding box expansion factor (~1.3×, consistent with the
frustum culling approach) to account for animation and transform imprecision

**Task 3.3 – Temporal Occlusion Culling (`Renderer3D.cpp`)**
- In `Renderer3D::DrawMesh()` and `DrawMeshParallel()`, before submitting draw
commands, check the object's `OcclusionState.wasVisibleLastFrame`
- If the object was **invisible** last frame: skip the draw call but still
submit a bounding box query (via the proxy and `OcclusionQueryPool`) so
re-visibility can be detected
- If the object was **visible** last frame: render normally and update
`wasVisibleLastFrame` from this frame's query result at the end of the frame
- Implement a grace period of 2–3 frames via `framesSinceVisible`:
recently-invisible objects continue rendering during the grace period to prevent
popping with fast-moving cameras
- Add an `EnableOcclusionCulling` flag to `Renderer3DData` and expose it through
the `Renderer3D` public API, analogous to the existing `EnableFrustumCulling`
flag

**Task 3.4 – Conditional Rendering for Dynamic Objects (`RenderCommand.h`,
`CommandDispatch.cpp`)**
- Add a `UseConditionalRender` boolean field to the `DrawMeshCommand` and
`DrawAnimatedMeshCommand` POD structs in
`OloEngine/src/OloEngine/Renderer/Commands/RenderCommand.h`
- In `CommandDispatch.cpp`, when dispatching a draw command with
`UseConditionalRender = true`, wrap the draw call between
`RenderCommand::BeginConditionalRender(queryID)` and
`RenderCommand::EndConditionalRender()`
- Default `UseConditionalRender` to `true` for animated meshes (which already
use a 2.0× bounding sphere expansion) since temporal prediction is less reliable
for them
- For static meshes, default to the temporal path (Task 3.3) rather than
conditional rendering

Research
The engine uses an EnTT-based ECS with a command bucket rendering system. Frustum culling exists via a Frustum class with Gribb-Hartmann plane extraction and sphere/box visibility tests, integrated into Renderer3D::DrawMesh(). However, several subsystems bypass or incompletely implement frustum culling: foliage accepts a Frustum parameter but ignores it, particles have no spatial bounds, and instanced mesh draws only test the first instance. No GPU occlusion culling infrastructure exists—there are no occlusion queries, Hi-Z buffers, or depth prepasses. The RendererAPI abstraction layer provides the extension point for adding new GPU query capabilities.
