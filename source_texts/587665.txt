Goal
Make retopology a first-class BrepSight workflow for real downstream modeling, not merely a mesh-repair option.
This remains part of the product target after 0.1 Viewer stabilization. A model that can only be inspected is insufficient: the intended workflow is scan/import -> edit/repair/retopologize -> convert/export -> continue modeling.
Real workflows
scan -> dense triangle mesh -> quad mesh -> Blender/Rhino/SubD editing;
STL/OBJ -> editable topology -> continue modeling;
sculpt/high-poly -> lower-density quads for subdivision/sculpt continuation;
hard-surface triangles -> feature-aligned quads;
scan -> quad layout -> surface fitting -> approximate B-Rep/STEP reverse engineering.
Stage A — automatic provider
Implement retopo.quadriflow as a headless Android-native provider.
Requirements:
build permissively (BUILD_FREE_LICENSE=ON);
target face count / ratio;
preserve sharp features;
preserve boundaries when supported;
optional symmetry;
source-surface projection;
cancellable worker with progress;
temporary document transaction: failed/cancelled solve does not replace current document.
Stage B — guided provider
Evaluate retopo.instant-meshes as a separate field-aligned provider:
orientation field preview;
orientation guides/brush;
position field preview;
feature and boundary constraints;
low-resolution interactive preview followed by final solve.
Product/UI convergence
Retopology belongs under an Edit/Repair workspace, not hidden as an import-provider detail.
It must share selection, units, progress/cancellation, undo/provenance and export/loss-report infrastructure with GUI/command/natural-language operations.
Mobile motion/gyroscope control is camera input only and must not alter retopology constraints unless the user explicitly commits a selection/guide.
Quality contract
Every result reports:
input/output face count;
quad/triangle/n-gon count and quad ratio;
manifold state when known;
boundary preservation;
mean/max source-surface deviation when available;
attribute-transfer warnings.
Attribute policy
Explicitly handle normals, UVs, vertex colors and material assignment. Skin weights and morph targets are not launch requirements and must never be silently claimed preserved.
Product safety / honesty
automatic retopology may be a useful animation starting point but is not guaranteed deformation-ready;
retopology is not equivalent to CAD reconstruction;
mesh -> STEP remains an explicit fitting/reverse-engineering stage with approximation/error provenance.
Acceptance criteria
representative scanned/triangulated model produces a usable quad/quad-dominant output on Android;
output can be exported to a polygon-preserving format such as OBJ and reopened with quad topology retained;
STL export explicitly reports that quad topology will be triangulated/lost;
cancellation leaves original document untouched;
quality report is visible to Flutter without copying the full mesh through MethodChannel.
See docs/RETOPOLOGY.md and packages/cad_engine/lib/src/mesh/retopology.dart.
