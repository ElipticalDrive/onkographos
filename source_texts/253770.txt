Motivation
Replace the camera's hard-coded per-pixel regular-grid anti-aliasing with a reusable, testable 2D sampling infrastructure following the RDD separation of concerns.
Provide a flexible way to express different sample distributions and target-area shapes so future beam-based effects (AA, depth-of-field, soft shadows) can reuse the same machinery.
Centralize ray-beam aggregation so averaging uses the actual generated ray count (after shape filtering) and is consistent across renderers.
Description
Introduce a two-dimensional sampling API: SamplePoint, Sampler and implementations GridSampler, StochasticSampler, and JitteredSampler, plus TargetAreaShape for rectangular/circular (and custom) area policies.
Add Blackboard which owns sample generation, filtering by shape, static caching for deterministic samplers, and compensation strategies when shape filtering reduces sample count.
Replace Camera's inline grid AA with a builder-configurable blackboard: the Camera.Builder now exposes setMultisampling(int) and setMultisampling(int, Sampler) and setSamplingAreaShape(...), and Camera maps 2D offsets into view-plane rays via constructBeam(...).
Add beam aggregation to RayTracerBase via traceRays(List<Ray>) that averages traced colors by the actual number of rays; update code paths to use this API when a blackboard is enabled.
Add JavaDoc for the new API and tests focusing on the sampling infrastructure and beam aggregation behavior.
Testing
Compiled the project successfully with javac -Xlint:all and generated JavaDoc with javadoc; compilation completed with two preexisting warnings unrelated to the changes. (success)
Ran a dependency-free verification harness (SamplingHarness) that exercises Blackboard, samplers, shape filtering, compensation logic and RayTracerBase.traceRays(...), and confirmed expected behavior (success).
Added focused JUnit tests for sampling (unittests/renderer/sampling/BlackboardTests.java) and beam averaging (unittests/renderer/RayTracerBaseTests.java) which compile in the repo; full automated JUnit execution in this environment could not be completed because the environment lacked the JUnit Jupiter runner (fetching the standalone runner from Maven Central returned HTTP 403).
