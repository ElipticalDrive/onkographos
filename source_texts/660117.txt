Description
Builds on the merged VRAM work (#448 budget, #449 eviction, #450 defrag). Under video memory pressure, textures with mip maps (flag 8) that were loaded from a file and have no flag 256 lose their biggest mip levels first, least recently drawn first, one level of each texture at a time. Only when that is not enough does the existing textures_evict move whole textures to system memory. Flag 256 textures are never made smaller.
A texture loaded while video memory is short is made with the biggest levels left out right away (instead of going to system memory).
Every 8 Flips, the most recently drawn texture that is not whole gets one level back, if at least 1/8 of video memory stays free afterwards (so it does not fight the dropping).
Reading or drawing to a texture (SetBuffer/LockBuffer/ReadPixel, anim sheet conversion) makes it whole first. A texture that was read or drawn to is never made smaller again.
Works for RGBA8 textures (the dropped levels are shrunk on the CPU with a 2x2 average) and for block compressed DDS that store their levels. 10 bit, animated, cube, atlas and render target textures are left alone.
The recipe keeps the whole picture (or the file), so device loss recovery, defrag and eviction keep working; recipe->drop says how many levels are missing.
BLITZLLVM_TEXTURE_STREAMING=0 turns it off, BLITZLLVM_STREAMING_REPORT=1 logs drops/promotions.
New code is in graphics_streaming.cpp; textures_evict is untouched, so this does not conflict with the heap in Pick textures to evict from a size heap #476.
Not done / worked around, not fixed: the freed-bytes estimate in textures_evict still counts the whole size of a texture that is already dropped; a promoted or restored texture of a file is decoded again from the file on the main thread (a short stall); tested only against the fake VRAM limit.
Before & After
Before: a mipmapped texture that does not fit goes to system memory as a whole (slow to draw), or whole textures are moved there to make room for a flag 256 texture.
After (pseudo-code):
```
create_image_memory fails for a flag 256 texture
  -> defrag
  -> textures_drop_mips(size)   ; LRU, one level at a time, GPU image remade from recipe at lower resolution
  -> textures_evict(size - freed)   ; as before
Flip: if drawn texture has levels left out and free VRAM > cost + 1/8 total: give back one level
```
BlitzBasic: no new commands. Textures stay the same size for TextureWidth/TextureHeight; they only look blurrier up close while levels are missing.
Benchmarks
Not applicable for the fake limit test. Real-GPU numbers have not been taken; physical-machine measurement is not requested yet.
