Closes #90.
Adds OVERLAY_COLOR_BLEND.OVER: overlays are composited in volume order, each over the ones before it, so an opaque later map covers an earlier one. Paired with the existing OVERLAY_ALPHA_BLEND.OVER, this is classic source-over stacking (e.g. segmentations). All other modes stay commutative.
WebGL2 (CPU): blendOverlayData now loops voxels outermost and keeps a few scalars per voxel, dropping the 20 B/voxel accumulator array. Output is byte-identical to main for existing modes; 256^3 x 3 overlays runs in ~200 ms either way once warm.
WebGPU: the blend accumulator grows from 20 to 24 B/voxel (max and union alpha both kept); the accum pass specializes on COLOR_BLEND. maxBlendSliceDim follows automatically (2364 at 128 MiB, still above the 2048 3D limit).
Demo: vox.stats-multi.html (and vox.tissues.html) colour menu gains "over (last map on top)". To see it: Axial view, z ~ +40 mm, Blend "over"; where Hand overlaps Broca the blended purple of "mean" becomes Hand's cyan.
MCP: volumeOverlayColorBlend accepts over.
Verification
bun test (new cases: ordered result, reversed order, opaque top hides lower).
scripts/check-blend-wgsl.mjs in Chrome: WGSL matches CPU for all checked mode pairs, including 2,2 and 0,2, across two slabs.
Visual check of vox.stats-multi.html on WebGL2 and WebGPU.
nx affected format/lint/typecheck/test/build, check-boundaries, codespell.
Note: the checked-in ipyniivue bindings include only this PR's hunk (volume_overlay_color_blend accepts 2), which the issue needs so Python can set over. A full regenerate also pulls in unrelated drift that is already stale on main (rc.22 vs rc.33); that is left to #257.

Nits from Claude(none blocking):
"Byte-identical" claim: the description says the existing modes come out byte-identical to main. They don't quite. The CPU now works in 64-bit numbers instead of 32-bit, so about 0.1%
of colour bytes differ by exactly 1; alpha never differs. The change is harmless, and arguably more accurate, but the claim should be reworded.
Duplicate GPU pipelines: the first GPU pass now depends only on the colour mode, but its pipelines are still cached per alpha and colour pair. That builds three identical copies per
colour mode. It could be cached by colour mode alone.
Narrow GPU check: the check script only tests two overlays in one order. A reversed order, or three overlays, would actually prove the GPU respects order.
