Summary
This pull request introduces pre-allocated persistent TypedArray buffer pooling for back-to-front depth sorting in the 3D Gaussian Splatting engine (GaussianSplatRenderer).
Problem
Previously, on every depth sorting pass / frame update during camera movement, sortSplats() allocated new Float32Array and Int32Array instances for distances, indices, sorted positions, sorted scales, sorted colors, and sorted rotations. For scenes with thousands of splat points, this generated hundreds of kilobytes to megabytes of temporary array garbage per second, causing memory thrashing and GC micro-stalls during interactive camera navigation.
Solution
Persistent Buffer Pool: Allocated persistent distances, indices, sortedPos, sortedScales, sortedColors, and sortedRotations instance properties on GaussianSplatRenderer.
Dynamic Buffer Resizing: Implemented ensureBufferCapacity(count) which resizes persistent buffers when loading datasets with different splat counts (handling expansion for larger scenes and scaling down for smaller datasets without retaining unneeded excess memory).
Allocation-free Sorting & Updates:
Recycled a persistent comparator this._sortComparator = (a, b) => this.distances[b] - this.distances[a] to prevent allocating inline arrow functions during sorting.
Mutated geometry attributes directly via .set() from persistent scratch arrays.
Render Loop Integration: Integrated sortSplats() into render() to maintain depth sorting as the camera navigates smoothly.

Verification Results
Automated Tests: Ran npm test. All 18 tests across 8 test suites passed, including 4 new automated unit tests verifying persistent buffer allocation, zero allocations during 50 continuous frames of camera movement, dynamic capacity resizing, and back-to-front visual depth ordering.
Visual Accuracy: Generated render screenshots via npm run render-test, verifying photorealistic rendering and depth ordering.
