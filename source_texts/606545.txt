Problem
With a COLMAP model of 47,691 cameras the viewport stalled:
Hover picking rebuilt and projected every camera's frustum on each mouse move: 54 ms per move, up to 94 ms.
Every view change rebuilt the frustum overlays on one thread: 27 ms.
A point cloud shown without Gaussians rebuilt the scene render state every frame (5.4 ms), because the single cloud path always made a copy.
Fix
RasterRenderingEngine::pickCameraFrustum keeps each camera's frustum points while the camera object, its calibration (size, FoVy, model) and its scene transform are unchanged, so undistortion applied in place rebuilds the affected frustums. Each frustum is projected once per pick and skipped when the cursor lies farther than the hit radius from its projected bounds. Distances are computed in parallel, then the original ordered selection runs over all cameras, so results and tie handling are unchanged. CameraFrustumPickRequest::scene_transforms is now a span.
CameraInteractionService uses the scene's cached camera snapshot and converts the scene transforms only when that snapshot changes.
The frustum overlay rebuild culls, colors and projects cameras in parallel, each camera writing only its own slots. Instances, thumbnail quads and equirectangular lines are appended afterwards in camera order, so the output equals the sequential pass.
SceneManager::buildRenderState references a single visible point cloud instead of copying it, so its cached render state is reused. A merge of several clouds still rebuilds.
Tests
CameraFrustumPickTest.CachedFrustumsFollowEveryInputChange (lichtfeld_visualizer_tests, cameras of the bicycle scene): picks over a cursor grid must equal those of an uncached engine after a change of scale, scene transforms, camera set and in-place undistortion, and must repeat exactly when nothing changes. Removing the calibration comparison makes it fail. It skips without CUDA or without the dataset.
One-off check against a copy of the previous picking algorithm (not committed): 1,931,868 cursor and view combinations over perspective and orthographic views and three frustum scales, including 269,532 cursors placed 0 to 12.001 px from frustum corners. All results identical.
ctest -R lichtfeld_visualizer_tests: 620 tests passed.
GUI smoke run: frustums and thumbnails render, no errors in the log.

What changed in this PR
This PR reduces CPU work in LichtFeld Studio’s viewer for large camera sets through geometry caching, parallel picking and overlay calculations, and single-point-cloud render-state reuse.
Changes:
Cache camera geometry and converted scene transforms while preserving ordered picking behavior.
Parallelize overlay projection and coloring, with ordered output and cleared visibility flags.
Add regression tests for cache invalidation, picking equivalence, overlays, and point-cloud state reuse.
