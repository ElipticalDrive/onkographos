Codex P2 review on PR #325: after `apply_preset(preset_name)` succeeded,
load_from_project_settings() unconditionally re-read max_raster_splats_per_tile,
key_bits, tile_bits, depth_bits, and enable_tie_breaker via ps->get_setting(...).

(65536/64/32/32/false), selecting any preset that defines a different layout

back to the GLOBAL_DEF defaults, defeating the preset's intended bandwidth
and tie-budget choices.

layout (or want to override one preset knob) should select
gpu_sorting/preset = "custom", which falls through to the manual-config
block at the function tail and reads every knob individually with the
intended fallback chain. Debug/logging/profiling reads remain since they're
orthogonal to the sort-key layout.

* gaussian_splatting/io: PLY + SPZ importers populate opacity_logits

GaussianSplatAsset::_ensure_buffer_sizes zero-fills opacity_logits to
splat_count as a defense against the 0xC0C0C0C0 poison pattern. Both PLY
and SPZ importers populated colors[i].a from sigmoid-decoded opacity but
never called set_opacity_logits(...). Net: .tres saved with all-zero
opacity_logits + correct color.a values.

At runtime, GaussianSplatAsset::get_opacities() (asset.cpp:549) prefers
opacity_logits whenever sized — applying sigmoid(0)=0.5 to every splat
regardless of color.a. Visible symptom: every splat rendered at ~50%
opacity producing fuzzy/over-opaque output, with an alpha_clip cull
cliff at exactly 0.5 (since g.opacity == 0.5 for every splat).

Fix populates opacity_logits with Math::log(p/(1-p)) per splat in
lockstep with color.a writes, then calls asset->set_opacity_logits()
before save. Pre-existing assets need a forced re-import (delete the
.godot/imported/<asset>.ply-*.tres cache).

* gaussian_splatting/gpu_sorting: stop GLOBAL_DEF defaults from overriding preset key layout

Codex P2 review on PR #325: after `apply_preset(preset_name)` succeeded,
load_from_project_settings() unconditionally re-read max_raster_splats_per_tile,
key_bits, tile_bits, depth_bits, and enable_tie_breaker via ps->get_setting(...).
Because every one of those paths is registered with GLOBAL_DEF defaults
(65536/64/32/32/false), selecting any preset that defines a different layout
(notably preset_low() with 32-bit keys at 16/16) would be silently promoted
back to the GLOBAL_DEF defaults, defeating the preset's intended bandwidth
and tie-budget choices.

layout (or want to override one preset knob) should select
gpu_sorting/preset = "custom", which falls through to the manual-config
block at the function tail and reads every knob individually with the
intended fallback chain. Debug/logging/profiling reads remain since they're
orthogonal to the sort-key layout.
