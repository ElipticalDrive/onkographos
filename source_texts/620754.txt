What happens
The [ methods for DenseNeuroVol with i numeric or integer and j missing (R/array_like.R, around lines 338 and 365) choose between two meanings from the values of i:
```
in_first_dim <- rng[1L] >= 1 && rng[2L] <= dim(x)[1L]
if (in_first_dim) x@.Data[i, , , drop = drop] else linear_access(x, i)
```
So vol[idx] with a vector of linear indices returns whole slices whenever every index happens to be ≤ dim(x)[1]:
```
library(neuroim2)
sp <- NeuroSpace(c(6, 6, 4))
a <- array(FALSE, c(6, 6, 4)); a[6] <- TRUE
v <- LogicalNeuroVol(a, sp)
length(v[which(a)])   # 24 (the slice v[6, , ]), not 1
a[] <- FALSE; a[8] <- TRUE
length(LogicalNeuroVol(a, sp)[which(a)])  # 1
```
conn_comp() relies on linear indexing internally (vals_in <- x[lin_idx] in R/neurovol.R), so it errors when every suprathreshold voxel lies in the first row of the volume:
```
conn_comp(LogicalNeuroVol(array(c(rep(FALSE, 5), TRUE, rep(FALSE, 138)), c(6, 6, 4)), sp))
#> Error in order(cid, -vals_in) : argument lengths differ
```
I found this in fmriregdsl's cluster explorer. Leave-one-subject-out group maps on a small grid produced a single suprathreshold voxel at linear index 6 on a 6 × 6 × 4 grid. With real-size grids it is rarer, but any code doing vol[which(mask)] silently gets the wrong values when the mask sits in the first x-row.
Suggestion
Decide by the call rather than by the values. x[i] and x[i, ] differ in nargs() (2 against 3), as in base R, where arr[i] is always linear indexing:
```
if (missing(k) && nargs() == 2L) return(linear_access(x, i))   # x[i]
x@.Data[i, , if (missing(k)) TRUE else k, drop = drop]          # x[i, ] / x[i, , k]
```
Apply it to both the numeric and integer methods, and to the ArrayLike3D method if it can be reached the same way. A regression test along the lines of the snippet above (length(v[6]) == 1, length(v[6, , ]) == 24) and a conn_comp() call on a first-row mask would lock it in.
