brepjs-implicit Phase 1 — field-first SDF core
First build phase of the brepjs-implicit program (evolving brepjs-voxel from mesh-first into a LEAP71/PicoGK-class field-first implicit engine; north-star = a regen-cooled rocket thrust chamber). Phase 0 de-risk spikes are complete and locked the design; this is the integration build.
What this adds
Today's VoxelField is mesh-first — you voxelize an existing mesh into a Grid. Phase 1 adds the field-first path: an analytic SDF expression tree that rasterizes directly into the same Grid substrate with no input mesh.
Rust (packages/brepjs-voxel-wasm/src/sdf/)
Expr tree with eval(p) -> distance + conservative analytic bounds().
Primitives (exact-distance, Inigo Quilez catalog): sphere, box, rounded-box, capped cylinder, capped cone, capsule, torus, plane.
Operators: hard + smooth booleans (polynomial smin; k=0 reproduces the hard op bit-exactly), offset / round / shell / onion.
Domain ops: translate / rotate / scale.
rasterize(expr, bounds, res, padding) fills a Grid with the same banded semantics as voxelize_mesh_banded, so the existing contour / offset / shell / reinit seam behaves identically.
Surfaced via an opaque #[wasm_bindgen] Sdf class + VoxelField::from_grid.
TypeScript (src/implicit/)
A Result-typed SdfHandle builder mirroring voxel/fieldFns disposal conventions (using / Symbol.dispose), rasterizing into the existing VoxelFieldHandle.
Root-barrel exports: sdfSphere, sdfBox, sdfRoundedBox, sdfCylinder, sdfCone, sdfCapsule, sdfTorus, sdfPlane.
Skeleton chamber v0 — a hollow cone + ring of cooling channels, rasterized and contoured watertight (Rust test + TS integration test against the real wasm engine). This is the skeleton-first forcing function: the demonstrator exists from Phase 1 and gets fleshed out as each capability lands.
Scope boundaries (deliberate)
No sweep, sparse-rasterize, rayon threading, or Manifold-DC yet — those are Phases 2–3. Phase 1 is the correctness-first algebra + integration.
Verification
Rust: 96 tests pass (78 pre-existing + 18 new), clippy -D warnings clean. New tests cover primitive exactness, the Spike-C smin fillet = k/4 invariant (machine precision), rasterize-vs-fill_box_sdf sign parity at every voxel, bounds() conservativeness, k=0 == hard ops, and negative-scale sign preservation.
TS: typecheck / lint / boundaries / format / knip / pattern-checker all clean; public-API surface test updated; the full changed-file suite (3395 tests) passes; implicit integration suite green against the rebuilt wasm artifact across all kernel projects.
Review notes
Two reviewer findings from the build Workflow were addressed before commit: a MEDIUM correctness bug (negative uniform scale was inverting the field sign — fixed to scale distance by |s|, with a regression test) and a misleading round() docstring. The capped-cone and smin math were adversarially verified against brute-force ground truth (0 sign mismatches over 200k points).

### Issue 1 of 2
tests/implicitCore.test.ts:88-104
**Accumulator not guarded against mid-loop exception**

Inside `buildChamber`, `acc` is disposed manually with `acc[Symbol.dispose]()` on the line immediately after `acc.union(placed)`. If `acc.union(placed)` throws (e.g., if `placed` were disposed before this call, or a WASM panic occurs), the explicit `acc[Symbol.dispose]()` is never reached and the accumulated WASM tree leaks for the remainder of the test run. The `using channel` and `using placed` guards in the loop protect those handles, but nothing protects the accumulator itself in the exceptional case. Per the `disposal-required` rule, a `DisposalScope.register(acc)` after each reassignment would make disposal unconditional.

### Issue 2 of 2
packages/brepjs-voxel-wasm/src/sdf/expr.rs:95-100
**`Aabb::scale` produces inverted bounds when `s < 0`**

Multiplying `min` and `max` directly by a negative scalar swaps their ordering (min becomes larger than max), producing an inverted AABB. The current call site in `bounds()` guards against this by passing `s.abs().max(f64::MIN_POSITIVE)`, so there is no live bug, but `scale` is `pub` with no documented precondition. Any future `Expr` variant that calls `scale` with a raw possibly-negative value would silently produce nonsensical bounds. Adding a doc comment noting `s` must be non-negative would make the precondition explicit.
