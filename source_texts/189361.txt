Contributor
What problem are you trying to solve?
wp.bvh_query_ray() and wp.tile_bvh_query_ray() can skip a box when a ray runs exactly along one of its faces. A MuJoCo Warp report found the same missing hits downstream. Lower-face rays were already missed in Warp v1.13.0; a change first released in v1.14.0 made upper-face rays fail too.
Closes #2011.
What does this change?
Scalar and tiled BVH ray queries now retain intersections on AABB faces, including flat boxes. The existing max_dist boundary is preserved. The change also adds CPU and CUDA regression coverage and a changelog fragment.
Existing pull requests
Checked open pull requests for duplicate or overlapping work.
Related pull requests: #1762 touches the tiled BVH code but addresses a separate block-size bug.
Validation
Regression validation: The new boundary test failed without the fix and passes with it on CPU and CUDA. It covers both faces, signed zero, reverse rays, flat boxes, root bounds, and max_dist.
NVIDIA GPU: RTX PRO 6000 Blackwell Server Edition MIG (sm120) on Ubuntu 22.04.5 LTS; tested on both visible CUDA devices.
Other validation: The native rebuild, 50 BVH tests, 20 fast-math tests, and targeted pre-commit checks passed. The largest observed slowdowns were 2.7% in ASV BvhRayQuery and 2.6% in the benchmark_bvh.py ray cases, below the agreed 5% threshold. AOT builds showed unchanged register counts for the measured sm110 and sm120 kernels. Runtime was measured on sm120 hardware.

Keep tiled BVH ray queries unbounded (NVIDIAGH-2011)
…
599e444
```
Tiled BVH rays have no distance limit, but FLT_MAX interval endpoints
reject valid intersections for sufficiently small, unnormalized
directions. The CPU fallback also applies the scalar distance cutoff.

Use unbounded intervals and preserve the original direction when
widening overflowing slab times. This keeps corner contact and rejects
disjoint intervals without making ordinary node tests use double
precision. Give CPU tiled rays an unbounded traversal mode while
preserving explicit scalar distance limits.

Validation: Standard native build, 79 BVH and grouped-BVH tests,
expanded CPU/CUDA regressions, and pre-commit checks.

Signed-off-by: Eric Shi <ershi@nvidia.com>
```

Guard BVH ray arithmetic ranges (NVIDIAGH-2011)
…
d47657d
```
CUDA fast math can flush finite reciprocals and slab differences to
zero. Combined with overflow, NaN-tolerant boundary clamps can then
discard real slab constraints and report false hits.

Certify bounds during BVH construction and updates so ordinary rays keep
the float path without per-box range checks. Widen unsafe arithmetic
from the original direction, retain scalar distance cutoffs, and share
the policy with tiled queries. Cache certification in an unused packed-
node flag and refresh it through all creation and update paths,
including winding-enabled mesh refits and graph replay.

This shifts range checks to an extra bounds scan during updates.
Measured refit overhead at 262k boxes is about 7 us on CUDA and 0.3 ms
on CPU, while ordinary query workloads retain or improve prior
throughput.

Validate with 107 targeted tests on CPU and two CUDA devices, including
extreme inputs, packed leaves, distance cutoffs, and update transitions.

Signed-off-by: Eric Shi <ershi@nvidia.com>
```
