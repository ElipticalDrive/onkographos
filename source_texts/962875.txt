You can actually set the seed of the node prng as well I'm doing that + a few other things to set up the benchmarks here:
https://github.com/jwagner/simplex-noise.js/blob/master/perf/benchmark.sh
At the CPU level I assume the LUTs are quite fast because they fit into L1 whereas the conditionals can cause branch mispredictions which are fairly expensive. But I haven't done any low level optimizations in quite a while.
At the node level I'm not sure what's going on but a general observation is that JavaScript jits by their nature need simple code to operate on. If functions get to complex they can get confused and will not work efficiently anymore. But I don't think that's what's happening here. The effects of that are usually more severe.
Anyway given that you arrived with similar results I did I guess the optimizations are not worth it. The corrections for the discontinuities sound like a good idea though. Am I correct that those involve nothing more than changing the 0.6 to 0.5 when calculating the t values?
