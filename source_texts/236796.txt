Owner
Fixes bugs found in two reviews of the codebase and aligns training with the reference 3DGS / Mip-Splatting / 2DGS implementations (each claim checked against their source). One commit per fix.
Bugs (first review)
Rasterizer backward with tile_size < 16 (3DGS and 2DGS): gradient staging assumed 256 threads per tile; smaller tiles read uninitialised shared memory, which gave wrong gradients and possible out-of-bounds atomics. The forward pass was unaffected.
Opacity reset kept stale Adam moments: after each reset, opacities recovered too slowly, and the next densify cull removed about 76% of the 2DGS model. The reset now zeroes the opacity's Adam moments, as the reference does.
Hard edges at tile borders and at the image border: tile boxes and projection culling stopped at 3σ, but an opaque gaussian still draws out to about 3.33σ. Tile boxes are now opacity-aware (sqrt(2 ln(255·opacity))), and projection culls at the maximum extent.
SH color not clamped at 0, unlike the reference and every viewer.
PLY export ignored the 3D filter, so exported scenes looked different in external viewers; save_ply(..., filter_3d=) now bakes it in.
PSNR was computed on unclamped predictions; one shared losses.psnr now clamps to [0, 1].
Held-out eval views leaked into training through the 3D filter, the initial scale and the camera extent.
Bugs (second review)
SH evaluation read other gaussians' coefficients when the active degree was above the stored one (eval_sh defaulted to degree 3). It now validates the degree, and the kernel gates every band on the stored count.
No input checks at the Metal op boundary: an int64 background rendered black, and an abs_grad_accum left at a stale size took atomic adds past its end. The wrappers now check dtype, device and shape.
3DGS depth and final_T reported requires_grad=True but their gradient was dropped, so a depth loss trained nothing. They are now marked non-differentiable.
The 3DGS reference rasterizer composited the gaussian that exhausts transmittance; the kernel drops it. The oracle was up to ~5e-3 off, under the tests' tolerance.
Densify stopped pruning once at max_points, and one round could overshoot the cap. The cap is now hard, and pruning always runs.
2DGS tile bounds were a 3DGS EWA box × 2.5 margin. They still clipped some tilted near-camera splats (4 of 480 drawn splats in random scenes) and were ~2.5× too wide per axis otherwise. Bounds are now the exact screen box of the splat's alpha-cutoff ellipse under the projective transform, and opacity-aware.
Model rebuilds went through the activations (densify, prune, seed, cleanup): logit's clamp capped every raw opacity at ±9.2, and quaternions were renormalized under migrated Adam moments. Rebuilds now copy raw parameters losslessly.
COLMAP fy/cy were scaled by the width ratio; they now use the height ratio (garden: cy 420.2 → 420.0).
Seeding's fallback depth came from every gaussian in front of the camera instead of those in frame.
Saving a model with zero gaussians crashed.
.gitignore's data/ also matched src/metalsplat/data/, so new files there would never be committed.
Structure
Shared model base: GaussianModel and Gaussian2DModel subclass one SplatModel, with lossless row operations (select, cat, raw_rows, with_rows).
Less duplication: one split/clone/prune core for both pipelines. Prune, seed and cleanup accept either model, and the 3DGS/2DGS copies of .ply I/O and Metal helpers are merged. The .ply parser now rejects non-float properties instead of misreading them. The Metal helpers live in kernels/common.metal, which the kernel loader inlines via a local #include.
metalsplat.training.GaussianTrainingState keeps the optimizer, accumulators and 3D filter in step with the model through densify/seed/prune. Both training scripts use it.
Clearer environment requirements: render() on CPU raises a clear "needs MPS" error, and the README no longer calls the references a CPU fallback. KMP_DUPLICATE_LIB_OK is set only when a COLMAP scene is loaded, not on import.
API changes
2DGS projection and rasterization:
project_gaussians_2dgs returns (means2d, depths, rects, valid, transform, normal) and takes filter_size / opacities.
rasterize_gaussians_2dgs takes rects instead of radii / conics.
render_2dgs drops eps2d, which only fed the old bound.
eval_sh defaults to the degree the coefficients hold.
Densify: max_points is a hard cap. prune_low_opacity_2dgs is now an alias of prune_low_opacity.
Aligned with the reference
3D filter: sampling_scale scales the variance, as in Mip-Splatting (* 0.2 ** 0.5); the old filter was about 2.2× too narrow.
Learning rates: SH base color 0.0025 and higher bands /20 (new per-coefficient lr_scale in SparseAdam), scales 0.005, rotations 0.001, held constant.
Density control: split and clone first, then prune the result; world-size pruning at 0.1 × camera extent (3DGS and 2DGS); split threshold at percent_dense × camera extent (3DGS). The reference's 20 px screen-size prune is deliberately not reproduced: its densification_postfix zeroes max_radii2D first, so it never fires. Enforcing it deleted foreground gaussians.

Validate tensors at the Metal op boundary
…
17a9404
```
The kernels index raw float32 buffers by gaussian id and stride with no
bounds checks, so a bad input was wrong memory rather than an error: an
int64 background was reinterpreted as float bits and rendered black, a
non-float32 input was misread, and an abs_grad_accum / pixel_count_accum
not reallocated after a densify, seed or prune took atomic adds past its
end.

The op wrappers now check every per-gaussian input for dtype, device and
shape, and the in-place accumulators for size and contiguity (a copy
would silently swallow the kernel's adds). The background is converted to
float32 on the right device, since nothing depends on its identity.
```

Bin 2DGS splats by their exact screen footprint
…
bda6b2f
```
2DGS reused the 3DGS EWA (local-affine) projection, with the missing
third scale set to 1e-6, to bound each splat for tile binning, inflated
by a 2.5x margin and blind to opacity. The affine approximation
underestimates a tilted or near-camera disk's perspective footprint, so
the margin still missed some (4 of 480 drawn splats, 320 composited
pixels, in random near-camera scenes), and it made every face-on splat's
box ~2.5x too wide per axis.

The footprint is now exact. The rasterizer draws where min(rho_uv,
rho_screen) is under the alpha cutoff: the perspective image of the
local ellipse u^2+v^2 <= c^2, whose dual conic T diag(c^2,c^2,-1) T^T
gives a closed-form bounding box (the whole frame if the ellipse reaches
the camera plane), joined with the screen filter's disk. The cutoff is
opacity-aware as in 3DGS; validity uses full opacity.

- Tiling bins per-gaussian rectangles (bin_and_sort_rects); 3DGS keeps
  bin_and_sort_gaussians, which derives them from its conic.
- project_gaussians_2dgs returns (means2d, depths, rects, valid,
  transform, normal) and takes filter_size and opacities; the EWA path
  (whose gradients were always zero) and eps2d are gone, also from
  render_2dgs. rasterize_gaussians_2dgs takes rects instead of
  radii/conics.

On the trained garden model the renders are bit-identical and 2x faster
(14.1 -> 6.9 ms per eval view); 3DGS renders are unchanged.
```
