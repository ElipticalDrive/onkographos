💡 What: Refactored MeshProcessor::from_file to perform transformation mapping (rotation, centering, scaling, translation, vertex noise) in only two unified passes, caching minimum and maximum constraints locally rather than triggering a post-build BVH query via TriMesh::local_aabb().
🎯 Why: Previously, transformations sequentially iterated over the entire Vec<Point> array up to six independent times. By using loop fusion and tracking coordinates on the final pass, we significantly reduce memory overhead, improve spatial cache localization, and remove a completely redundant O(N) recalculation for bounds.
📊 Impact: Increases voxelization speed and memory efficiency for large source meshes by avoiding repeated array passes and bounds calculations.
🔬 Measurement: Cargo tested locally under test_transform_combined to successfully ensure transformation sequencing accurately tracks point bounds natively matching the original isolated code path bounds.

Use indexed triangles when deriving bounds
This loop updates final_min/final_max from every entry in points, which changes behavior from the previous mesh.local_aabb() path: load_obj keeps all OBJ positions, including vertices that are never referenced by any face, while Parry’s trimesh AABB is derived from indexed triangles (QBVH). As a result, orphan vertices can now incorrectly inflate bounds_min/bounds_max, producing much larger voxel grids and unnecessary memory/runtime spikes for otherwise unchanged meshes.
