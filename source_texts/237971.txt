Adds source-power importance allocation, stratified initial directions, emissive-triangle transport and spatially ordered flux importance resampling to the VPL generator. The candidate multiplier increases CPU sampling during static generation while preserving the requested GPU VPL count and shadow-map capacity. Finite inverse-square point-light cutoffs propagate correctly through later diffuse bounces.
Both examples expose source importance, emissive transport and CPU candidates. The sampler supports transformed/indexed meshes, material groups, emission textures, alpha cutouts and double-sided emission. It adds no BVH dependency. Static geometry and diffuse transport remain the supported scope.
Validation: nine targeted VPL tests cover determinism, colored source power, escaped rays, transformed/textured emissive surfaces, cutouts, compression and finite attenuation. The WebGPU example renders in Chrome on Windows. Addon/example/test lint passes. The full addon run encounters the same pre-existing WebGL atan precision failure on the unchanged local base (error ~0.000011 against tolerance 0.00001).
Three-scene RTX 3060 Ti comparison: the experimental 128-VPL / 8-bounce / 16x-candidate configuration with a 3-unit clamp improves Blender PSNR by 3.95–4.66 dB over the original 128-ray / 2-bounce / 1-unit-clamp defaults, with steady-state frames around 3 ms. These figures combine algorithm and setting changes. Fixed-setting Cornell basic ablations attribute about 0.65 dB to emissive transport and 0.93 dB to source importance. The old per-texel RIS lightmap renderer remains substantially more accurate, so its replacement is deferred.
This PR targets the existing VPL feature branch. The fidelity-project integration and lossless captures are tracked in bhouston/three-fidelity#222.
