Summary
Closes #3194.
Implement native float16 and bfloat16 input support for IVF, BruteForce and LazyHGraph rather than rejecting these dtypes. Both formats use the existing shared Dataset::Float16Vectors(uint16_t*) API; input dtype is independent of the storage quantizer.
IVF converts native inputs at the index boundary, with sampled partition/base training and full-dataset precise/reorder training, and consistent float32 routing/storage internals. Half conversion is sample-only without reorder; with reorder the full dataset is converted once to preserve existing quantizer training semantics. This avoids double interpretation through QuantizerAdapter, per-vector conversion allocation in the IVF bucket hot path, and sampling lifetime/null-pointer bugs.
BruteForce uses native data consistently for build/add/search/update and Dataset distance calls, validates missing input, and exports storage reconstruction directly to float32 without narrowing through the input dtype. Removal compaction preserves encoded bytes instead of decoding and re-encoding. Unsupported sparse records are rejected before they can enter dense storage.
LazyHGraph supports its flat phase and graph transition, rebuilding native input from exported float32 data. HGraph export and native update-distance paths are corrected for this transition.
Generic FP16 conversion now handles IEEE signed zero, subnormals, infinities and NaNs, with nearest-even encoding. These boundaries are used by the new conversion paths.
Add numerical, malformed-input, serialization, route-graph, bucket-graph-rebuild and LazyHGraph-transition regressions.

[P2] [P2] Update capability detection for native-input adapters
For either newly supported half dtype with default fp32 storage, the flatten factory creates a quantizer named QUANTIZATION_ADAPTER_fp32. InitFeatures() still compares that name directly with fp32, so it omits SUPPORT_GET_RAW_VECTOR_BY_IDS; consequently, public GetRawVectorByIds() returns UNSUPPORTED_INDEX_OPERATION even after a successful build with lossless FP32 storage. The same comparison incorrectly marks these uncompressed indexes as needing training and omits their range-search/add-from-empty flags. Determine capabilities from the underlying storage quantizer when enabling native input.

major — 半精度路径下 float_dataset 的零拷贝契约与 scratch 生命周期需要显式约束。
该函数对 float32 输入直接返回入参 data，对半精度输入则返回一个新的 Dataset，其 Float32Vectors(scratch.data()) 且 Owner(false)。也就是说返回值始终指向调用方传入的 scratch，而 Dataset 自身并不持有它。当前三个调用点（Train 的 training_scratch、add 的 input_scratch、SearchWithRequest 的 query_scratch）都是局部变量，作用域覆盖了各自的使用区间，因此暂时正确；但接口签名上这两者的绑定关系完全隐式，返回的 DatasetPtr 如果被存下来或跨作用域传递就是悬垂指针。
