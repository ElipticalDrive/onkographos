Summary
Extend FrameGraphGeometryRendererTask so its beauty output includes the supported scene renderers while its MRT geometry outputs remain correctly typed and isolated.
Add native GLSL/WGSL geometry outputs for Gaussian splats, sprites, and CPU/GPU particles.
Render bounding boxes, edges, outlines, and overlays into beauty only, without contaminating geometry attachments.
Add optional FrameGraphObjectList.spriteManagers selection and propagate it through culling, NRGE, and MCP metadata. Omitted/null selects scene managers; an empty array selects none.
Prepare render-pass-specific resources before the first frame, and manage effect/VAO/motion-cache lifetime across rebuilds and pass disposal.
Behavior and scope
Existing opt-in defaults are preserved. CPU/GPU particles write neutral velocity values; sprite and Gaussian motion outputs remain supported. Translucent geometry retains the existing single-pass approximation. Automatic Gaussian geometry output covers GaussianSplattingMaterial; custom Gaussian NodeMaterial graphs retain their explicitly connected prepass outputs.
The implementation also preserves zero-alpha additive beauty contributions, supports non-UBO Gaussian geometry bindings, and avoids unnecessary work for unrequested outputs.
Validation
Repository formatting, source build, full typed/advisory lint, and tree-shaking checks.
Full unit suite: 398 files, 5,947 passing tests and one expected failure, including regressions for attachment routing, readiness, selection, cache disposal, motion history, blend behavior, and snippet revision handling.
Seven first-frame visualization cases on both WebGL2 and WebGPU (14 passing runs), without renderCount.
Byte-for-byte beauty comparisons between geometry and regular object-renderer paths, including the 786,233-splat Gaussian model.
Local unit runs use a 30-second timeout for cold module imports. Full typed lint used a verified 16 GB heap and reported zero errors; existing repository advisory warnings remain. Windows path assertions were normalized so the relevant test fixtures run on Windows.
The branch includes current master. The merge preserves the upstream per-axis Gaussian focal correction from #18921; the synthetic orthographic references were refreshed for that corrected footprint. Geometry and ordinary beauty outputs remain identical.

This beauty-only layout enables only attachment 0 even when targetTexture is an array. The base object-renderer task treats every array entry as a render target, and this task places all of them before the geometry attachments, so targetTexture[1..] are disabled for auxiliary/single-output draws. Keep all caller-supplied target slots enabled (for example, use index < targetTextureCount).

```
        this._colorAttachmentsLayout = this._engine.buildTextureLayout(allAttachmentsLayout.map((_, index) => targetTextureCount > 0 && index === 0));
```

When textureDescriptions contains PREPASS_COLOR_TEXTURE_TYPE and a beauty target is also supplied, this assignment overwrites the geometry color index computed above with 0.         if (targetTextureCount > 0) {

packages/dev/core/src/Materials/materialHelper.geometryrendering.ts:515
The new frame guard only prevents multiple updates within one frame; it does not detect a skipped frame. If a mesh renders at frame N, is absent at N+1, and reappears at N+2, currentWorldMatrices still contains frame N and is copied into previousWorldMatrices, producing a velocity spanning the visibility gap instead of neutral/reset motion. Reset the previous world matrix to the current world when the last update was not the immediately preceding frame.
```
            if (worldMatrixFrameIds[mesh.uniqueId] !== engine.frameId) {
                configuration.previousWorldMatrices[mesh.uniqueId].copyFrom(currentWorldMatrices[mesh.uniqueId]);
                worldMatrixFrameIds[mesh.uniqueId] = engine.frameId;
```
packages/dev/core/src/Materials/materialHelper.geometryrendering.ts:527
The view-projection history has the same discontinuity problem: after the geometry pass is skipped for a frame, a camera change takes the currentViewProjection from before the gap as previousViewProjection. The next velocity texture then reports motion across a period with no continuous prior frame, contrary to the task's temporal-history contract. Track continuity (and camera identity where multiple cameras share a pass) before reusing the old matrix; otherwise initialize both histories from the current transform.
```
            } else if (configuration.currentViewProjection.updateFlag !== scene.getTransformMatrix().updateFlag) {
                // First update of the prepass configuration for this rendering pass
                configuration.lastUpdateFrameId = engine.frameId;
                configuration.previousViewProjection.copyFrom(configuration.currentViewProjection);
                configuration.currentViewProjection.copyFrom(scene.getTransformMatrix());
```
