Reproduced issue: display 1 (yaw=45°, x=−1.0397) produces left=−1.152m, right=0.066m; user expects left=−0.066m, right=1.152m
Identified root cause: Three.js places the display with negated yaw (yawRad = -yaw * π/180, see sceneRenderer.js:770). To face that display, the Three.js fps camera needs rotation.y = 180° − display_yaw. At that angle the camera right vector is {−cos(yaw), 0, −sin(yaw)}, which is the negative of our current localX = rotateVector({1,0,0}, yaw).
Fix calculateDisplayAxes in display.js: change rotateVector({ x: 1, y: 0, z: 0 }, ...) → rotateVector({ x: -1, y: 0, z: 0 }, ...)
Fix calculateProjectionCorners in mathutils.js: negate the x component returned by inverseRotateVector; replace fixed-index min/max for angles and normalized corners with Math.min/max over all four corners
Fix getNearPlaneFrustum in display.js: replace fixed-corner indices with Math.min/max over all scaled corners
Fix updateNearPlane in sceneRenderer.js: change if (nearestDist <= 0) return → if (Math.abs(nearestDist) < 0.0001) return; replace np.normal * nearPlane with np.(x,y,z) * (nearPlane / Math.abs(nearestDist))
