Problem description
How do games like Minecraft or medical MRI scanners convert raw 3D data/noise into smooth, renderable surfaces? The Marching Cubes algorithm sweeps a theoretical cube through a 3D scalar field. By evaluating whether each of the 8 corners is "inside" or "outside" a threshold (an isovalue), it uses a 256-state lookup table to generate polygons. It is a legendary algorithm in computer graphics.
Proposed solution
Implement a 3D WebGL / Three.js Engine:
The Scalar Field: Render a 3D grid of points floating in space, colored based on a mathematical noise function (e.g., Perlin noise).
The Sweeping Cursor: A glowing wireframe cube slowly iterates through the grid, cell by cell.
Polygon Generation: As the cursor evaluates a cell, pause the engine. Highlight the corners that exceed the isovalue, draw the intersecting vertices on the edges, and animate the triangles filling in to build a solid 3D mesh.
Technical Constraints
Requires Three.js to manage camera controls (orbit/zoom), lighting, and dynamic mesh generation.
Must cleanly visualize the bitwise operations used to index the 256-state edge table.
Acceptance Criteria
[ ] Accurately generates a contiguous 3D mesh from a 3D array of noise values.
[ ] UI allows users to adjust the "Isovalue" slider, dynamically shrinking or expanding the generated mesh in real-time.
[ ] Step-by-step mode clearly highlights the 8 corners of the active cube and the resulting intersection points.
