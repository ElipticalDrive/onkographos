A sharp nearest-biome heightfield can produce shared central-difference normals that point behind its emitted stored triangles. The regression fixture previously had seven behind-face corners. After indexing, the builder now checks actual stored faces and replaces only offending shared normals with exact [0, 1, 0]; every heightfield face has positive Y winding. Valid normal bytes, positions, grid dimensions and indices remain unchanged.
This is a selective upward fallback, not face-normal averaging or corner duplication. The repair mask is allocated only when needed and bounded by the existing vertex limit. Public documentation explains the shading tradeoff and retained grid contract.
Validation: 101 unit tests, typecheck, lint (nonblocking warnings), build, package analysis and packed consumers passed. Independent source review verified the fallback and cache/layout preservation. A source-bound Metal fixture checks actual adapter buffers and rendered normal/lit-gray views, rejects an injected old-normal fault, restores exact buffers/captures and verifies disposal. Root inspected the captures; portable CI retains the images and receipt. Measured overhead over the cached builder was about 6–7% on two bounded fixtures, not a general performance guarantee.
Closes #21.

Review Summary
This PR adds correctHeightfieldIncidentNormals — a selective post-build pass that detects central-difference normals pointing behind their incident stored faces (a regression caused by sharp nearest-biome heightfield discontinuities) and replaces only the offending shared normals with the exact upward [0, 1, 0] fallback.
Core implementation (src/terrain.ts): The algorithm is structurally correct. The two-pass design (mark → repair) cleanly separates detection from mutation, and the lazy allocation of the repairs mask means no allocation occurs for smooth heightfields. The cross-product normalization pre-scales by the max component before calling Math.hypot, avoiding intermediate overflow. The existing builder guards (non-zero area check, finite normal magnitude) carry over correctly into the new post-pass. One concern raised above: the function accepts raw buffers without verifying that all vertex indices in indices are within [0, normals.length / 3 - 1]. While this invariant holds by construction at the call site, it is an unverified implicit assumption inside the function.
Test coverage (tests/terrain-incident-normals.test.ts): The two unit tests are well-scoped — the first asserts the exact regression count (7 behind-face corners) and that all dots are positive after repair; the second asserts byte-for-byte identity for smooth inputs. The Math.min(...incidentDots(legacy)) spread call is fragile for large fixtures (see inline comment).
Visual proof (tests/terrain-normals.playwright.ts): The Playwright test is thorough — it verifies the fault is visible, that restoring old normals fails the incident predicate, and that buffers restore byte-for-byte. The CI additions for the new Playwright config and artifact path are correct.
Two findings raised inline:
Silent bounds invariant in correctHeightfieldIncidentNormals — not a current crash risk but fragile.
Math.min(...incidentDots(legacy)) spread pattern — a one-click fix to use .reduce() is provided.
