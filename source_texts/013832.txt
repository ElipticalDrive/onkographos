Note, that there is a peculiar bug, where it won't traverse when "rd.y==0.". It happens in many shaders, however A Fast Voxel Traversal Algorithm does some carefull maths to avoid this.
It maps to your shader with following modifications:
- initial xy: "vec2 xy = abs((A + max(sign_rd, vec2(0.0)) - floor(A)) * rcp_rd);"
- mask computation: "vec2 mask = step(xy.xy, xy.yx);"
- xy update: "xy += mask * min(rcp_rd, 1.);"

/*
    Voxel 'Digital Differential Analyzer' Traversal Diagram by chronos
    
    // Self: https://www.shadertoy.com/view/MXfGRj
    
    This shader is the result of me trying to figure out how the voxel traversing shaders on shadertoy work.
    It didn't take me long to get the gist of it, and see how the various tricks worked for e.g branchless variants,
    but the thing I struggled with was the part where it determines and keeps track of which direction to step.
    It took me an embarrasingly long amount of time to feel like I had a rough handle on it, especially since I didn't find
    any other shaders that really explained it. I'm sure they exist, but I haven't seen any yet :)
    
    So this is my attempt to document what I learned by working it out for myself,
    and figured I may as well make it publicly available in case it helps anyone else.
    The code and notes here are currently terribly messy. I'm sorry about that, but you get what you pay for :D
    
    
    Yes, this is on a 2D grid but the method generalizes directly to 3D voxels ( or higher dimensions! )
    
    Observe that
    - The voxel traversal pattern only steps in one of two directions at a time, e.g right & up
      this is because a ray that starts in a cell only exits through one edge ( unless it's exactly on the corner )
      
    - From any cell you are currently in, it is safe to take a step the size of a voxel in the direction
      of the next 'crossing edge'. This will land us in the next voxel to visit, at the same relative position in the cell,
      without skipping over any cells or visiting them twice due to not moving far enough.
    
    - The direction of movement is axis aligned with the cell/voxel grid. In each case the direction is that of the normal vector of the 
      crossing edge / side.
    
    So now we just need to figure out which direction we should cross for each cell we visit,
    so that we do not visit any cells that the ray doesn't intersect, and we do not skip any that it does intersect.
    To that end, further observe that
      
    - The direction we should cross is the edge the ray first reaches. which is determined by how fast the ray travels in that direction
      and how far it has to travel to reach that edge.
      
    - Since there are only two possible edges to choose from (3 in 3D), and we must take one of them,
      the only thing that matters is which of the directions reaches the edge first, _not_ *when* they reach it.
      
    - If you step in an axis aligned direction (e.g X), you have not then accounted for any movement along the ray in the other direction (e.g Y).
      We must take this into account so that we as closely as possible maintain the ratio dY/dX = (B.y - A.y)/(B.x - A.x), 
      where A is the starting point, and B is the end point.
      
    - The right triangle with corners A, B and (B.x, A.y) has sidelengths equal to the total distance we
      must step in each axis aligned direction (X and Y), but it is not actually the total amount we need
      for determining where to go next, but the ratio between them, which is dY/dX, meaning that
      we don't need an endpoint at all, as long as we have the ratio of lengths of the ray direction 
      ( scaling a ray to be normalized does not change this ratio ).

    Outline of approach:
    
    The initial predicate for determining whether we move in a direction becomes essentially this:
    
        is the 
            (distance to the edge)
                divided by
            (the speed in that direction)
            
          smaller than
            
            (distance to the other edge)
                divided by
            (the speed in the other direction)
            
            ?

    But when we move in just one direction, we change the ratio dY/dX of distance traveled along each direction.
    We must somehow compensate for this when stepping.
    
    Since we always end up in _the same relative location_ in the cell whenever we step,
    the edge distances _do not change_ between steps.
    
    Therefore, we only need to initialize the stepping criterion with this offset once in the beginning,
    and only update the stepping criterions by the direction ratio discrepancy at each step. (!)
    
    
    We can find the initial edge distances for a unit-spaced grid size with edges at the integers by using 
        
        fract(x) and fract(y) for the left and down directions
        
    and 
    
        1.-fract(x) and 1.-fract(y) for the right and up directions
        
    
    Another way to view the method is to scale the grid spacing by the projected ray speed so that the distance ratio becomes 1.

    Yet one more thing to note is that uniform scaling of the grid does not change the ratios.

    Note that there are still some cases I have not yet handled here for special cases where denominators can be zero or comparisons
    have uncommon cases like equality, so be please be aware of that for any actual use!

    // See 
    // https://en.wikipedia.org/wiki/Digital_differential_analyzer_(graphics_algorithm)
    // https://www.shadertoy.com/view/4dX3zl by fb39ca4
    // https://www.shadertoy.com/view/MtcGDH by fb39ca4
    // https://www.shadertoy.com/view/4dfGzs by iq
    
    
*/

// This variable is a bit badly named, but I'm too lazy to come up with a better name heh
// it is actually the number of grid cells per unit width and height in uv coordinates.
// the unit size squares in UV coordinates are indicated in faint blue.
const float gridsize = 2.;

// zoom out factor. This is also perhaps a bit badly named since it has a reciprocal relationship to what you would expect from the name :)
const float zoom = 2.;

// Distance from line segment ab to point p
float seg(vec2 a, vec2 b, vec2 p)
{
    b-=a; p-=a;
    return length(clamp(dot(p,b)/dot(b,b), 0., 1.) * b - p);
}

// Axis Aligned Bounding Box check. Not necessary, but may be useful :)
bool within_AABB(vec2 AABB_min, vec2 AABB_max, vec2 p)
{
    return (
            all(greaterThanEqual(p, AABB_min))
            &&
            all(lessThanEqual(p, AABB_max))
        );
}

void mainImage( out vec4 fragColor, in vec2 fragCoord )
{
    vec2 uv = zoom * (2. * fragCoord-iResolution.xy) / iResolution.y;
    vec4 mouse = zoom * (2. * abs(iMouse)-iResolution.xyxy) / iResolution.y;
    float ps = zoom * 2. / iResolution.y; // pixel size in uv coordinates

    if(length(iMouse.xy) < 10.)
    {
        mouse.xy = vec2( .85,  .6) * zoom;
        mouse.zw = vec2(-.85, -.6) * zoom;
    }

    vec3 color = vec3(.0125);
    
    vec2 uv_coord_borders = 0.1 * (pow(fract(uv), vec2(32.)) + pow(1.-fract(uv), vec2(32.)));
    
    color += max(uv_coord_borders.x, uv_coord_borders.y) * vec3(1,2,3)/3.;

    vec2 p = uv * gridsize;

    vec2 pf = fract(p);
    vec2 pi = floor(p);
    float p_ps = length(fwidth(p)) / sqrt(2.); // pixel size in p-coordinates.

    float grid_thickness = 0.005;

    vec2 gridax = max(smoothstep(1.-grid_thickness-p_ps, 1.-grid_thickness, pf), smoothstep(grid_thickness+p_ps, grid_thickness, pf));
    float grid = max(gridax.x, gridax.y);

    color = color = mix(color, vec3(0.5), grid);

    vec2 vox_center = vec2(0.5);

    // grid center dots
    float d;
    float a = smoothstep(p_ps, -p_ps, length(pf-vox_center) - 0.05);
    color = mix(color, vec3(0.5), a);

    // grid origin
    color = mix(color, vec3(0), smoothstep(ps, -ps, length(uv)-0.06));
    color = mix(color, vec3(1), smoothstep(ps, -ps, length(uv)-0.05));

    // Start, end, and interpolated points
    float t = fract(iTime * .25);
    vec2 B = mouse.xy;
    vec2 A = mouse.zw;
    vec2 C = mix(A, B, t);
    
    vec2 rd = normalize(B-A); // Normalized ray direction
    
    float mousedotsize = .05;
    
    if(length(mouse.xy-mouse.zw) > 1e-7)
    {
        d = seg(mouse.xy, mouse.zw, uv) - mousedotsize/3.;
        float s = dot(uv-A,B-A)/dot(B-A,B-A);
        color = mix(color, mix(vec3(0.25, 1, 0.25), vec3(0, 0, 1), s), smoothstep(ps, -ps, d));
    
        d = length(uv-A)-mousedotsize;
        color = mix(color, vec3(0.25, 1, 0.25), smoothstep(ps, -ps, d));

        d = length(uv-B)-mousedotsize;
        color = mix(color, vec3(0, 0, 1), smoothstep(ps, -ps, d));
        
        d = length(uv-C)-mousedotsize;
        color = mix(color, vec3(1, 0, 0), smoothstep(ps, -ps, d));
        
        color += .025 * float(floor(C * gridsize) == pi) * vec3(1, 0, 0);
        
        d = seg(C, (floor(C*gridsize)+.5)/gridsize, uv) - mousedotsize/5.;
        color = mix(color, vec3(1, 0, 1), smoothstep(ps, -ps, d));
        
        d = seg(A, vec2(B.x, A.y), uv) - mousedotsize/3.;
        color = mix(color, vec3(1), .1 * smoothstep(ps, -ps, d));
        
        d = seg(vec2(B.x, A.y), B, uv) - mousedotsize/3.;
        color = mix(color, vec3(1), .1 * smoothstep(ps, -ps, d));
    }
    
    vec2 Ai = floor(A*gridsize) / gridsize;
    vec2 Bi = floor(B*gridsize) / gridsize;

    // Draw AABB
        vec2 AABB_min = min(Ai, Bi);
        vec2 AABB_max = max(Ai + 1./gridsize, Bi+1./gridsize);
        d = 9e9;
        d = min(d, seg(AABB_min, vec2(AABB_max.x, AABB_min.y), uv) - mousedotsize/5.);
        d = min(d, seg(vec2(AABB_max.x, AABB_min.y), AABB_max, uv) - mousedotsize/5.);
        d = min(d, seg(AABB_max, vec2(AABB_min.x, AABB_max.y), uv) - mousedotsize/5.);
        d = min(d, seg(vec2(AABB_min.x, AABB_max.y), AABB_min, uv) - mousedotsize/5.);
        d -= 0.01;
        color = mix(color, vec3(0.01), smoothstep(ps, -ps, d));
        color = mix(color, .5*vec3(0.1,1.,.5), smoothstep(ps, -ps, d));
    
    vec2 start_center = Ai + .5 / gridsize;
    vec2 end_center   = Bi + .5 / gridsize;
    
    vec2 current_pos_center = start_center;
    
    d = length(uv-start_center)-mousedotsize;
    color = mix(color, vec3(0,1,0), smoothstep(ps, -ps, d));
    
    d = length(uv-end_center)-mousedotsize;
    color = mix(color, vec3(0,0,1), smoothstep(ps, -ps, d));
    
    vec2 rcp_rd = 1. / abs(rd);
    vec2 sign_rd = sign(rd);
            
    vec2 xy = vec2(0);
    
    // Add distance to edge in relevant direction, and scale by projected (along edge normal) ray speed.
    // Distance to edges are fract(A) and 1.-fract(A)
    // Projected ray speed is rd.x and rd.y
    // This can very obviously be simplified and compacted, but I think this is a bit clearer: (?)
    // 
    // 
    if(sign_rd.x >= 0.)
        xy.x += (1.-fract(A.x*gridsize)) / abs(rd.x);
    if(sign_rd.y >= 0.)
        xy.y += (1.-fract(A.y*gridsize)) / abs(rd.y);
        
    if(sign_rd.x < 0.)
        xy.x += fract(A.x*gridsize) / abs(rd.x);
    if(sign_rd.y < 0.)
        xy.y += fract(A.y*gridsize) / abs(rd.y);
    
    // Draw seg from start cell center to ray origin.
    {
        d = seg(start_center, vec2(start_center.x, A.y), uv) - mousedotsize/3.;
        color = mix(color, vec3(0, 0, 1), smoothstep(ps, -ps, d));
        
        d = seg(vec2(start_center.x,A.y), A, uv) - mousedotsize/3.;
        color = mix(color, vec3(0, 0, 1), smoothstep(ps, -ps, d));
    }
    
    
    /*
        The actual traversal logic!
    */
    
    vec2 pos = A;
    vec2 mask_total = vec2(0);
    float max_steps = 100.;
    for(float i = 0.; i < max_steps; i++)
    { 
        if(!within_AABB(AABB_min, AABB_max, current_pos_center)) break;
        
        // Draw visited cell center
        {
            d = length(uv-current_pos_center)-mousedotsize/2.;
            color = mix(color, vec3(0, 1, 1), smoothstep(ps, -ps, d));
            color += .025 * float(floor(current_pos_center * gridsize) == pi);
        }

        vec2 mask = xy.x < xy.y ? vec2(1, 0) : vec2(0, 1);

        xy += mask * rcp_rd;
        
        mask /= gridsize;
        
        mask_total += mask;
        
        current_pos_center = start_center + mask_total * sign_rd;

        // Draw traversal step in alternating colors
        {
            d = seg(pos, pos + sign_rd * mask, uv) - mousedotsize/3.;
            color = mix(color, vec3(0, 1.-mod(i, 2.),mod(i, 2.)), .25 * smoothstep(ps, -ps, d));
            
            pos += sign_rd * mask;
        }
    }
    
    color = pow(color, vec3(1. / 2.2));
    fragColor = vec4(color, 1.0);
}
