Before: with Upscaler = FSR2, smoke, explosions, fire, dust and other particles smeared and left trails behind them. They write no depth and only get the camera's motion, so FSR 2 kept blending their old positions from its history. Sharpening of the FSR 2 image came only from the FSR 1.0 RCAS pass (FSRSharpness).
After: FSR 2 gets a reactive mask, so pixels covered by particles and other alpha-blended effects follow the current frame and stop ghosting, while terrain, units, trees, shadows and water keep full temporal anti-aliasing. New Options.ini keys: UpscalerReactiveScale (0 to 1, default 0.9, 0 = off) and UpscalerSharpness (FSR 2's own RCAS pass, 0 to 1, default 0.5; FSRSharpness then only sharpens the interface, so nothing is sharpened twice). Setting DXVK_FSR2_DEBUG=reactive shows the mask in red over a grey scene. INSTALL.txt describes all three.
How: RTS3DScene::Flush (Zero Hour and Generals) sets private render state 251 after the opaque scene and before translucent objects, particles and sorted alpha-blended polygons. It only does this inside the tactical view while FSR 2 is active. New DXVK patch 0015-fsr2-reactive-mask.patch copies render target 0 at that point. At present it runs AMD's ffxFsr2ContextGenerateReactiveMask on that copy and the scene colour from render state 252, using tonemap, threshold and max component as in AMD's sample. The threshold is 0.05 instead of the sample's 0.2, because LDR colour only spans 0 to 0.5 after FSR 2's tonemap. The mask then goes to the FSR 2 dispatch. The patch also fixes the SPIR-V reflection from #59, which listed resources a pass never reads. The backend bound those as empty descriptors. This caused validation errors on every frame in #59 and broke the reactive pass's constant buffer.
Checked: patches 0001 to 0015 apply with git apply and build with mingw. I also ran a native DXVK build on lavapipe with the validation layer. On a moving translucent quad, the trail measured 19.6 without the mask and 0.0 with it. The mask covers only the quad and never the interface. The per-frame validation errors are gone.
