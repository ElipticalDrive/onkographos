G4 shared generated-workspace design (controller synthesis, 2026-08-20)
Repeated workflow reviewers remain unavailable (503 auth_unavailable before tool use), so this design was derived directly from the current G1/G2/G3 code, GENERATION_PYRAMID, generated_world.rs, ChunkTrackingView, and the boot/session ownership path. No agent result is claimed.
Finite workspace and exact support ledger
The generated boot installs the exact 117 positions emitted by ChunkTrackingView::for_each at view distance 4. Build one tick-owned, X-major/Z-minor dense GeneratedChunkWorkspace around that set. Its required-status ledger is the union of GENERATION_PYRAMID.get_step_to(FULL).accumulated_dependencies() around every install target:
install target: FULL;
nearest Chebyshev distance 1: INITIALIZE_LIGHT;
distance 2: CARVERS;
distance 3: BIOMES;
distances 4 through 11: STRUCTURE_STARTS;
beyond 11: absent.
Radius 11 is therefore derived from the ported Paper pyramid, not a guessed margin. Run global status waves in deterministic X-major/Z-minor order, advancing a chunk only when its ledger status requires that rung. This ensures every neighborhood dependency is complete before the center task runs.
Retain FEATURES cross-boundary writes
Remove the production use of compose_feature_region's synthesized 17×17 owned ring. It currently drops every ring mutation after one center finishes. Instead, borrow the relevant 17×17 window from the workspace's dense iter_mut order through borrowed holder adapters. Refactor run_biome_decoration to receive that borrowed WorldGenRegion after the center's final heightmaps are primed. Target and distance-1 chunks both execute FEATURES; their write-radius-1 effects land in retained distance-2 CARVERS chunks.
Factor/expose one-rung WorldGenContext dispatch for non-FEATURES waves. The workspace intercepts FEATURES to supply its borrowed region, then consumes the integrated G1 LIGHT, G2 SPAWN, and G3 FULL seams for later waves.
Publish only complete generated authority
After every required wave succeeds, consume only the 117 target protos into a temporary Vec<(ChunkPos, LevelChunk)>. Do not touch ServerLevel/ChunkMap until every conversion succeeds. Then install the whole validated batch into an empty map before constructing or publishing the session manager. A failure drops the temporary values and returns a typed boot error; no join, partial world, or superflat fallback is possible.
ServerConfig must distinguish an explicit --seed generated request from the no-argument M1 superflat fixture, while --level retains precedence. Server::try_new performs generated boot synchronously before listener readiness.
Required tests
Pin the radius-11 ledger, exact per-distance statuses, deterministic wave order, no duplicate chunk generation, retained cross-boundary writes, all-or-nothing conversion/install, exactly 117 installed targets, is_flat=false, seed 42, no superflat fallback, and generated-world runner PASS/typed failure behavior.
Implementation task is now blocked explicitly on Batch 4, G1, and G2 release integration; G3's consuming promotion already exists locally.
