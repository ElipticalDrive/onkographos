operationId identifies the Split operation. featureId identifies the source feature. They must not be equated. outputRole is a semantic role within the source feature output. It must not be equated with negative/positive Split side or the logical outputSlotId.
Smallest proposed API change
Keep the existing read-only resolver name and existing zero/one/many result policy. Require a third caller context. Add a required scope to the authored reference. The module is not exported by index.ts, and no product or Editor caller was found. Treat this as an internal contract correction, not a public feature-graph expansion.
```
type FaceIdentity = {
  sourceId: string;
  faceId: string;
  surfaceId: string;
  loopId: string;
};

type AuthoredFaceReferenceV1 = {
  version: 1;
  scope: {
    graphId: string;
    revision: number;
    outputSlotId: string;
    bodyId: string;
  };
  featureId: string;             // Original source feature ID.
  outputRole: string;            // Original semantic Face role.
  target: FaceIdentity;
};

type QualifiedSplitFaceContextV1 = {
  schema: 'barocss-cad-qualified-split-face-context';
  version: 1;
  graphId: string;
  revision: number;
  sourceOwner: {
    featureId: string;
    outputSlotId: string;
    bodyId: string;
    outputRole: string;
    target: FaceIdentity;
  };
  split: {
    operationId: string;
    parentBodyId: string;
    negative: null | { bodyId: string; faces: readonly FaceIdentity[] };
    positive: null | { bodyId: string; faces: readonly FaceIdentity[] };
  };
};
```
This context scopes ONE requested original Face. It does not introduce a second graph, a general role registry, persistent topology history or a signed provenance format. A later adapter may produce this context from one specifically admitted graph/body family. Such an adapter is outside this correction until its ownership contract is frozen.
Caller qualification and authenticity limits
Before constructing the context, the caller must have qualified the current owning graph/document and the existing Native Split result with their unchanged validators. The caller must establish all of the following:
The current graph/revision owns the declared feature and logical output slot.
That output owns the declared body. The semantic role maps to the complete target tuple in that body.
The body is the actual Split request.parent, not another body with similar local IDs. Read bodyId from the actual qualified Solid report/request options, not a presumed logical slot ID.
target is exactly one complete row of that actual parent.graph.faces.
split.operationId equals the qualified Split request.options.operationId and report.operationId.
Each nonempty side inventory is copied from that actual outcome.solid.graph.faces. Its bodyId is read from that actual outcome, not merely from the requested negativeSolidId/positiveSolidId.
For outside/tangent cases the existing provider may return the original parent as the occupied outcome. Thus parent and output can have identical native body IDs and Face tuples. Do not require global raw-ID disjointness across parent/negative/positive scopes. Require exact body-qualified tuples and exact declared side instead.
The resolver checks the supplied context's consistency. It does not authenticate an arbitrary caller-created receipt/context or prove geometry. Existing Native validation is whole-result self-consistency, not provenance authentication. Do not call native validators from the pure resolver. No fake boolean such as certified:true is an ownership substitute.
Resolution and refusal contract
Capture each own data descriptor once. Work only on copied plain data. Refuse getters without calling them, inherited fields, symbols, hidden extras, holes, foreign prototypes, cycles and revoked-proxy reflection failures. Enforce exact fields, bounded ID strings (1..128 characters), safe revision 0..1000000000 excluding -0, and bounded dense arrays. Proposed budgets: depth12, value occurrences4096, record fields16, parent Face entries<=12, receipt faces<=12, outcomes<=2 per parent, generatedCaps<=2, output Face inventory<=12 per side. These bounds cover the existing admitted Split family. Native identity/geometry policies remain unchanged.
Missing context or an old unscoped authored reference returns unsupported. Do not infer graph/body/role from a matching local target.
Authored graphId/revision/featureId/outputSlotId/bodyId/outputRole/complete target must match the one context sourceOwner and graph scope.
sourceOwner.bodyId must equal split.parentBodyId.
Receipt operationId must be a valid ID and equal context.split.operationId. Validate all existing receipt header fields, face/outcome/cap shape, legal roles and role/null consistency.
Match ONE complete target tuple, not four separate ID memberships. Zero matching lineage rows remains missing/no-lineage. Duplicate parent rows remain unsupported.
Every surviving outcome must have a legal side and be exactly one complete tuple in that side's declared nonempty body inventory. A null side cannot own an output. A tuple from the other side/body must not be substituted.
Declared face resolution must agree with the computed survivor count. Deleted outcomes have null output; retained/clipped outcomes have an output. Malformed unrelated rows must not be silently skipped.
Zero survivors remains missing/deleted; one remains resolved; two remain ambiguous. No geometric nearest-face or side selection fallback.
Preserve the existing resolved result shape (target plus side). The caller reads the result body from the already validated context side. Do not imply a committed document.
Every result identity is a fresh copy. No caller data is changed, no input alias is returned, and no lookup failure changes a prior accepted document.
Suggested new refusal reasons are invalid-context and ownership-mismatch. Existing invalid-reference, unqualified-receipt, missing and ambiguous meanings remain. Root should freeze the exact reason strings before implementation.
