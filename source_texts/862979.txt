What to build
Stage 4 of §1.4 in ftgsxr_render::gpu: the player's own least-significant-digit radix sort of (k̄, slot) pairs in sort_count.wgsl, sort_scan.wgsl and sort_scatter.wgsl, every dispatch indirect from stage 3's arguments, run inside SplatPasses::encode_prepare. SplatPasses gets no public sort entry point: a pub(crate) sort encoder has private tests named after it, and R-4 reaches the sort through encode_prepare and the frame-buffer readback.
Spec items
§1.4 stage 4, E8, D-33, §2.4 GPU data layout (keys and payloads ping-pong between two buffer pairs). Q-n rows relied on: Q-2. PRD #76 candidate: "reading the frame buffers back for R-4 and R-5".
Acceptance criteria
R-4 passes
R-5 and R-6 still pass with the sort in encode_prepare
Every .wgsl file is referenced by ftgsxr-render (U-35 stays green)
The PRD's module doc sort.md written: the passes, the workgroup layout, why no subgroup operations, how R-4 reaches the sort
