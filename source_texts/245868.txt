Proposed changes
Fix some issues using AMR with new topologies.
Add ability to radially h-refine Bn topologies with AMR
These changes are sufficient for the RandomAmr executables to run successfully on conforming Domains.
This only tests the AMR projectors for the Mesh and Element; I will fix any issues with the remaining projectors next.
Then I will tackle non-conforming Domains (namely the compact binary domains with cylinders/spheres)

Every other basis sets its minimum to be the lowest at which it can be in order for the spectral functions (e.g. differentiation, modal <-> nodal, interpolation, integration, projection) give the correct answer. I see no reason to treat spherical harmonics differently. Setting limits based on specific use cases should be done somewhere else. For example, AMR lets you set the lower, upper limits in the input file. Meanwhile, insisting on at least L=6 in unit tests that check whether something independent of stability works for S2 or B3 makes tests slower and the length of DataVectors printed when debugging annoying.
