Summary
Completes the ADR-0013 v1 repair slice on top of the merged foundation (#1146): import a non-watertight triangle mesh → voxelize an FWN-signed SDF → Surface-Nets contour it back into a closed mesh. Each of the four seams is filled minimally, with optimizations deferred behind the same abstractions.
Seams
Rust (packages/brepjs-voxel-wasm)
Grid (grid.rs) — dense SDF grid behind an accessor abstraction (so a sparse grid can swap in later, no raw indexing exposed); MAX_VOXELS cap → GridError via checked_mul (no OOM).
Ops (ops.rs) — voxelize_mesh: exact closest-point-on-triangle distance (Ericson Voronoi regions, f64) × FWN sign (inside → negative), so holey input yields a watertight SDF; voxel boolean union/intersection/difference (min/max/max-neg).
Contour (contour.rs) — Surface Nets via fast-surface-nets 0.2 behind a Contourer trait (manifold dual contouring slots in behind it later); maps vertices into world coordinates.
Bridge (lib.rs) — wasm repair_mesh → RepairResult. 36 KB artifact (cap 250 KB).
TS
src/voxel/repairFns.ts — repairMesh(mesh, opts?) → Result<KernelMeshResult>. Validates the mesh (incl. in-bounds indices), resolution, and padding, and wraps the fallible wasm call in try/catch so a grid-cap error returns err(...) rather than escaping as a thrown wasm exception. Surfaced through the barrel; public-API allowlist updated.
Verification
20 cargo tests (grid/ops/contour + the FWN keystone), 73 vitest (incl. end-to-end holey-cube repair + Result-contract guards: OOB index, empty mesh, bad resolution, and the voxel-cap path returning err not a trap).
typecheck, lint, boundaries, knip — all green.
Build process
Built via a multi-agent workflow (parallel survey → sequential per-seam implementation, each self-gated with cargo/wasm-pack/vitest → integrate → parallel review). The review surfaced a Result-contract breach (the fallible repair_mesh call lacked a try/catch); fixed here with the validation + try/catch above and 4 added guard tests.
Deferred behind the seams (out of v1 scope)
Narrow-band + BVH/Barnes-Hut hierarchical FWN, flood-fill, sparse grid, manifold dual contouring, and a raw-KernelMeshResult→GLB adapter (the existing exportGlb takes ShapeMesh, not a bare mesh — no path exists today).

Greptile Summary
This PR completes the ADR-0013 v1 repair slice: a non-watertight triangle mesh is voxelized into an FWN-signed SDF, then Surface-Nets contoured back into a closed mesh, all exposed as repairMesh(mesh, opts?) → Result<KernelMeshResult>. Previous review concerns (disposal lifecycle on VoxelRepairResult, padding = 0 silently clipping the mesh, and the missing try/catch around the fallible wasm call) are all addressed in this revision.
Rust: grid.rs (dense SDF grid with MAX_VOXELS OOM guard), ops.rs (Ericson exact point-to-triangle distance + FWN sign), and contour.rs (Surface Nets via fast-surface-nets behind a Contourer trait) implement the core pipeline; lib.rs wires them into the repair_mesh wasm export with JsError propagation.
TypeScript: repairFns.ts validates resolution ≥ 1 and padding ≥ 1 before crossing the wasm boundary, wraps the call in try/catch, and uses the using declaration for safe RepairResult disposal; VoxelRepairResult correctly exposes free() and [Symbol.dispose]().
Tests: 20 Cargo tests (grid/ops/contour + the FWN keystone) and vitest coverage for the end-to-end holey-cube repair plus four Result-contract guards (OOB index, empty mesh, bad resolution, and the voxel-cap err-not-trap path).
Confidence Score: 5/5
Safe to merge; all three issues raised in the previous review round are resolved and the new pipeline is well-guarded end-to-end.
The wasm boundary is correctly handled: fallible repair_mesh is wrapped in try/catch, the RepairResult is disposed via using, and the TS layer rejects every input that would cause a wasm trap (OOB indices, empty mesh, padding < 1, resolution < 1). The Rust side caps grid allocation before any Vec is allocated. No correctness defects were found in the new Rust modules or the TypeScript bridge.
No files require special attention.

src/voxel/repairFns.ts:59-67
Each wasm-bindgen getter clones the full `Vec<f32>` or `Vec<u32>` on the Rust heap, serializes it into WASM linear memory, `.slice()`s it into a JS TypedArray, then frees the WASM allocation. `repaired.positions` is called twice (line 60 and 62) and `repaired.indices` is called twice (line 64 and 66), so four extra heap round-trips per repair call. Caching each getter into a local variable before reading `.length` eliminates the redundant copies.

    using repaired = engine.value.repair_mesh(mesh.vertices, mesh.triangles, resolution, padding);
    const positions = repaired.positions;
    const normals = repaired.normals;
    const indices = repaired.indices;
    const vertexCount = positions.length / 3;
    return ok({
      vertices: positions,
      normals,
      triangles: indices,
      uvs: new Float32Array(vertexCount * 2),
      faceGroups: [{ start: 0, count: indices.length / 3, faceHash: 0 }],
    });
