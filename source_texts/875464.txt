Goal
Add a blender adapter/port so splat can hand a GaussianCloud (or any manifest) to Blender's Python backend purely as a render engine — enabling a chain like splat gaussian view-a.png view-b.png view-c.png | splat blender -o render.png (or --script/--blend output), with Blender itself invoked headlessly (blender --background --python ...).
Background
There is currently no render/visualization backend in splat at all — ports/mesh.py's MeshExporter is for mesh (OBJ/glTF/USDZ) export, unrelated to rendering a Gaussian cloud. This issue designs and implements the first render adapter, using Blender as a headless renderer, and is what the blender-mcp MCP server (already wired up for this repo, see .mcp.json / mise run blender-mcp) was set up to develop interactively against — using Blender MCP to inspect how a raw vs. normalized (#49) Gaussian cloud imports, before automating the same import as a CLI stage.
Scope
A new adapter + CLI command, not a general-purpose Blender scripting SDK. Only what's needed to import a GaussianCloud into a Blender scene and render/export it.
Tasks
Design the port contract (ports/render.py?): something like RenderBackend.render(cloud: GaussianCloud, output: Path, **params) -> RenderResult, mirroring the shape of ReconstructionBackend/MeshExporter.
Decide the import path into Blender: whether points/splats become a Blender point cloud / mesh-with-instancing / a dedicated Gaussian-splatting add-on if one is scriptable via bpy, given Blender has no native Gaussian splat renderer — likely rendering as colored point/icosphere instances driven by sh_dc + to_linear_scales()/to_activated_opacities() from gaussian: normalize reconstruction output orientation and scale #49, not a physically-accurate splat renderer.
Implement src/splat/adapters/render/blender.py: writes/serializes the GaussianCloud to a temp format Blender-side Python can consume, then shells out to blender --background --factory-startup --python <script> -- <args>.
Add splat blender CLI command (src/splat/cli/blender.py) wired the same way as splat gaussian/splat tools convert (resolve_inputs, manifest cache, report).
Add a handlers/blender.py + application pipeline stage (run_blender?) consistent with run_gaussian's cache-key/manifest pattern.
Tests: a fake/subprocess-mocked RenderBackend for the handler/CLI layer (actual Blender execution isn't unit-testable in CI) plus a real integration test gated behind a Blender-installed marker if one doesn't already exist for other optional-runtime backends.
Use the blender-mcp MCP server during implementation to interactively verify import/render output looks correct before wiring the headless CLI path — check in with the user at that point.
Notes
Depends on #49 (normalized output is what this adapter should assume/render against) — branch stacked on top of it.
This is scoped to Blender-as-render-engine. It is not a Blender add-on for interactive Gaussian splat editing, and does not attempt to reproduce 3DGS's actual differentiable rasterizer inside Blender.
