Summary
Add an optional screen-space outline for splat objects selected in the scene tree, making their visible silhouettes easier to identify in dense scenes. The option is disabled by default and uses a continuous contour.
The outline follows accumulated selected opacity, rather than an individual Gaussian's footprint. Its object ID and occlusion depth are assigned at the coverage crossing, so a selected object's faint halo cannot claim pixels inside another selected object.
How to enable and configure it
Open Rendering > Selection.
Enable Selection outline.
Select a splat object, multiple objects, or a group containing splat objects in the scene tree.
The appearance controls are shown only while the outline is enabled:
| Control | Behavior | Default |
| --- | --- | --- |
| Outline color | Dedicated color picker, independent of the Center Marker color | Blue/cyan (0.0, 0.604, 0.733) |
| Opacity | Separate alpha control, from transparent to opaque | 1.0 |
| Width | Antialiased width from 1 to 12 render pixels | 2.0 |
| Coverage threshold | Accumulated opacity required to form the silhouette, from 0.05 to 0.95 | 0.5 |
| Interior contours | Include boundaries of fully enclosed holes | Enabled |
A higher coverage threshold excludes more transparent regions; it does not change the source splats. Width is measured in render pixels, not world units. Disabling Interior contours suppresses enclosed holes, while indentations connected to the exterior remain part of the outline.
The color picker uses the existing color-picker infrastructure. The controls use the existing rendering settings, scrubbing, project serialization and viewport-defaults paths. Labels and tooltips are translated in all ten supported languages.
Settings are saved with the project. Use the existing Save as Defaults action, or Preferences > Viewport > New Project Defaults, to configure defaults for new projects. Existing projects retain their saved settings unless defaults are explicitly applied. Projects predating selection outlines load with the feature disabled; the pre-existing custom Center Marker color is retained as the initial outline color when a project has no dedicated outline color.
Python example:
```
import lichtfeld as lf

s = lf.get_render_settings()

s.selection_outline = True

s.selection_outline_color = (0.0, 0.604, 0.733)

s.selection_outline_opacity = 1.0

s.selection_outline_width = 2.0

s.selection_outline_threshold = 0.5

s.selection_outline_holes = True
```
The same settings are exposed through the existing MCP render_settings_get and render_settings_set tools, including input validation.
Selection and visibility
The mask tracks scene objects, not individual Gaussian boundaries. Group selection uses the existing selected-descendant mask.
Scene opacity and selected opacity are accumulated separately as coverage += (1 - coverage) * alpha, including across depth waves.
The selected object ID and selected depth are committed when selected coverage reaches the configured threshold. The scene occlusion depth is likewise chosen at its coverage crossing. Sub-threshold candidates do not appear in the resolved silhouette.
For overlapping selected objects, the coverage-crossing surface determines ownership. A nearer but visually negligible Gaussian does not take ownership. HiGS equal-depth ordering is stabilized with an object-ID tie break.
Unselected foreground geometry does not clip the selected silhouette. Occluded contour portions are dimmed to 35% of the configured outline opacity.
Selection changes, deselection, imports and toggles invalidate the relevant cached mask. When neither the current nor previous frame has an active object outline, selection-only changes can use the existing cached-selection path.
The outline changes display color/transmittance without changing scene geometry or depth. It is gated off during training, point-cloud mode, depth views and selections without applicable splat objects.
Rendering and cost
Both 3DGS and 3DGUT are supported, including the dedicated RAD variants and HiGS selection-mask path. The merged RAD fix #3675 is included through the upstream master merges. This branch also includes master's global MSVC /bigobj fix #3708.
With outlines disabled, the existing color shaders and their early termination remain unchanged. Both legacy 3DGS and 3DGUT retain separate mask-only dispatches; HiGS keeps its dedicated mask pass without repeating SH color evaluation. The shared color/outline 3DGUT dispatch from b03f80b has been reverted following the reviewer's RTX 4080 regression measurements. The resulting tracked source tree is identical to 0bccd6a.
A selected-tile classification skips tiles untouched by selected splats and records each tile's final selected rank in the canonical global raster order. The dedicated mask paths stop fetching batches once the first entry exceeds that rank, using a uniform workgroup exit before barriers. This preserves hidden selections while avoiding traversal of irrelevant tails whose selected coverage can never reach the threshold. The existing classification dispatch writes inverse ranks into the tail of its existing scratch buffer; this adds 4 bytes per declared projection slot while the mask path is active, with existing allocation/reuse/destruction handling.
HiGS additionally rejects macro-list entries outside the current render tile using the existing conservative projection rectangle. Wrapped equirectangular cameras retain the previous conservative macro-list path. After scene coverage crosses the threshold, unselected entries no longer need alpha evaluation. The ordinary HiGS alpha cutoff logarithm is calculated once per Gaussian batch entry rather than per pixel, adding 1 KiB of shared memory per workgroup. Color/training alpha helpers remain unchanged. No new dispatch or per-pixel rank lookup is introduced. Per-pixel mask work still stops when both coverages and ownership are settled, and HiGS groups stop fetching batches when no lanes remain active.
For the guarded, unfiltered single-node case with no unrelated raster overlays, the outline reuses rendered opacity instead of rerasterizing the selected splats. Multi-object, filtered and overlay cases retain the general coverage-mask path. 3DGUT reuses the existing LOD bindings instead of binding the index buffers twice. The dedicated mask dispatches do not write the normal color/depth outputs.
The default 1-2 pixel resolve uses the small-neighborhood path. Widths above 2 add two separable nearest-boundary passes and two reusable 32-bit buffers, totaling 8 bytes per render pixel (about 15.8 MiB at 1920x1080 or 63.3 MiB at 3840x2160). Suppressing interior contours adds GPU background-component classification and scratch storage; keeping interior contours enabled avoids that classification. These optional costs are described in the tooltips.

Review changes
The legacy 3DGS/3DGUT path and the dedicated HiGS mask use coverage = 1 - product(1 - alpha) and emit the silhouette once selected coverage reaches 50%.
Scene coverage and selected coverage are tracked independently across depth waves. Unselected splats cannot contribute to the selected silhouette, and a faint foreground footprint alone does not mark the selected contour as occluded.
Candidate object IDs remain pending until selected coverage reaches the threshold. The nearest selected object ID and stable equal-depth tie break are retained.
Regression cases cover a single 20% floater, eight overlapping 8% contributions below 50% coverage, sixteen overlapping 8% contributions above it, unselected coverage, and a detached faint halo around a solid selected model.

Thanks for the second review. Pushed the coverage/ownership and rendering-cost fixes in 10e390020, followed by the final appearance controls in 396aedc1a. The branch also includes upstream master's global MSVC /bigobj fix (#3708). The PR description has been rewritten to describe the current implementation and validation rather than retaining the earlier benchmark figures.
Responses to the blocking findings
1. Object ID and dimming depth must come from the coverage crossing
Fixed in both alphablend_shader.slang and the HiGS selection_outline_mask.slang path.
Selected coverage and scene coverage are independent accumulators and remain valid across depth waves.
The selected object ID and depth are now assigned only when selected coverage reaches the threshold, defaulting to 50%. They no longer come from the nearest individually faint selected Gaussian.
Scene occlusion depth is also captured at the scene-coverage crossing. Coverage below the threshold stays hidden from the contour resolve.
HiGS equal-depth sorting has a stable object-ID tie break.
The GPU regressions now include multiple selected objects where one object's faint halo overlaps another object's opaque interior. They check that the halo does not introduce an interior contour, on both renderers. The previous individual-floater and accumulated-opacity tests remain.
2. HiGS should skip unrelated tiles and stop settled mask work
Added selected-tile classification before the depth waves. Untouched 16x16 tiles return before walking a macro-tile list. Within selected tiles, each pixel stops once scene coverage, selected coverage and ownership are settled. Group-wide activity checks stop shared-batch loads when no lanes need further work. The mask still reuses the existing projected/binning data and does not repeat SH evaluation.
The guarded, unfiltered single-node case can derive the mask from rendered coverage instead of running the general selected-splat mask pass. This fast path is excluded when other scene nodes, relevant filters or unrelated raster overlays could invalidate that equivalence. Filtered single-node regressions exercise the general path.
3. 3DGUT should preserve color-raster early termination
Separated the normal color raster from an outline-only mask dispatch. The color shader retains its normal early termination and register path; it no longer stays alive solely because an outline is enabled. The mask-only dispatch is restricted to selected tiles and ends its per-pixel work once coverage/ownership is settled.
Responses to the additional points
Selection-only updates with nothing selected: cache eligibility now checks whether an object outline is active in either the current request or the previous rendered frame. Merely enabling the preference does not force the full path when there is no applicable outline. Keeping the previous-frame check still invalidates the mask correctly when the last outlined object is deselected.
MCP: render_settings_get/set now expose selection_outline, the dedicated outline color, opacity, width, coverage threshold and interior-contour option. GPU integration checks exercise the MCP route and invalid values as well as the Python settings route.
Duplicate LOD bindings and depth access: 3DGUT outline variants reuse the existing LOD index/logical-index bindings. Mask-only dispatches do not write the normal color/depth outputs; they use dedicated outline state. The targeted MSVC Debug renderer compilation and shader/SPIR-V checks pass. This is not a claim of a full local Windows Debug application run or Vulkan validation-layer coverage.
Additional controls in this update
Under Rendering > Selection, enabling Selection outline reveals:
A dedicated color picker using the existing picker infrastructure, independent of Center Marker color.
A separate opacity control, default 1.0.
Antialiased width from 1 to 12 render pixels, default 2.
Accumulated-opacity threshold from 0.05 to 0.95, default 0.5. This adjusts silhouette sensitivity without modifying the source splats.
Interior contours, enabled by default. Turning it off removes fully enclosed hole boundaries; cavities connected to the exterior remain outlined.
These settings use the existing rendering properties, project persistence and viewport-defaults system. All ten languages are updated. The feature remains disabled by default, with a continuous blue/cyan outline when enabled. Projects without a dedicated outline color retain their previous custom Center Marker color as the initial outline color.
The default thin resolve retains its small-neighborhood path. Widths above 2 add two separable passes and 8 bytes of reusable scratch per render pixel. Disabling interior contours adds background-component classification. The tooltips describe these optional costs.
Performance evidence and limits
On a local 2,997,954-Gaussian single-node scene at 600x908, the short RasterizeForward GPU-timer samples were approximately 4.097 ms off / 4.148 ms on for 3DGS and 11.862 ms off / 11.659 ms on for 3DGUT, at width 2. A separate width sweep measured roughly +0.046 ms for 3DGS and +0.101 ms for 3DGUT from width 2 to width 12.
These samples exercise the single-node fast path, are subject to timing noise and do not demonstrate a general speedup. I have not reproduced your 9M multi-object scan here, so I cannot claim your reported 40 ms / +58% regressions are eliminated on that workload. The tile pruning, ownership crossing and termination changes are in place for retesting it. Presentation-limited UI frame intervals are not treated as GPU performance evidence.

Coverage bound and traversal
selected_coverage + scene_transmittance < threshold would not preserve the current hidden-outline behavior: an opaque unselected foreground can leave almost no scene transmittance while the selected object behind it still reaches the selected-only coverage threshold. That silhouette must remain visible with occlusion dimming.
Instead, the existing tile prepass records the final selected rank per render tile in the canonical global raster sort, and an inverse-rank table in the same scratch buffer. Both mask paths uniformly stop before loading a batch whose first rank is beyond that bound. The check is per workgroup/batch, not per pixel, and occurs before shared-memory barriers. It also covers pixels that never cross selected coverage and subsequent depth waves with no remaining selected entries. The bound uses the actual global sort rank rather than projected depth, since the raster order is radial.
For HiGS, macro-list entries are rejected against the existing projected render-tile rectangle before expensive fetch/evaluation. Wrapped equirectangular projection keeps its previous conservative traversal. Unselected alpha work is skipped once scene coverage is settled, and the ordinary alpha cutoff logarithm is hoisted from every pixel to each shared Gaussian entry. Shared color/training helpers are unchanged.
The inverse ranks add 4 bytes of logical scratch per declared projection slot, reusing the existing buffer and its lifecycle; the cached HiGS cutoff adds 1 KiB shared memory per workgroup. There is no new dispatch, per-pixel rank lookup or new buffer lifetime to manage.
