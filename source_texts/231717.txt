Motivation
Provide a clear, modular prototype to produce a compact, importance-weighted initialization point cloud for 3D Gaussian Splatting (3DGS) under a fixed point-budget, balancing geometric complexity and multi-view texture cues.
Structure the implementation so each component has a single responsibility and clear I/O shapes to ease later refinement and integration with the 3DGS training pipeline.
Description
Add geometry_features.py with estimate_geometry_features(points_xyz: [N,3]) that computes per-point curvature, normal_consistency, boundary_score, and fused geometry_score using kNN+PCA and scipy.spatial.cKDTree.
Add texture_features.py with estimate_texture_features(points_xyz: [N,3], points_rgb: [N,3], images, cameras) that projects points into views, computes Sobel gradient maps and color variance, and returns texture_score and related maps.
Add block_partition.py with build_blocks(points_xyz: [N,3]) that voxelizes the scene and returns per-point block_ids, voxel_coords, block_counts, and num_blocks for block-aware allocation.
Add adaptive_sampler.py with sample_adaptively(points_xyzrgb: [N,6], geometry_features, texture_features, block_info, target_num_points) that computes an importance score (weighted geometry+texture), allocates per-block quotas, performs weighted sampling, and outputs selected_indices, sampled_points_xyzrgb, and importance_score.
Add gaussian_initializer.py with initialize_gaussians(sampled_points_xyzrgb: [M,6]) to convert selected points into initial Gaussian parameter tensors (xyz, rgb, opacity, scale, rotation_quat).
Add run_pipeline.py which wires the modules into run_adaptive_downsample_pipeline(inputs) and provides simple load_xyzrgb_pcd/save_xyzrgb_ply helpers and a pseudo-demo entrypoint.
Testing
Run byte-compilation on the new modules with python -m py_compile geometry_features.py texture_features.py block_partition.py adaptive_sampler.py gaussian_initializer.py run_pipeline.py, which completed successfully.
The new files were added and committed as part of the change set; no further automated unit tests were included in this PR.

Reject mismatched image and camera list lengths
The texture feature loop iterates with zip(images, grad_maps, cameras), which silently truncates to the shorter list when len(images) != len(cameras). In that case, one or more views are dropped without any error, so view_count, mean_grad, rgb_var, and texture_score are computed from incomplete data and the adaptive sampler can downsample the wrong regions. Please add an explicit length check up front and fail fast when the counts differ.
