Summary
This PR adds support for gradient-based 6-DOF registration using PyTorch optimizers (AdamW and SGD) alongside the existing scipy Powell optimizer. The implementation includes differentiable DRR rendering, PyTorch-native similarity metrics, and a new TorchRegistrationRunner class that manages optimization in a background thread with progress streaming.
Key Changes
New TorchRegistrationRunner class (registration.py):
Implements gradient-based optimization with AdamW and SGD
Supports configurable learning rates with sensible defaults per optimizer
Includes early stopping via convergence detection (metric plateau for N iterations)
Gradient clipping to stabilize training
Learning rate scheduling (ReduceLROnPlateau)
Streams progress events and final results to WebSocket queue
Differentiable DRR rendering (drr_engine.py):
Added _euler_to_rotation_diff(): differentiable Euler angle to rotation matrix conversion
Added _apply_pose_diff(): differentiable pose application preserving computation graph
Added render_differentiable(): full differentiable rendering pipeline for gradient-based optimization
PyTorch similarity metrics (metrics.py):
Implemented torch_neg_ncc(): differentiable negative normalized cross-correlation
Implemented torch_neg_gradient_corr(): differentiable gradient correlation using conv2d
Implemented torch_mean_recipr_sqdiff(): differentiable mean reciprocal squared difference
New TORCH_METRIC_REGISTRY for PyTorch-compatible metrics
Backend routing (main.py):
Updated _handle_registration_start() to route to appropriate runner based on optimizer selection
Supports both scipy and PyTorch optimizers via optimizer parameter
Frontend UI (App.jsx):
Added optimizer selection dropdown with options: Scipy Powell, PyTorch AdamW, PyTorch SGD
Passes selected optimizer to backend registration request
Implementation Details
Gradient clipping (max_norm=50.0) prevents exploding gradients during early iterations
Convergence patience of 30 iterations with tolerance of 1e-5 enables early stopping
Learning rates tuned for pose parameter scale (0.5 for AdamW, 0.05 for SGD)
Differentiable normalization in rendering uses epsilon (1e-8) to avoid division by zero
All PyTorch operations preserve the computation graph for backpropagation
