Bug Report
AirSim Version/#commit: 1.8.1
UE/Unity version: 4.27.2
Autopilot version: N/A
OS Version: Windows 11
What's the issue you encountered?
The projection matrix (proj_mat) returned by the simGetCameraInfo API does not match the expected structure of a standard perspective projection matrix.
The returned projection matrix is as follows:
```
<ProjectionMatrix> {   
  'matrix': [   
    [0.0, 1.0016834735870361, 0.0, 0.0],
    [0.0, 0.0, -1.7807706594467163, 0.0],
    [0.0, 0.0, 0.0, 10.0],
    [-1.0, 0.0, 0.0, 0.0]
  ]
}
```
This matrix does not conform to the standard pinhole camera projection matrix structure (which typically includes parameters such as focal lengths fx/fy and principal points cx/cy), making it unusable for common computer vision tasks such as 3D-to-2D coordinate transformation.

Camera Model and Projection in AirSim
AirSim uses a pinhole camera model, implemented through Unreal Engine (UE4), to render images.
Key Points
The camera model is a standard pinhole camera.
Camera intrinsics are not directly exposed by the API.
Intrinsic parameters must be computed from:
image resolution
camera horizontal field of view (FOV)
About CameraInfo.proj_mat
CameraInfo.proj_mat is not a pinhole projection matrix of the form:
P = K [R | t]
It represents Unreal Engine’s clip-space projection matrix, intended for rendering.
It includes internal engine transformations (coordinate conversions, perspective divide, near/far planes).
Because of this, intrinsic parameters cannot be extracted or decomposed from proj_mat.
Correct Workflow
Treat the AirSim camera as a pinhole camera
Compute the intrinsic matrix K analytically from FOV and image resolution
Compute extrinsics R, t from CameraInfo.pose
Construct the full projection explicitly as:
P = K [R | t]
Important Note
The camera pose is different from the vehicle/drone pose.
Camera offsets and rotations relative to the vehicle must be taken into account when computing transformations.
