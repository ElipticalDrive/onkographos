Original author: @fwilliams
Date: 2024-12-12T19:45:08Z
We should handle 16 bit precision floating point numbers in Gaussian splatting. This should lead to a big performance and memory usage impact. I think it's probably not that hard but requires a bit of a deep dive into the components of the pipeline.
There are four parts to Gaussian Splatting:
Projection (i.e. for each 3D Gaussian, compute it's 2D footprint on each image plane)
Tile intersection (i.e. compute which projected Gaussians intersect tiles in the image).
Sort the gaussians in each tile by their depth.
Volume render each tile by traversing the sorted Gaussians.
(1) and (4) (and to a degree (3)) depend on the numerics of the algorithm. We should make the forward and backward passes stable in 16 bit floating point.
