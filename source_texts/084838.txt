Overview
Naively rendering every occupied voxel as a separate cube would require one Metal draw call per voxel — unusable at 100 000+ voxels. GreedyMesher merges adjacent same-colour, same-class voxels into axis-aligned cuboids (merged voxels), reducing instance count by 5–50× and GPU bandwidth proportionally.
The algorithm sweeps Z → Y → X, greedily extending rectangles along each axis. Output is [MergedVoxel] — a flat array uploaded once per chunk to a Metal MTLBuffer.
```
PackedVoxel (16 B each, raw):   100 000 voxels  →  1.6 MB
MergedVoxel (32 B each, merged): ~3 000 cuboids  →  96 KB  (≈33× reduction)
```
MergedVoxel layout (32 bytes):
center: SIMD3<Float> (12 B)
halfSize: SIMD3<Float> (12 B)
colorAndFlags: UInt32 (4 B) — r/g/b/classId packed
_pad: UInt32 (4 B) — 32-byte alignment
Subtasks
Define MergedVoxel struct (32 bytes, GPU-ready, MTLPackedFloat3 consideration)
Implement GreedyMesher.merge(chunk: VoxelChunk) -> [MergedVoxel] — Z→Y→X sweep
Pass 1 (Z): for each XY slice, find maximal runs of same-colour occupied voxels along Z
Pass 2 (Y): extend Z-runs along Y into rectangles
Pass 3 (X): extend YZ-rectangles along X into cuboids
Mark merged voxels in a visited: BitSet to avoid double-counting
Incremental remesh: GreedyMesher.remesh(chunk:dirtyVoxels:previous:) -> [MergedVoxel] — only recompute affected region (for live capture updates)
MeshCache actor: [ChunkKey: [MergedVoxel]] — stores last mesh per chunk, invalidated on voxel insert
Metal buffer upload: MeshCache.metalBuffer(for key: ChunkKey, device: MTLDevice) -> MTLBuffer — returns cached buffer or rebuilds
Swift Testing: known 4×4×4 uniform cube → single MergedVoxel; two-colour checkerboard → 2 merged voxels (alternating cannot merge)
Benchmark: 8 000-voxel chunk (1 m³) merges in < 1 ms on M1 Pro
Dependencies
Blocked by #2 (VoxelChunk definition)
Acceptance Criteria
A solid 20³ uniform-colour chunk produces exactly 1 MergedVoxel
Two adjacent chunks of different colours produce 2 MergedVoxels (no cross-chunk merging)
MergedVoxel is exactly 32 bytes (MemoryLayout<MergedVoxel>.size == 32)
Instance count reduction ≥ 10× on a realistic room scan (measured in unit test with sample data)
Incremental remesh of a 1-voxel change completes in < 0.1 ms
All Swift Testing tests pass
Implementation Notes
Sweep order Z→Y→X chosen so the most variable axis (height, Y) is merged last — empirically produces better reduction for architecture
BitSet implementation: UInt64 array, one bit per voxel in 20³ chunk = 8 000 bits = 125 × UInt64 — fits in L1 cache
MTLBuffer with .storageModeShared: CPU writes merged voxel array, GPU reads directly — zero memcpy on M1
Color equality for merge: compare packed colorAndFlags word — exact match only (no colour tolerance)
