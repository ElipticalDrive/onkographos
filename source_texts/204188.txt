On a related note, these issues were triggered by using a different eigen solver; In the case when the inertia tensor is close to identity matrix (times a factor), the eigenvalues are of course all equal, and any vector is an eigenvector. Eigen solvers will return the same eigenvalues, but any 3 orthogonal unit vectors could act as eigen basis. OBB tree split plane depends on the direction of the largest eigenvector, so for this particular case, the split plane can be any plane. Just changing the solver gave a different tree in this case. A different tree meant different tests, actually.
So the problem I have is that maybe for this degenerate case, we should take other considerations into account, for example the symmetry of the model; maybe force in this case to use for eigen basis a basis that is parallel to the coordinate systems. This is not about the test, it is about how the obb tree is built.

Paul Wilson (@gonuke) commented on 2016-11-09
It was very intentional to do away with tolerances as they result in the ambiguities that you are facing otherwise. The key feature of the Plucker test is that when a ray is tested against a gven edge, regardless of which triangle is being tested for that edge, the mathematical operations are identical. This ensures that all tests against a given edge give a consistent result for which side of that edge the intersection falls on regardless of floating point precision. This is a specific and intentional robustness feature, and designed to avoid the need to disambiguate multiple intersections near an edge or vertex. In general, it doesn't matter which triangle is reported as long as it is consistent and unambiguous.
As you noted, there is a tolerance used to determine when the intersection is close to an edge or vertex. This is simply to later invoke a separate test to determine whether the intersection is a glancing or piercing intersection.
