Summary
Improve index compression beyond the current posting list compression (added in v0.4.0, ~41% size reduction). Currently index size looks good compared to ParadeDB, but there are remaining opportunities.
Opportunities
Dictionary compression
Front-coding for term strings: Sorted terms share prefixes ("search", "searching", "searchable"). Store prefix_len (1 byte) + suffix bytes. Expected 30-50% reduction in string pool size.
TpDictEntry bitpacking: Block 256 terms together (like Tantivy's TermInfoStore). First term stores full values, rest use bitpacked deltas. Expected ~80% reduction in dict entry overhead.
FST (optional): Compressed trie mapping terms → ordinals. Maximum compression but more complex.
Adaptive delta encoding for posting lists
Better/adaptive delta encoding schemes
Roaring bitmaps for sparse posting lists
References
Tantivy's TermInfoStore with 256-term blocks
Roaring bitmap libraries for posting list compression
