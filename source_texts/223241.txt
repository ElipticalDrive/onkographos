Summary
Without ray-query lighting, the Vulkan frame was lit by stubs. That covers:
Adreno, whose surface has no storage images (Windows ARM64: build, and run Vulkan on Adreno #59);
macOS, where r_rayTracing is never requested;
r_rayTracing 0 anywhere.
The effects: walls and the viewmodel blew out to white, and scattered speckles and long sliver triangles ran across buildings and rock faces. win-x64 reproduced it on the RX 6400 with r_rayTracing 0 (see #65). Ledger 032 asserted this path by draw counts only.
Four causes, all fixed here:
Interactions added unlit albedo. Both interaction pipelines ran material.frag. The new interaction.vert/.frag light a surface in its model space with the terms of raytracing/lighting.comp:
N·L with the stage's RXGB normal map;
(1 − d/r)² for point lights;
a directional sun along the atmosphere's sun direction;
the light's resolved colour; alpha-tested stages discard.
Unshadowed lights use the same shader without the stencil test. MegaTexture terrain, whose albedo lives in the tiles, blends dst * (direct/ambient) + dst instead.
No ambient term. A full-screen pass (sky.vert at 0.999999, depth GREATER, dst *= src) scales the opaque base by r_rayTracingAmbient before the lights. A surface ends as albedo × (ambient + direct), as lighting.comp writes it.
Wrong depth range. The light loop drew with whatever viewport the last base-pass draw left, often the viewmodel's [0, r_depthRangeWeaponHackEnd], so volumes and interactions missed the base pass's depth and leaked onto occluded surfaces. Shadows and world interactions now use [r_depthRangeStartDefault, 1], and a weapon interaction uses the weapon's range and FOV, as the base pass does.
Shadow volumes extruded from the model origin. The shadow vertex shader drew shadowCache_t's w = 0 copies at infinity from the model's origin, ignoring the light. They are now extruded away from the light, as id Tech 4's shadow.vp does, with the light origin pushed in model space. The shadow depth test is LESS, as in id Tech 4, because the caps lie on the casting surface.
The shared push-constant range grows to 160 bytes where the device allows it (Adreno, AMD and MoltenVK report 256). At the 128-byte minimum the old pipelines remain.

Follow-up notes: why skinned models (viewmodel, arms, flag, vehicles) stay unlit in the raster path
These were investigated on win-arm64 and are not part of this PR. The branch is unchanged at 79cb2c7.
What the interaction loop sees. Every skinned model in view does get the sun's interactions: the viewmodel assault_rifle_2, gdf_arm, the flag, the Titan, the Husky, the badger and others. For all of them except the badger, the interaction's drawSurf->geo is the base pass's geometry: same srfTriangles_t, same ambient cache, same joint pointer, hardwareSkinnedSurface set, model _MD5_Snapshot_. The badger's interaction geometry has 1002 verts and is hardware-skinned, while its base surface has 1919 verts and is not.
Why they come out dark. The interaction shader doesn't skin, so these are lit in bind pose and fail LEQUAL against the skinned base depth.
Tried, not enough:
A skinned_interaction.vert (skinned_material's skinning, the same joint palette uploaded to the frame's arena at set 1, and the vertWeight_t stream) runs with 0 validation errors, but still fails the depth test. The hand's mean RGB is 21 either way; with depth test ALWAYS it is 94 and visibly lit in place.
invariant gl_Position in every world vertex shader: no change.
A depth bias on skinned interactions: at -16/-2 no change; at -2000/-4 the Titan reaches 60 of the 72 it gets with ALWAYS, and the viewmodel stays at 0.
So the skinned interaction does not land on the base pass's depth, by more than rounding, even with identical inputs. Next suspects: the joints changing between the base pass and the light pass (a front-end/back-end overlap), or a viewmodel-specific transform in the base pass. These need a depth readback or a skinned-pose dump to settle.

Independent review (openETQW-mac, a read-only subagent; I checked the blocker myself)
Blocker: the normal-map decode doesn't match what the Vulkan uploader produces (interaction.frag:64-71)
The shader reads X from alpha (RXGB). Retail normal maps are ATI2/BC5; the reviewer checked pak003.pk4 generated/dds/addnormals/.../994857124b84.dds.
DecodeDDSLevelRGBA (Image_load.cpp:209-229) writes ATI2 as (X, Y, 0, 255). So:
a = 1 → X = 1;
b = 0 → the "flat" test fails;
Z = sqrt(1 − 1 − y²) = 0.
Every ATI2-bumped surface therefore gets a normal lying in the tangent plane. With #65 loading retail DDS, that is most of the world. My macOS capture looks plausible, but N·L is computed against the tangent rather than the surface.
Fix: decode X and Y from .rg, with z = sqrt(1 − dot(xy, xy)).
RXGB already decodes to (X, Y, Z, 255) with alpha moved into R, and TGA bumps are RGB, so one .rg decode covers every source. Check ATI2's X/Y order against retail's GL path.
Bind a real flat map instead of the a/b heuristic.
material.frag:30-37 has the same alpha-X assumption.
High: the ambient multiply scales the whole composited scene (VulkanBackend.cpp:10004-10041)
The light block runs after every drawSurf is submitted. Water, heat haze, translucent, additive and emissive surfaces, in-world GUIs and the weapon are already in the framebuffer, and all of them get multiplied by r_rayTracingAmbient wherever depth < 0.999999.
Additive surfaces don't write depth, so a flare against a wall drops to about 0.34×. lighting.comp skips water explicitly (:367-378).
The MegaTexture snapshot also isn't unlit albedo: it already includes fog and additive work.
Fix: run the snapshot, the ambient pass and the interactions between the opaque sort range and the first translucent, water or heat-haze surface.
Medium
Viewport leaks into localShadows (:10128). worldViewport is set once before the stencil clear. Each localInteractions draw sets its own viewport, possibly the weapon's [0, weaponHackEnd], and the shadows rasterize with whatever was set last. Set it again before the shadow loop.
Shadow volumes use a different weapon projection. DrawVulkanShadowSurface:8506-8509 subtracts modelDepthHack. The interactions (:8710-8732) and the base pass (:9499-9520) use the weapon FOV and depth scale. One shared helper would keep them consistent.
A switched-off light draws white (:8758). When no light stage resolves, it falls back to white, whereas the ray path's ResolveLightColor skips the light. Return early instead.
MegaTexture is lit as white when CopyCurrentRender fails (no swapchainTransferSource). Skip mega surfaces in that case.
Low
Model-space lighting assumes unit scale: the inverse is a transpose, the same limitation as R_GlobalPointToLocal.
Lights the shaders don't handle: spot and box lights are lit spherically, as in the ray path.
Missing sun handling: there is no default sun when atmosphereLight is NULL, and r_rayTracingShadowStrength is ignored.
Skinned meshes are lit in bind pose: the interactions bind the unskinned ambientCache. This predates the PR and probably relates to the dark viewmodel.
Cost: a full-screen copy every view, even with no MegaTexture surface.
Checks out
Push constants: the std430 offsets match, and both the 128-byte and 160-byte pipeline sets stay valid.
Shadow extrusion: w = 0 → (v − L, 0) matches shadow.vp, as does the LESS depth test.
Stencil: EQUAL 0 for shadowed lights and none for unshadowed ones.
Falloff and N·L match lighting.comp.
The ray-query path and OpenGL are unchanged, except that the interaction shaders now have to compile on ray devices too.
