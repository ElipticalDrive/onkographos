Khronos has standardized gaussian splats in glTF 2.0: KHR_gaussian_splatting (splats as point
primitives with position/rotation/scale/opacity/SH attributes) plus
KHR_gaussian_splatting_compression_spz (SPZ blobs as glTF buffers). Announced February 2026
with OGC, Niantic, Cesium and Esri behind it; release-candidate status as of the announcement,
ratification targeted Q2 2026. This is shaping up to be the neutral splat interchange across
engines (Three.js, Cesium, Unreal/Unity toolchains are adopting it).
Spec: https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_gaussian_splatting
Current state in LichtFeld
Update (2026-10-19): the SPZ-compressed variant works: .glb files with KHR_gaussian_splatting_compression_spz_2 load as splats (src/io/formats/spz.hpp), SPZ export can wrap its payload in a .glb (glb option in src/io/include/io/exporter.hpp), and dev reads such GLBs inside 3D Tiles. Uncompressed KHR_gaussian_splatting accessors are still not supported. The rest of this section describes the original state.
.gltf/.glb are handled today only as mesh formats through the assimp-based mesh loader
(src/io/loaders/mesh_loader.cpp MESH_EXTENSIONS). A glTF carrying splat extensions would load
as an empty/garbage mesh; assimp knows nothing about these extensions, so splat glTF needs its
own reader/writer path alongside — not inside — the mesh loader.
Scope
Import: detect KHR_gaussian_splatting in .gltf/.glb, load splats (both raw
attribute accessors and the SPZ-compressed variant); files without the extension keep
routing to the mesh loader.
Export: add glTF to the export fan-out (GUI dropdown + CLI + Python/MCP, same surface as
PLY/SOG/SPZ), emitting KHR_gaussian_splatting; SPZ-compressed variant once SPZ v4 import/export (zstd container + extensions, incl. coordinate system) #1529 lands.
Node transforms: glTF scenes can carry splat primitives under transformed nodes — apply
them on import; on export write the node transform rather than baking when feasible.
Extension-version tolerance: unknown/newer extension parameters degrade with a typed
error or documented fallback, never a crash.
Round-trip fixture from a third-party implementation (e.g. a Cesium/Three.js sample
asset), not only our own writer reading itself.
Dependencies / relations
SPZ v4 import/export (zstd container + extensions, incl. coordinate system) #1529 (SPZ v4): KHR_gaussian_splatting_compression_spz embeds SPZ payloads — the updated
vendored SPZ library is the natural decoder/encoder for the compressed variant. Sequence SPZ
v4 first or vendor the decoder together.
Provenance stamps (Export provenance stamps — every export should record what produced it #1507): glTF has a first-class extras/asset metadata slot — the export
stamp should ride natively here from day one.
