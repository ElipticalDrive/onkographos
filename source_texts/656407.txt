Summary
Adds an elementwise mag_sqr(U) to the Python bindings: a VolumeField<Vec3> goes in, and a scalar VolumeField of
U_x^2 + U_y^2 + U_z^2 comes out, for the internal field and the boundary values alike.
Motivation
A compressible energy equation needs the kinetic-energy term K = 0.5 * |U|^2. Until now no binding reduced a full
VolumeField<Vec3> (with its boundary data and boundary conditions) to a scalar VolumeField; only helpers on raw
Vector<Vec3> existed, which leave the boundary values out. With this, K is 0.5 * neon.mag_sqr(U).
Changes
src/bindings/volumeField.cpp: new magSqrField, following the existing sqrtField / tanhField pattern. It allocates
a scalar field on the same mesh with calculated boundaries and fills the internal and the boundary values with one
Kokkos kernel each (magSqrVec), so it runs on every executor. Exposed to Python as mag_sqr(field).
Tests
test/bindings/test_volumeField.py::test_vec3_field_mag_sqr, on every executor of the fixture, checks:
U = (1, 2, 3) gives |U|^2 = 14 in every cell, and the result is a ScalarVolumeField;
a differently valued field gives a different result (catches a kernel that returns a constant);
the operand is left unchanged.
Only the internal values are checked, as for cross, because VectorVolumeField exposes no boundary accessor to Python.
Also checked against a real case: mag_sqr(U) equals sum(U_i^2) exactly.
Verified locally on this stack (Feat/ddt scalar rho overloads #618 + this PR): the ddt C++ tests pass (38 assertions) and the Python bindings suite
gives 148 passed, 1 skipped.
Notes
Purely additive: no behaviour change for existing callers.
The boundary values are computed from the vector field's boundary data. For a boundary condition that needs a
flux or time context, evaluate the boundary conditions of the input first.
