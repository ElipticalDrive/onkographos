Summary
Replaces the per-pixel volumetric fog raymarch with a froxel (frustum voxel) grid-based approach that decouples fog cost from screen resolution. Adds support for multiple overlapping fog volumes (global height fog + bounded AABB banks) that blend by density weight in the grid. Implements a three-stage pipeline: injection (compute), scattering integration (compute), and composite (fragment).
Key Changes
Architecture
Froxel grid: 160×90×64 3D texture with exponential depth distribution (more slices near camera)
Three-stage pipeline:
froxelInjection (compute): Per-froxel, blend every fog volume's density/scattering, light the medium (sun + PSSM shadow, tile-culled point/spot/rect lights), write in-scatter + extinction
scatteringIntegration (compute): March each froxel column front-to-back, accumulate scattering + transmittance
volumetricFogFragment (fragment): Sample integrated volume at pixel's depth slice, composite: scene * transmittance + in-scatter
Volume blending: Densities add (extinction is additive); albedo/phase-g/ambient are density×blendWeight-weighted averages
Data Structures
New VolumetricFogData struct (288 bytes): camera/sun/grid/temporal/wind globals, distinct from legacy FogRenderData
New VolumetricFogVolumeGPU struct (96 bytes): per-volume bounds, density params, albedo/phase/noise, wind speed
VolumetricFogComponent now supports bounded AABB volumes (position ± halfExtent × scale) in addition to global height fog
VolumetricFogSystem gathers all enabled components into a list pushed each frame
Shader Implementation
Metal (3d_volumetric_fog.metal): Complete froxel kernels + fallback simpleFogFragment raymarch
Vulkan (FroxelInject.comp, FroxelIntegrate.comp, FroxelFogComposite.frag): GLSL twins with identical binding layout
Shared (VolumetricFog.frag): Updated raymarch to support multi-volume blending; falls back to legacy single-volume when volumeCount == 0
Renderer Integration
Metal: VolumetricFogPass executes inject → integrate → composite in one compute encoder with barriers
Vulkan: Compute passes wired through RHI (barriers, storage texture transitions)
Both backends share light-set params (cluster grid, spot/rect counts) via push constants
Froxel resources (grids, globals buffer, pipelines) allocated on both backends; Metal uses them, Vulkan keeps raymarch as fallback
RHI Enhancements
computeBarrier(): Serializes compute dispatches (Metal tracked hazard, Vulkan VkMemoryBarrier)
computeStorageTextureBarrier(): Transitions storage texture layout between compute and fragment (Vulkan only)
setComputeSampledTexture(): Handles depth texture aspect correctly (COLOR vs DEPTH for PSSM sampling)
Scene Configuration
Example scene updated: global height fog enabled + bounded fog bank entity demonstrating volume blending
Implementation Details
Froxel reconstruction uses camera's own invProj/invView for exact depth-slice alignment with composite
Wind-animated value-noise modulates density per-volume (windSpeed already folds in global wind strength)
AABB volumes soft-fade over edgeFalloff distance at each face
Lighting mirrors simpleFogFragment conventions (sun + PSSM cascade tap for shafts, tile-culled point/spot/rect lights)
Temporal jitter support via frameIndex (setup for TAA, not yet wired)
Backward compatible: empty volume list disables froxel

composite textures 0-2 + buffers 0-1). The two compute dispatches share one
serial compute pass, so Metal orders them and barriers the grid automatically.

Review of the Vulkan froxel path surfaced three issues:

- BLOCKER: FroxelInject bound the fog-volume SSBO at set 0 binding 8, but Vulkan
  compute has only 8 storage-buffer slots (0-7) — setComputeBuffer(8) silently
  no-ops and the pipeline layout lacks the binding (validation error). Vulkan's
  light params ride a push constant (not a descriptor), so binding 7 is free:
  move FogVolumeBuf to b7 and bind it there on Vulkan (Metal keeps [[buffer(8)]],
  its b7 is the light-params bytes).

- BLOCKER: the integrated volume is written by the integrate compute pass in
  GENERAL layout, then sampled by the composite — with no barrier and no layout
  transition (graphics setTexture, called inside the render pass, can't do
  either). Add RHI::prepareTextureForSampling (Vulkan: GENERAL ->
  SHADER_READ_ONLY_OPTIMAL + the write->read dependency; no-op on Metal) and call
  it between endComputePass and the composite.

- Latent: setComputeSampledTexture hardcoded the COLOR aspect while the froxel
  inject binds the Depth32Float PSSM map — derive the aspect from the format
  (a COLOR barrier on a depth image is a validation error).
