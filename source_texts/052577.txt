This makes voxel-gi-particles at rt=on about twice as fast with the same image. It keeps 2 bounces, the same particle count, the same resolution and the same materials. Every change is to the example: no gi core or simulation file is touched.
Before and after
Headless Chrome, 1600×800, rt=on, Medium, 2 bounces, 8192 particles. The profiler is on (profile=1), timestamps are unquantized, and vsync is off.
The "before" build is development plus the same timing and capture hooks. It loaded alternately with this build, page after page, because other sessions share this Mac's GPU.

What changed (each measured A/B within one page, then kept)
Depth prepass for the spheres, then shading on equal depth: −27% of the main pass.
The impostors discard, and that turns off the hidden-surface removal Apple GPUs do for opaque draws. So every sphere of the pile drawn before a nearer one still ran the full shading and ray tracing.
Now a cheap pass lays the spheres' depth (room_spheres_depth.wgsl). The shading pass (room_spheres_shade.wgsl) uses depth_compare: Equal and no depth write, so it runs only for the nearest sphere of each pixel.
The position is @invariant, as AGENTS.md asks for a second pass testing against a first.
The wall cones are traced once: −10%.
The walls' five short occlusion cones were the first metres of their five light cones.
splitConeTrace follows gi's voxelConeTrace step for step and also returns the transmittance it had on reaching aoDistance. That is exactly what the short cone returned. So the walls now trace 6 cones a pixel instead of 11.
The ray walk tests only new cells: −15%.
The walk steps a 2×2×2 block of grid cells. After a step along one axis, half of the block was tested the step before.
Now it tests only the 4 cells on the leading side.
The walk stops above the pile: −7%.
A 64-thread compute pass (pile_top.wgsl) takes the highest sorted particle centre each frame.
Rays are clipped to the slab under it plus the largest radius, so rays leaving the pile upward no longer walk empty cells up to the ceiling.
One grid-walk call site per bounce level: −10%.
The mirror and glass branches each called the tracer, so the shader inlined 6 grid walks.
Now each level loops over its 1 or 2 rays (sphereRays). The shader inlines 2 walks, which holds fewer registers.
Rows of cells read as ranges: −14%.
Cells next to each other along x are next to each other in the sorted order too. So each row of the block is one range of particles: up to 4 ranges a step instead of 8 cells.
The radius rides in the position's w: about −14% (noisier run).
Each particle's radius share is now written into its position's w, which the fluid keeps through every pass.
A sphere test is one load. The sorted index is read only for a hit, to skip the sphere the ray leaves.
Tried and dropped: drawing the walls after the spheres, so the depth test would skip the walls behind the pile, was slower (4.7 vs 4.1 ms, three alternating pairs). The walls are opaque, so the GPU's hidden-surface removal already skips them.

Where those pixels are: single pixels on sphere silhouettes. They come from the @invariant position:
@invariant rounds the clip position a little differently from development, so the silhouette's discard boundary moves by a fraction of a pixel. That flips some rim pixels between the sphere and what is behind it.
Built without @invariant, the same rt=on comparison drops to 46 pixels (0.004%). Those lie where two overlapping spheres meet at the same 24-bit depth. The old draw kept the first sphere drawn there, and the equal-depth pass keeps the last.
With the prepass also off, it drops to 3 pixels, by 1/255. So the shading and ray tracing themselves are unchanged.
@invariant stays because without it the two pipelines may round depth differently on another GPU and leave holes.
