#1 — Specification: native Vulkan migration of Massive Poly Pusher
What to build
Render a shared array/volume probe covering baseline-supported layered and 3D resource paths.
Milestone: 2. Approved planning ID: 9d.
Estimated difficulty: medium. Priority: medium. Priority is scheduling importance, not difficulty; work only when all blockers are complete.
Acceptance criteria
Load and sample identified layers/slices using the existing resource contracts and backend shader variants.
Exercise supported updates, dimensions, format interpretations, and resource replacement.
Validate device limits and unsupported shape/format combinations explicitly.
Close the assigned array/volume entries in the baseline inventory rather than inventing new resource capabilities.
Preserve the source-interface/module/resource contracts and approved exceptions in spec Specification: native Vulkan migration of Massive Poly Pusher #1; test observable behaviour rather than private Vulkan implementation structure.
Add or extend the shared comparison scenario and applicable existing CPU/GPU/application tests; run relevant delivered regressions and record results. Use the frozen MPP reference and justify visual tolerances, never silently update references to hide a defect.
For rendering work, record Vulkan and synchronization-validation results, source-interface checks, and relevant lifetime checks. Record available Windows/Linux evidence; missing platform evidence blocks milestone qualification.
Keep the supported intermediate subset explicit. Unimplemented operations must fail clearly, not behave as successful no-ops.
