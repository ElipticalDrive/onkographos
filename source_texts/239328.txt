GPU Particle Research Findings (2026-02-22)
Executive Summary
Kaiju engine already has full compute shader infrastructure — pipeline creation, dispatch, memory barriers, storage buffers. The plumbing exists but isn't wired up for particles. Current particle rendering uses one Entity + one Drawing per particle (no instancing whatsoever), which is the primary bottleneck.
Current Bottleneck Analysis
ds_room.go:spawnHitDot() creates:
1 engine.Entity per particle
1 rendering.Drawing per particle
Each with individual ShaderDataUnlit (model matrix + color + UVs)
No batching — 25,000 particles = 25,000 individual draw submissions
DrawInstanceGroup.UpdateData() (draw_instance.go:315-358):
Per-instance: UpdateModel() → frustum cull → Memcpy(DataPointer(), instanceSize)
~0.7μs/particle CPU-side → 17.5ms at 25K particles

Phased Implementation Plan
Phase 1: Batched Instancing (SIMPLEST — no compute needed)
Impact: ~10× speedup (250 FPS at 25K)
Replace per-entity particles with a single DrawInstanceGroup:
Create ONE mesh (small sphere or point sprite) shared by all particles
Create ONE material instance
Pre-allocate instance buffer for maxParticles
On spawn: write position/color to next slot in instance buffer
On frame: single vkCmdDrawIndexed with instanceCount = activeParticles
This eliminates per-entity overhead and the per-instance UpdateModel + frustum cull loop.
Files to change: ds_room.go only (no engine changes)
Phase 2: Compute Shader Updates (FULL GPU)
Impact: ~50× from Phase 1 baseline → 60+ FPS at 250K
Move particle position updates to GPU:
Write particle_update.comp compute shader (position += velocity * dt, lifetime check)
Create particle_compute.shaderpipeline
Compile to SPIR-V (glslc required)
Use ComputeShaderBuffer for particle state (position, velocity, lifetime, color)
Dispatch compute each frame, barrier, then instanced draw from same buffer
CPU only sends spawn commands (ring buffer of new particle positions)
Files to change: ds_room.go, new particle_compute.go, new shader files in content/
Phase 3: Point Sprites (Optional)
Replace sphere mesh (24+ triangles) with point sprite (1 vertex):
Custom vertex shader: gl_PointSize = size / distance
Fragment shader: radial falloff for soft dot appearance
Reduces GPU vertex processing 24×
Recommended Order
Phase 1 first — simplest, biggest bang for buck, no engine modification
If still not hitting 60 FPS at 250K, add Phase 2
Phase 3 only if GPU-bound (unlikely with Phase 2)
Prerequisites
glslc or glslangValidator available for SPIR-V compilation (Phase 2 only)
James available for visual regression testing
