Implements both halves of #79 for the in-RAM tier, plus the decision doc that settles the architecture (plans/points-octree-lod.md, synthesized from five prior-art surveys: Potree ecosystem, formats/Python tooling, LOD techniques, encoding/compression, GPU efficiency).
1. Per-point time-window visibility
add_points(birth_times=, removal_times=) — optional (N,) lifetimes; the vertex shader shows a point only while birth_time <= t < removal_time, culling by pushing gl_Position outside the clip volume (pre-raster, zero fragment cost — Potree's GPS-time-filter trick via onBeforeCompile + customProgramCacheKey). Expresses the out-of-order appearance/removal that draw_range's buffer-prefix reveal cannot. NaN/±inf ends = unbounded (mapped to ±FLT_MAX Python-side; GLSL NaN compares are undefined).
Scrub time drivers: set_points_time(id, t) (streaming) and the new point_times animation channel (Animation.set_point_time_data, Frame(point_times=...)) — dragging the animation slider scrubs points in/out.

2. Streamed octree LOD
add_points(lod=True | {node_capacity, point_budget, refine_pixels, max_depth, seed}):
Build (Python, points_lod.py): Potree-style additive sampled octree — every node owns a seeded pseudo-random sample of its cube, time-stratified over birth/removal so the time filter thins every LOD level uniformly (sampled real points, never aggregated rollups: any merged voxel would fabricate a lifetime belonging to no real point). Per-node vertex order Morton-sorted + 128-batch shuffled (Schütz 2021, up to ~4× raster throughput).
Transport: one WS header + a 40 B/node binary hierarchy (bounds, count, [min birth, max removal), BFS topology). Node payloads are lazy callable blob-store providers — each GET /points_lod_<uuid>/<i> quantizes + packs a numpy slice on demand; nothing materialized up front. Payload: normalized int16 xyz over the node cube (free GPU dequant via normalized attribute + node transform; ints stay GPU-resident, unlike Potree's CPU float decode) + u8 rgb + f32 times.
Viewer runtime: per-frame priority traversal (max-heap on projected node size) — refine while ≥ refine_pixels, hard stop at point_budget (default 1.5M), ≤6 concurrent node fetches, LRU eviction past ~3× budget, per-node frustum culling, and per-node time culling (a node whose window misses the scrub time is neither drawn nor fetched). The group shares one scrub-time uniform, so set_points_time/point_times drive LOD clouds identically to flat ones. draw_range is a documented no-op on LOD clouds (buffer order is per-node Morton).

The builder re-sorted every interior node's candidates by time
(lexsort) — the root alone re-sorted all N points. Boolean-mask
partitioning preserves relative order, so sort once globally (time +
random tiebreak, or a plain random permutation without strat times) and
every node's candidate list inherits it; the stratified sample becomes a
pure strided pick. 10M points: ~19.7s -> ~8.3s build, 2M: 2.9s -> 1.2s.
Stratification quality unchanged (root-sample time quantiles still match
the full cloud).

* Grid Morton fast-path for points LOD + EDL auto-enable/tuning

Two additions serving the mill-sim voxel-carve demo (drafted in another
session; reviewed, benchmarked, docs + tests completed here):

Grid fast-path (points_lod.build_points_octree_grid, lod={"grid": ...}):
for lattice-aligned clouds, build the same additive sampled octree from
one global uint64 Morton code + one sort — every octree cell at every
level is a contiguous range of the sorted array, octants split by
searchsorted, no per-node re-partition or sort. Benchmarked 4x faster
than the float builder at 8.1M lattice points (1.1s vs 4.4s), identical
node structure. Sampling is spatial (strided over Morton order);
strat_times is accepted but ignored — carve removal times are spatially
correlated, and skipping the time sort keeps the build bit-reproducible
for external producers. Producers (mill-sim's Rust kernel) can pre-supply
codes/order/n_bits and skip the two super-linear stages; the bit-exact
contract is docs/points-lod-grid-api.md with grid_morton_codes() as the
Python reference. Gated on the caller's grid promise: the bit-slice
octant test only matches the float pos>centre test for cell-centred
points. Also per-cloud lod={"size_boost_max": k} (wire: sizeBoostMax).

EDL: auto-enables the first time a point cloud is added (unlit point
quads read as a washed-out sheet without a depth cue), suppressed once
the user pins the state (Shift+D, set_depth_cue(edl=...), or the new
set_edl(enabled, strength=, radius=)) — including an explicit OFF.
set_depth_cue grows edl_strength/edl_radius; tuning survives composer
rebuilds and can be set before the composer exists.

Review pass: fixed class name in the producer doc, documented both
features in CLAUDE.md, added a browser test (auto-enable fires, pinned
OFF survives a second cloud, tuning reaches the shader uniforms), and
clarified the size-unit semantics in the add_points docstring.
