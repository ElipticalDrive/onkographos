Overview
This issue tracks the implementation of Light Propagation Volumes (LPV) - the major remaining feature from #143 (Modern Lighting System Overhaul).
LPV enables cheap real-time global illumination by simulating light bounces in a voxel grid, allowing colored light from torches, lava, and glowstone to scatter and illuminate nearby surfaces.
Technical Details
How LPV Works
Light Injection - Direct light from emissive blocks is injected into a 3D grid
Propagation - Light spreads to neighboring cells using spherical harmonics (4-6 iterations)
Sampling - Final pass samples the grid for indirect lighting contributions
Architecture
Data Structures:
3D RGBA16F texture grid (64³ = ~16MB, or 32³ = ~2MB for testing)
Spherical harmonics coefficients (4 floats per channel)
Grid parameters (cell size, world bounds, cascade info)
New Components:
src/engine/graphics/lpv_system.zig - Core LPV management
assets/shaders/vulkan/lpv_inject.comp - Light injection compute
assets/shaders/vulkan/lpv_propagate.comp - Propagation compute
Integration in terrain.frag for indirect sampling
Implementation Tasks
Phase 1: Core System (4-6 hours)
Create LPV system module with 3D texture management
Define grid parameters and world-space mapping
Add LPV resources to frame graph
Implement compute pipeline setup
Phase 2: Shaders (4-5 hours)
Write light injection compute shader
Read block light sources from scene
Convert RGB to spherical harmonics
Write to 3D grid texture
Write propagation compute shader
4-6 iteration propagation passes
Neighbor sampling with attenuation
Spherical harmonics accumulation
Phase 3: Integration (2-3 hours)
Add LPV texture sampler to terrain.frag
Sample grid based on world position
Blend indirect light with existing lighting
Add settings toggles and intensity controls

Acceptance Criteria
Torches cast orange light that bounces onto nearby surfaces
Lava creates red-orange ambient glow in caves
Glowstone provides warm yellow ambient lighting
Light propagates realistically (dimmer with distance)
No visible performance impact on target hardware
Settings to enable/disable LPV and adjust intensity

Comment
This is a well-structured Feature Request for implementing Light Propagation Volumes. A few observations:
Missing Information Needed:
What is the current lighting system's architecture (which files handle direct lighting, shadowing, etc.)?
Does the terrain shader already have infrastructure for indirect lighting sampling?
What compute shader version (GLSL 4.50+ / Vulkan 1.0+) should targets assume?
Scope Concern:
This issue is too broad and should be split into 3-4 separate issues:
Suggested Breakdown:
Phase 1: LPV Core Infrastructure - Create lpv_system.zig, 3D texture management, frame graph integration
Phase 2a: Light Injection Shader - lpv_inject.comp compute shader only
Phase 2b: Propagation Shader - lpv_propagate.comp compute shader only
Phase 3: Integration & UI - Terrain shader sampling, settings toggles, intensity controls
Each sub-issue should reference this parent issue for context. This allows parallel work on shaders while core infrastructure is being built.
Architecture Question:
Should LPV be integrated with the existing shadow mapping system, or operate as a separate pass? Understanding this relationship is critical for Phase 3 integration.
