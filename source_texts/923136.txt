BRDF LUT: demoAssetUrl("./brdf-lut.png", import.meta.url) follows the module-relative pattern the other demos already use (tetris, calculator, bath-day...). copyDemoRuntimeAssets copies brdf-lut.png into the demos output for single-demo builds too, so the /lite-demos/ and nested base paths resolve.
Direct light: setLightIntensity is a root export, and it bumps the light version so the shared light UBO is refreshed. The old direct sun.intensity write left the UBO stale.
Thumbnail: thumbnailUrl is optional and HTML-escaped in both renderCard and the lab Demos tab, and the relative-JPG fallback is unchanged. It is pinned to an immutable Assets commit.
Single-demo build: it now refreshes index.html through the extracted writeDemoIndex. demos and manifest are both in scope there.
Tests: the build test covers the root 404 vs module-local 200, the BRDF bytes and MIME, and the gallery card. The lab card is rendered in a VM against the real escapeAttr/initDemosGrid.
Non-blocking: the Copilot reviewer's note is correct. The /pages dev preview (lab/vite.config.ts:74, renderPagesDemoCard) still hardcodes /thumbnails/demo-${slug}.jpg, so the AO card there won't show the hosted image. This only affects the dev preview and nothing regresses, but a one-line demo.thumbnailUrl ?? ... there would keep all three renderers in sync.
