Summary
Two related changes for memory-friendly chunked processing of huge meshes:
Lossless chunk simplification (src/mesh_n_bone/meshify/lossless_simplify.py)
A two-pass per-chunk pass that produces a mesh visually identical to its input while reducing face count by 77–98% on typical cellmap surfaces, AND guarantees that two adjacent blocks compute identical vertex sets on their shared chunk-boundary plane without cross-block communication.
Pass A — interior coplanar collapse: removes any vertex whose 1-ring of incident faces is coplanar (within angular tolerance) and retriangulates the resulting polygon. Handles flat-region interior + collinear vertices on a flat patch's perimeter.
Pass B — symmetric boundary-polyline simplification: for each chunk-boundary plane, extract the 2D polyline of mesh vertices on that plane and run Douglas-Peucker with fixed tolerance and lexicographic tie-breaking. Two neighboring blocks see the same polyline (the segmentation crossing the plane is identical on both sides) and run the deterministic same DP → identical reduced vertex sets without any communication.
Wired into fixed_edge.simplify_mesh via two new kwargs (lossless_first, lossless_dp_eps) and exposed from Meshify(...) + worker config so a run-config YAML can enable it with lossless_chunk_simplify: true.

```
This commit addresses two related quality/size issues for huge-mesh
chunked processing:

(1) Add lossless_chunk_simplify in a new util module:
    src/mesh_n_bone/meshify/lossless_simplify.py

    Two-pass algorithm that produces a mesh visually identical to its
    input while dramatically reducing triangle count, AND guarantees
    that two neighboring blocks produce identical vertex sets on their
    shared chunk-boundary plane (so the assembled mesh has no seams
    or T-junctions, without any cross-block communication).

    Pass A — interior coplanar collapse: vertex-by-vertex, remove
    any vertex whose entire 1-ring of incident faces is coplanar
    (within angular tolerance) and re-triangulate the hole.

    Pass B — symmetric boundary-polyline simplification: for each
    chunk-boundary plane, extract the 2D polyline of vertices on the
    plane, run Douglas-Peucker with a fixed tolerance and lexicographic
    tie-breaking. Both adjacent blocks see the same polyline and run
    the deterministic same DP → identical decimated boundary verts.
    Each block locally retriangulates the strip of faces touching
    removed vertices.

      * lossless_first: bool (default False)
      * lossless_dp_eps: float | None (default = half-voxel)

      * lossless_chunk_simplify: bool
      * lossless_chunk_simplify_dp_eps: float | None
    and plumbed through the worker config so a run-config YAML can
    enable it.

    MC → clip → lossless_chunk_simplify → assemble):
      * 80–98% face reduction on flat regions
      * 43% reduction on curved (sphere) — correctly preserves detail
```

Extend Pass A to collapse collinear feature-edge vertices
…
342c7a7
```
Original Pass A only removed vertices whose entire 1-ring of incident
faces was coplanar. Vertices on feature edges (where two coplanar
patches with different normals meet, e.g. the edge of a cube) have
a 2-normal 1-ring and were left intact — keeping marching-cubes-
density along every feature edge of the simplified mesh.

Extension: also remove a vertex V when its 1-ring partitions into
exactly two coplanar groups AND V's two feature-edge neighbors are
collinear with V (within tolerance). The 1-ring polygon is split at
the two transition vertices into two planar arcs (one per group),
each retriangulated independently in 2D. The two new triangulations
share the straight feature edge that replaces V's two incident
feature edges.

Impact on the four end-to-end shape tests:

  Box   : 1388 → 44 faces  (87.1% → 99.6% reduction)
  Sphere: 4608 → 2124 faces (44.9% → 74.6% reduction)
  Mixed : 2200 → 390 faces (80.9% → 96.6% reduction)
  Slab  : 2284 → 44 faces  (90.1% → 99.8% reduction)

All four still bit-exact (max distance MC → simplified = 0.0 in
both directions). All 325 tests still pass.

Add regression test test_mc_cube_collapses_to_near_minimum locking in
the cube-to-near-minimum behavior (asserts <100 faces on the MC box,
where pre-extension behavior produced 1388).
```

Gate feature-edge collapse on minimum dihedral angle
…
2885e5d
```
NG reads vertex normals straight from the Draco fragment (octahedron-
encoded snorm8) rather than recomputing at render time, so the
per-vertex averaged normals baked into the mesh are exactly what gets
shaded. The feature-edge extension was firing on the gentle voxel-step
"feature edges" between adjacent MC patches on curved surfaces,
collapsing vertices that contribute to smooth-looking shading and
leaving the lossless sphere visibly lumpier than the raw mesh.

Add a minimum dihedral-angle gate (default 45 degrees). Cube/slab
edges at 90 degrees still collapse aggressively; shallow voxel-step
features on a sphere (typically < 25 degrees) are preserved.
```
Make feature-edge collapse opt-in (default: pure-lossless Pass A)
…
2d1cdaf
```
Investigation: Neuroglancer computes per-vertex normals by *unweighted*
averaging of incident face normals. Under any face-count simplification
of a curved surface, that average shifts at surviving vertices — the
triangle counts in each adjacent plane change, even though the geometry
is bit-exact. NG-identical shading is therefore not achievable by any
algorithmic improvement; it would require area-weighted averaging in
the renderer, or NG honoring normals from the Draco fragment (it
ignores them).

Given that, the right default is the most conservative: pure-coplanar
collapse only (every removed vertex has a single-normal 1-ring), which
is bit-exact lossless and inverts no positions. The feature-edge
extension that collapsed cube/slab edges to their corners aggressively
modified normal averaging on shallow curvature steps and is the source
of the lumpy sphere; gate it behind ``collapse_feature_edges=True``
for CAD-like data where it's appropriate.

Reductions under pure Pass A:
  box     87.1%   (cube edges kept MC-dense, stage 2 reduces further)
  slab    90.1%   (same)
  sphere  46.6%   (interior verts of axis-aligned patches collapse;
                   curvature-step verts kept — bit-exact MC sub-set)
  mixed   83.7%   (flat regions collapse; divot curvature kept)
```
Compose lossless with target_reduction relative to raw MC
…
71e9f02
```
target_reduction is the user-facing knob meaning "fraction of raw MC
faces to remove across the whole pipeline." The two staged decimations
(stage_1_reduction_fraction / stage_2_reduction_fraction) already
compose multiplicatively to honor that total. But lossless was being
treated as free reduction on top, so lossless_first=True silently
made the pipeline over-decimate by the factor lossless had already
collapsed (e.g. ~10x on a cube box).

Fix: capture the raw face count before lossless runs and compute
target_faces from that. When lossless already brings the chunk at or
below target_faces, skip decimation rather than over-reduce. Now
lossless+decimation and decimation-alone land at the same absolute
face count for the same target_reduction.
```
