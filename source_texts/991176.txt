Parent
M1a: Walk the Planet, part of the Vertical-slice spec. Decided in Decide which inspiration techniques to adopt; the dev approved creating this ticket on 2026-11-07.
What to build
A traversal-cost heatmap debug view, next to the existing Depth / Normals views: per pixel, count the work the tracer did for the primary ray (bricks or AABB candidates entered, and DDA steps taken inside them) and show it as a heat ramp with a legend.
Tuxedo Labs found this view essential for tuning voxel ray tracing, because GPU tools can't see inside a custom intersection: their heatmap showed whole areas of wasted work on occluded geometry, which traced back to a bad TLAS (GPC 2025; see docs/research/inspiration-teardown-rt.md on branch research/inspiration-teardown-rt). They used a shader clock; wgpu has none, so this counts steps instead, which works on both tracers.
Counters live behind trace() so the compute DDA has them now and Hardware RT trace() gets them for free when it lands.
Zero cost when the view is off (a specialisation constant or a separate pipeline, not a runtime branch in the hot loop if that measurably costs).
Optional: show the frame's mean and p99 step count in the overlay.
Acceptance criteria
A debug view toggle shows the heatmap with a legend; it works on the compute DDA today.
Counts are exact on a hand-built test scene (a unit test or golden checks a known step count through a known brick layout).
With the view off, the bench's primary-visibility time is unchanged within noise.
Rendering ticket: the PR gets needs-benchmark (see docs/agents/benchmarking.md).
