Abstract
This project implements iterative Principal Component Analysis on the MNIST dataset.
We focused only on digit zero to helpe reduce the workload. We implemented two learning
methods, the first was one-step learning using Oja’s rule, the second was two-step learning
with explicit normalization. The online version of the algorithm gave us NaN errors, which
we switched to a batch update version. That fixed the numerical instability.
The dot product between the two methods was 1.000000, which means they converged
to identical principal components. The reconstruction error went down, with one PC it was
3416.86, and with two PCs it dropped to 2896.58. That is a reduction of 15.23%. The second
PC was orthogonal to the first, with dot product was 0.000000.

Introduction
MNIST stands for Modified National Institute of Standards and Technology. MNIST is a
database of handwritten digits used for training and testing many image processing systems
and machine learning research [6]. It has 60,000 training images and 10,000 testing images
of handwritten digits [6]. Later in 2017, an extended database has been published that has
240,000 training images and 40,000 testing images. Since MNIST is a standard training
dataset for digits in English, in recent times, others have also provided similar databases
for training digit datasets in other languages. The dataset is considered as a benchmark
for neural networks worldwide. The MNIST database is good for people who want to try
machine learning techniques and neural network methods on real-world data while spending
minimal efforts on preprocessing and formatting [6]. It reduces the time and effort spent
on preprocessing and formatting of data. The MNIST dataset was used, then neural layers
with fully connected (dense) architectures implemented.
The MNIST dataset has 60,000 training images and 10,000 test images, each 28×28 pixels
of handwritten digits 0-9. It is the standard benchmark for handwritten digit recognition.
The principal component analysis, is a multivariate technique that analyzes a data table in
which observations are described by several inter-correlated quantitative dependent variables
[2]. PCA extracts the important information from the statistical data to represent it as a
set of new orthogonal variables called principal components, and to display the pattern of
similarity between the observations and of the variables as points in spot maps [2].
In this project, we implemented iterative Principal Component Analysis (PCA) on the
MNIST dataset. . To reduce workload, we kept only images of digit zero. We used two
approaches for learning the principal components. The first approach is one-step learning
using Oja’s rule [7]. The second approach is two-step learning with explicit normalization.
We reconstructed the original data and computed the error in the first principal component. In the second principal component, we removed the first PC from the data. We
reconstructed using the first two PCs, and computed the reconstruction error again.
1.1
Project Requirements
The project is to implement iterative principal component analysis (PCA) on the MNIST
dataset. To reduce the workload, we may choose to work with images containing a single
specific digit. The project had two main tasks:
1. We found the first principal component (PC), reconstructed the original data, and
computed the reconstruction error:

2. We found the second PC, reconstructed the original data using the first two PCs, and
computed the reconstruction error:
• Using one-step learning on the original data
• Using two-step learning on the data with the first PC component being pre-removed

The project specification allowed us to work with a single digit to reduce the workload. We

Algorithm Description
2.1
Data Preprocessing
We loaded the MNIST data. We selected only images labeled zero. The data came as 28x28
pixel images. We reshaped each image into a vector of length 784. Then we centered the
data, it is necessary, for PCA. it makes sure the principal components capture variance
around the mean, not the mean itself. We subtracted the mean of each pixel across all
training images.
We first tried online updates, but we got NaN errors. So we switched to batch updates.
That fixed the numerical instability completely.
2.2

2.4
Finding the Second Principal Component
We removed the first PC from the data to find the second one. We used a method called
deflation. Here is the formula:
xremoved = x − (xT w1 )w1
(5)
After we removed the first component, the data has no variance left along the first PC
direction. Then we applied the same iterative algorithm to the modified data. That gave us
the second PC. In our results, it was orthogonal to the first. The dot product between the
two PCs was 0.000000.
2.5
Reconstruction and Error Computation
After we found the principal components, we reconstructed the data using:
x̂ = mean + Xcentered wwT
(6)
For two PCs, we summed the contributions:
x̂ = mean + Xcentered (w1 w1T + w2 w2T )
(7)
We computed the reconstruction error as the mean squared error between the original
images and the reconstructed images.

Discussion
4.1
Challenges Encountered
Several challenges came up during this project. The online version of the iterative PCA
algorithm gave us NaN errors. This happened no matter what learning rate or data normalization we tried. The numerical instability showed up in both the one-step and two-step
methods. We eventually dropped the online approach and used batch updates instead. That
fixed the NaN problem completely. The batch version gave us stable convergence with weight
changes around 10−16 .
The principal component images looked completely black at first when we reshaped them
to 28x28. The raw PC values were extremely small, so they were invisible when we displayed
them directly. We added normalization to scale the PC values to the range [0,1] before
visualization. That made the patterns visible.
4.2
Why Two Principal Components Improve Reconstruction
One PC captures the main direction of variance in the data. For digit zero, this is essentially
the average shape. However, handwritten zeros vary in loop size, thickness, slant, and other
8
properties. The second PC captures the next most important direction of variation. Adding
this second dimension reduced the reconstruction error by 15.23%.
4.3
Convergence Behavior
Both methods converged rapidly. The weight changes after 500 iterations were already at
10−16 , which is essentially zero. This indicates that the batch update algorithm is very stable
and efficient for this dataset. The dot product of 1.000000 between the two methods confirms
they found the same solution.
4.4
Proposed Improvements
With more time, we could make several improvements. First, we would try to figure out
why the online version failed. There might be a bug in our code. Or maybe we missed a
parameter that needed tuning. Second, we would find more than two PCs, maybe 10 or 20,
to see how much the reconstruction error keeps dropping. Third, we would test different
learning rates. Fourth, we would run the same experiment on other digits to compare their
principal components.
5
Conclusion
We implemented iterative PCA on MNIST digit zero using one-step learning (Oja’s rule) and
two-step learning with explicit normalization. Both methods produced identical principal
components with a dot product of 1.000000.
The main findings are as follows. The first principal component resembles an average
digit zero. The second principal component is orthogonal to the first with a dot product of
0.000000. Using two PCs reduced the reconstruction error by 15.23% compared to using one
PC, from 3416.86 to 2896.58. Both methods converged rapidly with weight changes on the
order of 10−16 .
All project requirements were met. We found the first PC using both methods and
computed reconstruction errors. We found the second PC by removing the first PC and
applying the same algorithms. We reconstructed using two PCs and computed the improved
reconstruction error.
