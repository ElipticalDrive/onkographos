Ray-Marching A Density Field Without a For Loop
Question
I've been working on a volumetrics plugin for Unity for quite some time now, and I've been looking for ways to optimize the rendering of large, high-resolution density fields that need not be sparse. In this case, the largest performance bottleneck is definitely sampling the Texture3D in the ray-marching loop. All the other tight loop calculations pale in comparison to this repeated sampling.
I started wondering if there's a way to speed things up by doing this work in parallel, instead of in a per-pixel loop. Consider the case of volume transmittance. You could do something like:
Dispatch a compute shader that computes the density of the volume at each pixel and each sample along the ray. If you're rendering at 1080p and using 8 raymarching samples, the resulting framebuffer would be something like a Texture 2D array of size 1080x1920x8.
Then, loop over these cached density samples to perform the actual transmittance integration.
The question I have is, more or less, would a scheme like this actually buy you any performance? As far as I see it it's contingent on the GPU actually being able to leverage the first step being done in parallel, and then on the second step having very good cache coherency, which I'm not sure it would.
Then there's the separate issue of the memory that a 1080x1920x8 intermediate framebuffer takes up. Imagine increasing the sample count to something like 64.
What are your guys' thoughts on this idea, and on parallelizing volume integration in general?
