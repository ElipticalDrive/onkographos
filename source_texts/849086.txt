Audit finding
The current VTU writer labels generated cells as VTK_TETRA but emits only three point IDs:
{ref_vertex, fv_a, fv_b}
A VTK tetrahedron requires four point IDs. Therefore the current export is not a valid tetrahedral decomposition and can produce malformed/incorrect ParaView data.
Required implementation
Prefer native VTK polyhedron export (cell type 42) when arbitrary CFDX polyhedra are present, using the VTK face-stream representation:
nFaces, nFace0Pts, pointIds..., nFace1Pts, pointIds...
and the corresponding faces / faceoffsets arrays required by the XML UnstructuredGrid format.
Alternative: implement a mathematically valid tetrahedralization with generated cell-center points and explicit point-field treatment.
Validation
unit cube exported as a valid volumetric cell;
prism, pyramid and arbitrary polyhedron;
ParaView/PyVista re-import;
cell count and cell types checked;
cell-field values preserved;
point fields preserved;
no degenerate cells;
XML connectivity/offsets validated.
Do not weaken tests or silently accept malformed tetrahedra.
