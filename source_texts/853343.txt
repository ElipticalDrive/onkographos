Task
Migrate the 34 branch-free scalar float conversion rows into typed
post-register-allocation machine records consumed by both assembly and object
serializers:
f64 -> f32 and f32 -> f64 (2 rows);
i8/u8/i16/u16/i32/u32/i64/char -> f32/f64 (16 rows);
f32/f64 -> i8/u8/i16/u16/i32/u32/i64/char (16 rows).
The four bidirectional u64/float rows are deliberately separate in #7353 and
#7354 because they need high-half control flow. The same-precision identities
f32 -> f32 and f64 -> f64 need only #7301 move/no-op dispositions and are
accounted for by the final matrix gate #7355, not by conversion opcodes here.
Findings on current main (ec884aac, 2026-09-02)
The production selectors still emit exactly six register-form SSE2
instructions after the real register/scratch plan:
cvtsd2ss, cvtss2sd, cvtsi2ssq, cvtsi2sdq, cvttss2siq, and
cvttsd2siq. compiler-backend-object-instr-semantically-supported? still
rejects every CompilerIrInstr.Cast; there is no partial direct-object path
to preserve or enable early.
compiler-backend-emit-float-to-float-cast,
compiler-backend-emit-int-to-float-cast, and
compiler-backend-emit-float-to-int-cast select final GP/XMM homes and
surround the conversion with typed loads/stores. Register and immediate
sources and spilled destinations are deliberately normalized through
planned registers. Do not fuse a memory form during migration.
The opcode records need only three checked semantic shapes:
precision-to-precision XMM/XMM, normalized signed-qword GP to f32/f64 XMM,
and f32/f64 XMM to signed-qword GP. Original integer signedness/width belongs
to the adjacent backend: migrate scalar physical moves, float rodata, and RIP-relative fixups #7301 typed extension/store record; serializers must never
recover it from high-level IR. char follows the u8 zero-extension path.
Unsigned sources through u32 fit in signed i64 after source-typed
zero-extension, so cvtsi2s{s,d}q is correct. Float-to-integer always uses a
qword truncating conversion, then the backend: migrate scalar physical moves, float rodata, and RIP-relative fixups #7301 destination-width store keeps the
low bits. The x86 indefinite result for NaN/infinity/out-of-range is permitted
by SPEC section 3.8, but remains defined/no-trap and must match across both
serializers without host-language conversion or UB.
compiler-reg-scratch-cast-xmm-needed? and
compiler-reg-scratch-cast-gp-count remain the authoritative scratch-count
interface. Their FloatCastValueXmm, FloatCastValueGp, and
FloatCastScratchGp assignments are already carried to
compiler-backend-emit-cast; the shared builder consumes those exact homes
and never scavenges.
The checked x86 encoding table is compact and target-neutral at selection:
precision casts use F2/F3 0F 5A /r; integer-to-float uses
F3/F2 REX.W 0F 2A /r; float-to-integer uses
F3/F2 REX.W 0F 2C /r. Mandatory prefix precedes REX. Low/high-register
probes produced, for example, f2 0f 5a c8, f2 45 0f 5a cc,
f3 48 0f 2a c0, f3 4d 0f 2a cc, f2 48 0f 2c f4, and
f2 4d 0f 2c fc; encode ModRM direction explicitly because the GP/XMM roles
reverse between opcode 2A and 2C.
Current backend unit tests cover representative direct and forced-spill i64
conversions plus both precision casts and assert planned homes. Source
coverage is not a 34-row semantic/differential matrix: f32_scalar.tl
covers one exact precision round trip, u64_float_casts.tl includes a u8
representative, and overflow_casts.tl is integer-only. The public CLI
compatibility gate currently permits old stage0 rejection of float casts;
that is frontend/bootstrap compatibility evidence, not object parity.
backend: migrate scalar SSE2 expressions to shared machine records #7205 shares the same legacy-SSE mandatory-prefix/REX/ModRM descriptor. The
first landing issue must expose and reuse one checked table rather than
creating conversion-private and arithmetic-private encoders.
Focused open issue and PR searches found no duplicate or claiming PR. No
priority label exists to propagate.
Landing shape
Extend backend: establish the typed machine-program core and migrate one scalar leaf #7055/backend: migrate scalar physical moves, float rodata, and RIP-relative fixups #7301's machine model with the three checked conversion record
shapes above. Constructors validate register classes, qword GP width,
distinct source/destination precision where required, and opcode/type
compatibility before serialization.
Replace the six string helpers at the production selection sites with one
record stream. Preserve instruction order, physical homes, no-op handling,
and every adjacent backend: migrate full-width scalar integer materialization to shared machine records #7202/backend: migrate scalar physical moves, float rodata, and RIP-relative fixups #7301 load/store record exactly.
Serialize that stream back to byte-identical AT&T assembly and through the
shared x86 encoder into ELF/COFF code bytes. Neither serializer chooses
precision, signedness, scratch registers, load/store width, or a memory
fusion.
Add the full 34-row source matrix plus forced source/destination spill
combinations. Compare assembly and direct-object execution at opt 0/1/2 on
Linux and Windows, including exact payload/bit oracles where equality is
insufficient.
Delete any overlapping independent object lowering and relax eligibility
only for complete programs whose needed move/immediate/conversion records
are all supported. Keep u64 rows and incomplete families fail-closed for
backend: migrate u64-to-float high-half cast records #7353/backend: migrate float-to-u64 high-half cast records #7354/backend: retire Cast object fallback after full scalar matrix parity #7355.

Acceptance criteria
Shared records cover exactly the 34 named conversion rows. u64 endpoints,
same-precision identities, bool, and nonnumeric types are rejected or
delegated to their named owner before serialization.
f64 -> f32 rounds to binary32 under the runtime's normal nearest rounding
mode; f32 -> f64 widens exactly. Tests cover both zero signs, finite
boundaries, subnormals, infinities, and representative quiet/signaling NaN
payload classes without promising impossible payload preservation across a
precision change.
Integer/char to float uses source-typed sign/zero extension followed by the
qword conversion. Tests cover every source width, signed boundaries,
unsigned maxima through u32, i64 precision boundaries, and halfway/tie
neighbors for both float precisions.
Float to integer/char truncates toward zero and then applies the target
width. Tests cover fractional signs, both zero signs, exact boundaries,
just-in/out-of-range values, infinities, and NaNs. Out-of-range assertions
prove deterministic no-trap serializer parity without strengthening SPEC
section 3.8's portable value contract.
Direct-register and every forced source/destination spill combination consume
production-planned scratch homes. Conversion records stay register-form and
the stream contains explicit backend: migrate scalar physical moves, float rodata, and RIP-relative fixups #7301 loads/stores; no serializer-side
scavenging, signedness inference, precision choice, or re-lowering is
allowed.
Exact ELF/COFF byte goldens cover all six mnemonics, F2/F3 and REX
ordering, low and extended GP/XMM registers, ModRM direction, and rejected
illegal class/width/precision combinations.
Assembly output remains byte-identical for migrated rows. Once a differential
fixture's remaining families are eligible, assembler fallback is fatal and
execution/output/trap/bit results match at opt 0/1/2 on Linux and Windows.
Report record count/bytes and allocations, compiler time/peak RSS, generated
instruction/code size, and representative conversion runtime before/after.
Avoid per-instruction heap or String allocation.
Pass typelisp fmt, focused regalloc/backend/encoder goldens, full
typelisp test, integration/direct-object differentials, deterministic
assembly, bootstrap/fixpoint, and Linux/Windows CI without reducing coverage.
Assumptions / blockers
Blocked exactly on #7055 (machine-program core), #7202 (full-width integer
materialization needed by the source-boundary matrix), and #7301 (physical
GP/XMM moves, spills, float data, and fixups). After all three close, replace
blocked with ready-for-implementation.
#7205 is a peer consumer, not a prerequisite; reuse whichever checked
legacy-SSE descriptor lands first. #7353/#7354 own directional u64 high-half
control flow, and #7355 owns final 121-row Cast eligibility/fallback retirement.
Coordinate the shared-core/target-adapter boundary with #5347.
Split from #7206.
