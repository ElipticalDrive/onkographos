Closes #48.
Stacked on #65 (the Material table, branch ticket-42). The two share renderer files. When #65 merges, GitHub retargets this PR to main. Bench #65 first, then this one.
What changed
Rings: a scene is a list of levels, where level n is mip n of the brick store (LOD pyramid in the brick store #43).
Each level gets a 16³-region box centred on the camera, so ring n is 1024 << n Voxels wide.
Box starts snap to even regions, so each box nests in the next.
On the test sphere from the surface, the first three rings hold 116k, 142k and 114k bricks.
GPU layout: still the same five bindings. The table is split per level, and regions, brick_refs and bricks are shared.
The allocation is fixed: 65.7 MiB for 7 rings.
Regions use a free list; words use a first-fit coalescing pool.
The overlay shows planet memory: X of Y MiB.
trace() and reference::trace: each level's box is walked, skipping the hole the finer ring covers, and the nearest hit wins.
A ray starting inside a hole begins that level at the finer box's exit.
Every point in space belongs to exactly one level, so there are no cracks.
A coarse hit reports the level-0 Voxel on its entry face.
Re-centring:
Scene::recentre writes only regions entering or leaving a box. A small move writes 0 bytes.
Hysteresis: a box stays put while the camera is in regions 6–9 of its 16. Jittering across a boundary costs nothing.
Scene::update carries Edits into every ring and writes only the words that changed.
A full pool is a RingsFull error that stops the client cleanly. It never panics.
Client and bench: the client draws the Planet as 7 rings and re-centres every frame. The bench re-centres before each timed frame, outside the timings, as documented.
Tests:
GPU/CPU agreement on ring scenes: near, mid and far hits, plus rays from coarse rings heading inward.
Agreement at 5 cameras from the surface to orbit.
Upload bytes per move.
Bounded memory on a surface→orbit flight.
7500 rays that never reach the sky where the Planet has ground.
A 4000-step nesting and hysteresis sweep.
Tiny-pool error paths.
New goldens: planet_rings_{surface,horizon,orbit}_256x144.png. The surface one matches the old single-level golden within tolerance. No existing golden changed.
Review: Opus /code-review found no blockers and confirmed the cross-level trace, the hole and nesting logic, and the pool and patching. It requested two fixes, both applied: hysteresis (jitter was re-packing every frame at 11–13 ms) and a panic when an Edit overflowed the rings.
Known, deferred to #49: moving a ring is still a one-frame hitch on the UI thread. Release numbers on the whole test Planet: a mean of about 25 ms per move, worst about 63 ms. Moves happen about every 64–512 Voxels of travel. Packing off the UI thread is #49's acceptance criterion. The bench doesn't time it.
Checks: fmt and clippy -D warnings are clean, cargo t --workspace passes on lavapipe (rings.rs takes about 47 s because it generates the whole test Planet), and the server dependency check is clean.
Benchmark: needs-benchmark. primary is expected to change, because each ray now walks up to 7 levels, though it skips hole regions. No budget line changes. Please bench after #65.
