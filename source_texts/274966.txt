Stacked on #3 (feat/editing-core). Merge #2, then #3, then this PR.
Summary
This adds the rendering layer (spec §8, the mesh worker pool from §6, and the rendering rows of §12). SchematicRenderer in src/render/index.ts is the API that the React UI in the next PR will drive.
Meshing: chunks are 16³ and meshed in a pool of workers sized to navigator.hardwareConcurrency. Each slice is sent with a one-block border and the buffers come back as Transferables. Each chunk has an opaque mesh and a transparent one.
Culling: faces next to opaque cubes are skipped, as are faces between identical transparent blocks.
Unknown blocks: drawn as magenta cubes, including block states that match no blockstate variant.
Textured mode:
Source: blockstates, models and the atlas come from misode/mcmeta, matched to the file's MinecraftDataVersion. They are resolved through deepslate and cached with the Cache API.
Failure: if loading fails, the view switches to colored mode and retryAssets() tries again.
Newer files: a file newer than every known version raises the §5 warning flag.
Colored mode: uses a bundled palette that npm run generate:palette builds from 26.3 textures, so it works offline. Blocks missing from the palette get a stable color derived from a hash of the name.
Layer view: a Y range that the mesher respects, so cut faces render solid. Only rows at the boundary are remeshed, and single-layer mode draws the layer below as a ghost.
Interaction:
Picking is a voxel DDA against the model grid, with hover info.
Box selection takes two clicks plus numeric input.
A highlight set fades every block outside it.
There is fit-to-view and WASD fly mode.
Updates and failures: edits remesh only dirty chunks, and stale worker results are dropped. A chunk that fails to mesh gets a red outline while the rest keeps rendering. A worker that crashes is replaced, and respawns are capped.
Dev harness: extended with a 3D viewport for manual checks; it is replaced in the next PR.
Testing
npx vitest run: 527 tests pass. tsc --noEmit is clean. vite build works.
All decision logic is pure TypeScript tested in Node: meshers, culling, slicing, model bake, version choice, scheduler, layers, DDA and the chunk manager.
A headless Chromium run (SwiftShader WebGL) covered:
textured and colored mode;
layers and the ghost layer;
highlight, selection, hover, replace and undo;
asset failure, retry and cache;
zoom and fly without clipping, and hover refreshing after an edit.
Notes
Older files: a file with no exact mcmeta version uses the oldest release at or after its data version, e.g. 1.13 files use 1.14 assets. Files newer than everything known use the newest release and get the warning.
Placeholder textures: signs, beds, wall heads and shulker boxes use them. deepslate 0.27.2's special-renderer texture names don't match 26.3.
Not done: rendering only when something changes. The view currently renders every frame.

Fix round 1 for ChunkManager review:
- ChunkScheduler now draws versions from one counter for the whole
  scheduler instead of per-entry, so a chunk removed and later
  invalidated again (setSchematic, layer rows dropped then re-shown)
  never reuses a version an in-flight job already holds. Previously a
  stale mesh or a stale failure could win the race and get shown.
- ChunkStats.queued now counts only main-pass entries (pending plus
  parked), matching its doc; it previously included ghost-pass
  entries too, so single-layer mode over-reported the queue.
- The success handler's view.set is now wrapped like the failure path,
  so a view exception is caught, logged and marks the chunk failed
  instead of escaping pump().
- The ghost-pass-with-no-range branch also clears the chunk's failed
  marker, matching the empty-slice branch.
- Test fixes: FakeView.clear() clears `failed`; the no-op-async test
  for empty chunks is no longer async.
