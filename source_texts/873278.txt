Scope
Milestone M5 of docs/clean-room/milestones.md: the gsplat renderer. It fills the gsplat render backend of openftgs.render, the §2.1 default, which still raises NotImplementedError (Q-32).
The backend runs on gsplat 1.5.3 and meets the RenderOutput contract of §2.1 and Q-32 in both layouts:
the 2D mean μ′ as the gradient anchor for the gradient statistics (E10, D-12);
visible from the screen radii;
packed mode with gaussian_ids.
render() gains one keyword the §2.1 signature lacks, packed, by owner decision (candidate A below). The backend is pinned to the reference by U-7, U-12, the GPU variants of U-4, U-8 and U-20, and the boundary cases named in the forward notes on #37.

Decisions within the spec's latitude
One front half, two backends. render() keeps its M4 front half: validation, time, at_time and compaction. Each backend returns image, alpha, means2d, visible and gaussian_ids. return_aux and retain_grad() stay in render().
gsplat's settings are private constants beside E6's. Classic mode (D-6), tile size 16 and radius_clip 0 (D-57). The unsegmented sort and sparse_grad off are passed as literals. ε, near and far come from the existing constants (D-72).
σ_eff goes into gsplat's projection. That gives the opacity cull and the opacity-aware extent inside the projection, D-32's default placement.
The gradient anchor in each layout (meeting Q-32):
Unpacked, opacity cull inside the backend. The 2D means are zeroed off the visible rows before they reach the rasterizer. That zeroed tensor is the anchor.
Unpacked, with compaction. Only the 2D means are scattered to all N rows. That [C, N, 2] tensor is the anchor, and the rasterizer reads the kept rows back from it. Rasterization still runs over the kept rows only, which keeps compaction's memory saving.
Packed. gsplat's own [nnz, 2] tensor is the anchor; every row of it is written.
gsplat's tile intersection gets gsplat's own ids, local to the rows passed, as rasterization() passes them. Only RenderOutput.gaussian_ids is remapped to model rows.
visible in compaction mode is scattered with index_copy, or index_put_ if CUDA refuses bool; neither syncs.
gsplat is imported inside the backend, so importing openftgs.render stays light on CPU-only machines.
Host syncs per render. The intersection count, the packed visible count, and with compaction the nonzero of D-57. No new ones; one fewer than §2.4 rule 3 allows, since no view matrix is inverted (candidate C).

A. The packed keyword
Spec location: §2.1 render; §2.4 Settings (PerfConfig.packed); D-57; RenderOutput.
Gap: PerfConfig.packed selects gsplat's packed mode, but the §2.1 render() signature has no way to ask for it. M4 recorded this as needing the same decision precull got.
Decision:
A keyword-only packed: bool = True, PerfConfig's and gsplat's default (D-57). M10 passes cfg.perf.packed.
The reference backend is always unpacked (Q-32) and ignores it. Consumers such as M8's statistics branch on gaussian_ids is not None, not on the flag.
Rationale: the smallest change that makes D-57's setting reachable, as Q-31 did for precull.
Alternatives:
The reference backend also honours it, returning the packed layout. That gives one layout per setting on both backends, at the cost of more work and a change to M4's reference.
A perf: PerfConfig keyword. precull would then exist twice.
Detecting test: the layout tests; U-8 on the GPU in both layouts; B-2 (M15).
B. How the gsplat backend meets Q-32, and visible in packed mode
Spec location: §2.1 RenderOutput (means2d, visible "unpacked mode", gaussian_ids); Q-31; Q-32; D-57.
Gap: gsplat 1.5.3's top-level rasterization() can't keep Q-32 as confirmed:
Stale rows. In unpacked mode its means2d holds stale memory in culled rows. The projection allocates the tensor uninitialized and writes only rows that pass every cull; a probe read back 123.0 left by the allocator. Zeroing those rows afterwards would break the gradient anchor.
No anchor under compaction. It can't give a [C, N, 2] anchor when precull="compact" runs unpacked, because gsplat sees only the kept rows.
No camera ids. §2.1's comment gives visible for unpacked mode only, but RenderOutput has no camera ids. In packed mode, per-camera visibility would otherwise be lost.
Decision:
Stage functions. The backend calls gsplat's exported stage functions, the same kernels rasterization() runs:
fully_fused_projection;
spherical_harmonics;
isect_tiles and isect_offset_encode;
rasterize_to_pixels.
Its glue is adapted from rasterization() (gsplat 1.5.3 rendering.py, Apache-2.0), with an attribution comment and a source-log row. gsplat has no NOTICE file, so no NOTICE entry is needed.
Q-32 holds as confirmed in every combination. Unpacked means2d is 0 off the visible rows and is the tensor compositing reads. Compaction keeps a [C, N, 2] anchor in unpacked mode.
visible [C, N] is returned in both layouts. In packed mode it is one scatter from the camera and primitive ids, with no host sync.
Rationale:
It keeps a confirmed row intact.
All four combinations work, which B-2 needs.
The GPU tests compare visibility per camera with the reference in both layouts.
Alternatives:
Call rasterization(), amend Q-32 (unpacked means2d unspecified off the visible rows), and reject compact + unpacked.
Leave visible None in packed mode, as §2.1's comment reads.
Detecting test: the layout tests (zeros off the visible rows, ∂L/∂μ′ in all four combinations); the rasterization() cross-check; U-8 on the GPU; U-16 (M8).
New Q-n candidates (provisional). The implement run records them as numbered rows in its first commit.
C. The gsplat backend's remaining semantics
Spec location: §2.1 render and RenderOutput; Q-32; D-28; E2; §2.4 rule 3; D-57.
Gap: the spec doesn't say:
the order of packed rows, or the dtype and meaning of gaussian_ids after compaction;
which dtypes and devices the gsplat backend accepts;
what it does with no rows;
how the background reaches a packed render;
where the SH camera center comes from.
Decision:
Packed rows. Packed means2d is [nnz, 2], camera-major, in ascending row order within a camera; that is gsplat's packed order. gaussian_ids is int64 and holds model rows, remapped through compaction.
Inputs. The gsplat backend requires CUDA float32 per-time arrays and raises ValueError naming the reference backend otherwise. Q-32's float64 path stays reference-only.
No rows. With no rows passed (N = 0, or none kept by compaction), gsplat is skipped. The render is Q-32's empty render: the background, alpha 0, zero means2d ([C, N, 2], or [0, 2] packed), all-False visible, and empty gaussian_ids.
Background. It is composited outside the kernel in both layouts, as image + (1 − alpha)·c_bg. That equals E6's T_final·c_bg, since alpha = 1 − T_final.
Matrices. View matrices are built from R_w and t_w with a last row (0, 0, 0, 1), and K from fx, fy, cx and cy only, so only the fields Q-32 names are read.
Camera center. The SH camera center is −R_wᵀt_w (E2, §1.4), not gsplat's inverse of the view matrix.
Rationale:
gsplat's kernels compute in float32.
N = 0 kills the process with SIGFPE in both layouts (probe), while all-culled with N > 0 works.
In packed mode, gsplat 1.5.3's rasterize_to_pixels checks the background against means2d.shape[:-2] + (3,), which is (3,). A [C, 3] background fails with or without visible rows (probe).
Taking the center from R_w and t_w is exact in real arithmetic and avoids torch.inverse's host sync, one of the three §2.4 rule 3 allows.
Camera-major ascending order and int64 ids are what the kernel writes (probe). The docstring's int32 is wrong for 1.5.3.
Alternatives:
A float64 model silently cast to float32.
Pass the background to gsplat in unpacked mode only.
Use gsplat's torch.inverse for the camera center.
gaussian_ids local to the rows passed.
Detecting test:
the CPU rejection tests;
empty and all-culled renders in all four combinations;
per-camera backgrounds in both layouts;
the layout tests (packed means2d equals unpacked means2d gathered at the ids);
the rasterization() cross-check (≤ 10⁻⁶).
D. Cross-backend comparisons at E6's discontinuities
Spec location: U-7 and U-12 pass criteria; E6. The precedent is Q-15, for U-28.
Gap: U-7's ≤ 10⁻⁴ and U-12's criteria are undefined where both backends' float32 arithmetic can land on opposite sides of a discontinuity. Such a pixel or row changes by about 1/255 or more, through no bug:
The α skip at 1/255. gsplat builds with fast math (__expf) and evaluates μ′ and the conic in another order.
The exclusive stop at T = 10⁻⁴.
The extent at the opacity threshold. gsplat computes __logf(σ_eff / float32(1/255)), the reference log(255·σ_eff). Both cull against float32(1/255), but a few ulps above it the extent can be 0 in one backend and positive in the other (M4 · Reference renderer #37, M4 milestone review finding 5).
Radius rounding. A radius differs by one where e·√Σ′ᵢᵢ is within rounding of an integer, which moves the off-image test.
Near-equal depths.
The depth cull at near and far.
Decision: exclusions, not a looser tolerance. Pixels and rows that are kept are still held to the spec's criteria.
Pixels excluded:
any primitive's float64 α within 10⁻³ relative of 1/255;
any float64 T after a primitive within 10⁻³ relative of 10⁻⁴;
two contributing primitives whose float64 depths are within 10⁻⁵ relative.
Rows excluded from the visible comparison:
float64 e·√Σ′ᵢᵢ within 10⁻⁴ of an integer;
a box edge within 10⁻⁴ px of the image edge.
Scene construction. Random scenes keep σ_eff ≥ 10⁻³ relative from 1/255 (resampled) and |z − 0.01| ≥ 10⁻³, except for deliberate culls far from the bounds.
Cap. The excluded share is asserted ≤ 1% per scene.
Report. The U-7 and U-12 tests report the largest |Δ| outside the mask and the largest excluded share. The first run's numbers go into the row's rationale.
Constructed tests cover the excluded cases: the 1/255 boundary, the exact depth tie and the touching box.
Rationale:
The spec's tolerances are meant for continuous rounding differences.
An estimate from the boundary-ring area gives order one boundary pixel over U-7's 50 scenes, so seed-dependent failures are plausible without exclusions.
The criterion stays meaningful only if it is defined away from discontinuities, as Q-15 did for U-28.
Alternatives:
Redraw scenes until no pixel is near a boundary.
Compare without exclusions and accept seed-dependent failures.
Detecting test: the reported excluded share and the largest |Δ| outside the mask, in U-7 and U-12.
Glossary and module docs
docs/GLOSSARY.md, under Rendering:
```
**Render backend**:
One of the two implementations of E6 behind `render()`: gsplat (CUDA, float32, production) or reference (pure PyTorch, in the parameters' dtype and on their device, the readable oracle for tests). §2.1
_Avoid_: rasterizer (ambiguous with gsplat itself), renderer mode, engine

**Packed mode**:
The layout of a render's 2D means in which each visible primitive–camera pair has one row, labeled by `gaussian_ids`; gsplat's default until B-2 calibrates, and never the reference render backend's. D-57
_Avoid_: sparse mode, compact mode (compaction is the explicit placement of the opacity cull)

**Unpacked mode**:
The layout of a render's 2D means with one row per camera and primitive, zero where the primitive is not visible in that camera; the reference render backend's only layout. D-57
_Avoid_: dense mode, full mode
```

Forward notes, addendum: Q-39 changed
M16 · harness
The problem. Q-39's exclusions cover only U-7 and U-12. L1 between the reference backend and gsplat, which M16's Tests line asks for ("the reference backend against gsplat passes L1 at its tier tolerances"), will meet the same discontinuities without them.
Which tier. Both backends report the same rasterizer constants (D-73, Q-35), so info puts them in the "same rasterizer and constants" tier: PSNR ≥ 60 dB and max |Δ| ≤ 1e-3 (§3.3).
What a boundary flip costs. A single flip at one of E6's discontinuities is enough to fail it:
an α-skip pixel, or a row just above 1/255 with a zero extent in one backend only, changes a pixel by about 1/255 ≈ 0.004;
a swapped order of near-equal depths changes it by more.
How likely. U-7 found no such flip in its 50 scenes at 64×48 on the RTX 4090. None of the 128 pixels Q-39 excluded differed by more than 10⁻⁴, and the largest difference elsewhere was 3.4·10⁻⁶. But L1 renders at least 200 items, at larger resolutions and with probes at the boundaries (P4, P7, P8), so a flip is likely.
What M16's planning should decide, as a Q-n candidate:
An exclusion rule for L1 like Q-39's. The harness would compute its own float64 margins from the FTGS-IF file and the request. It must not import either implementation (§3.3), so it can't reuse the test suite's helper.
The different-rasterizers tier for the two backends. That means PSNR ≥ 45 dB and ≤ 0.5% of pixels with |Δ| > 1/255, though info reports identical constants.
Probes at the boundaries. Keep P4, P7 and P8 away from the exact discontinuities, or judge them by their own criteria.
