What happened?
When an alignment point is missing at a moment, rotation_for() returns NULL (R/transform_coords_rotate.R:381-383), and apply_rotations() skips that row (lines 259-264). The row is centred on the reference point but keeps its arena orientation, so it looks like a valid egocentric position. Coincident or parallel alignment points give the identity rotation (R/rotation_matrix.R:51, 61, 91) with the same result. In 3D, a missing third point quietly falls back to the two-point rotation.
Mixed into egocentric data, these rows are wrong in a way nothing downstream can detect.
Reproducible example
```
af <- anicore::example_anipoint(n_obs = 5, n_individuals = 1, n_keypoints = 3)
kp <- unique(as.character(af$keypoint))
af$x[af$keypoint == kp[2] & af$time == 2] <- NA
anispace::transform_to_egocentric(af, to = kp[1], align = kp[1:2])
# at time 2, positions are translated but not rotated
```
What did you expect to happen?
Rows whose rotation can't be determined come back NA (all axes), optionally with a message counting them.
