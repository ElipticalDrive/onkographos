Motivation
Reduce draw/triangle count and shadow cost by replacing the monolithic instanced world with a chunked, mesh-based pipeline.
Enable streaming and culling so only nearby geometry is built and rendered to improve runtime performance.
Keep water and noncritical visual elements on a lightweight pass while the chunk system stabilizes.
Description
Replaced the single instanced-mesh generator with a ChunkManager that keys chunks by (cx,cz) and manages lifecycle, bounds and a world Group container.
Added per-chunk voxel population (getVoxelTypeAt, buildChunkVoxelData) and face-extraction + greedy meshing (buildMaterialGreedyGeometry) to emit only exposed faces and merge coplanar quads per material.
Implemented dynamic streaming around the camera (RENDER_DISTANCE, CHUNK_UNLOAD_PADDING) with frustum culling per-chunk and distance-based castShadow toggling (SHADOW_CAST_DISTANCE).
Tuned global shadow settings and kept water as a single MeshBasicMaterial plane separate from per-block geometry to limit shadow/map cost and simplify water rendering.
Testing
Ran node --check script.js which completed without errors.
Started a local server with python3 -m http.server and verified the page loaded; used Playwright to capture a screenshot of the running scene which succeeded and produced artifacts/chunk-world.png.
The in-browser smoke run exercised the chunk build/update loop (chunkManager.update(camera)) during the tick loop and produced visible chunked geometry in the captured screenshot.
