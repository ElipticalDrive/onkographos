Face to face constraints: replace the face constraints struct with individual arrays. The constraint limits and weights can be half floats as well (if we do this, must change the FLT_MAX value used in the shader)
Different layout for particles for better memory coalescence. There might even be a way to use shared memory in the FTF shader, even though no two threads use the same particles - if a single global memory read pulls all 8 particles of a voxel and a FTF constraint of thread A uses 4 of those, but thread B uses the other four, then using shared memory saves a global read.
Prefix scan: change the indexing of the upsweep to allow warps to retire early / improve occupancy. not possible with current algorithm.
Simplify meshes using CGAL, after doing boolean intersection.
Indirect dispatch of shaders that only run for surface voxels.
LODs - journal version of voxelization paper treats interior voxels as groups to speed up simulation

Not so much an idea, but just generally making a note that, by far, the biggest bottleneck right now is collisions.
I'm not sure it's worth the effort to improve in Maya though (maybe for some hypothetical unreal plugin that goes with this). The slowness comes from the use of a hashgrid to make collisions unbounded. That's nice for Maya and for UX, but not strictly necessary. A regular, bounded collision volume would make things much faster.

The voxelization process could be made faster (but it would be a significant effort for little gain. Still, will write it down here at least):
Voxelization time is currently dominated attribute and shading set transfer. These processes are pretty darn fast on the surface, but on the interior, they have to do slow searches.
There's probably a way to do this step manually in the actual voxelization process, which would allow us to leverage multithreading. (Also, with more control, we could just skip the normal transfer on the interior, which isn't necessary)
