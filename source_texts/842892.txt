Two roadmap milestones, one commit each.
Commit 1: gradient-driven densification with signed splat birth
Grow the mixture from a small K instead of guessing capacity up front.
adapt(): prunes splats with |w| below threshold and splits splats whose accumulated positional-gradient norm exceeds split_rel × median (absolute 3DGS-style thresholds fail near convergence — all norms shrink together while their ratios keep pointing at under-resolved splats). Adam moments follow the same row bookkeeping.
birth_field(): the weight gradient ∂L/∂w(μ) of a hypothetical splat at μ = the residual back-projected through the splat kernel, closed form. Key finding: split/clone alone cannot create negativity — from an all-positive K=4 local minimum, two positive children never make a negative fringe (2/3 seeds failed at L2 ≈ 1.0). A splat born at the field extremum with the descent sign fixes this; the gradient itself determines the newborn's sign.
Experiment 02 (same data as exp 01): K=4 → 9 with 2 negative weights placed on the true fringe lobes, relative L2 0.071 vs 0.125 for fixed K=8, negativity −0.191 vs true −0.190. All 5 tested seeds land in L2 0.05–0.09.
Commit 2: iterative MLE baseline — the falsification test
fock.py: truncated Fock-basis tools (cat density matrix, quadrature vectors, Wigner transform via displaced parity, fidelities). All conventions validated to ~1e-12 against the states.py closed forms.
mle.py: Lvovsky R ρ R iteration on the same binned histograms the splat fitter uses. Implementation note: R must be Σ (f/p)|v⟩⟨v| with |v⟩ᵢ = ⟨i|x_θ⟩ — the transposed outer product is not the likelihood-ascent operator and silently stalls at F ≈ 0.35 (regression-tested).
experiments/03_mle_baseline/run.py: fidelity / wall-clock / negativity across 250, 1000, 4000 shots per angle.

静的レビューです。依存導入が前回フリーズしたため、今回はテスト実行なしで差分と取得済みコードだけを見ています。
Findings:
Medium: fit.py の module docstring が実装と逆の説明になっています。
wigner_splat/fit.py 冒頭で「K stays fixed; gradient-norm-driven densification/pruning is the next milestone.」と書いたままですが、この PR で adapt() / birth_field() / densify_every が入っています。README と実装の中核主張に関わるファイルなので、次の読者が「densification は未実装」と誤読します。ここは PR 内で直した方がよいです。
Medium: MLE の停止条件が、尤度低下時にも収束扱いになります。
wigner_splat/mle.py の if ll - prev_ll < tol * ... は、ll が数値誤差や実装ミスで下がった場合も即 return します。R rho R は単調増加を期待する基準実装なので、低下は収束ではなく異常として検出するか、少なくとも 0 <= ll - prev_ll < tol * ... に寄せた方が安全です。今のままだと、将来 two-mode 化で不安定になった時に「早く収束した」ように見えてしまいます。
Low: adapt() の Adam moment bookkeeping は「行の対応」だけで、split 後の子の moment が親の値そのままです。
親行を複製し、子の w/mu/s を変更していますが、m1n/m2n 側は half weight や offset/shrink に合わせて調整されません。致命的ではないですが、PR 本文の「Adam moments follow the same row bookkeeping」は少し強い表現です。子はゼロ moment にする、または weight moment だけ半分にする、など方針を明示した方がレビューしやすいです。
Tests: 未実行。pytest が環境になく、検証用 venv への依存導入で前回フリーズしたため、今回は静的レビューに限定しました。
全体として、数式実装はかなり慎重にテストで縛られていて、即ブロック級の破綻は見えていません。ただし MLE は今後の反証基準そのものなので、停止条件だけは早めに硬くした方がいいです。

- fit.py module docstring still said densification was a future
  milestone; describe adapt()/birth_field() instead.
- mle.py stop condition treated a likelihood DECREASE as convergence.
  R rho R ascends monotonically, so a real decrease means broken
  operators or truncation: raise instead of returning, and converge
  only on |delta| < tol. Matters because this baseline is the
  falsification criterion for the whole approach and the two-mode
  version must not be able to "converge early" by going unstable.
- adapt(): make the split-children Adam-moment policy explicit in the
  docstring. Children deliberately inherit the parent's moment rows;
  zeroing them was measured worse (2 of 5 cat-state seeds degrade from
  L2 ~ 0.07 to ~ 0.4 because the near-empty second moment allows large
  uncontrolled steps right after the split).

Tests (11) and experiment 03 results are unchanged.
