Contributor
Instanced models can now be frustum culled and drawn indirectly on the GPU on supported Metal, Vulkan and WebGPU contexts. The renderer retains instance data between frames, uploads changes, and consumes GPU-generated visibility without waiting for CPU readback. Ineligible models, order-dependent passes and unsupported graphics contexts retain CPU culling.
GPU culling is enabled by default. It can be disabled in game.project; optional asynchronous profiler statistics are disabled by default:
```
[render]
gpu_culling = 1
```
Technical changes
Design: https://docs.google.com/document/d/16CnM1WM1NlloGkhmmCPgbLMdcWAgYCM5endRAF1xNQc/edit?tab=t.0
Builds on the persistent render-item API in Add a render item API to dmSDK #13469, whose commits are currently included against dev. Components retain item handles, update transforms, bounds and material state through setters, and submit their dispatch each frame. Legacy frame-local SDK APIs remain available and are deprecated; the new lifecycle is documented in the SDK header.
Adds indexed indirect drawing, storage-buffer views and synchronization on Metal, Vulkan and WebGPU. Capability checks require compute shaders, storage buffers and indirect drawing; OpenGL ES 2/WebGL 1 retain the CPU path.
Adds persistent GPU batches, compact bounds, dirty uploads and compute visibility compaction. Compatible shader variants fetch transforms through visible instance IDs; other supported layouts use compacted matrices. Visibility statistics are optional and asynchronous.
Restricts GPU batches to eligible indexed, instanced model layouts and order-independent passes. Skinning, morph targets, dynamic attributes and incompatible render state retain CPU culling. Allocation failures and device limits also fall back to the CPU path.
Keeps model allocation improvements local: stable chunk allocation, smaller hot component state, shared mesh bounds and cached bone-parent classification.
Documents the renderer path and adds localized project settings. Design document.
Validation
After merging current dev: 110 renderer, 612 gamesys, 69 engine and four focused shader-compiler tests passed, along with two small WebGPU pixel/visible-ID regressions.
Earlier native coverage passed 14 renderer tests each on Metal and Vulkan/MoltenVK, plus the Metal model integration test. Coverage includes CPU/GPU pixel equivalence, material changes, frame overlap, storage replacement, allocation failure and recovery. Generated SPIR-V validates for Vulkan 1.0.
With updated Dawn, both 100K WebGPU CPU-culling and GPU-culling diagnostic runs completed and exited normally. GPU mode processed 100K candidates, reported 614 visible instances and used one indirect draw. Windowed, 30 Hz, approximately 0.47-second recordings after population and warmup; no detected GPU errors or new WindowServer reports. The diagnostic build includes tracing and the same isolated duplicate-window-close correction used in the previous failed run. The earlier hang did not reproduce; its root cause remains unproven.
Historical Metal measurements on Apple M5 Max, before the latest dev/Dawn merge, show all-visible camera-motion model batch preparation falling from 1.112 to 0.067 ms in the 100K mixed-object scene (50K models and 50K sprites). In the full-motion workload, process physical footprint increased from 562.3 to 686.0 MiB; executable machine code increased by 90.6 KiB. These component and cost measurements do not establish a full-frame speedup for the current merged build.
