From documentation, a valid .DDS file must have at least the following flags set in DDS_HEADER/DDSURFACEDESC2 dwFlags:
DDSD_CAPS (0x1)
DDSD_HEIGHT (0x2)
DDSD_WIDTH (0x4)
DDSD_PIXELFORMAT (0x1000)
A simple test (compressonatorcli.exe -fd BC7 -mipsize 1 infile.png outfile.dds) produced an invalid .DDS file, missing both DDSD_CAPS and DDSD_PIXELFORMAT.
The fix is obvious.

As you can see, the file created with ./compressonatorcli -mipsize 1 -fd BC7 /tmp/square-white.png /tmp/squarew_compressonator .dds is missing:
DDSD_CAPS and DDSD_PIXELFORMAT in DDS_HEADER::dwFlags (as mentioned by @tamlin-mike)
DDSCAPS_COMPLEX in DDS_HEADER::dwCaps (must be set when mipmaps are stored)
For more information on those flags see https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dds-header
(yes, it says that DDSCAPS_COMPLEX is "optional", BUT "must be used on any file that contains more than one surface (a mipmap, a cubic environment map, or mipmapped volume texture)")
