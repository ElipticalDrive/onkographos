💡 What: Added an IntersectionObserver to pause the Three.js rendering loop when the canvas container is no longer visible in the viewport.
🎯 Why: The requestAnimationFrame loop was running continuously even when the user scrolled away from the hero section, wasting CPU and GPU cycles on unseen frames.
📊 Impact: Eliminates ~60 frames per second of unnecessary Three.js calculations and WebGL drawing calls while the user is reading other sections of the page, significantly improving battery life on mobile and overall page performance.
🔬 Measurement: Open Chrome DevTools > Performance monitor. Observe CPU usage and FPS. Scroll down past the 3D brick and notice the CPU usage drop when the canvas leaves the viewport.
