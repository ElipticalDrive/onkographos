Summary
Python bindings (nanobind) for swept-volumes: a zero-overhead numba.cfunc
transform, a CMake-fetched build (libigl v2.6.0), and a choice of marching
cubes or dual contouring — both running on the same sparse continuation cells,
with an analytically-validated correctness test suite.
A cross swept along a cyclic orbit-and-twist; translucent swept volume with the
input shape animated inside (headless polyscope). Marching cubes vs dual
contouring (root finding + analytic normals):
marching cubes
dual contouring
Bindings & build
NativeTransform wraps a numba.cfunc(void(double,double*,double*)); the hot
loop is a native indirect call (no CPython/GIL/NumPy). ~28 ns/call vs ~33 for a
C++ baseline (0.8x); a Python callable is ~180x slower; output bit-identical.
All deps via CMake FetchContent (libigl v2.6.0 + Eigen), no submodule/CGAL.
scikit-build-core packaging; native driver; headless polyscope demo.
Contouring: marching cubes or dual contouring
Both consume the continuation output (CS, CV, CI) — no dense grid, no stamping.
DC uses the same cells as unique edges (libigl's sparse dual_contouring
wants #edges x 2, not #cells x 8 — the original tearing bug), root-finds each
crossing with the continuation's own SDF (warm-started from the local argmin
time), and takes the analytic P - C normal there → crisp sharp features. MC
needs no root finding (its linear-interp crossings are already at the
continuation tolerance).
Validated analytically: a translating cube's swept volume (a box) is
dual-contoured to within 1e-4 of the true box.
Correctness (from review)
Two real bugs were caught and fixed:
The demo "cross" was three overlapping boxes — a non-manifold soup with
interior winding number > 1 (s = 1 - 2w gave s = -5, corrupting the field)
and interior faces that trap the continuation. The brush poked out ~2 cells and
the surface showed stamping-like banding. Fix: clamp the sign via w > 0.5, and
build the cross as a watertight mesh. Poke-out 2.05 → 0.55 cells; banding gone.
Confirmed it is not stamping: on the smooth analytic torus the deviation
stays at the ~1e-3 continuation tolerance at every resolution (0.04/0.02/0.01),
i.e. grid-scale artifacts that shrink with eps, not fixed-world-scale stamps.
Tests (tests/, libigl)
Analytic ground truth with two checks each — containment (posed brush points
inside the swept mesh within ~1 cell) and accuracy (swept mesh matches the
closed-form SDF within ~1 cell): translating sphere → capsule, circular sphere →
torus, rotating box → cylinder, torus refinement convergence, watertight-cross
containment + winding sanity; plus ABI / runtime-parity / MC-vs-DC / keyframe
tests and experiments/ (static sphere, analytic translating box). 15 pass.

…nectivity

Two independent bugs made DC output garbage; verifying each piece isolated them:

1. Normals. The swept SDF is f(P)=min_t g(P,t). By the envelope theorem, at the
   argmin pose t* (where dg/dt=0, the tangency condition the continuation solves),
   d f/d P = d g/d P, which for a signed distance to a mesh is
   s*(P - c_world)/||P - c_world|| -- c_world is the closest surface point we
   already have from the AABB query. No finite differences, no chain rule through
   t. Verified analytic == FD gradient (median err 1e-10, p99 4e-4) on a sphere
   brush; the earlier FD path produced noisy normals (spikes).

2. Connectivity. Marching cubes triangulates each cell independently, so the
   continuation's thin ~1-cell surface shell is fine. Dual contouring emits one
   face per sign-change edge and needs the four cells around it, which the shell
   lacks -> torn/holey mesh regardless of normal quality. Run the dense
   dual_contouring over the bounding box of the continuation cells (a complete
   grid) instead; f is only nonzero near the surface.

Result: DC now yields a complete, closed surface. example_polyscope.py gains a
--contouring {mc,dc} flag. MC remains the default (cleaner, faster, scales to
finer eps); DC is costlier and sharpens on the C0 stamped field.

Root cause of the earlier garbage DC: I passed the #cells x 8 cell matrix where
libigl's sparse dual_contouring expects a #edges x 2 list of the unique cell
edges (per its 805_MeshImplicitFunction tutorial). It silently used only the
first two columns -> wrong topology -> torn mesh. My "needs a dense grid /
complete neighbourhoods" conclusion was wrong; the same sparse cells feed both
marching cubes (cells) and dual contouring (edges).

Verified on static geometry (experiments/sparse_dc_static.cpp, sphere + exact
gradients): from one sparse_voxel_grid, both MC and DC are watertight
(boundary=0, non-manifold=0, Euler=2).

Rewrite the swept-volume DC path to be method-consistent:
- values: the continuation's own CS (no min-over-stamps sampling).
- normals: analytic envelope-theorem normal at each grid vertex from the
  continuation's per-vertex argmin time CV_argmins; s*(P-c_world)/||.|| with the
  closest point from the AABB query. No finite differences, no chain rule in t.
- topology: the same CI cells expressed as unique edges (igl::unique_simplices).

Result: DC now runs on the same sparse cells at the same eps and ~same cost as
MC (no stamping), and is closed (0 boundary edges; a few non-manifold edges only
at genuine sharp features). Regenerate the DC demo GIF at the fine eps=0.015.
Add a watertightness regression test and the static experiment target.

…c tests

Review found two real failures on the demo: the brush poked out of the swept
volume (~2 grid cells, far beyond corner-cutting) and the surface showed
stamping/strobo artifacts. Root cause: the demo "cross" brush was three
OVERLAPPING boxes -- a non-manifold soup.

- Winding sign: the continuation used s = 1 - 2*w, which is only +/-1 when the
  winding number w is 0 or 1. Overlapping boxes give w = 2 or 3 at the centre
  (verified: winding=3 -> s=-5), scaling the signed distance (and its t-gradient
  in the descent) by up to 5x -> corrupted field. Clamp the sign to +/-1 via the
  w > 0.5 threshold (a no-op for watertight meshes, correct for soups).
- Demo brush: build the cross as a single WATERTIGHT mesh (boolean union of the
  three bars, embedded) instead of overlapping boxes. This removes the winding
  ambiguity AND the interior faces that create spurious local minima in the
  distance-over-t objective. Poke-out drops from 2.05 -> 0.55 cells and the
  banding disappears.

Add tests/test_correctness.py: analytic ground-truth checks (translating sphere
-> capsule, circular sphere -> torus, rotating box -> cylinder), each asserting
(a) containment -- posed brush points lie inside the swept mesh within ~1 cell,
and (b) accuracy -- swept mesh matches the closed-form SDF within ~1 cell; plus a
grid-refinement convergence check (a stamping artifact would not converge) and a
watertight-cross containment + winding sanity test. Uses libigl for signed
distance.

Explored whether root finding (bisection on the sign-changing edge using the
continuous SDF) helps each contouring method:

- Dual contouring: YES. Add a continuous swept-SDF evaluator that reuses the
  continuation's own per-point optimizer (gradient_descent_test on the same
  f(t)/gf(t)), warm-started from the nearest grid vertex's argmin time
  CV_argmins -- so each edge-point evaluation is a cheap local descent, not a
  cold global search, and the value matches CS. dual_contouring now root-finds
  each crossing and takes the analytic normal P - C there (C = closest brush
  point at the tangent time; because the surface is the iso=1e-3 level set, the
  crossing sits ~iso off the brush so P - C is well defined -> the outward brush
  normal). This recovers sharp features the grid-gradient normal rounded off;
  the demo DC surface is visibly crisper.
- Marching cubes: NO. Its linear-interpolation crossings already sit at the
  continuation tolerance floor; a bisection post-pass changes the analytic torus
  error by <5e-5 (0.00105 -> 0.00100), and MC's terracing is structural. Left as
  an off-by-default helper (SV_MC_ROOTFIND) for reference.

Also confirmed (analytic torus, eps 0.04/0.02/0.01) that the artifacts are NOT
stamping: deviation from the exact torus stays at the ~1e-3 continuation
tolerance at every resolution (would grow/persist if stamping); the visible
banding is real sharp-edge ridges + grid-scale facets that shrink with eps.

Regenerate the DC demo GIF (root finding).

The swept_volume() call carried GUI-era overhead that does not affect the output
mesh (U, G): the strobo/stamping baseline (igl::swept_volume_signed_distance with
10+100 stamps), input.obj/ours.obj/transformations.dmat writes, a dead per-vertex
normals loop (a distance query per grid vertex), and verbose stdout stats. These
are now gated behind a trailing `compute_extras` flag (default false); the Python
bindings expose it as `diagnostics=False`.

Verified the output is byte-identical with the extras on or off, and the lean
default closes the ~30% speed gap vs gpytoolbox (2.59s vs 2.49s on the sphere
benchmark; was 3.2s). The dead normals loop is removed outright.

When diagnostics=True the strobo lists are populated and debug meshes written, as
before.
