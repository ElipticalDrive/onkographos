Motivation
A compiler-generated structural ray-tracing Record has an ordinary constant-buffer ABI, but its
value comes from the selected shader-table record. Consider the equivalent legacy HLSL:
```
struct Record
{
    float3 color;
    float opacity;
};

ConstantBuffer<Record> closestARecord : register(b0, space2);
ConstantBuffer<Record> closestBRecord : register(b1, space2);
ConstantBuffer<Record> anyHitRecord   : register(b2, space2);

[shader("closesthit")]
void ClosestHitA(inout Payload payload, Attributes attributes)
{
    payload.color = closestARecord.color;
}

[shader("closesthit")]
void ClosestHitB(inout Payload payload, Attributes attributes)
{
    payload.color = closestBRecord.color;
}

[shader("anyhit")]
void SharedAnyHit(inout Payload payload, Attributes attributes)
{
    if (anyHitRecord.opacity < 0.5)
        IgnoreHit();
}
```
If HitGroupA contains ClosestHitA + SharedAnyHit and HitGroupB contains
ClosestHitB + SharedAnyHit, DXR requires compatible local root-signature associations for both
groups and the reused SharedAnyHit export. The application supplies one logical Record value
per SBT entry, but each local root CBV needs a GPU virtual address rather than inline structure
bytes. The current D3D12 shader-table path has no materialization step for that representation.
Fixes #874.
Proposed solution
Read the compiler-reflected structural Record type, layout, and bN, spaceM binding for each
selected stage. Hit groups connected through a reused closest-hit, any-hit, or intersection export
receive the same sorted union of bindings and therefore the same local root signature.
For each shader-table entry that declares a structural Record, copy the semantic application bytes
into RHI-owned, 256-byte-aligned constant-buffer storage and write that storage's GPU virtual
address once for every CBV in the export's local signature. Groups that only inherit a component
signature through a shared Record-free stage keep the existing inline legacy record ABI.
This is a draft stacked on #856, which introduces ShaderRecordData. Until #856 merges, GitHub
shows its commit in this PR as well; afterward this PR reduces to the D3D12 local-CBV commit. The
reflection API is supplied by shader-slang/slang#12691. Standalone Slang RHI CI currently fetches
Slang 2026.12.2, which predates that API, so this draft remains blocked until #12691 lands and the
fetched Slang version is updated. No compatibility workaround is added. The separately compiled
entry-point runtime case also uses the independent fix in #873.
Change summary
Area
Change
Public record contract
Clarifies semantic structural Record data versus absolute native-record overwrites.
Pipeline reflection
Collects each selected stage's Record layout and compiler-reserved D3D binding.
Hit-group associations
Forms connected components through shared hit-stage exports and creates one compatible union local root signature per component.
Shader-table materialization
Allocates owned constant-buffer storage, copies Record bytes, and writes root-CBV addresses into native SBT records.
Lifetime and state
Retains the backing buffer with pipeline data and transitions it for constant-buffer use.
Compatibility
Preserves inline legacy records for inherited-only signatures and rejects legacy overwrites that would corrupt a generated CBV address.
Concepts and vocabulary
Structural Record: typed per-SBT-entry application data declared by a structural ray-tracing
stage and reflected by the compiler.
Connected hit-group component: hit groups joined by reuse of a closest-hit, any-hit, or
intersection export. DXR requires their local root associations to agree.
Inherited-only signature: a group receives a component-wide local root signature even though
none of its own stages declares the corresponding structural Record.
Native overwrite: the existing absolute byte patch applied to a native record after ordinary
inline data. It is not semantic structural Record storage.
Process report
DeviceImpl::createRayTracingPipeline2() reads the Record contract from selected entry-point
reflection. This is the canonical producer data: the compiler already chose the constant-buffer
register, space, target layout, and physical export name. The RHI does not reconstruct those facts
from source names or generic types.
Consider the two hit groups above. A disjoint-set pass joins them through SharedAnyHit, unions
{b0}, {b1}, and {b2}, sorts the resulting (register, space) pairs, and associates the same
local root signature with both hit groups. Direct miss, callable, and unused hit-stage exports are
associated with their own binding sets. Conflicting Record sizes or binding contracts are rejected
while the pipeline is created.
ShaderTableImpl::createDeviceBuffers() validates each semantic Record against its reflected size,
allocates one 256-byte-aligned constant-buffer range per physical entry, and writes the same range
address into every CBV slot in that entry. Keeping the backing buffer in PipelineData gives it the
same lifetime as the uploaded shader table and lets command submission transition it to constant-
buffer state before dispatch.
An explicitly carried hasStructuralRecord bit distinguishes Record = void, a possibly
zero-sized non-void Record, and a hit group that merely inherits another group's signature. This
input shape is intentional DXR behavior, not malformed reflection: an inherited-only group can
leave unused local-root arguments uninitialized, so its application bytes retain the legacy inline
layout. Conversely, an actual structural Record rejects ShaderRecordOverwrite; applying an
absolute overwrite after generating root-CBV addresses would silently corrupt the native record.
