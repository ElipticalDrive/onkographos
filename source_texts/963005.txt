```
## 2026-10-05 Refactored volume surface extraction

The Base module `Surface Extraction` processor now uses an `IsoValueProperty` for volume isosurfaces, aligning it with the Marching Squares workflow for `Layer` and `Image`. This fixes the previous assumption that the processor's iso value was already given in data space; iso values are now interpreted consistently through the volume `DataMap`. The processor also supports coloring extracted surfaces by iso value, by input volume index, or by a blend of both, and `Mesh Rasterizer` defaults were updated so incoming mesh colors are preserved by default.

The public marching algorithms for scalar volumes were updated accordingly. `util::marchingcubes` in `<modules/base/algorithm/volume/marchingcubes.h>`, `util::marchingCubesOpt` in `<modules/base/algorithm/volume/marchingcubesopt.h>`, `util::marchingtetrahedron`, and `MarchingTetrahedron::apply` in `<modules/base/algorithm/volume/marchingtetrahedron.h>` now take `const std::vector<TFPrimitiveData>& isoValues` and a `PrimitiveSetMode` from `<inviwo/core/datastructures/tfprimitiveset.h>` instead of a single `double iso` and `vec4 color`.

### Migration guide

Code calling the marching helpers needs to provide one or more `TFPrimitiveData` entries and specify whether their positions are relative or absolute:

```cpp
#include <inviwo/core/datastructures/tfprimitiveset.h>
#include <modules/base/algorithm/volume/marchingcubes.h>

using inviwo::PrimitiveSetMode;
using inviwo::TFPrimitiveData;

std::vector<TFPrimitiveData> isoValues = {
    TFPrimitiveData{0.5, vec4{1.0f, 0.7f, 0.2f, 1.0f}}
};

auto mesh = inviwo::util::marchingcubes(volume, isoValues, PrimitiveSetMode::Relative,
                                        false, true);
```
If custom processor code interacted with Surface Extraction, note that its output is now exposed as a MeshSequenceOutport and its iso/color controls are based on IsoValueProperty and TransferFunctionProperty rather than a single float iso value plus per-surface color properties.
