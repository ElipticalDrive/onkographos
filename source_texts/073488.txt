I need more information about Luisa's shaders and how the core calculates the shaders so I can add the necessary part to the core if it needed.
Currently, the surface shaders are derived from a base class Surface defined in https://github.com/LuisaGroup/LuisaRender/blob/next/src/base/surface.h. There are some main components:
Surface itself is a scene node that just records properties from the scene definition file.
Surface::build() generates a Surface::Instance, which creates resources like textures or LUTs on the GPU.
During rendering, Surface::Instance::closure() evaluates textures and other shader parameters and generates a Surface::Closure.
Surface::Closure can be used to evaluate the BSDF for a pair of input/output directions and sample for a now incoming direction.
All derived shaders are implemented under https://github.com/LuisaGroup/LuisaRender/tree/next/src/surfaces and matte.cpp might be a good starting point for you to understand how to write a surface shader.
For volumetric shaders, we currently do not have a specific design but I guess it should be much like the surface shaders.

Hi, @OmidGhotbi
Very excited to see these beautiful results and thank you so much for your efforts!
Here are my answers to your questions:
I notice changing aperture will not affect the brightness or light volume.
1- Is it the normal behavior in LC, or I making a mistake?
Yes, this is the expected behavior by design. The aperture parameter of the thin-lens camera only affects depth of field, not exposure.
2- Is there any exposure controller that I can use to change Gamma, Brightness, etc?
Currently, the Color film supports setting exposure as shown below:
```
"film": {
    "impl": "Color",
    "prop": {
        /* other properties */
        "exposure": -0.76 // or a per-channel list like [-0.76, -0.76, -0.76]
    }
},
```
The output is always in linear sRGB. That said, it should be relatively straightforward to add more image controls or tone mapping options, similar to what's implemented in the Display film.
3- Does it make sense to add an option for cut out near or far fog in the scene?
Yes, I think it definitely makes sense. It would give users more control and might also reduce some computation.
Cheers!

```
cmake --build build --config Release
```
