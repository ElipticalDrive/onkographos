You are right--the number of values in a block equals 4^d, where d is the number of dimensions. So a 4D block consists of 4^4 = 256 values. However, I'm not sure this is relevant to your main question.
Although the C interface allows you to compress lower-dimensional "slices" of a higher-dimensional array via strides, the numpy API does not directly expose such functionality. If some dimensions are not smooth, then they should not partake in compression, and you need to slice your numpy array yourself. This means you would have to make multiple compress_numpy() calls to compress the whole array as you iterate over lower-dimensional slices.
There are also more advanced tricks you could exploit by reshaping your array and setting ndarray strides. If the number of values along each smooth dimension is a multiple of four, then it is possible to trick zfp into compressing multiple 2D slices as a single 3D (or 4D) volume, for instance. I can provide more details but would need to know a bit more about your specific problem. Which dimensions are smooth, what are the array dimensions, how is the array ordered (e.g., C vs. Fortran order), and is the array contiguous?
