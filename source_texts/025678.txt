# Abstract

Meshes are used in a variety of applications to specify the three dimensional (3D) shapes of objects in simulated scenes. For example, a mesh can be used as an animal in an animation movie, a soldier in a video game, or a bulldozer in a simulation application. A straightforward way of creating a mesh is to modify an existing mesh. Although several mesh modification algorithms exist, there is a need for an algorithm that constructs a mesh from any combination of existing meshes and simple geometric shapes (called primitives) according to a list of user commands. When visualized, the resulting mesh should have a smooth (i.e. not blocky) surface.

We propose the Revo method for constructing meshes from any combination of existing meshes or primitives according to user commands. The commands required to construct a specific 3D mesh should be determined by an artist. First, the Revo method generates a volumetric representation of each input mesh or primitive. To do so, for each input mesh, it imposes a 3D grid called a volumetric grid on the portion of the 3D world that contains the mesh. Revo may apply some transformations to an input mesh to ensure that it is completely enclosed by the volumetric grid. A distance field is used to approximate the input mesh in the volumetric grid. Similarly, each required primitive is constructed in a volumetric grid to yield a distance field. A series of distance-based operations, such as union, intersection, and subtraction, are used to combine the distance fields according to the user commands. Finally, Revo extracts the implicit surface from the resulting distance field and constructs a mesh.

Using a larger volumetric grid results in more accurate volumetric data. However, it makes the process slower and the generated mesh more complex. The characteristics of the input meshes, such as the number of triangles, also affect the performance of Revo. # Chapter 1 Introduction

This thesis considers the problem of constructing a mesh from any combination of existing meshes and simple geometric shapes (called primitives) according to a list of user commands. When visualized, the resulting mesh should have a smooth (i.e. not blocky) surface.

A polygon mesh (or more simply hereafter a mesh) is a 3D geometric representation that specifies the shape of an object in a simulated scene. For example, a mesh can be used as an animal in an animation movie, a soldier in a video game, or a bulldozer in a simulation application. Figure 1.1 shows the difference between a mesh and a model, as the terms are used in this thesis. The mesh contains only the geometric information about the model, whereas the model contains the mesh plus all other information required to render (draw) the model, including the surface texture. As shown in Figure 1.1a, a mesh is typically represented as a collection of vertices, edges, and faces. The faces may be triangles, quadrilaterals, or other polygons. However, simple polygons such as triangles and quadrilaterals are almost always used, since they simplify the rendering process. In this thesis, we restrict attention to triangular meshes, since they are the most common [10].

Creating a 3D mesh can be a challenging and time-consuming task because literally



Figure 1.1: Example of (a) a 3D mesh and (b) a 3D model (taken from [2])

thousands of polygons must be precisely located. Three major techniques for creating meshes are using a 3D scanner on an existing object to capture detailed data about its shape [69], using mesh modification techniques, and creating a mesh from scratch by performing patch modeling [58] or image based modeling [61]. Digital artists use special purpose software, such as Maya and ZBrush, to employ these techniques to create meshes.

Mesh modification approaches are the most relevant to this thesis. Box modeling [77], digital sculpting [77], and primitive modeling [77] are examples of mesh modification techniques. Box modeling is a fast technique for creating a low-poly mesh (i.e. a mesh with a relatively small number of polygons). With this technique, the modeler starts with a primitive, usually a box, and extends it to create the desired mesh. With digital sculpting, the modeler uses a tool similar to brush to modify a base mesh and create a new mesh. The base mesh could represent a primitive or a more complex object. Primitive modeling refers to the modeling techniques that create a mesh by combining primitives such as box and sphere. Constructive Solid Geometry [64] and Constructive Volume Geometry [14] are examples of primitive modeling.

Here, we emphasize mesh construction approaches that use a volumetric representation of the 3D mesh commonly called a voxel representation. A voxel is a 3D grid element that occupies a single unit of three dimensional space. In some applications, such as video games and simulations, voxelized meshes are used for shape matching (e.g., collision detection), visibility processing (e.g., ambient occlusion and global illumination), rapid prototyping design (for 3D printing or laser sintering), and 360 degree display.

A voxel representation of a mesh is derived via a process called voxelization. Usually, the process of voxelization classifies each voxel as being either inside or outside of the mesh and generates a binary voxel representation. Such representations are frequently used in computer graphics applications. In a binary voxel representation, a 3D region is represented by a 3D array of bit values. A bit value is 1 if the corresponding region of space is part of the mesh and 0 otherwise. Ordinarily each region of space is a cube. When a binary voxel representation of a mesh is rendered, the visualized object is a blocky mesh, even if a fine grid is used for voxelization, as shown in Figure 1.2. In the figure, the size of the voxels is progressively decreased from left to right.



Figure 1.2: A binary voxel representation results in a blocky mesh (taken from [63])

We introduce the Revo mesh construction algorithm that utilizes a volumetric grid to create a desired mesh from any combination of existing meshes and primitives and a specified list of operations.

First, Revo voxelizes each mesh to produce volumetric data in the form of a distance field, i.e., a 3D array of floating point numbers representing distances. Revo also constructs distance fields to represent any primitives. Secondly, Revo uses distancebased operations to combine the distance fields according to the list of commands. Thirdly, it uses the standard Marching Cubes algorithm to generate the desired mesh from the resulting volumetric data. Since the distances are calculated accurately, Revo not only determines whether or not the mesh intersects a voxel but precisely where in the voxel the intersection occurs. This precise information allows Revo to generate an output mesh with a smooth surface.

#### 1.1 Motivation

Meshes are commonly used in computer graphics applications to represent 3D objects [9]. A mesh can represent almost any kind of a 3D object in a simulated scene. One of the main advantages of using meshes is that they are efficient for rendering. A polygon mesh can be rendered faster than a non-polygon mesh on a modern graphics card [60].

Mesh modification techniques are widely used for creating 3D meshes. Creating a mesh by modifying a given mesh may require significantly less effort than creating the same mesh from scratch. By using the idea of mesh modification, it is possible to create a new mesh by applying a series of operations to a given mesh.

Among mesh modification approaches, we are motivated to study those based on volumetric representations because such representations have several desirable features.

First, a volumetric representation can describe both the surface and the interior structure of 3D objects, in contrast to surface-based approaches, which can only represent the surface of 3D objects [28].

Secondly, volumetric data can contain detailed information about visual or physical properties of the surface and interiors of objects. Each voxel can be represented by a single sampled value or more complex data. For example, color, transparency, density, material properties, etc. can be associated with each voxel. Encoding many attributes for each voxel, makes it possible to model complex materials, structures, and behaviors [28].

Thirdly, the properties of volumetric data allow the use of flexible data models for volumetric scenes. For example, several values may be assigned to a particular voxel while no value is associated with its neighbor. In addition, a value can be shared among a group of voxels. Volumetric data can be sampled on a regular grid, an irregular grid, or at scattered points. The stored values can be scalar or vector quantities [28]. Using regular grids is the most common approach for volumetric representation. However, when the scene contains large transparent areas, octrees can be used to encode the values more efficiently [20].

Fourthly, volumetric representations have the potential to provide effective collision detection, i.e., detecting intersections (overlapping) between objects. Collision detection is an important requirement in computer graphics applications such as simulation and video games. It is generally performed more frequently than other operations in such software [28].

Volumetric representations work well in some existing game engines. Frostbite [3] and Atomontage Engine [1] are examples of game engines that take advantage of volumetric representation and volumetric rendering. In the Frostbite game engine, a set of techniques and optimizations are used to form a physically based volumetric rendering framework. Volumetric shadows and volumetric intersection between light and particles are example of volumetric features in the Frostbite game engine.

Unfortunately, existing voxel-based approaches are limited in their effectiveness. For a voxelized object in a 3D grid, we only know whether a voxel is inside or outside the object. We do not know the precise parts of space within that voxel that are occupied by the original object. Therefore, the quality of any voxel-based collision detection algorithm will be limited by the size of the voxels in the grid, i.e., the smaller they are, the more accurate the collision detection and resolution will be. Similarly, visualization with some scheme is limited by the size of the voxels. Using a direct visualization technique, such as ray tracing, to render a voxelized object results in a blocky surface as shown in Figure 1.2. Although using an indirect visualization techniques, such as Marching Cubes algorithm, generates a mesh with smoother surface, the constructed mesh approximates the original mesh with a large error. Deficiencies in current voxel-based approaches provide motivation for investigating a volumetric approach that works independently of the size of the voxel.

#### 1.2 Problem Statement

As mentioned earlier, this thesis addresses the problem of constructing 3D meshes using as input any combination of existing meshes and primitive geometric objects. Examples of primitives include spheres, cubes, cones, etc. Existing constructive methods, such as Constructive Solid Geometry, Constructive Volume Geometry, and Indirect Constructive Volume Geometry, have been used to create complex models by combining primitives through a series of Boolean operations, such as union, intersection, and difference. However, these methods do not accept 3D meshes as input.

We consider an approach to this problem that makes use of a signed distance field as an intermediate representation. As explained in detail in Chapter 2, for a given resolution N, the proposed distance field is a 3D grid of floating point numbers with N + 1 numbers along each dimension. The grid represents a local cube-shaped 3D space with grid points distributed at regular intervals along the three dimensions. The sign of each number in the distance field tells whether the corresponding grid point in the local 3D space is inside (negative) or outside (otherwise) the nearest object. The magnitude of each number tells the distance from the corresponding grid point to the nearest part of the surface of an object. An implicit parameter called the scale gives the ratio between a value in the distance field representing the distance between two neighboring grid points and the distance in the local 3D space between the same grid points. For simplicity, we assume that the scale is 1, indicating that the unit length for a distance in a distance field is the same as the side length of a voxel in the local 3D space.

We consider four sub-problems, which can be stated simply as follows:

- 1. Given an input mesh, construct a distance field that represents the mesh.
- 2. Given a primitive, construct a distance field that represents the primitive.
- 3. Given a Boolean operation (intersection, union, or difference) and two distance fields, construct a distance field representing the result of combining the two distance fields using that operation.
- 4. Given a distance field serving as volumetric data corresponding to a 3D scene containing one or more objects, produce an output mesh that represents all objects in the scene.

As described in Chapter 2, recent research by others [14, 46, 62, 64] has addressed the second and third problems. However, no previous solution exists for the first problem and adaptation of existing work is needed to solve the fourth problem.

Let us consider the first sub-problem in more detail. When converting a mesh to volumetric data, it is crucial to be able to determine whether a given location is inside or outside of the object. Here, we limit attention to watertight meshes, i.e., the input mesh does not have any cracks or holes. For watertight meshes, this information can readily be determined. Likewise, many existing meshes contain only triangles, while others contain more complex polygons, such as quadrilaterals. Here, we limit attention to triangular meshes. Thus, in this thesis, the input mesh is assumed to be a watertight, triangular mesh.

A detailed problem statement for the first sub-problem is as follows: Given a watertight triangular mesh M and a resolution N, create the corresponding (N + 1) × (N + 1) × (N + 1) distance field D. Suppose that mesh M is defined in a local coordinate space such that for all vertices (x, y, z) in mesh M, xmin ≤ x ≤ xmax, ymin ≤ y ≤ ymax, and zmin ≤ z ≤ zmax. We define the largest range n as max(xmax − xmin, ymax − ymin, zmax − zmin). The transformed mesh should fit in the volumetric grid without touching the edges, so it should be mapped to at most N − 1 of the voxels. We define a transformed local space of size N × N × N by applying function f to every x, y, and z coordinate of a vertex in the mesh, where f(r) = (r − rmin) ∗ (N − 1)/n + 0.5 and r is a meta variable representing x, y, or z. Since the scale is 1, each grid point (i, j, k) for integer i, j, and k in the distance field corresponds to location (i, j, k) in the transformed local 3D space. The value stored at location (i, j, k) in the distance field D gives the signed distance in the transformed local space from the corresponding grid point to the nearest surface of the mesh.

With respect to the second sub-problem, previous research on distance-based modeling has defined algorithms for constructing distance field representations of common geometric primitives [62]. As with the first sub-problem, the methods require information about the resolution N. The scale is assumed to be 1 and thus the corresponding local 3D space is of size N ×N ×N. A primitive may require parameters, such as radius (for spheres) and the side length (for cubes). Any space outside of the primitive is assumed to be empty.

For the third sub-problem, which involves combining distance fields, we consider the Boolean operations defined by previous research on distance-based modeling, namely union, intersection, and subtraction [62]. Combining two distance fields is more complicated if the distance fields have different scales or different resolutions, or if the local 3D spaces that they represent are not co-located. In general, when combining one might want to translate, rotate, and scale. To ensure that two distance fields with different resolutions can be combined together; we restrict interest to distance fields with a scale of 1, i.e., we consider the length of a voxel in the both local transformed spaces to be 1. Thus, a distance field of resolution N always represents a local 3D space of size N × N × N. We furthermore restrict attention to cases where the translation for each distance field can be specified as an offset of V = (i 0 , j0 , k0 ) where i 0 , j 0 , and k 0 are integers. The restricted problem is as follows: Given a Boolean operation B (intersection, union, or subtraction), an output resolution N3, two distance fields D1 and D2 both with scale 1 but with resolutions N1 and N2, respectively, and offsets V1 and V2, respectively, combine them using the specified Boolean operation to yield a distance field D3 of resolution N3. In order to perform a Boolean operation it is assumed that the origin occurs at the center of each local 3D space defined by a distance field (prior to applying any offsets). Finally, we restrict attention to cases where neither rotation nor scaling is required.

The fourth sub-problem addresses the process of constructing a mesh given a distance field. The goal is to construct a mesh that is visually correct when rendered, and in particular, it should have a smooth (i.e. not blocky) surface. The accuracy of the locations of the vertices of the mesh should not be limited to the voxel size in the volumetric representation. In particular, the error in their locations should be less than 1% of the length of a voxel.

Two techniques are available for assessing the effectiveness of algorithms for the above problem. First, the output mesh can be rendered and displayed, and then the visual appearance of the result can be evaluated. Secondly, the accuracy of the combined solutions to the first and fourth sub-problems can be assessed by taking an input mesh, constructing the corresponding volumetric data in the form of a distance field, and then creating a separate output mesh from the volumetric data. For this second technique, we require an algorithm that compares two meshes. Here, we restrict attention to comparing the mean-root-square of the distances from vertices in the input mesh to the surface of the output mesh. Since the algorithm compares two meshes, it is independent of the type of the volumetric data used as an intermediate representation.

#### 1.3 Outline

The remainder of this thesis is organized as follows. In Chapter 2, we review background research relevant to the primary contributions of this thesis. This chapter includes a review of techniques used to generate volumetric representations of 3D meshes. Previous work on distance fields, including the definition of a distance field and a signed distance field, is also described. Direct and indirect volume rendering, as well as some visualization methods, are described. Several techniques for constructive geometry are explained, as well.

Chapter 3 introduces the Revo mesh construction method, which given any combination of existing meshes and primitives and a list of operations produces an output mesh. Revo generates a volumetric representation of each input mesh or primitive. A distance field is used to approximate an input mesh or a primitive in the volumetric grid. A series of distance-based operations such as union, intersection, and subtraction, are used to combine the distance fields according to the user commands. Finally, Revo extracts the implicit surface from the resulting distance field and construct a mesh. Details of the algorithms and computations methods are provided in this chapter.

Chapter 4 presents visual and experimental results of our volumetric mesh construction approach. Some examples of mesh construction and mesh combination are presented. We evaluate the accuracy of the created volumetric data for different resolutions by comparing constructed meshes with input meshes. Also, the complexity of the constructed meshes in different resolutions is analyzed with respect to the complexity of the input meshes. The running time of our implementation is evaluated with respect to the number of triangles and the resolution.

In Chapter 5, we conclude and summarize our findings. Possible future work for optimizing the implementation of this method and extending its functionality are also described.

# Background

In this chapter we present an overview of previous work related to this thesis. We devote a section to each of the following: voxelization, distance fields, volume rendering, and constructive geometry.

#### 2.1 Voxelization

The term voxel is short for volume pixel. Analogous to a pixel, which is a single 2D image element, a voxel is a single 3D element. Often, a voxel is a 3D space 1 unit by 1 unit by 1 unit. A volumetric data set is a set of values for all voxels in some 3D space. Each value represents the value of some property relevant to that part of 3D space. Various values can be associated with a voxel, such as density, temperature, pressure, and color. The value associated with a voxel can also be a vector, such as a velocity. Volumetric data may be time-varying [42]. Organizing voxels in a 3D grid creates a volumetric grid. For example, Figure 2.1 shows a 4 × 4 × 4 volumetric grid.

Volumetric data is sometimes also defined by associating values with grid points instead of voxels in a volumetric grid. Preprocessing could be used to transform voxelbased values into grid point based values, albeit with some loss of information. So, without loss of generality, in this thesis, the grid point representation is assumed. The



Figure 2.1: A 4 × 4 × 4 volumetric grid

number of grid points for a N ×N ×N volumetric grid is (N + 1)×(N + 1)×(N + 1).

Volumetric data can be obtained by computation, sampling, simulation, or modeling techniques. For example, sample data is obtained from Magnetic Resonance Imaging (MRI), Computed Tomography (CT), functional MRI (fMRI), or Positron Emission Tomography (PET) [42].

Voxel-based representations of objects are useful in many applications. They can be used to represent material properties and other attributes of a 3D model in a video game or an animation. Since unlike meshes, they are not hollow, they can also be used for deep physical simulations of heat diffusion, fractures, and soft physics [66]. In some applications, increasing the number of polygons in the mesh makes the interaction process more expensive in terms of computing time and storage space. In such cases, alternative representations such as a voxel-based representation may sometimes be employed to achieve desired goals more effectively.

The process of converting a surface-based representation such as a mesh into a voxel-based representation is called voxelization [81]. Voxelization is applied in many applications such as volumetric modeling [78], medical imaging [59, 71, 44], haptic rendering [53], collision detection [12, 27, 35, 32], CSG operations [48] (see Section 2.4.1), visibility queries [68], 3D spacial analysis [7], terrain modeling [17], texture generation [39, 56], physically based simulation [47], and real-time rendering [22]. Voxelization generates discrete values for individual voxels, especially with respect to the question of whether a voxel is inside or outside the object, by considering the topology of the input mesh. Voxelization should satisfy the accuracy and efficiency requirements of the application. If the input mesh is continuous, then the voxelbased representation should also be continuous [36]. In such a case, the values for the attributes represent the state of the world at the center (or sometimes the lower, front, left corner) of the voxels and values at other locations are interpolated.

To voxelize an object, the size of the overall volumetric grid and the size of the grid unit (voxel) should be known. The appropriate size for a voxel depends on the application. The sizes of the three dimensions of the overall grid need to be large enough to encompass the object, but to avoid inefficiency, they should not be larger than necessary [66].

Huang et al. introduce a method for voxelizing planar objects, i.e. 2D objects in 3D space [36]. They claim that the voxelized form of a planar object S is the combination of three overlapping sets of voxels: the set of voxels that represent the vertices of S, the set of voxels that represent the edges of S, and the set of voxels that represent the faces of S. For each vertex, a bounding sphere centered at the corresponding vertex is defined. If the center of a voxel falls inside any of bounding spheres, the voxel represents the corresponding vertex. For each edge, a bounding cylinder is defined. If the center of a voxel falls inside any of bounding cylinders, the voxel represents the corresponding edge. For each face, some bounding planes are defined. If the center of a voxel falls inside the enclosed region formed by any set of bounding planes, the voxel represents the corresponding face. A linked list is used to store the volumetric data (i.e. information about voxels). If the number of voxels is increased, longer linked lists are required and the voxelization process is slower. Huang et al. extend this approach for voxelizing a 3D mesh. They claim that this

method eliminates common voxelization artifacts at edges and vertices. However, the algorithm needs to be optimized and accelerated [36].

Haumont and Warz´ee present a tool to automatically create a volumetric representation from a complete polygonal scene [34]. They use an octree data structure [34] to store the volumetric information. The tool implements an iterative two-step procedure. In every iteration, a voxel for which the status (i.e. inside/outside) can be determined uniquely, is selected as the seed voxel. In the second step, the status of the selected voxel is propagated to its surrounding voxels recursively, if they can be determined to have the same status. The procedure is repeated for different parts of the scene until the status of all voxels in the scene is determined.

Eisemann and D´ecoret describe an algorithm to voxelize the interior of a watertight object such that the watertightness property is preserved [23]. They convert a watertight object into a binary voxel-based representation where voxels are classified as inside or outside of the object. The voxels for which any part lies in the interior of the object are marked to be inside the object. The marked voxels are used to generate a solid interior for the volumetric object, i.e. the object is not hollow. The idea of this method is that for any ray leaving a point inside an object, the number of intersections with the surface of the object is odd. They take advantage of the rasterization process to accomplish voxelization. They also propose a GPU (i.e. graphics processing unit) adapted scheme to transform the binary grid into a density representation. They calculate the density at each voxel by examining the eight neighboring voxels. The calculated value is in the range [0, 8]. If the density value is zero, the voxel is outside the object. If the density value is eight, the voxel is entirely inside the object. The voxels on the boundary take values in the range [1, 7]. By dividing the calculated values by eight, they estimate the density values in the range [0, 1]. The density values can also be used to approximate the normals for the surface [23].

Dong et al. propose an voxelization method for complex polygonal meshes [19]. Their method takes advantage of the fast processing of textures provided by contemporary GPUs. They encode the volumetric data as 2D textures along three axis and store them in three buffers. The combination of these buffers represents the output in the volumetric grid. The three main steps in this approach are rasterization, texelization, and synthesis. In the rasterization stage, the triangles are rasterized to discrete voxels. Then, each voxel is encoded in a texture buffer in the texelization stage. In the last stage, the three encoded buffers are converted to a worksheet that represents the final volume. The main limitation of this method is the low quality of the voxelization, because in the rasterization stage some voxels are missing [19].

There are other techniques that take advantage of hardware capabilities to perform voxelization. Because rasterization and voxelization are similar scan conversion operations, the rasterization functionality of graphics hardware can be used to accelerate voxelization [81]. Scan conversion is the process of finding the screen pixels that intersect a polygon and it is usually considered the final step of rasterization process. Unfortunately, the standard rasterization performed on GPUs does not generate all fragments that intersect the projected polygon. This problem can be solved by a conservative rasterization algorithm [5, 33], which includes all pixels that intersect any part of the object rather than only pixels that are completely inside the object. Accurate voxelization is crucial for some applications such as, collision detection, occlusion culling, and visibility processing. For example, in collision detection, it guarantees that the collision is detected correctly [81]. Zhang et al. provide a GPUbased algorithm for triangular meshes. If the input is an arbitrary polygonal mesh, it is first tessellated into a triangular mesh. They claimed that their approach correctly identifies every voxel that intersects the input mesh [81]. Also, Karabassi et al. propose a voxelization algorithm that uses the z-buffer to create the volumetric data rapidly. Although, the algorithm does not create accurate volumetric data, it works for both polygonal and analytical objects [40]. Another GPU-based approach is proposed by Fang and Chen for voxelizing curves, surfaces, solids, and volumetric CSG objects [24]. Also, Llamas uses a GPU implementation to do real-time voxelization of triangular meshes [49].

#### 2.2 Distance Fields

A distance field is a scalar function which for each point p in the domain gives the minimum distance from that point to the closest point on the surface of any object in the domain. A distance field can be signed or unsigned. When it is signed, the sign indicates whether or not the query point p is inside the nearest object.

Perhaps the earliest usage of distance fields was in 1966 in image processing [38, 67]. Later, distance fields were used broadly in computer vision for image processing, in physics for wavefront and Eikonal equation solving schemes, and in computer graphics for object representation and processing. Distance fields have also found many applications such as collision detection and mesh topology correction [38] in volume graphics, i.e., the study of representing objects with a set of voxels [41]. They are also useful for physics simulations [72].

#### 2.2.1 Signed Distance Field Definition

A signed distance field is a combination of a distance function and a sign function. Thus, the signed distance field for object S can be defined as a function fS that returns the shortest distance from point p to the surface of object S

$$f_S(p) = \text{sign}(p, S) \cdot \text{dist}(p, S), \quad (2.1)$$

where sign(p, S) is a sign function that yields negative if p is inside object S and positive otherwise and dist(p, S) is a distance function that yields the distance from p to the surface of S. These functions are defined as follows:

$$dist(p, S) = \inf \left\{ \|x - p\| : x \text{ is a point on the surface of } S \right\} \quad (2.2)$$

and

$$\text{sign}(p, S) = \begin{cases} -1, & \text{if } p \in S; \\ 1, & \text{otherwise.} \end{cases} \quad (2.3)$$

where inf denotes the infimum.

Discrete distance fields can be generated by sampling a continuous distance field or by computing the distances directly for each point in the field. For the remainder of this thesis, we assume that every distance field is discrete. As mentioned in Chapter 1, a distance field of resolution N contains (N + 1) × (N + 1) × (N + 1) values.

#### 2.2.2 Computing Distance Fields

To construct a distance field (whether signed or unsigned) with respect to an object S represented as a mesh, we need to know the shortest distance between each grid point and the surface of the mesh. Since the surface of a mesh is composed of triangles, the distance between a point p and the surface of a mesh is defined as the distance between p and the closest point on one of the closest triangles in the mesh.

A brute-force algorithm for computing one such shortest distance is to calculate the distance from point p to every triangle in the mesh and then choose the smallest distance. For n points and m triangles, this approach requires that the distance between a point and a triangle be determined nm times. For simple meshes with few faces, this approach may be sufficiently fast. However, for large meshes with many faces, this approach is too slow for many applications. For example, to generate the distance field as a 256×256×256 grid for a mesh with one million triangles, the total number of distance calculations is 2563 × 106 ≈ 1.7 × 1013 .

We note that signed distance fields can only be generated for closed, orientable 2-manifold meshes. If a mesh belongs to this class, a distance field can be constructed that correctly classifies every point in the space as interior or exterior to the mesh [38].

Some efficient algorithms have been developed for computing the distances in a distance field. The two most relevant types are the hierarchical and the characteristics approaches [38].

#### Hierarchical Approaches

With a hierarchical approach for computing a signed distance field, all triangles in a mesh are organized in a hierarchy (some types of tree) in such a fashion that only some of the triangles need to be examined to determine the closest triangle to a given point.

Using a hierarchical approach compared to a brute-force approach can speed up the computation of the signed distance field. For instance, using a hierarchical data structure may decrease the computational complexity from O(nm) to O(n log m), where n is the number of grid points and m is the number of triangles [38].

Payne and Toga propose a basic approach for organizing and calculating distances to triangles in a hierarchy [57]. They store the triangles in a tree of bounding boxes. At every level, each bounding box encloses all its child bounding boxes at the more detailed level. A bounding box is allowed to overlap its sibling nodes to ensure that each triangle is completely inside a bounding box at each level. With this tree, it is possible to calculate the smallest and the greatest possible distance for any triangle inside a bounding box from a fixed point in space. This property can be used to prune the tree. Since we are interested in shortest distances, a branch can be pruned if its smallest distance is greater than the greatest distance of another branch.

by simplifying the geometry of the mesh. It organizes the bounding volumes in a multiresolution hierarchy. The hierarchy is used to compute the distance from a point to the mesh. At every level, each bounding volume encloses all its child bounding volumes at the more detailed level. The algorithm is dynamic and it can be used for a mesh that deforms.

#### Characteristics Approaches

The main idea of characteristics approaches for finding the minimum distance between a grid point and the surface of the mesh is to make the influence of each triangle on the surface local by eliminating the grid points that are farther from the plane of the triangle than a given distance.

Since we are potentially interested in all combinations of grid points and triangles, it is effective to examine all triangles but restrict attention to grid points up to a certain distance from the surface of triangles [38]. If the maximum distance is d, we can limit the distance calculations to the grid points that are at most a distance of d from the surface.

Dachille et al. propose using an axis aligned bounding box for each triangle [18]. Thus, distances are calculated only for grid points that are inside the bounding box around each triangle.

Mauch presented an approach whereby a characteristic (i.e. polygon or polyhedron) is constructed for each feature (face, edge, vertex) in a triangle that contains the closest points to the feature [51]. A special kind of polyhedron serves as a bounding volume for each feature. For instance, a prism bounds a face, a wedge bounds an edge, and an n-sided cone bounds a vertex. Figure 2.2 illustrates these three types of characteristics. Since a characteristic can be considered to be a Voronoi region [38], by constructing the characteristics for a triangle, the closest feature of the triangle to every grid point is determined. For each grid point in a characteristic, the distance

to the corresponding feature of the triangle is calculated. The distance from a grid point to the closest feature of the triangle is the shortest distance from the grid point to the triangle.

Sigg et al. proposed making the computation faster by using the graphics hardware to perform scan conversion on the characteristics [70]. Another hardware acceleration approach was devised by Sud et al. [73]. They claim that their method is applicable to all geometric objects without any assumptions about connectivity or a manifold representation.

#### Sign Computation

In sign computation, all grid points in a volumetric grid are classified as inside or otherwise (on the surface or outside). If a grid point is inside the object, its sign is negative, while if it is outside the object, its sign is positive. If a grid point is on the surface, it is arbitrary assigned a positive sign. In this case, since its distance from the surface is zero, the sign does not make any difference in the calculations. Overall, for each grid point p, we want to determine its sign. Three known methods are scan conversion, ray casting, and vector calculation.

Scan conversion is one of the methods for computing sign values on graphics hardware. For each z plane in the grid (i.e. a plane parallel to x-y plane) the intersection of the object and the plane is computed. Then scan conversion is performed. If the scan line (i.e. a line of constant y value) crosses the object an odd number of times, the cell is inside; otherwise, it is outside [38, 57].

Ray casting is a simpler method for sign generation. In this method, rays are cast along a row of the grid. If a ray started from a grid point has crossed the object an odd number of times before reaching the edge of the grid, the point is inside the object; otherwise, it is outside [38].

The vector calculation method is more complex than the other two methods. Logically, a grid point p must be closest to the face of the triangle, one of its vertices, or one of its edges. If the nearest point is on the face of a triangle, then a simple method based on surface normals can be used. To find the sign of point p, the dot product of two vectors is evaluated. The first vector is the surface normal, ~n of the face. The second vector is a direction vector ~v from the closest point on the surface to the point p. If both ~n and ~v point in roughly the same direction, then p is outside and if ~n and ~v point in roughly opposite directions, then p is inside. If the angle between two vectors is less than 90°, they are considered to be in roughly the same direction and if the angle is greater than 90°, they are considered to be in roughly opposite directions.

The dot product of two vectors can be used to evaluate the directions of the vectors. If the dot product of two vectors is negative, then the angle between them is greater than 90°, if the dot product is positive, then the angle between them is less than 90°, and if the dot product is zero, then the angle between them is 90°. This property can be easily derived from the definition of the dot product. The dot product of two vectors ~v1 and ~v2 is defined by

$$\vec{v}_1 \cdot \vec{v}_2 = |\vec{v}_1| |\vec{v}_2| \cos \theta \quad (2.4)$$

where θ is the angle between ~v1 and ~v2. If θ > 90° then cos θ < 0 and the dot product is negative. If θ < 90° then cos θ > 0 and the dot product is positive.

| $\theta < 90 \rightarrow \cos \theta > 0 \rightarrow v_1 \cdot v_2 > 0$ |  |  |  |  |       |
|-------------------------------------------------------------------------|--|--|--|--|-------|
| $\theta > 90 \rightarrow \cos \theta < 0 \rightarrow v_1 \cdot v_2 < 0$ |  |  |  |  | (2.5) |
| $\theta = 90 \rightarrow \cos \theta = 0 \rightarrow v_1 \cdot v_2 = 0$ |  |  |  |  |       |

As shown in Equation 2.5, if θ = 90°, then cos θ = 0 and the dot product is also zero. This case does not occur in the sign computation process as explained shortly.

Let c be the closest point on the flat surface to the point p where the sign is desired. Let ~n be the flat surface normal at c and let ~v be the direction vector from c to p. If the dot product of ~n and ~v is zero, then they are perpendicular. This means that the normal vector ~n is perpendicular to both the surface and vector ~v. Because ~v is perpendicular to ~n and it starts at c, which is a point on the surface, ~v lies on the surface. Therefore, point p, which is the head of the vector ~v, lies on the surface as well. If p is on the surface, then its distance from the surface is zero and no sign calculation is needed.



Figure 2.3: A shared vertex is the closest point on the surface, and the signs of ~v · ~n1 and ~v · ~n2 are different (adapted from [38])

If the point p is nearest to an edge or a vertex of the triangle rather than a face, the method based on normals is not suitable because the normal is not defined on edges and vertices. The simplest solution is to use the normal of the incident triangles. Unfortunately, this approach does not always work, because it may happen that two or more triangles have the same distance to p and the normals of these triangles generate different signs. For example, when a shared vertex is the closest point on the surface, as demonstrated in Figure 2.3, the normals of different triangles produce different signs.

We consider three approaches: naive, area-weighted, and angle-weighted.

A naive approach to this problem is to approximate the normal for edges and vertices. The average of the normal of the incident triangles can be used as the pseudonormal for a vertex [29]. If k triangles share one vertex, the approximated normal N~ A at the vertex can be calculated by

$$\vec{N}_A = \frac{\sum_{i=1}^k \vec{N}_i}{k} \quad (2.6)$$

where N~ i is the normal for incident triangle i. Although this approach is simple, it does not guarantee that the normal will have a positive dot product with the direction vector ~v whenever the point is outside the object and negative dot product whenever the point is inside. In Figure 2.4a, the normal N~ A is the average of the normals of the adjacent triangles. By changing the tessellation of one triangle, the resulting normal is changed, as shown in Figure 2.4b. However, the shape is the same.



Figure 2.4: Changing tessellation affects the average of the normal of the incident triangles (adapted from [26])

To overcome this problem, the normals should be weighted in some fashion to result in an appropriate pseudonormal vector. There are several approaches for weighting the normals, but not all of them work for both an edge and a vertex. Two weighting schemes that can be used to evaluate the pseudonormal for both an edge and a vertex are weighting by the area of adjacent triangles [52] and weighting by angle [75]. The area-weighted normal algorithm incorporates the area of the triangle formed by the two edges of each facet incident on the vertex. The area is given by the absolute value of the cross product of the two edges. Therefore, the pseudonormal N~ A is calculated by

$$\vec{N}_A = \frac{\sum_{i=1}^k \vec{N}_i |E_i' \times E_i''|}{\left\| \sum_{i=1}^k \vec{N}_i |E_i' \times E_i''| \right\|} \quad (2.7)$$

where Ei 0 and Ei 00 are two edge vectors of the ith facet sharing the vertex. For a vertex, the area of k incident triangles is used and for an edge, the area of two adjacent triangles is used.

Figure 2.5a shows that using the area-weighted normal solves the problem caused when the pseudonormal is calculated by the average. However, if we change the tessellation as shown in Figure 2.5b, the area-weighted pseudonormal will change, even though, the shape is unchanged.

Th¨urmer and W¨uthrich propose using the angle-weighted pseudonormal. One advantage of using the angle-weighted pseudonormal is that it is independent of tessellation [75]. In other words, we can change the tessellation without affecting the resulting normal. More importantly, it has been shown that the dot product of the angle-weighted normal NA and the vector ~v, from point c on the mesh to point p, is always positive if p is exterior to the mesh and negative otherwise [4, 6]. This property guarantees that the angle-weighted normal yields the correct signs when used for computing signed distance fields.

The angle-weighted normal for a vertex is computed by

$$\vec{N}_A = \frac{\sum_{i=1}^k \alpha_i \vec{N}_i}{k} \quad (2.8)$$

where αi is the angle between Ei 0 and Ei 00 (as in Equation 2.7). To calculate the normal for an edge, the same equation is used but the normals of the two adjacent triangles are weighted by π. #### 2.3 Volume Rendering

Volume visualization or volume rendering is a method for extracting information implied in volumetric data and visualizing it as an image. Rendering techniques are classified as either direct or indirect techniques.

#### 2.3.1 Direct Volume Rendering

In direct volume rendering or direct visualization, the visualization is done directly from the volumetric data and no intermediate representations are computed. Thus, voxels are mapped directly to pixels of a 2D image plane. Due to numerical complexity, direct volume rendering is expensive for interactive display.

Direct visualization can combine several characteristics of the data into a global representation. Each attribute can be treated as a separate partially transparent layer and the user can decide how each layer of the object should be visualized. Depending on the degree of transparency, the resulting image may highlight different characteristics of the data. A good example of direct volume visualization is an MRI image, which provides a three-dimensional view of the organs, muscles, and joints of a body.

In direct volume rendering, the voxels are projected onto a 2D image plane, in visibility order. The final value for each pixel is incrementally composed the value of the voxels which are visited during projection process. The projection can be done along different angles. Two straightforward techniques for direct volume rendering are ray casting and texture slicing [13]. With ray casting, the final value for one ray is calculated at a time. However, with texture slicing, the values for the rays in one slice are calculated simultaneously. Figures 2.7a and 2.7b show the overview of ray

casting and texture slicing, respectively. Ray casting is appropriate for CPUs, while texture slicing takes advantage of the hardware functionality present in GPUs.



Figure 2.7: Direct volume rendering techniques (taken from [13])

#### 2.3.2 Indirect Volume Rendering

Indirect volume rendering or indirect visualization performs visualization of volumetric data by first computing an intermediate representation and then performing visualization from the intermediate representation. Here we consider only isosurface extraction techniques, where the intermediate representation is a model of a surface called an isosurface. An isosurface is a surface that represents points with a constant value. In other words, any point p on the isosurface satisfies

$$F(p) = \alpha$$

where F is a scalar function on R3 and α is a constant called an isovalue. Given the volumetric data and an isovalue, points with values equal to the given isovalue are found and the surface corresponding to that isovalue is extracted. Based on the chosen topology (i.e. wireframe or tessellation) of the desired visual form, the isosurface is approximated by polygons. The best-known method for surface extraction from volumetric data is the Marching Cubes algorithm [50], which creates a triangular mesh that approximates the desired isosurface.

#### Marching Cubes

The Marching Cubes algorithm was introduced by Lorensen and Cline [50], for generating a mesh located roughly along an isosurface extracted from a 3D volumetric grid. It takes a regular scalar volumetric data set and an isovalue as input and approximates the isosurface by a mesh. If another surface is required based on another isovalue, the algorithm must be run again.

The algorithm processes the volumetric data set in a sequential manner. It treats every set of eight neighboring grid points in the volumetric grid as an imaginary cube (see Figure 2.8). Then, it locates the surface in every cube using a divide and conquer approach. Marching Cubes iterates through all possible cubes in the volumetric data and detects cubes that contain parts of the surface. It constructs a small number of triangles for each cube that represent the part of the surface that passes through that cube. The collection of all triangles forms a mesh that represents the desired isosurface.





Figure 2.8: Illustration of a cube formed by eight neighboring grid points

To determine how the surface intersects a cube, the algorithm classifies the vertices of the cube, as inside or outside the surface. If the associated value for a vertex is greater than the given isovalue, then the vertex is inside the surface. If the associated value is less than the given isovalue, then the vertex is outside the surface. The surface intersects those cube edges where one vertex is exterior and another one is interior to the surface. Since each cube has eight vertices and each vertex can be either inside or outside the surface, there are 256 (28 ) possible ways the surface can intersect a cube. Although various symmetries of a cube can be considered to reduce the number of cases, in practice it is preferred to deal with all 256 cases.

One can store the information about the 256-entry intersection topologies, i.e. how the surface may intersect a cube, in a lookup table built offline before running the algorithm. Using this lookup table makes the computations efficient.

The vertex numbering shown in Figure 2.9a can be used to create an index for each case based on the state of the vertices. The state of a vertex is a Boolean value with value 0 if the vertex is outside the object and value 1 otherwise. Lorensen and Cline [50] calculate a unit normal vector at each vertex of the cube using central differences. Then linear interpolation is used to estimate the normal at the intersection points. These normals can be used by a rendering algorithm to produce Gouraud-shaded images [29]. Because the direction of the gradient is parallel to the normal vector, the gradient can be used as the normal vector for a vertex. For vertex (i, j, k) in the volumetric grid, the gradient along the three coordinate axes is estimated as follows:

$$\vec{g}_x = \frac{v_{i+1,j,k} - v_{i-1,j,k}}{\Delta x}$$

$$\vec{g}_y = \frac{v_{i,j+1,k} - v_{i,j-1,k}}{\Delta y}$$

$$\vec{g}_z = \frac{v_{i,j,k+1} - v_{i,j,k-1}}{\Delta z}$$

where ~gx, ~gy, and ~gz are the gradients along the x, y, and z axes, respectively, vi,j,k is the associated value at vertex (i, j, k) and ∆x, ∆y, and ∆z are the lengths of the edges of the cube. The standard Marching Cubes algorithm uses the density value at each vertex to find the gradient.

The Marching Cubes algorithm has been extended in various ways. Some extension algorithms targeted the input types of the algorithm. For example, Weber et al. [79] use a set of nested grids of different resolutions with Marching Cubes. They take advantage of the simplicity of the rectilinear grids with the possibility to adapt to local changes in coarser parts of the mesh. Marching Cubes also has been extended to work in a 4-dimensional space [65, 80]. Weigle and Banks [80] treat a time-varying scalar field as a 4-dimensional space. They consider time as the fourth axis. Pressure, temperature, velocity magnitude, etc., are examples of scalar quantities that may be result in time-varying scalar fields [80]. Some extensions try to minimize unnecessary operations on empty voxels to accelerate the algorithm [8, 16, 74].

Some extensions try to solve standard Marching Cubes problems. One of the problems with Marching Cubes is that seven topologies are ambiguous because they can be facetized in multiple ways [15]. Chernyaev [15] shows that there are 33 different configurations instead of 15 as used in standard Marching Cubes. Chernyaev introduces two class of ambiguity: face ambiguity and internal ambiguity. A face ambiguity occurs because of inversion symmetry [55]. This occurs when the facetization in two adjacent cubes is not consistent. #### 2.4 Constructive Geometry

Section 2.4.1 describes the main idea of the Constructive Solid Geometry algebra. The Constructive Volume Geometry algebra is discussed in Section 2.4.2. Section 2.4.3 is devoted to Indirect Constructive Volume Geometry algebra. Finally, Distance-Based Modeling is presented in Section 2.4.4.

#### 2.4.1 Constructive Solid Geometry

Constructive Solid Geometry (CSG) is a technique for rapid solid modeling in computer graphics [64]. The idea behind the CSG technique is to create complex objects through a series of so-called Boolean operations that combine well-defined simple 3D objects called primitives. Three common CSG primitives are as follows: sphere, cube, and cylinder (see Figure 2.13).



Figure 2.13: Constructive Solid Geometry primitives (taken from [46])

The union (∪) operator merges two objects into one. The difference (−) operator subtracts one object from another one. The intersection (∩) operator produces a new object that contains only the portion common to both objects. The results of applying each of the three operators to two sphere are illustrated in Figure 2.14. Union and intersection are symmetric, i.e. A ∪ B = B ∪ A and A ∩ B = B ∩ A. However, difference is asymmetric, i.e. in general A − B 6= B − A.

Using CSG operators, CSG primitives can be combined into more complex models called compound objects. A compound object is stored as a binary tree. The internal nodes of the tree represent the operators and the leaves signify the primitives. Besides Boolean operators, transformation operators such as translation, rotation, and scaling can be represented by internal nodes, as well [25]. #### 2.4.2 Constructive Volume Geometry

Constructive Volume Geometry (CVG) is a superset of CSG that operates on volumetric data [14]. CSG is not able to describe the interiors of defined objects, but CVG overcomes this limitation by working with a volumetric representation of the objects. An opacity value specifies the visibility of every point in the domain and defines a spatial object. In many applications, the opacity values can be derived from the density values. As is normal with volumetric data, the other attributes may be used to define properties of the object such as colors, reflection coefficients, etc. CVG



Figure 2.15: Constructive Solid Geometry tree (taken from [46])

includes the traditional CSG operators, adapted for volumetric data. The union, intersection, and difference operators for the opacity field are defined as follows:

union : 
$$\cup(\mathbf{o}_1, \mathbf{o}_2) = \mathbf{MAX}(O_1, O_2)$$
intersection :  $\cap(\mathbf{o}_1, \mathbf{o}_2) = \mathbf{MIN}(O_1, O_2)$ 
difference :  $-(\mathbf{o}_1, \mathbf{o}_2) = \mathbf{SUB}(O_1, O_2)$ 

where o1 and o2 are spatial objects and MAX, MIN, and SUB are the pointwise extensions of the scalar operators max, min, and sub defined as follows:

$$\begin{aligned} \max(s_1, s_2) &= \begin{cases} s_1 & s_1 \geq s_2 \\ s_2 & s_1 < s_2 \end{cases} \\ \min(s_1, s_2) &= \begin{cases} s_1 & s_1 \leq s_2 \\ s_2 & s_1 > s_2 \end{cases} \end{aligned}$$

Besides these three operators, some other operators are also defined for CVG such as blend, cap, and trim. CVG operations can also be used to combine the associated properties of the objects such as color.

#### 2.4.3 Indirect Constructive Volume Geometry

Indirect Constructive Volume Geometry (ICVG) adapts the CVG operators for indirect visualization [46]. It uses density values instead of opacity values. ICVG enables the manipulation of volumetric data. The density value of every voxel is a non-negative integer in the range [L, H], where L is the lowest possible value (equal to 0) and H is the highest possible value (equal to 255). The surface threshold S is the midpoint between L and H, i.e.

$$S = \left\lfloor \frac{H - L}{2} \right\rfloor = \left\lfloor \frac{255 - 0}{2} \right\rfloor = 127.$$

The four basic primitives defined in ICVG are cuboid, ellipsoid, cylinder, and cone. It uses virtual volume sampling functions to generate suitable volumetric representation of the primitives. All primitives are axis aligned, but their centers do not have to be aligned with the grid.

#### Virtual Volume Sampling Function

Let B~ = (Bx, By, Bz) ∈ N 3 , where N represents the non-negative integers, be the upper bound and the origin (0, 0, 0) be the lower bound on a local 3D space (similar to a volumetric grid). Any position in this local space can be represented by V~ = (Vx, Vy, Vz) ∈ N 3 , such that Vx < Bx, Vy < By, and Vz < Bz. The positions range from (0, 0, 0) to (Bx − 1, By − 1, Bz − 1). A virtual volume sampling function, f : V~ → [L, H], takes a position in the local space as input and returns a density value in the range of [L, H] as output. Since the function specifies the volume with respect to the local space, a transformation is required to relocate the resulting primitive from its local space to the world space.

#### Cuboid

The cuboid primitive is used to represent rectangular solids. Laprairie addressed two problems for defining this primitive: clipping and beveling [46]. Both problems are solved in the ICVG cuboid sampling function fcu, which is defined as follows:

|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--|
|                                                                                                                                                                                                                                                                                                                                                |  |
|                                                                                                                                                                                                                                                                                                                                                |  |

The cuboid is defined to occupy all of the local space except one layer of voxels all around the outside boundary of the space. The cuboid sampling function fcu returns L for positions that touch the boundary of the 3D space, S for positions that are one voxel away from the boundary, and H for other positions in the space. #### Ellipsoid

Spherical and some rounded objects can be represented by ellipsoid primitives. Let the desired radius be R~ = (Rx, Ry, Rz) ∈ N 3 , where 1 ≤ R~ x ≤ \$ B~ x 2 % , 1 ≤ R~ y ≤ \$ B~ y 2 % , and 1 ≤ R~ z ≤ \$ B~ z 2 % . The ellipsoid is defined to be centered around point R~ in the local space. To do so, every input position V~ is translated by −R~ . Let T~ = (Tx, Ty, Tz) ∈ N 3 be the translated position, where T~ = (V~ − R~ ). The ellipsoid sampling function fel is defined as follows:

$$f_{el}(\vec{V}) = \begin{cases} H, & \text{if } EllipsoidBody(\vec{T} + \hat{T}) < 1; \\ L, & \text{if } EllipsoidBody(\vec{T} - \hat{T}) > 1; \\ \left[ \frac{S}{EllipsoidBody(\vec{T})} \right], & \text{otherwise.} \end{cases}$$

where Tˆ = T /~ kT~k represents the unit vector in the same direction as T~ and EllipsoidBody : P~ → [0,∞] is defined as follows:

$$\text{EllipsoidBody}(\vec{P}) = \left( \frac{P_x^2}{R_x^2} + \frac{P_y^2}{R_y^2} + \frac{P_z^2}{R_z^2} \right).$$

By changing the components of R separately, a variety of ellipsoidal shapes can be created. For example, if Rx = Ry = Rz, the defined ellipsoid is a sphere.

#### Cylinder

The cylinder sampling function fcy is defined as follows:

$$f_{cy}(\vec{V}) = \begin{cases} L, & \text{if } (EllipsoidBody(\vec{T} - \hat{T}) > 1) \vee \\ & (V_y = 0) \vee (V_y = B_y - 1); \\ S, & \text{if } (V_y = 1 \vee V_y = B_y - 2) \wedge \\ & (EllipsoidBody(\vec{T} + \hat{T}) < 1); \\ H, & \text{otherwise if } EllipsoidBody(\vec{T} + \hat{T}) < 1; \\ & \left[ \frac{S}{EllipsoidBody(\vec{T})} \right], \text{ otherwise.} \end{cases}$$

where the two dimensional ellipse function EllipsoidBody : P~ → [0,∞] is defined as follows:

$$\text{EllipsoidBody}(\vec{P}) = \left( \frac{P_x^2}{R_x^2} + \frac{P_z^2}{R_z^2} \right).$$

The base of the cylinder is defined on the X-Z plane and it is a two dimensional ellipse. The sampling position height Vy is used to determine whether the position is vertically within the cylinder or not. L and S padding are applied at the vertical ends of the cylinder in the same manner as for a cuboid.

#### Cone

To define the cone sampling function, we first define ConeBody : P~ → [0,∞] as follows:

$$\text{ConeBody}(\vec{P}) = \left( \frac{P_x^2}{(R_x * h)^2} + \frac{P_z^2}{(R_z * h)^2} \right)$$

where h = 1 − Vy By − 1 linearly interpolates from 0 to 1 as Vy varies from the bottom to the top of the volume. The ConeBody function is a modified ellipse function that takes the height-dependent variable h into account. Using the ConeBody function, the cone sampling function fco is defined as follows:

| $f_{co}(\vec{V}) = \begin{pmatrix} L, \\ S, \\ H, \\ \left  \frac{S}{ConeBody(\vec{T})} \right , \text{ otherwise.} \end{pmatrix}$ | if $(V_y = 0) \vee (ConeBody(\vec{T} - \hat{T}) > 1);$             |
|------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------|
|                                                                                                                                    | otherwise if $(V_y = 1) \wedge (ConeBody(\vec{T} + \hat{T}) < 1);$ |
|                                                                                                                                    | otherwise if $ConeBody(\vec{T} + \hat{T}) < 1;$                    |

The base of the cone is an ellipse and the radius of the ellipse reduces as the positions progress up the cone. For the cone, L and S padding are only applied at the bottom of the cone.

#### ICVG Algebra

ICVG contains versions of CVG operators modified for indirect visualization. ICVG algebra limits its focus to non-negative integer values. The ICVG union, intersection, trim, and cap operations are the same as the CVG ones, except that they restrict the input and output values to discrete positive volumes. These operations are defined as follows:

| union :        | $\cup(D_1, D_2) = MAX(D_1, D_2)$  |
|----------------|-----------------------------------|
| intersection : | $\cap(D_1, D_2) = MIN(D_1, D_2)$  |
| trim :         | $trim(D_1, D_2) = TRIM(D_1, D_2)$ |
| cap :          | $cap(D_1, D_2) = CAP(D_1, D_2)$   |

where D1 and D2 represent the density value for the two objects involved in the operation and MAX, MIN, T RIM, and CAP are functions defined on scalars in the range of [L, H] as follows:

$$MAX(X_1, X_2) = \begin{cases} X_1, & \text{if } X_1 > X_2; \\ X_2, & \text{otherwise} \end{cases}$$

$$MIN(X_1, X_2) = \begin{cases} X_1, & \text{if } X_1 < X_2; \\ X_2, & \text{otherwise} \end{cases}$$

$$TRIM(X_1, X_2) = \begin{cases} X_1, & \text{if } X_1 \geq X_2; \\ L, & \text{otherwise} \end{cases}$$

$$CAP(X_1, X_2) = \begin{cases} X_1, & \text{if } X_1 \leq X_2; \\ L, & \text{otherwise.} \end{cases}$$

The defined difference operator in ICVG is different from that in CVG, such that it ensures that the values in the resulting volume are always non-negative. Three possible operators are considered for difference:

differenceA : 
$$-(D_1, D_2) = MAX(D_1 - D_2, L)$$

differenceB : 
$$-(D_1, D_2) = \begin{cases} MAX(D_1 - D_2, L) & \text{if } D_2 \geq S \\ D_1 & \text{otherwise} \end{cases}$$

difference : 
$$-(D_1, D_2) = \begin{cases} MAX(D_1 - D_2, S) & \text{if } (D_1 \geq S) \wedge (D_2 < S) \\ MAX(D_1 - D_2, L) & \text{otherwise} \end{cases}$$

The differenceA operator can produce a beveling artifact (Figure 2.17a) when

it is applied. The beveling artifact may happen because some values that are below S in the ellipsoid primitive are not visible but may affect the operation. The differenceB operator ignores these values. As shown in Figure 2.17b, it may lead to a jagged surface on the carved area of the cuboid. The difference operator does not produce any beveling artifacts and it does not generate a jagged interior surface as differenceB does.





Figure 2.17: Three possible difference operators (taken from [46])

The add, modulate, and two divide operators are also defined for ICVG. The ICVG algebra includes scalar and unary operations in addition to the binary operators. An example of a unary operator is the inverse operation.

#### 2.4.4 Distance-Based Modeling

Distance-based modeling is a form of constructive modeling where the primitives, operations, and deformation functions are specified in terms of distance-based sampling functions, which are explained shortly [62]. Quilez provides the distance-based functions for some basic primitives, as well as formulas for combining them together and building more complex shapes. He also presents some distortion functions that can be used to change the shape of objects. His approach is summarized in this section.

#### Primitives

A distance-based sampling function (abbreviated as distance function for the remainder of this section) returns a distance value for every point in the 3D space. A distance function may be defined to return either signed or unsigned values. We only consider signed distance functions, and for the remainder of this section the term "distance function" refers to a signed distance function. To define a primitive, a distance function takes a sampling position V~ ∈ N 3 , where V~ = (Vx, Vy, Vz), as input and returns a distance value as output. The range of the input is not restricted and is chosen based on the application. All primitives are centered at the origin and transformations are used to rotate, translate, and scale objects as necessary for particular applications. If the sampling position is inside the primitive, then the output of the distance function is negative; otherwise, the output is positive. A distance field is created by calling the distance function for all the points in a grid defined over the 3D space.

#### Box

The box primitive is used to represent a rectangular object in 3D space, just as a cuboid primitive is in ICVG. Let B~ = (Bx, By, Bz) ∈ R 3 such that Bx, By, Bz > 0 be the size of a box in 3D space. Every position V~ in the volume has a distance to the surface of the box. The signed distance function for defining a box primitive is shown in Algorithm 1.

Ellipsoid primitives can be used to represent spherical and some other rounded objects. Let the desired radius vector for the ellipsoid be R~ = (Rx, Ry, Rz) ∈ R 3 such that Rx, Ry, Rz > 0. The distance function for defining an ellipsoid is shown in Algorithm 2.

As with ICVG, a variety of ellipsoidal shapes can be created by using different values for the components of R. For example, a sphere can be created if Rx = Ry = Rz.

#### Other Primitives

Quilez also presented distance functions for other primitives, such as a round box, a cone, a hexagonal prism, a triangular prism, a capsule, and a toroid. He also claimed that we can define primitives that have rounded edges instead of sharp ones by using other norms than the Euclidean. In other words, we can use √n x n + y n + z n where n > 2.

#### Distance-Based Operations

Distance-based union, intersection, and subtraction operations can also be defined on distance fields. Let D1 and D2 be corresponding distance values in two distance fields that we want to combine. The union, intersection, and subtraction operations for such values are defined as follows:

union : 
$$\cup(D_1, D_2) = \min(D_1, D_2)$$

intersection : 
$$\cap(D_1, D_2) = \max(D_1, D_2)$$

subtraction : 
$$-(D_1, D_2) = \max(-D_1, D_2)$$

# Approach

In this chapter, we present a new, practical, volumetric mesh construction method named Revo for creating a triangular mesh in a voxel-based computer graphics application. We use volumetric data in the form of distance fields as intermediate representations of 3D objects. Distance-based operations (see Section 2.4.4) are utilized for combining the distance fields according to user commands. The standard Marching Cubes algorithm (see Section 2.3.2) is used to extract the isosurface from volumetric data and construct the corresponding mesh.

Algorithm 5 shows the general outline of the Revo method. In Algorithm 5, S is an input parameter that specifies the sizes of the M, Res, and Off lists. Since each Boolean operation is applied to two distance fields, the size of Op is equal to S−1. As shown in Algorithm 5, the first mesh or primitive is converted to a distance field and then, after being translated by the given offset, it is directly copied to DO without performing any operation. Then, for each remaining mesh or primitive in the M list, it is converted to a distance field and then, after being translated by the given offset, it is combined with the current DO using the specified Boolean operation.
