Summary
As shown in the PBRT book for homogeneous media, if we sample a distance in a randomly chosen channel (R, G, or B), the total PDF (probability density function) is given by the average of the transmittances in all channels. That is because a distance t can be chosen either in channel R, channel G, or channel B, so the PDF is:
(PDF of channel R * PDF of distance t according to R) + (PDF of channel G * PDF of distance t according to G) + (PDF of channel B * PDF of distance t according to G)
This is how it is done in both PBRT and Mitsuba 1 for homogeneous media with the EBalance (default) method.
In Mitsuba 2, this weighting is not part of the medium anymore, it happens in volpath. In case the RGB mode is selected, a random channel is chosen and then all transmittance calculations are done according to that channel. However, the throughput is not weighted with the correct PDF, as it does not use the average of all the channels, but only uses the selected channel.
Note: For spectral rendering in Mitsuba 2, this does not seem to be a problem, because the 0th channel is always used, so the pdf does not have to take other channels into account. Althought using scalar_spectral mode on the same scene also behaves a bit weird, but that can be because of spectral uplifting issues.
The funny thing is that if the extinction (sigma_t) does not vary a lot over the RGB channels, then the wrong PDF is close to the correct PDF, so you cannot see the problem. However, if you use a sigma_t of, let's say, 0.1, 0.8, 0.1, the PDF becomes more and more wrong and the following starts to happen:

Hi Tomas
Thanks for looking into this. The volpath integrator does not perform any MIS between the different sampling strategies, that's why we divide by the PDF of the current color channel, and don't account for the other potential sampling strategies. This is a fairly bad approach to render scenes with spectrally varying extinction, that's why we also have the volpathmis integrator (I should really finally write the docs for these...). The volpathmis integrator does full MIS between color channels and also works well to render heterogeneous media with spectrally varying extinction.
The image you output with Mitsuba 2 is therefore quite noisy. If you render with a higher sample count, it should converge to the right result. Or you can switch to volpathmis, which gives similar noise performance as the Mitsuba 1 integrator.
I find it surprising that you observed the behavior to be fundamentally different between RGB and spectral mode, this is something which I will have to investigate. There shouldn't be a difference in behavior from that point of view. In the spectral mode we always use the 0th channel, but this one is already sampled (so choosing a random index would not make a difference).

PBRT and Mitsuba 1 use the "balance heuristic" MIS to weight the samples. That's why the PDF of the free flight distance accounts for the PDFs of sampling the same distance using the other color channels. This reduces the variance, but it is not necessary for correctness. Our volpathmis does a more extensive version of that kind of MIS weighting, which PBRT and Mitsuba 1 did not do. So you could also compare between volpath and volpathmis. If they don't converge to the same result, we indeed have a bug
