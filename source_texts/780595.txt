Summary
Implements a new camera glide system that tweens both position and a virtual look-at target, deriving rotation each frame instead of slerping between orientations. This creates more natural camera motion that sweeps the way a person turns their head toward what they're walking to.
Adds support for two-step focus on double-click: the first step keeps the camera's heading and slides the entity to the view center at framing distance; repeating the action runs the full framing with the entity's focus view orientation.
Key Changes
New cameraGlide.js module (src/editor/lib/cameraGlide.js):
createLookAtGlide() - Creates a glide between two camera poses by tweening position and target, deriving rotation each frame
lookAtQuaternion() - Builds a quaternion from position, target, and up vector
targetOnAxis() - Projects a hint onto the forward axis or uses fallback depth
headingPreservingFocusPosition() - Calculates a position that keeps heading while centering an object at framing distance
Updated ExperimentalControls.js:
focus() now accepts options.twoStep for double-click behavior
Refactored focus logic into _focusFrame() helper that returns bounds, distance, and camera state
New _startFocusGlide() method that uses createLookAtGlide instead of direct position/quaternion lerp
Tracks _softFocusTarget to detect repeat double-clicks on the same entity mid-glide
Applies glides to both focus animations and snapshot camera states
Updated focus-animation.js:
Added optional onFrame callback for custom per-frame pose writers
Falls back to default slerp/lerp when onFrame is not set
Clamps eased progress to [0, 1] to handle custom frame writers
Updated event emitters (viewport.js, raycaster.js, Entity.jsx, StreetCrossSectionStrip.jsx):
objectfocus events now pass { twoStep: true } option for double-click routes
F-key, Focus buttons, hotspots and AI tool keep one-step full framing
Comprehensive test suite (test/editor/cameraGlide.test.js):
Tests endpoint exactness, horizon leveling, target aiming, heading preservation
Tests edge cases: straight-down plan view, behind-camera targets, floor constraints
Implementation Details
Both start and end targets are projected onto their respective pose's forward axis, ensuring derived rotations at t=0 and t=1 match the endpoint quaternions exactly
Uses world up (0, 1, 0) when both poses are level; uses slerped pose up for rolled or vertical orientations (e.g., plan view)
Heading-preserving first step returns null if it would place the camera below the object's floor, forcing full framing instead
Glide system is reused for both focus animations and snapshot camera state transitions
No rotation slerp occurs during glide; rotation is purely derived from position and target each frame
