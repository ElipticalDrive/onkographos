Stacked on #170. This PR contains #170's commit (a1eb557) because GitHub can't target a fork branch. Review only the last commit, efeaf28. It stays a draft until #170 merges, then gets rebased onto main.
projection_align projected the reference and the mobile volume with the same candidate rotation and kept the one whose two projections matched best. That finds the view where the two volumes look most alike, not the rotation between them. Its only test aligned a volume with itself, so this never showed. On a volume rotated by a known Q, it came back 112° off.
Changes
Rotation search: the reference is projected along three fixed, mutually perpendicular views. Each candidate rotation R rotates the mobile back by R and projects it along the same views. The score is the 2D NCC peak averaged over the views.
Returned rotation: rotation_matrix now means the same as for exhaustive_search, gradient_refine and apply_alignment. If the mobile is the reference rotated by Q, it returns about Q. The docstring says so.
Translation is now full 3D: the three views' 2D shifts are combined by least squares. Previously the depth component was always 0. The half-voxel rotation-centre difference on even boxes is corrected.
Score is now a true NCC, between −1 and 1.
New config field: ProjectionAlignmentConfig.rotation_batch_size (default 64). Each candidate now needs three projections, so candidates are projected in batches.
This relies on #170's convention: project_3d_to_2d(V, R) projects V rotated by R.
Testing
New test_projection_align_recovers_known_rotation rotates an asymmetric reference by a known Q with scipy and shifts it by (1, 2, −3) px. It checks the rotation is within the 20° angular step of Q and the translation within 1.5 px. It fails before this change and passes after.
The existing identity test is now stricter: the whole 3D shift must be zero.
All 36 torch-fit-in-map tests pass on CPU. Ruff is clean.
Known limitations from torch-fourier-slice (also on main, not fixed here)
Views exactly along x are inaccurate. For example Ry(90°) puts the whole central slice on the kx = 0 plane of the rfft. The three views are tilted by a fixed generic rotation to avoid this.
Odd box sizes project slightly less accurately, so projection_align can occasionally miss on odd boxes. Padding to an even size avoids it.

The real-space functions (project_3d_to_2d, project_3d_to_2d_multichannel,

layer, on both backends, against a real-space rotation of an asymmetric
volume. The torch-tiltxcorr tests no longer need to invert their matrices.
