What
Vulcanus's spot noise uses a cone formula that is not quite the game's. Switching it to the game's formula raises all five of its spot-field counts toward full. This is a defect in shipped code, so it gets its own graded change instead of riding along with the Aquilo port.
How it was found
The Aquilo port (#454, branch aquilo-stage-1) needed spot noise to be bit-exact. It read the cone arithmetic from the 2.1.23 Linux binary (NoiseOperations::SpotNoise::run, and the placeSpots code inlined into the spot-list generator). The game:
computes the peak once in f64 and narrows it: f32((q * 3.0) / ((r * 3.1416) * r));
uses the double 3.1416 for pi (0x400921FF2E48E8A7, read from .rodata), not std::f64::consts::PI, a relative difference of 2.3e-6;
takes the slope as f32(peak / r);
takes the distance as an f32 sqrtss of an f32 sum of f32 squares;
culls on max_r < d, using that f32 distance;
takes the cone as max(out, peak - d * slope) in f32.
With that arithmetic (ConeArithmetic::GameBinary in crates/fmw-noise/src/spot_field.rs), all 11 Aquilo resource fields match the game on every sample in all three tier-1 cases.
Vulcanus still uses ConeArithmetic::PortedF32, which is what the TypeScript port did: per-op f32, PI * r with the f64 pi, and an f64 distance.

Where else to look
The same cone shape probably appears in crates/fmw-noise/src/resources/regular_patches.rs, crates/fmw-noise/src/resources/starting_patches.rs and the raw_spots loop in crates/fmw-noise/src/expressions/vulcanus_biomes.rs. Check each against the binary before you change it.
To fix
Move Vulcanus to GameBinary in its own PR. Re-freeze its tier-1, tier-2 and tier-3 values in that PR, with the before and after numbers.
