What was wrong
templates/gaussian_splat_template/project.godot put rendering/...-prefixed keys under the [rendering] section. Godot prefixes keys with their section, so each one was read as rendering/rendering/... and none of them took effect: the default environment (scenes/environment.tres), anti_aliasing/quality/msaa_3d, and the Gaussian splatting settings. Found while diagnosing #1089.
What changed
The redundant rendering/ prefix is dropped on 8 keys.
gaussian_splatting/async_compute_enabled is removed: no code in the repository registers or reads it (git grep async_compute_enabled finds only this line).
One file, 8 insertions, 9 deletions.

What users now see differently
Background: the flat grey clear colour becomes the environment's Sky. Note that environment.tres sets ground_color/top_color on the Sky resource, which has no such properties (they belong to ProceduralSkyMaterial), so the sky shows Godot's default pale grey-blue, not the dark blue the file intends. This PR does not change that; it needs a separate decision (a ProceduralSkyMaterial with those colours).
Splats: the applied colour ambient lifts the splat cloud from mean luma 0.10 to 0.31 in the shipped framing. It stays dark because of Starter template renders its splats nearly black: the splat cloud shadows itself under the template's DirectionalLight3D from the refocused camera #1089. With the light's shadows off, the cloud is 0.81 before and 0.88 after.
MSAA 2×: mesh edges only. Splat pixels are identical with MSAA disabled vs 2× (0.8845 vs 0.8845, shadows off).
LOD max distance 100 m to 150 m: no visible effect on this ~19 m scene.
Fog (density 0.0012) and Linear tonemap now apply. No visible difference at this scale.
Before/after full frames were captured (overlay visible) but not uploaded, because the CLI cannot attach images. They show the grey-to-pale-sky background change and the slightly lifted splats; the numbers above are measured from the same frames.
This does not fix #1089. The starter template still renders its splats dark until the self-shadowing is fixed.

* docs: describe #788 as state-dependent, per the single-route ADR §3.2

GaussianSplatSceneDirector::get_submission_residency_hint_for_renderer
gives an active, renderable world submission's hint precedence
(world_submission); only when that gate fails does the instance hint
(always RESIDENT) decide. Either node type can therefore be the one that
renders nothing. The world-blank resident_no_instances case measured on
#788 is kept as one configuration.
