Summary
Restores the dropped BSDF-ray-hits-emitter MIS leg for diffuse bounces in the spectral integrator. Before this PR the integrator applied only the NEE light-sampling leg (w_L) and dropped the complementary BSDF-sampled leg (w_B), biasing direct lighting dark by exactly the BSDF-weighted portion of the light — the softbox / large-near-area-light regime where bsdfPdf ~ lightPdf. When a BSDF-sampled continuation ray from a diffuse bounce (bounce>0 && !wasSpecular) hits an emitter, we now add throughput·Le·powerHeuristic(bsdfPdf_prev, lightPdf_hit), the complement of the NEE leg.

Research/citations: .astroray_plan/docs/pkg120-two-sided-mis-research.md

That is true for the production integrators, but the pkg55 oracle web (a bit-exact production trip-wire + cross-family mean-ratio parity gates comparing the wavefront family to the production family) means the term must move in all four to keep CI green. #4 is the single shared kernel advance_one_bounce used by both CPU wavefront oracles, so it's one file; bit-identity between them is preserved by construction. bsdfPdfPrev is carried through the CPU wavefront SoA round-trip (cpu_wavefront_state) mirroring the GPU path_bsdf_pdf SoA field.

CPU↔GPU lockstep (by construction)
Both sides compute w_B from the same values: prev-ray origin/direction (written verbatim, no snapshot skew), bsdfPdf_prev, and the reconstructed lightPdf_hit — LightList::pdfValue on CPU vs gpu_reconstruct_light_pdf on GPU, which mirrors it exactly including the normal = -dir proxy the CPU TreeLightSampler::pdfValue uses, the power-CDF selection pdf, and per-shape solid-angle pdfs. Same power-heuristic form (bp²/(bp²+lp²+1e-8)).
Tests / gate

test_two_sided_matches_analytic_formfactor — magnitude: one-sided reads dark vs the analytic oracle ρ·L_e·(R/d)² (L_e read from a calibration render so the emission convention cancels); two-sided matches within a convention-tolerant band.
test_no_regression_distant_compact_light — compact light (R/d≈0.06, w_B≈0): two-sided ≈ one-sided.
The max_depth=1 vs 2 mechanic isolates the one-sided leg without any integrator toggle: at max_depth=1 the BSDF continuation ray is never traced, so the two-sided term cannot fire.

Energy-gate linearity note
The dielectric/Disney furnace tests (test_dielectric_glass_furnace.py, test_disney_rough_glass_furnace.py) render with apply_gamma=True (4th positional render() arg True). Per the gamma-furnace-cannot-detect-energy-gain finding, gamma clamps to [0,1] and cannot detect an energy gain — only loss. pkg120 adds energy (recovers the previously-dropped BSDF-side MIS leg), so a hypothetical energy-gain regression from this change would NOT be caught by these two furnace tests; they passing is necessary but not sufficient evidence against over-counting. The pkg120 gate itself (test_pkg120_two_sided_mis.py) is the one that correctly measures gain, and it renders apply_gamma=False (linear) by design.
Visual inspection
Rendered the large-near-light scene (R=1.6, d=2.0, matching the gate scene) at 256x256/256spp for both max_depth=1 (one-sided) and max_depth=2 (two-sided): floor directly under the sphere is smoothly bright in both, fading gradually outward with no fireflies, no banding/quantization steps, no NaN pixels (np.isnan false on both), no dark ring near the light, and no mode regression (still monochrome/RGB as expected, not spectral). The two-sided render is visibly brighter in the floor region near the light base, consistent with the measured +28-38% energy recovery. No visual anomalies.
Anomalies worth watching
None found in this sweep. The test_two_sided_matches_analytic_formfactor patch-size sensitivity (8x8 vs 2x2 vs point) documented in the test file's own comment is a measurement-methodology property of the analytic oracle, not a rendering defect — reconfirmed here since transport correctness was independently triple-checked per that comment (center-point accumulator, single-pixel match, independent Python cosine-MC oracle at 0.9999x analytic).
