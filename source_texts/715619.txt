Summary
Set3DProjectionSettings took only a perspective, so an isometric or a side view of the 3D window meant typing into the 3D Projection Settings dialog. It now also takes an axonometry. Only the given values change:
```
 Set3DProjectionSettings
-  { perspective }                       required
+  { perspective } | { axonometry }      exactly one
+  axonometry: { projectionType?, azimuth?, transformationMatrix? }
+    from a perspective: switch back to the last axonometry first (switchOnlyAxonoOrPersp)
+    read the current API_AxonoPars, change the given fields, Change3DProjectionSets
+    transformationMatrix: its inverse is computed for invtranmat, a singular one is refused

 Get3DProjectionSettings
   axonometric: { transformationMatrix
+                , projectionType, azimuth }
```
projectionType is the API's projMod (#/AxonometryProjectionType). Archicad works out the matrix itself from the type and the azimuth, so an agent never writes a matrix for the predefined views:
Wanted
axonometry
Isometric from the south-east (X −30°, Y 30°, Z 90°)
{"projectionType": "Isometric", "azimuth": 270}
Isometric from the north-east
{"projectionType": "Isometric", "azimuth": 0}
Side view from the south
{"projectionType": "YZ", "azimuth": 270}
An exact saved view
{"projectionType": "Custom", "transformationMatrix": [...]}
Also:
The perspective schema now gives units and behaviour. azimuth is in degrees and recomputed by Archicad from the camera and target. viewCone is in degrees.
The descriptions note that the 3D window shows the change only after RebuildView.
InvertTranmat was in ProjectCommands.cpp and ExtendedElementCommands.cpp, and this would have been the third copy, so it moves to CommandBase.
Evidence
Archicad 29, macOS, a test project. The new check Test/checks/set_3d_axonometry.json was run step by step:
```
PASS isometric from the south-east        success == true
PASS read the isometric                   projectionType == "Isometric", azimuth ~= 270
PASS                                      matrix row 1 (0.866, 0.866, 0), row 2 (-0.5, 0.5, 1)
PASS side view from the east              projectionType == "YZ", screen X = model Y, screen Y = model Z
PASS custom matrix                        read back unchanged
PASS singular matrix                      success == false
failures: 0
```
Every type was also set at several azimuths and read back:
YZ and XZ give the same side view, looking from the azimuth.
XY is the top view, rotated by the azimuth.
The predefined axonometries look from 45° past the azimuth.
Parallel reads back as Custom with the matrix unchanged.
Before: {"axonometry": {...}} was refused by the schema; only a perspective could be set.
After: the calls above set the projection, and the 3D window shows it after RebuildView.
Merge Danger
Door: two-way
Additive. A call with only perspective behaves as before. Get adds two fields to axonometric.
Blast Radius: small
The new oneOf refuses a call that gives both perspective and axonometry; no such call could exist before.
GetOpeningTransformations and GetSurveyPointTransformation now use the shared InvertTranmat. Its maths and threshold (1e-12) are the same as both old copies.
