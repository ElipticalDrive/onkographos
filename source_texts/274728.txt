Describe the Bug
The NIFTI_VOLUME_LOADED event currently triggers immediately after header parsing rather than after the full volume is loaded.
This behavior results from the internal implementation of the fetchArrayBuffer function, where the loadFullVolume parameter defaults to false and is never exposed or modifiable externally.
Additionally, structural updates introduced in Cornerstone 3D v2.x—specifically the transition from directly loading volumes (volumeLoader.createAndCacheVolume) to generating imageIds first via createNiftiImageIdsAndCacheMetadata—appear to have indirectly influenced this behavior.
This bug is using:
@cornerstonejs/core: "3.4.0"
@cornerstonejs/nifti-volume-loader: "3.4.0"
Steps to Reproduce
Attempt to load a NIFTI volume expecting the entire volume data.
Monitor the NIFTI_VOLUME_LOADED event.
Observe that the event triggers immediately after the header parsing completes.
Confirm that the full volume data has not yet been fully loaded at this point.
The current behavior
The loadFullVolume parameter defaults to false internally and cannot be externally configured, causing the NIFTI_VOLUME_LOADED event to fire prematurely after header parsing.
Link to the code causing the problem:
https://github.com/cornerstonejs/cornerstone3D/blob/main/packages/nifti-volume-loader/src/createNiftiImageIdsAndCacheMetadata.ts#L27

The expected behavior
The NIFTI_VOLUME_LOADED event should trigger only after the full volume data has been completely loaded and processed, with the loadFullVolume flag being externally configurable.

@james-hanks In my opinion this isn't a bug.
NIFTI_VOLUME_LOADED is a nifti specific event that indicates that the nifti has been parsed.
CORNERSTONE_IMAGE_VOLUME_LOADING_COMPLETED is the generic event that indicates that the volume's image data has been fully loaded, and applies to any sort of volume, for example, a volume loaded from a series of dicoms.
The name NIFTI_VOLUME_LOADED is maybe not great. NIFTI_HEADER_PARSED might be better. But on the other hand there is already a lot you can do with a volume (such as assigning it to a viewport) before the image data has been loaded.
