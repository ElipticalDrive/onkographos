What
A hand-written WebGL2 port of Voxelwild in web/, so the game plays inside a web page (published as a Claude artifact). The Unity WebGL module can't be installed on this editor, and a Unity WebGL build would not fit the artifact limits anyway, so the browser build reimplements the runtime while reusing the game's data and rules:
World: same terrain/biome/cave/tree generation, voxel lighting and meshing, running in Web Workers; streaming, cave culling, edits with relighting, cellular water
Props: the Blender assets exported headless (web/tools/export_props.py) with LODs and bakes; same placement rules, barrier/core cells, voxel lighting, removal on edits
Renderer: HDR pipeline with the single-scattering sky, PBR terrain from the real texture sets, two shadow cascades, cloud shadows, refractive water, wind, bloom, light shafts, ACES; dynamic resolution
Gameplay: walking/sprinting/swimming/flight, mining with tool tiers and drops, placing with support rules, item entities, inventory + crafting, health/hunger/breath/fall damage/drowning/death, day/night, weather with rain/snow/lightning, synthesised audio, IndexedDB saves
UI: title over a live world, new world, unsaved creative sandbox, loading, HUD, inventory/palette, pause, settings, death; pointer lock with fallback; touch controls
Testing
npm test (web/test/run.mjs) drives the built page in real Chrome with the GPU — 19 steps, all passing: boot, world load, walking, hand mining with drops, placing, crafting, eating, fall damage, time/weather views, creative flight + streaming, creative palette, pause, tool tiers (stone needs a pickaxe; tools wear), torch light, drowning → death → respawn, water flow, drops rendering, props placement/lighting/removal, save, persistence across a page reload, zero console errors
Also passes under an artifact-like Content-Security-Policy (CSP=1 npm test)
web/test/shots.mjs screenshots fixed viewpoints, biomes, caves and props at chosen times and weather
Not covered
Only verified in headless Chrome here (Snapdragon X / Adreno, D3D11); not yet on Firefox or Safari
The live page runs in the artifact viewer; pointer lock and IndexedDB depend on the viewer allowing them (fallbacks are in place)

Browser build: Blender props (rocks, boulders, dead wood, cave format…
…
8fd6049
```
…ions, plants)

Ports the Unity prop system so the browser world matches the game:
- tools/export_props.py (Blender headless) converts the prop FBX files and
  their LODs into one vertex/index buffer (props.bin + props.json); the
  per-asset normal/AO/curvature/moss bakes are packed as texture arrays
- Placement rules and the decoration pass (spaced big props first, per-cell
  small ones, cave floors and ceilings), boulder cores and PropBarrier
  collision cells, all in the worker so columns stay deterministic
- Each prop is lit from the voxel light its section's mesh job computed
- Props go when an edit breaks what they stand on, take their core and
  barrier cells with them, and stay removed across saves
- Instanced drawing with distance LODs in the main pass and both shadow
  cascades; triplanar rock continuous with the blocks, UV-mapped bark,
  vertex-coloured plants with wind, moss from the bake
- Dead wood (barrier cells) mines like logs and yields 3 oak logs
- Fixes: title backdrop no longer replaces a world started early; item
  pickup uses the player's box grown like Minecraft's
```

Browser build: load Minecraft resource packs (LabPBR normals, heights…
…
b766dc7
```
…, specular) + POM

- Settings > Block textures: load a Java Edition resource pack ZIP (or drop it on
  the page); its block textures replace the game's materials, the rest stay
  built-in. The pack is read and kept only in the player's browser.
- LabPBR: RG normal (DirectX or OpenGL, selectable), B AO, A height; specular
  smoothness -> roughness, F0 >= 230 -> metal, emission; SEUS-style old PBR option
- PNGs are decoded through WebGL so heights in the alpha channel keep full
  precision; grey Minecraft textures get the default biome tint; up to 512x
- Parallax occlusion mapping with refinement, soft self-shadowing and a
  distance fade (0.25 blocks deep for packs, per LabPBR); relief slider
- Item icons rebuilt from the pack; test/make_test_pack.py builds a synthetic
  LabPBR pack for the e2e test (import, POM view, restore after reload)
```

Browser build: built-in texture packs (Photoreal CC0 scans, Soothing 32)
…
b02274a
```
Settings > Block textures now offers Default, Voxelwild Photoreal and
Soothing 32 next to loading your own resource pack ZIP.

- Voxelwild Photoreal: Poly Haven photogrammetry (CC0) at 512x512 with
  LabPBR normal, AO, height (drives parallax occlusion mapping) and
  roughness for 17 blocks; stone pulled toward neutral grey; ores composed
  from the stone scan with raised, grained mineral nuggets
- Soothing 32 by Zughy (CC BY-SA 4.0), the top-rated pack on ContentDB:
  mapped to Minecraft names, 16x nearest-neighbour; bedrock, mud and ores
  composed from its stone, dirt and mineral overlays
- web/tools/build_packs.py downloads the sources and writes a colour strip
  plus, for PBR packs, a greyscale data strip (one column per channel:
  lossy WebP stays accurate per channel; 9 MB instead of 16 MB lossless)
- respack.js: fetchBuiltinPack feeds pre-decoded images into the same
  converter as a player's ZIP; the choice is stored by id and re-fetched
- Fix: texture strips taller than the GPU's texture limit (8192 on many
  GPUs; the game's own strips are 8960 px) failed to decode, which also
  broke loading any pack there; decodeLarge decodes them in bands
- test/packs.mjs: switches through every pack in Chrome, screenshots,
  checks persistence across a reload
- CREDITS.md and web/README.md: sources and licences
```
