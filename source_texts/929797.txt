Scope
Atomic operations and a stated memory model. Everything above this point assumes an ordering that
has never been written down.
sync/atomic operations for the integer types and for pointers, mapped to the right LLVM atomic
instructions and orderings.
State which memory model the implementation targets and how it relates to the Go memory model.
Check that the channel, mutex, and scheduler implementations actually use orderings strong
enough for the guarantees they claim.
The write barrier interacts with this once marking is concurrent.
Depends on the sync package.
Done when
Atomic load, store, add, swap, and compare and swap work for the supported types.
The targeted memory model is documented along with the places the implementation relies on it.
A test that would expose a missing ordering, such as a publish then read pattern across
goroutines, passes on a weakly ordered target.
