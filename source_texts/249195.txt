<issue_title>Initial implementation</issue_title>
<issue_description>New web app
Single page client only React app using preact, Typescript 5.9, and NPM
The user can provide an image through drag and drop, browse, or paste. We will turn this image into a 3MF file suitable for a multi-color 3D printing.
The user can select how many colors to use (default this to 16 MAX but do not always use all 16 colors), and the UI displays. A preview of what the generated file will look like when printed. The user can also pick the total measured rectangular size of the resulting object and change the scale. The user can also select whether the image is displayed on the front face or the back face, and choose different heights for each color layer.
Have a radio box with three settings:
Full image - the entire image is converted into a rectangular output
Transparent - The corners of the image determine the transparency key for the image
Island - there's no explicit transparency key, but the image sits on an implied transparent field (e.g. a cartoon character on a white background, but with white eyes -- we want to ignore the background field, but preserve the whites of the eyes). Preprocess the image to flood-fill from the border with transparency
Complete all assigned work and do not leave behind to do's. Use standard algorithms and dependencies were appropriate. Complete the entire assigned task
You are to implement a program in TypeScript that takes a raster image with a maximum of 16 discrete colors and produces a separate watertight triangle mesh (STL or OBJ) for each color.
Each mesh represents a 3D solid volume corresponding to the connected regions of that color, including any interior voids.
The output geometry must be suitable for 3D printing.
Use the Marching Cubes algorithm to convert volumetric data into triangle meshes.
Use WebGL to show an animated preview of the output you've generated, using the generated triangle meshes.
The raster image will have reasonably high resolution but may include JPEG noise and isolated color specks that must be removed.
Processing pipeline (you must implement these steps)
Load and quantize the image
Read the raster image (PNG, JPEG, etc.) into a 2D pixel array.
Quantize it down to ≤16 colors if it has more.
Use a fixed small color-distance threshold (e.g., ΔE or Euclidean in RGB) to assign each pixel to its nearest canonical color.
Preprocess to remove noise
Apply a small median filter (3×3 kernel) to suppress JPEG artifacts and blended edge pixels.
Remove isolated single-pixel color errors:
For each pixel, if none of its 8 neighbors share its color, replace it with the majority color of its neighbors.
Optionally apply a morphological open + close (1–2 pixel radius) to fill tiny gaps and remove specks.
At this stage you have a clean, discrete color map colorMap[x][y] with at most 16 distinct colors.
For each color, create a 3D voxel volume
For each color C:
Create a binary mask M[x][y] = 1 if colorMap[x][y] == C else 0.
Define a physical voxelSize (e.g. 0.1 mm) and a layer thickness (e.g. 1–5 mm).
Extrude the 2D mask in the z-direction to produce a 3D volume:
V[x][y][z] = M[x][y] for z in [0 .. thickness/voxelSize - 1]
Optionally, if you want smoother edges, compute a signed distance field (SDF) instead of a binary mask using a 2D Euclidean distance transform before extrusion.
Preserve interior voids
A voxel value of 1 means solid; 0 means empty.
Do not fill enclosed empty regions — marching cubes will automatically generate internal surfaces for those voids.
To explicitly verify voids:
Flood-fill all 0 voxels from the outer boundary to mark external air.
Any remaining 0 regions not reached by the flood-fill are enclosed voids; keep them as 0.
Apply Marching Cubes
Implement or use an existing Marching Cubes algorithm in TypeScript (or a WASM wrapper around a C++/Rust library if available).
Use iso-value 0.5 for binary volumes or 0.0 for SDF volumes.
Interpolate vertex positions between voxel centers along cube edges.
Generate triangle faces per cube configuration using the standard lookup table.
Compute vertex normals from SDF gradients or from triangle normals.
Output: a watertight triangle mesh for the current color.
Postprocess and export
Merge duplicate vertices within an epsilon tolerance.
Remove degenerate or zero-area triangles.
Optionally simplify the mesh (e.g., quadric decimation).
Scale to physical units using voxelSize.
Export as .stl or .obj file named after the color label (e.g. red.stl, blue.obj).
Expected behavior summary
Input: High-resolution raster with ≤16 colors.
Preprocessing: Median filter + isolated pixel removal + optional morphology to denoise color regions.
Voxelization: Per-color binary or SDF 3D volume, extruded to a defined thickness.
Meshing: Marching Cubes at iso-surface 0.5 or 0.0.
