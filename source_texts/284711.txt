Closes #1055 (#979 Phase 2).
What this adds
A GPU reference path tracer: one fullscreen GL_EXT_ray_query fragment draw (GpuPathTracer.glsl) that replaces the rasterised scene colour with a progressively converging path-traced image, structured to mirror the CPU reference tracer (PathTracer.cpp) term by term so the two are comparable sample by sample, not only in the converged image.
Integrator: Sobol'-Owen sampler in the CPU's dimension order (PathTracerSampler.glsl, bit-identical to PathSampler.h), NEE over punctual lights (deterministic, no dimension) and emissive triangles (uniform by area, CDF), power-heuristic MIS on the emitter-hit path, Russian roulette on the max throughput channel, the ClosureV2 closure. Hits are shaded from the GPU Scene material factors (RHI: full bindless on Vulkan — runtime-indexed heap access in shaders (re-opens ADR 0011 amendment (50)) #805: untextured, counted).
Emissive table (EmissiveTriangleTable): gathered during GPU Scene extraction from the materials that emit, resolved against the committed material records at EndScene, uploaded by device address only (StorageBuffer::kNoBinding, new) and rewritten only when its bytes change.
Accumulation through the temporal-history registry and nothing else: four RGBA32F planes (radiance sum + count, second moments, first-hit albedo, first-hit normal) under TemporalHistoryEffect::PathTracer. The sample index each pixel draws is its accumulated count, so N frames at 1 spp and one frame at N spp draw the same indices. Restarts: any bitwise camera change on the unjittered projection, any integral-changing setting, and any dirty GPU Scene range after commit, which maps to a new TemporalHistoryDependency::SceneContent bit that only the tracer's planes declare (TAA/SSR/SSGI keep reprojecting by their own declaration; the tracer does not declare Jitter, so a TAA/FSR2 toggle does not throw the sum away).
AOVs selectable as the pass output: radiance, albedo, normal, variance, sample count.
Structural fallback: the shader is created only where SupportsRayTracing(); the target is declared only when enabled and ready; a stood-down frame uploads a zero TLAS address, passes the colour through and carries the history planes forward unchanged. GpuPathTracerFallbackReason is resolved most-fundamental-first every frame from the per-frame wiring (so a culled pass still reports) and logged once per change. Standing limits are counted in GpuPathTracerStats, never commented: untextured hits and masked geometry traced as solid where the backend cannot index the heap, lights past the shader's 256-slot bound, consecutive restarts (an animated scene restarts every frame and the pass says so).
Surface: scene YAML (15 keys, all sanitized through one SanitizeGpuPathTracerSettings), MCP pathtracer field group, Post-Process panel section with live stats, a Vulkan-only benchmark manifest (material-lab-furnace.pathtracer.yaml) capturing the four planes.

PathTracerSamplerParity.* / ClosureV2SampleGpuParity.* (shaderpipe): the GLSL sampler is bit-identical to PathSampler.h over a grid of (sample index, seed, dimension); the GLSL ClosureV2 sampling matches the CPU closure within 2e-4 on L and 1 % on pdf/value outside a conditioning band.

Review guide
Read in this order:
GpuPathTracerTypes.h: the vocabulary, the limits, the one sanitizer.
GpuPathTracer.glsl next to PathTracer.cpp: the integrator is a transcription; every divergence from the CPU is a comment naming why.
GpuPathTracerPass.cpp: ResolveAvailabilityForFrame (the fallback ladder), Execute (the UBO, the accumulation count).
EmissiveTriangleTable.cpp, MaterialTextureTable.cpp and the touch points in Renderer3DGPUScene.cpp / Renderer3DFrameExecution.cpp.
4b. Textures: docs/adr/0011-amendments.md (95), RHIDescriptorHeap.h + VulkanDescriptorHeapBackend.cpp (the resolvers), DescriptorHeapTextures.glsl, the PtApplyNormalMap / ReferenceScene::ApplyNormalMap pair.
RenderPipeline.cpp: the per-frame wiring block, the four history acquisitions, the fingerprint hashes, the alias-chain branch, the six-attachment target.
docs/agent-rules/gpu-path-tracer.md: the rules and what bit.
Things a reviewer might question, answered in the code: why the primary ray uses inverse(P*V) in GL clip convention and not the RHIProjectionSeam inverse (the shader never derives a ray from a backend texture coordinate); why a stood-down frame carries the sums forward instead of zeroing them (the registry is the only owner of "restart"); why an unshadeable ray-query hit is a black opaque hit rather than a miss (a miss would credit environment radiance through an occluder).

Textures (the #805 capability, scoped)
Hits now shade from the material's albedo, metallic-roughness (blue = metallic, green = roughness), normal and emissive maps at level 0, and alpha-MASK materials are confirmed per ray-query candidate, so masked geometry casts its real shadow. The shader indexes the descriptor heap itself with GL_EXT_descriptor_heap (descriptor_stride = 1, byte offsets), which ADR 0011 amendment (95) allows for shaders that have no OpenGL twin; every shader with a GL twin keeps classic bindings, and #805's full conversion stays open. Plumbing: two resolvers on IDescriptorHeapBackend (Vulkan answers from the draw path's slot cache and sampler heap; GL answers Invalid), MaterialTextureTable (one 16-byte record per material slot, by address), UVs and the emissive map in the emissive records so NEE sees the textured radiance, and VulkanDevice enabling shaderSampledImageArrayNonUniformIndexing. The CPU reference samples the same maps with the same convention (ReferenceTexture, ReferenceScene::ApplyNormalMap), so the oracle relationship holds on textured scenes. GpuPathTracerSampleTextures is the A/B toggle; the pass logs texture availability and its reason once per change.
Textured evidence (Vulkan, this box): GpuPathTracerDevice.TexturedCornellBoxAgreesWithTheCpuReferenceWithinTheBudget traces a Cornell box with a checker floor, a metallic-roughness + normal-mapped block, a ramp emissive light and a slatted alpha-mask quad. Frame mean GPU 0.2324/0.2374/0.2111 vs CPU 0.2325/0.2377/0.2112 (budget 1 %); every region mean, including the floor under the slats and both ends of the ramp emitter, within 0.3 % (budget 2 %); zero validation errors. PNGs: GpuPathTracer_CornellBoxTextured.png / _CpuReference.png. Live: MaterialLab's rusted-iron sphere traced with its albedo and normal map, log material textures are sampled (116 material records, 0 unresolved); toggling the setting off shades flat and logs why.
Sphere-area lights
Both tracers now model SphereAreaLightComponent as a spherical emitter, defined once in PathTracer.cpp (ViewSphereLight) and mirrored by the shader: a sphere of radius r at distance d is a uniform emitter whose radiance reproduces the raster path's diffuse irradiance at the receiver (calculateSphereAreaLightContribution's windowed attenuation), sampled by uniform solid angle over the cone it subtends with MIS against the BSDF, visible to camera and bounce rays and occluding for shadow rays, so both MIS strategies see one visibility. Each sphere light spends two sampler dimensions per bounce in light order on both tracers. Evidence: GpuPathTracerDevice.SphereLightCornellBoxAgreesWithTheCpuReferenceWithinTheBudget (the plain box plus a warm sphere light beside the block) agrees with the CPU to six significant digits on the frame mean and every region, including the emitter itself and the block's soft shadow; live, SphereAreaLightShadowTest.olo traces the light as a visible emitter with a penumbra off the cube. SphereAreaLightsIgnored is gone from the stats; SphereAreaLights counts what was sampled.
Both closures
Each hit is now shaded and sampled with its material's own closure, as the CPU reference dispatches: the Legacy sampler (cookTorranceBRDF, GGX-NDF importance sampling plus cosine with the shared lobe probability) is mirrored in the shader next to the v2 one, behind PtEvaluateBRDF / PtBsdfPdf / PtSampleBRDF. Evidence: GpuPathTracerDevice.LegacyClosureCornellBoxAgreesWithTheCpuReferenceWithinTheBudget, the plain box on PBRModel::Legacy. LegacyMaterialsShadedAsClosureV2 is gone from the stats; LegacyMaterials counts them.
Known limits (counted, not hidden)
Punctual lights past slot 256 not traced, occlusion maps not sampled (a path tracer computes occlusion), textures at level 0 (no ray cones), no denoiser (#979 non-goal). Untextured hits and masked-as-solid remain as counted fallbacks only where the backend cannot index the heap (OpenGL). The device parity tests and the live evidence are Vulkan-only; CI has no RT device and runs the CPU/GL half.
olo_pathtracer_stats reads this pass's counters over MCP (status with the fallback reason, accumulation, lights, the texture path's counted limits, settings). olo_rt_trace_ray is still missing; logged against #607.

CodeRabbit, 15 threads, all fixed in 5e3d487 and answered in-thread: the by-address tables now publish a fresh buffer per change instead of writing the one the previous frame reads (deferred reclaim keeps the old allocation alive); samplerAnisotropy is requested and the degree clamped to the device limit (pre-existing, moved here); SampleBilinear wraps before the integer conversion; the sampler probe pins eight dimensions unpacked (the old pack rounded); the MCP vec3 field, panel clamps, manifest bool decode, lifecycle audit, view-mask split and the small test hygiene items.

the ClosureV2 closure. Hits are shaded from the GPU Scene material factors.

Emissive table (EmissiveTriangleTable): gathered during GPU Scene extraction
from the materials that emit, resolved against the committed records at
EndScene, reached by device address only (StorageBuffer::kNoBinding, new on
both backends) and rewritten only when its bytes change.

Accumulation goes through the temporal-history registry and nothing else:
four RGBA32F planes under TemporalHistoryEffect::PathTracer, extracted from
the pass's own attachments. The sample index each pixel draws is its
accumulated count, so a capped run is reproducible whatever frame it began
on. Restarts: any bitwise camera change on the unjittered projection, any
integral-changing setting, and any dirty GPU Scene range after commit, which
maps to a new TemporalHistoryDependency::SceneContent bit that only the
tracer's planes declare (TAA/SSR/SSGI keep reprojecting; the tracer does not
declare Jitter, so a TAA toggle keeps the sum). A stood-down frame carries
the planes forward unchanged.

the target is declared only when enabled and ready; a zero TLAS address
passes the colour through. GpuPathTracerFallbackReason is resolved every
frame from the per-frame wiring (a culled pass still reports) and logged

untextured hits, masked geometry traced as solid, Legacy materials shaded as

sccache hashes preprocessed output, so every TU that reaches a Vulkan header
changes when the SDK does. The key carried the runner image and the sanitizer
but not the SDK, and `restore-keys` fell back to a bare
`sccache-asan-windows-2025-`, so an SDK bump restored the pre-bump entry and
then missed on most of the target.

Measured on PR #1112 (run 34166829499), which bumps the SDK: 923 misses of
1588, 42.17 % hits, a 2 h 06 build -- with a healthy restore and no warning
anywhere. Its log carries the tell, `Found Vulkan ... found version "1.4.357"`
under a `-1.4.321.0` cache key.

It read as a capacity problem, and that reading is what this commit is really
about. The stats said "Cache size 1 GiB / Max cache size 1 GiB", which looks
like a cache pinned at its cap. sccache ROUNDS: `du -sm` puts this job's object
set at 1241 MiB against a 1500M cap, and two dispatches on identical source,
one at 1500M and one at 3G, both returned 99.87 % and 12-13 min (runs
34206210094 / 34203502889). There is 259 MiB spare and raising the cap buys
nothing. The same rule the Linux keys already follow with `llvm-<version>`,
and that #1082 learned from a rolling clang: pin whatever the key is hashed
over.

`restore-keys` carries the version too, on purpose -- a bare fallback would
keep finding the pre-bump entry and reproduce the half-stale restore. The cost
is one visibly cold build per bump instead of a mystery 42 %.

cache-prune.yml strips the `-vk<version>` segment when it groups a lineage, so
a bump supersedes its ~1230 MiB predecessor instead of stranding it for the
30-day age-out -- the same leak the trailing-content-hash strip was added to
stop in #1073. Noted there but NOT fixed: the `llvm-<version>` stamp on the
three Linux keys has the same exposure, and a clang bump will strand three
entries.

Refs #1084
