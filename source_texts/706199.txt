# Spatial-4D Gaussian Viewer

An experimental dynamic Gaussian-splatting pipeline and local browser viewer for
moving through **space and time independently**. Pause an action, orbit around it,
resume playback from the same viewpoint, or select a calibrated camera without
changing the scene time.

> Research prototype: this is not a validated general-purpose 4D reconstruction
> system. Wide or weakly observed views can contain streaks and missing surfaces.

## What is included

- A persistent-ID temporal Gaussian representation
- Interpolation of position, scale, opacity, color logits, and quaternion rotation
- A PlayCanvas-based viewer with orbit, pan, zoom, scrubbing, and camera presets
- A temporally regularized sequential fitting pipeline
- PLY sequence export and manifest validation
- Tests for camera conversion, timelines, interpolation, ZIP safety, temporal
  losses, and export consistency

Trained checkpoints, source footage, and the 250 MB demonstration sequence are not
committed. They are excluded because of size and data licensing.

## Architecture

```text
synchronized calibrated cameras
            │
            ▼
 static Gaussian checkpoint ──► sequential temporal fitting
                                      │
                                      ▼
                         persistent-ID PLY sequence
                                      │
                                      ▼
                local viewer: camera state × scene time
```

The viewer retains one Gaussian object on the GPU. It updates that object's
parameters instead of replacing the model every frame, preserving camera state
and reducing black-frame transitions.

## Run the viewer

Requirements: Node.js 20+ and a browser with WebGL 2.

```bash
cd viewer
npm install
npm start
```

Open <http://127.0.0.1:8765/> and select a compatible sequence ZIP. You can also
place a package at `data/spatial4d-sequence.zip`, or provide an absolute path:

```bash
SPATIAL4D_SEQUENCE=/absolute/path/to/sequence.zip npm start
```

The server binds only to `127.0.0.1` and serves an explicit allowlist.

## Sequence format

A sequence ZIP contains `manifest.json` and ordered PLY frames. The modern
manifest uses `format: "spatial4d-sequence-v1"`, strictly increasing
`source_times_seconds`, and calibrated OpenCV cameras with `c2w`, `K`, `width`,
and `height`. Set `persistent_ids: true` only when every PLY has the same float-only
binary layout, point count, and ordering.

Viewer limits are 600 MB compressed, 384 MB decoded, 32 MB per member, 120 frames,
and 500,000 splats per persistent frame. Encrypted archives, ZIP64, multipart
archives, and external paths are rejected.

## Training code

The `training/` directory contains the temporal fit, losses, background anchoring,
motion-region logic, and PLY exporter. It expects synchronized, calibrated NumPy
input. GPU fitting requires CUDA and `gsplat`.

```bash
python -m unittest discover -s training/tests -p 'test_*.py'
```

## Verified experiment

The reference experiment used 19 synchronized cameras and 151 source frames over
five seconds. Its viewer export contained 31 persistent samples and 155,304
Gaussians, with a 2.34 dB mean PSNR improvement over the frozen baseline. See
[`docs/EXPERIMENT_AUDIT.md`](docs/EXPERIMENT_AUDIT.md) for reproducibility notes.

## Roadmap

- Learned deformation field instead of sequential parameter fitting
- Fresh held-out cameras and held-out time ranges
- Better foreground identity and topology-change handling
- GPU-resident interpolation and lower upload latency
- Denser synchronized capture for reliable wide-angle navigation
