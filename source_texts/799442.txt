Functional real-photo 3D reconstruction without supplied camera extrinsics
Uses the selected existing hash-pinned OpenCV environment, the actual two Middlebury Aloe stereo photographs already verified by the parent workflow, SIFT descriptors/ratio and rectified epipolar filtering, cv2.findEssentialMat (RANSAC), cv2.recoverPose and cv2.triangulatePoints to estimate camera-2 R and translation direction from real image correspondences and reconstruct an actual RGB 3D point cloud (source-observed left RGB, not generated colors). Exports wre-real-stereo-sift-estimated-3d.ply (ASCII PLY) and wre-real-stereo-sift-estimated-pose.json (estimated R, normalized t, inlier count, fitted reprojection RMSE and limits), includes them in the early CPU preview and final bundles. The parent's dense StereoSGBM solution remains intact. Exactly one existing optional .github/workflows/gsplat-common-runtime-import.yml changes; no new workflow, solver or dependency.
Scope and scientific honesty: Real photograph pixels but only two rectified views; estimated K remains approximate. No metric scale, known relative camera pose, supplied COLMAP 3D coordinates, supplied tracks or scene geometry enter this new pose/triangulation solver. The reprojection residual is IN-SAMPLE. Not verified on unrelated photos, no generic SfM or bundle adjustment, no photorealistic Gaussian render, no GPU kernel training and no 4D. The actual GitHub CPU job must reach these operations and upload the two output files before claiming execution. Existing native CUDA compilation is NOT GPU execution.
