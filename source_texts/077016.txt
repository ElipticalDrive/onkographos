Contributor
Exploratory draft: renders Spherical Beta (SB) view-dependent color for PLY gaussian splats. SB is the specular model from Deformable Beta Splatting (Liu et al., SIGGRAPH 2025). It adds a few explicit specular lobes on top of the SH color: 2 lobes are 12 floats per splat, against 45 for SH bands 1-3.
Related:
Add Spherical Beta view-dependent color with diffuse/specular separation and PLY export supersplat#1036 adds the same lobes to SuperSplat (load, render, edit, export).
Integrate Spherical Beta from Deformable Beta Splatting: higher PSNR and faster speed at half the size and memory than SH degree 3 nerfstudio-project/gsplat#1056 trains and exports them. Its Mip-NeRF 360 benchmark has SH degree 0 + 2 lobes beating SH degree 3 by +0.15 to +0.30 dB PSNR, at about 45% of the PLY size.
Changes:
PLY files with sb_params_* properties now render their lobes. Each lobe adds pow(max(dot(dir, axis), 0), 4 * exp(beta)) * softplus(rgb) to the SH / base color. Files without the properties are unaffected.
The lobes are converted once at load (axis from the spherical angles, sharpness, activated color) and stored as half floats, one 16-byte texel per lobe per splat. The shader is left with one pow per lobe.
Up to 4 lobes are rendered. The trainers default to 2.
The color the lobes are added to is clamped to zero first, matching the trainer. Many splats have a negative base color, which would otherwise absorb part of the highlight.
Works in the unified and non-unified paths, on WebGL2 and WebGPU.
Splats with lobes but no SH now re-evaluate their color as the camera moves.
Uncompressed PLY only for now. Compressed PLY, SOG and SPZ have no place for the lobe data.
Scope: lobes only, not the Beta kernel:
Deformable Beta Splatting has two parts: the Spherical Beta color lobes, and the Beta kernel, which replaces the Gaussian falloff with opacity * (1 - r²)^beta and a hard cutoff. This PR only adds the lobes.
The kernel would be much harder. It changes the splat shape, so it touches every renderer (quad, compute, shadow, picking), the quad extent and the bounds / culling math. It also needs another per-splat value, and SOG / splat-transform support.
It most likely brings less. The paper's ablation puts the kernel at +0.16 to +0.21 dB PSNR, against +0.07 to +0.22 dB plus a 55% smaller file for the lobes.
Only the paper's own code trains the kernel; gsplat#1056 keeps Gaussians. Files using the kernel, such as the paper's pretrained scenes on Hugging Face, won't render correctly with this PR.
Examples:
gaussian-splatting/viewer sets app.scene.gsplat.colorUpdateAngle = 0. View-dependent color (SH or lobes) is then re-evaluated on every frame the camera moves, instead of in 10° steps, so highlights can be compared exactly.
Try it:
Viewer: https://engine-ipzsitwwq-playcanvas.vercel.app/#/gaussian-splatting/viewer
Drag one of these sample PLYs into the viewer, then reload the page before dropping the other. Both are the same bonsai scene, trained separately by the author of the PRs above:
SH0_SB2.ply: SH degree 0 + 2 lobes (49 MB)
SH3_SB0.ply: SH degree 3, no lobes (111 MB)
The scenes are not axis aligned, so the orbit camera behaves strangely around them.
