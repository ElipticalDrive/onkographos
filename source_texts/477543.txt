Feature request: a Points primitive (add_points)
The viewer has add_polyline, add_mesh, add_toolpath, and the primitives, but no GPU point-cloud primitive. Today, showing a large set of unconnected points (a voxel field, a deviation/metrology cloud, a scan) has no good path: add_polyline connects them, and one box/sphere per point is far too heavy.
Why
Sibling project jeroens-huis already proves the simple approach works: it renders 7.4M LiDAR points with a single THREE.Points + a tiny size-attenuation shader (gl_PointSize = size * (k / -mvPosition.z)) and per-vertex colours — smooth, no LOD needed. That's exactly the primitive missing here.
Driver use case (mill-sim): visualise CNC material-removal results as voxel-state / cut-surface point clouds coloured by signed deviation (metrology heatmap), and progressively reveal points as a cheap material-removal animation (drawRange over the buffer). Mesh works for shaded "resulting shape" beauty shots; points are better for raw state, per-point scalars, and animation.
Proposed API (mirrors add_polyline's binary transfer)
```
v.add_points(
    "cloud",
    positions,                 # (N, 3) float32
    colors=signed_dev,         # (N,) scalar -> colormap, or (N,3) RGB; or None
    colormap="viridis", cmin=None, cmax=None,
    color=0xFFFFFF,            # used when colors is None
    size=2.0,                  # base point size (px)
    size_attenuation=True,     # perspective shrink with distance (jeroens-huis shader)
    parent=None, pickable=False,
)
```
Binary transfer of positions (+ colors) like add_polyline.
Per-vertex colours via the same _apply_colormap path already used by add_polyline.
A set_draw_range(id, count) (or reuse the existing draw_range animation channel) so points can be revealed over frames.
Reference implementation to copy
jeroens-huis/dist/lidar_viewer.html (~lines 205–234): THREE.BufferAttribute position+color, a ShaderMaterial with gl_PointSize = pointSize * (300.0 / -mvPosition.z), new THREE.Points(geometry, material).
Scope / non-goals
Flat THREE.Points covers ≤ ~10M points comfortably (jeroens-huis @ 7.4M).
Octree / Potree-style LOD for >10M points is a separate, later tier — not part of this request.
Acceptance
add_points renders an N×3 cloud with per-vertex colours and distance-attenuated size at ≥7M points / 60fps.
Example + a line in the README feature list.
