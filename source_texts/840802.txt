// TODO: Currently projection only performs spherical harmonics evaluation on input SH/features,
The Gaussian projection pipeline currently always evaluates spherical harmonics on the input SH/feature tensors. This means that functions like renderContributingGaussianIds, which need to render a non-SH quantity (integer IDs), must go through projectGaussiansImpl and pay for a full SH evaluation whose results are then discarded.
Desired behavior:
Allow rendering of arbitrary per-Gaussian feature tensors (any dtype/shape) without requiring SH evaluation — i.e. a "passthrough" shading model.
Longer-term, support pluggable shading models during projection so that SH is just one option alongside raw feature passthrough or future alternatives.
Current workaround:
renderContributingGaussianIdsImpl calls the existing projection path (which evaluates SH) and then ignores the SH output, passing hard-coded Gaussian IDs to a dedicated "deep IDs" rasterize kernel. This wastes compute on the unused SH evaluation.
Challenges / scope:
Much of the existing code assumes sh0/shN tensors are the primary per-Gaussian features. Supporting an additional feature tensor alongside (or instead of) the SH tensors would require refactoring that assumption in multiple places.
Reference: src/fvdb/GaussianSplat3d.cpp, renderContributingGaussianIdsImpl (~line 1100)
