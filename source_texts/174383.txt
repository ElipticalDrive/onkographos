Implementing greedy meshing questions
Question
Hello. I've been working on implementing greedy meshing into my simple voxel game (engine?) and I've encountered two obstacles.
First off, I've got the greedy meshing working (perfectly?) I don't need help with that, I don't think.
My issue is how the hell do I iterate over the 3 dimensions in 6 different directions.You've got to merge all blocks in the XY axis together front and back faces as well as the XZ and YZ axes. I'm currently testing with merging only the XY axis with the front face.
A "solution" to my issue that I wanted feedback or suggestions on would be a loop that iterates 6 times (north, south, top, bottom, left, right face or whatever) I assign 3 intermediate variables that control access to a visible faces array and I change what each of the 3 intermediate variables look at depending on the face.
Not sure how well I explained that, so I'll try illustrating with an example.
I'm currently doing:
```
for (x = 0; x < CHUNK_SIZE; ++x)
{
    for (y = 0; y < CHUNK_SIZE; ++y)
    {
    	for (z = 0; z < CHUNK_SIZE; ++z)
    	{
	    GreedyMesher(x, y, z, BlockRotation::NORTH);
    	}
    }
}
```
And my idea is:
```
int *i, *j, *k;
int x, y, z;
for (int face = 0; face < (int) BlockRotation::WEST; ++face) // WEST = 6 here
{
    if ((BlockRotation) face == BlockRotation::NORTH || SOUTH)
    {
    	i = &x;
    	j  = &y;
    	k = &z;
    }
    else if ((BlockRotation) face == BlockRotation::WEST || EAST)
    {
    	i = &y;
    	j  = &z;
    	k = &x;
    }
    else
    {
    	i = &z;
    	j  = &x;
    	k = &y;
    }
    for (x = 0; x < CHUNK_SIZE; ++x)
    {
    	for (y = 0; y < CHUNK_SIZE; ++y)
    	{
    	    for (z = 0; z < CHUNK_SIZE; ++z)
    	    {
	        GreedyMesher(i, j, k, (BlockRotation) face);
    	    }
    	}
    }
}
```
I, j & k aren't likely to be set to the right axes I just chose random ones for the illustration.
Hopefully the example gets across what I'm trying to say. Not sure how else to really try explain. I can try again in the comments if you want
The second issue I'll encounter as soon as I make the world interactable is altering or regenerating the mesh and wanted advice on how to deal with this.
I've thought of two solutions.
The first solution is simply recreating the entire mesh from scratch including the visible faces vector I use as a temporary medium between chunk -> mesh. Sounds slow though so not really sure on this solution.The second solution is trying to edit the visible faces vector and rebuilding the mesh from that. Still slow but atleast I don't have to recreate the visible faces vector. However, I'm not sure this is really possible. Couldn't changing one block cause a massive cascading effect where the entire greedy mesh needs to be rebuilt or am I over thinking the complexity of changing a face?Would love to hear how others have implemented this.

You probably will want to iterate in different directions on some axes so you do not have flipped triangles, and know in which direction the normal is. Personally I templated it so I can do meshing in UV space and check for visibility at the same time. (This does not do greedy meshing but the same idea applies)
The general wisdom to is to just throw away the chunk mesh and whatever visiblity info you might have and rebuild. Keep your chunk mesh at a size this will not be costly.
