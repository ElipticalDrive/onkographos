This PR adds GPU implementations of cucim.skimage.measure.marching_cubes and cucim.skimage.measure.mesh_surface_area for CuPy arrays. This resolves #332.
marching_cubes extracts triangular isosurfaces from 3D volumes and follows the scikit-image API for the supported options, including level, spacing, gradient_direction, step_size, allow_degenerate, method, and mask. method="lewiner" (the scikit-image default) and method="lorensen" are implemented, and method="vega", which is not in scikit-image (see below). The Lewiner mesh has exactly the same number of vertices and faces as scikit-image's on every volume tested, including noise volumes that contain millions of ambiguous cells.
mesh_surface_area computes the surface area of triangular meshes produced by marching_cubes using a CuPy reduction kernel.
On an RTX A6000 the GPU implementation is 14-17x faster than scikit-image for 64^3 volumes, 69-88x for 128^3, 113-175x for 192^3 to 384^3 volumes with a simple isosurface, and 290-590x for volumes with large, noisy isosurfaces (see Benchmark results).
Differences from scikit-image
These are also listed in the docstring of marching_cubes.

Supports additional, more modern method=vega in addition to the method=lewiner and method=lorensen approaches of scikit-image.
The vertices and faces of method="lewiner" and method="lorensen" are the same sets as scikit-image's, in a different order.
normals have the sign of scikit-image's, but a vertex on an edge gets the interpolated central-difference gradient of its two samples (scikit-image sums the gradients of the cells around it); values is the larger of the two sample values of the edge (scikit-image uses the range of the cells around the vertex). Neither is equal to scikit-image's. The reason is the vertex generation: one thread per crossed edge computes its vertex from the two samples at the ends of the edge, without visiting the cells around it. scikit-image accumulates the normal and the value of a vertex over every cell that emits it (up to four in 3D, and which cells do depends on the method's triangulation). Reproducing that would need an additional pass over the cells with atomic additions, which was not built or measured. The normal chosen is the usual one for a point on an edge: smooth and independent of how many cells share the vertex.
verts is float32 and faces int32 (scikit-image returns float64 verts for a non-unit spacing and int64 faces with allow_degenerate=False).
A volume that contains NaN raises a ValueError.
The level is used as a float32 by the kernels.
allow_degenerate=False can give different counts for volumes with samples equal to the level (scikit-image's vertices at samples have errors of about 1e-16, so it misses coincident vertices).
method="vega" is not guaranteed to give a manifold mesh (some noisy volumes have edges shared by four triangles), although each cell has the topology of its trilinear interpolant.

Implementation Approach
The implementation uses CuPy RawKernels and scan-based allocation: no kernel appends to an output with atomics, so the mesh is deterministic and every output array is allocated once at its final size. For one call the steps are:

Validate and prepare. Convert the volume to contiguous float32, check level against the data range and apply step_size by subsampling. The kernels index the nodes, cells and output arrays with 32-bit integers, and with 64-bit integers (compiled as a second variant of each kernel) when three times the number of nodes, cells, vertices or faces reaches 2**31, which is a volume of about 715 million voxels (894³). Volumes of over 2 billion voxels were checked (a 1300³ sphere, all three methods). The vertex ids are int32, so a mesh with 2**31 or more vertices or faces raises a ValueError.
Classify edges, one thread per grid node. Each thread tests the three edges that leave its node (along the three axes) and writes a 3-bit crossing mask and the number of crossed edges (uint8 each). With a mask, an edge only counts when it belongs to a cell whose mask is set.
Number the crossed edges. An inclusive scan over the per-node counts gives node_scan; the vertex id of a crossed edge is node_scan[node] - popcount(mask[node] >> side). Scanning per node rather than per edge makes the scan 3x smaller, and no separate array of vertex ids is stored. All scans of uint8 counts in the pipeline use a block scan (sums of blocks of 1024 counts, a scan of the block sums, and a scan inside each block with the block offset added), which gives the same values as cp.cumsum in half the time for 256^3 entries (0.17 ms against 0.34 ms); below about 2.6 million entries cp.cumsum is used because it is faster there. A small compaction kernel (one thread per node) writes the flat index of each crossed edge at its vertex id.
Generate vertices, one thread per vertex. Position by linear interpolation along the edge, a normal from the interpolated central-difference gradient, and the values output (the larger of the two edge values).
Count triangles, one thread per cell. uint8 triangle counts, and a scan gives each cell's output offset.
Generate faces, one thread per cell. Triangle indices are looked up and written at the cell's offset, with the winding flipped for gradient_direction.
allow_degenerate=False. Zero-area faces are found in parallel, coincident vertices are merged with a lock-free union-find, and the vertex and face arrays are compacted with scans (a no-op early return when no face is degenerate).

The code shared by both methods (validation, step_size, the edge classification, numbering and compaction kernels, the vertex kernel, the volume and gradient helpers, and degenerate-face removal) is in _marching_cubes_common.py. Each method supplies its crossing test (mc_crosses, which is now the same for the three methods: a sample equal to the level is below it, as in scikit-image). _marching_cubes_lorensen.py holds the classic 256-entry triangle table and the Lorensen counting and face kernels (steps 5-6).
The Lewiner path replaces steps 5-6 as follows. The counting kernel looks up the case and configuration of each cell and resolves the ambiguous cases (3, 4, 6, 7, 10, 12 and 13) with the face and interior tests of the Lewiner algorithm, evaluated in double precision, in the same operation order as scikit-image where the values allow it (the count kernel reads the sample values and the level as float32, so a sample or level that is not exactly a float32 can be classified differently from scikit-image, which keeps the level as a double). This is done once per cell: the kernel stores the triangle count, a "needs a center vertex" flag, and the offset of the cell's edges in a single concatenated triangle table (a uint16 per cell). A second kernel creates the center vertices (for the cells that need one) and writes them after the edge vertices in the same vertex, normal and value arrays. The face kernel is then a plain table lookup with no ambiguity tests and no double-precision work.
method="vega" is the marching cubes 33 implementation of Vega, Abache and Coll (J. Computer Graphics Techniques 8(3), 2019), whose interior test is corrected: it is made on a diagonal of the cell on the plane through the saddle point of the trilinear interpolant, so that the topology of the mesh does not depend on the orientation of the field (the Lewiner method gives different topologies for some cells and their mirror images), and it has the two patterns of the case 13.5.2. The counting kernel resolves each cell once, as for Lewiner, with the case selection of the MC33 C library of Vega and Abache (MIT; ported with the help of the CUDA port in the isoext project, MIT) and its 2310-entry lookup
table, and everything else is shared. The default stays lewiner, which matches scikit-image.
All methods support masks (in classification and counting), step_size and spacing.
Lorensen was implemented first because it is the simpler classic algorithm and provided the GPU data layout. The Lewiner path was added afterward to provide the topologically consistent behavior that scikit-image uses by default. Both methods are kept for API compatibility: method="lorensen" is part of the scikit-image API, and the Lorensen kernels are somewhat faster on noisy data (see below). The two meshes differ in topology (different Euler characteristic on noisy data, for example), not in watertightness: the classic table also gives meshes without open edges on the volumes tested.
References and Licensing
Licenses and attributions were added for some reference codebases:

The MC33 C library of Vega and Abache (MIT) and the isoext project of Guangyan Cai (MIT): the case selection and the lookup table of method="vega" are a port of the library's, made with the help of isoext's CUDA port, and are credited in LICENSE-3rdparty.md and in the file headers.
NVIDIA Warp, as a design reference for allocating the output from prefix scans rather than atomic appends. The reference is the legacy native CUDA marching cubes (warp/native/marching.cu) of Warp versions 1.6.2 to 1.7.2, the releases under Apache-2.0 (Warp was relicensed on 2025-03-06 and replaced this implementation in version 1.8.0).

The kernel code does not come from any of th above projects. The Lewiner path (case tables, ambiguity tests, center vertex) is derived from the scikit-image implementation, which is also the behavioral reference for validation, output conventions and supported API semantics.
Testing
Tests (120 in test_marching_cubes.py, test_marching_cubes_kernels.py and test_marching_cubes_vega.py) compare behavior against scikit-image across representative volumes and options: Lorensen and Lewiner, allow_degenerate=True and False, step_size, masks, spacing, gradient direction, and surface-area calculation.
The kernel-level tests check, for each of the 256 binary cases and the ambiguous branches (including center-vertex cases), that the face-generating kernels produce the triangles of a
Python port of scikit-image's reference selector. Noisy volumes (white and smoothed, with level 0 and 0.1) check that the Lewiner mesh has the same number of vertices and faces and the same surface area as scikit-image's. The 64-bit kernels are run on small volumes (by lowering the limit) and give meshes that are bitwise equal to the 32-bit ones, for the three methods, with and without a mask and with and without removal of the degenerate faces; a 900³ sphere (above the old limit) is checked against the radius and the area of the sphere (skipped when less than 16 GB of device memory is free).
The tests of vega check that the case selection equals that of the reference code (144 reference cells), that the topology of single cells and of closed random fields equals that of the trilinear interpolant on a finer grid, that it does not depend on the 48 symmetries of the cube, and the examples of the paper.
For allow_degenerate=False the geometry is preserved, but which of several coincident vertices survives (and so the exact vertex count in rare cases) can differ from scikit-image's sequential post-processing; for example, one extra vertex in 12.6 million on a 384^3 noise volume. This is noted in the docstring.
