Volume Rendering with CSS 3D Transforms
January 29, 2011
HTML5 is everywhere and even has a really fancy logo now – good enough of a reason for me to have a closer look on some of the new features. Because I wanted to do something in 3D – but without jumping into WebGL – I ended up reading the documentation of CSS 3D transforms.
There is a plethora of “cube” and “carrousel” demos out on the net, but while this is all nice and dandy it really felt limited. No wonder, CSS 3D transforms is limited – it basically allows you to texture-map a quad and move it in 3D space. So, what more than simple cubes or carrousels do you expect?
Well, how about real-time Volume Rendering?
Play the movie on the right to see a screen capture of a 1283 volumetric data set – an engine block (courtesy of GE) – rendered in real-time in Safari using pure CSS3 3D transforms.
Or even better, if you are surfing with any kind of Safari-based browser (i.e. Desktop Safari or the iOS browser), don’t hesitate and click the following link to see it in full action (give it a little time to load and feel free to rotate the volume via mouse or touch)…
Open Volume Rendering demo in new window (Safari only)
Implementation Details
The implementation is based on the idea of texture-mapped volume rendering as described in “Accelerated volume rendering and tomographic reconstruction using texture mapping hardware” by Cabral et al. from 1994. These slides have a good explanation of how it works.
The volume is basically sliced up along its three dimension vectors and rendered by drawing rotated quads with the slices texture mapped on them. Depending on the viewing angle, we show the set of quads (either along the volume’s x, y, or z axis) with the least artifacts. My first attempt of showing/hiding the different quad sets was by changing their display property in CSS, but that introduced a noticeable lag when switching from one set to another – especially on embedded devices. It turned out that making the “inactive” quad scale down to a size of 0 was working much better.
Because I use the WebKit-specific JavaScript class WebKitCSSMatrix it is unlikely to get this working on Firefox, Opera, or Internet Explorer without changing the code (but that should be simple, just fork the project on GitHub and exchange the aforementioned class by your own 4×4 matrix implementation).
I tested the code on the WebKit-based browsers Safari and Chrome. All Safari-based browsers are giving very good and fast/interactive results, but to my surprise the rendering in Chrome is incorrect and seems to be significantly slower. Most of the time Chrome just doesn’t display anything, though – please let me know if you figured out how to get it working.
And now, feel free to play around with the code…
