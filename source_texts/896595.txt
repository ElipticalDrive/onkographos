Update (2026-11-03)
Better title: Volume rendering: choose the supported backend; ViewScene has none, OSPRay and VTK paths are both optional and limited
Better description
Tuvok is gone from the plan, per the 2016 comment. The native ViewScene renderer has no volume path. Two optional ones exist, both default OFF (Superbuild/Superbuild.cmake:150, Superbuild/Superbuild.cmake:160):
OSPRay (ShowFieldWithOspray, OsprayViewer): structured volumes render (OSPRayRenderer.cpp:173). The algorithm also emits UNSTRUCTURED_VOLUME (OsprayDataAlgorithm.cc:414), but the renderer has no case for it, so hex/tet volumes hit the default and are dropped silently. Both OSPRay CI jobs are if: false (ccpp.yml:90, mac.yml:113). It cannot currently be built from source (OSPRay cannot be built from source: OsprayExternal.cmake depends on TBB/RKCommon/Embree externals deleted in a844a8e63 #2751, open), and src/CMakeLists.txt hardcodes the 2.0.1 path (CMakeLists.txt:340).
VTK (ShowFieldVtk + ViewSceneVtk): a "Show Volume" option drives vtkSmartVolumeMapper (src/Interface/Modules/Render/Vtk/VtkRenderer.cc:290), but only for latvols (src/Core/Algorithms/Visualization/VtkGeometryBuilder.cc:714). addUnstructVol (src/Core/Algorithms/Visualization/VtkGeometryBuilder.cc:891) never reads that option. WITH_VTK has CI jobs (ccpp.yml:79).
I read this code but ran neither path, so image quality and transfer-function behavior are unassessed. Correction to the 2026-06 triage: of #2486-#2491, only #2491 concerns rendering, and it is about the offscreen renderer, not volumes.
Concrete steps
Decide which backend is the supported volume path. The 2019-2020 comments here name OSPRay; the open "VTK renderer" milestone now exists as well.
If VTK: decide whether it needs to be on by default for this feature to count; add addUnstructVol volume support or document latvol-only; add a regression net.
If OSPRay: fix OSPRay cannot be built from source: OsprayExternal.cmake depends on TBB/RKCommon/Embree externals deleted in a844a8e63 #2751, re-enable a CI job, and add a case for UNSTRUCTURED_VOLUME in OSPRayRenderer or stop emitting it.
Either way, make unsupported field types report a module warning rather than draw nothing.
Retitle; this has been a placeholder since 2017, so list the chosen backend's tasks here.
Status: needs maintainer decision - two partial implementations exist off by default, and the choice of backend determines all remaining work.
