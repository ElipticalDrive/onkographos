Motivation
The batched Montgomery inversion path introduced earlier left the scan phase as the dominant ALU/barrier overhead, so the goal was to reduce scan work and VGPR pressure to improve RX 6800 throughput.
Changes aim to maximize RDNA2 occupancy and headroom for further tuning while keeping the hot path functional and avoiding new files.
Description
Replaced the Hillis–Steele inclusive prefix/suffix scan in shader.comp with a Blelloch (upsweep + downsweep) exclusive scan to reduce overall fe_mul work from O(n log n) to O(n).
Kept local_size_x = 128 and the existing DontInline strategy for fe_mul/fe_sq (post-processing via the build script) to control VGPR pressure and preserve the per-thread sequential accumulation optimizations.
Implemented reversed-indexing for the suffix array (rid = WG_SIZE - 1 - lid) so both prefix and suffix results are produced in the same upsweep/downsweep flow, and kept a single workgroup inversion combined with prefix/suffix products to produce per-item reciprocals.
All changes are confined to the functional shader hotpath (shader.comp) with no extra files added and no behavioral changes outside the inversion/scan algorithm.
Testing
Attempted a full build with make (make clean && make), but it failed in this environment due to missing Vulkan headers (vulkan/vulkan.h) so the host binary did not compile. (failed)
Attempted shader compile with ./build_shader.sh, but it failed because glslangValidator was not present in the environment so a SPIR-V build could not be produced. (failed)
No runtime GPU benchmarks were executed here because the environment lacks the required Vulkan toolchain and runtime; expected real-dGPU gains must be validated on an RX 6800 hardware setup with shader SPIR-V built via ./build_shader.sh.
