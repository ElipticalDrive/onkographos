Custom
Frustum Culling Bounding Volume in Three.js
This article explains how to define a custom bounding volume for
meshes in Three.js to manually control frustum culling behavior. By
overriding the default bounding sphere calculated by Three.js, you can
prevent objects with displaced vertices from disappearing unexpectedly
or artificially trigger early culling to optimize rendering
performance.
Understanding Three.js
Frustum Culling
Three.js automatically applies frustum culling to any
Mesh where the frustumCulled property is set
to true (which is the default). During the render pass, the
engine checks whether the mesh's bounding volume intersects the camera's
view frustum.
By default, Three.js uses the geometry's boundingSphere
for this test. If a vertex shader moves vertices far outside their
initial positions (such as with GPU grass, ocean waves, or cloth
simulations), the default bounding sphere will not encompass the
displaced mesh, causing it to disappear while still within view.
Setting a Custom Bounding
Sphere
To define a custom bounding volume, assign a new instance of
THREE.Sphere directly to
geometry.boundingSphere:
```
import * as THREE from 'three';

const geometry = new THREE.PlaneGeometry(10, 10);
const material = new THREE.MeshStandardMaterial();
const mesh = new THREE.Mesh(geometry, material);

// Define a custom bounding sphere with a center and a radius
mesh.geometry.boundingSphere = new THREE.Sphere(
  new THREE.Vector3(0, 0, 0), // Center in local coordinates
  25                          // Radius large enough to account for vertex displacement
);

// Ensure frustum culling is enabled
mesh.frustumCulled = true;
```
Preventing
Overwrites from Internal Computations
Certain loaders, modifiers, or updates might trigger
geometry.computeBoundingSphere(), which calculates the
sphere based on raw vertex positions and overwrites your custom
sphere.
To permanently preserve your custom bounds, override the
computeBoundingSphere method on that specific geometry
instance:
```
// Lock the custom bounding sphere
mesh.geometry.boundingSphere = new THREE.Sphere(new THREE.Vector3(0, 5, 0), 50);

// Prevent future computations from resetting it
mesh.geometry.computeBoundingSphere = () => {};
```
Expanding an Existing
Bounding Sphere
If you only need to add padding to the existing geometry boundaries
rather than manually calculating center points, compute the default
sphere first and expand its radius:
```
// Compute the initial bounds based on geometry attributes
mesh.geometry.computeBoundingSphere();

// Add padding to handle vertex shader inflation or displacement
const padding = 15;
mesh.geometry.boundingSphere.radius += padding;
```
Custom Bounding Boxes
While Three.js uses boundingSphere for standard frustum
culling in WebGLRenderer, you can also define a custom
boundingBox for custom culling scripts, raycasting, or
physics integration:
```
mesh.geometry.boundingBox = new THREE.Box3(
  new THREE.Vector3(-20, -5, -20), // Min corner
  new THREE.Vector3(20, 15, 20)    // Max corner
);

// Prevent computeBoundingBox from resetting it
mesh.geometry.computeBoundingBox = () => {};
```
Overriding the boundingSphere is the most efficient and
standard method to control frustum visibility in Three.js without
resorting to disabling frustum culling entirely via
mesh.frustumCulled = false.
