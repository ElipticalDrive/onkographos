What this PR is, and why
Test-only. In 14.0 the GPU builders' default output buffer changes from the dual DeviceBuffer to cuda::Buffer<std::byte> (#2232). Until now, Dilate, Merge, Prune, Refine, Coarsen, MeshToGrid (including the UDF sidecar), indexToGrid and addBlindData were only ever tested with the dual buffer.
These tests build each builder into both buffer types and require byte-identical, non-empty grids, so the single-space path is verified against the tested one before it becomes the default. The inputs reach the multi-node paths: two root tiles and upper nodes, a prune that removes leaves (asserted exactly), and chained blind data so existing metadata is shifted.
It also covers three entry points nothing instantiated before:
the maximum-points-per-voxel pointsToGrid overload
tools::cuda::createNanoGrid
the typed evalChecksum
A probe that instantiates and links every previously uninstantiated entry point found no further defects.
Testing
All single-GPU suites pass on an RTX PRO 6000 Blackwell with nvcc 12.6.

```
The equivalence helper accepted two identically empty grids, and several
inputs were too small to reach the builders' multi-node paths. The helper
now requires active voxels and returns the host image; the coordinates
gain a negative voxel so every builder sees two root tiles and upper
nodes; the density-targeted points are mirrored across the origin; and
addBlindData runs twice, so the path that shifts existing metadata is
compared too.

The Prune comment described its mask wrongly: retaining voxel 0 of each
leaf keeps exactly (0,64,0) and (0,0,2048), which the test now asserts.
Uploads go through an owning cuda::Buffer rather than a copyable raw-
pointer holder whose failures did not stop the test, the typed
evalChecksum comment claims only what is compared, and the banner and
include comment describe the new tests.
```

NanoVDB: make the single-space builder tests check what they claim (C…

3a5f545
```
…UDA)

The device checksum test now also compares against the host checksum of
the grid's host image, so the two device overloads cannot agree on a
wrong value. The createNanoGrid test compares its grid byte for byte
with indexToGrid's instead of discarding both. The density-targeting
pointsToGrid test asserts that the voxel size shrank, that the grid
spans two root tiles, that every point landed in a voxel, and that the
densest voxel is within the tolerance of the target; it uses scattered
points from a fixed sequence, since a regular lattice's densities jump
in steps the voxel-size search cannot land between.

Share the byte comparison (with its empty-buffer guard) and the indexed
input setup between the tests.
```
