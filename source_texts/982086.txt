The existing endpoint nudges in both marching-cubes implementations violate the linear edge-lift identity used by Jacobson's conservative-offset proof. Add opt-in RootfindingModes.LinearEdges without changing legacy mode values or defaults. This mode retains linear crossings, clamps rounding to the grid edge, throws InvalidOperationException on a crossing on a grid corner or a collapsed triangle (a throw on a rejected triangle stays as a guard) and ArgumentException for non-finite values, also from the parallel paths (InvalidOperationException preferred when several cells fail), and bypasses Pro's float sample cache. In Pro it refuses, with ArgumentException before any work, a cube size that is not finite and positive, a grid beyond its 16-bit corner/edge hash (more than 65535 cells per axis for Generate(), 65534 for GenerateContinuation(), which also visits the cell of index n) and a continuation seed outside cells 0 to n; so no silent hash aliasing remains in this mode. Legacy modes are unchanged. The enum doc states the preconditions; docs/OPERATIONS.md lists the mode.
The pilot checks all 256 active table rows combinatorially (closed high-side oriented boundary chains, matching neighbour faces) and proves small lift and normalized FP-envelope lemmas. The continuous enclosure theorem comes only from Jacobson, arXiv:2609.13430v1. The resulting certificate is conditional winding enclosure; it does not certify embeddedness or arbitrary SDF approximations. The coupling to the C# source is a whole-file SHA-256 review tripwire, not a semantic check: that find_iso matches the FP model, that shared crossings are bit-identical in neighbouring cells and that no FMA contraction happens are review obligations, backed by the native tests.
The recipe requires exact Cartesian grid nodes, normalized sample/coordinate bounds, a minimum crossing gap, the complete target zero set inside the actual extraction grid, all outer boundary samples high, and an uncanceled full extraction (Generate(); the continuation is excluded). It gives a deliberately loose 2^-26 level pad under those conditions. Approximate samples require a quantified evaluation bound and sampled-edge slope bound. These conditions and the composed proof are in tools/Z3Pilot/README.md; the initial table/placement audit is in docs/design/CONSERVATIVE_MC_AUDIT.md.
Validation:
Pilot: table certificate over 256 rows; 260 UNSAT queries with SAT assumptions: the edge-identity and nonnegative-product lemmas, 256 instances of one trivial linear lift lemma (elementary algebra, per case only tied to the parsed node list) and two FP envelopes. Non-vacuity comes from the two SAT controls (subthreshold sphere, wrong placement), replayed exactly. Per-query timeout from Z3_PILOT_TIMEOUT_MS (default 20 s, CI 120 s).
Native: --filter MarchingCubes 72 tests pass, including new ones: invariance of Generate() in LinearEdges over Similarity.All() for MarchingCubes and MarchingCubesPro, serial and parallel (2^k scales bit for bit, parallel equals serial, repeated runs); LinearEdges in MarchingCubes_ParallelIdsMatchSerialAndReuse; a grid node on the level throws InvalidOperationException in all four paths; simultaneous slab failures throw it from both parallel paths; Pro refuses grids beyond its hash (the reviewers' aliasing repros for Generate and GenerateContinuation, serial and parallel), the Generate limit is exact on each axis (65535 cells valid, 65536 refused), continuation seeds outside the grid (cells -1 and n + 1) are refused while the extreme cells 0 and n are accepted, and invalid cube sizes are refused; the collapsed-triangle path of MarchingCubes (a grid that is not exactly representable). Within these limits every visited grid edge has its own vertex and by the case table no edge between two crossings is used by more than two triangles, so the rejected-triangle guard is not expected to fire.
Mutations (restored afterwards): disabling the parallel unwrap fails 4 tests (3 runs); an absolute offset in the crossing fails 5 invariance tests; removing the Pro grid limit fails 6 tests, the continuation limit 65535 fails 2, an off-by-one y limit fails 2, removing the cube-size check fails 4, removing the seed check fails 4 and moving either seed bound by one fails 2; dropping the collapsed throw fails 2; restoring the legacy nudge fails 10; ignoring Z3_PILOT_TIMEOUT_MS fails the new pilot test.
All Python pilots: 24 tests, 1 skipped (existing D1 TODO). New solver tests run in child processes.
Library builds for net10.0 and netstandard2.0, net48 test compilation and dotnet pack API validation pass. Commands, exit codes and counts (no logs, no absolute paths) are in tools/Z3Pilot/results/conservative-mc-validation.json.
Three independent review rounds; their findings are addressed. Follow-up (owner decision 2026-11-08, ROADMAP research.md): a relative error model for the FP obligation instead of the gap >= 2^-20 and |f| <= 1 preconditions, in a separate PR. Separate ROADMAP item: out-of-range access of GenerateContinuation at the upper grid edge and for seeds outside the bounds in the legacy modes.
The optional unreduced --direct nonlinear zero-point model is included. The recorded 100 ms/query experiment proves only the all-low case and leaves 255 cases UNKNOWN. Those UNKNOWN results are not proofs; the documented recipe uses the modular certificate and explicit mathematical bridges.
Draft pending the full repository CI gates. No merge requested.
