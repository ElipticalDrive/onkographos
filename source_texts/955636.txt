Problem
There is no way to generate placeholder or concept meshes from a prompt or a reference image.
Behavior
A Studio tool sends a prompt or an attached image to Meshy or Tripo with the user's own API key. Meshy is the default. It polls the task, downloads the result as GLB with PBR textures, and imports it with ue-mcp's existing asset import as a Static Mesh with materials and textures under a chosen content folder. It runs in the background with progress, like a subagent.
Neither vendor offers a sign-in for third-party clients, so each takes an API key in Settings. The key stays on the user's machine and goes only to that vendor.
Meshy: request glb with enable_pbr: true. Text runs preview then refine. Image runs in one task with should_texture: true.
Tripo: request pbr: true and download the GLB. FBX goes through its convert task.
The tool downloads as soon as the task succeeds. Meshy deletes API outputs after 3 days.
Settings says that commercial ownership of outputs needs a paid account with that vendor.

Rejected:
Rodin (Hyper3D): API access only on the Business plan at $96 to $120 a month, too high a floor for a user's own key. https://hyper3d.ai/pricing
Stability (Stable Fast 3D, SPAR3D): image only, GLB only, no text input and no full PBR map set. Cheap at $0.04 to $0.10. https://docs.stability.ai/pricing
Tencent HY 3D Global (Hunyuan3D): terms 5.4(d) bar commercial use without Tencent's written consent, 6.3(d) let Tencent watermark output, and auth is Tencent Cloud request signing. https://www.tencentcloud.com/document/product/301/78149
Luma: the public API has no 3D generation, only image and video. https://docs.agents.lumalabs.ai/

A live import of a generated mesh from each provider against a published release.
