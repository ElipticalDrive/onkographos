Recommendation: MERGE
Summary: This prerequisite adds checked Morton mapping and generated compute GLSL for packed Z24S8 alias conversion. It has no runtime caller by itself, so it does not prove a gameplay speedup. It is refreshed onto #284's owned-readback repair, and its header now states the bounds and device checks required of a future dispatcher. The prerequisite parents are now merged; both exact-head CI workflows are green.
Remaining: None for this unused mapping primitive. Both exact-head workflows pass all 44 jobs; source review and focused mapping/shader tests pass. Native consumer gates remain owned by their later layers.
Problem
Conker's large linear depth surface and small swizzled view share guest bytes. Reinterpreting the image's first pixels would not preserve the small view's Morton layout. A checked mapping primitive is needed before a GPU-only conversion can avoid synchronous readback.
What this PR changes
surface-alias-map.c/.h adds a checked 2D Morton index and generated Vulkan compute source mapping guest-order packed words into linear packed words. The helper rejects zero/non-power-of-two dimensions, invalid coordinates and products beyond UINT32_MAX.
The header requires the dispatcher to validate dimensions/products, source/destination byte extents, descriptor ranges and selected device workgroup/dispatch limits before recording commands. Shader generation cannot validate later push constants. Tests compare square and rectangular mappings with the maintained guest swizzle routine and compile generated GLSL. Existing design/implementation documents describe the later runtime work; this slice changes no surface ownership or guest rendering path.
Why this approach
The mapping is separately testable before adding GPU ownership and barriers. It preserves layout semantics and lets unsupported aliases fall back. Bounds belong at dispatch because the generator does not receive actual push constants or buffer extents.
Validation
Parent merged main 10db341dacaf1a73e148bd2ec615ad7c2b753cf3; candidate 3661acb4234bf395b7ced90cb9dc8a78ed7ae33b. Its full tree equals independently reviewed/tested 828d7ea5643f42371ec730930d8babe4a86bd52d.

Actual generated workgroups 1 and 256: GLSL compiled with glslc, SPIR-V validated with spirv-val.
Current descendant nv2a/vk: bound packed depth alias compute dispatch #287's maintained glslang/reflection fixture also compiles the unchanged generator for 1/64/256 and checks its binding contract.
Diff whitespace check passes. Refreshed exact-head push/PR CI:44/44 successful jobs. Independent source review found no blocker.
Strict -Wextra compilation exposed existing signedness warnings in unchanged swizzle.c; production-compatible -Wall -Werror fixture builds and passes. No unrelated swizzle cleanup is included.
SPDX remains LGPL-2.0-or-later, matching the renderer's existing LGPL 2-or-later license; the older generic checkpatch allow-list does not list this valid identifier. It was not changed to a different license merely to silence that checker.

Review verdict: HOLD / good prerequisite, but fix hygiene and pin caller constraints
This PR is a source/test prerequisite only; it does not change runtime behavior. The Morton mapping helper and generated GLSL are useful, but I would keep the PR draft until the shader/caller contract is explicit and the new-file hygiene is cleaned up.
New-file license tag likely needs checkpatch confirmation
Both new files use:
```
/*
 * Vulkan depth surface alias layout
 * SPDX-License-Identifier: LGPL-2.0-or-later
 */
```
Elsewhere in this repo/QEMU-style code, new files often need the exact SPDX form accepted by the project checkpatch configuration. We recently hit this on another PR where LGPL-2.0-or-later was not accepted for new files. Please run the project checkpatch path or switch to the accepted identifier before this gets promoted.
Generated GLSL assumes the dispatcher already enforced all bounds
The shader performs the multiply and index math directly:
```
uint index = gl_GlobalInvocationID.x;
if (index >= width * height) return;
dst[index] = src[guest_index(index % width, index / width)];
```
The C helper correctly rejects non-power-of-two dimensions and width * height > UINT32_MAX, but the generated shader itself has no independent guard. That is fine only if every runtime dispatcher refuses invalid dimensions before pipeline dispatch. Please make that contract explicit in the header comment and keep a dependent test that proves the runtime caller rejects bad width/height, insufficient buffers, and descriptor-range overflow before recording commands.
A future-safe comment would be enough here:
```
/* Caller must validate power-of-two width/height, width*height bounds,
 * and source/destination byte ranges before dispatching this shader.
 */
char *pgraph_vk_alias_unswizzle_glsl(unsigned int workgroup_size);
```
Scope note
I do not see a runtime blocker in this isolated slice because nothing calls the shader yet. The merge gate should be the dependent native-GPU conversion path, not just unit compilation of the generated GLSL.

Double-check follow-up: no new blocker in the Morton primitive; improve the stack instead of the code
I rechecked the mapping contract, generated shader, and the later dispatcher assumptions. I do not see a new source defect that warrants more churn in this PR. The earlier SPDX/checkpatch concern is not a reason to change the valid LGPL identifier, and the admitted power-of-two/product bounds keep the C mapping arithmetic bounded.
The main problem is still packaging: this PR has no runtime caller, so its quality cannot be judged independently from the conversion path.
Recommended restack:
keep the generic compute-limit fix in [HOLD] nv2a/vk: Skip empty depth conversions before descriptor updates #312 separate;
make this Morton module the first commit in the complete alias conversion slice, immediately followed by admission/dispatch/conversion (nv2a/vk: qualify read-only depth aliases and buffer extents #288/nv2a/vk: record bounded GPU depth alias conversion #289 responsibilities);
avoid merging this alone as dormant renderer API;
defer shader micro-optimization (shift/mask coordinates, precomputed Morton constants, etc.) until nv2a/vk: record bounded GPU depth alias conversion #289 first removes the much larger full-producer work. Optimizing 1,024 alias invocations is lower value than avoiding hundreds of thousands of producer operations.
In short: the primitive is in a good review state. The next improvement is to reduce PR fragmentation and validate it through the real consumer.
