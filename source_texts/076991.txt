What
Build a Gaussian-splatting reconstruction demo on top of manifoldx: the user supplies one or more photos, the system reconstructs the scene as a set of 3D Gaussians, and the result is rendered as a navigable scene in near real time. Treat the demo itself as an example; add to the engine only the native primitives it needs that aren't already there.
Why
Gaussian splatting is one of the most compelling results in real-time 3D right now, and manifoldx has no story for volumetric / point-based rendering. Doing it as an example first keeps the engine's scope honest — we only grow native support where the demo can't live without it, and we end up with a demo that stresses the renderer in a direction the triangle-mesh path doesn't.
Scope
Reconstruction
Pipeline from image(s) to a .ply/.splat of 3D Gaussians (position, covariance, colour, opacity).
Likely wraps an existing training/inference stack — we are not reimplementing the research.
Native engine support
Audit what the demo needs that the engine does not already offer (billboarded Gaussian primitive, correct depth sorting / tile-based blending, radiance evaluation).
Implement only those primitives natively; everything else stays in the example.
Demo
Upload a photo, trigger the reconstruction, display progress.
Once ready, open the scene in a free-fly camera; grid, axes, basic lighting controls.
Performance target
Interactive navigation at a comfortable frame rate on the development machine; defer mobile/web until the native path is stable.
Out of scope
Multi-view capture tooling.
Training UI / hyperparameter exposure.
Hybrid Gaussians + mesh scenes (future).
