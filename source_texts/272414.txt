What this changes
Adds assets/shaders/lighting_pass_gl.frag, so OpenGL deferred (and the SSAO and IBL passes that hang off it) initializes from the engine's own assets. The vertex stage already comes from the generated lighting_pass.vert.glsl in #207.
Stacked on #207.
Why
CreateGBufferResources compiles lighting_pass_gl.vert + lighting_pass_gl.frag and the .frag was never in the repo. Without it the pass logs Failed to compile deferred lighting pass shader!, tears the GBuffer down, IsDeferredEnabled() stays false and the renderer quietly takes the forward branch. CreateSSAOResources is only reached from inside CreateGBufferResources, so GL SSAO died with it. It only worked in SleakCraft because the game ships its own copy in Game/assets/shaders.
This is not cross compiled from the Vulkan lighting_pass.frag, on purpose. The two backends feed the lighting pass different data: GL binds LightUBO at binding 2 (up to 16 lights, point lights included), ShadowUBO at 5, DeferredCB at 6, IBL settings at 10, the GBuffer at units 8 to 11 and a plain uSSAOEnabled uniform, and it tone maps and fogs in the pass since GL has no bloom/tonemap chain. Vulkan reads one directional light plus three fill lights from ShadowLightUBO, uses a full Cook-Torrance path when IBL is on and leaves tone mapping to bloom composite. Generating GL from the Vulkan source would mean changing what the GL backend uploads and what GL renders, which is a different PR.
So the file is the shader OpenGLRenderer.cpp was written against: SleakCraft's lighting_pass_gl.frag, with the code unchanged. I only rewrote the header comment (it claimed Cook-Torrance lighting, which this pass does not do), fixed a "units 8-12" comment, and took the game wording out of a few comments. The block layouts match LightCBData (including the trailing fog fields), the GL shadow UBO and IBLSettingsGPUData.
Docs: the troubleshooting entry for this is gone, and backend_support now lists GL deferred as supported and has the GL deferred row in the shadow filtering table.
Not covered here: the GL pass still declares the unused GGX/Smith/Fresnel helpers it came with, and it reads SSAO through a loose uSSAOEnabled uniform rather than a UBO. Both are left as they are so the file stays identical in behavior to the copy that has been running in SleakCraft. A game that ships its own lighting_pass_gl.frag still overrides this one.
Fixes #144
How it was verified
Builds on Linux
Ran SleakCraft on OpenGL
Builds on Windows (Windows CI only, nothing platform specific here)
SleakCraft debug build against this branch, OpenGL on llvmpipe under xvfb from bin:
With lighting_pass_gl.frag removed from bin/assets/shaders: Cannot open shader file: assets/shaders/lighting_pass_gl.frag, Failed to compile deferred lighting pass shader!, forward fallback. That is the OpenGL deferred rendering can never initialize: lighting_pass_gl.frag does not exist #144 failure.
With the engine's file copied in its place (checked with cmp), and the vertex stage coming from the generated lighting_pass.vert.glsl: OpenGL GBuffer created (640x360) ... deferred rendering active, OpenGLIBL: precompute complete, world loaded, ran to the 90 s timeout with no errors. So the lighting pass is built from engine files only.
Vulkan does not load this file, so I did not rerun it for this PR.
Checklist
Shader changes: GL only file, there is no Vulkan or DX counterpart for this contract (DX has no deferred path)
No new includes from src/ or include/private/ in public headers
No game-specific vocabulary added to engine API
