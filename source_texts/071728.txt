Purpose
A cone plot draws a three-dimensional vector field as solid cones, each with its apex pointing along the local vector and its size proportional to the vector's magnitude. It answers the same question as a three-dimensional quiver plot, namely the direction and strength of a flow, field or gradient at sampled points, but solid, shaded glyphs remain legible in a dense 3D field where thin arrows become a tangle of lines whose direction cannot be read.
Cone plots are used for velocity fields in fluid dynamics, magnetic and electric fields, and stress directions. They are usually drawn at a subsample of the grid points and are frequently combined with slice planes or isosurfaces of the same volume.
Example
Source: Plotly documentation.
Examples in other libraries
matplotlib: No native chart type; Axes3D.quiver draws 3D arrows as lines only.
MATLAB: coneplot, which also interpolates the field from a volume at given start points.
Chart.js: No three-dimensional charts and no widely used plugin that provides them.
Plotly: Cone plots (the cone trace), with sizemode choosing absolute or scaled cone sizes and anchor choosing whether the tip, tail or centre lies at the point.
Typical API
The question for review is whether cones are a new artist or a glyph of the existing quiver artist. Both forms are sketched; the second is preferred, because a cone plot carries exactly the data of a 3D quiver.
```
let mut ax = fig.axes3(0, 0);
ax.coneplot(&x, &y, &z, &u, &v, &w)     // same arguments as quiver3
    .anchor(GlyphAnchor::Tail)
    .scale(QuiverScale::Auto)
    .face(ColorSpec::Colormapped)       // coloured by magnitude
    .color_scale(scale);
// equivalently:
ax.quiver3(&x, &y, &z, &u, &v, &w).glyph(QuiverGlyph::Cone { aspect: 0.5, segments: 12 });
```
Sketch of the IR, for review and not a decision:
```
// Preferred: a property of Quiver.
pub struct Quiver {
    /* existing fields: x, y, z, u, v, w, scale, line, head_size */
    glyph: QuiverGlyph,          // Arrow (default) | Cone { aspect, segments }
    anchor: GlyphAnchor,         // Tail (default) | Centre | Tip
    face: ColorSpec,             // fill of solid glyphs; Colormapped by magnitude
    color_scale: Option<NodeId>,
}
// Alternative: Artist::Cone(Cone { x, y, z, u, v, w, scale, anchor, face, color_scale, .. })
```
Anchor: whether the tail, centre or tip of the glyph lies at the point; Plotly calls this anchor, and MATLAB places the cone's centre at the point.
Size: absolute or scaled to the spacing of the points, as QuiverScale already does for arrows; Plotly calls this sizemode and sizeref.
Colour: one colour, or colour by magnitude through a colour scale, which is the usual choice and needs a colourbar (Add a colorbar node #8).
Cone shape: the ratio of base radius to length and the number of segments around the cone; the latter is a rendering detail that may not belong in the IR.
Lighting: a solid cone without shading reads as a flat triangle, so this depends on a lighting model such as the one planned in Add interpolated (Gouraud) shading with PDF mesh shadings #5.
Each cone is a closed mesh of triangles, which the scene compiler emits as faces with depth planes, as it does for surfaces. Many cones intersect nothing but overlap one another, so painter's order on cone centres is usually exact; where cones interpenetrate, the export report records the raster fallback with its typed reason.
Possible duplicates and overlaps
quiver (quiver3): a cone plot has the same data and the same scaling rules, and differs only in the glyph drawn at each point.
Add stream tube chart type #139: stream tubes are the other common solid representation of a 3D vector field and need the same lighting.
Add barbs chart type #132: wind barbs are another alternative glyph for a vector field, in two dimensions; a glyph property on quiver would be the natural home for both.
Add isosurface chart type #140 and Add volume slice chart type #141: MATLAB's coneplot interpolates the field from volume data at arbitrary start points, which needs the volume grid proposed there.
Add interpolated (Gouraud) shading with PDF mesh shadings #5: legible solid glyphs need shading.
Alternative approaches
A glyph property on quiver, sketched first: one artist, one set of scaling rules, and a viewer that can switch between arrows and cones; the cost is that quiver gains properties (face colour, colour scale) that only solid glyphs use.
A separate Cone variant: the IR states plainly what is drawn and each artist keeps only its own properties, at the cost of duplicating the data and scaling of quiver.
Interpolating from a volume: storing a volume and start points, as MATLAB's coneplot accepts, lets the viewer move the start points, but needs volumetric data and interpolation in the scene compiler; computing the samples in the facade keeps the artist point-based and simple.
