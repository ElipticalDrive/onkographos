Summary
Opens 3D Tiles 1.0/1.1 tilesets with Gaussian splat content
(KHR_gaussian_splatting + KHR_gaussian_splatting_compression_spz_2) via drag and drop,
File > Import, or --view. Tilesets are recognized by their required properties, not by file name.
Loading: a tileset loads flat (editable, like a PLY) when its full detail fits half the GPU
memory and 8M splats; otherwise it streams.
Streaming: tiles are selected by screen-space error against their oriented bounding boxes.
REPLACE keeps a parent until its children are loaded, so the view has no holes. Tiles are loaded
on a worker into an LRU cache. When the view's tiles exceed the cache, the error threshold is
raised gradually until they fit.
Settings window: "3D Tiles Viewer Settings" opens on load, with cache size, max SSE,
frustum culling, freeze selection and statistics. Python: lichtfeld.get/set_tiles_settings,
get_tiles_stats.
Export: a streamed node can't be exported (it holds only the drawn tiles).
Projects: a streamed node is saved as a REFS reference to its tileset (kind tiles3d,
like live RAD) and streams again when the project is reopened.
Shared interface: SplatTileSource is format-neutral, so SSOG can implement it later.
Separate commit: exports VulkanMemory::allocate_readback, which fixes the Windows link of
lfs_visualizer/lfs_mcp on current dev.
SSOG Integration - viewer designed is such a way that integrating SSOG to the it should be relatively easy.
Creating a tileset from SSOG
The geo-register plugin converts an SSOG
folder to a 3D Tiles tileset, run from the plugin root:
```
python -m geo.ssog_tiles <ssog_dir_or_lod-meta.json> <similarity.json> <out_dir> \
    [--max-tile-splats 100000] [--error-scale 16] [--max-sh-degree 3]
```
similarity.json is the plugin's scene-to-ECEF transform; an identity transform
({"scale": 1, "rotation": [[1,0,0],[0,1,0],[0,0,1]], "translation": [0,0,0]}) keeps the
original dataset frame.
Notes for review
Tested manually on a 106M-splat tileset (streaming, save/reopen, export block).
tests/test_tiles3d.cpp is added but was not run locally (no LibTorch). The fast Python suite
shows the same failures as dev on the test machine (Windows environment issues).

Add a 3D Tiles viewer for Gaussian splat tilesets
…
c58b7f6
```
Open 3D Tiles 1.0/1.1 tilesets whose content is KHR_gaussian_splatting
with SPZ compression (drag and drop, File > Import, --view). Tilesets are
recognized by their required properties, not their file name.

- SplatTileSource (io/splat_tile_source.hpp) is a format-neutral tile
  tree with a screen-space-error selector: tiles refine when their
  error, measured to the oriented bounding box, exceeds the maximum
  screen-space error. REPLACE keeps a tile until its visible children
  are resident, so the view has no holes. SSOG can implement the same
  interface later.
- tiles3d.cpp parses the tile tree relative to the root frame (ECEF
  tilesets stay float-precise), follows external tilesets, and reads
  splat counts from GLB headers. Tile content is decoded by load_spz.
- The loader opens a tileset flat when its full detail fits half the
  GPU memory and 8M splats; otherwise it streams. SplatTileStreamer
  loads tiles on a worker into an LRU cache, merges the drawn tiles
  and swaps the node model. When the view's tiles exceed the cache,
  the error threshold is raised gradually until they fit.
- A "3D Tiles Viewer Settings" window opens on load with cache size,
  maximum screen-space error, frustum culling, freeze selection and
  statistics (lichtfeld.get/set_tiles_settings, get_tiles_stats).
- A streamed node cannot be exported, since it holds only the drawn
  tiles. Projects store it as a REFS reference to the tileset (kind
  "tiles3d", like live RAD) and stream it again on open.
```

Keep streamed 3D Tiles within the GPU memory limit
…
8518e42
```
The drawn model is a merged copy of its tiles, but the cache limit
counted only the cached tiles. Each rebuild also made a temporary
merged model and then copied it again into renderer storage, so a
dense view could hold the cache plus up to three model copies and
overcommit VRAM (driver paging, multi-second merges, OOM failures
in the migration step).

- merge_splat_tiles takes an optional allocator and slice-copies the
  tiles straight into it; the streamer passes the renderer allocator,
  so no separate migration copy is made.
- The memory limit now covers cached and in-flight tiles plus the
  drawn, pending and in-progress merged models. A tile that only
  misses the limit because of the in-progress merge waits for it
  instead of raising the screen-space error.
- Stats report drawn_bytes; the panel shows cache + drawn memory.
```

Keep the VkSplat renderer across in-place model swaps
…
5ea4105
```
Every model pointer change outside training reset the viewport
renderer: device idle, pipeline rebuild, a pipeline cache write to
disk and reallocation of all renderer buffers on the UI thread.
Streamed 3D Tiles swap the node model each time the drawn tiles
change, up to several times a second, so the reset showed as

rebinds the new tensors and holds the old ones until their frames
retire. Every other model change still resets.
```
