Native SDF collision has three correctness differences from CPU MuJoCo: octree gradients omit the conversion from normalized cell coordinates to physical coordinates, an exhausted line search returns the rejected trial, and narrowphase samples empty AABB intersections admitted by the broadphase candidate gap.
Apply the gradient chain rule, retain the previous point and distance when backtracking finds no improvement, and reject disjoint geometric bounds before sampling. These follow MuJoCo's octree derivatives, line-search fallback, and AABB rejection. The bounds check preserves CPU SDF behavior, including its use of unexpanded geometric bounds when margin or gap admits a broadphase candidate.
Add regressions for an anisotropic linear field, a rejected step across a piecewise-linear minimum, and two separated SDF cubes with a candidate gap. The bounds test covers one and two worlds, prefills the contact count, and checks that only the overlapping world generates contacts. On upstream, the linear field returns [0.004, 0.016, 0.048] instead of [1, 2, 3], and the cubes generate 40 contacts instead of CPU MuJoCo's zero. All three new tests fail before the fixes. With gradient scaling corrected but the old fallback retained, the rejected-step test also fails independently: it returns a worse distance of about -0.000440 instead of preserving -0.000499.
This is a focused correctness fix for the current collision path. The broader refactor in #1457 already includes the gradient scaling and rejected-step fallback, but also normalizes volume gradients and expands candidate bounds for margin/gap. This PR does not supersede that refactor; its regression coverage will need adaptation when the refactor is integrated.
Validation on GPU1: all 74 collision-driver tests passed, including the four regression cases. Ruff, formatting and kernel analyzer passed. This fix is a prerequisite for the native threading benchmark in #1637.

some recommendations:
1. Hoist inv_cell Division and Branching in find_oct
Issue: inv_cell = wp.cw_div(wp.vec3(1.0), vmax - vmin) executes 3 floating-point divisions unconditionally, even when grad=False (used during value-only clearance evaluations in line search). In addition, if not grad is evaluated inside the 8-iteration loop despite grad being invariant.
Recommendation: Check if not grad once outside the loop and only compute inv_cell in the gradient evaluation branch.
File: collision_sdf.py
```
# Before
inv_cell = wp.cw_div(wp.vec3(1.0), vmax - vmin)
for j in range(8):
  if not grad:
    rx[j] = (
      (coord[0] if j & 1 else 1.0 - coord[0])
      * (coord[1] if j & 2 else 1.0 - coord[1])
      * (coord[2] if j & 4 else 1.0 - coord[2])
    )
  else:
    # fmt: off
    rx[j] = ((1.0 if j & 1 else -1.0) * (coord[1] if j & 2 else 1.0 - coord[1])
             * (coord[2] if j & 4 else 1.0 - coord[2]) * inv_cell[0])
    ry[j] = ((coord[0] if j & 1 else 1.0 - coord[0]) * (1.0 if j & 2 else -1.0)
             * (coord[2] if j & 4 else 1.0 - coord[2]) * inv_cell[1])
    rz[j] = ((coord[0] if j & 1 else 1.0 - coord[0]) * (coord[1] if j & 2 else 1.0 - coord[1])
             * (1.0 if j & 4 else -1.0) * inv_cell[2])
    # fmt: on
return node, (rx, ry, rz)

# After
if not grad:
  for j in range(8):
    rx[j] = (
      (coord[0] if j & 1 else 1.0 - coord[0])
      * (coord[1] if j & 2 else 1.0 - coord[1])
      * (coord[2] if j & 4 else 1.0 - coord[2])
    )
else:
  inv_cell = wp.cw_div(wp.vec3(1.0), vmax - vmin)
  for j in range(8):
    # fmt: off
    rx[j] = ((1.0 if j & 1 else -1.0) * (coord[1] if j & 2 else 1.0 - coord[1])
             * (coord[2] if j & 4 else 1.0 - coord[2]) * inv_cell[0])
    ry[j] = ((coord[0] if j & 1 else 1.0 - coord[0]) * (1.0 if j & 2 else -1.0)
             * (coord[2] if j & 4 else 1.0 - coord[2]) * inv_cell[1])
    rz[j] = ((coord[0] if j & 1 else 1.0 - coord[0]) * (coord[1] if j & 2 else 1.0 - coord[1])
             * (1.0 if j & 4 else -1.0) * inv_cell[2])
    # fmt: on
return node, (rx, ry, rz)
```
2. Pre-Fill Tested Fields Before Collision Execution
Issue: test_data.fixture initializes d from CPU reference state, where d.nacon starts at 0 for disjoint geoms. Asserting d.nacon == 0 without pre-filling could mask a failure where the kernel did not execute.
Recommendation: Pre-fill d.nacon.fill_(-1) prior to invoking mjw.collision(m, d) to guarantee that mjw.collision ran and transitioned d.nacon to 0.
File: collision_driver_test.py
```
# Before
mujoco.mj_collision(mjm, mjd)
mjw.collision(m, d)
self.assertEqual(mjd.ncon, 0)
self.assertEqual(d.nacon.numpy()[0], 0)

# After
mujoco.mj_collision(mjm, mjd)
d.nacon.fill_(-1)
mjw.collision(m, d)
self.assertEqual(mjd.ncon, 0)
self.assertEqual(d.nacon.numpy()[0], 0)
```
3. Multi-World Parameterization with Heterogeneous Worlds
Issue: test_sdf_disjoint_bounds_with_candidate_gap only tests a single world (nworld=1). It does not verify that early-returning on empty AABB bounds in one world preserves valid contact generation across batched worlds.
Recommendation: Parameterize for nworld: 1, 2 (@parameterized.parameters(1, 2)) and vary world 1 to have overlapping cubes generating active contacts.
File: collision_driver_test.py
```
# Before
def test_sdf_disjoint_bounds_with_candidate_gap(self):
  """A candidate gap must not seed SDF minimization inside an empty AABB intersection."""
  mjm, mjd, m, d = test_data.fixture(
    xml="""...""",
  )
  mujoco.mj_collision(mjm, mjd)
  mjw.collision(m, d)
  self.assertEqual(mjd.ncon, 0)
  self.assertEqual(d.nacon.numpy()[0], 0)

# After
@parameterized.parameters(1, 2)
def test_sdf_disjoint_bounds_with_candidate_gap(self, nworld):
  """A candidate gap must not seed SDF minimization inside an empty AABB intersection."""
  mjm, mjd, m, d = test_data.fixture(
    xml="""...""",
    nworld=nworld,
  )

  mjds = [mjd]
  if nworld == 2:
    mjd1 = mujoco.MjData(mjm)
    qpos = d.qpos.numpy()
    qpos[1, 2] = 0.015  # shift z from 0.022 to 0.015 so world 1 penetrates
    d.qpos.assign(qpos)
    mjd1.qpos[:] = qpos[1]
    mjds.append(mjd1)

  for w in range(nworld):
    mujoco.mj_collision(mjm, mjds[w])

  d.nacon.fill_(-1)
  mjw.collision(m, d)

  self.assertEqual(mjds[0].ncon, 0)
  if nworld == 1:
    self.assertEqual(d.nacon.numpy()[0], 0)
  else:
    self.assertGreater(mjds[1].ncon, 0)
    self.assertEqual(d.nacon.numpy()[0], mjds[1].ncon)
```
