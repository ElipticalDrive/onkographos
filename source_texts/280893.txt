Add TinyBVH-backed acceleration structures to the CPU backend so compute shaders can use inline RayQuery through the existing RHI API.
CPU RayQuery lets developers and coding agents prototype, debug, and test ray-tracing algorithms in cloud development and CI environments without GPU access.
Support triangle and procedural BLAS, TLAS instances, resumable candidate traversal, shader binding, and compact copies.
Implement Slang's shared provider interface. Keep traversal phase, cursors, and stacks in a private view of its per-query word storage, without allocation, type-punning, or copying whole stacks during Proceed.
Fetch TinyBVH 1.9.0 with FetchContent, pinned to commit 4b8509fd26b29801c8f79386cf8a1ce5713070fb. Only the two platform-neutral headers needed by the scalar backend are downloaded, with SHA-256 verification.
Add CPU state-machine coverage and 30 adapted VK-GL-CTS scenarios for CPU and D3D12.
Keep CPU RayQuery optional when the configured Slang package does not provide its prelude ABI.
This initial implementation supports builds and compact copies; update/refit and motion are outside this PR's scope. Acceleration structures and referenced geometry must remain unchanged during active queries; rebuilding a BLAS with changed bounds requires rebuilding dependent TLAS objects.
Local validation on macOS arm64:
Build and all 32 selected CPU RayQuery tests pass with the fetched TinyBVH headers.
Feature-disabled configuration does not fetch TinyBVH.
Tests pass again after merging current main and resolving the test-target CMake conflict.
Copied/interleaved queries and reset after abort pass with the provider-private layout.
All 32 selected CPU RayQuery tests pass with the paired Slang changes; Slang also tests its provider ABI independently of RHI.
Depends on Slang #12282 for the CPU prelude ABI. That PR now includes a documented custom-provider contract and a standalone Cornell box example that does not use RHI.
CPU render from the standalone Slang example in Slang #12282: 512 × 512, 256 samples per pixel, five diffuse bounces. This image uses its custom for-loop triangle provider; the TinyBVH-backed RHI path is covered by the tests above.
Related: shader-slang/slang#2141.
