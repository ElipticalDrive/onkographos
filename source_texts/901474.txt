Summary
Fixes #188.
makes occlusion-cull workgroup synchronization uniform for FXC
moves the canonical Marching Cubes triangle table from shader-local constants into a packed 2 KiB read-only GPU buffer
removes FXC's potentially-uninitialized normal path without changing the computed fallback normal
validates every packed Marching Cubes case and constructs both affected pipelines on a real GPU
changes no caller API and adds no render-graph fallback or skipped pass
Why
Pulsar's complete Windows renderer graph exposed two independent FXC failures in Helio:
OcclusionCull Pipeline: X4026, because some invocations could return before a workgroupBarrier().
VoxelMesh Extract: X4505, because dynamic indexing of the 256 x 16 shader-local triangle table consumed more than FXC's 4096 temporary-register limit; FXC also warned that compute_normal could be uninitialized.
Every occlusion invocation now reaches the barrier. Voxel extraction still uses the exact canonical Marching Cubes topology, but reads two packed words per active cell instead of materializing the full table as indexable shader temporaries.
Validation
cargo test -p helio-pass-occlusion-cull -p helio-pass-voxel-mesh --locked (88 tests, including two real GPU pipeline-construction tests)
cargo clippy -p helio-pass-occlusion-cull -p helio-pass-voxel-mesh --all-targets --no-deps --locked -- -A clippy::type-complexity -A clippy::manual-div-ceil -D warnings
git diff --check
Pulsar's complete 38-pass Windows renderer graph passed its authoritative integration test against commit 3388c689; both prior FXC failures are gone. This is a shared Helio engine change and is intentionally left for maintainer review and merge.
