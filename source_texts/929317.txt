Fixes Unified height map code from Zero Hour to Generals causes mismatch for Generals replays #3610
This change fixes a Generals retail mismatch caused by the Height Map merge in #1991 (330ad22).
Problem
The cliff state of a map is a bit array with one bit per terrain cell. The pathfinder reads it to decide which cells are cliffs. Retail Generals keeps it in rows of (width+1)/8 bytes. That is too short for the last cells of a row when width % 8 is 2 to 6, so those cells share their bit with the first cells of the next row. The merge gave Generals Zero Hour's rows of (width+7)/8 bytes, so those cells read as no cliff. The pathfinder then classifies them differently from retail, and retail Generals replays on such maps mismatch. One example is a 1v1v1 replay on Grand Canyon (350 × 350), which mismatches in frame 35830.
Change
WorldHeightMap::ParseBlendTileData adjusts the cliff state once after loading. getCliffState and setCliffState are unchanged.
Retail compatible Generals (RTS_GENERALS && RETAIL_COMPATIBLE_CRC) restores the retail values of the shared cells for maps up to version 7:
Version 7: the last cells of a row take the stored bits of the first cells of the next row.
Versions 1 to 6: the flags are computed from the heights column by column. The first cells of the next row take the values of the last cells, because retail computes those last.
Without RETAIL_COMPATIBLE_CRC (both games): for version 7 maps, the last cells of a row are computed from the heights, because the file has no bits for them.
Retail compatible Zero Hour and all version 8 maps are unchanged.
Testing
VC6 Release, -headless -replay: all 6 Generals 1.08 replays of GeneralsReplays plus the Grand Canyon replay pass, and all 10 Zero Hour 1.04 replays pass. Without the fix the Grand Canyon replay mismatches in frame 35830.
A byte-level model of retail Generals' cliff state matches the loaded cliff state on every cell of all 56 readable maps in the retail maps.big and on the two Generals test maps. That includes the version 6 maps CHI08 and Cliff. With the transform disabled, the model finds 99 to 248 wrong cells per map.
Built both games with RTS_BUILD_OPTION_RETAIL_COMPATIBLE_GAME=OFF. On all version 7 maps in the retail maps.big the recomputed cells lie in the map border, outside the playable area. Maps with a very small border, such as Grand Canyon, gain these cliffs, and the computed values match the retail ones on all of its 1,745 shared cells.
