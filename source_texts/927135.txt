What
Four quality-neutral GPU optimizations for the raymarcher, centered on the Vision Pro fragment + MetalFX path:
Relaxed sphere tracing with overstep detection (Shaders.metal, both SceneWithCache* loops). Rays take omega× over-relaxed steps; when consecutive unbounding spheres stop overlapping, the ray retreats inside the last safe sphere and continues conservatively — hits are provably identical to 1.0× stepping. This turns the step multiplier into a pure speed knob, so the targets in RenderSettings rise to 1.4 settled / 1.2 interacting and Mandelbulb's 1.05 cap is removed. Expected ~20–30% fewer DE evaluations; also fixes Mandelbox previously overstepping at 1.2 with no safety check.
Tiled taaResolve. 16×16 threadgroups cooperatively decode an 18×18 halo of texels into threadgroup memory, so each texel is sRGB-decoded once instead of ~9× (per-neighbour) and texture reads drop ~7×, at full drawable res × 2 eyes. Output values are identical.
Depth-based TAA reprojection. The kernel now unprojects each pixel at its real scene depth (sampled from the MetalFX low-res depth target) instead of a fixed plane, so TAA history reprojects correctly under head translation — previously any head movement caused the variance clamp to discard history.
Temporal depth warm-start on the visionOS fragment path. MetalFXManager ping-pongs two depth targets; the fragment shader reprojects last frame's hit distance (same probe-then-refine scheme as the existing adaptive-compute kernel) and marches a narrow window at a 0.25× step budget. A window miss falls back to the full march, so the warm start can never change what is hit — only how fast it's found. For temporally stable scenes (the typical music-visualizer case) most pixels should march ~5–10 steps instead of hundreds.
Gating / safety
New FC_WARM_START function constant (index 13): only visionOS fragmentShader pipelines compile the warm start in; Mac, screenshot, and quad-shared pipelines compile it (and the prev-depth texture argument) out entirely.
Runtime warmStartEnabled uniform is cleared on fractal-type switches, spherical inversion, MetalFX texture rebuilds/pool swaps, and after adaptive-compute or Buddhabrot frames.
EmbeddedMetalSources.swift regenerated via Scripts/generate_metal_embeds.sh so runtime .threshfx compilation matches the new headers.
Verification
visionOS simulator build: SUCCEEDED (0 errors; CODE_SIGNING_ALLOWED=NO to sidestep FileProvider xattr/codesign detritus in this checkout).
macOS build: SUCCEEDED (also compile-validates all MSL).
iOS simulator: fails on a pre-existing, unrelated import MetalFX module-resolution error in MacSpatialUpscaler.swift (file untouched here).
Reviewer notes / on-device checks
Watch GPU frame time on a stable scene at resolutionScale ≈ 0.7 before/after (BenchmarkManager / frame breakdown).
Stress warm start with fast head motion and rapid fractal morphs — artifacts would appear as one-frame sparkle at disocclusion edges (the full-march fallback should prevent this).
Glow can differ very slightly on warm-started pixels (glow integrates per march step; skipped empty space contributes none).

Four quality-neutral raymarch optimizations, focused on the Vision Pro
fragment+MetalFX path:

1. Relaxed sphere tracing (Keinert overstep detection) in both march
   loops: omega-overstepped rays retreat into the last safe sphere on
   gap failure, making over-relaxation hit-identical to 1.0 stepping.
   Step multiplier targets raised to 1.4 settled / 1.2 interacting and
   the Mandelbulb 1.05 cap removed (~20-30% fewer DE evals).

2. taaResolve tiled: 16x16 threadgroups cooperatively decode an 18x18
   halo into threadgroup memory, so each texel pays one sRGB decode
   instead of ~9 and ~7x fewer texture reads at full res per eye.

3. TAA reprojection now unprojects at real per-pixel scene depth
   (sampled from the MetalFX depth target) instead of a fixed plane,
   so history survives head translation instead of being clamped away.

4. Temporal depth warm-start on the visionOS fragment path: MetalFX
   depth is ping-ponged; each ray reprojects last frame's hit and
   marches a narrow window at 0.25x step budget, falling back to the
   full march on a window miss so disocclusions render identically.
   Compiled in via new FC_WARM_START function constant (visionOS
   fragmentShader pipelines only; Mac/screenshot/quad-shared compile
   it out) and gated at runtime on depth-history validity, fractal
   type changes, and spherical inversion.

Built clean: visionOS sim (CODE_SIGNING_ALLOWED=NO) and macOS. iOS sim
target has a pre-existing unrelated MetalFX module resolution failure.
