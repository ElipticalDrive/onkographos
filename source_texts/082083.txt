Closes #886
Root cause
Pure-Python fallback delegated to skimage.measure.marching_cubes (lewiner). Cube-face ambiguity produces 48 four-fold edges + 24 byte-duplicate vertices on the analytic sphere fixture (25 - dist², 20³, iso 0.0), while native/seismic_3d_core 6-tet Freudenthal decomposition is watertight by construction. CI built native cores, so the watertight assertion only exercised native.
Fix
Replace _py_marching_cubes_3d skimage delegation with watertight marching-tetrahedra (_py_marching_cubes_3d_mt) — same 6-tet topology as C++ kernel (patches/issue886_mt_fallback.py), shared-vertex dedup via global flat-index cache, >= isovalue inside set, NaN-cube skip, 1e-3 corner-nudge.
Keep public name _py_marching_cubes_3d as thin wrapper over MT (dependency-free, skimage import removed).
Align tests/test_issues_823_828_830_833.py binary-at-max expectations: MT (like native) preserves 0/1 boundary crossing and yields a closed mesh, not empty; constant-volume case remains empty.
Tests
Sphere watertight reproduction (issue body script): edge-multiplicity {2: 4248} watertight=True, 0 duplicate vertices (was {2:1140,4:48} + 24 dups).
Native/fallback parity: both watertight, bbox within 0.6, closedness consistent (vertex count differs due to dedup: 1418 vs 8496).
tests/test_seismic_3d_api.py — 10 passed (fallback and native legs green)
tests/test_issues_823_828_830_833.py — 7 marching-cubes tests passed (after updating two binary-at-max assertions to match native/MT)
Risk
Low — fallback-only path. No native C++ change. Pure-Python MT is slower than skimage but preserves topology.
