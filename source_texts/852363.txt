Summary
Move Gaussian attributes from attributes dict to extension block: CesiumJS generates GLSL variable names from all mesh attribute keys. Colon-prefixed names like KHR_gaussian_splatting:ROTATION cause fragment shader compilation errors (ERROR: 0:11: ':' : syntax error). Only POSITION and COLOR_0 now remain in attributes, while rotation, scale, opacity, and SH data are referenced from the KHR_gaussian_splatting primitive extension as accessor indices.
Remove extensionsRequired for standard (non-SPZ) path: Allows viewers without KHR_gaussian_splatting support to gracefully fall back to rendering a simple point cloud.
Fix sh_degree assignment order in save_tileset: chunk_gc.sh_degree must be set before chunk_gc.sh to avoid spz validation error when exporting SH degree >= 1 data.
Backward-compatible reader: _parse_standard now reads Gaussian data from either the extension block (new format) or colon-prefixed attribute names (legacy format).
Background
When serving GLBs produced by save_gltf() as Cesium 3D Tiles, CesiumJS 1.140 attempts to compile a shader that includes variables for every attribute name. The colon character in KHR_gaussian_splatting:ROTATION etc. is not valid in GLSL identifiers, causing the shader to fail.
The save_tileset SH bug was discovered while testing SH degree 1 export — the spz library's GaussianCloud validates that sh must be empty when sh_degree == 0 (the default), so data must be assigned after the degree is set.
Test plan
All 87 existing tests pass
New test test_load_legacy_colon_attributes — verifies backward-compatible loading of GLBs with colon-prefixed attribute names
New test test_sh_degree_1_roundtrip — verifies SH degree 1 data survives chunked tileset save/load
Updated test_glb_json_structure — verifies only POSITION/COLOR_0 in attributes, Gaussian data in extension block
Updated test_glb_spz_json_structure — same for SPZ path

CesiumJS derives GLSL variable names from every key in the mesh
attributes dict.  Colon-prefixed names like
"KHR_gaussian_splatting:ROTATION" produce syntax errors such as
`ERROR: 0:11: ':' : syntax error` during fragment shader compilation.

This commit moves all Gaussian-specific data (rotation, scale, opacity,
SH coefficients) out of the attributes dict and into the
KHR_gaussian_splatting primitive extension block as accessor index
references.  Only POSITION and COLOR_0 remain in the attributes dict,
so any standard glTF viewer can render a fallback point cloud.

For the standard (non-SPZ) path, extensionsRequired is also removed
(only extensionsUsed) so viewers that don't support the extension can
gracefully fall back.

Additionally fixes a bug in save_tileset where chunk_gc.sh was assigned
before chunk_gc.sh_degree, causing a spz validation error when
exporting GaussianClouds with SH degree >= 1.

The reader (_parse_standard) now supports both the new extension-block
format and legacy colon-prefixed attribute names for backward
compatibility.
