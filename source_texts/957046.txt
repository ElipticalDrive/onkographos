The TAA resolve rejected history by colour alone. When an occluder moved off a surface, its ghost survived wherever the occluder's colour fell inside the current neighbourhood. The resolve now rejects by depth as well.
How it works
Previous depth lives in the history's alpha. The Hi-Z pyramid can't provide it: by the time the resolve runs, the two-phase rebuild and the end-of-frame build have refilled it from the current frame. The resolve writes 1 + view depth of each output pixel's dominant reconstruction tap into the history's alpha. That channel used to hold a constant 1, and nothing downstream reads it.
Expected depth comes from two rows. For each of the nine source taps, the resolve computes the view depth that surface would have had last frame if it had stood still. The CPU folds this into two rows once a frame (TaaDisocclusion.h), so the shader does no matrix inverse. The rows come from the jittered view-projection, which is what rasterised the depth.
The test. The resolve gathers the four history alphas at the reprojected position. It rejects the history when none of them falls inside the 3x3's expected range, widened by a relative tolerance. If the neighbourhood contains sky, the range stays open above. A history written without depth (alpha 1) decodes as "unknown" and is kept.
Contracts
TaaResolvePushConstants grows to 100 bytes: flags @60, rows @64/@80, tolerance @96. Offsets are pinned by static_assert and the shader interface golden.
Binding 3 (main depth) gets a second reader inside the same pass. There is no new resource, barrier or descriptor.
The test needs a samplable main depth and reprojection. When it's off, the resolve reads no depth for it and writes alpha 1.
New settings: taa.disocclusionRejection (on), taa.disocclusionTolerance (0.05, clamped 0.005–0.5) and taa.debugDisocclusion (paints rejected pixels red). Each has its field, clamp, JSON read/write, ImGui control and a history reset on change. The taa-history-plain leg turns the test off and debug-views turns the debug paint on.
Separate commit: the rejection-feedback tooltip was attached to the Catmull-Rom checkbox, so hovering Catmull-Rom showed both tooltips. Each tooltip now follows its own item.
Verification
tools/dev/verify_renderer.sh fast: 624/624 tests, no warnings. The new cases cover the depth reconstruction against direct reprojection (still camera, dolly, rotation with jitter), the encoding, and the keep/reject cases. A row/column mutation fails 10 assertions.
tools/dev/verify_renderer.sh sync: passes. It runs the default settings, where TAA is off, so I also ran the renderer under --sync-validation with TAA, rejection and debug on (default and sunlit scenes): 0 errors, 0 hazards.
check_shader_constants.py (39), check_shader_interface.py, check_ci_settings_coverage.py and check_settings_capture.py all pass.
RTX 3080 Ti Laptop, 1280x720, --deterministic, frame 30:
TAA off: bit-identical to main. The CI golden runs with TAA off, so it is unaffected.
Still camera: rejection changes only pixels around the animated skinned mesh (20 px default, 117 px sunlit).
Orbiting camera: there is no headless flag for this, so I patched an orbit in locally for the check and didn't commit it. Rejection changed 0.29% (default) and 0.14% (sunlit) of the frame. The debug view shows single-pixel lines along trailing silhouettes and nothing on flat surfaces.
Rejection off is not bit-identical to the old resolve. It differs on 941 of 921600 pixels, almost all by at most one level. The cause is the compiled shader, not the logic: compiling the depth path out restores the old output exactly, and writing a constant alpha with the path left in reproduces the drift. taa.md records this.
Not done
GPU cost is not measured. I couldn't pin clocks in this session. Per pixel the test adds nine depth fetches (velocity dilation already makes nine) and one gather. A pinned A/B/A/B of TAAResolvePass with rejection on vs off is still to do.
Known limits (in taa.md): the expected depth assumes the surface stood still, so an object moving along the view direction faster than the tolerance rejects its own history. The tolerance is relative. Blended surfaces write no depth.

frame's depth buffer, the view depth that surface had last frame is the
previous view-projection's clip w at its world position, and its current
view depth is the reciprocal of the inverse's w row. Both reduce to two

when the neighbourhood contains sky.

the keep and reject cases. Building the denominator from the wrong index

Treat sky as a distinct expected depth
When an opaque object moves away to reveal only sky, every current tap sets neighbourhoodHasSky but leaves expectedMin > expectedMax, so this early return keeps the object's history instead of rejecting or debug-painting it. A mixed geometry/sky neighborhood is also overly permissive because the infinite upper bound accepts every finite history depth, not just the encoded sky sentinel. This leaves the new depth rejection ineffective for disocclusions against sky, especially when neighborhood color clamping is disabled; include the encoded sky depth as a distinct expected candidate rather than treating the range as empty or unbounded.
