Description
Fixes #2348. Adds small safeguards that improve the quality of triangles on the iso-pressure surface generated by the hydroelastic contact pipeline.
Root cause: When two SDF boxes overlap deeply, marching-cubes edge interpolation can place vertices exactly at cube corners (t ≈ 0 or t ≈ 1). Multiple vertices collapse to the same corner, producing degenerate zero-area triangles. The subsequent wp.normalize() on a zero-length cross product returns NaN normals.
Changes (in both sdf_mc.py and sdf_hydroelastic.py):
Clamp the edge interpolation parameter t to [0.02, 0.98] so vertices stay away from cube corners.
Tighten the near-zero val_diff threshold from 1e-8 to 1e-10 to avoid unnecessary midpoint snapping.
Guard the triangle normal computation: when the cross-product squared length is below 1e-30, return zero area with a valid fallback normal instead of NaN.

Nice fix — the belt-and-suspenders approach (t-clamping + degenerate guard) is solid. A few observations:
Degenerate triangles still flow into the contact buffer / hashtable
When mc_calc_face_texture returns area = 0.0, the caller in generate_contacts_kernel (~L1523) doesn’t skip the triangle. It still gets a hashtable slot via hashtable_find_or_insert and (when pre_prune=False) a contact buffer slot. The area = 0.0 neutralizes the force, but wasted slots could contribute to “face contact overflow” warnings in the deep-penetration scenarios this PR targets. An early if area <= 0.0: continue in the face loop would be cleaner.
Same interpolation pattern unfixed in sdf_utils.py and sdf_texture.py
There are four copies of the MC edge-interpolation + wp.normalize(n) pattern in the codebase. This PR fixes two (sdf_mc.py and sdf_hydroelastic.py), but sdf_utils.py:1364 and sdf_texture.py:1869 still use the old 1e-8 threshold with no t-clamping and no degenerate-triangle guard (sdf_utils.py:1376 still calls wp.normalize(n) directly). Worth fixing here or in a follow-up.

   stuck-nut driver is the substep collision frequency, not the
