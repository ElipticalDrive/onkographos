Summary
A Rust 3DGS trainer on wgpu that competes with brush, plus GPU acceleration of the SfM front end and bundle adjustment. Together they turn raw EuRoC into a trained splat with no COLMAP and no Python.
3DGS trainer (visloc-gsplat-train, M0–M3)
M0: evaluator. Scoring matches brush's protocol: hold out every 8th view, black background, PSNR/SSIM. gsplat_eval implements it.
M1: backward pass. A CPU f64 reference, checked against finite differences, backs a GPU backward pass (Renderer::backward) that matches it to < 1e-6 relative.
M2: trainer.
Loss: L1 + 0.2 D-SSIM, with a tiled GPU SSIM gradient.
Adam on the GPU, using the Inria learning rates.
Inria densification (clone, split, prune, opacity reset), fully on the device.
GPU memory is halved: ground-truth views are streamed per step, the depth sort is sized to the gaussian count, and the tile sort runs in place over 4 per-intersection buffers instead of 8.
M3: gsplat_euroc example. Raw EuRoC is undistorted, run through SIFT, verified matching and visloc-rs incremental SfM, then trained.
SfM on the GPU (all opt-in, validated by quality rather than bytes)
visloc-sift-gpu: SiftGpu. The default SIFT path, run in f32. Against the CPU extractor, 99.9–100% of keypoints match and descriptor dot products are ≥ 0.99999. It is about 240× faster on 1024 px images.
GpuMatcher + FeatureBank. Batched top-2 matching over descriptors kept on the device. Its match sets are identical to CrossCheckMatcher(BruteForceMatcher { ratio }): 18 ms vs 1.4 s per pair (78×).
visloc-ba-gpu: GpuBundleAdjuster.
Keeps the CPU optimizer's LM schedule and gates, and runs its f64 cost test on the CPU.
Moves f32 linearization and implicit-Schur block-Jacobi PCG to the GPU.
Replayed SfM problems reach the same final cost as the dense CPU solver.
visloc_slam::BaAccelerator. A GPU-free hook that lets the incremental SfM hand its global BA to an accelerator.
Local windows are opt-in: they are latency-bound on small systems.
VISLOC_SFM_BA_DUMP / ba_problem_io / examples/ba_replay dump and replay the exact BA problems the SfM solves.
Parallel pair verification. gsplat_euroc verifies pairs with rayon; RANSAC is seeded, so the results do not change.

```
Set the 3DGS goal (docs/rust_3dgs_plan.md): a Rust trainer competing
with brush, differentiated by a COLMAP-free all-Rust pipeline and

- dataset: COLMAP model + images, views sorted by name, every Nth held
  out (brush's and the Inria split).
- metrics: PSNR on display-space RGB.
- gsplat_eval example: scores any Inria-format .ply on the held-out
  views with the wgpu renderer, so every method is compared with one
  renderer, split and metric (brush prints no metrics headless).

Fixes found on the way:
- Image::to_rgb8 applied a gamma-2.2 encode, but splat colours are
  already display-space (as in Inria/brush): every PNG was washed out.
- The PLY reader assumed f_dc/scale/rot properties are contiguous;
  brush writes them alphabetically. All are now looked up by name.
```

```
backward::render_backward returns dL/d(every gaussian parameter) for
L = sum_px dot(d_image, C), as the oracle for the GPU backward (M1):
- f64 forward (render_f64) with the same gates as cpu_render (matches
  it to 1e-4).
- Compositing differentiated analytically per pixel, back to front,
  from the recorded contributing splats.
- Projection (mean, log-scale, un-normalised quaternion, opacity logit)
  differentiated with forward-mode dual numbers, so the EWA Jacobian,
  the 1.3x frustum clamp, quaternion normalisation and the SH view
  direction are exact; SH coefficient gradients are the basis values.

Tests check every parameter group of three rotated, anisotropic,
semi-transparent degree-2 splats against central differences. The
renderer's hard gates (alpha >= 1/255 etc.) can make one step size jump
when a pixel crosses them, so a gradient passes if any of four step
sizes agrees within 0.2%.
```

```
sh_rest_coeffs_per_channel returned 9/24/45 for degrees 1..3 -- the
```

```
Renderer::backward(d_image) returns the gradient of
L = sum_px dot(d_image, C) w.r.t. every gaussian parameter for the last
rendered frame, in the forward input layouts.

Forward changes (always on, output unchanged):
- map_gaussians also writes each isect's own index; the tile sort now
  carries that instead of the compact id, and a gather kernel builds
  the compact id per sorted entry for rasterize.
- rasterize stores per-pixel final transmittance and one past the last
  blended list index.

Backward kernels:
- rasterize_backward: one workgroup per tile, pixels walk the list back
  to front (T_before = T_after / (1 - alpha), colour composited behind),
  per-splat pixel sums via subgroupAdd plus a shared-memory CAS float
  add across subgroups, written to the isect's own slot: no global
  atomics.
- grad_reduce: deterministic per-gaussian sum over its isect range.
- project_backward: hand-derived chain through conic inversion, the
  EWA Jacobian with the 1.3x frustum clamp, W Sigma W^T, Sigma = M M^T,
  scale, rotation and quaternion normalisation, opacity sigmoid, and
  SH (coefficients plus the view-direction term up to degree 3).

GpuContext requests Features::SUBGROUP when the adapter has it (DX12 +
DXC does); the backward errors without it.

Tests compare GPU against the f64 CPU oracle (itself FD-checked):
screen-space gradients worst 6e-6, parameter gradients worst 8e-7 of
each group's max, on a 3-splat degree-2 scene and a 64-splat degree-3
scene spanning many tiles. The CPU oracle also exposes screen-space
gradients (render_backward_screen).
```

```
- init: read COLMAP points3D.txt with colours; seed one gaussian per
  point (DC colour, isotropic scale = mean distance to 3 nearest
  neighbours via a hash grid, opacity 0.1, identity rotation).
```

```
- densify (host): Inria adaptive density control -- clone small /
  split large gaussians whose mean view-space gradient (NDC units)
  exceeds 2e-4, prune transparent (<0.005) and, after the first opacity
  reset, oversized ones; opacity reset every 3000 steps. Adam moments
  are carried for kept gaussians and zeroed for new ones.
- densify_stats kernel accumulates |dL/d mean2d| per gaussian after
  each backward; every 100 steps (500..15000) the trainer downloads the
  population, densifies, and rebuilds the renderer and optimiser state
  (Renderer::into_context returns the GPU context for that).
- D-SSIM: four separable passes (11x11 gaussian window, zero padding,
  the Inria SSIM) add ssim_weight * d(1 - SSIM)/dC to the gradient
  image; the L1 kernel is weighted by 1 - ssim_weight. Loss is the
  Inria 0.8 L1 + 0.2 D-SSIM.
- metrics::ssim / ssim_with_grad: f64 CPU SSIM and its gradient,
  checked against finite differences; the GPU gradient matches it to
  1.2e-6 of the maximum (gpu_ssim_gradient_matches_cpu).
```

perf(gsplat): densify on the device (no host copy of the scene)
…
ab5dc5c
```
The host densification downloaded parameters and Adam moments, built
the new population on the CPU and uploaded it again. At ~600k gaussians
that transiently needed ~2 GB of host RAM (a benchmark run died with
"memory allocation of 269959296 bytes failed") and cost ~1.5 s per
event at 1M gaussians.

Now:
- densify_classify: per gaussian keep / clone / split / prune (the
  Inria rule of crate::densify) and its output row count; tallies for
  the report.
- the counts are prefix-summed on the device (PrefixScanner).
- densify_scatter: one dispatch per parameter group copies rows and
  Adam moments to new buffers (kept rows keep moments, new rows start at
  zero); split children sample their mean from the parent with hashed
  normals and shrink scales by 1.6; opacity reset clamps logits and
  zeroes that group's moments.
- the renderer is rebuilt around the new device buffers
  (GpuScene::from_buffers, Renderer::from_gpu_scene); GpuScene now
  drops its host arrays after upload.

Only the new count and three tallies are read back. 2000 steps on
south-building: 145,631 gaussians / 20.43 dB (host version: 144,137 /
20.05 dB). The host densify stays as the reference implementation.
```

```
pair; sorting compact ids as values removes the isect_id indirection and
```

perf(gsplat): stage SH rows through shared memory in project_backward
…
dfcdd3f

```
Each thread read and wrote its gaussian's 48-float SH row float by float;
rows are scattered, so a warp touched 48 strided cache lines per row and
thrashed L1. A 64-wide workgroup now copies whole rows with consecutive
lanes into shared memory, each thread overwrites its row with the
gradient in place, and the rows go back the same way. project_backward
at ~1.1M visible gaussians: 37-41 ms -> 17-18 ms (GPU shared with another
process during the measurement; gradient tests unchanged).
```
