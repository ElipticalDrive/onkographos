父项：#231
依赖：#232、#233、#234
关联：#115、#148、#171、#184
目标
建立通用 ChunkedVisualLayer（名称可调整），让超大 2D 内容按 viewport 可见范围分块 materialize / retain / evict，而不是要求应用永久保留或每帧遍历全部 visual item。
典型非游戏 workload：
节点编辑器 / 白板的超大画布；
时间线的长时间范围；
地图/平面图；
大型素材/缩略图画布；
波形、频谱、热力图；
NanaStudio Scene / NanaShader graph。
游戏 TileLayer 只是 regular-grid specialization，不是 canonical 模型。
Canonical chunk contract
至少表达：
```
ChunkId
ContentBounds
revision
materialized state
visual collection / producer result
resource dependencies
last-visible / residency metadata
```
chunk 可以是规则网格，也允许应用按自己的空间分区提供 bounds。首版不要求 Nana 建立通用世界分区器。
Viewport-driven visibility
必须直接消费 #234 的 canonical visible content region：
```
ViewportTransform
      ↓
visible content bounds
      ↓
chunk selection
      ↓
materialize / retain / evict
```
禁止 renderer 与 chunk system 各自维护一套 camera/visible rect。
支持：
overscan/prefetch margin；
hidden/minimized policy；
fast pan 时的 bounded work；
resize/zoom 后精确失效；
rotation 下 conservative visibility。
Materialization
允许 application/provider 生成 chunk presentation data，但 Nana 只管理 presentation mechanics：
```
ChunkProvider
  request(bounds/id, revision)
  -> visual data / pending
```
不得因此引入：
application object database；
map/game world loader；
prefab/scene serialization；
business paging authority。
异步完成应复用 Nana Resource/operation lifetime/cancellation 机制，不另建 game streaming runtime。
Residency / cache budget
至少定义：
resident chunk 数/字节预算；
LRU/clock 等实现策略可内部调整；
pinned/current-visible chunk；
eviction 后资源 handle 的正确 lifetime；
device generation 与 CPU chunk cache 分离；
不可见 chunk 不因 steady frame 被重复 materialize。
与 DataView #115 的边界
ChunkedVisualLayer 是 presentation-level spatial chunking，不是 List/Table/Tree 的 Model/View virtualization 替代品。
如果内容需要：
item semantics；
keyboard focus；
screen reader item navigation；
editable cells；
SelectionModel；
应继续使用 DataView/UiWorld virtualization。Dense 2D 只解决纯视觉或由 anchor 统一交互的内容。
GPU / Scene
chunk 进入同一 VisualCollection/UiScene path：
不为每个 chunk 开 Device/Queue；
不为每个 chunk 强制独立 render pass；
renderer 可跨相邻 compatible chunk 合批；
resource/pipeline lifetime 复用 [GPU Foundation 2/4] GPU Policy Core：统一 UploadArena / FrameSlot / Transient Pool / Pipeline / Resource Lifetime #184；
document order 仍由外层 anchor 决定。
Diagnostics
至少：
chunks_total_known（若 provider 可知）；
chunks_visible；
chunks_resident；
chunk_materializations；
chunk_evictions；
items_considered / items_culled；
bytes_resident；
materialize latency；
work caused by pan/zoom。
性能门禁
建立至少：
10k+ logical chunks，仅少量 visible；
viewport 平移工作量与 visible/changed chunks 相关，而非 total chunks；
steady viewport 不重复 materialize；
快速 pan 不产生无界 task backlog；
eviction 不触发全 collection rebuild。
验收
节点画布/时间线/地图 workload 可直接使用。
regular grid 只是通用 chunk contract 的一种 adapter。
game TileLayer 可由此薄包装实现，无 game-only streaming/culling。
不替代 [Epic][DataView] Model / View / Delegate / Selection：统一列表、表格、树与虚拟化数据视图 #115 的 semantic data virtualization。
不创建通用 Object/World storage。
visibility、cache、async lifetime 有性能与取消门禁。
