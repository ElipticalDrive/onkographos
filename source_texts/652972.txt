# BIL333 - Computer Graphics Final Project (Option 1)
## 3D Scene Modeling and Lighting

Interactive 3D showroom rendered with hand-written transformations, Phong
shading, shadow mapping, and a planar floor reflection. Built for the
**BIL333 - Computer Graphics (2025-26 Spring)** final project at Istanbul
Ticaret University.

OpenGL is used **only as a rendering backend**. All geometry, transformation
matrices, lighting math, shadow mapping, and reflection are implemented from
scratch in the project sources, as required by the project guideline.

## Rendering pipeline

Each frame is rendered in three GPU passes:

1. **Shadow pass.** The scene is rendered from the directional light's POV
   into a 2048x2048 depth-only framebuffer. Front-face culling is used
   during this pass to reduce shadow acne. The resulting depth texture is
   later sampled with a 3x3 PCF kernel in `phong.frag`.
2. **Reflection pass (optional, toggled with F5).** Every opaque object
   except the floor is drawn with its model matrix premultiplied by a
   reflection-about-the-floor matrix. A clip plane discards fragments below
   the floor in world space so the mirrored geometry stays visually
   "above" the floor in the reflection.
3. **Main pass.** Walls and opaque objects are rendered with Phong shading
   (ambient + point with attenuation + directional with shadow). The floor
   is drawn last with alpha < 1 so the reflection underneath shows
   through. Finally, the semi-transparent glass sphere is sorted
   back-to-front and drawn with `GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA`.

## Shading model

Per-pixel Phong, computed in world space inside `phong.frag`:

```
color = ambient * albedo
      + Σ_lights [ diffuse(N, L) * albedo
                 + specular(N, L, V)^shininess * spec_color ] * (1 - shadow)
```

The point light uses a constant + linear + quadratic attenuation
(`1 / (1 + 0.09·d + 0.032·d²)`). The directional light is the one paired
with the shadow map. Shadow comparison uses slope-scaled bias and 3x3 PCF
filtering to soften the shadow edge.

## Scene contents

Inside a 10 x 5 x 10 room (5 inward-facing walls, each in its own color):

- **chrome_sphere** – shiny, neutral grey, shininess 128 (showcases specular)
- **red_sphere** – matte, scaled down
- **yellow_cube** – matte, rotated 28° around Y
- **teal_pyramid** – matte
- **purple_cylinder** – shiny, shininess 80
- **glass_sphere** – semi-transparent (α = 0.40), shininess 128 (bonus)

Three lights:

- **Ambient** – low strength (0.18) global term, slight warm tint
- **Point light** – warm (1.0, 0.78, 0.55), orbits slowly inside the room
- **Directional light** – warm-white sun, casts the shadow used by F4

## Known limitations / design notes

- Reflection is a single planar pass on the floor; reflective objects
  (chrome sphere, cylinder) do not show environment reflections. This
  keeps the global-illumination requirement satisfied while staying
  within the project's "approximation" wording.
- Transparency is blended without refraction. The glass sphere uses
  back-to-front sorting and depth-write disabled.
- Shadow mapping covers the directional light only; the point light is
  shadow-less by design (would need a cubemap shadow map).

## Implementation notes (for the report)

- All matrix builders in `src/transform.py` are implemented by hand
  (`translate`, `scale`, `rotate_x/y/z/axis`, `perspective`, `orthographic`,
  `look_at`). NumPy is used only as an array container.
- Procedural meshes (`src/geometry.py`) are emitted as packed
  `[pos.xyz, normal.xyz]` arrays + uint32 indices. Sphere and cylinder use
  smooth normals; pyramid/cube/room use flat per-face normals so the
  shading edges look crisp.
- The shadow framebuffer attaches a `GL_DEPTH_COMPONENT24` texture only,
  with `glDrawBuffer(GL_NONE)` to satisfy GL's "no color attachment"
  requirement.
- The renderer is multi-pass but uses a single shader program for the
  main + reflection passes, switching state via the `u_use_clip_plane`
  uniform and a clip plane (`gl_ClipDistance[0]`).
