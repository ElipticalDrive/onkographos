Gaussian splat layers
+ Add → ☁ Gaussian splats loads a .ply, .spz (versions 1–3) or .splat file. Without a file, the layer shows a small built-in galaxy.
Drawing (splat.wgsl):
Each splat is an ellipse on screen, projected from its 3D covariance (EWA, as in the 3DGS paper).
Splats are blended back to front over the scene. They are depth-tested but don't write depth, so solid shapes in front hide them.
They are drawn with the see-through layers and show in the mirror floor and fog.
Sorting: a linear-time counting sort on the CPU each frame.
Works on every backend, WebGL2 included:
the splat data is in an Rgba32Uint texture, two texels per splat;
the drawing order is a per-instance u32 vertex attribute, so no storage buffers are needed.
Settings:
Up axis: guessed from the format by default (PLY and .splat are Y down, SPZ is Y up).
Fit to size: uses the 2–98% box of the opaque splats, so stray splats far out don't shrink the rest.
Tint, brightness, opacity, splat size, scatter (animatable; bursts the scene apart on the beat).
A splat budget that keeps the most visible splats.
Works like other layers: transform, spin, symmetry, blink and steps all apply.
Limits (all in the manual):
only each splat's base colour is used, not the colours that change with viewing angle;
splats cast no shadows;
depth of field treats them like what is behind them;
.ksplat and SOG files are refused with a message to convert them.
More model formats
Shapes also load STL, PLY, OFF and 3MF, on top of glTF/GLB and OBJ.
STL and 3MF are Z-up by convention and are turned to stand upright.
Files without normals get smooth normals that stay sharp across creases (a box stays a box).
ply.rs is a general PLY reader (ASCII and both binary byte orders) used for both meshes and splats.
"3D model or splat file…" and dropping a file on the window pick the layer type from the file's contents, since a PLY file can be either a mesh or splats.
Dependencies
flate2 (for SPZ) and zip (for 3MF) were already in the lockfile through zip. No new crates are downloaded.
Testing
Unit tests:
PLY in all three encodings;
STL (binary, including files that start with solid, and ASCII), PLY, OFF and 3MF meshes (items, components, transforms);
splats from PLY, SPZ v1–3 and .splat;
fitting, packing and back-to-front sorting.
GPU test gaussian_splats_show_and_loop, for both the built-in cloud and a PLY file:
visible, and seamless when spinning once per loop;
hidden by a wall in front of it;
scatter changes the picture;
a missing file is reported.
shader_backends now includes splat.wgsl (HLSL, MSL, GLSL ES and desktop GLSL).
Checked by hand with real files:
an official Niantic .spz sample, alone and converted to a standard splat .ply;
a real .splat capture.
All rendered right way up through --render.
cargo test --workspace passes, with GPU tests on Mesa llvmpipe.
cargo clippy --workspace --all-targets -D warnings is clean, and so is cargo clippy -p ez_app --target wasm32-unknown-unknown -D warnings.
I haven't run the web app in a browser.
Also fixes a manual_range_contains lint that the current clippy reports in existing code (tests/library.rs).
