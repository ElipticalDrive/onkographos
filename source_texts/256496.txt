Summary
Adds optiland.nonsequential, a Monte Carlo non-sequential ray tracer for illumination design, stray-light analysis, and non-imaging optics, with a differentiable PyTorch backend for gradient-based illumination design.
The subpackage is architecturally independent of the sequential tracer: rays propagate freely and interact with surfaces in any order. It ships as a beta. The public API listed in optiland/nonsequential/__init__.py is stable and will not be removed without a deprecation cycle, while internals (backend classes, geometry helpers) may still change.
70 library modules, 149 tests, 12 documentation notebooks.
What's included
Engine. NSQScene / NSQTracer with two backends behind a common TracerBackend ABC: NumPy (fast forward tracing, ray compaction) and PyTorch (fixed-depth wavefront loop, full autograd graph). All numerical code goes through optiland.backend, so both backends share one implementation of the geometry and interaction math.
Sources. Point, collimated (tophat/Gaussian), and extended area sources, each with a Spectrum.
Components. Refractive, reflective, and absorbing surfaces; compound Lens, Mirror, and Doublet builders that assemble faces, edges, and rims. Analytic geometry (conic, sphere, plane, annulus, cylindrical frustum) plus forward-only mesh geometry.
Scatter. Specular, Lambertian, Harvey-Shack, and tabulated BSDFs.
Detectors. Irradiance (with differentiable splatting), far-field, spectral, and ray-database.
Interop. sequential_to_nonsequential() converts an existing Optic into a scene; versioned JSON scene serialization; 2D/3D viewers, with the shared visualization base refactored so sequential and non-sequential rendering reuse it.
Differentiability
With the torch backend, pass a requires_grad tensor straight into the ordinary config objects:
```
r1 = torch.tensor(120.0, dtype=torch.float64, requires_grad=True)
scene.add_lens("L1", CoordinateSystem(z=100.0), LensConfig(
    r1=r1, r2=float("inf"), thickness=5.0, material="N-BK7",
    front_aperture_radius=12.0))
loss = scene.trace(num_rays=20_000, seed=1).detectors["D1"].data.sum()
loss.backward()        # -> r1.grad
```
Differentiable: component geometry (radius, conic, aperture), IrradianceDetector extents, source total_flux, material index, BSDF reflectance.
Not differentiable in this release, and raising rather than detaching silently so a dead design variable is never mistaken for a live one: source geometry (sampling runs in NumPy), SpectralDetector extents, and visibility (which surface a ray hits is a discrete choice).
Fresnel splitting uses a detached-sample / attached-weight estimator: the reflect/transmit branch is drawn from a detached probability while the throughput weight carries the attached reflectance, so the forward pass is unbiased and ∂flux/∂R is non-zero. One consequence worth knowing: a ghost ray carries the same per-ray flux as a direct ray, because reflection is represented by sampling the branch rather than by attenuating flux.
Validation
Gradients are checked against central finite differences with common random numbers, through a spatially varying loss (flux-weighted second moment of the irradiance map) with respect to geometric parameters, the combination illumination designers actually optimize. A flux-only loss cannot detect a landing-position error, and a non-geometric parameter never touches the intersection code, so both halves are necessary.

RMS spot radius is compared with a looser 3% tolerance (observed: 0.6% to 1.9%), since the engines sample the pupil differently, a hexapolar grid against uniform Monte Carlo, which changes the radial weighting.
Also covered: flux-ledger closure (detected + absorbed + escaped + lost equals launched, to machine precision), conic normals against the finite-differenced sag, NumPy/torch forward agreement, non-finite-gradient safety cases, and a performance smoke test.
Known limitations
Tracked on the Limitations & Roadmap page.
Visibility gradients are zero, the biggest physics gap. Silhouette, vignetting, and which-surface-hit boundaries contribute no gradient. Reparameterization (Loubet/Bangaru) is roadmap item Feature/robust materials #1.
Mesh geometry is forward-only.
Source geometry is not differentiable (see above).
No polarization.
Gradient mode is capped at ~1e5 rays x depth 16, since compaction is disabled to keep fixed tensor shapes for the autograd graph. Forward mode handles 1e7+ rays. Path Replay Backpropagation (roadmap Feat/custom surface #3) lifts this via the gradient_mode seam already present in TorchBackend.

Finalization pass on the NSQ beta. Five defects found by validating the
merge-gate claims against finite differences and against the sequential
tracer.

Geometry parameters never reached the autograd graph. Every geometry,
source, and detector constructor cast its input with float(), so
LensConfig(r1=tensor) produced loss.requires_grad == False and r1.grad
== None. The flagship notebook only worked by assigning a private
attribute (scene.component_registry.compounds[0].surfaces[0].geometry
.radius) to bypass the constructor. Scene parameters now pass tensors
through intact via _utils.as_param; the notebook uses the public API.

Conic surface normals were wrong. The radius-form expression for
dsag/dx disagreed with the analytic derivative by up to 1.2% at the
aperture edge, tilting every refracted ray on aspheric and fast
surfaces. Replaced with the curvature form (dz/dr = c*r/S), which
matches finite differences to 8 decimals. This also fixes flat
surfaces: radius=inf produced inf*0, whose backward pass was NaN for
every scene parameter, and radius=0 (the plano convention used by
LensConfig) produced an infinite sag, so plano surfaces never
intersected correctly.

Detector hit distances were detached. The torch backend routed t
through NumPy, dropping the direction * dt/dparam term from the
splatted landing position. Negligible at normal incidence (0.1%), but
26% for a fast lens with a tilted detector. t now stays attached; only
the dispatch index is decided in NumPy.

Non-finite gradients. Rays that miss a component carry t = inf;
multiplying that inside a masked be.where backpropagates 0 * inf = NaN.
RefractiveComponent already guarded this, but AbsorbingComponent and
ReflectiveComponent did not, so any scene with a mirror or a lens edge
could produce NaN gradients. Diverging Newton lanes are also frozen to
finite values. be.grad_mode.enable(), Optiland's differentiable-mode
switch, raised on the in-place normal writes in plane.py; normals are
now built functionally.

flux_conservation_error omitted total_flux_lost, so any scene that
depth-kills rays reported a large error that was not real.

Parameters that cannot carry gradients (source geometry, SpectralDetector
extents) now raise NotImplementedError rather than detaching silently.

Merge gate rebuilt. The previous gradient tests validated only
total_flux, a linear scale factor that never touches the geometry, and
test_visibility_grad_zero asserted only hasattr(). Added:

- test_nsq_geometric_gradients.py: autograd vs finite differences for
  lens radius, conic constant, and mirror radius through a spatial
  (position-dependent) loss, including the tilted-detector case;
  NaN-safety cases; the differentiable-parameter contract.
- test_nsq_sequential_agreement.py: cross-validates NSQ against the
  sequential tracer (singlet, doublet, strong asphere). Marginal ray
  heights agree to 0.04%. The aspheric case fails with the old normal
  formula.
- Flux-ledger and conic-normal tests in test_nsq_basic.py.

149 NSQ tests pass; all 12 NSQ notebooks re-executed; ruff clean.

The NSQ side read the marginal ray from the 99.5th percentile radius while
the sequential side used the true maximum. For a uniformly sampled disk the
99.5th percentile corresponds to pupil radius sqrt(0.995)*R rather than the
edge, and under strong spherical aberration (image radius growing roughly as
pupil cubed) that undershoots the marginal ray by ~0.7%. The strong-asphere
case was reporting that 0.7% as an engine disagreement when it was an
artefact of comparing two different statistics.

Both sides now take the maximum. Ghost rays, which carry full per-ray flux
under the detached-sample estimator and so cannot be separated by flux, are
rejected by a gap criterion instead: the direct cluster runs continuously out
to the marginal ray while ghosts sit several times further out.

Measured agreement is now 0.000% (singlet), 0.007% (doublet) and 0.019%
(strong asphere), stable to 0.019% worst case over eight seeds, so the
tolerance tightens from 2% to 0.2%. The aspheric case still fails against the
previous conic normal formula (5.6% deviation), confirming it retains its
sensitivity.
