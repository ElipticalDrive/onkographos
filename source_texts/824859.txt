Player value
Dense projectile fights spend quadratic work on pairs that cannot intersect even during swept movement. Preserve every Sniper/Polish interception, shell burst, alliance rule, first-contact effect and descending pair order, while cheaply excluding pairs whose swept bounding boxes are disjoint.
Implementation
For volleys of 32+ bullets, reuse one per-game 4-number-per-shot bounds array; no per-pair allocations.
AABB test is conservative: only reject when separated by more than the sum of projectile radii + existing 1.5 allowance; tangent/high-speed crossing remain eligible.
Below 32 bullets the original narrow-phase path runs without setup.
No gameplay stat or collision-response changes.
Evidence before PR
Executed the real old and modified Sniper module wrappers in one JS runtime across 5,000 seeded randomized worlds: 0 divergent projectile/effect outcomes. Synthetic sparse stress: 512 bullets, 488 repetitions, old 28,768ms vs new 13,699ms (~2.10×). This is isolated resolver time, not FPS.
Regression gate
New test compares actual Sniper resolver with its AABB gate disabled under dense crossings, tangencies, shell-child birth, allegiance, 30/60/120/240 FPS displacement and Sniper+Polish composition. Await CI/build/browser smoke before merge.
Risks
The index remains quadratic, so this is a low-risk narrow-phase cost reduction, not a full spatial-index rewrite. Bounds are captured once at resolver entry; current collision callbacks do not mutate projectile trajectories except temporarily while bursting and restore them before returning.
