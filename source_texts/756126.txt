What this adds
Until now, mesh.adapt() refused 3D meshes honestly. This PR makes adaptive refinement exist in 3D: the same engine-less call that works in 2D now returns a graded tetrahedral child mesh, in serial and in parallel, and it can be layered on top of mesh.redistribute_nodes() so the node mover shapes the coarse mesh and the refinement adds detail where the metric asks for it. The user API does not change.
How it works, in plain language
A tetrahedron cannot simply be cut the way a triangle can: cutting the longest edge of each cell independently produces meshes whose corners get worse and worse. The method used here (newest-vertex bisection with tagged simplices) gives every cell a small amount of memory — which edge it should split next — and hands each child the right memory in turn. With the starting assignment chosen by a colouring of the mesh vertices, the theory guarantees the process always terminates, cells never degenerate (each starting cell produces at most 36 distinct shapes, ever), and the number of extra cells split to keep the mesh conforming is bounded. The references with the details are in the design note; the two key papers are Maubach (1995) and Diening, Gehring & Storn (2023).
The refinement runs inside PETSc's mesh-transform machinery, so boundary labels ride through automatically and each pass stays aligned with the parallel decomposition. Every rank computes the same starting assignment from geometry alone, so the refined mesh is identical no matter how many processors are used — the tests pin exact cell counts (5,198 in the 3D gate; 36,040 in the evaluation problem) at 1, 2, and 4 ranks.
Multigrid viability was a gate at every stage: on each refined mesh, geometric multigrid built from the refinement hierarchy matches an algebraic-multigrid reference and reproduces an exact linear solution (which also proves the boundary labels survived).
Composition with the node mover
redistribute_nodes() then adapt() now does what it says: the refinement starts from the moved node positions (previously it silently refined the unmoved base), and the multigrid ladder is adjusted to match. In the 2D fault evaluation this combination places the fine layers evenly along the fault trace, where refinement alone leaves pinch points inherited from the coarse mesh.
A real parallel bug found on the way (closes #376)
Validating the combination in parallel exposed a long-standing data-layer bug: writing to a masked slice of a variable (var.data[mask] /= s) fired the internal PETSc-sync callback on the temporary copy that numpy creates. In serial this only produced a swallowed warning. In parallel the mask differs across ranks, so some ranks abandoned the sync before its collective MPI calls while others entered them — and the run hung. The callback now only ever syncs the variable's actual storage (mesh and swarm variables both). An independent adversarial review of the branch then caught two further defects in the new code — a cloned mesh sharing its coordinate storage with the original, and a corner of the #376 fix that could itself become rank-asymmetric on empty ranks — both fixed with regression tests.
Also included
The per-cell marking geometry is now computed in one vectorised operation (it dominated wall time at deep refinement).
A profile="hyperbolic" option for the surface refinement metrics: cell size grows in proportion to distance from the surface, which the mesh evaluation found gives the best transition quality per cell. The docstrings say when to prefer each profile.
Evidence
Serial: full adapt-family and surfaces sweep, 127 tests green; new gates test_0840 (3D serial), test_0841 (native tet transform vs the reference engine), test_0764 additions (composition + warning-free mover).
Parallel (np=2 and np=4): test_0839/test_0842 confluence and multigrid gates green; the redistribute-then-adapt combination runs clean with multigrid converging in 2 iterations on the combined mesh.
Style gate clean, no allowlist additions.
Design note with the full technical narrative and per-stage status: docs/developer/design/ADAPTIVITY_3D_SPHERICAL_2026-07.md. Rendered mesh evaluations: ~/+Simulations/nvb_3d_adapt_evaluation/.

…er-pass closure (stage 1c-ii)

The UWNVBRefine drain-loop driver now serves tetrahedral meshes: each
tet's refinement state (Maubach vertex ordering + tag, packed into one
per-cell label value) is decoded to find its bisection edge, and the two
children's states are rebuilt after every pass by the fixed Maubach
recipe. The initial state is computed once in Python
(write_tagged_state_label, which runs the serial engine's own
coloring-based initialization) so the native driver and the serial
engine share a single seed implementation. mesh.adapt() on a 3D mesh at
np=1 now prefers the native driver, exactly as 2D does.

One structural change to the shared driver, needed for 3D and harmless
in 2D: the conforming closure (finding the neighbours that must split
first) now re-runs at the top of every drain pass instead of once up
front. In 2D one split always unblocks a waiting cell, so a single
up-front closure was enough; in 3D a cell can be blocked by children
created mid-drain across several generations, and the original
structure deadlocked ('drain stalled'). Re-growing an already-complete
closure adds nothing, so 2D behaviour is unchanged (exact-mesh
regressions 0836/0837/0838: 21/21).

Gates: test_0841 native-vs-serial-engine equality over 3 passes of
graded refinement (identical cell sets); test_0840 5/5 with the native
driver in the loop (FMG parity, label transfer, orientation class);

…#376)

The canonical callback on variable arrays is inherited by every derived
array, so a masked in-place update (data[mask] /= s) fired it on the
fancy-indexed COPY and tried to pack the subset into the full-size vec.
In serial that was a swallowed warning; in parallel the mask is
partition-dependent, so ranks where the pack failed skipped its
collective sync while the others entered it — mismatched collectives
that hung the MMPDE mover at np=2 (found validating the 3D adaptivity
composition slice).

The callback now only ever syncs the canonical storage it was
registered on: a copy is skipped (numpy's write-back through the parent
does the real sync on every rank), a partial view packs the full
canonical. Same guard in the MeshVariable and SwarmVariable callbacks.
Regression test locks redistribute_nodes warning-free on a
refinement=1 mesh (the trigger: one zero-magnitude corner normal).

…o-size guard

Two review findings on this branch's own additions, both verified
empirically before fixing:

1. The moved-coordinate carry in _adapt_nested wrote through the
   clone's getCoordinatesLocal().array — but DMClone shares the
   coordinates Vec by reference, so the write silently moved the
   parent's static hierarchy level (self-masking: the next _moved
   check then compared moved-vs-moved). The clone now installs a
   duplicated Vec. New regression test locks redistribute->adapt
   refining the moved geometry while the hierarchy stays untouched
   (validated failing against the unfixed build).

2. The #376 callback guard classified view-vs-copy with
   np.may_share_memory, which is False for ANY zero-size array — a
   rank whose slice is locally empty would classify a view as a copy
   and skip the collective sync the other ranks enter, re-creating
   the rank asymmetry the fix targets. View-vs-copy is now decided
   by identity in numpy's base chain, which follows the indexing
   statement and is identical on every rank (zero-size included).

Also from review: the distributed tagged-state seed now fails loudly
if distinct vertices collapse to one rounded coordinate key (silently
wrong partition-dependent coloring otherwise), and a stale
NotImplementedError claim in test_0840's docstring is corrected.

A focused re-review of the prior review-fix commit found one corner and
one latent hazard, neither blocking:

- The callback guard's rank-symmetry comment overclaimed: reshape/ravel
  of a NON-contiguous derived view is a copy on non-empty ranks but a

  the comments now say so and point at the #379 dirty-flag flush.

  owned vertices (false-positive RuntimeError on a healthy mesh) and
  its allreduce could go asymmetric if the SF were ungraphed unevenly.
  Every rank now enters the reductions unconditionally and the check is
  skipped collectively when any rank cannot count.
