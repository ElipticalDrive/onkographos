F58.9.11: compress splats, crop floaters, a better Your room
Matt, 2026-10-14: "The Your Room example should be a bit better than it is... very splotchy and low resolution right now." and "Is there a compression for gaussian splats that we could implement thats open source?"
What is built
npm run splat:compress and a compress stage in scan:room and the gen-assets splat stage, using splat-transform 3.8.0 (MIT, pinned devDependency, host scripts only). Every compressed copy is converted back and checked (same count, extent within 2%); the receipt records hash, size, ratio and lossy: true.
Robust extent (1st-99th percentile box plus 10%) used by scan:room to crop floaters and by the app's surround fit, plus a scale cap that drops oversized Gaussians (the streaks outside the walls). Unit-tested with planted outliers.
App imports .sog as well; SPZ and SOG are decoded with the renderer's own decoder for a real count and extent. Found by the e2e: splat-transform writes SPZ v4 (raw NGSP, not gzip), which the old header check refused.
Your room is now a reconstruction (COLMAP + Brush) of a rendered synthetic Blender room: 280,000 Gaussians, 4.86 MB .spz. scan:room gains --resume, --export, --max-gaussians, --sh-degree, --max-scale-fraction.
Measured (2026-10-14, one run each): 760,719 Gaussians, 179.5 MB PLY. SPZ on CPU 4.5 s, 17.5 MB (10.3x). SOG on CPU did not finish in over 3 hours (stopped). SOG on a GPU 9 s, 12.9 MB. So SPZ is the default and SOG is opt-in and refused without RECKONS_SPLAT_GPU. Floaters: raw extent 141.5 units, robust 24.9; surround scale 0.07 becomes 0.40.
Not true / weak (also in kpred:remaining): judged only in headless software rendering. Zoomed out the room is a clean block; zoomed in the sofa and shelves are recognisable but still soft and smeared. No PLY/SPZ/SOG pixel difference was measured. The 4.9 MB budget cost view-dependent colour and 63% of the Gaussians. The robust extent is a percentile rule tried on one synthetic reconstruction. Matt's real studio scan "very bad blob" needs the person to set centre and scale and clean the data (F58.9.12), not this PR.
Checks (2026-10-14): vitest 4077 passed (14 todo); npm run check 0 errors; build OK; your-room e2e 5 passed (headless Chromium); gen:check, graph-lint (0 errors) and md-align pass.

…and extent (F58.9.11)

The app accepts .ply, .spz and .sog (file input, kind detection, asset references, export and
import round-trip). SPZ and SOG are no longer judged by header alone in the browser: the
renderer's own decoder (gaussian-splat-lite Splats, which needs Web Workers) decodes them, and
the centres are checked for count (against the SPZ header), finite values and a robust extent.
Found by the e2e: splat-transform writes SPZ v4 by default, which is raw NGSP, not gzip, so the
old header check refused every file we produce; v4 now has its own header check. Without a
decoder (Node, unit tests) the check is header-only and its note says so. Level the floor reads
SPZ and SOG through the same decoder. Verified in headless Chromium: a .spz and a .sog are
decoded, stored and drawn, and a broken .sog is refused.
