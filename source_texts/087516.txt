Contributor
Adds a complete 3D inverse-distance weighting (IDW) interpolation pipeline that generates a scalar field from drill-hole sample data and renders it as a shader-driven voxel volume inside the existing Three.js scene.
New modules
Pure-JS interpolation kernel (no Three.js dependency)
SpatialHash3D — uniform 3D hash grid; queryRadius() and queryKNearest(); O(1) cell lookup, predictable performance for static datasets
IDWSampler — getValueAt(x,y,z) with configurable power, searchRadius, maxNeighbors, minNeighbors, epsilon; exact-hit short-circuit; designed for reuse by future slice/section/probe tools
computeVolumeBounds — AABB with configurable padding from any {x,y,z} point array
buildVoxelGrid — evaluates sampler onto a Float32Array voxel grid; async with event-loop yielding, onProgress callback, and cancellation token
buildInterpSamplesFromAssays — extracts midpoint support points from desurveyed assay rows; falls back to straight-line-vertical when desurvey coords are absent
Three.js rendering
IDWVolumeRenderer — uploads grid as Data3DTexture (one float/voxel), raymarches through a unit-cube ShaderMaterial; supports block mode (snap to voxel centres → crisp block-model look) and smooth compositing; display min/max, opacity, threshold, and colour gradient are uniform-only updates (no texture re-upload)
Inline GLSL (idwVolume.vert/frag.glsl) — front-to-back compositing, nodata sentinel skip (< -1e29), two-stop colour transfer function
Integration layer
IDWVolumeLayer — orchestrates the full pipeline; exposes setSamples, setIDWOptions, setGridOptions, rebuild(), getValueAt(), dispose(); cancels in-flight builds on re-trigger
Usage
```
const samples = buildInterpSamplesFromAssays(assayRows, 'Au_ppb');

const layer = new IDWVolumeLayer({
  samples,
  idw:        { power: 2, searchRadius: 60, maxNeighbors: 16 },
  grid:       { dims: [64, 64, 64] },
  displayMin: 0,
  displayMax: 500,
  opacity:    0.4,
});

await layer.rebuild();
scene.add(layer.object3D);

// Runtime display tweaks — no rebuild needed
layer.setOpacity(0.6);
layer.setThreshold(0.1);
```
Architecture notes
Interpolation math has zero Three.js imports → reusable by section/slice/probe tools without scene context
IDWVolumeLayer wires the pipeline but IDWSampler and buildVoxelGrid are independently importable
Shader clipping-plane support is present via ShaderMaterial for future slicing features
Memory: 64³ ≈ 1 MB, 128³ ≈ 8 MB, 256³ ≈ 64 MB — documented in buildVoxelGrid.js
Tests
39 unit tests added covering InterpSamplePoint, computeVolumeBounds, SpatialHash3D, IDWSampler, and buildVoxelGrid. Three.js-dependent modules follow existing repo pattern of not being unit-tested.

<issue_title>3d idw</issue_title>
<issue_description># Baselode Feature Specification: 3D IDW Interpolation Volume and Voxel Visualisation
Purpose
Add a new Baselode feature that generates a continuous 3D scalar field from drill-hole sample data using inverse distance weighting (IDW), then visualises that field inside a bounded 3D volume as voxels in the existing Three.js scene.
This feature is intended for exploration-style inspection of interpolated values such as Au_ppb, Cu_pct, or any other numeric downhole/sample attribute. It should work on a selected set of drill holes and support later extension to section and slice tools.
Goals
Compute a 3D bounding volume from a set of selected drill holes or sample points.
Build a spatial lookup structure for efficient nearest-sample queries.
Implement IDW interpolation for any point in 3D space.
Voxelise the interpolation volume and render it efficiently in the scene.
Expose controls for attribute selection, IDW exponent, search radius, voxel resolution, and display thresholds.
Design the implementation so it can later support section/slice inspection along X/Y/Z planes.
Non-goals for first implementation
No kriging, RBF, or advanced geostatistics.
No anisotropy or variogram modelling.
No hard geological domain constraints.
No implicit meshing / iso-surface extraction in v1.
No production-grade resource estimation claims. This is a visual analytic tool only.
User story
As a user viewing drill holes in a 3D Baselode scene, I want to select a numeric sample attribute and generate an interpolated 3D voxel volume around those holes so that I can visually inspect spatial patterns and potential trends between samples.
Scope
Inputs
A Three.js scene already containing drill-hole geometry and/or drill-hole sample data.
A selected subset of drill holes, or all currently visible drill holes.
A numeric sample attribute name, e.g. Au_ppb.
Sample intervals with 3D locations.
Optional interval lengths, downhole traces, and desurveyed positions.
Outputs
A computed 3D interpolation volume over a bounded box.
A rendered voxel/block-style representation in the scene.
A reusable scalar-field evaluation API for arbitrary 3D points.
Parameters exposed to the application/UI.
Data assumptions
The interpolation should operate on sample support points in 3D.
Preferred input form per sample:
```
type InterpSamplePoint = {
  id: string
  holeId: string
  x: number
  y: number
  z: number
  value: number
  from?: number
  to?: number
  length?: number
  metadata?: Record<string, unknown>
}
```
How sample points are derived
For interval data, create a representative point for each interval.
Default approach:
Use the midpoint of the sample interval along the drill trace.
Use desurveyed coordinates if available.
If desurvey is unavailable, allow a fallback assumption such as vertical or straight-line collar-to-end-of-hole.
This feature must not assume only collar positions. It should interpolate from interval/sample support points distributed downhole.
Functional requirements
1. Bounding box generation
Create a 3D axis-aligned bounding box that encloses the selected drill holes or selected sample points.
Requirements
Compute bounds from all participating sample points.
Allow optional padding in world units on all sides.
Store:
minX, minY, minZ
maxX, maxY, maxZ
dimensions
center
Support user override of padding and resolution.
API shape
```
type VolumeBounds = {
  min: [number, number, number]
  max: [number, number, number]
  size: [number, number, number]
  center: [number, number, number]
}
```
2. Spatial lookup / neighbour search
IDW should not scan all samples for every voxel if the sample count is large.
Requirement
Implement a reusable spatial index for 3D nearest-neighbour or radius-based queries.
Acceptable implementations
Uniform 3D grid / hash grid
KD-tree in 3D
Octree
Recommended v1
Use a simple spatial hash grid because:
data are static for each interpolation run
implementation is straightforward
radius queries are easy
performance is predictable
Required capabilities
insert sample points
query points within a search radius
optionally cap to max nearest neighbours
handle empty-neighbour cases
API shape
```
interface SpatialIndex3D<T> {
  build(points: T[]): void
  queryRadius(x: number, y: number, z: number, radius: number): T[]
  queryKNearest?(x: number, y: number, z: number, k: number): T[]
}
```
3. IDW interpolation
Implement inverse distance weighting for any point in 3D.
Formula
For a query point p, using nearby samples i:
weight: w_i = 1 / d_i^power
interpolated value: v = sum(w_i * value_i) / sum(w_i)
