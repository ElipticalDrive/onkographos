This PR implements support for traversal of linear tetrahedral elements in XDG. This is enabled by the XDG::segments method. The implementation of the method relies on the same implementation for all mesh managers via use of an abstract ElementFaceAccessor object that binds a mesh manager and element in a concrete implementation to return information about a given face. Here's a high-level description of the changes:
Adjacencies
An adjacency data structure for MOAB elements has been added to the MBDirectAccess class. Unlike connectivity and coordinate access, this information is stored directly to avoid querying this information via the MOAB interface (to circumvent the well-known issues with scalability in threaded access).
For libMesh, adjacencies are accessed on a Tet4 pointer via the side_nodes_map attribute rather than the node_ptr method. This was recommended by the libMesh team to avoid capturing a lock when creating what are referred to as proxy node objects.
Ray Traversal and Element Walking:
The methods MeshManager::next_element and MeshManager::walk_elements manage the processes of determining the distance to the next face and the element on the other side of that face (if any) and traversal across contiguous blocks of elements in space, respectively.
Constants and Configuration
A couple of new constants, PLUCKER_TOL and TINY_BIT, are used to handle some numerical issues seen in testing. The first is used to manage co-planar rays in triangle intersection routines and the second is used to avoid co-planar rays during element searches.
