Summary
C-31 froxel-cost fix (FINISH-LANE-07 Phase B P1): the volumetric path now responds to measured GPU cost instead of running the full froxel pass unconditionally.
Cost gate: notePrd07VolumetricGpuMs(device, ms) is the feed surface for a runtime that measures the volumetric pass (same shape as ParticleRenderHook.noteGpuMs). prd07VolumetricCostFallback(device, budgetMs) applies an EWMA + hysteresis policy identical to LowResAutoBudget — 8-frame warmup, fallback on above budget, off below 75%. When it engages, prd07.volumetric returns no passes and publishes prd07.volumetric.costFallback = "VOLUMETRIC_COST_FALLBACK" on the blackboard; the analytic fog path covers the frame. Budgets: 1.2ms froxel-medium / 2.0ms froxel-high; WebDriver (software GL) pins 0.6ms.
Temporal slice budget: VolumetricFogPass.update previously ran slices scissored inject draws every frame (up to 128 on froxel-high). Temporal grids now inject ceil(slices/8) per frame rotating through the atlas — the temporal accumulation hides the staggered update. Non-temporal grids keep the full per-frame inject.
New unit test froxel-cost.test.ts covers warmup, engagement, hysteresis release, and the budget table.
Verification
Lane unit suite green locally (4 new tests pass; tests/qr/prd07 vitest). Rendering tsc --noEmit clean. Lane remote CI pending on head.
Browser/capture: NOT RUN (remote-only lane rule). The measured-ms feed has no producer yet on main — the gate inerts until a runtime calls notePrd07VolumetricGpuMs (mirrors noteGpuMs, which is off until a runtime measures).
