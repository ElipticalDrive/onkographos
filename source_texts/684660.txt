It seems that there are some changes in cuda 12 :
CUDA texture objects replaced CUDA texture references in the 2012 (CUDA SDK 5.0 toolkit) and could be removed at any time from future SDK releases by Nvidia as they were depreciated in April 2021 (CUDA SDK 11.3).
What are your thoughts about it, should we try to correct the code to take into account this evolution or should we start from scratch ?

Hi @jeffwitz, indeed the textures in use in this implementation are deprecated, they must be replaced by bindless textures in order to work with modern versions of CUDA. Hi again, i just came to realize that bindless textures are not supported by pycuda (see here). This means that this problem would require a lot more effort to fix than i expected. Here are the options i can see to allow the project to move forward :
Switch to another CUDA binding that does provide the interface for bindless textures such as CuPy
Move all the computing part to pure CUDA and use ctypes or write a CPython module
Add bindless texture support to PyCUDA and make a PR (or wait until someone decides to implement bindless textures in PyCUDA, but since the issue date back to 2016, i would not count on that too much)
Another interesting option would be to move to ROCm HIP. Even though the project is far from mature, i find the promise of running on both AMD and Nvidia cards appealing.
