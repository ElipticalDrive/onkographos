Gaussian tile loading creates separate spherical harmonics (SH) coefficient arrays before it packs the rendering data.
This pull request packs SPZ decoder data directly into the existing dense format.
It also adds an application-wide position-cache limit for the shared sort worker.
Gaussian tile loaders use an explicit packed-data field and separate cache keys.
Ordinary attribute loaders retain their existing output and can share decoder data.
GaussianSplatPrimitive.maximumCacheByteLength controls retained position bytes. The default remains 128 MiB. Zero disables retention.
Budget changes evict entries without requiring camera movement. Deferred tasks carry the latest budget.
Production measurements use two interleaved pairs per asset on an NVIDIA RTX A4000 with locked clocks.

These memory values follow garbage collection. They do not measure peak process memory.
Two pairs do not establish statistical confidence.
Validation:
554 targeted tests pass across loading, glTF, resource-cache, and Gaussian-splat groups.
Exact packing comparisons pass for 262,144 splats per degree, degrees 0 through 3, including exceptional float values.
Six active tilesets exercise budget changes and disabling. Invalid values fail validation. Disabling also removes and refuses zero-length entries.
Twelve production load/remove cycles return position retention to zero and graphics-resource counts to baseline.
Removed array storage stays near 22.6 MB. JavaScript heap grows approximately 1.3 MB; indefinite memory stability remains unproven.
Normal commit hooks pass lint, formatting, and TypeScript checks.
The production report and raw-result summary are in docs/splat-perf/production-loading-2026-09-07/.
The earlier four-experiment report and harnesses are also included for review.
Worker decoding remains experimental because complete-view latency regresses. A second hardware graphics backend remains untested.
This pull request builds on merged pull requests #1, #2, and #3.
