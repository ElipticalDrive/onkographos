Summary
Modernizes the voxel terrain surface-extraction pipeline so chunk meshing scales with CPU cores and stops generating GC pressure on the hot path.
SurfExtractorCpuMC — parallel worker pool (was 1 thread + busy-wait):
Spawns clamp(processorCount - 2, 1, 6) background workers, each with its own WorkerContext { MarchingCubesSW, chunkDataBuffer }, so multiple chunks are meshed concurrently (output pools GenericPool/MCOutputData were already thread-safe).
Replaces the Thread.Sleep(1) busy loop with an AutoResetEvent (workers sleep when idle, are woken by AddSurfExtractReq).
PickReqToProceed no longer does per-pick LINQ Where(...).ToList() plus an O(maxLod × N) rescan; it now removes invalid requests and picks the lowest-LOD request in a single allocation-free pass.
IsIdle/IsAllClear now track in-flight work via an Interlocked counter instead of a single shared buffer pointer; Reset drains in-flight requests instead of killing/recreating the thread; threads are IsBackground so they can't hang process shutdown.
MarchingCubesSW:
The 64999-entry indicesConst array (~254 KB) is now lazily built — only the editor RebuildMesh path needs it, so terrain workers no longer pay it per instance.
Caches edgeTable[cubeindex] in a local for the 12 edge tests per cube; pre-sizes vertex/normal lists.
SurfExtractorCpuB45 (building-block extractor): same allocation-free single-pass request picking, and its worker thread is now a background thread.
No changes to mesh output format, request/req-pool interfaces, or the OpenCL extractor path.
