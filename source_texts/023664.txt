What changed
Optional CUDA backend for open4d/codecs/tsmc/source/arap-volume-tracking, enabled with the cuda mode flag (<mode>process cuda</mode>). Without the flag the managed code runs unchanged.
Native/: CMake project building bin/libarapcuda.so (CUDA kernels + C API).
Voxelization: per-triangle column crossings + prefix XOR along z; byte-identical to the managed voxelizer.
Nearest-center scan for the Lloyd gradient, LloydStats and the affinity sums; grid resident on the GPU per frame, sums in double.
Framework/Cuda/ArapCuda.cs: P/Invoke bindings.
VolumeGrid.GetTransformDistances replaces the GetPoints + new TransformDistance(...) pattern in Distances, TransformDistSmoothWeights and Stats.
Build:
```
cmake -S Native -B Native/build && cmake --build Native/build -j
dotnet build -c release
```
Verification
Answering sample, 10 frames, 2000 points, grid 512, process vs process cuda:
Wall time: 260.8 s → 14.9 s.
Volume grids: byte-identical for all 10 frames.
DFU 0.07672 → 0.07659; PCA compactness 0.86002 → 0.86007.
Tracked points: mean distance between runs 0.12–0.19 voxels; floating-point differences accumulate over iterations (max 10.5 voxels by frame 9).
scripts/check_provenance.py and scripts/check_markdown_links.py pass.
Ubuntu 24.04, .NET 10, CUDA 12.6, RTX 4090 (sm_89).
Safety checklist
Tests cover success, empty input, and relevant failure paths.
Optional dependencies remain optional and have actionable errors.
Wheel/sdist boundaries are unchanged or their exact checks were updated.
.github/THIRD_PARTY.md was updated for copied code, data, models, papers, media, binaries, or submodules.
No credentials, private captures, generated outputs, or local datasets were added.
Documentation and status claims match verified behavior.
Remaining limitations
The 2000×2000 transform-distance matrix is still managed code (~7.6 s of the CUDA run).
No automatic CPU fallback when the library or a GPU is missing; cuda must be set explicitly.
Tested on the whole-scene answering meshes only, not on SAM3 dynamic-part meshes, the IIR mode or global optimization.
The wheel/sdist checks were not run; the change is confined to source/.

Voxelization and the voxel-to-nearest-center scans (Lloyd gradient,
statistics, affinity sums) dominate ARAP volume tracking. The new
mode flag `cuda` runs them on the GPU through Native/libarapcuda.so;
without it the managed code runs unchanged.

- Voxelization: each triangle flips one bit per covered column and a
  prefix XOR along z recovers the odd-crossing occupancy. Grids are
  byte-identical to the managed voxelizer.
- Nearest-center scan: the grid stays on the GPU per frame; 4x4x16
  bricks prune candidate centers, and counts, sums and second moments
  are accumulated in double.

🩺 Stability & Availability | 🟡 Minor | ⚡ Quick win
Guard against best == -1 for occupied cells.
best starts at -1. The update at Line 145 requires d < bestD, or d == bestD && i < best. If every candidate distance is NaN (non-finite point coordinates or non-finite grid origin/a), neither condition is true. best then stays -1.
For that cell, Line 169 and Lines 178-193 index counts[-1], sums[-3..-1] and second[-6..-1]. This writes out of bounds on the device. The result is silent memory corruption or a sticky cudaErrorIllegalAddress. arap_grid_assign does not validate that the inputs are finite.
Add a fallback after the loop so that an occupied cell always has a valid index. A fallback after the loop is safer than seeding bestD, because a NaN bestD would block finite candidates from winning.
