Thanks for developing this amazing package. It makes rendering 3D mesh really easy in R. I was trying to visualize some brain data when I realize that the control is trackball, and the camera is perspective. I wonder if it's possible to support ArcballControls and OrthographicCamera? Here are the comparisons:
ArcballControls provides stable controls and does not rotate the camera up direction
OrthographicCamera does not distort the objects when they are far from the camera. This is important when drawing 3D sphere/points that use sizes to represent statistics.
ArcballControls + OrthographicCamera
Trackball + PerspectiveCamera

Thanks for the interest and input!
I've just added some basic support for choosing an Orthographic camera in the branch "add_camera_options". Usage is as follows
```
  p <- plot3js(
    x = iris$Sepal.Length,
    y = iris$Sepal.Width,
    z = iris$Petal.Length,
    col = rainbow(3)[iris$Species],
    xlab = "Sepal Length",
    ylab = "Sepal Width",
    zlab = "Petal Length"
  )

  r3js(p, camera = "orthographic")
```
It messes up the way different axis and plot faces are shown and hidden on rotation though, so that will require some fixing.
ArcballControls look neat, thanks for the suggestion. I'm sure they can be integrated but might take a bit of time since I think it may require updating all the code to use the latest threejs version, I'll look into it.

Thanks again for your input, I just pushed a new development version to the branch update_3js which now incorporates arcball controls and fixes the plot axes visibility issues that introducing an orthographic camera caused.
To integrate arcball controls, plot interaction now moves the camera rather than rotating the scene. This changes how you set your initial plot rotation etc. since you are setting the camera rather than plot. I guess this doesn't really create any problems other than perhaps making the "rotation", "position" and "zoom" settings slightly less intuitive.
In my use case if I want to fix the initial plot viewing angle I would anyway rotate the plot in the viewer and copy over the rotation settings etc. so I can update the code so this behaviour still works.

Yes, when first building these tools it made more sense to keep the camera fixed and rotate the scene, but this means you can't use the threejs built in controls, which are much better.
