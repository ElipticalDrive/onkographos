Issue body actions
Height-preserving cleaning and surface meshing now have a validated checkpoint, but the resulting volume meshes can contain almost-flat tetrahedra and microscopic incursions into intended building regions. Track and fix this separately from further footprint-cleaner work. No numerical prototype has been accepted; this issue is unresolved.
Reproducible evidence
Download the complete evidence bundle · Instructions and file guide
The attachment is pinned to an immutable evidence commit. It contains numeric, pickle-free PLC inputs, captured volume outputs, source and roof GeoJSON, a standalone TetGen replay/auditor, upstream synthetic reproductions, plotting scripts, source-checkpoint patch/fixtures and checksums. No live provider, raw LiDAR, private scratch directory or full core build is needed for the direct PLC replay.
All three captured PLCs were independently replayed on the recorded environment and produced identical vertices and cells. Both synthetic cases were also regenerated through public core APIs with identical output. These are real default-volume failures, not rejected-prototype-only examples.

The thresholds above are diagnostic bins for these metre-scale fixtures, not a universal mesh-quality specification. The last row demonstrates why the centroid check alone is insufficient: it has a near-flat tetrahedron without a below-roof centroid.
Lund's minimum volume is 2.7953e-14 m³ and minimum quality is 8.6614e-12. The thinnest recorded cell has edges from 0.0234 to 0.4739 m and altitude approximately 0.0113 nm. These are almost-flat cells, not uniformly tiny cells. Exact arithmetic confirms tiny positive volumes for the stored doubles. For the eight-spoke case the floating minimum-volume estimate is 1.1842e-15 m³; its exact rational value is approximately 9.2030e-17 m³. Both are defective shapes.
The saved meshes pass the existing incidence/orientation and roof/source coverage checks. The strict volume gate remains failed. Lund has 21787 tetrahedra below quality 0.02; that broader poor-quality tail is distinct from the near-flat-cell defect and is not fixed by merely changing a containment tolerance.
The normal-distance illustration uses nanometres laterally and metres vertically. It deliberately magnifies the lateral error; it is not an isotropic view. Cell 39672's centroid is below the intended 44.862 m roof and strictly inside its XY footprint. Its approximately 0.86 m vertical deficit must not be confused with its sub-nanometre lateral incursion.
Reproduction
After extracting the bundle, follow its README to create a Python 3.11 environment with NumPy 2.4.6, Shapely 2.1.2 and:
```
python -m pip install 'dtcc-tetgen-wrapper @ git+https://github.com/dtcc-platform/dtcc-tetgen-wrapper.git@22ab9ff2ee1dd03f82ce24dd0f378f00da7e487c'
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1
python audit_volume.py lund --replay --output lund-replayed.npz
python audit_volume.py synthetic-6 --replay --output six-replayed.npz
python audit_volume.py synthetic-8 --replay --output eight-replayed.npz
```
Exit code 1 is expected when the defect is reproduced. Native ordering may differ across platforms; compare the geometry and exact/scale-aware metrics when cell IDs differ. The script also audits saved outputs without invoking a mesher. Its spatial query padding only selects candidate tests; it does not allow XY boundary crossings.
The synthetic source examples have a 10 m radius outer hexagon/octagon, alternating high sectors truncated 0.1 m from the centre, and a low background source. Roofs are 20/25/30[/35] m and 6 m. Their transformed source GeoJSON and conditioned roofs are included. reproduce_synthetic.py constructs a flat terrain and calls the public cleaning/volume APIs, then captures the PLC. Instructions include restoration of the exact uncommitted core checkpoint in a separate checkout.

Provenance and likely investigation boundary
Of the 20 distinct XY positions implicated in tiny Lund cells, two are ground-mesher input graph vertices and 18 first appear in native 2D constraint subdivision. The input graph has 4375 points/3335 segments; native output has 15162 points. The wall builder copies XY and subdivides Z. All 20 tiny tetrahedra use existing PLC vertices. Eleven are in a newly restored-height block and nine in an unchanged block.
The near-collinear constraint chain therefore predates TetGen. This does not establish that only one library is responsible. The ground graph/output and exact-coordinate traces are included. Surface triangle quality is not a sufficient volume-admission guarantee.
Adaptive predicates can make correct decisions for stored coordinates; they do not restore intended collinearity after inexact point construction. Exact-lattice examples in the bundle show that some fixed endpoint pairs have no exactly collinear interior float64 point. This rules out exact projection as a universal solution, not every smaller construction/connectivity correction.
Rejected approaches and remaining options
Keeping subsequent volume construction in local XY fixed Lund but introduced a tiny cell in a transformed eight-way case.
Unrestricted dyadic reconstruction inverted a 2D triangle (signed twice-area −1.1331e-4 m²). Some adjustments needed up to 17.323 mm of tangential movement despite tiny normal error.
Guarded dyadic reconstruction plus local coordinates passed nine initial saved cases, then failed 3/18 transformed cases, including two exact centroid failures. It was rejected; no production code was adopted.
Earlier same-PLC TetGen quality-option trials failed with native error 2; optimization/coplanarity trials did not establish a general solution. These do not justify a default switch change.
The existing Triangle backend comparison remains uncompleted because that backend was unavailable in the previous locked environment. Build it separately before concluding that coordinated exact constructions across both native libraries are necessary.
The transformed matrix used six/eight spokes, angles 0/23/89.9°, and offsets (0,0), (100000,200000), (386500.25,6174500.75). Baseline: two degeneracy cases, one exact-centroid failure case. Rejected candidate: three degeneracy cases, two exact-centroid failure cases. All 36 meshes retained source partitions/heights and had zero PLC shell triangles below quality 0.02.
Acceptance and scope
Reduce one supplied failure further and identify the smallest general correction at the construction/constraint/volume interface. A coordinated exact-construction kernel is an unproven option, not the prescribed implementation.
Preserve all roof elevations, exposed source ownership and the fidelity/coverage contract; no additional whole-block flattening.
Validate both boundary conformity and element degeneracy on actual returned world-coordinate meshes, including the supplied transformations. Exact internal semantics alone do not establish valid rounded output.
Keep finite positive cells, conforming incidence/orientation, roof coverage and zero strict below-roof centroids. Retain dimensional and scale-normalized quality diagnostics; centroid-only success is insufficient.
Do not delete cells without conforming reconstruction, widen audit tolerances, add footprint repair families, or change TetGen defaults merely to pass examples.
If shared 2D output changes, rerun the full 2000-task flat/surface survey, ownership/fallback comparisons, native tests and established controlled performance protocol. Keep the cleaning/surface checkpoint independent of this deferred volume fix.
