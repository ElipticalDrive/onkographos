Goal
Baked lighting for static scenes: the cheapest way to high-quality indirect light, and the standard indie workflow.
Approach: GPU lightmapper first
GPU lightmappers are standard: Unity's Progressive GPU Lightmapper, Bakery, Unreal's GPU Lightmass, and Godot 4's
LightmapGI, which path-traces in Vulkan compute shaders over its own BVH and needs no ray-tracing hardware. Turian is
Vulkan, so it can do the same:
Compute path (baseline, any Vulkan GPU): BVH built on the CPU, uploaded once; progressive path tracing in compute
shaders, accumulated per lightmap texel; denoise (e.g. Intel Open Image Denoise, optional native)
Hardware path (when available): VK_KHR_ray_query / VK_KHR_ray_tracing_pipeline for a large speed-up
CPU fallback / reference: Prowl.Photonic (MIT, BVH4 + AVX2) for headless CI bakes and machines without a
capable GPU, and as a correctness reference
Lightmap UVs: Prowl.Unwrapper (MIT, pure C#; projection and conformal/LSCM) — usable as-is, or replaced later.
The same compute path tracer can bake the light probes and irradiance volumes of #58.
Tasks
"Generate lightmap UVs" model import setting (second UV set; the FBX importer already reads uv1)
Static flags per node (contribute GI, receive lightmaps)
GPU compute baker (progressive, previewable in the Scene view while baking), optional hardware ray tracing path
CPU fallback for headless bakes
Denoising pass
Bake job as a background task with progress and cancel; results stored as texture assets per scene
Shader path: sample lightmaps for static objects, light probes for dynamic ones
Light probe groups (baked SH), shared with the irradiance volumes of Bistro E2: draw-loop hot path — cached render list and material sort #58
Mixed lighting modes (baked indirect + realtime direct and shadows)
Related
Bistro E2: draw-loop hot path — cached render list and material sort #58 (global illumination epic), Project settings as DataAssets: implemented foundation #43 (shadows)
