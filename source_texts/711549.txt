Follow-up to the mesh substitutive-LOD PR, which ships cluster only. Mesh's method set is {cluster, auto} today; this adds qem and makes auto a real choice.
Why qem earns its place — and it is not "quality"
The tempting justification is that Garland–Heckbert edge collapse produces better-looking coarse meshes than vertex clustering. That argument was already tested and failed once in this area: a quadric placement was added to the clustering representative on exactly that reasoning, benchmarked on three shapes, and deleted because it improved nothing measurable (see the module docstring of packages/luxar/src/luxar/mesh/decimate.py — on a closed sphere the plain centroid was marginally better, on a crease the quadric system is rank-2 and falls back to the centroid anyway, and on a cube corner the two are bit-identical).
The real argument is topological, and it is measured:
Clustering does not preserve manifoldness, and cannot. When a grid cell swallows two sheets that were separate on the fine surface, their triangles land on the same representatives and the result has edges shared by more than two faces.
On a closed unit sphere (4098 vertices, boundary-free, χ=2) the coarse levels come back χ=2 with 0 boundary edges at most cell sizes, but at one cell size hit 120 boundary and 60 non-manifold edges. Edge collapse can veto a collapse that would break the link condition; clustering has no veto to exercise. That is a capability difference, not a polish difference.
Scope
decimate_qem(...) in luxar/mesh/decimate.py (or a sibling module if it outgrows the file): Garland–Heckbert quadrics with a lazy-invalidation min-heap. Not vectorizable — each collapse rewrites the 1-ring and invalidates ~12 neighbouring costs — so it is a Python heap loop.
Add "qem" to the mesh entry of the per-geometry substitutive method table.
Make auto a size-derived policy: qem at V <= 200_000, else cluster, with an aprint naming the choice and why. Precedent for a size-derived default: _MULTISCALE_CAP_TARGET in cli/lod.py.
luxar mesh lod --method qem.
Performance envelope, so the auto threshold is not invented
Measure before fixing 200k. The expectation from the plan: fine to ~200K vertices (~5 s), unacceptable at 10M (~5–10 min), and the writer's cap is 2**27. A 4-level K=4 ladder needs roughly 2× the single-level collapse count, so the ladder cost is not the single-level cost.
Tests that would make it worth having
The point is manifoldness, so test manifoldness — and test it the honest way. Do not use E = 3F/2 to compute the Euler characteristic: that identity assumes the closed manifold being tested, so using it to test manifoldness assumes the conclusion. Count unique undirected edges (test_decimate.py::edge_audit already does this). The sphere case above is the ready-made fixture: qem should hold χ=2 with 0 non-manifold edges at every level where cluster does not.
Every new test mutated to confirm it fails, per the repo rule.

No packages/luxar/src/luxar/mesh/decimate.py (the whole luxar/mesh/ package is __init__.py + interop/), and no test_decimate.py, so there is no edge_audit helper and no module docstring recording the quadric-placement experiment.
No decimate_cluster, and no per-geometry substitutive method table entry for mesh — grep -rn 'decimate' --include=*.py packages/ turns up only unrelated hits in gsplats/fitting/ and a demo.
No luxar mesh lod command; cli/mesh_commands.py registers import only.
Mesh substitutive LOD isn't merely unimplemented, it's actively refused — that's what Say why each mesh LOD flavour is refused, and refuse energy stamps #1327 landed (each mesh LOD flavour now explains why it's refused), and core/group/lod/group.py still treats a mesh leaf under a LOD group as a store nothing can load.
So the referenced "mesh substitutive-LOD PR, which ships cluster only" never landed and isn't open — nothing in gh pr list --state all matches, and none of the mesh-* branches carry a decimate.py.
The topological argument here is the good part and worth keeping verbatim: clustering has no veto for the link condition, so it cannot preserve manifoldness, and the sphere fixture (χ=2, 4098 vertices, the cell size that yields 120 boundary + 60 non-manifold edges) is exactly the falsifiable test to hold it to. Likewise the warning not to derive χ from E = 3F/2 — that assumes the manifoldness under test.
But as scoped this is an increment on a base that doesn't exist, so it can't be one PR. Marking it blocked until mesh decimation lands with cluster; at that point this becomes the straightforward follow-up it was written as. If the intent is instead to build mesh decimation from scratch here, that wants its own issue covering decimate_cluster, the method table, the writer path, and mesh lod — with qem as the second tier on top.

Picking this up now that #1351 has landed — mesh/decimate.py, decimate_cluster, the method table and luxar mesh lod are all on main, and test_decimate.py already has the octasphere fixture and the edge_audit helper this needs to extend.
Plan:
decimate_qem in a new sibling luxar/mesh/qem.py (decimate.py is already ~500 lines, and a heap loop with its own adjacency bookkeeping does not belong inside the vectorized module). Garland–Heckbert quadrics, lazy-invalidation min-heap, and the part that is the actual point: a link-condition veto, so a collapse that would leave an edge shared by more than two faces is refused instead of performed. Same signature and same output contract as decimate_cluster — nD-aware with barrier columns, per-cluster colour/scalar means, normals recomputed from the coarse surface — so both tiers are interchangeable at the call site.
"qem" into MESH_SUBSTITUTIVE_METHODS, and one decimate(..., method=...) dispatcher so the adder and the CLI resolve the method in exactly one place.
auto becomes size-derived with an aprint naming the choice and the reason. I will measure the envelope on real ladders before writing a threshold down — the issue asks for that explicitly and I would rather the number came from a timing than from the plan.
Tests on manifoldness, counted honestly with edge_audit (no E = 3F/2, which assumes the property under test): the sphere target where cluster returns boundary and non-manifold edges is the discriminator, and qem must hold χ=2 with zero of both at every level. Plus the auto policy and the CLI surface.
Docs to follow it: MESH_NODE_SPEC.md §9, mesh/README.md, CLI_REFERENCE.md, CHANGELOG.
