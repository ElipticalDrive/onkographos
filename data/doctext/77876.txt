The viamd side of scanberg/mdlib#15 (gto-iso-gpu-opt), the optimized GPU isosurface extraction. That PR has
the measurements.
Changes
iso_meshes: extraction goes through the library's non-blocking job API.
A job starts when a mesh's key changes and is polled each frame. It waits up to 3 ms, and only while
the job is younger than 12 ms, so a short job ends within its first frames and a long one never
stalls the render thread.
A superseded job is cancelled.
Electron densities are marked md_gto_iso_field_set_maxima_at_atoms, so the library floods them.
Async tasks window: shows an "Isosurface mesh N%" bar for each extraction running longer than
0.25 s.
Merging
Profiler: the temporary isosurface benchmark section is removed, along with its hooks in
iso_meshes.
master: merged into the branch without conflicts in the sources. ext/mdlib points at b5949ae, the
mdlib branch with mdlib master merged, so it includes everything viamd master's ext/mdlib had.
Order: merge md_gto_iso_gpu: optimized GPU isosurface extraction (non-blocking jobs, flood, one measured path) mdlib#15 first, with a merge commit so b5949ae lands on mdlib master. Then this
PR. If Issue with the Density Volume window #15 is squashed instead, ext/mdlib has to be moved to the squash commit.
CI: it builds on every platform. The test step fails with the same tests that fail on master
(6fd45b4), which this PR does not touch: viamd_color.optimize_colors_rare_pulled_apart on every
platform, and viamd_file_list.version_1_files_load_in_their_slots_order on both Windows builds.

Isosurface meshes: GPU extractions as jobs over frames; their progres…
…
92bc232
```
…s in the tasks window (mdlib r28)

- iso_meshes_update starts an md_gto_iso_gpu_job_t for new slots, and every update after that polls it
  for at most 3 ms. A job of a few milliseconds is done within the frame that began it or the next. A
  longer one (a large system, the high resolution, a slow GPU) goes on over frames, and the frame is
  never stalled.
- Until the job is done the previous mesh stays shown. Its host copy comes with the job (read_back), so
  the GL upload needs no blocking readback either.
- Slots changed while a job runs drop it for a new one (a dragged iso value never queues).
- A job that fails falls back to the CPU path, as a failed extraction did.
- Jobs under way for more than 0.25 s show a progress bar in the tasks window (iso_meshes_progress).
- The Profiler's extractions stay blocking: they are timed.
```
