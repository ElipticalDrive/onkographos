<a id="overview"></a>

## 🔎 Overview

IGS is a dialog-based Visual C++/MFC application that embeds a VTK render window inside a native Windows interface. It reads a text `.header` file, resolves the matching raw volume named by `OrgFile`, converts the samples into `vtkImageData`, and renders the result with `vtkOpenGLGPUVolumeRayCastMapper`.

The active application focuses on a compact workflow:

1. Select a volume header.
2. Parse the dimensions, voxel spacing, rescale parameters, and patient position.
3. Load and preprocess the corresponding 16-bit raw volume.
4. Display the volume in an interactive 3D scene.
5. Inspect picked 3D coordinates through the application window title.

[⬆ Back to top](#top)

<a id="key-features"></a>

## ✨ Key Features

- **Custom volume ingestion** — reads a `.header` file paired with a two-byte-per-voxel raw volume.
- **Header-driven preprocessing** — applies dimensions, voxel spacing, rescale parameters, byte swapping, and selected patient-position transforms.
- **GPU volume rendering** — uses VTK's OpenGL GPU volume ray-cast mapper with composite blending and configurable transfer functions.
- **Native embedded viewer** — hosts the VTK render window inside an MFC dialog control.
- **Interactive 3D navigation** — inherits VTK trackball-camera rotation, panning, and zoom behavior.
- **Spatial picking** — left-button interaction performs cell picking and reports the selected 3D coordinate in the window title.
- **Debug and Release support** — provides dedicated x64 configurations and runtime DLL paths.

<a id="getting-started"></a>

## 🚀 Getting Started

### 1. Install the build tools

Install Visual Studio 2019 with the following components:

- **Desktop development with C++** workload
- MSVC `v142` x64/x86 build tools
- Windows 10 SDK
- MFC for `v142` build tools

The solution currently defines x64 configurations only.

### 2. Prepare VTK 8.2.0

Place the complete VTK distribution used by the original project at:

```text
IGS-main/external/VTK8.2.0/
```

The dependency checks in `IGS.vcxproj` expect the following layout:

```text
external/VTK8.2.0/
├─ include/
│  └─ vtk-8.2/
│     ├─ vtk8.2.0.h
│     ├─ vtkSmartPointer.h
│     └─ ...
├─ lib/
│  ├─ debugX64/
│  │  ├─ vtkCommonCore-8.2.lib
│  │  └─ ...
│  └─ releaseX64/
│     ├─ vtkCommonCore-8.2.lib
│     └─ ...
└─ bin/
   ├─ debugX64/
   │  ├─ vtkCommonCore-8.2.dll
   │  └─ ...
   └─ releaseX64/
      ├─ vtkCommonCore-8.2.dll
      └─ ...
```

The project includes `vtk8.2.0.h` from that distribution to initialize and link the required VTK modules. A partial set of VTK headers or DLLs is not sufficient.

To keep VTK in another directory, override `VtkRoot` when building:

```powershell
msbuild .\IGS.sln /m /p:Configuration=Release /p:Platform=x64 /p:VtkRoot="D:\path\to\VTK8.2.0"
```

The custom location must follow the same `include`, `lib`, and `bin` layout.

### 3. Prepare a volume

Place a matching header/raw pair in `data/` or another local directory:

```text
data/
├─ head.512.header
└─ head.512
```

`OrgFile` inside the header must name the raw file in the same directory.

### 4. Build the application

#### Visual Studio

1. Open `IGS.sln`.
2. Select `Debug | x64` or `Release | x64`.
3. Confirm that `VtkRoot` points to the required VTK distribution.
4. Choose **Build → Build Solution**.

#### Developer PowerShell

```powershell
msbuild .\IGS.sln /m /p:Configuration=Release /p:Platform=x64
```

Build products are written to:

```text
build/Debug/IGS.exe
build/Release/IGS.exe
```

### 5. Run the executable

Visual Studio adds the appropriate VTK DLL directory to the debugger environment. To launch a Release build directly, prepend the runtime directory to `PATH`:

```powershell
$env:PATH = "$(Resolve-Path .\external\VTK8.2.0\bin\releaseX64);$env:PATH"
.\build\Release\IGS.exe
```

Use `bin\debugX64` for a Debug build.

## 🗂️ Volume Data Format

The loader expects a text header containing colon-separated key/value pairs. The following fields drive the active loading path:

```text
OrgFile           : volume.raw
SizeX             : <width>
SizeY             : <height>
SizeZ             : <depth>
PitchX            : <voxel-spacing-x>
PitchY            : <voxel-spacing-y>
PitchZ            : <voxel-spacing-z>
Thickness         : <slice-thickness>
PatientPosition   : <position-code>
RescaleIntercept  : <integer>
RescaleSlope      : <integer>
```

The corresponding raw payload is read as one signed 16-bit scalar per voxel. Its expected byte count is:

```text
SizeX × SizeY × SizeZ × 2 bytes
```

### Byte order

The current **Load Data** handler calls `LoadFile(..., true)`. The loader therefore swaps each pair of bytes before rescaling. Prepare the raw data accordingly; native little-endian input will not be interpreted correctly unless the call or the data is adjusted.

### Rescaling

Each loaded sample is transformed by the implementation as:

```text
output = (input + RescaleIntercept) × RescaleSlope
```

This is the formula implemented in `Visualization::Rescale`; it should not be assumed to match another medical-image format's convention.

### Patient-position conversion

The current code contains data transforms for these `PatientPosition` values:

- `HFS` — head first, supine
- `FFP` — feet first, prone
- `FFS` — feet first, supine

Other recognized position codes currently have placeholder branches and do not apply a transform.

<a id="usage-and-controls"></a>

## 🖱️ Usage and Controls

1. Start `IGS.exe`.
2. Select **Load Data**.
3. Choose a `.header` file.
4. The application resolves `OrgFile` relative to the header directory and loads the raw volume.
5. Use the inherited VTK trackball-camera mouse controls to rotate, pan, and zoom the scene.
6. Left-button interaction performs a cell pick; the selected `x, y, z` coordinate is displayed in the window title.

The initial renderer uses a blue background and a shaded color/opacity transfer function defined in `Visualization.cpp`.

<a id="implementation-notes"></a>

## 🧩 Implementation Notes

- `IGSDlg.cpp` owns the file dialog and passes the selected header to `Visualization`.
- `Visualization.cpp` parses the header, reads the raw volume into `vtkImageData`, performs preprocessing, and configures the VTK rendering pipeline.
- `vtkOpenGLGPUVolumeRayCastMapper` uses composite blending, automatic sample-distance adjustment, and the configured scalar/color transfer functions.
- The render window is attached to the `IDC_STC_SHOW` MFC control at runtime.
- `CInteractorStyle3D` extends `vtkInteractorStyleTrackballCamera` and adds cell picking before delegating to the default left-button behavior.
- `MoriFileReader.h` and `Vr.cpp` are retained as supplementary sources but are listed as `None` in the Visual Studio project and are not compiled into the active executable.

<a id="current-limitations"></a>

## ⚠️ Current Limitations

- The required VTK SDK and sample medical data are not distributed with this repository.
- The project targets Windows x64 with the Visual Studio 2019 `v142` toolset; no Win32 configuration is provided.
- The active loader supports the repository's custom header/raw format, not direct DICOM-series import.
- Patient-position conversion is implemented only for selected position codes.
- File-loading exceptions are currently caught without a user-facing error message.
- No automated test suite is included.

		int cxIcon = GetSystemMetrics(SM_CXICON);

void CVr::InitMaskColor()
{
	//��ȡӦ�ó���·��
	char path[MAX_PATH];
	GetModuleFileNameA(NULL, path, MAX_PATH);
	///< ��ȡ·��
	PathRemoveFileSpecA(path);
	StrCatA(path, "\\MaskColor.ini");
	CStringA str;
	int col;

	CStringA s;
	for (int i = 0; i < 7; i++)
	{
		s.Format("Color%d", i + 1);
		GetPrivateProfileStringA("Mask_Color", s.GetBuffer(), "255", str.GetBuffer(), MAX_PATH, path);
		col = atoi(str.GetBuffer(0));
		m_MaskColor[i] = vtkSmartPointer<vtkColorTransferFunction>::New();
		double r = ((double)GetRValue(col)) / 255.;
		double g = ((double)GetGValue(col)) / 255.;
		double b = ((double)GetBValue(col)) / 255.;
		m_MaskColor[i]->AddRGBSegment(0, r, g, b, 2550, r, g, b);
		m_VolumeProperty->SetColor(i + 1, m_MaskColor[i]);
	}
}
