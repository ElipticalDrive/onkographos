Horizon, closing the gap between
cinematic visualization and medical imaging
Javier Guajea1 , Serge Koudoroa , Eleftherios Garyfallidisa
a Department of Intelligent Systems Engineering, Luddy School of Informatics, Computing and Engineering,
Indiana University, Bloomington, USA.
Abstract
Medical imaging has become a fascinating field with detailed visualizations of the body’s internal
environments. Although the field has grown fast and is sensitive to new technologies, it does not use
the latest rendering techniques available in other domains, such as day-to-day movie production or
game development. In this work, we bring forward Horizon, a new engine that provides cinematic
rendering capabilities in real-time for quality controlling medical data. In addition, Horizon is
provided as free, open-source software to be used as a foundation stone for building the next
generation of medical imaging applications. In this introductory paper, we focus on the extensive
development of advanced shaders, which can be used to highlight untapped features of the data and
allow fast interaction with machine learning algorithms. In addition, Horizon provides physicallybased rendering capabilities, the epitome of advanced visualization, adapted for the needs of medical
imaging analysis practices.
Keywords: Medical imaging, medical visualization, shader programming, physically-based
rendering.

2. Methods
84
2.1. Cinematic scientific visualization
85
Horizon includes a rendering engine that supports Physically Based Rendering (PBR) (Shirley,
86
1991) capabilities. PBR engines aim to simulate light properties when interacting with objects in
87
the scene in a physically plausible way. In order to achieve this, light is studied and simulated from
88
a conductive point of view (Hoffman, 2013). In other words, light interacts differently with distinct
89
objects’ materials. In PBR, materials are divided into two categories based on their conductive
90
properties: dielectrics and metals (Shirley, 1991). Metallic is the first parameter of Horizon’s PBR
91
engine. It takes values between 0 and 1, where the former represents dielectric materials and the
92
latter metallic materials. Although, in principle, this parameter should be binary for only deciding
93
the conductive properties of the surface, having intermediate values between 0 and 1 provides the
94
flexibility for simulating more complex processes such as dust on metallic surfaces.
95
In order to be considered physically based, a rendering engine also must satisfy the following
96
conditions: 1) It should be based on a microfacet surface model, 2) It should be energy conserving,
97
and 3) It should use a physically based Bidirectional Distribution Function (BDF) (Hoffman, 2013).

2.2. Accessing advanced machine learning data structures
207
Many medical imaging methods generate big data sets that need to be displayed. One of these
208
techniques is fiber tracking algorithms which generate millions of streamlines (Rheault et al., 2015;
209
Smith et al., 2015). For real-time applications, finding new ways to handle and simplify these
210
large data sets are now a necessity. For that reason, Horizon provides easy ways to visualize such
211
datasets’ matrices and time series. More importantly, it provides a mechanism to access hierarchical
212
data structures straightforwardly and interactively. For example, Horizon can swiftly access the
213
dynamically generated tree of clusters built by QuickBundlesX (QBX). QBX is an advanced, unsu-
214
pervised machine learning algorithm that substantially improves over its predecessor QuickBundles
215
(QB) (Garyfallidis et al., 2012). QuickBundles is one of the most efficient algorithms for clustering
216
streamlines using streamline distances (Reichenbach et al., 2015), with a complexity of O(kN ). k is
217
the number of clusters, and N is the number of streamlines. Because k is usually much smaller than
218
N , the algorithm’s complexity is near O(N ) with large distance thresholds (e.g., 30mm). However,
219
when small thresholds (e.g., 10mm) are used, the number of clusters increases considerably, and the
220
complexity escalates accordingly. Additionally, it is essential to highlight that when N increases, so
221
do k, i.e., the more streamlines in the dataset, the more clusters will be created. QBX is an online
222
method that allows the clustering of large amounts of streamlines sequentially and in multiple res-
223
olutions by only passing one time through the whole streamlines. QBX does this by building a tree
224
of centroid nodes on the fly, each layer representing a different distance threshold. As in QB, the
225
distance metric used to compare the streamlines with the centroids of the clusters is the minimum
226
average direct and flip distance (MDF) (Garyfallidis et al., 2012).
227
In detail, for a set of streamlines and a set of distances (e.g., 30mm, 25mm, 20mm), the algorithm
228
will create a tree with as many levels as the number of input distances in descending order (Fig. 4).
229
Then, each streamline will traverse the tree from the root to the leaves in the following way: At
230
each level, the MDFs between the streamline and that level’s centroids are calculated and evaluated
231
sequentially. During this process, the streamline is assigned to that cluster if the MDF is lower
232
or equal to that level’s distance threshold. Otherwise, if the streamline is not within the radii
233
of one of the existing centroids, then that streamline becomes a centroid at that tree level. This

3.2. Enhanced line and streamtube shading
288
Most existing tools for visualizing fibers render them as unshaded lines or polygonal tubes.
289
Unfortunately, the use of unshaded lines gives no cues about the shape of the fibers, as shown
290
in Fig. 7. On the other hand, polygonal tubes require many polygons to achieve high image
291
quality. Unfortunately, this might compromise rendering performance. Additionally, neither of
292
these methods communicates the coherent structure of a collective of fibers.
293
Visualization of fibers can be compared to human hair rendering since both aim to display
294
many polyline-like objects with particular shapes and coherencies. These shapes and coherencies
295
are essential for the user because they contain vital information about the dataset’s structure. In
296
human hair rendering, they represent the hairstyle that the viewer then interprets. In medical

4. Discussion
330
Horizon is an advanced rendering engine and software for medical imaging visualization. It
331
provides high efficiency by exploiting parallel programming in the GPU and offers high flexibility
332
via its API interface in Python. The main focus of this paper is on physically-based rendering
333
capabilities, which are offered in Horizon using shaders both for reflection and refraction. The
334
proposed rendering engine shares some of the fundamentals of the famous Disney BRDF explorer
335
from which it is inspired. Its parameters are easy to interpret and use without compromising
336
realistic results but still give users the flexibility to create surreal visualizations. Additionally,
337
the light simulations were validated using the Material Exchange and Research Library (MERL)
338
database (Matusik, 2003), which provides a degree of certainty in the case our users would want to
339
create highly accurate photorealistic visualizations.
340
In this introductory paper, we use the new rendering engine to explore how it can help scientists
341
to get more insights from their data. The included parameters allow for novel representations of
342
the data. For example: a) we demonstrated how sheen reflections could be used as an alternative
343
to traditional opacity and similar occlusion techniques. This idea could be relevant for scientists
344
working with cortical surfaces in conjunction with connectivity networks or tractography-based
345
approaches. b) We demonstrated how anisotropic illumination, a technique borrowed from hair
346
rendering, can improve the appearance of elongated objects, such as streamlines and streamtubes.
17
medRxiv preprint doi: https://doi.org/10.1101/2023.07.11.23292519; this version posted July 13, 2023. The copyright holder for this preprint
(which was not certified by peer review) is the author/funder, who has granted medRxiv a license to display the preprint in perpetuity.
It is made available under a CC-BY-NC-ND 4.0 International license .
347
c) We used a novel refractive shader to explore color blending intensities of heatmaps with glass-
348
like rendering techniques. This shader sets the basis to explore different Bidirectional Distribution
349
Functions (BDF) and effects like Screen Space Refractions. Finally, d) we showed how combining
350
machine learning (ML) algorithms and data structures with shaders can accelerate the visualization
351
of complex elements such as tractograms. These kinds of strategies are common in production
352
rendering in which the size of the assets and associated information is considerably large, so efficient
353
ways to handle and visualize the data constitute the main challenge. In summary, Horizon adds
354
multiple new dimensions for investigating the data. Every parameter (or their combinations) of the
355
BRDF can be used to create a new story about the geometry and the features of medical datasets.
356
Advanced shading effects have been explored, and some efforts have found great value in ambient
357
occlusion and shadowing (hard and soft) techniques. Therefore, adding such extensions to our
358
rendering engine would be appropriate as the first next step. Additionally, a natural extension of
359
this work would be transitioning from a BRDF to a bidirectional scattering distribution function
360
(BSDF) with subsurface scattering capabilities. Lastly, when combined with ray tracing-based
361
rendering approaches, the included lighting methods can significantly improve the overall perception
362
of the generated images. One of the many benefits we consider relevant for scientific visualization
363
is indirect or global illumination techniques. However, Horizon is currently only supporting ray-
364
marching. We left ray tracing and global illumination as future work because these methods are
365
now too slow for real-time application in consumer hardware (general-purpose desktops and laptops
366
that most scientists use).
367
A noticeable impact of this work is that Horizon brings some of the latest rendering technology
368
to the medical imaging domain and offers it in a way that adheres to open standards. Therefore,
369
Horizon creates a much-needed environment where multiple domains can meet, build and extend.
370
The provided API is fully customizable and can be modified to include other (non-PBR) lighting
371
techniques. Developers can change or edit any internal parts of the code and create new products
372
without licensing restrictions.

5. Conclusion
386
We presented Horizon, a new software engine to democratize advanced visualization for medical
387
imaging. Horizon brings state-of-the-art shading techniques commonly seen in the gaming and
388
animation industries. It presents them in an easy-to-use and understandable way so medical imagers
389
can focus on visualizing their data rather than studying complex light transport concepts. In
390
this way, Horizon enables and accelerates discovery by facilitating access to technologies usually
391
out of reach for most medical imagers. Horizon comes with innovations, such as using sheen for
392
transparency, photorealistic glass animations, illuminated tractography with anisotropic shaders,
393
and provides shader access to advanced ML algorithms and data structures in real-time. For
394
the latter, an example for accessing hierarchical clusters of tractograms was provided. Horizon is
395
publicly available with DIPY.
