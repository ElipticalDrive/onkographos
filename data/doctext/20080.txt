100 Million-voxel volumetric display

Michael G. Giovinco, Michael J. Richmond, Won S. Chun
Actuality Systems, Inc.
ABSTRACT
A 360-degree-viewable volumetric 3-D display has been developed by Actuality Systems, Inc. It has a resolution of 768
x 768 x 198, has a 24 Hz volume refresh rate, contains an embedded graphics processing system, and uses dithering
methods to create images of 3-bit to 21-bit-stippled color, which is perceived as several hundred colors. The 3-D display
system is a visualization platform, comprised of a combination of hardware and software designed for ease-ofintegration into existing visualization systems. The system design1 is briefly recounted. Key enhancements are
described, such as the development of a complete volumetric visualization platform. Examples are given which guide
the system engineer who needs to include a volumetric display into a visualization solution.
Keywords: 3-D display, volumetric, autostereoscopic, spatial light modulator, military visualization
1. INTRODUCTION
The man-machine interface – particularly the display – is vital to many successful missions. In the context of this paper,
that mission is military. However, visualization contributes to success in many other applications, such as: drug
discovery, medical imaging, mathematical and financial analysis, product design, petroleum exploration, air-traffic
control, and airport security.
Mission-critical 3-D information can be considered either "structural" (i.e. visual, pertaining to 3-D structures) or
"numeric" (i.e. highly-multi-dimensional data.) It is assumed that the reader recognizes that today's mission-critical
visual information is complex. As evidence, one frequently "widens the pipe" between user and data with the help of
high-resolution 2-D displays, graphical workstations, and visualization applications. However, two facts bear
mentioning:
1.
True three-dimensional representations can enable faster visualization, simulation, and collaboration; and
2.
There is a class of information which cannot be visualized adequately in existing 2-D display technologies.
Examples include multispectral LIDAR / LADAR data, the 3-D structure of molecular docking simulations,
and the very (300+) multidimensional data that is analyzed in combinatorial chemistry, or, regarding national
security, patterns observed during cyberterrorist computer break-in attempts.
While traditional computer graphics techniques use a modern equivalent of trompe l'oeil (use of monocular depth cues),
3-D display technologies exploit the human visual system's inherently three-dimensional data-processing architecture.
The visual system's ability to process binocular information is well-documented.2 One type of display technology that
creates true three-dimensional imagery are volumetric displays.
1.1 Introduction to volumetric displays
Volumetric displays are the set of three-dimensional display technologies that produce volume-filling imagery. (This
term is not to be confused with "volume rendering," a computer-graphics technique of a similar name that is commonly
used in medical imaging and petroleum visualization.) Barry Blundell and Adam Schwarz offer the following definition:
"[a] volumetric display device permits the generation, absorption, or scattering of visible radiation from a set of localized
and specified regions within a physical volume."3 The definition might need to be extended to include: (1) holographic

video systems4, which use piecewise approximation to synthesize the wavefronts that emanate from a 3-D scene, and (2)
the set of re-imaging systems that use volume-filling imagery as the source5.
Simply put, volumetric displays create imagery that appears to float in a volume. Typically the imagery can be seen
from a wide variety of angles. Furthermore, goggles are generally not required to perceive the 3-D imagery.
Several publications provide surveys of existing volumetric display architectures. The authors point out the work of M.
Halle6, K. Langhans et al7, and Blundell and Schwarz3 as particularly instructive. The majority of volumetric displays
exploit persistence of vision by projecting 0-, 1-, or 2-D components of a scene rapidly enough that the retina fuses them
into a 3-D perception.
1.2 Related prior research
The authors chose a three-dimensional display method that provides high-resolution imagery in a mechanically-simple
manner at reasonable cost. The solution was inspired by a system reported in 1960 by ITT Laboratories8. The group
used a CRT to create simple 2-D images which were imaged onto a rotating screen. A similar design9 is taught by Max
Hirsch in a patent application filed in 1958 – a fast CRT is imaged onto a rotating screen with a slightly different
arrangement of relay mirrors. One clever aspect of these designs is the placement of several relay mirrors which rotate
in unison with the screen, thereby keeping the optical path length (and therefore the focus) the same regardless of the
screen's angle. See Fig. 1.
Fig. 1: Two early 3-D displays which maintain focus regardless of screen angle. An illustration of ITT's approach ca. 1960 (left), and
an illustration from a patent filed in 1958 (right.)
More recently, Batchko teaches a system10 using scanning a laser beam relayed by a similar architecture. Tsao et al
report a volumetric display11,12 that interposes image-derotation optics between the image generator and projection
screen, since the image of the screen would otherwise rotate in the plane of the projection screen as the screen rotates.
In the authors' case, the CRT is replaced with a high-frame-rate MEMS-based projector; a specialized off-axis projection
system is employed; and data is generated by a suite of graphics-processing hardware and software. Software, instead of
de-rotation optics, stabilizes the projector image in the plane of the rotating screen. The system is described in section 2.
1.3 Cockpit applications of volumetric 3-D displays
The military applications of 3-D displays have been reported elsewhere.13 In brief, tasks which require improved 3-D
visualization include: fighter combat training, situational awareness, telepresence, battlefield visualization, undersea
navigation, and medical visualization.
1.4 System engineer's guide: performance metrics of volumetric 3-D displays
Here we propose metrics to guide a system engineer who must choose a volumetric display for a particular application.
There are relatively few examples by which to gauge norms, nomenclature, and requirements.
For example, the term resolution deserves attention. CRTs and bitmapped-volumetric displays, such as the one
described here, treat the idea of resolution in a similar way. That is, the total number of addressable pixels (voxels)
equals the maximum number of utilizable pixels (voxels) in a given frame (volume). However, vector-scanned 3-D
displays13 have not yet been able to utilize 100% of the addressable voxels for a given volume. Because of modulation
and scanning constraints, the ratio has more typically been 1% or less.

1.4.1 Image type and quality
The first descriptor above pertains to the 3-D display methodology. As discussed in sections 1.1 and 1.2, there are
several ways to create volumetric imagery. Some researchers have created vector-scanned (swept 0-D) 3-D mages
within various vapors14 or glasses15, and often refer to these architectures as solid-state displays. Other volumetric
displays, called multiplanar displays, utilize a rotating or translating projection surface which receives a series of 2-D
cross-sections, or "slices," of a 3-D image. The series of slices constitutes a full 3-D image, just as a sequence of CT
scans are mentally stacked-up to constitute a patient's (3-D) anatomy. Multiplanar displays present an aggregate of
surfaces over time which the eye integrates into a volume-filling image.
There are several types of multiplanar displays. Swept-screen multiplanar displays use a spinning projection screen,
typically a plane16,17 (as in this example) or a helix. Reciprocating-screen multiplanar displays have a projection surface
that translates back-and-forth. Note that the screen need not be physical. It can be an electronically-switched opticallydiffuse surface5 or a macroscopic "surface" comprised of rare-earth dopants in a metastable state18.
Image size has ranged from less than one inch across to approximately 3 feet across. Some researchers prefer to describe
the image's spatial extent in terms of its volume. For example, the display described here has a volume of approximately
113 cubic inches (2 917 cm3).
The resolution of a volumetric display is typically governed by the resolution and frame rate of its projection engine. A
multiplanar volumetric display might use one engine (such as a 3-chip TI DMD™ system) with a resolution of 1024 x
768. Such an engine might have a frame rate of 5 kHz to 10 kHz (on the high-end at the time of writing).
The volumetric display manufacturer, in a simplified sense, is bound to the following relationship: (volume refresh rate)
x (slices per image) = (projector frame rate). In our case, the projector's internal single-bit frame rate of 5 kHz is used to
create a 198-slice image at 24 Hz. Development in this field has been hampered by limited access to fast, high-contrast
projectors, which are properly called spatial light modulators (SLMs). Advances in MEMS and FELCD (ferroelectric
LCD) technologies are providing opportunities to design higher-performance volumetric displays.
Note that the definition of "slice" bears discussion. If the projection screen is swept around its center, it sweeps an entire
volume in just 180º of rotation. Therefore the volume refresh rate (in Hz) is twice the screen's rotation rate (in rps).
Here, a slice is defined a 2-D cross-sectional surface of the 3-D dataset; for our 198-slice display, there are
approximately 1.1 slices per degree. Also note that the 198 slices that comprise 0º-180º ("front-scan") are different than
the 198 slices from 180º-360º ("back-scan"), even though care is taken to make them as visually similar as possible.
Unless the volume is swept many times faster than the desired volume refresh rate, a broad range of colors cannot be
created using typical (e.g. pulse-width modulation) schemes, because they would result in image artifacts such as dotted
lines. Rather, the authors use 3-D methods of spatial dithering to provide a larger color gamut. Other methods, such as
ganged projectors or the use of color wheels in conjunction with faster volume sweep rates, are also possible.
Methods and standards for measuring image brightness and contrast have not been defined by the volumetric display
community at this time.
1.4.2 Performance and interface: computation, memory, and connectors
The authors' volumetric display requires a high-bandwidth (GB/sec) path into its projection assembly. Therefore,
significant memory and computation are embedded in the 3-D display unit. A lower-bandwidth connection (e.g. SCSI)
to the host computer carries a simpler mathematical description of the 3-D scene, such as OpenGL-style polygonal data
streams.
The volume refresh rate does not necessarily match the video hardware's ability to fill graphics RAM with new imagery.
Just as a CRT may refresh at 72 Hz, a complex graphical scene may render at 10 fps. The same is true for volumetric
displays; the stack of 2-D slices may be updated faster or slower than the device is capable of projecting them. To
ensure smooth animation, the volumetric display described here has a double-buffered graphics memory system.
Regarding the memory specifications, 3 Gbits is enough to store 2 x 198 slices of 768 x 768 resolution at 3-bit color.
2. SYSTEM DESCRIPTION
The design of the 100-million voxel volumetric display presented here has been described in detail elsewhere1,19 ; this is
a system-level summary and report of results achieved.
The authors have developed a visualization platform that is a combination of hardware and software (Fig. 2):
•
Hardware: 768 x 768 x 198 volumetric 3-D display.
•
Software: Development of a 3-D "operating system" or, more properly, visualization platform. At the time of
writing, the platform is based on an open standard (OpenGL) and is therefore compatible with a range of legacy
applications.
Fig. 2: High-level system architecture. The hardware layer includes a host PC and volumetric display (with an embedded processing
system.) The software layer, distributed among the hardware, includes everything from the application to proprietary rendering
algorithms.
The theory of operation is that human persistence of vision is capable of integrating a series of 2-D slices – arranged like
slices of an apple around its core – into a volume-filling 3-D image. As illustrated in Fig. 3, a high-speed 2-D projection
engine images a time series of approximately 5,000 frames per second onto a diffuse projection screen which rotates at
730 rpm. A group of three mirrors relay the imagery to the rotating screen in a manner that ensures accurate focus
regardless of the screen's angle. That is, a sequence of 2-D images is projected onto a rotating screen by a stationary
projector via several relay mirrors.
Fig. 3: Schematic illustration of the volumetric 3-D display and a photograph of the display in operation. A fast projection engine
illuminates a rotating projection surface via several relay mirrors which rotate with the screen. The projector and control electronics
are fixed. The imagery is of a DNA helix and nearby protein from a popular molecular visualization package.
Each 2-D slice is a cross-section of a 3-D dataset, as explained earlier. As has been reported extensively in the past 40
years, if the sequence of slices is projected rapidly, a 3-D image will be perceived to hover in the addressable region
swept by the projection screen. Unlike panoramagrams (frequently called "autostereoscopic displays"), the image can be
seen at any of a continuum of locations around the display without the restriction of discrete viewzones and the dark
patterns they create. The reason is that the projector illuminates the screen with cross-sections of a dataset, not
snapshots normal to the screen. However, because the screen is essentially a Lambertian diffuser, each voxel appears to
emit omnidirectionally. Therefore, images are perceived to be translucent, and hidden-surface removal is not possible
without knowledge of the viewer's position. Obviously, no headwear is required to view the 3-D imagery, and all focus
(accommodation) and parallax cues are correct.
The system software allows the display to be integrated easily into existing applications and workflows. In particular,
the software platform incorporates Mesa, the open-source graphics library similar to OpenGL. Simply put, this implies
that (1) developers have a familiar programming interface, and (2) the display functions in real-time. For example, the
user can rotate a DNA molecule at-will, or pilot a helicopter over synthetic animated terrain with a standard joystick.
2.1 Optical / mechanical assembly
The volumetric display's projector is based on the Texas Instruments™ Digital Mirror Device™ technology, which
utilizes a MEMS-based reflective array to create single-bit-depth frames at approximately 5 kHz. The system uses a 3SLM projection engine, which uses a color-mixing prism to combine R, G, and B image components with 1-bit depth
each. Please refer to Fig. 4, which illustrates a simplified optical system.
A standard high-pressure mercury arc lamp illuminates a 3-SLM projector via an integrator rod and condensor lenses.
The image of the SLMs is projected onto a custom projection screen that (1) approximates a Lambertian diffuser, and (2)
has approximately 50/50 reflectance and transmission properties. The image is projected through the center of an openframe DC motor that rotates the final fold mirrors and the screen. Unfolding the optical path reveals that the SLMs
throw an image at a 45º angle onto the screen. Therefore, additional optics (proprietary; not shown) are required for
good focus across the screen. Real-time algorithms are used to counteract the effects of (1) keystoning, and (2) rotation
of the SLM image in the plane of the projection screen.
Fig. 4: Simplified (schematic) layout of optical assembly. Some components not shown.
2.2 System electronics
The system electronics are shown in Fig. 5. The host PC (not shown, on left) sends 3-D data to the raster engine, a
custom graphics-processing embedded computer. The raster engine, in conjunction with the host PC, scan-converts
typical 3-D data into the device coordinate system. The processor, a TMS320C6201™ is a COTS DSP (commercial offthe-shelf digital signal processor) manufactured by Texas Instruments. Note that the 3-D display described here uses a
type of cylindrical coordinate system, and therefore traditional scan-conversion algorithms20 do not apply. The authors
developed a group of proprietary efficient rasterization algorithms which convert lines and triangles into a cylindrical
voxel grid.
As the geometric or volume data is been rasterized, it is stored in graphics memory, which is 3 Gbits of DDR SDRAM
(double data rate synchronous dynamic RAM). The system described here is able to support higher resolution imagery
than is generated by the current projector system. Therefore the graphics memory can be populated with 6 Gbits of
RAM. Memory is partitioned into two volume buffers, each of which stores 198 slices of 768 x 768 imagery. A motor
controller pages through memory in tight synchronization with the position of the rotating screen. The graphics memory
is read out to the projector subsystem at (24 volumes/second) x (1024 x 768 pixels/slice) x (3 bits/pixel) x (198
slices/volume) = 1.4 GBytes / sec. Full 1024 x 768 frames are loaded into the SLM even though only the central 768 x
768 is used.

2.3 System software: 3-d operating system
The 3-D display system's software platform was designed to achieve the goals of: easy integration into legacy
applications (such as molecular viewers or battlefield visualization systems), use of open standards, simplicity of
development, and exploitation of the medium of volumetric 3-D using an intuitive GUI.
Fig. 6 is an overview of the software architecture. Segments which have been developed and are functional are outlined.
2.3.1 Application layer
Applications are either "native" (written with this platform in mind) or "legacy." The authors' volumetric visualization
platform currently operates with both. Examples of compatible legacy applications include the molecular visualization
package WebLab ViewerPro, a product of Accelrys Corporation, as shown in Fig. 3.
Fig. 6: Actuality's 3-D visualization platform.
2.3.2 User interface / Toolkit / API
Typically, one or more applications will send one or more regions of 3-D graphics to the physical 3-D display.
Therefore, a "3-D space manager" will be developed as part of a comprehensive 3-D user interface (UI). The UI will
provide functionality similar to the Xerox PARC / Apple / Microsoft windows metaphor, including drag/drop, 3-D
pointers, and icons.
Applications call upon an extensible toolkit to (1) draw in the 3-D display, or (2) enable back-compatibility with existing
standards. For instance, the platform has an OpenGL interface, which is based on Mesa, an open-source graphics
library.
The UI and Toolkit can call functions in the Application Programming Interface (API) to draw primitives in 3-D, such as
points, lines, surfaces, and text. The API is under development.
For example, the 3-D display is able to project 3-D mechanical CAD images directly from commercially-available
OpenGL-based software such as SolidWorks. The imagery is animated and interactive because the 3-D graphics
"OpenGL pipeline" is read directly into the 3-D display. Moving a part on the CRT results in the same movement in the
3-D display. Please see Please see Fig. 7.

4. CONCLUSION
The multi-mega-voxel 3-D display proposed earlier1 is now functional. The 3-D hardware utilizes a 5 kHz MEMSbased projector to illuminate a rotating projection screen with approximately 200 slices of 768 x 768-pixel 2-D images to
create a volume-filling 3-D scene. An evolving software platform supports many OpenGL-based applications in realtime. Results from commercial and custom applications are shown.
