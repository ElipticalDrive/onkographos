Purpose and Scope
This page documents the shading extension of the sphere tracing system implemented in Assets/044_SphereTracingShading/SphereTracingShading.shader. It covers how surface normals are derived from the SDF using finite differences, how diffuse lighting is calculated in object and world space, and how the material() function combines a base color with computed light.
The ray marching loop structure, vertex shader setup, scene() SDF function, and core tracing constants (MAX_STEPS, THICKNESS) are carried over unchanged from the previous tutorial. For a description of those fundamentals, see Sphere Tracing Basics. For information on writing correct depth buffer values from a sphere-traced surface, see Sphere Tracing with Depth Buffer Output.

The scene() SDF Function
Assets/044_SphereTracingShading/SphereTracingShading.shader59-61
scene() is unchanged from the basics tutorial. It returns the signed distance from a point pos to a unit sphere of radius 0.5 centered at the object origin:
```
scene(pos) = length(pos) - 0.5
```
The same function is sampled six times by normal() to estimate the surface gradient.
Normal Calculation: Finite Differences
Because the SDF is an analytic distance field, the surface normal at any point is the normalized gradient of the SDF. This shader approximates that gradient using the central difference method.
Finite-difference normal estimation
```
transform to world spacepos (surface point)scene(pos ± NORMAL_EPSILON, 0, 0)scene(pos ± 0, NORMAL_EPSILON, 0)scene(pos ± 0, 0, NORMAL_EPSILON)float3(changeX, changeY, changeZ)normalize( mul(unity_ObjectToWorld, float4(...,0)) )
```
The normal() function Assets/044_SphereTracingShading/SphereTracingShading.shader63-73 computes:
changeX = scene(pos + (ε,0,0)) - scene(pos - (ε,0,0))
changeY = scene(pos + (0,ε,0)) - scene(pos - (0,ε,0))
changeZ = scene(pos + (0,0,ε)) - scene(pos - (0,0,ε))
The resulting float3 is in local object space. It is then transformed to world space using unity_ObjectToWorld and normalize()d before being returned. This world-space normal is required because the subsequent lighting calculation uses a world-space light direction.
Note: The w component of the mul() call is 0 (a direction vector, not a position), so the translation column of the matrix is not applied.
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader63-73
Lighting Calculation: lightColor()
Assets/044_SphereTracingShading/SphereTracingShading.shader75-83
lightColor() implements a Lambertian (N·L) diffuse model using Unity's built-in light variables:
VariableSourceMeaning
_WorldSpaceLightPos0.xyzUnityCG.cgincDirectional light direction in world space
_LightColor0Lighting.cgincColor and intensity of the main directional light
The function:
Calls normal(position) to get the world-space surface normal.
Reads _WorldSpaceLightPos0.xyz as the light direction (valid for directional lights).
Computes saturate(dot(surfaceNormal, lightDirection)) — the clamped cosine of the angle between normal and light, giving the diffuse intensity.
Returns the product of that intensity and _LightColor0.
Lighting.cginc is explicitly included at Assets/044_SphereTracingShading/SphereTracingShading.shader16 to make _LightColor0 available in the fragment stage.
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader14-17 Assets/044_SphereTracingShading/SphereTracingShading.shader75-83
Material Composition: material()
Assets/044_SphereTracingShading/SphereTracingShading.shader85-93
material() is the final color composition step. It multiplies the object's base color property _Color by the result of lightColor():
```
output = _Color * lightColor(position)
```
This is a simple diffuse-only model. The _Color property is a fixed4 exposed in the Inspector Assets/044_SphereTracingShading/SphereTracingShading.shader4 and two demo materials (ShadedTracedObject.mat, ShadedTracedObject 1.mat) are included in the tutorial folder with different hue values.
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader85-93 Assets/044_SphereTracingShading/ShadedTracedObject.mat76 Assets/044_SphereTracingShading/ShadedTracedObject 1.mat76
Fragment Shader: Integration
The frag() function Assets/044_SphereTracingShading/SphereTracingShading.shader95-117 is nearly identical to the one in the basics shader. The only behavioral change is on a confirmed hit:
```
// basics:  return _Color;
// shading: return material(samplePoint);
```
The tracing loop structure — advancing progress by scene(samplePoint) each step, discarding on miss — is identical between the two shaders.
Data flow through the fragment shader
```
yesnoMAX_STEPS exceededv2f input(localPosition, viewDirection)pos = localPositiondir = normalize(viewDirection)progress = 0for iter in 0..MAX_STEPSsamplePoint = pos + dir * progressdistance = scene(samplePoint)distance < THICKNESS?progress += distancereturn material(samplePoint)discard
```

Render Queue and ZWrite Configuration
The shading shader uses Queue="Transparent" and ZWrite Off Assets/044_SphereTracingShading/SphereTracingShading.shader9-12 whereas the basics shader uses Queue="Geometry" with default ZWrite.
This is because sphere-traced geometry does not write the correct hardware depth, so placing it in the transparent queue (rendered after opaque) and disabling ZWrite prevents it from incorrectly occluding or being occluded by rasterized geometry based on the proxy mesh depth. Writing correct depth values is the subject of Sphere Tracing with Depth Buffer Output.
The DisableBatching="True" tag is also required on both shaders because the vertex shader constructs the ray by reading unity_WorldToObject, which is only valid per-object and breaks under static/dynamic batching.
Sources: Assets/044_SphereTracingShading/SphereTracingShading.shader8-12 Assets/043_SphereTracingBasics/SphereTracingBasics.shader8-9
