Summary
This PR introduces bone-animated voxel character support by adding skeletal mesh voxelization and a dual-mode rendering system that switches between static and bone-driven voxel chunks based on asset data.
Key Changes
New Voxelization System
FHktVoxelMeshVoxelizer (new class): Converts SkeletalMesh to voxel data at editor time
Extracts triangles from LOD0 reference pose with bone weights
Conservative rasterization using SAT-based triangle-AABB intersection
Solid fill via Z-slice scanline parity algorithm
BFS-based bone weight propagation to interior voxels
Outputs sparse voxels (static mode) and bone groups (animated mode)
Asset Storage
UHktVoxelSkinLayerAsset (new class): Stores baked voxel data
SparseVoxels: Full voxel array for static rendering
BoneGroups: Per-bone voxel clusters with reference pose positions
Custom serialization for efficient storage
Metadata: source mesh/skeleton references for editor validation
Dual-Mode Rendering in AHktVoxelUnitActor
Static Mode (existing): Single BodyChunk component, procedural fallback
Bone-Animated Mode (new): Multiple per-bone chunk components attached to hidden skeleton
HiddenSkeleton: Invisible SkeletalMeshComponent driving bone transforms
BoneChunks: Map of bone name → chunk component
Automatic mode switching based on asset bone data presence
Per-bone palette and mesh scheduling support
Animation Integration
UHktAnimInstance synchronization in ApplyPresentation():
Movement speed, stance, attack rate, CP ratio forwarding
Gameplay tag and animation trigger propagation
Enabled only in bone-animated mode
Assembler Updates
FHktVoxelSkinAssembler:
AssembleBoned(): Generates per-bone chunks from BoneGroups
HasAnyBoneData(): Detects if any layer has bone data
Asset-first approach with procedural fallback for missing assets
Implementation Details
Grid Size: 32³ uniform voxel grid fitted to mesh AABB with 1-voxel margin
Bone Assignment: Dominant bone (highest accumulated weight) per voxel
Chunk Coordination: Bone chunks use unique coordinates (BoneIndex+1, 0, 0) in shared render cache
Offset Calculation: Voxel origin adjusted by reference pose bone position for correct placement
Mesh Scheduling: Increased to 4 meshes/frame in bone mode, reverts to 1 in static mode
