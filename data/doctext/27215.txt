Summary
Forward-ports the tile-level empty-space skip from the stranded phase-3-tile-cached-raymarch branch onto the current multi-atlas VT. Skips raymarch stepping through resident-but-empty tiles — the gap that residency/LOD-walk skipping (which only skips unloaded space) didn't cover.
Two commits:
Plumbing (PageTable + VirtualTextureData) — a parallel Rg8Unorm metadata texture (same dims as the page table) holds each resident tile's (min, max) in the contrast-normalised [0,1] range. compute_tile_min_max scans the R16Float chunk at upload. Because the multi-atlas refresh_page_table re-points entries without the tile bytes on hand (a path the original predated), the values are cached in a tile_minmax map mirroring slot_map's lifetime (insert on upload, remove on eviction/scrub) and looked up there — defaulting to (0,1) = "never skip" if absent. No bind group / shader changes → no behavior change on its own.
Skip (volume.rs + volume_raymarch.wgsl) — metadata bound at group(1) binding 8 (multi-atlas took 0–7), non-filtering Float D2Array. try_lod/sample_vvt now return (value, lod, tile_max), reading .g of the parallel metadata texel on a resident hit. fs_translucent mode 0 jumps to the resolved tile's far boundary (tile_skip_advance, clamped to step_size so grazing rays still progress) when tile_max < contrast_min + ε. Debug modes and the other render modes step verbatim.
Design notes
Rendering-side, not residency-side. This never evicts or touches the wanted set — it only changes per-frame stepping. So coupling the threshold to the contrast floor is safe (recomputed every frame, zero re-streaming), and it does not conflict with the roadmap's "empty-tile dropping must be intrinsic, not contrast-relative" rule — that rule governs the separate residency layer.
Tile-cache deliberately omitted. The old 41e514b also added a per-step tile cache; that was written against the pre-multi-atlas shader and is a separable optimization. Left for a follow-up.
Verification
Builds clean on native + wasm; clippy clean.
Confirmed working in the Python volume rendering example.
A/B for perf: main (no skip) vs this branch; the mode-3 step heatmap shows where steps go.

Adds a `skip_empty` flag to VolumeUniforms (repurposing _pad0), wired through
VolumeCore::set_skip_empty (default on) and exposed in the native volume
renderer via the `K` key. fs_translucent mode 0 now gates the skip on it.

Lets you A/B the skip within a single build — same resident tiles, same
camera, just toggle — so a GPU frame capture (Xcode/Instruments) on a sparse
dataset gives an objective render-pass-time delta. PrepareStats is CPU-only
and won't reflect the GPU-shader win, so measure the pass, not that line.
