This instalment offers an in-depth exploration of how GPU Instancing can significantly enhance the performance and scalability of voxel-based engines. Aimed at both aspiring and seasoned game developers, the article provides practical insights and step-by-step instructions to harness the full potential of Unity’s advanced features for voxel rendering. Whether you’re developing intricate game worlds or working on complex simulations, this guide is a crucial resource for pushing the boundaries of voxel engine performance.
Create a new GameObject call it TestGPU and add a script to it CubeRenderer.cs, then add these vars…
```
public Material material;public Mesh mesh;GraphicsBuffer commandBuf;GraphicsBuffer.IndirectDrawIndexedArgs[] commandData;const int commandCount = 2;public int gridWidth = 1000;public int gridHeight = 1000;public float spacing = 1.0f;int totalInstances;
```
material: This refers to the Material object in Unity, which contains the shader and texture information for rendering the meshes.
mesh: Represents the Mesh object to be rendered. This is the geometry of the object you want to draw, like a cube or sphere.
commandBuf: A GraphicsBuffer object for storing indirect drawing arguments. It’s used for GPU instancing with indirect draw calls.
commandData: An array of IndirectDrawIndexedArgs that stores data for each indirect draw call, like the number of vertices and instances to draw.
commandCount: The number of commands in the commandBuf. This is typically the number of different draw calls you plan to make.
gridWidth and gridHeight: These define the dimensions of the grid in which the meshes will be placed.
spacing: The distance between each instance in the grid.
totalInstances: A calculated value representing the total number of instances (meshes) to be drawn. The product of gridWidth and gridHeight.
Make a Start()…
```
void Start(){    commandBuf = new GraphicsBuffer(GraphicsBuffer.Target.IndirectArguments, commandCount, GraphicsBuffer.IndirectDrawIndexedArgs.size);    commandData = new GraphicsBuffer.IndirectDrawIndexedArgs[commandCount];    totalInstances = gridWidth * gridHeight;}
```
In the Start method:
commandBuf is initialized as a GraphicsBuffer for indirect drawing arguments. It’s set up to store the number of commands specified by commandCount.
commandData is an array of IndirectDrawIndexedArgs, which holds the parameters for each indirect draw call (like the count of indices and instances).
totalInstances is calculated as the product of gridWidth and gridHeight, representing the total number of instances (or meshes) to be drawn in the grid. This value is crucial for setting up the draw commands correctly.
Setup an Update() method
```
void Update(){    material.SetInt("_GridWidth", gridWidth);    material.SetInt("_GridHeight", gridHeight);    material.SetFloat("_Spacing", spacing);        RenderParams rp = new RenderParams(material);    rp.worldBounds = new Bounds(Vector3.zero, 10000*Vector3.one); // use tighter bounds for better FOV culling    rp.matProps = new MaterialPropertyBlock();    rp.matProps.SetMatrix("_ObjectToWorld", Matrix4x4.Translate(new Vector3(-4.5f, 0, 0)));        commandData[0].indexCountPerInstance = mesh.GetIndexCount(0);    commandData[0].instanceCount = (uint)totalInstances;    commandData[1].indexCountPerInstance = mesh.GetIndexCount(0);    commandData[1].instanceCount = (uint)totalInstances;    commandBuf.SetData(commandData);    Graphics.RenderMeshIndirect(rp, mesh, commandBuf, commandCount);}
```
Shader Parameters: Sets the grid width, height, and spacing in the material shader using SetInt and SetFloat. These parameters are used in the shader for positioning instances in the grid.
Render Parameters: Creates a RenderParams object with the material and sets the world bounds for frustum culling.
Material Property Block: Initializes a MaterialPropertyBlock to optimize material property changes without creating new materials.
Instance Transformation: Sets a transformation matrix in the material property block for positioning instances.
Command Data Setup: Configures commandData for two draw calls, setting the number of indices per instance and the number of instances to draw.
Command Buffer Update: Updates the commandBuf with commandData.
Rendering: Calls Graphics.RenderMeshIndirect to draw the meshes using the indirect draw arguments in commandBuf.
Add an OnDestroy()…
```
void OnDestroy(){    commandBuf?.Release();    commandBuf = null;}
```
In the OnDestroy method, commandBuf?.Release(); is called. This line releases the memory associated with commandBuf.
The ? in commandBuf?.Release(); is a null-conditional operator, ensuring that Release() is called only if commandBuf is not null. This is important for resource management, preventing memory leaks by ensuring that the graphics buffer is properly disposed of when the script or its GameObject is destroyed.
After releasing the buffer, commandBuf is set to null, effectively cleaning up the reference.
In the inspector choose a material and cube mesh, we will go for 1 Million Voxels being rendered at the same time!
For this to work we need a custom shader to work with the Material. Create a new Standard Surface Shader and open the file…
```
Shader "VoxelShader"{    SubShader    {        Pass        {            CGPROGRAM            #pragma vertex vert            #pragma fragment frag            #include "UnityCG.cginc"            #define UNITY_INDIRECT_DRAW_ARGS IndirectDrawIndexedArgs            #include "UnityIndirect.cginc"            uniform int _GridWidth;            uniform int _GridHeight;            uniform float _Spacing;            uniform float4x4 _ObjectToWorld;            struct v2f            {                float4 pos : SV_POSITION;                float4 color : COLOR0;            };             v2f vert(appdata_base v, uint svInstanceID : SV_InstanceID)            {                InitIndirectDrawArgs(0);                v2f o;                uint cmdID = GetCommandID(0);                uint instanceID = GetIndirectInstanceID(svInstanceID);                uint x = instanceID % _GridWidth;                uint z = instanceID / _GridWidth;                                float3 gridPosition = float3(x * _Spacing, 0, z * _Spacing);                float4 wpos = mul(_ObjectToWorld, v.vertex + float4(gridPosition, 0));                o.pos = mul(UNITY_MATRIX_VP, wpos);                // Alternating green color based on instance ID                // Checkerboard pattern                bool isEven = ((x + z) % 2) == 0;                o.color = isEven ? float4(0.0, 1.0, 0.0, 1.0) : float4(0.0, 0.5, 0.0, 1.0); // Adjust green tones as desired                return o;            }            float4 frag(v2f i) : SV_Target            {                return i.color;            }            ENDCG        }    }}
```
CGPROGRAM and ENDCG: These mark the beginning and end of the shader code written in CG, a high-level shader language.
#pragma vertex vert: This directive tells the shader compiler that the vert function is the vertex shader.
#pragma fragment frag: Indicates that the frag function is the fragment (or pixel) shader.
#include “UnityCG.cginc”: Includes Unity’s common shader include file, which contains useful shader functions and macros.
#define UNITY_INDIRECT_DRAW_ARGS IndirectDrawIndexedArgs: Defines a macro for indirect draw arguments, used in GPU instancing.
#include “UnityIndirect.cginc”: Includes code necessary for indirect rendering.
Uniform variables (_GridWidth, _GridHeight, _Spacing, _ObjectToWorld): These are parameters that can be set from a script and remain constant for each draw call. They’re used to determine the grid layout and spacing of the voxels and to transform the voxels in the world space.
```
struct v2f{    float4 pos : SV_POSITION;    float4 color : COLOR0;}; 
```
The struct v2f defined in the shader is a custom data structure used for passing data from the vertex shader to the fragment shader:
float4 pos : SV_POSITION: This field represents the position of the vertex in screen space. The SV_POSITION semantic is used by the rasterizer to determine where the vertex appears on the screen.
float4 color : COLOR0: This field is for the color of the vertex. The COLOR0 semantic indicates that this is the primary color output from the vertex shader, which will be interpolated across the surface of the primitive and used by the fragment shader.
```
v2f vert(appdata_base v, uint svInstanceID : SV_InstanceID){    InitIndirectDrawArgs(0);    v2f o;    uint cmdID = GetCommandID(0);    uint instanceID = GetIndirectInstanceID(svInstanceID);    uint x = instanceID % _GridWidth;    uint z = instanceID / _GridWidth;        float3 gridPosition = float3(x * _Spacing, 0, z * _Spacing);    float4 wpos = mul(_ObjectToWorld, v.vertex + float4(gridPosition, 0));    o.pos = mul(UNITY_MATRIX_VP, wpos);    // Alternating green color based on instance ID    // Checkerboard pattern    bool isEven = ((x + z) % 2) == 0;    o.color = isEven ? float4(0.0, 1.0, 0.0, 1.0) : float4(0.0, 0.5, 0.0, 1.0); // Adjust green tones as desired    return o;}
```
The vert function is the vertex shader in the shader code. It processes each vertex of the mesh and performs the following tasks:
Initializes indirect drawing arguments with InitIndirectDrawArgs(0).
Calculates command and instance IDs using GetCommandID(0) and GetIndirectInstanceID(svInstanceID).
Determines the position of each instance in a grid using the instance ID, grid width (_GridWidth), grid height, and spacing (_Spacing).
Transforms the vertex position from local to world space (wpos), then to screen space (o.pos).
Assigns a color to each vertex based on its position in the grid, creating a checkerboard pattern of two different green tones.
Returns the transformed vertex data (v2f) for further processing in the graphics pipeline.
Make sure the material you attached to the Cube Renderer script has this shader selected on it. Press Play…
Considering I’m rendering this on a laptop that uses Intel XE Graphics, meaning there is no dedicated GPU, it is pretty impressive to draw 1 million voxels on screen all at once. So I hope you understand what we are doing here, with our previous optimization techniques, sparse voxel DAGS and GPU Instancing.
