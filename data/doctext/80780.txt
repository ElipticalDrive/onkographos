Implemented a new parameter --porosity that allows for random voxel dropping during voxelization. It randomly discards voxels based on a stable, fractional sine-based spatial hash (pseudo-random number generator) using their coordinates, resulting in porous/sponge-like generated meshes.
Changes:
Signature Update: Added porosity: Option<f64> to the MeshProcessor::voxelize method signature in src/lib.rs.
Voxel Dropping Logic: Modified both the surface and solid voxelization loops in src/lib.rs to compute a hash let hash = (dot.sin() * 43758.5453).fract().abs(); and keep voxels only if the hash is >= porosity.
CLI Interface: Added an optional --porosity flag to Args in src/main.rs along with a validate_porosity parser verifying the value falls between 0.0 and 1.0.
Tests: Added test_voxelize_porosity to src/lib.rs which verifies that setting porosity = 0.5 significantly reduces the number of generated voxels compared to the baseline voxelization. Updated other tests and bench parameters accordingly.

Validate porosity in the library API
When callers use MeshProcessor::voxelize directly rather than going through the CLI parser, this new porosity argument accepts values outside 0.0..=1.0 or NaN without returning an error. For example, Some(1.5) makes every kept voxel fail hash < p, while Some(-0.5) or Some(NaN) effectively disables dropping, so invalid inputs silently produce misleading particle sets; add the same finite/range validation here that the CLI applies.
