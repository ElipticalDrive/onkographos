This page covers the first sphere tracing implementation in the repository: how a ray is set up per-pixel, how a Signed Distance Function (SDF) describes scene geometry, and how the ray marching loop finds a surface hit. The result is a flat-colored, unlit shape rendered entirely in a fragment shader without polygon geometry describing the visible surface.
For lighting calculations added on top of this foundation, see Sphere Tracing with Shading. For depth buffer integration so that sphere-traced objects correctly occlude rasterized meshes, see Sphere Tracing with Depth Buffer Output.
Overview
Sphere tracing (a form of ray marching) renders geometry by shooting a ray through each pixel and repeatedly querying a Signed Distance Function (SDF). The SDF returns the distance to the nearest surface at any given point. Each step advances the ray by exactly that distance, which is safe because no geometry can be closer than what the SDF returns. When the accumulated distance falls below a threshold, the pixel is considered a surface hit.
The key difference from traditional rasterization is that the visible shape is defined mathematically by scene(), not by a triangle mesh. The host mesh (a Unity cube in the demo scene) serves only as a bounding volume to determine which pixels invoke the fragment shader.
Source file: Assets/043_SphereTracingBasics/SphereTracingBasics.shader

Vertex Shader: Ray Setup
The vert function in Assets/043_SphereTracingBasics/SphereTracingBasics.shader38-49 prepares two values that are interpolated to every covered pixel:
localPosition — the mesh vertex position in object/local space. Used as the starting point of the ray for that pixel.
viewDirection — the vector from the camera (in object space) to the vertex. This is not normalized; normalization happens in frag.
The camera position is transformed into object space using unity_WorldToObject:
```
objectSpaceCameraPos = mul(unity_WorldToObject, float4(_WorldSpaceCameraPos, 1))
viewDirection = vertex - objectSpaceCameraPos
```
Working in local/object space keeps the SDF definition simple: it does not need to account for the object's world transform.
Why DisableBatching? The tag "DisableBatching"="True" is required because batching combines objects into a shared mesh, which invalidates the per-object unity_WorldToObject matrix used to convert the camera position.
Sources: Assets/043_SphereTracingBasics/SphereTracingBasics.shader8-9 Assets/043_SphereTracingBasics/SphereTracingBasics.shader38-49
Scene SDF: scene()
```
float scene(float3 pos){
    return length(pos) - 0.5;
}
```
This is the SDF for a sphere of radius 0.5 centered at the local origin. length(pos) - 0.5 returns:
A negative value when pos is inside the sphere.
Zero exactly on the surface.
A positive value outside the sphere, equal to the distance to the nearest surface point.
All more complex scenes replace or extend this single function. The sphere tracing loop only ever calls scene() and checks the result — the entire shape of the rendered object is determined here.
Sources: Assets/043_SphereTracingBasics/SphereTracingBasics.shader52-54
Fragment Shader: Ray Marching Loop
Diagram: Ray marching step sequence
```
"scene(float3 pos)""frag()""scene(float3 pos)""frag()"alt["distance <THICKNESS"]loop["iter < MAX_STEPS"]"pos = localPosition (ray origin)""dir = normalize(viewDirection)""progress = 0""samplePoint = pos + dir * progress""scene(samplePoint)""distance""return _Color""progress += distance""discard (no hit)"
```
Sources: Assets/043_SphereTracingBasics/SphereTracingBasics.shader56-78
Step-by-step
Initialize: pos = interpolated local-space position from the mesh surface. dir = normalized view direction. progress = 0 (start at the mesh surface, not at the camera).
Sample: Compute samplePoint = pos + dir * progress.
Query: Call scene(samplePoint) to get distance to nearest geometry.
Hit check: If distance < THICKNESS, the ray is inside (or close enough to) the surface — return _Color.
Advance: Add distance to progress. Because the SDF guarantees no surface is closer than distance, this step cannot skip over a surface.
Miss: If MAX_STEPS is exhausted, call discard to throw away the pixel entirely (make it transparent).
The starting point is the mesh surface, not the camera. This means the ray begins at the bounding cube's face, not somewhere behind it. Pixels that correspond to the back half of the cube (where the cube face is already past the sphere) will fail to hit anything and be discarded.
Sources: Assets/043_SphereTracingBasics/SphereTracingBasics.shader56-78

Relationship to the Shading Tutorial (044)
The follow-up shader at Assets/044_SphereTracingShading/SphereTracingShading.shader extends the same structure. The changes are additive:


The frag loop logic is identical between both shaders. Only the value returned on hit differs: _Color directly in 043, and material(samplePoint) in 044.

Demo Scene
The scene file Assets/043_SphereTracingBasics/SphereTracingBasics.unity contains:
Main Camera at (0, 0, -2.186) pointing forward.
Directional Light providing scene illumination (not used by the basics shader, since it returns a flat color).
Cube game object with the SphereTracingBasics material applied. The cube acts as the bounding volume; the SDF sphere (radius 0.5) fits inside it.
The material SphereTracingBasics.mat sets _Color to a pale blue/lavender (r: 0.741, g: 0.713, b: 1.0).
