体积云效果的实现，游戏世界的云合雾集
游戏程序

云雾或散或聚，群峰则忽隐忽现，云是室外场景重要的组成部分之一，它千姿百态、千变万化，实时的体积云渲染技术在现在的3D游戏中也很常见，但如何打造翻滚的云浪，构建一个有着无边云层的虚拟世界？云朵又是如何从粗糙棉丝变成了缥缈柔雾的？
本文主要分享下面向PC/主机的体积云效果实现技术。下面先放两个效果图：
由于本项目还未上线，涉及信息保密，本文只用了比较简单的测试场景，效果也是笔者随手调的，不代表最终品质。下面主要对实现方法进行下分享和总结。
一. 体积云的建模
对体积云进行建模即是要构建体积云的密度场，计算出空间中任意一点的云的密度值。目前主流的做法一般是借助3D纹理来存储云的密度信息，3D纹理中可以直接存储云的密度值、可以存储距离场信息、也可以存储烘焙的光照信息等，具体做法多种多样，视需求而定。
本文主要介绍实时的天空体积云建模方法，目前 PC/主机端比较主流的做法都是基于噪声纹理进行程序化建模，然后配合一些美术资源来做出更加丰富的形态和表现效果。使用何种形式的噪声纹理和美术资源也有很多种做法，像是地平线、荒野大镖客2、寒霜等分享的方法都很值得参考，UE4里面甚至直接使用了Material Graph，将建模方式完全开放给美术/TA来做，这种方法虽然很灵活，但是性能上不太易于进行控制和优化，纠结了很久还是暂时没有采用这种做法。
本文体积云的建模方法主要参考了Unity HDRP 12.0版本之后新出的体积云效果，大致方法可以用下图描述：
形状噪声纹理使用分形Perlin-Worley噪声，用于生成云的基本形状；细节噪声纹理使用分形Perlin噪声，用于对云的形状边缘进行侵蚀以添加细节。两个噪声图都需要Tileable，噪声图的生成方式主要参考此ShaderToy中的方法（HDRP源码中也有，和这个基本一样）。
Cloud Map包含4个通道，本文的做法是RGBA分别存储Cloud Coverage、Cloud Type、Cloud Erosion和Cloud Wetness。Cloud Lut定义了不同类型和高度的云的分布，例如下图是Unity HDRP中提供的一张Cloud Lut图，图中RGB通道值分别表示云的Density、Erosion、Ambient Occlusion。
这张Cloud Lut分为四个部分，Cloud Type 0~0.125是高层云、0.125~0.25是高层云和积云（即同时有两层云）、0.25~0.5是积云、0.5~1.0是积雨云（这张图有挺多重复，感觉可以优化一下）。四种类型的云分别对应以下效果：
上面图片的效果都是只有一种类型的云的情况，且不同区域的云的疏密程度完全由噪声参数控制。如果美术需要场景中同时有不同类型的云、或者需要能够自由控制云的疏密程度，则需要用到Cloud Map。Cloud Map可以由美术直接进行绘制，不过由于这种方式无法实时观察到效果，不太方便，因此我们制作了一个笔刷工具，方便美术进行绘制，和UE4的Blueprint Painted Clouds类似。
最后补充一点，对于下图这种形状比较复杂的积雨云，我原本以为是需要结合Cloud Lut在Cloud Type的0.5~1.0之间进行过渡（这样当然也能做），但实际上有更为简单的做法，即根据高度给噪声不同的覆盖率和侵蚀度，高处的云覆盖率低且噪声侵蚀度高，低处的云覆盖率高且噪声侵蚀度低。CloudLut中G通道存储的Erosion实际上不只是给细节噪声用，也会影响形状噪声的计算结果，具体细节可以参考Unity HDRP源码中的实现。
二. 体积云的流动效果
体积云的流动包括两种：一种是全局的流动效果，另一种是局部的流动效果。对于天空上的体积云来说，一般只需要全局的流动效果，局部的流动效果可以用给云海、风暴云等效果用。
全局流动效果
我们给美术两个全局风速用于控制体积云的整体流动，一个用于控制云整体形状的流动（包括CloudMap和形状噪声纹理），另一个用于控制云细节（细节噪声纹理）的流动。实现上基本就是随时间变化对噪声图的采样坐标进行偏移，非常简单。
值得一提的是，两个风速的Y分量可以控制噪声竖直方向的滚动，将形状噪声纹理沿Y轴滚动可以实现云整体分布随时间的变化，这也是使用3D纹理的好处之一。不过也有其它做法，例如荒野大镖客2中在2D Cloud Map的四个通道存储了四种不同分布的云，然后根据TimeOfDay参数进行插值，这种做法也挺不错。
局部流动效果
局部流动效果一般使用FlowMap来做，顾名思义，FlowMap是一张记录了流动方向的纹理，我们使用世界坐标的XZ分量计算UV坐标，从FlowMap中采样得到三维的流动方向对噪声纹理进行偏移。对于比较简单的局部流动效果，比如圆形的漩涡，流动方向也可以直接在shader中计算得到，这样可以省去采样FlowMap的开销，但原理都类似。
和全局流动效果不同的是，由于FlowMap中记录的方向可能朝向四面八方，速度也有大有小，随着时间的推移，噪声纹理会被拉伸的越来越严重。解决这一问题的做法是取fract(time)让噪声纹理沿一小段距离重复流动，然后取fract(time+0.5)再采样一遍流动快半拍的噪声纹理，对两次纹理采样结果进行插值，即可得到一个相对平滑的流动效果，实现原理细节可以参考这篇文章。
在每个采样点完整的计算两遍CloudDensity显然是一笔很大的开销，因此我们只将FlowMap应用于形状噪声的流动上，即只采样两遍形状噪声纹理，其它纹理贴图保持原来的做法不变。效果如下图：

三. 体积云的光照
体积云的绘制方法通常是在屏幕空间做Ray Marching，在每一步累计光照和透射率。光照需要考虑单散射光照、多重散射光照和环境光照，透射率通过比尔定律（或者地平线中提出的Beer‘s-Powder方法）进行计算，下文进行简单介绍。

可见性函数Vis(·)可以分解为下式所示的两部分，即shadowMap阴影和体积阴影，对于天上的云来说一般不需要考虑shadowMap阴影和其它体积材质在云上投射的阴影，只需要考虑云本身的自阴影。
体积云自阴影的做法主要有两种：
第一种方法比较常见，做法是每个采样点向光源方向再做一次RayMarching（PC/主机端一般6步左右）来计算transmittance，这种做法思路简单，在采样步数够多的情况下效果也较好，但显然开销会比较大。
第二种方法是体积阴影映射，例如UE4的Beer's Shadow Map，以及更复杂一点的Transmittance Fucntion Mapping方法（目前只看到最终幻想中用过类似方法）。Transmittance Fucntion Mapping方法的原理是使用一系列正交基函数来近似透射率函数，基函数的选择上有用傅里叶函数、DCT函数、Haar小波函数等做法，与Beer's Shadow Map相比，TFM这类方法在一些情况下对透射率曲线的近似会更准确一些，当然开销也更大。
上述两种做法我们都尝试过，两种方法各有优缺点：
Ray Marching方法细节更丰富，但开销大（细节更丰富的原因一方面是由于阴影贴图精度受限，而RayMarching没有这个限制；还有一个原因其实是步数不足产生的噪波导致的，不过美术有时候就是喜欢带一些噪波的阴影效果）。
体积阴影映射方法效率会更高，且可以用于做云向其它物体的投影，不过在一些情况下会产生较大误差。
下图是我们测试的Ray Marching方法和TFM方法（使用傅里叶级数的前7个系数）的效果和效率对比，可以看到TFM方法效率上大致与RayMarching 1~2步相当，效果比Ray Marching 2步更接近正确结果一些（Ray Marching2步情况下步长太长的话会导致噪波比较严重，步长太短又会导致很多地方会偏亮），不过TFM方法也会产生一些带状artifacts，通过滤波可以一定程度上减弱。

环境光照
环境光照做法比较简单，我们通过采样大气散射生成的SkyLightLut来获取环境光颜色（大气散射用的UE4的方法），如果场景中没开大气散射则采样实时烘焙的Ambient Probe（三阶SH编码）。环境光AO根据海拔高度渐变，提供一个参数给美术设定云层底部的AO值，随着海拔增高逐渐增大到1，然后乘上Cloud Lut B通道的AO值。
上述做法仍存在一个问题，由于没有考虑环境光的多重散射，导致云的颜色偏蓝（过于偏向天空颜色）。我们参考了寒霜的做法，提供给美术一个参数来调整环境光颜色饱和度。
四. 体积云的渲染
本文体积云的渲染流程如下：
Editor模式下利用笔刷工具绘制CloudMap或FlowMap（如有需要），并保存到2D纹理中以供运行时使用，这一部分比较简单。
Runtime模式下主要包括四个pass：第一个pass是Transmittance Function Mapping，从太阳方向做正交投影生成体积阴影贴图，贴图使用512x512x3 R11G11B10格式，存储了投影计算得到的傅里叶级数的前9个系数（之前用的是512x512x2 RGBA Half存7个系数，后面改成了9个系数）。生成的系数大概是下图这个样子，之后在计算自阴影时读取傅里叶系数，和基函数进行线性组合得到重建的光学深度，进而得到透射率。具体细节可以参考这两篇文章：Transmittance function mapping和Fourier opacity mapping。
后面几个pass首先是在屏幕空间降分辨率做Ray Marching绘制体积云，然后做时域滤波降噪，最后上采样到全分辨率并混合到Scene Color RT中。
性能优化和降噪方面主要包含以下几点：
降分辨率 + 分帧处理。高配下直接降分辨率到1/2x1/2，处理起来比较简单；中低配下使用了分帧处理方法，和荒野大镖客2里面类似，不过在只考虑天上的云，不考虑云与其它物体穿插的情况下处理起来会简单很多。这方面知乎上这篇文章做过比较详细的分享，HDRP中也有类似的做法，感兴趣的话可以去看下。
蓝噪声Dither + Temporal Upsampling。蓝噪声Dither可以解决采样步数不足导致的切片问题，但又会引入噪点，可以进一步结合Temporal Upsampling减少噪点。
动态调整采样步长：连续多次密度采空时增大步长为原来的2倍，并且增大mipOffset；直到采样密度不为空时，回退一步，并将采样步长和mipOffset恢复为原来的值。（这个提升其实很小，某些情况下还会导致一些artifacts）
五. 其它细节
和大气散射的光照一致性
做法是根据地球半径和采样点高度计算UV，查询大气散射的transmittanceLut得到sunColor。在每个采样点都查询transmittanceLut没有必要，可以只在云层底部和顶部进行两次查询，中间结果插值。
混合雾效
采用UE4里面的做法，计算射线穿过云层的加权平均(Transmittance作为权重)深度，只在该深度处采样并混合雾效，而不需要每个采样点都进行处理。
实时反射
SSR只能反射屏幕空间内的云，如果需要实时反射屏幕空间外的云需要额外增加一个Pass，渲染低分辨率(256x128)的全景云，混合到天空的Cubemap中。不过这种做法精度比较低，只用于比较糊的反射，对于水面中的云一般会再单独做镜面反射处理。
结语
本文介绍了实现体积云效果的一些关键方法及其基本原理，以供大家学习和参考。未来的研究与改进方向主要是实现物体与云的实时交互效果，以及尝试下更加灵活的建模方法（类似UE的MaterialGraph，在Unity里面可以用ShaderGraph来做，不过性能优化上会比较难处理）。
此外，体积云和粒子等半透明物体的穿插也是很难处理的一个问题，像是用体积雾的体素化做法也不太现实。之前尝试过用一些OIT算法的思路来做，但无论是效果上还是性能上都不太理想。
最后，希望本次分享能对大家有所帮助，感谢大家的阅读！
