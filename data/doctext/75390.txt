The stronger variant — try all six orders per seed, keep the largest box — also ties on every room-like shape and comes out slightly worse on random masks (205.2 vs 202.8), because greedily maximizing one box leaves worse leftovers.
The reason is structural: the slab rule already extends maximally along each axis in turn, so for near-rectilinear geometry the result is order-independent. The option is kept but defaulted off, with a test pinning the negative result so the idea isn't rediscovered. Cutting the box count — and with it the interface area, where the error lives — needs a different lever: seed selection, or a merge pass.
Other departures from the spec
No BVH in the voxelizer. The spec called for a three-mesh-bvh box-vs-triangle query per candidate cell. Scattering each triangle into the cells its own bounding box covers is strictly better: work is proportional to the surface area in cells — the solid cells actually produced — rather than grid volume × log(triangles), and it needs no acceleration structure. The overlap test is exact either way: full 13-axis SAT, because a conservative AABB test thickens oblique walls into a blob, changing the air volume and with it the modal frequencies.
Pure core, separate adapter. voxelize.ts has no three, no stores, no DOM, so the geometry is testable on plain triangle lists. voxelize-room.ts is the thin adapter — the same split radiance/patch.ts already uses between buildPatchesFromTriangles and buildPatchesFromRoom.
Thin boxes are marked fdtd, not merged. Merging was the spec's first suggestion, but the union of two boxes is only a box in special cases, so a merge pass would succeed rarely and silently leave the rest. Marking the kind always works and Phase 4 already implements the partition — which is exactly why the reference keeps an FDTD partition around.
Leaks reported, not thrown. voxelize sets leaked and a warning; decompose is what refuses. A caller may still want the grid in order to find which surface is open.
Design notes worth a look
Leak detection. The grid is padded a cell on every side, so the exterior always touches the rim. If the fill reaches it, either the seed was outside or the surfaces don't close — and a gap of one cell drains the interior, making the "air region" the whole bounding box. Silently decomposing that would produce large, quiet nonsense.
Sealed voids are excluded. The fill is 6-connected from a seed, so a closet nobody opened stays solid — it isn't part of the room's acoustic volume.
validateDecomposition checks the cover is a true partition: every air cell in exactly one box, no box touching solid, assignment agreeing with the boxes. Cheap next to a simulation and worth running before Phase 6 spends minutes on a bad cover.

Known limits
Staircasing. Non-axis-aligned surfaces become stair steps. Intrinsic to grid methods, not a choice here, and part of why the plan keeps ARD to the low-frequency band.
Corner attribution. Where two surfaces meet, the shared cell is attributed to whichever triangle reached it first. Phase 6 may want an area-weighted rule for per-band absorption at corners.
Same 4 pre-existing failures in dir-angle-conversions.spec.ts / temperature-air-absorption.spec.ts, unchanged and unrelated.
Next
Phases 1–5 are now done and tested together. What remains is Phase 6 onward — the simulation driver and worker, the solver class, the UI wiring — plus §5's cost envelope, which is the open question the numerics can't answer.

Must-fix
- Seed relocation preferred the exterior on -x/-y/-z walls. The search
  returned the first free cell found walking k, then j, then i, which
  for a wall on a low-index face is the pad cell outside the room. The
  fill then flooded the exterior of a watertight cube, leaked went true
  and decompose threw. Reproduced before fixing: a closed unit cube at
  dx = 0.1 gave airCount 866 and leaked for -x, -y and -z seeds, against
  729 for an interior seed; +faces passed only because their low-index
  neighbour happens to be interior.

  This is not limited to seeds exactly on the mesh. Math.round maps any
  point within half a cell of a wall-cell centre onto that wall, so a
  source anywhere in the half-cell band inside a -face took the same
  path — which is where wall-mounted speakers go.

  Fixed by deciding relocation on whether the fill stays sealed rather
  than on scan order: candidates are ordered by radius then by distance
  to the grid centre, each is filled, and the first enclosed one wins.
  Ordering only affects how fast the right candidate is found; the fill
  check is what makes it correct. A seed that is already in free space
  is never relocated, so a genuinely open room still reports its leak
  instead of having it papered over.

- Strengthened the wall-seed test, which had asserted only the warning
  string and so let the bug ship. Now parametrized over all six faces
  and over half-cell-inward seeds, asserting leaked === false and an
  airCount matching a centre-seeded control, plus that decompose accepts
  the grid and produces identical boxes. Verified against the old
  behaviour: it fails exactly the three broken faces, the three
  near-wall seeds, and the decompose case.

Non-blocking
- Stencil depth is now defined once. partition.ts derives INTERFACE_DEPTH
  from STENCIL_6TH itself; interface.ts re-exports it and decompose.ts
  imports it for DEFAULT_MIN_BOX_EDGE. Previously the two declared 3
  independently and could drift, marking boxes dct that cannot supply
  the taps interface.ts goes on to read.

- voxelize-room expands an index buffer instead of reading positions as
  consecutive triples. Surface builds non-indexed geometry today, so
  this is defence, but an imported or re-loaded model carrying an index
  would have produced shared-vertex soup, a holed shell and a leak that
  is very hard to trace back here. TessellateModifier guards the same
  way. Tested for vertex reuse, world transform, and that an indexed
  cube voxelizes to a byte-identical grid.

201 ARD tests pass (was 184).
