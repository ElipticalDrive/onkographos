What and why
TriangleGrid.blocks walked each segment through the voxels it crosses as whole-array numpy passes over every ray still in flight. Profiled on a 51,200-triangle cylindrical wall, that bookkeeping cost ~150-180 ns per ray per voxel step and was most of the walk's time (the traced triangle test was 6-47%). That is also why refining the grid made it slower: fewer triangles tested, more steps taken.
A survey of how production ray tracers (Embree) get their speed found that the execution model (compiled per-ray traversal) came first and the data structure second. The first of these can be adopted without importing a ray tracer, so this PR does that:
aquaflux/radiation/grid_walk.py: a numba.njit(parallel=True) loop, one ray per prange iteration, walked to its first hit or its end. It visits the same voxels, in the same order, with the same tie rule and step cap, and uses the same watertight test (Woop, Benthin & Wald), including the averaged, exactly antisymmetric edge function. Each ray's axis permutation and shear are formed once per ray.
Numba is a core dependency (numba>=0.61, the first release with Python 3.13 wheels), as decided by the project owner instead of keeping it optional.
The array walk is deleted as dominated: it lost at every grid and scene measured. Its machinery (_Rays, _indexed_pair_is_cut, _work_groups, _pad, triangles._pair_is_cut) goes with it.
blocks takes no work_limit, since no (ray, triangle) pair array is formed. RayCastOcclusion(grid=...) and TriangleBody get the walk with no new setting.
NUMBA_NUM_THREADS=1 is set beside OMP_NUM_THREADS in tools/fastgate.sh's parallel tier and in CI, so xdist workers don't each start a machine-sized pool.
⚠️ The intersection test now exists twice: grid_walk._cuts alongside the traced _watertight_hit + _counts_as_hit, which the dense path still needs. A Numba loop cannot call a traced function. Every grid contract test compares the walk against segment_is_cut, and both docstrings say that a change to one must be made to the other.

The walk alone was measured against the array walk in one process, on the same 200,000 rays, at the prototype commit d9fc017. The speed-up was 16.9-37.3x across two scenes and three resolutions, with identical answers. The first call of a process also compiles the loop, which takes ~2 s.
⚠️ Not measured on the Sozzi wall (bodyWall.stl / work/case are absent here) or on the 11-core machine. What this buys against the 88 h mesh-scale estimate in the rules is therefore not established; grid_mask_check.py is the run that would establish it.
Tests
Contract tests: test_radiation_grid.py compares the walk against segment_is_cut at several resolutions.
New in this PR:
rays aimed at every vertex and edge midpoint of a closed drum (the watertight fixture);
the inclusive far end: a segment ending in a triangle's plane is blocked;
the exclusive near margin: a hit exactly at the margin doesn't count (axis-aligned, so the distance is exact);
y-parallel segments, added to the shared fixture.
Removed: the work-limit and compiled-shape tests, which went with the array walk.
Mutation pass on the final kernel: 13 mutations, 8 red. The 5 survivors are each recorded with the reason they cannot change an answer. Notably, the plain edge function survives even with fastmath={"contract"}; the averaged form stays so watertightness doesn't depend on the compiler.
Local runs: the radiation suite, the validation-API guard, check_rules and fastgate tests passed (653), and two crashed files passed serially (39).   16.9-37.3x on a long thin vessel and an annular reactor (4-core Linux container).
