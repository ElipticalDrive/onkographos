Description
Fixes sawtooth edges when rendering labels in 3D.

The issue
In 3D, labels layers are rendered with the iso_categorical method (or translucent_categorical when rendering='translucent'). Both march along each view ray in fixed steps (relative_step_size, 0.8 voxel by default) and only test the voxel at each sample. A ray that only clips the corner of a voxel, between two samples, misses it. Whether that happens depends on where the samples fall, which drifts from pixel to pixel, so straight edges seen at grazing angles render as a sawtooth that shifts as the camera moves. A smaller step makes the teeth finer but never removes them.
The fix
At the first unclipped sample, the shader now walks through every voxel the ray passes through, in order (Amanatides & Woo), and stops at the first one with a non-transparent label. No voxel can be skipped, so in volume depiction the result no longer depends on relative_step_size. Clipping planes are evaluated where the ray enters and leaves each voxel, so cut surfaces stay where they were. The ray is shortened by a tiny margin at both ends, as otherwise rounding reads the neighbouring voxels when a plane starts exactly on a voxel boundary.
Both categorical methods share the new snippet, and the fast and smooth gradient modes only change how the hit voxel is shaded, so all combinations are fixed.
Also fixed by this
Depth across scales. The new code sets each pixel's depth to the point where the ray enters the hit voxel, in data coordinates. On main, the depth (frag_depth_point = iloc * u_shape) was shifted by half a voxel along each axis, in the layer's own voxels. Layers with different scale are shifted by different amounts, so where two surfaces are close, the one behind can be drawn in front. As the shift is along every axis, how much it matters depends on the viewing direction; the figure uses the direction where it is largest:
Plane depiction. With depiction='plane', main's sub-stepping read the voxels just before the plane instead of those at it, so a plane at z = 5 showed the data at z = 4. The traversal reads the voxels within the plane's thickness:
Performance
The traversal visits every voxel along the ray. Each visit costs more than a sample of the old loop, and at oblique angles a ray crosses more voxels than it took samples. Frame times on an M1 Max (canvas about 2000 × 1800 px, iso_categorical, default step 0.8), main → this PR:

translucent_categorical is similar (1.1× to 1.8×). The old cost grows with 1/step while the new one does not depend on it: compared with main at step 0.4 (which still has the artifacts, only finer), this PR is as fast or faster in all of these cases (0.66× to 1.0×). Dense labels, where rays stop almost immediately, render in under 1 ms either way.
What remains is the cost of reading every voxel along the ray. I have a prototype for a follow-up PR that skips empty space using a coarse map of which 8 × 8 × 8 blocks contain labels. In the same benchmark it renders identically and is faster than main everywhere (0.5× to 0.93×), but it needs a second texture and has to be kept up to date when the data changes or is painted, so I'd rather keep it separate from this fix.
Tests
Two tests in src/napari/_vispy/_tests/test_vispy_labels_layer.py, both failing on main:
test_labels_iso_categorical_independent_of_step_size: a staircase at a grazing angle renders identically with step sizes 0.8 and 0.1.
test_labels_iso_categorical_depth_across_scales: of two overlapping layers with different scales, the one in front is drawn in front.
Not in this PR
vispy's own iso, mip and minip methods, used for image layers, compute the depth in the same way and have the same half-voxel offset. Fixing that belongs in vispy.
