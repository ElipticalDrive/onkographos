Summary
voxel_isosurface — Extract a triangulated isosurface at one or more threshold values from a 3D voxel field (a multidimensional raster), via marching cubes.
ArcGIS counterpart: Export Voxel Isosurface
Motivation
GeoLibre can now build 3D fields — idw_3d (#488) interpolates volumetric point observations onto a grid, interpolate_from_spatiotemporal_points (#463) writes multidimensional rasters, and the bundled kriging tools produce 3D-capable output. There is no way to turn any of them into geometry you can look at. The entire contouring suite (contours_from_raster, contour_with_barriers, percentile_contours, volume_percentile_contours) is 2D: it extracts lines from a plane. Extracting surfaces from a volume is the 3D analogue and is absent from both registries — nothing in either matches marching cubes, isosurface, or voxel.
This is the recommendation with the most upside for the repo's identity. It is pure computational geometry with no dependencies, it completes the round-14/15 3D push by giving that suite a renderable output, and it lands directly in the repo's web-delivery lane: an isosurface mesh is exactly what a browser viewer consumes. It's also the natural pairing for minimum_bounding_volume (#484) and inside_3d — one builds containers by hand, this one derives them from data.
Typical uses: plume and contamination envelopes from idw_3d output, ore-grade shells, cloud/aerosol layers from atmospheric stacks, and geological unit boundaries.
Proposed behavior
input — multidimensional/3D raster, or a stack of aligned bands treated as Z slices (required)
values — one or more threshold values, comma-separated; one surface per value
output — triangle mesh geometry, one feature per threshold, with the threshold as an attribute
format (optional) — multipatch (default, consistent with the existing 3D tools) or obj/gltf for direct web use
z_spacing (optional) — vertical spacing between slices when the source carries no dimension metadata; defaults to 1
close_boundaries (optional, default true) — cap surfaces where they meet the volume edge, so the result bounds a closed solid rather than leaking; this is what makes the output usable by inside_3d
smooth (optional) — Laplacian smoothing iterations over the extracted mesh, default 0
decimate (optional) — target triangle-reduction fraction, since raw marching-cubes output is dense
Implementation sketch
Pure Rust, no external crates:
Marching cubes. Walk every 2×2×2 cell of the voxel grid. Classify the eight corners against the threshold into an 8-bit index, look the index up in the standard 256-entry edge table, and emit triangles with vertices placed by linear interpolation along each crossed edge (not at edge midpoints — midpoint placement is what makes isosurfaces look blocky). The edge/triangle tables are static const data and should be committed as such, with the table's provenance noted in a comment.
Ambiguity. The classic marching-cubes ambiguous cases produce holes in the surface. Resolve with the asymptotic decider on ambiguous face configurations; a test that extracts a sphere and asserts the mesh is closed (every edge shared by exactly two triangles) is the right way to catch a regression here, and is worth writing first.
Vertex welding. Adjacent cells generate duplicate vertices on shared edges. Weld by hashing quantised edge identity — keying on the edge's grid indices rather than the float coordinates, which avoids the float-equality trap entirely.
Boundary capping. With close_boundaries, treat the volume's outer faces as a threshold-exceeding wall so surfaces reaching the edge are sealed.
Smoothing / decimation. Optional Laplacian smoothing over the welded mesh, then quadric-error-metric decimation to the requested fraction. Both operate on the welded topology from step 3.
Output. Multipatch through the same geometry path minimum_bounding_volume (feat(tools): minimum_bounding_volume — 3D convex hull, sphere, envelope or concave hull enclosing 3D features (ArcGIS Minimum Bounding Volume) #484) uses; gltf/obj as plain buffer writes for browser consumption.
Thresholds are independent, and within one threshold the cell sweep is embarrassingly parallel — dispatch_worker over Z slabs (native threads, serial WASM fallback), merging at the weld step. Fully deterministic: no RNG, no Date::now.
Wiring follows the standard 3-file pattern: a new module in crates/geolibre-tools/src/voxel_isosurface.rs implementing wbcore::Tool, three lines in lib.rs (mod + Box::new in geolibre_tools() + a geolibre_param_schemas match arm, enforced by a unit test), and a README table row.
