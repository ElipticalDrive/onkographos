Spec-first proposal (no implementation yet) for a mesh-native voxelizer in this library.
Scope
cmg::voxelize::voxelize(PLC, opts) → VoxelGrid (origin, spacing, dims, data):
Occupancy grid and signed-distance field modes.
Exact-predicate inside/outside classification (winding-number / ray-parity via orient3d) — not the carve's epsilon ray test — so watertight meshes classify robustly, including in single precision.
Reuses the existing point-in-solid classifier, the boundary-triangle spatial index (CarveGrid), and Shewchuk's predicates.
Exposed through the C ABI / Python (NumPy (nx,ny,nz) + origin/spacing) / Swift.
Why here (cmg), not SciPP
Built entirely from cmg-owned geometry + predicates, and the grid can feed the existing adaptive-sizing field. The grid is a plain array value type, so SciPP can layer generic grid math (morphology, resampling, level sets) on top — geometry → grid here; grid → grid math in SciPP.
Difference vs OCCT — made explicit in the proposal and spec
OCCT is a B-Rep CAD kernel and classifies against exact analytic surfaces. This is different by representation:
Fidelity is bounded by the input tessellation — cmg only sees a triangle mesh, so a curved input is only as accurate as its faceting. For STEP/IGES/curved CAD, OCCT is materially better (exact surface); that is an explicit non-goal here, not a defect.
For a triangle mesh (cmg's native input) there is no exact surface for either tool, so the ceiling is equal; the difference reduces to classifier robustness, which the spec closes by requiring exact predicates.
cmg is stronger on speed (fast, parallel spatial-grid classifier), footprint (no CAD dependency), and meshing/sizing integration.
Non-goals: B-Rep/exact-surface voxelization, hex meshing, marching-cubes/iso-surfacing, octree meshing, conservative GPU-rasterization semantics, healing non-watertight input.
