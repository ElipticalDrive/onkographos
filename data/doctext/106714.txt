Summary
Implements the two OpenVDB/NanoVDB ideas that apply to the web raymarcher, without the library:
Empty-space skipping. The shader fetches a page-table entry for the ray position each step. An empty page is jumped to its exit face in one loop iteration (one-level DDA) and the ray lands back on its jittered sample lattice so cadence does not change at page entries.
Leaf bricks with a page table. build_volume_texture now emits a page table (one RG8 entry per 8³-texel page: pool slot + 1, or 0 for no echo) and a pool of resident bricks, each the 8³ core wrapped in a one-texel apron copied from neighboring logical texels (clamped at the grid edge) so trilinear filtering never leaves the brick. The dense logical grid is never materialized.
Effects
Full source resolution at 120 NM. The dense grid capped each axis at 256 cells, so a ~440-cell request was coarsened 2× horizontally. The sparse grid allows a 2048-cell logical axis; coarsenX/Z = 1 in the common case.
Bounded uploads. Resident bricks are capped at MAX_VOLUME_BRICKS = 8192 (a 16.4 MB pool at 2 KB per brick). Past that the grid coarsens by the next whole footprint multiple after a count-only pass, so the pool is bounded without failing on widespread rain.
Terrain occlusion survives skipping. buildGroundPageMax records the highest ground under each page column (one-column halo for the linearly filtered heightfield). An empty page is jumped only when it lies wholly above that value; otherwise it is stepped with the per-sample ground test and no volume fetch.
Phase bleed on every stored copy. Empty texels bordering echo adopt the neighbor's phase in cores and aprons alike, so brick faces do not tint toward rain.
Debug panel. New Volume Bricks row: resident bricks, filled logical texels, cell size, coarsening multiple.
Extinction recalibration (follow-up commit)
Andy reported light precipitation reading as nearly invisible on the preview. Root cause: the old dense grid max-pooled 0.5 NM source cells into 1 NM texels, which filled the gaps of scattered light echo (a region 50% filled at source resolution read ~94% filled) and so gave light precipitation about twice its true optical path. The cubic extinction ramp had been tuned against that. Old-vs-new headless renders of the same live payloads measured the new grid 17–28% dimmer in lit-pixel energy, concentrated in light and moderate echo:

Doubling extinction (+24–41%) and a 2.5 power (+20–33%) overshot because the pooling barely inflated solid heavy echo. The ramp is now pow(t, 2.75); cores, which saturate, are unchanged. Documented in the shader, docs/rendering-weather-volume.md, and the decision note.
GPU smoke test (npm run test:smoke:volume)
scripts/volume-smoke/ bundles the real NexradVolumeRaymarch over the shipped WASM decoder, renders it in headless Chromium on SwiftShader WebGL2 against a committed KMIA AVMR fixture (or --live <lat>,<lon>), and fails on any console error (shader compile failures land there), on budget coarsening, on a page-table/pool layout mismatch, or on a broken occlusion invariant (60,000 ft flat ground must render zero pixels; a camera under the ground must render zero pixels). The browser is driven over the DevTools Protocol with Node's built-in WebSocket, since master dropped Playwright. Not part of CI; screenshots land in .tmp/volume-smoke/.

The native iOS/macOS renderer still consumes build_render_volume flat columns for its instanced boxes.

Add a headless GPU smoke test for the raymarched volume
…
1cc21ab
```
`npm run test:smoke:volume` bundles the real `NexradVolumeRaymarch`
component over the shipped WASM decoder, serves it locally, and renders
it in headless Chromium on SwiftShader WebGL2 through five scenarios: a
wide view with no terrain, a flat ground at 60,000 ft (must render
nothing), a flat ground at 15,000 ft (must remove some echo), a close-in
view where an 8-texel page seam would show, and a camera under the
ground (must render nothing). Any browser console error or warning fails
the run, which is where three.js reports shader compile and link
failures. It also checks the page table and pool byte sizes against
their reported layouts and that the payload rendered at full source
resolution inside the brick budget.

The default input is a captured KMIA AVMR v5 volume under
`fixtures/mrms/` so the result is repeatable; `--live <lat>,<lon>`
fetches current weather from the runtime. The test is not part of CI or
`npm run test` because it needs a WebGL2 browser.
```
