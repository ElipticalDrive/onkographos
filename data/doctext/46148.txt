References and relevant issues
I paired for a bit with @kevinyamauchi to try to resurrect #4764. I think this
is an extremely high-value contribution and we should aim to get it in ASAP and
certainly for 0.5.0. I've been playing around with it today and it makes
working with large volumes much more pleasant. It's also a good general
framework on which we can build with other layers, including adding support
e.g. for multiscale meshes, subsampling point clouds, etc.
Description
This PR adds a change_render_quality method to the base layer, that is
do-nothing by default, but emits a render_quality event that can be listened
to. It also connects the VispyImageLayer to this event and changes the node
step_size to be larger (coarser) when the framerate drops below a desired
value, or smaller (finer) when it is very fast. Finally, when a user stops
moving the camera for long enough, it makes a final high-quality render pass.
With this combination of settings, volumes that are previously unusably choppy
render smoothly when panning and zooming the camera, then render with maximum
(or rather default) level of detail when pausing in a certain view.
There are a lot of cool improvements to make here, including UI for manually
setting automatic quality adjustment or setting a specific quality level
manually, but imho those should come in subsequent PRs.
