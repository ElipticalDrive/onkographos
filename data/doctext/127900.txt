Description
Implement the Visualization::RayCaster utility that converts 2D screen coordinates into 3D rays based on the current Camera view/projection and provides helpers for intersecting those rays with the cube volume. This enables clicking/dragging in the viewport to manipulate positions inside the trilinear‑mixer cube.
Depends on: Visualization::Camera, GLM
Requirements
File Structure
Location: Source/Visualization/
Files:
RayCaster.h
RayCaster.cpp
Class Responsibilities
Live in namespace Visualization.
Provide:
```
struct Ray
{
    glm::vec3 origin;
    glm::vec3 direction; // normalized
};

class RayCaster
{
public:
    explicit RayCaster(const Camera* camera = nullptr);

    void setCamera(const Camera* camera);

    Ray castRay(float screenX, float screenY,
                float viewportWidth,
                float viewportHeight) const;

    bool intersectCube(const Ray& ray,
                       const glm::vec3& minBounds,
                       const glm::vec3& maxBounds,
                       glm::vec3& hitPoint) const;
};
```
castRay:
Takes screen coordinates in pixel space or normalized 0..1 (implementation should be documented).
Uses the camera’s matrices to create a world‑space ray through the near plane.
intersectCube:
Computes intersection (if any) between the ray and an axis‑aligned box defined by minBounds/maxBounds.
Returns the first hit point along the ray inside the box.
Technical Specifications
Ray Casting
Use inverse view‑projection (or inverse projection + inverse view) to unproject screen coordinates.
Handle varying aspect ratios and viewport sizes correctly.
Intersection
Implement standard ray–AABB intersection (slab method).
Clamp resulting hit point to within cube bounds.
Safety
Handle missing camera pointer gracefully (debug jassert, return a default Ray).
Avoid NaNs by checking for degenerate matrices or zero viewportHeight.
Testing
Manual / Visual
Click and drag inside the cube:
Confirm the cursor marker (from Phase 6 cursor issue) follows expected paths corresponding to screen motion.
Code-Level
Add small test harnesses (or debug code) for:
Ray straight at cube center from front camera → hit near front face center.
Rays starting outside the cube but pointing away → no intersection.
