Closes #728.
Click a voxel surface in the editor and place, carve, fill or paint it. A drag is one undo step.
Picking — VoxelRaycast
Amanatides–Woo traversal over the sparse grid, entered through a slab test against the volume's world AABB.
Chunks are not a second traversal level. A cell in a missing chunk is simply empty, so a ray crosses a chunk edge without the marcher knowing one is there — no chunk marcher, no special case at the boundary, and the negative-coordinate side works for the same reason.
The hit carries the exact grid cell, the entered face normal (what a placement brush needs — zero only when the ray starts inside solid, where there is no entered face), the distance, and the world point.
Editing — VoxelEdit
Four operations (Place / Carve / Fill / Paint) over a world-space radius, addressed on the unbounded grid rather than chunk-local indices, so behaviour does not change at a 32-cell boundary.
A stroke snapshots whole chunks, not cell deltas. That is what makes undo lossless on a sparse volume: undoing an edit that created a chunk removes the chunk again rather than leaving an empty allocation behind. Only chunks whose cells actually changed are kept, so the snapshot stays proportional to the edit.
Remesh
VoxelOverride grows unbounded-grid accessors that mark the owning chunk — and any existing neighbour across a shared face — dirty, so an edit rebuilds a ring around itself instead of the volume.
Both meshers now prune meshes for chunks that no longer exist. This is the non-obvious half: an undo that deletes a chunk leaves no dirty flag to drive a rebuild from. The chunk simply stops existing, nothing in the dirty-chunk path can mention it again, and without the prune its quads keep drawing forever — the undone stroke stays on screen while every CPU assertion still passes.
Editor
New Voxel mode in the Terrain Editor panel (operation, radius, material). EditorLayer transforms the mouse ray into each voxel terrain's local space before traversal, so a moved or scaled terrain picks correctly. The stroke accumulates across frames and pushes one VoxelEditCommand on release.
Verification
5 CPU contracts — chunk-boundary hit and entered face, negative grid coordinates mapping to the right chunk, exact multi-chunk undo/redo, dirty-region scope, material serialization round-trip.
1 GL-attached integration test driving the real VoxelGreedyMeshBuilder across an edit/undo cycle. Verified to fail when the prune is removed (undo deleted chunk (1,0,0) but its mesh is still being drawn) rather than merely passing alongside it. Skips cleanly with no GL 4.6 context.
Full suite: 6741 run, 6715 passed, 26 skipped, 0 failed.
Editor boots clean — all shaders compile, scene deserializes 18/18 entities, no errors in OloEngine.log.
The brush gesture itself is not machine-verifiable here (there is no way to drive a viewport click-drag headlessly), so the editor check is a boot/render smoke test; the picking and editing logic underneath it is covered by the contracts above.
Also in this branch
One unrelated commit: the PreToolUse build-lock hook resolved its guard script by a bare relative path, so any cd into a subdirectory made it unresolvable — and since it gates every shell call, it then blocked the cd back out, wedging the shell for the rest of the session. Now resolved against $CLAUDE_PROJECT_DIR with the old path as fallback. Happy to split it out if you'd rather.

```
The PreToolUse hook invoked .claude/hooks/claude-build-lock-guard.py by a
bare relative path, so it only worked while the agent's shell happened to
sit at the repo root. A single `cd` into any subdirectory made the guard
unresolvable; the hook then exited non-zero, and because it gates every
Bash and PowerShell call it blocked the `cd` back out as well. The shell
was wedged for the rest of the session with no in-band way to recover.

Resolve it against $CLAUDE_PROJECT_DIR instead, which Claude Code sets for
hook execution, falling back to the old relative path so behaviour is
unchanged where the variable is absent.
```

fix(terrain): guard voxel picking against degenerate terrain transforms
…
618ccd0
```
Review follow-ups on the voxel DDA editing path.

A TerrainComponent whose transform has a zero on any scale axis -- one
click away in the inspector -- inverts to a matrix of inf/NaN, and the
existing magnitude guard cannot catch it: `NaN <= 1e-8f` is FALSE, the
same trap VoxelOverride::Initialize documents. The poisoned ray reached
the DDA, where flooring NaN to an i32 cell index is UB. Both transformed
ray components are now finite-checked before the magnitude test.

SetVoxel resolved the chunk coordinate twice, the three local indices six
times and the owning chunk through two hash lookups per cell; a brush runs
it once per cell across its whole radius. The per-cell work is now done
once and the neighbour-dirty walk split into a private helper that the
public MarkVoxelAndNeighboursDirty still drives, so that entry point's
behaviour is unchanged.

Also: drop the unreachable Voxel branch in OnUpdate (EditorLayer routes
Voxel mode to OnVoxelUpdate, which is the sole commit path -- the state
resets below it still run); document that stroke accumulation is
deliberately not gated on m_CommandHistory; and correct the RLE format
comments from 'VXO1' to 'VOX1', which is what the unchanged magic
0x31584F56 actually emits little-endian.

Full suite: 6742 run, 6718 passed, 24 skipped, 0 failed.
```
