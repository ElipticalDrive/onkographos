# XPBD Simulation Loop

Also called: Extended Position-Based Dynamics, Position-Based Dynamics (PBD) / Extended PBD (XPBD)

## Overview
The XPBD simulation loop is a numerical integration method that treats a dynamic system as a set of $N$ vertices and $M$ constraints, converting variational energy minimization into sequential constraint projections [S1]. It distinguishes itself from standard Position-Based Dynamics (PBD) by introducing a compliance matrix $\alpha$, allowing constraints to be satisfied with variable stiffness rather than binary hard constraints, which enables stable simulation of fluids, rigid bodies, and hyperelastic objects [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** Current particle positions $x_n$, velocities $v_n$, external forces $f_{ext}(x)_n$, time step $\Delta t$, lumped mass matrix $M$, constraint vector $C(x)$, compliance matrix $\alpha$, and solver iteration count `solverIterations` [S1].
*   **Outputs:** Updated positions $x_{n+1}$ and velocities $v_{n+1}$ [S1].

**Data Structures**
*   **Positions ($x$):** Vector of size $N$ (or $3N$ for 3D vertices) [S1].
*   **Velocities ($v$):** Vector of size $N$ (or $3N$) [S1].
*   **Mass Matrix ($M$):** Diagonal matrix of size $N \times N$ representing lumped masses [S1].
*   **Constraints ($C$):** Vector of size $M$ where each element $C_j(x)$ is a scalar constraint value [S1].
*   **Compliance ($\alpha$):** Diagonal matrix of size $M \times M$ where $\alpha_j$ is the compliance for the $j$-th constraint (inverse of stiffness) [S1].
*   **Multipliers ($\lambda$):** Vector of size $M$ storing constraint force multipliers [S1].

**Numbered Steps**
1.  **Predict Position:** Compute the unconstrained predicted position $\tilde{x}$ using explicit integration with external forces [S1].
    $$ \tilde{x} \leftarrow x_n + \Delta t v_n + \Delta t^2 M^{-1} f_{ext}(x)_n $$
2.  **Initialize Solve Variables:** Set the current position estimate $x_0$ to the predicted position $\tilde{x}$ and initialize multipliers $\lambda_0$ to zero [S1].
    $$ x_0 \leftarrow \tilde{x} $$
    $$ \lambda_0 \leftarrow 0 $$
3.  **Iterative Constraint Projection:** Repeat for `solverIterations` times (index $i$ from 0 to `solverIterations` - 1):
    a.  **Compute Multiplier Update ($\Delta \lambda$):** For each constraint $j$, compute the update $\Delta \lambda_j$ using a Gauss-Seidel-like scheme [S1].
        $$ \Delta \lambda_j \leftarrow \frac{-\Delta t^2 C_j(x_i) - \alpha_j}{\Delta t^2 \nabla C_j(x_i) M^{-1} \nabla C_j(x_i)^\top + \alpha_j} $$
        Here, $\nabla C_j(x_i)$ is the gradient of the $j$-th constraint with respect to particle positions at $x_i$ [S1].
    b.  **Compute Position Update ($\Delta x$):** Update the primal variable (positions) based on the multiplier update [S1].
        $$ \Delta x \leftarrow M^{-1} \nabla C(x_i)^\top \Delta \lambda $$
        This sums the contributions of all constraints to each particle's position [S1].
    c.  **Update State:** Update the multipliers and positions for the next iteration step [S1].
        $$ \lambda_{i+1} \leftarrow \lambda_i + \Delta \lambda $$
        $$ x_{i+1} \leftarrow x_i + \Delta x $$
4.  **Finalize Step:** Update the system state for the next time step [S1].
    $$ x_{n+1} \leftarrow x_{\text{solverIterations}} $$
    $$ v_{n+1} \leftarrow \frac{x_{n+1} - x_n}{\Delta t} $$

**Formulas**
*   **System Potential Energy:**
    $$ U = \frac{1}{2} C(x)^\top \alpha^{-1} C(x) $$
    where $C(x)$ is the constraint vector and $\alpha$ is the compliance matrix [S1].
*   **Constraint Force Multiplier Update (General Form):**
    $$ \left[ \frac{2}{\Delta t^2} \nabla C(x) M^{-1} \nabla C^\top(x) + \alpha \right] \Delta \lambda = -\frac{2}{\Delta t^2} C(x) - \alpha \lambda $$
    The source text contains a factor of 2 in this general matrix form but a factor of 1 in the scalar Gauss-Seidel update used in the algorithm loop [S1].
*   **Primal Variable Update:**
    $$ \Delta x = M^{-1} \nabla C(x)^\top \Delta \lambda $$
*   **Scalar Multiplier Update (Gauss-Seidel):**
    $$ \Delta \lambda_j \leftarrow \frac{-\Delta t^2 C_j(x) - \alpha_j}{\Delta t^2 \nabla C_j M^{-1} \nabla C_j^\top + \alpha_j} $$
    where $\nabla C_j M^{-1} \nabla C_j^\top$ is computed using the lumped mass matrix $M$ and constraint gradients [S1].

**Parameters**
*   `solverIterations`: Number of iterations for the XPBD solver. Set to 10 for fluids and 50 for solids [S1].
*   $\Delta t$: Simulation time step size. Set to 0.005 seconds [S1].

**Edge Cases and Pitfalls**
*   **Singularity:** If $\alpha_j$ is zero (infinite stiffness), the denominator becomes $\Delta t^2 \nabla C_j M^{-1} \nabla C_j^\top$ [S1].
*   **Precision:** The term $\Delta t^2 \nabla C_j M^{-1} \nabla C_j^\top$ depends on mass and time step, affecting numerical stability [S1].
*   **Boundary Conditions:** The method assumes particles are free unless constrained; boundary constraints must be explicitly defined in $C(x)$ and $\alpha$ [G].

**Pseudocode**
```python
def xpbd_simulation_loop(x_n, v_n, f_ext, dt, masses, constraints, alphas, solver_iterations):
    # x_n: list of positions (N,)
    # v_n: list of velocities (N,)
    # f_ext: list of external forces (N,)
    # dt: float
    # masses: list of scalar masses (N,)
    # constraints: list of constraint objects with evaluate(x) and gradient(x) methods
    # alphas: list of compliance values (M,)
    # solver_iterations: int
    N = len(x_n)
    M = len(constraints)
    
    # Step 1: Predict Position
    x_pred = [x_n[k] + dt * v_n[k] + dt**2 * f_ext[k] / masses[k] for k in range(N)]
    
    # Step 2: Initialize Solve Variables
    x_curr = list(x_pred)
    lambda_curr = [0.0] * M
    
    # Step 3: Iterative Constraint Projection
    for i in range(solver_iterations):
        delta_lambda = [0.0] * M
        delta_x = [0.0] * N
        
        # Compute delta_lambda for each constraint
        for j in range(M):
            C_j = constraints[j].evaluate(x_curr)
            grad_C_j = constraints[j].gradient(x_curr) # list of gradients per particle
            
            # Compute denominator term: grad_C_j^T * M_inv * grad_C_j
            # Sum over particles k: (1/m_k) * |grad_C_j_k|^2
            denom_term = sum((g**2) / masses[k] for k, g in enumerate(grad_C_j))
            
            # Numerator: -dt^2 * C_j - alpha_j
            numerator = - (dt ** 2) * C_j - alphas[j]
            denominator = (dt ** 2) * denom_term + alphas[j]
            
            delta_lambda[j] = numerator / denominator
        
        # Compute delta_x
        # delta_x = M_inv * sum_j (delta_lambda_j * grad_C_j)
        for k in range(N):
            sum_grad = 0.0
            for j in range(M):
                sum_grad += delta_lambda[j] * constraints[j].gradient(x_curr)[k]
            delta_x[k] = sum_grad / masses[k]
        
        # Update State
        for k in range(N):
            x_curr[k] += delta_x[k]
        for j in range(M):
            lambda_curr[j] += delta_lambda[j]
            
    # Step 4: Finalize Step
    x_n_plus_1 = x_curr
    v_n_plus_1 = [(x_n_plus_1[k] - x_n[k]) / dt for k in range(N)]
    
    return x_n_plus_1, v_n_plus_1
```

## Subtopics

### [Position Based Fluids](1765-position-based-fluids.md)
A particle-based fluid simulation method that enforces incompressibility by correcting particle positions based on density constraints, allowing real-time simulation without meshing. It uses XPBD as its underlying solver.

### [Position Based Dynamics](1764-position-based-dynamics.md)
The foundational method that XPBD extends. PBD uses hard constraints (zero compliance) for immediate satisfaction, while XPBD uses compliance for smoother, more physically accurate behavior.

## Operating characteristics
*   **Strengths:** The method provides an easy and efficient simulation modality, supports parallelization via a Gauss-Seidel-like scheme, and is versatile across fluids, rigid bodies, and hyperelastic objects [S1].
*   **Limitations:** Not given in the sources.

## Background
XPBD was introduced as an extension of Position-Based Dynamics (PBD) to address the limitations of hard constraints in PBD, such as instability and lack of tunable stiffness [S1]. It converts the variational optimization problem of minimizing system potential energy into a series of constraint projections, making it computationally efficient and suitable for real-time applications [S1]. The method was notably used in the "Gaussian Splashing" framework for unified particle motion synthesis and rendering [S1].
