# Mass-Spring System Simulation
Also called: Mass-Spring Deformation, Mass-Spring System, Physically-based Simulation via Mass-Spring System
## Overview
A deformation method where a coarse tetrahedral mesh serves as a geometric proxy for simulation, configured as a mass-spring system to balance computational efficiency with accurate representation of complex deformations [S1].
## How it works
**Inputs and Outputs:**
- Input: A coarse tetrahedral mesh defining the geometry.
- Output: Deformed vertex positions satisfying physical constraints.

**Data Structures:**
- **Mesh:** A collection of vertices and edges. Each vertex acts as a mass point [S1]. Each edge acts as a spring connecting two mass points [S1].
- **Constraints:**
  1. **Spring Length Constraint:** Maintains the invariance of the distance between connected vertices [S1].
  2. **Tetrahedral Volume Constraint:** Maintains the invariance of the volume of each tetrahedron formed by four connected vertices [S1].

**Steps:**
1. **Configuration:** Configure each vertex of the coarse tetrahedral mesh as a mass point [S1].
2. **Physics Implementation:** Implement the XPBD simulation loop using the Taichi programming language to simulate the physics of the mass-spring system [S1].
3. **Constraint Enforcement:**
   - Enforce spring length constraints to maintain the invariance of spring length between connected vertices [S1].
   - Enforce tetrahedral volume constraints to maintain the invariance of the volume of the tetrahedra [S1].

**Parameters:**
- Not given in the sources.

**Edge Cases and Pitfalls:**
- The method may suffer from ill-shaped tetrahedra within the mesh, which can lead to artifacts in accumulation maps or density predictions [S1].

```python
def distance(p1, p2):
    return math.sqrt(sum((a-b)**2 for a, b in zip(p1, p2)))

def compute_tetrahedron_volume(p1, p2, p3, p4):
    v1 = [p2[i]-p1[i] for i in range(3)]
    v2 = [p3[i]-p1[i] for i in range(3)]
    v3 = [p4[i]-p1[i] for i in range(3)]
    cross = cross_product(v2, v3)
    dot = sum(a*b for a, b in zip(v1, cross))
    return math.fabs(dot) / 6.0

def cross_product(v1, v2):
    return [
        v1[1]*v2[2] - v1[2]*v2[1],
        v1[2]*v2[0] - v1[0]*v2[2],
        v1[0]*v2[1] - v1[1]*v2[0]
    ]

def enforce_length_constraint(v1, v2, rest_length):
    # Standard XPBD projection for length constraint [G]
    diff = [v1.position[i] - v2.position[i] for i in range(3)]
    current_len = distance(v1.position, v2.position)
    if current_len == 0: return
    grad1 = [d / current_len for d in diff]
    grad2 = [-d / current_len for d in diff]
    mass_sum = v1.mass + v2.mass
    if mass_sum == 0: return
    correction = (current_len - rest_length) / mass_sum
    v1.position = [v1.position[i] - correction * grad1[i] for i in range(3)]
    v2.position = [v2.position[i] - correction * grad2[i] for i in range(3)]

def enforce_volume_constraint(v1, v2, v3, v4, rest_volume):
    # Standard XPBD projection for volume constraint [G]
    p1, p2, p3, p4 = v1.position, v2.position, v3.position, v4.position
    v12 = [p2[i]-p1[i] for i in range(3)]
    v13 = [p3[i]-p1[i] for i in range(3)]
    v14 = [p4[i]-p1[i] for i in range(3)]
    cross13_14 = cross_product(v13, v14)
    cross12_14 = cross_product(v12, v14)
    cross12_13 = cross_product(v12, v13)
    grad1 = [-cross13_14[i] for i in range(3)]
    grad2 = [cross13_14[i] - cross12_14[i] for i in range(3)]
    grad3 = [cross12_14[i] - cross12_13[i] for i in range(3)]
    grad4 = [cross12_13[i] for i in range(3)]
    mass_sum = v1.mass + v2.mass + v3.mass + v4.mass
    if mass_sum == 0: return
    current_vol = compute_tetrahedron_volume(p1, p2, p3, p4)
    correction = (current_vol - rest_volume) / mass_sum
    v1.position = [v1.position[i] - correction * grad1[i] for i in range(3)]
    v2.position = [v2.position[i] - correction * grad2[i] for i in range(3)]
    v3.position = [v3.position[i] - correction * grad3[i] for i in range(3)]
    v4.position = [v4.position[i] - correction * grad4[i] for i in range(3)]
```
## Subtopics

### [FEM-based Force Computation](21395-fem-based-force-computation.md)
FEM-based Force Computation is a deformation method that computes internal forces on a tetrahedral mesh using Finite Element Method principles, chosen over mass-spring systems to provide a more precise representation of triangles by accounting for all surface contributions. It sets itself apart from its parent [Mass-Spring System Simulation](21252-mass-spring-system-simulation.md) by utilizing element stiffness matrices and local frame rotations rather than simple spring constants between nodes, resulting in physically more plausible deformation forces.

## Operating characteristics
**Time and Memory Complexity:**
- The method uses a coarse tetrahedral mesh to reduce computational overhead [S1].
- Memory usage varies by scene complexity. For example, mesh storage size ranged from 248.88 KB to 110.85 MB, with single-stage memory usage between 9.79 GB and 12.01 GB [S1].

**Measured Performance:**
- The method exhibits fewer artifacts in accumulation maps compared to methods suffering from ill-shaped tetrahedra, suggesting more precise prediction and depiction of densities [S1].

**Strengths and Limitations:**
- Strengths: Balance between computational efficiency and ability to accurately represent complex deformations; reduced computational overhead [S1].
- Limitations: Ill-shaped tetrahedra can lead to artifacts in accumulation maps [S1].

**When to Use:**
- Use when a balance between computational efficiency and deformation accuracy is required, and when the mesh quality is sufficient to avoid ill-shaped tetrahedra [S1].
