# Massless Particle System

Also called: Drag-Dominated Particle System, Massless Particle Tracing, Particle-Based Smoke Visualization

## Overview
The Massless Particle System visualizes flow fields by tracking tracer particles that move through a simulation domain influenced by an underlying velocity field [S1, unofficial]. It solves the problem of representing continuous fluid motion with discrete elements, assuming the drag force on the particle is large compared to gravity [S1, unofficial]. It is distinguished from its siblings, such as [Position Based Fluids](1765-position-based-fluids.md), by its reliance on kinematic advection via a pre-computed velocity field rather than solving coupled fluid dynamics equations for particle interactions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A velocity field $V(x, t)$ computed by a solver (e.g., FDS) [S1, unofficial].
*   **Output:** Particle positions $x_p(t)$ and optionally streak lines representing trajectory history [S1, unofficial].

**Data Structures:**
*   **Particle State:** A position vector $x_p$ and a timestamp or streak history buffer [S1, unofficial].
*   **Velocity Field:** A discrete grid or analytic function providing $V(x, t)$ [S1, unofficial].

**Parameters:**
*   **Particle Size:** Specified as a floating-point value `partpointsize` [S1, unofficial].
*   **Streak Length:** Specified as a time duration (seconds before current display time) [S1, unofficial].
*   **Note:** These parameters are typically configured via interface dialogs (e.g., File/Bounds) [S1, unofficial].

**Method Steps:**
1.  **Initialization:** Place particles at initial positions $x_p(0)$ within the domain [S1, unofficial].
2.  **Integration:** Update particle position using the differential equation:
    $$ \frac{dx_p}{dt} = V(x_p, t) $$
    where $x_p$ is the particle position and $V$ is the velocity at that position and time [S1, unofficial].
3.  **Rendering:** Render particles as points with size `partpointsize` or as streak lines extending back in time by the specified streak length [S1, unofficial].

**Pseudocode:**
```python
def update_massless_particles(particles, velocity_field, dt):
    """
    Update particle positions based on the massless particle assumption.
    
    Args:
        particles: List of particle objects, each with attribute 'pos' (vector).
        velocity_field: Function or grid lookup returning velocity vector V(x, t).
        dt: Time step size.
        
    Returns:
        Updated particles list.
    """
    for particle in particles:
        # Get velocity at current particle position
        # Note: velocity_field must handle interpolation if grid-based
        v = velocity_field(particle.pos)
        
        # Integrate position using Euler method (standard for this model)
        # dxp/dt = V(xp, t)
        particle.pos = particle.pos + v * dt
        
    return particles

def render_particles(particles, partpointsize, streak_length_seconds):
    """
    Render particles as points or streaks.
    
    Args:
        particles: List of particle objects with 'pos' and potentially 'history'.
        partpointsize: Floating point size for glPointSize.
        streak_length_seconds: Duration of streak line in seconds.
    """
    # Set point size for rendering
    glPointSize(partpointsize)
    
    for particle in particles:
        # Render current position
        render_point(particle.pos)
        
        # If streaks are enabled, render history
        if streak_length_seconds > 0:
            # Retrieve history of positions from 'streak_length_seconds' ago to now
            # This requires storing position history during update
            history = get_particle_history(particle, streak_length_seconds)
            if history:
                render_streak_line(history)
```

**Edge Cases and Pitfalls:**
*   **Gravity Assumption:** The model assumes drag force is large compared to gravity ($mg$) [S1, unofficial]. If gravity is significant, this model is inaccurate [S1, unofficial].
*   **Static Images:** Static particle images do not effectively display motion; streak lines are preferred for visualizing curved motion due to obstructions [S1, unofficial].
*   **Precision:** The accuracy of individual particle motion is less critical than the statistical behavior of the ensemble, allowing for simpler integration methods [S2].

## Subtopics

### Hotaru
A visualization method where thousands of tracer particles are randomly scattered in the whole simulation data space to show statistical behavior [S2]. It is distinguished by its focus on statistical representation rather than precise trajectory accuracy, using the 1st order Euler method for numerical integration [S2]. Choose this when the goal is to visualize the general flow pattern or statistical behavior of a vector field rather than individual particle paths [S2].

### [Particle Motion with Thermal Buoyancy and Diffusion](14660-particle-motion-with-thermal-buoyancy-and-diffusion.md)
This method defines the kinematic trajectory of massless particles in volumetric fire simulation by combining wind advection, thermal buoyancy, source movement, and diffusion [14660-particle-motion-with-thermal-buoyancy-and-diffusion.md]. It solves the problem of realistic macro-scale flame motion by treating particles as tracer elements subject to specific physical forces, building on the [Massless Particle System](3970-massless-particle-system.md) framework [14660-particle-motion-with-thermal-buoyancy-and-diffusion.md]. It is distinguished from pure fluid solvers by its reliance on simplified Navier-Stokes approximations for wind and explicit algebraic formulas for buoyancy, prioritizing real-time performance over strict physical fidelity [14660-particle-motion-with-thermal-buoyancy-and-diffusion.md].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of particles $N_p$ and the cost of velocity field lookup/interpolation $O(V)$: $O(N_p \cdot V)$ per time step [S1, unofficial].
*   **Memory Complexity:** $O(N_p)$ to store particle positions and histories [S1, unofficial].
*   **Strengths:** Computationally inexpensive; effective for visualizing flow patterns and obstructions via streak lines [S1, unofficial].
*   **Limitations:** Does not model particle inertia or gravity accurately; relies on an external velocity field [S1, unofficial].
*   **When to Use:** When visualizing smoke flow or wind patterns where drag dominates and real-time performance is needed [S1, unofficial].
*   **When Not to Use:** When particle inertia, gravity, or complex particle-particle interactions are significant [S1, unofficial].

## Background
The method was implemented in Smokeview (Version 6) for visualizing Fire Dynamics Simulation (FDS) data [S1, unofficial]. It was the first method implemented in Smokeview for visualizing smoke flow and was inspired by the software tool named Frames written by James Sims [S1, unofficial]. The approach uses particles as tracer elements to allow visualization of flow, distinct from droplets used for fire suppression modeling or fuel elements like embers [S1, unofficial].
