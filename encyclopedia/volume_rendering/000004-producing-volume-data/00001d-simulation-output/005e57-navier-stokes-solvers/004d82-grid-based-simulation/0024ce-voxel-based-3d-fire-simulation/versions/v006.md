# Voxel-based 3D Fire Simulation

Also called: 3D Texture Fire Simulation, Navier-Stokes Fire Simulation

## Overview
This method simulates fire and smoke by solving the Navier-Stokes equations on a 3D voxelized grid to compute velocity, smoke density, temperature, and fuel level [S1, unofficial]. It differs from particle-based fire by maintaining a continuous volumetric field, allowing for realistic interaction between smoke, heat, and fuel, and enabling direct volume rendering of the resulting 3D textures [S1, unofficial]. It builds on [Grid-Based Simulation](13502-grid-based-simulation.md).

## How it works
**Inputs:**
- Simulation domain dimensions (e.g., $128 \times 128 \times 128$ voxels) [S1, unofficial].
- Physical constants: $P$ (pressure constant), $m$ (molecular mass), $g$ (gravity), $R$ (gas constant), $T_0$ (reference temperature) [S1, unofficial].
- Simulation parameters: time step $\delta t$, vorticity confinement strength $\epsilon$, grid spacing $\delta x$ [S1, unofficial].

**Outputs:**
- Four 3D textures (or equivalent 3D arrays) storing per-voxel values:
  1. Velocity vector $\mathbf{u}$ [S1, unofficial].
  2. Pressure scalar $p$ [S1, unofficial].
  3. Temperature scalar $T$ [S1, unofficial].
  4. Fuel level scalar [S1, unofficial].
  - Smoke density is also tracked as a per-voxel attribute [S1, unofficial].

**Data Structures:**
- The spatial domain is discretized into a 3D grid of voxels [S1, unofficial].
- Each voxel stores scalar or vector attributes in contiguous memory, mapped to 3D textures for GPU access [S1, unofficial].
- GPU implementation uses blocks of size $16 \times 16 \times 16$ with 512 threads per block [S1, unofficial].

**Formulas:**
The core dynamics are governed by the Navier-Stokes equation for fluid dynamics [S1, unofficial]:
$$
\frac{\partial u}{\partial t} = -(u \cdot \nabla) u - \frac{1}{\rho} \nabla p + f
$$
Where:
- $u$ is the velocity [S1, unofficial].
- $p$ is the pressure [S1, unofficial].
- $\rho$ is the density of the molecule mass [S1, unofficial].
- $f$ is the external force on molecules [S1, unofficial].
- The first term represents advection, which transports quantities along the flow [S1, unofficial].
- The source describes the parenthetical term as divergence, representing the rate at which density exits the region [S1, unofficial].
- The second term simulates how pressure gathers and generates force, providing accelerations to surrounding molecules [S1, unofficial].

The external force $f$ consists of buoyancy and vorticity confinement [S1, unofficial]:
1. **Buoyancy Force:**
   $$
   f_{buoyancy} = \frac{Pmg}{R} \left(\frac{1}{T_0} - \frac{1}{T}\right)z
   $$
   Where $T$ is the current temperature, $T_0$ is the reference temperature, and $z$ is the vertical direction [S1, unofficial]. Higher temperatures result in larger upward velocity [S1, unofficial].
2. **Vorticity Confinement Force:**
   $$
   f_{vc} = \epsilon(\Psi \times \omega)\delta x
   $$
   Where $\epsilon$ is a scaling factor, $\delta x$ is grid spacing, and $\omega$ is vorticity [S1, unofficial].
   - $\Psi$ is the normalized gradient of the vorticity magnitude: $\Psi = \frac{\eta}{|\eta|}$ [S1, unofficial].
   - $\eta$ is the gradient of the magnitude of vorticity: $\eta = \nabla |\omega|$ [S1, unofficial].
   This force restores curling behavior lost due to the discrete nature of the simulation [S1, unofficial].

**Algorithm Steps:**
1. Initialize the 3D textures for velocity, pressure, temperature, fuel level, and smoke density [S1, unofficial].
2. For each time step:
   a. Compute advection and divergence based on interaction between neighboring voxels [S1, unofficial].
   b. Calculate external forces: buoyancy from temperature/density differences, and vorticity confinement to restore curling behavior [S1, unofficial].
   c. Propagate changes in temperature, pressure, and velocity correspondingly [S1, unofficial].
   d. Update values in each 3D texture [S1, unofficial].
3. Render by injecting a shader into the post-processing stage of the main camera to ray march the 3D textures [S1, unofficial].

**Pseudocode:**
```python
def simulate_fire(grid_shape, dt, epsilon, dx, rho, P, m, g, R, T0):
    # Initialize 3D textures/arrays
    u = zeros(grid_shape, 3)
    p = zeros(grid_shape)
    T = zeros(grid_shape)
    fuel = zeros(grid_shape)
    smoke = zeros(grid_shape)
    z_vec = array([0, 1, 0])
    
    while simulation_running:
        # 1. Compute vorticity and confinement force
        omega = curl(u)
        eta = gradient(magnitude(omega))
        Psi = eta / magnitude(eta)
        f_vc = epsilon * cross(Psi, omega) * dx
        
        # 2. Compute buoyancy force
        f_buoy = (P * m * g / R) * (1.0 / T0 - 1.0 / T) * z_vec
        
        # 3. Total external force
        f = f_buoy + f_vc
        
        # 4. Compute advection and divergence from neighboring voxels
        adv_u = dot(u, gradient(u))
        div_u = divergence(u)
        
        # 5. Propagate changes (Navier-Stokes update)
        u = u - dt * (adv_u + (1.0 / rho) * gradient(p)) + dt * f
        
        # 6. Propagate scalars via advection
        T = T - dt * dot(u, gradient(T))
        fuel = fuel - dt * dot(u, gradient(fuel))
        smoke = smoke - dt * dot(u, gradient(smoke))
        
        # 7. Solve pressure projection (standard step implied by divergence handling)
        # [G] Solve Poisson equation: laplacian(p) = rho * divergence(u) / dt
        p = solve_pressure_poisson(div_u, rho, dt)
        
        # 8. Update 3D textures
        update_texture(u)
        update_texture(p)
        update_texture(T)
        update_texture(fuel)
        update_texture(smoke)
```

**Pitfalls:**
- **HLSL Global Variables:** Global variables in HLSL compute shaders cannot be assigned within the shader file using an assignment operator during declaration; this results in zero values without a syntax error [S1, unofficial].
  - *Solution:* Manually assign these variables in the host driver script (e.g., C#) before each invocation of the compute kernels [S1, unofficial].
- **Debugging:** HLSL shaders lack print debugging capabilities [S1, unofficial]. Use debug shaders that fill 3D textures when values pass thresholds, or external tools like RenderDoc [S1, unofficial]. Cross-validate formulas with a Python script [S1, unofficial].

## Subtopics

### Stam and Fiume Fire Animation
A variant that applies the diffusion method to the animation of fire and other gaseous phenomena [S2]. It is noted for handling complex scenes, though progressive energy shooting can be expensive, potentially requiring a hierarchical approach [S2].

## Operating characteristics
- **Performance:** Achieved real-time performance (60+ fps) on an NVIDIA RTX 2060 graphics card [S1, unofficial].
- **Resolution:** Tested with a voxel grid size of $128 \times 128 \times 128$ [S1, unofficial].
- **Parallelism:** Uses GPU blocks of $16 \times 16 \times 16$ with 512 threads per block [S1, unofficial].
- **Strengths:** Realistic interaction between smoke, heat, and fuel; continuous volumetric representation suitable for volume rendering [S1, unofficial].
- **Limitations:** Debugging is difficult due to lack of print support in shaders [S1, unofficial]. Performance scales with grid resolution and may require hierarchical approaches for very complex scenes [S2].

## Background
This method is based on the Navier-Stokes equations for fluid dynamics [S1, unofficial]. It was implemented and demonstrated in a project reported on GitHub Pages, achieving real-time results on consumer hardware [S1, unofficial]. The diffusion method for fire animation was previously applied by Stam and Fiume [S2].
