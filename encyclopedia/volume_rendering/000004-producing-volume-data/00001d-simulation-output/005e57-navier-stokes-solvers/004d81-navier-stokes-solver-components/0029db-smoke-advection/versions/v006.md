# Smoke Advection
Also called: Tracking additional quantities like density and temperature, MacCormack routine for smoke

## Overview
Smoke advection tracks scalar fields (density, temperature, color) that are transported by the fluid velocity field to visualize the fluid's motion, as the velocity field alone lacks visual detail [S1, unofficial]. It differs from velocity advection by solving the passive scalar transport equation $\frac{\partial \phi}{\partial t} = -(\mathbf{u} \cdot \nabla) \phi$ using the same numerical scheme as the velocity, allowing low-resolution grids to retain visual detail [S1, unofficial]. Unlike the unconditionally stable semi-Lagrangian scheme, the MacCormack scheme used here is conditionally stable and requires a limiter to prevent numerical blow-up [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Velocity field $\mathbf{u}$, previous scalar field $\phi^n$, time step $dt$, grid dimensions.
- Output: Updated scalar field $\phi^{n+1}$.

**Data Structures:**
- For each additional quantity $\phi$ (density, temperature, color), allocate a texture/grid with the same dimensions as the velocity grid [S1, unofficial].
- The scalar field $\phi$ stores values at cell centers (collocated) or staggered positions depending on the specific solver implementation, but is advected using the velocity field $\mathbf{u}$ [S1, unofficial].

**Steps:**
1. **Source Injection:** Inject a 3D Gaussian "splat" into the color or density texture each frame to provide a source of smoke [S1, unofficial].
2. **Advection:** Advect the scalar field $\phi$ using the MacCormack advection scheme driven by the velocity field $\mathbf{u}$ [S1, unofficial]. The evolution is governed by:
   $$ \frac{\partial \phi}{\partial t} = -(\mathbf{u} \cdot \nabla) \phi $$
3. **Buoyancy (Optional):** If temperature $T$ is tracked, compute buoyant force to influence velocity dynamics, making hot smoke rise and cool smoke fall [S1, unofficial].

**Pseudocode:**
```python
def advect_smoke(phi, u, dt, grid_size, limiter_threshold=1.0):
    """
    Advect scalar field phi using MacCormack scheme with velocity u.
    phi: 3D array of scalar values (density/temperature/color)
    u: 3D vector field (velocity)
    dt: time step
    grid_size: (nx, ny, nz)
    limiter_threshold: threshold for slope limiter to prevent blow-up
    """
    # Predictor step: Forward differencing
    phi_pred = predictor_step(phi, u, dt, grid_size)
    
    # Corrector step: Backward differencing using predicted values
    phi_corr = corrector_step(phi, phi_pred, u, dt, grid_size)
    
    # Apply limiter to prevent numerical blow-up (conditional stability)
    phi_new = apply_limiter(phi, phi_corr, limiter_threshold)
    
    return phi_new

def predictor_step(phi, u, dt, grid_size):
    """
    Calculate temporary predicted value using forward differencing.
    """
    phi_pred = copy(phi)
    # Advect forward: phi(x - u*dt)
    # In practice, trace back from x to x - u*dt and sample phi
    for each cell (i, j, k):
        trace_back = (i, j, k) - u[i, j, k] * dt
        phi_pred[i, j, k] = interpolate(phi, trace_back)
    return phi_pred

def corrector_step(phi, phi_pred, u, dt, grid_size):
    """
    Determine final corrected value using backward differencing.
    Alternates direction to avoid bias and achieve second-order accuracy.
    """
    phi_corr = copy(phi)
    # Advect backward: phi(x + u*dt)
    # Use phi_pred for the intermediate state
    for each cell (i, j, k):
        trace_back = (i, j, k) + u[i, j, k] * dt
        phi_corr[i, j, k] = 0.5 * (phi[i, j, k] + interpolate(phi_pred, trace_back))
    return phi_corr

def apply_limiter(phi, phi_corr, threshold):
    """
    Apply slope limiter to prevent numerical blow-up.
    """
    phi_new = copy(phi)
    for each cell (i, j, k):
        slope = calculate_slope(phi, i, j, k)
        if abs(slope) > threshold:
            phi_new[i, j, k] = clamp(phi_corr[i, j, k], phi[i, j, k] - threshold, phi[i, j, k] + threshold)
        else:
            phi_new[i, j, k] = phi_corr[i, j, k]
    return phi_new
```

**Parameters:**
- $dt$: Time step. Must satisfy CFL condition for stability [S1, unofficial].
- Limiter threshold: Prevents numerical blow-up in the MacCormack scheme [S1, unofficial].

**Edge Cases and Pitfalls:**
- The MacCormack scheme is conditionally stable; without a limiter, it can blow up [S1, unofficial].
- Color values have no physical significance but create attractive swirling patterns [S1, unofficial].
- Temperature values influence dynamics via buoyant force [S1, unofficial].

## Subtopics

### [MacCormack Advection Scheme](4952-maccormack-advection-scheme.md)
The MacCormack advection scheme is a higher-order numerical method used to advect scalar fields (such as smoke density or temperature) and vector fields (velocity) in fluid simulations, designed to reduce the numerical smoothing inherent in standard semi-Lagrangian advection. It achieves this by combining a forward semi-Lagrangian step with a backward correction step, allowing low-resolution grids to retain visual detail comparable to significantly higher-resolution grids using standard first-order methods. Unlike the unconditionally stable semi-Lagrangian scheme, the MacCormack scheme is conditionally stable and requires a limiter to prevent numerical blow-up.

### Parallel Navier-Stokes Solver (MacCormack Method)
An explicit, two-step, three-time level scheme used to solve unsteady compressible Navier-Stokes equations, second-order accurate in both time and space, chosen for ease of parallelization [S2, unofficial].
- **Steps:**
  1. Predictor step: Calculate a temporary 'predicted' value using forward differencing.
  2. Corrector step: Determine the final 'corrected' value using backward differencing.
  3. Alternate forward and backward differencing between predictor and corrector steps to avoid bias and achieve second-order accuracy [S2, unofficial].
  4. Subdivide data domain into blocks.
  5. At each time level, exchange solution values at the outermost boundary layers of each block between nearest neighbors after each predictor and corrector step [S2, unofficial].
  6. Application programmer writes a 'Prepare Data' routine to calculate flow properties to be visualized and store in the appropriate format for rendering [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the advection scheme. MacCormack is second-order accurate in time and space [S2, unofficial].
- **Memory Complexity:** Requires additional texture/grid for each scalar quantity $\phi$ with the same dimensions as the velocity grid [S1, unofficial].
- **Performance:** MacCormack scheme allows low-resolution grids to retain visual detail comparable to significantly higher-resolution grids using standard first-order methods [S1, unofficial].
- **Strengths:** Easier to parallelize and implement than more sophisticated CFD codes [S2, unofficial]. Reduces numerical smoothing [S1, unofficial].
- **Limitations:** Conditionally stable, requires limiter [S1, unofficial]. Not a physical diffusion solve for DiffUpSample [S3].
