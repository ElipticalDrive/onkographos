# Smoke Advection

Also called: MacCormack routine for smoke, Tracking additional quantities like density and temperature

## Overview
Smoke advection transports scalar quantities, such as density and temperature, through a fluid velocity field to visualize smoke effects in real-time simulations [S1, unofficial]. It distinguishes itself from pure velocity advection by introducing source terms (e.g., Gaussian splats) and coupling scalar fields (like temperature) back into the dynamics via buoyant forces, rather than treating them as passive tracers alone [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Velocity field $\mathbf{u}$, current scalar field $\phi$ (density or temperature), time step $\Delta t$, and source injection parameters.
*   **Outputs:** Updated scalar field $\phi$ for the next time step.

**Data Structures:**
*   For each additional quantity $\phi$ (e.g., density, temperature, color), allocate a texture or grid with the same dimensions as the velocity grid [S1, unofficial].
*   The scalar field $\phi$ is stored as a 3D array or volume texture.

**Method:**
The evolution of the scalar quantity $\phi$ is governed by the advection equation [S1, unofficial]:

$$
\frac{\partial \phi}{\partial t} = -(\mathbf{u} \cdot \nabla) \phi
$$

This equation is solved using the same MacCormack advection routine used for the velocity field [S1, unofficial]. The MacCormack method is an explicit, two-step, three-time level scheme that is second-order accurate in both time and space [S2, unofficial].

1.  **Predictor Step:** Calculate a temporary "predicted" value $\phi^*$ using forward differencing.
2.  **Corrector Step:** Determine the final "corrected" value $\phi^{n+1}$ using backward differencing based on the predicted value [S2, unofficial].
3.  **Alternation:** Forward and backward differencing are alternated between predictor and corrector steps to avoid bias due to one-sided differencing and achieve second-order accuracy [S2, unofficial].

**Source Injection:**
To generate smoke, a 3D Gaussian "splat" is injected into a color texture (or density field) each frame [S1, unofficial]. These values serve as a source term for the advection equation. While color values may lack physical significance, they create swirling patterns as they are advected [S1, unofficial].

**Coupling with Dynamics (Buoyancy):**
For physically plausible smoke, temperature $T$ is tracked and advected by $\mathbf{u}$ [S1, unofficial]. Unlike passive color, temperature influences fluid dynamics through a buoyant force. The source notes indicate this influence is described by a buoyant force term involving pressure $P$, though the specific formula for the force vector is not fully detailed in the provided text [S1, unofficial].

**Pseudocode:**
```python
def advect_scalar(phi, u, dt):
    """
    Advect scalar field phi using MacCormack scheme with velocity u.
    phi: 3D array of current scalar values
    u: 3D vector field (velocity)
    dt: time step
    """
    # Predictor step: forward differencing
    # Calculate gradient of phi
    grad_phi = compute_gradient(phi)
    # Compute flux: u . grad_phi
    flux = dot_product(u, grad_phi)
    # Update phi using forward Euler-like step for predictor
    phi_pred = phi - dt * flux
    
    # Corrector step: backward differencing
    # Calculate gradient of predicted phi
    grad_phi_pred = compute_gradient(phi_pred)
    # Compute flux using predicted phi
    flux_pred = dot_product(u, grad_phi_pred)
    # Average the predictor and corrector steps
    # Note: Standard MacCormack averages the fluxes or the results.
    # Based on [S2, unofficial], it determines the final corrected value using backward differencing.
    # A common implementation averages the forward and backward updates.
    phi_new = 0.5 * (phi - dt * flux + phi_pred - dt * flux_pred)
    
    return phi_new

def inject_smoke_source(phi, source_position, source_strength, gaussian_width):
    """
    Inject a 3D Gaussian splat into the scalar field.
    """
    # Apply Gaussian function centered at source_position
    # to the relevant region of phi
    for each voxel in domain:
        distance = length(voxel_pos - source_position)
        contribution = source_strength * exp(-distance**2 / (2 * gaussian_width**2))
        phi[voxel_pos] += contribution
```

## Subtopics

### [MacCormack Advection Scheme](4952-maccormack-advection-scheme.md)
The MacCormack advection scheme is a higher-order numerical method used to advect scalar fields (such as smoke density or temperature) and vector fields (velocity) in fluid simulations, designed to reduce the numerical smoothing inherent in standard semi-Lagrangian advection. It achieves this by combining a forward semi-Lagrangian step with a backward correction step, allowing low-resolution grids to retain visual detail comparable to significantly higher-resolution grids using standard first-order methods. Unlike the unconditionally stable semi-Lagrangian scheme, the MacCormack scheme is conditionally stable and requires a limiter to prevent numerical blow-up.

### Parallel Navier-Stokes Solver (MacCormack Method)
An explicit, two-step, three-time level scheme used to solve unsteady compressible Navier-Stokes equations, second-order accurate in both time and space, chosen for ease of parallelization [S2, unofficial]. It subdivides the data domain into blocks, exchanging solution values at the outermost boundary layers of each block between nearest neighbors after each predictor and corrector step [S2, unofficial]. A "Prepare Data" routine is used to calculate flow properties for visualization [S2, unofficial].

## Operating characteristics
*   **Stability:** The MacCormack scheme is conditionally stable, unlike unconditionally stable semi-Lagrangian schemes, requiring careful selection of $\Delta t$ and potentially limiters to prevent numerical blow-up [S1, unofficial].
*   **Accuracy:** It is second-order accurate in both time and space, reducing numerical diffusion compared to first-order methods [S2, unofficial].
*   **Parallelization:** The method is noted for being easier to parallelize and implement in distributed memory systems (e.g., Intel Paragon) by exchanging boundary layers between block neighbors [S2, unofficial].
*   **Performance:** Allows low-resolution grids to retain visual detail comparable to higher-resolution grids using standard first-order methods, improving efficiency [S1, unofficial].
