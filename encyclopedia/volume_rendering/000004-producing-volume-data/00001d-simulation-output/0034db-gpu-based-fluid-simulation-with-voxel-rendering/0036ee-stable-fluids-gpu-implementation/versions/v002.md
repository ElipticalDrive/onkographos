# Stable Fluids (GPU Implementation)

Also called: Jacobi Pressure Solver, Jacobi method for pressure-Poisson system, Semi-Lagrangian Advection

## Overview
Stable Fluids (GPU Implementation) is a method for computing fluid velocity by discretizing the momentum equation on a fixed Eulerian grid and solving for velocity via advection, external forces, and pressure projection [S1, unofficial]. It sets itself apart from its siblings by utilizing the Jacobi method to solve the pressure-Poisson system because it is easy to implement efficiently on the GPU, and by using semi-Lagrangian advection which is unconditionally stable [S1, unofficial]. It builds on [GPU-based Fluid Simulation with Voxel Rendering](7400-gpu-based-fluid-simulation-with-voxel-rendering.md) by providing the specific simulation kernels required to update the fluid state.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Current velocity field $\mathbf{u}$, pressure field $p$, external forces $\mathbf{f}$, time step $\Delta t$, and grid dimensions.
*   **Outputs:** Updated velocity field $\mathbf{u}^{n+1}$ and pressure field $p^{n+1}$.

**Data Structures:**
Cell attributes (velocity, pressure) are stored in 3D textures, mapping grid cells to voxels [S1, unofficial].
*   **Velocity:** Stored as a 3D texture (e.g., `RGBA16`), where each texel holds a 3D vector (xyz) and a dummy w component.
*   **Pressure:** Stored as a 3D texture (e.g., `R8` or `R16`), where each texel holds a scalar value.
*   **Divergence:** Stored as a 3D texture (e.g., `R8` or `R16`), holding the divergence of the intermediate velocity field.

The geometry shader output structure for the simulation kernels is defined as follows [S1, unofficial]:

```cpp
struct GS_OUTPUT_FLUIDSIM {
    // Index of the current grid cell (i,j,k in [0,gridSize] range)
    float3 cellIndex : TEXCOORD0;
    // Texture coordinates (x,y,z in [0,1] range) for the
    // current grid cell and its immediate neighbors
    float3 CENTERCELL : TEXCOORD1;
    float3 LEFTCELL : TEXCOORD2;
    float3 RIGHTCELL : TEXCOORD3;
    float3 BOTTOMCELL : TEXCOORD4;
    float3 TOPCELL : TEXCOORD5;
    float3 DOWNCELL : TEXCOORD6;
    float3 UPCELL : TEXCOORD7;
    float4 pos : SV_Position; // 2D slice vertex in homogeneous clip space
    uint RTIndex : SV_RenderTargetArrayIndex; // Specifies destination slice
};
```

**Numbered Steps:**
The momentum equation solution is split into successive operations: advection, application of external forces, and pressure projection [S1, unofficial].

1.  **Advection (Semi-Lagrangian):**
    *   Trace back along the characteristic: $\mathbf{pos} = \mathbf{current\_pos} - \Delta t \cdot \mathbf{cellVelocity}$.
    *   Convert the resulting index to texture coordinates.
    *   Sample the velocity field at the traced position.
    *   *Note:* This scheme is unconditionally stable but introduces numerical smoothing [S1, unofficial].

2.  **External Forces:**
    *   Apply forces (e.g., gravity) to the velocity field.
    *   Formula: $\mathbf{u}^{*} = \mathbf{u}^{n} + \Delta t \cdot \mathbf{f}$ (Forward Euler integration) [S1, unofficial].

3.  **Divergence Calculation:**
    *   Compute velocity divergence using central differences on neighboring cell velocities.
    *   Formula:
        $$ \nabla \cdot \mathbf{u}^* = 0.5 \cdot ((u_R - u_L) + (v_T - v_B) + (w_U - w_D)) $$
        where $u, v, w$ are the x, y, z components of velocity at the Right, Left, Top, Bottom, Up, and Down neighbors respectively.

4.  **Pressure Solve (Jacobi):**
    *   Iterate to solve the pressure-Poisson system $\nabla^2 p = \nabla \cdot \mathbf{u}^*$ [S1, unofficial].
    *   Update pressure at the center cell using the 6 neighbors and the divergence:
        $$ p_{new} = \frac{p_L + p_R + p_B + p_T + p_D + p_U - \nabla \cdot \mathbf{u}^*}{6.0} $$

5.  **Projection:**
    *   Subtract the pressure gradient from the velocity to make it divergence-free.
    *   Compute pressure gradient:
        $$ \nabla p = 0.5 \cdot (p_R - p_L, \ p_T - p_B, \ p_U - p_D) $$
    *   Update velocity:
        $$ \mathbf{u}^{n+1} = \mathbf{u}^* - \nabla p $$

**Pseudocode:**
The following pseudocode implements the kernels described in the sources. It assumes a 3D texture sampling function `Sample(tex, coord)` and a coordinate conversion function `cellIndex2TexCoord(index)`.

```python
# Helper to convert grid index to texture coordinate
def cellIndex2TexCoord(index):
    # index is float3 (i, j, k)
    # textureWidth, textureHeight, textureDepth are grid dimensions
    return float3(
        index.x / textureWidth,
        index.y / textureHeight,
        (index.z + 0.5) / textureDepth
    )

# Kernel: Semi-Lagrangian Advection of Velocity
# Input: GS_OUTPUT_FLUIDSIM in, Texture3D velocity
# Output: float4 (velocity vector)
def PS_ADVECT_VEL(in, velocity):
    # Current cell position in grid coordinates
    pos = in.cellIndex
    
    # Get velocity at current cell
    cellVelocity = velocity.Sample(samPointClamp, in.CENTERCELL).xyz
    
    # Trace back along characteristic
    pos = pos - timeStep * cellVelocity
    
    # Convert to texture coordinates
    pos = cellIndex2TexCoord(pos)
    
    # Sample velocity at traced position
    return velocity.Sample(samLinear, pos)

# Kernel: Compute Divergence
# Input: GS_OUTPUT_FLUIDSIM in, Texture3D velocity
# Output: float (divergence)
def PS_DIVERGENCE(in, velocity):
    # Get velocity values from neighboring cells
    fieldL = velocity.Sample(samPointClamp, in.LEFTCELL)
    fieldR = velocity.Sample(samPointClamp, in.RIGHTCELL)
    fieldB = velocity.Sample(samPointClamp, in.BOTTOMCELL)
    fieldT = velocity.Sample(samPointClamp, in.TOPCELL)
    fieldD = velocity.Sample(samPointClamp, in.DOWNCELL)
    fieldU = velocity.Sample(samPointClamp, in.UPCELL)
    
    # Compute divergence using central differences
    # field.x is u, field.y is v, field.z is w
    divergence = 0.5 * (
        (fieldR.x - fieldL.x) + 
        (fieldT.y - fieldB.y) + 
        (fieldU.z - fieldD.z)
    )
    return divergence

# Kernel: Jacobi Pressure Solve
# Input: GS_OUTPUT_FLUIDSIM in, Texture3D pressure, Texture3D divergence
# Output: float (new pressure)
def PS_JACOBI(in, pressure, divergence):
    # Get divergence at current cell
    dC = divergence.Sample(samPointClamp, in.CENTERCELL)
    
    # Get pressure values from neighboring cells
    pL = pressure.Sample(samPointClamp, in.LEFTCELL)
    pR = pressure.Sample(samPointClamp, in.RIGHTCELL)
    pB = pressure.Sample(samPointClamp, in.BOTTOMCELL)
    pT = pressure.Sample(samPointClamp, in.TOPCELL)
    pD = pressure.Sample(samPointClamp, in.DOWNCELL)
    pU = pressure.Sample(samPointClamp, in.UPCELL)
    
    # Compute new pressure value
    return (pL + pR + pB + pT + pU + pD - dC) / 6.0

# Kernel: Projection
# Input: GS_OUTPUT_FLUIDSIM in, Texture3D pressure, Texture3D velocity
# Output: float4 (new velocity)
def PS_PROJECT(in, pressure, velocity):
    # Get pressure values from neighboring cells
    pL = pressure.Sample(samPointClamp, in.LEFTCELL)
    pR = pressure.Sample(samPointClamp, in.RIGHTCELL)
    pB = pressure.Sample(samPointClamp, in.BOTTOMCELL)
    pT = pressure.Sample(samPointClamp, in.TOPCELL)
    pD = pressure.Sample(samPointClamp, in.DOWNCELL)
    pU = pressure.Sample(samPointClamp, in.UPCELL)
    
    # Compute gradient of pressure
    gradP = 0.5 * float3(pR - pL, pT - pB, pU - pD)
    
    # Get old velocity
    vOld = velocity.Sample(samPointClamp, in.CENTERCELL).xyz
    
    # Project velocity
    vNew = vOld - gradP
    
    return float4(vNew, 0)
```

**Parameters:**
*   `timeStep` ($\Delta t$): The duration of the time step used in semi-Lagrangian advection [S1, unofficial].
*   `Iterations`: The number of Jacobi iterations. For smoke/fire, this can be adjusted based on available resources. For liquids, more iterations are required to maintain volume [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **GPU Rendering Limitation:** GPUs render into 2D buffers, so 3D volume kernels must be executed once per slice by iterating over slice indices [S1, unofficial].
*   **Numerical Smoothing:** Semi-Lagrangian advection is unconditionally stable but introduces numerical smoothing, making water look viscous or smoke lose detail [S1, unofficial].
*   **Volume Loss:** Too few Jacobi iterations for liquids cause volume loss, making water sink through the tank bottom because pressure from the floor cannot counteract gravity [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The Jacobi solver converges linearly. The number of iterations required depends on the grid size and the desired accuracy. For real-time applications, the number of iterations is often fixed or limited by frame time [S1, unofficial].
*   **Memory Complexity:** Storage is proportional to the grid volume. Table 30-1 in the source indicates approximately 9 bytes per cell for simulation textures (1xRGBA16 velocity, 1xRGBA16 temporary, 1xR8 inside-outside) [S1, unofficial].
*   **Performance:** The method is designed for real-time performance on GPUs. The use of 3D textures and geometry shaders allows for efficient parallel execution [S1, unofficial].
*   **Strengths:** Unconditionally stable advection, simple implementation on GPU, easy to parallelize.
*   **Limitations:** Numerical smoothing from semi-Lagrangian advection, potential volume loss with insufficient Jacobi iterations, fixed Eulerian grid limits resolution.
*   **When to use:** Real-time fluid simulation where visual plausibility is more important than physical accuracy, particularly for smoke and fire.
*   **When not to use:** High-quality animation requiring precise volume conservation (liquids) without additional iterations, or when high-frequency detail preservation is critical.

## Background
The "stable fluids" method for computing velocity was introduced by Jos Stam in 1999 [S1, unofficial]. A GPU implementation of this method for 2D fluids was presented by Mark Harris in 2004 [S1, unofficial]. The 3D GPU implementation described in the sources is detailed in "Real-Time Simulation and Rendering of 3D Fluids" from GPU Gems 3 [S1, unofficial]. Alternatives to the Jacobi solver include the Conjugate Gradient method (Bolz et al. 2003), Multigrid (Goodnight et al. 2003), and Cyclic reduction (Kass et al. 2006) [S1, unofficial].
