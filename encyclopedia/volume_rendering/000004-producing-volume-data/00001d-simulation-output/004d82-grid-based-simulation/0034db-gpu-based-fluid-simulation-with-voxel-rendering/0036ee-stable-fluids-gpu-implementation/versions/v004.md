# Stable Fluids (GPU Implementation)
Also called: Jacobi Pressure Solver, Jacobi method for pressure-Poisson system, Semi-Lagrangian Advection

## Overview
Stable Fluids (GPU Implementation) is a method for computing fluid velocity by discretizing the momentum equation on a fixed Eulerian grid and solving for velocity via advection, external forces, and pressure projection [S1, unofficial]. It solves the problem of real-time incompressible fluid simulation on graphics hardware by leveraging 3D textures and slice-based rendering to map grid cells directly to voxels [S1, unofficial]. It sets itself apart from its siblings by using the Jacobi method for the pressure-Poisson system due to its GPU efficiency, and Semi-Lagrangian advection for unconditional stability, distinguishing it from [Free-Slip Boundary Condition Enforcement](7908-free-slip-boundary-condition-enforcement.md) which handles dynamic obstacles, and [GPU-based Eulerian Fluid Solver](14187-gpu-based-eulerian-fluid-solver.md) which uses half-precision textures and multigrid [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 3D grid of cubical cells representing the simulation domain; initial velocity field $\mathbf{u}$; pressure field $p$; external forces $\mathbf{f}$; time step $\Delta t$.
*   **Outputs:** Updated velocity field $\mathbf{u}^{n+1}$; updated pressure field $p^{n+1}$.

**Data Structures:**
State is stored in 3D textures mapping grid cells to voxels.
*   **Velocity Texture:** Stores vector quantities (velocity) at cell centers. Format: RGBA16 (or similar floating-point format).
*   **Pressure Texture:** Stores scalar quantities (pressure) at cell centers. Format: R8 or R16.
*   **Geometry Shader Output Struct (`GS_OUTPUT_FLUIDSIM`):** Used to pass neighbor coordinates to pixel shaders.
    ```cpp
    struct GS_OUTPUT_FLUIDSIM {
        float3 cellIndex : TEXCOORD0;      // Index of current grid cell (i,j,k)
        float3 CENTERCELL : TEXCOORD1;     // Texture coords for center cell
        float3 LEFTCELL : TEXCOORD2;       // Texture coords for left neighbor
        float3 RIGHTCELL : TEXCOORD3;      // Texture coords for right neighbor
        float3 BOTTOMCELL : TEXCOORD4;     // Texture coords for bottom neighbor
        float3 TOPCELL : TEXCOORD5;        // Texture coords for top neighbor
        float3 DOWNCELL : TEXCOORD6;       // Texture coords for down neighbor
        float3 UPCELL : TEXCOORD7;         // Texture coords for up neighbor
        float4 pos : SV_Position;          // 2D slice vertex in homogeneous clip space
        uint RTIndex : SV_RenderTargetArrayIndex; // Destination slice index
    };
    ```

**Numbered Steps:**
The momentum equation is split into successive operations: advection, application of external forces, and pressure projection [S1, unofficial].

1.  **Domain Discretization:** Subdivide the rectilinear volume into a regular grid of cubical cells. Store scalar (pressure) and vector (velocity) quantities at cell centers [S1, unofficial].
2.  **Advection (Semi-Lagrangian):** Trace back along the characteristic from the current cell position to find the source velocity.
    *   Calculate position: $\mathbf{pos} = \mathbf{current\_pos} - \Delta t \cdot \mathbf{cellVelocity}$.
    *   Convert index to texture coordinates.
    *   Sample the velocity field at the traced position using linear interpolation [S1, unofficial].
    *   *Note:* This scheme is unconditionally stable but introduces numerical smoothing [S1, unofficial].
3.  **External Forces:** Apply forces (e.g., gravity) to the advected velocity field. $\mathbf{u}^* = \mathbf{u}^{advected} + \Delta t \cdot \mathbf{f}$ [S1, unofficial].
4.  **Divergence Calculation:** Compute the divergence of the intermediate velocity field $\mathbf{u}^*$ using central differences on neighboring cell velocities.
    $$ \nabla \cdot \mathbf{u}^* = 0.5 \cdot ((u^*_R - u^*_L) + (v^*_T - v^*_B) + (w^*_U - w^*_D)) $$
    Where $R, L, T, B, U, D$ refer to Right, Left, Top, Bottom, Up, Down neighbors respectively [S1, unofficial].
5.  **Pressure Solve (Jacobi):** Solve the pressure-Poisson system $\nabla^2 p = \nabla \cdot \mathbf{u}^*$ iteratively.
    *   Initialize pressure field (e.g., to zero).
    *   For each iteration:
        $$ p_{new} = \frac{p_L + p_R + p_B + p_T + p_U + p_D - \nabla \cdot \mathbf{u}^*}{6.0} $$
    *   Repeat for a fixed number of iterations. Liquids require more iterations to maintain volume than smoke/fire [S1, unofficial].
6.  **Projection:** Subtract the pressure gradient from the velocity to enforce incompressibility ($\nabla \cdot \mathbf{u} = 0$).
    *   Compute gradient: $\nabla p = 0.5 \cdot \mathbf{float3}(p_R - p_L, p_T - p_B, p_U - p_D)$.
    *   Update velocity: $\mathbf{u}^{n+1} = \mathbf{u}^* - \nabla p$ [S1, unofficial].

**Pseudocode:**
```python
# Helper to convert grid index to texture coordinate
def cellIndex2TexCoord(index, textureWidth, textureHeight, textureDepth):
    # Assuming index is in [0, gridSize] range
    x = index.x / textureWidth
    y = index.y / textureHeight
    z = (index.z + 0.5) / textureDepth
    return float3(x, y, z)

# Geometry Shader: Rasterizes a quad for each slice
# Generates GS_OUTPUT_FLUIDSIM for every pixel in the quad
def GS_FLUIDSIM(input_vertex):
    # input_vertex contains slice index and 2D position
    slice_index = input_vertex.slice_index
    width = textureWidth
    height = textureHeight
    
    # Calculate grid coordinates for the current pixel
    # Assuming input_vertex maps to grid coordinates [0, width-1] x [0, height-1]
    grid_x = input_vertex.pos.x
    grid_y = input_vertex.pos.y
    grid_z = slice_index
    
    # Define neighbor offsets
    offsets = {
        'CENTER': float3(0, 0, 0),
        'LEFT': float3(-1, 0, 0),
        'RIGHT': float3(1, 0, 0),
        'BOTTOM': float3(0, -1, 0),
        'TOP': float3(0, 1, 0),
        'DOWN': float3(0, 0, -1),
        'UP': float3(0, 0, 1)
    }
    
    output = GS_OUTPUT_FLUIDSIM()
    output.cellIndex = float3(grid_x, grid_y, grid_z)
    output.RTIndex = slice_index
    
    for name, offset in offsets.items():
        neighbor_index = output.cellIndex + offset
        output.name = cellIndex2TexCoord(neighbor_index, width, height, textureDepth)
        
    output.pos = input_vertex.pos # Pass through clip space position
    return output

# Pixel Shader: Advection
def PS_ADVECT_VEL(in_data: GS_OUTPUT_FLUIDSIM, velocity_texture: Texture3D, timeStep: float):
    # Current position in grid coordinates
    pos = in_data.cellIndex
    
    # Get velocity at current cell
    cellVelocity = velocity_texture.Sample(samPointClamp, in_data.CENTERCELL).xyz
    
    # Back-trace
    pos = pos - timeStep * cellVelocity
    
    # Convert back to texture coordinates
    pos = cellIndex2TexCoord(pos, velocity_texture.width, velocity_texture.height, velocity_texture.depth)
    
    # Sample velocity at traced position
    return velocity_texture.Sample(samLinear, pos)

# Pixel Shader: Divergence
def PS_DIVERGENCE(in_data: GS_OUTPUT_FLUIDSIM, velocity_texture: Texture3D):
    # Sample velocities from neighbors
    fieldL = velocity_texture.Sample(samPointClamp, in_data.LEFTCELL)
    fieldR = velocity_texture.Sample(samPointClamp, in_data.RIGHTCELL)
    fieldB = velocity_texture.Sample(samPointClamp, in_data.BOTTOMCELL)
    fieldT = velocity_texture.Sample(samPointClamp, in_data.TOPCELL)
    fieldD = velocity_texture.Sample(samPointClamp, in_data.DOWNCELL)
    fieldU = velocity_texture.Sample(samPointClamp, in_data.UPCELL)
    
    # Compute divergence using central differences
    # Assuming velocity is stored as float4 (x,y,z,w) where w is unused or padding
    divergence = 0.5 * ((fieldR.x - fieldL.x) + (fieldT.y - fieldB.y) + (fieldU.z - fieldD.z))
    return divergence

# Pixel Shader: Jacobi Pressure Solve
def PS_JACOBI(in_data: GS_OUTPUT_FLUIDSIM, pressure_texture: Texture3D, divergence_texture: Texture3D):
    # Get divergence at current cell
    dC = divergence_texture.Sample(samPointClamp, in_data.CENTERCELL)
    
    # Sample pressure from neighbors
    pL = pressure_texture.Sample(samPointClamp, in_data.LEFTCELL)
    pR = pressure_texture.Sample(samPointClamp, in_data.RIGHTCELL)
    pB = pressure_texture.Sample(samPointClamp, in_data.BOTTOMCELL)
    pT = pressure_texture.Sample(samPointClamp, in_data.TOPCELL)
    pD = pressure_texture.Sample(samPointClamp, in_data.DOWNCELL)
    pU = pressure_texture.Sample(samPointClamp, in_data.UPCELL)
    
    # Jacobi iteration
    new_pressure = (pL + pR + pB + pT + pU + pD - dC) / 6.0
    return new_pressure

# Pixel Shader: Projection
def PS_PROJECT(in_data: GS_OUTPUT_FLUIDSIM, pressure_texture: Texture3D, velocity_texture: Texture3D):
    # Sample pressure from neighbors
    pL = pressure_texture.Sample(samPointClamp, in_data.LEFTCELL)
    pR = pressure_texture.Sample(samPointClamp, in_data.RIGHTCELL)
    pB = pressure_texture.Sample(samPointClamp, in_data.BOTTOMCELL)
    pT = pressure_texture.Sample(samPointClamp, in_data.TOPCELL)
    pD = pressure_texture.Sample(samPointClamp, in_data.DOWNCELL)
    pU = pressure_texture.Sample(samPointClamp, in_data.UPCELL)
    
    # Compute pressure gradient
    gradP = 0.5 * float3(pR - pL, pT - pB, pU - pD)
    
    # Get old velocity
    vOld = velocity_texture.Sample(samPointClamp, in_data.CENTERCELL).xyz
    
    # Project velocity
    vNew = vOld - gradP
    return float4(vNew, 0)

# Main Simulation Loop
def simulate_step(velocity_tex, pressure_tex, divergence_tex, timeStep, num_jacobi_iters):
    # 1. Advection
    advected_velocity = run_kernel(PS_ADVECT_VEL, velocity_tex, timeStep)
    
    # 2. External Forces (simplified as addition)
    # u* = advected_velocity + dt * f
    # Note: Force application kernel not detailed in sources, assumed to be a simple add
    intermediate_velocity = advected_velocity + timeStep * external_force_field
    
    # 3. Divergence
    div = run_kernel(PS_DIVERGENCE, intermediate_velocity)
    
    # 4. Jacobi Iterations
    # Initialize pressure to zero or previous pressure
    pressure_tex.clear(0)
    for i in range(num_jacobi_iters):
        new_pressure = run_kernel(PS_JACOBI, pressure_tex, div)
        pressure_tex = new_pressure # Swap buffers or write in place depending on implementation
        
    # 5. Projection
    final_velocity = run_kernel(PS_PROJECT, pressure_tex, intermediate_velocity)
    
    return final_velocity
```

**Parameters:**
*   `timeStep` ($\Delta t$): The duration of the time step. Must be chosen to balance stability and detail.
*   `Iterations`: The number of Jacobi iterations. Adjustable based on resources. Smoke/fire may use fewer; liquids require more to prevent volume loss [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **GPU Rendering Limitation:** GPUs render into 2D buffers. 3D volume kernels must be executed once per slice by iterating over slice indices and using `SV_RenderTargetArrayIndex` [S1, unofficial].
*   **Numerical Smoothing:** Semi-Lagrangian advection is unconditionally stable but introduces smoothing, making water look viscous or smoke lose detail [S1, unofficial].
*   **Volume Loss:** Too few Jacobi iterations for liquids cause volume loss, making water sink through the tank bottom because pressure from the floor cannot counteract gravity [S1, unofficial].
*   **Boundary Conditions:** The basic implementation stores quantities at cell centers. Staggered MAC grids are more robust for boundary conditions but are not the default in this specific implementation [S1, unofficial].

## Subtopics

### [Free-Slip Boundary Condition Enforcement](7908-free-slip-boundary-condition-enforcement.md)
This method enforces a free-slip boundary condition for fluid simulations involving dynamic obstacles represented as voxelized solids. It ensures that fluid velocity normal to the obstacle surface matches the solid's normal velocity, allowing tangential slip, while preventing mass leakage into solid interiors. It differs from no-slip conditions by retaining tangential fluid velocity and from static boundary handling by explicitly updating obstacle velocity fields and modifying the pressure solver to ignore solid cell contributions.

### [Projection Method](8336-projection-method.md)
The Projection Method enforces incompressibility on a fluid velocity field by subtracting the gradient of a pressure field, ensuring the resulting velocity is divergence-free. It distinguishes itself from sibling methods like Free-Slip Boundary Condition Enforcement by focusing specifically on the Helmholtz-Hodge decomposition step required to satisfy the continuity equation within the Stable Fluids framework.

### [Operator Splitting for Fluid Dynamics](12465-operator-splitting-for-fluid-dynamics.md)
Operator splitting decomposes the complex dynamic equations of fluid dynamics into sequential, simpler sub-steps to facilitate numerical integration on a grid. It solves the problem of enforcing incompressibility while applying external forces and advecting the fluid state. It sets itself apart from the parent [Stable Fluids (GPU Implementation)](7906-stable-fluids-gpu-implementation.md) by explicitly structuring the time integration into three distinct, ordered phases: advection, force application, and pressure projection.

### [GPU-based Eulerian Fluid Solver](14187-gpu-based-eulerian-fluid-solver.md)
A GPU-based Eulerian fluid solver that simulates and renders volumetrics at VR resolutions and refresh rates using operator splitting to approximately solve the Navier-Stokes equations. It sets itself apart by utilizing half-precision 3D textures for state storage and a specific geometric multigrid configuration to achieve interactive frame rates on consumer hardware, building on [Stable Fluids (GPU Implementation)](7906-stable-fluids-gpu-implementation.md).

## Operating characteristics
*   **Time Complexity:** The dominant cost is the pressure solve. With Jacobi iteration, the cost is $O(N \cdot I)$, where $N$ is the number of grid cells and $I$ is the number of iterations.
*   **Memory Complexity:** Storage is proportional to the grid size. Table 30-1 in [S1, unofficial] indicates ~9 bytes per cell for simulation (velocity RGBA16, inside-outside R8, temporary RGBA16) and ~20 bytes per pixel for rendering (off-screen targets, ray data, depth).
*   **Measured Performance:** Designed for real-time applications. Performance depends on the number of Jacobi iterations. Smoke/fire can tolerate fewer iterations for higher frame rates, while liquids require more [S1, unofficial].
*   **Strengths:** Unconditional stability of semi-Lagrangian advection; efficient GPU implementation using 3D textures and geometry shaders; simple to implement [S1, unofficial].
*   **Limitations:** Numerical smoothing from semi-Lagrangian advection; volume loss if Jacobi iterations are insufficient for liquids; cell-centered storage is less robust than staggered grids for complex boundaries [S1, unofficial].
*   **When to use:** Real-time fluid simulation where visual plausibility is prioritized over physical accuracy, particularly for smoke, fire, and simple liquids [S1, unofficial].
*   **When not to use:** High-fidelity liquid simulation requiring strict volume conservation without excessive iterations; simulations requiring complex boundary conditions handled by no-slip or dynamic obstacles (use [Free-Slip Boundary Condition Enforcement](7908-free-slip-boundary-condition-enforcement.md) or [GPU-based Eulerian Fluid Solver](14187-gpu-based-eulerian-fluid-solver.md)) [S1, unofficial].

## Background
The "stable fluids" method for computing velocity was introduced by Jos Stam in 1999 [S1, unofficial]. A GPU implementation of this method for 2D fluids was presented by Mark Harris in 2004 [S1, unofficial]. The 3D GPU implementation described in the sources extends these concepts to volumetric grids using Direct3D 10 features like 3D textures and geometry shaders [S1, unofficial]. Alternatives to the Jacobi solver include Conjugate Gradient (Bolz et al. 2003), Multigrid (Goodnight et al. 2003), and Cyclic reduction (Kass et al. 2006) [S1, unofficial].
