# GPU-based Fluid Simulation with Voxel Rendering

Also called: Integrating Real-Time Fluid Simulation with a Voxel Engine, Poxels Fluid Integration

## Overview
This method integrates real-time incompressible fluid simulation with sparse voxel-based rasterization on graphics hardware, specifically using Direct3D geometry shaders for rendering and compute shaders for simulation [S1]. It solves the problem of efficiently visualizing fluid dynamics within a voxel engine by offloading the Navier–Stokes solver and voxel activation logic entirely to the GPU, thereby eliminating the performance bottleneck of copying simulation data back to the CPU [S1]. It sets itself apart from its siblings by utilizing a specific "Poxels" rendering pipeline where the geometry shader handles voxel activation and color ramping via stream-out, rather than relying on CPU-side voxel culling or standard ray marching [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Simulation grid dimensions $(N_x, N_y, N_z)$, external forces, and initial velocity/pressure fields.
*   **Outputs:** A 3D speed grid texture (single precision floats) serving as the volumetric source for the voxel engine, and a stream of rendered primitives (triangles) for the rasterizer [S1].

**Data Structures:**
The simulation state is stored in GPU compute textures composed of single-precision float4 types [S1]:
1.  **Velocity Textures:** Three textures are used to store velocity components and temporary values during the simulation stages [S1].
2.  **Pressure Textures:** Two textures are used for pressure values and temporary calculations [S1].
3.  **Active Voxel Texture:** A texture containing only non-zero values, used to determine which voxels are active for rendering [S1].
4.  **Staging Texture:** A 3D texture used only in the CPU approach to transfer data from GPU memory to CPU memory; its size must match the simulation grid size [S1].

**Numbered Steps:**
1.  **Define Processing Stages:** The Navier–Stokes equations are discretized into four stages: advection of the velocity field, acceleration caused by pressure, diffusion of momentum, and application of external forces [S1].
2.  **Update Velocity:** Perform three computations to update the velocity field at each time step: advection, diffusion, and force application [S1].
3.  **Pressure Projection:** Compute the pressure field and subtract the pressure gradient from the velocity field to enforce incompressibility [S1].
4.  **Output Simulation State:** The final result of the five GPU compute stages is output into a 3D speed grid texture filled with single-precision floats [S1].
5.  **Voxel Activation (GPU Optimization):** Instead of reading the grid back to the CPU, a texture containing only non-zero values is generated in the compute shader and passed to the geometry shader [S1].
6.  **Geometry Shader Processing:** The geometry shader receives the active voxel data. It determines which voxels should be rendered and applies a color ramp function (taking a float between 0 and 1 to return an RGB color) directly within the shader [S1].
7.  **Stream-Out:** The geometry shader continuously outputs vertex data using stream-out to a cached vertex buffer, guaranteeing deterministic ordering of rendered primitives [S1].
8.  **Rasterization:** Regular triangle geometry is rasterized using the generated vertex buffer [S1].

**Pseudocode:**
```python
# GPU Compute Shader Stage
def update_fluid_state(velocity_textures, pressure_textures, forces, dt):
    # Step 2: Update Velocity
    # Advection: Transport velocity field
    advected_velocity = semi_lagrangian_advect(velocity_textures, dt)
    
    # Diffusion: Momentum diffusion
    diffused_velocity = apply_diffusion(advected_velocity, dt)
    
    # Force Application: External forces
    forced_velocity = diffused_velocity + forces * dt
    
    # Step 3: Pressure Projection
    # Compute divergence and solve pressure Poisson equation (e.g., Jacobi)
    pressure = solve_pressure_poisson(forced_velocity)
    
    # Subtract pressure gradient
    final_velocity = forced_velocity - gradient(pressure)
    
    # Step 4: Output
    return final_velocity

# GPU Geometry Shader Stage (Poxels Optimization)
def render_voxels(active_voxel_texture, color_ramp_function):
    # Step 5: Receive active voxels (non-zero values)
    voxels = read_active_voxels(active_voxel_texture)
    
    for voxel in voxels:
        # Step 6: Apply color ramp
        concentration = voxel.value # Float between 0 and 1
        color = color_ramp_function(concentration)
        
        # Generate vertex data for the voxel (e.g., cube faces)
        vertices = generate_cube_geometry(voxel.position)
        
        # Step 7: Stream-out
        stream_out(vertices, color)
```

**Parameters:**
*   **Simulation Grid Size:** Must match the size of the 3D voxel staging texture (if used) [S1].
*   **Memory Alignment:** CPU memory buffers require appropriate memory address alignment [S1].
*   **Color Ramp:** A function mapping a float $[0, 1]$ to an RGB color [S1].

**Edge Cases and Pitfalls:**
*   **Obstacles:** The described simulation does not detect or respond to obstacles [S1].
*   **Single Chunk:** The simulation is based on a single chunk; extending to multiple chunks requires additional logic [S1].
*   **Precision:** The use of single-precision floats is specified for the textures [S1].

## Subtopics

### [Stable Fluids (GPU Implementation)](7906-stable-fluids-gpu-implementation.md)
A method for computing fluid velocity by discretizing the momentum equation on a fixed Eulerian grid and solving for velocity via advection, external forces, and pressure projection. It sets itself apart from its siblings by using the Jacobi method to solve the pressure-Poisson system because it is easy to implement efficiently on the GPU, and by employing semi-Lagrangian advection which is unconditionally stable. It builds on [GPU-based Fluid Simulation with Voxel Rendering](7400-gpu-based-fluid-simulation-with-voxel-rendering.md) by providing the specific simulation kernels required to update the fluid state on graphics hardware.

## Operating characteristics
**Time and Memory Complexity:**
*   The performance scales linearly with the number of voxels [S1].
*   In the CPU approach, the time to copy data back to the CPU is the most significant bottleneck [S1].
*   The GPU-only method eliminates this copy, resulting in significant performance improvements [S1].

**Measured Performance:**
*   **NVIDIA GeForce GTX 950M (CPU Approach):**
    *   64x64x64 chunk (262,144 blocks): 100 FPS (10.000 ms frame time) [S1].
    *   Copy from staging texture to CPU: 23,088,969 ns [S1].
    *   Activate voxels and render: 976,276 ns [S1] (Note: This step is performed on CPU in the original method, but the timing suggests it might be part of the total frame time breakdown; the text states the copy is the significant part) [S1].
*   **NVIDIA GeForce GT540M (GPU-only Method):**
    *   64x64x64 chunk: 180 FPS (5.556 ms frame time) [S1].
    *   Performance improvement: From 30 fps (original method) up to 1100 fps (GPU-only method) for a 64x64x64 chunk [S1].

**Strengths and Limitations:**
*   **Strengths:** High performance due to GPU-only processing; deterministic ordering of primitives via stream-out; efficient integration with Poxels engine [S1].
*   **Limitations:** No obstacle detection or response; limited to single-chunk simulation in the base description; requires Direct3D geometry shaders and compute shaders [S1].

**When to Use:**
*   When real-time fluid visualization is required in a voxel engine and GPU resources are available.
*   When obstacle interaction is not a primary requirement or can be handled separately.

**When Not to Use:**
*   When obstacle collision detection is critical and must be handled within the simulation loop.
*   When multi-chunk scalability is required without additional implementation effort.

## Background
This method was proposed by Miller et al. (2014) and Vlietinck (2009) in the paper "Integrating Real-Time Fluid Simulation with a Voxel Engine" [S1]. It builds on recent results in GPU-accelerated fluid simulation (Crane et al. 2007 and Harris 2004) and voxel-based rendering [S1]. The fluid simulation is based on the Navier–Stokes differential equations (Stam 2003) [S1]. The rendering engine used is the Poxels voxel engine (Miller et al. 2014) [S1]. The method was tested on an Asus N751JX-T4180H with a GeForce GTX 950M video card and an Intel Core i7-4720HQ CPU [S1].
