# Orthographic Multi-View Voxelization

Also called: 3-Direction Rasterization, 3-View Voxelization, Directional Sheet Buffer Voxelization, Orthographic 3D Texture Rasterization, Voxelization via Orthographic Projection, Worksheet Voxelization

## Overview
Orthographic Multi-View Voxelization rasterizes scene geometry into a 3D texture using three orthographic cameras aligned with the scene's bounding box axes to create a voxelized representation for subsequent volume rendering [S1, unofficial]. It differs from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by using multiple views to ensure coverage and from [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md) by operating directly in voxel space rather than registering depth maps. The method relies on the principle that rasterizing from multiple orthogonal directions ensures every intersected voxel is covered, provided views are sufficiently separated [Parent].

## How it works
**Inputs:** Scene mesh (triangles), scene bounding box ($bb_{min}, bb_{max}$), target voxel grid resolution ($V_x, V_y, V_z$).
**Outputs:** A 3D texture (or equivalent storage) representing the voxel grid.

**Data Structures:**
1.  **Scene Bounding Box:** Defined by $bb_{min}$ and $bb_{max}$.
2.  **Voxel Grid:** A 3D texture of size $V_x \times V_y \times V_z$. In the implementation [S1, unofficial], this is a `std::vector<GLfloat>` of size $4 \times V_x \times V_y \times V_z$, initialized to $0.0f$, representing RGBA32F data.
3.  **View-Projection Matrices:** Three matrices, `viewProject[0]`, `viewProject[1]`, `viewProject[2]`, corresponding to the X, Y, and Z axes.

**Parameters:**
*   `voxelTextureSize`: Default resolution, e.g., `glm::uvec3(64, 64, 64)` [S1, unofficial].
*   `offset`: Camera extension distance beyond the bounding box, fixed at `0.2f` [S1, unofficial].
*   `projection_scale`: Frustum expansion factor, fixed at `1.02f` (passed as `0.51f` to half-width) [S1, unofficial].
*   `near_plane`: Fixed at `0.1f` [S1, unofficial].
*   `far_plane`: Calculated as $1.2 \times \text{range} + \text{offset}$ [S1, unofficial].

**Algorithm Steps:**

1.  **Calculate Bounding Box and Range:**
    Compute the scene bounding box min ($bb_{min}$) and max ($bb_{max}$). Calculate the range vector:
    $$ range = bb_{max} - bb_{min} $$

2.  **Setup Camera Parameters:**
    *   Set camera offset: $offset = 0.2f$ [S1, unofficial].
    *   Set near plane: $near = 0.1f$ [S1, unofficial].
    *   Set far plane: $far = 1.2 \times \max(range.x, range.y, range.z) + offset$ [S1, unofficial].
    *   Set frustum half-width: $half\_width = 0.51 \times \max(range.x, range.y, range.z)$ [S1, unofficial].

3.  **Construct View-Projection Matrices:**
    Create three orthographic projection matrices for the X, Y, and Z axes.
    *   The frustum bounds are set to $1.02 \times \text{scene range}$ on the viewing planes [S1, unofficial].
    *   The camera position is offset by $0.2f$ beyond the max bounds along each axis [S1, unofficial].
    *   Pass these matrices to the voxelization shader uniforms `viewProject[0]`, `viewProject[1]`, and `viewProject[2]` [S1, unofficial].

4.  **Initialize Voxel Texture:**
    *   Clear the 3D texture to RGBA(0,0,0,0) [S1, unofficial].
    *   Disable multisampling, depth testing, and face culling [S1, unofficial].
    *   Bind the texture as a read-write image buffer (e.g., `GL_RGBA8` or `GL_RGBA32F`) [S1, unofficial].

5.  **Setup Shader Uniforms:**
    *   Set voxel grid scale uniform: $scale = (voxelTextureSize / range)$ [S1, unofficial].
    *   Set box min uniform: $boxMin = bb_{min}$ [S1, unofficial].
    *   Upload light data if required [S1, unofficial].

6.  **Rasterization (Per Triangle):**
    For each triangle in the scene:
    *   **Dominant Axis Selection:** Determine the axis direction where the triangle has the maximum projection area (or is most parallel to its normal) to avoid degenerate rasterization [S2, unofficial]. If a triangle is parallel to the rasterization direction, 2D linear interpolation results in a line segment [S2, unofficial].
    *   **Rasterization:** Rasterize the triangle using the corresponding view-projection matrix.
    *   **Atomic Writes:** When multiple triangles or views write to the same voxel, atomic operations are used to prevent race conditions if the implementation is parallel [G].

7.  **Post-Processing (Optional Mipmaps):**
    Generate mipmaps for the filled 3D texture to enable multi-resolution cone tracing [S1, unofficial].

**Pseudocode:**

```python
def orthographic_multi_view_voxelization(scene_mesh, voxel_texture_size):
    # 1. Calculate Bounding Box
    bb_min, bb_max = compute_bounding_box(scene_mesh)
    range_vec = bb_max - bb_min
    
    # 2. Setup Parameters
    offset = 0.2f
    near_plane = 0.1f
    max_range = max(range_vec.x, range_vec.y, range_vec.z)
    far_plane = 1.2 * max_range + offset
    half_width = 0.51 * max_range
    
    # 3. Construct View-Projection Matrices
    # Matrices for X, Y, Z axes. 
    # Camera position is offset by 0.2f beyond max bounds along each axis.
    view_proj_x = create_orthographic_matrix(half_width, half_width, near_plane, far_plane, offset, axis='X')
    view_proj_y = create_orthographic_matrix(half_width, half_width, near_plane, far_plane, offset, axis='Y')
    view_proj_z = create_orthographic_matrix(half_width, half_width, near_plane, far_plane, offset, axis='Z')
    
    view_projs = [view_proj_x, view_proj_y, view_proj_z]
    
    # 4. Initialize Voxel Texture
    # Size: 4 * Vx * Vy * Vz floats (RGBA32F)
    voxel_texture = [0.0] * (4 * voxel_texture_size.x * voxel_texture_size.y * voxel_texture_size.z)
    
    # 5. Setup Shader Uniforms
    scale = voxel_texture_size / range_vec
    box_min = bb_min
    
    # 6. Rasterize
    for triangle in scene_mesh.triangles:
        # Determine dominant axis to avoid degenerate projection
        normal = triangle.normal
        # Select axis with largest absolute component in normal
        if abs(normal.x) >= abs(normal.y) and abs(normal.x) >= abs(normal.z):
            axis_idx = 0
        elif abs(normal.y) >= abs(normal.x) and abs(normal.y) >= abs(normal.z):
            axis_idx = 1
        else:
            axis_idx = 2
            
        vp = view_projs[axis_idx]
        
        # Rasterize triangle to voxel space
        # This step involves transforming vertices, clipping, and interpolating
        # to determine which voxels are covered.
        covered_voxels = rasterize_triangle_to_voxels(triangle, vp, scale, box_min)
        
        # Write to texture with atomic operations if parallel
        for voxel in covered_voxels:
            atomic_write(voxel_texture, voxel, triangle.data)
            
    # 7. Generate Mipmaps
    generate_mipmaps(voxel_texture)
    
    return voxel_texture
```

## Subtopics

### [Shadow Volume Voxelization](5629-shadow-volume-voxelization.md)
Shadow Volume Voxelization is a rasterization-based technique that generates a 3D shadow volume texture by voxelizing scene geometry into a 3D grid, where each voxel stores a bitmask representing which of its 8 constituent sub-voxels are occluded. It builds on [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) by replacing the standard occupancy flag with a 3-bit occlusion mask per coarse voxel, enabling multi-resolution shadow representation through mipmaps. Unlike standard binary voxelization, this method preserves partial occlusion information within each voxel, allowing for smoother shadow transitions and hierarchical shadow testing.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of triangles and the number of views (3). The cost is dominated by rasterization.
*   **Memory Complexity:** $O(V_x \times V_y \times V_z)$ for the 3D texture.
*   **Performance:** The method is significantly faster than slicing-based voxelization. For a 256^3 resolution, it takes ~100ms compared to ~5 seconds for slicing-based methods [S2, unofficial].
*   **Strengths:** Hardware-accelerated, real-time capable, produces 6-separating voxel grids ensuring tunnel-free connectivity [Parent].
*   **Limitations:** Requires support for 3D textures and read-write image buffers. Degenerate rasterization can occur if triangles are parallel to the view direction, requiring dominant axis selection [S2, unofficial].
*   **When to use:** When real-time voxelization is required for volume rendering or shadow mapping.
*   **When not to use:** When hardware does not support 3D textures or atomic writes, or when extremely high resolution is needed with limited memory.

## Background
The method was presented in "Real-time Voxelization for Complex Models" [S2, unofficial] as a scheme to solve the problem of fast voxelization for interactive graphics applications. It represents the resultant volume as 2D textures (worksheet) which can be efficiently processed. The approach was developed to overcome the limitations of slicing-based voxelization, which was too slow and required 3D texture support not available in consumer hardware at the time [S2, unofficial]. It is used in voxel cone tracing pipelines [S1, unofficial].
