# Orthographic Multi-View Voxelization

Also called: 3-Direction Rasterization, 3-View Voxelization, Directional Sheet Buffer Voxelization, Orthographic 3D Texture Rasterization, Voxelization via Orthographic Projection, Worksheet Voxelization

## Overview
Orthographic Multi-View Voxelization is a rasterization-based technique that generates a 3D voxelized representation of scene geometry by projecting triangles onto three intermediate 2D buffers aligned with the principal axes (X, Y, Z) and synthesizing them into a final compact 2D texture or 3D volume [S1, unofficial][S2, unofficial]. It solves the problem of efficiently converting complex triangle meshes into a discrete volumetric grid for subsequent volume rendering or ray tracing, avoiding the performance penalties of CPU-side traversal or view-dependent methods [S2, unofficial]. Unlike [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md), which uses only one view and suffers from occlusion errors and degenerate projections, this method uses three orthogonal views to ensure complete coverage and robustness against degenerate triangle orientations [S2, unofficial].

## How it works
The method consists of two primary architectural approaches: direct 3D texture writing (GPU-friendly) and the sheet-buffer-to-worksheet synthesis (CPU/GPU hybrid or memory-constrained GPU). Both rely on orthographic projection along the X, Y, and Z axes.

### Inputs and Outputs
*   **Input:** A triangle mesh (vertices, indices), a desired voxel grid resolution ($N_x \times N_y \times N_z$), and the scene's bounding box.
*   **Output:** A 3D texture (voxel grid) or a 2D "worksheet" texture encoding the 3D volume.

### Data Structures

#### Direct 3D Texture Approach [S1, unofficial]
*   **Voxel Texture:** A 3D texture (`texture3D`) of size $N_x \times N_y \times N_z$.
    *   **Format:** RGBA32F (or RGBA8).
    *   **Layout:** Linear memory representation in host code: `std::vector<GLfloat>` of size $4 \times N_x \times N_y \times N_z$, initialized to 0.0.
    *   **GPU Binding:** Bound as a read-write image buffer (`GL_RGBA8` or `GL_RGBA32F`) using `glBindImageTexture` to allow atomic writes from the shader.

#### Sheet Buffer / Worksheet Approach [S2, unofficial]
*   **Sheet Buffers:** Three 2D buffers (one for each axis: X, Y, Z). Each buffer stores the rasterized output for triangles projected along that specific axis.
*   **Worksheet:** A 2D texture of resolution $2^W \times 2^H$.
    *   **Encoding:** Encodes the discrete voxel space ($2^L \times 2^M \times 2^N$) such that $2^L \times 2^M \times 2^N = 2^W \times 2^H \times C$, where $C$ is the number of voxels encoded per texel.
    *   **Example:** For binary voxelization with 8-bit components, a 4-component texel holds $C=32$ voxels.
    *   **Patch Structure:** The worksheet is divided into patches. The number of patches along the X and Y axes are $2^{W-L}$ and $2^{H-M}$ respectively. Each patch corresponds to a volume slab.

### Algorithm Steps

#### 1. Initialization and Camera Setup
1.  Calculate the scene bounding box min ($bb_{min}$) and max ($bb_{max}$).
2.  Compute the range: $range = bb_{max} - bb_{min}$.
3.  Define the voxel grid resolution $voxelTextureSize$ (e.g., $64 \times 64 \times 64$) [S1, unofficial].
4.  Set the camera offset $offset$ beyond the bounding box (e.g., $0.2f$) [S1, unofficial].
5.  Configure three orthographic cameras aligned with the X, Y, and Z axes.
    *   **Frustum Bounds:** Set the viewing plane bounds to $1.02 \times range$ (half-width $0.51 \times range$) [S1, unofficial].
    *   **Near/Far Planes:** Near plane at $0.1f$, Far plane at $1.2 \times range + offset$ [S1, unofficial].
    *   **View-Projection Matrices:** Generate matrices $VP_X, VP_Y, VP_Z$ and pass them to the shader uniforms `viewProject[0]`, `viewProject[1]`, `viewProject[2]` [S1, unofficial].
6.  Set the voxel grid scale uniform: $scale = voxelTextureSize / range$ [S1, unofficial].
7.  Set the box min uniform: $boxMin = bb_{min}$ [S1, unofficial].

#### 2. Rasterization (Per Axis)
For each axis direction ($D \in \{X, Y, Z\}$):
1.  **Triangle Culling:** Identify triangles that intersect the current slab or volume extent.
2.  **Degeneracy Check:** Determine the projection direction for each triangle. If a triangle is parallel to the current rasterization direction, it will project as a line segment due to 2D linear interpolation, causing artifacts [S2, unofficial].
    *   *Mitigation:* Rasterize the triangle along the axis direction (X, Y, or Z) where it has the **maximum projected area** (i.e., the normal is most parallel to the view direction) [S2, unofficial].
3.  **Rasterization:**
    *   **Direct 3D Texture:** Rasterize the triangle into the 3D texture using the corresponding $VP_D$ matrix. The fragment shader computes the voxel index directly from the clip-space coordinates transformed by the scale and offset.
    *   **Sheet Buffer:** Rasterize the triangle into the 2D sheet buffer corresponding to axis $D$. The fragment shader outputs the voxel coordinates or occupancy flags.

#### 3. Synthesis (Worksheet Approach Only)
If using the worksheet method, the three sheet buffers must be transcoded into the final 2D worksheet texture.
1.  **Transform to Discrete Space:** For each element in the sheet buffers, transform the 2D coordinates back to the discrete 3D voxel space $(px, py, pz)$.
2.  **Map to Worksheet:**
    *   Determine the patch index by dividing $pz$ by $C$ (voxels per texel).
    *   Identify the texel location $(px, py)$ within the worksheet.
    *   Calculate the bit offset within the texel based on $pz \pmod C$ and $C$.
    *   Use a lookup table to determine the specific bit/component to modify.
3.  **Blending/Encoding:** Perform a blending operation or atomic bit-set at the calculated texel location to encode the voxel data [S2, unofficial].

#### 4. Post-Processing
1.  **Mipmap Generation:** Generate mipmaps for the filled 3D texture or worksheet to enable multi-resolution cone tracing or efficient sampling [S1, unofficial].
2.  **Solid Filling (Optional):** For closed objects, perform a 3D scan-fill operation to fill interior voxels. This traverses the volume slice by slice, checking scan lines for entry/exit points to set occupancy flags [S2, unofficial].

def synthesize_worksheet(sheet_buffers, voxel_size, C):
    worksheet = create_2d_texture(resolution=calculate_worksheet_res(voxel_size, C))
    
    for sheet in sheet_buffers:
        for element in sheet:
            # Transform 2D sheet coords to 3D voxel coords (px, py, pz)
            px, py, pz = transform_to_voxel_space(element)

### Parameters and Typical Values
*   **Voxel Resolution:** Default $64 \times 64 \times 64$ [S1, unofficial].
*   **Camera Offset:** $0.2f$ beyond bounding box max [S1, unofficial].
*   **Projection Scale:** $1.02f$ expansion factor (passed as $0.51f$ for half-width) [S1, unofficial].
*   **Voxels per Texel (C):** 32 for binary voxelization with 8-bit components [S2, unofficial].

### Edge Cases and Pitfalls
*   **Degenerate Rasterization:** If a triangle is parallel to the rasterization direction, 2D linear interpolation results in a line segment, causing missing voxels [S2, unofficial].
    *   *Solution:* Rasterize along the axis direction most parallel to the triangle's normal (maximizing projected area) [S2, unofficial]. In a 3-view setup, this usually means ensuring the triangle is processed by the view where it has the largest area, or relying on the union of all three views to cover gaps.
*   **Hardware Support:** Direct rendering to 3D textures was not supported in consumer PC graphics hardware at the time of the worksheet method's publication, necessitating the 2D worksheet approach [S2, unofficial]. Modern GPUs support `GL_TEXTURE_3D` with image loads/stores, making the direct approach viable.
*   **Precision:** Floating-point precision in fragment shaders when mapping clip-space to voxel indices can cause gaps or overlaps. Using integer arithmetic or careful scaling is recommended.

## Subtopics

### Slicing-based voxelization
A method that rasterizes the model the same number of times as the resolution of the volume along the Z-direction [S2, unofficial]. It renders to 3D textures directly, one slice at a time.
*   **Comparison:** It is significantly slower than the Orthographic Multi-View Voxelization (Worksheet) method. For a Blade model at $256^3$ resolution, slicing-based voxelization takes ~5 seconds, whereas the worksheet method takes ~100ms [S2, unofficial].
*   **Limitation:** Requires hardware support for rendering to 3D textures, which was lacking in consumer hardware at the time of the worksheet method's introduction [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N_{tris} \cdot V)$, where $N_{tris}$ is the number of triangles and $V$ is the number of views (3). The rasterization cost is proportional to the screen space coverage of the triangles.
*   **Memory Complexity:** $O(N_x \cdot N_y \cdot N_z)$ for the 3D texture, or $O(2^W \cdot 2^H)$ for the worksheet, where $2^W \cdot 2^H \approx N_x \cdot N_y \cdot N_z / C$.
*   **Performance:** The worksheet method is highly efficient, achieving real-time voxelization for complex models. For a $256^3$ volume, it takes ~100ms compared to 5s for slicing-based methods [S2, unofficial].
*   **Strengths:**
    *   Hardware-accelerated using standard rasterization pipelines.
    *   Robust against degenerate triangles via multi-view synthesis.
    *   Compact storage via the worksheet encoding (multiple voxels per texel).
*   **Limitations:**
    *   Requires post-processing (synthesis) if using the worksheet method.
    *   Occupancy-based; solid filling requires an additional 3D scan-fill pass for closed objects [S2, unofficial].
    *   Memory bandwidth intensive due to multiple writes to the texture/voxel grid.

## Background
Orthographic Multi-View Voxelization was developed as a solution for real-time voxelization of complex models, addressing the limitations of CPU-based traversal and view-dependent methods like Layered Depth Images (LDI) [S2, unofficial]. The method was introduced in the paper "Real-time Voxelization for Complex Models" [S2, unofficial]. It leverages the parallelism of GPU rasterization to project geometry onto three orthogonal planes, combining the results to form a complete 3D representation. The "worksheet" optimization was proposed to overcome the lack of 3D texture write support in consumer hardware at the time, encoding the 3D volume into a 2D texture for efficient storage and retrieval. This technique is foundational for voxel cone tracing and other GPU-accelerated volume rendering techniques [S1, unofficial].
