# Orthographic Multi-View Voxelization

Also called: 3-Direction Rasterization, 3-View Voxelization, Directional Sheet Buffer Voxelization, Orthographic 3D Texture Rasterization, Voxelization via Orthographic Projection, Worksheet Voxelization

## Overview
Orthographic Multi-View Voxelization converts 3D triangle meshes into a volumetric representation by rasterizing geometry along three principal axes (X, Y, Z) using orthographic cameras [S1, unofficial][S2, unofficial]. It distinguishes itself from direct 3D texture rasterization by using intermediate 2D "sheet buffers" that are transcoded into a compact 2D "worksheet" texture, avoiding the need for hardware support for direct 3D texture writes [S2, unofficial]. This method solves the problem of generating voxel data for volume rendering or cone tracing while maintaining high performance on standard consumer graphics hardware [S2, unofficial].

## How it works
The method operates in two primary variants: direct 3D texture writing and the sheet-buffer-to-worksheet synthesis. Both variants share the input of a triangle mesh and its bounding box, and the output of a voxelized volume representation.

### Inputs and Outputs
*   **Input:** Triangle mesh, scene bounding box ($bb_{min}, bb_{max}$), target voxel grid resolution ($V_x, V_y, V_z$).
*   **Output:** 
    *   Variant A: A 3D texture (e.g., RGBA32F) representing the voxel grid [S1, unofficial].
    *   Variant B: A 2D "worksheet" texture encoding the 3D voxel space [S2, unofficial].

### Data Structures

**Variant A: Direct 3D Texture**
*   `texture3D`: A 3D texture object. In software simulation, represented as `std::vector<GLfloat>` of size $4 \times V_x \times V_y \times V_z$, initialized to `0.0f` [S1, unofficial].
*   Uniforms passed to shader:
    *   `viewProject[0..2]`: Orthographic view-projection matrices for X, Y, Z axes [S1, unofficial].
    *   `scale`: Voxel grid scale, calculated as $(V_x/range_x, V_y/range_y, V_z/range_z)$ [S1, unofficial].
    *   `boxMin`: Scene bounding box minimum corner [S1, unofficial].

**Variant B: Sheet Buffer and Worksheet**
*   `SheetBuffers`: Three 2D buffers (one for each axis X, Y, Z) representing intermediate rasterization results [S2, unofficial].
*   `Worksheet`: A 2D texture of resolution $2^W \times 2^H$. It encodes the discrete voxel space ($2^L \times 2^M \times 2^N$) such that $2^L \times 2^M \times 2^N = 2^W \times 2^H \times C$, where $C$ is the number of voxels encoded per texel (e.g., $C=32$ for binary voxelization with four 8-bit components) [S2, unofficial].
*   **Voxel Access Logic (Worksheet):** To access voxel at coordinates $(px, py, pz)$:
    1.  Determine patch index: $patch\_index = pz / C$ [S2, unofficial].
    2.  Access texel at $(px, py)$ within the identified patch [S2, unofficial].
    3.  Determine bit offset within the texel component using $pz$ and $C$ [S2, unofficial].
    4.  Use a lookup table to extract the specific bits [S2, unofficial].

### Algorithm Steps

#### Variant A: Direct 3D Texture Rasterization
1.  **Initialization:**
    *   Calculate scene bounding box min/max. Compute range $R = bb_{max} - bb_{min}$ [S1, unofficial].
    *   Set camera offset $O = 0.2f$ [S1, unofficial].
    *   Clear the 3D texture to `RGBA(0,0,0,0)` [S1, unofficial].
    *   Disable multisampling, depth testing, and face culling [S1, unofficial].
    *   Bind the 3D texture as a read-write image buffer (e.g., `GL_RGBA8` or `GL_RGBA32F`) [S1, unofficial].
2.  **Matrix Setup:**
    *   Set orthographic frustum bounds to $1.02 \times$ the scene range on the viewing planes (half-width expansion of $0.51 \times$ range) [S1, unofficial].
    *   Set near plane to $0.1f$ and far plane to $1.2 \times$ range + offset [S1, unofficial].
    *   Generate three view-projection matrices for axes X, Y, and Z [S1, unofficial].
3.  **Rasterization Passes:**
    *   For each axis (X, Y, Z):
        *   Bind the corresponding `viewProject` matrix [S1, unofficial].
        *   Upload `scale` and `boxMin` uniforms [S1, unofficial].
        *   Rasterize the scene geometry. The shader transforms vertices to voxel space and writes occupancy/material data directly to the 3D texture using atomic operations or overwrites [S1, unofficial].
4.  **Post-Processing:**
    *   Generate mipmaps for the filled 3D texture to enable multi-resolution cone tracing [S1, unofficial].

#### Variant B: Sheet Buffer to Worksheet Synthesis
1.  **Stage 1: Rasterization (Sheet Buffers)**
    *   For each of the three axes (X, Y, Z):
        *   Identify triangles intersecting the current slab/volume.
        *   **Degeneracy Handling:** Determine the rasterization direction for each triangle. If a triangle is parallel to the current view direction (which would cause degenerate line segments due to 2D linear interpolation), rasterize it along the axis direction most parallel to its normal/orientation [S2, unofficial].
        *   Rasterize the triangle onto the corresponding 2D sheet buffer [S2, unofficial].
2.  **Stage 2: Texelization (Transformation)**
    *   Transform the voxel positions from the sheet buffers into 3D volume coordinates immediately [S2, unofficial].
    *   Use these coordinates to find the correct position in the worksheet [S2, unofficial].
    *   Add voxels to the worksheet via a blending operation at the corresponding location [S2, unofficial].
3.  **Stage 3: Synthesis (Transcoding)**
    *   Transcode the three directional sheet buffers into the final 2D worksheet texture [S2, unofficial].
    *   Transform each element to discrete voxel space.
    *   Encode the voxel data into the appropriate texel in the worksheet according to the $C$-voxels-per-texel layout [S2, unofficial].

### Pseudocode (Variant B Implementation)

```python
def orthographic_multi_view_voxelization(mesh, bb_min, bb_max, voxel_res, worksheet_res):
    """
    Variant B: Sheet Buffer to Worksheet Synthesis.
    voxel_res: (L, M, N) in powers of 2, e.g., (8, 8, 8) for 256^3
    worksheet_res: (W, H) in powers of 2
    C: voxels per texel
    """
    range_x = bb_max.x - bb_min.x
    range_y = bb_max.y - bb_min.y
    range_z = bb_max.z - bb_min.z
    
    # Calculate C based on worksheet and voxel resolutions
    # 2^L * 2^M * 2^N = 2^W * 2^H * C
    # C = (2^L * 2^M * 2^N) / (2^W * 2^H)
    total_voxels = (1 << voxel_res[0]) * (1 << voxel_res[1]) * (1 << voxel_res[2])
    total_texels = (1 << worksheet_res[0]) * (1 << worksheet_res[1])
    C = total_voxels / total_texels
    
    # Initialize Sheet Buffers
    sheet_x = create_2d_buffer(worksheet_res)
    sheet_y = create_2d_buffer(worksheet_res)
    sheet_z = create_2d_buffer(worksheet_res)
    
    # Stage 1: Rasterization
    for axis in [X, Y, Z]:
        sheet = get_sheet(axis)
        for triangle in mesh.triangles:
            # Check if triangle intersects current slab/volume
            if not intersects_slab(triangle, axis):
                continue
            
            # Degeneracy Handling: Choose rasterization direction
            # If triangle is parallel to 'axis', use dominant normal axis
            if is_parallel_to_view(triangle, axis):
                raster_axis = get_dominant_normal_axis(triangle)
            else:
                raster_axis = axis
            
            # Rasterize triangle onto sheet buffer
            rasterize_triangle_to_sheet(triangle, raster_axis, sheet)
            
    # Stage 2 & 3: Synthesis
    worksheet = create_2d_texture(worksheet_res)
    
    for axis in [X, Y, Z]:
        sheet = get_sheet(axis)
        for patch in sheet.patches:
            # Transform patch to discrete voxel space
            voxel_coords = transform_to_voxel_space(patch, axis)
            
            # Encode to worksheet
            for voxel in patch.voxels:
                px, py, pz = voxel_coords
                
                # Determine patch index in worksheet
                patch_index = pz // C
                
                # Access texel at (px, py) in the specific patch
                texel = worksheet.get_texel(px, py, patch_index)
                
                # Determine bit offset
                bit_offset = (pz % C) * bits_per_voxel
                
                # Update texel with voxel data using lookup table logic
                worksheet.update_texel(texel, bit_offset, voxel.data)
                
    return worksheet
```

### Parameters
*   **voxelTextureSize:** Default resolution of the voxel grid, typically `glm::uvec3(64, 64, 64)` [S1, unofficial].
*   **offset:** Camera extension distance beyond the bounding box, fixed at `0.2f` [S1, unofficial].
*   **projection_scale:** Frustum expansion factor applied to range, fixed at `1.02f` (passed as `0.51f` to half-width) [S1, unofficial].
*   **C (Voxels per Texel):** Depends on worksheet resolution and voxel resolution. Example: $C=32$ for binary voxelization if a texel is composed of four 8-bit components [S2, unofficial].

### Edge Cases and Pitfalls
*   **Degenerate Rasterization:** If a triangle is parallel to the rasterization direction, 2D linear interpolation results in a line segment, causing missing voxels. The solution is to rasterize along the direction most parallel to the triangle's orientation (dominant normal) [S2, unofficial].
*   **Hardware Support:** Direct 3D texture writes (Variant A) were not supported in consumer graphics hardware of PC platforms at the time of the original paper's writing, necessitating Variant B [S2, unofficial].

## Subtopics

### [Shadow Volume Voxelization](5629-shadow-volume-voxelization.md)
Shadow Volume Voxelization is a rasterization-based technique that generates a 3D shadow volume texture by voxelizing scene geometry into a 3D grid, where each voxel stores a bitmask representing which of its 8 constituent sub-voxels are occluded. It builds on Orthographic Multi-View Voxelization by replacing the standard occupancy flag with a 3-bit occlusion mask per coarse voxel, enabling multi-resolution shadow representation through mipmaps. Unlike standard binary voxelization, this method preserves partial occlusion information within each voxel, allowing for smoother shadow transitions and hierarchical shadow testing.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of triangles and $A$ is the average area of their projection onto the 2D buffers. The synthesis step is $O(V)$, where $V$ is the number of voxels.
*   **Memory Complexity:** 
    *   Variant A: $O(V)$ for the 3D texture.
    *   Variant B: $O(W \cdot H \cdot C)$ for the worksheet, where $C$ is voxels per texel.
*   **Measured Performance:** For a Blade model at $256^3$ resolution, the sheet-buffer method takes approximately 100ms, whereas slicing-based voxelization takes ~5 seconds [S2, unofficial].
*   **Strengths:** High performance on standard GPUs; avoids 3D texture write limitations; handles complex models efficiently.
*   **Limitations:** Requires careful handling of degenerate triangles; worksheet encoding adds complexity to voxel access.
*   **When to use:** When real-time or interactive voxelization is required on consumer hardware without 3D texture write support, or when memory bandwidth for 3D textures is a bottleneck.
*   **When not to use:** When direct 3D texture writes are supported and simpler access patterns are preferred, or when the scene is static and offline voxelization is acceptable.

## Background
Orthographic Multi-View Voxelization was introduced as a method for fast, hardware-accelerated voxelization of complex models for real-time applications [S2, unofficial]. It addresses the limitations of earlier slicing-based methods, which required rasterizing the model once per volume slice (e.g., 256 times for a $256^3$ grid), resulting in significant performance penalties [S2, unofficial]. The method leverages standard 2D rasterization hardware by using multiple orthographic views and synthesizing the results into a compact 2D representation [S2, unofficial].
