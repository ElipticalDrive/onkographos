# Iterative Volume Refinement

Also called: Scattering Voxel Removal, Volume Refinement

## Overview
Iterative Volume Refinement is a post-initialization algorithm that cleans and smooths a sparse voxel cloud generated from multi-view depth maps by removing scattering voxels and smoothing sharp corners to increase coding gain [S1, S2]. It distinguishes itself from static voxelization by dynamically regenerating voxels based on a smooth surface assumption and iteratively re-evaluating visibility, ensuring the final volume accurately represents the real scene for virtual view synthesis [S1, S2].

## How it works
**Inputs:**
*   Initial sparse voxel cloud $V$ generated by registering estimated depth maps from $N$ reference views [S1, S2].
*   $N$ reference images $I_1, \dots, I_N$ with known camera parameters [S1].
*   Threshold $\tau$ for Mean Square Error (MSE) [S1].
*   Window size $W \times W$ (e.g., $3 \times 3$) for error calculation [S1, S2].

**Outputs:**
*   Refined voxel cloud $V'$ where scattering voxels are removed and surface corners are smoothed [S1, S2].

**Data Structures:**
*   **Voxel:** A 3D grid cell containing a depth value $d$ and a color value $C$. The color is temporarily defined as the median of color values from all visible views [S1].
*   **Visibility Map:** For each view, determines which voxels are visible (front-most along the ray) and which are occluded [S1].

**Steps:**

1.  **Initialization:** Register estimated depth maps to create the initial volume $V$ [S2].
2.  **Color Assignment:** Temporarily define the color $C_v$ for each voxel $v \in V$ by taking the median of color values from all visible views [S1].
3.  **Iterative Refinement Loop:** Repeat the following until no voxels are removed or generated in a full pass:
    1.  **Reconstruction:** Reconstruct images from the current volume $V$ [S1, S2].
    2.  **View Processing:** Iterate through reference views (e.g., from furthest left to furthest right) [S1].
    3.  **Error Calculation:** For each view $I_k$, calculate the Mean Square Error (MSE) between the reconstructed view and the original reference image $I_k$ using a window-based computation of size $W \times W$ [S1, S2]. This handles inaccurate camera calibration and unequal resolutions [S1, S2].
        $$ \text{MSE}_k = \frac{1}{|W|} \sum_{(x,y) \in W} (R_k(x,y) - I_k(x,y))^2 $$
        Where $R_k$ is the reconstructed image and $I_k$ is the reference image [S1].
    4.  **Voxel Removal:** If $\text{MSE}_k > \tau$, remove the old depth and its associated voxel [S1].
    5.  **New Depth Investigation:** Derive a new depth value from neighboring pixels based on a smooth surface assumption [S1].
    6.  **Voxel Generation:** If the new depth value meets color constraints for all visible views, generate the new associated voxel [S1].
    7.  **Visibility Update:** If any voxels are removed or generated, update the visibility map, as changes in voxel position produce new depths that might change an invisible point to a visible point and vice versa [S1, S2].

**Parameters:**
*   Threshold $\tau$: Not given in the sources.
*   Window size $W$: Typically $3 \times 3$ pixels [S1, S2].

**Edge Cases and Pitfalls:**
*   **Inaccurate Calibration:** Unequal resolutions and calibration errors can displace mapped pixels. Using a window-based computation ($3 \times 3$) instead of single-pixel comparison mitigates this [S1, S2].
*   **Visibility Changes:** Removing or adding a voxel changes the depth along rays, potentially altering the visibility of other voxels. The algorithm must re-evaluate visibility after every modification [S1, S2].
*   **Color Definition:** The median color assignment is temporary and may need re-evaluation if visibility changes significantly [S1].

## Operating characteristics
*   **Time Complexity:** Iterative, with convergence dependent on the number of scattering voxels and the complexity of the scene. The source notes 26 iterations for a five-view Leo sequence [S1].
*   **Memory Complexity:** Sparse voxel cloud, significantly reduced from the initial volume by removing scattering voxels [S1, S2].
*   **Strengths:** Improves coding gain by smoothing sharp corners and removing noise; handles non-Lambertian reflections and inaccurate camera calibration [S1, S2].
*   **Limitations:** Requires multiple iterations; performance depends on the initial quality of depth maps [S1, S2].
*   **When to Use:** When high-quality virtual view synthesis is required from sparse multi-view inputs, and the initial voxelization contains significant noise or scattering [S1, S2].

## Background
*   **Origin:** Proposed in "Colour volumetric compression for realistic view synthesis applications" (2010) and "Volumetric Representation for Sparse Multi-Views" (2006) [S1, S2].
*   **History:** Developed to address errors in constructed volumes that adversely affect virtual view synthesis, particularly in multi-view video applications [S1, S2].
*   **Usage:** Used in volumetric compression and sparse multi-view representation for realistic view synthesis [S1, S2].
