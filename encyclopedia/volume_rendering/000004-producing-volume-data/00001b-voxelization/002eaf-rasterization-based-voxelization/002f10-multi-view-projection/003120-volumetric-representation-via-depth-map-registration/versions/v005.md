# Volumetric Representation via Depth Map Registration

Also called: Sparse Non-Lambertian Multi-view Volume Construction, Volume Initialization

## Overview
This method constructs a 3D sparse voxel volume from a set of multi-view images by registering estimated depth maps into a voxel grid [S1]. It solves the problem of non-Lambertian reflection artifacts by using individual minimum cost per view for depth estimation rather than a global threshold, representing scene geometry as a sparse voxel cloud where voxel values indicate the number of views mapping to that location [S1]. It is distinguished from sibling methods by its explicit iterative refinement loop that removes scattering voxels and smooths sharp corners to increase coding gain, rather than relying solely on the initial registration [S1].

## How it works
**Inputs:** A set of $N$ reference views (images and camera parameters); estimated depth maps for each view.
**Outputs:** A 3D sparse voxel grid where each occupied voxel $(i, j, k)$ holds a weight $\delta_{ijk}$ (count of views) and a color value.

**Data Structures:**
*   **Voxel Grid:** A sparse 3D structure. Each entry at index $(i, j, k)$ contains:
    *   $\delta_{ijk}$: Integer counter, initialized to 0. Represents the number of views mapping to this voxel.
    *   $C_{ijk}$: Color value (RGB), updated during refinement.
*   **Depth Map:** 2D array per view, storing depth values $d$ and associated weights $\delta$.

**Steps:**

1.  **Volume Initialization (Registration):**
    For each reference view $v \in \{1, \dots, N\}$:
    *   Estimate a depth map for view $v$. The depth estimation compensates for non-Lambertian reflection by exploiting the individual minimum cost for that view [S1].
    *   Register the depth map into the 3D volume. For each voxel $(i, j, k)$ hit by the depth ray:
        $$ \delta_{ijk} = \begin{cases} n & \text{if registering depth} \\ 0 & \text{otherwise} \end{cases} $$
        where $n$ is the count of views mapping to the voxel [S1].

2.  **Isolated Voxel Removal and Depth Refinement:**
    *   Detect isolated voxels (those with no neighbors) in the current volume [S1].
    *   Project the volume back to the reference view geometry to build new depth maps. This step removes errors from the previous registration by incorporating depth information from other views [S1].
    *   If multiple depth values exist for a pixel in the projected map, consider the front cluster of depths. Determine the proper depth value $d$ for a pixel:
        $$ d = \begin{cases} d_n & \text{if only one depth has } \delta_n = \max(\delta_K) \\ \frac{\sum_{k=1}^K \delta_k d_k}{\sum_{k=1}^K \delta_k} & \text{otherwise} \end{cases} $$
        where $K$ is the number of depth values in the front cluster, $d_k$ is the depth value, and $\delta_k$ is the voxel weight [S1].
    *   Reconstruct the volume again. Interpolate voxels to connect the surface of the volume among near voxels [S1].

3.  **Iterative Volume Refinement:**
    *   Temporarily define voxel colors $C_{ijk}$ by taking the median of color values from all visible views [S1].
    *   Iterate through reference views (e.g., from furthest left to furthest right) [S1]:
        *   Calculate the Mean Square Error (MSE) between the reconstructed view and the original reference image. Use a window-based computation (e.g., 3x3 pixels) for error calculation to handle inaccurate camera calibration and unequal resolutions [S1].
        *   If the MSE exceeds a threshold:
            *   Remove the old depth and its associated voxel [S1].
            *   Investigate a new depth derived from neighboring pixels based on a smooth surface assumption [S1].
            *   If the new depth value meets color constraints for all visible views, generate the new associated voxel [S1].
    *   If any voxels are removed or generated, iteratively reconstruct images, as changes in voxel position affect visibility (invisible points may become visible and vice versa) [S1].
    *   Repeat the refinement loop until no new voxels are generated and no old voxels are removed [S1].

**Pseudocode:**

```python
def depth_map_registration(volume, views, depth_maps):
    """
    volume: SparseVoxelGrid initialized to 0
    views: List of View objects (camera params, image)
    depth_maps: List of 2D arrays, one per view, containing depth values
    """
    # Step 1: Initialization
    for view_idx, depth_map in enumerate(depth_maps):
        for y, x in depth_map.nonzero():
            depth_val = depth_map[y, x]
            # Project depth_val from view_idx to 3D voxel coordinates (i, j, k)
            i, j, k = project_to_voxel(views[view_idx], x, y, depth_val)
            if (i, j, k) is valid:
                volume[i, j, k].delta += 1

    # Step 2: Isolated Voxel Removal and Depth Refinement
    remove_isolated_voxels(volume)
    
    # Re-project to get refined depth maps
    refined_depth_maps = []
    for view in views:
        new_depth_map = project_volume_to_view(volume, view)
        # Handle multiple depths per pixel using front cluster logic
        final_depth_map = resolve_front_cluster(new_depth_map, volume)
        refined_depth_maps.append(final_depth_map)
        
    # Reconstruct volume with refined depths
    volume = reconstruct_volume(views, refined_depth_maps)
    
    # Interpolate to connect surface
    interpolate_voxels(volume)

    # Step 3: Iterative Refinement
    # Initialize colors with median of visible views
    for voxel in volume.active_voxels():
        voxel.color = median_color(voxel, views)

    converged = False
    while not converged:
        converged = True
        for view in views:
            # Calculate MSE using 3x3 window
            mse = calculate_windowed_mse(view, volume)
            
            if mse > threshold:
                # Remove old depth/voxel
                old_depth = get_depth_from_volume(view, volume)
                remove_voxel_at_depth(volume, view, old_depth)
                converged = False # Need to re-evaluate
                
                # Investigate new depth from neighbors
                new_depth = estimate_smooth_depth(view, volume)
                
                # Check color constraints
                if meets_color_constraints(new_depth, volume, views):
                    add_voxel_at_depth(volume, view, new_depth)
                    converged = False # Need to re-evaluate
                    
    return volume

def resolve_front_cluster(depth_map, volume):
    """
    For each pixel, if multiple depths map to it, select the front cluster
    and compute weighted average or max delta depth.
    """
    result = empty_depth_map()
    for y, x in depth_map.nonzero():
        depths = get_depths_at_pixel(depth_map, y, x)
        # Group depths into clusters (front cluster is closest to camera)
        front_cluster = get_front_cluster(depths)
        
        if len(front_cluster) == 1:
            d = front_cluster[0].depth
        else:
            # Weighted average
            numerator = sum(d.delta * d.depth for d in front_cluster)
            denominator = sum(d.delta for d in front_cluster)
            d = numerator / denominator if denominator != 0 else front_cluster[0].depth
        result[y, x] = d
    return result
```

## Subtopics

### Iterative Volume Refinement
An iterative algorithm to refine the shape of the volume by removing scattering voxels and smoothing sharp corners to increase coding gain [S1]. It compares reconstructed views against original reference images to identify and correct geometry errors [S1]. It is chosen when high coding efficiency and accurate surface representation are required, particularly for scenes with non-Lambertian properties where initial registration leaves artifacts [S1].

## Operating characteristics
*   **Time Complexity:** The initialization is linear with respect to the number of depth map pixels and views. The refinement step is iterative and its complexity depends on the number of iterations required for convergence and the number of voxels modified per iteration [S1].
*   **Memory Complexity:** Sparse voxel grid, storing only occupied voxels. The size depends on the scene complexity and resolution [S1].
*   **Performance:** The method is described as "simple and fast" for the initialization step [S1]. The refinement step can be computationally intensive due to iterative reconstruction and error calculation [S1].
*   **Strengths:** Handles non-Lambertian reflections well by using per-view minimum cost; removes isolated noise voxels; smooths sharp corners to improve coding gain [S1].
*   **Limitations:** Requires accurate initial depth estimation; sensitive to camera calibration errors (mitigated by window-based MSE) [S1].
*   **When to use:** When constructing volumes for view synthesis applications where coding efficiency and visual quality are critical, and the scene contains non-Lambertian surfaces [S1].

## Background
The method was proposed in the context of color volumetric compression for realistic view synthesis applications [S1]. It builds on the principle that depth registration methods provide a good representation for natural scenery [S1]. The specific iterative refinement algorithm was introduced to address the reduction of coding gain caused by sharp corners and scattering voxels in the initial volume [S1].
