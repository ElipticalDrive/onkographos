# Volumetric Representation via Depth Map Registration

Also called: Sparse Non-Lambertian Multi-view Volume Construction, Volume Initialization

## Overview
This method constructs a 3D volumetric representation from a set of multi-view images by registering estimated depth maps into a voxel grid [S1]. It specifically addresses the challenge of non-Lambertian reflections by utilizing individual minimum cost per view for depth estimation rather than relying on a global threshold [S1]. The resulting volume is represented as a sparse voxel cloud where voxel values indicate the count of views mapping to that location, providing a robust initialization for subsequent volume refinement and color selection [S1]. It differs from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by using depth registration rather than direct rasterization, and from [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) by employing a per-view cost minimization strategy to handle specularities and non-Lambertian surfaces [S1].

## How it works
**Inputs:** A set of $N$ reference views, each with known camera parameters and associated color images. A depth estimation algorithm capable of producing depth maps with associated confidence or cost metrics.

**Outputs:** A 3D voxel grid where each voxel $(i, j, k)$ holds an integer value $\delta_{ijk}$ representing the number of views that mapped to that voxel location.

**Data Structures:**
*   **Voxel Grid:** A 3D array or sparse hash map.
    *   Key: Voxel coordinates $(i, j, k)$.
    *   Value: Integer $\delta_{ijk} \in \{0, 1, \dots, N\}$.
    *   Layout: Not specified in the sources. [G] Implementation typically uses a 3D array for dense regions or a hash map for sparse regions.

**Algorithm Steps:**

1.  **Depth Estimation and Registration:**
    For each reference view $v \in \{1, \dots, N\}$:
    a. Estimate a depth map $D_v$ by searching along the view's geometry.
    b. Compensate for non-Lambertian reflections by selecting the depth value corresponding to the individual minimum cost for each pixel, rather than a global threshold [S1].
    c. Register the depth map into the 3D volume. For each pixel $(u, v)$ in the image with depth $d$, project the point into 3D space to determine voxel coordinates $(i, j, k)$.
    d. Update the voxel value $\delta_{ijk}$:
       $$
       \delta_{ijk} = \begin{cases} 
       n & \text{if registering depth} \\
       0 & \text{otherwise}
       \end{cases}
       $$
       where $n$ is the count of views mapping to the voxel [S1].

2.  **Isolated Voxel Detection and Depth Refinement:**
    a. Detect isolated voxels that have no neighbors (i.e., $\delta_{ijk} = 0$ for all adjacent voxels) [S1].
    b. Project the current volume back to the reference view geometry to build new depth maps. This step removes errors from the previous registration step by incorporating depth information from other views [S1].
    c. If multiple depth values exist for a single pixel in the projected map, identify the "front cluster" of depths. Ideally, there is one depth value from the front surface, but spurious noise causes dispersion [S1].
    d. Determine the proper depth value $d$ for a pixel using the following formula:
       $$
       d = \begin{cases} 
       d_n & \text{if only one depth has } \delta_n = \max(\delta_K) \\
       \frac{\sum_{k=1}^{K} \delta_k d_k}{\sum_{k=1}^{K} \delta_k} & \text{otherwise}
       \end{cases}
       $$
       where $K$ is the number of depth values in the front cluster, $d_k$ is the depth value, and $\delta_k$ is the voxel weight (count of views mapping to the voxel containing depth $d_k$) [S1].

3.  **Volume Reconstruction and Interpolation:**
    a. Reconstruct the volume using the refined depth values [S1].
    b. Interpolate voxels to connect the surface of the volume among near voxels, filling gaps caused by isolated voxels or registration errors [S1].

            # Find max delta in the cluster

            max_delta_depths = [d for d in front_cluster if d.delta == max_delta]

                d = max_delta_depths[0].depth
            else:
                # Weighted average of all depths in front cluster
                numerator = sum(d.delta * d.depth for d in front_cluster)
                denominator = sum(d.delta for d in front_cluster)
                if denominator == 0:
                    d = front_cluster[0].depth
                else:
                    d = numerator / denominator
            
            new_depth_map[(pixel_u, pixel_v)] = d
        refined_depth_maps[view.id] = new_depth_map

    # Step 3: Volume Reconstruction and Interpolation
    # Clear old volume and rebuild with refined depths
    volume_grid.clear()
    for view in views:
        depth_map = refined_depth_maps[view.id]
        for pixel_u, pixel_v in depth_map:
            depth_val = depth_map[(pixel_u, pixel_v)]

                i, j, k = voxel_coords
                volume_grid[(i, j, k)] = volume_grid.get((i, j, k), 0) + 1

    volume_grid = interpolate_voxels(volume_grid)
    
    return volume_grid

    isolated = []
    for (i, j, k), count in volume_grid.items():
        if count == 0:
            continue
        has_neighbor = False
        for di in [-1, 0, 1]:
            for dj in [-1, 0, 1]:

                if has_neighbor: break
            if has_neighbor: break

## Subtopics

### Iterative Volume Refinement
An iterative algorithm to refine the shape of the volume by removing scattering voxels and smoothing sharp corners to increase coding gain [S1]. It compares reconstructed views against original reference images to identify and correct geometry errors [S1].
*   **Definition:** A post-processing step that improves the initial volume by removing noise and smoothing surfaces [S1].
*   **Steps:**
    1.  Temporarily define voxel colors by taking the median of color values from all visible views [S1].
    2.  Iterate through reference views (e.g., from furthest left to furthest right) [S1].
    3.  For each view, calculate the Mean Square Error (MSE) between the reconstructed view and the original reference image [S1].
    4.  If the MSE exceeds a threshold, remove the old depth and its associated voxel [S1].
    5.  Investigate a new depth derived from neighboring pixels based on a smooth surface assumption [S1].
    6.  If the new depth value meets color constraints for all visible views, generate the new associated voxel [S1].
    7.  Use a window-based computation (e.g., 3x3 pixels) for error calculation to handle inaccurate camera calibration and unequal resolutions [S1].
    8.  Iteratively reconstruct images if voxels are removed or generated, as voxel position changes affect visibility [S1].
    9.  Repeat until no new voxels are generated and no old voxels are removed [S1].
*   **When to choose:** When the initial volume contains significant scattering voxels or sharp corners that reduce coding gain, and high-fidelity view synthesis is required [S1].

## Operating characteristics
*   **Time Complexity:** Not explicitly given. The registration step is $O(N \cdot W \cdot H)$ where $N$ is the number of views and $W, H$ are image dimensions. The refinement step is iterative and depends on the number of iterations and views [S1].
*   **Memory Complexity:** Proportional to the number of voxels in the volume. The volume is sparse, so memory usage depends on the scene complexity and resolution [S1].
*   **Measured Performance:** The method was tested on the "Leo sequence" with five views, requiring 26 iterations for refinement [S1].
*   **Strengths:** Handles non-Lambertian reflections effectively by using per-view minimum cost. Provides a good representation for natural scenery. The iterative refinement removes scattering voxels and smooths sharp corners [S1].
*   **Limitations:** Requires accurate depth estimation. Inaccurate camera calibration and unequal resolutions can displace mapped pixels, requiring window-based error calculation [S1]. The iterative refinement can be computationally expensive [S1].
*   **When to use:** When constructing a volume from multi-view images with non-Lambertian surfaces and when high-quality view synthesis is the goal [S1].
*   **When not to use:** When real-time performance is critical and the iterative refinement is too slow, or when the input views have poor calibration [S1].

## Background
The method was proposed in the context of color volumetric compression for realistic view synthesis applications [S1]. It builds on the principle that depth registration methods provide a good representation for natural scenery [S1]. The work addresses the limitations of global thresholding in depth estimation, which fails to handle non-Lambertian reflections, by introducing individual minimum cost per view [S1]. The iterative refinement step was introduced to improve the shape of the volume by removing scattering voxels and smoothing sharp corners, which are known to reduce coding gain in volumetric compression [S1].
