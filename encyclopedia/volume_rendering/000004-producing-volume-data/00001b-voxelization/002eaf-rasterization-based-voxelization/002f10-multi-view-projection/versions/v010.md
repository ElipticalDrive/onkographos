# Multi-view projection
Also called: Multi-view rasterization, Orthographic multi-view voxelization, 3-pass voxelization

## Overview
Multi-view projection voxelization converts a triangle mesh into a voxel grid by rasterizing the geometry from multiple distinct camera viewpoints, typically aligned with the principal axes of the scene's bounding box. This approach solves the problem of geometric gaps, cracks, and missing data that occur in single-view projection methods when surfaces are parallel to the view direction or when thin geometry is undersampled. It differs from single-view methods by aggregating fragments from orthogonal perspectives to ensure complete coverage, and from compute-shader-based methods by leveraging standard graphics pipeline rasterization for fragment generation.

## Shared principles
The family relies on the principle that a 3D volume can be approximated by projecting 2D slices or rays from multiple directions. The core mechanism involves:
1.  **Orthographic Projection:** Cameras are positioned at infinity (or effectively so) along specific axes (e.g., X, Y, Z) to create orthographic view frustums.
2.  **Rasterization:** Triangle meshes are rasterized into 2D buffers (depth, color, or occupancy) from each viewpoint.
3.  **Aggregation:** Results from multiple views are combined. This can be done by writing directly to a 3D texture using atomic operations, or by synthesizing intermediate 2D buffers into a final 3D representation.
4.  **Coverage Guarantee:** By using views aligned with the principal axes, the method ensures that no surface normal is perpendicular to all view directions, thereby minimizing "blind spots" where a triangle might project to a line or pixel and be missed.

## Subtopics

### [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md)
This method produces 6-separating (tunnel-free) voxelization using only a single 2D orthographic projection along the dominant axis of a triangle's normal vector, leveraging the thinness property of the voxel grid. It differs from its sibling [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) and [3-Pass Voxelization](5300-3-pass-voxelization.md) by eliminating the need for multiple projection passes, reducing computational overhead at the cost of more complex per-pixel edge handling. It builds on the shared principles of [Multi-view projection](5937-multi-view-projection.md).

### [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md)
Orthographic Multi-View Voxelization rasterizes scene geometry into a 3D texture using three orthographic cameras aligned with the scene's bounding box axes to create a voxelized representation for subsequent volume rendering. It differs from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by using multiple views to ensure coverage and from [3-Pass Voxelization](5300-3-pass-voxelization.md) by synthesizing the result into a final "worksheet" texture rather than leaving it in intermediate slab buffers.

### [3-Pass Voxelization](5300-3-pass-voxelization.md)
3-Pass Voxelization is a rasterization-based technique that eliminates cracks and missing data in the voxel grid by rendering the scene from three distinct orthographic views aligned with the principal axes (X, Y, and Z). Unlike single-view projection methods which suffer from geometric distortion or gaps for surfaces parallel to the view direction, this method ensures accurate voxel occupancy by aggregating fragments from all three orthogonal perspectives. It builds on the shared principles of [Multi-view projection](5937-multi-view-projection.md) but restricts camera orientations to the three cardinal axes to guarantee coverage of all surface normals.

### [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md)
This method constructs a 3D volumetric representation from a sparse set of calibrated multi-view images by registering estimated depth maps into a voxel grid. It addresses the challenge of representing non-Lambertian scenes where global depth thresholds fail, using individual minimum cost per view for depth estimation. It distinguishes itself from static voxelization methods by incorporating an iterative refinement loop that removes isolated noise voxels and smooths sharp corners to maximize coding gain for virtual view synthesis.

#### Multi-View Stereo Cost Volume Construction
**Definition:** A cost volume $V_c$ is constructed from feature volumes $\{Vf_i\}$ of $N$ reference views to perceive coarse scene structure and provide scene priors for sampling, skipping blank areas [S1].
**Parameter:** $L$: Number of depth layers in the cost volume. Typical value: 16 [S1].
**Pitfall:** Checkerboard artifacts caused by deconvolution layers in the Res-Unet processing the cost volume are eliminated by replacing deconvolution with combinations of upsampling and convolution layers [S1].

## Background
Multi-view projection techniques originated in the field of computer graphics and computer vision as a robust alternative to single-view voxelization. The "3-Pass" approach became standard in real-time rendering pipelines to handle dynamic geometry where single-view methods failed to capture thin structures or surfaces facing away from the camera. The use of orthographic cameras simplifies the mapping between screen space and voxel space, as depth is linear with respect to the world coordinate along the view axis.

In the context of Neural Radiance Fields (NeRF) and Multi-View Stereo (MVS), multi-view projection principles are extended to construct cost volumes for depth estimation. Recent works, such as NeRF-SDP, utilize multi-view stereo matching to construct cost volumes that provide scene priors, improving the efficiency of sampling and reducing blank areas in the reconstructed volume [S1].
