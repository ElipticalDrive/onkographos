# Multi-view projection

Also called: 3-pass voxelization, multi-axis rasterization

## Overview
Multi-view projection voxelization produces a 6-separating (tunnel-free) voxel representation of a triangle mesh by rasterizing the geometry from multiple orthogonal viewpoints, typically aligned with the principal axes of the scene bounding box. It solves the problem of geometric artifacts such as cracks and missing voxels that occur when voxelizing from a single direction, particularly when triangle normals are parallel to the view vector. It sets itself apart from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by using multiple views to guarantee coverage regardless of local surface orientation, and from [3D Grid Rasterization](903-3d-grid-rasterization.md) by operating in screen space (image-space) rather than world-space grid traversal.

## Shared principles
The family relies on the principle that rasterizing a 3D triangle from multiple orthogonal directions ensures that every voxel intersected by the triangle is covered by at least one view, provided the views are sufficiently separated.

1.  **Orthogonal Views:** The scene is rasterized from cameras positioned along the principal axes (X, Y, Z). For each axis, a view-projection matrix is constructed.
2.  **Dominant Axis Selection:** To avoid degenerate projections (where a triangle appears as a line or point), each triangle is rasterized along the axis where its normal has the largest component, or all three axes are used to ensure robustness [S2, unofficial].
3.  **Voxel Space Mapping:** The rasterization output is mapped directly to voxel coordinates. This involves scaling the clip-space coordinates to the voxel grid resolution and offsetting by the bounding box minimum [S1, unofficial].
4.  **Atomic Writes:** When multiple triangles or views write to the same voxel, atomic operations are often used to prevent race conditions if the implementation is parallel [G].
5.  **6-Separation:** The resulting voxel grid is 6-separating, meaning no two occupied voxels share only an edge or vertex without sharing a face, ensuring tunnel-free connectivity for subsequent ray marching or cone tracing [S1, unofficial].

## Subtopics

### [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md)
A method that achieves 6-separation using only a single 2D rasterization pass per triangle, determined by the triangle's dominant normal axis. It is chosen for high performance on planar geometry but may fail if the dominant axis selection is not robust or if the triangle is nearly parallel to the projection plane.

### [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md)
Rasterizes geometry into a 3D texture using three orthographic cameras aligned with the scene's bounding box axes. It synthesizes these views into a final worksheet texture. It ensures robust coverage by rasterizing each triangle along its dominant axis, avoiding the degeneracy issues of [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md).

### [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md)
Constructs a 3D volume by registering estimated depth maps from multiple reference views into a voxel grid. It handles non-Lambertian reflections by using per-pixel minimum cost for depth selection. It differs from direct rasterization methods by using depth estimation and registration rather than triangle rasterization.

### 3-Pass Voxelization
#### definition
- [S1, unofficial] A voxelization approach that fixes cracks and missing data in the voxel grid by voxelizing the scene from each of the 3 major axes, requiring 3 render passes.
#### step
- [S1, unofficial] For each of the 3 major axes, multiply the clip-space projection matrix by a rotation matrix corresponding to that axis to generate fragments from that view-axis.
- [S1, unofficial] Use the voxel-space projection matrix without multiplying it by the rotation matrix, as it already maps all values properly.
#### pitfall
- [S1, unofficial] Requires 3 render calls per rendered object, which becomes expensive as models become more complex.
- [S1, unofficial] If optimizing by separating dynamic and static objects, the voxel grid of dynamic objects must be cleared every frame, requiring separate voxel grids for dynamic and static objects.

## Background
The concept of multi-view voxelization originates from the need to create robust voxel representations for real-time global illumination, specifically for voxel cone tracing. The seminal work by Ize et al. (2010) introduced voxelization techniques for real-time ray-traced global illumination, highlighting the issue of cracks when voxelizing from a single direction [S1, unofficial]. The "3-pass voxelization" method was proposed as a simple solution to cover cracks by rasterizing from three orthogonal axes. This approach has since been refined in various implementations, including those using GPU compute shaders and optimized worksheet data structures for memory efficiency.
