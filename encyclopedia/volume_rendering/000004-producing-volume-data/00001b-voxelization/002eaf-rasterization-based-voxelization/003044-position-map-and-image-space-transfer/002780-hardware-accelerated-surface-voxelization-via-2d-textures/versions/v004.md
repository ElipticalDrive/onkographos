# Hardware-accelerated surface voxelization via 2D textures

Also called: Image-space voxelization

## Overview
This method transfers intersection computation from geometric space to image space by rasterizing model surfaces into 2D textures, enabling collision detection and volumetric rendering at real-time frame rates [S1, unofficial]. It differs from slicing-based voxelization by rasterizing the model approximately once rather than $N$ times (where $N$ is the volume resolution along $z$), making performance insensitive to scene complexity [S1, unofficial]. Unlike Layered Depth Image (LDI) extraction, it is view-independent and avoids CPU-side sorting of depth lists [S1, unofficial]. Builds on [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md). Siblings: [Position Map Voxelization](2604-position-map-voxelization.md), [Billboard Voxelization](2659-billboard-voxelization.md).

## How it works
**Inputs and Outputs:**
*   **Input:** Polygonal mesh (vertices, normals, triangles) or implicit surface definition; volume resolution $D$; bounding box parameters ($p_{min}, p_{max}$) [S1, unofficial].
*   **Output:** 2D texture(s) representing the voxelized volume data in image space [S1, unofficial].

**Data Structures:**
The volume is stored in 2D textures (worksheets) [S1, unofficial]. The bit-depth per voxel depends on the resolution:
*   **512^3 resolution:** 1 bit per voxel, stored in one worksheet [S1, unofficial].
*   **256^3 resolution:** 8 bits per voxel [S1, unofficial].
*   **128^3 resolution:** 16 bits per voxel (used to encode vertex normals) [S1, unofficial].
*   **64^3 resolution:** 8 bits per voxel [S1, unofficial].

**Steps:**
1.  **Rasterization:** Rasterize the model surfaces into 2D textures. This step traverses the model approximately once, and its performance depends mainly on the number of triangles [S1, unofficial].
2.  **Texelization and Synthesis:** Convert rasterized fragments into voxel data. Texelization and synthesis are image-space operations dominated by volume resolution and bit-depth [S1, unofficial].
3.  **Collision Query:** Perform collision detection by querying the generated 2D textures in image space [S1, unofficial].
4.  **Rendering:** Render the volume data and voxelized slices orderly in 3D space to display complex deformable geometric models semi-transparently [S1, unofficial].

**Formulas:**
The mapping from world position $p$ to voxel index $i$ follows the standard formula defined in the parent article [G]:
$$
i = D \times \frac{p - p_{min}}{p_{max} - p_{min}}
$$
For implicit surfaces, the surface is defined by $f(x,y,z) = 0$. The example given is $x^4 - 5x^2 + y^4 - 5y^2 + z^4 - 5z^2 + 11.8 = 0$ [S1, unofficial]. Both surface and solid voxelization for this implicit surface take 25ms at 256^3 resolution [S1, unofficial].

**Parameters:**
*   **Volume Resolution:** 256^3 is identified as a good choice under current hardware conditions (ATI Radeon 9800 Pro) [S1, unofficial].
*   **Bit-depth:** 8 bits per voxel for the standard 256^3 configuration [S1, unofficial].
*   **Hardware:** Implemented using Vertex/Pixel Shader 2.0 of Direct3D 9.0b [S1, unofficial].

**Pitfalls:**
*   **Aliasing:** Aliasing effects exist in solid voxelization for closed polygonal models, appearing as prolonged lines where some voxels at the rasterization stage are missing [S1, unofficial].
*   **Bit-operations Cost:** Bit-operations are much more expensive than byte-operations [S1, unofficial].
*   **Memory Constraints:** If multivalued voxelization is required for high resolution, multiple worksheets are needed given sufficient video memory [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The algorithm traverses the model approximately once, making performance insensitive to scene complexity [S1, unofficial]. Rasterization timings depend mainly on the number of triangles [S1, unofficial]. Texelization and synthesis are image-space operations dominated by volume resolution and bit-depth [S1, unofficial].
*   **Memory Complexity:** Depends on volume resolution and bit-depth [S1, unofficial]. For 512^3 with 1-bit depth, memory is 16MB [S1, unofficial]. For 256^3 with 8-bit depth, memory is 16MB [S1, unofficial]. For 128^3 with 16-bit depth, memory is 4MB [S1, unofficial]. For 64^3 with 8-bit depth, memory is 256KB [S1, unofficial].
*   **Measured Performance:**
    *   **Hardware:** PC with 2.4 GHz Pentium IV CPU, 2GB RAM, ATI Radeon 9800 Pro (256MB RAM) [S1, unofficial].
    *   **Blade Model (1,765,388 triangles):** 75ms for rasterization at 256^3 resolution [S1, unofficial]. Slicing-based voxelization for the same model at 256^3 costs about 5 seconds (20.8ms x 256) [S1, unofficial].
    *   **Wagner Model (60,246 triangles):** 512^3, 1-bit: 500ms [S1, unofficial]. 256^3, 8-bit: 30ms [S1, unofficial]. 128^3, 16-bit: 24ms [S1, unofficial]. 64^3, 8-bit: 21ms [S1, unofficial].
    *   **Implicit Surface:** 25ms at 256^3 resolution [S1, unofficial].
    *   **Visualization:** Costs about 8ms on average, depending mainly on volume resolution [S1, unofficial].
    *   **Hybrid Rendering:** Transparent cerebra model (36,758 triangles) with MRI head volume (128^3) achieves about 10 fps [S1, unofficial].
*   **Strengths:** Real-time frame rates for collision detection and volumetric rendering; insensitive to scene complexity; simple, robust, and easy-to-implement [S1, unofficial].
*   **Limitations:** Aliasing effects in solid voxelization for closed polygonal models; bit-operations are expensive; requires sufficient video memory for high-resolution multivalued voxelization [S1, unofficial].
*   **When to Use:** Surgical planning, intra-operation navigation, and radiation therapy [S1, unofficial]. When real-time collision detection and volumetric rendering are required for complex models [S1, unofficial].
*   **When Not to Use:** Not given in the sources.

## Background
This technique was presented in "Real-time Voxelization for Complex Models" [S1, unofficial]. It was implemented using Vertex/Pixel Shader 2.0 of Direct3D 9.0b [S1, unofficial]. The method addresses the bottleneck of traditional slicing-based voxelization, which rasterizes the model $N$ times, and LDI extraction, which is view-dependent and requires CPU-side sorting [S1, unofficial]. It is particularly useful in fields requiring fast or real-time voxelization for interactive graphics applications [S1, unofficial].
