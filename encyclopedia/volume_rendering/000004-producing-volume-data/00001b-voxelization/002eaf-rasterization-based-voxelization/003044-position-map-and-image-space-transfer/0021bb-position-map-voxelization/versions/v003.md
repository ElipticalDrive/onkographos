# Position Map Voxelization

Also called: Voxelization via Position Map and 3D Image Store

## Overview
Position Map Voxelization is a post-processing step that converts a 2D position map (containing world-space coordinates of previously identified surface points) into a 3D voxel grid by rasterizing these points into a volume texture [S1, unofficial]. It differs from direct triangle rasterization by operating on pre-computed surface samples and ensuring connectivity by marking the primary voxel and its 8 immediate neighbors as active [S1, unofficial]. It is distinct from [Billboard Voxelization](2659-billboard-voxelization.md) and [Hardware-accelerated surface voxelization via 2D textures](4042-hardware-accelerated-surface-voxelization-via-2d-textures.md) because it explicitly uses a 2D image store to write directly into a 3D volume texture during a second pass [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D image texture `positionMap` storing `vec4` world-space positions [S1, unofficial].
*   **Output:** A 3D volume texture `volume` storing 8-bit values [S1, unofficial].
*   **Parameters:**
    *   `stepSize`: Distance in world units to offset positions for neighbor voxels [S1, unofficial].
    *   `voxelDim`: The dimension of the cubic volume grid (e.g., 32) [S1, unofficial].
    *   `xBounds`, `yBounds`, `zBounds`: The min/max world-space coordinates defining the volume extent [S1, unofficial].

**Data Structures:**
*   `positionMap`: `layout(binding=1, rgba32f) uniform image2D` storing `vec4` where `xyz` is world position and `a` is a validity flag (e.g., `> 0`) [S1, unofficial].
*   `volume`: `layout(binding=0, r8) uniform image3D` storing 8-bit values [S1, unofficial].

**Algorithm:**
The method is executed as a second voxelization pass, rendering a full-screen quad to process every sample in the position map [S1, unofficial].

1.  **Setup:**
    *   Bind the voxelization shader [S1, unofficial].
    *   Bind `positionMap` as an image texture at binding point 1 [S1, unofficial].
    *   Bind `volume` as an image texture at binding point 0 [S1, unofficial].
    *   Bind a full-screen quad VAO [S1, unofficial].
    *   Load identity matrices for projection, view, inverse view, normal, and model matrices [S1, unofficial].
    *   Disable depth testing, depth mask, culling, and color mask to prevent incorrect overwrites [S1, unofficial].

2.  **Fragment Shader Execution (per fragment):**
    *   Read the world-space position from the position map using current fragment coordinates: `vec4 worldPos = imageLoad(positionMap, ivec2(gl_FragCoord.xy));` [S1, unofficial].
    *   Check if the voxel is active by testing the alpha channel: `if (worldPos.a > 0)` [S1, unofficial].
    *   **Primary Voxel:** Convert `worldPos.xyz` to voxel indices using the bounding box formula and store `vec4(1)` in the volume texture at that index [S1, unofficial].
    *   **Neighbor Voxels:** For each of the 8 neighbors defined by sign combinations of $(\pm 1, \pm 1, \pm 1)$:
        *   Calculate the neighbor's world position: $pos_{neighbor} = worldPos.xyz + stepSize \times \text{normalize}(vec3(dx, dy, dz))$ where $(dx, dy, dz) \in \{(-1,-1,-1), \dots, (1,1,1)\}$ excluding $(0,0,0)$ [S1, unofficial].
        *   Convert $pos_{neighbor}$ to voxel indices and store `vec4(1)` in the volume texture at the neighbor index [S1, unofficial].

3.  **Post-Processing:**
    *   Generate mipmaps for the 3D volume texture [S1, unofficial].
    *   Unbind textures, shader, and VAO [S1, unofficial].
    *   Reset OpenGL state (enable depth test, culling, depth mask, color mask) [S1, unofficial].

**Formulas:**
The voxel index $(x, y, z)$ for a world position $pos = (pos.x, pos.y, pos.z)$ is calculated as [S1, unofficial]:

$$
x = \text{voxelDim} \times \frac{pos.x - xBounds.x}{xBounds.y - xBounds.x}
$$

$$
y = \text{voxelDim} \times \frac{pos.y - yBounds.x}{yBounds.y - yBounds.x}
$$

$$
z = \text{voxelDim} \times \frac{pos.z - zBounds.x}{zBounds.y - zBounds.x}
$$

The function returns `ivec3(x, y, z)` [S1, unofficial]. Standard integer truncation or floor is implied by the return type `ivec3` in typical GLSL implementations [G].

**Pseudocode:**
```python
import math

def calculate_voxel_index(world_pos, voxelDim, xBounds, yBounds, zBounds):
    x = voxelDim * (world_pos[0] - xBounds[0]) / (xBounds[1] - xBounds[0])
    y = voxelDim * (world_pos[1] - yBounds[0]) / (yBounds[1] - yBounds[0])
    z = voxelDim * (world_pos[2] - zBounds[0]) / (zBounds[1] - zBounds[0])
    return (int(math.floor(x)), int(math.floor(y)), int(math.floor(z)))

def process_fragment(position_map, volume, frag_coord, voxelDim, xBounds, yBounds, zBounds, stepSize):
    world_pos_vec = position_map[frag_coord]
    if world_pos_vec[3] > 0:
        world_pos = (world_pos_vec[0], world_pos_vec[1], world_pos_vec[2])
        primary_idx = calculate_voxel_index(world_pos, voxelDim, xBounds, yBounds, zBounds)
        volume[primary_idx] = 1.0
        for dx in (-1, 1):
            for dy in (-1, 1):
                for dz in (-1, 1):
                    norm_offset = (dx / math.sqrt(3), dy / math.sqrt(3), dz / math.sqrt(3))
                    neighbor_pos = (world_pos[0] + stepSize * norm_offset[0],
                                    world_pos[1] + stepSize * norm_offset[1],
                                    world_pos[2] + stepSize * norm_offset[2])
                    neighbor_idx = calculate_voxel_index(neighbor_pos, voxelDim, xBounds, yBounds, zBounds)
                    volume[neighbor_idx] = 1.0
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The index calculation assumes the position is within bounds [G]. Positions outside the bounding box will result in indices $< 0$ or $\ge \text{voxelDim}$, potentially causing out-of-bounds texture writes if not clamped [G].
*   **Precision:** Using `rgba32f` for the position map ensures high precision for world coordinates, but the final volume is `r8`, losing density/opacity information in favor of binary occupancy [S1, unofficial].
*   **Neighbor Logic:** The neighbor step uses `normalize` on the offset vector [S1, unofficial]. Since the offset is $(\pm 1, \pm 1, \pm 1)$, the normalized vector is $(\pm 1/\sqrt{3}, \pm 1/\sqrt{3}, \pm 1/\sqrt{3})$, ensuring the neighbor position is exactly `stepSize` away in Euclidean distance [S1, unofficial].

## Background
This method is described in the context of a cloud renderer implementation, specifically as a "second voxelization" pass to update the position map and generate volume data for ray marching or cone tracing [S1, unofficial]. It is part of a pipeline that first identifies surface points (likely via ray marching or rasterization) and then converts them to a voxel grid for further processing [S1, unofficial]. The pass highlights voxels nearest to the light and generates mipmaps for the volume texture [S1, unofficial].
