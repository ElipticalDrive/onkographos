# Topological Voxelization with Intersection Targets

Also called: Intersection Target Method, Intersection Target Voxelization

## Overview
Topological Voxelization with Intersection Targets determines which voxels in a grid are intersected by input geometry by testing against specific geometric shapes contained within each voxel, rather than relying on geometric proximity measures [S1, unofficial]. It guarantees topological connectivity and separability of the resulting voxel set by matching the dimensionality of the intersection target to the effective dimension of the input, making it independent of input tessellation and suitable for curved primitives [S1, unofficial]. Unlike [Point-Tessellated Voxelization](2290-point-tessellated-voxelization.md), which relies on tessellation-dependent edge and vertex handling, this method treats voxelization as a topological intersection problem [S1, unofficial].

## How it works
### Inputs and Outputs
The input consists of geometric primitives (points, curves, surfaces, or volumes), a voxel grid resolution, and the known effective dimension of the input ($d_{eff}$) [S1, unofficial]. The output is the voxel set $S_d$ containing the indices of voxels intersected by the input geometry [S1, unofficial].

### Data Structures
The Voxel Grid stores the output set $S_d$ as a collection of voxel indices or boolean flags [S1, unofficial]. The Intersection Target is a geometric primitive defined within the local coordinate space of a voxel, with dimensionality $d_{target}$ determined by $d_{eff}$ and the desired connectivity [S1, unofficial].

### Algorithm Steps
1. Determine the effective dimension $d_{eff}$ of the input geometry (0D, 1D, 2D, or 3D) [S1, unofficial].
2. Select an intersection target shape and dimension $d_{target}$ corresponding to $d_{eff}$ and the required connectivity (e.g., 6-connected vs 26-connected in 3D) [S1, unofficial].
3. Compute the supercover of the input surface $S$; only voxels in this set are tested, as intersection targets in other voxels cannot intersect the input geometry [S1, unofficial].
4. For each voxel $V$ in the supercover, test if the input geometry intersects the target $T_V$ [S1, unofficial].
5. Include $V$ in $S_d$ if an intersection occurs [S1, unofficial].
6. Resolve degenerate intersections by applying an infinitesimal perturbation vector $\vec{\epsilon}$ to the input or target, or by testing shifts in $+x, +y, +z$ directions until a non-degenerate result is obtained [S1, unofficial].

### Formulas and Definitions
Intersection Condition: $V \in S_d \iff \text{Intersect}(\text{Input}, T_V)$ [S1, unofficial].
Perturbation Vector: An infinitesimal vector $\vec{\epsilon}$ used to resolve degeneracies; a typical example is $\vec{\epsilon} = (\epsilon, 2\epsilon, 3\epsilon)$ [S1, unofficial].
Degeneracy Resolution: When input boundaries touch target boundaries, causing spurious holes or thick results, the method tests infinitesimal shifts in $+x, +y, +z$ until a non-degenerate intersection is found [S1, unofficial].

### Parameters
Effective Dimension: The dimension of the input geometry (0D, 1D, 2D, 3D) [S1, unofficial].
Connectivity: The desired connectivity of the output voxel set (e.g., 6-connected, 18-connected, 26-connected in 3D) [S1, unofficial].
Perturbation Vector: An infinitesimal vector for resolving degeneracies; example $(\epsilon, 2\epsilon, 3\epsilon)$ [S1, unofficial].

### Edge Cases and Pitfalls
Mismatched Dimensions: Using a 0D target (point) for 1D input (thin strand) results in intersection only by chance, failing to preserve connectivity [S1, unofficial].
Degenerate Intersections: Occur when input boundaries touch voxel boundaries, causing spurious holes or thick results [S1, unofficial].
Tessellation Dependence: Unlike methods relying on tessellation, this method is independent of input tessellation and supports curved primitives [S1, unofficial].

## Operating characteristics
Time complexity depends on the number of voxels in the supercover and the complexity of the intersection test [S1, unofficial]. Memory complexity is proportional to the number of voxels in the supercover [S1, unofficial]. Strengths include guaranteed topological connectivity and separability, independence from input tessellation, support for curved primitives, and simple proofs of properties [S1, unofficial]. Limitations include the requirement for known effective dimension, potential for thick results if not carefully tuned, and the need for perturbation handling [S1, unofficial]. The method should be used when topological correctness is critical or when input geometry is curved [S1, unofficial]. It should not be used when geometric proximity is more important than topology or when the effective dimension is unknown [S1, unofficial].

## Background
The method was proposed by Samuli Laine at NVIDIA in 2013 [S1, unofficial]. The foundational paper is "A Topological Approach to Voxelization" presented at the Eurographics Symposium on Rendering (EGSR) 2013 [S1, unofficial]. It builds on earlier work in voxelization, such as the supercover concept by Cohen-Or and Kaufman [COK95] and distance-based methods by Varadhan et al. [VKK*03] [S1, unofficial]. Applications include global illumination, collision detection, visualization, and simulation [S1, unofficial].
