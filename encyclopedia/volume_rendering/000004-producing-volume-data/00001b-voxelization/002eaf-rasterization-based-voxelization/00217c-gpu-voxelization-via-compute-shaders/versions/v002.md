# GPU Voxelization via Compute Shaders

Also called: AHD GPU Voxelizer, AfterHumanDeclined, AfterHumanDeclined (AHD) GPU Voxelizer, GPU Boxelizer, GPUVoxelizer, VoxelizerX12

## Overview
GPU Voxelization via Compute Shaders converts a triangle mesh into a voxel grid by parallelizing geometric intersection tests or rasterization steps across GPU compute threads [S1, unofficial][S2, unofficial][S3]. It differs from [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly managing voxel occupancy and attributes via compute kernels (e.g., SAT or plane tests) or by using compute shaders to drive the accumulation of rasterized fragments, avoiding the limitations of fixed-function depth buffers for complex surface reconstruction [S1, unofficial][S3].

## How it works
The method generally follows a two-phase or single-pass compute approach, depending on the specific implementation variant (AHD, VoxelizerX12, or GPU Boxelizer). The core logic involves preparing resources, calculating grid bounds, and dispatching compute kernels to determine voxel occupancy.

### Inputs and Outputs
**Inputs:**
*   Triangle mesh data: Vertex positions (3 floats), normals (3 floats, optional), indices (uint16 or uint32).
*   Grid parameters: Resolution ($N_x, N_y, N_z$), bounding box center, and voxel size (unit).
*   View/Projection matrices (for rasterization variants) or geometric transforms (for intersection variants).

**Outputs:**
*   A voxel grid: A 1D array of `Voxel_t` structures representing the 3D grid, stored linearly to optimize GPU access [S3].
*   Occupancy flags, surface normals, and optional attributes (color, texture coordinates) [S1, unofficial][S3].

### Data Structures
**Voxel_t (Logical 3D, Physical 1D):**
The voxel grid is allocated as a 1D `ComputeBuffer` of size $W \times H \times D$ [S3].
*   `x, y, z`: Integer coordinates within the grid.
*   `front`: Boolean flag indicating if the voxel is intersected by a front-facing triangle [S3].
*   `back`: Boolean flag indicating if the voxel is intersected by a back-facing triangle [S3].
*   `color`: Optional attribute (e.g., `float4`) [S1, unofficial].
*   `normal`: Optional attribute (e.g., `float3`) [S3].

**Constant Buffers (Uniforms):**
*   `_Start, _End, _Size`: `Vector3` defining the spatial bounds and dimensions of the voxel grid [S3].
*   `_Unit, _InvUnit, _HalfUnit`: `float` values for voxel size, inverse voxel size, and half-voxel size ($0.5 \times \text{unit}$) [S3].
*   `_Width, _Height, _Depth`: `int` dimensions of the grid [S3].
*   `_TriangleCount`: `int` number of triangles in the mesh [S3].
*   `World, View, Projection`: Matrices for transforming vertices to clip space [S1, unofficial].
*   `bcount`: `bool` flag to switch between counting pass and writing pass (AHD specific) [S1, unofficial].

**Buffers:**
*   `Vertex Buffer`: `ComputeBuffer` of `Vector3`, size equal to mesh vertex count [S3].
*   `Triangle Index Buffer`: `ComputeBuffer` of `int`, size equal to mesh index count (3 indices per triangle) [S3].
*   `Voxel Buffer`: `RWBuffer` or `RWTexture3D` for reading/writing voxel data [S1, unofficial][S3].

### Steps

1.  **Resource Preparation:**
    *   Load mesh vertices and indices into GPU buffers [S3].
    *   Compute the Axis-Aligned Bounding Box (AABB) of the mesh [S1, unofficial][S3].
    *   Calculate the grid dimensions:
        $$ \text{maxLength} = \max(\text{bounds.size.x}, \text{bounds.size.y}, \text{bounds.size.z}) $$
        $$ \text{unit} = \frac{\text{maxLength}}{\text{resolution}} $$
        $$ \text{start} = \text{bounds.min} - \text{unit} \cdot (1, 1, 1) $$
        $$ \text{end} = \text{bounds.max} + \text{unit} \cdot (1, 1, 1) $$
        $$ W = \lceil \frac{\text{end.x} - \text{start.x}}{\text{unit}} \rceil, \quad H = \lceil \frac{\text{end.y} - \text{start.y}}{\text{unit}} \rceil, \quad D = \lceil \frac{\text{end.z} - \text{start.z}}{\text{unit}} \rceil $$
        [S3]
    *   For AHD: Compute translation matrix to center AABB at origin: $M_{\text{trans}} = \text{XMMatrixTranslation}(-\text{center})$ [S1, unofficial].

2.  **Dispatch Surface Kernels (Intersection-Based):**
    *   **SurfaceFront:** Dispatch compute shader with thread group size $(\lceil \text{TriangleCount} / \text{ThreadX} \rceil, 1, 1)$ [S3]. Each thread processes one triangle.
        *   Retrieve triangle vertices from buffers [S3].
        *   Determine front/back face based on normal dot product with view direction (e.g., $(0,0,1)$) [S3].
        *   If front-facing, calculate triangle AABB, map to voxel grid indices, clamp to grid bounds, and iterate through voxels to check intersection (e.g., using SAT or plane tests) [S3].
        *   Set `front` flag in voxel data [S3].
    *   **SurfaceBack:** Dispatch compute shader with same dimensions [S3].
        *   Process only back-facing triangles [S3].
        *   Set `back` flag in voxel data [S3].
        *   *Note:* Back-facing triangles override front-facing flags if both intersect the same voxel, resolving race conditions [S3].

3.  **Dispatch Volume Kernel (Interior Filling):**
    *   Dispatch compute shader with thread group size $(\lceil W / \text{ThreadX} \rceil, \lceil H / \text{ThreadY} \rceil, \lceil D / \text{ThreadZ} \rceil)$ [S3].
    *   Each thread processes one voxel coordinate.
    *   Check if the voxel is inside the mesh (e.g., ray casting or parity check) and fill interior voxels [S3].

4.  **Rasterization-Based Variant (AHD/VoxelizerX12):**
    *   **Pass 1 (Count):** Render scene to a UAV counter buffer with `bcount=true` [S1, unofficial]. This counts the total number of voxels generated. Read back count to CPU [S1, unofficial].
    *   **Allocate Output:** Create UAV buffer of size `numVoxels * sizeof(Voxel)` [S1, unofficial].
    *   **Pass 2 (Write):** Render scene to allocated UAV buffer with `bcount=false` [S1, unofficial].
    *   **Views:** Use 4 orthographic views along principal axes (X, Y, Z) [S1, unofficial].
        *   View 1: Eye=0, Dir=X, Up=Y
        *   View 2: Eye=0, Dir=Y, Up=Z
        *   View 3: Eye=0, Dir=Z, Up=Y (Non-standard, but implemented) [S1, unofficial]
        *   View 4: (Implicitly required for full coverage, typically Dir=-X or similar) [S1, unofficial]
    *   **Projection:** Orthographic projection matrix:
        $$ P = \text{XMMatrixOrthographicOffCenterLH}(-\text{half}, \text{half}, -\text{half}, \text{half}, -\text{half}, \text{half}) $$
        where $\text{half} = \text{length} / 2$ [S1, unofficial].

### Pseudocode

```python
# GPU Voxelization via Compute Shaders (Intersection-Based Variant)

def voxelize_compute(mesh, resolution):
    # 1. Prepare Resources
    vertices = mesh.vertices  # List of Vector3
    indices = mesh.triangles  # List of int (3 per triangle)
    triangle_count = len(indices) // 3
    
    # 2. Calculate Grid Parameters
    bounds = mesh.bounds
    max_length = max(bounds.size.x, bounds.size.y, bounds.size.z)
    unit = max_length / resolution
    half_unit = unit * 0.5
    
    start = bounds.min - Vector3(unit, unit, unit)
    end = bounds.max + Vector3(unit, unit, unit)
    size = end - start
    
    width = ceil(size.x / unit)
    height = ceil(size.y / unit)
    depth = ceil(size.z / unit)
    
    # 3. Allocate Voxel Buffer (1D array)
    voxel_buffer = ComputeBuffer(width * height * depth, sizeof(Voxel_t))
    
    # 4. Dispatch SurfaceFront Kernel
    thread_x = 8  # Example thread group size
    dispatch_x = ceil(triangle_count / thread_x)
    dispatch_y = 1
    dispatch_z = 1
    
    kernel_surface_front = ComputeShaderKernel("SurfaceFront")
    kernel_surface_front.set_buffer("_VoxelBuffer", voxel_buffer)
    kernel_surface_front.set_buffer("_VertBuffer", vertices)
    kernel_surface_front.set_buffer("_TriBuffer", indices)
    kernel_surface_front.set_int("_TriangleCount", triangle_count)
    kernel_surface_front.set_vector("_Start", start)
    kernel_surface_front.set_vector("_End", end)
    kernel_surface_front.set_float("_Unit", unit)
    kernel_surface_front.set_float("_InvUnit", 1.0 / unit)
    kernel_surface_front.set_float("_HalfUnit", half_unit)
    kernel_surface_front.set_int("_Width", width)
    kernel_surface_front.set_int("_Height", height)
    kernel_surface_front.set_int("_Depth", depth)
    
    kernel_surface_front.dispatch(dispatch_x, dispatch_y, dispatch_z)
    
    # 5. Dispatch SurfaceBack Kernel
    kernel_surface_back = ComputeShaderKernel("SurfaceBack")
    kernel_surface_back.set_buffer("_VoxelBuffer", voxel_buffer)
    kernel_surface_back.set_buffer("_VertBuffer", vertices)
    kernel_surface_back.set_buffer("_TriBuffer", indices)
    kernel_surface_back.set_int("_TriangleCount", triangle_count)
    kernel_surface_back.set_vector("_Start", start)
    kernel_surface_back.set_vector("_End", end)
    kernel_surface_back.set_float("_Unit", unit)
    kernel_surface_back.set_float("_InvUnit", 1.0 / unit)
    kernel_surface_back.set_float("_HalfUnit", half_unit)
    kernel_surface_back.set_int("_Width", width)
    kernel_surface_back.set_int("_Height", height)
    kernel_surface_back.set_int("_Depth", depth)
    
    kernel_surface_back.dispatch(dispatch_x, dispatch_y, dispatch_z)
    
    # 6. Dispatch Volume Kernel (Interior Filling)
    kernel_volume = ComputeShaderKernel("Volume")
    kernel_volume.set_buffer("_VoxelBuffer", voxel_buffer)
    kernel_volume.set_vector("_Start", start)
    kernel_volume.set_vector("_End", end)
    kernel_volume.set_float("_Unit", unit)
    kernel_volume.set_float("_InvUnit", 1.0 / unit)
    kernel_volume.set_float("_HalfUnit", half_unit)
    kernel_volume.set_int("_Width", width)
    kernel_volume.set_int("_Height", height)
    kernel_volume.set_int("_Depth", depth)
    
    dispatch_vol_x = ceil(width / 8)
    dispatch_vol_y = ceil(height / 8)
    dispatch_vol_z = ceil(depth / 8)
    
    kernel_volume.dispatch(dispatch_vol_x, dispatch_vol_y, dispatch_vol_z)
    
    # 7. Read Back Results
    voxel_data = voxel_buffer.read_back()
    return voxel_data

# Compute Shader Kernel: SurfaceFront
[numthreads(8, 1, 1)]
void SurfaceFront(uint3 id : SV_DispatchThreadID) {
    int idx = id.x;
    if (idx >= _TriangleCount) return;
    
    float3 va, vb, vc;
    bool front;
    get_triangle(idx, va, vb, vc, front);
    
    if (!front) return;
    
    surface(va, vb, vc, front);
}

# Helper: get_triangle
void get_triangle(int idx, out float3 va, out float3 vb, out float3 vc, out bool front) {
    int i0 = _TriBuffer[idx * 3];
    int i1 = _TriBuffer[idx * 3 + 1];
    int i2 = _TriBuffer[idx * 3 + 2];
    
    va = _VertBuffer[i0];
    vb = _VertBuffer[i1];
    vc = _VertBuffer[i2];
    
    float3 normal = normalize(cross(vb - va, vc - vb));
    front = dot(normal, float3(0, 0, 1)) > 0;
}

# Helper: surface
void surface(float3 va, float3 vb, float3 vc, bool front) {
    // Calculate triangle AABB
    float3 min_v = min(va, min(vb, vc));
    float3 max_v = max(va, max(vb, vc));
    
    // Map to voxel grid indices
    int3 min_idx = floor((min_v - _Start) * _InvUnit);
    int3 max_idx = floor((max_v - _Start) * _InvUnit);
    
    // Clamp to grid bounds
    min_idx = clamp(min_idx, int3(0, 0, 0), int3(_Width - 1, _Height - 1, _Depth - 1));
    max_idx = clamp(max_idx, int3(0, 0, 0), int3(_Width - 1, _Height - 1, _Depth - 1));
    
    // Iterate through voxels and check intersection
    for (int z = min_idx.z; z <= max_idx.z; z++) {
        for (int y = min_idx.y; y <= max_idx.y; y++) {
            for (int x = min_idx.x; x <= max_idx.x; x++) {
                int3 voxel_coord = int3(x, y, z);
                float3 voxel_center = _Start + (voxel_coord + 0.5) * _Unit;
                
                if (intersect_triangle(voxel_center, va, vb, vc)) {
                    int voxel_idx = x + y * _Width + z * _Width * _Height;
                    if (front) {
                        _VoxelBuffer[voxel_idx].front = true;
                    } else {
                        _VoxelBuffer[voxel_idx].back = true;
                    }
                }
            }
        }
    }
}
```

### Parameters
*   `resolution`: Target voxel grid resolution (e.g., 128, 256) [S3].
*   `USE_MUTEX`: Compile-time flag for VoxelizerX12 to use multiple mutexed grids or a single grid with atomic operations [S2, unofficial].

### Edge Cases and Pitfalls
*   **Race Conditions:** Multiple threads may access the same voxel data simultaneously. The implementation prioritizes back-facing triangles by processing front-facing triangles first, then back-facing ones, allowing back flags to override front flags if both intersect the same voxel [S3].
*   **Index Format:** Index buffer stride must be 2 or 4 bytes. If 2, format is `R16_UINT`; if 4, format is `R32_UINT`. Other strides throw an exception [S1, unofficial].
*   **Texture Handling:** If a resource has a texture, it must be added to the Voxelizer via `addTexture` before voxelization. The texture is bound as a Shader Resource View (SRV) with anisotropic filtering and wrap addressing [S1, unofficial].
*   **Precision:** Floating-point precision issues may arise when mapping continuous coordinates to discrete voxel indices. Using `_InvUnit` and `_HalfUnit` helps mitigate this [S3].

## Subtopics

### [GPU Mesh Voxelization (Schwarz & Seidel 2010)](1633-gpu-mesh-voxelization-schwarz-seidel-2010.md)
GPU Mesh Voxelization converts a triangle mesh into a set of occupied voxel coordinates within a 3D grid by performing explicit geometric intersection tests on the GPU. It differs from rasterization-based voxelization [Multi-channel Surface Voxelization](1899-multi-channel-surface-voxelization.md) by avoiding fragment shaders and depth buffers, instead using compute shaders to iterate over voxels or triangles and applying Separating Axis Theorem (SAT) or plane/projection tests. This method provides exact surface intersection results without the aliasing artifacts common in rasterization, though it is computationally more expensive for high-poly meshes due to its brute-force nature.

### [Multi-channel Surface Voxelization](1899-multi-channel-surface-voxelization.md)
Multi-channel surface voxelization is a real-time GPU technique that rasterizes 3D geometry into a uniform voxel grid while simultaneously computing and storing multiple surface attributes (such as albedo, normals, and spherical harmonics coefficients) per voxel. It distinguishes itself from binary occupancy voxelization methods by supporting partial occupancy, transparency, and rich multi-channel data in a single pass, albeit at a higher computational cost.

### [GPU Rasterization-based Octree Building](2406-gpu-rasterization-based-octree-building.md)
GPU Rasterization-based Octree Building is a technique for constructing sparse voxel octrees directly on the GPU by exploiting the rasterization pipeline to identify occupied leaf nodes. It solves the problem of efficiently generating hierarchical voxel data for fully dynamic scenes by rasterizing geometry from multiple orthogonal directions to eliminate boundary holes inherent in single-pass methods. Unlike sibling methods that may require pre-processing or specific primitive types, this approach handles any hardware-supported rasterizable geometry in a single geometry submission pass, leveraging 32-bit integer textures and bitwise operations for high performance. It differs from [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md) by using rasterization fragments to drive the octree traversal rather than a purely compute-based atomic accumulation, and from [GPU Mesh Voxelization (Schwarz & Seidel 2010)](1633-gpu-mesh-voxelization-schwarz-seidel-2010.md) by explicitly building the hierarchical octree structure during the rasterization phase rather than just filling a flat voxel grid.

## Operating characteristics
*   **Time Complexity:** $O(T \cdot V)$ for intersection-based methods, where $T$ is the number of triangles and $V$ is the number of voxels in the triangle's bounding box [S3]. For rasterization-based methods, it is $O(N^2)$ per view, where $N$ is the grid resolution [S1, unofficial].
*   **Memory Complexity:** $O(W \cdot H \cdot D)$ for the voxel grid [S3].
*   **Measured Performance:** Real-time voxelization is achievable with DirectX 12 and compute shaders, especially for dynamic scenes [S2, unofficial].
*   **Strengths:** Parallelizable, flexible, supports complex attributes [S3].
*   **Limitations:** Computationally expensive for high-poly meshes in intersection-based methods [S2, unofficial]. Race conditions require careful handling [S3].
*   **When to Use:** When exact surface intersection is required or when custom attributes need to be computed per voxel [S3].
*   **When Not to Use:** When performance is critical and the mesh is very high-poly, consider rasterization-based methods [S1, unofficial].

## Background
*   **Origin:** The method is based on GPU-based voxelization techniques using Direct3D 11 and Shader Model 5.0 [S1, unofficial]. It has been extended to DirectX 12 for real-time solid voxelization [S2, unofficial].
*   **History:** The technique has been developed in various forms, including the AfterHumanDeclined (AHD) voxelizer [S1, unofficial], VoxelizerX12 [S2, unofficial], and GPU Boxelizer [S3].
*   **Usage:** Used in real-time rendering, volume rendering, and collision detection [S2, unofficial][S3].
