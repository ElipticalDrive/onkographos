# Rasterization-based Voxelization

Also called: Cube Mesh Generation, Hash-based Surface Voxelization, Sparse Voxelization with PositionMap Hashing, Voxelizing a Triangle Mesh, madcad Voxelization

## Overview
Rasterization-based Voxelization converts a continuous triangle mesh into a discrete volumetric representation by projecting the geometry onto a 3D grid using rasterization principles [S1][S3, S4, unofficial]. It solves the problem of generating surface-level voxel data (shell voxelization) without performing deep interior filling or complex surface reconstruction [S2, S5, unofficial]. It differs from [Voxel Carving](1213-voxel-carving.md) by using constructive rasterization rather than destructive projection, and from [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md) by relying on explicit triangle intersection tests rather than signed distance field evaluation [S1][S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle mesh defined by vertices $V$ and faces $F$ [S1][S4, unofficial].
*   **Parameters:** Voxel size $vs = (vs_x, vs_y, vs_z)$, voxel origin $origin$ (typically $[0,0,0]$), and a precision factor $p$ to reduce artifacts [S1][S2, S4, unofficial].
*   **Output:** A set of occupied voxel coordinates (integer indices $ijk$) [S1][S3, unofficial], or a generated mesh/point cloud representing the voxelized surface [S2, S4, unofficial].

**Data Structures:**
*   **Sparse Hash Table / Set:** Used to store occupied voxel coordinates to avoid dense 3D arrays, optimizing memory for sparse meshes [S3, S4, unofficial]. In C implementations, this is a hash table with linked-list nodes containing `position` and `color` [S4, unofficial]. In Python, a `set` of tuples is used [S3, unofficial].
*   **Voxel Grid Geometry (Optional):** If generating a mesh, a cube is defined by 8 vertices relative to the voxel center and 36 indices (6 faces) [S4, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Define the voxel size $vs$ and compute half-voxel size $hvs = vs \times 0.5$ [S4, unofficial].
2.  **Iteration:** For each triangle face in the input mesh:
    a.  Determine the bounding box of the triangle in world space.
    b.  Map the bounding box to voxel grid indices.
    c.  Rasterize the triangle onto the grid. This involves testing which voxel cells intersect the triangle [S1][S4, unofficial].
    d.  For each intersected voxel, compute the voxel center or representative point.
    e.  Insert the voxel coordinate into the hash table/set. If the implementation supports attributes (color/normal), interpolate them from the triangle vertices and store them with the voxel [S3, S4, unofficial].
3.  **Post-Processing (Optional):**
    a.  **Cube Mesh Generation:** Iterate through the hash table. For each occupied voxel, generate a cube mesh centered at the voxel position using the precomputed half-voxel offsets [S4, unofficial].
    b.  **Point Cloud Generation:** Extract positions and colors from the hash table into a point cloud structure [S4, unofficial].

**Pseudocode:**
```python
def rasterization_voxelization(vertices, faces, voxel_size, origin, precision=0.01):
    """
    Voxelize a triangle mesh using rasterization principles.
    Returns a set of occupied voxel coordinates (ijk).
    """
    occupied_voxels = set()
    
    # Precompute half voxel size for center calculations if needed
    hvs = [s * 0.5 for s in voxel_size]
    
    for face in faces:
        # Get triangle vertices
        v0 = vertices[face[0]]
        v1 = vertices[face[1]]
        v2 = vertices[face[2]]
        
        # 1. Compute Bounding Box of the triangle in world space
        min_world = [min(v0[i], v1[i], v2[i]) for i in range(3)]
        max_world = [max(v0[i], v1[i], v2[i]) for i in range(3)]
        
        # 2. Expand bounding box slightly by precision to handle edge cases
        min_world = [min_world[i] - precision for i in range(3)]
        max_world = [max_world[i] + precision for i in range(3)]
        
        # 3. Map world-space bounding box to voxel grid indices
        min_ijk = [floor((min_world[i] - origin[i]) / voxel_size[i]) for i in range(3)]
        max_ijk = [floor((max_world[i] - origin[i]) / voxel_size[i]) for i in range(3)]
        
        # 4. Iterate over all voxels in the bounding box
        for i in range(min_ijk[0], max_ijk[0] + 1):
            for j in range(min_ijk[1], max_ijk[1] + 1):
                for k in range(min_ijk[2], max_ijk[2] + 1):
                    # 5. Check if the voxel intersects the triangle
                    # This is the core rasterization/intersection step.
                    # A simple approximation is checking if the voxel center is close to the triangle plane,
                    # or using a conservative rasterization test.
                    # For exact implementation, one would use a triangle-voxel intersection test.
                    if voxel_intersects_triangle((i, j, k), voxel_size, origin, v0, v1, v2):
                        occupied_voxels.add((i, j, k))
                        
    return occupied_voxels

def voxel_intersects_triangle(voxel_ijk, voxel_size, origin, v0, v1, v2):

    [G] Placeholder for the specific intersection logic.
    Common implementations use:
    1. Barycentric coordinate test on the voxel center projected onto the triangle plane.
    2. Separating Axis Theorem (SAT) for AABB-Triangle intersection.
    3. Conservative rasterization logic (checking if the triangle covers any part of the voxel volume).
    """
    # Calculate voxel center in world space
    center = [
        origin[0] + (voxel_ijk[0] + 0.5) * voxel_size[0],
        origin[1] + (voxel_ijk[1] + 0.5) * voxel_size[1],
        origin[2] + (voxel_ijk[2] + 0.5) * voxel_size[2]
    ]
    
    # [G] Simple point-in-triangle test is insufficient for volume.
    # A robust method checks the distance from the voxel center to the triangle plane
    # and ensures the projection falls within the triangle bounds, expanded by voxel half-size.
    # For the purpose of this generic description, we assume a helper function exists
    # that returns True if the triangle intersects the voxel AABB.
    return triangle_aabb_intersection(v0, v1, v2, center, voxel_size[0]/2, voxel_size[1]/2, voxel_size[2]/2)
```

**Edge Cases and Pitfalls:**
*   **Holes/Artifacts:** Standard rasterization may miss voxels if the triangle is thin or aligned with the grid, leading to "holes" in the voxel shell. A precision factor or conservative rasterization is required to mitigate this [S2, S6, unofficial].
*   **Performance:** The output mesh size scales significantly with voxel density. For example, a torus with 441 vertices can produce over 144,000 vertices at a voxel size of 0.5 [S2, unofficial].
*   **Sparse vs Dense:** Using a dense 3D array for large bounding boxes is memory-inefficient. Hash-based storage is preferred for sparse meshes [S3, S4, unofficial].

## Subtopics

### [3D Grid Rasterization](903-3d-grid-rasterization.md)
A CPU-based algorithm that determines which voxels in a fixed-resolution 3D grid are intersected by a triangle mesh, producing a binary occupancy grid or a grid with interpolated colors. It solves the problem of converting continuous polygonal geometry into a discrete volumetric representation without performing surface reconstruction (such as QEF or dual vertex solving). It differs from full o-voxel implementations by omitting the face QEF, boundary QEF, and dual vertex solve steps, focusing solely on the intersect scanline to find occupied voxels. It differs from GPU-based siblings like [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on CPU-side scanline filling and hash-table deduplication rather than parallel fragment shaders.

### [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md)
GPU Volume Kernel Voxelization is a technique that accelerates the voxelization of triangle meshes by parallelizing the iteration over the 2D XY plane of the voxel grid using a GPU compute shader. It solves the performance bottleneck of CPU-based voxelization, where nested loops over X and Y coordinates are executed sequentially. Unlike rasterization-based alternatives that project geometry into 3D textures, this method retains the explicit triangle-voxel intersection logic of CPU implementations but distributes the workload across GPU threads, achieving significant speedups (e.g., 50x) for high-resolution grids.

### [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md)
GPU Voxelization via Compute Shaders converts 3D triangle meshes into a uniform 3D voxel grid by leveraging GPU parallel processing. It solves the problem of generating volumetric data for real-time ray marching or volume rendering with high throughput. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md), which projects triangles via the fixed-function graphics pipeline, compute shader methods decouple intersection logic from rasterization, allowing custom geometric tests and atomic operations on 3D buffers or textures.

### [GPU Voxelization](2633-gpu-voxelization.md)
GPU Voxelization converts a triangle mesh into a regular voxel grid by leveraging the GPU's hardware rasterization pipeline to map fragments directly to 3D grid cells. It solves the performance bottleneck of CPU-based ray-tracing voxelization by parallelizing the intersection test across the rasterizer. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using a 3D texture UAV or SSBO as the direct write target rather than a 2D accumulation buffer, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on standard triangle rasterization rather than volume kernels.

### [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md)
CPU Mesh Voxelization converts a triangle mesh into a 3D grid of voxels by iterating over the bounding box of each triangle and testing each voxel center against the triangle's plane and edge constraints. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly rasterizing triangles into a hash table of voxel centers and colors, then generating a cube mesh for each occupied voxel, whereas CPU Mesh Voxelization typically outputs a binary occupancy grid or bit-packed table. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using exact geometric overlap tests (SAT or plane/projection) rather than simple grid cell intersection, and from [Voxelization via Triangle Scattering](3779-voxelization-via-triangle-scattering.md) by iterating cells against triangles rather than scattering triangles into cells.

### [Voxel Rasterization](3204-voxel-rasterization.md)
Voxel Rasterization converts a triangle mesh into a voxelized representation by rendering the geometry into a 3D voxel buffer, supporting both simple occupancy and normal/color mapping. It differs from its sibling [3D Grid Rasterization](903-3d-grid-rasterization.md) by explicitly iterating over triangle surfaces to calculate interpolated points and normals rather than relying on a pure grid traversal, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by utilizing a Direct3D 11-based rendering pipeline or CUDA kernels for the rasterization step.

### [Conservative Voxelization](3247-conservative-voxelization.md)
Conservative voxelization is a hardware-accelerated algorithm for polygonal models that guarantees conservative correctness: every voxel intersecting the input model is correctly recognized, solving the problem where previous approaches miss intersecting voxels. It differs from standard rasterization-based voxelization [Rasterization-based Voxelization] by computing the exact depth range of the intersection between the triangle and the voxel column, rather than using a single depth value (e.g., the fragment center) which leads to missed voxels.

### [Conservative Rasterization via Triangle Expansion](3531-conservative-rasterization-via-triangle-expansion.md)
This method eliminates voxelization holes caused by standard rasterization, which only covers pixels whose centers lie inside a triangle, by expanding the triangle in clip space and culling the expanded area in the fragment shader. It differs from sibling methods like [Conservative Voxelization](3247-conservative-voxelization.md) by implementing the expansion logic manually in the geometry shader using homogeneous plane mathematics, rather than relying on hardware-specific conservative rasterization extensions or post-processing hole-filling.

### [Multi-view projection](5937-multi-view-projection.md)
Multi-view projection voxelization converts a triangle mesh into a voxel grid by rasterizing the geometry from multiple camera viewpoints, typically aligned with the principal axes of the scene's bounding box. This approach solves the coverage gaps and geometric distortions inherent in single-view projection methods, which fail when surface normals are perpendicular to the view direction. It differs from single-view methods by ensuring comprehensive coverage through redundancy, and from compute-shader-based methods by leveraging standard graphics pipeline rasterization.

### [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md)
This family of techniques converts 3D geometric data into voxel grids by projecting or transferring information into 2D image space (textures) before reconstructing the 3D volume. Unlike direct 3D rasterization, these methods leverage the GPU's fixed-function rasterizer or image load/store operations on 2D textures to determine voxel occupancy, often trading memory bandwidth for computational simplicity. They are distinguished from direct triangle rasterization by operating on pre-computed surface samples or 2D texture slices, ensuring connectivity or enabling real-time performance insensitive to scene complexity.

### Rasterization-based Volume Modeling
The process of building volume data voxel-by-voxel, considered the third layer in the voxel modeling abstraction hierarchy [S5, unofficial]. It solves the problem of assigning density values to voxels based on primitive contributions. It differs from instantiation-based modeling by pulling values into a voxel (similar to raytracing), whereas instantiation-based modeling pushes values into voxels (similar to micropolygon rendering) [S5, unofficial]. The main rasterization loop iterates over voxels in the discrete bounding box, transforms voxel position to world space, samples the primitive, and adds the value to the buffer if positive [S5, unofficial].

### Single-Pass Voxelization
A voxelization approach that utilizes the geometry shader to reduce draw calls by selecting the axis from which each triangle has the largest overall projection for fragment generation [S6, unofficial]. It solves the problem of multiple draw calls for objects with the same material. It employs conservative rasterization to generate fragments as long as there is something inside the pixel, not only if its center is covered [S6, unofficial]. It uses an MSAA render target to solve the issue of incorrectly filling empty cells caused by conservative rasterization generating too many fragments [S6, unofficial]. Hardware support for conservative rasterization is available on Nvidia Maxwell architecture and later; RTX driver support is available for Turing and Pascal architecture GPUs [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot B)$, where $N$ is the number of triangles and $B$ is the average number of voxels in the bounding box of a triangle. The complexity depends heavily on the triangle-to-voxel intersection test efficiency [S1][S4, unofficial].
*   **Memory Complexity:** $O(V)$, where $V$ is the number of occupied voxels. Using a hash table or set ensures memory usage is proportional to the surface area rather than the volume of the bounding box [S3, S4, unofficial].
*   **Performance:** CPU-based implementations (e.g., `voxelizer` library) can be slow for high-resolution grids due to sequential processing [S1][S2, unofficial]. GPU-based variants (e.g., [GPU Voxelization](2633-gpu-voxelization.md)) offer significant speedups (e.g., 50x) by parallelizing the rasterization process [S1].
*   **Strengths:** Simple to implement; generates clean surface shells; efficient for sparse data using hash structures; supports attribute interpolation (color/normal) [S2, S3, S4, unofficial].
*   **Limitations:** Output mesh size can be very large compared to the input mesh (e.g., 100x increase in vertices) [S2, unofficial]; prone to holes if precision is not handled correctly [S2, S6, unofficial]; requires careful handling of bounding boxes to avoid excessive voxel checks [S5, unofficial].
*   **When to Use:** When a surface-level voxel representation is needed for voxel art, collision detection, or as input for volume rendering where interior density is not required [S2, S5, unofficial].
*   **When Not to Use:** When deep interior voxelization is required (use [Voxel Carving](1213-voxel-carving.md) or [Solid Volume Accumulation via Sphere-Box Intersection](7681-solid-volume-accumulation-via-sphere-box-intersection.md)); when memory is extremely constrained and the mesh is dense (use [Sparse and Hierarchical Structures](4391-sparse-and-hierarchical-structures.md)).

## Background
Rasterization-based voxelization has been implemented in various libraries and research contexts. The `point-cloud-utils` library provides a Python interface for rasterizing triangle meshes to voxels and generating cube meshes [S1]. The `voxelizer` library by Karim Naaji is a header-only C library that performs shell voxelization and outputs a new mesh with vertices and faces representing the voxelized surface [S2, S4, unofficial]. The `madcad` library uses a `PositionMap` hasher for efficient sparse voxelization [S3, unofficial]. The concept is also discussed in the context of volume modeling abstraction, where rasterization is distinguished from instantiation-based modeling [S5, unofficial]. Single-pass voxelization using geometry shaders and conservative rasterization has been explored in real-time ray-traced voxel global illumination research [S6, unofficial].
