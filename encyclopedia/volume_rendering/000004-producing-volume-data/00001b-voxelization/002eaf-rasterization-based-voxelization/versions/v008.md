# Rasterization-based Voxelization

Also called: Cube Mesh Generation, Hash-based Surface Voxelization, Sparse Voxelization with PositionMap Hashing, Voxelizing a Triangle Mesh, madcad Voxelization

## Overview
Rasterization-based Voxelization converts a continuous triangle mesh into a discrete volumetric representation by projecting the geometry onto a 3D grid using rasterization principles [S1][S3, S4, unofficial]. It solves the problem of generating a voxel grid (binary occupancy, point cloud, or surface mesh) from polygonal input without performing explicit ray-triangle intersection tests for every voxel [S1][S3, unofficial]. It differs from ray-tracing methods by leveraging the efficiency of scan-conversion logic, and from dense grid methods by often employing sparse data structures (hash tables) to store only occupied voxels, making it memory-efficient for sparse scenes [S3, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle mesh defined by vertices $V$ and faces $F$ [S1][S4, unofficial].
*   **Parameters:** Voxel size $vs = (vs_x, vs_y, vs_z)$ [S4, unofficial], voxel origin $vox\_origin$ (typically $[0,0,0]$) [S1], and a precision factor $p$ to reduce artifacts [S2, S4, unofficial].
*   **Output:** A set of occupied voxel coordinates, optionally converted into a cube mesh or point cloud [S1][S4, unofficial].

**Data Structures:**
The method typically uses a hash table to store occupied voxels to avoid allocating a dense 3D array [S3, S4, unofficial].
*   **Hash Table:** Maps voxel coordinates (keys) to voxel data (values).
    *   **Key:** Integer tuple $(i, j, k)$ representing the grid index [S3, unofficial].
    *   **Value:** `voxel_data_t` containing position (center of the voxel) and optional attributes like color [S4, unofficial].
*   **Output Mesh Structure (`vx_mesh_t`):**
    *   `vertices`: Array of size $N_{voxels} \times 8$ [S4, unofficial].
    *   `normals`: Array of size 6 (predefined for cube faces) [S4, unofficial].
    *   `colors`: Array of size $N_{voxels} \times 8$ (optional) [S4, unofficial].
    *   `indices`: Array of size $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$ [S4, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Define voxel size $vs$ and compute half-voxel size $hvs = vs \times 0.5$ [S4, unofficial]. Initialize an empty hash table `table` [S4, unofficial].
2.  **Iteration:** For each triangle face $f$ in the mesh:
    a.  Determine the bounding box of the triangle in world space [S5, unofficial].
    b.  Map the bounding box to voxel grid coordinates [S5, unofficial].
    c.  Iterate over all integer voxel coordinates $(i, j, k)$ within this bounding box [S5, unofficial].
    d.  For each voxel, check if it intersects the triangle. This is often done by rasterizing the triangle into the voxel space or checking if the voxel center lies within the triangle's projection [S3, S4, unofficial].
    e.  If the voxel is occupied, compute its center position $C$ in world space:
        $$ C = vox\_origin + (i + 0.5) \times vs $$
    f.  Insert $C$ and associated attributes (e.g., interpolated color) into the hash table [S4, unofficial].
3.  **Geometry Generation (Optional):** If a cube mesh is required:
    a.  Allocate output arrays for vertices and indices based on the number of unique voxels $N_{voxels}$ [S4, unofficial].
    b.  Define the 8 corner offsets for a cube centered at the origin using $hvs$:
        $$
        \begin{aligned}
        &(-hvs_x, hvs_y, hvs_z), (-hvs_x, -hvs_y, hvs_z), (hvs_x, -hvs_y, hvs_z), (hvs_x, hvs_y, hvs_z), \\
        &(-hvs_x, hvs_y, -hvs_z), (-hvs_x, -hvs_y, -hvs_z), (hvs_x, -hvs_y, -hvs_z), (hvs_x, hvs_y, -hvs_z)
        \end{aligned}
        $$
    c.  For each voxel in the hash table, add a cube mesh to the output using the voxel center and the corner offsets [S4, unofficial].
4.  **Cleanup:** Free the hash table [S4, unofficial].

**Pseudocode:**
```python
def rasterization_based_voxelization(mesh, vox_size, vox_origin, precision=0.01):
    """
    Voxelize a triangle mesh using rasterization principles and a hash table.
    
    Args:
        mesh: Object with vertices (V) and faces (F).
        vox_size: Tuple (vs_x, vs_y, vs_z) defining voxel dimensions.
        vox_origin: Tuple (ox, oy, oz) defining the grid origin.
        precision: Float tolerance for intersection checks.
        
    Returns:
        list of tuples: Occupied voxel coordinates (i, j, k).
    """
    hvs = [s * 0.5 for s in vox_size]
    occupied_voxels = set()
    
    # Helper to map world coordinate to voxel index
    def world_to_voxel_index(world_coord):
        return tuple(floor((c - o) / s) for c, o, s in zip(world_coord, vox_origin, vox_size))

    for face in mesh.faces:
        # Get triangle vertices in world space
        v0, v1, v2 = face.vertices
        
        # Compute bounding box of the triangle in world space
        min_world = min(v0, v1, v2, key=lambda v: v.x) # Simplified min logic
        max_world = max(v0, v1, v2, key=lambda v: v.x) # Simplified max logic
        # Note: Real implementation requires min/max of all components
        
        # Map bounding box to voxel indices
        min_idx = world_to_voxel_index(min_world)
        max_idx = world_to_voxel_index(max_world)
        
        # Iterate over voxels in the bounding box
        for i in range(min_idx[0], max_idx[0] + 1):
            for j in range(min_idx[1], max_idx[1] + 1):
                for k in range(min_idx[2], max_idx[2] + 1):
                    # Check if voxel (i,j,k) intersects the triangle
```

**Edge Cases and Pitfalls:**
*   **Holes:** Standard rasterization may leave gaps if triangle centers do not align with voxel centers. A precision factor or conservative rasterization is used to mitigate this [S2, S6, unofficial].
*   **Performance:** The output mesh size scales with voxel density. High-resolution grids can produce significantly more vertices and faces than the input mesh [S2, unofficial].
*   **Sparse Data:** Using a hash table (set) instead of a 3D array is crucial for memory efficiency when the mesh occupies a small volume relative to the grid [S3, S4, unofficial].

## Subtopics

### [3D Grid Rasterization](903-3d-grid-rasterization.md)
A CPU-based algorithm that determines which voxels in a fixed-resolution 3D grid are intersected by a triangle mesh, producing a binary occupancy grid or a grid with interpolated colors. It solves the problem of converting continuous polygonal geometry into a discrete volumetric representation without performing surface reconstruction (such as QEF or dual vertex solving). It differs from full o-voxel implementations by omitting the face QEF, boundary QEF, and dual vertex solve steps, focusing solely on the intersect scanline to find occupied voxels. It differs from GPU-based siblings like [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on CPU-side scanline filling and hash-table deduplication rather than parallel fragment shaders.

### [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md)
GPU Volume Kernel Voxelization is a technique that accelerates the voxelization of triangle meshes by parallelizing the iteration over the 2D XY plane of the voxel grid using a GPU compute shader. It solves the performance bottleneck of CPU-based voxelization, where nested loops over X and Y coordinates are executed sequentially. Unlike rasterization-based alternatives that project geometry into 3D textures, this method retains the explicit triangle-voxel intersection logic of CPU implementations but distributes the workload across GPU threads, achieving significant speedups (e.g., 50x) for high-resolution grids.

### [3D Scan-conversion](1895-3d-scan-conversion.md)
3D scan-conversion is a rendering method that converts geometric primitives (polygons) into a volumetric dataset, combines them with existing volumetric data using volume matting operators, and renders the resulting composite ensemble using standard volume rendering techniques. It sets itself apart from hybrid ray tracing by pre-filtering and sampling geometry into the voxel grid, allowing the use of standard ray-casting for the final image while avoiding aliasing artifacts through analytic anti-aliasing. Unlike rasterization-based voxelization which maps to screen space, this method maps directly to the 3D volume grid coordinates.

### [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md)
Implicit Surface Voxelization converts a mathematical implicit surface definition into a discrete voxel grid by rasterizing 2D rectangles within a Region of Interest (ROI) and evaluating the implicit function in the pixel shader. It differs from triangle-based rasterization methods (e.g., [Rasterization-based Voxelization](908-rasterization-based-voxelization.md)) by operating directly on analytical functions rather than polygonal approximations, allowing for the handling of complex, non-polygonal geometry.

### [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md)
GPU Voxelization via Compute Shaders converts 3D triangle meshes into a uniform 3D voxel grid by leveraging GPU parallel processing. It solves the problem of generating volumetric data for real-time ray marching or volume rendering with high throughput. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md), which projects triangles via the fixed-function graphics pipeline, compute shader methods decouple intersection logic from rasterization, allowing custom geometric tests and atomic operations on 3D buffers or textures.

### [GPU Voxelization](2633-gpu-voxelization.md)
GPU Voxelization converts a triangle mesh into a regular voxel grid by leveraging the GPU's hardware rasterization pipeline to map fragments directly to 3D grid cells. It solves the performance bottleneck of CPU-based ray-tracing voxelization by parallelizing the intersection test across the rasterizer. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using a 3D texture UAV or SSBO as the direct write target rather than a 2D accumulation buffer, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on standard triangle rasterization rather than volume kernels.

### [Mesh-to-Voxel Geometry Shader](2800-mesh-to-voxel-geometry-shader.md)
The Mesh-to-Voxel Geometry Shader is a real-time DirectX technique that converts mesh objects into voxel-like cubes by iterating over integer grid positions within a triangle's bounding box and emitting explicit cube geometry for grid cells close to the triangle plane. Unlike rasterization-based voxelization which fills pixels or conservative voxelization which determines occupancy, this method explicitly generates the 3D geometry of every intersecting voxel, resulting in significantly higher vertex and triangle counts.

### [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md)
CPU Mesh Voxelization converts a triangle mesh into a 3D grid of voxels by iterating over the bounding box of each triangle and testing each voxel center against the triangle's plane and edge constraints. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly rasterizing triangles into a hash table of voxel centers and colors, then generating a cube mesh for each occupied voxel, whereas CPU Mesh Voxelization typically outputs a binary occupancy grid or bit-packed table. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using exact geometric overlap tests (SAT or plane/projection) rather than simple grid cell intersection, and from [Voxelization via Triangle Scattering](3779-voxelization-via-triangle-scattering.md) by iterating cells against triangles rather than scattering triangles into cells.

### [Voxel Rasterization](3204-voxel-rasterization.md)
Voxel Rasterization converts a triangle mesh into a voxelized representation by rendering the geometry into a 3D voxel buffer, supporting both simple occupancy and normal/color mapping. It differs from its sibling [3D Grid Rasterization](903-3d-grid-rasterization.md) by explicitly iterating over triangle surfaces to calculate interpolated points and normals rather than relying on a pure grid traversal, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by utilizing a Direct3D 11-based rendering pipeline or CUDA kernels for the rasterization step.

### [Conservative Rasterization via Triangle Expansion](3531-conservative-rasterization-via-triangle-expansion.md)
This method eliminates voxelization holes caused by standard rasterization, which only covers pixels whose centers lie inside a triangle, by expanding the triangle in clip space and culling the expanded area in the fragment shader. It differs from sibling methods like [Conservative Voxelization](3247-conservative-voxelization.md) by implementing the expansion logic manually in the geometry shader using homogeneous plane mathematics, rather than relying on hardware-specific conservative rasterization extensions or post-processing hole-filling.

### [Multi-view projection](5937-multi-view-projection.md)
Multi-view projection is a family of rasterization-based voxelization techniques that convert triangle meshes into voxel grids by rendering scene geometry from multiple distinct camera viewpoints. The core problem it solves is ensuring topological correctness (specifically 6-separation or tunnel-freedom) and complete coverage of the volume, which single-view methods often fail to achieve due to perspective distortion or degenerate alignments. It sets itself apart from single-view methods by requiring multiple passes (typically 2, 3, or 6) to guarantee that every voxel intersected by a triangle is covered by at least one view, provided the views are sufficiently separated [Parent].

### [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md)
This family of techniques converts 3D geometric data into voxel grids by projecting or transferring information into 2D image space (textures) before reconstructing the 3D volume. Unlike direct 3D rasterization, these methods leverage the GPU's fixed-function rasterizer or image load/store operations on 2D textures to determine voxel occupancy, often trading memory bandwidth for computational simplicity. They are distinguished from direct triangle rasterization by operating on pre-computed surface samples or 2D texture slices, ensuring connectivity or enabling real-time performance insensitive to scene complexity.

#### Rasterization-based Volume Modeling
The process of building volume data voxel-by-voxel, considered the third layer in the voxel modeling abstraction hierarchy [S5, unofficial]. It solves the problem of assigning density values to voxels based on primitive contributions. It differs from instantiation-based modeling by pulling values into a voxel (similar to raytracing), whereas instantiation-based modeling pushes values into voxels (similar to micropolygon rendering) [S5, unofficial]. The main rasterization loop iterates over voxels in the discrete bounding box, transforms the voxel position to world space, samples the primitive's density function, and adds the value to the buffer if positive [S5, unofficial].

#### Single-Pass Voxelization
A voxelization approach that utilizes the geometry shader to reduce draw calls by selecting the axis from which each triangle has the largest overall projection for fragment generation [S6, unofficial]. It solves the problem of multiple draw calls in multi-pass approaches. It employs conservative rasterization to generate fragments as long as there is something inside the pixel, not only if its center is covered [S6, unofficial]. It uses an MSAA render target during the voxelization process to solve the issue of incorrectly filling empty cells caused by conservative rasterization generating too many fragments [S6, unofficial]. Hardware support for conservative rasterization is available on Nvidia Maxwell architecture and later; RTX driver support is available for Turing and Pascal architecture GPUs [S6, unofficial]. A pitfall is that GPUs only generate fragments if a pixel's center is covered by a triangle, leading to small cracks at the edges of triangles if conservative rasterization is not used [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N_{faces} \times N_{voxels\_in\_bbox})$, where $N_{faces}$ is the number of triangles and $N_{voxels\_in\_bbox}$ is the number of voxels in the bounding box of each triangle [S5, unofficial].
*   **Memory Complexity:** $O(N_{occupied\_voxels})$ when using a hash table [S3, S4, unofficial].
*   **Performance:** GPU-based variants offer significant speedups (e.g., 50x) for high-resolution grids compared to CPU-based methods [S1].
*   **Strengths:** Efficient for sparse meshes; leverages existing rasterization hardware; simple to implement [S3, S4, unofficial].
*   **Limitations:** Output mesh size can be very large compared to input; standard rasterization may produce holes without conservative techniques [S2, S6, unofficial].
*   **When to use:** When a surface representation (voxel mesh) is needed for voxel art or simplified collision detection, and the mesh is sparse [S2, S4, unofficial].
*   **When not to use:** When deep voxelization (interior voxels) is required, as this method typically performs shell voxelization [S2, unofficial].

## Background
The method originates from the need to convert polygonal models into voxel formats for real-time rendering and voxel art applications. It is implemented in libraries such as Point-Cloud-Utils [S1] and the header-only C library by Karim Naaji [S4, unofficial]. It is also used in Python via `madcad` [S3, unofficial]. The technique is distinct from ray-tracing voxelization and is often compared to geometry shader-based approaches, with rasterization-based methods generally providing better surface accuracy [S2, unofficial].
