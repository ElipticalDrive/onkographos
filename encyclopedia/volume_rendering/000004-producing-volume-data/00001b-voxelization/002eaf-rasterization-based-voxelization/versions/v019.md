# Rasterization-based Voxelization

Also called: Cube Mesh Generation, Hash-based Surface Voxelization, Sparse Voxelization with PositionMap Hashing, Voxelizing a Triangle Mesh, madcad Voxelization

## Overview
Rasterization-based Voxelization converts a continuous triangle mesh into a discrete volumetric representation by projecting the geometry onto a 3D grid using rasterization primitives [S1][S4, unofficial]. It solves the problem of generating a voxelized mesh (either as a set of occupied voxel centers or explicit cube geometry) from polygonal input [S2, unofficial]. It differs from [Voxel Carving](1213-voxel-carving.md) and [Voxel Grid Data Generation Pipeline](1208-voxel-grid-data-generation-pipeline.md) by treating the mesh as a set of fragments to be accumulated into a sparse structure, rather than ray-casting through a volume or using constructive solid geometry [S1][S3, unofficial]. Unlike [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md), it operates directly on explicit triangle coordinates without requiring signed distance field evaluation [S4, unofficial].

## How it works
**Inputs:**
*   Input mesh: Vertices $V$ and Faces $F$ (triangles).
*   Voxel size: $vs = (vs_x, vs_y, vs_z)$, the physical dimensions of a voxel [S4, unofficial].
*   Voxel origin: $vox\_origin$, the world-space coordinate of the $(0,0,0)$ voxel corner [S1].
*   Precision: $p$, a tolerance factor to reduce artifacts [S2, unofficial].

**Outputs:**
*   Option A: A sparse set of occupied voxel integer coordinates $(i, j, k)$ [S1].
*   Option B: A `vx_mesh_t` structure containing cube vertices, normals, and indices for each occupied voxel [S4, unofficial].
*   Option C: A point cloud of voxel centers with optional colors [S4, unofficial].

**Data Structures:**
*   **Hash Table:** A sparse structure mapping voxel positions to data. In C implementations, this is a hash table with buckets containing linked lists of `vx_voxel_data_t` nodes [S4, unofficial]. In Python, a `set` of tuples is used [S3, unofficial].
*   **Voxel Data (`vx_voxel_data_t`):** Contains `position` (world-space center of the voxel) and `color` (optional) [S4, unofficial].
*   **Output Mesh (`vx_mesh_t`):**
    *   `vertices`: Array of size $N_{voxels} \times 8$ [S4, unofficial].
    *   `normals`: Array of size 6 (predefined for 6 faces of a cube) [S4, unofficial].
    *   `indices`: Array of size $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$ [S4, unofficial].
    *   `colors`: Array of size $N_{voxels} \times 8$ (if input has colors) [S4, unofficial].

**Steps:**

1.  **Compute Half-Voxel Size:**
    Calculate $hvs = vs \times 0.5$ [S4, unofficial]. This defines the offset from the voxel center to its corners.

2.  **Initialize Rasterization Context:**
    Create a hash table or set to store unique voxel coordinates [S3, S4, unofficial].

3.  **Iterate Over Triangles:**
    For each triangle face $f \in F$ with vertices $v_0, v_1, v_2$:
    
    4.  **Determine Occupied Voxels:**
        Identify all voxel grid cells intersected by the triangle.
        *   *Implementation Note (C):* The internal function `vx__voxelize` is called with the mesh, voxel size, half-voxel size, and precision. It iterates the triangle's bounding box in voxel space and inserts occupied voxel keys into the hash table [S4, unofficial].
        *   *Implementation Note (Python):* The `PositionMap` hasher maps the triangle's points to voxel grid keys. `hasher.keysfor(points)` returns the set of occupied voxel coordinates [S3, unofficial].
        
    5.  **Store Voxel Data:**
        For each unique voxel coordinate $(i, j, k)$ found:
        *   Compute the world-space center: $C = vox\_origin + (i + 0.5) \times vs$ [G].
        *   If colors are present, interpolate the vertex colors of the triangle at the intersection point or use the centroid color [S4, unofficial].
        *   Insert $(C, color)$ into the hash table. If the voxel already exists, the hash table handles deduplication (e.g., by not incrementing the voxel count or merging data) [S4, unofficial].

6.  **Generate Output Geometry (Optional):**
    If generating a cube mesh (`vx_mesh_t`):
    
    7.  **Allocate Memory:**
        Allocate arrays for $N_{voxels}$ cubes:
        *   Vertices: $N_{voxels} \times 8$
        *   Indices: $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$ (typically 36 for 12 triangles per cube) [S4, unofficial].
        
    8.  **Define Cube Offsets:**
        Define the 8 corner offsets relative to the center using $hvs$:
        $$
        \begin{aligned}
        &(-hvs_x, hvs_y, hvs_z), (-hvs_x, -hvs_y, hvs_z), (hvs_x, -hvs_y, hvs_z), (hvs_x, hvs_y, hvs_z), \\
        &(-hvs_x, hvs_y, -hvs_z), (-hvs_x, -hvs_y, -hvs_z), (hvs_x, -hvs_y, -hvs_z), (hvs_x, hvs_y, -hvs_z)
        \end{aligned}
        $$ [S4, unofficial].
        
    9.  **Populate Mesh:**
        Iterate through the hash table. For each occupied voxel:
        *   Add the 8 vertices (center + offsets) to the global vertex buffer.
        *   Add the 12 triangle indices (referencing the 8 vertices) to the index buffer.
        *   Copy predefined face normals to the normal buffer [S4, unofficial].

10. **Free Resources:**
    Destroy the hash table and temporary structures [S4, unofficial].

**Pseudocode (Python-like):**

```python
def rasterization_voxelization(vertices, faces, voxel_size, voxel_origin, precision=0.01):
    """
    Voxelize a triangle mesh into a set of occupied voxel centers.
    """
    # 1. Compute half-voxel size
    hvs = [s * 0.5 for s in voxel_size]
    
    # 2. Initialize sparse storage (Hash Set)
    occupied_voxels = set()
    
    # 3. Iterate over triangles
    for face in faces:
        # Get triangle vertices
        v0, v1, v2 = vertices[face[0]], vertices[face[1]], vertices[face[2]]
        
        # 4. Determine occupied voxels for this triangle
        # This step depends on the specific rasterizer implementation.
        # Conceptually, it finds all (i,j,k) such that the voxel box 
        # intersects the triangle plane within the triangle bounds.
        
        # Using a hypothetical rasterizer function that returns voxel keys
        # In 'madcad', this is hasher.keysfor([v0, v1, v2])
        voxel_keys = rasterize_triangle(v0, v1, v2, voxel_size, voxel_origin, precision)
        
        # 5. Add to set (deduplication happens automatically)
        for key in voxel_keys:
            occupied_voxels.add(key)
            
    return occupied_voxels

def generate_cube_mesh(occupied_voxels, voxel_size, voxel_origin):
    """
    Convert occupied voxel coordinates into a cube mesh.
    """
    hvs = [s * 0.5 for s in voxel_size]
    
    # Define 8 corner offsets relative to center
    offsets = [
        (-hvs[0],  hvs[1],  hvs[2]),
        (-hvs[0], -hvs[1],  hvs[2]),
        ( hvs[0], -hvs[1],  hvs[2]),
        ( hvs[0],  hvs[1],  hvs[2]),
        (-hvs[0],  hvs[1], -hvs[2]),
        (-hvs[0], -hvs[1], -hvs[2]),
        ( hvs[0], -hvs[1], -hvs[2]),
        ( hvs[0],  hvs[1], -hvs[2])
    ]
    
    vertices = []
    indices = []
    
    for (i, j, k) in occupied_voxels:
        # Compute world center
        center = [
            voxel_origin[0] + (i + 0.5) * voxel_size[0],
            voxel_origin[1] + (j + 0.5) * voxel_size[1],
            voxel_origin[2] + (k + 0.5) * voxel_size[2]
        ]
        
        # Add 8 vertices
        base_idx = len(vertices)
        for dx, dy, dz in offsets:
            vertices.append([
                center[0] + dx,
                center[1] + dy,
                center[2] + dz
            ])
            
        # Add 12 triangles (36 indices) for the cube
        # Standard cube face connectivity
        cube_faces = [
            0, 1, 2, 0, 2, 3,  # Front
            4, 6, 5, 4, 7, 6,  # Back
            4, 5, 1, 4, 1, 0,  # Left
            3, 2, 6, 3, 6, 7,  # Right
            3, 7, 0, 3, 4, 7,  # Top
            1, 5, 6, 1, 6, 2   # Bottom
        ]
        
        for idx in cube_faces:
            indices.append(base_idx + idx)
            
    return vertices, indices
```

**Edge Cases and Pitfalls:**
*   **Holes/Artifacts:** Standard rasterization may miss voxels if the triangle is thin or aligned with the grid, leading to "holes" in the voxel shell [S2, unofficial]. The `precision` parameter helps mitigate this by expanding the intersection test [S2, unofficial].
*   **Performance:** The output mesh size scales with voxel density. A small voxel size on a complex mesh can result in millions of vertices and faces, impacting rendering performance [S2, unofficial].
*   **Sparse vs Dense:** Using a hash table/set (sparse) is more memory-efficient for sparse meshes than a 3D boolean array (dense) [S3, unofficial].

## Subtopics

### [3D Grid Rasterization](903-3d-grid-rasterization.md)
3D Grid Rasterization is a CPU-based algorithm that determines which voxels in a fixed-resolution 3D grid are intersected by a triangle mesh, producing a binary occupancy grid. It solves the problem of converting continuous polygonal geometry into a discrete volumetric representation without performing surface reconstruction (such as QEF or dual vertex solving). It differs from full o-voxel implementations by omitting the face QEF, boundary QEF, and dual vertex solve steps, focusing solely on the intersect scanline to find occupied voxels. It differs from GPU-based siblings like [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on CPU-side scanline filling and hash-table deduplication rather than parallel fragment shaders [G].

### [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md)
GPU Volume Kernel Voxelization is a technique that accelerates the voxelization of triangle meshes by parallelizing the iteration over the 2D XY plane of the voxel grid using a GPU compute shader. It solves the performance bottleneck of CPU-based voxelization, where nested loops over X and Y coordinates are executed sequentially. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) and [3D Grid Rasterization](903-3d-grid-rasterization.md) which project geometry into 3D textures, this method retains the explicit triangle-voxel intersection logic of CPU implementations but distributes the workload across GPU threads, achieving significant speedups (e.g., 50x) for high-resolution grids.

### [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md)
GPU Voxelization via Compute Shaders converts 3D triangle meshes into a uniform 3D voxel grid by leveraging GPU parallel processing. It solves the problem of generating volumetric data for real-time ray marching or volume rendering with high throughput. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md), which projects triangles via the fixed-function graphics pipeline, compute shader methods decouple intersection logic from rasterization, allowing custom geometric tests and atomic operations on 3D buffers or textures.

### [GPU Voxelization](2633-gpu-voxelization.md)
GPU Voxelization converts a triangle mesh into a regular voxel grid by leveraging the GPU's hardware rasterization pipeline to map fragments directly to 3D grid cells. It solves the performance bottleneck of CPU-based ray-tracing voxelization by parallelizing the intersection test across the rasterizer. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using a 3D texture UAV or SSBO as the direct write target rather than a 2D accumulation buffer, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on standard triangle rasterization rather than volume kernels.

### [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md)
CPU Mesh Voxelization converts a triangle mesh into a 3D grid of voxels by iterating over the bounding box of each triangle and testing each voxel center against the triangle's plane and edge constraints. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by outputting a binary occupancy grid or bit-packed table rather than generating a cube mesh per occupied voxel. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using exact geometric overlap tests (SAT or plane/projection) rather than simple grid cell intersection, and from [Voxelization via Triangle Scattering](3779-voxelization-via-triangle-scattering.md) by iterating cells against triangles rather than scattering triangles into cells.

### [Voxel Rasterization](3204-voxel-rasterization.md)
Voxel Rasterization converts a triangle mesh into a voxelized representation by rendering the geometry into a 3D voxel buffer, supporting both simple occupancy and normal/color mapping. It differs from its sibling [3D Grid Rasterization](903-3d-grid-rasterization.md) by explicitly iterating over triangle surfaces to calculate interpolated points and normals rather than relying on a pure grid traversal, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by utilizing a Direct3D 11-based rendering pipeline or CUDA kernels for the rasterization step.

### [Conservative Voxelization](3247-conservative-voxelization.md)
Conservative voxelization is a hardware-accelerated algorithm for polygonal models that guarantees conservative correctness: every voxel intersecting the input model is correctly recognized. It differs from standard rasterization-based voxelization [Rasterization-based Voxelization] by computing the exact depth range of the intersection between the triangle and the voxel column, rather than using a single depth value which leads to missed voxels.

### [Conservative Rasterization via Triangle Expansion](3531-conservative-rasterization-via-triangle-expansion.md)
This method eliminates voxelization holes caused by standard rasterization, which only covers pixels whose centers lie inside a triangle, by expanding the triangle in clip space and culling the expanded area in the fragment shader. It differs from sibling methods like [Conservative Voxelization](3247-conservative-voxelization.md) by implementing the expansion logic manually in the geometry shader using homogeneous plane mathematics, rather than relying on hardware-specific conservative rasterization extensions or post-processing hole-filling.

### [Multi-view projection](5937-multi-view-projection.md)
Multi-view projection voxelization converts a triangle mesh into a voxel grid by rasterizing the geometry from multiple camera viewpoints, typically aligned with the principal axes of the scene's bounding box. This approach solves the coverage gaps and geometric distortions inherent in single-view projection methods, which fail when surface normals are perpendicular to the view direction. It differs from single-view methods by ensuring comprehensive coverage through redundancy, and from compute-shader-based methods by leveraging standard graphics pipeline rasterization.

### [Parametric Surface Voxelization](6032-parametric-surface-voxelization.md)
Parametric Surface Voxelization converts a parametric surface (such as a subdivision surface or implicit field) into a voxel grid by rasterizing points in the 2D parameter space rather than the 3D object space. It differs from triangle-based rasterization methods by operating directly on the parametric domain, allowing for the voxelization of complex implicit or subdivision surfaces without explicit triangulation. This approach is particularly suited for real-time applications where rapid voxelization of non-polygonal geometry is required.

### [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md)
This family of techniques converts 3D geometric data into voxel grids by projecting or transferring information into 2D image space (textures) before reconstructing the 3D volume [G]. Unlike direct 3D rasterization, these methods leverage the GPU's fixed-function rasterizer or image load/store operations on 2D textures to determine voxel occupancy [G]. They are distinguished from direct triangle rasterization by operating on pre-computed surface samples or 2D texture slices, ensuring connectivity or enabling real-time performance insensitive to scene complexity [G].

### Rasterization-based Volume Modeling
Rasterization-based Volume Modeling is the process of building volume data voxel-by-voxel, considered the third layer in the voxel modeling abstraction hierarchy [S5, unofficial]. It solves the problem of assigning density values to voxels based on primitive contributions [S5, unofficial]. It differs from instantiation-based modeling by pulling values into a voxel (similar to raytracing), whereas instantiation-based modeling pushes values into voxels (similar to micropolygon rendering) [S5, unofficial]. The main rasterization loop iterates over voxels in the discrete bounding box, transforms the voxel position to world space, samples the primitive's density function, and adds the value to the buffer if positive [S5, unofficial].

### Single-Pass Voxelization
Single-Pass Voxelization is a voxelization approach that utilizes the geometry shader to reduce draw calls by selecting the axis from which each triangle has the largest overall projection for fragment generation [S6, unofficial]. It solves the problem of excessive draw calls in multi-object scenes [S6, unofficial]. It employs conservative rasterization to generate fragments as long as there is something inside the pixel, not only if its center is covered, and uses an MSAA render target to solve the issue of incorrectly filling empty cells [S6, unofficial]. Hardware support for conservative rasterization is available on Nvidia Maxwell architecture and later; RTX driver support is available for Turing and Pascal architecture GPUs [S6, unofficial]. A pitfall is that GPUs only generate fragments if a pixel's center is covered by a triangle, leading to small cracks at the edges of triangles, and conservative rasterization can generate too many fragments, incorrectly filling cells in the voxel grid that should be empty [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N_{triangles} \times N_{voxels\_per\_triangle})$ for the rasterization step, where $N_{voxels\_per\_triangle}$ depends on the triangle's bounding box in voxel space and the grid resolution [S1][S4, unofficial]. Hash table insertions are $O(1)$ on average [S3, unofficial].
*   **Memory Complexity:** $O(N_{occupied\_voxels})$ for the sparse hash table [S3, unofficial]. The output mesh size is $O(N_{occupied\_voxels} \times 8)$ for vertices [S4, unofficial].
*   **Measured Performance:** For a torus mesh (441 vertices, 800 faces, radius 20 units), a voxel size of 0.75 results in 61,312 vertices and 91,968 faces, while a voxel size of 0.5 results in 144,968 vertices and 217,452 faces [S2, unofficial]. For a bunny mesh (2503 vertices, 4968 faces), a voxel size of 0.2 results in 53,720 vertices and 80,580 faces [S2, unofficial].
*   **Strengths:** Simple to implement; produces clean shell voxelization suitable for voxel art; sparse storage is memory-efficient for large, sparse scenes [S2, S3, unofficial].
*   **Limitations:** Output mesh size can be very large compared to the input, impacting rendering performance if not managed [S2, unofficial]. Standard rasterization may produce holes if precision is not tuned [S2, unofficial].
*   **When to use:** When a surface-only voxel representation (shell) is needed for voxel art or simple volume rendering, and the mesh is not extremely dense [S2, unofficial].
*   **When not to use:** When deep voxelization (interior voxels) is required, or when the output mesh size is a critical bottleneck [S2, unofficial].

## Background
Rasterization-based voxelization is a technique implemented in libraries such as Point-Cloud-Utils and the C-based voxelizer library by Karim Naaji [S1][S4, unofficial]. It is used in applications like GeeXLab for real-time voxel visualization [S2, unofficial]. The method is part of the broader voxel modeling abstraction hierarchy, where it is classified as a rasterization primitive that pulls values into a voxel [S5, unofficial]. It is often compared favorably to geometry shader-based methods for its accuracy in surface intersection [S2, unofficial].
