# Rasterization-based Voxelization

Also called: Cube Mesh Generation, Voxelizing a Triangle Mesh

## Overview
Rasterization-based Voxelization converts a continuous triangle mesh into a discrete 3D voxel grid by projecting the mesh geometry onto a 2D plane and using hardware or software rasterization to determine voxel occupancy [S1][S2, S3, unofficial]. It solves the problem of generating volumetric representations for ray marching or volume rendering by leveraging the efficiency of scan-conversion algorithms [S1][S4, unofficial]. It differs from ray-tracing voxelization by avoiding per-voxel ray intersection tests, and from analytic voxelization by relying on polygonal approximations rather than implicit functions [S1][S2, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle mesh defined by vertices $V$ and faces $F$, a voxel size $vs = (vs_x, vs_y, vs_z)$, an origin $origin$ (typically $[0,0,0]$), and a precision factor $p$ [S1][S2, S3, unofficial].
*   **Output:** A set of occupied voxel coordinates (integer indices $ijk$), and optionally a cube mesh or point cloud representing the voxelized surface [S1][S3, unofficial].

**Data Structures:**
*   **Voxel Grid/Hash Table:** A sparse structure mapping voxel coordinates to data. In CPU implementations, a hash table is often used to store occupied voxels to handle arbitrary mesh positions and resolutions efficiently [S3, unofficial].
*   **Voxel Data:** Each entry in the hash table stores the voxel center position and optionally interpolated attributes (color, normal) [S3, unofficial].
*   **Output Mesh Layout (Cube Mesh):**
    *   `vertices`: Array of size $N_{voxels} \times 8$, storing the 8 corners of each voxel cube [S3, unofficial].
    *   `normals`: Array of size 6, storing predefined face normals for the cube [S3, unofficial].
    *   `indices`: Array of size $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$, defining the faces of the cubes [S3, unofficial].
    *   `colors`: Optional array of size $N_{voxels} \times 8$ [S3, unofficial].

**Steps:**
1.  **Initialization:** Define the voxel size $vs$ and compute the half-voxel size $hvs = vs \times 0.5$ [S3, unofficial].
2.  **Rasterization (Voxelization):**
    *   Iterate over each triangle in the input mesh.
    *   Determine the bounding box of the triangle in voxel space.
    *   Rasterize the triangle onto the 2D plane (typically XY, ZY, or XZ depending on implementation or view direction) to identify intersecting voxel cells [S1][S3, S5, unofficial].
    *   For each intersected cell, compute the voxel center and insert it into the hash table. If a voxel is already present, attributes (like color) may be averaged or overwritten depending on the specific implementation [S3, unofficial].
    *   Use the precision factor $p$ to handle edge cases and reduce "holes" artifacts [S2, S3, unofficial].
3.  **Geometry Generation (Optional):**
    *   Iterate through the hash table of occupied voxels.
    *   For each occupied voxel, generate the 8 corner vertices of a cube centered at the voxel position.
    *   Assign the predefined normals and indices to construct the cube mesh [S3, unofficial].
4.  **Output:** Return the voxel coordinates, point cloud, or cube mesh [S1][S3, unofficial].

**Pseudocode:**
```python
def rasterization_voxelize(mesh, voxel_size, origin, precision):
    """
    Voxelize a triangle mesh using rasterization.
    Returns a list of occupied voxel coordinates (ijk).
    """
    # 1. Initialize data structures
    occupied_voxels = {} # Hash map: (i, j, k) -> attributes
    
    # 2. Process each triangle
    for triangle in mesh.faces:
        vertices = [mesh.vertices[i] for i in triangle.indices]
        
        # Compute bounding box in voxel space
        # Map world coordinates to voxel indices
        min_ijk = floor((min(vertices) - origin) / voxel_size)
        max_ijk = floor((max(vertices) - origin) / voxel_size)
        
        # 3. Rasterize triangle to voxel grid
        # This step typically involves projecting the triangle to 2D 
        # and filling the corresponding 2D pixels, then extruding to 3D.
        # For a robust implementation, one might iterate the 2D bounding box
        # and test if the pixel center lies inside the projected triangle.
        for i in range(min_ijk.x, max_ijk.x + 1):
            for j in range(min_ijk.y, max_ijk.y + 1):
                # Determine the range of k indices intersected by the triangle
                # This requires solving for the intersection of the triangle plane
                # with the voxel slab boundaries.
                k_min, k_max = get_k_range(vertices, i, j, voxel_size, origin)
                
                for k in range(k_min, k_max + 1):
                    voxel_key = (i, j, k)
                    
                    # Check if the voxel center is inside the triangle
                    # Or use rasterization coverage logic
                    if is_voxel_intersected(vertices, voxel_key, voxel_size, origin, precision):
                        if voxel_key not in occupied_voxels:
                            # Compute voxel center
                            center = origin + voxel_size * (vec3(i, j, k) + 0.5)
                            occupied_voxels[voxel_key] = {'center': center}
                            
    return list(occupied_voxels.keys())

def generate_cube_mesh(occupied_voxels, voxel_size, origin, gap_fraction=0.0):
    """
    Generate a cube mesh from occupied voxel coordinates.
    """
    vertices = []
    indices = []
    
    # Predefined cube corner offsets relative to center
    # Note: The order must match the index definition
    hvs = voxel_size * 0.5
    offsets = [
        [-hvs.x,  hvs.y,  hvs.z],
        [-hvs.x, -hvs.y,  hvs.z],
        [ hvs.x, -hvs.y,  hvs.z],
        [ hvs.x,  hvs.y,  hvs.z],
        [-hvs.x,  hvs.y, -hvs.z],
        [-hvs.x, -hvs.y, -hvs.z],
        [ hvs.x, -hvs.y, -hvs.z],
        [ hvs.x,  hvs.y, -hvs.z]
    ]
    
    # Define cube faces (indices into the 8 corners)
    # Standard cube face indices (e.g., 6 faces, 4 vertices each, 3 indices per triangle)
    # Simplified for brevity: assuming a standard quad or triangle list format
    face_indices = [
        0, 1, 2, 0, 2, 3, # Front
        4, 5, 6, 4, 6, 7, # Back
        0, 4, 7, 0, 7, 3, # Top
        1, 5, 6, 1, 6, 2, # Bottom
        0, 1, 5, 0, 5, 4, # Left
        2, 6, 7, 2, 7, 3  # Right
    ]
    
    vertex_offset = 0
    for voxel_key, data in occupied_voxels.items():
        center = data['center']
        
        # Generate 8 vertices for this voxel
        for offset in offsets:
            # Apply gap fraction if desired (shrink cube)
            # For simplicity, we use full voxel size here
            v = center + offset
            vertices.append(v)
            
        # Generate indices for this voxel
        for idx in face_indices:
            indices.append(vertex_offset + idx)
            
        vertex_offset += 8
        
    return vertices, indices
```

**Parameters:**
*   `voxel_size`: Physical dimension of a voxel. Typical values: $0.75, 0.5, 0.2, 0.1$ units [S2, unofficial]. In Point-Cloud-Utils, a common value is $1/256.0$ [S1].
*   `origin`: Location of the bottom-left-back corner of the $[0,0,0]$ voxel. Typically $[0,0,0]$ [S1].
*   `precision`: A factor to reduce "holes" artifacts. Typical value: $0.01$ [S2, S3, unofficial].
*   `gap_fraction`: Spacing between cubes in the generated voxel grid geometry. Typical value: $0.02$ [S1].

**Edge Cases and Pitfalls:**
*   **Holes:** Standard rasterization only covers pixels whose centers lie inside a triangle, leading to small cracks at edges [S5, unofficial]. Conservative rasterization or precision factors can mitigate this [S2, S5, unofficial].
*   **Overfilling:** Conservative rasterization may generate too many fragments, incorrectly filling empty cells [S5, unofficial]. MSAA render targets can help resolve this [S5, unofficial].
*   **Performance:** The output mesh size scales with voxel density. A torus with 441 vertices and 800 faces can result in 61,312 vertices and 91,968 faces at voxel size 0.75, or 144,968 vertices and 217,452 faces at voxel size 0.5 [S2, unofficial].

## Subtopics

### [3D Grid Rasterization](903-3d-grid-rasterization.md)
A CPU-based algorithm that determines which voxels in a fixed-resolution 3D grid are intersected by a triangle mesh, producing a binary occupancy grid or a grid with interpolated colors. It solves the problem of converting continuous polygonal geometry into a discrete volumetric representation without performing surface reconstruction (such as QEF or dual vertex solving). It differs from full o-voxel implementations by omitting the face QEF, boundary QEF, and dual vertex solve steps, focusing solely on the intersect scanline to find occupied voxels. It differs from GPU-based siblings like [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on CPU-side scanline filling and hash-table deduplication rather than parallel fragment shaders.

### [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md)
GPU Volume Kernel Voxelization is a technique that accelerates the voxelization of triangle meshes by parallelizing the iteration over the 2D XY plane of the voxel grid using a GPU compute shader. It solves the performance bottleneck of CPU-based voxelization, where nested loops over X and Y coordinates are executed sequentially. Unlike rasterization-based alternatives that project geometry into 3D textures, this method retains the explicit triangle-voxel intersection logic of CPU implementations but distributes the workload across GPU threads, achieving significant speedups (e.g., 50x) for high-resolution grids.

### [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md)
Implicit Surface Voxelization converts a mathematical implicit surface definition into a discrete voxel grid by rasterizing 2D rectangles within a Region of Interest (ROI) and evaluating the implicit function in the pixel shader. It differs from triangle-based rasterization methods (e.g., [Rasterization-based Voxelization](908-rasterization-based-voxelization.md)) by operating directly on analytical functions rather than polygonal approximations, allowing for the handling of complex, non-polygonal geometry.

### [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md)
GPU Voxelization via Compute Shaders converts 3D triangle meshes into a uniform 3D voxel grid by leveraging GPU parallel processing. It solves the problem of generating volumetric data for real-time ray marching or volume rendering with high throughput. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md), which projects triangles via the fixed-function graphics pipeline, compute shader methods decouple intersection logic from rasterization, allowing custom geometric tests and atomic operations on 3D buffers or textures.

### [GPU Voxelization](2633-gpu-voxelization.md)
GPU Voxelization maps 3D triangle meshes to a voxel grid by leveraging the GPU's hardware rasterization pipeline, projecting triangles onto a 2D plane and using shaders to write occupied voxel indices into a buffer. It solves the performance bottleneck of CPU-based ray-tracing voxelization by parallelizing the rasterization process across thousands of GPU cores. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by specifically utilizing the GPU rendering pipeline (vertex, geometry, fragment shaders) and atomic operations for concurrent writes, distinguishing it from CPU-based or compute-shader-only approaches.

### [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md)
CPU Mesh Voxelization converts a triangle mesh into a 3D grid of voxels by iterating over the bounding box of each triangle and testing each voxel center against the triangle's plane and edge constraints. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly rasterizing triangles into a hash table of voxel centers and colors, then generating a cube mesh for each occupied voxel, whereas CPU Mesh Voxelization typically outputs a binary occupancy grid or bit-packed table. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using exact geometric overlap tests (SAT or plane/projection) rather than simple grid cell intersection, and from [Voxelization via Triangle Scattering](3779-voxelization-via-triangle-scattering.md) by iterating cells against triangles rather than scattering triangles into cells.

### [Voxel Rasterization](3204-voxel-rasterization.md)
Voxel Rasterization converts a triangle mesh into a voxelized representation by rendering the geometry into a 3D voxel buffer, supporting both simple occupancy and normal/color mapping. It differs from its sibling [3D Grid Rasterization](903-3d-grid-rasterization.md) by explicitly iterating over triangle surfaces to calculate interpolated points and normals rather than relying on a pure grid traversal, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by utilizing a Direct3D 11-based rendering pipeline or CUDA kernels for the rasterization step.

### [Conservative Rasterization via Triangle Expansion](3531-conservative-rasterization-via-triangle-expansion.md)
This method eliminates voxelization holes caused by standard rasterization, which only covers pixels whose centers lie inside a triangle, by expanding the triangle in clip space and culling the expanded area in the fragment shader. It differs from sibling methods like [Conservative Voxelization](3247-conservative-voxelization.md) by implementing the expansion logic manually in the geometry shader using homogeneous plane mathematics, rather than relying on hardware-specific conservative rasterization extensions or post-processing hole-filling.

### [Multi-view projection](5937-multi-view-projection.md)
Multi-view projection voxelization generates a 3D voxel representation of a scene by rasterizing geometry from multiple orthogonal viewing directions, typically aligned with the principal axes. It solves the problem of geometric holes, cracks, and missing surface data that occur when voxelizing from a single viewpoint, ensuring robust coverage for subsequent volume rendering or ray tracing. It differs from single-view methods by explicitly handling degenerate cases where triangles are parallel to the viewing direction, and from compute-shader methods by relying on standard rasterization pipelines to project geometry into intermediate buffers.

### [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md)
This family of techniques converts 3D geometric data into voxel grids by projecting or transferring information into 2D image space (textures) before reconstructing the 3D volume. Unlike direct 3D rasterization, these methods leverage the GPU's fixed-function rasterizer or image load/store operations on 2D textures to determine voxel occupancy, often trading memory bandwidth for computational simplicity. They are distinguished from direct triangle rasterization by operating on pre-computed surface samples or 2D texture slices, ensuring connectivity or enabling real-time performance insensitive to scene complexity.

### Rasterization-based Volume Modeling
The process of building volume data voxel-by-voxel, considered the third layer in the voxel modeling abstraction hierarchy [S4, unofficial]. It solves the problem of assigning density values to voxels based on primitive contributions. It differs from instantiation-based modeling by pulling values into a voxel (similar to raytracing), whereas instantiation-based modeling pushes values into voxels (similar to micropolygon rendering) [S4, unofficial]. The main rasterization loop iterates over voxels in the discrete bounding box, transforms voxel position to world space, samples the primitive, and adds the value to the buffer if positive [S4, unofficial].

### Single-Pass Voxelization
A voxelization approach that utilizes the geometry shader to reduce draw calls by selecting the axis from which each triangle has the largest overall projection for fragment generation [S5, unofficial]. It solves the problem of multiple draw calls for objects with the same material. It employs conservative rasterization to generate fragments as long as there is something inside the pixel, not only if its center is covered [S5, unofficial]. It uses an MSAA render target to solve the issue of incorrectly filling empty cells caused by over-aggressive conservative rasterization [S5, unofficial]. Hardware support for conservative rasterization is available on Nvidia Maxwell architecture and later; RTX driver support is available for Turing and Pascal architecture GPUs [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Generally $O(N \cdot R)$, where $N$ is the number of triangles and $R$ is the number of voxels intersected by the triangles. GPU implementations can achieve significant speedups (e.g., 50x) for high-resolution grids compared to CPU-based nested loops [S1].
*   **Memory Complexity:** Depends on the output format. A cube mesh output scales with the number of occupied voxels ($N_{voxels} \times 8$ vertices) [S3, unofficial]. For a torus mesh (441 vertices, 800 faces), voxel size 0.75 results in 61,312 vertices and 91,968 faces, while voxel size 0.5 results in 144,968 vertices and 217,452 faces [S2, unofficial].
*   **Strengths:** High performance due to hardware rasterization; simple implementation; good for shell voxelization (surface only) [S2, unofficial].
*   **Limitations:** Output mesh size can be very large compared to the input mesh, impacting rendering performance if not managed [S2, unofficial]. Standard rasterization can produce holes, requiring conservative rasterization or precision adjustments [S2, S5, unofficial]. Conservative rasterization can overfill empty cells [S5, unofficial].
*   **When to use:** When a quick, surface-level voxel representation is needed for volume rendering or ray marching, and the input mesh is not excessively complex [S2, unofficial].
*   **When not to use:** When deep voxelization (interior voxels) is required, as this method typically performs shell voxelization [S2, unofficial]. When memory bandwidth is a critical bottleneck and the output mesh size is prohibitive [S2, unofficial].

## Background
Rasterization-based voxelization has been widely used in computer graphics for converting polygonal models into volumetric data for rendering and simulation. The Point-Cloud-Utils library provides a Python interface for this technique [S1]. A header-only C library for mesh voxelization was also popularized in the community, demonstrating its simplicity and effectiveness for voxel art [S2, unofficial]. The technique is often compared to geometry shader-based voxelizers, with rasterization-based methods generally providing better results due to more accurate surface intersection or rasterization techniques, avoiding the coarse approximation of centroid-based cubes [S2, unofficial]. The concept of rasterization-based volume modeling is also discussed in the context of production volume rendering, where it is distinguished from instantiation-based modeling [S4, unofficial]. Single-pass voxelization using geometry shaders and conservative rasterization has been explored for real-time ray-traced voxel global illumination [S5, unofficial].
