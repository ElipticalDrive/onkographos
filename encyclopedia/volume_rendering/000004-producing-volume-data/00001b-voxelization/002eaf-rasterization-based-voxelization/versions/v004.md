# Rasterization-based Voxelization

Also called: Cube Mesh Generation, Voxelizing a Triangle Mesh

## Overview
Rasterization-based Voxelization converts a continuous triangle mesh into a discrete volumetric representation by projecting the geometry onto a 3D grid using the graphics pipeline's rasterization logic [S1][S3, S4, unofficial]. It solves the problem of generating voxel data (occupancy, density, or surface meshes) from polygonal inputs without performing explicit ray-triangle intersection tests or surface reconstruction [S1][S4, unofficial]. It differs from ray-tracing voxelization by leveraging hardware-accelerated fragment generation to determine voxel coverage, and from analytic voxelization by relying on discrete geometric clipping rather than closed-form mathematical solutions [S4, S5, unofficial].

## How it works
The method maps continuous world-space coordinates to discrete integer grid indices $(i, j, k)$ using the principles defined in [Voxelization](12-voxelization.md). The core mechanism involves projecting triangles into a 3D voxel buffer, determining occupancy via rasterization coverage, and optionally generating explicit cube geometry for each occupied voxel [S1][S3, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   Input mesh vertices $V$ and faces $F$ [S1][S3, unofficial].
    *   Voxel size $v_s = (v_{sx}, v_{sy}, v_{sz})$ [S1][S3, unofficial].
    *   Voxel origin $o = (o_x, o_y, o_z)$, typically $(0,0,0)$ [S1].
    *   Precision factor $p$ (to reduce holes) [S2, S3, unofficial].
    *   Gap fraction $g$ (for cube mesh generation) [S1].
*   **Outputs**:
    *   Binary occupancy grid (array of voxel coordinates) [S1].
    *   Voxelized mesh (cube vertices and faces) [S1][S3, unofficial].
    *   Point cloud (voxel centers and optional colors) [S3, unofficial].

### Data Structures
The implementation typically uses a hash table to store occupied voxels to handle sparse grids and avoid fixed-size array limits [S3, unofficial].

**Hash Table Node (`vx_voxel_data_t`)**:
*   `position`: 3D float vector $(x, y, z)$ representing the voxel center [S3, unofficial].
*   `color`: Optional 3D float vector or RGBA value [S3, unofficial].

**Output Mesh Structure (`vx_mesh_t`)** [S3, unofficial]:
*   `vertices`: Array of size $N_{voxels} \times 8$, storing the 8 corners of each cube.
*   `normals`: Array of size 6, storing predefined face normals for cubes.
*   `colors`: Array of size $N_{voxels} \times 8$ (or NULL if no color data).
*   `indices`: Array of size $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$, storing face indices for cube construction.
*   `normalindices`: Array of size $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$.
*   `nvertices`, `nindices`, `nnormals`: Counters for active elements.

**Point Cloud Structure (`vx_point_cloud_t`)** [S3, unofficial]:
*   `vertices`: Array of size $N_{voxels}$, storing voxel centers.
*   `colors`: Array of size $N_{voxels}$ (or NULL).
*   `nvertices`: Count of voxels.

### Algorithm Steps
1.  **Initialization**:
    *   Load input mesh vertices $V$ and faces $F$ [S1].
    *   Compute half-voxel sizes $hvs = v_s \times 0.5$ [S3, unofficial].
    *   Allocate a hash table for voxel storage [S3, unofficial].

2.  **Rasterization (Voxelization)**:
    *   For each triangle in the mesh:
        *   Determine the bounding box of the triangle in voxel space.
        *   Iterate over all voxels within this bounding box.
        *   For each voxel, perform a triangle-voxel intersection test or rasterization coverage check [S3, unofficial].
        *   If the voxel intersects the triangle:
            *   Calculate the voxel center $c$ in world space.
            *   Compute a hash key for $c$ [S3, unofficial].
            *   Insert $(c, \text{color})$ into the hash table. If the voxel already exists, update or skip based on priority (e.g., first-come-first-served or accumulation) [S3, unofficial].
    *   *Note*: In GPU implementations, this step is parallelized using fragment shaders or compute shaders, writing to a 3D texture or buffer with atomic operations [S2, S4, S5, unofficial].

3.  **Output Generation**:
    *   **For Occupancy Grid**: Return the list of unique voxel coordinates from the hash table [S1].
    *   **For Cube Mesh**:
        *   Allocate output mesh arrays based on the number of unique voxels $N_{voxels}$ [S3, unofficial].
        *   Copy predefined cube normals to `outmesh->normals` [S3, unofficial].
        *   Define the 8 corner offsets for a cube centered at origin using $hvs$:
            $$
            \begin{aligned}
            &(-hvs_x, hvs_y, hvs_z), (-hvs_x, -hvs_y, hvs_z), (hvs_x, -hvs_y, hvs_z), (hvs_x, hvs_y, hvs_z), \\
            &(-hvs_x, hvs_y, -hvs_z), (-hvs_x, -hvs_y, -hvs_z), (hvs_x, -hvs_y, -hvs_z), (hvs_x, hvs_y, -hvs_z)
            \end{aligned}
            $$
        *   Iterate through the hash table. For each occupied voxel:
            *   Translate the 8 corner offsets by the voxel's center position.
            *   Store these vertices in `outmesh->vertices`.
            *   Store the corresponding indices in `outmesh->indices`.
            *   If colors are present, replicate the voxel's color to its 8 corners [S3, unofficial].
    *   **For Point Cloud**:
        *   Allocate point cloud arrays [S3, unofficial].
        *   Iterate through the hash table. For each voxel:
            *   Store the center position in `pc->vertices`.
            *   If colors exist, store the color in `pc->colors` [S3, unofficial].

4.  **Cleanup**:
    *   Free the hash table and temporary structures [S3, unofficial].

### Pseudocode
```python
def rasterization_voxelization(mesh, voxel_size, origin, precision=0.01, gap_fraction=0.02):
    """
    Converts a triangle mesh to a voxelized cube mesh using rasterization principles.
    """
    # 1. Initialization
    hvs = voxel_size * 0.5
    hash_table = HashTable()
    
    # 2. Rasterization Loop
    for triangle in mesh.faces:
        # Determine bounding box in voxel space
        # This involves transforming triangle vertices to voxel coordinates
        # and finding min/max integer indices
        voxel_bounds = get_voxel_bounds(triangle, voxel_size, origin)
        
        for i in range(voxel_bounds.min_x, voxel_bounds.max_x + 1):
            for j in range(voxel_bounds.min_y, voxel_bounds.max_y + 1):
                for k in range(voxel_bounds.min_z, voxel_bounds.max_z + 1):
                    # Check if voxel (i,j,k) intersects the triangle
                    # In GPU: this is handled by fragment shader coverage
                    # In CPU: this is an explicit intersection test
                    if intersects_triangle_voxel(triangle, i, j, k, voxel_size, origin, precision):
                        # Calculate voxel center
                        center = origin + voxel_size * vec3(i, j, k) + hvs
                        
                        # Insert into hash table
                        hash_table.insert(center, triangle.color)

    # 3. Generate Cube Mesh
    num_voxels = hash_table.size()
    out_vertices = []
    out_indices = []
    
    # Predefined cube corner offsets relative to center
    cube_offsets = [
        vec3(-hvs.x,  hvs.y,  hvs.z), vec3(-hvs.x, -hvs.y,  hvs.z),
        vec3( hvs.x, -hvs.y,  hvs.z), vec3( hvs.x,  hvs.y,  hvs.z),
        vec3(-hvs.x,  hvs.y, -hvs.z), vec3(-hvs.x, -hvs.y, -hvs.z),
        vec3( hvs.x, -hvs.y, -hvs.z), vec3( hvs.x,  hvs.y, -hvs.z)
    ]
    
    # Predefined cube face indices (24 indices for 12 triangles, or 36 for 6 quads)
    # Assuming 12 triangles (2 per face) for standard cube mesh
    cube_face_indices = [
        0, 1, 2, 0, 2, 3,  # Front
        4, 6, 5, 4, 7, 6,  # Back
        4, 5, 1, 4, 1, 0,  # Left
        3, 2, 6, 3, 6, 7,  # Right
        1, 5, 6, 1, 6, 2,  # Bottom
        4, 0, 3, 4, 3, 7   # Top
    ]
    
    vertex_offset = 0
    for center, color in hash_table.items():
        # Add 8 vertices for this voxel
        for offset in cube_offsets:
            out_vertices.append(center + offset)
            # If color is needed, replicate color to each vertex
            # out_colors.append(color)
        
        # Add indices for this voxel
        for idx in cube_face_indices:
            out_indices.append(vertex_offset + idx)
            
        vertex_offset += 8

    return out_vertices, out_indices
```

### Parameters and Typical Values
*   **Voxel Size**: Determines resolution. Typical values: $1/256$ [S1], or $0.1$ to $0.75$ units depending on scene scale [S2, unofficial].
*   **Precision**: A tolerance factor for intersection tests to prevent holes. Typical value: $0.01$ [S2, S3, unofficial].
*   **Gap Fraction**: Spacing between generated cubes. Typical value: $0.02$ [S1].

### Edge Cases and Pitfalls
*   **Holes**: Standard rasterization only covers pixels/voxels whose centers lie inside the triangle, leading to cracks at edges [S5, unofficial]. This is mitigated by the precision parameter or conservative rasterization [S2, S5, unofficial].
*   **Overfilling**: Conservative rasterization can incorrectly fill empty cells if not handled carefully (e.g., via MSAA or collision checks) [S5, unofficial].
*   **Performance**: The output mesh size scales with voxel density. A torus with 441 vertices can result in >140,000 vertices at voxel size 0.5 [S2, unofficial].
*   **Precision**: Floating-point errors in coordinate mapping can cause duplicate voxels or gaps [S3, unofficial].

## Subtopics

### [3D Grid Rasterization](903-3d-grid-rasterization.md)
A CPU-based algorithm that determines which voxels in a fixed-resolution 3D grid are intersected by a triangle mesh, producing a binary occupancy grid or a grid with interpolated colors. It solves the problem of converting continuous polygonal geometry into a discrete volumetric representation without performing surface reconstruction (such as QEF or dual vertex solving). It differs from full o-voxel implementations by omitting the face QEF, boundary QEF, and dual vertex solve steps, focusing solely on the intersect scanline to find occupied voxels. It differs from GPU-based siblings like [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on CPU-side scanline filling and hash-table deduplication rather than parallel fragment shaders.

### [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md)
GPU Volume Kernel Voxelization is a technique that accelerates the voxelization of triangle meshes by parallelizing the iteration over the 2D XY plane of the voxel grid using a GPU compute shader. It solves the performance bottleneck of CPU-based voxelization, where nested loops over X and Y coordinates are executed sequentially. Unlike rasterization-based alternatives that project geometry into 3D textures, this method retains the explicit triangle-voxel intersection logic of CPU implementations but distributes the workload across GPU threads, achieving significant speedups (e.g., 50x) for high-resolution grids.

### [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md)
Implicit Surface Voxelization converts a mathematical implicit surface definition into a discrete voxel grid by rasterizing 2D rectangles within a Region of Interest (ROI) and evaluating the implicit function in the pixel shader. It differs from triangle-based rasterization methods (e.g., [Rasterization-based Voxelization](908-rasterization-based-voxelization.md)) by operating directly on analytical functions rather than polygonal approximations, allowing for the handling of complex, non-polygonal geometry.

### [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md)
GPU Voxelization via Compute Shaders converts 3D triangle meshes into a uniform 3D voxel grid by leveraging GPU parallel processing. It solves the problem of generating volumetric data for real-time ray marching or volume rendering with high throughput. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md), which projects triangles via the fixed-function graphics pipeline, compute shader methods decouple intersection logic from rasterization, allowing custom geometric tests and atomic operations on 3D buffers or textures.

### [GPU Voxelization](2633-gpu-voxelization.md)
GPU Voxelization maps 3D triangle meshes to a voxel grid by leveraging the GPU's hardware rasterization pipeline, projecting triangles onto a 2D plane and using shaders to write occupied voxel indices into a buffer. It solves the performance bottleneck of CPU-based ray-tracing voxelization by parallelizing the rasterization process across thousands of GPU cores. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by specifically utilizing the GPU rendering pipeline (vertex, geometry, fragment shaders) and atomic operations for concurrent writes, distinguishing it from CPU-based or compute-shader-only approaches.

### [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md)
CPU Mesh Voxelization converts a triangle mesh into a 3D grid of voxels by iterating over the bounding box of each triangle and testing each voxel center against the triangle's plane and edge constraints. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly rasterizing triangles into a hash table of voxel centers and colors, then generating a cube mesh for each occupied voxel, whereas CPU Mesh Voxelization typically outputs a binary occupancy grid or bit-packed table. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using exact geometric overlap tests (SAT or plane/projection) rather than simple grid cell intersection, and from [Voxelization via Triangle Scattering](3779-voxelization-via-triangle-scattering.md) by iterating cells against triangles rather than scattering triangles into cells.

### [Voxel Rasterization](3204-voxel-rasterization.md)
Voxel Rasterization converts a triangle mesh into a voxelized representation by rendering the geometry into a 3D voxel buffer, supporting both simple occupancy and normal/color mapping. It differs from its sibling [3D Grid Rasterization](903-3d-grid-rasterization.md) by explicitly iterating over triangle surfaces to calculate interpolated points and normals rather than relying on a pure grid traversal, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by utilizing a Direct3D 11-based rendering pipeline or CUDA kernels for the rasterization step.

### [Conservative Rasterization via Triangle Expansion](3531-conservative-rasterization-via-triangle-expansion.md)
This method eliminates voxelization holes caused by standard rasterization, which only covers pixels whose centers lie inside a triangle, by expanding the triangle in clip space and culling the expanded area in the fragment shader. It differs from sibling methods like [Conservative Voxelization](3247-conservative-voxelization.md) by implementing the expansion logic manually in the geometry shader using homogeneous plane mathematics, rather than relying on hardware-specific conservative rasterization extensions or post-processing hole-filling.

### [Multi-view projection](5937-multi-view-projection.md)
Multi-view projection voxelization converts a triangle mesh into a voxelized representation by rasterizing the geometry from multiple orthogonal viewpoints, typically aligned with the scene's principal axes. It solves the problem of topological errors (cracks, tunnels, and missing voxels) inherent in single-axis projection methods by taking the union of occupied voxels from all views. Unlike [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md), which relies on edge-crossing tests for a single dominant axis, multi-view methods guarantee 6-connectivity coverage by ensuring every surface voxel is hit by at least one projection.

### [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md)
This family of techniques converts 3D geometric data into voxel grids by projecting or transferring information into 2D image space (textures) before reconstructing the 3D volume. Unlike direct 3D rasterization, these methods leverage the GPU's fixed-function rasterizer or image load/store operations on 2D textures to determine voxel occupancy, often trading memory bandwidth for computational simplicity. They are distinguished from direct triangle rasterization by operating on pre-computed surface samples or 2D texture slices, ensuring connectivity or enabling real-time performance insensitive to scene complexity.

### Rasterization-based Volume Modeling
The process of building volume data voxel-by-voxel, considered the third layer in the voxel modeling abstraction hierarchy [S4, unofficial]. It solves the problem of assigning density values to voxels from primitive representations. It differs from instantiation-based modeling by pulling values into a voxel (similar to raytracing), whereas instantiation-based modeling pushes values into voxels (similar to micropolygon rendering) [S4, unofficial]. The main rasterization loop iterates over voxels in the discrete bounding box, transforms voxel position to world space, samples the primitive, and adds the value to the buffer if positive [S4, unofficial].

### Single-Pass Voxelization
A voxelization approach that utilizes the geometry shader to reduce draw calls by selecting the axis from which each triangle has the largest overall projection for fragment generation [S5, unofficial]. It employs conservative rasterization to generate fragments as long as there is something inside the pixel, not only if its center is covered [S5, unofficial]. It uses an MSAA render target during the voxelization process to solve the issue of incorrectly filling empty cells [S5, unofficial]. Hardware support for conservative rasterization is available on Nvidia Maxwell architecture and later; RTX driver support is available for Turing and Pascal architecture GPUs [S5, unofficial]. GPUs only generate fragments if a pixel's center is covered by a triangle, leading to small cracks at the edges of triangles [S5, unofficial]. Conservative rasterization generates too many fragments, incorrectly filling cells in the voxel grid that should be empty [S5, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N \cdot B)$, where $N$ is the number of triangles and $B$ is the average number of voxels in the triangle's bounding box. In GPU implementations, this is parallelized, reducing effective time to $O(N)$ or $O(V)$ depending on implementation [S1][S5, unofficial].
*   **Memory Complexity**: $O(V)$, where $V$ is the number of occupied voxels. Hash tables add overhead for sparse grids [S3, unofficial].
*   **Performance**: GPU-based methods offer significant speedups (e.g., 50x) for high-resolution grids compared to CPU-based nested loops [S1].
*   **Strengths**: Fast, leverages existing graphics hardware, handles complex meshes well [S2, unofficial].
*   **Limitations**: Output mesh size can be very large (scaling with voxel density) [S2, unofficial]. Standard rasterization can produce holes [S5, unofficial]. Conservative rasterization can overfill [S5, unofficial].
*   **When to Use**: Real-time applications, voxel art generation, preprocessing for volume rendering [S1][S2, unofficial].
*   **When Not to Use**: When exact analytical surface representation is required, or when memory bandwidth is severely constrained and sparse structures are preferred [S4, unofficial].

## Background
Rasterization-based voxelization originated from the need to efficiently convert polygonal models into volumetric data for rendering and simulation [S1][S4, unofficial]. Early implementations used CPU-based scanline algorithms [S1]. The method evolved with GPU hardware, leveraging fragment shaders and later compute shaders for parallel processing [S2, S5, unofficial]. Libraries like Point-Cloud-Utils and the C-based voxelizer library popularized simple, header-only implementations for game development and voxel art [S1][S2, unofficial]. It is widely used in voxel art tools, real-time ray tracing preprocessing, and volume rendering pipelines [S1][S4, S5, unofficial].
