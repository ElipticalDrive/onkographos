# Rasterization-based Voxelization

Also called: Cube Mesh Generation, Hash-based Surface Voxelization, Sparse Voxelization with PositionMap Hashing, Voxelizing a Triangle Mesh, madcad Voxelization

## Overview
Rasterization-based Voxelization converts a continuous triangle mesh into a discrete volumetric representation by projecting the geometry onto a 3D grid using rasterization principles [S1][S4, S5, unofficial]. It solves the problem of generating a voxelized mesh (either a sparse occupancy grid or an explicit mesh of cubes) from polygonal input without performing complex surface reconstruction [S1][S2, unofficial]. It differs from [Voxel Carving](1213-voxel-carving.md) and [Voxel Occupancy Test](1281-voxel-occupancy-test.md) by actively rasterizing triangle surfaces to determine occupancy rather than ray-casting or boolean operations, and from [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md) by operating on explicit triangle primitives [S1][S5, unofficial].

## How it works
**Inputs:**
- Input mesh: Vertices $V$ and Faces $F$ (triangles) [S1][S4, unofficial].
- Voxel size: $vs = (vs_x, vs_y, vs_z)$ [S4, unofficial].
- Voxel origin: $vox\_origin = (o_x, o_y, o_z)$, the world coordinate of the $(0,0,0)$ voxel corner [S1].
- Precision: $p$ (float), a tolerance factor to reduce artifacts [S2, S4, unofficial].
- Optional: Gap fraction $g$ for cube spacing [S1].

**Outputs:**
- Option A: A sparse set of occupied voxel integer coordinates $(i, j, k)$ [S1][S3, unofficial].
- Option B: A voxelized mesh structure containing vertices, normals, colors, and indices representing cubes at occupied locations [S4, unofficial].
- Option C: A point cloud of voxel centers [S4, unofficial].

**Data Structures:**
1.  **Hash Table / Set:** Stores occupied voxel keys. In Python, a `set` of tuples $(i,j,k)$ [S3, unofficial]. In C, a hash table with buckets, linked lists, and nodes containing `voxeldata` (position, color) [S4, unofficial].
2.  **Voxel Mesh Structure (`vx_mesh_t`):**
    -   `vertices`: Array of size $N_{voxels} \times 8$ [S4, unofficial].
    -   `normals`: Array of size 6 (predefined cube normals) [S4, unofficial].
    -   `colors`: Array of size $N_{voxels} \times 8$ (optional) [S4, unofficial].
    -   `indices`: Array of size $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$ [S4, unofficial].
    -   `normalindices`: Array of size $N_{voxels} \times VOXELIZER\_INDICES\_SIZE$ [S4, unofficial].
    -   `nvertices`, `nindices`: Counts [S4, unofficial].

**Steps:**

1.  **Initialization:**
    Compute half-voxel size $hvs = vs \times 0.5$ [S4, unofficial].
    Initialize the hash table or set [S3, S4, unofficial].

2.  **Rasterization (Triangle Iteration):**
    For each triangle face $f$ in the mesh:
    a.  Determine the bounding box of the triangle in world space.
    b.  Map the bounding box to voxel grid indices.
    c.  Rasterize the triangle into the grid. This involves iterating over the 2D projection (or 3D span) and determining which voxel cells intersect the triangle [S1][S3, S4, unofficial].
    d.  For each intersected voxel, compute its center or key.
    e.  Insert the voxel key into the hash table/set. If using the C library, store position and interpolated color in the node [S4, unofficial].

    *Note on Rasterization Logic:* The core rasterization step `vx__voxelize` or `hasher.keysfor` handles the geometric intersection. It typically iterates over the triangle's bounding box in voxel space and tests for overlap, often using a precision parameter $p$ to ensure robust coverage [S4, unofficial].

3.  **Geometry Generation (Optional):**
    If a voxel mesh is required:
    a.  Allocate output arrays based on the number of unique voxels $N_{voxels}$ [S4, unofficial].
    b.  Define the 8 corner offsets for a cube centered at $(0,0,0)$ with size $vs$:
        $$
        \text{offsets} = \{
        (-hvs_x, hvs_y, hvs_z), (-hvs_x, -hvs_y, hvs_z), (hvs_x, -hvs_y, hvs_z), (hvs_x, hvs_y, hvs_z), \\
        (-hvs_x, hvs_y, -hvs_z), (-hvs_x, -hvs_y, -hvs_z), (hvs_x, -hvs_y, -hvs_z), (hvs_x, hvs_y, -hvs_z)
        \}
        $$
    c.  Iterate through the hash table. For each occupied voxel at position $P$:
        i.  Compute world coordinates of the 8 corners: $C_k = P + \text{offsets}_k$.
        ii. Add these vertices to the output mesh.
        iii. Add indices to form the 12 triangles (or 36 vertices) of the cube.
        iv. Assign normals (from predefined set) and colors (interpolated from triangle or stored in hash) [S4, unofficial].

4.  **Finalization:**
    Free temporary hash tables [S4, unofficial].
    Return the voxel mesh or point cloud [S4, unofficial].

**Pseudocode (Python-like, combining sparse set and mesh generation logic):**

```python
def rasterization_voxelization(vertices, faces, voxel_size, origin, precision=0.01, gap_fraction=0.02):
    """
    vertices: list of [x, y, z]
    faces: list of [i, j, k] indices into vertices
    voxel_size: float or tuple (sx, sy, sz)
    origin: tuple (ox, oy, oz)
    """
    # 1. Setup
    if isinstance(voxel_size, float):
        vs = (voxel_size, voxel_size, voxel_size)
    else:
        vs = voxel_size
    
    hvs = (vs[0]*0.5, vs[1]*0.5, vs[2]*0.5)
    
    # Sparse set for occupied voxels
    occupied_voxels = set()
    
    # 2. Rasterize Triangles
    for face in faces:
        # Get triangle vertices
        v0 = vertices[face[0]]
        v1 = vertices[face[1]]
        v2 = vertices[face[2]]
        
        # Compute bounding box in world space
        min_x = min(v0[0], v1[0], v2[0])
        max_x = max(v0[0], v1[0], v2[0])
        min_y = min(v0[1], v1[1], v2[1])
        max_y = max(v0[1], v1[1], v2[1])
        min_z = min(v0[2], v1[2], v2[2])
        max_z = max(v0[2], v1[2], v2[2])
        
        # Map to voxel indices
        min_ix = floor((min_x - origin[0]) / vs[0])
        max_ix = floor((max_x - origin[0]) / vs[0])
        min_iy = floor((min_y - origin[1]) / vs[1])
        max_iy = floor((max_y - origin[1]) / vs[1])
        min_iz = floor((min_z - origin[2]) / vs[2])
        max_iz = floor((max_z - origin[2]) / vs[2])
        
        # Iterate over bounding box voxels
        for ix in range(min_ix, max_ix + 1):
            for iy in range(min_iy, max_iy + 1):
                for iz in range(min_iz, max_iz + 1):
                    # Check if voxel center is inside triangle or if voxel intersects triangle
                    # This is the core rasterization step. 
                    # Simplified: Check if voxel center is within triangle bounds or use robust intersection test.
                    # The 'precision' parameter affects this test tolerance.
                    voxel_center_world = (
                        origin[0] + (ix + 0.5) * vs[0],
                        origin[1] + (iy + 0.5) * vs[1],
                        origin[2] + (iz + 0.5) * vs[2]
                    )
                    
                    if point_in_triangle(voxel_center_world, v0, v1, v2, precision):
                        occupied_voxels.add((ix, iy, iz))
                        
    # 3. Generate Output (Cube Mesh)
    cube_vertices = []
    cube_indices = []
    normal_indices = []
    
    # Predefined cube corner offsets relative to center
    offsets = [
        (-hvs[0], hvs[1], hvs[2]), (-hvs[0], -hvs[1], hvs[2]), (hvs[0], -hvs[1], hvs[2]), (hvs[0], hvs[1], hvs[2]),
        (-hvs[0], hvs[1], -hvs[2]), (-hvs[0], -hvs[1], -hvs[2]), (hvs[0], -hvs[1], -hvs[2]), (hvs[0], hvs[1], -hvs[2])
    ]
    
    # Cube topology (12 triangles, 36 indices)
    # Standard cube face indices: 0,1,2, 0,2,3 (front), etc.
    # For simplicity, assuming a standard cube generation pattern
    cube_face_indices = [
        0, 1, 2, 0, 2, 3,  # Front
        4, 6, 5, 4, 7, 6,  # Back
        4, 5, 1, 4, 1, 0,  # Left
        2, 6, 7, 2, 7, 3,  # Right
        3, 7, 6, 3, 6, 2,  # Top
        4, 0, 1, 4, 1, 5   # Bottom
    ]
    
    base_vertex_idx = 0
    for (ix, iy, iz) in occupied_voxels:
        # Calculate world center of this voxel
        center = (
            origin[0] + (ix + 0.5) * vs[0],
            origin[1] + (iy + 0.5) * vs[1],
            origin[2] + (iz + 0.5) * vs[2]
        )
        
        # Add 8 vertices
        for ox, oy, oz in offsets:
            cube_vertices.append((center[0] + ox, center[1] + oy, center[2] + oz))
            
        # Add indices
        for idx in cube_face_indices:
            cube_indices.append(base_vertex_idx + idx)
            normal_indices.append(0) # Placeholder for normal index
            
        base_vertex_idx += 8
        
    return occupied_voxels, cube_vertices, cube_indices

def point_in_triangle(p, v0, v1, v2, precision):
    """
    Simple barycentric coordinate check. 
    In practice, robust geometric intersection tests are used [S4, unofficial].
    """
    # Vector functions
    v0v1 = (v1[0]-v0[0], v1[1]-v0[1], v1[2]-v0[2])
    v0v2 = (v2[0]-v0[0], v2[1]-v0[1], v2[2]-v0[2])
    v0p = (p[0]-v0[0], p[1]-v0[1], p[2]-v0[2])
    
    dot00 = v0v1[0]*v0v1[0] + v0v1[1]*v0v1[1] + v0v1[2]*v0v1[2]
    dot01 = v0v1[0]*v0v2[0] + v0v1[1]*v0v2[1] + v0v1[2]*v0v2[2]
    dot02 = v0v1[0]*v0p[0] + v0v1[1]*v0p[1] + v0v1[2]*v0p[2]
    dot11 = v0v2[0]*v0v2[0] + v0v2[1]*v0v2[1] + v0v2[2]*v0v2[2]
    dot12 = v0v2[0]*v0p[0] + v0v2[1]*v0p[1] + v0v2[2]*v0p[2]
    
    inv_denom = 1 / (dot00 * dot11 - dot01 * dot01)
    u = (dot11 * dot02 - dot01 * dot12) * inv_denom
    v = (dot00 * dot12 - dot01 * dot02) * inv_denom
    
    # Check with precision tolerance
    return (u >= -precision) and (v >= -precision) and (u + v <= 1 + precision)
```

## Subtopics

### [3D Grid Rasterization](903-3d-grid-rasterization.md)
A CPU-based algorithm that determines which voxels in a fixed-resolution 3D grid are intersected by a triangle mesh, producing a binary occupancy grid. It differs from full o-voxel implementations by omitting face QEF and dual vertex solve steps, focusing solely on intersect scanlines.

### [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md)
Accelerates voxelization by parallelizing the iteration over the 2D XY plane of the voxel grid using a GPU compute shader. It retains explicit triangle-voxel intersection logic but distributes it across GPU threads, achieving significant speedups for high-resolution grids.

### [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md)
Converts meshes to voxel grids using GPU parallel processing, decoupling intersection logic from rasterization to allow custom geometric tests and atomic operations on 3D buffers.

### [GPU Voxelization](2633-gpu-voxelization.md)
Uses the GPU's hardware rasterization pipeline to map fragments directly to 3D grid cells, differing from CPU methods by parallelizing intersection tests across the rasterizer.

### [Mesh-to-Voxel Geometry Shader](2800-mesh-to-voxel-geometry-shader.md)
A real-time DirectX technique that iterates over integer grid positions within a triangle's bounding box and emits explicit cube geometry for intersecting cells, resulting in higher vertex counts than rasterization-based filling.

### [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md)
Converts meshes to 3D grids by iterating over triangle bounding boxes and testing voxel centers against plane/edge constraints, outputting binary occupancy grids rather than cube meshes.

### [Voxel Rasterization](3204-voxel-rasterization.md)
Focuses on the specific steps of iterating over triangle surfaces, interpolating attributes, and writing to voxel buffers, often leveraging GPU acceleration.

### [Conservative Voxelization](3247-conservative-voxelization.md)
A hardware-accelerated algorithm guaranteeing that every intersecting voxel is recognized by computing exact depth ranges, avoiding missed voxels from single-depth rasterization.

### [Conservative Rasterization via Triangle Expansion](3531-conservative-rasterization-via-triangle-expansion.md)
Eliminates holes by expanding triangles in clip space and culling in the fragment shader, implementing expansion manually in geometry shaders using homogeneous plane mathematics.

### [Multi-view projection](5937-multi-view-projection.md)
Rasterizes geometry from multiple camera viewpoints to solve coverage gaps inherent in single-view projection, ensuring comprehensive coverage through redundancy.

### [Parametric Surface Voxelization](6032-parametric-surface-voxelization.md)
Converts parametric surfaces (subdivision/implicit) into voxel grids by rasterizing points in the 2D parameter domain, avoiding mesh tessellation.

### [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md)
Projects 3D data into 2D image space (textures) before reconstructing the 3D volume, leveraging GPU rasterization or image load/store on 2D textures [G].

#### Rasterization-based Volume Modeling
The process of building volume data voxel-by-voxel, considered the third layer in the voxel modeling abstraction hierarchy [S5, unofficial]. It involves instancing the primitive, bounding it to find overlapping voxels, and sampling its density function at each voxel [S5, unofficial]. It pulls values into a voxel (similar to raytracing), whereas instantiation-based modeling pushes values into voxels [S5, unofficial].

#### Single-Pass Voxelization
Utilizes the geometry shader to reduce draw calls by selecting the axis of largest triangle projection for fragment generation [S6, unofficial]. It employs conservative rasterization to generate fragments for any pixel with content inside, not just centers, and uses MSAA render targets to prevent incorrectly filling empty cells [S6, unofficial]. Hardware support for conservative rasterization is available on Nvidia Maxwell and later [S6, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of triangles $N_t$ and the number of voxels $N_v$ in the bounding box. For sparse hashing, it is proportional to the number of intersected voxels. For dense grids, it can be $O(N_t \cdot N_v)$ in worst-case bounding box traversal, but optimized rasterization reduces this to $O(N_t \cdot A)$ where $A$ is the projected area in voxels [S1][S4, unofficial].
- **Memory Complexity:** $O(N_v)$ for the hash table or occupancy grid [S3, S4, unofficial]. Sparse structures are more memory-efficient for sparse meshes [S3, unofficial].
- **Performance:** GPU-based variants achieve significant speedups (e.g., 50x) over CPU implementations for high-resolution grids [S1]. CPU implementations are simpler but slower [S1][S3, unofficial].
- **Strengths:** Fast, leverages existing graphics hardware (GPU) or simple CPU logic; generates explicit voxel meshes suitable for further processing [S1][S4, unofficial].
- **Limitations:** Output mesh vertex/face count scales with voxel density, impacting rendering performance if not managed [S2, unofficial]. Conservative rasterization can overfill empty cells if not handled with MSAA or collision checks [S6, unofficial].
- **When to use:** When an explicit voxel mesh is needed for further geometric processing or when real-time performance is required via GPU acceleration [S1][S4, unofficial].
- **When not to use:** When deep interior voxelization is required (this method is typically shell/surface only) [S2, unofficial].

## Background
Originating from the need to convert polygonal models into volumetric data for rendering and simulation, this method leverages the efficiency of rasterization pipelines [S1][S5, unofficial]. The Point-Cloud-Utils library popularized a Python-accessible implementation [S1]. The C library `voxelizer` by Karim Naaji provides a header-only solution for shell voxelization [S2, S4, unofficial]. The concept of rasterization-based volume modeling as a distinct layer in volume rendering pipelines was formalized in production volume rendering literature [S5, unofficial].
