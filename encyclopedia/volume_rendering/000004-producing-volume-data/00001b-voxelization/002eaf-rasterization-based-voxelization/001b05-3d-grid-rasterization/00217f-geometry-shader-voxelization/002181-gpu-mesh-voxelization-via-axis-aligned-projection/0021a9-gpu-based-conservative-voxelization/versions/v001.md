# GPU-based Conservative Voxelization

Also called: voxelize::operator()

## Overview
A two-pass GPU algorithm that converts 3D triangle meshes into a list of voxels using conservative rasterization, followed by an octree construction step [S1, unofficial]. It differs from standard rasterization-based voxelization by explicitly counting occupied voxels in a first pass to enable exact buffer allocation, ensuring no memory is wasted on empty space or overflowed during storage [S1, unofficial].

## How it works
**Inputs:** A triangle mesh (vertices, normals, UVs, indices) and voxelization parameters (target resolution on Y-axis, bounding box position and size).
**Outputs:** A dynamic list of occupied voxels (typically stored in a structured buffer or atomic counter result) ready for octree construction.

**Data Structures:**
*   **Scene Normalization Matrix:** A $4 \times 4$ matrix mapping the model's bounding box to the unit cube $(0,0,0)$ to $(1,1,1)$.
*   **Projection Matrices:** Three orthogonal projection matrices ($X, Y, Z$) for axis-aligned projection.
*   **Atomic Counter:** A GPU buffer bound to binding point 3, used to count occupied voxels.
*   **Voxel List Buffer:** A storage buffer bound to binding points 1 and 2, storing the final voxel coordinates.
*   **Uniforms:**
    *   `u_transform`: Scene normalization matrix.
    *   `u_x_ortho_projection`, `u_y_ortho_projection`, `u_z_ortho_projection`: Orthographic projection matrices.
    *   `u_grid`: Grid dimensions (width, height, depth).
    *   `u_can_store`: Boolean flag (0 for count pass, 1 for store pass).

**Steps:**

1.  **Disable Rasterization Filters:**
    Disable depth testing, alpha testing, and face culling to ensure all fragments generated by conservative rasterization are processed regardless of depth or transparency [S1, unofficial].
    ```cpp
    glDisable(GL_DEPTH_TEST);
    glDisable(GL_ALPHA_TEST);
    glDisable(GL_CULL_FACE);
    ```

2.  **Prepare Matrices:**
    *   Calculate the scene normalization matrix using the mesh's bounding box position and size: `create_scene_normalization_matrix(area_position, area_size)` [S1, unofficial]. Upload to `u_transform`.
    *   Calculate three orthogonal projection matrices for the X, Y, and Z axes using `create_projection_matrices(proj)` [S1, unofficial]. Upload to `u_x_ortho_projection`, `u_y_ortho_projection`, and `u_z_ortho_projection`.

3.  **Determine Grid Dimensions:**
    *   Calculate proportional grid dimensions based on the bounding box size (`area_size`) and a target resolution on the Y-axis (`voxels_on_y`) using `calc_proportional_grid` [S1, unofficial].
    *   Determine `max_side` as the maximum dimension among width, height, and depth.
    *   Set the viewport size to `max_side x max_side` [S1, unofficial].
    *   Set the grid dimensions uniform `u_grid` and create a framebuffer with default width/height set to `max_side` [S1, unofficial].

4.  **Pass 1: Count Voxels:**
    *   Set uniform `u_can_store` to 0.
    *   Reset the atomic counter buffer to 0.
    *   Bind the atomic counter to binding point 3.
    *   Invoke the shader program to render the mesh. The shader uses conservative rasterization to determine which voxels are intersected by the projected triangles and increments the atomic counter for each unique voxel [S1, unofficial].

5.  **Pass 2: Store Voxels:**
    *   Set uniform `u_can_store` to 1.
    *   Reset the atomic counter buffer to 0.
    *   Bind the atomic counter to binding point 3.
    *   Bind the voxel list buffer to binding points 1 and 2.
    *   Invoke the shader program to render the mesh. The shader uses conservative rasterization to determine intersected voxels and writes their coordinates into the voxel list buffer using atomic operations [S1, unofficial].

6.  **Synchronize:**
    Execute `glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT)` to ensure storage buffer writes are visible to subsequent reads or CPU access [S1, unofficial].

**Pseudocode:**
```python
def gpu_conservative_voxelization(mesh, voxels_on_y, area_position, area_size):
    # 1. Disable filters
    glDisable(GL_DEPTH_TEST)
    glDisable(GL_ALPHA_TEST)
    glDisable(GL_CULL_FACE)

    # 2. Prepare matrices
    transform = create_scene_normalization_matrix(area_position, area_size)
    proj_matrices = create_projection_matrices() # Returns X, Y, Z ortho matrices
    
    # 3. Determine grid
    grid_dims = calc_proportional_grid(area_size, voxels_on_y)
    max_side = max(grid_dims.width, grid_dims.height, grid_dims.depth)
    set_viewport(max_side, max_side)
    set_uniform_u_grid(grid_dims)
    create_framebuffer(max_side, max_side)

    # 4. Pass 1: Count
    set_uniform_u_can_store(0)
    reset_atomic_counter()
    bind_atomic_counter(binding_point=3)
    bind_mesh_to_shader(mesh)
    draw_elements(mesh)

    # 5. Pass 2: Store
    set_uniform_u_can_store(1)
    reset_atomic_counter()
    bind_atomic_counter(binding_point=3)
    bind_voxel_list_buffer(binding_points=[1, 2])
    bind_mesh_to_shader(mesh)
    draw_elements(mesh)

    # 6. Synchronize
    glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT)
```

## Subtopics
## Operating characteristics
*   **Time Complexity:** Two full rasterization passes over the mesh. Conservative rasterization is generally more expensive than standard rasterization due to fragment generation overhead.
*   **Memory Complexity:** $O(V)$ where $V$ is the number of occupied voxels. The atomic counter approach ensures exact allocation, avoiding over-allocation.
*   **Strengths:** Exact memory usage for the voxel list; handles complex meshes without manual culling; leverages GPU parallelism for conservative rasterization.
*   **Limitations:** Requires two passes; conservative rasterization performance varies by GPU driver/hardware; not given in the sources for specific resolution benchmarks.
*   **When to use:** When exact voxel count is critical for memory management or when integrating with an octree construction step that requires a flat list of voxels [S1, unofficial].
*   **When not to use:** When memory is not a constraint and a simpler, single-pass rasterization into a 3D texture is sufficient.

## Background
Originated in the `loryruta/voxelizer` project, an unofficial implementation of GPU-based voxelization [S1, unofficial]. It builds on [GPU Mesh Voxelization via Axis-Aligned Projection](2561-gpu-mesh-voxelization-via-axis-aligned-projection.md) by adding a counting pass and conservative rasterization to produce a precise list of voxels.
