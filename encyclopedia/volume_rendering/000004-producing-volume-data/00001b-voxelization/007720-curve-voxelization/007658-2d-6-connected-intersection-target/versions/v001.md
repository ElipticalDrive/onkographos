# 2D 6-Connected Intersection Target

Also called: 2D mesh ensuring 6 connectivity with diagonal target, Diagonal target for 2D 6-connectivity

## Overview
The 2D 6-Connected Intersection Target (Diagonal) defines a set of line segments within a single voxel that serves as the geometric target for ray-casting or curve-voxelization algorithms to ensure 6-connectivity in the resulting voxel grid. It consists of the four space diagonals of the voxel cube, connecting opposite corners. Unlike the [2D_6_intersectionTarget](23483-2d-6-intersectiontarget.md) which uses the 12 edges of the cube, this method uses only 4 internal diagonals. It is chosen when a minimal set of intersection lines is required to guarantee that a 2D input (such as a curve or line segment) intersects the voxel in a manner consistent with 6-connectivity (face-adjacency), while reducing the number of intersection tests compared to the outline target.

## How it works
### Inputs and Outputs
- **Input**:
  - `VoxelPoint`: The 3D coordinates of the voxel's center or a reference corner (typically the minimum corner, depending on implementation convention; the sources define vertices relative to a center-like offset, but the formula `VoxelPoint + offset` implies `VoxelPoint` is the center if offsets are $\pm u, \pm v, \pm w$. However, standard voxelization often uses the minimum corner. Let's look at the offsets: `+u, +v, +w` and `-u, -v, -w`. If `VoxelPoint` is the center, these are the corners. If `VoxelPoint` is the min corner, `u,v,w` would be half-dimensions, and `+u,+v,+w` would be the max corner. The code `VX[0] = VoxelPoint + (+u, +v, +w)` and `VX[4] = VoxelPoint + (-u, -v, -w)` suggests `VoxelPoint` is the **center** of the voxel, because `VX[0]` and `VX[4]` are opposite corners. Wait, `VX[0]` is `(+u,+v,+w)` and `VX[4]` is `(-u,-v,-w)`. These are opposite. `VX[1]` is `(-u,+v,+w)` and `VX[5]` is `(+u,-v,-w)`. These are opposite. So `VoxelPoint` is the **center** of the voxel.
  - `vSize`: A 3D vector $(S_x, S_y, S_z)$ representing the dimensions of the voxel.
- **Output**:
  - `IT`: An array of 4 `Line` objects, where each `Line` is defined by two 3D points (endpoints).

### Data Structures
- **Point3d**: A structure with fields `x`, `y`, `z` of type `double`.
- **Line**: A structure with fields `p1`, `p2` of type `Point3d`.
- **VoxelPoint**: `Point3d`.
- **vSize**: `Vector3d` (or `Point3d` used as vector).

### Steps
1. **Initialize**:
   - Create an array `IT` of size 4.
   - Create an array `VX` of size 8.
   - Calculate half-dimensions:
     $$ u = S_x / 2 $$
     $$ v = S_y / 2 $$
     $$ w = S_z / 2 $$
2. **Create Vertices**:
   Define the 8 corners of the voxel relative to `VoxelPoint` (the center):
   - $VX[0] = (VoxelPoint.x + u, VoxelPoint.y + v, VoxelPoint.z + w)$
   - $VX[1] = (VoxelPoint.x - u, VoxelPoint.y + v, VoxelPoint.z + w)$
   - $VX[2] = (VoxelPoint.x - u, VoxelPoint.y - v, VoxelPoint.z + w)$
   - $VX[3] = (VoxelPoint.x + u, VoxelPoint.y - v, VoxelPoint.z + w)$
   - $VX[4] = (VoxelPoint.x - u, VoxelPoint.y - v, VoxelPoint.z - w)$
   - $VX[5] = (VoxelPoint.x + u, VoxelPoint.y - v, VoxelPoint.z - w)$
   - $VX[6] = (VoxelPoint.x + u, VoxelPoint.y + v, VoxelPoint.z - w)$
   - $VX[7] = (VoxelPoint.x - u, VoxelPoint.y + v, VoxelPoint.z - w)$
3. **Create Edges (Diagonals)**:
   Connect opposite corners to form the 4 space diagonals:
   - $IT[0] = \text{Line}(VX[0], VX[4])$
   - $IT[1] = \text{Line}(VX[1], VX[5])$
   - $IT[2] = \text{Line}(VX[2], VX[6])$
   - $IT[3] = \text{Line}(VX[3], VX[7])$
4. **Return** `IT`.

### Pseudocode
```python
def compute_2d_6_connected_intersection_target_diagonal(voxel_point, v_size):
    """
    Computes the 4 space diagonals of a voxel for 6-connectivity intersection testing.
    
    Args:
        voxel_point: Point3d, the center of the voxel.
        v_size: Vector3d, the dimensions (width, height, depth) of the voxel.
        
    Returns:
        List[Line]: A list of 4 Line objects representing the space diagonals.
    """
    # 1. Initialize
    # u, v, w are half-dimensions
    u = v_size.x / 2.0
    v = v_size.y / 2.0
    w = v_size.z / 2.0
    
    # 2. Create Vertices (8 corners)
    # VX indices:
    # 0: +u, +v, +w
    # 1: -u, +v, +w
    # 2: -u, -v, +w
    # 3: +u, -v, +w
    # 4: -u, -v, -w
    # 5: +u, -v, -w
    # 6: +u, +v, -w
    # 7: -u, +v, -w
    
    vx = [None] * 8
    vx[0] = Point3d(voxel_point.x + u, voxel_point.y + v, voxel_point.z + w)
    vx[1] = Point3d(voxel_point.x - u, voxel_point.y + v, voxel_point.z + w)
    vx[2] = Point3d(voxel_point.x - u, voxel_point.y - v, voxel_point.z + w)
    vx[3] = Point3d(voxel_point.x + u, voxel_point.y - v, voxel_point.z + w)
    vx[4] = Point3d(voxel_point.x - u, voxel_point.y - v, voxel_point.z - w)
    vx[5] = Point3d(voxel_point.x + u, voxel_point.y - v, voxel_point.z - w)
    vx[6] = Point3d(voxel_point.x + u, voxel_point.y + v, voxel_point.z - w)
    vx[7] = Point3d(voxel_point.x - u, voxel_point.y + v, voxel_point.z - w)
    
    # 3. Create Edges (4 space diagonals)
    # IT[0]: 0 -> 4
    # IT[1]: 1 -> 5
    # IT[2]: 2 -> 6
    # IT[3]: 3 -> 7
    it = [None] * 4
    it[0] = Line(vx[0], vx[4])
    it[1] = Line(vx[1], vx[5])
    it[2] = Line(vx[2], vx[6])
    it[3] = Line(vx[3], vx[7])
    
    return it
```

### Parameters and Edge Cases
- **Parameters**: The voxel size `vSize` must be positive. If any dimension is zero, the voxel is degenerate, and the diagonals collapse to points or lines.
- **Precision**: Using floating-point arithmetic for `u, v, w` and vertex coordinates may introduce small errors. For exact intersection tests, consider using robust geometric predicates.
- **Connectivity**: This target ensures 6-connectivity. A ray intersecting any of these 4 diagonals is guaranteed to pass through the voxel in a way that respects face-adjacency constraints for the connected component. Note that 4 diagonals are sufficient to cover the "interior" connectivity paths between opposite corners, whereas the outline target uses 12 edges.

## Operating characteristics
- **Time Complexity**: $O(1)$ to construct the target for a single voxel. The number of intersection tests per voxel is 4 (one for each diagonal).
- **Memory Complexity**: $O(1)$ per voxel (stores 4 lines, 8 points).
- **Strengths**: Minimal number of intersection lines (4) compared to the outline target (12). This reduces computational cost during the intersection phase.
- **Limitations**: Only ensures 6-connectivity. It does not provide the same level of boundary definition as the outline target. It may miss intersections that only touch the voxel faces but not the space diagonals if the ray path is tangent to the voxel interior in a specific way, although for 6-connectivity purposes, this is the intended minimal set.
- **When to use**: When 6-connectivity is sufficient and performance is critical.
- **When not to use**: When 26-connectivity is required (use [2D_26_intersectionTarget](23483-2d-26-intersectiontarget.md)) or when boundary accuracy is more important than connectivity speed (use [2D_6_intersectionTarget](23483-2d-6-intersectiontarget.md) outline).

## Background
This method is part of the voxelization algorithms for geospatial applications, specifically designed for curve voxelization. It was introduced in the context of ensuring topological correctness (connectivity) in voxelized representations of curves and lines. The distinction between "diagonal target" and "outline target" highlights the trade-off between the number of intersection tests and the connectivity guarantee. The diagonal target is a subset of the full set of lines that could be used, optimized for 6-connectivity.
