# 3D Scan-conversion
Also called: Polygon-to-voxel conversion, Voxelization with geometric primitives

## Overview
3D scan-conversion is a rendering method that converts geometric primitives (polygons) into a volumetric dataset, combines them with existing volumetric data using volume matting operators, and renders the resulting composite ensemble using standard volume rendering techniques [S1, unofficial]. It sets itself apart from hybrid ray tracing by pre-filtering and sampling geometry into the voxel grid, allowing the use of standard ray-casting for the final image while avoiding aliasing artifacts through analytic anti-aliasing [S1, unofficial].

## How it works
**Inputs:**
1. A volumetric dataset (scalar field) defined on an $N \times N \times N$ voxel array [S1, unofficial].
2. A set of embedded geometric primitives (polygons) [S1, unofficial].

**Outputs:**
1. A final rendered image [S1, unofficial].
2. An intermediate composite volumetric dataset containing color and opacity for every voxel [S1, unofficial].

**Data Structures:**
*   **Volumetric Buffer:** An $N \times N \times N$ array storing scalar values [S1, unofficial].
*   **Color/Opacity Buffers:** Arrays storing the color $c_v$ and opacity $o_v$ for the volumetric data, and $c_p, o_p$ for the polygons [S1, unofficial].
*   **Light Strength Buffer:** A 3D buffer storing fractional light strength for shadow calculations (optional) [S1, unofficial].

**Steps:**
1.  **Classify Volumetric Data:** Shade and classify the volumetric data to yield a color $c_v$ and opacity $o_v$ for each voxel [S1, unofficial].
2.  **Shade and Filter Polygons:** For each polygon: shade it (homogeneous color per source), apply a 3D edge filtering algorithm to bandlimit the data, and sample it at the volumetric resolution to yield a color $c_p$ and opacity $o_p$ for each affected voxel [S1, unofficial].
3.  **Combine (Volume Matting):** Combine the volumetric color/opacity ($c_v, o_v$) and polygon color/opacity ($c_p, o_p$) using volume matting operators to yield a composite color $c_c$ and opacity $o_c$ for each voxel [S1, unofficial].
4.  **Render Composite:** Ray trace, resample, and composite the composite dataset ($c_c, o_c$) without further consideration of the geometric data [S1, unofficial].
5.  **Shadow Calculation (Optional):** If shadows are required, use a two-pass approach storing shadow information in a 3D light strength buffer instead of a 2D shadow depth buffer, computing fractional light strength at every point in space [S1, unofficial].

**Formulas:**
*   Volume matting (over operator): $o_c' = o_c + o_p(1 - o_c)$
*   Composite color: $c_c' = \frac{c_c o_c + c_p o_p (1 - o_c)}{o_c'}$ (when $o_c' > 0$) [S1, unofficial].

**Parameters:**
*   **Filter:** 3D version of the edge filtering algorithm by Feibush et al. [1980] [S1, unofficial].
*   **Convolution Kernel:** Constant weight ball, 2 voxels in diameter [S1, unofficial].
*   **Sampling Rate:** One ray per pixel is usually sufficient to prevent aliasing artifacts [S1, unofficial].

**Pitfalls:**
*   **Matting Order:** Matting is not commutative. The order in which polygons are scan-converted affects the appearance of polygon-polygon intersections [S1, unofficial].
*   **Volumetric Interaction:** Polygons may be matted over or under volumetric data, affecting appearance [S1, unofficial].
*   **Aliasing:** If polygonal data is not sufficiently bandlimited prior to sampling, aliasing artifacts will appear [S1, unofficial].

## Subtopics

### [Hybrid Ray Tracer vs 3D Scan-Conversion](2036-hybrid-ray-tracer-vs-3d-scan-conversion.md)
This family compares two distinct approaches for rendering mixtures of geometric primitives and volumetric data: hybrid ray tracing and 3D scan-conversion. Both methods are reasonably efficient and produce aliasing-free images, but they differ significantly in computational cost, image quality characteristics, and versatility. The choice between them depends on whether the application prioritizes the physical accuracy of ray-traced lighting and shadows or the structural clarity provided by scan-converted geometric backdrops.

### Cylindrical Rasterization
A rasterization technique that converts geometric primitives (lines and triangles) from standard 3-D data into a cylindrical voxel grid coordinate system, specifically designed for a volumetric display with a rotating screen [S2]. The raster engine, in conjunction with the host PC, scan-converts typical 3-D data into the device coordinate system, storing rasterized data in graphics memory (e.g., 3 Gbits DDR SDRAM) [S2]. Traditional Cartesian scan-conversion algorithms do not apply because the display uses a cylindrical coordinate system, requiring proprietary efficient rasterization algorithms [S2].

## Operating characteristics
*   **Time Complexity:** Not explicitly given. Requires shading, filtering, and sampling each polygon into the volume grid, followed by standard volume ray casting [S1, unofficial].
*   **Memory Complexity:** Requires storage for the volumetric data, color/opacity buffers for the volume and polygons, and potentially a 3D light strength buffer for shadows [S1, unofficial]. The 3D buffer is noted to require significantly more memory than a 2D shadow depth buffer [S1, unofficial].
*   **Performance:** Designed to be efficient. The pre-filtering of polygons allows for standard sampling rates (one ray per pixel) without aliasing [S1, unofficial].
*   **Strengths:** Produces images free from aliasing artifacts; allows use of standard volume rendering techniques for the final composite; convenient for adding shadows via 3D light strength buffers [S1, unofficial].
*   **Limitations:** Matting is non-commutative, requiring careful ordering of polygons; high memory usage for 3D shadow buffers; continuous shading is noted as under investigation, implying potential limitations with current implementations [S1, unofficial].
*   **When to Use:** When structural clarity of geometric backdrops is prioritized over physical accuracy of lighting; when aliasing-free rendering of mixed data is required without the cost of full hybrid ray tracing [S1, unofficial].
*   **When Not to Use:** When physical accuracy of ray-traced lighting and shadows is the primary goal (use Hybrid Ray Tracer instead); when memory is severely constrained (due to 3D buffers) [S1, unofficial].

## Background
Originating from research in medical imaging and molecular graphics, this method was presented in a study comparing hybrid ray tracing and 3D scan-conversion for rendering mixtures of geometric and volumetric data [S1, unofficial]. It builds on volume matting operators [Drebin et al., 1988] and edge filtering algorithms [Feibush et al., 1980] [S1, unofficial]. The method was developed to provide an efficient alternative to hybrid ray tracing while maintaining high image quality and avoiding aliasing artifacts [S1, unofficial].
