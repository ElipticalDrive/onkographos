# GPU Mesh Voxelization via Axis-Aligned Projection

Also called: Axis-Aligned Projection, Axis-aligned voxelization, CustomVoxelizer, DefaultEffect, Dominant Axis Projection, Dominant Axis Voxelization, GPU-based Voxelization (Axis-Aligned), Hardware rasterizer voxelization, Primitive Reprojection, Voxelization using the GPU hardware rasterizer, Voxelization with Dominant Axis Projection

## Overview
GPU Mesh Voxelization via Axis-Aligned Projection is a rasterization-based technique that converts polygonal triangle meshes into a 3D voxel grid by projecting each triangle onto a 2D plane aligned with its dominant normal axis [S1, S4]. It solves the problem of efficiently filling a 3D occupancy or color grid using standard GPU hardware rasterizers, which are optimized for 2D screens [S4]. Unlike [Geometry Shader Voxelization](2566-geometry-shader-voxelization.md) which may use generic 3D rasterization logic, this method explicitly selects the optimal projection axis per triangle to maximize fragment coverage and minimize holes [S3]. It differs from [GPU Mesh Voxelization via AABB-Triangle Intersection](2541-gpu-mesh-voxelization-via-aabb-triangle-intersection.md) by relying on hardware rasterization rather than analytical intersection tests, and from [GPU Voxelization Using OpenGL Image Atomics](2544-gpu-voxelization-using-opengl-image-atomics.md) by typically using a single draw call with axis-specific view matrices rather than multiple passes or pure atomic accumulation without depth-based projection [S4].

## How it works
**Inputs and Outputs:**
*   **Input:** Triangle mesh (vertices, indices), voxel grid dimensions ($W \times H \times D$), world-to-voxel transformation parameters.
*   **Output:** 3D voxel grid (either `RWTexture3D` or `RWStructuredBuffer`) containing occupancy flags, positions, and colors.

**Data Structures:**
1.  **Constant Buffer (`cbuffer`):**
    *   Matrices: `World`, `ViewX`, `ViewY`, `ViewZ`, `Projection` [S1, S4].
    *   Integers: `width`, `height`, `depth`, `bcount` (flag for depth/occlusion handling) [S1].
2.  **Voxel Buffer (`u1`):**
    *   Option A: `RWTexture3D<float4> voxels` [S1].
    *   Option B: `RWStructuredBuffer<Voxel> voxels` where `struct Voxel { int3 pos; int4 color; }` [S1].
3.  **Pixel Shader Input (`PS_INPUT`):**
    *   `float4 pos : SV_POSITION` [S1].
    *   `unsigned int axis : COLOR1` (Dominant axis index: 0=X, 1=Y, 2=Z) [S1].
    *   `float4 color : COLOR0` (Optional vertex/texture color) [S1].
    *   `float2 uv : TEXCOORD0` (Optional) [S1].

**Steps:**

1.  **CPU Setup:**
    *   Compute the voxel grid position, extents, and three view-projection matrices: $VP_X$, $VP_Y$, and $VP_Z$. These matrices project 3D world coordinates onto the 2D planes perpendicular to the X, Y, and Z axes respectively, mapping them into the voxel grid space [S4].
    *   Configure the GPU pipeline: Disable depth testing and face culling to ensure all triangles are processed regardless of occlusion or orientation [S3, S4]. Disable color writes to the default render target if using a structured buffer output [S4].

2.  **Geometry Shader (Dominant Axis Selection):**
    *   For each input triangle, calculate the face normal $\mathbf{n}$ (or use the cross product of edge vectors $\mathbf{p} = |\text{cross}(\mathbf{v}_1-\mathbf{v}_0, \mathbf{v}_2-\mathbf{v}_0)|$) [S1, S3].
    *   Determine the dominant axis index $ind$ by finding the component with the maximum absolute value:
        $$ \text{maxComponent} = \max(|n_x|, |n_y|, |n_z|) $$
        $$ ind = \begin{cases} 0 & \text{if } |n_x| = \text{maxComponent} \\ 1 & \text{if } |n_y| = \text{maxComponent} \\ 2 & \text{if } |n_z| = \text{maxComponent} \end{cases} $$
        [S2, S4].
    *   Select the corresponding view matrix ($View_X, View_Y, \text{or } View_Z$) [S1].
    *   Transform the triangle vertices using the World matrix and the selected View matrix.
    *   **Reprojection:** Reorder the components of the clip-space position `gl_Position` to project along the dominant axis. This ensures the rasterizer generates fragments for the "front-most" or most visible projection of the triangle, maximizing coverage [S2]:
        *   If $ind == 0$ (X-axis dominant): `gl_Position = vec4(gl_in[i].gl_Position.zyx, 1.0)`
        *   If $ind == 1$ (Y-axis dominant): `gl_Position = vec4(gl_in[i].gl_Position.xzy, 1.0)`
        *   If $ind == 2$ (Z-axis dominant): `gl_Position = vec4(gl_in[i].gl_Position.xyz, 1.0)`
        [S2].
    *   Emit the vertex using `EmitVertex()` [S2].

3.  **Pixel Shader (Voxel Writing):**
    *   Receive the projected fragment, the dominant axis index, and color data [S1].
    *   **Conservative Rasterization (Optional but recommended):** To avoid holes, "bloat" the triangle vertices before rasterization or use extensions like `NV_conservative_raster` to guarantee all partially covered voxels are filled [S4, S2].
    *   **Depth Handling:** If `bcount` is non-zero, increment an atomic counter and discard the fragment to handle depth buffering or occlusion culling logic [S1].
    *   **Coordinate Conversion:** Calculate the 3D voxel coordinates $(x, y, z)$ from the 2D rasterized position and the dominant axis. Using viewport dimensions $W, H$ and depth $D$:
        *   If axis is 0 (X): $x = \text{depth} - \text{input.pos.x}$, $y = \text{input.pos.z} \times W$, $z = H - \text{input.pos.y}$ [S1].
        *   If axis is 1 (Y): $y = \text{input.pos.x} \times H$, $z = \text{input.pos.z} \times D$, $x = W - \text{input.pos.y}$ (Derived from symmetry and standard axis swaps).
        *   If axis is 2 (Z): $z = \text{input.pos.x} \times D$, $x = \text{input.pos.z} \times W$, $y = H - \text{input.pos.y}$ (Derived from symmetry).
        *   *Note: Specific implementations vary slightly in axis mapping and coordinate system handedness. The formula `pos.x = input.Pos.z * width; pos.y = height - input.Pos.y; pos.z = input.Pos.x` is cited for viewport 0 in CustomVoxelizer [S1].*
    *   **Write:** Write the voxel data (position and color) to the output buffer. If using a `RWStructuredBuffer`, use an atomic counter (`IncrementCounter()`) to append voxels, as the order is not guaranteed [S1]. If using `RWTexture3D`, write directly to the calculated 3D index [S1].

**Pseudocode:**

```python
# Geometry Shader (GLSL-like pseudocode)
void main() {
    // 1. Calculate Normal
    vec3 edge1 = gl_in[1].gl_Position.xyz - gl_in[0].gl_Position.xyz;
    vec3 edge2 = gl_in[2].gl_Position.xyz - gl_in[0].gl_Position.xyz;
    vec3 normal = normalize(cross(edge1, edge2));
    
    // 2. Find Dominant Axis
    float maxComp = max(abs(normal.x), max(abs(normal.y), abs(normal.z)));
    int axis = 0;
    if (abs(normal.y) == maxComp) axis = 1;
    else if (abs(normal.z) == maxComp) axis = 2;
    
    // 3. Select View Matrix
    mat4 viewMat;
    if (axis == 0) viewMat = ViewX;
    else if (axis == 1) viewMat = ViewY;
    else viewMat = ViewZ;
    
    // 4. Process Vertices
    for (int i = 0; i < 3; i++) {
        vec4 worldPos = World * vec4(gl_in[i].gl_Position.xyz, 1.0);
        vec4 viewPos = viewMat * worldPos;
        
        // 5. Reproject for Dominant Axis
        // Reorder components to project along the dominant axis
        vec4 reprojected;
        if (axis == 0) reprojected = vec4(viewPos.z, viewPos.y, viewPos.x, 1.0); // Project to YZ plane (X is depth)
        else if (axis == 1) reprojected = vec4(viewPos.x, viewPos.z, viewPos.y, 1.0); // Project to XZ plane (Y is depth)
        else reprojected = vec4(viewPos.x, viewPos.y, viewPos.z, 1.0); // Project to XY plane (Z is depth)
        
        gl_Position = reprojected;
        
        // Pass axis info to pixel shader
        OutAxis = axis;
        OutColor = VertexColor[i];
        
        EmitVertex();
    }
    EndPrimitive();
}

# Pixel Shader (GLSL-like pseudocode)
void main() {
    // 1. Calculate Voxel Coordinates
    // Assuming standard NDC to viewport conversion
    float x_ndc = gl_FragCoord.x / width;
    float y_ndc = gl_FragCoord.y / height;
    float z_ndc = gl_FragCoord.z; // Depth buffer value
    
    int3 voxelPos;
    
    if (OutAxis == 0) {
        // Dominant X: Projected on YZ. X is derived from depth/normal direction?
        // Based on S1 formula for axis 0: v.pos.x = depth - input.pos.x; 
        // Here input.pos.x in S1 likely refers to the reprojected depth component.
        // Mapping NDC back to grid indices:
        voxelPos.x = int((1.0 - z_ndc) * depth); // Assuming Z in NDC maps to X grid
        voxelPos.y = int(x_ndc * width);
        voxelPos.z = int((1.0 - y_ndc) * height);
    } else if (OutAxis == 1) {
        voxelPos.y = int((1.0 - z_ndc) * height); // Y is depth
        voxelPos.x = int(x_ndc * width);
        voxelPos.z = int((1.0 - y_ndc) * depth);
    } else {
        voxelPos.z = int((1.0 - z_ndc) * depth); // Z is depth
        voxelPos.x = int(x_ndc * width);
        voxelPos.y = int((1.0 - y_ndc) * height);
    }
    
    // 2. Write to Buffer
    // If using Structured Buffer with Atomic Counter:
    uint index = voxels.IncrementCounter();
    voxels[index] = Voxel(voxelPos, int4(Color, 1.0));
    
    // If using Texture3D:
    // voxels[voxelPos] = float4(Color, 1.0);
}
```

**Parameters:**
*   **Grid Resolution:** Commonly tested at $32^3, 128^3, 256^3, 512^3$ [S4].
*   **bcount:** Integer flag. If non-zero, triggers atomic counter increment and fragment discard for depth/occlusion management [S1].
*   **viewport:** Integer flag (0, 1, 2) to select projection plane in some implementations [S1].

**Edge Cases and Pitfalls:**
*   **Holes:** Standard rasterization only covers pixels where the triangle center lies. This creates holes in the voxel grid. Mitigation requires "bloated" vertices or `NV_conservative_raster` extension [S4, S2].
*   **Overwriting:** Using atomic counters for structured buffers means write order is undefined. Without proper depth handling (e.g., `bcount` logic), voxels may be overwritten incorrectly [S1].
*   **Precision:** Floating-point atomic operations are not universally supported; manual averaging or integer formats may be required for color accumulation [S2].

## Subtopics

### [GPU-based Conservative Voxelization](2580-gpu-based-conservative-voxelization.md)
A two-pass GPU algorithm that converts 3D triangle meshes into a list of voxels using conservative rasterization, followed by an octree construction step. It uses atomic counters to determine voxel count for buffer allocation. Choose this when memory efficiency (sparse storage) is critical and you need guaranteed hole-free voxelization.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of triangles, as each triangle is processed once in a single draw call [S4].
*   **Memory Complexity:** $O(W \times H \times D)$ for the voxel grid storage [S4].
*   **Performance:** Voxelizing a whole scene at $512 \times 512 \times 512$ resolution took 11.70 ms on an NVIDIA GTX 770 without LOD or optimizations [S4]. The $128^3$ grid is significantly faster [S4].
*   **Strengths:** Single-pass rendering (efficient), leverages highly optimized hardware rasterizer, simple implementation [S4].
*   **Limitations:** Requires conservative rasterization to avoid holes, fixed-resolution grid can be memory-intensive for high resolutions, order-independent writing requires careful handling of overwrites [S1, S4].
*   **When to use:** Real-time global illumination, voxel cone tracing, volumetric effects where speed is prioritized over perfect geometric accuracy [S4].
*   **When not to use:** When sparse storage is strictly required (use octree variants), or when analytical precision is needed without rasterization artifacts.

## Background
This method originated as a practical implementation of the first step of Voxel Cone Tracing, a technique for real-time global illumination [S3, S4]. It was popularized by blog posts and source code from developers like Alexandre Pestana, Simon Yeung, and Alex Nankervis, who adapted hardware rasterization for 3D grids [S4]. The core insight is that the GPU rasterizer can be "tricked" into filling a 3D volume by projecting triangles along their dominant axis, effectively treating the 3D grid as a series of 2D layers [S4]. It is widely used in modern real-time rendering pipelines for GI and volumetric effects [S4].
