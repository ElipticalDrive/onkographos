# LOD Ground Truth Generation from Surface Intersections

Also called: intersection-based LOD construction

## Overview
Constructs a Level-of-Detail (LOD) representation for a scene by downsampling high-resolution binary voxels and Signed Distance Fields (SDFs), extracting surface intersections along axes, and storing them in a sparse pointer/data structure per grid cell. It differs from standard binary voxelization by preserving continuous surface geometry information (intersections and normals) at lower resolutions, enabling more accurate ground truth generation for neural rendering or implicit surface reconstruction tasks.

## How it works
**Inputs:**
- High-resolution binary voxel grid (e.g., $1024^3$).
- High-resolution SDF grid (e.g., $128^3$).
- Intersection files (pre-computed or derived).
- Target grid sizes (e.g., $[32, 64]$).

**Outputs:**
- `LOD_gt_int`: 4D array `[grid_size+1, grid_size+1, grid_size+1, 3]`, `uint8`. Stores 3 cube edge flags per cell.
- `LOD_gt_float`: 4D array `[grid_size+1, grid_size+1, grid_size+1, 3]`, `float32`. Stores 1 cube internal plane parameter (P) per cell.
- `LOD_intersection_pointer`: 1D array of `int32`. Stores pointers/indices to intersection data per cell.
- `LOD_intersection_data`: 2D array `[max_len, 6]`, `float32`. Stores intersection coordinates (3) and normals (3).

**Data Structures:**
The method uses a sparse representation for intersections to handle varying density across the grid. Each cell in the target LOD grid points to a list of intersections via `LOD_intersection_pointer`. The actual data (position and normal) is stored contiguously in `LOD_intersection_data`.

**Parameters:**
- `grid_size_list`: List of target grid resolutions, e.g., `[32, 64]` [S1, unofficial].
- `cell_voxel_size`: Scaling factor for voxel size, set to 8 [S1, unofficial].
- `point_sample_num`: Number of points sampled from mesh for testing, set to 65536 [S1, unofficial].

**Steps:**
1. **Load Data:** Load high-resolution voxel, SDF, and intersection files [S1, unofficial].
2. **Compute Downscale:** For each target grid size in `grid_size_list`, compute the downscale factor relative to the high-resolution input.
3. **Downsample:** Downsample the voxel and SDF grids by striding with the computed downscale factor [S1, unofficial].
4. **Extract Intersections:** Identify grid cells where surface intersections occur. Specifically, extract intersections where the coordinate modulo the downscale factor equals 0, then divide the coordinates by the downscale factor to map them to the target LOD grid [S1, unofficial].
5. **Store Intersections:** Store the extracted intersections in `LOD_intersection_pointer` and `LOD_intersection_data`. Each intersection entry contains 6 values: 3 for coordinates and 3 for normals [S1, unofficial].
6. **Handle Empty Cells:** If a cell has no intersections (reference length == 0), skip processing to avoid singular least-squares systems [S1, unofficial].
7. **Plane Parameter Fitting:** For cells with intersections, fit a plane parameter using iterative regularization. If the solution $x$ falls outside $[0,1]$, cap the regularization scale at 1000. If it still fails, fall back to the center point $[0.5, 0.5, 0.5]$ [S1, unofficial].
8. **Output Generation:** Generate the final `LOD_gt_int` and `LOD_gt_float` arrays based on the processed data [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of intersections and the grid size. Downsampling is $O(N)$ where $N$ is the number of high-resolution voxels. Intersection extraction and fitting are $O(M)$ where $M$ is the number of intersections.
- **Memory Complexity:** $O(G^3)$ for the dense arrays (`LOD_gt_int`, `LOD_gt_float`) where $G$ is the grid size. The sparse intersection data is $O(I)$ where $I$ is the total number of intersections.
- **Strengths:** Preserves continuous surface geometry at lower resolutions, enabling more accurate ground truth for neural rendering.
- **Limitations:** Requires pre-computed high-resolution data. Sparse data structures can be complex to manage.
- **When to use:** When generating ground truth for neural rendering or implicit surface reconstruction at multiple resolutions.
- **When not to use:** When only binary voxelization is needed, or when computational resources are limited.

## Background
Originated in the context of neural rendering and implicit surface reconstruction, specifically in the NDC (Normalized Device Coordinates) framework. The method is part of a pipeline for generating high-quality ground truth data for training neural networks to represent 3D scenes.
