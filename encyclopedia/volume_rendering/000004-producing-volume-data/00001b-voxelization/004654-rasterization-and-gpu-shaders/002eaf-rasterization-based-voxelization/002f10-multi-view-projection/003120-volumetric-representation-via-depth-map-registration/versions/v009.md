# Volumetric Representation via Depth Map Registration

Also called: Sparse Non-Lambertian Multi-view Volume Construction, Volume Initialization

## Overview
This method constructs a 3D sparse voxel volume from a set of multi-view images by registering estimated depth maps into a voxel grid [S1]. It specifically addresses non-Lambertian reflections by using individual minimum cost per view rather than a global threshold for depth estimation [S1]. Unlike standard rasterization-based voxelization which relies on geometric projection of triangles, this approach relies on photometric consistency and depth registration, resulting in a sparse voxel cloud where voxel values indicate the count of views mapping to that location [S1]. It serves as a robust initialization step for view synthesis applications, handling noise and scattering artifacts through iterative refinement [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   A set of $N$ reference views (images and camera parameters).
*   Estimated depth maps for each reference view, derived by searching along the view's geometry using individual minimum cost to handle non-Lambertian reflections [S1].

**Outputs:**
*   A sparse 3D voxel grid where each occupied voxel $(i, j, k)$ stores a weight $\delta_{ijk}$ representing the number of views mapping to that location.
*   A refined volume with smoothed surfaces and removed scattering voxels.

### Data Structures
*   **Voxel Grid:** A 3D array or sparse hash map indexed by $(i, j, k)$.
*   **Voxel Value:** An integer $\delta_{ijk} \in \{0, 1, \dots, N\}$.
    *   $\delta_{ijk} = n$ if a depth is registered to voxel $(i, j, k)$ from $n$ views.
    *   $\delta_{ijk} = 0$ if no depth is registered [S1].
*   **Depth Cluster:** For each pixel in a reference view, a list of candidate depth values projected from the current volume state, each associated with a weight $\delta_k$ [S1].

### Algorithm Steps

#### Phase 1: Volume Initialization

1.  **Depth Estimation:** For each reference view, estimate a depth map by searching along the view's geometry. Use individual minimum cost per view to compensate for non-Lambertian reflections, avoiding global thresholds [S1].

2.  **Depth Registration:** Register the estimated depth maps into the 3D volume. For each voxel at location $(i, j, k)$, calculate its value $\delta_{ijk}$:
    $$
    \delta_{ijk} = 
    \begin{cases} 
    n & \text{if registering depth} \\
    0 & \text{otherwise}
    \end{cases}
    $$
    where $n$ is the number of views mapping to the voxel, and $n \in \{1, 2, \dots, N\}$ [S1].

3.  **Isolated Voxel Detection and Correction:**
    *   Detect isolated voxels that have no neighbors.
    *   Project the current volume back to the reference view geometry to build new depth maps. This step removes errors from the previous registration by incorporating depth information from other views [S1].
    *   If multiple depth values exist for a single pixel in the projected view, identify the "front cluster" of depths. Ideally, there is one depth value from the front surface, but noise causes dispersion [S1].
    *   Determine the proper depth value $d$ for the pixel using the following weighted formula:
        $$
        d = 
        \begin{cases} 
        d_n & \text{if only one depth has } \delta_n = \max(\delta_K) \\
        \frac{\sum_{k=1}^{K} \delta_k d_k}{\sum_{k=1}^{K} \delta_k} & \text{otherwise}
        \end{cases}
        $$
        where $K$ is the number of depth values in the front cluster, $d_k$ is the depth value, and $\delta_k$ is the voxel weight associated with that depth [S1].
    *   Reconstruct the volume again using the corrected depths. Interpolate voxels to connect the surface of the volume among near voxels [S1].

#### Phase 2: Iterative Volume Refinement

4.  **Color Assignment:** Temporarily define the color of each voxel by taking the median of color values from all visible views [S1].

5.  **Error Calculation and Correction:**
    *   Iterate through the reference views (e.g., from furthest left to furthest right) [S1].
    *   For each view, calculate the Mean Square Error (MSE) between the reconstructed view (using current voxel colors and positions) and the original reference image. Use a window-based computation (e.g., 3x3 pixels) for error calculation to handle inaccurate camera calibration and unequal resolutions [S1].
    *   If the MSE exceeds a predefined threshold:
        *   Remove the old depth and its associated voxel.
        *   Investigate a new depth derived from neighboring pixels based on a smooth surface assumption [S1].
        *   If the new depth value meets color constraints for all visible views, generate the new associated voxel [S1].
    *   If voxels are removed or generated, iteratively reconstruct the images because changes in voxel position affect visibility (an invisible point may become visible and vice versa) [S1].
    *   Repeat the iteration until no new voxels are generated and no old voxels are removed [S1].

        voxel_colors = compute_median_colors(volume, reference_views)

### Parameters and Edge Cases
*   **Threshold:** The MSE threshold for removing voxels is not explicitly defined in the sources [S1].
*   **Window Size:** A 3x3 pixel window is suggested for error calculation to handle calibration inaccuracies [S1].
*   **Non-Lambertian Reflections:** Handled by using individual minimum cost per view during depth estimation rather than a global threshold [S1].
*   **Camera Calibration:** Inaccurate calibration and unequal resolutions are mitigated by the window-based error computation [S1].
*   **Convergence:** The process is iterative. In the source example (Leo sequence, 5 views), convergence took 26 iterations [S1].

## Subtopics

### Iterative Volume Refinement
An iterative algorithm to refine the shape of the volume by removing scattering voxels and smoothing sharp corners to increase coding gain [S1]. It compares reconstructed views against original reference images to identify and correct geometry errors [S1]. It is chosen when the initial volume contains significant noise or sharp artifacts that reduce coding efficiency. It differs from the initialization phase by actively modifying the topology based on photometric error (MSE) rather than geometric registration counts.

## Operating characteristics

*   **Time Complexity:** The initialization phase is linear with respect to the number of pixels in the depth maps and the number of voxels. The refinement phase is iterative and its complexity depends on the number of iterations required for convergence. In the source example, 26 iterations were required for a 5-view sequence [S1].
*   **Memory Complexity:** Proportional to the number of occupied voxels in the sparse volume. The volume is sparse, storing only voxels with $\delta_{ijk} > 0$ [S1].
*   **Strengths:**
    *   Handles non-Lambertian reflections effectively by using per-view minimum cost [S1].
    *   Robust to noise through the front-cluster depth selection and iterative refinement [S1].
    *   Improves coding gain by smoothing sharp corners and removing scattering voxels [S1].
*   **Limitations:**
    *   Requires accurate initial depth estimation.
    *   Computationally expensive due to iterative reconstruction and error calculation [S1].
    *   Sensitive to camera calibration errors, though mitigated by window-based MSE [S1].
*   **When to use:** Suitable for view synthesis applications where high-quality volumetric representation is needed for coding or rendering, and where non-Lambertian effects are present [S1].
*   **When not to use:** When real-time performance is critical and iterative refinement is too slow, or when depth estimation is unreliable.

## Background

*   **Origin:** The method was proposed in the paper "Colour volumetric compression for realistic view synthesis applications" [S1].
*   **History:** It was developed to address limitations in existing volume construction methods, specifically regarding non-Lambertian reflections and scattering artifacts. The method builds on the principle that depth registration methods provide a good representation for natural scenery [S1].
*   **Usage:** It is used in colour volumetric compression for realistic view synthesis applications [S1].
