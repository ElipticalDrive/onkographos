# Multi-view projection

Also called: Multi-view rasterization, Multi-axis voxelization

## Overview
Multi-view projection voxelization converts a triangle mesh into a voxel grid by rasterizing the geometry from multiple orthogonal viewpoints (typically along the X, Y, and Z axes) and synthesizing the results into a unified 3D volume [S1, unofficial][S2, unofficial]. It solves the problem of "tunneling" or missing voxels that occurs when projecting along a single axis, particularly for thin or degenerate triangles, by ensuring complete spatial coverage through redundancy [S2, unofficial]. Unlike [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md), which relies on a single dominant axis and complex edge-crosshair tests to avoid tunnels, multi-view methods use multiple passes to guarantee robustness against degenerate orientations, at the cost of increased render passes [S2, unofficial].

## Shared principles
All methods in this family share the following mechanism:
1.  **Orthographic Projection:** Triangles are projected using orthographic cameras aligned with the principal axes (X, Y, Z). The view frustum is expanded slightly (e.g., $1.02 \times$ bounding box range) to ensure no geometry is clipped [S1, unofficial].
2.  **Multi-Pass Rasterization:** The scene is rasterized multiple times, once for each axis. Each pass generates a 2D buffer (or directly writes to a 3D texture) representing the intersection of triangles with the voxel grid along that axis [S1, unofficial][S2, unofficial].
3.  **Synthesis/Union:** The outputs from the individual views are combined. In direct 3D texture approaches, atomic writes or overwrites merge the data [S1, unofficial]. In sheet-buffer approaches, 2D buffers are transcoded into a compact 2D "worksheet" texture encoding the 3D space [S2, unofficial].
4.  **Degeneracy Handling:** Triangles parallel to a specific view direction may project as lines, causing missing voxels. Robust implementations either rely on the union of multiple views to cover these gaps or explicitly re-project triangles along their dominant normal axis [S2, unofficial].

## Subtopics

### [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md)
A method that uses only a single 2D rasterization pass along the dominant axis of the triangle's normal vector to produce 6-separating (tunnel-free) voxelizations. It differs from other multi-view siblings by eliminating the need for multiple render passes, leveraging the "thinness" property of voxels to prove that the dominant axis is sufficient. It requires complex per-pixel crosshair tests (horizontal and vertical bisectors) to detect edge intersections that standard rasterization misses. Choose this when performance is critical and triangles are planar and non-degenerate. See [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md).

### [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md)
A technique that projects triangles onto three intermediate 2D buffers aligned with the principal axes (X, Y, Z) and synthesizes them into a final 3D volume or compact 2D texture. It solves the coverage issues of single-view methods by using three orthogonal views to ensure complete coverage and robustness against degenerate triangle orientations. It supports two implementation variants: direct 3D texture writing (GPU-friendly) and sheet-buffer-to-worksheet synthesis (for memory-constrained or older hardware). Choose this for general-purpose, robust mesh voxelization where correctness is prioritized over minimal pass count. See [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md).

### [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md)
This method constructs a 3D sparse voxel volume from a set of multi-view images by registering estimated depth maps into a voxel grid. It differs from the mesh-based siblings by explicitly using depth estimation and registration to handle view-dependent appearance and non-Lambertian reflections through per-view minimum cost selection. It includes an iterative refinement step to remove scattering noise and smooth corners, which the rasterization-based siblings do not inherently provide. Choose this when initializing volumes from image sequences rather than triangle meshes. See [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md).

### 3-Pass Voxelization
#### definition
- A voxelization approach that fixes cracks and missing data in the voxel grid by voxelizing the scene from each of the 3 major axes, requiring 3 render passes [S1, unofficial].

#### step
- For each of the 3 major axes, multiply the clip-space projection matrix by a rotation matrix corresponding to that axis to generate fragments from that view-axis [S1, unofficial].
- Use the voxel-space projection matrix without multiplying it by the rotation matrix, as it already maps all values properly [S1, unofficial].

#### pitfall
- Requires 3 render calls per rendered object, which becomes expensive as models become more complex [S1, unofficial].
- If optimizing by separating dynamic and static objects, the voxel grid of dynamic objects must be cleared every frame, requiring separate voxel grids for dynamic and static objects [S1, unofficial].

## Background
The concept of multi-view voxelization originated as a solution to the "cracking" artifacts inherent in single-axis rasterization-based voxelization. Early implementations, such as those described in *Real-Time Ray Traced Voxel Global Illumination*, highlighted that a single projection direction fails to capture thin geometry or fills gaps due to rasterization precision [S1, unofficial]. The 3-pass approach was introduced as a simple fix to ensure full coverage by rasterizing along X, Y, and Z axes [S1, unofficial]. Later developments, such as the sheet-buffer-to-worksheet synthesis method, addressed hardware limitations regarding direct 3D texture writes on consumer GPUs, allowing for efficient memory usage by encoding multiple voxels per 2D texel [S2, unofficial]. These methods are widely used in real-time global illumination, voxel cone tracing, and volume rendering pipelines where fast mesh-to-voxel conversion is required.
