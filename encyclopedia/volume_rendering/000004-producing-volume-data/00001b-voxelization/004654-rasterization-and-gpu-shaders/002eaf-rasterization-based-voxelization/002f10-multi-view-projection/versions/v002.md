# Multi-view projection

Also called: Multi-view voxelization, Orthographic multi-view voxelization

## Overview
Multi-view projection methods convert triangle meshes into voxel grids by rasterizing geometry from multiple orthogonal viewpoints (typically along the X, Y, and Z axes) to resolve occlusion ambiguities and prevent cracks that occur with single-view approaches [S1, S2, unofficial]. Unlike [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md), which relies on a single dominant axis and may miss boundary voxels, multi-view techniques synthesize data from all three axes to ensure topological correctness and 6-connectivity, distinguishing them from [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md) which operates on continuous depth maps from camera images rather than discrete rasterization of meshes [S2, unofficial].

## Shared principles
All methods in this family share the core mechanism of projecting 3D geometry onto 2D planes aligned with the principal axes of the voxel grid.

1.  **Orthographic Projection:** The scene is viewed from infinity along the X, Y, and Z axes. This eliminates perspective distortion, allowing direct mapping of screen-space coordinates to voxel indices.
2.  **Axis-Aligned Rasterization:** Triangles are rasterized into buffers corresponding to the projection plane (e.g., XY plane for Z-axis view).
3.  **Synthesis:** Results from multiple views are combined. In direct write approaches, this involves atomic operations or blending into a 3D texture. In sheet-buffer approaches, it involves transcoding 2D buffers into a compact 2D worksheet or 3D texture.
4.  **Dominant Axis Selection (Optional):** To avoid degenerate projections (where a triangle appears as a line), some implementations select the projection axis that maximizes the projected area of the triangle [S2, unofficial].

## Subtopics

### [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md)
Produces 6-separating (tunnel-free) voxelization using only a single 2D projection along the dominant axis of a triangle's normal vector. It leverages the "thinness property" to avoid redundant calculations. Unlike the full multi-view approach, it reduces computational cost by determining occupancy based on orientation, but it requires careful edge testing to ensure boundary voxels are captured. Choose this when computational resources are limited and the geometry is relatively thin or aligned with grid axes.

### [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md)
Generates a 3D voxelized representation by projecting geometry onto three orthogonal planes (X, Y, Z) and synthesizing the results. It solves the problem of depth ambiguity and cracks inherent in single-view methods by using three views to resolve occlusion. It differs from single 2D projection by explicitly handling all orientations, and from depth-map registration by operating directly in discrete voxel space using sheet buffers or direct 3D texture writes. Choose this for robust, crack-free voxelization of complex meshes in real-time rendering pipelines.

### [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md)
Constructs a 3D volume from a set of multi-view images by registering estimated depth maps into a voxel grid. It solves the problem of non-Lambertian reflections by using individual minimum cost per view rather than a global threshold. It differs from Orthographic Multi-View Voxelization by explicitly handling non-Lambertian surfaces through per-view depth estimation costs and by refining the volume shape iteratively to remove scattering voxels. Choose this when working with image-based reconstruction (SfM/MVS) rather than explicit triangle meshes.

### 3-Pass Voxelization
#### definition
- [S1, unofficial] A voxelization approach that fixes cracks and missing data in the voxel grid by voxelizing the scene from each of the 3 major axes, requiring 3 render passes.
#### step
- [S1, unofficial] For each of the 3 major axes, multiply the clip-space projection matrix by a rotation matrix corresponding to that axis to generate fragments from that view-axis.
- [S1, unofficial] Use the voxel-space projection matrix without multiplying it by the rotation matrix, as it already maps all values properly.
#### pitfall
- [S1, unofficial] Requires 3 render calls per rendered object, which becomes expensive as models become more complex.
- [S1, unofficial] If optimizing by separating dynamic and static objects, the voxel grid of dynamic objects must be cleared every frame, requiring separate voxel grids for dynamic and static objects.

## Background
The concept of multi-view voxelization originated as a solution to the "crack" problem in single-direction rasterization-based voxelization, where triangles parallel to the view direction or thin geometry could leave gaps in the voxel grid [S1, unofficial]. The 3-pass approach was formalized in early real-time ray-traced voxel global illumination research to ensure complete coverage of the scene geometry for subsequent cone tracing [S1, unofficial]. The technique has since evolved to include optimizations such as sheet buffers for memory efficiency and dominant axis selection to handle degenerate cases [S2, unofficial]. It is primarily used in real-time global illumination techniques like Voxel Cone Tracing (VCT) and hardware-accelerated ray tracing pipelines where a dense, watertight voxel representation is required for efficient light transport simulation.
