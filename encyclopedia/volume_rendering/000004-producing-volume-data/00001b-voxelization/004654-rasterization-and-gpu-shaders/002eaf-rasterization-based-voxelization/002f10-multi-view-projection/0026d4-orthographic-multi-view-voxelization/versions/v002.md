# Orthographic Multi-View Voxelization

Also called: 3-Direction Rasterization, 3-View Voxelization, Directional Sheet Buffer Voxelization, Orthographic 3D Texture Rasterization, Voxelization via Orthographic Projection, Worksheet Voxelization

## Overview
Orthographic Multi-View Voxelization is a rasterization-based technique that generates a 3D voxelized representation of a scene by projecting geometry onto three orthogonal planes (X, Y, Z) and synthesizing the results into a final compact texture [S1, S2, unofficial]. It solves the problem of efficiently converting triangle meshes into volumetric data for subsequent rendering techniques like voxel cone tracing [S1, unofficial]. Unlike [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md), which suffers from depth ambiguity and cracks, this method uses three views to resolve occlusion ambiguities by selecting the projection direction with the maximum surface area for each triangle [S2, unofficial]. It differs from [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md) by operating directly in discrete voxel space using sheet buffers rather than continuous depth maps [S2, unofficial].

## How it works
**Inputs:** A triangle mesh with a known axis-aligned bounding box (AABB) defined by `bb_min` and `bb_max`.
**Outputs:** A 3D texture (or a 2D "worksheet" texture encoding the 3D volume) containing voxel occupancy or material data.

**Data Structures:**
1.  **Scene Bounding Box:** `bb_min` (vec3), `bb_max` (vec3).
2.  **Voxel Grid Scale:** `scale` = `(voxelTextureSize / range)`, where `range = bb_max - bb_min` [S1, unofficial].
3.  **3D Texture (Direct Write):** A `std::vector<GLfloat>` of size `4 * voxelTextureSize.x * voxelTextureSize.y * voxelTextureSize.z`, initialized to `0.0f`, representing RGBA32F data [S1, unofficial].
4.  **Sheet Buffers:** Three 2D intermediate buffers, one for each axis direction (X, Y, Z), used during rasterization [S2, unofficial].
5.  **Worksheet (2D Texture):** A 2D texture of resolution $2^W \times 2^H$. It encodes the discrete voxel space ($2^L \times 2^M \times 2^N$) such that $2^L \times 2^M \times 2^N = 2^W \times 2^H \times C$, where $C$ is the number of voxels encoded in a single texel (e.g., $C=32$ for binary voxelization with four 8-bit components) [S2, unofficial].

**Parameters:**
*   `voxelTextureSize`: Default resolution, e.g., `glm::uvec3(64, 64, 64)` [S1, unofficial].
*   `offset`: Camera extension distance beyond the bounding box, fixed at `0.2f` [S1, unofficial].
*   `projection_scale`: Frustum expansion factor, fixed at `1.02f` (passed as `0.51f` to half-width) [S1, unofficial].

**Steps:**

1.  **Initialization:**
    *   Calculate `range = bb_max - bb_min`.
    *   Compute `scale = voxelTextureSize / range` [S1, unofficial].
    *   Clear the target 3D texture to `RGBA(0,0,0,0)` [S1, unofficial].
    *   Disable multisampling, depth testing, and face culling [S1, unofficial].
    *   Bind the 3D texture as a read-write image buffer (e.g., `GL_RGBA8` or `GL_RGBA32F`) [S1, unofficial].

2.  **Camera Setup:**
    *   Set up three orthographic cameras aligned with the X, Y, and Z axes.
    *   Set the camera offset to `0.2f` beyond the max bounds along each axis [S1, unofficial].
    *   Set the orthographic projection frustum bounds to `1.02x` the scene range on the viewing planes [S1, unofficial].
    *   Set near plane to `0.1f` and far plane to `1.2x range + offset` [S1, unofficial].
    *   Pass the three view-projection matrices to shader uniforms `viewProject[0]`, `viewProject[1]`, and `viewProject[2]` [S1, unofficial].

3.  **Rasterization (Stage 1):**
    *   For each of the three axes (X, Y, Z):
        *   Identify triangles intersecting the current slab/direction.
        *   **Direction Selection:** Determine the axis direction where the triangle has the maximum projection area. Rasterize the triangle along this direction to avoid degenerate line segments caused by 2D linear interpolation when the triangle is parallel to the view [S2, unofficial].
        *   Rasterize the triangle into the corresponding Sheet Buffer for that axis.

4.  **Texelization (Stage 2):**
    *   Transform the rasterized voxel positions from 2D screen space to 3D volume coordinates immediately [S2, unofficial].
    *   Use these coordinates to find the correct position in the Worksheet or 3D texture.
    *   Add voxels to the Worksheet via a blending operation at the corresponding location [S2, unofficial].

5.  **Synthesis (Stage 3):**
    *   Transcode the three directional Sheet Buffers to the final Worksheet [S2, unofficial].
    *   Transform each element to discrete voxel space.
    *   Encode to the appropriate texel in the Worksheet.
    *   **Voxel Access Logic (for Worksheet):**
        *   Given volume coordinates $(p_x, p_y, p_z)$:
        *   Determine the patch by dividing $p_z$ by $C$ (voxels per texel).
        *   Access the texel at $(p_x, p_y)$ in the found patch.
        *   Determine the bit offset within the component using $p_z$ and $C$.
        *   Use a lookup table to access the specific bits [S2, unofficial].

6.  **Post-Processing:**
    *   Generate mipmaps for the filled 3D texture to enable multi-resolution cone tracing [S1, unofficial].

**Pseudocode:**

```python
def orthographic_multi_view_voxelization(mesh, bb_min, bb_max, voxel_texture_size):
    """
    Voxelizes a mesh using three orthographic views.
    """
    # 1. Initialization
    range_vec = bb_max - bb_min
    scale = voxel_texture_size / range_vec
    offset = 0.2f
    projection_scale = 1.02f
    
    # Clear 3D texture
    voxel_texture = create_3d_texture(voxel_texture_size, format=RGBA32F)
    voxel_texture.clear(0.0)
    
    # Disable depth/culling for direct write
    disable_depth_test()
    disable_face_culling()
    
    # Bind texture as image buffer
    bind_image_texture(0, voxel_texture, access=GL_READ_WRITE)
    
    # 2. Setup Cameras and Shaders
    # Create 3 orthographic cameras aligned with X, Y, Z axes
    cameras = []
    for axis in [X_AXIS, Y_AXIS, Z_AXIS]:
        cam = OrthographicCamera()
        cam.offset = bb_max + offset # Extend beyond max bounds
        cam.frustum_half_width = range_vec * (projection_scale / 2.0)
        cam.near = 0.1f
        cam.far = (range_vec * 1.2) + offset
        cameras.append(cam)
        
    # Pass matrices to shader
    shader.set_uniform("viewProject", [cam.get_view_projection() for cam in cameras])
    shader.set_uniform("boxMin", bb_min)
    shader.set_uniform("scale", scale)
    
    # 3. Rasterization Loop
    for i, cam in enumerate(cameras):
        # Identify triangles intersecting the current view/slab
        intersecting_triangles = get_intersecting_triangles(mesh, cam)
        
        for tri in intersecting_triangles:
            # Determine rasterization direction based on max projection area
            # This avoids degenerate line segments
            best_axis = get_max_projection_axis(tri.normal, [X_AXIS, Y_AXIS, Z_AXIS])
            
            # Rasterize triangle into the sheet buffer for the best axis
            # Note: In a GPU implementation, this is done via draw calls
            # with the specific view matrix for that axis
            rasterize_triangle(tri, cam, best_axis)
            
    # 4. Synthesis (if using Worksheet method)
    # Transcode sheet buffers to final worksheet
    worksheet = transcode_sheet_buffers_to_worksheet(sheet_buffers, voxel_texture_size)
    
    # 5. Post-processing
    generate_mipmaps(voxel_texture)
    
    return voxel_texture
```

## Subtopics

### [Shadow Volume Voxelization](5629-shadow-volume-voxelization.md)
Shadow Volume Voxelization is a rasterization-based technique that generates a 3D shadow volume texture by voxelizing scene geometry into a 3D grid, where each voxel stores a bitmask representing which of its 8 constituent sub-voxels are occluded. It builds on [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) by replacing the standard occupancy flag with a 3-bit occlusion mask per coarse voxel, enabling multi-resolution shadow representation through mipmaps. Unlike standard binary voxelization, this method preserves partial occlusion information within each voxel, allowing for smoother shadow transitions and hierarchical shadow testing.

### Slicing-based voxelization
Slicing-based voxelization rasterizes the model the same number of times as the resolution of the volume along the z-direction [S2, unofficial]. This method is significantly slower than the proposed 2D texture method; for the Blade model at $256^3$, it takes ~5 seconds compared to ~100ms for the proposed method [S2, unofficial]. A major pitfall is that rendering directly to 3D textures was not supported in consumer graphics hardware of the PC platform at the time of writing [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of triangles and the number of views (constant 3). The synthesis step is linear with respect to the number of voxels/texels.
*   **Memory Complexity:** $O(V)$ where $V$ is the number of voxels. The worksheet method compresses this into a 2D texture of size $2^W \times 2^H$.
*   **Measured Performance:** For a $256^3$ resolution, the proposed method takes ~100ms, whereas slicing-based voxelization takes ~5 seconds [S2, unofficial].
*   **Strengths:** Hardware-accelerated via standard rasterization pipelines; avoids CPU-side depth sorting; handles complex models efficiently.
*   **Limitations:** Requires careful handling of degenerate cases (parallel triangles); the worksheet encoding adds complexity to voxel access; 3D texture direct write support may be limited on older hardware [S2, unofficial].
*   **When to use:** Real-time voxelization for complex models where performance is critical.
*   **When not to use:** When exact sub-voxel precision is required without bitmasking, or when hardware does not support 3D texture writes.

## Background
The method was presented in "Real-time Voxelization for Complex Models" [S2, unofficial], which proposed representing the resultant volume as 2D textures (worksheet) to enable efficient hardware-accelerated voxelization. It was designed to overcome the limitations of slicing-based voxelization and Layered Depth Image (LDI) extraction, which were either too slow or view-dependent [S2, unofficial]. An unofficial implementation of this concept is found in the "Voxel Cone Tracing" project [S1, unofficial], which uses a similar 3-view orthographic projection approach to generate voxel data for real-time global illumination.
