# Orthographic Multi-View Voxelization

Also called: 3-Direction Rasterization, 3-View Voxelization, Directional Sheet Buffer Voxelization, Orthographic 3D Texture Rasterization, Voxelization via Orthographic Projection, Worksheet Voxelization

## Overview
Orthographic Multi-View Voxelization rasterizes scene geometry into a 3D voxel grid using three orthographic cameras aligned with the scene's bounding box axes ($X, Y, Z$) to create a voxelized representation for subsequent volume rendering [S1, unofficial]. It builds on [Multi-view projection](5937-multi-view-projection.md) by explicitly managing three directional sheet buffers to synthesize a final volume, avoiding the degenerate rasterization artifacts that occur when triangles are parallel to the viewing direction [S2, unofficial]. Unlike [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md), which suffers from missing geometry on surfaces parallel to the single view axis, this method ensures robust coverage through union semantics across all three axes [S1, unofficial].

## How it works
**Inputs:**
*   Scene geometry (triangles) in world space.
*   Scene bounding box $B = [B_{min}, B_{max}]$.
*   Target voxel grid resolution $V = (V_x, V_y, V_z)$.
*   Camera extension offset (default $0.2f$) [S1, unofficial].
*   Frustum expansion factor (default $1.02f$) [S1, unofficial].

**Outputs:**
*   A 3D texture (or worksheet) representing the voxelized volume.

**Data Structures:**
1.  **3D Texture / Image Buffer:** A `std::vector<GLfloat>` of size $4 \times V_x \times V_y \times V_z$, initialized to `0.0f`, representing RGBA32F voxel data [S1, unofficial]. In the "Worksheet" variant, this is a 2D texture of resolution $2^W \times 2^H$ encoding the discrete voxel space $2^L \times 2^M \times 2^N$ such that $2^L \times 2^M \times 2^N = 2^W \times 2^H \times C$, where $C$ is the number of voxels encoded in a single texel (e.g., $C=32$ for binary voxelization with four 8-bit components) [S2, unofficial].
2.  **Sheet Buffers:** Three 2D buffers representing parts of the discrete voxel space, one for each axis direction (X, Y, Z) [S2, unofficial].
3.  **View-Projection Matrices:** Three matrices `viewProject[0]`, `viewProject[1]`, and `viewProject[2]` corresponding to the X, Y, and Z axes [S1, unofficial].

**Steps:**

1.  **Initialization:**
    *   Calculate the scene bounding box min/max and compute the range $R = B_{max} - B_{min}$ [S1, unofficial].
    *   Set the voxel grid scale uniform to $(V_x/R_x, V_y/R_y, V_z/R_z)$ and the box min uniform to $B_{min}$ [S1, unofficial].
    *   Clear the 3D texture to RGBA(0,0,0,0) [S1, unofficial].
    *   Disable multisampling, depth testing, and face culling [S1, unofficial].
    *   Bind the texture as a read-write image buffer (e.g., `GL_RGBA8` or `GL_RGBA32F`) [S1, unofficial].

2.  **Camera Setup:**
    *   Construct orthographic projection matrices for each axis.
    *   Set the orthographic frustum bounds to $1.02 \times$ the scene range on the viewing planes [S1, unofficial].
    *   Set the near plane at $0.1f$ and the far plane at $1.2 \times \text{range} + \text{offset}$ [S1, unofficial].
    *   The offset is fixed at $0.2f$ beyond the max bounds along each axis [S1, unofficial].

3.  **Rasterization (Per Axis):**
    *   For each axis $A \in \{X, Y, Z\}$:
        *   Bind the corresponding `viewProject[A]` matrix [S1, unofficial].
        *   **Triangle Selection:** Identify triangles intersecting the current slab or volume [S2, unofficial].
        *   **Direction Selection:** Determine the rasterization direction for each triangle. To avoid degenerate rasterization where 2D linear interpolation results in a line segment, rasterize the triangle along the axis direction most parallel to its orientation (i.e., the direction where it has the maximum projection area) [S2, unofficial].
        *   **Rasterization:** Rasterize the triangles onto the intermediate sheet buffer for axis $A$. Fragments are written to the 3D texture or sheet buffer.
        *   **Atomic Accumulation:** Use atomic operations (e.g., `atomicAdd` or `atomicMax`) to handle concurrent writes from multiple fragments to the same voxel coordinate, ensuring occupancy or material data is preserved [S1, unofficial].

4.  **Synthesis (Worksheet Variant Only):**
    *   If using the worksheet approach, transcode the three directional sheet buffers to the final 2D worksheet texture [S2, unofficial].
    *   Transform each element from the sheet buffers to discrete voxel space coordinates $(px, py, pz)$ [S2, unofficial].
    *   Encode the voxel into the appropriate texel in the worksheet.
    *   **Voxel Access Logic:** To access a voxel at $(px, py, pz)$:
        1.  Determine the patch by dividing $pz$ by $C$ (voxels per texel) [S2, unofficial].
        2.  Access the texel at $(px, py)$ in the found patch [S2, unofficial].
        3.  Determine the bit offset within the texel components using $pz$ and $C$ [S2, unofficial].
        4.  Use a lookup table to extract the specific bits representing the voxel [S2, unofficial].

5.  **Finalization:**
    *   Generate mipmaps for the filled 3D texture to enable multi-resolution cone tracing [S1, unofficial].

**Pseudocode:**

```python
def orthographic_multi_view_voxelization(scene_triangles, bbox_min, bbox_max, voxel_size):
    # 1. Initialization
    range_vec = bbox_max - bbox_min
    scale = voxel_size / range_vec
    offset = 0.2f
    projection_scale = 1.02f
    
    # Initialize 3D texture buffer
    texture_size = voxel_size.x * voxel_size.y * voxel_size.z * 4
    voxel_texture = [0.0f] * texture_size
    
    # Disable depth testing, culling, multisampling
    # Bind voxel_texture as read-write image buffer
    
    # 2. Camera Setup
    # Create 3 orthographic view-projection matrices for X, Y, Z axes
    # Frustum bounds: 1.02 * range_vec
    # Near: 0.1f, Far: 1.2 * range_vec + offset
    
    view_projects = [
        create_ortho_matrix(axis='X', range_vec=range_vec, offset=offset, scale=projection_scale),
        create_ortho_matrix(axis='Y', range_vec=range_vec, offset=offset, scale=projection_scale),
        create_ortho_matrix(axis='Z', range_vec=range_vec, offset=offset, scale=projection_scale)
    ]
    
    # 3. Rasterization
    for axis_idx in range(3):
        vp_matrix = view_projects[axis_idx]
        
        # Select triangles intersecting the current view/slab
        relevant_triangles = get_intersecting_triangles(scene_triangles, axis_idx, bbox_min, bbox_max)
        
        for tri in relevant_triangles:
            # Determine rasterization direction: axis most parallel to triangle normal
            # This avoids degenerate line segments from 2D linear interpolation
            raster_axis = get_most_parallel_axis(tri.normal)
            
            # Rasterize triangle onto sheet buffer for this axis
            # Use atomic operations for concurrent writes
            fragments = rasterize_triangle_gpu(tri, vp_matrix, raster_axis)
            
            for frag in fragments:
                # Convert fragment coordinates to voxel space
                voxel_coord = transform_to_voxel_space(frag.position, scale, bbox_min)
                
                # Atomic write to 3D texture
                atomic_add(voxel_texture, voxel_coord, frag.color)
                
    # 4. Synthesis (if using Worksheet method)
    # If not using worksheet, skip to Finalization
    if use_worksheet:
        worksheet = create_2d_texture(width=2^W, height=2^H)
        for axis_idx in range(3):
            sheet_buffer = get_sheet_buffer(axis_idx)
            for element in sheet_buffer:
                # Transform to discrete voxel space
                px, py, pz = element.voxel_coords
                # Encode into worksheet
                patch_idx = pz // C
                texel = worksheet[patch_idx][px, py]
                bit_offset = (pz % C) * bits_per_voxel
                set_bits(texel, bit_offset, element.value)
        voxel_texture = worksheet

    # 5. Finalization
    generate_mipmaps(voxel_texture)
    return voxel_texture
```

## Subtopics

### [Shadow Volume Voxelization](5629-shadow-volume-voxelization.md)
Shadow Volume Voxelization is a rasterization-based technique that generates a 3D shadow volume texture by voxelizing scene geometry into a 3D grid, where each voxel stores a bitmask representing which of its 8 constituent sub-voxels are occluded. It builds on [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) by replacing the standard occupancy flag with a 3-bit occlusion mask per coarse voxel, enabling multi-resolution shadow representation through mipmaps. Unlike standard binary voxelization, this method preserves partial occlusion information within each voxel, allowing for smoother shadow transitions and hierarchical shadow testing.

### Slicing-based voxelization
Slicing-based voxelization rasterizes the model the same number of times as the resolution of the volume along the z-direction [S2, unofficial]. This feature (rendering to 3D textures) has not been supported in consumer graphics hardware of PC platform at the time of writing [S2, unofficial]. It is significantly slower than the proposed 2D texture method; for the Blade model at $256^3$, it takes ~5 seconds compared to ~100ms for the proposed method [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V_{proj})$, where $N$ is the number of triangles and $V_{proj}$ is the projection area in pixels. The synthesis step adds overhead proportional to the number of voxels/texels.
*   **Memory Complexity:** $O(V_x \cdot V_y \cdot V_z)$ for the 3D texture. The worksheet variant uses $O(2^W \cdot 2^H)$ which is smaller if $C > 1$.
*   **Measured Performance:** For a $256^3$ resolution, the worksheet method takes ~100ms for the Blade model, whereas slicing-based voxelization takes ~5 seconds [S2, unofficial].
*   **Strengths:** Robust against degenerate cases (parallel surfaces) due to multi-view union semantics; hardware-accelerated rasterization; supports solid voxelization via 3D scan-filling [S2, unofficial].
*   **Limitations:** Requires atomic operations for concurrent writes; the worksheet synthesis step adds complexity; consumer hardware support for 3D texture rendering was limited at the time of the original paper [S2, unofficial].
*   **When to use:** When robust voxelization of complex geometry is required for volume rendering or shadow mapping, and hardware supports 3D textures or efficient 2D-to-3D transcoding.
*   **When not to use:** When memory bandwidth is extremely constrained and $C$ is small, or when the hardware does not support 3D textures or atomic operations on the target platform.

## Background
The method was introduced in "Real-time Voxelization for Complex Models" [S2, unofficial], which proposed representing the resultant volume as 2D textures (worksheet) to leverage efficient 2D rasterization hardware. It was developed to address the limitations of slicing-based voxelization and Layered Depth Image (LDI) extraction, which were either too slow or view-dependent [S2, unofficial]. The implementation details in [S1, unofficial] demonstrate its application in "Voxel Cone Tracing" for real-time global illumination, using a 3D texture approach with atomic accumulation.
