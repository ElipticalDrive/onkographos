# Hybrid Voxelization Classification

Also called: GPView Voxelization

## Overview
Hybrid Voxelization Classification is a GPU-accelerated method for voxelizing 3D CAD models (.obj, .off) using a nested two-level resolution structure [S1, unofficial]. It distinguishes itself from single-resolution rasterization by maintaining a coarse Level1 grid and a finer Level2 grid for voxels containing surface geometry, enabling detailed normal estimation while managing memory [S1, unofficial]. It builds on [Voxel Rasterization](3204-voxel-rasterization.md) by extending the output data structures to support hierarchical classification and normal accumulation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D CAD model geometry (triangles) in .obj or .off format [S1, unofficial].
*   **Output:** Binary .raw files containing contiguous arrays representing the voxelized state [S1, unofficial].

**Data Structures:**
The method uses three primary CUDA device arrays:

1.  **Level1 Voxel Data (`inOutCUDAData`):** `float*` array with one float per Level1 voxel. A value of `2` indicates a Level1 voxel contains surface points [S1, unofficial].
2.  **Level1 Triangle Metadata:** `voxelTriCountCUDAData` (`int*`) stores the count of triangles intersecting each Level1 voxel [S1, unofficial]. `voxelTriIndexCUDAData` (`int*`) stores triangle IDs, indexed as `index * triBuffer + newIndex` [S1, unofficial].
3.  **Level2 Voxel Data (`level2InOutCUDAData`):** `float*` array with one float per Level2 voxel. A value of `1` indicates a Level2 surface voxel [S1, unofficial].
4.  **Level2 Normal Data (`level2NormalCUDAData`):** `float*` array with stride 4 per Level2 voxel. Indices 0-2 store accumulated normal components ($x, y, z$). Index 3 stores a counter initialized to `0`, incremented by `1` for each point [S1, unofficial].

**Algorithm Steps:**
The voxelization process iterates over triangles and maps their vertices/intersections to the voxel grid [S1, unofficial].

1.  **Level1 Classification:** Identify Level1 voxels containing surface points. Set `inOutCUDAData[voxelIndex] = 2`. Atomically increment the triangle count in `voxelTriCountCUDAData`. Store the triangle ID in `voxelTriIndexCUDAData` using the formula `index * triBuffer + newIndex` [S1, unofficial].
2.  **Level2 Normal Accumulation:** For Level2 voxels associated with a Level1 surface voxel, accumulate the surface normal into `level2NormalCUDAData`. Let $N$ be the surface normal vector and $C$ be the counter at index 3. Update components: `level2NormalCUDAData[4*i + 0] += N.x`, `level2NormalCUDAData[4*i + 1] += N.y`, `level2NormalCUDAData[4*i + 2] += N.z`, `level2NormalCUDAData[4*i + 3] += 1`. Set the voxel status to `1` in `level2InOutCUDAData` [S1, unofficial].
3.  **Level2 Fallback Classification:** For Level2 voxels that do not participate in normal accumulation or serve as a fallback, set the status to `1` in `level2InOutCUDAData` [S1, unofficial].

**Pseudocode:**
```python
def atomic_add_float(arr, idx, val):
    old_val = arr[idx]
    arr[idx] += val
    return old_val

def atomic_add_int(arr, idx, val):
    old_val = arr[idx]
    arr[idx] += val
    return old_val

def add_triangle_to_level1(voxel_index, triangle_id, tri_buffer):
    inOutCUDAData[voxel_index] = 2.0
    old_count = atomic_add_int(voxelTriCountCUDAData, voxel_index, 1)
    voxelTriIndexCUDAData[voxel_index * tri_buffer + old_count] = triangle_id

def add_normal_to_level2(voxel_index, normal_x, normal_y, normal_z):
    base_idx = voxel_index * 4
    atomic_add_float(level2NormalCUDAData, base_idx + 0, normal_x)
    atomic_add_float(level2NormalCUDAData, base_idx + 1, normal_y)
    atomic_add_float(level2NormalCUDAData, base_idx + 2, normal_z)
    atomic_add_float(level2NormalCUDAData, base_idx + 3, 1.0)
    level2InOutCUDAData[voxel_index] = 1.0

def add_point_to_level2_fallback(voxel_index):
    level2InOutCUDAData[voxel_index] = 1.0
```

**Parameters:**
*   **EPSILON:** `0.000001` (used in AABB-triangle overlap tests) [S1, unofficial].
*   **Resolution:** Not given in the sources.

**Edge Cases:**
*   **Boundaries:** AABB tests use a fixed epsilon for overlap detection [S1, unofficial].
*   **Atomic Precision:** Atomic operations on floats may have precision limitations depending on the GPU architecture [G].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Proportional to the number of Level1 and Level2 voxels [S1, unofficial]. Level2 data requires 4 floats per voxel (3 for normal, 1 for counter) [S1, unofficial].
*   **Performance:** GPU-accelerated. Specific benchmarks are not provided in the sources.
*   **Strengths:** Hybrid resolution allows for detailed normal estimation in complex areas while keeping coarse data simple [S1, unofficial].
*   **Limitations:** Requires managing two levels of voxel data and atomic operations for normal accumulation [S1, unofficial].
*   **When to use:** When detailed surface normals are required for CAD models and memory efficiency for non-surface areas is important [G].
*   **When not:** For simple occupancy visualization where normals are not needed [G].

## Background
The method is part of the **GPView** framework, developed by Onur R. Bingol, Sambit Ghadai, Aditya Balu, Gavin Young, and Xin Huang from IDEALab at Iowa State University [S1, unofficial]. It was designed for learning localized features in 3D CAD models for manufacturability analysis, specifically for drilled holes [S1, unofficial]. The framework supports Wavefront (.obj) and .off file formats and outputs binary .raw files [S1, unofficial].
