# Surface Voxelization

Also called: GPU surface-voxelization, Triangle Mesh Voxelization

## Overview
Surface Voxelization determines which voxels in a 3D grid are intersected by the surface of a triangle mesh. It operates on individual triangles independently, supporting non-watertight meshes without requiring the input geometry to be closed [S2, unofficial]. Unlike naive pipeline-based voxelization that samples only triangle centers, this method ensures coverage by checking collisions within the triangle's bounding volume, either via brute-force iteration or Breadth-First Search (BFS) [S2, unofficial]. It differs from [Point-Tessellated Voxelization](2290-point-tessellated-voxelization.md) by relying on geometric collision tests rather than tessellation-based point sampling, and from [Sparse Voxel DAG Voxelization via Bounding Box Grid and Plane Projections](1680-sparse-voxel-dag-voxelization-via-bounding-box-grid-and-plan.md) by focusing on explicit surface intersection rather than hierarchical sparse structures.

## How it works
**Inputs and Outputs:**
- **Input:** A triangle mesh (list of triangles), a 3D voxel grid defined by `gridSize` (dimensions) and `gridVoxelSize` (physical size of a voxel), and a parallel execution context (CUDA kernel or CPU thread pool).
- **Output:** A bit-packed voxel table (`vTable1`) marking occupied voxels. Optional metadata (surface count, inside/outside status) if enabled.

**Data Structures:**
- **Voxel Grid:** A 1D array of bitsets. Each bit represents a voxel.
  - Layout: `voxels_[index / kBatchSize]` returns a `uint` word containing `kBatchSize` bits.
  - Indexing: `INDEX(x, y, z)` maps 3D coordinates to a linear index.
- **Triangle:** Defined by three vertices ($a, b, c$).
- **Collision Checker:** A function `Collide(half_unit, voxel_location, triangle)` that returns true if the triangle intersects the voxel.

**Parameters:**
- `numThreads`: Threads per block (CUDA) or workers (CPU). Fixed at 256 in reference implementations [S1, unofficial].
- `kThresholdBfsSurface`: Integer threshold for switching between brute-force and BFS methods [S2, unofficial].
- `kBatchSize`: Number of bits packed into one integer word (implementation detail, typically 32 or 64) [S2, unofficial].

**Steps:**
1. **Initialization:**
   - Validate `gridSize` and `gridVoxelSize`. If either is 0, abort to prevent invalid memory access [S1, unofficial].
   - Initialize the voxel bitset table to all zeros.
   - Launch parallel execution:
     - **CUDA:** Calculate blocks = $\lceil \text{num\_triangles} / \text{numThreads} \rceil$. Launch `voxelGPU` kernel [S1, unofficial].
     - **CPU:** Create a thread pool with `num_thread` workers. Iterate over all triangle IDs, launching `RunSurfaceTask` for each [S2, unofficial].

2. **Per-Triangle Processing (`RunSurfaceTask`):**
   For each triangle $T$:
   a. Compute the local Axis-Aligned Bounding Box (AABB) of the triangle.
   b. Convert AABB min/max to voxel coordinates:
      - $lb = \text{GetVoxel}(T.\text{aabb\_local.min})$
      - $ub = \text{GetVoxel}(T.\text{aabb\_local.max})$
      - Let $lx, ux, ly, uy, lz, uz$ be the integer voxel coordinates of $lb$ and $ub$.
   c. Calculate estimated dimension:
      $$ esti = \min(ux - lx, \min(uy - ly, uz - lz)) $$
   d. **Selection Criterion:**
      - If $esti < kThresholdBfsSurface$: Use **Method 1 (Bounding Box Check)**.
      - Else: Use **Method 2 (BFS Search)**.

3. **Method 1: Bounding Box Check (Brute-Force):**
   Iterate through every voxel $(x, y, z)$ in the range $[lx, ux] \times [ly, uy] \times [lz, uz]$:
   a. Calculate `voxel_index = INDEX(x, y, z)`.
   b. Load the bitset word: `tmp = voxels_[voxel_index / kBatchSize].load()`.
   c. Check if bit is already set: `GETBIT(tmp, voxel_index)`.
      - If set, continue to next voxel.
   d. Check collision: `Collide(half_unit, GetLoc(voxel_index), T)`.
      - If true, set the bit: `SETBIT(voxels_, voxel_index)` and increment count.

4. **Method 2: BFS Search:**
   a. Find an initial voxel intersected by the triangle (e.g., by checking the center or a corner, or by running a quick bounding box check for one voxel). Let this be `start_voxel`.
   b. Initialize queue $Q$ and HashSet $S$.
   c. Push `start_voxel` to $Q$ and insert into $S$.
   d. While $Q$ is not empty:
      i. Pop `top_voxel_index` from $Q$.
      ii. Convert `top_voxel_index` to voxel coordinates `top_voxel`.
      iii. Load bitset: `tmp = voxels_[top_voxel_index / kBatchSize].load()`.
      iv. Check if bit is NOT set OR collision is true:
          - If `GETBIT(tmp, top_voxel_index)` is false OR `Collide(half_unit, GetLoc(top_voxel), T)` is true:
            - If bit is not set, `SETBIT(voxels_, top_voxel_index)`.
            - Iterate 6 neighbors (directions $D_6$):
              - `new_voxel = top_voxel + D_6[i]`
              - If `new_voxel` is within grid bounds $[lb, ub]$ and `new_voxel_index` not in $S$:
                - Insert `new_voxel_index` into $S$.
                - Push `new_voxel_index` to $Q$.

5. **Post-Processing (Optional):**
   - If `WithMeta()` is enabled, count surface voxels.
   - If `Tight()` is enabled, run flood fill to determine inside/outside status [S2, unofficial].
   - Synchronize device/threads to ensure completion [S1, unofficial].

## Subtopics

### [Point-Tessellated Voxelization](2290-point-tessellated-voxelization.md)
Uses hardware tessellation to generate points on triangles, rasterizing them into voxels. Chosen for real-time, gap-free rendering where strict geometric accuracy is less critical than performance.

### [Topological Voxelization with Intersection Targets](2479-topological-voxelization-with-intersection-targets.md)
Tests voxels against predefined geometric targets to guarantee topological properties. Chosen when topological correctness (connectivity/separability) is required regardless of input tessellation density.

## Operating characteristics
- **Time Complexity:** $O(m \cdot c)$, where $m$ is the number of triangles and $c$ is the cost per triangle. $c$ is proportional to the number of voxels in the bounding box for Method 1, or the constant overhead of BFS expansion for Method 2 [S2, unofficial].
- **Memory Complexity:** $O(N)$, where $N$ is the total number of voxels in the grid, stored as a bitset [S2, unofficial].
- **Performance:** Method 1 is lightweight but inefficient if the triangle's volume-to-bounding-box ratio is small (many empty voxels checked) [S2, unofficial]. Method 2 has high constant overhead but avoids checking non-intersecting voxels in the bounding box [S2, unofficial].
- **Strengths:** Supports non-watertight meshes; parallelizable per triangle; no need for complex hierarchical structures [S2, unofficial].
- **Limitations:** Collision testing is expensive; BFS can mark non-surface voxels if expansion logic is not strictly bounded to surface proximity [S2, unofficial].

## Background
Originating from implementations in open-source voxelization projects (e.g., `topskychen/voxelizer`), this method addresses the need for fast, parallel surface voxelization without the constraint of watertight geometry [S2, unofficial]. It is often a precursor to solid voxelization (flood fill) in collision detection and physics simulation pipelines [S2, unofficial].
