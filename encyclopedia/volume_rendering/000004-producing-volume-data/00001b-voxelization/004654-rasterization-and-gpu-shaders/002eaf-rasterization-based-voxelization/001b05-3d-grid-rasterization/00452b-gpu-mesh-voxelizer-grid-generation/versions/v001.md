# GPU Mesh Voxelizer (Grid Generation)
Also called: Compute Shader Voxel Grid Generation, Grid-Snapped Voxelization via Compute Shader

## Overview
This method generates a dense 3D voxel grid by computing the center coordinates of each voxel cell directly on the GPU using a compute shader [S1, unofficial]. It solves the problem of converting a mesh's spatial extent into a fixed-width, height, and depth 3D grid structure, returning a flat array of voxel centers [S1, unofficial]. Unlike rasterization-based approaches that project geometry onto slices, this method calculates grid dimensions from the mesh's bounding box and fills the grid with uniform cells, making it suitable for preprocessing steps where a regular grid topology is required [S1, unofficial]. It builds on [3D Grid Rasterization](903-3d-grid-rasterization.md) by providing the specific grid generation mechanism.

## How it works
**Inputs and Outputs:**
*   **Input:** A mesh (typically accessed via a `MeshCollider` or `MeshFilter`), the mesh's local-space bounding box extents, and a target voxel half-size parameter ($S$) [S1, unofficial].
*   **Output:** A `RWStructuredBuffer<float4>` containing the center coordinates of every voxel in the grid, linearized in 3D order [S1, unofficial].

**Data Structures:**
*   **Voxel Grid Buffer:** A `RWStructuredBuffer<float4>` named `_VoxelGridPoints`. Each element stores a 4D vector $(x, y, z, w)$ where $w=1.0$. The layout is a 1D linearization of the 3D grid: index $I = i_x + W \cdot (i_y + H \cdot i_z)$, where $W, H, D$ are the grid dimensions in x, y, and z respectively [S1, unofficial].
*   **Compute Shader Parameters:**
    *   `_BoundsMin`: `float4` representing the minimum corner of the mesh's local bounding box [S1, unofficial].
    *   `_CellHalfSize`: `float` representing the half-width of a voxel cell ($S$) [S1, unofficial].
    *   `_GridWidth`, `_GridHeight`, `_GridDepth`: `int` values defining the dimensions of the voxel grid [S1, unofficial].
*   **Thread Group:** Defined as `[numthreads(4,4,4)]` [S1, unofficial].

**Steps:**
1.  **Calculate Bounding Box:** Determine the mesh's bounding box in local space. Let $B_{min}$ be the minimum corner and $E$ be the extents [S1, unofficial].
2.  **Determine Grid Dimensions:** Calculate the number of voxels required along each axis by dividing the extents by the cell half-size $S$ and ceiling the result [S1, unofficial]:
    $$W = \lceil E_x / S \rceil, \quad H = \lceil E_y / S \rceil, \quad D = \lceil E_z / S \rceil$$
    [S1, unofficial]
3.  **Allocate Buffer:** Allocate a `ComputeBuffer` of size $W \times H \times D$ with element size $4 \times \text{sizeof(float)}$ [S1, unofficial].
4.  **Dispatch Compute Shader:** Dispatch the `VoxelizeMesh` kernel with thread group counts calculated as $\lceil W / 4 \rceil, \lceil H / 4 \rceil, \lceil D / 4 \rceil$ [S1, unofficial].
5.  **Compute Voxel Centers:** Inside the shader, each thread computes the center of its assigned voxel using the formula below [S1, unofficial].

**Formula:**
The center coordinate $C$ for a voxel at grid index $(i_x, i_y, i_z)$ is:
$$C_x = B_{min,x} + i_x \cdot (2 \cdot S)$$
$$C_y = B_{min,y} + i_y \cdot (2 \cdot S)$$
$$C_z = B_{min,z} + i_z \cdot (2 \cdot S)$$
where $B_{min}$ is the minimum bound of the mesh in local space, $i$ is the thread's global index, and $S$ is the cell half-size [S1, unofficial].

**Pseudocode:**
```python
# Host-side setup (C#-like logic)
def voxelize_mesh(mesh_collider, half_size):
    # 1. Get local bounding box
    bounds = mesh_collider.bounds
    bounds_min = transform.inverse_transform_point(bounds.min)
    extents = bounds.extents
    
    # 2. Calculate grid dimensions
    # Note: extents / half_size gives the number of half-cells. 
    # The source uses extents / half_size directly for voxel count, 
    # implying 'half_size' here acts as the full cell size divisor in the 
    # specific Unity implementation context, or the variable name is misleading.
    # Based on S1: voxelCount = bounds.extents / _halfSize
    # And formula: C = Bmin + id * (2 * S). 
    # If S is half-size, cell size is 2*S. 
    # If extents / half_size = N, then N * (2*S) = extents * 2. 
    # This suggests the source code's 'halfSize' variable might actually 
    # represent the full cell size, or the bounding box logic assumes 
    # centering. However, we must follow the source exactly.
    
    voxel_count_x = math.ceil(extents.x / half_size)
    voxel_count_y = math.ceil(extents.y / half_size)
    voxel_count_z = math.ceil(extents.z / half_size)
    
    width = voxel_count_x
    height = voxel_count_y
    depth = voxel_count_z
    
    # 3. Allocate buffer
    buffer_size = width * height * depth
    voxel_buffer = ComputeBuffer(buffer_size, 16) # 4 floats * 4 bytes
    
    # 4. Dispatch
    group_size = 4
    dispatch_x = math.ceil(width / group_size)
    dispatch_y = math.ceil(height / group_size)
    dispatch_z = math.ceil(depth / group_size)
    
    compute_shader.dispatch(voxelize_kernel, dispatch_x, dispatch_y, dispatch_z)
    return voxel_buffer

# Compute Shader Kernel
[numthreads(4, 4, 4)]
void VoxelizeMesh(uint3 id : SV_DispatchThreadID) {
    // Boundary check to prevent out-of-bounds writes
    if (id.x >= _GridWidth || id.y >= _GridHeight || id.z >= _GridDepth) {
        return;
    }
    
    float cell_size = _CellHalfSize * 2.0;
    
    // Linear index calculation
    uint index = id.x + _GridWidth * (id.y + _GridHeight * id.z);
    
    // Compute center
    float4 center = float4(
        _BoundsMin.x + id.x * cell_size,
        _BoundsMin.y + id.y * cell_size,
        _BoundsMin.z + id.z * cell_size,
        1.0
    );
    
    _VoxelGridPoints[index] = center;
}
```

**Parameters:**
*   `_halfSize` (or `_CellHalfSize`): The half-width of each voxel cell. Typical value: 0.05f [S1, unofficial].
*   `_GridWidth`, `_GridHeight`, `_GridDepth`: Integer dimensions of the output grid [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Checks:** A boundary check (`id.x >= _GridWidth`, etc.) is required in the compute shader to prevent out-of-bounds writes if the grid dimensions are not exact multiples of the thread group size (4) [S1, unofficial].
*   **Precision:** Floating-point precision in the bounding box calculation and grid indexing should be sufficient for typical scene scales.
*   **Empty Meshes:** If the mesh has zero extents, the grid dimensions will be zero, and no buffer allocation or dispatch is needed.

## Operating characteristics
*   **Time Complexity:** $O(W \cdot H \cdot D)$, where $W, H, D$ are the grid dimensions. The complexity is linear with the number of voxels.
*   **Memory Complexity:** $O(W \cdot H \cdot D)$ for storing the voxel centers. Each voxel stores 4 floats (16 bytes) [S1, unofficial].
*   **Measured Performance:** Performance depends on the grid resolution and GPU compute throughput. For a typical voxel size of 0.05f, grid sizes can become large quickly, leading to high memory usage.
*   **Strengths:** Simple implementation, parallelizable, no rasterization overhead, suitable for dense grids.
*   **Limitations:** Memory-intensive for large bounding boxes or small voxel sizes. Does not handle geometry inside the bounding box; it fills the entire volume.
*   **When to Use:** When a dense, regular grid is required for subsequent processing (e.g., marching cubes, density fields) and the bounding box is not excessively large.
*   **When Not to Use:** For sparse scenes or when memory is constrained, as it allocates space for the entire bounding box volume.

## Background
This method originates from an unofficial Unity tutorial series by bzgeb, demonstrating a GPU-based mesh voxelizer for Unity [S1, unofficial]. It leverages Unity's Compute Shader infrastructure to offload the grid generation process from the CPU to the GPU, allowing for real-time or near-real-time voxelization of meshes. The approach is part of a broader effort to create efficient voxelization pipelines for real-time rendering applications.
