# Voxel Indexing and Bit Compression

Also called: Binary Voxel Bit Packing, Bit-packed Voxel Array

## Overview
Voxel Indexing and Bit Compression maps 3D voxel coordinates to a 1D linear index and packs the resulting occupancy data into a compact bit-array, typically stored as an array of 64-bit integers. It solves the problem of efficiently storing sparse or dense binary voxel grids by reducing memory overhead and enabling parallel write operations via atomic bit-setting. It differs from [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md) by storing the raw bit-stream directly rather than compressing runs of identical values, and from [RLE Index Computation](4339-rle-index-computation.md) by focusing on the storage format of the index itself rather than generating a lookup structure for RLE offsets.

## How it works
**Inputs:** 3D voxel grid dimensions ($size_x, size_y, size_z$); a set of occupied voxel coordinates $(x, y, z)$.
**Outputs:** A bit-packed array representing the occupancy status of the voxel grid.

**Data Structures:**
1.  **Linear Index:** A 1D integer representing the position of a voxel in the flattened grid.
2.  **Bit-Packed Array:** An array of 64-bit unsigned integers (`uint64_t` or `unsigned long long`) where each bit corresponds to one voxel.

**Steps:**
1.  **Calculate Linear Index:** For each occupied voxel at coordinates $(x, y, z)$, compute its 1D index $I$ using row-major ordering:
    $$ I = x \cdot size_y \cdot size_z + y \cdot size_z + z $$
    where $size_x, size_y, size_z$ are the dimensions of the voxel grid [S1, unofficial].
2.  **Initialize Storage:** Allocate an array of 64-bit unsigned integers large enough to hold $I_{max} + 1$ bits. The size of the array in elements is $\lceil (size_x \cdot size_y \cdot size_z) / 64 \rceil$.
3.  **Set Occupancy Bit:** For each occupied voxel, set the bit at position $I$ to 1. In a parallel implementation, this is done using atomic operations to ensure thread safety when multiple threads write to the same array concurrently [S1, unofficial].
    *   Determine the array index: $arr\_idx = I / 64$.
    *   Determine the bit offset: $bit\_offset = I \pmod{64}$.
    *   Perform atomic OR: `atomic_or(&array[arr_idx], 1 << bit_offset)`.
4.  **Handle Unoccupied Voxels:** Voxels not explicitly set remain 0, indicating they are empty [S1, unofficial].

**Parameters:**
*   **Bit Width:** 64 bits per array element is standard for efficient alignment and atomic operations [S1, unofficial].
*   **Grid Dimensions:** Must fit within the addressable range of the linear index.

**Edge Cases and Pitfalls:**
*   **Precision:** The linear index must not overflow the integer type used for calculation. For large grids, 64-bit integers for the index calculation may be required even if the storage is bit-packed.
*   **Boundaries:** Coordinates must be strictly within $[0, size_x-1] \times [0, size_y-1] \times [0, size_z-1]$. Out-of-bounds access causes undefined behavior or memory corruption.
*   **Atomicity:** Without atomic operations, concurrent writes from multiple threads (e.g., in a GPU or multi-threaded CPU kernel) can result in lost updates or race conditions [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def pack_voxels(voxel_coords, grid_size):
    """
    Pack a list of occupied voxel coordinates into a bit-compressed array.
    
    Args:
        voxel_coords: List of tuples (x, y, z) representing occupied voxels.
        grid_size: Tuple (size_x, size_y, size_z) defining the grid dimensions.
        
    Returns:
        numpy array of uint64 representing the bit-packed voxel grid.
    """
    size_x, size_y, size_z = grid_size
    total_voxels = size_x * size_y * size_z
    num_uint64 = (total_voxels + 63) // 64
    
    # Initialize bit-packed array with zeros
    packed_array = np.zeros(num_uint64, dtype=np.uint64)
    
    for (x, y, z) in voxel_coords:
        # Calculate 1D linear index
        index = x * size_y * size_z + y * size_z + z
        
        # Calculate array index and bit offset
        arr_idx = index // 64
        bit_offset = index % 64
        
        # Set the bit (simulating atomic OR for single-threaded execution)
        # In a real parallel implementation, this would use atomic operations
        packed_array[arr_idx] |= (1 << bit_offset)
        
    return packed_array
```

## Subtopics

### Detail Coefficient Representation
This variant reduces memory usage to 4 bytes per voxel by distributing 32 bits across X, Y, and Z coordinates in a 12+10+10 split, supporting volumes up to $4096 \times 1024 \times 1024$ [S2, unofficial]. It packs coordinates into two `GL_SHORT` values and unpacks them in a vertex program. For GPUs lacking bit shift operators, unpacking is emulated using multiplication by a fraction (via `floor` function) and subtraction [S2, unofficial]. This approach trades computation for memory bandwidth efficiency, which is beneficial for large volumes [S2, unofficial].

### O-Voxel Packing and Serialization
This variant extends bit packing to include dual vertices and intersection flags for efficient serialization to `.vxz` format [S3, unofficial]. Dual vertices are packed by computing `dual_vertices = (dual_vertices * RES - voxel_indices)`, clamping to $[0, 1]$, and scaling to `uint8` [S3, unofficial]. Intersection flags (3 boolean channels) are packed into a single `uint8` where Bit 0 corresponds to channel 0, Bit 1 to channel 1, and Bit 2 to channel 2 [S3, unofficial]. This method is used in the O-Voxel library for GPU-accelerated volume rendering [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(n)$ where $n$ is the number of voxels in the bounding box, as each voxel requires a constant-time index calculation and bit set operation [S1, unofficial].
*   **Memory Complexity:** $O(V/8)$ bytes where $V$ is the total number of voxels in the grid, as each voxel is stored as a single bit [S1, unofficial].
*   **Performance:** Bit packing significantly reduces memory footprint compared to byte-per-voxel storage. Parallel atomic writes can achieve high throughput on multi-core CPUs and GPUs [S1, unofficial].
*   **Strengths:** Extremely compact storage for binary occupancy data; simple indexing scheme; efficient for sparse data if combined with sparse access patterns.
*   **Limitations:** Not suitable for storing per-voxel attributes (e.g., density, color) without additional structures; random access to specific voxels requires bit manipulation; not compressed for runs of zeros/ones like RLE.
*   **When to Use:** When memory bandwidth is a bottleneck and only binary occupancy is needed; when parallel voxelization is required.
*   **When Not to Use:** When per-voxel attributes are needed; when the grid is extremely sparse and RLE or sparse octrees are more efficient.

## Background
Voxel indexing and bit compression is a fundamental technique in voxel-based rendering and geometry processing. It is widely used in GPU-accelerated volume rendering and mesh voxelization pipelines. The method is described in various implementations, including the `topskychen/voxelizer` repository [S1, unofficial], which uses atomic operations for parallel voxelization. The technique is also referenced in research on multiresolution MIP rendering [S2, unofficial] and in the O-Voxel library for GPU-based volume rendering [S3, unofficial].
