# NRRD-like Volume I/O
Also called: NRRD-like Format I/O

## Overview
Exports and imports volumes in a simple NRRD-like format consisting of two header lines followed by raw binary payload [S1, unofficial]. It differs from [Binvox File Parsing](2862-binvox-file-parsing.md) by storing full 32-bit values rather than binary flags, and from [IMS File Format & Image Stack Class](3322-ims-file-format-image-stack-class.md) by using a single contiguous file rather than a directory of image stacks. It provides a minimal, non-standardized alternative to [VTK Legacy ASCII File Writing](6698-vtk-legacy-ascii-file-writing.md) and [VRDF File Format / VRDF Loader](6906-vrdf-file-format-vrdf-loader.md) by omitting metadata and using binary data for compactness.

## How it works
**Inputs:** A volume data structure containing dimensions ($dim_x, dim_y, dim_z$) and a contiguous array of `uint32_t` values ($m\_data$).
**Outputs:** A file with a specific text header and raw binary body.

**Data Structure Layout:**
The file consists of:
1.  Line 1: Three space-separated integers representing width ($dim_x$), height ($dim_y$), and depth ($dim_z$).
2.  Line 2: The literal string `uint32`.
3.  Body: Raw bytes of the volume data.

**Numbered Steps:**

1.  **Export:**
    1.  Open the output file for writing in binary mode.
    2.  Write the dimensions as a string: `std::to_string(dim_x) + " " + std::to_string(dim_y) + " " + std::to_string(dim_z) + "\n"`.
    3.  Write the type string: `"uint32\n"`.
    4.  Calculate the total byte size: $size = dim_x \times dim_y \times dim_z \times 4$.
    5.  Write the raw bytes of $m\_data$ to the file.

2.  **Import:**
    1.  Open the input file for reading in binary mode.
    2.  Read the first line and parse three integers into $dim_x, dim_y, dim_z$.
    3.  Read the second line and verify it equals `"uint32"`. If not, raise an error.
    4.  Calculate the voxel count: $N = dim_x \times dim_y \times dim_z$.
    5.  Resize the destination data array to hold $N$ `uint32_t` values.
    6.  Read $N \times 4$ bytes from the file into the data array.
    7.  Verify the read operation was successful (i.e., the number of bytes read matches the expected size).

**Pseudocode:**

```python
import struct

def export_volume(filepath, dim_x, dim_y, dim_z, data):
    """
    Exports volume data to NRRD-like format.
    data: list or array of uint32_t values, length dim_x * dim_y * dim_z.
    """
    with open(filepath, 'wb') as f:
        # Write header line 1: dimensions
        header1 = f"{dim_x} {dim_y} {dim_z}\n"
        f.write(header1.encode('ascii'))
        
        # Write header line 2: type
        header2 = "uint32\n"
        f.write(header2.encode('ascii'))
        
        # Write raw binary payload
        # Assuming data is a list of integers, convert to bytes
        # Each uint32 is 4 bytes, little-endian is standard for this context unless specified otherwise
        # The source uses reinterpret_cast, implying native endianness or raw memory dump.
        # For portability, we assume the source implies raw memory layout.
        # In Python, we use struct to ensure consistent binary output if needed, 
        # but 'raw bytes' implies direct memory view.
        # Using struct.pack for explicit uint32 LE/BE or native. 
        # The C++ code uses reinterpret_cast<char*> which is native endian.
        # We will write raw bytes assuming the input data is already in the correct byte order.
        byte_data = bytes(data) # Assuming data is already bytes or convertible
        f.write(byte_data)

def import_volume(filepath):
    """
    Imports volume data from NRRD-like format.
    Returns: (dim_x, dim_y, dim_z, data_list)
    """
    with open(filepath, 'rb') as f:
        # Read header line 1
        line1 = f.readline().decode('ascii').strip()
        parts = line1.split()
        if len(parts) != 3:
            raise ValueError("Invalid header line 1")
        dim_x = int(parts[0])
        dim_y = int(parts[1])
        dim_z = int(parts[2])
        
        # Read header line 2
        line2 = f.readline().decode('ascii').strip()
        if line2 != "uint32":
            raise ValueError(f"Expected 'uint32', got '{line2}'")
        
        # Calculate size
        voxel_count = dim_x * dim_y * dim_z
        byte_count = voxel_count * 4
        
        # Read raw data
        raw_data = f.read(byte_count)
        if len(raw_data) != byte_count:
            raise ValueError("File truncated or read error")
        
        # Convert bytes to list of uint32
        # Using native endianness to match C++ reinterpret_cast behavior
        # struct.unpack with '<I' for little-endian or '>I' for big-endian or 'I' for native
        # The C++ code does not specify endianness conversion, so we assume native or consistent storage.
        # For a robust implementation, one might need to know the endianness.
        # Here we assume native for simplicity as per the source's direct memory copy.
        data = list(struct.unpack(f'{voxel_count}I', raw_data))
        
        return (dim_x, dim_y, dim_z, data)
```

**Parameters:**
-   Data type: Fixed to `uint32_t` (4 bytes per voxel).
-   Endianness: Not explicitly specified in the source, but `reinterpret_cast` implies native machine endianness [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Endianness:** If files are exchanged between systems with different endianness, the data will be corrupted unless a standard endianness (e.g., little-endian) is enforced [G].
-   **Data Type Verification:** The import step must strictly check for the string `uint32` to prevent misinterpreting other data types [S1, unofficial].
-   **Truncation:** The import step must verify that the exact number of bytes were read to handle truncated files [S1, unofficial].

## Subtopics

## Operating characteristics
-   **Time Complexity:** Export is $O(N)$ where $N$ is the number of voxels, dominated by the write operation. Import is $O(N)$, dominated by the read operation.
-   **Memory Complexity:** $O(N)$ for storing the volume data. The header is negligible.
-   **Performance:** Very fast due to minimal parsing overhead and raw binary storage. No compression is applied.
-   **Strengths:** Simplicity, small file size (compared to ASCII), fast I/O.
-   **Limitations:** No metadata support (no spacing, direction, etc.), no compression, fixed data type (`uint32`), potential endianness issues.
-   **When to use:** When a lightweight, fast, and simple binary volume format is needed for internal tools or specific pipelines where metadata is not required.
-   **When not to use:** When interoperability with standard tools (which expect full NRRD metadata) is required, or when compression is needed.

## Background
This format is an informal, simplified variant of the NRRD (Nearly Raw Raster Data) format, used in the `compressed-segmentation-volumes` project [S1, unofficial]. It strips down the full NRRD specification to just dimensions and data type, followed by raw binary data, to facilitate fast I/O for voxel-based volume rendering pipelines.
