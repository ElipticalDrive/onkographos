# Voxel File I/O

Also called: Output Format Handling, Voxel Export

## Overview
Voxel File I/O is the method for serializing and deserializing voxel grid data to and from disk storage formats. It solves the problem of persisting volumetric representations generated by voxelization or optimization pipelines for later use in rendering engines or analysis tools. Unlike [Voxel File I/O (binvox/rawvox)](1698-voxel-file-i-o-binvox-rawvox.md), which focuses on specific legacy binary and raw byte formats, this method encompasses a broader range of structured formats including ASCII-based scientific formats (VTK, PLY, CSV), specialized scientific image formats (PFM, NRRD-like), and custom binary schemas.

## How it works
The method supports multiple output schemas. The implementation selects a format and executes the corresponding serialization or deserialization routine.

### Inputs and Outputs
- **Inputs**: A voxel grid (typically a contiguous array or sparse structure), metadata (dimensions, bounding box, scalar field names), and a target file path.
- **Outputs**: A file on disk conforming to the chosen format specification.

### Data Structures
The core data structure is the voxel grid, represented as a contiguous array of values. For formats requiring geometric topology (e.g., VTK), the grid is decomposed into vertices and cells.

### Steps and Formulas

#### 1. CSV Export [S1, unofficial]
Exports voxel data as comma-separated values.
1. Write header line: `"x,y,z,phase"`.
2. Iterate through all voxels $(x, y, z)$ with associated phase value $v$.
3. Write row: `"{x},{y},{z},{v}"`.

#### 2. PLY Export [S1, unofficial]
Exports voxel centers as ASCII points.
1. Write header:
   ```
   ply
   format ascii 1.0
   element vertex {count}
   property float x
   property float y
   property float z
   end_header
   ```
2. For each voxel center $(x, y, z)$, write: `"{x} {y} {z}"`.

#### 3. VTK Legacy ASCII Export [S6, unofficial]
Exports voxel data as an `UNSTRUCTURED_GRID` with hexahedral cells. This format supports multiple scalar fields.
1. **Header**:
   - Write `# vtk DataFile Version 2.0`.
   - Write title string.
   - Write `ASCII`.
   - Write `DATASET UNSTRUCTURED_GRID`.
2. **POINTS**:
   - Calculate `point_count = cell_count * 8`.
   - Write `POINTS {point_count} float`.
   - For each cell $i$ with bounds $[x_{min}, y_{min}, z_{min}]$ to $[x_{max}, y_{max}, z_{max}]$, compute 8 vertices using local index $k \in [0, 7]$:
     $$
     \begin{aligned}
     x &= x_{min} + (k \& 1) \cdot (x_{max} - x_{min}) \\
     y &= y_{min} + ((k \gg 1) \& 1) \cdot (y_{max} - y_{min}) \\
     z &= z_{min} + ((k \gg 2) \& 1) \cdot (z_{max} - z_{min})
     \end{aligned}
     $$
   - Write coordinates formatted as `"{:.17g}"`.
3. **CELLS**:
   - Write `CELLS {cell_count} {cell_count * 9}`.
   - For each cell $i$, write `8 {start} {start+1} ... {start+7}` where `start = i * 8`.
4. **CELL_TYPES**:
   - Write `CELL_TYPES {cell_count}`.
   - Write `11` for each cell (VTK_HEXAHEDRON).
5. **CELL_DATA**:
   - Write `CELL_DATA {cell_count}`.
   - For each scalar field (e.g., `void_ratio`, `particle_count`):
     - Write `SCALARS {name} {type} 1`.
     - Write `LOOKUP_TABLE default`.
     - Write values for each cell.

#### 4. NRRD-like Volume I/O [S3, unofficial]
A simplified binary format consisting of a two-line header and raw payload.
1. **Export**:
   - Write line 1: `"{dim_x} {dim_y} {dim_z}\n"`.
   - Write line 2: `"uint32\n"`.
   - Write raw bytes of the data array: `fout.write(reinterpret_cast<char *>(m_data.data()), m_data.size() * sizeof(uint32_t))`.
2. **Import**:
   - Read line 1. Parse space-separated integers for `dim_x`, `dim_y`, `dim_z`.
   - Read line 2. Verify it equals `"uint32"`.
   - Calculate `voxel_count = dim_x * dim_y * dim_z`.
   - Resize `m_data` to `voxel_count`.
   - Read raw bytes: `fin.read(reinterpret_cast<char *>(m_data.data()), static_cast<long>(voxel_count * sizeof(uint32_t)))`.
   - Check read success.

#### 5. Binary Volume File Format [S5, unofficial]
A custom binary format for volumes generated from image slices.
1. **Parameters**:
   - `BBOX_SIZE_X`: Fixed width of the bounding box in X dimension, value `5.0`.
2. **Layout**:
   - Bytes 0-11: Three `int` (4 bytes each) for `grid_dim[0]`, `grid_dim[1]`, `grid_dim[2]`.
   - Bytes 12-23: Three `float` (4 bytes each) for `bbox_size[0]`, `bbox_size[1]`, `bbox_size[2]`.
   - Remaining bytes: Voxel values as `float` (4 bytes each), row-major order (x varying fastest, then y, then z).
3. **Steps**:
   - Read slices from input directory, sorted by filename.
   - Determine grid dimensions: `w, h` from first image shape, `len(slices_files)` for depth.
   - Calculate bounding box size:
     $$
     \begin{aligned}
     bbox\_size[0] &= BBOX\_SIZE\_X \\
     bbox\_size[1] &= (BBOX\_SIZE\_X / grid\_dim[0]) \cdot (vol\_size[1] / vol\_size[0]) \cdot grid\_dim[1] \\
     bbox\_size[2] &= (BBOX\_SIZE\_X / grid\_dim[0]) \cdot (vol\_size[2] / vol\_size[0]) \cdot grid\_dim[2]
     \end{aligned}
     $$
   - Write grid dimensions as integers.
   - Write bounding box floats.
   - Write voxel values.

#### 6. PFM File Parsing [S2, unofficial]
Reads Portable FloatMap images, handling endianness and color format.
1. Read header to determine color format (`PF` for grayscale, `Pf` for RGB) and dimensions.
2. Parse endianness marker (`2.1` for big-endian, `2.1` with specific handling for little-endian depending on implementation details in source).
3. Read pixel data.

#### 7. ArrayMesh Byte Reader [S4, unofficial]
Narrows a listed -1 to 255 in the ArrayMesh byte reader, as Godot does. This ensures consistent byte representation for color indices.

#### 8. BIN Export [S1, unofficial]
Uses bincode serialization for a compact binary format. The specific layout depends on the bincode implementation but generally serializes the struct fields sequentially.

### Pseudocode

```python
def write_vtk_legacy_ascii(output_path, voxel_data):
    """
    Exports voxel data to a legacy VTK ASCII UNSTRUCTURED_GRID file.
    voxel_data: dict containing 'box_min', 'box_max', 'void_ratio', 
                'void_ratio_smoothed', 'particle_count', 'solid_volume', 
                'measurement_volume', 'cell_count'.
    """
    box_min = voxel_data["box_min"]
    box_max = voxel_data["box_max"]
    raw_values = voxel_data["void_ratio"]
    smoothed_values = voxel_data["void_ratio_smoothed"]
    particle_counts = voxel_data["particle_count"]
    solid_volumes = voxel_data["solid_volume"]
    measurement_volumes = voxel_data["measurement_volume"]
    cell_count = len(raw_values)
    point_count = cell_count * 8

    with open(output_path, 'w') as f:
        # Header
        f.write("# vtk DataFile Version 2.0\n")
        f.write("Voxel Data\n")
        f.write("ASCII\n")
        f.write("DATASET UNSTRUCTURED_GRID\n")

        # Points
        f.write(f"POINTS {point_count} float\n")
        for i in range(cell_count):
            xmin, ymin, zmin = box_min
            xmax, ymax, zmax = box_max
            for k in range(8):
                x = xmin + ((k & 1) * (xmax - xmin))
                y = ymin + (((k >> 1) & 1) * (ymax - ymin))
                z = zmin + (((k >> 2) & 1) * (zmax - zmin))
                f.write(f"{x:.17g} {y:.17g} {z:.17g}\n")

        # Cells
        f.write(f"CELLS {cell_count} {cell_count * 9}\n")
        for i in range(cell_count):
            start = i * 8
            f.write(f"8 {start} {start+1} {start+2} {start+3} {start+4} {start+5} {start+6} {start+7}\n")

        # Cell Types
        f.write(f"CELL_TYPES {cell_count}\n")
        f.write("11\n" * cell_count)

        # Cell Data
        f.write(f"CELL_DATA {cell_count}\n")
        
        # Scalar Fields
        write_scalar_field(f, "void_ratio", raw_values, "double")
        write_scalar_field(f, "void_ratio_smoothed", smoothed_values, "double")
        write_scalar_field(f, "particle_count", particle_counts, "int")
        write_scalar_field(f, "solid_volume", solid_volumes, "double")
        write_scalar_field(f, "measurement_volume", measurement_volumes, "double")

def write_scalar_field(f, name, values, vtype):
    f.write(f"SCALARS {name} {vtype} 1\n")
    f.write("LOOKUP_TABLE default\n")
    for val in values:
        f.write(f"{val}\n")

def write_nrrd_like(data, dims, output_path):
    """
    Exports data in a simple NRRD-like format.
    data: list of uint32
    dims: tuple (dim_x, dim_y, dim_z)
    """
    with open(output_path, 'wb') as f:
        f.write(f"{dims[0]} {dims[1]} {dims[2]}\n".encode())
        f.write(b"uint32\n")
        f.write(bytes(data))

def read_nrrd_like(input_path):
    """
    Imports data from a simple NRRD-like format.
    """
    with open(input_path, 'rb') as f:
        line1 = f.readline().decode().strip()
        line2 = f.readline().decode().strip()
        
        if line2 != "uint32":
            raise ValueError("Expected 'uint32' in second line")
        
        dims = list(map(int, line1.split()))
        voxel_count = dims[0] * dims[1] * dims[2]
        
        data_bytes = f.read(voxel_count * 4)
        if len(data_bytes) != voxel_count * 4:
            raise ValueError("Read failed or incomplete")
            
        # Convert bytes to list of uint32
        import struct
        data = list(struct.unpack(f"{voxel_count}I", data_bytes))
        return data, dims
```

## Subtopics

### [Binvox File Parsing](2862-binvox-file-parsing.md)
Binvox File Parsing is the method for importing the binary voxel (binvox) file format into a contiguous array or a Sparse Voxel Octree (SVO) structure. It solves the problem of converting a legacy, run-length encoded (RLE) voxel representation into a format suitable for modern ray-casting or rasterization engines. Unlike raw voxel formats that store every voxel explicitly, binvox uses a compact binary RLE scheme, requiring specific handling to decompress the data correctly.

### [IMS File Format & Image Stack Class](3322-ims-file-format-image-stack-class.md)
The IMS file format and `ims_base` class provide a mechanism for persisting and managing 3D image stacks (volumes) with typed pixel storage and extensible metadata segments. It solves the problem of storing volumetric data where pixel types are fixed at compile time via templates and metadata is stored as typed binary segments. It differs from generic binary voxel formats by embedding a rigid 16-byte header, supporting memory-mapped loading on Windows, and using a chunked write strategy to handle large volumes without buffer overflow.

### [VRDF File Format / VRDF Loader](6906-vrdf-file-format-vrdf-loader.md)
The VRDF (Volume Rendering Data Format) is a binary file format designed for storing 3D voxel grids alongside associated metadata and transfer functions. It solves the problem of interoperability between medical imaging pipelines and volume rendering engines by packaging geometry, intensity data, and rendering parameters into a single self-describing file. Unlike [Binvox File Parsing](2862-binvox-file-parsing.md), which is limited to binary occupancy grids, VRDF supports continuous floating-point data, multi-channel interleaved data (e.g., label and weight), and embedded JSON metadata. It builds on [Voxel File I/O](2786-voxel-file-i-o.md) by providing a structured schema for complex volume data rather than simple raw bytes.

### PFM File Parsing
Reads a PFM (Portable FloatMap) image file, handling endianness and color format [S2, unofficial]. Steps include reading the header to determine color (PF/Pf) and dimensions, then parsing the pixel data accordingly [S2, unofficial].

### NRRD-like Volume I/O
Exports and imports volumes in a simple NRRD-like format consisting of two header lines followed by raw binary payload [S3, unofficial]. Export writes `dim_x`, `dim_y`, `dim_z` separated by spaces and a newline, then 'uint32' and a newline, then raw bytes. Import reads the dimensions, verifies the type, and reads the raw bytes into the data array [S3, unofficial].

### ArrayMesh Byte Reader
Narrows a listed -1 to 255 in the ArrayMesh byte reader, as Godot does (variant_parser.cpp:650) [S4, unofficial].

### Binary Volume File Format
A binary file format for storing volume data generated from image slices, containing grid dimensions, bounding box size, and voxel values [S5, unofficial]. It reads slices from an input directory, determines grid dimensions and bounding box size, and writes the data in a specific binary layout [S5, unofficial].

### VTK Legacy ASCII File Writing
Exports voxel data to a legacy VTK ASCII UNSTRUCTURED_GRID file with hexahedral cells and multiple scalar fields [S6, unofficial]. It writes the header, points, cells, cell types, and cell data for fields like void_ratio and particle_count [S6, unofficial].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of voxels $N$ for most formats ($O(N)$), as each voxel is written/read once. VTK ASCII has higher constant factors due to string formatting.
- **Memory Complexity**: Linear with respect to $N$ for the data buffer. VTK ASCII may require temporary buffers for coordinate generation.
- **Performance**: Binary formats (BIN, NRRD-like, Binary Volume) are significantly faster than ASCII formats (CSV, PLY, VTK ASCII) due to lack of parsing/serialization overhead.
- **Strengths**: Supports diverse data types (binary, ASCII, float, int). Flexible metadata handling.
- **Limitations**: ASCII formats are verbose and slow. Custom binary formats (Binary Volume) lack standardization and interoperability.
- **When to use**: Use binary formats for large datasets and performance-critical applications. Use ASCII formats for debugging, human readability, or interoperability with standard scientific tools (VTK, PLY).

## Background
Voxel file I/O methods have evolved alongside volume rendering techniques. Early formats like raw bytes were simple but lacked metadata. Scientific formats like VTK and PLY gained popularity for their structured approach. Custom formats like the Binary Volume File Format and NRRD-like formats emerged for specific research needs, balancing simplicity with necessary metadata. The binvox format remains a legacy standard for binary voxel data.
