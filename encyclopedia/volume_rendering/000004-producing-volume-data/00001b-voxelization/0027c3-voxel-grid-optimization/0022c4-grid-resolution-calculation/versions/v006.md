# Grid Resolution Calculation

Also called: proportional grid, voxel count

## Overview
Grid Resolution Calculation determines the discrete dimensions $(N_x, N_y, N_z)$ of a uniform 3D voxel grid based on the spatial extent of the scene and a target density parameter. It solves the problem of mapping continuous world coordinates to a fixed-size integer array without manual dimension specification. It differs from [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) by operating on the grid's structural definition rather than its content, and from [Adaptive Voxel Spacing](#adaptive-voxel-spacing) by maintaining uniform cell sizes across all dimensions [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- `size`: A 3D vector $(S_x, S_y, S_z)$ representing the dimensions of the scene's bounding box in world units.
- `voxels_on_y`: An integer scalar representing the desired number of voxels along the Y-axis ($N_y$).

**Outputs:**
- `grid_dims`: A 3D integer vector $(N_x, N_y, N_z)$ representing the number of voxels in each dimension.

**Data Structures:**
- `size`: `float3` (x, y, z components).
- `grid_dims`: `uint3` (x, y, z components).

**Steps:**
1. Set the Y-dimension resolution directly to the input target:
   $$N_y = \text{voxels\_on\_y}$$
2. Calculate the X-dimension resolution by scaling $N_y$ by the aspect ratio of the bounding box's X and Y dimensions, then rounding up to the nearest integer:
   $$N_x = \left\lceil N_y \times \frac{S_x}{S_y} \right\rceil$$
3. Calculate the Z-dimension resolution by scaling $N_y$ by the aspect ratio of the bounding box's Z and Y dimensions, then rounding up to the nearest integer:
   $$N_z = \left\lceil N_y \times \frac{S_z}{S_y} \right\rceil$$

**Pseudocode:**
```python
def calculate_grid_resolution(size: Vector3, voxels_on_y: int) -> Vector3:
    """
    Calculate grid dimensions based on bounding box size and target Y-resolution.
    
    Args:
        size: Bounding box dimensions (Sx, Sy, Sz).
        voxels_on_y: Target number of voxels along the Y-axis.
        
    Returns:
        Grid dimensions (Nx, Ny, Nz).
    """
    # Guard against division by zero
    if size.y == 0:
        raise ValueError("Bounding box Y-dimension cannot be zero.")
        
    Ny = voxels_on_y
    Nx = ceil(Ny * (size.x / size.y))
    Nz = ceil(Ny * (size.z / size.y))
    
    return Vector3(Nx, Ny, Nz)
```

**Parameters:**
- `voxels_on_y`: Typical values depend on the desired visual fidelity and memory budget. Not given in the sources.

**Edge Cases:**
- If $S_y = 0$, the calculation is undefined. A guard must check for this [G].
- If $S_x$ or $S_z$ are zero, the resulting $N_x$ or $N_z$ will be 0, potentially creating a degenerate grid.

## Subtopics

### Adaptive Voxel Spacing
This variant adjusts voxel grid resolution dynamically using a quality parameter to balance performance and detail [S2, unofficial]. It differs from the standard proportional method by allowing real-time adjustment of voxel size based on user input or scene complexity, rather than a static calculation based on bounding box aspect ratios [S2, unofficial].

**Definition:**
Adjusts voxel grid resolution dynamically using a quality parameter to balance performance and detail [S2, unofficial].

**Steps:**
1. Define a quality parameter $Q$ ranging from $0.0$ to $3.0$, adjustable by user input (e.g., key presses) [S2, unofficial].
2. Calculate the voxel size in X and Y directions:
   $$\Delta x = \Delta y = \frac{2.0 \times vw_{asp}}{vw_{xdim}} \times (1.0 + Q \times 4.0)$$
   Where $vw_{asp}$ is the viewport aspect ratio and $vw_{xdim}$ is the viewport width in pixels [S2, unofficial].
3. Calculate the voxel size in Z direction:
   $$\Delta z = \frac{2.0 \times vw_{aspz}}{200.0} \times (1.0 + Q)$$
   Where $vw_{aspz}$ is a Z-axis aspect parameter [S2, unofficial].

**When to choose:**
Use when interactive adjustment of detail level is required, such as in real-time visualization tools [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ arithmetic operations.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Simple to implement; ensures uniform voxel size across the grid; preserves aspect ratio of the bounding box.
- **Limitations:** Does not account for non-uniform distribution of primitives; may result in wasted voxels in empty regions if the bounding box is loose.
- **When to use:** When a uniform grid is required and the bounding box is known and tight.
- **When not:** When the scene has highly anisotropic features or when memory constraints require non-uniform spacing.

## Background
The proportional grid calculation is a standard technique in voxel-based rendering and ray tracing, often used in conjunction with [Voxelization](12-voxelization.md) to define the sampling grid. The specific implementation cited in [S1, unofficial] is part of a voxelizer project for real-time rendering. The adaptive variant in [S2, unofficial] is used in the context of generating holographic fractals, where dynamic resolution adjustment aids in visualizing complex 3D structures.
