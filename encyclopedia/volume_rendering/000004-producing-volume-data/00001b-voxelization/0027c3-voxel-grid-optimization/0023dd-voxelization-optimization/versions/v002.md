# Voxelization Optimization


## Overview
Voxelization Optimization refers to a collection of techniques designed to reduce the computational cost and memory bandwidth requirements of generating voxel data from 3D geometry, particularly in real-time applications. It addresses the bottleneck of high draw call counts and redundant geometric transformations during the rasterization of meshes into voxel grids. It is distinguished from its siblings by focusing on the *generation pipeline* efficiency (e.g., stream output, instancing, LOD selection) rather than post-generation data compression (like RLE) or structural simplification (like smoothing).

## How it works
The method optimizes the GPU-based rasterization process used to convert triangle meshes into voxel occupancy or density fields.

### Inputs and Outputs
- **Input:** 3D mesh geometry (vertices, indices), voxel grid parameters (resolution, bounds), and transformation matrices (model, view, projection).
- **Output:** A voxel grid (3D texture or buffer) containing occupancy values or density data.

### Data Structures
- **Voxel Grid:** A 3D array or texture where each cell represents a voxel. The specific layout (dense vs. sparse) depends on the downstream consumer, but the optimization applies to the generation phase regardless of the final storage format.
- **Stream Output Buffer:** A GPU buffer used to cache transformed vertex data.
- **Instance Data:** Per-slice transformation matrices or offsets used in instanced rendering.

### Steps
1. **Mesh Simplification (LOD Selection):**
   For obstacles or static geometry, use a low-level-of-detail (LOD) mesh for voxelization. This reduces the number of triangles processed per slice, minimizing fill rate and vertex processing costs [S1, unofficial].

2. **Stream Output for Deforming Meshes:**
   When voxelizing deforming meshes (e.g., skinned characters), use GPU stream output to cache the transformed vertices.
   - Render the mesh once to a stream output buffer, applying the skinning/transform matrices.
   - Reuse this cached vertex buffer for all subsequent voxel slices, avoiding the recomputation of vertex transformations for each slice [S1, unofficial].

3. **Instanced Slicing:**
   Instead of issuing a separate draw call for each voxel slice (plane), use instanced rendering.
   - Define a single draw call that renders the mesh geometry.
   - Use instance IDs to offset or transform the geometry for each slice.
   - This reduces CPU-GPU overhead and driver state changes [S1, unofficial].

4. **Static Object Caching:**
   Do not re-voxelize static objects unless necessary.
   - Precompute the voxel data for static geometry.
   - Apply inverse transformations when accessing the data if the object undergoes rigid body motion (translation/rotation) [S1, unofficial].
   - Note: Dynamic lights intersecting static objects may force re-voxelization or dynamic updates if the lighting affects the voxel data (e.g., voxel cone tracing) [S2, unofficial].

5. **Heightmap Optimization (Min/Max Altitude):**
   For voxel grids with vertical structure (e.g., terrain), maintain per-column minimum and maximum occupied voxel heights to skip empty or fully occupied columns during meshing or traversal.
   - **Data Structures:**
     - `minAltitude`: Byte array of size $ChunkSize^2$ (e.g., 1024 bytes for $32 \times 32$ chunks), storing the lowest occupied Y index per XZ column.
     - `maxAltitude`: Byte array of size $ChunkSize^2$, storing the highest occupied Y index per XZ column.
   - **Initialization:** Initialize `minAltitude` to $ChunkSize$ (indicating empty) for all columns [S3, unofficial].
   - **Update on Voxel Addition:** When a voxel at $(i, j, k)$ is added (index > 0), update `minAltitude[i][k]` and `maxAltitude[i][k]` to reflect the new occupied column bounds [S3, unofficial].
   - **Update on Voxel Removal:** When a voxel at $(i, j, k)$ is removed (index == 0), update `minAltitude[i][k]` and `maxAltitude[i][k]` to reflect the cleared column bounds [S3, unofficial].

### Pseudocode
```python
def optimize_voxelization(mesh, voxel_grid, is_deforming=False, is_static=False):
    """
    Optimizes the voxelization process based on mesh type and properties.
    """
    if is_static:
        # Precompute voxel data for static objects
        if not voxel_grid.has_data():
            voxel_grid = voxelize_mesh(mesh)
            voxel_grid.cache()
        return voxel_grid

    if is_deforming:
        # Use stream output to cache transformed vertices
        # 1. Transform vertices once and store in stream output buffer
        transformed_vertices = stream_output_transform(mesh)
        
        # 2. Use instancing to draw all slices in a single draw call
        #    Instance ID specifies the target slice
        voxel_grid = instanced_voxel_slice_render(transformed_vertices, voxel_grid)
        return voxel_grid

    # General optimization: Use LOD mesh
    lod_mesh = get_low_detail_mesh(mesh)
    voxel_grid = voxelize_mesh(lod_mesh)
    return voxel_grid

def update_heightmaps(min_altitude, max_altitude, chunk_size, x, z, y, operation):
    """
    Updates min/max altitude heightmaps for a specific column.
    operation: 'add' or 'remove'
    """
    # Initialize if needed
    if min_altitude[x][z] == chunk_size:
        min_altitude[x][z] = y
        max_altitude[x][z] = y
        return

    if operation == 'add':
        min_altitude[x][z] = min(min_altitude[x][z], y)
        max_altitude[x][z] = max(max_altitude[x][z], y)
    elif operation == 'remove':
        # Recalculate min/max for the column if necessary
        # This requires scanning the column or maintaining a count
        # For simplicity, we assume a full scan or count-based update
        min_altitude[x][z] = calculate_min_y_for_column(x, z)
        max_altitude[x][z] = calculate_max_y_for_column(x, z)
```

### Parameters
- **LOD Level:** The level of detail for obstacle meshes. Lower LOD reduces performance cost [S1, unofficial].
- **Chunk Size:** For heightmap optimization, typically 32x32, resulting in 1024-byte arrays for min/max altitude [S3, unofficial].

### Edge Cases and Pitfalls
- **Dynamic Lights:** Dynamic lights intersecting static objects may force re-voxelization, negating the benefits of static caching [S2, unofficial].
- **Precision:** Stream output and instancing require careful management of vertex attributes and instance data to avoid precision loss or alignment issues.
- **Empty Columns:** Heightmap optimization assumes vertical continuity; gaps in columns must be handled correctly during removal updates.

## Subtopics

### [32nd Bit Avoidance Modification](3351-32nd-bit-avoidance-modification.md)
The 32nd Bit Avoidance Modification is a set of adjustments to GPU-based solid voxelization and density computation pipelines to prevent conflicts with the reserved 32nd bit of standard 32-bit integer or floating-point formats. It ensures that the highest bit (bit 31) remains available for other purposes, such as flags or sign bits, by restricting voxel data to lower bits. This method is distinct from general sparse voxelization techniques by focusing specifically on bit-packing constraints within dense or semi-dense voxel grids.

### [Sparse Voxelization with Oracle and Parallel Scan](3687-sparse-voxelization-with-oracle-and-parallel-scan.md)
Sparse Voxelization with Oracle and Parallel Scan is a real-time, high-resolution technique for reconstructing 3D surface models from image-based inputs (calibrated RGB camera streams) using a coarse-to-fine voxel hierarchy. It solves the problem of on-the-fly surface reconstruction by iteratively refining a sparse list of voxels, using an oracle kernel to cull empty space and a parallel prefix sum scan to compact the list, ensuring that only relevant voxels are subdivided. Unlike bottom-up approaches or methods designed for static models, this method is top-down and optimized for interactive rates (e.g., >30 fps at 1024^3 resolution) by leveraging GPU parallelism for both computation and rendering.

### [Greedy Voxel Mesh Optimization](3979-greedy-voxel-mesh-optimization.md)
Greedy Voxel Mesh Optimization is a greedy algorithm that optimizes voxel mesh generation for 2D tile grids (e.g., Minecraft-like games) by merging adjacent identical tiles into larger rectangular quads to reduce draw calls. It differs from its siblings, [32nd Bit Avoidance Modification](3351-32nd-bit-avoidance-modification.md) and [Sparse Voxelization with Oracle and Parallel Scan](3687-sparse-voxelization-with-oracle-and-parallel-scan.md), by explicitly constructing maximal rectangular regions of uniform tile properties through iterative expansion, rather than relying on bit-packing tricks or parallel scan-based sparse structures.

### Stream Output for Voxelization
A technique to optimize voxelization of deforming meshes by caching transformed vertices, avoiding recomputation for each slice [S1, unofficial]. It uses GPU stream output to cache an entire buffer of transformed vertices during the voxelization of deforming meshes (e.g., skinned characters) [S1, unofficial].

### Min/Max Altitude Heightmap Optimization
Stores per-column minimum and maximum occupied voxel heights to skip empty or fully occupied columns during meshing [S3, unofficial]. On voxel addition (index > 0), `OnVoxelAdded(i, j, k)` updates the heightmaps to reflect the new occupied column. On voxel removal (index == 0), `OnVoxelRemoved(i, j, k)` updates the heightmaps to reflect the cleared column. The `minAltitude` array is a byte array of size $ChunkSize^2$ (1024 bytes for $ChunkSize=32$), storing the lowest occupied Y index per XZ column. The `maxAltitude` array is similarly sized, storing the highest occupied Y index. Initialization sets `minAltitude` to $ChunkSize$ for all columns, indicating initially empty columns [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of triangles and voxel slices. Instancing reduces CPU overhead from $O(S)$ to $O(1)$ draw calls, where $S$ is the number of slices. Stream output reduces vertex transformation cost from $O(S \cdot V)$ to $O(V)$, where $V$ is the number of vertices.
- **Memory Complexity:** Stream output requires additional GPU memory for the vertex buffer. Heightmap optimization adds $O(W \cdot D)$ memory for min/max altitude arrays, where $W$ and $D$ are the width and depth of the voxel grid.
- **Measured Performance:** Techniques are used in games like *Rise of Tomb Raider* (voxel AO) and *The Tomorrow Children* (on consoles) [S2, unofficial]. Sparse Voxel Octrees can further reduce memory requirements [S2, unofficial]. Voxel cascades can improve framerates through clever updating frequency changes [S2, unofficial].
- **Strengths:** Significant reduction in CPU-GPU overhead and vertex processing time for dynamic scenes. Effective for real-time applications.
- **Limitations:** Requires GPU support for stream output and instancing. Static object caching may be invalidated by dynamic lighting. Heightmap optimization is limited to vertical structures.

## Background
Voxelization optimization techniques have been developed to address the high computational cost of real-time voxel-based rendering and simulation. The use of stream output and instancing for voxelization was highlighted in *GPU Gems 3* [S1, unofficial]. The application of these techniques in commercial games like *Rise of Tomb Raider* and *The Tomorrow Children* demonstrates their practical viability [S2, unofficial]. Heightmap optimization for voxel meshing has been explored in open-source projects like *vercidium-patreon/meshing* [S3, unofficial].
