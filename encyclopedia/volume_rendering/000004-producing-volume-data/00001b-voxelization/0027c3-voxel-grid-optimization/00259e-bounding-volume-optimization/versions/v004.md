# Bounding Volume Optimization

Also called: Adaptive Voxel-Array-Größe, BV Optimisation, Bounding Volume Optimisation, Bounding-Volume-Optimierung, SDF Bounding Volume Culling, Volumen-Größenanpassung

## Overview
Bounding Volume Optimization reduces the computational cost of volume rendering by eliminating empty regions and skipping expensive evaluations for objects that do not contribute to the final image [S1, unofficial][S2]. It achieves this by either resizing the voxel grid to fit the data or using bounding volumes to cull Signed Distance Field (SDF) evaluations [S1, unofficial][S2]. Unlike [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) which modifies values, or [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md) which compresses storage, this method focuses on spatial culling and grid dimensionality reduction to minimize false positives and redundant calculations [S1, unofficial][S2].

## How it works
**Inputs:**
1.  A 3D voxel grid or a set of geometric primitives with associated SDFs.
2.  The bounding box (AABB) of the active data or primitives.

**Outputs:**
1.  A resized voxel grid with dimensions matching the active data extent.
2.  A culling mask or traversal logic that skips evaluation for out-of-bounds or non-contributing volumes.

**Data Structures:**
*   **Voxel Grid:** A 3D array of size $W \times H \times D$. In the optimized case, dimensions are reduced from a fixed power-of-two (e.g., $512^3$) to the minimal bounding box of the content (e.g., $512 \times 321 \times 512$) [S1, unofficial].
*   **Bounding Volume:** An Axis-Aligned Bounding Box (AABB) defined by minimum $(x_{min}, y_{min}, z_{min})$ and maximum $(x_{max}, y_{max}, z_{max})$ coordinates [S1, unofficial][S2].

**Steps:**
1.  **Determine Extent:** Calculate the minimum and maximum coordinates of all active voxels or primitives in the scene [S1, unofficial][S2].
2.  **Resize Grid (Voxel Approach):** If using a voxel grid, allocate a new texture/array with dimensions equal to the calculated extent. This eliminates empty space that would otherwise cause false positives during traversal [S1, unofficial].
3.  **Define Bounding Volumes (Primitive Approach):** For each primitive contributing to the SDF, compute its AABB [S2].
4.  **Cull During Traversal:**
    *   For raymarching, check if the current ray segment or sample point lies within the bounding volume of a primitive [S2].
    *   If the point is outside the bounding volume, skip the evaluation of that primitive's SDF [S2].
    *   If using a resized grid, clamp ray coordinates to the new grid boundaries to prevent out-of-bounds memory access and unnecessary sampling [S1, unofficial].
5.  **Evaluate SDF:** Only evaluate the SDF for primitives where the ray intersects the bounding volume [S2].

**Pseudocode:**
```python
def render_with_bounding_volume_optimization(ray_origin, ray_direction, grid, primitives):
    # Step 1: Determine grid bounds if resizing is applied
    if use_grid_resizing:
        grid_min = grid.get_min_bounds()
        grid_max = grid.get_max_bounds()
        # Clamp ray to grid bounds to avoid false positives and out-of-bounds access
        t_min, t_max = ray_intersect_aabb(ray_origin, ray_direction, grid_min, grid_max)
        if t_max < 0:
            return background_color
        
    # Step 2: Iterate along ray
    t = t_min
    while t < t_max:
        point = ray_origin + ray_direction * t
        
        # Step 3: Bounding Volume Culling for Primitives
        min_dist = infinity
        for primitive in primitives:
            # Check if point is inside primitive's AABB
            if is_inside_aabb(point, primitive.bounding_box):
                # Evaluate SDF only if inside bounding volume
                dist = primitive.evaluate_sdf(point)
                if dist < min_dist:
                    min_dist = dist
        
        # If no primitive was close enough, or using grid-only rendering
        if min_dist == infinity:
            if use_grid_resizing:
                # Sample from resized grid
                dist = grid.sample(point)
            else:
                # No data, break or continue
                break
        
        # Step 4: Advance ray
        t += min_dist
        
        # Safety break for infinite loops
        if t > max_ray_length:
            break
            
    return compute_color(point, min_dist)
```

**Parameters:**
*   **Grid Resolution:** Should match the data extent. Example: $512 \times 321 \times 512$ instead of $512^3$ [S1, unofficial].
*   **Bounding Box Tightness:** Tighter bounds yield better culling but require more precise calculation [S2].

**Edge Cases:**
*   **Precision:** Floating-point errors in AABB intersection tests may cause false negatives (skipping valid samples) or false positives (evaluating unnecessary primitives) [S1, unofficial][S2].
*   **Degenerate Input:** Empty scenes or single-voxel objects may result in degenerate bounding boxes (zero volume), requiring special handling to avoid division by zero in intersection tests [G].

## Subtopics

### Grid Resizing
Adapting the voxel array dimensions to the data extent. Best for static scenes with known bounds. Reduces memory bandwidth [S1, unofficial].

### Primitive Culling
Using AABBs to skip SDF evaluations. Best for scenes with many expensive primitives. Reduces compute load [S2].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$ where $N$ is the number of samples and $M$ is the number of primitives. Culling reduces $M$ effectively to only visible primitives [S2].
*   **Memory Complexity:** $O(W \cdot H \cdot D)$ for the grid. Resizing reduces memory usage proportional to the reduction in volume [S1, unofficial].
*   **Performance:** In a scene with 20 expensive primitives at 720p, enabling BV optimization reduced average frame duration from 41 ms (24 fps) to 21 ms (48 fps) [S2].
*   **Strengths:** Eliminates false positives from empty space [S1, unofficial]; localizes expensive computations to areas with complex geometry [S2]; separates game world and entities for physics [S1, unofficial].
*   **Limitations:** AABBs do not allow visually appealing lighting on voxel faces (hard lighting) [S1, unofficial]; requires pre-calculation of bounds [S2].
*   **Hardware:** Modern GPUs are MIMD, allowing distribution of expensive threads after cheaper parts finish early, which complements BV optimization [S2].

## Background
Originating from voxel rendering and raymarching research, this method addresses the inefficiency of fixed-size grids and uniform SDF evaluation [S1, unofficial][S2]. It was notably discussed in the context of raycasting-based voxel rendering for game worlds and CUDA-based raymarching [S1, unofficial][S2]. The technique allows for the separation of game worlds and entities, treating dense voxel models as bounding boxes for rigid bodies [S1, unofficial].
