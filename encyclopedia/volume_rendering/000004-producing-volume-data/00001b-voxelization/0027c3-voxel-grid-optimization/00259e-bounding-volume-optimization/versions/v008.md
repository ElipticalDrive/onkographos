# Bounding Volume Optimization

Also called: Adaptive Voxel-Array-Größe, BV Optimisation, Bounding Volume Optimisation, Bounding-Volume-Optimierung, SDF Bounding Volume Culling, Volumen-Größenanpassung

## Overview
Bounding Volume Optimization reduces the computational cost of voxel-based rendering by eliminating evaluations in empty space or for primitives that do not contribute to the final image [S1, unofficial][S2]. It achieves this by adapting the 3D voxel array dimensions to the actual data extent or by using bounding volumes to skip Signed Distance Field (SDF) evaluations for objects outside the view or minimal distance field [S1, unofficial][S2]. Unlike [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) which improves visual quality, or [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md) which reduces memory footprint, this method specifically targets traversal and evaluation overhead by spatial culling [S1, unofficial][S2].

## How it works
**Inputs:**
*   A scene containing $N$ primitives or voxel entities.
*   A target rendering resolution (e.g., width $W$, height $H$).
*   A base voxel grid configuration (e.g., nominal dimensions $D_x, D_y, D_z$).

**Outputs:**
*   An optimized voxel grid with reduced dimensions matching the data extent.
*   A set of bounding volumes (e.g., AABBs) associated with primitives to enable early-out culling during raymarching.

**Data Structures:**
1.  **Optimized Voxel Grid:** A 3D array with dimensions $W_{vox} \times H_{vox} \times D_{vox}$, where $W_{vox} \le D_x$, $H_{vox} \le D_y$, and $D_{vox} \le D_z$. The array stores occupancy or material data only for the active region.
2.  **Bounding Volume (AABB):** For each primitive $i$, an Axis-Aligned Bounding Box defined by minimum corner $\mathbf{min}_i = (x_{min}, y_{min}, z_{min})$ and maximum corner $\mathbf{max}_i = (x_{max}, y_{max}, z_{max})$.

**Steps:**
1.  **Determine Data Extent:** Analyze the scene to find the minimum and maximum coordinates occupied by all relevant primitives or voxel models. Let $X_{min}, X_{max}, Y_{min}, Y_{max}, Z_{min}, Z_{max}$ be these bounds.
2.  **Calculate Optimized Dimensions:** Compute the new grid dimensions based on the extent and the chosen voxel resolution $\Delta v$:
    $$ W_{vox} = \lceil \frac{X_{max} - X_{min}}{\Delta v} \rceil $$
    $$ H_{vox} = \lceil \frac{Y_{max} - Y_{min}}{\Delta v} \rceil $$
    $$ D_{vox} = \lceil \frac{Z_{max} - Z_{min}}{\Delta v} \rceil $$
    [G] The grid origin is typically shifted to $(X_{min}, Y_{min}, Z_{min})$ to align the first voxel with the data start.
3.  **Construct Bounding Volumes:** For each primitive $i$, compute its AABB $\mathbf{B}_i$ in world space.
4.  **Ray-Volume Intersection Test:** During raymarching, for each ray, check if it intersects the global optimized bounding box of the scene or individual primitive bounding boxes before evaluating the SDF.
    *   If a ray does not intersect the global bounding box, skip rendering for that ray.
    *   If a ray intersects the global box but not a specific primitive's $\mathbf{B}_i$, skip the SDF evaluation for that primitive.
5.  **Evaluate SDF:** Only evaluate the SDF map function for primitives whose bounding volumes are intersected by the ray and whose contribution is potentially minimal (closest to the ray origin).

**Pseudocode:**
```python
def bounding_volume_optimization(scene_primitives, voxel_resolution):
    """
    Calculates optimized grid dimensions and bounding volumes.
    """
    # Step 1: Determine global extent
    global_min = [inf, inf, inf]
    global_max = [-inf, -inf, -inf]
    
    primitive_bboxes = []
    
    for prim in scene_primitives:
        # Compute AABB for primitive
        bbox = compute_aabb(prim)
        primitive_bboxes.append(bbox)
        
        # Update global bounds
        for axis in range(3):
            if bbox.min[axis] < global_min[axis]:
                global_min[axis] = bbox.min[axis]
            if bbox.max[axis] > global_max[axis]:
                global_max[axis] = bbox.max[axis]
                
    # Step 2: Calculate optimized dimensions
    width_vox = ceil((global_max[0] - global_min[0]) / voxel_resolution)
    height_vox = ceil((global_max[1] - global_min[1]) / voxel_resolution)
    depth_vox = ceil((global_max[2] - global_min[2]) / voxel_resolution)
    
    return {
        "dimensions": (width_vox, height_vox, depth_vox),
        "origin": global_min,
        "bboxes": primitive_bboxes
    }

def raymarch_with_bv_optimization(ray_origin, ray_direction, scene_data):
    """
    Renders a single ray using bounding volume optimization.
    """
    # Check against global bounding box
    if not intersects_aabb(ray_origin, ray_direction, scene_data.global_bbox):
        return background_color
        
    distance = 0.0
    max_steps = 1000
    
    for step in range(max_steps):
        current_pos = ray_origin + ray_direction * distance
        
        # Find closest primitive bounding box intersected by ray
        closest_prim_idx = -1
        min_dist_to_bbox = inf
        
        for i, bbox in enumerate(scene_data.bboxes):
            if intersects_aabb(ray_origin, ray_direction, bbox):
                # Calculate distance to the entry point of the bbox
                t_entry = ray_aabb_intersection_t(ray_origin, ray_direction, bbox)
                if t_entry < min_dist_to_bbox:
                    min_dist_to_bbox = t_entry
                    closest_prim_idx = i
                    
        # If no primitive bbox is hit, we are in empty space
        if closest_prim_idx == -1:
            break
            
        # Evaluate SDF only for the closest primitive
        # Note: In a full implementation, one would check if the ray is 
        # actually inside the bbox or close enough to warrant evaluation.
        # For simplicity, we assume the bbox culling has filtered out 
        # non-contributing primitives.
        
        sdf_val = evaluate_sdf(current_pos, scene_primitives[closest_prim_idx])
        
        if sdf_val < epsilon:
            return shade(current_pos, ray_direction)
            
        distance += sdf_val
        
    return background_color
```

**Parameters:**
*   **Voxel Resolution ($\Delta v$):** Determines the granularity of the grid. Typical values depend on scene scale, e.g., 0.1 units per voxel.
*   **Epsilon:** Small threshold for SDF intersection.

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point errors in AABB intersection tests can lead to false positives or missed culling opportunities [S1, unofficial].
*   **Degenerate Input:** Primitives with zero volume (planes or lines) may have degenerate AABBs. These require special handling or expansion to ensure valid intersection tests [S1, unofficial].
*   **Dynamic Scenes:** If primitives move frequently, bounding volumes must be updated every frame, which adds overhead. Static scenes benefit most [S1, unofficial].

## Operating characteristics
**Time Complexity:**
*   Preprocessing: $O(N)$ to compute bounding boxes and extents, where $N$ is the number of primitives.
*   Per-Frame: $O(R \cdot P)$ in the worst case without culling, where $R$ is the number of rays and $P$ is the number of primitives. With BV optimization, the average case is significantly lower as many primitives are skipped.

**Memory Complexity:**
*   $O(W_{vox} \cdot H_{vox} \cdot D_{vox})$ for the voxel grid, which is reduced compared to a fixed-size grid.
*   $O(N)$ for storing bounding volumes.

**Measured Performance:**
*   In a scene with 20 expensive primitives at 720p, enabling BV optimization reduced average frame duration from 41 ms (24 fps) to 21 ms (48 fps) [S2].
*   Without optimization, computation cost is uniform across the frame; with optimization, expensive computations are localized to areas with complex geometry [S2].

**Strengths and Limitations:**
*   **Strengths:** Significantly reduces false positives during traversal [S1, unofficial]. Separates game world and entities, allowing dense voxel models to act as bounding boxes for rigid bodies [S1, unofficial]. Adapts to the actual data extent, saving memory and bandwidth [S1, unofficial].
*   **Limitations:** AABBs do not allow visually appealing lighting on voxel faces, leading to hard, physically implausible shading [S1, unofficial]. Requires additional logic for dynamic scenes.

**When to Use:**
*   Use when the scene has significant empty space or when primitives are sparse within a large bounding volume.
*   Use when the cost of SDF evaluation is high relative to the cost of bounding volume intersection tests.

**When Not to Use:**
*   Use when the scene is uniformly dense, as the overhead of BV checks may outweigh the benefits.
*   Use when dynamic updates to bounding volumes are too costly for the frame budget.

## Background
Bounding Volume Optimization originated in the context of raymarching and voxel rendering to address the high computational cost of evaluating Signed Distance Fields (SDFs) for every primitive at every sample point [S2]. It was developed to minimize the cost of the map function by skipping evaluations for objects that do not contribute to the minimal distance field [S2]. The technique is particularly relevant in real-time rendering where frame rates are critical [S2]. It builds on the principles of spatial culling and data compression shared by the [Voxel Grid Optimization](4131-voxel-grid-optimization.md) family [S1, unofficial][S2].
