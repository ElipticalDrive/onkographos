# Voxel Carving

Also called: Carve Voxelization

## Overview
Voxel Carving is a technique that creates a dense, filled voxel grid representing the volume of a shape by intersecting the viewing frustums of multiple cameras, unlike surface-only voxelization methods [S1]. It solves the problem of reconstructing a volumetric representation from 2D depth maps or silhouettes by iteratively "carving" away empty space from a bounding volume [S1]. It differs from [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md) and [Parametric Surface Voxelization](6032-parametric-surface-voxelization.md) by producing an explicit, dense grid rather than a boundary representation, and from [Multi-Plane Projection Voxelization and Aggregation](12100-multi-plane-projection-voxelization-and-aggregation.md) by directly modifying the voxel occupancy state based on visibility constraints rather than aggregating projected features.

## How it works
**Inputs:**
*   A set of camera poses (extrinsic matrices) and intrinsic parameters.
*   Depth maps or silhouette masks for each camera pose.
*   Grid definition: `width`, `height`, `depth` (in voxels), `voxel_size`, and `origin` (bounding box corner) [S1].

**Outputs:**
*   A dense voxel grid where each voxel is marked as occupied or empty [S1].

**Data Structures:**
*   **Voxel Grid:** A 3D array of booleans (or integers for multi-resolution variants) indexed by $(i, j, k)$. The physical coordinate $P$ of a voxel center is calculated from its index relative to the `origin` and `voxel_size` [S1].

**Steps:**
1.  **Initialize Grid:** Create a dense voxel grid with dimensions $W \times H \times D$. Initialize all voxels as "occupied" (potential surface) [S1].
2.  **Iterate Cameras:** For each camera $c$ in the set of views:
    a.  **Compute Projection:** Determine the camera's extrinsic matrix $T_c$ and intrinsic matrix $K_c$ [S1].
    b.  **Render/Obtain Data:** Acquire the depth map $D_c$ (float values representing distance from camera center) or silhouette mask $M_c$ (binary) for the scene from camera $c$ [S1].
    c.  **Carve:**
        *   **Depth Map Method:** For each pixel $(u, v)$ in the depth map with value $d$:
            i.  Back-project the pixel to 3D space using $K_c^{-1}$ and $T_c$ to get the ray origin and direction.
            ii. Calculate the 3D point $P_{surf}$ at distance $d$ along the ray.
            iii. Identify all voxels intersected by the ray segment from the camera center to $P_{surf}$.
            iv. Mark these voxels as "occupied" [S1].
            v.  *Note:* Some implementations (e.g., binvox `-dc`) stop carving 1 voxel before the intersection point to prevent overhang artifacts [S2].
        *   **Silhouette Method:** For each pixel $(u, v)$ in the silhouette mask where $M_c(u,v) = 1$:
            i.  Cast a ray from the camera center through $(u, v)$.
            ii. Mark all voxels along this ray (up to a maximum depth or infinity) as "occupied" [S1].
3.  **Finalize:** The resulting grid contains only voxels that were marked occupied by *all* cameras (intersection of all viewing frustums) [S1].

**Pseudocode:**
```python
def voxel_carving(depth_maps, silhouettes, camera_params, grid_config):
    """
    depth_maps: list of 2D arrays (float), depth in meters
    silhouettes: list of 2D arrays (bool), True if in silhouette
    camera_params: list of dicts with 'intrinsic' (3x3), 'extrinsic' (4x4)
    grid_config: dict with 'voxel_size', 'origin' (3,), 'dimensions' (3,)
    """
    # Initialize grid: True means occupied (potential surface)
    # Dimensions are (depth, height, width) to match typical array indexing
    grid = np.ones(grid_config['dimensions'], dtype=bool)
    
    voxel_size = grid_config['voxel_size']
    origin = np.array(grid_config['origin'])
    
    for i, (depth_map, silhouettes, params) in enumerate(zip(depth_maps, silhouettes, camera_params)):
        K = params['intrinsic']
        T = params['extrinsic']
        T_inv = np.linalg.inv(T)
        
        # Get image dimensions
        H, W = depth_map.shape
        
        # Precompute ray directions for all pixels to optimize
        # Pixel coordinates (u, v)
        u, v = np.meshgrid(np.arange(W), np.arange(H))
        # Homogeneous pixel coordinates
        pixel_homo = np.stack([u, v, np.ones_like(u)], axis=-1).astype(np.float32)
        
        # Transform to camera space direction
        # K_inv * [u, v, 1] gives direction in camera frame
        K_inv = np.linalg.inv(K)
        directions_cam = np.einsum('ij, ...j -> ...i', K_inv, pixel_homo)
        
        # Normalize to get unit vectors
        norms = np.linalg.norm(directions_cam, axis=-1, keepdims=True)
        directions_cam = directions_cam / norms
        
        # Transform direction to world space
        # The rotation part of T_inv transforms camera frame to world frame
        R_world_from_cam = T_inv[:3, :3]
        directions_world = np.einsum('ij, ...j -> ...i', R_world_from_cam, directions_cam)
        
        # Camera center in world space
        cam_center_world = T_inv[:3, 3]
        
        # Process Depth Map Carving
        if depth_map is not None:
            # For each pixel, carve along the ray up to the depth value
            # We iterate over pixels to handle variable depth
            for y in range(H):
                for x in range(W):
                    d = depth_map[y, x]
                    if d <= 0:
                        continue # Invalid depth
                    
                    ray_origin = cam_center_world
                    ray_dir = directions_world[y, x]
                    
                    # Target point on surface
                    target_point = ray_origin + d * ray_dir
                    
                    # Determine voxel indices for the segment
                    # Start voxel (camera center)
                    start_voxel = world_to_voxel(ray_origin, origin, voxel_size)
                    # End voxel (surface)
                    end_voxel = world_to_voxel(target_point, origin, voxel_size)
                    
                    # Mark voxels along the ray as occupied
                    # Using a simple line drawing algorithm (Bresenham-like) for voxels
                    occupied_voxels = get_voxels_on_ray(start_voxel, end_voxel)
                    
                    for vx, vy, vz in occupied_voxels:
                        if is_inside_grid(vx, vy, vz, grid_config['dimensions']):
                            grid[vz, vy, vx] = True

        # Process Silhouette Carving (Optional, usually mutually exclusive with depth in simple implementations)
        if silhouettes is not None:
            # Carve along all rays where silhouette is True
            # This is computationally expensive if done per-pixel; often optimized on GPU
            # Here we show the logical step
            for y in range(H):
                for x in range(W):
                    if silhouettes[y, x]:
                        ray_origin = cam_center_world
                        ray_dir = directions_world[y, x]
                        
                        # Carve to a maximum depth or infinity
                        # For simplicity, assume a max depth or infinite ray
                        # In practice, this might be limited by the grid bounds
                        max_dist = np.linalg.norm(grid_config['dimensions'] * voxel_size)
                        target_point = ray_origin + max_dist * ray_dir
                        
                        start_voxel = world_to_voxel(ray_origin, origin, voxel_size)
                        end_voxel = world_to_voxel(target_point, origin, voxel_size)
                        
                        occupied_voxels = get_voxels_on_ray(start_voxel, end_voxel)
                        
                        for vx, vy, vz in occupied_voxels:
                            if is_inside_grid(vx, vy, vz, grid_config['dimensions']):
                                grid[vz, vy, vx] = True
                                
    return grid

def world_to_voxel(point, origin, voxel_size):
    """Convert world coordinate to voxel index."""
    # point - origin gives offset from origin
    # divide by voxel_size gives index
    # floor to get the voxel containing the point
    return np.floor((point - origin) / voxel_size).astype(int)

def get_voxels_on_ray(start_voxel, end_voxel):
    """Return list of voxel indices along the line from start to end."""
    # Implementation of 3D Bresenham or DDA algorithm
    # Not given in sources, standard graphics primitive [G]
    voxels = []
    x0, y0, z0 = start_voxel
    x1, y1, z1 = end_voxel
    
    dx = abs(x1 - x0)
    dy = abs(y1 - y0)
    dz = abs(z1 - z0)
    
    xs = 1 if x1 > x0 else -1
    ys = 1 if y1 > y0 else -1
    zs = 1 if z1 > z0 else -1
    
    # Driving axis is the one with the largest difference
    if dx >= dy and dx >= dz:
        p1 = 2 * dy - dx
        p2 = 2 * dz - dx
        while x0 != x1:
            voxels.append((x0, y0, z0))
            x0 += xs
            if p1 >= 0:
                y0 += ys
                p1 -= 2 * dx
            if p2 >= 0:
                z0 += zs
                p2 -= 2 * dx
            p1 += 2 * dy
            p2 += 2 * dz
    elif dy >= dx and dy >= dz:
        p1 = 2 * dx - dy
        p2 = 2 * dz - dy
        while y0 != y1:
            voxels.append((x0, y0, z0))
            y0 += ys
            if p1 >= 0:
                x0 += xs
                p1 -= 2 * dy
            if p2 >= 0:
                z0 += zs
                p2 -= 2 * dy
            p1 += 2 * dx
            p2 += 2 * dz
    else:
        p1 = 2 * dy - dz
        p2 = 2 * dx - dz
        while z0 != z1:
            voxels.append((x0, y0, z0))
            z0 += zs
            if p1 >= 0:
                y0 += ys
                p1 -= 2 * dz
            if p2 >= 0:
                x0 += xs
                p2 -= 2 * dz
            p1 += 2 * dy
            p2 += 2 * dx
            
    voxels.append((x0, y0, z0))
    return voxels

def is_inside_grid(x, y, z, dimensions):
    return 0 <= x < dimensions[2] and 0 <= y < dimensions[1] and 0 <= z < dimensions[0]
```

**Parameters:**
*   `voxel_resolution`: Controls the density of the voxel grid. The `voxel_size` is calculated as `cubic_size / voxel_resolution` [S1].
*   `cubic_size`: Defines the dimensions of the bounding box for the voxel grid. The grid is centered at the origin with bounds $[-cubic\_size/2, cubic\_size/2]$ [S1].
*   `-dc` (Dilated Carving): Stops carving in each direction 1 voxel before the intersection point to mitigate artifacts [S2].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point depth values must be handled carefully to avoid jitter in voxel assignment [S1].
*   **Boundaries:** Voxels on the boundary of the grid must be checked to ensure they are within the defined `origin` and `dimensions` [S1].
*   **Calibration:** The method requires accurately calibrated cameras; errors in intrinsic or extrinsic parameters lead to reconstruction artifacts [S3, unofficial].
*   **Bugs:** Historical implementations (e.g., binvox v0.48) had rendering bugs, and v1.38 had a y-direction bug in carve voxelization [S2].

## Subtopics

### [Streaming GPU-based Voxel Carving](4436-streaming-gpu-based-voxel-carving.md)
A streaming GPU-based voxel carving method that creates an explicit volume, avoids 3D texture drawbacks by using only surface voxels in a GPU-optimal 2D data representation, and minimizes GPU-CPU data transfer through effective load balancing. It differs from its parent method, Voxel Carving, by explicitly optimizing for graphics hardware trends to maintain interactivity, and from previous approaches like [LiMS04], [WoeKoch04], and [ZacKar04] by avoiding the continuous access and dual-texture overhead inherent in 3D texture-based representations.

### Interactive Multi-resolution Voxel Carving
A CPU-based voxel carving method that uses GVC-IB as its core but adds user-driven interactive refinement to create a model with varying resolution and level of detail across the voxel structure [S3, unofficial]. It differs from standard voxel carving by allowing human-guided input to assign perceptual significance to selected features, manipulating complexity via simple 2D image editing operations [S3, unofficial].

### Cell Carving
An algorithm that uses correspondence between arbitrary image regions to enable reconstruction of concavities difficult or impossible to reconstruct with other methods [S3, unofficial].

### Voxel Space Warping
A method that warps the voxel space to model large scale scenes without requiring an excessive number of voxels [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of cameras and $V$ is the number of voxels intersected by the viewing frustums. The complexity is linear with respect to the number of voxels and cameras [S3, unofficial].
*   **Memory Complexity:** $O(W \cdot H \cdot D)$ for the dense voxel grid, where $W, H, D$ are the grid dimensions [S1].
*   **Performance:** Computationally expensive, typically requiring tens of seconds to tens of minutes for high-resolution reconstructions [S3, unofficial].
*   **Strengths:** Produces dense, filled volumes suitable for volumetric rendering and collision detection; robust to noise in individual views due to intersection logic [S1].
*   **Limitations:** Requires accurate camera calibration; sensitive to missing data (occlusions) which can create holes; high memory usage for large scenes [S3, unofficial].
*   **When to use:** When a dense volumetric representation is required from multi-view depth data, and computational resources allow for iterative processing [S1].
*   **When not to use:** For real-time applications with limited hardware, or when only surface geometry is needed (use surface voxelization instead) [S1][S3, unofficial].

## Background
Voxel Carving originates from the field of multi-view stereo and volumetric reconstruction. It is based on the concept of "Space Carving," where the volume is constrained by the silhouettes or depth maps of multiple views. The method is supported in tools like Open3D (`carve_depth_map`, `carve_silhouette`) and binvox (z-buffer based carving) [S1, S2]. Early hardware-accelerated approaches were explored by Culbertson [Culbertson99] and Sainz et al. [SBS02], while theoretical foundations were laid by researchers like Seitz and Dyer [ProDy, S3, unofficial]. The method has been extended to handle uncalibrated views (Approximate Space Carving by Kutulakos [Kutulakos00, S3, unofficial]) and interactive refinement [S3, unofficial].
