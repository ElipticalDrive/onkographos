# CSG Model Voxelization

Also called: Basic CSG Voxelization by Frame Buffer Pixel Mapping, Boolean CSG voxelization, Hardware-Assisted Frame Buffer Pixel Mapping for CSG Voxelization

## Overview
CSG Model Voxelization is a hardware-accelerated algorithm that generates a binary voxelization of a Constructive Solid Geometry (CSG) model by encoding primitive classifications into frame buffer pixel colors and using logical operations to compute the final CSG classification implicitly via the Point-Classification Map (PCM) [S1]. It differs from [SDF-based Voxelization](6595-sdf-based-voxelization.md) by operating in image space via rasterization rather than distance field evaluation, and from [Sequential CSG](7629-sequential-csg.md) by leveraging GPU blending and logical operations for parallel boolean combination rather than linear CPU iteration [S1].

## How it works
**Inputs:** A CSG tree with $n$ leaf nodes (primitives), where each primitive is either a geometric boundary surface or a volume data set.
**Outputs:** A binary volume representation stored in texture memory, where each voxel indicates inclusion in the final CSG model.

**Data Structures:**
*   **Classification Index:** An $n$-bit binary number where the $j$-th bit is 1 if the point is inside the $j$-th primitive, and 0 otherwise [S1].
*   **Primitive Color ($C_j$):** For the $j$-th primitive, the color assigned to a pixel is the $j$-th color bit if the point is inside the primitive, and 0 otherwise [S1]. The $j$-th primitive's color code is a binary number with the $j$-th bit set to 1 and all other bits set to 0 [S1].
*   **Point-Classification Map (PCM):** A hardware-implemented look-up table (LUT) that maps the $n$-bit classification index (pixel color) to the final CSG classification (binary 0 or 1). The PCM is defined by the CSG tree structure, denoted as $CSG\_PCM(root)$ [S1].

**Algorithm Steps:**

1.  **Initialization:**
    *   Generate cumulative transformation matrices for each primitive [S1].
    *   Define texture objects for all volume primitives [S1].
    *   Assign color codes to all primitives such that the $j$-th primitive has only the $j$-th bit set [S1].
    *   Compute the PCM from the CSG root node using the recursive procedure below [S1].
    *   Clear the frame buffer [S1].

2.  **Loop over Z-planes (Slices):**
    For each Z-plane (slice) within the volume boundary:
    *   Define the thin viewing volume between two adjacent Z-planes [S1].
    *   **Loop over primitives:** For each primitive $j$:
        *   Define the system transformation matrix for the primitive [S1].
        *   **If Geometric Primitive (Boundary Surface):**
            *   Set the logical operation to **XOR** [S1].
            *   Set the primitive's color ($C_j$) [S1].
            *   Render the boundary surfaces. The clipping hardware ensures only parts within the thin viewing volume are displayed [S1].
            *   *Note:* The frame buffer is **not** cleared between slices or primitives. The XOR operation toggles the $j$-th bit: entering the primitive sets the bit to 1, exiting sets it to 0 [S1].
        *   **If Volume Data Set Primitive:**
            *   Clear the frame buffer's color bit for this primitive (specifically the $j$-th bit) for all pixels on the frame buffer. This must be done selectively to retain bits for other geometric primitives [S1].
            *   Bind the 3D texture object defined by the volume data set [S1].
            *   Set a Color Look-Up Table (CLUT) to map intensity values within the threshold interval $[s, t]$ to the primitive's color ($C_j$) and other values to 0 [S1].
            *   Set the logical operation to **OR** [S1].
            *   Draw the Z-plane using 3D texture mapping [S1].
    *   **Post-Processing for Slice:**
        *   Define the frame buffer pixel map using the computed PCM [S1].
        *   Copy the frame buffer to texture memory. The PCM is automatically applied during this copy operation, mapping the classification index to the final binary CSG classification [S1].

**Parameters:**
*   $n$: The number of primitives in the CSG tree. The algorithm assumes $n$ distinct colors are assigned [S1].

**Edge Cases and Pitfalls:**
*   **Frame Buffer Bit Depth:** Standard RGBA frame buffers have 8 bits per component (32 bits total). The basic algorithm is limited to 8 primitives if using only one color component (e.g., Red) because the frame buffer pixel map only has separate look-up tables for individual RGBA components, not cross-combinations [S1].
*   **Large CSG Trees:** For CSG trees with more than 8 primitives, the basic algorithm must be modified using a multi-pass approach or bit-packing strategies, which are not detailed in the primary source [S1].
*   **Volume Primitive Bit Clearing:** When rendering volume primitives, the specific bit for that primitive must be cleared before rendering. Clearing the entire frame buffer is incorrect as it would erase bits for previously rendered geometric primitives [S1].

## Subtopics

### [CSG and Inter-object Intersection](4703-csg-and-inter-object-intersection.md)
Performs general CSG operations by voxelizing each object into a separate slicemap and rendering them over one another using GPU blending to achieve boolean operations. It differs from this method by explicitly focusing on the intersection and boolean combination of multiple distinct objects rather than single-object voxelization, and from [SDF-based Voxelization](6595-sdf-based-voxelization.md) by operating in image space via rasterization rather than distance field evaluation.

### [SDF-based Voxelization](6595-sdf-based-voxelization.md)
Visualizes CSG meshes or analytic primitives as voxel chunks by sampling a 3D grid and querying Signed Distance Fields. It differs from this method by performing voxelization on the CPU and storing results in a packed bitmap, which is later rendered as analytic box primitives via an existing path tracer without requiring shader changes.

### [Sequential CSG](7629-sequential-csg.md)
A CPU-based algorithm for performing boolean operations on two voxel grids using word-level parallelism. It differs from this method by iterating linearly through the grid data structure, applying bitwise operations to chunks of voxels (words) rather than individual voxels, ensuring simplicity and deterministic execution at the cost of parallel throughput.

## Operating characteristics
*   **Time Complexity:** Interactive performance is achieved due to hardware acceleration. The algorithm avoids generating intermediate texture objects for each Boolean operation node, which was a bottleneck in previous methods [S1].
*   **Memory Complexity:** Requires frame buffer space proportional to the resolution of the display window and Z-resolution. Texture memory is used to store the resulting binary volume slices [S1].
*   **Strengths:** No pre-processing is required for changes to the CSG tree, making it effective for volumetric CSG modeling environments. It provides a multi-resolution rendering solution through dynamic voxelization of viewing regions [S1].
*   **Limitations:** Limited by frame buffer bit depth (typically max 8 primitives per pass without multi-pass strategies). The frame buffer pixel map limitation restricts cross-component look-ups [S1].
*   **When to use:** When interactive CSG voxelization is required for volume rendering or layered manufacturing, and the CSG tree has a manageable number of primitives (or multi-pass can be employed) [S1].
*   **When not to use:** When the CSG tree has a very large number of primitives and hardware multi-pass support is unavailable, or when high-precision distance-based operations are required [S1].

## Background
The method was introduced to overcome the limitations of previous hardware-accelerated CSG voxelization algorithms that used blending functions and intermediate textures for each Boolean operation node, which were limited by hardware restrictions on blending function combinations [S1]. The new method employs a Point-Classification Map (PCM) for Boolean operations based on a frame buffer color encoding scheme, resulting in faster performance [S1]. It is applicable to regions of interest for multi-resolution rendering and is used in volumetric CSG modeling environments, medical image analysis, and layered manufacturing [S1].
