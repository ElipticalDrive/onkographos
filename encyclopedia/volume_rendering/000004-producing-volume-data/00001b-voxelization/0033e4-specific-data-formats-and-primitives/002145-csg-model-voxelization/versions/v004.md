# CSG Model Voxelization

Also called: Boolean CSG voxelization

## Overview
CSG Model Voxelization is a method for converting Constructive Solid Geometry (CSG) models into voxel data by voxelizing individual CSG nodes into separate 2D texture worksheets and performing boolean operations in image space using GPU blending [S1, unofficial][S2, unofficial]. It differs from its sibling [SDF-based Voxelization](6595-sdf-based-voxelization.md) by operating directly on discrete voxel grids to achieve real-time performance with low dependence on input geometry complexity, whereas SDF-based methods rely on signed distance fields for smooth boundaries [S1, unofficial]. It also differs from [CSG and Inter-object Intersection](4703-csg-and-inter-object-intersection.md) by focusing on the general voxelization of CSG trees rather than specifically leveraging density computation for rapid intersection volume recovery in collision detection [S1, unofficial].

## How it works
The method processes a CSG tree by decomposing it into primitive nodes and boolean operators, voxelizing the primitives, and then combining the results via GPU-based image-space blending.

**Inputs and Outputs:**
*   **Input:** A CSG model defined by a tree of nodes (primitives and boolean operators).
*   **Output:** A voxel representation (worksheet) of the final CSG result.

**Data Structures:**
*   **Worksheet:** A 2D texture or buffer representing a slice or the full voxel grid, storing occupancy or material data for the voxelized nodes [S1, unofficial][S2, unofficial].
*   **CSG Node:** Represents either a primitive (e.g., sphere, box) or a boolean operation (Union, Intersection, Difference).

**Steps:**
1.  **Voxelize CSG Nodes:** Each leaf node (primitive) of the CSG tree is voxelized individually into its respective worksheet. This involves processing vertices in a vertex shader, using texture coordinates in the parametric domain to calculate 3D positions, and transcoding these positions to the worksheet [S1, unofficial][S2, unofficial].
2.  **Perform CSG Constructions:** The boolean operations are performed from the bottom of the CSG tree to the top. This is done automatically in image space by applying boolean operations on the 2D textures defined by GPU blending operations [S1, unofficial][S2, unofficial].

## Subtopics

### [CSG and Inter-object Intersection](4703-csg-and-inter-object-intersection.md)
Performs general CSG operations on voxelized objects by rendering individual object slicemaps over one another using GPU blending. It differs from its parent method by explicitly leveraging the density computation inherent in solid voxelization to recover intersection volumes rapidly, making it particularly suitable for collision detection and haptic feedback. Unlike SDF-based Voxelization, which relies on signed distance fields for smooth boundaries, this method operates directly on discrete voxel grids to achieve real-time performance with low dependence on input geometry complexity.

### [SDF-based Voxelization](6595-sdf-based-voxelization.md)
Visualizes any CSG mesh or analytic primitive as a Minecraft-style voxel chunk pile by determining world-space bounding boxes, sampling a 3D grid, and querying Signed Distance Fields (SDF) to determine occupancy. It differs from GPU-based rasterization voxelization by relying on CPU-side SDF queries and storing results in a packed bitmap for later rendering as analytic box primitives, enabling A/B comparison with the original mesh without shader changes.

## Background
The method was introduced in the paper "Real-time Voxelization for Complex Models" [S1, unofficial][S2, unofficial]. It addresses the challenge of transparent illustration and rapid voxelization for complex models. The approach leverages the GPU's ability to perform boolean operations on 2D textures through blending operations, making it suitable for real-time applications.
