# Naive CSG Voxel Operations

Also called: NaiveCSG, ProcessingNaive

## Overview
Naive CSG Voxel Operations is a brute-force GPU kernel for performing Constructive Solid Geometry (Boolean) operations (Union, Intersection, Difference) on two voxel grids by processing every voxel independently [S1, unofficial]. It differs from optimized methods by iterating over all voxels without skipping empty regions or using hierarchical structures, prioritizing implementation simplicity over computational efficiency [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Two voxel grids (`grid1`, `grid2`) of identical dimensions and voxel sizes [S1, unofficial].
*   **Output:** The result of the Boolean operation written into `grid1` [S1, unofficial].

**Data Structures:**
The method operates on `VoxelsGrid<T, true>` structures which inherit from `Grid<T>` [S1, unofficial].
*   `mGrid`: A span of type `T` storing the voxel data [S1, unofficial].
*   `mSizeX`, `mSizeY`, `mSizeZ`: Dimensions of the grid [S1, unofficial].
*   `mVoxelSize`: Physical size of a voxel [S1, unofficial].
*   `mOriginX`, `mOriginY`, `mOriginZ`: Origin coordinates [S1, unofficial].
*   Access is performed via a `Bit` struct which utilizes atomic operations (`atomicOr`, `atomicAnd`, `atomicXor`) for device writes [S1, unofficial].

**Parameters:**
*   `blockSize`: Calculated as the next power of 2 of `numWord`, capped at half the device's maximum threads dimension [S1, unofficial].
    *   Formula: `blockSize = NextPow2(numWord, prop.maxThreadsDim[0] / 2)`
*   `gridSize`: Number of blocks, calculated as `(numWord + blockSize - 1) / blockSize` [S1, unofficial].

**Steps:**
1.  Calculate the total number of words to process: `numWord = grid1.Size() * grid1.WordSize()` [S1, unofficial].
2.  Determine the linear word index from the thread/block indices: `wordIndex = (blockIdx.x * blockDim.x) + threadIdx.x` [S1, unofficial].
3.  Check bounds: If `wordIndex >= numWord`, terminate the thread [S1, unofficial].
4.  Compute the linear voxel index: `voxelIndex = wordIndex * grid1.WordSize()` [S1, unofficial].
5.  Convert the linear voxel index to 3D coordinates $(z, y, x)$ using division and modulo operations on `grid1.VoxelsPerSide()` [S1, unofficial].
6.  Execute the specific Boolean operation function `Op` on the words at the computed coordinates: `Op(grid1.Word(x, y, z), grid2.Word(x, y, z))` [S1, unofficial].

**Pseudocode:**
```python
def next_pow2(n, cap):
    p = 1
    while p < n:
        p *= 2
    return min(p, cap)

def get_device_properties():
    return type('obj', (object,), {'max_threads_dim': [1024, 1024, 64]})()

def naive_csg_kernel(grid1, grid2, Op, thread_idx, block_dim):
    # 1. Calculate total words
    num_word = grid1.size() * grid1.word_size()

    # 2. Calculate linear word index from thread/block indices
    word_index = (thread_idx // block_dim) * block_dim + (thread_idx % block_dim)

    # 3. Check bounds
    if word_index >= num_word:
        return

    # 4. Calculate linear voxel index
    voxel_index = word_index * grid1.word_size()

    # 5. Compute 3D coordinates (z, y, x) from linear voxel index
    N = grid1.voxels_per_side()
    z = voxel_index // (N * N)
    remainder = voxel_index % (N * N)
    y = remainder // N
    x = remainder % N

    # 6. Execute operation on words at coordinates
    Op(grid1.word(x, y, z), grid2.word(x, y, z))

def launch_naive_csg(grid1, grid2, Op):
    # Assert identical dimensions and voxel sizes
    assert grid1.view().voxels_per_side() == grid2.view().voxels_per_side()
    assert grid1.view().voxel_size() == grid2.view().voxel_size()

    num_word = grid1.size() * grid1.word_size()

    # Calculate block size: next power of 2, capped at half max threads dim
    prop = get_device_properties()
    block_size = next_pow2(num_word, prop.max_threads_dim[0] // 2)

    # Calculate grid size (number of blocks)
    grid_size = (num_word + block_size - 1) // block_size

    # Launch kernel
    for i in range(grid_size * block_size):
        naive_csg_kernel(grid1, grid2, Op, i, block_size)
```

**Edge Cases and Pitfalls:**
*   **Dimension Mismatch:** The two input grids must have identical dimensions and voxel sizes. This is enforced by assertions at runtime [S1, unofficial].
*   **Precision:** The method relies on integer arithmetic for coordinate mapping; ensure `VoxelsPerSide()` is consistent across grids [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the total number of voxels, because every voxel is processed regardless of content [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the input and output grids [G].
*   **Strengths:** Simple implementation without complex data structure overhead [G].
*   **Limitations:** Inefficient for sparse data or large grids with significant empty space, as it does not skip empty regions or use hierarchical structures [S1, unofficial].
*   **When to use:** Small to medium dense grids where implementation simplicity is prioritized over performance [G].
*   **When not to use:** Large sparse grids or real-time applications requiring high performance on complex CSG operations [G].

## Background
Naive CSG Voxel Operations is a straightforward approach to voxel-based Boolean operations, implemented as a CUDA kernel in the context of GPU-accelerated mesh voxelization [S1, unofficial]. It serves as a baseline for comparison against more optimized sequential or hierarchical CSG methods [S1, unofficial].
