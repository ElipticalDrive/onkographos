# Point Feature Generation


## Overview
Point Feature Generation constructs per-point feature vectors for ray samples by indexing pre-computed volume features and optionally integrating color information from input images [S1, unofficial]. It solves the problem of associating rich geometric and appearance data with sparse 3D points in neural rendering pipelines. Unlike sibling methods that rely on direct spatial averaging of raw LiDAR points [11242-mean-feature-aggregation-by-voxel.md] or voxel-based Gaussian sampling [7021-voxel-feature-composition.md], this method operates directly on ray points, leveraging existing volume indices to build color volumes or assign features [S1, unofficial].

## How it works
**Inputs:**
- `input_feat`: Tensor of input features with shape $(N, C_{in})$, where $N$ is the number of points and $C_{in}$ is the input channel dimension.
- `img_feat` (optional): Tensor of image features. If provided, its spatial dimensions are added to the feature dimension count [S1, unofficial].
- `use_color_volume`: Boolean flag indicating whether to build a color volume from images [S1, unofficial].

**Outputs:**
- `ray_feats`: Tensor of shape $(N, 8)$ containing the first 8 channels of `input_feat` [S1, unofficial].
- `color_volume` (optional): Volume data built from images if `use_color_volume` is true [S1, unofficial].

**Data Structures:**
- `ray_feats`: Fixed 8-channel tensor per point.
- `volume_features`: Indexed structure allowing direct access to features based on ray point coordinates [S1, unofficial].

**Steps:**
1. **Dimension Calculation**: If `img_feat` is provided, update the total feature dimension $C_{total} = C_{in} + C_{img\_spatial}$ [S1, unofficial].
2. **Initialization**: If `use_color_volume` is false, initialize `input_feat` and index the volume features [S1, unofficial].
3. **Feature Splitting**: Assign the first 8 channels of `input_feat` to `ray_feats`. Formally:
   $$ \text{ray\_feats}_i = \text{input\_feat}_i[:, 0:8] \quad \forall i \in [0, N) $$
   [S1, unofficial]
4. **Color Volume Construction**: Assign the remaining channels ($C_{in} - 8$) to the color volume built from images. If `use_color_volume` is true, directly index the volume features using the ray point coordinates [S1, unofficial].

## Subtopics

### [Voxel Feature Composition](7021-voxel-feature-composition.md)
Voxel Feature Composition generates per-voxel feature vectors by sampling points within the volume of 3D Gaussians and weighting them by Gaussian attenuation. It aggregates voxel-level geometric and appearance data into a single feature vector per voxel for storage or further processing. Unlike its sibling [Mean Feature Aggregation by Voxel](11242-mean-feature-aggregation-by-voxel.md), which relies on direct spatial averaging of raw LiDAR points, this method computes features by sampling Gaussian volumes and weighting by attenuation.

### Attention Aggregation for 3D Points
Aggregates unordered, variable-sized sets of retrieved pixel features from multiple input views into a single unique feature vector for a query 3D point, handling visual occlusions and arbitrary input counts [S2]. The attention mechanism must be permutation invariant with regard to the input set of feature vectors [S2]. For a query 3D point $p$ with query viewpoint $V_p$ and retrieved pixel features $\{F^1_p, \dots, F^m_p\}$, shared MLPs integrate the query point information to generate position-aware features $\hat{F}^m_p = \text{MLPs}(F^m_p \oplus [x_p, y_p, z_p])$ [S2]. The final feature vector is computed as $\bar{F}_p = \mathcal{A}(\hat{F}^1_p, \dots, \hat{F}^m_p)$, where $\mathcal{A}$ is an attention function that learns unique weights for all input features [S2].
