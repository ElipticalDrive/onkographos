# Mean Feature Aggregation by Voxel
Also called: Lidar Feature Extraction, Mean Feature Aggregation, Voxel Feature Averaging

## Overview
Mean Feature Aggregation by Voxel computes mean features for each voxel by aggregating point features based on voxel indices, returning unique voxel features and their indices [S2, unofficial]. It solves the problem of constructing a dense, geometrically consistent representation from sparse sensor data (such as LiDAR) by averaging spatial positions within voxel cells to yield a 3-dimensional feature vector [S1]. Unlike its sibling [Voxel Feature Composition](7021-voxel-feature-composition.md), which generates per-voxel feature vectors containing coordinates, RGB color, and opacity by sampling points within each Gaussian's volume and weighting them by Gaussian attenuation, this method explicitly averages the raw spatial coordinates of discrete points falling into each grid cell [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of LiDAR point clouds aggregated from all frames of a sequence. Each point $i$ has a 3D location $p_i$ and an associated $n$-dimensional neural feature vector $f_i$ [S1].
*   **Output:** A set of unique voxel features and their corresponding indices. Specifically, for each occupied voxel, a neural volumetric feature vector of dimension $n$ [S1].

**Data Structures:**
*   **Voxel Grid:** A 3D grid where each cell corresponds to a spatial region.
*   **Point Set:** $P = \{(p_i, f_i) \mid i = 1, \dots, N\}$, where $p_i$ is the 3D location and $f_i$ is the $n$-dim neural feature vector of the voxel cell it resides in [S1].

**Steps:**
1.  **Aggregation:** Aggregate LiDAR point clouds from all frames of the entire sequence to construct a denser set of point clouds [S1].
2.  **Device Transfer:** Move all input tensors (points, features, batch IDs, bounding boxes, colors, depth confidence) to the target device [S2, unofficial].
3.  **Voxelization:** Voxelize the point clouds into a voxel grid. For each voxel cell, average the spatial positions of points falling into that cell to yield a 3-dimensional feature for the cell [S1].
4.  **Index Computation:** Compute voxel indices using a function `get_vox_indices` with `shift=False` and `cat_batch_ids=True` [S2, unofficial].
5.  **Hashing:** Compute voxel hashes using a hash function `self.hash_fn(voxel_indices)` [S2, unofficial].
6.  **Uniqueness:** Get unique hashes and inverse IDs using `torch.unique(voxel_hash, return_inverse=True)` [S2, unofficial].
7.  **Feature Encoding:** Encode the scene geometry feature using a 3D sparse UNet on the voxel grid. The input is the voxel grid along with its 3-dimensional features. The output is neural volumetric features consisting of an $n$-dimensional feature for each occupied voxel [S1].

**Parameters:**
*   **Voxel Size:** Not given in the sources.
*   **Search Radius (R) and K:** Used in the subsequent "Query of Lidar features" step, not the aggregation itself. $K$ nearby points within radius $R$ are queried using Fixed Radius Nearest Neighbors (FRNN) [S1].

**Edge Cases and Pitfalls:**
*   **Empty Voxels:** Voxels with no points falling into them are not processed or output as unique features [S1].
*   **Precision:** The averaging of spatial positions requires floating-point precision to maintain geometric accuracy [S1].
*   **Batch IDs:** The method supports batched processing via `cat_batch_ids=True`, ensuring points from different sequences or scenes are correctly indexed [S2, unofficial].

## Subtopics

### [Double Backward Voxel Grid Feature](15967-double-backward-voxel-grid-feature.md)
Computes second-order gradients for voxel grid features to support Eikonal regularization, solving the memory overhead of naive automatic differentiation. It differs from Mean Feature Aggregation by Voxel by implementing backward passes for gradient computation rather than first-order mean aggregation.

## Operating characteristics
*   **Time Complexity:** Dominated by the voxelization step ($O(N)$ for $N$ points) and the 3D sparse UNet encoding. The UNet complexity depends on the number of occupied voxels and the network depth [S1].
*   **Memory Complexity:** Proportional to the number of unique occupied voxels and the feature dimension $n$ [S1].
*   **Strengths:** Leverages the strength of both LiDAR and visual data by providing a dense geometric context. The 3D sparse UNet allows learning from a global context of scene geometry [S1].
*   **Limitations:** Requires aggregation of multiple frames to construct a dense point cloud, which may be computationally expensive for large sequences [S1].
*   **When to Use:** When high-quality and complete scene rendering is required, particularly in street scenes where LiDAR data is available [S1].

## Background
Originating from the LidaRF paper, this method was introduced to delve into LiDAR for Neural Radiance Fields on street scenes [S1]. It builds on the success of 3D perception frameworks that use sparse UNets for geometry encoding [S1]. The method is part of a pipeline that jointly learns LiDAR and visual features for high-quality rendering [S1].
