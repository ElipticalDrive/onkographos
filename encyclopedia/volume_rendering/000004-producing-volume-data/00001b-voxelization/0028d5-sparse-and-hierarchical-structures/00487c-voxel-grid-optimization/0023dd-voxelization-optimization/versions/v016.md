# Voxelization Optimization


## Overview
Voxelization Optimization encompasses techniques to reduce the computational and memory costs of generating voxel grids for volume rendering, primarily by accelerating the rasterization of geometry into voxels and minimizing redundant updates. It distinguishes itself from downstream processing methods (like [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) or [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md)) by focusing on the input stage: converting triangle meshes into 3D occupancy or density fields. Key strategies include GPU hardware acceleration via stream output and instancing, spatial culling of static geometry, and level-of-detail (LOD) simplification for obstacles [S1, S2, unofficial].

## How it works
The method optimizes the pipeline from mesh to voxel grid using the following components:

### Inputs and Outputs
*   **Input:** Triangle mesh geometry (static or deforming/skinned), camera/view parameters, and voxel grid resolution/bounds.
*   **Output:** A populated voxel grid (occupancy, density, or velocity fields) ready for ray marching or cone tracing.

### Data Structures
*   **Transformed Vertex Buffer:** A GPU buffer storing pre-transformed vertex positions and attributes, used to avoid recomputing skinning matrices per slice [S1, unofficial].
*   **Instance Data:** Structs containing slice-specific transformation matrices or offsets, enabling single-draw-call voxelization [S1, unofficial].
*   **Min/Max Altitude Heightmaps:** (Optional, for specific meshing variants) Two byte arrays (`minAltitude`, `maxAltitude`) of size $N^2$ (where $N$ is chunk size, e.g., 32) storing the lowest and highest occupied Y-index per XZ column [S3, unofficial].

### Steps
1.  **Geometry Simplification:** Replace high-poly obstacle meshes with low-poly LOD meshes to reduce the number of triangles processed during rasterization [S1, unofficial].
2.  **Transform Caching (Stream Output):** For deforming meshes (e.g., skinned characters), use GPU stream output to cache the transformed vertices into a buffer. This avoids recomputing skinning transformations for every voxel slice [S1, unofficial].
3.  **Instanced Slicing:** Use geometry shaders or compute shaders with instancing to render all voxel slices (or layers) in a single draw call. The instance ID determines the target slice's position or transformation [S1, unofficial].
4.  **Static Culling:** Do not re-voxelize static objects unless their state changes or they are intersected by dynamic elements (e.g., dynamic lights) that require updated illumination data [S2, unofficial].
5.  **Analytic Transformation Inversion:** For objects with simple analytic transformations (rigid body motion), precompute the voxelization and apply the inverse transformation during texture access rather than re-rasterizing [S1, unofficial].
6.  **Heightmap Maintenance (Variant):** For chunk-based meshing, maintain `minAltitude` and `maxAltitude` arrays. On voxel addition/removal, update these arrays to reflect the new column bounds, allowing the renderer to skip empty or fully occupied columns [S3, unofficial].

# Step 1: Precompute LOD mesh for obstacles
def get_lod_mesh(obstacle):
    return simplify_mesh(obstacle, target_triangles=100) # [S1, unofficial]

# Step 2: Cache transformed vertices for deforming mesh
def cache_transformed_vertices(mesh, skinning_matrices):
    # Use GPU stream output to write transformed vertices to a buffer
    # Avoids CPU-to-GPU transfer and per-slice skinning calculation
    transformed_buffer = stream_output(mesh, skinning_matrices)
    return transformed_buffer

# Step 3: Instanced Voxelization
def voxelize_instanced(transformed_buffer, slice_count, slice_transforms):
    # Single draw call using instancing
    # Instance ID i specifies the target slice
    for i in range(slice_count):
        # The geometry shader uses instance ID to determine slice position
        draw_instanced(transformed_buffer, slice_transforms[i])

# Step 4: Static Object Handling
def voxelize_static(static_mesh, needs_update):
    if not needs_update:
        return cached_voxel_grid
    else:
        # Re-voxelize only if necessary
        return rasterize(static_mesh)

# Step 5: Heightmap Update (Variant from [S3, unofficial])
def update_heightmaps(chunk, x, z, y, is_addition):
    if is_addition:
        chunk.min_altitude[x, z] = min(chunk.min_altitude[x, z], y)
        chunk.max_altitude[x, z] = max(chunk.max_altitude[x, z], y)
    else:
        # Recalculate min/max for the column if needed
        chunk.min_altitude[x, z] = find_min_y_in_column(chunk, x, z)
        chunk.max_altitude[x, z] = find_max_y_in_column(chunk, x, z)

### Parameters
*   **LOD Triangle Count:** Low enough to ensure fast rasterization but high enough to preserve shape fidelity. Not given in the sources.
*   **Chunk Size:** Typically 32x32x32 voxels for heightmap optimization [S3, unofficial].
*   **Update Frequency:** Static objects updated only on intersection with dynamic lights [S2, unofficial].

### Edge Cases and Pitfalls
*   **Dynamic Lights:** Dynamic lights intersecting static objects force re-voxelization of those static objects, complicating the "static" optimization [S2, unofficial].
*   **Precision:** Stream output buffers must be large enough to hold all transformed vertices for the frame.
*   **Degenerate Input:** Simplified LOD meshes must not introduce self-intersections that cause incorrect voxel occupancy.

## Subtopics

### [32nd Bit Avoidance Modification](3351-32nd-bit-avoidance-modification.md)
The 32nd Bit Avoidance Modification adjusts the solid voxelization and density computation pipelines to exclude the highest bit of 32-bit storage formats, which is reserved for other purposes. It restricts voxel and density data to the lower bits, distinguishing it from general sparse voxelization by targeting bit-packing constraints in dense grids.

### [Sparse Voxelization with Oracle and Parallel Scan](3687-sparse-voxelization-with-oracle-and-parallel-scan.md)
Sparse Voxelization with Oracle and Parallel Scan is a real-time, high-resolution technique for reconstructing 3D surface models from image-based inputs (calibrated RGB camera streams) using a coarse-to-fine voxel hierarchy. It solves the problem of on-the-fly surface reconstruction by iteratively refining a sparse list of voxels, using an oracle kernel to cull empty space and a parallel prefix sum scan to compact the list, ensuring that only relevant voxels are subdivided. Unlike bottom-up approaches or methods designed for static models, this method is top-down and optimized for interactive rates (e.g., >30 fps at 1024^3 resolution) by leveraging GPU parallelism for both computation and rendering.

### [Greedy Voxel Mesh Optimization](3979-greedy-voxel-mesh-optimization.md)
Greedy Voxel Mesh Optimization is a greedy algorithm that optimizes voxel mesh generation by merging adjacent identical tiles into larger rectangular quads to reduce draw calls. It operates on 2D slices (e.g., the XZ plane) of solid voxels, differing from its parent [Voxelization Optimization](3191-voxelization-optimization.md) by focusing on the geometric merging phase after occlusion culling. It differs from [Disjoint Set Mesh Optimization](4495-disjoint-set-mesh-optimization.md) by using a simple iterative expansion rather than a Disjoint Set Union structure for the merging logic.

### Stream Output for Voxelization
A technique to optimize voxelization of deforming meshes by caching transformed vertices, avoiding recomputation for each slice [S1, unofficial]. It uses stream output to cache an entire buffer of transformed vertices during the voxelization of deforming meshes (e.g., skinned characters) [S1, unofficial].

### Min/Max Altitude Heightmap Optimization
Stores per-column minimum and maximum occupied voxel heights to skip empty or fully occupied columns during meshing [S3, unofficial]. On voxel addition (index > 0), `OnVoxelAdded(i, j, k)` updates the heightmaps to reflect the new occupied column. On voxel removal (index == 0), `OnVoxelRemoved(i, j, k)` updates the heightmaps to reflect the cleared column. The `minAltitude` array is initialized to `Constants.ChunkSize` (32) for all columns, indicating initially empty columns. The `minAltitude` and `maxAltitude` are byte arrays of size `ChunkSizeSquared` (1024 bytes), storing the lowest and highest occupied Y index per XZ column, respectively [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Voxelization is generally $O(N \cdot T)$, where $N$ is the number of voxels and $T$ is the number of triangles. Instancing reduces draw call overhead to $O(1)$ per frame regardless of slice count [S1, unofficial].
*   **Memory Complexity:** Depends on the grid resolution. Sparse structures (like Sparse Voxel Octrees) reduce memory requirements significantly compared to dense grids [S2, unofficial].
*   **Performance:** Techniques allow real-time performance on fast GPUs, used in titles like *Rise of the Tomb Raider* (voxel AO) and *The Tomorrow Children* on consoles [S2, unofficial].
*   **Strengths:** Significant reduction in CPU/GPU workload for dynamic scenes; efficient handling of deforming meshes.
*   **Limitations:** Static optimization is complex due to dynamic light interactions; LOD simplification may lose fine geometric details.

## Background
Voxelization optimization techniques have evolved alongside real-time global illumination methods. Early implementations focused on brute-force rasterization, but as real-time voxel cone tracing became viable, optimizations like stream output and instancing were introduced to handle the high draw call counts [S1, unofficial]. The use of sparse structures and voxel cascades for updating frequencies further refined performance for games like *Rise of the Tomb Raider* and *The Tomorrow Children* [S2, unofficial].
