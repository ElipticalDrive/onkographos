# Voxelization Optimization


## Overview
Voxelization Optimization refers to a set of techniques designed to reduce the computational cost and memory bandwidth requirements of generating voxel data from geometric primitives, particularly in real-time rendering pipelines. It addresses the bottleneck of high draw call counts and redundant vertex transformations during the rasterization of 3D meshes into voxel grids. It distinguishes itself from sibling methods by focusing on the *generation* phase efficiency (e.g., stream output, instancing, LOD) rather than post-generation data compression or structural simplification.

## How it works
The method optimizes the voxelization pipeline through four primary mechanisms: stream output caching, instancing, level-of-detail (LOD) reduction, and static/dynamic separation.

### Inputs and Outputs
- **Input:** 3D mesh geometry (vertices, indices), transformation matrices (model, view, projection), voxel grid resolution, and slice configuration.
- **Output:** A populated voxel grid (3D texture or buffer) representing the scene geometry.

### Data Structures
1.  **Stream Output Buffer:** A GPU buffer storing transformed vertex positions and velocities. Size depends on the mesh vertex count.
2.  **Instance Data Buffer:** Contains slice-specific parameters (e.g., slice index, transformation offsets).
3.  **LOD Mesh:** A simplified version of the input mesh with reduced vertex/face count.

### Steps
1.  **LOD Selection:** For each obstacle or mesh, select a low-polygon version (LOD) to reduce rasterization workload [S1, unofficial].
2.  **Stream Output Caching (Deforming Meshes):**
    - For deforming meshes (e.g., skinned characters), render the mesh once to a stream output buffer.
    - Capture the transformed vertices (position, velocity) into this buffer.
    - Avoid recomputing skinning/transformations for every voxel slice [S1, unofficial].
3.  **Instanced Slicing:**
    - Configure the voxelization shader to accept an instance ID.
    - Use the instance ID to determine the target Z-slice (or other axis) for the current draw.
    - Issue a single instanced draw call to render all slices, rather than one draw call per slice [S1, unofficial].
4.  **Static/Dynamic Separation:**
    - Identify static objects (geometry that does not change).
    - Pre-voxelize static objects if they undergo simple analytic transformations (e.g., rigid translation/rotation). Apply the inverse transformation during voxel access [S1, unofficial].
    - Do not re-voxelize static objects unless necessary.
    - Force re-voxelization of static objects if dynamic lights intersect them, as lighting changes may require updated voxel data [S2, unofficial].

### Pseudocode
```python
def voxelize_scene(meshes, voxel_grid, slices):
    # Step 1: LOD Selection
    lod_meshes = [mesh.get_lowest_lod() for mesh in meshes]

    # Step 2: Stream Output for Deforming Meshes
    stream_buffer = None
    for mesh in lod_meshes:
        if mesh.is_deforming():
            # Render mesh to stream output buffer to cache transformed vertices
            stream_buffer = render_to_stream_output(mesh)
            # Use cached vertices for subsequent slices
            mesh.vertex_buffer = stream_buffer

    # Step 3: Instanced Slicing
    # Create instance data for each slice
    instance_data = []
    for slice_idx in slices:
        instance_data.append({
            'slice_id': slice_idx,
            'transform': get_slice_transform(slice_idx)
        })

    # Single instanced draw call for all slices
    draw_instanced(
        geometry_shader=voxelization_shader,
        vertex_buffer=lod_meshes,
        instance_buffer=instance_data,
        output=voxel_grid
    )

    # Step 4: Static/Dynamic Separation
    for mesh in lod_meshes:
        if mesh.is_static():
            if mesh.has_simple_transformation():
                # Pre-voxelize and store inverse transform
                prevoxelized_data = prevoxelize(mesh)
                mesh.voxel_data = prevoxelized_data
                mesh.inverse_transform = mesh.get_inverse_transform()
            else:
                # Check for dynamic light intersection
                if dynamic_lights_intersect(mesh):
                    # Re-voxelize if necessary
                    mesh.voxel_data = voxelize(mesh)
```

### Parameters
- **LOD Level:** Not given in the sources. Typically chosen to balance visual fidelity and performance.
- **Stream Output Buffer Size:** Equal to the number of vertices in the deforming mesh.
- **Instance Count:** Equal to the number of slices in the voxel grid.

### Edge Cases and Pitfalls
- **Dynamic Lights:** Dynamic lights intersecting static objects force re-voxelization, which can negate optimization benefits if not managed carefully [S2, unofficial].
- **Complex Transformations:** Skinned or complex deforming meshes require stream output; simple analytic transformations allow pre-voxelization [S1, unofficial].
- **Precision:** Not given in the sources.

## Subtopics

### [32nd Bit Avoidance Modification](3351-32nd-bit-avoidance-modification.md)
Modifications to the solid voxelization algorithm to avoid using the 32nd bit, which is reserved for different purposes. This involves modifying the 1D texture to exclude the highest bit [3351-32nd-bit-avoidance-modification.md].

### [Sparse Voxelization with Oracle and Parallel Scan](3687-sparse-voxelization-with-oracle-and-parallel-scan.md)
A parallel voxelization pipeline that uses an oracle kernel to decide voxel retention, applies a parallel prefix sum scan to culling decisions for subdivision or compaction, repeats until high resolution, and renders pixel-sized voxels as splats textured by weighted input color images [3687-sparse-voxelization-with-oracle-and-parallel-scan.md].

### [Greedy Voxel Mesh Optimization](3979-greedy-voxel-mesh-optimization.md)
A greedy algorithm to optimize voxel mesh generation for 2D tile grids (e.g., Minecraft-like games) by merging adjacent identical tiles into larger rectangular quads to reduce draw calls [3979-greedy-voxel-mesh-optimization.md].

### Stream Output for Voxelization
A technique to optimize voxelization of deforming meshes by caching transformed vertices, avoiding recomputation for each slice. It uses stream output to cache an entire buffer of transformed vertices during the voxelization of deforming meshes (e.g., skinned characters) [S1, unofficial].

### Min/Max Altitude Heightmap Optimization
Stores per-column minimum and maximum occupied voxel heights to skip empty or fully occupied columns during meshing. On voxel addition (index > 0), `OnVoxelAdded(i, j, k)` updates the heightmaps to reflect the new occupied column. On voxel removal (index == 0), `OnVoxelRemoved(i, j, k)` updates the heightmaps to reflect the cleared column. Initialize `minAltitude` array to `Constants.ChunkSize` (32) for all columns, indicating initially empty columns. `minAltitude` is a byte array of size `ChunkSizeSquared` (1024 bytes), storing the lowest occupied Y index per XZ column. `maxAltitude` is a byte array of size `ChunkSizeSquared` (1024 bytes), storing the highest occupied Y index per XZ column [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Reduced by minimizing draw calls (instancing) and vertex transformations (stream output). Pre-voxelization of static objects reduces per-frame cost to O(1) for those objects.
- **Memory Complexity:** Stream output buffers add memory overhead proportional to the number of vertices in deforming meshes. Pre-voxelized static objects require additional storage for voxel data and inverse transforms.
- **Measured Performance:** Used in games like *Rise of Tomb Raider* (voxel AO) and *The Tomorrow Children* (on consoles) [S2, unofficial].
- **Scaling:** Benefits from higher resolutions due to reduced per-vertex overhead, but memory usage for stream output and pre-voxelized data scales with mesh complexity.
- **Strengths:** Significant reduction in CPU-GPU transfer and vertex processing overhead for deforming meshes. Efficient handling of static geometry.
- **Limitations:** Requires careful management of dynamic lights intersecting static objects. Pre-voxelization is only effective for simple analytic transformations.
- **When to Use:** Real-time rendering of scenes with deforming meshes and static geometry. When draw call overhead is a bottleneck.
- **When Not to Use:** Scenes with highly dynamic geometry where pre-voxelization is not feasible. When memory bandwidth is the primary bottleneck and stream output buffers are too large.

## Background
Voxelization optimization techniques have been developed to address the performance challenges of real-time voxel-based rendering. Stream output and instancing were highlighted in *GPU Gems 3* for fluid simulation and voxelization [S1, unofficial]. The use of voxel cascades and sparse voxel octrees for optimization was discussed in the context of voxel-based global illumination in *Rise of Tomb Raider* and *The Tomorrow Children* [S2, unofficial]. Min/Max altitude heightmap optimization is a specific technique for efficient meshing of voxel chunks, as seen in open-source projects like *vercidium-patreon/meshing* [S3, unofficial].
