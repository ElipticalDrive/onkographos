# Greedy Voxel Mesh Optimization

Also called: CEVoxelGreedyOptimizer, Greedy Voxel Meshing

## Overview
Greedy Voxel Mesh Optimization is a greedy algorithm that optimizes voxel mesh generation by merging adjacent identical tiles into larger rectangular quads to reduce draw calls [S1, unofficial]. It operates on 2D slices (e.g., the XZ plane) of solid voxels, differing from its parent [Voxelization Optimization](3191-voxelization-optimization.md) by focusing on the geometric merging phase after occlusion culling [S1, unofficial]. It differs from [Disjoint Set Mesh Optimization](4495-disjoint-set-mesh-optimization.md) by using a simple iterative expansion rather than a Disjoint Set Union structure for the merging logic [S1, unofficial].

## How it works
**Inputs:**
- `_boundMin`: `Vector2Int` defining the minimum X and Y coordinates of the optimization range.
- `_boundMax`: `Vector2Int` defining the maximum X and Y coordinates of the optimization range.
- `_isSameTileCallback`: A function `Func<int, int, int, int, bool>` taking `(tileA.x, tileA.y, tileB.x, tileB.y)` returning `true` if tiles are identical/mergeable.
- `_isHaveTileCallback`: A function `Func<int, int, bool>` taking `(x, y)` returning `true` if a tile exists at that coordinate.

**Outputs:**
- A list of `GreedyOptimizeResult` structs, each containing `x`, `y`, `sizeX`, and `sizeY`, representing the top-left corner and dimensions of a merged tile [S1, unofficial].

**Data Structures:**
- `mProcessAreaDic`: A dictionary mapping `Vector2Int` (coordinates) to `bool`, marking tiles that have already been processed and included in a quad.
- `mResultList`: A list of `GreedyOptimizeResult` storing the final merged quads.
- `mBoundMin`, `mBoundMax`: Stored bounds for the current optimization pass.
- `mIsSameTileCallback`, `mIsHaveTileCallback`: Stored references to the callback functions.

**Algorithm Steps:**
1. Initialize `mResultList`, `mProcessAreaDic`, `mBoundMin`, `mBoundMax`, `mIsSameTileCallback`, and `mIsHaveTileCallback` from the input parameters [S1, unofficial].
2. Iterate `y` from `mBoundMin.y` to `mBoundMax.y` inclusive.
3. For each `y`, iterate `x` from `mBoundMin.x` to `mBoundMax.x` inclusive.
4. Call `DoProcessTile(x, y)` for each coordinate.
5. In `DoProcessTile(_nowX, _nowY)`:
   a. If `_nowX, _nowY` is in `mProcessAreaDic` or `!mIsHaveTileCallback(_nowX, _nowY)`, return immediately [S1, unofficial].
   b. Call `FindSameTileMaxX(_nowX, _nowY, _nowY, mBoundMax.x, out nowMaxX)` to find the maximum X extent of identical tiles in the current row starting from `_nowX` [S1, unofficial].
   c. Initialize `nowMaxY` to `_nowY` [S1, unofficial].
   d. Loop `checkY` from `_nowY + 1` to `mBoundMax.y` inclusive:
      i. Call `FindSameTileMaxX(_nowX, _nowY, checkY, nowMaxX, out checkMaxX)` [S1, unofficial].
      ii. If `!isHaveResult` or `checkMaxX < nowMaxX`, break the loop. This indicates either no tile exists or the tile type differs at the start of that row [S1, unofficial].
      iii. If the loop continues, set `nowMaxY = checkY` [S1, unofficial].
   e. Mark all tiles in the rectangle from `(_nowX, _nowY)` to `(nowMaxX, nowMaxY)` as processed in `mProcessAreaDic` [S1, unofficial].
   f. Add a new `GreedyOptimizeResult` to `mResultList` with `x=_nowX`, `y=_nowY`, `sizeX=nowMaxX-_nowX+1`, `sizeY=nowMaxY-_nowY+1` [S1, unofficial].
6. In `FindSameTileMaxX(_startX, _startY, _staticY, _maxSearchX, out _maxX)`:
   a. Initialize `isHaveResult = false` and `_maxX = _startX` [S1, unofficial].
   b. Loop `nowX` from `_startX` to `_maxSearchX` inclusive:
      i. If `(nowX, _staticY)` is in `mProcessAreaDic`, break [S1, unofficial].
      ii. If `!mIsHaveTileCallback(nowX, _staticY)`, break [S1, unofficial].
      iii. If `!mIsSameTileCallback(_startX, _startY, nowX, _staticY)`, break [S1, unofficial].
      iv. Update `_maxX = nowX` and `isHaveResult = true` [S1, unofficial].
   c. Return `isHaveResult` [S1, unofficial].

**Pseudocode:**

```python
def optimize_greedy(bound_min: Vector2Int, bound_max: Vector2Int, 
                    is_same_tile: Callable[[int, int, int, int], bool], 
                    is_have_tile: Callable[[int, int], bool]) -> List[GreedyOptimizeResult]:
    result_list = []
    process_area_dic = {}  # Key: Vector2Int, Value: bool
    m_bound_min = bound_min
    m_bound_max = bound_max
    m_is_same_tile = is_same_tile
    m_is_have_tile = is_have_tile

    def find_same_tile_max_x(start_x: int, start_y: int, static_y: int, max_search_x: int) -> tuple:
        """
        Returns (is_have_result, max_x)
        """
        is_have_result = False
        max_x = start_x
        for now_x in range(start_x, max_search_x + 1):
            pos = Vector2Int(now_x, static_y)
            if pos in process_area_dic:
                break
            if not m_is_have_tile(now_x, static_y):
                break
            if not m_is_same_tile(start_x, start_y, now_x, static_y):
                break
            max_x = now_x
            is_have_result = True
        return is_have_result, max_x

    def do_process_tile(now_x: int, now_y: int):
        pos = Vector2Int(now_x, now_y)
        if pos in process_area_dic or not m_is_have_tile(now_x, now_y):
            return

        # Step 1: Find max X in current row
        is_have_result, now_max_x = find_same_tile_max_x(now_x, now_y, now_y, m_bound_max.x)

        # Step 2: Extend vertically
        now_max_y = now_y
        for check_y in range(now_y + 1, m_bound_max.y + 1):
            is_have_result, check_max_x = find_same_tile_max_x(now_x, now_y, check_y, now_max_x)
            if not is_have_result or check_max_x < now_max_x:
                break
            now_max_y = check_y

        # Mark processed
        for writer_x in range(now_x, now_max_x + 1):
            for writer_y in range(now_y, now_max_y + 1):
                process_area_dic[Vector2Int(writer_x, writer_y)] = True

        # Add result
        result_list.append(GreedyOptimizeResult(
            x=now_x,
            y=now_y,
            size_x=now_max_x - now_x + 1,
            size_y=now_max_y - now_y + 1
        ))

    # Main loop
    for y in range(m_bound_min.y, m_bound_max.y + 1):
        for x in range(m_bound_min.x, m_bound_max.x + 1):
            do_process_tile(x, y)

    return result_list
```

**Parameters:**
- `_boundMin`: `Vector2Int` (Not given in the sources for typical values, but implied to cover the active voxel slice).
- `_boundMax`: `Vector2Int` (Not given in the sources for typical values).
- `_isSameTileCallback`: Callback for tile identity (Not given in the sources for typical implementation details, but typically compares voxel type/material).
- `_isHaveTileCallback`: Callback for tile existence (Not given in the sources for typical implementation details, but typically checks if the voxel is non-empty).

**Edge Cases and Pitfalls:**
- If `FindSameTileMaxX` returns false for a row above the current one (`checkY > _nowY`), the vertical expansion stops immediately because it indicates either no tile exists or the tile type differs at the start of that row [S1, unofficial].
- The algorithm assumes a 2D plane; for 3D volumes, this method is applied slice-by-slice [S1, unofficial].

## Subtopics

### [Disjoint Set Visible Plane Optimization](4045-disjoint-set-visible-plane-optimization.md)
Disjoint Set Visible Plane Optimization is a greedy meshing algorithm that optimizes a 2D slice (VisiblePlane) of solid voxels by merging contiguous regions of identical voxel IDs into single rectangular mesh quads using a Disjoint Set Union (DSU) data structure. It operates on pre-culled 2D planes rather than the full 3D volume, differing from its parent [Greedy Voxel Mesh Optimization](3979-greedy-voxel-mesh-optimization.md). It differs from [Disjoint Set Mesh Optimization](4495-disjoint-set-mesh-optimization.md) by focusing specifically on the plane-by-plane merging phase after occlusion culling.

### [Color Quantization](4893-color-quantization.md)
Color Quantization reduces the number of unique colors in a voxel grid to facilitate greedy meshing by snapping RGB values to discrete levels. It differs from its sibling [Disjoint Set Visible Plane Optimization](4045-disjoint-set-visible-plane-optimization.md) by operating on color attributes rather than geometric topology, ensuring that adjacent voxels with visually similar colors are treated as identical for the purpose of quad merging.

## Operating characteristics
**Time Complexity:**
- Not given in the sources. The algorithm iterates through each tile in the bound area once, and for each unprocessed tile, it expands to find the largest possible quad. The expansion involves checking adjacent rows and columns, which can be proportional to the size of the merged quad. In the worst case, it may approach $O(N^2)$ where $N$ is the number of tiles in the slice, but typically performs closer to $O(N)$ for large uniform regions.

**Memory Complexity:**
- $O(N)$ where $N$ is the number of tiles in the bound area, due to the `mProcessAreaDic` storing a boolean for each processed tile.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Not given in the sources.

**Strengths and Limitations:**
- Strengths: Simple to implement, effective at reducing draw calls for large uniform areas (e.g., Minecraft-like games) [S1, unofficial].
- Limitations: Greedy approach may not produce the globally optimal mesh (fewest quads) compared to more complex algorithms, but is often sufficient for real-time applications [S2, unofficial].

**When to Use:**
- When generating meshes for voxel engines where performance is critical and the voxel data consists of large uniform regions [S2, unofficial].

**When Not to Use:**
- When the globally optimal mesh is required, or when the voxel data is highly irregular with small uniform regions.

## Background
Greedy Voxel Mesh Optimization was popularized in the context of voxel engines, particularly those inspired by Minecraft. Mikola Lysenko provided a detailed description of various meshing methods, emphasizing the importance of quad ordering [S2, unofficial]. The specific implementation detailed in the sources, `CEVoxelGreedyOptimizer`, is an unofficial implementation found in a GitHub repository [S1, unofficial]. The technique is widely used in voxel-based games to improve rendering performance by reducing the number of draw calls [S2, unofficial].
