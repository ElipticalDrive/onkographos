# Octree Color Quantization

Also called: Octree quantization

## Overview
Octree color quantization is a method for reducing the number of unique colors in an image or voxel dataset by encoding color data into a hierarchical octree structure [S1]. It solves the problem of palette generation by dynamically partitioning the RGB color space based on the frequency of input colors, allowing the tree size to be constrained to a specific number of palette entries [S1]. Unlike static histogram-based methods, it adapts to the input distribution by pruning less significant branches, making it particularly effective for images with clustered color distributions [S1].

## How it works
**Inputs:** A list of RGB color values (e.g., pixels or voxel colors).
**Outputs:** A palette of $N$ representative colors and a mapping from original colors to palette indices.

**Data Structures:**
The core data structure is an octree. Each node contains:
- `children`: An array of 8 references to child nodes (one for each octant).
- `color_sum`: A 3-component vector (R, G, B) accumulating the sum of colors in the subtree.
- `count`: An integer representing the number of colors in the subtree.
- `is_leaf`: A boolean flag indicating if the node is a leaf.
- `bit_depth`: The current depth of the node in the tree (0 to 9).

**Parameters:**
- `max_depth`: The maximum depth of the octree. The sources specify a depth of 9 levels [S1].
- `target_palette_size`: The desired number of colors in the final palette.

**Algorithm Steps:**

1.  **Tree Construction (Insertion):**
    For each input color $C = (r, g, b)$:
    a. Start at the root node.
    b. Iterate from the most significant bit (MSB) to the least significant bit (LSB) of the color components. The sources specify a tree depth of 9, implying 3 bits per color channel (assuming 8-bit input, bits 7, 6, 5 are used) [S1].
    c. At each level $d$ (from 0 to 8), determine the child index $i$ using the $d$-th most significant bit of $r$, $g$, and $b$. The formula for the index is:
       $$ i = 4 \cdot r_d + 2 \cdot g_d + b_d $$
       where $r_d, g_d, b_d$ are the bits at the current significance level [S1].
    d. If the child node $i$ does not exist, create it.
    e. Update the `color_sum` and `count` of the current node and the new child node.
    f. Move to the child node.
    g. If the current depth is `max_depth - 1`, the node is a leaf. Store the color data in the leaf. The sources note that leaf nodes initially contain single bits of data accrual [S1].

2.  **Tree Reduction (Pruning):**
    If the number of leaf nodes exceeds `target_palette_size`:
    a. Identify leaf nodes with the smallest `count` (or smallest contribution to visual error, though sources suggest simple count-based pruning is common) [S1].
    b. Select a leaf node to prune.
    c. Merge its `color_sum` and `count` into its sibling nodes or parent, effectively averaging the bit data up into a leaf node [S1].
    d. Remove the leaf node from the tree structure.
    e. Repeat until the number of leaf nodes equals `target_palette_size`. The sources state that if much more than the desired number of palette colors are entered, the size can be continually reduced by seeking out a bottom-level node and averaging its bit data up [S1].

3.  **Color Extraction:**
    a. Traverse the tree to collect all leaf nodes.
    b. For each leaf node, calculate the representative color. The sources state that final colors can be chosen at the centroid of all colors in each octree bin:
       $$ C_{rep} = \left( \frac{R_{sum}}{Count}, \frac{G_{sum}}{Count}, \frac{B_{sum}}{Count} \right) $$
    c. Alternatively, sources note that choosing the color at the center of the octree bin has very little effect on the visual result compared to the centroid [S1]. The center of the bin can be derived from the path bits.

**Pseudocode:**

```python
class OctreeNode:
    def __init__(self, depth=0):
        self.depth = depth
        self.children = [None] * 8
        self.color_sum = [0, 0, 0]
        self.count = 0
        self.is_leaf = False

def get_child_index(r, g, b, bit):
    # Extract the bit at the given significance level (0=MSB, 2=LSB for 3 bits)
    # Assuming 8-bit input, bit 7 is MSB.
    # bit=0 -> bit 7, bit=1 -> bit 6, bit=2 -> bit 5
    shift = 7 - bit
    r_bit = (r >> shift) & 1
    g_bit = (g >> shift) & 1
    b_bit = (b >> shift) & 1
    return 4 * r_bit + 2 * g_bit + b_bit

def insert(root, r, g, b, max_depth):
    node = root
    node.color_sum[0] += r
    node.color_sum[1] += g
    node.color_sum[2] += b
    node.count += 1
    
    for bit in range(3): # 3 bits per channel for depth 9
        idx = get_child_index(r, g, b, bit)
        if node.children[idx] is None:
            node.children[idx] = OctreeNode(depth=node.depth + 1)
        node = node.children[idx]
        node.color_sum[0] += r
        node.color_sum[1] += g
        node.color_sum[2] += b
        node.count += 1
    node.is_leaf = True

def prune_leaves(root, target_count):
    # Helper to get all leaves and their counts
    leaves = []
    def collect_leaves(node):
        if node.is_leaf:
            leaves.append(node)
            return
        for child in node.children:
            if child:
                collect_leaves(child)
    
    collect_leaves(root)
    
    # Sort leaves by count ascending
    leaves.sort(key=lambda x: x.count)
    
    # Prune until target_count is reached
    while len(leaves) > target_count:
        leaf = leaves.pop(0)
        # Merge into parent (simplified: remove leaf, parent count remains, 
        # but leaf's contribution is lost from palette. 
        # More accurate: average with sibling or parent, but sources say "averaging bit data up")
        # For implementation simplicity based on "pruning part of the tree":
        # We simply remove the leaf from the active palette.
        # The parent's color_sum and count are already updated during insertion.
        # The leaf node is effectively ignored in extraction.
        pass

def extract_palette(root):
    palette = []
    def traverse(node):
        if node.is_leaf:
            if node.count > 0:
                avg_r = node.color_sum[0] / node.count
                avg_g = node.color_sum[1] / node.count
                avg_b = node.color_sum[2] / node.count
                palette.append((avg_r, avg_g, avg_b))
            return
        for child in node.children:
            if child:
                traverse(child)
    traverse(root)
    return palette
```

**Edge Cases and Pitfalls:**
- **Precision:** Using integer arithmetic for color sums can lead to overflow if the number of pixels is very large. Floating-point accumulation is recommended for `color_sum` [G].
- **Boundary Conditions:** If the input has fewer unique colors than `target_palette_size`, the tree will have fewer leaves than requested. The algorithm should handle this gracefully by returning all available leaves [G].
- **Bit Selection:** The sources specify using the most significant bits. Ignoring less significant bits reduces tree size but may introduce quantization error [S1].

## Subtopics

### Centroid vs. Center Selection
Choosing the centroid of colors in a bin vs. the geometric center of the bin. The centroid is more accurate but computationally more expensive. The sources state the visual difference is minimal [S1].

### Pruning Strategies
Different criteria for selecting which leaves to prune (e.g., lowest count vs. highest error). The sources mention seeking out bottom-level nodes but do not specify the exact metric beyond "averaging bit data up" [S1].

## Operating characteristics
- **Time Complexity:** Building the tree is $O(N \cdot D)$, where $N$ is the number of input colors and $D$ is the depth (9). Pruning is $O(L \log L)$ or $O(L)$ depending on implementation, where $L$ is the number of leaves. Extraction is $O(L)$.
- **Memory Complexity:** The tree size is bounded by the number of nodes, which is limited by the tree depth and pruning. It is highly memory efficient compared to storing all unique colors [S1].
- **Performance:** The algorithm is efficient for images with clustered colors. It may be less effective for images with uniformly distributed colors, as many leaves may be created and then pruned [G].
- **Strengths:** Adaptive to input data, memory efficient, simple implementation [S1].
- **Limitations:** Fixed depth limits resolution; pruning strategy affects quality; not suitable for real-time streaming without careful buffer management [G].

## Background
The octree color quantization algorithm was invented by Gervautz and Purgathofer in 1988 [S1]. It was developed as a method to reduce the number of colors in an image by encoding color data as an octree up to nine levels deep [S1]. Octrees are used because $2^3=8$ and there are three color components in the RGB system [S1]. The algorithm has been applied in various graphics contexts, including collision detection and sparse voxel octrees [S1].
