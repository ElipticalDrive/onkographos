# Volpack Run-Length Encoded Volume Classification and Storage

Also called: Volpack, VolPack Classified Volume Construction

## Overview
Volpack Run-Length Encoded Volume Classification and Storage is a pre-processing method that converts a dense voxel grid into three axis-aligned Run-Length Encoded (RLE) structures (one for X, Y, and Z viewing axes) to optimize ray casting by skipping transparent regions [S1, unofficial][S2]. It differs from standard RLE by classifying voxel data into opacity/material categories during construction and storing shading fields alongside quantized opacity, enabling the renderer to bypass empty space efficiently [S1, unofficial]. Unlike [Scan Offset Computation](4338-scan-offset-computation.md), which only provides lookup tables for ray entry points, this method fully constructs the compressed data streams for all three orthogonal axes, allowing the renderer to traverse runs sequentially along the viewing axis [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** An unclassified voxel grid (dense array), a classification function (transfer function), and optional scalar data [S1, unofficial][S2]. Parameters include `min_opacity` (threshold for non-transparent voxels) and boolean flags `skip_rle_x`, `skip_rle_y`, `skip_rle_z` to disable specific axis constructions [S1, unofficial][S2].
*   **Outputs:** Three RLE structures (`rle_x`, `rle_y`, `rle_z`), each containing a `data` array (shading + opacity) and a `lengths` array (run counts), plus `scan_offsets` for Y and Z axes to locate scanline starts in the 1D stream [S1, unofficial].

**Data Structures:**
1.  **Classified Voxel Layout:** Each voxel in the RLE data stream occupies `rle_bytes_per_voxel` bytes [S1, unofficial].
    *   Layout: `[shading_data_bytes] [opacity_byte]`.
    *   `shading_data_bytes`: `rle_bytes_per_voxel - 1` bytes.
    *   `opacity_byte`: 1 byte, quantized integer `opc_int = clamp(opacity * 255, 0, 255)` [S1, unofficial].
    *   `rle_bytes_per_voxel` calculation: Sum of maximum offsets of all shading fields + 1 (for opacity), padded to the byte boundary of the largest field: `rle_bytes_per_voxel = (sum_offsets + 1 + maxsize - 1) & ~(maxsize - 1)` [S1, unofficial].
2.  **RLE Structure:**
    *   `data`: Array of `unsigned char` containing the classified voxel data.
    *   `lengths`: Array of `unsigned char` containing run lengths.
    *   `scan_offsets`: Array of `ScanOffset` structs (size `zlen` for Y/Z axes). Each `ScanOffset` contains `first_data` (offset in `data` array) and `first_len` (offset in `lengths` array) [S1, unofficial].
3.  **Run Encoding:**
    *   Run lengths are stored as `unsigned char` (max 255) [S1, unofficial].
    *   Runs > 255 are split: `255`, `0`, `remainder`. The `0` acts as a marker for the split [S1, unofficial].
    *   A zero-length non-zero run (end of scanline) is stored as `0` [S1, unofficial].

**Algorithm Steps:**
The method can be invoked via three entry points, all building the same internal construction buffer (`cbuf`) before finalizing [S2]:

1.  **Initialization:**
    *   If `vpc->cbuf` is NULL, call `VPCheckClassifier` and `InitRLE` to set up buffers [S1, unofficial].
    *   Calculate `rle_bytes_per_voxel` based on configured shading fields [S1, unofficial].
    *   Initialize pointers: `data_buf = vpc->cbuf->data_buf_head`, `lengths_buf = vpc->cbuf->lengths_buf_head` [S1, unofficial].
    *   Initialize `x_run_length = 0`, `is_non_zero = 1` [S1, unofficial].

2.  **Processing (Per Scanline):**
    *   For each scanline (in Z-order, then Y-order, then X-voxels):
        *   If using an octree, use `VPComputeScanRuns` to skip zero-voxel runs and determine non-zero run lengths [S1, unofficial].
        *   Iterate through X-voxels (0 to `xlen-1`):
            *   If `x_run_length == 0`:
                *   Fetch next run length from `lengths_buf` [S1, unofficial].
                *   If `lengths_bytes_left <= 0`, advance buffer [S1, unofficial].
                *   If not skipping Z-RLE, copy to `z_lengths` [S1, unofficial].
                *   `x_run_length = *lengths++`, decrement `lengths_bytes_left` [S1, unofficial].
                *   Toggle `is_non_zero`, increment `z_length_offset` [S1, unofficial].
            *   Decrement `x_run_length`.
            *   If `is_non_zero`:
                *   Fetch voxel data from `data_buf` if needed (similar buffer management) [S1, unofficial].
                *   Call `StoreNonZeroVoxel` for X-axis RLE (if not skipping) and Y-axis RLE (if not skipping) [S1, unofficial].
                *   Increment `data` by `rle_bytes_per_voxel`, decrement `data_bytes_left`, increment `z_data_offset` [S1, unofficial].
            *   Else (transparent):
                *   Update zero-run counters if a gap exists between current index and last processed index (`rundata->next_index != index`) [S1, unofficial].
                *   Write out previous non-zero run and intervening zero run [S1, unofficial].
                *   Split runs > 255 as described [S1, unofficial].
        *   Finalize X-axis statistics: `CountNonZeroVoxel(&rundata_x, x, 1, vpc)` [S1, unofficial].
        *   Update construction buffer: `cbuf->non_zero_count += rundata_x.p.p1.non_zero_count; cbuf->x_run_count += rundata_x.p.p1.run_count;` [S1, unofficial].

3.  **Finalization (End of Volume):**
    *   If current scanline is last in Z-dimension (`++cbuf->next_z == zlen`):
        *   Call `RepackClassifiedVolume` [S1, unofficial].
        *   If `non_zero_count == 0`, create empty RLE structures using `CreateEmptyRLEVoxels` [S1, unofficial].
        *   Allocate Y and Z RLE structures using `CreateRLEVoxelsFromRunData` with pre-computed run data [S1, unofficial].
        *   Allocate X RLE structure using `VPCreateRLEVoxels` and `scan_offsets` array of size `zlen * sizeof(ScanOffset)` [S1, unofficial].
        *   Set `vpc->rle_z->scan_offsets[z].first_data` and `first_len` based on `z_data_offset` and `z_length_offset` parity [S1, unofficial].
        *   Call `PadScanlines` for Y and Z axes if not skipping [S1, unofficial].
        *   Destroy construction buffer [S1, unofficial].

**Pseudocode:**
```python
def volpack_classify_volume(vpc, xlen, ylen, zlen, min_opacity=0.0, skip_rle_x=False, skip_rle_y=False, skip_rle_z=False):
    # 1. Initialization
    if vpc.cbuf is None:
        vp_check_classifier(vpc)
        init_rle(vpc)

    rle_bytes_per_voxel = calculate_rle_bytes(vpc)
    data_buf = vpc.cbuf.data_buf_head
    lengths_buf = vpc.cbuf.lengths_buf_head
    x_run_length = 0
    is_non_zero = 1
    z_data_offset = 0
    z_length_offset = 0

    for z in range(zlen):
        if not skip_rle_z:
            vpc.rle_z.scan_offsets[z].first_data = z_data_offset
            vpc.rle_z.scan_offsets[z].first_len = z_length_offset

    for y in range(ylen):
        rundata_y = vpc.cbuf.rundata_y[z]

        for x in range(xlen):
            while x_run_length == 0:
                if vpc.cbuf.lengths_bytes_left <= 0:
                    # Advance to next buffer [G]
                    lengths_buf = vpc.cbuf.next_lengths_chunk
                    vpc.cbuf.lengths_bytes_left = len(lengths_buf)
                if not skip_rle_z:
                    vpc.cbuf.z_lengths.append(lengths_buf[0])
                x_run_length = lengths_buf[0]
                lengths_buf = lengths_buf[1:]
                vpc.cbuf.lengths_bytes_left -= 1
                is_non_zero = 1 - is_non_zero
                z_length_offset += 1

            x_run_length -= 1

            if is_non_zero:
                if vpc.cbuf.data_bytes_left <= 0:
                    # Advance to next buffer [G]
                    data_buf = vpc.cbuf.next_data_chunk
                    vpc.cbuf.data_bytes_left = len(data_buf)
                voxel_data = data_buf[0]
                data_buf = data_buf[1:]
                vpc.cbuf.data_bytes_left -= 1

                if not skip_rle_x:
                    # Append run to X RLE [G]
                    vpc.rle_x.lengths.append(x_run_length)
                    vpc.rle_x.data.extend([voxel_data] * x_run_length)
                if not skip_rle_y:
                    # Append run to Y RLE [G]
                    vpc.rle_y.lengths.append(x_run_length)
                    vpc.rle_y.data.extend([voxel_data] * x_run_length)

                data_buf = data_buf[rle_bytes_per_voxel:]
                z_data_offset += 1
            else:
                if rundata_y.next_index != x:
                    # Write out previous non-zero run and intervening zero run [S1, unofficial]
                    # Runs > 255 are split into 255, 0, remainder [S1, unofficial]
                    pass

        # Finalize X-axis statistics [S1, unofficial]
        vpc.cbuf.non_zero_count += rundata_y.p.p1.non_zero_count
        vpc.cbuf.x_run_count += rundata_y.p.p1.run_count

    if vpc.cbuf.next_z == zlen:
        repack_classified_volume(vpc, xlen, ylen, zlen, skip_rle_x, skip_rle_y, skip_rle_z)
        destroy_construction_buffer(vpc)
```

**Parameters:**
*   `min_opacity`: Float threshold [0.0, 1.0]. Voxels with opacity below this are treated as transparent. Typical value not specified in code, but example uses 0.05 [S1, unofficial][S2].
*   `skip_rle_x`, `skip_rle_y`, `skip_rle_z`: Boolean flags. If true, the respective RLE structure is not computed [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Run Length > 255:** Must be split into `255`, `0`, `remainder` because lengths are `unsigned char` [S1, unofficial].
*   **Out-of-order Scanlines:** Not supported. Scanlines must be processed in Z, then Y, then X order [S2].
*   **Single Volume Context:** Only one classified volume can exist in a rendering context. Starting a new classification deallocates the old one [S2].
*   **Incomplete Volume:** Rendering cannot begin until all scanlines are loaded and `RepackClassifiedVolume` is called [S2].
*   **Empty Volume:** If `non_zero_count == 0`, empty RLE structures are created [S1, unofficial].

## Subtopics

### [Scan Offset Computation](4338-scan-offset-computation.md)
Generates the lookup table mapping 2D scanline coordinates $(j, k)$ to starting positions in the 1D RLE stream. It solves the problem of efficiently locating the beginning of a ray's traversal without scanning the entire RLE array. Unlike [ComputeIndex](52-compute-index.md), which maps every voxel coordinate to a specific run position, this method only stores starting offsets for each scanline $(j, k)$, requiring the renderer to traverse the RLE runs sequentially along the $i$-axis to find specific voxels.

## Operating characteristics
*   **Time Complexity:** Pre-processing is $O(N)$ where $N$ is the number of voxels, as each voxel is visited once. Finalization is $O(M)$ where $M$ is the number of runs [G].
*   **Memory Complexity:** $O(N)$ for the input volume, plus $O(M)$ for the RLE structures. Not given in the sources.
*   **Measured Performance:** The RLE structure is described as the "fastest rendering algorithm" provided by VolPack because it skips transparent regions entirely during ray casting [S2].
*   **Scaling:** Performance gains increase with volume sparsity. Dense volumes see less benefit from skipping but still benefit from the compact storage and cache-friendly sequential access [G].
*   **Strengths:** Fast rendering due to run skipping; compact storage for sparse volumes; supports three viewing axes for optimal ray traversal [S2].
*   **Limitations:** High pre-processing time and memory overhead; out-of-order scanline loading is not supported; only one classified volume per context [S2].
*   **When to Use:** When rendering sparse volumes with significant transparent regions and when pre-processing time is acceptable.
*   **When Not to Use:** For dense volumes with little transparency, or when dynamic updates require frequent re-classification.

## Background
Volpack was developed by William M. Newman's group at Stanford University. The method is described in the VolPack User's Guide and associated source code [S2]. It was designed to provide efficient volume rendering for medical imaging and scientific visualization, leveraging the sparsity of volumetric data [S1, unofficial][S2]. The RLE classification technique is described as the fastest rendering algorithm provided by VolPack [S2].
