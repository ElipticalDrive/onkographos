# ArrayMesh Byte Reader

Also called: Godot ArrayMesh Byte Reader

## Overview
The ArrayMesh Byte Reader is a data conversion utility within the Godot engine that interprets raw byte arrays into `ArrayMesh` geometry structures. It solves the problem of efficiently transferring pre-computed vertex and index data from script or plugin layers into the engine's rendering backend without intermediate serialization overhead. It is distinguished from general voxel file I/O methods by its specific handling of signed integer normalization (mapping -1 to 255) and its role as an internal bridge rather than a disk-based format parser.

## How it works
**Inputs and Outputs:**
- Input: A `PackedByteArray` containing raw binary data representing vertex positions, normals, colors, or indices.
- Output: An `ArrayMesh` instance populated with `ArrayMesh.ARRAY_*` arrays.

**Data Structures:**
The reader processes bytes based on the target `ArrayMesh` array type. For color data, it expects 8-bit unsigned integers (0-255). A specific edge case involves signed byte interpretation: if the source data contains a value of -1 (0xFF in two's complement), the reader normalizes it to 255 to fit the unsigned 8-bit color channel range [S1, unofficial].

**Numbered Steps:**
1. Initialize an empty `ArrayMesh`.
2. Determine the array format (e.g., `ARRAY_POSITION`, `ARRAY_COLOR`).
3. Iterate through the input `PackedByteArray`.
4. For color arrays, read each byte. If the byte value is interpreted as a signed integer equal to -1, convert it to 255 [S1, unofficial].
5. Append the processed values to the corresponding `ArrayMesh` array.
6. Commit the mesh to the renderer.

**Formulas:**
For color normalization:
$$ C_{out} = \begin{cases} 255 & \text{if } C_{in} = -1 \\ C_{in} & \text{otherwise} \end{cases} $$
Where $C_{in}$ is the signed byte value and $C_{out}$ is the stored unsigned byte value.

**Parameters:**
- Normalization threshold: -1 maps to 255.

**Edge Cases and Pitfalls:**
- **Signed/Unsigned Ambiguity:** The reader must correctly interpret the source byte as signed to detect the -1 value before storing it as unsigned [S1, unofficial].
- **HDR Channels:** Note that while this reader handles standard 8-bit colors, other Godot texture systems (like `GradientTexture2D`) may handle HDR channels above 1.0, but the ArrayMesh byte reader is strictly for mesh attributes [S1, unofficial].

**Pseudocode:**

```python
def read_array_mesh_bytes(byte_array: list[int], array_type: str) -> ArrayMesh:
    mesh = ArrayMesh()
    
    if array_type == "ARRAY_COLOR":
        colors = []
        for byte_val in byte_array:
            # Interpret as signed 8-bit integer
            signed_val = byte_val if byte_val < 128 else byte_val - 256
            
            # Normalize -1 to 255 as per Godot implementation
            if signed_val == -1:
                colors.append(255)
            else:
                colors.append(signed_val)
        
        mesh.add_array_mesh_array(ArrayMesh.ARRAY_COLOR, colors)
```

### MZ3 Mesh Parser
- **What it is:** A parser for the binary MZ3 mesh format, often used in neuroimaging tools.
- **What sets it apart:** It supports optional gzip compression and parses a specific header structure with a magic signature.
- **When to choose it:** When loading MZ3 files generated by tools like `nii2mesh`.
- **Link:** [MZ3 Mesh Parser](2862-mz3-mesh-parser.md) (Hypothetical link based on sibling structure; no article exists yet).
- **Definition:** Parses a binary MZ3 mesh file, supporting optional gzip compression, to extract triangle indices and vertex coordinates into dynamically allocated arrays.
- **Step:** Open file. Read packed header. Check signature 23117. If missing and `HAVE_ZLIB`, try `gzopen`. Read header from gz. Read `NFACE` triangles (vec3i). Read `NVERT` vertices as float (3 per vertex). Convert to vec3d array. Free temporary buffers.
- **Parameter:** `SIGNATURE`: magic number, expected 23117. `NSKIP`: bytes to skip after header before triangle data.
- **Layout:** `mz3hdr` struct: `uint16_t SIGNATURE`, `uint16_t ATTR`, `uint32_t NFACE`, `uint32_t NVERT`, `uint32_t NSKIP`. Packed with `__attribute__((__packed__))` or `#pragma pack(2)`.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of bytes in the input array.
- **Memory Complexity:** Linear with respect to the number of vertices/indices generated.
- **Strengths:** Low overhead for in-memory mesh generation; handles specific normalization quirks required by Godot's rendering pipeline.
- **Limitations:** Specific to Godot's internal data structures; not a general-purpose file format reader.
- **When to use:** When generating meshes from script-level byte data in Godot.
- **When not to use:** For loading mesh files from disk (use [Binvox File Parsing](2862-binvox-file-parsing.md) or [MZ3 Mesh Parser](2862-mz3-mesh-parser.md) instead).

## Background
The ArrayMesh Byte Reader is part of Godot's core engine, specifically within the `variant_parser.cpp` and `array_mesh.cpp` modules. The specific normalization of -1 to 255 was implemented to handle edge cases in color data interpretation [S1, unofficial]. It is not a standalone file format but an internal API component.
