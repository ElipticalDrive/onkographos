# PLY Mesh Loader & Normal Calculator

Also called: PLY Header & Face Parser, Voxel Generation: PLY Loading, loadPLY

## Overview
This method parses ASCII PLY (Polygon File Format) files to extract vertex coordinates and triangle face indices, normalizes the mesh geometry into a canonical $[0,1]^3$ bounding box, and computes per-face normals via cross products. It serves as the bridge between raw mesh assets and the voxelization pipeline by providing clean, normalized, and oriented geometric data. It differs from its sibling [OBJ Mesh Loader & Triangulator](12664-obj-mesh-loader-triangulator.md) by targeting the PLY format specifically and lacking built-in triangulation for non-triangular faces, whereas the OBJ loader explicitly handles polygon-to-triangle conversion.

## How it works
**Inputs:** Path to an ASCII PLY file.
**Outputs:** 
- `vertex_arr`: Flat array of floats, size $3 \times N_v$, containing normalized $(x, y, z)$ coordinates.
- `faces_arr`: Flat array of integers, size $3 \times N_f$, containing 0-based vertex indices for each triangle.
- `normal_arr`: Flat array of floats, size $3 \times N_v$, initialized to zero (accumulated normals).

**Data Structures:**
- `Vertex_Buffer`: Temporary storage for raw vertex coordinates during parsing.
- `Faces_Triangles`: Temporary storage for raw face indices.
- Bounds: `min_x, min_y, min_z` and `max_x, max_y, max_z` initialized to extreme values (e.g., $\infty, -\infty$).

**Steps:**

1. **Open and Parse Header:**
   Open the file. Read lines until the token `end_header` is encountered. Use string parsing (e.g., `sscanf`) to extract `TotalConnectedPoints` (vertex count $N_v$) and `TotalFaces` (face count $N_f$) from the header metadata [S1, S2, unofficial].

2. **Read Vertices and Compute Bounds:**
   Loop $i$ from $0$ to $N_v - 1$:
   - Read three floats $x, y, z$ from the current line.
   - Store in `Vertex_Buffer[i*3]`, `Vertex_Buffer[i*3+1]`, `Vertex_Buffer[i*3+2]` [S2, unofficial].
   - Update bounds:
     $$
     \begin{aligned}
     min\_x &= \min(min\_x, x), & max\_x &= \max(max\_x, x) \\
     min\_y &= \min(min\_y, y), & max\_y &= \max(max\_y, y) \\
     min\_z &= \min(min\_z, z), & max\_z &= \max(max\_z, z)
     \end{aligned}
     $$
   [S1, unofficial].

3. **Normalize Vertices:**
   Compute scale factor $S$ as the maximum dimension of the bounding box:
   $$
   S = \max(max\_x - min\_x, \ max\_y - min\_y, \ max\_z - min\_z)
   $$
   [S1, unofficial].
   For each vertex $i$ with raw coordinates $(x_i, y_i, z_i)$, compute normalized coordinates $(x'_i, y'_i, z'_i)$:
   $$
   \begin{aligned}
   x'_i &= \frac{x_i - min\_x}{S} \\
   y'_i &= 1.0 - \frac{y_i - min\_y}{S} \\
   z'_i &= \frac{z_i - min\_z}{S}
   \end{aligned}
   $$
   [S1, unofficial]. Note the inversion of the Y-axis ($1.0 - \dots$) to align with typical graphics coordinate systems where Y points up [S1, unofficial]. Store results in `vertex_arr`.

4. **Read Faces:**
   Loop $j$ from $0$ to $N_f - 1$:
   - Read the face line. Parse the first integer $n$ (number of vertices in the face) followed by vertex indices [S1, S2, unofficial].
   - **Pitfall:** The reference implementation assumes $n=3$ (triangles). If $n=4$ (quads), the face is skipped or left unprocessed in the provided snippet [S2, unofficial].
   - For triangles ($n=3$), parse indices $v_1, v_2, v_3$. These are treated as 0-based directly from the file [S2, unofficial].
   - Store $v_1, v_2, v_3$ in `faces_arr` [S1, S2, unofficial].

5. **Compute Face Normals:**
   Initialize `normal_arr` of size $3 \times N_v$ to zeros [S1, unofficial].
   For each triangle $j$ with vertices $p_1, p_2, p_3$ (from `vertex_arr`):
   - Compute edge vectors:
     $$
     \vec{d_1} = p_2 - p_1, \quad \vec{d_2} = p_3 - p_1
     $$
     [S1, unofficial].
   - Compute unnormalized normal via cross product:
     $$
     \vec{n}_{raw} = \vec{d_1} \times \vec{d_2}
     $$
     [S1, S2, unofficial].
   - Compute magnitude:
     $$
     val = \sqrt{n_{raw,x}^2 + n_{raw,y}^2 + n_{raw,z}^2}
     $$
     [S2, unofficial].
   - Normalize:
     $$
     \vec{n} = \frac{\vec{n}_{raw}}{val}
     $$
     [S2, unofficial].
   - Accumulate $\vec{n}$ into the `normal_arr` entries corresponding to $p_1, p_2, p_3$ [S1, unofficial]. (Note: The source implies accumulation but does not explicitly detail the per-vertex accumulation loop, only the face normal calculation [S1, S2, unofficial]).

## Subtopics

### [OBJ Mesh Loader & Triangulator](12664-obj-mesh-loader-triangulator.md)
Reads an OBJ file, extracts vertices and faces, and ensures all polygons are triangulated. It differs by parsing the Wavefront OBJ format and explicitly handling triangulation, which this method does not.

## Operating characteristics
- **Time Complexity:** $O(N_v + N_f)$ for parsing and normalization. Normal calculation is $O(N_f)$.
- **Memory Complexity:** $O(N_v + N_f)$ to store vertices, faces, and normals.
- **Strengths:** Simple, robust for ASCII PLY files; provides normalized coordinates ready for voxelization.
- **Limitations:** Does not handle binary PLY files (only ASCII as per source [S1, S2, unofficial]); does not triangulate quads or higher-order polygons [S2, unofficial]; assumes 0-based indexing [S2, unofficial].
- **When to use:** When the input asset is an ASCII PLY file and the mesh is already triangular.
- **When not to use:** For binary PLY files, non-triangular meshes, or when OBJ format is the source.

## Background
This method originates from the Sparse Voxel Octree Raycasting project by sp4cerat [S1, unofficial] and the SVO Workbench by skyfex [S2, unofficial]. It is used in voxelization pipelines to convert mesh data into a format suitable for sparse voxel grid construction.
