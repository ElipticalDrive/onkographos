# FAV (Fabricatable Voxel) Format

Also called: Fabricatable Voxel

## Overview
FAV (Fabricatable Voxel) is a voxel-based 3D data format that represents models as a 3D buildup of volume cells (voxels) on a grid, allowing free design of internal structures, materials, colors, and connection intensities [S1]. Unlike mesh-based formats (STL, AMF, 3MF) which are limited to surface definitions, FAV enables intensive 3D structure modeling and seamless data flow to 3D printers by retaining optimized information for fabrication [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** None explicitly defined for the format itself; it is a storage/transport format [S1].
*   **Output:** An XML document representing a 3D voxel model [S1].

**Data Structures:**
The format is an XML tree. Key elements and their attributes/contents are:

1.  `<metadata>`: Contains `<author>`, `<license>`, `<title>` [S1].
2.  `<palette>`: Contains definitions for basic information [S1].
    *   `<geometry (ID, Name)>`: Defines voxel `<shape>` and `<scale>` for grid cells. Can refer to an external file [S1].
    *   `<material (ID, Name)>`: Defines material information (e.g., ABS, PLA, ISO standard, product code, URL) [S1].
3.  `<voxel (ID, Name)>`: Defines a voxel unit [S1].
    *   References `<geometry>` ID and `<material>` ID [S1].
    *   For hybrid materials, multiple `<material>` entries are defined with a `<ratio>` [S1].
    *   Can hold arbitrary properties [S1].
4.  `<object (ID, Name)>`: Defines the actual 3D model data [S1].
    *   Contains `<grid>` [S1].
5.  `<grid>`: Defines the space for voxel buildup [S1].
    *   `<origin>`: Distance from global origin [S1].
    *   `<unit>`: Cell size [S1].
    *   `<dimension>`: Max number of voxels in each axis [S1].
    *   `<structure (Compression)>`: Maps voxels to the grid [S1].
        *   Contains `<voxel_map>`, `<color_map>`, `<link_map>` [S1].
        *   Each map is defined separately by layer [S1].
6.  `<structure (Compression)>`:
    *   Attribute `Compression`: Options are 'none' (uncompressed), 'Base64', or 'ZLIB' (compressed) [S1].
7.  `<voxel_map (bit_per_voxel=8)>`:
    *   Stores shape/attributes [S1].
    *   Layout: Connected voxel lines for `dimension.y` arranged for `dimension.x` [S1].
    *   Encoding: Two hexadecimal characters express one voxel [S1].
    *   Value: If a voxel exists, its `<voxel>` ID is specified; if not, 0 is specified [S1].
8.  `<color_map (color_mode)>`:
    *   Stores full-color info [S1].
    *   Modes: Grayscale, RGB, CYMK [S1].
    *   Layout: Connected color value lines for `dimension.y` arranged for `dimension.x` [S1].
    *   Encoding: Six hexadecimal characters express one voxel's color in RGB format [S1].
    *   Omission: If `voxel_map` specifies 0, color info is omitted from the map [S1].
9.  `<link_map (neighbors)>`:
    *   Stores connection intensity [S1].
    *   Neighbors: 6, 18, or 26 [S1].
    *   Layout: Connected link value lines for `dimension.y` arranged for `dimension.x` [S1].
    *   Encoding: Twelve hexadecimal characters express one voxel's link information for 6 neighbors [S1].
    *   Omission: If `voxel_map` specifies 0, link info is omitted from the map [S1].

**Steps:**
1.  Register basic information to `<palette>` [S1].
2.  Define `<voxel>` using some basic information on `<palette>` [S1].
3.  Carry out modeling of a three-dimensional structure and attributes by buildup of `<voxel>` on a three-dimensional grid [S1].

**Pseudocode:**
```python
def parse_fav_layer(voxel_hex: str, color_hex: str, link_hex: str, dim_x: int, dim_y: int, neighbors: int = 6) -> dict:
    """
    Parses a single layer's structure from FAV hex streams.
    voxel_hex: hex string for voxel_map (2 chars/voxel)
    color_hex: hex string for color_map (6 chars/voxel for RGB, omitted for 0 voxels)
    link_hex:  hex string for link_map (12 chars/voxel for 6 neighbors, omitted for 0 voxels)
    dim_x, dim_y: grid dimensions
    neighbors: 6, 18, or 26 (determines link data size)
    Returns a dict with 'voxels', 'colors', 'links' as 2D lists [dim_x][dim_y].
    """
    voxels = []
    colors = []
    links = []
    
    # Decode voxel map (fixed size: 1 byte per voxel)
    voxel_bytes = bytes.fromhex(voxel_hex)
    voxel_idx = 0
    
    for x in range(dim_x):
        row_v = []
        row_c = []
        row_l = []
        for y in range(dim_y):
            if voxel_idx < len(voxel_bytes):
                vid = voxel_bytes[voxel_idx]
                voxel_idx += 1
                row_v.append(vid)
                if vid == 0:
                    row_c.append(None)
                    row_l.append(None)
                else:
                    # Read color data (3 bytes for RGB)
                    c_start = len(bytes.fromhex(color_hex)) - len(bytes.fromhex(color_hex[6:])) # Simplified stream tracking
                    # In practice, parsers maintain a single byte pointer per stream
                    pass 
            else:
                row_v.append(0)
                row_c.append(None)
                row_l.append(None)
        voxels.append(row_v)
        colors.append(row_c)
        links.append(row_l)
        
    # Correct stream-based parsing for variable-length maps:
    voxels = []
    colors = []
    links = []
    
    voxel_bytes = bytes.fromhex(voxel_hex)
    color_bytes = bytes.fromhex(color_hex)
    link_bytes = bytes.fromhex(link_hex)
    
    v_ptr, c_ptr, l_ptr = 0, 0, 0
    c_bytes_per_voxel = 3  # RGB = 6 hex chars
    l_bytes_per_voxel = neighbors // 2  # 12 hex chars = 6 bytes for 6 neighbors
    
    for x in range(dim_x):
        row_v = []
        row_c = []
        row_l = []
        for y in range(dim_y):
            if v_ptr < len(voxel_bytes):
                vid = voxel_bytes[v_ptr]
                v_ptr += 1
                row_v.append(vid)
                if vid == 0:
                    row_c.append(None)
                    row_l.append(None)
                else:
                    # Read color
                    if c_ptr + c_bytes_per_voxel <= len(color_bytes):
                        row_c.append(color_bytes[c_ptr:c_ptr + c_bytes_per_voxel])
                        c_ptr += c_bytes_per_voxel
                    else:
                        row_c.append(None)
                    # Read link
                    if l_ptr + l_bytes_per_voxel <= len(link_bytes):
                        row_l.append(link_bytes[l_ptr:l_ptr + l_bytes_per_voxel])
                        l_ptr += l_bytes_per_voxel
                    else:
                        row_l.append(None)
            else:
                row_v.append(0)
                row_c.append(None)
                row_l.append(None)
        voxels.append(row_v)
        colors.append(row_c)
        links.append(row_l)
        
    return {'voxels': voxels, 'colors': colors, 'links': links}
```

**Parameters:**
*   `bit_per_voxel`: Default 8 [S1].
*   `color_mode`: Grayscale, RGB, CYMK [S1].
*   `neighbors`: 6, 18, or 26 [S1].
*   `compression`: 'none', 'Base64', 'ZLIB' [S1].

**Edge Cases and Pitfalls:**
*   **Omission of Data:** If `voxel_map` specifies 0 (no voxel), color and link info are omitted from their respective maps [S1]. The parser must sequentially consume fixed-size hex blocks and skip them when a voxel is absent, rather than relying on fixed grid indexing [S1].
*   **Hex Encoding:** Voxel IDs are 2 hex chars, Colors are 6 hex chars (RGB), Links are 12 hex chars (6 neighbors) [S1]. Ensure correct byte conversion.
*   **Grid Layout:** The arrangement of voxels in the map is "connected voxel lines for dimension.y arranged for dimension.x" [S1]. This implies the data is structured as `dimension_x` lines, each of length `dimension_y` [S1].

### Hierarchical Sparse Voxel Format (glTF-based)
A glTF-based format for sparse voxels. Choose when interoperability with web-based 3D viewers and glTF ecosystems is required [G]. [Hierarchical Sparse Voxel Format (glTF-based)](13799-hierarchical-sparse-voxel-format-gltf-based.md)

### Comparison
FAV is XML-based and designed for intensive 3D structure modeling and 3D printing, allowing free internal structure design [S1]. Hierarchical Sparse Voxel Format is glTF-based, likely optimized for sparse data and web rendering [G].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1].
*   **Memory Complexity:** Not given in the sources [S1].
*   **Measured Performance:** Not given in the sources [S1].
*   **Strengths:** Allows free design of internal structures, materials, colors, and connection intensities at each voxel position [S1]. Enables complex microstructures and varied material distributions [S1]. Seamless data flow to 3D printers [S1]. Retains optimized information for fabrication [S1].
*   **Limitations:** XML-based, which may be verbose. Limited to voxel-based representation.
*   **When to Use:** Intensive 3D structure modeling, seamless data flow to 3D printers, 3D half-toning, enhancing expressiveness of 3D printers [S1].
*   **When Not to Use:** When surface-only representation is sufficient (use STL/AMF/3MF) [S1]. When sparse data efficiency is critical and glTF interoperability is needed [G].

## Background
FAV (Fabricatable Voxel) was proposed in 2016 to effectively utilize the abilities of current 3D printers by retaining optimized information for fabrication [S1]. It was released as a specification in July 2016 [S1]. It addresses the limitations of mesh-based formats (STL, AMF, 3MF) which are limited to surface definitions and predefined internal patterns [S1]. FAV allows for intensive and minute design of internal structures and attributes [S1].
