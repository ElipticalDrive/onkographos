# Hierarchical Sparse Voxel Format (glTF-based)

Also called: OpenVoxelFileFormat, Voxel Chunk Format, Voxel Volume Data Format & Encoding, glTF-based Voxel Format

## Overview
A hierarchical sparse voxel data format that divides a single voxel object into volumes and primitives (chunks) to handle sparsity, modeled after glTF's mesh/primitive structure [S1, unofficial]. It differs from its sibling [Voxel Interchange Format Serialization](7065-voxel-interchange-format-serialization.md) by introducing a hierarchical structure of volumes and primitives rather than a flat 1D array, allowing for efficient storage of large, sparse 3D scenes [S1, unofficial].

## How it works
**Inputs:** A 3D voxel scene with sparse occupancy represented as a hierarchical structure of volumes and primitives [S1, unofficial].
**Outputs:** A JSON structure mirroring glTF conventions containing `voxelVolumes` and a binary buffer for voxel data [S1, unofficial].

**Data Structures:**
1.  **Voxel Volume:** An object containing an array of primitives. It defines the global bounds and attributes for a set of voxels [S1, unofficial].
    *   `voxelVolumes`: Array of volume objects [S1, unofficial].
    *   `attributes`: Array of attribute definitions (semantic, componentType, normalized) [S1, unofficial].
    *   `primitives`: Array of primitive objects [S1, unofficial].
2.  **Primitive:** Defines a 3D box volume within the Voxel Volume [S1, unofficial].
    *   `position`: 3 integers representing the offset coordinates (min corner) of the box [S1, unofficial].
    *   `size`: 3 unsigned integers representing the volume dimensions [S1, unofficial].
    *   `material`: Integer index to a palette or single material [S1, unofficial].
    *   `bufferView`: Reference to the underlying data buffer [S1, unofficial].
3.  **Buffer View:** References the underlying binary data [S1, unofficial].
    *   `buffer`: Index into the glTF buffer array [S1, unofficial].
    *   `byteOffset`: Start of voxel data in the buffer [S1, unofficial].
    *   `byteLength`: Size of voxel data in bytes [S1, unofficial].
4.  **Voxel Record (Binary):** A variable-length record for a run of voxels, preceded by a Presence Bitmask [S1, unofficial].
    *   **Presence Bitmask:** A leading bitfield specifying which attributes follow [S1, unofficial].
    *   **Attributes:** Variable fields based on the mask [S1, unofficial].

**Numbered Steps:**
1.  **Parse Presence Bitmask:** Read the first $N$ bits of the voxel record, where $N$ is the number of defined attributes. Each bit corresponds to an attribute in the `attributes` array [S1, unofficial].
    *   Example: For attributes `[MATERIAL_INDEX, DENSITY, RLE_LENGTH]`, bit 0 is `MATERIAL_INDEX`, bit 1 is `DENSITY`, bit 2 is `RLE_LENGTH` [S1, unofficial].
    *   Mask `111` (binary) indicates all three attributes follow [S1, unofficial]. Mask `110` indicates `MATERIAL_INDEX` and `DENSITY` follow, but `RLE_LENGTH` is omitted (implying a single voxel) [S1, unofficial].
2.  **Decode Attributes:** Based on the bitmask, read the subsequent bytes [S1, unofficial].
    *   `MATERIAL_INDEX`: 8-bit unsigned integer [S1, unofficial].
    *   `DENSITY`: 8-bit unsigned integer, normalized [S1, unofficial].
    *   `RLE_LENGTH`: 8-bit unsigned integer [S1, unofficial].
3.  **Handle RLE Length:** If `RLE_LENGTH` is present, the value represents the number of voxels in the run minus 2 [S1, unofficial]. Value 0 represents exactly 2 voxels [S1, unofficial]. 0-voxel runs are never stored [S1, unofficial]. 1-voxel runs are encoded with the explicit length field (presence bit set) [S1, unofficial]. If the mask excludes `RLE_LENGTH`, it is a single voxel [S1, unofficial].
4.  **Repeat:** Continue reading voxel records until the `byteLength` of the buffer view is exhausted [G].

**Formulas:**
*   Voxel Count from RLE: $C = \text{RLE\_LENGTH} + 2$ [S1, unofficial].
*   Total Voxels in Primitive: $\sum C_i$ for all records $i$ in the primitive's buffer view [G].

**Parameters:**
*   `RLE_COUNT_BIT_DEPTH`: 8-bit unsigned integer is proposed as a starting default [S1, unofficial].
*   `MATERIAL_INDEX`: 8-bit unsigned integer [S1, unofficial].
*   `DENSITY`: 8-bit unsigned integer, normalized [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **RLE Length 0:** Represents 2 voxels, not 0 [S1, unofficial].
*   **JSON Integer Precision:** JSON integers use double precision, which may exceed glTF reader capabilities and cause implementation variance across readers [S1, unofficial].
*   **Terminology:** This format uses 'DENSITY' where Roblox's voxel Disk format uses 'OCCUPANCY' for the same attribute concept [S1, unofficial].

**Pseudocode:**
```python
def decode_voxel_primitive(buffer_bytes, attributes):
    """
    Decodes a voxel primitive from a binary buffer.
    
    Args:
        buffer_bytes: bytes object containing the voxel data.
        attributes: list of dicts with 'semantic' and 'bit_index'.
        
    Returns:
        list of dicts representing voxel records. Each record contains
        attribute values and a 'count' key for the number of voxels in the run.
    """
    records = []
    byte_idx = 0
    bit_idx = 0
    num_attrs = len(attributes)

    def read_bit():
        nonlocal byte_idx, bit_idx
        val = (buffer_bytes[byte_idx] >> bit_idx) & 1
        bit_idx += 1
        if bit_idx == 8:
            bit_idx = 0
            byte_idx += 1
        return val

    def read_bits(count):
        val = 0
        for _ in range(count):
            val |= read_bit() << _
        return val

    while byte_idx < len(buffer_bytes):
        # 1. Parse Presence Bitmask
        mask = read_bits(num_attrs)

        record = {}
        for i, attr in enumerate(attributes):
            if (mask >> i) & 1:
                if attr['semantic'] == 'RLE_LENGTH':
                    rle_val = read_bits(8)
                    record['count'] = rle_val + 2
                elif attr['semantic'] == 'MATERIAL_INDEX':
                    record['MATERIAL_INDEX'] = read_bits(8)
                elif attr['semantic'] == 'DENSITY':
                    record['DENSITY'] = read_bits(8)
                else:
                    record[attr['semantic']] = read_bits(8)
        records.append(record)

    return records
```

## Subtopics

### Voxel Volume
A container for primitives, defining the global bounds and attribute schema for a chunk of voxels. It allows grouping related voxels. [Link](7065-voxel-interchange-format-serialization.md)

### Primitive
A subset of a Voxel Volume, defining a specific 3D box region and its associated binary data. It enables independent encoding and access of sparse regions. [Link](7065-voxel-interchange-format-serialization.md)

## Operating characteristics
*   **Time Complexity:** Decoding is linear with respect to the number of bytes in the buffer view, $O(N)$, where $N$ is the byte length [G]. Parsing the bitmask is constant time per record [G].
*   **Memory Complexity:** Depends on the sparsity and the efficiency of the RLE encoding [G].
*   **Strengths:** Leverages glTF infrastructure for buffer management and metadata [S1, unofficial]. Variable-length records allow efficient storage of single voxels without overhead [S1, unofficial]. Hierarchical structure supports large scenes [S1, unofficial].
*   **Limitations:** JSON integer precision issues may cause portability problems [S1, unofficial]. RLE is a simple compression and may not be optimal for all data types [S1, unofficial]. 8-bit RLE length limits run lengths to 258 voxels (0-255 + 2) [S1, unofficial].
*   **When to use:** When storing sparse voxel data in a glTF-compatible pipeline, especially for terrain or large-scale environments where sparsity is high [S1, unofficial].
*   **When not to use:** For dense, fully occupied volumes where the overhead of the bitmask and structure outweighs the benefits [G]. For data requiring high-precision floating point density without normalization [G].

## Background
The format was proposed in a GitHub issue by dougbinks on November 28, 2025, as part of the OpenVoxelFileFormat project [S1, unofficial]. It was designed to handle sparsity in voxel data by dividing objects into volumes and primitives, mirroring the glTF mesh/primitive model [S1, unofficial]. The discussion involved contributors like scallyw4g, who suggested using RLE encoding and 8-bit bit depths for counts [S1, unofficial]. The format draws inspiration from Roblox's voxel Disk format, differing primarily in terminology (Density vs. Occupancy) [S1, unofficial].
