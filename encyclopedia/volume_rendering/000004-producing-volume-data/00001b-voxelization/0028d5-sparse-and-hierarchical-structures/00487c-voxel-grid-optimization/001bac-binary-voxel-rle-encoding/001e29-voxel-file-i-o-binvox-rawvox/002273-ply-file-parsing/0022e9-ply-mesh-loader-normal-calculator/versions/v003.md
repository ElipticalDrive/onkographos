# PLY Mesh Loader & Normal Calculator
Also called: PLY Header & Face Parser
## Overview
This method parses ASCII PLY (Polygon File Format) files to extract vertex coordinates and triangle/quad face indices into flat float arrays, and computes face normals via cross product [S1, unofficial]. It solves the problem of loading raw mesh geometry for subsequent voxelization or rendering [G]. It differs from its parent [PLY File Parsing](2781-ply-file-parsing.md) by handling the actual data extraction and geometric computation rather than just header structure, and from its child [OBJ Mesh Loader & Triangulator](12664-obj-mesh-loader-triangulator.md) by relying on the PLY format's explicit face definition rather than parsing token-based text and performing polygon-to-triangle conversion [S1, unofficial].
## How it works
**Inputs:** A text stream or file pointer to an ASCII PLY file, along with vertex and face counts extracted by the parent parser [S1, unofficial].
**Outputs:** 
- `Vertex_Buffer`: A flat array of floats containing vertex coordinates [S1, unofficial].
- `Faces_Triangles`: A flat array of integers containing triangle vertex indices [S1, unofficial].
- Face normals computed for each triangle [S1, unofficial].

**Data Structures:**
- `Vertex_Buffer`: Array of size $3 \times N$, where $N$ is the number of vertices. Layout: $[x_0, y_0, z_0, x_1, y_1, z_1, \dots]$ [S1, unofficial].
- `Faces_Triangles`: Array of size $3 \times M$, where $M$ is the number of triangles. Layout: $[v_{0,0}, v_{0,1}, v_{0,2}, v_{1,0}, v_{1,1}, v_{1,2}, \dots]$ [S1, unofficial].

**Steps:**
1. **Read Vertices:** Loop $i$ from $0$ to $TotalConnectedPoints - 1$. Read 3 floats per line into `Vertex_Buffer[i*3]`, `Vertex_Buffer[i*3+1]`, `Vertex_Buffer[i*3+2]` [S1, unofficial].
2. **Read Faces:** Loop $j$ from $0$ to $TotalFaces - 1$. Read a line representing the face [S1, unofficial].
3. **Parse Face Type:** Check the first value of the face data (`num_verts`) [S1, unofficial].
   - If `num_verts == 3`: Parse the next 3 integers as vertex indices $v_1, v_2, v_3$ [S1, unofficial].
   - Map these indices to `Vertex_Buffer` using offsets $3 \times v_1$, $3 \times v_1 + 1$, etc. [S1, unofficial].
   - Store the indices in `Faces_Triangles` [S1, unofficial].
   - [G] Note: The source snippet does not handle `num_verts == 4` (quads) or other polygon types.
4. **Calculate Normals:** For each triangle in `Faces_Triangles`:
   - Retrieve coordinates $C_1, C_2, C_3$ from `Vertex_Buffer` [S1, unofficial].
   - Compute vectors: $V_A = C_1 - C_2$, $V_B = C_1 - C_3$ [S1, unofficial].
   - Compute cross product: $V_R = V_A \times V_B$ [S1, unofficial].
   - Compute magnitude: $V_L = \sqrt{V_R.x^2 + V_R.y^2 + V_R.z^2}$ [S1, unofficial].
   - Normalize: $N = V_R / V_L$ [S1, unofficial].

**Pseudocode:**
```python
def load_ply_mesh(file_lines, total_connected_points, total_faces):
    vertex_buffer = [0.0] * (3 * total_connected_points)
    faces_triangles = []
    normals = []

    # Step 1: Read Vertices
    idx = 0
    for i in range(total_connected_points):
        parts = file_lines.pop(0).strip().split()
        vertex_buffer[idx] = float(parts[0])
        vertex_buffer[idx + 1] = float(parts[1])
        vertex_buffer[idx + 2] = float(parts[2])
        idx += 3

    # Step 2: Read Faces
    for j in range(total_faces):
        line = file_lines.pop(0).strip()
        parts = line.split()
        num_verts = int(parts[0])

        if num_verts == 3:
            # Step 3: Parse Face Type
            v1 = int(parts[1])
            v2 = int(parts[2])
            v3 = int(parts[3])

            # Map indices to Vertex_Buffer and store in Faces_Triangles
            faces_triangles.extend([v1, v2, v3])

            # Step 4: Calculate Normals
            c1 = [vertex_buffer[v1 * 3], vertex_buffer[v1 * 3 + 1], vertex_buffer[v1 * 3 + 2]]
            c2 = [vertex_buffer[v2 * 3], vertex_buffer[v2 * 3 + 1], vertex_buffer[v2 * 3 + 2]]
            c3 = [vertex_buffer[v3 * 3], vertex_buffer[v3 * 3 + 1], vertex_buffer[v3 * 3 + 2]]

            va = [c1[k] - c2[k] for k in range(3)]
            vb = [c1[k] - c3[k] for k in range(3)]

            vr = [
                va[1] * vb[2] - va[2] * vb[1],
                va[2] * vb[0] - va[0] * vb[2],
                va[0] * vb[1] - va[1] * vb[0]
            ]

            val = (vr[0]**2 + vr[1]**2 + vr[2]**2)**0.5

            if val > 0:
                norm = [vr[k] / val for k in range(3)]
            else:
                norm = [0.0, 0.0, 0.0]
            normals.append(norm)
        else:
            # Pitfall: Quads or other polygons are not handled in the source snippet
            # Skip remaining vertices for this face
            for _ in range(num_verts - 1):
                file_lines.pop(0)

    return vertex_buffer, faces_triangles, normals
```

**Parameters:**
- Not given in the sources.

**Edge Cases:**
- **Quads:** The method does not handle quad faces (`buffer[0]=='4'`), leaving them unprocessed [S1, unofficial].
- **Index Base:** Vertex indices are treated as 0-based directly from the file [S1, unofficial].
- **Degenerate Triangles:** If the cross product magnitude is zero, normalization fails; a guard is required [G].

## Operating characteristics
**Time Complexity:** Linear with respect to the number of vertices and faces, $O(V + F)$, assuming constant-time file reads and arithmetic operations [G].
**Memory Complexity:** $O(V)$ for vertex storage and $O(F)$ for face storage [G].
**Strengths:** Simple implementation for standard triangular PLY files [G].
**Limitations:** Does not support quads or higher-order polygons. Relies on ASCII parsing which can be slow for large files compared to binary PLY parsers [G].
**When to use:** When loading triangular meshes from ASCII PLY files for voxelization [G].
**When not to use:** When the mesh contains quads, or when performance is critical and binary PLY is available [G].

## Background
This method is derived from the `svo-workbench` project by skyfex, which implements a sparse voxel octree raytracer [S1, unofficial]. It is part of a pipeline that loads mesh data for voxelization into a sparse voxel structure [G].
