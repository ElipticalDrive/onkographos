# MagicaVoxel File Output
Also called: MagicaVoxel Export, VOX File Export

## Overview
Exports voxel particles or grids to the MagicaVoxel `.vox` binary format, handling grid sizing, chunk structure, and coordinate transformations. It differs from sibling parsers by focusing on the serialization of sparse voxel data into a hierarchical chunk-based binary layout, whereas [MagicaVoxel File Parsing](2405-magicavoxel-file-parsing.md) handles the reverse. It builds on [Voxel File I/O (binvox/rawvox)](1698-voxel-file-i-o-binvox-rawvox.md) by providing a specific implementation for the `.vox` standard rather than generic binary or raw formats.

## How it works
**Inputs:** A set of voxel particles (position $x, y, z$ and color index $c$) or a voxel grid; resolution $res$ (world units per voxel); optional flag for squared padding.
**Outputs:** A binary `.vox` file.

**Data Structures:**
The `.vox` file consists of a sequence of chunks. Each chunk has a header:
- `ID` (4 bytes, ASCII): Chunk identifier (e.g., "MAIN", "SIZE", "XYZI").
- `Size` (4 bytes, little-endian u32): Size of the chunk's children in bytes.
- `Content` (variable): The chunk's data.

**Steps:**

1.  **Calculate Bounding Box:**
    Initialize `min_x, min_y, min_z` to $+\infty$ and `max_x, max_y, max_z` to $-\infty$. Iterate over all input particles $p_i = (p.x, p.y, p.z, p.index)$. Update bounds:
    $$
    \begin{aligned}
    min_x &= \min(min_x, p.x) \\
    max_x &= \max(max_x, p.x)
    \end{aligned}
    $$
    (Repeat for $y$ and $z$). [S1, unofficial]

2.  **Compute Grid Dimensions:**
    Calculate the number of voxels in each dimension based on the resolution $res$:
    $$
    size_x = \left\lfloor \frac{max_x - min_x}{res} \right\rfloor + 1
    $$
    (Repeat for $size_y$ and $size_z$). [S1, unofficial]
    *Pitfall:* If any dimension exceeds 256, clamp it to 256 to respect MagicaVoxel's per-model limit. [S1, unofficial]

3.  **Write Header:**
    Write the magic number `"VOX "` (4 bytes) followed by the version number `150` as a little-endian u32. [S1, unofficial]

4.  **Write MAIN Chunk:**
    - Write ID `"MAIN"` (4 bytes).
    - Calculate `children_size`: Sum of sizes of child chunks (SIZE, XYZI, and any others).
    - Write `children_size` as little-endian u32.
    - Write child chunks. [S1, unofficial]

5.  **Write SIZE Chunk:**
    - Write ID `"SIZE"` (4 bytes).
    - Write `size` as little-endian u32 (value 12, representing the 3 u32 dimensions).
    - Write `padding` as little-endian u32 (value 0).
    - Write `size_x`, `size_y`, `size_z` as little-endian u32. [S1, unofficial]

6.  **Write XYZI Chunk:**
    - Write ID `"XYZI"` (4 bytes).
    - Calculate `content_size`: $4 + (num\_voxels \times 4)$ bytes.
    - Write `content_size` as little-endian u32.
    - Write `padding` as little-endian u32 (value 0).
    - Write `count` (number of voxels) as little-endian u32.
    - For each voxel, write `vx`, `vy`, `vz` as little-endian i32 and `index` as u8.
    
    **Coordinate Transformation:**
    Convert world coordinates to voxel indices:
    $$
    vx = \left\lfloor \frac{p.x - min_x}{res} + 0.5 \right\rfloor
    $$
    (Repeat for $vy, vz$). [S1, unofficial]
    
    *Note on Coordinate System:* Some implementations transform coordinates to $(x, z, y)$ to match MagicaVoxel's internal axis convention. If squared padding is enabled, empty voxels must be added to fill the grid to the calculated dimensions. [S2, unofficial]

        min_x = min(min_x, p.x)
        max_x = max(max_x, p.x)

    size_y = math.floor((max_y - min_y) / resolution) + 1
    size_z = math.floor((max_z - min_z) / resolution) + 1

## Subtopics

### VOX Export
Exports the voxel grid to the `.vox` format with specific handling for squared padding and coordinate transformation $(x, z, y)$. It initializes a `VoxWriter`, clears existing voxels/colors, and iterates over the grid dimensions. If squared, it fills empty space with `VOXEL_EMPTY`. If not squared, it filters out free voxels. It handles filename generation by appending a random integer if the extension is missing. [S2, unofficial]

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of particles, for bounding box calculation and serialization.
- **Memory Complexity:** $O(N)$ to store particle data and the output buffer.
- **Limitations:** Grid dimensions are clamped to 256 per axis, limiting the maximum volume size per model. [S1, unofficial]
- **Performance:** Binary output is fast; no compression is applied in the basic XYZI chunk.

## Background
The `.vox` format is the native file format for MagicaVoxel, a popular voxel art tool. The export method described here is based on implementations found in open-source voxelization tools. [S1, unofficial]
