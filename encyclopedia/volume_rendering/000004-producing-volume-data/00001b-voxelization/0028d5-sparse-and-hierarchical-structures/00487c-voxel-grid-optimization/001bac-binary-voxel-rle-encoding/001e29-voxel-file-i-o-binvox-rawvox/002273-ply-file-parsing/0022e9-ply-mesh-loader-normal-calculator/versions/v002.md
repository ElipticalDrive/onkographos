# PLY Mesh Loader & Normal Calculator
Also called: PLY Header & Face Parser
## Overview
This method parses ASCII PLY (Polygon File Format) files to extract vertex coordinates and face indices, converting them into flat float arrays and triangle lists while computing face normals. It solves the problem of loading raw mesh geometry for subsequent voxelization or rendering. It differs from its parent [PLY File Parsing](2781-ply-file-parsing.md) by handling the actual data extraction and geometric computation rather than just header structure, and from its child [OBJ Mesh Loader & Triangulator](12664-obj-mesh-loader-triangulator.md) by relying on the PLY format's explicit face definition rather than parsing token-based text and performing polygon-to-triangle conversion.
## How it works
**Inputs:** A text stream or file pointer to an ASCII PLY file.
**Outputs:** 
- `Vertex_Buffer`: A flat array of floats containing vertex coordinates.
- `Faces_Triangles`: A flat array of integers containing triangle vertex indices.
- Face normals computed for each triangle.

**Data Structures:**
- `Vertex_Buffer`: Array of size $3 \times N$, where $N$ is the number of vertices. Layout: $[x_0, y_0, z_0, x_1, y_1, z_1, \dots]$.
- `Faces_Triangles`: Array of size $3 \times M$, where $M$ is the number of triangles. Layout: $[v_{0,0}, v_{0,1}, v_{0,2}, v_{1,0}, v_{1,1}, v_{1,2}, \dots]$.

**Steps:**
1. **Read Vertices:** Loop $i$ from $0$ to $TotalConnectedPoints - 1$. Read 3 floats per line (or token) into `Vertex_Buffer[i*3]`, `Vertex_Buffer[i*3+1]`, `Vertex_Buffer[i*3+2]`.
2. **Read Faces:** Loop $j$ from $0$ to $TotalFaces - 1$. Read a line or token representing the face.
3. **Parse Face Type:** Check the first value of the face data (let's call it `num_verts`).
   - If `num_verts == 3`: Parse the next 3 integers as vertex indices $v_1, v_2, v_3$.
   - Map these indices to `Vertex_Buffer` using offsets $3 \times v_1$, $3 \times v_1 + 1$, etc.
   - Store the indices in `Faces_Triangles`.
   - [G] Note: The source snippet does not handle `num_verts == 4` (quads) or other polygon types.
4. **Calculate Normals:** For each triangle in `Faces_Triangles`:
   - Retrieve coordinates $C_1, C_2, C_3$ from `Vertex_Buffer`.
   - Compute vectors: $V_A = C_1 - C_2$, $V_B = C_1 - C_3$.
   - Compute cross product: $V_R = V_A \times V_B$.
   - Compute magnitude: $V_L = \sqrt{V_R.x^2 + V_R.y^2 + V_R.z^2}$.
   - Normalize: $N = V_R / V_L$.

**Pseudocode:**
```python
def load_ply_mesh(file_stream):
    # Assume header parsing is done by parent method
    # Extract TotalConnectedPoints and TotalFaces from header
    
    vertex_buffer = []
    faces_triangles = []
    
    # Step 1: Read Vertices
    for i in range(TotalConnectedPoints):
        x = read_float(file_stream)
        y = read_float(file_stream)
        z = read_float(file_stream)
        vertex_buffer.extend([x, y, z])
        
    # Step 2: Read Faces
    for j in range(TotalFaces):
        # Read face header (number of vertices in this face)
        num_verts = read_int(file_stream)
        
        if num_verts == 3:
            # Step 3: Parse Triangle
            v1 = read_int(file_stream)
            v2 = read_int(file_stream)
            v3 = read_int(file_stream)
            
            # Store indices (0-based as per source)
            faces_triangles.extend([v1, v2, v3])
            
            # Step 4: Calculate Normal
            # Get coordinates
            c1 = [vertex_buffer[v1*3], vertex_buffer[v1*3+1], vertex_buffer[v1*3+2]]
            c2 = [vertex_buffer[v2*3], vertex_buffer[v2*3+1], vertex_buffer[v2*3+2]]
            c3 = [vertex_buffer[v3*3], vertex_buffer[v3*3+1], vertex_buffer[v3*3+2]]
            
            # Vectors
            va = [c1[k] - c2[k] for k in range(3)]
            vb = [c1[k] - c3[k] for k in range(3)]
            
            # Cross Product
            vr = [
                va[1]*vb[2] - va[2]*vb[1],
                va[2]*vb[0] - va[0]*vb[2],
                va[0]*vb[1] - va[1]*vb[0]
            ]
            
            # Magnitude
            val = sqrt(vr[0]**2 + vr[1]**2 + vr[2]**2)
            
            # Normalize
            if val > 0:
                normal = [vr[k] / val for k in range(3)]
            else:
                normal = [0.0, 0.0, 0.0] # Degenerate case
            
            # Store normal (implementation detail: could be separate array)
            
        else:
            # Pitfall: Quads or other polygons are not handled in the source snippet
            # Skip remaining vertices for this face
            for _ in range(num_verts):
                read_int(file_stream)
                
    return vertex_buffer, faces_triangles
```

**Parameters:**
- Not given in the sources.

**Edge Cases:**
- **Quads:** The method does not handle quad faces (`buffer[0]=='4'`), leaving them unprocessed [S1, unofficial].
- **Index Base:** Vertex indices are treated as 0-based directly from the file [S1, unofficial].
- **Degenerate Triangles:** If the cross product magnitude is zero, normalization fails; a guard is required [G].

## Operating characteristics
**Time Complexity:** Linear with respect to the number of vertices and faces, $O(V + F)$, assuming constant-time file reads and arithmetic operations.
**Memory Complexity:** $O(V)$ for vertex storage and $O(F)$ for face storage.
**Strengths:** Simple implementation for standard triangular PLY files.
**Limitations:** Does not support quads or higher-order polygons. Relies on ASCII parsing which can be slow for large files compared to binary PLY parsers.
**When to use:** When loading triangular meshes from ASCII PLY files for voxelization.
**When not to use:** When the mesh contains quads, or when performance is critical and binary PLY is available.

## Background
This method is derived from the `svo-workbench` project by skyfex, which implements a sparse voxel octree raytracer. It is part of a pipeline that loads mesh data for voxelization into a sparse voxel structure.
