# ArrayMesh Byte Reader

Also called: Godot ArrayMesh Byte Reader

## Overview
The ArrayMesh Byte Reader is an internal Godot engine component that processes raw byte arrays for mesh attributes [S1, unofficial]. It is distinguished from disk-based voxel file parsers like [Binvox File Parsing](2862-binvox-file-parsing.md) by its direct in-memory byte processing and specific signed-to-unsigned normalization [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Raw byte array (e.g., `PackedByteArray`).
- Output: Processed byte values ready for `ArrayMesh` attribute arrays.
Not given in the sources.

**Data Structures:**
The reader processes bytes according to the target `ArrayMesh` array type [G]. For color data, it expects 8-bit values [G]. A specific edge case involves signed byte interpretation: if the source data contains a value of -1 (0xFF in two's complement), the reader normalizes it to 255 to fit the unsigned 8-bit color channel range [S1, unofficial].

**Numbered Steps:**
1. Iterate through the input byte array.
2. For each byte, interpret it as a signed 8-bit integer [G].
3. If the signed value equals -1, narrow it to 255 [S1, unofficial].
4. Store the resulting unsigned byte value into the corresponding `ArrayMesh` attribute array [G].

**Formulas:**
For color normalization:
$$ C_{out} = \begin{cases} 255 & \text{if } C_{in} = -1 \\ C_{in} & \text{otherwise} \end{cases} $$
Where $C_{in}$ is the signed byte value and $C_{out}$ is the stored unsigned byte value [S1, unofficial].

**Parameters:**
- Normalization threshold: -1 maps to 255 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Signed/Unsigned Ambiguity:** The reader must correctly interpret the source byte as signed to detect the -1 value before storing it as unsigned [S1, unofficial].
- **HDR Channels:** While this reader handles standard 8-bit colors, other Godot texture systems (like `GradientTexture2D`) may handle HDR channels above 1.0, but the ArrayMesh byte reader is strictly for mesh attributes [S1, unofficial].

**Pseudocode:**
```python
def narrow_array_mesh_bytes(byte_array: list[int]) -> list[int]:
    """
    Processes a raw byte array for ArrayMesh attributes.
    Narrows listed -1 values to 255 as per Godot's variant_parser.cpp:650 [S1, unofficial].
    """
    result = []
    for byte_val in byte_array:
        # Interpret as signed 8-bit integer
        signed_val = byte_val if byte_val < 128 else byte_val - 256
        
        # Normalize -1 to 255
        if signed_val == -1:
            result.append(255)
        else:
            result.append(signed_val)
    # Engine-specific ArrayMesh array population is not given in the sources.
    return result
```

## Subtopics

### MZ3 Mesh Parser
- **What it is:** A parser for the binary MZ3 mesh format, often used in neuroimaging tools [S2, unofficial].
- **What sets it apart:** It supports optional gzip compression and parses a specific header structure with a magic signature [S2, unofficial].
- **When to choose it:** When loading MZ3 files generated by tools like `nii2mesh` [S2, unofficial].
- **Definition:** Parses a binary MZ3 mesh file, supporting optional gzip compression, to extract triangle indices and vertex coordinates into dynamically allocated arrays [S2, unofficial].
- **Step:** Open file. Read packed header. Check signature 23117. If missing and `HAVE_ZLIB`, try `gzopen`. Read header from gz. Read `NFACE` triangles (vec3i). Read `NVERT` vertices as float (3 per vertex). Convert to vec3d array. Free temporary buffers [S2, unofficial].
- **Parameter:** `SIGNATURE`: magic number, expected 23117. `NSKIP`: bytes to skip after header before triangle data [S2, unofficial].
- **Layout:** `mz3hdr` struct: `uint16_t SIGNATURE`, `uint16_t ATTR`, `uint32_t NFACE`, `uint32_t NVERT`, `uint32_t NSKIP`. Packed with `__attribute__((__packed__))` or `#pragma pack(2)` [S2, unofficial].
- **Code:**
```python
for i in range(h.NVERT):
    v = vec3d()
    v.x = verts32[j]; j += 1
    v.y = verts32[j]; j += 1
    v.z = verts32[j]; j += 1
    vs[i] = v
```
