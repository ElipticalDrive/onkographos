# FLVC File Format

Also called: Free Lossless Voxel Compression, Free Lossless Voxel Compression (FLVC) File Format

## Overview
FLVC is a container format for voxel data that supports zlib-compressed content for non-empty volumes [S1]. It is designed to store sparse voxel octrees (SVOs) and their associated attributes, providing a structured way to serialize voxel grids with metadata [S1]. Unlike raw binary dumps, FLVC includes a header defining volume dimensions, offsets, and attribute schemas, allowing for flexible storage of color, normals, and custom data [S1].

## How it works
**Inputs and Outputs:** Input is a voxel volume (typically an SVO) with associated attributes [S1]. Output is a binary file with the `.flvc` extension and media type `model/x-flvc` [S1].

**Data Structures:** The file layout consists of a fixed-size header followed by optional compressed content [S1].
1. Type definitions: `u8` is an 8-bit unsigned integer; `u16`, `u32`, `u64` are little-endian unsigned integers of 16, 32, and 64 bits; `i8`, `i16`, `i32`, `i64` are two's complement signed integers (little-endian for >8 bits) [S1].
2. Helper struct `string8`: a non-zero `u8` size followed by `size` bytes of ASCII content [S1].
3. Attribute type enum (`attribute_type`, `u8`): `BOOL` = 0x01, `INT_8` = 0x11, `INT_16` = 0x12, `INT_32` = 0x14, `INT_64` = 0x18, `UINT_8` = 0x21, `UINT_16` = 0x22, `UINT_32` = 0x24, `UINT_64` = 0x28, `FLOAT_32` = 0x41, `FLOAT_64` = 0x42 [S1].
4. Attribute modifier enum (`attribute_modifier`, `u16`): `NON_LOCAL` = 1 (no spatial locality), `ALPHA_LAST` = 2 (only for 'color', alpha appended last) [S1].
5. Main header (40 bytes fixed + variable definitions): `magic` (`u64`) = `0xff11_33cc_666c_7663`; `version_major` (`u8`) = 0; `version_minor` (`u8`) = 1; `volume_offset` (`i32[3]`); `volume_size` (`u32[3]`); `empty` (`u8`); `padding` (`u8[5]`) = `"(def)"`; `definitions_size` (`u16`); `definitions` (`attribute_definition[definitions_size]`); `reserved` (`u8`) = `'|'`; `content` (`zlib_stream`) if `!empty` [S1].
6. Attribute definition struct: `identifier` (`string8`); `atype` (`attribute_type`); `cardinality` (`u8`); `modifiers` (`u16`) [S1].

**Numbered Steps:**
1. Read 8-byte magic and verify against `0xff11_33cc_666c_7663`.
2. Read `version_major`, `version_minor`, `volume_offset`, `volume_size`, `empty`, and 5-byte padding.
3. Read `definitions_size`, then iterate to parse `definitions_size` attribute definitions.
4. Read the `reserved` byte.
5. If `empty` is `0`, read and decompress the `zlib_stream` content; otherwise, terminate.

**Formulas:** Not given in the sources.

**Parameters:** File extension `.flvc`, media type `model/x-flvc`, header fixed size 40 bytes, version `0.1` [S1].

**Edge Cases and Pitfalls:** SVOs internally require power-of-two dimensions even if `volume_size` specifies exact dimensions [S1]. If `empty` is `1`, no `zlib_stream` follows the reserved byte [S1]. The `'|'` reserved byte acts as a visual separator and guards against reading past the header [S1].

**Pseudocode for Header Parsing:**
```python
import struct

def read_u8(stream): return struct.unpack('<B', stream.read(1))[0]
def read_u16_le(stream): return struct.unpack('<H', stream.read(2))[0]
def read_u32_le(stream): return struct.unpack('<I', stream.read(4))[0]
def read_u64_le(stream): return struct.unpack('<Q', stream.read(8))[0]
def read_i32_le(stream): return struct.unpack('<i', stream.read(4))[0]
def read_bytes(stream, n): return stream.read(n)

def parse_flvc_header(file_stream):
    magic = read_u64_le(file_stream)
    if magic != 0xff11_33cc_666c_7663:
        raise ValueError("Invalid FLVC magic bytes")

    version_major = read_u8(file_stream)
    version_minor = read_u8(file_stream)

    volume_offset = tuple(read_i32_le(file_stream) for _ in range(3))
    volume_size = tuple(read_u32_le(file_stream) for _ in range(3))

    empty = read_u8(file_stream)
    padding = read_bytes(file_stream, 5)
    if padding != b"(def)":
        pass

    definitions_size = read_u16_le(file_stream)
    definitions = []
    for _ in range(definitions_size):
        size = read_u8(file_stream)
        identifier = read_bytes(file_stream, size).decode('ascii')
        atype = read_u8(file_stream)
        cardinality = read_u8(file_stream)
        modifiers = read_u16_le(file_stream)
        definitions.append({
            "identifier": identifier,
            "atype": atype,
            "cardinality": cardinality,
            "modifiers": modifiers
        })

    reserved = read_u8(file_stream)
    if reserved != ord('|'):
        pass

    return {
        "version": (version_major, version_minor),
        "volume_offset": volume_offset,
        "volume_size": volume_size,
        "empty": empty,
        "definitions": definitions
    }
```

## Operating characteristics
*   **Compression:** Uses zlib compression for the voxel data payload [S1]. Compression ratio depends on the sparsity and redundancy of the voxel data [S1].
*   **Memory:** The header is small (40 bytes + attribute definitions) [S1]. The payload size depends on the compressed voxel data [S1].
*   **Performance:** Not given in the sources.
*   **Strengths:** Flexible attribute system, standard compression, clear structure for debugging [S1].
*   **Limitations:** SVO internal power-of-two constraint may lead to wasted space for non-power-of-two volumes [S1].

## Background
FLVC was produced based on research results into voxel compression [S1]. It is part of the "Voxel Compression" project, aiming to provide a robust file format for voxel data [S1].
