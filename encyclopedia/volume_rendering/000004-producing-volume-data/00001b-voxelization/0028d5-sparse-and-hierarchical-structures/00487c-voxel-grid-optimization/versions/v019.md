# Voxel Grid Optimization

Also called: Sparse Voxel Grid Optimization, Voxelization Pipeline Optimization

## Overview
Voxel Grid Optimization encompasses the techniques used to reduce the computational and memory costs associated with generating, storing, and traversing voxel grids for volume rendering [S1, S2, unofficial]. It solves the problem of excessive resource consumption in sparse scenes by accelerating the rasterization of geometry into voxels, compressing occupancy data, and restricting ray traversal to active spatial extents [S1, S2, unofficial]. Unlike its siblings [Sparse and Hierarchical Structures](4391-sparse-and-hierarchical-structures.md), which focus on the data structure hierarchy itself, this family focuses on the optimization of the voxel grid generation pipeline and the efficiency of the resulting grid's usage in rendering [S1, S2, unofficial].

## Shared principles
The methods in this family share the goal of minimizing the cost of converting continuous geometry or implicit fields into discrete voxel representations and subsequently accessing them. Common mechanisms include:
1.  **Spatial Culling:** Restricting computation to bounding volumes that contain active geometry, thereby skipping empty regions [S1, S2, unofficial].
2.  **Hardware Acceleration:** Leveraging GPU features such as stream output, instancing, and layered rendering to accelerate the rasterization process [S1, S2, unofficial].
3.  **Data Compression:** Using encoding schemes like Run-Length Encoding (RLE) or block-based occupancy masks to reduce the memory footprint of sparse data [S1, S2, unofficial].
4.  **Resolution Management:** Dynamically calculating grid dimensions based on aspect ratios or target voxel counts to balance fidelity and memory usage [S1, unofficial].

## Subtopics

### [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md)
A preprocessing technique applied to 3D voxel grids to reduce high-frequency noise and aliasing artifacts prior to isosurface extraction or volume rendering. It operates by applying a separable 3D convolution using a fixed 3-tap triangular filter $\{0.5, 1.0, 0.5\}$. Unlike [3D Box Filter for Voxel Averaging](1513-3d-box-filter-for-voxel-averaging.md), which generalizes to arbitrary kernel sizes, this method specifically utilizes this fixed kernel. It differs from [Iterative Convolution and Thresholding for Noise Removal](1516-iterative-convolution-and-thresholding-for-noise-removal.md) by preserving continuous scalar field values rather than acting as a binary morphological filter. Choose this method when smoothing scalar fields without altering their binary nature is required.

### [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md)
Compresses a 3D voxel grid into a binary stream using run-length encoding (RLE) to store occupancy data efficiently. It solves the problem of excessive storage size for sparse voxel grids by storing only voxels within the minimal bounding box of the mesh. Unlike [Voxel Indexing and Bit Compression](1707-voxel-indexing-and-bit-compression.md) which stores explicit occupancy bits for every possible voxel, this method encodes runs of identical values, making it suitable for sparse data. It differs from [RLE4 Compression](4441-rle4-compression.md) by storing only binary occupancy (0 or 1) rather than per-voxel material and intensity information. Choose this method for efficient storage of binary occupancy masks.

### [Coordinate Grid Generation](1273-coordinate-grid-generation.md)
Constructs a regular lattice of sample points within a specified spatial domain, typically mapping pixel indices to Normalized Device Coordinates (NDC) in the range $[-1, 1]$ for 2D image planes or defining 3D voxel centers for volumetric evaluation. It serves as the foundational sampling mechanism for evaluating implicit functions (such as Signed Distance Fields) or density fields across a volumetric domain. It differs from [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) by generating raw coordinate tensors rather than modifying existing voxel values, and from [Occupancy Voxel Creation](2628-occupancy-voxel-creation.md) by producing coordinate arrays for neural field evaluation rather than binary occupancy masks. Choose this method when initializing neural voxel fields or sampling implicit functions.

### [Occupancy Voxel Creation](2628-occupancy-voxel-creation.md)
Converts a continuous density matrix into a sparse boolean occupancy mask by identifying fully occupied $2 \times 2 \times 2$ blocks of voxels. It solves the problem of representing dense volumetric data efficiently by grouping adjacent occupied cells into larger primitives, reducing the number of elements processed during rendering or training. It differs from [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) by using discrete block detection rather than continuous field smoothing, and from [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md) by producing a structural mask rather than a compressed byte stream. Choose this method when block-based occupancy is required for neural rendering or sparse traversal.

### [Grid Resolution Calculation](2908-grid-resolution-calculation.md)
Calculates the integer dimensions of a 3D voxel grid based on a target voxel count along the Y-axis and the aspect ratio of the scene bounding box. It solves the problem of determining discrete grid resolution required to cover a spatial extent while maintaining aspect ratio consistency, serving as the foundational step for allocating memory in sparse and hierarchical voxel structures. It is distinguished from [Grid Resolution Selection via Lambda](3270-grid-resolution-selection-via-lambda.md) by its direct geometric division based on a fixed Y-axis target, rather than optimizing resolution via a cost function or lambda parameter. Choose this method for fixed-aspect-ratio grid allocation.

### [Voxelization Optimization](3191-voxelization-optimization.md)
Encompasses techniques to reduce the computational and memory costs of generating voxel grids for volume rendering, primarily by accelerating the rasterization of geometry into voxels and minimizing redundant updates. It distinguishes itself from downstream processing methods (like [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) or [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md)) by focusing on the input stage: converting triangle meshes into 3D occupancy or density fields. Key strategies include GPU hardware acceleration via stream output and instancing, spatial culling of static geometry, and level-of-detail (LOD) simplification for obstacles. Choose this method when optimizing the mesh-to-voxel pipeline.

### [Bounding Volume Optimization](3583-bounding-volume-optimization.md)
Reduces the computational cost of voxel-based rendering by restricting ray traversal and Signed Distance Field (SDF) evaluation to the spatial extents of active geometry. It solves the problem of uniform computation waste in sparse scenes by eliminating false positives from empty regions and skipping expensive primitive evaluations for objects that do not contribute to the minimal distance field. Unlike [Grid Resolution Calculation](2908-grid-resolution-calculation.md), which adjusts the density of the grid, this method adjusts the spatial bounds of the data structure itself. Choose this method to accelerate ray marching in sparse scenes.

### [Bucket-based LBVH construction](5163-bucket-based-lbvh-construction.md)
Builds a Bounding Volume Hierarchy (BVH) from a voxel model by grouping voxels into dynamic buckets rather than a fixed uniform grid. This approach accelerates sparse volume rendering by enabling efficient empty-space skipping, achieving two to three times higher frame rates compared to methods without such optimization. It distinguishes itself from fixed-brick approaches (like Zellmann et al. [ZHL19]) by adapting bucket sizes to local voxel density, reducing memory overhead in sparse regions. Choose this method for building efficient traversal structures for sparse voxel grids.

### Volume Buffer
#### definition
- A volume data caching structure that encapsulates functionality, storage, and access similar to a Frame Buffer Object (FBO), but for 3D scalar data. It rasterizes primitives in 3D space and accumulates up to 1024 bits of arbitrary data per voxel [S1, unofficial].
#### step
- Generate the final volume by fusing three intermediate passes (one for each perpendicular sweep axis) into a single multi-buffer using the MAX blending operation [S1, unofficial].
- Disable face culling and z-test, and do not attach a z-buffer to the frame buffer object [S1, unofficial].
- Use the OpenGL extension for layered rendering, writing to `gl_Layer` in the geometry shader to render primitives to arbitrary volume texture layers [S1, unofficial].
#### parameter
- Max bits per voxel: 1024 bits [S1, unofficial].
- Max render targets: 8 floating point render targets (MRTs), as 8 is the current maximum available number of MRTs [S1, unofficial].
#### comparison
- Uses MAX blending for scalar data fusion instead of the OR operation used in binary voxelization [S1, unofficial].

### Voxelization Projection Culling
#### definition
- Optimizes multi-pass voxelization by skipping primitives whose precomputed dominant axis does not match the current projection direction, preventing redundant voxel writes [S2, unofficial].
#### step
- In the vertex shader, compute world position. If multi-pass mode is active, read the primitive's dominant axis from `triDominantAxis[vid / 3]`. Compare with `projDir.direction`. If they mismatch, skip the primitive (early return/continue implied) [S2, unofficial].
#### parameter
- `kVoxelizationMultiPass = !kVoxelizationSinglePass` (compile-time flag controlling pass strategy) [S2, unofficial].
#### layout
- `VoxelProjectionDir` struct: `uint direction`; (bound to buffer 2). `triDominantAxis` buffer: bound to buffer index 10 (`TRI_DOMINANT_BUFFER_BINDING_IDX`) [S2, unofficial].
#### pitfall
- Vertex ID to triangle ID mapping uses integer division `vid / 3`, assuming contiguous triangle strips/arrays [S2, unofficial].

### Density Voxel Grid Reconstruction
#### definition
- A scene representation method using a density voxel grid to generate high-quality 3D reconstructed scenes and images once camera poses are optimized [S3].
#### comparison
- Unlike NeRF which uses an MLP, or Plenoxels which uses sparse voxels with spherical harmonics, CBARF uses a density voxel grid for the final reconstruction stage after pose refinement [S3].

### Rate-distortion training objective with spatial predictive coding
#### step
- Incorporate the bitrate of prediction residuals into the loss function and jointly train for rate and distortion to enhance spatial correlation of the voxel grid [S4].
#### parameter
- Trade-off factor $\lambda$ controls the emphasis on bitrate during training; a larger $\lambda$ emphasizes bitrate more, while $\lambda=0$ removes rate loss entirely [S4].
#### number
- Ablation study shows disabling rate loss increases model size by +0.633 MB while improving PSNR by +0.13 dB and SSIM by +0.002 [S4].
#### comparison
- Training without rate loss ($\lambda=0$) yields better rendering quality but causes a rapid increase in bitrate, harming overall RD performance [S4].

## Background
Voxelization is a fundamental operation in computer graphics for converting polygonal models into volume representations, enabling applications such as smoke/fluid simulations, visibility information, and global illumination effects [S1, unofficial]. Early methods focused on simple binary voxelization, often using hardware rasterization [S1, unofficial]. The introduction of GPU-based techniques allowed for real-time multi-channel voxelization of dynamic scenes, utilizing geometry shaders and layered rendering to accumulate scalar data [S1, unofficial]. As scenes became more complex and sparse, optimization techniques such as bounding volume culling, run-length encoding, and hierarchical structures (like BVHs built from voxel clusters) were developed to manage memory and traversal costs [S2, unofficial]. In the context of neural rendering, voxel grids have been adapted for density representation (e.g., DVGO, Plenoxels) and compressed using rate-distortion objectives with spatial predictive coding to balance quality and model size [S3, S4].
