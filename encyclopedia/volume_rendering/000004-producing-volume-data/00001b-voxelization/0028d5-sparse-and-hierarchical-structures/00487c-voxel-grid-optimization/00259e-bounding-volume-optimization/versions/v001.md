# Bounding Volume Optimization

Also called: Adaptive Voxel-Array-Größe, BV Optimisation, Bounding Volume Optimisation, Bounding-Volume-Optimierung, SDF Bounding Volume Culling, Volumen-Größenanpassung

## Overview
Bounding Volume Optimization reduces the effective complexity of voxel data by trimming the voxel array dimensions to the minimal bounding box of the actual data, thereby eliminating empty space traversal during rendering [S1, unofficial]. It also minimizes the computational cost of Signed Distance Field (SDF) evaluation by skipping calculations for objects that do not contribute to the minimal distance field [S2]. Unlike [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) which reduces noise, or [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md) which compresses storage, this method focuses on spatial culling and array dimensionality reduction to prevent false positives and redundant computations [S1, unofficial][S2].

## How it works
**Inputs:**
1.  A dense 3D voxel array or a set of geometric primitives with their associated SDF map functions.
2.  The global bounding box of the scene or the specific object's bounding box.

**Outputs:**
1.  A reduced voxel array dimensions (e.g., $512 \times 321 \times 512$ instead of $512^3$) [S1, unofficial].
2.  A culling mask or bounding volume hierarchy that allows the renderer to skip SDF evaluations for non-contributing objects [S2].

**Data Structures:**
*   **Voxel Array:** A 3D texture or memory buffer. The dimensions are adjusted to $W \times H \times D$, where $W, H, D$ correspond to the extent of the occupied voxels along each axis.
*   **Bounding Volumes:** Axis-Aligned Bounding Boxes (AABBs) or other primitive shapes enclosing each object or group of primitives. These define the region where the expensive SDF map function must be evaluated [S2].

**Steps:**
1.  **Compute Extents:** Determine the minimum and maximum coordinates of all occupied voxels or geometric primitives in the scene.
2.  **Trim Array:** Resize the voxel array dimensions to match these extents. For example, if a landscape occupies a height of 321 voxels within a 512-unit width, the array is resized to $512 \times 321 \times 512$ [S1, unofficial].
3.  **Define Bounding Volumes:** For each object or primitive, compute its bounding volume (e.g., AABB) [S2].
4.  **Cull During Raymarching:**
    *   For each ray, check intersection with the global trimmed bounding box. If outside, terminate immediately [S1, unofficial].
    *   For SDF evaluation, check intersection with individual object bounding volumes. If the ray does not intersect the bounding volume, skip the evaluation of that object's SDF map function [S2].
5.  **Evaluate SDF:** Only evaluate the expensive SDF map functions for primitives whose bounding volumes are intersected by the ray [S2].

**Formulas:**
*   Let $B_{global} = [min_x, min_y, min_z, max_x, max_y, max_z]$ be the bounding box of the trimmed voxel array.
*   Let $B_i$ be the bounding volume of the $i$-th primitive.
*   A ray $R(t) = O + tD$ contributes to the distance field only if:
    $$ R(t) \cap B_{global} \neq \emptyset \quad \text{AND} \quad \exists i : R(t) \cap B_i \neq \emptyset $$
    If $R(t) \cap B_i = \emptyset$, the SDF evaluation $SDF_i(P)$ is skipped [S2].

**Parameters:**
*   **Resolution:** The voxel resolution should be sufficient to capture the detail within the trimmed bounds. [S1, unofficial] notes that a fixed $512^3$ array is inefficient if the data only occupies $512 \times 321 \times 512$.
*   **Primitive Count:** The optimization is most beneficial when there are "dozens or even hundreds of surfaces" [S2].

**Edge Cases and Pitfalls:**
*   **False Positives:** Using a fixed, oversized array (e.g., $512^3$) for smaller data loads unnecessary data into GPU memory and causes false positives during traversal [S1, unofficial].
*   **Lighting Artifacts:** While AABBs are efficient for culling, they do not provide smooth normals for lighting calculations. The flat faces of AABBs can result in hard, physically implausible lighting if used for shading instead of just culling [S1, unofficial].
*   **GPU Architecture:** Modern GPUs are MIMD (Multiple Instruction, Multiple Data) rather than pure SIMD. This allows different Streaming Multiprocessors (SMs) to process different instruction streams. Bounding volume optimization helps by localizing expensive computations, allowing cheaper parts of the frame to finish early and distributing expensive threads across available SMs [S2].

**Pseudocode:**
```python
def raymarch_with_bounding_volume_optimization(ray_origin, ray_direction, scene):
    # 1. Check global trimmed bounding box
    if not intersects_aabb(ray_origin, ray_direction, scene.global_bounding_box):
        return BACKGROUND_COLOR

    min_distance = INFINITY
    closest_object = None

    # 2. Iterate over objects
    for object in scene.objects:
        # 3. Cull using object's bounding volume
        if not intersects_aabb(ray_origin, ray_direction, object.bounding_volume):
            continue

        # 4. Evaluate SDF only if bounding volume is hit
        distance = evaluate_sdf(object.sdf_function, ray_origin, ray_direction)
        
        if distance < min_distance:
            min_distance = distance
            closest_object = object

    # 5. Render closest hit
    if closest_object is not None:
        return render_surface(closest_object, min_distance)
    else:
        return BACKGROUND_COLOR
```

## Subtopics

### Voxel Array Dimensionality Reduction
Adjusting the 3D texture size to the exact bounds of the data. This is distinct from compression as it changes the memory footprint and traversal range. Choose this when the scene has significant empty space around the data. See [Voxel Grid Optimization](4131-voxel-grid-optimization.md).

### SDF Culling
Using bounding volumes to skip SDF evaluations. This is distinct from smoothing or RLE encoding. Choose this when the scene contains many expensive primitives. See [Voxel Grid Optimization](4131-voxel-grid-optimization.md).

## Operating characteristics
*   **Time Complexity:** Reduces the number of SDF evaluations per ray. In a scene with 20 expensive primitives at 720p, enabling BV optimization reduced average frame duration from 41 ms (24 fps) to 21 ms (48 fps) [S2].
*   **Memory Complexity:** Reduces memory usage by loading only the necessary voxel data. A $512 \times 321 \times 512$ array uses less memory than a $512^3$ array [S1, unofficial].
*   **Strengths:** Eliminates false positives from empty space traversal [S1, unofficial]; localizes expensive computations to areas with complex geometry [S2]; enables separation of game world and entities for physics simulation [S1, unofficial].
*   **Limitations:** Does not improve lighting quality; AABBs can cause hard lighting artifacts if used for shading [S1, unofficial].
*   **When to Use:** When the scene has significant empty space or many expensive primitives.
*   **When Not to Use:** When the scene is uniformly dense or when lighting quality is prioritized over performance for the bounding volumes themselves.

## Background
The concept of bounding volume optimization in voxel rendering and raymarching has been explored in the context of reducing computational cost for SDF evaluation [S2]. It is also discussed in the context of voxel landscape rendering to reduce redundancy and memory usage [S1, unofficial]. The technique leverages the MIMD nature of modern GPUs to distribute computational load more effectively [S2].
