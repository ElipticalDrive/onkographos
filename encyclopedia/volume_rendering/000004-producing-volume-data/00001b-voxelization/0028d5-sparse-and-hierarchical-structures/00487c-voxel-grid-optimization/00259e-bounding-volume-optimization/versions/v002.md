# Bounding Volume Optimization

Also called: Adaptive Voxel-Array-Größe, BV Optimisation, Bounding Volume Optimisation, Bounding-Volume-Optimierung, SDF Bounding Volume Culling, Volumen-Größenanpassung

## Overview
Bounding Volume Optimization reduces the computational cost of volume rendering by eliminating unnecessary evaluations of expensive primitives, such as Signed Distance Fields (SDFs), for regions that do not contribute to the final image [S2]. It achieves this through two primary mechanisms: culling SDF evaluations using bounding volumes and resizing the voxel array to match the actual data extent, thereby removing unused memory and traversal false positives [S1, unofficial][S2]. Unlike sibling methods that focus on data compression or smoothing, this method optimizes the *access pattern* and *evaluation scope* during the raymarching or voxelization pipeline [S1, unofficial][S2].

## How it works
**Inputs:**
1.  A set of geometric primitives (e.g., SDFs) with their associated mathematical evaluation functions.
2.  A 3D voxel grid or raymarching domain.
3.  Bounding volumes (typically Axis-Aligned Bounding Boxes, AABBs) for each primitive.

**Outputs:**
1.  A reduced set of active primitives for each ray or voxel block.
2.  A resized voxel array (if array optimization is applied) containing only valid data.

**Data Structures:**
*   **Primitive List:** An array of objects, each containing:
    *   `id`: Unique identifier.
    *   `bounding_box`: AABB defined by `min` and `max` vectors (3 floats each).
    *   `sdf_function`: Pointer or reference to the distance function.
*   **Voxel Array:** A 3D texture or buffer. If optimized, its dimensions $(D_x, D_y, D_z)$ are determined by the min/max extents of the active voxel data, rather than a fixed power-of-two size [S1, unofficial].

**Steps:**

1.  **Bounding Volume Construction:** For each primitive $i$, compute or retrieve its AABB $B_i = [\mathbf{b}_{min}, \mathbf{b}_{max}]$. This volume encloses the region where the primitive's SDF is non-zero or relevant [S2].

2.  **Ray-Box Intersection Test:** For each ray (or voxel block traversal), perform an intersection test against all bounding volumes $B_i$.
    *   Let the ray be defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.
    *   The intersection test returns a boolean `hit` or a range $[t_{min}, t_{max}]$ along the ray.
    *   Formula for AABB intersection (slab method):
        $$ t_{min} = \max_i \left( \frac{b_{min,i} - o_i}{d_i} \right), \quad t_{max} = \min_i \left( \frac{b_{max,i} - o_i}{d_i} \right) $$
        where $i \in \{x, y, z\}$. If $t_{min} > t_{max}$ or $t_{max} < 0$, the ray does not intersect the box [S2, G].

3.  **Culling:**
    *   If a bounding volume $B_i$ does not intersect the ray within the current marching step or the relevant depth range, skip the evaluation of the primitive's SDF function $S_i(\mathbf{p})$ [S2].
    *   Only evaluate $S_i(\mathbf{p})$ for primitives where the intersection test passes [S2].

4.  **Voxel Array Resizing (Optional but recommended):**
    *   Determine the global bounding box of all active voxel data.
    *   Resize the voxel array dimensions from a fixed size (e.g., $512^3$) to the minimal enclosing box of the data (e.g., $512 \times 321 \times 512$) [S1, unofficial].
    *   This reduces memory bandwidth and eliminates "false positives" during traversal where the ray marches through empty space outside the data bounds [S1, unofficial].

5.  **Evaluation:**
    *   For each active primitive, compute the distance $d = S_i(\mathbf{p})$.
    *   Combine distances (e.g., minimum for union) to form the final SDF value [S2].

**Pseudocode:**

```python

        # Note: In a real raymarcher, this happens inside a loop advancing along the ray
        # Here we show the culling logic for a single point evaluation or block
        dist = prim['sdf_func'](ray_origin + ray_direction * current_distance)

            current_distance = dist
            hit_primitive = prim

def ray_box_intersection(origin, direction, bbox_min, bbox_max):
    """
    Returns (t_min, t_max) for intersection with AABB.
    Returns (inf, -inf) if no intersection.
    """
    t_min = -float('inf')
    t_max = float('inf')
    
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < bbox_min[i] or origin[i] > bbox_max[i]:
                return (float('inf'), -float('inf'))
        else:
            t1 = (bbox_min[i] - origin[i]) / direction[i]
            t2 = (bbox_max[i] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
            
    if t_min > t_max:
        return (float('inf'), -float('inf'))
        
    return (t_min, t_max)
```

**Parameters:**
*   **Bounding Volume Type:** AABBs are standard due to fast intersection tests [S1, unofficial][S2].
*   **Voxel Array Dimensions:** Should be set to the minimal bounding box of the actual data, not a fixed power of two [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Ray-box intersection tests can suffer from floating-point precision issues near the boundaries of the bounding box. Use epsilon values for comparisons [G].
*   **Degenerate Input:** If a primitive has zero volume (e.g., a plane or a point), the bounding box may be degenerate. Ensure the intersection test handles zero-length dimensions correctly [G].
*   **False Positives:** Using a fixed-size voxel array larger than the data extent causes the raymarcher to traverse empty space, leading to false positives and wasted computation [S1, unofficial].

## Operating characteristics
**Time Complexity:**
*   **Culling:** $O(N)$ per ray, where $N$ is the number of primitives. However, the constant factor is very small due to the simplicity of AABB intersection [S2].
*   **SDF Evaluation:** Reduced from $O(N)$ to $O(K)$, where $K$ is the number of primitives intersecting the ray's bounding volume. In complex scenes, $K \ll N$ [S2].

**Memory Complexity:**
*   **Voxel Array:** Reduced from $O(D^3)$ (fixed size) to $O(V)$, where $V$ is the number of active voxels. For example, reducing a $512^3$ array to $512 \times 321 \times 512$ saves significant memory [S1, unofficial].
*   **Bounding Volumes:** $O(N)$ storage for the bounding boxes of all primitives [S2].

**Measured Performance:**
*   In a scene with 20 expensive primitives at 720p, enabling BV optimization reduced average frame duration from 41 ms (24 fps) to 21 ms (48 fps) [S2].
*   The optimization localizes expensive computations to areas with complex geometry, making the frame duration more uniform and efficient [S2].

**Strengths and Limitations:**
*   **Strengths:** Significant speedup in scenes with many primitives; reduced memory footprint; better GPU utilization by distributing expensive threads only where needed [S2].
*   **Limitations:** Requires pre-computation of bounding volumes; less effective if most primitives are always visible or if the scene is sparse but large [S2].
*   **When to Use:** Scenes with many expensive SDF primitives; scenes with significant empty space; when memory bandwidth is a bottleneck [S1, unofficial][S2].
*   **When Not to Use:** Scenes with very few primitives; scenes where primitives are uniformly distributed and always intersected [S2].

## Background
Bounding Volume Optimization originated as a technique to improve the performance of raymarched distance fields. It was notably explored in the context of CUDA-based raymarching engines, where the high cost of SDF evaluation necessitated culling strategies [S2]. The concept of resizing voxel arrays to fit data extents has been discussed in academic works on voxel-based rendering, particularly in the context of game development and physics simulation, where separating the game world from entities allows for efficient memory management [S1, unofficial].
