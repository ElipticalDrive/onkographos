# Grid Resolution Calculation
Also called: proportional grid, voxel count
## Overview
This method calculates the discrete resolution of a 3D voxel grid based on a target number of voxels along the Y-axis and the aspect ratio of the scene's bounding box [S1, unofficial]. It ensures the grid dimensions fit the specified physical volume while maintaining a consistent aspect ratio [S1, unofficial]. It is distinguished from [Grid Resolution Selection via Lambda](3270-grid-resolution-selection-via-lambda.md) by its direct geometric division approach rather than optimizing for primitive-to-volume ratios via a scaling factor [S1, unofficial].
## How it works
**Inputs:**
- `voxels_on_y`: Target number of voxels along the Y-axis (integer).
- `size`: Bounding box dimensions as a 3D vector $(size.x, size.y, size.z)$ [S1, unofficial].

**Outputs:**
- `Grid X`, `Grid Y`, `Grid Z`: The number of voxels in each dimension [S1, unofficial].

**Data Structures:**
- `size`: `glm::vec3` or equivalent float3 structure containing width, height, and depth [S1, unofficial].
- `Grid`: `glm::uvec3` or equivalent uint3 structure containing the calculated resolutions [S1, unofficial].

**Steps:**
1. Set the Y-axis resolution to the target value:
   $$Grid.Y = \text{voxels\_on\_y}$$
2. Calculate the X-axis resolution by scaling the Y-resolution by the aspect ratio of the bounding box width to height, rounding up to the nearest integer:
   $$Grid.X = \lceil \frac{\text{voxels\_on\_y}}{size.y} \times size.x \rceil$$
3. Calculate the Z-axis resolution by scaling the Y-resolution by the aspect ratio of the bounding box depth to height, rounding up to the nearest integer:
   $$Grid.Z = \lceil \frac{\text{voxels\_on\_y}}{size.y} \times size.z \rceil$$

**Parameters:**
- `voxels_on_y`: Typical values depend on the desired visual fidelity and memory constraints. Not given in the sources.
- `size`: Determined by the scene's bounding box. Not given in the sources.

**Edge Cases and Pitfalls:**
- Division by zero: If `size.y` is zero, the calculation is undefined. A guard should check for this [G].
- Precision: Use floating-point arithmetic for the intermediate scaling before applying the ceiling function to avoid truncation errors [G].

**Pseudocode:**
```python
def calculate_grid_resolution(voxels_on_y: int, size: Vector3) -> Vector3:
    """
    Calculate grid resolution based on target Y voxels and bounding box size.
    
    Args:
        voxels_on_y: Target number of voxels on the Y-axis.
        size: Bounding box dimensions (x, y, z).
        
    Returns:
        Grid resolution (x, y, z).
    """
    if size.y == 0:
        raise ValueError("Bounding box height (size.y) cannot be zero.")
        
    grid_y = voxels_on_y
    grid_x = ceil((voxels_on_y / size.y) * size.x)
    grid_z = ceil((voxels_on_y / size.y) * size.z)
    
    return Vector3(grid_x, grid_y, grid_z)
```
## Subtopics

### Adaptive Voxel Spacing
This variant adjusts voxel grid resolution dynamically using a quality parameter to balance performance and detail [S2, unofficial]. The quality parameter ranges from 0.0f to 3.0f, adjustable by key presses (+/-) [S2, unofficial]. The X and Y voxel sizes are calculated as $(2.0f \times vw.aspx) / vw.xdim \times (1.0f + quality \times 4.0f)$, while the Z voxel size is $(2.0f \times vw.aspz) / 200.0f \times (1.0f + quality)$ [S2, unofficial]. This method allows for real-time adjustment of granularity based on user preference or performance constraints [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for the calculation itself.
- **Memory Complexity:** $O(1)$ for the calculation.
- **Strengths:** Simple to implement; ensures the grid aspect ratio matches the scene bounding box [S1, unofficial].
- **Limitations:** Does not account for scene complexity or primitive count, unlike lambda-based methods [S1, unofficial].
- **When to use:** When a fixed target resolution along one axis is desired, and the scene aspect ratio is known [S1, unofficial].
- **When not to use:** When the scene has varying complexity or when optimal traversal cost is critical [S1, unofficial].
## Background
This method is used in voxelization pipelines where the grid dimensions must align with the scene's bounding box proportions [S1, unofficial]. It is part of the broader family of voxel grid optimization techniques [S1, unofficial].
