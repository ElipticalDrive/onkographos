# Grid Resolution Calculation

Also called: proportional grid, voxel count

## Overview
This method calculates the dimensions of a uniform 3D voxel grid by fixing the resolution along one axis (typically Y) and deriving the other axes (X, Z) based on the aspect ratios of the scene's bounding box. It ensures the grid maintains the geometric proportions of the scene while allowing the user to control the total voxel count via a single parameter. It differs from [Grid Resolution Selection via Lambda](3270-grid-resolution-selection-via-lambda.md) by relying on spatial aspect ratios rather than primitive counts, and from [Adaptive Voxel Spacing](#adaptive-voxel-spacing) by producing a uniform grid rather than variable-sized cells.

## How it works
**Inputs:**
- `voxels_on_y`: Target number of voxels along the Y-axis (integer).
- `size`: Bounding box dimensions of the scene, represented as a 3D vector $(size.x, size.y, size.z)$ [S1, unofficial].

**Outputs:**
- `grid_resolution`: A 3D vector $(grid.x, grid.y, grid.z)$ representing the number of voxels in each dimension [S1, unofficial].

**Data Structures:**
- `size`: `vec3` (float).
- `grid_resolution`: `uvec3` (unsigned integer).

**Steps:**
1. Set the Y-axis resolution to the target value:
   $$grid.y = \text{voxels\_on\_y}$$
2. Calculate the X-axis resolution by scaling the Y-resolution by the ratio of the bounding box width to height, rounding up to the nearest integer:
   $$grid.x = \lceil \frac{\text{voxels\_on\_y}}{size.y} \times size.x \rceil$$
3. Calculate the Z-axis resolution by scaling the Y-resolution by the ratio of the bounding box depth to height, rounding up to the nearest integer:
   $$grid.z = \lceil \frac{\text{voxels\_on\_y}}{size.y} \times size.z \rceil$$

**Pseudocode:**
```python
import math

def calculate_grid_resolution(voxels_on_y: int, size_x: float, size_y: float, size_z: float) -> tuple:
    """
    Calculate uniform grid dimensions based on Y-axis target and bounding box aspect ratios.
    
    Args:
        voxels_on_y: Target voxel count for the Y-axis.
        size_x: Width of the scene bounding box.
        size_y: Height of the scene bounding box.
        size_z: Depth of the scene bounding box.
        
    Returns:
        tuple: (grid_x, grid_y, grid_z) as integers.
    """
    if size_y == 0:
        raise ValueError("Bounding box height (size_y) cannot be zero.")
        
    grid_y = voxels_on_y
    grid_x = math.ceil((voxels_on_y / size_y) * size_x)
    grid_z = math.ceil((voxels_on_y / size_y) * size_z)
    
    return (grid_x, grid_y, grid_z)
```

**Edge Cases and Pitfalls:**
- **Zero Dimension:** If `size.y` is zero, division by zero occurs. A guard clause is required [G].
- **Precision:** Using floating-point division before ceiling ensures the aspect ratio is preserved. Integer division would truncate the ratio and distort the grid shape.

## Subtopics

### Adaptive Voxel Spacing
This variant adjusts voxel grid resolution dynamically using a quality parameter to balance performance and detail [S2, unofficial]. It differs from the standard proportional method by producing non-uniform voxel sizes rather than a uniform grid [S2, unofficial].

**Definition:**
Adjusts voxel grid resolution dynamically using a quality parameter to balance performance and detail [S2, unofficial].

**Steps:**
1. Accept a `quality` parameter ranging from $0.0$ to $3.0$, adjustable by user input (e.g., key presses) [S2, unofficial].
2. Calculate X and Y voxel sizes using the formula:
   $$\text{voxel\_size}_{x/y} = \frac{2.0 \times vw\_aspx}{vw\_xdim} \times (1.0 + \text{quality} \times 4.0)$$
3. Calculate Z voxel size using the formula:
   $$\text{voxel\_size}_z = \frac{2.0 \times vw\_aspz}{200.0} \times (1.0 + \text{quality})$$
   Where $vw\_aspx$, $vw\_xdim$, and $vw\_aspz$ are scene-specific viewport or aspect parameters [S2, unofficial].

**When to choose:**
Use when visual fidelity needs to be traded for performance in real-time applications, and uniform grid constraints are too restrictive.

## Operating characteristics
- **Time Complexity:** $O(1)$ arithmetic operations.
- **Memory Complexity:** $O(1)$ for the calculation itself; the resulting grid memory scales with the product of the calculated dimensions.
- **Strengths:** Simple to implement; guarantees the grid matches the scene's aspect ratio; single parameter controls density.
- **Limitations:** Does not account for scene complexity (number of primitives); may result in over-sampling empty space or under-sampling dense regions if the bounding box is loose.

## Background
This method is implemented in the `voxelizer` project by loryruta, which uses it to configure the voxel grid for ray tracing [S1, unofficial]. It is a standard approach in voxel-based rendering to ensure that the discretization error is consistent across axes relative to the scene's geometry.
