# Grid Resolution Calculation

Also called: proportional grid, voxel count

## Overview
Grid Resolution Calculation determines the discrete dimensions $(N_x, N_y, N_z)$ of a uniform 3D voxel grid based on the scene's bounding box geometry and a target voxel density. It solves the problem of mapping continuous world-space extents to a finite integer grid, ensuring that the resulting cells maintain a specific aspect ratio relative to the bounding box. It differs from its siblings by providing a static, proportional scaling method [S1, unofficial], whereas variants like [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) or [Adaptive Voxel Spacing] adjust resolution dynamically based on quality parameters or local detail [S2, unofficial].

## How it works
**Inputs:**
- `size`: A 3D vector $(size.x, size.y, size.z)$ representing the dimensions of the scene bounding box in world units.
- `voxels_on_y`: An integer scalar representing the desired number of voxels along the Y-axis.

**Outputs:**
- `grid`: A 3D integer vector $(N_x, N_y, N_z)$ representing the number of voxels in each dimension.

**Data Structures:**
- `size`: `vec3` (float).
- `voxels_on_y`: `int` or `float`.
- `grid`: `uvec3` (unsigned integer).

**Steps:**
1. Set the Y-dimension resolution directly to the target value:
   $$N_y = \text{voxels\_on\_y}$$
2. Calculate the X-dimension resolution by scaling the target Y-count by the aspect ratio of the bounding box in X relative to Y, then rounding up:
   $$N_x = \lceil N_y \times \frac{size.x}{size.y} \rceil$$
3. Calculate the Z-dimension resolution by scaling the target Y-count by the aspect ratio of the bounding box in Z relative to Y, then rounding up:
   $$N_z = \lceil N_y \times \frac{size.z}{size.y} \rceil$$

**Pseudocode:**
```python
def calculate_grid_resolution(size: Vec3, voxels_on_y: int) -> UVec3:
    """
    Calculate grid resolution based on bounding box size and target Y voxels.
    
    Args:
        size: Bounding box dimensions (x, y, z).
        voxels_on_y: Target number of voxels along the Y-axis.
        
    Returns:
        Grid dimensions (nx, ny, nz).
    """
    ny = voxels_on_y
    
    # Calculate nx and nz based on aspect ratios, rounding up to ensure full coverage
    # Using math.ceil equivalent for integer arithmetic
    nx = int(ny * (size.x / size.y))
    if (ny * size.x) % size.y != 0:
        nx += 1
        
    nz = int(ny * (size.z / size.y))
    if (ny * size.z) % size.y != 0:
        nz += 1
        
    return UVec3(nx, ny, nz)
```

**Edge Cases and Pitfalls:**
- **Zero Division:** If `size.y` is zero or near-zero, the aspect ratios become undefined. A guard clause should check for `size.y > epsilon` [G].
- **Rounding Direction:** The source uses `ceil` (rounding up) [S1, unofficial]. Rounding down may leave parts of the bounding box uncovered. Rounding up may introduce slight empty space at the boundaries.
- **Integer Overflow:** For very large bounding boxes or high voxel counts, intermediate calculations like `ny * size.x` may overflow standard 32-bit integers if not handled carefully [G].

## Subtopics

### Adaptive Voxel Spacing
This variant adjusts voxel grid resolution dynamically using a quality parameter to balance performance and detail [S2, unofficial]. It differs from the static proportional method by allowing runtime adjustment of voxel sizes based on user input or scene complexity.

- **Definition:** Adjusts voxel grid resolution dynamically using a quality parameter to balance performance and detail [S2, unofficial].
- **Steps:**
  1. Define a quality parameter ranging from $0.0f$ to $3.0f$, adjustable by key presses (+/-) [S2, unofficial].
  2. Calculate X and Y voxel sizes using the formula:
     $$\text{voxel\_size}_{x,y} = \frac{2.0f \times vw.aspx}{vw.xdim} \times (1.0f + \text{quality} \times 4.0f)$$
  3. Calculate Z voxel size using the formula:
     $$\text{voxel\_size}_z = \frac{2.0f \times vw.aspz}{200.0f} \times (1.0f + \text{quality})$$
  4. Iterate through the world space using these calculated voxel sizes to draw or process voxels [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for the calculation of grid dimensions given the bounding box and target Y count.
- **Memory Complexity:** $O(1)$ auxiliary space. The resulting grid size determines the memory footprint of the subsequent voxelization, but the calculation itself uses constant memory.
- **Strengths:** Simple to implement; ensures the grid aspect ratio matches the scene bounding box; easy to control resolution via a single scalar (`voxels_on_y`).
- **Limitations:** Does not account for local scene complexity; uniform resolution may waste memory in empty regions or lack detail in dense regions.
- **When to use:** When a uniform grid is required and the scene bounding box is known in advance.
- **When not to use:** When adaptive resolution or sparse structures are needed.

## Background
The method is implemented in the `voxelizer` project by loryruta [S1, unofficial]. It is used in the context of voxel-based rendering and ray tracing, where a uniform grid is constructed to represent the scene geometry for efficient traversal.
