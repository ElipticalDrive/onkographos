# Grid Resolution Selection via Lambda

Also called: Cleary et al. Heuristic, Lambda Grid Sizing, Uniform Grid Resolution Formula

## Overview
This method determines the number of cells in each dimension of a uniform or hierarchical spatial acceleration grid based on the scene's bounding box volume and the count of geometric primitives, using a scaling factor $\lambda$ [S1][S3, unofficial]. It solves the problem of balancing grid granularity against memory overhead and traversal cost by targeting a cell count proportional to the primitive count [S1]. It is distinguished from [Voxel Grid Resolution Calculation](13832-voxel-grid-resolution-calculation.md) by its explicit use of the $\lambda$ scaling factor derived from surface-area-to-volume optimization principles, rather than fixed aspect-ratio constraints alone [S1][S3, unofficial].

## How it works
**Inputs:**
- $N$: Number of geometric primitives (triangles or particles) in the scene.
- $V$: Volume of the scene's bounding box.
- $d_x, d_y, d_z$: Extents (diagonal lengths or box dimensions) of the bounding box along the X, Y, and Z axes.
- $\lambda$: User-defined scaling factor (grid density).

**Outputs:**
- $N_x, N_y, N_z$: Number of grid cells in each dimension.

**Data Structures:**
The method computes integer resolutions. No persistent data structure is created by this step alone; the resulting integers are used to allocate a 3D array of cells.

**Steps:**
1. Calculate the ratio of scaled primitive count to volume: $R = \frac{\lambda N}{V}$.
2. Compute the resolution for each axis using the bounding box extents and the cube root of $R$.
   - Note: Sources [S1][S3, unofficial] use the cube root ($\sqrt[3]{\cdot}$), while [S2, unofficial] uses the square root ($\sqrt{\cdot}$). The cube root formulation is attributed to Cleary et al. [CWVB83] and is consistent with the "cubically shaped cells" optimization rationale [S1]. The square root formulation in [S2, unofficial] appears to be a deviation or error in that specific GPU-focused paper, as it contradicts the cited Cleary heuristic. The cube root formula is implemented below as the primary method.
3. Round the resulting floating-point resolutions to the nearest integer.

**Formula:**
$$N_x = d_x \sqrt[3]{\frac{\lambda N}{V}}$$
$$N_y = d_y \sqrt[3]{\frac{\lambda N}{V}}$$
$$N_z = d_z \sqrt[3]{\frac{\lambda N}{V}}$$

Where:
- $N_x, N_y, N_z$: Number of cells in each dimension.
- $d_x, d_y, d_z$: Extents of the bounding box in each dimension. [S1][S3, unofficial] define $d$ as the diagonal length of the grid in that dimension, but [S3, unofficial] clarifies it as the extent of the box. Given $V = d_x d_y d_z$ for a box aligned with axes, if $d$ is the full diagonal, the formula scales differently. However, standard interpretation of "extent" in this context (and consistency with $V$) implies $d_i$ is the side length. If $d_i$ is the side length, then $V = d_x d_y d_z$. The formula $N_i = d_i \sqrt[3]{\frac{\lambda N}{V}}$ ensures that if $N_i$ are equal, the cells are cubic.
- $V$: Volume of the bounding box.
- $N$: Number of primitives.
- $\lambda$: Scaling factor.

**Parameters:**
- $\lambda$: Typical value is 5 [S1]. Most scenes are insensitive to this parameter and achieve best performance around $\lambda = 5$ [S1].

**Pitfalls:**
- **Hardware Assumptions:** Optimal $\lambda$ values derived for CPU ray tracing (e.g., by Ize et al. [ISP07]) may be sub-optimal for GPU ray tracing because they assume fast atomic operations and compute-limited traversal, which may not hold for specific GPU hardware [S2, unofficial].
- **Primitive Representation:** Treating geometric primitives as points can severely limit quality for other acceleration structures like BVHs [S2, unofficial]. While this method is for grids, the underlying assumption of point-like primitives affects the validity of the density heuristic.
- **Particle Datasets:** For particle-based simulations with extremely large particle counts, the original insensitivity to $\lambda$ may not hold, and optimal $\lambda$ may shift significantly (e.g., to 1) [S5].

**Pseudocode:**
```python
def calculate_grid_resolution(num_primitives, bounding_box_extents, lambda_factor):
    """
    Calculates grid resolution using the Cleary et al. heuristic.
    
    Args:
        num_primitives (int): N, the number of triangles or particles.
        bounding_box_extents (tuple): (dx, dy, dz), the side lengths of the bounding box.
        lambda_factor (float): Lambda, the scaling factor (typically 5).
        
    Returns:
        tuple: (Nx, Ny, Nz), the number of cells in each dimension.
    """
    dx, dy, dz = bounding_box_extents
    
    # Calculate volume
    volume = dx * dy * dz
    
    # Avoid division by zero
    if volume == 0:
        return (1, 1, 1)
        
    # Calculate the scaling term
    # Using cube root as per Cleary et al. [S1][S3, unofficial]
    scaling_term = (lambda_factor * num_primitives / volume) ** (1/3)
    
    # Calculate resolutions
    nx = dx * scaling_term
    ny = dy * scaling_term
    nz = dz * scaling_term
    
    # Round to nearest integer
    nx = int(round(nx))
    ny = int(round(ny))
    nz = int(round(nz))
    
    # Ensure minimum resolution of 1
    nx = max(1, nx)
    ny = max(1, ny)
    nz = max(1, nz)
    
    return (nx, ny, nz)
```

## Subtopics

### [Uniform Grid Construction](4876-uniform-grid-construction.md)
Uniform Grid Construction is a two-step method to create a spatial acceleration structure for ray tracing by determining grid resolution and partitioning geometric objects into grid cells, allowing duplicates if an object overlaps multiple cells. It is distinguished from its sibling, [Hierarchical Grid Organization with Macrocells](5025-hierarchical-grid-organization-with-macrocells.md), by its flat, non-hierarchical storage of primitives in a regular 3D array, and from [Coarse Grid for Large Models](5481-coarse-grid-for-large-models.md) by its explicit optimization of cell count based on average object density rather than fixed coarse granularity.

### [Hierarchical Grid Organization with Macrocells](5025-hierarchical-grid-organization-with-macrocells.md)
This method organizes volumetric primitives (such as particles or spheres) into a two-level hierarchical grid structure to accelerate ray traversal and culling. It builds on [Grid Resolution Selection via Lambda](3270-grid-resolution-selection-via-lambda.md) to determine the finest grid resolution, then imposes a coarser macrocell level on top. It differs from [Uniform Grid Construction](4876-uniform-grid-construction.md) by adding hierarchical culling and from [Coarse Grid for Large Models](5481-coarse-grid-for-large-models.md) by using a specific two-level macrocell structure with parameter-range culling rather than just a static coarse grid.

### [Coarse Grid for Large Models](5481-coarse-grid-for-large-models.md)
This method selects a significantly coarser voxel grid resolution (lower $\lambda$) for very large triangle models to minimize grid rebuild time, accepting increased ray traversal overhead to achieve better aggregate frame rates. It differs from the standard [Grid Resolution Selection via Lambda](3270-grid-resolution-selection-via-lambda.md) approach, which targets moderate scenes with $\lambda \approx 5$, by prioritizing build speed over traversal efficiency for models exceeding several million triangles.

### Voxel Size Calculation (Optical/Diffraction-based)
In optical/volumetric rendering contexts involving laser focal points, voxel size is determined by diffraction limits rather than primitive density. The size of an emission dot (voxel) is assumed equal to the size of the laser focal point, which is an oval with two diameters [S4]. The diameter perpendicular to the laser beam ($w_f$) is the diffraction limit: $w_f = \frac{2\lambda r}{a}$, where $\lambda$ is the wavelength, $r$ is the focal length, and $a$ is the original beam width [S4]. The diameter along the laser beam ($w_d$) is derived geometrically: $w_d = 4\lambda \left(\frac{r}{a}\right)^2$ [S4].

### Grid Resolution Parameter Tuning
In modified coherent grid traversal approaches for particle-based simulation data, the parameter $\lambda$ relates the number of cells to the total number of particles. Unlike the original CGT algorithm where most scenes were largely insensitive to $\lambda$, performance in these modified algorithms varies widely with different values of $\lambda$ due to the extremely large number of particles in test datasets [S5]. After testing values in the range [0.2, 5], $\lambda = 1$ provides the best performance for these specific datasets [S5].

## Operating characteristics
- **Time Complexity:** $O(1)$ for the resolution calculation itself. The subsequent grid construction (inserting primitives) is $O(N \cdot k)$ where $k$ is the average number of cells a primitive overlaps.
- **Memory Complexity:** $O(N_x N_y N_z)$ for the grid structure. With $\lambda=5$, the number of cells is roughly $5N$, so memory usage is proportional to the number of primitives.
- **Measured Performance:** Optimum performance for grid resolution is reached at approximately $\lambda \approx 5$ for nearly all tested scenes, both static and dynamic [S1].
- **Strengths:** Cubically shaped cells minimize a grid's expected ray tracing cost due to having the smallest surface area in relation to volume [S1]. It is simple to implement and robust for general scenes.
- **Limitations:** Insensitive to $\lambda$ in many cases, but this insensitivity may break down for very large particle datasets [S5]. GPU-specific optimizations may require different $\lambda$ values than CPU-based analyses suggest [S2, unofficial].
- **When to use:** General-purpose ray tracing of animated or static scenes with moderate triangle counts.
- **When not to use:** Very large models where build time is critical (use [Coarse Grid for Large Models](5481-coarse-grid-for-large-models.md)) or particle simulations with extreme counts requiring tuned $\lambda$ [S5].

## Background
The heuristic was introduced by Cleary et al. [CWVB83] and also used by Wald et al. [WIK∗ 06] [S2, unofficial]. It is based on the principle that cubically shaped cells minimize the expected ray tracing cost by minimizing surface area relative to volume [S1]. The method has been adapted for GPU ray tracing, where optimal densities may differ from CPU-based theoretical analyses [S2, unofficial].
