# Uniform Grid Construction

Also called: Grid Resolution and Object Partitioning, PBRT Uniform Grid Construction

## Overview
Uniform Grid Construction is a two-step method to create a spatial acceleration structure for ray tracing by determining grid resolution and partitioning geometric objects into grid cells, allowing duplicates if an object overlaps multiple cells [S1, unofficial]. It builds on [Grid Resolution Selection via Lambda](3270-grid-resolution-selection-via-lambda.md) to compute cell dimensions, and differs from [Hierarchical Grid Organization with Macrocells](5025-hierarchical-grid-organization-with-macrocells.md) by using a flat regular array rather than a tree, and from [Coarse Grid for Large Models](5481-coarse-grid-for-large-models.md) by optimizing cell count based on average object density rather than fixed coarse granularity [S1, unofficial].

## How it works
**Inputs:**
- $N$: Total number of geometric objects [S1, unofficial].
- $n$: Target average number of objects per grid cell [S1, unofficial].
- $MaxResolution$: User-specified maximum resolution along each axis [S1, unofficial].
- $xSize, ySize, zSize$: Dimensions of the axis-aligned bounding box (AABB) containing all objects [S1, unofficial].
- For each object: its AABB defined by $(x_{min}, y_{min}, z_{min})$ and $(x_{max}, y_{max}, z_{max})$ [G].

**Outputs:**
- A 3D uniform grid data structure with dimensions $(xResolution, yResolution, zResolution)$ [S1, unofficial].
- Each cell contains a list of object indices that intersect the cell [S1, unofficial].

**Data Structures:**
- **Grid:** A 3D array or flattened 1D array of size $xResolution \times yResolution \times zResolution$ [S1, unofficial]. Each element is a dynamic list (e.g., Python `list`) storing object IDs [G].
- **Object AABB:** Stored separately or as part of the object data [G].

**Formulas:**
1.  **Cell Volume Calculation:**
    $$boxVolume = xSize \times ySize \times zSize$$
    $$a = \left( \frac{n \times boxVolume}{N} \right)^{1/3} = n^{1/3} \times \left( \frac{boxVolume}{N} \right)^{1/3}$$
    Where $a$ is the side length of the cubic cell [S1, unofficial].

    *PBRT Simplification:* If assuming a cube of the maximum box dimension and $n=3^3=27$, the formula simplifies to:
    $$a = \frac{3 \times \max(xSize, ySize, zSize)}{N^{1/3}}$$
    [S1, unofficial]

2.  **Resolution Calculation:**
    $$xResolution = \text{clamp}(\text{round}(xSize / a), 1, MaxResolution)$$
    $$yResolution = \text{clamp}(\text{round}(ySize / a), 1, MaxResolution)$$
    $$zResolution = \text{clamp}(\text{round}(zSize / a), 1, MaxResolution)$$
    *Note:* The source text contains a typo using $ySize$ for $zResolution$, but the logical intent and implementation context imply $zSize$ [S1, unofficial].

3.  **Grid Index Calculation:**
    For a point $P=(x_p, y_p, z_p)$ within the global AABB:
    $$gridIndex(P) = \left( \frac{x_p - x_{min\_AABB}}{xSize\_AABB}, \frac{y_p - y_{min\_AABB}}{ySize\_AABB}, \frac{z_p - z_{min\_AABB}}{zSize\_AABB} \right)$$
    [S1, unofficial]
    This yields normalized coordinates in $[0, 1]$. The cell index is obtained by multiplying by the resolution and flooring: $idx = \lfloor gridIndex(P) \times resolution \rfloor$.

**Parameters:**
- $n$: Typical value is $3^3 = 27$ (implied by PBRT suggestion) or a user-defined small number representing the average number of ray-intersection tests per cell intersection [S1, unofficial].
- $MaxResolution$: Typical value is 64, suggested by the PBRT textbook to limit memory overhead [S1, unofficial].

**Steps:**
1.  Calculate $a$ using the chosen formula (standard or PBRT simplified) [S1, unofficial].
2.  Compute $xResolution, yResolution, zResolution$ using the clamp function [S1, unofficial].
3.  Initialize the grid data structure with the computed dimensions [G].
4.  For each object:
    a.  Compute the grid indices for the object's minimum bound: $(i_{min}, j_{min}, k_{min}) = gridIndex(minBound)$ [S1, unofficial].
    b.  Compute the grid indices for the object's maximum bound: $(i_{max}, j_{max}, k_{max}) = gridIndex(maxBound)$ [S1, unofficial].
    c.  Clamp these indices:
        - If index $< 0$, set to $0$.
        - If index $> resolution - 1$, set to $resolution - 1$ [S1, unofficial].
    d.  Iterate through all cells $(i, j, k)$ where $i \in [i_{min}..i_{max}]$, $j \in [j_{min}..j_{max}]$, and $k \in [k_{min}..k_{max}]$ [S1, unofficial].
    e.  Add the object ID to the list of each visited cell [S1, unofficial].

**Pseudocode:**
```python
import math

def uniform_grid_construction(objects, n=27, max_resolution=64):
    """
    Construct a uniform grid acceleration structure.
    
    Args:
        objects: List of objects, each having a method get_aabb() returning 
                 (x_min, y_min, z_min, x_max, y_max, z_max).
        n: Target average objects per cell.
        max_resolution: Maximum resolution per axis.
        
    Returns:
        grid: 3D list of lists of lists containing object indices.
        resolution: Tuple (x_res, y_res, z_res).
    """
    if not objects:
        return [], (0, 0, 0)

    # 1. Compute global AABB
    x_min_global = min(obj.get_aabb()[0] for obj in objects)
    y_min_global = min(obj.get_aabb()[1] for obj in objects)
    z_min_global = min(obj.get_aabb()[2] for obj in objects)
    x_max_global = max(obj.get_aabb()[3] for obj in objects)
    y_max_global = max(obj.get_aabb()[4] for obj in objects)
    z_max_global = max(obj.get_aabb()[5] for obj in objects)

    x_size = x_max_global - x_min_global
    y_size = y_max_global - y_min_global
    z_size = z_max_global - z_min_global
    
    # Handle degenerate cases where size is 0
    if x_size == 0: x_size = 1e-9
    if y_size == 0: y_size = 1e-9
    if z_size == 0: z_size = 1e-9

    N = len(objects)
    box_volume = x_size * y_size * z_size
    
    # 2. Calculate cell size 'a'
    a = math.pow((n * box_volume) / N, 1/3)
    if a < 1e-9:
        a = 1e-9

    # 3. Calculate resolutions
    def clamp(val, min_val, max_val):
        return max(min_val, min(val, max_val))

    x_res = clamp(round(x_size / a), 1, max_resolution)
    y_res = clamp(round(y_size / a), 1, max_resolution)
    z_res = clamp(round(z_size / a), 1, max_resolution) # Corrected from ySize to zSize per source typo [S1, unofficial]

    # 4. Initialize Grid
    grid = [[[[] for _ in range(z_res)] for _ in range(y_res)] for _ in range(x_res)]

    # 5. Partition objects
    for obj_idx, obj in enumerate(objects):
        x_min, y_min, z_min, x_max, y_max, z_max = obj.get_aabb()
        
        # Compute indices using cell size 'a' (equivalent to normalized * resolution)
        i_min = clamp(int(math.floor((x_min - x_min_global) / a)), 0, x_res - 1)
        i_max = clamp(int(math.floor((x_max - x_min_global) / a)), 0, x_res - 1)
        j_min = clamp(int(math.floor((y_min - y_min_global) / a)), 0, y_res - 1)
        j_max = clamp(int(math.floor((y_max - y_min_global) / a)), 0, y_res - 1)
        k_min = clamp(int(math.floor((z_min - z_min_global) / a)), 0, z_res - 1)
        k_max = clamp(int(math.floor((z_max - z_min_global) / a)), 0, z_res - 1)

        # Add object to all intersecting cells
        for i in range(i_min, i_max + 1):
            for j in range(j_min, j_max + 1):
                for k in range(k_min, k_max + 1):
                    grid[i][j][k].append(obj_idx)

    return grid, (x_res, y_res, z_res)
```

**Edge Cases and Pitfalls:**
- **Boundary Indices:** Rays entering the bounding box from the maximum end may produce an index equal to the resolution (e.g., $xResolution$), which is out of bounds for the range $[0..xResolution-1]$ [S1, unofficial].
- **Floating-Point Precision:** Due to precision issues, a ray entering from the minimum end may produce an index of $-1$ [S1, unofficial].
- **Mitigation:** All grid indices must be clamped: indices less than $0$ are set to $0$, and indices greater than $resolution-1$ are set to $resolution-1$ [S1, unofficial].

## Subtopics

### [Sort-last Grid Construction](12788-sort-last-grid-construction.md)
Sort-last Grid Construction is a voxelization method that assigns geometric primitives to grid cells by iterating over primitives and determining which cells they intersect. It solves the problem of building an acceleration structure for ray tracing by creating a uniform grid where objects are stored in all cells they overlap. It is distinguished from its sibling, Sort-first Grid Construction, by its iteration order: sort-last processes primitives to find cells, whereas sort-first processes cells to find primitives.

### Heterogeneous Grid
An approach in adaptive grid construction where the number of voxels is proportional to the number of objects, but voxels are made cubic as much as possible [S2, unofficial]. The number of cells along an axis is set proportional to the relative length of the axis [S2, unofficial]. This setting is generally more efficient than the regular $N^{1/3}$ setting because it assumes uniform ray direction, although this assumption is often violated in practice [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Resolution calculation is $O(1)$ [G]. Partitioning is $O(N \cdot k)$, where $N$ is the number of objects and $k$ is the average number of cells an object intersects [G]. In the worst case (large objects), $k$ can be proportional to the grid volume [G].
- **Memory Complexity:** $O(xResolution \times yResolution \times zResolution + N_{total\_references})$, where $N_{total\_references}$ is the total number of object-cell associations [G]. Memory overhead increases with higher resolution [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Higher grid resolution reduces object partition size, leading to faster ray-object intersection tests [S1, unofficial]. However, it increases memory overhead and the number of cells to traverse along a ray, which can counterbalance the speed-up [S1, unofficial].
- **Strengths:** Simple to implement; robust; provides a good baseline for acceleration structures [G].
- **Limitations:** Inefficient for scenes with highly non-uniform object distribution; high memory usage for high resolutions; duplicate storage of objects in multiple cells [G].
- **When to use:** Scenes with relatively uniform object distribution; when simplicity is prioritized over optimal performance [G].
- **When not to use:** Scenes with large variations in object density; memory-constrained environments [G].

## Background
Originating from standard ray tracing acceleration techniques, this method is described in the PBRT textbook and discussed in various online resources such as Sumant Pattanaik's Observable notebook [S1, unofficial]. The concept of using $N^{1/3}$ for resolution is a pragmatic rule often cited in real-time rendering literature, such as RTN (Ray Tracing News) [S2, unofficial].
