# Grid Resolution Selection via Lambda

Also called: Cleary et al. Heuristic, Lambda Grid Sizing, Uniform Grid Resolution Formula

## Overview
This method determines the number of cells in each dimension of a uniform 3D grid based on the scene's bounding box volume, the number of primitives, and a scaling factor $\lambda$ [S1][S2, unofficial]. It solves the problem of selecting an appropriate grid resolution that balances build time and traversal efficiency by approximating cubically shaped cells, which minimize the expected ray tracing cost due to their optimal surface-area-to-volume ratio [S1]. It differs from adaptive methods by using a fixed global resolution derived from scene statistics, and from simple fixed-resolution approaches by scaling dynamically with primitive count [S1][S2, unofficial].

## How it works
**Inputs:**
*   $N$: Number of primitives (triangles) in the scene.
*   $V$: Volume of the scene's bounding box.
*   $d_x, d_y, d_z$: Extents (diagonal lengths or bounding box dimensions) of the scene's bounding box in each dimension.
*   $\lambda$: User-defined scaling factor (grid density).

**Outputs:**
*   $N_x, N_y, N_z$: Number of cells in the grid along the x, y, and z axes, respectively.

**Data Structures:**
No complex data structures are required for the calculation itself. The output integers define the dimensions of the uniform grid array to be allocated.

**Steps:**
1.  Calculate the term inside the cube root: $T = \frac{\lambda N}{V}$.
2.  Compute the number of cells for each dimension using the cube root of $T$ scaled by the respective bounding box extent:
    $$N_x = d_x \sqrt[3]{T}$$
    $$N_y = d_y \sqrt[3]{T}$$
    $$N_z = d_z \sqrt[3]{T}$$
3.  Round $N_x, N_y, N_z$ to the nearest integers. [G] Standard rounding or ceiling is typically used to ensure sufficient coverage, though the sources do not specify the rounding mode explicitly.

**Parameters:**
*   $\lambda$: The scaling factor. The typical and recommended value is 5 [S1]. Experiments show that most scenes are insensitive to this parameter and achieve optimum performance around $\lambda \approx 5$ for both static and dynamic scenes [S1].

**Edge Cases and Pitfalls:**
*   **Zero Volume:** If $V$ is zero (degenerate bounding box), the formula is undefined. A guard clause should handle this, likely by falling back to a default resolution or skipping grid construction.
*   **Primitive Count:** If $N$ is zero, the resolution becomes zero. This should be handled by ensuring a minimum grid size (e.g., $1 \times 1 \times 1$) if the scene is empty but needs to be traversed.
*   **Precision:** The cube root operation should be performed with sufficient floating-point precision to avoid significant quantization errors in the final integer cell counts, especially for very large or very small scenes.

**Pseudocode:**
```python
import math

def calculate_grid_resolution(N, V, d_x, d_y, d_z, lambda_factor=5.0):
    """
    Calculate the number of cells in a uniform 3D grid.
    
    Args:
        N (int): Number of primitives (triangles).
        V (float): Volume of the scene bounding box.
        d_x (float): Extent of the bounding box in x-dimension.
        d_y (float): Extent of the bounding box in y-dimension.
        d_z (float): Extent of the bounding box in z-dimension.
        lambda_factor (float): Scaling factor (default 5.0).
        
    Returns:
        tuple: (N_x, N_y, N_z) number of cells in each dimension.
    """
    if V == 0:
        # Handle degenerate bounding box
        return (1, 1, 1)
    
    if N == 0:
        # Handle empty scene
        return (1, 1, 1)
        
    # Calculate the term inside the cube root
    term = (lambda_factor * N) / V
    
    # Calculate cube root
    cube_root_term = term ** (1.0 / 3.0)
    
    # Calculate number of cells for each dimension
    N_x = d_x * cube_root_term
    N_y = d_y * cube_root_term
    N_z = d_z * cube_root_term
    
    # Round to nearest integer
    N_x = round(N_x)
    N_y = round(N_y)
    N_z = round(N_z)
    
    # Ensure minimum resolution of 1
    N_x = max(1, N_x)
    N_y = max(1, N_y)
    N_z = max(1, N_z)
    
    return (N_x, N_y, N_z)
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ for the resolution calculation itself. The subsequent grid construction is $O(N)$ as each primitive must be inserted into the grid cells.
*   **Memory Complexity:** $O(N_x \cdot N_y \cdot N_z)$ for the grid structure. With $\lambda \approx 5$, the grid size is proportional to $N$, leading to $O(N)$ memory usage in practice.
*   **Performance:** Optimum performance is reached at $\lambda \approx 5$ for nearly all tested scenes [S1]. The method is robust and insensitive to small variations in $\lambda$ [S1].
*   **Strengths:** Simple to implement; adapts to scene complexity; minimizes expected ray tracing cost by promoting cubic cells [S1].
*   **Limitations:** Assumes a uniform distribution of primitives; may be inefficient for scenes with highly clustered or sparse geometry; does not account for object size distribution, only count [S1][S2, unofficial].
*   **When to use:** General-purpose ray tracing of animated or static scenes where a quick, effective grid resolution is needed without complex analysis.
*   **When not to use:** Scenes with extreme geometric clustering or where hierarchical structures are significantly more efficient.

## Background
The method originates from the work of Cleary et al. (1983) [S1], who proposed choosing the number of cells to be a multiple, $\lambda$, of the number of triangles. It was later popularized in the context of coherent grid traversal for animated scenes by Lext and Akenine-Moller (2001) [S1]. The heuristic is based on the principle that cubically shaped cells have the smallest surface area in relation to volume, thereby minimizing the expected ray tracing cost [S1].
