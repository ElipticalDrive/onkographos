# Coordinate Grid Generation
Also called: Meshgrid Setup, NDC Pixel Coordinate Generation, Pixel Coordinate Generation, Pixel coordinate grid, SF Decoder, Spherical Folding Grid, [-1, 1] coordinate grid

## Overview
Coordinate Grid Generation constructs a regular lattice of sample points within a specified spatial domain, typically mapping pixel indices to Normalized Device Coordinates (NDC) in the range $[-1, 1]$ for 2D image planes or defining 3D voxel centers for volumetric evaluation [S2, S5, S6, unofficial]. It serves as the foundational sampling mechanism for evaluating implicit functions (such as Signed Distance Fields) or density fields across a volumetric domain [S2, S6, unofficial]. It differs from [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) by generating raw coordinate tensors rather than modifying existing voxel values, and from [Occupancy Voxel Creation](2628-occupancy-voxel-creation.md) by producing coordinate arrays for neural field evaluation rather than binary occupancy masks [S2, S6, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs:** Image dimensions (width $W$, height $H$) or grid resolution ($s_x, s_y, s_z$); physical spacing or scale parameters; device specification.
*   **Outputs:** A flattened tensor of coordinates. For 2D, shape $[W \times H, 2]$ in NDC space [S2, S5, unofficial]. For 3D, a flattened list of 3D coordinates and a learnable cell tensor [S6, unofficial].

### Data Structures
*   **2D Grid:** Tensor of shape $[H \times W, 2]$ (or $[W \times H, 2]$ depending on flattening order) containing $(x, y)$ coordinates [S2, S5, unofficial].
*   **3D Grid:**
    *   `grid_coords`: Flattened tensor of shape $[s_x \times s_y \times s_z, 3]$ containing physical 3D coordinates [S6, unofficial].
    *   `grid_cells`: Tensor of shape $[s_x, s_y, s_z, \text{info\_size}]$ storing learnable attributes (e.g., RGB + Alpha) [S6, unofficial].
*   **Spherical Folding Grid:** Tensor of shape $[\text{grid\_dim}^2, 3]$ containing 3D coordinates on a sphere [S7, unofficial].

### Steps

#### 2D NDC Pixel Coordinate Generation
This method generates pixel coordinates for a 2D image plane, mapping them to the $[-1, 1]$ range used in neural field training [S2, S5, unofficial].

1.  **Extract Dimensions:** Get width $W$ and height $H$ from the image size [S4, S5, unofficial].
2.  **Generate Indices:** Create 1D tensors for x and y indices.
    *   Method A (Integer): $x_{idx} \in [0, W-1]$, $y_{idx} \in [0, H-1]$ [S4, unofficial].
    *   Method B (Float/Centered): Create ranges $[0, W)$ and $[0, H)$ [S1, unofficial].
3.  **Normalize to NDC:** Convert indices to $[-1, 1]$ range.
    *   Formula:
        $$ x_{ndc} = \frac{x_{idx} - \frac{W-1}{2}}{\frac{W-1}{2}} $$
        $$ y_{ndc} = \frac{y_{idx} - \frac{H-1}{2}}{\frac{H-1}{2}} $$
        [S4, unofficial]
    *   Alternative Formula (Linear):
        $$ x_{ndc} = \frac{x}{W} \times 2 - 1 $$
        $$ y_{ndc} = \frac{y}{H} \times 2 - 1 $$
        [S1, unofficial]
4.  **Meshgrid:** Create a 2D grid using `torch.meshgrid` or equivalent.
    *   Use `indexing="ij"` for matrix-style indexing (row, col) [S2, S6, unofficial].
    *   Stack dimensions: `torch.stack([X, Y], dim=-1)` [S1, S2, unofficial].
    *   Note: Some implementations reverse the order to `(y, x)` before stacking or transpose the result to mimic `np.meshgrid(..., indexing="xy")` [S3][S4, S8, unofficial].
5.  **Flatten:** Reshape the grid to $[-1, 2]$ (or $[H \times W, 2]$) [S2, S5, unofficial].
6.  **Negate:** Negate the resulting coordinates before returning [S1, unofficial][S3][S5, unofficial].

#### 3D Coordinate Grid Generation
This method constructs a 3D lattice for volumetric evaluation, often with physical spacing [S6, unofficial].

1.  **Initialize Indices:** Create index arrays for x, y, z using `torch.arange` or `linspace` [S6, unofficial].
2.  **Meshgrid:** Generate meshgrid of indices with `indexing="ij"` [S6, unofficial].
3.  **Stack:** Stack components to form a normalized coordinate tensor [S6, unofficial].
4.  **Center:** Subtract $\lceil \text{dim}/2 \rceil - 1$ from each coordinate to center the grid at the origin [S6, unofficial].
5.  **Scale:** Multiply by `points_distance` (default 0.5) to set physical spacing [S6, unofficial].
6.  **Flatten:** Reshape to a flat list of coordinates `grid_coords` [S6, unofficial].
7.  **Initialize Cells:** Create `grid_cells` tensor of shape $[s_x, s_y, s_z, \text{info\_size}]$ with `requires_grad=True` [S6, unofficial].

#### Spherical Folding Grid (SF Decoder)
Used in specific decoder architectures to map 2D grid indices to 3D spherical coordinates [S7, unofficial].

1.  **Define Grid:** Create a 2D meshgrid of azimuth ($u \in [0, 2\pi]$) and elevation ($v \in [0, \pi]$) with `grid_dim` points each (default 45) [S7, unofficial].
2.  **Convert to 3D:** Map to sphere of radius $r=0.1$:
    $$ x = \sin(v) \cos(u) \times 0.1 $$
    $$ y = \sin(v) \sin(u) \times 0.1 $$
    $$ z = \cos(v) \times 0.1 $$
    [S7, unofficial]
3.  **Flatten:** Reshape to $[\text{grid\_dim}^2, 3]$ [S7, unofficial].

### Parameters
*   **Image Size:** $W, H$ (Width, Height) [S4, S5, unofficial].
*   **Grid Resolution:** $s_x, s_y, s_z$ (Number of points per dimension) [S6, unofficial].
*   **Points Distance:** Physical spacing between grid points. Default: 0.5 [S6, unofficial].
*   **Info Size:** Number of channels per cell (e.g., 4 for RGB+Alpha). Default: 4 [S6, unofficial].
*   **Grid Dim:** Side length of the 2D folding grid. Default: 45 [S7, unofficial].
*   **Scale:** Spatial extent. Default: 0.5 (range $[-0.5, 0.5]$) [S3].

### Edge Cases and Pitfalls
*   **Indexing Convention:** `torch.meshgrid` defaults to `indexing="ij"`, which differs from NumPy's `indexing="xy"`. Implementations must explicitly transpose or swap axes if `xy` convention is required [S8, unofficial].
*   **Negation:** Several implementations negate the final grid coordinates [S1, unofficial][S3][S5, unofficial]. This may be due to camera coordinate system conventions (e.g., OpenGL vs. DirectX) or specific neural field training requirements [S1, S5, unofficial].
*   **Boundary Handling:** The normalization formula $\frac{x_{idx} - \frac{W-1}{2}}{\frac{W-1}{2}}$ maps the center pixel to 0 and the edges to $\pm 1$. Ensure integer division or float precision is maintained to avoid off-by-one errors at boundaries [S4, unofficial].

### Pseudocode

```python
import torch
import numpy as np

def generate_2d_ndc_grid(width: int, height: int, device: str = 'cuda') -> torch.Tensor:
    """
    Generates a flattened 2D coordinate grid in NDC space [-1, 1].
    Returns shape [height * width, 2].
    """
    # 1. Generate indices
    x_idx = torch.arange(0, width, device=device, dtype=torch.float32)
    y_idx = torch.arange(0, height, device=device, dtype=torch.float32)
    
    # 2. Normalize to [-1, 1]
    # Formula: (idx - center) / center
    x_ndc = (x_idx - (width - 1) / 2) / ((width - 1) / 2)
    y_ndc = (y_idx - (height - 1) / 2) / ((height - 1) / 2)
    
    # 3. Create Meshgrid
    # Using 'ij' indexing: X varies along columns, Y varies along rows
    X, Y = torch.meshgrid(x_ndc, y_ndc, indexing='ij')
    
    # 4. Stack and Flatten
    # Stack along last dimension: (H, W, 2)
    grid = torch.stack([X, Y], dim=-1)
    
    # Flatten to (H * W, 2)
    grid_flat = grid.view(-1, 2)
    
    # 5. Negate (common in implementations like [S1, S5, unofficial])
    grid_flat = -grid_flat
    
    return grid_flat

def generate_3d_grid(sx: int, sy: int, sz: int, points_distance: float = 0.5, device: str = 'cuda') -> tuple:
    """
    Generates a 3D coordinate grid centered at origin with physical spacing.
    Returns (grid_coords, grid_cells).
    """
    # 1. Create index arrays
    x = torch.arange(sx, device=device, dtype=torch.float32)
    y = torch.arange(sy, device=device, dtype=torch.float32)
    z = torch.arange(sz, device=device, dtype=torch.float32)
    
    # 2. Meshgrid
    X, Y, Z = torch.meshgrid(x, y, z, indexing='ij')
    
    # 3. Stack
    grid = torch.stack([X, Y, Z], dim=-1) # (sx, sy, sz, 3)
    
    # 4. Center
    # Subtract ceil(dim/2) - 1
    center_x = torch.ceil(torch.tensor(sx / 2)).item() - 1
    center_y = torch.ceil(torch.tensor(sy / 2)).item() - 1
    center_z = torch.ceil(torch.tensor(sz / 2)).item() - 1
    
    grid = grid - torch.tensor([center_x, center_y, center_z], device=device)
    
    # 5. Scale
    grid = grid * points_distance
    
    # 6. Flatten
    grid_coords = grid.view(-1, 3)
    
    # 7. Initialize Cells (Learnable)
    info_size = 4 # RGB + Alpha
    grid_cells = torch.zeros((sx, sy, sz, info_size), device=device, requires_grad=True)
    
    return grid_coords, grid_cells

def generate_spherical_folding_grid(grid_dim: int = 45, device: str = 'cuda') -> torch.Tensor:
    """
    Generates a 2D grid mapped to a sphere of radius 0.1.
    Returns shape [grid_dim^2, 3].
    """
    # 1. Azimuth (u) and Elevation (v)
    u = torch.linspace(0, 2 * np.pi, grid_dim, device=device)
    v = torch.linspace(0, np.pi, grid_dim, device=device)
    
    # 2. Meshgrid
    U, V = torch.meshgrid(u, v, indexing='ij')
    
    # 3. Convert to 3D (Radius 0.1)
    x = torch.sin(V) * torch.cos(U) * 0.1
    y = torch.sin(V) * torch.sin(U) * 0.1
    z = torch.cos(V) * 0.1
    
    # 4. Stack and Flatten
    grid = torch.stack([x, y, z], dim=-1)
    grid_flat = grid.view(-1, 3)
    
    return grid_flat
```

## Subtopics

### [3D Coordinate Grid Generation](2333-3d-coordinate-grid-generation.md)
Constructs a regular lattice of 3D sample points within a specified spatial volume, typically defined by bounds and step sizes or a resolution within a canonical unit cube. It serves as the foundational sampling mechanism for evaluating implicit functions (such as Signed Distance Fields) or density fields across a volumetric domain. It differs from [Coordinate Grid Generation](1273-coordinate-grid-generation.md) by explicitly handling 3D spatial bounds and voxel center calculations rather than just generating flattened 2D image-like coordinate arrays, and from [CT Slice Voxel Construction](8351-ct-slice-voxel-construction.md) by generating a full 3D volume rather than processing 2D slices independently.

### [CT Slice Voxel Construction](8351-ct-slice-voxel-construction.md)
Constructs a 3D grid cell (voxel) from two adjacent 2D CT slices by calculating the 3D coordinates of its 8 vertices and retrieving the scalar values (Hounsfield units) for each vertex. It differs from [3D Coordinate Grid Generation](2333-3d-coordinate-grid-generation.md) by explicitly handling the discrete nature of medical imaging data, using slice-specific metadata (pixel spacing, origin) rather than a normalized [-1, 1] domain, and mapping values directly from the source image arrays.

### Meshgrid XY
Mimics `np.meshgrid(..., indexing="xy")` in PyTorch, as `torch.meshgrid` only allows "ij" indexing. It involves calling `torch.meshgrid(tensor1, tensor2)` and returning `ii.transpose(-1, -2), jj.transpose(-1, -2)`. [S8, unofficial]

### Create Pixel Coordinate Grid
Creates a grid of pixel coordinates (x, y) and frame indices for a sequence of frames, returning arrays for all frames and individual coordinate components. It uses `np.indices` to create 2D coordinate grids, broadcasts them across frames, and stacks x, y, and frame indices into a shape of `(num_frames, height, width, 3)`. [S9, unofficial]

## Operating characteristics
*   **Time Complexity:** $O(W \times H)$ for 2D and $O(s_x \times s_y \times s_z)$ for 3D, as every pixel/voxel coordinate must be generated [S2, S6, unofficial].
*   **Memory Complexity:** $O(W \times H \times D)$ where $D$ is the dimensionality (2 or 3) [S2, S6, unofficial].
*   **Performance:** Generation is typically fast and can be vectorized using GPU tensors. The cost is negligible compared to the subsequent neural field evaluation or volume rendering steps [S2, S6, unofficial].
*   **Strengths:** Provides a consistent, differentiable coordinate system for neural fields; supports both 2D image planes and 3D volumes [S2, S6, unofficial].
*   **Limitations:** Memory usage grows quadratically/cubically with resolution; not suitable for extremely high resolutions without sparse structures [S2, S6, unofficial].
*   **When to Use:** When training neural radiance fields (NeRF), SDFs, or other implicit representations that require point-wise evaluation [S2, S6, unofficial].
*   **When Not to Use:** When memory is constrained and sparse voxel structures are preferred [S2, S6, unofficial].

## Background
Coordinate grid generation is a fundamental step in neural rendering and volumetric visualization, enabling the mapping of discrete pixel/voxel indices to continuous spatial coordinates. It is widely used in implementations of NeRF, SDF-based rendering, and 3D deep learning frameworks. The method has been adapted across various libraries, including PyTorch, JAX, and NumPy, with variations in normalization conventions (e.g., $[-1, 1]$ vs $[0, 1]$) and indexing orders [S1, S2, S4, S5, S6, S7, S8, S9, unofficial].
