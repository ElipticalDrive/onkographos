# Voxel Grid Density Volume Creation

Also called: Density Generation

## Overview
Voxel Grid Density Volume Creation generates a 3D density volume and associated position/color data within an axis-aligned bounding box grid based on a specified density mode, such as sphere or cube [S1, unofficial]. It transforms spatial sample points into volumetric attributes suitable for rendering or mesh extraction, differing from sibling methods by explicitly defining density thresholds and modes rather than relying solely on procedural noise or hierarchical subdivision strategies [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- Grid dimensions: $H$ (height/depth), $W$ (width), $D$ (depth/length) [S1, unofficial].
- World bounds: $min\_x, max\_x, min\_y, max\_y, min\_z, max\_z$ [S1, unofficial].
- Density mode: 'sphere' or 'cube' [S1, unofficial].
- Sphere parameters: center $(x_c, y_c, z_c)$ [S1, unofficial].
- Cube parameters: center $(x_c, y_c, z_c)$, threshold $thres\_pos$ [S1, unofficial].
- Density values: $high\_density\_val$, $min\_density\_val$ [S1, unofficial].
- Chunk context (for chunked generation): $center$ (chunk world position), $densityOffset$ (3D vector), $mapSize$ (world map size) [S2, unofficial].

**Outputs:**
- A density volume array of shape $(H, W, D, 7)$ [S1, unofficial].
- Each element at index $[i, k, j]$ contains:
  - Indices 0-2: World position $(x, y, z)$ [S1, unofficial].
  - Indices 3-5: Color $(r, g, b)$, fixed at $(255, 255, 255)$ [S1, unofficial].
  - Index 6: Density value (float) [S1, unofficial].

**Data Structures:**
- `density_volume`: Dense buffer of shape $(H, W, D, 7)$ [S1, unofficial].
- `DensityGenerator`: Component or function handling the generation logic, taking buffers and parameters [S2, unofficial].

**Steps:**
1. Initialize `density_volume` with zeros or appropriate defaults [S1, unofficial].
2. Iterate through grid indices $i \in [0, H-1]$, $k \in [0, W-1]$, $j \in [0, D-1]$ [S1, unofficial].
3. Map grid indices to world coordinates:
   $$x = \frac{i}{H-1}(max\_x - min\_x) + min\_x$$
   $$y = \frac{k}{W-1}(max\_y - min\_y) + min\_y$$
   $$z = \frac{j}{D-1}(max\_z - min\_z) + min\_z$$
   [S1, unofficial].
4. Calculate density based on mode:
   - **Sphere Mode**:
     Calculate squared distance:
     $$sphere\_radius = (x - x_c)^2 + (y - y_c)^2 + (z - z_c)^2$$
     [S1, unofficial].
     - If $sphere\_radius < 1.0$, set $density = 1.0$ [S1, unofficial].
     - If $sphere\_radius < 0.25$, set $density = high\_density\_val$ [S1, unofficial].
     - Else, set $density = 0$ [S1, unofficial].
   - **Cube Mode**:
     - If $x, y, z$ are all within $[center - thres\_pos, center + thres\_pos]$, set $density = high\_density\_val$ [S1, unofficial].
     - Else, set $density = min\_density\_val$ [S1, unofficial].
5. Store data in `density_volume[i, k, j]`:
   - `[0] = x`, `[1] = y`, `[2] = z` [S1, unofficial].
   - `[3] = 255`, `[4] = 255`, `[5] = 255` [S1, unofficial].
   - `[6] = density` [S1, unofficial].

**Pseudocode:**
```python
def generate_density_volume(H, W, D, min_x, max_x, min_y, max_y, min_z, max_z, mode, center, thres_pos, high_density_val, min_density_val):
    """
    Generates a 3D density volume array.
    
    Args:
        H, W, D: Grid dimensions.
        min_x, max_x, etc.: World bounds.
        mode: 'sphere' or 'cube'.
        center: Tuple (xc, yc, zc).
        thres_pos: Threshold for cube mode.
        high_density_val: Density for high-density regions.
        min_density_val: Base density value.
        
    Returns:
        density_volume: Nested list representing a dense buffer of shape (H, W, D, 7).
    """
    xc, yc, zc = center
    # Initialize dense buffer manually to avoid external library dependencies
    density_volume = [[[[] for _ in range(D)] for _ in range(W)] for _ in range(H)]
    
    for i in range(H):
        for k in range(W):
            for j in range(D):
                # Map grid indices to world coordinates
                x = (i / (H - 1)) * (max_x - min_x) + min_x
                y = (k / (W - 1)) * (max_y - min_y) + min_y
                z = (j / (D - 1)) * (max_z - min_z) + min_z
                
                density = 0.0
                
                if mode == 'sphere':
                    sphere_radius = (x - xc)**2 + (y - yc)**2 + (z - zc)**2
                    if sphere_radius < 0.25:
                        density = high_density_val
                    elif sphere_radius < 1.0:
                        density = 1.0
                    else:
                        density = 0.0
                        
                elif mode == 'cube':
                    if (center[0] - thres_pos <= x <= center[0] + thres_pos) and \
                       (center[1] - thres_pos <= y <= center[1] + thres_pos) and \
                       (center[2] - thres_pos <= z <= center[2] + thres_pos):
                        density = high_density_val
                    else:
                        density = min_density_val
                
                # Store data: [x, y, z, r, g, b, density]
                density_volume[i][k][j] = [x, y, z, 255, 255, 255, density]
                
    return density_volume
```

**Parameters:**
- $thres\_pos$: Threshold distance from center for cube mode. Typical value: 0.8 [S1, unofficial].
- $high\_density\_val$: Density value for high-density regions. Typical value: 0.95 [S1, unofficial].
- $min\_density\_val$: Base density value. Typical value: 0.2 [S1, unofficial].
- $densityOffset$: 3D vector offset applied to noise function input to prevent seams between chunks [S2, unofficial].
- $mapSize$: Total size of the world map, calculated as $numberOfChunks \times (chunkSize \ll levelsOfDetail)$, used for edge solidification [S2, unofficial].

**Edge Cases and Pitfalls:**
- Division by zero if $H, W,$ or $D$ is 1. The formula assumes $H, W, D > 1$ [S1, unofficial].
- Sphere mode uses squared radius directly, so thresholds are squared distances (0.25 and 1.0) [S1, unofficial].
- Cube mode bounds check should respect world boundaries if the chunk is at the edge of the map [S2, unofficial].

## Operating characteristics
- **Time Complexity**: $O(H \times W \times D)$, as every voxel is visited once [S1, unofficial].
- **Memory Complexity**: $O(H \times W \times D \times 7)$ for the dense volume array [S1, unofficial].
- **Strengths**: Supports both sphere and cube primitives [S1, unofficial].
- **Limitations**: Dense storage requires fixed memory allocation; seams may occur between chunks without proper offset handling [S2, unofficial].
- **When to use**: Small to medium volumes; simple geometric primitives [S1, unofficial].
- **When not to use**: Large-scale terrain or complex organic shapes requiring sparse representation or hierarchical structures [S2, unofficial].
