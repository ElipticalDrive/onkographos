# Structured Grid Triangle List Generation


## Overview
Precomputes vertex index arrays for triangle lists representing surfaces parallel to the xy, yz, and xz planes on a regular 3D grid [S1, unofficial]. It solves the connectivity generation problem for axis-aligned planar slices by providing static index buffers that are offset for different grid depths [S1, unofficial]. It differs from general isosurface extraction by assuming fixed axis-aligned topology, enabling $O(1)$ index computation per triangle without geometric intersection tests [S1, unofficial].

## How it works
**Inputs:**
- `ngx`, `ngy`, `ngz`: Integer grid dimensions in the x, y, and z directions respectively [S1, unofficial].
- `ngxy`: Precomputed stride `ngx * ngy` [S1, unofficial].

**Outputs:**
- Three integer arrays storing vertex indices for triangle lists:
  - `indices_xy`: Size $6(n_x-1)(n_y-1)$ [S1, unofficial].
  - `indices_yz`: Size $6(n_y-1)(n_z-1)$ [S1, unofficial].
  - `indices_xz`: Size $6(n_z-1)(n_x-1)$ [S1, unofficial].

**Data Structures:**
- `index`: A flat integer array used to store the 6 indices per quad (2 triangles) for each cell in the grid [S1, unofficial].

**Algorithm:**
The method generates base indices for the plane at coordinate 0 along the axis perpendicular to the plane. These base indices are reused for all slices by adding an offset corresponding to the slice's position [S1, unofficial].

1. **XY-Plane Generation:**
   - Initialize index pointer `k = 0`.
   - Loop `i` from `0` to `ngy - 2`.
   - Loop `j` from `0` to `ngx - 2`.
   - Assign 6 indices to `index[k...k+5]`:
     - `index[k] = ngx * i + j`
     - `index[k+1] = ngx * i + j + 1`
     - `index[k+2] = ngx * (i + 1) + j + 1`
     - `index[k+3] = ngx * i + j`
     - `index[k+4] = ngx * (i + 1) + j + 1`
     - `index[k+5] = ngx * (i + 1) + j`
   - Increment `k` by 6 [S1, unofficial].

2. **YZ-Plane Generation:**
   - Initialize index pointer `k = 0`.
   - Loop `i` from `0` to `ngz - 2`.
   - Set `base = i * ngxy`.
   - Loop `j` from `0` to `ngy - 2`.
   - Set `m = base + j * ngx`.
   - Assign 6 indices to `index[k...k+5]`:
     - `index[k] = m`
     - `index[k+1] = m + ngx`
     - `index[k+2] = m + ngx + ngxy`
     - `index[k+3] = m`
     - `index[k+4] = m + ngx + ngxy`
     - `index[k+5] = m + ngxy`
   - Increment `k` by 6 [S1, unofficial].

3. **XZ-Plane Generation:**
   - Initialize index pointer `k = 0`.
   - Loop `i` from `0` to `ngz - 2`.
   - Set `base = i * ngxy`.
   - Loop `j` from `0` to `ngx - 2`.
   - Set `m = base + j`.
   - Assign 6 indices to `index[k...k+5]`:
     - `index[k] = m`
     - `index[k+1] = m + 1`
     - `index[k+2] = m + 1 + ngxy`
     - `index[k+3] = m`
     - `index[k+4] = m + 1 + ngxy`
     - `index[k+5] = m + ngxy`
   - Increment `k` by 6 [S1, unofficial].

**Rendering Usage:**
To render a surface at a specific z-coordinate `z_idx` for the XY-plane, add `z_idx * ngxy` to every index in the `indices_xy` array before passing to the GPU [S1, unofficial]. For YZ-parallel surfaces, add `x_idx` to every index. For XZ-parallel surfaces, add `y_idx` to every index [S1, unofficial]. The grid indexing scheme follows $idx(x,y,z) = x + y \cdot dX + z \cdot dX \cdot dY$ [S2, unofficial].

**Pitfalls:**
- Indices must be offset by the grid position of the perpendicular axis when computing triangle lists for surfaces not at the origin (e.g., z-axis offset for xy-plane surfaces) [S1, unofficial].
- The original source loops contain an off-by-one error; correct implementation requires iterating up to `dimension - 2` to match the stated array sizes [S1, unofficial].

```python
def generate_structured_grid_triangles(ngx, ngy, ngz):
    ngxy = ngx * ngy
    indices_xy = []
    indices_yz = []
    indices_xz = []

    # XY Plane: Parallel to XY, varies in Z
    for i in range(ngy - 1):
        for j in range(ngx - 1):
            base = ngx * i + j
            indices_xy.extend([base, base + 1, base + ngx + 1,
                               base, base + ngx + 1, base + ngx])

    # YZ Plane: Parallel to YZ, varies in X
    for i in range(ngz - 1):
        base_z = i * ngxy
        for j in range(ngy - 1):
            m = base_z + j * ngx
            indices_yz.extend([m, m + ngx, m + ngx + ngxy,
                               m, m + ngx + ngxy, m + ngxy])

    # XZ Plane: Parallel to XZ, varies in Y
    for i in range(ngz - 1):
        base_z = i * ngxy
        for j in range(ngx - 1):
            m = base_z + j
            indices_xz.extend([m, m + 1, m + 1 + ngxy,
                               m, m + 1 + ngxy, m + ngxy])

    return indices_xy, indices_yz, indices_xz
```

## Subtopics

### Structured Grid Cell Generation
Generates the volume mesh (hexahedra or quads) for a structured grid, returning a list of vertex indices per cell in z-major order [S2, unofficial]. It differs from surface generation by including internal cell connectivity rather than just boundary faces [S2, unofficial]. It handles 3D hexahedra (8 vertices) and 2D planar cases (quads, 4 vertices) depending on whether dimensions are greater than 1 [S2, unofficial]. Vertex indexing follows $idx(x, y, z) = x + y \cdot dX + z \cdot dX \cdot dY$ [S2, unofficial].

### Structured Grid Surface Generation
Generates the surface mesh (quads) for a structured grid by iterating over the boundary faces of the voxel grid defined by dimensions $dX, dY, dZ$ [S2, unofficial]. It calculates effective loop counts clamped to minimum 1 ($cx = \max(1, dX-1)$, etc.) [S2, unofficial]. It generates 6 faces for 3D grids, or single planes for 2D grids (dZ=1, dY=1, or dX=1) [S2, unofficial].

### Voxel Grid Surface Triangulation
Processes the voxel grid slice by slice in 3 directions (X, Y, Z), where a slice is a 2D submatrix with one dimension fixed [S3, unofficial]. It covers each voxel cube completely by overlaying three triangle strips parallel to the XY, XZ, and YZ planes [S3, unofficial]. It removes double triangles caused by overlapping strips from different directions [S3, unofficial]. For convex objects, two striping directions are sufficient, but complex objects (e.g., torus) require all 3 directions to ensure full surface coverage [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of cells in the grid, specifically proportional to $(n_x-1)(n_y-1) + (n_y-1)(n_z-1) + (n_z-1)(n_x-1)$ [S1, unofficial].
- **Memory Complexity:** $O(N)$ for storing the index arrays [S1, unofficial].
- **Strengths:** Extremely fast precomputation; no runtime geometric calculation required; simple offset-based rendering for multiple slices [S1, unofficial].
- **Limitations:** Only supports axis-aligned planar surfaces; cannot represent arbitrary isosurfaces or curved boundaries [S1, unofficial].
- **When to use:** When rendering orthogonal slices or planar isosurfaces on a regular grid [S1, unofficial].

## Background
Originated in the context of visualizing surfaces and 3D vector fields on regular grids [S1, unofficial]. The method relies on the regular topology of structured grids to precompute connectivity, avoiding the need for dynamic mesh generation during rendering [S1, unofficial].
