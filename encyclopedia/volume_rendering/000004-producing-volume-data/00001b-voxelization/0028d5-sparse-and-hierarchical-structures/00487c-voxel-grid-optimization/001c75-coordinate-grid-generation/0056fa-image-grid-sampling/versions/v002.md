# Image Grid Sampling
## Overview
Image Grid Sampling generates a grid of normalized coordinates and corresponding integer indices for a specified 2D shape [S1, unofficial]. It provides the foundational coordinate layout used in downstream neural field and rendering pipelines [G].
## How it works
**Inputs:** `shape` (tuple of integers $(H, W)$ representing height and width), `device` (compute device) [G].
**Outputs:** `coordinates` (tensor of shape $(H, W, 2)$ containing normalized coordinates), `indices` (tensor of shape $(H, W, 2)$ containing integer indices) [S1, unofficial].

1. Create integer indices for each dimension:
   $$ \text{idx\_list} = [\text{torch.arange}(L, \text{device}=\text{device}) \text{ for } L \text{ in } \text{shape}] $$
2. Stack meshgrid of integer indices with 'ij' indexing:
   $$ \text{indices} = \text{torch.stack}(\text{torch.meshgrid}(*\text{idx\_list}, \text{indexing}="ij"), \text{dim}=-1) $$
3. Compute normalized coordinates by adding 0.5 and dividing by length:
   $$ \text{coords} = [(\text{idx} + 0.5) / L \text{ for } \text{idx}, L \text{ in } \text{zip}(\text{idx\_list}, \text{shape})] $$
4. Reverse the coordinates list to match xy ordering:
   $$ \text{coords} = \text{coords}[::-1] $$
5. Stack meshgrid of normalized coordinates with 'xy' indexing:
   $$ \text{coordinates} = \text{torch.stack}(\text{torch.meshgrid}(*\text{coords}, \text{indexing}="xy"), \text{dim}=-1) $$
6. Return `coordinates` and `indices` [S1, unofficial].

```python
import torch

def image_grid_sampling(shape, device):
    """
    Generates a grid of normalized coordinates and integer indices for a 2D shape.
    
    Args:
        shape (tuple): (height, width) of the grid.
        device: torch device.
        
    Returns:
        coordinates: Tensor of shape (H, W, 2) with normalized coordinates.
        indices: Tensor of shape (H, W, 2) with integer indices.
    """
    # Step 1: Create integer indices for each dimension
    idx_list = [torch.arange(L, device=device) for L in shape]
    
    # Step 2: Stack meshgrid of integer indices with 'ij' indexing
    indices = torch.stack(torch.meshgrid(*idx_list, indexing="ij"), dim=-1)
    
    # Step 3: Compute normalized coordinates by adding 0.5 and dividing by length
    coords = [(idx + 0.5) / L for idx, L in zip(idx_list, shape)]
    
    # Step 4: Reverse the coordinates list to match xy ordering
    coords = coords[::-1]
    
    # Step 5: Stack meshgrid of normalized coordinates with 'xy' indexing
    coordinates = torch.stack(torch.meshgrid(*coords, indexing="xy"), dim=-1)
    
    # Step 6: Return normalized coordinates and integer indices
    return coordinates, indices
```

**Parameters:**
- `shape`: Tuple of integers $(H, W)$ [G].
- `device`: Compute device (e.g., `cuda:0`) [G].

**Edge cases and pitfalls:**
- The normalization formula $(idx + 0.5) / L$ maps indices to the range $[0.5/L, 1 - 0.5/L]$ [S1, unofficial]. This does not strictly span $[-1, 1]$ unless further scaled and shifted [G]. Implementers should verify if downstream modules expect $[-1, 1]$ or $[0, 1]$ and apply additional scaling if necessary [G].
- The reversal in Step 4 ensures the final coordinate tensor aligns with standard image 'xy' ordering (width, height) rather than 'ij' ordering (height, width) [S1, unofficial].

## Subtopics

### [True World-Space MPR Sampling](21391-true-world-space-mpr-sampling.md)
True World-Space MPR Sampling generates a 2D image of intensities by sampling a 3D volume along a user-defined 2D plane in world space. It solves the problem of extracting arbitrary orthogonal or oblique slices (axial, coronal, sagittal, or custom) from a volumetric dataset without requiring pre-computed slice data, by iterating over pixel grid coordinates, converting them to world space, transforming to voxel space, and interpolating the volume value. It differs from standard image grid sampling by explicitly defining the sampling plane via world-space origin and direction vectors, ensuring geometric accuracy relative to the patient or world coordinate system rather than the voxel grid axes.

## Operating characteristics
**Time complexity:** $O(H \times W)$, where $H$ and $W$ are the height and width of the grid [G].
**Memory complexity:** $O(H \times W \times D)$, where $D=2$ is the dimensionality of the coordinates [G].
