# Bucket-based LBVH construction

Also called: BVH Building, Bvh constructor, Fernandes and Walter LBVH construction

## Overview
Bucket-based LBVH construction builds a Bounding Volume Hierarchy (BVH) from a voxel model by grouping voxels into dynamic buckets rather than using a uniform grid with a fixed brick size [S2, unofficial]. This approach sets itself apart from siblings like [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) by enabling efficient empty-space skipping for sparse volumes, potentially yielding two to three times higher frame rates than methods without such skipping [S2, unofficial]. It differs from [Bounding Volume Optimization](3583-bounding-volume-optimization.md) by utilizing a bucket-based spatial partitioning strategy specifically optimized for GPU-based parallel construction [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A voxel model (discrete grid of occupied/empty voxels).
*   **Output:** A BVH structure representing the spatial hierarchy of the voxel data.

**Data Structures:**
*   `volatileGPUData`: A temporary storage structure on the GPU used to hold intermediate voxel cluster information during the build process. The exact layout is not specified in the sources [S1, unofficial].
*   **BVH Nodes:** Standard BVH node structure (bounding volume, children pointers/indices). Not explicitly detailed in the provided notes [S1, unofficial].

**Parameters:**
*   `BVH_BUILDING_RADIUS`: A static constant set to 100. Its specific role in the bucketing or merging logic is not detailed in the sources [S1, unofficial].

**Steps:**
1.  **Initialize Data:** Prepare the `volatileGPUData` structure to hold voxel cluster information. [S1, unofficial]
2.  **Aggregate Data:** Call `aggregateSSBOData(volatileGPUData)` to organize the initial voxel data into a format suitable for parallel processing. [S1, unofficial]
3.  **Find Best Neighbor:** Execute the `FIND_BEST_NEIGHBOR` compute shader. This step identifies the most suitable neighboring voxel or cluster for merging, likely using the `BVH_BUILDING_RADIUS` to limit the search space. [S1, unofficial]
4.  **Merge Clusters:** Execute the `CLUSTER_MERGING` compute shader. This step combines voxels or small clusters into larger buckets based on the neighbor information found in the previous step. [S1, unofficial]
5.  **Reallocate Clusters:** Execute the `REALLOCATE_CLUSTERS` compute shader. This step adjusts the cluster assignments, possibly to balance the hierarchy or handle boundary conditions. [S1, unofficial]
6.  **Prefix Scan for Hierarchy:** Execute the `REDUCE_PREFIX_SCAN`, `DOWN_SWEEP_PREFIX_SCAN`, and `RESET_LAST_POSITION_PREFIX_SCAN` compute shaders. These steps perform parallel prefix scans to determine the hierarchical structure of the BVH, such as assigning parent-child relationships and computing node offsets. [S1, unofficial]
7.  **Finalize:** Execute the `END_LOOP_COMPUTATIONS` compute shader to finalize the BVH structure and clean up temporary data. [S1, unofficial]

**Pseudocode:**
```python
def build_bucket_lbvh(voxel_model):
    # Initialize volatile GPU data structure
    volatile_gpu_data = allocate_gpu_buffer()
    
    # Aggregate initial voxel data into the GPU buffer
    aggregateSSBOData(volatile_gpu_data)
    
    # Step 1: Find best neighbors for each voxel/cluster
    # Uses compute shader FIND_BEST_NEIGHBOR
    # Likely uses BVH_BUILDING_RADIUS (100) to limit search
    find_best_neighbor(volatile_gpu_data, radius=100)
    
    # Step 2: Merge clusters based on neighbor information
    # Uses compute shader CLUSTER_MERGING
    cluster_merging(volatile_gpu_data)
    
    # Step 3: Reallocate clusters to balance or adjust hierarchy
    # Uses compute shader REALLOCATE_CLUSTERS
    reallocate_clusters(volatile_gpu_data)
    
    # Step 4: Perform parallel prefix scans to build BVH hierarchy
    # Uses compute shaders REDUCE_PREFIX_SCAN, DOWN_SWEEP_PREFIX_SCAN, RESET_LAST_POSITION_PREFIX_SCAN
    reduce_prefix_scan(volatile_gpu_data)
    down_sweep_prefix_scan(volatile_gpu_data)
    reset_last_position_prefix_scan(volatile_gpu_data)
    
    # Step 5: Finalize the BVH structure
    # Uses compute shader END_LOOP_COMPUTATIONS
    end_loop_computations(volatile_gpu_data)
    
    # Extract and return the final BVH structure
    bvh = extract_bvh(volatile_gpu_data)
    return bvh
```

## Subtopics

### [Bucket Size Computation](8964-bucket-size-computation.md)
Computes the Bucket Texture, which stores the position of the last voxel of each bucket. It solves the problem of efficiently identifying bucket boundaries on the GPU by splitting the computation into fragment and vertex shader steps, avoiding inefficient vertex shader texture fetches.

## Background
The method is attributed to Fernandes and Walter [FW20], as cited in [S2, unofficial]. It was developed as an alternative to uniform grid-based LBVH construction (e.g., Zellmann et al. [ZHL19]) to better handle sparse voxel data. The implementation described in [S1, unofficial] is part of a project called "VoxelFragmentML" or "SdfMesher," which supports procedural soft geometry rendering.
