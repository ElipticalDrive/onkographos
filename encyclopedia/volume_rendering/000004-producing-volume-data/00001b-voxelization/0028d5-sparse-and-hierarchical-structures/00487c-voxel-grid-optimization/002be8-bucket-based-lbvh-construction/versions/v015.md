# Bucket-based LBVH construction

Also called: BVH Building, Bvh constructor, Fernandes and Walter LBVH construction

## Overview
Bucket-based LBVH construction builds a Bounding Volume Hierarchy (BVH) from a voxel model by grouping voxels into dynamic buckets rather than a fixed uniform grid [S2, unofficial]. This approach accelerates sparse volume rendering by enabling efficient empty-space skipping, achieving two to three times higher frame rates compared to methods without such optimization [S2, unofficial]. It distinguishes itself from fixed-brick approaches (like Zellmann et al. [ZHL19]) by adapting bucket sizes to local voxel density, reducing memory overhead in sparse regions [S2, unofficial].

## How it works
**Inputs:** A voxel model (implicit or explicit grid).
**Outputs:** A BVH structure ready for traversal.

**Data Structures:**
*   `volatileGPUData`: A buffer holding intermediate voxel cluster information.
*   `BVH_BUILDING_RADIUS`: A static constant defining the search radius for neighbor finding. Value: 100 [S1, unofficial].

**Steps:**
1.  **Initialization:** Prepare `volatileGPUData` to store voxel cluster states.
2.  **Neighbor Finding:** Use the `FIND_BEST_NEIGHBOR` compute shader to identify adjacent voxels within `BVH_BUILDING_RADIUS` [S1, unofficial].
3.  **Cluster Merging:** Use the `CLUSTER_MERGING` compute shader to group neighboring voxels into clusters based on spatial proximity [S1, unofficial].
4.  **Reallocation:** Use the `REALLOCATE_CLUSTERS` compute shader to reorganize cluster data for efficient processing [S1, unofficial].
5.  **Prefix Scan:** Perform a parallel prefix scan to determine bucket boundaries and cluster indices:
    *   `REDUCE_PREFIX_SCAN`: Compute aggregate sums.
    *   `DOWN_SWEEP_PREFIX_SCAN`: Distribute indices.
    *   `RESET_LAST_POSITION_PREFIX_SCAN`: Finalize boundary positions [S1, unofficial].
6.  **Finalization:** Use `END_LOOP_COMPUTATIONS` to finalize the BVH structure from the clustered data [S1, unofficial].
7.  **Aggregation:** Call `aggregateSSBOData(volatileGPUData)` to consolidate the final BVH nodes [S1, unofficial].

**Pseudocode:**
```python
def build_bucket_lbvhi(voxel_model):
    # Initialize volatile data structure for GPU processing
    volatileGPUData = allocate_volatile_buffer(voxel_model)
    
    # Step 1: Find best neighbors within a fixed radius
    # Uses compute shader FIND_BEST_NEIGHBOR
    # Radius is defined by BVH_BUILDING_RADIUS = 100
    radius = 100
    neighbor_data = find_best_neighbors(voxel_model, radius)
    
    # Step 2: Merge clusters of neighboring voxels
    # Uses compute shader CLUSTER_MERGING
    clusters = merge_clusters(neighbor_data)
    
    # Step 3: Reallocate cluster data for efficient access
    # Uses compute shader REALLOCATE_CLUSTERS
    reallocated_clusters = reallocate_clusters(clusters)
    
    # Step 4: Compute prefix scans to determine bucket boundaries
    # Uses compute shaders: REDUCE_PREFIX_SCAN, DOWN_SWEEP_PREFIX_SCAN, RESET_LAST_POSITION_PREFIX_SCAN
    prefix_sums = reduce_prefix_scan(reallocated_clusters)
    indices = down_sweep_prefix_scan(prefix_sums)
    boundaries = reset_last_position_prefix_scan(indices)
    
    # Step 5: Finalize BVH structure
    # Uses compute shader END_LOOP_COMPUTATIONS
    bvh = finalize_bvh(boundaries)
    
    # Step 6: Aggregate final data
    aggregateSSBOData(volatileGPUData)
    
    return bvh
```

**Edge Cases:**
*   **Sparse Volumes:** The bucket approach is specifically designed to handle sparsity better than fixed grids [S2, unofficial].
*   **Radius Limit:** The fixed `BVH_BUILDING_RADIUS` of 100 may limit neighbor discovery in highly sparse or large-scale scenes if not adjusted [S1, unofficial].

## Subtopics

### [Bucket Size Computation](8964-bucket-size-computation.md)
Computes the Bucket Texture storing the index of the last voxel of each bucket. It avoids expensive vertex shader texture fetches by splitting the work between fragment and vertex shaders.

## Operating characteristics
*   **Performance:** Enables 2-3x higher frame rates in sparse volumes compared to no empty-space skipping [S2, unofficial].
*   **Complexity:** Parallel construction using compute shaders allows for efficient GPU utilization [S1, unofficial].
*   **Memory:** Dynamic bucketing reduces memory overhead in sparse regions compared to uniform grids [S2, unofficial].
*   **Limitations:** Relies on a fixed neighbor search radius, which may require tuning for different scene densities [S1, unofficial].

## Background
The method is attributed to Fernandes and Walter [FW20], as cited in Skalierbares Webbasiertes Volume Rendering großer biomedizinischer Datensätze [S2, unofficial]. It was implemented in the VoxelFragmentML project by AlfonsoLRz [S1, unofficial]. The approach contrasts with Zellmann et al.'s fixed-brick LBVH construction [ZHL19], offering a more adaptive solution for sparse data [S2, unofficial].
