# HieRarchical Sparse Radiance Grid (HrSRG)

## Overview
HrSRG is a radiance grid representation that assigns higher voxel resolution to informative 3D spaces and lower resolution to other spaces, enabling high-resolution scene description without excessive memory footprint [S1]. It differs from siblings like [Plenoxels](link) and [DirectVoxGO](link) by avoiding Trilinear Interpolation to prevent rendering speed degradation, and from [Instant-NGP](link) by directly optimizing voxel values (color/texture) rather than using hash encoding [S1]. It builds on [Voxel Grid Optimization](4131-voxel-grid-optimization.md) by adaptively allocating resolutions across 3D spaces [S1].

## How it works
**Inputs:** Source images with known camera poses; initial scene bounding volume.
**Outputs:** A hierarchical sparse voxel grid containing density, radiance, and feature vectors.

**Data Structures:**
The grid is hierarchical. Each active voxel stores:
1.  Volume density ($\sigma$)
2.  Radiance (color)
3.  A three-dimensional feature vector ($\mathbf{f}$) [S1].

**Steps:**
1.  **Hierarchical Grid Construction:** Build the grid using a hierarchical voxel grid building process [S1]. This process adaptively allocates higher resolution to informative spaces and lower resolution elsewhere, avoiding the memory issues of uniform high-resolution grids (e.g., $1024^3$) [S1].
2.  **Direct Optimization:** Treat voxel values as direct optimization parameters, similar to a 2D texture atlas [S1]. This allows recovery of texture characteristics without relying on a large MLP [S1].
3.  **Perceptual Loss Training:** Incorporate a perceptual loss during training to add tolerance to misalignments caused by camera pose errors, improving clarity and preserving fine details [S1]. This is critical because standard per-pixel losses (like $\ell_p$-norm) fail to address misalignment issues [S1].
4.  **Rendering:** Render by sampling rays through the grid. The tiny MLP encodes view-dependent effects [S1].

**Parameters:**
*   **Grid Resolution:** Adaptive. Uniform $1024^3$ causes OOM [S1].
*   **Batch Size:** >200,000 rays per iteration [S1].
*   **Loss Function:** Perceptual Loss (LPIPS) [S1].

**Edge Cases and Pitfalls:**
*   **Camera Pose Errors:** Misaligned 2D pixels among source images prevent fine detail restoration in standard NeRFs [S1]. HrSRG mitigates this via perceptual loss tolerance [S1].
*   **Memory:** Optimizing a uniform $1024^3$ voxel grid typically causes out-of-memory (OOM) errors on modern GPUs [S1].

## Subtopics

### HrSRG Pruning and Real-Time Rendering
Further compression of the HrSRG tree structure using the median cut algorithm to reduce file size for transmission and mobile rendering, avoiding decompression overhead [S1]. Uncompressed HrSRG requires average storage space of 210MB. Compacted HrSRG is about 40MB [S1]. HrSRG enables rendering 1080p images at 61 FPS on a laptop GPU. Removing the tiny specular MLP improves speed to ~75 FPS with slight quality loss [S1]. SNeRG applies PNG compression by flattening features into image planes, requiring a decompression step during rendering which is not friendly to mobile devices. HrSRG uses median cut pruning to allow direct loading without decompression [S1].

## Operating characteristics
*   **Training Time:** Approximately 5 to 6 hours on a V100 GPU, which is multiple orders of magnitude faster than conventional NeRFs (1-2 days) [S1].
*   **Rendering Speed:** 61 FPS for 1080p images on a Lenovo ThinkPad P1 Gen 2 notebook equipped with a 4GB NVIDIA Quadro T1000 mobile GPU [S1]. Removing the tiny MLP improves speed to ~75 FPS [S1].
*   **Memory:** Memory-friendly nature allows simultaneous optimization of more than 200,000 rays per iteration [S1]. Uncompressed size ~210MB; compacted ~40MB [S1].
*   **Strengths:** Real-time rendering, detail preservation, fast training, mobile-friendly (no decompression needed for compacted version) [S1].
*   **Limitations:** Requires perceptual loss for best quality with pose errors; tiny MLP is a bottleneck for view-dependent effects [S1].
*   **Comparison:** Unlike Plenoxels and DirectVoxGO which use Trilinear Interpolation on low-resolution grids to save memory, HrSRG avoids Tri. Interp. to prevent a ~3x rendering speed degradation [S1]. Unlike Instant-NGP which uses hash encoding, HrSRG directly optimizes color values or a 3D texture atlas, inspired by 2D texture atlas optimization success [S1].

## Background
HrSRG was introduced by Jian Zhang et al. in the 2022 ECCV paper 'Digging into Radiance Grid for Real-Time View Synthesis with Detail Preservation' as an improvement over SNeRG [S1]. It addresses the limitations of SNeRG, which enjoys real-time synthesis at the cost of rendering quality [S1].
