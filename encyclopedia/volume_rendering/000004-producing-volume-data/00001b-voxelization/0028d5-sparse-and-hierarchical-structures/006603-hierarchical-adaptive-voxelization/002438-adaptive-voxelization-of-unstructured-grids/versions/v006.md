# Adaptive Voxelization of Unstructured Grids

Also called: Geresim, Geresim-Spike, Hierarchical 3D Texture Mapping for Unstructured Grids, Hierarchical 3D Voxelization, Octree-based Voxelization, Spike

## Overview
Adaptive Voxelization of Unstructured Grids converts large, out-of-core unstructured grids (tetrahedral or hexahedral meshes) into a hierarchical 3D texture (voxel octree) to enable interactive volume rendering on standard PC hardware [S2]. Unlike uniform grid approaches that suffer from undersampling or excessive memory consumption, this method partitions model space using an adaptive octree to preserve data at higher resolutions only where needed [S2]. It differs from multi-triangulation approaches by relying on structured grid hierarchies and 3D texture mapping acceleration [S1, unofficial][S2].

## How it works
The method consists of a CPU-based preprocessing stage to build the octree and a GPU-based rendering stage.

### Inputs and Outputs
*   **Input:** Unstructured grid (tetrahedral or hexahedral) or structured grid. For hexahedral inputs, cells are sliced into 5 tetrahedra [S2].
*   **Output:** A voxel octree where each node contains a texture brick (scalar field/gradient texture and stencil texture) and a file listing tetrahedra contained within that node's spatial extent [S2].

### Data Structures

**Tetrahedron File Format**
Flat, unindexed binary file. Each tetrahedron is stored as 56 bytes:
*   4 vertices.
*   Each vertex: 3 × 32-bit float (x, y, z) + 1 × 16-bit float (scalar value).

**Octree Node Structure**
*   **Spatial Extent:** Bounding box of the node.
*   **Texture Brick:** Fixed resolution $r$ (e.g., $4 \times 4$ in 2D examples, general $r$ in 3D).
    *   **Usable Domain:** Texture coordinates from $1/(2r)$ to $(2r-1)/(2r)$.
    *   **Overlap:** Neighboring bricks share 1 texel of overlap to ensure continuity [S2].
    *   **Content:** Scalar field/gradient texture and a 1-bit-per-voxel stencil texture (0 for null, 1 for data) [S2].

**Cell Index Texture (Geresim-Spike variant)**
*   **Format:** `R32UI` 3D texture.
*   **Content:** Stores the index of the unstructured cell corresponding to each voxel in a coarse grid [S1, unofficial].

### Algorithm Steps

#### 1. Tetrahedralization (Preprocess Stage 1)
If the input is a structured grid (e.g., hexahedral), convert it to tetrahedra.
*   For convex hexahedral cells, slice off tetrahedra from corners until one remains, or use a template to break each cell into 5 tetrahedra [S2].
*   Write tetrahedra to a flat, unindexed file [S2].

#### 2. Octree Construction (Preprocess Stage 2)
Top-down recursive construction. The function `Process(Node N, Tetrahedra File FN)` operates as follows [S2]:

```python
def Process(Node N, TetrahedraFile FN):
    # Read N's spatial extent
    extent = N.extent
    
    # Create 8 children and their associated files
    children = []
    child_files = []
    for i in range(8):
        child = ChildNode(i, extent)
        child_file = CreateFile()
        WriteExtent(child_file, child.extent)
        children.append(child)
        child_files.append(child_file)
        
    N.recursion_needed = False
    
    # Distribute tetrahedra to children
    for tet in FN.read_all_tetrahedra():
        for i, child in enumerate(children):
            if Intersect(child.extent, tet):
                child_files[i].write(tet)
                # Check if this tet requires higher resolution than current node
                if tet.needs_resolution > N.resolution:
                    N.recursion_needed = True
                    
    if not N.recursion_needed:
        # Leaf node: delete children/files, sample voxels
        Delete(children)
        Delete(child_files)
        N.voxel_grid = Sample(N, FN)
    else:
        # Internal node: delete FN, recurse
        Delete(FN)
        for i, child in enumerate(children):
            child.voxel_grid = Process(child, child_files[i])
            
    return N.voxel_grid
```

**Tetrahedron-Cell Overlap Test**
To determine if a tetrahedron intersects a node's bounding box, extend the Separating Axis Theorem. Test 25 axes:
1.  3 axes orthogonal to cell faces.
2.  4 axes orthogonal to tetrahedron faces.
3.  18 cross products of cell edges (3) and tetrahedron edges (6) [S2].
Exit early if any axis proves no overlap [S2].

**Termination Criteria**
Recursion stops when scalar-field homogeneity or tetrahedra size thresholds are reached. A zero-error threshold ensures no two vertices lie in the same voxel, but degenerate (nearly flat) tetrahedra are excluded from this computation to remain feasible [S2].

#### 3. Node Sampling (Preprocess Stage 3)
For leaf nodes, resample tetrahedra into a regular grid of voxels.
*   Use a voxel-order algorithm.
*   Compute barycentric coordinates for each voxel sample point relative to the tetrahedron. If coordinates sum to < 1, the point is contained. Use these coordinates for trilinear interpolation of the scalar value [S2].
*   Cache the basis conversion matrix (Euclidean to barycentric) for each tetrahedron to accelerate computation [S2].

#### 4. Node Filtering (Preprocess Stage 4)
Bottom-up, level-by-level filtering to produce voxel grids for interior nodes from their children. Two stages [S2]:

**Stage 1: Merge Children**
*   Apply a 3x3 box filter (or Gaussian) to merge 8 children into the parent.
*   **Border Continuity:** Load 7 adjacent nodes (in 2D quadtree analogy) or 26 neighbors (in 3D) to maintain overlapping borders. If a neighbor does not exist at the same level, load a special null data node [S2].
*   **Internal Border Fix:** If only a portion of a node's octants subdivides, copy border data from existing siblings into the node being merged to prevent discontinuities at internal child boundaries [S2].

**Stage 2: Compute Gradients**
*   Apply a gradient filter kernel.
*   Use central difference for interior voxels; forward/backward difference at boundaries [S2].
*   Normalize the output [S2].

**Pseudocode for Filtering** [S2]:
```python
def Filter(Node N, FilterStage S):
    buffers B, O = CreateBuffers()
    
    if S == MERGE_CHILDREN:
        # Read N's 8 children into B
        for child in N.children:
            ReadIntoBuffer(B, child)
        # Read adjacent nodes for border continuity
        for child in N.children:
            for neighbor in child.adjacent_nodes:
                ReadIntoBuffer(B, neighbor)
        Kernel K = CreateBoxFilterKernel()
    else: # S == COMPUTE_GRADIENT
        # Read N and its 26 neighbors into B
        ReadIntoBuffer(B, N)
        for neighbor in N.neighbors_26:
            ReadIntoBuffer(B, neighbor)
        Kernel K = CreateGradientFilterKernel()
        
    O = Convolve(B, K)
    O = Normalize(O)
    WriteToFile(N.output_filename, O)
    FreeBuffers(B, O)
```

#### 5. Padding and Stencil (Preprocess Stage 5)
To prevent striping artifacts at data boundaries [S2]:
1.  **Stencil:** Create a 1-bit-per-voxel texture (0 for null, 1 for data).
2.  **Padding:** Extend discontinuity outward from real data by one texel. Replicate boundary data by averaging neighboring non-null voxels [S2].
3.  **Rendering:** Use a 3D stencil test to clip the replicated data so it is never rendered, but is used for linear interpolation near boundaries [S2].

#### 6. Rendering (Geresim-Spike Variant)
For the specific Geresim-Spike implementation [S1, unofficial]:
1.  **Coarse Grid:** CPU precomputes an $8^3$ coarse grid mapping tiles to cell AABBs.
2.  **Cell Index Texture:** For each $32^3$ voxel, perform linear inverse-trilinear interpolation at the cell center to find local coordinates $(u,v,w)$. Store cell indices in an `R32UI` 3D texture.
3.  **GPU Fragment Shader:**
    *   Ray-march through the 3D texture of cell indices.
    *   Sample per-cell 8-corner data from a 2D `RGBA32F` texture.
    *   Compute trilinear scalar value and analytic gradient.
    *   Use the analytic gradient as a pseudo-normal for Blinn-Phong shading.
    *   Composite results front-to-back.

### Parameters
*   **Coarse Grid Resolution:** $8^3$ (Geresim-Spike) [S1, unofficial].
*   **Voxel Sampling Resolution:** $32^3$ per tile (Geresim-Spike) [S1, unofficial].
*   **Brick Resolution:** Fixed resolution $r$ (e.g., 4 in 2D examples) [S2].
*   **Target Frame Rate:** User-specified, typically >10 fps [S2].

### Edge Cases and Pitfalls
*   **Micro-cells:** Cell-by-cell look yields ~35% voxel coverage in Geresim-Spike; the rest are micro-cells too small to hit the grid or fall on boundaries where linear approximation fails [S1, unofficial].
*   **Degenerate Tetrahedra:** Nearly flat tetrahedra are excluded from the zero-error constraint to ensure feasibility [S2].
*   **Striping Artifacts:** Naïve filling of non-data voxels with zero-scalar data causes discontinuities. Linear interpolation displays this as striping along the model boundary. Solved by padding and stenciling [S2].
*   **Internal Border Discontinuity:** In adaptive sparse octrees, merging children can create incorrect borders if children lack neighbors at their depth. Fixed by copying border from existing siblings [S2].

## Subtopics

### [Octree-based Regular Grid Hierarchy](7295-octree-based-regular-grid-hierarchy.md)
Converts unstructured grids into a hierarchy of regular grids stored in an octree for texture-based LOD rendering. Solves memory consumption by managing resampling out-of-core. Chosen when structured grid hierarchies are preferred over multi-triangulation.

## Operating characteristics
*   **Time Complexity:** Preprocessing is top-down recursive with bottom-up filtering. Rendering is interactive, dependent on frame rate management.
*   **Memory Complexity:** Out-of-core processing. RAM usage is low (< 5 MB for tested datasets) despite handling data larger than main memory (up to 9 GB voxel data) [S2].
*   **Performance:** Interactive rates >10 fps for datasets ranging from 1,700 to 6,000,000 tetrahedra on standard PC hardware (NVIDIA Geforce4, OpenGL 3D texturing) [S2].
*   **Strengths:** Handles large out-of-core datasets; leverages standard 3D texture hardware; adaptive resolution preserves quality where needed.
*   **Limitations:** Requires preprocessing; striping artifacts if padding/stenciling is omitted; discontinuities at internal borders if not handled correctly.

## Background
Originated in the early 2000s for interactive visualization of large unstructured grids. The method was implemented on Windows PCs using NVIDIA Geforce4 accelerators [S2]. It builds upon the texture octree data structure from [LaMar et al. 1999] and differs from [Weiler et al. 2000] by using a hierarchical arrangement of constant-resolution bricks rather than a uniform grid of multi-resolution bricks [S2].
