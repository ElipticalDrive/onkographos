# Adaptive Voxelization of Unstructured Grids

Also called: Adaptive Voxelization, Geresim, Geresim-Spike, Hierarchical 3D Texture Mapping for Unstructured Grids, Hierarchical 3D Voxelization, Octree-based Voxelization, Spike

## Overview
Adaptive Voxelization of Unstructured Grids converts large, out-of-core unstructured grids (tetrahedral or hexahedral meshes) into a hierarchical 3D texture (voxel octree) to enable interactive volume rendering on standard PC hardware [S2]. It solves the problem of rendering massive datasets that exceed main memory by using an adaptive octree to preserve data at higher resolutions where needed, avoiding the undersampling or oversampling inherent in uniform grids [S2]. Unlike sibling methods that use uniform grid arrangements of multi-resolution bricks [S2], this method uses a hierarchical arrangement of constant-resolution texture bricks and specializes the octree to distinguish data from non-data voxels using a pad-and-stencil algorithm to eliminate boundary artifacts [S2].

## How it works
The method consists of a preprocessing stage that builds the octree and a rendering stage that visualizes it.

### Inputs and Outputs
**Inputs:**
*   Unstructured grid (tetrahedral or hexahedral) or structured grid [S2].
*   Target frame rate (e.g., >10 fps) [S2].
*   Scalar field values associated with grid vertices [S2].

**Outputs:**
*   A voxel octree consisting of texture bricks, each containing a scalar/gradient texture and a stencil texture [S2].
*   Rendered image via 3D texture mapping [S2].

### Data Structures

**Tetrahedron File Format** [S2]:
*   Flat, unindexed binary file.
*   Each tetrahedron: 4 vertices.
*   Each vertex: 3 × 32-bit float (coordinates) + 1 × 16-bit float (scalar value).
*   Total size: 56 bytes per tetrahedron.

**Octree Node Structure** [S2]:
*   Each node contains a texture brick of fixed resolution $r$.
*   Usable texture domain: $[1/(2r), (2r-1)/(2r)]$.
*   Neighboring bricks overlap by 1 texel to ensure continuity.
*   Final brick data includes:
    *   Scalar field/gradient texture.
    *   Stencil texture (1-bit per voxel: 0 for null, 1 for data).

**Cell Index Texture (Geresim-Spike variant)** [S1, unofficial]:
*   `R32UI` 3D texture storing cell indices for a coarse grid.
*   Coarse grid resolution: $8^3$ [S1, unofficial].
*   Voxel sampling resolution: $32^3$ per tile [S1, unofficial].

**Cell Data Texture (Geresim-Spike variant)** [S1, unofficial]:
*   `RGBA32F` 2D texture storing 8-corner data per cell.

### Algorithm Steps

#### Preprocessing: Adaptive Voxelization

**1. Tetrahedralization** [S2]:
If the input is a structured grid (e.g., hexahedral), convert it to tetrahedra. For convex hexahedral cells, slice each cell into 5 tetrahedra using a fixed decomposition template. If the input is already tetrahedral, skip this step.

**2. Octree Construction** [S2]:
Build the octree top-down recursively.
*   **Input:** Node $N$, Tetrahedra File $F_N$.
*   **Process:**
    1.  Read $N$'s spatial extent.
    2.  Create 8 children $C_i$ and corresponding files $F_{C_i}$.
    3.  Write $C_i$'s extent to $F_{C_i}$.
    4.  Initialize $N.Recursion = FALSE$.
    5.  For each tetrahedron $T$ in $F_N$:
        *   For each child $C_i$:
            *   If $Intersect(C_i, T)$ is true, write $T$ to $F_{C_i}$.
            *   If $T.NeededResolution > Resolution$, set $N.Recursion = TRUE$.
    6.  If $N.Recursion$ is FALSE:
        *   Delete children $C_i$ and files $F_{C_i}$.
        *   $V_N = Sample(N, F_N)$.
    7.  Else:
        *   Delete $F_N$.
        *   For each child $C_i$: $V_{C_i} = Process(C_i, F_{C_i})$.
    8.  Return $V_N$.

**Tetrahedron-Cell Overlap Test** [S2]:
To determine if a tetrahedron intersects a cell (box), extend the Separating Axis Theorem. Test 25 axes:
*   3 axes orthogonal to cell faces.
*   4 axes orthogonal to tetrahedron faces.
*   18 cross products of cell edges (3) and tetrahedron edges (6).
*   Exit early if overlap is disproven.

**Node Sampling (Leaf Nodes)** [S2]:
*   Resample tetrahedra within the leaf node's spatial cell into a regular grid of voxels.
*   Use barycentric coordinates to determine if a sample point is inside a tetrahedron. If the sum of barycentric coordinates is less than 1, the point is contained.
*   Interpolate scalar values using these barycentric coordinates.
*   Cache the basis conversion matrix (Euclidean to barycentric) for each tetrahedron to accelerate computation.

**Node Filtering (Interior Nodes)** [S2]:
Filter leaf node voxels bottom-up to produce voxel grids for all interior tree nodes. Two stages:
1.  **Merge Children:** Apply a $3 \times 3$ box filter (or Gaussian) to merge 8 children into a parent.
2.  **Compute Gradients:** Use central difference (forward/backward at boundaries) to compute gradients.

**Padding and Stencil** [S2]:
1.  **Stencil Creation:** Create a 1-bit-per-voxel stencil texture (0 for null, 1 for data).
2.  **Padding:** Extend discontinuity outward from real data by one texel during resampling by replicating boundary data (averaging neighboring non-null voxels).
3.  **Stenciling:** During rendering, use a 3D stencil test to clip the replicated data so it is never rendered, but is used for linear interpolation near boundaries.

**Pseudocode for Octree Construction** [S2]:
```python
def Process(Node N, TetrahedraFile FN):
    # Read N's spatial extent
    extent = N.get_extent()
    
    # Create 8 children and their files
    children = []
    child_files = []
    for i in range(8):
        Ci = Node()
        Ci.set_extent(extent.get_child_extent(i))
        FCi = TetrahedraFile()
        FCi.write_extent(Ci.get_extent())
        children.append(Ci)
        child_files.append(FCi)
        
    N.Recursion = False
    
    # Distribute tetrahedra
    for T in FN:
        for Ci, FCi in zip(children, child_files):
            if Intersect(Ci, T):
                FCi.write(T)
                if T.NeededResolution > N.Resolution:
                    N.Recursion = True
                    
    if not N.Recursion:
        # Leaf node: sample directly
        for Ci, FCi in zip(children, child_files):
            Ci.delete()
            FCi.delete()
        VN = Sample(N, FN)
        return VN
    else:
        # Internal node: recurse
        FN.delete()
        for Ci, FCi in zip(children, child_files):
            VCi = Process(Ci, FCi)
        return VN
```

**Pseudocode for Node Filtering** [S2]:
```python
def Filter(Node N, FilterStage S):
    # Create data buffers B and O
    B = DataBuffer()
    O = DataBuffer()
    
    if S == MERGE_CHILDREN:
        # Read N's 8 children into B
        for Ci in N.children:
            B.read(Ci)
        # Read adjacent nodes for border continuity
        for Ci in N.children:
            for neighbor in Ci.get_adjacent_nodes():
                B.read(neighbor)
        # Create box filter kernel K
        K = BoxFilterKernel(3)
    else: # S == COMPUTE_GRADIENT
        # Read N and N's neighbors into B
        B.read(N)
        for neighbor in N.get_neighbors():
            B.read(neighbor)
        # Create gradient filter kernel K
        K = GradientFilterKernel()
        
    # Convolve B by K into O
    O = Convolve(B, K)
    
    # Perform normalization on O
    O.normalize()
    
    # Write O into N's output filename
    N.write_output(O)
    
    # Free temporary data
    B.free()
    O.free()
```

#### Rendering (Geresim-Spike Variant) [S1, unofficial]

**1. CPU Precompute** [S1, unofficial]:
*   Create an $8^3$ coarse grid mapping tiles to cell AABBs.
*   For each $32^3$ voxel, perform linear inverse-trilinear interpolation at the cell center to find local coordinates $(u,v,w)$.
*   Store resulting cell indices in an `R32UI` 3D texture.

**2. GPU Fragment Shader** [S1, unofficial]:
*   **Ray-march:** Through the 3D texture of cell indices.
*   **Sample Data:** Per-cell 8-corner data from a 2D `RGBA32F` texture.
*   **Compute Value:** Trilinear scalar value and analytic gradient.
*   **Shading:** Use the analytic gradient as a pseudo-normal for Blinn-Phong shading.
*   **Composite:** Front-to-back.

### Parameters
*   **Coarse grid resolution:** $8^3$ [S1, unofficial].
*   **Voxel sampling resolution:** $32^3$ per tile [S1, unofficial].
*   **Brick resolution:** Fixed resolution $r$ for texture bricks. Example: $4 \times 4$ for 2D representation [S2].
*   **Target Frame Rate:** User-specified, typically >10 fps [S2].
*   **Scalar Field Error Threshold:** Binds maximum resampling error. Zero-error is possible but excludes degenerate tetrahedra [S2].

### Edge Cases and Pitfalls
*   **Degenerate Tetrahedra:** Nearly flat tetrahedra are excluded from the scalar field error threshold computation to make the zero-error constraint feasible [S2].
*   **Internal Border Discontinuity:** In adaptive sparse octrees, if only a portion of a node's octants subdivides, merging children can create incorrect borders because children lack neighbors at their depth. Fix: Copy border from existing siblings into the node being merged [S2].
*   **Striping Artifact:** Naïve filling of non-data voxels with zero-scalar data causes discontinuity, displaying as striping along the model boundary. Solved by the pad-and-stencil algorithm [S2].
*   **Cell-by-Cell Look:** In the Geresim-Spike variant, the trilinear gradient is constant within a cell but discontinuous at cell faces, leading to a "cell-by-cell" visual appearance [S1, unofficial].
*   **Coverage:** Cell index precompute yields approximately 35% voxel coverage; the rest are micro-cells too small to hit the grid or fall on boundaries where linear approximation fails [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing is out-of-core, processing tetrahedra independently. Rendering is interactive, managed by frame rate feedback [S2].
*   **Memory Complexity:** Uses less than 5 MB of RAM for tested datasets, despite handling data larger than main memory (up to 9 GB voxel data) [S2].
*   **Performance:** Visualized scalar fields ranging from 1,700 to 6,000,000 tetrahedra at interactive rates >10 fps on standard PC with OpenGL 3D texturing [S2].
*   **Hardware:** Implemented on Windows PC using NVIDIA Geforce4 accelerator [S2].
*   **Strengths:** Handles out-of-core data; adaptive resolution preserves detail where needed; leverages standard 3D texture hardware; maximizes quality for a target frame rate [S2].
*   **Limitations:** Discontinuities at cell faces in Geresim-Spike variant; requires careful handling of border continuity in adaptive octrees; striping artifacts if padding/stenciling is omitted [S1, unofficial][S2].

## Background
The method was introduced by Leven et al. in 2002 as "Interactive Visualization of Unstructured Grids Using Hierarchical 3D Texture Mapping" [S2]. It builds upon the texture octree data structure developed by LaMar et al. [1999] and Boada et al. [2001], specializing it for unstructured grids. It differs from Weiler et al. [2000] by using a hierarchical arrangement of constant-resolution bricks rather than a uniform grid of multi-resolution bricks. The Geresim-Spike variant is an unofficial WebGL implementation by Amory0709, based on the technique described by Miranda and Celes (Tecgraf/PUC-Rio + Petrobras, SIBGRAPI 2011 / TVC 2012) [S1, unofficial].
