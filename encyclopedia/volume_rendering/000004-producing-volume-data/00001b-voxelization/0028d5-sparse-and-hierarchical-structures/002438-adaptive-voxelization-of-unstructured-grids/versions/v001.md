# Adaptive Voxelization of Unstructured Grids

Also called: Adaptive Voxelization, Geresim, Geresim-Spike, Hierarchical 3D Texture Mapping for Unstructured Grids, Hierarchical 3D Voxelization, Octree-based Voxelization, Spike

## Overview
Adaptive Voxelization converts large, unstructured grids (tetrahedral or hexahedral meshes) into a hierarchical 3D texture (voxel octree) to enable interactive volume rendering on standard PC hardware [S2]. It solves the problem of undersampling or oversampling inherent in uniform grids by partitioning model space with an adaptive octree, preserving high resolution only where the scalar field varies significantly [S2]. Unlike uniform multi-resolution brick approaches [S2], it uses a hierarchical arrangement of constant-resolution texture bricks and specializes the octree to distinguish data from non-data voxels using a pad-and-stencil algorithm to eliminate boundary artifacts [S2].

## How it works
The method consists of a preprocessing stage that builds the octree and a rendering stage that traverses it.

### Inputs and Outputs
**Inputs:**
*   Unstructured grid (tetrahedral or hexahedral) or structured grid [S2].
*   Scalar field values associated with vertices [S2].
*   Target frame rate (e.g., >10 fps) [S2].

**Outputs:**
*   A voxel octree where each node contains a texture brick (scalar/gradient texture and stencil texture) [S2].
*   Rendered image via 3D texture mapping [S2].

### Data Structures

**Tetrahedron File Format (Flat, Unindexed) [S2]:**
*   Each tetrahedron is stored sequentially.
*   Each vertex contains:
    *   3 × 32-bit floats (x, y, z coordinates).
    *   1 × 16-bit float (scalar field value).
*   Total size: 56 bytes per tetrahedron.

**Octree Node Structure [S2]:**
*   Each node contains a texture brick of fixed resolution $r$.
*   **Usable Domain:** The valid data occupies the texture domain from $1/(2r)$ to $(2r-1)/(2r)$.
*   **Overlap:** Neighboring bricks overlap by 1 texel to ensure continuity.
*   **Brick Data:**
    *   Scalar field / Gradient texture.
    *   Stencil texture (1-bit per voxel: 0 for null, 1 for data).

**Cell Index Texture (Geresim-Spike variant) [S1, unofficial]:**
*   Format: `R32UI` 3D texture.
*   Content: Cell indices mapping 32³ voxel tiles to unstructured cell AABBs.

**Cell Data Texture (Geresim-Spike variant) [S1, unofficial]:**
*   Format: 2D `RGBA32F` texture.
*   Content: 8-corner data per cell (positions and scalar values).

### Algorithm Steps

#### 1. Tetrahedralization (Preprocessing) [S2]
If the input is a structured grid (e.g., hexahedral), it is converted to tetrahedra.
*   For convex hexahedral cells, slice the cell into 5 tetrahedra using a fixed decomposition template [S2].
*   Write tetrahedra to a flat file (56 bytes/tet) [S2].

#### 2. Adaptive Octree Construction [S2]
A top-down recursive procedure partitions space.

**Pseudocode for `Process(Node N, Tetrahedra File FN)`:**

```python
def Process(Node N, TetrahedraFile FN):
    # Read N's spatial extent
    extent = N.extent
    
    # Create 8 children and their associated files
    Children = []
    ChildFiles = []
    for i in 0..7:
        Child Ci = new Node()
        Ci.extent = extent.subdivide(i)
        File FCi = new TetrahedraFile()
        write Ci.extent to FCi
        Children.append(Ci)
        ChildFiles.append(FCi)
        
    N.Recursion = False
    
    # Distribute tetrahedra to children
    for Tetrahedron T in FN:
        for Child Ci in Children:
            if Intersect(Ci, T):
                write T to FCi
                # Check if this tetrahedron requires higher resolution
                if T.NeededResolution > N.Resolution:
                    N.Recursion = True
                    
    if not N.Recursion:
        # Leaf node: Sample tetrahedra into voxel grid
        delete Children, ChildFiles
        VoxelGrid VN = Sample(N, FN)
        return VN
    else:
        # Internal node: Recurse
        delete FN
        for Child Ci in Children:
            VCi = Process(Ci, ChildFiles[i])
        return None # Internal nodes don't return voxel grids directly; children do
```

**Tetrahedron-Cell Overlap Test [S2]:**
Uses an extended Separating Axis Theorem for box-tetrahedron intersection. Tests 25 axes:
1.  3 axes orthogonal to cell faces.
2.  4 axes orthogonal to tetrahedron faces.
3.  18 cross products of cell edges (3) and tetrahedron edges (6).
*   Exit early if any axis proves no overlap [S2].

**Node Sampling (Leaf) [S2]:**
*   Load all tetrahedra for the leaf node into memory.
*   For each voxel in the leaf's grid, compute barycentric coordinates within intersecting tetrahedra.
*   If coordinates sum < 1, the point is inside; interpolate scalar value using barycentric weights [S2].
*   Cache basis conversion matrix (Euclidean to barycentric) per tetrahedron for acceleration [S2].

**Node Filtering (Bottom-Up) [S2]:**
Two stages executed level-by-level from leaves to root.

**Pseudocode for `Filter(Node N, FilterStage S)`:**

```python
def Filter(Node N, FilterStage S):
    Buffer B = new DataBuffer()
    Buffer O = new DataBuffer()
    
    if S == MERGE_CHILDREN:
        # Read N's 8 children into B
        for Child Ci in N.children:
            read Ci.data into B
        # Read adjacent nodes for border continuity
        for Child Ci in N.children:
            for Neighbor Ni in Ci.adjacent_nodes:
                read Ni.data into B
        # Create box filter kernel K (3x3)
        Kernel K = BoxFilter(3)
    else: # S == COMPUTE_GRADIENT
        # Read N and its 26 neighbors into B
        read N.data into B
        for Neighbor Ni in N.neighbors_26:
            read Ni.data into B
        # Create gradient filter kernel K
        Kernel K = GradientKernel()
        
    # Convolve
    O = Convolve(B, K)
    
    # Normalize
    O = Normalize(O)
    
    # Write result
    write O to N.output_filename
    
    free B, O
```

*   **Merge Children:** Uses a 3x3 box filter (or Gaussian) to average children into the parent [S2].
*   **Compute Gradients:** Uses central differences (forward/backward at boundaries) [S2].
*   **Border Continuity:** To avoid discontinuities, load 7 adjacent nodes (2D example) or 26 neighbors (3D gradient stage) [S2]. If a neighbor doesn't exist at the same depth, load a null data node [S2].
*   **Internal Border Fix:** If only a portion of a node's octants subdivides, copy border data from existing siblings into the node being merged to prevent incorrect averaging [S2].

#### 3. Padding and Stencil [S2]
*   **Stencil:** Create a 1-bit-per-voxel texture (0 for null, 1 for data) [S2].
*   **Padding:** Extend discontinuity outward by one voxel. Replicate boundary data by averaging neighboring non-null voxels [S2].
*   **Rendering:** Use a 3D stencil test to clip the replicated data so it is never rendered, but is used for linear interpolation near boundaries, removing striping artifacts [S2].

#### 4. Rendering (Geresim-Spike Variant) [S1, unofficial]
*   **Ray Marching:** GPU fragment shader ray-marches through the `R32UI` 3D texture of cell indices.
*   **Sampling:** Sample per-cell 8-corner data from the 2D `RGBA32F` texture.
*   **Interpolation:** Compute trilinear scalar value and analytic gradient at the ray intersection point within the cell.
*   **Shading:** Use the analytic gradient as a pseudo-normal for Blinn-Phong shading.
*   **Compositing:** Composite results front-to-back [S1, unofficial].

### Parameters
*   **Coarse Grid Resolution (Spike):** 8³ [S1, unofficial].
*   **Voxel Sampling Resolution (Spike):** 32³ per tile [S1, unofficial].
*   **Brick Resolution:** Fixed resolution $r$ per octree node (e.g., 4x4 in 2D examples) [S2].
*   **Target Frame Rate:** User-specified, typically >10 fps [S2].
*   **Scalar Field Error Threshold:** Controls subdivision; zero-error is possible but excludes degenerate tetrahedra [S2].

### Edge Cases and Pitfalls
*   **Degenerate Tetrahedra:** Nearly flat tetrahedra are excluded from the scalar field error threshold computation to make the zero-error constraint feasible [S2].
*   **Discontinuities at Borders:** Merging children in incomplete adaptive octrees can create incorrect borders if children lack neighbors at their depth. Fix by copying border from existing siblings [S2].
*   **Striping Artifact:** Naïve filling of non-data voxels with zero-scalar data causes discontinuity, visible as striping along the model boundary. Solved by the pad-and-stencil algorithm [S2].
*   **Cell-by-Cell Look (Spike):** The trilinear gradient is constant within a cell but discontinuous at cell faces. This is intentional for the "cell-by-cell" rendering style [S1, unofficial].
*   **Coverage:** Cell index precompute yields ~35% voxel coverage; the rest are micro-cells too small to hit the 32³ grid or fall on boundaries where linear approximation fails [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing is out-of-core, processing tetrahedra independently. Rendering is interactive, dependent on frame rate management [S2].
*   **Memory Usage:** Less than 5 MB RAM for tested datasets, despite handling data larger than main memory (up to 9 GB voxel data) [S2].
*   **Performance:** Interactive rates >10 fps for scalar fields ranging from 1,700 to 6,000,000 tetrahedra on standard PC hardware (NVIDIA Geforce4, OpenGL 3D texturing) [S2].
*   **Strengths:** Handles out-of-core data; maximizes quality for a target frame rate rather than maximizing frame rate for a given quality; leverages standard 3D texture hardware [S2].
*   **Limitations:** Requires 3D texture mapping support; adaptive octree construction can be complex due to border continuity issues; Geresim-Spike variant has low voxel coverage (~35%) due to micro-cells [S1, unofficial][S2].

## Background
*   **Origin:** The method was developed by Leven, et al. for interactive visualization of unstructured grids [S2].
*   **History:** It builds upon the texture octree data structure from LaMar et al. [1999] and Boada et al. [2001], specializing it for unstructured grids with a novel pad-and-stencil algorithm [S2]. It differs from Weiler et al. [2000] by using a hierarchical arrangement of constant-resolution bricks instead of a uniform grid of multi-resolution bricks [S2].
*   **Usage:** Used to visualize scalar fields from unstructured grids, structured grids, and regular voxel data [S2].
*   **Geresim-Spike:** An unofficial WebGL/fragment-shader implementation of the technique by Miranda and Celes (Tecgraf/PUC-Rio + Petrobras, SIBGRAPI 2011 / TVC 2012), adapted for modern web browsers [S1, unofficial].
