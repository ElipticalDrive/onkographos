# Sparse Voxel Octree Construction (Optimized Version)
Also called: SVO construction, optimized version

## Overview
This method constructs a Sparse Voxel Octree (SVO) from a stream of non-empty voxel Morton codes by optimizing the handling of empty space [S1]. Unlike the basic version, which inserts empty child nodes individually, this approach calculates the number of empty nodes between consecutive input leaves and directly inserts empty parent nodes into higher-level queues [S1]. This reduces the number of queue operations significantly, as pushing back $2^d$ empty nodes is equivalent to pushing back a single node at the level above [S1]. It builds on [Sparse Voxel Octree Construction (Basic Version)](1694-sparse-voxel-octree-construction-basic-version.md) [S1].

## How it works
**Inputs:** A sorted stream of non-empty leaf nodes, each containing a 64-bit Morton code [S1].
**Outputs:** An out-of-core SVO stored on disk, with internal structure maintained in memory queues [S1].
**Data Structures:**
- `queues`: An array of queues, one for each depth level $d \in [0, \text{depth}]$. Each queue holds nodes (empty or internal) waiting to be merged [S1].
- `current_morton`: An integer tracking the Morton code of the previously processed leaf, initialized to 0 [S1].
- `depth`: The maximum depth of the octree [G].
- Node layout: Each node uses 24 bytes: a 64-bit reference to the first child, a 1-byte offset for every child, and a 64-bit reference to the associated data [S1].

**Algorithm Steps:**
1. Initialize `current_morton` to 0 [S1].
2. While input exists:
   a. Consume the next leaf node $l$ from the input stream [S1].
   b. Calculate the number of empty nodes between the current and previous Morton code: $\text{nb\_empty\_nodes} = l.\text{morton} - \text{current\_morton}$ [S1].
   c. While $\text{nb\_empty\_nodes} > 0$:
      i. Determine the insertion depth for empty nodes [S1]. Calculate $a$ as the largest integer such that $8^a < \text{nb\_empty\_nodes}$ [S1]. Calculate $b$ as the largest index such that `queues[b]` is not empty [S1]. Set the insertion depth $d_i = \max(\text{depth} - a, b)$ [S1].
      ii. Push an empty node onto `queues[d_i]` [S1].
      iii. While $d_i > 0$ and `queues[d_i]` is full:
           1. Create an internal node $p$.
           2. Set $p.\text{children}$ to the contents of `queues[d_i]` [S1].
           3. Write non-empty elements of `queues[d_i]` to disk [S1].
           4. Clear `queues[d_i]`.
           5. Push $p$ onto `queues[d_i - 1]`.
           6. Decrement $d_i$.
           7. Subtract $8^{\text{depth} - d_i}$ from $\text{nb\_empty\_nodes}$ [S1].
   d. Process the non-empty leaf node $l$ using the basic version logic: push $l$ to the appropriate queue, and if the queue is full, merge nodes up the tree as described in the basic version [S1].
   e. Update `current_morton` to $l.\text{morton}$ [S1].

**Pseudocode:**
```python
def optimized_svo_construction(input_stream, depth, queue_capacity=8):
    queues = [[] for _ in range(depth + 1)]
    current_morton = 0
    disk_output = []

    for leaf in input_stream:
        nb_empty_nodes = leaf.morton - current_morton

        while nb_empty_nodes > 0:
            a = 0
            while 8 ** (a + 1) < nb_empty_nodes:
                a += 1

            b = 0
            for i in range(depth, -1, -1):
                if queues[i]:
                    b = i
                    break

            di = max(depth - a, b)
            queues[di].append({'type': 'empty'})

            while di > 0 and len(queues[di]) >= queue_capacity:
                p = {'type': 'internal', 'children': queues[di]}
                for child in queues[di]:
                    if child['type'] != 'empty':
                        disk_output.append(child)
                queues[di] = []
                queues[di - 1].append(p)
                di -= 1
                nb_empty_nodes -= 8 ** (depth - di)

        queues[depth].append(leaf)
        d = depth
        while d > 0 and len(queues[d]) >= queue_capacity:
            p = {'type': 'internal', 'children': queues[d]}
            for child in queues[d]:
                if child['type'] != 'empty':
                    disk_output.append(child)
            queues[d] = []
            queues[d - 1].append(p)
            d -= 1

        current_morton = leaf.morton
```

**Parameters:**
- `depth`: The maximum depth of the octree. Not given in the sources. [G]
- Queue capacity: Not given in the sources. [G]
- Node size: 24 bytes per node (64-bit reference to first child, 1-byte offset per child, 64-bit reference to data) [S1].

**Edge Cases and Pitfalls:**
- Precision: Morton codes are 64-bit integers; ensure no overflow when calculating differences [G].
- Boundary: If `nb_empty_nodes` is exactly a power of 8, the logic for $a$ must handle the strict inequality $8^a < \text{nb\_empty\_nodes}$ correctly [S1].
- Empty Input: If the input stream is empty, the algorithm terminates immediately [G].

## Operating characteristics
- **Time Complexity:** The optimized version is over two orders of magnitude faster than the non-optimized version [S1].
- **Memory Complexity:** The process consumes only roughly 1.6 MB of memory [S1].
- **Scaling:** Efficient for large voxel grids where the majority of cells are empty [S1].
- **Strengths:** Significantly reduced queue operations by inserting empty parent nodes directly [S1].
- **Limitations:** Requires sorted input of Morton codes [S1].

## Background
The optimized version was introduced by Lagae and Dutre in 2008 [S1]. It addresses the inefficiency of the basic version, which spends considerable time processing empty nodes [S1]. The key insight is that pushing back $2^d$ empty nodes is equivalent to pushing back a single node at the level above [S1]. This method is part of the out-of-core construction of sparse voxel octrees, allowing for the handling of very large voxel grids that do not fit in main memory [S1].
