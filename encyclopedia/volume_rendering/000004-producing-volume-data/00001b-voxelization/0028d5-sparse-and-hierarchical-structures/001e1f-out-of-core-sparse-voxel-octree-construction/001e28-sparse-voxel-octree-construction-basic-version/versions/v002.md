# Sparse Voxel Octree Construction (Basic Version)

Also called: Basic SVO Construction, SVO Construction, basic version

## Overview
This method constructs a Sparse Voxel Octree (SVO) from a stream of non-empty voxel Morton codes by maintaining fixed-size queues per depth level, merging nodes when a queue fills, and writing non-empty nodes to disk [S2]. It differs from its siblings, such as [Brute Force SVO Construction](1704-brute-force-svo-construction.md), by avoiding complex sorting or streaming logic in favor of a simple recursive subdivision and depth-first search [S2]. This method is chosen when implementation simplicity is prioritized over memory efficiency and construction speed [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A stream of non-empty voxel Morton codes, sorted in ascending order, generated by the voxelization process [S2].
*   **Output:** A Sparse Voxel Octree written to disk (or an output buffer), structured with good locality of reference so that siblings are stored contiguously [S2].

**Data Structures:**
*   **Queues:** An array of queues, one for each depth level of the octree. Each queue holds node descriptors (leaf nodes or internal node references) [S2].
*   **Node Descriptor:** A 24-byte representation per node consisting of a 64-bit reference to the first child of the node, a 1-byte offset for every child of the node, and a 64-bit reference to the data associated with the node [S2].
*   **Empty Node:** A special descriptor (value `0`) indicating an empty subtree [S1, unofficial].

**Algorithm Steps:**
1.  Initialize an array of queues, one for each depth level of the octree.
2.  While input exists:
    a.  Consume a leaf node `l` from the input stream [S2].
    b.  Push the leaf node `l` onto the queue corresponding to its depth [S2].
    c.  Initialize a depth counter `d` to the current depth of the voxel grid [S2].
    d.  While `d > 0` and the queue at depth `d` is full:
        i.  Create an internal node `p` [S2].
        ii. Set `p.children` to the child offsets of the elements in `queues[d]` [S2].
        iii. Write the non-empty elements of `queues[d]` to disk [S2].
        iv. Clear `queues[d]` [S2].
        v.  Push `p` onto `queues[d-1]` [S2].
        vi. Decrement `d` [S2].
3.  Write the root node to output and clear the queue of level 0 [S2].

**Pseudocode:**
```python
def build_svo_basic(input_stream, max_depth):
    # Initialize queues for each depth level
    queues = [Queue(capacity=8) for _ in range(max_depth + 1)]
    output_buffer = []
    
    for leaf_node in input_stream:
        depth = leaf_node.depth
        queues[depth].push_back(leaf_node)
        
        d = depth
        while d > 0 and queues[d].is_full():
            internal_node = make_internal_node()
            internal_node.children = get_child_offsets(queues[d])
            write_to_disk(queues[d].non_empty_elements())
            queues[d].clear()
            queues[d - 1].push_back(internal_node)
            d -= 1
            
    write_to_disk(queues[0].non_empty_elements())
    queues[0].clear()
    return output_buffer

class Queue:
    def __init__(self, capacity):
        self.items = []
        self.capacity = capacity
    def push_back(self, item):
        self.items.append(item)
    def is_full(self):
        return len(self.items) >= self.capacity
    def clear(self):
        self.items = []
    def non_empty_elements(self):
        return self.items

def make_internal_node():
    return {'children': [0] * 8}

def get_child_offsets(queue):
    return queue.non_empty_elements()

def write_to_disk(data):
    output_buffer.extend(data)
```

**Parameters:**
*   `max_depth`: The maximum depth of the octree.
*   `SVO_SIZE`: World side length in voxels, must be a power of two. Typical value: 512 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Out-of-bounds octants:** If `x`, `y`, or `z >= n` (grid size), return `0` immediately to treat them as empty [S1, unofficial].
*   **Empty node overhead:** The method spends significant time processing empty nodes, which reduces construction speed compared to optimized variants [S2].
*   **Color packing:** When creating a solid leaf, the descriptor uses a high-bit set value (`0x8000_0000`) combined with packed RGB8 color data [S1, unofficial]. (Note: source code uses `voxel_color_packed(y)` for the color value, which is corrected here to `v` [G]).

## Subtopics

### [Brute Force SVO Construction](1704-brute-force-svo-construction.md)
Brute Force SVO Construction is a top-down algorithm that builds a complete octree in memory and subsequently prunes empty branches to form a Sparse Voxel Octree (SVO). It differs from its siblings, such as [Sparse Voxel Octree Construction via Morton Code Sorting](2227-sparse-voxel-octree-construction-via-morton-code-sorting.md), by avoiding complex sorting or streaming logic in favor of a simple recursive subdivision and depth-first search. This method is chosen when implementation simplicity is prioritized over memory efficiency and construction speed.

### [Sparse Voxel Octree Construction (Optimized Version)](1900-sparse-voxel-octree-construction-optimized-version.md)
This method constructs a Sparse Voxel Octree (SVO) from a stream of non-empty voxel Morton codes by optimizing the handling of empty space. Unlike the basic version, which inserts empty child nodes individually, this approach calculates the number of empty nodes between consecutive input leaves and directly inserts empty parent nodes into higher-level queues. This reduces the number of queue operations significantly, as pushing back $2^d$ empty nodes is equivalent to pushing back a single node at the level above. It builds on [Sparse Voxel Octree Construction (Basic Version)](1694-sparse-voxel-octree-construction-basic-version.md).

### [Sparse Voxel Octree Construction via Morton Code Sorting](2227-sparse-voxel-octree-construction-via-morton-code-sorting.md)
This method constructs a static Sparse Voxel Octree (SVO) from a set of 3D points or voxels by converting them to Z-order (Morton) codes, sorting them for spatial locality, and recursively partitioning the sorted array into octree nodes and leaf voxels. It differs from dynamic insertion methods by pre-sorting all points into Morton order, which guarantees spatial locality and allows $O(1)$ range queries via binary search instead of tree traversal during construction.

### [Dynamic Octree Growth Algorithm](2375-dynamic-octree-growth-algorithm.md)
The Dynamic Octree Growth Algorithm constructs a Sparse Voxel Octree (SVO) by dynamically increasing its depth and spatial extent as new voxels are processed, rather than pre-calculating the scene's bounding box. It differs from static voxelization methods by handling out-of-bounds coordinates on-the-fly, ensuring the octree grows to encompass all input data without prior knowledge of the scene's dimensions. This method serves as the foundational growth logic for incremental SVO construction, upon which [Octree Insertion with Growth](2387-octree-insertion-with-growth.md) builds specific recursive insertion and boundary check logic.

### [Sparse Voxel Octree Construction (Queue-Based Collapse)](2457-sparse-voxel-octree-construction-queue-based-collapse.md)
This method constructs a Sparse Voxel Octree (SVO) from a stream of indexed leaves by maintaining a fixed-size array of queues, one per tree depth level, and collapsing homogeneous subtrees into single leaf or invalid nodes to compress the structure. It differs from brute-force or sorting-based builders by processing leaves in a single pass without requiring full in-memory tree storage or pre-sorting.

### [Sparse Voxel Octree (SVO) Builder](2617-sparse-voxel-octree-svo-builder.md)
The Sparse Voxel Octree (SVO) Builder is an algorithm that constructs a flat-array representation of a Sparse Voxel Octree from a list of input voxels or geometric primitives. It solves the problem of efficiently organizing spatial data for ray marching or pathfinding by creating a hierarchy where empty space is skipped, but internal nodes are explicitly allocated to maintain traversal continuity. It differs from its siblings by focusing on either a recursive depth-first initialization of a dense structure or a parallel, level-by-level GPU-based allocation and merging process, whereas the Brute Force method [1704-brute-force-svo-construction.md] typically relies on simpler, less memory-efficient insertion strategies.

### Out-of-Core SVO Construction via Morton Order
An out-of-core algorithm to build a Sparse Voxel Octree (SVO) from voxel grid data sorted in Morton order [S3, unofficial]. It reads voxels in groups of 8, generates parent nodes, and flushes buffers to disk to manage memory constraints [S3, unofficial]. The buffer size is $8 \times \text{octree\_depth} \times \text{node\_size}$ bits [S3, unofficial]. The resulting array structure ensures that at every level, child nodes are stored next to each other [S3, unofficial]. The tree is sparse, containing only nodes for voxels that have data [S3, unofficial]. This method assumes the octree spans the whole grid space, meaning 8 voxels always share the same parent, eliminating the need for a top-down search to find the parent node [S3, unofficial]. Unlike point-based global illumination methods (e.g., Tabellion EGSR2011) which require a top-down search to find parents for scattered points, this method benefits from voxel data spanning the whole grid, simplifying parent lookup [S3, unofficial].

### SSVDAG Construction Algorithm
An out-of-core, bottom-up external-memory algorithm that reduces an SVO to a minimal SSVDAG [S4, unofficial]. The algorithm operates bottom-up, alternating phases at each level of the octree hierarchy [S4, unofficial]. Phase 1: Cluster nodes representing similar subtrees (identical up to a similarity transform) and replace them with a single representative node [S4, unofficial]. Phase 2: Replace pointers in the immediately higher level to the clustered nodes with tagged pointers to the single representative [S4, unofficial]. The tag encodes the required similarity transform [S4, unofficial]. Phase 3: Sort the representatives by their reference count to facilitate variable-bit-rate encoding of the pointers [S4, unofficial]. The method assumes the original scene has geometric redundancy (many subtrees similar with respect to a reflective transformation) [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** The basic version is slower than the optimized version because it spends significant time processing empty nodes [S2]. The optimized version is over two orders of magnitude faster than the non-optimized version [S2].
*   **Memory Complexity:** The out-of-core method using 128 MB or 1 GB memory is roughly as fast as an in-core method using 8 GB memory, but uses up to 64 times less memory [S2]. The sparse voxel octree construction process consumes only roughly 1.6 MB of memory [S2].
*   **Performance:** On a Dell Precision T7500 workstation (Intel Xeon X5650 CPU, 7200 RPM SATA II disk), the out-of-core method using 128 MB or 1 GB memory is roughly as fast as an in-core method using 8 GB memory, but uses up to 64 times less memory [S2].
*   **Strengths:** Simple implementation, out-of-core capability, good locality of reference [S2].
*   **Limitations:** Slow processing of empty nodes [S2].

## Background
The method was introduced in the paper "Out-of-Core Construction of Sparse Voxel Octrees" [S2]. It is based on the idea of reading voxels in groups of 8 and storing the generated parent voxels at each level, allowing for efficient out-of-core construction [S3, unofficial]. The algorithm processes an intermediate high-resolution 3D voxel grid in Morton order in a streaming manner, keeping memory usage logarithmic in the size of the SVO [S2].
