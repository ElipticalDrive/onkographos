# Sparse Voxel Octree Construction (Basic Version)

Also called: Basic SVO Construction, SVO Construction, basic version

## Overview
This method constructs a Sparse Voxel Octree (SVO) from a stream of non-empty voxel Morton codes by maintaining queues per depth level, merging nodes when a queue fills up, and writing non-empty nodes to disk [S3]. It differs from its siblings, such as [Brute Force SVO Construction](1704-brute-force-svo-construction.md) and [Sparse Voxel Octree Construction via Morton Code Sorting](2227-sparse-voxel-construction-via-morton-code-sorting.md), by processing the input in a single streaming pass without requiring the entire octree structure to reside in memory or pre-sorting all points into Morton order [S3][S2, unofficial]. Trade-offs include high memory usage relative to optimized variants due to processing empty nodes, but it offers a straightforward implementation for out-of-core construction [S3].

## How it works
**Inputs and Outputs:**
- **Input:** A stream of non-empty voxel leaf nodes, typically sorted by Morton code (Z-order) [S3]. Each leaf node contains a Morton code and associated data (e.g., color) [S3].
- **Output:** A serialized Sparse Voxel Octree written to disk, where nodes are stored with good locality of reference (siblings stored next to each other) [S3].

**Data Structures:**
- **Queues:** An array of queues, one for each depth level of the octree. The number of queues corresponds to the maximum depth of the tree [S3].
- **Node Representation:** The output SVO uses a compact representation of 24 bytes per node: a 64-bit reference to the first child of the node, a 1-byte offset for every child of the node, and a 64-bit reference to the data associated with the node [S3].
- **Leaf Node:** Represents a non-empty voxel. It is pushed onto the queue corresponding to its depth [S3].

**Algorithm Steps:**
1. Initialize an array of queues, one for each depth level $d$ from $0$ to $max\_depth$.
2. While the input stream is not empty:
   a. Consume the next leaf node $l$ from the input stream [S3].
   b. Push $l$ onto the queue corresponding to its depth $d$ [S3].
   c. Initialize a depth counter $d$ to the depth of the pushed leaf [S3].
   d. While $d > 0$ and the queue at depth $d$ is full:
      i. Create an internal node $p$ [S3].
      ii. Set the children of $p$ to the child offsets of the elements currently in `queues[d]` [S3].
      iii. Write the non-empty elements of `queues[d]` to disk [S3].
      iv. Clear `queues[d]` [S3].
      v. Push the internal node $p$ onto `queues[d-1]` [S3].
      vi. Decrement $d$ by 1 [S3].
3. After the input stream is exhausted, write the root node (from `queues[0]`) to disk and clear `queues[0]` [S3].

**Pseudocode:**
```python
def build_svo_basic(input_stream, max_depth):
    # Initialize queues for each depth level
    queues = [Queue() for _ in range(max_depth + 1)]
    
    # Process input stream
    for leaf in input_stream:
        # Push leaf onto the queue corresponding to its depth
        d = leaf.depth
        queues[d].push_back(leaf)
        
        # Merge nodes bottom-up while queue is full
        while d > 0 and queues[d].is_full():
            # Create internal node
            p = InternalNode()
            
            # Set children to offsets of elements in current queue
            p.children = get_child_offsets(queues[d])
            
            # Write non-empty elements of current queue to disk
            write_to_disk(queues[d])
            
            # Clear current queue
            queues[d].clear()
            
            # Push internal node to parent queue
            queues[d - 1].push_back(p)
            
            # Move up one level
            d -= 1
            
    # Write root node to disk
    write_to_disk(queues[0])
```

**Parameters:**
- **max_depth:** The maximum depth of the octree. Not given in the sources.
- **Queue Size:** The size of each queue determines when merging occurs. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Empty Nodes:** The basic version spends significant time processing empty nodes, which makes it slower than optimized versions [S3].
- **Input Order:** The algorithm assumes the input stream is sorted by Morton code to ensure spatial locality and correct parent-child relationships [S3].

## Subtopics

### [Brute Force SVO Construction](1704-brute-force-svo-construction.md)
Brute Force SVO Construction is a top-down algorithm that builds a complete Sparse Voxel Octree (SVO) in main memory by recursively subdividing the world space, followed by a depth-first search to prune empty branches. It differs from its siblings, such as [Out-of-Core SVO Construction via Morton Order](1885-out-of-core-svo-construction-via-morton-order.md) and [Sparse Voxel Octree Construction via Morton Code Sorting](2227-sparse-voxel-construction-via-morton-code-sorting.md), by requiring the entire octree structure to reside in memory during construction and relying on post-construction pruning rather than incremental merging or sorting. This approach is chosen for its implementation simplicity and recursive clarity, but is limited by high memory consumption and poor cache coherence due to scattered node allocation.

### [Out-of-Core SVO Construction via Morton Order](1885-out-of-core-svo-construction-via-morton-order.md)
This method constructs a Sparse Voxel Octree (SVO) from voxel grid data sorted in Morton order by reading voxels in groups of eight, generating parent nodes, and flushing buffers to disk to manage memory constraints. It differs from point-based global illumination methods (e.g., Tabellion EGSR2011) by leveraging the fact that voxel data spans the whole grid space, which eliminates the need for a top-down search to find parent nodes.

### [Sparse Voxel Octree Construction (Optimized Version)](1900-sparse-voxel-octree-construction-optimized-version.md)
This method constructs a Sparse Voxel Octree (SVO) from a stream of non-empty voxel Morton codes by optimizing the handling of empty space. Unlike the basic version, which inserts empty child nodes individually, this approach calculates the number of empty nodes between consecutive input leaves and directly inserts empty parent nodes into higher-level queues. This reduces the number of queue operations significantly, as pushing back $2^d$ empty nodes is equivalent to pushing back a single node at the level above. It builds on [Sparse Voxel Octree Construction (Basic Version)](1694-sparse-voxel-octree-construction-basic-version.md).

### [Sparse Voxel Octree Construction via Morton Code Sorting](2227-sparse-voxel-octree-construction-via-morton-code-sorting.md)
This method constructs a static Sparse Voxel Octree (SVO) from a set of 3D points or voxels by converting them to Z-order (Morton) codes, sorting them for spatial locality, and recursively partitioning the sorted array into octree nodes and leaf voxels. It differs from dynamic insertion methods by pre-sorting all points into Morton order, which guarantees spatial locality and allows $O(1)$ range queries via binary search instead of tree traversal during construction.

### [Dynamic Octree Growth Algorithm](2375-dynamic-octree-growth-algorithm.md)
The Dynamic Octree Growth Algorithm constructs a Sparse Voxel Octree (SVO) by dynamically increasing its depth and spatial extent as new voxels are processed, rather than pre-calculating the size from the input data. It handles both positive and negative coordinates by centering the root at the boundary between -1 and 0, ensuring the tree grows to encompass all input data without pre-calculating the scene's bounding box. It differs from static voxelization by adapting resolution locally and handling boundary conditions through recursive growth.

### [Sparse Voxel Octree Construction (Queue-Based Collapse)](2457-sparse-voxel-octree-construction-queue-based-collapse.md)
This method constructs a Sparse Voxel Octree (SVO) from a stream of indexed leaves by maintaining a fixed-size array of queues, one per tree depth level, and collapsing homogeneous subtrees into single leaf or invalid nodes to compress the structure. It differs from brute-force or sorting-based builders by processing leaves in a single pass without requiring full in-memory tree storage or pre-sorting.

### [Sparse Voxel Octree (SVO) Builder](2617-sparse-voxel-octree-svo-builder.md)
The Sparse Voxel Octree (SVO) Builder constructs a hierarchical Sparse Voxel Octree from a flat list of voxelized geometry, typically using GPU compute shaders or CPU parallel processing. It solves the problem of converting dense voxel grids into a compact, memory-efficient hierarchical structure suitable for ray tracing, voxel cone tracing, or pathfinding. Unlike its sibling [Brute Force SVO Construction](1704-brute-force-svo-construction.md) which may use less optimized memory layouts, or [Out-of-Core SVO Construction via Morton Order](1885-out-of-core-svo-construction-via-morton-order.md) which prioritizes disk I/O, the SVO Builder focuses on in-core hierarchical aggregation. It differs from [Sparse Voxel Octree Construction (Optimized Version)](1900-sparse-voxel-octree-construction-optimized-version.md) by using a specific level-by-level flagging and allocation strategy rather than Morton code sorting or queue-based collapse. It builds on the principles of [Sparse Voxel Octree Construction (Basic Version)](1694-sparse-voxel-octree-construction-basic-version.md) but implements the aggregation via explicit shader stages or parallel tasks.

### SSVDAG Construction Algorithm
An out-of-core, bottom-up external-memory algorithm that reduces an SVO to a minimal SSVDAG [S4, unofficial]. The algorithm operates bottom-up, alternating phases at each level of the octree hierarchy [S4, unofficial]. Phase 1: Cluster nodes representing similar subtrees (identical up to a similarity transform) and replace them with a single representative node [S4, unofficial]. Phase 2: Replace pointers in the immediately higher level to the clustered nodes with tagged pointers to the single representative. The tag encodes the required similarity transform [S4, unofficial]. Phase 3: Sort the representatives by their reference count to facilitate variable-bit-rate encoding of the pointers [S4, unofficial]. The method assumes the original scene has geometric redundancy (many subtrees similar with respect to a reflective transformation) [S4, unofficial].

## Operating characteristics
- **Time Complexity:** The basic version is significantly slower than the optimized version because it spends considerable time processing empty nodes [S3]. The optimized version is over two orders of magnitude faster than the non-optimized version [S3].
- **Memory Complexity:** The method uses roughly 1.6 MB of memory for the construction process, which is up to 64 times less memory than an in-core method requiring 8 GB [S3].
- **Measured Performance:** On a Dell Precision T7500 workstation (Intel Xeon X5650 CPU, 7200 RPM SATA II disk), the out-of-core method using 128 MB or 1 GB memory is roughly as fast as an in-core method using 8 GB memory, but uses up to 64 times less memory [S3].
- **Strengths:** Low memory usage, suitable for out-of-core construction, simple implementation.
- **Limitations:** Slow due to processing empty nodes, requires input to be sorted by Morton code.
- **When to Use:** When memory is constrained and the input is already sorted by Morton code.
- **When Not to Use:** When performance is critical and the input contains many empty nodes; use the optimized version instead.

## Background
The Sparse Voxel Octree (SVO) is a hierarchical representation of a voxel grid where nodes store 8 child descriptors. Each child descriptor is either 0 (empty subtree), a high-bit set value indicating a solid leaf with packed RGB8 color in the lower 24 bits, or an index into a flat storage buffer of nodes [S2, unofficial]. The construction of an octree hierarchy from a voxel grid is often stored as a compressed NPZ archive for later reuse [S1, unofficial]. The basic version of SVO construction was introduced in the context of out-of-core construction methods to handle large scenes that do not fit in main memory [S3].
