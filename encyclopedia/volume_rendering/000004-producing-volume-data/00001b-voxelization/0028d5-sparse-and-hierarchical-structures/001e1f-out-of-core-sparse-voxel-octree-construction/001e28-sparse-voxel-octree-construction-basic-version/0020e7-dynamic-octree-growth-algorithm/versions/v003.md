# Dynamic Octree Growth Algorithm

Also called: Jan Schultke's construction method, Octree expansion method

## Overview
The Dynamic Octree Growth Algorithm constructs a Sparse Voxel Octree (SVO) by dynamically increasing its depth and spatial extent as new voxels are processed, rather than pre-calculating the scene's bounding box [S1, unofficial]. It differs from static voxelization methods by handling out-of-bounds coordinates on-the-fly, ensuring the octree grows to encompass all input data without prior knowledge of the scene's limits [S1, unofficial]. This builds on [Sparse Voxel Octree Construction (Basic Version)](1694-sparse-voxel-octree-construction-basic-version.md) by providing the specific logic for root expansion when the current tree depth is insufficient to contain an incoming voxel.

## How it works
**Inputs and Outputs:**
- Input: An octree $o$ (initially containing only a root node) and a sequence of voxel coordinates $v$.
- Output: The modified octree $o$ with expanded depth if necessary.

**Data Structures:**
- **Octree Node:** A structure containing up to 8 children. Children are indexed $0$ to $7$.
- **Child Indexing:** Child $0$ (binary `000`) corresponds to the lowest position (negative coordinates); Child $7$ (binary `111`) corresponds to the highest position (positive coordinates) [S1, unofficial].
- **Coordinate System:** The root node covers the range $[-1, 0)$ for each axis. A voxel $v$ is contained in an octree of depth $d$ if $v$ is in the range $[-2^{d-1}, 2^{d-1})$ [S1, unofficial].

**Algorithm Steps:**

1. **Check Containment:** Determine if the incoming voxel $v$ is contained within the current octree depth $d$.
   - If $v$ is within the bounds defined by the current root's spatial extent, proceed to insertion (see [Octree Insertion with Growth](2387-octree-insertion-with-growth.md) for the recursive insertion logic).
   - If $v$ is outside the bounds, trigger the **Growth Loop**.

2. **Growth Loop:** Expand the octree by one level. For each child index $i$ from $1$ to $8$ (note: the source uses 1-based indexing for the loop, mapping to 0-based child indices $0$ to $7$):
   - Let $r$ be the current root node.
   - Let $n$ be the existing child of $r$ at index $i-1$ (if it exists; if null, treat as empty).
   - Create a new node $n'$.
   - Move the existing child $n$ to become the child at index $8 - i$ of $n'$ (using 1-based indexing for the position, which corresponds to index $7 - (i-1)$ in 0-based indexing). Specifically, if $n$ was at index $k$ (0-based), it moves to index $7-k$ [S1, unofficial].
   - Make $n'$ the new child of root $r$ at index $i-1$.

3. **Repeat:** After one growth iteration, re-evaluate containment. If the voxel is still not contained, repeat the Growth Loop.

4. **Bitstream Generation for Insertion:** Once contained, generate a bitstream based on the normalized position of the voxel $v$.
   - Normalize $v$ such that no component is negative.
   - Divide the bitstream into strips of 3 bits.
   - Each strip indicates which child to follow (0 to 7).
   - The leftmost strip represents the root's child; the rightmost represents the leaf [S1, unofficial].

**Pseudocode:**
The following pseudocode implements the root expansion step described in the source [S1, unofficial]. It assumes 1-based indexing for the loop variable $i$ as per the source, mapping to 0-based child array indices.

```python
def grow_octree(octree):
    """
    Expands the octree root by one level to accommodate larger coordinate ranges.
    Based on Algorithm 1 from [S1, unofficial].
    """
    r = octree.root
    
    # The source iterates i from 1 to 8. 
    # Child indices are 0 to 7.
    # Mapping: loop i=1 -> child index 0, loop i=8 -> child index 7.
    for i in range(1, 9):
        # Get existing child at index (i-1)
        # If child does not exist, n is None/null
        n = r.children[i - 1]
        
        # Create a new node
        n_prime = Node()
        
        # Move existing child n to position (8 - i) in n_prime.
        # Note: Source uses 1-based indexing for position "8-i".
        # If i=1, position is 7 (index 7).
        # If i=8, position is 0 (index 0).
        # In 0-based indexing, the target index is (8 - i).
        target_index = 8 - i
        
        # Set the child. If n was None, this sets a null child.
        n_prime.children[target_index] = n
        
        # Make n_prime the new child of root r at index (i-1)
        r.children[i - 1] = n_prime
        
    # Update the root reference if necessary (though r is a reference)
    octree.root = r
    return octree
```

**Parameters and Edge Cases:**
- **Root Bounds:** The initial root covers $[-1, 0)$. After one growth, the bounds expand. The exact expansion formula for subsequent levels is not explicitly detailed in the source beyond the containment check $[-2^{d-1}, 2^{d-1})$ [S1, unofficial].
- **Coordinate Sign:** The method supports both positive and negative coordinates by centering the root at the boundary between $-1$ and $0$ [S1, unofficial].
- **Pitfall:** The source code snippet uses 1-based indexing for the loop and child positions, which must be carefully translated to 0-based array implementations [S1, unofficial].

## Subtopics

### [Octree Insertion with Growth](2387-octree-insertion-with-growth.md)
Provides the recursive insertion logic and boundary checks required for incremental construction. It differs from static voxelization by handling out-of-bounds coordinates on-the-fly. Choose this when you need to insert voxels one by one into a dynamically growing tree.

### [Sparse Voxel Octree (Dynamic, Origin-Centered)](3622-sparse-voxel-octree-dynamic-origin-centered.md)
Enforces a strict origin-centered coordinate system and power-of-two voxel dimensions. Choose this when alignment to widths and origin-centering are required.

### [Regular-Adaptive Octree Construction](6560-regular-adaptive-octree-construction.md)
Introduces a fixed-depth regular base and explicit topological validation. Choose this when representing implicit surfaces with manifoldness guarantees.

## Operating characteristics
- **Time Complexity:** Not given in the sources. The growth step involves iterating over 8 children, which is $O(1)$ per growth level. The number of growth levels depends on the coordinate range.
- **Memory Complexity:** Not given in the sources. The algorithm creates new nodes during growth, potentially increasing memory usage if the tree expands significantly.
- **Strengths:** No need to pre-calculate the scene's bounding box; handles arbitrary coordinate ranges including negative values.
- **Limitations:** The source does not provide measured performance or scaling characteristics. The growth mechanism may lead to fragmentation or inefficient memory usage if not managed carefully [S1, unofficial].

## Background
The algorithm was published by Jan Schultke [S1, unofficial]. It is used in the context of constructing Sparse Voxel Octrees for efficient ray tracing and global illumination calculations, particularly when dealing with voxel data formats like .vox [S1, unofficial]. The method was chosen for its ability to handle both positive and negative coordinates without pre-defining the tree size.
