# Dynamic Octree Expansion

Also called: Enlarge, EnlargeCorners

## Overview
Dynamic Octree Expansion grows a Sparse Voxel Octree when a voxel insertion falls outside the current bounding volume [S1, unofficial]. It replaces the root node with a new parent spanning a larger volume, accommodating data without pre-allocating a fixed grid [S1, unofficial].

## How it works
**Inputs:**
- `m_size`: Current side length of the octree's bounding box [S1, unofficial].
- `m_position`: Current world-space position of the octree's origin [S1, unofficial].
- `direction`: The axis and sign of expansion (e.g., `xplus`, `yminus`, `zplus`) [S1, unofficial].

**Outputs:**
- A new Octree root node with double the size and updated position [S1, unofficial].
- A new `OctreeChildren` structure containing the previous root and the new empty child [S1, unofficial].

**Data Structures:**
- `OctreeChildren`: Contains a bitmask indicating which of the 8 children are valid, and an array `rootChildren[8]` of pointers to child nodes [S1, unofficial].
- `Octree`: Contains `m_size`, `m_position`, and a pointer to the root `OctreeChildren` [S1, unofficial].

**Steps:**
1. **Compute Indices and Offset:** Call `EnlargeCorners(direction)` to determine `oldCornerIdx`, `newCornerIdx`, and `offset` [S1, unofficial].
2. **Initialize Children Array:** Create an array `rootChildren` of 8 pointers, initialized to `nullptr` [S1, unofficial].
3. **Place Existing Root:** Assign the current root node to `rootChildren[oldCornerIdx]` [S1, unofficial].
4. **Create New Empty Node:** Instantiate a new empty octree node at `rootChildren[newCornerIdx]` with size `m_size`, position `m_position + offset`, and depth 1 [S1, unofficial].
5. **Construct Children Struct:** Create a new `OctreeChildren` object with a bitmask containing only `oldCornerIdx` and `newCornerIdx`, and the `rootChildren` array [S1, unofficial].
6. **Update Position (Negative Directions):** If the expansion direction is negative (`xminus`, `yminus`, or `zminus`), update `m_position` by adding `offset` [S1, unofficial].
7. **Double Size:** Update `m_size` to `m_size * 2` [S1, unofficial].
8. **Replace Root:** Create a new `Octree` instance with the new `OctreeChildren`, the updated `m_size`, and the updated `m_position` [S1, unofficial].

**Pitfalls:**
- The offset calculation for `xplus` in the source implementation uses `glm::vec3(m_size, 0, 0)` but is marked as unused in a comment, indicating a potential bug or placeholder that should be zeroed or properly utilized [S1, unofficial].
- Incorrect offsets cause gaps or overlaps in the spatial coverage [G].

**Pseudocode:**
```python
def dynamic_octree_expansion(octree, direction):
    # Step 1: Compute indices and offset
    old_corner_idx, new_corner_idx, offset = enlarge_corners(direction)

    # Step 2: Initialize children array
    root_children = [None] * 8

    # Step 3: Place existing root
    root_children[old_corner_idx] = octree.root_children

    # Step 4: Create new empty node
    new_node_size = octree.m_size
    new_node_position = tuple_add(octree.m_position, offset)
    new_empty_node = OctreeNode(size=new_node_size, position=new_node_position, depth=1)
    root_children[new_corner_idx] = new_empty_node

    # Step 5: Construct children struct
    bitmask = (1 << old_corner_idx) | (1 << new_corner_idx)
    new_children = OctreeChildren(bitmask=bitmask, children=root_children)

    # Step 6: Update position for negative directions
    if direction in ("xminus", "yminus", "zminus"):
        octree.m_position = tuple_add(octree.m_position, offset)

    # Step 7: Double size
    octree.m_size = octree.m_size * 2

    # Step 8: Replace root
    octree.root_children = new_children

def enlarge_corners(direction):
    # Maps expansion direction to child indices and spatial offset
    # [G] Standard corner mapping for axis-aligned expansion
    mapping = {
        "xplus": (0, 4, (1, 0, 0)), "xminus": (4, 0, (-1, 0, 0)),
        "yplus": (0, 2, (0, 1, 0)), "yminus": (2, 0, (0, -1, 0)),
        "zplus": (0, 1, (0, 0, 1)), "zminus": (1, 0, (0, 0, -1))
    }
    old_idx, new_idx, base_offset = mapping[direction]
    return old_idx, new_idx, base_offset

def tuple_add(a, b):
    return (a[0] + b[0], a[1] + b[1], a[2] + b[2])

class OctreeNode:
    def __init__(self, size, position, depth):
        self.size = size
        self.position = position
        self.depth = depth

class OctreeChildren:
    def __init__(self, bitmask, children):
        self.bitmask = bitmask
        self.children = children
```

## Subtopics

### Node Expansion
Expands a pruned node into its 8 children, setting their occupancy probability to the parent's value [S2]. This reverses pruning, and the caller must verify the node is indeed pruned (i.e., not a leaf at the lowest level) [S2]. The operation is expensive, especially when the tree is nearly empty [S2].

## Operating characteristics
- **Time Complexity:** O(1) for the expansion step, involving constant pointer assignments and one node allocation [S1, unofficial].
- **Memory Complexity:** O(1) additional memory for the new children structure and one empty node [S1, unofficial].
- **Strengths:** Enables unbounded growth without pre-allocation [S1, unofficial].
- **Limitations:** Frequent expansions increase tree depth, raising traversal costs [G].

## Background
Dynamic Octree Expansion is used in dynamic sparse voxel octree construction to handle boundary conditions during voxel insertion [S1, unofficial]. Its node expansion logic shares conceptual similarities with pruning reversal in octomap libraries [S2].
