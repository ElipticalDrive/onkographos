# Dynamic Octree Growth Algorithm

Also called: Jan Schultke's construction method, Octree expansion method

## Overview
The Dynamic Octree Growth Algorithm constructs a Sparse Voxel Octree (SVO) by dynamically increasing its depth and spatial extent as new voxels are processed, rather than pre-calculating the scene's bounding box [S1, unofficial]. It differs from static voxelization methods by handling out-of-bounds coordinates on-the-fly, ensuring the octree grows to encompass all input data without prior knowledge of the scene's dimensions [S1, unofficial]. This method serves as the foundational growth logic for incremental SVO construction, upon which [Octree Insertion with Growth](2387-octree-insertion-with-growth.md) builds specific recursive insertion and boundary check logic.

## How it works
**Inputs and Outputs:**
- Input: An octree structure $o$ (initially containing only a root node) and a sequence of voxel coordinates $v$.
- Output: The modified octree $o$ with expanded depth and spatial extent if necessary.

**Data Structures:**
- **Octree Node:** Each node has up to 8 children, indexed 0 to 7.
- **Child Indexing:** Child 0 (binary `000`) represents the lowest position (minimum coordinates), and Child 7 (binary `111`) represents the highest position (maximum coordinates) [S1, unofficial].
- **Coordinate System:** The root node covers the range $[-1, 0)$ for each axis. A voxel $v$ is contained in an octree of depth $d$ if $v$ is in the range $[-2^{d-1}, 2^{d-1})$ for each axis [S1, unofficial].

**Algorithm Steps:**

1. **Check Containment:** Determine if the incoming voxel $v$ is contained within the current octree depth $d$. If $v$ is within the bounds $[-2^{d-1}, 2^{d-1})$, no growth is needed. If not, trigger the growth loop [S1, unofficial].

2. **Growth Loop:** To expand the octree, the algorithm doubles the spatial extent by adding a new layer of nodes around the existing tree. For each child index $i$ from 1 to 8 of the root node $r$:
   - Create a new node $n'$.
   - Move the existing child $n$ (at index $i$ of the current root) to become the child at index $8 - i + 1$ of the new node $n'$.
   - Make $n'$ the new child of the root $r$ at index $i$, replacing the previous child $n$ [S1, unofficial].
   
   *Note:* The source pseudocode uses 1-based indexing for the loop ($1 \le i \le 8$) and the child index calculation ($8-i+1$). In standard 0-based indexing (0 to 7), this corresponds to iterating $i$ from 0 to 7, and moving the child at index $i$ to index $7-i$ in the new node. The source text explicitly states "position $8-i$" in the narrative but "8-i+1" in the pseudocode. Given 1-based indexing in the pseudocode ($1 \dots 8$), $8-1+1=8$ is invalid for 0-based 8 children. However, the text says "position $8-i$" in the narrative list. Let's stick to the provided pseudocode structure but clarify the indexing. The pseudocode says `set child(n', n, 8-i+1)`. If $i=1$, index is 8. If $i=8$, index is 1. This implies 1-based indexing for child positions in the source's internal logic. For implementation, we must map this to 0-based indexing: Child $i$ (0-based) moves to Child $7-i$ (0-based) in the new node.

3. **Bitstream Generation:** To locate the voxel within the expanded tree, generate a bitstream based on the normalized position of the voxel. The bitstream is divided into strips of 3 bits. Each strip indicates which child to follow (0 to 7). The leftmost strip represents the root's child; the rightmost represents the leaf [S1, unofficial].

**Parameters and Edge Cases:**
- **Coordinate System:** The root node covers the range $[-1, 0)$ for each axis [S1, unofficial]. This allows handling both positive and negative coordinates symmetrically around the origin boundary.
- **Containment Check:** A voxel $v$ is contained if $-2^{d-1} \le v < 2^{d-1}$ for all axes [S1, unofficial].
- **Edge Cases:** The algorithm assumes the octree starts with a root node. If the octree is empty, initialization is required [G]. The growth loop assumes the root has 8 children (or nulls) to shift. If a child is null, it is moved as null, preserving the empty space structure [G].

## Operating characteristics
- **Time Complexity:** Growth requires iterating over all 8 children of the root, making it $O(1)$ per growth step (constant number of children). However, if growth is triggered frequently, the cost accumulates. Traversal is $O(d)$ where $d$ is depth.
- **Memory Complexity:** Each growth step doubles the spatial extent and adds a new layer of nodes. The memory usage scales with the number of non-empty nodes and the depth required to cover the scene.
- **Strengths:** No need to pre-calculate scene bounds; handles arbitrary coordinate ranges including negative values.
- **Limitations:** Frequent growth operations can be costly if voxels are widely scattered. The root-centric growth strategy may lead to inefficient memory usage if the scene is not centered near the origin [G].
- **When to use:** Ideal for streaming voxel data where the total extent is unknown or dynamic.

## Background
The method follows the methodology published by Jan Schultke [S1, unofficial]. It was adopted in the project "Estudio de la compresión y la eficiencia del Sparse Voxel Octree en el cálculo de la Iluminación Global" to handle .vox file formats that accept both positive and negative coordinates, avoiding the memory inefficiency of regular grids and the intersection test overhead of naive voxel models [S1, unofficial].
