# Voxel Placement in Octree

Also called: SVO set, Sparse Voxel Octree (SVO) insertion with collapse/expand, octree voxel placement, placeVoxel

## Overview
Voxel Placement in Octree inserts a colored voxel into a Sparse Voxel Octree (SVO) at a specific 3D coordinate [S1, unofficial]. It handles recursive descent through the tree hierarchy, creating intermediate nodes as necessary, and marks the target leaf node with the voxel's color [S1, unofficial]. It is distinguished from sibling methods by its explicit handling of the collapse/expand state of internal nodes, ensuring that previously collapsed uniform regions can be correctly subdivided when new non-uniform data is inserted [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Inputs**:
    *   `node`: The current octree node (initially the root) [S1, unofficial].
    *   `nx, ny, nz`: The 3D coordinates of the center of the current node's bounding box [S1, unofficial].
    *   `size`: The side length of the current node's bounding box [S1, unofficial].
    *   `depth`: The current recursion depth (0 for root) [S1, unofficial].
    *   `x, y, z`: The 3D coordinates of the voxel to be placed [S1, unofficial].
    *   `color`: The color or density value of the voxel [S1, unofficial].
    *   `maxDepth`: The maximum allowed depth of the octree [S1, unofficial].
*   **Outputs**:
    *   Modifies the octree structure in place: creates child nodes if they do not exist, sets `isLeaf` flags, and assigns `color` to the target leaf [S1, unofficial].
    *   Returns `void` or a boolean indicating success/bounds status [S2, unofficial].

### Data Structures
The implementation relies on an `OctreeNode` structure [S1, unofficial]. While exact memory layouts vary by language, the logical fields required are:
*   `isLeaf`: Boolean flag indicating if the node is a leaf [S1, unofficial].
*   `color`: The value stored in the voxel [S1, unofficial].
*   `children`: An array or pointer to 8 child nodes (indexed 0-7) [S1, unofficial]. If `isLeaf` is true or the node is collapsed, this may be `null` or `None` [S1, unofficial].
*   `position`: The 3D center coordinates of the node [S1, unofficial].
*   `size`: The side length of the node [S1, unofficial].

### Numbered Steps
1.  **Base Case (Max Depth)**: If `depth` equals `maxDepth`, the current node is the target leaf [S1, unofficial]. Set `node.isLeaf = true`, set `node.color = color`, set `node.children = null`, and return [S1, unofficial].
2.  **Boundary Check**: If the voxel position `(x, y, z)` is outside the current node's bounding box defined by `(nx, ny, nz)` and `size`, return immediately or return `false` [S2, unofficial].
3.  **Collapse/Expand Check**: If `depth < maxDepth` and `node.isLeaf` is true (indicating a previously collapsed node), the node must be expanded [S1, unofficial]. Create 8 new child nodes, initialize each as a leaf with `isLeaf = true`, assign each child the `node.color` to propagate the uniform value, set `node.isLeaf = false`, and set `node.children` to the array of new children [S1, unofficial].
4.  **Calculate Child Index**: Determine which of the 8 octants contains the voxel [S1, unofficial]. Calculate `half = size / 2` [S1, unofficial]. Determine bit flags based on the voxel's position relative to the node's center: `ix = 1` if `x >= nx + half`, else `0`; `iy = 1` if `y >= ny + half`, else `0`; `iz = 1` if `z >= nz + half`, else `0` [S1, S2, unofficial]. Compute `childIdx = ix + (iy << 1) + (iz << 2)` [S1, S2, unofficial].
5.  **Create Child if Missing**: If `node.children[childIdx]` does not exist, create a new `OctreeNode` [S1, unofficial]. Set its position to `(nx + ix*half, ny + iy*half, nz + iz*half)` and its size to `half` [S1, unofficial]. Assign it to `node.children[childIdx]` [S1, unofficial].
6.  **Recurse**: Call `placeVoxel` (or `_set`) on `node.children[childIdx]` with `depth + 1` [S2, unofficial].

### Formulas
*   **Child Index**:
    $$ \text{childIdx} = i_x + 2 \cdot i_y + 4 \cdot i_z $$
    Where $i_x, i_y, i_z \in \{0, 1\}$ are determined by:
    $$ i_x = \begin{cases} 1 & \text{if } x \ge n_x + \frac{s}{2} \\ 0 & \text{otherwise} \end{cases} $$
    (Analogous for $i_y, i_z$ with $n_y, n_z, y, z$) [S1, S2, unofficial].
*   **Half Size**:
    $$ h = \frac{s}{2} $$ [S1, unofficial].

### Pseudocode
```python
class OctreeNode:
    def __init__(self):
        self.isLeaf = False
        self.color = None
        self.children = None
        self.position = (0.0, 0.0, 0.0)
        self.size = 0.0

def placeVoxel(node, nx, ny, nz, size, depth, maxDepth, x, y, z, color):
    # 1. Base Case: Reached maximum depth
    if depth == maxDepth:
        node.isLeaf = True
        node.color = color
        node.children = None
        return

    # 2. Boundary Check: Position outside current node bounds
    half = size / 2
    if not (nx - half <= x <= nx + half and
            ny - half <= y <= ny + half and
            nz - half <= z <= nz + half):
        return False

    # 3. Collapse/Expand Check: If node is currently a leaf but we need to go deeper
    if node.isLeaf:
        node.isLeaf = False
        node.children = [None] * 8
        for i in range(8):
            child = OctreeNode()
            child.isLeaf = True
            child.color = node.color
            ix = i & 1
            iy = (i >> 1) & 1
            iz = (i >> 2) & 1
            child.position = (nx + (2*ix - 1)*half, 
                              ny + (2*iy - 1)*half, 
                              nz + (2*iz - 1)*half)
            child.size = half
            node.children[i] = child

    # 4. Calculate Child Index
    ix = 1 if x >= nx + half else 0
    iy = 1 if y >= ny + half else 0
    iz = 1 if z >= nz + half else 0
    childIdx = ix + (iy << 1) + (iz << 2)

    # 5. Create Child if Missing
    if node.children[childIdx] is None:
        child = OctreeNode()
        child.position = (nx + (2*ix - 1)*half, 
                          ny + (2*iy - 1)*half, 
                          nz + (2*iz - 1)*half)
        child.size = half
        node.children[childIdx] = child

    # 6. Recurse
    placeVoxel(node.children[childIdx],
               node.children[childIdx].position[0],
               node.children[childIdx].position[1],
               node.children[childIdx].position[2],
               node.children[childIdx].size,
               depth + 1,
               maxDepth,
               x, y, z, color)
    return True
```

### Parameters
*   `maxDepth`: The maximum recursion depth. Not given in the sources.
*   `color`: The data value. Not given in the sources.

### Edge Cases and Pitfalls
*   **Collapsed Node Access**: If a `collapse()` operation previously set `children = null` on an internal node (at `depth < maxDepth`), a subsequent `set()` will throw an error when accessing `node.children[childIdx]` [S1, unofficial]. The implementation must check `node.isLeaf` or `!node.children` before descending and expand the node if necessary [S1, unofficial].
*   **Null Color Removal**: Using `set(x, y, z, null)` to remove voxels leaves leaf nodes with `color = null`, which prevents effective pruning/collapsing and can permanently "materialize" empty regions [S1, unofficial]. A dedicated `delete(x, y, z)` function is recommended to remove nodes and prune upward when a branch becomes entirely empty [S1, unofficial].
*   **Out of Bounds**: If the voxel position is outside the current node's bounding box, the function should return early to avoid infinite recursion or invalid memory access [S2, unofficial].

## Subtopics

### Octree-based Mesh Voxelization
*   **What it is**: A method that converts a triangle mesh into a voxel grid using an octree structure.
*   **Difference**: Focuses on rasterizing geometry into voxels rather than inserting individual voxels into a sparse structure.
*   **When to choose**: When starting from a mesh model.
*   **Link**: [Octree-based Mesh Voxelization](3071-octree-based-mesh-voxelization.md)

### Dynamic Sparse Voxel Octree with Morton Codes
*   **What it is**: An SVO implementation that uses Morton codes (Z-order curves) for efficient spatial indexing and traversal.
*   **Difference**: Uses linearized indices for memory layout and traversal, whereas this method uses explicit tree pointers.
*   **When to choose**: When memory locality and cache efficiency are critical, or for out-of-core storage.
*   **Link**: [Dynamic Sparse Voxel Octree with Morton Codes](4099-dynamic-sparse-voxel-octree-with-morton-codes.md)

## Background

### Origin
The method is derived from implementations of Sparse Voxel Octrees (SVO) for real-time rendering and voxel editing [S1, S2, unofficial]. The specific logic for handling collapse/expand states and the pitfalls of null-color removal are documented in community-driven development projects [S1, S2, unofficial].

### History
SVOs were popularized for ray marching in real-time graphics [G]. The specific "placeVoxel" implementation with explicit collapse handling appears in modern web-based voxel editors and tools [S1, S2, unofficial].

### Usage
Used in voxel-based games, CAD tools, and scientific visualization where dynamic modification of volumetric data is required [S1, S2, unofficial].
