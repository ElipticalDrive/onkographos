# Voxel Placement in Octree

Also called: SVO set, Sparse Voxel Octree (SVO) insertion with collapse/expand, octree voxel placement, placeVoxel

## Overview
Voxel Placement in Octree is the fundamental operation for inserting a colored voxel into a Sparse Voxel Octree (SVO) at a specific 3D coordinate [S1, S2, unofficial]. It handles the recursive descent through the tree hierarchy, creating intermediate nodes as necessary, and marking the target leaf node with the voxel's color [S1, unofficial]. Unlike static voxelization which fills a dense grid, this method dynamically grows the sparse structure only where data exists [S2, unofficial]. It is distinguished from sibling methods by its explicit handling of the "collapse/expand" state of internal nodes, ensuring that previously collapsed uniform regions can be correctly subdivided when new non-uniform data is inserted [S1, unofficial].

## How it works

### Inputs and Outputs
*   **Inputs**:
    *   `node`: The current octree node (initially the root).
    *   `nx, ny, nz`: The 3D coordinates of the center of the current node's bounding box.
    *   `size`: The side length of the current node's bounding box.
    *   `depth`: The current recursion depth (0 for root).
    *   `x, y, z`: The 3D coordinates of the voxel to be placed.
    *   `color`: The color (or density/value) of the voxel.
    *   `maxDepth`: The maximum allowed depth of the octree.
*   **Outputs**:
    *   Modifies the octree structure in place: creates child nodes if they do not exist, sets `isLeaf` flags, and assigns `color` to the target leaf.
    *   Returns `void` (or `true`/`false` in some implementations to indicate success or if the position was out of bounds) [S2, unofficial].

### Data Structures
The implementation relies on an `OctreeNode` structure. While exact memory layouts vary by language, the logical fields required are:
*   `isLeaf`: Boolean flag indicating if the node is a leaf.
*   `color`: The value stored in the voxel (e.g., RGBA or density).
*   `children`: An array or pointer to 8 child nodes (indexed 0-7). If `isLeaf` is true or the node is collapsed, this may be `null` or `None`.
*   `position`: (Optional) The 3D center coordinates of the node.
*   `size`: (Optional) The side length of the node.

### Numbered Steps
1.  **Base Case (Max Depth)**: If `depth` equals `maxDepth`, the current node is the target leaf.
    *   Set `node.isLeaf = true`.
    *   Set `node.color = color`.
    *   Set `node.children = null` (ensure no children exist).
    *   Return.
2.  **Boundary Check**: If the voxel position `(x, y, z)` is outside the current node's bounding box defined by `(nx, ny, nz)` and `size`, return immediately (or return `false`) [S2, unofficial].
3.  **Collapse/Expand Check**: If `depth < maxDepth` and `node.isLeaf` is true (indicating a previously collapsed node), the node must be expanded.
    *   Create 8 new child nodes.
    *   Initialize each child as a leaf with `isLeaf = true`.
    *   Assign each child the `node.color` (propagating the uniform value).
    *   Set `node.isLeaf = false`.
    *   Set `node.children` to the array of new children.
    *   *Note: This step prevents runtime errors when accessing `children` on a collapsed node* [S1, unofficial].
4.  **Calculate Child Index**: Determine which of the 8 octants contains the voxel.
    *   Calculate `half = size / 2`.
    *   Determine bit flags based on the voxel's position relative to the node's center:
        *   `ix = 1` if `x >= nx + half`, else `0`.
        *   `iy = 1` if `y >= ny + half`, else `0`.
        *   `iz = 1` if `z >= nz + half`, else `0`.
    *   Compute `childIdx = ix + (iy << 1) + (iz << 2)`.
5.  **Create Child if Missing**: If `node.children[childIdx]` does not exist (is `null`/`None`):
    *   Create a new `OctreeNode`.
    *   Set its position to `(nx + ix*half, ny + iy*half, nz + iz*half)`.
    *   Set its size to `half`.
    *   Assign it to `node.children[childIdx]`.
6.  **Recurse**: Call `placeVoxel` (or `_set`) on `node.children[childIdx]` with `depth + 1`.

### Formulas
*   **Child Index**:
    $$ \text{childIdx} = i_x + 2 \cdot i_y + 4 \cdot i_z $$
    Where $i_x, i_y, i_z \in \{0, 1\}$ are determined by:
    $$ i_x = \begin{cases} 1 & \text{if } x \ge n_x + \frac{s}{2} \\ 0 & \text{otherwise} \end{cases} $$
    (Analogous for $i_y, i_z$ with $n_y, n_z, y, z$).
*   **Half Size**:
    $$ h = \frac{s}{2} $$

### Pseudocode
```python
def placeVoxel(node, nx, ny, nz, size, depth, maxDepth, x, y, z, color):
    # 1. Base Case: Reached maximum depth
    if depth == maxDepth:
        node.isLeaf = True
        node.color = color
        node.children = None
        return

    # 2. Boundary Check: Position outside current node bounds
    # Node bounds are [nx - size/2, nx + size/2], etc.
    half = size / 2
    if not (nx - half <= x <= nx + half and
            ny - half <= y <= ny + half and
            nz - half <= z <= nz + half):
        return False

    # 3. Collapse/Expand Check: If node is currently a leaf but we need to go deeper
    if node.isLeaf:
        # Expand node into 8 children
        node.isLeaf = False
        node.children = [None] * 8
        for i in range(8):
            child = OctreeNode()
            child.isLeaf = True
            child.color = node.color
            # Calculate child position based on index bits
            ix = i & 1
            iy = (i >> 1) & 1
            iz = (i >> 2) & 1
            child.position = (nx + (2*ix - 1)*half, 
                              ny + (2*iy - 1)*half, 
                              nz + (2*iz - 1)*half)
            child.size = half
            node.children[i] = child

    # 4. Calculate Child Index
    ix = 1 if x >= nx + half else 0
    iy = 1 if y >= ny + half else 0
    iz = 1 if z >= nz + half else 0
    childIdx = ix + (iy << 1) + (iz << 2)

    # 5. Create Child if Missing
    if node.children[childIdx] is None:
        child = OctreeNode()
        child.position = (nx + (2*ix - 1)*half, 
                          ny + (2*iy - 1)*half, 
                          nz + (2*iz - 1)*half)
        child.size = half
        node.children[childIdx] = child

    # 6. Recurse
    placeVoxel(node.children[childIdx],
               node.children[childIdx].position[0],
               node.children[childIdx].position[1],
               node.children[childIdx].position[2],
               node.children[childIdx].size,
               depth + 1,
               maxDepth,
               x, y, z, color)
    return True
```

### Parameters
*   `maxDepth`: The maximum recursion depth. Typical values depend on the world size and voxel resolution. Not given in the sources.
*   `color`: The data value. Can be a single float (density) or a vector (RGBA).

### Edge Cases and Pitfalls
*   **Collapsed Node Access**: If a `collapse()` operation previously set `children = null` on an internal node (at `depth < maxDepth`), a subsequent `set()` will throw an error when accessing `node.children[childIdx]` [S1, unofficial]. The implementation must check `node.isLeaf` or `!node.children` before descending and expand the node if necessary [S1, unofficial].
*   **Null Color Removal**: Using `set(x, y, z, null)` to remove voxels leaves leaf nodes with `color = null`, which prevents effective pruning/collapsing and can permanently "materialize" empty regions [S1, unofficial]. A dedicated `delete(x, y, z)` function is recommended to remove nodes and prune upward when a branch becomes entirely empty [S1, unofficial].
*   **Out of Bounds**: If the voxel position is outside the current node's bounding box, the function should return early to avoid infinite recursion or invalid memory access [S2, unofficial].

## Subtopics

### Octree-based Mesh Voxelization
*   **What it is**: A method that converts a triangle mesh into a voxel grid using an octree structure.
*   **Difference**: Focuses on rasterizing geometry into voxels rather than inserting individual voxels into a sparse structure.
*   **When to choose**: When starting from a mesh model.
*   **Link**: [Octree-based Mesh Voxelization](3071-octree-based-mesh-voxelization.md)

### Dynamic Sparse Voxel Octree with Morton Codes
*   **What it is**: An SVO implementation that uses Morton codes (Z-order curves) for efficient spatial indexing and traversal.
*   **Difference**: Uses linearized indices for memory layout and traversal, whereas this method uses explicit tree pointers.
*   **When to choose**: When memory locality and cache efficiency are critical, or for out-of-core storage.
*   **Link**: [Dynamic Sparse Voxel Octree with Morton Codes](4099-dynamic-sparse-voxel-octree-with-morton-codes.md)

## Operating characteristics

### Time and Memory Complexity
*   **Time**: $O(D)$ where $D$ is the depth of the octree, as the algorithm traverses one path from root to leaf.
*   **Memory**: $O(N)$ where $N$ is the number of nodes created. Each insertion may create up to $D$ new nodes.

### Measured Performance
*   Not given in the sources.

### Scaling
*   Scales linearly with the number of voxels inserted.
*   Memory usage is proportional to the surface area of the occupied volume in a sparse octree, significantly less than dense grids for thin or complex structures.

### Strengths and Limitations
*   **Strengths**: Efficient storage for sparse data; dynamic growth allows for interactive editing; supports arbitrary resolution via depth.
*   **Limitations**: Pointer overhead per node; potential for fragmentation if not collapsed; recursion depth limits maximum resolution.

### When to Use
*   Use for interactive voxel sculpting, dynamic scene updates, or when memory efficiency is required for sparse volumes.
*   Do not use for dense, fully occupied volumes where a flat array or grid is more efficient.

## Background

### Origin
The method is derived from implementations of Sparse Voxel Octrees (SVO) for real-time rendering and voxel editing. The specific logic for handling collapse/expand states and the pitfalls of null-color removal are documented in community-driven development projects [S1, S2, unofficial].

### History
SVOs were popularized for ray marching in real-time graphics (e.g., by Laine and Karras). The specific "placeVoxel" implementation with explicit collapse handling appears in modern web-based voxel editors and tools [S1, S2, unofficial].

### Usage
Used in voxel-based games, CAD tools, and scientific visualization where dynamic modification of volumetric data is required.
