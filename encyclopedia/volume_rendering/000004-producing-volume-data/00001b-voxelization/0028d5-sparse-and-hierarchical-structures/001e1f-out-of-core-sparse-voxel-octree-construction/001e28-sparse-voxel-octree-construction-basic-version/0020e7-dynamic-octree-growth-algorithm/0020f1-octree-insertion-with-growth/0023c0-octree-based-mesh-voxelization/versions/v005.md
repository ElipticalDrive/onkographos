# Octree-based Mesh Voxelization

Also called: Recursive Octree Voxelization, Sparse Voxel Octree Triangle Filling, Mesh to Sparse Voxel Octree Conversion, Voxelization using octree spatial partitioning

## Overview
Octree-based mesh voxelization converts a 3D triangle mesh into a sparse hierarchical voxel representation by recursively subdividing the mesh's bounding volume into eight equal sub-cubes and marking those intersecting the mesh as active [S1, abstract only][S3, unofficial]. Unlike uniform grid voxelization, which wastes memory on empty space, this method builds a sparse structure where only occupied regions are stored, making it suitable for large or complex geometries [S3, unofficial]. It differs from [Voxel Placement in Octree](3097-voxel-placement-in-octree.md) by focusing on the initial construction from geometry rather than dynamic insertion, and from [Dynamic Sparse Voxel Octree with Morton Codes](4099-dynamic-sparse-voxel-octree-with-morton-codes.md) by using a recursive subdivision approach rather than Morton-code-based spatial hashing for the initial fill [G].

## How it works
**Inputs:** A triangle mesh (vertices, indices), a target `voxelSize`, and optional parameters `currentDepth` (default 6) and `maxDepth` (default 10) [S3, unofficial].
**Outputs:** An Octree structure where leaf nodes represent voxels intersecting the mesh surface [S1, abstract only][S3, unofficial].

**Data Structures:**
The core structure is the `OctreeNode` [S3, unofficial]:
*   `isLeaf` (bool): True if the node has no children.
*   `isActive` (bool): True if the node intersects the mesh.
*   `position` (vec3): The center of the voxel in world space.
*   `size` (vec3): The side length of the voxel (uniform cube).
*   `color` (vec3): Optional attribute (e.g., sampled from mesh) [S3, unofficial].
*   `children` (OctreeNode*[8]): Array of pointers to child nodes. Null if `isLeaf` is true.

**Algorithm Steps:**

1.  **Initialize Bounds:**
    Calculate the aligned center of the mesh bounds to ensure grid alignment [S2, unofficial]:
    $$ octreePos[i] = \text{round}\left(\frac{mesh.bounds.center[i]}{voxelSize}\right) \times voxelSize $$
    Calculate the required size to cover the mesh, rounded up to the next power of two multiple of `voxelSize` [S2, unofficial]:
    $$ octreeSize = 2 \times \max_i(|max[i] - octreePos[i]|, |min[i] - octreePos[i]|) $$
    $$ octreeSize = \text{nextPowerOfTwo}\left(\text{ceil}\left(\frac{octreeSize}{voxelSize}\right)\right) \times voxelSize $$
    Create the root node with `position = (0,0,0)` and `size = (2,2,2)` (or derived from bounds) [S3, unofficial]. Set `currentDepth` and `maxDepth` [S3, unofficial].

2.  **Process Triangles:**
    Iterate through all triangles in the mesh by stepping through indices in increments of 3 [S3, unofficial]. For each triangle with vertices $v_0, v_1, v_2$:
    a. Transform vertices into the octree's local coordinate space [S2, unofficial]:
       $$ triVerts[v] = (vertices[triIndices[v]] - octreeCenter) \times octreeSizeInv $$
    b. Call the recursive voxelization function: `voxelizeTriangle(root, v0, v1, v2, depth=1)` [S3, unofficial].

3.  **Recursive Voxelization (`voxelizeTriangle`):**
    Given a `node`, triangle vertices $v_0, v_1, v_2$, and current `depth`:
    a. **Calculate Bounding Box:**
       $$ halfSize = node.size \times 0.5 $$
       $$ boxMin = node.position - halfSize $$
       $$ boxMax = node.position + halfSize $$
    b. **Intersection Test:**
       Check if the triangle intersects the node's bounding box [S3, unofficial].
       *Note:* Sources indicate a simplified AABB-AABB overlap test is often used for speed, computing $triMin = \min(v_0, v_1, v_2)$ and $triMax = \max(v_0, v_1, v_2)$, then checking for overlap along axes [S3, unofficial]. This is not a precise triangle-box intersection but a bounding box overlap test [S3, unofficial]. If no intersection, return [S3, unofficial].
    c. **Termination Conditions:**
       If `depth >= currentDepth` (target resolution), mark the node as `isLeaf = true` and `isActive = true`, then return [S3, unofficial].
    d. **Subdivision:**
       If not terminated, mark `isLeaf = false` [S3, unofficial]. Iterate through 8 children ($i = 0 \dots 7$):
       i. Allocate new `OctreeNode` if null.
       ii. Calculate child position offset based on bit flags of $i$:
           - x-offset: $\pm halfSize.x \times 0.5$ if $(i \& 1)$
           - y-offset: $\pm halfSize.y \times 0.5$ if $(i \& 2)$
           - z-offset: $\pm halfSize.z \times 0.5$ if $(i \& 4)$ [S3, unofficial].
       iii. Set child `position` to `node.position + offset` and `size` to `halfSize` [S3, unofficial].
       iv. Recursively call `voxelizeTriangle(child, v0, v1, v2, depth + 1)` [S3, unofficial].

4.  **Attribute Generation (Optional):**
    If attributes (color, normal) are required, interpolate them at the voxel's position or use triangle barycentric coordinates to sample vertex attributes (normals, UVs) and texture colors [S2, unofficial]. Encode normals using a standard encoder (e.g., cubic mapping) [S2, unofficial].

**Pseudocode:**
```python
def voxelize_triangle(node, v0, v1, v2, depth, current_depth, max_depth):
    half_size = node.size * 0.5
    box_min = node.position - half_size
    box_max = node.position + half_size

    # Simplified AABB-AABB overlap test
    tri_min = min(v0, v1, v2)
    tri_max = max(v0, v1, v2)
    if tri_min.x > box_max.x or tri_max.x < box_min.x or \
       tri_min.y > box_max.y or tri_max.y < box_min.y or \
       tri_min.z > box_max.z or tri_max.z < box_min.z:
        return

    if depth >= current_depth:
        node.is_leaf = True
        node.is_active = True
        return

    node.is_leaf = False
    for i in range(8):
        if node.children[i] is None:
            node.children[i] = OctreeNode()
        offset_x = half_size.x * 0.5 if (i & 1) else -half_size.x * 0.5
        offset_y = half_size.y * 0.5 if (i & 2) else -half_size.y * 0.5
        offset_z = half_size.z * 0.5 if (i & 4) else -half_size.z * 0.5
        child_pos = node.position + vec3(offset_x, offset_y, offset_z)
        node.children[i].position = child_pos
        node.children[i].size = half_size
        voxelize_triangle(node.children[i], v0, v1, v2, depth + 1, current_depth, max_depth)
```

**Pitfalls:**
*   **Intersection Accuracy:** The simplified AABB-AABB test may produce false positives (marking empty voxels as active) if the triangle passes near the corner of the box without intersecting the volume [S3, unofficial].
*   **Watertightness:** For closed meshes, the method can discriminate between inside and outside voxels and include them accordingly [S1, abstract only].

## Subtopics

### Sparse Voxel Octree Construction via Triangle Overlap Testing
A GPU-parallel variant where one thread is allocated per triangle [S4]. It determines the triangle's bounding box and checks for overlap with Sparse Grid (SG) voxel centers in the yz plane [S4]. It derives the yz range of level-0 tiles, sets up edge functions, and loops over tiles to check for overlap [S4]. If an active tile is found, it loops over 4x4 SG voxel columns, projects centers onto the triangle plane to find the first voxel to flip, and uses atomic XOR operations to flip voxels in the column [S4]. Navigation uses x-neighbor pointers and Morton code ancestor derivation for fast access [S4].

### Octree-Based Sparse Solid Voxelization
A method that creates a space-efficient representation directly from the mesh without an intermediate full voxelization [S4]. Finest-level voxels are stored only near the boundary, while uniform interior/exterior regions use coarser-level voxels [S4]. This enables voxelizations of grid size $4096^3$ (saving memory compared to the 8 GB required for a full bit array) and accelerates ray traversal [S4].

### Mesh to Octree Conversion with Standard Attributes
A variant that converts a mesh into a sparse voxel octree by sampling vertex attributes (normals, UVs, texture colors) at triangle barycentric coordinates [S2, unofficial]. It interpolates UVs and normals using barycentric weights relative to the voxel mesh bounds center, samples texture colors bilinearly, and encodes the normal vector using a standard attribute encoder (cubic mapping) [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Efficient for large meshes due to early rejection of non-intersecting nodes. The simplified AABB test is fast but may overestimate occupancy [S3, unofficial].
*   **Strengths:** Handles arbitrary mesh complexity; memory efficient; supports hierarchical attribute storage [S2, unofficial][S4].
*   **Limitations:** Recursive nature can cause stack overflow for very deep trees; simplified intersection tests may lead to "bloated" voxels (false positives) [S2, unofficial][S3, unofficial]. Not suitable for real-time dynamic updates without careful management of tree growth [S2, unofficial].

## Background
We developed a voxelization tool for colored 3D-mesh representations of workpiece geometries that allows for the structured, dimensionality-reducing storage of geometry information and Product Manufacturing Information (PMI) [S1, abstract only]. The recursive octree approach is a standard technique in computer graphics for spatial partitioning, implemented in open-source tools like `model_voxelizer` and Unity-based SVO libraries [S2, unofficial][S3, unofficial]. Parallel GPU variants were introduced to handle unprecedented voxelization sizes (e.g., $4096^3$) by avoiding intermediate full grids [S4].
