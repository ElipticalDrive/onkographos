# Grid-Free Out-Of-Core GPU Voxelization

Also called: Grid-Free Out-Of-Core Voxelization to Sparse Voxel Octrees on GPU

## Overview
This method is the first grid-free, out-of-core GPU voxelization technique that directly generates voxelized data in a Sparse Voxel Octree (SVO) representation without an intermediate grid structure [S1]. It solves the memory limitations of in-core GPU methods and the performance bottlenecks of in-core CPU methods by using parallel triangle voxelization optimized for balanced workload and avoiding atomic operations [S1]. Unlike Baert et al. [S1], it uses triangle sorting instead of subgrid-partitioning and ensures all triangle attributes per voxel are accessible during attribute computation, while unlike Schwarz and Seidel [S1], it creates leaf voxels directly and builds the SVO bottom-up in a single pass to enable out-of-core processing.

## How it works
The method comprises two processing stages: Triangle Stream Processing and Voxel Stream Processing (SVO Creation) [S1].

### Inputs and Outputs
*   **Input:** A set of triangles $\{T_i\}$ and a target voxel resolution (e.g., $8192^3$) [S1].
*   **Output:** A Sparse Voxel Octree (SVO) structure [S1].

### Data Structures
*   **Stitch Queue Buffer:** A buffer introduced to maintain the advancing front of incomplete hierarchy nodes which will be finalized by subsequent batches [S1].
*   **Triangle Batch:** A set of triangles processed in parallel during one iteration [S1].

### Steps

#### 1. Triangle Stream Processing
This stage prepares the triangle set $\{T_i\}$ for efficient parallel batch processing on the GPU [S1].

1.  **Subdivision Scheme:**
    *   **Goal:** Create triangles as homogeneous as possible regarding:
        1.  The number of voxels generated per triangle $N_{vox/tri}(T_i)$ should be equal among all triangles.
        2.  The range of Morton indices $m$ generated for voxels of a triangle should be compact, minimizing the ratio:
            $$ \frac{m_{max}(T_i) - m_{min}(T_i)}{N_{vox/tri}(T_i)} \rightarrow \min! $$
            where $m_{min}(T_i)$ and $m_{max}(T_i)$ denote the minimum and maximal Morton index generated by triangle $T_i$, respectively [S1].
    *   **Constraint:** The subdivision must prevent the trivial solution of 1 voxel per triangle [S1].
    *   **Result:** Improved spatial locality of triangles, voxel handling efficiency, and processing performance on GPU [S1].

2.  **Triangle Sorting:**
    *   Sort the subdivided triangles to achieve voxel prediction.
    *   Determine the position of the triangle in the sorted triangle set for the creation of the SVO.
    *   Estimate how many triangles per iteration can be processed in parallel, defining the term "triangle batch" [S1].

3.  **Sequential Batch Processing:**
    *   Process batches sequentially.
    *   Each batch starts with voxelization and attribute creation [S1].
    *   The method uses conservative voxelization instead of surface voxelization [S1].

#### 2. Voxel Stream Processing (SVO Creation)
This stage builds the SVO hierarchically in a bottom-up manner, starting with leaf nodes [S1].

1.  **Leaf Node Creation:**
    *   Leaf nodes are created directly from the voxelized triangles [S1].
    *   Leaf node attributes are calculated using the current voxel attribute set [S1].
    *   Unlike prior out-of-core CPU methods (Baert et al. [S1]), this method ensures all triangle attributes contributing to a voxel are accessible when calculating the voxel attribute, allowing for proper per-voxel attribute quality (e.g., color and normal) rather than constant per-triangle values [S1].

2.  **Hierarchical Bottom-Up Construction:**
    *   On higher hierarchy levels, nodes are created only if all attribute information from their descendants is available [S1].
    *   Incomplete hierarchy nodes are maintained in the **stitch queue buffer** [S1].

3.  **Finalization:**
    *   The creation of the SVO is finished on the CPU by iterating over all remaining nodes in the stitch queue buffer after all batches have been processed [S1].

### Edge Cases and Pitfalls
*   **Attribute Handling:** Prior out-of-core CPU methods (Baert et al. [S1]) created attributes as constant per-triangle values where only the first processed triangle contributed, restricting per-voxel attribute quality. This method avoids this by ensuring all triangle attributes per voxel are accessible during attribute computation [S1].
*   **Memory Limitations:** In-core GPU methods rapidly reach their memory limit for highly detailed models at high voxel resolution [S1]. In-core CPU methods (Laine and Karras [S1]) are limited by the size of the SVO and triangle count that can fit into memory, especially the root node [S1]. This method avoids these limits by being out-of-core [S1].

## Operating characteristics
*   **Performance:** The San Miguel scene at $8192^3$ resolution is created in 44.3 seconds [S1].
*   **Memory:** The method is out-of-core, allowing processing of scenes with large triangle counts at high resolution without being limited by available GPU or CPU memory for the entire SVO structure [S1].
*   **Parallelism:** Optimized for balanced GPU workload by avoiding atomic operations and using triangle sorting [S1].
*   **Strengths:** Grid-free, out-of-core, proper per-voxel attribute handling, high performance on GPU [S1].
*   **Limitations:** Not given in the sources.

## Background
*   **Origin:** The method was presented by Martin Pätzold and Andreas Kolb from the Computer Graphics and Multimedia Systems Group, University of Siegen, Germany [S1].
*   **History:** It is the first grid-free, out-of-core GPU voxelization method [S1]. It builds on concepts from Baert et al. [S1] (triangle and voxel streaming) and Schwarz and Seidel [S1] (conservative voxelization), but differs by using triangle sorting, grid-free processing, and bottom-up SVO creation [S1].
*   **Usage:** Used for generating SVOs for massive scenes to increase level-of-detail while keeping memory consumption low and rendering performance high [S1].
