# GPU-based SVO Construction and Mipmap Generation

Also called: SVO Mipmap Pipeline, Sparse Voxel Octree Build

## Overview
A GPU compute shader pipeline that constructs a Sparse Voxel Octree (SVO) by allocating nodes per level, writing leaf nodes from a fragment list, and generating mipmaps level-by-level from leaves up to the root [S1, unofficial]. It differs from its parent [Sparse Voxel Octree (SVO) Builder](2617-sparse-voxel-octree-svo-builder.md) by explicitly detailing the dispatch dimensions, constant buffer bindings, and the specific loop structure for mipmap generation, whereas the parent focuses on the high-level logical steps of flagging and memory allocation [G].

## How it works
**Inputs and Outputs**
*   **Input:** A list of voxels (fragments), the total number of SVO levels ($mTotalLevel$), and the total number of voxels ($mTotalVoxel$) [S1, unofficial].
*   **Output:** A fully constructed Sparse Voxel Octree stored in a structured buffer pool, including leaf nodes and internal nodes with mipmap levels [S1, unofficial].

**Data Structures**
*   **mBricksPool:** A structured buffer with 3 Unordered Access View (UAV) channels (`uav[0]`, `uav[1]`, `uav[2]`) used for leaf node and brick data during construction [S1, unofficial].
*   **mNodesPool:** A structured buffer storing node data, accessed via Shader Resource View (SRV) during mipmap generation [S1, unofficial].
*   **mFragmentList:** A structured buffer containing the input voxel list, accessed via SRV [S1, unofficial].
*   **Constant Buffers:** `mCBInfo` (general construction information), `mCBBrickInfo` (brick-specific parameters), and `mCBGroupInfo` (thread group configuration parameters) [S1, unofficial].

**Parameters**
*   **VoxelDispatchUnit:** A divisor for voxel dispatch grid dimensions to control thread group size [S1, unofficial].
*   **mTotalLevel:** The total number of SVO levels, determining loop bounds and dispatch sizes [S1, unofficial].
*   **PAD16(x):** A padding function ensuring $x$ is aligned to a 16-byte boundary or multiple [S1, unofficial].

**Steps**
1.  **Allocate Nodes for Current Level:**
    *   Calculate `sqrNode` as $\sqrt{mNumNodePerLevel[level]}$ [S1, unofficial].
    *   Set thread group dimensions $ddd = \{sqrNode + 1, sqrNode + 1, 1\}$ [S1, unofficial].
    *   Dispatch the allocation compute shader `mAllocCS` with dimensions $ddd$ [S1, unofficial].
    *   Read back the total brick count from `mTotalBrick = brickIndex.getValue()` [S1, unofficial].

2.  **Write Leaf Nodes:**
    *   Calculate `sqrVoxel` as $\sqrt{mTotalVoxel}$ [S1, unofficial].
    *   Calculate voxel dispatch dimensions $dd = \{ \lfloor PAD16(sqrVoxel) / VoxelDispatchUnit \rfloor, \lfloor PAD16(sqrVoxel) / VoxelDispatchUnit \rfloor, 1 \}$ [S1, unofficial].
    *   Bind constant buffers `mCBInfo`, `mCBBrickInfo`, `mCBGroupInfo` [S1, unofficial].
    *   Bind Shader Resource Views (SRVs) for `mFragmentList` and `mNodesPool` [S1, unofficial].
    *   Bind Unordered Access Views (UAVs) for `mBricksPool.uav[0..2]` [S1, unofficial].
    *   Dispatch the leaf write compute shader `mWriteLeafCS` with dimensions $dd$ [S1, unofficial].

3.  **Generate SVO Mipmaps:**
    *   Loop from $level = mTotalLevel - 2$ down to $0$ [S1, unofficial].
    *   For each level:
        *   Calculate `sqrNode` as $\sqrt{mNumNodePerLevel[level]}$ [S1, unofficial].
        *   Set thread group dimensions $ddd = \{sqrNode + 1, sqrNode + 1, 1\}$ [S1, unofficial].
        *   Bind constant buffers `mCBInfo`, `mCBBrickInfo`, `mCBGroupInfo` [S1, unofficial].
        *   Bind SRV for `mNodesPool` [S1, unofficial].
        *   Bind UAVs for `numNode()` and `mBricksPool.uav[0..2]` [S1, unofficial].
        *   Dispatch the mipmap compute shader `mMipmapCS` with dimensions $ddd$ [S1, unofficial].

```python
import math

def gpu_svo_build(mTotalLevel, mTotalVoxel, mNumNodePerLevel, VoxelDispatchUnit):
    # Step 1: Allocate Nodes for Current Level
    level = mTotalLevel - 1
    sqrNode = int(math.sqrt(mNumNodePerLevel[level]))
    ddd = (sqrNode + 1, sqrNode + 1, 1)
    # dispatch_compute_shader(mAllocCS, ddd) -> API call not detailed in source
    # mTotalBrick = brickIndex.getValue() -> API call not detailed in source
    
    # Step 2: Write Leaf Nodes
    sqrVoxel = int(math.sqrt(mTotalVoxel))
    dispatch_x = (pad16(sqrVoxel) // VoxelDispatchUnit)
    dispatch_y = (pad16(sqrVoxel) // VoxelDispatchUnit)
    dd = (dispatch_x, dispatch_y, 1)
    # bind_constant_buffers(mCBInfo, mCBBrickInfo, mCBGroupInfo) -> API call not detailed in source
    # bind_srv(mFragmentList.srv) -> API call not detailed in source
    # bind_srv(mNodesPool.srv) -> API call not detailed in source
    # bind_uav(mBricksPool.uav[0]) -> API call not detailed in source
    # bind_uav(mBricksPool.uav[1]) -> API call not detailed in source
    # bind_uav(mBricksPool.uav[2]) -> API call not detailed in source
    # dispatch_compute_shader(mWriteLeafCS, dd) -> API call not detailed in source
    
    # Step 3: Generate SVO Mipmaps
    for level in range(mTotalLevel - 2, -1, -1):
        sqrNode = int(math.sqrt(mNumNodePerLevel[level]))
        ddd = (sqrNode + 1, sqrNode + 1, 1)
        # bind_constant_buffers(mCBInfo, mCBBrickInfo, mCBGroupInfo) -> API call not detailed in source
        # bind_srv(mNodesPool.srv) -> API call not detailed in source
        # bind_uav(numNode()) -> API call not detailed in source
        # bind_uav(mBricksPool.uav[0]) -> API call not detailed in source
        # bind_uav(mBricksPool.uav[1]) -> API call not detailed in source
        # bind_uav(mBricksPool.uav[2]) -> API call not detailed in source
        # dispatch_compute_shader(mMipmapCS, ddd) -> API call not detailed in source

def pad16(x):
    """Align x to the next multiple of 16."""
    return ((x + 15) // 16) * 16
```

**Edge Cases and Pitfalls**
*   **Thread Group Dimensions:** Must account for padding and unit division to avoid out-of-bounds dispatches. The code uses `PAD16(sqrVoxel) / VoxelDispatchUnit` to align and scale the dispatch grid [S1, unofficial].
*   **Precision:** Square roots of node counts per level must be handled carefully to ensure integer dimensions for dispatch grids [G].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of nodes and voxels, as each node/voxel is processed by a thread group [G]. The mipmap generation is $O(N)$ where $N$ is the number of internal nodes [G].
*   **Memory Complexity:** Proportional to the size of the SVO, stored in `mBricksPool` and `mNodesPool` [S1, unofficial].
*   **Measured Performance:** Not given in the sources [S1, unofficial].
*   **Scaling:** Scales with GPU compute capabilities. The use of thread groups allows for parallel processing of nodes and voxels [G].
*   **Strengths:** Efficient parallel construction on GPU; explicit control over dispatch dimensions [G].
*   **Limitations:** Requires careful tuning of `VoxelDispatchUnit` and padding. Dependent on specific D3D11 API calls in the source implementation [S1, unofficial].
*   **When to use:** When constructing large SVOs on GPU is required and the input is a list of voxels [G].
*   **When not to use:** For small datasets where CPU construction might be simpler; if the hardware does not support the required compute shader features [G].
