# Sparse Voxel Octree (SVO) Builder

Also called: SVO Builder, BuildSVO, SVO construction, Sparse Voxel Octree (SVO) Construction, Voxel-to-SVO Builder

## Overview
The Sparse Voxel Octree (SVO) Builder constructs a hierarchical Sparse Voxel Octree from a flat list of voxelized geometry, typically using GPU compute shaders or CPU parallel processing. It solves the problem of converting dense voxel grids into a compact, memory-efficient hierarchical structure suitable for ray tracing, voxel cone tracing, or pathfinding. Unlike its sibling [Brute Force SVO Construction](1704-brute-force-svo-construction.md) which may use less optimized memory layouts, or [Out-of-Core SVO Construction via Morton Order](1885-out-of-core-svo-construction-via-morton-order.md) which prioritizes disk I/O, the SVO Builder focuses on in-core hierarchical aggregation. It differs from [Sparse Voxel Octree Construction (Optimized Version)](1900-sparse-voxel-octree-construction-optimized-version.md) by using a specific level-by-level flagging and allocation strategy rather than Morton code sorting or queue-based collapse. It builds on the principles of [Sparse Voxel Octree Construction (Basic Version)](1694-sparse-voxel-octree-construction-basic-version.md) but implements the aggregation via explicit shader stages or parallel tasks.

## How it works
The method constructs the SVO by grouping voxels into leaf blocks, iteratively building parent layers up to a power-of-two bounding volume, and establishing parent and neighbor pointers. The implementation varies slightly between CPU-based (Rust/Bevy) and GPU-based (Compute Shader) approaches, but the logical flow is consistent.

### Inputs and Outputs
**Inputs:**
- A list of voxelized meshes, represented as a flat list of voxel coordinates (e.g., `Vec<IVec3>` or `voxel_list`).
- `voxel_size`: Physical size of a single voxel in world space [S2, unofficial].
- `min`, `max`: Bounding box in voxel coordinates, computed as `(world_min / voxel_size).floor()` and `(world_max / voxel_size).ceil()` [S2, unofficial]. If input meshes fall outside user-specified bounds, the builder automatically expands `min`/`max` to include them [S2, unofficial].
- `maxDepth`: Maximum octree subdivision depth [S3, S4, unofficial].

**Outputs:**
- A `SparseVoxelOctree` structure containing:
  - `origin`: The minimum voxel coordinate `IVec3` [S2, unofficial].
  - `layers`: A vector of vectors, where each inner vector represents a depth level of the octree [S2, unofficial].
  - `leafs`: A list of leaf nodes (often `CompoundNode` or similar) [S2, unofficial].
  - `voxel_size`: The input voxel size [S2, unofficial].
- Alternatively, a flat GPU buffer `_tree` storing node data as `uint32_t` [S3, unofficial].

### Data Structures
**Node Layout (GPU/Flat Array):**
- Stored as `uint32_t` [S3, unofficial].
- **Bits 0-16 (17 bits):** Index of the first child node [S3, unofficial].
- **Bit 17 (1 bit):** Leaf flag. If set, the node is a leaf [S3, unofficial].
- **Empty Node Value:** `0x0000FFFF` (Child index 0, not a leaf) [S3, unofficial].
- **Solid Leaf Node Value:** `0x00004200` (Leaf flag set, specific child index) [S3, unofficial].
- **CPU Struct (`SparseVoxelOctreeNode`):** Contains `position`, `first_child`, `parent`, `neighbors`, `is_leaf`, `layer_index`, `node_index` [S2, unofficial].

**CPU Struct (`SparseVoxelOctreeBuilder`):**
- `voxel_size: f32` [S2, unofficial].
- `meshes: Vec<VoxelizedMesh>` [S2, unofficial].
- `min: IVec3`, `max: IVec3` [S2, unofficial].

### Steps

1. **Initialize Root and Bounds:**
   - Compute bounding box `min` and `max` in voxel coordinates [S2, unofficial].
   - Calculate `origin = min` and `size` (max dimension rounded up to next power of two) [S2, unofficial].
   - Initialize the root node (Level 0). In GPU implementations, clear memory for the first 8 nodes (start=0, count=8) using a `node_init` shader, setting them to empty `0x0000FFFF` [S3, S5, unofficial]. In CPU implementations, initialize the root layer [S2, unofficial].

2. **Build Voxel Fragment List:**
   - Collect all voxels from input meshes into a flat list [S2, unofficial].
   - Group voxels into $4 \times 4 \times 4$ leaf blocks. This is done by aligning coordinates to multiples of 4: `leaf_parent_coords = offset >> 3 << 3` (assuming 4-voxel leaves, though some implementations use 8-voxel blocks for higher levels) [S2, unofficial].
   - Create Level 0 nodes (leaf nodes) from these groups [S2, unofficial].

3. **Iterative Level Construction (Bottom-Up):**
   - Iterate from Level 1 to `resolution - 1` (where `resolution` is $\log_2(\text{size})$) [S5, unofficial].
   - **Tag Nodes:** Execute a `node_flag` shader (or CPU equivalent) to determine which nodes at the current level are internal (have children) or leaves. This binds the octree buffer and the voxel list [S5, unofficial].
   - **Allocate Memory:** Execute a `node_alloc` shader to allocate memory for the children of the internal nodes identified. This uses an atomic counter to track the number of allocated nodes. The output start address is `alloc_start`, and the count of new nodes is `alloc_count * 8` [S5, unofficial].
   - **Initialize Allocated Nodes:** Clear the memory for newly allocated nodes using the `node_init` shader, setting them to empty `0x0000FFFF` [S3, S5, unofficial].
   - **Update State:** Set `start = alloc_start`, `count = alloc_count * 8`, and `alloc_start = start + count` for the next iteration [S5, unofficial].

4. **Store Leaf Data:**
   - After the loop, execute a `store_leaf` shader (or CPU equivalent) to store leaf node data. This binds the octree buffer and voxel list, dispatching work based on the voxel list size [S5, unofficial].
   - Inject voxel attributes (albedo, normal, etc.) into the leaf nodes. If multiple voxel fragments fall into the same leaf node, average their attribute values [S1, unofficial].

5. **Mipmap Values:**
   - Mipmap node values from bottom to top, level by level, into the interior nodes. This aggregates data (e.g., density, color) from children to parents [S1, unofficial].

6. **Connect Pointers:**
   - **Parent Pointers:** Assign parent pointers to all nodes. For each node, set its parent to the node at the previous level that contains it [S2, unofficial].
   - **Neighbor Pointers:** Connect face-sharing neighbors. For siblings, use pre-defined offset mappings to link adjacent nodes. If a neighbor lacks children, link directly to the neighbor instead of its children [S2, unofficial].

### Pseudocode (CPU Implementation based on [S2, unofficial])

```python
def build_svo(meshes, voxel_size):
    # 1. Collect and Bounds
    voxel_list = []
    for mesh in meshes:
        voxel_list.extend(mesh.get_voxels())
    
    if not voxel_list:
        return SparseVoxelOctree(origin=IVec3(0,0,0), layers=[], leafs=[], voxel_size=voxel_size)
        
    min_coord = min(voxel_list)
    max_coord = max(voxel_list)
    
    # Expand bounds to power of two
    size = max(max_coord.x - min_coord.x, max_coord.y - min_coord.y, max_coord.z - min_coord.z)
    size = next_power_of_two(size)
    origin = min_coord
    
    # 2. Group into Leaf Blocks (4x4x4)
    # Group voxels by their 4-voxel aligned parent coordinate
    leaf_groups = {}
    for v in voxel_list:
        # Align to 4
        gx = (v.x >> 2) << 2
        gy = (v.y >> 2) << 2
        gz = (v.z >> 2) << 2
        key = (gx, gy, gz)
        if key not in leaf_groups:
            leaf_groups[key] = []
        leaf_groups[key].append(v)
        
    layers = []
    current_layer_nodes = []
    
    # Create Level 0 (Leaves)
    for key, voxels in leaf_groups.items():
        node = SparseVoxelOctreeNode(position=key, is_leaf=True)
        node.attributes = average_attributes(voxels) # [S1, unofficial]
        current_layer_nodes.append(node)
        
    layers.append(current_layer_nodes)
    
    # 3. Build Parent Layers
    current_size = 4
    while current_size < size:
        next_size = current_size * 2
        next_layer_nodes = []
        node_map = {} # Map position to node for parent linking
        
        # Group current layer nodes into 2x2x2 blocks
        # Note: Logic simplified; actual implementation uses Morton order or spatial hashing
        for node in current_layer_nodes:
            # Calculate parent position
            parent_pos = (node.position >> 1) << 1 # Align to 2
            
            if parent_pos not in node_map:
                parent_node = SparseVoxelOctreeNode(position=parent_pos, is_leaf=False)
                node_map[parent_pos] = parent_node
                next_layer_nodes.append(parent_node)
            
            parent_node = node_map[parent_pos]
            parent_node.children.append(node)
            node.parent = parent_node
            
        layers.append(next_layer_nodes)
        current_size = next_size
        
    # 4. Connect Neighbors
    for layer in layers:
        connect_neighbors(layer)
        
    return SparseVoxelOctree(origin=origin, layers=layers, leafs=[], voxel_size=voxel_size)
```

### Pseudocode (GPU Implementation based on [S5, unofficial])

```python
# GPU Compute Shader Pipeline
def build_svo_gpu(voxel_list, resolution):
    # 1. Init Root
    node_init(start=0, count=8, value=0x0000FFFF)
    
    start = 0
    count = 8
    alloc_start = 8
    
    for level in range(1, resolution):
        # 2. Flag Internal Nodes
        node_flag(octree_buffer, voxel_list, start, count)
        
        # 3. Allocate Children
        alloc_start, alloc_count = node_alloc(octree_buffer, start, count)
        
        # 4. Init New Nodes
        node_init(start=alloc_start, count=alloc_count * 8, value=0x0000FFFF)
        
        # 5. Update State
        start = alloc_start
        count = alloc_count * 8
        alloc_start = start + count
        
    # 6. Store Leaves
    store_leaf(octree_buffer, voxel_list)
    
    # 7. Mipmap
    mipmap_levels(octree_buffer, resolution)
```

### Parameters
- `voxel_size`: Physical size of a voxel. Typical values depend on scene scale [S2, unofficial].
- `maxDepth`: Maximum subdivision depth. Typical value not specified in sources, but determines when leaf nodes are created [S3, S4, unofficial].
- `SVOObstacle`: Custom collision trace channel used exclusively for occupancy testing; default response is Ignore [S4, unofficial].

### Edge Cases and Pitfalls
- **Empty Input:** If the voxel list is empty, `get_min_max` returns `(IVec3::ZERO, IVec3::ZERO)`. `get_origin_and_size` handles `min == max` by returning `(min, 1)` [S2, unofficial].
- **Bounds Expansion:** If input meshes fall outside specified bounds, the builder expands `min`/`max` to include them, then extends to a power of two [S2, unofficial].
- **Layer Validation:** Each layer's node count must be a multiple of 8. Positions must follow `OFFSETS_IN_MORTON_CODE_ORDER` relative to the first child. Fails if grouping is incorrect [S2, unofficial].
- **Missing Neighbors:** If a neighbor lacks children, the current node's children link directly to the neighbor instead of its children [S2, unofficial].
- **Work Imbalance:** In parallel implementations, SVO sparsity can cause work imbalance. Mitigated by using "Unbalanced" scheduling [S4, unofficial].
- **Precision:** Node indices are stored in 17 bits, limiting the maximum number of nodes to $2^{17}$ per parent [S3, unofficial].

## Subtopics

### [GPU-based Octree Generation](5332-gpu-based-octree-generation.md)
Generates a hierarchical octree directly on the GPU by partitioning the input volume into fixed-size cubes of $32 \times 32 \times 32$ voxels. Unlike standard SVOs that only subdivide non-empty regions, this approach uniformly subdivides the entire volume space down to the minimum node size, simplifying compute shader logic by avoiding dynamic branching for empty regions. It constructs a pre-allocated array-based octree by mapping every non-empty voxel to a hierarchical path.

### [Sparse Octree Voxelization Performance](9137-sparse-octree-voxelization-performance.md)
Documents the performance characteristics and implementation details of the SVO construction method used for GPU-based voxelization. It addresses the problem of efficiently converting triangle meshes into a compact hierarchical voxel representation for real-time global illumination. Unlike in-core CPU methods or grid-based GPU approaches, this method generates the SVO directly on the GPU, optimizing for parallel triangle processing and minimizing atomic contention. It is distinct from [Grid-Free Out-Of-Core GPU Voxelization](11494-grid-free-out-of-core-gpu-voxelization.md) by its reliance on preallocated buffers and specific atomic merging strategies for fragment consolidation.

### [GPU-based SVO Construction and Mipmap Generation](16487-gpu-based-svo-construction-and-mipmap-generation.md)
A GPU compute shader pipeline that constructs a Sparse Voxel Octree (SVO) by allocating nodes per level, writing leaf nodes from a fragment list, and generating mipmaps level-by-level from leaves up to the root. It differs from its parent [Sparse Voxel Octree (SVO) Builder](2617-sparse-voxel-octree-svo-builder.md) by explicitly detailing the dispatch dimensions, constant buffer bindings, and the specific loop structure for mipmap generation, whereas the parent focuses on the high-level logical steps of flagging and memory allocation.

## Operating characteristics
- **Time Complexity:** Linear in the number of input voxels for collection and leaf grouping. Iterative layer construction scales with tree depth ($\log_2(\text{size})$) [S2, unofficial]. Parent/neighbor filling scales linearly with total node count [S2, unofficial].
- **Memory Complexity:** Proportional to the number of nodes in the octree. The flat array `_tree` stores nodes as `uint32_t`, with 17 bits for child index and 1 bit for leaf flag [S3, unofficial].
- **Performance:** One of the goals of SVO is to reduce memory consumption compared to dense voxel grids [S1, unofficial].
- **Strengths:** Compact representation of sparse geometry; efficient for ray tracing and pathfinding due to hierarchical structure [S2, unofficial].
- **Limitations:** Construction can be complex; requires careful handling of bounds and neighbor linking [S2, unofficial]. Parallel implementation requires careful scheduling to avoid work imbalance [S4, unofficial].
- **When to Use:** When memory efficiency is critical and the geometry is sparse. Suitable for real-time global illumination (voxel cone tracing) and pathfinding [S1, S2, unofficial].
- **When Not to Use:** For dense, fully occupied volumes where a simple 3D array is more efficient. For very small scenes where the overhead of hierarchical construction outweighs benefits.

## Background
- **Origin:** Based on the method described in Chapter 22 of *OpenGL Insights* by Cyril Crassin and Simon Green [S1, unofficial]. Also based on the algorithm described in *3D Flight Navigation Using Sparse Voxel Octrees* [S2, unofficial].
- **History:** The SVO Builder is a standard technique for constructing hierarchical voxel structures. It has been implemented in various forms for CPU (e.g., `svo-rs` for Bevy engine) and GPU (compute shaders) environments [S2, S5, unofficial].
- **Usage:** Used in the `svo-rs` Rust crate for Bevy engine integration, relying on external `pathfinding` crate for A* traversal [S2, unofficial]. Also used in UE5 tutorials for 3D pathfinding [S4, unofficial].
