# GPU-based SVO Construction and Mipmap Generation

Also called: SVO Mipmap Pipeline, Sparse Voxel Octree Build

## Overview
A GPU compute shader pipeline that constructs a Sparse Voxel Octree (SVO) by allocating nodes per level, writing leaf nodes from a fragment list, and generating mipmaps level-by-level from leaves up to the root. It differs from its parent [Sparse Voxel Octree (SVO) Builder](2617-sparse-voxel-octree-svo-builder.md) by explicitly detailing the dispatch dimensions, constant buffer bindings, and the specific loop structure for mipmap generation, whereas the parent focuses on the high-level logical steps of flagging and memory allocation.

## How it works
**Inputs and Outputs**
*   **Input:** A list of voxels (fragments), the total number of SVO levels ($mTotalLevel$), and the total number of voxels ($mTotalVoxel$).
*   **Output:** A fully constructed Sparse Voxel Octree stored in a structured buffer pool, including leaf nodes and internal nodes with mipmap levels.

**Data Structures**
*   **mBricksPool:** A structured buffer with 3 Unordered Access View (UAV) channels (`uav[0]`, `uav[1]`, `uav[2]`) used for leaf node and brick data during construction [S1, unofficial].
*   **mNodesPool:** A structured buffer storing node data, accessed via Shader Resource View (SRV) during mipmap generation [S1, unofficial].
*   **mFragmentList:** A structured buffer containing the input voxel list, accessed via SRV [S1, unofficial].
*   **Constant Buffers:**
    *   `mCBInfo`: General construction information [S1, unofficial].
    *   `mCBBrickInfo`: Brick-specific parameters [S1, unofficial].
    *   `mCBGroupInfo`: Thread group configuration parameters [S1, unofficial].

**Parameters**
*   **VoxelDispatchUnit:** A divisor for voxel dispatch grid dimensions to control thread group size [S1, unofficial].
*   **mTotalLevel:** The total number of SVO levels, determining loop bounds and dispatch sizes [S1, unofficial].
*   **PAD16(x):** A padding function ensuring $x$ is aligned to a 16-byte boundary or multiple [S1, unofficial].

**Steps**
1.  **Allocate Nodes for Current Level:**
    *   Calculate `sqrNode` as $\sqrt{mNumNodePerLevel[level]}$ [S1, unofficial].
    *   Set thread group dimensions $ddd = \{sqrNode + 1, sqrNode + 1, 1\}$ [S1, unofficial].
    *   Dispatch the allocation compute shader `mAllocCS` with dimensions $ddd$ [S1, unofficial].
    *   Read back the total brick count from `mTotalBrick = brickIndex.getValue()` [S1, unofficial].

2.  **Write Leaf Nodes:**
    *   Calculate `sqrVoxel` as $\sqrt{mTotalVoxel}$ [S1, unofficial].
    *   Calculate voxel dispatch dimensions $dd = \{ \lfloor PAD16(sqrVoxel) / VoxelDispatchUnit \rfloor, \lfloor PAD16(sqrVoxel) / VoxelDispatchUnit \rfloor, 1 \}$ [S1, unofficial].
    *   Bind constant buffers `mCBInfo`, `mCBBrickInfo`, `mCBGroupInfo` [S1, unofficial].
    *   Bind Shader Resource Views (SRVs) for `mFragmentList` and `mNodesPool` [S1, unofficial].
    *   Bind Unordered Access Views (UAVs) for `mBricksPool.uav[0..2]` [S1, unofficial].
    *   Dispatch the leaf write compute shader `mWriteLeafCS` with dimensions $dd$ [S1, unofficial].

3.  **Generate SVO Mipmaps:**
    *   Loop from $level = mTotalLevel - 2$ down to $0$ [S1, unofficial].
    *   For each level:
        *   Calculate `sqrNode` as $\sqrt{mNumNodePerLevel[level]}$ [S1, unofficial].
        *   Set thread group dimensions $ddd = \{sqrNode + 1, sqrNode + 1, 1\}$ [S1, unofficial].
        *   Bind constant buffers `mCBInfo`, `mCBBrickInfo`, `mCBGroupInfo` [S1, unofficial].
        *   Bind SRV for `mNodesPool` [S1, unofficial].
        *   Bind UAVs for `numNode()` and `mBricksPool.uav[0..2]` [S1, unofficial].
        *   Dispatch the mipmap compute shader `mMipmapCS` with dimensions $ddd$ [S1, unofficial].

**Pseudocode**
```python
def gpu_svo_build(mTotalLevel, mTotalVoxel, mNumNodePerLevel, VoxelDispatchUnit):
    # Step 1: Allocate Nodes for Current Level
    # Note: The source implies this is done per level or for a specific level context.
    # We assume level is provided or iterated. Based on S1, this step is distinct from mipmap generation.
    # However, S1 lists "Allocate nodes for the current level" then "Write leaf nodes" then "Generate mipmaps".
    # It is ambiguous if "current level" in step 1 refers to the leaf level or a specific allocation phase.
    # Given the parent article mentions "level-by-level", we assume Step 1 is for the leaf level allocation.
    
    level = mTotalLevel - 1  # Assuming leaf level is the top level in this context or specific allocation phase
    sqrNode = int(math.sqrt(mNumNodePerLevel[level]))
    ddd = (sqrNode + 1, sqrNode + 1, 1)
    
    # Dispatch mAllocCS
    dispatch_compute_shader(mAllocCS, ddd)
    
    # Read back total brick count
    mTotalBrick = brickIndex.getValue()
    
    # Step 2: Write Leaf Nodes
    sqrVoxel = int(math.sqrt(mTotalVoxel))
    # PAD16 is assumed to be a function that aligns to 16. 
    # The division is integer division.
    dispatch_x = (pad16(sqrVoxel) // VoxelDispatchUnit)
    dispatch_y = (pad16(sqrVoxel) // VoxelDispatchUnit)
    dd = (dispatch_x, dispatch_y, 1)
    
    bind_constant_buffers(mCBInfo, mCBBrickInfo, mCBGroupInfo)
    bind_srv(mFragmentList.srv)
    bind_srv(mNodesPool.srv)
    bind_uav(mBricksPool.uav[0])
    bind_uav(mBricksPool.uav[1])
    bind_uav(mBricksPool.uav[2])
    
    # Dispatch mWriteLeafCS
    dispatch_compute_shader(mWriteLeafCS, dd)
    
    # Step 3: Generate SVO Mipmaps
    for level in range(mTotalLevel - 2, -1, -1):
        sqrNode = int(math.sqrt(mNumNodePerLevel[level]))
        ddd = (sqrNode + 1, sqrNode + 1, 1)
        
        bind_constant_buffers(mCBInfo, mCBBrickInfo, mCBGroupInfo)
        bind_srv(mNodesPool.srv)
        bind_uav(numNode())
        bind_uav(mBricksPool.uav[0])
        bind_uav(mBricksPool.uav[1])
        bind_uav(mBricksPool.uav[2])
        
        # Dispatch mMipmapCS
        dispatch_compute_shader(mMipmapCS, ddd)

def pad16(x):
    """Align x to the next multiple of 16."""
    return ((x + 15) // 16) * 16
```

**Edge Cases and Pitfalls**
*   **Thread Group Dimensions:** Must account for padding and unit division to avoid out-of-bounds dispatches. The code uses `PAD16(sqrVoxel) / VoxelDispatchUnit` to align and scale the dispatch grid [S1, unofficial].
*   **Precision:** Square roots of node counts per level must be handled carefully to ensure integer dimensions for dispatch grids.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of nodes and voxels, as each node/voxel is processed by a thread group. The mipmap generation is $O(N)$ where $N$ is the number of internal nodes.
*   **Memory Complexity:** Proportional to the size of the SVO, stored in `mBricksPool` and `mNodesPool`.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with GPU compute capabilities. The use of thread groups allows for parallel processing of nodes and voxels.
*   **Strengths:** Efficient parallel construction on GPU; explicit control over dispatch dimensions.
*   **Limitations:** Requires careful tuning of `VoxelDispatchUnit` and padding. Dependent on specific D3D11 API calls in the source implementation.
*   **When to use:** When constructing large SVOs on GPU is required and the input is a list of voxels.
*   **When not to use:** For small datasets where CPU construction might be simpler; if the hardware does not support the required compute shader features.

This method is derived from the `SVODemo` project, an unofficial implementation of Sparse Voxel Octree construction. It is part of a pipeline that builds upon the basic SVO builder algorithm.
