# Out-of-Core Sparse Voxel Octree Construction

Also called: Out-of-core SVO construction, Streaming SVO construction

## Overview
This method constructs a sparse voxel octree (SVO) from a triangle mesh while keeping memory usage logarithmic in the size of the SVO, by processing an intermediate high-resolution 3D voxel grid in Morton order in a streaming manner [S1]. It differs from in-core methods like [Laine and Karras 2010a] because the input is consumed and output is produced in a streaming manner with logarithmic memory usage [S1]. It builds on [Sparse and Hierarchical Structures](4391-sparse-and-hierarchical-structures.md) [G].

## How it works
The algorithm consists of two sequential subprocesses: (1) voxelization, which consumes a triangle mesh and produces an intermediate high-resolution 3D voxel grid in Morton order, and (2) SVO construction, which consumes the voxel grid and produces the output SVO [S1].

### Inputs and Outputs
- **Input**: A triangle mesh (with or without bounding box) and available memory size [S1].
- **Output**: A sparse voxel octree written to disk/stream [S1].
- **Intermediate**: A high-resolution 3D voxel grid in Morton order, stored on disk [S1].

### Data Structures
1. **Subgrid Partition**: A temporary file on disk storing the subset of triangles intersecting a specific subgrid [S1].
2. **Morton Code Stream**: A sequence of integers representing the Morton codes of non-empty cells in the intermediate voxel grid [S1].
3. **Level Queues**: An array of queues, one for each level of the octree [S1]. Each queue holds at most $2^d$ nodes (where $d=3$ for 3D, so max 8 nodes per level) [S1].
4. **SVO Node**: Represents a voxel or internal node, containing the Morton code and child pointers/flags [S1].

### Parameters
- **Grid Resolution**: Power-of-two resolution (e.g., $2048^3$) [S1].
- **Subgrid Size**: Determined by regularly subdividing the high-resolution grid until a subgrid fits in available memory [S1].
- **Queue Size**: At most $2^d$ nodes per level [S1].

### Steps

#### 1. Voxelization Subprocess
1. **Partitioning**: Partition the triangle mesh according to subgrids of the high-resolution 3D voxel grid in a streaming manner by testing each triangle against the bounding box of every subgrid. Store the resulting triangle mesh partitions temporarily on disk [S1].
2. **Subgrid Sizing**: Determine subgrid size by regularly subdividing the high-resolution 3D voxel grid until a subgrid fits in available memory. Use only power-of-two resolutions for the high-resolution 3D voxel grid to ensure subgrids correspond to contiguous ranges in Morton order [S1].
3. **Actual Voxelization**: Sequentially process each subgrid. For each subgrid, consume its corresponding triangle mesh partition in a streaming manner. Voxelize triangles using the 6-separability surface voxelization variant of Huang et al. [1998]. Output only the Morton codes of non-empty cells, not boolean values for all cells [S1].
4. **Output Order**: Ensure subgrids are processed in Morton order so that the output of the voxelization subprocess is the intermediate high-resolution 3D voxel grid in Morton order [S1].

#### 2. SVO Construction (Basic Version)
The construction process reads the Morton code stream and builds the octree bottom-up using queues [S1].

1. **Initialize**: Create an array of empty queues, one for each level of the octree (from leaf level up to root level) [S1].
2. **Read Leaf Nodes**: Read cells with Morton codes corresponding to the current level's leaf nodes from the input and store them in the queue for that level [S1].
3. **Create Parent Nodes**: When a parent node's children (all nodes in the current level's queue) are processed, create an internal node with the parent's Morton code. Store this internal node in the queue of the parent's level. Record the parent-child relation. Write all non-empty nodes currently in the child's queue to the output. Clear the child's queue [S1].
4. **Repeat**: Repeat reading leaf nodes and creating parent nodes level by level until the root is processed. Finally, write the root node to output and clear the root's queue [S1].

### Pseudocode

```python
import math
from collections import deque

def out_of_core_svo_construction(morton_code_stream, grid_resolution):
    """
    Constructs an SVO from a Morton code stream using bottom-up queue processing.
    Args:
        morton_code_stream: Iterator yielding Morton codes of non-empty leaf cells in Morton order.
        grid_resolution: Power-of-two resolution of the intermediate voxel grid (e.g., 2048).
    Returns:
        None (writes SVO nodes to output stream/file).
    """
    num_levels = int(math.log2(grid_resolution)) + 1
    queues = [deque() for _ in range(num_levels)]
    current_level = num_levels - 1

    for morton_code in morton_code_stream:
        queues[current_level].append(morton_code)
        if len(queues[current_level]) == 8:
            children = [queues[current_level].popleft() for _ in range(8)]
            parent_code = children[0] >> 3
            # Output children to disk/stream [G]
            # write_node_to_output(children)
            if current_level > 0:
                queues[current_level - 1].append(parent_code)
            else:
                # Root node reached
                # write_node_to_output(parent_code, is_leaf=False) [G]
                pass
            current_level -= 1

    # Drain remaining queues (handles incomplete parents or final root)
    level = current_level
    while level >= 0:
        while queues[level]:
            children = [queues[level].popleft() for _ in range(len(queues[level]))]
            if len(children) == 8:
                parent_code = children[0] >> 3
                # write_node_to_output(children) [G]
                if level > 0:
                    queues[level - 1].append(parent_code)
                else:
                    # write_node_to_output(parent_code, is_leaf=False) [G]
                    pass
                level -= 1
            else:
                # Incomplete parent (empty octants); write remaining as leaves [G]
                # write_node_to_output(children) [G]
                level -= 1
        level -= 1
```

## Subtopics

### Out-of-Core Voxelization with Appearance Data
An extension of the out-of-core SVO construction that handles appearance data (colors, normals, texture coordinates) by interpolating vertex attributes during voxelization and propagating them to higher levels of the octree, provided the data is available locally [S1].

### Sparse-Voxel-Octree (SVO) Voxelization
A variant of voxel cone tracing that uses a Sparse-Voxel-Octree (SVO) instead of a regular 3D texture to store lighting data, reducing GPU memory usage by dynamically instantiating nodes [S2, unofficial]. The voxelization procedure for SVO undergoes three rasterization passes, once for each spatial axis [S2, unofficial]. The SVO structure is a tree-like hierarchy where each internal node has exactly eight children (octants), with one node representing a voxel and its children representing the subdivision of that voxel into eight others [S2, unofficial]. Storing lighting data in a sparse octree is significantly more challenging to implement and navigate compared to a regular grid [S2, unofficial].

## Operating characteristics
- **Space Complexity**: The SVO construction process has a space complexity that is logarithmic in the size of the sparse voxel octree [S1].
- **Time Complexity**: Not given in the sources [S1].
- **Measured Performance**: Implemented in C++ requiring approximately 1000 lines of code. Tested on a Dell Precision T7500 workstation (Intel Xeon X5650 CPU, 7200 RPM SATA II disk). A grid resolution of $2048^3$ requires 8 GB of memory for the intermediate voxel grid using a 1-byte-per-cell representation [S1].
- **Scaling**: Handles extremely large triangle meshes larger than available memory by streaming input and output [S1].
- **Strengths**: Out-of-core operation, logarithmic memory usage, and good locality of reference (siblings are stored next to each other in the output) [S1].
- **Limitations**: Requires power-of-two resolutions for the high-resolution voxel grid to ensure subgrids correspond to contiguous ranges in Morton order [S1].

## Background
The method was presented to address the lack of scenes available in the form of sparse voxel octrees for rendering systems, which require benefits and drawbacks analysis, storage space requirements, compact data structures, and efficient ray-casting algorithms [S1]. It builds on the concept of hierarchically subdividing a z-shaped space-filling curve, also called z-order, where the Morton code of a cell in an n-dimensional grid is obtained from Cartesian coordinates using bitwise operations [S1]. It is used in rendering systems for managing highly detailed scenes and compact data structures [S1].
