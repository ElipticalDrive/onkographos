# Sparse Voxelization with Hierarchical LoD

Also called: Fabre et al. voxelization, Fast Voxelization and Level of Detail for Microgeometry Rendering

## Overview
This method is a voxelization pipeline designed for high-frequency sparse geometric objects (fibers, hair, thin planes) that processes volumetric data into multiple Levels of Detail (LoD) [S1]. It preserves appearance information by separating geometric/directional data from material properties, aggregating fine sparse details into coarser blocks without rasterization or fixed-size memory allocation for sub-block grids [S1]. It differs from sibling methods by explicitly handling microgeometry via SGGX distribution fitting and asynchronous sample gathering to avoid draw-call ordering artifacts [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A triangle mesh or a collection of Catmull-Rom splines.
*   **Output:** A hierarchical sparse voxel structure with multiple LoDs, where leaf nodes contain aggregated directional data (SGGX) and material properties.

**Data Structures**
1.  **Node Structure (Initial):** Each node holds:
    *   Translation $p=(x,y,z) \in \mathbb{R}^3$ [S1].
    *   Normal $n=(n_x,n_y,n_z) \in \mathbb{R}^3$ with $\|n\|=1$ [S1].
    *   Tangent $t=(t_x,t_y,t_z) \in \mathbb{R}^3$ with $\|t\|=1$ [S1].
    *   Properties ID: A 32-bit integer $id \in \mathbb{Z}^{32}$ [S1].
2.  **Per-Sample Data Structure (Table 1):** Used during generation [S1]:
    *   2nd level index: integer (4 bytes) [S1].
    *   3rd level index: integer (4 bytes) [S1].
    *   Tangent data: u-integer (3x1 bytes) [S1].
    *   Normal data: u-integer (3x1 bytes) [S1].
    *   Material ID: u-integer (4 bytes) [S1].

**Parameters**
*   $Resolution$: Target resolution for the first two levels. Calculated as $Resolution = \sqrt[3]{\prod_{i=1}^3 Resolution_i}$ [S1].
*   $\delta$: Maximum generation radius (e.g., max yarn radius or triangle edge length) [S1].
*   $S_{block}$: Block size [S1].

**Steps**
1.  **Bounding Box and Coordinate Mapping:** Compute global bounding box $B(b_{min}, b_{max})$ and $\delta$. Transform samples from global space to normalized coordinates $P_{normalized} \in [0, Resolution)$ using:
    $$ P_{normalized} = \frac{P - b_{min}}{b_{max} - b_{min}} $$
    $$ P_{volume} = P_{normalized} * Resolution $$
    [S1]

2.  **Block Filtering (GPU Kernel 1):** Generate maximum nodes for first-level blocks. Identify empty blocks by checking control nodes using distance function $D$:
    $$ P_{block} = S_{block} * I_{block} $$
    $$ P_{relative} = \frac{P_{volume} - P_{block}}{S_{block}} - \frac{2}{2} $$
    $$ Q = P_{relative} - \frac{2}{2} $$
    $$ D = \| \max(Q, 0) \| + \min(\max(Q_x, Q_y, Q_z), 0) $$
    Discard nodes where $D \ge \delta^2$ [S1].

3.  **Node Counting:** Initialize a CPU flat array with space for the number of nodes per block and an extra counter. Run a kernel to write the number of valid nodes and their IDs for each block. Copy the mask to CPU to identify empty first-level blocks and generate an axis-aligned stencil for volumetric path tracing [S1].

4.  **Sparse Data Sampling (GPU Kernels 2-4, for non-empty blocks only):**
    *   **Prepare Initial Nodes:** Reorder, duplicate, or generate additional data to ensure consecutive access [S1].
    *   **Subsample:**
        *   *Splines (Catmull-Rom):* Define spline from 4 points, generate additional samples using linear spline interpolation [S1].
        *   *Triangles:* Generate additional points on the surface using barycentric coordinates [S1].
        *   *Distribution:* Use equally distributed samples based on kernel indices (not random). For triangles, weight sample count by relative area to the largest triangle in the model [S1].
    *   **Generate Voxel Nodes:** Create voxel nodes from the new samples [S1].

5.  **Sample Gathering:** Move samples to a grid-like structure. Save only the last sample generated at each voxel asynchronously to avoid implicit ordering of draw calls [S1].

6.  **Block Aggregation:** Order samples by second-level block ID. Use a kernel to detect vector positions where the ID changes to determine block start positions and sample counts [S1].

7.  **Directional Data Fitting:** Compute a distribution histogram for directional data (normals/tangents) at every voxel with density $> 0$. Fit each histogram to an SGGX function [18] to encode the distribution using 6 values [S1].

**Edge Cases and Pitfalls**
*   **Empty Blocks:** Must be identified and discarded early to save memory and computation [S1].
*   **Draw Call Ordering:** Asynchronous saving of the last sample per voxel is required to avoid implicit ordering artifacts from multiple draw calls [S1].
*   **Random Sampling:** Not feasible on GPU for this method; equally distributed samples based on kernel indices must be used [S1].
*   **Memory:** Memory usage scales with the number of samples, not voxel resolution, preventing waste in empty voxels [S1].

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but involves multiple GPU kernels for filtering, sampling, gathering, and aggregation.
*   **Memory Complexity:** Scales with the number of samples generated, not the voxel resolution. Empty voxels do not consume memory [S1].
*   **Strengths:** Efficient for high-frequency sparse objects (fibers, hair). Avoids rasterization and fixed-size sub-block grids. Preserves appearance information via SGGX fitting.
*   **Limitations:** Requires careful handling of sample distribution to avoid discontinuities. SGGX fitting adds computational overhead for directional data [S1].
*   **When to Use:** Microgeometry rendering, fibers, hair, thin planes with texture data [S1].
*   **When Not to Use:** Dense volumetric data where rasterization might be more efficient, or when directional data is not required [S1].
