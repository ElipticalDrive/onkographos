# Solid Voxelization via Octree

Also called: Solid Voxelization using Octree

## Overview
Solid Voxelization via Octree converts a set of 3D line segments (typically derived from triangle meshes) into a solid voxel representation using an octree data structure [S1, unofficial]. This method enables efficient ray intersection testing against the solid volume, distinguishing it from surface-only voxelization by filling the interior [S1, unofficial]. It sets itself apart from siblings like [Out-of-Core Sparse Voxel Octree Construction](1689-out-of-core-sparse-voxel-octree-construction.md) by focusing on a fixed-resolution, fully solid representation optimized for ray tracing rather than adaptive sparse storage for large-scale scenes.

## How it works
The method operates in three phases: Build, Mesh Generation, and Ray Traversal. It maps continuous world-space coordinates to discrete integer grid indices $(i, j, k)$ using the coordinate mapping defined in [Voxelization](12-voxelization.md).

### Inputs and Outputs
- **Input**: A list of 3D line segments (edges of a mesh) and a target `resolution`.
- **Output**: An octree structure representing the solid volume, and optionally a generated mesh for visualization.

### Data Structures
The core data structure is the Octree Node, aligned to 8 bytes [S1, unofficial]:

```cpp
struct Node {
    uint32_t child_offset; // Index to children in a flat array or pointer offset
    uint8_t  child_masks;  // 8 bits, one per child
    bool     full;         // True if the node is completely filled
};
```

The `child_masks` field uses 8 bits to represent the occupancy of the 8 children. The bit order corresponds to the Morton code (Z-order curve) indices: 000, 001, 011, 010, 110, 111, 101, 100 [S1, unofficial]. The `full` flag indicates if the node is completely filled with solid material.

For mesh generation, a unit cube is defined by 8 vertices at $(0,0,0)$ to $(1,1,1)$ and 12 triangles (36 indices) forming the surface [S1, unofficial].

### Parameters
- **resolution**: The side length of the bounding box in voxels. Must be a power of two between 2 and 4096 inclusive [S1, unofficial]. Typical values in examples are 512 [S1, unofficial].

### Steps

#### 1. Build Phase
Recursively build the octree from the input segments.
1.  **Base Case (Empty)**: If the list of segments intersecting the current node's bounding box is empty, mark the node as empty.
2.  **Base Case (Leaf)**: If the current resolution is 2 (leaf level), determine the occupancy of the 8 sub-cubes. A sub-cube is occupied if any segment intersects its Z-range (or more generally, intersects the sub-cube volume) [S1, unofficial]. Set the corresponding bit in `child_masks`.
3.  **Recursive Step**: If resolution > 2:
    -   Partition the segments by X, then Y, then Z coordinates to distribute them to the 8 children [S1, unofficial].
    -   Recursively build each child.
    -   Set `child_masks` based on which children are non-empty.
    -   If all 8 children are full, mark the current node as `full = true`.

#### 2. Mesh Generation Phase
Traverse the octree to generate a triangle mesh for visualization.
1.  **Full Node**: If the node is marked `full`, add a single cube mesh for the node's bounding box.
2.  **Leaf Node (resolution 2)**: Iterate over the 8 children. If a child's mask bit is set, add a unit cube mesh at the child's offset.
3.  **Inner Node**: Iterate over the 8 children. If a child's mask bit is set, recursively traverse the child node at the offset `current_offset + child_index` [S1, unofficial].

#### 3. Ray Traversal Phase
Use a stack-based traversal for ray intersection testing.
1.  Start with the root node on the stack.
2.  For each node popped from the stack:
    -   Compute the intersection of the ray with the node's bounding box.
    -   If the hit is valid and closer than the current closest hit:
        -   If the node is `full`, update the closest hit to the entry point of the box.
        -   If the node is a leaf, check the 8 sub-cubes for intersection.
        -   If the node is inner, push its children (those with set mask bits) onto the stack [S1, unofficial].

### Pseudocode

```python
# Box Intersection using Akari's method (simplified slab method)
# Returns true if ray intersects box, updates t_min and t_max
def intersect_box_akari(ray_origin, ray_direction, box_min, box_max):
    t_min = -float('inf')
    t_max = float('inf')
    
    for i in range(3):
        if ray_direction[i] == 0:
            if ray_origin[i] < box_min[i] or ray_origin[i] > box_max[i]:
                return False
        else:
            t1 = (box_min[i] - ray_origin[i]) / ray_direction[i]
            t2 = (box_max[i] - ray_origin[i]) / ray_direction[i]
            t_enter = min(t1, t2)
            t_exit = max(t1, t2)
            t_min = max(t_min, t_enter)
            t_max = min(t_max, t_exit)
            
    return t_min <= t_max

# Build Phase
def build_octree(segments, node_bounds, resolution):
    if not segments:
        return Node(child_offset=0, child_masks=0, full=False)
    
    if resolution == 2:
        # Leaf level: check occupancy of 8 sub-cubes
        masks = 0
        for i in range(8):
            sub_cube_bounds = get_sub_cube_bounds(node_bounds, i)
            if any(segment_intersects_box(seg, sub_cube_bounds) for seg in segments):
                masks |= (1 << i)
        return Node(child_offset=0, child_masks=masks, full=False)
    
    # Recursive step
    children = []
    for i in range(8):
        child_bounds = get_sub_cube_bounds(node_bounds, i)
        child_segments = partition_segments(segments, child_bounds)
        children.append(build_octree(child_segments, child_bounds, resolution - 1))
    
    # Pack children into flat array and set masks
    masks = 0
    for i, child in enumerate(children):
        if child.child_masks != 0 or child.full:
            masks |= (1 << i)
            
    # Determine if full
    is_full = all(child.full for child in children)
    
    return Node(child_offset=0, child_masks=masks, full=is_full)

# Ray Traversal Phase
def traverse_ray(ray, node, stack, closest_hit):
    if not node or node.child_masks == 0 and not node.full:
        return
        
    if intersect_box_akari(ray.origin, ray.direction, node.bounds_min, node.bounds_max):
        if node.full:
            # Update closest hit with entry point
            t_hit = get_entry_t(ray, node.bounds_min, node.bounds_max)
            if t_hit < closest_hit.t:
                closest_hit.t = t_hit
                closest_hit.point = ray.origin + ray.direction * t_hit
        elif node.child_masks != 0:
            # Push children to stack
            for i in range(8):
                if (node.child_masks >> i) & 1:
                    child = get_child(node, i)
                    if child:
                        stack.push(child)
```

### Edge Cases and Pitfalls
-   **Floating Point Comparison**: Box intersection uses a tolerance of $10^{-5}$ to determine which face was hit [S1, unofficial].
-   **Resolution Constraints**: Resolution must be a power of two between 2 and 4096 [S1, unofficial].
-   **Two Box Intersection Methods**: Two methods are implemented: `intersect_box_akari` (simpler, uses component-wise max/min) and `intersect_box` (more complex, validates intersection points against bounding box faces explicitly) [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: Build phase is $O(N \log R)$ where $N$ is the number of segments and $R$ is the resolution. Ray traversal is $O(\log R)$ for sparse regions and $O(1)$ for full nodes.
-   **Memory Complexity**: $O(R^3)$ in the worst case for a full volume, but significantly less for sparse objects due to the octree structure.
-   **Strengths**: Efficient ray intersection for solid volumes; simple implementation; good for small to medium resolution scenes.
-   **Limitations**: Fixed resolution; not suitable for extremely large or highly detailed scenes without out-of-core techniques; memory usage can be high for dense volumes.
-   **When to Use**: When ray tracing solid volumes is required and the scene size is manageable within memory.
-   **When Not to Use**: For very large scenes requiring adaptive resolution or out-of-core processing.
