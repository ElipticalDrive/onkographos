# Sparse Voxelization into an Octree

Also called: Sparse Octree Voxelization, Two-Level Voxelization, Voxelization into Octree

## Overview
Sparse Voxelization into an Octree stores only voxels intersected by mesh triangles in a sparse-voxel octree, avoiding the memory overhead of a full grid for large and complex scenes [S2, unofficial]. It differs from its parent method, [Sparse Sampling / Sparse Voxel Grid Generation](4588-sparse-sampling-sparse-voxel-grid-generation.md), which marks every 5th voxel as occupied for testing, by dynamically constructing a hierarchical tree structure based on actual geometric intersection [S2, unofficial]. It also differs from [Voxelization into a Uniform Grid](4589-voxelization-into-a-uniform-grid.md) by using a pointer-based octree structure that allows for variable resolution and mipmapped interior nodes, enabling efficient traversal and filtering [S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A triangle mesh representing the scene geometry [S1].
*   The spatial bounds of the scene (defining the root node) [G].
*   The maximum octree depth (defining the finest resolution) [G].

**Outputs:**
*   A sparse-voxel octree stored in linear video memory (the "octree pool") [S2, unofficial].
*   A voxel-fragment list (intermediate data structure) [S2, unofficial].

### Data Structures
**Octree Pool**
*   **Layout:** Linear buffer object in video memory [S2, unofficial].
*   **Grouping:** Nodes are grouped into $2 \times 2 \times 2$ node tiles [S2, unofficial].
*   **Node Content:** Each node stores a single pointer (index into the buffer) pointing to eight child nodes [S2, unofficial].
*   **Values:** Voxel values can be stored directly in nodes or in "bricks" associated with node tiles, stored in a big 3D texture [S2, unofficial]. The structure contains values for all levels, allowing filtered sampling at any resolution [S2, unofficial].

**Voxel-Fragment List**
*   **Layout:** Linear vector of entries in a preallocated buffer object [S2, unofficial].
*   **Entry Content:**
    *   3D coordinates: Encoded in one 32-bit word (10 bits per component, 2 unused bits) [S2, unofficial].
    *   Attributes: Arrays for additional data (e.g., one color per fragment) [S2, unofficial].
*   **Counter:** A separate 32-bit value in a buffer object tracks the index of the next available entry (atomic counter) [S2, unofficial].

### Algorithm Steps
The algorithm builds the octree from top to bottom, one level at a time, starting from the 1-voxel root node [S2, unofficial].

1.  **Voxel-Fragment List Construction:**
    *   Voxelize the input mesh only once at the maximum resolution (deepest octree level) [S2, unofficial].
    *   Allocate one thread per triangle [S1].
    *   Perform 2D rasterization in the yz plane to determine the bounding box and check for overlap with any Sparse Grid (SG) voxel center [S1].
    *   Derive the yz range of level-0 voxels (tiles) containing overlapped SG voxel centers [S1].
    *   Set up edge functions for overlap testing [S1].
    *   Loop over tiles and check for triangle overlap [S1].
    *   If an active tile is identified, loop over its $4 \times 4$ SG voxel columns and test their centers for overlap [S1].
    *   If overlap is reported, project the center along the x-axis onto the triangle's plane to derive the x index $\bar{q}$ of the first SG voxel to flip [S1].
    *   Identify the level-0 node containing that voxel [S1].
    *   Flip all voxels in the corresponding column of its voxel sub-grid within the local x-index range $(\bar{q} \mod 4), \dots, 3$ via an atomic xor operation [S1].
    *   Append voxel fragments to the list using an atomic counter (e.g., OpenGL 4.2 `atomicAdd`) to manage the index of the next available entry, allowing concurrent access by thousands of threads [S2, unofficial].
    *   This list is used instead of the triangle mesh to subdivide the octree during building [S2, unofficial].

2.  **Octree Building (Top-Down):**
    *   Start from the 1-voxel root node [S2, unofficial].
    *   For each successive octree level of increasing resolution:
        *   Detect nonempty nodes by voxelizing the scene at the resolutions corresponding to the level's resolution (using the voxel-fragment list) [S2, unofficial].
        *   Create a new tile of $2^3$ subnodes for each nonempty node [S2, unofficial].
        *   Progressively subdivide nonempty nodes (intersected by at least one triangle) [S2, unofficial].

3.  **Value Propagation and Mipmapping:**
    *   Write voxel-fragment values into the leaves of the tree [S2, unofficial].
    *   Mipmap values into the interior nodes [S2, unofficial].
    *   *Solid Voxelization (Optional/Contextual):* If solid voxelization is required, hierarchically propagate bit flips in the +x direction [S1]. If the last bit in a level-0 node's SG voxel column is set, all SG voxels in the same column belonging to nodes in +x direction must be flipped [S1]. This is done by looping over all (even-indexed) level-0 nodes in parallel, identifying those with no level-0 -x neighbor, and navigating along +x-neighbor pointers to propagate flips [S1].

### Node Access and Navigation
*   **Initial Access:** Perform a full descent from the top level [S1].
*   **Intra-Tile Navigation:** Use x-neighbor pointers for fast navigation within a tile [S1].
*   **Inter-Tile Navigation:** When entering a new tile, derive the common ancestor node of the previous and desired node from their Morton codes [S1]. Depending on the ancestor's level, either ascend to this node and then descend, or perform a full descent [S1].

### Pseudocode
```python
def voxelize_mesh_to_list(mesh):
    """
    Step 1: Construct the voxel-fragment list.
    Voxelize mesh once at max resolution. Allocate one thread per triangle.
    """
    for triangle in mesh.triangles:
        # 2D rasterization in yz plane to determine bounding box
        bbox_yz = [min(triangle.y), max(triangle.y), min(triangle.z), max(triangle.z)]
        
        # Check for overlap with any Sparse Grid (SG) voxel center
        if bbox_yz[0] < grid.max_y and bbox_yz[1] > grid.min_y and \
           bbox_yz[2] < grid.max_z and bbox_yz[3] > grid.min_z:
            
            # Derive yz range of level-0 voxels (tiles) containing overlapped SG voxel centers
            tile_min_y = floor(bbox_yz[0] / TILE_SIZE)
            tile_max_y = floor(bbox_yz[1] / TILE_SIZE)
            tile_min_z = floor(bbox_yz[2] / TILE_SIZE)
            tile_max_z = floor(bbox_yz[3] / TILE_SIZE)
            
            # Set up edge functions for overlap testing
            edge_funcs = compute_edge_functions(triangle) # [G] Standard 2D rasterization setup
            
            # Loop over tiles and check for triangle overlap
            for ty in range(tile_min_y, tile_max_y + 1):
                for tz in range(tile_min_z, tile_max_z + 1):
                    tile = get_tile(ty, tz)
                    if evaluate_tile_active(tile, edge_funcs): # [G] Standard edge function evaluation
                        # Loop over its 4x4 SG voxel columns and test their centers for overlap
                        for col in tile.columns_4x4:
                            if ray_triangle_intersect_x(col.center, triangle): # [G] Standard ray-triangle intersection
                                # Project the center along the x-axis onto the triangle's plane
                                # to derive the x index q_bar of the first SG voxel to flip
                                t = plane_intersection_t(col.center, triangle)
                                x_coord = col.center.x + t * triangle.normal.x
                                q_bar = floor(x_coord / VOXEL_SIZE)
                                
                                # Identify the level-0 node containing that voxel
                                level0_node = map_to_level0_node(col.center)
                                
                                # Flip all voxels in the corresponding column of its voxel sub-grid
                                # within the local x-index range (q_bar mod 4), ..., 3 via atomic xor
                                start_local_x = q_bar % 4
                                for local_x in range(start_local_x, 4):
                                    atomic_xor(level0_node.voxel_grid, local_x, col.y, col.z)
                                
                                # Encode fragment coordinates: 10 bits per component, 2 unused bits
                                coord_word = (int(col.center.x) << 20) | (int(col.center.y) << 10) | int(col.center.z)
                                color = get_triangle_color(triangle)
                                
                                # Append voxel fragments to the list using an atomic counter
                                index = atomic_add(fragment_counter, 1)
                                fragment_list[index] = VoxelFragment(coord_word, color)

def build_octree_from_list(fragment_list):
    """
    Step 2 & 3: Build octree top-down using the fragment list.
    """
    root = allocate_node(octree_pool)
    current_level_nodes = [root]
    
    for level in range(1, MAX_DEPTH + 1):
        next_level_nodes = []
        
        # Detect nonempty nodes by voxelizing the scene at the resolutions 
        # corresponding to the level's resolution, using the fragment list
        for node in current_level_nodes:
            if check_node_nonempty(node, fragment_list, level): # [G] Check if any fragment falls within node bounds
                # Create a new tile of 2^3 subnodes for each nonempty node
                children_indices = allocate_tile(octree_pool, 8)
                node.pointer_to_children = children_indices
                
                for i in range(8):
                    child = get_node_at_index(octree_pool, children_indices + i)
                    next_level_nodes.append(child)
        
        current_level_nodes = next_level_nodes

    # Write voxel-fragment values into the leaves of the tree
    scatter_fragments_to_leaves(fragment_list, current_level_nodes) # [G] Scatter fragments to leaf nodes
    # Mipmap values into the interior nodes
    aggregate_values_up_tree(octree_pool) # [G] Interpolate/aggregate values up the tree
```

### Parameters and Typical Values
*   **Bits per coordinate:** 10 bits per component (30 bits total) + 2 unused bits [S2, unofficial].
*   **Tile Size:** $2 \times 2 \times 2$ node tiles [S2, unofficial].
*   **SG Voxel Column Size:** $4 \times 4$ columns within a level-0 tile [S1].
*   **Atomic Operation:** `atomicAdd` for counter, `atomicXor` for voxel flipping [S1][S2, unofficial].

### Edge Cases and Pitfalls
*   **Collision Rate:** Lower resolution voxelization can end up slower than higher resolution due to an increase in the number of collisions encountered per voxel [S2, unofficial].
*   **Precision:** The 10-bit coordinate encoding limits the maximum scene size/resolution. Ensure the scene bounds fit within the 10-bit range ($2^{10} = 1024$ units) or scale appropriately [S2, unofficial].
*   **Atomic Contention:** High triangle counts can lead to contention on the atomic counter and voxel grid updates [G]. Use efficient atomic operations provided by the hardware (e.g., OpenGL 4.2) [S2, unofficial].
*   **Solid Voxelization:** Simple intersection testing may leave holes [G]. Hierarchical propagation of bit flips in the +x direction is required for solid voxelization [S1].

## Operating characteristics
*   **Time Complexity:** The voxel-fragment list construction is $O(T)$ where $T$ is the number of triangles, with parallel execution per triangle [S1][S2, unofficial]. The octree building processes each level sequentially, subdividing nonempty nodes and allocating child tiles [S2, unofficial].
*   **Memory Complexity:** $O(N)$ where $N$ is the number of occupied voxels/nodes. The sparse structure avoids storing empty space [G].
*   **Measured Performance:** On the Stanford Dragon mesh, the voxelization algorithm execution time varies with resolution. At resolution 128, it takes 1.18 ms (RGBA8), while at 512, it takes 1.47 ms. Comparison with VoxelPipe shows times of 1.40 ms and 5.30 ms respectively at 128, and 1.63 ms and 2.07 ms at 512. Times marked with a star in the source correspond to results obtained with hardware `atomicAdd` instead of emulation [S2, unofficial].
*   **Strengths:** Handles large and complex scenes efficiently by storing only intersected voxels. Allows for mipmapped interior nodes, enabling fast filtered sampling at multiple resolutions [S2, unofficial].
*   **Limitations:** Requires atomic operations for concurrent writes, which can be a bottleneck. Lower resolution levels may suffer from higher collision rates, potentially slowing down the process [S2, unofficial].
*   **When to Use:** When memory is a constraint and the scene has sparse geometry [G]. When multi-resolution access is needed for rendering or traversal [G].
*   **When Not to Use:** When the scene is dense and nearly fills the volume, as the overhead of the tree structure may outweigh the benefits [G]. When hardware atomic operations are not available or slow [G].

## Background
The sparse-voxel octree structure is in the spirit of [Laine and Karras 10] and [Crassin et al. 09] [S2, unofficial]. The method was described in the context of OpenGL-based real-time global illumination applications [S2, unofficial]. The voxel-fragment list construction using atomic counters leverages OpenGL 4.2 features [S2, unofficial]. The two-level approach (rasterizing to level-0 nodes and then propagating) was introduced to optimize the voxelization process [S1].
