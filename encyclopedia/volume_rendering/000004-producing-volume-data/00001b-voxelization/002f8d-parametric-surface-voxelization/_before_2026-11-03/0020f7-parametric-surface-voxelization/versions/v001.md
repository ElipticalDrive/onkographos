# Parametric Surface Voxelization
Also called: Parametric field rasterization

## Overview
Parametric surface voxelization is a GPU-based technique that converts parametric surface patches directly into a voxel grid by rasterizing point primitives generated in the parametric domain [S1, unofficial]. It differs from standard triangle rasterization by operating in the 2D parameter space of the surface definition, allowing for the voxelization of complex implicit or free-form surfaces that lack explicit triangular meshes [S1, unofficial]. This method enables real-time voxelization of complex models by leveraging the vertex shader to map 2D texture coordinates to 3D world positions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A parametric surface definition (function $S(u, v)$ mapping 2D parameters to 3D space), a resolution for the voxel grid (worksheet), and a sampling density for the parametric domain.
*   **Output:** A voxel grid (worksheet) where occupied voxels correspond to the surface.

**Data Structures:**
*   **Parametric Boole:** A structured set of 2D points $(u_i, v_i)$ covering the parametric domain $[0,1] \times [0,1]$ (or the specific domain of the patch). These points act as the "vertices" for the rasterization process.
*   **Voxel Grid (Worksheet):** A 3D texture or buffer representing the volume, indexed by integer coordinates $(x, y, z)$.

**Steps:**
1.  **Generate Parametric Points:** Construct a "boodle" (a dense, structured collection) of 2D points that uniformly or adaptively cover the parametric field of the surface patch. Let this set be $P = \{(u_k, v_k)\}$.
2.  **Vertex Shader Processing:** Treat each point $(u_k, v_k)$ in the boodle as a vertex primitive. Pass the $(u, v)$ coordinates as texture coordinates or vertex attributes to the vertex shader.
3.  **3D Position Calculation:** In the vertex shader, evaluate the parametric surface function $S(u, v)$ for each vertex to compute its 3D position $\mathbf{p}_k = (x_k, y_k, z_k)$.
    $$ \mathbf{p}_k = S(u_k, v_k) $$
    Where $S$ is the specific parametric equation (e.g., Bezier, B-spline, or NURBS patch evaluation).
4.  **Transcoding to Worksheet:** Transform the 3D position $\mathbf{p}_k$ into the voxel grid's coordinate system. Determine the integer voxel indices $(i, j, l)$ corresponding to $\mathbf{p}_k$.
    $$ i = \lfloor \frac{x_k - x_{min}}{\Delta x} \rfloor, \quad j = \lfloor \frac{y_k - y_{min}}{\Delta y} \rfloor, \quad l = \lfloor \frac{z_k - z_{min}}{\Delta z} \rfloor $$
    Mark the voxel at $(i, j, l)$ as occupied in the worksheet. This step is performed immediately for each vertex, effectively rasterizing the point cloud generated from the parametric domain into the volume.

**Parameters:**
*   **Sampling Density:** The number of points in the parametric boodle. Higher density reduces gaps but increases computational cost. Not given in the sources.
*   **Voxel Resolution:** The dimensions of the output worksheet. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision in the vertex shader during the evaluation of $S(u, v)$ and the subsequent coordinate transformation can lead to slight inaccuracies in voxel placement.
*   **Boundary Conditions:** The parametric domain boundaries must be handled correctly to ensure the entire surface is covered without over- or under-sampling.
*   **Complex Surfaces:** The method assumes the shader program supports sufficient instruction slots for complex surface evaluations [S1, unofficial].

**Pseudocode:**
```python
# Assume S(u, v) is the parametric surface function
# Assume voxel_grid is a 3D boolean array or bitfield
# Assume resolution is (Nx, Ny, Nz)
# Assume bounds are (x_min, y_min, z_min) and (x_max, y_max, z_max)

def parametric_surface_voxelization(S, resolution, bounds, parametric_resolution):
    x_min, y_min, z_min = bounds[0]
    x_max, y_max, z_max = bounds[1]
    dx = (x_max - x_min) / resolution[0]
    dy = (y_max - y_min) / resolution[1]
    dz = (z_max - z_min) / resolution[2]

    # Step 1: Build a boodle of points covering the parametric field
    # Assuming parametric domain is [0,1]x[0,1]
    u_coords = [i / parametric_resolution for i in range(parametric_resolution + 1)]
    v_coords = [j / parametric_resolution for j in range(parametric_resolution + 1)]
    
    points = []
    for u in u_coords:
        for v in v_coords:
            points.append((u, v))

    # Step 2 & 3: Process each point as a vertex in the vertex shader
    # Step 4: Transcode positions to the worksheet
    for u, v in points:
        # Calculate 3D position
        p = S(u, v)
        x, y, z = p.x, p.y, p.z
        
        # Convert to voxel indices
        ix = int((x - x_min) / dx)
        iy = int((y - y_min) / dy)
        iz = int((z - z_min) / dz)
        
        # Mark voxel as occupied
        # Check bounds to avoid out-of-bounds access
        if 0 <= ix < resolution[0] and 0 <= iy < resolution[1] and 0 <= iz < resolution[2]:
            voxel_grid[ix, iy, iz] = True

    return voxel_grid
```

## Subtopics

### [Recursive Parameter Space Voxelization for Catmull-Clark Subdivision Surfaces](2533-recursive-parameter-space-voxelization-for-catmull-clark-sub.md)
This method converts a free-form object represented by a Catmull-Clark subdivision surface (CCSS) into a voxel grid by recursively subdividing the 2D parameter space of surface patches and sampling 3D points, rather than subdividing 3D object space. It ensures leak-free results for closed objects when a 3D flooding operation is performed by guaranteeing that voxels generated from a single patch satisfy specific N-adjacency properties. Unlike 3D space subdivision techniques which are computationally expensive due to distance computations between 3D points, this method performs subdivision in 2D parameter space, avoiding expensive 3D distance computations.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of points in the parametric boodle and the number of surface patches. The cost is dominated by the evaluation of the parametric surface function $S(u, v)$ for each point.
*   **Memory Complexity:** Linear with respect to the size of the voxel grid and the number of points in the parametric boodle.
*   **Strengths:** Enables real-time voxelization of complex implicit and free-form surfaces; leverages GPU vertex shaders for parallel processing; straightforward implementation for CSG models by combining voxelized components [S1, unofficial].
*   **Limitations:** Requires the surface to be defined parametrically; may produce gaps if the parametric sampling density is insufficient; dependent on the computational capacity of the vertex shader for complex surface evaluations [S1, unofficial].
*   **When to Use:** When dealing with parametric surfaces (e.g., NURBS, Bezier) that need to be voxelized in real-time, especially when traditional triangle-based voxelization is not applicable or efficient.
*   **When Not to Use:** For surfaces defined implicitly by distance fields or for static meshes where pre-computed triangle-based voxelization is more efficient.

## Background
The method was introduced in the context of real-time voxelization for complex models, specifically addressing the challenge of voxelizing parametric surfaces and CSG models [S1, unofficial]. It builds on the idea of using GPU shaders to perform geometric transformations and rasterization in a flexible manner, extending the concept of point-based rasterization to parametric domains. The approach is particularly relevant for applications requiring rapid voxelization of non-polygonal geometry, such as transparent illustration and collision detection in complex scenes [S1, unofficial].
