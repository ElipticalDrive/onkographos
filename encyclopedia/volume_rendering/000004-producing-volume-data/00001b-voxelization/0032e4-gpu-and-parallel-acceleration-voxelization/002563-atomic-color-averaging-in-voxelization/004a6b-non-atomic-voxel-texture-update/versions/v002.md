# Non-Atomic Voxel Texture Update

Also called: Voxel Texture Update (Non-Atomic)

## Overview
This method updates a voxel texture by averaging incoming fragment colors to reduce flickering artifacts, explicitly avoiding floating-point atomic operations [S1, unofficial]. It differs from [Atomic Color Averaging in Voxelization](3529-atomic-color-averaging-in-voxelization.md) by using a read-modify-write sequence instead of hardware atomics [S1, unofficial].

## How it works
**Inputs:** `u_voxelTexture` (3D image texture), `posVoxelSpace` (voxel coordinate), `val` (incoming `vec4` color and alpha), `dim` (voxel grid dimensions).
**Outputs:** Updated `u_voxelTexture`.
**Data Structures:** The voxel texture is a 3D array of `vec4` values, accessed via `imageLoad` and `imageStore` operations [S1, unofficial].
**Steps:**
1. Scale the incoming alpha: `val.a = val.a * (1.0f / 255.0f)` [S1, unofficial].
2. Load the previous voxel value: `prev = imageLoad(u_voxelTexture, ivec3(dim * posVoxelSpace))` [S1, unofficial].
3. Compute the weighted average: `avg = (prev.rgb * prev.a + val.rgb * val.a) / (prev.a + val.a)` [S1, unofficial].
4. Update the value vector: `val = vec4(avg, prev.a + val.a)` [S1, unofficial].
5. Store the result: `imageStore(u_voxelTexture, ivec3(dim * posVoxelSpace), val)` [S1, unofficial].

**Pseudocode:**
```python
def update_voxel_texture(texture, pos_voxel_space, val, dim):
    # Step 1: Scale alpha
    val_a = val[3] * (1.0 / 255.0)
    # Step 2: Load previous value
    idx = tuple(int(d * p) for d, p in zip(dim, pos_voxel_space))
    prev = texture[idx]
    # Step 3: Calculate average
    total_alpha = prev[3] + val_a
    avg_r = (prev[0] * prev[3] + val[0] * val_a) / total_alpha
    avg_g = (prev[1] * prev[3] + val[1] * val_a) / total_alpha
    avg_b = (prev[2] * prev[3] + val[2] * val_a) / total_alpha
    # Step 4: Update val
    new_val = [avg_r, avg_g, avg_b, total_alpha]
    # Step 5: Store result
    texture[idx] = new_val
```

**Parameters:** `dim` (voxel grid dimensions), `posVoxelSpace` (voxel coordinate), `val` (incoming `vec4`). Not given in the sources.

## Subtopics

### Serial Point Loop
A variant where the voxelization loop is executed serially because concurrent writes to a shared `AbstractDataStore` are not thread-safe [S2, unofficial].

## Background
This method is part of a voxelization pipeline that includes cone tracing and shadow mapping [S1, unofficial]. It was implemented in the `gidemo` project to handle voxel texture updates without relying on advanced GPU features [S1, unofficial]. The serial variant is discussed in the context of point cloud voxelization in the `simplnx` project, highlighting thread safety concerns [S2, unofficial].
