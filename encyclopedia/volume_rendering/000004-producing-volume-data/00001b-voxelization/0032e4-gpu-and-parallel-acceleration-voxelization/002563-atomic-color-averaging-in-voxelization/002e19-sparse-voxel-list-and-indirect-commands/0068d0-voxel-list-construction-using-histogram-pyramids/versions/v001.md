# Voxel List Construction Using Histogram Pyramids

Also called: Histogram pyramid traversal, Parallel voxel list initialization, Voxel List Construction via Histogram Pyramid Traversal

## Overview
This method initializes a sparse voxel list on the GPU by mapping linear indices of non-zero voxels back to their spatial coordinates. It solves the problem of parallel coordinate reconstruction by using a histogram pyramid to perform a binary-search-like traversal. It differs from atomic accumulation methods by avoiding race conditions and sorting overhead during the initial population phase, instead relying on a deterministic traversal of a precomputed reduction structure [S1, unofficial].

## How it works
**Inputs:**
- Input volume data $V$ of size $m \times m \times m$ (or 2D $m \times m$ as per source example).
- A binary classification mask $B$ where $B_{ijk} = 1$ if $V_{ijk} \neq 0$, else $0$.

**Outputs:**
- A voxel list $L$ containing $n$ elements, where $n$ is the count of non-zero voxels.
- Each element in $L$ stores the Morton code (z-order) of the corresponding voxel's spatial location.

**Data Structures:**
1.  **Histogram Pyramid $H$:** A hierarchical structure storing partial sums of the binary mask $B$.
    -   **Levels:** $0$ to $\lceil \log_2 m \rceil$.
    -   **Level 0 (Leaves):** Contains $m^2$ (or $m^3$) entries, each holding the value of $B_{ijk}$ (0 or 1).
    -   **Level $k > 0$:** Contains entries representing the sum of children from level $k-1$. The root (level $\lceil \log_2 m \rceil$) holds the total count $n$.
    -   **Layout:** Stored as a flat array or structured hierarchy. The source implies a standard reduction tree layout where parent nodes sum their children [S1, unofficial].
2.  **Voxel List $L$:** An array of size $n$. Each entry stores a Morton code.

**Algorithm Steps:**

1.  **Binary Classification:**
    Generate the binary mask $B$ from input volume $V$. $B_{ijk} = 1$ if $V_{ijk} \neq 0$, else $0$.

2.  **Construct Histogram Pyramid:**
    Perform a parallel reduction on $B$ to build $H$.
    -   Initialize level 0 with $B$.
    -   For each level $k$ from 1 to $\lceil \log_2 m \rceil$:
        -   Each node at level $k$ sums the values of its children from level $k-1$.
        -   In 2D, a node at $(x, y)$ in level $k$ sums four children from level $k-1$ (or two in 1D, or eight in 3D, though the source example is 2D). The source explicitly mentions "Morton order" iteration, implying the hierarchy respects spatial locality [S1, unofficial].
    -   Read the root value to determine $n$, the total number of non-zero voxels.

3.  **Parallel Traversal Kernel:**
    Launch a GPU kernel with $n$ work-items (threads). Each thread $t$ (where $t \in [0, n-1]$) is responsible for finding the spatial coordinate of the $t$-th non-zero voxel.

    **Traversal Logic for Thread $t$ (Target Index $i = t$):**
    -   Start at the root of $H$.
    -   Maintain a current coordinate interval $[min, max]$ (initially covering the entire volume bounds).
    -   Iterate from level $k = \lceil \log_2 m \rceil$ down to 1:
        -   Iterate over the children of the current node in Morton order (z-order).
        -   Accumulate the sum $S$ of the children's values.
        -   Check if $S > i$.
        -   If $S > i$:
            -   The target voxel is within the subtree of the current child that caused the sum to exceed $i$.
            -   Move down to that child node.
            -   Update the coordinate interval $[min, max]$ to the bounds of this child.
            -   Update $i$ to $i - (\text{sum of previous siblings})$. *Note: The source describes stopping when the next entry exceeds $i$, implying we subtract the sums of skipped siblings.*
        -   If $S \le i$:
            -   Subtract $S$ from $i$ (since the target is not in this subtree).
            -   Continue to the next sibling.
    -   **Leaf Level:** When reaching the leaf level (level 0), the traversal stops. The final coordinate interval identifies the specific voxel $(x, y, z)$. The source example shows stopping at $[1, 2]$ for index 5 in a 2D grid, where the sum of preceding leaves exceeded the index [S1, unofficial].

4.  **Morton Code Conversion:**
    -   Convert the final spatial coordinates $(x, y, z)$ obtained from the traversal into a Morton code.
    -   Store this Morton code in the voxel list $L[t]$.
    -   The source references an external method for this transformation (Appendix A of [S1, unofficial]), typically involving bit-interleaving [S1, unofficial].

5.  **Sorting (Optional/Post-Processing):**
    -   Sort the voxel list $L$ by Morton code. This is not part of the traversal itself but is performed to enable efficient binary search lookups later [S1, unofficial].

**Pseudocode:**

```python
def build_histogram_pyramid(binary_mask, m):
    """
    Builds a histogram pyramid from a binary mask of size m x m.
    Returns the pyramid levels as a list of arrays.
    """
    levels = []
    current_level = binary_mask.flatten() # Level 0
    levels.append(current_level)
    
    # Build pyramid up to root
    while len(current_level) > 1:
        next_level_size = len(current_level) // 4 # Assuming 2D 4-way reduction
        next_level = [0] * next_level_size
        for i in range(next_level_size):
            # Sum 4 children in Morton/spatial order
            idx = i * 4
            next_level[i] = (current_level[idx] + 
                             current_level[idx+1] + 
                             current_level[idx+2] + 
                             current_level[idx+3])
        current_level = next_level
        levels.append(current_level)
        
    return levels

def traverse_histogram_pyramid(levels, target_index, m):
    """
    Traverses the histogram pyramid to find the coordinate of the target_index-th non-zero element.
    Returns the linear index or coordinate interval.
    """
    # Start at root
    current_node_idx = 0
    current_level_idx = len(levels) - 1
    
    # We need to track the offset within the current level's range
    # The source implies tracking boundaries. 
    # For simplicity, we track the remaining index to find.
    remaining_index = target_index
    
    # Traverse down to leaf
    while current_level_idx > 0:
        current_level = levels[current_level_idx]
        next_level = levels[current_level_idx - 1]
        
        # Determine the range of children for the current node
        # In a flat array representation of a quadtree/histogram pyramid:
        # Node i at level k has children at indices i*4 to i*4+3 at level k-1
        child_start = current_node_idx * 4
        child_end = child_start + 4
        
        found_child = False
        for j in range(child_start, child_end):
            child_val = next_level[j]
            if remaining_index < child_val:
                # Target is in this child
                current_node_idx = j - child_start # Index relative to next level? 
                # Actually, we move to the child node in the next level.
                # The child's index in the next level is j.
                current_node_idx = j 
                found_child = True
                break
            else:
                remaining_index -= child_val
        
        if not found_child:
            # This should not happen if target_index < total count
            raise ValueError("Target index out of bounds")
            
        current_level_idx -= 1
        
    # At leaf level (level 0), current_node_idx is the index in the flattened binary mask
    # Convert linear index to (x, y)
    x = remaining_index % m # This is a simplification; true Morton traversal requires coordinate interval tracking
    y = remaining_index // m
    
    # Note: The source emphasizes tracking coordinate intervals [min, max] during traversal.
    # A precise implementation would maintain min_x, max_x, min_y, max_y and subdivide them.
    # Given the constraints, we return the linear index which maps to the voxel.
    return current_node_idx

def voxel_list_construction(input_volume, m):
    """
    Main function to construct the voxel list.
    """
    # 1. Binary Classification
    binary_mask = (input_volume != 0).astype(int)
    
    # 2. Build Histogram Pyramid
    levels = build_histogram_pyramid(binary_mask, m)
    n = levels[-1][0] # Root value
    
    # 3. Parallel Traversal (Simulated sequentially here)
    voxel_list = []
    for i in range(n):
        # Traverse to find the coordinate
        # The source states traversal takes log(m) steps
        coord_index = traverse_histogram_pyramid(levels, i, m)
        
        # 4. Convert to Morton Code
        # Assuming a standard Morton code function exists
        # x = coord_index % m
        # y = coord_index // m
        # morton_code = interleave_bits(x, y)
        
        # Placeholder for Morton conversion logic from Appendix A of [S1, unofficial]
        morton_code = coord_index # Simplified for demonstration
        
        voxel_list.append(morton_code)
        
    # 5. Sort by Morton Code
    voxel_list.sort()
    
    return voxel_list
```

**Edge Cases and Pitfalls:**
-   **Empty Volume:** If $n=0$, the kernel launches with 0 work-items. The histogram pyramid root is 0.
-   **Precision:** The histogram values are integers (counts), so no floating-point precision issues arise during summation.
-   **Boundary Conditions:** The traversal must correctly handle the last element. The source example shows index 5 in an 8-element list. The logic "stop when index $i$ is just exceeded" requires careful handling of the final sibling [S1, unofficial].
-   **Morton Order:** The traversal must strictly follow Morton order (z-order) to ensure the spatial locality required for the binary search property. Deviating from this order breaks the mapping between linear index and spatial coordinate [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(n)$ for the parallel traversal, where $n$ is the number of non-zero voxels. The histogram construction is $O(m^2)$ (or $O(m^3)$) for a volume of side length $m$. The traversal depth is $\log(m)$ [S1, unofficial].
-   **Memory Complexity:** $O(m^2)$ (or $O(m^3)$) to store the histogram pyramid. The voxel list requires $O(n)$ space.
-   **Performance:** The method is designed for GPU parallel execution. It avoids the contention of atomic operations. The source notes that the traversal takes $\log(m)$ steps per element [S1, unofficial].
-   **Strengths:** Deterministic, no race conditions, efficient for sparse data.
-   **Limitations:** Requires storing the full histogram pyramid. The initial construction cost is non-trivial for large volumes.

## Background
This method was introduced by Ziegler in the context of adaptive, hybrid data structures for volume datasets on the GPU [S1, unofficial]. It builds upon the concept of histogram pyramids for parallel reduction and applies it to the specific problem of coordinate reconstruction in voxel lists. The use of Morton codes for sorting and lookup is a standard technique in spatial indexing, adapted here to facilitate the traversal [S1, unofficial].
