# CUDA Voxelizer GPU Voxelization

Also called: CUDA Voxelizer

## Overview
CUDA Voxelizer is a GPU-accelerated method for converting polygon meshes into discrete voxel grids, supporting both surface (faces) and solid (filled volume) voxelization [S3, S5, unofficial]. It is an optimized implementation of the algorithm described by Schwarz and Seidel [S1, S4]. Unlike CPU-based voxelizers, it leverages CUDA parallelism to achieve real-time performance, making it suitable for per-frame voxelization in interactive applications [S3, S5, unofficial]. It distinguishes itself by using a bit-packed storage format and conservative rasterization techniques adapted for GPU atomics [S2, unofficial][S4].

## How it works
**Inputs and Outputs:**
*   **Input:** An indexed triangle mesh (vertex buffer and index buffer) [S1, S4].
*   **Output:** A voxel grid. The default output format is `.binvox` or a morton-ordered grid [S5, unofficial]. The internal representation is a bit-packed 3D array [S2, unofficial].

**Data Structures:**
*   **Voxel Grid:** Stored as a 1D array of integers. The coordinate mapping for a voxel $(x, y, z)$ in a grid of size $N$ is:
    $$ \text{index} = (x + y \cdot N) \cdot \lceil N / 32 \rceil + \lfloor z / 32 \rfloor $$
    The specific bit within the integer is $z \pmod{32}$ [S2, unofficial]. This packs 32 voxels along the Z-axis into one 32-bit integer.
*   **Voxel Table (vtable):** A bit-packed array where each voxel is 1 bit. The size is $\lceil N_x N_y N_z / 32 \rceil \times 4$ bytes [S3, unofficial].
*   **Device Triangles:** A flat array of floats on the GPU. Layout is 9 floats per triangle (3 vertices $\times$ 3 coordinates). Total size is $9 \times N_{faces} \times \text{sizeof(float)}$ [S3, unofficial].
*   **Voxinfo Struct:** Passed to kernel functions. Contains:
    *   `bbox_mesh_cubed`: The cubical bounding box of the mesh [S3, unofficial].
    *   `gridsize`: The dimensions of the voxel grid (typically cubic) [S3, unofficial].
    *   `num_faces`: The number of triangles [S3, unofficial].

**Parameters:**
*   **gridsize:** The length of the cubical voxel grid. Default is 256 [S3, unofficial]. The grid is constructed to be the tightest possible cubical bounding box around the input model [S3, unofficial].
*   **solidVoxelization:** Boolean flag. If true, performs solid voxelization (requires a watertight mesh) [S3, unofficial].
*   **epsilon:** Floating-point constant for error checking, value is $0.00001$ [S2, unofficial].
*   **Hardware:** Requires CUDA-compatible video card with Compute Capability 2.0 or higher (Nvidia Fermi or better) [S5, unofficial].

**Algorithm Steps:**
1.  **Preprocessing (Host):**
    *   Compute the bounding box of the mesh.
    *   Pad the bounding box to form a cube ($AABox<float3> \ bbox\_mesh\_cubed$) [S3, unofficial].
    *   Allocate CUDA-managed unified memory for the triangle data and voxel table [S3, unofficial].
    *   Copy vertex data into a flat float array [S3, unofficial].

2.  **Kernel Launch (Host):**
    *   Calculate block size as 128 [S2, unofficial].
    *   Calculate block number as $\lceil (N_{faces} + \text{block\_size} - 1) / \text{block\_size} \rceil$ [S2, unofficial].
    *   Launch `device::voxelize_kernel` with the calculated blocks and threads, passing vertices, triangles, bounding boxes, delta, inverse delta, stride, and voxel data pointers [S2, unofficial].

3.  **Voxelization Kernel (Device):**
    *   **Triangle Processing:** Each thread processes one or more triangles. To mitigate atomic contention, warps access triangles with a certain stride, increasing the chance that concurrent atomics refer to different memory locations [S1, S4].
    *   **Conservative Rasterization:** For each triangle, determine the bounding box in voxel space. Iterate through the voxels in this bounding box.
    *   **Plane Tests:** For each voxel, perform projection tests to determine if the triangle overlaps the voxel.
        *   Compute the triangle normal $\mathbf{n} = \text{normalize}((\mathbf{v}_1 - \mathbf{v}_0) \times (\mathbf{v}_2 - \mathbf{v}_0))$ [S3, unofficial].
        *   Compute plane constants $d_1$ and $d_2$ based on the voxel grid unit vector $\mathbf{c}$ and triangle vertices [S3, unofficial].
        *   Evaluate the depth range condition: $(\mathbf{n} \cdot \mathbf{p} + d_1) \cdot (\mathbf{n} \cdot \mathbf{p} + d_2) > 0$ to skip voxels outside the triangle's depth range [S2, unofficial].
        *   Perform 2D projection tests on the YZ and ZX planes (and XY) using edge normals and dot products to verify 2D overlap [S3, unofficial].
    *   **Bit Setting:** If the voxel is inside the triangle, set the corresponding bit in the voxel table using atomic operations. Special care is taken for bit manipulation: if setting a range of bits, handle the last integer carefully (e.g., if `bit_end` is 31, use `-1 << bit_begin`; otherwise use `(1 << (bit_end+1)) - (1 << bit_begin)`) [S2, unofficial].
    *   **Solid Voxelization:** If enabled, fill the volume inside the mesh. This typically involves ray casting or scan-line filling within the voxel grid, requiring the mesh to be watertight [S3, unofficial].

4.  **Post-processing (Host):**
    *   Copy the voxel data back to host memory [S2, unofficial].
    *   Write to the output format (e.g., `.binvox`) [S5, unofficial].

    # Each thread handles one triangle
    tri_idx = blockIdx.x * blockDim.x + threadIdx.x
    if tri_idx >= num_triangles:
        return

    # Load triangle vertices
    v0 = triangles[tri_idx * 9 + 0:3]
    v1 = triangles[tri_idx * 9 + 3:6]
    v2 = triangles[tri_idx * 9 + 6:9]

    # Compute triangle normal
    e0 = v1 - v0
    e1 = v2 - v1
    e2 = v0 - v2
    n = normalize(cross(e0, e1))

    # Compute bounding box in voxel space
    # Clamp to grid boundaries
    min_v = clamp(floor(min(v0, v1, v2) * inv_delta), 0, grid_size - 1)
    max_v = clamp(ceil(max(v0, v1, v2) * inv_delta), 0, grid_size - 1)

    # Precompute plane constants for depth test
    # c is the voxel size vector
    c = delta
    d1 = dot(n, c - v0)
    d2 = dot(n, (delta_p - c) - v0) # delta_p is likely a typo in source, assume related to voxel position

    for z in range(min_v.z, max_v.z + 1):
        for y in range(min_v.y, max_v.y + 1):
            for x in range(min_v.x, max_v.x + 1):

                p = float3(x, y, z) * delta + delta / 2.0

## Subtopics

### [Parallel CPU/GPU Voxelization](7027-parallel-cpu-gpu-voxelization.md)
This method accelerates the voxelization of tetrahedral meshes by distributing the computational workload between CPU cores (using OpenMP) and GPU streams (using CUDA). It addresses the performance bottleneck of iterating over large numbers of tetrahedra and voxel points, which is the core operation in robust voxelization algorithms like Philipp B’s. Unlike pure CPU or pure GPU approaches, this hybrid strategy aims to maximize throughput for high-density meshes while acknowledging the memory transfer overhead that penalizes smaller datasets.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of triangles and the volume of the bounding box in voxels. The kernel launch overhead is constant.
*   **Memory Complexity:** Proportional to the number of voxels ($N_x N_y N_z / 32$ integers) and the number of triangles ($9 N_{faces}$ floats) [S3, unofficial].
*   **Performance:** On a GTX 1060, for the Stanford Bunny Model (70k triangles), voxelization times including GPU memory transfers are:
    *   $128^3$: 4.2 ms
    *   $256^3$: 6.2 ms
    *   $512^3$: 13.4 ms
    *   $1024^3$: 38.6 ms [S5, unofficial].
    *   On a GTX 1050 Ti, times are faster: $64^3$: 0.2 ms, $128^3$: 0.3 ms, $256^3$: 0.6 ms, $512^3$: 1.8 ms [S3, unofficial].
*   **Strengths:** High performance for real-time applications; supports both surface and solid voxelization; bit-packed storage reduces memory usage [S3, S5, unofficial].
*   **Limitations:** Atomic operations can be expensive on older hardware (GT200), leading to contention if many triangles overlap the same voxel [S1, S4]. Solid voxelization requires a watertight mesh [S3, unofficial].

## Background
The method is based on the paper "Fast Parallel Surface and Solid Voxelization on GPUs" by M. Schwarz and H.P. Seidel (2010) [S1, S4]. The implementation by Jeroen Baert (cuda_voxelizer) also incorporates morton-encoded tables from his 2013 HPG paper "Out-Of-Core construction of Sparse Voxel Octrees" and the libmorton library [S3, S5, unofficial]. It is designed for use as a per-frame voxelization step for real-time applications [S3, S5, unofficial].
