# CUDA Voxelizer GPU Voxelization

Also called: Implementation Details, voxelize

## Overview
A GPU-accelerated method to convert polygon meshes into voxel grids using CUDA, supporting both surface voxelization (faces) and solid voxelization (filled volume) [S1, unofficial]. It differs from its siblings by providing a complete, standalone command-line implementation that handles mesh loading, bounding box computation, and parallel rasterization in a single pipeline, whereas [Per-Pixel Linked List Voxelization](1187-per-pixel-linked-list-voxelization.md) focuses on specific rasterization techniques and [Vessel Voxelizer](2321-vessel-voxelizer.md) targets specific anatomical structures [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An indexed triangle set (vertex and index buffer) in formats such as .ply, .off, .obj, .3DS, .SM, or RAY [S1, unofficial].
*   **Output:** A voxel grid in formats including .vox, .binvox, .obj cubes, point cloud, or morton-ordered grid [S1, unofficial].

**Data Structures:**
*   **`voxinfo`:** A struct passed to the voxelization kernel containing:
    *   `bbox_mesh_cubed`: An axis-aligned bounding box (`AABox<float3>`) of the mesh, padded to form a cube [S1, unofficial].
    *   `gridsize`: A `uint3` representing the length of the cubical voxel grid [S1, unofficial].
    *   `num_faces`: A `size_t` count of triangles [S1, unofficial].
*   **`vtable`:** A voxel table stored as a bit-packed array. The size is $\lceil \text{gridsize}_x \times \text{gridsize}_y \times \text{gridsize}_z / 32.0 \rceil \times 4$ bytes. Each voxel occupies 1 bit [S1, unofficial].
*   **`device_triangles`:** An array of floats on the GPU with a layout of 9 floats per triangle (3 vertices $\times$ 3 coordinates). Total size is $\text{sizeof(float)} \times 9 \times \text{num\_faces}$ [S1, unofficial].

**Parameters:**
*   `gridsize`: The length of the cubical voxel grid. Default value is 256 [S1, unofficial].
*   `solidVoxelization`: A boolean flag. If true, performs solid voxelization (requires a watertight input mesh) [S1, unofficial].
*   `morton_code`: A flag to enable morton ordering of the output grid [S1, unofficial].

**Steps:**
1.  **Compute Bounding Box:** Calculate the bounding box of the input mesh and pad it to form a cube (`bbox_mesh_cubed`) [S1, unofficial].
2.  **Allocate Memory:** Allocate CUDA-managed unified memory for `device_triangles` and `vtable` based on the calculated sizes [S1, unofficial].
3.  **Transfer Data:** Copy vertex data into a flat float array (`v0.x, v0.y, v0.z, v1.x, ...`) and transfer to the GPU [S1, unofficial].
4.  **Transform and Initialize:** Transform vertices to voxel space and initialize the voxel grid (`vtable`) with zeroes [S2].
5.  **Execute Voxelization:** Call `voxelize()` for surface voxelization or `voxelize_solid()` for solid voxelization, passing `voxinfo`, `device_triangles`, `vtable`, and the `morton_code` flag [S1, unofficial].
6.  **Post-Processing (Optional):** Use `chag::pp` for scan and compaction, and radix sort from CUDPP for sorting, processing only significant bits [S2].

**Pseudocode:**
```python
# Pseudocode for the core voxelization kernel logic
# Based on [S1, unofficial] and [S2]

def cuda_voxelize(mesh, gridsize=256, solid=False):
    # 1. Compute bounding box
    bbox_world = compute_mesh_bbox(mesh)
    bbox_cubed = pad_to_cube(bbox_world)
    
    # 2. Prepare voxel info
    voxinfo = {
        'bbox_mesh_cubed': bbox_cubed,
        'gridsize': (gridsize, gridsize, gridsize),
        'num_faces': len(mesh.faces)
    }
    
    # 3. Allocate and transfer data
    # Layout: 9 floats per triangle (v0.x, v0.y, v0.z, v1.x, ...)
    device_triangles = allocate_unified_memory(voxinfo['num_faces'] * 9 * 4)
    copy_mesh_to_device(mesh, device_triangles)
    
    # Voxel table size: ceil(gridsize^3 / 32) * 4 bytes
    vtable_size = ceil((gridsize**3) / 32.0) * 4
    vtable = allocate_unified_memory(vtable_size)
    memset(vtable, 0, vtable_size) # Initialize with zeroes [S2]
    
    # 4. Launch Kernel
    if solid:
        voxelize_solid<<<grid, block>>>(voxinfo, device_triangles, vtable)
    else:
        voxelize<<<grid, block>>>(voxinfo, device_triangles, vtable)
        
    # 5. Synchronize and Output
    synchronize()
    return vtable

# Kernel logic (simplified from [S1, unofficial])
__global__ void voxelize(voxinfo info, float* triangles, unsigned int* vtable) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    int num_triangles = info.num_faces;
    
    // Persistent thread pattern [S2]
    for (int i = tid; i < num_triangles; i += blockDim.x * gridDim.x) {
        // Extract triangle vertices
        float3 v0 = make_float3(triangles[i*9], triangles[i*9+1], triangles[i*9+2]);
        float3 v1 = make_float3(triangles[i*9+3], triangles[i*9+4], triangles[i*9+5]);
        float3 v2 = make_float3(triangles[i*9+6], triangles[i*9+7], triangles[i*9+8]);
        
        // Transform to voxel space
        // Note: Exact transformation matrix depends on bbox_cubed and gridsize [S1, unofficial]
        v0 = transform_to_voxel_space(v0, info);
        v1 = transform_to_voxel_space(v1, info);
        v2 = transform_to_voxel_space(v2, info);
        
        // Compute triangle bounding box in grid coordinates
        int3 min_v = make_int3(min(v0.x, min(v1.x, v2.x)), 
                               min(v0.y, min(v1.y, v2.y)), 
                               min(v0.z, min(v2.z, v2.z)));
        int3 max_v = make_int3(max(v0.x, max(v1.x, v2.x)), 
                               max(v0.y, max(v1.y, v2.y)), 
                               max(v0.z, max(v2.z, v2.z)));
                               
        // Clamp to grid bounds
        min_v = clamp(min_v, make_int3(0,0,0), info.gridsize - 1);
        max_v = clamp(max_v, make_int3(0,0,0), info.gridsize - 1);
        
        // Rasterize triangle to voxels
        // This involves plane tests and projection tests as per [S1, unofficial]
        for (int z = min_v.z; z <= max_v.z; z++) {
            for (int y = min_v.y; y <= max_v.y; y++) {
                for (int x = min_v.x; x <= max_v.x; x++) {
                    if (is_triangle_intersecting_voxel(v0, v1, v2, x, y, z, info)) {
                        // Atomic set bit
                        atomic_or(&vtable[(x + y * info.gridsize.x + z * info.gridsize.x * info.gridsize.y) / 32], 
                                  1 << ((x + y * info.gridsize.x + z * info.gridsize.x * info.gridsize.y) % 32));
                    }
                }
            }
        }
    }
}
```

**Edge Cases and Pitfalls:**
*   **Atomic Contention:** Atomic memory operations are expensive on GT200-based hardware and can dominate runtime if multiple atomics touch the same memory location [S2]. Mitigation includes making a warp access triangles with a certain stride to increase the chance that concurrent atomics refer to different memory locations [S2].
*   **Watertight Mesh:** Solid voxelization requires a watertight input mesh [S1, unofficial].
*   **Hardware Compatibility:** Requires CUDA-compatible video card with Compute Capability 2.0 or higher (Nvidia Fermi or better) [S1, unofficial].

## Subtopics

### [Parallel CPU/GPU Voxelization](7027-parallel-cpu-gpu-voxelization.md)
Parallel implementation of the voxelization process using OpenMP (CPU) and CUDA (GPU) to accelerate the iteration over tetrahedra and voxel points.

## Operating characteristics
*   **Time Complexity:** The method uses parallel processing to reduce complexity compared to CPU-only approaches. On a GTX 1050 Ti, voxelization times for the Stanford Bunny (70k triangles) are 0.2 ms (64³), 0.3 ms (128³), 0.6 ms (256³), and 1.8 ms (512³) [S1, unofficial].
*   **Memory Complexity:** Memory usage is dominated by the voxel table ($\lceil \text{gridsize}^3 / 32 \rceil \times 4$ bytes) and the triangle buffer ($9 \times \text{num\_faces} \times 4$ bytes) [S1, unofficial].
*   **Performance:** GPU performance significantly outperforms CPU (OpenMP) for large grids. For a 256³ grid, GPU takes 0.6 ms vs CPU 118.2 ms on an Intel i7 8750H [S1, unofficial].
*   **Strengths:** High performance for real-time applications, support for both surface and solid voxelization, and flexible output formats [S1, unofficial].
*   **Limitations:** Atomic contention can impact performance on older hardware (GT200) [S2]. Requires a CUDA-compatible GPU [S1, unofficial].

## Background
The method is based on the work of M. Schwarz and HP Seidel in their 2010 paper *Fast Parallel Surface and Solid Voxelization on GPU's* [S1, unofficial]. The morton-encoded table implementation was based on the author's 2013 HPG paper *Out-Of-Core construction of Sparse Voxel Octrees* and the work in *libmorton* [S1, unofficial]. It is implemented as a command-line tool `cuda_voxelizer` [S1, unofficial].
