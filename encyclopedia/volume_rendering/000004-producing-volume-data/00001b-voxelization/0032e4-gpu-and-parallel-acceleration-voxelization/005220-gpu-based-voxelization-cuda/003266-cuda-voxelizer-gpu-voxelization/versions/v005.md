# CUDA Voxelizer GPU Voxelization

Also called: CUDA Voxelizer

## Overview
CUDA Voxelizer is a GPU-accelerated method for converting polygon meshes into voxel grids, supporting both surface (faces) and solid (filled volume) voxelization [S3, unofficial]. It is an optimized implementation of the algorithm described by Schwarz and Seidel [S1], designed for high-performance, real-time per-frame voxelization [S3, unofficial]. Unlike CPU-based approaches, it leverages CUDA parallelism to handle large triangle counts efficiently, though it relies heavily on atomic operations which can introduce contention on older hardware architectures [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An indexed triangle set consisting of a vertex buffer (float3 per vertex) and an index buffer (uint3 per triangle) [S1].
*   **Output:** A voxel grid. The default output format is `.binvox` or a morton-ordered grid [S5, unofficial]. The internal representation is a bit-packed 3D array [S2, unofficial].

**Data Structures:**
*   **Voxel Grid:** Stored in a 3D grid with bit-packed layout. Each `int` (32 bits) stores 32 voxels along the Z-axis. The coordinate mapping for a voxel at $(x, y, z)$ in a grid of size $n$ is:
    $$ \text{index} = (x + y \cdot n) \cdot \lceil n / 32 \rceil + \lfloor z / 32 \rfloor $$
    The specific bit within the integer is $z \pmod{32}$ [S2, unofficial].
*   **Voxel Table (`vtable`):** A bit-packed array where each voxel is 1 bit. Size is $\lceil \text{gridsize}_x \cdot \text{gridsize}_y \cdot \text{gridsize}_z / 32.0 \rceil \times 4$ bytes [S3, unofficial].
*   **Device Triangles:** A flat float array on the GPU. Layout is 9 floats per triangle (3 vertices $\times$ 3 coordinates). Total size is $9 \times \text{num\_faces} \times 4$ bytes [S3, unofficial].
*   **VoxInfo Struct:** Passed to kernel functions. Contains:
    *   `bbox_mesh_cubed`: `AABox<float3>` representing the tightest cubical bounding box around the mesh [S3, unofficial].
    *   `gridsize`: `uint3` dimensions of the voxel grid [S3, unofficial].
    *   `num_faces`: `size_t` count of triangles [S3, unofficial].

**Parameters:**
*   `gridsize`: Length of the cubical voxel grid. Default is 256. The grid is constructed to tightly encompass the input model [S3, unofficial].
*   `epsilon`: Floating-point constant for error checking, value $0.00001$ [S2, unofficial].
*   `solidVoxelization`: Boolean flag. If `true`, performs solid voxelization (requires watertight mesh) [S3, unofficial].
*   `block_size`: Number of threads per block. Default is 128 [S2, unofficial].

**Algorithm Steps:**
1.  **Bounding Box Calculation:** Compute the bounding box of the mesh and pad it to form a cube (`AABox<float3> bbox_mesh_cubed`) [S3, unofficial].
2.  **Memory Allocation:** Allocate CUDA-managed unified memory for the triangle data and the voxel table (`vtable`) [S3, unofficial].
3.  **Data Transfer:** Copy vertex data into a flat float array on the GPU [S3, unofficial].
4.  **Kernel Launch:** Launch the `voxelize_kernel` with `block_num = (N + block_size - 1) / block_size` blocks and `block_size` threads [S2, unofficial].
5.  **Post-processing (if required):** Use radix sort (e.g., CUDPP) for sorting and scan/compaction (e.g., chag::pp) if generating sparse or morton-ordered outputs [S1].

**Device Kernel Logic (`voxelize_kernel`):**
The kernel processes triangles in parallel. Each thread block handles a subset of triangles.
1.  **Triangle Processing:** For each triangle assigned to the thread:
    a.  Transform vertices to voxel space.
    b.  Compute the triangle's bounding box in grid coordinates, clamped to grid limits [S3, unofficial].
    c.  Calculate plane properties (normal, d1, d2) for depth testing [S3, unofficial].
    d.  Calculate projection test properties for XY, YZ, and ZX planes [S3, unofficial].
2.  **Voxel Rasterization:** Iterate through the voxels in the triangle's bounding box.
    a.  **Depth Test:** Evaluate $(n \cdot p + d1) \cdot (n \cdot p + d2) > 0$ to skip voxels outside the triangle's depth range [S2, unofficial].
    b.  **Projection Tests:** Perform barycentric/projection tests on the YZ and ZX planes to determine if the voxel center lies within the triangle's projection [S2, unofficial].
    c.  **Bit Setting:** If the voxel is inside, set the corresponding bit in the `vtable` using atomic operations [S2, unofficial].
3.  **Atomic Contention Mitigation:** Warps access triangles with a specific stride to reduce the probability of concurrent atomics targeting the same memory location [S1].

**Pseudocode:**
```python
# Pseudocode for the device-side voxelization kernel logic
# Note: This is a simplified representation of the core rasterization logic.

__global__ void voxelize_kernel(float* d_vertices, int* d_triangles, int N, 
                                float* d_tri_bbox0, float* d_tri_bbox1, 
                                VoxelInfo info, int* vtable) {
    int tri_idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (tri_idx >= N) return;

    // 1. Load triangle data
    int v0_idx = d_triangles[tri_idx * 3];
    int v1_idx = d_triangles[tri_idx * 3 + 1];
    int v2_idx = d_triangles[tri_idx * 3 + 2];

    float3 v0 = make_float3(d_vertices[v0_idx * 3], d_vertices[v0_idx * 3 + 1], d_vertices[v0_idx * 3 + 2]);
    float3 v1 = make_float3(d_vertices[v1_idx * 3], d_vertices[v1_idx * 3 + 1], d_vertices[v1_idx * 3 + 2]);
    float3 v2 = make_float3(d_vertices[v2_idx * 3], d_vertices[v2_idx * 3 + 1], d_vertices[v2_idx * 3 + 2]);

    // 2. Compute triangle normal and plane constants
    float3 e0 = v1 - v0;
    float3 e1 = v2 - v1;
    float3 n = normalize(cross(e0, e1));
    
    // Compute d1 and d2 for depth test (Eq. 1 in Schwarz & Seidel)
    // c is the corner of the voxel unit in the direction of the normal
    float3 c;
    c.x = (n.x > 0.0f) ? info.unit.x : 0.0f;
    c.y = (n.y > 0.0f) ? info.unit.y : 0.0f;
    c.z = (n.z > 0.0f) ? info.unit.z : 0.0f;
    
    float d1 = dot(n, c - v0);
    float d2 = dot(n, (info.delta_p - c) - v0);

    // 3. Compute bounding box in grid coordinates
    float3 min_w = fminf(v0, fminf(v1, v2));
    float3 max_w = fmaxf(v0, fmaxf(v1, v2));
    
    int3 min_g = clamp(int3(min_w / info.unit), make_int3(0,0,0), info.gridsize - 1);
    int3 max_g = clamp(int3(max_w / info.unit), make_int3(0,0,0), info.gridsize - 1);

    // 4. Iterate over voxels in bounding box
    for (int z = min_g.z; z <= max_g.z; ++z) {
        for (int y = min_g.y; y <= max_g.y; ++y) {
            for (int x = min_g.x; x <= max_g.x; ++x) {
                float3 p = make_float3(x * info.unit.x, y * info.unit.y, z * info.unit.z);
                
                // Depth test
                float n_dot_p = dot(n, p);
                if ((n_dot_p + d1) * (n_dot_p + d2) <= 0.0f) continue;

                // Projection tests (simplified logic for one plane, e.g., XY)
                // Check if point p is inside triangle projection on XY plane
                if (!is_inside_xy_projection(p, v0, v1, v2, info.unit)) continue;
                
                // Check other necessary projections (YZ, ZX) as per Schwarz & Seidel
                if (!is_inside_yz_projection(p, v0, v1, v2, info.unit)) continue;
                if (!is_inside_zx_projection(p, v0, v1, v2, info.unit)) continue;

                // 5. Set voxel bit atomically
                int grid_size = info.gridsize.x;
                int bit_index = (x + y * grid_size) * (grid_size / 32) + (z / 32);
                int bit_offset = z % 32;
                
                // Atomic OR to set the bit
                atomicOr(&vtable[bit_index], 1 << bit_offset);
            }
        }
    }
}

// Helper: Check if point p is inside triangle projection on XY plane
__device__ bool is_inside_xy_projection(float3 p, float3 v0, float3 v1, float3 v2, float3 unit) {
    // Compute edge normals in 2D (XY)
    float2 e0_xy = make_float2(-e0.y, e0.x); // Perpendicular to e0
    float2 e1_xy = make_float2(-e1.y, e1.x);
    float2 e2_xy = make_float2(-e2.y, e2.x);
    
    // Adjust signs based on triangle orientation
    // (Simplified: assumes consistent winding and normal direction)
    float2 p_xy = make_float2(p.x, p.y);
    float2 v0_xy = make_float2(v0.x, v0.y);
    
    // Barycentric or cross-product test
    // Using cross product sign consistency
    float2 v0v1 = make_float2(v1.x - v0.x, v1.y - v0.y);
    float2 v0v2 = make_float2(v2.x - v0.x, v2.y - v0.y);
    float2 v0p = make_float2(p.x - v0.x, p.y - v0.y);
    
    float c1 = cross(v0v1, v0p);
    float c2 = cross(v0v2, v0v1); // Normal direction indicator
    float c3 = cross(v0v2, v0p);
    
    // Check if p is on the same side of all edges
    // Note: Exact implementation depends on winding order and normal direction
    // This is a placeholder for the complex projection logic described in [S3, unofficial]
    return (c1 * c2 >= 0.0f) && (c3 * c2 >= 0.0f); 
}
```

**Edge Cases and Pitfalls:**
*   **Atomic Contention:** On older hardware (GT200), atomic operations are expensive and can dominate runtime if multiple threads write to the same memory location [S1]. Mitigation involves warping triangles with a stride [S1].
*   **Degenerate Triangles:** If start and end coordinates match on an axis, special bit manipulation is required to set bits along the remaining axes [S2, unofficial].
*   **Solid Voxelization:** Requires a watertight input mesh [S3, unofficial].
*   **Precision:** Use `epsilon` ($0.00001$) for floating-point comparisons to handle boundary cases [S2, unofficial].

## Subtopics

### [Parallel CPU/GPU Voxelization](7027-parallel-cpu-gpu-voxelization.md)
Accelerates tetrahedral mesh voxelization by distributing workload between CPU (OpenMP) and GPU (CUDA). Chosen for high-density meshes where pure GPU atomic contention is prohibitive or CPU overhead is acceptable.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of triangles and the volume of the bounding box. The kernel launch overhead is constant.
*   **Memory Complexity:** $O(N)$ for triangle storage and $O(G^3)$ for the voxel grid, where $G$ is the grid size. The bit-packed storage reduces memory usage by a factor of 32 compared to byte-per-voxel storage [S2, unofficial].
*   **Performance:** On a GTX 1060 with the Stanford Bunny Model (70k triangles):
    *   128³ grid: 4.2 ms [S5, unofficial]
    *   256³ grid: 6.2 ms [S5, unofficial]
    *   512³ grid: 13.4 ms [S5, unofficial]
    *   1024³ grid: 38.6 ms [S5, unofficial]
    *   Note: These timings include GPU memory transfers [S5, unofficial]. On a GTX 1050 Ti, 256³ grid takes 0.6 ms (excluding I/O) [S3, unofficial].
*   **Strengths:** High performance for real-time applications; supports both surface and solid voxelization; bit-packed storage saves memory [S3, unofficial].
*   **Limitations:** Heavy reliance on atomic operations can cause contention on older GPUs (GT200) [S1]. Solid voxelization requires watertight meshes [S3, unofficial].

## Background
The method is based on the paper "Fast Parallel Surface and Solid Voxelization on GPUs" by M. Schwarz and H.P. Seidel (2010) [S1]. The specific implementation, CUDA Voxelizer, was developed by Jeroen Baert and released as open-source software [S3, unofficial]. It was designed to be a fast, per-frame voxelization step for real-time applications [S3, unofficial]. The morton-encoded table implementation was based on Baert's 2013 HPG paper "Out-Of-Core construction of Sparse Voxel Octrees" and the `libmorton` library [S3, unofficial].
