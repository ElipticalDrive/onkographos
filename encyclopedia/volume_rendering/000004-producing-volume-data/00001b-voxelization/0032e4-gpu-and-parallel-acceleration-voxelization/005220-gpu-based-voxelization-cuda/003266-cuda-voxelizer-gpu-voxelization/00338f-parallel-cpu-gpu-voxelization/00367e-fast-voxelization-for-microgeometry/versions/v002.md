# Fast Voxelization for Microgeometry

Also called: Voxelization of Microgeometry

## Overview
Fast Voxelization for Microgeometry is a GPU-accelerated method designed to voxelize sparse, high-frequency microgeometry (such as fibers, hair, and fabrics) while preserving directional orientation data across multiple levels of detail (LoD) [S1]. Unlike traditional raster-based approaches like OpenVDB that prioritize storage density over processing speed, this method maximizes voxelization throughput by distributing workload between CPU and GPU, enabling the processing of highly detailed scenes that would otherwise exceed memory limits [S1]. It specifically addresses the limitation of simple averaging in prior works (e.g., Lopez-Moreno et al.'s Lumislice adaptation) by clustering and preserving orientation distributions, ensuring accurate anisotropic scattering simulation at coarser resolutions [S1].

## How it works
**Inputs and Outputs:** The method accepts sparse microgeometry data, which may include splines, textured orientation data, or triangle meshes representing fibers and hair [S1]. It outputs a hierarchical volumetric data model (SGGX-H) containing density and orientation distributions at multiple resolution levels [S1].

**Data Structures:** The method utilizes a hierarchical structure based on Symmetrical GGX (SGGX) distributions [S1]. Each voxel stores occupancy, optical density, and fitted directional distributions (normals or tangents) [S1]. The output spans two distinct resolution levels controlled by user parameters [S1].

**Parameters:** The pipeline exposes three user-controllable parameters: `first level resolution` controls the base resolution, `second level resolution` controls the finer resolution, and `sample number` determines the sampling density during voxelization [S1].

**Algorithm Steps:** 
1. Distribute the voxelization workload strategically between CPU and GPU cores to maximize speed and memory efficiency [S1].
2. Process input primitives by generating samples according to the `sample number` parameter [S1].
3. Cluster and preserve orientation distributions across multiple detail levels instead of applying simple averaging [S1].
4. Fit SGGX distributions to generate lower-resolution volumes suitable for LoD rendering [S1].
5. Select LoD levels using standard Path Tracer MipMap selection based on projected width on the camera [S1].
6. Balance the `sample number` and resolution parameters to stay within GPU memory limits [S1].

**Pitfalls and Edge Cases:** Combining an elevated number of samples with high resolution can lead to out-of-memory errors [S1]. For models where one dimension is almost flat compared to the largest dimension, regular cubic voxel shapes require a significant increase in global resolution to ensure the smaller dimension has enough nodes for proper voxelization [S1]. There is no automatic heuristic provided for selecting suitable combinations of input parameters for a given model, requiring manual adjustment [S1].

## Operating characteristics
**Time Complexity:** The method is optimized for speed via GPU parallelization and maximizes voxelization time efficiency compared to CPU-centric frameworks like OpenVDB [S1].

**Memory Complexity:** Memory usage is a critical constraint, as combining high resolution with a high sample count can lead to out-of-memory problems [S1].

**Performance:** The approach is validated on a CUDA-based implementation for triangle meshes and other primitives, outperforming traditional raster-based methods in processing speed for microgeometry [S1].

**Strengths:** The method handles sparse microgeometry (fibers, hair, vegetation, fabrics) efficiently [S1]. It preserves orientation distributions across LoD levels, enabling accurate anisotropic scattering [S1]. It is GPU-optimized for speed, unlike OpenVDB and NanoVDB which prioritize storage density [S1].

**Limitations:** The implementation requires manual tuning of resolution and sample parameters to avoid memory issues [S1]. Regular cubic voxels are inefficient for flat geometries, requiring excessive global resolution [S1]. The method exhibits limited per-voxel accuracy with complex geometries at lower resolutions, potentially requiring future improvements such as neural methods [S1].

**When to use:** The method is ideal for rendering sparse, high-frequency microgeometry where anisotropic appearance is critical and GPU memory allows for the required resolution and sample trade-off [S1].

**When not to use:** The method is not suitable for dense, non-sparse geometry where standard voxelization suffices, or for flat geometries where cubic voxels would require prohibitive resolution increases [S1].

## Background
The method was introduced in the paper "Fast Voxelization and Level of Detail for Microgeometry Rendering" [S1]. It addresses the prevalence of sparse microgeometry materials in real-world applications (cloth, hair, vegetation) where traditional voxelization methods fall short [S1]. Prior approaches, such as Lopez-Moreno et al.'s adaptation of Lumislice, failed to preserve orientation data at coarser levels due to simple averaging [S1]. This work builds on Symmetrical GGX (SGGX) distributions to create the SGGX-H hierarchical model [S1]. It contrasts with industry standards like OpenVDB and NanoVDB, which focus on storage density and CPU parallelization rather than GPU-optimized voxelization speed for specific primitives [S1].
