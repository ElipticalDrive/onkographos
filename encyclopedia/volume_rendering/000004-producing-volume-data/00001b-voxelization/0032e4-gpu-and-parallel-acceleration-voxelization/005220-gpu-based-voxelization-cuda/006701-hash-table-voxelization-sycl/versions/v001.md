# Hash-Table Voxelization (SYCL)

Also called: BEVFusion Voxelization (SYCL Port), SYCL BEVFusion Voxelization, lidar-voxelization.cu port

## Overview
This method implements the NVIDIA BEVFusion PointPillars lidar voxelization operator using the SYCL programming model, specifically targeting Intel Arc GPUs. It solves the memory overflow issues of dense voxelization in high-resolution BEVFusion parameter settings by using a hash table for open addressing to map sparse 3D points to voxels, scatter for point feature storage, and reduce_mean for voxel aggregation [S1, unofficial]. It is distinguished from its sibling [CUDA Voxelizer GPU Voxelization](6757-cuda-voxelizer-gpu-voxelization.md) by its explicit use of a hash table to handle sparse data efficiently on hardware where dense grids may exceed available VRAM, and by its SYCL porting of the original CUDA implementation [S1, unofficial].

## How it works
The method operates in three kernel stages: building the hash table, scattering point features into voxels, and computing the mean feature per voxel. It uses half-precision (`sycl::half`) for output features and supports two coordinate ordering templates: `XYZ` and `ZYX` [S1, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `points`: Array of shape `[N, 5]` or `[N, num_feature]` containing point coordinates and features.
    *   `min_range`, `max_range`: 3D vectors defining the voxelization bounding box.
    *   `voxel_size`: 3D vector defining the size of each voxel.
    *   `max_voxels`: Maximum number of voxels to output.
    *   `max_points_per_voxel`: Maximum number of points to aggregate per voxel.
    *   `num_feature`: Number of feature channels per point.
*   **Outputs**:
    *   `voxel_features`: Array of shape `[max_voxels, max_points_per_voxel, num_feature]` containing the mean features.
    *   `voxel_indices`: Array of shape `[max_voxels, 4]` storing voxel coordinates (packed as `sycl::uint4`).
    *   `num_voxels`: The actual number of non-empty voxels created.

### Data Structures
1.  **Hash Table**: A flat array of size `hash_size`. It stores keys and values in two contiguous halves.
    *   Layout: `hash_table[0 ... hash_size/2 - 1]` stores keys (voxel offsets). `hash_table[hash_size/2 ... hash_size - 1]` stores values (voxel IDs).
    *   Key type: `uint32_t`. Value type: `uint32_t`.
    *   Empty key marker: `UINT32_MAX`.
    *   Size: `param_.max_points * 2 * 2 * sizeof(unsigned int)` (provides a load factor of 0.25, i.e., 2x capacity for keys and values relative to max points) [S1, unofficial].
2.  **Voxel Feature Buffer (`voxels_temp`)**: Temporary buffer of shape `[max_voxels, max_points_per_voxel, num_feature]` used for accumulation.
3.  **Point Counter (`num_points_per_voxel`)**: Array of size `max_voxels` tracking the number of points added to each voxel.

### Hash Function
The hash function for a key $k$ is defined as [S1, unofficial]:
$$
\begin{aligned}
k &\leftarrow k \oplus (k \gg 16) \\
k &\leftarrow k \times 0x85ebca6b \\
k &\leftarrow k \oplus (k \gg 13) \\
k &\leftarrow k \times 0xc2b2ae35 \\
k &\leftarrow k \oplus (k \gg 16) \\
\text{return } k
\end{aligned}
$$

### Parameters
*   `hash_table_size`: Calculated as `param_.max_points * 2 * 2 * sizeof(unsigned int)` [S1, unofficial].
*   `CoordinateOrder`: Template parameter. `XYZ` stores `{0, x, y, z}`; `ZYX` stores `{0, z, y, x}` in `sycl::uint4` [S1, unofficial].
*   `grid_size`: Computed as `size.x = round((max_range.x - min_range.x) / voxel_size.x)`, similarly for y and z [S1, unofficial].
*   Optimization Flag: `-DVOX_RELAXED_ATOMICS` enables relaxed atomics (memory ordering `relaxed` instead of `seq_cst`) for performance [S1, unofficial].

### Steps

1.  **Build Hash Table**:
    For each point index `point_idx`:
    1.  Extract coordinates `px, py, pz`.
    2.  Compute voxel indices: `voxel_idx = floor((px - min_range.x) / voxel_size.x)`, similarly for `voxel_idy`, `voxel_idz`.
    3.  Check bounds: If any index is outside `[0, grid_size)`, skip.
    4.  Compute linear offset: `voxel_offset = (voxel_idz * grid_size.y + voxel_idy) * grid_size.x + voxel_idx`.
    5.  Call `insert_to_hash_table(voxel_offset, real_voxel_num, hash_size, hash_table)` [S1, unofficial].

2.  **Voxelization (Scatter)**:
    For each point index `point_idx`:
    1.  Extract `px, py, pz`.
    2.  Check range bounds: If `px < min_range.x` or `px >= max_range.x` (same for y, z), skip.
    3.  Compute voxel indices and check grid bounds.
    4.  Compute `voxel_offset`.
    5.  Call `lookup_hash_table(voxel_offset, hash_size, hash_table)` to get `voxel_id`.
    6.  If `voxel_id >= param.max_voxels`, skip.
    7.  Atomically increment `num_points_per_voxel[voxel_id]` to get `current_num`.
    8.  If `current_num < param.max_points_per_voxel`:
        *   Compute `dst_offset = voxel_id * (num_feature * max_points_per_voxel) + current_num * num_feature`.
        *   Compute `src_offset = point_idx * num_feature`.
        *   Loop `feature_idx` from 0 to `num_feature - 1`: `voxels_temp[dst_offset + feature_idx] = (float)points[src_offset + feature_idx]`.
    9.  Save coordinates: `save_result_by_order<order>((sycl::uint4*)voxel_indices + voxel_id, x, y, z)` [S1, unofficial].

3.  **Reduce Mean**:
    For each `voxel_idx` from 0 to `num_voxels - 1`:
    1.  Clamp `num_points_per_voxel[voxel_idx]` to `max_points_per_voxel`. Let this be `valid_points_num`.
    2.  If `valid_points_num <= 0`, skip.
    3.  Loop `feature_idx` from 0 to `num_feature - 1`:
        *   Initialize `sum = voxels_temp[voxel_idx * num_feature * max_points_per_voxel + feature_idx]`.
        *   Loop `point_idx` from 1 to `valid_points_num - 1`:
            *   `sum += voxels_temp[voxel_idx * num_feature * max_points_per_voxel + point_idx * num_feature + feature_idx]`.
        *   `voxels_temp[voxel_idx * num_feature * max_points_per_voxel + feature_idx] = sum / valid_points_num`.
    4.  Move to continuous output: Loop `feature_idx`: `voxel_features[voxel_idx * num_feature + feature_idx] = (sycl::half)voxels_temp[voxel_idx * num_feature * max_points_per_voxel + feature_idx]` [S1, unofficial].

### Pseudocode

```python
# Helper: Hash function
def hash_key(k: uint32) -> uint64:
    k = k ^ (k >> 16)
    k = k * 0x85ebca6b
    k = k ^ (k >> 13)
    k = k * 0xc2b2ae35
    k = k ^ (k >> 16)
    return k

# Helper: Insert into hash table (Open Addressing)
def insert_to_hash_table(key: uint32, value_ptr: ptr[uint32], hash_size: uint32, hash_table: ptr[uint32]):
    hash_value = hash_key(key)
    slot = hash_value % (hash_size // 2)
    empty_key = 0xFFFFFFFF
    while True:
        # Atomic CAS to try to claim the slot with the key
        pre_key = atomic_cas(hash_table + slot, empty_key, key)
        if pre_key == empty_key:
            # Slot was empty, we claimed it. Now store the voxel ID.
            vid = atomic_fetch_add(value_ptr, 1)
            atomic_store(hash_table + slot + (hash_size // 2), vid)
            break
        elif pre_key == key:
            # Key already exists, no need to insert again
            break
        else:
            # Collision, probe next slot
            slot = (slot + 1) % (hash_size // 2)

# Helper: Lookup in hash table
def lookup_hash_table(key: uint32, hash_size: uint32, hash_table: ptr[uint32]) -> uint32:
    hash_value = hash_key(key)
    slot = hash_value % (hash_size // 2)
    empty_key = 0xFFFFFFFF
    while True:
        k = atomic_load(hash_table + slot)
        if k == key:
            return atomic_load(hash_table + slot + (hash_size // 2))
        elif k == empty_key:
            return empty_key
        else:
            slot = (slot + 1) % (hash_size // 2)
    return empty_key

# Helper: Save coordinates based on order
def save_result_by_order(output: ptr[sycl_uint4], x: uint32, y: uint32, z: uint32, order: str):
    if order == "XYZ":
        output[0] = sycl_uint4(0, x, y, z)
    elif order == "ZYX":
        output[0] = sycl_uint4(0, z, y, x)

# Kernel 1: Build Hash Table
def kernel_build_hash_table(points: ptr[float], min_range: vec3, voxel_size: vec3, grid_size: vec3, 
                            hash_size: uint32, hash_table: ptr[uint32], real_voxel_num: ptr[uint32]):
    point_idx = get_global_id()
    if point_idx >= num_points: return
    
    px = points[point_idx * 5 + 0]
    py = points[point_idx * 5 + 1]
    pz = points[point_idx * 5 + 2]
    
    # Compute voxel indices
    vx = floor((px - min_range.x) / voxel_size.x)
    vy = floor((py - min_range.y) / voxel_size.y)
    vz = floor((pz - min_range.z) / voxel_size.z)
    
    # Check bounds
    if vx < 0 or vx >= grid_size.x or vy < 0 or vy >= grid_size.y or vz < 0 or vz >= grid_size.z:
        return
        
    voxel_offset = (vz * grid_size.y + vy) * grid_size.x + vx
    insert_to_hash_table(voxel_offset, real_voxel_num, hash_size, hash_table)

# Kernel 2: Voxelization (Scatter)
def kernel_voxelization(points: ptr[float], voxel_indices: ptr[sycl_uint4], 
                        num_points_per_voxel: ptr[uint32], voxels_temp: ptr[float],
                        hash_size: uint32, hash_table: ptr[uint32], max_voxels: uint32,
                        max_points_per_voxel: uint32, num_feature: uint32, order: str):
    point_idx = get_global_id()
    if point_idx >= num_points: return
    
    px = points[point_idx * 5 + 0]
    py = points[point_idx * 5 + 1]
    pz = points[point_idx * 5 + 2]
    
    # Check range bounds
    if px < min_range.x or px >= max_range.x or py < min_range.y or py >= max_range.y or pz < min_range.z or pz >= max_range.z:
        return
        
    vx = floor((px - min_range.x) / voxel_size.x)
    vy = floor((py - min_range.y) / voxel_size.y)
    vz = floor((pz - min_range.z) / voxel_size.z)
    
    if vx < 0 or vx >= grid_size.x or vy < 0 or vy >= grid_size.y or vz < 0 or vz >= grid_size.z:
        return
        
    voxel_offset = (vz * grid_size.y + vy) * grid_size.x + vx
    voxel_id = lookup_hash_table(voxel_offset, hash_size, hash_table)
    
    if voxel_id >= max_voxels:
        return
        
    current_num = atomic_add(num_points_per_voxel + voxel_id, 1)
    
    if current_num < max_points_per_voxel:
        dst_offset = voxel_id * (num_feature * max_points_per_voxel) + current_num * num_feature
        src_offset = point_idx * num_feature
        for feature_idx in range(num_feature):
            voxels_temp[dst_offset + feature_idx] = points[src_offset + feature_idx]
            
    save_result_by_order(voxel_indices + voxel_id, vx, vy, vz, order)

# Kernel 3: Reduce Mean
def kernel_reduce_mean(num_points_per_voxel: ptr[uint32], voxels_temp: ptr[float], 
                       voxel_features: ptr[sycl_half], max_voxels: uint32, 
                       max_points_per_voxel: uint32, num_feature: uint32):
    voxel_idx = get_global_id()
    if voxel_idx >= max_voxels: return
    
    valid_points_num = num_points_per_voxel[voxel_idx]
    if valid_points_num <= 0:
        return
        
    # Clamp to max_points_per_voxel
    if valid_points_num > max_points_per_voxel:
        valid_points_num = max_points_per_voxel
        
    base_offset = voxel_idx * num_feature * max_points_per_voxel
    
    for feature_idx in range(num_feature):
        sum_val = voxels_temp[base_offset + feature_idx]
        for point_idx in range(1, valid_points_num):
            sum_val += voxels_temp[base_offset + point_idx * num_feature + feature_idx]
        mean_val = sum_val / valid_points_num
        voxel_features[voxel_idx * num_feature + feature_idx] = sycl_half(mean_val)
```

### Edge Cases and Pitfalls
*   **Div-by-zero in reduce_mean**: If `valid_points_num` is 0, division by zero occurs. The code handles this by checking `if (valid_points_num <= 0) return;` before the accumulation loop [S1, unofficial].
*   **Level Zero Backend Bug**: On Intel Arc [0xb080], the Level Zero backend causes segmentation faults. The OpenCL backend must be used via `ONEAPI_DEVICE_SELECTOR=opencl:gpu` [S1, unofficial].
*   **Precision**: Intel GPU floating-point division may not be IEEE-correctly rounded, leading to ±1 voxel boundary shifts in real data (approx. 0.04% deviation). Synthetic data is bit-exact [S1, unofficial].
*   **Memory Latency Bound**: The voxelization kernel is memory-latency-bound due to random access in the hash table and scattered writes. It does not saturate memory bandwidth [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ for hash table construction and scattering, where $N$ is the number of points. The reduce mean step is $O(V \cdot M \cdot F)$, where $V$ is the number of voxels, $M$ is max points per voxel, and $F$ is the number of features.
*   **Memory Complexity**: $O(P)$ for the hash table, where $P$ is the max number of points (specifically $2 \cdot P \cdot 2 \cdot 4$ bytes). This is significantly lower than dense voxelization's $O(G)$, where $G$ is the total number of grid cells [S1, unofficial].
*   **Measured Performance**: On Intel Arc Graphics [0xb080] with 240k real points, the optimized version achieves a 3.5-3.8x speedup, reducing wall time from 1.938ms to 0.530ms [S1, unofficial].
*   **Scaling**: The hash-table approach scales with the number of points, not the grid size. This allows it to handle fine-grained voxelization parameters (e.g., 1440x1440x40 grid) that would cause Out-Of-Memory (OOM) errors in dense implementations [S1, unofficial].
*   **Strengths**: Memory efficiency for sparse data; ability to run with fine voxel sizes; portability to Intel hardware via SYCL.
*   **Limitations**: Memory-latency bound due to random hash table access; performance is limited by hash collisions and cache misses; requires careful handling of atomic operations and backend-specific bugs [S1, unofficial].
*   **When to use**: When voxelizing sparse lidar data with high-resolution grids where dense voxelization would exceed memory limits.
*   **When not to use**: When the grid is very coarse and dense access patterns are more efficient, or when deterministic IEEE-compliant floating-point results are strictly required on Intel hardware [S1, unofficial].

## Background
This method is a SYCL port of the NVIDIA BEVFusion PointPillars lidar voxelization operator (`lidar-voxelization.cu`) [S1, unofficial]. It was developed to enable BEVFusion workloads on Intel Arc GPUs, addressing the memory constraints of dense voxelization in high-resolution settings. The implementation was validated for correctness against CPU references and tested on real-world nuScenes lidar data [S1, unofficial].
