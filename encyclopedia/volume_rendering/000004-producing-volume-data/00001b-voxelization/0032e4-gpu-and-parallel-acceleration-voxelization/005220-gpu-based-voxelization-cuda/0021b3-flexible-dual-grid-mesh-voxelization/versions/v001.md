# Flexible Dual Grid Mesh Voxelization

Also called: CUDA Mesh-to-Flexible-Dual-Grid

## Overview
Flexible Dual Grid Mesh Voxelization converts a polygon mesh into a sparse voxel representation by determining active voxels and solving a Quadratic Error Function (QEF) to compute dual vertex positions [S1, unofficial]. It distinguishes itself from sibling methods like [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly reconstructing surface geometry via dual vertices rather than merely filling occupancy, and from [Interior Voxelize](995-interior-voxelize.md) by focusing on surface-accurate QEF solutions suitable for high-fidelity rendering and reconstruction [S1, unofficial].

## How it works
**Inputs:**
- `vertices`: 2D tensor of shape $(N, 3)$, float32, representing mesh vertices.
- `faces`: 2D tensor of shape $(M, 3)$, int32 (or long), representing triangle indices.
- `grid_size`: 1D tensor of shape $(3,)$, int32, specifying resolution per axis.
- `aabb`: 2D tensor of shape $(2, 3)$, float32, defining the axis-aligned bounding box $[min\_xyz, max\_xyz]$.
- `face_weight`: float, weight for the face term in QEF (default 1.0).
- `boundary_weight`: float, weight for the boundary term in QEF (default 0.2).
- `regularization_weight`: float, weight for the regularization term in QEF (default $10^{-2}$).

**Outputs:**
- `voxel_indices`: 1D tensor of active voxel coordinates.
- `dual_vertices`: 2D tensor of shape $(K, 3)$, float32, containing the QEF solution for each active voxel.
- `intersected`: 1D tensor, bit-packed flags indicating edge intersections.

**Data Structures:**
- **Hashmap:** Used for sparse voxel lookup.
  - `hashmap_keys`: Tensor of size `capacity`. Dtype is `uint32` if volume $< 2^{32}$, else `uint64`. Initialized to max value.
  - `hashmap_vals`: Tensor of size `capacity`, dtype `uint32`.

**Algorithm Steps:**

1.  **Input Validation and Normalization:**
    - Ensure `vertices` and `faces` are 2D tensors with 3 columns.
    - Ensure they reside on the same device.
    - Convert `vertices` to `float32` contiguous tensor.
    - Convert `faces` to `int32` contiguous tensor.
    - Handle `voxel_size` and `grid_size` inputs: convert lists/tuples/ndarrays to `torch` tensors. Ensure metadata is on CPU to avoid implicit CUDA synchronization. Move tensors to the target device.

2.  **AABB Derivation and Padding:**
    - If `aabb` is not provided, compute `min_xyz` and `max_xyz` from `vertices`.
    - If `voxel_size` is provided:
      - Compute padding: $padding = \lceil \frac{max\_xyz - min\_xyz}{voxel\_size} \rceil \cdot voxel\_size - (max\_xyz - min\_xyz)$.
      - Adjust bounds: $min\_xyz \leftarrow min\_xyz - 0.5 \cdot padding$, $max\_xyz \leftarrow max\_xyz + 0.5 \cdot padding$.
    - If `grid_size` is provided:
      - Compute padding: $padding = \frac{max\_xyz - min\_xyz}{grid\_size - 1}$.
      - Adjust bounds: $min\_xyz \leftarrow min\_xyz - 0.5 \cdot padding$, $max\_xyz \leftarrow max\_xyz + 0.5 \cdot padding$.
    - Stack into `aabb` tensor.

3.  **Grid Parameter Derivation:**
    - If `voxel_size_cpu` is None, compute from `aabb` and `grid_size`:
      $$voxel\_size\_cpu = \left( \frac{aabb[1] - aabb[0]}{grid\_size} \right).to(dtype=float32).contiguous()$$
    - If `grid_size_cpu` is None, compute from `aabb` and `voxel_size`:
      $$grid\_size\_cpu = \left( \frac{aabb[1] - aabb[0]}{voxel\_size} \right).round().to(dtype=int32).contiguous()$$

4.  **Kernel Argument Preparation:**
    - Convert `grid_size_cpu` to device tensor.
    - Create `voxel_size_arg`: List of floats from `voxel_size_cpu.tolist()`.
    - Create `grid_range_arg`: List `[0, 0, 0]` concatenated with integers from `grid_size_cpu.tolist()`.

5.  **Coordinate Transformation:**
    - Shift vertices relative to AABB:
      $$vertices_{shifted} = vertices - aabb[0].reshape(1, 3)$$
    - Extract triangles:
      $$triangles = vertices_{shifted}[faces]$$

6.  **CUDA Execution (Occupancy and QEF):**
    - Invoke `intersect_occ_cuda` (or equivalent CPU fallback) with `triangles`, `voxel_size_arg`, and `grid_range_arg`.
    - This step computes active voxel indices and accumulates QEF constraints (face, boundary, regularization) for each voxel.
    - Solve the QEF for each active voxel to determine `dual_vertices`.
    - [G] The QEF solution typically involves solving a linear system $A^T A x = A^T b$ for each voxel, where $A$ and $b$ are accumulated from triangle intersections.

7.  **Serialization and Sorting:**
    - Compute sequence ID: $vid = o\_voxel.serialize.encode\_seq(voxel\_indices)$.
    - Compute mapping: $mapping = torch.argsort(vid)$.
    - Apply mapping to `voxel_indices`, `dual_vertices`, and `intersected` to ensure alignment for subsequent material voxelization or serialization.

**Pseudocode:**

```python
import torch

def mesh_to_flexible_dual_grid(vertices, faces, grid_size=None, voxel_size=None, aabb=None,
                               face_weight=1.0, boundary_weight=0.2, regularization_weight=1e-2):
    """
    Converts a mesh to a Flexible Dual Grid representation.
    """
    # 1. Input Validation
    assert vertices.dim() == 2 and vertices.size(1) == 3
    assert faces.dim() == 2 and faces.size(1) == 3
    assert vertices.device == faces.device
    
    device = vertices.device
    vertices = vertices.float().contiguous()
    faces = faces.int().contiguous()
    
    # 2. Handle AABB and Grid Parameters
    if aabb is None:
        min_xyz = vertices.min(dim=0).values
        max_xyz = vertices.max(dim=0).values
    else:
        min_xyz = aabb[0]
        max_xyz = aabb[1]
        
    # Convert voxel_size/grid_size to tensors if provided
    voxel_size_cpu = None
    grid_size_cpu = None
    
    if voxel_size is not None:
        if isinstance(voxel_size, (list, tuple)):
            voxel_size_cpu = torch.tensor(voxel_size, dtype=torch.float32)
        elif isinstance(voxel_size, torch.Tensor):
            assert not voxel_size.is_cuda, "voxel_size metadata must be on CPU"
            voxel_size_cpu = voxel_size.float().contiguous()
        else:
            voxel_size_cpu = torch.tensor([voxel_size, voxel_size, voxel_size], dtype=torch.float32)
            
    if grid_size is not None:
        if isinstance(grid_size, (list, tuple)):
            grid_size_cpu = torch.tensor(grid_size, dtype=torch.int32)
        elif isinstance(grid_size, torch.Tensor):
            assert not grid_size.is_cuda, "grid_size metadata must be on CPU"
            grid_size_cpu = grid_size.int().contiguous()
        else:
            grid_size_cpu = torch.tensor([grid_size, grid_size, grid_size], dtype=torch.int32)
            
    # Derive missing parameters
    if voxel_size_cpu is None:
        assert grid_size_cpu is not None
        voxel_size_cpu = ((max_xyz - min_xyz) / grid_size_cpu).float().contiguous()
        
    if grid_size_cpu is None:
        assert voxel_size_cpu is not None
        grid_size_cpu = ((max_xyz - min_xyz) / voxel_size_cpu).round().int().contiguous()
        
    # Apply padding
    if voxel_size is not None:
        padding = torch.ceil((max_xyz - min_xyz) / voxel_size_cpu) * voxel_size_cpu - (max_xyz - min_xyz)
        min_xyz = min_xyz - 0.5 * padding
        max_xyz = max_xyz + 0.5 * padding
    elif grid_size is not None:
        padding = (max_xyz - min_xyz) / (grid_size_cpu - 1)
        min_xyz = min_xyz - 0.5 * padding
        max_xyz = max_xyz + 0.5 * padding
        
    aabb_final = torch.stack([min_xyz, max_xyz])
    
    # 3. Prepare Arguments
    voxel_size_arg = voxel_size_cpu.tolist()
    grid_range_arg = [0, 0, 0] + grid_size_cpu.tolist()
    
    # 4. Transform Geometry
    vertices_shifted = vertices - aabb_final[0].reshape(1, 3)
    triangles = vertices_shifted[faces]
    
    # 5. Execute CUDA Kernel
    # Note: This calls the external C++/CUDA extension defined in the source.
    # The kernel handles occupancy, QEF accumulation, and solving.
    voxel_indices, dual_vertices, intersected = _C.intersect_occ_cuda(
        triangles, voxel_size_arg, grid_range_arg
    )
    
    # 6. Sort for Serialization
    vid = o_voxel.serialize.encode_seq(voxel_indices)
    mapping = torch.argsort(vid)
    
    voxel_indices = voxel_indices[mapping]
    dual_vertices = dual_vertices[mapping]
    intersected = intersected[mapping]
    
    return voxel_indices, dual_vertices, intersected
```

**Edge Cases and Pitfalls:**
- **Degenerate Triangles:** CUDA FMA (Fused Multiply-Add) contraction in cross-product based normal computation can produce a tiny non-zero normal for nearly degenerate triangles, which is then amplified by normalization. The implementation uses an aligned cross-normalize path to fix this mismatch [S1, unofficial].
- **Device Sync:** Passing CUDA tensors as metadata (e.g., `voxel_size`) to the kernel preparation can cause implicit synchronization. Ensure metadata is on CPU before conversion [S1, unofficial].

## Subtopics

### [Flexible Dual Grid Occupancy](3522-flexible-dual-grid-occupancy.md)
Returns only the voxel coordinates intersected by a triangle mesh. It uses the same grid setup as mesh_to_flexible_dual_grid but stops after the occupancy stage and does not compute QEFs or dual vertices.

### [O-Voxel](3835-o-voxel.md)
A sparse, voxel-based native 3D representation designed for high-quality 3D generation and reconstruction. It utilizes a Flexible Dual Grid formulation to robustly represent surfaces with arbitrary topology (including non-manifold and open surfaces) and volumetric surface properties such as Physically-Based Rendering (PBR) material attributes.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of triangles and active voxels. The CUDA implementation provides significant speedup over CPU counterparts.
- **Memory Complexity:** Sparse. Memory usage is proportional to the number of active voxels and the hashmap capacity. Benchmarks show memory usage around 1.8 GB for a 3.6M vertex mesh at resolution 512, compared to ~13 GB for dense representations [S1, unofficial].
- **Performance:** On a subdivided mesh (3.6M vertices, 10.3M faces) at RES=512, the reference CUDA implementation takes ~113.9 ms, while the optimized CUDA implementation takes ~85.9 ms [S1, unofficial].
- **Accuracy:** Dual-vertex error (Dual RMS) for the original mesh is $9.1 \times 10^{-5}$ (old CUDA) and $1.66 \times 10^{-4}$ (reference CUDA). For subdivided meshes, it is $1.16 \times 10^{-4}$ (optimized CUDA) and $2.08 \times 10^{-4}$ (reference CUDA) [S1, unofficial].
- **Strengths:** Exact occupancy match with CPU implementation; robust handling of arbitrary topology; efficient sparse storage.
- **Limitations:** Requires CUDA-capable hardware for the optimized implementation; sensitive to degenerate triangles without proper normalization guards.

## Background
The Flexible Dual Grid method was originally implemented on CPU and later ported to GPU to enable instant bidirectional conversion between Meshes and O-Voxels. The CUDA implementation (`mesh_to_flexible_dual_grid`) aims to reproduce the original CPU semantics, including occupancy, QEF accumulation, boundary handling, and final dual-vertex solve. It builds on reference implementations such as `yuyujunjun/o-voxel-gpu` [S1, unofficial]. The method is a core component of the O-Voxel representation, which supports high-quality 3D generation and reconstruction with PBR attributes [S1, unofficial].
