# GPU Evaluation and Occupancy Assembly

Also called: CUDA Voxelization Kernel

## Overview
This method performs the core GPU-side computation for voxelizing 3D data by evaluating geometric primitives against a voxel grid and assembling the resulting occupancy flags. It serves as the computational engine for GPU-based voxelization, translating continuous scene representations into discrete voxel grids. Unlike sibling methods that may handle specific data structures (like octrees) or specialized inputs (like vessel meshes), this kernel focuses on the general parallel evaluation and assembly pipeline. It builds on [GPU-based Voxelization (CUDA)](14644-gpu-based-voxelization-cuda.md) by providing the specific kernel logic for occupancy determination.

## How it works
**Inputs and Outputs:**
*   **Inputs:** A list of geometric primitives (e.g., triangles, splats), camera parameters (if view-dependent), and voxel grid dimensions ($N_x, N_y, N_z$) and resolution ($\Delta$).
*   **Outputs:** A 3D occupancy grid (or sparse representation) indicating which voxels are occupied.

**Data Structures:**
*   **Voxel Grid:** A 3D array or hash map mapping $(i, j, k)$ indices to boolean or integer occupancy values.
*   **Primitive Buffer:** Device-accessible memory containing primitive data (vertices, attributes).

**Steps:**
1.  **Dispatch:** Launch a CUDA kernel where each thread block or thread is responsible for evaluating one or more voxels or primitives.
2.  **Evaluation:** For each assigned voxel, determine if it intersects with any input primitive. This involves transforming the voxel center or bounds into the primitive's local space and performing intersection tests.
3.  **Assembly:** Write the occupancy result to the output grid. If using a sparse structure, compute the hash key and write to the hash table.
4.  **Synchronization:** Ensure all writes are complete before the grid is accessed by subsequent stages.

**Formulas:**
*   Voxel index to world position: $P_{world} = P_{center} + \Delta \cdot (i, j, k)$
*   Occupancy flag: $O_{ijk} = 1 \text{ if } \exists \text{ primitive } p \text{ s.t. } \text{intersect}(voxel_{ijk}, p), \text{ else } 0$

**Parameters:**
*   **Block Size:** Typically 256 or 512 threads per block, depending on occupancy requirements.
*   **Grid Resolution:** Determined by scene bounds and desired detail.

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point inaccuracies in intersection tests can lead to holes or artifacts. Use robust geometric predicates if possible.
*   **Boundaries:** Voxels on the grid boundary must be handled correctly to avoid out-of-bounds memory access.
*   **Degenerate Input:** Empty primitives or zero-volume voxels should be skipped or handled gracefully.

**Pseudocode:**
```python
# Pseudocode for a simple voxel evaluation kernel
# Note: This is a simplified representation. Actual implementation depends on primitive type.

__global__ void evaluate_occupancy_kernel(
    float3* voxel_centers, 
    int* occupancy_grid, 
    int num_voxels,
    Primitive* primitives,
    int num_primitives
) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx >= num_voxels) return;

    float3 center = voxel_centers[idx];
    bool occupied = false;

    // Evaluate each primitive against the voxel
    for (int i = 0; i < num_primitives; ++i) {
        if (intersect_primitive_voxel(primitives[i], center)) {
            occupied = true;
            break; // Optimization: stop if already occupied
        }
    }

    if (occupied) {
        atomicOr(&occupancy_grid[idx], 1);
    }
}

// Helper function for intersection (example for sphere)
__device__ bool intersect_primitive_voxel(Primitive p, float3 center) {
    if (p.type == SPHERE) {
        float dist_sq = length_sq(center - p.center);
        return dist_sq <= p.radius * p.radius;
    }
    // Other primitive types...
    return false;
}
```

## Operating characteristics
*   **Time Complexity:** $O(V \cdot P)$ for dense grids, where $V$ is voxels and $P$ is primitives. Optimized implementations use spatial acceleration structures to reduce this.
*   **Memory Complexity:** $O(V)$ for dense grids, or $O(O)$ for sparse grids, where $O$ is occupied voxels.
*   **Performance:** Highly parallelizable. Performance scales with GPU compute power and memory bandwidth.
*   **Strengths:** Fast, scalable, leverages GPU parallelism.
*   **Limitations:** Memory usage can be high for dense grids. Precision issues may arise.
*   **When to Use:** Real-time voxelization, large-scale scenes.
*   **When Not to Use:** Extremely sparse scenes where CPU-based methods might be more efficient due to overhead.

**Pitfalls from Sources:**
*   Memory management: Using raw `cudaMalloc` instead of memory pools can lead to inefficient VRAM usage and fragmentation [S1, unofficial].
*   Data transfer overhead: Copying data to the host for processing (e.g., sorting, attribute computation) negates GPU benefits [S1, unofficial].

## Background
This method is a fundamental component of GPU-accelerated volume rendering pipelines, particularly those using CUDA. It enables the efficient conversion of continuous geometric data into discrete voxel representations suitable for ray marching or other volume rendering techniques.
