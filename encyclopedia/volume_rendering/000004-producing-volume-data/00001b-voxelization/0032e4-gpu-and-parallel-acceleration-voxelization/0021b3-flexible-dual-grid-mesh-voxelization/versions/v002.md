# Flexible Dual Grid Mesh Voxelization

Also called: CUDA Mesh-to-Flexible-Dual-Grid

## Overview
Flexible Dual Grid Mesh Voxelization determines the set of active sparse voxels intersected by a triangle mesh and solves an enhanced Quadratic Error Function (QEF) to compute dual vertex positions within those voxels [S1, unofficial]. It differs from its sibling [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly constructing a dual-grid representation that captures sharp features and open boundaries without requiring watertight meshes, and from [Interior Voxelize](995-interior-voxelize.md) by solving for continuous dual vertices rather than binary occupancy or signed distance fields [S1, unofficial]. This method serves as the foundational geometry processing stage for [O-Voxel](3835-o-voxel.md), enabling high-quality 3D generation and reconstruction with arbitrary topology [S1, unofficial].

## How it works
**Inputs:**
- `vertices`: Tensor of shape $(N, 3)$, float32, representing mesh vertices.
- `faces`: Tensor of shape $(M, 3)$, int32 or long, representing triangle indices.
- `grid_size`: Tensor of shape $(3)$, int32, or `voxel_size`: Tensor of shape $(3)$, float32. One must be provided.
- `aabb`: Tensor of shape $(2, 3)$, float32, defining the axis-aligned bounding box `[min_xyz, max_xyz]`. If not provided, computed from vertices.
- `face_weight`: Float, weight for the face term in QEF. Default: $1.0$ [S1, unofficial].
- `boundary_weight`: Float, weight for the boundary term in QEF. Default: $0.2$ [S1, unofficial].
- `regularization_weight`: Float, weight for the regularization term in QEF. Default: $10^{-2}$ [S1, unofficial].

**Outputs:**
- `voxel_indices`: Tensor of occupied sparse voxel coordinates.
- `dual_vertices`: Tensor of shape $(K, 3)$, float32, containing the solved dual vertex positions for each occupied voxel.
- `intersected`: Tensor of shape $(K, 3)$, bool, indicating which edges of the voxel cell are intersected by the mesh.

**Data Structures:**
- **Sparse Hashmap**: Used for efficient voxel lookup during accumulation.
  - `hashmap_keys`: Tensor of size `capacity`, dtype `uint32` (if volume $< 2^{32}$) or `uint64` (if volume $< 2^{64}$), initialized to max value.
  - `hashmap_vals`: Tensor of size `capacity`, dtype `uint32`, storing counts or pointers.

**Algorithm Steps:**

1.  **Input Validation and Normalization**:
    - Ensure `vertices` and `faces` are 2D tensors with 3 columns and reside on the same device [S1, unofficial].
    - Convert `vertices` to `float32` contiguous tensor and `faces` to `int32` contiguous tensor on the target device [S1, unofficial].
    - Handle `voxel_size`, `grid_size`, and `aabb` inputs. Convert lists/tuples/ndarrays to torch tensors. Ensure metadata for `voxel_size` and `aabb` remains on CPU to avoid implicit CUDA synchronization, then move to device [S1, unofficial].

2.  **AABB Derivation and Padding**:
    - If `aabb` is not provided, compute `min_xyz` and `max_xyz` from `vertices` [S1, unofficial].
    - Apply padding to ensure the grid covers the geometry with integer-aligned boundaries:
      - If `voxel_size` is provided:
        $$ padding = \lceil \frac{max\_xyz - min\_xyz}{voxel\_size} \rceil \cdot voxel\_size - (max\_xyz - min\_xyz) $$
        $$ min\_xyz \leftarrow min\_xyz - \frac{padding}{2} $$
        $$ max\_xyz \leftarrow max\_xyz + \frac{padding}{2} $$
      - If `grid_size` is provided:
        $$ padding = \frac{max\_xyz - min\_xyz}{grid\_size - 1} $$
        $$ min\_xyz \leftarrow min\_xyz - \frac{padding}{2} $$
        $$ max\_xyz \leftarrow max\_xyz + \frac{padding}{2} $$
    - Stack into `aabb` tensor $[min\_xyz, max\_xyz]$ [S1, unofficial].

3.  **Grid Parameter Derivation**:
    - If `voxel_size` is missing, compute it:
      $$ voxel\_size = \frac{aabb[1] - aabb[0]}{grid\_size} $$
    - If `grid_size` is missing, compute it:
      $$ grid\_size = \text{round}\left( \frac{aabb[1] - aabb[0]}{voxel\_size} \right) $$
    - Prepare arguments for CUDA kernel: `voxel_size_arg` as list of floats, `grid_range_arg` as `[0, 0, 0] + grid_size` [S1, unofficial].

4.  **Coordinate Transformation**:
    - Shift vertices relative to the AABB origin:
      $$ v' = v - aabb[0] $$
    - Form triangles tensor from shifted vertices and face indices [S1, unofficial].

5.  **Occupancy and QEF Accumulation (CUDA Kernel)**:
    - For each triangle, determine intersected voxels using spatial hashing or octree traversal.
    - For each intersected voxel, accumulate QEF matrices and vectors. The enhanced QEF minimizes the distance to the mesh surface, incorporating face, boundary, and regularization terms:
      $$ QEF = \sum_{i} w_i (A_i x - b_i)^2 + \lambda_{reg} \|x\|^2 $$
      Where $w_i$ are weights (face, boundary), $A_i, b_i$ define the plane/edge constraints, and $\lambda_{reg}$ is the regularization weight [S1, unofficial].
    - **Pitfall Handling**: To address CUDA FMA contraction issues where nearly degenerate triangles produce tiny non-zero normals amplified by normalization, use an aligned cross-normalize path for normal computation [S1, unofficial].

6.  **Dual Vertex Solve**:
    - Solve the accumulated QEF for each occupied voxel to obtain the dual vertex position. This typically involves solving a small linear system $Ax=b$ derived from the accumulated QEF matrices [S1, unofficial].

7.  **Serialization and Sorting**:
    - Compute sequence IDs for voxel indices to ensure alignment between geometry and material data:
      $$ vid = \text{encode\_seq}(voxel\_indices) $$
    - Compute mapping:
      $$ mapping = \text{argsort}(vid) $$
    - Apply mapping to `voxel_indices`, `dual_vertices`, and `intersected` to sort the output [S1, unofficial].

**Pseudocode:**

```python
def mesh_to_flexible_dual_grid(vertices, faces, grid_size=None, voxel_size=None, aabb=None, 
                               face_weight=1.0, boundary_weight=0.2, regularization_weight=1e-2):
    """
    Converts a mesh to a Flexible Dual Grid representation.
    
    Args:
        vertices: (N, 3) float tensor
        faces: (M, 3) long tensor
        grid_size: (3,) int tensor or None
        voxel_size: (3,) float tensor or None
        aabb: (2, 3) float tensor or None
        face_weight: float
        boundary_weight: float
        regularization_weight: float
        
    Returns:
        voxel_indices: occupied voxel coordinates
        dual_vertices: (K, 3) solved dual vertex positions
        intersected: (K, 3) bool tensor of intersected edges
    """
    # 1. Input Validation
    assert vertices.dim() == 2 and vertices.size(1) == 3
    assert faces.dim() == 2 and faces.size(1) == 3
    assert vertices.device == faces.device
    
    device = vertices.device
    dtype = torch.float32
    
    # 2. Normalize Inputs
    vertices = vertices.to(dtype=dtype, device=device, contiguous=True)
    faces = faces.to(dtype=torch.int32, device=device, contiguous=True)
    
    # Handle AABB
    if aabb is None:
        min_xyz = vertices.min(dim=0).values
        max_xyz = vertices.max(dim=0).values
    else:
        min_xyz = aabb[0]
        max_xyz = aabb[1]
        
    # Handle voxel_size and grid_size
    voxel_size_cpu = None
    grid_size_cpu = None
    
    if voxel_size is not None:
        if isinstance(voxel_size, (list, tuple)):
            voxel_size = torch.tensor(voxel_size, dtype=dtype)
        voxel_size_cpu = voxel_size.to(dtype=dtype, device=torch.device('cpu'), contiguous=True)
        voxel_size = voxel_size_cpu.to(device=device, contiguous=True)
        
    if grid_size is not None:
        if isinstance(grid_size, (list, tuple)):
            grid_size = torch.tensor(grid_size, dtype=torch.int32)
        grid_size_cpu = grid_size.to(dtype=torch.int32, device=torch.device('cpu'), contiguous=True)
        grid_size = grid_size_cpu.to(device=device, contiguous=True)
        
    # Derive missing parameters
    if voxel_size_cpu is None:
        assert grid_size_cpu is not None
        voxel_size_cpu = ((max_xyz.cpu() - min_xyz.cpu()) / grid_size_cpu).to(dtype=dtype, contiguous=True)
        voxel_size = voxel_size_cpu.to(device=device, contiguous=True)
        
    if grid_size_cpu is None:
        assert voxel_size_cpu is not None
        grid_size_cpu = ((max_xyz.cpu() - min_xyz.cpu()) / voxel_size_cpu).round().to(dtype=torch.int32, contiguous=True)
        grid_size = grid_size_cpu.to(device=device, contiguous=True)
        
    # 3. AABB Padding
    extent = max_xyz - min_xyz
    if voxel_size_cpu is not None:
        # Ceiling division for padding
        padded_extent = torch.ceil(extent / voxel_size_cpu) * voxel_size_cpu
        padding = padded_extent - extent
        min_xyz = min_xyz - padding * 0.5
        max_xyz = max_xyz + padding * 0.5
    else:
        # Grid size based padding
        padding = extent / (grid_size_cpu - 1)
        min_xyz = min_xyz - padding * 0.5
        max_xyz = max_xyz + padding * 0.5
        
    aabb_final = torch.stack([min_xyz, max_xyz], dim=0)
    
    # 4. Coordinate Transformation
    vertices_shifted = vertices - aabb_final[0].reshape(1, 3)
    triangles = vertices_shifted[faces]
    
    # 5. CUDA Kernel Invocation (Placeholder for actual C++/CUDA binding)
    # The actual implementation calls _C.intersect_occ_cuda or similar
    # which handles hashing, QEF accumulation, and solving.
    
    # Prepare arguments
    voxel_size_arg = [float(x) for x in voxel_size_cpu.tolist()]
    grid_range_arg = [0, 0, 0] + [int(x) for x in grid_size_cpu.tolist()]
    
    # Call CUDA kernel
    # Note: This is a conceptual representation of the C++ binding

        triangles, 
        voxel_size_arg, 
        grid_range_arg,
        face_weight,
        boundary_weight,
        regularization_weight
    )
    
    # 6. Serialization and Sorting

    mapping = torch.argsort(vid)
    
    voxel_indices = voxel_indices[mapping]
    dual_vertices = dual_vertices[mapping]
    intersected = intersected[mapping]
    
    return voxel_indices, dual_vertices, intersected
```

## Subtopics

### [Flexible Dual Grid Occupancy](3522-flexible-dual-grid-occupancy.md)
Computes only the set of sparse voxel coordinates intersected by a triangle mesh. It differs from [O-Voxel](3835-o-voxel.md) by strictly returning occupied indices without solving the QEF for dual vertex positions or computing edge intersection data. Use this when only occupancy is needed.

### [O-Voxel](3835-o-voxel.md)
A sparse, voxel-based native 3D representation that utilizes Flexible Dual Grid formulation to robustly represent surfaces with arbitrary topology. It differs by solving an enhanced QEF to capture sharp features and open boundaries without watertight meshes. Use this for high-quality 3D generation and reconstruction with PBR attributes.

## Operating characteristics
- **Time Complexity**: Dominated by triangle-voxel intersection tests and QEF accumulation. The CUDA implementation achieves significant speedups over CPU, with benchmarked times of ~85-130 ms for meshes with 3.6M vertices and 10.3M faces at resolution 512 [S1, unofficial].
- **Memory Complexity**: Sparse storage using hashmaps. Memory usage scales with the number of occupied voxels. For a 3.6M vertex mesh at RES 512, memory usage is ~1.8 GB for the GPU implementation, compared to ~12.9 GB for the reference CPU implementation [S1, unofficial].
- **Performance**: The CUDA implementation shows exact occupancy match and zero intersected-flag mismatch against the CPU reference. Dual-vertex RMS error is low ($1.16 \times 10^{-4}$ to $2.08 \times 10^{-4}$) [S1, unofficial].
- **Strengths**: Handles non-manifold and open surfaces; captures sharp features via QEF; efficient GPU parallelization; sparse representation reduces memory footprint.
- **Limitations**: Requires careful handling of degenerate triangles (FMA contraction issues); depends on CUDA; QEF solving adds computational overhead compared to simple occupancy.
- **When to use**: When high-fidelity surface reconstruction from arbitrary meshes is required, especially for non-watertight inputs, and when GPU acceleration is available.
- **When not to use**: For simple binary occupancy grids where sharp features are not critical, or on hardware without CUDA support.

## Background
Flexible Dual Grid Mesh Voxelization originates from the O-Voxel library, which provides instant bidirectional conversion between Meshes and O-Voxels [S1, unofficial]. The method was originally implemented on CPU and later ported to CUDA to reproduce the computation on GPU, including occupancy, QEF accumulation, boundary handling, and dual-vertex solve semantics [S1, unofficial]. It builds on the principles of sparse voxel grids and quadratic error function minimization for surface approximation [S1, unofficial].
