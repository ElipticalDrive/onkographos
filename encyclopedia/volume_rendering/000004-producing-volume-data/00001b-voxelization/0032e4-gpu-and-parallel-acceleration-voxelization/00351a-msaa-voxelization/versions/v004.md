# MSAA Voxelization

Also called: 8xMSAA Voxelization, Conservative Raster via MSAA, Conservative Rasterization with MSAA render target, Multi-Sampling Anti-Aliasing Voxelization

## Overview
MSAA Voxelization is a GPU-based technique that approximates conservative rasterization by leveraging Multi-Sampling Anti-Aliasing (MSAA) coverage tests to determine voxel inclusion, thereby avoiding the computational overhead of explicit primitive edge expansion in the Geometry Shader [S1, unofficial].

## How it works
**Inputs and Outputs:**
* **Input:** A mesh (set of triangles) to be voxelized [S1, unofficial].
* **Output:** A 3D voxel grid (density or color values) stored in a texture or buffer [S1, unofficial].

**Data Structures:**
* **MSAA Render Target:** A render target texture with an MSAA sample count (typically 8x) bound to the output merger stage [S1, unofficial].
* **Voxel Grid:** A 3D texture or structured buffer representing the spatial domain [G].

**Steps:**
1. **Setup Render State:** Configure the graphics pipeline to use an MSAA sample count of $N$ (typically $N=8$) [S1, unofficial].
2. **Bind Render Target:** Bind the MSAA render target to the Output Merger stage [S1, unofficial]. In DirectX 11.1+, one may use "Forced Sample Count" to enable MSAA rasterization without binding an MSAA render target, reducing memory overhead [S1, unofficial].
3. **Rasterization:** Issue draw calls for the mesh [S1, unofficial]. The hardware rasterizer evaluates coverage against the $N$ subsamples per pixel [S1, unofficial].
4. **Pixel Shader Invocation:** The pixel shader is invoked once per pixel if any of the $N$ subsamples are covered by the primitive [S1, unofficial].
5. **Voxel Writing:** Inside the pixel shader, write the voxel data (e.g., density, color) to the voxel grid at the position corresponding to the pixel/fragment [S1, unofficial]. The coverage by any subsample is treated as sufficient evidence that the primitive occupies that voxel space [S1, unofficial].

**Parameters:**
* **MSAA Count:** Typically 8x subsamples [S1, unofficial]. This provides sufficient spacing to approximate conservative rasterization [S1, unofficial].

**Pitfalls and Edge Cases:**
* **Holes:** Primitives lying strictly between subsamples may not be covered by any subsample, leading to "holes" in the voxel grid [S1, unofficial].
* **Mitigation:** Ensure the voxel grid resolution is sufficiently high relative to the size of the voxelized primitives to minimize the probability of primitives falling between subsamples [S1, unofficial].
* **Memory:** Binding an MSAA render target increases video memory usage [S1, unofficial].

**Pseudocode:**
```python
def msaa_voxelize(triangles, voxel_grid, screen_width, screen_height):
    # 1. Setup render state with 8x MSAA
    msaa_sample_count = 8
    # Allocate MSAA render target texture with 8 samples per pixel
    render_target = allocate_texture(screen_width, screen_height, samples=msaa_sample_count)
    # Bind render target to Output Merger stage
    set_output_merger_target(render_target)
    # Set rasterizer to use 8 subsamples per pixel
    set_rasterizer_sample_count(msaa_sample_count)

    # 2. Rasterization: Issue draw calls for the mesh
    for triangle in triangles:
        # Set current geometry to triangle
        set_geometry(triangle)
        # Hardware rasterizer evaluates coverage against 8 subsamples per pixel
        rasterize()

    # 3. Pixel Shader: Invoked once per pixel if any subsample is covered
    def pixel_shader(pixel_x, pixel_y):
        # Map screen pixel to voxel grid coordinates
        voxel_pos = transform_pixel_to_voxel(pixel_x, pixel_y)
        # Write voxel data; invocation implies coverage by at least one subsample
        voxel_grid[voxel_pos] = compute_voxel_value()

    # 4. Resolve MSAA render target to final texture
    resolve_msaa_render_target(render_target)
    return voxel_grid
```

## Subtopics

### Conservative Rasterization via Edge Expansion
Expands primitive edges in the Geometry Shader to ensure coverage. More computationally expensive due to extra geometry processing and requires primitive-voxel intersection tests to remove redundant voxels [S1, unofficial].

### Hardware Conservative Rasterization
Native support in GPU architectures (e.g., NVIDIA Maxwell and higher). Recommended over MSAA approximation for modern hardware [S1, unofficial].

## Operating characteristics
* **Time Complexity:** The pixel shader is invoked once per covered pixel, regardless of the number of subsamples covered [S1, unofficial].
* **Memory Complexity:** Binding an MSAA render target slightly increases video memory usage [S1, unofficial].
* **Strengths:** Simplifies the Geometry Shader by eliminating the need for manual edge expansion; avoids extra pixel shader calls; eliminates the need for post-rasterization primitive-voxel intersection tests to remove redundant voxels [S1, unofficial].
* **Limitations:** It is an approximation, not genuine conservative rasterization; prone to "holes" if primitives fall between subsamples; requires higher resolution voxel grids to mitigate holes; increases video memory usage due to MSAA target [S1, unofficial].
* **When to use:** Recommended for hardware prior to NVIDIA Maxwell architecture [S1, unofficial].
* **When not to use:** On Maxwell or higher architectures, use official conservative rasterization functions instead [S1, unofficial].

## Background
MSAA Voxelization was described as a practical GPU voxelization technique in an unofficial NVIDIA Developer article [S1, unofficial]. It emerged as an alternative to manual conservative rasterization implementations that relied on Geometry Shader edge expansion, which consumed significant GPU cycles [S1, unofficial]. The method leverages existing MSAA hardware features to approximate conservative coverage without additional geometric processing [S1, unofficial].
