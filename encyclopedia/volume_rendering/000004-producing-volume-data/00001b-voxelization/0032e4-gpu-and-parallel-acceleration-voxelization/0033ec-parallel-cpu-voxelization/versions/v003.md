# Parallel CPU Voxelization

Also called: Parallel Voxelization, ThreadPoolExecutor Voxelization

## Overview
Parallel CPU Voxelization is a multi-threaded method that converts geometric sources into a discrete volumetric grid, activated when CUDA is unavailable or forced via a command-line flag [S1, unofficial]. It partitions the workload across CPU cores using Python's `ThreadPoolExecutor` rather than relying on GPU compute or single-threaded execution [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A geometric source (mesh or point cloud) and a target resolution $(N_x, N_y, N_z)$ defining the voxel grid dimensions [S1, unofficial][S2, unofficial].
*   **Output:** A voxelized representation stored as a binary file (e.g., `.vox`), a Morton-ordered binary grid, or a mesh format (e.g., `.obj`) if solid voxelization is requested [S1, unofficial].

**Data Structures:**
The method partitions the voxel grid into sub-tasks [G]. Each worker item contains voxel bounds `(x_start, x_end, y_start, y_end, z_start, z_end)` and indices `(i, j, k)` [S2, unofficial].

**Steps:**
1.  **Initialization:** Check for CUDA availability and evaluate the `-cpu` flag [S1, unofficial].
2.  **Task Generation:** Generate a list of worker items containing voxel bounds and indices [S2, unofficial].
3.  **Parallel Execution:** Submit tasks to a `ThreadPoolExecutor` with `max_workers` set to `os.cpu_count()` to utilize all available cores [S2, unofficial].
4.  **Voxel Computation:** For each worker, iterate through the specified voxel bounds and compute values using plane projection intersection logic [S1, unofficial].
5.  **Aggregation:** Collect results from all workers and write the final voxel data to the specified output format [S1, unofficial].

**Pseudocode:**
```python
import os
from concurrent.futures import ThreadPoolExecutor
import numpy as np

def parallel_cpu_voxelization(mesh, resolution, output_path, force_cpu=True):
    cuda_ok = False  # [G] Standard CUDA device detection
    forceCPU = force_cpu

    if not cuda_ok or forceCPU:
        worker_items = generate_worker_items(resolution)
        max_workers = os.cpu_count()

        with ThreadPoolExecutor(max_workers=max_workers) as executor:
            futures = [
                executor.submit(process_voxel_chunk, mesh, item)
                for item in worker_items
            ]
            results = [f.result() for f in futures]

        write_voxel_data(results, resolution, output_path)

def generate_worker_items(resolution):
    Nx, Ny, Nz = resolution
    # [G] Standard grid partitioning into contiguous bounding boxes
    chunks = []
    for i in range(2):
        for j in range(2):
            for k in range(2):
                x_start, x_end = i * (Nx // 2), (i + 1) * (Nx // 2) - 1
                y_start, y_end = j * (Ny // 2), (j + 1) * (Ny // 2) - 1
                z_start, z_end = k * (Nz // 2), (k + 1) * (Nz // 2) - 1
                chunks.append({
                    'x_start': x_start, 'x_end': x_end,
                    'y_start': y_start, 'y_end': y_end,
                    'z_start': z_start, 'z_end': z_end,
                    'i': i, 'j': j, 'k': k
                })
    return chunks
```

**Parameters:**
*   `max_workers`: Set to `os.cpu_count()` to utilize all available CPU cores [S2, unofficial].
*   `force_cpu`: Boolean flag to force CPU execution even if CUDA is available [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Small Models:** For very small models, the overhead of CPU thread creation and synchronization may make this method slower than GPU execution [S1, unofficial].
*   **Watertight Meshes:** Solid voxelization requires a watertight input mesh; non-watertight meshes may produce incorrect internal voxel values [S1, unofficial].

## Operating characteristics
Time complexity scales linearly with the number of voxels and triangles processed per thread [G]. Memory usage scales linearly with the voxel grid size $(N_x \times N_y \times N_z)$ [G]. Performance is optimal for small models where GPU launch overhead dominates, and scales with available CPU cores [S1, unofficial][S2, unofficial].

## Background
Parallel CPU Voxelization is part of the `cuda_voxelizer` project by Forceflow, which primarily focuses on GPU acceleration but includes a CPU fallback for compatibility [S1, unofficial]. It is also referenced in the `Point-Cloud-Voxelizer` project, which uses Python's `ThreadPoolExecutor` for parallel processing [S2, unofficial].
