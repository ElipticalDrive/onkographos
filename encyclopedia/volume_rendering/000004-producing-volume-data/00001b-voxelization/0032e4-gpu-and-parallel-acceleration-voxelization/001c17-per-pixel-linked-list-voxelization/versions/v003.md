# Per-Pixel Linked List Voxelization

Also called: A-Buffer Ray Intersection List, ABuffer Voxel Output Representation & Traversal, Atomic Counter Voxelization, Linked List Voxel Output, Shader Storage Buffer Object Linked List Voxelization

## Overview
Per-Pixel Linked List Voxelization is a GPU-based technique that constructs a linked list of fragment depths per screen pixel using atomic counters and shader storage buffers, allowing for subsequent sorting and processing of depth-sorted voxels [S1, unofficial]. It solves the problem of efficiently capturing multiple geometry intersections per pixel (occlusion/overlapping surfaces) into a structure that can be traversed to determine voxel occupancy, distinguishing itself from single-depth methods like MSAA Voxelization by preserving the full intersection history per pixel [S1, unofficial].

## How it works
The method operates in three phases: counting fragments, building the linked list, and sorting the lists.

### Inputs and Outputs
*   **Inputs**: A mesh defined by vertex positions and a model transformation matrix. The voxel grid resolution (width, height, depth) is required to map screen coordinates to voxel indices.
*   **Outputs**: A `Voxelizer_ABufferLinkedList` structure containing arrays for head pointers, node pointers, and node data, representing the sorted voxel intervals for each pixel.

### Data Structures
The implementation relies on Shader Storage Buffer Objects (SSBOs) bound to specific bindings [S1, unofficial]:

1.  **HeadPointers** (Binding 1, `std430`): An array of integers `int HeadPointers[]` of size `width * height`. Each element stores the index of the first node in the linked list for the corresponding pixel. Initialized to `-1` [S1, unofficial].
2.  **NodePointers** (Binding 2, `std430`): An array of integers `int NodePointers[]` storing the index of the next node in the linked list for each fragment.
3.  **NodeData** (Binding 3, `std430`): An array of integers `int NodeData[]` storing the depth data for each fragment node. The depth is scaled by the framebuffer width: `int(depth * framebufferWidth)` [S1, unofficial].
4.  **Atomic Counter** (Binding 0, `uniform atomic_uint`): Used to generate unique indices for each fragment in the linked list [S1, unofficial].

The final output structure `Voxelizer_ABufferLinkedList` contains:
*   `width`, `height`, `depth`: Grid dimensions.
*   `fragmentCount`: Total number of fragments processed.
*   `headPointers`: Pointer to the head pointers array.
*   `nodePointers`: Pointer to the node pointers array.
*   `nodeData`: Pointer to the node data array.

### Steps

1.  **Fragment Counting**:
    *   Render the mesh with a fragment shader that increments a global atomic counter for each fragment generated.
    *   Shader: `atomicCounterIncrement(counter)` [S1, unofficial].
    *   This determines the total number of nodes required in the linked list arrays.

2.  **Linked List Construction**:
    *   Render the mesh again. For each fragment:
        *   Increment the atomic counter to get a unique index `count` [S1, unofficial].
        *   Calculate the head pointer index for the current pixel using fragment coordinates and framebuffer width:
            $$ headPointerIndex = \lfloor gl\_FragCoord.x \rfloor + \lfloor gl\_FragCoord.y \rfloor \times framebufferWidth $$
        *   Atomically exchange the current head pointer value with the new fragment index to link the new node to the existing list:
            $$ prevPtr = atomicExchange(HeadPointers[headPointerIndex], count) $$
        *   Set the next pointer of the new node to the previous head pointer:
            $$ NodePointers[count] = prevPtr $$
        *   Store the depth data in the new node, scaled by framebuffer width:
            $$ NodeData[count] = \lfloor gl\_FragCoord.z \times framebufferWidth \rfloor $$
        *   Note: This results in a linked list where nodes are added in reverse depth order (newest/nearest first if depth increases with distance, or vice versa depending on coordinate system) [S1, unofficial].

3.  **Sorting**:
    *   Render a full-screen quad. For each pixel:
        *   Calculate `headPointerIndex` as above.
        *   Retrieve `headPtr = HeadPointers[headPointerIndex]`.
        *   If `headPtr == -1`, discard the fragment (no nodes to sort) [S1, unofficial].
        *   Perform a selection sort on the linked list using nested loops with a safety counter (max 1024 iterations) to prevent infinite loops [S1, unofficial].
        *   **Outer Loop**: Iterate `outerPtr` through the list.
        *   **Inner Loop**: Find the node with the smallest data value (smallest depth) in the remaining list.
        *   **Swap**: If the smallest node is not the current outer node, swap their `NodeData` values. Note: The implementation swaps data values rather than restructuring pointers, which simplifies the sort but requires the list structure to remain intact for traversal [S1, unofficial].
        *   Advance `outerPtr` to `NodePointers[outerPtr]`.

4.  **Traversal**:
    *   Iterate over screen pixels $(i, j)$.
    *   For each pixel, read the starting node index: `curPtr = headPointers[i + j * width]`.
    *   Traverse the list to determine the interval $[startVoxel, endVoxel)$ representing contiguous filled voxels along the ray for pixel $(i, j)$.
    *   The traversal may involve advancing the pointer by two hops (`curPtr = nodePointers[nodePointers[curPtr]]`) depending on the specific voxelization logic applied to the sorted depths [S1, unofficial].

### Pseudocode

```python
# Phase 1: Count Fragments
def count_fragments(mesh, counter_buffer):
    for fragment in mesh.rasterize():
        counter_buffer.value += 1
    return counter_buffer.value

# Phase 2: Build Linked List
def build_linked_list(mesh, counter_buffer, head_pointers, node_pointers, node_data, framebuffer_width):
    # Reset counter if needed, or use existing count
    count = counter_buffer.value
    
    for fragment in mesh.rasterize():
        # Get unique index
        current_count = counter_buffer.value
        counter_buffer.value += 1
        
        # Calculate pixel index
        frag_x = int(fragment.gl_FragCoord.x)
        frag_y = int(fragment.gl_FragCoord.y)
        head_pointer_index = frag_x + frag_y * framebuffer_width
        
        # Atomic exchange to link new node
        prev_ptr = atomic_exchange(head_pointers[head_pointer_index], current_count)
        
        # Set next pointer and data
        node_pointers[current_count] = prev_ptr
        node_data[current_count] = int(fragment.gl_FragCoord.z * framebuffer_width)

# Phase 3: Sort Linked Lists
def sort_linked_lists(head_pointers, node_pointers, node_data, framebuffer_width, width, height):
    max_iterations = 1024
    
    for y in range(height):
        for x in range(width):
            head_pointer_index = x + y * framebuffer_width
            head_ptr = head_pointers[head_pointer_index]
            
            if head_ptr == -1:
                continue
            
            outer_ptr = head_ptr
            outer_loop_count = 0
            
            while outer_loop_count < max_iterations and outer_ptr != -1:
                smallest_ptr = outer_ptr
                smallest_data = node_data[smallest_ptr]
                
                inner_ptr = node_pointers[outer_ptr]
                inner_loop_count = 0
                
                while inner_loop_count < max_iterations and inner_ptr != -1:
                    inner_data = node_data[inner_ptr]
                    if inner_data < smallest_data:
                        smallest_ptr = inner_ptr
                        smallest_data = inner_data
                    inner_ptr = node_pointers[inner_ptr]
                    inner_loop_count += 1
                
                # Swap data if needed
                if smallest_ptr != outer_ptr:
                    node_data[smallest_ptr] = node_data[outer_ptr]
                    node_data[outer_ptr] = smallest_data
                
                outer_ptr = node_pointers[outer_ptr]
                outer_loop_count += 1

# Phase 4: Traverse for Voxels
def traverse_voxels(head_pointers, node_pointers, node_data, width, height):
    for y in range(height):
        for x in range(width):
            head_pointer_index = x + y * framebuffer_width
            cur_ptr = head_pointers[head_pointer_index]
            
            # Example traversal logic
            while cur_ptr != -1:
                depth = node_data[cur_ptr] / framebuffer_width
                # Map depth to voxel index k
                # k = map_depth_to_voxel(depth)
                # Mark voxel (x, y, k) as occupied
                cur_ptr = node_pointers[cur_ptr]
```

### Parameters
*   `framebufferWidth`: Uniform integer representing the width of the framebuffer, used to calculate pixel indices from fragment coordinates [S1, unofficial].
*   `counter`: Atomic unsigned integer used to generate unique indices for each fragment in the linked list [S1, unofficial].
*   `max_iterations`: Safety limit for sorting loops, typically 1024 [S1, unofficial].

### Edge Cases and Pitfalls
*   **Infinite Loops**: Prevented by limiting the number of iterations in both the outer and inner sorting loops to 1024 [S1, unofficial].
*   **Empty Pixel Lists**: Handled by checking if the head pointer is `-1` and discarding the fragment during the sort phase [S1, unofficial].
*   **Precision**: Depth is stored as an integer scaled by framebuffer width. This may lose precision for very large depth ranges or small depth differences [S1, unofficial].
*   **Memory Usage**: The method requires storing a linked list for every fragment, which can be memory-intensive for scenes with high overdraw [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: The sorting phase is $O(N \log N)$ or $O(N^2)$ depending on the sort implementation (selection sort is $O(N^2)$ per list, where $N$ is the number of fragments per pixel). The construction phase is $O(F)$ where $F$ is the total number of fragments.
*   **Memory Complexity**: $O(F)$ for node storage and $O(W \times H)$ for head pointers, where $W$ and $H$ are framebuffer dimensions.
*   **Strengths**: Efficiently handles multiple intersections per pixel without requiring complex spatial partitioning on the GPU. Simple to implement using standard OpenGL features.
*   **Limitations**: Sorting is performed on the GPU, which can be slow for large lists. Memory usage scales with the number of fragments, which can be high for complex scenes.
*   **When to use**: Suitable for real-time voxelization where multiple intersections per pixel are common and GPU sorting performance is acceptable.
*   **When not to use**: Not suitable for scenes with extremely high overdraw where sorting becomes a bottleneck, or when memory is constrained.

## Background
The method is described in the Voxelizer project by Kelsey Kurzeja [S1, unofficial]. It utilizes OpenGL 4.2 features such as atomic counters and shader storage buffer objects (SSBOs) to implement the linked list structure and atomic operations.
