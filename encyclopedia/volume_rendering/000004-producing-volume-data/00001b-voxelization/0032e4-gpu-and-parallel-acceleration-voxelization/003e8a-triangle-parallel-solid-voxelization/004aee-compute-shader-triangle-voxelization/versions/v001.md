# Compute Shader Triangle Voxelization

Also called: Large Triangle DDA Voxelization

## Overview
A compute shader technique for voxelizing large triangles by iterating over a 2D bounding box in the plane of the triangle and testing for collisions, designed to handle triangles that span many voxels more efficiently than per-voxel rasterization [S1, unofficial]. It differs from standard rasterization-based voxelization by explicitly solving the plane equation for every candidate voxel within the triangle's 2D footprint, allowing for precise solid voxelization and texture coordinate interpolation without relying on hardware rasterization pipelines [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A buffer of triangle indices (`large_triangles`), global vertex arrays (`vertices`), index arrays (`indices`), a texture map (`triangle_map`), a Uniform Buffer Object (`ubo`) containing AABB bounds (`aabb_min`, `aabb_max`) and image size, and a texture atlas for diffuse colors.
*   **Output:** A 3D `voxelTexture` (storage image) where voxel colors are written.

**Data Structures:**
*   `large_triangles`: A buffer or array where `large_triangles[gl_WorkGroupID.x].triangle_index` stores the index of the triangle assigned to the workgroup.
*   `vertices`: Global array of vertex positions.
*   `indices`: Global array of triangle indices.
*   `triangle_map`: Array mapping triangle index to texture atlas index.
*   `ubo`: Uniform buffer containing `aabb_min` (vec4), `aabb_max` (vec4), and implicitly the voxel grid resolution via `imageSize(voxelTexture).x`.
*   `shared uint triangle_index`: Shared memory variable used to broadcast the triangle index from thread 0 to all threads in the workgroup.

**Parameters:**
*   `NUM_THREADS`: Number of threads per workgroup, set to 64 [S1, unofficial].

**Steps:**
1.  **Triangle Index Broadcast:** Thread 0 loads the triangle index from `large_triangles[gl_WorkGroupID.x].triangle_index` into the shared memory variable `triangle_index`. All threads synchronize using a barrier.
2.  **Vertex Retrieval:** All threads retrieve the three vertex positions from `vertices` using the shared `triangle_index` and the `indices` array. They also retrieve the associated texture index from `triangle_map[triangle_index]`.
3.  **Coordinate Transformation:**
    *   Transform the three vertices from model space to world space using the model matrix `pc.model`.
    *   Convert world-space vertices to voxel space. The voxel space origin is defined by `ubo.aabb_min` and the scale is defined by `voxel_width`, derived from `ubo.aabb_max`, `ubo.aabb_min`, and `imageSize(voxelTexture).x` [S1, unofficial].
4.  **Bounding Box Calculation:** Calculate the axis-aligned bounding box (AABB) of the triangle in voxel space. Determine the minimum and maximum coordinates for x, y, and z (`min_x`, `max_x`, etc.) and compute the dimensions `x_dim`, `y_dim`, `z_dim`.
5.  **Plane Equation:** Compute the plane equation of the triangle in voxel space.
    *   Calculate the normal vector $\mathbf{n}$ via the cross product of two edge vectors.
    *   Compute the plane coefficients: `plane_x_coefficient`, `plane_y_coefficient`, and `plane_constant` (derived from the normal and the distance $D$ from the origin) [S1, unofficial].
6.  **2D Bounding Box:** Determine the 2D bounding box in voxel coordinates for the x and y axes (`min_x_voxel`, `max_x_voxel`, `min_y_voxel`, `max_y_voxel`). Calculate the total number of voxels to process in this 2D footprint.
7.  **Voxel Iteration and Z-Computation:** For each thread, determine its local position $(i, j)$ within the 2D bounding box. Calculate the $z$ coordinate on the triangle plane for the current $(i, j)$ position using the plane equation coefficients:
    $$ z = \frac{\text{plane\_constant} - \text{plane\_x\_coefficient} \cdot i - \text{plane\_y\_coefficient} \cdot j}{\text{plane\_z\_coefficient}} $$
    [S1, unofficial]
8.  **Collision Test:** Construct the voxel coordinate `voxel_coord` using $i$, $j$, and the calculated $z$ value. Perform a collision test `voxel_triangle_collision_test` to verify if the voxel is inside the triangle [S1, unofficial].
9.  **Texture Interpolation:** If the collision test passes, compute the barycentric coordinates of the voxel center in voxel space. Interpolate the texture coordinates (UVs) using these barycentric weights. Sample the diffuse color from the texture atlas using the interpolated UVs.
10. **Output:** Store the resulting voxel color (diffuse color + alpha 1.0) into the `voxelTexture` at `voxel_coord` [S1, unofficial].

**Pseudocode:**

```python
# Shared memory declaration
shared uint triangle_index

# Thread 0 loads the triangle index
if gl_LocalInvocationID.x == 0:
    triangle_index = large_triangles[gl_WorkGroupID.x].triangle_index

# Synchronize all threads in the workgroup
barrier()

# Retrieve vertices and texture index
v0 = vertices[indices[triangle_index * 3]]
v1 = vertices[indices[triangle_index * 3 + 1]]
v2 = vertices[indices[triangle_index * 3 + 2]]
tex_idx = triangle_map[triangle_index]

# Transform to world space
v0_world = pc.model * v0
v1_world = pc.model * v1
v2_world = pc.model * v2

# Convert to voxel space
# voxel_width is derived from ubo.aabb_min, ubo.aabb_max, and imageSize(voxelTexture).x
voxel_v0 = (v0_world - ubo.aabb_min) / voxel_width
voxel_v1 = (v1_world - ubo.aabb_min) / voxel_width
voxel_v2 = (v2_world - ubo.aabb_min) / voxel_width

# Calculate bounding box in voxel space
min_x = min(voxel_v0.x, voxel_v1.x, voxel_v2.x)
max_x = max(voxel_v0.x, voxel_v1.x, voxel_v2.x)
min_y = min(voxel_v0.y, voxel_v1.y, voxel_v2.y)
max_y = max(voxel_v0.y, voxel_v1.y, voxel_v2.y)
min_z = min(voxel_v0.z, voxel_v1.z, voxel_v2.z)
max_z = max(voxel_v0.z, voxel_v1.z, voxel_v2.z)

x_dim = max_x - min_x + 1
y_dim = max_y - min_y + 1
z_dim = max_z - min_z + 1

# Calculate plane equation in voxel space
edge1 = voxel_v1 - voxel_v0
edge2 = voxel_v2 - voxel_v0
normal = cross(edge1, edge2)

# Plane equation: normal.x * x + normal.y * y + normal.z * z = D
# D = dot(normal, voxel_v0)
D = dot(normal, voxel_v0)

plane_x_coefficient = normal.x
plane_y_coefficient = normal.y
plane_z_coefficient = normal.z
plane_constant = D

# Determine 2D bounding box for x and y
min_x_voxel = floor(min_x)
max_x_voxel = ceil(max_x)
min_y_voxel = floor(min_y)
max_y_voxel = ceil(max_y)

# Calculate local 2D position within the workgroup
# Assuming threads map to 2D grid within the bounding box
# This mapping depends on the specific launch configuration and NUM_THREADS
# For simplicity, assuming a linear mapping to 2D coordinates within the bbox
local_id = gl_LocalInvocationID.x
# Map local_id to (i, j) within [min_x_voxel, max_x_voxel] x [min_y_voxel, max_y_voxel]
# Note: The source does not specify the exact 2D thread mapping, so this is a placeholder [G]
# Typically, i = local_id % width, j = local_id / width
width = max_x_voxel - min_x_voxel + 1
height = max_y_voxel - min_y_voxel + 1

if local_id < width * height:
    i = local_id % width + min_x_voxel
    j = local_id / width + min_y_voxel
    
    # Calculate z coordinate on the plane
    # z = (plane_constant - plane_x_coefficient * i - plane_y_coefficient * j) / plane_z_coefficient
    if plane_z_coefficient != 0:
        z_value = (plane_constant - plane_x_coefficient * i - plane_y_coefficient * j) / plane_z_coefficient
    else:
        z_value = 0 # Degenerate case, plane is parallel to z-axis [G]
    
    # Construct voxel coordinate
    voxel_coord = vec3(i, j, z_value)
    
    # Perform collision test
    if voxel_triangle_collision_test(voxel_coord, voxel_v0, voxel_v1, voxel_v2):
        # Compute barycentric coordinates
        # This requires solving for barycentric weights at the voxel center
        # The source mentions computing barycentric coordinates in voxel space [S1, unofficial]
        barycentric = compute_barycentric_coordinates(voxel_coord, voxel_v0, voxel_v1, voxel_v2)
        
        # Interpolate texture coordinates
        # Assuming v0, v1, v2 have associated UVs u0, u1, u2
        # The source does not specify how UVs are stored, so we assume they are available [G]
        uv = barycentric.x * u0 + barycentric.y * u1 + barycentric.z * u2
        
        # Sample diffuse color from texture atlas
        color = texture(voxelTexture, uv).rgb # Placeholder for actual texture sampling logic [G]
        
        # Store voxel color
        voxelTexture[voxel_coord] = vec4(color, 1.0)
```

**Edge Cases and Pitfalls:**
*   **Degenerate Triangles:** If the triangle is degenerate (area zero), the normal will be zero, leading to division by zero in the plane equation. A guard should check for this [G].
*   **Plane Parallel to Z-axis:** If `plane_z_coefficient` is zero, the plane is vertical relative to the voxel grid's Z-axis. The Z coordinate cannot be uniquely determined from X and Y alone. This requires special handling, such as iterating over Z or using a different projection [G].
*   **Precision:** Floating-point precision issues may arise when calculating the plane equation and barycentric coordinates, especially for large triangles or small voxel sizes. Using higher precision types (e.g., `double`) may be necessary [G].
*   **Boundary Conditions:** The bounding box calculation must correctly handle voxels that are partially covered by the triangle. The collision test must be robust to handle edge cases where the voxel center is exactly on the triangle edge [G].

## Subtopics

### Correct Texture Coordinates Voxelization
A compute shader variant for voxelizing triangles with correct texture coordinate interpolation, processing one triangle per thread group (or per invocation depending on launch configuration), focusing on accurate UV mapping [S1, unofficial]. It differs from the Large Triangle DDA method by explicitly calculating and interpolating texture coordinates for each voxel, ensuring that the resulting voxel colors accurately reflect the original triangle's texture [S1, unofficial]. It uses a local size of 32 threads per workgroup [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of triangles and $A$ is the average area of the triangle in voxels. Each triangle is processed by a workgroup, and each thread in the workgroup processes a voxel within the triangle's 2D bounding box.
*   **Memory Complexity:** $O(V)$, where $V$ is the number of voxels in the output volume. The shared memory usage is minimal, only storing the triangle index.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales well with the number of triangles, as each triangle is processed independently. Performance may be limited by memory bandwidth when writing to the `voxelTexture`.
*   **Strengths:** Handles large triangles efficiently by avoiding per-voxel rasterization overhead. Provides precise control over voxelization and texture interpolation.
*   **Limitations:** Requires careful handling of degenerate cases and precision issues. Performance may degrade for triangles with very large areas due to the large number of voxels to process.
*   **When to Use:** Suitable for applications requiring high-quality solid voxelization with accurate texture mapping, such as voxel cone tracing or global illumination.
*   **When Not to Use:** Not suitable for real-time applications with extremely large scenes where performance is critical and approximate voxelization is acceptable.

## Background
Originated from the Voxel-Cone-Tracing project by Oshanath [S1, unofficial]. The method is part of a broader effort to implement efficient voxelization techniques for real-time global illumination using compute shaders.
