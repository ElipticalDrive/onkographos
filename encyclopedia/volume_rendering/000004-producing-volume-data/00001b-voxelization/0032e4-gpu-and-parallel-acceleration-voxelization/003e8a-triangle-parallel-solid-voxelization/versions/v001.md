# Triangle-Parallel Solid Voxelization

Also called: direct triangle-parallel solid voxelization

## Overview
Triangle-Parallel Solid Voxelization is a data-parallel algorithm that maps a set of input triangles to a discrete 3D voxel grid by dedicating one processing thread to each triangle [S1]. It solves the problem of determining the interior of a closed surface by flipping the occupancy state of all voxels lying below the triangle's projection along the primary axis [S1]. Unlike sibling methods that parallelize over voxel columns or tiles, this approach parallelizes strictly over the input primitives, making it conceptually simple but potentially inefficient for complex meshes due to warp divergence and memory contention [S1].

## How it works
**Inputs:** A list of triangles defined by three vertices each; a voxel grid resolution $(n_x, n_y, n_z)$; a bounding box defining the world-space extent of the grid.
**Outputs:** A 3D boolean grid (or bitfield) where each cell $(i, j, k)$ indicates whether the voxel is inside the solid.

**Data Structures:**
*   **Voxel Grid:** A 3D array of bits or booleans, indexed by $(i, j, k)$ where $0 \le i < n_x$, $0 \le j < n_y$, $0 \le k < n_z$. The physical size of each voxel is 1 unit in voxel space [S1].
*   **Triangle:** Defined by vertices $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$. Vertices must be ordered consistently (e.g., counter-clockwise when viewed from the outside) to ensure correct normal direction [S1].

**Algorithm Steps:**

1.  **Thread Assignment:** Assign one thread to each triangle in the input mesh.
2.  **Bounding Box Calculation:** For the assigned triangle, compute the bounding box of its projection onto the $yz$-plane. Determine the integer range of voxel columns $(j, k)$ that intersect this bounding box. Let this range be $[j_{min}, j_{max}] \times [k_{min}, k_{max}]$ [S1].
3.  **Column Iteration:** If the range is non-empty, iterate over each voxel column $(j, k)$ within the bounding box.
4.  **Center Projection and Test:** For each column, identify the center point $\mathbf{p}_{yz} = (j + 0.5, k + 0.5)$ in the $yz$-plane. Test if this center lies inside the triangle's $yz$ projection using edge functions [S1].
    *   Compute edge normals $\mathbf{n}_{yz}^{e_i}$ for each edge $i \in \{0, 1, 2\}$ of the triangle's projection.
    *   Compute the distance parameter $d_{yz}^{e_i} = -\langle \mathbf{n}_{yz}^{e_i}, \mathbf{v}_{i,yzi} \rangle$, where $\mathbf{v}_{i,yzi}$ is the $yz$-component of the $i$-th vertex [S1].
    *   Apply the **Top-Left Fill Rule** to handle shared edges and vertices consistently. This rule ensures that if an edge or vertex is shared by adjacent triangles, only one triangle reports an overlap, preventing double-counting of surface intersections [S1].
    *   The fill rule ignores overlapping edges except for:
        *   Left edges: where the $y$-component of the edge normal is positive ($n_{yz}^{e_i,y} > 0$).
        *   Top edges: where the $y$-component of the edge normal is zero and the $z$-component is negative ($n_{yz}^{e_i,y} = 0 \land n_{yz}^{e_i,z} < 0$) [S1].
    *   Modify the standard edge test by introducing a small floating-point offset $f_{yz}^{e_i}$. Set $f_{yz}^{e_i}$ to the smallest representable floating-point number if the edge is a left or top edge; otherwise, set it to zero [S1].
    *   The test passes if:
        $$ \bigwedge_{i=0}^2 \left( (\langle \mathbf{n}_{\mathbf{e}_i}^{\text{YZ}}, \mathbf{p}_{\text{YZ}} \rangle + d_{\mathbf{e}_i}^{\text{YZ}}) + f_{\mathbf{e}_i}^{\text{YZ}} > 0 \right) $$
        where $\mathbf{p}_{\text{YZ}}$ is the voxel center in the $yz$-plane [S1].
5.  **X-Axis Projection:** If the test passes, project the voxel center along the $x$-axis onto the triangle's plane. Calculate the intersection coordinate $q$ in voxel space [S1].
6.  **Voxel Range Determination:** Determine the range of voxels along the $x$-axis that need to be flipped. The range is defined as $\lfloor q + 0.5 \rfloor$ to $n_x - 1$. Let $\bar{q} = \lfloor q + 0.5 \rfloor$. The voxels to flip are those with indices $i \in [\bar{q}, n_x - 1]$ [S1].
7.  **Atomic Flip:** For each voxel $(i, j, k)$ in the determined range, perform an atomic XOR operation on the grid bit at $(i, j, k)$. This flips the inside/outside state of the voxel [S1].

**Pseudocode:**

```python
def triangle_parallel_solid_voxelization(triangles, grid_shape):
    """
    triangles: List of tuples (v0, v1, v2), where each v is (x, y, z).
    grid_shape: Tuple (nx, ny, nz).
    Returns: 3D boolean array grid of shape (nx, ny, nz).
    """
    nx, ny, nz = grid_shape
    # Initialize grid to False (outside)
    grid = [[False] * nz for _ in range(ny)]
    # Note: In a real GPU implementation, this is a global atomic bitfield.
    # Here we simulate the logic for a single thread processing one triangle.
    
    for tri in triangles:
        v0, v1, v2 = tri
        # 1. Determine bounding box in yz plane
        y_coords = [v0[1], v1[1], v2[1]]
        z_coords = [v0[2], v1[2], v2[2]]
        
        y_min = floor(min(y_coords))
        y_max = ceil(max(y_coords))
        z_min = floor(min(z_coords))
        z_max = ceil(max(z_coords))
        
        # Clamp to grid bounds
        y_min = max(0, y_min)
        y_max = min(ny, y_max)
        z_min = max(0, z_min)
        z_max = min(nz, z_max)
        
        # 2. Loop over voxel columns
        for j in range(y_min, y_max):
            for k in range(z_min, z_max):
                # Center of the voxel column in yz plane
                p_yz = (j + 0.5, k + 0.5)
                
                # 3. Test if center is inside triangle projection
                if is_inside_yz_projection(v0, v1, v2, p_yz):
                    # 4. Project center along x-axis onto triangle plane
                    q = project_x_onto_plane(v0, v1, v2, p_yz)
                    
                    # 5. Determine x range to flip
                    # floor(q + 0.5)
                    q_bar = floor(q + 0.5)
                    
                    # 6. Flip voxels from q_bar to nx-1
                    for i in range(q_bar, nx):
                        # Atomic XOR flip
                        grid[j][k][i] = not grid[j][k][i]

def is_inside_yz_projection(v0, v1, v2, p_yz):
    """
    Tests if p_yz is inside the yz projection of the triangle using edge functions
    and the top-left fill rule.
    """
    # Define edges
    edges = [(v0, v1), (v1, v2), (v2, v0)]
    
    for i in range(3):
        v_start, v_end = edges[i]
        
        # Edge vector in yz
        ey = v_end[1] - v_start[1]
        ez = v_end[2] - v_start[2]
        
        # Edge normal in yz (perpendicular to edge, pointing left)
        # n_yz = (-ez, ey)
        n_yz_y = -ez
        n_yz_z = ey
        
        # Distance parameter d_yz = -<n_yz, v_start_yz>
        d_yz = -(n_yz_y * v_start[1] + n_yz_z * v_start[2])
        
        # Test value
        val = (n_yz_y * p_yz[0] + n_yz_z * p_yz[1]) + d_yz
        
        # Top-left fill rule offset
        f_yz = 0.0
        
        # Check if left edge: n_yz_y > 0
        is_left = (n_yz_y > 0)
        
        # Check if top edge: n_yz_y == 0 and n_yz_z < 0
        is_top = (n_yz_y == 0 and n_yz_z < 0)
        
        if is_left or is_top:
            # Set to smallest floating point number (epsilon)
            f_yz = -1e-9 # Approximation of smallest float for negative offset logic in source context
            # Note: Source says "smallest floating-point number". 
            # In practice, this is a tiny negative epsilon to push the test over 0.
            # The source formula adds f_yz. If f_yz is negative, it makes the test harder.
            # Wait, source says: "f_yz is set to the smallest floating-point number if the left or top edge criteria hold".
            # And the test is: (val + f_yz) > 0.
            # If f_yz is the smallest positive number, it makes it harder.
            # If f_yz is the smallest negative number, it makes it easier.
            # Standard top-left fill rule usually includes the edge.
            # Let's look at the source text carefully: "ignores overlapping edges except left edges... and top edges".
            # This implies left and top edges ARE included.
            # If val is exactly 0 (on the edge), we want the test to pass.
            # So we need val + f_yz > 0. If val=0, f_yz must be > 0.
            # So f_yz is the smallest POSITIVE floating point number.
            f_yz = 1e-9 
            
        if (val + f_yz) <= 0:
            return False
            
    return True

def project_x_onto_plane(v0, v1, v2, p_yz):
    """
    Projects the point p_yz=(y,z) along the x-axis onto the plane defined by v0, v1, v2.
    Returns the x-coordinate q.
    """
    # Plane equation: Ax + By + Cz + D = 0
    # Normal vector n = (v1-v0) x (v2-v0)
    v01 = (v1[0]-v0[0], v1[1]-v0[1], v1[2]-v0[2])
    v02 = (v2[0]-v0[0], v2[1]-v0[1], v2[2]-v0[2])
    
    nx = v01[1]*v02[2] - v01[2]*v02[1]
    ny = v01[2]*v02[0] - v01[0]*v02[2]
    nz = v01[0]*v02[1] - v01[1]*v02[0]
    
    D = -(nx*v0[0] + ny*v0[1] + nz*v0[2])
    
    # We want x such that nx*x + ny*p_yz[0] + nz*p_yz[1] + D = 0
    # nx*x = - (ny*p_yz[0] + nz*p_yz[1] + D)
    # x = - (ny*p_yz[0] + nz*p_yz[1] + D) / nx
    
    if nx == 0:
        # Triangle is parallel to x-axis or degenerate in x. 
        # This case is not explicitly handled in the source notes.
        # [G] Return a value that ensures no voxels are flipped or handle as error.
        return float('inf')
        
    q = -(ny * p_yz[0] + nz * p_yz[1] + D) / nx
    return q
```

## Operating characteristics
*   **Time Complexity:** The complexity is proportional to the sum of the number of voxel columns covered by each triangle. For a triangle covering $C$ columns, the work is $O(C)$. Since $C$ varies significantly between triangles, warp divergence is high when triangles are processed in groups [S1].
*   **Memory Complexity:** $O(n_x n_y n_z)$ for the voxel grid.
*   **Performance:** The method suffers from high memory bandwidth requirements, especially for large voxel grids, because it flips all voxels in the derived $x$ range for every column [S1]. Furthermore, many atomic XOR operations may need to be sequentialized due to contention, negatively affecting performance [S1].
*   **Strengths:** Simple implementation; data-parallel over primitives; no need for complex acceleration structures like BVHs for the voxelization step itself.
*   **Limitations:** Poor warp utilization due to varying column counts; high memory bandwidth usage; potential for race conditions if atomic operations are not handled correctly (though atomic XOR mitigates overwriting issues, it doesn't solve bandwidth bottlenecks).

## Background
The method was introduced in the paper "Fast parallel surface and solid voxelization on GPUs" [S1]. It is part of a family of GPU-accelerated voxelization techniques that parallelize over input primitives rather than output pixels or voxels. The approach builds on standard rasterization concepts, specifically the top-left fill rule, to ensure watertightness and consistency in solid voxelization.
