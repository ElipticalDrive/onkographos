# Triangle-Parallel Solid Voxelization

Also called: direct triangle-parallel solid voxelization

## Overview
Triangle-Parallel Solid Voxelization is a data-parallel algorithm that maps a triangle mesh into a discrete 3D voxel grid by dedicating one processing thread to each triangle [S1]. It solves the problem of converting surface geometry into a volumetric representation suitable for ray marching or volume rendering by determining the interior of the mesh via ray-casting along the primary axis [S1]. Unlike sibling methods that parallelize over voxels or tiles, this approach parallelizes over the input primitives, making it highly suitable for GPU architectures where thread count matches triangle count [S1]. It differs from [Per-Pixel Linked List Voxelization](1187-per-pixel-linked-list-voxelization.md) by operating in 3D space directly rather than projecting to 2D screens, and from [Compute Shader Triangle Voxelization](12867-compute-shader-triangle-voxelization.md) by using a simpler column-based iteration rather than solving plane equations for every candidate voxel in a 2D footprint [S1, 12867].

## How it works
**Inputs:** A set of triangles defined by three vertices each, a 3D voxel grid of resolution $(n_x, n_y, n_z)$, and a consistent vertex winding order for all triangles [S1].
**Outputs:** A 3D boolean array (or bitfield) `voxels[n_x][n_y][n_z]` where `true` indicates the voxel center is inside the mesh [S1].
**Data Structures:**
*   `voxels`: A 3D array of bits/booleans. Size $n_x \times n_y \times n_z$.
*   `triangle`: Struct containing three 3D vertices $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$.

**Parameters:**
*   Voxel size: 1 unit in voxel space [S1].
*   Coordinate system: Voxel $(i, j, k)$ corresponds to the center at $(i, j, k)$ [S1].

**Algorithm Steps:**

1.  **Thread Assignment:** Assign one thread to each triangle in the input mesh [S1].
2.  **Bounding Box Calculation:** For the assigned triangle, compute the bounding box of its projection onto the $yz$-plane. Determine the integer range of voxel indices $[j_{min}, j_{max}]$ and $[k_{min}, k_{max}]$ that contain the triangle's projection [S1].
3.  **Column Iteration:** If the range is non-empty, iterate over all voxel columns $(j, k)$ within $[j_{min}, j_{max}] \times [k_{min}, k_{max}]$ [S1].
4.  **2D Containment Test:** For each column, let $\mathbf{p}_{yz} = (j, k)$ be the center of the voxel in the $yz$-plane. Test if $\mathbf{p}_{yz}$ lies inside the triangle's $yz$-projection using edge functions [S1].
    *   For each edge $i \in \{0, 1, 2\}$, define the edge normal in the $yz$-plane $\mathbf{n}_{yz}^{e_i}$ and the offset $d_{yz}^{e_i}$ [S1]:
        $$ d_{yz}^{e_i} = -\langle \mathbf{n}_{yz}^{e_i}, \mathbf{v}_{i,yzi} \rangle $$
        where $\mathbf{v}_{i,yzi}$ is the $yz$-component of the $i$-th vertex of the triangle [S1].
    *   Apply the **top-left fill rule** to handle shared edges/vertices consistently and avoid double-counting [S1]:
        *   Ignore an edge if it is not a "left" or "top" edge.
        *   An edge is a **left edge** if $n_{yz}^{e_i, y} > 0$.
        *   An edge is a **top edge** if $n_{yz}^{e_i, y} = 0$ and $n_{yz}^{e_i, z} < 0$.
    *   Define a bias term $f_{yz}^{e_i}$:
        $$ f_{yz}^{e_i} = \begin{cases} \epsilon & \text{if edge } i \text{ is left or top} \\ 0 & \text{otherwise} \end{cases} $$
        where $\epsilon$ is the smallest positive floating-point number [S1].
    *   The point is inside if:
        $$ \bigwedge_{i=0}^2 \left( \langle \mathbf{n}_{yz}^{e_i}, \mathbf{p}_{yz} \rangle + d_{yz}^{e_i} + f_{yz}^{e_i} > 0 \right) $$
        [S1].
5.  **X-Axis Projection:** If the containment test passes, project the voxel center $(j, k)$ along the $x$-axis onto the triangle's plane to find the intersection $x$-coordinate $q$ [S1].
6.  **Voxel Range Determination:** Calculate the range of voxel indices along the $x$-axis that are "below" the triangle surface. The range starts at $\bar{q} = \lfloor q + 0.5 \rfloor$ (note: source text says $\lfloor q + 2 \rfloor$ but context implies rounding to nearest integer for center-based voxelization, typically $\lfloor q + 0.5 \rfloor$ or similar; however, the source explicitly writes $\lfloor q + 2 \rfloor$ which appears to be a typo for $0.5$ or a specific offset. Given "voxel size is 1" and "center", standard rounding is $\lfloor q + 0.5 \rfloor$. The source text "⌊*q + 2 ⌋" is likely a transcription error for $0.5$ or similar. We will use the standard interpretation of "voxels whose corresponding bits have to be flipped" starting from the intersection. The source says "yields the x range $\lfloor q + 2 \rfloor =: \bar{q}, \dots, n_x - 1$". This is physically inconsistent with standard voxelization unless $q$ is scaled. Assuming standard voxel space where voxel size is 1, the start index is typically $\lfloor q + 0.5 \rfloor$. We will note the source's specific formula but implement the logical intent: flip from intersection to end [S1]).
    *   *Correction based on strict source adherence:* The source states the range is $\lfloor q + 2 \rfloor =: \bar{q}, \dots, n_x - 1$. This is likely a typo for $\lfloor q + 0.5 \rfloor$. We will define $\bar{q}$ as the first voxel index along $x$ that is inside.
    *   Range: $i \in [\bar{q}, n_x - 1]$ [S1].
7.  **Atomic Flip:** For each $i$ in the range, flip the state of `voxels[i][j][k]` using an atomic XOR operation [S1].

**Pseudocode:**

```python
import math

def triangle_parallel_solid_voxelization(triangles, nx, ny, nz):
    """
    Voxelize a mesh using the triangle-parallel solid voxelization method.
    
    Args:
        triangles: List of tuples (v0, v1, v2), where each v is (x, y, z).
        nx, ny, nz: Dimensions of the voxel grid.
        
    Returns:
        voxels: 3D list of booleans, initialized to False.
    """
    # Initialize voxel grid. 
    # Using a flat list for memory efficiency in implementation, 
    # but logically 3D.
    voxels = [False] * (nx * ny * nz)

    # Helper to get index
    def idx(x, y, z):
        return x * ny * nz + y * nz + z

    # Process each triangle in parallel (simulated here sequentially)
    for v0, v1, v2 in triangles:
        # 1. Determine bounding box in yz plane
        y_coords = [v0[1], v1[1], v2[1]]
        z_coords = [v0[2], v1[2], v2[2]]
        
        j_min = int(math.floor(min(y_coords)))
        j_max = int(math.ceil(max(y_coords)))
        k_min = int(math.floor(min(z_coords)))
        k_max = int(math.ceil(max(z_coords)))
        
        # Clamp to grid bounds
        j_min = max(0, j_min)
        j_max = min(ny - 1, j_max)
        k_min = max(0, k_min)
        k_max = min(nz - 1, k_max)
        
        if j_min > j_max or k_min > k_max:
            continue

        # Precompute edge normals and offsets for the triangle's yz projection
        # Vertices in yz plane
        verts_yz = [(v0[1], v0[2]), (v1[1], v1[2]), (v2[1], v2[2])]
        
        edges = []
        for i in range(3):
            p1 = verts_yz[i]
            p2 = verts_yz[(i + 1) % 3]
            
            # Edge vector
            ex = p2[0] - p1[0]
            ey = p2[1] - p1[1]
            
            # Normal pointing to the left of the edge (in yz plane)
            # Standard 2D normal (-ey, ex) or (ey, -ex) depends on winding.
            # Assuming consistent winding (e.g., counter-clockwise), 
            # the interior is to the left.
            # Normal n = (-dy, dx)
            nx_val = -ey
            ny_val = ex
            
            # Normalize not strictly necessary for sign test, but good for consistency
            length = math.sqrt(nx_val**2 + ny_val**2)
            if length == 0:
                continue
                
            nx_val /= length
            ny_val /= length
            
            # Offset d = -<n, v_i>
            d_val = -(nx_val * p1[0] + ny_val * p1[1])
            
            # Determine if left or top edge for fill rule
            # Left edge: n_y > 0
            # Top edge: n_y == 0 and n_z < 0
            is_left = ny_val > 0
            is_top = (abs(ny_val) < 1e-9) and (nx_val < 0) # n_z is nx_val in yz plane? 
            # Wait, n_yz = (n_y, n_z). 
            # In code: nx_val is n_y component, ny_val is n_z component?
            # Let's stick to vector notation: n = (n_y, n_z).
            # p1 = (y, z).
            # Edge vector e = (dy, dz).
            # Normal n = (-dz, dy).
            
            # Re-evaluating normal components for clarity
            # n_y = -dz
            # n_z = dy
            
            n_y = -ey
            n_z = ex
            
            # Check fill rule criteria
            # Left: n_y > 0
            # Top: n_y == 0 and n_z < 0
            
            is_left_edge = n_y > 0
            is_top_edge = (abs(n_y) < 1e-9) and (n_z < 0)
            
            f_val = 1e-9 if (is_left_edge or is_top_edge) else 0.0
            
            edges.append({
                'n_y': n_y,
                'n_z': n_z,
                'd': d_val,
                'f': f_val
            })

        # 2. Loop over voxel columns
        for j in range(j_min, j_max + 1):
            for k in range(k_min, k_max + 1):
                # Test containment in yz plane
                p_yz = (j, k)
                inside_yz = True
                
                for edge in edges:
                    # Test: <n, p_yz> + d + f > 0
                    val = (edge['n_y'] * p_yz[0] + edge['n_z'] * p_yz[1]) + edge['d'] + edge['f']
                    if val <= 0:
                        inside_yz = False
                        break
                
                if not inside_yz:
                    continue
                
                # 3. Project along x-axis
                # Plane equation: A*x + B*y + C*z + D = 0
                # Compute plane normal from 3D vertices
                v0_v1 = (v1[0]-v0[0], v1[1]-v0[1], v1[2]-v0[2])
                v0_v2 = (v2[0]-v0[0], v2[1]-v0[1], v2[2]-v0[2])
                
                # Cross product for normal
                nx_plane = v0_v1[1]*v0_v2[2] - v0_v1[2]*v0_v2[1]
                ny_plane = v0_v1[2]*v0_v2[0] - v0_v1[0]*v0_v2[2]
                nz_plane = v0_v1[0]*v0_v2[1] - v0_v1[1]*v0_v2[0]
                
                # Plane constant
                d_plane = -(nx_plane*v0[0] + ny_plane*v0[1] + nz_plane*v0[2])
                
                # Solve for x given y=j, z=k
                # nx*x + ny*j + nz*k + d = 0 => x = -(ny*j + nz*k + d) / nx
                if abs(nx_plane) < 1e-9:
                    continue # Triangle parallel to x-axis, skip or handle degenerate
                
                q = -(ny_plane * j + nz_plane * k + d_plane) / nx_plane
                
                # 4. Determine x range
                # Source says: floor(q + 2) = q_bar. 
                # This is likely a typo for floor(q + 0.5). 
                # We use standard rounding to nearest integer for center.
                q_bar = int(math.floor(q + 0.5))
                
                # Clamp start to grid
                q_bar = max(0, q_bar)
                
                # 5. Flip voxels from q_bar to nx-1
                for i in range(q_bar, nx):
                    # Atomic XOR simulation (since Python lists aren't atomic, 
                    # in GPU this is atomic_xor)
                    current = voxels[idx(i, j, k)]
                    voxels[idx(i, j, k)] = not current
```

## Subtopics

### [Compute Shader Triangle Voxelization](12867-compute-shader-triangle-voxelization.md)
A compute shader technique for voxelizing large triangles by iterating over a 2D bounding box in the plane of the triangle and testing for collisions, designed to handle triangles that span many voxels more efficiently than per-voxel rasterization. It differs from standard rasterization-based voxelization by explicitly solving the plane equation for every candidate voxel within the triangle's 2D footprint, allowing for precise solid voxelization and texture coordinate interpolation without relying on hardware rasterization pipelines.

## Operating characteristics
*   **Time Complexity:** $O(T \cdot C \cdot L)$, where $T$ is the number of triangles, $C$ is the average number of voxel columns intersected by a triangle, and $L$ is the average length of the voxel column (number of voxels flipped along $x$) [S1].
*   **Memory Complexity:** $O(N_x N_y N_z)$ for the voxel grid [S1].
*   **Performance:** The method suffers from warp divergence because the number of relevant voxel columns varies significantly among triangles processed by one warp, leading to underutilization [S1]. For larger voxel grids, flipping all voxels in the derived $x$ range poses high memory bandwidth requirements [S1]. Many atomic operations may have to be sequentialized, negatively affecting performance [S1].
*   **Strengths:** Simple parallelization model (one thread per triangle); robust handling of solid interiors via ray casting [S1].
*   **Limitations:** High memory bandwidth usage for large grids; poor warp efficiency due to irregular workloads [S1].
*   **When to use:** Small to medium voxel grids; meshes with relatively uniform triangle distribution; when simplicity of implementation is prioritized over peak performance [S1].
*   **When not to use:** Very large voxel grids where memory bandwidth is a bottleneck; meshes with highly variable triangle sizes causing severe warp divergence [S1].

## Background
The method was introduced in the paper "Fast parallel surface and solid voxelization on GPUs" [S1]. It is part of a family of GPU-accelerated voxelization techniques that parallelize over primitives rather than voxels or tiles [S1].
