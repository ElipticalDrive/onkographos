# Height Curve Activation & Voxel Column Generation

Also called: Heightmap to Voxel Mesh Conversion

## Overview
This method transforms a normalized 2D noise heightmap into a 3D voxel column structure by applying a hyperbolic tangent activation function to smooth terrain features, clamping values to a water line, and stacking voxels from a defined ground offset to the calculated height [S1, unofficial]. It differs from simple linear extrusion by using a non-linear activation curve to compress extreme noise values, providing more natural-looking terrain profiles, and explicitly handles color mapping based on discrete terrain bands [S1, unofficial].

## How it works
**Inputs:**
- `noise_map`: A 2D grid of normalized noise values (typically floats in $[-1, 1]$ or $[0, 1]$ depending on implementation, here assumed normalized for the tanh input).
- `color_map`: A structure defining terrain bands (start/end levels) and associated color indices.
- `zscale`: A scaling factor to convert normalized height to world units (voxel depth).
- `ground`: The base voxel Y-coordinate (or Z-coordinate in this specific implementation's coordinate system) for the floor.

**Outputs:**
- A 3D voxel mesh (e.g., `VoxFile`) containing stacked voxels representing the terrain.

**Data Structures:**
The implementation uses a `MeshMap` struct to hold the processing state [S1, unofficial]:
- `zscale`: `f64`, scaling factor for height.
- `ground`: `u8`, base height offset.
- `map`: `Vec<Vec<u8>>`, the resulting 2D grid of voxel heights.
- `color_map`: `Option<&'a ColorMap>`, reference to terrain color definitions.
- `noise_map`: `Option<&'a NoiseMap>`, reference to input noise data.

The `ColorMap` contains a list of `Terrain` objects, each defined by:
- `name`: String identifier.
- `color_index`: `u8`, index into the voxel palette.
- `start_level`: `u8`, inclusive lower bound of the height band.
- `end_level`: `u8`, inclusive upper bound of the height band.

**Steps:**

1.  **Initialize MeshMap**: Create the `MeshMap` with the provided `zscale`, `ground`, and references to the `noise_map` and `color_map`. Initialize the `map` grid with dimensions matching the `noise_map`.

2.  **Process Each Pixel**: Iterate through every coordinate $(x, y)$ in the `noise_map` [S1, unofficial]:
    a.  **Retrieve Noise**: Get the raw noise value $n$ at $(x, y)$.
    b.  **Apply Activation**: Apply the hyperbolic tangent activation function to smooth the height. The formula is [S1, unofficial]:

3.  **Generate Voxels**: Iterate through the `map` grid again [S1, unofficial]:
    a.  **Get Top Voxel**: For each $(x, y)$, retrieve $z = map[x][y]$.
    b.  **Map Color**: Calculate the relative height $h_{rel} = z - ground$. Look up the color index using `color_map.get_terrain_color(h_{rel})`.
        - The `get_terrain_color` function iterates through the `Terrain` list and returns the `color_index` of the first `Terrain` where `start_level <= h_{rel} <= end_level`.
        - If no terrain band matches, return an error: "Unable to map height: {h_{rel}}".
    c.  **Add Top Voxel**: Create a `Voxel` at $(x, y, z)$ with the mapped color index. Add it to the voxel model.
    d.  **Fill Column**: If $z > ground$, iterate downwards from $z-1$ to $ground$ (inclusive) [S1, unofficial]:
        i.  Calculate relative height $h_{rel\_col} = zp - ground$.
        ii. Look up color index for $h_{rel\_col}$. If None, return error.
        iii. Create `Voxel` at $(x, y, zp)$ with the mapped color index.
        iv. Add voxel to the model. If the model rejects the voxel (e.g., out of bounds), return error "Unable to add voxel, does it fit inside the model?".

**Parameters:**
- `zscale`: Not given in the sources. Typical values depend on the desired terrain resolution.
- `ground`: Not given in the sources. Typically 0 or a small positive integer.
- Activation Factor: 1.5 (from $\tanh(n \times 1.5)$).
- Water Line: The source mentions "clamping to a water line" in the Overview, but the code snippet does not show explicit clamping to a water level in the `z` calculation. The `Terrain` for water is defined as levels 0-6. This implies water is a terrain band, not a hard clamp on height. The "water line" might refer to the visual representation or a separate logical step not detailed in the code. We note the discrepancy.

**Edge Cases and Pitfalls:**
- **Color Mapping Failure**: If the calculated relative height $z - ground$ falls outside all defined `Terrain` bands in the `color_map`, `get_terrain_color` returns `None`. This causes the generation to fail with the error "Unable to map height" [S1, unofficial]. Ensure the `color_map` covers the full range of possible heights $[0, zscale]$.
- **Voxel Bounds**: If the calculated $z$ exceeds the depth of the target voxel model, `add_voxel` may fail. Ensure the model depth is sufficient for the maximum possible height.
- **Precision**: Casting to `u8` truncates floating-point values. Ensure `zscale` and `ground` are chosen to avoid overflow or underflow.

**Pseudocode:**

```python
import math

def generate_terrain(noise_map, color_map, zscale, ground, model):
    """
    Generates a voxel terrain from a noise map using tanh activation.
    
    Args:
        noise_map: 2D array of floats (normalized noise).
        color_map: Object with method get_terrain_color(relative_height) -> int.
        zscale: float, scaling factor for height.
        ground: int, base height.
        model: Object with method add_voxel(x, y, z, color_index) -> bool.
        
    Returns:
        True if successful, raises ValueError on failure.
    """
    height = len(noise_map)
    width = len(noise_map[0])
    
    # Step 1: Process noise and calculate heights
    map_heights = [[0] * width for _ in range(height)]
    
    for y in range(height):
        for x in range(width):
            # Get raw noise value
            n = noise_map[y][x]
            
            # Apply tanh activation with factor 1.5
            # Note: Source uses (x * 1.5).tanh(). Assuming x is noise value.
            activated = math.tanh(n * 1.5)
            
            # Scale and add ground
            # Cast to u8 (truncate)
            z = int(activated * zscale) + ground
            
            # Clamp to u8 range if necessary, though source doesn't explicitly show clamp
            # Assuming zscale and ground keep it in range, or truncation handles it.
            # Pitfall: if z < 0 or z > 255, it might cause issues.
            if z < 0:
                z = 0
            if z > 255:
                z = 255
                
            map_heights[y][x] = z

    # Step 2: Generate voxels
    for y in range(height):
        for x in range(width):
            z = map_heights[y][x]
            
            # Get color for top voxel
            rel_height = z - ground
            color_index = color_map.get_terrain_color(rel_height)
            
            if color_index is None:
                raise ValueError(f"Unable to map height: {rel_height}")
            
            # Add top voxel
            if not model.add_voxel(x, y, z, color_index):
                raise ValueError("Unable to add voxel, does it fit inside the model?")
            
            # Fill column downwards
            if z > ground:
                for zp in range(z - 1, ground - 1, -1):
                    rel_height_col = zp - ground
                    color_index_col = color_map.get_terrain_color(rel_height_col)
                    
                    if color_index_col is None:
                        raise ValueError(f"Unable to map height: {rel_height_col}")
                    
                    if not model.add_voxel(x, y, zp, color_index_col):
                        raise ValueError("Unable to add voxel, does it fit inside the model?")

    return True
```

## Operating characteristics
- **Time Complexity**: $O(W \times H \times D)$, where $W$ and $H$ are the noise map dimensions and $D$ is the average column depth. The nested loops iterate over all pixels and then over the column height.
- **Memory Complexity**: $O(W \times H)$ for the intermediate `map` grid, plus the memory for the voxel model itself.
- **Strengths**: Simple to implement; the tanh activation provides smooth, natural-looking terrain transitions without complex filtering.
- **Limitations**: The color mapping is discrete and can result in banding if terrain bands are not carefully defined. The method does not handle overhangs or caves (it is a heightmap-based extrusion). Performance is linear with respect to the number of voxels, which can be large for high-resolution maps.
- **When to use**: Ideal for generating simple, 2D-height-based terrain for voxel games or visualizations where performance is critical and complex geometry is not required.
- **When not to use**: When overhangs, caves, or non-heightmap-based geometry is needed.
