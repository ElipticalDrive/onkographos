# Porous Voxelization

Also called: Random Voxel Dropping

## Overview
Porous Voxelization is a voxelization technique that generates porous or sponge-like meshes by randomly discarding voxels during the voxelization process based on a spatial hash of their coordinates [S1, unofficial]. Unlike standard voxelization which retains all computed voxels, this method selectively removes voxels to create a porous structure while maintaining spatial distribution properties [S1, unofficial]. It is implemented in the `voxelizer-rs` project as part of the `MeshProcessor::voxelize` method [S1, unofficial].

## How it works
**Inputs:**
- A mesh to voxelize.
- Voxel resolution/grid parameters, handled by the parent surface or solid voxelization loop [S1, unofficial].
- `porosity`: An optional floating-point value `Option<f64>` specifying the threshold for voxel retention [S1, unofficial].

**Outputs:**
- A set of voxels forming a porous mesh [S1, unofficial].

**Data Structures:**
- A boolean flag `final_keep` tracks whether a voxel is initially valid before porosity checks [S1, unofficial].
- A hash value `hash` is computed per voxel [S1, unofficial].

**Steps:**
1. Iterate through each voxel generated in the surface or solid voxelization loop [S1, unofficial].
2. Compute a hash value using the voxel's coordinates: `hash = |fract(sin(dot) * 43758.5453)|`, where `dot` is derived from the voxel coordinates [S1, unofficial].
3. If `porosity` is `Some(p)`, check if the computed hash is greater than or equal to `p` [S1, unofficial]. If `hash >= p`, keep the voxel; otherwise, discard it [S1, unofficial].
4. The check is performed using a let-chain logic: `if final_keep && let Some(p) = porosity { ... }` where the hash comparison determines retention [S1, unofficial].

**Pseudocode:**
```python
import math
from typing import List, Tuple, Optional

def porous_voxelization(voxel_coords: List[Tuple[float, float, float]], porosity: Optional[float]) -> List[Tuple[float, float, float]]:
    kept = []
    for x, y, z in voxel_coords:
        # [G] The source does not specify how 'dot' is derived from voxel coordinates.
        # Standard spatial hashing typically uses a dot product with a fixed vector.
        dot = x * 12.9898 + y * 78.233 + z * 45.164
        hash_val = abs((math.sin(dot) * 43758.5453) % 1.0)
        final_keep = True  # [G] Represents validity from parent surface/solid voxelization loop
        if final_keep:
            if porosity is not None:
                if hash_val >= porosity:
                    kept.append((x, y, z))
            else:
                kept.append((x, y, z))
    return kept
```

**Parameters:**
- `porosity`: `Option<f64>`. Valid values are in the range `[0.0, 1.0]` [S1, unofficial]. If `None`, no voxels are dropped [S1, unofficial].

**Edge Cases and Pitfalls:**
- Invalid porosity values (outside `0.0..=1.0` or `NaN`) passed directly to the library API (`MeshProcessor::voxelize`) are not validated, leading to misleading results [S1, unofficial].
- `Some(1.5)` causes every kept voxel to fail the retention check, effectively dropping all valid voxels [S1, unofficial].
- `Some(-0.5)` or `Some(NaN)` effectively disables dropping [S1, unofficial].
- The CLI interface includes a `validate_porosity` parser that verifies the value falls between `0.0` and `1.0`, but the library API does not [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Not given in the sources.

**Measured Performance:**
- A test `test_voxelize_porosity` verifies that setting `porosity = 0.5` significantly reduces the number of generated voxels compared to the baseline voxelization [S1, unofficial].

**Strengths and Limitations:**
- Strength: Creates porous/sponge-like generated meshes [S1, unofficial].
- Limitation: Invalid inputs to the library API can lead to silent errors and misleading results [S1, unofficial].

**When to Use:**
- When a porous or sponge-like mesh structure is desired [S1, unofficial].
