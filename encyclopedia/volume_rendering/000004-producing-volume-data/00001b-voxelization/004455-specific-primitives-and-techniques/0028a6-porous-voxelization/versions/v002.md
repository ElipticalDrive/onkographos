# Porous Voxelization

Also called: Random Voxel Dropping

## Overview
Porous Voxelization is a voxelization technique that generates porous or sponge-like meshes by randomly discarding voxels during the voxelization process based on a spatial hash of their coordinates [S1, unofficial]. Unlike standard voxelization methods which retain all computed voxels, this technique selectively removes voxels using a deterministic pseudo-random hash, maintaining spatial distribution properties while reducing voxel count [S1, unofficial]. It is distinct from probabilistic sampling methods by using a fixed threshold parameter `p` where a voxel is kept if its hash value is greater than or equal to `p` [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Candidate voxels generated by a parent voxelization method, represented by their integer grid coordinates $(i, j, k)$ [S1, unofficial].
- **Parameter:** `porosity`: An optional floating-point value $p \in [0.0, 1.0]$ specifying the threshold for voxel retention [S1, unofficial].
- **Output:** A subset of the input voxels that pass the retention test [S1, unofficial].

**Data Structures:**
- Voxel coordinates are stored as integer tuples or vectors $(i, j, k)$ [S1, unofficial].
- The hash function operates on these coordinates to produce a scalar value [S1, unofficial].

**Steps:**
1. For each voxel generated by the parent voxelization algorithm, extract its integer grid coordinates $(i, j, k)$ [S1, unofficial].
2. Compute a scalar value `dot` derived from the voxel coordinates $(i, j, k)$ [S1, unofficial].
3. Compute a spatial hash value $h$ using the formula: $h = \left| \text{fract}(\sin(\text{dot}) \times 43758.5453) \right|$ [S1, unofficial].
4. If `porosity` is `Some(p)`, check if $h \ge p$ [S1, unofficial].
5. If the condition is met, keep the voxel; otherwise, discard it [S1, unofficial].
6. If `porosity` is `None`, keep all voxels without filtering [S1, unofficial].

**Pseudocode:**
```python
import math

def porous_voxelization(voxels: list[tuple[int, int, int]], porosity: float | None) -> list[tuple[int, int, int]]:
    """Filter voxels based on a porous threshold."""
    if porosity is None:
        return voxels

    # Validate porosity range [G]
    if not (0.0 <= porosity <= 1.0):
        raise ValueError("Porosity must be between 0.0 and 1.0")

    kept_voxels = []
    for (i, j, k) in voxels:
        # Compute scalar dot from coordinates using standard sine hash constants [G]
        dot = i * 12.9898 + j * 78.233 + k * 45.164
        # Compute hash: (dot.sin() * 43758.5453).fract().abs()
        sin_val = math.sin(dot)
        scaled = sin_val * 43758.5453
        fract_part = scaled - math.floor(scaled)
        hash_val = abs(fract_part)

        if hash_val >= porosity:
            kept_voxels.append((i, j, k))
    return kept_voxels
```

**Parameters:**
- `porosity` ($p$): The threshold for voxel retention. Valid range $[0.0, 1.0]$ [S1, unofficial]. A value of $0.0$ keeps all voxels since $h \ge 0$ is always true, and $1.0$ keeps no voxels since $h < 1$ is always true for the fractional part [G]. This matches the implementation behavior where $p=0.5$ significantly reduces the generated voxel count [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Invalid Input:** Passing `porosity` values outside $[0.0, 1.0]$ or `NaN` to the core logic without validation leads to undefined or misleading behavior [S1, unofficial]. For example, $p=1.5$ causes all voxels to fail the retention check, effectively dropping all voxels, while $p=-0.5$ or `NaN` disables dropping or causes errors [S1, unofficial].
- **Determinism:** The hash is deterministic based on coordinates, ensuring reproducible porous structures for the same input mesh and resolution [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of candidate voxels, as the hash computation is constant time per voxel [G].
- **Memory Complexity:** $O(N)$ for the output list of kept voxels [G].
- **Performance:** Reduces the number of voxels in the final volume, which can speed up subsequent rendering or processing steps [S1, unofficial].
- **Strengths:** Simple to implement, deterministic, reduces data size while maintaining spatial distribution [S1, unofficial].
- **Limitations:** Creates a non-manifold or disconnected structure if porosity is high, making it unsuitable for applications requiring solid, watertight volumes without further processing [G].

It is designed to generate porous or sponge-like meshes by randomly discarding voxels during the voxelization process based on a spatial hash of their coordinates [S1, unofficial].
