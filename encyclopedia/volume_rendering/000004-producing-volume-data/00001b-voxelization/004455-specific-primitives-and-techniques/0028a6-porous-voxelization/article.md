# Porous Voxelization

Also called: Random Voxel Dropping

## Overview
Porous Voxelization is a voxelization technique that generates porous or sponge-like meshes by randomly discarding voxels during the voxelization process based on a spatial hash of their coordinates [S1, unofficial]. Unlike standard voxelization which retains all computed voxels, this method selectively removes voxels to create a porous structure while maintaining spatial distribution properties [S1, unofficial]. It is implemented in the `voxelizer-rs` project as part of the `MeshProcessor::voxelize` method [S1, unofficial].

## How it works
**Inputs:**
- A mesh to voxelize.
- Voxel resolution/grid parameters (implied by the context of surface or solid voxelization loops).
- `porosity`: An optional floating-point value `Option<f64>` specifying the threshold for voxel retention [S1, unofficial].

**Outputs:**
- A set of voxels forming a porous mesh [S1, unofficial].

**Data Structures:**
- The implementation uses a boolean flag `final_keep` to track whether a voxel is initially valid before porosity checks [S1, unofficial].
- A hash value `hash` is computed for each voxel [S1, unofficial].

**Steps:**
1. Iterate through each voxel generated in the surface or solid voxelization loop [S1, unofficial].
2. Compute a hash value using the voxel's coordinates. Let `dot` be derived from the voxel coordinates. The hash is calculated as:
   $$ hash = | \text{fract}( \sin(dot) \times 43758.5453 ) | $$
   where `fract` extracts the fractional part and `abs` takes the absolute value [S1, unofficial].
3. If `porosity` is `Some(p)`, check if the computed hash is greater than or equal to `p`. If `hash >= p`, keep the voxel; otherwise, discard it [S1, unofficial].
4. The check is performed using a let-chain logic: `if final_keep && let Some(p) = porosity { ... }` where the hash comparison determines if the voxel is kept [S1, unofficial].

**Parameters:**
- `porosity`: `Option<f64>`. Valid values are in the range `[0.0, 1.0]`. If `None`, no voxels are dropped [S1, unofficial].

**Edge Cases and Pitfalls:**
- Invalid porosity values (outside `0.0..=1.0` or `NaN`) passed directly to the library API (`MeshProcessor::voxelize`) are not validated, leading to misleading results [S1, unofficial].
- `Some(1.5)` causes every kept voxel to fail the `hash < p` check (effectively dropping all if logic is inverted or none if logic is correct but threshold is unreachable) [S1, unofficial].
- `Some(-0.5)` or `Some(NaN)` effectively disables dropping [S1, unofficial].
- The CLI interface includes a `validate_porosity` parser that verifies the value falls between `0.0` and `1.0`, but the library API does not [S1, unofficial].
