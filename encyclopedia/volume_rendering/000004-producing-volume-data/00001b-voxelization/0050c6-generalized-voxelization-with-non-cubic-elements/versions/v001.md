# Generalized Voxelization with Non-Cubic Elements

Also called: Palette-based voxelization, Voxelization using elements of different shapes

## Overview
This method approximates a 3D polygonal object $O$ using a discrete set of elements $P$ from a predefined palette, where each element is bounded by and contained within a single voxel $V$ of a regular grid [S1, unofficial]. Unlike standard voxelization which assigns binary values (empty/full) to cubic voxels, this approach minimizes approximation error by selecting the best-fitting non-cubic shape from the palette for partial intersections, without increasing memory occupation [S1, unofficial]. It differs from surface-reconstruction methods like Marching Cubes or extended cuberille models by focusing on volumetric approximation for artistic recreation rather than surface visualization [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
1.  **Object $O$**: A 3D polygonal object, typically a closed two-manifold surface [S1, unofficial].
2.  **Grid**: A regular 3D grid of voxels $V$ with resolution $(N_x, N_y, N_z)$ and dimensions $(x_l, y_l, z_l)$ per voxel [S1, unofficial].
3.  **Palette $P$**: A set of possible elements $P = \{E_0, \dots, E_n\}$ where $n \ge 1$. $E_0 = \emptyset$ (empty) and $E_1 = V$ (full cubic voxel). Other elements are polyhedrons with rectangular and diagonal faces, including transformations like mirroring and axis swapping [S1, unofficial].

**Outputs:**
*   A voxel grid where each voxel $(i, j, k)$ is assigned an element index $e_{i,j,k} \in \{0, \dots, n\}$ corresponding to the best-matching element $E_{e_{i,j,k}} \in P$ [S1, unofficial].

### Data Structures
*   **Voxel Grid**: A 3D array of integers of size $N_x \times N_y \times N_z$. Each cell stores the index of the selected element from the palette.
*   **Palette $P$**: A list or lookup table of geometric primitives. Each primitive $E_v$ is defined by its geometry (vertices/faces) relative to the voxel local coordinate system $[0, x_l] \times [0, y_l] \times [0, z_l]$.
*   **Object Description Function $o(x, y, z)$**: A boolean or binary function returning 1 if point $(x,y,z)$ is inside object $O$, 0 otherwise. In implementation, this is evaluated via ray-object intersection [S1, unofficial].
*   **Element Description Function $e_v(x, y, z)$**: A boolean or binary function returning 1 if point $(x,y,z)$ is inside element $E_v$, 0 otherwise.

### Numbered Steps

1.  **Partition Space**: Divide the 3D space containing object $O$ into a regular grid of voxels $V$. Each voxel $V$ is a box of size $x_l \times y_l \times z_l$ with center $(x_c, y_c, z_c)$ and integer indices $(i, j, k)$. Points $(x, y, z)$ in voxel $(i, j, k)$ satisfy:
    $$ i \cdot x_l \le x < (i + 1) \cdot x_l, \quad j \cdot y_l \le y < (j + 1) \cdot y_l, \quad k \cdot z_l \le z < (k + 1) \cdot z_l $$
    [S1, unofficial]

2.  **Trivial Assignment**: For each voxel $V$, determine the intersection with $O$.
    *   If $V \subseteq O$ (fully contained), assign $E_1$ (full voxel).
    *   If $V \cap O = \emptyset$ (fully empty), assign $E_0$ (empty).
    *   If $\emptyset \subset V \cap O \subset V$ (partial intersection), proceed to Step 3.
    [S1, unofficial]

3.  **Compute Similarity**: For partial intersections, compute the similarity measure $B_v$ for each element $E_v \in P$. The measure is the normalized integral of a metric $g$ over the voxel volume:
    $$ B_v = \frac{\int_0^{z_l} \int_0^{y_l} \int_0^{x_l} g(e_v(x, y, z), o(x, y, z), x, y, z) \, dx \, dy \, dz}{G} $$
    where $G$ is a normalization constant:
    $$ G = \int_0^{z_l} \int_0^{y_l} \int_0^{x_l} \max_{(H,Z)\in\{0,1\}^2} (g(H, Z, x, y, z)) \, dx \, dy \, dz $$
    [S1, unofficial]

4.  **Select Element**: Select the element $E_{v^*}$ that maximizes $B_v$:
    $$ v^* = \arg \max_{v} B_v $$
    Assign $E_{v^*}$ to the voxel.
    [S1, unofficial]

5.  **Monte Carlo Approximation**: Since analytical integration is complex, approximate $B_v$ using Monte Carlo sampling. Generate a finite set of random points $U$ uniformly distributed inside the voxel space $V$. The approximation $\hat{B}_v$ is:
    $$ \hat{B}_v = \frac{1}{|U|} \sum_{(x,y,z) \in U} g(e_v(x, y, z), o(x, y, z), x, y, z) \approx G \cdot B_v $$
    As $|U| \to \infty$, $\hat{B}_v \to G \cdot B_v$.
    [S1, unofficial]

6.  **Optimization (Column Processing)**: To optimize memory access and computation, process voxels in columns. Fix indices $i$ and $j$, and vary only $k$ (the z-axis). For each column, cast a set $U_r$ of $t$ randomly positioned rays parallel to the z-axis. Each ray is identified by $(x, y) \in [0, x_l] \times [0, y_l]$. Compute intersections of these rays with $O$ to determine $o(x, y, z)$ efficiently for all $z$ in the column.
    [S1, unofficial]

### Formulas and Metrics

The metric $g(e, o, x, y, z)$ measures the difference between the element value $e$ and object value $o$ at a point. Three specific metrics are defined:

1.  **Nearest Approximation**: Minimizes mean squared difference.
    $$ g_N(e, o, x, y, z) = 1 - (e - o)^2 $$
    *   $g_N = 1$ if $e = o$ (match).
    *   $g_N = 0$ if $e \neq o$ (mismatch).
    [S1, unofficial]

2.  **Best Outer Box**: Computes the smallest approximation containing the object. Penalizes cases where the object is full ($o=1$) but the element is empty ($e=0$).
    $$ g_O(e, o, x, y, z) = 2 - (e - o) - \frac{1}{2} \text{step}(e - o) $$
    where $\text{step}(x) = 0$ if $x < 0$, and $1$ otherwise.
    *   Note: The text states this term tends to $-\infty$ when $o=1, e=0$, effectively excluding such elements. Table 1 in the source confirms $g_O = -\infty$ for $e=0, o=1$.
    [S1, unofficial]

3.  **Best Inner Box**: Computes the largest approximation contained in the object. Penalizes cases where the element is full ($e=1$) but the object is empty ($o=0$).
    $$ g_I(e, o, x, y, z) = 2 - (e - o)^2 - \frac{1}{2} \text{step}(o - e) $$
    *   Note: This ensures elements with $e=1, o=0$ are excluded (effectively $-\infty$ penalty).
    [S1, unofficial]

### Pseudocode

```python
import random

def generalized_voxelization(object_mesh, grid_resolution, voxel_size, palette, num_samples):
    """
    Performs generalized voxelization using non-cubic elements.
    
    Args:
        object_mesh: A mesh object supporting ray intersection.
        grid_resolution: Tuple (Nx, Ny, Nz).
        voxel_size: Tuple (xl, yl, zl).
        palette: List of element primitives. Each primitive has a method 
                 contains_point(x, y, z) returning 1 if inside, 0 otherwise.
                 palette[0] is empty, palette[1] is full cube.
        num_samples: Number of Monte Carlo samples per voxel.
        
    Returns:
        grid: 3D array of integers, indices into palette.
    """
    Nx, Ny, Nz = grid_resolution
    xl, yl, zl = voxel_size
    grid = [[[-1 for _ in range(Nz)] for _ in range(Ny)] for _ in range(Nx)]
    
    # Precompute normalization constant G for the chosen metric g
    # G depends only on g, not on the object or element.
    # For simplicity, assume g is fixed (e.g., Nearest Approximation).
    # G = integral of max(g(H,Z)) over voxel volume.
    # For Nearest Approx: max(g) is 1. So G = xl * yl * zl.
    G = xl * yl * zl 
    
    # Define the metric function g based on the desired approximation type
    # Here we use Nearest Approximation as the default example.
    def metric(e, o):
        return 1 - (e - o)**2

    # Helper to check if a point is inside the object
    def is_inside_object(x, y, z):
        # Cast ray from (x,y,z) in any direction or use point-in-mesh test
        # For closed two-manifold surfaces, ray casting is robust.
        # Simplified: assume a function exists that returns 1 if inside, 0 if outside.
        return object_mesh.is_inside(x, y, z)

    # Helper to check if a point is inside an element
    def is_inside_element(element_idx, x, y, z):
        elem = palette[element_idx]
        return elem.contains_point(x, y, z)

    # Process voxels in columns (fix i, j; vary k) for cache efficiency
    for i in range(Nx):
        for j in range(Ny):
            # Generate random rays for this column
            # Each ray is defined by (x_ray, y_ray) in local voxel coords [0, xl] x [0, yl]
            # We generate num_samples rays
            rays = []
            for _ in range(num_samples):
                rx = random.uniform(0, xl)
                ry = random.uniform(0, yl)
                rays.append((rx, ry))
            
            # For each ray, compute intersections with object to determine o(x,y,z) along z
            # This avoids evaluating is_inside_object for every sample point individually
            # Instead, we evaluate o along the ray segments
            
            for k in range(Nz):
                # Local voxel bounds
                z_min = k * zl
                z_max = (k + 1) * zl
                
                # Determine if voxel is trivial
                # Check center point or sample a few points to decide triviality
                # If fully inside or fully empty, assign directly
                # For robustness, we use the Monte Carlo approach for all, 
                # but trivial checks can optimize.
                
                # Check triviality by sampling center
                cx, cy, cz = i*xl + xl/2, j*yl + yl/2, k*zl + zl/2
                o_center = is_inside_object(cx, cy, cz)
                
                # If we assume the object is convex or simple, center check might suffice.
                # For general meshes, we rely on the ray casting below.
                
                best_score = -float('inf')
                best_elem_idx = 0
                
                # Evaluate each element in the palette
                for elem_idx in range(len(palette)):
                    score = 0.0
                    
                    # Monte Carlo integration over the voxel volume
                    # Using the rays generated for the column
                    for rx, ry in rays:
                        # Global coordinates of the ray
                        gx = i * xl + rx
                        gy = j * yl + ry
                        
                        # Sample points along the ray within this voxel's z-range
                        # To approximate the integral, we sample z uniformly in [z_min, z_max]
                        # Or use the intersections to define segments
                        
                        # Simplified: Sample num_samples_z points along z for this ray
                        # But the source suggests using the ray intersections to determine o(x,y,z)
                        # Let's stick to the source's Monte Carlo formula:
                        # sum(g(ev, o, x,y,z)) / |U|
                        
                        # Generate sample points (x,y,z) in the voxel
                        # We reuse the ray x,y and sample z
                        for _ in range(num_samples // num_samples_per_ray): # Adjust sample distribution
                            rz = random.uniform(z_min, z_max)
                            gz = rz
                            
                            # Evaluate o(x,y,z)
                            # Using ray casting for efficiency: 
                            # If we have intersections for this (rx, ry), we can determine o(gx, gy, gz)
                            # For simplicity, we call the general function
                            o_val = is_inside_object(gx, gy, gz)
                            
                            # Evaluate e(x,y,z)
                            # Element is defined in local coords. 
                            # rx, ry, rz are local coords relative to voxel (i,j,k)
                            e_val = is_inside_element(elem_idx, rx, ry, rz)
                            
                            score += metric(e_val, o_val)
                    
                    # Normalize score by number of samples
                    # The source defines B_v approx as sum / |U|
                    # We need to compare B_v values. G is constant for all elements.
                    # So we can just compare the sum of metrics.
                    # However, the number of samples might vary if we optimize.
                    # Let's assume uniform sampling.
                    
                    # Correct normalization:
                    # B_v_hat = (1/|U|) * sum
                    # We want to maximize B_v.
                    # Since |U| is constant for all elements in the same voxel,
                    # we can just maximize the sum.
                    
                    if score > best_score:
                        best_score = score
                        best_elem_idx = elem_idx
                
                grid[i][j][k] = best_elem_idx

    return grid
```

### Parameters and Typical Values
*   **Palette Size ($n$)**: Typically small (e.g., 4-10 basic shapes plus transformations) to keep memory low and selection fast [S1, unofficial].
*   **Number of Samples ($|U|$)**: Depends on desired accuracy. Higher samples reduce noise but increase computation. The source does not specify a fixed number, but notes that $|U| \to \infty$ yields exact results [S1, unofficial].
*   **Voxel Size**: Determined by the desired resolution of the output model.

### Edge Cases and Pitfalls
*   **Infinity Penalties**: The Best Outer Box and Best Inner Box metrics involve terms that tend to $-\infty$ for specific mismatches ($e=0, o=1$ for Outer; $e=1, o=0$ for Inner). Implementation must handle these values to prevent invalid element selection or numerical instability. Using a sufficiently small large negative number or explicit checks is required [S1, unofficial].
*   **Element Constraint**: Elements must be completely contained within the voxel ($E_v \cap V = E_v$). Elements extending beyond voxel boundaries are excluded [S1, unofficial].
*   **Object Topology**: The method assumes closed two-manifold surfaces. Non-closed or self-intersecting meshes may lead to incorrect inside/outside tests [S1, unofficial].

## Operating characteristics

*   **Time Complexity**: $O(N_x N_y N_z \cdot n \cdot |U|)$, where $n$ is the number of elements in the palette and $|U|$ is the number of Monte Carlo samples per voxel. Column processing optimization reduces memory access overhead but not the fundamental complexity [S1, unofficial].
*   **Memory Complexity**: $O(N_x N_y N_z)$ for the output grid. The palette size is negligible. This is the same as standard binary voxelization, fulfilling the goal of not increasing memory occupation [S1, unofficial].
*   **Strengths**:
    *   Better approximation of curved or diagonal surfaces compared to binary voxels.
    *   Low memory footprint.
    *   Suitable for artistic recreation where the "look" of the voxelization matters more than strict volumetric accuracy [S1, unofficial].
*   **Limitations**:
    *   Approximation error is still present, especially for complex geometries with small features.
    *   Computationally expensive due to Monte Carlo integration and ray-object intersections.
    *   Limited to elements contained within a single voxel, restricting the types of shapes that can be represented [S1, unofficial].
*   **When to Use**: Artistic and advertising purposes where the goal is to recreate models using small components that resemble palette elements, emphasizing artistic nature [S1, unofficial].
*   **When Not to Use**: When strict volumetric accuracy is required, or when real-time performance is critical without hardware acceleration.

## Background

*   **Origin**: The method was introduced by Davide Cavagnino and Marco Gribaudo from the University of Turin, Italy, in 2010 [S1, unofficial].
*   **Paper**: "Discretization of 3D models using voxel elements of different shapes," published in the proceedings of the Computer Graphics International (CGI) 2010 conference, edited by O. Deussen and P. Jepp [S1, unofficial].
*   **History**: The work extends traditional voxelization (which uses cubic voxels) by introducing a palette of non-cubic elements. It differentiates itself from surface reconstruction methods like Marching Cubes and extended cuberille models by focusing on volumetric approximation for artistic purposes rather than surface visualization [S1, unofficial].
*   **Usage**: The technique has been used to create models with artistic and advertising purposes, guiding the recreation of original models using geometry instancing in tools like Blender [S1, unofficial].
