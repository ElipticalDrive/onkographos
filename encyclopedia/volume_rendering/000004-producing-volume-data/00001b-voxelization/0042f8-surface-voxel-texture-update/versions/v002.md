# Surface Voxel Texture Update

Also called: Surface Voxel Texture Generation, Surface Voxel to Texture Upload

## Overview
Surface Voxel Texture Update converts discrete surface voxel data into a GPU-accessible 2D texture format for volume rendering [S1, unofficial]. It differs from general voxelization methods by focusing on the specific data layout (position and normal) and OpenGL texture upload mechanics rather than the geometric intersection logic itself [S1, unofficial].

## How it works
**Inputs:**
- `surface_voxels`: A list or array of voxel data. If `None`, a surface voxel structure is generated from `volume_data` [S1, unofficial].
- `volume_data`: The source volumetric data used to generate surface voxels when `surface_voxels` is `None` [S1, unofficial].
- `surface_data.shape`: The dimensions of the source data, used to determine texture width [S1, unofficial].

**Outputs:**
- A 2D OpenGL texture (`surface_voxel_texture`) containing surface voxel data [S1, unofficial].

**Data Structures:**
- **Surface Voxel Array**: A numpy array of shape $(N, 7)$ with `float32` dtype, where each row is $(x, y, z, n_x, n_y, n_z, ?)$ [S1, unofficial].
- **Texture**: A 2D texture with width $W = \min(\text{surface\_data.shape}[0], \text{GL\_MAX\_TEXTURE\_SIZE})$, height $H = 1$, internal format `GL_RGBA32F`, format `GL_RGBA`, type `GL_FLOAT`, min/mag filter `GL_LINEAR`, and S/T wrap mode `GL_CLAMP_TO_EDGE` [S1, unofficial].

**Steps:**
1. **Generate Surface Voxels**: If `surface_voxels` is `None`, call `create_surface_voxel_structure(volume_data)` to generate the voxel list [S1, unofficial].
2. **Convert to Array**: Convert the `surface_voxels` list into a numpy array of shape $(N, 7)$ cast to `float32` [S1, unofficial].
3. **Extract Components**: Extract the first 6 components $(x, y, z, n_x, n_y, n_z)$ from the array for texture data [S1, unofficial].
4. **Determine Dimensions**: Calculate texture width $W$ as $\min(\text{surface\_data.shape}[0], \text{GL\_MAX\_TEXTURE\_SIZE})$ and set height $H=1$ [S1, unofficial].
5. **Upload Texture**: Create a 2D texture with the calculated dimensions and formats. Upload the extracted data, padding or truncating to match the texture's $W \times H \times 4$ float capacity [S1, unofficial].
6. **Set Filters**: Set minification and magnification filters to `GL_LINEAR` [S1, unofficial].
7. **Set Wrapping**: Set S and T wrapping modes to `GL_CLAMP_TO_EDGE` [S1, unofficial].

```python
def update_surface_voxel_texture(surface_voxels, volume_data, surface_data_shape, gl_max_texture_size):
    # Step 1: Generate if None
    if surface_voxels is None:
        surface_voxels = create_surface_voxel_structure(volume_data)
    
    # Step 2: Convert to numpy array of shape (N, 7) cast to float32
    voxel_array = np.array(surface_voxels, dtype=np.float32).reshape(-1, 7)
    
    # Step 3: Extract first 6 components (x, y, z, nx, ny, nz)
    extracted_data = voxel_array[:, :6]
    
    # Step 4: Determine texture dimensions
    width = min(surface_data_shape[0], gl_max_texture_size)
    height = 1
    
    # Step 5: Create and upload texture
    texture_id = gl.glGenTextures(1)
    gl.glBindTexture(gl.GL_TEXTURE_2D, texture_id)
    
    # The source notes specify extracting 6 components but uploading to GL_RGBA32F (4 floats/texel).
    # The exact packing formula is not given in the sources [S1, unofficial].
    # We flatten and pad/truncate to match the required W*H*4 float buffer size.
    flat_data = extracted_data.flatten()
    target_size = width * height * 4
    if len(flat_data) < target_size:
        flat_data = np.pad(flat_data, (0, target_size - len(flat_data)), 'constant')
    elif len(flat_data) > target_size:
        flat_data = flat_data[:target_size]
        
    gl.glTexImage2D(
        gl.GL_TEXTURE_2D, 0,
        gl.GL_RGBA32F, width, height, 0,
        gl.GL_RGBA, gl.GL_FLOAT, flat_data
    )
    
    # Step 6: Set Filters
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_MIN_FILTER, gl.GL_LINEAR)
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_MAG_FILTER, gl.GL_LINEAR)
    
    # Step 7: Set Wrapping
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_WRAP_S, gl.GL_CLAMP_TO_EDGE)
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_WRAP_T, gl.GL_CLAMP_TO_EDGE)
    
    return texture_id
```

**Edge Cases and Pitfalls:**
- **Texture Size Limit**: If the number of voxels exceeds `GL_MAX_TEXTURE_SIZE`, the texture width is capped, potentially truncating data or requiring a different packing strategy [S1, unofficial].
- **Data Packing**: The source notes specify extracting 6 components but uploading to a 4-component texture (`GL_RGBA32F`) without defining the packing scheme [S1, unofficial].
- **Missing Surface Voxels**: If `surface_voxels` is `None`, the generation step relies on `volume_data` [S1, unofficial].

## Subtopics

### Particle Emission Update
Updates the voxel texture for particle systems (e.g., fire) by adding emission color without averaging [S2, unofficial]. It calculates emission as $\text{emission} = \text{pow}(u\_emission, \text{vec3}(gammaEditor))$, opacity as $\text{opacity} = \text{texture}(u\_emissionMap, b\_uv).r \times u\_opacity$, and color as $\text{color} = \text{vec4}(\text{emission} \times \text{opacity}, 0.0)$ [S2, unofficial]. It loads the previous voxel value, adds the new color, and stores the result [S2, unofficial]. When to choose: Use for dynamic particle effects like fire or smoke where emission is additive and non-averaging [S2, unofficial].

## Operating characteristics
- **Time and Memory Complexity**: Not given in the sources.
- **Strengths**: Efficient transfer of surface data to GPU using standard OpenGL texture formats [S1, unofficial].
- **Limitations**: Limited by `GL_MAX_TEXTURE_SIZE`; the exact packing scheme for mapping 6 components to 4 components per texel is not specified in the sources [S1, unofficial].
- **When to use**: When surface voxel data needs to be rendered on the GPU [S1, unofficial].
- **When not to use**: When the number of voxels exceeds texture size limits or when more than 4 components per voxel are needed without complex packing [S1, unofficial].

## Background
The method is derived from implementations in medical volume rendering and general voxel rendering systems [S1, S2, unofficial]. It is used in real-time rendering applications where surface data must be efficiently accessed by shaders [S1, S2, unofficial].
