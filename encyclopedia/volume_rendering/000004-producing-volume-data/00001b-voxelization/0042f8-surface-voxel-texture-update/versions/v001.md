# Surface Voxel Texture Update

Also called: Surface Voxel Texture Generation, Surface Voxel to Texture Upload

## Overview
Surface Voxel Texture Update is a method for converting discrete surface voxel data into a GPU-accessible 2D texture format for volume rendering. It solves the problem of transferring geometric surface information (position and normal) from CPU-side voxel structures to the GPU for ray-marching or ray-casting. It differs from general voxelization methods by focusing on the specific data layout (position + normal) and texture upload mechanics rather than the geometric intersection logic itself [S1, unofficial].

## How it works
**Inputs:**
- `surface_voxels`: A list or array of voxel data. If `None`, a surface voxel structure is generated from `volume_data` [S1, unofficial].
- `volume_data`: The source volumetric data used to generate surface voxels if they are missing [S1, unofficial].
- `surface_data.shape`: The dimensions of the source data, used to determine texture width [S1, unofficial].

**Outputs:**
- A 2D OpenGL texture (`surface_voxel_texture`) containing surface voxel data [S1, unofficial].

**Data Structures:**
- **Surface Voxel Array**: A numpy array of shape $(N, 7)$, where $N$ is the number of voxels. Each row contains:
  - $x, y, z$: Voxel coordinates (float32) [S1, unofficial].
  - $n_x, n_y, n_z$: Surface normal components (float32) [S1, unofficial].
  - The 7th component is ignored in the texture upload [S1, unofficial].
- **Texture**: A 2D texture with:
  - Width: $W = \min(\text{surface\_data.shape}[0], \text{GL\_MAX\_TEXTURE\_SIZE})$ [S1, unofficial].
  - Height: $H = 1$ [S1, unofficial].
  - Internal Format: `GL_RGBA32F` [S1, unofficial].
  - Format: `GL_RGBA` [S1, unofficial].
  - Type: `GL_FLOAT` [S1, unofficial].
  - Min/Mag Filter: `GL_LINEAR` [S1, unofficial].
  - Wrap S/T: `GL_CLAMP_TO_EDGE` [S1, unofficial].

**Steps:**
1. **Generate Surface Voxels**: If `surface_voxels` is `None`, call `sbs.create_surface_voxel_structure(volume_data)` to generate the voxel list [S1, unofficial].
2. **Convert to Array**: Convert the `surface_voxels` list into a numpy array of shape $(N, 7)$ with `float32` dtype [S1, unofficial].
3. **Extract Components**: Extract the first 6 components ($x, y, z, n_x, n_y, n_z$) from the array. The 7th component is discarded [S1, unofficial].
4. **Determine Dimensions**: Calculate the texture width $W$ as $\min(\text{surface\_data.shape}[0], \text{GL\_MAX\_TEXTURE\_SIZE})$ [S1, unofficial]. Set height $H=1$ [S1, unofficial].
5. **Upload Texture**: Create a 2D texture with the calculated dimensions, internal format `GL_RGBA32F`, format `GL_RGBA`, and type `GL_FLOAT`. Upload the extracted 6-component data (padded to 4 components per voxel for RGBA, likely interleaved or packed) into the texture [S1, unofficial].
6. **Set Filters**: Set minification and magnification filters to `GL_LINEAR` [S1, unofficial].
7. **Set Wrapping**: Set S and T wrapping modes to `GL_CLAMP_TO_EDGE` [S1, unofficial].

**Pseudocode:**

import numpy as np
import OpenGL.GL as gl

def update_surface_voxel_texture(surface_voxels, volume_data, surface_data_shape, gl_max_texture_size):
    # Step 1: Generate if None
    if surface_voxels is None:
        # Implementation detail: sbs.create_surface_voxel_structure is assumed to exist
        surface_voxels = sbs.create_surface_voxel_structure(volume_data)
    
    # Step 2: Convert to numpy array of shape (N, 7)
    # Assuming surface_voxels is a list of tuples/arrays with 7 elements
    voxel_array = np.array(surface_voxels, dtype=np.float32).reshape(-1, 7)
    
    # Step 3: Extract first 6 components (x, y, z, nx, ny, nz)
    # The 7th component is ignored
    extracted_data = voxel_array[:, :6]
    
    # Step 4: Determine texture dimensions
    width = min(surface_data_shape[0], gl_max_texture_size)
    height = 1
    
    # Step 5: Create and upload texture
    texture_id = gl.glGenTextures(1)
    gl.glBindTexture(gl.GL_TEXTURE_2D, texture_id)
    
    # Prepare data for upload: GL_RGBA32F expects 4 floats per pixel.
    # We have 6 components per voxel. The source notes say "Extract first 6 components... for texture data"
    # and "Upload as 2D texture... internal format GL_RGBA32F".
    # This implies a packing strategy. A common strategy for (x,y,z,nx,ny,nz) in RGBA32F
    # is not directly 1:1. However, the note says "Extract first 6... for texture data".
    # Given the constraint of GL_RGBA32F (4 channels), we must pack.
    # The note does not specify the packing formula. We assume a direct mapping where
    # the data is prepared to match the texture format.
    # Since the note is ambiguous on packing 6 floats into 4, we assume the implementation
    # handles the packing or the "texture data" refers to a pre-packed buffer.
    # For the purpose of this article, we assume the extracted data is formatted
    # to fit the GL_RGBA32F format, likely by ignoring the 7th and packing 6 into 4?
    # Actually, 6 floats cannot fit into 4 floats.
    # Re-reading [S1, unofficial]: "Extract first 6 components (x,y,z,nx,ny,nz) for texture data."
    # "Upload as 2D texture... internal format GL_RGBA32F".
    # This is a contradiction if 1 voxel = 1 texel.
    # Hypothesis: The texture stores multiple voxels per texel or the "texture data"
    # is a flattened array of RGBA values where each voxel contributes to multiple texels?
    # Or perhaps the 7th component is part of the 6? No, it says "first 6".
    # Let's assume the source code packs (x,y,z) into RGB and (nx,ny,nz) into something else?
    # Or maybe it's (x,y,z) in one texel and (nx,ny,nz) in another?
    # The note is insufficient to define the packing. We will state the extraction and upload
    # as described, noting the packing is implementation-specific but required for GL_RGBA32F.
    
    # To make the pseudocode complete, we assume a packing function `pack_voxel_to_rgba`
    # exists or is defined. Since we cannot guess, we will assume the data is
    # reshaped/packed to match the texture dimensions.
    
    # Reshape extracted_data to fit width*height*4 floats
    # If N voxels, and 6 floats/voxel, total floats = 6N.
    # Texture has W*H*4 floats.
    # This implies W*H*4 == 6N? Or the texture is larger?
    # The note says width is min(shape[0], max_size).
    # We will assume the data is padded/reshaped to fit the texture.
    
    # Flatten and pad to multiple of 4
    flat_data = extracted_data.flatten()
    # Pad with zeros if necessary to match W*H*4
    target_size = width * height * 4
    if len(flat_data) < target_size:
        flat_data = np.pad(flat_data, (0, target_size - len(flat_data)), 'constant')
    elif len(flat_data) > target_size:
        flat_data = flat_data[:target_size]
        
    gl.glTexImage2D(
        gl.GL_TEXTURE_2D, 0,
        gl.GL_RGBA32F, width, height, 0,
        gl.GL_RGBA, gl.GL_FLOAT, flat_data
    )
    
    # Step 6: Set Filters
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_MIN_FILTER, gl.GL_LINEAR)
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_MAG_FILTER, gl.GL_LINEAR)
    
    # Step 7: Set Wrapping
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_WRAP_S, gl.GL_CLAMP_TO_EDGE)
    gl.glTexParameteri(gl.GL_TEXTURE_2D, gl.GL_TEXTURE_WRAP_T, gl.GL_CLAMP_TO_EDGE)
    
    return texture_id

**Edge Cases and Pitfalls:**
- **Texture Size Limit**: If the number of voxels exceeds `GL_MAX_TEXTURE_SIZE`, the texture width is capped, potentially truncating data or requiring a different packing strategy [S1, unofficial].
- **Data Packing**: The source notes specify extracting 6 components but uploading to a 4-component texture (`GL_RGBA32F`). The exact packing scheme (e.g., interleaving, splitting across multiple textures, or ignoring components) is not explicitly defined in the notes [S1, unofficial]. Implementers must determine how to map 6 floats to 4 floats per texel.
- **Missing Surface Voxels**: If `surface_voxels` is `None`, the generation step must be robust to handle empty or invalid `volume_data` [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of surface voxels $N$ for conversion and upload [S1, unofficial].
- **Memory Complexity**: $O(N)$ for the voxel array and $O(W \times H)$ for the texture [S1, unofficial].
- **Strengths**: Efficient transfer of surface data to GPU; uses standard OpenGL texture formats [S1, unofficial].
- **Limitations**: Limited by `GL_MAX_TEXTURE_SIZE`; packing 6 components into 4 components is ambiguous [S1, unofficial].
- **When to use**: When surface voxel data needs to be rendered on the GPU using ray-marching [S1, unofficial].
- **When not to use**: When the number of voxels exceeds texture size limits or when more than 4 components per voxel are needed without complex packing [S1, unofficial].

## Background
The method is derived from implementations in medical volume rendering and general voxel rendering systems [S1, S2, unofficial]. It is used in real-time rendering applications where surface data must be efficiently accessed by shaders [S1, S2, unofficial].
