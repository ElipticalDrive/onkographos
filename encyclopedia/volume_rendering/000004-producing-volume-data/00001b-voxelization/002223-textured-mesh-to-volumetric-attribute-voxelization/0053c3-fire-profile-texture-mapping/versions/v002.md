# Fire Profile Texture Mapping

Also called: Unit Fire Volume Creation

## Overview
Fire Profile Texture Mapping is a voxelization technique that generates a 3D cylindrical volumetric fire from a 2D artist-created texture [S1][S2, unofficial]. It solves the problem of creating customizable, real-time volumetric fire by sweeping a 2D profile around the z-axis to form a unit fire volume [S1][S2, unofficial]. Unlike general textured mesh voxelization which maps surface attributes to volume, this method specifically constructs a radial symmetry model where the texture defines the fire's shape, color, and intensity profile [S1][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 2D `FireProfileTexture` (RGB or RGBA) created by artists [S1][S2, unofficial].
*   **Input:** A 3D position `tex` within the unit fire volume [S1][S2, unofficial].
*   **Output:** A `color` value representing the volumetric attribute at `tex` [S1][S2, unofficial].

**Data Structures**
*   **Unit Fire Volume:** A cylindrical coordinate space where the horizontal axes ($x, y$) range in $[-1, 1]$ and the vertical axis ($z$) ranges in $[0, 1]$ [S1][S2, unofficial].
*   **Fire Profile Texture:** A 2D image texture with no restrictions on size or shape, created in standard image editing applications [S1][S2, unofficial].

**Numbered Steps**
1.  Compute the radial distance from the z-axis using the input 3D coordinates $tex_x$ and $tex_y$ [S1][S2, unofficial].
2.  Construct the 2D positional vector $\vec{uv}$ by pairing the radial distance with the vertical coordinate $tex_z$ [S1][S2, unofficial].
3.  Sample the fire profile texture at $\vec{uv}$ to retrieve the color value [S1][S2, unofficial].

**Formulas**
*   Radial distance: $v = \sqrt{tex_x^2 + tex_y^2}$
*   Texture coordinate vector: $\vec{uv} = (v, tex_z)$ [S1][S2, unofficial]
*   Color lookup: $color = FireProfileTexture(\vec{uv})$ [S1][S2, unofficial]
Where $tex$ is the 3D location in the unit fire volume, $\vec{uv}$ is the 2D positional vector sampled in the fire profile texture, and $FireProfileTexture$ denotes the texture lookup function [S1][S2, unofficial].

**Parameters**
*   **Coordinate Range:** $x, y \in [-1, 1]$; $z \in [0, 1]$ [S1][S2, unofficial].
*   **Texture Filtering:** Not given in the sources.

**Edge Cases and Pitfalls**
*   **Boundary Conditions:** The radial distance $v$ can reach $\sqrt{2} \approx 1.414$ when $x$ and $y$ are at their maximum bounds, which may exceed standard $[0, 1]$ texture coordinate ranges [S1][S2, unofficial].
*   **Precision:** Floating-point precision in the square root calculation may cause minor artifacts near the z-axis where $tex_x$ and $tex_y$ approach zero [G].

**Pseudocode**
```python
import math

def fire_profile_texture_mapping(tex_x: float, tex_y: float, tex_z: float, fire_profile_texture) -> tuple:
    """
    Maps a 3D position in a unit fire volume to a color using a 2D fire profile texture.
    
    Args:
        tex_x (float): X coordinate in unit fire volume, range [-1, 1].
        tex_y (float): Y coordinate in unit fire volume, range [-1, 1].
        tex_z (float): Z coordinate in unit fire volume, range [0, 1].
        fire_profile_texture: Texture object supporting a sample(u, v) method.
        
    Returns:
        tuple: The color (and alpha) sampled from the fire profile texture.
    """
    # Calculate radial distance from the z-axis
    v = math.sqrt(tex_x**2 + tex_y**2)
    
    # Map 3D position to 2D texture coordinates
    # u corresponds to radial distance v
    # v corresponds to height tex_z
    u = v
    v_tex = tex_z
    
    # Note: Standard texture samplers expect coordinates in [0, 1].
    # The source defines the mapping directly as uv = (sqrt(tex_x^2 + tex_y^2), tex_z).
    # Implementation requires normalizing u and v_tex to [0, 1] if the texture 
    # expects normalized coordinates, or scaling the texture dimensions accordingly.
    # This normalization step is not specified in the source [G].
    
    color = fire_profile_texture.sample(u, v_tex)
    
    return color
```

## Subtopics

### [Fire Profile Texture Mapping with Noise](16941-fire-profile-texture-mapping-with-noise.md)
This variant extends the base method by perturbing the vertical texture coordinate using procedural noise turbulence to create animated, organic fire details without pre-computed 3D noise volumes. It differs from static volume rendering by integrating noise directly into the texture coordinate lookup to simulate rising flames and micro-level details. Choose this variant when animated, turbulent fire is required rather than a static profile. See [Fire Profile Texture Mapping with Noise](16941-fire-profile-texture-mapping-with-noise.md).

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Not given in the sources.
*   **Strengths:** Highly customizable by artists; real-time performance [S1][S2, unofficial].
*   **Limitations:** Requires a 2D texture input; static profile shape unless deformed via additional techniques [S1][S2, unofficial].
*   **When to use:** Real-time volumetric fire rendering where artistic control is prioritized [S1][S2, unofficial].
*   **When not to use:** Offline rendering requiring high-fidelity physical simulation [S1].

## Background
The method was introduced by Fuller, Krishnan, Mahrous, Hamann, and Joy from the UC Davis Visualization Research Group (IDAV) [S1][S2, unofficial]. It was presented at the International Conference on Interactive 3D Graphics (I3D) in 2007 [S2, unofficial]. The work addresses the gap between computationally intense offline fire simulations and the need for real-time, artist-controllable fire in computer graphics [S1][S2, unofficial].
