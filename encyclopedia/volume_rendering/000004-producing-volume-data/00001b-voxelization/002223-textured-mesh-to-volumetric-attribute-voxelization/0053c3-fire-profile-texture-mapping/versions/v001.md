# Fire Profile Texture Mapping

Also called: Unit Fire Volume Creation

## Overview
Fire Profile Texture Mapping is a voxelization technique that generates a 3D cylindrical volumetric fire from a 2D artist-created texture [S1][S2, unofficial]. It solves the problem of creating customizable, real-time volumetric fire by sweeping a 2D profile around the z-axis to form a unit fire volume [S1][S2, unofficial]. Unlike general textured mesh voxelization which maps surface attributes to volume, this method specifically constructs a radial symmetry model where the texture defines the fire's shape, color, and intensity profile [S1][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 2D `FireProfileTexture` (RGB or RGBA) created by artists [S1][S2, unofficial].
*   **Input:** A 3D position `tex` within the unit fire volume [S1][S2, unofficial].
*   **Output:** A `color` value representing the volumetric attribute at `tex` [S1][S2, unofficial].

**Data Structures**
*   **Unit Fire Volume:** A cylindrical coordinate space.
    *   Horizontal axes ($x, y$): Range $[-1, 1]$ [S1][S2, unofficial].
    *   Vertical axis ($z$): Range $[0, 1]$ [S1][S2, unofficial].
*   **Fire Profile Texture:** A 2D image texture. No specific resolution is mandated; it is created in standard image editing applications [S1][S2, unofficial].

**Mapping Logic**
The method maps a 3D point in the unit fire volume to a 2D point in the fire profile texture using radial symmetry. The horizontal position in the texture is determined by the distance from the z-axis, while the vertical position corresponds directly to the height in the volume.

1.  Calculate the radial distance $v$ from the z-axis using the input 3D coordinates $tex_x, tex_y$:
    $$ v = \sqrt{tex_x^2 + tex_y^2} $$
2.  Define the 2D texture coordinate vector $\vec{uv}$:
    $$ \vec{uv} = (v, tex_z) $$
    Where $tex_z$ is the vertical coordinate of the input point [S1][S2, unofficial].
3.  Sample the color from the fire profile texture using $\vec{uv}$:
    $$ color = FireProfileTexture(\vec{uv}) $$
    This retrieves the color (and potentially alpha/intensity) defined by the artist at that radial and vertical position [S1][S2, unofficial].

**Parameters**
*   **Coordinate Range:** $x, y \in [-1, 1]$; $z \in [0, 1]$ [S1][S2, unofficial].
*   **Texture Access:** Standard bilinear or trilinear filtering is implied by the use of texture lookups, though not explicitly detailed in the core mapping equations [S1][S2, unofficial].

**Pseudocode**
```python
def fire_profile_texture_mapping(tex_x, tex_y, tex_z, fire_profile_texture):
    """
    Maps a 3D position in a unit fire volume to a color using a 2D fire profile texture.
    
    Args:
        tex_x (float): X coordinate in unit fire volume, range [-1, 1].
        tex_y (float): Y coordinate in unit fire volume, range [-1, 1].
        tex_z (float): Z coordinate in unit fire volume, range [0, 1].
        fire_profile_texture (Texture2D): The 2D artist-created fire profile.
        
    Returns:
        vec4: The color sampled from the fire profile texture.
    """
    # Calculate radial distance from the z-axis
    v = sqrt(tex_x**2 + tex_y**2)
    
    # Map 3D position to 2D texture coordinates
    # u corresponds to radial distance v
    # v corresponds to height tex_z
    u = v
    v_tex = tex_z
    
    # Sample the texture
    # Note: Texture coordinates are typically normalized [0,1].
    # The source does not specify normalization steps for v and tex_z.
    # Assuming the texture is sized to accommodate the range [0,1] for v and [0,1] for z,
    # or that the texture lookup function handles the coordinate space.
    # Given the range of v is [0, sqrt(2)] for x,y in [-1,1], 
    # and z is [0,1], specific normalization logic would be required 
    # if the texture is strictly [0,1]x[0,1]. 
    # However, the source defines the mapping directly as:
    # color = FireProfileTexture(u~v)
    # We implement the direct mathematical mapping provided.
    
    color = fire_profile_texture.sample(u, v_tex)
    
    return color
```

## Subtopics

### Fire Profile Texture Mapping with Noise
This variant adds procedural animation and micro-details to the fire profile by perturbing the vertical texture coordinate with noise [S2, unofficial]. It is chosen when animated, turbulent fire is required rather than a static profile [S2, unofficial].

*   **Definition:** Mapping noise turbulence to the vertical texture coordinate to create micro-level details and animation [S2, unofficial].
*   **Steps:**
    1.  Calculate the turbulence value using a noise function based on position and offset [S2, unofficial].
    2.  Multiply the turbulence by a kernel function $f(tex_z)$ and add it to the vertical texture coordinate [S2, unofficial].
    3.  Look up the color in the fire profile texture using the horizontal coordinate $u$ and the modified vertical coordinate [S2, unofficial].
*   **Formulas:**
    *   Horizontal coordinate:
        $$ u = \sqrt{tex_x^2 + tex_y^2} $$
    *   Vertical coordinate with noise offset:
        $$ v = tex_z + f(tex_z) \cdot turb(noise\_pos + offset) $$
    *   Color lookup:
        $$ color = FireProfileTexture(u, v) $$
    *   Kernel function:
        $$ f(tex_z) = stability \cdot \sqrt{height} $$
        Where $stability$ is a stability factor and $height$ is $tex_z$ [S2, unofficial].
    *   Turbulence calculation (sum of octaves):
        $$ turb = \sum_{i=0}^{octaves} gain_i \cdot noise(position \cdot lacunarity_i) $$
    *   Noise position scaling:
        $$ noise\_pos = (radius, radius, length, 1) \cdot frequency $$
        $$ noise\_pos = (tex_x, tex_y, tex_z - time, time) \cdot noisescale $$
        Where $time$ is used to create upward flow, and $offset$ is an instance-specific constant to ensure uniqueness [S2, unofficial].
*   **Parameters:**
    *   $octaves$: Number of noise layers (e.g., 0, 1, 3) [S2, unofficial].
    *   $stability$: Customizable factor controlling noise amplitude [S2, unofficial].
    *   $frequency, noisescale$: Control the spatial scale of the noise [S2, unofficial].
    *   $time$: Drives the animation [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel/sample, as it involves basic arithmetic and a single texture lookup [S1][S2, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary memory, plus the size of the 2D fire profile texture [S1][S2, unofficial].
*   **Performance:** On a nVidia GeForce 7800 GT, a unit-radius fire with slice spacing 0.2 (approx. 90,000 pixels) achieved 197 FPS with 0 noise octaves, dropping to 30 FPS with 3 octaves of 4D noise [S2, unofficial].
*   **Strengths:** Highly customizable by artists; real-time performance; physically plausible appearance through procedural noise [S1][S2, unofficial].
*   **Limitations:** Requires a 2D texture input; static profile shape unless deformed via additional techniques (e.g., Volumetric Free-Form Deformation) [S1][S2, unofficial].
*   **When to use:** Real-time volumetric fire rendering where artistic control is prioritized over physical simulation accuracy [S1][S2, unofficial].
*   **When not to use:** Offline rendering requiring high-fidelity physical simulation (e.g., Nguyen et al. method takes ~3 minutes per frame) [S1].

## Background
The method was introduced by Fuller, Krishnan, Mahrous, Hamann, and Joy from the UC Davis Visualization Research Group (IDAV) [S1][S2, unofficial]. It was presented at the International Conference on Interactive 3D Graphics (I3D) in 2007 [S2, unofficial]. The work addresses the gap between computationally intense offline fire simulations and the need for real-time, artist-controllable fire in computer graphics [S1][S2, unofficial].
