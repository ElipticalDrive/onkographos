# Bitstream-oriented TexF Compression
Also called: TexF Compression using 3D Attribute Codecs

## Overview
Bitstream-oriented TexF Compression is a method for compressing the volumetric attribute data of a Surface-aligned Texture Field (TexF) by leveraging established 3D point cloud attribute codecs. It solves the problem of storing and transmitting large volumes of texture attributes associated with sparse surface-aligned voxels. Unlike [Differentiable TexF Rendering](10095-differentiable-texf-rendering.md), which focuses on gradient-based optimization for rendering, this method focuses on lossy or lossless bitstream compression for storage and transmission. It sets itself apart by treating the TexF attributes as a point cloud attribute dataset, compressing them without separately transmitting the voxel coordinates, as the geometry is assumed to be known or reconstructed separately.

## How it works
The method relies on the assumption that the underlying mesh geometry (and thus the voxel set $Q$) is either known to the decoder or reconstructed independently. The compression applies only to the texture attributes $t(q)$ associated with each voxel $q \in Q$.

**Inputs and Outputs:**
*   **Input:** A TexF defined as $T = \{(q, t(q)) \mid q \in Q\}$, where $Q$ is the set of voxel positions derived from the reconstructed mesh geometry, and $t(q)$ are the texture attributes (e.g., color, normal, roughness) at each voxel.
*   **Output:** A compressed bitstream containing the encoded attributes.

**Data Structures:**
*   **Voxel Set $Q$:** A set of 3D coordinates. The coordinates are not explicitly stored in the attribute bitstream but are derived from the geometry.
*   **Attributes $t(q)$:** A vector of values for each voxel. The specific format (e.g., RGB, RGBA, float, integer) depends on the attribute type and the backend codec's requirements.

**Steps:**
1.  **Geometry Reconstruction/Alignment:** The encoder and decoder must derive the same voxel set $Q$ from the reconstructed mesh geometry. This ensures that the attribute indices align correctly. [S1, unofficial]
2.  **Attribute Extraction:** Extract the texture attributes $t(q)$ for all $q \in Q$. If multiple surface samples map to the same voxel, their attributes are averaged to produce a single $t(q)$. [S1, unofficial]
3.  **3D Attribute Encoding:** Pass the set of attributes $\{t(q)\}$ and their corresponding positions $Q$ to an established 3D attribute codec backend (e.g., Unicorn or G-PCC). The codec performs:
    *   **Analysis Transform:** Converts the attribute data into a domain suitable for compression (e.g., prediction residuals).
    *   **Entropy Coding:** Compresses the transformed data into a bitstream.
    *   Note: The voxel coordinates $Q$ are not separately transmitted in the attribute bitstream. [S1, unofficial]
4.  **Bitstream Generation:** The output is the compressed bitstream of the attributes. [S1, unofficial]
5.  **Decoding:** The decoder uses the same geometry-derived voxel set $Q$ and the established backend codec to perform entropy decoding and inverse analysis transform, reconstructing the attributes $\hat{t}(q)$. [S1, unofficial]

**Parameters:**
*   **Backend Codec:** Established 3D attribute codecs such as Unicorn or G-PCC are used. These handle the analysis transform, entropy coding, and decoding. [S1, unofficial]
*   **Typical Values:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Geometry Mismatch:** If the decoder's reconstructed geometry differs from the encoder's, the voxel set $Q$ will not match, leading to incorrect attribute assignment. This is a critical dependency. [S1, unofficial]
*   **Precision:** The precision of the reconstructed attributes $\hat{t}(q)$ depends on the codec's quantization and compression ratio. [S1, unofficial]

**Pseudocode:**
```python
# Encoder
def encode_texf_attributes(mesh_geometry, texf_attributes):
    # 1. Derive voxel set Q from mesh geometry
    # This step must be deterministic and identical on decoder side
    Q = derive_voxel_set_from_mesh(mesh_geometry)
    
    # 2. Extract attributes for Q
    # texf_attributes is a dict or list mapping q -> t(q)
    # Ensure all q in Q have an attribute value
    attributes = [texf_attributes[q] for q in Q]
    
    # 3. Encode using 3D attribute codec
    # Backend handles analysis transform and entropy coding
    # Coordinates Q are not explicitly encoded in this bitstream
    bitstream = encode_3d_attribute_codec(Q, attributes)
    
    return bitstream

# Decoder
def decode_texf_attributes(bitstream, mesh_geometry):
    # 1. Derive voxel set Q from mesh geometry
    # Must match encoder's Q
    Q = derive_voxel_set_from_mesh(mesh_geometry)
    
    # 2. Decode attributes using 3D attribute codec
    # Backend handles entropy decoding and inverse analysis transform
    attributes = decode_3d_attribute_codec(bitstream)
    
    # 3. Reconstruct TexF
    # T = {(q, t(q)) | q in Q}
    texf = {q: attributes[i] for i, q in enumerate(Q)}
    
    return texf
```

## Subtopics

### [GPU-resident Neural Compression for TexF](10087-gpu-resident-neural-compression-for-texf.md)
GPU-resident neural compression for TexF is a method for memory-efficient random access during rendering, using GPU-resident neural compression. It adapts multiresolution hash encoding to TexF. It replaces explicit voxel attributes with a directly queryable compressed field to avoid storing per-voxel lookup entries. Unlike bitstream-oriented TexF compression which uses established 3D attribute codecs for disk storage, GPU-resident neural compression targets memory-efficient random access during rendering.

## Operating characteristics
*   **Time Complexity:** Depends on the complexity of the 3D attribute codec (e.g., Unicorn or G-PCC). Typically involves spatial prediction and entropy coding.
*   **Memory Complexity:** Depends on the codec's internal buffers and the size of the compressed bitstream.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with the number of voxels in $Q$.
*   **Strengths:** Leverages mature, optimized 3D attribute codecs. Simple integration if geometry is already available.
*   **Limitations:** Requires identical geometry reconstruction on encoder and decoder sides. Does not compress the geometry itself.
*   **When to use:** When storage/transmission of TexF attributes is needed, and geometry is known or separately compressed.
*   **When not to use:** When random access during rendering is the primary concern (use GPU-resident neural compression instead).

## Background
Bitstream-oriented TexF Compression was introduced in the paper "Beyond UV Mapping: Mesh Texture Compression via Surface-Aligned Texture Fields" [S1, unofficial]. It builds on the concept of TexF, which associates texture attributes with surface-aligned voxels. The method adapts techniques from 3D point cloud compression to the specific case of TexF attributes.
