# Differentiable TexF Rendering

Also called: TexF Rendering

## Overview
Differentiable TexF Rendering is the rendering and refinement stage of the Surface-aligned Texture Field (TexF) pipeline [S1, unofficial]. It generates images from a sparse, surface-aligned voxel representation without UV parameterization [S1, unofficial]. Unlike UV-based rendering that samples a 2D texture using interpolated UV coordinates, this method queries the 3D texture field directly at rasterized surface positions using trilinear interpolation in 3D space [S1, unofficial]. It is distinct from its sibling [Bitstream-oriented TexF Compression](10086-bitstream-oriented-texf-compression.md) as it handles forward rendering and gradient-based refinement of voxel attributes rather than entropy coding [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sparse active voxel set $Q$ with texture attributes, and rasterized 3D surface positions $p$ for each pixel [S1, unofficial].
*   **Output:** The rendered color $c(p)$ at position $p$, and gradients of the loss with respect to voxel attributes for refinement [S1, unofficial].

**Data Structures:**
*   **Active Set $Q$:** A sparse set of 3D integer coordinates $q \in \mathbb{Z}^3$ representing voxels intersecting the mesh surface, with indices satisfying $0 \le q < K$ where $K$ is the grid resolution [S1, unofficial]. Dense allocation of $K^3$ is avoided by constructing this support efficiently through surface sampling and voxelization [S1, unofficial].
*   **Texture Attributes:** Stored at each active voxel $q$ [S1, unofficial].

**Method:**
1.  **Rasterization:** Project the mesh surface to obtain the 2D screen position and corresponding 3D surface position $p$ for each pixel [G].
2.  **Neighborhood Identification:** Identify the set of active grid points $N(p)$ within the $2 \times 2 \times 2$ neighborhood of the query position $p$ [S1, unofficial].
3.  **Weight Calculation:** Compute trilinear interpolation weights $\omega_i$ for each neighbor $q_i \in N(p)$ based on the relative position of $p$ within the grid cell [S1, unofficial].
4.  **Interpolation:** Compute the color $c(p)$ by summing the weighted attributes of the neighbors [S1, unofficial].
5.  **Refinement:** If training, compute a photometric loss between the rendered image and a UV reference image, then backpropagate through the interpolation step to update voxel attributes [S1, unofficial].

**Formula:**
The color $c(p)$ at a surface position $p$ is obtained by trilinearly interpolating neighboring texture attributes [S1, unofficial]:

$$
c(p) = \sum_{i \in N(p)} \omega_i t(q_i)
$$

Where:
*   $N(p)$ is the set of active grid points within the $2 \times 2 \times 2$ neighborhood of $p$ [S1, unofficial].
*   $\omega_i$ are the trilinear weights determined by the query position $p$ within the grid cell defined by the neighbors [S1, unofficial].
*   $t(q_i)$ is the texture attribute (e.g., color) stored at voxel $q_i$ [S1, unofficial].

**Pseudocode:**
```python
def texf_render(p, active_voxels, voxel_attributes):
    """
    Render color at surface position p using TexF.
    Args:
        p: 3D vector, the surface position in world/grid space.
        active_voxels: List of 3D integer coordinates (q) that are active.
        voxel_attributes: Dict mapping q to attribute vector t(q).
    Returns:
        c: Rendered color vector.
    """
    q_min = [int(x) for x in p]  # Floor coordinates to find base corner
    local_p = [p[i] - q_min[i] for i in range(3)]
    
    neighbors = []
    for dx in [0, 1]:
        for dy in [0, 1]:
            for dz in [0, 1]:
                q = [q_min[0] + dx, q_min[1] + dy, q_min[2] + dz]
                if q in active_voxels:
                    neighbors.append(q)
                    
    if not neighbors:
        return [0.0, 0.0, 0.0]  # Zero output for empty neighborhood [G]
        
    weights = []
    colors = []
    for q in neighbors:
        dx = q[0] - q_min[0]
        dy = q[1] - q_min[1]
        dz = q[2] - q_min[2]
        w = (1.0 - local_p[0]) if dx == 0 else local_p[0]
        w *= (1.0 - local_p[1]) if dy == 0 else local_p[1]
        w *= (1.0 - local_p[2]) if dz == 0 else local_p[2]
        weights.append(w)
        colors.append(voxel_attributes[q])
        
    c = [0.0, 0.0, 0.0]
    for i in range(3):
        c[i] = sum(w * col[i] for w, col in zip(weights, colors))
    return c
```

**Parameters and Edge Cases:**
*   **Input Reconstruction (IR):** An optional preprocessing step that improves input fidelity, but can be omitted when preprocessing time is a priority [S1, unofficial].
*   **Sparse Support:** The method relies on $Q$ being sparse [S1, unofficial]. If $p$ falls in a region with no active neighbors, the result is zero [G].
*   **Precision:** Trilinear interpolation assumes continuous attributes, and discontinuities at mesh boundaries may require refinement [S1, unofficial].

## Subtopics

### TexF/Unicorn
A variant where Input Reconstruction (IR) is omitted to prioritize preprocessing speed over maximum input fidelity, which may require larger TexF representations to compensate [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per pixel due to a fixed $2 \times 2 \times 2$ neighborhood lookup and interpolation [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of active voxels $|Q|$, which is sparse relative to the total grid volume $K^3$ [S1, unofficial].
*   **Performance:** In experiments, TexF/3DNTC achieved a 4.52 MB bitrate with 37.5 PSNR and 0.9900 SSIM, outperforming UV-Source/ASTC at 8.93 MB, 33.5 PSNR, and 0.9726 SSIM [S1, unofficial].
*   **Strengths:** UV-free, preserves spatial locality, and supports neural rendering and editing [S1, unofficial].
*   **Limitations:** Requires surface sampling and voxelization, and needs refinement to achieve high fidelity when IR is omitted [S1, unofficial].

## Background
Originating from the work on "Beyond UV Mapping: Mesh Texture Compression via Surface-Aligned Texture Fields" [S1, unofficial], this method addresses the long-standing reliance on UV atlases in texture modeling [S1, unofficial]. It builds on associating appearance with mesh-derived voxels to provide a common representation for 3D attribute codecs and GPU-resident neural compression [S1, unofficial].
