# Parametric Surface Voxelization

Also called: Directional Sheet Buffer Voxelization, Parametric field rasterization

## Overview
Parametric surface voxelization converts a parametric surface into a voxel grid by rasterizing its 2D parameter domain in the vertex shader rather than the 3D object space [S1, S2, unofficial]. It differs from implicit surface voxelization by evaluating the surface function directly on a point boodle and projecting the results immediately, avoiding fragment-shader ray marching or interval solving [S1, S2, unofficial].

## How it works
**Inputs:**
- Parametric surface function $S(u, v)$ mapping 2D parameters to 3D space [S1, S2, unofficial].
- A boodle of 2D points covering the parametric domain [S1, S2, unofficial].
- Target voxel grid bounds and resolution [G].

**Outputs:**
- A voxel grid (worksheet) populated with surface data [S1, S2, unofficial].

**Data Structures:**
- **Parametric Boodle:** An unordered list of 2D points $\{(u_i, v_i)\}$ covering the parameter space [S1, S2, unofficial].
- **Worksheet:** The target volume buffer where 3D positions are transcoded [S1, S2, unofficial].

**Steps:**
1. Build a boodle of points that cover the parametric field [S1, S2, unofficial].
2. Consider each point as a vertex processed in the vertex shader [S1, S2, unofficial].
3. Use texture coordinates in the parametric domain to calculate positions in 3D space [S1, S2, unofficial].
4. Transcode these positions to the worksheet immediately [S1, S2, unofficial].

**Pseudocode:**
```python
def parametric_surface_voxelization(surface_func, parametric_samples, bounds, resolution):
    """
    Voxelize a parametric surface by rasterizing its parameter domain.
    
    Args:
        surface_func: Callable taking (u, v) and returning (x, y, z).
        parametric_samples: List of (u, v) tuples covering the domain.
        bounds: Tuple (min_x, min_y, min_z, max_x, max_y, max_z).
        resolution: Tuple (res_x, res_y, res_z).
    """
    min_x, min_y, min_z, max_x, max_y, max_z = bounds
    res_x, res_y, res_z = resolution
    
    for u, v in parametric_samples:
        # Step 3: Calculate 3D position from parametric coordinates
        x, y, z = surface_func(u, v)
        
        # Step 4: Transcode position to voxel grid
        # Map continuous 3D coordinates to discrete voxel indices
        # Standard coordinate transform [G]
        nx = (x - min_x) / (max_x - min_x)
        ny = (y - min_y) / (max_y - min_y)
        nz = (z - min_z) / (max_z - min_z)
        
        i = int(nx * res_x)
        j = int(ny * res_y)
        k = int(nz * res_z)
        
        # Clamp to valid range
        i = max(0, min(i, res_x - 1))
        j = max(0, min(j, res_y - 1))
        k = max(0, min(k, res_z - 1))
        
        # Store the transcoded position in the worksheet
        worksheet.set(i, j, k, value=(x, y, z))
```

**Edge Cases and Pitfalls:**
- **Instruction Slot Limits:** Handling very complex surfaces depends on the shader program supporting enough instruction slots [S2, unofficial].
- **Shader Stage Selection:** The method explicitly uses the vertex shader instead of the pixel shader for rasterization [S1, S2, unofficial].

## Subtopics

### [Recursive Parameter Space Voxelization for Catmull-Clark Subdivision Surfaces](2533-recursive-parameter-space-voxelization-for-catmull-clark-sub.md)
This method converts a free-form object represented by a Catmull-Clark subdivision surface (CCSS) into a voxel grid by recursively subdividing the 2D parameter space of surface patches and sampling 3D points, rather than subdividing 3D object space. It ensures leak-free results for closed objects when a 3D flooding operation is performed by guaranteeing that voxels generated from a single patch satisfy specific N-adjacency properties. Unlike 3D space subdivision techniques which are computationally expensive due to distance computations between 3D points, this method performs subdivision in 2D parameter space, avoiding expensive 3D distance computations.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of points in the parametric boodle [G].
- **Memory Complexity:** Linear with respect to the worksheet size and parametric boodle size [G].
- **Performance:** The method leverages GPU vertex shader parallelism for surface evaluation and projection [S1, S2, unofficial].
- **Strengths:** Enables rapid voxelization for applications like transparent illustration and CSG boolean operations on 2D textures [S1, S2, unofficial].
- **Limitations:** Requires the surface to be defined parametrically and the shader to support sufficient instruction slots for complex evaluations [S2, unofficial].
- **When to Use:** When voxelizing parametric surfaces in real-time applications where GPU acceleration is available [S1, S2, unofficial].
- **When Not to Use:** For implicit surfaces defined by scalar fields or polygonal meshes [G].

## Background
The method was described in the context of real-time voxelization for complex models, including CSG models and parametric surfaces [S1, S2, unofficial]. It was proposed to solve rapid voxelization challenges, enabling techniques like transparent illustration and GPU-based boolean operations on voxelized worksheets [S1, S2, unofficial].
