# Parametric Surface Voxelization

Also called: Directional Sheet Buffer Voxelization, Parametric field rasterization

## Overview
Parametric surface voxelization converts a parametric surface (such as a NURBS or subdivision surface patch) into a voxel grid by rasterizing the surface's 2D parameter domain rather than the 3D object space [S1, S2, unofficial]. It differs from implicit surface voxelization by evaluating the surface function in the vertex shader to generate points, which are then projected directly into the voxel volume, avoiding the need for ray-marching or interval solving in the fragment shader [S1, S2, unofficial]. This approach is particularly suited for real-time applications where the surface definition is available as a shader program [S2, unofficial].

## How it works
**Inputs:**
- Parametric surface definition (function $S(u, v)$ mapping 2D parameters to 3D space).
- Target voxel grid resolution and bounds.
- A "boodle" (unordered list) of 2D points covering the parametric domain $[u, v]$.

**Outputs:**
- A voxel grid (worksheet) populated with surface data.

**Data Structures:**
- **Parametric Booble:** An array of 2D vectors $\{(u_i, v_i)\}$ representing sample points in the parameter space. The density of this boodle determines the sampling rate of the surface.
- **Voxel Grid (Worksheet):** A 3D array or texture buffer storing the voxelized data. The term "worksheet" refers to the target volume buffer where 3D positions are transcoded [S1, S2, unofficial].

**Steps:**
1. **Generate Parametric Samples:** Construct a boodle of 2D points $(u, v)$ that uniformly or adaptively cover the parametric domain of the surface patches.
2. **Vertex Shader Processing:** For each point in the boodle, invoke the vertex shader. The vertex shader treats the 2D point as a vertex.
3. **3D Position Calculation:** Inside the vertex shader, use the texture coordinates $(u, v)$ to evaluate the parametric surface function $S(u, v)$ to obtain the 3D position $\mathbf{p} = (x, y, z)$ [S1, S2, unofficial].
4. **Transcoding to Voxel Grid:** Immediately project the calculated 3D position $\mathbf{p}$ into the voxel grid coordinate system. This "transcoding" step maps the continuous 3D position to discrete voxel indices $(i, j, k)$ in the worksheet [S1, S2, unofficial].

**Pseudocode:**
```python
def parametric_surface_voxelization(surface_func, parametric_samples, voxel_grid):
    """
    Voxelize a parametric surface by rasterizing its parameter domain.
    
    Args:
        surface_func: A callable that takes (u, v) and returns (x, y, z).
        parametric_samples: A list of (u, v) tuples covering the domain.
        voxel_grid: A 3D data structure representing the target volume.
    """
    for u, v in parametric_samples:
        # Step 3: Calculate 3D position from parametric coordinates
        # This corresponds to the vertex shader evaluation
        x, y, z = surface_func(u, v)
        
        # Step 4: Transcode position to voxel grid
        # Map continuous 3D coordinates to discrete voxel indices
        i, j, k = world_to_voxel_indices(x, y, z, voxel_grid.bounds, voxel_grid.resolution)
        
        # Store the data in the worksheet
        # Note: The specific data stored (e.g., normal, color, or just occupancy)
        # depends on the application, but the position is the primary output.
        voxel_grid.set(i, j, k, value=(x, y, z))

def world_to_voxel_indices(x, y, z, bounds, resolution):
    """
    Convert world coordinates to voxel indices.
    bounds: (min_x, min_y, min_z, max_x, max_y, max_z)
    resolution: (res_x, res_y, res_z)
    """
    min_x, min_y, min_z, max_x, max_y, max_z = bounds
    res_x, res_y, res_z = resolution
    
    # Normalize to [0, 1]
    nx = (x - min_x) / (max_x - min_x)
    ny = (y - min_y) / (max_y - min_y)
    nz = (z - min_z) / (max_z - min_z)
    
    # Scale to resolution
    i = int(nx * res_x)
    j = int(ny * res_y)
    k = int(nz * res_z)
    
    # Clamp to valid range
    i = max(0, min(i, res_x - 1))
    j = max(0, min(j, res_y - 1))
    k = max(0, min(k, res_z - 1))
    
    return i, j, k
```

**Edge Cases and Pitfalls:**
- **Sampling Density:** If the parametric boodle is too sparse, the resulting voxel grid will have holes or aliasing artifacts. The density must be sufficient to capture the surface detail relative to the voxel size [S1, S2, unofficial].
- **Precision:** The vertex shader must support sufficient instruction slots to evaluate complex parametric surfaces (e.g., high-degree NURBS) without precision loss [S2, unofficial].
- **Boundary Conditions:** Points near the edge of the parametric domain must be handled correctly to avoid missing surface parts or generating out-of-bounds voxels.

## Subtopics

### [Recursive Parameter Space Voxelization for Catmull-Clark Subdivision Surfaces](2533-recursive-parameter-space-voxelization-for-catmull-clark-sub.md)
This method converts a free-form object represented by a Catmull-Clark subdivision surface (CCSS) into a voxel grid by recursively subdividing the 2D parameter space of surface patches and sampling 3D points, rather than subdividing 3D object space. It ensures leak-free results for closed objects when a 3D flooding operation is performed by guaranteeing that voxels generated from a single patch satisfy specific N-adjacency properties. Unlike 3D space subdivision techniques which are computationally expensive due to distance computations between 3D points, this method performs subdivision in 2D parameter space, avoiding expensive 3D distance computations.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of points in the parametric boodle and the number of surface patches. The cost is dominated by the vertex shader evaluations and the transcoding step.
- **Memory Complexity:** Linear with respect to the size of the voxel grid and the parametric boodle.
- **Performance:** Suitable for real-time applications because the heavy lifting (surface evaluation) is offloaded to the GPU vertex shader, which is highly parallelized [S1, S2, unofficial].
- **Strengths:** Efficient for complex parametric surfaces; leverages GPU hardware acceleration; avoids expensive 3D distance computations [S1, S2, unofficial].
- **Limitations:** Requires the surface to be defined parametrically; sampling density must be carefully chosen to avoid artifacts; may struggle with very high-frequency details if the parametric domain is not sampled densely enough [S1, S2, unofficial].
- **When to Use:** When voxelizing parametric surfaces (NURBS, subdivision surfaces) in real-time applications where GPU acceleration is available.
- **When Not to Use:** For implicit surfaces defined by scalar fields (use Implicit Surface Voxelization) or for polygonal meshes (use Rasterization and GPU Shaders or Voxel Carving).

## Background
The method was described in the context of real-time voxelization for complex models, including CSG models and parametric surfaces [S1, S2, unofficial]. It leverages the GPU's vertex shader capabilities to perform surface evaluation and projection, treating the parametric domain as a rasterizable entity [S1, S2, unofficial]. This approach was proposed as a solution for rapid voxelization, enabling applications such as transparent illustration and CSG operations [S1, S2, unofficial].
