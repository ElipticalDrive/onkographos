# Visual Hull Construction

Also called: Octree Visual Hull Construction, Octree carving, Photo Hull, Shape from Silhouette, Shape from Silhouette (SfS) / Octree Visual Hull Construction, Silhouette Intersection, Visual hull reconstruction

## Overview
Visual Hull Construction generates a 3D representation of an object by intersecting multiple 3D cones created by back-projecting 2D silhouettes from different views onto 3D space [S1]. It is a Shape from Silhouette (SfS) technique that represents the resulting volume using an octree, where the object is defined as the intersection of all view-consistent volumes [S1]. Unlike [Smooth Visual Hull Reconstruction](5917-smooth-visual-hull-reconstruction.md), which uses a continuous product of filtered silhouette values to define an implicit surface, Visual Hull Construction relies on discrete octree subdivision and binary classification of spatial regions [S1].

## How it works
**Inputs:** $N$ 2D images (or precomputed binary silhouette masks), camera projection matrices for each view, and an initial 3D bounding cube enclosing the object [S1, S2].
**Outputs:** An octree data structure representing the visual hull, where nodes are classified as `inside`, `outside`, or `intersection` [S1].

**Data Structures:**
*   **Octree Node:** Represents a cubic volume in 3D space with fields for `status` (enum: `OUTSIDE`, `INSIDE`, `INTERSECTION`), `children` (array of 8 child nodes for `INTERSECTION` nodes), and `bbox` (bounding box coordinates) [S1, G].
*   **Silhouette Mask:** Binary 2D image where 1 indicates the object silhouette and 0 indicates background [S2].

**Parameters:**
*   $\epsilon$: Threshold for binary mask generation. Typical value: 0.04 [S2].
*   $\sigma_{img}$: Blur kernel size for image masks. Typical value: 1 pixel [S2].
*   $\sigma_{vol}$: Blur kernel size for volume hulls. Typical value: 0.5 cells [S2].
*   $K$: Camera intrinsic matrix. Remains constant if the same camera is used [S1].
*   $\theta$: Rotational angle from reference position [S1].
*   $t_x, t_y$: X and Y translations at $\theta=0$ [S1].

**Steps:**

1.  **Preprocessing:**
    *   For each input image, perform background subtraction to isolate the object [S2].
    *   Convert the result to a binary mask using threshold $\epsilon$ [S2].
    *   Apply a Gaussian blur with $\sigma_{img}$ to the binary masks to smooth edges [S2].

2.  **Camera Model Setup:**
    *   Define the projection matrix $P(\theta)$ for each view. For circular motion (e.g., turntable), use:
        $$ P(\theta) = K \begin{bmatrix} \cos \theta & \sin \theta & 0 & t_x \\ -\sin \theta & \cos \theta & 0 & t_y \\ 0 & 0 & 1 & 0 \end{bmatrix} $$
        where $\theta$ is the rotational angle, and $t_x, t_y$ are translations at $\theta=0$ [S1].
    *   If only a single view is available, generate 4 auxiliary views by rotating the camera around the central Y-axis [S2]. Mirror the masks from these auxiliary views at the projected rotation axis to reduce cutoffs [S2].

3.  **Octree Construction (Carving):**
    *   Project the initial bounding cube onto multiple images [S1].
    *   Split the cube into eight smaller cubes (octants) if the projection intersects a silhouette [S1].
    *   Classify each octant as outside, inside, or intersection [S1].
    *   Carve out octants classified as outside [S1].
    *   Extract surfaces from the resulting octree [S1].

4.  **Post-processing (Optional):**
    *   Apply a Gaussian blur with $\sigma_{vol}$ to the resulting binary volume representation to smooth the hull [S2].

5.  **Surface Extraction:**
    *   Extract the surface from the final octree using the Marching Cubes (MC) algorithm [S1].
    *   MC estimates surface triangles from `INTERSECTION` octants [S1].
    *   The location of the triangles is determined by the configuration of inside vertices [S1].

**Pseudocode:**

```python
class OctreeNode:
    def __init__(self, bbox, status='INSIDE'):
        self.bbox = bbox  # (min_x, min_y, min_z, max_x, max_y, max_z)
        self.status = status
        self.children = []

def get_bbox_corners(bbox):
    min_x, min_y, min_z, max_x, max_y, max_z = bbox
    return [
        (min_x, min_y, min_z), (max_x, min_y, min_z), (min_x, max_y, min_z), (max_x, max_y, min_z),
        (min_x, min_y, max_z), (max_x, min_y, max_z), (min_x, max_y, max_z), (max_x, max_y, max_z)
    ]

def project_3d_to_2d(bbox, P):
    corners = get_bbox_corners(bbox)
    projected = []
    for x, y, z in corners:
        p_h = [x, y, z, 1.0]
        proj_h = [
            P[0][0]*p_h[0] + P[0][1]*p_h[1] + P[0][2]*p_h[2] + P[0][3]*p_h[3],
            P[1][0]*p_h[0] + P[1][1]*p_h[1] + P[1][2]*p_h[2] + P[1][3]*p_h[3],
            P[2][0]*p_h[0] + P[2][1]*p_h[1] + P[2][2]*p_h[2] + P[2][3]*p_h[3]
        ]
        if proj_h[2] != 0:
            projected.append((proj_h[0]/proj_h[2], proj_h[1]/proj_h[2]))
    if not projected:
        return None
    min_u = min(p[0] for p in projected)
    min_v = min(p[1] for p in projected)
    max_u = max(p[0] for p in projected)
    max_v = max(p[1] for p in projected)
    return (min_u, min_v, max_u, max_v)

def check_overlap(proj_2d, mask):
    min_u, min_v, max_u, max_v = proj_2d
    for u in range(int(min_u), int(max_u) + 1):
        for v in range(int(min_v), int(max_v) + 1):
            if 0 <= u < mask.width and 0 <= v < mask.height:
                if mask[v, u] == 1:
                    return True
    return False

def split_octant(bbox):
    min_x, min_y, min_z, max_x, max_y, max_z = bbox
    mid_x, mid_y, mid_z = (min_x+max_x)/2, (min_y+max_y)/2, (min_z+max_z)/2
    children = []
    for i in range(2):
        for j in range(2):
            for k in range(2):
                x0 = min_x if i == 0 else mid_x
                x1 = mid_x if i == 0 else max_x
                y0 = min_y if j == 0 else mid_y
                y1 = mid_y if j == 0 else max_y
                z0 = min_z if k == 0 else mid_z
                z1 = mid_z if k == 0 else max_z
                children.append(OctreeNode((x0, y0, z0, x1, y1, z1), 'INSIDE'))
    return children

def is_leaf(bbox, min_size):
    min_x, min_y, min_z, max_x, max_y, max_z = bbox
    return (max_x - min_x < min_size) or (max_y - min_y < min_size) or (max_z - min_z < min_size)

def construct_visual_hull(masks, projection_matrices, initial_bbox, min_size):
    root = OctreeNode(initial_bbox, 'INSIDE')
    queue = [root]
    while queue:
        node = queue.pop(0)
        proj_2ds = [project_3d_to_2d(node.bbox, P) for P in projection_matrices]
        if proj_2ds is None:
            node.status = 'OUTSIDE'
            continue
        all_intersect = True
        any_intersect = False
        for proj, mask in zip(proj_2ds, masks):
            if proj is None:
                all_intersect = False
                continue
            if check_overlap(proj, mask):
                any_intersect = True
            else:
                all_intersect = False
        if all_intersect:
            node.status = 'INSIDE'
        elif any_intersect:
            node.status = 'INTERSECTION'
        else:
            node.status = 'OUTSIDE'
        if node.status == 'OUTSIDE':
            continue
        if node.status == 'INSIDE' or is_leaf(node.bbox, min_size):
            continue
        node.children = split_octant(node.bbox)
        queue.extend(node.children)
    return root
```

**Ambiguity and Pitfalls:**
*   **Inside Vertex Identification:** Ambiguity arises when only part of an octant edge is within a silhouette (case b) or the silhouette is entirely within an octant (case c) [S1]. These cases frequently arise from imperfect silhouettes, projection matrix errors, or insufficient octree resolution [S1].
*   **Projection Errors:** Errors in $\theta$ or wobbly rotational axes propagate to surface construction errors [S1].
*   **Noise Robustness:** Octree construction is robust against image noise because an octant is only removed if no nonzero-valued pixels are found in its projection [S1]. However, simple thresholding preserves non-convex details but degrades the subsequent Marching Cubes surface [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the octree depth and the number of views [G]. Each node requires projection and intersection tests for all views [G]. Complexity is roughly $O(N \cdot V)$ where $N$ is the number of views and $V$ is the number of voxels/nodes in the octree [G].
*   **Memory Complexity:** Proportional to the number of nodes in the octree [G]. Sparse octrees save memory compared to dense voxel grids [G].
*   **Strengths:** Robust against image noise [S1]. Simple thresholding preserves non-convex details during construction [S1]. Efficient representation for large volumes with sparse object presence [G].
*   **Limitations:** Surface quality depends on octree resolution and the accuracy of silhouette extraction [S1]. Marching Cubes on octree leaves can produce degraded surfaces if silhouettes are imperfect [S1]. Single-view reconstruction requires symmetry assumptions which may not hold for arbitrary shapes [S2].
*   **When to Use:** When multiple views are available and computational efficiency is prioritized over high-fidelity surface detail [G]. Suitable for objects with clear silhouettes [G].
*   **When Not to Use:** When high-fidelity surface reconstruction is required from imperfect silhouettes without post-processing [S1]. Not suitable for single-view reconstruction of asymmetric objects without auxiliary assumptions [S2].

## Background
The concept of the 3D visual hull was introduced as the intersection of multiple 3D cones created by back-projecting 2D silhouettes [S1]. This technique is part of the broader Shape from Silhouette (SfS) family [S1]. The use of octrees for representing visual hulls became widely adopted due to their efficiency in handling sparse 3D data [S1]. The Marching Cubes algorithm, originally developed for medical imaging, is commonly used for surface extraction from these octrees [S1]. Recent applications include fluid reconstruction, where visual hulls guide density estimation [S2].
