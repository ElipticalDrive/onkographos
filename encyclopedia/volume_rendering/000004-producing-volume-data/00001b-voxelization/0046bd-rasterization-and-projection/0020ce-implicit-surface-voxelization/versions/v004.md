# Implicit Surface Voxelization
Also called: Iso-surface voxelization
## Overview
Implicit Surface Voxelization converts an analytical implicit surface into a discrete voxel grid by rasterizing a sequence of rectangles within the Region of Interest (ROI) and evaluating the implicit function in the pixel shader [S1, S2, unofficial]. It differs from [Parametric Surface Voxelization](6032-parametric-surface-voxelization.md) by evaluating the surface equation in the pixel shader rather than computing positions in the vertex shader, and from [Mesh Rasterization and Triangle Intersection](11783-mesh-rasterization-and-triangle-intersection.md) by handling non-polygonal, analytically defined surfaces directly [S1, S2, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** An implicit surface function $f(\mathbf{x})$, the Region of Interest (ROI) bounding the surface, and a target voxel grid resolution.
*   **Output:** A voxel grid where each voxel is marked as occupied (binary) or contains a value (solid) based on the implicit function evaluation.

**Data Structures:**
*   **Render Target:** A 2D texture or buffer representing the projection of the ROI. Each pixel corresponds to a specific 3D coordinate in the voxel grid.
*   **Implicit Function:** A mathematical function $f(\mathbf{x})$ defining the surface, typically evaluated in a shader program.

**Steps:**
1.  **Generate Rectangles:** The host application computes the ROI of the target surface. A sequence of rectangles is generated that are embedded within this ROI [S1, S2, unofficial].
2.  **Rasterize Rectangles:** Each rectangle is rasterized to the render target from front to back [S1, S2, unofficial].
3.  **Evaluate Implicit Surface:** For each pixel in the render target, the pixel's coordinates are used to determine the corresponding 3D point $\mathbf{x}$ in space [S1, S2, unofficial]. The implicit function $f(\mathbf{x})$ is evaluated.
4.  **Check Conditions:** If the result of the implicit function satisfies given conditions, the pixel is output and transformed to the worksheet (voxel grid) [S1, S2, unofficial].
5.  **Voxelization Type:**
    *   **Binary Voxelization:** Extracts the defined iso-surface, typically where $f(\mathbf{x}) = 0$ [S1, S2, unofficial].
    *   **Solid Voxelization:** Finds an interval that satisfies some inequation, such as $f(\mathbf{x}) \leq 0$ or a range of values, to determine occupancy [S1, S2, unofficial].

**Pseudocode:**
```python
def implicit_surface_voxelization(implicit_func, roi, voxel_grid, resolution):
    """
    Voxelize an implicit surface by rasterizing rectangles in the ROI.
    
    Args:
        implicit_func: Function f(x) evaluating the implicit surface.
        roi: Bounding box or list of rectangles defining the Region of Interest.
        voxel_grid: 3D array to store voxel data.
        resolution: Number of voxels per dimension.
    """
    # Step 1: Generate a sequence of rectangles embedded in the ROI
    # [G] Implementation detail: This typically involves creating a set of 
    # screen-space or world-space quads that cover the bounding volume of interest.
    rectangles = generate_rectangles_in_roi(roi)
    
    # Step 2: Rasterize each rectangle to a render target from front to back
    # [G] Implementation detail: The render target is a 2D buffer where each 
    # pixel maps to a 3D coordinate. Front-to-back ordering ensures correct 
    # overwriting or accumulation if needed.
    render_target = initialize_render_target(resolution)
    
    for rect in rectangles:
        rasterize_rectangle_to_target(rect, render_target)
        
    # Step 3 & 4: Evaluate implicit surface and check conditions
    for y in range(resolution[1]):
        for x in range(resolution[0]):
            # Get 3D coordinate corresponding to pixel (x, y)
            # [G] Implementation detail: This requires the inverse projection 
            # or ray origin/direction setup used during rasterization.
            point_3d = get_3d_point_from_pixel(render_target, x, y)
            
            # Evaluate implicit function
            value = implicit_func(point_3d)
            
            # Check if result satisfies given conditions
            # [G] Implementation detail: For binary, check value == 0 (or within epsilon).
            # For solid, check value <= 0 or value in [min, max].
            if is_occupied(value):
                # Output pixel and transform to worksheet
                voxel_grid[x, y, :] = mark_voxel(value)
                
    return voxel_grid

def is_occupied(value):
    # [G] Placeholder for specific condition logic (binary vs solid)
    # Binary: abs(value) < epsilon
    # Solid: value <= 0
    return value <= 0.0
```

**Parameters:**
*   **ROI:** Defines the spatial extent of the surface. Computed by the host application [S1, S2, unofficial].
*   **Instruction Slots:** The shader program must support enough long instruction slots to handle very complex implicit surfaces [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Complexity:** Very complex implicit surfaces may exceed shader instruction limits [S1, S2, unofficial].
*   **Precision:** The accuracy of the voxelization depends on the precision of the implicit function evaluation and the rasterization process.
*   **Binary vs. Solid:** Binary voxelization extracts the exact iso-surface, while solid voxelization requires finding an interval satisfying an inequation, which may lead to over- or under-estimation of volume if not carefully defined [S1, S2, unofficial].

## Subtopics

### Analytical Implicit Voxelization
An approach to rendering general-form implicit surfaces by sampling an analytical implicit into a regular grid by voxelization, followed by direct volume rendering [S3, unofficial]. It is chosen when subvoxel surface detail is critical or when the implicit surface is defined analytically and needs to be rendered as a volume [S3, unofficial].

### Smooth Visual Hull Reconstruction
Voxelization of a surface defined as the product of $n$ filtered silhouette images. The surface is the isosurface $S(\mathbf{p}) = 0.5$, where $S(\mathbf{p})$ is the product of silhouette values projected into NVC space [S4]. It is used for image-based modeling from multiple camera views [S4]. The surface is defined by:
$$ S(\mathbf{p}) = \prod_i \mathcal{I}_i(\mathcal{C}_i(\mathbf{p})) $$
where $\mathcal{I}_i: \mathbb{R}^2 \rightarrow [0, 1]$ is the filtered silhouette image for camera $i$, and $\mathcal{C}_i: \mathbb{R}^3 \rightarrow \mathbb{R}^2$ is the projective transform from NVC space to image space for camera $i$ [S4]. The gradient $\nabla S(\mathbf{p})$ is normal to the surface, providing a smooth normal field if the silhouette images are smooth [S4].

## Operating characteristics
*   **Time Complexity:** Depends on the number of rectangles generated and the resolution of the render target. Rasterization is generally efficient on GPUs [S1, S2, unofficial].
*   **Memory Complexity:** Proportional to the size of the voxel grid and the render target [S1, S2, unofficial].
*   **Strengths:** Can handle very complex implicit surfaces given sufficient shader instruction slots [S1, S2, unofficial]. Real-time performance is achievable [S1, S2, unofficial].
*   **Limitations:** Limited by shader instruction length for very complex functions [S1, S2, unofficial]. Binary voxelization extracts the iso-surface, while solid voxelization requires interval finding, which may be less precise [S1, S2, unofficial].
*   **When to Use:** When the surface is defined analytically and real-time voxelization is required [S1, S2, unofficial].
*   **When Not to Use:** When the implicit function is too complex for the available shader instruction slots [S1, S2, unofficial].

## Background
The method was proposed in "Real-time Voxelization for Complex Models" [S1, S2, unofficial]. It is part of a broader effort to enable real-time voxelization for complex models, including implicit and parametric surfaces [S1, S2, unofficial]. The approach leverages GPU rasterization and shader programming to evaluate implicit functions efficiently [S1, S2, unofficial].
