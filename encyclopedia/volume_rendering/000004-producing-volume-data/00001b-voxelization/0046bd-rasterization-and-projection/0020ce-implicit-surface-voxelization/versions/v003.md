# Implicit Surface Voxelization

Also called: Iso-surface voxelization

## Overview
Implicit Surface Voxelization maps a continuous implicit surface definition into a discrete 3D grid by rasterizing bounding rectangles and evaluating the implicit function in a pixel shader [S1, S2, unofficial]. It solves the problem of converting analytical or complex implicit representations into a volumetric format suitable for direct volume rendering or further geometric processing [S3, unofficial]. Unlike [Parametric Surface Voxelization](6032-parametric-surface-voxelization.md), which evaluates surface positions in the vertex shader, this method evaluates the implicit function per-pixel, allowing for arbitrary implicit definitions provided the shader supports the necessary instruction count [S1, S2, unofficial].

## How it works
**Inputs:**
*   An implicit surface function $f(\mathbf{x})$ where $\mathbf{x} \in \mathbb{R}^3$.
*   A Region of Interest (ROI) bounding box defined in 3D space.
*   A target 3D grid resolution $(N_x, N_y, N_z)$.
*   A voxelization type: Binary (extracting the iso-surface) or Solid (filling the volume).

**Outputs:**
*   A 3D voxel grid where each voxel stores a value indicating occupancy, distance, or scalar field value.

**Data Structures:**
*   **Render Target:** A 2D texture or framebuffer used during rasterization. Each pixel corresponds to a specific 3D coordinate within the ROI.
*   **Voxel Grid:** A 3D array or texture storing the final voxel values.

**Steps:**
1.  **ROI Partitioning:** The host application computes the ROI of the target surface. A sequence of rectangles (or other primitives) is generated that are embedded within this ROI [S1, S2, unofficial].
2.  **Rasterization:** Each rectangle is rasterized to the render target from front to back [S1, S2, unofficial].
3.  **Implicit Evaluation:** For each pixel in the render target, the pixel's coordinates are interpreted as a 3D point $\mathbf{p}$ in the workspace [S1, S2, unofficial]. The implicit function $f(\mathbf{p})$ is evaluated in the pixel shader [S1, S2, unofficial].
4.  **Condition Check:** The result of $f(\mathbf{p})$ is checked against specific conditions [S1, S2, unofficial].
    *   **Binary Voxelization:** The defined iso-surface is extracted. Typically, this involves checking if $f(\mathbf{p}) = 0$ or if the sign of $f(\mathbf{p})$ changes relative to neighbors [S1, S2, unofficial].
    *   **Solid Voxelization:** An interval satisfying an inequality is found. For example, if $f(\mathbf{p}) \leq 0$, the voxel is marked as inside the solid [S1, S2, unofficial].
5.  **Output:** If the condition is satisfied, the pixel is output and transformed into the final voxel worksheet/grid [S1, S2, unofficial].

**Pseudocode:**
```python
def implicit_surface_voxelization(implicit_func, roi_bounds, grid_resolution, voxel_type='binary'):
    """
    Voxelize an implicit surface by rasterizing rectangles within the ROI.
    
    Args:
        implicit_func: Function f(p) -> float, evaluating the implicit surface at point p.
        roi_bounds: Bounding box (min_x, min_y, min_z, max_x, max_y, max_z) defining the ROI.
        grid_resolution: Tuple (Nx, Ny, Nz) defining the output voxel grid dimensions.
        voxel_type: 'binary' to extract iso-surface, 'solid' to fill volume.
        
    Returns:
        3D numpy array of shape (Nz, Ny, Nx) containing voxel values.
    """
    # Initialize output grid
    # Note: In a real GPU implementation, this is a render target or compute buffer.
    voxel_grid = create_3d_buffer(grid_resolution)
    
    # Step 1: Generate rectangles embedded in the ROI.
    # The source describes generating a sequence of rectangles. 
    # For implementation, we assume a set of rectangles covering the ROI.
    # A simple approach is to slice the ROI into planes or use bounding quads.
    rectangles = generate_rectangles_in_roi(roi_bounds)
    
    # Step 2: Rasterize each rectangle to a render target from front to back.
    # We simulate the rasterization process by iterating over pixels covered by rectangles.
    # In a GPU implementation, this is done via the graphics pipeline.
    
    for rect in rectangles:
        # Determine the 3D points corresponding to the pixels of this rectangle.
        # The rectangle is embedded in 3D space.
        pixel_points = rasterize_rect_to_3d_points(rect, grid_resolution, roi_bounds)
        
        for point in pixel_points:
            # Step 3: Evaluate the implicit surface at the point.
            value = implicit_func(point)
            
            # Step 4: Check conditions based on voxelization type.
            is_valid = False
            if voxel_type == 'binary':
                # Binary voxelization extracts the defined iso-surface.
                # Typically checks if the point is on the surface (value approx 0)
                # or uses a threshold.
                if abs(value) < 1e-6: # Threshold for iso-surface
                    is_valid = True
            elif voxel_type == 'solid':
                # Solid voxelization involves finding an interval that satisfies some inequation.
                # Typically checks if the point is inside the object.
                if value <= 0: # Assuming f(p) <= 0 is inside
                    is_valid = True
            
            # Step 5: Output the pixel and transform to the worksheet.
            if is_valid:
                # Transform point to grid coordinates
                grid_coords = world_to_grid(point, roi_bounds, grid_resolution)
                # Write to voxel grid
                voxel_grid[grid_coords] = 1.0 # Or store 'value' for solid voxelization
                
    return voxel_grid

def generate_rectangles_in_roi(roi_bounds):
    """
    Generate a sequence of rectangles embedded in the ROI.
    This is a placeholder for the specific geometry generation strategy.
    Common strategies include slicing the ROI into planes or using bounding quads.
    """
    # Example: Generate rectangles parallel to XY plane at each Z slice
    min_x, min_y, min_z, max_x, max_y, max_z = roi_bounds
    Nx, Ny, Nz = 100, 100, 100 # Example resolution for rectangle generation
    
    rectangles = []
    for z in range(Nz):
        z_coord = min_z + (z / Nz) * (max_z - min_z)
        rect = {
            'vertices': [
                (min_x, min_y, z_coord),
                (max_x, min_y, z_coord),
                (max_x, max_y, z_coord),
                (min_x, max_y, z_coord)
            ],
            'normal': (0, 0, 1)
        }
        rectangles.append(rect)
    return rectangles

def rasterize_rect_to_3d_points(rect, grid_resolution, roi_bounds):
    """
    Simulate rasterization of a rectangle to get 3D points corresponding to grid voxels.
    """
    # This function maps the 2D rasterization of the rectangle to 3D grid coordinates.
    # In a real implementation, this is handled by the GPU rasterizer.
    # Here, we assume the rectangle covers a subset of the grid.
    # We return a list of 3D points that fall within the rectangle's projection.
    points = []
    min_x, min_y, min_z, max_x, max_y, max_z = roi_bounds
    Nx, Ny, Nz = grid_resolution
    
    # Determine the range of grid indices covered by the rectangle
    # This is a simplified approximation.
    # In reality, the rectangle's position and orientation determine the covered voxels.
    
    # For the example rectangle (XY plane at z_coord):
    z_coord = rect['vertices'][0][2]
    z_idx = int((z_coord - min_z) / (max_z - min_z) * Nz)
    
    for x_idx in range(Nx):
        for y_idx in range(Ny):
            x = min_x + (x_idx / Nx) * (max_x - min_x)
            y = min_y + (y_idx / Ny) * (max_y - min_y)
            points.append((x, y, z_coord))
            
    return points

def world_to_grid(point, roi_bounds, grid_resolution):
    """
    Transform a 3D world point to 3D grid coordinates.
    """
    min_x, min_y, min_z, max_x, max_y, max_z = roi_bounds
    Nx, Ny, Nz = grid_resolution
    
    x, y, z = point
    
    # Clamp to bounds
    x = max(min_x, min(x, max_x))
    y = max(min_y, min(y, max_y))
    z = max(min_z, min(z, max_z))
    
    # Map to grid indices
    x_idx = int((x - min_x) / (max_x - min_x) * Nx)
    y_idx = int((y - min_y) / (max_y - min_y) * Ny)
    z_idx = int((z - min_z) / (max_z - min_z) * Nz)
    
    # Clamp indices to grid size
    x_idx = max(0, min(x_idx, Nx - 1))
    y_idx = max(0, min(y_idx, Ny - 1))
    z_idx = max(0, min(z_idx, Nz - 1))
    
    return (z_idx, y_idx, x_idx) # Return as (z, y, x) for numpy array indexing
```

**Parameters:**
*   **Instruction Slots:** The method can handle very complex implicit surfaces provided the shader program supports enough long instruction slots [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Evaluating the implicit function in the pixel shader requires sufficient precision to correctly determine the iso-surface, especially for complex surfaces [S1, S2, unofficial].
*   **Coverage:** The sequence of rectangles must fully cover the ROI to ensure no voxels are missed [S1, S2, unofficial].
*   **Front-to-Back Order:** Rasterizing from front to back ensures correct depth handling if the implicit surface has multiple intersections [S1, S2, unofficial].

## Subtopics

### Analytical Implicit Voxelization
An approach to rendering general-form implicit surfaces by sampling an analytical implicit into a regular grid by voxelization, followed by direct volume rendering [S3, unofficial]. This variant emphasizes the use of the voxelized data for direct volume rendering rather than just surface extraction [S3, unofficial].

### Smooth Visual Hull Reconstruction
Voxelization of a surface defined as the product of $n$ filtered silhouette images. The surface is the isosurface $S(\mathbf{p}) = 0.5$, where $S(\mathbf{p})$ is the product of silhouette values projected into NVC space [S4]. The surface is defined by:
$$S(\mathbf{p}) = \prod_i I_i(C_i(\mathbf{p}))$$
where $I_i: \mathbb{R}^2 \rightarrow [0, 1]$ is the filtered silhouette image for camera $i$, and $C_i: \mathbb{R}^3 \rightarrow \mathbb{R}^2$ is the projective transform from NVC space to image space for camera $i$ [S4]. This method provides a smooth normal field over the surface if the silhouette images are smooth [S4].

## Operating characteristics
*   **Time Complexity:** Depends on the number of rectangles generated and the resolution of the render target. The implicit function evaluation is performed per pixel, so complexity is proportional to the number of pixels in the rasterized rectangles [S1, S2, unofficial].
*   **Memory Complexity:** Proportional to the size of the 3D voxel grid and the render target [S1, S2, unofficial].
*   **Strengths:** Can handle very complex implicit surfaces given sufficient shader instruction slots [S1, S2, unofficial]. It leverages GPU rasterization hardware for efficient sampling [S1, S2, unofficial].
*   **Limitations:** Requires the implicit function to be evaluable in a shader [S1, S2, unofficial]. The quality of the voxelization depends on the coverage of the rectangles and the precision of the implicit function evaluation [S1, S2, unofficial].
*   **When to Use:** When the implicit surface is defined by a complex analytical function that can be evaluated in a shader, and real-time or near-real-time voxelization is required [S1, S2, unofficial].
*   **When Not to Use:** When the implicit function is too complex for the shader's instruction limit, or when the ROI is very large and the number of rectangles becomes prohibitive [S1, S2, unofficial].

## Background
Implicit Surface Voxelization is a technique for converting implicit surface representations into voxel grids. It is often used in applications such as collision detection, volume-based modeling, and transparent illustrations [S2, unofficial]. The method leverages GPU rasterization to efficiently sample the implicit function [S1, S2, unofficial]. Variants like Smooth Visual Hull Reconstruction use this approach for image-based modeling [S4]. Analytical Implicit Voxelization is used for rendering general-form implicit surfaces via direct volume rendering [S3, unofficial].
