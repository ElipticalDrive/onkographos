# Implicit Surface Voxelization
Also called: Iso-surface voxelization
## Overview
Implicit Surface Voxelization converts an analytical implicit surface into a discrete voxel grid by rasterizing a sequence of rectangles within the Region of Interest (ROI) and evaluating the implicit function in the pixel shader [S1, S2, unofficial]. It differs from [Parametric Surface Voxelization](6032-parametric-surface-voxelization.md) by evaluating the surface equation in the pixel shader rather than computing positions in the vertex shader, and from [Rasterization and GPU Shaders](11755-rasterization-and-gpu-shaders.md) by handling non-polygonal, analytically defined surfaces directly [S1, S2, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** An implicit surface function $f(\mathbf{x})$, the Region of Interest (ROI) bounding the surface, and a target voxel grid resolution [S1, unofficial].
*   **Output:** A voxel grid where each voxel is marked as occupied (binary) or contains a value (solid) based on the implicit function evaluation [S1, unofficial].

**Data Structures:**
*   **Render Target:** A 2D buffer or texture representing the projection of the ROI. Each pixel corresponds to a specific 3D coordinate in the voxel grid [S1, unofficial].
*   **Implicit Function:** A mathematical function $f(\mathbf{x})$ defining the surface, evaluated in a shader program [S1, unofficial].

**Steps:**
1.  **Generate Rectangles:** The host application computes the ROI of the target surface and generates a sequence of rectangles embedded within it [S1, S2, unofficial].
2.  **Rasterize Rectangles:** Each rectangle is rasterized to the render target from front to back [S1, S2, unofficial].
3.  **Evaluate Implicit Surface:** For each pixel in the render target, the pixel's coordinates determine the corresponding 3D point $\mathbf{x}$ in space [S1, S2, unofficial]. The implicit function $f(\mathbf{x})$ is evaluated.
4.  **Check Conditions:** If the result satisfies given conditions, the pixel is output and transformed to the worksheet (voxel grid) [S1, S2, unofficial].
5.  **Voxelization Type:**
    *   **Binary Voxelization:** Extracts the defined iso-surface [S1, S2, unofficial].
    *   **Solid Voxelization:** Finds an interval that satisfies some inequation [S1, S2, unofficial].

**Pseudocode:**
```python
class Quad:
    def __init__(self, screen_bounds, ray_origin, ray_direction):
        self.screen_bounds = screen_bounds # (min_x, max_x, min_y, max_y)
        self.ray_origin = ray_origin
        self.ray_direction = ray_direction

    def point_at_pixel(self, x, y):
        # [G] Standard inverse projection: ray = origin + direction * (x, y, 1)
        return self.ray_origin + self.ray_direction * (x, y, 1.0)

def implicit_surface_voxelization(implicit_func, quads, voxel_grid, resolution):
    # Step 1: Generate a sequence of rectangles embedded in the ROI
    # [G] The host application computes the ROI and provides a list of quads covering it.
    rectangles = quads

    # Step 2: Rasterize each rectangle to a render target from front to back
    # [G] Render target is a 2D buffer mapping pixel indices to 3D coordinates.
    render_target = [[None for _ in range(resolution[0])] for _ in range(resolution[1])]
    for quad in rectangles:
        min_x, max_x, min_y, max_y = quad.screen_bounds
        for y in range(min_y, max_y + 1):
            for x in range(min_x, max_x + 1):
                render_target[y][x] = quad.point_at_pixel(x, y)

    # Step 3 & 4: Evaluate implicit surface and check conditions
    for y in range(resolution[1]):
        for x in range(resolution[0]):
            point_3d = render_target[y][x]
            if point_3d is None:
                continue
            value = implicit_func(point_3d)
            if value <= 0.0:
                # Output pixel and transform to worksheet (voxel grid)
                # [G] Mapping 2D pixel to 3D voxel slice depends on projection setup
                voxel_grid[x, y, :] = 1.0
    return voxel_grid
```

**Parameters:**
*   **ROI:** Defines the spatial extent of the surface. Computed by the host application [S1, S2, unofficial].
*   **Instruction Slots:** The shader program must support enough long instruction slots to handle very complex implicit surfaces [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Complexity:** Very complex implicit surfaces may exceed shader instruction limits [S1, S2, unofficial].
*   **Precision:** The accuracy of the voxelization depends on the precision of the implicit function evaluation and the rasterization process [G].
*   **Binary vs. Solid:** Binary voxelization extracts the defined iso-surface, while solid voxelization requires finding an interval satisfying an inequation [S1, S2, unofficial].

## Subtopics

### Analytical Implicit Voxelization
An approach to rendering general-form implicit surfaces by sampling an analytical implicit into a regular grid by voxelization, followed by direct volume rendering [S3, unofficial]. It is chosen when subvoxel surface detail is critical or when the implicit surface is defined analytically and needs to be rendered as a volume [S3, unofficial].

### [Smooth Visual Hull Reconstruction](5917-smooth-visual-hull-reconstruction.md)
Voxelization of a surface defined as the product of $n$ filtered silhouette images [G]. The surface is the isosurface $S(\mathbf{p}) = 0.5$, where $S(\mathbf{p})$ is the product of silhouette values projected into NVC space [G]. It is used for image-based modeling from multiple camera views [G]. The surface is defined by:
$$ S(\mathbf{p}) = \prod_i \mathcal{I}_i(\mathcal{C}_i(\mathbf{p})) $$
where $\mathcal{I}_i: \mathbb{R}^2 \rightarrow [0, 1]$ is the filtered silhouette image for camera $i$, and $\mathcal{C}_i: \mathbb{R}^3 \rightarrow \mathbb{R}^2$ is the projective transform from NVC space to image space for camera $i$ [G]. The gradient $\nabla S(\mathbf{p})$ is normal to the surface, providing a smooth normal field if the silhouette images are smooth [G].

## Operating characteristics
*   **Time Complexity:** Depends on the number of rectangles generated and the resolution of the render target. Rasterization is generally efficient on GPUs [S1, S2, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Can handle very complex implicit surfaces given sufficient shader instruction slots [S1, S2, unofficial]. Real-time performance is achievable [S1, S2, unofficial].
*   **Limitations:** Limited by shader instruction length for very complex functions [S1, S2, unofficial].
*   **When to Use:** When the surface is defined analytically and real-time voxelization is required [S1, S2, unofficial].
*   **When Not to Use:** When shader instruction limits are insufficient for the implicit function complexity [S1, S2, unofficial].

## Background
The method was proposed in "Real-time Voxelization for Complex Models" [S1, S2, unofficial]. It is part of a broader effort to enable real-time voxelization for complex models, including implicit and parametric surfaces [S1, S2, unofficial]. The approach leverages GPU rasterization and shader programming to evaluate implicit functions efficiently [S1, S2, unofficial].
