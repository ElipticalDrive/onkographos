# Rasterization


## Overview
Rasterization is a rendering technique that exploits the geometric properties of objects (primarily meshes) to quickly create a 2D image from 3D data [S1, unofficial]. It solves the problem of mapping continuous geometric primitives to a discrete pixel buffer by projecting vertices and interpolating face attributes, rather than simulating light transport [S1, unofficial]. It is distinguished from ray tracing by its performance scaling with visible geometry rather than pixel count, making it the standard for high-performance applications like video games, though it is less flexible for physically-based rendering (PBR) effects [S2].

## How it works
**Inputs:**
*   A set of vertices $V$ and faces $F$ (triangles or quads) defining the geometry.
*   An extrinsic camera matrix $E$ (world-to-camera transformation).
*   An intrinsic camera matrix $K$ (projection parameters).
*   A 2D image buffer (framebuffer) with associated depth buffer (z-buffer).

**Outputs:**
*   A discretized 2D image buffer containing color and depth values for each pixel.

**Data Structures:**
*   **Vertices:** Array of 3D points $(x, y, z)$ in world space.
*   **Faces:** List of indices referencing vertices, defining surface connectivity.
*   **Z-buffer:** 2D array storing depth values for occlusion testing.

**Steps:**
1.  **Transform:** Transform each vertex $v$ from world coordinates to camera coordinates using the extrinsic matrix $E$:
    $$ v_{cam} = E \cdot v $$
2.  **Cull:** Discard vertices or faces that are outside the view frustum or have incorrect normal orientation (back-face culling) to reduce processing load [S1, unofficial].
3.  **Project:** Project the remaining camera-space vertices to 2D image coordinates using the intrinsic matrix $K$:
    $$ p_{image} = K \cdot v_{cam} $$
4.  **Interpolate and Rasterize:** For each visible face, interpolate attributes (such as depth) across the 2D projected triangle. Store the topmost (closest to camera) face values in the z-buffer, overwriting previous values if the new depth is smaller [S1, unofficial].

**Pitfalls:**
*   Harder to capture complex lighting effects, shadows, and reflections compared to ray casting [S1, unofficial].
*   Implementing physically-based rendering (PBR) numerical methods atop rasterization is markedly harder or impossible in some cases compared to ray-tracing [S2].

## Operating characteristics
*   **Performance:** Scales with the number of visible vertices and primitives, not the number of pixels [S1, unofficial]. This makes it significantly faster than ray casting for scenes with many pixels but manageable geometry.
*   **Parallelization:** Highly parallelizable on GPUs, favoring its use in real-time applications like video games [S2].
*   **Limitations:** Struggles with accurate global illumination, shadows, and reflections without additional techniques (e.g., shadow maps, screen-space reflections) [S1, unofficial]. PBR implementation is restricted compared to ray tracing [S2].
*   **Differentiability:** Can be made differentiable through "soft" rasterization techniques, enabling use in optimization and learning-based rendering [S1, unofficial].

## Background
Rasterization is an alternative to ray casting, primarily used with meshes described by vertices and faces [S1, unofficial]. It was developed as a method to quickly create images by exploiting geometric properties rather than emulating the physical image formation process [S1, unofficial]. Modern approaches have extended it to be differentiable for neural rendering applications [S1, unofficial].
