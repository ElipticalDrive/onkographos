# Cylindrical Rasterization

Also called: Cylindrical voxel grid conversion, Line- and triangle-drawing algorithms for rotating screen coordinate space, Proprietary efficient rasterization algorithms, Raster Engine Coordinate Transformation and Rasterization, Volumetric Rasterization

## Overview
Cylindrical Rasterization is a specialized scan-conversion technique that transforms standard 3D geometric primitives (lines and triangles) or volumetric data into a cylindrical voxel grid coordinate system, specifically designed for volumetric displays featuring a rotating screen [S1, S2]. Unlike traditional Cartesian rasterization, this method accounts for the unique kinematics of a rotating projection plane and projector-induced keystoning, ensuring that voxels are correctly mapped to the physical display space [S1, S2]. It is distinct from general 3D scan-conversion [1895-3d-scan-conversion.md] by its explicit handling of the cylindrical coordinate transformation required for rotating hardware, rather than static volume buffers.

## How it works
**Inputs and Outputs:**
*   **Input:** 3D geometric data (polygons/lines) or pre-existing volumetric data (e.g., MRI, seismic) from a host PC [S1, S2].
*   **Output:** Voxel data in the 3D-display-specific coordinate system, stored in graphics memory for continuous display [S2].

**Data Structures:**
*   **Graphics Memory:** Partitioned into volume buffers. In the reference implementation, this is 3 Gbits (expandable to 6 Gbits) of DDR SDRAM [S1].
*   **Buffer Layout:** Each buffer stores 198 slices of 768 x 768 imagery [S1].
*   **Coordinate System:** Defined as the composition of a rotating screen with a rotation in the plane of the screen [S2].

**Steps:**
1.  **Data Reception:** The Raster Engine accepts volumetric or geometry-based 3D data from the host PC via a SCSI interface [S2].
2.  **Pre-processing (Geometry Only):**
    *   Split polygons into triangles [S2].
    *   Clip polygons that fall outside the cylindrical volume of the display [S2].
    *   Calculate parameters required to draw in the display's specific coordinate system [S2]. This involves proprietary algorithms to handle the non-Cartesian space and keystoning [S1, S2].
3.  **Pre-processing (Volumetric Data Only):**
    *   Resample the volumetric data so that points in volumetric space align with the cylindrical grid [S2].
    *   *Note:* Volumetric data may optionally be transformed into polygonal surfaces for rendering [S2].
4.  **Rasterization/Conversion:** Convert the prepared data into voxel data in the 3D-display-specific coordinate system [S2]. Traditional scan-conversion algorithms are not applicable due to the cylindrical coordinate system [S1].
5.  **Memory Storage:** Store the resulting voxel data into graphics memory [S1, S2].
6.  **Synchronization:** A motor controller pages through memory in tight synchronization with the position of the rotating screen [S1].
7.  **Output:** The graphics memory is read out to the projector subsystem (e.g., DMD formatter electronics) at a rate of 24 volumes/second [S1].

**Pseudocode:**
```python
def cylindrical_rasterization(host_data, display_config):
    """
    host_data: List of polygons or volumetric grid points
    display_config: Object containing cylindrical parameters, memory layout, and motor sync
    """
    # 1. Receive data from host via SCSI
    data = receive_from_host(host_data)
    
    # 2. Pre-process geometry or volumetric data
    if is_geometry(data):
        # Split polygons into triangles
        triangles = split_into_triangles(data.polygons)
        
        # Clip triangles outside the cylindrical volume
        clipped_triangles = clip_to_cylindrical_volume(triangles, display_config.cylinder_radius)
        
        # Calculate parameters for the specific coordinate system
        # This step uses proprietary algorithms to handle rotation and keystoning
        raster_params = calculate_cylindrical_raster_params(clipped_triangles, display_config)
        
        # Convert to voxel data in display coordinate system
        voxel_data = rasterize_to_voxels(raster_params, display_config.grid_resolution)
        
    elif is_volumetric(data):
        # Resample volumetric data to the cylindrical grid
        voxel_data = resample_volumetric_to_cylindrical(data.grid, display_config.grid_resolution)
        
    # 3. Store in graphics memory
    # Memory is partitioned into buffers (e.g., 198 slices of 768x768)
    write_to_graphics_memory(voxel_data, display_config.memory_layout)
    
    # 4. Synchronize with rotating screen
    # Motor controller pages through memory based on screen position
    while display_config.is_running:
        screen_angle = get_motor_encoder_position()
        current_slice_index = map_angle_to_slice(screen_angle, display_config)
        read_slice_from_memory(current_slice_index)
        send_to_projector()
```

**Parameters and Typical Values:**
*   **Memory:** 3 Gbits DDR SDRAM (standard), up to 6 Gbits (high resolution) [S1].
*   **Resolution:** 768 x 768 pixels per slice [S1].
*   **Slices per Volume:** 198 slices [S1].
*   **Update Rate:** 24 volumes/second [S1].
*   **Interface:** SCSI [S2].

**Edge Cases and Pitfalls:**
*   **Coordinate Mismatch:** Traditional scan-conversion algorithms fail because the display uses a cylindrical coordinate system rather than Cartesian [S1].
*   **Keystoning:** Projector-induced keystoning distorts the image, requiring specific parameter calculations during rasterization [S2].
*   **Bottleneck:** For volumetric data, the SCSI connection speed is the primary bottleneck, limiting update rates and image complexity [S2].

## Operating characteristics
*   **Time Complexity:** Not explicitly defined in terms of Big-O, but the system supports 24 volumes/second for 198 slices of 768x768 imagery [S1].
*   **Memory Complexity:** Requires significant dedicated graphics memory (3-6 Gbits) to buffer the entire volume for continuous display [S1].
*   **Performance:** The system can support higher resolution imagery than the current projector generates, allowing for up to 6 Gbits of RAM [S1]. For volumetric data, performance is limited by the SCSI bandwidth [S2].
*   **Strengths:** Enables real-time 3D visualization on rotating cylindrical displays; handles both geometry and raw volumetric data [S1, S2].
*   **Limitations:** Proprietary algorithms limit portability; SCSI bottleneck for volumetric data; requires custom hardware (DSP, motor controller) [S1, S2].
*   **When to use:** When rendering to a volumetric display with a rotating screen component [S1, S2].
*   **When not to use:** For standard Cartesian displays or static volume rendering without rotation [S1].

## Background
Cylindrical Rasterization was developed for a 100-million-voxel volumetric display system [S1]. The hardware implementation uses a Texas Instruments TMS320C6201 DSP as the Raster Engine [S1]. The algorithms were created because existing line- and triangle-drawing algorithms were unsuitable for the display's unique coordinate space and projector-induced keystoning [S2]. The system was presented at SPIE Vol. 4297A, "Stereoscopic Displays and Virtual Reality Systems IX" in San Jose, CA, in January 2001 [S2].
