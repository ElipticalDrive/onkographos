# Rasterization-based Voxelization Shader

Also called: GVShader, Geometry Volume (GV) Shader

## Overview
A fragment shader that rasterizes geometry into a 3D grid volume by mapping clip-space coordinates to grid indices and writing a value to a structured buffer [S1, unofficial]. It differs from [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by operating directly on the GPU via fragment shaders to produce volumetric data (binary occupancy or spherical harmonic coefficients) rather than 2D buffers, and from [Mesh-to-Voxel Geometry Shader](2800-mesh-to-voxel-geometry-shader.md) by relying on standard rasterization pipelines rather than explicit geometry shader topology expansion [S1, S2, unofficial].

## How it works
**Inputs:**
- Clip-space vertex positions and vertex normals [S1, S2, unofficial].
- Grid resolution parameter: `_CVCT_GridResolutionI` for CVCT or `_LPV_GridResolution` for LPV [S1, S2, unofficial].
- Transformation matrix `_LPV_WorldToLightLocalMatrix` for converting world normals to light local space [S2, unofficial].
- Boolean flag `UNITY_REVERSED_Z` indicating reversed-Z depth buffer layout [S1, S2, unofficial].
- Fixed-point conversion scale `SH_F2I` for spherical harmonic coefficients [S2, unofficial].

**Outputs:**
- `_CVCT_gv`: A `RWStructuredBuffer<int>` storing binary occupancy values (1 for a hit) [S1, unofficial].
- `_RSM_gv`: A `RWStructuredBuffer<int>` storing spherical harmonic (SH) coefficients weighted by normal, used for lighting accumulation [S2, unofficial].

**Data Structures:**
- **Grid Indexing:** 3D integer coordinates $(pos_x, pos_y, pos_z)$ mapped to a 1D linear index [S1, S2, unofficial].
  - CVCT: $index = pos_x + pos_y \cdot R + pos_z \cdot R^2$, where $R = \_CVCT\_GridResolutionI$ [S1, unofficial].
  - LPV: $index = (pos_x + R \cdot (pos_y + R \cdot pos_z)) \cdot 4$, storing 4 integer components per voxel [S2, unofficial].
- **Spherical Harmonic Coefficients:** Stored as `int4` in `_RSM_gv`, representing the first-order SH basis functions for the normal direction [S2, unofficial].

**Steps:**
1. **Vertex Transformation:** Transform vertex position to clip space and vertex normal to world space [S2, unofficial].
2. **Clip-Space Extraction:** Extract the clip-space position $xyz$ from the vertex shader output [S1, unofficial].
3. **Z-Handling:** If `UNITY_REVERSED_Z` is defined, invert the Z component: $xyz.z = 1 - xyz.z$ [S1, S2, unofficial].
4. **Coordinate Scaling:** Scale $xyz.z$ by the grid resolution multiplied by $0.99999$ (using `_CVCT_GridResolutionI` for CVCT or `_LPV_GridResolution` for LPV) [S1, S2, unofficial]. The factor $0.99999$ prevents out-of-bounds writes due to floating-point precision errors at the grid boundary [S1, unofficial].
5. **Integer Conversion:** Cast the scaled coordinates to integer grid coordinates `int3 pos` [S1, S2, unofficial].
6. **Orientation Permutation (LPV only):** If `ORIENTATION_2` is defined, permute `pos = pos.yzx` and set `reduce = normal.y`. If `ORIENTATION_3` is defined, permute `pos = pos.zxy` and set `reduce = normal.x` [S2, unofficial].
7. **Index Calculation:** Compute the linear buffer index based on the grid resolution and permuted coordinates [S1, S2, unofficial].
8. **Value Computation:**
   - CVCT: The value is simply `1` (binary occupancy) [S1, unofficial].
   - LPV: Transform the normal to light local space, then compute spherical harmonic normal coefficients: `shNormalScaled = int4(dirToCosineLobe(normal) * SH_F2I * (reduce * reduce))` [S2, unofficial].
9. **Atomic Write:**
   - CVCT: Write `1` to `_CVCT_gv[index]` [S1, unofficial].
   - LPV: Atomically add `shNormalScaled` components to `_RSM_gv[index]`, `_RSM_gv[index+1]`, `_RSM_gv[index+2]`, and `_RSM_gv[index+3]` [S2, unofficial].

**Pseudocode (CVCT Variant):**
```python
def frag_cvct(clip_pos, grid_res, reversed_z, buffer):
    xyz = clip_pos[:3]
    if reversed_z:
        xyz[2] = 1.0 - xyz[2]
    xyz[2] *= grid_res * 0.99999
    pos = [int(x) for x in xyz]
    index = pos[0] + pos[1] * grid_res + pos[2] * (grid_res * grid_res)
    buffer[index] = 1
```

**Pseudocode (LPV Variant):**
```python
import math

def normalize(v):
    l = math.sqrt(sum(x*x for x in v))
    return [x/l for x in v]

def mul(M, v):
    return [sum(M[i][j]*v[j] for j in range(3)) for i in range(3)]

def dir_to_cosine_lobe(normal):
    # First-order SH cosine lobe projection [S2, unofficial]
    C0 = 0.886226925
    C1 = 1.02332671
    return [C0, -C1 * normal[1], C1 * normal[2], -C1 * normal[0]]

def atomic_add(buffer, index, value):
    buffer[index] = buffer[index] + value

def frag_lpv(clip_pos, world_normal, grid_res, reversed_z, orientation, world_to_light_matrix, buffer, SH_F2I):
    xyz = clip_pos[:3]
    if reversed_z:
        xyz[2] = 1.0 - xyz[2]
    xyz[2] *= grid_res * 0.99999
    pos = [int(x) for x in xyz]
    
    light_normal = normalize(mul(world_to_light_matrix, world_normal))
    
    if orientation == 2:
        pos = [pos[1], pos[2], pos[0]]
        reduce = light_normal[1]
    elif orientation == 3:
        pos = [pos[2], pos[0], pos[1]]
        reduce = light_normal[0]
    else:
        reduce = light_normal[2]
        
    base_index = (pos[0] + grid_res * (pos[1] + grid_res * pos[2])) * 4
    
    sh_coeffs = dir_to_cosine_lobe(light_normal)
    sh_scaled = [int(c * SH_F2I * (reduce * reduce)) for c in sh_coeffs]
    
    atomic_add(buffer, base_index, sh_scaled[0])
    atomic_add(buffer, base_index + 1, sh_scaled[1])
    atomic_add(buffer, base_index + 2, sh_scaled[2])
    atomic_add(buffer, base_index + 3, sh_scaled[3])
```

## Operating characteristics
- Time and memory complexity: Not given in the sources [S1, S2, unofficial].
- Strengths: Efficient GPU-based voxelization without CPU-GPU synchronization; supports atomic operations for concurrent writes [S1, S2, unofficial].
- Limitations: Precision issues at grid boundaries require the `0.99999` scaling factor; orientation permutations add complexity for LPV [S1, S2, unofficial].
- When to use: When real-time voxelization is required for techniques like Cascaded Voxel Cone Tracing (CVCT) or Local Persistent Volumes (LPV) [S1, S2, unofficial].

## Background
The method originates from implementations of Cascaded Voxel Cone Tracing (CVCT) and Local Persistent Volumes (LPV) in real-time rendering engines [S1, S2, unofficial]. The CVCT variant was introduced by arigo in the "CascatedVoxelConeTracing" repository, while the LPV variant was developed in the "LPVTest" repository [S1, S2, unofficial]. These methods are used in Unity-based projects to provide efficient global illumination and shadowing [S1, S2, unofficial].
