# Rasterization-based Voxelization Shader

Also called: GVShader, Geometry Volume (GV) Shader

## Overview
A fragment shader that rasterizes geometry into a 3D grid volume by mapping clip-space coordinates to grid indices and writing a value to a structured buffer [S1, S2, unofficial]. It differs from [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by operating directly on the GPU via compute/fragment shaders to produce volumetric data (such as binary occupancy or spherical harmonic coefficients) rather than just 2D depth or color buffers, and from [Mesh-to-Voxel Geometry Shader](2800-mesh-to-voxel-geometry-shader.md) by relying on standard rasterization pipelines rather than explicit geometry shader topology expansion [S1, S2, unofficial].

## How it works
**Inputs:**
- Vertex positions transformed to clip space.
- Vertex normals transformed to world or light local space.
- Grid resolution parameters: `_CVCT_GridResolutionI` (integer) or `_LPV_GridResolution` [S1, S2, unofficial].
- Transformation matrices: `_LPV_WorldToLightLocalMatrix` for normal transformation [S2, unofficial].

**Outputs:**
- `_CVCT_gv`: A `RWStructuredBuffer<int>` storing binary occupancy values (1 for hit, 0 otherwise) [S1, unofficial].
- `_RSM_gv`: A `RWStructuredBuffer<int>` storing spherical harmonic (SH) coefficients weighted by normal, used for lighting accumulation [S2, unofficial].

**Data Structures:**
- **Grid Indexing:** 3D integer coordinates $(pos_x, pos_y, pos_z)$ mapped to a 1D linear index.
  - For CVCT: $index = pos_x + pos_y \cdot R + pos_z \cdot R^2$, where $R = \_CVCT\_GridResolutionI$ [S1, unofficial].
  - For LPV: $index = (pos_x + R \cdot (pos_y + R \cdot pos_z)) \cdot 4$, storing 4 components per voxel [S2, unofficial].
- **Spherical Harmonic Coefficients:** Stored as `int4` in `_RSM_gv`, representing the first-order SH basis functions for the normal direction [S2, unofficial].

**Steps:**
1. **Vertex Transformation:** Transform vertex position to clip space and normal to world space (or light local space for LPV) [S1, S2, unofficial].
2. **Clip-Space Extraction:** Extract the clip-space position $xyz$ from the vertex shader output [S1, unofficial].
3. **Z-Handling:** If `UNITY_REVERSED_Z` is defined, invert the Z component: $xyz.z = 1 - xyz.z$ [S1, S2, unofficial].
4. **Coordinate Scaling:**
   - For CVCT: Scale $xyz.z$ by `_CVCT_GridResolutionI * 0.99999` [S1, unofficial].
   - For LPV: Scale $xyz.z$ by `_LPV_GridResolution * 0.99999` [S2, unofficial].
   - *Note:* The factor `0.99999` prevents out-of-bounds writes due to floating-point precision errors at the grid boundary [S1, unofficial].
5. **Integer Conversion:** Cast the scaled coordinates to `int3 pos` [S1, S2, unofficial].
6. **Orientation Permutation (LPV only):** If `ORIENTATION_2` is defined, permute `pos = pos.yzx` and set `reduce = normal.y`. If `ORIENTATION_3` is defined, permute `pos = pos.zxy` and set `reduce = normal.x` [S2, unofficial].
7. **Index Calculation:** Compute the linear buffer index based on the grid resolution [S1, S2, unofficial].
8. **Value Computation:**
   - **CVCT:** The value is simply `1` (binary occupancy) [S1, unofficial].
   - **LPV:** Compute spherical harmonic normal coefficients: `shNormalScaled = int4(dirToCosineLobe(normal) * SH_F2I * (reduce * reduce))` [S2, unofficial].
9. **Atomic Write:**
   - **CVCT:** Write `1` to `_CVCT_gv[index]` [S1, unofficial].
   - **LPV:** Atomically add `shNormalScaled` components to `_RSM_gv[index]`, `_RSM_gv[index+1]`, `_RSM_gv[index+2]`, and `_RSM_gv[index+3]` [S2, unofficial].

**Pseudocode (CVCT Variant):**
```python
# Vertex Shader
def vert(vertex_pos):
    clip_pos = UnityObjectToClipPos(vertex_pos)
    return clip_pos

# Fragment Shader
def frag(clip_pos):
    xyz = clip_pos.xyz
    
    # Handle reversed Z if applicable
    if UNITY_REVERSED_Z:
        xyz.z = 1 - xyz.z
        
    # Scale Z to grid resolution with precision guard
    xyz.z *= _CVCT_GridResolutionI * 0.99999
    
    # Convert to integer grid coordinates
    pos = int3(xyz)
    
    # Calculate flat index
    R = _CVCT_GridResolutionI
    index = pos.x + pos.y * R + pos.z * (R * R)
    
    # Write to buffer
    _CVCT_gv[index] = 1
```

**Pseudocode (LPV Variant):**
```python
# Vertex Shader
def vert(vertex_pos, vertex_normal):
    clip_pos = UnityObjectToClipPos(vertex_pos)
    world_normal = normalize(mul((float3x3)UNITY_MATRIX_IT_MV, vertex_normal))
    return clip_pos, world_normal

# Fragment Shader
def frag(clip_pos, world_normal):
    xyz = clip_pos.xyz
    
    # Handle reversed Z if applicable
    if UNITY_REVERSED_Z:
        xyz.z = 1 - xyz.z
        
    # Scale Z to grid resolution with precision guard
    xyz.z *= _LPV_GridResolution * 0.99999
    
    # Convert to integer grid coordinates
    pos = int3(xyz)
    
    # Orientation permutation (example for ORIENTATION_2)
    if ORIENTATION_2:
        pos = pos.yzx
        reduce = world_normal.y
    elif ORIENTATION_3:
        pos = pos.zxy
        reduce = world_normal.x
    else:
        reduce = world_normal.z # Default assumption if not specified
        
    # Transform normal to light local space
    light_normal = normalize(mul((float3x3)_LPV_WorldToLightLocalMatrix, world_normal))
    
    # Calculate index
    R = _LPV_GridResolution
    base_index = (pos.x + R * (pos.y + R * pos.z)) * 4
    
    # Compute SH coefficients
    # dirToCosineLobe returns a float4 representing SH coefficients for the direction
    sh_coeffs = dirToCosineLobe(light_normal)
    sh_scaled = int4(sh_coeffs * SH_F2I * (reduce * reduce))
    
    # Atomic add to buffer
    atomic_add(_RSM_gv, base_index, sh_scaled.x)
    atomic_add(_RSM_gv, base_index + 1, sh_scaled.y)
    atomic_add(_RSM_gv, base_index + 2, sh_scaled.z)
    atomic_add(_RSM_gv, base_index + 3, sh_scaled.w)
```

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of triangles, as each triangle is rasterized and processed per fragment [S1, S2, unofficial].
- **Memory Complexity:** $O(R^3)$ for the structured buffer, where $R$ is the grid resolution [S1, S2, unofficial].
- **Strengths:** Efficient GPU-based voxelization without CPU-GPU synchronization; supports atomic operations for concurrent writes [S1, S2, unofficial].
- **Limitations:** Precision issues at grid boundaries require the `0.99999` scaling factor; orientation permutations add complexity for LPV [S1, S2, unofficial].
- **When to Use:** When real-time voxelization is required for techniques like Cascaded Voxel Cone Tracing (CVCT) or Local Persistent Volumes (LPV) [S1, S2, unofficial].

## Background
The method originates from implementations of Cascaded Voxel Cone Tracing (CVCT) and Local Persistent Volumes (LPV) in real-time rendering engines [S1, S2, unofficial]. The CVCT variant was introduced by arigo in the "CascatedVoxelConeTracing" repository, while the LPV variant was developed in the "LPVTest" repository [S1, S2, unofficial]. These methods are used in Unity-based projects to provide efficient global illumination and shadowing [S1, S2, unofficial].
