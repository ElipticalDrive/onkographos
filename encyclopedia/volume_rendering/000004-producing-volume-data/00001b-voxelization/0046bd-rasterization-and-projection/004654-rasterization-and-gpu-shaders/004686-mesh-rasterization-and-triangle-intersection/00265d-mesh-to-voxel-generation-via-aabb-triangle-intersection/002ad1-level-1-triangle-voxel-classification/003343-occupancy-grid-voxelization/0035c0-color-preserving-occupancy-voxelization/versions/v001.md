# Color-Preserving Occupancy Voxelization

Also called: Color Preservation in Occupancy Grids

## Overview
This method extends standard occupancy grid voxelization by storing the index of the first intersecting mesh face in each occupied voxel, rather than a binary occupancy flag. This preserves color information by mapping face indices to voxel values, allowing the original mesh colors to be reconstructed from the voxel grid. It differs from [Occupancy Grid Voxelization](6958-occupancy-grid-voxelization.md) by retaining per-voxel identity data instead of simple presence/absence.

## How it works
**Inputs:**
- A watertight triangular mesh in OFF format.
- Optional color data associated with mesh faces.
- Grid dimensions: `width`, `height`, `depth`.
- Voxel bounds defined by minimum and maximum coordinates.

**Outputs:**
- An occupancy grid where occupied voxels store a face index (integer).
- If color preservation is enabled, a separate HDF5 file (`_color.h5`) containing the original mesh face colors.

**Data Structures:**
- **Occupancy Grid:** A 3D array of integers with dimensions `width x height x depth`.
    - Value `0` indicates empty space.
    - Value `f` (where $f > 0$) indicates the voxel intersects with face index $f$.
    - Value `num_faces()` indicates the voxel intersects with face index 0 (see Pitfalls).
- **Color File:** An HDF5 file storing RGB color vectors for each face.

**Steps:**
1. Initialize a parallel loop over all voxel indices $i$ from $0$ to $width \times height \times depth - 1$.
2. Calculate voxel coordinates $(w, h, d)$ from index $i$:
   $$ d = i \pmod{depth} $$
   $$ w = \left\lfloor \frac{i}{depth} \right\rfloor \pmod{width} $$
   $$ h = \left\lfloor \frac{i}{width \times depth} \right\rfloor $$
3. Define the voxel bounding box using integer coordinates:
   - Minimum corner: $(w, h, d)$
   - Maximum corner: $(w + 1, h + 1, d + 1)$
4. Loop over all mesh faces $f$ from $0$ to $num\_faces() - 1$.
5. Retrieve the three vertices $v_1, v_2, v_3$ of face $f$.
6. Perform triangle-box intersection test:
   $$ overlap = \text{triangle\_box\_intersection}((w, h, d), (w+1, h+1, d+1), v_1, v_2, v_3) $$
7. If $overlap$ is true:
   - Determine the stored value $val$:
     - If $f == 0$, set $val = num\_faces()$.
     - Otherwise, set $val = f$.
   - Store $val$ in the occupancy grid at $(h, w, d)$.
   - Break the face loop (only the first intersecting face is stored).
8. If the `--color` flag is set, save the mesh face colors to a separate color file.

**Pseudocode:**
```python
def color_preserving_voxelization(mesh, width, height, depth, use_color=False):
    num_faces = mesh.num_faces()
    # Initialize grid with 0 (empty)
    occ_grid = [[0] * width for _ in range(height)]
    for z in range(depth):
        occ_grid[z] = [row[:] for row in occ_grid] # Deep copy if needed, or 3D array

    # Parallel loop over voxels
    for i in range(width * height * depth):
        d = i % depth
        w = (i // depth) % width
        h = (i // (width * depth)) % height

        # Voxel bounds
        min_coord = (w, h, d)
        max_coord = (w + 1, h + 1, d + 1)

        # Check faces
        for f in range(num_faces):
            v1, v2, v3 = mesh.get_face_vertices(f)
            
            if triangle_box_intersection(min_coord, max_coord, v1, v2, v3):
                # Store face index, handling face 0 special case
                if f == 0:
                    occ_grid[h][w][d] = num_faces
                else:
                    occ_grid[h][w][d] = f
                break # First face found

    if use_color:
        save_colors_to_hdf5(mesh, "output_color.h5")

    return occ_grid
```

**Parameters:**
- `--color`: Boolean flag. When set, enables color preservation mode.
- `width`, `height`, `depth`: Integer dimensions of the voxel grid.

**Edge Cases and Pitfalls:**
- **Face Index 0:** Face index 0 is treated as "not voxelized" space by default because 0 is the empty value. If face 0 intersects a voxel, the value `num_faces()` is stored instead to distinguish it from empty space [S1, unofficial].
- **Multiple Color Files:** When converting the voxel grid back to an OFF file using `occ_to_off.py`, if multiple color files are provided, their ordering is critical [S2, unofficial].
- **Watertight Meshes:** The input triangular meshes should be watertight. Simplification or semi-convex hull algorithms may be required to ensure this [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(V \cdot F)$, where $V$ is the number of voxels and $F$ is the number of faces. In practice, spatial acceleration structures (not detailed in the source) are often used to reduce this, but the base method iterates all faces for all voxels or uses a broad-phase check.
- **Memory Complexity:** $O(V)$ for the occupancy grid plus $O(F)$ for the color storage if enabled.
- **Strengths:** Preserves color information directly in the voxel index, allowing lossless reconstruction of face colors for visualization.
- **Limitations:** Only stores the *first* intersecting face. If a voxel intersects multiple faces, only one is recorded. Face 0 requires special handling.
- **When to use:** When color information is needed for the voxelized representation and the mesh is watertight.
- **When not to use:** When multiple surface interactions per voxel are required, or when face 0 is common and the special mapping is undesirable.

## Background
This method is part of the `mesh-voxelization` toolkit by David Stutz. It is designed to work with OFF format meshes and provides a bridge between mesh-based and voxel-based representations while retaining attribute data. The approach relies on the assumption that the first intersecting face is sufficient for color preservation.
