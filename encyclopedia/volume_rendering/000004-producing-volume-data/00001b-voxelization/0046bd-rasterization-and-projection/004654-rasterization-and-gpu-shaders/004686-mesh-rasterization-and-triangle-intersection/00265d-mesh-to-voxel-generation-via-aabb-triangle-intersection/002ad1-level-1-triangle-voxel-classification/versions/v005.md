# Level 1 Triangle-Voxel Classification

Also called: CUDAClassifyTessellationKernel

## Overview
Level 1 Triangle-Voxel Classification maps a triangle mesh into a coarse 3D voxel grid by determining which voxels intersect with each triangle. It solves the problem of spatial indexing for volume rendering by creating a list of candidate triangles for every voxel, enabling efficient downstream processing. It differs from [Tessellation-based Voxelization](5430-tessellation-based-voxelization.md) by operating on a fixed grid rather than tessellating geometry, and from [Fake Voxelization via Triangle-Cube Intersection](6951-fake-voxelization-via-triangle-cube-intersection.md) by explicitly computing overlaps for all voxels in the triangle's bounding box rather than approximating with a single cube.

## How it works
**Inputs:**
- `trianglesCUDAData`: Flat float array, stride 9 per triangle (v0.x, v0.y, v0.z, v1.x, v1.y, v1.z, v2.x, v2.y, v2.z) [S1, unofficial].
- `objBoxMin`, `objBoxMax`: Scene bounding box coordinates (float3) [S1, unofficial].
- `numDiv`: 3D grid resolution (int3: numDiv.x, numDiv.y, numDiv.z) [S1, unofficial].
- `boxExtents`: Voxel size parameter (float3) [S1, unofficial].
- `inOutCUDAData`, `voxelTriCountCUDAData`, `voxelTriIndexCUDAData`: Buffers for voxel triangle lists [S1, unofficial].
- `triBufferLen`: Maximum number of triangles allocated per voxel in the buffer [S1, unofficial].

**Outputs:**
- Populated `voxelTriIndexCUDAData` and `voxelTriCountCUDAData` indicating which triangles intersect which voxels.

**Data Structures:**
- Voxel grid is indexed linearly: `index = r * numDiv.y * numDiv.x + q * numDiv.x + p`, where `(p, q, r)` are the voxel coordinates [S1, unofficial].
- Each voxel maintains a list of triangle indices, capped at `triBufferLen` [S1, unofficial].

**Steps:**
1. Each thread processes one triangle. Extract 3 vertices from `trianglesCUDAData` at offset `t*9` [S1, unofficial].
2. Map each vertex to voxel indices. For vertex $i \in \{0, 1, 2\}$:
   $$
   \text{boxNumX}_i = \left\lfloor \frac{\text{vertex}_i.x - \text{objBoxMin}.x}{\text{objBoxMax}.x - \text{objBoxMin}.x} \times \text{numDiv}.x \right\rfloor
   $$
   $$
   \text{boxNumY}_i = \left\lfloor \frac{\text{vertex}_i.y - \text{objBoxMin}.y}{\text{objBoxMax}.y - \text{objBoxMin}.y} \times \text{numDiv}.y \right\rfloor
   $$
   $$
   \text{boxNumZ}_i = \left\lfloor \frac{\text{vertex}_i.z - \text{objBoxMin}.z}{\text{objBoxMax}.z - \text{objBoxMin}.z} \times \text{numDiv}.z \right\rfloor
   $$
   Clamp boundary: if $\text{boxNumX}_i == \text{numDiv}.x$ and $\text{vertex}_i.x == \text{objBoxMax}.x$, then $\text{boxNumX}_i \leftarrow \text{boxNumX}_i - 1$. Repeat for Y and Z [S1, unofficial].
3. Compute min/max box indices across the 3 vertices:
   $$
   \text{minBoxX} = \min(\text{boxNumX}_0, \text{boxNumX}_1, \text{boxNumX}_2)
   $$
   $$
   \text{maxBoxX} = \max(\text{boxNumX}_0, \text{boxNumX}_1, \text{boxNumX}_2)
   $$
   Repeat for Y and Z [S1, unofficial].
4. Iterate $p$ from $\text{minBoxX}$ to $\text{maxBoxX}$, $q$ from $\text{minBoxY}$ to $\text{maxBoxY}$, $r$ from $\text{minBoxZ}$ to $\text{maxBoxZ}$ [S1, unofficial].
5. For each voxel $(p, q, r)$, compute box midpoint:
   $$
   \text{boxMidPoint}.x = (p + 0.5) \times \text{boxExtents}.x \times 2 + \text{objBoxMin}.x
   $$
   $$
   \text{boxMidPoint}.y = (q + 0.5) \times \text{boxExtents}.y \times 2 + \text{objBoxMin}.y
   $$
   $$
   \text{boxMidPoint}.z = (r + 0.5) \times \text{boxExtents}.z \times 2 + \text{objBoxMin}.z
   $$
   [S1, unofficial].
6. Call `TriBoxOverlapCUDA(boxMidPoint, boxExtent, triVerts)`. If overlap, compute linear index: $r \times \text{numDiv}.y \times \text{numDiv}.x + q \times \text{numDiv}.x + p$. Add triangle index to voxel list via `AddPointToVoxel` [S1, unofficial].

**Pseudocode:**
```python
def classify_triangle(t, triangles, objBoxMin, objBoxMax, numDiv, boxExtents, voxel_lists, tri_buffer_len):
    # Extract vertices
    v0 = triangles[t*9 : t*9+3]
    v1 = triangles[t*9+3 : t*9+6]
    v2 = triangles[t*9+6 : t*9+9]
    
    # Map vertices to voxel indices
    def map_vertex(v, axis):
        idx = int((v[axis] - objBoxMin[axis]) / (objBoxMax[axis] - objBoxMin[axis]) * numDiv[axis])
        if idx == numDiv[axis] and v[axis] == objBoxMax[axis]:
            idx -= 1
        return idx

    bx0, by0, bz0 = map_vertex(v0, 0), map_vertex(v0, 1), map_vertex(v0, 2)
    bx1, by1, bz1 = map_vertex(v1, 0), map_vertex(v1, 1), map_vertex(v1, 2)
    bx2, by2, bz2 = map_vertex(v2, 0), map_vertex(v2, 1), map_vertex(v2, 2)
    
    # Compute bounding box of voxels
    min_x, max_x = min(bx0, bx1, bx2), max(bx0, bx1, bx2)
    min_y, max_y = min(by0, by1, by2), max(by0, by1, by2)
    min_z, max_z = min(bz0, bz1, bz2), max(bz0, bz1, bz2)
    
    # Iterate over candidate voxels
    for p in range(min_x, max_x + 1):
        for q in range(min_y, max_y + 1):
            for r in range(min_z, max_z + 1):
                # Compute voxel center
                cx = (p + 0.5) * boxExtents[0] * 2 + objBoxMin[0]
                cy = (q + 0.5) * boxExtents[1] * 2 + objBoxMin[1]
                cz = (r + 0.5) * boxExtents[2] * 2 + objBoxMin[2]
                
                # Check intersection
                if tri_box_overlap((cx, cy, cz), boxExtents, (v0, v1, v2)):
                    # Compute linear index
                    idx = r * numDiv[1] * numDiv[0] + q * numDiv[0] + p
                    # Add triangle to voxel list
                    add_triangle_to_voxel(idx, t, voxel_lists, tri_buffer_len)
```

## Operating characteristics
- **Time Complexity:** $O(N \cdot B)$, where $N$ is the number of triangles and $B$ is the average number of voxels in the triangle's bounding box. The bounding box size depends on triangle size relative to voxel size.
- **Memory Complexity:** $O(V + T_{total})$, where $V$ is the number of voxels and $T_{total}$ is the total number of triangle-voxel intersections stored, capped by `triBufferLen` per voxel.
- **Performance:** Parallelized on GPU with one thread per triangle. Performance scales with the number of triangles and the spatial coherence of the mesh.
- **Strengths:** Simple to implement, efficient for coarse grids, leverages GPU parallelism.
- **Limitations:** Coarse resolution may miss thin features; requires careful handling of boundary conditions; memory usage can be high for dense meshes.

## Background
Originated in the GPView project by idealab-isu, this method is part of a pipeline for real-time volume rendering from mesh data. It is designed for GPU execution, utilizing CUDA kernels for parallel processing.
