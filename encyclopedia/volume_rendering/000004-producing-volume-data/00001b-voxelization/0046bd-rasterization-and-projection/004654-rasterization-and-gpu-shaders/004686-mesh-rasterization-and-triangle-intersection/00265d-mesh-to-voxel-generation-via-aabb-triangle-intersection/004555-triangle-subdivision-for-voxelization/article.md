# Triangle Subdivision for Voxelization

Also called: Triangle Split, Triangle Splitting, Pre-processing Subdivision

## Overview
Triangle Subdivision for Voxelization is a pre-processing method that recursively splits mesh triangles to ensure they are small enough to be voxelized efficiently and predictably [S1, S2]. It solves the problem of variable voxel counts per triangle, which complicates memory allocation and parallel processing in out-of-core or batch-based voxelization pipelines [S1]. Unlike general-purpose mesh smoothing or tessellation, this method is geometry-driven, targeting specific edge-length or area thresholds relative to the voxel resolution to guarantee homogeneous voxel generation and compact Morton index ranges [S1]. It differs from [Level 1 Triangle-Voxel Classification](4872-level-1-triangle-voxel-classification.md) by actively modifying the mesh geometry rather than just classifying existing triangles, and from [Tessellation-based Voxelization](5430-tessellation-based-voxelization.md) by using a deterministic, CPU/GPU-friendly iterative queue rather than hardware tessellation pipelines [S1, S2].

## How it works
**Inputs:**
- A triangle soup $\{T_i\}$, where each triangle $T$ has three vertices and three edge lengths $T.a, T.b, T.c$ [S1].
- A user-defined parameter $K_{vox/tri}^{max}$, the maximum allowed ratio of the triangle's projected bounding box area to the voxel face area [S1].
- The voxel grid resolution, defined by the voxel edge length $L$ [S1].

**Outputs:**
- A refined set of triangles $\{T_i\}$ (stored in result queue $R$) such that for every triangle, the area of its projected bounding box $A_{bbox}(T)$ satisfies $A_{bbox}(T) \le K_{vox/tri}^{max} \cdot A_{vox}$ [S1].
- An upper bound $N_{vox/tri}^{max}(T_i)$ for the number of voxels generated by each resulting triangle, used for pre-allocating memory [S1].

**Data Structures:**
- Queue $Q$: Stores triangles pending subdivision [S1].
- Queue $R$: Stores triangles that satisfy the area constraint and are ready for voxelization [S1].
- Edge lengths: For each triangle, edges are sorted such that $T.a \le T.b \le T.c$ [S1].

**Formulas:**
1. **Voxel Face Area:** $A_{vox} = L^2$ [S1].
2. **Subdivision Condition:** A triangle $T$ is subdivided if $A_{bbox}(T) > K_{vox/tri}^{max} \cdot A_{vox}$ [S1].
3. **Voxel Count Upper Bound:** $N_{vox/tri}^{max}(T_i)$ is calculated by discretizing the projected bounding box of $T_i$ onto the voxel grid to count enclosed projected voxels, then multiplying by 3 [S1]. The factor of 3 accounts for the maximum number of voxels a planar triangle can occupy along the projection direction [S1].

**Parameters:**
- $K_{vox/tri}^{max}$: User-defined threshold controlling the granularity of the subdivision [S1].
- $L$: Voxel edge length; [S2] references a threshold where the longest edge must be smaller than 0.5 voxel [S2].

**Steps:**
1. Initialize $Q$ with all input triangles $\{T_i\}$ and $R$ as empty [S1].
2. While $Q$ is not empty:
   a. Dequeue triangle $T$ from $Q$ [S1].
   b. Calculate $A_{bbox}(T)$, the area of the projected bounding box of $T$ [S1].
   c. If $A_{bbox}(T) \le K_{vox/tri}^{max} \cdot A_{vox}$:
      i. Enqueue $T$ into $R$ [S1].
   d. Else, apply subdivision logic based on sorted edge lengths $T.a \le T.b \le T.c$ [S1]:
      i. **Case 1 (Long thin, obtuse):** If $(T.a + T.b) < 2 \cdot T.c$ (angles larger than $\sim 90^\circ$):
         - Split $T$ into two triangles.
         - Append the resulting triangles to $Q$ [S1].
      ii. **Case 2 (Long thin, acute):** If $3 \cdot T.a < T.b$ (angles smaller than $\sim 20^\circ$):
         - Subdivide $T$ to generate approximately equilateral triangles by cutting the short edge $T.a$ off the long edges and splitting the resulting quadrilateral.
         - Append the resulting triangles to $Q$ [S1].
      iii. **Case 3 (Regular):** Otherwise:
         - Compute subdivision factor $s = \sqrt{A_{bbox}(T) / (K_{vox/tri}^{max} \cdot A_{vox})}$ [S1].
         - Subdivide $T$ directly using this factor to satisfy the area constraint.
         - Enqueue the resulting triangles into $R$ [S1].
3. The final set of triangles is $\{T_i\} = R$ [S1].

```python
import math

def triangle_subdivision(triangles, K_max, L):
    """
    Subdivides triangles until their projected bounding box area is within limits.
    
    Args:
        triangles: List of dicts with 'v0', 'v1', 'v2' (each a tuple of 3 floats).
        K_max: User-defined max ratio of bbox area to voxel face area.
        L: Voxel edge length.
        
    Returns:
        List of subdivided triangles satisfying the area constraint.
    """
    A_vox = L * L
    Q = list(triangles)
    R = []
    
    while Q:
        T = Q.pop(0)
        A_bbox = compute_projected_bbox_area(T)
        
        if A_bbox <= K_max * A_vox:
            R.append(T)
        else:
            edges = sorted([edge_length(T, 0, 1), edge_length(T, 1, 2), edge_length(T, 2, 0)])
            a, b, c = edges[0], edges[1], edges[2]
            
            if (a + b) < 2 * c:
                # Case 1: Long thin, obtuse (>90 deg)
                new_tris = split_triangle_obtuse(T)
                Q.extend(new_tris)
            elif 3 * a < b:
                # Case 2: Long thin, acute (<20 deg)
                new_tris = subdivide_triangle_acute(T)
                Q.extend(new_tris)
            else:
                # Case 3: Regular
                factor = math.sqrt(A_bbox / (K_max * A_vox))
                new_tris = regular_subdivide(T, factor)
                R.extend(new_tris)
                
    return R

def compute_projected_bbox_area(T):
    """Projects triangle to the plane perpendicular to its dominant normal axis and returns bbox area."""
    v0, v1, v2 = T['v0'], T['v1'], T['v2']
    # Compute normal
    n = cross(sub(v1, v0), sub(v2, v0))
    # Determine dominant axis
    axes = [('x', 0), ('y', 1), ('z', 2)]
    dominant = max(axes, key=lambda ax: abs(n[ax[1]]))
    # Project vertices onto the plane perpendicular to dominant axis
    proj = []
    for v in [v0, v1, v2]:
        p = list(v)
        p[dominant[1]] = 0.0
        proj.append(p)
    # Compute 2D bounding box area
    mins = [min(p[i] for p in proj) for i in range(3)]
    maxs = [max(p[i] for p in proj) for i in range(3)]
    # Use the two non-dominant axes for area
    axes_used = [ax[1] for ax in axes if ax[1] != dominant[1]]
    return (maxs[axes_used[0]] - mins[axes_used[0]]) * (maxs[axes_used[1]] - mins[axes_used[1]])

def edge_length(T, i, j):
    return math.dist(T[f'v{i}'], T[f'v{j}'])

def sub(a, b): return tuple(a[i] - b[i] for i in range(3))
def cross(a, b): return (a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0])

def split_triangle_obtuse(T):
    """Splits a triangle with one long edge and two short edges by connecting the midpoint of the longest edge to the opposite vertex."""
    edges = sorted([edge_length(T, 0, 1), edge_length(T, 1, 2), edge_length(T, 2, 0)])
    a, b, c = edges[0], edges[1], edges[2]
    # Identify longest edge indices
    if c == edge_length(T, 0, 1): i1, i2 = 0, 1
    elif c == edge_length(T, 1, 2): i1, i2 = 1, 2
    else: i1, i2 = 2, 0
    opposite = 3 - i1 - i2
    mid = tuple((T[f'v{i1}'][k] + T[f'v{i2}'][k]) / 2.0 for k in range(3))
    return [
        {'v0': T[f'v{i1}'], 'v1': T[f'v{opposite}'], 'v2': mid},
        {'v0': T[f'v{i2}'], 'v1': T[f'v{opposite}'], 'v2': mid}
    ]

def subdivide_triangle_acute(T):
    """Generates approximately equilateral triangles from a long thin acute triangle by cutting the short edge off the long edges."""
    edges = sorted([edge_length(T, 0, 1), edge_length(T, 1, 2), edge_length(T, 2, 0)])
    a, b, c = edges[0], edges[1], edges[2]
    # Identify short edge indices
    if a == edge_length(T, 0, 1): i1, i2 = 0, 1
    elif a == edge_length(T, 1, 2): i1, i2 = 1, 2
    else: i1, i2 = 2, 0
    # Cut short edge off long edges: create points on the two long edges at distance 'a' from the shared vertex
    shared = 3 - i1 - i2
    v_short1 = T[f'v{i1}']
    v_short2 = T[f'v{i2}']
    v_shared = T[f'v{shared}']
    len_long1 = edge_length(T, shared, i1)
    len_long2 = edge_length(T, shared, i2)
    p1 = tuple(v_shared[k] + (v_short1[k] - v_shared[k]) * (a / len_long1) for k in range(3))
    p2 = tuple(v_shared[k] + (v_short2[k] - v_shared[k]) * (a / len_long2) for k in range(3))
    # Split resulting quadrilateral into two triangles
    return [
        {'v0': v_short1, 'v1': v_short2, 'v2': p1},
        {'v0': v_short2, 'v1': v_shared, 'v2': p2}
    ]

def regular_subdivide(T, factor):
    """Subdivides a triangle uniformly based on a scaling factor to meet the area constraint."""
    # Uniform subdivision: divide each edge into 'factor' segments and fill
    n = max(2, int(math.ceil(factor)))
    new_tris = []
    for i in range(n):
        for j in range(n - i):
            # Barycentric interpolation
            p0 = tuple(T[f'v{k}'][d] + (T[f'v{(k+1)%3}'][d] - T[f'v{k}'][d]) * (i / n) for k in range(3) for d in range(3))
            p1 = tuple(T[f'v{k}'][d] + (T[f'v{(k+1)%3}'][d] - T[f'v{k}'][d]) * ((i + j + 1) / n) for k in range(3) for d in range(3))
            p2 = tuple(T[f'v{k}'][d] + (T[f'v{(k+2)%3}'][d] - T[f'v{k}'][d]) * ((i + j) / n) for k in range(3) for d in range(3))
            new_tris.append({'v0': p0, 'v1': p1, 'v2': p2})
    return new_tris
```

**Edge Cases and Pitfalls:**
- **Termination:** The subdivision logic guarantees termination because Case 1 splits a triangle into two triangles that fall into Case 2 or Case 3, and Case 3 directly satisfies the area constraint [S1].
- **Precision:** Floating-point comparisons for area thresholds and edge lengths require an epsilon guard to avoid infinite recursion on near-degenerate inputs [G].
- **Degenerate Input:** Triangles with zero area or collinear vertices should be filtered out before subdivision begins [G].

## Subtopics

### [Legolizer Subdivision](14398-legolizer-subdivision.md)
A GPU-based iterative refinement strategy that subdivides a triangular mesh until all edge lengths are smaller than or equal to a user-defined cube size $r$. It solves the problem of preparing boundary models for voxelization into "LEGOr" representations, ensuring uniform sampling and watertightness by guaranteeing that at least one vertex of the input mesh lies inside each resulting voxel brick. It differs from general-purpose subdivision schemes (like Catmull-Clark) by using a fixed, geometry-driven split pattern based on edge length thresholds relative to a target voxel resolution, rather than smoothing or topological refinement.

## Operating characteristics
- **Time Complexity:** The subdivision process is iterative and depends on the initial triangle sizes and the threshold $K_{vox/tri}^{max}$ [S1]. The number of subdivisions is bounded by the ratio of the initial bounding box area to the target area [S1].
- **Memory Complexity:** The method requires storing the queue $Q$ and result queue $R$ [S1]. The memory usage scales with the number of generated triangles, and the upper bound $N_{vox/tri}^{max}(T_i)$ is used to pre-allocate memory for the voxelization step to prevent dynamic reallocation [S1].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Batch size trade-offs exist; processing very small batches results in poor utilization of GPU processing power, whereas rather large batches may lead to fragmentation of the Morton queue [S1].
- **Strengths:** Ensures homogeneous voxel counts per triangle, which simplifies batch processing and memory management [S1]. Compact Morton index ranges reduce fragmentation in out-of-core voxelization [S1].
- **Limitations:** Requires pre-processing of the mesh [S1]. The subdivision logic is specific to the area-based constraint and may not be optimal for all voxelization algorithms [S1].

## Background
The method originates from the work on grid-free out-of-core voxelization to sparse voxel octrees on GPU [S1]. It was developed to address the challenges of processing large triangle soups efficiently on GPU by ensuring that each triangle contributes a predictable and manageable number of voxels [S1]. The subdivision scheme is a key component of the pre-processing step, enabling efficient sorting and batch processing of triangles for voxelization [S1]. The "Triangle Split" method is also referenced in comparative assessments of implicit and explicit plenoptic scene representations [S2], where it is described as a direct discretization method splitting triangles until the longest edge is smaller than 0.5 voxel [S2].
