# Color-Preserving Occupancy Voxelization

Also called: Color Preservation in Occupancy Grids

## Overview
This method computes an occupancy grid where voxel values store the index of the first mesh face intersecting the voxel, preserving color information by mapping face indices to voxel values [S1, unofficial]. It differs from [Occupancy Grid Voxelization](6958-occupancy-grid-voxelization.md) by storing face indices instead of binary flags, and from [Adaptive Triangle-to-Voxel Overlap Test](14342-adaptive-triangle-to-voxel-overlap-test.md) by using a fixed parallel iteration over all voxels [S1, G, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A watertight triangular mesh in OFF format with optional per-face RGB colors [S2, unofficial].
- Output: An HDF5 file containing an $N \times H \times W \times D$ tensor of integer face indices ($0$ for empty, $f$ for occupied by face $f$) [S2, unofficial]. If the `--color` flag is set, a separate `[int]_color.h5` file stores the original mesh face colors [S2, unofficial].

**Data Structures:**
- **Occupancy Grid:** 3D array of integers with dimensions $H \times W \times D$ [S1, unofficial].
- **Color File:** HDF5 file storing RGB values for each face in the mesh [S2, unofficial].

**Algorithm Steps:**
1. Initialize a parallel loop over all voxel indices $i$ from $0$ to $H \times W \times D - 1$ [S1, unofficial].
2. Calculate voxel coordinates: $d = i \bmod D$, $w = \lfloor i / D \rfloor \bmod W$, $h = \lfloor i / D \rfloor / W$ [S1, unofficial].
3. Define voxel bounds in grid coordinates: $\text{min} = (w, h, d)$ and $\text{max} = (w + 1, h + 1, d + 1)$ [S1, unofficial].
4. Loop over all mesh faces $f$ from $0$ to $N_{\text{faces}} - 1$ [S1, unofficial].
5. Retrieve vertices $v_1, v_2, v_3$ for face $f$ [S1, unofficial].
6. Check intersection: $\text{overlap} = \text{triangle\_box\_intersection}(\text{min}, \text{max}, v_1, v_2, v_3)$ [S1, unofficial].
7. If $\text{overlap}$ is true, store face index $f$ in the occupancy grid at $(h, w, d)$ and break the face loop [S1, unofficial].
8. If color mode is enabled, write the original mesh face colors to `[int]_color.h5` [S2, unofficial].

**Pseudocode:**
```python
def color_preserving_voxelization(mesh, height, width, depth):
    occ_grid = [[[0] * depth for _ in range(width)] for _ in range(height)]
    num_faces = mesh.num_faces()
    for i in range(height * width * depth):
        d = i % depth
        w = (i // depth) % width
        h = (i // depth) // width
        min_coord = (w, h, d)
        max_coord = (w + 1, h + 1, d + 1)
        for f in range(num_faces):
            v1, v2, v3 = mesh.get_face_vertices(f)
            # Perform triangle-box intersection test (implementation not provided in sources)
            overlap = triangle_box_intersection(min_coord, max_coord, v1, v2, v3)
            if overlap:
                face_id = f if f != 0 else num_faces
                occ_grid[h][w][d] = face_id
                break
    return occ_grid
```

**Parameters:**
- `--color`: Enables color file output [S2, unofficial].
- Grid dimensions ($H, W, D$): Determined by mesh bounds and voxel size [G].

**Edge Cases and Pitfalls:**
- **Face Index 0:** Face index $0$ is treated as 'not voxelized' space by default; if face $0$ overlaps a voxel, store `num_faces()` instead of $0$ to distinguish it from empty space [S1, unofficial].
- **Watertight Meshes:** Input OFF files must contain watertight triangular meshes [S2, unofficial].
- **Color File Ordering:** When providing multiple color files to `occ_to_off.py`, the ordering is important [S2, unofficial].

## Subtopics

### [Surface-based Voxel Color Sampling](16409-surface-based-voxel-color-sampling.md)
Assigns colors by sampling the nearest point on the mesh surface rather than the voxel center, avoiding color errors when voxel centers fall inside empty space. It differs from center-based sampling by ensuring that surface voxels receive colors derived from the actual geometry intersection. This method builds on [Color-Preserving Occupancy Voxelization](7557-color-preserving-occupancy-voxelization.md) by utilizing the occupancy grid to identify which voxels require surface sampling.

## Operating characteristics
- **Time Complexity:** $O(V \times F)$, where $V$ is the number of voxels and $F$ is the number of faces, due to the nested loop structure [S1, G, unofficial].
- **Memory Complexity:** $O(V)$ for the occupancy grid, plus $O(F)$ for the color file if enabled [G].
- **Strengths:** Preserves color information directly in the voxel grid, enabling simple color reconstruction [G].
- **Limitations:** Only stores the first intersecting face, which may not be the most representative for thick surfaces; performance degrades with high face counts due to the linear scan per voxel [G].
- **When to use:** When color preservation is required and the mesh is watertight [S2, G, unofficial].
- **When not to use:** For non-watertight meshes or when multiple surface interactions per voxel are needed [G].

## Background
Originating from the `mesh-voxelization` project by David Stutz, this method was developed to enhance standard occupancy grid voxelization by incorporating color data [S1, S2, unofficial]. It is used in contexts requiring colored voxel representations of 3D meshes, such as 3D reconstruction and visualization [S2, unofficial].
