# Occupancy Grid Voxelization

Also called: Occupancy grid computation, Grid Occupancy Voxelization, Voxelization from Triangle Mesh, Mesh Voxelization into Occupancy Grids, Scene Discretization to Occupancy Grid

## Overview
Occupancy Grid Voxelization converts a triangle mesh into a 3D boolean occupancy grid by mapping vertex positions to discrete grid indices and marking voxels that intersect the mesh surface as occupied [S1, S3, S4, unofficial]. It serves as a foundational step for generating volume data from polygonal models, providing a binary representation aligned with sensor resolution [S2, unofficial]. Unlike Signed Distance Field (SDF) derived occupancy, which may miss thin surfaces due to interpolation or level-set thresholds, this method guarantees that any voxel intersecting the mesh geometry is explicitly marked as occupied [S4, unofficial].

## How it works
The method takes a triangle mesh and a target grid resolution, producing a 3D occupancy grid where each cell indicates the presence of the mesh surface [S1, S4, unofficial].

### Inputs and Outputs
*   **Input:** A triangle mesh defined by a list of vertices $V$ and faces $F$. Each face $f \in F$ consists of three vertex indices [S3, unofficial]. Optionally, a color flag preserves original mesh face colors by storing face IDs in occupied voxels instead of binary flags [S4, unofficial].
*   **Output:** A 3D occupancy grid $O$ of dimensions $H \times W \times D$ (Height, Width, Depth) [S4, unofficial]. $O[h][w][d] = 1$ if the voxel intersects the mesh, $0$ otherwise [S4, unofficial].

### Data Structures
The grid is typically stored as a dense 3D array [S1, S3, unofficial].
*   **Layout:** A 3D array `voxelData` of type `bool` or `int` [S1, unofficial].
*   **Dimensions:** $(SAMPLE\_RATE + 1) \times (SAMPLE\_RATE + 1) \times (SAMPLE\_RATE + 1)$ in some implementations, though the active rendering loop often iterates only up to $SAMPLE\_RATE$ [S1, unofficial].
*   **Memory:** Sequential allocation, e.g., `voxelData[x][y][z]` [S1, unofficial].
*   **Alternative Layout:** For batch processing, an HDF5 tensor of shape $N \times C \times H \times W \times D$ is used, where $N$ is the number of files and $C=2$ (SDF and occupancy channels) [S4, unofficial].
*   **Eigen Tensor:** `Eigen::Tensor<int, 3, Eigen::RowMajor> occ` [S3, unofficial].

### Algorithm Steps
1.  **Initialize Bounds:** Determine the bounding box of the mesh. Initialize `minX, maxX, minY, maxY, minZ, maxZ` to extreme values (e.g., $\pm 99999999$) and iterate over all vertices to update these bounds [S1, unofficial].
2.  **Compute Grid Parameters:** Calculate the index spans for each axis based on the desired resolution (e.g., `SAMPLE_RATE` or user-defined $H, W, D$) [S1, S4, unofficial]:
    $$
    X_{span} = \frac{|maxX - minX|}{SAMPLE\_RATE}, \quad Y_{span} = \frac{|maxY - minY|}{SAMPLE\_RATE}, \quad Z_{span} = \frac{|maxZ - minZ|}{SAMPLE\_RATE}
    $$
    Alternatively, scale the mesh to lie in the range $[0, H] \times [0, W] \times [0, D]$ corresponding to the resolution [S4, unofficial].
3.  **Initialize Grid:** Allocate the occupancy grid and set all entries to 0 (empty) [S3, S4, unofficial].
4.  **Voxelization (Triangle-Box Intersection):**
    *   Iterate over all voxels in the grid. For each voxel $(h, w, d)$, define its spatial bounds $[min_x, max_x] \times [min_y, max_y] \times [min_z, max_z]$ [S3, unofficial].
    *   Iterate over all mesh faces $f$. For each face with vertices $v_1, v_2, v_3$:
        *   Perform a triangle-box intersection test: `overlap = triangle_box_intersection(min, max, v1, v2, v3)` [S3, unofficial].
        *   If an intersection is detected:
            *   Set $O[h][w][d] = 1$ (or store face ID/color if enabled) [S3, S4, unofficial].
            *   Break the face loop for this voxel to avoid redundant checks [S3, unofficial].
5.  **Post-Processing (Optional):** If a solid volume is required, apply a connected components algorithm to fill the interior of the surface voxels, as the raw output only marks the surface [S4, unofficial].

### Pseudocode
```python
def occupancy_grid_voxelization(vertices, faces, resolution):
    # 1. Initialize bounds
    min_x = min_y = min_z = float('inf')
    max_x = max_y = max_z = float('-inf')
    for v in vertices:
        min_x = min(min_x, v[0]); max_x = max(max_x, v[0])
        min_y = min(min_y, v[1]); max_y = max(max_y, v[1])
        min_z = min(min_z, v[2]); max_z = max(max_z, v[2])

    # 2. Compute voxel size
    dx = (max_x - min_x) / resolution
    dy = (max_y - min_y) / resolution
    dz = (max_z - min_z) / resolution

    # 3. Initialize grid
    occ_grid = [[ [0 for _ in range(resolution)] for _ in range(resolution)] for _ in range(resolution)]

    # 4. Voxelization
    for h in range(resolution):
        for w in range(resolution):
            for d in range(resolution):
                v_min_x = min_x + w * dx; v_max_x = v_min_x + dx
                v_min_y = min_y + h * dy; v_max_y = v_min_y + dy
                v_min_z = min_z + d * dz; v_max_z = v_min_z + dz

                occupied = False
                for face in faces:
                    v1 = vertices[face[0]]; v2 = vertices[face[1]]; v3 = vertices[face[2]]
                    if triangle_box_intersect(v1, v2, v3, v_min_x, v_max_x, v_min_y, v_max_y, v_min_z, v_max_z):
                        occupied = True
                        break
                if occupied:
                    occ_grid[h][w][d] = 1
    return occ_grid

def triangle_box_intersect(v1, v2, v3, min_x, max_x, min_y, max_y, min_z, max_z):
    # Standard Separating Axis Theorem for triangle-box intersection [G]
    n = cross(v2-v1, v3-v1)
    if separating_axis(v1, v2, v3, n, min_x, max_x, min_y, max_y, min_z, max_z): return False
    for axis in [(1,0,0), (0,1,0), (0,0,1)]:
        if separating_axis(v1, v2, v3, axis, min_x, max_x, min_y, max_y, min_z, max_z): return False
    edges = [v2-v1, v3-v2, v1-v3]
    box_axes = [(1,0,0), (0,1,0), (0,0,1)]
    for e in edges:
        for b in box_axes:
            axis = cross(e, b)
            if separating_axis(v1, v2, v3, axis, min_x, max_x, min_y, max_y, min_z, max_z): return False
    return True

def separating_axis(p1, p2, p3, axis, min_x, max_x, min_y, max_y, min_z, max_z):
    ax = axis
    t0 = dot(p1, ax); t1 = dot(p2, ax); t2 = dot(p3, ax)
    t_min = min(t0, t1, t2); t_max = max(t0, t1, t2)
    b_min = 0.0; b_max = 0.0
    for i, (mn, mx) in enumerate([(min_x, max_x), (min_y, max_y), (min_z, max_z)]):
        if ax[i] >= 0:
            b_min += mn; b_max += mx
        else:
            b_min += mx; b_max += mn
    return t_max < b_min or t_min > b_max

def cross(a, b): return (a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0])
def dot(a, b): return a[0]*b[0]+a[1]*b[1]+a[2]*b[2]
def sub(a, b): return (a[0]-b[0], a[1]-b[1], a[2]-b[2])
```

### Parameters
*   **Resolution ($H, W, D$):** The number of voxels along each axis. Typical values are $32^3$, $64^3$, or higher depending on required detail [S1, S4, unofficial].
*   **Color Flag:** A boolean parameter. When set, the grid stores face IDs or colors instead of binary occupancy [S4, unofficial].

### Edge Cases and Pitfalls
*   **Index Calculation Error:** Incorrectly using `abs(minY)` instead of `abs(minZ)` in the z-index calculation can cause vertical misalignment in the voxel grid [S1, unofficial].
*   **Boundary Rendering:** Allocating a grid of size `SAMPLE_RATE + 1` but iterating strictly less than `SAMPLE_RATE` leaves the outermost layer of voxels unrendered or uninitialized [S1, unofficial].
*   **Surface vs. Volume:** The method produces hollow occupancy grids (only surface voxels are marked) [S4, unofficial]. It does not fill the interior. A connected components algorithm is required to generate a solid volume [S4, unofficial].
*   **Empty Models:** If the tetravoxelization variant yields no active voxels (e.g., due to misaligned AABB), it may fall back to a naive fill to prevent empty grids [S6, unofficial].

## Subtopics

### [Color-Preserving Occupancy Voxelization](7557-color-preserving-occupancy-voxelization.md)
This method extends standard occupancy grid voxelization by storing the index of the first intersecting mesh face in each occupied voxel, rather than a binary occupancy flag. This preserves color information by mapping face indices to voxel values, allowing the original mesh colors to be reconstructed from the voxel grid. It differs from [Occupancy Grid Voxelization](6958-occupancy-grid-voxelization.md) by retaining per-voxel identity data instead of simple presence/absence.

### [Adaptive Triangle-to-Voxel Overlap Test](14342-adaptive-triangle-to-voxel-overlap-test.md)
The Adaptive Triangle-to-Voxel Overlap Test is a voxelization algorithm that determines which grid voxels overlap with a mesh triangle by classifying the triangle's axis-aligned bounding box (AABB) thickness into three cases (1D, 2D, or 3D) to optimize the overlap test. It builds on [Occupancy Grid Voxelization](6958-occupancy-grid-voxelization.md) by replacing a naive intersection check with a hierarchical classification that skips geometric tests when the bounding box is thin in multiple dimensions, marking those voxels as fully occupied without further computation.

### Tetravoxelization Grid Population
Populates a regular voxel grid by tetravoxelizing input 3D models and mapping binary occupancy results to grid values [S6, unofficial]. It initializes a tetravoxelizer with grid subdivisions, processes each model component to compute voxelization into a 1D array (`_voxelOpenGL`), and then maps these results to a grid [S6, unofficial]. If no active voxels are found, it falls back to a naive fill method to prevent empty grids [S6, unofficial].

### Auto-Size Bounding Box Walk
The auto-size path walks the vertex list twice: once to get the bounding box (`getBoundingBox()`) and once for the voxelization loop [S7, unofficial]. This is $O(1)$ memory [S7, unofficial].

### Midpoint Occupancy
A voxel rasterization method where a cell (cube) is considered solid if its center point lies inside the parametric object [S8, unofficial]. The method suffers from high aliasing, making it suitable only for small voxels, which Minecraft does not have [S8, unofficial].

### Gaussian-based Occupancy Voxelization
Converts a 3DGS scene into a binary occupancy voxel grid by thresholding voxel opacity, which is calculated by summing contributions from the $K$-nearest 3D Gaussians to the voxel center [S9, unofficial]. To extend the method to 2DGS, each flat 2D ellipse is converted into a 3D ellipsoid by computing the third axis as the cross product of the first two axes and setting its length to $10^{-5}$ [S9, unofficial]. The opacity is calculated as $d(v) = \sum_{g} \frac{1}{2} \alpha_g \exp\left(-\frac{1}{2} (v - \mu_g)^T \Sigma_g^{-1} (v - \mu_g)\right)$ [S9, unofficial]. $K$ is set to 16 and the opacity threshold is $10^{-6}$ [S9, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S7, unofficial].
*   **Memory Complexity:** $O(H \cdot W \cdot D)$ for the dense grid [S1, S4, unofficial].
*   **Performance:** The method is computationally expensive for high-resolution grids due to the large number of triangle-box intersection tests [S4, unofficial]. It is suitable for moderate resolutions (e.g., $32^3$ to $64^3$) [S1, S4, unofficial].
*   **Strengths:** Guarantees surface voxel inclusion; simple to implement; preserves geometric accuracy better than SDF-based methods for thin structures [S4, unofficial].
*   **Limitations:** Does not fill interior volumes by default; sensitive to resolution; performance degrades with increasing resolution and triangle count [S4, unofficial].

## Background
The method originates from basic volumetric rendering pipelines where mesh data needs to be converted to a voxel-based representation for raycasting or volume rendering [S1, unofficial]. It is often implemented as a preliminary step in projects involving Marching Cubes or Sparse Voxel Octree Raycasting [S1, unofficial]. The specific triangle-box intersection approach is attributed to Tomas Akenine-Möller, ensuring robust detection of surface voxels [S4, unofficial]. It is used in various open-source projects for volumetric visualization and additive manufacturing simulations [S2, S4, unofficial][S5].
