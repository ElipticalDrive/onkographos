# Occupancy Grid Voxelization

Also called: Discretize, Grid Occupancy Voxelization, Mesh Voxelization into Occupancy Grids, Occupancy grid computation, Scene Discretization to Occupancy Grid, Vertex-based Voxelization

## Overview
Occupancy Grid Voxelization converts a triangle mesh into a 3D boolean occupancy grid by mapping vertex positions to discrete grid indices and marking voxels that intersect the mesh surface as occupied [S1, S3, S4, unofficial]. It serves as a foundational step for generating volume data from polygonal models, providing a binary representation aligned with sensor resolution [S2, unofficial]. Unlike Signed Distance Field (SDF) derived occupancy, which may miss thin surfaces due to interpolation or level-set thresholds, this method guarantees that any voxel intersecting the mesh geometry is explicitly marked as occupied [S4, unofficial]. It differs from its sibling [Level 2 Triangle-Voxel Classification](5512-level-2-triangle-voxel-classification.md) by relying on direct triangle-box intersection tests rather than more complex hierarchical or analytical overlap criteria.

## How it works
The method takes a triangle mesh and a target grid resolution, producing a 3D occupancy grid where each cell indicates the presence of the mesh surface.

### Inputs and Outputs
*   **Input:** A triangle mesh defined by a list of vertices $V$ and faces $F$. Each face $f \in F$ consists of three vertex indices. Optionally, color or face ID data may be attached to faces [S4, unofficial].
*   **Output:** A 3D occupancy grid $O$ of dimensions $H \times W \times D$ (Height, Width, Depth). $O[h][w][d] = 1$ if the voxel intersects the mesh, $0$ otherwise. In color-preserving variants, the value may store a face index instead of a binary flag [S4, unofficial].

### Data Structures
The grid is typically stored as a dense 3D array.
*   **Layout:** A 3D array `voxelData` of type `bool` or `int`.
*   **Dimensions:** $(SAMPLE\_RATE + 1) \times (SAMPLE\_RATE + 1) \times (SAMPLE\_RATE + 1)$ in some implementations, though the active rendering loop often iterates only up to $SAMPLE\_RATE$ [S1, unofficial].
*   **Memory:** Sequential allocation, e.g., `voxelData[x][y][z]` [S1, unofficial].
*   **Alternative Layout:** For batch processing, an HDF5 tensor of shape $N \times C \times H \times W \times D$ is used, where $N$ is the number of files and $C=2$ (SDF and occupancy channels) [S4, unofficial].
*   **Eigen Tensor:** `Eigen::Tensor<int, 3, Eigen::RowMajor> occ` [S3, unofficial].

### Algorithm Steps
1.  **Initialize Bounds:** Determine the bounding box of the mesh. Initialize `minX, maxX, minY, maxY, minZ, maxZ` to extreme values (e.g., $\pm 99999999$) and iterate over all vertices to update these bounds [S1, unofficial].
2.  **Compute Grid Parameters:**
    *   Calculate the index spans for each axis based on the desired resolution (e.g., `SAMPLE_RATE` or user-defined $H, W, D$) [S1, S4, unofficial]:
        $$
        X_{span} = \frac{|maxX - minX|}{SAMPLE\_RATE}, \quad Y_{span} = \frac{|maxY - minY|}{SAMPLE\_RATE}, \quad Z_{span} = \frac{|maxZ - minZ|}{SAMPLE\_RATE}
        $$
    *   Alternatively, scale the mesh to lie in the range $[0, H] \times [0, W] \times [0, D]$ corresponding to the resolution [S4, unofficial].
3.  **Initialize Grid:** Allocate the occupancy grid and set all entries to 0 (empty) [S3, S4, unofficial].
4.  **Voxelization (Triangle-Box Intersection):**
    *   Iterate over all voxels in the grid. For each voxel $(h, w, d)$, define its spatial bounds $[min_x, max_x] \times [min_y, max_y] \times [min_z, max_z]$ [S3, unofficial].
    *   Iterate over all mesh faces $f$. For each face with vertices $v_1, v_2, v_3$:
        *   Perform a triangle-box intersection test: `overlap = triangle_box_intersection(min, max, v1, v2, v3)` [S3, unofficial].
        *   If an intersection is detected:
            *   Set $O[h][w][d] = 1$ (or store face ID/color if enabled) [S3, S4, unofficial].
            *   Break the face loop for this voxel to avoid redundant checks [S3, unofficial].
5.  **Post-Processing (Optional):** If a solid volume is required, apply a connected components algorithm to fill the interior of the surface voxels, as the raw output only marks the surface [S4, unofficial].

### Pseudocode
```python
def occupancy_grid_voxelization(vertices, faces, resolution):
    """
    Convert a mesh to a binary occupancy grid.
    
    Args:
        vertices: List of (x, y, z) coordinates.
        faces: List of (v1_idx, v2_idx, v3_idx) indices.
        resolution: Integer, the number of voxels along each axis (H=W=D).
        
    Returns:
        occ_grid: 3D numpy array of shape (resolution, resolution, resolution) with 0s and 1s.
    """
    # 1. Initialize bounds
    min_x = min_y = min_z = float('inf')
    max_x = max_y = max_z = float('-inf')
    
    for v in vertices:
        min_x = min(min_x, v[0])
        max_x = max(max_x, v[0])
        min_y = min(min_y, v[1])
        max_y = max(max_y, v[1])
        min_z = min(min_z, v[2])
        max_z = max(max_z, v[2])
        
    # 2. Compute voxel size and grid dimensions
    # Note: Some implementations use SAMPLE_RATE + 1 for allocation, 
    # but iterate only up to SAMPLE_RATE. We follow the standard resolution.
    dx = (max_x - min_x) / resolution
    dy = (max_y - min_y) / resolution
    dz = (max_z - min_z) / resolution
    
    # Initialize grid
    occ_grid = np.zeros((resolution, resolution, resolution), dtype=int)
    
    # 3. Iterate over voxels
    for h in range(resolution):
        for w in range(resolution):
            for d in range(resolution):
                # Define voxel bounds
                v_min_x = min_x + w * dx
                v_max_x = v_min_x + dx
                v_min_y = min_y + h * dy
                v_max_y = v_min_y + dy
                v_min_z = min_z + d * dz
                v_max_z = v_min_z + dz
                
                # Check intersection with any triangle
                occupied = False
                for face in faces:
                    v1 = vertices[face[0]]
                    v2 = vertices[face[1]]
                    v3 = vertices[face[2]]
                    
                    # Triangle-box intersection test
                    if triangle_box_intersect(v1, v2, v3, 
                                              v_min_x, v_max_x, 
                                              v_min_y, v_max_y, 
                                              v_min_z, v_max_z):
                        occupied = True
                        break # Optimization: stop checking faces for this voxel
                
                if occupied:
                    occ_grid[h, w, d] = 1
                    
    return occ_grid
```

### Parameters
*   **Resolution ($H, W, D$):** The number of voxels along each axis. Typical values are $32^3$, $64^3$, or higher depending on required detail [S1, S4, unofficial].
*   **Color Flag:** A boolean parameter. When set, the grid stores face IDs or colors instead of binary occupancy [S4, unofficial].

### Edge Cases and Pitfalls
*   **Index Calculation Error:** Incorrectly using `abs(minY)` instead of `abs(minZ)` in the z-index calculation can cause vertical misalignment in the voxel grid [S1, unofficial].
*   **Boundary Rendering:** Allocating a grid of size `SAMPLE_RATE + 1` but iterating strictly less than `SAMPLE_RATE` leaves the outermost layer of voxels unrendered or uninitialized [S1, unofficial].
*   **Surface vs. Volume:** The method produces "hollow" occupancy grids (only surface voxels are marked). It does not fill the interior. A connected components algorithm is required to generate a solid volume [S4, unofficial].
*   **Empty Models:** If the tetravoxelization variant yields no active voxels (e.g., due to misaligned AABB), it may fall back to a naive fill to prevent empty grids [S5, unofficial].

## Subtopics

### [Color-Preserving Occupancy Voxelization](7557-color-preserving-occupancy-voxelization.md)
This method extends standard occupancy grid voxelization by storing the index of the first intersecting mesh face in each occupied voxel, rather than a binary occupancy flag. This preserves color information by mapping face indices to voxel values, allowing the original mesh colors to be reconstructed from the voxel grid. It differs from [Occupancy Grid Voxelization](6958-occupancy-grid-voxelization.md) by retaining per-voxel identity data instead of simple presence/absence.

### [Adaptive Triangle-to-Voxel Overlap Test](14342-adaptive-triangle-to-voxel-overlap-test.md)
The Adaptive Triangle-to-Voxel Overlap Test is a voxelization algorithm that determines which grid voxels overlap with a mesh triangle by classifying the triangle's axis-aligned bounding box (AABB) thickness into three cases (1D, 2D, or 3D) to optimize the overlap test. It builds on [Occupancy Grid Voxelization](6958-occupancy-grid-voxelization.md) by replacing a naive intersection check with a hierarchical classification that skips geometric tests when the bounding box is thin in multiple dimensions, marking those voxels as fully occupied without further computation.

### Tetravoxelization Grid Population
Populates a regular voxel grid by tetravoxelizing input 3D models and mapping binary occupancy results to grid values. It initializes a tetravoxelizer with grid subdivisions, processes each model component to compute voxelization into a 1D array (`_voxelOpenGL`), and then maps these results to a grid. If no active voxels are found, it falls back to a naive fill method to prevent empty grids [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(V \cdot H \cdot W \cdot D)$ in the naive implementation where every triangle is tested against every voxel, or $O(N_{voxels} \cdot N_{faces})$ if spatial acceleration is not used. With spatial partitioning (e.g., AABB culling), it approaches $O(N_{occupied\_voxels} \cdot N_{local\_faces})$.
*   **Memory Complexity:** $O(H \cdot W \cdot D)$ for the dense grid. For high resolutions, this can be significant. Sparse representations (like Voxel Octrees) are alternatives but are not part of this specific method's definition [S1, unofficial].
*   **Performance:** The method is computationally expensive for high-resolution grids due to the large number of triangle-box intersection tests. It is suitable for moderate resolutions (e.g., $32^3$ to $64^3$) or when high precision is required for surface detection [S4, unofficial].
*   **Strengths:** Guarantees surface voxel inclusion; simple to implement; preserves geometric accuracy better than SDF-based methods for thin structures [S4, unofficial].
*   **Limitations:** Does not fill interior volumes by default; sensitive to resolution; performance degrades with increasing resolution and triangle count [S4, unofficial].

## Background
The method originates from basic volumetric rendering pipelines where mesh data needs to be converted to a voxel-based representation for raycasting or volume rendering. It is often implemented as a preliminary step in projects involving Marching Cubes or Sparse Voxel Octree Raycasting [S1, unofficial]. The specific triangle-box intersection approach is attributed to Tomas Akenine-Möller, ensuring robust detection of surface voxels [S4, unofficial]. It is used in various open-source projects for volumetric visualization and additive manufacturing simulations [S2, S4, S5, unofficial].
