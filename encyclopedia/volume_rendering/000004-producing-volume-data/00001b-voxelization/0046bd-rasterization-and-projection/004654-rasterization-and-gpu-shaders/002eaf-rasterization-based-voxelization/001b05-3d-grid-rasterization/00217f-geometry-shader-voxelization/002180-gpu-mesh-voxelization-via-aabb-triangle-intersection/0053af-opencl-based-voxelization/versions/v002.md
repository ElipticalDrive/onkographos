# OpenCL-based Voxelization

Also called: Parallelized Voxelization using OpenCL

## Overview
This method converts a triangular mesh into a voxel grid by dispatching compute threads to test for intersections between mesh facets and voxel cubes [S1]. It distinguishes itself from conventional single-thread CPU approaches by leveraging OpenCL for parallel execution, achieving up to a 260-fold decrease in computation time [S1]. It builds on [GPU Mesh Voxelization via AABB-Triangle Intersection](2541-gpu-mesh-voxelization-via-aabb-triangle-intersection.md) by optimizing memory access patterns for the specific geometry of triangular facets [S1].

## How it works
**Inputs:** A triangular mesh $M$ with $n$ triangles; user-defined voxel grid parameters (origin $p_0 \in \mathbb{R}^3$, dimensions $d \in \mathbb{N}^+$, diagonal $\Delta p \in \mathbb{R}^3$) [S1].
**Outputs:** A 1D array of length $d_x d_y d_z$ storing material-specific information for each voxel [S1].

**Data Structures:**
1. **Preprocessed Mesh Array:** A contiguous `float` array of length $9n$ [S1]. For triangle $i$, elements $9i$ to $9i+8$ store the $x,y,z$ coordinates of vertices $v_0, v_1, v_2$ respectively [S1]. This ensures coalesced memory access [S1].
2. **Voxel Grid Representation:** Defined by origin $p_0$, dimensions $d=(d_x, d_y, d_z)$, and voxel diagonal $\Delta p$ [S1]. The grid covers the Axis-Aligned Bounding Box (AABB) of the mesh [S1].
3. **Output Array:** 1D array of size $d_x d_y d_z$ [S1]. Index $i$ corresponds to voxel $(x,y,z)$ via $i = x + y d_x + z d_x d_y$ [S1].

**Algorithm Steps:**

1. **Input Preparation:** Construct the preprocessed mesh array [S1]. Sort vertex coordinates per triangle into a single contiguous buffer to avoid cluttered memory access caused by separate vertex/index arrays [S1].
2. **Grid Construction:** Calculate the AABB of the mesh using min/max vertex coordinates [S1]. Define the voxel grid parameters $p_0, d, \Delta p$ [S1]. Allocate the output array [S1].
3. **Kernel Execution:** Dispatch work-items [S1]. Each work-item processes voxel/facet intersections [S1].
    * **Index Mapping:** If processing by voxel index $i$, calculate grid coordinates:
        $$ z = \lfloor i / (d_x d_y) \rfloor $$
        $$ y = \lfloor (i - z d_x d_y) / d_x \rfloor $$
        $$ x = i - z d_x d_y - y d_x $$
        [S1]
    * **Voxel Corner Calculation:** Calculate the minimum corner $o$ of voxel $V(x,y,z)$:
        $$ o = p_0 + \langle \Delta p, (x, y, z) \rangle $$
        where $\langle \cdot, \cdot \rangle$ is the dot product [S1]. The voxel is defined by corners $p=o$ and $p+\Delta p$ [S1].
    * **Facet/Voxel Overlap Test:** For each triangle $T$ with vertices $v_0, v_1, v_2$:
        1. Calculate normal $n$ of $T$ [S1].
        2. Calculate critical point $c$ relative to the voxel's diagonal $\Delta p$:
            $$ c_k = \begin{cases} \Delta p_k & \text{if } n_k > 0 \\ 0 & \text{if } n_k \le 0 \end{cases} $$
            [S1]
        3. Perform the overlap test based on the enhanced separating axis theorem variant [S1].
        4. If an intersection is detected, mark the voxel in the output array [S1].

**Parameters:**
* **Local Size:** Number of work-items per work-group [S1]. Best practice suggests maximization, but limited local memory often forces reliance on global memory [S1].
* **Global Size:** Total number of work-items [S1].

**Pitfalls:**
* **Memory Access:** Standard mesh formats (separate vertex/index arrays) cause slow, uncoalesced access [S1]. Preprocessing into a contiguous float array is required [S1].
* **Global Memory Limits:** Efficient OpenCL programming limits global memory access to a maximum of two per kernel execution (one read, one write) [S1]. Excessive access compromises performance [S1].

## Operating characteristics
* **Performance:** Up to 99.6% reduction or 260 times decrease in computation time compared to conventional single-thread CPU approaches [S1].
* **Complexity:** Linear with respect to the number of triangles and voxels, but heavily dependent on memory access patterns [S1].
* **Strengths:** High parallelism on heterogeneous hardware (GPU/CPU); optimized memory access via data preprocessing [S1].
* **Limitations:** Performance is constrained by the trade-off between local size maximization and global memory access limits [S1]. Limited local memory often forces reliance on slower global memory [S1].
* **When to use:** When voxelizing large triangular meshes on hardware supporting OpenCL, and memory bandwidth is a bottleneck for standard CPU approaches [S1].

## Background
This method was developed in the context of heterogeneous computing for computer graphics, with planned integration into virtual orthopaedic surgery platforms [S1]. It adopts an enhanced version of the separating axis theorem from prior work, requiring fewer operations than standard implementations [S1].
