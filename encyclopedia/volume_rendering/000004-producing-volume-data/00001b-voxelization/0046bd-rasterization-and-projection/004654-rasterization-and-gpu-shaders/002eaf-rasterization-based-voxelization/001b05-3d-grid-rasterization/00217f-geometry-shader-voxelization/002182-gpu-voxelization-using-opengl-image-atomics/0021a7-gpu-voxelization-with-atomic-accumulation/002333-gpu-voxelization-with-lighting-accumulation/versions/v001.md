# GPU Voxelization with Lighting Accumulation

Also called: Light Injection & Opacity Voxelization

## Overview
This method rasterizes scene geometry into a 3D texture to store light contribution and opacity for subsequent cone tracing. It solves the problem of generating the volumetric lighting data required for indirect diffuse illumination by calculating reflected light, direct spotlight illumination, and emissive contributions during the rasterization pass. It differs from its parent [GPU Voxelization with Atomic Accumulation](2559-gpu-voxelization-with-atomic-accumulation.md) by using `imageStore` to overwrite voxel data rather than accumulating samples via atomics, thereby avoiding race conditions at the cost of not computing a moving average of samples per voxel.

## How it works
**Inputs and Outputs:**
*   **Input:** Rasterized geometry (fragments), scene lighting parameters (spotlights, emissive materials), shadow maps, and a 3D texture buffer.
*   **Output:** A 3D RGBA texture where channels 0-2 (RGB) encode the light radiance coming from the voxel, and channel 3 (A) encodes the voxel opacity.

**Data Structures:**
*   **3D Texture:** RGBA format.
    *   `RGB`: Light intensity/radiance.
    *   `A`: Opacity (1.0 for opaque, 0.0 for empty).

**Steps:**
1.  **Rasterization Setup:** Render scene geometry into a depth buffer relative to the camera or light sources as required for shadow map generation.
2.  **Fragment Processing:** For every fragment generated by the rasterizer:
    a.  Determine the 3D voxel coordinates corresponding to the fragment's position.
    b.  Set the opacity channel (A) of the target voxel to 1.0 (fully opaque).
    c.  Calculate the light contribution based on the surface properties and light sources.
3.  **Lighting Calculation:**
    *   **Direct Lighting:** Calculate diffuse light using the Lambertian model, light falloff, and shadow map visibility.
    *   **Emissive Lighting:** Add the emitted light intensity from emissive materials.
    *   **Indirect Lighting:** Note that this specific pass approximates only indirect diffuse lighting; specular components are not stored [S1, unofficial].
4.  **Storage:** Write the computed RGBA value to the 3D texture using `imageStore()`, discarding the fragment from the color buffer.

**Formulas:**
*   **Lambertian Diffuse Lighting:**
    $$ L_{diffuse} = k_d \cdot \frac{I}{d^2} \cdot \max(0, \mathbf{n} \cdot \mathbf{l}) \cdot V $$
    Where:
    *   $k_d$: Diffuse material reflectivity.
    *   $I$: Light intensity.
    *   $d$: Distance from light to surface (light falloff).
    *   $\mathbf{n}$: Surface normal.
    *   $\mathbf{l}$: Direction to light source.
    *   $V$: Visibility (1.0 if lit, 0.0 if in shadow, derived from shadow maps) [S1, unofficial].

*   **Emissive Contribution:**
    $$ L_{emissive} = \mathbf{E} $$
    Where $\mathbf{E}$ is the emissive color/intensity of the material [S1, unofficial].

*   **Total Voxel Radiance:**
    $$ \mathbf{C}_{voxel} = \mathbf{L}_{diffuse} + \mathbf{L}_{emissive} $$
    The final RGBA value written is $(\mathbf{C}_{voxel}, 1.0)$ [S1, unofficial].

**Parameters:**
*   **Texture Format:** RGBA [S1, unofficial].
*   **Opacity Value:** 1.0 for intersecting voxels [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Race Conditions:** Using `imageStore` without atomics means that if two primitives write to the same voxel, the result is undefined (last-write-wins). This method assumes a specific rendering order or that overwriting is acceptable for the approximation [S1, unofficial].
*   **Directionality:** Since only intensity is stored, directional information is lost. This limits the approximation to indirect diffuse lighting; specular reflections cannot be accurately reconstructed [S1, unofficial].
*   **Shadow Artifacts:** Incorrect shadow map sampling can lead to light leaking or incorrect occlusion in the voxel grid [S1, unofficial].

**Pseudocode:**
```python
# Fragment Shader Logic (Conceptual)
# Input: fragment_position, fragment_normal, material_properties, light_data
# Output: None (writes to 3D texture)

def process_fragment(fragment_position, fragment_normal, material, lights, shadow_maps):
    # 1. Determine voxel coordinates
    voxel_coords = world_to_voxel(fragment_position)
    
    # 2. Calculate lighting
    total_light = vec3(0.0)
    
    for light in lights:
        if light.type == SPOTLIGHT:
            # Calculate visibility using shadow map
            shadow_factor = sample_shadow_map(light.shadow_map, fragment_position, light.direction)
            
            # Lambertian diffuse model
            light_direction = normalize(light.position - fragment_position)
            normal_dot_light = max(dot(fragment_normal, light_direction), 0.0)
            
            # Light falloff (inverse square)
            distance = length(light.position - fragment_position)
            falloff = 1.0 / (distance * distance)
            
            diffuse_contribution = material.diffuse_color * light.intensity * normal_dot_light * falloff * shadow_factor
            total_light += diffuse_contribution
            
        elif light.type == EMISSIVE:
            total_light += material.emissive_color
            
    # 3. Set opacity to fully opaque
    opacity = 1.0
    
    # 4. Store to 3D texture
    # imageStore(voxel_texture, ivec3(voxel_coords), vec4(total_light, opacity))
    pass
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of fragments generated by rasterization.
*   **Memory Complexity:** Proportional to the resolution of the 3D texture ($N^3$).
*   **Strengths:** Simple implementation using standard rasterization pipeline; avoids atomic operation overhead; produces few noticeable artifacts in complex scenes [S1, unofficial].
*   **Limitations:** No accumulation of multiple samples per voxel (unlike atomic methods); potential for race conditions if geometry overlaps significantly in voxel space; only supports diffuse lighting approximation [S1, unofficial].
*   **When to Use:** When indirect diffuse lighting is sufficient and performance is prioritized over precise multi-sample accumulation.

## Background
Originated in the context of Voxel Cone Tracing, a real-time global illumination technique. The method was described in an unofficial report by righier (2026) detailing the implementation of voxelization for cone tracing pipelines. It is used in real-time rendering engines to approximate indirect illumination by storing light data in a 3D grid.
