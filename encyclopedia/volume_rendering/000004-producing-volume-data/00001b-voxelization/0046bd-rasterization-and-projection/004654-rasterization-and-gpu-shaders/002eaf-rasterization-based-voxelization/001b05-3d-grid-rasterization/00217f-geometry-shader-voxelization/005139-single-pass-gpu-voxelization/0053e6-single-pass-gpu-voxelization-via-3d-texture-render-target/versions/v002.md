# Single-Pass GPU Voxelization via 3D Texture Render Target

Also called: Geometry Shader Voxelization via 3D Texture, Real-time GPU-Based Voxelization, Voxelization via 3D Texture Render Target, slicing-based voxelization using geometry shader [S2, unofficial]

## Overview
This method transforms a surface-represented scene into a high-resolution voxel grid in a single GPU pass by using the geometry shader to duplicate geometry for intersecting slices and a 3D volume texture as the direct render target [S2, unofficial]. It solves the inefficiency of multi-pass slicing algorithms and the projection artifacts or fixed-resolution limitations of grid encoding methods [S2, unofficial]. Unlike encoding methods that induce errors, this approach uses a clipping plane algorithm to avoid projection artifacts [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A mesh defined by triangles (or quadrilaterals) with vertex positions, colors, and normals [S2, unofficial].
*   **Output:** A 3D volume texture where each texel stores volumetric existence, color, surface normal, transmission coefficient, and refraction index [S1, unofficial][S2, unofficial].

**Data Structures:**
*   **3D Volume Texture:** The primary storage for voxel data, with dimensions adjustable based on hardware limitations and application needs [S2, unofficial].
*   **Texel Layout:** Each texel stores existence (implicit via render target or explicit flag), color, surface normal, transmission coefficient, refraction index, and an absorption coefficient [S1, unofficial][S2, unofficial]. The absorption coefficient is computed according to the number of surface drawings in each voxel during voxelization [S1, unofficial].

**Numbered Steps:**
1.  **Vertex Shader:** Compute the positions of triangle vertices in camera coordinates [S2, unofficial].
2.  **Geometry Shader:** Determine which slices along the z-axis intersect the triangle [S2, unofficial]. Duplicate the triangle for each intersecting slice to rasterize in the pixel shader [S2, unofficial].
3.  **Pixel Shader:** Rasterize the duplicated triangles onto the 3D texture render target [S2, unofficial]. Store surfacial data (normal, color) and volumetric data (transmittance) in the corresponding texels [S2, unofficial]. Update the absorption coefficient based on the number of surface drawings in each voxel [S1, unofficial].

**Formulas:**
Let $z_i$ be the camera-space z-coordinate of vertex $i$ of a triangle [S2, unofficial].
Let $thickness$ be the slice depth parameter [S2, unofficial].
The slice index range is computed as:
$$maxslice = \max(z_0, z_1, z_2) / thickness$$
$$minslice = \min(z_0, z_1, z_2) / thickness$$
where $maxslice$ and $minslice$ define the inclusive range of z-axis slices that intersect the triangle [S2, unofficial].

**Parameters:**
Typical values are not given in the sources [G]. The voxel resolution is determined by the dimensions of the 3D texture [S2, unofficial]. The absorption coefficient is derived from the count of surface intersections per voxel [S1, unofficial].

**Edge Cases and Pitfalls:**
Deformable models are handled without preprocessing or sorting, overcoming limitations of previous encoding methods [S2, unofficial]. The algorithm can be extended to handle quadrilaterals without major modification [S2, unofficial]. The size of the 3D texture is adjustable but constrained by hardware limitations [S2, unofficial]. Precision issues may arise when computing slice indices from floating-point z-coordinates, requiring careful rounding or floor/ceil operations [G]. Degenerate triangles with zero area or coplanar vertices may produce invalid slice ranges and require explicit culling [G].

## Operating characteristics
*   **Time Complexity:** Single GPU pass, making it efficient for real-time applications [S2, unofficial].
*   **Memory Complexity:** Depends on the size of the 3D texture, which is adjustable [S2, unofficial].
*   **Performance:** Capable of real-time voxelization of highly complex scenes [S2, unofficial].
*   **Strengths:** Avoids projection artifacts, handles deformable models without preprocessing, allows adjustable resolution, and stores rich surfacial and volumetric data [S2, unofficial].
*   **Limitations:** Limited by hardware constraints on 3D texture size [S2, unofficial].
*   **When to Use:** Real-time applications requiring transparent shadow, transmittance, and refraction effects [S2, unofficial].
*   **When Not to Use:** When hardware does not support 3D texture render targets or geometry shaders [S2, unofficial].

## Background
This method was proposed by Hsu-Huai Chang and Yu-Chi Lai in their paper "Real-time GPU-Based Voxelization and Applications" [S2, unofficial]. It leverages newly available GPU functionalities, specifically the geometry shader and 3D volume texture as render targets, to overcome limitations of previous slicing-based and encoding-based voxelization methods [S2, unofficial]. The technique is used for rendering transparent shadow, transmittance, and refraction effects in real-time applications [S2, unofficial].
