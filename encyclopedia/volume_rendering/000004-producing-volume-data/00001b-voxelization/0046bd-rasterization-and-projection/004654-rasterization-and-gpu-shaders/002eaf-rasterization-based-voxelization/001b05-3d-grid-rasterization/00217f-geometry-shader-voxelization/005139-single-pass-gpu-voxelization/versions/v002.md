# Single-Pass GPU Voxelization

Also called: LEGOr Voxelization, Voxelization: Vertex Shader

## Overview
Single-Pass GPU Voxelization maps 3D mesh vertices directly to a 3D grid (voxel space) in a single rasterization pass using a Frame Buffer Object (FBO), avoiding the multiple passes required by methods like Karabassi et al. [S1]. It encodes voxel indices into the FBO alpha channel during the vertex shader stage, rather than rasterizing triangles into a 3D texture via a geometry shader [G].

## How it works
**Inputs:**
- `vp`: 3D vertex position $(v_{px}, v_{py}, v_{pz})$ [S1].
- `vc`: 3D vertex color $(v_{cx}, v_{cy}, v_{cz})$ [S1].
- `size`: Integer grid resolution (side length of the cubic voxel grid) [S1].

**Outputs:**
- A 2D Frame Buffer Object (FBO) where each pixel corresponds to a projected vertex [S1].
- The FBO channels store: Red ($R$) = $v_{cx}$, Green ($G$) = $v_{cy}$, Blue ($B$) = $v_{cz}$, Alpha ($A$) = normalized voxel index [S1].
- A Vertex Buffer Object (VBO) generated from the downloaded FBO data, used for subsequent polygonization [S1].

**Data Structures:**
- **FBO Layout**: A 2D texture or render target with RGBA format [G]. The spatial resolution of the FBO must be sufficient to avoid overlapping projections of distinct vertices [S1].
- **Voxel Index**: A linear integer index $w$ representing the position in the 3D grid, calculated as $w = i_x \cdot size^2 + i_y \cdot size + i_z$, where $i_x, i_y, i_z$ are the integer voxel coordinates [S1].

**Steps:**

1.  **Vertex Shader Execution**: For each vertex of the input mesh:
    a.  Compute the linear voxel index $w$ from the vertex position $v_p$ and grid `size`:
        $$ w = \lfloor v_{px} \rfloor \cdot size^2 + \lfloor v_{py} \rfloor \cdot size + \lfloor v_{pz} \rfloor $$
        *Note: The source uses `int()` which truncates toward zero; for positive voxel-space coordinates this is equivalent to floor [G].*
    b.  Check bounds: If $w$ is outside the valid grid range $[0, size^3 - 1]$, set the output alpha to `NULL` (or 0) and discard the vertex for further processing [S1].
    c.  Normalize the voxel index for storage in the alpha channel:
        $$ \alpha = \frac{w}{size^3} $$
    d.  Output the vertex color $(v_{cx}, v_{cy}, v_{cz})$ to the RGB channels and $\alpha$ to the Alpha channel [S1].

2.  **Rasterization**: The vertices are rasterized into the FBO [S1]. Standard depth testing (Z-buffer) is applied [G]. Vertices closer to the camera overwrite those further away [G]. Vertices projecting to the same pixel position are resolved by the Z-buffer, which keeps the closest vertex and discards others [S1].

3.  **FBO Download and VBO Creation**:
    a.  Read the FBO data back to the CPU [S1].
    b.  Interpret each pixel in the FBO as a vertex [S1].
    c.  Construct a VBO where each vertex contains the RGB color and the Alpha value (which encodes the voxel index) [S1].

4.  **Polygonization (LEGOr Brick Generation)**:
    a.  Use a Geometry Shader to process the VBO [S1].
    b.  Convert the normalized alpha value $\alpha$ back to spatial coordinates $(i_x, i_y, i_z)$ to find the center of the cube [S1].
    c.  Generate the geometry (triangles) for the LEGOr brick (voxel) at that location [S1].
    d.  Discard vertices with illegal/null values [S1].

**Pseudocode:**

```python
def vertex_shader(vp: tuple, vc: tuple, size: int) -> tuple:
    # 1. Compute linear voxel index w
    ix = int(vp[0])
    iy = int(vp[1])
    iz = int(vp[2])
    w = ix * size * size + iy * size + iz

    # 2. Check bounds
    max_voxels = size * size * size
    if w < 0 or w >= max_voxels:
        return (vc[0], vc[1], vc[2], 0.0)  # Null value for alpha

    # 3. Normalize voxel index for alpha channel
    alpha = w / max_voxels
    
    # 4. Emit pixel with color in RGB and normalized index in Alpha
    return (vc[0], vc[1], vc[2], alpha)

def reconstruct_and_polygonize(vbo_data: list, size: int) -> list:
    bricks = []
    for pixel in vbo_data:
        alpha = pixel[3]
        if alpha == 0.0:
            continue  # Discard illegal/null values
        w = int(alpha * size * size * size)
        iz = w % size
        w //= size
        iy = w % size
        ix = w // size
        # Generate LEGOr brick geometry at (ix, iy, iz)
        bricks.append((ix, iy, iz, pixel[0], pixel[1], pixel[2]))
    return bricks
```

**Parameters:**
- `size`: The grid resolution (e.g., 128, 256) [S1].
- FBO Resolution: Must be large enough to prevent overlapping projections of distinct vertices [S1]. Typical values are 512x512 for resolutions up to $128^3$ voxels, and >1024x1024 for complex objects [S1].

**Edge Cases and Pitfalls:**
- **Holes in Back Surfaces**: Because the method relies on vertex projection and Z-buffering, back-facing surfaces may be occluded by front-facing vertices, resulting in holes [S1]. This is mitigated by increasing the FBO size to reduce vertex overlap and ensure distinct vertices map to distinct pixels [S1].
- **Vertex Overlap**: Complex objects may have many vertices projecting to the same pixel [S1]. The Z-buffer resolves this by keeping only the closest vertex, which may discard interior geometry information if the application requires it [S1].
- **Precision**: The normalization of the voxel index into the alpha channel introduces quantization error [G]. Using floating-point FBOs is recommended to preserve index integrity [G].

## Subtopics

### [Single-Pass GPU Voxelization via 3D Texture Render Target](15078-single-pass-gpu-voxelization-via-3d-texture-render-target.md)
This method transforms a surface-represented scene into a high-resolution voxel grid in a single GPU pass by using the geometry shader to duplicate geometry for intersecting slices and a 3D volume texture as the direct render target. It solves the inefficiency of multi-pass slicing algorithms and the projection artifacts or fixed-resolution limitations of grid encoding methods. Unlike encoding methods that induce errors, this approach uses a clipping plane algorithm to avoid projection artifacts.

## Operating characteristics
- **Time Complexity**: $O(V)$ for the vertex shader pass, where $V$ is the number of vertices [G]. The subsequent geometry shader pass is $O(P)$, where $P$ is the number of projected pixels (voxels) [G].
- **Memory Complexity**: $O(size^2)$ for the FBO storage (2D projection) and $O(size^3)$ for the final voxel grid if explicitly stored, though the method primarily outputs a VBO of projected vertices [G].
- **Performance**: On an AMD Athlon 64 3500+ with 2GB RAM and GeForce 8800GTX, a 512x512 FBO produces good results for $128^3$ voxel resolutions [S1]. Complex objects require FBO sizes >1024x1024 [S1].
- **Speed**: Up to 5 times faster than Passalis et al., which renders the model six times using multiple buffers [S1]. This method renders the model only once using a single frame buffer [S1].
- **Strengths**: Single-pass rasterization; real-time performance; no preprocessing required [S1].
- **Limitations**: Dependent on model surface complexity; prone to holes in back surfaces if FBO is too small; misses concavities in concave objects if not carefully tuned (though less prone than Karabassi et al.) [S1].

## Background
The method was introduced in the "Legolizer" system, described in the paper *Legolizer: A Real-Time System for Modeling and Rendering LEGO Representations of Boundary Models* [S1]. It was developed to create LEGO-like representations of 3D models efficiently [S1]. The approach was compared against Passalis et al. and Karabassi et al. [S1].
