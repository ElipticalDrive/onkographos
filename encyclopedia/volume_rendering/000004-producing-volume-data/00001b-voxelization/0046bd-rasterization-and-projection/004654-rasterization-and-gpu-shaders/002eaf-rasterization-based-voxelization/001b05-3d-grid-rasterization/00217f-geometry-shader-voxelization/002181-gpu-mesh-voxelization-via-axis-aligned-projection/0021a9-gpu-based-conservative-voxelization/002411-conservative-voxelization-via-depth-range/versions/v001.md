# Conservative Voxelization via Depth Range

Also called: Depth range voxelization

## Overview
Conservative Voxelization via Depth Range is a GPU-based rasterization technique that converts 3D triangle meshes into a binary voxel grid by computing the depth range of a projected triangle over each fragment rectangle and encoding occupancy bits into a texture [S1, unofficial]. It differs from standard rasterization by ensuring that any voxel intersecting the triangle is marked as occupied, avoiding the "missing voxel" artifacts common in non-conservative methods, and differs from slicemap-based approaches by explicitly calculating geometric intersection bounds rather than relying on bitwise blending of discrete depth slices [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D triangle mesh defined by vertices $P_i = (x_i, y_i, z_i)$ for $i \in \{1, 2, 3\}$, and a target voxel grid resolution $(res_x, res_y, res_z)$.
*   **Output:** A 2D texture (or set of textures) where each texel at $(i, j)$ contains a bitmask representing the occupancy of voxels $(i, j, k)$ for $k \in [0, res_z-1]$.

**Data Structures:**
*   **Lookup Table Texture:** A 2D texture storing precomputed bitmasks.
    *   Standard mode (32 slices): Size $32 \times 32$. Format RGBA8. Each texel stores a 32-bit mask. Index $(z^*_{min}, z^*_{max})$ maps to the mask for depth range $[z_{min}, z_{max}]$, where $z^* = z \times 32$.
    *   MRT mode (128 slices): Size $512 \times 128$. Format RGBA8. Each texel stores 32 bits. Four consecutive texels store a 128-bit mask.
*   **Fragment Rectangle ($R$):** The axis-aligned bounding box of the fragment in screen space, defined by $x_{min}, x_{max}, y_{min}, y_{max}$.

**Parameters:**
*   $\epsilon_I$: Threshold for detecting parallel lines and degenerate edges.
*   $\epsilon_S$: Threshold for detecting degenerate triangles (projected area).
*   $\epsilon_m$: Machine error constant used to initialize enlarged rectangle dimensions.
*   $\epsilon_{float}$: Floating point error constant (e.g., $10^{-5}$) added to the computed depth range to address limited GPU precision [S1, unofficial].

**Algorithm Steps:**

1.  **Vertex Processing (Partial Derivatives):**
    For each vertex $P_i$, compute the barycentric coordinate derivatives and depth derivatives.
    *   Compute signed area $S$ of the projected triangle:
        $$ S = x_1 y_2 - x_2 y_1 + x_2 y_3 - x_3 y_2 + x_3 y_1 - x_1 y_3 $$
    *   Compute partial derivatives of barycentric coordinates $\mathbf{C}$:
        $$ \frac{\partial \mathbf{C}}{\partial x} = \frac{(y_2 - y_3, y_3 - y_1, y_1 - y_2)}{S} $$
        $$ \frac{\partial \mathbf{C}}{\partial y} = \frac{(x_3 - x_2, x_1 - x_3, x_2 - x_1)}{S} $$
    *   Compute partial derivatives of depth $z$:
        $$ \frac{\partial z}{\partial x} = (z_1, z_2, z_3) \cdot \frac{\partial \mathbf{C}}{\partial x} $$
        $$ \frac{\partial z}{\partial y} = (z_1, z_2, z_3) \cdot \frac{\partial \mathbf{C}}{\partial y} $$
    *   Compute $\Delta \mathbf{C}$ (offset for conservative rasterization) and output $C^* = C(P_i) - \Delta \mathbf{C}$ as a 3D vector [S1, unofficial].

2.  **Intersection Computation:**
    Compute intersection points $Q$ between each edge of the triangle $T_p$ and each edge of the fragment rectangle $R$.
    *   For an edge $P_i P_j$ and a horizontal rectangle edge (e.g., top or bottom), calculate coefficients:
        $$ a_{ij}^y = \frac{1}{y_j - y_i}, \quad b_{ij}^y = \frac{-y_i}{y_j - y_i} $$
    *   Calculate parameter $t$ for intersection with $y_{max}$ (or $y_{min}$):
        $$ t = a_{ij}^y \cdot y_{max} + b_{ij}^y $$
    *   Calculate intersection point $Q$:
        $$ Q = \mathcal{L}(P_i, P_j, t) $$
        where $\mathcal{L}$ denotes linear interpolation.
    *   Calculate $z(Q) = \mathcal{L}(z_i, z_j, t)$.
    *   Check if $Q$ lies on both the triangle edge and the rectangle edge. If true, keep $z(Q)$; otherwise, assign $z(Q)$ a huge value (infinity) [S1, unofficial].
    *   Repeat for all 12 combinations (3 edges $\times$ 4 rectangle edges).

3.  **Depth Range Determination:**
    *   Find the minimal depth value among the valid intersection points to determine $z_{min}$.
    *   Find the maximal depth value to determine $z_{max}$.
    *   Apply optimization: Use GPU 4D vector processing to compute intersections of one triangle edge with four rectangle edges simultaneously. Compare 12 depth values using four comparisons (two 4D vectors, one 2D vector, one scalar) [S1, unofficial].

4.  **Special Case Handling (Robustness):**
    *   **Parallel Lines:** If $|\frac{y_j - y_i}{x_j - x_i}| < \epsilon_I$, the edge is nearly horizontal. Set $a_{ij}^y = 0, b_{ij}^y = 2$ to discard intersections with top/bottom edges. Enlarge rectangle height by $\epsilon_I$. Test intersection with left/right edges by checking $y_{min} - \epsilon_I \le y \le y_{max} + \epsilon_I$ [S1, unofficial].
    *   **Degenerate Edges:** If $|x_j - x_i| < \epsilon_I$ and $|y_j - y_i| < \epsilon_I$, assume both vertices are inside the fragment. Check if the third vertex $P_k$ is inside $R$ using the enlarged bounds [S1, unofficial].
    *   **Degenerate Triangles:** If $|S| < \epsilon_S$, barycentric coordinates are unreliable. Set $C^* = (-1, -1, -1)$. Enlarge rectangle width and height by $\sqrt{2}h$, where $h$ is the minimal height of the triangle [S1, unofficial].

5.  **Voxel Encoding:**
    *   Apply a small constant $\epsilon_{float}$ to $z_{min}$ and $z_{max}$ to handle precision errors: $z_{min} \leftarrow z_{min} + \epsilon_{float}$, $z_{max} \leftarrow z_{max} + \epsilon_{float}$ [S1, unofficial].
    *   Map depth range to voxel indices: $z^*_{min} = \lfloor z_{min} \times 32 \rfloor$, $z^*_{max} = \lceil z_{max} \times 32 \rceil$ (for 32-slice mode).
    *   Perform a texture lookup in the Lookup Table using $(z^*_{min}, z^*_{max})$ to retrieve the 32-bit bitmask.
    *   Write the bitmask to the fragment color buffer. If using MRT, write to multiple targets to cover 128 slices [S1, unofficial].

6.  **Conservative Rasterization Integration:**
    *   Enlarge each triangle by half a pixel to form a bounding polygon.
    *   Draw the optimal bounding triangle and cull redundant fragments to improve efficiency [S1, unofficial].

## Subtopics

### Slicemap Boundary Voxelization
A technique to represent a binary 3D grid of voxels using a single 2D texture, where the $k$-th bit of the RGBA representation of pixel $(i, j)$ encodes the value of voxel $(i, j, k)$ [S2, unofficial]. It renders the scene and, for each fragment, if its depth lies in the $k$-th slice, outputs a color having only the $k$-th bit activated. It uses a bitwise OR blending mode to combine all fragments projecting to the same pixel, allowing tracking of all fragments in a single pass rather than discarding all but the closest [S2, unofficial]. Unlike Conservative Voxelization via Depth Range, it does not compute geometric intersection bounds but relies on depth quantization and bitwise operations [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of triangles, as each triangle is processed in a single pass (or few passes for MRT). The intersection computation is constant time per triangle (12 intersections).
*   **Memory Complexity:** $O(res_x \times res_y \times \frac{res_z}{32})$ for the output texture. The lookup table is small ($32 \times 32$ or $512 \times 128$ texels).
*   **Performance:** The method leverages GPU native 4D vector processing for intersection calculations, significantly accelerating the depth range computation [S1, unofficial]. MRT support allows processing 128 slices in a single pass, reducing the number of rendering passes required for high-resolution volumes [S1, unofficial].
*   **Accuracy:** Theoretically accurate; misses no voxels. Redundant voxels are minimal (no more than 0.1% of total) due to the conservative enlargement and precision error constant [S1, unofficial].
*   **Limitations:** Requires hardware support for MRT and bitwise blending operations. The lookup table size grows with the number of slices if not using MRT. Parallel line and degenerate triangle cases require careful handling to maintain correctness [S1, unofficial].

## Background
The method was introduced in a paper on conservative voxelization, which proposed computing the depth range of a projected triangle over a fragment rectangle to encode occupancy bits into a texture [S1, unofficial]. It builds upon the concept of slicemaps, where a 3D grid is represented by a 2D texture using bits of RGBA channels [S2, unofficial]. The approach addresses the limitations of pre-computation based approaches that use switch-case structures and costly intersection point location computations, offering a more hardware-friendly implementation using native GPU vector operations [S1, unofficial].
