# 3D Grid Rasterization

Also called: Grid-Snapped Voxelization

## Overview
3D Grid Rasterization converts a triangle mesh into a binary occupancy grid by projecting the mesh onto three orthogonal planes (XY, YZ, XZ) using hardware rasterization and combining the results [S4, unofficial]. It solves the problem of efficiently determining which voxels in a fixed-resolution 3D grid are intersected by the mesh surface, serving as a fast, GPU-accelerated alternative to CPU-based raycasting or brute-force AABB intersection tests [S4, unofficial]. Unlike [Conservative Voxelization](3247-conservative-voxelization.md) which guarantees no holes by expanding primitives, this method relies on standard rasterization rules and bit-packing to achieve high throughput, prioritizing speed over watertightness for complex internal structures [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle mesh (vertices, indices, optional colors/normals) and a target grid resolution.
*   **Output:** A 3D occupancy grid (binary or color) representing the voxelized mesh.

**Data Structures:**
*   **Voxel Grid Storage:** A compact 1-bit-per-voxel format is often used for occupancy. The grid is stored as a `std::vector<uint32_t>` (or equivalent) of size $(N_x \times N_y \times N_z) / 32$, where each `uint32_t` stores 32 voxels [S4, unofficial]. Memory order is linear in X, then Y, then Z [S4, unofficial].
*   **Intermediate Projections:** Three 3D textures (or image buffers) are used to store the rasterized projections along the X, Y, and Z axes. These textures are organized in "slabs" of 32 voxels along the projection axis to facilitate batch processing [S4, unofficial].
    *   `xProjTextureId`: Dimensions $(N_y, N_z, N_x/32)$.
    *   `yProjTextureId`: Dimensions $(N_x, N_z, N_y/32)$.
    *   `zProjTextureId`: Dimensions $(N_x, N_y, N_z/32)$.
*   **Voxel Coordinate Hash:** For CPU variants or hash-table based implementations, a `VoxelCoord` struct with `x, y, z` integers is hashed using primes $p_1=73856093, p_2=19349663, p_3=83492791$: $hash = x \cdot p_1 \oplus y \cdot p_2 \oplus z \cdot p_3$ [S1, unofficial].

**Parameters:**
*   `resolution`: Target grid resolution along the smallest bounding box dimension. Typical values: 64, 128, 256, 512 [S4, unofficial].
*   `voxel_size`: Calculated as $\min(\text{boundingBoxSize}) / \text{resolution}$ [S4, unofficial].
*   `grid_min`, `grid_max`: Integer bounds of the grid, typically $\{0,0,0\}$ and $\{\text{grid\_size}, \text{grid\_size}, \text{grid\_size}\}$ [S1, unofficial].

**Steps:**

1.  **Bounding Box and Grid Setup:**
    Compute the axis-aligned bounding box (AABB) of the mesh vertices. Calculate the voxel size $v_s$ using the smallest dimension of the bounding box divided by the resolution [S4, unofficial]. Round the number of voxels in each dimension up to the nearest multiple of 32 to align with the slab-based storage [S4, unofficial]. Calculate the grid origin (minCorner) and dimensions [S4, unofficial].

2.  **Projection Passes (X, Y, Z):**
    For each axis (X, Y, Z), perform a rasterization pass:
    *   **Setup:** Allocate a 3D texture for the projection. Bind slices of this texture to the framebuffer color attachment.
    *   **Camera/View:** Set up an orthographic projection matrix. The view direction is along the current axis. The near and far planes are set to cover a slab of 32 voxels: $[z_{slice}, z_{slice} + 32 \cdot v_s]$ [S4, unofficial].
    *   **Rotation:** Rotate the mesh or view matrix so the projection axis aligns with the camera's view direction. For example, for Z-projection, rotate 180° around Z and 180° around Y [S4, unofficial].
    *   **Rasterization:** Render the mesh triangles into the current slice. Use `GL_OR` logic operation or additive blending to accumulate occupancy bits. Disable depth testing to ensure all fragments within the slab contribute [S4, unofficial].
    *   **Loop:** Iterate through all slices along the projection axis (step 32) and repeat.

3.  **Combination (Optional for Z-axis):**
    In some implementations, the X and Y projections are combined into the Z-projection texture using a fragment shader (`compileProjections`) that reads from the X and Y textures and writes to the Z texture, effectively performing a 3D intersection test via 2D rasterization [S4, unofficial].

4.  **Result Retrieval:**
    Read back the final 3D texture (e.g., `zProjTextureId`) using `glGetTexImage` with format `GL_RGBA_INTEGER` and type `GL_UNSIGNED_INT_8_8_8_8` (or equivalent bit-packed format) to retrieve the occupancy grid on the CPU [S4, unofficial].

**Pseudocode (GPU-based Slab Rasterization):**

```python
def rasterize_mesh_to_grid(mesh, resolution):
    # 1. Compute Bounding Box and Grid Params
    min_coords, max_coords = mesh.compute_aabb()
    min_side = min(max_coords.x - min_coords.x, 
                   max_coords.y - min_coords.y, 
                   max_coords.z - min_coords.z)
    voxel_size = min_side / resolution
    
    # Round dimensions to multiple of 32
    nb_voxels = [round_up_to_multiple_32(max_coords.x - min_coords.x / voxel_size),
                 round_up_to_multiple_32(max_coords.y - min_coords.y / voxel_size),
                 round_up_to_multiple_32(max_coords.z - min_coords.z / voxel_size)]
    
    min_corner = min_coords - 0.5 * (nb_voxels * voxel_size)
    
    # 2. Allocate Intermediate Textures
    x_proj = allocate_3d_texture(nb_voxels.y, nb_voxels.z, nb_voxels.x // 32)
    y_proj = allocate_3d_texture(nb_voxels.x, nb_voxels.z, nb_voxels.y // 32)
    z_proj = allocate_3d_texture(nb_voxels.x, nb_voxels.y, nb_voxels.z // 32)
    
    # 3. X-Axis Projection
    for slice_x in range(0, nb_voxels.x, 32):
        bind_texture_3d_slice(x_proj, 0, slice_x // 32)
        set_viewport(nb_voxels.y, nb_voxels.z)
        clear_buffer()
        # Ortho view: look along X axis, slab [slice_x, slice_x + 32*voxel_size]
        view_proj = ortho(min_coords.y, max_coords.y, 
                          min_coords.z, max_coords.z, 
                          min_corner.x + slice_x * voxel_size, 
                          min_corner.x + (slice_x + 32) * voxel_size)
        # Rotate mesh to align X with view direction
        mesh.model_matrix = rotate_x(-90) * rotate_z(90)
        mesh.draw(view_proj)
        
    # 4. Y-Axis Projection
    for slice_y in range(0, nb_voxels.y, 32):
        bind_texture_3d_slice(y_proj, 0, slice_y // 32)
        set_viewport(nb_voxels.x, nb_voxels.z)
        clear_buffer()
        view_proj = ortho(min_coords.x, max_coords.x, 
                          min_coords.z, max_coords.z, 
                          min_corner.y + slice_y * voxel_size, 
                          min_corner.y + (slice_y + 32) * voxel_size)
        mesh.model_matrix = rotate_x(-90)
        mesh.draw(view_proj)
        
    # 5. Z-Axis Projection
    for slice_z in range(0, nb_voxels.z, 32):
        bind_texture_3d_slice(z_proj, 0, slice_z // 32)
        set_viewport(nb_voxels.x, nb_voxels.y)
        clear_buffer()
        view_proj = ortho(min_coords.x, max_coords.x, 
                          min_coords.y, max_coords.y, 
                          min_corner.z + slice_z * voxel_size, 
                          min_corner.z + (slice_z + 32) * voxel_size)
        mesh.model_matrix = rotate_z(180) * rotate_y(180)
        mesh.draw(view_proj)
        
    # 6. Combine Projections (if using compile shader)
    # Bind x_proj and y_proj to texture units 0 and 1
    # Bind z_proj slice to framebuffer
    # Draw full-screen quad with compileProjections shader
    # This step merges X and Y occupancy into Z
    
    # 7. Readback
    grid_data = glGetTexImage(z_proj, format=GL_RGBA_INTEGER, type=GL_UNSIGNED_INT_8_8_8_8)
    return grid_data
```

**Edge Cases and Pitfalls:**
*   **Triangles Outside Grid:** Triangles outside the `[GridMin, GridMax]` region map outside the valid NDC range and are not voxelized [S3, unofficial].
*   **Precision Glitches:** On some hardware (e.g., Intel HD 4400 on Linux), rasterization may suffer from glitches or lower max resolution compared to other platforms [S4, unofficial].
*   **Additive Blending Assumptions:** Using additive blending (`GL_ONE, GL_ONE`) assumes opaque mesh fragments. If multiple fragments write to the same pixel with different bits, it may cause issues if exact single-bit setting is required, though the slab logic usually isolates bits [S5, unofficial].
*   **Division by Zero:** Handle cases where grid dimension is zero [S8, unofficial].

## Subtopics

### [A-Buffer Solid Voxelization](1189-a-buffer-solid-voxelization.md)
A-Buffer Solid Voxelization is a GPU-based technique that voxelize a watertight mesh by rasterizing it into a fixed-width, height, and depth 3D grid and resolving multiple depth intersections per pixel using an A-buffer linked list structure. It differs from standard depth-buffer rasterization by retaining all fragment depth information rather than discarding occluded fragments, allowing it to output a linked list of starting and ending voxels for each row and column in the grid.

### [Adaptive Sparse Voxelization with Bounding Box Thickness Cases](1686-adaptive-sparse-voxelization-with-bounding-box-thickness-cas.md)
This method rasterizes triangle meshes into a Morton-ordered sparse voxel grid by classifying each triangle into one of nine cases based on the thickness of its axis-aligned bounding box (AABB) in grid coordinates. It solves the problem of efficiently determining intersected voxels while minimizing redundant depth tests, setting itself apart from general 3D grid rasterization by explicitly handling "thin" (1-voxel thick) triangles via 2D projection and "thick" triangles via 3D plane and projection tests.

### [Geometry Shader Voxelization](2566-geometry-shader-voxelization.md)
Geometry Shader Voxelization rasterizes polygonal meshes directly into a 3D voxel grid by leveraging the GPU's geometry shader stage to project triangles onto axis-aligned planes and iterate through occupied grid cells. It solves the problem of converting continuous surface geometry into discrete volumetric data without requiring explicit CPU-side raycasting or compute-shader-based brute-force intersection tests. Unlike sibling methods that rely on hardware rasterization of 2D fragments (e.g., [Image-space Voxelization](14395-image-space-voxelization.md)) or pure compute shaders (e.g., [GPU Mesh Voxelization via AABB-Triangle Intersection](2541-gpu-mesh-voxelization-via-aabb-triangle-intersection.md)), this method explicitly generates 3D voxel primitives or iterates grid bounds within the shader, offering a balance between implementation simplicity and watertightness control.

### [GPU Mesh Voxelizer (Grid Generation)](11413-gpu-mesh-voxelizer-grid-generation.md)
This method generates a dense 3D voxel grid by computing the center coordinates of each voxel cell directly on the GPU using a compute shader. It solves the problem of converting a mesh's spatial extent into a fixed-width, height, and depth 3D grid structure, returning a flat array of voxel centers. Unlike rasterization-based approaches that project geometry onto slices, this method calculates grid dimensions from the mesh's bounding box and fills the grid with uniform cells, making it suitable for preprocessing steps where a regular grid topology is required. It builds on [3D Grid Rasterization](903-3d-grid-rasterization.md) by providing the specific grid generation mechanism.

### [Derived Grid Rasterization](11477-derived-grid-rasterization.md)
Derived Grid Rasterization converts an unstructured 3D volume mesh (e.g., tetrahedra, hexahedra) into a dense, regular 3D voxel grid spanning the mesh's Axis-Aligned Bounding Box (AABB). This creates a structured data layout required for efficient volume ray-marching and axis-aligned slice planes on data that originally lacks a grid structure. Unlike sibling methods that may produce sparse structures or rely on different rasterization primitives, this method explicitly maps each voxel to its owning unstructured cell and local tetrahedron index, enabling direct lookup during rendering. It builds on [3D Grid Rasterization](903-3d-grid-rasterization.md) by handling unstructured cell topology rather than simple surface mesh voxelization.

### [Unstructured Mesh Pixelization via Convex Element Containment](11479-unstructured-mesh-pixelization-via-convex-element-containmen.md)
A pixelization routine that transforms variable-resolution unstructured mesh values into an image buffer by depositing values through nearest-neighbor interpolation with anti-aliasing, decoupling the pixelization step from the underlying data model. It differs from standard rasterization by using a geometric containment test based on dot product signs relative to element centroids, which eliminates the requirement for consistent vertex winding order (CW/CCW).

### [Fast Solid Voxelization via Planar Raycasting](13748-fast-solid-voxelization-via-planar-raycasting.md)
Fast Solid Voxelization via Planar Raycasting is a rasterization-based method that generates a solid voxel mesh from an arbitrary polyhedron by casting rays along the three world coordinate planes (XY, YZ, XZ). It solves the problem of converting polygonal meshes into dense 3D grids by determining voxel occupancy through intersection parity, prioritizing raw computational speed over memory efficiency. It differs from its sibling [A-Buffer Solid Voxelization](1189-a-buffer-solid-voxelization.md) and [3D Grid Rasterization](903-3d-grid-rasterization.md) by using pre-computed plane buffers and bit-shifting accumulation rather than per-voxel raycasting or hierarchical data structures, making it significantly faster but less accurate for complex internal structures.

### [Image-space Voxelization](14395-image-space-voxelization.md)
Image-space voxelization projects the vertices of a triangular mesh into a 2D image stored in a Frame Buffer Object (FBO) to determine voxel locations and colors. It solves the problem of converting boundary models into volumetric representations by leveraging GPU rasterization hardware, specifically using a single render pass and a single buffer to preserve original vertex colors, unlike methods requiring multiple passes or z-buffer stacks.

### Projection Voxelization Shader
A vertex shader that generates a full-screen quad to process each voxel slice, outputting non-normalized voxel coordinates for the fragment shader [S4, unofficial]. It defines quad corners `vec2(0,0), vec2(1,0), vec2(0,1), vec2(1,1)` and calculates voxel coordinate `texelCoord = vec3(corner * gridSize.xy, slice)` where `corner` is selected by `gl_VertexID` [S4, unofficial]. It sets clip space position `gl_Position = vec4(corner*2-1, 0, 1)` [S4, unofficial]. Inputs include `uniform uint slice` and `uniform vec3 gridSize` [S4, unofficial].

### 3D Rasterization Algorithm
A simplicial covering method that computes the minimal bounding box and centroid of the polygon/solid [S12, unofficial]. It constructs a tetrahedron (in 3D) or triangle (in 2D) between the origin vertex (centroid) and one edge (or face) of the polygon/solid [S12, unofficial]. It rasterizes the simplex in the P-Buffer (Presence Buffer), flipping all positions (bits) covered by it [S12, unofficial]. It repeats this for all edges/faces until no edges are left, then transfers all positions from the P-Buffer within the minimal bounding box that have a presence value of 1 to the framebuffer, applying the corresponding color [S12, unofficial]. The P-Buffer is a 3D buffer where each position stores a single bit representing the presence value of a voxel (1 if inside, 0 if outside) [S12, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$ where $N$ is the number of triangles in the mesh and $V$ is the number of slices (proportional to grid resolution). Each slice renders the entire mesh [S4, unofficial].
*   **Measured Performance:** On an Intel HD 4400 with a Suzanne model (31,000 vertices): 64³ grid takes 2 ms; 128³ takes 9 ms; 256³ takes 10 ms; 512³ takes 120 ms. A 1,000,000 vertex model at 128³ takes 45 ms [S4, unofficial].
*   **Scaling:** Performance scales linearly with the number of triangles and the number of slices (resolution). The 32-slab optimization reduces the number of draw calls and texture binds [S4, unofficial].
*   **Strengths:** High throughput on GPU hardware; simple implementation using standard rasterization pipeline; compact 1-bit storage reduces memory bandwidth [S4, unofficial].
*   **Limitations:** Not inherently watertight; may produce holes or artifacts on complex geometry or thin surfaces; precision issues on some hardware [S4, unofficial].
*   **When to Use:** When speed is critical and approximate occupancy is sufficient (e.g., global illumination voxelization, sparse voxel octree initialization) [S3, unofficial].
*   **When Not to Use:** When watertightness is required for simulation or precise collision detection; use [Conservative Voxelization](3247-conservative-voxelization.md) or [A-Buffer Solid Voxelization](1189-a-buffer-solid-voxelization.md) instead.

## Background
Originating from GPU-based voxelization techniques for global illumination (VXGI) and real-time rendering, this method leverages the efficiency of hardware rasterization to avoid CPU-side intersection tests [S3, unofficial]. It is a core component of pipelines like o-voxel, where it serves as the fast "intersect scanline" step to discover occupied voxels before more expensive surface reconstruction steps [S1, unofficial]. The technique was popularized by implementations such as `voxelizer-gpu` which demonstrated the feasibility of using OpenGL 3.3+ rasterization for 3D grid generation [S4, unofficial].
