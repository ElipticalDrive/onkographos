# GPU-based Voxelization via Slice Rendering

Also called: Hardware Rasterization Voxelization, Voxelizer

## Overview
GPU-based Voxelization via Slice Rendering converts a triangle mesh into a 3D voxel grid by rendering the mesh slice-by-slice using hardware rasterization [S1, unofficial]. It differs from CPU-based methods by performing all computation on the GPU and adjusting the Z-near and Z-far planes for each slice to isolate geometry [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A triangle mesh defined by vertex positions, normals, and indices [S1, unofficial].
*   **Output:** A 3D voxel grid stored in a `std::vector<uint32_t>`, where each voxel is represented by 1 bit [S1, unofficial].

**Data Structures**
The result grid is a 1D array of `uint32_t` [S1, unofficial]. Each `uint32_t` stores the state of 32 voxels [S1, unofficial]. The grid dimensions ($X_{max}, Y_{max}, Z_{max}$) must be multiples of 32 to align with this bit-packing scheme [S1, unofficial]. The memory layout is organized by Z-blocks [S1, unofficial]. Within each Z-block, the data is stored as $(X_0,Y_0,Z_{00-31}) \mid (X_1,Y_0,Z_{00-31}) \mid \dots \mid (X_{max},Y_0,Z_{00-31})$ for the first block, followed by $(X_0,Y_1,Z_{00-31}) \mid \dots$ for the next Y-slice, and so on, up to $Y_{max}$ [S1, unofficial]. This pattern repeats for subsequent Z-blocks ($Z_{32-63}$, etc.) [S1, unofficial].

**Parameters**
*   `resolution`: The target resolution for the voxel grid, passed to `recompute` [S1, unofficial].
*   `_precision`: The default precision/resolution used in the reference implementation, set to 32 [S1, unofficial].

**Algorithm Steps**
1.  **Grid Initialization:** Compute the optimal 3D grid dimensions based on the mesh and target resolution [S1, unofficial].
2.  **Slice Iteration:** Fill the 3D grid by iterating through slices along an axis [S1, unofficial].
3.  **Rendering:** For each slice, draw the mesh slice using a specific shader and axis [S1, unofficial].

**Pseudocode**
```python
def voxelize_mesh(mesh, resolution=32):
    # 1. Compute grid dimensions based on mesh bounds and target resolution
    # Dimensions must be multiples of 32 for bit-packing alignment
    X, Y, Z = compute_grid_dimensions(mesh.bounds, resolution)
    assert X % 32 == 0 and Y % 32 == 0 and Z % 32 == 0

    # 2. Initialize bit-packed grid
    # Each uint32 stores 32 consecutive Z-voxels for a given (x, y)
    grid = [0] * (X * Y * Z // 32)

    # 3. Iterate through slices along the Z axis
    for z in range(Z):
        # Adjust view frustum Z-near and Z-far planes for the current slice
        view_matrix = setup_slice_view(z, resolution)
        
        # Draw the mesh slice using hardware rasterization
        covered = rasterize_mesh_slice(mesh, view_matrix, resolution)
        
        # Update grid with covered voxel coordinates
        for x, y in covered:
            set_voxel(grid, x, y, z, X, Y)

    return grid

def compute_grid_dimensions(bounds, resolution):
    # [G] Standard bounding-box to grid-dimension calculation
    width = bounds.max_x - bounds.min_x
    height = bounds.max_y - bounds.min_y
    depth = bounds.max_z - bounds.min_z
    X = ((width / resolution) // 32 + 1) * 32
    Y = ((height / resolution) // 32 + 1) * 32
    Z = ((depth / resolution) // 32 + 1) * 32
    return X, Y, Z

def setup_slice_view(slice_z, resolution):
    # [G] Standard view matrix setup isolating a slice at depth slice_z
    return create_view_matrix(z_near=slice_z, z_far=slice_z + 1)

def rasterize_mesh_slice(mesh, view_matrix, resolution):
    # [G] Standard hardware rasterization: project triangles, clip to frustum, return covered (x, y)
    projected = [multiply_matrix_vector(view_matrix, v) for v in mesh.vertices]
    return hardware_rasterize_triangles(projected, resolution)

def set_voxel(grid, x, y, z, X, Y):
    # Layout: X varies fastest, then Y, then Z-block
    # Maps (x, y, z) to the correct uint32_t index and bit position
    idx = (x + y * X + z * X * Y) // 32
    bit = 1 << (z % 32)
    grid[idx] |= bit
```

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** $O(V)$, where $V$ is the total number of voxels, stored as 1 bit per voxel [S1, unofficial].
*   **Strengths:** All computation is handled on the GPU using hardware rasterization [S1, unofficial].
*   **Limitations:** Grid dimensions must be multiples of 32 to align with the bit-packing scheme [S1, unofficial].
