# Conservative Voxelization via Depth Range

Also called: Depth range voxelization

## Overview
Conservative Voxelization via Depth Range is a GPU-based technique that converts 3D triangle meshes into a binary 3D grid of voxels by computing the depth range of a projected triangle over a fragment rectangle and encoding occupancy bits into a texture [S1, unofficial]. It solves the problem of real-time voxelization by leveraging graphics hardware to test geometry for intersection with an encompassing grid of cells, allowing the tracking of all fragments in a single pass rather than discarding all but the closest [S1, unofficial]. Unlike [Slicemap Boundary Voxelization](3344-slicemap-boundary-voxelization.md), which explicitly maps specific depth slices to specific bit positions, this method encodes depth ranges into occupancy bits, enabling efficient accumulation of all intersecting geometry via bitwise operations [S1, unofficial].

## How it works
**Inputs:** A 3D triangle mesh defined by vertices $P_i = (x_i, y_i, z_i)$ for $i \in \{1, 2, 3\}$.
**Outputs:** A 3D voxel grid where a voxel is marked as occupied if it intersects the triangle.

**Data Structures:**
1.  **Lookup Table Texture:** A 2D texture storing bitmasks.
    *   Standard mode: Size $32 \times 32$. Format RGBA8. Each texel stores 32 bits (one per voxel slice). Index $(z^*_{min}, z^*_{max})$ where $z^* = z \times 32$.
    *   MRT mode: Size $512 \times 128$. Format RGBA8. Stores 128-bit bitmasks across four texels.
2.  **Frame Buffer:** Render targets storing the voxel occupancy. Supports logical 'OR' operations to combine results from multiple triangles.

**Parameters:**
*   $\epsilon_m$: Machine error constant for GPU precision [S1, unofficial].
*   $\epsilon_I$: Threshold for detecting parallel lines and degenerate edges [S1, unofficial].
*   $\epsilon_S$: Threshold for detecting degenerate triangles based on projected area [S1, unofficial].
*   Floating point error constant: $10^{-5}$, added to the computed depth range to address limited GPU precision [S1, unofficial].

**Steps:**

1.  **Vertex Processing (Partial Derivatives):**
    For each vertex $P_i$, compute the barycentric coordinate derivatives and depth derivatives.
    *   Compute signed area $S$ of the projected triangle:
        $$ S = x_1 y_2 - x_2 y_1 + x_2 y_3 - x_3 y_2 + x_3 y_1 - x_1 y_3 $$
    *   Compute barycentric derivatives:
        $$ \frac{\partial \mathbf{C}}{\partial x} = \frac{(y_2 - y_3, y_3 - y_1, y_1 - y_2)}{S} $$
        $$ \frac{\partial \mathbf{C}}{\partial y} = \frac{(x_3 - x_2, x_1 - x_3, x_2 - x_1)}{S} $$
    *   Compute depth derivatives via dot product with vertex depths $z = (z_1, z_2, z_3)$:
        $$ \frac{\partial z}{\partial x} = z \cdot \frac{\partial \mathbf{C}}{\partial x} $$
        $$ \frac{\partial z}{\partial y} = z \cdot \frac{\partial \mathbf{C}}{\partial y} $$
    *   Compute $\Delta \mathbf{C}$ and output $C^* = C(P_i) - \Delta \mathbf{C}$ as a 3D vector. $C^*_{min}$ is obtained via bilinear interpolation during rasterization [S1, unofficial].

2.  **Fragment Processing (Depth Range Calculation):**
    For each fragment covered by the triangle, determine the depth range $[z_{min}, z_{max}]$ of the triangle within the fragment rectangle $R$.
    *   Initialize enlarged width/height of $R$: $x_E, y_E \leftarrow \epsilon_m$ [S1, unofficial].
    *   For each edge $P_i P_j$ of the triangle:
        *   Check for parallelism with horizontal/vertical edges of $R$. If $|\frac{y_j - y_i}{x_j - x_i}| < \max(\epsilon_I, \epsilon_I |x_j - x_i|)$:
            *   Set $a^y_{ij} = 0, b^y_{ij} = 2$ to discard intersections with top/bottom edges $e_T, e_B$.
            *   Update $y_E \leftarrow \max(y_E, \epsilon_I)$.
        *   Else:
            *   Compute coefficients: $a^y_{ij} = \frac{1}{y_j - y_i}$, $b^y_{ij} = \frac{-y_i}{y_j - y_i}$.
        *   Compute $a^x_{ij}, b^x_{ij}$ similarly for vertical comparisons.
    *   Check for degenerate triangle: If $|S| < \epsilon_S$:
        *   Set $C^* \leftarrow (-1, -1, -1)$.
        *   Enlarge $R$: $x_E \leftarrow \max(x_E, \sqrt{2}h)$, $y_E \leftarrow \max(y_E, \sqrt{2}h)$, where $h$ is the minimal triangle height.
    *   Compute intersection points $Q$ between edge $P_i P_j$ and edges of $R$. For edge $e_T$ (top), calculate $t = a^y_{ij} \cdot y_{\max} + b^y_{ij}$ and $Q = \mathcal{L}(P_i, P_j, t)$.
    *   Validate $Q$: If $Q$ lies on both the triangle edge and the fragment edge, set $z(Q) = \mathcal{L}(z_i, z_j, t)$. Otherwise, assign $z(Q)$ a huge value.
    *   Handle parallel case robustness: If $P_i P_j$ is nearly horizontal, replace intersection with top edge $Q_T$ with intersection with prolonged right edge $Q_R$ to avoid numerical instability [S1, unofficial].
    *   Handle degenerate edges: If $|x_j - x_i| < \epsilon_I$ and $|y_j - y_i| < \epsilon_I$, assume both vertices are inside $R$. Check if third vertex $P_k$ is inside $R$ using $x_{min} - \epsilon_I \le x_k \le x_{max} + \epsilon_I$ and $y_{min} - \epsilon_I \le y_k \le y_{max} + \epsilon_I$ [S1, unofficial].
    *   Compute $z_{min}$ and $z_{max}$ as the minimal and maximal depth values among the 12 intersection points (optimized using GPU 4D vector processing) [S1, unofficial].
    *   Apply floating point error correction: $z_{max} \leftarrow z_{max} + 10^{-5}$ [S1, unofficial].

3.  **Voxel Encoding:**
    *   Map $z_{min}, z_{max}$ to indices $z^*_{min} = z_{min} \times 32$ and $z^*_{max} = z_{max} \times 32$.
    *   Perform a texture lookup in the precomputed lookup table to retrieve the bitmask representing occupied voxels.
    *   Write the bitmask to the frame buffer using logical 'OR' to accumulate occupancy from multiple triangles [S1, unofficial].

**Pseudocode:**

def compute_depth_range(vertices, epsilon_I, epsilon_S, epsilon_m):
    """
    Computes the depth range [z_min, z_max] for a triangle within a fragment.
    vertices: list of 3 tuples (x, y, z)
    """
    x1, y1, z1 = vertices[0]
    x2, y2, z2 = vertices[1]
    x3, y3, z3 = vertices[2]
    
    # 1. Compute Signed Area
    S = x1*y2 - x2*y1 + x2*y3 - x3*y2 + x3*y1 - x1*y3
    
    # 2. Handle Degenerate Triangle
    if abs(S) < epsilon_S:
        # Set C* to invalid, enlarge R by sqrt(2)*h
        # h is minimal height of triangle (not given in sources, assumed computed)
        h = compute_minimal_height(vertices)
        return None, None, True # Signal degenerate case for enlargement
    
    # 3. Compute Derivatives
    inv_S = 1.0 / S
    dC_dx = ((y2 - y3) * inv_S, (y3 - y1) * inv_S, (y1 - y2) * inv_S)
    dC_dy = ((x3 - x2) * inv_S, (x1 - x3) * inv_S, (x2 - x1) * inv_S)
    
    z_vec = (z1, z2, z3)
    dz_dx = dot(z_vec, dC_dx)
    dz_dy = dot(z_vec, dC_dy)
    
    # 4. Initialize Enlargement
    xE = epsilon_m
    yE = epsilon_m
    
    # 5. Process Edges for Intersections
    edges = [(vertices[0], vertices[1]), (vertices[1], vertices[2]), (vertices[2], vertices[0])]
    intersection_depths = []
    
    for P_i, P_j in edges:
        xi, yi, zi = P_i
        xj, yj, zj = P_j
        
        # Check for parallel/horizontal edge
        if abs(yj - yi) < max(epsilon_I, epsilon_I * abs(xj - xi)):
            ay_ij = 0
            by_ij = 2
            yE = max(yE, epsilon_I)
        else:
            ay_ij = 1.0 / (yj - yi)
            by_ij = -yi / (yj - yi)
            
        # Compute ax, bx similarly (omitted for brevity, symmetric logic)
        # ax_ij = 1.0 / (xj - xi)
        # bx_ij = -xi / (xj - xi)
        
        # Compute intersections with fragment edges (Top, Bottom, Left, Right)
        # Assuming fragment R bounds are known: x_min, x_max, y_min, y_max
        
        # Intersection with Top Edge (y = y_max)
        t_top = ay_ij * y_max + by_ij
        Q_top = linear_interpolate(P_i, P_j, t_top)
        if is_on_segment(P_i, P_j, Q_top) and is_on_fragment_edge(Q_top, 'top'):
            z_top = linear_interpolate_z(zi, zj, t_top)
            intersection_depths.append(z_top)
        else:
            # Robustness: if nearly horizontal, use Right Edge intersection instead
            # This logic is simplified; full implementation requires checking all 4 edges
            pass
            
        # Intersection with Bottom, Left, Right edges similarly...
        # Note: GPU optimization uses 4D vectors to compute 4 intersections simultaneously
        
    # 6. Determine Min/Max Depth
    if not intersection_depths:
        # Fallback for degenerate or fully inside/outside cases
        # Sources imply using min/max of vertex depths if intersections are invalid
        intersection_depths = [z1, z2, z3]
        
    z_min = min(intersection_depths)
    z_max = max(intersection_depths)
    
    # 7. Apply Floating Point Error Correction
    z_max += 1e-5
    
    return z_min, z_max, False

def encode_voxels(z_min, z_max, lookup_table):
    """
    Encodes voxel occupancy using a lookup table.
    """
    z_star_min = int(z_min * 32)
    z_star_max = int(z_max * 32)
    
    # Lookup bitmask from precomputed texture
    bitmask = lookup_table[z_star_min, z_star_max]
    return bitmask

## Subtopics

### [Slicemap Boundary Voxelization](3344-slicemap-boundary-voxelization.md)
Slicemap Boundary Voxelization is a technique to represent a binary 3D grid of voxels using a single 2D texture, where the $k$-th bit of the RGBA representation of pixel $(i, j)$ encodes the occupancy of voxel $(i, j, k)$. It solves the problem of real-time voxelization by leveraging graphics hardware to test geometry for intersection with an encompassing grid of cells, allowing the tracking of all fragments in a single pass rather than discarding all but the closest. Unlike [Conservative Voxelization via Depth Range](3129-conservative-voxelization-via-depth-range.md), which encodes depth ranges into occupancy bits, slicemaps explicitly map specific depth slices to specific bit positions, enabling efficient accumulation of all intersecting geometry via bitwise operations.

## Operating characteristics
**Time and Memory Complexity:**
The method performs constant-time operations per fragment for derivative calculation and intersection checks, optimized by GPU 4D vector processing. Memory usage is dominated by the lookup table texture ($32 \times 32$ or $512 \times 128$ texels) and the frame buffer.

**Measured Performance:**
Implemented on an AMD AthlonXP 3000+ CPU, 512 MB RAM, and NVidia 6600 GT video card using Cg shaders [S1, unofficial]. The approach achieves conservatively correct results with negligible errors (redundant voxels $\le 0.1\%$ of total) [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Real-time performance via GPU rasterization; conservative correctness ensures no voxels are missed; efficient bitwise encoding allows processing 128 slices in a single pass with MRT [S1, unofficial].
*   **Limitations:** Limited by GPU floating-point precision, requiring error correction constants; alternative pre-computation approaches using lookup tables for intersection codes are faster in theory but expensive in hardware due to switch-case structures [S1, unofficial].

**When to Use:**
Use when real-time voxelization of triangle meshes is required and conservative accuracy is critical. Not suitable when hardware does not support MRT or logical 'OR' blending.

## Background
The method was proposed in a paper titled "Conservative Voxelization" [S1, unofficial]. It builds on the need for efficient, hardware-accelerated voxelization techniques that maintain geometric accuracy. The approach leverages standard graphics pipeline features (vertex processing, rasterization, fragment shaders) to compute depth ranges, avoiding the need for explicit geometric intersection algorithms on the CPU or specialized hardware.
