# GPU Mesh Voxelization via Axis-Aligned Projection

Also called: Dominant Axis Projection, Dominant Axis Projection Voxelization, Dominant Axis Voxelization, GPU Voxelization via Rasterization and Geometry Shader Axis Projection, Voxelization with Dominant Axis Projection

## Overview
GPU Mesh Voxelization via Axis-Aligned Projection converts a triangle mesh into a 3D voxel grid (typically a 3D texture or structured buffer) by projecting each triangle onto a 2D plane aligned with its dominant normal axis, rasterizing it, and writing the resulting fragments into the 3D volume [S1, S2, S3, S8, unofficial]. This method solves the "missing voxel" artifacts common in single-direction rasterization by ensuring that every triangle is viewed from the orientation that maximizes its projected surface area, thereby minimizing gaps caused by edge-on or thin polygons [S1, S11, unofficial]. It differs from [GPU Mesh Voxelization via AABB-Triangle Intersection](2541-gpu-mesh-voxelization-via-aabb-triangle-intersection.md) by relying on hardware rasterization rather than explicit geometric intersection tests, and from [GPU Voxelization Using OpenGL Image Atomics](2544-gpu-voxelization-using-opengl-image-atomics.md) by using a geometry shader to determine projection axes rather than a single fixed view or pure compute shaders [S3, S4, S13, unofficial].

## How it works
**Inputs:** A triangle mesh (vertices, normals, colors) and a target voxel grid resolution $r$ (e.g., $128^3$) and physical scale $s$ (bounding box size) [S2, S11, unofficial].
**Outputs:** A 3D occupancy grid (3D texture or structured buffer) where occupied voxels store color/normal data [S1, S3, unofficial].

**Data Structures:**
1.  **Voxel Storage:** A 3D texture (`RWTexture3D<float4>`) or a structured buffer (`RWStructuredBuffer<Voxel>`) [S3, S9, unofficial].
    *   If 3D texture: RGBA format. RGB stores direct light/color; Alpha stores solidity (0=empty, 1=surface) [S1, unofficial].
    *   If Structured Buffer: Layout depends on implementation, e.g., `struct Voxel { int3 pos; int4 color; }` [S3, unofficial] or a packed `uint` buffer where bits 0-7 are Blue, 8-15 Green, 16-23 Red, 24-31 Luminance [S11, unofficial].
2.  **Constant Buffer:** Contains model-to-projection matrices, grid dimensions ($g\_gridSizeX, Y, Z$), and strides [S4, unofficial].
3.  **Dummy Render Target:** A 2D texture bound as a render target to trigger fragment shader execution, though color writes are disabled [S4, S13, unofficial].

**Steps:**

1.  **Initialization:** Create the 3D voxel texture/buffer and clear it to zero [S1, S4, unofficial]. Configure the GPU pipeline: disable depth testing and depth writes, disable color writes to the dummy render target, and set the viewport to match the lateral resolution of the voxel grid (e.g., $r \times r$) [S4, S10, unofficial].
2.  **Dominant Axis Selection & Projection (Geometry Shader):** For each input triangle, calculate the face normal $\vec{n}$ using the cross product of two edge vectors: $\vec{n} = (\vec{v}_2 - \vec{v}_1) \times (\vec{v}_3 - \vec{v}_1)$ [S1, S8, unofficial]. Determine the dominant axis by finding the component of $\vec{n}$ with the largest absolute magnitude [S2, S7, unofficial]. Rotate the triangle vertices so that the dominant axis aligns with the view direction (typically the Z-axis in clip space) to maximize the projected area on the 2D rasterization plane [S1, S8, unofficial]. Pass the original 3D vertex positions to the fragment shader to allow reconstruction of the 3D position [S2, S11, unofficial].
3.  **Rasterization:** The GPU hardware rasterizer projects the transformed triangle onto the 2D viewport [S10, unofficial]. Because depth testing is disabled, all fragments generated by the triangle are processed [S13, unofficial].
4.  **Voxel Mapping and Writing (Fragment Shader):** For each fragment, compute the 3D world position $\vec{p}$ using the interpolated vertex positions [S2, unofficial]. Calculate the voxel index $\vec{i}$ using the formula: $\vec{i} = \left( \frac{\vec{p}}{s} + 1 \right) \times r$ [S2, unofficial]. Here, $\vec{p}$ is the 3D position, $s$ is the physical scale of the volume (bounding box extent), and $r$ is the resolution [S2, unofficial]. Write the fragment's color and/or normal data to the voxel at index $\vec{i}$ in the 3D texture or structured buffer [S1, S3, unofficial]. Use atomic operations (e.g., `InterlockedMax` or `IncrementCounter`) if writing to a structured buffer to handle concurrent writes [S3, S11, unofficial].

**Pseudocode (Dominant Axis Selection & Projection):**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Input: v1, v2, v3 (float3 vertices)
# Output: projected vertices for rasterization
n = abs(cross(v2 - v1, v3 - v1))
dom_axis = max(n.x, n.y, n.z)

for v in [v1, v2, v3]:
    if dom_axis == n.x:
        v.xyz = v.zyx  # X becomes depth
    elif dom_axis == n.y:
        v.xyz = v.xzy  # Y becomes depth
    else:
        v.xyz = v.xyz  # Z is already depth
```

**Pitfalls and Edge Cases:**
*   **Holes in Thin/Edge-on Polygons:** Standard rasterization may miss thin triangles [S11, unofficial]. Solutions include using Multi-Sample Anti-Aliasing (MSAA, e.g., 8x) on the render target or implementing conservative rasterization by expanding the triangle vertices in the geometry shader [S11, S14, unofficial].
*   **Overwriting Artifacts:** Triangles overlapping in the 2D projection plane will overwrite each other in the volume texture [S2, unofficial]. To mitigate flickering or incorrect colors, use `InterlockedMax` based on luminance to keep the brightest color [S11, unofficial].
*   **Lighting Errors:** If calculating Phong lighting in the fragment shader, use the surface normal *before* the dominant axis rotation, as the rotation changes the normal's orientation relative to the light source [S1, unofficial].
*   **MSAA Interpolation Corruption:** MSAA can corrupt interpolated world position data [S11, unofficial]. Use the `centroid` qualifier on position varyings to ensure accurate position sampling [S11, unofficial].

## Subtopics

### [GPU-based Conservative Voxelization](2580-gpu-based-conservative-voxelization.md)
Uses conservative rasterization hardware to ensure any voxel intersected by a triangle is marked, eliminating missing voxel artifacts without relying solely on dominant axis projection.

### [GPU-based Voxelization via Slice Rendering](10593-gpu-based-voxelization-via-slice-rendering.md)
Projects geometry onto a 3D grid using a slice-by-slice rendering strategy, adjusting Z-near and Z-far planes for each slice.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of triangles, as each triangle is processed once in the geometry shader [S12, S13, unofficial].
*   **Memory Complexity:** $O(r^3)$ for the voxel grid storage, where $r$ is the resolution [S1, S2, unofficial].
*   **Performance:** On mainstream graphics cards, this method can convert millions of triangles into a $256^3$ volume at 10 fps or real-time [S12, unofficial]. A specific implementation on an NVIDIA GTX 770 voxelized a scene at $512^3$ resolution in 11.70 ms [S13, unofficial].
*   **Strengths:** Real-time performance, simple implementation using standard graphics pipeline, avoids complex CPU-side sorting or traversal [S12, S13, unofficial].
*   **Limitations:** Can produce overlapping artifacts if not managed; standard rasterization misses thin polygons without MSAA or conservative rasterization; single-pass dominant axis projection may still leave small gaps compared to multi-pass or conservative methods [S1, S2, S11, unofficial].
*   **When to use:** Real-time global illumination, voxel cone tracing, and volumetric effects where speed is critical and perfect geometric accuracy is secondary [S9, S13, unofficial].
*   **When not to use:** Applications requiring strict 26-separating voxel accuracy or perfect geometric coverage without post-processing [S10, S14, unofficial].

## Background
The method originates from the need for efficient real-time global illumination techniques like Voxel Cone Tracing [S1, unofficial]. It builds on the observation that rasterizing triangles from a single direction leaves gaps, and that rotating triangles to their dominant axis is a computationally cheaper alternative to full 3D rotation matrices [S1, S2, unofficial]. Key references include "Real-Time Global Illumination Using OpenGL And Voxel Cone Tracing" [S1, unofficial], "The beautiful hack of voxelization" [S2, unofficial], and implementations in "GpuPro3Vox" [S4, unofficial] and "Voxel Cone Tracing Metal" [S6, unofficial]. Historical context includes earlier works like "An Accurate Method for Voxelizing Polygon Meshes" by Huang et al. (1998) and "Fast Parallel Surface and Solid Voxelization on GPUs" by Michael et al. (2010) [S14, unofficial].
