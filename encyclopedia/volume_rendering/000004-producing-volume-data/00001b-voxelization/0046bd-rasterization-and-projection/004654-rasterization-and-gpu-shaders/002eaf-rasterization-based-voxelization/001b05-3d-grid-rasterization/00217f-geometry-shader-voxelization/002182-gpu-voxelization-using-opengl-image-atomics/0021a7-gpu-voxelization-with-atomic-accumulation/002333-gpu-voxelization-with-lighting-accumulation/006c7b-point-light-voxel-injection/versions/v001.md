# Point Light Voxel Injection

Also called: Point Light Capture, Point Light Injection

## Overview
Point Light Voxel Injection is a GPU-based method for accumulating indirect diffuse lighting from point lights into a 3D voxel grid, serving as the lighting accumulation step in cone tracing pipelines. It differs from standard geometry voxelization by rendering scene geometry into a depth buffer relative to each point light, then using a compute shader to sample that depth information alongside voxel material properties to inject radiance into the grid. Unlike its parent method which may handle general lighting accumulation, this specific technique is optimized for point light sources by leveraging cube map depth maps for occlusion-aware radiance injection.

## How it works

### Inputs and Outputs
**Inputs:**
*   Scene geometry (vertices, indices, normals, UVs).
*   Voxel grid data: Albedo texture, Normal texture, and Radiance texture (read-write).
*   Point light parameters: Position, color, attenuation cutoff.
*   Voxel grid resolution ($m\_PointLightInjectionRes$).
*   Compute shader group size ($m\_LightInjectionGroupSize$).

**Outputs:**
*   Updated Voxel Radiance texture (3D texture, format `GL_R32UI`).

### Data Structures and Layouts

**Uniform Buffer Layout (Point Light Capture):**
The uniform buffer stores transformation matrices and light parameters. The layout is defined as follows:
*   Offset 0: `glm::mat4` array of size 6 (Light view matrices for the 6 faces of the cube map).
*   Offset $6 \times 16$ bytes: `glm::mat4` (Projection matrix).
*   Offset $7 \times 16$ bytes: `glm::vec4` (Light position).
*   Offset $7 \times 16 + 16$ bytes: `glm::vec2` (Capture range: near and far planes).

**Texture Bindings:**
*   **Voxel Albedo:** Read-only image texture.
*   **Voxel Normal:** Read-only image texture.
*   **Voxel Radiance:** Read-write image texture with format `GL_R32UI`. Bound at binding point `BINDING_POINT_START_VOXEL_IMG + VoxelChannel::TexVoxelRadiance`.
*   **Cube Depth Map:** Texture unit 0. Stores depth values from the geometry rasterization pass relative to the point light.

### Parameters
*   **Attenuation Cutoff ($atten\_cutoff$):** Threshold used to compute the point light cutoff radius. Value: `0.05f` [S1, unofficial].
*   **Capture Range:** Near and far planes for the light's cube map frustum. Value: `(0.1f, range\_far)`, where `range_far` is derived from the attenuation cutoff [S1, unofficial].

### Algorithm Steps

1.  **Iterate Active Lights:** Loop over all active point lights in the scene.
2.  **Setup Depth FBO:** For the current light, bind a Framebuffer Object (FBO) and its associated cube depth map.
3.  **Compute Cutoff:** Calculate the light's cutoff radius using the attenuation threshold ($0.05f$).
4.  **Setup Frustum:** Set the capture range to $(0.1f, cutoff)$. Generate 6 view matrices (one for each face of the cube map) and a projection matrix.
5.  **Upload Uniforms:** Upload the 6 view matrices, projection matrix, light position, and capture range to the uniform buffer.
6.  **Clear Depth:** Clear the depth buffer of the FBO.
7.  **Render Geometry:** Render the scene geometry using the point light's view and projection matrices. This populates the cube depth map with depth values from the perspective of the light.
8.  **Bind Textures:**
    *   Bind Voxel Albedo and Normal textures as read-only image textures.
    *   Bind Voxel Radiance texture as a read-write image texture (`GL_R32UI`).
    *   Bind the Cube Depth map to texture unit 0.
9.  **Set Compute Uniforms:** Set uniforms for light position, light color, and the current light pass index.
10. **Dispatch Compute Shader:** Dispatch the compute shader with grid dimensions calculated as $\lceil m\_PointLightInjectionRes / m\_LightInjectionGroupSize \rceil$.
11. **Barrier:** Issue a `GL_SHADER_IMAGE_ACCESS_BARRIER_BIT` to ensure memory consistency.

### Pseudocode

```python
def point_light_voxel_injection(scene_geometry, voxel_albedo, voxel_normal, voxel_radiance, 
                                point_lights, grid_resolution, group_size, atten_cutoff=0.05f):
    """
    Accumulates point light radiance into a 3D voxel grid.
    
    Args:
        scene_geometry: List of meshes with positions, normals, indices.
        voxel_albedo: Read-only 3D texture for albedo.
        voxel_normal: Read-only 3D texture for normals.
        voxel_radiance: Read-write 3D texture (GL_R32UI) for radiance accumulation.
        point_lights: List of point light objects (position, color, intensity).
        grid_resolution: Resolution of the voxel grid (m_PointLightInjectionRes).
        group_size: Compute shader group size (m_LightInjectionGroupSize).
        atten_cutoff: Attenuation threshold (default 0.05f).
    """
    
    for light in point_lights:
        # 1. Compute cutoff radius based on attenuation threshold
        # Note: Exact formula for range_far from atten_cutoff is not provided in sources [G]
        # Assuming standard inverse square law cutoff or similar heuristic
        cutoff_radius = compute_cutoff_radius(light.intensity, atten_cutoff)
        
        # 2. Setup capture range
        near_plane = 0.1f
        far_plane = cutoff_radius
        capture_range = vec2(near_plane, far_plane)
        
        # 3. Generate cube map matrices
        # Generate 6 view matrices for the 6 faces of the cube map
        view_matrices = generate_cube_view_matrices(light.position, capture_range)
        projection_matrix = generate_perspective_projection_matrix(capture_range)
        
        # 4. Setup Depth FBO and Render Geometry
        depth_fbo = create_depth_fbo(cube_map_size)
        bind_fbo(depth_fbo)
        clear_depth_buffer()
        
        for mesh in scene_geometry:
            set_view_projection(view_matrices, projection_matrix, light.position)
            render_mesh(mesh)
        
        unbind_fbo()
        
        # 5. Bind Textures for Compute Shader
        # Bind voxel textures
        bind_image_texture(voxel_albedo, binding=ALBEDO_BINDING, access=READ_ONLY)
        bind_image_texture(voxel_normal, binding=NORMAL_BINDING, access=READ_ONLY)
        
        # Bind radiance texture as read-write
        # Format must be GL_R32UI
        bind_image_texture(voxel_radiance, 
                           binding=BINDING_POINT_START_VOXEL_IMG + VoxelChannel::TexVoxelRadiance, 
                           access=READ_WRITE, 
                           format=GL_R32UI)
        
        # Bind cube depth map to texture unit 0
        bind_texture(depth_fbo.cube_map, texture_unit=0)
        
        # 6. Set Compute Shader Uniforms
        set_uniform("u_ViewMatrices", view_matrices)
        set_uniform("u_ProjectionMatrix", projection_matrix)
        set_uniform("u_LightPosition", light.position)
        set_uniform("u_CaptureRange", capture_range)
        set_uniform("u_LightColor", light.color)
        set_uniform("u_LightPassIndex", current_light_index)
        
        # 7. Dispatch Compute Shader
        # Grid dimensions: ceil(grid_resolution / group_size)
        dispatch_count = ceil(grid_resolution / group_size)
        dispatch_compute_shader(dispatch_count, dispatch_count, dispatch_count)
        
        # 8. Memory Barrier
        gl_shader_image_access_barrier()
```

### Edge Cases and Pitfalls
*   **Precision:** The radiance texture uses `GL_R32UI` (unsigned 32-bit integer). This limits the dynamic range and precision of accumulated radiance. Overflow may occur if light intensities are high or if many lights contribute to the same voxel. [S1, unofficial]
*   **Boundaries:** The capture range is fixed at `(0.1f, cutoff)`. Geometry closer than 0.1f to the light may be clipped or cause depth precision issues. [S1, unofficial]
*   **Degenerate Input:** If a point light has zero intensity or invalid position, the cutoff radius calculation may fail or produce undefined behavior. [G]

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** $O(L \cdot N)$, where $L$ is the number of point lights and $N$ is the number of voxels (or grid cells) processed by the compute shader. The rasterization step is $O(V)$, where $V$ is the number of vertices, per light.
*   **Memory Complexity:** $O(V_{ox})$, where $V_{ox}$ is the volume of the voxel grid. The depth buffer requires $O(C \cdot R^2)$ memory per light, where $C$ is the cube map resolution and $R$ is the grid resolution.

### Measured Performance
*   Not given in the sources.

### Scaling
*   Scales linearly with the number of point lights.
*   Scales with the cube of the voxel grid resolution.

### Strengths and Limitations
*   **Strengths:** Efficiently captures indirect diffuse lighting from point lights using GPU parallelism. Leverages existing rasterization hardware for depth testing.
*   **Limitations:** Only captures diffuse lighting. Specular lighting is not handled. Limited by the precision of `GL_R32UI`. Performance degrades with high voxel resolutions and many lights.

### When to Use
*   Use when real-time indirect diffuse lighting from point lights is required and cone tracing is the chosen rendering technique.
*   Not suitable for specular lighting or global illumination involving complex bounces beyond the first indirect diffuse pass.

## Background

### Origin
The method is implemented in the "HarshLight" project by MangoSister. It is part of a larger voxelization and cone tracing pipeline.

### History and Development
The technique is described in the source code of the HarshLight repository. It appears to be an implementation detail of a custom renderer rather than a widely published academic algorithm.

### Where It Is Used
Used in the HarshLight renderer for voxelizing scene lighting for cone tracing.
