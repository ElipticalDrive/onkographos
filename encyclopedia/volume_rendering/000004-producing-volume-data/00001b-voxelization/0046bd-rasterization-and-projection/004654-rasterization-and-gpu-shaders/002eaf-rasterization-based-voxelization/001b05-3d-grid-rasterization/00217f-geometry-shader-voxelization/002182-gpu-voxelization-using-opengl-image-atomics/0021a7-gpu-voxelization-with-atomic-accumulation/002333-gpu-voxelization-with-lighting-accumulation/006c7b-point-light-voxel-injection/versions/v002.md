# Point Light Voxel Injection

Also called: Point Light Capture, Point Light Injection

## Overview
Point Light Voxel Injection accumulates point light radiance into a 3D voxel grid by rendering scene geometry to a depth buffer, then dispatching a compute shader that reads voxel albedo/normal/radiance textures and the light's cube depth map to inject lighting data [S1, unofficial]. It differs from standard geometry voxelization by leveraging cube map depth maps for occlusion-aware radiance injection relative to each point light [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   Scene geometry (vertices, indices, normals, UVs) [S1, unofficial].
*   Voxel grid data: Albedo texture, Normal texture, and Radiance texture (read-write) [S1, unofficial].
*   Point light parameters: Position, color, and attenuation cutoff ($0.05f$) [S1, unofficial].
*   Voxel grid resolution ($m\_PointLightInjectionRes$) and compute shader group size ($m\_LightInjectionGroupSize$) [S1, unofficial].

**Outputs:**
*   Updated Voxel Radiance texture (3D texture, format `GL_R32UI`) [S1, unofficial].

### Data Structures and Layouts

**Uniform Buffer Layout (Point Light Capture):**
The uniform buffer stores transformation matrices and light parameters [S1, unofficial].
*   Offset 0: `glm::mat4` array of size 6 (Light view matrices for the 6 faces of the cube map).
*   Offset $6 \times 16$ bytes: `glm::mat4` (Projection matrix).
*   Offset $7 \times 16$ bytes: `glm::vec4` (Light position).
*   Offset $7 \times 16 + 16$ bytes: `glm::vec2` (Capture range: near and far planes) [S1, unofficial].

**Texture Bindings:**
*   **Voxel Albedo:** Read-only image texture [S1, unofficial].
*   **Voxel Normal:** Read-only image texture [S1, unofficial].
*   **Voxel Radiance:** Read-write image texture with format `GL_R32UI`, bound at `BINDING_POINT_START_VOXEL_IMG + VoxelChannel::TexVoxelRadiance` [S1, unofficial].
*   **Cube Depth Map:** Bound to texture unit 0, storing depth values from the geometry rasterization pass relative to the point light [S1, unofficial].

### Parameters
*   **Attenuation Cutoff ($atten\_cutoff$):** Threshold used to compute the point light cutoff radius. Value: `0.05f` [S1, unofficial].
*   **Capture Range:** Near and far planes for the light's cube map frustum. Value: `(0.1f, range_far)`, where `range_far` is computed from the attenuation cutoff [S1, unofficial].

### Algorithm Steps

1.  **Iterate Active Lights:** Loop over all active point lights in the scene [S1, unofficial].
2.  **Setup Depth FBO:** For the current light, bind a depth FBO and its associated cube depth map [S1, unofficial].
3.  **Compute Cutoff:** Calculate the light's cutoff radius using the attenuation threshold ($0.05f$) [S1, unofficial].
4.  **Setup Frustum:** Set the capture range to $(0.1f, cutoff)$ [S1, unofficial].
5.  **Generate Matrices:** Generate 6 cube map view matrices and a projection matrix [S1, unofficial].
6.  **Upload Uniforms:** Upload the 6 view matrices, projection matrix, light position, and capture range to the uniform buffer [S1, unofficial].
7.  **Clear Depth:** Clear the depth buffer of the FBO [S1, unofficial].
8.  **Render Geometry:** Render scene geometry for the point light injection pass [S1, unofficial].
9.  **Bind Textures:** Bind voxel albedo and normal textures as read-only image textures [S1, unofficial]. Bind the voxel radiance texture as a read-write image texture with format `GL_R32UI` [S1, unofficial]. Bind the cube depth map to texture unit 0 [S1, unofficial].
10. **Set Compute Uniforms:** Set light position, color, and current light pass index uniforms [S1, unofficial].
11. **Dispatch Compute Shader:** Dispatch the compute shader with grid dimensions $\lceil m\_PointLightInjectionRes / m\_LightInjectionGroupSize \rceil$ [S1, unofficial].
12. **Barrier:** Issue a `GL_SHADER_IMAGE_ACCESS_BARRIER_BIT` [S1, unofficial].

```python
    for light in point_lights:

        # Set capture range to (0.1, cutoff)
        capture_range = (0.1, 1.0)  # Placeholder value for missing formula [G]

        # Generate 6 view matrices and 1 projection matrix for cube map (not provided in sources) [G]

        projection_matrix = None

        # Setup Depth FBO and Render Geometry
        depth_fbo = create_depth_fbo()
        bind_fbo(depth_fbo)
        clear_depth_buffer()
        for mesh in scene_geometry:

        unbind_fbo()

        bind_image_texture(voxel_albedo, access=READ_ONLY)
        bind_image_texture(voxel_normal, access=READ_ONLY)
        # Format must be GL_R32UI, bound at specific binding point [S1, unofficial]
        bind_image_texture(voxel_radiance,
                           binding=BINDING_POINT_START_VOXEL_IMG + TEX_VOXEL_RADIANCE,
                           access=READ_WRITE,
                           format=GL_R32UI)
        bind_texture(depth_fbo.cube_map, texture_unit=0)

        # Set Compute Shader Uniforms
        set_uniform("u_ViewMatrices", view_matrices)
        set_uniform("u_ProjectionMatrix", projection_matrix)
        set_uniform("u_LightPosition", light.position)
        set_uniform("u_CaptureRange", capture_range)
        set_uniform("u_LightColor", light.color)
        set_uniform("u_LightPassIndex", current_light_index)

        # Dispatch Compute Shader
        dispatch_count = math.ceil(grid_resolution / group_size)
        dispatch_compute_shader(dispatch_count, dispatch_count, dispatch_count)

        # Memory Barrier
        gl_shader_image_access_barrier()
```

### Edge Cases and Pitfalls
*   **Boundaries:** The capture range is fixed at `(0.1f, cutoff)`. Geometry closer than 0.1f to the light may be clipped or cause depth precision issues [G].
*   **Degenerate Input:** If a point light has zero intensity or invalid position, the cutoff radius calculation may fail or produce undefined behavior [G].

### Strengths and Limitations
*   **Strengths:** Efficiently captures indirect diffuse lighting from point lights using GPU parallelism [S1, unofficial].
*   **Limitations:** Approximates only indirect diffuse lighting, not specular [Parent]. Limited by the precision of `GL_R32UI` [S1, unofficial].

### When to Use
*   Use when real-time indirect diffuse lighting from point lights is required and cone tracing is the chosen rendering technique [G].
*   Not suitable for specular lighting or global illumination involving complex bounces beyond the first indirect diffuse pass [Parent].
