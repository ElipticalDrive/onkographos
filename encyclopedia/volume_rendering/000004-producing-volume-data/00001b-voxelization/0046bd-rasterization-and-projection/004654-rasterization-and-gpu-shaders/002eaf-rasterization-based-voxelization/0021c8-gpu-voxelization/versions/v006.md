# GPU Voxelization
Also called: Basic GPU Voxelization, GPU Rasterization-based Voxelization, GPU Voxelization via GPU Rasterization, GPU Voxelization via Orthogonal Rasterization, GPU-based Voxelization, Voxelization using 3D Texture UAV, Voxelization via GPU Rasterization

## Overview
GPU Voxelization converts a triangle mesh into a regular voxel grid by leveraging the GPU's hardware rasterization pipeline to map fragments directly to 3D grid cells [S1, S3, S5, unofficial]. It solves the performance bottleneck of CPU-based ray-tracing voxelization by parallelizing the rasterization process across the GPU [S5, unofficial]. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by writing directly to a 3D texture UAV or SSBO instead of a 2D accumulation buffer [S3, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Triangle mesh vertices, voxel grid resolution ($W, H, D$), voxel step size (edge length), and projection parameters [S5, unofficial].
- Output: A voxel grid (3D texture or SSBO) marking occupied cells, or a list of voxel coordinates [S3, S5, unofficial].

**Data Structures:**
- **Voxel Grid:** A 3D texture bound as an Unordered Access View (UAV) [S3, unofficial] or a 1D Shader Storage Buffer Object (SSBO) `int cnts[]` of size $W \times H \times D$ [S5, unofficial].
- **Projection Matrices:** Orthographic projection matrices mapping world space to clip space $[-1, 1]^2 \times [0, 1]$ and then to voxel space $[0, W] \times [0, H] \times [0, D]$ [S1, unofficial].

**Steps:**
1. **Compute AABB:** Iterate over mesh vertices to find min/max $x, y, z$ to determine the Axis-Aligned Bounding Box (AABB) [S5, unofficial].
2. **Calculate Resolution:** Compute grid dimensions: $W = \lfloor (max_x - min_x) / step \rfloor + 1$, similarly for $H, D$ [S5, unofficial].
3. **Setup Render State:** Disable depth testing and back-face culling to ensure all triangles are processed regardless of orientation [S3, S5, unofficial].
4. **Rasterize:** Render the mesh using an orthographic camera aligned with a voxel grid axis. The viewport dimensions match the 2D projection of the voxel grid [S3, unofficial].
5. **Fragment Processing:** In the Pixel/Fragment Shader, map the fragment's position to voxel coordinates and write data to the grid using atomic operations [S3, S5, unofficial].

**Formulas:**
- **Voxel Index (SSBO):** $index = y \times (D \times W) + z \times W + x$ [S5, unofficial].
- **Voxel Coordinates:** $x = \lfloor (FragPos.x - min_x) / step \rfloor$, $y = \lfloor (FragPos.y - min_y) / step \rfloor$, $z = \lfloor (FragPos.z - min_z) / step \rfloor$ [S5, unofficial].
- **Homogeneous Mapping:** After applying the voxel-space projection matrix, divide $x, y, z$ by $w$ to get cell coordinates [S1, unofficial].
- **CPU Read-back:** Given linear index $x$, $iy = x / (W \times D)$, $iz = (x - iy \times W \times D) / W$, $ix = x - iy \times W \times D - iz \times W$ [S5, unofficial].

**Parameters:**
- `step`: Voxel edge length determining resolution. Typical value depends on scene scale [S5, unofficial].
- `projection_matrix`: Orthographic matrix mapping world to clip space $[-1, 1]^2 \times [0, 1]$ [S1, unofficial].

**Pseudocode:**
```python
def voxelize_mesh(vertices, step, grid_dims):
    W, H, D = grid_dims
    # 1. Compute AABB
    box_min = vec3(min(v.x for v in vertices), min(v.y for v in vertices), min(v.z for v in vertices))
    box_max = vec3(max(v.x for v in vertices), max(v.y for v in vertices), max(v.z for v in vertices))

    # 2. Initialize SSBO/UAV
    ssbo = [0] * (W * H * D)

    # 3. Setup orthographic projection & viewport
    # Projection maps world to clip space [-1,1]^2 x [0,1]
    # Viewport matches 2D projection of voxel grid [S3, unofficial]

    # 4. Rasterize & Fragment Processing
    # [G] Standard GPU rasterization step generates fragments for each triangle
    for frag in hardware_rasterize(vertices):
        # Map fragment world position to voxel indices
        x = int((frag.pos.x - box_min.x) / step)
        y = int((frag.pos.y - box_min.y) / step)
        z = int((frag.pos.z - box_min.z) / step)

        # Clamp to grid bounds
        x = max(0, min(x, W - 1))
        y = max(0, min(y, H - 1))
        z = max(0, min(z, D - 1))

        # Calculate linear index
        index = y * (D * W) + z * W + x

        # Atomic write to SSBO
        ssbo[index] += 1

    # 5. Read back occupied voxels
    occupied = []
    for idx in range(W * H * D):
        if ssbo[idx] > 0:
            iy = idx // (W * D)
            iz = (idx - iy * W * D) // W
            ix = idx - iy * W * D - iz * W
            occupied.append(box_min + vec3(ix * step, iy * step, iz * step))
    return occupied
```

**Edge Cases and Pitfalls:**
- **Cracks:** Occur when triangle slope is steep relative to view direction (depth gradient > 1.0) [S3, unofficial].
- **Holes:** Occur if primitives are projected in a direction where no pixel centers are covered [S3, unofficial].
- **Extra Voxels:** Manual conservative rasterization (edge expansion) may shade extra pixels [S3, unofficial].
- **Mitigation:** Use multi-view projection based on face normals [S5, unofficial] or enable 8xMSAA to approximate conservative rasterization without edge expansion [S3, unofficial].

## Subtopics

### [VoxelPipe](2797-voxelpipe.md)
VoxelPipe is a highly flexible, programmable software pipeline for triangle voxelization implemented in CUDA. It distinguishes itself from prior binary voxelizers by supporting arbitrary framebuffer types and programmability via vertex and fragment shaders, tackling load balancing via a tile-based algorithm instead of assigning individual triangles to single threads with global memory atomics, and optimizing the triangle/box overlap test. Choose it when arbitrary render targets and custom shaders are required. [VoxelPipe](2797-voxelpipe.md)

### [Conservative Rasterization](2936-conservative-rasterization.md)
This method prevents holes in voxelized geometry caused by triangles smaller than the voxel grid resolution by rasterizing all fragments that "touch" the triangle. It achieves this by analytically expanding the triangle in clip space before rasterization, ensuring that any voxel potentially intersected by the triangle is covered. Unlike hardware conservative rasterization (limited to NVIDIA) or Multi-Sample Anti-Aliasing (MSAA) activation, this geometric approach is hardware-agnostic but computationally more intensive, requiring a geometry shader for the expansion logic. Choose it when exact geometric coverage is required without MSAA overhead. [Conservative Rasterization](2936-conservative-rasterization.md)

## Operating characteristics
- **Memory Complexity:** $O(W \cdot H \cdot D)$ for the voxel grid [S5, unofficial].
- **Performance:** Extremely fast due to GPU parallelism, significantly faster than CPU ray-tracing [S5, unofficial].
- **Strengths:** High throughput, leverages existing graphics hardware [S5, unofficial].
- **Limitations:** Memory intensive for high resolutions; prone to cracks/holes without conservative rasterization or multi-view [S3, S5, unofficial].
- **When to Use:** Real-time applications requiring fast mesh-to-voxel conversion [S5, unofficial].
- **Time Complexity:** Not given in the sources.
- **When Not to Use:** Not given in the sources.

## Background
Originated from the need for efficient voxelization for position-based dynamics physics simulations [S5, unofficial] and real-time ray tracing [S1, unofficial]. Based on approaches by Michael Schwarz [S1, unofficial] and NVIDIA [S3, S5, unofficial]. Used in real-time ray tracing, position-based dynamics, and voxel cone tracing [S1, S4, S5, unofficial].
