# Single-Pass Voxelization

Also called: Axis-Aligned Voxelization, Dynamic Voxelization, One pass voxelization pipeline, Thin surface voxelization

## Overview
Single-Pass Voxelization is a GPU-based method that converts triangle meshes into a sparse voxel representation in a single rendering pass by leveraging the geometry shader for axis selection and conservative rasterization for coverage [S1, S2, unofficial]. It distinguishes itself from sibling methods by eliminating the need for multiple draw calls per object (via geometry shaders) and avoiding plain grid allocations (via sparse structures), making it suitable for dynamic scenes where objects are added at runtime [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Triangle mesh data (vertices, normals) and a sparse voxel data structure (e.g., sparse octree or hash table) [S1, S2, unofficial].
*   **Output:** Occupied voxels with attributes (position, color, normal) written to a 3D surface or texture [S2, unofficial].

**Data Structures:**
*   **Sparse Voxel Structure:** No plain grid allocation; uses a sparse octree or hash map to store only occupied voxels [S2, unofficial].
*   **Render Target:** An MSAA (Multi-Sample Anti-Aliasing) render target is required to prevent incorrect filling of empty cells [S1, unofficial].

**Steps:**
1.  **Dominant Axis Selection:** For each input triangle, the geometry shader calculates the projection of the triangle's normal onto the X, Y, and Z axes and selects the axis with the largest absolute projection value as the dominant axis [S1, S2, unofficial].
2.  **Triangle Projection:** The triangle is projected onto the 2D plane perpendicular to the dominant axis [S2, unofficial].
3.  **Edge Shifting:** The edges of the projected triangle are shifted outward to account for voxel grid alignment, ensuring full coverage of intersected voxels [S2, unofficial].
4.  **Hardware Setup/Rasterization:** The rasterizer processes the shifted triangle using conservative rasterization, generating fragments for all pixels that have any overlap with the triangle rather than only those whose centers are covered [S1, S2, unofficial].
5.  **Fragment Shader Execution:** For each generated fragment, the fragment shader computes thin surface voxelization attributes and writes them to a 3D surface [S2, unofficial].
6.  **Sparse Octree Construction:** A post-processing step organizes voxels into a hierarchical structure via top-down subdivision and value MIP-mapping [S2, unofficial].

**Formulas:**
*   **Dominant Axis Selection:** Let $\mathbf{n} = (n_x, n_y, n_z)$ be the triangle normal. The dominant axis $A$ is:
    $$ A = \arg \max_{i \in \{x,y,z\}} |n_i| $$
*   **Conservative Rasterization Condition:** A fragment is generated for a pixel $p$ if the triangle $T$ intersects the pixel's coverage area, rather than just the pixel center [S1, unofficial].

**Parameters:**
*   **Hardware Support:** Requires hardware conservative rasterization support, available on Nvidia Maxwell architecture and later [S1, unofficial]. RTX driver support is available for Turing and Pascal architectures [S1, unofficial].
*   **Performance:** Dynamic objects are added at runtime in ~4-5ms, while static environments are pre-voxelized in ~20ms [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Cracks:** Without conservative rasterization, GPUs only generate fragments if a pixel's center is covered, leading to small cracks at triangle edges [S1, unofficial].
*   **Over-filling:** Conservative rasterization generates too many fragments, incorrectly filling cells that should be empty [S1, unofficial]. This is mitigated by using an MSAA render target [S1, unofficial].

**Pseudocode:**
```python
def geometry_shader(triangle):
    v0, v1, v2 = triangle.vertices
    normal = normalize(cross(v1 - v0, v2 - v0))
    abs_normal = abs(normal)
    if abs_normal.x >= abs_normal.y and abs_normal.x >= abs_normal.z:
        dominant_axis = 'x'
    elif abs_normal.y >= abs_normal.x and abs_normal.y >= abs_normal.z:
        dominant_axis = 'y'
    else:
        dominant_axis = 'z'
    projected = project_2d(triangle, dominant_axis)
    shifted = shift_edges(projected)
    yield shifted

def project_2d(triangle, axis):
    if axis == 'x':
        return Triangle([(0, v[1], v[2]) for v in triangle.vertices])
    elif axis == 'y':
        return Triangle([(v[0], 0, v[2]) for v in triangle.vertices])
    else:
        return Triangle([(v[0], v[1], 0) for v in triangle.vertices])

def shift_edges(triangle):
    # Expand triangle bounds to cover adjacent grid cells
    xs = [v[0] for v in triangle.vertices]
    ys = [v[1] for v in triangle.vertices]
    zs = [v[2] for v in triangle.vertices]
    min_v = (min(xs) - 0.5, min(ys) - 0.5, min(zs) - 0.5)
    max_v = (max(xs) + 0.5, max(ys) + 0.5, max(zs) + 0.5)
    return Triangle([min_v, max_v, (min_v[0], max_v[1], min_v[2])])

def compute_voxel_position(fragment):
    # Map fragment screen coordinates to voxel grid indices
    return (int(fragment.screen_x * grid_width), int(fragment.screen_y * grid_height), fragment.depth)

def compute_color(fragment):
    # Barycentric interpolation of vertex colors
    return fragment.barycentric[0] * fragment.color0 + fragment.barycentric[1] * fragment.color1 + fragment.barycentric[2] * fragment.color2

def fragment_shader(fragment):
    voxel_pos = compute_voxel_position(fragment)
    voxel_color = compute_color(fragment)
    # Conceptual atomic write to sparse structure
    sparse_voxels[voxel_pos] = voxel_color
```

## Subtopics

### Anisotropic Voxelization
Encodes directional data in voxels instead of isotropic data, improving quality when view-dependent changes occur. Choose when directional lighting or material properties vary significantly with viewing angle. [Link](908-anisotropic-voxelization.md) [S1, unofficial].

### Sparse Octree Construction
Post-processing step that organizes flat voxel data into a hierarchical tree structure via top-down subdivision and value MIP-mapping. Choose when hierarchical traversal or compression is required. [Link](908-sparse-octree-construction.md) [S2, unofficial].

## Operating characteristics
*   **Performance:** Dynamic objects are added at runtime in ~4-5ms, while static environments are pre-voxelized in ~20ms [S2, unofficial].
*   **Strengths:** Reduces draw calls via geometry shaders, supports dynamic scene updates, and avoids plain grid memory overhead through sparse allocation [S1, S2, unofficial].
*   **Limitations:** Requires hardware conservative rasterization (Nvidia Maxwell architecture and later), incurs MSAA overhead, and risks over-filling empty cells without MSAA [S1, unofficial].
*   **When to Use:** Real-time applications with dynamic scenes requiring efficient, single-pass voxelization [S2, unofficial].
*   **When Not to Use:** Hardware lacking conservative rasterization support, or when exact voxel coverage is critical and MSAA cannot be used, as conservative rasterization inherently over-fills empty cells [S1, unofficial].

## Background
Single-Pass Voxelization was introduced as part of the Voxel Cone Tracing pipeline for real-time indirect illumination [S2, unofficial]. It was developed to address the inefficiencies of previous voxelization methods that required multiple passes or draw calls [S1, unofficial]. The method leverages advancements in GPU hardware, specifically conservative rasterization, to achieve efficient and accurate voxelization [S1, unofficial].
