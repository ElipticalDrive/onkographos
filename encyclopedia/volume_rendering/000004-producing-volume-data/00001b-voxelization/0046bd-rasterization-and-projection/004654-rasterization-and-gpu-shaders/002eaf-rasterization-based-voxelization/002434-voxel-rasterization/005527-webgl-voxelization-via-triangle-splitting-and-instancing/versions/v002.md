# WebGL Voxelization via Triangle Splitting and Instancing

Also called: Triangle Splitting Voxelization, WebGL Voxelizer

## Overview
A method to calculate the distance field of a mesh in real-time on WebGL by converting mesh triangles into small points (particles) that fit within voxels, using instancing to handle adjacent voxels and depth testing to simulate atomic minimum-distance updates [S1, unofficial]. It sets itself apart from GPU-native voxelization methods by avoiding compute shaders and atomic operations, which are unavailable in WebGL, by instead leveraging the rasterization pipeline, instancing, and depth buffering [S1, unofficial]. It builds on [Voxel Rasterization](3204-voxel-rasterization.md).

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle mesh [S1, unofficial].
*   **Output:** A 3D distance field stored in a 2D texture (simulating 3D data) [S1, unofficial].

**Data Structures:**
*   **Small Triangles Buffer:** Contains triangles split until they meet a size threshold [S1, unofficial].
*   **Big Triangles Buffer:** Contains triangles that exceed the threshold but are below a secondary threshold [S1, unofficial].
*   **Distance Texture:** A 2D texture where each texel stores the minimum distance to the mesh [S1, unofficial].

**Steps:**

1.  **Triangle Splitting (CPU):**
    *   Split the original mesh triangles on the CPU until they meet a size threshold [S1, unofficial].
    *   Separate triangles that are still too large ("big triangles") into a different buffer. The threshold for "big" is a secondary, larger threshold [S1, unofficial].
    *   *Rationale:* CPU splitting is preferred over GPU splitting to avoid excessive memory usage and triangle generation for meshes with varying triangle sizes [S1, unofficial].

2.  **Small Triangle Voxelization (Vertex Shader + Instancing):**
    *   Launch a draw call with points, where the number of points equals the number of small triangles [S1, unofficial].
    *   In the vertex shader, use `gl_VertexID` to read the three vertices of the triangle from a texture [S1, unofficial].
    *   Calculate the average position of the three vertices to define the center voxel [S1, unofficial].
    *   Use instancing (`gl_InstanceID`) to iterate over 27 instances representing the center voxel and its 26 adjacent neighbors in 3D [S1, unofficial].
    *   For each instance, calculate the offset from the center voxel and compute the distance from the triangle to that specific voxel [S1, unofficial].
    *   Map the 3D voxel position to a 2D texture coordinate and write the distance, using the depth test to ensure only the minimum distance is saved [S1, unofficial].

3.  **Big Triangle Voxelization (Fragment Shader):**
    *   For big triangles, execute a fragment shader pass that evaluates the distance field for all voxels in the texture for up to 64 big triangles [S1, unofficial].
    *   Update the texture with the minimum distance via depth testing [S1, unofficial].

**Pseudocode:**

```python
import math

class Triangle:
    def __init__(self, v0, v1, v2):
        self.v0 = v0
        self.v1 = v1
        self.v2 = v2
        # Placeholder for area calculation; in practice computed from vertex positions
        self.area = 0.0 

def split_mesh(mesh, small_threshold, big_threshold):
    small_triangles = []
    big_triangles = []
    for tri in mesh.triangles:
        if tri.area > big_threshold:
            big_triangles.append(tri)
        elif tri.area > small_threshold:
            split_triangle_recursive(tri, small_threshold, small_triangles)
        else:
            small_triangles.append(tri)
    return small_triangles, big_triangles

def split_triangle_recursive(tri, threshold, result_list):
    if tri.area <= threshold:
        result_list.append(tri)
        return
    mid0 = (tri.v0 + tri.v1) / 2.0
    mid1 = (tri.v1 + tri.v2) / 2.0
    mid2 = (tri.v2 + tri.v0) / 2.0
    split_triangle_recursive(Triangle(tri.v0, mid0, mid2), threshold, result_list)
    split_triangle_recursive(Triangle(tri.v1, mid1, mid0), threshold, result_list)
    split_triangle_recursive(Triangle(tri.v2, mid2, mid1), threshold, result_list)
    split_triangle_recursive(Triangle(mid0, mid1, mid2), threshold, result_list)

def read_triangle_from_texture(texture, vertex_id):
    # Simulates reading triangle vertices from a texture buffer using gl_VertexID [G]
    return texture.triangle_buffer[vertex_id]

def get_neighbor_offset(instance_id, voxel_size):
    # Maps 0-26 to a 3x3x3 grid offset centered at (0,0,0)
    dx = (instance_id % 3) - 1
    dy = ((instance_id // 3) % 3) - 1
    dz = (instance_id // 9) - 1
    return (dx * voxel_size, dy * voxel_size, dz * voxel_size)

def distance_triangle_to_voxel(v0, v1, v2, voxel_pos):
    # Standard point-to-triangle distance calculation [G]
    e1 = v1 - v0
    e2 = v2 - v0
    n = cross(e1, e2)
    d = dot(v0 - voxel_pos, n) / dot(n, n)
    proj = voxel_pos + d * n
    return math.dist(voxel_pos, proj)

def map_3d_to_2d(pos, width, depth):
    # Standard 3D-to-2D texture coordinate packing (layer-by-layer) [G]
    x, y, z = pos
    return (x + y * width + z * width * depth, 0.0)

def write_min_distance(texture, coord, dist):
    # Simulates depth test / atomic minimum update [G]
    current = texture.read(coord)
    if current is None or dist < current:
        texture.write(coord, dist)

def voxelize_small_triangles(small_triangles, distance_texture, voxel_size):
    # Draw call launches points equal to number of small triangles
    for i, tri in enumerate(small_triangles):
        # Vertex shader: read vertices using gl_VertexID
        v0, v1, v2 = read_triangle_from_texture(distance_texture, i)
        center = (v0 + v1 + v2) / 3.0
        # Instancing loop: 27 instances (1 center + 26 neighbors)
        for inst_id in range(27):
            offset = get_neighbor_offset(inst_id, voxel_size)
            target_voxel = center + offset
            dist = distance_triangle_to_voxel(v0, v1, v2, target_voxel)
            tex_coord = map_3d_to_2d(target_voxel, distance_texture.width, distance_texture.depth)
            write_min_distance(distance_texture, tex_coord, dist)

def voxelize_big_triangles(big_triangles, distance_texture):
    # Fragment shader pass over all voxels in the texture
    for voxel_pos in distance_texture.all_voxels():
        min_dist = float('inf')
        # Evaluate up to 64 big triangles
        for tri in big_triangles[:64]:
            dist = distance_triangle_to_voxel(tri.v0, tri.v1, tri.v2, voxel_pos)
            if dist < min_dist:
                min_dist = dist
        tex_coord = map_3d_to_2d(voxel_pos, distance_texture.width, distance_texture.depth)
        write_min_distance(distance_texture, tex_coord, min_dist)
```

**Parameters:**
*   **Max big triangles per shader pass:** 64 [S1, unofficial].
*   **Number of instances for 3D voxel neighborhood:** 27 (1 center + 26 adjacent) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   WebGL lacks compute shaders, storage buffers, and atomic operations, requiring the use of the rasterization pipeline, 2D texture simulation for 3D data, and depth testing for min-distance updates [S1, unofficial].
*   Large triangles cause performance bottlenecks in naive voxelization because the bounding box contains too many voxels to evaluate in a loop [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial].
*   **Measured Performance:** Not given in the sources [S1, unofficial].
*   **Scaling:** Not given in the sources [S1, unofficial].
*   **Strengths:** Works within WebGL constraints (no compute shaders/atomics); handles dense meshes well with small triangles; separates big triangles to avoid excessive voxel evaluation loops [S1, unofficial].
*   **Limitations:** Requires CPU-side triangle splitting; limited to 64 big triangles per pass; 2D texture simulation for 3D data adds complexity [S1, unofficial].
*   **When to use:** Real-time distance field calculation in WebGL environments [S1, unofficial].
*   **When not to use:** When compute shaders and atomic operations are available (use CUDA or native GPU methods instead) [S1, unofficial].

## Background
Origin: The method was developed to implement real-time distance field voxelization in WebGL, adapting concepts from the TressFX shader to work around WebGL's lack of compute shaders, storage buffers, and atomic operations [S1, unofficial]. The author discusses conversations with Vicente Lucendo regarding GPU triangle splitting, which led to the decision to perform splitting on the CPU to avoid excessive memory usage and triangle generation for meshes with varying sizes [S1, unofficial].
