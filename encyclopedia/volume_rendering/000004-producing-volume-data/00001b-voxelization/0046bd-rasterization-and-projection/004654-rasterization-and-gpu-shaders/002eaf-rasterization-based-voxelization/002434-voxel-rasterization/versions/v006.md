# Voxel Rasterization

Also called: CUDA Voxel Rasterization

## Overview
Voxel Rasterization converts a triangle mesh into a 3D voxel grid by projecting triangles onto the grid and marking occupied voxels, often accompanied by normal or color data [S2, S3, unofficial]. It differs from its sibling [3D Grid Rasterization](903-3d-grid-rasterization.md) by explicitly iterating over triangle edges to sample points for occupancy and attribute mapping, rather than using a pure grid-based traversal or ray-casting approach [S3, unofficial]. It serves as the foundational rasterization step in [Rasterization-based Voxelization](908-rasterization-based-voxelization.md), providing the raw voxel occupancy and attributes before cube mesh generation [S2, unofficial].

## How it works
**Inputs:**
*   Triangle mesh: List of triangles, each defined by 3 vertices ($p_1, p_2, p_3$) and 3 normals ($n_1, n_2, n_3$) [S3, unofficial].
*   Voxel grid dimensions: $(v_x, v_y, v_z)$ [S3, unofficial].
*   Accuracy multiplier: $accuracy$ (float) [S3, unofficial].
*   Mode flags: `octree_render` (bool), `colorizemap` (bool) [S3, unofficial].
*   Optional: Voxel size scaling $mScale$ (default 1.0f) and grid size $mSize$ (Vector3) [S2, unofficial].

**Outputs:**
*   Voxel buffer: A bit-packed array representing occupancy, and optionally color/normal arrays [S3, unofficial].
*   Struct layout for voxel data: `pos[3]` (int) for coordinates, `color[4]` (int) for RGBA [S2, unofficial].

**Data Structures:**
*   **Voxel Occupancy Array:** A 1D bit-packed array `voxel`. The index for a voxel at integer coordinates $(px, py, pz)$ is calculated as:
    $$
    \begin{aligned}
    vx8 &= v_x / 8 \\
    ofs &= (px \gg 3) + py \cdot vx8 + pz \cdot vx8 \cdot v_y
    \end{aligned}
    $$
    The bit index within the byte is $bit = 1 \ll (px \& 7)$ [S3, unofficial].
*   **Color Arrays:** If `colorizemap` is true, separate bit arrays (e.g., `voxel_col1`) store color bits [S3, unofficial].

**Algorithm Steps:**
1.  **Preparation:** For each triangle in the mesh, extract vertices $p_1, p_2, p_3$ and normals $n_1, n_2, n_3$ [S3, unofficial].
2.  **Edge Vector Calculation:** Compute edge vectors $d_1 = p_2 - p_1$, $d_2 = p_3 - p_1$ and normal differences $dn_1 = n_2 - n_1$, $dn_2 = n_3 - n_1$ [S3, unofficial].
3.  **Sampling Density Determination:** Calculate the maximum dimension $vm = \max(v_x, v_y, v_z)$ [S3, unofficial]. Determine the number of samples $c$ along the longest edge to ensure sufficient coverage:
    $$
    \begin{aligned}
    c_1 &= \text{length}(d_1) \cdot vm \cdot accuracy \\
    c_2 &= \text{length}(d_2) \cdot vm \cdot accuracy \\
    c &= \max(c_1, c_2)
    \end{aligned}
    $$
    Typical $accuracy$ is 2, increased to 3 if $v_x < 1024$, and 4 if $v_x < 512$ [S3, unofficial].
4.  **Outer Loop (Edge Sampling):** Iterate $i$ from 0 to $c$:
    *   Calculate interpolation factor $a = i / c$ [S3, unofficial].
    *   Calculate points on the two edges: $x_1 = p_1 + d_1 \cdot a$ and $x_2 = p_1 + d_2 \cdot a$ [S3, unofficial].
    *   Calculate the connecting vector $dx = x_2 - x_1$ [S3, unofficial].
    *   Calculate interpolated normals: $xn_1 = n_1 + dn_1 \cdot a$ and $xn_2 = n_1 + dn_2 \cdot a$ [S3, unofficial].
5.  **Inner Loop (Line Rasterization):** Calculate the number of samples $d$ along the connecting vector $dx$:
    $$
    d = \text{length}(dx) \cdot vm \cdot accuracy
    $$
    Iterate $j$ from 0 to $d$:
    *   Calculate factor $b = j / d$ [S3, unofficial].
    *   Calculate the point $p = x_1 + dx \cdot b$ [S3, unofficial].
    *   Calculate the interpolated normal $n = xn_1 + (xn_2 - xn_1) \cdot b$ [S3, unofficial].
6.  **Voxel Mapping:**
    *   If `octree_render` is false, map the point $p$ to the voxel grid [S3, unofficial].
    *   Convert $p$ to integer voxel coordinates $(px, py, pz)$ [S3, unofficial].
    *   **Boundary Check:** If $px \ge v_x$ or $py \ge v_y$ or $pz \ge v_z$, skip (prevent out-of-bounds writes) [S3, unofficial].
    *   **Occupancy:** Set the bit in the `voxel` array:
        $$
        voxel[ofs] \mid= bit
        $$
    *   **Color/Normal Mapping:** If `colorizemap` is true, call `map_voxel(p, n)` [S3, unofficial]. This involves updating color bit arrays. For a specific color bit `bit` and color value `color`:
        $$
        \begin{aligned}
        voxel\_col1[ofs] \&= 255 - bit \\
        voxel\_col1[ofs] \mid= (color \& 1) \ll bit
        \end{aligned}
        $$
        [S3, unofficial].

**Pseudocode:**
```python
def voxel_rasterization(triangles, vx, vy, vz, accuracy=2.0, colorizemap=False):
    # Initialize bit-packed occupancy array
    # Size calculation: assuming vx is divisible by 8 for simplicity as per source
    vx8 = vx // 8
    total_voxels = vx8 * vy * vz
    voxel = [0] * total_voxels
    
    # Optional color arrays if colorizemap is true
    voxel_col1 = [0] * total_voxels if colorizemap else None

    for tri in triangles:
        p1, p2, p3 = tri.vertices
        n1, n2, n3 = tri.normals
        
        d1 = p2 - p1
        d2 = p3 - p1
        dn1 = n2 - n1
        dn2 = n3 - n1
        
        vm = max(vx, vy, vz)
        
        # Calculate sampling counts
        c1 = length(d1) * vm * accuracy
        c2 = length(d2) * vm * accuracy
        c = max(c1, c2)
        
        for i in range(int(c) + 1):
            a = i / c
            x1 = p1 + d1 * a
            x2 = p1 + d2 * a
            dx = x2 - x1
            
            xn1 = n1 + dn1 * a
            xn2 = n1 + dn2 * a
            dnx = xn2 - xn1
            
            d = length(dx) * vm * accuracy
            
            for j in range(int(d) + 1):
                b = j / d
                p = x1 + dx * b
                n = xn1 + dnx * b
                
                # Convert to voxel coordinates
                px = int(p.x * vx)
                py = int(p.y * vy)
                pz = int(p.z * vz)
                
                # Boundary checks
                if px >= vx or py >= vy or pz >= vz:
                    continue
                
                # Calculate index
                ofs = (px >> 3) + py * vx8 + pz * vx8 * vy
                bit = 1 << (px & 7)
                
                # Set occupancy
                voxel[ofs] |= bit
                
                # Set color if enabled
                if colorizemap:
                    # Assuming color is mapped to a single bit for simplicity based on source
                    # In practice, color mapping logic may vary
                    color_val = 1 # Placeholder for actual color bit extraction
                    voxel_col1[ofs] &= (255 - bit)
                    voxel_col1[ofs] |= (color_val & 1) << bit

    return voxel, voxel_col1
```

## Subtopics

### [CUDA Voxelization](3491-cuda-voxelization.md)
A CUDA GPU implementation that launches a 3D grid of thread blocks to process voxels in parallel. It differs from the base method by utilizing a specific 3D block launch configuration and precomputed face bounds to optimize device-side computation.

### [Hybrid Voxelization Classification](3946-hybrid-voxelization-classification.md)
A GPU-accelerated method for voxelizing 3D CAD models using a nested two-level resolution structure (coarse Level1 and fine Level2 grids). It distinguishes itself by maintaining hierarchical grids for detailed normal estimation while managing memory, building on Voxel Rasterization by extending output data structures.

### [CUDA Sparse Voxel Rasterization Wrapper](10783-cuda-sparse-voxel-rasterization-wrapper.md)
Provides a differentiable PyTorch interface for rasterizing sparse voxels into 2D image space. It supports simultaneous outputs for color, depth, normals, and distortion, facilitating gradient-based optimization, unlike standard binary rasterization.

### [Direct Voxel Rasterization with Edge Fading](13471-direct-voxel-rasterization-with-edge-fading.md)
Renders 3D spheres into a voxel grid by iterating over AABBs, computing Euclidean distance, and applying linear edge fade with maximum blending. It differs from binary voxelization by introducing anti-aliased edges and is computationally lightweight for real-time updates.

### [WebGL Voxelization via Triangle Splitting and Instancing](15405-webgl-voxelization-via-triangle-splitting-and-instancing.md)
Calculates distance fields on WebGL by converting triangles to points (particles) and using instancing with depth testing to simulate atomic minimum-distance updates. It sets itself apart by avoiding compute shaders and atomic operations, leveraging the rasterization pipeline instead.

### CUDA Rasterizer
Custom forward and backward CUDA kernels for rasterization and interpolation, supporting full-image rendering and batched pixel-query modes. Training takes 1-3 minutes on an RTX A6000 Ada [S5].

### Raster Preprocessing
A preprocessing step that calculates duplicate counts and generates a geometry buffer for rasterization. It calls `_C.rasterize_preprocess` with image dimensions, camera parameters, and voxel data, optionally returning both duplicate count and geometry buffer [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of triangles multiplied by the sampling density along their edges. The sampling density $c$ and $d$ scales with the triangle edge length and the voxel grid dimensions ($v_x, v_y, v_z$) [S3, unofficial].
*   **Memory Complexity:** Dominated by the voxel buffer size, which is $O(v_x \cdot v_y \cdot v_z / 8)$ bits for occupancy, plus additional space for color/normal data if enabled [S3, unofficial].
*   **Performance:** The method is efficient for moderate-resolution grids. High accuracy multipliers or large grids can lead to significant over-sampling and memory usage [S3, unofficial].
*   **Strengths:** Simple implementation, supports direct normal/color mapping, compatible with standard graphics pipelines (e.g., Direct3D 11, OpenGL) [S2, S3, unofficial].
*   **Limitations:** Potential for over-sampling if accuracy is too high, under-sampling if too low. Boundary checks are critical to prevent out-of-bounds writes [S3, unofficial]. Bit-packing assumes specific grid dimension properties (e.g., divisibility by 8) [S3, unofficial].

## Background
Voxel Rasterization is a technique used in Direct3D 11-based voxelization systems to render input geometry into a voxel buffer, supporting multiple material effects and outputting voxel data through a callback interface [S2, unofficial]. It is also implemented in CUDA for GPU-accelerated voxelization [S4, unofficial]. The method is foundational in various voxelization pipelines, including those for terrain generation and neural reconstruction [S1, unofficial][S5].
