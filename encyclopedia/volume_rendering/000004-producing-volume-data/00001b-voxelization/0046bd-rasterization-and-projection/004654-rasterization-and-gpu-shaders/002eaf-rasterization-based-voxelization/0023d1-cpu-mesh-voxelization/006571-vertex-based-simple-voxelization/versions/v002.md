# Vertex-Based Simple Voxelization

Also called: Point Voxelization, Vertex Snap Voxelization

## Overview
Vertex-Based Simple Voxelization converts a triangle mesh into a 3D voxel grid by marking only the voxels that contain the mesh's vertices, ignoring edges and faces to maximize speed [S1, unofficial]. Unlike its sibling [Voxelization via Triangle Scattering](3779-voxelization-via-triangle-scattering.md), which rasterizes triangle surfaces, this method is strictly point-based, making it significantly faster but prone to leaving large empty regions in thin geometry or large triangles [S1, unofficial].

## How it works
**Inputs:** A triangle mesh defined by a list of vertices and faces, a bounding box minimum (`mesh_min`), a target resolution (`voxels_per_axis`), and a chunking system for memory management [S1, unofficial].
**Outputs:** A sparse or dense voxel grid (organized into chunks) where occupied voxels are marked with a value of 1 [S1, unofficial].

**Data Structures:**
*   `mesh.vertices`: Array of 3D vectors $(x, y, z)$.
*   `mesh.faces`: Array of structures/tuples containing three vertex indices $[i, j, k]$.
*   `voxels_per_axis`: Integer scalar defining the grid resolution per chunk axis [S1, unofficial].
*   `chunk`: A data structure representing a sub-volume of the world, capable of storing local voxel data [S1, unofficial].

**Parameters:**
*   `voxels_per_axis`: The number of voxels along one axis of a chunk [S1, unofficial]. Typical values depend on the desired world resolution and chunk size; not given in the sources.

**Steps:**
1.  **Precompute Grid Constants:** Calculate the physical size of a single voxel and its inverse [S1, unofficial].
    $$ \text{voxel\_size} = \frac{1.0}{\text{voxels\_per\_axis}} $$
    $$ \text{inv\_voxel\_size} = \frac{1.0}{\text{voxel\_size}} = \text{voxels\_per\_axis} $$
    [S1, unofficial]
2.  **Iterate Mesh Geometry:** Loop through every face in the mesh [S1, unofficial]. For each face, iterate through its three vertex indices [S1, unofficial].
3.  **Transform and Snap to Grid:** For each vertex index, retrieve the vertex position from the mesh [S1, unofficial]. Subtract the mesh bounding box minimum to obtain local coordinates relative to the chunk origin [S1, unofficial].
    $$ \mathbf{v}_{local} = \mathbf{v}_{world} - \mathbf{mesh\_min} $$
    [S1, unofficial]
    Compute the voxel coordinates by scaling the local position by the inverse voxel size and flooring the result to snap to the nearest lower grid integer [S1, unofficial].
    $$ \mathbf{v}_{voxel} = \lfloor \mathbf{v}_{local} \times \text{inv\_voxel\_size} \rfloor $$
    [S1, unofficial]
4.  **Determine Local and Global Indices:** Calculate the local voxel position within the current chunk using modulo arithmetic [S1, unofficial].
    $$ \mathbf{v}_{local\_voxel} = \mathbf{v}_{voxel} \pmod{\text{voxels\_per\_axis}} $$
    [S1, unofficial]
    Determine the global chunk position based on the world voxel coordinates and the chunk's world size [S1, unofficial].
    $$ \mathbf{p}_{chunk} = \lfloor \mathbf{v}_{voxel} / \text{voxels\_per\_axis} \rfloor $$
    [S1, unofficial]
5.  **Mark Occupancy:** Retrieve or create the chunk at $\mathbf{p}_{chunk}$ [S1, unofficial]. Set the voxel at $\mathbf{v}_{local\_voxel}$ within that chunk to 1 (occupied) [S1, unofficial].

**Pseudocode:**
```python
import math

def vertex_based_simple_voxelization(mesh, mesh_min, voxels_per_axis):
    # Precompute constants
    inv_voxel_size = voxels_per_axis
    
    # Dictionary to store chunks: key is chunk_position tuple, value is dict of local_voxel -> 1
    chunks = {}
    
    # Iterate over all faces
    for face in mesh.faces:
        # Iterate over the three vertices of the face
        for vertex_index in [face.x, face.y, face.z]:
            # Retrieve vertex position (adjusting for 1-based indexing if necessary)
            vertex_world = mesh.vertices[vertex_index - 1]
            
            # Transform to local chunk coordinates
            vertex_local = vertex_world - mesh_min
            
            # Snap to voxel grid
            voxel_world = math.floor(vertex_local * inv_voxel_size)
            
            # Calculate local position within the chunk
            local_voxel = voxel_world % voxels_per_axis
            
            # Determine which chunk this voxel belongs to
            chunk_position = voxel_world // voxels_per_axis
            
            # Get or create the chunk
            if chunk_position not in chunks:
                chunks[chunk_position] = {}
            chunk = chunks[chunk_position]
            
            # Mark the voxel as occupied
            chunk[local_voxel] = 1
```
[S1, unofficial]

**Edge Cases and Pitfalls:**
*   **Thin Geometry:** Because edges and faces are ignored, thin structures (e.g., walls with thickness less than a voxel) may result in disconnected or missing voxels if no vertex falls inside the volume [S1, unofficial].
*   **Large Triangles:** Large triangles with vertices far apart may leave significant empty space between the snapped vertex voxels, failing to represent the surface area [S1, unofficial].
*   **Boundary Precision:** Floating-point precision errors in `floor` operations can cause vertices exactly on grid boundaries to snap incorrectly. [G] Ensure consistent handling of boundary conditions (e.g., epsilon offsets) if exact grid alignment is required.

## Subtopics

### [Simplified Parallel Voxelization](19528-simplified-parallel-voxelization.md)
A variant that voxelizes only the eight corner points of an object's bounding box. It is chosen when hardware has limited local storage and high parallelism (e.g., PlayStation 3 Cell Processor), assuming grid cells are larger than the objects to avoid false negatives. It eliminates edge/face traversal entirely.

## Operating characteristics
*   **Time Complexity:** $O(V)$, where $V$ is the number of vertices in the mesh, as it iterates over each vertex exactly once [G]. It is extremely fast as it avoids rasterization or ray-casting per triangle [S1, unofficial].
*   **Memory Complexity:** Depends on the output format (sparse vs. dense) and chunking overhead. Not given in the sources.
*   **Strengths:** Minimal computational overhead; highly parallelizable at the vertex level; simple implementation [G].
*   **Limitations:** Geometrically inaccurate for non-vertex-centric features; produces "hollow" or sparse volumes for thin or large surfaces [S1, unofficial].
*   **When to use:** Rapid prototyping, coarse collision detection, or as a pre-pass for more accurate voxelization methods where vertex density is high [G].
*   **When not to use:** When accurate surface representation is required, or when the mesh has low vertex density relative to its surface area [G].
