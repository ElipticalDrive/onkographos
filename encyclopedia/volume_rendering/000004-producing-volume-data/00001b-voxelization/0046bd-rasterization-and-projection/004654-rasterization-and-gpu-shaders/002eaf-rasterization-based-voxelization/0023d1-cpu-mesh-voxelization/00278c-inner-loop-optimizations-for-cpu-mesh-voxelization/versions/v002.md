# Inner Loop Optimizations for CPU Mesh Voxelization

Also called: Inner loop optimizations for voxelization, MeshProcessor::voxelize optimizations, Pre-allocated hit_xs and rolling index voxelization

## Overview
This method applies structural and algorithmic optimizations to the core inner loop of `MeshProcessor::voxelize` to reduce constant overhead when processing millions of grid cells [S1, unofficial]. It distinguishes itself from sibling methods by focusing on pre-allocating the `hit_xs` array to avoid dynamic reallocations, hoisting loop-invariant calculations, and replacing binary searches with rolling indices to achieve amortized $O(1)$ lookups, rather than changing the fundamental rasterization approach [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Triangle mesh data, voxel grid bounds, `narrow_band` flag (boolean) [S1, unofficial].
- Output: Voxel grid with signed distance field (SDF) values or occupancy flags [S1, unofficial].

**Data Structures:**
- `hit_xs`: A fixed-capacity array storing X-coordinates of triangle intersections along a scanline, pre-allocated with capacity 8 [S1, unofficial].
- `hit_idx`: An integer index tracking the current position in `hit_xs` for rolling lookups [S1, unofficial].

**Numbered Steps:**
1. **Pre-allocate Intersection Array:** Initialize `hit_xs` with a fixed capacity of 8 before processing scanlines to avoid dynamic heap reallocations [S1, unofficial].
2. **Hoist Loop-Invariant Calculations:** Move `base_x` calculations and `phase_sphere` offset computations outside the innermost X-axis loops to eliminate redundant floating-point operations [S1, unofficial].
3. **Replace Binary Search with Rolling Index:** Maintain a rolling index `hit_idx` that advances monotonically as X strictly ascends, replacing the $O(\log M)$ `partition_point` binary search with an amortized $O(1)$ lookup per voxel [S1, unofficial].
4. **Conditionally Assign Distance:** If a voxel is exterior and `narrow_band` is `None`, assign a dummy distance of `1.0`; otherwise, compute the distance via a BVH query [S1, unofficial].
5. **Store Voxel Data:** Write the voxel if the computed distance is $\le 0.0$ [G].

**Pseudocode:**
```python
def voxelize_inner_loop_optimized(triangles, grid_bounds, narrow_band=False):
    # Pre-allocate hit_xs with capacity 8 to avoid dynamic reallocations [S1, unofficial]
    hit_xs = [0.0] * 8
    hit_count = 0

    for y in range(grid_bounds.min_y, grid_bounds.max_y):
        for z in range(grid_bounds.min_z, grid_bounds.max_z):
            # Hoist loop-invariant calculations outside innermost loop [S1, unofficial]
            base_x = calculate_base_x(y, z)
            phase_sphere_offset = calculate_phase_sphere_offset(y, z)

            hit_count = 0
            # Collect intersections for current scanline
            for tri in triangles:
                if tri.intersects_scanline(y, z):
                    if hit_count < 8:
                        hit_xs[hit_count] = tri.get_intersection_x(y, z)
                        hit_count += 1
                    else:
                        hit_xs.append(tri.get_intersection_x(y, z))

            hit_xs.sort()

            hit_idx = 0
            is_inside = False

            for x in range(grid_bounds.min_x, grid_bounds.max_x):
                # Rolling index advances monotonically as X strictly ascends [S1, unofficial]
                while hit_idx < len(hit_xs) and hit_xs[hit_idx] <= x:
                    hit_idx += 1

                is_inside = (hit_idx % 2 == 1)

                # Bypass BVH for exterior voxels when narrow_band is disabled [S1, unofficial]
                if not is_inside and not narrow_band:
                    distance = 1.0
                else:
                    distance = distance_to_local_point(x, y, z)

                # Store voxel data if within surface threshold [G]
                if distance <= 0.0:
                    set_voxel_sdf(x, y, z, distance)
```

**Parameters:**
- `hit_xs_capacity`: 8 (typical for small meshes, but pre-allocation avoids reallocation overhead) [S1, unofficial].
- `narrow_band`: Boolean flag. If `False`, exterior voxels receive a dummy distance of `1.0` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Erosion:** When `narrow_band` is `None`, assigning `distance = 1.0` to exterior voxels changes boundary behavior for voxels exactly on the surface that are parity-classified as outside (common on the +X exit face where `hit_x == x`) [S1, unofficial]. Previously, these points had `distance_to_local_point(...) == 0` and were retained (`sdf == 0`) [S1, unofficial]. Now, they become `sdf = 1.0` and are dropped, which can asymmetrically erode the solid by a boundary layer on grid-aligned meshes [S1, unofficial].
- **Small Mesh Regression:** On very small 10x10x10 benchmark cubes, the algorithmic wins are overshadowed by constant branching overhead, resulting in a ~3-4% micro-regression [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Replaces an $O(N \log M)$ binary search operation across a scanline with an $O(M)$ rolling index update operation, where $N$ is the number of voxels and $M$ is the number of intersections [S1, unofficial].
- **Memory Complexity:** Pre-allocates `hit_xs` with a fixed capacity of 8, reducing heap fragmentation and dynamic allocation overhead [S1, unofficial].
- **Measured Performance:** Theoretical asymptotic improvements for large-scale high-resolution voxel grids [S1, unofficial]. Small benchmarks (10x10x10) show a ~3-4% regression due to constant loop overhead [S1, unofficial].
- **Strengths:** Reduces redundant arithmetic, avoids dynamic allocations, and short-circuits expensive BVH queries for discarded exterior voxels [S1, unofficial].
- **Limitations:** Potential boundary erosion on grid-aligned meshes when `narrow_band` is disabled; minor regression on very small meshes [S1, unofficial].
- **When to Use:** Large-scale production mesh workloads where voxel grid resolution is high and `narrow_band` is not required [S1, unofficial].
- **When Not to Use:** Small meshes where constant overhead dominates, or when precise boundary retention is critical without `narrow_band` [S1, unofficial].

## Background
This method was implemented by lhemerly in May 2026 as part of the `voxelizer-rs` project, specifically in PR #121 [S1, unofficial]. It addresses bottlenecks in the `MeshProcessor::voxelize` function, including dynamic vector allocation, redundant invariant math, binary searches over intersection arrays, and unneeded BVH distance queries for discarded exterior voxels [S1, unofficial]. The optimizations are designed for CPU-based voxelization, building on the foundational approach of [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md) [G].
