# Hardware-accelerated surface voxelization via 2D textures

Also called: Image-space voxelization

## Overview
This method transfers the geometric intersection computation from 3D space to 2D image space by rasterizing model surfaces into 2D textures, enabling real-time collision detection and volumetric rendering for complex models [S1, unofficial]. It is distinguished from slicing-based voxelization by rasterizing the scene approximately once rather than $N$ times (where $N$ is the volume resolution), making its performance insensitive to scene complexity and dependent only on volume resolution [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A polygonal mesh (vertices, normals, triangles) and a target volume resolution $D$ (e.g., $256^3$).
*   **Output:** A 3D voxel grid stored as a set of 2D textures (worksheets), where each texel represents a voxel's state (occupancy, normal, or color).

**Data Structures:**
The 3D volume is decomposed into 2D "worksheets" (2D textures). The storage format depends on the resolution and required bit-depth:
*   **Low Resolution (e.g., $64^3$):** 8-bit depth per voxel. Memory usage is low (e.g., 256 KB for $64^3$) [S1, unofficial].
*   **Medium Resolution (e.g., $128^3$):** 16-bit depth per voxel (e.g., encoding vertex normals) [S1, unofficial].
*   **High Resolution (e.g., $256^3$):** 8-bit depth per voxel is considered optimal for current hardware conditions [S1, unofficial].
*   **Very High Resolution (e.g., $512^3$):** 1-bit depth per voxel to fit within memory constraints (e.g., 16 MB) [S1, unofficial].

**Coordinate Transformation:**
World-space coordinates are mapped to voxel indices using the formula from the parent article [Parent](6237-position-map-and-image-space-transfer.md):
$$ i = D \times \frac{p - p_{min}}{p_{max} - p_{min}} $$
where $p$ is the world position, $p_{min}$ is the bounding box minimum, and $D$ is the resolution. Integer truncation (floor) yields the discrete voxel index [G].

**Algorithm Steps:**
1.  **Rasterization:** Render the input polygonal mesh into a 2D texture (or set of 2D textures) using the GPU's fixed-function rasterizer. This step determines coverage in image space [S1, unofficial].
2.  **Texelization/Synthesis:** Process the 2D texture data to populate the 3D voxel grid. This involves mapping the 2D rasterized output to the 3D volume structure. For binary surface voxelization, this may involve bit-operations [S1, unofficial].
3.  **Collision Query:** Use the generated 2D textures in image space to perform collision queries. Since voxelization is no longer the bottleneck, real-time frame rates are achievable [S1, unofficial].
4.  **Rendering:** Render the volume data and voxelized slices in 3D space to display complex deformable models semi-transparently [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Solid voxelization of closed polygonal models may exhibit aliasing effects, appearing as prolonged lines where some voxels are missing at the rasterization stage [S1, unofficial].
*   **Memory Constraints:** High-resolution volumes (e.g., $512^3$) require significant memory. Using 1-bit depth is necessary to fit within video memory limits (e.g., 16 MB) [S1, unofficial].
*   **Performance Sensitivity:** While insensitive to scene complexity, performance is dominated by volume resolution and bit-depth [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The rasterization phase depends on the number of triangles, but the overall voxelization performance is insensitive to scene complexity because the model is traversed approximately once [S1, unofficial]. The texelization and synthesis phases are image-space operations dominated by volume resolution and bit-depth [S1, unofficial].
*   **Memory Complexity:** Memory usage scales with the volume resolution and bit-depth. For example, a $512^3$ volume with 1-bit depth uses 16 MB, while a $256^3$ volume with 8-bit depth uses 16 MB [S1, unofficial].
*   **Measured Performance:**
    *   On a PC with a 2.4 GHz Pentium IV CPU, 2GB RAM, and ATI Radeon 9800 Pro:
        *   Blade model (1,765,388 triangles) at $256^3$ resolution: 75 ms for rasterization [S1, unofficial].
        *   Wagner model (60,246 triangles) at $512^3$ resolution (1-bit): 500 ms [S1, unofficial].
        *   Wagner model at $256^3$ resolution (8-bit): 30 ms [S1, unofficial].
        *   Wagner model at $128^3$ resolution (16-bit): 24 ms [S1, unofficial].
        *   Wagner model at $64^3$ resolution (8-bit): 21 ms [S1, unofficial].
        *   Visualization of voxelized volume: ~8 ms on average [S1, unofficial].
        *   Implicit surface voxelization at $256^3$: 25 ms [S1, unofficial].
        *   Hybrid volume rendering (transparent cerebra model + MRI head volume $128^3$): ~10 fps [S1, unofficial].
*   **Strengths:** Real-time performance for complex and deformable models; view-independent; avoids CPU-side sorting [S1, unofficial].
*   **Limitations:** Aliasing effects in solid voxelization; performance dependent on volume resolution and bit-depth; requires sufficient video memory for high resolutions [S1, unofficial].
*   **When to Use:** Surgical planning, intra-operation navigation, and radiation therapy [S1, unofficial].
*   **When Not to Use:** When high-fidelity surface representation is critical without aliasing artifacts; when video memory is severely constrained for very high resolutions.
