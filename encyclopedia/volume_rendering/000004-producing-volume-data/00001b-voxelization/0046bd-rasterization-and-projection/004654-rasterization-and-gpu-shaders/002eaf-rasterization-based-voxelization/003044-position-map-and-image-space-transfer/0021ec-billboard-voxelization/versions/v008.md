# Billboard Voxelization
Also called: firstVoxelize, instanced billboard voxelization

## Overview
Billboard Voxelization is a two-pass rasterization-based technique that converts polygonal geometry into a 3D voxel grid by rendering instanced quads (billboards) into a position map. It differs from standard position map voxelization by explicitly generating voxel-sized quads for each potential voxel location, allowing for direct initialization of voxel data during the rasterization pass rather than relying solely on post-processing of a surface position texture.

## How it works
**Inputs:**
*   Polygonal mesh (vertices, normals).
*   Volume bounds: $[x_{min}, x_{max}]$, $[y_{min}, y_{max}]$, $[z_{min}, z_{max}]$.
*   Volume resolution: `voxelDim` (assumed uniform).
*   Camera matrices: Projection ($P$), View ($V$).
*   Voxel size vector: `voxelSize` ($s_x, s_y, s_z$).

**Outputs:**
*   A 3D texture (or volume buffer) where each voxel contains initialized data (e.g., density, color) and position information.

**Data Structures:**
*   **Position Map FBO:** A Framebuffer Object with a color attachment (typically `rgba32f` for high precision) storing world-space positions and a depth attachment for occlusion culling.
*   **Voxel Grid:** A 3D texture or buffer indexed by $(x, y, z)$.

**Steps:**
1.  **Setup:** Bind the Position Map FBO. Clear color and depth buffers to 0.
2.  **Matrix Preparation:**
    *   Load light/camera projection matrix $P$ and view matrix $V$.
    *   Compute modified inverse view matrix $V_i$. This is done by zeroing out the translation components of $V$, then transposing the remaining rotation/scaling submatrix [S1, unofficial].
3.  **Uniform Loading:** Load $P$, $V$, $V_i$, light near plane, clip distance, volume position, and `voxelSize` into the shader.
4.  **Rendering Pass (Billboard Generation):**
    *   Render instanced quads. Each instance corresponds to a voxel in the grid.
    *   The vertex shader transforms the quad's local position into world space using `voxelPosition` and `voxelSize`, then projects it using $P \times V$.
    *   The fragment shader writes the world-space position of the fragment to the position map color attachment. Depth testing ensures only the nearest surface fragment is recorded.
5.  **Volume Population:**
    *   Unbind the VAO, volume, shader, and framebuffer.
    *   Render a full-screen quad.
    *   Sample the position map to retrieve world-space positions.
    *   Convert world-space positions to voxel indices using the formula provided in the parent article.
    *   Write the sampled data (or derived density) to the 3D voxel grid.

**Pseudocode:**

```python
def billboard_voxelization(mesh, volume_bounds, voxel_dim, camera):
    # 1. Setup Position Map FBO
    fbo = create_fbo(width=volume_bounds.resolution, height=volume_bounds.resolution, format='rgba32f')
    bind_fbo(fbo)
    clear_buffers(color=0.0, depth=1.0)

    # 2. Prepare Matrices
    P = camera.projection_matrix
    V = camera.view_matrix
    # Compute Vi: zero translation in V, then transpose
    V_inv_rot = transpose(V[0:3, 0:3])
    Vi = identity_matrix()
    Vi[0:3, 0:3] = V_inv_rot

    # 3. Load Uniforms
    shader.set_uniform('P', P)
    shader.set_uniform('V', V)
    shader.set_uniform('Vi', Vi)
    shader.set_uniform('voxelSize', vec3(1.0/voxel_dim)) # Assuming uniform voxel size
    shader.set_uniform('volumeBounds', volume_bounds)

    # 4. Render Instanced Billboards
    # For each voxel in the grid:
    for z in range(volume_bounds.z_min, volume_bounds.z_max):
        for y in range(volume_bounds.y_min, volume_bounds.y_max):
            for x in range(volume_bounds.x_min, volume_bounds.x_max):
                # Calculate world position of voxel center
                voxel_pos = world_position_from_index(x, y, z, volume_bounds)
                
                # Set instance data
                shader.set_instance_attribute('voxelPosition', voxel_pos)
                shader.set_instance_attribute('voxelData', 1.0) # Initial data
                
                # Render quad
                draw_instanced_quad()

    # 5. Unbind and Process
    unbind_fbo()
    unbind_vao()
    unbind_shader()
    
    # 6. Volume Population (Full Screen Quad)
    bind_fbo(None) # Back to screen or target volume
    render_fullscreen_quad()
    # Fragment shader samples position map and converts to voxel indices
    # x = voxelDim * (pos.x - x_min) / (x_max - x_min)
    # ... (see parent article for index conversion)
```

**Edge Cases and Pitfalls:**
*   **Precision:** Insufficient precision in the position map (e.g., using `rgba16f` instead of `rgba32f`) leads to incorrect voxel indexing [S1, unofficial].
*   **Boundary Conditions:** Positions outside the volume bounds result in negative or out-of-bounds indices. Explicit clamping is required [G].
*   **Aliasing:** Solid voxelization of closed polygonal models may exhibit aliasing effects, appearing as prolonged lines where some voxels are missing at the rasterization stage [S1, unofficial].

## Subtopics

### [Position Map FBO Setup](2749-position-map-fbo-setup.md)
Creates a Framebuffer Object (FBO) with a color attachment (position map) and a depth attachment for voxelization rendering. It prepares the GPU state for the first pass of billboard voxelization, where instanced quads are rendered to initialize voxel positions in a 3D texture.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of voxels and $M$ is the cost of rasterizing a billboard. The complexity is dominated by the number of voxels rather than the number of triangles, making it efficient for high-resolution volumes with sparse geometry.
*   **Memory Complexity:** $O(V)$, where $V$ is the volume resolution, for storing the position map and the final voxel grid.
*   **Strengths:** Direct control over voxel placement; efficient for large volumes with simple geometry; leverages GPU rasterization hardware.
*   **Limitations:** Memory intensive for high-resolution volumes; potential aliasing artifacts; requires careful handling of precision and boundaries.
*   **When to use:** Suitable for real-time applications where geometry is simple and volume resolution is moderate to high.
*   **When not to use:** Not suitable for complex geometry with high triangle counts where triangle-based voxelization might be more efficient.

## Background
Billboard Voxelization is a technique used in cloud rendering and other volume visualization applications. It was popularized by implementations such as the Cloud-Renderer project, which utilizes instanced rendering to efficiently populate voxel grids [S1, unofficial].
