# Voxelization Pass

Also called: Voxelization Rendering Pass, Voxelizer Pass

## Overview
The Voxelization Pass renders scene geometry into a 3D texture to produce a volumetric representation of the scene for subsequent ray-marching or cone-tracing rendering. It differs from standard rasterization by writing directly to a 3D image buffer rather than a 2D color buffer, effectively discretizing the scene into a voxel grid. It builds on [Position Map FBO Setup](2749-position-map-fbo-setup.md) which prepares the framebuffer targets.

## How it works
**Inputs:**
- Scene geometry (meshes with position and normal attributes).
- Camera configuration (`voxelizer_camera_`) with an orthographic projection.
- Voxel grid dimensions (`tex_size`).
- Scene scale parameter (`scene_scale`).

**Outputs:**
- A 3D texture (`tex3D`) of format `GL_RGBA8` containing the voxelized scene data.

**Data Structures:**
- `tex3D`: A 3D image texture bound at unit 0. Layout is `RGBA8` per voxel.
- `voxelizer_camera_`: Orthographic camera with frustum bounds $(-1, 1)$ for X and Y, and $(1, -1)$ for Z (near/far). Note: The source specifies frustum `(-1, 1, -1, 1, 1, -1)`, implying a left-handed or specific OpenGL convention where near=1 and far=-1, or a coordinate system inversion.

**Steps:**
1. Set the viewport to `tex_size` $\times$ `tex_size`.
2. Bind the default framebuffer.
3. Clear the color and depth buffers.
4. Disable face culling and depth testing to ensure all geometry contributes to the voxel volume without occlusion culling.
5. Bind `tex3D` as a write-only image texture at texture unit 0 with format `GL_RGBA8`.
6. Activate the voxelization shader (`shader_voxelization_`).
7. Set uniform `voxelImage` to 0.
8. Set uniform `sceneScale` to `scene_scale`.
9. Render the entire scene using the `voxelizer_camera_` orthographic projection.
10. Insert a memory barrier to ensure texture writes are visible for subsequent fetches.
11. Generate mipmaps for the 3D texture.

**Pseudocode:**
```python
def voxelization_pass(scene, tex_size, scene_scale, voxelizer_camera, tex3D):
    # 1. Setup Viewport
    gl.viewport(0, 0, tex_size, tex_size)
    
    # 2. Bind Default Framebuffer
    gl.bind_framebuffer(GL_FRAMEBUFFER, 0)
    
    # 3. Clear Buffers
    gl.clear_color(0.0, 0.0, 0.0, 0.0)
    gl.clear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)
    
    # 4. Disable Culling and Depth Testing
    gl.disable(GL_CULL_FACE)
    gl.disable(GL_DEPTH_TEST)
    
    # 5. Bind 3D Texture as Image
    gl.bind_texture(GL_TEXTURE_3D, tex3D.id)
    gl.active_texture(GL_TEXTURE0)
    gl.bind_image_texture(0, tex3D.id, 0, GL_FALSE, 0, GL_WRITE_ONLY, GL_RGBA8)
    
    # 6. Activate Shader
    shader = get_shader("shader_voxelization_")
    shader.use()
    
    # 7. Set Uniforms
    shader.set_int("voxelImage", 0)
    shader.set_float("sceneScale", scene_scale)
    
    # 8. Render Scene
    # The shader handles mapping vertex positions to voxel coordinates
    # based on the orthographic camera projection.
    scene.render(voxelizer_camera)
    
    # 9. Memory Barrier
    gl.memory_barrier(GL_SHADER_IMAGE_ACCESS_BARRIER_BIT)
    
    # 10. Generate Mipmaps
    gl.generate_mipmap(GL_TEXTURE_3D)
```

**Edge Cases and Pitfalls:**
- **Depth Testing:** Depth testing must be disabled. If enabled, only the front-most surface of each voxel column would be written, losing internal geometry information required for accurate volume rendering [S1, unofficial].
- **Face Culling:** Face culling must be disabled to ensure both front and back faces of geometry contribute to the voxel density [S1, unofficial].
- **Coordinate System:** The orthographic frustum bounds `(-1, 1, -1, 1, 1, -1)` suggest a specific coordinate mapping. Implementers must ensure the vertex shader correctly transforms world-space positions into the voxel grid space defined by `sceneScale` [S1, unofficial].

## Subtopics

### [G-Buffer Rasterization (Voxel Rendering Pass)](21931-g-buffer-rasterization-voxel-rendering-pass.md)
This method performs the initial rasterization pass for voxelization, rendering scene geometry into a multi-target framebuffer (G-Buffer) to capture position, normal, and albedo data.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of triangles in the scene, as each triangle is rasterized into the 3D texture.
- **Memory Complexity:** $O(V)$ where $V$ is the number of voxels ($tex\_size^3$). Each voxel stores 4 floats (RGBA8).
- **Performance:** Dependent on `tex_size` and scene complexity. High-resolution voxel grids consume significant VRAM.
- **Strengths:** Simple to implement using standard rasterization hardware; parallelizable on GPU.
- **Limitations:** Fixed resolution; aliasing artifacts at low resolutions; no hierarchical structure (unless mipmaps are used for coarser levels).

## Background
This method is derived from the Voxel Cone Tracing technique, specifically the implementation found in the `Voxel_Cone_Tracing` repository by kbladin [S1, unofficial]. It represents a direct rasterization-based approach to voxelization, contrasting with ray-marching or marching cubes approaches.
