# Rasterization-based Voxelization

Also called: Cube Mesh Generation, Hash-based Surface Voxelization, Sparse Voxelization with PositionMap Hashing, Voxelizing a Triangle Mesh, madcad Voxelization

## Overview
Rasterization-based Voxelization converts a continuous triangle mesh into a discrete volumetric representation by projecting the geometry onto a 3D grid using rasterization primitives [S1][S3, S4, unofficial]. It solves the problem of generating a voxel grid (either sparse occupancy or explicit cube meshes) from polygonal input without performing complex surface reconstruction [S1][S5, unofficial]. It differs from [Voxel Carving](1213-voxel-carving.md) by using constructive rasterization of primitives rather than destructive projection of camera rays, and from [Implicit Surface Voxelization](2379-implicit-surface-voxelization.md) by operating on explicit triangle lists rather than signed distance fields [S1][S5, unofficial].

## How it works
**Inputs:** A triangle mesh defined by vertex positions $V$ and face indices $F$, a voxel size $s = (s_x, s_y, s_z)$, and an origin $O$ [S1][S4, unofficial].
**Outputs:** A set of occupied voxel coordinates (sparse grid) or a mesh of cubes representing the voxelized surface [S1][S4, unofficial].

**Data Structures:**
1.  **Hash Table:** A sparse structure mapping voxel coordinates to occupancy data. In C implementations, this is a hash table with buckets containing linked lists of `vx_voxel_data_t` nodes, where each node stores a `position` (voxel center) and optional `color` [S4, unofficial]. In Python, a `set` of integer tuples `(i, j, k)` is used [S3, unofficial].
2.  **Output Mesh (Optional):** If generating a cube mesh, an array of vertices (8 per voxel), normals (6 shared), indices, and optional colors [S4, unofficial].

**Steps:**
1.  **Initialization:** Compute half-voxel size $hvs = s \times 0.5$ [S4, unofficial]. Initialize the hash table or voxel set [S3, S4, unofficial].
2.  **Triangle Rasterization:** For each triangle in the mesh:
    a. Determine the bounding box of the triangle in voxel space.
    b. Iterate over all integer voxel coordinates $(i, j, k)$ within this bounding box [S5, unofficial].
    c. For each voxel, determine if the triangle intersects the voxel cell. This is often done by checking if the voxel center lies within the triangle's projection or by using a conservative rasterization test [S1][S4, S6, unofficial].
    d. If occupied, insert the voxel coordinate into the hash table/set [S3, S4, unofficial].
3.  **Geometry Generation (Optional):** If a cube mesh is required:
    a. Allocate memory for $N$ voxels: vertices array of size $8N$, indices array of size $36N$ (6 faces $\times$ 2 triangles $\times$ 3 vertices) [S4, unofficial].
    b. For each unique voxel in the hash table:
        i. Calculate the voxel center $C$ from its grid index and origin $O$: $C = O + (i + 0.5)s_x, (j + 0.5)s_y, (k + 0.5)s_z$ [G].
        ii. Generate the 8 corner vertices of the cube centered at $C$ using offsets $\pm hvs$ [S4, unofficial].
        iii. Assign standard face normals and indices [S4, unofficial].
4.  **Finalization:** Return the set of occupied voxels or the constructed mesh [S1][S4, unofficial].

**Pseudocode:**
```python
def rasterize_mesh_to_voxels(vertices, faces, voxel_size, origin):
    """
    Rasterize a triangle mesh into a sparse set of voxel coordinates.
    vertices: list of [x, y, z]
    faces: list of [i, j, k] indices into vertices
    voxel_size: float or [sx, sy, sz]
    origin: [ox, oy, oz]
    """
    voxels = set()
    hvs = [v * 0.5 for v in voxel_size]
    
    # Helper to map world pos to voxel index
    def world_to_voxel_idx(p):
        return (
            int((p[0] - origin[0]) / voxel_size[0]),
            int((p[1] - origin[1]) / voxel_size[1]),
            int((p[2] - origin[2]) / voxel_size[2])
        )

    for face in faces:
        v0 = vertices[face[0]]
        v1 = vertices[face[1]]
        v2 = vertices[face[2]]
        
        # Compute bounding box in voxel space
        # Note: In practice, this requires careful handling of negative indices
        # and conservative expansion to avoid holes [S6, unofficial].
        min_idx = min(world_to_voxel_idx(v0), world_to_voxel_idx(v1), world_to_voxel_idx(v2))
        max_idx = max(world_to_voxel_idx(v0), world_to_voxel_idx(v1), world_to_voxel_idx(v2))
        
        # Expand bounds to cover partial overlaps (conservative rasterization logic)
        # [G] Simple expansion by 1 in each direction is a common approximation
        # for conservative rasterization without hardware support.
        min_idx = (min_idx[0] - 1, min_idx[1] - 1, min_idx[2] - 1)
        max_idx = (max_idx[0] + 1, max_idx[1] + 1, max_idx[2] + 1)
        
        for i in range(min_idx[0], max_idx[0] + 1):
            for j in range(min_idx[1], max_idx[1] + 1):
                for k in range(min_idx[2], max_idx[2] + 1):
                    # Check if triangle intersects voxel (i, j, k)
                    # [G] A robust implementation uses plane tests or barycentric coordinates.
                    # Here we assume a helper function exists.
                    if triangle_intersects_voxel(v0, v1, v2, i, j, k, voxel_size, origin):
                        voxels.add((i, j, k))
                        
    return voxels

def triangle_intersects_voxel(v0, v1, v2, i, j, k, voxel_size, origin):
    """
    Returns True if the triangle intersects the voxel cell (i,j,k).
    """
    # Calculate voxel bounds in world space
    x0 = origin[0] + i * voxel_size[0]
    y0 = origin[1] + j * voxel_size[1]
    z0 = origin[2] + k * voxel_size[2]
    x1 = x0 + voxel_size[0]
    y1 = y0 + voxel_size[1]
    z1 = z0 + voxel_size[2]
    
    # Simple AABB-Triangle intersection test
    # [G] Using a standard SAT or separating axis theorem implementation.
    # For brevity, we assume a standard library function or inline test.
    return aabb_triangle_intersect(
        [x0, y0, z0], [x1, y1, z1],
        v0, v1, v2
    )
```

**Parameters:**
*   `voxel_size`: Physical size of a voxel. Typical values: $1/256$ [S1], or $0.1$ to $0.75$ units [S2, unofficial].
*   `origin`: World coordinate of the $(0,0,0)$ voxel corner. Typically $[0,0,0]$ [S1].
*   `precision`: A tolerance factor used in some C implementations to reduce "holes" artifacts during rasterization. Typical value: $0.01$ [S2, S4, unofficial].
*   `gap_fraction`: Spacing between generated cubes in the output mesh. Typical value: $0.02$ [S1].

**Edge Cases and Pitfalls:**
*   **Holes:** Standard rasterization only covers pixels/voxels whose centers lie inside the triangle, leading to cracks at edges [S6, unofficial]. Conservative rasterization or bounding box expansion is required to fix this [S6, unofficial].
*   **Performance:** The output mesh size scales with voxel density. A torus with 800 faces can result in >140,000 vertices at small voxel sizes [S2, unofficial].
*   **Precision:** Floating-point errors in coordinate mapping can cause double-counting or missed voxels. Using integer grid indices for storage mitigates this [S3, unofficial].

## Subtopics

### [3D Grid Rasterization](903-3d-grid-rasterization.md)
A CPU-based algorithm that determines which voxels in a fixed-resolution 3D grid are intersected by a triangle mesh, producing a binary occupancy grid or a grid with interpolated colors. It solves the problem of converting continuous polygonal geometry into a discrete volumetric representation without performing surface reconstruction (such as QEF or dual vertex solving). It differs from full o-voxel implementations by omitting the face QEF, boundary QEF, and dual vertex solve steps, focusing solely on the intersect scanline to find occupied voxels. It differs from GPU-based siblings like [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on CPU-side scanline filling and hash-table deduplication rather than parallel fragment shaders.

### [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md)
GPU Volume Kernel Voxelization is a technique that accelerates the voxelization of triangle meshes by parallelizing the iteration over the 2D XY plane of the voxel grid using a GPU compute shader. It solves the performance bottleneck of CPU-based voxelization, where nested loops over X and Y coordinates are executed sequentially. Unlike rasterization-based alternatives that project geometry into 3D textures, this method retains the explicit triangle-voxel intersection logic of CPU implementations but distributes the workload across GPU threads, achieving significant speedups (e.g., 50x) for high-resolution grids.

### [GPU Voxelization via Compute Shaders](2549-gpu-voxelization-via-compute-shaders.md)
GPU Voxelization via Compute Shaders converts 3D triangle meshes into a uniform 3D voxel grid by leveraging GPU parallel processing. It solves the problem of generating volumetric data for real-time ray marching or volume rendering with high throughput. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md), which projects triangles via the fixed-function graphics pipeline, compute shader methods decouple intersection logic from rasterization, allowing custom geometric tests and atomic operations on 3D buffers or textures.

### [GPU Voxelization](2633-gpu-voxelization.md)
GPU Voxelization converts a triangle mesh into a regular voxel grid by leveraging the GPU's hardware rasterization pipeline to map fragments directly to 3D grid cells. It solves the performance bottleneck of CPU-based ray-tracing voxelization by parallelizing the intersection test across the rasterizer. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using a 3D texture UAV or SSBO as the direct write target rather than a 2D accumulation buffer, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by relying on standard triangle rasterization rather than volume kernels.

### [CPU Mesh Voxelization](3137-cpu-mesh-voxelization.md)
CPU Mesh Voxelization converts a triangle mesh into a 3D grid of voxels by iterating over the bounding box of each triangle and testing each voxel center against the triangle's plane and edge constraints. It differs from its parent [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly rasterizing triangles into a hash table of voxel centers and colors, then generating a cube mesh for each occupied voxel, whereas CPU Mesh Voxelization typically outputs a binary occupancy grid or bit-packed table. It differs from [3D Grid Rasterization](903-3d-grid-rasterization.md) by using exact geometric overlap tests (SAT or plane/projection) rather than simple grid cell intersection, and from [Voxelization via Triangle Scattering](3779-voxelization-via-triangle-scattering.md) by iterating cells against triangles rather than scattering triangles into cells.

### [Voxel Rasterization](3204-voxel-rasterization.md)
Voxel Rasterization converts a triangle mesh into a voxelized representation by rendering the geometry into a 3D voxel buffer, supporting both simple occupancy and normal/color mapping. It differs from its sibling [3D Grid Rasterization](903-3d-grid-rasterization.md) by explicitly iterating over triangle surfaces to calculate interpolated points and normals rather than relying on a pure grid traversal, and from [GPU Volume Kernel Voxelization](1496-gpu-volume-kernel-voxelization.md) by utilizing a Direct3D 11-based rendering pipeline or CUDA kernels for the rasterization step.

### [Conservative Rasterization via Triangle Expansion](3531-conservative-rasterization-via-triangle-expansion.md)
This method eliminates voxelization holes caused by standard rasterization, which only covers pixels whose centers lie inside a triangle, by expanding the triangle in clip space and culling the expanded area in the fragment shader. It differs from sibling methods like [Conservative Voxelization](3247-conservative-voxelization.md) by implementing the expansion logic manually in the geometry shader using homogeneous plane mathematics, rather than relying on hardware-specific conservative rasterization extensions or post-processing hole-filling.

### [Multi-view projection](5937-multi-view-projection.md)
Multi-view projection voxelization converts a triangle mesh into a voxel grid by rasterizing the geometry from multiple camera viewpoints, typically aligned with the principal axes of the scene's bounding box. This approach solves the coverage gaps and geometric distortions inherent in single-view projection methods, which fail when surface normals are perpendicular to the view direction. It differs from single-view methods by ensuring comprehensive coverage through redundancy, and from compute-shader-based methods by leveraging standard graphics pipeline rasterization.

### [Position Map and Image-Space Transfer](6237-position-map-and-image-space-transfer.md)
This family of techniques converts 3D geometric data into voxel grids by projecting or transferring information into 2D image space (textures) before reconstructing the 3D volume. Unlike direct 3D rasterization, these methods leverage the GPU's fixed-function rasterizer or image load/store operations on 2D textures to determine voxel occupancy, often trading memory bandwidth for computational simplicity. They are distinguished from direct triangle rasterization by operating on pre-computed surface samples or 2D texture slices, ensuring connectivity or enabling real-time performance insensitive to scene complexity.

### Rasterization-based Volume Modeling
The process of building volume data voxel-by-voxel, considered the third layer in the voxel modeling abstraction hierarchy [S5, unofficial]. It solves the problem of assigning density values to a voxel buffer from primitive representations. It differs from instantiation-based modeling by pulling values into a voxel (similar to raytracing), whereas instantiation-based modeling pushes values into voxels (similar to micropolygon rendering) [S5, unofficial]. The main loop iterates over voxels in the discrete bounding box, transforms voxel position to world space, samples the primitive, and adds the value to the buffer if positive [S5, unofficial].

### Single-Pass Voxelization
A voxelization approach that utilizes the geometry shader to reduce draw calls by selecting the axis from which each triangle has the largest overall projection for fragment generation [S6, unofficial]. It solves the problem of multiple draw calls required for multi-axis voxelization. It employs conservative rasterization to generate fragments as long as there is something inside the pixel, not only if its center is covered [S6, unofficial]. It uses an MSAA render target to solve the issue of incorrectly filling empty cells caused by excessive fragment generation from conservative rasterization [S6, unofficial]. Hardware support for conservative rasterization is available on Nvidia Maxwell architecture and later; RTX driver support is available for Turing and Pascal architecture GPUs [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot B)$, where $N$ is the number of triangles and $B$ is the average number of voxels in the triangle's bounding box. The complexity is linear with respect to the number of triangles and the grid resolution within the object's bounds [S1][S5, unofficial].
*   **Memory Complexity:** $O(V)$, where $V$ is the number of occupied voxels. Using a hash table (sparse voxelization) ensures memory usage is proportional to the surface area rather than the volume of the bounding box [S3, S4, unofficial].
*   **Performance:** GPU-based variants offer significant speedups (e.g., 50x) over CPU implementations for high-resolution grids [S1]. CPU implementations are simpler to debug but bottleneck on nested loops [S1].
*   **Strengths:** Fast, simple to implement, produces clean surface shells (no interior voxels unless explicitly filled) [S2, S5, unofficial].
*   **Limitations:** Can produce "holes" or cracks if not using conservative rasterization [S6, unofficial]. Output mesh size can be very large compared to the input mesh (e.g., 100x vertex count increase) [S2, unofficial].
*   **When to use:** Real-time voxelization for ray marching, voxel art generation, or when a sparse surface representation is sufficient [S1][S2, unofficial].
*   **When not to use:** When deep volumetric data (interior density) is required, or when exact manifold surface reconstruction is needed without post-processing [S2, S5, unofficial].

## Background
Rasterization-based voxelization originated from the need to convert standard polygonal meshes into voxel formats for volume rendering and voxel art applications. Early implementations relied on CPU-based scanline algorithms [S1]. The method gained prominence with the availability of GPU hardware rasterization, allowing for real-time voxelization via fragment shaders and compute shaders [S1][S6, unofficial]. Libraries such as Point-Cloud-Utils [S1] and the header-only C voxelizer [S4, unofficial] popularized efficient hash-based sparse voxelization techniques. The distinction between "pull" (rasterization) and "push" (instantiation) modeling was formalized in production volume rendering literature [S5, unofficial].
