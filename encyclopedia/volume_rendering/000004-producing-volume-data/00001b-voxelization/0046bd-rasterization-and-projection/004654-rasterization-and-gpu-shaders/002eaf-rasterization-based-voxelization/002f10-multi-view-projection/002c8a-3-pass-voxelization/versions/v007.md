# 3-Pass Voxelization
Also called: 3-Axis Voxelization, 3D Mesh Voxelization via Axis-Aligned Rasterization, Multi-View Voxelization

## Overview
3-Pass Voxelization is a rasterization-based technique that eliminates cracks and missing data in the voxel grid by rendering the scene geometry from three orthogonal view directions aligned with the principal axes (X, Y, and Z) [S1, S2, unofficial]. Unlike single-view projection methods which suffer from geometric distortion or gaps when viewing angles are oblique, this method ensures accurate voxel occupancy by covering the volume from every cardinal direction [S2, unofficial]. It is chosen when robustness against occlusion artifacts is prioritized over the computational cost of multiple draw calls [S1, unofficial].

## How it works
**Inputs:** Triangle mesh geometry; voxel grid resolution $R = (R_x, R_y, R_z)$; axis-aligned bounding box (AABB) defined by $bb_{min}$ and $bb_{max}$.
**Outputs:** A 3D occupancy texture or buffer where occupied voxels are marked.

**Data Structures:**
*   **Voxel Grid:** A 3D array or texture of size $R_x \times R_y \times R_z$.
*   **Matrices:**
    *   $P_{clip}$: Clip-space projection matrix.
    *   $M_{rot, A}$: Rotation matrix aligning the camera to axis $A \in \{X, Y, Z\}$.
    *   $M_{vox}$: Voxel-space transformation matrix mapping clip space to voxel indices.

**Steps:**
1.  **Coordinate System Setup:** Place the coordinate system at the center of the voxel grid, ensuring the axes are parallel to the grid edges [S2, unofficial].
2.  **Matrix Preparation:** Compute the voxel-space matrix $M_{vox}$. This matrix maps continuous coordinates to discrete integer indices $(i, j, k)$ based on the resolution and bounding box [S1, unofficial]. Note that $M_{vox}$ does not need to be multiplied by the rotation matrix, as it already maps values properly; the rotation is only required to generate fragments from the correct view direction [S1, unofficial].
3.  **Pass Execution:** For each axis $A \in \{X, Y, Z\}$:
    a. Construct the view matrix by multiplying the clip-space projection matrix $P_{clip}$ by the rotation matrix $M_{rot, A}$ corresponding to axis $A$ [S1, unofficial].
    b. Execute a rendering pass viewing the scene along the direction of axis $A$ (e.g., +Z, +X, +Y) [S2, unofficial].
    c. During rasterization, depth testing is typically disabled or configured to allow overwriting to ensure all intersected voxels are marked, as the goal is occupancy rather than surface visibility [Parent].
    d. Fragment positions are transformed into voxel grid indices using $M_{vox}$ [Parent].
    e. Write to the voxel grid using atomic operations to handle concurrent writes from multiple fragments or passes [Parent, G].
4.  **Completion:** After all three passes, the voxel grid contains the union of occupied voxels from all three axes.

**Parameters:**
*   **Rotation:** Standard configuration uses rotations aligning the camera with the principal axes [S1, S2, unofficial].
*   **Optimization:** Dynamic objects may be voxelized every frame while static objects are updated less frequently, requiring separate voxel grids for dynamic and static objects [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Performance:** Requires 3 render calls per object, which becomes expensive as model complexity increases [S1, unofficial].
*   **Memory:** If separating dynamic and static objects, two separate voxel grids are required because the dynamic grid must be cleared every frame [S1, unofficial].
*   **Precision:** Adjusting voxel grid resolution according to hardware capabilities can mitigate performance bottlenecks [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of triangles and $V$ is the number of voxels covered by the bounding box. The factor of 3 comes from the three passes.
*   **Memory Complexity:** $O(R_x \cdot R_y \cdot R_z)$ for the voxel grid. If dynamic/static separation is used, memory usage doubles.
*   **Strengths:** Eliminates cracks and missing data inherent in single-view projection; simple to implement [S1, S2, unofficial].
*   **Limitations:** High computational cost due to multiple render passes; not suitable for real-time applications with very complex models without optimization [S1, unofficial].
*   **When to use:** When voxel quality is critical and performance constraints allow for multiple passes.
*   **When not to use:** When real-time performance is paramount and the scene is highly complex, or when single-view artifacts are acceptable.

## Background
3-Pass Voxelization was introduced as a solution to the problem of cracks and missing data in voxel grids generated by single-direction rasterization [S1, unofficial]. It is described in the context of real-time ray-traced voxel global illumination, where robust voxel data is essential for accurate lighting calculations [S1, unofficial]. The method is also implemented in open-source projects such as the 3D-Mesh-Voxelizer [S2, unofficial].
