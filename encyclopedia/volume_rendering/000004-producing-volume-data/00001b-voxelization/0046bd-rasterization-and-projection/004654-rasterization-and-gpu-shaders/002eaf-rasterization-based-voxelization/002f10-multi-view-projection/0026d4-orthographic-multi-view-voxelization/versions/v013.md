# Orthographic Multi-View Voxelization

Also called: 3-Direction Rasterization, 3-View Voxelization, Directional Sheet Buffer Voxelization, Orthogonal Voxelization Camera Setup, Orthographic 3D Texture Rasterization, Voxelization via Orthographic Projection, Worksheet Voxelization

## Overview
Orthographic Multi-View Voxelization rasterizes scene geometry into a 3D texture using three orthographic cameras aligned with the scene's bounding box axes to create a voxelized representation for subsequent volume rendering [S2, unofficial]. It differs from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by using three orthogonal views to ensure complete coverage and from [3-Pass Voxelization](5300-3-pass-voxelization.md) by utilizing intermediate "sheet buffers" and a final "worksheet" synthesis to handle discrete voxel encoding efficiently on GPU hardware [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Triangle mesh geometry, scene axis-aligned bounding box (AABB) defined by `bb_min` and `bb_max`, and target voxel grid resolution $R = (R_x, R_y, R_z)$ [S2, unofficial].
*   **Output:** A 3D texture (Direct Method) or a 2D worksheet texture encoding 3D data (Indirect Method) representing the voxelized volume [S2, unofficial][S3, unofficial].

**Data Structures:**
1.  **3D Texture (Direct Method):** A `std::vector<GLfloat>` of size $4 \times R_x \times R_y \times R_z$, initialized to `0.0f`, representing RGBA32F voxel data [S2, unofficial].
2.  **Sheet Buffers (Indirect Method):** Three 2D buffers representing parts of the discrete voxel space, one for each axis direction (X, Y, Z) [S3, unofficial].
3.  **Worksheet (Indirect Method):** A 2D texture of resolution $2^W \times 2^H$. It encodes the discrete voxel space ($2^L \times 2^M \times 2^N$) such that $2^L \times 2^M \times 2^N = 2^W \times 2^H \times C$, where $C$ is the number of voxels encoded in a single texel (e.g., $C=32$ for binary voxelization with four 8-bit components) [S3, unofficial].

**Parameters:**
*   `voxelTextureSize`: Default resolution, e.g., `glm::uvec3(64, 64, 64)` [S2, unofficial].
*   `offset`: Camera extension distance beyond the bounding box, fixed at `0.2f` [S2, unofficial].
*   `projection_scale`: Frustum expansion factor applied to range, fixed at `1.02f` (passed as `0.51f` to half-width) [S2, unofficial].
*   `C`: Voxels per texel in the worksheet method [S3, unofficial].

**Steps:**

1.  **Bounding Box and Camera Setup:**
    Calculate the scene bounding box min/max. Compute the range $Range = bb_{max} - bb_{min}$. Set the camera offset to `0.2f` beyond the max bounds along each axis [S2, unofficial]. Configure three orthographic cameras looking towards the scene's AABB along the X, Y, and Z axes. Set the orthographic projection frustum bounds to $1.02 \times Range$ on the viewing planes, with near plane at `0.1f` and far plane at $1.2 \times Range + offset$ [S2, unofficial].

2.  **Rasterization (Stage 1):**
    For each of the three views (X, Y, Z):
    *   Pass the corresponding view-projection matrix to the voxelization shader uniform `viewProject[i]` [S2, unofficial].
    *   For each triangle, determine the axis direction along which it has the maximum projection area. Rasterize the triangle against this axis direction to avoid degenerate line segments caused by 2D linear interpolation when the triangle is parallel to the view [S3, unofficial].
    *   If using the **Direct Method**: Clear the 3D texture to RGBA(0,0,0,0), disable multisampling, depth testing, and face culling. Bind the texture as a read-write image buffer. Rasterize triangles directly into the 3D texture using atomic operations for occupancy [S2, unofficial].
    *   If using the **Indirect Method**: Rasterize triangles into the corresponding 2D Sheet Buffer. Only triangles intersecting the current slab are processed [S3, unofficial].

3.  **Texelization (Stage 2 - Indirect Method Only):**
    Transform voxel positions to 3D volume coordinates immediately. Use these coordinates to find the correct position in the worksheet. Add voxels to the worksheet via a blending operation at the corresponding location [S3, unofficial].

4.  **Synthesis (Stage 3 - Indirect Method Only):**
    Transcode the three directional sheet buffers to the final worksheet. Transform each element to discrete voxel space, then encode to the appropriate texel in the worksheet [S3, unofficial].
    *   **Voxel Access Logic:** To access a voxel at coordinates $(p_x, p_y, p_z)$:
        1.  Determine the patch by dividing $p_z$ by $C$.
        2.  Access the texel at $(p_x, p_y)$ in the found patch.
        3.  Determine the bit offset within the texel component using $p_z$ and $C$.
        4.  Use a lookup table to facilitate accessing bits from the component [S3, unofficial].

5.  **Finalization:**
    Generate mipmaps for the filled 3D texture (Direct Method) or the final worksheet (Indirect Method) to enable multi-resolution cone tracing [S2, unofficial].

**Pseudocode (Direct Method):**

```python
def orthographic_multi_view_voxelization(mesh, bb_min, bb_max, voxel_size):
    """
    Voxelizes a mesh into a 3D texture using 3 orthographic views.
    """
    # 1. Setup
    range_vec = [bb_max[i] - bb_min[i] for i in range(3)]
    offset = 0.2
    scale = [voxel_size[i] / range_vec[i] for i in range(3)]
    max_extent = max(range_vec)
    center = [(bb_min[i] + bb_max[i]) / 2.0 for i in range(3)]

    # Initialize 3D texture (RGBA32F)
    texture_size = voxel_size[0] * voxel_size[1] * voxel_size[2] * 4
    voxel_texture = [0.0] * texture_size

    # Camera configurations for X, Y, Z views
    cameras = [
        {"pos": [center[0] + max_extent + offset, center[1], center[2]], "look": [-1.0, 0.0, 0.0], "up": [0.0, 1.0, 0.0]},
        {"pos": [center[0], center[1] + max_extent + offset, center[2]], "look": [0.0, -1.0, 0.0], "up": [0.0, 0.0, 1.0]},
        {"pos": [center[0], center[1], center[2] - max_extent - offset], "look": [0.0, 0.0, 1.0], "up": [0.0, 1.0, 0.0]}
    ]

    for cam in cameras:
        for tri in mesh.triangles:
            # Determine axis with max projection area to avoid degenerate rasterization
            v0, v1, v2 = tri.vertices
            normal = cross(v1 - v0, v2 - v0)
            max_axis = max(range(3), key=lambda i: abs(normal[i]))

            # Project vertices to clip space [-1, 1]
            clip_coords = [[(v[i] - cam["pos"][i]) / (0.51 * max_extent) for i in range(3)] for v in (v0, v1, v2)]

            # Rasterize into 3D texture using atomic OR for occupancy
            rasterize_triangle_to_grid(clip_coords, voxel_texture, scale, bb_min, max_axis)

    generate_mipmaps(voxel_texture)
    return voxel_texture
```

```python
def worksheet_voxelization(mesh, bb_min, bb_max, voxel_res, texel_voxels_c):
    """
    Voxelizes a mesh into a 2D worksheet texture using 3 sheet buffers.
    """
    # 1. Setup
    range_vec = [bb_max[i] - bb_min[i] for i in range(3)]
    offset = 0.2
    max_extent = max(range_vec)
    center = [(bb_min[i] + bb_max[i]) / 2.0 for i in range(3)]

    sheet_buffers = [[0] * (voxel_res[0] * voxel_res[1]) for _ in range(3)]

    cameras = [
        {"pos": [center[0] + max_extent + offset, center[1], center[2]], "look": [-1.0, 0.0, 0.0], "up": [0.0, 1.0, 0.0]},
        {"pos": [center[0], center[1] + max_extent + offset, center[2]], "look": [0.0, -1.0, 0.0], "up": [0.0, 0.0, 1.0]},
        {"pos": [center[0], center[1], center[2] - max_extent - offset], "look": [0.0, 0.0, 1.0], "up": [0.0, 1.0, 0.0]}
    ]

    # 2. Rasterization Stage
    for view_idx, cam in enumerate(cameras):
        for tri in mesh.triangles:
            v0, v1, v2 = tri.vertices
            normal = cross(v1 - v0, v2 - v0)
            max_axis = max(range(3), key=lambda i: abs(normal[i]))

            if max_axis == view_idx:
```

## Subtopics

### [Shadow Volume Voxelization](5629-shadow-volume-voxelization.md)
Shadow Volume Voxelization generates a 3D shadow volume texture by voxelizing scene geometry into a 3D grid, where each voxel stores a bitmask representing which of its 8 constituent sub-voxels are occluded. It replaces standard occupancy flags with a bitmask per coarse voxel to enable multi-resolution shadow representation through mipmaps.

### Slicing-based voxelization
Slicing-based voxelization rasterizes the model the same number of times as the resolution of the volume along the z-direction [S3, unofficial]. This feature (rendering to 3D textures) has not been supported in consumer graphics hardware of PC platform at the time of writing [S3, unofficial]. It is significantly slower than the proposed 2D texture method; for the Blade model at $256^3$, it takes ~5 seconds compared to ~100ms for the proposed method [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of triangles and $V$ is the number of views (3) [G]. The indirect method adds a synthesis step proportional to the number of fragments [S3, unofficial].
*   **Memory Complexity:** $O(R_x R_y R_z)$ for the direct method [G]. The indirect method uses $O(R_x R_y)$ for sheet buffers and $O(R_x R_y / C)$ for the worksheet, reducing memory footprint [S3, unofficial].
*   **Performance:** The worksheet method is significantly faster than slicing-based voxelization. For a $256^3$ resolution, the worksheet method takes ~100ms, while slicing-based takes ~5 seconds [S3, unofficial].
*   **Strengths:** Hardware-accelerated, real-time capable, handles complex models efficiently [S3, unofficial].
*   **Limitations:** Requires careful handling of degenerate triangles (parallel to rasterization direction) [S3, unofficial]. The indirect method requires additional synthesis pass and lookup logic [S3, unofficial].
*   **When to use:** Real-time volume rendering, shadow volume generation [S5, unofficial].
*   **When not to use:** When high-precision solid voxelization is required without post-processing (requires 3D scan-filling) [S3, unofficial].

## Background
The method was introduced in "Real-time Voxelization for Complex Models" [S3, unofficial] as a scheme to solve the problem of fast voxelization for interactive graphics applications by representing the resultant volume as 2D textures. The direct method implementation is found in "Voxel Cone Tracing" [S2, unofficial].
