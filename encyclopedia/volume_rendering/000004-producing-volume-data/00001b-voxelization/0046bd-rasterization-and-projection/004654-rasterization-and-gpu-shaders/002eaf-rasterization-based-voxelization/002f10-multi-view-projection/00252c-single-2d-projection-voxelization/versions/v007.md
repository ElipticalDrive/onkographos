# Single 2D Projection Voxelization

Also called: Dominant axis voxelization, Thin voxelization via single projection

## Overview
Single 2D Projection Voxelization is a method for producing 6-separating (tunnel-free) voxelization using only a single 2D rasterization pass along the dominant axis of a triangle's normal vector [S1, unofficial]. It leverages the "thinness" property of 6-separating voxelization to eliminate the need for multi-view accumulation, significantly reducing computational cost compared to siblings like [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md). It is chosen when performance is critical and the input geometry consists primarily of planar triangles, provided the dominant axis selection strategy is robust.

## How it works
**Inputs:** A planar triangle defined by three vertices in 3D space; a voxel grid resolution; a voxel size.
**Outputs:** A set of voxels (3D grid cells) that form a 6-separating representation of the triangle.

**Data Structures:**
*   **Triangle:** Defined by vertices $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$.
*   **Normal:** $\mathbf{n} = (\mathbf{v}_1 - \mathbf{v}_0) \times (\mathbf{v}_2 - \mathbf{v}_0)$, normalized.
*   **Voxel Grid:** 3D array or hash map mapping $(i, j, k)$ indices to occupancy status.
*   **Pixel Buffer:** 2D buffer storing depth values or occupancy for the projected view.

**Steps:**

1.  **Identify Dominant Axis:**
    Compute the absolute values of the normal vector components $|n_x|, |n_y|, |n_z|$. Select the axis with the maximum absolute value as the projection axis (e.g., if $|n_z|$ is max, project along the Z-axis onto the XY plane). This axis is the "dominant axis" [S1, unofficial].

2.  **Project and Rasterize:**
    Project the triangle vertices onto the 2D plane perpendicular to the dominant axis. Rasterize this 2D triangle into a pixel buffer. For each pixel $(u, v)$ covered by the projection:
    *   Determine if the pixel center $(u+0.5, v+0.5)$ lies inside the projected triangle.
    *   Determine if the pixel contains an edge of the triangle but does not contain the center.

3.  **Process Center Pixels:**
    For pixels where the projected triangle contains the pixel center:
    *   Evaluate the depth of the triangle at the pixel center. Let the pixel center in 2D be $\mathbf{p}_{center}$. The 3D point on the triangle is $\mathbf{P}_{center}$.
    *   Determine the voxel index $k$ along the dominant axis corresponding to the depth of $\mathbf{P}_{center}$. Specifically, output the voxel whose center depth is closest to the depth of the triangle evaluated at the pixel center [S1, unofficial]. This corresponds to intersecting the triangle against the crosshair segment parallel to the projection axis.

4.  **Process Edge Pixels (Horizontal Test):**
    For pixels that contain an edge of the triangle but where the triangle does not overlap the center:
    *   Find the intersection points of the triangle edges with the horizontal line bisecting the pixel (i.e., the line $y = v + 0.5$ in the projection plane). Let these horizontal extents be $x_{min}$ and $x_{max}$.
    *   Clamp these extents to the horizontal pixel extents $[u, u+1]$.
    *   Evaluate the depth of the triangle at these two clamped points $(x_{min}, v+0.5)$ and $(x_{max}, v+0.5)$. Let these depths be $d_{min}$ and $d_{max}$.
    *   Let $d_{voxel}$ be the depth of the center of the voxel column at $(u, v)$ along the dominant axis.
    *   If $d_{min}$ and $d_{max}$ are on different sides of $d_{voxel}$ (i.e., $(d_{min} - d_{voxel}) \times (d_{max} - d_{voxel}) < 0$), output the corresponding voxel [S1, unofficial].

5.  **Process Edge Pixels (Vertical Test):**
    If the horizontal test fails (values are not on different sides):
    *   Repeat the test for the vertical direction. Find the intersection points of the triangle edges with the vertical line bisecting the pixel ($x = u + 0.5$).
    *   Clamp these vertical extents to the vertical pixel extents $[v, v+1]$.
    *   Evaluate the depth of the triangle at these two clamped points.
    *   If the evaluated depths are on different sides of the voxel's center depth, output the corresponding voxel [S1, unofficial].

    # 1. Identify Dominant Axis
    v0, v1, v2 = triangle.vertices
    normal = cross(v1 - v0, v2 - v0)
    abs_normal = abs(normal)
    
    # Select axis with max component
    if abs_normal.x >= abs_normal.y and abs_normal.x >= abs_normal.z:
        proj_axis = 'x'
        plane_coords = lambda p: (p.y, p.z)
    elif abs_normal.y >= abs_normal.x and abs_normal.y >= abs_normal.z:
        proj_axis = 'y'
        plane_coords = lambda p: (p.x, p.z)
    else:
        proj_axis = 'z'
        plane_coords = lambda p: (p.x, p.y)
        
    # Project vertices

**Edge Cases and Pitfalls:**
*   **Degenerate Triangles:** If the triangle normal is zero (degenerate triangle), the dominant axis is undefined. [G] Handle by skipping or treating as a line/point.
*   **Parallel Edges:** If an edge is parallel to the bisecting line, the intersection test may fail or return a single point. [G] Ensure robust geometric predicates.
*   **Precision:** Depth comparisons must be robust to floating-point errors. [G] Use a small epsilon for side-of-plane tests.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R)$, where $N$ is the number of triangles and $R$ is the number of pixels covered by the projection. Significantly faster than multi-view methods which require $3 \times$ or more rasterization passes.
*   **Memory Complexity:** $O(V)$, where $V$ is the number of voxels in the grid. No additional buffers for multiple views are needed.
*   **Strengths:** High performance due to single pass; produces 6-separating (tunnel-free) results.
*   **Limitations:** Relies on the "thinness" property, which holds for 6-separating voxelization. May produce artifacts if the dominant axis selection is poor (e.g., if the triangle is nearly perpendicular to the dominant axis, though the method is designed to handle this via the edge tests). Not suitable for non-planar geometry without tessellation.
*   **When to use:** When 6-separating voxelization is required and performance is a priority. Ideal for real-time applications or large-scale geometry processing.
*   **When not to use:** When higher-order separation (e.g., 18- or 26-separating) is required, or when the input geometry is not composed of planar triangles.

## Background
The method is derived from the "thinness" property of 6-separating voxelization, which states that the voxelization of a planar triangle is "thin" in the sense that it does not contain any 6-tunnels [S1, unofficial]. The equivalence of 3-axis rasterization with the crosshairs target was established in earlier work [FBP09, CNS*11]. The single 2D projection method was presented as an interesting corollary in "A Topological Approach to Voxelization" by Laine et al. (2013) [S1, unofficial]. It simplifies the voxelization process by reducing the number of required projections from three to one, leveraging the fact that the dominant axis projection captures all necessary voxels for the center pixels, and the edge tests handle the remaining cases.
