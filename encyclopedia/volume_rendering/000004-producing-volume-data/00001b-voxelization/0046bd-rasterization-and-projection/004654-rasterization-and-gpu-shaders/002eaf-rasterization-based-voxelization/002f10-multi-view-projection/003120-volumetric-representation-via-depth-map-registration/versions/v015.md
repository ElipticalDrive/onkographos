# Volumetric Representation via Depth Map Registration

Also called: Sparse Multi-View Volumetric Representation, Sparse Non-Lambertian Multi-view Volume Construction, Volume Initialization

## Overview
This method constructs a 3D volumetric representation from a sparse set of calibrated multi-view images by registering estimated depth maps into a voxel grid [S1, S2]. It specifically addresses non-Lambertian reflections by using individual minimum cost per view rather than a global threshold, and represents scene geometry as a sparse voxel cloud where voxel values indicate the number of views mapping to that location [S1, S2]. Unlike static voxelization methods that simply mark occupancy, this approach includes an iterative refinement stage to smooth sharp corners and remove scattering voxels, ensuring the volume accurately represents the real scene for virtual view synthesis [S1, S2]. It builds on [Multi-view projection](5937-multi-view-projection.md) by utilizing the registered depth maps as the primary geometric input.

## How it works
**Inputs:**
*   A set of $N$ calibrated reference views (images and camera parameters).
*   Estimated depth maps for each reference view, where depth estimation compensates for non-Lambertian reflection using individual minimum cost [S1, S2].
*   A 3D voxel grid defined by resolution $(R_x, R_y, R_z)$ and bounding box, as established in [Multi-view projection](5937-multi-view-projection.md).

**Outputs:**
*   A refined sparse voxel volume where each voxel $(i, j, k)$ holds an integer value $\delta_{ijk}$ representing the count of views mapping to it, and associated color data.

**Data Structures:**
*   **Voxel Grid:** A 3D array or sparse hash map. Each voxel stores:
    *   $\delta_{ijk}$: Integer count of views mapping to this voxel.
    *   $C_{ijk}$: Color value (Y, U, V or RGB) assigned during color selection.
*   **Depth Map:** 2D array of depth values $d$ for each pixel in a reference view.

**Algorithm Steps:**

1.  **Volume Initialization (Registration):**
    For each reference view $v \in \{1, \dots, N\}$, project the estimated depth map into the 3D voxel grid. For every voxel $(i, j, k)$, count the number of views that register a depth value to that location.
    The voxel value $\delta_{ijk}$ is defined as [S1, S2]:
    $$
    \delta_{ijk} = \begin{cases} 
    n & \text{if registering depth} \\
    0 & \text{otherwise}
    \end{cases}
    $$
    where $n \in \{1, 2, \dots, N\}$ is the number of views mapped to voxel $(i, j, k)$, and $N$ is the total number of reference views.

2.  **Isolated Voxel Removal:**
    Detect voxels with $\delta_{ijk} > 0$ that have no neighbors (voxels with $\delta > 0$ in the 6-connected or 26-connected neighborhood). These are likely errors and are removed (set $\delta_{ijk} = 0$) [S1, S2].

3.  **Back-Projection and Depth Refinement:**
    Project the current volume back to the reference view geometry to build new depth maps.
    *   If multiple depth values exist for a pixel (due to noise or multiple surfaces), consider the front cluster of depths.
    *   Let $K$ be the number of depth values in the front cluster. Let $d_k$ be the depth value and $\delta_k$ be the voxel weight (count) for the $k$-th depth.
    *   Calculate the proper depth value $d$ for the pixel [S1, S2]:
        $$
        d = \begin{cases} 
        d_n & \text{if only one depth has } \delta_n = \max(\delta) \\
        \frac{\sum_{k=1}^{K} \delta_k d_k}{\sum_{k=1}^{K} \delta_k} & \text{otherwise}
        \end{cases}
        $$
    *   Reconstruct the volume again using these refined depths. Interpolate voxels to connect the surface of the volume among near voxels [S1, S2].

4.  **Iterative Volume Refinement:**
    This step cleans and smooths the sparse voxel cloud [S1, S2].
    *   **Temporary Coloring:** Assign temporary colors to voxels using the median of color values from all visible views. The median is less sensitive to extreme values than the mean [S2].
    *   **Error Calculation:** Iterate through reference views (e.g., left to right). For each view, calculate the Mean Square Error (MSE) between the reconstructed view (using temporary colors) and the original reference image. Use window-based computation (e.g., $3 \times 3$ pixels) to handle calibration imperfections and unequal resolutions [S2].
    *   **Voxel Update:** If the MSE for a pixel exceeds a threshold:
        1.  Remove the old depth and its associated voxel.
        2.  Investigate a new depth derived from neighboring pixels (smooth surface assumption).
        3.  If the new depth satisfies color constraints for all visible views, generate the new associated voxel.
    *   **Reconstruction:** If any voxels are removed or generated, iteratively reconstruct the images repeatedly. This is necessary because the change in voxel position produces a new depth, which might change an invisible point to a visible point and vice versa [S2].

5.  **Color Selection:**
    Post-process colors for each voxel to handle non-Lambertian reflectance [S2].
    *   For a voxel $x$, consider two views 1 and 2 with lines $L_1$ and $L_2$ passing through the voxel.
    *   Let $C_1, C_2$ be the intensity (Y) or color (U,V) components. Let $a_1, a_2$ be the angles between the voxel $x$ and the points on lines $L_1, L_2$ respectively.
    *   Calculate blended color $C$:
        $$
        C = \begin{cases} 
        \frac{a_1 C_2 + a_2 C_1}{a_1 + a_2} & \text{if condition is true} \\
        C_1 & \text{otherwise}
        \end{cases}
        $$
    *   **Blur Handling:** If the difference between $C_1$ and $C_2$ is significant, the average method causes object blur. Define a "blur group" if $|C_1 - C_2| > \text{threshold}$, and a "clear group" otherwise. For voxels in the blur group, replace the color $C_{old}$ with the color of a neighboring voxel that has the closest value to $C_{old}$ and belongs to the clear group [S2].

**Pseudocode:**

```python
def volumetric_representation_via_depth_map_registration(reference_views, depth_maps, voxel_grid):
    """
    reference_views: List of N view objects (camera params, image data)
    depth_maps: List of N 2D arrays (depth values)
    voxel_grid: 3D structure supporting sparse storage, initialized to 0
    """
    
    # Step 1: Volume Initialization
    for view_idx, depth_map in enumerate(depth_maps):
        for y, x in pixels_in_view(view_idx):
            d = depth_map[y, x]
            if d is not None:
                voxel_coords = project_to_voxel(view_idx, d)
                voxel_grid[voxel_coords].count += 1
                
    # Step 2: Isolated Voxel Removal
    voxels_to_remove = []
    for voxel in voxel_grid.non_zero_voxels():
        if not has_neighbors(voxel, voxel_grid):
            voxels_to_remove.append(voxel)
    for voxel in voxels_to_remove:
        voxel_grid[voxel].count = 0
        
    # Step 3: Back-Projection and Depth Refinement
    for view_idx in range(len(reference_views)):
        new_depth_map = create_empty_depth_map()
        for y, x in pixels_in_view(view_idx):
            front_cluster = get_front_cluster_depths(view_idx, y, x, voxel_grid)
            if front_cluster:
                # front_cluster is list of (d_k, delta_k)
                max_delta = max(k[1] for k in front_cluster)
                unique_max = sum(1 for k in front_cluster if k[1] == max_delta)
                
                if unique_max == 1:
                    d = next(k[0] for k in front_cluster if k[1] == max_delta)
                else:
                    sum_delta_d = sum(k[0] * k[1] for k in front_cluster)
                    sum_delta = sum(k[1] for k in front_cluster)
                    d = sum_delta_d / sum_delta
                new_depth_map[y, x] = d
        # Update depth maps for next iteration or volume reconstruction
        depth_maps[view_idx] = new_depth_map
        
    # Reconstruct volume with refined depths (interpolation implied)
    voxel_grid = reconstruct_volume(depth_maps, voxel_grid)
    
    # Step 4: Iterative Volume Refinement
    converged = False
    while not converged:
        converged = True
        for view_idx in range(len(reference_views)):
            # Temporary coloring
            assign_temp_colors(voxel_grid, reference_views)
            
            # MSE Calculation with window
            mse_map = calculate_mse_windowed(reference_views[view_idx].image, 
                                             render_view(voxel_grid, reference_views[view_idx]), 
                                             window_size=3)
            
            # Update voxels based on threshold
            for y, x in pixels_in_view(view_idx):
                if mse_map[y, x] > threshold:
                    # Remove old voxel
                    old_depth = depth_maps[view_idx][y, x]
                    voxel_coords = project_to_voxel(view_idx, old_depth)
                    voxel_grid[voxel_coords].count = 0
                    
                    # Investigate new depth from neighbors
                    new_depth = estimate_smooth_depth(view_idx, y, x, depth_maps)
                    
                    # Check color constraints
                    if satisfies_color_constraints(new_depth, voxel_coords, reference_views):
                        # Generate new voxel
                        new_voxel_coords = project_to_voxel(view_idx, new_depth)
                        voxel_grid[new_voxel_coords].count = 1
                        converged = False # Need to re-evaluate visibility
    return voxel_grid

def calculate_color_blend(C1, C2, a1, a2):
    """
    C1, C2: Color components (Y or U,V)
    a1, a2: Angles between voxel and points on lines L1, L2
    """
    if abs(C1 - C2) > blur_threshold:
        # Blur group: replace with closest neighbor in clear group
        # Implementation detail: search neighbors for clear group with min |C_neighbor - C1|
        return find_closest_clear_neighbor_color(C1)
    else:
        # Clear group: blend
        return (a1 * C2 + a2 * C1) / (a1 + a2)
```

## Subtopics

### [Iterative Volume Refinement](6473-iterative-volume-refinement.md)
Iterative Volume Refinement is a post-initialization algorithm that cleans and smooths a sparse voxel cloud generated from multi-view depth maps by removing scattering voxels and smoothing sharp corners to increase coding gain. It distinguishes itself from static voxelization by dynamically regenerating voxels based on a smooth surface assumption and iteratively re-evaluating visibility, ensuring the final volume accurately represents the real scene for virtual view synthesis.

## Operating characteristics
*   **Time Complexity:** The initialization step is $O(N \cdot W \cdot H)$ where $N$ is the number of views and $W \times H$ is the image resolution. The refinement step is iterative and depends on the convergence rate, potentially requiring multiple passes over the views and voxels.
*   **Memory Complexity:** Proportional to the number of non-zero voxels in the sparse volume. The sparse representation is efficient for scenes with limited depth coverage.
*   **Strengths:** Handles non-Lambertian reflections effectively by using per-view minimum cost. The iterative refinement removes noise and sharp corners, improving coding gain for compression. The back-projection step corrects registration errors.
*   **Limitations:** Requires accurate initial depth maps. The iterative refinement can be computationally expensive. Color blending may cause blur if color components differ significantly between views [S2].
*   **When to use:** Sparse multi-view synthesis where coding efficiency and view quality are critical, and the scene has non-Lambertian properties.
*   **When not to use:** Dense volumetric rendering where every voxel must be filled, or real-time applications where iterative refinement is too slow.

## Background
This method was proposed by N. Anantrasirichai, C. Nishan Canagarajah, David W. Redmill, and David R. Bull from the University of Bristol [S2]. It was introduced in 2006 as a novel volumetric representation for sparse multi-view images of non-Lambertian scenes [S2]. The work was later expanded upon in a 2010/2011 publication focusing on color volumetric compression for realistic view synthesis applications [S1]. The method is used in 3D visual environments for communication and computer vision, particularly in applications requiring efficient storage and high-quality view synthesis from sparse camera arrays [S2].
