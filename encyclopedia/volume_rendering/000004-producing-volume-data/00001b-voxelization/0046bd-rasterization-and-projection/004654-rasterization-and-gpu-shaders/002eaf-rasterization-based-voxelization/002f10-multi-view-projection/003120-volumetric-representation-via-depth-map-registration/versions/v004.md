# Volumetric Representation via Depth Map Registration

Also called: Sparse Non-Lambertian Multi-view Volume Construction, Volume Initialization

## Overview
Constructs a 3D volume from multi-view images by registering estimated depth maps into a voxel grid, specifically handling non-Lambertian reflections through per-view cost minimization rather than global thresholds [S1]. It represents scene geometry as a sparse voxel cloud where voxel values indicate the count of views mapping to that location, distinguishing itself from sibling methods by explicitly refining the volume shape iteratively to remove scattering voxels and smooth sharp corners for improved coding gain [S1].

## How it works
**Inputs:** A set of $N$ reference views (images and camera parameters); estimated depth maps for each view.
**Outputs:** A 3D voxel grid where each voxel $(i, j, k)$ holds an integer weight $\delta_{ijk}$ representing the number of views mapping to it, and associated color data.

**Data Structures:**
*   **Voxel Grid:** A 3D array indexed by $(i, j, k)$.
*   **Voxel Value:** $\delta_{ijk} \in \{0, 1, \dots, N\}$.
*   **Depth Cluster:** For each pixel in a reference view, a list of candidate depths derived from projected voxels.

**Algorithm Steps:**

1.  **Depth Estimation with Non-Lambertian Compensation:**
    For each reference view, estimate a depth map by searching along the view's geometry. Use an individual minimum cost function per view to handle non-Lambertian reflections, avoiding a global threshold [S1].

2.  **Volume Initialization (Registration):**
    Register the estimated depth maps into the 3D volume. For each voxel at location $(i, j, k)$:
    *   If a depth is registered to this voxel from a view, increment the count.
    *   The value $\delta_{ijk}$ is set to $n$, where $n$ is the number of views mapping to this voxel ($n \in \{1, \dots, N\}$).
    *   If no depth is registered, $\delta_{ijk} = 0$ [S1].
    
    $$
    \delta_{ijk} = 
    \begin{cases} 
    n & \text{if registering depth} \\
    0 & \text{otherwise}
    \end{cases}
    $$

3.  **Error Removal and Depth Selection:**
    Detect isolated voxels with no neighbors. Project the current volume back to the reference view geometry to build new depth maps, removing errors from the previous step [S1].
    *   If multiple depth values exist for a pixel, consider the "front cluster" of depths.
    *   Select the proper depth value $d$ for a pixel using the following weighted logic, where $K$ is the number of depth values in the front cluster, $d_k$ is the depth value, and $\delta_k$ is the voxel weight associated with that depth:
    
    $$
    d = 
    \begin{cases} 
    d_n & \text{if only one depth has } \delta_n = \max(\delta_K) \\
    \frac{\sum_{k=1}^{K} \delta_k d_k}{\sum_{k=1}^{K} \delta_k} & \text{otherwise}
    \end{cases}
    $$
    
    *   If the maximum $\delta$ appears in two or more depth values, the fit depth value is calculated from the average of all depth values of the front cluster weighted by $\delta$ [S1].

4.  **Volume Reconstruction and Interpolation:**
    Reconstruct the volume using the selected depths. Interpolate voxels to connect the surface of the volume among near voxels, filling gaps left by isolated or removed voxels [S1].

5.  **Iterative Volume Refinement:**
    Refine the shape by removing scattering voxels and smoothing sharp corners to increase coding gain [S1].
    *   **Color Assignment:** Temporarily define voxel colors by taking the median of color values from all visible views [S1].
    *   **Iteration Loop:** Iterate through reference views (e.g., from furthest left to furthest right).
    *   **Error Calculation:** For each view, calculate the Mean Square Error (MSE) between the reconstructed view and the original reference image. Use a window-based computation (e.g., $3 \times 3$ pixels) to handle inaccurate camera calibration and unequal resolutions [S1].
    *   **Voxel Removal/Generation:**
        *   If MSE exceeds a threshold, remove the old depth and its associated voxel.
        *   Investigate a new depth derived from neighboring pixels based on a smooth surface assumption.
        *   If the new depth meets color constraints for all visible views, generate the new associated voxel [S1].
    *   **Reconstruction:** If voxels are removed or generated, iteratively reconstruct images because voxel position changes affect visibility (an invisible point may become visible and vice versa) [S1].
    *   **Termination:** Repeat until no new voxels are generated and no old voxels are removed [S1].

**Pseudocode:**

```python
def volumetric_representation_via_depth_map_registration(reference_views, initial_depth_maps):
    """
    reference_views: List of view objects containing image, camera matrix, and resolution.
    initial_depth_maps: List of depth maps estimated for each reference view.
    Returns: VoxelGrid (3D array of weights), ColorGrid (3D array of colors)
    """
    N = len(reference_views)
    # Initialize voxel grid with zeros
    # Dimensions determined by the bounding box of all reference views
    voxel_grid = initialize_voxel_grid(N) 
    
    # Step 1 & 2: Registration
    for view_idx, view in enumerate(reference_views):
        depth_map = initial_depth_maps[view_idx]
        # Register depth map into voxel grid
        # For each pixel (u, v) in depth_map with depth d:
        #   project d into 3D space using view camera
        #   find voxel (i, j, k) containing this point
        #   increment voxel_grid[i, j, k]
        register_depth_map(view, depth_map, voxel_grid)

    # Step 3: Error Removal and Depth Selection
    refined_depth_maps = []
    for view_idx, view in enumerate(reference_views):
        # Project current volume back to view geometry
        projected_depths = project_volume_to_view(voxel_grid, view)
        
        # Select proper depth for each pixel
        final_depth_map = select_depth_for_view(projected_depths, view)
        refined_depth_maps.append(final_depth_map)

    # Step 4: Reconstruction and Interpolation
    voxel_grid = reconstruct_volume(refined_depth_maps, voxel_grid)
    interpolate_voxels(voxel_grid)

    # Step 5: Iterative Refinement
    # Temporarily assign colors
    color_grid = assign_median_colors(voxel_grid, reference_views)
    
    converged = False
    while not converged:
        converged = True
        # Iterate through views
        for view_idx, view in enumerate(reference_views):
            # Reconstruct view from current volume
            reconstructed_view = render_volume(voxel_grid, color_grid, view)
            
            # Calculate MSE using window-based computation (e.g., 3x3)
            mse = calculate_windowed_mse(reconstructed_view, view.image, window_size=3)
            
            if mse > threshold:
                # Remove old depth and associated voxel
                old_depth = get_depth_from_view(view, voxel_grid)
                remove_voxel(view, old_depth, voxel_grid)
                converged = False
                
                # Investigate new depth from neighbors (smooth surface assumption)
                new_depth = estimate_new_depth_from_neighbors(view, voxel_grid)
                
                # Check color constraints for all visible views
                if meets_color_constraints(new_depth, voxel_grid, reference_views):
                    # Generate new voxel
                    add_voxel(view, new_depth, voxel_grid)
                    converged = False
                    # Update color grid if necessary
                    color_grid = update_colors(voxel_grid, reference_views)

    return voxel_grid, color_grid
```

## Subtopics

### Iterative Volume Refinement
An iterative algorithm to refine the shape of the volume by removing scattering voxels and smoothing sharp corners to increase coding gain [S1]. It compares reconstructed views against original reference images to identify and correct geometry errors, using window-based MSE calculation to handle calibration inaccuracies [S1]. Choose this when high-fidelity reconstruction for view synthesis is required and computational cost allows for iterative processing.

## Operating characteristics
*   **Time Complexity:** The initialization step is linear with respect to the number of voxels and views. The refinement step is iterative; the source notes 26 iterations for a five-view sequence [S1]. Each iteration involves rendering all views and calculating MSE, making it computationally expensive.
*   **Memory Complexity:** Proportional to the volume of the voxel grid. The method produces a sparse representation where $\delta_{ijk}=0$ for unmapped voxels, but the grid structure itself may require significant memory if the bounding box is large.
*   **Strengths:** Handles non-Lambertian reflections effectively via per-view cost minimization [S1]. Produces a clean volume with reduced scattering and smoothed corners, improving coding gain for compression [S1].
*   **Limitations:** Computationally intensive due to iterative refinement and repeated volume reconstruction/rendering [S1]. Sensitive to camera calibration errors, mitigated by window-based MSE but still requiring robust handling [S1].
*   **When to use:** When the goal is high-quality volumetric representation for view synthesis with compression in mind, and multi-view data is available.
*   **When not to use:** When real-time performance is critical, or when the scene is highly dynamic and iterative refinement is too slow.

## Background
Originated in the context of color volumetric compression for realistic view synthesis applications [S1]. The method builds on the principle that depth registration provides a good representation for natural scenery [S1]. It was developed to address issues with non-Lambertian reflections and scattering voxels in multi-view volume construction, aiming to improve coding gain by refining the volume shape [S1].
