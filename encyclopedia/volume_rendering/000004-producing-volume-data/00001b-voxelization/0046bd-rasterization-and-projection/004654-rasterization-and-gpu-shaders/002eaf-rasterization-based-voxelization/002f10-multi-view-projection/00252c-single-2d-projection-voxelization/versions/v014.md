# Single 2D Projection Voxelization
Also called: Dominant axis voxelization, Thin voxelization via single projection
## Overview
This method produces a 6-separating (tunnel-free) voxelization of a triangle mesh using only a single 2D rasterization pass along the dominant axis of each triangle's normal vector [S1, unofficial]. It leverages the "thinness" property of crosshair-based voxelization to prove that projecting along the dominant axis is sufficient to capture all voxels in the corresponding column, eliminating the need for the three orthogonal passes required by standard multi-view methods [S1, unofficial]. It is chosen when computational cost must be minimized by reducing rasterization overhead, accepting the complexity of edge-case handling for pixels intersected only by triangle boundaries.
## How it works
**Inputs:** A triangle mesh defined by vertices $\mathbf{v}_i$ and face normals $\mathbf{n}$. A voxel grid resolution $R = (R_x, R_y, R_z)$ and bounding box $[bb_{min}, bb_{max}]$.
**Outputs:** A 3D occupancy grid (or 3D texture) where occupied voxels are marked.

**Data Structures:**
*   **Voxel Grid:** 3D array of size $R_x \times R_y \times R_z$.
*   **Triangle:** Defined by 3 vertices $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$ and normal $\mathbf{n} = \frac{(\mathbf{v}_1 - \mathbf{v}_0) \times (\mathbf{v}_2 - \mathbf{v}_0)}{\|(\mathbf{v}_1 - \mathbf{v}_0) \times (\mathbf{v}_2 - \mathbf{v}_0)\|}$.

**Steps:**
1.  **Dominant Axis Selection:** For each triangle, determine the dominant axis $A \in \{X, Y, Z\}$ of its geometric normal $\mathbf{n}$. The dominant axis is the one with the largest absolute component: $A = \arg\max_{k \in \{x,y,z\}} |n_k|$ [S1, unofficial].
2.  **Projection Setup:** Construct an orthographic camera looking along the negative direction of axis $A$. The projection plane is perpendicular to $A$. The other two axes form the 2D rasterization plane (e.g., if $A=Z$, rasterize onto the $XY$ plane) [S1, unofficial].
3.  **Rasterization:** Rasterize the 2D projection of the triangle onto the pixel grid corresponding to the voxel grid's resolution in the projection plane [S1, unofficial].
4.  **Pixel Processing:** For each pixel $(u, v)$ covered by the projected triangle:
    *   **Case 1: Pixel Center Inside Triangle.** If the pixel center $\mathbf{c}_{uv}$ lies inside the projected triangle:
        *   Evaluate the depth $d_{tri}$ of the triangle at $\mathbf{c}_{uv}$ along the projection axis $A$ [S1, unofficial].
        *   Determine the voxel index $k$ along axis $A$ such that the voxel center depth $d_{vox}$ is closest to $d_{tri}$ [S1, unofficial].
        *   Mark voxel $(u, v, k)$ as occupied [S1, unofficial].
    *   **Case 2: Pixel Center Outside, Edge Intersection.** If the pixel center is outside the triangle but the triangle intersects the pixel boundary (indicating an edge passes through):
        *   **Horizontal Test:** Find the intersection points of the triangle edges with the horizontal line bisecting the pixel (constant $v$). Let these be $x_{left}$ and $x_{right}$ [S1, unofficial].
        *   Clamp $x_{left}$ and $x_{right}$ to the horizontal pixel extents $[u, u+1]$ [S1, unofficial].
        *   Evaluate the triangle depth $d_{left}$ and $d_{right}$ at these clamped points along axis $A$ [S1, unofficial].
        *   Determine the voxel center depth $d_{vox}$ for the voxel at column $(u, v)$ [S1, unofficial].
        *   If $d_{left}$ and $d_{right}$ are on different sides of $d_{vox}$ (i.e., $(d_{left} - d_{vox})(d_{right} - d_{vox}) < 0$), mark the voxel $(u, v, k)$ as occupied [S1, unofficial].
        *   **Vertical Test:** If the horizontal test fails (both depths on the same side), repeat the process using the vertical line bisecting the pixel (constant $u$), finding intersections $y_{top}, y_{bottom}$, clamping to $[v, v+1]$, evaluating depths, and checking if they straddle $d_{vox}$ [S1, unofficial].

**Pseudocode:**
```python
def single_2d_projection_voxelization(triangles, grid_res, bb_min, bb_max):
    # Initialize empty 3D grid
    grid = zeros(grid_res)
    
    for tri in triangles:
        # 1. Identify dominant axis
        normal = normalize(cross(tri.v1 - tri.v0, tri.v2 - tri.v0))
        abs_n = abs(normal)
        if abs_n.x >= abs_n.y and abs_n.x >= abs_n.z:
            axis = 'x'
            u_axis, v_axis = 'y', 'z'
        elif abs_n.y >= abs_n.x and abs_n.y >= abs_n.z:
            axis = 'y'
            u_axis, v_axis = 'x', 'z'
        else:
            axis = 'z'
            u_axis, v_axis = 'x', 'y'
            
        # 2. Project triangle to 2D plane defined by u_axis, v_axis
        # Remove the coordinate corresponding to 'axis'
        tri_2d = [vertex[coord] for coord in [u_axis, v_axis] for vertex in tri.vertices]
        
        # 3. Rasterize 2D triangle to find covered pixels
        covered_pixels = rasterize_2d_triangle(tri_2d, grid_res[u_axis], grid_res[v_axis])
        
        for (u, v) in covered_pixels:
            # Determine voxel index along the projection axis
            # Map pixel center to world coordinates
            pixel_center_world = map_pixel_to_world(u, v, axis, bb_min, bb_max, grid_res)
            
            # Check if pixel center is inside the 3D triangle projection
            # This is equivalent to checking if the ray along 'axis' through pixel center
            # intersects the triangle.
            if point_in_projected_triangle(u, v, tri_2d):
                # Case 1: Center inside
                depth_at_center = evaluate_triangle_depth_at_pixel_center(tri, u, v, axis, bb_min, bb_max, grid_res)
                voxel_idx = get_closest_voxel_index(depth_at_center, axis, bb_min, bb_max, grid_res)
                grid[u, v, voxel_idx] = 1
            else:
                # Case 2: Edge intersection
                # Horizontal test
                x_left, x_right = get_edge_intersections_horizontal(u, v, tri, axis, bb_min, bb_max, grid_res)
                # Clamp to pixel bounds
                x_left = clamp(x_left, u, u + 1)
                x_right = clamp(x_right, v, v + 1) # Note: v is the other axis
                
                d_left = evaluate_triangle_depth_at_point(x_left, v, tri, axis, bb_min, bb_max, grid_res)
                d_right = evaluate_triangle_depth_at_point(x_right, v, tri, axis, bb_min, bb_max, grid_res)
                
                voxel_center_depth = get_voxel_center_depth(axis, u, v, bb_min, bb_max, grid_res)
                
                if (d_left - voxel_center_depth) * (d_right - voxel_center_depth) < 0:
                    voxel_idx = get_voxel_index_for_column(u, v, axis, bb_min, bb_max, grid_res)
                    grid[u, v, voxel_idx] = 1
                else:
                    # Vertical test
                    y_top, y_bottom = get_edge_intersections_vertical(u, v, tri, axis, bb_min, bb_max, grid_res)
                    y_top = clamp(y_top, v, v + 1)
                    y_bottom = clamp(y_bottom, u, u + 1) # Note: u is the other axis
                    
                    d_top = evaluate_triangle_depth_at_point(u, y_top, tri, axis, bb_min, bb_max, grid_res)
                    d_bottom = evaluate_triangle_depth_at_point(u, y_bottom, tri, axis, bb_min, bb_max, grid_res)
                    
                    if (d_top - voxel_center_depth) * (d_bottom - voxel_center_depth) < 0:
                        voxel_idx = get_voxel_index_for_column(u, v, axis, bb_min, bb_max, grid_res)
                        grid[u, v, voxel_idx] = 1

    return grid
```

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$ where $N$ is the number of triangles and $P$ is the average number of pixels covered per triangle. It is faster than multi-view methods by a factor of 3 in rasterization overhead, but requires more complex per-pixel logic for edge cases.
*   **Memory Complexity:** $O(R_x R_y R_z)$ for the output grid.
*   **Strengths:** Reduces GPU rasterization passes by 2/3 compared to 3-axis methods. Maintains 6-separating (tunnel-free) property.
*   **Limitations:** Logic is more complex than simple center-depth tests. Requires careful handling of edge cases where the triangle grazes a pixel.
*   **When to use:** When rasterization cost is a bottleneck and the scene geometry allows for efficient dominant-axis selection.
*   **When not to use:** If the geometry is extremely thin or aligned such that dominant axis selection leads to degenerate projections (though the method claims robustness via the crosshair equivalence).

## Background
This method is derived from the "thinness" property of crosshair-based voxelization, as described by Laine et al. [S1, unofficial]. It builds on the equivalence between 3-axis rasterization and the crosshairs target [FBP09, CNS*11]. The key insight is that for a planar triangle, projecting along the dominant normal axis is sufficient to capture all voxels in the column, as other projection directions cannot produce additional voxels in those columns due to thinness [S1, unofficial]. This allows for a 6-separating voxelization using only one 2D projection per triangle.
