# Volumetric Representation via Depth Map Registration

Also called: Sparse Multi-View Volumetric Representation, Sparse Non-Lambertian Multi-view Volume Construction, Volume Initialization

## Overview
Volumetric Representation via Depth Map Registration constructs a 3D sparse voxel cloud from a set of calibrated multi-view images by registering estimated depth maps into a voxel grid [S1, S2]. It solves the problem of representing non-Lambertian scenes where global depth thresholds fail, using individual minimum cost per view to handle reflections [S1]. It distinguishes itself from [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) by explicitly handling non-Lambertian artifacts through per-view depth estimation and iterative refinement, and from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by leveraging multi-view consistency to remove isolated noise voxels [S1, S2].

## How it works
**Inputs:** A set of $N$ calibrated reference views (images and camera parameters).
**Outputs:** A sparse 3D voxel grid where each active voxel stores a count of contributing views and a color value.

**Data Structures:**
*   **Voxel Grid:** A 3D array or sparse hash map. Each voxel at location $(i, j, k)$ has a value $\delta_{ijk}$.
*   **Voxel Value $\delta_{ijk}$:** An integer representing the number of views mapping to the voxel.
    *   $\delta_{ijk} = n$ if a depth is registered to it, where $n \in \{1, 2, ..., N\}$.
    *   $\delta_{ijk} = 0$ otherwise [S1, S2].
*   **Depth Map:** A 2D array of depth values $d$ for each reference view.

**Algorithm Steps:**

1.  **Depth Estimation:** For each reference view, estimate a depth map by searching along the view's geometry. Use individual minimum cost per view to compensate for non-Lambertian reflections [S1].

2.  **Volume Initialization (Registration):** Register the depth maps into the 3D volume. For each voxel $(i, j, k)$, if a depth map from any view maps to this location, increment its value $\delta_{ijk}$ by 1. If no view maps to it, $\delta_{ijk} = 0$ [S1, S2].
    $$
    \delta_{ijk} = \begin{cases} 
    n & \text{if registering depth} \\
    0 & \text{otherwise}
    \end{cases}
    $$
    where $n$ is the count of views mapping to voxel $x$ [S1, S2].

3.  **Noise Removal and Depth Consolidation:**
    *   Detect and remove isolated voxels (voxels with no neighbors) as they are likely errors [S2].
    *   Project the remaining volume back to the reference view geometry to build new depth maps. This incorporates depth information from other views, removing errors from the previous step [S1, S2].
    *   If multiple depth values exist for a pixel in the projected view, consider the "front cluster" of depths. Calculate the proper depth value $d$ for the pixel:
        $$
        d = \begin{cases} 
        d_n & \text{if only one depth has } \delta_n = \max(\delta) \\
        \frac{\sum_{k=1}^{K} \delta_k d_k}{\sum_{k=1}^{K} \delta_k} & \text{otherwise}
        \end{cases}
        $$
        where $K$ is the number of depth values in the front cluster, $d_k$ is the depth value, and $\delta_k$ is the voxel weight [S1, S2].

4.  **Interpolation:** Reconstruct the volume again. Interpolate voxels to connect the surface of the volume among near voxels, addressing resolution differences between reference views [S1, S2].

5.  **Iterative Refinement:**
    *   Temporarily assign colors to voxels using the median of color values from all visible views [S2].
    *   Iterate through each reference view (e.g., left to right). For each view, calculate the Mean Square Error (MSE) between the reconstructed view and the original reference image using a window-based computation (e.g., 3x3 pixels) to handle calibration/imperfect resolution issues [S2].
    *   If MSE > threshold:
        *   Remove the old depth and its associated voxel [S2].
        *   Investigate a new depth derived from neighboring pixels (smooth surface assumption) [S2].
        *   If the new depth satisfies color constraints for all visible views, generate the new associated voxel [S2].
    *   If voxels are removed or generated, iteratively reconstruct images repeatedly because voxel position changes affect visibility (invisible to visible or vice versa) [S2].

6.  **Color Selection (Post-Processing):**
    *   For each voxel, determine color from visible views.
    *   For two views 1 and 2, blend colors $C_1, C_2$ using angles $a_1, a_2$ between the voxel $x$ and points on lines $L_1, L_2$:
        $$
        C = \begin{cases} 
        \frac{a_1 C_2 + a_2 C_1}{a_1 + a_2} & \text{if condition is true} \\
        C_1 & \text{otherwise}
        \end{cases}
        $$
        where $C_1, C_2$ are intensity (Y) or color (U,V) components [S2].
    *   Handle non-Lambertian blur: If the difference between $C_1$ and $C_2$ exceeds a threshold, the result is placed in a "blur group." To preserve sharpness, replace the blurred color with the color of a neighboring voxel that has the closest value and is in a "clear group" [S2].

## Subtopics

### [Iterative Volume Refinement](6473-iterative-volume-refinement.md)
Iterative Volume Refinement is a post-initialization algorithm that cleans and smooths a sparse voxel cloud generated from multi-view depth maps by removing scattering voxels and smoothing sharp corners to increase coding gain. It distinguishes itself from static voxelization by dynamically regenerating voxels based on a smooth surface assumption and iteratively re-evaluating visibility, ensuring the final volume accurately represents the real scene for virtual view synthesis.

## Operating characteristics
*   **Time Complexity:** The initialization step is $O(N \cdot H \cdot W)$ where $N$ is the number of views and $H, W$ are image dimensions. The refinement step is iterative and depends on the number of voxels and views, potentially $O(V \cdot N \cdot I)$ where $V$ is the number of voxels and $I$ is the number of iterations.
*   **Memory Complexity:** Proportional to the number of active voxels in the sparse grid.
*   **Performance:** Provides a good representation for natural scenery and handles non-Lambertian reflections better than global threshold methods [S1].
*   **Strengths:** Simple and fast registration; handles non-Lambertian scenes; iterative refinement improves shape accuracy [S1, S2].
*   **Limitations:** May cause object blur if color components differ significantly between views (non-Lambertian artifacts) [S2]. Requires calibrated multi-view images [S2].
*   **When to use:** Sparse multi-view synthesis of non-Lambertian scenes where view-dependent color is important [S2].
*   **When not to use:** Dense volumetric rendering requiring high-frequency detail without iterative refinement; scenes with significant calibration errors that cannot be handled by window-based MSE [S2].

## Background
The method was proposed by N. Anantrasirichai, C. Nishan Canagarajah, David W. Redmill, and David R. Bull from the University of Bristol [S2]. It was introduced in 2006 at the IEEE International Conference on Image Processing (ICIP) [S2]. The work addresses the challenges of 3D visual environments in communication and computer vision, specifically for sparse multi-view setups [S2]. It builds on the principle that depth registration methods provide a good representation for natural scenery [S1].
