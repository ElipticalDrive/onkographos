# Multi-view projection

## Overview
Multi-view projection voxelization converts a triangle mesh into a voxel grid by rasterizing the geometry from multiple camera viewpoints, typically aligned with the principal axes of the scene's bounding box [G]. This approach solves the coverage gaps and geometric distortions inherent in single-view projection methods, which fail when surface normals are perpendicular to the view direction [3482-single-2d-projection-voxelization.md]. It differs from single-view methods by ensuring comprehensive coverage through redundancy, and from compute-shader-based methods by leveraging standard graphics pipeline rasterization [G].

## Shared principles
The family relies on the principle that projecting a 3D object from multiple orthogonal directions ensures that every surface element is visible from at least one viewpoint, preventing "shadow" voxels caused by occlusion or grazing angles [3892-orthographic-multi-view-voxelization.md].

1. **View Direction Selection:** Cameras are positioned along the principal axes (X, Y, Z) of the scene's bounding box [G]. The view direction is parallel to the axis being projected onto [G].
2. **Orthographic Projection:** Orthographic cameras are used to map 3D world coordinates directly to 2D screen coordinates without perspective distortion, simplifying the mapping from pixel coordinates to voxel grid indices [G].
3. **Fragment-to-Voxel Mapping:** Rasterized fragments are transformed from clip space to voxel grid space [G]. The mapping uses the scene's bounding box and target resolution to determine the integer voxel coordinates $(i, j, k)$ [G].
4. **Atomic Writes or Synthesis:** To handle concurrent writes from multiple triangles or views, atomic operations are used when writing directly to a 3D texture [G]. Alternatively, intermediate 2D buffers (sheets) are synthesized into a final 3D representation [3892-orthographic-multi-view-voxelization.md].
5. **Degeneracy Handling:** Triangles parallel to a view direction may project to a line or point [G]. These cases are handled by either skipping the view for that triangle, expanding the triangle, or rasterizing along a different axis where the projection area is non-zero [3892-orthographic-multi-view-voxelization.md].

```python
def multi_view_projection_voxelization(mesh, bounding_box, resolution):
    # 1. Initialize voxel grid
    voxel_grid = create_3d_array(resolution)
    
    # 2. Define three orthographic view directions along principal axes
    view_directions = [X_AXIS, Y_AXIS, Z_AXIS]
    
    # 3. For each view direction, rasterize the mesh
    for direction in view_directions:
        # Setup orthographic camera aligned with direction
        camera = setup_orthographic_camera(direction, bounding_box)
        
        # Rasterize triangles to 2D screen space
        fragments = rasterize_mesh(mesh, camera)
        
        # 4. Map fragments to voxel coordinates
        for frag in fragments:
            voxel_coords = clip_to_voxel(frag.position, bounding_box, resolution)
            
            # 5. Handle concurrent writes
            atomic_write(voxel_grid, voxel_coords, frag.data)
            
    return voxel_grid
```

## Subtopics

### [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md)
Produces 6-separating (tunnel-free) voxelization using one 2D projection along the dominant axis of a triangle's normal vector [3482-single-2d-projection-voxelization.md]. It leverages the "thinness" property of voxelization to reduce the computational cost of multi-view approaches by eliminating redundant projections for pixels where the triangle center is visible, while handling edge cases via crosshair-like tests [3482-single-2d-projection-voxelization.md]. Unlike [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) which requires multiple views to ensure coverage, this method relies on a single optimized view direction determined by the geometry's orientation [3482-single-2d-projection-voxelization.md].

### [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md)
Rasters scene geometry into a 3D texture using three orthographic cameras aligned with the scene's bounding box axes to create a voxelized representation for subsequent volume rendering [3892-orthographic-multi-view-voxelization.md]. It differs from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by using multiple views to ensure coverage and from [3-Pass Voxelization](5300-3-pass-voxelization.md) by synthesizing the result into a final "worksheet" texture rather than leaving it in intermediate slab buffers [3892-orthographic-multi-view-voxelization.md].

### [3-Pass Voxelization](5300-3-pass-voxelization.md)
A rasterization-based technique that eliminates cracks and missing data in the voxel grid by rendering the scene from three orthogonal directions aligned with the principal axes (X, Y, Z) [5300-3-pass-voxelization.md]. Unlike single-view projection methods which suffer from geometric distortion or gaps when surface normals are perpendicular to the view direction, this approach ensures comprehensive coverage by aggregating fragments from all three major axes [5300-3-pass-voxelization.md]. It builds on the general principles of [Multi-view projection](5937-multi-view-projection.md) but restricts the view directions to the three cardinal axes to simplify the projection matrices and guarantee that no triangle is missed due to alignment issues [5300-3-pass-voxelization.md].

### [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md)
Constructs a 3D sparse voxel cloud from a set of calibrated multi-view images by registering estimated depth maps into a voxel grid [6435-volumetric-representation-via-depth-map-registration.md]. It solves the problem of representing non-Lambertian scenes where global depth thresholds fail, using individual minimum cost per view to handle reflections [6435-volumetric-representation-via-depth-map-registration.md]. It distinguishes itself from [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md) by explicitly handling non-Lambertian artifacts through per-view depth estimation and iterative refinement, and from [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md) by leveraging multi-view consistency to remove isolated noise voxels [6435-volumetric-representation-via-depth-map-registration.md].

### Multi-View Stereo Cost Volume Construction
A cost volume $V_c$ is constructed from feature volumes $\{Vf_i\}$ of $N$ reference views to perceive coarse scene structure and provide scene priors for sampling, skipping blank areas [S1]. The number of depth layers $L$ is typically 16 [S1]. Checkerboard artifacts caused by deconvolution layers in the Res-Unet processing the cost volume are eliminated by replacing deconvolution with combinations of upsampling and convolution layers [S1].
