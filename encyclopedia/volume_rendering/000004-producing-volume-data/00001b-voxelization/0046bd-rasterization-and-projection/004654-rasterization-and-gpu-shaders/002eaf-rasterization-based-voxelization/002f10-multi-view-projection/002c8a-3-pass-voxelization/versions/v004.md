# 3-Pass Voxelization
Also called: 3-Axis Voxelization, 3D Mesh Voxelization via Axis-Aligned Rasterization, Multi-View Voxelization

## Overview
3-Pass Voxelization is a rasterization-based technique that eliminates cracks and missing data in the voxel grid by rendering the scene from three orthogonal directions aligned with the principal axes (X, Y, Z) [S1, S2, unofficial]. Unlike single-view projection methods which suffer from geometric distortion or gaps when surface normals are perpendicular to the view direction, this approach ensures comprehensive coverage by aggregating fragments from all three major axes [S1, S2, unofficial]. It builds on the general principles of [Multi-view projection](5937-multi-view-projection.md) but restricts the view directions to the three cardinal axes to simplify the projection matrices and guarantee that no triangle is missed due to alignment issues.

## How it works
**Inputs:** A triangle mesh (vertices and indices), a target voxel grid resolution ($N_x, N_y, N_z$), and the spatial bounds of the voxel grid.
**Outputs:** A populated 3D voxel grid (occupancy or density values).

**Data Structures:**
1.  **Voxel Grid:** A 3D array or texture of size $N_x \times N_y \times N_z$. Each voxel stores occupancy status or accumulated data.
2.  **Projection Matrices:**
    *   $P_{clip}$: The standard clip-space projection matrix (orthographic or perspective, though orthographic is implied by the axis-aligned nature).
    *   $R_x, R_y, R_z$: Rotation matrices corresponding to the X, Y, and Z axes respectively.
    *   $M_{voxel}$: The voxel-space transformation matrix that maps clip-space coordinates to voxel grid indices.

**Steps:**
1.  **Coordinate System Setup:** Place the origin of the coordinate system at the center of the voxel grid, ensuring that the X, Y, and Z axes are parallel to the edges of the voxel grid cells [S2, unofficial].
2.  **Pass 1 (Axis 1):**
    *   Construct the view matrix for the first axis (e.g., viewing along the Z-axis).
    *   Compute the combined projection matrix: $M_1 = P_{clip} \times R_{axis1}$ [S1, unofficial].
    *   Render the scene triangles into a 2D buffer or directly into the voxel grid layers corresponding to this view direction.
    *   The fragments generated are mapped to voxel coordinates using $M_{voxel}$. Note that $M_{voxel}$ is applied directly without the rotation component, as it already maps values properly for the specific axis being processed [S1, unofficial].
3.  **Pass 2 (Axis 2):**
    *   Construct the view matrix for the second axis (e.g., viewing along the X-axis).
    *   Compute the combined projection matrix: $M_2 = P_{clip} \times R_{axis2}$ [S1, unofficial].
    *   Render the scene, populating the corresponding voxel layers.
4.  **Pass 3 (Axis 3):**
    *   Construct the view matrix for the third axis (e.g., viewing along the Y-axis).
    *   Compute the combined projection matrix: $M_3 = P_{clip} \times R_{axis3}$ [S1, unofficial].
    *   Render the scene, populating the remaining voxel layers.
5.  **Aggregation:** The results from the three passes are combined. If using atomic writes to a 3D texture, the grid is updated in place. If using intermediate 2D buffers, they are synthesized into the final 3D representation.

**Pseudocode:**
```python
def voxelize_3_pass(mesh, voxel_grid, resolution, clip_space_matrix):
    """
    Voxelize a mesh using 3 orthogonal passes.
    
    Args:
        mesh: Triangle mesh data (vertices, indices)
        voxel_grid: 3D array/texture of size (Nx, Ny, Nz)
        resolution: Tuple (Nx, Ny, Nz)
        clip_space_matrix: The base clip-space projection matrix P_clip
        
    Returns:
        voxel_grid: Populated voxel grid
    """
    # Define rotation matrices for X, Y, Z axes
    # Note: Exact rotation matrices depend on the coordinate system convention (LH/RH)
    # and whether viewing along + or - axis. 
    # For example, viewing along Z-axis usually requires no rotation if Z is forward,
    # but if using a standard camera setup, rotations align the view frustum with the grid.
    rotations = [
        get_rotation_matrix_for_axis(0), # X-axis pass
        get_rotation_matrix_for_axis(1), # Y-axis pass
        get_rotation_matrix_for_axis(2)  # Z-axis pass
    ]
    
    # Voxel-space matrix maps clip-space to voxel indices
    # This matrix is constant for all passes as it maps to the grid structure
    voxel_space_matrix = compute_voxel_space_matrix(resolution, voxel_grid_bounds)
    
    for i, rotation in enumerate(rotations):
        # Compute the combined projection matrix for this pass
        # M = P_clip * R_axis
        combined_matrix = multiply_matrices(clip_space_matrix, rotation)
        
        # Render the mesh using the combined matrix
        # This generates fragments in clip space
        fragments = rasterize_mesh(mesh, combined_matrix)
        
        # Map fragments to voxel coordinates
        # The voxel_space_matrix is applied directly without the rotation
        # because it already handles the mapping to the grid indices
        for frag in fragments:
            # Transform fragment position to voxel space
            voxel_coords = transform_to_voxel_space(frag.position, voxel_space_matrix)
            
            # Check if voxel coordinates are within bounds
            if is_within_bounds(voxel_coords, resolution):
                # Write to voxel grid
                # Use atomic operation if concurrent, or direct write if single-threaded
                write_to_voxel_grid(voxel_grid, voxel_coords, frag.data)
                
    return voxel_grid

def get_rotation_matrix_for_axis(axis_index):
    """
    Returns the rotation matrix to align the view with the specified axis.
    Implementation detail: [G]
    """
    if axis_index == 0: # X-axis
        return rotate_x(90.0) # Example rotation
    elif axis_index == 1: # Y-axis
        return rotate_y(90.0) # Example rotation
    else: # Z-axis
        return identity_matrix() # No rotation needed if Z is already forward

def transform_to_voxel_space(position, voxel_space_matrix):
    """
    Transforms a clip-space position to voxel grid indices.
    """
    # Homogeneous division
    w = position.w
    x = position.x / w
    y = position.y / w
    z = position.z / w
    
    # Apply voxel space matrix
    # M_voxel * [x, y, z, 1]^T
    voxel_pos = multiply_matrix_vector(voxel_space_matrix, [x, y, z, 1])
    
    # Convert to integer indices
    return [int(voxel_pos.x), int(voxel_pos.y), int(voxel_pos.z)]
```

**Parameters:**
*   **Resolution:** The number of voxels along each axis. Higher resolution increases accuracy but also memory and compute cost.
*   **Voxel Grid Bounds:** The spatial extent of the voxel grid. Must encompass the entire scene.

**Edge Cases and Pitfalls:**
*   **Performance:** The method requires 3 render calls per object, which can become expensive for complex models [S1, unofficial].
*   **Dynamic Objects:** If optimizing by separating dynamic and static objects, the voxel grid for dynamic objects must be cleared every frame, necessitating separate voxel grids for dynamic and static content [S1, unofficial].
*   **Precision:** Floating-point precision in the transformation matrices can lead to gaps or overlaps if not handled carefully.
*   **Degenerate Input:** Triangles with zero area or vertices with identical positions may cause undefined behavior in rasterization.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R)$, where $N$ is the number of triangles and $R$ is the resolution (specifically, the number of pixels/voxels covered). Since there are 3 passes, the constant factor is 3.
*   **Memory Complexity:** $O(N_x \cdot N_y \cdot N_z)$ for the voxel grid.
*   **Strengths:** Simple to implement; guarantees coverage of all surface orientations; avoids cracks and missing data associated with single-view projection.
*   **Limitations:** Computationally expensive due to multiple render passes; requires separate handling for dynamic and static objects if optimization is applied.
*   **When to Use:** When high-quality voxelization is required and performance is not the primary constraint, or when the scene geometry is relatively simple.
*   **When Not to Use:** For highly complex scenes with many dynamic objects where real-time performance is critical.

## Background
3-Pass Voxelization was introduced as a solution to the problem of cracks and missing data in voxel grids generated by single-direction rasterization [S1, unofficial]. It is a specific instance of multi-view projection voxelization, leveraging the orthographic projection principle along the three principal axes [S2, unofficial]. The method is commonly used in real-time ray tracing applications, particularly for voxel global illumination, where accurate representation of geometry is crucial for light transport simulation [S1, unofficial].
