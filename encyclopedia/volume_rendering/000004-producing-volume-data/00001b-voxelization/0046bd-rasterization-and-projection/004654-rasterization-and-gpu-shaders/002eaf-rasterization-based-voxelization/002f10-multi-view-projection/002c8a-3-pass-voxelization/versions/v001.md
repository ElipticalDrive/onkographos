# 3-Pass Voxelization

Also called: 3-Axis Voxelization, 3D Mesh Voxelization via Axis-Aligned Rasterization, Multi-View Voxelization

## Overview
3-Pass Voxelization is a rasterization-based technique that eliminates cracks and missing data in voxel grids by rendering a 3D scene from three orthogonal directions (along the X, Y, and Z axes) [S1, unofficial][S2, unofficial]. Unlike single-view projection methods which suffer from geometric distortion or gaps due to perspective or alignment issues, this approach ensures that every voxel intersected by a triangle is covered by at least one view, provided the views are sufficiently separated [S2, unofficial]. It builds on the [Multi-view projection](5937-multi-view-projection.md) principle but restricts the view directions to the three principal axes to guarantee robustness against degenerate projections [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D mesh (triangle soup) defined in world or object space, and a target voxel grid resolution $(R_x, R_y, R_z)$.
*   **Output:** A populated voxel grid where each occupied voxel represents a part of the mesh surface or volume.

**Data Structures:**
*   **Voxel Grid:** A 3D array or hash map storing occupancy data. The size is determined by the resolution parameters.
*   **Transformation Matrices:**
    *   $M_{proj}$: The voxel-space projection matrix. This matrix maps 3D coordinates directly to voxel indices. It typically includes scaling by resolution and offsetting by the bounding box minimum [S1, unofficial].
    *   $M_{rot}$: Rotation matrices for each axis. These are used to align the view direction with the principal axes.

**Numbered Steps:**

1.  **Initialize Voxel Grid:** Clear the voxel grid. If optimizing for dynamic/static separation, maintain separate grids for each category [S1, unofficial].
2.  **Define View Directions:** Identify the three principal axes: X, Y, and Z.
3.  **Loop through Axes:** For each axis $A \in \{X, Y, Z\}$:
    a.  **Construct View Matrix:** Create a view-projection matrix. According to [S1, unofficial], this involves multiplying the clip-space projection matrix by a rotation matrix $M_{rot}$ corresponding to the current axis $A$. This rotation ensures that the fragments generated are aligned with the voxel grid axes.
    b.  **Rasterize:** Render the mesh using this view matrix. The rasterization process projects the triangles onto the 2D plane perpendicular to axis $A$.
    c.  **Map to Voxel Space:** The fragments generated are mapped to voxel coordinates. [S1, unofficial] notes that the voxel-space matrix ($M_{proj}$) does not need to be multiplied by the rotation matrix because it already maps values properly; the rotation is only required to ensure fragments are generated in the correct pass. The mapping involves scaling clip-space coordinates to the voxel grid resolution and offsetting by the bounding box minimum [S1, unofficial].
    d.  **Atomic Write:** For each fragment, write to the corresponding voxel in the grid. Use atomic operations if the implementation is parallel to prevent race conditions [G].
4.  **Repeat:** Execute the above steps for all three axes. This results in three render passes per object [S1, unofficial].

**Formulas:**
*   **Voxel Coordinate Mapping:**
    Let $P_{world}$ be a point in world space.
    Let $M_{view}$ be the view matrix for the current axis.
    Let $M_{proj}$ be the voxel-space projection matrix.
    The voxel coordinate $V$ is calculated as:
    $$ V = \text{floor}(M_{proj} \cdot M_{view} \cdot P_{world}) $$
    Note: [S1, unofficial] suggests that $M_{proj}$ handles the mapping to voxel space directly, and the rotation is applied via $M_{view}$ to generate the correct fragments.

**Parameters:**
*   **Resolution:** $(R_x, R_y, R_z)$. Typical values depend on hardware capabilities and scene complexity [S1, unofficial].
*   **Bounding Box:** The minimum and maximum extents of the scene or object, used for offsetting voxel coordinates [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Performance:** Requires 3 render calls per object, which can be expensive for complex models [S1, unofficial].
*   **Dynamic Objects:** If separating dynamic and static objects, the voxel grid for dynamic objects must be cleared every frame, requiring separate grids [S1, unofficial].
*   **Degenerate Projections:** While 3-axis coverage reduces the risk, ensuring the rotation matrices are correctly applied is crucial to avoid missing fragments [S1, unofficial].

## Subtopics

### [Single 2D Projection Voxelization](3482-single-2d-projection-voxelization.md)
Uses a single view direction. Simpler but prone to cracks. Choose when performance is critical and cracks are acceptable.

### [Orthographic Multi-View Voxelization](3892-orthographic-multi-view-voxelization.md)
Uses multiple views but not necessarily restricted to the 3 principal axes. More robust than single-view but potentially more expensive than 3-pass. Choose when higher accuracy is needed than 3-pass can provide.

### [Volumetric Representation via Depth Map Registration](6435-volumetric-representation-via-depth-map-registration.md)
Uses depth maps from multiple views to build a volumetric representation. Different approach, not strictly rasterization-based in the same way. Choose when depth map data is already available.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of triangles and $V$ is the number of voxels covered by the triangles. Since it requires 3 render passes, the constant factor is 3 times that of a single-pass method [S1, unofficial].
*   **Memory Complexity:** $O(R_x \cdot R_y \cdot R_z)$ for the voxel grid. If dynamic and static objects are separated, the memory usage doubles [S1, unofficial].
*   **Measured Performance:** Performance depends heavily on the hardware capabilities and the resolution of the voxel grid. Adjusting the resolution can greatly increase performance [S1, unofficial].
*   **Strengths:** Simple to implement, robust against cracks and missing data, ensures 6-separating voxel grids [S1, unofficial][S2, unofficial].
*   **Limitations:** Expensive for complex models due to 3 render calls per object [S1, unofficial]. Requires separate grids for dynamic and static objects if optimized [S1, unofficial].
*   **When to Use:** When accurate voxelization is required and performance is not the primary constraint. Suitable for static scenes or scenes with limited dynamic objects.
*   **When Not to Use:** When performance is critical and the scene is very complex. When single-view cracks are acceptable.

## Background
3-Pass Voxelization is a technique used in real-time ray tracing and voxel global illumination to ensure accurate voxelization of 3D meshes [S1, unofficial][S2, unofficial]. It addresses the limitations of single-view projection methods by using three orthogonal views to cover all possible orientations of triangles [S1, unofficial][S2, unofficial]. The method is described in the context of real-time ray traced voxel global illumination [S1, unofficial] and is implemented in open-source projects like 3D-Mesh-Voxelizer [S2, unofficial].
