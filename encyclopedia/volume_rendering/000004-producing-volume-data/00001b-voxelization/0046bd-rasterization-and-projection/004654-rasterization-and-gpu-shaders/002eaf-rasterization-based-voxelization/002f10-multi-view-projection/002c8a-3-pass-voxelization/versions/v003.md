# 3-Pass Voxelization

Also called: 3-Axis Voxelization, 3D Mesh Voxelization via Axis-Aligned Rasterization, Multi-View Voxelization

## Overview
3-Pass Voxelization is a rasterization-based technique that eliminates cracks and missing data in the voxel grid by rendering the scene from three distinct orthographic views aligned with the principal axes (X, Y, and Z) [S1, S2, unofficial]. Unlike single-view projection methods which suffer from geometric distortion or gaps for surfaces parallel to the view direction, this method ensures accurate voxel occupancy by aggregating fragments from all three orthogonal perspectives [S2, unofficial]. It builds on the shared principles of [Multi-view projection](5937-multi-view-projection.md) but restricts camera orientations to the three cardinal axes to guarantee coverage of all surface normals.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D mesh (triangle soup) defined in world space, and a target voxel grid resolution $(V_x, V_y, V_z)$.
*   **Output:** A populated 3D voxel grid (or occupancy/depth buffers) representing the scene geometry.

**Data Structures:**
*   **Voxel Grid:** A 3D array of size $V_x \times V_y \times V_z$. Each cell represents a unit volume in voxel space.
*   **Transformation Matrices:**
    *   $M_{voxel}$: Maps world coordinates to voxel indices. Defined in the parent article as $\text{Scale}(V_x, V_y, V_z) \times \text{Translate}(-B_{min})$ [S1, S2, unofficial].
    *   $R_x, R_y, R_z$: Rotation matrices aligning the view direction with the X, Y, and Z axes respectively.
    *   $P$: The clip-space projection matrix (typically orthographic, scaled to cover the bounding box).

**Numbered Steps:**
1.  **Initialize Grid:** Clear the voxel grid (or depth buffers) for the current frame. If optimizing for dynamic/static separation, clear only the dynamic object grid [S1, unofficial].
2.  **Pass 1 (Axis 1):**
    *   Construct the view matrix by rotating the camera to look along the first principal axis (e.g., +Z or -Z) [S2, unofficial].
    *   Multiply the clip-space projection matrix $P$ by the rotation matrix $R_{axis1}$ to generate the view-projection matrix for this pass [S1, unofficial].
    *   Render the scene geometry. The rasterizer generates fragments.
    *   Map fragment coordinates to voxel indices using $M_{voxel}$. Note: $M_{voxel}$ is applied directly without the rotation matrix, as it already maps world values to voxel space correctly; the rotation is only necessary to ensure fragments are generated for surfaces not visible from this specific angle [S1, unofficial].
    *   Write occupancy/depth data to the grid. Use atomic operations if multiple fragments map to the same voxel to prevent race conditions [G].
3.  **Pass 2 (Axis 2):**
    *   Construct the view matrix by rotating the camera to look along the second principal axis (e.g., +X or -X) [S2, unofficial].
    *   Update the view-projection matrix with the corresponding rotation $R_{axis2}$ [S1, unofficial].
    *   Render the scene and accumulate results into the voxel grid.
4.  **Pass 3 (Axis 3):**
    *   Construct the view matrix by rotating the camera to look along the third principal axis (e.g., +Y or -Y) [S2, unofficial].
    *   Update the view-projection matrix with the corresponding rotation $R_{axis3}$ [S1, unofficial].
    *   Render the scene and accumulate results into the voxel grid.
5.  **Finalize:** The resulting grid contains voxels hit by any of the three passes, effectively closing cracks that would occur with a single view [S1, unofficial].

**Pseudocode:**
```python
def voxelize_3_pass(mesh, voxel_resolution, bounding_box_min):
    """
    Voxelize a mesh using 3 orthographic passes along principal axes.
    """
    # 1. Setup Voxel Space Matrix
    # Scale to resolution, translate by bounding box min
    scale = voxel_resolution
    translate = -bounding_box_min
    M_voxel = scale_matrix(scale) * translate_matrix(translate)
    
    # 2. Define Rotation Matrices for each axis
    # Assuming standard right-handed coordinate system
    # Rotations align the camera view vector with the axis
    R_x = rotation_matrix_x(90)   # Look along X
    R_y = rotation_matrix_y(90)   # Look along Y
    R_z = rotation_matrix_z(0)    # Look along Z (default)
    
    rotations = [R_x, R_y, R_z]
    
    # 3. Clear Voxel Grid
    voxel_grid = create_grid(voxel_resolution)
    
    # 4. Execute 3 Passes
    for R_axis in rotations:
        # Construct View-Projection Matrix
        # P is the orthographic projection matrix covering the bounding box
        VP = P * R_axis
        
        # Render Scene Geometry
        # For each triangle in mesh:
        for triangle in mesh.triangles:
            # Transform vertices to clip space
            v_clip = [VP * v for v in triangle.vertices]
            
            # Rasterize triangle to fragments
            fragments = rasterize_triangle(v_clip, viewport_size)
            
            # Map fragments to voxel indices
            for frag in fragments:
                # Map fragment world position to voxel index
                # M_voxel maps world space directly to voxel indices
                voxel_idx = M_voxel * frag.world_position
                
                # Check bounds
                if is_inside_grid(voxel_idx, voxel_resolution):
                    # Atomic write to prevent race conditions
                    voxel_grid[voxel_idx] = mark_occupied(voxel_grid[voxel_idx])
                    
    return voxel_grid
```

**Parameters:**
*   **Voxel Resolution $(V_x, V_y, V_z)$:** Determines grid granularity. Higher resolution increases accuracy but also memory and compute cost [S1, unofficial].
*   **Bounding Box:** Defines the spatial extent of the scene. The orthographic frustum must be expanded slightly (e.g., $1.02 \times R$) to ensure full coverage of the bounding box [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degeneracy:** Triangles parallel to the view direction project to lines. While 3 passes cover most orientations, extremely thin geometry aligned with an axis might still be missed if not handled by robust rasterization or if the grid resolution is too low [S2, unofficial].
*   **Performance:** Requires 3 render calls per object. This becomes expensive for complex models [S1, unofficial].
*   **Dynamic Objects:** If separating dynamic and static objects, the dynamic voxel grid must be cleared every frame, requiring separate storage structures [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of triangles and $V$ is the number of voxels (or more accurately, the number of fragments generated). Since 3 passes are required, the cost is roughly 3x that of a single-pass method [S1, unofficial].
*   **Memory Complexity:** $O(V_x \cdot V_y \cdot V_z)$ for the voxel grid. If dynamic/static separation is used, memory usage doubles [S1, unofficial].
*   **Strengths:** Eliminates cracks and missing data inherent in single-view projection; simple to implement; robust against surface orientation [S1, S2, unofficial].
*   **Limitations:** High computational cost due to multiple render passes; not suitable for real-time applications with very high triangle counts without optimization (e.g., LOD interleaving, resolution scaling) [S1, unofficial].
*   **When to use:** When voxel quality is critical and cracks are unacceptable, and performance budget allows for 3x rasterization cost.
*   **When not to use:** When real-time performance on complex scenes is required and some voxel artifacts are tolerable.

## Background
3-Pass Voxelization was introduced as a solution to the "crack" problem in voxel global illumination, where single-direction rasterization fails to capture geometry from certain angles [S1, unofficial]. It is a specific instance of multi-view projection tailored for axis-aligned coverage. The method is discussed in the context of real-time ray-traced voxel global illumination systems [S1, unofficial] and implemented in educational/open-source voxelizers [S2, unofficial].
