# GPU Voxelizer using Nearest Vertex and Normal Dot Product

Also called: Compute Shader Voxelizer, GPUVoxelizer

## Overview
This method is a real-time voxelization technique that determines if a voxel is inside, on the edge, or outside a mesh by finding the nearest vertex on the mesh for each voxel and using the dot product between the ray from the vertex to the voxel and the vertex normal to determine interiority [S1, unofficial]. It differs from sibling methods like [GPU Mesh Voxelization (Schwarz & Seidel 2010)](1633-gpu-mesh-voxelization-schwarz-seidel-2010.md) and [Multi-channel Surface Voxelization](1899-multi-channel-surface-voxelization.md) by avoiding traditional rasterization for the voxelization pass, instead relying on direct vertex proximity checks executed in a compute shader [S1, unofficial]. The source implementation explicitly notes that the dot-product interiority logic is considered buggy and is often superseded by distance-only checks in practice [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A mesh defined by an array of vertices (position and normal) and a voxel grid defined by an array of entities (voxel positions and scales) [S1, unofficial].
*   **Output:** A voxel grid where each voxel's scale (opacity/visibility) is updated based on its proximity to the mesh surface and interiority [S1, unofficial].

**Data Structures:**
The implementation uses two `std430` buffers in a compute shader:
1.  `entities` (Binding 0): An array of `particle` structs representing voxels [S1, unofficial].
    *   `position`: `vec4` (xyz: voxel center, w: unused/padding) [S1, unofficial].
    *   `scale`: `vec4` (xyz: unused/padding, w: opacity/visibility factor) [S1, unofficial].
2.  `meshdata` (Binding 1): An array of `meshData` structs representing the mesh [S1, unofficial].
    *   `position`: `vec4` (xyz: vertex position, w: unused/padding) [S1, unofficial].
    *   `normal`: `vec4` (xyz: vertex normal, w: unused/padding) [S1, unofficial].

**Parameters:**
*   `meshdataCount`: Uniform integer specifying the number of vertices in the mesh to test against [S1, unofficial].
*   `voxelSize`: Uniform float specifying the size of each voxel, used as the threshold for edge detection [S1, unofficial].

**Steps:**
1.  Initialize a compute shader with a local group size of `(1024, 1, 1)` [S1, unofficial].
2.  Each work item corresponds to one voxel, identified by the global invocation ID `gid` [S1, unofficial].
3.  Retrieve the voxel's position `p` from the `entities` buffer at index `gid` [S1, unofficial].
4.  Iterate through all `meshdataCount` vertices in the `meshdata` buffer to find the nearest vertex [S1, unofficial].
5.  Calculate the squared Euclidean distance $d$ between the voxel position $p$ and each vertex position $v_i$:
    $$d = (p.x - v_i.x)^2 + (p.y - v_i.y)^2 + (p.z - v_i.z)^2$$
    (Implemented as `pow(d1, 2.0) + pow(d2, 2.0) + pow(d3, 2.0)` in the source) [S1, unofficial].
6.  Track the minimum squared distance `nearDist` and the index `nearestIndex` of the closest vertex [S1, unofficial].
7.  Calculate the vector from the nearest mesh vertex to the voxel:
    $$toCell = \text{normalize}(p - \text{meshdata}[nearestIndex].position)$$ [S1, unofficial].
8.  Calculate the dot product between the normalized vector to the cell and the mesh vertex normal:
    $$dotProduct = \text{dot}(toCell, \text{meshdata}[nearestIndex].normal)$$ [S1, unofficial].
9.  Determine the "inside" factor using a step function with a threshold of -0.9:
    $$isInside = 1 - \text{step}(-0.9, dotProduct)$$
    If $dotProduct \le -0.9$, the ray from the vertex to the voxel is opposed to the normal, indicating the voxel is inside the mesh [S1, unofficial].
10. Determine the "edge" factor based on the distance to the nearest vertex:
    $$fDist = 1 - \text{step}(voxelSize, \sqrt{nearDist})$$
    If $\sqrt{nearDist} < voxelSize$, the voxel is considered on the edge [S1, unofficial].
11. Calculate the final voxel scale using the maximum of the edge factor and the inside factor:
    $$voxelScale = \max(fDist, isInside)$$ [S1, unofficial].
12. Write the calculated scale to the `scale` component (w) of the voxel entity in the `entities` buffer [S1, unofficial].

**Pseudocode:**
```python
def process_voxel(gid, entities, meshdata, meshdataCount, voxelSize):
    # 1. Retrieve voxel position
    p = entities[gid].position.xyz
    
    # 2. Find nearest vertex by brute-force iteration
    near_dist_sq = float('inf')
    nearest_index = -1
    
    for i in range(meshdataCount):
        v_pos = meshdata[i].position.xyz
        dx = p.x - v_pos.x
        dy = p.y - v_pos.y
        dz = p.z - v_pos.z
        dist_sq = dx*dx + dy*dy + dz*dz
        
        if dist_sq < near_dist_sq:
            near_dist_sq = dist_sq
            nearest_index = i
            
    # 3. Calculate vectors
    nearest_v_pos = meshdata[nearest_index].position.xyz
    nearest_v_norm = meshdata[nearest_index].normal.xyz
    
    to_cell_x = p.x - nearest_v_pos.x
    to_cell_y = p.y - nearest_v_pos.y
    to_cell_z = p.z - nearest_v_pos.z
    
    # Normalize to_cell, handling degenerate case where voxel center coincides with vertex
    mag = (to_cell_x**2 + to_cell_y**2 + to_cell_z**2)**0.5
    if mag > 0.0:
        to_cell_x /= mag
        to_cell_y /= mag
        to_cell_z /= mag
    else:
        to_cell_x, to_cell_y, to_cell_z = 0.0, 0.0, 0.0
        
    # 4. Dot product
    dot_product = to_cell_x * nearest_v_norm.x + \
                  to_cell_y * nearest_v_norm.y + \
                  to_cell_z * nearest_v_norm.z
                  
    # 5. Determine factors
    # isInside: 1 if dot_product <= -0.9, else 0
    is_inside = 1.0 if dot_product <= -0.9 else 0.0
        
    # fDist: 1 if sqrt(near_dist_sq) < voxelSize, else 0
    dist = near_dist_sq**0.5
    f_dist = 1.0 if dist < voxelSize else 0.0
        
    # 6. Final scale
    voxel_scale = max(f_dist, is_inside)
    
    # 7. Write output
    entities[gid].scale.w = voxel_scale
```

**Edge Cases and Pitfalls:**
*   **Buggy Logic:** The source explicitly notes that the dot-product method for determining interiority is considered "bugged" and that the final effective logic often relies primarily on the distance check (`fDist`) rather than the combination with `isInside` [S1, unofficial]. Implementers should be aware that `isInside` may produce incorrect results for non-convex or complex meshes where the nearest vertex is not a reliable indicator of interiority [S1, unofficial].
*   **Precision:** The squared distance calculation uses floating-point arithmetic [S1, unofficial]. For very large meshes or high-precision requirements, precision loss in `near_dist_sq` tracking may occur [S1, unofficial].
*   **Degenerate Input:** If a voxel center coincides exactly with a mesh vertex, the `toCell` vector has zero magnitude [S1, unofficial]. The pseudocode handles this by setting the vector to zero, which results in a dot product of 0 [S1, unofficial]. Since $0 > -0.9$, `isInside` becomes 0 [S1, unofficial]. The voxel will only be marked if it is within `voxelSize` of the vertex (which it is, distance 0), so `fDist` will be 1 [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot V)$, where $N$ is the number of voxels (work items) and $V$ is the number of mesh vertices (`meshdataCount`), as each voxel iterates through all vertices to find the nearest one [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Tested on NVIDIA GTX 1070 and 1060 GPUs [S1, unofficial]. The implementation is noted as not being the most optimized version [S1, unofficial].
*   **Strengths:** Simple brute-force logic; fully GPU-accelerated via compute shaders [S1, unofficial].
*   **Limitations:** Linear scaling with vertex count; dot-product interiority detection is unreliable for complex geometry and noted as buggy in the source [S1, unofficial].

## Background
This technique originates from an unofficial implementation by `alexr4` (Bonjour Lab) for the Processing.org environment, aiming to provide a real-time voxelization solution using GPU compute shaders [S1, unofficial]. It was developed as a practical experiment for real-time rendering and voxel display, tested on consumer NVIDIA hardware [S1, unofficial].
