# Voxel Carving

Also called: space carving

## Overview
Voxel Carving is a technique to reconstruct a dense, filled 3D voxel grid from multiple 2D depth maps or silhouettes [S1]. Unlike surface-only voxelization methods that occupy only the boundary voxels, Voxel Carving fills the interior volume consistent with the input views [S1]. It differs from [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by explicitly enforcing visibility constraints from multiple camera viewpoints to determine occupancy, rather than projecting geometry directly into a grid.

## How it works
**Inputs:**
- A 3D mesh or point cloud representing the target object.
- A set of camera poses (extrinsics) and intrinsic parameters.
- Depth maps or silhouette images rendered from these poses.
- Grid parameters: `cubic_size` (bounding box dimension), `voxel_resolution` (number of voxels per axis), and `origin` (typically center of the bounding box).

**Outputs:**
- A dense `VoxelGrid` data structure where each voxel is marked as occupied or empty.

**Data Structures:**
- **Voxel Grid**: A 3D array of boolean values (or occupancy flags). The grid dimensions are $(N, N, N)$ where $N = \text{voxel\_resolution}$. The physical bounds are defined by `origin` and `voxel_size`.
- **Camera Pose**: Defined by an extrinsic matrix $T \in \mathbb{R}^{4 \times 4}$ and intrinsic parameters (focal length, principal point).

**Steps:**

1.  **Initialize Grid**: Create a dense voxel grid with width, height, and depth equal to `cubic_size`. Set `voxel_size` as:
    $$ \text{voxel\_size} = \frac{\text{cubic\_size}}{\text{voxel\_resolution}} $$
    Set the origin to $[-\text{cubic\_size}/2, -\text{cubic\_size}/2, -\text{cubic\_size}/2]$ [S1]. Initialize all voxels as potentially occupied (or empty, depending on the specific variant: silhouette carving typically starts with all occupied and carves out empty space, while depth carving may start empty and fill, or vice versa; Open3D's `carve_depth_map` implies a consistency check) [S1].

2.  **Preprocess Geometry**: Center the input mesh at the origin and scale it such that its bounding box fits within the `cubic_size` bounds [S1].
    $$ \text{center} = \frac{\text{min\_bound} + \text{max\_bound}}{2} $$
    $$ \text{scale} = \frac{\|\text{max\_bound} - \text{min\_bound}\|}{2} $$
    $$ v' = \frac{v - \text{center}}{\text{scale}} $$

3.  **Iterate Cameras**: For each camera pose $i$ defined by a position $xyz_i$ and extrinsic matrix $T_i$:
    a. **Render Depth**: Render a depth image $D_i$ from the current camera pose. The depth value $d(u,v)$ represents the distance from the camera center to the surface along the ray through pixel $(u,v)$ [S1].
    b. **Carve**: Update the voxel grid based on $D_i$ and $T_i$.

    **Carving Logic (Depth Map Variant):**
    For each pixel $(u,v)$ in the depth image $D_i$ with depth $d$:
    1.  Construct the ray from the camera center $C_i$ through the pixel.
    2.  Identify all voxels intersected by this ray from the camera up to distance $d$. Mark these voxels as **occupied** (or consistent with the view) [S1].
    3.  Identify all voxels intersected by this ray from distance $d$ to the maximum range. Mark these voxels as **empty** (carved out) [S1].

    **Carving Logic (Silhouette Variant):**
    1.  Project the voxel grid onto the image plane.
    2.  If a voxel projects to a pixel outside the silhouette mask, mark the voxel as **empty** [S1].
    3.  Voxels projecting inside the silhouette remain potentially occupied.

4.  **Finalize**: The resulting grid contains voxels that are consistent with all input depth maps or silhouettes [S1].

**Pseudocode:**

```python
def voxel_carving(mesh, camera_poses, depth_images, cubic_size, voxel_resolution):
    # 1. Initialize Grid
    voxel_size = cubic_size / voxel_resolution
    origin = [-cubic_size / 2.0, -cubic_size / 2.0, -cubic_size / 2.0]
    # Create dense voxel grid, initialized to all occupied (for silhouette) 
    # or all empty (for depth fill), depending on implementation. 
    # Open3D's carve_depth_map typically fills consistent regions.
    grid = create_dense_voxel_grid(width=cubic_size, height=cubic_size, depth=cubic_size, 
                                   voxel_size=voxel_size, origin=origin)
    
    # 2. Preprocess Mesh to fit grid bounds
    mesh = preprocess_geometry(mesh, cubic_size)
    
    # 3. Iterate over cameras
    for pose, depth_image in zip(camera_poses, depth_images):
        extrinsic = pose.extrinsic
        intrinsic = pose.intrinsic
        
        # 4. Carve using depth map
        # For each pixel in the depth image
        for u, v in pixels(depth_image):
            depth_val = depth_image[u, v]
            
            # Calculate 3D point at depth
            # Ray direction in camera space
            ray_cam = unproject_pixel(u, v, depth_val, intrinsic)
            # Transform to world space
            ray_world = extrinsic[:3, :3] * ray_cam + extrinsic[:3, 3]
            camera_center = extrinsic[:3, 3]
            
            # Cast ray from camera center to depth_val
            # Mark voxels along this segment as occupied
            voxels_near = get_voxels_intersected(camera_center, ray_world, depth_val)
            for v_near in voxels_near:
                grid.set_occupied(v_near, True)
                
            # Mark voxels beyond depth_val as empty (carved out)
            voxels_far = get_voxels_intersected(camera_center, ray_world, max_range)
            for v_far in voxels_far:
                if not is_in(voxels_near, v_far):
                    grid.set_occupied(v_far, False)
                    
    return grid
```

**Parameters:**
- `voxel_resolution`: Controls grid density. Typical values depend on scene scale [S1].
- `cubic_size`: Defines the bounding box dimension. The grid is centered at the origin with bounds $[-\text{cubic\_size}/2, \text{cubic\_size}/2]$ [S1].

**Edge Cases:**
- **Calibration Errors**: Standard space carving requires accurate camera calibration. Approximate Space Carving handles errors by relaxing constraints [S2, unofficial].
- **Concavities**: Standard silhouette carving may fail to reconstruct deep concavities. Cell Carving addresses this using correspondence between arbitrary image regions [S2, unofficial].
- **Precision**: Floating point depth maps should be used to avoid quantization errors during ray casting [S1].

## Subtopics

### Streaming GPU-based Voxel Carving
A method that creates an explicit volume using only surface voxels in a GPU-optimal 2D data representation, avoiding 3D texture drawbacks and minimizing GPU-CPU data transfer through load balancing [S2, unofficial]. It does not sacrifice interactivity for speed [S2, unofficial].

### Interactive Multi-resolution Voxel Carving
A CPU-based method using GVC-IB as its core, adding user-driven interactive refinement. Users assign perceptual significance to features via 2D image editing operations to manipulate complexity and level of detail across the voxel structure [S2, unofficial].

### Cell Carving
An algorithm using correspondence between arbitrary image regions to enable reconstruction of concavities that are difficult or impossible to reconstruct with standard silhouette or depth carving methods [S2, unofficial].

### Voxel Space Warping
A method that warps the voxel space to model large-scale scenes (e.g., outdoors) without requiring an excessive number of voxels [S2, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N^3 \cdot V)$ where $N$ is the resolution and $V$ is the number of voxels, or more accurately $O(P \cdot R)$ where $P$ is the number of pixels in all depth maps and $R$ is the average ray length in voxels. It is computationally expensive, taking seconds to minutes [S2, unofficial].
- **Memory Complexity**: $O(N^3)$ for a dense grid. Sparse variants or explicit surface representations (like the GPU streaming method) reduce this to $O(S)$ where $S$ is the number of surface voxels [S2, unofficial].
- **Strengths**: Produces dense, filled volumes; robust to noise if multiple views are available; handles complex geometry.
- **Limitations**: Requires accurate camera calibration; high memory usage for high resolutions; struggles with concavities without extensions; sensitive to calibration errors [S2, unofficial].
- **When to use**: When a dense volumetric representation is needed for rendering or simulation, and multiple calibrated views are available.
- **When not to use**: For real-time applications with limited hardware (unless using GPU streaming variants); when only surface geometry is required (use mesh extraction instead).

## Background
Voxel Carving, also known as Space Carving, was introduced by Seitz and Dyer [SeiDye97] as a method to reconstruct 3D structure from multiple views. It is based on the principle of volume intersection: a voxel is occupied if it is consistent with all input views. The method has been extended to handle uncalibrated views [S2, unofficial], GPU acceleration [S2, unofficial], and multi-resolution representations [S2, unofficial]. It is widely used in 3D reconstruction, virtual reality, and computer graphics for generating volumetric data from 2D images.
