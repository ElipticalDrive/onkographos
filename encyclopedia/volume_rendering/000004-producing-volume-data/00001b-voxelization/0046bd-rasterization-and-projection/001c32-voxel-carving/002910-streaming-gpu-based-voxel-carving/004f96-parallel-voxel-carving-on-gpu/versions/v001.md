# Parallel Voxel Carving on GPU

Also called: Parallel Voxel Carving

## Overview
Parallel Voxel Carving on GPU is a method for reconstructing 3D geometry from multi-view images by executing voxel-by-voxel visibility tests in parallel on a graphics processor [S1, unofficial]. It solves the problem of efficiently generating an explicit, surface-oriented volume representation for large-scale scenes, such as urban environments, by leveraging the GPU's massive parallelism to process independent voxel columns simultaneously [S1, unofficial]. It differs from its parent method, Streaming GPU-based Voxel Carving, by explicitly defining the thread-to-voxel mapping strategy (y-axis columns) and the specific data layout (8-byte quantized planes) required for high-throughput parallel execution, while building on the streaming and load-balancing principles established in [Streaming GPU-based Voxel Carving](4436-streaming-gpu-based-voxel-carving.md).

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of calibrated input views (images and depth maps), camera projection matrices, and a 3D bounding volume defined by the x-z plane extent and y-axis height.
*   **Outputs:** A set of "surface" voxels, each containing a quantized plane representation (normal and distance) and an averaged color. Non-surface voxels are discarded.

**Data Structures:**
The core data structure for a surface voxel is an 8-byte block [S1, unofficial]:
1.  **Plane Quantities (4 bytes):** Four signed 1-byte values representing the plane equation $Ax + By + Cz + D = 0$.
    *   $A, B, C$: Normal vector components.
    *   $D$: Normalized distance. Defined as the ratio of the signed distance between the plane and the voxel center to the half-diagonal of the voxel cube [S1, unofficial].
    *   Range: $-127$ to $+127$.
    *   Value $-128$: Indicates no intersection with the voxel; the voxel/plane is removed [S1, unofficial].
2.  **Color (4 bytes):** One byte per RGBA component.
    *   The Alpha component stores the voxel visibility mode: 'uncarved', 'carved', or 'surface' [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Tag all voxels in the volume as 'uncarved' [S1, unofficial].
2.  **Thread Assignment:** Assign one GPU thread to each column of voxels along the y-axis. This balances workload because urban scenes are typically flat on the x-z plane [S1, unofficial]. For a $256^3$ volume, $256^2$ threads are launched, with each thread processing 256 voxels [S1, unofficial].
3.  **Carving Loop:** For each voxel in the assigned y-axis column:
    a.  Iterate through all input views.
    b.  Project the voxel center onto the image plane of the current view to determine the corresponding pixel coordinates.
    c.  Retrieve the depth value $d_{depth}$ from the depth map at those coordinates.
    d.  Calculate the Euclidean distance $d_{voxel}$ from the voxel center to the camera position.
    e.  **Visibility Test:**
        *   If $d_{voxel} < d_{depth}$: The voxel is in front of the observed surface. Mark it as 'carved' and stop processing this voxel for subsequent views [S1, unofficial].
        *   If $d_{voxel} > d_{depth}$: The voxel is behind the observed surface. Preserve the current tag [S1, unofficial].
    f.  **Termination:** If a voxel is marked 'carved', it is no longer examined by later camera projections [S1, unofficial].
4.  **Surface Tagging:** After checking all views, any voxel still tagged 'uncarved' is checked against the depth maps. If the voxel is within a specified threshold distance of a depth map value, it is tagged as 'surface' [S1, unofficial].
5.  **Color and Normal Computation:** For each 'surface' voxel:
    a.  **Color:** For each view where the voxel is visible, bilinearly interpolate the color from the neighboring pixels in the image onto which the voxel is projected. Average these colors using weights based on the angle between the surface normal and the viewing direction (following Debevec et al. [6]) [S1, unofficial].
    b.  **Normal/Distance:** If multiple planes intersect the voxel cube, compute the final normal and distance as weighted averages of the intersecting planes, similar to signed distance and weight functions described in [3] [S1, unofficial].
    c.  **Quantization:** Quantize the resulting $A, B, C, D$ values to signed 1-byte integers in the range $[-127, 127]$. Set invalid values to $-128$ [S1, unofficial].
6.  **Point-Based Rendering Adjustment (Optional):** If the output is intended for point-based rendering (e.g., QSplat), shift the center of each surface voxel to the nearest point on its weighted average plane [S1, unofficial].

**Pseudocode:**
```python
# Constants
MAX_BYTE = 127
INVALID_BYTE = -128
THRESHOLD = 0.0 # Distance threshold for surface tagging

# Data Structures
class Voxel:
    mode: int # 0: uncarved, 1: carved, 2: surface
    A: int
    B: int
    C: int
    D: int
    R: int
    G: int
    B: int
    Alpha: int # Reused for mode in storage, but logically separate in process

def quantize(value, min_val, max_val):
    # Map float to signed 1-byte int
    # Clamp to [-127, 127]
    if value < -1.0: return INVALID_BYTE
    if value > 1.0: return INVALID_BYTE
    return int(round(value * MAX_BYTE))

def parallel_voxel_carving(volume_dims, cameras, depth_maps):
    # volume_dims: (Vx, Vy, Vz)
    # cameras: list of camera objects with projection and depth_map
    # depth_maps: list of 2D arrays corresponding to cameras
    
    # Initialize volume
    # Note: In GPU implementation, this is done via kernel launch or texture initialization
    volume = [[[[Voxel(mode=0, A=0, B=0, C=0, D=0, R=0, G=0, B=0, Alpha=0) 
                 for z in range(volume_dims[2])] 
                for y in range(volume_dims[1])] 
               for x in range(volume_dims[0])] 
              for _ in range(1)] # Simplified structure for logic

    # Thread function: Each thread handles a fixed (x, z) column
    def thread_func(x, z):
        for y in range(volume_dims[1]):
            voxel = volume[0][x][y][z]
            
            # Loop over all views
            for i, camera in enumerate(cameras):
                if voxel.mode == 1: # Already carved
                    break
                
                # Project voxel to image plane
                # Assuming camera has a method to project world point to image coords
                u, v = camera.project(voxel.center)
                
                # Check bounds
                if not camera.is_in_bounds(u, v):
                    continue
                
                # Get depth from depth map
                d_depth = depth_maps[i][v][u]
                
                # Calculate distance from camera to voxel
                d_voxel = camera.distance_to(voxel.center)
                
                if d_voxel < d_depth:
                    voxel.mode = 1 # Carved
                # Else: preserved (remains uncarved or surface candidate)
            
            # After all views, check for surface
            if voxel.mode == 0:
                is_surface = False
                for i, camera in enumerate(cameras):
                    u, v = camera.project(voxel.center)
                    if camera.is_in_bounds(u, v):
                        d_depth = depth_maps[i][v][u]
                        d_voxel = camera.distance_to(voxel.center)
                        if abs(d_voxel - d_depth) <= THRESHOLD:
                            is_surface = True
                            break
                
                if is_surface:
                    voxel.mode = 2 # Surface
                    # Compute color and normal
                    compute_surface_properties(voxel, cameras, depth_maps)

    # Launch threads
    # For 256^3 volume, launch 256^2 threads
    # Each thread calls thread_func(x, z) for its assigned x, z
    for x in range(volume_dims[0]):
        for z in range(volume_dims[2]):
            thread_func(x, z)

def compute_surface_properties(voxel, cameras, depth_maps):
    # Compute weighted average normal and distance
    total_weight = 0.0
    avg_A = 0.0
    avg_B = 0.0
    avg_C = 0.0
    avg_D = 0.0
    weighted_color_sum = [0.0, 0.0, 0.0, 0.0]
    
    for i, camera in enumerate(cameras):
        u, v = camera.project(voxel.center)
        if not camera.is_in_bounds(u, v):
            continue
            
        d_depth = depth_maps[i][v][u]
        d_voxel = camera.distance_to(voxel.center)
        
        # Check if close to surface
        if abs(d_voxel - d_depth) <= THRESHOLD:
            # Get surface normal from depth map gradient or camera ray
            # Simplified: use camera ray direction as normal approximation for weighting
            # Or compute from local depth variation
            normal = camera.get_normal_at(u, v)
            dist = d_voxel # Signed distance relative to voxel center
            
            # Weight based on angle between normal and viewing direction
            view_dir = camera.get_view_direction_at(u, v)
            weight = max(0.0, dot(normal, view_dir)) # Debevec et al. weighting
            
            # Plane parameters from camera view
            # A, B, C from normal, D from distance ratio
            # D is ratio of signed distance to half-diagonal
            half_diag = voxel.half_diagonal_length
            D_val = dist / half_diag
            
            avg_A += normal.x * weight
            avg_B += normal.y * weight
            avg_C += normal.z * weight
            avg_D += D_val * weight
            total_weight += weight
            
            # Color interpolation
            color = camera.interpolate_color(u, v)
            weighted_color_sum[0] += color.R * weight
            weighted_color_sum[1] += color.G * weight
            weighted_color_sum[2] += color.B * weight
            weighted_color_sum[3] += color.A * weight
            
    if total_weight > 0:
        voxel.A = quantize(avg_A / total_weight, -1.0, 1.0)
        voxel.B = quantize(avg_B / total_weight, -1.0, 1.0)
        voxel.C = quantize(avg_C / total_weight, -1.0, 1.0)
        voxel.D = quantize(avg_D / total_weight, -1.0, 1.0)
        
        voxel.R = int(weighted_color_sum[0] / total_weight)
        voxel.G = int(weighted_color_sum[1] / total_weight)
        voxel.B = int(weighted_color_sum[2] / total_weight)
        voxel.Alpha = 255 # Surface is opaque
        
        # Adjust center for point rendering if needed
        # shift_center_to_plane(voxel)
```

**Parameters:**
*   **Volume Size per Kernel:** Approximately $256^3$ voxels, limited by GPU memory [S1, unofficial].
*   **Thread Count:** $256^2$ threads for a $256^3$ volume [S1, unofficial].
*   **Threshold:** Distance threshold for tagging 'surface' voxels. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Quantization to 1-byte signed integers limits normal and distance precision. Values outside $[-127, 127]$ are clamped or marked invalid ($-128$) [S1, unofficial].
*   **Boundaries:** Voxels projected outside the image bounds of a view are ignored for that view [S1, unofficial].
*   **Degenerate Input:** If depth maps are missing or noisy, the visibility test may fail, leading to incorrect carving or failure to tag surface voxels [S1, unofficial].

## Subtopics

### [Scalable Reconstruction Scheme](14018-scalable-reconstruction-scheme.md)
A scheme to reconstruct large-scale urban scenes by exploiting streaming computation and GPU-accelerated parallel computation, partitioning the volume into sub-volumes. It addresses the memory limitation of the single kernel by dividing the scene, whereas Parallel Voxel Carving on GPU focuses on the parallel execution within a single volume block.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels and the number of views ($O(V \cdot N)$), where $V$ is the number of voxels and $N$ is the number of views. Parallelization reduces wall-clock time by a factor proportional to the number of threads, up to GPU saturation.
*   **Memory Complexity:** $O(V)$ for the volume data structure. Each voxel stores 8 bytes. For a $256^3$ volume, this is $256^3 \times 8$ bytes $\approx 128$ MB [S1, unofficial].
*   **Measured Performance:** The method is designed for GPU memory limits, handling $\approx 256^3$ voxels per kernel [S1, unofficial]. Performance drops rapidly as resolution increases beyond this limit without the scalable scheme.
*   **Strengths:** High parallelism, efficient memory usage (8 bytes/voxel), suitable for flat scenes (urban).
*   **Limitations:** Limited by GPU memory per kernel ($256^3$), requires careful load balancing (y-axis carving), quantization artifacts.
*   **When to Use:** Large-scale urban scene reconstruction where memory is constrained but parallel throughput is needed.
*   **When Not to Use:** Scenes with high vertical complexity (where y-axis load balancing fails) or when sub-voxel precision is required beyond 1-byte quantization.

## Background
Parallel Voxel Carving on GPU was introduced in the paper "GPU-based Scalable Volumetric Reconstruction for Multi-view Stereo" [S1, unofficial]. It builds upon the principles of voxel carving and leverages the parallel architecture of GPUs to accelerate the visibility testing process. The method is particularly suited for urban scenes due to the flatness of the x-z plane, which allows for effective workload distribution among threads.
