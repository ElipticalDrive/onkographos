# Forward Projection
Also called: ASTRA CUDA Projector Wrapper

## Overview
Forward projection maps a 3D volume dataset into 2D projection space (sinograms) by simulating the line integrals of X-ray attenuation along specific acquisition trajectories defined by a geometry object [S1, unofficial]. It serves as the forward model in iterative reconstruction algorithms, such as SIRT or PWLS, where it computes the estimated projections from a current volume estimate to calculate residuals [S1, unofficial]. Unlike spectral or filtered methods that modify the data content during projection, this method performs a standard additive projection without spectral effects [S1, unofficial].

## How it works
**Inputs and Outputs:**
- `vol`: Input 3D volume array (float32).
- `proj`: Output projection array, initialized as zeros with dtype float32 [S1, unofficial].
- `geometry`: Projection geometry object defining the acquisition setup (source, detector, and rotation parameters) [S1, unofficial].
- `sign`: Scalar, either +1 or -1, determining whether to add or subtract the projected data [S1, unofficial].
- `settings.subsets`: Integer specifying the number of memory-efficient subsets for large volumes [S1, unofficial].

**Data Structures:**
The method relies on the ASTRA Toolbox data structures.
- `vol_geom`: Geometry descriptor for the volume, created from `vol` dimensions and physical spacing.
- `proj_geom`: Geometry descriptor for the projections, derived from `geometry`.
- `vol_id`: ASTRA data handle linked to the volume memory.
- `sin_id`: ASTRA data handle linked to the projection memory.
- `projector_id`: ASTRA projector handle (type 'cuda3d') linking `vol_geom` and `proj_geom`.

**Steps:**
1.  **Preprocessing and Contiguity Check:**
    -   Check if `vol` is contiguous in memory. If not, create a contiguous copy `vol_temp = numpy.ascontiguousarray(volume)` [S1, unofficial].
    -   If `vol` is a `numpy.memmap`, ensure `vol_temp` is linked to the original memory layout for efficient back-copying [S1, unofficial].
    -   Determine the number of subsets from `settings.subsets`. If not set, default to 1 [S1, unofficial].

2.  **Subset Generation:**
    -   Initialize the output `proj` array to zeros [S1, unofficial].
    -   Generate subsets of the projection data and corresponding geometry objects using a subset generator function `_subset_generator_` [S1, unofficial]. This function yields tuples of `(subset, pro_geom, vol_geom)` for each subset [S1, unofficial].

3.  **Linking and Projector Creation:**
    -   For each subset, link the volume data to ASTRA: `vol_id = astra.data3d.link('-vol', vol_geom, vol_temp)` [S1, unofficial].
    -   Link the projection subset to ASTRA: `sin_id = astra.data3d.link('-sino', proj_geom, subset)` [S1, unofficial].
    -   Create the CUDA 3D projector: `projector_id = astra.create_projector('cuda3d', proj_geom, vol_geom)` [S1, unofficial].

4.  **Execution:**
    -   Perform the forward projection operation. The specific ASTRA algorithm used depends on whether filtering is applied in the broader reconstruction context. For pure forward projection, the accumulation is typically handled via `astra.algorithm.execute` or a specific forward projection call. Based on the source, the operation adds to the subset:
        -   If not filtered: `astra.algorithm.execute(projector_id, vol_id, sin_id)` [S1, unofficial].
        -   Note: The source mentions `asex.accumulate_BP` and `asex.accumulate_FDK`, but these are specific to backprojection or FDK reconstruction loops. For pure forward projection, the standard ASTRA forward projection algorithm is used, which computes the line integrals and adds them to the `sin_id` buffer [S1, unofficial].
    -   The `sign` parameter is applied during the accumulation if the wrapper supports signed operations, or handled by pre-multiplying the volume or result [S1, unofficial].

5.  **Cleanup and Update:**
    -   Delete ASTRA data handles: `astra.data3d.delete(vol_id)`, `astra.data3d.delete(sin_id)` [S1, unofficial].
    -   Delete the projector handle: `astra.algorithm.delete(projector_id)` [S1, unofficial].
    -   If a contiguous copy `vol_temp` was created, update the original subset array in `proj` with the results from the ASTRA buffer [S1, unofficial].
    -   If `vol` was a `memmap`, copy the results back: `volume[:] = vol_temp` [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Memory Contiguity:** ASTRA requires contiguous memory buffers. Non-contiguous arrays must be copied, which incurs memory overhead [S1, unofficial].
-   **Memmap Handling:** When using `numpy.memmap`, the temporary contiguous array must be correctly linked and copied back to avoid data loss or memory leaks [S1, unofficial].
-   **Data Types:** The volume and projection arrays must be `float32` to match ASTRA's expectations [S1, unofficial].
-   **Geometry Consistency:** The `vol_geom` and `proj_geom` must be consistent with the physical dimensions and pixel sizes of the input data [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Linear with respect to the number of voxels and the number of projection angles. The CUDA implementation provides significant speedup over CPU-based methods [S1, unofficial].
-   **Memory Complexity:** Proportional to the size of the volume and projection data. Subset splitting reduces peak memory usage by processing projections in chunks [S1, unofficial].
-   **Performance:** Highly efficient on NVIDIA GPUs due to the CUDA3D projector implementation [S1, unofficial].
-   **Strengths:** Fast, accurate forward model for iterative reconstruction; supports large datasets via subset splitting [S1, unofficial].
-   **Limitations:** Requires GPU memory; dependent on ASTRA Toolbox availability and compatibility [S1, unofficial].

## Background
Forward projection is a fundamental operation in computed tomography (CT) reconstruction, simulating the physical process of X-ray attenuation. The ASTRA Toolbox, a high-performance toolbox for 2D and 3D image reconstruction, provides efficient CUDA-based projectors [S1, unofficial]. The flexTOMO library wraps this functionality to integrate it into a broader tomographic reconstruction pipeline [S1, unofficial].
