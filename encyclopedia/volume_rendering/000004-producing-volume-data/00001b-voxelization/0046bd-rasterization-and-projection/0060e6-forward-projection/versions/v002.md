# Forward Projection
Also called: 3D → 2D Forward Projection, Voxel-to-Detector Projection, project

## Overview
Forward projection maps a 3D volume dataset into 2D projection space (sinograms) by simulating line integrals of X-ray attenuation along acquisition trajectories defined by a geometry object [S4, unofficial]. It serves as the forward model in iterative reconstruction algorithms, such as SIRT or PWLS, where it computes estimated projections from a current volume estimate to calculate residuals [S4, unofficial]. Unlike spectral or filtered methods that modify data content during projection, this method performs a standard additive projection without spectral effects [S4, unofficial].

## How it works
**Inputs and Outputs:**
- `vol`: Input 3D volume array (float32) [S4, unofficial].
- `proj`: Output projection array, initialized as zeros with dtype float32 [S4, unofficial].
- `geometry`: Projection geometry object defining the acquisition setup (source, detector, and rotation parameters) [S4, unofficial].
- `sign`: Scalar, either +1 or -1, determining whether to add or subtract the projected data [S4, unofficial].
- `settings.subsets`: Integer specifying the number of memory-efficient subsets for large volumes [S4, unofficial].

**Data Structures:**
The method relies on the ASTRA Toolbox data structures [S4, unofficial].
- `vol_geom`: Geometry descriptor for the volume, created from `vol` dimensions and physical spacing [S4, unofficial].
- `proj_geom`: Geometry descriptor for the projections, derived from `geometry` [S4, unofficial].
- `vol_id`: ASTRA data handle linked to the volume memory [S4, unofficial].
- `sin_id`: ASTRA data handle linked to the projection memory [S4, unofficial].
- `projector_id`: ASTRA projector handle (type 'cuda3d') linking `vol_geom` and `proj_geom` [S4, unofficial].

**Steps:**
1. **Preprocessing and Contiguity Check:** Check if `vol` is contiguous in memory. If not, create a contiguous copy `vol_temp = numpy.ascontiguousarray(volume)` [S4, unofficial]. If `vol` is a `numpy.memmap`, ensure `vol_temp` is linked to the original memory layout for efficient back-copying [S4, unofficial].
2. **Subset Generation:** Initialize the output `proj` array to zeros [S4, unofficial]. Determine the number of subsets from `settings.subsets` [S4, unofficial]. Loop over subsets generated by the internal subset generator [S4, unofficial].
3. **Linking and Projector Creation:** Link the volume data to ASTRA using the original array: `vol_id = astra.data3d.link('-vol', vol_geom, volume)` [S4, unofficial]. Link the projection subset to ASTRA: `sin_id = astra.data3d.link('-sino', proj_geom, projections)` [S4, unofficial]. Create the CUDA 3D projector: `projector_id = astra.create_projector('cuda3d', proj_geom, vol_geom)` [S4, unofficial].
4. **Execution:** Perform the forward projection operation. The specific accumulation function depends on filtering: if not filtered, call `asex.accumulate_BP(projector_id, vol_id, sin_id)`; if filtered, call `asex.accumulate_FDK(projector_id, vol_id, sin_id)` [S4, unofficial].
5. **Cleanup and Update:** Delete ASTRA data handles: `astra.data3d.delete(vol_id)` and `astra.data3d.delete(sin_id)` [S4, unofficial]. Delete the projector handle: `astra.algorithm.delete(projector_id)` [S4, unofficial]. Update the original subset array with the contiguous copy [S4, unofficial]. If `vol` was a `memmap`, copy the results back: `volume[:] = vol_temp` [S4, unofficial].
6. **Sign Application:** The `sign` parameter is applied during the accumulation by passing it to `_forwardproject_block_add_(subset_c, volume, pro_geom, vol_geom, sign)` where it acts as +1 or -1 to add or subtract the data [S4, unofficial].

**Pseudocode:**
```python
import numpy as np
import astra

def forward_project(volume, proj, geometry, sign=1.0, settings=None):
    """
    Forward projects a volume into sinogram space using ASTRA CUDA3D projector.
    """
    if settings is None:
        settings = type('Settings', (), {'subsets': 1})()
    num_subsets = settings.subsets

    # Handle memory contiguity and memmap
    if isinstance(volume, np.memmap):
        vol_temp = np.ascontiguousarray(volume)
        is_memmap = True
    elif not volume.flags['C_CONTIGUOUS']:
        vol_temp = np.ascontiguousarray(volume)
        is_memmap = False
    else:
        vol_temp = volume
        is_memmap = False

    # Initialize output
    proj[:] = 0.0

    # Loop over subsets
    for i in range(num_subsets):
        # Generate subset geometry and data slice
        # The sources do not provide the internal subset generator implementation
        pro_geom, vol_geom, subset_slice = _get_subset_geometry_and_slice(geometry, volume.shape, proj.shape, i, num_subsets)
        subset = proj[subset_slice]

        # Link data to ASTRA (uses original volume array, not vol_temp)
        vol_id = astra.data3d.link('-vol', vol_geom, volume)
        sin_id = astra.data3d.link('-sino', pro_geom, subset)

        # Create projector
        projector_id = astra.create_projector('cuda3d', pro_geom, vol_geom)

        # Execute forward projection
        # Uses asex.accumulate_BP if not filtered, else asex.accumulate_FDK
        asex.accumulate_BP(projector_id, vol_id, sin_id)

        # Cleanup
        astra.data3d.delete(vol_id)
        astra.data3d.delete(sin_id)
        astra.algorithm.delete(projector_id)

        # Apply sign via block add function
        _forwardproject_block_add_(subset, volume, pro_geom, vol_geom, sign)

    # Copy back if memmap
    if is_memmap:
        volume[:] = vol_temp

def _get_subset_geometry_and_slice(geometry, vol_shape, proj_shape, subset_idx, num_subsets):

    return geometry, geometry, slice(None)

def _forwardproject_block_add_(subset, volume, pro_geom, vol_geom, sign):

    subset[:] *= sign
```

**Edge Cases and Pitfalls:**
- **Memory Contiguity:** ASTRA requires contiguous memory buffers. Non-contiguous arrays must be copied, which incurs memory overhead [S4, unofficial].
- **Memmap Handling:** When using `numpy.memmap`, the temporary contiguous array must be correctly linked and copied back to avoid data loss or memory leaks [S4, unofficial].
- **Data Types:** The volume and projection arrays must be `float32` to match ASTRA's expectations [S4, unofficial].
- **Geometry Consistency:** The `vol_geom` and `proj_geom` must be consistent with the physical dimensions and pixel sizes of the input data [S4, unofficial].

## Subtopics

### Parallel Beam Forward Projection
A simulation technique to generate synthetic X-ray projection data from a 3D volume using a parallel beam geometry, assuming a perfectly monochromatic source and ideal detector response [S5]. The forward projection operator is configured for parallel beam geometry with uniform projection angles between 0° and 180°, a detector width of 300 pixels, and each simulation time step projected independently as a static volume [S5]. High-quality FBP reconstruction requires at least 471 projections for a 300-pixel detector, with 720 used conservatively [S5].

### Tomographic Projection Calculation (Radon Method)
Computes the Radon transform for each z-slice in the voxelized object using a built-in Radon function, passes the resulting sinograms through a Ram-Lak filter in the Fourier domain, and performs coordinate system remapping to account for refraction at the air-vial interface and non-telecentricity of the optical source [S6].

### Fourier-Space Forward Projection (Central Slice Theorem)
Generates 2D projections from a 3D Fourier-space reconstruction by sampling central slices through the 3D volume, implementing the Central Slice Theorem [S3, unofficial]. It extends 2D projection coordinates to 3D by setting the third coordinate to zero, applies a 3×3 rotation matrix inverse to map coordinates to the reconstruction space, and performs trilinear or tricubic interpolation with phase modulation for translation [S3, unofficial]. Gradients are computed via chain rule extension for rotation matrices and spatial derivatives for interpolation kernels [S3, unofficial].

### [Robust SIRT](18352-robust-sirt.md)
An algebraic reconstruction technique that modifies the standard Simultaneous Iterative Reconstruction Technique (SIRT) to be resilient to outliers in projection data by employing a Student's t-distribution likelihood model. It builds on Forward Projection by enabling specific robust weighting within the ASTRA projector framework. Unlike standard SIRT, which minimizes the L2-norm of residuals and is sensitive to noise spikes, Robust SIRT down-weights large residuals, making it suitable for data with impulsive noise or artifacts.

### [Forward Projection with Siddon's Algorithm](18800-forward-projection-with-siddon-s-algorithm.md)
Computes the length of intersection between rays and voxels to project volume data into sinogram bins. It distinguishes itself from sibling methods by explicitly calculating geometric ray-voxel intersections rather than relying on iterative reconstruction or simplified binning approximations.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of voxels and the number of projection angles [S4, unofficial].
- **Memory Complexity:** Proportional to the size of the volume and projection data [S4, unofficial].
- **Performance:** Highly efficient on NVIDIA GPUs due to the CUDA3D projector implementation [S4, unofficial].
- **Strengths:** Supports large datasets via subset splitting to reduce peak memory usage [S4, unofficial].
- **Limitations:** Requires GPU memory; dependent on ASTRA Toolbox availability and compatibility [S4, unofficial].

## Background
Forward projection is a fundamental operation in computed tomography (CT) reconstruction, simulating the physical process of X-ray attenuation [S4, unofficial]. The ASTRA Toolbox provides efficient CUDA-based projectors for 2D and 3D image reconstruction [S4, unofficial]. The flexTOMO library wraps this functionality to integrate it into a broader tomographic reconstruction pipeline [S4, unofficial].
