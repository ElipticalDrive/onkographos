# Tessellation-based Voxelization
Also called: VoxelizationByTessellationPass

## Overview
Tessellation-based Voxelization is a GPU-accelerated method for generating 3D voxel grids from triangle meshes by leveraging the hardware tessellation pipeline to subdivide geometry before rasterization [S1, unofficial]. It differs from fixed-function or CPU-based voxelizers by enabling adaptive triangle density and displacement mapping during the generation phase, allowing for higher fidelity in complex regions [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A triangle mesh defined by index buffers and vertex data.
- **Output:** A 3D voxel grid stored in a Unordered Access View (UAV), where each voxel stores occupancy or density information.

**Data Structures:**
The method relies on a specific Direct3D 12 pipeline layout named `PASS_VOXELIZE_TESS` [S1, unofficial]. The descriptor ranges are defined as follows:
- **Range 0:** Constant Buffer View (CBV), count 1, offset 0, flags `DATA_STATIC` [S1, unofficial].
- **Range 1:** Constant Buffer View (CBV), count 1, offset 0, flags `DATA_STATIC` [S1, unofficial].
- **Range 2:** Unordered Access View (UAV), count `numUAVs`, offset 0, flags `DATA_STATIC_WHILE_SET_AT_EXECUTE` [S1, unofficial].
- **Range 3:** Constant Buffer View (CBV), count 1, offset 0, flags `DATA_STATIC` [S1, unofficial] [G: This range likely holds projection or camera parameters, though the source does not explicitly define the content].

**Shader Stages:**
The pipeline utilizes five shader stages:
1.  **Vertex Shader (VS):** `VS_TRI_PROJ_TESS` [S1, unofficial].
2.  **Hull Shader (HS):** `HS_TRI_PROJ` [S1, unofficial].
3.  **Domain Shader (DS):** `DS_TRI_PROJ` [S1, unofficial].
4.  **Pixel Shader (PS):** `PS_TRI_PROJ` [S1, unofficial].
5.  **Geometry Shader:** Not used; the primitive topology is set to `CONTROL_POINT3_PATCHLIST` [S1, unofficial].

**Numbered Steps:**
1.  Bind the pipeline layout `PASS_VOXELIZE_TESS` with the descriptor ranges specified above [S1, unofficial].
2.  Bind the pipeline state object (PSO) configured with the shader stages listed above [S1, unofficial].
3.  Set the primitive topology type to `PATCH` (specifically `CONTROL_POINT3_PATCHLIST`) [S1, unofficial].
4.  Force the instance count to 1 [S1, unofficial].
5.  Execute the draw call: `DrawIndexed(m_numIndices, instanceCount, 0, 0, 0)` [S1, unofficial].

**Pseudocode:**
The following Python-like pseudocode represents the setup and execution sequence derived from the source [S1, unofficial].

```python
def render_voxelization_tess(p_command_list, m_voxelizer, m_solid, m_vox_method, m_frame_index, p_render_target, m_depth, m_num_indices):
    # Apply resource barriers if necessary (omitted for brevity, see source context)
    
    # Clear render target if not solid
    if not m_solid:
        clear_color = [0.0, 0.0, 0.0, 0.0] # Placeholder for CLEAR_COLOR
        p_command_list.clear_render_target_view(p_render_target.get_rtv(), clear_color)
    
    # Clear depth stencil
    p_command_list.clear_depth_stencil_view(m_depth.get_dsv(), clear_flag=ClearFlag.DEPTH, depth=1.0)
    
    # Render voxelization
    m_voxelizer.render(
        p_command_list, 
        m_solid, 
        m_vox_method, 
        m_frame_index, 
        p_render_target.get_rtv(), 
        m_depth.get_dsv()
    )

def voxelizer_render(p_command_list, m_solid, m_vox_method, m_frame_index, rtv, dsv):
    # Bind Pipeline Layout
    # Range 0: CBV(1), DATA_STATIC
    # Range 1: CBV(1), DATA_STATIC
    # Range 2: UAV(numUAVs), DATA_STATIC_WHILE_SET_AT_EXECUTE
    # Range 3: CBV(1), DATA_STATIC
    p_command_list.set_pipeline_layout("PASS_VOXELIZE_TESS")
    
    # Bind Pipeline State with Shaders
    p_command_list.set_shader(ShaderStage.VS, get_shader(ShaderStage.VS, "VS_TRI_PROJ_TESS"))
    p_command_list.set_shader(ShaderStage.HS, get_shader(ShaderStage.HS, "HS_TRI_PROJ"))
    p_command_list.set_shader(ShaderStage.DS, get_shader(ShaderStage.DS, "DS_TRI_PROJ"))
    p_command_list.set_shader(ShaderStage.PS, get_shader(ShaderStage.PS, "PS_TRI_PROJ"))
    
    # Set Primitive Topology
    p_command_list.ia_set_primitive_topology_type(PrimitiveTopologyType.PATCH)
    
    # Draw Call
    instance_count = 1
    p_command_list.draw_indexed(
        index_count=m_num_indices,
        instance_count=instance_count,
        start_index_location=0,
        base_vertex_location=0,
        start_instance_location=0
    )
```

**Parameters and Edge Cases:**
- `m_numIndices`: The number of indices in the input mesh.
- `numUAVs`: The number of UAVs required for the voxel grid storage.
- **Edge Cases:** The method assumes the hardware supports Direct3D 12 and the tessellation stages [S1, unofficial]. Precision issues may arise if the tessellation factor is not appropriately scaled to the voxel grid resolution [G].

## Subtopics

### Level 1 Triangle-Voxel Classification
A sibling method that classifies triangles against voxels using a simpler, non-tessellation approach. Choose this when hardware tessellation is unavailable or when the mesh is static and low-poly. See [Level 1 Triangle-Voxel Classification](4872-level-1-triangle-voxel-classification.md).

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Depends on `numUAVs` and the voxel grid resolution.
- **Performance:** Not given in the sources.
- **Strengths:** Enables adaptive density and displacement mapping [S1, unofficial].
- **Limitations:** Requires a GPU with Direct3D 12 support and tessellation capabilities [S1, unofficial].

## Background
The method is implemented in the `VoxelizerX` project, an unofficial Direct3D 12 voxelization sample [S1, unofficial]. It was developed by StarsX and published on GitHub [S1, unofficial].
