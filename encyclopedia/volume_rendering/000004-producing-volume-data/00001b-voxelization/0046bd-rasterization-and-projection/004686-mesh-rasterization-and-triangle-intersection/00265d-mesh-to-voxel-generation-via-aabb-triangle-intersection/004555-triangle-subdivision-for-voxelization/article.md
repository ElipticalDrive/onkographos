# Triangle Subdivision for Voxelization

Also called: Triangle Split, Triangle Splitting, Pre-processing Subdivision

## Overview
Triangle Subdivision for Voxelization is a pre-processing method that recursively splits mesh triangles to ensure they are small enough to be voxelized efficiently and predictably [S1, S2]. It solves the problem of variable voxel counts per triangle, which complicates memory allocation and parallel processing in out-of-core or batch-based voxelization pipelines [S1]. Unlike general-purpose mesh smoothing or tessellation, this method is geometry-driven, targeting specific edge-length or area thresholds relative to the voxel resolution to guarantee homogeneous voxel generation and compact Morton index ranges [S1]. It differs from [Level 1 Triangle-Voxel Classification](4872-level-1-triangle-voxel-classification.md) by actively modifying the mesh geometry rather than just classifying existing triangles, and from [Tessellation-based Voxelization](5430-tessellation-based-voxelization.md) by using a deterministic, CPU/GPU-friendly iterative queue rather than hardware tessellation pipelines [S1, S2].

## How it works
**Inputs:**
- A triangle soup $\{T_i\}$, where each triangle $T$ has three vertices and three edge lengths $T.a, T.b, T.c$.
- A user-defined parameter $K_{vox/tri}^{max}$, the maximum allowed ratio of the triangle's projected bounding box area to the voxel face area [S1].
- The voxel grid resolution, defined by the voxel length $L$ [S1].

**Outputs:**
- A refined set of triangles $\{T_i\}$ (stored in result queue $R$) such that for every triangle, the area of its axis-aligned bounding box $A_{bbox}(T)$ satisfies $A_{bbox}(T) \le K_{vox/tri}^{max} \cdot A_{vox}$ [S1].
- An upper bound $N_{vox/tri}^{max}(T_i)$ for the number of voxels generated by each resulting triangle, used for pre-allocating memory [S1].

**Data Structures:**
- Queue $Q$: Stores triangles pending subdivision. Initialized with the input triangle soup.
- Queue $R$: Stores triangles that satisfy the area constraint and are ready for voxelization.
- Edge lengths: For each triangle, edges are sorted such that $T.a \le T.b \le T.c$ [S1].

**Formulas:**
1.  **Voxel Face Area:** $A_{vox} = L^2$ [S1].
2.  **Subdivision Condition:** A triangle $T$ is subdivided if $A_{bbox}(T) > K_{vox/tri}^{max} \cdot A_{vox}$ [S1].
3.  **Voxel Count Upper Bound:** $N_{vox/tri}^{max}(T_i)$ is calculated by discretizing the projected bounding box of $T_i$ onto the voxel grid to count enclosed projected voxels, then multiplying by 3. The factor of 3 accounts for the maximum number of voxels a planar triangle can occupy along the projection direction [S1].

**Parameters:**
- $K_{vox/tri}^{max}$: User-defined threshold. Typical values are not explicitly given in the sources, but it controls the granularity of the subdivision [S1].
- $L$: Voxel edge length. In [S2], a threshold of 0.5 voxel is mentioned for the longest edge, implying a specific relationship between edge length and voxel size [S2].

**Steps:**
1.  Initialize $Q$ with all input triangles $\{T_i\}$ and $R$ as empty [S1].
2.  While $Q$ is not empty:
    a. Dequeue triangle $T$ from $Q$ [S1].
    b. Calculate $A_{bbox}(T)$, the area of the axis-aligned bounding box of $T$ [S1].
    c. If $A_{bbox}(T) \le K_{vox/tri}^{max} \cdot A_{vox}$:
        i. Enqueue $T$ into $R$ [S1].
    d. Else, apply subdivision logic based on sorted edge lengths $T.a \le T.b \le T.c$ [S1]:
        i. **Case 1 (Long thin, obtuse):** If $(T.a + T.b) < 2 \cdot T.c$ (angles larger than $\sim 90^\circ$):
            - Split $T$ into two triangles.
            - Append the resulting triangles to $Q$ [S1].
        ii. **Case 2 (Long thin, acute):** If $3 \cdot T.a < T.b$ (angles smaller than $\sim 20^\circ$):
            - Subdivide $T$ to generate approximately equilateral triangles. This is done by cutting the short edge $T.a$ off the long edges and splitting the resulting quadrilateral.
            - Append the resulting triangles to $Q$ [S1].
        iii. **Case 3 (Regular):** Otherwise:
            - Compute subdivision factor $s = \sqrt{A_{bbox}(T) / (K_{vox/tri}^{max} \cdot A_{vox})}$ [S1].
            - Subdivide $T$ directly using this factor to satisfy the area constraint.
            - Enqueue the resulting triangles into $R$ [S1].
3.  The final set of triangles is $\{T_i\} = R$ [S1].

    """
    Subdivides triangles until their bounding box area is within limits.
    
    Args:
        triangles: List of Triangle objects with vertices and edge lengths.
        K_max: User-defined max ratio of bbox area to voxel face area.
        L: Voxel edge length.
        
    Returns:
        List of subdivided triangles satisfying the area constraint.
    """
    A_vox = L * L
    Q = list(triangles)  # Queue of triangles to process
    R = []               # Result queue
    
    while Q:
        T = Q.pop(0)     # Dequeue T
        
        # Calculate bounding box area of T
        # Assuming T has vertices v0, v1, v2
        min_x = min(v.x for v in T.vertices)
        max_x = max(v.x for v in T.vertices)
        min_y = min(v.y for v in T.vertices)
        max_y = max(v.y for v in T.vertices)
        A_bbox = (max_x - min_x) * (max_y - min_y)
        
        if A_bbox <= K_max * A_vox:
            R.append(T)

**Edge Cases and Pitfalls:**
- **Precision:** The area calculation $A_{bbox}(T)$ must be robust to floating-point errors, especially for very small or very large triangles [S1].
- **Degenerate Input:** Triangles with zero area or collinear vertices should be handled or filtered out before subdivision [G].
- **Infinite Loop:** The subdivision logic must guarantee that the longest edge decreases in each step to prevent infinite loops. Case 1 and 2 are designed to handle specific thin geometries, while Case 3 uses a factor that ensures the area constraint is met in one step [S1].

## Subtopics

### [Legolizer Subdivision](14398-legolizer-subdivision.md)
A GPU-based iterative refinement strategy that subdivides a triangular mesh until all edge lengths are smaller than or equal to a user-defined cube size $r$. It solves the problem of preparing boundary models for voxelization into "LEGOr" representations, ensuring uniform sampling and watertightness by guaranteeing that at least one vertex of the input mesh lies inside each resulting voxel brick. It differs from general-purpose subdivision schemes (like Catmull-Clark) by using a fixed, geometry-driven split pattern based on edge length thresholds relative to a target voxel resolution, rather than smoothing or topological refinement.

## Operating characteristics
- **Time Complexity:** The subdivision process is iterative and depends on the initial triangle sizes and the threshold $K_{vox/tri}^{max}$. In the worst case, triangles are subdivided until they meet the area constraint. The number of subdivisions is bounded by the ratio of the initial bounding box area to the target area [S1].
- **Memory Complexity:** The method requires storing the queue $Q$ and result queue $R$. The memory usage scales with the number of triangles generated. The upper bound $N_{vox/tri}^{max}(T_i)$ is used to pre-allocate memory for the voxelization step, preventing dynamic reallocation [S1].
- **Measured Performance:** Not given in the sources.
- **Scaling:** The method is designed to be processed in parallel on GPU, as mentioned in the source [S1]. However, the subdivision logic itself is sequential per triangle unless parallelized carefully.
- **Strengths:** Ensures homogeneous voxel counts per triangle, which simplifies batch processing and memory management. Compact Morton index ranges reduce fragmentation in out-of-core voxelization [S1].
- **Limitations:** Requires pre-processing of the mesh. The subdivision logic is specific to the area-based constraint and may not be optimal for all voxelization algorithms.
- **When to use:** When voxelizing meshes into sparse voxel octrees or out-of-core representations where batch processing and memory pre-allocation are critical [S1].
- **When not to use:** When real-time voxelization is required and pre-processing is not feasible, or when the mesh is already sufficiently fine-grained.

## Background
The method originates from the work on grid-free out-of-core voxelization to sparse voxel octrees on GPU [S1]. It was developed to address the challenges of processing large triangle soups efficiently on GPU by ensuring that each triangle contributes a predictable and manageable number of voxels. The subdivision scheme is a key component of the pre-processing step, enabling efficient sorting and batch processing of triangles for voxelization [S1]. The "Triangle Split" method is also referenced in comparative assessments of implicit and explicit plenoptic scene representations [S2], where it is described as a direct discretization method splitting triangles until the longest edge is smaller than 0.5 voxel.
