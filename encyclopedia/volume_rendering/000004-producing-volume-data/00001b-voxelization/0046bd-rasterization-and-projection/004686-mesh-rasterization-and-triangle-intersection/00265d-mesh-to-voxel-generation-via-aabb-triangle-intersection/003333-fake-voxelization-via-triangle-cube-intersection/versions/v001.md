# Fake Voxelization via Triangle-Cube Intersection

Also called: Laine's method implementation, Mesh Voxelization (DGtal), MeshVoxelizer, Triangle Digitization, Triangle Rasterization into Voxels

## Overview
Fake Voxelization via Triangle-Cube Intersection is a surface-only voxelization technique that digitizes a triangulated mesh by independently testing each triangle against a grid of axis-aligned cubes (voxels) [S1, S3]. Unlike solid voxelization methods that fill the interior volume using Constructive Solid Geometry (CSG), this approach outputs only the voxels intersected by the mesh surface, making it computationally simpler and suitable for generating surface representations [S2, unofficial][S3]. It is distinguished from its siblings by its independence from tessellation depth and its reliance on a template-based intersection test to control topological separability (6- or 26-connectivity) [S1, S3].

## How it works
**Inputs:**
- A triangulated mesh $M$ consisting of vertices $V$ and triangles $T$.
- A 3D domain (grid) defined by an origin $O$ and dimensions $D_x, D_y, D_z$, representing the voxel grid resolution [S1, S3].
- A scale factor $S$ (e.g., 15.0) defining the relationship between mesh coordinates and grid units [S1, S3].
- A separability parameter $K \in \{6, 26\}$ determining the topology of the resulting digital set [S1, S3].

**Outputs:**
- A digital set (voxel grid) containing the coordinates of all voxels intersected by at least one triangle in $M$ [S1, S3].

**Data Structures:**
- **Mesh:** List of triangles, where each triangle is defined by three 3D points $(v_1, v_2, v_3)$.
- **DigitalSet:** A collection of integer grid points $(i, j, k)$ representing occupied voxels.
- **Template:** A geometric shape centered at a grid point, used to define the intersection criteria. The geometry of the template depends on $K$:
    - For $K=6$: The template is a cross-shaped structure (face-connected neighbors).
    - For $K=26$: The template is a cube-shaped structure (edge and corner-connected neighbors).
    *Note: The exact geometric definition of the templates is implementation-specific (e.g., in DGtal) but serves to ensure topological consistency [S1, S3].*

**Algorithm Steps:**
1. **Preprocessing:** If the input mesh contains non-triangular faces, triangulate them using a naive fan approach [S1, S3].
2. **Initialization:** Create an empty digital set for the specified domain [S1, S3].
3. **Iteration:** For each triangle $t$ in the mesh:
    a. Determine the bounding box of the triangle in grid coordinates.
    b. Iterate through all voxels $v$ within this bounding box.
    c. Perform an intersection test between triangle $t$ and the template centered at voxel $v$.
    d. If the intersection is true, add voxel $v$ to the digital set [S1, S3].
4. **Parallelization:** The iteration over triangles can be parallelized using OpenMP or similar frameworks [S1, S3].

**Intersection Test:**
The core operation is determining if a triangle intersects a template centered at a grid point. This is often implemented as a triangle-cube intersection test, potentially refined by the template geometry [S1, S3]. A common optimization is to limit the voxel iteration to the axis-aligned bounding box (AABB) of the triangle [S2, unofficial].

    """
    Voxelize a mesh using fake voxelization via triangle-cube intersection.
    
    Args:
        mesh: List of triangles, each triangle is a list of 3 points (x, y, z).
        domain_origin: Tuple (ox, oy, oz) representing the grid origin.
        domain_size: Tuple (dx, dy, dz) representing the grid dimensions.
        scale_factor: Float scaling mesh coordinates to grid units.
        separability: Integer, either 6 or 26.
        
    Returns:
        A set of voxel coordinates (ix, iy, iz).
    """
    voxels = set()
    
    # Preprocess mesh: ensure all faces are triangles
    # [G] If non-triangular faces exist, triangulate using fan method.
    triangles = preprocess_mesh(mesh)
    
    # Define the template geometry based on separability
    # [G] The template is a shape centered at (0,0,0) in local grid coordinates.
    # For 6-separability, it includes face-adjacent neighbors.
    # For 26-separability, it includes all adjacent neighbors.
    template = create_template(separability)
    
    for triangle in triangles:
        # Calculate bounding box of the triangle in grid coordinates
        min_x, max_x, min_y, max_y, min_z, max_z = get_triangle_grid_bbox(
            triangle, domain_origin, scale_factor
        )
        
        # Iterate over voxels in the bounding box
        for ix in range(int(min_x), int(max_x) + 1):
            for iy in range(int(min_y), int(max_y) + 1):
                for iz in range(int(min_z), int(max_z) + 1):
                    # Check intersection between triangle and template at (ix, iy, iz)
                    if triangle_intersects_template(triangle, template, ix, iy, iz, domain_origin, scale_factor):
                        voxels.add((ix, iy, iz))
                        
    return voxels

def preprocess_mesh(mesh):
    """Convert non-triangular faces to triangles using fan triangulation."""
    triangles = []
    for face in mesh:
        if len(face) == 3:
            triangles.append(face)
        else:
            # Naive fan triangulation
            v0 = face[0]
            for i in range(1, len(face) - 1):
                triangles.append([v0, face[i], face[i+1]])
    return triangles

def get_triangle_grid_bbox(triangle, origin, scale):
    """Compute the grid bounding box of a triangle."""
    # [G] Transform triangle vertices to grid coordinates
    grid_verts = [( (v[0] - origin[0]) / scale, 
                    (v[1] - origin[1]) / scale, 
                    (v[2] - origin[2]) / scale ) for v in triangle]
    
    min_x = min(v[0] for v in grid_verts)
    max_x = max(v[0] for v in grid_verts)
    min_y = min(v[1] for v in grid_verts)
    max_y = max(v[1] for v in grid_verts)
    min_z = min(v[2] for v in grid_verts)
    max_z = max(v[2] for v in grid_verts)
    
    return min_x, max_x, min_y, max_y, min_z, max_z

def triangle_intersects_template(triangle, template, ix, iy, iz, origin, scale):
    """
    Check if the triangle intersects the template centered at (ix, iy, iz).
    This is typically implemented as a triangle-cube intersection test.
    """
    # [G] The template is centered at the voxel center.
    # The voxel center in world coordinates is:
    voxel_center = (
        origin[0] + (ix + 0.5) * scale,
        origin[1] + (iy + 0.5) * scale,
        origin[2] + (iz + 0.5) * scale

    return triangle_intersects_cube(triangle, voxel_center, scale)

**Parameters:**
- **Separability ($K$):** Integer, 6 or 26. Determines the connectivity of the output digital set [S1, S3].
- **Scale Factor:** Float, e.g., 15.0. Defines the voxel size relative to the mesh coordinate system [S1, S3].
- **Domain:** Defined by origin and dimensions. Controls the spatial extent and resolution of the output [S1, S3].

**Edge Cases and Pitfalls:**
- **Non-triangular faces:** If the input mesh has non-triangular faces, they are triangulated using a naive fan approach. If the face is not planar or convex, the digitization may be incorrect [S1, S3].
- **Precision:** Intersection tests use floating-point arithmetic (double) as an approximation of $\mathbb{R}^3$. Digitization may not be exact for meshes with integer or rational vertices [S1, S3].
- **Empty Interior:** The method does not fill the interior of closed surfaces. Only surface voxels are output [S1, S3].

This method determines if a voxel is intersected by a triangle by checking if the voxel's diagonals cross the triangle's plane within the triangle bounds, and handling edge cases where the triangle lies entirely within or touches the voxel faces. It is a specific implementation of [Fake Voxelization via Triangle-Cube Intersection](6951-fake-voxelization-via-triangle-cube-intersection.md) that avoids complex Constructive Solid Geometry (CSG) operations by treating each triangle independently.

## Operating characteristics
- **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of triangles and $M$ is the number of voxels in the bounding box of each triangle. Optimizations can reduce $M$ by limiting the iteration to the triangle's AABB [S2, unofficial].
- **Memory Complexity:** $O(V)$, where $V$ is the number of voxels in the output digital set [S1, S3].
- **Performance:** The method is generally faster than solid voxelization due to the absence of CSG operations [S2, unofficial]. Parallelization is supported via OpenMP [S1, S3].
- **Strengths:** Simple implementation, no CSG required, suitable for surface representation, parallelizable [S2, unofficial][S3].
- **Limitations:** Does not produce solid interiors, precision issues with floating-point arithmetic, incorrect results for non-planar/non-convex faces [S1, S3].
- **When to use:** When only surface voxelization is needed, and computational simplicity is prioritized over topological accuracy of the interior [S2, unofficial][S3].
- **When not to use:** When solid interior filling is required, or when high precision is needed for integer/rational meshes [S1, S3].

## Background
The method is based on the approach described by Laine [S1, S3]. It is implemented in the DGtal library as the `MeshVoxelizer` class, part of the Shapes package [S1, S3]. The method is used for digital geometry processing, specifically for digitizing triangulated structures [S1, S3].
