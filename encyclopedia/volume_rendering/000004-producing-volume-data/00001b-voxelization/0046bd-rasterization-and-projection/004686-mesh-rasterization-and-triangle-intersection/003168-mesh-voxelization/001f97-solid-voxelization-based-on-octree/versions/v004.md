# Solid Voxelization based on Octree

Also called: RFVoxelOctreeBuilder

## Overview
Solid Voxelization based on Octree converts a triangular mesh (specifically OBJ files) into an adaptive octree representation where each leaf node stores its solid/empty status and signed distance to the surface [S1, unofficial]. It differs from fixed-grid voxelization by using recursive spatial subdivision to achieve adaptive resolution, and from sibling octree methods by relying on ray casting with precomputed spherical samples to determine the inside/outside status of empty internal nodes [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangular mesh in OBJ format (vertices and faces), a requested voxelization dimension $D_{req}$, and an optional border size (unused in logic).
*   **Output:** An octree structure (`RFVoxelOctree`) where leaf nodes contain the signed distance to the closest surface point. The octree can be traversed to extract a voxelized mesh representation.

**Data Structures:**
*   `RFVoxelOctree`:
    *   `m_uiOctreeDim`: `uint`, the final power-of-two dimension of the octree.
    *   `m_fVoxelSize`: `double`, the physical size of a leaf voxel.
    *   `m_kOctreeOrigin`: `RFVector3d`, the world-space origin of the octree.
    *   `m_kDataDimension`: `RFVector3i`, dimensions of the voxel grid.
    *   `m_pkRoot`: Pointer to the root `RFVoxelOctreeNode`.
    *   `m_uiNumberOfLeafs`, `m_uiNumberOfEmptyLeafs`, `m_uiNumberOfInternalNodes`: Counters.
*   `RFVoxelOctreeNode`:
    *   `m_kWorldAabb`: `RFAABB3d`, world-space axis-aligned bounding box.
    *   `m_kBuildAabb`: `RFAABB3d` (integer min/max), build-space bounding box.
    *   `m_pkChildren`: Array of 8 pointers to child nodes.
    *   `m_eNodeType`: Enum (`NT_EMPTY_LEAF`, `NT_LEAF`, `NT_INTERNAL`).
    *   `m_fDistanceToSurface`: `double`, signed distance to surface (negative if inside, positive if outside).
*   `RFAABB3d`:
    *   `kMin`: `RFVector3d`, minimum corner.
    *   `kMax`: `RFVector3d`, maximum corner.

**Parameters:**
*   `kOctreeDim`: Requested dimension. Default: 64 [S1, unofficial].
*   `fMinCoverage`: Threshold for classifying an internal empty leaf as solid based on ray coverage. Default: 0.9 in header, 0.8 in implementation call [S1, unofficial].
*   `fBorderSize`: Passed to constructor but not used in logic. Default: 0.0 [S1, unofficial].

**Algorithm Steps:**

1.  **Calculate Octree Dimension:**
    Compute the next power of two for the requested dimension $D_{req}$. If $D_{req} == 0$, result is 2. Otherwise, decrement $D_{req}$, then perform bitwise OR with right shifts of 16, 8, 4, 2, and 1 bits, then increment the result [S1, unofficial].

2.  **Initialize Root Node:**
    *   Compute mesh AABB ($kMin, kMax$).
    *   Find longest axis dimension $fMaxDim = \max(kMax - kMin)$.
    *   Set $m\_uiOctreeDim$ to the calculated power of two.
    *   Set $m\_fVoxelSize = fMaxDim / m\_uiOctreeDim$.
    *   Set $fOctreeWorldSize = m\_uiOctreeDim \times m\_fVoxelSize$.
    *   Set $m\_kOctreeOrigin = \text{MeshAABB.Center} - \text{RFVector3d}(fOctreeWorldSize / 2.0)$.
    *   Create root `RFVoxelOctreeNode`.
    *   Set root `m_kWorldAabb` from $m\_kOctreeOrigin$ to $m\_kOctreeOrigin + \text{RFVector3d}(fOctreeWorldSize)$.
    *   Set root `m_kBuildAabb.kMin` to $(0,0,0)$ and `kMax` to $(m\_uiOctreeDim, m\_uiOctreeDim, m\_uiOctreeDim)$.
    *   Set `m_kDataDimension` to $\text{RFVector3i}(m\_uiOctreeDim)$.
    *   Assign all mesh triangles to the root node.

3.  **Recursive Subdivision and Classification:**
    For a given parent node with a list of triangles:
    *   **Subdivide:** Create 8 children. For each child $(x,y,z)$ where $x,y,z \in \{0,1\}$:
        *   Calculate child build AABB:
            $$kMin_{child} = kMin_{parent} + (iAabbDim \cdot x, iAabbDim \cdot y, iAabbDim \cdot z)$$
            $$kMax_{child} = kMin_{child} + iAabbDim$$
            where $iAabbDim$ is the side length of the parent's build AABB.
        *   Calculate child world AABB using $m\_kOctreeOrigin$ and $m\_fVoxelSize$.
        *   **Assign Triangles:** For each triangle in parent's list, check if `TriangleAabbIntersects(triangle_verts, child_world_aabb)`. If true, add triangle index to child's list.
    *   **Classify Child:**
        *   If child triangle list is empty: Set type to `NT_EMPTY_LEAF`.
        *   If `iAabbDim == 1`: Set type to `NT_LEAF`. Call `UpdateLeafNodeDistanceValue`.
        *   Otherwise: Set type to `NT_INTERNAL`. Recursively call Subdivide on the child.

4.  **Update Leaf Distance Value (for `NT_LEAF`):**
    *   Initialize $fMinDist$ to max double.
    *   For each triangle in the leaf's list:
        *   Compute normal: $kNormal = \text{Cross}(v_2 - v_0, v_1 - v_0)$.
        *   Find closest point on triangle to leaf center: $kClosestPoint = \text{ClosestPointOnTriangle}(verts, leaf\_center)$.
        *   Compute delta: $kDelta = kClosestPoint - leaf\_center$.
        *   Compute sign: $fSign = (\text{Dot}(kDelta, kNormal) < 0.0) ? -1.0 : 1.0$.
        *   Compute distance: $fDist = \text{Length}(kDelta)$.
        *   If $fDist < |fMinDist|$, set $fMinDist = fDist \times fSign$.
    *   Store $fMinDist$ in `m_fDistanceToSurface`.

5.  **Update Internal Empty Leaf Signs (for `NT_INTERNAL` nodes with empty children):**
    *   Recurse to children.
    *   For any child classified as `NT_EMPTY_LEAF`:
        *   Cast rays from node center using precomputed `m_kSampleDirections` (200 directions).
        *   Count hits ($uiCoverage$) and misses ($uiMisses$).
        *   Stop if $uiMisses \ge size/4$ (where $size$ is total samples, i.e., 200).
        *   Calculate coverage: $fCoverage = uiCoverage / size$.
        *   If $fCoverage \ge fMinCoverage$, set `m_fDistanceToSurface` = -1.0 (inside).
        *   Else, set `m_fDistanceToSurface` = 1.0 (outside).

6.  **Generate Sample Directions (Constructor):**
    *   Loop $i$ from 0 to 199.
    *   Compute $kRand = \text{Hammersley2D}(i, 200)$.
    *   Compute direction = $\text{UniformSphericalSampling}(kRand.tX, kRand.tY)$.
    *   Store in `m_kSampleDirections`.

**Formulas:**

*   **Hammersley2D:**
    $$x = i/N$$
    $$y = \text{RadicalInverseVdC}(i)$$
    $\text{RadicalInverseVdC}$ performs bit reversal on $uiBits$: swap 16-bit halves, swap 8-bit halves, swap 4-bit nibbles, swap 2-bit pairs, swap 1-bit pairs, then multiply by $2.3283064365386963e-10$.

*   **UniformSphericalSampling:**
    $$\phi = v \cdot 2\pi$$
    $$\cos\theta = 1 - u$$
    $$\sin\theta = \sqrt{1 - \cos^2\theta}$$
    Result: $(\cos\phi \sin\theta, \sin\phi \sin\theta, \cos\theta)$.

def next_power_of_two(n: int) -> int:
    if n == 0:
        return 2
    n -= 1
    n |= n >> 16
    n |= n >> 8
    n |= n >> 4
    n |= n >> 2
    n |= n >> 1
    return n + 1

def radical_inverse_vdc(n: int, bits: int = 32) -> float:
    # Bit reversal
    n = ((n & 0xFFFF0000) >> 16) | ((n & 0x0000FFFF) << 16)
    n = ((n & 0xFF00FF00) >> 8) | ((n & 0x00FF00FF) << 8)
    n = ((n & 0xF0F0F0F0) >> 4) | ((n & 0x0F0F0F0F) << 4)
    n = ((n & 0xCCCCCCCC) >> 2) | ((n & 0x33333333) << 2)
    n = ((n & 0xAAAAAAAA) >> 1) | ((n & 0x55555555) << 1)
    return n * 2.3283064365386963e-10

def hammersley2d(i: int, N: int) -> tuple:
    x = i / N
    y = radical_inverse_vdc(i)

    return (v1[1]*v2[2] - v1[2]*v2[1], v1[2]*v2[0] - v1[0]*v2[2], v1[0]*v2[1] - v1[1]*v2[0])

## Subtopics

### [Octree-based 3D Voxelization with SAT Pruning](2588-octree-based-3d-voxelization-with-sat-pruning.md)
This method converts arbitrary 3D triangular surface meshes into uniform voxel representations by recursively partitioning space into an octree and using the Separating Axis Theorem (SAT) to prune empty bounding volumes. It builds on [Solid Voxelization based on Octree](2062-solid-voxelization-based-on-octree.md) by replacing ray casting with exact geometric intersection tests for robustness and performance.

### [Robust Inside and Outside Solid Voxelization](3376-robust-inside-and-outside-solid-voxelization.md)
Robust Inside and Outside Solid Voxelization is a method for determining the solid/empty status of octree cells in a voxelized mesh, specifically designed to handle non-watertight meshes with holes and intersecting geometry. Unlike ray casting methods which require watertight meshes, this technique uses a heuristic model based on cube map rendering and visibility propagation to classify cells. It sets itself apart by allowing "seed" cells to propagate their status to visible neighbors, overcoming the topological restrictions of traditional ray casting. It builds on [Solid Voxelization based on Octree](2062-solid-voxelization-based-on-octree.md) by replacing the ray-casting sign test with a GPU-accelerated cube map heuristic.

### [Solid Voxelization via Ray Casting](6829-solid-voxelization-via-ray-casting.md)
A method to convert a triangle mesh into a solid voxel representation (octree) by casting rays through the mesh to determine occupied voxel intervals along the Z-axis. It differs from sibling methods by explicitly computing solid intervals per pixel via ray-mesh intersection rather than relying solely on spatial partitioning pruning or robust topological checks for inside/outside status.

### [Hierarchical Inside/Outside Propagation](9772-hierarchical-inside-outside-propagation.md)
A level-$i$ node without children is inside the solid object if its inside flag is set, and outside otherwise.

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The source provides empirical timing for an Armadillo mesh on Apple M1 Pro: BuildOctree took 483.902ms before optimization and presumably less after (outputOBJ was 133.618ms before, 77.343ms after) [S1, unofficial].
*   **Memory Complexity:** Adaptive, depending on the octree depth and mesh complexity. Uses an octree structure instead of a fixed grid, allowing adaptive resolution and potentially fewer nodes for sparse scenes [S1, unofficial].
*   **Strengths:** Adaptive resolution; fast build time for small dependencies; supports OBJ files [S1, unofficial].
*   **Limitations:** Only supports OBJ files with vertices ordered in triangles [v0,v1,v2]; empty leaf classification uses a stopping heuristic (misses > 25% of samples) which may lead to inaccurate coverage calculation for nodes near the surface [S1, unofficial].
*   **When to use:** When adaptive resolution is needed and input is a clean OBJ mesh.
*   **When not to use:** For non-OBJ formats, non-watertight meshes (may fail ray casting), or when exact geometric intersection is preferred over ray casting heuristics.
