# Coverage Factor Voxelization

Also called: 64x Supersampling Coverage, Coverage Factor Computation, Scalar Voxelization

## Overview
Coverage Factor Voxelization computes a scalar-valued voxelization where each voxel stores the percentage of its volume covered by the input object, rather than a binary occupancy flag [S1, S2]. It is derived from a finer-resolution binary solid voxelization, typically using an octree structure to provide 64× supersampling accuracy for the coverage factors [S1, S2]. This method is distinct from binary voxelization methods like [Interior Voxelize](995-interior-voxelize.md) by providing continuous density-like values directly from the geometric intersection data.

## How it works
**Inputs and Outputs:**
*   **Input:** An octree-based binary solid voxelization. The octree consists of nodes at various levels. Each node has an `inside` flag (boolean) and, if it is a leaf or has children, a set of child nodes or sub-grid voxels [S1, S2].
*   **Output:** A scalar field where each voxel (octree node) stores a coverage factor $C \in [0, 1]$.

**Data Structures:**
The method relies on the octree structure defined in the parent [Volumetric Attribute and Density Formation](6304-volumetric-attribute-and-density-formation.md).
*   **Node:** Contains an `inside` flag and a pointer to children.
*   **Level-0 Node:** Represents a coarse voxel. It has a sub-grid of 64 finer-resolution binary voxels (8x8x8) [S1, S2].
*   **Level-1 Node:** Represents a super-voxel composed of 8 Level-0 nodes.

**Algorithm Steps:**
The coverage factor is computed iteratively from the finest level (Level-0) up to the coarser levels (Level-1, etc.) [S1, S2].

1.  **Compute Level-0 Coverage Factors:**
    For each Level-0 node, calculate the coverage factor $C_0$ as the fraction of set bits (occupied voxels) in its 8x8x8 sub-grid [S1, S2].
    $$ C_0 = \frac{\text{count of occupied voxels in sub-grid}}{64} $$

2.  **Compute Level-1 Coverage Factors:**
    For each Level-1 node, calculate the coverage factor $C_1$ by averaging the coverage factors of its 8 child Level-0 nodes [S1, S2].
    $$ C_1 = \frac{1}{8} \sum_{i=1}^{8} C_{0,i} $$

3.  **Handle Leaf Nodes (No Children):**
    If a node at any level has no children (it is a leaf in the octree representation of the solid), its coverage factor is determined solely by its `inside` flag [S1, S2].
    $$ C = \begin{cases} 1.0 & \text{if } \text{inside} \text{ is true} \\ 0.0 & \text{if } \text{inside} \text{ is false} \end{cases} $$
    *Note: The sources imply that for non-leaf nodes, the averaging process is used, while for leaf nodes, the binary flag is used. In the context of Level-0, the "sub-grid" acts as the children. If a Level-0 node is treated as a leaf in a shallower tree, the flag applies. However, the primary definition for Level-0 uses the sub-grid fraction.*

4.  **Iterate for Remaining Levels:**
    Apply the averaging process iteratively for all remaining levels (Level-2, Level-3, etc.) up to the root [S1, S2]. For a node at level $L$, the coverage factor is the average of the coverage factors of its 8 children at level $L-1$.

**Pseudocode:**
```python
def compute_coverage_factors(octree_root):
    """
    Computes coverage factors for an octree-based solid voxelization.
    Assumes the octree is structured such that Level-0 nodes have 8x8x8 sub-grids,
    and higher-level nodes have 8 children.
    """
    
    # Helper to compute coverage for a Level-0 node
    def compute_level_0_coverage(node):
        # node.sub_grid is an array of 64 binary values (0 or 1)
        occupied_count = sum(node.sub_grid)
        return occupied_count / 64.0

    # Helper to compute coverage for a non-leaf node with children
    def compute_parent_coverage(node):
        if node.children is None:
            # Leaf node: coverage is defined by inside flag
            return 1.0 if node.inside else 0.0
        
        # Non-leaf node: average of children's coverage factors
        child_coverages = [compute_coverage_factors_recursive(child) for child in node.children]
        return sum(child_coverages) / len(child_coverages)

    def compute_coverage_factors_recursive(node):
        # Determine if this node is a Level-0 node or higher
        # Based on sources, Level-0 uses sub-grid, others use children averaging
        if node.is_level_0:
            return compute_level_0_coverage(node)
        else:
            return compute_parent_coverage(node)

    # Start from the root
    return compute_coverage_factors_recursive(octree_root)
```

**Parameters:**
*   **Supersampling Factor:** The method offers 64× supersampling for coverage factors, derived from the 8x8x8 sub-grid at Level-0 [S1, S2].

**Edge Cases and Pitfalls:**
*   **Precision:** The coverage factor is a floating-point value. Precision issues may arise if the number of occupied voxels is very small relative to the sub-grid size, but 64 is small enough to maintain exact fractional representation in standard float types.
*   **Boundary Conditions:** The `inside` flag must be correctly set during the initial binary voxelization step. If the flag is incorrect, leaf node coverage will be wrong.
*   **Empty Octrees:** If the octree is empty, all coverage factors are 0.0.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels in the octree. The computation involves a single pass from leaves to root, with constant work per node (summing 8 children or 64 sub-grid bits).
*   **Memory Complexity:** Requires storing the octree structure and the coverage factors. The coverage factors are typically stored as floats, doubling the memory requirement compared to binary flags if stored alongside them.
*   **Performance:** The method is efficient on GPUs due to the parallelizable nature of the sub-grid counting and averaging operations. The 64× supersampling provides high accuracy without requiring a full fine-resolution grid.
*   **Strengths:** Provides accurate scalar values for rendering (e.g., for volume rendering with smooth transitions). Simple to implement on top of an existing binary voxelization.
*   **Limitations:** Requires an initial binary voxelization step. Not suitable for non-scalar attributes (e.g., normals, colors) without extension.
*   **When to Use:** When smooth density or coverage information is needed for volume rendering or other scalar-based applications.
*   **When Not to Use:** When binary occupancy is sufficient, or when surface normals/shells are required.

## Background
The method was introduced in the paper "Fast parallel surface and solid voxelization on GPUs" by Michael Schwarz et al. (SIGGRAPH Asia 2010) [S1, S2]. It is part of a broader family of voxelization techniques designed for efficient GPU-based processing of geometric data. The 64× supersampling feature allows for high-quality scalar voxelization without the memory overhead of a full fine-resolution grid.
