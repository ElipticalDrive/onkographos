# Voxel File I/O (binvox/rawvox)
Also called: Binvox File Writing, Sparse Voxel Grid Export, Text-based Voxel Output, WriteBinvox

## Overview
Exports voxelized geometry data to standard file formats for interchange with other graphics applications [S1, unofficial]. It implements two primary output modes: the `binvox` format, which uses a compact binary run-length encoding for occupancy data, and the `rawvox` format, which provides a simple binary dump of grid dimensions and metadata [S1, unofficial]. Unlike its sibling [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md) which focuses on the internal compression algorithm, this method handles the specific file headers, coordinate transformations, and I/O protocols required by external tools [S1, unofficial].

## How it works
The method supports two distinct output formats: `binvox` (binary, sparse) and `rawvox` (binary, dense metadata) [S1, unofficial]. Both require a source voxel grid with defined dimensions, bounding box, and unit size [S1, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `size_x_`, `size_y_`, `size_z_`: Integer grid dimensions [S1, unofficial].
    *   `lb_`: Lower bound coordinates of the bounding box (Vec3f) [S1, unofficial].
    *   `unit_`: Voxel unit sizes (Vec3f) [S1, unofficial].
    *   `bound_`: Bounding box object providing a `norm()` method for normalization [S1, unofficial].
    *   `Filled(x, y, z)`: Boolean function returning true if the voxel at integer coordinates $(x, y, z)$ is occupied [S1, unofficial].
    *   `OutFilePath()`: Path string for the output file [S1, unofficial].
*   **Outputs**:
    *   A binary file containing either `binvox` or `rawvox` data [S1, unofficial].

### Data Structures
*   **Binvox Header**: Text-based ASCII lines defining format version, dimensions, translation, and scale [S1, unofficial].
*   **Binvox Data**: Binary stream of pairs `(value, count)` [S1, unofficial].
    *   `value`: 1 byte (unsigned char), 1 if occupied, 0 if empty [S1, unofficial].
    *   `count`: 1 byte (unsigned char), number of consecutive voxels with the same `value` [S1, unofficial].
*   **Rawvox Header**: Binary stream of floats [S1, unofficial].
    *   First 3 floats: `size_x_`, `size_y_`, `size_z_` [S1, unofficial].
    *   Next 3 floats: `lb_[0]`, `lb_[1]`, `lb_[2]` [S1, unofficial].
    *   Next 3 floats: `unit_[0]`, `unit_[1]`, `unit_[2]` [S1, unofficial].

### Steps: Binvox Format
The `binvox` format stores data in row-major order (X, then Y, then Z) with normalization [S1, unofficial].

1.  **Calculate Normalization Parameters**:
    *   Calculate `norm_translate` from `lb_` [S1, unofficial].
    *   Calculate `norm_scale` from `bound_.norm()` [S1, unofficial].
2.  **Write Header**:
    *   Open file in binary mode [S1, unofficial].
    *   Write line 1: `#binvox 1\n` [S1, unofficial].
    *   Write line 2: `dim {bx} {by} {bz}\n` where $bx=size\_x_, by=size\_y_, bz=size\_z_$ [S1, unofficial].
    *   Write line 3: `translate {-norm\_translate[0]} {-norm\_translate[2]} {-norm\_translate[1]}\n` [S1, unofficial].
    *   Write line 4: `scale {norm\_scale}\n` [S1, unofficial].
    *   Write line 5: `data\n` [S1, unofficial].
3.  **Encode Data**:
    *   Initialize $x = lx, y = ly, z = lz$ (grid bounds) [S1, unofficial].
    *   Initialize `total_ones = 0`, `bytes_written = 0` [S1, unofficial].
    *   Loop while $x \le ux$:
        *   Get `value = Filled(x, y, z)` [S1, unofficial].
        *   Initialize `count = 0` [S1, unofficial].
        *   Inner Loop: While $x \le ux$ AND `count < 255` AND `value == Filled(x, y, z)`:
            *   Increment $z$ [S1, unofficial].
            *   If $z > uz$:
                *   Reset $z = lz$ [S1, unofficial].
                *   Increment $y$ [S1, unofficial].
                *   If $y > uy$:
                    *   Reset $y = ly$ [S1, unofficial].
                    *   Increment $x$ [S1, unofficial].
            *   Increment `count` [S1, unofficial].
        *   If `value` is true, `total_ones += count` [S1, unofficial].
        *   Write `value` (1 byte) and `count` (1 byte) to file [S1, unofficial].
        *   `bytes_written += 2` [S1, unofficial].
4.  **Close File** [S1, unofficial].

### Steps: Rawvox Format
The `rawvox` format is a simpler binary dump of metadata [S1, unofficial].

1.  **Open File**: Open output file in binary mode [S1, unofficial].
2.  **Write Header**:
    *   Write `size_x_` [S1, unofficial].
    *   Write `size_y_` [S1, unofficial].
    *   Write `size_z_` [S1, unofficial].
    *   Write `lb_[0]`, `lb_[1]`, `lb_[2]` (cast to double/float) [S1, unofficial].
    *   Write `unit_[0]`, `unit_[1]`, `unit_[2]` (cast to double/float) [S1, unofficial].
3.  **Close File** [S1, unofficial].

### Steps: Voxel Metadata File Output
A companion text-based format often used with rawvox [S1, unofficial].

1.  **Derive Path**: Strip `.rawvox` or `.binvox` extension from base output path and append `.meta` [S1, unofficial].
2.  **Open File**: Open output file in binary mode [S1, unofficial].
3.  **Write Header**:
    *   Write `#voxmeta 1\n` [S1, unofficial].
    *   Write `size_x_ size_y_ size_z_\n` [S1, unofficial].
4.  **Write Voxel Data**:
    *   Iterate `voxel_index` from $0$ to $\text{TotalVoxelSize()} - 1$ [S1, unofficial].
    *   Write `voxel_index` and `flags` separated by space, followed by newline [S1, unofficial].
5.  **Close File** [S1, unofficial].

### Pseudocode: Binvox Writer

```python
def write_binvox(out_path, size_x, size_y, size_z, lb, bound, filled_func):
    """
    Writes a voxel grid to the binvox format.
    lb: tuple (lb_x, lb_y, lb_z)
    bound: object with norm() method returning a scalar for normalization
    filled_func: callable(x, y, z) -> bool
    """
    # 1. Calculate normalization parameters per S1
    norm_translate = lb
    norm_scale = bound.norm()
    
    # 2. Write Header
    with open(out_path, 'wb') as f:
        f.write(b'#binvox 1\n')
        f.write(f'dim {size_x} {size_y} {size_z}\n'.encode('ascii'))
        # Y and Z components of translation are swapped in the header per S1
        f.write(f'translate {-norm_translate[0]} {-norm_translate[2]} {-norm_translate[1]}\n'.encode('ascii'))
        f.write(f'scale {norm_scale}\n'.encode('ascii'))
        f.write(b'data\n')
        
        # 3. Encode Data
        lx, ly, lz = 0, 0, 0
        ux, uy, uz = size_x - 1, size_y - 1, size_z - 1
        
        x, y, z = lx, ly, lz
        while x <= ux:
            value = 1 if filled_func(x, y, z) else 0
            count = 0
            
            # Inner loop: run-length encode consecutive voxels with same value
            while x <= ux and count < 255 and (1 if filled_func(x, y, z) else 0) == value:
                z += 1
                if z > uz:
                    z = lz
                    y += 1
                    if y > uy:
                        y = ly
                        x += 1
                count += 1
            
            # Write value and count as unsigned chars
            f.write(bytes([value, count]))
            
    return

def write_rawvox(out_path, size_x, size_y, size_z, lb, unit):
    """
    Writes voxel grid metadata to rawvox format.
    """
    with open(out_path, 'wb') as f:
        # Write dimensions as floats
        f.write(float(size_x).to_bytes(4, 'little') + float(size_y).to_bytes(4, 'little') + float(size_z).to_bytes(4, 'little'))
        # Write lower bound
        f.write(float(lb[0]).to_bytes(4, 'little') + float(lb[1]).to_bytes(4, 'little') + float(lb[2]).to_bytes(4, 'little'))
        # Write unit size
        f.write(float(unit[0]).to_bytes(4, 'little') + float(unit[1]).to_bytes(4, 'little') + float(unit[2]).to_bytes(4, 'little'))
```

## Subtopics

### [MagicaVoxel File Output](1752-magicavoxel-file-output.md)
Exports voxel particles to the MagicaVoxel `.vox` binary format, handling grid sizing and chunk structure. It differs from generic voxel I/O by enforcing the specific chunk-based binary layout and resolution limits required by the MagicaVoxel application. Choose it when targeting MagicaVoxel workflows.

### [MagicaVoxel File Parsing](2405-magicavoxel-file-parsing.md)
A loader for MagicaVoxel `.vox` files (versions 150 and 200) that parses models, palette, MATL materials, and the nTRN/nGRP/nSHP scene graph, converting visible faces into quads within a BVH. It structures data into chunks containing tags, sizes, and child chunks. Unlike raw voxel grids, this method extracts surface geometry (quads) for ray tracing while supporting complex scene hierarchies and coordinate transformations. Choose it when importing MagicaVoxel assets for rendering.

### [PLY File Parsing](2781-ply-file-parsing.md)
PLY File Parsing extracts vertex attributes and topology from Polygon File Format (PLY) files, serving as the bridge between raw file storage and in-memory voxel or mesh data structures. It solves the problem of heterogeneous PLY headers (ASCII vs. binary, varying property types) by normalizing the input into a consistent vertex buffer and face index array. Unlike [Voxel File I/O (binvox/rawvox)](1698-voxel-file-i-o-binvox-rawvox.md) which handles volumetric grids, this method processes surface representations; it differs from [MagicaVoxel File Parsing](2405-magicavoxel-file-parsing.md) by supporting arbitrary vertex properties and standard triangle/quad topology rather than a proprietary voxel color format. Choose it when converting mesh assets to voxelization pipelines.

### [Voxel File I/O](2786-voxel-file-i-o.md)
Voxel File I/O is the method for serializing and deserializing voxel grid data to and from disk storage formats. It solves the problem of persisting volumetric representations generated by voxelization or optimization pipelines for later use in rendering engines or analysis tools. Unlike [Voxel File I/O (binvox/rawvox)](1698-voxel-file-i-o-binvox-rawvox.md), which focuses on specific legacy binary and raw byte formats, this method encompasses a broader range of structured formats including ASCII-based scientific formats (VTK, PLY, CSV), specialized scientific image formats (PFM, NRRD-like), and custom binary schemas. Choose it when requiring cross-platform scientific data exchange.

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of voxels in the bounding box, as every voxel must be checked for occupancy [S1, unofficial]. The binvox encoding step is also linear in the number of runs [S1, unofficial].
*   **Memory Complexity**: $O(1)$ auxiliary memory for the writer, as it streams data [S1, unofficial]. The input grid must be stored in memory [S1, unofficial].
*   **Performance**: Binvox is significantly smaller in file size for sparse grids due to RLE [S1, unofficial]. Rawvox is fast to write but produces larger files if metadata is dense [S1, unofficial].
*   **Strengths**: Standardized formats for interchange [S1, unofficial]. Binvox is widely supported by 3D modeling tools [S1, unofficial].
*   **Limitations**: Binvox is binary and opaque without a parser [S1, unofficial]. Rawvox lacks color/texture data in the basic header [S1, unofficial]. Coordinate normalization in binvox can introduce precision issues if not handled carefully [S1, unofficial].

## Background
The `binvox` format was developed as a compact binary format for storing 3D voxel data, particularly for use in computer graphics and 3D modeling [S1, unofficial]. It is widely used in datasets like ShapeNet and by tools like MagicaVoxel [S1, unofficial]. The `rawvox` format is a simpler, less standardized binary format often used in research voxelizers for quick debugging or intermediate storage [S1, unofficial]. The implementation described here originates from the `topskychen/voxelizer` project, which provides a C++ voxelization pipeline [S1, unofficial].
