# Voxelization Optimization


## Overview
Voxelization Optimization encompasses techniques to reduce the computational and memory costs of converting geometric primitives into voxel grids, addressing the bottleneck of high draw call counts and redundant vertex transformations [S1, unofficial][S2, unofficial]. It distinguishes itself from general grid construction by focusing on pipeline efficiency (stream output, instancing) and data structure pruning (heightmaps, LOD) rather than just the final storage format [S1, unofficial][S3, unofficial].

## How it works
**Inputs:**
*   Geometric primitives (meshes, obstacles).
*   Voxel grid parameters (resolution, chunk size).
*   Camera/view state (for rendering order optimization).

**Outputs:**
*   Optimized voxel data structures (3D textures, sparse lists, or heightmaps).
*   Reduced number of draw calls and vertex computations.

**Data Structures:**
*   **Stream Output Buffer:** A GPU buffer storing transformed vertex positions and velocities, indexed by instance ID [S1, unofficial].
*   **Min/Max Altitude Heightmaps:** Two byte arrays, `minAltitude` and `maxAltitude`, of size $N_x \times N_z$ (e.g., $32 \times 32 = 1024$ bytes for a chunk), storing the lowest and highest occupied Y indices per XZ column [S3, unofficial].
*   **Instance ID:** Used to specify the target slice in instanced rendering [S1, unofficial].

**Steps:**

1.  **Preprocessing Geometry:**
    *   For static obstacles, precompute voxelization if the transformation is analytic (e.g., rigid translation/rotation) and apply the inverse transformation during access [S1, unofficial].
    *   For dynamic obstacles, use a low-level-of-detail (LOD) mesh to approximate the geometry, reducing the vertex count processed per frame [S1, unofficial].

2.  **Stream Output Caching (Deforming Meshes):**
    *   When voxelizing deforming meshes (e.g., skinned characters), use GPU stream output to cache the entire buffer of transformed vertices [S1, unofficial].
    *   This avoids recomputing skinning transformations for each voxel slice [S1, unofficial].

3.  **Instanced Rendering:**
    *   Draw all voxel slices in a single draw call using instancing [S1, unofficial].
    *   Use the instance ID to specify the target slice (Z-coordinate or depth layer) [S1, unofficial].

4.  **Heightmap Maintenance (Dynamic Voxel Updates):**
    *   Initialize `minAltitude` array to `Constants.ChunkSize` (e.g., 32) for all columns, indicating initially empty columns [S3, unofficial].
    *   Initialize `maxAltitude` array to -1 or 0 (depending on convention) for all columns [S3, unofficial].
    *   On voxel addition at index $(i, j, k)$ where $k > 0$:
        *   Update `minAltitude[i][j]` if $k < minAltitude[i][j]$.
        *   Update `maxAltitude[i][j]` if $k > maxAltitude[i][j]$.
    *   On voxel removal at index $(i, j, k)$ where $k == 0$:
        *   Recalculate `minAltitude[i][j]` by scanning the column for the new lowest occupied voxel.
        *   Recalculate `maxAltitude[i][j]` by scanning the column for the new highest occupied voxel.
    *   *Note:* The sources describe the update logic but do not provide the full scanning algorithm for removal [S3, unofficial].

5.  **Rendering Order Optimization:**
    *   Determine chunk rendering order based on camera pitch and yaw to achieve front-to-back rendering [S3, unofficial].
    *   Calculate start/end indices and steps for X and Z axes based on view direction [S3, unofficial].
    *   Pre-calculate access strides to avoid excessive multiplications in the inner loop [S3, unofficial].

**Parameters:**
*   **Chunk Size:** Typically 32 voxels per dimension (e.g., $32^3$) [S3, unofficial].
*   **LOD Level:** Low detail mesh for obstacles [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Dynamic Lights:** Dynamic lights intersecting static objects may force re-voxelization of those static objects, complicating the "static vs. dynamic" optimization strategy [S2, unofficial].
*   **Precision:** Stream output caching requires careful management of vertex buffer sizes to avoid overflow for large deforming meshes [S1, unofficial].
*   **Heightmap Consistency:** Removing voxels requires a full column scan to update heightmaps, which can be costly if done frequently [S3, unofficial].

**Pseudocode:**

```python
# Pseudocode for Stream Output and Instanced Voxelization
def voxelize_deforming_mesh(mesh, grid_resolution, stream_output_buffer):
    """
    Voxelizes a deforming mesh using stream output caching and instancing.
    """
    # Step 1: Transform vertices once using stream output
    # This caches transformed vertices, avoiding per-slice skinning
    transformed_vertices = stream_output_cache(mesh.vertices, mesh.skin_weights)
    
    # Step 2: Instanced draw call for all slices
    # Instance ID specifies the target slice (e.g., Z layer)
    for slice_id in range(grid_resolution.z):
        draw_instanced(
            geometry_shader=voxel_geometry_shader,
            vertex_buffer=transformed_vertices,
            instance_count=1,
            instance_id=slice_id,
            slice_z=slice_id
        )

# Pseudocode for Heightmap Maintenance
class HeightmapOptimizer:
    def __init__(self, chunk_size_x, chunk_size_z):
        self.chunk_size = 32 # Example constant
        self.min_altitude = [self.chunk_size] * (chunk_size_x * chunk_size_z)
        self.max_altitude = [-1] * (chunk_size_x * chunk_size_z)

    def on_voxel_added(self, x, y, z):
        """Update heightmaps when a voxel is added."""
        idx = x * self.chunk_size + z
        if y < self.min_altitude[idx]:
            self.min_altitude[idx] = y
        if y > self.max_altitude[idx]:
            self.max_altitude[idx] = y

    def on_voxel_removed(self, x, y, z):
        """Update heightmaps when a voxel is removed.
        Requires scanning the column to find new bounds."""
        idx = x * self.chunk_size + z
        # [G] Implementation detail: Scan column z from y+1 to max to find new min
        # and from y-1 down to 0 to find new max.
        # This is computationally expensive if done frequently.
        new_min = self.chunk_size
        new_max = -1
        for k in range(self.chunk_size):
            if is_voxel_occupied(x, k, z):
                if k < new_min:
                    new_min = k
                if k > new_max:
                    new_max = k
        self.min_altitude[idx] = new_min
        self.max_altitude[idx] = new_max
```

## Subtopics

### [32nd Bit Avoidance Modification](3351-32nd-bit-avoidance-modification.md)
The 32nd Bit Avoidance Modification adjusts the solid voxelization and density computation pipelines to exclude the highest bit of 32-bit storage formats, which is reserved for other purposes. It restricts voxel and density data to the lower bits, distinguishing it from general sparse voxelization by targeting bit-packing constraints in dense grids.

### [Sparse Voxelization with Oracle and Parallel Scan](3687-sparse-voxelization-with-oracle-and-parallel-scan.md)
Sparse Voxelization with Oracle and Parallel Scan is a real-time, high-resolution technique for reconstructing 3D surface models from image-based inputs (calibrated RGB camera streams) using a coarse-to-fine voxel hierarchy. It solves the problem of on-the-fly surface reconstruction by iteratively refining a sparse list of voxels, using an oracle kernel to cull empty space and a parallel prefix sum scan to compact the list, ensuring that only relevant voxels are subdivided. Unlike bottom-up approaches or methods designed for static models, this method is top-down and optimized for interactive rates (e.g., >30 fps at $1024^3$ resolution) by leveraging GPU parallelism for both computation and rendering.

### [Greedy Voxel Mesh Optimization](3979-greedy-voxel-mesh-optimization.md)
Greedy Voxel Mesh Optimization is a greedy algorithm that optimizes voxel mesh generation for 2D tile grids (e.g., Minecraft-like games) by merging adjacent identical tiles into larger rectangular quads to reduce draw calls. It differs from its siblings, [32nd Bit Avoidance Modification](3351-32nd-bit-avoidance-modification.md) and [Sparse Voxelization with Oracle and Parallel Scan](3687-sparse-voxelization-with-oracle-and-parallel-scan.md), by explicitly constructing maximal rectangular regions of uniform tile properties through iterative expansion, rather than relying on bit-packing tricks or parallel scan-based sparse structures.

### Stream Output for Voxelization
A technique to optimize voxelization of deforming meshes by caching transformed vertices, avoiding recomputation for each slice [S1, unofficial]. It uses stream output to cache an entire buffer of transformed vertices during the voxelization of deforming meshes (e.g., skinned characters) [S1, unofficial].

### Min/Max Altitude Heightmap Optimization
Stores per-column minimum and maximum occupied voxel heights to skip empty or fully occupied columns during meshing [S3, unofficial]. On voxel addition (index > 0), `OnVoxelAdded(i, j, k)` updates the heightmaps to reflect the new occupied column. On voxel removal (index == 0), `OnVoxelRemoved(i, j, k)` updates the heightmaps to reflect the cleared column. It initializes `minAltitude` array to `Constants.ChunkSize` (32) for all columns, indicating initially empty columns. Parameters include `minAltitude` (byte array of size `ChunkSizeSquared` (1024 bytes), stores the lowest occupied Y index per XZ column) and `maxAltitude` (byte array of size `ChunkSizeSquared` (1024 bytes), stores the highest occupied Y index per XZ column) [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Stream output reduces vertex transformation cost from $O(N \cdot S)$ to $O(N)$ per frame, where $N$ is vertices and $S$ is slices [S1, unofficial]. Heightmap updates are $O(1)$ for additions but $O(H)$ for removals, where $H$ is chunk height [S3, unofficial].
*   **Memory Complexity:** Stream output buffers require memory proportional to the number of vertices [S1, unofficial]. Heightmaps add $O(N_x \cdot N_z)$ memory per chunk [S3, unofficial].
*   **Measured Performance:** Techniques are used in games like *Rise of Tomb Raider* (voxel AO) and *The Tomorrow Children* (on consoles) [S2, unofficial].
*   **Strengths:** Significant reduction in draw calls and vertex processing for dynamic scenes [S1, unofficial]. Efficient culling for meshing via heightmaps [S3, unofficial].
*   **Limitations:** Complex to implement stream output caching [S1, unofficial]. Heightmap updates can be costly for frequent voxel removals [S3, unofficial]. Dynamic lights complicate static object optimization [S2, unofficial].
*   **When to Use:** Real-time fluid simulation, dynamic character voxelization, and meshing of large voxel chunks [S1, unofficial][S3, unofficial].
*   **When Not to Use:** Static scenes with no dynamic lights or simple transformations, where precomputation is sufficient [S1, unofficial].

## Background
Voxelization optimization techniques have been developed for real-time simulation and rendering of 3D fluids and global illumination [S1, unofficial][S2, unofficial]. The use of stream output for voxelization was highlighted in GPU Gems 3 [S1, unofficial]. Heightmap-based optimizations are used in voxel meshing engines like vercidium-patreon/meshing [S3, unofficial]. The techniques are applied in commercial games such as *Rise of Tomb Raider* and *The Tomorrow Children* [S2, unofficial].
