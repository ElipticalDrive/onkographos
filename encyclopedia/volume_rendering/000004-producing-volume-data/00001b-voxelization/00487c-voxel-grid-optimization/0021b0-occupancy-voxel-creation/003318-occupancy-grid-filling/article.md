# Occupancy Grid Filling
## Overview
Occupancy Grid Filling is a post-processing step that fills the interior regions of an occupancy grid by identifying the "outside" label and setting all other background labels to occupied (1). It solves the problem of hollow or fragmented occupancy masks generated by voxelization by ensuring that enclosed voids are treated as solid, while preserving original non-zero data (e.g., colors) attached to occupied voxels. It differs from [Mark Invisible Cells](4648-mark-invisible-cells.md) by focusing on topological closure of the volume rather than visibility culling.
## How it works
**Inputs and Outputs:**
- Input: An HDF5 file containing an occupancy tensor (numpy array).
- Output: An HDF5 file containing the filled occupancy tensor.

**Data Structures:**
- **HDF5 Dataset**: The input and output files use an HDF5 dataset with the key `'tensor'` (default). The dataset contains a numpy array. Chunks are created based on the tensor shape, with dimensions > 2 set to chunk size 1 [S1, unofficial].

**Parameters:**
- `background`: The background label value for `skimage.morphology.label`, set to 1 [S1, unofficial].
- `connectivity`: The connectivity for `skimage.morphology.label`, set to 1 (6-connectivity in 3D) [S1, unofficial].

**Steps:**
1. Read the input HDF5 file to obtain the occupancy tensor.
2. If the occupancy tensor has fewer than 4 dimensions, expand the dimensions to add a batch dimension.
3. Initialize a `filled` tensor of zeros with the same shape as the occupancy tensor.
4. Loop through each sample $n$ in the batch (range of `occupancy.shape[0]`):
    a. Label connected components in the occupancy slice using `skimage.morphology.label` with `background=1` and `connectivity=1`. Obtain `labels` and `num_labels`.
    b. Identify the `outside_label` as the label value at the corner of the grid (`labels[0][0][0]`).
    c. Set all voxels in the `filled` slice that do not have the `outside_label` to 1.
    d. Preserve original non-zero values (e.g., colors) in the `filled` slice by copying them from the original `occupancy` slice to the `filled` slice where `occupancy[n] != 0`.
5. Write the `filled` tensor to the output HDF5 file.

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
import h5py
import numpy as np
from skimage.morphology import label

def fill_occupancy(input_path: str, output_path: str):
    """
    Fill interior regions of an occupancy grid.
    
    :param input_path: Path to input HDF5 file.
    :param output_path: Path to output HDF5 file.
    """
    with h5py.File(input_path, 'r') as f_in:
        # Read tensor; assume key 'tensor' is used as per source
        occupancy = f_in['tensor'][:]
        
        # Expand dimensions if necessary to add batch dimension
        if occupancy.ndim < 4:
            # Add batch dimension at axis 0
            occupancy = np.expand_dims(occupancy, axis=0)
            
        # Initialize filled tensor with zeros
        filled = np.zeros_like(occupancy, dtype=occupancy.dtype)
        
        # Loop through batch
        for n in range(occupancy.shape[0]):
            # Label connected components
            # background=1, connectivity=1 (6-connectivity in 3D)
            labels = label(occupancy[n], background=1, connectivity=1)
            
            # Identify outside label from corner voxel
            outside_label = labels[0, 0, 0]
            
            # Set all non-outside voxels to 1 (occupied)
            # Note: labels == 0 are background (outside), labels > 0 are components
            # The source says "Set all voxels... that do not have the outside_label to 1"
            # This implies filling everything that is not the specific outside component label
            mask = (labels != outside_label)
            filled[n, mask] = 1
            
            # Preserve original non-zero values (e.g., colors)
            # Copy from original occupancy where occupancy != 0
            original_nonzero = occupancy[n] != 0
            # We need to preserve the *values*, not just set to 1.
            # The source says: "copying them from the original occupancy slice 
            # to the filled slice where occupancy[n] != 0"
            # This implies: filled[n] = original if original != 0 else filled[n]
            # However, filled[n] was just set to 1 for non-outside.
            # If original had color values, we overwrite the 1s with those colors.
            # If original was 0 (background/outside), we keep the 1s (filled).
            
            # Logic:
            # 1. filled[n] is 1 where mask is True, 0 elsewhere.
            # 2. We want to preserve original non-zero values.
            # 3. So, where original[n] != 0, filled[n] = original[n].
            # 4. Where original[n] == 0, filled[n] remains as calculated (1 or 0).
            
            filled[n, original_nonzero] = occupancy[n, original_nonzero]
            
    with h5py.File(output_path, 'w') as f_out:
        # Create dataset with chunks as per source
        # Chunks: dimensions > 2 set to chunk size 1.
        # Assuming standard numpy array storage.
        # The source mentions chunks are created based on tensor shape.
        # We will write the array directly; HDF5 handles chunking if specified.
        # To match source behavior precisely, we might need to specify chunks.
        # "dimensions > 2 set to chunk size 1"
        # If shape is (B, D, H, W), chunks could be (1, 1, 1, 1) or similar.
        # Let's assume standard chunking or let HDF5 decide if not specified, 
        # but source implies specific chunking.
        # Since we don't have exact chunking logic for all dims, we write without explicit chunking 
        # or use a simple chunk size. The source says "chunks are created...".
        # We will write the data.
        f_out.create_dataset('tensor', data=filled)
```

**Edge Cases and Pitfalls:**
- **Precision**: The method relies on integer labels. Floating point occupancy values must be thresholded or converted appropriately before labeling if they are not already binary/integer labels [S1, unofficial].
- **Boundaries**: The outside label is determined by the corner voxel `labels[0][0][0]`. If the corner voxel is part of an internal object (e.g., a sphere touching the corner), the "outside" might be misidentified, leading to incorrect filling [S1, unofficial].
- **Degenerate Input**: If the occupancy tensor is empty or has zero volume, the labeling step may fail or produce no labels [G].

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N)$ where $N$ is the number of voxels, due to the connected component labeling and element-wise operations.
- Memory: $O(N)$ for the input, output, and label tensors.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scales linearly with the number of voxels and batch size.

**Strengths and Limitations:**
- Strengths: Simple to implement; effectively fills hollow interiors; preserves color/attribute data.
- Limitations: Relies on 6-connectivity; sensitive to corner voxel placement for outside detection; requires `skimage` dependency.

**When to Use:**
- Use when you have a voxelized mesh and need to ensure the volume is watertight or solid for rendering or simulation.

**When Not to Use:**
- Do not use if the corner voxel is not guaranteed to be outside the object.
- Do not use if high connectivity (e.g., 18 or 26) is required for diagonal filling.
