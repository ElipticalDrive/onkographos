# Sort-last Grid Construction
Also called: General Grid Building Algorithm, IWRP06 algorithm, Sort-last building algorithm

## Overview
Sort-last Grid Construction is a voxelization method that assigns geometric primitives to grid cells by iterating over primitives and determining which cells they intersect [S1][S2, unofficial]. It solves the problem of building an acceleration structure for ray tracing by creating a uniform grid where objects are stored in all cells they overlap [S1]. It is distinguished from its sibling, Sort-first Grid Construction, by its iteration order: sort-last processes primitives to find cells, whereas sort-first processes cells to find primitives [S1][S2, unofficial].

## How it works
**Inputs:**
*   A scene containing $N$ geometric primitives.
*   A subdivision factor $m$, determining the grid resolution.

**Outputs:**
*   A uniform grid partitioned into $m^3$ cells.
*   Each cell contains a list of primitives that intersect it.

**Data Structures:**
*   **Grid:** A 3D array of size $m \times m \times m$. Each cell holds a dynamic list (e.g., linked list or vector) of primitive indices or pointers.
*   **Primitive Bounding Box (AABB):** For each primitive $p$, an axis-aligned bounding box defined by `box.min` and `box.max` coordinates in the grid's coordinate space.

**Parameters:**
*   $m$: The number of divisions along each axis. The total number of cells is $m^3$. The value is typically determined by a function `determinatem()` based on scene statistics (e.g., average objects per cell) [S1].

**Algorithm Steps:**
1.  Determine the grid resolution $m$ using `determinatem()` [S1].
2.  Initialize the grid as $m^3$ empty cells [S1].
3.  For each primitive $p$ in the scene:
    a.  Compute the AABB of $p$ [S1].
    b.  Identify the range of grid cells intersected by this AABB. This is calculated from `box.min` to `box.max` [S1].
    c.  Insert $p$ into the lists of all identified cells [S1].

**Pseudocode:**
```python
def sort_last_grid_construction(primitives, determinatem):
    # Step 1: Determine resolution
    m = determinatem(primitives)
    
    # Step 2: Initialize grid
    # Grid is a 3D array of lists, dimensions m x m x m
    grid = [[[] for _ in range(m)] for _ in range(m)]
    
    # Step 3: Iterate over primitives
    for p in primitives:
        # Get bounding box of primitive p
        # Returns coordinates in grid space [0, m]
        box_min = p.get_bounding_box_min()
        box_max = p.get_bounding_box_max()
        
        # Determine cell indices covered by the box
        # Clamp to grid boundaries [0, m-1]
        min_x = int(box_min.x)
        max_x = int(box_max.x)
        min_y = int(box_min.y)
        max_y = int(box_max.y)
        min_z = int(box_min.z)
        max_z = int(box_max.z)
        
        # Clamp indices to valid grid range
        min_x = max(0, min(min_x, m - 1))
        max_x = max(0, min(max_x, m - 1))
        min_y = max(0, min(min_y, m - 1))
        max_y = max(0, min(max_y, m - 1))
        min_z = max(0, min(min_z, m - 1))
        max_z = max(0, min(max_z, m - 1))
        
        # Insert primitive into all intersected cells
        for x in range(min_x, max_x + 1):
            for y in range(min_y, max_y + 1):
                for z in range(min_z, max_z + 1):
                    grid[x][y][z].append(p)
                    
    return grid
```

**Edge Cases and Pitfalls:**
*   **Imprecise Tests:** The algorithm may use an AABB test for speed, which is faster but imprecise compared to an exact intersection test [S1]. This can lead to primitives being inserted into cells they do not strictly intersect, increasing the number of ray-primitive intersection tests during traversal [S1].
*   **Ray Coherence:** Although the packet may traverse cells that some rays do not intersect, increasing overhead, ray coherence in practice compensates for this [S1].
*   **Dynamic Scenes:** The algorithm is easy to parallelize, making it suitable for dynamic scenes [S1].

## Operating characteristics
*   **Time Complexity:** Linear time complexity $O(N)$, assuming each primitive covers a constant number of grid cells and `determinatem()` is $O(N)$ [S1].
*   **Memory Complexity:** Proportional to $m^3$ for the grid structure plus the storage for primitive references in cells.
*   **Strengths:** Simple to implement, easy to parallelize, and efficient for interactive real-time environments when using AABB tests [S1].
*   **Limitations:** Potential for over-insertion of primitives due to AABB approximation, leading to redundant intersection tests [S1].
*   **Scalability:** Sublinear scaling in screen resolution is observed because higher resolutions enable larger ray packets [S1].

## Background
The algorithm was proposed by Ize et al. in 2006 [S1][S2, unofficial]. It is referred to as the "general grid building algorithm" in the context of the IWRP06 paper [S1]. The authors extended this algorithm to hierarchical grids, showing competitive performance with kd-tree based systems for static scenes and significant results in dynamic scenes [S1].
