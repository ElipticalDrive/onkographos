# Bucket-based LBVH construction

Also called: BVH Building, Bvh constructor, Fernandes and Walter LBVH construction

## Overview
Bucket-based LBVH construction builds a Bounding Volume Hierarchy (BVH) from voxel data by grouping voxels into dynamic buckets rather than a fixed uniform grid [S2, unofficial]. It solves the inefficiency of fixed-brick approaches on sparse volumes by allowing bucket sizes to adapt to local voxel density [S2, unofficial]. It sets itself apart from [3D Voxel Grid Smoothing](833-3d-voxel-grid-smoothing.md) by preserving discrete voxel boundaries for culling, and from [Binary Voxel RLE Encoding](1071-binary-voxel-rle-encoding.md) by constructing a hierarchical traversal structure rather than a compressed linear array.

## How it works
**Inputs and Outputs:**
*   Input: A populated 3D voxel grid (occupancy/density) defined on integer indices $(i, j, k)$ [G].
*   Output: A BVH data structure (nodes and leaves) suitable for ray traversal.

**Data Structures:**
*   `volatileGPUData`: A temporary storage structure holding intermediate cluster and neighbor information during the compute shader pipeline [S1, unofficial].
*   `BVH`: The final hierarchy, typically stored in a Buffer Object (SSBO) or texture [S1, unofficial].

**Parameters:**
*   `BVH_BUILDING_RADIUS`: A static constant defining the search radius for neighbor finding. Typical value: 100 [S1, unofficial].

**Steps:**
1.  **Initialization**: Load voxel data into `volatileGPUData` [S1, unofficial].
2.  **Neighbor Finding**: Execute the `FIND_BEST_NEIGHBOR` compute shader. This step identifies spatial relationships between voxels within the `BVH_BUILDING_RADIUS` [S1, unofficial].
3.  **Cluster Merging**: Execute the `CLUSTER_MERGING` compute shader. Voxels are grouped into clusters based on neighbor proximity, forming the basis of the buckets [S1, unofficial].
4.  **Reallocation**: Execute the `REALLOCATE_CLUSTERS` compute shader to optimize cluster distribution and resolve conflicts [S1, unofficial].
5.  **Loop Termination Check**: Execute `END_LOOP_COMPUTATIONS` to determine if further merging is required based on convergence criteria [S1, unofficial].
6.  **Prefix Scan (Reduction)**: If merging continues, perform a parallel prefix scan using `REDUCE_PREFIX_SCAN` and `DOWN_SWEEP_PREFIX_SCAN` to compute new cluster boundaries and offsets [S1, unofficial].
7.  **Reset State**: Execute `RESET_LAST_POSITION_PREFIX_SCAN` to prepare for the next iteration [S1, unofficial].
8.  **Aggregation**: Call `aggregateSSBOData(volatileGPUData)` to finalize the BVH structure from the computed clusters [S1, unofficial].

**Pseudocode:**
```python
def bucket_based_lbvh_construction(voxel_grid):
    # Initialize temporary storage for GPU compute shaders
    volatile_gpu_data = initialize_volatile_data(voxel_grid)
    
    # Define the search radius for neighbor identification
    BVH_BUILDING_RADIUS = 100
    
    # Step 1: Find best neighbors for each voxel within the radius
    # This groups spatially close voxels
    find_best_neighbor(volatile_gpu_data, BVH_BUILDING_RADIUS)
    
    # Step 2: Merge voxels into clusters based on neighbor data
    cluster_merging(volatile_gpu_data)
    
    # Step 3: Reallocate clusters to optimize spatial distribution
    reallocate_clusters(volatile_gpu_data)
    
    # Step 4: Check if the construction loop should continue
    # This typically checks if cluster sizes or counts have stabilized
    should_continue = end_loop_computations(volatile_gpu_data)
    
    if should_continue:
        # Step 5: Perform parallel prefix scan to compute new boundaries
        # Reduction phase
        reduce_prefix_scan(volatile_gpu_data)
        # Down-sweep phase to finalize offsets
        down_sweep_prefix_scan(volatile_gpu_data)
        
        # Step 6: Reset state for next iteration
        reset_last_position_prefix_scan(volatile_gpu_data)
        
        # Recursive or iterative call to continue merging
        bucket_based_lbvh_construction(voxel_grid)
    else:
        # Finalize the BVH structure
        bvh = aggregate_ssbo_data(volatile_gpu_data)
        return bvh
```

**Edge Cases and Pitfalls:**
*   **Precision**: Floating-point precision in neighbor distance calculations may cause jitter in cluster boundaries for voxels at the edge of the `BVH_BUILDING_RADIUS` [S1, unofficial].
*   **Boundaries**: Voxels on the grid boundary may have fewer neighbors, leading to smaller or irregular clusters [G].
*   **Degenerate Input**: Empty volumes or single-voxel inputs may cause the prefix scan or merging steps to fail if not guarded [G].

### [Bucket Size Computation](8964-bucket-size-computation.md)
Computes the bucket texture storing the index of the last voxel of each bucket. It splits computation into fragment and vertex shader steps to avoid inefficient vertex shader texture fetches.

## Operating characteristics
*   **Time Complexity**: Parallel compute shader execution allows for near-linear scaling with voxel count, but the iterative merging and prefix scans add overhead [S1, unofficial].
*   **Memory Complexity**: Requires additional GPU memory for `volatileGPUData` and intermediate cluster states [S1, unofficial].
*   **Performance**: Allows 2-3 times higher frame rates than no empty-space skipping [S2, unofficial]. Outperforms fixed-brick approaches (e.g., Zellmann et al.) on sparse volumes [S2, unofficial].
*   **Strengths**: Adapts to sparse data; efficient GPU implementation.
*   **Limitations**: Iterative nature may cause divergence; requires careful tuning of `BVH_BUILDING_RADIUS` [S1, unofficial].

## Background
The method originates from Fernandes and Walter [FW20], who proposed grouping voxels into buckets for LBVH construction [S2, unofficial]. It is implemented in projects like `VoxelFragmentML` using compute shaders for neighbor finding and cluster merging [S1, unofficial].
