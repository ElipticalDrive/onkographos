# CT Slice Voxel Construction
Also called: Grid Cell Construction from CT Slices

## Overview
Constructs a 3D grid cell (voxel) from two adjacent 2D CT slices by calculating the 3D coordinates of its 8 vertices and retrieving the scalar values (Hounsfield units) for each vertex [S1, unofficial]. It differs from [3D Coordinate Grid Generation](2333-3d-coordinate-grid-generation.md) by explicitly handling the discrete nature of medical imaging data, using slice-specific metadata (pixel spacing, origin) rather than a normalized [-1, 1] domain, and mapping values directly from the source image arrays [S1, unofficial].

## How it works
**Inputs:**
- `theSliceIndex`: Index of the front slice [S1, unofficial].
- `theRowIndex`: Row index in the 2D slice grid [S1, unofficial].
- `theColumnIndex`: Column index in the 2D slice grid [S1, unofficial].
- `CTSliceFront`: Metadata object for the front slice (Z-plane $Z_{front}$, origin $(X_{UL}, Y_{UL})$, pixel spacing $(S_x, S_y)$) [S1, unofficial].
- `CTSliceBack`: Metadata object for the back slice (Z-plane $Z_{back}$, origin $(X_{UL}, Y_{UL})$, pixel spacing $(S_x, S_y)$) [S1, unofficial].

**Outputs:**
- `GridCell`: A structure containing:
  - `p[0..7]`: Array of 8 `Point3D` objects representing the voxel vertices [S1, unofficial].
  - `val[0..7]`: Array of 8 integers representing the Hounsfield unit (HU) values at each vertex [S1, unofficial].

**Data Structures:**
- `Point3D`: Contains `x`, `y`, `z` (double) [S1, unofficial].
- `CTSliceInfo`: Contains `UpperLeft_X`, `UpperLeft_Y`, `UpperLeft_Z`, `PixelSpacing_X`, `PixelSpacing_Y` [S1, unofficial].
- `GridCell`: Contains `p` (array of 8 `Point3D`) and `val` (array of 8 `Int32`) [S1, unofficial].

**Vertex Convention:**
The vertices are mapped according to the Marching Cubes convention (Paul Bourke's index convention) [S1, unofficial]:
- Indices 0-3: Back slice (Bottom-Left, Bottom-Right, Top-Right, Top-Left) [S1, unofficial].
- Indices 4-7: Front slice (Bottom-Left, Bottom-Right, Top-Right, Top-Left) [S1, unofficial].
The mapping is consistent with standard MC indexing where the first 4 vertices belong to the "back" (lower Z) and the last 4 to the "front" (higher Z), but the specific Y-ordering (Top/Bottom) must be verified against the coordinate system [S1, unofficial].

**Steps:**
1. **Calculate X coordinates:**
   - Front Slice: $X_{L,F} = X_{UL,F} + (\text{theColumnIndex} \times S_{x,F})$ and $X_{R,F} = X_{L,F} + S_{x,F}$ [S1, unofficial].
   - Back Slice: $X_{L,B} = X_{UL,B} + (\text{theColumnIndex} \times S_{x,B})$ and $X_{R,B} = X_{L,B} + S_{x,B}$ [S1, unofficial].
2. **Calculate Y coordinates:**
   - Front Slice: $Y_{T,F} = Y_{UL,F} + (\text{theRowIndex} \times S_{y,F})$ and $Y_{B,F} = Y_{T,F} + S_{y,F}$ [S1, unofficial].
   - Back Slice: $Y_{T,B} = Y_{UL,B} + (\text{theRowIndex} \times S_{y,B})$ and $Y_{B,B} = Y_{T,B} + S_{y,B}$ [S1, unofficial].
3. **Calculate Z coordinates:**
   - $Z_F = Z_{UL,F}$ and $Z_B = Z_{UL,B}$ [S1, unofficial].
4. **Assign vertex positions:**
   - $p[0] = (X_{L,B}, Y_{B,B}, Z_B)$, $p[1] = (X_{R,B}, Y_{B,B}, Z_B)$, $p[2] = (X_{R,F}, Y_{B,F}, Z_F)$, $p[3] = (X_{L,F}, Y_{B,F}, Z_F)$ [S1, unofficial].
   - $p[4] = (X_{L,B}, Y_{T,B}, Z_B)$, $p[5] = (X_{R,B}, Y_{T,B}, Z_B)$, $p[6] = (X_{R,F}, Y_{T,F}, Z_F)$, $p[7] = (X_{L,F}, Y_{T,F}, Z_F)$ [S1, unofficial].
5. **Retrieve scalar values (Hounsfield Units):**
   The source code implies a specific row/column indexing for the pixel array [S1, unofficial].
   - Back Slice: `val[0]` at `(theRowIndex + 1, theColumnIndex)`, `val[1]` at `(theRowIndex + 1, theColumnIndex + 1)`, `val[4]` at `(theRowIndex, theColumnIndex)`, `val[5]` at `(theRowIndex, theColumnIndex + 1)` [S1, unofficial].
   - Front Slice: `val[2]` at `(theRowIndex + 1, theColumnIndex + 1)`, `val[3]` at `(theRowIndex + 1, theColumnIndex)`, `val[6]` at `(theRowIndex, theColumnIndex + 1)`, `val[7]` at `(theRowIndex, theColumnIndex)` [S1, unofficial].

**Pseudocode:**
```python
def construct_grid_cell(theSliceIndex, theRowIndex, theColumnIndex, slice_front, slice_back):
    """
    Constructs a GridCell from two adjacent CT slices.
    
    Args:
        theSliceIndex: Index of the front slice.
        theRowIndex: Row index in the 2D slice grid.
        theColumnIndex: Column index in the 2D slice grid.
        slice_front: Object with attributes UpperLeft_X, UpperLeft_Y, UpperLeft_Z, 
                     PixelSpacing_X, PixelSpacing_Y, and a method GetHounsfieldPixelValue(row, col).
        slice_back: Same structure as slice_front.
        
    Returns:
        A GridCell object with p[0..7] (Point3D) and val[0..7] (int).
    """
    
    # 1. Calculate X coordinates
    x_l_front = slice_front.UpperLeft_X + (theColumnIndex * slice_front.PixelSpacing_X)
    x_r_front = x_l_front + slice_front.PixelSpacing_X
    
    x_l_back = slice_back.UpperLeft_X + (theColumnIndex * slice_back.PixelSpacing_X)
    x_r_back = x_l_back + slice_back.PixelSpacing_X
    
    # 2. Calculate Y coordinates
    y_t_front = slice_front.UpperLeft_Y + (theRowIndex * slice_front.PixelSpacing_Y)
    y_b_front = y_t_front + slice_front.PixelSpacing_Y
    
    y_t_back = slice_back.UpperLeft_Y + (theRowIndex * slice_back.PixelSpacing_Y)
    y_b_back = y_t_back + slice_back.PixelSpacing_Y
    
    # 3. Calculate Z coordinates
    z_front = slice_front.UpperLeft_Z
    z_back = slice_back.UpperLeft_Z
    
    # 4. Assign vertex positions
    # p[0..3] are Back slice, p[4..7] are Front slice
    p = [None] * 8
    p[0] = Point3D(x_l_back, y_b_back, z_back)
    p[1] = Point3D(x_r_back, y_b_back, z_back)
    p[2] = Point3D(x_r_front, y_b_front, z_front)
    p[3] = Point3D(x_l_front, y_b_front, z_front)
    p[4] = Point3D(x_l_back, y_t_back, z_back)
    p[5] = Point3D(x_r_back, y_t_back, z_back)
    p[6] = Point3D(x_r_front, y_t_front, z_front)
    p[7] = Point3D(x_l_front, y_t_front, z_front)
    
    # 5. Retrieve scalar values
    val = [None] * 8
    
    # Back Slice Values
    val[0] = slice_back.GetHounsfieldPixelValue(theRowIndex + 1, theColumnIndex)
    val[1] = slice_back.GetHounsfieldPixelValue(theRowIndex + 1, theColumnIndex + 1)
    val[4] = slice_back.GetHounsfieldPixelValue(theRowIndex, theColumnIndex)
    val[5] = slice_back.GetHounsfieldPixelValue(theRowIndex, theColumnIndex + 1)
    
    # Front Slice Values
    val[2] = slice_front.GetHounsfieldPixelValue(theRowIndex + 1, theColumnIndex + 1)
    val[3] = slice_front.GetHounsfieldPixelValue(theRowIndex + 1, theColumnIndex)
    val[6] = slice_front.GetHounsfieldPixelValue(theRowIndex, theColumnIndex + 1)
    val[7] = slice_front.GetHounsfieldPixelValue(theRowIndex, theColumnIndex)
    
    return GridCell(p, val)

class Point3D:
    def __init__(self, x, y, z):
        self.x = x
        self.y = y
        self.z = z

class GridCell:
    def __init__(self, p, val):
        self.p = p
        self.val = val
```

**Edge Cases and Pitfalls:**
- **Index Offset:** The code uses `theRowIndex + 1` for the bottom row values and `theRowIndex` for the top row values, implying a specific coordinate system where row 0 might be the top or bottom [S1, unofficial]. If the image array is stored with row 0 at the top (standard image format), then `row + 1` corresponds to a lower Y coordinate (if Y increases upwards) or higher Y coordinate (if Y increases downwards) [G]. The source code's mapping of `val[0]` (Back-Bottom-Left) to `(row+1, col)` suggests that in the image array, a higher row index corresponds to the "Bottom" of the voxel in world space [S1, unofficial]. This is a critical assumption that must be verified against the specific DICOM header or image storage format [S1, unofficial].
- **Boundary Conditions:** The algorithm assumes `theRowIndex + 1` and `theColumnIndex + 1` are valid indices [S1, unofficial]. For the last row or column of a slice, this will cause an out-of-bounds error [G]. The caller must ensure that the loop bounds exclude the last row and column, or handle boundary conditions explicitly [G].
- **Pixel Spacing:** The algorithm assumes uniform pixel spacing within a slice [S1, unofficial]. If pixel spacing varies, the calculation must be adjusted [G].
- **Z-Ordering:** The algorithm assumes `slice_back` has a lower Z value than `slice_front` [S1, unofficial]. If the slices are not ordered correctly, the voxel geometry will be inverted [G].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel, as it involves a fixed number of arithmetic operations and array lookups [G].
- **Memory Complexity:** $O(1)$ per voxel, storing 8 points and 8 values [G].
- **Strengths:** Simple, efficient, and directly maps to the Marching Cubes algorithm's requirements [S1, unofficial].
- **Limitations:** Requires careful handling of image array indexing and coordinate system orientation [S1, unofficial]. Not suitable for non-uniform voxel sizes or irregular grids [G].

## Background
This method is derived from a C# implementation for generating 3D meshes from CT slices using the Marching Cubes algorithm [S1, unofficial]. It is based on the vertex indexing convention described by Paul Bourke in "Polygonising a scalar field" [S1, unofficial]. The method is commonly used in medical imaging visualization to convert 2D CT scan slices into a 3D volumetric representation [S1, unofficial].
