# Kernel Density Estimation for Volume Reconstruction
Also called: Splatting-based Density Estimation
## Overview
Kernel Density Estimation (KDE) reconstructs a 3D volume from discrete samples by treating reconstruction as a density estimation problem [S1]. It differs from iterative solvers like SART by allowing samples to be splatted independently and discarded, avoiding the need to maintain grid state during accumulation [S1].
## How it works
**Inputs and Outputs:**
- Input: A set of $N$ samples, each with a 3D position $\mathbf{x}_i$ and a scalar value $v_i$ [G].
- Output: A regular 3D volume grid $V$ where each voxel stores the accumulated density [G].

**Data Structures:**
- The output grid $V$ is a 3D array indexed by $(u, v, w)$ [G].
- Each voxel corresponds to a spatial region defined by a uniform voxel size $\Delta$ [G].

**Steps:**
1. **Grid Initialization:** Initialize the volume grid $V$ to zero [G].
2. **Sample Splatting:** For each sample $i$ with position $\mathbf{x}_i$ and value $v_i$:
   a. Determine the bounding box of voxels whose centers lie within the kernel support [G].
   b. For each affected voxel $(u, v, w)$, compute the trilinear interpolation weight $w_{uvw}$ based on the distance between $\mathbf{x}_i$ and the voxel center [G].
   c. Accumulate the sample's value into the voxel: $V_{uvw} \leftarrow V_{uvw} + v_i \cdot w_{uvw}$ [G].
3. **Completion:** After all samples are processed, the grid $V$ contains the reconstructed density field [G].

**Formulas:**
The trilinear weight $w$ for a sample at $\mathbf{x}_i$ contributing to a voxel at center $\mathbf{c}_{uvw}$ is the product of 1D linear interpolation factors along each axis [G]. With voxel size $\Delta$, the weight is non-zero only if $|\mathbf{x}_i - \mathbf{c}_{uvw}|_\infty \le \Delta$, and is computed as:
$$ w_{uvw} = \prod_{d \in \{x,y,z\}} \max\left(0, 1 - \frac{|x_{i,d} - c_{uvw,d}|}{\Delta}\right) $$

**Parameters:**
- Voxel size $\Delta$: Determines grid resolution and kernel support [G].

**Edge Cases and Pitfalls:**
- **Boundaries:** Samples near the grid boundary have their kernel support clipped, reducing their contribution [G].
- **Precision:** Accumulating many small values may lead to floating-point precision issues [G].

**Pseudocode:**
```python
def kernel_density_estimation(samples, grid_shape, voxel_size):
    """Reconstructs a 3D volume from samples using trilinear KDE."""
    grid = [[[0.0] * grid_shape[2] for _ in range(grid_shape[1])] for _ in range(grid_shape[0])]
    inv_voxel = 1.0 / voxel_size
    for pos, value in samples:
        x, y, z = pos
        start_u = max(0, int((x - voxel_size * 0.5) * inv_voxel))
        end_u = min(grid_shape[0], int((x + voxel_size * 0.5) * inv_voxel) + 1)
        start_v = max(0, int((y - voxel_size * 0.5) * inv_voxel))
        end_v = min(grid_shape[1], int((y + voxel_size * 0.5) * inv_voxel) + 1)
        start_w = max(0, int((z - voxel_size * 0.5) * inv_voxel))
        end_w = min(grid_shape[2], int((z + voxel_size * 0.5) * inv_voxel) + 1)
        for u in range(start_u, end_u):
            for v in range(start_v, end_v):
                for w in range(start_w, end_w):
                    cx = (u + 0.5) * voxel_size
                    cy = (v + 0.5) * voxel_size
                    cz = (w + 0.5) * voxel_size
                    dx = abs(x - cx) * inv_voxel
                    dy = abs(y - cy) * inv_voxel
                    dz = abs(z - cz) * inv_voxel
                    if dx < 1.0 and dy < 1.0 and dz < 1.0:
                        wx = 1.0 - dx
                        wy = 1.0 - dy
                        wz = 1.0 - dz
                        grid[u][v][w] += value * wx * wy * wz
    return grid
```
## Subtopics

### [Transient 2D Kernel Density Estimation](9520-transient-2d-kernel-density-estimation.md)
Transient 2D Kernel Density Estimation (KDE) estimates the radiance contribution of photon beams to a camera ray in a homogeneous participating medium by projecting the interaction onto a 2D spatial kernel and a 1D temporal window. It solves the problem of computing time-resolved light transport (transient rendering) efficiently by approximating the continuous beam contribution as a discrete density estimate. It differs from the standard 3D KDE [Kernel Density Estimation for Volume Reconstruction](9516-kernel-density-estimation-for-volume-reconstruction.md) by explicitly modeling the temporal footprint of the light pulse, and from the 1D kernel variant by distributing energy over a temporal interval rather than a single instant, introducing a trade-off between temporal bias and computational simplicity.

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N)$ assuming constant support size per sample [G].
- Memory: $O(D_x \cdot D_y \cdot D_z)$ for the output grid; samples are discarded after splatting [S1].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Linear with sample count. Adaptive grids (e.g., octrees) can improve efficiency for sparse data [S1].

**Strengths and Limitations:**
- Strengths: Simple implementation, parallelizable, allows discarding samples after processing [S1].
- Limitations: Produces smoother results than exact reconstruction, potentially losing high-frequency details [G].

**When to Use:**
- Quick, smooth reconstruction or streaming samples [S1].

**When Not to Use:**
- High-fidelity, sharp reconstruction is required, or when iterative solvers like SART are preferred for solving linear systems on adaptive grids [S1].
## Background
**Origin:**
- Based on Parzen density estimation [S1].

**History and Development:**
- Used for volume reconstruction from samples, with extensions to 2D re-rendering and per-slice reconstructions [S1]. Contrasted with matrix-free iterative solvers like SART, noting KDE's efficiency on adaptive grids [S1].

**Where it is Used:**
- Volume reconstruction from samples in computer graphics [S1].
