# Kernel Density Estimation for Volume Reconstruction
Also called: Splatting-based Density Estimation, Volume Reconstruction
## Overview
Kernel Density Estimation (KDE) reconstructs a 3D volume from discrete samples by treating the reconstruction as a density estimation problem [S1]. It differs from iterative solvers like SART by allowing samples to be splatted independently and discarded, avoiding the need to maintain grid state during the accumulation phase [S1].
## How it works
**Inputs and Outputs:**
- Input: A set of $N$ samples, where each sample $i$ has a position $\mathbf{x}_i \in \mathbb{R}^3$ and a scalar value $v_i$ (e.g., density or radiance).
- Output: A regular 3D volume grid $V$ of dimensions $D_x \times D_y \times D_z$, where each voxel stores the accumulated density.

**Data Structures:**
- The output grid $V$ is a 3D array. Each voxel $(u, v, w)$ corresponds to a spatial region in the world coordinate system.
- The grid resolution is determined by the desired output size and the spatial extent of the samples.

**Steps:**
1. **Grid Initialization:** Initialize the volume grid $V$ to zero.
2. **Sample Splatting:** For each sample $i$ with position $\mathbf{x}_i$ and value $v_i$:
   a. Determine the bounding box of the kernel support around $\mathbf{x}_i$. The kernel has compact support, typically defined by a radius $h$.
   b. Identify all voxels $(u, v, w)$ whose centers lie within this support.
   c. For each affected voxel, compute the trilinear interpolation weight $w_{uvw}$ based on the distance between $\mathbf{x}_i$ and the voxel center. Trilinear weights ensure smooth transitions and compact support [S1].
   d. Accumulate the sample's value into the voxel:
      $$ V_{uvw} \leftarrow V_{uvw} + v_i \cdot w_{uvw} $$
3. **Completion:** After all samples are processed, the grid $V$ contains the reconstructed density field.

**Formulas:**
The trilinear weight $w$ for a sample at $\mathbf{x}_i$ contributing to a voxel at $\mathbf{c}_{uvw}$ is proportional to the product of 1D linear interpolation factors along each axis. If the kernel support radius is $h$, and the voxel size is $\Delta$, the weight is non-zero only if $|\mathbf{x}_i - \mathbf{c}_{uvw}|_\infty \le h$.

**Parameters:**
- Kernel radius $h$: Determines the smoothness and support size. Not given in the sources.
- Grid resolution: Determines the spatial detail. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** Accumulating many small values may lead to floating-point precision issues. Not given in the sources.
- **Boundaries:** Samples near the grid boundary may have their kernel support clipped. Not given in the sources.
- **Degenerate Input:** If samples are identical, they will accumulate in the same voxels, potentially causing overestimation if not normalized. Not given in the sources.

**Pseudocode:**
```python
def kernel_density_estimation(samples, grid_shape, voxel_size, kernel_radius):
    """
    Reconstructs a 3D volume from samples using KDE.
    
    Args:
        samples: List of tuples (position, value), where position is (x, y, z).
        grid_shape: Tuple (Dx, Dy, Dz) defining the output grid dimensions.
        voxel_size: Float, size of each voxel in world units.
        kernel_radius: Float, radius of the kernel support.
        
    Returns:
        3D numpy array representing the density grid.
    """
    import numpy as np
    
    # Initialize grid
    grid = np.zeros(grid_shape, dtype=np.float32)
    
    # Precompute grid bounds
    min_x = 0.0
    min_y = 0.0
    min_z = 0.0
    max_x = grid_shape[0] * voxel_size
    max_y = grid_shape[1] * voxel_size
    max_z = grid_shape[2] * voxel_size
    
    for pos, value in samples:
        x, y, z = pos
        
        # Determine voxel indices covered by the kernel
        # Calculate the range of voxel indices that might be affected
        start_u = max(0, int((x - kernel_radius) / voxel_size))
        end_u = min(grid_shape[0], int((x + kernel_radius) / voxel_size) + 1)
        start_v = max(0, int((y - kernel_radius) / voxel_size))
        end_v = min(grid_shape[1], int((y + kernel_radius) / voxel_size) + 1)
        start_w = max(0, int((z - kernel_radius) / voxel_size))
        end_w = min(grid_shape[2], int((z + kernel_radius) / voxel_size) + 1)
        
        for u in range(start_u, end_u):
            for v in range(start_v, end_v):
                for w in range(start_w, end_w):
                    # Calculate voxel center
                    cx = (u + 0.5) * voxel_size
                    cy = (v + 0.5) * voxel_size
                    cz = (w + 0.5) * voxel_size
                    
                    # Calculate distance components
                    dx = x - cx
                    dy = y - cy
                    dz = z - cz
                    
                    # Check if within kernel support
                    if abs(dx) <= kernel_radius and abs(dy) <= kernel_radius and abs(dz) <= kernel_radius:
                        # Compute trilinear weight
                        # Assuming a linear kernel for simplicity, normalized by kernel_radius
                        # Weight = (1 - |dx|/h) * (1 - |dy|/h) * (1 - |dz|/h)
                        wx = 1.0 - abs(dx) / kernel_radius
                        wy = 1.0 - abs(dy) / kernel_radius
                        wz = 1.0 - abs(dz) / kernel_radius
                        
                        weight = wx * wy * wz
                        
                        # Accumulate value
                        grid[u, v, w] += value * weight
                        
    return grid
```
## Subtopics

### [Transient 2D Kernel Density Estimation](9520-transient-2d-kernel-density-estimation.md)
Transient 2D Kernel Density Estimation (KDE) estimates the radiance contribution of photon beams to a camera ray in a homogeneous participating medium by projecting the interaction onto a 2D spatial kernel and a 1D temporal window. It solves the problem of computing time-resolved light transport (transient rendering) efficiently by approximating the continuous beam contribution as a discrete density estimate. It differs from the standard 3D KDE [Kernel Density Estimation for Volume Reconstruction](9516-kernel-density-estimation-for-volume-reconstruction.md) by explicitly modeling the temporal footprint of the light pulse, and from the 1D kernel variant by distributing energy over a temporal interval rather than a single instant, introducing a trade-off between temporal bias and computational simplicity.

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N \cdot K)$, where $N$ is the number of samples and $K$ is the number of voxels in the kernel support. Since the kernel has compact support, $K$ is constant for a fixed grid resolution and kernel radius.
- Memory: $O(D_x \cdot D_y \cdot D_z)$ for the output grid. Samples can be discarded after splatting, so input memory is not retained [S1].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- The method scales linearly with the number of samples. Adaptive grids (e.g., octrees) can improve efficiency for sparse data, as noted in the sources [S1].

**Strengths and Limitations:**
- Strengths: Simple implementation, parallelizable (samples are independent), allows discarding samples after processing [S1].
- Limitations: May produce smoother results than necessary, potentially losing high-frequency details. Not given in the sources.

**When to Use:**
- When a quick, smooth reconstruction is needed, or when samples can be processed in a streaming fashion [S1].

**When Not to Use:**
- When high-fidelity, sharp reconstruction is required, or when iterative methods like SART are preferred for their accuracy in solving the underlying linear system [S1].
## Background
**Origin:**
- The method is based on Kernel Density Estimation, a non-parametric way to estimate the probability density function of a random variable, originally proposed by Parzen in 1962 [S1].
- In the context of volume reconstruction, it was applied to stochastic tomography for 3D imaging of mixing fluids [S1].

**History and Development:**
- The approach was used in the paper "Stochastic tomography and its applications in 3D imaging of mixing fluids" [S1].
- It is noted as an alternative to matrix-free iterative solvers like SART, particularly for adaptive grids [S1].

**Where it is Used:**
- 3D imaging of mixing fluids [S1].
- Volume reconstruction from samples in computer graphics [S1].
