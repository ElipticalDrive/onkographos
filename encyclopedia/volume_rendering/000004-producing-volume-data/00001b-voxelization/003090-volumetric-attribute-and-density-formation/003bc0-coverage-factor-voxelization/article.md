# Coverage Factor Voxelization

Also called: 64x Supersampling Coverage, Coverage Factor Computation, Scalar Voxelization

## Overview
Coverage Factor Voxelization computes a scalar-valued voxelization where each voxel stores the percentage of its volume covered by the input object, derived from a finer-resolution binary solid voxelization [S1, S2]. It differs from sibling methods like [Interior Voxelize](995-interior-voxelize.md) by providing continuous density estimates rather than binary occupancy, leveraging an octree structure to achieve 64x supersampling efficiency [S1, S2].

## How it works
**Inputs:** An octree-based binary solid voxelization (typically generated by a preceding solid voxelization step) where each node has an `inside` flag and potentially child nodes representing a finer sub-grid.
**Outputs:** A scalar field where each voxel (or octree node) stores a coverage factor $C \in [0, 1]$.

**Data Structures:**
The method operates on an octree. Each node $N$ at level $i$ contains:
- `inside`: Boolean flag indicating if the node is fully inside the object.
- `children`: List of 8 child nodes (for level $i < L_{max}$).
- `coverage`: Float value storing the computed coverage factor.

**Steps:**
1. **Initialize Level-0 Coverage:** For each root node (level-0), calculate the coverage factor as the fraction of set bits (occupied voxels) in its associated $2 \times 2 \times 2$ sub-grid (8 voxels). Let $k$ be the number of occupied voxels in the sub-grid. The coverage is $C = k / 8$. [S1, S2]
2. **Iterative Aggregation:** Process nodes from the finest level up to the root (or recursively from root down, depending on implementation, but logically defined by children's values).
   - If a node $N$ has children, its coverage factor is the arithmetic mean of its children's coverage factors:
     $$ C_N = \frac{1}{8} \sum_{j=1}^{8} C_{child_j} $$
   - If a node $N$ has no children (leaf node in the context of the solid voxelization's depth), its coverage factor is determined by its `inside` flag:
     $$ C_N = \begin{cases} 1.0 & \text{if } inside \\ 0.0 & \text{if } \neg inside \end{cases} $$
3. **Apply Iteratively:** This process is applied iteratively for all remaining levels, ensuring that coarser nodes aggregate the detailed coverage information from their finer descendants [S1, S2].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def compute_coverage_factor(node):
    """
    Recursively computes the coverage factor for an octree node.
    Assumes the node structure has 'children' (list of nodes or None)
    and 'inside' (bool).
    """
    if node.children is None:
        # Leaf node: coverage is 1.0 if inside, 0.0 if outside
        return 1.0 if node.inside else 0.0
    
    # Internal node: average coverage of children
    child_coverages = [compute_coverage_factor(child) for child in node.children]
    return sum(child_coverages) / len(child_coverages)

def process_level0(root_node):
    """
    Special handling for level-0 nodes which may have a fixed 2x2x2 sub-grid
    if the octree depth is minimal or defined differently.
    Note: The source describes level-0 as fraction of set bits in sub-grid.
    This implies the 'children' might be the 8 voxels directly.
    """
    # If the root node's children are the 8 voxels of the sub-grid:
    if len(root_node.children) == 8:
        occupied_count = sum(1 for child in root_node.children if child.inside)
        return occupied_count / 8.0
    else:
        # Fallback to recursive average if structure differs
        return compute_coverage_factor(root_node)
```

**Parameters:**
- Supersampling factor: 64x [S1, S2]. This refers to the effective resolution increase provided by the octree's ability to represent fine details within coarse voxels, specifically noting that level-0 nodes can be derived from a finer binary solid voxelization.

**Edge Cases:**
- Nodes with no children: Handled by the `inside` flag [S1, S2].
- Precision: Floating-point averaging may introduce minor precision errors, but standard float precision is sufficient for coverage factors [G].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of octree nodes, as each node is visited once to compute its coverage from children [S1, S2].
- **Memory Complexity:** Requires storing the octree structure and the coverage factor for each node. The octree provides memory efficiency by only subdividing where necessary [S1, S2].
- **Performance:** Implemented in CUDA using persistent threads for parallel processing of triangles and voxels [S1, S2]. The 64x supersampling is achieved without explicitly storing all fine voxels, reducing memory footprint compared to uniform high-resolution grids [S1, S2].
- **Strengths:** Provides smooth, continuous density values; efficient memory usage via octree; supports 64x supersampling [S1, S2].
- **Limitations:** Requires a pre-computed binary solid voxelization; accuracy depends on the depth of the octree [S1, S2].

## Background
The method was introduced by Michael Schwarz et al. in "Fast parallel surface and solid voxelization on GPUs" (2010) [S1, S2]. It was developed to support applications requiring scalar-valued voxelizations, such as volume rendering with smooth density transitions, by leveraging the octree structure for efficient supersampling [S1, S2].
