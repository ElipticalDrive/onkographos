# Voronoi-based Customization Volume Generation

Also called: Discrete Voronoi Diagram Calculation on GPU, Discrete Voronoi Diagram for Customization, Natural Neighbor Interpolation via Voronoi

## Overview
This method generates a low-resolution 3D customization volume by computing a discrete Voronoi diagram on the GPU, assigning each voxel to its nearest seed point, and subsequently calculating customization values via natural neighbor interpolation [S1]. It solves the performance bottleneck of calculating position-dependent transfer function parameters for large volume datasets by decoupling the customization resolution from the input data size, enabling interactive frame rates [S1]. It builds on [Voronoi-like Segmentation Volume Generation](4218-voronoi-like-segmentation-volume-generation.md) by adding the interpolation step to produce continuous scalar values rather than discrete labels.

## How it works
The method operates in two compute-shader passes. Pass 1 computes the discrete Voronoi diagram. Pass 2 computes the customization volume values using natural neighbor interpolation based on the Voronoi cell memberships determined in Pass 1.

**Inputs and Outputs:**
*   **Input:** A buffer of seed points `points[]`. Each seed point contains a 3D voxel position `pos` and a numeric visualization parameter `value`. The positions are specified in the original high-resolution input volume coordinate system.
*   **Input:** The resolution of the customization volume `resolution` (e.g., $64^3$).
*   **Output:** A linear buffer `voronoi[]` storing the index of the nearest seed point for each voxel in the customization volume.
*   **Output:** The final customization volume (scalar values per voxel).

**Data Structures:**
*   `points[]`: Array of structures. Each element has `pos` (vec3) and `value` (float).
*   `voronoi[]`: Linear 1D array of integers. Size equals the total number of voxels in the customization volume ($R_x \times R_y \times R_z$).
*   `customization[]`: Linear 1D array of floats. Size equals the total number of voxels in the customization volume.

**Parameters:**
*   **Resolution:** The customization volume resolution is typically $64^3$ voxels, significantly lower than the input volume data to reduce memory usage [S1].
*   **Distance Measure:** Can be squared Euclidean distance or Manhattan distance [S1].
*   **Scaling:** Seed point positions must be scaled from the original input volume resolution to the customization volume resolution before being passed to the shader [S1].

**Steps:**

1.  **Pass 1: Discrete Voronoi Diagram Calculation**
    For each voxel in the customization volume grid, a work item is launched.
    1.  Determine the 3D position `cur3DPos` of the current voxel from the global invocation ID.
    2.  Initialize `minPoint` to 0 and `minDist` to infinity.
    3.  Iterate through all seed points in the input buffer `points[]`.
    4.  Calculate the distance `d` between the seed point's position `points[i].pos` and `cur3DPos`.
    5.  If `d < minDist`, update `minDist = d` and `minPoint = i`.
    6.  Calculate the linear index for the current voxel in the output buffer:
        $$ index = cur3DPos.x + resolution.x \cdot cur3DPos.y + resolution.y \cdot resolution.x \cdot cur3DPos.z $$
    7.  Store `minPoint` in `voronoi[index]`.

2.  **Pass 2: Customization Volume Generation**
    For each voxel in the customization volume grid, a work item is launched to compute the final value.
    1.  Retrieve the index of the nearest seed point `nearestIdx` from `voronoi[]` for the current voxel.
    2.  Retrieve the position `cur3DPos` of the current voxel.
    3.  Compute the customization value using natural neighbor interpolation. This involves calculating the intersection of Voronoi cells to determine weights for neighboring seed points [S1].
    4.  Store the result in the customization volume buffer.

**Pseudocode (Pass 1):**
```python
# Input: points[] (array of {pos: vec3, value: float}), resolution (vec3)
# Output: voronoi[] (array of int)

# Each work item handles one voxel
def compute_voronoi_diagram():
    # Get 3D position from current global work item index
    cur3DPos = vec3(gl_GlobalInvocationID.x, gl_GlobalInvocationID.y, gl_GlobalInvocationID.z)
    
    # Initialize temporary variables
    minPoint = 0
    minDist = float('inf')
    
    # Determine the nearest point to cur3DPos
    numPoints = len(points)
    for i in range(numPoints):
        # Calculate distance (Euclidean or Manhattan as configured)
        d = distance(points[i].pos, cur3DPos)
        
        if d < minDist:
            minDist = d
            minPoint = i
            
    # Calculate linear index from cur3DPos and set Voronoi data
    index = cur3DPos.x + resolution.x * cur3DPos.y + resolution.y * resolution.x * cur3DPos.z
    voronoi[index] = minPoint
```

**Pseudocode (Pass 2 - Conceptual):**
```python
# Input: voronoi[], points[], resolution (vec3)
# Output: customization[] (array of float)

def compute_customization_volume():
    # Get 3D position
    cur3DPos = vec3(gl_GlobalInvocationID.x, gl_GlobalInvocationID.y, gl_GlobalInvocationID.z)
    
    # Get nearest seed point index
    nearestIdx = voronoi[cur3DPos.x + resolution.x * cur3DPos.y + resolution.y * resolution.x * cur3DPos.z]
    
    # Compute value using natural neighbor interpolation
    # This requires calculating Voronoi cell intersections for the current voxel
    # relative to all seed points to determine weights.
    # The specific algorithm for natural neighbor interpolation is detailed in 
    # [Natural Neighbor Interpolation](6494-natural-neighbor-interpolation.md).
    value = natural_neighbor_interpolation(cur3DPos, points, voronoi)
    
    customization[cur3DPos.x + resolution.x * cur3DPos.y + resolution.y * resolution.x * cur3DPos.z] = value
```

**Edge Cases and Pitfalls:**
*   **Precision:** The distance calculation must be consistent with the chosen metric (Euclidean vs. Manhattan) [S1].
*   **Boundaries:** Seed points specified in the original high-resolution input must be correctly scaled to the customization volume resolution; failure to do so results in incorrect nearest-neighbor assignments [S1].
*   **Degenerate Input:** If multiple seed points are equidistant to a voxel, the behavior depends on the iteration order and comparison logic (strict `<` vs `<=`). The provided pseudocode uses strict `<`, so the first encountered point in the buffer order wins ties.

## Subtopics

### [Natural Neighbor Interpolation](6494-natural-neighbor-interpolation.md)
An interpolation method that satisfies three requirements: (1) values at user-defined seed points remain unchanged, (2) interpolation between neighboring seed points is continuous and monotonic, and (3) each seed point has only local influence (occlusion). It calculates a Voronoi diagram of seed points and uses the intersection of Voronoi cells to determine weights.

## Operating characteristics
*   **Time Complexity:** Pass 1 (Voronoi Diagram) is $O(V \cdot N)$, where $V$ is the number of voxels in the customization volume and $N$ is the number of seed points [S1]. Pass 2 (Customization Volume) is $O(V^2)$, as each work item iterates over all voxels in the resolution to compute natural neighbor weights [S1].
*   **Memory Complexity:** The method requires storing the `voronoi[]` buffer (integer per voxel) and the `customization[]` buffer (float per voxel) for the low-resolution grid. The seed points buffer is also required.
*   **Performance:** The low resolution (e.g., $64^3$) allows for interactive frame rates despite the $O(V^2)$ complexity of Pass 2, because $V$ is small [S1]. However, the additional lookups and computations (such as the power function in natural neighbor interpolation) reduce the overall performance of the volume rendering pipeline compared to standard raycasting [S1].
*   **Strengths:** Exploits massively parallel GPU computing; decouples customization resolution from input data size; allows interactive frame rates for large datasets [S1].
*   **Limitations:** The $O(V^2)$ complexity of the second pass can become a bottleneck if the customization volume resolution is increased significantly; requires minor modifications to the existing rendering pipeline to apply the customization values [S1].
*   **When to use:** When interactive customization of transfer function parameters is needed for large volume datasets, and the customization field can be adequately represented at a lower resolution (e.g., $64^3$).
*   **When not to use:** When high-frequency spatial variations in customization parameters are required, or when the number of seed points $N$ is extremely large, making Pass 1 prohibitively slow.

## Background
The method was proposed by [S1] to overcome performance issues associated with calculating position-dependent customization parameters on the GPU for large volume datasets. It builds on the discretization approach proposed by Park et al. [PLK∗06] to approximate the volume of Voronoi cells by the number of voxels belonging to them. The method utilizes compute shaders (available in OpenGL 4.3+) to perform the calculations in parallel. It is used in the context of interactive position-dependent customization of transfer function classification parameters in volume rendering.
