# COM Repeat Projection

Also called: Project 2 COM, Project 2 COM Repeat

## Overview
COM Repeat Projection is an anisotropic voxelization technique that projects volumetric data (such as optical depth) onto a 2D grid while accounting for the shift caused by non-nadir viewing angles. It solves the problem of geometric distortion in single-view projections by repeating the data array to handle shifts induced by the Viewing Zenith Angle (VZA), then interpolating back to the original coordinate system. It sets itself apart from standard projection methods by explicitly managing the spatial extent expansion required to capture the full shifted footprint of the volume before re-sampling.

## How it works
The method operates on a 3D data array `da` with dimensions `(x, y, vza)`, where `vza` represents the Viewing Zenith Angle. The goal is to produce a projected data array `da_proj` that aligns the shifted projections back to the original `x` coordinates for each view.

### Inputs and Outputs
- **Input**: `da`, a DataArray with dimensions `x`, `y`, and `vza`. `x` and `y` are spatial coordinates, `vza` is the viewing zenith angle in degrees.
- **Output**: `da_proj`, a DataArray with the same shape and coordinates as `da`, containing the projected values.

### Data Structures
- `da`: 3D array. `da.data` is a numpy array of shape `(nx, ny, nvza)`.
- `x_coord`: 1D array of x-coordinates from the nadir view (`vza=0`).
- `dx`: Spatial resolution (step size) in the x-direction.
- `cloud_height_avg`: Average cloud height (used to calculate shift).
- `delta_z`: Vertical step size or height difference associated with `dx` and `cloud_height_avg`.

### Steps
1. **Extract Data**: Get `x`, `y`, and `vza` arrays from `da`.
2. **Iterate VZA**: For each unique VZA value `_vza`:
    a. Calculate the tangent factor: `tan_factor = tan(deg2rad(_vza))`.
    b. Calculate the physical shift: `shift = tan_factor * delta_z`.
    c. Determine the repeat count: `repeat = int(abs(shift) // x.max())`.
    d. Determine the number of repeats: `n_repeat = int(3 + repeat)`.
    e. Create shifted x-coordinates: `x_shift = x + shift`.
    f. Repeat the data slice `da.sel(vza=_vza)` along a new axis `n_repeat` times and concatenate them into `array_concat`.
    g. Create extended x-coordinates for the concatenated array: `x_ext = linspace(0, x.max() * n_repeat, array_concat.shape[0])`.
    h. Create an extended DataArray `extended` with dimensions `x`, `y` and coordinates `x_ext`, `y`.
    i. Interpolate `extended` to the target coordinate `repeat * x.max() + x_shift` to get `od_proj`.
    j. Assign the original `x` coordinates to `od_proj`.
    k. Store `od_proj` in a list `views`.
3. **Concatenate Views**: Concatenate all `views` along the `vza` dimension to form a combined dataset.
4. **Initialize Output**: Create `data_proj` as a zero-filled array with the same shape as `da.data`.
5. **Get Nadir Coordinates**: Extract `x_coord` from `da.sel(vza=0).x`.
6. **Project and Align**: For each index `ivza` and VZA value `vza`:
    a. Select the view: `view = da.sel(vza=vza)`.
    b. Get projection sort index and new grid using `get_projection_sortIndex(vza, cloud_height_avg, x_coord, dx)`. This helper function returns `idx` (sorting indices) and `grid_new` (new grid coordinates).
    c. Calculate projection shift: `proj_shift = min(grid_new)`.
    d. Create a projected DataArray `_data_proj` using `view.data[idx, :]` and coordinates `x = view.x.data + proj_shift`, `y = view.y.data`.
    e. Interpolate `_data_proj` to the original `x_coord` and store the result in `data_proj[:, :, ivza]`.
7. **Return Result**: Return `da` with `data` replaced by `data_proj`.

### Parameters and Typical Values
- `cloud_height_avg`: Average cloud height. Typical values depend on the scene (e.g., 1-10 km for atmospheric clouds).
- `dx`: Spatial resolution. Typical values are in meters (e.g., 280m as seen in the source config).
- `vza`: Viewing Zenith Angle. Typical values range from 0 (nadir) to 60+ degrees.

### Edge Cases and Pitfalls
- **Precision**: Floating-point errors in `linspace` and interpolation can cause misalignment.
- **Boundaries**: The repeat count `n_repeat` must be sufficient to cover the entire shifted footprint. If `n_repeat` is too small, data will be truncated.
- **Degenerate Input**: If `x.max()` is zero, division by zero occurs in `repeat` calculation. Ensure `x` has non-zero extent.
- **Helper Function**: `get_projection_sortIndex` is not fully defined in the source. Implementers must provide a valid implementation that returns sorting indices and the new grid coordinates.

## Operating characteristics
- **Time Complexity**: $O(N \cdot M \cdot V)$, where $N$ is the number of x-points, $M$ is the number of y-points, and $V$ is the number of VZA values. The repeat operation adds a factor of $n\_repeat$, which depends on the VZA and cloud height.
- **Memory Complexity**: $O(N \cdot M \cdot V \cdot n\_repeat)$ during the repeat and concatenation steps. The final output is $O(N \cdot M \cdot V)$.
- **Scaling**: Performance scales linearly with the number of VZA values and the repeat factor. The repeat factor increases with VZA and cloud height.
- **Strengths**: Explicitly handles view-dependent shifts, ensuring accurate projection for non-nadir views.
- **Limitations**: Requires careful handling of the repeat count and helper functions. Memory usage can be high for large scenes with many VZA values.
- **When to Use**: When accurate anisotropic projection is required for non-nadir views, especially in cloud tomography or remote sensing applications.
- **When Not to Use**: For near-nadir views where shift is negligible, or when computational resources are limited.

## Background
COM Repeat Projection is used in the `hybridCT` project for cloud tomography. It is part of the data preprocessing pipeline to generate anisotropic voxel data for tomographic reconstruction. The method is implemented in the `emulator` module of the `hybridCT` repository.
