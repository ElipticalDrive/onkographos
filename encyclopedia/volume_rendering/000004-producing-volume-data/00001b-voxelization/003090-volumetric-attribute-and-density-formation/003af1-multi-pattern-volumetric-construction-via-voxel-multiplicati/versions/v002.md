# Multi-pattern Volumetric Construction via Voxel Multiplication

Also called: Multi-pattern volumetric volume construction via voxel multiplication, Multiplicative voxel encoding, Voxel value determination by pattern intersection

## Overview
This method constructs a 3D volumetric structure that displays multiple distinct 2D patterns when viewed from different projection angles by calculating voxel values as the product of pixel values from those patterns [S1]. It differs from standard voxelization methods that rely on geometric occupancy or density estimation by using multiplicative interference between orthogonal pattern projections to encode information in the third dimension [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** $N$ original 2D patterns (e.g., $A, B, C$), each defined by a pixel grid with color components (Red, Green, Blue). The patterns are associated with specific projection axes (e.g., $z$-axis for pattern $A$, $x$-axis for pattern $B$, $y$-axis for pattern $C$).
*   **Outputs:** A 3D voxel grid where each voxel $V(x,y,z)$ contains a color value determined by the intersection of the patterns.

**Data Structures**
*   **Voxel Grid:** A 3D array indexed by $(x, y, z)$.
*   **Voxel Value:** $V(x,y,z)$ represents the amount of ink at position $(x,y,z)$. For full-color, it comprises three components: $V_R(x,y,z)$, $V_G(x,y,z)$, and $V_B(x,y,z)$ [S1].
*   **Pattern Data:** 2D arrays representing the pixel values of the original patterns. Let $a(u_a, v_a)$, $b(u_b, v_b)$, and $c(u_c, v_c)$ denote the pixel values of patterns $A$, $B$, and $C$ at their respective 2D coordinates [S1].

**Steps**
1.  **Setup Patterns:** Define the orientation of each original pattern. For example, pattern $A$ is projected along the $z$-axis, pattern $B$ along the $x$-axis, and pattern $C$ along the $y$-axis [S1].
2.  **Determine Projection Axes:** For a specific voxel at coordinates $(x,y,z)$, identify the perpendicular projection axes $PA$, $PB$, and $PC$ extending from the voxel to the respective pattern planes [S1].
3.  **Map Coordinates to Pattern Pixels:**
    *   For pattern $A$ (projected along $z$), the voxel $(x,y,z)$ maps to 2D coordinates $(u_a, v_a)$ on the pattern plane. Since the projection is along $z$, $u_a$ and $v_a$ are derived from $x$ and $y$ (or the specific axis orthogonal to the projection direction).
    *   Similarly, map $(x,y,z)$ to $(u_b, v_b)$ for pattern $B$ and $(u_c, v_c)$ for pattern $C$ based on their respective projection axes [S1].
4.  **Calculate Voxel Value:** Compute the voxel value $V(x,y,z)$ as the product of the pixel values from all patterns at their corresponding mapped coordinates [S1]:
    $$ V(x,y,z) = a(u_a, v_a) \cdot b(u_b, v_b) \cdot c(u_c, v_c) $$
    This calculation is performed for each color component (R, G, B) independently [S1].

**Formulas**
The core voxel value determination is:
$$ V(x,y,z) = \prod_{k=1}^{N} P_k(u_k, v_k) $$
where $P_k$ is the pixel value of the $k$-th pattern at the coordinates determined by the projection axis [S1].

The projected pattern value $a'(u_a, v_a)$ observed from the direction of pattern $A$ is the summation of voxel values along the projection axis $PA$:
$$ a'(u_a, v_a) = \sum_{PA} V(x,y,z) $$
Substituting the voxel value formula and noting that $a(u_a, v_a)$ is constant along $PA$:
$$ a'(u_a, v_a) = a(u_a, v_a) \sum_{PA} \left( b(u_b, v_b) \cdot c(u_c, v_c) \right) $$
This shows the projected pattern is the original pattern multiplied by a background noise term (interference from other patterns) [S1].

**Parameters**
*   **Number of Patterns:** The method supports an arbitrary number of patterns, though the example uses three ($A, B, C$) [S1]. There is a trade-off between the number of patterns and image quality [S1].
*   **Voxel Resolution:** Higher resolution in the depth direction minimizes blurring effects [S1].

**Edge Cases and Pitfalls**
*   **Background Noise:** The projected pattern contains interference from other patterns. The original pattern component tends to be dominant when 2D images are used, allowing recognition of the original patterns [S1].
*   **Image Deterioration:** Projected patterns may deteriorate due to contrast degradation (absorption by films) and blurring (diffraction/refraction) in physical implementations [S1].
*   **Noise Suppression:** Background noise can be suppressed by introducing an iteration algorithm or other optimization methods, though this is not part of the basic multiplicative definition [S1].

**Pseudocode**
```python
def compute_voxel_grid(patterns, grid_shape):
    """
    Compute voxel values by multiplying pixel values from orthogonal patterns.
    
    Args:
        patterns: List of 2D arrays (images) representing the original patterns.
                  Each pattern is associated with a projection axis.
                  For 3 patterns A, B, C along Z, X, Y axes respectively:
                  - Pattern A (Z-projection): shape (H, W)
                  - Pattern B (X-projection): shape (H, D)
                  - Pattern C (Y-projection): shape (W, D)
        grid_shape: Tuple (D, H, W) representing the voxel grid dimensions (Depth, Height, Width).
        
    Returns:
        voxel_grid: 3D array of shape (D, H, W) with RGB values.
    """
    D, H, W = grid_shape
    # Initialize voxel grid with zeros
    voxel_grid = np.zeros((D, H, W, 3))
    
    # Assume patterns are provided as RGB images
    # Pattern A is projected along Z-axis (viewed from top/bottom)
    # Pattern B is projected along X-axis (viewed from side)
    # Pattern C is projected along Y-axis (viewed from front/back)
    
    # Note: The exact mapping of 2D pattern coordinates to 3D voxel indices
    # depends on the specific axis alignment. Assuming standard alignment:
    # A corresponds to (x, y) -> pattern index (y, x) or similar
    # B corresponds to (y, z) -> pattern index (y, z)
    # C corresponds to (x, z) -> pattern index (x, z)
    
    # For simplicity, assume patterns are aligned such that:
    # A[y, x] maps to voxel_grid[z, y, x]
    # B[y, z] maps to voxel_grid[z, y, x]
    # C[x, z] maps to voxel_grid[z, y, x]
    
    # Retrieve pattern arrays
    # A: (H, W, 3)
    # B: (H, D, 3)
    # C: (W, D, 3)
    
    A = patterns[0]
    B = patterns[1]
    C = patterns[2]
    
    for z in range(D):
        for y in range(H):
            for x in range(W):
                # Get pixel values from each pattern at the projected coordinates
                # Pattern A (Z-projection): uses x, y
                pixel_a = A[y, x]
                
                # Pattern B (X-projection): uses y, z
                pixel_b = B[y, z]
                
                # Pattern C (Y-projection): uses x, z
                pixel_c = C[x, z]
                
                # Multiply pixel values
                # Element-wise multiplication for RGB components
                voxel_value = pixel_a * pixel_b * pixel_c
                
                voxel_grid[z, y, x] = voxel_value
                
    return voxel_grid
```

## Operating characteristics
*   **Time Complexity:** $O(D \cdot H \cdot W \cdot N)$, where $D, H, W$ are grid dimensions and $N$ is the number of patterns. Each voxel requires $N$ lookups and multiplications.
*   **Memory Complexity:** $O(D \cdot H \cdot W)$ for the voxel grid, plus $O(N \cdot H \cdot W)$ for storing the input patterns.
*   **Strengths:** Allows encoding of multiple distinct 2D images into a single 3D volume without complex geometric calculations. Simple to implement.
*   **Limitations:** Background noise from pattern interference. Image quality degrades with the number of patterns. Physical implementation suffers from contrast loss and blurring.
*   **When to use:** When the goal is to display multiple 2D patterns from different viewpoints in a volumetric display.
*   **When not to use:** When high-fidelity geometric representation or accurate density estimation is required.

## Background
This method was proposed for inkjet printing-based volumetric displays to project multiple full-colour 2D patterns [S1]. It is based on a previous study [13] and extended to full-colour representation [S1]. The method was experimentally validated, though physical results showed deterioration compared to simulations due to film absorption and blurring [S1].
