# Multi-pattern Volumetric Construction via Voxel Multiplication

Also called: Multi-pattern volumetric volume construction via voxel multiplication, Multiplicative voxel encoding, Voxel value determination by pattern intersection

## Overview
This method constructs a 3D volumetric structure that exhibits multiple distinct 2D patterns when viewed from specific projection axes by calculating voxel values as the product of pixel values from those patterns [S1]. It differs from standard occupancy or density-based voxelization by encoding spatial information through multiplicative interference, where the presence of a pattern at a specific coordinate is determined by the simultaneous alignment of features from all input patterns [S1]. Unlike [Interior Voxelize](995-interior-voxelize.md) which fills volume based on geometric containment, or [Shell-based Voxelization](1748-shell-based-voxelization.md) which focuses on surface boundaries, this method creates a "holographic" volume where the visual output is a superposition of the original 2D inputs, modulated by background noise from the other patterns [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** $N$ 2D patterns (images), where $N \ge 1$. Each pattern $P_i$ is defined on a 2D grid with pixel values. The example uses $N=3$ (Patterns A, B, C) for full-color representation, but the method supports an arbitrary number [S1].
*   **Outputs:** A 3D voxel grid $V(x,y,z)$, where each voxel contains a value representing the "amount of ink" or intensity. For full-color, $V(x,y,z)$ comprises three components: $V_R(x,y,z)$, $V_G(x,y,z)$, and $V_B(x,y,z)$ [S1].

**Data Structures:**
*   **Voxel Grid:** A 3D array indexed by $(x,y,z)$. The size is determined by the resolution required to display the patterns and the depth range of the 3D structure [S1].
*   **Pattern Data:** 2D arrays for each pattern $A, B, C, \dots$. Each element represents a pixel value (e.g., RGB vector) [S1].

**Algorithm Steps:**
1.  **Pattern Setup:** Define the orientation and position of each original 2D pattern in 3D space. Each pattern is associated with a specific projection axis (e.g., Pattern A is projected along axis $PA$, Pattern B along $PB$, etc.) [S1].
2.  **Projection Axis Definition:** For each voxel at coordinate $(x,y,z)$, define the projection axes $PA, PB, PC, \dots$ perpendicular to the respective patterns $A, B, C, \dots$ [S1].
3.  **Intersection Mapping:** Determine the intersection points of each projection axis with its corresponding 2D pattern. Let $a(u_a, v_a)$ be the pixel value of Pattern A at the intersection with axis $PA$, $b(u_b, v_b)$ for Pattern B, and $c(u_c, v_c)$ for Pattern C [S1].
4.  **Voxel Value Calculation:** Compute the voxel value $V(x,y,z)$ as the product of the pixel values at these intersections [S1]:
    $$ V(x,y,z) = a(u_a, v_a) \cdot b(u_b, v_b) \cdot c(u_c, v_c) $$
    For full-color, this is applied component-wise for Red, Green, and Blue [S1].
5.  **Iteration (Optional):** To suppress background noise, an iteration algorithm or optimization method can be applied, though this is not part of the basic definition [S1].

**Formulas:**
The core definition of the voxel value is:
$$ V(x,y,z) = \prod_{i=1}^{N} P_i(u_i, v_i) $$
where $P_i(u_i, v_i)$ is the pixel value of the $i$-th pattern at the intersection of the voxel's projection axis with the pattern [S1].

The projected pattern $A'$ observed from the direction of axis $PA$ is the summation of voxel values along that axis:
$$ a'(u_a, v_a) = \sum_{PA} V(x,y,z) $$
Substituting the voxel definition, and noting that $a(u_a, v_a)$ is constant along $PA$:
$$ a'(u_a, v_a) = a(u_a, v_a) \sum_{PA} \left( b(u_b, v_b) \cdot c(u_c, v_c) \right) $$
This shows the projected pattern is the original pattern multiplied by a background noise term (interference from other patterns) [S1].

**Parameters:**
*   **Number of Patterns ($N$):** The example uses 3. There is a trade-off between the number of patterns and image quality; more patterns increase complexity and noise [S1].
*   **Voxel Resolution:** Higher resolution in the depth direction minimizes blurring effects [S1].

**Edge Cases and Pitfalls:**
*   **Background Noise:** The projected pattern contains interference from other patterns. The original pattern component tends to be dominant when 2D images are used, allowing recognition, but noise is always present [S1].
*   **Image Deterioration:** In physical implementations, projected patterns deteriorate due to contrast degradation (absorption by films) and blurring (diffraction/refraction) [S1].
*   **Contrast Degradation:** Caused by absorption of emitted light by the films/materials. Using highly transparent materials can decrease this effect [S1].
*   **Blurring:** Minimized by increasing display resolution in the depth direction [S1].

**Pseudocode:**
```python
def multi_pattern_voxel_construction(patterns, grid_shape):
    """
    Construct a 3D voxel grid by multiplying pixel values from multiple 2D patterns.
    
    Args:
        patterns: List of 2D numpy arrays representing the input patterns.
                  Each array has shape (H, W) or (H, W, 3) for RGB.
        grid_shape: Tuple (D, H, W) representing the dimensions of the output voxel grid.
                    D is depth, H is height, W is width.
    
    Returns:
        voxel_grid: 3D numpy array of shape (D, H, W, C) where C is the number of color channels.
    """
    num_patterns = len(patterns)
    # Initialize voxel grid with zeros
    # Assuming RGB output, shape (D, H, W, 3)
    voxel_grid = np.zeros((grid_shape[0], grid_shape[1], grid_shape[2], 3))
    
    # Determine the projection axis for each pattern.
    # In the basic model, each pattern is projected along a specific axis.
    # For simplicity, assume Pattern i is projected along axis i.
    # The intersection point for a voxel (d, h, w) with Pattern i depends on the axis.
    # If Pattern A is projected along Z (depth), then for voxel (z, y, x),
    # the intersection with Pattern A is at (y, x) in Pattern A's 2D grid.
    
    # Note: The exact mapping of 3D coordinates to 2D pattern coordinates depends on the
    # specific orientation of the patterns. The general case assumes that for each pattern P_i,
    # there is a mapping function map_i(d, h, w) -> (u_i, v_i).
    # For the standard case where patterns are orthogonal slices:
    
    for d in range(grid_shape[0]):
        for h in range(grid_shape[1]):
            for w in range(grid_shape[2]):
                # Initialize voxel value for this position
                voxel_value = np.ones(3) # Start with identity for multiplication
                
                for i, pattern in enumerate(patterns):
                    # Determine the 2D coordinates (u, v) in pattern i corresponding to voxel (d, h, w)
                    # This step requires knowledge of the pattern's orientation.
                    # Assuming a simple case where Pattern 0 is XY plane (projected along Z),
                    # Pattern 1 is YZ plane (projected along X), etc.
                    # This is a simplification; the general case uses perpendicular lines PA, PB, PC.
                    
                    if i == 0:
                        # Pattern A projected along Z. Intersection at (h, w) in Pattern A.
                        u, v = h, w
                    elif i == 1:
                        # Pattern B projected along X. Intersection at (d, w) in Pattern B.
                        u, v = d, w
                    elif i == 2:
                        # Pattern C projected along Y. Intersection at (d, h) in Pattern C.
                        u, v = d, h
                    else:
                        # For N > 3, the mapping must be defined.
                        # Not given in the sources for N > 3. [G]
                        continue
                    
                    # Get pixel value from the pattern
                    # Handle boundary checks
                    if 0 <= u < pattern.shape[0] and 0 <= v < pattern.shape[1]:
                        pixel_val = pattern[u, v]
                        # Multiply voxel value by pixel value
                        voxel_value = voxel_value * pixel_val
                    else:
                        # If intersection is outside pattern bounds, value is 0?
                        # Not specified. Assume 0 for out-of-bounds. [G]
                        voxel_value = np.zeros(3)
                        break
                
                voxel_grid[d, h, w] = voxel_value
                
    return voxel_grid
```

## Operating characteristics
*   **Time Complexity:** $O(D \cdot H \cdot W \cdot N)$, where $D, H, W$ are the dimensions of the voxel grid and $N$ is the number of patterns. Each voxel requires $N$ lookups and multiplications [S1].
*   **Memory Complexity:** $O(D \cdot H \cdot W \cdot C)$ for the output voxel grid, where $C$ is the number of color channels (e.g., 3 for RGB) [S1].
*   **Performance:** The method is computationally straightforward but generates significant background noise. The quality of the projected patterns depends heavily on the contrast and resolution of the input patterns and the display medium [S1].
*   **Strengths:** Allows the creation of 3D structures that display multiple distinct 2D images from different viewpoints. Simple to implement [S1].
*   **Limitations:** Background noise from other patterns reduces image clarity. Physical implementations suffer from contrast degradation and blurring. The trade-off between the number of patterns and image quality limits the practical number of patterns [S1].
*   **When to use:** When the goal is to create a volumetric display that shows specific 2D patterns from specific angles, and high fidelity is not the primary concern, or when combined with noise suppression algorithms [S1].
*   **When not to use:** When high-contrast, noise-free volumetric rendering is required, or when the scene contains complex 3D geometry rather than flat 2D patterns [S1].

## Background
The method was introduced in the context of inkjet printing-based volumetric displays [S1]. It extends a previous study [13] to support full-color representation and an arbitrary number of patterns [S1]. The core idea is based on the principle that the projected pattern is the original pattern multiplied by background noise, which allows the original pattern to be recognized if it is dominant [S1]. The method has been experimentally validated with fabricated devices, though physical limitations such as film absorption and diffraction were observed [S1].
