# Multi-pattern Volumetric Construction via Voxel Multiplication

Also called: Multi-pattern volumetric volume construction via voxel multiplication, Multiplicative voxel encoding, Voxel value determination by pattern intersection

## Overview
This method constructs a 3D volumetric representation by determining voxel values as the element-wise product of pixel values from multiple 2D source patterns projected along their respective axes [S1]. It solves the problem of encoding distinct 2D cross-sectional images into a single 3D volume such that each original pattern remains recognizable when the volume is projected back along its respective axis [S1]. It differs from additive voxelization methods (e.g., [Interior Voxelize](995-interior-voxelize.md)) by using multiplication, which causes the projected pattern to be the original pattern multiplied by background noise from interference of other patterns [S1].

## How it works
**Inputs:**
*   $N$ original 2D patterns (images), denoted $P_1, P_2, \dots, P_N$ [S1].
*   For each pattern $P_i$, an orientation (projection axis) and a spatial position (plane) in 3D space [S1].
*   A 3D voxel grid with resolution $(N_x, N_y, N_z)$ and bounding box [G].
*   Each pixel in pattern $P_i$ has values for $C$ color components (e.g., $C=3$ for RGB) [S1].

**Outputs:**
*   A 3D voxel array $V$ of shape $(N_x, N_y, N_z)$ with $C$ components per voxel [S1]. $V(x,y,z)$ represents the amount of ink at position $(x,y,z)$ [S1].

**Data Structures:**
*   **Pattern Array:** A list of 2D arrays [G]. Pattern $i$ has dimensions $H_i \times W_i$ [G].
*   **Voxel Grid:** A 3D array `voxels[N_x][N_y][N_z][C]` [G].

**Parameters:**
*   Number of patterns $N$. The source example uses $N=3$ [S1]. The algorithm supports arbitrary $N$, with a trade-off between pattern count and image quality [S1].
*   Color channels $C$ (typically 3 for RGB) [S1].

**Steps:**
1.  **Initialize Grid:** Create a 3D array $V$ of size $(N_x, N_y, N_z)$ with $C$ channels, initialized to $0$ [G].
2.  **Map Patterns to Axes:** For each pattern $P_i$ ($i=1 \dots N$): identify its projection axis direction and the plane coordinates perpendicular to the axis where the pattern is placed [S1].
3.  **Compute Voxel Values:** Iterate through every voxel coordinate $(x, y, z)$ in the grid:
    *   For each pattern $P_i$: determine the projection axis for $P_i$ [S1].
    *   Find the intersection point of the perpendicular line from $(x, y, z)$ to the plane of $P_i$ [S1]. Let the 2D coordinates of this intersection on pattern $P_i$ be $(u_i, v_i)$ [S1].
    *   Retrieve the pixel value $p_i(u_i, v_i)$ from pattern $P_i$ [S1]. This is a vector of $C$ components.
    *   Calculate the voxel value $V(x,y,z)$ as the element-wise product of the pixel values from all $N$ patterns.
    *   Store $V(x,y,z)$ in the grid.
4.  **Output:** Return the voxel grid $V$.

**Formulas:**
The voxel value $V(x,y,z)$ is calculated as the product of the pixel values of the original patterns at the intersections of the projection axes with the patterns [S1]:
$$ V(x,y,z) = a(u_a, v_a) \cdot b(u_b, v_b) \cdot c(u_c, v_c) $$
where $a(u_a, v_a)$, $b(u_b, v_b)$, and $c(u_c, v_c)$ are the pixel values of patterns A, B, and C at the intersections [S1]. For full-colour representation, each voxel value comprises three colour components: $V_R(x,y,z)$, $V_G(x,y,z)$, and $V_B(x,y,z)$ [S1].

The projected pattern pixel value $a'(u_a, v_a)$ is the summation of voxel values along the projection axis $P_A$ [S1]:
$$ a'(u_a, v_a) = \sum_{P_A} V(x,y,z) $$
Substituting the voxel formula and noting that $a(u_a, v_a)$ is constant along $P_A$, the projected pattern is [S1]:
$$ a'(u_a, v_a) = a(u_a, v_a) \sum_{P_A} b(u_b, v_b) \cdot c(u_c, v_c) $$

**Pseudocode:**
```python
def multi_pattern_voxel_multiplication(patterns, grid_shape, pattern_axes):
    Nx, Ny, Nz = grid_shape
    C = len(patterns[0][0])
    voxels = [[[ [0.0] * C for _ in range(Nz) ] for _ in range(Ny) ] for _ in range(Nx)]
    N = len(patterns)
    for x in range(Nx):
        for y in range(Ny):
            for z in range(Nz):
                voxel_val = [1.0] * C
                for i in range(N):
                    pattern = patterns[i]
                    axis = pattern_axes[i]
                    if axis == 0:
                        u, v = y, z
                    elif axis == 1:
                        u, v = x, z
                    elif axis == 2:
                        u, v = x, y
                    else:
                        raise ValueError("Axis must be 0, 1, or 2")
                    if 0 <= u < len(pattern[0]) and 0 <= v < len(pattern):
                        pixel_val = pattern[v][u]
                        for c in range(C):
                            voxel_val[c] *= pixel_val[c]
                    else:
                        voxel_val = [0.0] * C
                        break
                voxels[x][y][z] = voxel_val
    return voxels
```

**Edge Cases and Pitfalls:**
*   **Background Noise:** The projected pattern $a'(u_a, v_a)$ is the sum of voxel values along the projection axis [S1]. Substituting the voxel formula, $a'(u_a, v_a) = a(u_a, v_a) \sum_{P_A} b(u_b, v_b) \cdot c(u_c, v_c)$ [S1]. The term $\sum b \cdot c$ acts as background noise (interference from other patterns) [S1].
*   **Dominance:** The original pattern component tends to be dominant when 2D images are used, allowing recognition [S1].
*   **Image Deterioration:** In physical implementations, contrast degrades due to absorption by films, and blurring occurs due to diffraction/refraction [S1].
*   **Noise Suppression:** Background noise can be suppressed by iteration algorithms or optimization methods, though not part of the basic construction [S1].

## Operating characteristics
*   **Time Complexity:** $O(N_x N_y N_z \cdot N)$, where $N$ is the number of patterns [G]. Each voxel requires $N$ lookups and multiplications [G].
*   **Memory Complexity:** $O(N_x N_y N_z \cdot C)$ for the voxel grid [G].
*   **Strengths:** Simple construction; allows encoding of multiple distinct 2D views into one volume; multiplicative nature can suppress "empty" space if patterns are sparse (values near 0) [G].
*   **Limitations:** Background noise from overlapping patterns; sensitivity to pattern alignment; potential for very low voxel values (darkness) if many patterns are multiplied [G].
*   **When to use:** When the goal is to store multiple 2D cross-sections in a single 3D volume for projection-based display or reconstruction [S1].
*   **When not to use:** When high-fidelity 3D geometry is required without cross-talk between views; when additive blending is preferred [G].

## Background
The method was proposed for inkjet printing-based volumetric displays that project multiple full-colour 2D patterns [S1]. It extends a previous study to support full-colour representation and an arbitrary number of patterns [S1]. The core idea is that the projected image of the 3D structure will resemble the original 2D patterns because the original pattern component dominates the background noise in the projection sum [S1].
