# Textured Mesh to Volumetric Attribute Voxelization
## Overview
This method samples texture maps and material properties from a textured 3D mesh into a discrete voxel grid to produce volumetric attributes such as base color, metallic, and roughness [S1, unofficial]. It maps continuous surface appearance data to a volumetric representation by computing mesh-voxel intersections and sorting the resulting indices to align attribute tensors [S1, unofficial].

## How it works
**Inputs:**
- `asset`: A mesh object containing vertices, faces, and associated texture maps or material properties [S1, unofficial].
- `grid_size`: The resolution of the output voxel grid, specified as an integer (cubical) or a list/tuple/array of three integers $(N_x, N_y, N_z)$ [S1, unofficial].
- `aabb`: The Axis-Aligned Bounding Box defining the spatial extent of the voxelization, specified as two 3D vectors $[min_x, min_y, min_z]$ and $[max_x, max_y, max_z]$ [S1, unofficial].

**Outputs:**
- `voxel_indices_mat`: A tensor or array of voxel indices corresponding to occupied voxels [S1, unofficial].
- `attributes`: A dictionary mapping attribute names to tensors or arrays. Common keys include `'base_color'`, `'metallic'`, and `'roughness'` [S1, unofficial].

**Data Structures:**
- The output attributes are aligned with `voxel_indices_mat` via a computed sequence ID [S1, unofficial].
- For proximity-based variants, the color array layout is shape $(X, Y, Z, 4)$, where $X, Y, Z$ are the grid dimensions and 4 represents RGBA components [S2, unofficial].

**Steps:**
1.  **Normalize and Prepare Mesh Data**:
    -   Ensure `voxel_size` is a 1D tensor of length 3 on the CPU to avoid implicit CUDA synchronization [S1, unofficial].
    -   Compute `grid_size` from `aabb` and `voxel_size` if not explicitly provided:
        $$ grid\_size = \text{round}\left(\frac{aabb[1] - aabb[0]}{voxel\_size}\right) $$
        [S1, unofficial].
    -   Translate mesh vertices relative to the AABB origin:
        $$ vertices_{local} = vertices - aabb[0] $$
        [S1, unofficial].
    -   Construct triangles from local vertices and face indices [S1, unofficial].

2.  **Compute Occupancy and Initial Indices**:
    -   Perform mesh-voxel intersection to determine occupied voxels [S1, unofficial].
    -   Generate `voxel_indices_mat` containing the indices of all occupied voxels [S1, unofficial].

3.  **Serialize and Sort for Alignment**:
    -   To ensure strict alignment between occupancy masks and attribute data, serialize the voxel indices into a sequence ID:
        $$ vid\_mat = \text{serialize.encode\_seq}(voxel\_indices\_mat) $$
        [S1, unofficial].
    -   Compute the sorting permutation that orders these sequence IDs:
        $$ mapping\_mat = \text{argsort}(vid\_mat) $$
        [S1, unofficial].

4.  **Map Attributes**:
    -   Extract attributes (e.g., base color, metallic, roughness) for each occupied voxel [S1, unofficial].
    -   Apply the sorting mapping to all attribute tensors to match the sorted `voxel_indices_mat`:
        $$ attributes = \{ k : v[mapping\_mat] \text{ for } k, v \text{ in attributes.items()} \} $$
        [S1, unofficial].

5.  **Output**:
    -   Return `voxel_indices_mat` and the sorted `attributes` dictionary [S1, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np

def serialize_encode_seq(indices, grid_size):
    """Linearizes 3D voxel indices into a 1D sequence ID for sorting alignment [G]."""
    # Standard linearization: i * (Ny * Nz) + j * Nz + k
    return indices[:, 0] * (grid_size[1] * grid_size[2]) + indices[:, 1] * grid_size[2] + indices[:, 2]

def intersect_occ(triangles, voxel_size, grid_size):
    """Computes occupied voxel indices by intersecting triangles with the voxel grid [S1, unofficial]."""
    # The source implementation calls a C++ extension _C.intersect_occ_cuda/_cpu [S1, unofficial].
    # Returns a tensor of shape (N, 3) containing [i, j, k] for each occupied voxel.
    return torch.zeros((0, 3), dtype=torch.int64)

def extract_attributes(mesh, indices):
    """Extracts material attributes (base_color, metallic, roughness) aligned with raw indices [S1, unofficial]."""
    # Returns a dict of tensors matching the length of indices
    return {
        "base_color": torch.zeros((len(indices), 3)),
        "metallic": torch.zeros(len(indices)),
        "roughness": torch.zeros(len(indices))
    }

def textured_mesh_to_volumetric_attr(mesh, grid_size, aabb, voxel_size):
    # 1. Prepare inputs
    voxel_size_cpu = voxel_size.to(dtype=torch.float32).contiguous()
    assert voxel_size_cpu.dim() == 1 and voxel_size_cpu.size(0) == 3

    if grid_size is None:
        aabb_cpu = aabb.detach()
        grid_size_cpu = ((aabb_cpu[1] - aabb_cpu[0]) / voxel_size_cpu).round().to(dtype=torch.int32)
        grid_size = grid_size_cpu
    else:
        if isinstance(grid_size, int):
            grid_size = [grid_size, grid_size, grid_size]
        grid_size_cpu = torch.tensor(grid_size, dtype=torch.int32)
        grid_size = grid_size_cpu

    # 2. Transform mesh vertices
    vertices = mesh.vertices - aabb[0].reshape(1, 3)
    triangles = vertices[mesh.faces.to(dtype=torch.long)]

    # 3. Compute occupancy
    voxel_indices_mat = intersect_occ(triangles, voxel_size_cpu, grid_size)

    # 4. Serialize and Sort
    vid_mat = serialize_encode_seq(voxel_indices_mat, grid_size)
    mapping_mat = torch.argsort(vid_mat)

    # 5. Extract and Map Attributes
    raw_attributes = extract_attributes(mesh, voxel_indices_mat)
    sorted_attributes = {k: v[mapping_mat] for k, v in raw_attributes.items()}

    return voxel_indices_mat, sorted_attributes
```

**Edge Cases and Pitfalls:**
-   **Non-Watertight Meshes**: If the input mesh is not perfectly watertight (e.g., due to Structure from Motion reconstruction artifacts), the voxelized mesh may exhibit holes [S2, unofficial].
-   **Precision**: `voxel_size` metadata must be on CPU to avoid implicit CUDA synchronization; pass Python values or ensure CPU placement [S1, unofficial].
-   **Alignment**: Failure to sort `voxel_indices_mat` and apply the same permutation to attributes will result in misaligned data [S1, unofficial].

## Subtopics

### Trimesh Mesh Voxelization & Texture Color Mapping
This variant voxelizes the mesh into a hollow grid and maps vertex texture colors to voxels using proximity queries [S2, unofficial]. It computes distances between mesh vertices and voxel points, finds the closest vertex for each voxel, and maps its color to an array of shape $(X, Y, Z, 4)$ [S2, unofficial]. Pitfalls include holes in the voxelized mesh if the input mesh is not perfectly watertight, often due to Structure from Motion reconstruction artifacts [S2, unofficial].
