# CPU Solid Voxelization

Also called: CPU Triangle Voxelization (Y-Z Plane Sweep), Solid Voxelization

## Overview
CPU Solid Voxelization is a deterministic, CPU-based algorithm that fills the interior of a triangle mesh into a voxel grid by projecting triangles onto the Y-Z plane and sweeping along the X-axis [S1, unofficial]. It determines which voxels are inside the mesh by testing voxel centers against the projected 2D triangle and calculating the maximum X-intersection, then filling all voxels from the origin up to that intersection [S1, unofficial]. Unlike [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) which uses probabilistic sampling, or [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) which casts rays per voxel, this method uses exact geometric projection and edge traversal logic derived from the Schwarz-Seidel approach [S1, unofficial]. It differs from [Front/Back Face Flagging](1506-front-back-face-flagging.md) by explicitly computing the X-extent of the surface intersection rather than relying on normal orientation flags alone [S1, unofficial].

## How it works
**Inputs:**
- A mesh defined by a list of triangles, each with three 3D vertices $(v_0, v_1, v_2)$.
- A voxel grid defined by:
  - `gridsize`: A 3D vector $(G_x, G_y, G_z)$ representing the number of voxels in X, Y, and Z dimensions.
  - `unit`: A 3D vector $(u_x, u_y, u_z)$ representing the physical size of a single voxel in X, Y, and Z dimensions.
  - `origin`: The 3D world coordinate of the grid's minimum corner (implied by the coordinate transformation logic).
- `morton_order`: A boolean flag determining if the output voxel table uses Morton code indexing or linear indexing.
- `voxel_table`: An array of `unsigned int` acting as a bitfield.

**Outputs:**
- `voxel_table`: The bitfield is modified such that bits corresponding to interior voxels are set (or flipped, depending on the specific implementation variant cited) [S1, unofficial].

**Data Structures:**
- `voxel_table`: `unsigned int*` array. The size is sufficient to hold $G_x \times G_y \times G_z$ bits.
- Indexing:
  - Linear: $idx = x + y \cdot G_y + z \cdot G_y \cdot G_z$ [S1, unofficial].
  - Morton: $idx = \text{mortonEncode\_LUT}(x, y, z)$ [S1, unofficial].
- Bit manipulation:
  - `setBit`: Sets a specific bit to 1.
  - `setBitXor`: Flips a bit using XOR. $idx_{int} = idx / 32$, $bit\_pos = 31 - (idx \% 32)$, $mask = 1 \ll bit\_pos$, $voxel\_table[idx_{int}] \ ^= \ mask$ [S1, unofficial].

**Parameters:**
- `float_error`: Epsilon value for floating-point comparisons, typically $10^{-6}$ [S1, unofficial].

**Algorithm Steps:**

1. **Preprocessing:**
   - For each triangle in the mesh:
     - Compute edge vectors: $e_0 = v_1 - v_0$, $e_1 = v_2 - v_1$, $e_2 = v_0 - v_2$ [S1, unofficial].
     - Compute the triangle normal: $n = \text{normalize}(\text{cross}(e_0, e_1))$ [S1, unofficial].
     - **Pitfall Check:** If $|n.x| < \text{float\_error}$, skip the triangle. This prevents division by zero or numerical instability when calculating the X-coordinate intersection, as the triangle is nearly perpendicular to the X-axis (parallel to the YZ projection plane) [S1, unofficial].

2. **Projection and Winding:**
   - Project vertices to the Y-Z plane: $v_{0\_yz} = (v_0.y, v_0.z)$, $v_{1\_yz} = (v_1.y, v_1.z)$, $v_{2\_yz} = (v_2.y, v_2.z)$ [S1, unofficial].
   - Ensure Counter-Clockwise (CCW) winding in the Y-Z plane:
     - Compute cross product of edges in 2D: $result = (v_{1\_yz}.x - v_{0\_yz}.x)(v_{2\_yz}.y - v_{0\_yz}.y) - (v_{2\_yz}.x - v_{0\_yz}.x)(v_{1\_yz}.y - v_{0\_yz}.y)$ [S1, unofficial].
     - If $result \le 0$, swap $v_{1\_yz}$ and $v_{2\_yz}$ to enforce CCW winding [S1, unofficial].

3. **Bounding Box Calculation:**
   - Compute the 2D bounding box of the projected triangle in world coordinates:
     - $bbox\_min.yz = \min(v_{0\_yz}, v_{1\_yz}, v_{2\_yz})$
     - $bbox\_max.yz = \max(v_{0\_yz}, v_{1\_yz}, v_{2\_yz})$ [S1, unofficial].
   - Convert to grid indices:
     - $bbox\_min\_grid.y = \lceil \frac{bbox\_min.y}{u_y} - 0.5 \rceil$
     - $bbox\_min\_grid.z = \lceil \frac{bbox\_min.z}{u_z} - 0.5 \rceil$
     - $bbox\_max\_grid.y = \lfloor \frac{bbox\_max.y}{u_y} - 0.5 \rfloor$
     - $bbox\_max\_grid.z = \lfloor \frac{bbox\_max.z}{u_z} - 0.5 \rfloor$ [S1, unofficial].
   - Clamp grid indices to the valid range $[0, G_y-1]$ and $[0, G_z-1]$ [G].

4. **Sweep and Fill:**
   - Iterate $y$ from $bbox\_min\_grid.y$ to $bbox\_max\_grid.y$.
   - Iterate $z$ from $bbox\_min\_grid.z$ to $bbox\_max\_grid.z$.
   - For each $(y, z)$ pair:
     - Calculate the voxel center in world coordinates:
       - $point.y = (y + 0.5) \cdot u_y$
       - $point.z = (z + 0.5) \cdot u_z$ [S1, unofficial].
     - **Point-in-Triangle Test:**
       - Test if $(point.y, point.z)$ is inside the projected triangle $v_{0\_yz}, v_{1\_yz}, v_{2\_yz}$.
       - Let $checknum$ be the result indicator (1 if inside edge 0-1, 2 if inside edge 1-2, 3 if inside edge 2-0, 0 if outside, or similar logic based on barycentric/cross-product signs) [S1, unofficial].
       - **Edge Case Handling:** The voxel is considered for filling if:
         - $(checknum == 1 \land \text{TopLeftEdge}(v_{0\_yz}, v_{1\_yz})) \lor$
         - $(checknum == 2 \land \text{TopLeftEdge}(v_{1\_yz}, v_{2\_yz})) \lor$
         - $(checknum == 3 \land \text{TopLeftEdge}(v_{2\_yz}, v_{0\_yz})) \lor$
         - $(checknum == 0)$ [S1, unofficial].
         - Note: The condition `checknum == 0` implies filling even if the center is strictly outside, likely to handle boundary cases or specific solid filling rules where the sweep line intersects the triangle [S1, unofficial].
     - **X-Intersection Calculation:**
       - If the point passes the test, calculate the maximum X grid index intersected by the triangle plane at this $(y, z)$:
         - $x_{coord} = \text{get\_x\_coordinate}(n, v_0, point)$ [S1, unofficial].
         - This function solves the plane equation $n \cdot (P - v_0) = 0$ for $P.x$ given $P.y = point.y$ and $P.z = point.z$.
         - $x_{grid} = \lfloor \frac{x_{coord}}{u_x} - 0.5 \rfloor$ [S1, unofficial].
     - **Fill Voxels:**
       - Iterate $x$ from $0$ to $x_{grid}$ (inclusive) [S1, unofficial].
       - For each $x$, calculate the linear or Morton index.
       - Set the bit in `voxel_table` using `setBit` (or `setBitXor` if the implementation uses XOR for solid filling to handle overlapping triangles) [S1, unofficial].

**Pseudocode:**

```python
def cpu_solid_voxelization(mesh_triangles, gridsize, unit, morton_order, voxel_table):
    float_error = 0.000001
    
    for v0, v1, v2 in mesh_triangles:
        # 1. Compute Normal
        e0 = v1 - v0
        e1 = v2 - v1
        n = normalize(cross(e0, e1))
        
        # Pitfall: Skip if normal is nearly perpendicular to X
        if abs(n.x) < float_error:
            continue
            
        # 2. Project to YZ and Ensure CCW
        v0_yz = (v0.y, v0.z)
        v1_yz = (v1.y, v1.z)
        v2_yz = (v2.y, v2.z)
        
        if not check_ccw(v0_yz, v1_yz, v2_yz):
            v1_yz, v2_yz = v2_yz, v1_yz
            
        # 3. Bounding Box in Grid Coordinates
        min_yz = min(v0_yz, v1_yz, v2_yz)
        max_yz = max(v0_yz, v1_yz, v2_yz)
        
        bbox_min_grid_y = ceil(min_yz[0] / unit.y - 0.5)
        bbox_min_grid_z = ceil(min_yz[1] / unit.z - 0.5)
        bbox_max_grid_y = floor(max_yz[0] / unit.y - 0.5)
        bbox_max_grid_z = floor(max_yz[1] / unit.z - 0.5)
        
        # Clamp to grid bounds
        bbox_min_grid_y = max(0, min(bbox_min_grid_y, gridsize.y - 1))
        bbox_max_grid_y = max(0, min(bbox_max_grid_y, gridsize.y - 1))
        bbox_min_grid_z = max(0, min(bbox_min_grid_z, gridsize.z - 1))
        bbox_max_grid_z = max(0, min(bbox_max_grid_z, gridsize.z - 1))
        
        # 4. Sweep YZ
        for y in range(bbox_min_grid_y, bbox_max_grid_y + 1):
            for z in range(bbox_min_grid_z, bbox_max_grid_z + 1):
                # Voxel center in world coords
                point_y = (y + 0.5) * unit.y
                point_z = (z + 0.5) * unit.z
                point_pz = (point_y, point_z)
                
                # Point-in-Triangle Test
                checknum = check_point_triangle(v0_yz, v1_yz, v2_yz, point_pz)
                
                # Edge handling logic
                fill = False
                if checknum == 1 and top_left_edge(v0_yz, v1_yz):
                    fill = True
                elif checknum == 2 and top_left_edge(v1_yz, v2_yz):
                    fill = True
                elif checknum == 3 and top_left_edge(v2_yz, v0_yz):
                    fill = True
                elif checknum == 0:
                    fill = True
                    
                if fill:
                    # Calculate X intersection
                    # Plane equation: n.x * x + n.y * y + n.z * z = d
                    # d = dot(n, v0)
                    # x = (d - n.y * y - n.z * z) / n.x
                    d = dot(n, v0)
                    x_coord = (d - n.y * point_y - n.z * point_z) / n.x
                    
                    x_grid = floor(x_coord / unit.x - 0.5)
                    
                    # Fill from 0 to x_grid
                    # Note: In some implementations, x might start from 0 or the mesh min.
                    # The source iterates x from 0 to xmax.
                    for x in range(0, x_grid + 1):
                        if morton_order:
                            idx = morton_encode(x, y, z)
                        else:
                            idx = x + y * gridsize.y + z * gridsize.y * gridsize.z
                            
                        set_bit_xor(voxel_table, idx)

def check_ccw(v0, v1, v2):
    e0 = (v1[0] - v0[0], v1[1] - v0[1])
    e1 = (v2[0] - v0[0], v2[1] - v0[1])
    cross_z = e0[0] * e1[1] - e1[0] * e0[1]
    return cross_z > 0

def top_left_edge(v0, v1):
    return (v1[1] < v0[1]) or (v1[1] == v0[1] and v0[0] > v1[0])

def check_point_triangle(v0, v1, v2, p):
    # Returns 1, 2, 3 if inside specific edge regions, 0 if outside
    # Simplified logic based on source description:
    # This function likely uses barycentric coordinates or cross products
    # to determine which "wedge" the point falls into.
    # For implementation, standard barycentric test is sufficient for "inside".
    # The source uses specific return codes for edge cases.
    # We implement a standard inside test for the core logic, 
    # noting the source's specific edge flags.
    
    # Cross products of edges with point
    c1 = cross2d(v1 - v0, p - v0)
    c2 = cross2d(v2 - v1, p - v1)
    c3 = cross2d(v0 - v2, p - v2)
    
    # Assuming CCW winding, inside if all cross products are >= 0
    if c1 >= 0 and c2 >= 0 and c3 >= 0:
        # Determine which edge is "active" or closest for the specific flag logic
        # This part is heuristic based on source's checknum usage
        if c1 <= c2 and c1 <= c3: return 1
        if c2 <= c1 and c2 <= c3: return 2
        if c3 <= c1 and c3 <= c2: return 3
    return 0

def cross2d(a, b):
    return a[0] * b[1] - a[1] * b[0]

def set_bit_xor(voxel_table, index):
    int_location = index // 32
    bit_pos = 31 - (index % 32)
    mask = 1 << bit_pos
    voxel_table[int_location] ^= mask
```

## Subtopics

### Stochastic Ray-Casting Voxelization
Uses random sampling of rays to determine interior voxels. Choose when mesh topology is complex or non-manifold, but accept probabilistic errors. [Link](1067-stochastic-ray-casting-voxelization.md)

### Ray-Cast Style Voxel Filling
Casts rays per voxel center to determine intersection. Choose for high accuracy per voxel but higher computational cost per voxel. [Link](1502-ray-cast-style-voxel-filling.md)

### Front/Back Face Flagging
Uses face normal orientation relative to the camera or axis to flag voxels. Choose for simple convex shapes or when normal consistency is guaranteed. [Link](1506-front-back-face-flagging.md)

### Mesh Winding Number Voxelization
Computes the winding number for each voxel. Choose for robust handling of self-intersecting or non-manifold meshes. [Link](2328-mesh-winding-number-voxelization.md)

### Polyhedron Moment Integration and Voxelization
Integrates moments over the polyhedron volume. Choose for analytical volume preservation and smooth density fields. [Link](3722-polyhedron-moment-integration-and-voxelization.md)

### Point-Containment Voxelization
Samples points within the grid and checks containment. Choose for simplicity and when grid resolution is low. [Link](3882-point-containment-voxelization.md)

## Operating characteristics
- **Time Complexity**: $O(N \cdot A)$, where $N$ is the number of triangles and $A$ is the average area of the projected triangle in grid cells (number of Y-Z voxels tested per triangle). The inner loop fills X voxels, adding a factor of $G_x$ in the worst case, but typically bounded by the triangle's X-extent.
- **Memory Complexity**: $O(G_x \cdot G_y \cdot G_z)$ for the voxel table. The algorithm itself uses $O(1)$ auxiliary space per triangle.
- **Measured Performance**: In the reference implementation (CUDA Voxelizer CPU fallback), performance is measured in milliseconds for typical mesh sizes (e.g., thousands of triangles) on a CPU [S1, unofficial].
- **Strengths**: Deterministic results; no stochastic noise; efficient for convex or simple concave meshes; leverages 2D projection to reduce 3D complexity.
- **Limitations**: Fails or produces artifacts for triangles parallel to the YZ plane (handled by skipping, potentially causing holes); assumes a consistent winding order; may produce "staircase" artifacts on diagonal surfaces; not suitable for non-manifold meshes without preprocessing.
- **When to use**: When a fast, deterministic CPU-based solid voxelization is needed for meshes with well-defined normals and no extreme degeneracies.
- **When not to use**: For meshes with triangles parallel to the projection plane, non-manifold geometry, or when high-frequency surface detail requires ray-casting accuracy.

## Background
The method is based on the Schwarz-Seidel solid voxelization algorithm, which uses 2D projection and edge traversal to fill voxels [S1, unofficial]. It is implemented as a CPU fallback in the CUDA Voxelizer project by Jeroen Baert, providing a deterministic alternative to GPU-based stochastic or ray-casting methods [S1, unofficial]. The algorithm handles edge cases by checking winding order and using specific edge flags to determine voxel inclusion.
