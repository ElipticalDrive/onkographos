# Direct, triangle-parallel solid voxelization

Also called: GPU Solid Voxelization via Triangle-Parallel YZ Projection, Triangle-Parallel Atomic Solid Voxelization, Triangle-Parallel Conservative Voxelization

## Overview
Direct, triangle-parallel solid voxelization is a data-parallel algorithm that determines all voxels inside a closed, watertight mesh by processing every triangle in parallel, dedicating one thread per triangle [S1, S2]. It solves the problem of generating a dense voxel grid representation of a mesh on a GPU by projecting triangles onto the YZ plane, testing voxel columns for overlap, and using atomic operations to set the interior bits along the X axis [S2]. It differs from its sibling [Tile-Based Solid Voxelization](9087-tile-based-solid-voxelization.md) by grouping work by input primitive (triangles) rather than by spatial location (tiles), which avoids memory bandwidth bottlenecks and atomic serialization costs at the expense of warp underutilization [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A mesh defined by a list of triangles, where each triangle consists of three vertices $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$ [S1, S2]. The mesh is assumed to be closed and watertight [S2].
*   **Output:** A linear array of bits representing the voxel grid. Each bit corresponds to a voxel $(i, j, k)$ in the grid, where $0 \le i < n_x$, $0 \le j < n_y$, $0 \le k < n_z$ [S1, S2]. The grid has a fixed resolution and spatial bounds [G].

**Data Structures:**
*   **Voxel Grid:** A 1D array of 32-bit integers [S1]. The bit at index $b$ corresponds to voxel $(i, j, k)$ where $b = i + n_x \cdot (j + n_y \cdot k)$ [G]. Adjacent voxels in the X direction are stored in consecutive bits within the same 32-bit word [S1].
*   **Triangle Data:** For each triangle, the algorithm computes the bounding box in the YZ plane and the plane equation of the triangle [S2, G].

**Numbered Steps:**
1.  **Bounding Box Calculation:** For each triangle, determine the bounding box in the YZ plane [S2]. Calculate the range of voxel centers covered by this bounding box [S2]. Let the YZ range be $[y_{min}, y_{max}] \times [z_{min}, z_{max}]$ in voxel coordinates [G].
2.  **Column Loop:** If the YZ range is non-empty, loop over all voxel columns $(j, k)$ contained within this range [S2].
3.  **YZ Overlap Test:** For each column $(j, k)$, test if the column center $\mathbf{p}_{YZ} = (j, k)$ overlaps with the triangle's projection onto the YZ plane [S2]. This is done using edge functions.
    *   Compute edge normals $\mathbf{n}_{e_i}^{YZ}$ for the triangle's projection [S2].
    *   Compute offsets $d_{e_i}^{YZ} = -\langle \mathbf{n}_{e_i}^{YZ}, \mathbf{v}_i^{YZ} \rangle$ [S2].
    *   Apply the modified edge test to handle shared edges/vertices consistently (Top-Left Fill Rule):
        $$ \bigwedge_{i=0}^2 \left( (\langle \mathbf{n}_{e_i}^{YZ}, \mathbf{p}_{YZ} \rangle + d_{e_i}^{YZ}) + f_{e_i}^{YZ} > 0 \right) $$
        where $f_{e_i}^{YZ}$ is the smallest positive floating-point number if the edge is a "left" edge ($n_{e_i}^{YZ,y} > 0$) or a "top" edge ($n_{e_i}^{YZ,y} = 0 \land n_{e_i}^{YZ,z} < 0$), and zero otherwise [S2]. Vertex ordering must be consistent to ensure correct application of this rule [S2].
4.  **X-Range Determination:** If the YZ test passes, project the column center $\mathbf{p}_{YZ}$ along the X-axis onto the triangle's plane to find the intersection point [S2]. Calculate the X-coordinate $q$ of this intersection in voxel space [S2].
5.  **Bit Flipping:** Determine the range of X-indices $[\lfloor q + 0.5 \rfloor, n_x - 1]$ that are considered "inside" the triangle for this column [S2]. Flip the corresponding bits in the voxel grid using an atomic XOR operation [S2]. This ensures that if multiple triangles cover the same voxel, the bit is set correctly without race conditions [S2].

**Pseudocode:**
```python
import math

def cross(a, b):
    return (a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0])

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def triangle_parallel_solid_voxelization(triangles, grid_width, grid_height, grid_depth):
    # Initialize voxel grid as a flat array of 32-bit integers
    num_words = math.ceil(grid_width * grid_height * grid_depth / 32)
    voxel_grid = [0] * num_words

    for triangle in triangles:
        v0, v1, v2 = triangle.vertices
        
        # 1. Determine YZ bounding box
        y_min = min(v0.y, v1.y, v2.y)
        y_max = max(v0.y, v1.y, v2.y)
        z_min = min(v0.z, v1.z, v2.z)
        z_max = max(v0.z, v1.z, v2.z)
        
        # Convert to voxel indices
        j_start = math.floor(y_min)
        j_end = math.ceil(y_max)
        k_start = math.floor(z_min)
        k_end = math.ceil(z_max)
        
        # Clip to grid bounds
        j_start = max(0, j_start)
        j_end = min(grid_height, j_end)
        k_start = max(0, k_start)
        k_end = min(grid_depth, k_end)
        
        # 2. Loop over YZ columns
        for j in range(j_start, j_end):
            for k in range(k_start, k_end):
                # 3. YZ Overlap Test
                # Center of the voxel column in YZ plane
                p_yz = (j + 0.5, k + 0.5)
                
                # Compute edge normals and offsets for YZ projection
                edges = [(v1, v2), (v2, v0), (v0, v1)]
                edge_normals_yz = []
                edge_offsets_yz = []
                edge_flags = []
                
                for idx in range(3):
                    v_start, v_end = edges[idx]
                    dy = v_end.y - v_start.y
                    dz = v_end.z - v_start.z
                    # Normal in YZ plane: (dz, -dy)
                    n_y = dz
                    n_z = -dy
                    
                    # Offset d = - <n, v>
                    d = -(n_y * v_start.y + n_z * v_start.z)
                    
                    edge_normals_yz.append((n_y, n_z))
                    edge_offsets_yz.append(d)
                    
                    # Top-left fill rule flags
                    is_left = n_y > 0
                    is_top = (n_y == 0) and (n_z < 0)
                    flag = 1e-9 if (is_left or is_top) else 0.0
                    edge_flags.append(flag)
                
                # Test all 3 edges
                overlap = True
                for i in range(3):
                    n_y, n_z = edge_normals_yz[i]
                    d = edge_offsets_yz[i]
                    f = edge_flags[i]
                    val = (n_y * p_yz[0] + n_z * p_yz[1]) + d + f
                    if val <= 0:
                        overlap = False
                        break
                
                if not overlap:
                    continue
                
                # 4. X-Range Determination
                # Project p_yz along X onto triangle plane
                v0v1 = (v1.x - v0.x, v1.y - v0.y, v1.z - v0.z)
                v0v2 = (v2.x - v0.x, v2.y - v0.y, v2.z - v0.z)
                normal = cross(v0v1, v0v2)
                A, B, C = normal
                D = -dot(normal, v0)
                
                if abs(A) < 1e-9:
                    continue 
                
                q = -(B * p_yz[0] + C * p_yz[1] + D) / A
                
                # 5. Bit Flipping
                i_start = math.floor(q + 0.5)
                i_start = max(0, i_start)
                i_end = grid_width
                
                for i in range(i_start, i_end):
                    bit_index = i + grid_width * (j + grid_height * k)
                    word_index = bit_index // 32
                    bit_pos = bit_index % 32
                    
                    # In hardware, this is an atomic XOR operation [S2]
                    voxel_grid[word_index] ^= (1 << bit_pos)
```

**Parameters:**
*   **Grid Resolution:** $(n_x, n_y, n_z)$. Typical values depend on the scene scale and required detail.
*   **Voxel Size:** Implicitly 1 unit in voxel space.

**Edge Cases and Pitfalls:**
*   **Shared Edges/Vertices:** If an edge or vertex shared by adjacent triangles overlaps a voxel center, the test must report overlap for only one triangle to avoid double-counting. This is solved by the Top-Left Fill Rule [S2].
*   **Tessellation Independence:** Voxels merely touched by the bounding box must be considered to ensure voxelization is independent of the tessellation of planar surfaces [S1].
*   **Degenerate Triangles:** Triangles with zero area or parallel to the X-axis require special handling. If the triangle's normal has a zero X-component, the projection along X is undefined.
*   **Atomic Serialization:** High memory bandwidth and atomic serialization costs can negatively affect performance, especially for large grids [S2].

## Subtopics

### [Tile-Based Solid Voxelization](9087-tile-based-solid-voxelization.md)
A data-parallel algorithm that assigns triangles to pixel tiles in the $yz$ plane, then processes these tiles in parallel to determine interior voxels. It solves the memory bandwidth bottlenecks and atomic operation serialization inherent in triangle-parallel methods by keeping tile data in fast memory and avoiding conflicting writes from multiple triangles overlapping the same pixel. It differs from its sibling [Direct, triangle-parallel solid voxelization](9073-direct-triangle-parallel-solid-voxelization.md) by grouping work by spatial location (tiles) rather than by input primitive (triangles).

## Operating characteristics
*   **Time Complexity:** $O(T \cdot C)$, where $T$ is the number of triangles and $C$ is the average number of voxel columns per triangle. The complexity is linear with respect to the number of triangles and the projected area [S2].
*   **Memory Complexity:** $O(V)$, where $V$ is the total number of voxels in the grid [S1].
*   **Measured Performance:** The method suffers from warp underutilization due to varying voxel column counts among triangles processed by one warp [S2]. For large grids, flipping all voxels in the derived X range poses high memory bandwidth requirements, and many atomic operations may have to be sequentialized, negatively affecting performance [S2].
*   **Strengths:** Simple implementation, fully data-parallel, conservative voxelization is affordable in real-time scenarios [S2].
*   **Limitations:** High memory bandwidth usage, atomic serialization overhead, warp divergence [S2].
*   **When to use:** When the number of triangles is moderate and the grid size is small to medium, or when simplicity of implementation is prioritized over maximum performance [S2].
*   **When not to use:** For large grids or scenes with many triangles, where tile-based or sparse voxelization methods are more efficient [S2].

## Background
The method was introduced by Michael Schwarz et al. in 2010 as part of the paper "Fast Parallel Surface and Solid Voxelization on GPUs" [S1, S2]. It was developed to replace the fixed-function 2D rasterizer with custom "3D rasterizers" on GPUs, allowing for direct application of coverage criteria without modifying the rasterizer's pixel coverage test [S2]. The algorithm is part of a suite of data-parallel algorithms for solid voxelization, including tile-based and octree-based methods [S2].
