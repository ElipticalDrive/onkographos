# Tile-Based Solid Voxelization
Also called: Advanced Tile-Based Solid Voxelization

## Overview
Tile-Based Solid Voxelization is a data-parallel algorithm that assigns triangles to pixel tiles in the $yz$ plane, then processes these tiles in parallel to determine interior voxels [S1, S2]. It avoids the memory bandwidth bottlenecks and atomic operation serialization of triangle-parallel methods by keeping tile data in fast memory and preventing conflicting writes from overlapping triangles [S1, S2]. It differs from [Direct, triangle-parallel solid voxelization](9073-direct-triangle-parallel-solid-voxelization.md) by grouping work spatially rather than by primitive [S2].

## How it works
### Inputs and Outputs
*   **Input:** A set of triangles defining a closed object and a voxel grid resolution [S1].
*   **Output:** A solid voxel grid marking interior and exterior voxels [S1].
*   **Tile Dimensions:** Fixed at $4 \times 4$ voxel columns [S1].

### Data Structures
1.  **Work Queue:** A dynamic array of tile/triangle pairs [S1].
2.  **Tile List:** A compacted list of unique tiles present in the work queue, along with offsets into the work queue where each tile's triangle list begins [S1].
3.  **Thread State (per thread):** `active_segment` (a 32-bit integer representing the current 32-voxel segment of the voxel column) and `flip_bitmask` (a bitmask where each bit corresponds to a 32-bit segment) [S1].
4.  **Shared Memory:** Stores setup data for up to 14 triangles simultaneously [S1].

### Algorithm Steps
#### Phase 1: Tile Assignment and Queue Construction
1.  **Triangle Tile Counting:** Each triangle computes its bounding box and checks whether any voxel column center lies within it [S1]. If so, it tests all tiles containing those voxel centers against the triangle using edge functions evaluated at the critical voxel column center within each tile [S1]. This precise testing is more expensive than bounding box enumeration but yields a shorter queue, saving memory and sorting time [S1]. Caching binary results for the first 32 visited tiles per triangle in a buffer did not improve performance [S1].
2.  **Exclusive Scan:** An exclusive scan on the buffer of tile counts yields the total work queue size and an offset into the queue for each triangle [S1].
3.  **Queue Population:** Triangles are visited again in parallel; each determines its overlapped tiles and writes the corresponding tile/triangle pairs into the work queue at its calculated offset [S1].
4.  **Sorting:** The work queue is sorted by tile identifier [S1].
5.  **Compaction:** A list of all unique tiles is derived along with offsets to each tile's triangle list in the work queue [S1].

#### Phase 2: Tile Processing
1.  **Thread Allocation:** Tiles are processed in parallel, with one warp (32 threads) assigned per tile [S1]. To utilize all threads, the algorithm processes two triangles per warp, causing two threads (twin threads) to process the same voxel column simultaneously [S1]. If a tile's triangle list length is odd, the second half-warp remains idle [S1].
2.  **Parallel Triangle Setup:** Voxel column processing is interleaved with a parallel triangle setup stage where each thread fetches and sets up one triangle into shared memory [S1].
3.  **Voxel Column Processing:** One thread is allocated per voxel column in the tile [S1]. Each thread tests its column center for overlap with the current triangle and determines the range of affected voxels, analogous to the triangle-parallel method [S1].
4.  **Bitmask Flipping Logic:** When an overlapping triangle triggers flipping for voxels with $x$ index $\ge \bar{q}$, the thread checks whether $\bar{q}$ is in the `active_segment` [S1]. If not, it flushes the `active_segment` to global memory via bitwise XOR, selects $\lfloor \bar{q}/32 \rfloor$ as the new `active_segment`, and initializes it to zero [S1]. It then flips all bits for voxels $\ge \bar{q}$ in the `active_segment` and sets bits in the `flip_bitmask` for all succeeding segments [S1].
5.  **Twin Thread Synchronization:** Twin threads communicate to avoid conflicting and superfluous writes [S1]. If one thread flushes an `active_segment` but its twin has the same segment active, the twin incorporates the value into its own `active_segment` instead of writing to global memory [S1].
6.  **Final Flush:** After processing all triangles in a tile, the thread flushes the final `active_segment` and flips the bits of all segments marked in the `flip_bitmask` [S1]. No atomic memory operations are required [S1].

### Pseudocode
```python
def edge_function_test(triangle, point):
    """Returns True if point is inside triangle using barycentric edge functions."""
    # Standard barycentric coordinate test [G]
    v0, v1, v2 = triangle.vertices
    d00 = (v1[0]-v0[0])*(v1[0]-v0[0]) + (v1[1]-v0[1])*(v1[1]-v0[1])
    d01 = (v1[0]-v0[0])*(v2[0]-v0[0]) + (v1[1]-v0[1])*(v2[1]-v0[1])
    d11 = (v2[0]-v0[0])*(v2[0]-v0[0]) + (v2[1]-v0[1])*(v2[1]-v0[1])
    d20 = (v1[0]-v0[0])*(v2[0]-v0[0]) + (v1[1]-v0[1])*(v2[1]-v0[1])
    d21 = (v2[0]-v0[0])*(v2[0]-v0[0]) + (v2[1]-v0[1])*(v2[1]-v0[1])
    denom = d00 * d11 - d01 * d01
    v = ((d11 * d00 - d01 * d20) * (point[0]-v0[0]) + (d01 * d21 - d11 * d01) * (point[1]-v0[1])) / denom
    w = ((d00 * d21 - d01 * d20) * (point[0]-v0[0]) + (d01 * d01 - d00 * d01) * (point[1]-v0[1])) / denom
    u = 1.0 - v - w
    return u >= 0.0 and v >= 0.0 and w >= 0.0

def compute_bounding_box(triangle):
    """Returns (min_x, min_y, min_z, max_x, max_y, max_z)."""
    xs = [triangle.vertices[i][0] for i in range(3)]
    ys = [triangle.vertices[i][1] for i in range(3)]
    zs = [triangle.vertices[i][2] for i in range(3)]
    return (min(xs), min(ys), min(zs), max(xs), max(ys), max(zs))

def exclusive_scan(arr):
    """Standard prefix sum returning offsets."""
    n = len(arr)
    offsets = [0] * n
    total = 0
    for i in range(n):
        offsets[i] = total
        total += arr[i]
    return offsets

def build_work_queue(triangles, tile_size=4):
    """Phase 1: Assign triangles to tiles and build sorted queue."""
    # Step 1: Count tiles for all triangles
    tile_counts = []
    for tri in triangles:
        bbox = compute_bounding_box(tri)
        count = 0
        # Check voxel column centers within bounding box
        for y in range(bbox[1], bbox[4] + 1, tile_size):
            for z in range(bbox[2], bbox[5] + 1, tile_size):
                center = (0.0, y + tile_size/2.0, z + tile_size/2.0)
                if bbox[0] <= center[0] <= bbox[3] and edge_function_test(tri, center):
                    count += 1
        tile_counts.append(count)
    
    # Step 2: Exclusive scan
    offsets = exclusive_scan(tile_counts)
    
    # Step 3: Populate queue
    work_queue = []
    for i, tri in enumerate(triangles):
        offset = offsets[i]
        bbox = compute_bounding_box(tri)
        for y in range(bbox[1], bbox[4] + 1, tile_size):
            for z in range(bbox[2], bbox[5] + 1, tile_size):
                center = (0.0, y + tile_size/2.0, z + tile_size/2.0)
                if bbox[0] <= center[0] <= bbox[3] and edge_function_test(tri, center):
                    work_queue.append(((y, z), tri))
                    
    # Step 4: Sort by tile
    work_queue.sort(key=lambda pair: pair[0])
    
    # Step 5: Compaction
    tile_list = []
    current_tile = None
    for pair in work_queue:
        tile, _ = pair
        if tile != current_tile:
            tile_list.append({'tile': tile, 'offset': len(tile_list)})
            current_tile = tile
            
    return work_queue, tile_list

def process_tile(tile, triangles, global_grid, thread_id, warp_size=32):
    """Phase 2: Process a single tile using a warp."""
    active_segment = 0
    flip_bitmask = 0
    twin_id = (thread_id + warp_size // 2) % warp_size
    
    # Shared memory simulation for triangle setup
    shared_tri_data = [None] * 14
    
    for tri in triangles:
        # Parallel triangle setup stage
        idx = thread_id % len(triangles)
        if idx < 14:
            shared_tri_data[idx] = tri
        # Synchronize threads to ensure setup data is ready [G]
        
        # Voxel column processing
        for col_idx in range(tile['width'] * tile['height']):
            col_center = (0.0, tile['y'] + (col_idx % tile['width']) + 0.5, 
                          tile['z'] + (col_idx // tile['width']) + 0.5)
            
            # Test overlap
            if shared_tri_data[thread_id % len(triangles)] is not None:
                tri = shared_tri_data[thread_id % len(triangles)]
                if edge_function_test(tri, col_center):
                    # Determine flip threshold q_bar (x-index of first affected voxel)
                    q_bar = compute_flip_threshold(tri, col_center)
                    
                    # Bitmask logic
                    if q_bar // 32 != active_segment:
                        # Flush active segment
                        if thread_id == 0:
                            global_grid[col_idx] ^= active_segment
                        # Switch segment
                        active_segment = q_bar // 32
                        active_segment_val = 0
                        # Update flip bitmask for succeeding segments
                        flip_bitmask |= (0xFFFFFFFF << (q_bar // 32))
                    
                    # Flip bits in active segment for voxels >= q_bar
                    mask = (0xFFFFFFFF << (q_bar % 32))
                    active_segment_val ^= mask
                    
                    # Twin thread synchronization
                    if thread_id < warp_size // 2:
                        # Communicate with twin to avoid conflicting writes [S1]
                        if flip_bitmask & (1 << active_segment):
                            active_segment_val |= get_twin_value(twin_id, active_segment)
                    
                    active_segment = active_segment_val
    
    # Final flush
    if thread_id == 0:
        global_grid[col_idx] ^= active_segment
        for seg_idx in range(active_segment + 1, 32):
            if flip_bitmask & (1 << seg_idx):
                global_grid[seg_idx] ^= 0xFFFFFFFF

def voxelize(triangles, grid_dims):
    """Main entry point."""
    work_queue, tile_list = build_work_queue(triangles)
    global_grid = [0] * (grid_dims[0] * grid_dims[1] * grid_dims[2])
    
    for tile_info in tile_list:
        tile = tile_info['tile']
        # Extract triangles for this tile using offset
        start = tile_info['offset']
        end = tile_info['offset'] + 1 # Simplified for pseudocode
        triangles_for_tile = [pair[1] for pair in work_queue[start:end]]
        
        # Launch warp per tile
        for t in range(32):
            process_tile(tile, triangles_for_tile, global_grid, t)
            
    return global_grid
```

### Parameters and Edge Cases
*   **Tile Size:** Fixed at $4 \times 4$ voxel columns [S1]. Larger tiles reduce sample test efficiency [S1].
*   **Warp Size:** 32 threads [S1].
*   **Shared Memory Limit:** Limits triangle setup to 14 triangles at once [S1].
*   **Edge Case (Odd Triangle Count):** If a tile has an odd number of triangles, the second half-warp is idle [S1].
*   **Pitfall:** Caching binary results for the first 32 visited tiles per triangle in a buffer did not pay off [S1].
*   **Pitfall:** Testing tiles via edge functions is more expensive than bounding box enumeration, but necessary for queue shortening [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by the sorting of the work queue and the sequential processing of triangles within tiles [S1]. The initial counting and scanning are linear with respect to the number of triangles [S1].
*   **Memory Complexity:** Requires storage for the work queue (tile/triangle pairs) and the voxel grid [S1]. The queue size is proportional to the number of triangle-tile overlaps [S1].
*   **Performance:** Avoids atomic memory operations, which can be sequentialized and costly on GPUs [S1]. By keeping tile data in fast memory and minimizing global memory writes via the bitmask strategy, it reduces memory bandwidth requirements [S1].
*   **Strengths:** No atomic operations required; efficient memory usage due to queue compaction; avoids conflicting writes [S1, S2].
*   **Limitations:** Limited by shared memory size (14 triangles); warp utilization issues with odd triangle counts per tile; precise tile testing is computationally expensive [S1].
*   **When to Use:** Suitable for solid voxelization on GPUs where memory bandwidth and atomic contention are bottlenecks, particularly for larger voxel grids [S1].
*   **When Not to Use:** When the number of triangles is very small, or when the overhead of queue construction and sorting outweighs the benefits of tile-based processing [S1].

## Background
The method was developed to address the shortcomings of triangle-parallel solid voxelization, specifically the high memory bandwidth requirements and atomic operation serialization issues that arise when flipping voxels in larger grids [S1]. It is part of a broader framework for parallel surface and solid voxelization that also includes direct triangle-parallel approaches and sparse octree-based techniques [S2]. The algorithm builds upon earlier work in real-time voxelization and parallel data structure construction [S2].
