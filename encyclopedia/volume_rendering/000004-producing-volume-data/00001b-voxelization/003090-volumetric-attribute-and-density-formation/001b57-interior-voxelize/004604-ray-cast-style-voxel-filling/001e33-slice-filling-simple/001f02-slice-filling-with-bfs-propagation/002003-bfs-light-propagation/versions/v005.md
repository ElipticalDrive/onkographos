# BFS Light Propagation

Also called: Cellular Automata Lighting, Flood Fill Lighting, Light Propagation (BFS), Voxel Light Propagation

## Overview
BFS Light Propagation is a voxel lighting algorithm that computes light intensity by flooding non-opaque space from light sources using a Breadth-First Search (BFS) queue, attenuating intensity by a fixed amount per step [S1, S3, unofficial][S5]. It solves the problem of efficiently updating dynamic lighting in voxel worlds where blocks are added, removed, or changed, avoiding the high computational cost of ray-casting or global illumination for every frame [S2, unofficial][S5]. Unlike [Slice Filling with BFS Propagation](1909-slice-filling-with-bfs-propagation.md), which propagates light only within a single slice plane, BFS Light Propagation operates in full 3D volume, handling vertical attenuation and cross-chunk boundaries [S2, S3, unofficial]. It differs from [Flood Fill for Minkowski Sum Boundary Identification](14571-flood-fill-for-minkowski-sum-boundary-identification.md) by tracking scalar light intensity values rather than binary boundary states [S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A voxel grid (chunk or world) containing block types (opaque/non-opaque) and light sources; a list of changed voxels (additions, removals, or updates).
- **Output:** Updated light intensity values for all voxels in the affected region, stored in a light map.

**Data Structures:**
- **Voxel Grid:** Stores block types. Opaque blocks block light; transparent/empty blocks allow propagation [S2, S3, unofficial].
- **Light Map:** A 1D array indexed by flat voxel coordinate.
    - **Layout (4-bit Nibble):** Each byte stores two 4-bit values: upper 4 bits (bits 4-7) for sky light, lower 4 bits (bits 0-3) for block light [S6, S4, unofficial].
    - **Layout (Byte Array):** Alternatively, a single byte array where each element represents the total light level (0–15) for that voxel [S2, S4, unofficial].
- **Propagation Queue:** A FIFO queue (e.g., `VecDeque` or `std::queue`) storing tuples of `(voxel_index, light_level)` [S1, S2, S3, unofficial].
- **Removal Queue:** A FIFO queue storing tuples of `(voxel_index, old_light_level)` for propagating light decay [S2, unofficial].
- **Neighbor Strides:** Precomputed offsets for 6-connected neighbors in a padded chunk layout: `[1, -1, PADDED, -PADDED, PADDED*PADDED, -PADDED*PADDED]` [S1, unofficial].

**Parameters:**
- **Attenuation:** Light intensity decreases by 1 per propagation step [S1, S3, S6, unofficial].
- **Max Light Level:** Typically 15 (4-bit range) [S2, S6, unofficial].
- **Opaque Check:** A voxel is opaque if `is_opaque(block_type)` returns true [S1, S3, unofficial].

**Algorithm Steps:**

1. **Initialization (Sky Light):**
   - For each column $(x, z)$ in the chunk, iterate $y$ from the top ($chunk\_size.y - 1$) down to 0 [S6, unofficial].
   - If the block at $(x, y, z)$ is opaque, stop the column [S6, unofficial].
   - Otherwise, set the sky light component to the current height-based intensity (starting at 15, decrementing per step) [S6, unofficial].
   - Trigger a flood fill from the top-most non-opaque voxel in the column with the calculated sky light value [S6, unofficial].

2. **Initialization (Block Light Sources):**
   - Identify all voxels with active light sources (e.g., lamps, torches) [S1, unofficial].
   - For each source voxel with light level $L > 0$, enqueue $(voxel\_index, L)$ into the `PropagationQueue` [S1, S3, unofficial].

3. **Processing Added/Changed Light:**
   - While `PropagationQueue` is not empty:
     a. Dequeue $(idx, level)$ [S1, unofficial].
     b. If $level \le 0$, skip [S1, unofficial].
     c. Compute $new\_level = level - 1$ [S1, unofficial].
     d. For each of the 6 neighbors $ni$ of $idx$ (using strides or coordinate offsets):
        i. Check if $ni$ is within bounds [S1, unofficial].
        ii. Check if the block at $ni$ is non-opaque (exists and is not opaque) [S2, S3, unofficial].
        iii. Get the current light level $current\_light$ at $ni$ [S3, unofficial].
        iv. If $new\_level > current\_light$:
            - Update $light\_map[ni] = new\_level$ [S2, unofficial].
            - If $new\_level > 1$, enqueue $(ni, new\_level)$ into `PropagationQueue` [S3, unofficial].

4. **Processing Removed/Occluded Light:**
   - When a light source is removed or a voxel becomes opaque (blocking light):
     a. Identify the affected voxel and its previous light level $L_{old}$ [S2, unofficial].
     b. Enqueue $(voxel\_index, L_{old})$ into the `RemovalQueue` [S2, unofficial].
   - While `RemovalQueue` is not empty:
     a. Dequeue $(idx, L_{old})$ [S2, unofficial].
     b. For each neighbor $ni$:
        i. If $ni$ is within bounds and non-opaque:
           - Get current light $current\_light$ at $ni$ [S2, unofficial].
           - If $current\_light > 0$ and $current\_light < L_{old}$:
               - Set $light\_map[ni] = 0$ [S2, unofficial].
               - Enqueue $(ni, L_{old})$ into `RemovalQueue` to propagate the decay [S2, unofficial].
           - Else if $current\_light \ge L_{old}$:
               - Enqueue $(ni, current\_light)$ into `PropagationQueue` to re-propagate existing light from other sources [S2, unofficial].

5. **Cross-Chunk Propagation:**
   - When processing a neighbor $ni$ that lies outside the current chunk:
     a. Calculate the target chunk coordinates and local voxel coordinates in the adjacent chunk [S3, unofficial].
     b. Create a `NeighborLightPropagation` event with the side, target voxel, light type, and intensity [S3, unofficial].
     c. Add this event to a list of pending cross-chunk updates [S3, unofficial].
     d. Apply the intensity reduction (decrement by 1 for non-downward propagation) before sending to the neighbor chunk [S3, unofficial].

6. **Flood Fill (Sky Light Specific):**
   - Recursive or iterative flood fill starting from sky-light-exposed voxels [S6, unofficial].
   - Base case: If voxel is out of bounds or opaque, return [S6, unofficial].
   - Update rule: If the incoming light value $v$ is greater than the current sky light $lv$ (or first visit), set sky light to $v$ and enqueue neighbors with $v-1$ [S6, unofficial].

**Pseudocode:**

```python
def propagate_light(grid, light_map, changes):
    """
    grid: 3D array of block types (opaque or not)
    light_map: 1D array of light levels (0-15)
    changes: list of (index, change_type) where change_type is 'add', 'remove', 'update'
    """
    propagation_queue = Queue()
    removal_queue = Queue()
    cross_chunk_events = []

    # 1. Initialize Sky Light (Top-Down)
    for x in range(chunk_size.x):
        for z in range(chunk_size.z):
            light_level = 15
            for y in range(chunk_size.y - 1, -1, -1):
                idx = get_flat_index(x, y, z)
                if is_opaque(grid, idx):
                    break
                # Set sky light component (upper 4 bits)
                current_val = light_map[idx]
                block_light = current_val & 0x0F
                light_map[idx] = (light_level << 4) | block_light
                
                # Trigger flood fill for sky light
                if light_level > 0:
                    flood_fill_sky_light(grid, light_map, x, y, z, light_level, propagation_queue)
                light_level -= 1

    # 2. Process Changes
    for (idx, change_type) in changes:
        if change_type == 'add' or change_type == 'update':
            if is_source(grid, idx):
                source_level = get_source_intensity(grid, idx)
                if source_level > light_map[idx]:
                    light_map[idx] = source_level
                    propagation_queue.enqueue((idx, source_level))
            elif is_opaque(grid, idx):
                # Voxel became opaque, trigger removal
                old_level = light_map[idx]
                light_map[idx] = 0
                removal_queue.enqueue((idx, old_level))
        elif change_type == 'remove':
            # Voxel became empty/transparent, might need re-propagation
            # Handled by neighbor checks during propagation
            pass

    # 3. Process Propagation Queue (Adding Light)
    while not propagation_queue.is_empty():
        (idx, level) = propagation_queue.dequeue()
        if level <= 1:
            continue
        
        new_level = level - 1
        neighbors = get_6_neighbors(idx)
        
        for ni in neighbors:
            if not is_in_bounds(ni):
                # Handle cross-chunk
                event = create_cross_chunk_event(idx, ni, new_level)
                cross_chunk_events.append(event)
                continue
            
            if is_opaque(grid, ni):
                continue
            
            current_light = light_map[ni]
            if new_level > current_light:
                light_map[ni] = new_level
                if new_level > 1:
                    propagation_queue.enqueue((ni, new_level))

    # 4. Process Removal Queue (Removing Light)
    while not removal_queue.is_empty():
        (idx, old_level) = removal_queue.dequeue()
        
        neighbors = get_6_neighbors(idx)
        for ni in neighbors:
            if not is_in_bounds(ni):
                continue
            if is_opaque(grid, ni):
                continue
            
            current_light = light_map[ni]
            if current_light > 0 and current_light < old_level:
                light_map[ni] = 0
                removal_queue.enqueue((ni, old_level))
            elif current_light >= old_level:
                propagation_queue.enqueue((ni, current_light))

    # 5. Apply Cross-Chunk Events
    for event in cross_chunk_events:
        send_to_neighbor_chunk(event)

def flood_fill_sky_light(grid, light_map, x, y, z, level, queue):
    """Recursive or iterative flood fill for sky light."""
    if level <= 0:
        return
    idx = get_flat_index(x, y, z)
    if is_opaque(grid, idx):
        return
    
    current_val = light_map[idx]
    current_sky = (current_val >> 4) & 0x0F
    
    if level > current_sky:
        block_light = current_val & 0x0F
        light_map[idx] = (level << 4) | block_light
        
        # Enqueue neighbors
        neighbors = get_6_neighbors(idx)
        for ni in neighbors:
            if is_in_bounds(ni) and not is_opaque(grid, ni):
                queue.enqueue((ni, level - 1))
```

## Subtopics

### Voxel Light Propagation via Component-wise Max
- **Definition:** A variant that propagates colored light using component-wise maximum operations across neighbors instead of averaging or simple BFS decrement [S7, unofficial].
- **Mechanism:** Replaces the standard decay with a max-filter approach, where each voxel takes the maximum light value from its neighbors, fading tint at the volume's edge [S7, unofficial].
- **Parameters:** Per-block falloff factor of 0.8 [S7, unofficial].
- **Advantages:** Converges significantly faster than Jacobi diffusion (8 frames vs 179 frames for 8 blocks) and reaches further (15 blocks vs 3 blocks) [S7, unofficial].
- **Pitfalls:** Initial Jacobi diffusion was too slow and decayed exponentially, leaving sealed rooms black [S7, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels affected by changes, as each voxel is processed a constant number of times per update [S2, unofficial][S5].
- **Memory Complexity:** $O(V)$ for the light map storage, where $V$ is the number of voxels [S2, S6, unofficial].
- **Performance:** Highly efficient for dynamic voxel worlds. The BFS approach ensures that only reachable non-opaque voxels are updated [S5].
- **Strengths:** Simple to implement, handles dynamic changes efficiently, low memory overhead [S2, unofficial][S5].
- **Limitations:** Does not produce soft shadows or diagonal light effects (rhombus/diamond artifacts may appear) [S5]. Requires diagonal spreading to mitigate shape artifacts, which increases computational cost [S5]. Recursion depth in flood fill can cause stack overflow in deep shafts if not implemented iteratively [S6, unofficial].
- **When to Use:** Real-time voxel games with frequent block placement/destruction [S2, unofficial][S5].
- **When Not to Use:** Scenes requiring realistic shadows, global illumination, or diagonal light propagation [S5].

## Background
BFS Light Propagation originated in voxel-based games like Minecraft, where efficient lighting updates are critical for performance [S2, S6, unofficial]. It is often referred to as "Cellular Automata Lighting" or "Flood Fill Lighting" in the context of voxel engines [S1, S4, unofficial][S5]. The method was popularized by the need to handle dynamic lighting in large, mutable voxel grids without resorting to expensive ray-tracing or precomputed lightmaps [S5]. Variants using component-wise max operations were developed to address convergence speed and color fidelity issues in earlier diffusion-based approaches [S7, unofficial].
