# Single-pass GPU Solid Voxelization

Also called: DX10 voxelization, DX9 voxelization, Eisemann & Decoret method, Slicemap-based solid voxelization, XOR Voxelization

## Overview
Single-pass GPU Solid Voxelization is a technique to voxelize the interior of watertight 3D models into a high-resolution binary volume in a single rendering pass, using bitwise arithmetic to pack information [S2, unofficial]. It builds on [Solid Voxelization](1695-solid-voxelization.md) by exploiting the Jordan curve theorem: a point is interior if a ray from it intersects the surface an odd number of times [S2, unofficial]. It distinguishes itself from [Boundary Voxelization](1694-boundary-voxelization.md) by outputting 1s in all positions smaller than the fragment's depth (all voxels in front) and accumulating via XOR, whereas boundary voxelization outputs a single 1 at the fragment's depth using OR [S2, unofficial]. Unlike [Depth Peeling](1693-depth-peeling.md) which requires multiple passes, this method performs solid voxelization in one geometry pass [S1, unofficial].

## How it works
**Inputs:** A watertight 3D mesh (manifold or non-manifold, but topologically closed per component) and a voxel grid resolution $(W, H, D)$. The camera frustum must encompass the model.
**Outputs:** A slicemap texture representing the solid voxelization.

**Data Structures:**
*   **Slicemap:** A 2D texture of size $W \times H$. Each texel stores a 32-bit integer (or packed across RGBA channels). The $k$-th bit of the texel at $(i, j)$ represents the occupancy of voxel $(i, j, k)$ in the 3D grid. The $z$-axis is encoded in the bits of the color channels.
*   **Bitmask Texture:** A small 1D texture (or precomputed integer) where index $k$ contains a bitmask with all bits from $0$ to $k-1$ set to 1. This allows efficient generation of the "voxels in front" mask.

**Parameters:**
*   **Blending Mode:** Bitwise XOR. The framebuffer is initialized to zero.
*   **Depth Clamp:** Enabled (e.g., `GL_DEPTH_CLAMP` or `NV_depth_clamp`). Polygons must not be clipped by near/far planes to ensure correct intersection counting from inside the volume [S2, unofficial].
*   **Z-Offset:** Add half a voxel to the fragment's depth/distance to counteract rasterization center sampling shift [S2, unofficial].

**Steps:**
1.  **Initialize Framebuffer:** Clear the slicemap texture to all zeros.
2.  **Render Geometry:** For each fragment generated by rasterization:
    a.  Compute the fragment's depth $d$ in voxel units (or normalized depth mapped to voxel index $k$).
    b.  Generate a bitmask $M$ representing all voxels in front of the current fragment. If the fragment falls into voxel column $k$, $M$ should have bits $0$ through $k-1$ set to 1. This is typically done via a lookup in a 1D bitmask texture or a shader computation: $M = (1 \ll k) - 1$.
    c.  Accumulate $M$ into the slicemap texel at $(i, j)$ using bitwise XOR blending: $Texel(i, j) \leftarrow Texel(i, j) \oplus M$.
3.  **Result:** After rendering, the slicemap contains the solid voxelization. A voxel $(i, j, k)$ is interior if the $k$-th bit of the texel at $(i, j)$ is 1. This corresponds to an odd number of intersections ($n \mod 2 = 1$) [S2, unofficial].

**Pseudocode:**

```python
# Initialization
slicemap = Texture2D(width=W, height=H, format=UINT32)
slicemap.clear(0)

# Bitmask generation helper
# Returns an integer with bits 0 to k-1 set to 1
def get_front_mask(k):
    if k == 0:
        return 0
    return (1 << k) - 1

# Fragment Shader
def fragment_shader(fragment_depth_voxel_index):
    # fragment_depth_voxel_index is the k-th voxel the fragment occupies
    # Add 0.5 offset to align with voxel centers if necessary
    k = fragment_depth_voxel_index + 0.5 
    k = floor(k)
    
    # Generate mask for all voxels in front of this fragment
    mask = get_front_mask(k)
    
    # Return mask for XOR blending
    return mask

# Blending Operation
```

**Edge Cases and Pitfalls:**
*   **Watertightness:** The model must be watertight. Cracks or non-closed surfaces lead to ambiguous interior classification [S2, unofficial].
*   **Intersecting Models:** If two watertight models intersect, the algorithm computes the symmetric difference (hollow representation), not the union [S1, unofficial].
*   **Rasterization Shift:** Standard rasterization samples voxel centers shifted by half a voxel along the z-axis. Counteract by adding half a voxel to the fragment's distance [S2, unofficial].
*   **Clipping:** Polygons must not be clipped by near/far planes. Use Depth Clamp to ensure correct intersection counting even from inside the volume [S2, unofficial].
*   **Ambiguity:** When several front and back-facing triangles fall in one voxel, XOR accumulation handles the parity logic implicitly [S2, unofficial].

## Subtopics

### [Single-pass Solid Voxelization via XOR Bitmask Accumulation](3325-single-pass-solid-voxelization-via-xor-bitmask-accumulation.md)
This method voxelize watertight models in a single GPU render pass by exploiting the Jordan curve theorem: a point is interior if a ray from it intersects the surface an odd number of times. It accumulates fragment bitmasks using bitwise XOR to determine voxel occupancy, distinguishing itself from boundary-only voxelization by producing a fully filled interior volume. It builds on [Single-pass GPU Solid Voxelization](3323-single-pass-gpu-solid-voxelization.md).

### [Conservative Solid Voxelization](3563-conservative-solid-voxelization.md)
Conservative Solid Voxelization is a technique to fill voxels that are partially interior, addressing the issue where thin geometry misses voxel centers and is annihilated by XOR blending. It builds on [Single-pass GPU Solid Voxelization](3323-single-pass-gpu-solid-voxelization.md) by adding a conservative boundary pass to ensure no surface-touching voxels are lost, resulting in a conservative solid voxelization.

### [Slice-based Solid Voxelization](12949-slice-based-solid-voxelization.md)
Slice-based Solid Voxelization is a GPU-accelerated algorithm that converts closed surface-based geometric objects into multi-valued solid volumetric models. Unlike binary voxelization methods that only determine occupancy, this method generates interior material properties (e.g., colors, textures, noise) for every voxel within the object's volume. It distinguishes itself from its parent [Single-pass GPU Solid Voxelization](3323-single-pass-gpu-solid-voxelization.md) by explicitly supporting diverse, non-uniform interior attributes via dynamic slice functions, and from siblings like [Single-pass Solid Voxelization via XOR Bitmask Accumulation](3325-single-pass-solid-voxelization-via-xor-bitmask-accumulation.md) by avoiding logical XOR operations that result in binary outputs and missing voxels.

### Density Map Construction
Density Map Construction transforms the binary slicemap into a density representation using box-filtering (sum of $2^3=8$ neighbors) to indicate occupancy [S2, unofficial].
**Steps:**
1.  Compute intermediate z-density map via in-place operation storing two bits per voxel (pairwise sum of neighbors in column $c$).
2.  Formula: $d(i, j, k) := \sum_{l,m,n=0}^1 v(2i+l, 2j+m, 2k+n)$, where $v$ is the binary value (0 or 1) of the slicemap. $d$ takes values in $[0,8]$.
3.  Implementation uses bitwise operations: $c_{new} = (c \& I_{10101...}) + ((c \& I_{01010...}) \gg 1)$, where $I$ is a bitmask integer, $\&$ is bitwise AND, $\gg$ is shift right.
**Layout:**
*   Input Slicemap: $2^w \times 2^h \times 128$ grid, stored in one integer texture with 32 bits per color channel.
*   Output Density Map: $w \times h \times 64$ grid. Each voxel stores 4 bits (value 0-8). Stored across two $w \times h$ textures (256 bits per column total), each representing half the column.
**Pitfall:** The succeeding zero bit introduced by the mask ensures summation does not pollute the solution [S2, unofficial].

## Operating characteristics
**Time Complexity:** $O(N)$ where $N$ is the number of fragments, as it is a single pass.
**Memory Complexity:** $O(W \times H \times D)$ bits, packed into $O(W \times H)$ texels.
**Performance:**
*   DX10 (G80) density computation timings: 0.20 ms at $64^3$, 0.6 ms at $128^3$, 2.9 ms at $256^3$, 20.9 ms at $512^3$ [S1, unofficial].
*   DX9 density computation timings: 0.28 ms at $256^3$, 0.9 ms at $512^3$, 6.5 ms at $1024^3$ [S1, unofficial].
*   DX10 implementation achieves >300x speedup over [5] for complex models, with a theoretical maximum of 1024x [S2, unofficial].
*   DX10 implementation gains ~20x speedup even on a simple 12-triangle cube, which is a worst-case scenario due to low geometric complexity and high fill-rate [S1, unofficial].
*   On DX9 (G6) without MRT support, 32 layers are still extracted per rendering, yielding ~2x cost compared to 4 MRTs and converging to a 23x speedup over [5] [S1, unofficial].
**Strengths:**
*   Single pass, real-time performance.
*   Handles arbitrary number of fragments in a single voxel accurately [S1, unofficial].
*   Does not require front/back face separation [S1, unofficial].
*   Does not require a manifold or topologically coherent mesh; watertight input suffices [S1, unofficial].
**Limitations:**
*   Standard rasterization runs at >100 Hz for a $256^3$ volume on a simple cube, but framerate drops quickly for high-polygon models and high voxel resolutions [S2, unofficial].
*   Using 4 MRTs imposes more than the expected 33% supplementary workload compared to 3 MRTs, likely due to hardware sweet spots [S1, unofficial].
*   DX9 without MRT support still extracts 32 layers per pass, but performance converges to ~23x speedup over [5] rather than 4x, possibly due to G6 MRT sweet spot [S1, unofficial].
*   If two watertight models intersect, the algorithm computes the symmetric difference, resulting in a hollow representation rather than a union [S1, unofficial].

## Background
Origin: Elmar Eisemann and Xavier Decoret, 2009, "Single-Pass GPU Solid Voxelization for Real-Time Applications" [S2, unofficial].
History: Builds on boundary voxelization techniques [8, 10] and addresses limitations of depth peeling [5]. It was developed to enable real-time solid voxelization for applications like translucency effects, CSG operations, and particle simulations.
Usage: Used in real-time rendering for volumetric effects, fluid/gas simulation interactions, and morphological operations.
