# Solid Voxelization
Also called: 3D Scan-filling, BfsSolid, Bulk Voxelization, Inner region filling, Two-Level Model Voxelization

## Overview
Solid Voxelization fills the interior of a watertight 3D mesh with voxels, producing a fully occupied volume rather than just a surface shell [S1, unofficial]. It extends surface voxelization by determining which interior voxels are enclosed by the mesh boundary [S3, unofficial]. Unlike [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md), which relies on Z-axis scanning to identify front-to-back intervals, Solid Voxelization typically employs a two-level grid model or a flood-fill approach to robustly handle complex topologies and singular points [S1, unofficial][S3, unofficial].

## How it works
The method generally operates in two phases: surface boundary identification followed by interior filling. Two primary implementations exist: a GPU-based two-pass approach using bitwise arithmetic and a CPU-based flood-fill optimization.

### Inputs and Outputs
- **Input**: A watertight triangular mesh (vertices and indices) and a voxel size `gridVoxelSize` [S1, unofficial].
- **Output**: A binary volume grid where voxels inside the mesh are marked as solid (1) and outside as empty (0) [S1, unofficial].

### Data Structures
**MeshDataDevice** (GPU memory layout) [S1, unofficial]:
- `bbox[6]`: Float array containing the mesh bounding box minimum and maximum coordinates.
- `vertices`: Array of 3D vectors.
- `triangles`: Array of `Triangle` structs.
- `trianglesNo`: Pointer to integer count of triangles.
- `_bottom`, `_top`: Vector3Df representing the triangle's bounding box extremes.

**Triangle** [S1, unofficial]:
- `_idx1`, `_idx2`, `_idx3`: Indices into the `vertices` array.
- `_bottom`, `_top`: Vector3Df bounding box of the triangle.

**Voxel Grid** [S1, unofficial]:
- `vTable1`: Bitset array representing the surface voxels.
- `voxels_`: Bitset array for final solid voxels.
- `voxels_buffer_`: Temporary bitset for intermediate filling states.
- `voxel_metas_`: Metadata array (e.g., `Surface()`, `SetSolid()` flags) [S1, unofficial].

### Algorithm: GPU Two-Pass Solid Voxelization
This implementation uses a two-level grid model [S1, unofficial].

1. **Preprocessing**:
   - Compute global translation: `globalTranslation[0..2] = meshData->bbox[0..2]` [S1, unofficial].
   - Compute grid sizes using `ops::computeTwoLevelSizes(meshData->bbox, gridVoxelSize)` [S1, unofficial].
   - Allocate GPU memory for `MeshDataDevice` and copy data from CPU [S1, unofficial].

2. **Pass 1: Surface Voxelization**:
   - Launch `solidVoxelGpu` kernel. For each triangle, compute its bounding box and transform vertices relative to the mesh bounding box minimum [S1, unofficial].
   - For each voxel within the triangle's bounding box, determine if it intersects the triangle using plane tests [S1, unofficial].
   - **Plane Tests**:
     - Compute edge vectors $e_0, e_1, e_2$.
     - Compute 2D normals for XY, YZ, and ZX planes. If the normal's relevant component (z for XY, y for ZX) is negative, flip the normal direction [S1, unofficial].
     - Calculate distances $d$ for each plane.
     - A voxel at $(x,y,z)$ is inside if it satisfies the half-space constraints for all three edges in all three projected planes [S1, unofficial].
     - **Edge Case**: When the dot product plus distance equals zero, use a specific normal direction check: `(n.x > 0.0f || (n.x == 0.0f && n.y < 0.0f))` to determine inclusion [S1, unofficial].
     - If the voxel intersects the triangle, flip the bit in `grid->vTable1` at `location = x + (y * gridSizeY) + (z * gridSizeY * gridSizeZ)` [S1, unofficial].

3. **Pass 2: Interior Filling**:
   - Launch `fillBulkVoxelGpu` kernel. This performs a 1D scan-fill along X for each Y-Z slice [S1, unofficial].
   - For each thread processing a Y-Z slice:
     - Identify occupied voxels (surface voxels) in the slice.
     - If more than one surface voxel exists, fill all voxels between the first and last occupied voxel in the X direction [S1, unofficial].
     - Use `ops::flipBit` to mark these voxels as filled in a bulk table [S1, unofficial].

4. **Finalization**:
   - Apply bitwise inversion and XOR to combine surface and bulk results: `voxels_.get()[i] = voxels_buffer_.get()[i] ^ (~static_cast<VoxelIndex>(0))` [S1, unofficial].
   - If metadata is enabled, iterate through voxels. If a voxel is marked solid in the buffer but not as a surface voxel, mark it as solid in the metadata [S1, unofficial].
   - Synchronize device and free GPU memory [S1, unofficial].

### Algorithm: CPU Flood Fill with Filter-and-Refine
An alternative optimization avoids the need for watertight meshes by using a filter-and-refine strategy [S2, unofficial].

1. **Filter Step**:
   - Iterate along each axis (X, Y, Z).
   - For a fixed pair of coordinates (e.g., fix $x, y$), enumerate $z$ from 0 to max.
   - If a voxel is occupied (by surface voxelization), stop filling in that direction. This marks all voxels visible along that axis [S2, unofficial].

2. **Refine Step**:
   - Identify "holes": voxels not marked as visible along any axis.
   - Perform a standard Breadth-First Search (BFS) flood fill on these remaining empty voxels [S2, unofficial].

### Algorithm: 3D Scan-Filling (Singular Point Handling)
To handle singular points that cause errors in single-direction scan-filling, a robust method performs scan-filling along three axis directions and intersects the results [S3, unofficial].

1. **Initialization**:
   - Initialize a flag for each scan line to `false` [S3, unofficial].

2. **Traversal**:
   - Traverse the volume slice by slice and line by line [S3, unofficial].
   - For each scan line, check voxels from left to right [S3, unofficial].
   - Toggle the flag's value when the scan line spans a voxel that intersects the boundary of the object [S3, unofficial].

3. **Intersection**:
   - Repeat for X, Y, and Z axes.
   - A voxel is solid if it is marked as interior in all three directional passes [S3, unofficial].

### Pseudocode: BFS Solid Fill (CPU)
```python
def BfsSolid(start_index, voxels, voxels_buffer, mesh_vox_lb, mesh_vox_ub, kBatchSize):
    """
    Performs a BFS flood fill to mark solid voxels.
    voxels: Bitset array of surface voxels.
    voxels_buffer: Bitset array for solid voxels being built.
    """
    voxel_index = start_index
    # Load bits from both surface and buffer
    tmp = voxels[voxel_index // kBatchSize].load() | voxels_buffer[voxel_index // kBatchSize].load()
    
    # If already set, return
    if GETBIT(tmp, voxel_index):
        return

    queue = [voxel_index]
    
    while queue:
        voxel_index = queue.pop(0)
        
        # Reload bits
        tmp = voxels[voxel_index // kBatchSize].load() | voxels_buffer[voxel_index // kBatchSize].load()
        
        if not GETBIT(tmp, voxel_index):
            SETBIT(voxels_buffer, voxel_index)
            
            # Convert voxel index to 3D coordinates
            top_voxel = ConvIndexToVoxel(voxel_index)
            
            # Check 6 neighbors
            for i in range(6):
                new_voxel = top_voxel + D_6[i]
                
                # Check bounds
                if not InRange(new_voxel, mesh_vox_lb, mesh_vox_ub):
                    continue
                
                new_index = ConvVoxelToIndex(new_voxel)
                tmp_new = voxels[new_index // kBatchSize].load() | voxels_buffer[new_index // kBatchSize].load()
                
                if not GETBIT(tmp_new, new_index):
                    queue.append(new_index)
```

### Parameters
- `gridVoxelSize`: Physical size of one side of a voxel [S1, unofficial].
- `kBatchSize`: Number of voxels per bitset word (implementation detail) [S2, unofficial].

### Edge Cases and Pitfalls
- **Singular Points**: Single-point singularities can cause errors in scan-filling. Mitigated by intersecting results from three axis directions [S3, unofficial].
- **Planar Tests**: Zero dot products require specific normal direction checks to avoid ambiguity [S1, unofficial].
- **Non-Watertight Meshes**: Basic flood fill may fail on non-watertight meshes. The filter-and-refine strategy handles this by filling visible voxels first [S2, unofficial].

## Subtopics

### [Single-pass GPU Solid Voxelization](3323-single-pass-gpu-solid-voxelization.md)
A technique to voxelize the interior of watertight 3D models into a high-resolution binary volume with solid interior in a single rendering pass, using bitwise arithmetic to pack information. It builds on [Single-pass GPU Solid Voxelization](3323-single-pass-gpu-solid-voxelization.md) by exploiting the Jordan curve theorem: a point is interior if a ray from it intersects the surface an odd number of times. It distinguishes itself from boundary-only voxelization by producing a fully filled interior volume. Unlike depth peeling which requires multiple passes and occlusion queries, this method performs solid voxelization in a single geometry rendering pass.

### Solid Voxelization via Filter-and-Refine
A technique to fill the interior of a mesh to create a solid voxel representation. It uses a filter-and-refine strategy to optimize basic flood fill, avoiding the need for watertight meshes [S2, unofficial].
- **Filter Step**: Fill voxels along each axis. For a fixed pair of coordinates (e.g., fix x, y), enumerate z in [0, maxz]. If a voxel (x,y,z) is occupied (by surface voxelization), stop filling in that direction. This marks all voxels visible along that axis [S2, unofficial].
- **Refine Step**: Identify 'holes'—voxels that are not marked as visible along any axis. Perform a standard flood fill specifically on these remaining empty voxels to fill the interior [S2, unofficial].
- **Pitfall**: Holes exist because the filter step alone does not fill the entire interior; some interior voxels are occluded from all axis-aligned viewing directions [S2, unofficial].
- **Complexity**: Time Complexity is O(n), where n is the total number of voxels in the bounding box of the whole mesh [S2, unofficial].
- **Advantage**: Much more efficient than basic flood fill because the filter step uses lightweight operations, and the subsequent flood fill is only applied to a small number of holes [S2, unofficial].

## Operating characteristics
- **Time Complexity**: 
  - GPU Two-Pass: O(m*c), where m is the number of triangles and c is a factor related to voxel count or BFS overhead [S2, unofficial].
  - CPU Filter-and-Refine: O(n), where n is the total number of voxels in the bounding box [S2, unofficial].
- **Memory Complexity**: O(n) for the voxel grid, plus O(m) for mesh data [S2, unofficial].
- **Performance**: The GPU implementation leverages parallel processing for triangle-voxel intersection tests. The CPU filter-and-refine method is faster than basic flood fill due to the lightweight nature of the axis-aligned filling [S2, unofficial].
- **Strengths**: Handles complex geometries; GPU version is fast for high-resolution grids; Filter-and-Refine handles non-watertight meshes [S2, unofficial][S3, unofficial].
- **Limitations**: Basic flood fill is too heavy and time-consuming without optimization [S2, unofficial]. Singular points can cause errors in single-direction scan-filling [S3, unofficial].

## Background
Solid Voxelization is an extension of surface voxelization, designed to fill the inner region of closed objects [S3, unofficial]. The algorithm described in [S1, unofficial] implements the method from doi:10.1145/1882261.1866201. The technique utilizes programmable graphics hardware for flexible and adjustable computation, exploiting features like huge texture sizes and dynamic vertex buffers [S3, unofficial].
