# Mesh Winding Number Voxelization
Also called: Hierarchical Mesh Winding Number Voxelization

## Overview
Mesh Winding Number Voxelization determines the interior of a 3D mesh by evaluating the Mesh Winding Number (MWN) at sample points within a voxel grid [S1, unofficial]. Unlike [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) or [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md), which rely on ray-mesh intersections, this method computes a scalar field based on the solid angle subtended by the mesh triangles [S1, unofficial]. It is distinct from [Front/Back Face Flagging](1506-front-back-face-flagging.md) and [Tight Voxelization (Point-in-Mesh Test)](1709-tight-voxelization-point-in-mesh-test.md) because it yields an integer value for closed meshes and smoothly diffuses around open boundaries, allowing it to correctly handle non-manifold geometry and meshes with holes [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A triangular mesh and a target grid resolution (`numcells`) [S1, unofficial].
- Output: A 3D boolean bitmap (`Bitmap3`) where `true` indicates the voxel center is inside the mesh [S1, unofficial].

**Data Structures:**
- `Bitmap3`: A 3D array of bits. Internally, bits are packed into 32-bit integers [S1, unofficial]. Due to the lack of atomic read-and-flip operations on individual bits within a 32-bit integer, concurrent writes require synchronization (e.g., a `SpinLock`) to prevent race conditions [S1, unofficial].
- `ShiftGridIndexer3`: Maps grid indices $(i, j, k)$ to world coordinates $(x, y, z)$ using a bounding box minimum and a uniform cell size [S1, unofficial].

**Parameters:**
- `numcells`: The resolution of the voxel grid along one axis [S1, unofficial].
- `bounds`: The axis-aligned bounding box of the mesh [S1, unofficial].
- `cellsize`: Calculated as `bounds.MaxDim / numcells` [S1, unofficial].
- `threshold`: The MWN value above which a point is considered inside. Typical value: $0.5$. Values like $0.8$ may result in missing chunks for meshes with holes [S1, unofficial].

**Steps:**
1. **Calculate Grid Parameters:** Determine `cellsize` from the mesh bounding box and `numcells`. Create a `ShiftGridIndexer3` using `bounds.Min` and `cellsize` [S1, unofficial].
2. **Seed Hierarchical Cache:** Call `WindingNumber` on a point known to be outside the mesh (e.g., the origin) to initialize the hierarchical acceleration structure [S1, unofficial].
3. **Parallel Evaluation:** Iterate over all grid indices $(i, j, k)$ in parallel [S1, unofficial].
4. **Coordinate Mapping:** For each index, compute the world coordinate $v$ using `indexer.FromGrid(idx)` [S1, unofficial].
5. **Winding Number Computation:** Compute the MWN at $v$ using the hierarchical tree structure [S1, unofficial].
6. **Voxel Assignment:** Set the voxel to `true` if `WindingNumber(v) > threshold`, otherwise `false`. Use a thread-safe set operation (e.g., `SafeSet`) to handle concurrent writes [S1, unofficial].

**Pseudocode:**
```python
def mesh_winding_number_voxelization(mesh, numcells):
    bounds = mesh.get_bounding_box() # [G] Standard bounding box query
    cellsize = bounds.max_dim / numcells
    dims = (numcells + 2, numcells + 2, numcells + 2)
    bitmap = [[[False] * dims[2] for _ in range(dims[1])] for _ in range(dims[0])]
    tree = build_aabb_tree(mesh) # [G] Build hierarchical bounding volume hierarchy
    tree.winding_number([0.0, 0.0, 0.0]) # Seed cache outside mesh
    def process_voxel(i, j, k):
        v = [bounds.min.x + i * cellsize, bounds.min.y + j * cellsize, bounds.min.z + k * cellsize]
        w = tree.winding_number(v)
        # Use thread-safe set (e.g., SpinLock) to avoid race conditions on BitArray [S1, unofficial]
        bitmap[i][j][k] = (w > 0.5)
    parallel_for_each(dims, process_voxel) # [G] Parallel iteration over grid indices
    return bitmap
```

**Edge Cases and Pitfalls:**
- **Race Conditions:** Writing to the `Bitmap3` from multiple threads without synchronization causes data corruption because bits are packed into 32-bit integers. Use `SafeSet` or equivalent atomic operations [S1, unofficial].
- **Threshold Selection:** Using a high threshold (e.g., $0.8$) for meshes with holes can lead to incomplete voxelization ("missing chunks"). A threshold of $0.5$ is recommended [S1, unofficial].
- **Non-Hierarchical Performance:** Computing the winding number without the hierarchical AABB tree acceleration is extremely slow for large grids (e.g., >1 minute for $64^3$) [S1, unofficial].

## Subtopics

### [Generalized Winding Number Voxelization](7623-generalized-winding-number-voxelization.md)
Generalized Winding Number Voxelization constructs a binary image (voxelization) from a set of oriented point clouds in $\mathbb{R}^3$ by evaluating an implicit surface defined by the generalized winding number framework. It differs from standard mesh voxelization by operating directly on oriented point clouds without requiring a manifold mesh, using the winding number to handle non-manifold geometry and holes via smooth diffusion. It builds on [Mesh Winding Number Voxelization](2328-mesh-winding-number-voxelization.md) by providing the specific implementation for point clouds using the libIGL backend.

## Operating characteristics
- **Time Complexity:** Not given in the sources [S1, unofficial].
- **Measured Performance:** On a 6-core/12-thread machine in Release build, computing a $64^3$ voxelization takes 1–2 seconds using the hierarchical version [S1, unofficial].
- **Memory Complexity:** Not given in the sources [S1, unofficial].
- **Strengths:** Handles non-manifold geometry, open boundaries, and self-intersections robustly. It does not require the mesh to be watertight [S1, unofficial].
- **Limitations:** Computationally more expensive per voxel than simple ray casting for closed, manifold meshes. Requires careful handling of thread safety for the output bitmap [S1, unofficial].
- **When to Use:** When the mesh has holes, is non-manifold, or when a smooth transition around boundaries is desired [S1, unofficial].
- **When Not to Use:** For simple, closed, manifold meshes where performance is critical and ray-casting methods are sufficient [G].

## Background
The Mesh Winding Number was introduced by Alec Jacobson, Ladislav Kavan, and Olga Sorkine-Hornung in a SIGGRAPH paper in 2013 [S1, unofficial]. It extends the concept of the 2D polygon winding number to 3D meshes, providing a robust way to determine point containment [S1, unofficial]. The hierarchical implementation leverages bounding volume hierarchies to accelerate the computation for large-scale voxelization tasks [S1, unofficial].
