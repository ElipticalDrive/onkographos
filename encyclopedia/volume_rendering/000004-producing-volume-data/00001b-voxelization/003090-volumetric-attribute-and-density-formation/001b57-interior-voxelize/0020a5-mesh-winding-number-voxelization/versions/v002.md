# Mesh Winding Number Voxelization
Also called: Hierarchical Mesh Winding Number Voxelization

## Overview
Mesh Winding Number Voxelization determines the interior of a mesh by evaluating the Mesh Winding Number (MWN) at sample points within a voxel grid [S1, unofficial]. It differs from sibling methods like [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxelization.md) or [Front/Back Face Flagging](1506-front-back-face-flagging.md) by computing a hierarchical field evaluation rather than relying on ray intersection parity or face orientation [S1, unofficial]. It sets itself apart by yielding an integer value for closed meshes and a smoothly diffusing value around open boundaries, allowing for a consistent threshold-based classification [S1, unofficial].

## How it works
**Inputs:**
- A triangular mesh [S1, unofficial].
- A base voxel grid resolution per axis, `numcells` [S1, unofficial].
- The spatial bounds of the mesh, specifically the minimum corner and maximum dimension [S1, unofficial].

**Outputs:**
- A 3D boolean bitmap representing the interior voxels [S1, unofficial].

**Data Structures:**
- `Bitmap3`: A 3D boolean array. Internally, bits are packed into 32-bit integers [S1, unofficial]. Concurrent writes require synchronization via a `SpinLock` using a method like `SafeSet` [S1, unofficial].
- Grid indexer: Maps integer grid indices $(i, j, k)$ to 3D world coordinates $(x, y, z)$ using a minimum corner vector and a cell size [S1, unofficial].

**Parameters:**
- `numcells`: Base resolution per axis [S1, unofficial].
- `cellsize`: Derived from mesh bounds. $cellsize = \frac{\text{bounds.MaxDim}}{numcells}$ [S1, unofficial].
- `threshold`: Classification threshold. Typical value: $0.5$. Values like $0.8$ may result in missing chunks for meshes with holes [S1, unofficial].

**Steps:**
1. Initialize the output grid dimensions to $(numcells+2, numcells+2, numcells+2)$ [S1, unofficial].
2. Calculate `cellsize` from the mesh bounds and `numcells` [S1, unofficial].
3. Create a grid indexer mapping grid indices to world coordinates using the bounds minimum corner and `cellsize` [S1, unofficial].
4. Seed the hierarchical cache by calling `WindingNumber` on a point outside the mesh (e.g., the origin) [S1, unofficial].
5. Parallelize evaluation over all grid indices [S1, unofficial].
6. For each index, map to a 3D world coordinate [S1, unofficial].
7. Compute the MWN at the coordinate and set the voxel to true if the value is greater than $0.5$ [S1, unofficial].

**Pseudocode:**
```python
def mesh_winding_number_voxelization(mesh, numcells):
    # 1. Calculate bounds and cell size [S1, unofficial]
    bounds_min = mesh.bounds.min
    max_dim = mesh.bounds.max_dim
    cellsize = max_dim / numcells

    # 2. Initialize grid with dimensions numcells + 2 per axis [S1, unofficial]
    grid_dims = (numcells + 2, numcells + 2, numcells + 2)
    bitmap = [[[False] * grid_dims[2] for _ in range(grid_dims[1])] for _ in range(grid_dims[0])]

    # 3. Define grid-to-world mapping [S1, unofficial]
    def grid_to_world(idx):
        return (bounds_min.x + idx[0] * cellsize,
                bounds_min.y + idx[1] * cellsize,
                bounds_min.z + idx[2] * cellsize)

    # 4. Seed hierarchical cache with an outside point (e.g., origin) [S1, unofficial]
    mesh.aabb_tree.winding_number((0.0, 0.0, 0.0))

    # 5. Parallel evaluation over all grid indices [S1, unofficial]
    def process_voxel(idx):
        world_pos = grid_to_world(idx)
        wn = mesh.aabb_tree.winding_number(world_pos)
        # 6. Set voxel if MWN > threshold [S1, unofficial]
        if wn > 0.5:
            bitmap_safe_set(bitmap, idx, True) # Thread-safe write using SpinLock [S1, unofficial]

    # Standard parallel iteration construct [G]
    parallel_for(grid_indices(grid_dims), process_voxel)
    return bitmap
```

**Edge Cases and Pitfalls:**
- **Race Conditions:** Writing to a `BitArray` from multiple threads without synchronization causes data corruption because bits are packed into 32-bit integers and cannot be read-and-flipped atomically [S1, unofficial]. `SafeSet` with a `SpinLock` is required [S1, unofficial].
- **Threshold Selection:** For meshes with holes, the MWN diffuses smoothly [S1, unofficial]. A threshold of $0.5$ is standard, but higher thresholds (e.g., $0.8$) cause significant parts of the interior to be missed [S1, unofficial].
- **Performance:** The hierarchical evaluation is critical for large grids [S1, unofficial]. The non-hierarchical version takes well over a minute for a $64^3$ grid, while the hierarchical version takes 1-2 seconds on a 6-core/12-thread machine in Release build [S1, unofficial].

## Background
The Mesh Winding Number was introduced by Alec Jacobson, Ladislav Kavan, and Olga Sorkine-Hornung in a SIGGRAPH paper in 2013 [S1, unofficial]. It extends the concept of the 2D polygon winding number to 3D meshes [S1, unofficial]. For closed meshes, it yields an integer value (1 inside, 0 outside), while for meshes with holes, it diffuses smoothly around the boundaries [S1, unofficial]. This property makes it particularly useful for voxelization tasks where mesh quality may vary or where open boundaries are present [S1, unofficial].
