# Inside-Outside Voxelization

Also called: Stencil Shadow Volume Voxelization, Stencil-based Interior Voxelize

## Overview
Inside-Outside Voxelization determines whether a grid cell lies inside or outside a solid obstacle by leveraging stencil buffer operations, inspired by stencil shadow volume algorithms [S1, unofficial]. It distinguishes interior cells (nonzero stencil value) from exterior cells (zero stencil value), serving as the core step for solid obstacle voxelization in fluid simulation [S1, unofficial]. It sets itself apart from boundary-focused methods by explicitly classifying the volume interior, relying on the topological property that a closed mesh has one back face for every front face [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: A triangle mesh representing a solid obstacle.
*   Output: A 3D texture (or voxel grid) where each cell contains a boolean or integer indicating interior/exterior status.

**Data Structures:**
*   **Stencil Buffer:** A 2D buffer with dimensions matching the current slice of the 3D texture. Initialized to zero.
*   **3D Texture:** The destination volume. Each slice corresponds to a specific depth plane.

**Parameters:**
*   **Near Clip Plane:** Set to the depth of the current slice being processed [S1, unofficial].
*   **Far Clip Plane:** Set to infinity [S1, unofficial].
*   **Stencil Operations:**
    *   Back faces: Increment stencil value (with wrapping) [S1, unofficial].
    *   Front faces: Decrement stencil value (with wrapping) [S1, unofficial].

**Steps:**
1.  Iterate through each slice (depth plane) of the destination 3D texture.
2.  For the current slice:
    a. Initialize the 2D stencil buffer to zero.
    b. Set the near clip plane to the depth of the current slice and the far clip plane to infinity.
    c. Configure the stencil test to increment on back-face depth passes and decrement on front-face depth passes, with wrapping enabled for both operations.
    d. Render the input triangle mesh into the current slice using an orthogonal projection. This populates the stencil buffer based on the winding order and visibility of triangles relative to the viewing direction (which aligns with the slice normal).
    e. Perform a final pass to copy the stencil buffer values into the corresponding cells of the 3D texture.
3.  After processing all slices, classify cells:
    *   Nonzero stencil value: Interior cell.
    *   Zero stencil value: Exterior cell.
    *   Note: Cells that are interior but adjacent to the boundary may be tagged by the subsequent velocity voxelization algorithm, not this one [S1, unofficial].

**Pseudocode:**
```python
def inside_outside_voxelization(mesh, volume_dimensions):
    # volume_dimensions: (width, height, depth)
    # mesh: list of triangles
    
    # Initialize 3D texture with zeros
    inside_outside_texture = zeros(volume_dimensions)
    
    # Iterate over each slice (z-axis)
    for z in range(volume_dimensions[2]):
        # Initialize stencil buffer for this slice
        stencil_buffer = zeros((volume_dimensions[0], volume_dimensions[1]))
        
        # Set up rendering state for this slice
        near_clip = z
        far_clip = infinity
        projection = orthogonal_projection(near_clip, far_clip)
        
        # Configure stencil operations
        # Increment on back face, decrement on front face, with wrapping
        stencil_op_back = increment_wrap
        stencil_op_front = decrement_wrap
        
        # Render mesh into stencil buffer
        # The rasterizer determines front/back faces based on winding order
        # and visibility relative to the orthogonal view direction (along z)
        render_mesh_to_stencil(mesh, stencil_buffer, stencil_op_back, stencil_op_front)
        
        # Copy stencil values to the 3D texture
        for y in range(volume_dimensions[1]):
            for x in range(volume_dimensions[0]):
                inside_outside_texture[x, y, z] = stencil_buffer[x, y]
                
    return inside_outside_texture
```

**Edge Cases and Pitfalls:**
*   **Watertight Requirement:** The method depends on having one back face for every front face. It is best suited to watertight closed meshes [S1, unofficial]. Non-watertight meshes may produce incorrect interior classifications.
*   **Boundary Cells:** Cells interior but next to the boundary are not reliably tagged by this algorithm alone; they are handled by the velocity voxelization algorithm [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of slices times the number of triangles rendered per slice. Each triangle is processed once per slice it intersects.
*   **Memory Complexity:** Requires a stencil buffer of size $W \times H$ per slice and the output 3D texture of size $W \times H \times D$.
*   **Strengths:** Efficiently classifies interior/exterior for closed meshes using standard GPU rasterization primitives.
*   **Limitations:** Requires watertight meshes. Does not handle boundary-adjacent interior cells directly.
*   **When to use:** When voxelizing solid obstacles for fluid simulation where interior/exterior distinction is needed for closed meshes.
*   **When not to use:** For non-watertight meshes or when boundary-adjacent cell classification is required without additional processing.

## Background
This method is described in "Real-Time Simulation and Rendering of 3D Fluids" [S1, unofficial]. It is inspired by stencil shadow volume algorithms, adapting the technique of counting front/back face intersections to determine volume occupancy. It is used in the context of GPU-based fluid simulation to create obstacle representations.
