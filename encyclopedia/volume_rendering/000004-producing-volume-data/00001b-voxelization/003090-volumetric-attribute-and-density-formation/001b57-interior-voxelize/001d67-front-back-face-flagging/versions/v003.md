# Front/Back Face Flagging

Also called: Voxel Surface Orientation

## Overview
Front/Back Face Flagging assigns a boolean orientation flag to voxels intersected by a mesh surface, distinguishing whether the intersecting triangle is front-facing or back-facing relative to a specified filling direction [S1]. This method solves the ambiguity of surface orientation during voxelization, providing the necessary geometric context for subsequent interior filling algorithms to determine which voxels lie inside the mesh [S1]. It differs from sibling methods like [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) or [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) by explicitly tracking surface normal orientation per voxel rather than relying on ray intersection counts or probabilistic sampling to determine volume status [S1].

## How it works
**Inputs:**
*   A triangular mesh defined by vertices $A, B, C$.
*   A 3D voxel grid (array of voxel structures).
*   A filling direction vector $\vec{d}$ (e.g., $(0, 0, 1)$) [S1].

**Outputs:**
*   The voxel grid where intersected voxels have `fill = 1` and `front` flag set according to the triangle's orientation relative to $\vec{d}$ [S1].

**Data Structures:**
Each voxel in the grid contains at least the following fields:
*   `fill`: Boolean or integer (1 if the voxel is part of the mesh surface, 0 otherwise).
*   `front`: Boolean indicating if the intersecting triangle is front-facing relative to $\vec{d}$.
*   `position`: Vector3 representing the center of the voxel [S1].

**Algorithm Steps:**

1.  **Triangle Normal Calculation:**
    Compute the unnormalized normal $\vec{n}_{raw}$ using the cross product of two edge vectors:
    $$ \vec{n}_{raw} = (B - A) \times (C - A) $$
    Normalize to get $\vec{n}$:
    $$ \vec{n} = \frac{\vec{n}_{raw}}{\|\vec{n}_{raw}\|} $$
    [S1]

2.  **Front/Back Determination:**
    Calculate the dot product between the triangle normal $\vec{n}$ and the filling direction $\vec{d}$. The triangle is considered front-facing if the dot product is less than or equal to zero:
    $$ \text{front} = (\vec{n} \cdot \vec{d} \le 0) $$
    This implies that if the normal points opposite to the viewing/filling direction, the face is front-facing [S1].

3.  **Voxel Intersection and Flagging:**
    For each voxel in the grid:
    a. Check if the voxel's Axis-Aligned Bounding Box (AABB) intersects the triangle. This is typically done by checking if the triangle's AABB intersects the voxel's AABB, followed by a precise plane-AABB intersection test [S1].
    b. If an intersection occurs:
       i. Set `voxel.fill = 1`.
       ii. If `voxel.fill` was previously 0 (not yet marked), set `voxel.front = front`.
       iii. If `voxel.fill` was already 1 (already marked by another triangle), update the flag using logical AND:
       $$ \text{voxel.front} = \text{voxel.front} \ \& \ \text{front} $$
       This prioritizes the back-facing state; if a voxel is intersected by both a front and a back face, the resulting flag is false (back) [S1].

**Pseudocode:**

```python
def compute_front_back_flag(triangle, voxel_grid, fill_direction):
    """
    triangle: object with attributes a, b, c (Vector3)
    voxel_grid: 3D array of Voxel objects
    fill_direction: Vector3
    """
    # 1. Calculate Normal
    edge1 = triangle.b - triangle.a
    edge2 = triangle.c - triangle.a
    normal_raw = cross(edge1, edge2)
    normal = normalize(normal_raw)
    
    # 2. Determine Front/Back status for this triangle
    # Front if dot product <= 0
    is_front = dot(normal, fill_direction) <= 0.0
    
    # 3. Iterate over voxels (optimization: only check voxels within triangle's AABB)
    for x, y, z in voxel_grid.indices_intersecting(triangle.aabb):
        voxel = voxel_grid[x, y, z]
        
        # Check intersection between triangle and voxel AABB
        if intersects_triangle_aabb(triangle, voxel.aabb):
            voxel.fill = 1
            voxel.position = voxel.aabb.center
            
            if voxel.fill == 0:
                # First time marking this voxel
                voxel.front = is_front
            else:
                # Already marked: prioritize back (AND logic)
                # If current is_front is False (back), result becomes False
                # If current is_front is True (front), result stays True only if new is_front is True
                voxel.front = voxel.front and is_front
            
            voxel_grid[x, y, z] = voxel

def intersects_triangle_aabb(triangle, aabb):
    """
    Simplified intersection check using Plane-AABB intersection.
    """
    # Create plane from triangle
    # Plane equation: N . X + D = 0
    # D = -N . A
    normal = triangle.normal
    distance = -dot(normal, triangle.a)
    plane = Plane(normal, distance)
    
    # Check if plane intersects AABB
    center = aabb.center
    extents = aabb.max - center
    
    # Project extents onto normal
    r = (abs(plane.normal.x) * extents.x +
         abs(plane.normal.y) * extents.y +
         abs(plane.normal.z) * extents.z)
    
    # Distance from plane center to AABB center
    s = dot(plane.normal, center) - plane.distance
    
    return abs(s) <= r
```

**Parameters:**
*   `fill_direction`: The direction vector used to determine orientation. In the reference implementation, this is $(0, 0, 1)$ [S1].

**Edge Cases and Pitfalls:**
*   **Degenerate Triangles:** If the triangle vertices are collinear, the normal calculation results in a zero vector, causing normalization to fail. [G] Guard against zero-length normals by skipping such triangles.
*   **Non-Watertight Meshes:** If the mesh is not closed, the front/back flags may not correctly enclose a volume, leading to incorrect interior filling in subsequent steps [S1].
*   **Precision:** Floating-point precision errors in the dot product or cross product may cause ambiguous orientation for triangles nearly parallel to the filling direction. [G] Use a small epsilon threshold when comparing the dot product to zero if necessary.

## Subtopics

### Inside-Outside Voxelization
Determines whether a grid cell is inside or outside a solid obstacle using stencil buffer operations, inspired by stencil shadow volumes [S2, unofficial]. It renders the input triangle mesh into each slice of a 3D texture using an orthogonal projection, initializing a stencil buffer to zero. Stencil operations increment for back faces and decrement for front faces (with wrapping). Interior cells receive a nonzero stencil value [S2, unofficial]. It depends on having one back face for every front face, making it best suited to watertight closed meshes [S2, unofficial]. Far clip plane is set to infinity, and near clip plane matches the depth of the current slice [S2, unofficial].

### Solid Mesh Auto-Fill
A feature to auto-fill the interior of a surface mesh during voxelization, converting the mesh into a solid volume [S3]. It is considerably slower and not robust, potentially leading to artifacts and holes in complex meshes [S3]. Setting this flag turns off greyscale values (background becomes 0, mesh becomes 255) because material data inside the mesh is unavailable [S3]. The flag is ignored if the input contains only Tetrahedron data or if the `use_tetra` flag is set, as these are not surface meshes [S3].

### Inside/Outside Inversion
By default, values above the surface level are considered internal. When enabled, this option swaps the inside and outside definitions [S4].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of triangles and $M$ is the number of voxels intersected by those triangles. In practice, spatial acceleration structures (like AABB trees or voxel grids) reduce the number of intersection tests [S1].
*   **Memory Complexity:** $O(V)$, where $V$ is the total number of voxels in the grid, as each voxel stores `fill` and `front` flags [S1].
*   **Strengths:** Simple to implement; provides explicit orientation data required for directional filling algorithms [S1].
*   **Limitations:** Requires a defined filling direction; does not inherently handle non-watertight meshes or complex topology without additional logic [S1]. The related "Solid Mesh Auto-Fill" variant is noted as slow and prone to artifacts [S3].

## Background
The method originates from real-time GPU-based voxelization techniques, specifically detailed in the context of Unity graphics programming and real-time fluid simulation [S1][S2, unofficial]. It is used to prepare voxel data for subsequent interior filling processes, such as those found in fluid dynamics simulations where distinguishing between interior and exterior voxels is critical [S1][S2, unofficial].
