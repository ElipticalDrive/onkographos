# Tight Voxelization (Point-in-Mesh Test)
Also called: Interior Voxel Verification, Point-in-Mesh Test, Tetrahedron Point-Inclusion Test

## Overview
Tight Voxelization is an optional post-processing step applied after an initial solid voxelization pass to verify if the center point of each candidate voxel lies strictly inside the input mesh, removing those determined to be outside [S1, unofficial]. It is primarily used for volume meshes (tetrahedral) where a specific point-in-tetrahedron test is employed, distinguishing it from surface mesh approaches that rely on ray casting or winding numbers [S2]. Unlike [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) which probabilistically determines occupancy, this method provides a deterministic geometric check on the voxel center [S2].

## How it works
**Inputs and Outputs:**
- Input: A set of candidate voxels (typically generated by a parent method like [Interior Voxelize](995-interior-voxelize.md)) and a volume mesh defined by tetrahedra.
- Output: A refined set of voxels where only those with centers inside the mesh are retained.

**Data Structures:**
- **Voxel Center:** A 3D point $P = (x, y, z)$.
- **Tetrahedron:** Defined by four vertices $A, B, C, D$.
- **Triangle:** A face of the tetrahedron defined by three vertices.

**Algorithm Steps:**
The method checks if a point $P$ is inside a tetrahedron defined by vertices $A, B, C, D$ [S2].

1.  **Decompose Tetrahedron:** Identify the four triangular faces of the tetrahedron: $(A,B,C)$, $(A,B,D)$, $(A,C,D)$, and $(B,C,D)$ [S2].
2.  **Calculate Normals:** For each triangle, calculate its normal vector. The normal $\mathbf{n}$ for a triangle with vertices $V_1, V_2, V_3$ is computed as the cross product of two edge vectors:
    $$ \mathbf{n} = (V_2 - V_1) \times (V_3 - V_1) $$
    The vertices must be ordered such that the normal points *away* from the interior of the tetrahedron (outward-facing) [S2].
3.  **Plane Test:** For each of the four triangles, determine the side of the plane on which point $P$ lies. This is done by computing the dot product of the triangle's normal $\mathbf{n}$ and the vector from a vertex on the plane (e.g., $V_1$) to the point $P$:
    $$ d = \mathbf{n} \cdot (P - V_1) $$
4.  **Classification:** If $P$ is on the opposite side of the plane for all four triangles (i.e., the dot product $d$ is negative for all outward-facing normals, assuming standard right-hand rule orientation where outward normals yield negative values for interior points), then $P$ is classified as inside the tetrahedron [S2]. If $P$ is outside any one of the four planes, it is outside the tetrahedron.

**Parameters:**
- `--tight`: A command-line flag to enable this verification. Default is `false` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Performance:** This option is time-consuming because it requires a geometric test for every voxel against the mesh geometry [S1, unofficial].
- **Orientation:** The correctness of the test depends on the consistent outward orientation of the tetrahedron's faces [S2].
- **Precision:** Floating-point precision errors may cause points exactly on the boundary to be misclassified [G].

**Pseudocode:**
```python
def is_point_in_tetrahedron(P, A, B, C, D):
    """
    Checks if point P is inside tetrahedron ABCD.
    Assumes vertices are ordered such that normals point outward.
    """
    # Define the four faces
    faces = [
        (A, B, C),
        (A, B, D),
        (A, C, D),
        (B, C, D)
    ]
    
    for V1, V2, V3 in faces:
        # Calculate normal vector (outward)
        # Edge vectors
        edge1 = [V2[i] - V1[i] for i in range(3)]
        edge2 = [V3[i] - V1[i] for i in range(3)]
        
        # Cross product
        normal = [
            edge1[1] * edge2[2] - edge1[2] * edge2[1],
            edge1[2] * edge2[0] - edge1[0] * edge2[2],
            edge1[0] * edge2[1] - edge1[1] * edge2[0]
        ]
        
        # Vector from vertex to point P
        vec_to_P = [P[i] - V1[i] for i in range(3)]
        
        # Dot product
        dot_product = sum(normal[i] * vec_to_P[i] for i in range(3))
        
        # If dot product is positive, P is on the "outside" side of this face
        # (assuming outward normals). If negative or zero, it is on the inside side.
        if dot_product > 0:
            return False
            
    return True

def tight_voxelization(voxels, tetrahedra):
    """
    Filters voxels based on whether their center is inside the mesh.
    """
    valid_voxels = []
    for voxel in voxels:
        center = voxel.center
        # Determine which tetrahedron (if any) contains this center.
        # In a volume mesh, a point might be in multiple tetrahedra or none.
        # The method described in [S2] implies checking containment within 
        # the specific tetrahedron defining the volume. 
        # For a general mesh, one must iterate through tetrahedra.
        
        inside = False
        for tet in tetrahedra:
            if is_point_in_tetrahedron(center, *tet.vertices):
                inside = True
                break # Found a containing tetrahedron
        
        if inside:
            valid_voxels.append(voxel)
            
    return valid_voxels
```

## Operating characteristics
- **Time Complexity:** $O(V \cdot T)$ in the naive implementation where $V$ is the number of voxels and $T$ is the number of tetrahedra, as each voxel center may need to be tested against the mesh. Optimizations can reduce this by spatial indexing, but the source notes do not specify such optimizations [S1, unofficial][S2].
- **Memory Complexity:** $O(V)$ to store the voxel grid and $O(T)$ for the mesh data.
- **Performance:** The operation is noted as "time-consuming" [S1, unofficial]. It is significantly slower than the initial solid voxelization pass.
- **Strengths:** Provides a deterministic check for volume meshes (tetrahedral) [S2].
- **Limitations:** High computational cost [S1, unofficial]. Only applicable to volume meshes or requires decomposition for surface meshes [S2].

## Background
This method is implemented in the `CudaVox` library, which is part of the `cad2vox` project [S2]. It is designed for volume meshes based on tetrahedrons, contrasting with the surface mesh voxelization methods (like those by Schwarz and Seidel) also supported by `CudaVox` [S2]. The approach is a straightforward geometric inclusion test [S2].
