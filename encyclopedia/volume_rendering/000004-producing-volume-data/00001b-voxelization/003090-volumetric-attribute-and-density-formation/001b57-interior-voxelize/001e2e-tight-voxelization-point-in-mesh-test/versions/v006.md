# Tight Voxelization (Point-in-Mesh Test)

Also called: Interior Voxel Verification, Point-in-Mesh Test, Tetrahedron Point-Inclusion Test

## Overview
Tight Voxelization is an optional post-processing step that verifies if the center point of each voxel is inside or outside the mesh, removing voxels determined to be outside [S1, unofficial]. It applies explicit geometric containment tests to candidate voxels [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of candidate voxels and the source mesh [S1, unofficial].
*   **Output:** A filtered voxel grid retaining only centers classified as inside the mesh [S1, unofficial].

**Data Structures:**
*   **Voxel Center:** A 3D point $P = (x, y, z)$ representing the geometric center of the voxel [S2].
*   **Mesh Element:** For volume meshes, a tetrahedron defined by four vertices $A, B, C, D$ [S2]. For triangle meshes, CudaVox implements an optimized version of the method from Schwarz and Seidel (2010) rather than the point-in-tetrahedron test [S2].

**Algorithm Steps:**
1.  **Identify Candidate Tetrahedron:** For a voxel center $P$, identify the tetrahedron $T$ (vertices $A, B, C, D$) that potentially contains $P$ [S2].
2.  **Compute Face Normals:** For each of the four faces of the tetrahedron, calculate the normal vector [S2].
3.  **Orient Normals Outward:** Verify that the calculated normals point away from the center of the tetrahedron [S2].
4.  **Plane Side Test:** Check if point $P$ is on the opposite side of the plane for each of the four triangles [S2].
5.  **Classification:** If $P$ is on the opposite side of the plane for all four triangles, classify $P$ as inside the tetrahedron [S2].
6.  **Filtering:** Remove the voxel from the output if its center $P$ is determined to be outside the mesh [S1, unofficial].

**Formulas:**
*   Face normal for vertices $V_0, V_1, V_2$: $\vec{n} = \frac{(V_1 - V_0) \times (V_2 - V_0)}{\|(V_1 - V_0) \times (V_2 - V_0)\|}$ [G]
*   Outward orientation check: $\vec{n} \cdot (\text{center} - V_0) < 0$ [G]
*   Plane side test: $\vec{n} \cdot (P - V_0) < 0$ [G]

**Parameters:**
*   `--tight`: Boolean flag to enable this step. Default: `false` [S1, unofficial].
*   `voxel_size`: Determines the size of each voxel [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Performance Cost:** The option is time-consuming [S1, unofficial].
*   **Boundary Precision:** Points lying exactly on the mesh surface may yield $\vec{n} \cdot (P - V_0) = 0$. Implementation should handle floating-point epsilon errors to avoid incorrect classification at boundaries [G].

**Pseudocode:**
```python
def point_in_tetrahedron(P, A, B, C, D):
    vertices = [A, B, C, D]
    faces = [(A, B, C), (A, B, D), (A, C, D), (B, C, D)]
    center = (A + B + C + D) / 4.0
    for face in faces:
        V0, V1, V2 = face
        n = cross(V1 - V0, V2 - V0)
        n_len = sqrt(dot(n, n))
        if n_len == 0:
            return False
        n = n / n_len
        if dot(n, center - V0) > 0:
            n = -n
        if dot(n, P - V0) >= 0:
            return False
    return True
```

## Subtopics

### [Pivot Token Representation](14345-pivot-token-representation.md)
A compact voxelization method that encodes surface-intersecting voxels using a pivot point and orientation sign, differing from standard tight voxelization by storing geometric primitives for efficient multi-resolution reconstruction.

## Operating characteristics
*   **Time Complexity:** Not given in the sources [G]. The method is described as time-consuming [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [G].
*   **Strengths:** Produces a tighter, more accurate volume by removing false positives from the initial voxelization step [S1, unofficial].
*   **Limitations:** High computational cost; not suitable for real-time applications or very high-resolution grids without optimization [S1, unofficial].
*   **When to use:** When geometric accuracy is prioritized over speed, and the input mesh is tetrahedral or can be efficiently converted [S1, unofficial].

## Background
Tight Voxelization as a post-processing verification step is documented in the `voxelizer` tool by topskychen [S1, unofficial] and in the `CudaVox` component of `cad2vox` [S2]. The point-in-tetrahedron algorithm is a standard computational geometry technique, with implementations discussed in community resources like Stack Overflow [S2]. The specific integration into voxelization pipelines appears in open-source tools targeting CAD-to-voxel conversion [S2].
