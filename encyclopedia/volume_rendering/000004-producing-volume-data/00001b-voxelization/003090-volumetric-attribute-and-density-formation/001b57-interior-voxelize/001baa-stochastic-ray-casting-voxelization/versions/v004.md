# Stochastic Ray-Casting Voxelization

Also called: Probabilistic Inside-Outside Test, Randomized Direction Voxelization

## Overview
Stochastic Ray-Casting Voxelization determines the interior status of a voxel grid by casting multiple random rays from each voxel center and counting intersections with the input mesh triangles [S1, unofficial]. It differs from its sibling [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) and [Tight Voxelization (Point-in-Mesh Test)](1709-tight-voxelization-point-in-mesh-test.md) by replacing the deterministic single-ray parity test with a probabilistic majority vote over randomized directions, which provides robustness against non-manifold, broken, or self-intersecting meshes where a single ray might fail [S1, unofficial].

## How it works
**Inputs:**
- A watertight or non-watertight triangle mesh defined by a list of triangles.
- A voxel grid resolution `dimX`, `dimY`, `dimZ`.
- Parameter `samples`: Number of random rays to cast per voxel. Default is often 1 (deterministic) or higher (e.g., 5, 11) for broken meshes [S1, unofficial].
- Parameter `double_thick`: Boolean flag. If true, the mesh is treated as double-thick (watertight), affecting the logic in the `inside` function [S1, unofficial].

**Outputs:**
- A voxel grid where each voxel is marked as inside or outside.

**Data Structures:**
- `TriangleStruct`: Contains three `Vec3` members: `m_v1`, `m_v2`, `m_v3` [S1, unofficial].
- `Vec3`: Struct with a union containing `precision_type m_pos[3]` and individual members `m_x`, `m_y`, `m_z`. `precision_type` is `float` by default (`USE_DOUBLE false`) [S1, unofficial].
- `VoxelGrid`: Contains `bool *m_insideArray` of size `dimX * dimY * dimZ`. Accessor `isInside(i, j, k)` returns `m_insideArray[k*(m_dimX*m_dimY)+j*m_dimY + i]`. The layout is Z-major, where `k` is the most significant index in the linear array calculation [S1, unofficial].

**Algorithm Steps:**
1. Initialize `votes = 0` for the current voxel.
2. Loop `samples` times (variable `j`):
   a. Generate a random direction `dir` uniformly distributed on the unit sphere using polar-to-Euclidean conversion.
      - Generate two random numbers `u1, u2` from a uniform distribution $[0, 1)$.
      - Compute $\theta = u1 \cdot 2\pi$.
      - Compute $z = 2u2 - 1$.
      - Compute $r = \sqrt{1 - z^2}$.
      - Set $dir.x = r \cos(\theta)$, $dir.y = r \sin(\theta)$, $dir.z = z$.
      - *Note: The source implementation contains a bug where $dir.z$ is calculated as $r \cos(\theta)$ instead of $z$, resulting in a non-uniform distribution biased towards the x-y plane [S1, unofficial]. The correct formula above is provided for implementation.*
   b. Initialize `intersections = 0`.
   c. Loop over all triangles in the mesh (index `i` from 0 to `numTriangles`):
      - Check if the ray starting at `pos` (voxel center) with direction `dir` intersects the triangle `triangles[i]`.
      - If it intersects, increment `intersections`.
   d. Determine if the voxel is inside based on the intersection count.
      - If `double_thick` is true, check if `(intersections / 2) % 2 == 1`.
      - If `double_thick` is false, check if `intersections % 2 == 1`.
      - If the condition is true, increment `votes`.
3. After all samples are processed, determine the final inside/outside status.
   - If `votes > (samples / 2)`, set the voxel to inside (true).
   - Otherwise, set the voxel to outside (false).

                # Calculate voxel center position
                # Assuming mesh is normalized to [0, 1] or needs scaling

**Parameters:**
- `samples`: Number of random rays cast per voxel. Default is often 1 (deterministic) or higher (e.g., 5, 11) for broken meshes. Controlled by command line option `-s` [S1, unofficial].
- `double_thick`: Boolean flag. If true, the mesh is treated as double-thick (watertight), affecting the logic in the `inside` function. Controlled by command line option `-d` [S1, unofficial].

**Edge Cases and Pitfalls:**
- The source implementation contains a bug in the z-component calculation of the random direction: it uses `cosf(theta)` instead of `z`. This results in a non-uniform distribution where the z-axis is biased towards the x-y plane projection of the angle theta, rather than being independent [S1, unofficial]. Implementers should use the correct spherical coordinate generation formula.
- Broken or non-manifold meshes may require a higher number of samples to achieve a reliable majority vote [S1, unofficial].

## Subtopics

### [Solid Voxelization via 6-Direction Odd-Even Ray Parity](2320-solid-voxelization-via-6-direction-odd-even-ray-parity.md)
This method converts a normalized, watertight mesh into a solid voxel target by determining the inside/outside status of each voxel center using the parity of ray intersections along six axis-aligned directions. It differs from its parent [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) by using deterministic, axis-aligned rays and a majority vote on parity rather than random rays and intersection counts, providing a robust, non-stochastic solution for solid interior filling.

### [Monte Carlo Voxelization with Ray-Casting Optimization](14300-monte-carlo-voxelization-with-ray-casting-optimization.md)
This method approximates the geometric similarity between a voxel and a 3D object by sampling points within the voxel using rays, avoiding full volumetric intersection tests. It builds on [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) by organizing sampling into columns and optimizing the evaluation of occupancy and element membership, significantly reducing the computational cost of selecting the best approximating element from a palette.

## Operating characteristics
- **Time Complexity:** $O(V \cdot S \cdot T)$, where $V$ is the number of voxels, $S$ is the number of samples per voxel, and $T$ is the number of triangles in the mesh.
- **Memory Complexity:** $O(V)$ for the voxel grid, plus $O(T)$ for the mesh storage.
- **Performance:** GPU implementation is 400-2750 times faster than the provided CPU sample executable. For example, on an NVIDIA GTX970, it achieved a 396x speedup for a teapot (2464 tris, 64³) and a 2750x speedup for a bunny (69664 tris, 64³) [S1, unofficial].
- **Strengths:** Robustness against non-manifold or broken meshes due to probabilistic sampling. GPU acceleration provides significant speedups.
- **Limitations:** The stochastic nature means results may vary slightly between runs if the random seed is not fixed. The bug in the source code's random direction generation can lead to biased results if not corrected.
- **When to use:** When dealing with non-watertight or broken meshes where deterministic ray casting might fail.
- **When not to use:** When deterministic results are required and the mesh is known to be watertight and manifold, in which case deterministic methods like [Solid Voxelization via 6-Direction Odd-Even Ray Parity](2320-solid-voxelization-via-6-direction-odd-even-ray-parity.md) may be more appropriate.

## Background
Stochastic Ray-Casting Voxelization is a GPU-based voxelization technique that determines if a voxel center is inside a mesh by casting multiple random rays from the voxel center and counting intersections with mesh triangles [S1, unofficial]. It was developed as part of the `voxelizer` project by kctess5, which provides a simple voxelization utility for converting OBJ meshes to voxel grids [S1, unofficial]. The method is designed to handle non-manifold or broken meshes by using a majority vote over randomized directions rather than a single deterministic ray [S1, unofficial].
