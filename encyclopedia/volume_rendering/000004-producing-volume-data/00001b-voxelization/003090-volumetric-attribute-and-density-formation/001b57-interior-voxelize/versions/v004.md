# Interior Voxelize

Also called: Naive Model Filling, fillNaive

## Overview
Interior Voxelize determines which voxels in a discrete 3D grid lie strictly inside a closed surface mesh by sampling points within the grid volume and performing point-in-mesh containment tests [S1, S2, S3, unofficial]. It differs from its siblings [Shell-based Voxelization](1748-shell-based-voxelization.md) and [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) by avoiding surface rasterization or axis-aligned ray casting in favor of direct geometric queries against a spatial index, making it robust against non-manifold geometry and self-intersections where projection-based methods may fail [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A closed triangle mesh (e.g., `DMesh3` or `trimesh.Mesh`), a target voxel grid resolution `numcells` (or shape tuple), and a bounding box defining the spatial domain.
*   **Output:** A 3D boolean grid (e.g., `Bitmap3` or numpy array) where `True` indicates the voxel center is inside the mesh, and `False` indicates it is outside.

**Data Structures:**
1.  **Spatial Index:** A bounding volume hierarchy (BVH) or AABB tree (e.g., `DMeshAABBTree3`) built from the input mesh triangles to accelerate containment queries.
2.  **Grid Indexer:** A mapping structure (e.g., `ShiftGridIndexer3`) that converts discrete grid indices $(i, j, k)$ to continuous world coordinates $(x, y, z)$ based on the mesh bounding box and cell size.
3.  **Bitmap/Grid:** A 3D array of dimensions $(N_x, N_y, N_z)$ storing the occupancy status.

**Steps:**
1.  **Compute Bounding Box:** Calculate the axis-aligned bounding box (AABB) of the input mesh. Let $B_{min}$ be the minimum corner and $B_{max}$ be the maximum corner.
2.  **Determine Resolution:** Set the grid resolution `numcells`. A typical value is 32, or it may be derived from the desired cell size relative to the bounding box dimensions [S3, unofficial].
3.  **Calculate Cell Size:** Compute the uniform cell size $s$ using the maximum dimension of the bounding box:
    $$ s = \frac{\max(B_{max} - B_{min})}{\text{numcells}} $$
    [S3, unofficial]
4.  **Build Spatial Index:** Construct a spatial acceleration structure (e.g., `DMeshAABBTree3`) from the mesh triangles with auto-build enabled [S1, S3, unofficial].
5.  **Initialize Grid:** Create a 3D boolean array `grid` of size $(\text{numcells}, \text{numcells}, \text{numcells})$ initialized to `False` (or `VOXEL_FREE`) [S1, S3, unofficial].
6.  **Iterate and Query:** For each grid index $(i, j, k)$ in the grid:
    a. Map the grid index to a world coordinate $P$ using the Grid Indexer: $P = \text{Indexer.FromGrid}(i, j, k)$ [S3, unofficial].
    b. Perform a point-in-mesh containment test: $inside = \text{SpatialIndex.IsInside}(P)$ [S3, unofficial].
    c. Set `grid[i, j, k] = inside` [S3, unofficial].
7.  **Return Grid:** Output the populated boolean grid [S2, S3, unofficial].

**Pseudocode:**
```python
def interior_voxelize(mesh, numcells=32):
    """
    Voxelize a mesh by testing voxel centers for interior containment.
    
    Args:
        mesh: A triangle mesh object with a method to compute bounding box and triangles.
        numcells: Integer resolution for the voxel grid along the longest axis.
        
    Returns:
        grid: A 3D numpy array of booleans (numcells, numcells, numcells).
    """
    # 1. Compute Bounding Box
    # Assuming mesh has a cached bounding box or method to compute it
    bounds = mesh.get_bounding_box()
    bb_min = bounds.min # Vector3: (x_min, y_min, z_min)
    bb_max = bounds.max # Vector3: (x_max, y_max, z_max)
    
    # 2. Calculate Cell Size
    # MaxDim is the maximum of (x_max-x_min), (y_max-y_min), (z_max-z_min)
    max_dim = max(bb_max.x - bb_min.x, bb_max.y - bb_min.y, bb_max.z - bb_min.z)
    cell_size = max_dim / numcells
    
    # 3. Build Spatial Index
    # This step depends on the specific library. 
    # For example, in MeshKit, this is DMeshAABBTree3(mesh, autoBuild=True)
    spatial_index = build_aabb_tree(mesh) 
    
    # 4. Initialize Grid
    grid = np.zeros((numcells, numcells, numcells), dtype=bool)
    
    # 5. Iterate and Query
    # Using numpy meshgrid for efficient coordinate generation
    i = np.arange(numcells)
    j = np.arange(numcells)
    k = np.arange(numcells)
    I, J, K = np.meshgrid(i, j, k, indexing='ij')
    
    # Map grid indices to world coordinates
    # P_x = bb_min.x + (I + 0.5) * cell_size
    # P_y = bb_min.y + (J + 0.5) * cell_size
    # P_z = bb_min.z + (K + 0.5) * cell_size
    # Note: Some implementations use integer grid indices directly if the indexer 
    # handles the offset. Here we assume center-point sampling.
    points_x = bb_min.x + (I + 0.5) * cell_size
    points_y = bb_min.y + (J + 0.5) * cell_size
    points_z = bb_min.z + (K + 0.5) * cell_size
    
    # Flatten for batch processing if the spatial index supports it, 
    # otherwise iterate.
    points = np.stack([points_x.ravel(), points_y.ravel(), points_z.ravel()], axis=1)
    
    # Perform containment test
    # spatial_index.is_inside(points) returns a boolean array
    inside_flags = spatial_index.is_inside(points)
    
    # Reshape back to 3D grid
    grid = inside_flags.reshape(numcells, numcells, numcells)
    
    return grid
```

**Parameters:**
*   `numcells`: The resolution of the voxel grid. Typical value: 32 [S3, unofficial].
*   `cell_size`: Derived from `numcells` and bounding box. Not given in the sources as a direct input, but calculated as $s = \frac{\max(B_{max} - B_{min})}{\text{numcells}}$ [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-Manifold Geometry:** Unlike rasterization methods, this method is robust against non-manifold geometry and self-intersections because it relies on the winding number or ray-casting logic internal to `IsInside` rather than surface projection [S3, unofficial].
*   **Precision:** Floating-point precision in the containment test may cause voxels on the boundary to be misclassified if the mesh is not watertight or if the point lies exactly on a triangle edge/vertex. Adding small noise to sample points can help break symmetry in degenerate cases [S2, unofficial].
*   **Performance:** For high resolutions, the number of queries grows cubically ($O(N^3)$). Building the spatial index is $O(T \log T)$ where $T$ is the number of triangles, but the query phase dominates for large grids.

## Operating characteristics
*   **Time Complexity:** $O(N^3 \cdot \log T)$, where $N$ is the grid resolution (`numcells`) and $T$ is the number of triangles in the mesh. The spatial index lookup is $O(\log T)$ per voxel [S3, unofficial].
*   **Memory Complexity:** $O(N^3)$ for the output grid, plus $O(T)$ for the spatial index [S3, unofficial].
*   **Measured Performance:** At resolution 32, the method is fast enough for interactive use on modern CPUs, but becomes slow for resolutions above 128 due to the cubic growth in queries [S3, unofficial].
*   **Strengths:** Robust to non-manifold geometry, self-intersections, and holes (depending on the `IsInside` implementation, often based on winding numbers) [S3, unofficial]. Simple to implement if a robust point-in-mesh library is available.
*   **Limitations:** Does not provide density values, only binary occupancy. Slow for high-resolution grids. Sensitive to the definition of "inside" for open meshes (though winding numbers handle this better than ray casting) [S3, unofficial].
*   **When to Use:** When the mesh may be non-manifold or self-intersecting, and a binary occupancy grid is sufficient. When simplicity and robustness are prioritized over speed.
*   **When Not to Use:** When high-resolution density fields are needed, or when the mesh is extremely complex and the grid resolution is very high (consider hierarchical or sparse voxelization).

## Background
Interior Voxelize is a fundamental technique in volumetric rendering and CAD processing for converting boundary representations (B-rep) into voxel grids. The specific implementation using `DMeshAABBTree3.IsInside()` and `ShiftGridIndexer3` originates from tutorials on 3D bitmaps and mesh winding numbers by gradientspace [S3, unofficial]. It is widely used in 3D printing, medical imaging, and physics simulations where a solid volume representation is required from a surface mesh. The method is also referenced in machine learning contexts for voxelizing CAD models for neural network training [S1, S2, unofficial].
