# 3D Block Stitching and Resampling

Also called: Stitching and resampling for 3D block construction

## Overview
This method constructs 3D volumetric blocks from 2D image tiles by stitching them into a 3D target grid and applying a 3D pre-filter to avoid aliasing during resampling [S1]. It is designed for visualization-driven processing of petascale microscopy data streams, where volume construction and visualization may occur on separate nodes [S1]. Unlike methods that perform full 3D convolution on raw data, this approach decouples the 2D pre-filtering from the 3D stitching to enable efficient GPU-based resampling using texture mapping [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   $N$ source 2D image tiles $I_k^{2d}$, where $k \in \{1, \dots, N\}$.
*   Affine transformation matrices $\tilde{T}_k$ for aligning each tile $k$ to the global 3D coordinate system [S1].
*   A requested 3D target block defined by its spatial extent and resolution [S1].
*   Filter kernels: a 2D filter $W_{x,y}$ for the $(x, y)$ plane and a 1D filter $W_z$ for the $z$ axis [S1].

**Outputs:**
*   A 3D volume block $I^{3d}$ sampled at the requested resolution [S1].

### Data Structures
*   **2D Mipmap Archive:** Stores pre-filtered 2D image tiles $\tilde{I}_k^{2d}$ at multiple resolution levels. Each level corresponds to a down-sampled version of the raw tile, generated by applying $W_{x,y}$ [S1].
*   **Texture Pool:** A pool of 2D texture maps on the GPU, populated with sub-tiles fetched from the mipmap archive [S1].
*   **Off-screen Buffer:** A render target used during the GPU-based stitching process to resolve overlapping tiles via depth testing [S1].
*   **3D Block Cache:** Memory (and optionally fast local SSD) used to cache resampled 3D blocks if construction and visualization are on separate nodes [S1].
*   **Block Dimensions:** Blocks are constructed at $512 \times 512 \times 32$ voxels to avoid inefficient disk accesses, from which actual $32^3$ blocks are extracted [S1].

### Steps
1.  **Raw Tile Pre-processing (Offline/Async):**
    For each incoming raw 2D image tile $I_k^{2d}$, compute the pre-filtered 2D images $\tilde{I}_k^{2d}$ by applying the 2D filter $W_{x,y}$:
    $$ \tilde{I}_k^{2d}(x) = \sum_i W_{x,y}(x - x_i) I_k^{2d}(x_i) $$
    Store these pre-filtered images as levels of a 2D mipmap in the visualization archive [S1].

2.  **Tile Fetching:**
    Upon a request for a 3D block, determine the required resolution level $l$. Fetch the corresponding sub-tiles from the 2D mipmap archive. Download these sub-tiles into the GPU texture pool [S1].

3.  **GPU Stitching and Resampling:**
    Perform stitching and resampling directly on the 3D target grid using fragment shaders [S1].
    *   Set the alignment matrix $\tilde{T}_k$ as the texture matrix for each contributing sub-tile [S1].
    *   Render all contributing sub-tiles to an off-screen buffer.
    *   To resolve overlaps, set the depth of each fragment to the Euclidean distance from the fragment's position to the center of its respective source tile [S1].
    *   Perform a depth test to select the pixel with the minimum distance to its tile center. This heuristic selects one actual measurement value over a blend [S1].
    *   Apply a reconstruction filter (e.g., GPU bi-linear filtering or a higher-order filter in the fragment shader) during sampling [S1].

4.  **3D Volume Assembly:**
    The stitched and resampled data forms the 3D block $I^{3d}$. The value at a voxel $x$ is computed as:
    $$ I^{3d}(x) = \sum_i W_z(\pi_z(x - x_i)) \cdot S^{2d}_{\tilde{T}_1, \tilde{I}_1}, \dots, (\tilde{T}_N, \tilde{I}_N)(x_i) $$
    where $S^{2d}$ is the stitching operator, $\pi_z$ is the projection onto the $z$-coordinate, and $x_i$ ranges over a 1D neighborhood of $x$ in the $z$-direction [S1].

5.  **Coarse Resolution Handling:**
    Define a threshold resolution level $m$, corresponding to the resolution of one sub-tile times the number of image tiles comprising the full volume [S1].
    *   For levels $l \le m$, compute the block via the stitching/resampling process above.
    *   For levels $l > m$ (coarser resolutions), first compute the entire level $l=m$ via stitching. Then, compute blocks for $l > m$ via simple down-sampling of the $l=m$ result [S1].

6.  **Caching:**
    If volume construction and visualization are on separate nodes, cache the resampled 3D blocks in memory and optionally on fast local SSD storage [S1].

### Formulas
The fundamental equation for the pre-filtered 3D volume is:
$$ I^{3d}(x) = \sum_i W_{x,y} \otimes W_z(x - x_i) \cdot S^{2d}_{\tilde{T}_1, I_1}, \dots, (\tilde{T}_N, I_N)(x_i) $$
where $S^{2d}$ performs stitching of the $N$ required 2D source image tiles $I_k^{2d}$ into the 3D grid [S1].

The approximation used for efficiency separates the 2D and 3D filtering:
$$ \tilde{I}_k^{2d}(x) = \sum_i W_{x,y}(x - x_i) I_k^{2d}(x_i) $$
$$ I^{3d}(x) = \sum_i W_z(\pi_z(x - x_i)) \cdot S^{2d}_{\tilde{T}_1, \tilde{I}_1}, \dots, (\tilde{T}_N, \tilde{I}_N)(x_i) $$
where $\tilde{I}_k^{2d}$ is the pre-filtered 2D image [S1].

### Parameters
*   $W_{x,y}$: 2D filter kernel in the $(x, y)$ plane [S1].
*   $W_z$: 1D filter kernel along the $z$ axis. In the current implementation, this is a box filter of size one (nearest-neighbor interpolation) [S1].
*   $\tilde{T}_k$: Affine transformations for tile alignment [S1].
*   $I_k^{2d}(x)$: 2-vector image defined as $(I_k^{2d}(x), D_k^{2d}(x))$, where $D_k^{2d}(x)$ is the distance between $x$ and the center of tile $I_k^{2d}$ [S1].
*   Reconstruction filter: Either GPU bi-linear filtering or a higher-order filter implemented in the fragment shader [S1].
*   3D block size: $512 \times 512 \times 32$ voxels [S1].
*   $m$: Resolution level corresponding to the resolution of one sub-tile times the number of image tiles comprising the full volume [S1].

### Edge Cases and Pitfalls
*   **Approximation Error:** The approach approximates the full 3D pre-filter because $W_{x,y}$ is applied before stitching, not afterward. This decouples stitching from pre-filtering [S1].
*   **Anisotropy:** Using a box filter for $W_z$ (nearest-neighbor) may cause quality degradation with highly anisotropic data. The general formulation allows integrating additional pre-filters or interpolating intermediate slices to mitigate this [S1].
*   **Disk Access:** Constructing blocks larger than $32^3$ (specifically $512 \times 512 \times 32$) avoids inefficient disk accesses for small blocks [S1].

## Operating characteristics
*   **Time Complexity:** The method is visualization-driven, meaning computation occurs only for visible 3D blocks. The 2D pre-filtering is done once per tile. The stitching/resampling step is performed on the GPU using fragment shaders, which is efficient for parallel sampling [S1].
*   **Memory Complexity:** Requires storing 2D mipmaps for all source tiles. The 3D blocks are cached in memory/SSD if construction and visualization are separate [S1].
*   **Strengths:** Avoids aliasing through pre-filtering; efficient GPU-based stitching; decouples 2D filtering from 3D assembly; handles large-scale petascale data streams [S1].
*   **Limitations:** Approximates the ideal 3D filter; relies on GPU hardware for stitching; requires careful management of tile alignment and overlap resolution [S1].
*   **When to use:** When rendering 3D volumes constructed from 2D image tiles (e.g., microscopy data) where aliasing must be avoided and performance is critical [S1].
*   **When not to use:** When exact 3D convolution is required and the approximation error is unacceptable, or when hardware does not support the required GPU features [S1].

## Background
This method was developed for the interactive exploration of petascale microscopy data streams. It addresses the challenge of visualizing large volumes of 2D image tiles (from electron microscopy) as 3D volumes without prohibitive computational cost or aliasing artifacts. The technique was presented by Hadwiger et al. in 2012 [S1].
