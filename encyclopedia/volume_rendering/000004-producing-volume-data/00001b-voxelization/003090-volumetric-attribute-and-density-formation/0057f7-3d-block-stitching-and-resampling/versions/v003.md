# 3D Block Stitching and Resampling

Also called: Stitching and resampling for 3D block construction

## Overview
This method constructs 3D volumetric blocks from 2D image tiles by stitching them into a 3D target grid and applying a 3D pre-filter to avoid aliasing during resampling [S1]. It separates 2D pre-filtering into a raw tile processing stage from visualization-driven 3D stitching, and resolves overlapping tile contributions by selecting the pixel with the minimum distance to its tile center rather than blending [S1].

## How it works
**Inputs and Outputs**
*   **Input**: A set of $N$ 2D source image tiles $I_k^{2d}$ with associated affine alignment matrices $\tilde{T}_k$ [S1].
*   **Output**: A 3D volume block $I^{3d}$ at the requested resolution, typically extracted from a larger constructed block [S1].

**Data Structures**
*   **2D Mipmap Archive**: For each source tile $k$, a hierarchy of pre-filtered 2D images $\tilde{I}_k^{2d}$ is stored in the visualization archive [S1]. Each level $l$ contains images filtered by $W_{x,y}$ [S1].
*   **Texture Pool**: A pool of 2D GPU textures holding the sub-tiles fetched from the mipmap archive for the current resampling operation [S1].
*   **Off-screen Buffer**: A render target used to store depth values for the Voronoi selection during stitching [S1].

**Parameters**
*   $W_{x,y}$: 2D filter kernel in the $(x, y)$ plane [S1].
*   $W_z$: 1D filter kernel along the $z$ axis [S1]. In the cited implementation, this is a box filter of size one (nearest-neighbor interpolation along $z$) [S1].
*   $S^{2d}$: Operator performing stitching of $N$ required 2D source image tiles into the 3D grid of $I^{3d}$ [S1].
*   $\pi_z$: Projection onto the $z$-coordinate [S1].
*   $x_i$: Range over a 1D neighborhood of $x$ in the $z$-direction [S1].
*   Block Size: Constructed blocks are $512 \times 512 \times 32$ voxels to avoid inefficient disk accesses, from which actual $32^3$ blocks are extracted [S1].
*   Resolution Level $m$: The threshold where the strategy switches from stitching to down-sampling, defined such that it corresponds to the resolution of one sub-tile times the number of image tiles comprising the full volume [S1].

**Algorithm Steps**

1.  **Raw Tile Pre-processing (Mipmap Generation)**
    For each source image tile $I_k^{2d}$, compute the pre-filtered 2D images $\tilde{I}_k^{2d}$ by applying the 2D filter $W_{x,y}$:
    $$
    \tilde{I}_k^{2d}(x) = \sum_i W_{x,y}(x - x_i) I_k^{2d}(x_i)
    $$
    Store these levels in the visualization archive [S1]. This step approximates the full 3D pre-filtering by applying $W_{x,y}$ before stitching [S1].

2.  **Tile Fetching**
    Upon a 3D block request at resolution level $l$:
    *   If $l \le m$: Fetch the required sub-tiles from the correct resolution level of the 2D image tile mipmaps [S1].
    *   If $l > m$: Compute the entire level $l = m$ via stitching/resampling first, then compute the block for $l > m$ via simple down-sampling of the level $m$ result [S1].

3.  **GPU Stitching and Resampling**
    Perform stitching and resampling directly on the 3D target grid using texture mapping and fragment shaders:
    a. Download the fetched sub-tiles into the pool of 2D texture maps [S1].
    b. Render all contributing sub-tiles to an off-screen buffer using the alignment matrix $\tilde{T}_k$ as the texture matrix [S1].
    c. For each fragment, set the depth value to the Euclidean distance from the fragment's position to the center of its respective source tile [S1].
    d. Perform a depth test (minimum distance) to select the pixel with the minimum distance to its tile center, implementing the stitching operator $S^{2d}$ and selecting one measurement value over a blend [S1].
    e. Sample the selected texture using a reconstruction filter, which is either GPU bi-linear filtering or a higher-order filter implemented in the fragment shader [S1].

4.  **3D Volume Assembly**
    The resampled 3D volume $I^{3d}(x)$ is computed by applying the 1D filter $W_z$ to the stitched 2D data:
    $$
    I^{3d}(x) = \sum_i W_z(\pi_z(x - x_i)) \cdot S^{2d}_{(\tilde{T}_1, \tilde{I}_1^{2d}), \dots, (\tilde{T}_N, \tilde{I}_N^{2d})}(x_i)
    $$
    where $x_i$ ranges over a 1D neighborhood of $x$ in the $z$-direction [S1].

5.  **Caching and Extraction**
    Extract the requested $32^3$ block from the constructed $512 \times 512 \times 32$ block [S1]. If construction and visualization are on separate nodes, cache the resampled 3D blocks in memory and optionally on fast local SSD storage [S1].

**Pseudocode**

```python
def construct_3d_block(requested_origin, requested_level, m, W_z, alignment_matrices, mipmap_levels):
    # m is the resolution threshold where strategy switches from stitching to down-sampling
    if requested_level > m:
        if requested_level not in cache:
            full_level_m = stitch_full_volume(m, alignment_matrices, mipmap_levels)
            cache[requested_level] = downsample(full_level_m, requested_level)
        return cache[requested_level]

    # Fetch sub-tiles from 2D mipmap archive
    sub_tiles = [mipmap_levels[k][requested_level] for k in range(len(alignment_matrices))]
    
    # Create 2D texture maps from sub-tiles
    gpu_textures = [copy_array_to_texture(tile) for tile in sub_tiles]
    
    # Render to off-screen buffer for Voronoi selection
    offscreen_buffer = render_voronoi_selection(gpu_textures, alignment_matrices)
    
    # Sample selected pixels with reconstruction filter and apply 1D filter W_z
    resampled_block = sample_and_filter_1d(offscreen_buffer, W_z)
    
    # Extract requested block from larger constructed block
    final_block = extract_block(resampled_block, requested_origin)
    
    # Cache if necessary
    if separate_nodes:
        cache_in_memory(final_block)
        cache_on_ssd(final_block)
        
    return final_block

def stitch_full_volume(level, alignment_matrices, mipmap_levels):
    all_tiles = [mipmap_levels[k][level] for k in range(len(alignment_matrices))]
    full_voronoi_buffer = render_voronoi_selection(all_tiles, alignment_matrices)
    return sample_and_filter_1d(full_voronoi_buffer, W_z)

def render_voronoi_selection(textures, matrices):
    buffer = {}
    for i, (tile, matrix) in enumerate(zip(textures, matrices)):
        for x, y in tile.grid:
            depth = euclidean_distance_to_tile_center(x, y, matrix)
            if (x, y) not in buffer or depth < buffer[(x, y)].depth:
                buffer[(x, y)] = Fragment(value=tile[x, y], depth=depth, tile_index=i)
    return buffer

def sample_and_filter_1d(buffer, W_z):
    block = {}
    for x, y, z in target_grid:
        value = sum(W_z(z - z_i) * buffer[(x, y, z_i)].value for z_i in z_neighbors(z))
        block[(x, y, z)] = value
    return block

def extract_block(full_block, origin):
    return full_block[origin.x:origin.x+32, origin.y:origin.y+32, origin.z:origin.z+32]

def copy_array_to_texture(data):
    return data  # Simulates GPU texture upload

def downsample(volume, target_level):
    return volume[::2, ::2, ::2]  # Standard nearest-neighbor down-sampling
```

**Edge Cases and Pitfalls**
*   **Approximation Error**: The method approximates the ideal 3D pre-filter because $W_{x,y}$ is applied before stitching, not afterward, decoupling stitching from pre-filtering and sub-sampling [S1].
*   **Anisotropy**: Using a box filter for $W_z$ (nearest-neighbor) may cause quality degradation with highly anisotropic data, though the framework allows integrating other $W_z$ filters or interpolating intermediate slices if higher quality is required [S1].
*   **Tile Overlap**: The Voronoi selection heuristic (minimum distance to tile center) is used to resolve overlaps, preferring a single measurement value over a blend [S1].

## Operating characteristics
*   **Time Complexity**: The stitching and resampling step is performed on the GPU using fragment shaders, making it efficient for visualization-driven processing [S1]. The complexity is proportional to the number of visible 3D blocks and the number of contributing tiles per block [S1].
*   **Memory Complexity**: Requires storing 2D mipmaps for all source tiles, and large $512 \times 512 \times 32$ blocks are constructed in memory or SSD to avoid inefficient disk accesses of small $32^3$ blocks [S1].
*   **Strengths**: Avoids aliasing through pre-filtering; decouples 2D filtering from 3D stitching for performance; handles overlapping tiles efficiently via GPU depth testing; supports multi-resolution hierarchies [S1].
*   **Limitations**: Approximates the ideal 3D pre-filter; relies on GPU hardware for efficient stitching; requires significant memory for large constructed blocks and mipmap archives [S1].
*   **When to use**: When visualizing microscopy data streams where 2D image tiles need to be converted to 3D volumes on-the-fly with minimal aliasing and efficient disk I/O [S1].
*   **When not to use**: When exact 3D pre-filtering is required and the approximation error is unacceptable; when GPU resources are unavailable [S1].

## Background
The method is applied to interactive volume exploration of petascale microscopy data streams [S1]. It addresses the challenge of converting 2D image tiles from electron microscopy into 3D volumes suitable for real-time visualization, handling the large data volumes and multi-resolution requirements typical of such datasets [S1]. The approach uses a GPU-based method akin to Hoff et al.’s Voronoi computation for tile selection [S1], and employs a hybrid strategy for coarse resolution levels similar in spirit to clipmaps [S1].
