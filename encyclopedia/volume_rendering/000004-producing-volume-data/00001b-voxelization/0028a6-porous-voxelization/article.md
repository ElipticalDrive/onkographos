# Porous Voxelization

Also called: Random Voxel Dropping

## Overview
Porous Voxelization is a post-processing or integrated step in the voxelization pipeline that selectively discards generated voxels to create a porous, sponge-like structure from an otherwise solid or surface mesh [S1, unofficial]. Unlike standard voxelization methods which retain all computed voxels, this technique uses a deterministic pseudo-random hash of voxel coordinates to decide retention, maintaining spatial distribution properties while reducing voxel count [S1, unofficial]. It is distinct from probabilistic sampling methods by using a fixed threshold parameter `p` where a voxel is kept if its hash value is greater than or equal to `p` [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A set of candidate voxels generated by a parent voxelization method (e.g., [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) or [Interior Voxelize](995-interior-voxelize.md)), represented by their integer grid coordinates $(i, j, k)$.
- **Parameter:** `porosity`: An optional floating-point value $p \in [0.0, 1.0]$. If `None`, no voxels are dropped [S1, unofficial].
- **Output:** A subset of the input voxels that pass the retention test.

**Data Structures:**
- Voxel coordinates are typically stored as integer tuples or vectors $(i, j, k)$.
- The hash function operates on these coordinates.

**Steps:**
1. For each voxel with coordinates $(i, j, k)$ generated by the parent voxelization algorithm:
2. Compute a spatial hash value $h$ using the coordinates. The specific implementation cited uses a fractional sine-based hash:

3. If `porosity` is `Some(p)`:

   - If false, discard the voxel.
4. If `porosity` is `None`, keep all voxels.

**Pseudocode:**

```python
import math

def porous_voxelization(voxels: list[tuple[int, int, int]], porosity: float | None) -> list[tuple[int, int, int]]:
    """
    Filter voxels based on a porous threshold.
    
    Args:
        voxels: List of voxel coordinates (i, j, k).
        porosity: Threshold p in [0.0, 1.0]. If None, no filtering.
        
    Returns:
        List of kept voxels.
    """
    if porosity is None:
        return voxels
    
    # Validate porosity range [G]
    if not (0.0 <= porosity <= 1.0):
        raise ValueError("Porosity must be between 0.0 and 1.0")
        
    kept_voxels = []
    
    # Standard sine hash vector components [G]
    # These are standard constants for this type of hash, 
    # inferred from the multiplier 43758.5453 and the sine function.
    const_vec = (12.9898, 78.233, 45.164)
    
    for (i, j, k) in voxels:
        # Compute dot product of coordinates with constant vector
        dot_product = i * const_vec[0] + j * const_vec[1] + k * const_vec[2]
        
        # Compute hash as per source: (dot.sin() * 43758.5453).fract().abs()
        # Note: sin() expects radians.
        sin_val = math.sin(dot_product)
        scaled = sin_val * 43758.5453
        fract_part = scaled - math.floor(scaled) # fract()
        hash_val = abs(fract_part)
        
        # Keep if hash >= porosity
        if hash_val >= porosity:
            kept_voxels.append((i, j, k))
            
    return kept_voxels
```

**Parameters:**
- `porosity` ($p$): The threshold for voxel retention. Valid range $[0.0, 1.0]$. A value of $0.0$ keeps all voxels (since $h \ge 0$ is always true for absolute values), and $1.0$ keeps no voxels (since $h < 1$ is always true, so $h \ge 1$ is never true, unless $h=1$ which is rare/impossible for fract). *Correction*: If $p=0$, $h \ge 0$ is always true, so all kept. If $p=1$, $h \ge 1$ is never true (since fract is $<1$), so none kept. This matches the description "significantly reduces" for $p=0.5$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Invalid Input:** Passing `porosity` values outside $[0.0, 1.0]$ or `NaN` to the core logic without validation leads to undefined or misleading behavior. For example, $p=1.5$ causes all voxels to fail the check (if logic is $h \ge p$), effectively dropping all. $p=-0.5$ or `NaN` may disable dropping or cause errors [S1, unofficial].
- **Determinism:** The hash is deterministic based on coordinates, ensuring reproducible porous structures for the same input mesh and resolution.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of candidate voxels. The hash computation is constant time per voxel.
- **Memory Complexity:** $O(N)$ for the output list of kept voxels.
- **Performance:** Reduces the number of voxels in the final volume, which can speed up subsequent rendering or processing steps. The reduction factor is approximately $1-p$ [S1, unofficial].
- **Strengths:** Simple to implement, deterministic, reduces data size while maintaining spatial distribution.
- **Limitations:** Creates a non-manifold or disconnected structure if porosity is high. Not suitable for applications requiring solid, watertight volumes without further processing.

## Background
Porous Voxelization was implemented in the `voxelizer-rs` project (lhemerly/voxelizer-rs) as part of Pull Request #179, adding a `--porosity` flag to the CLI and the `MeshProcessor::voxelize` method [S1, unofficial]. It is designed to generate porous or sponge-like meshes by randomly discarding voxels during the voxelization process based on a spatial hash of their coordinates [S1, unofficial].
