# Analytic Moment Voxelization
Also called: GPU Polyhedral Voxelization with Analytic Moments

## Overview
Analytic Moment Voxelization is a GPU-based technique for converting 3D polyhedra into a discrete Cartesian grid by computing the analytic moments of a polynomial density field over the polyhedron's volume [S1, unofficial]. It solves the problem of high-fidelity volume data generation for scientific visualization (e.g., SPH simulations) by avoiding rasterization artifacts and supporting arbitrary polynomial orders [S1, unofficial]. It differs from its siblings by using exact geometric clipping and simplicial decomposition to compute integrals, rather than sampling (Monte Carlo) or differentiable approximations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D polyhedron defined by vertices and connectivity; an axis-aligned bounding box (AABB) in grid coordinates `ibox[2]`; grid spacing `d`; and the polynomial order `polyorder`.
*   **Output:** A dense grid buffer `dest_grid` storing the computed moments for each voxel in the AABB.

**Data Structures:**
The implementation uses specific C-style structures for geometric primitives [S1, unofficial]:
*   `r3d_poly`: Contains an array of `r3d_vertex` (max `R3D_MAX_VERTS = 64`) and an integer `nverts`.
*   `r3d_vertex`: Contains `pnbrs[3]` (neighbor indices), `pos` (`r3d_rvec3`), and `orient` (`r3d_orientation`).
*   `r3d_rvec3`: A union of `{x, y, z}` and `xyz[3]`, typed as `float` or `double` based on compilation flags.
*   `r3d_dvec3`: A union of `{i, j, k}` and `ijk[3]`, typed as `int32_t`.
*   `r3d_plane`: Contains a unit normal `n` (`r3d_rvec3`) and signed distance `d` (`r3d_real`).
*   `r3d_orientation`: Contains `fdist[4]` (signed distances to clip planes) and `fflags` (bit flags indicating inside/outside status for each face).

**Number of Moments:**
The number of moments $M$ required for a given polynomial order $P$ is:
$$ M = \frac{(P+1)(P+2)(P+3)}{6} $$
The moments are stored in row-major order: $1, x, y, z, x^2, xy, xz, y^2, yz, z^2, \dots$ [S1, unofficial].

**Algorithm Steps:**
1.  **Validation:** Verify the polyhedron is valid. The vertices must form a 3-vertex-connected graph (Steinitz' theorem) [S1, unofficial]. This check runs in $O(n_{verts}^2)$ time [S1, unofficial].
2.  **Bounding Box Calculation:** Compute the AABB of the polyhedron in grid coordinates to determine the range of voxels to process.
3.  **Simplicial Decomposition:** Decompose the polyhedron into tetrahedra. For each tetrahedron:
    *   Ensure correct orientation (positive volume). If volume is negative, swap two vertices to invert orientation [S1, unofficial].
    *   Compute the faces of the tetrahedron from its vertices.
4.  **Voxel Intersection Testing:** For each voxel in the AABB:
    *   Define the 8 corners of the voxel.
    *   For each corner, compute the signed distance to each of the tetrahedron's 4 faces.
    *   Set `fflags` for each corner: if signed distance $> 0$, the corner is outside the face; otherwise, it is inside.
    *   Determine if the tetrahedron intersects the voxel by checking if any corner is strictly inside all faces (intersection) or strictly outside (no intersection).
5.  **Geometric Clipping:** If the tetrahedron intersects the voxel, clip the tetrahedron against the voxel boundaries (or vice versa) to form a new polytope representing the intersection. This involves:
    *   Iterating through active clip faces.
    *   Identifying edges that cross the clipping plane.
    *   Computing intersection points using weighted averages of perpendicular distances.
    *   Updating vertex connectivity (`pnbrs`) and flags for new vertices.
6.  **Moment Integration:** Compute the analytic moments of the resulting clipped polytope (or the original tetrahedron if fully contained) over the voxel volume. This is done by reducing the polytope's moments into the destination grid.
7.  **Accumulation:** Add the computed moments to the corresponding location in `dest_grid`.

## Subtopics

### [Polynomial Field Integration via Coordinate Moments](3791-polynomial-field-integration-via-coordinate-moments.md)
Integrates arbitrary scalar fields by computing coordinate moments over each voxel and taking linear combinations using polynomial coefficients, avoiding the need to re-clip voxels for different fields.

### [R3D Polytope Splitting and Moment Reduction](3809-r3d-polytope-splitting-and-moment-reduction.md)
A voxelization technique that computes exact coordinate moments of the intersection between a 3D polytope and a Cartesian grid by recursively splitting the polytope along grid axes until it fits within a single voxel, then reducing the polytope's moments to that voxel.

## Operating characteristics
*   **Time Complexity:** The validation step runs in $O(n_{verts}^2)$ time [S1, unofficial]. The voxelization complexity depends on the number of voxels intersected by the polyhedron and the number of tetrahedra.
*   **Memory Complexity:** Proportional to the number of voxels in the bounding box multiplied by the number of moments per voxel.
*   **Performance:** Implemented on GPU using CUDA, allowing for parallel processing of voxels and primitives [S1, unofficial].
*   **Strengths:** Exact analytic integration avoids sampling noise; supports arbitrary polynomial orders; efficient GPU implementation.
*   **Limitations:** Requires valid 3-vertex-connected polyhedra; complex clipping logic; memory intensive for high polynomial orders.
*   **When to Use:** Scientific visualization of volumetric data (e.g., SPH simulations) where exact density representation is critical.
*   **When Not to Use:** When approximate rasterization is sufficient, or when input geometry is not a valid polyhedron.
