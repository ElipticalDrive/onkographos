# 2D Polygon Edge to Sparse Boundary Conversion

Also called: 2D Polygon-to-Raster Stage 1, 2D Vector Edge to Sparse Boundary Conversion, Stage 1 (2D)

## Overview
This method converts the edges of a 2D polygon dataset into a sparse boundary grid using bitwise XOR operations, serving as the first stage of a two-stage rasterization process [S1]. It differs from intersection-based methods by computing grid values based solely on edge topology and polygon area identifiers, ignoring polygon interiors until the subsequent filling stage [S1]. Unlike generic voxelization techniques that require distinct logic for different primitive types, this approach uniformly handles any closed watertight primitive by decoupling boundary extraction from interior filling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of 2D polygon edges. Each edge is defined by two endpoints $(y_0, x_0)$ and $(y_1, x_1)$ and separates two regions with integer area identifiers $A_{left}$ and $A_{right}$. The background area identifier is $0$ [S1].
*   **Output:** A sparse boundary grid where each cell $(r, c)$ contains an integer value representing the XOR sum of area identifiers of all edges passing through that cell [S1].

**Data Structures:**
*   **Edge Record:** A structure containing:
    *   `y0`, `x0`: Coordinates of the first endpoint.
    *   `y1`, `x1`: Coordinates of the second endpoint.
    *   `area1`: Integer identifier of the polygon on one side of the edge.
    *   `area2`: Integer identifier of the polygon on the other side.
*   **Sparse Boundary Grid:** A 2D array or hash map indexed by $(row, col)$. Initialized to $0$ [S1].

**Parameters:**
*   **Resolution:** The number of pixels per unit length (or grid dimensions $H \times W$) [S1].
*   **Background Value:** $0$ [S1].

**Algorithm Steps:**
1.  **Determine Row Range:** For each edge, calculate the minimum row index $r_{min}$ and maximum row index $r_{max}$ covered by the edge. These are derived from the y-coordinates of the endpoints $(y_0, y_1)$, the grid resolution, and the total extent of the area [S1].
2.  **Iterate Rows:** For each row index $r$ from $r_{min}$ to $r_{max}$:
    a.  **Compute Intersection Column:** Calculate the column index $c$ where the edge intersects the horizontal line corresponding to row $r$. This is based on the linear interpolation of the edge defined by its endpoints [S1].
    b.  **Calculate XOR Value:** Compute the value $v$ to be inserted into the grid:
        $$ v = \text{area1} \oplus \text{area2} $$
        where $\oplus$ denotes the bitwise XOR operation [S1].
    c.  **Update Grid:** Update the grid cell at $(r, c)$:
        $$ \text{Grid}[r, c] = \text{Grid}[r, c] \oplus v $$
        If the cell is empty (initially 0), it becomes $v$. If it already contains a value, the new value is XOR-ed with the existing one [S1].

**Edge Cases and Pitfalls:**
*   **Vertex Collisions:** When multiple edges meet at a vertex, the XOR accumulation ensures that edges belonging to the same polygon cancel each other out or occupy adjacent pixels, which are resolved in Stage 2 [S1].
*   **Grid Shift:** The resulting grid appears shifted half a pixel to the right relative to the geometric input. Implementation must account for this offset when positioning values in the sparse boundary grid [S1].
*   **Vertex Ambiguity:** When multiple areas meet at one vertex, the "winning" area is determined by the XOR accumulation of edge values, not by geometric precedence [S1].
*   **Duplicate Edges:** In input data with separate polygons (no shared topology), vertices appearing multiple times create duplicate edges. Each edge is processed independently with its specific area pair plus background, and the XOR operation handles the accumulation [S1].

**Pseudocode:**

```python
def stage_1_vector_to_sparse_boundary(edges, resolution, height, width):
    """
    Convert 2D polygon edges to a sparse boundary grid.
    
    Args:
        edges: List of Edge objects. Each Edge has:
            - y0, x0: float, y and x coordinates of start point.
            - y1, x1: float, y and x coordinates of end point.
            - area1: int, identifier of polygon on one side.
            - area2: int, identifier of polygon on other side.
        resolution: float, pixels per unit length.
        height: int, height of the output grid in pixels.
        width: int, width of the output grid in pixels.
        
    Returns:
        grid: 2D numpy array of shape (height, width), initialized to 0.
    """
    import numpy as np
    
    # Initialize grid with background value 0
    grid = np.zeros((height, width), dtype=np.int32)
    
    for edge in edges:
        # 1. Determine row range
        # Convert y-coordinates to row indices
        # Assuming y=0 is at the top or bottom? Standard image coords: y=0 top.
        # Let's assume standard Cartesian y-up for calculation, then flip if needed.
        # The source mentions "row indices... based on y-coordinates".
        # Let's assume row r corresponds to y coordinate.
        # r = y * resolution.
        
        y0 = edge.y0
        y1 = edge.y1
        
        # Calculate min and max row indices
        # Using floor/ceil to determine which pixels the edge spans
        r_start = int(np.floor(min(y0, y1) * resolution))
        r_end = int(np.ceil(max(y0, y1) * resolution))
        
        # Clamp to grid bounds
        r_start = max(0, min(r_start, height - 1))
        r_end = max(0, min(r_end, height - 1))
        
        # 2. Iterate over rows
        for r in range(r_start, r_end + 1):
            # 3. Compute intersection column
            # Linear interpolation: x = x0 + (x1 - x0) * (y - y0) / (y1 - y0)
            # Here, y corresponds to the row center or top?
            # The source says "intersects the (horizontal) row under consideration".
            # Let's assume the row r corresponds to y = (r + 0.5) / resolution 
            # to account for the half-pixel shift mentioned in pitfalls.
            
            y_row = (r + 0.5) / resolution
            
            # Avoid division by zero for horizontal edges
            if abs(y1 - y0) < 1e-9:
                continue
                
            # Interpolate x
            t = (y_row - y0) / (y1 - y0)
            x_intersect = edge.x0 + t * (edge.x1 - edge.x0)
            
            # Convert x to column index
            # Account for half-pixel shift: shift right by 0.5 pixels
            c = int(np.floor(x_intersect * resolution + 0.5))
            
            # Clamp column to grid bounds
            c = max(0, min(c, width - 1))
            
            # 4. Calculate XOR value
            xor_val = edge.area1 ^ edge.area2
            
            # 5. Update grid
            grid[r, c] = grid[r, c] ^ xor_val
            
    return grid
```

## Subtopics

### [Vector-to-Raster Conversion via Sparse Boundary Grids](22895-vector-to-raster-conversion-via-sparse-boundary-grids.md)
This method converts a set of non-overlapping, closed polyhedra (or polygons) into a fully occupied 3D (or 2D) grid of voxels (or pixels) where every voxel holds a specific value. It solves the problem of generic, high-performance voxelization by decoupling the process into two distinct stages: an object-based boundary extraction and a scan-line-based interior filling. Unlike intersection-based methods that compute distances for every voxel or object-type-specific algorithms requiring different logic for lines, surfaces, and parametric curves, this approach uses bitwise XOR operations to handle any closed watertight primitive (polyhedra, ellipsoids, splines) with uniform complexity. It builds on [2D Polygon Edge to Sparse Boundary Conversion](22873-2d-polygon-edge-to-sparse-boundary-conversion.md) by providing the mechanism to fill the interior defined by those boundaries.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of edges and the average length of edges in pixels. For each edge, the algorithm iterates over the rows it spans, performing constant-time interpolation and XOR operations.
*   **Memory Complexity:** Proportional to the number of non-zero cells in the sparse boundary grid. In the worst case (dense edges), it is $O(H \times W)$, but typically sparse.
*   **Strengths:** Uniform handling of any closed watertight primitive; efficient bitwise operations; decoupling of boundary and interior processing allows for optimized Stage 2.
*   **Limitations:** Requires careful handling of the half-pixel grid shift; vertex ambiguity resolution depends on XOR accumulation order; not directly differentiable without additional smoothing (see [Differentiable Voxelization via Smoothed Winding Numbers](2325-differentiable-voxelization-via-smoothed-winding-numbers.md)).
*   **When to Use:** When a fast, non-differentiable boundary extraction is needed as a preprocessing step for a two-stage rasterization/voxelization pipeline.
*   **When Not to Use:** When differentiability is required directly from the boundary extraction, or when the input is not a set of closed polygons/polyhedra.

## Background
This method originates from the work on rasterization and voxelization of space partitionings, specifically described in the paper "RASTERIZATION AND VOXELIZATION OF TWO- AND THREE-DIMENSIONAL SPACE PARTITIONINGS" [S1]. It is part of a two-stage approach where Stage 1 extracts boundaries and Stage 2 fills interiors. The use of XOR operations for boundary representation is a key innovation that allows for uniform processing of diverse geometric primitives.
