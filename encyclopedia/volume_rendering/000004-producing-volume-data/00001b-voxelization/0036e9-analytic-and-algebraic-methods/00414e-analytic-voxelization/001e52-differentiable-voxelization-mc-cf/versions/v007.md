# Differentiable Voxelization (MC/CF)

Also called: Closed-form Voxelization, Convolution Filter Voxelization, Differentiable 3D Voxelization (Forward/Backward Mode), VoxelizeFunc

## Overview
Differentiable Voxelization converts parametrically defined continuous geometric objects (2D polygons or 3D triangle meshes) into digital voxel grids of winding numbers or occupancy values, while providing closed-form gradients with respect to the input vertex positions [S1, unofficial]. It solves the differentiability bottleneck in gradient-based optimization of surface representations by avoiding the non-differentiable nature of standard rasterization or discrete marching cubes [S1, unofficial]. Unlike [Monte Carlo 2D Voxelization](1734-monte-carlo-2d-voxelization.md) which relies on stochastic sampling, or [Analytic Moment Voxelization](3307-analytic-moment-voxelization.md) which computes polynomial moments, this method uses deterministic closed-form integration over triangle faces to compute both the primal voxel values and their derivatives [S1, unofficial].

## How it works
The method is implemented as a PyTorch `autograd.Function` that supports two primal modes: Marching Cubes (MC) and Convolution Filter (CF) [S1, unofficial]. The MC mode uses Monte Carlo integration for the forward pass and closed-form integration for the backward pass, while the CF mode uses a box filter approximation for both [S1, unofficial].

### Inputs and Outputs
**Inputs:**
*   `vertices`: Array of shape $(N, D)$ containing triangle/polygon vertices, type `Float` (float32 or float64) [S1, unofficial].
*   `indices` (or `faces`/`edges`): Array of shape $(M, D)$ containing vertex indices for each simplex, type `uint32_t` [S1, unofficial].
*   `grid_shape`: Tuple defining the output voxel grid dimensions (e.g., $(H, W)$ for 2D or $(D, H, W)$ for 3D) [S1, unofficial].
*   `voxel_size`: The physical size of a single voxel cell [S1, unofficial].
*   `num_samples_per_voxel`: Number of Monte Carlo samples per voxel for the MC forward pass. Default: 16 [S1, unofficial].
*   `num_samples_per_simplex`: Number of Monte Carlo samples per simplex for the MC backward pass. Default: 64 [S1, unofficial].
*   `filter_radius`: Radius of the filter. Default: half_voxel_size. For CF, it must equal half_voxel_size; otherwise, it has no effect [S1, unofficial].

**Outputs:**
*   `occupancy`: Output tensor of shape `grid_shape` and dtype matching `vertices`, containing the voxel winding numbers or occupancy values [S1, unofficial].

### Data Structures
The implementation uses standard dense tensors for vertices, indices, and the output grid. No complex sparse structures are required for the core algorithm [S1, unofficial].

### Algorithm Steps

#### 1. Primal Forward Pass (Voxelization)
The forward pass computes the occupancy/winding number for each voxel.

1.  **Validation:** Validate inputs using `validate_common_voxelize_arguments` [S1, unofficial].
2.  **Dispatch:** Select the primal function based on method ('mc' or 'cf') and dtype (float32/float64). Select from `dvx_ext.voxelize_mc_f32`, `voxelize_mc_f64`, `voxelize_cf_f32`, or `voxelize_cf_f64` [S1, unofficial].
3.  **Initialization:** Initialize the output voxel grid `occupancy` as a zero tensor of shape `grid_shape` and dtype matching `vertices` [S1, unofficial].
4.  **Execution:** Execute the primal voxelization function with `vertices`, `indices`, and the `occupancy` output tensor [S1, unofficial].

**Detailed Forward Logic (CF Mode):**
The CF method assumes a box filter the size of a voxel [S1, unofficial].
1.  Iterate over all faces. For each face, extract vertices $v_0, v_1, v_2$.
2.  Compute edge vectors $e_1 = v_1 - v_0$, $e_2 = v_2 - v_0$.
3.  Compute normal $n = \text{normalize}(\text{cross}(e_1, e_2))$ and area $A = 0.5 \times \|\text{cross}(e_1, e_2)\|$ [S1, unofficial].
4.  Determine the bounding box in grid coordinates $(i_{min}, i_{max}, j_{min}, j_{max}, k_{min}, k_{max})$ covering the triangle [S1, unofficial].
5.  For each voxel in the bounding box, compute the intersection of the triangle with the voxel cell. This is done by splitting the triangle polygon in barycentric coordinates against the voxel planes [S1, unofficial].
6.  Compute the contribution to the voxel occupancy based on the signed area of the intersection polygon and the normal direction [S1, unofficial].

**Detailed Forward Logic (MC Mode):**
1.  For each face, perform Monte Carlo integration over the triangle surface [S1, unofficial].
2.  Generate uniform random samples $u, v$. If $u + v > 1$, reflect: $u = 1 - u; v = 1 - v$ [S1, unofficial].
3.  Compute sample point on triangle: $p = v_0 + u \cdot e_1 + v \cdot e_2$ [S1, unofficial].
4.  Determine which voxel contains $p$ and increment its occupancy count [S1, unofficial].
5.  Normalize by the number of samples [S1, unofficial].

#### 2. Backward Pass (Gradient Computation)
The backward pass computes the gradient of the loss with respect to the vertex positions, $\frac{\partial L}{\partial v_i}$, given the gradient of the loss with respect to the occupancy grid, $\delta \text{occupancy}$ [S1, unofficial].

1.  **Save:** Save `vertices`, `indices`, and `occupancy` for the backward pass [S1, unofficial].
2.  **Dispatch:** Select the appropriate backward function (`voxelize_backward_mc_*` or `voxelize_backward_cf_*`) based on method and dtype [S1, unofficial].
3.  **Initialization:** Initialize gradient tensor for vertices $\delta \text{vertices}$ as zeros with same shape and dtype [S1, unofficial].
4.  **Execution:** Execute the backward function with `vertices`, `indices`, `occupancy`, $\delta \text{vertices}$, and $\delta \text{occupancy}$ [S1, unofficial].

**Detailed Backward Logic (CF Mode):**
1.  Iterate over all faces. For each face, extract vertices $v_0, v_1, v_2$ [S1, unofficial].
2.  Compute edge vectors $e_1 = v_1 - v_0$, $e_2 = v_2 - v_0$, normal $n = \text{normalize}(\text{cross}(e_1, e_2))$, and area $A = 0.5 \times \|\text{cross}(e_1, e_2)\|$ [S1, unofficial].
3.  Determine the bounding box in grid coordinates [S1, unofficial].
4.  For each voxel in the bounding box:
    a.  Compute the filter weight (intersection area/volume contribution) [S1, unofficial].
    b.  If the weight is non-zero, compute the differential weight:
        $$ w_{diff} = \delta \text{occupancy}[voxel] \times \text{filter\_weight} \times A / \text{num\_samples\_per\_simplex} $$
        [S1, unofficial].
    c.  Compute normal velocities for backward pass:
        $$ \frac{\partial x_{bn}}{\partial v_0} = n \times (1 - u - v) $$
        $$ \frac{\partial x_{bn}}{\partial v_1} = n \times u $$
        $$ \frac{\partial x_{bn}}{\partial v_2} = n \times v $$
        [S1, unofficial].
    d.  Add to vertex gradients:
        $$ \delta \text{vertices}[3 \cdot v_0 + d] += \frac{\partial x_{bn}}{\partial v_0}[d] \times w_{diff} $$
        for all 3 vertices and 3 dimensions $d$ [S1, unofficial].

**Detailed Backward Logic (MC Mode):**
1.  Iterate over all faces. For each face, extract vertices $v_0, v_1, v_2$ [S1, unofficial].
2.  Compute edge vectors $e_1 = v_1 - v_0$, $e_2 = v_2 - v_0$, normal $n = \text{normalize}(\text{cross}(e_1, e_2))$, and area $A = 0.5 \times \|\text{cross}(e_1, e_2)\|$ [S1, unofficial].
3.  Perform Monte Carlo integration over the triangle surface. Generate uniform $u, v$. If $u + v > 1$, reflect: $u = 1 - u; v = 1 - v$ [S1, unofficial].
4.  Compute normal velocities for backward pass:
    $$ \frac{\partial x_{bn}}{\partial v_0} = n \times (1 - u - v) $$
    $$ \frac{\partial x_{bn}}{\partial v_1} = n \times u $$
    $$ \frac{\partial x_{bn}}{\partial v_2} = n \times v $$
    [S1, unofficial].
5.  In Forward mode (accumulating gradients from downstream), compute $d_{xbn}$ by dotting the vertex gradients with the normal velocities:
    $$ d_{xbn} += \text{dot}(\delta v_0, \frac{\partial x_{bn}}{\partial v_0}) + \text{dot}(\delta v_1, \frac{\partial x_{bn}}{\partial v_1}) + \text{dot}(\delta v_2, \frac{\partial x_{bn}}{\partial v_2}) $$
    [S1, unofficial].
6.  Compute sample point on triangle: $p = v_0 + u \cdot e_1 + v \cdot e_2$. Convert to grid coordinates and get support box [S1, unofficial].
7.  Iterate over neighbor voxels $(nx, ny, nz)$. Compute neighbor center $n_{center} = (nx + 0.5) \times \text{voxel\_size} - 1$ [S1, unofficial].
8.  Compute filter weight. If non-zero, update gradients. Forward:
    $$ \delta \text{occupancy}[n_{voxel\_index}] += d_{xbn} \times \text{filter\_weight} \times A / \text{num\_samples\_per\_simplex} $$
    [S1, unofficial].
9.  Backward: Compute $differential\_weight = \delta \text{occupancy}[n_{voxel\_index}] \times \text{filter\_weight} \times A / \text{num\_samples\_per\_simplex}$. Add to vertex gradients:
    $$ \delta \text{vertices}[3 \cdot v_0 + d] += \frac{\partial x_{bn}}{\partial v_0}[d] \times differential\_weight $$
    for all 3 vertices and 3 dimensions [S1, unofficial].

### Parameters
*   `num_samples_per_voxel`: Number of samples per voxel for MC forward pass. Default: 16 [S1, unofficial].
*   `num_samples_per_simplex`: Number of samples per simplex for MC backward pass. Default: 64 [S1, unofficial].

### Edge Cases and Pitfalls
*   **Coordinate Convention:** The CF method uses a different coordinate convention (width, height vs height, width), requiring a transpose of the output voxels (`voxels.transpose(0, -1)`), which regresses performance [S1, unofficial].
*   **Hardware Support:** The implementation is CPU-only; GPU tensors are automatically moved to CPU for processing and moved back, issuing a warning [S1, unofficial].
*   **Degenerate Triangles:** Triangles with zero area (normal length < $10^{-12}$) are skipped in the backward pass [S1, unofficial].
*   **Method Selection:** The 'auto' method selects 'cf' if `filter_radius` equals half_voxel_size, otherwise 'mc' [S1, unofficial].

## Subtopics

### [Differentiable Voxelization via Smoothed Winding Numbers](2325-differentiable-voxelization-via-smoothed-winding-numbers.md)
Differentiable Voxelization via Smoothed Winding Numbers (DVX) is a method for voxelizing triangle meshes into smoothed winding number voxel grids that provides closed-form gradients with respect to mesh vertex positions, enabling gradient-based optimization of surface representations based on volumetric properties. Unlike [Differentiable Voxelization (MC/CF)](1742-differentiable-voxelization-mc-cf.md) which samples a non-smoothed winding number and uses automatic differentiation (yielding sparse near-surface derivative signals), this method yields a broader gradient pattern matching finite-difference references.

### [Differentiable Voxelization from Radiative Gaussians](2380-differentiable-voxelization-from-radiative-gaussians.md)
This method provides a differentiable voxelizer $\mathcal{V}$ that efficiently queries a 3D density volume $V \in \mathbb{R}^{X \times Y \times Z}$ from a set of radiative Gaussians $G_3$. It solves the computational bottleneck of mapping continuous Gaussian splats to a discrete grid, enabling 3D regularization priors for tomographic reconstruction. Unlike [Differentiable Voxelization (MC/CF)](1742-differentiable-voxelization-mc-cf.md) which operates on polygonal meshes, this method operates directly on parametric Gaussian distributions, leveraging spatial tiling for acceleration.

### [Silhouette Fitting](16939-silhouette-fitting.md)
Silhouette fitting is a post-processing voxelization technique that refines an initial coarse voxel model by aligning its boundary with the silhouette of the input 3D mesh, thereby preserving shape accuracy. Unlike standard rasterization-based voxelization which produces blocky artifacts, this method minimizes an energy function based on distance, tangent, and gradient differences to carve or adjust the voxel boundary. It is distinct from [Differentiable Voxelization (MC/CF)](1742-differentiable-voxelization-mc-cf.md) because it operates on a discrete voxel set using heuristic search rather than continuous gradient descent, and from [Differentiable Voxelization via Smoothed Winding Numbers](2325-differentiable-voxelization-via-smoothed-winding-numbers.md) by focusing specifically on silhouette curve matching rather than volumetric field smoothing.

### Backward Differentiable Closed-form Voxelization
Computes backward-mode gradients of voxel occupancy with respect to vertex positions using closed-form integration [S1, unofficial].
*   **Steps:** Validate inputs using `validate_common_differential_voxelize_arguments`. Dispatch to 2D or 3D backward-mode closed-form implementation [S1, unofficial].
*   **Parameters:** `d_vertices`: output array of shape $(N, D)$ containing vertex gradients, type `Float`. `d_occupancy`: input array of shape $(H, W)$ or $(D, H, W)$ containing occupancy gradients, type `Float` [S1, unofficial].

### Forward Differentiable Closed-form Voxelization
*   **Steps:** Validate inputs using `validate_common_differential_voxelize_arguments`. Dispatch to 2D or 3D forward-mode closed-form implementation [S1, unofficial].
*   **Parameters:** `d_vertices`: input array of shape $(N, D)$ containing vertex gradients, type `Float`. `d_occupancy`: output array of shape $(H, W)$ or $(D, H, W)$ containing occupancy gradients, type `Float` [S1, unofficial].

### 2D Polygon Rasterization to Grid Moments
Rasterizes a 2D polygon to a destination grid by computing polynomial density moments over the covered cells [S2, unofficial].
*   **Parameters:** `poly`: The polygon to be rasterized. `ibox`: Minimum and maximum indices of the polygon, found with `r2d_get_ibox()`. Indices are from a virtual grid starting at the origin. `dest_grid`: The rasterization buffer. A row-major grid patch starting at `d*ibox[0]` and ending at `d*ibox[1]`. Must have size at least `(ibox[1].i-ibox[0].i)*(ibox[1].j-ibox[0].j)*(ibox[1].k-ibox[0].k)*R2D_NUM_MOMENTS(polyorder)`. `d`: The cell spacing of the grid. `polyorder`: Order of the polynomial density field. 0 for constant (1 moment), 1 for linear (3 moments), 2 for quadratic (6 moments) [S2, unofficial].
*   **Layout:** `r2d_dest_grid` struct: `r2d_real* moments[6]` (row-major C order, size `n.x*n.y`), `r2d_int polyorder`, `r2d_orientation* orient` (size `(n.x+1)*(n.y+1)`, unused if compiled with `-DUSE_TREE`), `r2d_long bufsz`, `r2d_dvec2 n` (grid dimensions), `r2d_rvec2 d` (cell size) [S2, unofficial].

### Differentiable Voxelization with Padding
Calculates an $N \times N \times N$ voxel volume of signed distance values for a given mesh. The mesh is transformed to fit inside a cube ranging from -1 to 1 [S3, unofficial].
*   **Steps:** Check if the result is plausible by verifying if the difference in SDF is smaller than the difference in distance between any two points. If not, throw an exception [S3, unofficial].
*   **Parameters:** `voxel_resolution`: The resolution $N$ of the resulting voxel volume. Default value is 64. `pad`: If True, the resulting array is padded with ones, ensuring a mesh without holes when reconstructing with Marching Cubes. Default value is False [S3, unofficial].
*   **Layout:** Returns a numpy array of shape $(N, N, N)$ or $(N + 2, N + 2, N + 2)$ when using padding. If `return_gradients` is True, additionally returns gradients in a numpy array of shape $(N, N, N, 3)$ or $(N + 2, N + 2, N + 2, 3)$ when using padding [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The CF method is deterministic and generally faster than MC for high-resolution grids because it avoids sampling overhead, but the barycentric splitting logic can be complex. The MC method's complexity scales with the number of samples per voxel/simplex.
*   **Memory Complexity:** Linear in the number of voxels and vertices. No auxiliary sparse structures are used in the core implementation [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** The method is CPU-only in the provided implementation, which limits scalability for large grids or high-resolution meshes [S1, unofficial].
*   **Strengths:** Provides closed-form gradients, enabling end-to-end differentiable rendering and optimization. Supports both MC and CF modes.
*   **Limitations:** CPU-only implementation. CF mode has a coordinate convention pitfall. MC mode is stochastic and may require many samples for low noise.
*   **When to use:** When gradient-based optimization of mesh vertices is required based on volumetric properties.
*   **When not to use:** When GPU acceleration is critical, or when non-differentiable voxelization is sufficient.

## Background
The method originates from the work on differentiable voxelization of surface representations, specifically the `differentiable-voxelization` repository [S1, unofficial]. It builds on the principles of analytic voxelization, extending them to provide differentiable backward passes for gradient-based optimization [S1, unofficial]. The CF method is related to convolution-based rasterization techniques, while the MC method leverages Monte Carlo integration for differentiability [S1, unofficial].
