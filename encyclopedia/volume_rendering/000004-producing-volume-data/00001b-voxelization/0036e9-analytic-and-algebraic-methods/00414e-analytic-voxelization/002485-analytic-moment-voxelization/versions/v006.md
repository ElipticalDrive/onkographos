# Analytic Moment Voxelization

Also called: GPU Polyhedral Voxelization with Analytic Moments

## Overview
Analytic Moment Voxelization is a GPU-based technique for converting 3D polyhedra into digital volume representations by computing analytic moments of a polynomial density field over the polyhedron's volume [S1, unofficial]. It uses geometric clipping and simplicial decomposition to derive exact moment integrals, rather than relying on sampling or rasterization [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D polyhedron (`r3d_poly* poly`), a bounding box defined by integer grid indices `ibox[0]` and `ibox[1]`, a voxel size vector `d`, and a polynomial order `polyorder` [S1, unofficial].
*   **Output:** A flattened array `dest_grid` storing the computed moments for each voxel in the bounding box [S1, unofficial].

**Data Structures:**
The implementation uses specific C-style structures defined in the source [S1, unofficial]:
1.  `r3d_poly`: `struct { r3d_vertex verts[R3D_MAX_VERTS]; r3d_int nverts; }` where `R3D_MAX_VERTS = 64`.
2.  `r3d_vertex`: `struct { r3d_int pnbrs[3]; r3d_rvec3 pos; r3d_orientation orient; }`. `pnbrs` stores neighbor indices.
3.  `r3d_rvec3`: `union { struct { r3d_real x, y, z; }; r3d_real xyz[3]; }`. Type is `float` if compiled with `-DSINGLE_PRECISION`, else `double` [S1, unofficial].
4.  `r3d_dvec3`: `union { struct { r3d_int i, j, k; }; r3d_int ijk[3]; }`. Type is `int32_t`.
5.  `r3d_plane`: `struct { r3d_rvec3 n; r3d_real d; }`. `n` is a unit-length normal vector, `d` is signed perpendicular distance to the origin [S1, unofficial].
6.  `r3d_orientation`: `struct { r3d_real fdist[4]; unsigned char fflags; }`. `fdist` stores signed distances to clip planes, `fflags` stores bit flags for inside (1) or outside (0) [S1, unofficial].

**Moment Ordering and Count:**
The moments are stored in row-major order corresponding to monomials $x^a y^b z^c$ where $a+b+c \le polyorder$ [S1, unofficial]. The total number of moments $M$ is:
$$ M = \frac{(polyorder+1)(polyorder+2)(polyorder+3)}{6} $$
The ordering sequence begins: $1, x, y, z, x^2, xy, xz, y^2, yz, z^2, x^3, x^2y, \dots$ [S1, unofficial].

**Algorithm Steps:**
1.  **Validation:** Check if the polyhedron is valid using `r3d_is_good`. This requires the vertex graph to be 3-vertex-connected (Steinitz' theorem) [S1, unofficial]. This check runs in $O(n_{verts}^2)$ time [S1, unofficial].
2.  **Initialization:** Initialize the `r3d_poly` structure with the input vertices [S1, unofficial].
3.  **Bounding Box Clipping (Coarse):** For each voxel in the bounding box `ibox`, determine which vertices are inside/outside relative to the voxel's faces by computing signed distances from vertices to the voxel planes [S1, unofficial].
4.  **Geometric Clipping:** Iteratively clip the polyhedron against the active faces of the voxel [S1, unofficial]. Identify the first face `f` where `andcmp & (1 << f)` is true (vertex is outside) [S1, unofficial]. Traverse the vertex ring. For each edge `(vprev, vcur)`: If `vcur` is outside the current face `f` and `vprev` is inside (or vice versa), compute the intersection point [S1, unofficial]. The intersection point `P` is calculated using a weighted average of the perpendicular distances to the plane:
    $$ P = \frac{-dist_{prev} \cdot pos_{cur} + dist_{cur} \cdot pos_{prev}}{dist_{cur} - dist_{prev}} $$
    where $dist_{prev}$ and $dist_{cur}$ are the signed distances of the previous and current vertices to the clipping plane [S1, unofficial]. Insert the new vertex into the vertex buffer, updating neighbor links (`pnbrs`) to maintain the doubly-linked ring structure [S1, unofficial]. Update the orientation flags (`fflags`) and distances (`fdist`) for the new vertex against remaining clip planes [S1, unofficial]. Repeat until all faces are processed or the polyhedron is fully clipped [S1, unofficial].
5.  **Simplicial Decomposition:** Decompose the clipped polyhedron into tetrahedra [S1, unofficial].
6.  **Moment Integration:** For each tetrahedron, compute the analytic moments of the polynomial density field over its volume [S1, unofficial].
7.  **Reduction:** Use `cur3d_reduce` to aggregate the moments from the tetrahedral contributions into the final voxel grid [S1, unofficial].

def r3d_voxelize(poly, ibox, dest_grid, d, polyorder):
    M = (polyorder + 1) * (polyorder + 2) * (polyorder + 3) // 6
    
    if not r3d_is_good(poly):
        raise ValueError("Polyhedron is not 3-vertex-connected")

    for i in range(ibox[0].i, ibox[1].i):
        for j in range(ibox[0].j, ibox[1].j):
            for k in range(ibox[0].k, ibox[1].k):
                voxel_moments = [0.0] * M
                temp_poly = copy_poly(poly)
                
                voxel_faces = get_voxel_faces(i, j, k, d)
                for face in voxel_faces:
                    temp_poly = clip_poly_against_plane(temp_poly, face)
                    if temp_poly.nverts == 0:
                        break
                
                if temp_poly.nverts > 0:
                    tetrahedra = decompose_into_tetrahedra(temp_poly)
                    for tet in tetrahedra:
                        # The sources do not provide the explicit analytic integration formulas for monomials over a tetrahedron.
                        tet_moments = compute_tet_moments(tet, polyorder)
                        for m in range(M):
                            voxel_moments[m] += tet_moments[m]
                
                voxel_idx = get_voxel_index(i, j, k, ibox[0], ibox[1])
                dest_grid[voxel_idx * M : (voxel_idx + 1) * M] = voxel_moments

def clip_poly_against_plane(poly, plane):
    new_verts = []
    nverts = poly.nverts
    
    # Compute distances and flags for all vertices
    for v in range(nverts):
        dist = plane.n.x * poly.verts[v].pos.x + plane.n.y * poly.verts[v].pos.y + plane.n.z * poly.verts[v].pos.z + plane.d
        poly.verts[v].orient[0] = dist
        poly.verts[v].orient[1] = 1 if dist > 0 else 0
        
    # Sutherland-Hodgman style edge traversal
    for v_prev in range(nverts):
        v_curr = (v_prev + 1) % nverts
        curr_outside = poly.verts[v_curr].orient[1]
        prev_outside = poly.verts[v_prev].orient[1]
        
        if not curr_outside:
            new_verts.append(poly.verts[v_curr])
            
        if curr_outside != prev_outside:
            dist_curr = poly.verts[v_curr].orient[0]
            dist_prev = poly.verts[v_prev].orient[0]
            
            t = -dist_prev / (dist_curr - dist_prev)
            p_int = poly.verts[v_prev].pos + t * (poly.verts[v_curr].pos - poly.verts[v_prev].pos)
            
            new_vert = R3DVertex()
            new_vert.pos = p_int
            new_vert.pnbrs = [0, 0, 0]
            new_vert.orient = [0.0]*4, 0
            new_verts.append(new_vert)
            
    n_new = len(new_verts)
    for i in range(n_new):
        new_verts[i].pnbrs[0] = new_verts[(i + 1) % n_new]
        new_verts[i].pnbrs[1] = new_verts[(i - 1) % n_new]
        
    return R3DPoly(verts=new_verts, nverts=n_new)

def compute_tet_moments(tet, polyorder):
    # The sources do not provide the explicit analytic integration formulas for monomials over a tetrahedron.
    return [0.0] * ((polyorder + 1) * (polyorder + 2) * (polyorder + 3) // 6)

**Parameters:**
*   `polyorder`: Order of the polynomial density field. 0 for constant (1 moment), 1 for linear (4 moments), 2 for quadratic (10 moments) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Buffer Size:** The `dest_grid` buffer must be at least `(ibox[1].i-ibox[0].i)*(ibox[1].j-ibox[0].j)*(ibox[1].k-ibox[0].k)*R3D_NUM_MOMENTS(polyorder)` in size [S1, unofficial].
*   **Validity:** Polyhedron vertices must form a 3-vertex-connected graph for `r3d_is_good` to pass [S1, unofficial].
*   **Precision:** The type of `r3d_real` depends on compilation flags (`-DSINGLE_PRECISION` for float, else double) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The validation step `r3d_is_good` runs in $O(n_{verts}^2)$ time [S1, unofficial]. The overall complexity depends on the number of voxels, the complexity of the polyhedron, and the polynomial order [S1, unofficial].
*   **Memory Complexity:** Requires storage for the polyhedron vertices (up to 64) and the output grid [S1, unofficial]. The output grid size scales with the bounding box volume and the number of moments $M$ [S1, unofficial].
*   **Performance:** Implemented on GPU using CUDA, leveraging parallel processing for voxel-wise clipping and integration [S1, unofficial].
*   **Strengths:** Provides exact analytic moments for polynomial fields; handles arbitrary convex polyhedra; deterministic results [S1, unofficial].
*   **Limitations:** Requires 3-vertex-connected polyhedra; complexity increases with polynomial order; clipping logic can be intricate for complex geometries [S1, unofficial].
*   **Usage:** Used in `mainVoxel.py` to process Gadget files (SPH simulation data) [S1, unofficial].

## Background
The method is part of the R3D (Real-time Ray Tracing for Volumetric Data) library, developed by Los Alamos National Laboratory (LANL) [S1, unofficial]. The code was prepared by Devon Powell on 31 August 2015 [S1, unofficial]. It is designed for high-performance voxelization of volumetric data, particularly for scientific simulations like SPH (Smoothed Particle Hydrodynamics) [S1, unofficial].
