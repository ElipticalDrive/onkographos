# Signed Distance Field (SDF) Generation from Scanned Surfaces

Also called: 3D Texture Distance Field for Implicit Surfaces, Mesh SDF Generation, Mesh to SDF Voxelization, MeshDistance conversion, SDF Texture Generation from Mesh, SDF Voxelization, Signed distance to triangulated surface

## Overview
This method converts a triangulated surface mesh (typically from 3D scanning) into a 3D Signed Distance Field (SDF) stored as a texture or grid [S2, unofficial]. It solves the problem of representing explicit, potentially noisy or complex scanned geometry as an implicit function suitable for raymarching, isosurfacing, or volume rendering [S3, unofficial]. Unlike [Slice-based SDF Voxelization](1736-slice-based-sdf-voxelization.md), which processes depth slices, this method operates directly on geometric primitives (triangles) to compute exact Euclidean distances [S1]. It differs from [Signed Distance Field from Mesh](1327-signed-distance-field-from-mesh.md) by explicitly handling the conversion to a bounded 3D texture domain with specific boundary shell logic [S3, unofficial].

## How it works
**Inputs:**
*   A triangulated mesh (e.g., PLY format) containing vertices and triangles [S1].
*   Grid resolution $N$ (e.g., $N=128$ for tetrahedral grids to preserve detail) [S1].
*   Texture boundary parameters: `textureBoundary` (default $0.5$) and `textureShell` (default $0.05$) [S3, unofficial].

**Outputs:**
*   A 3D texture/grid where each voxel stores the signed distance to the mesh surface [S1]. In GPU implementations, this is stored in the red channel of a fragment shader output [S2, unofficial].

**Data Structures:**
*   **Mesh:** Stored as a 1D array of vertices with a fixed stride (e.g., 16384 bytes per vertex in GPU implementations) [S2, unofficial].
*   **Grid:** A 3D array indexed by integer coordinates `pos` derived from normalized texture coordinates, typically mapped from $[0, 1]$ to $[-1, 1]$ [S2, unofficial][S3, unofficial].

**Steps:**
1.  **Pre-processing:** Close any holes in the input mesh (e.g., the 5 holes in the Stanford Bunny) to ensure correct topological containment and distance representation [S3, unofficial].
2.  **Grid Initialization:** Define the bounding box centered at the origin, bounded by $|x| \le \text{textureBoundary}$ (typically a $1 \times 1 \times 1$ cube) [S3, unofficial].
3.  **Distance Computation:** For each voxel center $x$ in the grid:
    *   Iterate through all triangles in the mesh [S2, unofficial].
    *   Compute the Euclidean distance $d$ from $x$ to the triangle surface using a routine like `dist3d` or `udTriangle` [S1][S2, unofficial].
    *   Update the minimum distance: $D(x) = \min(D(x), d)$ [S2, unofficial].
    *   Assign sign: negative for interior points, positive for exterior points [S1].
4.  **Boundary Handling (Texture Lookup):** When evaluating the distance field at runtime or for boundary points, apply the following logic to handle points outside the valid texture region [S3, unofficial]:
    *   Calculate difference: $d_i = |x| - \text{textureBoundary} + \text{textureShell}$ [S3, unofficial].
    *   If the point is outside the 3D texture space, calculate the distance as the L2 norm of the positive components: $res = \| \max(d_i + \text{textureShell}, 0) \|_2$ [S3, unofficial].
    *   If the point is inside the texture space (check if $c = \max(d_{i_x}, \max(d_{i_y}, d_{i_z})) < 0$):
        *   Adjust coordinate: $x' = x + \text{textureBoundary}$ [S3, unofficial].
        *   Lookup the pre-computed distance from the 3D texture: $res = \text{lookupTexture}(\text{texture}, x')$ [S3, unofficial].
    *   Return $res$ [S3, unofficial].

**Pseudocode:**
```python
import math

class Vec3:
    def __init__(self, x, y, z): self.x, self.y, self.z = x, y, z
    def __sub__(self, o): return Vec3(self.x-o.x, self.y-o.y, self.z-o.z)
    def __add__(self, o): return Vec3(self.x+o.x, self.y+o.y, self.z+o.z)
    def __mul__(self, s): return Vec3(self.x*s, self.y*s, self.z*s)
    def dot(self, o): return self.x*o.x + self.y*o.y + self.z*o.z
    def cross(self, o): return Vec3(self.y*o.z-self.z*o.y, self.z*o.x-self.x*o.z, self.x*o.y-self.y*o.x)
    def length(self): return math.sqrt(self.dot(self))

def compute_triangle_distance(p, v0, v1, v2):
    """Computes unsigned Euclidean distance from point p to triangle v0-v1-v2."""
    e1, e2 = v1 - v0, v2 - v0
    n = e1.cross(e2)
    n_len = n.length()
    if n_len == 0: return p.length()
    n = n * (1.0 / n_len)
    d = n.dot(p - v0)
    if d > 0:
        u, v, w = e1.dot(e1), e2.dot(e2), e1.dot(e2)
        a, b = (p - v0).dot(e1), (p - v0).dot(e2)
        denom = u * v - w * w
        yb = (a * v - b * w) / denom
        xb = (b * u - a * w) / denom
        if yb >= 0 and xb >= 0 and yb + xb <= 1: return abs(d)
        return min((p - v0).length(), (p - v1).length(), (p - v2).length())
    return abs(d)

def generate_sdf(mesh, resolution, texture_boundary=0.5, texture_shell=0.05):
    """Generates a 3D SDF grid from a triangulated mesh."""
    grid_size = resolution ** 3
    sdf_grid = [10000.0] * grid_size
    for z in range(resolution):
        for y in range(resolution):
            for x in range(resolution):
                coord_x = (x / resolution) * 2.0 - 1.0
                coord_y = (y / resolution) * 2.0 - 1.0
                coord_z = (z / resolution) * 2.0 - 1.0
                pos = Vec3(coord_x * texture_boundary, coord_y * texture_boundary, coord_z * texture_boundary)
                min_dist = 10000.0
                for tri in mesh.triangles:
                    d = compute_triangle_distance(pos, tri.v0, tri.v1, tri.v2)
                    if d < min_dist: min_dist = d
                idx = x + y * resolution + z * resolution * resolution
                sdf_grid[idx] = min_dist
    return sdf_grid

def evaluate_sdf(x, sdf_texture, texture_boundary=0.5, texture_shell=0.05):
    """Evaluates SDF at point x with boundary handling."""
    di = [abs(x[i]) - texture_boundary + texture_shell for i in range(3)]
    if any(di[i] + texture_shell > 0 for i in range(3)):
        res = math.sqrt(sum(max(di[i] + texture_shell, 0.0) ** 2 for i in range(3)))
    else:
        x_adjusted = [x[i] + texture_boundary for i in range(3)]
        tex_coord = [(x_adjusted[i] / (2.0 * texture_boundary)) + 0.5 for i in range(3)]
        res = sdf_texture.lookup(tex_coord).r
    return res
```

**Parameters:**
*   `textureBoundary`: Defines the box centered at origin bounded by $|x| \le 0.5$. Represents the full $1 \times 1 \times 1$ cube containing the texture [S3, unofficial].
*   `textureShell`: A small value (default $0.05$) defining a boundary region around the texture where distance values might be invalid. It should be as small as possible to maximize the valid lookup region [S3, unofficial].
*   `shell_voxels`: (Variant specific) The shell half-thickness in voxels. Default $1.5$. Must be $\ge \sqrt{3}/2 \approx 0.866$ to prevent holes [S4, unofficial].

**Edge Cases and Pitfalls:**
*   **Holes:** Open meshes (e.g., Stanford Bunny with 5 holes) must be closed before conversion to ensure correct interior/exterior sign assignment [S3, unofficial].
*   **Boundary Accuracy:** The `textureShell` value is not universal and must be adjusted for different textures to balance avoiding invalid boundary data and maximizing the valid lookup area [S3, unofficial].
*   **Scanner Noise:** The accuracy of the resulting SDF depends heavily on the surface scanner quality and the accuracy of the signed distance computation routine [S1].
*   **Resolution:** Low resolution may lose detail. For complex meshes, resolution may need to be increased (e.g., $N=128$) [S1].

## Subtopics

### Shell SDF
An unsigned distance field minus a shell half-thickness [S4, unofficial]. Negative within `shell_voxels` of any triangle, positive beyond [S4, unofficial]. Works on open, non-manifold, self-intersecting, and inconsistently wound meshes [S4, unofficial]. Extracts a thin solid around every triangle: two walls around an open sheet, and an outer surface plus an inner one for a closed solid [S4, unofficial]. Default `shell_voxels` is $1.5$, must be $\ge \sqrt{3}/2$ and $< \text{trunc\_dist}$ [S4, unofficial]. This is the unsigned offset field from Xu & Barbic, 'Signed Distance Fields for Polygon Soup Meshes' (GI 2014), before their interior-component removal step [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N^3 \cdot T)$, where $N$ is the grid resolution and $T$ is the number of triangles [G].
*   **Memory Complexity:** $O(N^3)$ to store the 3D texture/grid [G].
*   **Performance:** Measured on standard meshes like the Stanford Bunny (35,947 vertices, 69,451 triangles) and automobile parts (156,229 vertices, 312,458 triangles) [S1].
*   **Strengths:** Provides exact Euclidean distances to the mesh surface, enabling high-quality rendering and isosurfacing [S3, unofficial].
*   **Limitations:** Computationally intensive for large meshes. Sensitive to mesh quality (holes, normals) [S3, unofficial]. Boundary handling requires careful tuning of `textureShell` [S3, unofficial].
*   **When to use:** When exact distance to a scanned mesh is required for raymarching or implicit surface reconstruction [G].
*   **When not to use:** For real-time applications with very high triangle counts where approximate methods are preferred, or when the mesh is not closed and topological containment is ambiguous [G].

## Background
The method originates from the need to represent complex scanned surfaces (like the Stanford Bunny) as implicit distance functions for rendering and simulation [S3, unofficial]. Early implementations used tools like `MeshDistance` from the GEL (GEometry and Linear algebra) framework to sample distances into 3D textures [S3, unofficial]. The approach was popularized in the context of GPU raymarching, where distance fields allow for efficient scene representation [S2, unofficial]. The specific boundary handling algorithm (Algorithm 4.1) was detailed in academic work on GPU ray marching of distance fields [S3, unofficial]. The Shell SDF variant was introduced by Xu & Barbic in 'Signed Distance Fields for Polygon Soup Meshes' (GI 2014) to handle non-manifold meshes [S4, unofficial].
