# Mesh Loading and Normalization

Also called: Mesh Import and Preprocessing, Assimp Mesh Loading

## Overview
This method loads a 3D mesh from a file, extracts its geometric primitives, normalizes the geometry to a canonical space, and constructs an acceleration structure for ray tracing. It solves the problem of converting raw asset files into a format suitable for analytic voxelization or SDF generation. It differs from [Mesh Normalization](3796-mesh-normalization.md) by including the file I/O and acceleration structure construction steps, and from [SDF Generation from Scanned Surfaces](3795-sdf-generation-from-scanned-surfaces.md) by stopping at the mesh representation rather than computing the distance field.

## How it works
**Inputs:** A file path to a 3D model (e.g., OBJ, STL, GLTF) and configuration flags for loading.
**Outputs:** A normalized mesh data structure containing vertices, indices, and an associated acceleration structure (e.g., BVH or Octree).

**Data Structures:**
*   **Vertex:** A 3D vector (`glm::vec3` or equivalent), typically `float32` per component.
*   **Index:** A triplet of unsigned integers (`glm::uvec3` or equivalent), representing triangle face connectivity.
*   **Acceleration Structure:** A hierarchical data structure (BVH or Octree) storing triangle references for efficient ray intersection.

**Steps:**

1.  **Load Model:** Import the mesh file using a library such as Assimp. Apply specific processing flags to ensure a clean, triangulated, and cache-friendly representation.
    *   Flags include: `Triangulate`, `JoinIdenticalVertices`, `RemoveComponent`, `ImproveCacheLocality`, `OptimizeMeshes`, `OptimizeGraph`, and `DropNormals` (if normals are not required for the immediate step).
    *   Extract vertices and face indices from the first mesh in the scene. [S1, unofficial]

2.  **Compute Bounding Box:** Calculate the Axis-Aligned Bounding Box (AABB) of the raw vertices.
    *   Find the centroid $C$ of the bounding box.
    *   Find the maximum distance $R$ from the centroid to any vertex. [S1, unofficial]
    *   Alternatively, compute the raw AABB min/max, calculate the diagonal vector $D = \text{max} - \text{min}$, and determine the scale factor $S = \max(|D_x|, |D_y|, |D_z|)$. [S2, unofficial]

3.  **Normalize Geometry:** Transform vertices to fit a canonical space.
    *   **Method A (Unit Sphere):** Translate vertices by $-C$ and scale by $1/R$. This centers the mesh at the origin and fits it within a unit sphere. [S1, unofficial]
    *   **Method B (Unit Cube):** Translate vertices by $-0.5 \times D - \text{min}$ and scale by $1/S$. This maps the mesh to the $[0, 1]^3$ cube. Optionally, inflate the final AABB by a small factor (e.g., 0.5%) to prevent precision issues during voxelization. [S2, unofficial]

4.  **Build Acceleration Structure:** Construct a spatial index for ray tracing.
    *   Convert face indices to triangle primitives (triplets of vertex indices).
    *   Build a BVH (Bounding Volume Hierarchy) or Octree using the normalized vertices and indices.
    *   Copy the structure to GPU memory if hardware-accelerated ray tracing (e.g., OptiX, Embree) is used. [S1, unofficial][S2, unofficial]

**Pseudocode:**

```python
def load_and_normalize_mesh(file_path, method="unit_cube"):
    # 1. Load Model
    # Implementation detail: Use Assimp::Importer with flags:
    # aiProcess_Triangulate | aiProcess_JoinIdenticalVertices | 
    # aiProcess_RemoveComponent | aiProcess_OptimizeMeshes | 
    # aiProcess_DropNormals
    raw_vertices = load_vertices_from_file(file_path)
    
    # 2. Compute Bounding Box
    min_coord = min(raw_vertices, key=lambda v: v.x) # Simplified: find min/max components
    max_coord = max(raw_vertices, key=lambda v: v.x)
    
    # Calculate centroid and diagonal
    centroid = (min_coord + max_coord) / 2.0
    diagonal = max_coord - min_coord
    scale_factor = max(diagonal.x, diagonal.y, diagonal.z)
    
    # 3. Normalize Geometry
    normalized_vertices = []
    for v in raw_vertices:
        if method == "unit_sphere":
            # Center at origin, scale to unit radius
            centered = v - centroid
            radius = length(centered)
            if radius > 0:
                normalized_vertices.append(centered / radius)
            else:
                normalized_vertices.append(centered) # Handle degenerate point
        elif method == "unit_cube":
            # Map to [0, 1]^3
            # Formula: (v - min - 0.5 * diag) / scale + 0.5
            normalized_v = (v - min_coord - 0.5 * diagonal) / scale_factor + 0.5
            normalized_vertices.append(normalized_v)
            
    # 4. Build Acceleration Structure
    # Extract indices from the loaded file
    indices = load_indices_from_file(file_path)
    
    # Convert to triangle triplets if necessary
    triangles = convert_to_triangles(indices)
    
    # Build BVH/Octree
    accel_structure = build_bvh(normalized_vertices, triangles)
    
    return Mesh(normalized_vertices, triangles, accel_structure)
```

**Parameters:**
*   `method`: String, either `"unit_sphere"` or `"unit_cube"`. Default: `"unit_cube"`.
*   `inflation_factor`: Float, typically `0.005` (0.5%), used in Method B to prevent boundary artifacts. [S2, unofficial]

**Edge Cases:**
*   **Degenerate Meshes:** If the mesh consists of a single point or line, the radius or scale factor may be zero. Guard against division by zero. [G]
*   **Non-Triangular Faces:** Ensure the loader triangulates quads or N-gons. [S1, unofficial]
*   **Precision:** Use `float32` for vertices and indices unless higher precision is required for the specific voxelization algorithm. [S1, unofficial]

## Subtopics

### Mesh Preprocessing and BVH/Octree Build
This variant focuses on the construction of acceleration structures and probability distributions for sampling. It normalizes the mesh to $[0, 1]^3$, builds a Triangle BVH and a Triangle Octree, and computes surface area weights for importance sampling. It is chosen when the downstream voxelization requires probabilistic sampling of the surface. [S2, unofficial]

## Operating characteristics
*   **Time Complexity:** Loading is $O(N)$ where $N$ is the number of vertices/faces. Normalization is $O(N)$. BVH/Octree construction is typically $O(N \log N)$ or $O(N)$ depending on the algorithm.
*   **Memory Complexity:** $O(N)$ for storing vertices, indices, and acceleration structure nodes.
*   **Strengths:** Provides a robust, standardized input for subsequent SDF generation. Handles various file formats via Assimp.
*   **Limitations:** Dependent on the Assimp library's support for specific formats. Normalization to a unit cube may distort aspect ratios if not handled carefully for non-uniform scaling requirements.
*   **When to use:** When preparing a mesh for analytic voxelization or SDF generation.
*   **When not to use:** When preserving the original scale and position is critical for the application.

## Background
This method is commonly used in modern voxelization pipelines, particularly those leveraging hardware-accelerated ray tracing (Embree, OptiX). It bridges the gap between raw asset files and the mathematical requirements of analytic SDF computation. The use of Assimp for loading and glm for vector math is a common pattern in C++ graphics applications. [S1, unofficial][S2, unofficial]
