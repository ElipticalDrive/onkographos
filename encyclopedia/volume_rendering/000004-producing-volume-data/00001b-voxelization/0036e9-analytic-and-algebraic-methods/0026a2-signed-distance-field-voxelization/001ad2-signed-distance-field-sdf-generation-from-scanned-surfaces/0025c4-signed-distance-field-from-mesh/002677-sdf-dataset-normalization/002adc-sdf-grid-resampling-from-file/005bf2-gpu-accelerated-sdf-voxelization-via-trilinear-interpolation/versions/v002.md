# GPU-accelerated SDF Voxelization via Trilinear Interpolation

Also called: SDF Voxelization

## Overview
This method converts pre-computed Signed Distance Field (SDF) data into a voxel grid suitable for Lattice Boltzmann Method (LBM) simulations, serving as an alternative to runtime STL mesh voxelization [S1, unofficial]. It leverages GPU-accelerated trilinear interpolation to produce smoother solid boundaries compared to ray-casting STL triangles, and offers performance benefits for complex geometries that are reused across multiple simulations [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A binary SDF file containing grid dimensions, bounding box, and distance values; a target scale in LBM units; an optional center position; and an optional 3×3 rotation matrix [S1, unofficial].
*   **Output:** A voxel grid where each cell is flagged as solid (`TYPE_S`) or fluid, populated by sampling the SDF at transformed coordinates [S1, unofficial].

**Data Structures**
The input SDF file follows a strict binary little-endian layout [S1, unofficial]:
*   **Header (36 bytes):**
    *   Offset 0: `int32` $N_x$ (grid dimension X) [S1, unofficial].
    *   Offset 4: `int32` $N_y$ (grid dimension Y) [S1, unofficial].
    *   Offset 8: `int32` $N_z$ (grid dimension Z) [S1, unofficial].
    *   Offset 12: `float32` $B_{min,x}$ [S1, unofficial].
    *   Offset 16: `float32` $B_{min,y}$ [S1, unofficial].
    *   Offset 20: `float32` $B_{min,z}$ [S1, unofficial].
    *   Offset 24: `float32` $B_{max,x}$ [S1, unofficial].
    *   Offset 28: `float32` $B_{max,y}$ [S1, unofficial].
    *   Offset 32: `float32` $B_{max,z}$ [S1, unofficial].
*   **Data:** A contiguous array of `float32` values starting at offset 36, with layout `data[x + N_x * (y + N_y * z)]` [S1, unofficial]. Negative values indicate inside the solid; positive values indicate outside [S1, unofficial].

**Algorithm Steps**
1.  **Load SDF:** Read the binary file to extract $N_x, N_y, N_z$, bounds, and the distance array [S1, unofficial].
2.  **Upload to GPU:** Transfer the SDF data to device memory [S1, unofficial].
3.  **Initialize Kernel:** Launch an OpenCL kernel where each work-item corresponds to a target voxel in the simulation domain [S1, unofficial].
4.  **Coordinate Transformation:** For each target voxel at position $\mathbf{p}_{lbm}$ in LBM space:
    a.  Translate to center: $\mathbf{p}' = \mathbf{p}_{lbm} - \mathbf{c}$, where $\mathbf{c}$ is the specified center [S1, unofficial].
    b.  Apply inverse rotation: $\mathbf{p}'' = R^{-1} \mathbf{p}'$, where $R$ is the input rotation matrix [S1, unofficial].
    c.  Scale to SDF units: $\mathbf{p}_{sdf} = \mathbf{p}'' / s$, where $s$ is the scale factor [S1, unofficial].
    d.  Map to SDF grid indices: Calculate continuous grid coordinates $(u, v, w)$ within the SDF bounding box $[B_{min}, B_{max}]$ using linear mapping [S1, unofficial].
5.  **Trilinear Interpolation:** Sample the SDF value $d$ at $(u, v, w)$ using trilinear interpolation of the 8 surrounding grid points [S1, unofficial].
6.  **Flagging:** If $d < 0$, flag the voxel as solid (`TYPE_S`); otherwise, flag as fluid (`TYPE_F`) [S1, unofficial].

**Pseudocode**
```python
# Constants and types
TYPE_S = 1  # Solid flag
TYPE_F = 0  # Fluid flag

class float3:
    def __init__(self, x, y, z):
        self.x, self.y, self.z = x, y, z
    def __sub__(self, other):
        return float3(self.x - other.x, self.y - other.y, self.z - other.z)
    def __truediv__(self, scalar):
        return float3(self.x / scalar, self.y / scalar, self.z / scalar)

def get_global_id(dim):
    # Returns the work-item index along the given dimension (OpenCL intrinsic simulation)
    return thread_index[dim]

def mat3x3_mul_vec(R, v):
    # Standard 3x3 matrix-vector multiplication
    return float3(
        R[0][0]*v.x + R[0][1]*v.y + R[0][2]*v.z,
        R[1][0]*v.x + R[1][1]*v.y + R[1][2]*v.z,
        R[2][0]*v.x + R[2][1]*v.y + R[2][2]*v.z
    )

def map_to_grid(val, min_val, max_val, N):
    # Linear mapping from physical space to grid indices [0, N-1]
    return (val - min_val) / (max_val - min_val) * (N - 1)

def trilinear_interpolate(data, Nx, Ny, Nz, u, v, w):
    iu, fu = int(u), u - int(u)
    iv, fv = int(v), v - int(v)
    iw, fw = int(w), w - int(w)

    def get_val(ix, iy, iz):
        # Clamp indices to valid grid range [0, N-1]
        ix = max(0, min(Nx - 1, ix))
        iy = max(0, min(Ny - 1, iy))
        iz = max(0, min(Nz - 1, iz))
        idx = ix + Nx * (iy + Ny * iz)
        return data[idx]

    c000 = get_val(iu, iv, iw)
    c100 = get_val(iu + 1, iv, iw)
    c010 = get_val(iu, iv + 1, iw)
    c110 = get_val(iu + 1, iv + 1, iw)
    c001 = get_val(iu, iv, iw + 1)
    c101 = get_val(iu + 1, iv, iw + 1)
    c011 = get_val(iu, iv + 1, iw + 1)
    c111 = get_val(iu + 1, iv + 1, iw + 1)

    c00 = lerp(c000, c100, fu)
    c01 = lerp(c010, c110, fu)
    c10 = lerp(c001, c101, fu)
    c11 = lerp(c011, c111, fu)

    c0 = lerp(c00, c01, fv)
    c1 = lerp(c10, c11, fv)

    return lerp(c0, c1, fw)

def lerp(a, b, t):
    return a + t * (b - a)

def voxelize_sdf_kernel(sdf_data, Nx, Ny, Nz, bounds_min, bounds_max, 
                        center, R_inv, scale, target_grid_size, output_flags):
    # 1. Get target voxel coordinates
    idx, idy, idz = get_global_id(0), get_global_id(1), get_global_id(2)
    if idx >= target_grid_size[0] or idy >= target_grid_size[1] or idz >= target_grid_size[2]:
        return

    # 2. LBM World Position
    p_lbm = float3(float(idx), float(idy), float(idz))

    # 3. Translate to center
    p_prime = p_lbm - center

    # 4. Apply Inverse Rotation
    p_rotated = mat3x3_mul_vec(R_inv, p_prime)

    # 5. Scale to SDF Space
    p_sdf = p_rotated / scale

    # 6. Map to SDF Grid Coordinates
    u = map_to_grid(p_sdf.x, bounds_min.x, bounds_max.x, Nx)
    v = map_to_grid(p_sdf.y, bounds_min.y, bounds_max.y, Ny)
    w = map_to_grid(p_sdf.z, bounds_min.z, bounds_max.z, Nz)

    # 7. Trilinear Interpolation
    d = trilinear_interpolate(sdf_data, Nx, Ny, Nz, u, v, w)

    # 8. Flagging
    if d < 0:
        output_flags[idx, idy, idz] = TYPE_S
    else:
        output_flags[idx, idy, idz] = TYPE_F
```

**Parameters**
*   `path`: Path to the binary SDF file [S1, unofficial].
*   `center`: `float3` position in LBM coordinates where the SDF center is placed [S1, unofficial].
*   `rotation`: `float3x3` rotation matrix, same format as `voxelize_stl` [S1, unofficial].
*   `scale`: `float` target size of the largest SDF dimension in LBM units; default `1.0f` [S1, unofficial].
*   `flag`: `uchar` voxel flag type; default `TYPE_S` (solid) [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Precision:** Trilinear interpolation smooths the sharp boundaries of the original mesh, which is a feature, but may slightly alter the effective volume of the solid [S1, unofficial].
*   **Rotation Inversion:** The kernel requires the inverse of the provided rotation matrix [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of target voxels $N_{target}$ and constant with respect to SDF resolution for the interpolation step [S1, unofficial].
*   **Memory Complexity:** $O(N_x N_y N_z)$ for the SDF data upload [S1, unofficial].
*   **Performance:** Tested with a cow model resulting in 996,355 solid voxels, achieving ~7000 MLUPs performance [S1, unofficial].
*   **Strengths:** Smoother boundaries than ray-casting; faster for complex, reused geometries compared to runtime STL voxelization [S1, unofficial].
*   **Limitations:** Requires pre-computation of the SDF file; memory usage scales with SDF resolution [S1, unofficial].

## Background
This method was introduced as part of the FluidX3D project to support Lattice Boltzmann Method simulations [S1, unofficial]. It was added to provide an alternative to STL voxelization, leveraging GPU acceleration for efficiency and quality [S1, unofficial]. The SDF files themselves are typically generated from STL meshes using tools like SDFGenFast [S1, unofficial].
