# Signed Distance Field from Mesh

Also called: Signed Mesh SDF, Triangle Mesh SDF, Mesh SDF Rendering

## Overview
This method converts an explicit triangle mesh into a 3D Signed Distance Field (SDF) volume, where each voxel stores the signed Euclidean distance to the nearest point on the mesh surface [S1, S2, unofficial][S4]. The sign is negative inside the surface and positive outside, enabling robust rendering via interval-arithmetic bisection or isosurfacing [S1, S3, unofficial]. It differs from [Slice-based SDF Voxelization](1736-slice-based-sdf-voxelization.md) by computing distances directly from geometric primitives rather than projecting slices, and from [Projective TSDF Fusion](2658-projective-tsdf-fusion.md) by operating on explicit geometry rather than raw depth buffers [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A closed (or open, with caveats) triangle mesh (e.g., STL, OBJ) [S1, unofficial][S4].
- Output: A 3D texture or volume grid where each voxel $(x, y, z)$ contains a scalar signed distance [S2, S5, unofficial].

**Data Structures:**
- **Mesh Representation:** Stored as a list of triangles. For CPU methods, often wrapped in an Accelerated Bounding Volume Hierarchy (BVH) or AABB tree for efficient nearest-point queries [S4]. For GPU methods, vertices may be stored in a texture (`meshtex`) with layout: 3 floats (RGB) per texel, stride 16384 texels per row [S2, unofficial].
- **Voxel Grid:** Defined by resolution `res` (e.g., 50) and bounds (typically $[-1, 1]^3$) [S2, unofficial]. The grid stores `float` values.

**Steps:**
1. **Preprocessing:** Load the mesh and compute its bounding box. Normalize the mesh to fit within a canonical space, typically the unit cube $[-1, 1]^3$ centered at the origin [S2, S1, unofficial].
2. **Grid Initialization:** Define the voxel grid resolution and origin. Map voxel indices to world coordinates [S5, unofficial].
3. **Distance Computation:** For each voxel center `pos`:
   - Find the closest point `cp` on the mesh surface [S4].
   - Compute the unsigned Euclidean distance $d = \| \mathbf{pos} - \mathbf{cp} \|_2$ [S4].
   - Determine the sign based on the mesh topology and the position of `pos` relative to the surface [S3, unofficial][S4].
4. **Sign Determination:**
   - If the mesh is closed and `pos` is on the bounded (inside) side, negate the distance: $d_{signed} = -d$ [S4].
   - Alternatively, use the closest triangle's face normal $\mathbf{n}$: if $\mathbf{n} \cdot (\mathbf{pos} - \mathbf{v}) < 0$ (where $\mathbf{v}$ is a vertex on the triangle), the point is inside [S3, unofficial].
5. **Storage:** Write $d_{signed}$ to the voxel [S2, S5, unofficial].

**Formulas:**
- **Triangle Distance (GPU/Naive):** For a point $\mathbf{p}$ and triangle vertices $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$:
  - Let $\mathbf{e}_1 = \mathbf{v}_1 - \mathbf{v}_0$, $\mathbf{e}_2 = \mathbf{v}_2 - \mathbf{v}_0$, $\mathbf{pa} = \mathbf{p} - \mathbf{v}_0$.
  - Compute barycentric coordinates or projection to find the closest point on the triangle [S2, unofficial].
  - If outside: $d = \| \mathbf{p} - \mathbf{cp} \|$ [S2, unofficial].
  - If inside: $d = \frac{(\mathbf{n} \cdot \mathbf{pa})^2}{\mathbf{n} \cdot \mathbf{n}}$ (projected distance to plane) [S2, unofficial].
  - Inside check: $\sum \text{sign}(\mathbf{ba} \times \mathbf{n} \cdot \mathbf{pa}) < 2$ [S2, unofficial].
- **Ray-Triangle Intersection (Möller-Trumbore):** Used for raycasting approaches [S2, unofficial]:
  - $\mathbf{e}_1 = \mathbf{v}_1 - \mathbf{v}_0$, $\mathbf{e}_2 = \mathbf{v}_2 - \mathbf{v}_0$, $\mathbf{pvec} = \mathbf{dir} \times \mathbf{e}_2$, $\mathbf{tvec} = \mathbf{p} - \mathbf{v}_0$.
  - $det = \mathbf{e}_1 \cdot \mathbf{pvec}$. If $|det| < 10^{-8}$, parallel.
  - $u = (\mathbf{tvec} \cdot \mathbf{pvec}) / det$, $v = (\mathbf{dir} \cdot \mathbf{qvec}) / det$ (where $\mathbf{qvec} = \mathbf{tvec} \times \mathbf{e}_1$).
  - Hit if $0 \le u, v$ and $u + v \le 1$ [S2, unofficial].

**Parameters:**
- `res`: Voxel resolution (e.g., 50) [S2, unofficial].
- `is_closed`: Boolean flag indicating if the mesh is closed, used to determine sign [S4].
- `trunc_dist`: Truncation distance for TSDF variants (not given in sources for pure SDF) [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Open Meshes:** Grow a "skirt" up to `trunc_dist` past their rim [S3, unofficial].
- **Inside-Out Meshes:** If the mesh winding is clockwise (inward normals), the SDF will be inverted (inside-out) [S3, unofficial].
- **Winding:** Requires counter-clockwise winding seen from outside (normal $\mathbf{n} = \text{cross}(\mathbf{v}_1 - \mathbf{v}_0, \mathbf{v}_2 - \mathbf{v}_0)$ points out) [S3, unofficial].
- **Sharp Corners:** Edges/corners with faces meeting at under 90 degrees may take the wrong side due to nearest-face tie-breaking by lowest index [S3, unofficial]. A 90-degree edge off-grid axes also fails [S3, unofficial].
- **Precision:** Rounding errors can cause incorrect sign assignment near boundaries [S3, unofficial].

**Pseudocode (CPU/AABB Tree Approach):**
```python
import numpy as np
from cgal import AABB_tree, Side_of_triangle_mesh # Pseudo-import for CGAL-like API

def generate_sdf_from_mesh(mesh, resolution, bounds=(-1.0, 1.0)):
    """
    Generate SDF from a closed triangle mesh using AABB tree.
    mesh: List of triangles (each triangle is 3 vertices, each vertex is (x,y,z))
    resolution: int, grid size in each dimension
    bounds: tuple, (min_val, max_val) for the canonical space
    """
    # 1. Build AABB tree from mesh faces
    tree = AABB_tree(mesh.faces)
    
    # 2. Initialize sign functor
    # Assumes mesh is closed and winding is correct (outward normals)
    is_closed = True # Must be verified or assumed
    sotm = Side_of_triangle_mesh(mesh)
    
    # 3. Define grid
    min_val, max_val = bounds
    step = (max_val - min_val) / resolution
    grid = np.zeros((resolution, resolution, resolution))
    
    # 4. Iterate over voxel centers
    for i in range(resolution):
        for j in range(resolution):
            for k in range(resolution):
                # Map grid index to world coordinate
                x = min_val + (i + 0.5) * step
                y = min_val + (j + 0.5) * step
                z = min_val + (k + 0.5) * step
                p = np.array([x, y, z])
                
                # 5. Find closest point on mesh
                cp = tree.closest_point(p)
                
                # 6. Compute unsigned distance
                d = np.linalg.norm(p - cp)
                
                # 7. Determine sign
                if is_closed and sotm(p) == Side_of_triangle_mesh.ON_BOUNDED_SIDE:
                    d = -d
                
                grid[i, j, k] = d
                
    return grid
```

## Subtopics

### [Explicit Surface to TSDF Conversion](2615-explicit-surface-to-tsdf-conversion.md)
Converts explicit geometry (triangle meshes, oriented point clouds) into a Truncated Signed Distance Field (TSDF) voxel grid. It differs from [Projective TSDF Fusion](2658-projective-tsdf-fusion.md) by operating directly on explicit primitives rather than raw depth buffers, and from [Sparse VDB SDF Generation](4498-sparse-vdb-sdf-generation.md) by focusing on the initial conversion of a single explicit surface into a dense or sparse voxel volume. Choose this when you need a bounded distance field for integration or rendering, and the input is a clean mesh.

### [SDF Dataset Normalization](3787-sdf-dataset-normalization.md)
Preprocessing step that transforms vertex coordinates of an input 3D mesh to fit within a standardized canonical space, typically the unit cube $[-1, 1]^3$ centered at the origin. It solves the problem of inconsistent scale and position in raw mesh data, which is critical for downstream SDF generation where grid resolution and sampling bounds depend on predictable input dimensions. Choose this before any voxelization method to ensure consistent results.

### [Sparse VDB SDF Generation](4498-sparse-vdb-sdf-generation.md)
Converts a triangle mesh into a sparse, tree-structured signed or unsigned distance grid using OpenVDB, storing only active voxels near the surface for memory efficiency. It differs from dense voxelization by dynamically allocating memory only for the narrow band around the mesh, making it suitable for large or complex models where ray-marched rendering or fast implicit queries are required. Choose this for large-scale scenes or when memory is constrained.

### [Naive SDF Generation (CPU)](10688-naive-sdf-generation-cpu.md)
Computes the SDF for a triangle mesh by explicitly evaluating the distance from every voxel sample point to every triangle in the mesh. It converts an explicit mesh representation into an implicit volume representation suitable for ray marching or voxel-based rendering [G]. Unlike spatial acceleration methods, it performs a linear scan of all triangles for each sample, making it simple to implement but computationally prohibitive for high-resolution volumes or complex meshes. Choose this for small meshes or prototyping.

### [SDF BSP Tree Construction](15293-sdf-bsp-tree-construction.md)
Generates a Signed Distance Field (SDF) from a triangle mesh by recursively subdividing space into two sets using dividing hyperplanes, allowing ray traversal to calculate the distance to the nearest point on the surface. It offers perfect accuracy compared to voxel grids by using original triangles, but suffers from poor generation and runtime performance due to sequential CPU construction and GPU-unfriendly branching. Choose this when exact distance queries are required and voxelization artifacts are unacceptable.

## Operating characteristics
- **Time Complexity:** $O(N \cdot M)$ for naive CPU methods, where $N$ is the number of voxels and $M$ is the number of triangles [S1, unofficial]. With AABB trees, it reduces to $O(N \log M)$ [S4]. GPU implementations can parallelize the voxel loop, but triangle traversal remains a bottleneck [S2, unofficial].
- **Memory Complexity:** $O(N)$ for dense voxel grids [S1, unofficial]. Sparse methods (VDB) use $O(K)$ where $K \ll N$ is the number of active voxels near the surface [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Performance degrades linearly with resolution in naive methods. Accelerated methods scale better but have higher overhead for tree construction [S4].
- **Strengths:** Robust rendering with interval arithmetic [S1, unofficial]; exact distance queries (non-voxelized variants) [S1, unofficial]; supports CSG operations [S1, unofficial].
- **Limitations:** Open meshes cause artifacts (skirts) [S3, unofficial]; sensitive to mesh winding and topology [S3, unofficial]; high memory usage for dense grids [S1, unofficial].
- **When to use:** Rendering CAD meshes, isosurfacing offset meshes [S4][S1, unofficial].
- **When not to use:** Open meshes without truncation (use Shell mode) [S3, unofficial]; extremely high-resolution meshes where naive CPU methods are too slow [S1, unofficial].

## Background
Originated from the need to render complex CAD meshes (e.g., brake calipers, sheet-metal hooks) as implicit surfaces using robust interval-arithmetic bisection [S1, unofficial]. The method is implemented in libraries like `isoray` (MeshSDF class) and CGAL (Isosurfacing_3 module) [S1, unofficial][S4]. It allows meshes to be treated as analytic implicit functions, enabling seamless integration with CSG operations and differentiable rendering [S1, unofficial].
