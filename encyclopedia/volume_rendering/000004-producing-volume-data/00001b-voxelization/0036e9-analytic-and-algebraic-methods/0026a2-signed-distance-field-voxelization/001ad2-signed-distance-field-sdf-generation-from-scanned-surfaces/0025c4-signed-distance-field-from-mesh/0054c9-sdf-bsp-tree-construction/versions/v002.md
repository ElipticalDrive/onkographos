# SDF BSP Tree Construction

Also called: BSP Tree, BSP Tree Construction for SDF, Binary Space Partitioning (BSP) Tree SDF, SDF BSP Tree, Signed Distance Field BSP Tree

## Overview
A method to generate a Signed Distance Field (SDF) from a triangle mesh by recursively subdividing space into two sets using dividing hyperplanes, allowing ray traversal to calculate the distance to the nearest point on the surface [S1, unofficial]. It offers perfect accuracy compared to voxel grids by using original triangles, but suffers from poor generation and runtime performance due to sequential CPU construction and GPU-unfriendly branching [S1, unofficial].

## How it works

### Inputs and Outputs
- **Input**: A triangle mesh (list of vertices and indices) [S1, unofficial].
- **Output**: A Binary Space Partitioning (BSP) tree where leaf nodes contain subsets of the original mesh triangles [S1, unofficial].

### Data Structures

**BSP Node**
- `plane`: Plane equation $(\mathbf{n}, d)$, where $\mathbf{n}$ is the normal and $d$ is the distance from origin [S1, unofficial].
- `front`: Pointer to child BSP node (geometry in front of plane) [S1, unofficial].
- `back`: Pointer to child BSP node (geometry behind plane) [S1, unofficial].
- `triangles`: List of triangle indices (only present in leaf nodes) [S1, unofficial].

**Plane**
- $\mathbf{n}$: Normal vector $(n_x, n_y, n_z)$ [S1, unofficial].
- $d$: Scalar offset [S1, unofficial].
- Signed distance from point $\mathbf{p}$ to plane: $s = \mathbf{n} \cdot \mathbf{p} - d$ [S1, unofficial].

### Steps

1. **Construct BSP Tree on CPU**: Call `BuildTree(triangles)` [S1, unofficial].
2. **Select Dividing Plane**: Choose between **General Partitioning Plane** or **Autopartitioning Plane** [S1, unofficial].
   - **General Partitioning Plane**:
     - Calculate centroid $\mathbf{c}$ of all vertices in the current set [S1, unofficial].
     - Compute the $3 \times 3$ covariance matrix $\Sigma$ for the vertices $V$:
       $$ \Sigma = \begin{bmatrix} Cov(x,x) & Cov(x,y) & Cov(x,z) \\ Cov(y,x) & Cov(y,y) & Cov(y,z) \\ Cov(z,x) & Cov(z,y) & Cov(z,z) \end{bmatrix} $$
       Where covariance between components $u$ and $v$ is:
       $$ Cov(u,v) = \frac{1}{N} \sum_{i=1}^{N} (u_i - \bar{u})(v_i - \bar{v}) $$
       ($N$ is number of vertices, $\bar{u}, \bar{v}$ are means) [S1, unofficial].
     - Solve for eigenvalues $\lambda$ of $\Sigma$ using Eberly's numerically robust noniterative method for the characteristic polynomial of a $3 \times 3$ matrix [S1, unofficial].
       - Characteristic polynomial: $\lambda^3 - \text{tr}(\Sigma)\lambda^2 + C\lambda - \det(\Sigma) = 0$, where $C$ is the sum of principal minors [S1, unofficial].
     - Solve for eigenvectors $\mathbf{v}$ using $(\Sigma - \lambda I)\mathbf{v} = \mathbf{0}$ [S1, unofficial].
     - Select the eigenvector corresponding to the largest eigenvalue as the plane normal $\mathbf{n}$ [S1, unofficial].
     - Set plane position $d = \mathbf{n} \cdot \mathbf{c}$ [S1, unofficial].
   - **Autopartitioning Plane**:
     - Find the Axis-Aligned Bounding Box (AABB) of the current vertex set [S1, unofficial].
     - Select the largest axis of the box [S1, unofficial].
     - Test all triangles against this axis using a dot product with their normals [S1, unofficial].
     - Choose the triangle with a normal facing closest to the axis as the dividing plane [S1, unofficial].
3. **Partition Geometry**:
   - Classify each triangle in the current set with respect to the dividing plane by calculating the signed distance for each vertex [S1, unofficial]:
     - If all signs are positive: Triangle is **in front** [S1, unofficial].
     - If all signs are negative: Triangle is **behind** [S1, unofficial].
     - If mixture of signs: Triangle is **straddling** [S1, unofficial].
     - If all distances are 0: Triangle is **coincident** (safely ignored, treat as front or behind) [S1, unofficial].
   - **Handling Straddling Triangles**:
     - *Approach 1 (Split)*: Split triangle into two. Dropped as it makes mesh harder to split [S1, unofficial].
     - *Approach 2 (Duplicate)*: Add triangle to both front and back sets. Causes overlap, higher memory usage, and potential infinite loops if same triangles added repeatedly [S1, unofficial].
   - Recursively call `BuildTree` on the front and back sets [S1, unofficial].
4. **Termination**: Stop recursion if a heuristic is met, typically a **maximum triangle count** in a node [S1, unofficial].

### Pseudocode

```python
import math

def dot(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def sub(a, b): return [a[0]-b[0], a[1]-b[1], a[2]-b[2]]
def cross(a, b): return [a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0]]
def normalize(v):
    l = math.sqrt(dot(v, v))
    return [v[0]/l, v[1]/l, v[2]/l] if l > 1e-8 else [1.0, 0.0, 0.0]

class Plane:
    def __init__(self, normal, distance):
        self.normal = normal
        self.distance = distance
    def signed_distance(self, point):
        return dot(self.normal, point) - self.distance

class Triangle:
    def __init__(self, v0, v1, v2):
        self.vertices = [v0, v1, v2]
        self.normal = normalize(cross(sub(v1, v0), sub(v2, v0)))

class BSPNode:
    def __init__(self, plane=None):
        self.plane = plane
        self.front = None
        self.back = None
        self.triangles = []

def build_bsp(triangles, max_triangles=10):
    if len(triangles) <= max_triangles:
        node = BSPNode()
        node.triangles = triangles
        return node
    plane = select_dividing_plane(triangles)
    front_triangles = []
    back_triangles = []
    for tri in triangles:
        signs = []
        for v in tri.vertices:
            signs.append(plane.signed_distance(v))
        if all(s > 0 for s in signs):
            front_triangles.append(tri)
        elif all(s < 0 for s in signs):
            back_triangles.append(tri)
        elif all(s == 0 for s in signs):
            front_triangles.append(tri)
        else:
            front_triangles.append(tri)
            back_triangles.append(tri)
    node = BSPNode(plane)
    node.front = build_bsp(front_triangles, max_triangles)
    node.back = build_bsp(back_triangles, max_triangles)
    return node

def select_dividing_plane(triangles):
    vertices = []
    for tri in triangles:
        vertices.extend(tri.vertices)
    n = len(vertices)
    centroid = [sum(v[i] for v in vertices)/n for i in range(3)]
    means = centroid
    cov = [[0.0]*3 for _ in range(3)]
    for i in range(3):
        for j in range(3):
            cov[i][j] = sum((v[i]-means[i])*(v[j]-means[j]) for v in vertices)/n
    eigenvalues = solve_eigenvalues_3x3(cov)
    max_idx = eigenvalues.index(max(eigenvalues))
    normal = solve_eigenvector(cov, eigenvalues[max_idx])
    distance = dot(normal, centroid)
    return Plane(normal, distance)

def solve_eigenvalues_3x3(m):
    tr = m[0][0] + m[1][1] + m[2][2]
    C = (m[0][0]*m[1][1] - m[0][1]*m[1][0]) + (m[0][0]*m[2][2] - m[0][2]*m[2][0]) + (m[1][1]*m[2][2] - m[1][2]*m[2][1])
    det = m[0][0]*(m[1][1]*m[2][2] - m[1][2]*m[2][1]) - m[0][1]*(m[1][0]*m[2][2] - m[1][2]*m[2][0]) + m[0][2]*(m[1][0]*m[2][1] - m[1][1]*m[2][0])
    # Solves lambda^3 - tr*lambda^2 + C*lambda - det = 0 per Eberly's method [G]
    p = C - tr*tr/3.0
    q = 2.0*tr*tr*tr/27.0 - C*tr/3.0 + det
    D = q*q/4.0 + p*p*p/27.0
    if D > 0:
        u = (-q/2.0 + math.sqrt(D))**(1/3.0)
        v = (-q/2.0 - math.sqrt(D))**(1/3.0)
        return [u+v+tr/3.0, u+v+tr/3.0, u+v+tr/3.0]
    return [0.0, 0.0, 0.0]

def solve_eigenvector(m, eigenvalue):
    a = m[0][0] - eigenvalue
    b = m[0][1]
    c = m[0][2]
    d = m[1][0]
    e = m[1][1] - eigenvalue
    f = m[1][2]
    v = [b*f - c*e, c*d - a*f, a*e - b*d]
    return normalize(v)

def ray_triangle_intersection(origin, direction, tri):
    # Standard Möller–Trumbore ray-triangle intersection [G]
    v0, v1, v2 = tri.vertices
    e1 = sub(v1, v0)
    e2 = sub(v2, v0)
    h = cross(direction, e2)
    a = dot(e1, h)
    if a < 1e-8: return None
    f = 1.0/a
    s = sub(origin, v0)
    u = f * dot(s, h)
    if u < 0.0 or u > 1.0: return None
    q = cross(s, e1)
    v = f * dot(direction, q)
    if v < 0.0 or u + v > 1.0: return None
    t = f * dot(e2, q)
    return t if t > 1e-8 else None

def traverse_to_leaf(node, point):
    current = node
    while current.plane is not None:
        if current.plane.signed_distance(point) > 0:
            current = current.front
        else:
            current = current.back
    return current

def raymarch_bsp(ray_origin, ray_direction, root_node, max_steps=1000, max_dist=100.0):
    t = 0.0
    for _ in range(max_steps):
        if t >= max_dist: break
        point = [ray_origin[i] + ray_direction[i]*t for i in range(3)]
        leaf = traverse_to_leaf(root_node, point)
        min_tri_dist = float('inf')
        for tri in leaf.triangles:
            dist = ray_triangle_intersection(point, ray_direction, tri)
            if dist is not None and dist < min_tri_dist:
                min_tri_dist = dist
        if min_tri_dist < 1e-6: break
        t += min_tri_dist
    return t
```

### Parameters
- **Maximum triangle count**: Heuristic for stopping recursion. Typical values not given in sources, but small enough to keep leaf nodes efficient [S1, unofficial].

### Edge Cases and Pitfalls
- **Straddling Triangles**: Splitting triangles makes mesh harder to split. Adding to both sides causes overlap, higher memory usage, and potential infinite loops if the same triangles are added repeatedly [S1, unofficial].
- **Infinite Loops/Memory Exhaustion**: Adding triangles to both sides can lead to infinite loops. Example: generating for a few hours and consuming over 97% of memory without completing [S1, unofficial].
- **Caching Optimization Error**: Caching the closest leaf node (Wald's thesis method) causes rendering errors because the ray never checks distances to other triangles in the mesh that may be closer [S1, unofficial].
- **Precision**: Eberly's method is used for numerical robustness in eigenvalue solving [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
- **Generation Time**: Very slow. The algorithm takes a while to generate and is not suitable for larger data sets [S1, unofficial]. CPU utilization averages 6.7%, suggesting multithreading could halve generation time [S1, unofficial].
- **Runtime Performance**: Poor. Average frame time of 0.0498ms [S1, unofficial]. Reasons: slow tree traversal per ray step/pixel/frame, and branching unforgiving for GPU lock-stepping parallelism [S1, unofficial].
- **Memory**: High. Triangle mesh must be maintained alongside BSP tree nodes and leaf node indices. Straddling triangles added to both sides exacerbate this [S1, unofficial].

### Scaling
- **Mesh Size**: Larger meshes are practically impossible to generate useful trees for with the current system due to memory and time constraints [S1, unofficial].
- **Parallelism**: Sequential CPU construction limits scalability. Multithreading could be applied after the first split [S1, unofficial].

### Strengths and Limitations
- **Strengths**: Perfect accuracy using original triangles, adapts well to the shape of the underlying surface [S1, unofficial].
- **Limitations**: Very poor generation and runtime performance, high memory consumption, GPU-unfriendly branching [S1, unofficial].

### When to Use
- Use when perfect accuracy is required and mesh size is small [S1, unofficial].
- Avoid for large datasets or real-time applications requiring high frame rates [S1, unofficial].

## Background

### Origin
- Explored in the context of representing meshes using distance fields for real-time applications like games [S1, unofficial].
- References Wu & Kobbelt (2003) for BSP tree adaptation to surface shape [S1, unofficial].
- References Fryazinov et al. (2011) for generation time issues [S1, unofficial].

### History and Development
- Binary Space Partitioning (BSP) trees recursively subdivide space using hyperplanes [S1, unofficial].
- KD-Trees (Wald et al., 2005) are a type of BSP tree with axis-aligned planes [S1, unofficial].
- Eberly's method for eigenvalue solving is preferred for numerical robustness over Householder or QR methods [S1, unofficial].

### Where It Is Used
- Custom C++ engines using Vulkan for real-time rendering [S1, unofficial].
