# SDF Dataset Normalization

Also called: SDF Mesh Loading

## Overview
SDF Dataset Normalization is a preprocessing method that loads a 3D mesh and transforms its vertex coordinates to fit within the range $[-1, 1]$ along each axis [S1, unofficial]. It differs from [Explicit Surface to TSDF Conversion](2615-explicit-surface-to-tsdf-conversion.md) and [Sparse VDB SDF Generation](4498-sparse-vdb-sdf-generation.md) by operating directly on the source mesh geometry before discretization [S1, unofficial].

## How it works
**Inputs:** A path to a mesh file [S1, unofficial].
**Outputs:** A normalized mesh object with vertices scaled and translated to fit within the bounding box $[-1, 1]^3$ [S1, unofficial].

**Data Structures:**
- `mesh`: Object containing vertex coordinates `vertices` (array of shape $[N, 3]$) and faces.
- `vs`: Vertex array extracted from `mesh.vertices`.
- `vmin`: 3D vector of minimum coordinate extents.
- `vmax`: 3D vector of maximum coordinate extents.
- `v_center`: 3D vector representing the bounding box midpoint.

**Steps:**
1. Load the mesh from the given path using `trimesh.load` with `force='mesh'` [S1, unofficial].
2. Extract the vertex coordinates `vs` from `self.mesh.vertices` [S1, unofficial].
3. Calculate `vmin` as the minimum value of `vs` along axis 0, yielding a 3D vector of per-axis minimums [S1, unofficial].
4. Calculate `vmax` as the maximum value of `vs` along axis 0 [S1, unofficial].
5. Calculate `v_center` as the midpoint of the bounding box:
   $$ v_{center} = \frac{v_{min} + v_{max}}{2} $$
6. [G] Compute the scale factor $s = \frac{2}{\max(v_{max} - v_{min})}$ to ensure the largest bounding box dimension maps to a span of 2.
7. [G] Apply the transformation to each vertex $v_i$: $v_i' = (v_i - v_{center}) \times s$, centering the mesh at the origin and scaling it to fit within $[-1, 1]^3$.

**Parameters:**
- Target range: $[-1, 1]$ for each axis [S1, unofficial].

**Edge cases and pitfalls:**
- If all vertices are identical, the bounding box dimensions are zero, causing division by zero during scaling; a guard must check for this degenerate case [G].

**Pseudocode:**
```python
import numpy as np
import trimesh

def normalize_sdf_mesh(mesh_path: str) -> trimesh.Trimesh:
    # Step 1: Load mesh
    mesh = trimesh.load(mesh_path, force='mesh')
    
    # Step 2: Extract vertices
    vs = mesh.vertices  # Shape: [N, 3]
    
    # Step 3 & 4: Calculate vmin and vmax
    vmin = np.min(vs, axis=0)
    vmax = np.max(vs, axis=0)
    
    # Step 5: Calculate center
    v_center = (vmin + vmax) / 2.0
    
    # Step 6: Calculate scale
    dimensions = vmax - vmin
    max_dim = np.max(dimensions)
    if max_dim == 0:
        return mesh  # Guard for degenerate case [G]
    
    scale = 2.0 / max_dim
    
    # Step 7: Apply transformation
    normalized_vertices = (vs - v_center) * scale
    
    # Create a new mesh with normalized vertices
    normalized_mesh = trimesh.Trimesh(vertices=normalized_vertices, faces=mesh.faces)
    
    return normalized_mesh
```

## Subtopics

### [Mesh Normalization](3796-mesh-normalization.md)
Mesh Normalization is a preprocessing method that transforms a 3D mesh's vertex coordinates so that the geometry fits within a standardized canonical space, typically a unit cube or unit sphere centered at the origin [G]. This process solves the problem of inconsistent scale and position in input meshes, which is critical for downstream volume rendering pipelines such as Signed Distance Field (SDF) generation, where grid resolution and sampling bounds depend on predictable input dimensions [G]. It differs from [SDF Grid Resampling from File](4878-sdf-grid-resampling-from-file.md) by operating on the source mesh geometry directly rather than on an existing voxel grid, ensuring the input data is normalized before discretization [G].

### [SDF Grid Resampling from File](4878-sdf-grid-resampling-from-file.md)
Reads a raw Signed Distance Field (SDF) text file, parses its grid resolution, bounding box, and voxel size, then resamples it to a target cubic grid resolution using coordinate mapping and clamping [G]. It differs from sibling methods by handling non-cubic source grids and normalizing the spatial extent to a centered bounding box before interpolation [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of vertices, requiring a single pass to find min/max and a single pass to transform vertices [G].
- **Memory Complexity:** $O(N)$ to store the vertex array and the new mesh [G].
- **Strengths:** Ensures consistent input scale for SDF generation, preventing issues with grid resolution and sampling bounds [G].
- **Limitations:** Only normalizes position and scale; does not handle rotation or non-uniform scaling of the original mesh unless explicitly included [G].
- **When to use:** When preparing mesh data for SDF voxelization or other volume rendering pipelines that require canonical input bounds [G].
- **When not to use:** When the original scale or orientation is critical and must be preserved, or when the input is already a voxel grid rather than a mesh [G].

## Background
The method originates from the NeRF-Factory/IDDR-NGP project, which uses it as part of its data loading pipeline for generating Signed Distance Fields from meshes [S1, unofficial]. It is a standard preprocessing step in many 3D deep learning and rendering frameworks to ensure consistent input data [G].
