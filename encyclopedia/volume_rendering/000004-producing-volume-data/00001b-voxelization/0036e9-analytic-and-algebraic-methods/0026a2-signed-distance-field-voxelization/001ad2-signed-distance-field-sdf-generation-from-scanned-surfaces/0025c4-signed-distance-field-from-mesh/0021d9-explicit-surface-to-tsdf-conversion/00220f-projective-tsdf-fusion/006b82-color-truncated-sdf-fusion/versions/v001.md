# Color Truncated SDF Fusion
Also called: KinectFusion with Color, Kintinous Color Fusion

## Overview
Color Truncated SDF Fusion extends Projective TSDF Fusion by integrating color information into the volume alongside the signed distance field (SDF) [S1, unofficial]. It solves the problem of producing photorealistic, textured 3D models from RGB-D data by maintaining a separate color volume that is updated via weighted averaging based on the SDF integration weights [S1, unofficial]. It differs from its parent method by adding a parallel color accumulation step and from [Single Layer TSDF Update](13744-single-layer-tsdf-update.md) by operating on the full 3D voxel grid rather than a single slice.

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `vol`: A `BoundedVolume<SDF_t>` storing the fused SDF values. `SDF_t` is a struct containing `sd` (clamped signed distance) and `w` (integration weight).
    *   `colorVol`: A `BoundedVolume<float>` storing the fused color value for each voxel, initialized to zero or a background color.
    *   `depth`: An `Image<float>` containing depth values.
    *   `normals`: An `Image<float4>` containing surface normals (x, y, z components in the first three floats).
    *   `img`: An `Image<uchar3>` containing RGB color data (8-bit unsigned integer per channel).
    *   `T_cw`: A `Mat<float,3,4>` transformation matrix from world to depth camera coordinates.
    *   `K`: Intrinsics for the depth camera.
    *   `T_iw`: A `Mat<float,3,4>` transformation matrix from world to color (image) camera coordinates [S1, unofficial].
    *   `Kimg`: Intrinsics for the color camera [S1, unofficial].
    *   `trunc_dist`: The truncation distance for the SDF.
    *   `max_w`: The maximum allowed integration weight.
    *   `mincostheta`: The minimum cosine of the angle between the viewing ray and surface normal.
*   **Outputs:** Updated `vol` and `colorVol`.

**Data Structures:**
*   `SDF_t`: A struct with fields `sd` (float, signed distance) and `w` (float, weight).
*   `BoundedVolume<T>`: A 3D grid structure accessible via `vol(x,y,z)` or `vol.VoxelPositionInUnits(x,y,z)`.
*   `Image<T>`: A 2D image structure with methods `GetBilinear`, `InBounds`, and `Project`.

**Steps:**
1.  Launch a GPU kernel iterating over the x and y dimensions of the volume, with a loop over the z dimension inside the kernel: `for(int z=0; z < vol.d; ++z)`.
2.  Compute the world position $P_w$ for the voxel $(x,y,z)$ using `vol.VoxelPositionInUnits(x,y,z)`.
3.  Transform $P_w$ to the depth camera coordinate system: $P_c = T_{cw} P_w$.
4.  Project $P_c$ to the depth image coordinates: $p_c = K.\text{Project}(P_c)$.
5.  Transform $P_w$ to the color camera coordinate system: $P_i = T_{iw} P_w$.
6.  Project $P_i$ to the color image coordinates: $p_i = K_{img}.\text{Project}(P_i)$.
7.  Check if $p_c$ is within bounds of the depth image and $p_i$ is within bounds of the color image, using a margin of 2 pixels: `depth.InBounds(p_c, 2) && img.InBounds(p_i, 2)`.
8.  Retrieve the depth value $m_d$, normal $m_{dn}$, and color $c$ using bilinear interpolation:
    *   $m_d = \text{depth}.\text{GetBilinear<float>}(p_c)$
    *   $m_{dn} = \text{make\_float3}(\text{normals}.\text{GetBilinear<float4>}(p_c))$
    *   $c = \text{ConvertPixel<float,float3>}( \text{img}.\text{GetBilinear<float3>}(p_i) ) / 255.0$
9.  Calculate the viewing ray direction $P_c$ (from camera center to point), the depth value $v_d = P_c.z$, and the observed depth $m_d$.
10. Calculate the cosine of the angle between the normal and the viewing ray:
    $$ \cos\theta = \frac{\text{dot}(m_{dn}, P_c)}{-\text{length}(P_c)} $$
11. Calculate the signed distance $s_d$ and integration weight $w$:
    $$ s_d = \cos\theta \cdot (m_d - v_d) $$
    $$ w = \cos\theta \cdot \frac{1.0f}{v_d} $$
12. If $s_d \le -\text{trunc\_dist}$, skip the voxel.
13. If $m_d$ and $w$ are finite and $\cos\theta > \text{mincostheta}$:
    a. Retrieve the current SDF value at the voxel: `curvol = vol(x,y,z)`.
    b. Create a new SDF value with clamped distance and weight:
       $$ \text{sdf} = (\text{clamp}(s_d, -\text{trunc\_dist}, \text{trunc\_dist}), w) $$
    c. Add the new SDF value to the current one: `sdf += curvol`.
    d. Limit the weight: `sdf.LimitWeight(max_w)`.
    e. Update the SDF volume: `vol(x,y,z) = sdf`.
    f. Update the color volume using a weighted average:
       $$ \text{colorVol}(x,y,z) = \frac{w \cdot c + \text{colorVol}(x,y,z) \cdot \text{curvol}.w}{w + \text{curvol}.w} $$

**Pseudocode:**
```python
def kern_sdf_fuse(vol, color_vol, depth_img, norm_img, img, T_cw, K, T_iw, Kimg, trunc_dist, max_w, mincostheta):
    # Grid and block dimensions are handled by the runtime
    x = blockIdx.x * blockDim.x + threadIdx.x
    y = blockIdx.y * blockDim.y + threadIdx.y
    
    for z in range(vol.d):
        P_w = vol.VoxelPositionInUnits(x, y, z)
        P_c = T_cw * P_w
        p_c = K.Project(P_c)
        P_i = T_iw * P_w
        p_i = Kimg.Project(P_i)
        
        if depth_img.InBounds(p_c, 2) and img.InBounds(p_i, 2):
            v_d = P_c.z
            m_d = depth_img.GetBilinear(p_c)
            m_dn = make_float3(norm_img.GetBilinear(p_c))
            c_raw = img.GetBilinear(p_i)
            c = convert_to_float3(c_raw) / 255.0
            
            costheta = dot(m_dn, P_c) / -length(P_c)
            sd = costheta * (m_d - v_d)
            w = costheta * (1.0 / v_d)
            
            if sd <= -trunc_dist:
                continue
            
            if is_finite(m_d) and is_finite(w) and costheta > mincostheta:
                curvol = vol[x, y, z]
                new_sd = clamp(sd, -trunc_dist, trunc_dist)
                new_w = w
                
                # Accumulate SDF
                acc_sd = new_sd + curvol.sd
                acc_w = new_w + curvol.w
                
                # Limit weight
                if acc_w > max_w:
                    acc_w = max_w
                
                vol[x, y, z] = SDF_t(acc_sd, acc_w)
                
                # Update Color
                color_vol[x, y, z] = (w * c + color_vol[x, y, z] * curvol.w) / (w + curvol.w)
```

**Parameters:**
*   `trunc_dist`: Typical values depend on voxel size; not given in the sources.
*   `max_w`: Not given in the sources.
*   `mincostheta`: Not given in the sources.

**Edge Cases and Pitfalls:**
*   Precision: Color is normalized by 255.0 to float [S1, unofficial].
*   Boundaries: A margin of 2 pixels is used for bounds checking [S1, unofficial].
*   Degenerate input: If `length(P_c)` is zero, division by zero occurs in `costheta` and `w` calculations. The code assumes valid camera projections.

## Subtopics

### Single Layer TSDF Update
Updates only a single slice of the volume. Choose when memory is constrained or for real-time slice-by-slice processing. [Single Layer TSDF Update](13744-single-layer-tsdf-update.md)

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of voxels in the volume, $O(W \cdot H \cdot D)$, where $W, H, D$ are volume dimensions.
*   **Memory Complexity**: $O(W \cdot H \cdot D)$ for the SDF volume plus $O(W \cdot H \cdot D)$ for the color volume.
*   **Measured Performance**: Not given in the sources.
*   **Strengths**: Produces textured 3D models; integrates color alongside geometry.
*   **Limitations**: Requires synchronized RGB-D data; color updates are subject to the same weighting and truncation as SDF.
*   **When to use**: When photorealistic reconstruction is required.
*   **When not**: When only geometry is needed or color data is unavailable.

## Background
Originated as an extension to KinectFusion, described in "Robust Tracking for Real-Time Dense RGB-D Mapping with Kintinous" by Whelan et al. [S1, unofficial]. It is used in real-time dense RGB-D mapping systems.
