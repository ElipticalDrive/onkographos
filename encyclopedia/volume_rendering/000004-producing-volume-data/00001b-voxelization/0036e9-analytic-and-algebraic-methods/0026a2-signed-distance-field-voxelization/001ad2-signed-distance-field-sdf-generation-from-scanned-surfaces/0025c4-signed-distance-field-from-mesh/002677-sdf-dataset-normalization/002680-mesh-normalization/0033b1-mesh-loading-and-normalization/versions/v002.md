# Mesh Loading and Normalization

Also called: Mesh Import and Preprocessing, Assimp Mesh Loading

## Overview
This method loads a 3D model from a file, extracts vertices and indices, normalizes the mesh to a canonical space, and builds an acceleration structure for ray tracing [S1, unofficial]. It differs from [Mesh Normalization](3796-mesh-normalization.md) by including file I/O and acceleration structure construction, and from [SDF Generation from Scanned Surfaces](3795-sdf-generation-from-scanned-surfaces.md) by stopping at the mesh representation rather than computing the distance field [G].

## How it works
**Inputs:** A file path to a 3D model (e.g., OBJ, STL) and configuration flags for loading [S1, unofficial][S2, unofficial].
**Outputs:** A normalized mesh data structure containing vertices, indices, and an associated acceleration structure (e.g., BVH or Octree) [S1, unofficial][S2, unofficial].

**Data Structures:**
*   **Vertex:** A 3D vector (`glm::vec3` or equivalent), using `float32` per component [S1, unofficial].
*   **Index:** A triplet of unsigned integers (`glm::uvec3` or equivalent), representing triangle face connectivity [S1, unofficial].
*   **Acceleration Structure:** A hierarchical data structure (BVH or Octree) storing triangle references for efficient ray intersection [S2, unofficial].

**Steps:**

1.  **Load Model:** Import the mesh file using Assimp with flags: `Triangulate`, `JoinIdenticalVertices`, `RemoveComponent`, `ImproveCacheLocality`, `OptimizeMeshes`, `OptimizeGraph`, and `DropNormals` [S1, unofficial]. Extract vertices and face indices from the first mesh in the scene [S1, unofficial].
2.  **Compute Bounding Box:** Calculate the Axis-Aligned Bounding Box (AABB) of the raw vertices [S2, unofficial]. Find the centroid $C$ and maximum distance $R$ from the centroid to any vertex [S1, unofficial]. Alternatively, compute the diagonal vector $D = \text{max} - \text{min}$ and scale factor $S = \max(|D_x|, |D_y|, |D_z|)$ [S2, unofficial].
3.  **Normalize Geometry:** Transform vertices to fit a canonical space.
    *   **Method A (Unit Sphere):** Translate vertices by $-C$ and scale by $1/R$ to center the mesh at the origin and fit it within a unit sphere [S1, unofficial].
    *   **Method B (Unit Cube):** Translate vertices by $-0.5 \times D - \text{min}$ and scale by $1/S$, then add $0.5$ to map the mesh to the $[0, 1]^3$ cube [S2, unofficial]. Inflate the final AABB by $0.5\%$ and intersect with $[0, 1]^3$ to prevent precision issues [S2, unofficial].
4.  **Build Acceleration Structure:** Convert face indices to triangle primitives (triplets of vertex indices) [S1, unofficial]. Build a BVH and a Triangle Octree using the normalized vertices and indices [S2, unofficial]. Copy the structure to GPU memory if hardware-accelerated ray tracing is used [S2, unofficial]. Compute triangle surface area weights and build a discrete probability distribution (CDF) for sampling [S2, unofficial].

    # 2. Compute Bounding Box

    normalized_vertices = []
    for v in raw_vertices:
        if method == "unit_sphere":

            radius = length(centered)
            if radius > 0:
                normalized_vertices.append(centered / radius)
            else:
                normalized_vertices.append(centered)
        elif method == "unit_cube":
            normalized_v = (v - min_coord - 0.5 * diagonal) / scale_factor + 0.5
            normalized_vertices.append(normalized_v)

    # 4. Build Acceleration Structure
    # Convert face indices to triangle triplets [G]
    triangles = [tuple(raw_indices[i:i+3]) for i in range(0, len(raw_indices), 3)]
    # Construct BVH/Octree from vertices and triangles [G]
    accel_structure = build_accel_structure(normalized_vertices, triangles)
    return normalized_vertices, triangles, accel_structure

**Parameters:**
*   `method`: String, either `"unit_sphere"` or `"unit_cube"`. Default: `"unit_cube"`.
*   `inflation_factor`: Float, typically `0.005` (0.5%), used in Method B to prevent boundary artifacts [S2, unofficial].

**Edge Cases:**
*   **Degenerate Meshes:** If the mesh consists of a single point or line, the radius or scale factor may be zero. Guard against division by zero [G].
*   **Non-Triangular Faces:** Ensure the loader triangulates quads or N-gons [S1, unofficial].
*   **Precision:** Use `float32` for vertices and `uint32` for indices [S1, unofficial].

## Subtopics

### Mesh Preprocessing and BVH/Octree Build
This variant focuses on the construction of acceleration structures and probability distributions for sampling [S2, unofficial]. It normalizes the mesh to $[0, 1]^3$, builds a Triangle BVH and a Triangle Octree, and computes surface area weights for importance sampling [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Loading is $O(N)$ where $N$ is the number of vertices/faces [G]. Normalization is $O(N)$ [G]. BVH/Octree construction is typically $O(N \log N)$ or $O(N)$ depending on the algorithm [G].
*   **Memory Complexity:** $O(N)$ for storing vertices, indices, and acceleration structure nodes [G].
*   **Strengths:** Provides a robust, standardized input for subsequent SDF generation [G]. Handles various file formats via Assimp [S1, unofficial].
*   **Limitations:** Dependent on the Assimp library's support for specific formats [G]. Normalization to a unit cube may distort aspect ratios if not handled carefully for non-uniform scaling requirements [G].
*   **When to use:** When preparing a mesh for analytic voxelization or SDF generation [G].
*   **When not to use:** When preserving the original scale and position is critical for the application [G].

## Background
This method is commonly used in modern voxelization pipelines, particularly those leveraging hardware-accelerated ray tracing (Embree, OptiX) [S1, unofficial][S2, unofficial]. It bridges the gap between raw asset files and the mathematical requirements of analytic SDF computation [G].
