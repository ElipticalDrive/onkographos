# Signed Distance Field Voxelization

Also called: SDF Voxelization, Signed Distance Grid Generation

## Overview
Signed Distance Field (SDF) Voxelization converts continuous surface geometry (typically triangle meshes) into a discrete 3D grid where each voxel stores the signed Euclidean distance to the nearest surface point [S1][S2, unofficial][S4, unofficial]. It solves the problem of creating a continuous, topologically robust volumetric representation from explicit geometry, enabling smooth surface reconstruction, collision detection, and fluid simulation. It differs from [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) by computing exact geometric distances rather than projected coverage, and from [Point Cloud Voxelization](1000-point-cloud-voxelization.md) by operating on explicit mesh topology rather than sampled points.

## Shared principles
All methods in this family compute a scalar field $D(x)$ for every voxel center $x$ in a defined 3D grid. The core mechanism involves:
1.  **Grid Definition**: Defining a bounding box, resolution ($N_x \times N_y \times N_z$), and voxel size. The domain is often normalized to $[-1, 1]$ or $[0, 1]$ before mapping to world coordinates [S2, unofficial][S3, unofficial].
2.  **Distance Evaluation**: For each voxel center, calculating the shortest Euclidean distance to the input surface primitives (triangles). This requires a point-to-primitive distance routine [S2, unofficial].
3.  **Sign Determination**: Assigning a sign to the distance to distinguish interior from exterior. Common methods include ray-casting parity (odd intersections = inside) or winding numbers, which are robust for non-watertight meshes [S1][S2, unofficial].
4.  **Truncation and Bounds**: Many implementations truncate the distance field to a specific band (TSDF) or limit computation to a maximum distance to save memory and compute time [S1][S2].

## Subtopics

### [Signed Distance Field (SDF) Generation from Scanned Surfaces](854-signed-distance-field-sdf-generation-from-scanned-surfaces.md)
Converts a triangulated surface mesh into a 3D SDF texture. It differs from [Slice-based SDF Voxelization](1736-slice-based-sdf-voxelization.md) by evaluating distance directly from mesh geometry rather than 2D slices. Choose this for high-fidelity reconstruction from scanned data. Requires mesh hole-closing for correct interior distances.

### [SDF-based Binary Voxelization](2402-sdf-based-binary-voxelization.md)
Converts a continuous SDF into a discrete binary volume (occupied/unoccupied). It differs from [Dense Volume SDF Generation](4499-dense-volume-sdf-generation.md) by discarding distance values for hard classification. Choose this for memory-efficient occupancy grids or boolean operations. Voxels with $d < 0$ are inside.

### [MeshIntegrator Integration](3630-meshintegrator-integration.md)
Computes a Truncated Signed Distance Function (TSDF) volume by writing distance and weight values into a `VoxelBlockGrid`. It differs from unbounded SDF generation by operating within a fixed truncation band and overwriting voxel values. Choose this for GPU-accelerated integration where memory is constrained by `depth_trunc`.

### [Dense Volume SDF Generation](4499-dense-volume-sdf-generation.md)
Computes a scalar field $D(x)$ for every voxel in a dense 3D grid. It differs from sparse methods by storing data for every voxel, providing full access for simulation or marching cubes. Choose this when memory is not a bottleneck and full volumetric data is required. Builds on [Signed Distance Field Voxelization](3849-signed-distance-field-voxelization.md) by managing dense grid layout and sign detection.

### [Level Set Water Representation](4635-level-set-water-representation.md)
Tracks the liquid-air interface by storing signed distances to the water surface. It differs from binary voxelization by storing continuous distances, allowing for smoother surface reconstruction and accurate normal estimation. Choose this for fluid simulations requiring topological flexibility.

### Function Volume SDF
A method that stores no data in memory, returning a function object that computes distance on each query, trading computational power for memory savings [S1].
- Load mesh and calculate `oneDimVoxelSize` using `mm.suggestVoxelSize(mesh, 1e7)` [S1].
- Calculate `origin` and `dimensions` using `mm.calcOriginAndDimensions(mesh.computeBoundingBox(), oneDimVoxelSize)` [S1].
- Set `dist.signMode` to `mm.SignDetectionMode.HoleWindingRule` [S1].
- If CUDA is available, create `FastWindingNumber` mesh and assign to `params.fwn` [S1].
- Call `mm.meshToDistanceFunctionVolume(mesh, params)` to generate `functionVolume` [S1].
- Call `mm.marchingCubes(functionVolume, mcParams)` to extract `offMesh` [S1].
- `voxelSize`: Vector3f diagonal size, calculated via `mm.suggestVoxelSize(mesh, 1e7)` [S1].
- `origin`: Vector3f defining the grid origin, calculated via `mm.calcOriginAndDimensions` [S1].
- `dimensions`: Vector3i defining the grid dimensions, calculated via `mm.calcOriginAndDimensions` [S1].
- `maxDistSq`: float squared maximum distance to calculate. Set to `(3 * oneDimVoxelSize)^2` [S1].
- `nullOutsideMinMax`: boolean. If True, do not calculate values too far [S1].
- `signMode`: enum for sign detection. `mm.SignDetectionMode.HoleWindingRule` is robust [S1].
- `fwn`: Optional FastWindingNumber object (GPU/CUDA) for accelerated sign calculation [S1].

## Background
The concept of Signed Distance Fields was introduced by Jos Stam in 1998 for fluid simulation [S1]. The specific library `meshlib` (MRMesh) provides efficient C++ and Python implementations for converting meshes to SDFs, supporting features like winding number sign detection and CUDA acceleration [S1]. SDF voxelization is widely used in computer graphics for implicit modeling, collision detection, and as input for marching cubes algorithms to extract surfaces [S1].
