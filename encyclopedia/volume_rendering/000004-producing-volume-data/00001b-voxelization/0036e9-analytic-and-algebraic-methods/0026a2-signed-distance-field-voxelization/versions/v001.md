# Signed Distance Field Voxelization

Also called: SDF Voxelization, Signed Distance Field Generation

## Overview
Signed Distance Field (SDF) Voxelization converts continuous geometric primitives (meshes, point clouds) into a 3D grid where each voxel stores the signed Euclidean distance to the nearest surface. It solves the problem of creating smooth, resolution-independent implicit representations suitable for rendering, simulation, and constructive solid geometry. It differs from [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) and [Interior Voxelize](995-interior-voxelize.md) by providing exact analytical distance values rather than binary occupancy or rasterized projections, allowing for sub-voxel precision and smooth surface reconstruction.

## Shared principles
All methods in this family compute a scalar field $D(x)$ for every voxel center $x$ in a 3D grid. The value $D(x)$ represents the shortest Euclidean distance from $x$ to the input geometry. The sign of $D(x)$ indicates the topological relationship: typically negative for interior points and positive for exterior points (or vice versa, depending on convention).

The core computation for a point $p$ and a triangle $T$ with vertices $a, b, c$ involves finding the closest point on the triangle surface. The distance $d(p, T)$ is calculated using standard point-to-triangle distance routines [S2, unofficial][S4, unofficial]. For a grid of resolution $N \times N \times N$, the algorithm iterates over all voxels and all primitives (or uses spatial acceleration structures) to find the minimum distance:
$$ D(x) = \min_{T \in \text{Mesh}} d(x, T) $$

Sign determination is critical. Common methods include:
1.  **Ray Casting Parity:** Cast a ray from $x$ to infinity; odd intersections imply inside (negative), even imply outside (positive) [S1][S3, unofficial].
2.  **Normal Alignment:** Use the normal of the closest triangle; if the vector from the closest point to $x$ opposes the normal, the point is inside [S4, unofficial].
3.  **Winding Number:** Use a robust winding number calculation, which is continuous and handles non-watertight meshes better than parity tests [S1].

## Subtopics

### [Signed Distance Field (SDF) Generation from Scanned Surfaces](854-signed-distance-field-sdf-generation-from-scanned-surfaces.md)
Converts a triangulated surface mesh into a 3D SDF texture. It differs from [Slice-based SDF Voxelization](1736-slice-based-sdf-voxelization.md) by evaluating distances directly from explicit mesh geometry via raycasting or spatial acceleration, avoiding rasterization artifacts. Choose this when exact analytical distances from a scanned mesh are required.

### [SDF-based Binary Voxelization](2402-sdf-based-binary-voxelization.md)
Discretizes an existing SDF into a binary volume (occupied/unoccupied). It differs from [Dense Volume SDF Generation](4499-dense-volume-sdf-generation.md) by discarding continuous distance values for hard classification. Choose this when a binary occupancy grid is needed for collision detection or boolean operations.

### [MeshIntegrator Integration](3630-meshintegrator-integration.md)
Writes a triangle mesh's truncated distance field into a `VoxelBlockGrid`. It differs from standard SDF generation by overwriting voxels within a truncation band with clamped distances and weights, leaving other blocks untouched. Choose this for integrating mesh data into existing voxel-based rendering pipelines that support truncation.

### [Dense Volume SDF Generation](4499-dense-volume-sdf-generation.md)
Builds a dense 3D grid of signed distance values. It differs from sparse methods by storing data for every voxel in the domain. Choose this for full data access, simulation, or marching cubes where memory is not a constraint.

### [Level Set Water Representation](4635-level-set-water-representation.md)
Uses the level set method to represent liquid surfaces as an SDF. It differs from static mesh SDFs by supporting dynamic surface evolution. Choose this for fluid simulation where the surface topology changes over time.

#### Function Volume SDF
**Definition**
A method that stores no data in memory, returning a function object that computes distance on each query, trading computational power for memory savings [S1].

**Steps**
1.  Load mesh and calculate `oneDimVoxelSize` using `mm.suggestVoxelSize(mesh, 1e7)` [S1].
2.  Calculate origin and dimensions using `mm.calcOriginAndDimensions(mesh.computeBoundingBox(), oneDimVoxelSize)` [S1].
3.  Set `dist.signMode` to `mm.SignDetectionMode.HoleWindingRule` [S1].
4.  If CUDA is available, create `FastWindingNumber` mesh and assign to `params.fwn` [S1].
5.  Call `mm.meshToDistanceFunctionVolume(mesh, params)` to generate `functionVolume` [S1].
6.  Call `mm.marchingCubes(functionVolume, mcParams)` to extract `offMesh` [S1].

**Parameters**
*   `voxelSize`: Vector3f diagonal size. Calculated via `mm.suggestVoxelSize(mesh, 1e7)` [S1].
*   `origin`: Vector3f defining the grid origin, calculated via `mm.calcOriginAndDimensions` [S1].
*   `dimensions`: Vector3i defining the grid dimensions, calculated via `mm.calcOriginAndDimensions` [S1].
*   `maxDistSq`: float squared maximum distance to calculate. Set to $(3 \times \text{oneDimVoxelSize})^2$ [S1].
*   `nullOutsideMinMax`: boolean. If True, do not calculate values too far [S1].
*   `signMode`: enum for sign detection. `mm.SignDetectionMode.HoleWindingRule` is robust [S1].
*   `fwn`: Optional `FastWindingNumber` object (GPU/CUDA) for accelerated sign calculation [S1].

## Background
The concept of Signed Distance Fields originates from computational geometry and computer graphics, popularized for rendering and collision detection in the late 1990s and early 2000s. The specific implementation details for generating SDFs from scanned meshes using libraries like MeshLib (mrmeshpy) were documented in the mid-2020s [S1]. The use of SDFs for voxelization allows for high-quality surface reconstruction and is widely used in 3D scanning, medical imaging, and real-time rendering pipelines.
