# MeshIntegrator Integration

Also called: Mesh Voxelization via Truncated Distance Field, TSDF Voxelization

## Overview
MeshIntegrator Integration writes a triangle mesh's truncated signed distance field (TSDF) into a `VoxelBlockGrid`'s `tsdf` and `weight` attributes [S1, unofficial]. It solves the problem of efficiently rasterizing arbitrary triangle meshes into a volumetric distance representation suitable for downstream fusion or rendering [G]. It differs from its siblings by performing a GPU-accelerated, block-based binning and integration pass that overwrites voxel values within the truncation band, rather than computing a global SDF from scratch or fusing multi-view observations directly [S1, unofficial][S2, unofficial]. It builds on [Signed Distance Field Voxelization](3849-signed-distance-field-voxelization.md) by providing the specific integration mechanism for mesh inputs [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle mesh (vertices and indices) and a target `VoxelBlockGrid` structure.
*   **Output:** The `tsdf` and `weight` attributes of the `VoxelBlockGrid` are updated. Voxels within the mesh's truncation band are overwritten; voxels outside the band in affected blocks are reset to zero [S1, unofficial].

**Data Structures:**
*   **VoxelBlockGrid:** Contains `tsdf` (signed distance values) and `weight` (integration confidence/weight) attributes.
*   **Scratch Memory:** ~16 bytes per grid block slot, plus storage for the largest mesh's inputs and bins. Counts, prefix sums, fill cursors, and occupied bins remain on the device [S1, unofficial].

**Parameters:**
*   `trunc_dist`: The truncation distance. Voxels within this distance of the surface are updated [S1, unofficial].
*   `kMaxBinTriangles`: Maximum triangles one block's bin may hold. Value: $2^{16}$ (65,536) [S1, unofficial].
*   `kMaxVoxelsPerBlock`: Maximum voxels a block may hold. Value: $2^{12}$ (4,096) [S1, unofficial].
*   `kMaxDispatchBinEntries`: Maximum bin entries one integrate dispatch measures. Value: $2^{20}$ (1,048,576) [S1, unofficial].

**Algorithm Steps:**
1.  **Clear Grid (Optional but Recommended):** If converting a single mesh to a standalone grid, clear the grid first. Otherwise, blocks outside the truncation band retain previous values [S1, unofficial].
2.  **Bin Count Pass:** Dispatch a kernel to count how many triangles fall into the truncation band of each grid block. This populates a bin count array. Each dispatch runs one work item per (triangle, candidate block) pair [S1, unofficial].
3.  **Prefix Sum:** Compute a prefix sum over the bin counts to determine the starting offset for each block's bin in the scratch memory [G].
4.  **Bin Fill Pass:** Dispatch a kernel to fill the bins. Each work item processes one (triangle, candidate block) pair. If a triangle's bounding box intersects the block's truncation band, the triangle index is added to the block's bin [S1, unofficial].
5.  **Sort Bins:** For each block, sort its bin entries by distance to the block center (nearest first) [S1, unofficial].
6.  **Integrate Dispatch:** For each block, launch a workgroup to write its voxels. If the number of bin entries exceeds `kMaxDispatchBinEntries`, split the work into multiple submissions [S1, unofficial]. Each voxel in the block iterates through the sorted triangles. It computes the distance to the triangle. It stops processing further triangles if they are strictly farther than the current best distance or `trunc_dist`. The minimum distance is recorded. Triangle index is used as a tie-breaker. If the minimum distance $d$ satisfies $|d| \le \text{trunc\_dist}$: $tsdf = \text{clamp}(d, -\text{trunc\_dist}, \text{trunc\_dist})$ and $weight = 1$. Else (voxel is outside the band but inside the block): $tsdf = 0$ and $weight = 0$ [S1, unofficial].
7.  **Validation:** Only validation totals and bounded dispatch ranges are read back from the device [S1, unofficial].

**Pseudocode:**

def mesh_integrator_integration(mesh, grid, trunc_dist):
    # 1. Clear Grid (Optional but Recommended)
    # If converting a single mesh to a standalone grid, clear the grid first.
    # Otherwise, blocks outside the truncation band retain previous values [S1, unofficial].

    # 2. Bin Count Pass
    # Dispatch a kernel to count how many triangles fall into the truncation band of each grid block.
    # Each dispatch runs one work item per (triangle, candidate block) pair [S1, unofficial].
    bin_counts = [0] * grid.num_blocks
    for tri_idx in range(mesh.num_triangles):
        tri = mesh.triangles[tri_idx]
        for block_id in range(grid.num_blocks):
            if triangle_intersects_block_band(tri, grid.blocks[block_id], trunc_dist):
                bin_counts[block_id] += 1

    # 3. Prefix Sum
    # Compute a prefix sum over the bin counts to determine the starting offset for each block's bin in the scratch memory [G].
    bin_offsets = [0] * (grid.num_blocks + 1)
    current = 0
    for i in range(grid.num_blocks):
        current += bin_counts[i]
        bin_offsets[i] = current
    bin_offsets[grid.num_blocks] = current

    # 4. Bin Fill Pass
    # Dispatch a kernel to fill the bins. Each work item processes one (triangle, candidate block) pair [S1, unofficial].
    bins = [[] for _ in range(grid.num_blocks)]
    for tri_idx in range(mesh.num_triangles):
        tri = mesh.triangles[tri_idx]
        for block_id in range(grid.num_blocks):
            if triangle_intersects_block_band(tri, grid.blocks[block_id], trunc_dist):
                bins[block_id].append(tri_idx)

    # 5. Sort Bins
    # For each block, sort its bin entries by distance to the block center (nearest first) [S1, unofficial].
    for block_id in range(grid.num_blocks):
        if len(bins[block_id]) > 1:
            bins[block_id].sort(key=lambda t_idx: triangle_distance_to_block_center(t_idx, grid.blocks[block_id]))

    # 6. Integrate Dispatch
    # For each block, launch a workgroup to write its voxels [S1, unofficial].
    kMaxDispatchBinEntries = 1 << 20
    for block_id in range(grid.num_blocks):
        block_bins = bins[block_id]
        num_triangles = len(block_bins)

        # The write is split into multiple submissions if the block exceeds kMaxDispatchBinEntries bin entries [S1, unofficial].
        if num_triangles > kMaxDispatchBinEntries:
            integrate_block_split(block_bins, num_triangles, grid, block_id, trunc_dist)
        else:
            integrate_block(block_bins, num_triangles, grid, block_id, trunc_dist)

    # 7. Validation
    # Only validation totals and bounded dispatch ranges are read back from the device [S1, unofficial].

def integrate_block(bin_entries, num_triangles, grid, block_id, trunc_dist):
    voxels = grid.get_voxels(block_id)
    for voxel in voxels:
        best_dist = float('inf')
        best_triangle_idx = -1

        for i in range(num_triangles):
            tri_idx = bin_entries[i]
            tri = mesh.triangles[tri_idx]

            # Compute distance from voxel to triangle
            dist = compute_point_triangle_distance(voxel.center, tri)

            # A triangle is ruled out only if strictly farther than the voxel's best so far or trunc_dist [S1, unofficial].
            if dist > best_dist or dist > trunc_dist:
                continue

            best_dist = dist
            best_triangle_idx = tri_idx

        # The minimum distance is taken with triangle index as tie-break [S1, unofficial].
        if best_dist <= trunc_dist:
            grid.tsdf[voxel] = max(-trunc_dist, min(trunc_dist, best_dist))
            grid.weight[voxel] = 1
        else:
            grid.tsdf[voxel] = 0
            grid.weight[voxel] = 0

**Edge Cases and Pitfalls:**
*   **Bin Overflow:** If a bin exceeds `kMaxBinTriangles` (65,536), the mesh is refused rather than measured. This occurs when the mesh is far finer than the voxel size. Decimate the mesh toward voxel size first [S1, unofficial].
*   **Grid State:** The grid must be quiescent across the call. The binning kernel probes the hash table without a lock [S1, unofficial].
*   **Overwriting:** Voxels within the truncation band are overwritten, not blended. To fuse multiple meshes, additional blending logic is required outside this method [S1, unofficial].

## Subtopics

### [TSDF Fusion Mesh Extraction](6831-tsdf-fusion-mesh-extraction.md)
TSDF Fusion Mesh Extraction reconstructs a 3D triangle mesh by integrating multi-view depth and color observations into a Truncated Signed Distance Function (TSDF) volume and extracting the surface via marching cubes. It converts per-surfel depth outputs into a unified 3D mesh by computing a robust depth value per pixel and fusing the resulting depth maps via TSDF. It differs from direct neural rendering mesh extraction by relying on explicit geometric fusion rather than differentiable surface optimization. It builds on [MeshIntegrator Integration](3630-meshintegrator-integration.md), which writes the raw distance field data, by consuming that data to produce a final watertight mesh.

### TSDF Volume Representation
TSDF can be initialized from an axis-aligned bounding box (aabb) and volume dimensions (volume_dims) using the static method `from_aabb` [S2, unofficial]. The truncation distance is calculated as `voxel_size[0] * truncation_margin` [S2, unofficial]. The TSDF dataclass fields are: `voxel_coords` (TensorType[3, "xdim", "ydim", "zdim"]), `values` (TensorType["xdim", "ydim", "zdim"]), `weights` (TensorType["xdim", "ydim", "zdim"]), `colors` (TensorType["xdim", "ydim", "zdim", 3]), `voxel_size` (TensorType[3]), `origin` (TensorType[3]), and `truncation_margin` (float, default 5.0) [S2, unofficial].

### Mesh Voxelization into SDFs
Computes the signed distance function (SDF) for a volume grid by determining the distance of each voxel (either its corner or center) to the nearest mesh face. The sign is negative for interior voxels and positive for exterior voxels [S3, unofficial]. The raw watertight triangular mesh is scaled to lie in the range $[0, H] \times [0, W] \times [0, D]$, corresponding to the chosen resolution $H \times D \times W$ [S3, unofficial]. For each voxel, the distance to the nearest mesh face is calculated using triangle-point distance implementation. If the `--center` flag is set, voxel centers are used; otherwise, corners are used (default) [S3, unofficial]. If the original mesh is not watertight (has significant holes) or contains internal structures preventing SDF computation, the SDF might not have negative values, causing marching cubes to fail with 'Surface level must be within volume data range.' [S3, unofficial]. Using voxel centers for SDF computation influences the marching cubes implementation; standard PyMCubes uses corners, so a fork with center support is required for center-based SDFs [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the binning and integration passes. The binning pass is $O(N \cdot B)$ where $N$ is the number of triangles and $B$ is the number of blocks, but optimized via spatial hashing. The integration pass is $O(V \cdot T_{avg})$ where $V$ is the number of voxels in the truncation band and $T_{avg}$ is the average number of triangles per voxel. Sorting bins adds $O(T \log T)$ per block [G].
*   **Memory Complexity:** $O(B + N)$ for scratch memory and bins, where $B$ is the number of blocks and $N$ is the number of triangles. Scratch memory is ~16 bytes per block slot [S1, unofficial].
*   **Performance:** Efficient for large meshes and grids due to GPU acceleration and block-based processing. Performance degrades if bins overflow `kMaxBinTriangles` [S1, unofficial].
*   **Strengths:** Fast, GPU-accelerated, handles arbitrary triangle meshes, supports truncation for memory efficiency.
*   **Limitations:** Overwrites values (no blending), requires quiescent grid, sensitive to mesh density relative to voxel size.
*   **When to Use:** When you need to convert a mesh to a TSDF volume for fusion or rendering, and performance is critical.
*   **When Not to Use:** When you need to blend multiple meshes into a single TSDF without overwriting, or when the mesh is extremely dense relative to the voxel size (decimate first).

## Background
The method is part of the `volumetric_kit` library, specifically the `vgrid` module, which focuses on efficient voxel grid operations [S1, unofficial]. The underlying triangle-point distance implementation is derived from `christopherbatty/SDFGen`, and triangle-ray intersection from Tomas Akenine-Möller [S3, unofficial]. The approach is widely used in 3D reconstruction pipelines, particularly in systems like SDFStudio, which utilize TSDF fusion for multi-view integration [S2, unofficial].
