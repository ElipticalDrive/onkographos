# GPU TSDF Fusion with Voxel Hashing

Also called: fusion: 'tsdf'

## Overview
This method performs Truncated Signed Distance Function (TSDF) fusion using voxel hashing for sparse memory allocation, free-space carving to remove artifacts, and multi-resolution voxel levels based on distance from the camera [S1, unofficial]. It is implemented as the `tsdf` option for `reconstructDenseGpu` in the typeshade/typecv library [S1, unofficial]. It is significantly faster than pixel fusion but yields lower reconstruction accuracy [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Depth and color maps (or pre-filtered confidence maps), camera poses, and a device budget (memory limit).
*   **Outputs:** A fused 3D point cloud or mesh extracted from the TSDF volume [S1, unofficial].

**Data Structures:**
*   **Voxel Blocks:** Voxels are grouped into blocks of $8 \times 8 \times 8$ [S1, unofficial].
*   **Hash Table:** Blocks are stored in an open-addressing hash table [S1, unofficial].
*   **Multi-resolution Levels:** The hash table supports 4 levels ($L=0,1,2,3$). The voxel size $v_L$ at level $L$ is defined as:
    $$ v_L = v_0 \cdot 2^L $$
    where $v_0$ is the base voxel scale [S1, unofficial].
*   **Chunks:** The hash table is organized into chunks. Each chunk must hold a minimum number of elements defined by `TSDF_OCCUPANCY_FLOOR` [S1, unofficial].

**Parameters:**
*   **Voxel Scale ($v_0$):** Default is 2 [S1, unofficial].
*   **Truncation:** Default is 3 [S1, unofficial].
*   **TSDF_OCCUPANCY_FLOOR:** 16,384 elements [S1, unofficial].
*   **GPU_CEILING_MS:** Threshold for hardware adapters to lower the occupancy floor if dispatches exceed this time [S1, unofficial].

**Algorithm Steps:**

1.  **Planning (Host Side):**
    The host function `fuseTsdfGpu` performs a dry run to count the required blocks. It then cuts the volume into boxes that fit the device budget. Each box includes a margin of one block [S1, unofficial].

2.  **Allocation (`tsdfAllocate`):**
    GPU kernel allocates hash table entries for the required blocks within the current box and margin [S1, unofficial].

3.  **Assignment (`tsdfAssign`):**
    GPU kernel assigns depth samples to the corresponding voxel blocks based on camera projection [S1, unofficial].

4.  **Integration (`tsdfIntegrate`):**
    GPU kernel integrates depth samples into the TSDF values.
    *   Uses integer `atomicAdd` operations for sums to ensure the result is independent of the invocation order [S1, unofficial].
    *   Integration weight is the confidence value from the input maps (see [TSDF Fusion Mesh Extraction](6831-tsdf-fusion-mesh-extraction.md)) [S1, unofficial].

5.  **Carving (`tsdfCarve`):**
    GPU kernel removes free-space artifacts.
    *   For each ray, the kernel walks only the part of the ray inside the current pass's box and its margin, rather than the whole ray, to optimize performance for cut volumes [S1, unofficial].
    *   This step accounts for 62% of the kernel time [S1, unofficial].

6.  **Extraction (`tsdfExtract`):**
    GPU kernel extracts the mesh or points.
    *   The extraction step reads its own voxel before any lookup to handle boundary conditions or self-references correctly [S1, unofficial].

**Pseudocode:**

```python
# Pseudocode for the host-side planning and dispatch logic
def fuse_tsdf_gpu(depth_maps, poses, budget):
    # 1. Dry run to count blocks
    required_blocks = count_required_blocks(depth_maps, poses)
    
    # 2. Cut volume into boxes fitting the budget
    # Each box has a margin of one block (8x8x8 voxels)
    boxes = cut_volume_into_boxes(required_blocks, budget, margin_blocks=1)
    
    # 3. Dispatch kernels for each box
    for box in boxes:
        # Allocate hash table entries for this box
        tsdf_allocate(box, hash_table)
        
        # Assign depth samples to blocks
        tsdf_assign(depth_maps, poses, box, hash_table)
        
        # Integrate TSDF values using atomic adds
        tsdf_integrate(hash_table, confidence_maps)
        
        # Carve free space within box and margin
        tsdf_carve(poses, box, hash_table)
        
        # Extract mesh/points
        extract_mesh(hash_table, box)

# Pseudocode for the carving optimization
def tsdf_carve(poses, box, hash_table):
    for each ray in poses:
        # Calculate intersection of ray with box and its margin
        ray_start, ray_end = get_ray_segment_in_box_margin(ray, box)
        
        # Walk only this segment, not the whole ray
        for t from ray_start to ray_end:
            voxel = get_voxel_at(ray, t, hash_table)
            if voxel is free_space:
                set_voxel_to_free(voxel)

# Pseudocode for extraction boundary handling
def tsdf_extract(hash_table, box):
    for each voxel in box:
        # Read own voxel first to handle self-references
        current_value = read_voxel(voxel)
        
        # Perform lookup for neighbors
        neighbors = get_neighbors(voxel, hash_table)
        
        # Extract surface based on current_value and neighbors
        extract_surface(voxel, current_value, neighbors)
```

**Edge Cases and Pitfalls:**
*   **Occupancy Floor:** Without the `TSDF_OCCUPANCY_FLOOR` (16,384 elements), performance degrades significantly due to excessive kernel dispatches [S1, unofficial]. On the ETH3D pipes dataset, fusion took 226 seconds with 26,215 dispatches without the floor, compared to 20.1 seconds with 342 dispatches with the floor [S1, unofficial].
*   **Hardware Adapters:** Hardware adapters may lower the occupancy floor after a dispatch exceeds `GPU_CEILING_MS` [S1, unofficial]. Software adapters honor no occupancy floor [S1, unofficial].
*   **Accuracy Gap:** TSDF fusion has lower accuracy than pixel fusion (69.0% at 2cm vs 83.3% at 2cm on ETH3D pipes) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Significantly faster than pixel fusion. On the ETH3D pipes dataset (14 views, scale 8), TSDF fusion took 20.5 seconds with 343 dispatches, while pixel fusion took 97–118 seconds with ~16,000 dispatches [S1, unofficial].
*   **Memory Complexity:** Sparse due to voxel hashing. Peak device bytes were 136.8 MB at a 256 MiB budget, and 59.4 MB at a quarter of the blocks per pass [S1, unofficial].
*   **Scaling:** The method scales with the device budget by cutting the volume into boxes. The budget changes speed, not the final point cloud [S1, unofficial].
*   **Strengths:** High speed, sparse memory usage, robust handling of large volumes via chunking and hashing.
*   **Limitations:** Lower accuracy compared to pixel fusion. Accuracy gap candidates include `minWeight` counting views and step 4 (10.5) [S1, unofficial].
*   **When to Use:** When speed is critical and moderate accuracy is acceptable. Default fusion method in the lab [S1, unofficial].
*   **When Not to Use:** When high accuracy is required (use pixel fusion instead via `?denseFusion=pixel`) [S1, unofficial].
