# TSDF Fusion Mesh Extraction

Also called: Bounded TSDF Mesh Extraction, Direct extraction, Progressive extraction, ScalableTSDFVolume Mesh Extraction, Sparse Voxel Mesh Extraction, TSDF Volume Integration

## Overview
TSDF Fusion Mesh Extraction reconstructs a 3D triangle mesh from multi-view depth and color observations by integrating them into a Truncated Signed Distance Function (TSDF) volume and extracting the surface via marching cubes [S1, unofficial][S2, unofficial]. It solves the problem of noisy or incomplete depth data by fusing multiple views into a unified volumetric representation, where the surface is defined as the zero-level set of the TSDF [S2, unofficial]. It differs from direct neural rendering mesh extraction by relying on explicit geometric fusion rather than differentiable surface optimization [S1, unofficial]. This method builds on [MeshIntegrator Integration](3630-meshintegrator-integration.md), which writes the raw distance field data into the volume structure.

## How it works
**Inputs:**
- RGB images and corresponding depth maps from multiple camera viewpoints.
- Camera intrinsics (focal length, principal point, distortion) and extrinsics (rotation, translation) for each viewpoint.
- Volume parameters: `voxel_size`, `sdf_trunc`, `depth_trunc`, `max_depth`, `max_weight`.
- Optional: Alpha masks for background removal.

**Outputs:**
- A triangle mesh (vertices and faces) representing the reconstructed surface.
- Optional: Vertex colors derived from the integrated color data.

**Data Structures:**
The method uses a scalable TSDF volume, typically implemented as a hash map of voxel blocks (e.g., Open3D's `ScalableTSDFVolume`).
- **Voxel Block:** A 3D grid of voxels. Each voxel stores:
  - `tsdf`: Normalized signed distance value (float).
  - `weight`: Integration weight (float).
  - `color`: RGB color value (uint8 or float).
- **Hash Map:** Maps 3D block coordinates to block indices, allowing sparse storage of the volume.

**Parameters:**
- `voxel_size`: Resolution of the TSDF volume. Default: 0.004 meters [S2, S4, unofficial].
- `sdf_trunc`: Truncation distance for the SDF, defining the surface neighborhood. Default: 0.02 meters [S2, S4, unofficial]. Often set to $5.0 \times \text{voxel\_size}$ [S2, unofficial].
- `depth_trunc`: Maximum depth range for integration. Default: 3.0 meters [S2, S4, unofficial].
- `max_depth`: Maximum depth considered valid for integration.
- `max_weight`: Maximum allowable weight value to saturate weights during fusion.
- `depth_scale`: Scalar factor to convert raw depth sensor units to world units (meters). Default: 1.0 [S2, S4, unofficial].
- `alpha_thres`: Alpha threshold for background masking. Default: 0.5 [S3, unofficial].

**Steps:**

1. **Volume Initialization:**
   Initialize the scalable TSDF volume with `voxel_size`, `sdf_trunc`, and `color_type` (e.g., RGB8) [S2, S4, unofficial].

2. **Viewpoint Processing:**
   For each camera viewpoint in the stack:
   a. **Preprocessing:**
      - If background masking is enabled and a ground truth alpha mask exists, set depth values to 0 where the alpha mask is less than `alpha_thres` (typically 0.5) [S2, S4, unofficial].
      - Convert the camera to the required format (e.g., Open3D camera) [S1, S4, unofficial].
   
   b. **Active Block Identification:**
      - Compute unique frustum block coordinates for the current depth frame using the volume's hashmap, intrinsic, extrinsic, depth scale, and `max_depth` [S1, unofficial].
      - Activate the identified blocks in the volume hashmap and retrieve buffer indices and volume masks for those blocks [S1, unofficial].
   
   c. **Voxel Projection:**
      - Retrieve voxel coordinates and flattened indices for the active blocks [S1, unofficial].
      - Transform voxel coordinates from local block space to world space using the extrinsic matrix (converted to float64) [S1, unofficial].
      - Project world-space voxel centers to 2D image coordinates $(u, v)$ and depth $d$ using the intrinsic matrix [S1, unofficial].
   
   d. **Masking:**
      - Create a projection mask for voxels that are in front of the camera ($d > 0$) and within the image bounds ($0 \le u < W, 0 \le v < H$) [S1, unofficial].
      - Create an inlier mask for voxels where the depth reading is valid ($> 0$ and $< \text{max\_depth}$) and the computed SDF is within the truncation distance ($\ge -\text{sdf\_trunc}$) [S1, unofficial].
      - Identify valid voxel indices that satisfy both projection and inlier masks [S1, unofficial].
   
   e. **TSDF and Color Integration:**
      - Retrieve the depth reading from the input depth map at the projected pixel coordinates and convert to world units using `depth_scale` [S1, unofficial].
      - Calculate the Signed Distance Field (SDF) value for each voxel as the difference between the observed depth reading and the projected voxel depth [S1, unofficial].
      - Saturate SDF values at the truncation limit and normalize the SDF by dividing by `sdf_trunc` [S1, unofficial].
      - Retrieve the current weight and TSDF attributes from the volume, reshaped to match the voxel index structure [S1, unofficial].
      - Retrieve the weight readings from the input depth weights map at projected coordinates [S1, unofficial].
      - Update the TSDF value using a weighted average of the existing TSDF and the new normalized SDF, weighted by their respective weights [S1, unofficial].
      - Retrieve color readings from the input color image at projected coordinates [S1, unofficial].
      - Update the volume color attribute using a weighted average of the existing color and the new color reading [S1, unofficial].
      - Update the volume weight attribute with the computed new weights [S1, unofficial].

3. **Mesh Extraction:**
   - Extract the triangle mesh from the volume using marching cubes [S2, S4, unofficial].
   - If progressive mode is enabled, call `extract_mesh_progressive` with `init_lv` and `final_lv` [S3, unofficial].
   - If progressive mode is disabled, call `extract_mesh` with `final_lv` [S3, unofficial].

**Pseudocode:**

```python
import numpy as np
import open3d as o3d

def tsdf_fusion_mesh_extraction(cameras, depth_maps, color_images, args):
    """
    Extract mesh from TSDF volume integrated from multi-view depth/color data.
    
    Args:
        cameras: List of camera objects with intrinsic, extrinsic, and image data.
        depth_maps: List of depth maps corresponding to cameras.
        color_images: List of RGB images corresponding to cameras.
        args: Configuration object with voxel_size, sdf_trunc, depth_trunc, etc.
    
    Returns:
        mesh: Open3D TriangleMesh object.
    """
    # 1. Initialize Volume
    voxel_size = args.voxel_size if args.voxel_size > 0 else 0.004
    sdf_trunc = args.sdf_trunc if args.sdf_trunc > 0 else 5.0 * voxel_size
    depth_trunc = args.depth_trunc if args.depth_trunc > 0 else 3.0
    
    volume = o3d.pipelines.integration.ScalableTSDFVolume(
        voxel_length=voxel_size,
        sdf_trunc=sdf_trunc,
        color_type=o3d.pipelines.integration.TSDFVolumeColorType.RGB8
    )
    
    # 2. Process Each Viewpoint
    for i, cam in enumerate(cameras):
        depth = depth_maps[i]
        color = color_images[i]
        
        # Preprocessing: Background Masking
        if args.mask_background and cam.gt_alpha_mask is not None:
            # Set depth to 0 where alpha < 0.5
            depth[cam.gt_alpha_mask < 0.5] = 0
            
        # Convert to Open3D RGBD Image
        # Clip RGB to [0,1], multiply by 255, cast to uint8
        color_uint8 = np.clip(color, 0, 1) * 255
        color_uint8 = color_uint8.astype(np.uint8)
        
        rgbd = o3d.geometry.RGBDImage.create_from_color_and_depth(
            o3d.geometry.Image(color_uint8),
            o3d.geometry.Image(depth.astype(np.float32)),
            depth_scale=1.0,
            depth_trunc=depth_trunc,
            convert_rgb_to_intensity=False
        )
        
        # Convert Camera to Open3D Format
        cam_o3d = to_cam_open3d(cam)
        
        # Integrate into Volume
        volume.integrate(rgbd, intrinsic=cam_o3d.intrinsic, extrinsic=cam_o3d.extrinsic)
        
    # 3. Extract Mesh
    if args.progressive:
        mesh = extract_mesh_progressive(args, None, None, args.init_lv, args.final_lv, None)
    else:
        mesh = volume.extract_triangle_mesh()
        
    return mesh

def to_cam_open3d(cam):
    """
    Convert custom camera object to Open3D CameraIntrinsic and Extrinsics.
    [G] Implementation details depend on the specific camera class structure.
    """
    # Assuming cam has intrinsic matrix K and extrinsic matrix T (4x4)
    intrinsic = o3d.camera.PinholeCameraIntrinsic()
    intrinsic.set_intrinsics(cam.width, cam.height, cam.fx, cam.fy, cam.cx, cam.cy)
    
    extrinsic = o3d.geometry.PinholeCameraExtrinsic()
    extrinsic.extrinsic_matrix = cam.extrinsic_matrix
    
    return type('Open3DCam', (object,), {'intrinsic': intrinsic, 'extrinsic': extrinsic})()
```

**Edge Cases and Pitfalls:**
- **Precision:** Extrinsics should be converted to float64 to avoid precision loss during voxel coordinate transformation [S1, unofficial].
- **Boundaries:** Voxels outside the `depth_trunc` range are ignored. Voxels with invalid depth readings (0 or > max_depth) are masked out [S1, unofficial].
- **Clamping:** In non-progressive mode, octree levels strictly greater than `outside_level + final_lv` are clamped, indicated by the suffix `>>> Level clamped <<<` [S3, unofficial].
- **Progressive Mode:** In progressive mode, the initial extraction level is marked with `>>> Init level <<<` when `lv == outside_level + args.init_lv` [S3, unofficial].

## Subtopics

### [TSDF Reconstruction from Depth Maps](9982-tsdf-reconstruction-from-depth-maps.md)
TSDF Reconstruction from Depth Maps is a method to reconstruct a 3D mesh from multi-view depth images by integrating them into a Truncated Signed Distance Function (TSDF) volume and extracting the surface via marching cubes. It converts per-surfel depth outputs into a unified 3D mesh by computing a robust depth value per pixel and fusing the resulting depth maps via TSDF. It differs from direct neural rendering mesh extraction by relying on explicit geometric fusion rather than differentiable surface optimization.

### [TSDF Volume Integration with Uncertainty Weighting](15425-tsdf-volume-integration-with-uncertainty-weighting.md)
TSDF Volume Integration with Uncertainty Weighting is a volumetric fusion method that integrates depth maps into a Truncated Signed Distance Function (TSDF) volume using per-pixel weights derived from depth uncertainty (inverse standard deviation). It solves the problem of noisy depth measurements in SLAM pipelines by down-weighting unreliable observations, distinguishing it from standard TSDF fusion which applies uniform weights. This method is specifically designed for integration with 2D Gaussian Splatting or NeRF-based depth outputs where uncertainty estimates are available.

### SDF and RGB Fusion (Fuser)
A variant that fuses SDF and RGB data using specific parameters.
- **Parameters:**
  - `xyz`: Input coordinates, set to `voxel_model.grid_pts_xyz` [S3, unofficial].
  - `bandwidth`: Set to 20 times the minimum voxel size: `voxel_model.vox_size.min().item() * 20` [S3, unofficial].
  - `use_trunc`: Boolean flag, set to True for truncation [S3, unofficial].
  - `fuse_tsdf`: Boolean flag, set to True to fuse Truncated SDF [S3, unofficial].
- **Pitfall:** Alternative bandwidth calculation is commented out, which would use the maximum voxel size repeated 8 times per voxel key, multiplied by 3 [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of voxels in the active frustum blocks and the number of viewpoints. Integration is $O(N \cdot V)$, where $N$ is the number of viewpoints and $V$ is the number of active voxels per view.
- **Memory Complexity:** Proportional to the number of active voxels in the TSDF volume. The scalable volume uses a hash map to store only occupied blocks, making it memory-efficient for sparse scenes.
- **Measured Performance:** Default voxel size of 0.004m and sdf_trunc of 0.02m provide a good balance between detail and noise robustness for indoor scenes [S2, S4, unofficial].
- **Scaling:** Scales well with the number of viewpoints due to the incremental integration process. Progressive extraction allows for early termination or lower-resolution extraction for faster feedback [S3, unofficial].
- **Strengths:** Robust to noise and outliers due to truncation and weighted averaging. Efficient memory usage via sparse voxel storage.
- **Limitations:** Requires accurate camera poses and depth maps. Performance degrades in textureless regions or areas with significant occlusion if not handled by multi-view fusion.
- **When to Use:** Suitable for reconstructing meshes from multi-view depth sensors (e.g., Kinect, RealSense) or depth outputs from neural rendering methods (e.g., 2D Gaussian Splatting) [S2, S4, unofficial].
- **When Not to Use:** Not suitable for single-view reconstruction or scenes with highly dynamic elements that cannot be aligned.

## Background
TSDF Fusion Mesh Extraction originates from the field of 3D reconstruction from multi-view stereo and depth sensors. The concept of Truncated Signed Distance Functions was popularized by Curless and Levoy for integrating range data [S1, unofficial]. The method is widely used in robotics (SLAM), computer vision, and increasingly in neural rendering pipelines (e.g., 2D Gaussian Splatting) to extract explicit meshes from implicit or point-based representations [S2, S4, unofficial]. Open3D's `ScalableTSDFVolume` provides an efficient implementation for large-scale scenes [S2, S4, unofficial].
