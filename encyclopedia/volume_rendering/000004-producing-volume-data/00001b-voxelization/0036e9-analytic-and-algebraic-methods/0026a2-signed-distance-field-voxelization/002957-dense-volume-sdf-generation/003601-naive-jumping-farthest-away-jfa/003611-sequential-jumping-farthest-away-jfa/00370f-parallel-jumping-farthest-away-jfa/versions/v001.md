# Parallel Jumping Farthest Away (JFA)

Also called: OpenMP JFA

## Overview
Parallel Jumping Farthest Away (JFA) is an OpenMP-based parallelization of the Sequential JFA algorithm for generating Signed Distance Fields (SDFs) in voxel grids. It accelerates the distance propagation phase by distributing the voxel iteration space across multiple CPU threads. Unlike its sequential parent, it employs a double-buffering strategy to prevent race conditions during concurrent updates.

## How it works
The method extends the sequential JFA approach [S1, unofficial] by parallelizing the outer loops of the initialization and processing phases. It relies on the same multi-scale search logic but executes it concurrently.

**Inputs and Outputs:**
- Input: A voxel grid containing initial SDF values (`sdf`) and surface positions (`positions`).
- Output: Updated `sdf` and `positions` buffers representing the computed distance field.

**Data Structures:**
- `sdf`: 3D array of floating-point values representing distances.
- `positions`: 3D array of vectors representing surface positions.
- `sdfApp`: Temporary buffer for SDF values, same dimensions as `sdf`.
- `positionsApp`: Temporary buffer for positions, same dimensions as `positions`.

**Parameters:**
- `k`: The number of iterations or scales for the JFA propagation.
- `voxelZ`, `voxelY`, `voxelX`: Dimensions of the voxel grid.

**Steps:**

1. **Initialization Parallelization:**
   The initial setup phase, which identifies boundary voxels and sets initial distances, is parallelized. The outer loop over `voxelZ` is distributed among threads using OpenMP. The inner loops over `voxelY` and `voxelX` remain sequential within each thread to maintain locality.
   ```cpp
   #pragma omp parallel for collapse(1) schedule(static)
   for (int voxelZ = 0; voxelZ < Z; ++voxelZ) {
       for (int voxelY = 0; voxelY < Y; ++voxelY) {
           for (int voxelX = 0; voxelX < X; ++voxelX) {
               // Initialization logic (e.g., checking if voxel is inside/outside)
               // This part is typically read-heavy or independent per voxel
           }
       }
   }
   ```

2. **Processing Parallelization:**
   The core JFA propagation loop iterates `k` times. The outer loop over `k` remains sequential to ensure ordered propagation of distance information. The inner triple loop over `voxelZ`, `voxelY`, and `voxelX` is parallelized.
   ```cpp
   for (int k = 0; k < numIterations; ++k) {
       #pragma omp parallel for collapse(3) schedule(static)
       for (int voxelZ = 0; voxelZ < Z; ++voxelZ) {
           for (int voxelY = 0; voxelY < Y; ++voxelY) {
               for (int voxelX = 0; voxelX < X; ++voxelX) {
                   // Compute new distance based on neighbors
                   // Write to sdfApp and positionsApp
               }
           }
       }
       // Swap buffers
       std::swap(sdf, sdfApp);
       std::swap(positions, positionsApp);
   }
   ```

**Formulas:**
The distance update for a voxel at $(x, y, z)$ at iteration $k$ is computed based on its neighbors. Let $d_{old}(x,y,z)$ be the distance from the previous iteration. The new distance $d_{new}(x,y,z)$ is typically:
$$ d_{new}(x,y,z) = \min_{(dx,dy,dz) \in \mathcal{N}} \left( d_{old}(x+dx, y+dy, z+dz) + \sqrt{dx^2 + dy^2 + dz^2} \right) $$
where $\mathcal{N}$ is the set of neighboring voxels (e.g., 26-neighborhood). The position is updated similarly by tracking the source of the minimum distance.

**Edge Cases and Pitfalls:**
- **Race Conditions:** Concurrent writes to the same memory location during the processing step can cause data corruption. To avoid this, the algorithm uses separate `sdfApp` and `positionsApp` buffers for writing while reading from the original `sdf` and `positions` buffers. These buffers are swapped at the end of each `k` iteration [S1, unofficial].
- **Thread Safety:** The `std::swap` operation must be thread-safe or performed outside the parallel region. In the described implementation, the swap occurs after the parallel region completes, ensuring no concurrent access.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(k \cdot N)$, where $N$ is the number of voxels and $k$ is the number of iterations. Parallelization reduces wall-clock time by a factor proportional to the number of threads, subject to overhead.
- **Memory Complexity:** $O(N)$ for the voxel grid, plus $O(N)$ for the double buffers (`sdfApp`, `positionsApp`).
- **Strengths:** Significant speedup on multi-core CPUs compared to sequential JFA. Simple to implement using OpenMP pragmas.
- **Limitations:** Memory bandwidth bound due to double buffering. Cache coherence overhead in parallel regions. Not suitable for GPU execution without modification (see Compute Shader variant).

## Background
Parallel Jumping Farthest Away (JFA) is an adaptation of the Sequential JFA algorithm, designed to leverage multi-core CPU architectures. It is part of the broader family of analytic and algebraic voxelization methods. The specific OpenMP implementation is documented in the `cuda-mesh-voxelization` repository, which provides a reference for parallel SDF generation [S1, unofficial].
