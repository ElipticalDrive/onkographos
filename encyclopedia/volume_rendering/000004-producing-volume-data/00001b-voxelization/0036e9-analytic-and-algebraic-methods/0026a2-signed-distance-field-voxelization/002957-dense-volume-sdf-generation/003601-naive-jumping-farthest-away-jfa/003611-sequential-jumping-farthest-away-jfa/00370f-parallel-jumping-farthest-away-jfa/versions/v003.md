# Parallel Jumping Farthest Away (JFA)

Also called: OpenMP JFA

## Overview
Parallel Jumping Farthest Away (JFA) is an OpenMP-based parallelization of the Sequential JFA algorithm for computing Signed Distance Fields (SDFs) on voxel grids [S1, unofficial]. It accelerates the distance propagation phase by parallelizing the inner triple loop over voxel coordinates, while keeping the outer iteration over the jump distance scale $k$ sequential [S1, unofficial]. It differs from the Compute Shader variant by running on CPU multi-core architectures rather than GPU, and from the Sequential JFA by utilizing thread-level parallelism for the spatial updates [S1, unofficial].

## How it works
The method computes the SDF and surface positions for a voxel grid by iteratively refining distance estimates [S1, unofficial]. It relies on the initialization provided by the parent [Sequential Jumping Farthest Away (JFA)](7637-sequential-jumping-farthest-away-jfa.md) or a separate bounding box calculation to seed the grid [S1, unofficial].

**Inputs and Outputs:**
- Input: A voxel grid of dimensions $W \times H \times D$ [S1, unofficial].
- Input: Initial SDF values and surface positions (typically from a sequential pass or bounding box intersection) [S1, unofficial].
- Output: Updated SDF values and surface positions for all voxels [S1, unofficial].

**Data Structures:**
The algorithm uses two sets of buffers to handle parallel writes safely [S1, unofficial]:
1. `sdf`: Current SDF values (read-only during the inner loop).
2. `positions`: Current surface positions (read-only during the inner loop).
3. `sdfApp`: Appended/updated SDF values (write-only during the inner loop).
4. `positionsApp`: Appended/updated surface positions (write-only during the inner loop).

Each buffer is a 3D array of size $W \times H \times D$ [S1, unofficial]. The type `T` represents the data type for distance (e.g., `float`) and position (e.g., `vec3`) [G].

**Numbered Steps:**
1. **Initialization Parallelization**: The initial seeding of the grid (identifying boundary voxels) is parallelized [S1, unofficial]. The outer loop over the Z-axis (`voxelZ`) is parallelized using OpenMP [S1, unofficial]. The inner loops over Y and X remain sequential within each thread [S1, unofficial].
   - Parallel directive: `#pragma omp parallel for collapse(1) schedule(static)` on the `voxelZ` loop [S1, unofficial].
2. **Processing Parallelization**: The main JFA propagation loop iterates over the jump distance scale $k$ [S1, unofficial].
   - The outer loop over $k$ remains sequential to ensure correct propagation order across scales [S1, unofficial].
   - The inner triple loop over `voxelZ`, `voxelY`, and `voxelX` is parallelized [S1, unofficial].
   - Parallel directive: `#pragma omp parallel for collapse(3) schedule(static)` on the triple loop [S1, unofficial].
3. **Distance Update**: For each voxel $(x, y, z)$ and each neighbor defined by the current jump distance $k$, compute the candidate distance [S1, unofficial]. If the candidate distance is smaller than the current value in `sdfApp[x][y][z]`, update `sdfApp` and `positionsApp` [S1, unofficial].
   - Formula: $d_{\text{new}} = \sqrt{(x-x')^2 + (y-y')^2 + (z-z')^2} + \text{sdf}[x'][y'][z']$ [G].
   - Update condition: If $d_{\text{new}} < \text{sdfApp}[x][y][z]$, then $\text{sdfApp}[x][y][z] = d_{\text{new}}$ and $\text{positionsApp}[x][y][z] = \text{positions}[x'][y'][z']$ [S1, unofficial].
4. **Buffer Swap**: After the parallel inner loops complete for a given $k$, swap the contents of `sdf` with `sdfApp` and `positions` with `positionsApp` [S1, unofficial]. This ensures that the next iteration reads from the most recently updated values without race conditions [S1, unofficial].

**Pseudocode:**
```python
def parallel_jfa(sdf, positions, width, height, depth, max_k):
    # Initialize double-buffered arrays for parallel writes
    sdf_app = [[[sdf[z][y][x] for x in range(width)] for y in range(height)] for z in range(depth)]
    positions_app = [[[positions[z][y][x] for x in range(width)] for y in range(height)] for z in range(depth)]

    # Step 1: Initialization Parallelization
    # #pragma omp parallel for collapse(1) schedule(static)
    for voxel_z in range(depth):
        for voxel_y in range(height):
            for voxel_x in range(width):
                # Seed logic: identify boundary voxels
                # The sources do not specify the exact seeding routine; 
                # it is typically handled by a preceding pass or CSG operation.
                pass

    # Step 2 & 3: Processing Parallelization
    for k in range(1, max_k + 1):
        # Reset app buffers to current values before parallel update
        for voxel_z in range(depth):
            for voxel_y in range(height):
                for voxel_x in range(width):
                    sdf_app[voxel_z][voxel_y][voxel_x] = sdf[voxel_z][voxel_y][voxel_x]
                    positions_app[voxel_z][voxel_y][voxel_x] = positions[voxel_z][voxel_y][voxel_x]

        # #pragma omp parallel for collapse(3) schedule(static)
        for voxel_z in range(depth):
            for voxel_y in range(height):
                for voxel_x in range(width):
                    current_dist = sdf[voxel_z][voxel_y][voxel_x]
                    current_pos = positions[voxel_z][voxel_y][voxel_x]

                    best_dist = current_dist
                    best_pos = current_pos

                    # Check neighbors at jump distance k
                    # Iterate over all offsets (dx, dy, dz) where max(|dx|, |dy|, |dz|) == k
                    for dx in range(-k, k + 1):
                        for dy in range(-k, k + 1):
                            for dz in range(-k, k + 1):
                                if max(abs(dx), abs(dy), abs(dz)) != k:
                                    continue
                                nx = voxel_x + dx
                                ny = voxel_y + dy
                                nz = voxel_z + dz

                                # Boundary check
                                if 0 <= nx < width and 0 <= ny < height and 0 <= nz < depth:
                                    neighbor_dist = sdf[nz][ny][nx]
                                    neighbor_pos = positions[nz][ny][nx]

                                    # Calculate candidate distance
                                    dist_to_neighbor = ((dx)**2 + (dy)**2 + (dz)**2)**0.5
                                    candidate = dist_to_neighbor + neighbor_dist

                                    if candidate < best_dist:
                                        best_dist = candidate
                                        best_pos = neighbor_pos

                    sdf_app[voxel_z][voxel_y][voxel_x] = best_dist
                    positions_app[voxel_z][voxel_y][voxel_x] = best_pos

        # Step 4: Buffer Swap
        sdf, sdf_app = sdf_app, sdf
        positions, positions_app = positions_app, positions
```

**Parameters:**
- `max_k`: The number of iterations for the jump flooding process. Typical value: $\lceil \log_2(\max(W, H, D)) \rceil$ [G].
- `schedule(static)`: Used for OpenMP loop scheduling to distribute chunks of iterations to threads [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Race Conditions**: The algorithm avoids race conditions by using separate `sdfApp` and `positionsApp` buffers for writing, while reading from `sdf` and `positions`. Buffers are swapped after each $k$ iteration [S1, unofficial].
- **Boundary Checks**: Neighbors outside the grid bounds must be handled to avoid out-of-bounds access [G].
- **Precision**: Floating-point precision issues may arise in distance calculations for large grids [G].

## Subtopics

## Operating characteristics
- **Time Complexity**: $O(k \cdot W \cdot H \cdot D)$, where $k$ is the number of jump iterations. Parallelization reduces wall-clock time by a factor proportional to the number of CPU cores, subject to overhead [G].
- **Memory Complexity**: $O(W \cdot H \cdot D)$ for the SDF and position buffers. The use of double buffering (`sdf`/`sdfApp`) doubles the memory requirement for the grid data [G].
- **Strengths**: Leverages multi-core CPU performance for SDF generation. Simple to implement using OpenMP pragmas [S1, unofficial].
- **Limitations**: Limited by CPU core count and memory bandwidth. Not suitable for real-time rendering on GPU without porting to compute shaders [G].
- **When to use**: When SDF generation is performed on the CPU as part of a preprocessing pipeline, and GPU compute shaders are not available or desired [G].

## Background
Parallel Jumping Farthest Away is an adaptation of the JFA algorithm for multi-core CPU environments using OpenMP [S1, unofficial]. The method is used in computer graphics for generating Signed Distance Fields from mesh data, enabling efficient ray marching and collision detection in volume rendering [G].
