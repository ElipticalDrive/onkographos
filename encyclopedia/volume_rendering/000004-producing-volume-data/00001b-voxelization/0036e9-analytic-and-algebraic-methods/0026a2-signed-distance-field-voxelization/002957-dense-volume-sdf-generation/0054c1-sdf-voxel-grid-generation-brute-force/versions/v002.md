# SDF Voxel Grid Generation (Brute Force)

Also called: 3D Voxel Grid, Brute Force SDF Generation, Naive SDF Voxelization, Naïve Voxel Grid, Voxel Grid SDF Generation

## Overview
This method generates a dense Signed Distance Field (SDF) by explicitly computing the distance from every voxel in a 3D grid to the nearest surface of an input triangle mesh [S1, unofficial]. It converts a polygonal representation into a continuous scalar field suitable for raymarching or simulation [S1, unofficial]. Unlike hierarchical methods, this approach guarantees exact distance values for the grid resolution by iterating through all mesh triangles for each voxel, resulting in high accuracy at the cost of quadratic computational complexity [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A triangle mesh defined by a vertex array and an index array (32-bit or two 16-bit indices packed into 32-bit) [S1, unofficial].
*   **Input:** Grid dimensions $(W, H, D)$ and the mesh bounding box [S1, unofficial].
*   **Output:** A 3D voxel grid image where each cell stores a signed distance value [S1, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 3D image allocated on the GPU from device local memory for maximum read/write performance in shaders [S1, unofficial].
    *   **Format:** `VK_FORMAT_R32_SFLOAT` (32-bit floating point per cell) [S1, unofficial].
    *   **Initialization:** All cells are initialized to `F32_MAX` (the maximum representable floating-point value) [S1, unofficial].
    *   **Memory:** Half precision (16-bit) is preferable for memory reduction but requires SPIR-V and Vulkan extensions for 16-bit floating point atomics, which were unsupported on the author's drivers [S1, unofficial].

**Preprocessing (Transformation):**
Triangles are transformed by a scaling factor and an offset within the voxel grid to ensure the SDF grid represents the same size as the original mesh and is centered to fully utilize cells [S1, unofficial]. Without this transformation, the mesh extends out of grid bounds, clipping parts like ears and tails [S1, unofficial].

**Algorithm Steps:**
1.  **Parallel Dispatch:** Launch a compute shader where each thread is responsible for one voxel cell $(x, y, z)$, exploiting the embarrassingly parallel nature of independent cell computations [S1, unofficial].
2.  **Initialize Distance:** For the current voxel, set the current minimum distance $d_{min} = \text{F32\_MAX}$ [S1, unofficial].
3.  **Iterate Triangles:** Loop through every triangle in the mesh [S1, unofficial]. For each triangle, calculate the distance from the voxel center to the triangle surface [S1, unofficial]. Use the absolute value of the distance during comparison to find the nearest surface regardless of front/back orientation [S1, unofficial]. Update $d_{min} = \min(d_{min}, \text{absolute\_distance})$ [S1, unofficial].
4.  **Assign Sign:** Assign the signed value to the cell so that the inside of the object is maintained as negative [S1, unofficial]. (Note: The specific sign-determination algorithm is not specified in the sources.)
5.  **Store Result:** Write the signed distance value to the voxel grid at $(x, y, z)$ [S1, unofficial].

**Formula:**
For a single voxel at position $P$, the distance $d$ is calculated as [S1, unofficial]:

$$ d = \min_{t \in \text{Triangles}} (\text{dist}(P, t)) $$

Where $\text{dist}(P, t)$ is the Euclidean distance from voxel center $P$ to triangle $t$ [S1, unofficial]. The absolute value is used for minimization, but the final stored value retains the sign indicating interior/exterior status [S1, unofficial].

**Pseudocode:**
```python
# Compute Shader Entry Point
# Input: voxel_index (global thread ID mapped to 3D grid coordinates)
# Input: mesh_vertices (array of vec3)
# Input: mesh_indices (array of uint)
# Input: grid_scale (float)
# Input: grid_offset (vec3)
# Input: grid_dims (vec3: W, H, D)
# Output: voxel_grid (write-only image3D)

def compute_sdf_brute_force(voxel_index, mesh_vertices, mesh_indices, grid_scale, grid_offset, grid_dims):
    # 1. Map voxel index to 3D coordinates
    W, H, D = grid_dims
    x = voxel_index % W
    y = (voxel_index // W) % H
    z = voxel_index // (W * H)
    
    # 2. Get voxel center in world space
    voxel_center = vec3(x, y, z) * grid_scale + grid_offset
    
    # 3. Initialize minimum distance to infinity
    min_dist = float('inf')
    
    # 4. Iterate through all triangles
    num_triangles = len(mesh_indices) // 3
    for i in range(0, num_triangles * 3, 3):
        idx0 = mesh_indices[i]
        idx1 = mesh_indices[i+1]
        idx2 = mesh_indices[i+2]
        
        v0 = mesh_vertices[idx0]
        v1 = mesh_vertices[idx1]
        v2 = mesh_vertices[idx2]
        
        # 5. Calculate distance from voxel_center to triangle (v0, v1, v2)
        dist = distance_point_to_triangle(voxel_center, v0, v1, v2)
        
        # 6. Update minimum distance using absolute value
        if abs(dist) < min_dist:
            min_dist = abs(dist)
            
    # 7. Determine sign (Inside/Outside)
    # [G] Sign determination method not specified in sources; standard approach uses ray casting or winding number.
    # is_inside = ray_cast_test(voxel_center, mesh_vertices, mesh_indices)
    # For implementation completeness, a standard ray-cast is assumed:
    is_inside = False # Placeholder for standard [G] sign test
    
    if is_inside:
        signed_dist = -min_dist
    else:
        signed_dist = min_dist
        
    # 8. Write to grid
    voxel_grid[voxel_index] = signed_dist

def distance_point_to_triangle(p, v0, v1, v2):
    # [G] Standard geometric distance calculation
    normal = normalize(cross(v1 - v0, v2 - v0))
    dist_plane = dot(p - v0, normal)
    p_proj = p - normal * dist_plane
    
    if is_point_in_triangle(p_proj, v0, v1, v2):
        return dist_plane
        
    d0 = distance_point_to_segment(p, v0, v1)
    d1 = distance_point_to_segment(p, v1, v2)
    d2 = distance_point_to_segment(p, v2, v0)
    
    return min(d0, d1, d2)

def is_point_in_triangle(p, v0, v1, v2):
    # [G] Barycentric coordinate check
    u = v1 - v0
    v = v2 - v0
    w = p - v0
    dot00 = dot(v, v)
    dot01 = dot(u, v)
    dot02 = dot(u, w)
    dot11 = dot(u, u)
    dot12 = dot(v, w)
    inv_denom = 1 / (dot00 * dot11 - dot01 * dot01)
    u_coord = (dot11 * dot02 - dot01 * dot12) * inv_denom
    v_coord = (dot00 * dot12 - dot01 * dot02) * inv_denom
    return (u_coord >= 0) and (v_coord >= 0) and (u_coord + v_coord <= 1)

def distance_point_to_segment(p, a, b):
    # [G] Distance from point to line segment
    ab = b - a
    ap = p - a
    t = dot(ap, ab) / dot(ab, ab)
    t = clamp(t, 0.0, 1.0)
    closest = a + ab * t
    return length(p - closest)
```

**Edge Cases and Pitfalls:**
*   **Grid Bounds:** If the mesh is not transformed (scaled/offset) to fit the grid, parts of the mesh may lie outside the voxel grid boundaries, resulting in clipped geometry (e.g., ears or tails of a bunny mesh) [S1, unofficial].
*   **Precision:** Using 16-bit floats reduces memory but requires specific hardware support for atomic operations, which may be unavailable [S1, unofficial].
*   **Performance:** The brute force approach is computationally expensive. For large meshes, optimization techniques like organizing a mesh hierarchy before computing distances are suggested to reduce the number of triangle checks per voxel [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Quadratic $O(V \cdot T)$, where $V$ is the number of voxels and $T$ is the number of triangles. Increasing either dimension significantly increases generation time [S1, unofficial].
*   **Memory Complexity:** Linear $O(V)$, proportional to the volume of the grid. Each voxel stores one 32-bit float [S1, unofficial].
*   **Performance:** On a GPU using compute shaders, generation can be rapid (under a second) for meshes with over 14,000 triangles when paired with optimizations like the Jump Flooding Algorithm (JFA) for refinement, though the initial brute force pass remains the bottleneck for high-resolution grids [S1, unofficial].
*   **Strengths:** Simple to implement; provides exact distance values for the given resolution; highly parallelizable; supports distance field operations (blending, twisting) directly on the grid [S1, unofficial].
*   **Limitations:** Poor performance for high-resolution grids or complex meshes; memory-intensive for large volumes; requires careful handling of mesh-to-grid transformation [S1, unofficial].
*   **When to Use:** Small to medium-sized meshes where high accuracy is required and resolution is manageable; suitable for preprocessing steps before applying faster refinement algorithms like JFA [S1, unofficial].
*   **When Not to Use:** Very large meshes or extremely high-resolution grids where quadratic complexity becomes prohibitive [S1, unofficial].

## Background
The method was explored in the context of generating Signed Distance Fields from triangle meshes using the Vulkan graphics API and C++ [S1, unofficial]. It builds on the naïve implementation outlined by Payne & Toga (1992), who proposed iterating through all triangles for each voxel to compute precomputed mesh distances [S1, unofficial]. The implementation described in the sources utilizes Vulkan compute shaders to parallelize this process across the GPU, leveraging the SIMD architecture for efficient distance calculations [S1, unofficial]. The approach was compared against Binary Space Partitioning (BSP) trees, which offered perfect accuracy but suffered from poor generation and runtime performance [S1, unofficial].
