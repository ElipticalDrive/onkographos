# General Mesh SDF and Occupancy Voxelization

Also called: SDF voxelization, occupancy grid generation

## Overview
This method converts a solid boundary representation into a regular volumetric occupancy grid and optionally a signed-distance field (SDF) [S1, unofficial]. It solves the problem of discretizing continuous CAD geometry into a dense 3D grid suitable for downstream applications such as 3D-print lattice generation, finite element meshing, and collision queries [S1, unofficial]. Unlike core B-rep operations, this is an application-level capability that relies on tessellated mesh data rather than exact analytical surfaces [S1, unofficial]. It builds on [Dense Volume SDF Generation](4499-dense-volume-sdf-generation.md) and differs from [Cube SDF Grid Construction](4883-cube-sdf-grid-construction.md) and [Naive Jumping Farthest Away (JFA)](7621-naive-jumping-farthest-away-jfa.md) by operating directly on arbitrary tessellated meshes rather than axis-aligned primitives or distance transforms [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A solid body identifier (`CCShapeId`), a double-precision isotropic voxel spacing ($s$) in millimeters, and an integer mode flag selecting the output type (occupancy-only or occupancy+SDF) [S1, unofficial].
*   **Output:** A `CCVoxelGrid` structure containing the grid origin, dimensions, spacing, an occupancy array, and an optional SDF array [S1, unofficial].

**Data Structures:**
The output is defined by the following layout [S1, unofficial]:
```c
typedef struct {
  double   origin[3];     /* Grid origin in mm */
  double   spacing;       /* Isotropic voxel size in mm */
  int      dims[3];       /* nx, ny, nz */
  uint8_t *occupancy;     /* Array of size dims[0]*dims[1]*dims[2]. 1 = inside solid, 0 = outside */
  float   *sdf;           /* Optional signed distance field in mm. NULL if not requested. */
} CCVoxelGrid;
```

**Algorithm Steps:**
1.  **Grid Initialization:** Allocate the `CCVoxelGrid` structure and set `origin` to the desired grid start point [G]. Set `spacing` to the input $s$ [S1, unofficial]. Calculate `dims` based on the bounding box of the input body and the spacing [G].
2.  **Tessellation:** Convert the `CCShapeId` body into a tessellated triangle mesh [G]. This step is a prerequisite as the voxelization operates on the discrete mesh representation rather than the exact B-rep [S1, unofficial].
3.  **Occupancy Classification:** For each voxel center $p_i$ in the grid, perform an inside/outside test against the tessellated mesh using ray-stabbing or generalized winding number [S1, unofficial]. Set `occupancy[i] = 1` if the point is inside the solid, and `0` otherwise [S1, unofficial]. This step is naturally data-parallel and suitable for GPU acceleration via Metal compute [S1, unofficial].
4.  **SDF Computation (Optional):** If the mode requests SDF, for each voxel center $p_i$, calculate the Euclidean distance to the nearest point on the surface mesh [S1, unofficial]. Assign the sign based on the occupancy result: negative if inside, positive if outside [S1, unofficial]. Store the result in `sdf[i]` [S1, unofficial]. This can be implemented as a full SDF or a narrow-band approximation [S1, unofficial].
5.  **Validation:** Verify that the grid meets acceptance criteria [S1, unofficial].

**Pseudocode:**

class CCVoxelGrid:
    def __init__(self):
        self.origin = [0.0, 0.0, 0.0]
        self.spacing = 0.0
        self.dims = [0, 0, 0]
        self.occupancy = []
        self.sdf = None

def cc_voxelize(body_id, spacing, mode, grid_origin):
    # [G] Standard B-rep to triangle mesh conversion
    mesh = tessellate(body_id)
    # [G] Compute min/max coordinates from mesh vertices
    bbox_min, bbox_max = get_bounding_box(mesh)
    # [G] Dimension calculation
    dims_x = math.ceil((bbox_max[0] - grid_origin[0]) / spacing)
    dims_y = math.ceil((bbox_max[1] - grid_origin[1]) / spacing)
    dims_z = math.ceil((bbox_max[2] - grid_origin[2]) / spacing)
    dims = [dims_x, dims_y, dims_z]
    total_voxels = dims[0] * dims[1] * dims[2]

    occupancy = [0] * total_voxels
    sdf = None
    if mode == 1:
        sdf = [0.0] * total_voxels

    for z in range(dims[2]):
        for y in range(dims[1]):
            for x in range(dims[0]):
                idx = x + y * dims[0] + z * dims[0] * dims[1]
                px = grid_origin[0] + (x + 0.5) * spacing
                py = grid_origin[1] + (y + 0.5) * spacing
                pz = grid_origin[2] + (z + 0.5) * spacing
                p = [px, py, pz]

                is_inside = point_in_solid(p, mesh)
                occupancy[idx] = 1 if is_inside else 0

                if mode == 1:
                    dist = distance_to_mesh(p, mesh)
                    sdf[idx] = -dist if is_inside else dist

    grid = CCVoxelGrid()
    grid.origin = grid_origin
    grid.spacing = spacing
    grid.dims = dims
    grid.occupancy = occupancy
    grid.sdf = sdf
    return grid

**Parameters:**
*   `spacing`: Double. Isotropic voxel size in mm. Determines grid resolution [S1, unofficial].
*   `mode`: Integer. Selects output type: occupancy-only or occupancy+SDF [S1, unofficial].

**Validation Formulas:**
*   **Volume Convergence:** Voxelizing a unit box or sphere at spacing $s$ yields an occupancy count whose implied volume converges to the analytic volume as $s \to 0$ [S1, unofficial]:
    $$ \lim_{s \to 0} \text{Volume}_{\text{voxel}} = \text{Volume}_{\text{analytic}} $$
*   **SDF Correctness:** The SDF sign must be correct (negative inside, positive outside) and the absolute value must match the distance-to-surface within tolerance on analytic primitives [S1, unofficial]:
    $$ \text{sign}(SDF) = \begin{cases} -1 & \text{inside} \\ +1 & \text{outside} \end{cases} $$
    $$ |SDF| \approx \text{dist}(p, \text{surface}) $$
*   **GPU/CPU Parity:** If GPU-accelerated, the fp32 GPU result must match the fp64 CPU reference within tolerance $\epsilon$ [S1, unofficial]:
    $$ |Result_{GPU} - Result_{CPU}| \leq \epsilon $$

**Edge Cases and Pitfalls:**
*   **Precision:** The CPU must be the source of truth using fp64 [S1, unofficial]. The GPU is used for throughput with fp32 [S1, unofficial]. The exact classification must remain defensible on the CPU [S1, unofficial].
*   **Memory Management:** Large grids can cause Out Of Memory (OOM) errors [S1, unofficial]. Implementation must stream or tile large grids [S1, unofficial].
*   **Determinism:** The result must be deterministic for a fixed body, spacing, and grid origin [S1, unofficial].
*   **Application-Level Nature:** This is not a core B-rep feature [S1, unofficial]. It should be scheduled only against a concrete product driver, not on the critical path [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** The method is naturally data-parallel, making it a good fit for GPU acceleration via Metal compute backend for fp32-tolerant throughput work [S1, unofficial].
*   **Strengths:** Provides dense volumetric data for simulation, 3D printing, and spatial queries [S1, unofficial]. Enables smooth booleans and offsets via SDF [S1, unofficial].
*   **Limitations:** Resolution-dependent [S1, unofficial]. High resolution leads to large memory footprints [S1, unofficial]. Not suitable for exact B-rep operations [S1, unofficial]. Requires a concrete driver to justify the computational cost [S1, unofficial].
*   **When to use:** 3D-print lattice/infill generation, FE simulation meshing, collision/spatial queries, generative design, medical/CT import [S1, unofficial].
*   **When not to use:** When exact boundary representation is required, or when memory is severely constrained without tiling strategies [S1, unofficial].

## Background
This subsystem is a net-new addition to the CyberCadKernel (CC) [S1, unofficial]. OCCT's historical Voxel package was dropped long ago, and there were zero references to voxel/SDF/marching-cubes/distance-field in the repository prior to this implementation [S1, unofficial]. The feature was proposed in July 2026 by leonardoaraujosantos in the CyberdyneCorp/CyberCadKernel repository [S1, unofficial]. It is designed to support downstream pipelines such as CalculiX++ FE meshing and 3D-print manufacturing features [S1, unofficial].
