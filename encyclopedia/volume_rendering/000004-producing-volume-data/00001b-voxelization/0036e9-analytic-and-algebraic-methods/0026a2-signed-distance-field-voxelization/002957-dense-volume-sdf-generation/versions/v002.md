# Dense Volume SDF Generation

Also called: Dense Grid SDF, SDF Voxelization, meshToDistanceVolume

## Overview
Dense Volume SDF Generation computes a scalar field $D(x)$ for every voxel center $x$ in a dense 3D grid, where $D(x)$ represents the shortest Euclidean distance from $x$ to the input mesh surface, with a sign indicating the topological relationship (inside/outside) [S1, unofficial][S2]. It differs from sparse methods by storing data for every voxel in the bounding volume, providing full data access ideal for simulation, marching cubes, or machine learning, at the cost of higher memory usage [S2]. It builds on [Signed Distance Field Voxelization](3849-signed-distance-field-voxelization.md) by explicitly managing the dense grid layout and sign detection parameters.

## How it works
**Inputs:**
*   Input mesh geometry defined by vertices $V$ and faces $F$.
*   Grid resolution parameters: `voxelSize` (scalar or vector), `origin`, and `dimensions` ($N_x \times N_y \times N_z$).
*   Distance bounds: `maxDistSq` (squared maximum distance to compute) and `nullOutsideMinMax` (boolean flag).
*   Sign detection mode: `signMode` (e.g., HoleWindingRule, RayParity).

**Outputs:**
*   A dense 3D grid (tensor) of signed distance values, typically stored in a format like HDF5 or a contiguous memory array [S1, unofficial][S2].

**Data Structures:**
*   **Grid:** A 3D array `sdf` of type `float` with dimensions `height`, `width`, `depth` (or $N_z, N_y, N_x$). In C++ implementations, this may be an `Eigen::Tensor<float, 3, Eigen::RowMajor>` [S1, unofficial].
*   **Mesh:** Vertices stored as a list of 3D vectors; faces stored as a list of vertex indices (triplets) [S1, unofficial].

**Parameters:**
*   `voxelSize`: The physical size of one voxel side. Often calculated automatically using `suggestVoxelSize(mesh, target_voxel_count)` to achieve a desired resolution (e.g., $10^7$ voxels) [S2].
*   `maxDistSq`: The squared maximum distance from the mesh surface to compute. A common heuristic is $(3 \times \text{voxelSize})^2$, covering 3 voxel layers [S2].
*   `signMode`: Determines how the sign is computed. `HoleWindingRule` is robust for non-watertight meshes and self-intersections [S2].
*   `nullOutsideMinMax`: If `True`, voxels with distance greater than `maxDistSq` are set to a null value (e.g., NaN or infinity) rather than the computed distance [S2].

**Algorithm Steps:**

1.  **Initialization:**
    *   Load the input mesh.
    *   Calculate the bounding box of the mesh.
    *   Determine `voxelSize`, `origin`, and `dimensions` based on the bounding box and desired resolution [S2].
    *   Initialize the output grid `sdf` with dimensions `dimensions`. Initialize all values to infinity or a null marker [S1, unofficial].

2.  **Voxel Iteration:**
    *   Iterate over every voxel index $i$ from $0$ to $N_x \times N_y \times N_z - 1$.
    *   Calculate voxel coordinates $(w, h, d)$ from $i$:
        $$ w = i \% N_x $$
        $$ h = (i / N_x) \% N_y $$
        $$ d = (i / N_x) / N_y $$
    *   Calculate the voxel center $C$ in world space:
        $$ C = \text{origin} + (w + 0.5, h + 0.5, d + 0.5) \times \text{voxelSize} $$
        *Note: If `VoxelizationMode::CORNER` is used, the offset is $(0,0,0)$ instead of $(0.5,0.5,0.5)$ [S1, unofficial].*

3.  **Distance Calculation:**
    *   Initialize `min_dist` to infinity.
    *   Iterate over all triangles $T$ in the mesh. For each triangle with vertices $v_1, v_2, v_3$:
        *   Compute the closest point $P_{closest}$ on the triangle to $C$.
        *   Compute the Euclidean distance $d = \| C - P_{closest} \|$.
        *   If $d^2 < \text{maxDistSq}$ and $d < \text{min\_dist}$, update `min_dist = d`.
    *   If `nullOutsideMinMax` is True and `min_dist` remains infinity (or $> \sqrt{\text{maxDistSq}}$), set `sdf[d, h, w]` to null/NaN and continue to the next voxel.
    *   Otherwise, store `min_dist` in `sdf[d, h, w]`.

4.  **Sign Determination:**
    *   Determine the sign of the distance based on the selected `signMode` [S1, unofficial][S2]:
        *   **Ray Casting Parity:** Cast a ray from $C$ to infinity (e.g., towards the origin or a fixed direction). Count intersections with the mesh triangles. If the count is odd, the point is inside (negative sign); if even, outside (positive sign) [S1, unofficial].
        *   **Winding Number:** Compute the solid angle or winding number of the mesh around $C$. A non-zero winding number indicates the interior. This method is robust for holes and self-intersections [S2].
    *   Apply the sign to the stored distance:
        $$ \text{sdf}[d, h, w] = \text{sign} \times \text{min\_dist} $$

**Pseudocode:**

                # Naive iteration over all triangles (use acceleration in practice)

                    v2 = vertices[faces[face_idx, 1]]
                    v3 = vertices[faces[face_idx, 2]]
                    
                    cp, dist_sq = point_to_triangle_distance(center, v1, v2, v3)
                    
                    if dist_sq < min_dist_sq:
                        min_dist_sq = dist_sq
                        closest_point = cp
                
                # Check max distance bound
                max_dist_sq = (3 * voxel_size) ** 2
                if min_dist_sq > max_dist_sq:
                    sdf_grid[d, h, w] = np.nan # Null outside
                    continue
                
                min_dist = np.sqrt(min_dist_sq)
                
                # 4. Sign Determination (Ray Parity Example)
                # Cast ray from center to origin (or infinity)
                ray_direction = -center # Towards origin
                num_intersections = 0
                
                for face_idx in range(len(faces)):

                    v3 = vertices[faces[face_idx, 2]]
                    
                    if triangle_ray_intersection(center, ray_direction, v1, v2, v3):
                        num_intersections += 1
                
                # Parity rule: Odd = Inside (Negative), Even = Outside (Positive)
                if num_intersections % 2 == 1:
                    sdf_grid[d, h, w] = -min_dist
                else:
                    sdf_grid[d, h, w] = min_dist
                    
    return sdf_grid, {'origin': origin, 'dimensions': dimensions, 'voxel_size': voxel_size}

## Subtopics

### [Cube SDF Grid Construction](4883-cube-sdf-grid-construction.md)
Constructs a discrete SDF grid for a cube using analytical box-based min/max operations. It is faster than general mesh traversal for primitive shapes but lacks the generality of mesh-based generation.

### [Sphere SDF Grid Construction](4895-sphere-sdf-grid-construction.md)
Uses spherical symmetry and Euclidean distance from the center. It is optimal for spheres but not applicable to arbitrary meshes.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot F)$, where $N$ is the number of voxels and $F$ is the number of triangles in the mesh. This is computationally expensive for high-resolution grids and complex meshes. Spatial acceleration structures (BVH, Grid) are typically required to reduce this to $O(N \log F)$ or better [S2].
*   **Memory Complexity:** $O(N)$, where $N$ is the total number of voxels. A $1024^3$ grid requires ~4GB of memory for single-precision floats [S2].
*   **Performance:** Suitable for small to medium-sized meshes where exact voxel-by-voxel control is needed [S2]. Low resolution (e.g., $64^3$) results in poor reconstruction quality; higher resolutions (e.g., $256^3$ or more) are recommended for detailed geometry [S1, unofficial].
*   **Strengths:** Provides complete volumetric data; compatible with standard marching cubes implementations; robust sign detection options (Winding Number) handle non-watertight meshes [S2].
*   **Limitations:** High memory consumption for large volumes; slow without acceleration structures; sensitive to voxel size selection [S2].

## Background
The method originates from the need to convert polygonal meshes into volumetric representations for simulation, 3D printing, and machine learning applications. The specific implementation details, such as `meshToDistanceVolume` and `HoleWindingRule`, are documented in the MeshLib library [S2]. The general concept of voxelizing meshes into SDFs has been widely used in computer graphics for decades, with early implementations relying on ray casting for sign determination [S1, unofficial].
