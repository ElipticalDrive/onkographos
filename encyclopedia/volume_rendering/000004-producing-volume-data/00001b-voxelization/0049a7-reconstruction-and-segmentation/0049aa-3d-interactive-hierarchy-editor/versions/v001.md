# 3D Interactive Hierarchy Editor

Also called: 3D IHE, Region Hierarchy Editor, Semantic Region Selection

## Overview
The 3D Interactive Hierarchy Editor (3D IHE) is a semantic control tool that allows users to define regions of interest (ROIs) by selecting primitive collections of voxels, which are then used to modify volume rendering parameters such as color and opacity [S1, unofficial]. It differs from local syntactic controls (like ramp-based classification) and geometric clipping by using global set-membership of data points to isolate morphological features [S1, unofficial]. Unlike sibling methods that segment voxel-by-voxel or via pure geometric intersection, 3D IHE builds a hierarchy of related voxels to enable efficient, 3D-aware selection via a slice paradigm [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volumetric dataset (e.g., $128^3$ with 256 gray levels) and a pre-computed hierarchy of voxel primitives.
*   **Output:** A selection mask (binary or weighted) and opcodes sent to a volume renderer via TCP/IP.

**Data Structures:**
1.  **Hierarchy Tree:** A directed acyclic graph where nodes represent primitive regions of voxels with similar characteristics. The root represents the entire volume; leaves represent individual voxels or minimal coherent volumes [S1, unofficial].
2.  **Selection Mask:** A 3D array matching the input dataset resolution, storing binary values (selected/not selected) or weights for each voxel.

**Algorithm Steps:**

1.  **Hierarchy Generation (Preprocessing):**
    *   Treat the 3D image as a 3-manifold in 4-space (intensity as the 4th dimension) [S1, unofficial].
    *   Analyze ridges and valleys in this 3-fold surface [S1, unofficial].
    *   Compute "reverse gravity watersheds" to segment the volume into primitive regions [S1, unofficial].
    *   Organize these primitives into a hierarchy where parent nodes encompass child regions [S1, unofficial].
    *   *Note:* This step is computationally expensive. For a $128^3$ image, it takes ~15 minutes on a Decstation 3100 [S1, unofficial].

2.  **Interactive Selection:**
    *   Display a full-size 2D slice of the current 3D dataset [S1, unofficial].
    *   User selects/deselects primitive regions within this 2D slice using mouse operations [S1, unofficial].
    *   Selections are extended in 3D: selecting a primitive in one slice applies the selection to the entire 3D extent of that primitive [S1, unofficial].
    *   Navigate slices using forward/backward buttons or a slider to view adjacent slices [S1, unofficial].
    *   Preview effects using scaled-down thumbnails of multiple slices [S1, unofficial].

3.  **Mask Transmission:**
    *   Generate the final 3D selection mask based on user interactions [S1, unofficial].
    *   Send the mask and opcodes to the volume renderer via Unix sockets over Ethernet using TCP packets [S1, unofficial].
    *   Transmission latency is ~10 seconds for the mask [S1, unofficial].

4.  **Rendering Application:**
    *   The volume renderer applies the mask during ray casting [S1, unofficial].
    *   Selected voxels have their color and opacity modified to emphasize them [S1, unofficial].
    *   *Limitation:* The mask does not interact with raw data before local classification; it only affects rendering parameters [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Hierarchy generation is high-cost. Preprocessing a $128^3$ image takes ~15 minutes on a Decstation 3100 [S1, unofficial]. Interactive selection is fast (<1 minute for brain portion selection with 10 button presses) compared to 2D slice-by-slice editing (~40 minutes) [S1, unofficial].
*   **Memory Complexity:** Requires storage for the hierarchy tree and the selection mask. Not given in the sources.
*   **Performance:** The 3D IHE significantly reduces user time for complex 3D selections compared to 2D methods [S1, unofficial].
*   **Strengths:** Enables semantic, global set-membership selection; efficient 3D region definition via 2D interaction; immediate visual feedback [S1, unofficial].
*   **Limitations:** Slow preprocessing; high transmission latency; mask does not affect pre-classification data processing [S1, unofficial].
*   **When to use:** When users need to select complex, non-contiguous 3D regions based on semantic meaning rather than local intensity thresholds [S1, unofficial].
*   **When not to use:** When real-time, low-latency interaction is critical, or when raw data modification is required before classification [S1, unofficial].

## Background
The 3D Interactive Hierarchy Editor was developed as part of an explorational 3D visualization system for medical image data [S1, unofficial]. It builds on earlier work in image segmentation using ridges and valleys, extending 2D methods to 3D by treating images as 3-manifolds in 4-space [S1, unofficial]. The system was designed to change 3D display from a post-processing step to a primary way of viewing medical image data by allowing dynamic control of opacity and regions of interest [S1, unofficial].
