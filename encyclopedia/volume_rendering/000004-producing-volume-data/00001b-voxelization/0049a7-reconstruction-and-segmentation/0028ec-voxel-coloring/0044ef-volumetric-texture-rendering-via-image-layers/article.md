# Volumetric Texture Rendering via Image Layers

Also called: Image layers representation, Rendering by using the new model of volumetric texture, Volumetric Textures Representation Based on Image Layers

## Overview
This method renders volumetric textures by converting a reconstructed voxel volume into a set of 2D transparent image layers, which are then projected and alpha-composited onto the image plane using a Z-buffer. It solves the performance bottleneck of traditional ray-casting volumetric rendering by leveraging standard graphics hardware polygon processing, offering real-time capabilities for complex repetitive scenes. It differs from its parent [Voxel Coloring](4418-voxel-coloring.md) by shifting from a voxel-based storage model to a layered 2D texture model, and from siblings like [Generalized Voxel Coloring](5526-generalized-voxel-coloring.md) by explicitly utilizing 2D image layers for rendering rather than direct voxel traversal.

## How it works
**Inputs and Outputs:**
*   **Input:** A reference volume generated by voxel coloring, represented as $N$ 2D images of size $X \times Y$ in RGBA format.
*   **Output:** A final 2D image on the screen.

**Data Structures:**
*   **Volume Representation:** The volume is treated as a collection of $N$ layers. Each layer is a 2D image (texture) containing precalculated colors (RGB) and transparency (Alpha). No reflectance or lighting information is stored; shading is fixed during construction [S1].
*   **Box:** The volumetric grid is decomposed into boxes. Each box is defined by $2N$ points: $N$ points for the base and $N$ points for the top. Each point has 3D space coordinates $(X, Y, Z)$ and 2D texture coordinates $(U, V)$ [S1].
*   **Texel Directions:** Each texel has three orthogonal directions: Normal ($N_R$), Tangent ($T$), and Bi-normal ($B$) [S1].

**Algorithm Steps:**

1.  **Layer Conversion:** Convert the volumetric texture (reference volume) into a set of $N$ layers, where each layer is a 2D image considered as a transparent texture [S1].
2.  **View Direction Selection:** For each texel, determine the best viewing direction to minimize distortion or occlusion issues. Compute the scalar products between the view axis $V$ and the three texel directions ($N_R, T, B$). Select the direction with the largest absolute scalar product [S1].
3.  **Coordinate Interpolation:** Calculate the spatial coordinates for the intermediate sections of a box. Let $A_0, B_0, C_0$ be the coordinates of the bottom layer points and $A_{n-1}, B_{n-1}, C_{n-1}$ be the coordinates of the top layer points, where $n$ is the number of layers. The coordinates for section $i$ are calculated as:
    $$
    A_i = A_0 + \frac{i}{n} (A_{n-1} - A_0)
    $$
    $$
    B_i = B_0 + \frac{i}{n} (B_{n-1} - B_0)
    $$
    $$
    C_i = C_0 + \frac{i}{n} (C_{n-1} - C_0)
    $$
    Note: The source text contains a conflicting definition $A_i = A_0$ alongside the interpolation formula; the interpolation formula is used for rendering [S1].
4.  **Rendering Loop:** Iterate through all boxes and all sections within each box.
    *   Load the texture for the current section.
    *   Display the section of the box. This involves binding the texture identifier and loading the 2D image data into the graphics context [S1].
5.  **Projection and Composition:** Project each layer onto the image plane using a Z-buffer. Successively compose the projected layers. Each projected layer is combined with the preceding result taking into account the density (alpha) of each pixel [S1].
6.  **Alpha Compositing:** Render transparent faces in depth order (back-to-front). For each point:
    *   If the point's depth is further than the Z-buffer value AND the Z-buffer point belongs to a completely opaque polygon, reject the point.
    *   Otherwise, apply alpha compositing:
        $$
        C_{screen} = \alpha_{point} \times C_{point} + (1 - \alpha_{point}) \times C_{screen}
        $$
    *   For opaque semi-polygons, compose colors by displaying faces back-to-front respecting depth order relative to the viewpoint [S1].

def render_polygon_with_texture(polygon, texture):
    """
    Projects polygon to screen, handles Z-buffer and Alpha blending.
    """
    # Project vertices to screen space
    screen_vertices = [project_to_screen(v) for v in polygon.vertices]
    
    # Rasterize polygon
    for pixel in rasterize(screen_vertices):
        # Get depth of this pixel from the polygon
        z_poly = pixel.z_depth
        
        # Get current depth in Z-buffer
        z_buf = get_z_buffer(pixel.x, pixel.y)
        
        # Get color and alpha from texture at this pixel's UV
        tex_color, tex_alpha = sample_texture(texture, pixel.uv)
        
        # Z-buffer test for transparent faces
        # Condition: if point is further than Z-buffer AND Z-buffer point is opaque
        if z_poly > z_buf and is_opaque(z_buf):
            continue # Reject point
        
        # Alpha compositing
        # C_screen = alpha_point * C_point + (1 - alpha_point) * C_screen
        current_screen_color = get_screen_color(pixel.x, pixel.y)
        new_color = tex_alpha * tex_color + (1 - tex_alpha) * current_screen_color
        
        # Update screen and Z-buffer
        set_screen_color(pixel.x, pixel.y, new_color)
        set_z_buffer(pixel.x, pixel.y, z_poly)

**Parameters:**
*   **Level of Detail (LOD):** The number of display layers $n$ can be reduced based on the distance $d$ of the observer and the vision angle $a$. Two criteria are mentioned:
    1.  $H \times \tan(a) < d_0$, where $n$ is the minimum number of sections to keep constant visual quality [S1].
    2.  Spacing between layers is defined to balance realism and speed [S1].
*   **Typical Values:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Opaque Semi-polygons:** Must be rendered back-to-front respecting depth order [S1].
*   **Z-buffer Rejection:** Transparent points behind opaque surfaces must be correctly rejected to avoid visual artifacts [S1].
*   **Deformation:** Coordinates of box faces are recomputed only when the box becomes deformed [S1].

## Subtopics

### Voxel Coloring
The reconstruction method that generates the initial reference volume from multiple images using color consistency. This method builds on [Voxel Coloring](4418-voxel-coloring.md) by converting its output into a renderable format.

### Generalized Voxel Coloring
An extension of voxel coloring that handles more complex scene structures. This method differs by using 2D layers for rendering, whereas generalized voxel coloring may retain voxel-based rendering or other representations.

### Multi-view Color Consistency and Smoothing
Techniques to refine color values across views. This method uses the precalculated colors from such refinements but renders them via layers rather than volumetric ray casting.

## Operating characteristics
*   **Time Complexity:** Faster than traditional ray casting. The projection of a layer is faster than calculating projection for each voxel along a ray, providing an appreciable time benefit [S1].
*   **Memory Complexity:** Requires storing $N$ 2D images of size $X \times Y$ in RGBA format. The memory usage is proportional to the number of layers and image resolution.
*   **Measured Performance:** The method allows for real-time rendering, reducing calculation times from 5-20 minutes (typical for ray casting) to acceptable real-time frames [S1].
*   **Strengths:** Exploits graphics board capacities effectively; suitable for repetitive complex scenes; supports Level of Detail (LOD) based on viewer distance and angle.
*   **Limitations:** Fixed shading and lighting (no dynamic reflectance); requires precalculation of colors; relies on Z-buffer for transparency, which can be sensitive to draw order.
*   **When to Use:** Real-time applications requiring realistic rendering of repetitive complex scenes (e.g., fur, foliage) where dynamic lighting is not required or is baked in.
*   **When Not to Use:** Scenes requiring dynamic lighting, complex material interactions, or non-repetitive volumetric data.

## Background
*   **Origin:** The method was presented by Hemidi Djallel and Jedi Noureddine in 2006 [S1].
*   **History:** Volumetric textures were initially introduced by Kajiya and Kay in 1989 for fur rendering [S1]. This method integrates voxel coloring techniques into volumetric textures to improve rendering speed for real-time applications.
*   **Usage:** Used in real-time graphics applications for rendering complex repetitive scenes such as fur, grass, or other volumetric textures where traditional ray casting is too slow.
