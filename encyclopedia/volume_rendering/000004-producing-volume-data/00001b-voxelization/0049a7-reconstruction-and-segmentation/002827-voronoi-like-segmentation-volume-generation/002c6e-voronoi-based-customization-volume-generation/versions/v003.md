# Voronoi-based Customization Volume Generation

Also called: Discrete Voronoi Diagram Calculation on GPU, Discrete Voronoi Diagram for Customization, Natural Neighbor Interpolation via Voronoi

## Overview
This method generates a low-resolution 3D customization volume by computing a discrete Voronoi diagram on the GPU, assigning each voxel to its nearest seed point, and subsequently deriving customization parameters via natural neighbor interpolation [S1]. It solves the performance bottleneck of calculating position-dependent transfer function parameters for large volume datasets by decoupling the customization resolution from the input data size [S1]. Unlike its sibling [Soft Voronoi Decomposition](7634-soft-voronoi-decomposition.md), this method produces a hard segmentation where each voxel belongs exclusively to one Voronoi cell, enabling interactive frame rates through trilinear interpolation of the low-resolution result during rendering [S1].

## How it works
The method operates in two distinct compute-shader passes [S1]. Pass 1 constructs a discrete Voronoi diagram [S1]. Pass 2 computes the final customization values using natural neighbor interpolation, building on the segmentation from Pass 1 [S1].

### Inputs and Outputs
**Inputs:**
1.  **Seed Points Buffer:** An array of $N$ seed points [S1]. Each point contains a 3D voxel position (`pos`) and a numeric visualization parameter (`value`) [S1].
2.  **Resolution:** A 3D integer vector defining the dimensions of the output customization volume grid (e.g., $64^3$) [S1].

**Outputs:**
1.  **Voronoi Volume:** A linear buffer `voronoi[]` storing the index of the seed point in the input buffer to which each voxel's Voronoi cell belongs [S1].
2.  **Customization Volume:** A 3D texture or buffer storing the interpolated scalar values for each voxel, derived from the Voronoi diagram and seed values [S1].

### Data Structures
*   **Seed Point Structure:**
    ```python
    class SeedPoint:
        pos: tuple[float, float, float]  # 3D voxel position in original input volume coordinates
        value: float  # Scalar visualization parameter
    ```
*   **Voronoi Volume:**
    ```python
    voronoi: list[int]  # Linear buffer of size V = res.x * res.y * res.z
    ```
*   **Customization Volume:**
    ```python
    customization: list[float]  # Linear buffer or 3D texture
    ```

### Parameters
*   **Resolution:** The customization volume resolution is lower than the input volume data, typically $64^3$ voxels, to reduce memory usage and allow interactive frame rates [S1].
*   **Distance Measure:** The distance metric for nearest-neighbor search can be changed between (squared) Euclidean distance or Manhattan distance [S1].
*   **Coordinate Scaling:** Seed customization point positions, specified in the original higher input volume resolution, must be scaled relative to the customization volume resolution before passing to the shader [S1].

### Algorithm Steps

#### Pass 1: Discrete Voronoi Diagram Calculation
For every voxel in the customization volume grid, a compute shader work item determines the nearest seed point [S1].
1.  For each voxel in the discretized grid, determine its 3D position `cur3DPos` [S1].
2.  Initialize `minPoint` to 0 and `minDist` to infinity [S1].
3.  Iterate through all seed points in the input buffer [S1].
4.  Calculate the distance `d` between the seed point's position and `cur3DPos` [S1].
5.  If `d` is less than `minDist`, update `minDist` to `d` and `minPoint` to the current seed point index [S1].
6.  After checking all points, calculate the linear index for the voxel in the output buffer [S1].
7.  Store the index of the nearest seed point (`minPoint`) in the output buffer at the calculated linear index [S1].

#### Pass 2: Natural Neighbor Interpolation
For every voxel in the customization volume, the final value is computed based on the geometric relationship between its Voronoi cell and its neighbors [S1].
1.  Identify the Voronoi cell membership for the current voxel from the Voronoi volume generated in Pass 1 [S1].
2.  Compute the final customization value for each voxel using natural neighbor interpolation based on the Voronoi cell membership [S1].
3.  The method approximates the volume of a Voronoi cell by the number of voxels which belong to it [S1].
4.  During volume rendering, samples between voxels of the low-resolution customization volume are reconstructed using trilinear interpolation when accessing the customization volume [S1].

### Pseudocode
```python
def compute_voronoi(points, resolution):
    # points: list of SeedPoint
    # resolution: tuple (res_x, res_y, res_z)
    # Returns: list of int (voronoi buffer)
    res_x, res_y, res_z = resolution
    V = res_x * res_y * res_z
    voronoi = [0] * V
    
    # Simulate compute shader work items for each voxel
    for z in range(res_z):
        for y in range(res_y):
            for x in range(res_x):
                cur3DPos = (float(x), float(y), float(z))
                minPoint = 0
                minDist = float('inf')
                
                # Iterate through all seed points in the input buffer
                for i, point in enumerate(points):
                    # Calculate distance (Euclidean or Manhattan)
                    d = ((cur3DPos[0] - point.pos[0])**2 + 
                         (cur3DPos[1] - point.pos[1])**2 + 
                         (cur3DPos[2] - point.pos[2])**2)**0.5
                    if d < minDist:
                        minDist = d
                        minPoint = i
                        
                # Calculate linear index from cur3DPos and set Voronoi data
                index = x + res_x * y + res_y * res_x * z
                voronoi[index] = minPoint
    return voronoi

def compute_customization(points, voronoi, resolution):
    # points: list of SeedPoint
    # voronoi: list of int
    # resolution: tuple (res_x, res_y, res_z)
    # Returns: list of float (customization buffer)
    res_x, res_y, res_z = resolution
    V = res_x * res_y * res_z
    customization = [0.0] * V
    
    # Pass 2: each work item iterates over all voxels in the resolution [S1]
    for z in range(res_z):
        for y in range(res_y):
            for x in range(res_x):
                cur3DPos = (float(x), float(y), float(z))
                nearest_idx = voronoi[x + res_x * y + res_y * res_x * z]
                
                weighted_sum = 0.0
                total_weight = 0.0
                
                # Iterate over all voxels to compute natural neighbor weights [S1]
                for z2 in range(res_z):
                    for y2 in range(res_y):
                        for x2 in range(res_x):
                            idx2 = x2 + res_x * y2 + res_y * res_x * z2
                            neighbor_idx = voronoi[idx2]
                            if neighbor_idx != nearest_idx:
                                # Exact natural neighbor weight calculation based on Voronoi cell topology [G]
                                # The sources do not provide the explicit weight formula [S1]
                                weight = 1.0 / (distance(cur3DPos, points[neighbor_idx].pos) + 1e-6)
                                weighted_sum += weight * points[neighbor_idx].value
                                total_weight += weight
                                
                if total_weight > 0:
                    final_value = weighted_sum / total_weight
                else:
                    final_value = points[nearest_idx].value
                    
                customization[x + res_x * y + res_y * res_x * z] = final_value
    return customization

def distance(p1, p2):
    return ((p1[0] - p2[0])**2 + (p1[1] - p2[1])**2 + (p1[2] - p2[2])**2)**0.5
```

### Edge Cases and Pitfalls
*   **Coordinate Scaling:** Seed positions must be scaled from the original input volume resolution to the customization volume resolution before shader execution [S1].
*   **Distance Metric Consistency:** The distance measure can be changed between (squared) Euclidean distance or Manhattan distance [S1].
*   **Boundary Conditions:** Voxels on the boundary of the customization volume may have fewer neighbors. The neighbor search must handle grid boundaries correctly to avoid out-of-bounds memory access [G].
*   **Degenerate Input:** If multiple seed points are equidistant to a voxel, the algorithm selects the first one encountered in the iteration order [G].

## Subtopics

### [Natural Neighbor Interpolation](6494-natural-neighbor-interpolation.md)
Natural neighbor interpolation is a spatial interpolation method that determines the value of a query point based on the geometric relationship between its Voronoi cell and the Voronoi cells of its neighboring seed points. It solves the problem of creating smooth, continuous, and monotonic interpolation fields where each seed point exerts only local influence, ensuring that the original seed values remain unchanged. It is distinguished from linear or polynomial interpolation by its adaptive weighting scheme, which relies on the topology of the Voronoi diagram rather than fixed distance metrics or basis functions.

## Operating characteristics
*   **Time Complexity:**
    *   Pass 1 (Voronoi Diagram): $O(V \cdot N)$, where $V$ is the number of voxels in the customization volume and $N$ is the number of seed points [S1].
    *   Pass 2 (Customization Volume): $O(V^2)$, where $V$ is the number of voxels in the customization volume, as each work item iterates over all voxels in the resolution [S1].
*   **Memory Complexity:** $O(V + N)$. The Voronoi volume requires $V$ integers, and the seed points require $N$ structures [S1].
*   **Performance:** The method allows for interactive frame rates because the customization volume resolution is kept low (e.g., $64^3$) independent of the input volume size [S1]. Trilinear interpolation during rendering efficiently reconstructs values between voxels, minimizing the need for high-resolution customization data [S1].
*   **Strengths:**
    *   GPU-friendly: The discrete Voronoi calculation is highly parallelizable [S1].
    *   Low Memory Footprint: Low-resolution customization volume reduces VRAM usage [S1].
    *   Interactive: Enables real-time customization of transfer functions [S1].
*   **Limitations:**
    *   Approximation: The discrete Voronoi diagram is an approximation of the continuous diagram, which may introduce artifacts at cell boundaries [S1].
    *   Resolution Dependency: The quality of the customization depends on the chosen resolution [S1].
    *   Performance Overhead: The additional lookups and computations (such as the power function in natural neighbor interpolation) reduce the overall performance of the volume rendering pipeline [S1].

## Background
The method was introduced in the context of interactive position-dependent customization of transfer function classification parameters in volume rendering [S1]. It addresses the performance issues associated with calculating customization parameters for large volume datasets on the GPU [S1]. The approach builds on discretization techniques proposed by Park et al. [PLK∗06], adapting them for modern GPU compute shaders (OpenGL 4.3+) to exploit massive parallelism [S1]. By calculating the Voronoi diagram and customization volume in a lower resolution, the method achieves a balance between visual quality and interactive performance [S1].
