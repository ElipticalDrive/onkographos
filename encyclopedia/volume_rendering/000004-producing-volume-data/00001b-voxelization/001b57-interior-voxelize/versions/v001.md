# Interior Voxelize

Also called: point-in-mesh test, occupancy grid generation

## Overview
Interior Voxelize determines which voxels in a 3D grid lie inside a given mesh volume by sampling points within the grid cells and testing their containment against the mesh surface [S1, S2, unofficial]. It solves the problem of converting a polygonal surface representation into a binary volumetric occupancy field, distinguishing interior from exterior space [S1, unofficial]. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) which projects geometry onto a grid, or [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) which scans along axes, Interior Voxelize relies on direct geometric point-in-polyhedron queries, making it robust to complex topology but computationally heavier per voxel [S1, S2, unofficial].

## How it works
**Inputs:**
- A closed polygon mesh (vertices and triangles).
- A target grid resolution (integer, typically 32 or higher) [S2, unofficial].
- Optional: A bounding box for the grid; if not provided, the mesh's bounding box is used [S2, unofficial].

**Outputs:**
- A 3D boolean array (bitmap) of shape $(N, N, N)$ where $N$ is the resolution, indicating occupancy (true for interior, false for exterior) [S1, S2, unofficial].

**Data Structures:**
1.  **Mesh Spatial Index:** An AABB tree (e.g., `DMeshAABBTree3`) built from the input mesh triangles to accelerate ray/point intersection tests [S2, unofficial].
2.  **Grid Indexer:** A mapping structure (e.g., `ShiftGridIndexer3`) that converts discrete grid indices $(i, j, k)$ to continuous 3D world coordinates $(x, y, z)$ based on the bounding box minimum and cell size [S2, unofficial].
3.  **Bitmap:** A 3D boolean array of size $(numcells, numcells, numcells)$ [S2, unofficial].

**Steps:**
1.  **Compute Bounds:** Calculate the axis-aligned bounding box (AABB) of the input mesh. Let $B_{min}$ be the minimum corner and $B_{max}$ be the maximum corner [S2, unofficial].
2.  **Determine Cell Size:** Calculate the side length of a voxel cell. Let $L_{max} = \max(B_{max} - B_{min})$ be the maximum dimension of the bounding box. For a target resolution $N$ (e.g., 32), the cell size $h$ is:
    $$ h = \frac{L_{max}}{N} $$
    [S2, unofficial]
3.  **Initialize Indexer:** Create a grid indexer that maps grid index $(i, j, k)$ to world space. The world coordinate $v$ for index $(i, j, k)$ is:
    $$ v = B_{min} + (i + 0.5, j + 0.5, k + 0.5) \cdot h $$
    This centers the sample point within each voxel [S2, unofficial].
4.  **Sample Points:** Generate a set of 3D points corresponding to the center of each voxel in the grid. If using a differentiable or stochastic variant, noise may be added to break symmetry, but the standard deterministic method uses exact centers [S1, S2, unofficial].
5.  **Containment Test:** For each point $v$, query the mesh spatial index to determine if $v$ is inside the mesh. The spatial index uses a winding number or ray-casting algorithm internally to return a boolean `IsInside(v)` [S2, unofficial].
6.  **Populate Bitmap:** Set the voxel at grid index $(i, j, k)$ to `true` if `IsInside(v)` is true, and `false` otherwise [S2, unofficial].
7.  **Optional Tightening:** If the "tight" option is enabled, verify the center point of each voxel again and remove any voxels determined to be outside, though this is computationally expensive [S3, unofficial].

**Pseudocode:**
```python
def interior_voxelize(mesh, resolution=32):
    # 1. Build spatial index for fast containment queries
    # Assumes mesh has vertices V and faces F
    spatial_index = build_aabb_tree(mesh.vertices, mesh.faces)
    
    # 2. Compute bounding box
    bb_min = mesh.vertices.min(axis=0)
    bb_max = mesh.vertices.max(axis=0)
    max_dim = max(bb_max - bb_min)
    
    # 3. Calculate cell size
    cell_size = max_dim / resolution
    
    # 4. Initialize output bitmap
    # Shape is (resolution, resolution, resolution)
    occupancy_grid = np.zeros((resolution, resolution, resolution), dtype=bool)
    
    # 5. Iterate over all grid indices
    for i in range(resolution):
        for j in range(resolution):
            for k in range(resolution):
                # Calculate center of the voxel in world space
                # Using ShiftGridIndexer logic: origin + (index + 0.5) * cell_size
                x = bb_min[0] + (i + 0.5) * cell_size
                y = bb_min[1] + (j + 0.5) * cell_size
                z = bb_min[2] + (k + 0.5) * cell_size
                point = np.array([x, y, z])
                
                # 6. Check if point is inside the mesh
                # spatial_index.is_inside() typically uses winding number or ray casting
                is_inside = spatial_index.is_inside(point)
                
                occupancy_grid[i, j, k] = is_inside
                
    return occupancy_grid
```

**Parameters:**
- `resolution` ($N$): The number of voxels along the longest axis of the bounding box. Typical value: 32 [S2, unofficial]. Higher values increase accuracy but scale cubically in time and memory.
- `tight` (boolean): If true, performs an additional verification step to remove exterior voxels. Default: false [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Non-manifold Geometry:** Standard point-in-mesh tests may fail or behave unpredictably on non-manifold meshes. Methods like [Mesh Winding Number Voxelization](2328-mesh-winding-number-voxelization.md) are preferred for such cases as they handle holes and non-manifold edges more gracefully [S2, unofficial].
- **Performance:** The complexity is $O(N^3 \cdot T)$, where $T$ is the cost of the containment test. For high resolutions, this becomes prohibitive. [S3, unofficial] notes that the "tight" option is particularly time-consuming.
- **Precision:** Floating-point errors in coordinate mapping can cause boundary voxels to be misclassified. Using a robust spatial index (like an AABB tree with epsilon handling) is critical [S2, unofficial].

## Subtopics

### [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md)
Determines interior status by casting multiple random rays from each voxel center and counting intersections. It differs from [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) and [Front/Back Face Flagging](1506-front-back-face-flagging.md) by relying on statistical majority voting over randomized directions rather than deterministic axis-aligned rays or face orientation flags, making it robust against non-manifold geometry, broken meshes, and self-intersections where a single deterministic ray might fail.

### [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md)
Scans along a principal axis (typically Z) and fills intervals between front-facing and back-facing surface voxels. It differs from [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) by using deterministic scanline logic rather than probabilistic sampling, and from [Mesh Winding Number Voxelization](2328-mesh-winding-number-voxelization.md) by relying on explicit face orientation flags rather than topological winding counts.

### [Front/Back Face Flagging](1506-front-back-face-flagging.md)
Assigns a boolean orientation flag to voxels intersected by triangle surfaces to distinguish interior from exterior. It solves the problem of ambiguity in non-watertight or open meshes by tracking the direction of surface traversal relative to a specified filling direction. Unlike sibling methods that rely on ray-casting parity [1067-stochastic-ray-casting-voxelization.md], winding numbers [2328-mesh-winding-number-voxelization.md], or stencil buffer accumulation [3722-polyhedron-moment-integration-and-voxelization.md], this approach explicitly records whether a voxel's boundary triangle is front-facing or back-facing relative to a global vector.

### [Mesh Winding Number Voxelization](2328-mesh-winding-number-voxelization.md)
Determines the interior by evaluating the Mesh Winding Number (MWN) at sample points. Unlike [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) or [Front/Back Face Flagging](1506-front-back-face-flagging.md), which rely on ray intersection parity or face orientation, MWN provides a robust signed distance-like field that handles meshes with holes and non-manifold geometry gracefully. It yields an integer value for closed meshes and a smoothly diffusing value around open boundaries, allowing for consistent threshold-based classification.

### [Polyhedron Moment Integration and Voxelization](3722-polyhedron-moment-integration-and-voxelization.md)
Computes polynomial density moments of a convex polyhedron within a voxel grid by recursively splitting the polyhedron along its longest axis until it occupies single voxels, then integrating the polynomial density field over the resulting volume for each voxel. It differs from [Stochastic Ray-Casting Voxelization](1067-stochastic-ray-casting-voxelization.md) and [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) by providing exact analytic integration of density moments rather than stochastic or rasterization-based approximations, and from [Mesh Winding Number Voxelization](2328-mesh-winding-number-voxelization.md) by supporting arbitrary polynomial density orders (not just binary occupancy).

### [Point-Containment Voxelization](3882-point-containment-voxelization.md)
Converts a 3D solid model into a 3D grid by determining which voxels intersect the solid's volume. It achieves this by sampling the grid vertices and checking their containment against the solid's Boundary Representation (BRep). It is distinguished from sibling methods by its reliance on exact geometric containment queries for grid vertices rather than ray casting, winding numbers, or stochastic sampling.

## Operating characteristics
- **Time Complexity:** $O(N^3 \cdot T)$, where $N$ is the resolution and $T$ is the time for a single point-in-mesh query. With an AABB tree, $T$ is typically $O(\log F)$ where $F$ is the number of faces, but worst-case can be higher.
- **Memory Complexity:** $O(N^3)$ for the output bitmap. The spatial index requires $O(F)$ memory.
- **Performance:** For $N=32$, the grid has 32,768 voxels. If each containment test takes 10 microseconds, the total time is ~0.3 seconds. Performance degrades rapidly with higher resolutions (e.g., $N=128$ requires 64x more time). [S3, unofficial] warns that the "tight" post-processing step is time-consuming.
- **Strengths:** Simple to implement; robust to complex mesh topology if a robust point-in-polyhedron test (like winding number) is used; produces exact binary occupancy for watertight meshes.
- **Limitations:** Computationally expensive for high resolutions; sensitive to mesh quality (non-manifold geometry can cause errors in standard containment tests); does not inherently produce signed distance fields or density values without extension.
- **When to use:** Low-to-medium resolution occupancy grids; preprocessing for neural radiance fields or differentiable rendering where exact binary masks are needed; scenes with complex, non-manifold geometry where rasterization methods fail.
- **When not to use:** High-resolution requirements (use hierarchical or sparse methods); real-time applications requiring dynamic updates; meshes with significant non-watertight artifacts unless using winding number variants.

## Background
Originating from the need to convert 3D models into voxel-based representations for rendering and simulation, Interior Voxelize is a fundamental technique in computer graphics. The specific implementation using `DMeshAABBTree3` and `ShiftGridIndexer3` is documented in tutorials on 3D bitmaps and mesh winding numbers [S2, unofficial]. The method is widely used in differentiable volumetric rendering pipelines, where a differentiable voxelizer is required to backpropagate gradients from the volume to the mesh vertices [S1, unofficial]. It is also employed in voxelization tools for 3D printing and medical imaging, where accurate interior/exterior classification is critical [S3, unofficial].
