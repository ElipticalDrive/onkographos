# Single-pass GPU Solid Voxelization

Also called: DX10 voxelization, DX9 voxelization

## Overview
A GPU-based algorithm to voxelize solid geometry in a single pass, producing point-sampled or over/under-conservative results [S1]. It differs from boundary-only voxelization by producing a fully filled interior volume and from multi-pass methods by extracting up to 1024 layers in a single geometry pass [S1], while unlike [8, 10], it is accurate even if an arbitrary number of fragments fall in a single voxel and does not require front/back face separation [S1].

## How it works
**Inputs:** A watertight mesh (manifold or topologically coherent mesh not required) [S1].
**Outputs:** A 3D voxel grid representing the solid interior [S1].

**Data Structures:**
*   **Slicemap:** A 2D texture storing fragment data. In DX10, this supports multiple render targets (MRT) [S1]. In DX9, it uses color components [S1].
*   **Voxel Column:** A 32-bit integer (or bitset) representing occupancy for a column of voxels [S1].

**Steps:**
1.  **Rasterization:** Render the input mesh to the slicemap. Each fragment contributes to the voxel column corresponding to its screen-space position [S1].
2.  **Bitmask Accumulation:** Accumulate fragment bitmasks using bitwise XOR. This exploits the Jordan curve theorem: a point is interior if a ray from it intersects the surface an odd number of times [S1].
3.  **Symmetric Difference:** For intersecting watertight models, the algorithm computes the symmetric difference (hollow representation), not the union [S1]. This is consistent with the definition of watertight surfaces [S1].
4.  **Density Computation:** Compute density using a kernel of size $2^3$ [S1]. This is fast and memory efficient because all information is tightly packed [S1].

**Parameters:**
*   **Maximum layers per pass without MRT on DX9:** 32 [S1].
*   **Kernel size for density:** $2^3$ [S1].

**Edge Cases and Pitfalls:**
*   **DX9 without MRT:** Performance converges to ~23x speedup over [5] rather than 4x, possibly due to G6 MRT sweet spot [S1].
*   **DX9 Implementation:** Treats all four color components equally, reflecting vector capacities of older processors [S1]. It would not scale for DX10 hardware because a lookup texture for a 32-bit integer would need $2^{32}$ entries and not fit into GPU memory [S1]. Breaking integers into 16-bit parts would imply two lookups per channel, leading to 64 lookups per 1024-bit voxel column, making bitwise arithmetic more efficient [S1].
*   **DX10 Timings:** Depend solely on the resolution of the initial slicemap and include the reordering, which is not very expensive [S1].
*   **DX9 Timings:** Reordering is free, but slicemap content plays a role due to cache effects from dependent lookups [S1].
*   **Pseudocode:** Not provided in the sources.

## Subtopics

### [Single-pass Solid Voxelization via XOR Bitmask Accumulation](3325-single-pass-solid-voxelization-via-xor-bitmask-accumulation.md)
This method voxelize watertight models in a single GPU render pass by exploiting the Jordan curve theorem: a point is interior if a ray from it intersects the surface an odd number of times. It accumulates fragment bitmasks using bitwise XOR to determine voxel occupancy, distinguishing itself from boundary-only voxelization by producing a fully filled interior volume. It builds on [Single-pass GPU Solid Voxelization](3323-single-pass-gpu-solid-voxelization.md).

## Operating characteristics
**Time and Memory Complexity:**
*   **DX10 (G80) density computation timings:** 0.20 ms at $64^3$, 0.6 ms at $128^3$, 2.9 ms at $256^3$, 20.9 ms at $512^3$ [S1].
*   **DX9 density computation timings:** 0.28 ms at $256^3$, 0.9 ms at $512^3$, 6.5 ms at $1024^3$ [S1].
*   **DX10 speedup over [5]:** Up to >300x for complex models; ~20x for simple cube (12 triangles) [S1].
*   **DX9 speedup over [5]:** ~2x without MRT, converges to 23x for models up to 12,500 triangles [S1].

**Strengths and Limitations:**
*   **Strengths:** High speed for complex models due to multi-layer extraction per pass [S1]. Accurate even if arbitrary fragments fall in a single voxel [S1]. Does not require front/back face separation [S1].
*   **Limitations:** Fill-rate cost for fragment output and blending [S1]. Simple models (low geometric complexity, high fill-rate) are worst-case scenarios because standard rendering is very cheap [S1].

**When to use:**
*   When high-speed voxelization of complex watertight models is required [S1].
*   When MRT support is available (DX10) or when older cards without MRT are used (DX9) [S1].

**When not to use:**
*   When union of intersecting models is required (algorithm computes symmetric difference) [S1].
*   When manifold or topologically coherent mesh is not available (watertight input suffices, but non-watertight may produce unexpected results) [S1].

## Background
Originated in the paper "Single-pass GPU Solid Voxelization and Applications" [S1]. The approach is simple but efficient single-pass solutions were previously non-existent [S1]. It is appealing due to its accuracy and simplicity [S1].
