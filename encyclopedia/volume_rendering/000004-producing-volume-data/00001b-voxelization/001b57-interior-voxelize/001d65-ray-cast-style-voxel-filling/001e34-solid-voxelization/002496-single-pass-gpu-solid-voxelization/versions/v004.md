# Single-pass GPU Solid Voxelization

Also called: DX10 voxelization, DX9 voxelization

## Overview
Single-pass GPU Solid Voxelization is a GPU-based algorithm that voxelize solid geometry in a single render pass, producing point-sampled or over/under-conservative results [S1]. It solves the problem of efficiently converting watertight meshes into volumetric data by exploiting the Jordan Curve Theorem: a point is interior if a ray from it intersects the surface an odd number of times [S1]. Unlike [8, 10], this method is accurate even if an arbitrary number of fragments fall in a single voxel and does not require front/back face separation [S1]. It builds on [Solid Voxelization](1695-solid-voxelization.md) but achieves significant speedups by extracting multiple layers per pass [S1].

## How it works
**Inputs:** A watertight mesh (manifold or topologically coherent mesh not required, only watertightness) [S1].
**Outputs:** A 3D texture (or volume) where each voxel is marked as interior or exterior based on the symmetric difference of intersecting models [S1].

**Data Structures:**
* **Slicemap:** A 2D texture mapping screen-space pixels to depth intervals. For DX10, this includes reordering information [S1]. For DX9, the slicemap content affects cache performance due to dependent lookups [S1].
* **Bitmask Texture:** A small 1D texture used to transform depth extremes into bitmasks [S1]. This avoids allocating large 2D textures, which are expensive on DX10 hardware [S1].
* **Frame Buffer:** Stores the accumulated voxel state [S1]. For DX9 without MRT, all four color components are treated equally [S1].

**Parameters:**
* **Maximum layers per pass (DX9 without MRT):** 32 [S1].
* **Maximum layers per pass (DX10):** Up to 1024 [S1].
* **Filtering Kernel:** Box-filtering of size $2^3$ is used for density estimation [S1].

**Steps:**
1. **Render Slicemap:** Project the mesh onto the screen to generate depth intervals for each pixel. This defines the "column" of voxels to be processed [S1].
2. **Fragment Shader Execution:** For each fragment generated by rasterization:
   a. Retrieve the depth interval from the slicemap [S1].
   b. Transform the near and far depth extremes into bitmasks using the 1D bitmask texture [S1].
   c. To handle conservative voxelization, shift the farther depth value by one voxel distance and leave the near value unmodified [S1].
   d. Compute the XOR of the corresponding bitmasks in the shader (or subtraction for older cards) to activate voxels between the extents [S1].
   e. Accumulate the result into the frame buffer using an OR operation (not XOR) to create the conservative boundary, while keeping the solid voxelization in the framebuffer before adding the hull [S1].
3. **Interior Determination:** The XOR accumulation effectively computes the symmetric difference for intersecting watertight models, resulting in a hollow representation for concentric boxes rather than a union [S1]. The interior is defined by the Jordan Theorem [S1].
4. **Density Estimation (Optional):** If a density representation is needed, apply a box-filtering kernel of size $2^3$ to the binary grid [S1]. For DX9, allocating a 32-bit integer lookup texture would require $2^{32}$ entries, which does not fit in GPU memory; breaking integers into 16-bit parts implies 64 lookups per voxel column, making bitwise arithmetic more efficient [S1].

**Pseudocode:**
```python
def sample_texture(tex, coord):
    # Standard texture sampling operation
    return tex[coord]

def voxelize_fragment(near_depth, far_depth, voxel_size, bitmask_texture, frame_buffer, pixel_coord):
    # Shift farther depth by one voxel distance for conservative filling
    shifted_far = far_depth + voxel_size
    # Transform depth extremes to bitmasks using the 1D bitmask texture
    near_bitmask = sample_texture(bitmask_texture, near_depth)
    far_bitmask = sample_texture(bitmask_texture, shifted_far)
    # Compute XOR to activate voxels between extents
    column_mask = near_bitmask ^ far_bitmask
    # Accumulate into frame buffer using OR blending
    current_buffer = sample_texture(frame_buffer, pixel_coord)
    new_buffer = current_buffer | column_mask
    return new_buffer

def compute_density(binary_volume, kernel_size=2):
    # Apply box-filtering kernel of size 2^3
    # Standard 3D box filter convolution
    density_volume = binary_volume.copy()
    for z in range(binary_volume.shape[0]):
        for y in range(binary_volume.shape[1]):
            for x in range(binary_volume.shape[2]):
                # Box filter over neighborhood
                density_volume[z, y, x] = sum(binary_volume[max(0,z-kernel_size):min(binary_volume.shape[0],z+kernel_size+1),
                                                          max(0,y-kernel_size):min(binary_volume.shape[1],y+kernel_size+1),
                                                          max(0,x-kernel_size):min(binary_volume.shape[2],x+kernel_size+1)])
    return density_volume
```

**Edge Cases and Pitfalls:**
* **Intersecting Models:** If two watertight models intersect, the algorithm assumes the symmetric difference, not the union [S1].
* **DX9 Performance:** Without MRT support, DX9 still extracts 32 layers per pass, but performance converges to ~23x speedup over [5] rather than 4x, possibly due to G6 MRT sweet spot [S1].
* **DX9 Memory:** For DX9, allocating a 32-bit integer lookup texture would require $2^{32}$ entries, which does not fit in GPU memory; breaking integers into 16-bit parts implies 64 lookups per voxel column, making bitwise arithmetic more efficient [S1].

## Subtopics

### Conservative Solid Voxelization
A technique to fill voxels that are partially interior, addressing the issue where thin geometry misses voxel centers and is annihilated by XOR [S1]. It renders the scene once with the standard single-pass solid voxelization algorithm, then performs a conservative boundary voxelization [38] and adds it to the same texture [S1]. Implementation uses a small 1D bitmask texture to transform depth extremes into bitmasks, shifting the farther depth value by one voxel distance [S1]. The XOR of bitmasks activates voxels between extents, blended with an OR operation to create the conservative boundary [S1]. To get conservative interior only (no boundary), subtract the conservative boundary voxelization from the conservative overestimate using XOR: $Result = ConservativeInterior \text{ XOR } ConservativeBoundary$ [S1].

## Operating characteristics
**Time Complexity:** The method achieves significant speedups over previous work [5] [S1]. For DX10, speedup is up to >300x for complex models and ~20x for a simple cube (12 triangles) [S1]. For DX9, speedup is ~2x without MRT, converging to 23x for models up to 12,500 triangles [S1].
**Memory Complexity:** Memory efficient due to tight packing of information [S1]. Uses a small 1D bitmask texture instead of large 2D textures [S1].
**Measured Performance:**
* **DX10 (G80) Density Computation:** 0.20 ms at $64^3$, 0.6 ms at $128^3$, 2.9 ms at $256^3$, 20.9 ms at $512^3$ [S1].
* **DX9 Density Computation:** 0.28 ms at $256^3$, 0.9 ms at $512^3$, 6.5 ms at $1024^3$ [S1].
**Strengths:** High speed, accuracy even with arbitrary fragments per voxel, no front/back face separation needed, works with non-manifold watertight meshes [S1].
**Limitations:** DX9 bitwise arithmetic does not scale for DX10 hardware because a 32-bit integer lookup texture would require $2^{32}$ entries, which does not fit in GPU memory [S1].

## Background
Originated in the paper "Single-pass GPU Solid Voxelization and Applications" [S1]. It was developed to provide an efficient single-pass solution for solid voxelization, which was previously lacking in efficiency [S1]. The method is useful for applications like conservative visibility testing [7] and density/normal estimation [S1]. It builds on the concept of solid voxelization [1695-solid-voxelization.md] but optimizes it for GPU architectures, particularly DX10 and DX9 [S1].
