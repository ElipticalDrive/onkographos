# Single-pass Solid Voxelization via XOR Bitmask Accumulation

Also called: Bitmask accumulation voxelization, Single-pass Solid Voxelization, XOR-based solid voxelization

## Overview
This method voxelize watertight models in a single GPU render pass by exploiting the Jordan curve theorem: a point is interior if a ray from it intersects the surface an odd number of times [S1]. It accumulates fragment bitmasks using bitwise XOR to determine voxel occupancy, distinguishing itself from boundary-only voxelization by producing a fully filled interior volume [S1]. It builds on [Single-pass GPU Solid Voxelization](3323-single-pass-gpu-solid-voxelization.md) [S1].

## How it works
**Inputs:** A watertight 3D mesh; a voxel grid resolution $(W, H, D)$; a camera view direction aligned with the voxelization axis (typically Z) [S1].
**Outputs:** A 3D texture or texture array representing the solid voxel grid, where each voxel is a single bit (0 for exterior, 1 for interior) [S1].

**Data Structures:**
*   **Framebuffer:** A render target with a single-bit color channel per voxel slice. In DirectX 10/OpenGL, this is a texture array or 3D texture [S1]. In DirectX 9, texture tiling is used to simulate this storage [S1].
*   **Bitmask Texture:** A small 1D texture containing precomputed bitmasks [S1]. The index into this texture corresponds to the fragment's depth (voxel index) [S1].

**Algorithm Steps:**
1.  **Initialization:** Clear the framebuffer to all zeros (exterior) [S1].
2.  **Rendering Pass:** Render the mesh from the chosen view direction [S1].
3.  **Fragment Shader Execution:** For each fragment generated by rasterization:
    a.  Compute the fragment's depth $d$, representing the voxel index $k$ along the view axis [S1].
    b.  Generate a bitmask $M$ where all bits corresponding to voxel indices $j < k$ are set to 1, and bits for $j \ge k$ are 0 [S1]. This is typically done via a lookup in the 1D bitmask texture using $d$ as the coordinate [S1].
    c.  Accumulate $M$ into the framebuffer's current value for the corresponding $(x, y)$ column using a bitwise XOR operation [S1].
4.  **Completion:** After rendering all fragments, the framebuffer contains the final voxelization [S1]. A voxel at index $k$ is interior if the accumulated bit is 1 [S1].

**Formulas:**
A voxel at index $k$ is inside the model if the number of fragments $n$ in front of it is odd [S1]:
$$ n \pmod 2 = 1 $$
This is computed via XOR accumulation over all fragments $t$:
$$ \bigoplus_{t=0}^{n} 1 $$
where $\oplus$ denotes the XOR operation [S1].

**Parameters:**
*   **Bitmask Texture Size:** Small 1D texture, size equal to the voxel grid depth $D$ [S1].
*   **Depth Clamp:** Must be enabled to prevent near/far plane clipping [S1].

**Edge Cases and Pitfalls:**
*   **Watertightness:** The method relies on the Jordan curve theorem. Models with cracks, inner walls separating volumes, or nested shells (where the inner shell is considered empty) are not watertight under this definition and produce incorrect interiors [S1].
*   **Clipping:** Polygons must not be clipped by the near and far planes of the camera. Use Depth Clamp (e.g., NV_depth_clamp extension) to clamp depth values to the frustum, ensuring all intersections are counted [S1].
*   **Voxel Shift:** The voxel grid is shifted by half a voxel along the Z-axis because the bitmask is based on the voxel the fragment falls into [S1]. This can be counteracted by adding half a voxel to the fragment's distance in the shader [S1].
*   **API Limitations:** DirectX does not support bitwise blending operations needed for correct accumulation [S1]. For DX9, texture tiling is required [S1].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Initialization
framebuffer = [[0] * depth for _ in range(width * height)]
bitmask_texture = [(1 << i) - 1 for i in range(depth)]

# Rendering Pass
# Standard GPU rasterization produces fragments with screen-space coordinates (x, y) and depth z [G]
# API requires: enable_depth_clamp() and set_blend_operation(xor) [G]

for fragment in rasterize(mesh):
    depth_index = max(0, min(depth - 1, fragment.z_voxel_index))
    mask = bitmask_texture[depth_index]
    idx = fragment.y * width + fragment.x
    framebuffer[idx] ^= mask
```

### Subtopics
**Boundary Voxelization**
Outputs only the surface voxels. Simpler but does not provide interior data [G]. Choose when memory is constrained and only surface representation is needed. [Boundary Voxelization](boundary-voxelization.md)

**Multi-pass Solid Voxelization**
Uses multiple passes to fill interiors, often allowing for more complex geometry handling but at higher computational cost [G]. Choose when single-pass performance is not critical or geometry is non-watertight. [Multi-pass Solid Voxelization](multi-pass-solid-voxelization.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ fragments processed in a single pass [S1].
*   **Memory Complexity:** One bit per voxel in the grid, stored in a texture array or 3D texture [S1].
*   **Performance:** Single-pass rasterization with bitwise accumulation [S1].
*   **Strengths:** Fast, single-pass, produces solid interiors, no aliasing from XOR operator [S1].
*   **Limitations:** Requires watertight geometry; sensitive to cracks and nested shells; requires Depth Clamp; limited to view-aligned voxelization; DX9 requires texture tiling [S1].
*   **When to Use:** When fast voxelization of watertight models is needed and view-aligned grids are acceptable [S1].
*   **When Not to Use:** For non-watertight models, models with internal voids that should be filled, or when arbitrary voxel grid orientations are required [G].
