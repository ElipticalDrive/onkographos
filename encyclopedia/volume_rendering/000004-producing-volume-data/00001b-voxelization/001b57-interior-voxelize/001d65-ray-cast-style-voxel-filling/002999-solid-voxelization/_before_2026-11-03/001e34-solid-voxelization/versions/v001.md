# Solid Voxelization

Also called: BfsSolid, Bulk Voxelization, Two-Level Model Voxelization

## Overview
Solid Voxelization fills the interior volume of a closed mesh with voxels, producing a dense volumetric representation rather than a surface shell. It builds on [Ray-Cast Style Voxel Filling](1502-ray-cast-style-voxel-filling.md) by first identifying surface voxels and then propagating that information into the interior. It is distinguished from [Slice Filling (Simple)](1691-slice-filling-simple.md) by its use of a two-level grid model and explicit boundary checks (often via BFS or filter-and-refine) to handle non-watertight inputs or complex topologies more robustly than simple axis-aligned scanning [S1, S2, unofficial].

## How it works
The method typically operates in two phases: surface identification (often GPU-accelerated) and interior filling (CPU or GPU-based BFS or filter-and-refine). The following implementation details are derived from the primary GPU/CPU hybrid implementation [S1, unofficial] and the optimized filter-and-refine variant [S2, unofficial].

### Inputs and Outputs
- **Input**: A triangle mesh defined by vertices and indices.
- **Output**: A 3D boolean grid (voxel array) where `true` indicates a solid voxel inside the mesh.

### Data Structures
**Mesh Data (CPU/GPU Transfer)** [S1, unofficial]:
- `MeshDataDevice`:
  - `bbox[6]`: `float` array, min/max x, y, z of the mesh bounding box.
  - `vertices`: Array of `Vector3Df` (x, y, z).
  - `triangles`: Array of `Triangle` structs.
  - `trianglesNo`: `int*`, count of triangles.
  - `_bottom`, `_top`: `Vector3Df`, bounding box corners of individual triangles.
- `Triangle`:
  - `_idx1`, `_idx2`, `_idx3`: `int`, indices into `vertices`.
  - `_bottom`, `_top`: `Vector3Df`, local bounding box.

**Voxel Grid** [S1, S2, unofficial]:
- `voxels_`: Bitset array representing the final solid state.
- `voxels_buffer_`: Bitset array used during computation (e.g., BFS queue or filter results).
- `voxel_metas_`: Optional metadata array (e.g., `Surface()` flag) [S1, unofficial].
- `kBatchSize`: Constant for bitset indexing (e.g., 64 or 32, depending on implementation) [S2, unofficial].

### Parameters
- `gridVoxelSize`: Physical size of one voxel side [S1, unofficial].
- `num_thread`: Number of threads for parallel execution [S1, S2, unofficial].
- `WithMeta`: Boolean flag to enable metadata updates (solid marking) [S1, unofficial].

### Algorithm Steps

#### Phase 1: Surface Voxelization (GPU) [S1, unofficial]
1. **Preprocessing**: Compute `globalTranslation` from `meshData->bbox[0..2]`.
2. **Grid Setup**: Compute grid dimensions using `ops::computeTwoLevelSizes(meshData->bbox, gridVoxelSize)`.
3. **Memory Allocation**: Allocate `gpuData` of type `MeshDataDevice` on the GPU.
4. **Data Transfer**: Copy `meshData` to `gpuData` using `copyMeshData2Device->copyData`.
5. **Kernel Launch**: Launch `solidVoxelGpu` with `numBlocks = ceil(totNumThreads / 256)` and `numThreads = 256`, where `totNumThreads` equals the number of triangles.

**Kernel Logic (`solidVoxelGpu`)** [S1, unofficial]:
For each triangle thread `thread_id`:
1. Retrieve triangle vertices `V0, V1, V2` relative to `meshBbox`.
2. Compute triangle bounding box `triBbox`.
3. Call `voxelizeTriangleSolidGpu(grid, meshBbox, triBbox, V0, V1, V2, true, thread_id)`.

**Triangle Voxelization Logic (`voxelizeTriangleSolidGpu`)** [S1, unofficial]:
For each voxel `(x, y, z)` in the triangle's bounding box:
1. **Edge Normal Calculation**:
   - Compute edge vectors `e0, e1, e2`.
   - Compute 2D normals for XY, YZ, and ZX planes:
     $$n_{xy\_e0} = (-e0.y, e0.x)$$
     $$n_{zx\_e0} = (-e0.x, e0.z)$$
     $$n_{yz\_e0} = (-e0.y, e0.z)$$
   - **Normal Flipping**:
     - If $n.z < 0$, flip $n_{xy\_e0}, n_{xy\_e1}, n_{xy\_e2}$.
     - If $n.y < 0$, flip $n_{zx\_e0}, n_{zx\_e1}, n_{zx\_e2}$.
2. **Distance Calculation**:
   - Compute distances for XY plane:
     $$d_{xy\_e0} = -\text{dot2D}(n_{xy\_e0}, (v0.x, v0.y)) + \max(0, \delta_p.x \cdot n_{xy\_e0}.x) + \max(0, \delta_p.y \cdot n_{xy\_e0}.y)$$
   - Compute distances for XZ plane:
     $$d_{xz\_e0} = -\text{dot2D}(n_{zx\_e0}, (v0.z, v0.x)) + \max(0, \delta_p.x \cdot n_{zx\_e0}.x) + \max(0, \delta_p.z \cdot n_{zx\_e0}.y)$$
   - Compute distances for YZ plane (similar to XY).
3. **Point-in-Triangle Test**:
   - For a voxel center $p = (x \cdot \text{voxelSize}, y \cdot \text{voxelSize}, z \cdot \text{voxelSize})$:
     - Check YZ plane:
       $$\text{cond1} = (\text{dot2D}(n_{yz\_e0}, p_{yz}) + d_{yz\_e0} > 0) \lor (\text{dot2D}(n_{yz\_e0}, p_{yz}) + d_{yz\_e0} == 0 \land (n_{yz\_e0}.x > 0 \lor (n_{yz\_e0}.x == 0 \land n_{yz\_e0}.y < 0)))$$
       (Repeat for edges 1 and 2).
     - If not all conditions met, continue.
     - Check XY plane:
       $$\text{dot2D}(n_{xy\_e0}, p_{xy}) + d_{xy\_e0} < 0 \implies \text{continue}$$
       (Repeat for edges 1 and 2).
     - Check XZ plane:
       $$\text{dot2D}(n_{zx\_e0}, p_{zx}) + d_{xz\_e0} < 0 \implies \text{continue}$$
       (Repeat for edges 1 and 2).
     - Final check:
       $$n \cdot p = \text{dot}(n, p)$$
       $$\text{if } ((n \cdot p + d1) \cdot (n \cdot p + d2) > 0) \implies \text{continue}$$
   - If all tests pass, flip the bit in `grid->vTable1` at location $x + y \cdot \text{gridSizeY} + z \cdot \text{gridSizeY} \cdot \text{gridSizeZ}$.

#### Phase 2: Interior Filling (CPU/GPU Hybrid) [S1, S2, unofficial]

**Variant A: BFS with Two-Level Model [S1, unofficial]**
1. **Launch Fill Kernel**: Launch `fillBulkVoxelGpu` with `totNumThreads = gridSize^2`.
   - For each thread `i_thr` (representing a Y-slice):
     - Count surface voxels in the slice.
     - Store their X-coordinates in `locRastPoints`.
     - For each pair of adjacent surface voxels, fill the bits between them in `vTableBulk`.
2. **BFS Initialization**:
   - Select a `start_index` (e.g., a known exterior voxel or the first empty voxel).
   - Call `BfsSolid(start_index)`.
3. **BFS Execution (`BfsSolid`)** [S2, unofficial]:
   - Initialize queue with `start_index`.
   - While queue not empty:
     - Pop `voxel_index`.
     - Load `tmp = voxels_[index/kBatchSize] | voxels_buffer_[index/kBatchSize]`.
     - If `GETBIT(tmp, voxel_index)` is true, skip.
     - Else, `SETBIT(voxels_buffer_, voxel_index)`.
     - Convert `voxel_index` to `top_voxel` (Vec3f).
     - For each of 6 neighbors:
       - If `InRange(newVoxel, mesh_vox_lb, mesh_vox_ub)` and bit not set in `tmp`:
         - Push neighbor to queue.
4. **Final Inversion**:
   - Iterate `i` from 0 to `compressed_total_size - 1`.
   - Update `voxels_[i] = voxels_buffer_[i] ^ (~0)`. This inverts the buffer to mark interior voxels.
5. **Metadata Update (Optional)** [S1, unofficial]:
   - If `WithMeta()`, iterate all voxels. If `GETBIT` is true and `Surface()` is false, call `SetSolid()`.

**Variant B: Filter-and-Refine [S2, unofficial]**
1. **Filter Step**:
   - For each axis (X, Y, Z):
     - Fix the other two coordinates.
     - Enumerate voxels along the axis.
     - If a voxel is occupied (surface), stop filling in that direction.
     - Mark all visible voxels as "filled" in a temporary buffer.
2. **Refine Step**:
   - Identify "holes": voxels not marked as visible along any axis.
   - Perform standard flood fill (BFS) only on these holes.
3. **Merge**: Combine surface voxels, filter-filled voxels, and hole-filled voxels into the final solid grid.

### Edge Cases and Pitfalls
- **Planar Test Precision**: When $\text{dot}(n, p) + d = 0$, inclusion is determined by normal direction: $n.x > 0$ or ($n.x = 0$ and $n.y < 0$) [S1, unofficial].
- **Normal Flipping**: Incorrect handling of negative normal components ($n.z < 0$ or $n.y < 0$) leads to incorrect edge normal signs and false negatives/positives [S1, unofficial].
- **Holes in Filter Step**: The filter step alone does not fill the entire interior; holes remain for voxels occluded from all axis-aligned views [S2, unofficial].
- **Non-Watertight Meshes**: Basic flood fill may fail on non-watertight meshes if the exterior is not properly defined. The filter-and-refine method or explicit exterior marking is required [S2, unofficial].

## Subtopics

### Solid Voxelization via Filter-and-Refine
A technique to fill the interior of a mesh using a filter-and-refine strategy to optimize basic flood fill, avoiding the need for watertight meshes [S2, unofficial]. It uses a filter step to fill voxels visible along each axis, followed by a refine step to flood fill remaining "holes" [S2, unofficial]. Advantage over basic flood fill is efficiency due to lightweight filter operations [S2, unofficial]. Time complexity is $O(n)$ where $n$ is the total number of voxels in the bounding box [S2, unofficial].

## Operating characteristics
- **Time Complexity**:
  - Surface Voxelization: $O(m \cdot c)$, where $m$ is the number of triangles and $c$ is the number of voxels in the triangle's bounding box or constant overhead [S2, unofficial].
  - Interior Filling (BFS/Filter): $O(n)$, where $n$ is the total number of voxels in the mesh bounding box [S2, unofficial].
- **Memory Complexity**: $O(n)$ for the voxel grid and bitsets [S1, S2, unofficial].
- **Performance**: GPU-accelerated surface voxelization provides significant speedup for high triangle counts [S1, unofficial]. The filter-and-refine method is faster than basic BFS for large meshes with few internal holes [S2, unofficial].
- **Strengths**: Handles non-watertight meshes (with filter-and-refine), efficient parallelization on GPU [S1, S2, unofficial].
- **Limitations**: Requires careful handling of edge cases in triangle-voxel intersection [S1, unofficial]. BFS can be slow for meshes with many internal holes if not optimized [S2, unofficial].

## Background
Solid Voxelization is a fundamental technique in computer graphics for converting polygonal meshes into volumetric data for simulation, rendering, and 3D printing. The GPU-based implementation described in [S1, unofficial] is part of a broader mesh voxelization toolkit. The filter-and-refine optimization [S2, unofficial] addresses the limitations of basic flood fill, particularly for non-watertight meshes.
