# Morphological Dilation via Bit-Parallel Leaf Influence

Also called: Hierarchical bit-parallel dilation, Leaf-level Neighbor Influence Masks

## Overview
This method expands the topology of a sparse voxel grid by determining which leaf nodes must be materialized based on the active voxels within existing leaves, using bitwise operations on packed occupancy masks to avoid expensive tree traversals [S1, unofficial]. It sets itself apart from dense grid morphological operations by operating directly on the sparse hierarchy's leaf structure, and from other sparse methods by decoupling topological expansion (which leaf nodes exist) from voxel-level population (which voxels are active) to minimize global memory contention [S1, unofficial].

## How it works
**Inputs:**
- Source sparse voxel grid (compliant with NanoVDB specification).
- Dilation radius $r$ (typically $r=1$ for a $3 \times 3 \times 3$ stencil).
- CUDA device context.

**Outputs:**
- Dilated sparse voxel grid topology (updated `upperMasks` and `lowerMasks`).
- Dilated voxel values (via separate sidecar update, not detailed here).

**Data Structures:**
- `Mask<3>`: An 8x8x8 voxel occupancy mask bit-packed into eight `uint64_t` variables. Each `uint64_t` represents a slice of the 8x8x8 volume [S1, unofficial].
- `Mask<4>`: A 16x16x16 leaf-node occupancy mask (representing the children of a lower internal node) bit-packed into 16 `uint64_t` variables [S1, unofficial].
- `offsetMasks`: An array of 27 `Mask<4>` bitmaps, one for each neighbor offset in a $3 \times 3 \times 3$ stencil.
- `resultMasks`: An array of 27 `Mask<4>` bitmaps, one for the central lower node and one for each of its 26 neighbors.

**Steps:**

1.  **Leaf-Level Neighbor Influence Mask Computation:**
    For each leaf node, a single CUDA thread determines if its active voxels require materializing any of its 26 leaf neighbors.
    -   For a standard $3 \times 3 \times 3$ box dilation ($r=1$), the influence is confined to the immediate $3 \times 3 \times 3$ cluster of leaf neighbors [S1, unofficial].
    -   Compute a 27-bit influence mask per leaf. This is done by combining slices of the `Mask<3>` via bitwise OR and isolating the "faces" of the 8x8x8 volume via bitwise AND with predetermined masks. A bit set in the 27-bit mask indicates that the corresponding neighbor leaf node must be materialized [S1, unofficial].
    -   Note: For any stencil with radius $r \le 8$, the influence of an 8x8x8 leaf node is strictly confined to its immediate $3 \times 3 \times 3$ cluster of leaf neighbors [S1, unofficial].

2.  **Leaf-Major to Tap-Major Transposition:**
    To avoid high contention from irregular atomic updates, transpose the influence masks from shared memory.
    -   **Leaf-Major (Scatter):** Each leaf thread updates 27 "taps" (neighbor offsets).
    -   **Tap-Major (Gather):** The lower internal node computes 27 uniform spatial shifts.
    -   Transpose the grid-of-stencils (leaf-major) into a stencil-of-grids (tap-major). Each grid is encoded as a `Mask<4>` [S1, unofficial].
    -   At the warp level, use `CUB::WarpReduce` to aggregate influence bits across lanes. Tally the "votes" of 32 leaves into a single bit-parallel write to produce the `offsetMasks` [S1, unofficial]. These `offsetMasks` represent the collective topological footprint of the lower internal node for every neighbor offset.

3.  **Warp-Collective Stencil Convolution:**
    Combine the 27 `offsetMask` bitmaps to compute the leaf nodes that should be marked active.
    -   Implement a warp-level operator `MaskShift`: a 3-dimensional bit shift on a `Mask<4>` with compile-time signed shift distances. This uses warp-level shuffle and rotation instructions to exploit bit-level parallelism [S1, unofficial].
    -   Accumulate the result by shifting each `offsetMask` by its own tap offset $(dx, dy, dz)$ and combining the shifted masks with a bitwise OR. A bit set at leaf slot $i$ of tap $(dx, dy, dz)$ indicates that slot $i + (dx, dy, dz)$ must be materialized [S1, unofficial].
    -   Bits displaced past the $16^3$ extent of the lower node are accumulated into the mask of the corresponding neighboring lower node.
    -   The kernel yields 27 `resultMasks`: one for the central lower node and one for each of its 26 neighbors [S1, unofficial].

4.  **Global Atomic Merging:**
    Commit the 27 resulting neighbor masks to global scratchpads.
    -   For any `resultMask` containing active bits, the thread probes the `dilatedRoot` to find the target tile.
    -   Use `atomicOr` to update `upperMasks` and `lowerMasks` in the global scratchpads. This "blackboard" approach allows thousands of threads to concurrently contribute to the new topology, which is then finalized via a prefix-sum pipeline [S1, unofficial].

5.  **Voxel Mask Reconstruction:**
    After the topology is established, reconstruct the active voxel masks.
    -   Every leaf node composes its `valueMask` (a bit-encoded `Mask<3>`) by fetching the `valueMasks` of neighboring leaf nodes from the source topology and combining them with bit-parallel shifts [S1, unofficial].

**Pseudocode:**

```python
# Assumes CUDA-like parallel execution model

def compute_leaf_influence_mask(leaf_mask: Mask3, stencil_radius: int = 1) -> uint64_t:
    """
    Computes a 27-bit influence mask for a leaf node.
    leaf_mask: Mask3, 8x8x8 occupancy packed in 8 uint64_t.
    Returns: uint64_t where each bit corresponds to a neighbor in 3x3x3 grid.
    """
    # Predetermined masks for isolating faces of 8x8x8 volume
    # These are compile-time constants derived from the stencil geometry
    face_masks = get_predetermined_face_masks() 
    
    # Combine slices via bitwise OR and isolate faces via bitwise AND
    # This yields a 27-bit influence mask per leaf
    influence = 0
    for i in range(27):
        # Determine which voxels in the leaf contribute to neighbor i
        # This involves shifting and masking the leaf_mask slices
        # Simplified logic:
        voxel_contributions = extract_voxel_contributions(leaf_mask, i, stencil_radius)
        if any(voxel_contributions):
            influence |= (1 << i)
    return influence

def transpose_leaf_major_to_tap_major(leaf_influence_masks: List[uint64_t], warp_size: int = 32) -> List[Mask4]:
    """
    Transposes leaf-major influence stencils to tap-major offset masks.
    leaf_influence_masks: List of 27 uint64_t per leaf, for all leaves in a lower node.
    Returns: List of 27 Mask4 (offsetMasks).
    """
    # Initialize 27 offsetMasks (Mask4, 16x16x16 leaf extent)
    offset_masks = [Mask4() for _ in range(27)]
    
    # Process leaves in warps
    for warp_start in range(0, len(leaf_influence_masks), warp_size):
        warp_leaves = leaf_influence_masks[warp_start : warp_start + warp_size]
        
        # Use CUB::WarpReduce to aggregate influence bits across lanes
        # Tally votes of 32 leaves into a single bit-parallel write
        for tap_idx in range(27):
            # Aggregate bits for this tap across the 32 leaves
            aggregated_bits = warp_reduce_bits([leaf[tap_idx] for leaf in warp_leaves])
            # Write to the corresponding offsetMask
            offset_masks[tap_idx].set_bits(aggregated_bits, warp_start // warp_size)
            
    return offset_masks

def warp_collective_stencil_convolution(offset_masks: List[Mask4]) -> List[Mask4]:
    """
    Combines offset masks to compute active leaf nodes.
    Returns: List of 27 resultMasks (one for central node, 26 for neighbors).
    """
    result_masks = [Mask4() for _ in range(27)]
    
    # Define tap offsets for 3x3x3 stencil
    tap_offsets = get_3x3x3_offsets()
    
    for tap_idx, offset in enumerate(tap_offsets):
        # Shift the offsetMask by its tap offset
        shifted_mask = mask_shift(offset_masks[tap_idx], offset)
        
        # Combine with bitwise OR into the corresponding resultMask
        # Bits displaced past 16^3 extent go to neighbor resultMasks
        for neighbor_idx in range(27):
            # Determine if shifted bits fall into neighbor_idx's region
            # This involves checking bounds and shifting into the correct resultMask slot
            bits_for_neighbor = extract_bits_for_neighbor(shifted_mask, neighbor_idx, offset)
            result_masks[neighbor_idx] |= bits_for_neighbor
            
    return result_masks

def global_atomic_merging(result_masks: List[Mask4], dilated_root: SparseGrid, scratchpads: Dict[str, List[Mask4]]):
    """
    Commits result masks to global scratchpads using atomicOr.
    """
    for neighbor_idx, result_mask in enumerate(result_masks):
        if result_mask.has_active_bits():
            # Probe dilatedRoot to find target tile
            target_tile = find_target_tile(dilated_root, neighbor_idx)
            
            # Update upperMasks and lowerMasks in global scratchpads
            atomic_or_update(scratchpads, target_tile, result_mask)

def voxel_mask_reconstruction(source_grid: SparseGrid, dilated_topology: SparseGrid) -> SparseGrid:
    """
    Reconstructs voxel value masks by fetching from source topology.
    """
    # For each leaf in dilated_topology
    for leaf in dilated_topology.leaves():
        # Fetch valueMasks of neighboring leaf nodes from source_grid
        neighbor_value_masks = fetch_neighbor_value_masks(source_grid, leaf)
        
        # Combine them with bit-parallel shifts to compose leaf's valueMask
        leaf.value_mask = combine_value_masks(neighbor_value_masks)
        
    return dilated_topology
```

**Parameters:**
- Dilation radius $r$: Typically 1 ($3 \times 3 \times 3$ stencil). For $r \le 8$, influence is confined to immediate $3 \times 3 \times 3$ leaf neighbors [S1, unofficial].

**Edge Cases and Pitfalls:**
- Precision: Bit-packing relies on exact `uint64_t` alignment and shift operations. Incorrect shift distances can lead to data corruption [S1, unofficial].
- Boundaries: Bits displaced past the $16^3$ extent of a lower node must be correctly accumulated into the mask of the corresponding neighboring lower node. Failure to do so results in lost topology [S1, unofficial].
- Degenerate Input: Empty leaves or leaves with no active voxels produce zero influence masks, which should be handled efficiently to avoid unnecessary atomic operations [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by the leaf-level influence computation and the global atomic merging. The bit-parallel nature reduces the constant factor significantly compared to tree traversals.
- **Memory Complexity:** Requires scratchpads for `upperMasks` and `lowerMasks` during the atomic merging phase. The `offsetMasks` and `resultMasks` are held in shared memory or registers during warp-level processing.
- **Measured Performance:** Topological updates typically complete in less time than streaming the data payload through memory, allowing for a separate sidecar update operator [S1, unofficial].
- **Strengths:** Avoids expensive tree traversals for neighbor access. Decouples topology from voxel population. Efficient use of GPU parallelism via warp-level operations.
- **Limitations:** Requires significant shared memory for the transposition step. Atomic operations can cause contention if not managed carefully (mitigated by the tap-major transposition).
- **When to use:** When performing morphological dilation on large sparse voxel grids on a GPU, especially when the dilation radius is small ($r \le 8$).
- **When not to use:** For dense grids (use dense convolution), or for very large dilation radii where the influence extends beyond immediate leaf neighbors (requires different handling).

## Background
This method was introduced in the context of dynamic GPU sparse grids and voxel-sequential processing, specifically for the NanoVDB specification [S1, unofficial]. It addresses the challenge of expanding sparse grid topology efficiently on GPUs by leveraging bit-parallel operations and hierarchical processing. The approach is part of a broader effort to optimize sparse voxel operations for real-time rendering and simulation [S1, unofficial].
