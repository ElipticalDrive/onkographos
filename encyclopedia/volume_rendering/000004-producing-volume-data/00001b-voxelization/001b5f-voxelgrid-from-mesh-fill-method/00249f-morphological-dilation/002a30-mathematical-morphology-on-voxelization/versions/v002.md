# Mathematical Morphology on Voxelization
Also called: Separable Morphological Operations on Voxels, Voxel Erosion/Dilation

## Overview
Mathematical Morphology on Voxelization performs erosion and dilation on solid voxel grids to create hierarchical structures for rapid neighborhood queries, path finding, or visibility checks [S1, unofficial]. It differs from standard morphological dilation by explicitly leveraging the separability of logical operations on binary voxel data to achieve high performance through iterative, axis-aligned passes [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A solid voxelization grid (binary volume where foreground voxels are 1 and background are 0) [S1, unofficial].
- Output: An eroded or dilated voxel grid of the same dimensions [S1, unofficial].

**Data Structures:**
- The voxel grid is stored as a 3D array where voxels are packed into 32-bit integers along the Z-axis, so one integer represents a column of 32 voxels [S1, unofficial].
- Let $V(x, y, z)$ be the binary voxel value at coordinates $(x, y, z)$ [G].
- Let $I(x, y)$ be the 32-bit integer representing the column at $(x, y)$, where the $k$-th bit corresponds to $V(x, y, k)$ for $k \in [0, 31]$ [S1, unofficial].

**Steps:**
1. **Separable Decomposition:** Decompose the 3D morphological operation into two stages: first erode/dilate along the X and Y directions, then along the Z direction [S1, unofficial].
2. **2D Pass (X/Y):** Apply the logical kernel in the XY plane [S1, unofficial]. For a 3x3 cross or square kernel, dilation uses logical OR and erosion uses logical AND across the 2D neighborhood [S1, unofficial]. This step can be implemented using texture lookups or direct memory access [G].
3. **1D Pass (Z):** Apply the operation along the Z-axis using bit manipulation on the packed integers $I(x, y)$ [S1, unofficial]. Dilation shifts the integer by $\pm 1$ bit and performs a bitwise OR: $I_{out}(x, y) = I_{in}(x, y) \lor (I_{in}(x, y) \ll 1) \lor (I_{in}(x, y) \gg 1)$ [S1, unofficial]. Erosion shifts and performs bitwise AND: $I_{out}(x, y) = I_{in}(x, y) \land (I_{in}(x, y) \ll 1) \land (I_{in}(x, y) \gg 1)$ [S1, unofficial]. Care must be taken as some bits are needed from adjacent integers when shifting [S1, unofficial].
4. **Iteration:** Larger kernel sizes are obtained by repeating the separable passes [S1, unofficial].

**Pseudocode:**
```python
def morphological_voxel_operation(grid, operation='dilate', radius=1):
    """
    grid: 2D list/array of packed 32-bit integers representing Z-columns.
    operation: 'dilate' or 'erode'
    radius: number of iterations
    """
    current_grid = grid
    height = len(grid)
    width = len(grid[0])
    for _ in range(radius):
        # Stage 1: 2D Pass (X/Y)
        next_grid_2d = [[0] * height for _ in range(width)]
        for x in range(width):
            for y in range(height):
                # Standard 2D kernel application over neighbors [G]
                neighbors = []
                for dx in [-1, 0, 1]:
                    for dy in [-1, 0, 1]:
                        nx, ny = x + dx, y + dy
                        if 0 <= nx < width and 0 <= ny < height:
                            neighbors.append(current_grid[nx][ny])
                if operation == 'dilate':
                    next_grid_2d[x][y] = 1 if any(neighbors) else 0
                else:
                    next_grid_2d[x][y] = 1 if all(neighbors) else 0
        # Stage 2: 1D Pass (Z) using bit shifts
        next_grid = []
        for x in range(width):
            col_x = []
            for y in range(height):
                packed = next_grid_2d[x][y]
                if operation == 'dilate':
                    packed_out = packed | (packed << 1) | (packed >> 1)
                else:
                    packed_out = packed & (packed << 1) & (packed >> 1)
                col_x.append(packed_out)
            next_grid.append(col_x)
        current_grid = next_grid
    return current_grid
```

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** When shifting bits in the Z-direction, some bits are needed from adjacent integers, requiring careful boundary handling [S1, unofficial].
- **Precision:** The method relies on binary logic, so precision issues are minimal, but boundary handling is critical to avoid artifacts [G].
- **Degenerate Input:** Empty or fully filled grids result in empty or fully filled outputs, respectively [G].

## Subtopics

### [Voxel Erosion / Fracture](10370-voxel-erosion-fracture.md)
Voxel Erosion / Fracture is a GPU-accelerated iterative process that removes voxels from a solid voxelized model to simulate physical fracture or weathering effects. It differs from standard mathematical morphology by introducing probabilistic removal based on noise buffers and configurable thresholds, allowing for irregular, natural-looking fragmentation rather than uniform shrinking. It builds on [Mathematical Morphology on Voxelization](4702-mathematical-morphology-on-voxelization.md) by replacing deterministic logical operations with stochastic compute shader passes.

### Morphological Refinement of Segmentation
Applies morphological opening to the binary segmentation using a 3x3x3 structure of ones to remove small noise [S2, unofficial]. It then applies morphological closing to the opened segmentation using a 3x3x3 structure of ones to fill small holes [S2, unofficial]. Finally, it converts the refined binary segmentation to uint8 by multiplying by 255 [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot r)$, where $N$ is the number of voxels and $r$ is the number of iterations [G].
- **Memory Complexity:** $O(N)$ for storing the voxel grid [G].
- **Performance:** The method is faster than lengthy preprocesses because it is purely image-based and relies on the solid voxelization as the only step involving actual scene geometry [S1, unofficial].
- **Strengths:** High performance on GPU hardware, especially with integer texture support [S1, unofficial]. Simple implementation using bitwise operations [G].
- **Limitations:** Limited to binary or quantized data [G]. Boundary handling can be complex for large Z-dimensions [G].
- **When to Use:** Path finding, visibility checks, and hierarchical neighborhood queries on voxelized data [S1, unofficial].
- **When Not to Use:** When non-binary data or complex kernel shapes are required [G].

## Background
The method originates from single-pass GPU solid voxelization techniques, where morphological operations are applied directly to the voxelized representation of geometry [S1, unofficial]. It leverages the separability of logical operations to optimize performance on GPU hardware [S1, unofficial]. Hardware testing confirms compatibility with 32-bit integer textures on DX9 and DX10 architectures [S1, unofficial].
