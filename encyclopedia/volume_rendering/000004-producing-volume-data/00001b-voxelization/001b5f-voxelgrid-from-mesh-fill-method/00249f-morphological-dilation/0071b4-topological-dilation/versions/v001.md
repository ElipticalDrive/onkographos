# Topological Dilation

Also called: Bit Mask Morphology, Bit-mask dilation, Nearest-neighbor mask update, Topological Morphology Operations, Topology-Only Dilation

## Overview
Topological Dilation is a method for expanding the active region (narrow band) of a sparse voxel grid by one voxel in all six cardinal directions, operating purely on grid topology without modifying voxel values [S1, unofficial]. It solves the problem of efficiently tracking moving interfaces or preparing data for convolution-based filtering and ray marching by propagating `mValueMask` bits from a LeafNode to its six immediate neighbors [S1, unofficial]. Unlike naive implementations that require two full grid copies and suffer from redundant random accesses, this method exploits the separate encoding of topology in bit masks to perform the update using compact bitwise operations on a single copy of the masks [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The original undilated `mValueMask` of a LeafNode, stored as an array of bytes (`oldValueMask`).
*   **Output:** Updated `mValueMask` arrays for the current LeafNode and its six nearest neighbors (`NN[0]` to `NN[6]`).

**Data Structures:**
*   **LeafNode Dimensions:** The algorithm assumes a cubic LeafNode with dimensions $2^k \times 2^k \times 2^k$. The provided implementation assumes $k=3$ (8x8x8 voxels), resulting in 64 voxels per leaf. The parameter `Log2Z` represents the logarithm base 2 of the Z-dimension (and X/Y dimensions). Typical values are 3, 4, 5, or 6 [S1, unofficial].
*   **mValueMask:** A compact representation of topology. For an 8x8x8 leaf, this is an array of 8 `uint8_t` values, where each byte represents a column of 8 voxels along the Z-axis [S1, unofficial].
*   **NN Array:** An array of 7 pointers to `uint8_t` arrays (or the appropriate bit-mask type). These pointers reference the `mValueMask` of the nearest neighbor LeafNodes. The indexing order is:
    *   `NN[0]`: Current Node
    *   `NN[1]`: -x Neighbor
    *   `NN[2]`: +x Neighbor
    *   `NN[3]`: -y Neighbor
    *   `NN[4]`: +y Neighbor
    *   `NN[5]`: -z Neighbor
    *   `NN[6]`: +z Neighbor
    Indices into these arrays correspond to the linear position $n$ within the 8x8x8 leaf structure [S1, unofficial].

**Algorithm Steps:**
The dilation is implemented as a scatter algorithm. It iterates through each Z-column of the current LeafNode. For each column, it reads the bit mask and scatters the active bits to the corresponding positions in the current node and its neighbors using bitwise shifts and OR operations.

1.  Iterate $x$ from 0 to $2^k - 1$.
2.  Iterate $y$ from 0 to $2^k - 1$.
3.  Calculate the linear index $n = (x \ll k) + y$.
4.  Read `oldValueMask[n]` into a temporary variable `b`.
5.  If `b == 0`, skip to the next iteration (empty Z-column).
6.  Update the Z-direction neighbors and the current node's Z-bits:
    *   The current node's mask `NN[0][n]` is updated with bits shifted up and down by 1 (representing the -z and +z neighbors within the same column).
    *   The -z neighbor mask `NN[5][n]` receives the bits shifted left by $2^k$ (moving to the previous Z-slice).
    *   The +z neighbor mask `NN[6][n]` receives the bits shifted right by $2^k$ (moving to the next Z-slice).
7.  Update the Y-direction neighbors:
    *   If $y > 0$, write `b` to `NN[0][n-1]` (current node, previous Y).
    *   If $y == 0$, write `b` to `NN[3][n + (2^k \times (2^k - 1))]` (wrapping to the previous Y-slice in the same leaf or neighbor, effectively $n + 56$ for $k=3$).
    *   If $y < 2^k - 1$, write `b` to `NN[0][n+1]` (current node, next Y).
    *   If $y == 2^k - 1$, write `b` to `NN[4][n - 2^k]` (wrapping to the next Y-slice, effectively $n - 8$ for $k=3$).
8.  Update the X-direction neighbors:
    *   If $x > 0$, write `b` to `NN[0][n - 2^k]` (current node, previous X).
    *   If $x == 0$, write `b` to `NN[1][n + (2^k \times (2^k - 1) \times 2^k)]` (wrapping to the previous X-slice, effectively $n + 56$ for $k=3$).
    *   If $x < 2^k - 1$, write `b` to `NN[0][n + 2^k]` (current node, next X).
    *   If $x == 2^k - 1$, write `b` to `NN[2][n - (2^k \times (2^k - 1) \times 2^k)]` (wrapping to the next X-slice, effectively $n - 56$ for $k=3$).

**Pseudocode:**
The following Python-like pseudocode implements the dilation for an 8x8x8 leaf ($k=3$). It assumes `NN` is a list of 7 lists of integers (representing the byte arrays), and `oldValueMask` is a list of 8 integers.

```python
def topological_dilation_8x8x8(oldValueMask, NN):
    """
    Performs topological dilation on an 8x8x8 LeafNode.
    
    Args:
        oldValueMask: List of 8 uint8_t values representing the Z-columns of the current leaf.
        NN: List of 7 lists of 8 uint8_t values.
            NN[0]: Current Node
            NN[1]: -x Neighbor
            NN[2]: +x Neighbor
            NN[3]: -y Neighbor
            NN[4]: +y Neighbor
            NN[5]: -z Neighbor
            NN[6]: +z Neighbor
    """
    k = 3  # Log2Z for 8x8x8
    size = 1 << k  # 8
    
    for x in range(size):
        for y in range(size):
            n = (x << k) + y
            b = oldValueMask[n]
            
            # Skip empty z-columns
            if b == 0:
                continue
            
            # Update Z-direction:
            # Current node gets bits shifted by +/- 1 (within the same Z-column)
            # Note: The source code uses bitwise OR to combine shifts.
            NN[0][n] |= (b >> 1) | (b << 1)
            
            # -z neighbor (NN[5]) gets bits shifted by -2^k (previous Z-slice)
            # In 8x8x8, shifting left by 7 moves to the previous Z-slice in the linear mask layout
            NN[5][n] |= (b << 7)
            
            # +z neighbor (NN[6]) gets bits shifted by +2^k (next Z-slice)
            # Shifting right by 7 moves to the next Z-slice
            NN[6][n] |= (b >> 7)
            
            # Update Y-direction:
            # -y neighbor
            if y > 0:
                NN[0][n - 1] |= b
            else:
                # Wrap to previous y-slice: n - 1 + 64 = n + 63? 
                # Source says NN[3][n+7] for y=0. 
                # Let's trace: n=0 (x=0,y=0). n-1 is invalid. 
                # Previous y-slice for x=0 is y=7. Index in NN[3] for x=0,y=7 is (0<<3)+7 = 7.
                # So n+7 is correct for the wrap-around index in the neighbor mask.
                NN[3][n + 7] |= b
                
            # +y neighbor
            if y < 7:
                NN[0][n + 1] |= b
            else:
                # Wrap to next y-slice: n + 1 - 64 = n - 63?
                # Source says NN[4][n-7] for y=7.
                # Trace: n=7 (x=0,y=7). n+1 is invalid.
                # Next y-slice for x=0 is y=0. Index in NN[4] for x=0,y=0 is 0.
                # So n-7 is correct for the wrap-around index.
                NN[4][n - 7] |= b
                
            # Update X-direction:
            # -x neighbor
            if x > 0:
                NN[0][n - 8] |= b
            else:
                # Wrap to previous x-slice: n - 8 + 64 = n + 56?
                # Source says NN[1][n+56] for x=0.
                # Trace: n=0 (x=0,y=0). n-8 invalid.
                # Previous x-slice for y=0 is x=7. Index in NN[1] for x=7,y=0 is (7<<3)+0 = 56.
                # So n+56 is correct.
                NN[1][n + 56] |= b
                
            # +x neighbor
            if x < 7:
                NN[0][n + 8] |= b
            else:
                # Wrap to next x-slice: n + 8 - 64 = n - 56?
                # Source says NN[2][n-56] for x=7.
                # Trace: n=56 (x=7,y=0). n+8 invalid.
                # Next x-slice for y=0 is x=0. Index in NN[2] for x=0,y=0 is 0.
                # So n-56 is correct.
                NN[2][n - 56] |= b
```

**Parameters:**
*   `Log2Z`: The logarithm base 2 of the Z-dimension of the LeafNode. Typical values are 3, 4, 5, or 6, corresponding to 8-, 16-, 32-, or 64-bit operations. The provided code assumes `Log2Z=3` (8x8x8 LeafNodes) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Syntax Error in Source:** The source code snippet contains a syntax error in the line updating `NN[0][n]` (`b>>1   b<<1`). It likely intends a bitwise OR operation (`|`) between the shifted values, but the source text omits the operator [S1, unofficial]. The pseudocode above corrects this to `(b >> 1) | (b << 1)`.
*   **Boundary Conditions:** The boundary conditions for $x=0, x=7, y=0, y=7$ require wrapping indices to adjacent slices within the 8x8x8 leaf or to neighbor nodes. The code uses ternary operators to handle these wrap-arounds explicitly (e.g., `n+56` for $x=0$ -x neighbor, `n-56` for $x=7$ +x neighbor) [S1, unofficial].
*   **Grid Boundaries:** This algorithm operates on a single LeafNode and its immediate neighbors. If the LeafNode is at the boundary of the grid, the neighbor pointers (`NN[1]` to `NN[6]`) may point to null or invalid memory if not handled by the higher-level grid structure. The algorithm assumes valid neighbor masks are provided [G].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per LeafNode, as it iterates over a fixed number of voxels (64 for 8x8x8). The number of operations is constant regardless of the total grid size.
*   **Memory Complexity:** $O(1)$ per LeafNode. It requires only a copy of the `oldValueMask` (8 bytes for 8x8x8) and access to the neighbor masks. It does not require a full grid copy [S1, unofficial].
*   **Measured Performance:** The algorithm is described as "very fast" because it updates eight bits at a time and avoids random access to voxels [S1, unofficial].
*   **Strengths:**
    *   Avoids redundant random access operations per voxel.
    *   Does not require two copies of the grid; only the compact `oldValueMasks` are copied, and only for the duration of the dilation [S1, unofficial].
    *   Exploits the separate encoding of topology and values in VDB [S1, unofficial].
*   **Limitations:**
    *   Specific to VDB's `mValueMask` structure.
    *   Assumes a specific LeafNode dimension (8x8x8) in the provided code, though it can be generalized to other dimensions where `Log2Z` is 3, 4, 5, or 6 [S1, unofficial].
*   **When to Use:** Use when tracking moving interfaces, performing convolution-based filtering, resampling, or ray marching in sparse dynamic volumes where topology updates are needed without modifying voxel values [S1, unofficial].
*   **When Not to Use:** Use when voxel values need to be modified, or when the grid structure does not support the `mValueMask` topology encoding [G].

## Background
Topological Morphology Operations, including dilation and erosion, were introduced as part of the VDB (Voxel Database) framework by Ken Museth in the paper "VDB: High-Resolution Sparse Volumes with Dynamic Topology" (ACM Transactions on Graphics, 2013) [S1, unofficial]. The paper highlights these operations as fundamental for practical applications of VDB to simulations and sparse dynamic volumes, such as interface tracking during deformations [S1, unofficial]. The efficient bit-mask-based implementation was developed to overcome the performance limitations of naive random-access implementations [S1, unofficial].
