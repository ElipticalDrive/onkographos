# VoxelGrid from Mesh (Fill Method)
## Overview
This method converts a triangular mesh into a dense voxel grid by computing surface occupancy and subsequently filling internal voids using morphological operations [S1, unofficial]. It differs from surface-only voxelization by producing a solid, filled volume representation [S1, unofficial].
## How it works
**Inputs and outputs:**
- Input: A mesh (vertices and faces) and a target resolution $(N_x, N_y, N_z)$ [S1, unofficial].
- Output: A 3D boolean array `occ` of shape $(N_x, N_y, N_z)$, where `True` indicates a filled voxel [S1, unofficial].

**Data structures:**
- `occ`: A 3D NumPy array of boolean values [S1, unofficial].

**Steps:**
1. **Validate Bounds**: Check if the mesh bounding box exceeds the unit cube $[-0.5, 0.5]^3$. If any coordinate bound satisfies $\ge 0.5$ in absolute value, raise a `ValueError` [S1, unofficial].
2. **Compute Surface Occupancy**: Determine which voxels intersect the mesh surface geometry [S1, unofficial].
3. **Fill Holes**: Apply a binary morphological fill operation to the surface occupancy grid to fill enclosed voids [S1, unofficial].

**Pseudocode:**
```python
import numpy as np
from scipy import ndimage

def voxelize_fill(mesh, resolution):
    # Step 1: Validate bounds
    bounds = mesh.get_bounds()  # Returns array of coordinate bounds
    if np.any(np.abs(bounds) >= 0.5):
        raise ValueError("Bounds must be within [-0.5, 0.5]")

    # Step 2: Compute surface occupancy
    # Not given in the sources.
    occ_surface = np.zeros(resolution, dtype=bool)

    # Step 3: Fill holes
    occ = ndimage.morphology.binary_fill_holes(occ_surface)
    return occ
```

**Parameters:**
- `resolution`: The number of voxels along each axis. Typical values are Not given in the sources [S1, unofficial].

**Edge cases and pitfalls:**
- **Out-of-bounds mesh**: The method explicitly checks for bounds outside $[-0.5, 0.5]$ and raises an error [S1, unofficial].
- **Precision**: The validation step uses `np.abs(bounds) >= 0.5`, which may fail for meshes exactly on the boundary. Floating-point precision issues should be considered [G].
