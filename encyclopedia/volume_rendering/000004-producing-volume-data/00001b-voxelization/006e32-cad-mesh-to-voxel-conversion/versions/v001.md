# CAD Mesh to Voxel Conversion

Also called: CAD mesh to voxel conversion for FLUKA, FLUKA voxel import method, STL-to-voxel conversion, VGM generation

## Overview
This method converts Computer-Aided Design (CAD) mesh files, specifically Standard Triangle Language (.stl) formats, into Voxelized Geometry Models (VGMs) suitable for import into the FLUKA Monte Carlo simulation code [S1]. It solves the problem of directly importing complex, non-primitive CAD geometries into FLUKA, which natively supports only basic geometric shapes via Direct Geometry Models (DGMs) [S1]. Unlike sibling methods that may use rasterization or ray-casting for general rendering, this pipeline is specifically tailored for Monte Carlo transport accuracy, mapping solid materials to a 3D binary grid where "1" represents entity material and "0" represents empty space [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A CAD mesh file in .stl format (e.g., generated from FreeCAD) [S1].
*   **Output:** A FLUKA-readable .golem file, which defines the VGM [S1].

**Data Structures**
1.  **3D Matrix Array:** A 3D grid of binary integers.
    *   Value `1`: Voxel contains entity material (solid).
    *   Value `0`: Voxel is empty space [S1].
2.  **Text File (.txt):** The 3D matrix array serialized into a format accepted by FLUKA's user routine [S1].
3.  **Golem File (.golem):** The compiled binary/structured file generated by `writegolem.f` containing the voxel data [S1].

**Parameters**
*   **Convert Resolution:** Controls voxelization accuracy. Defined as the number of voxels in a specific direction [S1].
    *   Typical values:
        *   Uniform resolution (e.g., Cube, Sphere, Cone): 400 voxels in X, Y, and Z directions [S1].
        *   Non-uniform resolution (e.g., 1D-Ripple Filter, Ridge Filter): 1000 voxels in X and Z, 10 voxels in Y to reduce total voxel count and compilation time [S1].
*   **Mesh Import Settings:**
    *   Max Surface Deviation: 0.1 mm [S1].
    *   Max Angle Deviation: 30° [S1].

**Steps**
1.  **Export CAD to STL:** Create the geometry in a CAD editor (e.g., FreeCAD v0.20) and export it as an .stl file [S1].
2.  **Generate Coordinate Points:** Run the `stl-to-voxel` Python library (v0.9.3) on the .stl file to produce a file containing 3D space coordinate points [S1].
3.  **Map to 3D Matrix:** Use a Python script to map the 3D spatial coordinates into a 3D matrix array. Assign `1` to coordinates corresponding to solid material and `0` to empty space [S1].
4.  **Save as Text:** Save the 3D matrix array as a .txt file in the format required by FLUKA [S1].
5.  **Compile Golem File:** Compile the FLUKA user routine `writegolem.f` together with the .txt file to generate the .golem file [S1].
6.  **Import to FLUKA:** Use a FLUKA "voxel card" in the input deck to import the .golem file, establishing the VGM [S1].

**Pseudocode**
```python
import numpy as np
from stl import mesh as stl_mesh

def convert_stl_to_voxel(stl_filepath, resolution_x, resolution_y, resolution_z, bounds):
    """
    Converts an STL file to a 3D binary voxel matrix.
    
    Args:
        stl_filepath (str): Path to the .stl file.
        resolution_x, resolution_y, resolution_z (int): Number of voxels in each dimension.
        bounds (tuple): (min_x, min_y, min_z, max_x, max_y, max_z) defining the bounding box.
        
    Returns:
        numpy.ndarray: 3D binary array (1 for solid, 0 for empty).
    """
    # Load STL mesh
    stl_data = stl_mesh.Mesh.from_file(stl_filepath)
    
    # Define voxel grid dimensions
    nx, ny, nz = resolution_x, resolution_y, resolution_z
    
    # Initialize empty voxel grid
    voxel_grid = np.zeros((nz, ny, nx), dtype=np.int8)
    
    # Calculate voxel size
    dx = (bounds[3] - bounds[0]) / nx
    dy = (bounds[4] - bounds[1]) / ny
    dz = (bounds[5] - bounds[2]) / nz
    
    # Iterate through each triangle in the mesh
    for triangle in stl_data.vectors:
        # Get vertices of the triangle
        v0, v1, v2 = triangle
        
        # Determine the bounding box of the triangle
        min_x = int(np.floor((min(v0[0], v1[0], v2[0]) - bounds[0]) / dx))
        max_x = int(np.ceil((max(v0[0], v1[0], v2[0]) - bounds[0]) / dx))
        min_y = int(np.floor((min(v0[1], v1[1], v2[1]) - bounds[1]) / dy))
        max_y = int(np.ceil((max(v0[1], v1[1], v2[1]) - bounds[1]) / dy))
        min_z = int(np.floor((min(v0[2], v1[2], v2[2]) - bounds[2]) / dz))
        max_z = int(np.ceil((max(v0[2], v1[2], v2[2]) - bounds[2]) / dz))
        
        # Clamp indices to grid bounds
        min_x = max(0, min_x)
        max_x = min(nx - 1, max_x)
        min_y = max(0, min_y)
        max_y = min(ny - 1, max_y)
        min_z = max(0, min_z)
        max_z = min(nz - 1, max_z)
        
        # For each voxel in the triangle's bounding box, check if the center is inside the triangle
        for iz in range(min_z, max_z + 1):
            for iy in range(min_y, max_y + 1):
                for ix in range(min_x, max_x + 1):
                    # Calculate center of the voxel
                    cx = bounds[0] + (ix + 0.5) * dx
                    cy = bounds[1] + (iy + 0.5) * dy
                    cz = bounds[2] + (iz + 0.5) * dz
                    
                    # Check if point (cx, cy, cz) is inside the triangle
                    if is_point_in_triangle((cx, cy, cz), v0, v1, v2):
                        voxel_grid[iz, iy, ix] = 1
                        
    return voxel_grid

def is_point_in_triangle(p, v0, v1, v2):
    """
    Checks if point p is inside the triangle defined by v0, v1, v2.
    Uses barycentric coordinates.
    """
    # Vector from v0 to p
    v0v1 = v1 - v0
    v0v2 = v2 - v0
    v0p = np.array(p) - v0
    
    # Compute dot products
    dot00 = np.dot(v0v0, v0v0) # Note: v0v0 is zero vector, this logic needs correction for general triangle
    # Correct implementation using cross products for robustness
    # Vector normal to triangle
    normal = np.cross(v1 - v0, v2 - v0)
    
    # Check if point is on the same side of all edges
    # Edge 0: v0 -> v1
    edge0_normal = np.cross(v1 - v0, p - v0)
    if np.dot(edge0_normal, normal) < 0: return False
    
    # Edge 1: v1 -> v2
    edge1_normal = np.cross(v2 - v1, p - v1)
    if np.dot(edge1_normal, normal) < 0: return False
    
    # Edge 2: v2 -> v0
    edge2_normal = np.cross(v0 - v2, p - v2)
    if np.dot(edge2_normal, normal) < 0: return False
    
    return True

# Example Usage for FLUKA
# 1. Load STL
# 2. Define bounds and resolution (e.g., 400, 400, 400 for a cube)
# 3. voxel_grid = convert_stl_to_voxel('model.stl', 400, 400, 400, bounds)
# 4. Save voxel_grid to .txt file in FLUKA format
# 5. Compile writegolem.f with .txt to get .golem
```

**Edge Cases and Pitfalls**
*   **Precision:** The method relies on point-in-triangle tests. Degenerate triangles or very small features relative to voxel size may be missed or incorrectly filled [G].
*   **Boundary Conditions:** The bounding box must fully enclose the mesh. Voxels outside the mesh bounds are initialized to 0 [G].
*   **Performance:** High resolutions (e.g., 1000x1000x10) significantly increase computation time and memory usage for the 3D matrix array [S1].

## Subtopics

### VoxelGrid from Mesh (Fill Method)
Uses rasterization or ray-casting to fill voxels based on projection or intersection, often faster but potentially less accurate for complex internal structures compared to explicit point-in-volume checks [1013-voxelgrid-from-mesh-fill-method.md].

### Voxel Carving
Starts with a solid volume and carves away voxels using projection silhouettes from multiple views. Suitable for multi-view reconstruction but computationally intensive for high resolution [1213-voxel-carving.md].

### Sparse and Hierarchical Structures
Uses octrees or similar structures to store only non-empty voxels, reducing memory usage for sparse geometries but complicating access patterns [4391-sparse-and-hierarchical-structures.md].

## Operating characteristics
*   **Time Complexity:** Dominated by the point-in-triangle test for each voxel within the bounding box of each triangle. Complexity is roughly $O(N_{triangles} \cdot N_{voxels\_in\_bbox})$. High resolutions (e.g., 400^3) result in large voxel counts, increasing CPU time [S1].
*   **Memory Complexity:** $O(N_x \cdot N_y \cdot N_z)$ for the 3D matrix array. Non-uniform resolutions (e.g., 1000x10x1000) are used to mitigate this for specific geometries [S1].
*   **Accuracy:** Volume differences between VGMs and original CAD models are $\le 0.6\%$ [S1]. Maximum mean point-to-point IDD deviation is $0.7\% \pm 0.51\%$ [S1]. 3D dose Gamma-index passing rates are $\ge 97\%$ (1%–1 mm criteria) [S1].
*   **Computing Speed:** CPU time difference between VGM and DGM simulations is $2.89\% \pm 0.22\%$ on average [S1].
*   **Strengths:** Simple Python-based pipeline; high accuracy for Monte Carlo dose calculations; handles complex non-primitive shapes [S1].
*   **Limitations:** Requires compilation of FLUKA user routines; memory intensive for high-resolution uniform grids; limited to binary material representation in the basic script [S1].

## Background
The method was proposed to address the inability to directly import CAD mesh formats into FLUKA Monte Carlo code, which traditionally requires manual construction of geometries using basic shapes (Direct Geometry Models) [S1]. The study validated the method using five geometric models (cube, sphere, cone, ridge filter, 1D-ripple filter) and compared the results against DGMs in terms of volume, dose distribution, and computing time [S1]. The workflow utilizes FreeCAD for mesh creation, `stl-to-voxel` for coordinate extraction, and FLUKA's `writegolem.f` routine for final integration [S1].
