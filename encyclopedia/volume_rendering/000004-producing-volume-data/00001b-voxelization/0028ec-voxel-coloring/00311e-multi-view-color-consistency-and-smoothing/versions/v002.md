# Multi-view Color Consistency and Smoothing

Also called: Color Consistency with Blur Grouping, Colour Selection, Colour Selection for Voxels, Weighted Average Colour Selection, Weighted Color Selection, Weighted average colour definition

## Overview
Multi-view Color Consistency and Smoothing is a post-processing method for assigning colors to voxels in a fine volumetric reconstruction, designed to compensate for noise arising from camera calibration, imaging artifacts, imperfect light balance, and volume quantization [S1, S2]. It distinguishes itself from basic voxel coloring by explicitly handling non-Lambertian reflectance and preventing visual blurring through a "blur group" mechanism that preserves sharp edges [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A fine voxel grid with 3D positions $(x, y, z)$ and visibility status per view. Source view images with known camera centers $c_v$ [S2].
*   **Output:** A color value $C$ for each voxel, using intensity (Y) or color (U,V) components [S1, S2].

**Data Structures:**
*   **Voxel:** Stores position $(x, y, z)$ and a list of visible view indices [S1, S2].
*   **Group Tag:** Each voxel is classified as either a **Clear Group** or **Blur Group** based on color difference [S1, S2].

**Steps:**

1.  **Mark Center Line:** Approximately mark the line $L_c$ passing through the center of the volume [S2].
2.  **Identify Visible Views:** For a voxel $x$, determine visible views. If visible in fewer than two views, assign $C = C_1$ from the single visible view and skip to Step 6 [S1, S2]. Otherwise, identify the two nearest visible views (View 1 and View 2) [S1, S2].
3.  **Define Reference Lines:** For each nearest view $v \in \{1, 2\}$, define line $L_v$ as the intersection of the volume surface and the line connecting $L_c$ to the camera center $c_v$ of view $v$ [S2].
4.  **Calculate Weighted Color:** Check if voxel $x$ lies between $L_1$ and $L_2$ [S2]. If true, compute $C = (\alpha_1 C_2 + \alpha_2 C_1) / (\alpha_1 + \alpha_2)$, where $C_1, C_2$ are the Y or U,V components from View 1 and View 2, and $\alpha_1, \alpha_2$ are the angles between voxel $x$ and the points in the same layer on $L_1$ and $L_2$ respectively [S1, S2]. If false, assign $C = C_1$ [S1, S2].
5.  **Blur Grouping Check:** Calculate the difference between $C_1$ and $C_2$. If the difference exceeds a particular threshold, place the voxel in the **Blur Group**; otherwise, place it in the **Clear Group** [S1, S2].
6.  **Sharpness Preservation:** For voxels in the Blur Group, let $C_{old}$ be the color computed in Step 4. Replace $C_{old}$ with the color of a neighboring voxel in the Clear Group that has the closest value to $C_{old}$ [S1, S2].

    if len(visible_views) < 2:

        return get_view_color(voxel_pos, visible_views[0], cameras, surface)

    # Identify two nearest views by camera distance
    view_dists = []
    for v in visible_views:
        cam_center = cameras[v].center
        dist = math.sqrt(sum((voxel_pos[i] - cam_center[i])**2 for i in range(3)))
        view_dists.append((dist, v))
    view_dists.sort(key=lambda x: x[0])
    v1, v2 = view_dists[0][1], view_dists[1][1]

    # Step 3 & 4: Reference lines and weighted color
    C1 = get_view_color(voxel_pos, v1, cameras, surface)
    C2 = get_view_color(voxel_pos, v2, cameras, surface)

    # Calculate angles alpha1, alpha2
    ref1 = get_reference_point(voxel_pos, v1, cameras, surface)
    ref2 = get_reference_point(voxel_pos, v2, cameras, surface)

    vec_v1 = [voxel_pos[i] - cameras[v1].center[i] for i in range(3)]
    vec_r1 = [ref1[i] - cameras[v1].center[i] for i in range(3)]

    vec_v2 = [voxel_pos[i] - cameras[v2].center[i] for i in range(3)]
    vec_r2 = [ref2[i] - cameras[v2].center[i] for i in range(3)]
    alpha2 = angle_between(vec_v2, vec_r2)

    # Check if between L1 and L2
    # The exact geometric test depends on surface topology [G]
    if not is_between_lines(voxel_pos, ref1, ref2):
        color = C1
    else:
        denom = alpha1 + alpha2
        if denom == 0:
            color = (C1 + C2) / 2.0  # [G] Fallback for degenerate angles
        else:
            color = (alpha1 * C2 + alpha2 * C1) / denom

    diff = abs(C1 - C2)
    is_blur = diff > threshold

    # Step 6: Sharpness preservation

        neighbor_color = find_closest_clear_neighbor(voxel_pos, color)
        if neighbor_color is not None:
            color = neighbor_color

    return color

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $\alpha_1 + \alpha_2 = 0$, the weights are undefined; a fallback to a simple average or $C_1$ is required [G].
*   **Non-Lambertian Surfaces:** Highly specular or non-Lambertian surfaces cause $C_1$ and $C_2$ to differ significantly, triggering the blur group [S1, S2].
*   **Threshold Selection:** A particular threshold determines whether a voxel enters the blur or clear group [S1, S2].
*   **Visibility:** Voxels visible in only one view are assigned $C_1$ directly, which may retain noise [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Produces smooth colors and brightness, compensating for calibration and quantization noise. The blur group mechanism preserves sharpness better than simple averaging [S1, S2].
*   **Limitations:** Computationally intensive due to multi-view projection. Sensitive to the threshold parameter. May fail on highly reflective surfaces if the "clear" neighbor is not available or representative [S2].
*   **When to Use:** Post-processing for fine volumetric reconstructions where visual smoothness is prioritized, and non-Lambertian artifacts are manageable [S2].
*   **When Not to Use:** Real-time applications requiring low latency, or scenes with extreme specularities where color consistency is fundamentally violated [S2].

## Background
This method was introduced in the context of volumetric representation for sparse multi-view synthesis. It was proposed to address the limitations of iterative volume refinement, which can produce noisy or inconsistent colors due to non-Lambertian reflectance and calibration errors [S1, S2]. The approach was tested on sequences like the "Leo" sequence, composed of five cameras [S1, S2]. It is part of a pipeline that includes pre-processing for adaptive resolution, allowing for scalable view synthesis [S1].
