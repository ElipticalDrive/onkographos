# Voxel Coloring


## Overview
Voxel Coloring is a volumetric reconstruction algorithm that uses color consistency to distinguish object surface voxels from background, starting with an opaque volume and carving inconsistent voxels [S1, unofficial]. It sets itself apart from sibling methods like Space Carving by enforcing an ordinal visibility constraint that allows for a single monotonic scan of the volume, rather than multiple scans or plane-by-plane evaluation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ calibrated camera views (images and intrinsic/extrinsic parameters) and a bounding volume defined as a 3D grid of voxels.
*   **Output:** A 3D volume where voxels are classified as opaque (part of the object) or transparent (background).

**Data Structures:**
*   **Volume Grid:** A 3D array of voxels. Each voxel stores a state: `opaque` or `transparent`.
*   **Camera List:** A list of camera poses and images.

**Parameters:**
*   **Ordinal Visibility Constraint:** Camera locations must be arranged such that voxels can be visited in a single near-to-far scan relative to every camera. This prevents cameras from surrounding the scene [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Initialize all voxels in the reconstruction volume as `opaque`.
2.  **Traversal:** Traverse the voxels in a monotonic order (e.g., increasing distance from a reference point or along a specific axis) to ensure correct visibility handling under the ordinal constraint [S1, unofficial].
3.  **Consistency Test:** For each `opaque` voxel $v$:
    a. Project $v$ into each input image $i$.
    b. Sample the color $C_{v,i}$ at the projected pixel location.
    c. Check if the colors $C_{v,i}$ are consistent across all visible views. Consistency is typically defined by a threshold on the color difference (e.g., Euclidean distance in RGB space).
4.  **Carving:** If the voxel $v$ is found to be color inconsistent (i.e., colors differ significantly across views), mark it as `transparent`.
5.  **Termination:** Repeat steps 3-4 until all remaining `opaque` voxels are color consistent.

**Pseudocode:**
```python
def voxel_coloring(voxels, cameras, color_threshold):
    # Initialize all voxels as opaque
    for v in voxels:
        v.state = OPAQUE

    # Traverse in monotonic order (e.g., sorted by distance from origin)
    sorted_voxels = sort_by_distance(voxels)

    for v in sorted_voxels:
        if v.state == TRANSPARENT:
            continue

        colors = []
        for cam in cameras:
            # Project voxel center to image plane
            pixel = project(v.center, cam)
            if pixel is within_image_bounds(cam.image):
                # Sample color from image
                c = sample_color(cam.image, pixel)
                colors.append(c)

        # Check color consistency
        if not is_consistent(colors, color_threshold):
            v.state = TRANSPARENT

    return voxels

def is_consistent(colors, threshold):
    if len(colors) < 2:
        return True
    # Simple pairwise consistency check
    for i in range(len(colors)):
        for j in range(i + 1, len(colors)):
            if distance(colors[i], colors[j]) > threshold:
                return False
    return True
```

**Edge Cases and Pitfalls:**
*   **Ordinal Constraint Violation:** If cameras surround the scene, the monotonic traversal order cannot guarantee correct visibility for all cameras, leading to incorrect carving or failure to reconstruct hidden surfaces [S1, unofficial].
*   **Noise and Calibration Errors:** Inconsistent colors due to noise or calibration errors may lead to over-carving (removing valid surface voxels).
*   **Degenerate Input:** If no views see a voxel, it remains opaque by default, potentially creating false positives.

## Subtopics

### [Generalized Voxel Coloring](5526-generalized-voxel-coloring.md)
A voxel coloring algorithm that computes visibility exactly to obtain a color-consistent model, using either Item Buffers (IB) or Layered Depth Images (LDI).

### [Multi-view Color Consistency and Smoothing](6445-multi-view-color-consistency-and-smoothing.md)
A method to define voxel colour C by weighting colours from the two nearest visible views to compensate for noise from camera calibration, imaging, light balance, and volume quantization.

## Operating characteristics
*   **Time Complexity:** $O(V \cdot N)$, where $V$ is the number of voxels and $N$ is the number of cameras. Each voxel is tested against all cameras.
*   **Memory Complexity:** $O(V)$ to store the voxel states.
*   **Strengths:** Simple to implement; efficient single-pass traversal under ordinal constraints; produces clean, watertight surfaces.
*   **Limitations:** Cannot reconstruct surfaces hidden from all cameras; sensitive to camera calibration errors and lighting variations; requires the ordinal visibility constraint.
*   **When to Use:** When cameras are arranged in a non-surrounding configuration (e.g., a subset of views around an object) and high-quality color consistency is available.
*   **When Not to Use:** When cameras surround the scene or when occluded surfaces are critical.

## Background
Voxel Coloring was introduced by Seitz and Dyer as an improvement over the Space Carving algorithm [S1, unofficial]. It was designed to simplify voxel visibility computation and allow reconstruction in a single scan by imposing an ordinal visibility constraint on camera locations. The algorithm uses color-based consistency alone, without volume intersection, to distinguish points belonging to the object surface from other points in the scene [S1, unofficial].
