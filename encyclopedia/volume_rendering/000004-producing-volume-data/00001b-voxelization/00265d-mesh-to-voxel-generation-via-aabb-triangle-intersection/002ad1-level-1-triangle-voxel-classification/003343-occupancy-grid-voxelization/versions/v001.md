# Occupancy Grid Voxelization

Also called: Discretize, Scene Discretization to Occupancy Grid

## Overview
Occupancy Grid Voxelization converts a target mesh shape into a binary occupancy grid aligned with the sensor resolution, serving as an optimization reference for inverse rendering tasks [S1, unofficial]. It computes this grid by explicitly checking if each voxel box in a 3D lattice intersects with any triangle in the input mesh [S2, unofficial]. Unlike hierarchical or ray-casting approaches, this method performs a brute-force classification of every voxel against every triangle, prioritizing implementation simplicity and exact boundary definition over computational speed [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A mesh defined by a list of vertices $V$ and faces $F$. Vertices are 3D points ($\mathbb{R}^3$), and faces are triplets of vertex indices.
*   **Input**: Sensor bounding box extents ($W, H, D$) and target resolution dimensions ($width, height, depth$).
*   **Output**: A 3D binary occupancy grid $O$ of shape $(height, width, depth)$. $O[h, w, d] = 1$ if the voxel intersects the mesh, else $0$.

**Data Structures**
*   **Vertices**: Array of $N_v$ vectors, each containing $(x, y, z)$ floats.
*   **Faces**: Array of $N_f$ triplets, each containing three integer indices into the vertices array.
*   **Occupancy Grid**: A 3D tensor $O$ of integers (0 or 1). In C++ implementations, this may be stored as `Eigen::Tensor<int, 3, Eigen::RowMajor>` [S2, unofficial].

**Parameters**
*   **Resolution**: $(width, height, depth)$ integers defining the grid dimensions.
*   **Voxel Size**: Derived from the sensor bounding box extents divided by the resolution. Let $E_x, E_y, E_z$ be the extents. The voxel size is $\Delta x = E_x / width$, $\Delta y = E_y / height$, $\Delta z = E_z / depth$ [S1, unofficial].

**Steps**
1.  **Coordinate Grid Generation**: Generate coordinate grids for the voxel indices using 'ij' indexing (row-major order) to map integer indices to physical space [S1, unofficial].
2.  **Voxel Iteration**: Initialize a parallel loop over all voxel indices $i$ from $0$ to $height \times width \times depth - 1$ [S2, unofficial].
3.  **Index Decomposition**: For each $i$, calculate the voxel coordinates $(h, w, d)$:
    $$ d = i \pmod{depth} $$
    $$ w = \lfloor (i / depth) \pmod{width} \rfloor $$
    $$ h = \lfloor (i / depth) / width \rfloor $$
    [S2, unofficial]
4.  **Voxel Bounds Definition**: Define the physical bounds of the voxel box. Let $min\_coord$ and $max\_coord$ be the minimum and maximum physical coordinates of the sensor bounding box. The voxel bounds are:
    $$ x_{min} = min\_coord_x + w \cdot \Delta x, \quad x_{max} = min\_coord_x + (w + 1) \cdot \Delta x $$
    $$ y_{min} = min\_coord_y + h \cdot \Delta y, \quad y_{max} = min\_coord_y + (h + 1) \cdot \Delta y $$
    $$ z_{min} = min\_coord_z + d \cdot \Delta z, \quad z_{max} = min\_coord_z + (d + 1) \cdot \Delta z $$
    [S2, unofficial]
5.  **Triangle Intersection Check**: Loop over all faces $f$ in the mesh. For each face, retrieve vertices $v_1, v_2, v_3$.
6.  **Overlap Test**: Perform a triangle-box intersection test:
    $$ overlap = \text{triangle\_box\_intersection}(x_{min}, y_{min}, z_{min}, x_{max}, y_{max}, z_{max}, v_1, v_2, v_3) $$
    [S2, unofficial]
7.  **Mark Occupancy**: If $overlap$ is true, set $O[h, w, d] = 1$ and break the face loop for this voxel. If the loop completes without overlap, $O[h, w, d]$ remains 0.

**Pseudocode**
```python
def occupancy_grid_voxelization(vertices, faces, bounds, resolution):
    """
    vertices: list of [x, y, z] floats
    faces: list of [i, j, k] integer indices
    bounds: tuple (xmin, ymin, zmin, xmax, ymax, zmax)
    resolution: tuple (width, height, depth)
    """
    width, height, depth = resolution
    xmin, ymin, zmin, xmax, ymax, zmax = bounds
    
    # Calculate voxel sizes
    dx = (xmax - xmin) / width
    dy = (ymax - ymin) / height
    dz = (zmax - zmin) / depth
    
    # Initialize occupancy grid
    occ = [[[0 for _ in range(depth)] for _ in range(width)] for _ in range(height)]
    
    # Pre-calculate voxel bounds to avoid repeated arithmetic in inner loop
    # Note: In a parallel implementation, this might be done per-thread or pre-computed
    voxel_bounds = []
    for h in range(height):
        for w in range(width):
            for d in range(depth):
                x_min = xmin + w * dx
                x_max = x_min + dx
                y_min = ymin + h * dy
                y_max = y_min + dy
                z_min = zmin + d * dz
                z_max = z_min + dz
                voxel_bounds.append((x_min, y_min, z_min, x_max, y_max, z_max))

    # Iterate over all voxels
    for i in range(height * width * depth):
        h = i // (width * depth)
        w = (i // depth) % width
        d = i % depth
        
        x_min, y_min, z_min, x_max, y_max, z_max = voxel_bounds[i]
        
        # Check against all triangles
        for face in faces:
            v1 = vertices[face[0]]
            v2 = vertices[face[1]]
            v3 = vertices[face[2]]
            
            if triangle_box_intersection(x_min, y_min, z_min, x_max, y_max, z_max, v1, v2, v3):
                occ[h][w][d] = 1
                break # Found intersection, no need to check other triangles for this voxel
                
    return occ
```

**Edge Cases and Pitfalls**
*   **Precision**: Floating-point errors in vertex coordinates may cause false negatives or positives at boundaries. [G] Use a small epsilon when comparing coordinates to voxel bounds.
*   **Degenerate Input**: Triangles with zero area (collinear vertices) should be handled or filtered out to avoid undefined intersection behavior.
*   **Performance**: The $O(N_v \cdot N_f)$ complexity makes this method impractical for high-resolution grids or complex meshes without spatial acceleration structures (e.g., BVH, Grid) [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(V \cdot T)$, where $V$ is the number of voxels and $T$ is the number of triangles. This is the primary bottleneck.
*   **Memory Complexity**: $O(V)$ for the occupancy grid.
*   **Measured Performance**: Not given in the sources.
*   **Strengths**: Simple to implement; provides exact binary boundary representation; parallelizable (each voxel is independent).
*   **Limitations**: Extremely slow for large meshes or high resolutions; does not account for partial voxel coverage.
*   **When to Use**: Small to medium meshes; low-resolution grids; when binary occupancy is sufficient for optimization references.
*   **When Not to Use**: High-resolution scenes; real-time applications; when partial volume effects are significant.
