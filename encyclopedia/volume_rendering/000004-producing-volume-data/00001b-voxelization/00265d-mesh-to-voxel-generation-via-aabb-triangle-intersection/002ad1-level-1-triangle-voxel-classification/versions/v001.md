# Level 1 Triangle-Voxel Classification

Also called: CUDAClassifyTessellationKernel

## Overview
Classifies input triangles into a coarse 3D voxel grid by mapping vertices to voxel indices and testing overlap with all candidate voxels the triangle spans. It serves as the initial broad-phase culling step in hierarchical voxelization, building on [Mesh to Voxel Generation via AABB-Triangle Intersection](3775-mesh-to-voxel-generation-via-aabb-triangle-intersection.md) by applying the AABB-Triangle intersection test to a grid structure. It differs from [Tessellation-based Voxelization](5430-tessellation-based-voxelization.md) by using a fixed-resolution grid and explicit triangle-voxel overlap tests rather than GPU tessellation hardware.

## How it works
**Inputs:**
- `trianglesCUDAData`: Flat float array, stride 9 per triangle (v0.x, v0.y, v0.z, v1.x, v1.y, v1.z, v2.x, v2.y, v2.z).
- `objBoxMin`, `objBoxMax`: Scene bounding box coordinates (float3).
- `numDiv`: 3D grid resolution (int3: `numDiv.x`, `numDiv.y`, `numDiv.z`).
- `boxExtents`: Voxel size parameter (float3). Note: The source formula uses `boxExtents * 2`, implying `boxExtents` may represent half-extents or a scaling factor.
- `inOutCUDAData`, `voxelTriCountCUDAData`, `voxelTriIndexCUDAData`: Buffers for voxel triangle lists.
- `triBufferLen`: Maximum number of triangles allocated per voxel in the buffer.

**Outputs:**
- Populated `voxelTriIndexCUDAData` and `voxelTriCountCUDAData` indicating which triangles intersect which voxels.

**Data Structures:**
- Voxel grid is indexed linearly: `index = r * numDiv.y * numDiv.x + q * numDiv.x + p`, where `p, q, r` are x, y, z indices.
- Each voxel maintains a list of triangle indices up to `triBufferLen`.

**Steps:**
1. Each thread processes one triangle. Extract 3 vertices from `trianglesCUDAData` at offset `t*9`.
2. Map each vertex to voxel indices:
   $$ boxNumX = \left\lfloor \frac{vertex.x - objBoxMin.x}{objBoxMax.x - objBoxMin.x} \times numDiv.x \right\rfloor $$
   Clamp boundary: if `boxNumX == numDiv.x` and `vertex.x == objBoxMax.x`, then `boxNumX--`. Repeat for Y and Z.
3. Compute `minBoxX/Y/Z` and `maxBoxX/Y/Z` across the 3 vertices.
4. Iterate `p` from `minBoxX` to `maxBoxX`, `q` from `minBoxY` to `maxBoxY`, `r` from `minBoxZ` to `maxBoxZ`.
5. For each voxel, compute `boxMidPoint`:
   $$ boxMidPoint[0] = (p + 0.5) \times boxExtents.x \times 2 + objBoxMin.x $$
   $$ boxMidPoint[1] = (q + 0.5) \times boxExtents.y \times 2 + objBoxMin.y $$
   $$ boxMidPoint[2] = (r + 0.5) \times boxExtents.z \times 2 + objBoxMin.z $$
6. Call `TriBoxOverlapCUDA(boxMidPoint, boxExtent, triVerts)`. If overlap, compute linear index and add triangle index to voxel list via `AddPointToVoxel`.

**Pseudocode:**
```python
def classify_triangle(t, tri_data, obj_box_min, obj_box_max, num_div, box_extents, tri_buffer_len, voxel_tri_count, voxel_tri_index):
    # Extract vertices
    offset = t * 9
    v0 = (tri_data[offset], tri_data[offset+1], tri_data[offset+2])
    v1 = (tri_data[offset+3], tri_data[offset+4], tri_data[offset+5])
    v2 = (tri_data[offset+6], tri_data[offset+7], tri_data[offset+8])
    
    # Map vertices to voxel indices
    def map_vertex_to_box(vertex):
        bx = int((vertex[0] - obj_box_min[0]) / (obj_box_max[0] - obj_box_min[0]) * num_div[0])
        by = int((vertex[1] - obj_box_min[1]) / (obj_box_max[1] - obj_box_min[1]) * num_div[1])
        bz = int((vertex[2] - obj_box_min[2]) / (obj_box_max[2] - obj_box_min[2]) * num_div[2])
        
        # Clamp boundary
        if bx == num_div[0] and vertex[0] == obj_box_max[0]:
            bx -= 1
        if by == num_div[1] and vertex[1] == obj_box_max[1]:
            by -= 1
        if bz == num_div[2] and vertex[2] == obj_box_max[2]:
            bz -= 1
        return (bx, by, bz)

    b0 = map_vertex_to_box(v0)
    b1 = map_vertex_to_box(v1)
    b2 = map_vertex_to_box(v2)
    
    # Compute bounding box of voxels spanned
    min_x = min(b0[0], b1[0], b2[0])
    min_y = min(b0[1], b1[1], b2[1])
    min_z = min(b0[2], b1[2], b2[2])
    
    max_x = max(b0[0], b1[0], b2[0])
    max_y = max(b0[1], b1[1], b2[1])
    max_z = max(b0[2], b1[2], b2[2])
    
    tri_verts = [v0, v1, v2]
    
    # Iterate over candidate voxels
    for p in range(min_x, max_x + 1):
        for q in range(min_y, max_y + 1):
            for r in range(min_z, max_z + 1):
                # Compute voxel center
                mid_x = (p + 0.5) * box_extents[0] * 2 + obj_box_min[0]
                mid_y = (q + 0.5) * box_extents[1] * 2 + obj_box_min[1]
                mid_z = (r + 0.5) * box_extents[2] * 2 + obj_box_min[2]
                box_mid = (mid_x, mid_y, mid_z)
                
                # Check overlap
                if tri_box_overlap(box_mid, box_extents, tri_verts):
                    # Compute linear index
                    index = r * num_div[1] * num_div[0] + q * num_div[0] + p
                    
                    # Add triangle to voxel list
                    add_point_to_voxel(index, t, tri_buffer_len, voxel_tri_count, voxel_tri_index)
```

**Parameters:**
- `triBufferLen`: Maximum number of triangles allocated per voxel. Not given in the sources.

**Edge Cases:**
- **Boundary Vertices:** Vertices exactly at `objBoxMax` are clamped to `numDiv - 1` to prevent out-of-bounds indexing.
- **Voxel Overflow:** If a voxel contains more than `triBufferLen` triangles, additional triangles are discarded or require a dynamic buffer strategy [G].

## Subtopics

### [Level 2 Triangle-Voxel Classification](5512-level-2-triangle-voxel-classification.md)
Refines triangle classification into a finer 3D voxel grid (Level 2) using precomputed Level 1 voxel mappings and triangle lists. Chosen when higher resolution is needed for complex geometry without reprocessing all triangles from scratch.

## Operating characteristics
- **Time Complexity:** $O(N \times V_{span})$, where $N$ is the number of triangles and $V_{span}$ is the number of voxels spanned by each triangle.
- **Memory Complexity:** $O(V_{total} \times T_{max})$, where $V_{total}$ is the total number of voxels and $T_{max}$ is `triBufferLen`.
- **Performance:** Parallelized per triangle on GPU. Performance scales with grid resolution and triangle count.
- **Strengths:** Simple, parallelizable, effective for coarse culling.
- **Limitations:** Fixed resolution, potential for voxel overflow, requires explicit overlap test for each candidate voxel.

## Background
Originated in the GPView project by idealab-isu [S1, unofficial]. Used in real-time volume rendering pipelines for efficient mesh-to-voxel conversion.
