# Asynchronous Voxel Update

Also called: Lower-frequency Voxelization, Temporal Voxel Update, Timed Update Logic

## Overview
Asynchronous Voxel Update decouples the frequency of voxel grid regeneration from the rendering frame rate to leverage temporal coherency in scenes with static or slowly moving geometry and lighting [S2, unofficial]. Unlike synchronous voxelization methods that update the volume data every frame, this approach updates the voxel world at a lower, configurable frequency, trading geometric accuracy for significant performance gains [S2, unofficial]. It is distinct from view-adaptive or sparse voxelization methods by focusing specifically on temporal decoupling rather than spatial resolution or structure optimization [G].

## How it works
The method controls the update decision based on elapsed time and a progress threshold, allowing the voxelization process to run asynchronously or be skipped entirely if the scene state has not changed sufficiently [G].

**Inputs and Outputs:**
- **Input:** `current_time` (float, milliseconds), `last_update_time` (float, milliseconds), `update_every` (float, milliseconds), `progress` (float, $[0, 1]$) [G].
- **Output:** Boolean flag indicating whether an update should occur; `last_update_time` is updated if an update is triggered [G].

**Data Structures:**
- `last_update_time`: Timestamp of the last voxelization pass [G].
- `update_every`: Minimum time interval between updates [G].
- `current_time`: Current system or frame timestamp [G].
- `progress`: Completion metric for the current frame or scene state [G].

**Parameters:**
- Update interval: 1500 ms [S1, unofficial].
- Update frequency: Can be specified as a frame count, such as every 5 frames [S2, unofficial].

**Steps:**
1. Check the `progress` metric. If `progress >= 0.95`, skip the update and return `false` [S1, unofficial].
2. Calculate the elapsed time since the last update: `elapsed = current_time - last_update_time` [G].
3. If `elapsed >= update_every`, trigger the voxelization process, set `last_update_time = current_time`, and return `true` [S1, unofficial].
4. Otherwise, return `false` [G].

**Pseudocode:**
```python
def should_update_voxel_grid(current_time, last_update_time, update_every, progress):
    """
    Determines if the voxel grid should be updated based on time and progress.
    Returns a tuple: (should_update: bool, new_last_update_time: float)
    """
    if progress >= 0.95:
        return False, last_update_time
    
    elapsed = current_time - last_update_time
    if elapsed >= update_every:
        return True, current_time
    
    return False, last_update_time
```

**Edge Cases and Pitfalls:**
- **Visual Artifacts:** Lowering the update frequency causes the voxel model to lag behind the triangle mesh, resulting in visible artifacts, especially with dynamic geometry or lighting [S2, unofficial].
- **Precision:** Ensure `current_time` and `last_update_time` use a consistent high-resolution timer to avoid drift or incorrect intervals [G].
- **Degenerate Input:** If `current_time` is not monotonically increasing, `elapsed` becomes negative; the method assumes standard monotonic time progression [G].

## Operating characteristics
- **Time Complexity:** Reduces the number of voxelization passes by a factor of $N$ (where $N$ is the ratio of render frame rate to update frequency), effectively lowering the computational load per second by $1 - 1/N$ [G].
- **Memory Complexity:** No additional memory overhead compared to synchronous voxelization, as the same voxel grid structure is reused [G].
- **Measured Performance:** In implementations using voxel cone tracing, updating every 5 frames significantly reduces processing power usage, enabling real-time global illumination with dynamic lighting [S2, unofficial].
- **Strengths:** High performance improvement for static or slow-moving scenes; leverages temporal coherency [S2, unofficial].
- **Limitations:** Introduces latency between scene changes and their representation in the voxel grid, causing visual artifacts if objects move quickly [S2, unofficial].
- **When to Use:** Ideal for scenes with static geometry and lighting, or where performance is critical and minor visual lag is acceptable [G].
- **When Not to Use:** Unsuitable for fast-moving dynamic scenes or when high-fidelity real-time geometric accuracy is required [G].

## Background
The technique was described in the context of implementing voxel cone tracing for real-time global illumination, where it was noted that voxel worlds can be updated at a different frequency than the render frame rate to exploit temporal coherency of light sources and dynamic models [S2, unofficial].
