# Voxel Collision Test
Also called: Grid Check
## Overview
A method to determine if a point or trajectory intersects with occupied voxels in a discrete volume representation. It serves as the foundational collision detection primitive for voxel-based physics and particle systems, distinguishing itself from continuous mesh-based checks by operating directly on the occupancy grid [S1, unofficial]. Unlike its sibling [Voxel Occupancy Test](1281-voxel-occupancy-test.md), which merely reports binary presence, this method often implies interaction logic (such as bouncing) or trajectory traversal [S2, unofficial].
## How it works
**Inputs:**
1.  **Voxel Grid:** A 3D array representing the scene geometry. For solid voxelization, this includes density and normal fields [S2, unofficial]. For simple occupancy, a binary mask suffices [S1, unofficial].
2.  **Query Object:** A point position $\mathbf{p}$ or a trajectory segment $\mathbf{p}_0 \to \mathbf{p}_1$.

**Outputs:**
1.  **Collision Status:** Boolean indicating intersection.
2.  **Collision Data:** (Optional) Normal vector $\mathbf{n}$ at the contact point, penetration depth, or bounce velocity [S2, unofficial].

**Data Structures:**
*   **Occupancy Grid:** A 3D array `grid[x][y][z]`. In simple implementations, this is a boolean or integer bitmask [S1, unofficial]. In solid voxelization, it stores density $\rho$ and normal $\mathbf{n}$ per voxel [S2, unofficial].
*   **Hash Map:** (Optional) For sparse grids, a hash map maps 3D coordinates to voxel data to save memory [S1, unofficial].

**Steps:**
1.  **Grid Query:** Determine the voxel coordinates $(i, j, k)$ corresponding to the query point $\mathbf{p}$.
    $$ i = \lfloor \frac{p_x - b_x}{s_x} \rfloor, \quad j = \lfloor \frac{p_y - b_y}{s_y} \rfloor, \quad k = \lfloor \frac{p_z - b_z}{s_z} \rfloor $$
    Where $(b_x, b_y, b_z)$ is the grid origin and $(s_x, s_y, s_z)$ is the voxel size [G].
2.  **Occupancy Check:** Access `grid[i][j][k]`. If the voxel is empty, no collision occurs [S1, unofficial].
3.  **Normal Evaluation (Solid Voxelization):** If the voxel is occupied, evaluate the surface normal $\mathbf{n}$. To optimize, normals are computed only when a particle enters contact with a surface, rather than every frame for all particles [S2, unofficial].
4.  **Dynamic Update:** For deformable scenes, recompute density and normals at every frame to reflect the new geometry [S2, unofficial].
5.  **Response:** If a collision is detected, apply physics response (e.g., bounce) using the stored normal [S2, unofficial].

**Edge Cases:**
*   **High Velocity/Large Time Steps:** Particles may tunnel through boundaries. Solid voxelization handles this better than surface-only methods because it represents a volume, allowing detection even if the particle crosses the boundary entirely within one step [S2, unofficial].
*   **Precision:** Floating-point errors in coordinate-to-index conversion can cause missed collisions. [G] Use epsilon checks or robust integer arithmetic for grid indexing.

**Pseudocode:**
```python
def voxel_collision_test(grid, query_point, voxel_size, grid_origin):
    # Convert world position to voxel coordinates
    # G: Handle boundary checks if grid is not infinite
    vx = int((query_point.x - grid_origin.x) / voxel_size.x)
    vy = int((query_point.y - grid_origin.y) / voxel_size.y)
    vz = int((query_point.z - grid_origin.z) / voxel_size.z)
    
    # Check if voxel exists and is occupied
    # G: Assuming grid is a dense 3D array or hash map with default empty value
    voxel = grid.get(vx, vy, vz)
    
    if voxel is None or not voxel.is_occupied:
        return False, None
    
    # For solid voxelization, retrieve normal
    # G: Normals might be precomputed or computed on-the-fly
    normal = voxel.normal
    
    # Evaluate normal only when contact is made (optimization from [S2, unofficial])
    # If this is a continuous sweep test, more complex traversal is needed
    return True, normal
```
## Subtopics

### Solid Voxel Particle Physics
A variant that uses solid voxelization (with normals) to detect collisions and make particles bounce. It treats concave regions and dynamic deformation seamlessly [S2, unofficial]. It is chosen when high precision is required for complex geometries (e.g., tunnels, holes) and dynamic scenes. It offers uniform quality in all directions, unlike depth peeling (which has resolution/hole issues) or clipping planes (restricted z-axis info) [S2, unofficial]. It allows consistent back integration and can be combined with movement extraction steps [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for point query in a dense grid. $O(k)$ for ray traversal, where $k$ is the number of voxels intersected.
*   **Memory Complexity:** $O(N)$ for dense grid, where $N$ is the total number of voxels. Sparse implementations reduce this but add hash overhead [S1, unofficial].
*   **Performance:** The simulation runs entirely on the GPU. The bottleneck is often particle display (billboards) rather than the collision check itself [S2, unofficial].
*   **Strengths:** Handles concave regions and dynamic deformation efficiently. Uniform quality in all directions. High precision for tunneling prevention [S2, unofficial].
*   **Limitations:** Memory intensive for large, dense volumes. Requires recomputation of normals for dynamic scenes [S2, unofficial].
*   **When to Use:** Particle physics in voxel worlds, dynamic deformation, complex concave geometry [S1, S2, unofficial].
*   **When Not to Use:** Static, simple convex scenes where mesh-based collision is cheaper.
## Background
The concept of collision detection as a simple grid check is a fundamental technique in voxel-based game engines, such as the noa engine, where it is used alongside raycasting (line rasterization) and physics [S1, unofficial]. More advanced applications, such as solid voxelization for particle systems, were developed to address limitations of depth peeling and clipping planes, offering uniform directional quality and support for dynamic deformation [S2, unofficial].
