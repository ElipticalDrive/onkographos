# Relaxed Connectivity Voxelization

Also called: 26-connected voxelization of 1D input

## Overview
Relaxed Connectivity Voxelization is a method for voxelizing effectively one-dimensional input (1D, 2D, or 3D primitives) in 3D space that ensures the resulting voxels form a connected path, preventing gaps in flow simulation or fill operations [S1, unofficial]. It produces a 26-connected path, allowing for fewer voxels than 6-connected methods while still maintaining connectivity [S1, unofficial]. Unlike existing algorithms restricted to 1D primitives (e.g., line segments), this method works for input composed of 2D or 3D primitives that are effectively 1D [S1, unofficial]. It builds on [Mesh Topology and Robust Digitization](8496-mesh-topology-and-robust-digitization.md) and differs from [Polygon Mesh Voxelization via Union of Sets](4605-polygon-mesh-voxelization-via-union-of-sets.md), [Labeled Volume Creation via MultiBlock Iteration](7389-labeled-volume-creation-via-multiblock-iteration.md), and [Improved Tetrahedral Mesh Generation for Voxelization](7476-improved-tetrahedral-mesh-generation-for-voxelization.md) by targeting effectively 1D primitives with relaxed 26-connectivity.

## How it works
**Inputs and Outputs:**
*   **Input:** A continuous geometric object composed of 1D, 2D, or 3D primitives that is effectively one-dimensional (cannot produce separation in 3D space) [S1, unofficial].
*   **Output:** A set of voxels in a uniform grid that form a 26-connected path [S1, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 3D uniform grid where each cell represents a voxel [G].
*   **Intersection Target:** A geometric construct defined within each voxel to determine if the input intersects the voxel, consisting of three quadrilaterals that bisect the voxel along all three axes, subdividing space into cubes centered at voxel corners [S1, unofficial].

**Steps:**
1.  **Define Intersection Target:** For each voxel $V$, construct three quadrilaterals that bisect $V$ along the $x$, $y$, and $z$ axes [S1, unofficial].
2.  **Intersect Input with Target:** Check if the input geometry intersects any of the three quadrilaterals within $V$ [S1, unofficial].
3.  **Mark Voxels:** If the input intersects the target in $V$, mark $V$ as part of the voxelization [S1, unofficial].
4.  **Verify Connectivity:** If the input intersects the target in $V$, parts of the intersection targets of the 26-neighbors of $V$ form a closed box with side length twice that of a single voxel [S1, unofficial].
5.  **Ensure Path Continuity:** Any continuous path from $V$ to voxels outside immediate neighbors must intersect this enclosing box, and therefore intersect the target in $N_{26}(V)$ [S1, unofficial].

**Pseudocode:**
```python
def relaxed_connectivity_voxelization(input_segments, grid_bounds, voxel_size):
    """
    Voxelizes effectively 1D input with 26-connectivity.
    Args:
        input_segments: List of line segments, each ((x0,y0,z0), (x1,y1,z1)).
        grid_bounds: Bounding box (min_x, min_y, min_z, max_x, max_y, max_z).
        voxel_size: Size of each cubic voxel.
    Returns:
        Set of voxel coordinates (x, y, z) forming a 26-connected path.
    """
    grid_size = [
        int((grid_bounds[3] - grid_bounds[0]) / voxel_size),
        int((grid_bounds[4] - grid_bounds[1]) / voxel_size),
        int((grid_bounds[5] - grid_bounds[2]) / voxel_size)
    ]
    voxelized_voxels = set()
    half = voxel_size / 2.0

    for x in range(grid_size[0]):
        for y in range(grid_size[1]):
            for z in range(grid_size[2]):
                cx = grid_bounds[0] + (x + 0.5) * voxel_size
                cy = grid_bounds[1] + (y + 0.5) * voxel_size
                cz = grid_bounds[2] + (z + 0.5) * voxel_size

                # Three quadrilaterals bisecting the voxel along x, y, z axes
                quads = [
                    [(cx-half, cy-half, cz), (cx+half, cy-half, cz), (cx+half, cy+half, cz), (cx-half, cy+half, cz)], # XY
                    [(cx-half, cy, cz-half), (cx+half, cy, cz-half), (cx+half, cy, cz+half), (cx-half, cy, cz+half)], # XZ
                    [(cx, cy-half, cz-half), (cx, cy+half, cz-half), (cx, cy+half, cz+half), (cx, cy-half, cz+half)]  # YZ
                ]

                intersects = False
                for p0, p1 in input_segments:
                    for q in quads:
                        if intersects_segment_quad(p0, p1, q):
                            intersects = True
                            break
                    if intersects: break
                if intersects:
                    voxelized_voxels.add((x, y, z))
    return voxelized_voxels

def intersects_segment_quad(p0, p1, quad):
    v0, v1, v2 = quad[0], quad[1], quad[2]
    n = cross(sub(v1, v0), sub(v2, v1))
    n_len = length(n)
    if n_len == 0: return False
    n = scale(n, 1.0/n_len)
    d = dot(n, v0)
    denom = dot(n, sub(p1, p0))
    if abs(denom) < 1e-9: return False
    t = (d - dot(n, p0)) / denom
    if t < 0 or t > 1: return False
    ix = add(p0, scale(sub(p1, p0), t))
    return point_in_convex_quad(ix, quad)

def sub(a, b): return (a[0]-b[0], a[1]-b[1], a[2]-b[2])
def add(a, b): return (a[0]+b[0], a[1]+b[1], a[2]+b[2])
def scale(v, s): return (v[0]*s, v[1]*s, v[2]*s)
def dot(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def cross(a, b): return (a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0])
def length(v): return (v[0]**2+v[1]**2+v[2]**2)**0.5

def point_in_convex_quad(p, quad):
    v0, v1, v2 = quad[0], quad[1], quad[2]
    n = cross(sub(v1, v0), sub(v2, v1))
    axes = [i for i in range(3) if abs(n[i]) < 1e-9]
    if len(axes) != 1: return False
    axis = axes[0]
    min_v = [min(v[i] for v in quad) for i in range(3)]
    max_v = [max(v[i] for v in quad) for i in range(3)]
    return min_v[0] <= p[0] <= max_v[0] and min_v[1] <= p[1] <= max_v[1] and min_v[2] <= p[2] <= max_v[2]
```

**Parameters:**
*   **Voxel Size:** Determines the resolution of the output grid. Not given in the sources. [G]
*   **Grid Bounds:** Defines the spatial extent of the voxelization. Not given in the sources. [G]

**Edge Cases and Pitfalls:**
*   The resulting voxelization may contain almost as many voxels as a cover produced by intersecting the input against the entire 3D voxel, making it potentially inefficient [S1, unofficial].
*   The result is not thin in the same sense as the 2D crosshairs target; stepping along a curve in the dominant direction may produce fewer voxels [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. [G]
*   **Memory Complexity:** Not given in the sources. [G]

*   **Strengths:** Works for input composed of 2D or 3D primitives that are effectively 1D, unlike existing algorithms restricted to 1D primitives [S1, unofficial]. Produces a 26-connected path, allowing for fewer voxels than 6-connected methods [S1, unofficial].
*   **Limitations:** The resulting voxelization may contain almost as many voxels as a cover produced by intersecting the input against the entire 3D voxel, making it potentially inefficient [S1, unofficial].
*   **When to Use:** When 26-connectivity is sufficient and the input is effectively 1D but composed of 2D or 3D primitives [S1, unofficial].
*   **When Not to Use:** When 6-connectivity is strictly required for flow simulation, or when a thinner representation is needed (stepping along a curve in the dominant direction may yield fewer voxels) [S1, unofficial].

## Background
*   **Origin:** The method is described in "A Topological Approach to Voxelization" by Laine et al. [S1, unofficial].
*   **History and Development:** The method is part of a broader topological approach to voxelization, which includes 6-connected voxelization and 26-separating voxelization [S1, unofficial].
*   **Usage:** Used in applications requiring connected voxelizations of effectively 1D structures, such as flow simulation or fill operations [S1, unofficial].
