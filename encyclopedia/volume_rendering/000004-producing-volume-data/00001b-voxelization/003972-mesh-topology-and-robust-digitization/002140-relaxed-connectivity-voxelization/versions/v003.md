# Relaxed Connectivity Voxelization

Also called: 26-connected voxelization of 1D input

## Overview
Relaxed Connectivity Voxelization is a method for voxelizing effectively one-dimensional input (1D, 2D, or 3D primitives) in 3D space that guarantees the resulting voxels form a connected path (either 6-connected or 26-connected) [S1, unofficial]. Unlike standard voxelization which may produce gaps in thin structures, this method uses specific intersection targets to ensure topological continuity, allowing for flow simulation or fill operations within the voxelized curve [S1, unofficial]. It is distinguished from its siblings by its ability to handle 2D or 3D primitives that are effectively 1D, whereas many existing algorithms are restricted to strict 1D primitives like line segments [S1, unofficial].

## How it works
The method relies on defining an "intersection target" within each voxel. If the input geometry intersects this target, the voxel is marked as occupied. The geometry of the target is designed such that any continuous path from an occupied voxel to a non-neighbor must intersect the target of an intermediate voxel, thereby enforcing connectivity.

### Inputs and Outputs
*   **Input**: A continuous geometric primitive (curve, surface, or volume) that is "effectively one-dimensional" in 3D space. This includes 1D curves, but also 2D surfaces or 3D volumes that are thin enough to be treated as 1D structures for connectivity purposes [S1, unofficial].
*   **Output**: A set of voxel coordinates $(x, y, z)$ representing the voxelized structure, guaranteed to be 6-connected or 26-connected depending on the chosen target [S1, unofficial].

### Data Structures
*   **Voxel Grid**: A 3D array or sparse structure representing the domain.
*   **Intersection Target**: Defined geometrically within the local coordinate system of a voxel (typically $[-0.5, 0.5]^3$).

### Steps

1.  **Define the Voxel Domain**: Establish the 3D grid resolution $(N_x, N_y, N_z)$ and the bounding box [S1, unofficial].
2.  **Select Connectivity and Target**: Choose between 6-connected or 26-connected voxelization based on application needs (e.g., flow simulation vs. storage efficiency) [S1, unofficial].
3.  **Construct Intersection Target**:
    *   **For 6-Connected Voxelization**:
        *   Construct a continuous surface for each of the 6 faces of the voxel. This surface prevents curves from outside the voxel from entering and exiting through another face without intersecting this surface [S1, unofficial].
        *   *Realization A (Octahedral)*: Close each face with pyramids meeting at the voxel center. The centers of these octahedra are located at the voxel face centers [S1, unofficial].
        *   *Realization B (Cubical)*: Push the surfaces to the boundaries of the voxels. The target consists of the surface of the cube (2D sheets) [S1, unofficial].
    *   **For 26-Connected Voxelization**:
        *   Define the intersection target as three quadrilaterals that bisect the voxel along all three axes (X, Y, and Z) [S1, unofficial].
        *   These quadrilaterals subdivide space into 8 smaller cubes centered at the voxel corners [S1, unofficial].
4.  **Intersect Input with Target**: For each voxel, determine if the input geometry intersects the defined target [S1, unofficial].
5.  **Mark Voxels**: If an intersection occurs, mark the voxel as occupied [S1, unofficial].

### Pseudocode

```python
def relaxed_connectivity_voxelization(input_geometry, voxel_grid, connectivity_type='26'):
    """
    Voxelizes effectively 1D input using relaxed connectivity.
    
    Args:
        input_geometry: A continuous geometric object (curve/surface/volume).
        voxel_grid: A 3D grid structure to store occupancy.
        connectivity_type: '6' for 6-connected, '26' for 26-connected.
        
    Returns:
        voxel_grid with occupied voxels marked.
    """
    for voxel in voxel_grid:
        # 1. Define the intersection target for the current voxel
        if connectivity_type == '6':
            # Construct target for 6-connected connectivity
            # Option A: Octahedral tessellation (pyramids meeting at center)
            # Option B: Cubical tessellation (surface of the cube)
            target = construct_6_connected_target(voxel)
        elif connectivity_type == '26':
            # Construct target for 26-connected connectivity
            # Three quadrilaterals bisecting the voxel along X, Y, Z axes
            target = construct_26_connected_target(voxel)
        else:
            raise ValueError("Unsupported connectivity type")

        # 2. Check for intersection between input geometry and target
        if input_geometry.intersects(target):
            voxel.occupied = True
        else:
            voxel.occupied = False
            
    return voxel_grid

def construct_6_connected_target(voxel):
    """
    Constructs a 6-connected intersection target.
    Returns a set of geometric primitives (surfaces).
    """
    # Implementation depends on chosen realization (Octahedral or Cubical)
    # For Cubical realization:
    # Target is the surface of the voxel cube.
    return voxel.surface

def construct_26_connected_target(voxel):
    """
    Constructs a 26-connected intersection target.
    Returns three quadrilaterals bisecting the voxel.
    """
    center = voxel.center
    # Quadrilateral 1: Bisects along X axis (plane x=0 in local coords)
    quad_x = Quadrilateral(center + [0, -0.5, -0.5], 
                           center + [0,  0.5, -0.5], 
                           center + [0,  0.5,  0.5], 
                           center + [0, -0.5,  0.5])
    
    # Quadrilateral 2: Bisects along Y axis (plane y=0 in local coords)
    quad_y = Quadrilateral(center + [-0.5, 0, -0.5], 
                           center + [ 0.5, 0, -0.5], 
                           center + [ 0.5, 0,  0.5], 
                           center + [-0.5, 0,  0.5])
                           
    # Quadrilateral 3: Bisects along Z axis (plane z=0 in local coords)
    quad_z = Quadrilateral(center + [-0.5, -0.5, 0], 
                           center + [ 0.5, -0.5, 0], 
                           center + [ 0.5,  0.5, 0], 
                           center + [-0.5,  0.5, 0])
                           
    return [quad_x, quad_y, quad_z]
```

### Parameters and Edge Cases
*   **Connectivity Type**: '6' or '26'. 6-connected is stricter and may produce more voxels; 26-connected is "relaxed" and produces fewer voxels [S1, unofficial].
*   **Input Type**: The method works for "effectively one-dimensional" input. This includes 1D primitives (lines, curves) but also 2D/3D primitives that are thin [S1, unofficial].
*   **Pitfall - Efficiency**: The resulting voxelization may contain almost as many voxels as a cover produced by intersecting the input against the entire 3D voxel, making it potentially inefficient for storage [S1, unofficial].
*   **Pitfall - Thinness**: The result is not "thin" in the same sense as the 2D crosshairs target. Stepping along a curve in the dominant direction may produce fewer voxels than this method [S1, unofficial].
*   **Connectivity Proof**: For 26-connected voxelization, if input intersects the target in voxel $V$, parts of the intersection targets of the 26-neighbors of $V$ form a closed box with side length twice that of a single voxel. Any continuous path from $V$ to voxels outside immediate neighbors must intersect this enclosing box, and therefore intersect the target in $N_{26}(V)$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Depends on the intersection test between the input geometry and the intersection target. For complex inputs, this can be expensive.
*   **Memory Complexity**: The number of voxels can be large, potentially approaching the volume of the bounding box if the input is dense or the target is not optimized [S1, unofficial].
*   **Strengths**: Guarantees topological connectivity (6 or 26) for effectively 1D structures; handles 2D/3D primitives that are effectively 1D.
*   **Limitations**: May produce more voxels than necessary (not "thin"); potentially inefficient for storage; the practical relevance of 6-connected targets is described as "dubious" due to voxel count [S1, unofficial].
*   **When to Use**: When flow simulation or fill operations require guaranteed connectivity within voxelized thin structures, and the input is effectively 1D.
*   **When Not to Use**: When storage efficiency is critical and the input is not effectively 1D, or when a "thin" representation is required.

## Background
The method was introduced by M. C. Laine et al. in the paper "A Topological Approach to Voxelization" (2013) [S1, unofficial]. It is part of a broader topological approach to voxelization that uses intersection targets to ensure connectivity. The method extends earlier 2D techniques to 3D, addressing the need for connectivity in 3D space for effectively 1D inputs.
