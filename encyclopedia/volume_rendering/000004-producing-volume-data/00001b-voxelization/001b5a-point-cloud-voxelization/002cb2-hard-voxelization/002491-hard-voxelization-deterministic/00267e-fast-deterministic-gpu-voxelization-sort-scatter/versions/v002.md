# Fast Deterministic GPU Voxelization (Sort-Scatter)

Also called: fast GPU voxelizer, parallel sort + unique + scatter PyTorch path

## Overview
Fast Deterministic GPU Voxelization is a PyTorch-based method for converting 3D point clouds into a fixed-size voxel grid that achieves bit-identical output to a reference C++/CUDA implementation while providing a ~100× speedup [S1, unofficial]. It replaces an $O(N^2)$ sequential CUDA kernel with a parallel pipeline of filtering, coordinate computation, stable sorting, and scattering [S1, unofficial]. Unlike the standard `deterministic=False` path which relies on non-reproducible atomic operations, this method guarantees reproducibility by preserving original point order within voxels via stable sorting [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** `points` tensor of shape $(N, D)$, where $N$ is the number of points and $D \ge 3$ [S1, unofficial]. `rmin` and `rmax` define the bounding box [S1, unofficial]. `voxel_size` defines the grid resolution [S1, unofficial]. `max_voxels` is the global limit on occupied voxels [S1, unofficial]. `max_num_points` is the limit on points per voxel [S1, unofficial].
*   **Outputs:** `voxels` tensor, `coors` tensor, and `num_points_per_voxel` tensor [S1, unofficial].

**Data Structures:**
*   `points`: Float tensor on GPU [S1, unofficial].
*   `in_range`: Boolean mask of length $N$ [S1, unofficial].
*   `voxel_coords`: Integer tensor of shape $(N', 3)$, where $N'$ is the number of points within the range and valid grid bounds [S1, unofficial].
*   `sort_keys`: Integer tensor of shape $(N')$, representing a linearized voxel index used for sorting [S1, unofficial].

**Parameters:**
*   `voxel_size`: Float scalar or vector $(v_x, v_y, v_z)$ [S1, unofficial].
*   `rmin`, `rmax`: Float vectors $(x_{min}, y_{min}, z_{min})$ and $(x_{max}, y_{max}, z_{max})$ [S1, unofficial].
*   `max_voxels`: Integer. If the number of points $M$ exceeds `max_voxels`, the method falls back to the existing C++ op to preserve bit-identity [S1, unofficial].
*   `max_num_points`: Integer. Maximum points retained per voxel [S1, unofficial].

**Algorithm Steps:**
1.  **Range Filtering:** Compute a boolean mask for points inside the bounding box. The condition is inclusive of the lower bound and exclusive of the upper bound: $p_i \in [r_{min}, r_{max})$ for all dimensions [S1, unofficial].
2.  **Coordinate Computation:** For each point in the filtered set, compute its voxel coordinate $c$ for each dimension $d \in \{x, y, z\}$:
    $$ c_d = \lfloor \frac{p_d - r_{min,d}}{v_d} + 0.5 \rfloor $$
    This formula mirrors the C++ `round()` behavior exactly [S1, unofficial].
3.  **Grid Boundary Validation:** Compute the grid dimensions $G_d$ from the configuration [S1, unofficial]. Filter out points where any coordinate $c_d < 0$ or $c_d \ge G_d$ [S1, unofficial]. This step is critical to handle non-integer grid sizes or points at the upper bound that might round up to an out-of-bounds index [S1, unofficial].
4.  **Linearization:** Compute a unique linear key for each valid voxel coordinate to enable sorting. For 3D coordinates $(x, y, z)$ and grid dimensions $(W, H, D)$:
    $$ key = z \cdot (W \cdot H) + y \cdot W + x $$
    This z-major linear key is an internal sort/group key only [S1, unofficial].
5.  **Stable Sorting:** Sort the points (and their associated data) by the linear key using a stable sort algorithm [S1, unofficial]. This preserves the original relative order of points that map to the same voxel [S1, unofficial].
6.  **Grouping and Truncation:** Identify unique voxel keys [S1, unofficial]. For each unique voxel, select the first `max_num_points` points from the sorted list [S1, unofficial]. Points beyond this limit are discarded [S1, unofficial].
7.  **Scattering:** Scatter the selected points into the output `voxels` tensor, populate `coors` with the voxel coordinates, and record the count of points per voxel in `num_points_per_voxel` [S1, unofficial].

**Pseudocode:**
```python
import torch

def voxelize_fast_gpu(points, rmin, rmax, voxel_size, max_voxels, max_num_points, grid_dims):
    """
    points: (N, D) float tensor
    rmin: (3,) float tensor
    rmax: (3,) float tensor
    voxel_size: (3,) float tensor
    max_voxels: int
    max_num_points: int
    grid_dims: (3,) int tensor (W, H, D)
    """
    # 1. Range Filter: inclusive min, exclusive max
    in_range = torch.all((points[:, :3] >= rmin) & (points[:, :3] < rmax), dim=1)
    pts = points[in_range]
    if pts.shape[0] == 0:
        return torch.empty((0, max_num_points, pts.shape[1]), device=pts.device), \
               torch.empty((0, 3), dtype=torch.long, device=pts.device), \
               torch.empty((0,), dtype=torch.long, device=pts.device)

    # 2. Compute Voxel Coordinates: floor((p - rmin) / voxel_size + 0.5)
    coords = torch.floor((pts[:, :3] - rmin) / voxel_size + 0.5).long()

    # 3. Grid Boundary Validation: keep only 0 <= coord < grid_dim
    valid = torch.all((coords >= 0) & (coords < grid_dims), dim=1)
    pts = pts[valid]
    coords = coords[valid]
    if pts.shape[0] == 0:
        return torch.empty((0, max_num_points, pts.shape[1]), device=pts.device), \
               torch.empty((0, 3), dtype=torch.long, device=pts.device), \
               torch.empty((0,), dtype=torch.long, device=pts.device)

    # 4. Linearize Coordinates for Sorting: z * (W * H) + y * W + x
    W, H, D = grid_dims
    keys = coords[:, 2] * (W * H) + coords[:, 1] * W + coords[:, 0]

    # 5. Stable Sort
    sorted_indices = torch.argsort(keys, stable=True)
    sorted_pts = pts[sorted_indices]
    sorted_coords = coords[sorted_indices]
    sorted_keys = keys[sorted_indices]

    # 6. Identify Unique Voxels and Counts
    unique_keys, counts = torch.unique_consecutive(sorted_keys, return_counts=True)
    num_voxels = counts.numel()

    # Fallback check: if number of points M exceeds max_voxels, fall back to C++ op
    if num_voxels > max_voxels:
        raise NotImplementedError("Fallback to C++ op required when M > max_voxels")

    # 7. Select Points per Voxel (first max_num_points)
    # Calculate start indices for each voxel group in the sorted list
    start_indices = torch.cat([torch.tensor([0], device=counts.device), counts[:-1]])
    # Calculate rank of each point within its voxel group
    ranks = torch.arange(pts.shape[0], device=pts.device) - start_indices[torch.searchsorted(unique_keys, sorted_keys)]
    # Mask for points to keep
    keep_mask = ranks < max_num_points

    final_pts = sorted_pts[keep_mask]
    final_coords = sorted_coords[keep_mask]

    # 8. Scatter Output
    voxels = torch.zeros((num_voxels, max_num_points, final_pts.shape[1]), device=pts.device)
    coors = torch.zeros((num_voxels, 3), dtype=torch.long, device=pts.device)
    num_points_per_voxel = torch.zeros((num_voxels,), dtype=torch.long, device=pts.device)

    # De-linearize unique keys to get x, y, z coordinates
    coors[:, 2] = unique_keys // (W * H)
    coors[:, 1] = (unique_keys % (W * H)) // W
    coors[:, 0] = unique_keys % W

    # Fill voxels and counts
    # Map each kept point to its voxel ID and local rank
    kept_voxel_ids = torch.searchsorted(unique_keys, sorted_keys[keep_mask])
    kept_ranks = ranks[keep_mask]
    dest_indices = kept_voxel_ids * max_num_points + kept_ranks

    # Flatten voxels for scatter
    voxels_flat = voxels.view(-1, final_pts.shape[1])
    voxels_flat[dest_indices] = final_pts

    # Compute actual point counts per voxel
    num_points_per_voxel = torch.bincount(kept_voxel_ids, minlength=num_voxels).long()

    return voxels, coors, num_points_per_voxel
```

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ due to the stable sort step, where $N$ is the number of points within the range [S1, unofficial]. This is a significant improvement over the $O(N^2)$ complexity of the reference C++ implementation which scans previous points for rank [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for storing intermediate tensors (masks, coordinates, keys) [G].
*   **Performance:** On an NVIDIA H100 with PyTorch 2.12, the method achieves 0.69–0.70 ms per frame for 250k points, compared to 69.8–70.1 ms for the C++ deterministic version, a ~100× speedup [S1, unofficial]. In a full end-to-end training loop, this reduces per-step time from 2.61 s to 0.38 s (~6.9× faster) [S1, unofficial].
*   **Strengths:** Bit-identical output to the reference implementation; highly parallelizable; reproducible [S1, unofficial].
*   **Limitations:** Falls back to the slower C++ implementation if the number of occupied voxels exceeds `max_voxels` [S1, unofficial]. Requires PyTorch and CUDA [G].
*   **When to use:** BEVFusion training where deterministic, reproducible voxelization is required and performance is critical [S1, unofficial].
*   **When not to use:** Deployment scenarios like Autoware which use different voxelizers (e.g., spconv hash voxelizer) [S1, unofficial].

## Background
The method was introduced in a pull request to the Tier4 AWML repository in June 2026 by Max-Bin [S1, unofficial]. It was developed to address a bottleneck in BEVFusion training, where the existing deterministic CUDA voxelizer was too slow due to its sequential nature [S1, unofficial]. The method leverages PyTorch's built-in sorting and scattering operations to achieve parallelism while maintaining the strict determinism required for reproducible research and training [S1, unofficial].
