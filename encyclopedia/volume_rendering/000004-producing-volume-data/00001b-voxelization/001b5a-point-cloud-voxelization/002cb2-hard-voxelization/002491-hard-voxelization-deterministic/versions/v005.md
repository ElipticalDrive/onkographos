# Hard Voxelization (Deterministic)

Also called: Point Cloud Voxelization via Histogramming, Voxel Grid Downsampling, Voxelization of unstructured 3D data, voxel aggregation, voxelize

## Overview
Hard Voxelization (Deterministic) discretizes a continuous 3D point cloud into a fixed-size 3D grid of cubic voxels by binning points based on their spatial coordinates and aggregating associated attribute values within each voxel [S3, unofficial]. It outputs a single representative point per occupied voxel calculated as the centroid of the aggregated attributes [S1, unofficial]. Unlike its sibling [Multiscale Hard Voxelization](3319-multiscale-hard-voxelization.md), which handles multiple resolutions, this method operates on a single fixed scale [S2, unofficial]. It differs from the non-deterministic variant by guaranteeing reproducible output through explicit sorting and unique-coordinate identification, ensuring that the order of points within a voxel is preserved, whereas non-deterministic versions rely on atomic operations that may yield varying results across runs [S3, unofficial].

## How it works
The method maps continuous point coordinates $(x, y, z)$ to discrete integer voxel indices $(i, j, k)$ using floor division relative to a bounding box origin and voxel dimensions [S1, unofficial].

### Inputs and Outputs
**Inputs:**
- `points`: A 2D array of shape $(N, D)$, where $N$ is the number of points and $D$ is the number of features [S2, S3, unofficial].
- `voxel_size`: A 3-element array $[v_x, v_y, v_z]$ indicating the physical size of a voxel in x, y, and z dimensions [S3, unofficial].
- `coors_range`: A 6-element array $[x_{min}, y_{min}, z_{min}, x_{max}, y_{max}, z_{max}]$ defining the bounding box of the voxel grid [S3, unofficial].
- `max_points`: Integer. Maximum number of points allowed in a single voxel. If -1, dynamic voxelization is used [S2, unofficial].
- `max_voxels`: Integer. Maximum number of voxels to create. Points falling into voxels beyond this limit are dropped. Typical value is 20000 [S2, unofficial].

**Outputs:**
- `voxels`: A tensor of shape $[M, \text{max\_points}, D]$, where $M$ is the number of valid voxels ($\le \text{max\_voxels}$). It stores the features of the points assigned to each voxel [S2, unofficial].
- `coors`: A tensor of shape $[M, 3]$ containing the integer voxel indices $(i, j, k)$ for each of the $M$ voxels [S2, unofficial].
- `num_points_per_voxel`: A tensor of shape $[M]$ storing the number of points assigned to each voxel [S2, unofficial].

### Data Structures
1. **Point**: Represents a single point with coordinates and attributes. In CPU implementations, this may be a struct with contiguous fields (e.g., `x, y, z, intensity, ring` as float32, 20 bytes total) [S1, unofficial]. In GPU implementations, points are stored in flat arrays [S2, unofficial].
2. **Voxel Grid (CPU)**: Two 3D arrays `vcnt` and `vsum` of dimensions $(X, Y, Z)$, where $X = \lfloor \frac{x_{max} - x_{min}}{v_x} \rfloor + 1$, etc. `vcnt` stores the count of points, and `vsum` stores the sum of attribute values for each voxel [S4, unofficial].
3. **Voxel Grid (GPU)**: A linear array or hash map mapping linear voxel indices to a `Voxel` struct containing sums (`sum_x`, `sum_y`, `sum_z`, `sum_intensity`, `sum_ring`) and a `count` integer [S1, unofficial].

### Steps
1. **Compute Bounding Box and Grid Dimensions**:
    - If `coors_range` is not provided, iterate over all input points to find $x_{min}, x_{max}, y_{min}, y_{max}, z_{min}, z_{max}$ [S1, unofficial].
    - Calculate grid dimensions using ceiling division:
        $$
        \text{dim}_x = \max(1, \lceil \frac{x_{max} - x_{min}}{v_x} \rceil), \quad
        \text{dim}_y = \max(1, \lceil \frac{y_{max} - y_{min}}{v_y} \rceil), \quad
        \text{dim}_z = \max(1, \lceil \frac{z_{max} - z_{min}}{v_z} \rceil)
        $$
        [S1, unofficial]
    - Ensure dimensions are at least 1 to prevent zero-size allocations [S1, unofficial].

2. **Map Points to Voxel Indices**:
    - For each point $p = [x, y, z, \dots]$, compute voxel coordinates:
        $$
        i = \left\lfloor \frac{x - x_{min}}{v_x} \right\rfloor, \quad
        j = \left\lfloor \frac{y - y_{min}}{v_y} \right\rfloor, \quad
        k = \left\lfloor \frac{z - z_{min}}{v_z} \right\rfloor
        $$
        [S1, S2, S3, unofficial]
    - Points with coordinates outside the range $R$ are mapped to invalid indices (e.g., $-1$) [S1, S2, unofficial].

3. **Identify Unique Voxels and Map Indices (Deterministic Step)**:
    - Collect all valid voxel coordinates $(i, j, k)$ (excluding $-1$) [S2, unofficial].
    - Find unique voxel coordinates and generate a mapping from the original point index to a unique voxel index. This is typically done using a stable sort or a unique operation (e.g., `at::unique_dim` in PyTorch) to ensure reproducibility [S2, unofficial].
    - If the invalid coordinate $(-1, -1, -1)$ is present in the unique list, remove it and adjust the mapping indices accordingly [S2, unofficial].
    - Compute `coors_order` (the order in which voxels appear in the output) and `reduce_count` (number of points per voxel) [S2, unofficial].

4. **Aggregate Attributes**:
    - **CPU Approach**: Iterate through all points. For each point, increment `vcnt[i, j, k]` and add its attributes to `vsum[i, j, k]` [S4, unofficial].
    - **GPU Approach**: Use a parallel kernel to accumulate sums into a `Voxel` struct array. Shared memory may be used for block-level reduction [S1, unofficial].
    - Compute the average attribute value per voxel:
        $$
        \text{vavg} = \frac{\text{vsum}}{\text{vcnt}}
        $$
        [S4, unofficial]
    - Handle empty voxels by setting their average value to NaN where the count is less than 1: `vavg[vcnt < 1] = np.nan` [S4, unofficial].

5. **Assign Features to Output Tensors**:
    - Iterate over the voxel grid or use a parallel kernel to write the aggregated data into the `voxels`, `coors`, and `num_points_per_voxel` tensors [S2, unofficial].
    - For each voxel, store the coordinates in `coors` and the count in `num_points_per_voxel` [S2, unofficial].
    - Store the point features (or centroids) in `voxels`. If multiple points exist in a voxel, they are stored sequentially up to `max_points` [S2, unofficial].
    - Clamp the number of points per voxel to `max_points` [S2, unofficial].

### Pseudocode (CPU Implementation)
```python
import numpy as np

def hard_voxelize_deterministic(points, voxel_size, coors_range, max_points, max_voxels):
    """
    points: (N, C) array-like
    voxel_size: (3,) float array [vx, vy, vz]
    coors_range: (6,) float array [xmin, ymin, zmin, xmax, ymax, zmax]
    max_points: int
    max_voxels: int
    Returns: voxels (M, max_points, C), coors (M, 3), num_points_per_voxel (M,)
    """
    N, C = points.shape
    vx, vy, vz = voxel_size
    xmin, ymin, zmin, xmax, ymax, zmax = coors_range
    grid_x = int(np.round((xmax - xmin) / vx))
    grid_y = int(np.round((ymax - ymin) / vy))
    grid_z = int(np.round((zmax - zmin) / vz))

    coors = np.zeros((N, 3), dtype=np.int32)
    coors[:, 0] = np.floor((points[:, 0] - xmin) / vx).astype(np.int32)
    coors[:, 1] = np.floor((points[:, 1] - ymin) / vy).astype(np.int32)
    coors[:, 2] = np.floor((points[:, 2] - zmin) / vz).astype(np.int32)

    invalid_mask = (
        (coors[:, 0] < 0) | (coors[:, 0] >= grid_x) |
        (coors[:, 1] < 0) | (coors[:, 1] >= grid_y) |
        (coors[:, 2] < 0) | (coors[:, 2] >= grid_z)
    )
    coors[invalid_mask] = -1

    unique_coors, inverse_indices = np.unique(coors, axis=0, return_inverse=True)
    if unique_coors[0, 0] == -1:
        unique_coors = unique_coors[1:]
        inverse_indices[inverse_indices == 0] = -1
        inverse_indices[inverse_indices > 0] -= 1

    valid_point_mask = (inverse_indices >= 0)
    valid_points = points[valid_point_mask]
    valid_voxel_indices = inverse_indices[valid_point_mask]

    seen = set()
    ordered_unique_voxels = []
    for vid in valid_voxel_indices:
        if vid not in seen:
            seen.add(vid)
            ordered_unique_voxels.append(vid)
    ordered_unique_voxels = np.array(ordered_unique_voxels, dtype=np.int32)

    voxel_to_pos = {vid.item(): i for i, vid in enumerate(ordered_unique_voxels)}
    point_to_voxel_pos = np.array([voxel_to_pos[vid.item()] for vid in valid_voxel_indices], dtype=np.int32)

    M = len(ordered_unique_voxels)
    if M > max_voxels:
        M = max_voxels
        ordered_unique_voxels = ordered_unique_voxels[:M]
        drop_mask = (point_to_voxel_pos >= M)
        point_to_voxel_pos[drop_mask] = -1
        valid_point_mask = valid_point_mask & ~drop_mask
        valid_points = points[valid_point_mask]
        point_to_voxel_pos = point_to_voxel_pos[valid_point_mask]

    voxels = np.zeros((M, max_points, C), dtype=points.dtype)
    coors_out = np.zeros((M, 3), dtype=np.int32)
    num_points_per_voxel = np.zeros((M), dtype=np.int32)

    for i in range(len(valid_points)):
        voxel_idx = point_to_voxel_pos[i]
        if voxel_idx == -1:
            continue
        count = num_points_per_voxel[voxel_idx]
        if count < max_points:
            voxels[voxel_idx, count] = valid_points[i]
            num_points_per_voxel[voxel_idx] += 1

    coors_out = unique_coors[ordered_unique_voxels]
    return voxels, coors_out, num_points_per_voxel
```

### Parameters and Typical Values
- `voxel_size`: Typical value used in example: 0.7 [S4, unofficial].
- `coors_range`: Not given in the sources.
- `max_points`: Not given in the sources.
- `max_voxels`: Typical value is 20000 [S2, unofficial].

### Edge Cases and Pitfalls
- **Points Outside Range**: Points with coordinates outside `coors_range` are mapped to $-1$ and must be filtered out before unique operations to avoid invalid indices [S2, unofficial].
- **Empty Voxels**: Voxels with no points should be excluded from the output or marked with NaN for attributes to avoid division by zero during averaging [S4, unofficial].
- **Boundary Precision**: Floating-point precision issues may cause points exactly on the boundary to be assigned to the wrong voxel. Clamping indices to $[0, \text{dim}-1]$ is recommended [S1, unofficial].
- **Coordinate Systems**: Ensure the input point cloud coordinate system matches the expected range. For example, nuScenes uses $x=$right, $y=$forward, $z=$up, which may need conversion to KITTI/ROS ($x=$forward, $y=$left, $z=$up) [S1, unofficial].

## Subtopics

### [Fast Deterministic GPU Voxelization (Sort-Scatter)](3806-fast-deterministic-gpu-voxelization-sort-scatter.md)
Fast Deterministic GPU Voxelization is a PyTorch-based method for converting 3D point clouds into a fixed-size voxel grid that achieves bit-identical output to a reference C++/CUDA implementation while providing a ~100× speedup. It replaces an $O(N^2)$ sequential CUDA kernel with a parallel pipeline of filtering, coordinate computation, stable sorting, and scattering. Unlike the standard `deterministic=False` path which relies on non-reproducible atomic operations, this method guarantees reproducibility by preserving original point order within voxels via stable sorting. Choose this when bit-identical reproducibility is required on GPU. Link: [Fast Deterministic GPU Voxelization (Sort-Scatter)](3806-fast-deterministic-gpu-voxelization-sort-scatter.md).

### [Grid Pooling (Max Pooling over Points)](4327-grid-pooling-max-pooling-over-points.md)
Grid Pooling aggregates point cloud features into a fixed-size 3D voxel grid by performing max-pooling within each grid cell. It maps a set of $N$ points with $C$-dimensional features to a $W \times H \times D$ grid where each cell stores the maximum feature value among points falling into that cell. It differs from its sibling [Hard Voxelization (Deterministic)](3321-hard-voxelization-deterministic.md) by explicitly tracking the index of the point that achieved the maximum value to enable differentiable backpropagation. Choose this when differentiable aggregation is needed. Link: [Grid Pooling (Max Pooling over Points)](4327-grid-pooling-max-pooling-over-points.md).

### [Grid-based Scene Cropping with KNN Precomputation](4462-grid-based-scene-cropping-with-knn-precomputation.md)
This method generates cropped point cloud datasets by dividing a normalized 3D scene into a structured grid, applying padding, and precomputing K-nearest neighbor (KNN) relationships for both input points and grid voxels to facilitate local feature grouping. It solves the problem of preparing fixed-size, spatially coherent data structures with relative coordinate offsets for deep learning models. It differs from its siblings by explicitly precomputing KNN indices and relative coordinates for both points and voxels within a cropped region. Choose this for preparing local feature grouping inputs. Link: [Grid-based Scene Cropping with KNN Precomputation](4462-grid-based-scene-cropping-with-knn-precomputation.md).

### Hard Voxelization (Non-Deterministic)
A faster, non-reproducible variant of hard voxelization that uses atomic operations or parallel reductions to assign points to voxels, avoiding the sorting/unique step of the deterministic version [S3, unofficial]. It filters out invalid coordinates, finds unique voxel coordinates using `at::unique_dim`, and then uses `nondisterministic_get_assign_pos` and `nondisterministic_assign_point_voxel` kernels to assign features [S3, unofficial]. It is faster but not reproducible. Choose this when speed is prioritized over reproducibility.

### [Nearest Neighbour Interpolation for Voxelization](6290-nearest-neighbour-interpolation-for-voxelization.md)
This method assigns attribute values (e.g., intensity, color) to voxel centers by identifying the single closest point in the original point cloud to each voxel center, rather than aggregating all points within the voxel volume. It is used when a specific point's value is preferred over an average, distinguishing it from histogramming methods that sum or average all points falling within a voxel. Choose this when a specific point's value is preferred over an average.

## Operating characteristics
- **Time Complexity**: $O(N \log N)$ due to sorting or unique operations on $N$ points [S2, unofficial]. The GPU parallel version can achieve significant speedups (~100×) over sequential CPU implementations [S1, unofficial].
- **Memory Complexity**: $O(M \cdot \text{max\_points} \cdot D)$ for the output tensors, where $M$ is the number of voxels [S2, unofficial]. The grid storage is $O(\text{dim}_x \cdot \text{dim}_y \cdot \text{dim}_z)$ if a dense grid is used [S1, S3, unofficial].
- **Measured Performance**: On the nuScenes dataset, the parallel CUDA version significantly outperforms the sequential CPU version, with execution times logged in CSV files for benchmarking [S1, unofficial].
- **Strengths**: Deterministic output, simple implementation, efficient downsampling.
- **Limitations**: Fixed resolution, loss of information within voxels (averaging), sensitivity to voxel size and range.
- **When to Use**: When a fixed-resolution representation is required for deep learning models and reproducibility is important.
- **When Not to Use**: When variable resolution is needed (use [Multiscale Hard Voxelization](3319-multiscale-hard-voxelization.md)) or when differentiable aggregation is required (use [Grid Pooling](4327-grid-pooling-max-pooling-over-points.md)).

## Background
Hard Voxelization is a fundamental technique in point cloud processing, particularly in autonomous driving and 3D computer vision. It was popularized by methods like VoxelNet and SECOND, which use voxelized point clouds as input to 3D convolutional neural networks [S1, S2, unofficial]. The deterministic variant ensures that the downsampling process is reproducible, which is crucial for debugging and benchmarking [S2, unofficial]. The method is used for benchmarking point cloud downsampling on the nuScenes dataset, logging metrics to CSV and Weights & Biases [S1, unofficial].
