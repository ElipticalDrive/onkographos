# Point Cloud Voxelization Visualization

Also called: PCL Voxelization Viewer, Voxel Grid Rendering

## Overview
This method provides a visualization pipeline for rendering voxelized point clouds using the Point Cloud Library (PCL), supporting axis-aligned or custom bounding boxes with three distinct rendering modes [S1, unofficial]. It differs from standard hard voxelization by focusing on the visual representation of the voxel grid structure itself (solid cubes, wireframes, or colored points) rather than just producing the discrete data structure for downstream processing [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A point cloud (typically `pcl::PointXYZ`), a voxel size parameter, a bounding box mode ("AABB" or "CUSTOM"), and a rendering mode ("A", "B", or "C") [S1, unofficial].
- **Output:** A visual scene rendered via `PCLVisualizer` [S1, unofficial].

**Data Structures:**
- `center_cloud`: An array of `point_XYZ` structures. Each element contains fields `point_X`, `point_Y`, and `point_Z` representing the center coordinates of occupied voxels [S1, unofficial].
- `voxel_interval`: A vector of pairs defining the start and end indices of points belonging to each voxel [S1, unofficial].

**Parameters:**
- `voxelSize`: The side length of each voxel grid cell. Typical values for hairstyle point data are between 0.011 and 0.016 [S1, unofficial].
- `BOX_MODE`: Determines the bounding box type. Accepts "AABB" (computed from min/max points) or "CUSTOM" (fixed resolution, e.g., 128x192x128) [S1, unofficial].
- `RENDERING_MODE`: Selects the visualization style. "A" shows only the point cloud, "B" shows solid cubes, "C" shows wireframe cubes with the point cloud [S1, unofficial].

**Steps:**
1. **Voxelization:** Compute the voxel center for each point. For a point with coordinates $(x, y, z)$ and voxel size $v$, the center is calculated as:
   $$
   c_x = \left\lfloor \frac{x}{v} \right\rfloor \cdot v + \frac{v}{2}, \quad
   c_y = \left\lfloor \frac{y}{v} \right\rfloor \cdot v + \frac{v}{2}, \quad
   c_z = \left\lfloor \frac{z}{v} \right\rfloor \cdot v + \frac{v}{2}
   $$
   [S1, unofficial]. Note: The source code uses raw coordinates divided by voxel size, implying the points are already within the relevant coordinate space or the origin is implicitly 0 [S1, unofficial].

2. **Bounding Box Setup:**
   - If `BOX_MODE` is "AABB", add a cube using the minimum and maximum coordinates of the point cloud (`min_point_AABB`, `max_point_AABB`) [S1, unofficial].
   - If `BOX_MODE` is "CUSTOM", add a cube using fixed bounds (`bound_min`, `bound_max`) [S1, unofficial].
   - Set the bounding box rendering property to wireframe representation [S1, unofficial].

3. **Rendering Mode Execution:**
   - **Mode A:** Color the original point cloud by the Z-axis field and add it to the viewer [S1, unofficial].
   - **Mode B:** Iterate through filtered points (or `center_cloud` in CUSTOM mode), compute voxel centers using the formula in Step 1, and add solid cubes at each center [S1, unofficial].
   - **Mode C:** Combine Mode A and Mode B. Add the Z-colored point cloud, then add wireframe cubes at each voxel center [S1, unofficial].

**Pseudocode:**
```python
def visualize_point_cloud_voxelization(cloud, voxel_size, box_mode, rendering_mode):
    """
    Visualize voxelized point cloud using PCL-like logic.
    cloud: list of points with x, y, z attributes
    voxel_size: float
    box_mode: str ("AABB" or "CUSTOM")
    rendering_mode: str ("A", "B", or "C")
    """
    viewer = create_viewer("Voxelization")
    viewer.set_background_color(0, 0, 0)

    # 1. Setup Bounding Box
    if box_mode == "AABB":
        min_pt = get_min_point(cloud)
        max_pt = get_max_point(cloud)
        viewer.add_cube(min_pt.x, max_pt.x, min_pt.y, max_pt.y, min_pt.z, max_pt.z, 
                        1.0, 1.0, 1.0, "AABB")
        viewer.set_shape_rendering_property("AABB", WIREFRAME)
    elif box_mode == "CUSTOM":
        # Assuming bound_min and bound_max are predefined or passed
        viewer.add_cube(bound_min.x, bound_max.x, bound_min.y, bound_max.y, bound_min.z, bound_max.z, 
                        1.0, 1.0, 1.0, "AABB")
        viewer.set_shape_rendering_property("AABB", WIREFRAME)
    else:
        raise ValueError("Invalid BOX_MODE")

    # 2. Compute Voxel Centers (if needed for B or C)
    voxel_centers = []
    if rendering_mode in ["B", "C"]:
        for point in cloud:
            cx = floor(point.x / voxel_size) * voxel_size + voxel_size / 2
            cy = floor(point.y / voxel_size) * voxel_size + voxel_size / 2
            cz = floor(point.z / voxel_size) * voxel_size + voxel_size / 2
            voxel_centers.append((cx, cy, cz))

    # 3. Render based on Mode
    if rendering_mode == "A":
        # Color by Z-axis
        viewer.add_point_cloud(cloud, color_field="z", name="vertices color")
    elif rendering_mode == "B":
        # Solid cubes at voxel centers
        for i, (cx, cy, cz) in enumerate(voxel_centers):
            center = Vector3(cx, cy, cz)
            rotation = Quaternion(1, 0, 0, 0) # Identity
            cube_name = f"Cube_{i}"
            viewer.add_cube(center, rotation, voxel_size, voxel_size, voxel_size, cube_name)
    elif rendering_mode == "C":
        # Wireframe cubes + Z-colored points
        viewer.add_point_cloud(cloud, color_field="z", name="vertices color")
        for i, (cx, cy, cz) in enumerate(voxel_centers):
            center = Vector3(cx, cy, cz)
            rotation = Quaternion(1, 0, 0, 0)
            cube_name = f"Cube_{i}"
            viewer.add_cube(center, rotation, voxel_size, voxel_size, voxel_size, cube_name)
            viewer.set_shape_rendering_property(cube_name, WIREFRAME)
    else:
        raise ValueError("Invalid RENDERING_MODE")

    # 4. Main Loop
    while not viewer.was_closed():
        viewer.spin_once(100) # 100ms sleep
```

**Edge Cases and Pitfalls:**
- Invalid `BOX_MODE` or `RENDERING_MODE` values cause immediate program termination with an error message [S1, unofficial].
- The source code implies that for Mode B in CUSTOM mode, `center_cloud` is pre-computed by averaging points within voxel intervals, whereas for AABB mode, it iterates through filtered points [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of points $N$ for voxelization and rendering setup $O(N)$.
- **Memory Complexity:** Linear with respect to the number of points $N$ to store the cloud and voxel centers [S1, unofficial].
- **Performance:** Dependent on the number of occupied voxels and the rendering backend (PCL) [S1, unofficial].
- **Strengths:** Simple visualization of voxel occupancy; supports both data-driven (AABB) and fixed (CUSTOM) bounding boxes [S1, unofficial].
- **Limitations:** Tied to PCL visualization; not a general-purpose volume renderer [S1, unofficial].

## Background
This method originates from an unofficial GitHub repository `ericmaic/Point-Cloud-Voxelization` [S1, unofficial]. It is used in PCL-based point cloud processing pipelines for visualizing voxel grid occupancy and bounding box constraints, particularly in contexts like hairstyle point data analysis [S1, unofficial].
