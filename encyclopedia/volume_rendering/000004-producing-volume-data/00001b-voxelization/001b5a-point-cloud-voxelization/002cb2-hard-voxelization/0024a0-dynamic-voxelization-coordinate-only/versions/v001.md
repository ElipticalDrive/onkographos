# Dynamic Voxelization (Coordinate Only)
## Overview
Dynamic Voxelization (Coordinate Only) computes the discrete voxel coordinates for each point in a point cloud without assigning them to a fixed-size voxel grid structure or handling duplicate merging [S1, unofficial]. It is used when `max_points` is set to -1, effectively bypassing the aggregation and duplicate-handling stages of standard hard voxelization [S1, unofficial]. It serves as the coordinate-mapping foundation for variants that subsequently handle features or deterministic aggregation.

## How it works
**Inputs and Outputs:**
*   **Input:** Point cloud coordinates tensor `points` of shape $(N, D)$, where $N$ is the number of points and $D$ is the dimensionality (typically 3). Bounding box range $R = [x_{min}, y_{min}, z_{min}, x_{max}, y_{max}, z_{max}]$ and voxel sizes $v = [v_x, v_y, v_z]$.
*   **Output:** Tensor `coors` of shape $(N, D)$ containing the integer voxel indices for each point.

**Data Structures:**
*   `points`: Float tensor, shape $(N, D)$.
*   `coors`: Integer tensor, shape $(N, D)$.
*   `grid_dims`: Integer tuple $(G_x, G_y, G_z)$ representing the dimensions of the bounding box in voxels.

**Parameters:**
*   `NDim`: Number of coordinate dimensions. Default is 3 [S1, unofficial].
*   `max_points`: Set to -1 to indicate coordinate-only mode [S1, unofficial].

**Steps:**
1.  **Calculate Grid Dimensions:** Compute the number of voxels along each axis using rounding:
    $$
    G_x = \text{round}\left(\frac{x_{max} - x_{min}}{v_x}\right), \quad
    G_y = \text{round}\left(\frac{y_{max} - y_{min}}{v_y}\right), \quad
    G_z = \text{round}\left(\frac{z_{max} - z_{min}}{v_z}\right)
    $$
    [S1, unofficial]
2.  **Compute Voxel Coordinates:** For each point $p_n$ with coordinates $(x_n, y_n, z_n)$, compute the voxel index $(i_n, j_n, k_n)$:
    $$
    i_n = \left\lfloor \frac{x_n - x_{min}}{v_x} \right\rfloor, \quad
    j_n = \left\lfloor \frac{y_n - y_{min}}{v_y} \right\rfloor, \quad
    k_n = \left\lfloor \frac{z_n - z_{min}}{v_z} \right\rfloor
    $$
    [S1, unofficial]
3.  **Boundary Handling:** Points falling outside the bounding box $R$ result in indices outside $[0, G_x-1] \times [0, G_y-1] \times [0, G_z-1]$. In this specific coordinate-only implementation, these points are typically stored as-is or filtered in subsequent stages, as no duplicate merging or max-point limiting occurs [S1, unofficial].

**Pseudocode:**
```python
def dynamic_voxelize_coordinate_only(points, coors_range, voxel_size, ndim=3):
    """
    points: (N, ndim) float tensor
    coors_range: [x_min, y_min, z_min, x_max, y_max, z_max]
    voxel_size: [vx, vy, vz]
    returns: (N, ndim) int tensor of voxel coordinates
    """
    x_min, y_min, z_min, x_max, y_max, z_max = coors_range
    vx, vy, vz = voxel_size
    
    # Calculate grid dimensions
    grid_x = round((x_max - x_min) / vx)
    grid_y = round((y_max - y_min) / vy)
    grid_z = round((z_max - z_min) / vz)
    
    # Initialize output tensor
    coors = torch.zeros_like(points, dtype=torch.int32)
    
    # Compute voxel coordinates for each point
    # Note: This is a simplified CPU representation of the CUDA kernel logic
    for i in range(points.shape[0]):
        x, y, z = points[i]
        
        # Check bounds implicitly by floor division; 
        # indices outside [0, grid-1] are invalid but stored
        coors[i, 0] = floor((x - x_min) / vx)
        coors[i, 1] = floor((y - y_min) / vy)
        if ndim == 3:
            coors[i, 2] = floor((z - z_min) / vz)
            
    return coors
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point division and floor operations may cause points exactly on boundaries to be assigned to adjacent voxels depending on implementation details [G].
*   **Out-of-Bounds:** Points outside the range $R$ produce negative or excessive indices. Standard hard voxelization filters these; this variant does not filter them automatically [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of points. Each point is processed independently.
*   **Memory Complexity:** $O(N)$ for the output coordinate tensor. No auxiliary structures for duplicate merging or feature storage are allocated [S1, unofficial].
*   **Strengths:** Minimal memory overhead; fast execution as it skips complex atomic operations and sorting required for duplicate handling.
*   **Limitations:** Does not reduce point count; output size equals input size. Not suitable for fixed-size voxel grid inputs required by many 3D CNNs without further processing [S1, unofficial].
*   **When to use:** When only spatial indexing is needed, or as a pre-processing step for more complex voxelization variants.

## Background
This method is part of the dynamic voxelization pipeline used in 3D object detection frameworks, specifically implemented in CUDA for GPU acceleration [S1, unofficial]. It originates from the need to efficiently map sparse point clouds to voxel grids without the overhead of fixed-grid constraints.
