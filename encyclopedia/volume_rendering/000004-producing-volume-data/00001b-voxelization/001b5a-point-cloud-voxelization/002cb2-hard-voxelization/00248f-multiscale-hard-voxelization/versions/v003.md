# Multiscale Hard Voxelization

Also called: multiscale voxelization CUDA operator

## Overview
Multiscale Hard Voxelization is a GPU-accelerated method that simultaneously voxelizes a LiDAR point cloud into multiple spatial resolutions (scales) in a single pass [S1, unofficial]. It extends standard hard voxelization by iterating over a list of voxel sizes and point limits, outputting separate voxel feature tensors, coordinates, and point counts for each scale [S1, unofficial]. It differs from single-scale voxelization by managing multiple memory blocks indexed by scale, offering a 10% speed improvement over ordinary single-scale CUDA operators on NVIDIA RTX 3090 hardware [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A point cloud tensor `points` of shape $[N, D]$, where $N$ is the number of points and $D$ is the number of features (e.g., $x, y, z, r$).
*   **Input:** `voxel_sizes`: A list of $S$ voxel dimensions, where each scale $s$ has size $v^{(s)} = [v_x^{(s)}, v_y^{(s)}, v_z^{(s)}]$.
*   **Input:** `max_points_for_all_scales`: A list of $S$ integers, where $M^{(s)}$ is the maximum number of points allowed per voxel for scale $s$.
*   **Input:** `point_cloud_range`: A list of 6 floats $[x_{min}, y_{min}, z_{min}, x_{max}, y_{max}, z_{max}]$ defining the bounding box.
*   **Input:** `max_voxels`: The maximum total number of voxels allowed across all scales.
*   **Output:** `voxels`: Tensor of shape $[S, M_{max}, M_{max\_pts}, D]$, containing point features grouped by voxel and scale.
*   **Output:** `coors`: Tensor of shape $[S, M_{max}, 3]$, containing voxel coordinates in $[z, y, x]$ order.
*   **Output:** `num_points_per_voxel`: Tensor of shape $[S, M_{max}]$, containing the count of points in each voxel.

**Data Structures:**
The algorithm uses several auxiliary arrays allocated per scale:
1.  `point_to_voxelidx`: Array of size $N$, initialized to $-1$. Stores the voxel index assigned to each point.
2.  `point_to_pointidx`: Array of size $N$. Stores the index of the "first" point in the same voxel for each point.
3.  `coor_to_voxelidx`: Array of size $N$. Maps a point's index to its voxel index.
4.  `voxel_num`: Scalar counter tracking the number of allocated voxels for the current scale.

**Steps:**
For each scale $s$ from $0$ to $S-1$:

1.  **Initialize Grid Dimensions:**
    Calculate the grid dimensions for the current scale based on the range and voxel size:
    $$
    grid_x = \left\lfloor \frac{x_{max} - x_{min}}{v_x^{(s)}} \right\rfloor, \quad
    grid_y = \left\lfloor \frac{y_{max} - y_{min}}{v_y^{(s)}} \right\rfloor, \quad
    grid_z = \left\lfloor \frac{z_{max} - z_{min}}{v_z^{(s)}} \right\rfloor
    $$
    [S1, unofficial]

2.  **Compute Voxel Coordinates:**
    For each point $p$ at index $i$ with coordinates $(x, y, z)$:
    $$
    c_x = \left\lfloor \frac{x - x_{min}}{v_x^{(s)}} \right\rfloor, \quad
    c_y = \left\lfloor \frac{y - y_{min}}{v_y^{(s)}} \right\rfloor, \quad
    c_z = \left\lfloor \frac{z - z_{min}}{v_z^{(s)}} \right\rfloor
    $$
    [S1, unofficial]

3.  **Boundary Check:**
    Validate coordinates against the grid dimensions $[0, grid_x)$, $[0, grid_y)$, and $[0, grid_z)$.
    *   If $c_x$ is out of bounds, mark coordinate as invalid (e.g., set `coors[0] = -1`) and skip.
    *   If $c_y$ is out of bounds, mark invalid and skip.
    *   If $c_z$ is out of bounds, mark invalid and skip.
    [S1, unofficial]

4.  **Link Points to Voxels (Deterministic):**
    To ensure deterministic ordering and handle points falling into the same voxel, the implementation uses a nested loop approach [S1, unofficial]:
    *   Initialize `num = 0`.
    *   Iterate $j$ from $0$ to $i-1$:
        *   If point $j$ has the same voxel coordinates $(c_x, c_y, c_z)$ as point $i$:
            *   Increment `num`.
            *   If `num == 1`, set `point_to_pointidx[i] = j`.
            *   If `num >= max_points_for_all_scales[s]`, discard point $i$ (set `point_to_voxelidx[i] = -1`) and break.
    *   If `num == 0`, set `point_to_pointidx[i] = i`.
    *   Set `point_to_voxelidx[i] = num` if valid, else $-1$.
    [S1, unofficial]

5.  **Allocate Voxel Indices:**
    *   If `point_to_voxelidx[i] == 0` (this is the first point in a new voxel):
        *   If `voxel_num[s] >= max_voxels`, skip allocation.
        *   Assign `voxelidx = voxel_num[s]`.
        *   Increment `voxel_num[s]`.
        *   Set `coor_to_voxelidx[i] = voxelidx`.
        *   Set `num_points_per_voxel[voxelidx] = 1`.
    *   If `point_to_voxelidx[i] > 0`:
        *   Find the index of the first point in the same voxel: `point_idx = point_to_pointidx[i]`.
        *   Set `coor_to_voxelidx[i] = coor_to_voxelidx[point_idx]`.
        *   Increment `num_points_per_voxel[coor_to_voxelidx[i]]`.
    [S1, unofficial]

6.  **Store Results:**
    *   Store valid voxel coordinates in `coors` in $[z, y, x]$ order.
    *   Store point features in `voxels` up to `max_points_for_all_scales[s]`.
    [S1, unofficial]

**Pseudocode:**
```python
def multiscale_hard_voxelize(points, voxel_sizes, max_points_limits, point_cloud_range, max_voxels):
    """
    points: [N, D] float tensor
    voxel_sizes: List of [vx, vy, vz]
    max_points_limits: List of int
    point_cloud_range: [xmin, ymin, zmin, xmax, ymax, zmax]
    max_voxels: int
    Returns: voxels, coors, num_points_per_voxel
    """
    S = len(voxel_sizes)
    N = points.shape[0]
    D = points.shape[1]
    
    # Pre-allocate output tensors
    # Note: max_points_for_all_scale is the max across all scales for allocation
    max_pts_global = max(max_points_limits)
    voxels = torch.zeros((S, max_voxels, max_pts_global, D), dtype=points.dtype)
    coors = torch.zeros((S, max_voxels, 3), dtype=torch.int32)
    num_points_per_voxel = torch.zeros((S, max_voxels), dtype=torch.int32)
    
    voxel_nums = [0] * S
    
    for s in range(S):
        vx, vy, vz = voxel_sizes[s]
        max_pts = max_points_limits[s]
        xmin, ymin, zmin, xmax, ymax, zmax = point_cloud_range
        
        # Grid dimensions
        grid_x = int((xmax - xmin) / vx)
        grid_y = int((ymax - ymin) / vy)
        grid_z = int((zmax - zmin) / vz)
        
        # Auxiliary arrays for this scale
        point_to_voxelidx = torch.full((N,), -1, dtype=torch.int32)
        point_to_pointidx = torch.full((N,), -1, dtype=torch.int32)
        coor_to_voxelidx = torch.full((N,), -1, dtype=torch.int32)
        
        # Process each point
        for i in range(N):
            x, y, z = points[i, 0], points[i, 1], points[i, 2]
            
            # Compute voxel coordinates
            c_x = int((x - xmin) / vx)
            c_y = int((y - ymin) / vy)
            c_z = int((z - zmin) / vz)
            
            # Boundary check
            if not (0 <= c_x < grid_x and 0 <= c_y < grid_y and 0 <= c_z < grid_z):

            # Deterministic linking: find previous points with same coords

                if points[j, 0] == x and points[j, 1] == y and points[j, 2] == z:

                     # For strict determinism as per source, we rely on the nested loop logic
                     # However, comparing floats directly is risky. 
                     # The source implies checking if they map to the same voxel.
                     # We assume a helper `get_coors` exists or coors are precomputed.
                     pass 
            
            # Re-implementing the source's specific logic for linking:
            # The source iterates i from 0 to index-1.
            # It checks if prev_coor matches current coor.
            
            # Let's assume we have a list of coors for previous points
            # This part is the O(N^2) bottleneck mentioned in sources
            current_coors = [c_z, c_y, c_x]
            num = 0
            first_point_idx_in_voxel = -1
            
            for j in range(i):
                # Retrieve coors for point j. 
                # In a real implementation, these would be stored in a temporary array.
                # For this pseudocode, we assume we recompute or store them.
                xj, yj, zj = points[j, 0], points[j, 1], points[j, 2]
                cj_x = int((xj - xmin) / vx)
                cj_y = int((yj - ymin) / vy)
                cj_z = int((zj - zmin) / vz)
                
                if cj_x == c_x and cj_y == c_y and cj_z == c_z:
                    num += 1
                    if num == 1:
                        first_point_idx_in_voxel = j
                    if num >= max_pts:
                        break
            
            if num >= max_pts:
                continue # Discard point
            
            point_to_voxelidx[i] = num
            point_to_pointidx[i] = first_point_idx_in_voxel if num > 0 else i
            
            if num == 0:
                # New voxel
                if voxel_nums[s] >= max_voxels:
                    continue
                voxelidx = voxel_nums[s]
                voxel_nums[s] += 1
                coor_to_voxelidx[i] = voxelidx
                num_points_per_voxel[s, voxelidx] = 1
                
                # Store coors in [z, y, x] order
                coors[s, voxelidx, 0] = c_z
                coors[s, voxelidx, 1] = c_y
                coors[s, voxelidx, 2] = c_x
                
                # Store features
                voxels[s, voxelidx, 0, :] = points[i, :]
            else:
                # Same voxel as first_point_idx_in_voxel
                voxelidx = coor_to_voxelidx[first_point_idx_in_voxel]
                coor_to_voxelidx[i] = voxelidx
                num_points_per_voxel[s, voxelidx] += 1

                # The source says "voxels: [scale_num, M, max_points, ndim]"
                # We store at index num
                if num < max_pts:
                    voxels[s, voxelidx, num, :] = points[i, :]

    # Trim outputs to actual voxel counts
    voxels_out = []
    coors_out = []
    num_points_out = []
    
    for s in range(S):
        count = voxel_nums[s]
        voxels_out.append(voxels[s, :count, :max_points_limits[s], :])
        coors_out.append(coors[s, :count, :])
        num_points_out.append(num_points_per_voxel[s, :count])
        
    return voxels_out, coors_out, num_points_out
```

[G] The pseudocode above implements the deterministic $O(N^2)$ linking described in the source notes. In practice, this is optimized on GPU using shared memory and atomic operations to avoid the explicit nested loop, but the logical outcome (deterministic assignment of points to voxels based on order) remains the same. The source explicitly states `deterministic=True` is required for this version.

**Parameters:**
*   `voxel_sizes`: Nested list, e.g., `[[0.16, 0.16, 4], [0.32, 0.32, 4], [0.64, 0.64, 4]]` [S1, unofficial].
*   `max_points_for_all_scales`: List, e.g., `[32, 64, 128]` [S1, unofficial].
*   `point_cloud_range`: List of 6 floats, e.g., `[0, -39.68, -3, 69.12, 39.68, 1]` [S1, unofficial].
*   `max_voxels`: Integer, e.g., `20000` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Out of Bounds:** Points with coordinates outside the range $R$ are discarded. The implementation sets invalid coordinates to $-1$ [S1, unofficial].
*   **Determinism:** The method uses a deterministic $O(N^2)$ approach for linking points, which is inefficient for large point clouds but ensures consistent ordering [S1, unofficial]. A non-deterministic version is noted as a TODO [S1, unofficial].
*   **Max Voxels:** If `voxel_num` exceeds `max_voxels`, subsequent voxels are skipped. Users are advised to shuffle points before calling the function to mitigate bias from dropping points [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The deterministic linking step is $O(N^2)$ per scale due to the nested loop checking previous points [S1, unofficial]. This is a significant limitation for large point clouds.
*   **Memory Complexity:** $O(S \cdot M_{max} \cdot M_{max\_pts} \cdot D)$ for the output tensors, where $S$ is the number of scales, $M_{max}$ is `max_voxels`, and $M_{max\_pts}$ is the maximum `max_points` across all scales.
*   **Performance:** On an NVIDIA RTX 3090, the multiscale operator shows a 10% speed improvement over the ordinary single-scale voxelization CUDA operator [S1, unofficial].
*   **Strengths:** Simplifies API by handling multiple scales in one call; faster than running single-scale voxelization multiple times.
*   **Limitations:** The deterministic linking is inefficient; not batched; requires `deterministic=True` for the current stable version.

## Background
Multiscale Hard Voxelization was introduced as a CUDA operator to address the inconvenience of invoking single-scale voxelization multiple times for feature extraction in 3D object detection networks [S1, unofficial]. It builds upon the normal voxelization method, specifically those found in the MMDetection3D ecosystem [S1, unofficial]. The implementation is based on the `mmcv` and `mmdet` open-source codebases [S1, unofficial]. It is commonly used in LiDAR-based 3D perception tasks where multi-scale feature representation is beneficial for detecting objects of varying sizes.
