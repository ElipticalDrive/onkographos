# Voxelize Point Cloud (Basic Mode)

Also called: Basic partitioning mode

## Overview
Voxelize Point Cloud (Basic Mode) converts a point cloud into a regular 3D grid by calculating voxel spacing from a user-specified number of cells per axis and the cloud's bounding box, then applying a fixed padding to the extent before finalizing dimensions [S1, unofficial]. Unlike the 'Existing Image Geometry' path which validates spacing > 0, Basic mode allows zero spacing if not fixed, leading to division by zero [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Point cloud data (vertices), user-requested number of cells per axis ($N$).
*   **Output:** A 3D grid geometry (ImageGeometry or RectGridGeometry) and associated data array.

**Data Structures:**
*   **Bounding Box:** Defined by minimum and maximum coordinates $(x_{min}, y_{min}, z_{min})$ and $(x_{max}, y_{max}, z_{max})$.
*   **Extent:** $E_x = x_{max} - x_{min}$, $E_y = y_{max} - y_{min}$, $E_z = z_{max} - z_{min}$.
*   **Spacing ($h$):** Calculated as $h = E / N$ for each axis.
*   **Dimensions ($D$):** Final grid dimensions calculated as $D = \lceil 1.002 \times E / h \rceil$.

**Steps:**
1.  **Preflight:**
    *   Calculate initial spacing $h = E / N$.
    *   Create a temporary $N \times N \times N$ geometry with this spacing [S1, unofficial].
    *   *Note:* Preflight dimensions and origin do not agree with the output dimensions, causing downstream filters to receive incorrect geometry information during preflight [S1, unofficial].

2.  **Execute:**
    *   Apply padding to the extent. The source mentions a padding of $0.1\%$ and a specific value of $1e-6$ in pitfalls. The formula uses a factor of $1.002$ (which corresponds to $0.2\%$ padding, or potentially $0.1\%$ on each side summing to $0.2\%$).
    *   Recalculate dimensions: $D = \lceil 1.002 \times E / h \rceil$ [S1, unofficial].
    *   Resize the image geometry to these new dimensions, keeping the preflight spacing [S1, unofficial].

**Pseudocode:**
```python
def voxelize_point_cloud_basic(points, N):
    # 1. Calculate bounding box
    x_min, y_min, z_min = min(points, key=lambda p: p[0])[0], min(points, key=lambda p: p[1])[1], min(points, key=lambda p: p[2])[2]
    x_max, y_max, z_max = max(points, key=lambda p: p[0])[0], max(points, key=lambda p: p[1])[1], max(points, key=lambda p: p[2])[2]
    
    # 2. Calculate extents
    E_x = x_max - x_min
    E_y = y_max - y_min
    E_z = z_max - z_min
    
    # 3. Preflight: Calculate initial spacing
    # Note: This step creates a temporary N x N x N grid
    h_x = E_x / N
    h_y = E_y / N
    h_z = E_z / N
    
    # 4. Execute: Apply padding and recalculate dimensions
    # The source specifies a factor of 1.002 for the final dimension calculation
    # This implies a 0.2% increase in extent or spacing adjustment
    D_x = ceil(1.002 * E_x / h_x)
    D_y = ceil(1.002 * E_y / h_y)
    D_z = ceil(1.002 * E_z / h_z)
    
    # 5. Create final geometry with calculated dimensions and preflight spacing
    # The spacing remains h_x, h_y, h_z from preflight
    final_geometry = create_image_geometry(dimensions=(D_x, D_y, D_z), spacing=(h_x, h_y, h_z))
    
    return final_geometry
```

**Edge Cases and Pitfalls:**
*   **Small N:** For $N < 500$, the executed dimensions are $N+1$, not $N$. For example, $N=10$ results in $11 \times 11 \times 11$, and $N=2$ results in $4 \times 4 \times 4$ [S1, unofficial].
*   **Zero Extent:** If the bounding box has zero extent on an axis (e.g., planar cloud at $z=100$) and the padding ($1e-6$) is smaller than half a float32 ULP ($\sim 7.6e-6$), the padded extent becomes 0, resulting in spacing 0. This causes a divide-by-zero in dimension calculation ($\lceil distance/0 \rceil = \infty$), leading to undefined behavior, `bad_alloc`, or incorrect grids [S1, unofficial].
*   **Preflight Mismatch:** Preflight dimensions and origin do not agree with the output dimensions, causing downstream filters to receive incorrect geometry information during preflight [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of points for bounding box calculation, constant for grid creation.
*   **Memory Complexity:** Linear with respect to $N^3$ for the grid storage.
*   **Strengths:** Simple implementation, user-controlled resolution via $N$.
*   **Limitations:** Prone to division by zero with degenerate inputs (planar clouds). Inconsistent behavior for small $N$ ($N < 500$). Preflight/output mismatch can cause issues in pipelines relying on preflight geometry.
*   **When to use:** When a fixed number of cells per axis is desired and the point cloud is guaranteed to have non-zero extent on all axes.
*   **When not to use:** For planar or degenerate point clouds, or when strict preflight/output consistency is required.

## Background
This mode is part of the `VoxelizePointCloud` filter in the simplnx library [S1, unofficial]. It is designed as a basic partitioning mode, contrasting with more advanced methods like Octree Construction or Hard Voxelization.
