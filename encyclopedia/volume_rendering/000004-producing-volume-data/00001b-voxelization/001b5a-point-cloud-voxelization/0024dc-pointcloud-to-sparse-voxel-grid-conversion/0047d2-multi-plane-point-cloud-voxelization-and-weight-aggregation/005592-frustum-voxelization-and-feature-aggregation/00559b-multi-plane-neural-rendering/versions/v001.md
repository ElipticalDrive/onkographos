# Multi-plane Neural Rendering

Also called: 3D Convolutional Renderer, MPP Network, Neural Volume Rendering Network

## Overview
Multi-plane neural rendering is a technique that uses a 3D convolutional neural network to predict RGB images and blending weights for multiple depth planes, which are then composited to form the final output image [S1]. It differs from standard volume rendering by replacing explicit density estimation along rays with a learned multi-plane projection that handles projection errors from geometry noise via 3D convolutions [S1]. It builds on [Frustum Voxelization and Feature Aggregation](15511-frustum-voxelization-and-feature-aggregation.md).

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor of aggregated voxel features with shape `[batch, P, H, W, C]`, where $P=32$ is the number of planes, $H$ and $W$ are spatial dimensions, and $C=8$ is the feature dimension per plane [S2, unofficial]. The features are derived from point cloud data, where the point feature dimension is 11 (initialized as 0.5 for 5 dimensions, RGB for 3 dimensions, and viewpoint direction for 3 dimensions), but only the first 8 dimensions are updated during training [S1].
*   **Output:** A final rendered image $I$ [S1].

**Data Structures:**
The network processes a 5D tensor representing the multi-plane features. The internal architecture uses standard 3D convolutional layers with specific kernel sizes, strides, and dilation rates [S2, unofficial].

**Algorithm Steps:**
1.  **Encode:** Pass the input tensor through a U-Net-like 3D CNN encoder [S1].
    *   Conv0: 1x1 kernel, 16 filters, LReLU activation.
    *   Pool1: 2x2x2 pooling, stride 2.
    *   Conv1: 3x3 kernel, 32 filters, LReLU activation.
    *   Pool2: 2x1x1 pooling, stride [2,1,1].
    *   Conv2: 3x3 kernel, 32 filters, LReLU activation.
    *   Pool3: 2x2x2 pooling, stride 2.
    *   Conv3: 3x3 kernel, 64 filters, LReLU activation.
    *   Pool4: 2x1x1 pooling, stride [2,1,1].
    *   Conv4: 3x3 kernel, 64 filters, LReLU activation.
    *   Pool5: 2x2x2 pooling, stride 2.
    *   Conv5: 3x3 kernel, 128 filters, LReLU activation.
    *   Conv6 (Bottleneck): 1x3x3 kernel, 128 filters, LReLU activation. If `use_dilation` is True, dilation rate is [1,2,2]; otherwise [1,1,1] [S2, unofficial].
2.  **Decode:** Pass the encoded features through the U-Net decoder using upsampling and skip connections [S2, unofficial].
    *   Up1: Upsample Conv6 (2x2x2) and concatenate with Conv5 (128 channels).
    *   Up2: Upsample Conv7 (2x1x1) and concatenate with Conv4 (64 channels).
    *   Up3: Upsample Conv8 (2x2x2) and concatenate with Conv3 (64 channels).
    *   Up4: Upsample Conv9 (2x1x1) and concatenate with Conv2 (32 channels).
    *   Up5: Upsample Conv10 (2x2x2) and concatenate with Conv1 (32 channels).
3.  **Predict:** Apply final 1x1x1 convolutions to predict color and density [S2, unofficial].
    *   Conv12: 1x1x1 kernel, 3 filters, linear activation. Predicts color $c_i$ for each voxel $x_i$.
    *   Conv12_1: 1x1x1 kernel, 1 filter, linear activation. Predicts density $\rho_i$ for each voxel $x_i$.
4.  **Render:** Composite the predicted planes using discrete volume rendering [S2, unofficial].
    *   For each pixel, accumulate color over $N$ samples (default 32) along the depth axis.
    *   Calculate transmittance $T_i$ and opacity $\alpha_i$ based on density $\rho_i$ and depth delta $\delta_i$.
    *   Compute final color $C$ [S2, unofficial].

**Formulas:**
Density prediction:
$$ \rho_i = \text{Conv12}_1(x_i) $$
Color prediction:
$$ c_i = \text{Conv12}(x_i) $$
Rendering (discrete volume rendering):
$$ C = \frac{1}{N} \sum_{i=1}^{N} T_i \times (1 - \exp(-\rho_i \times \delta_i)) \times c_i $$
where $T_i$ is the transmittance up to sample $i$, $\rho_i$ is the predicted density, $\delta_i$ is the depth delta, and $N$ is the number of samples [S2, unofficial].

The final output image $I$ is obtained by summing the plane predictions weighted by their blending weights $\alpha_p$ [S1]:
$$ I = \sum_{p} I_p \cdot \alpha_p $$
where $I_p$ is the RGB image for plane $p$ and $\alpha_p$ is the blending weight [S1]. Note: [S2, unofficial] describes a volume rendering accumulation, while [S1] describes a multi-plane blending. The implementation must follow the specific source variant used. The blending parameters $a$ and $b$ in [S1] are set to 1 [S1].

**Parameters:**
*   `use_dilation`: Boolean flag, default True. Enables dilation rate [1,2,2] in Conv6 [S2, unofficial].
*   $P, H, W$: Plane count and spatial dimensions. Set to (32, 480, 640) for ScanNet and (32, 512, 640) for Matterport 3D [S1].
*   Learning rate: Decreases from 0.01 to 0.005 to 0.001 [S1].
*   Loss function: Perceptual loss using VGG-19 features [S1].

**Edge Cases and Pitfalls:**
*   Invalid camera poses (e.g., -Inf) must be skipped during preprocessing [S2, unofficial].
*   Point cloud features are initialized with specific values (0.5, RGB, viewpoint) but only the first 8 dimensions are updated [S1].
*   Precision issues may arise from the depth delta calculation in volume rendering [S2, unofficial].

## Subtopics

### Multi-Plane Blending
Uses explicit blending weights $\alpha_p$ for each plane [S1]. Choose when geometry noise is significant and 3D context is needed.

### Volume Rendering Accumulation
Uses density $\rho$ and discrete integration [S2, unofficial]. Choose when continuous volume representation is preferred.

## Operating characteristics
*   **Time Complexity:** Training takes approximately 41.5 hours per scene on a GeForce 1080 Ti [S1]. Inference time is not explicitly given but depends on the 3D CNN depth and resolution [S2, unofficial].
*   **Memory Complexity:** Depends on the voxel grid size and network depth. The input tensor is `[batch, 32, H, W, 8]` [S2, unofficial].
*   **Strengths:** Effectively exploits information from neighboring pixels and depth, handling projection errors caused by geometry noise [S1]. Perceptual loss improves visual quality over L1/L2/SSIM [S1].
*   **Limitations:** Requires significant computational resources for training [S1]. Performance is tied to the quality of the input point cloud and voxelization [S2, unofficial].
*   **When to use:** When rendering from sparse point clouds with significant noise or when high-quality perceptual results are needed [S1].
*   **When not to use:** When real-time inference on low-power hardware is required, or when the input data is already dense and noise-free.

## Background
Multi-plane neural rendering was introduced in the paper "Neural Point Cloud Rendering via Multi-Plane Projection" [S1]. It was developed to improve the rendering quality of neural point clouds by using a 3D CNN to predict multi-plane RGB images and blending weights. The method was evaluated on the ScanNet and Matterport 3D datasets [S1]. An unofficial implementation is available on GitHub [S2, unofficial].
