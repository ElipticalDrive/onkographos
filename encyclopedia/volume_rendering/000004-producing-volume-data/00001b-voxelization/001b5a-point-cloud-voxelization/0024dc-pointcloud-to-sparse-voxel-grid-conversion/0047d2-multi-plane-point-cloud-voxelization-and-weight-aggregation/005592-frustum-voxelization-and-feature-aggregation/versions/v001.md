# Frustum Voxelization and Feature Aggregation

Also called: Feature Aggregation, Frustum Voxelization

## Overview
Frustum Voxelization and Feature Aggregation is a pre-processing method that maps a 3D point cloud into a structured 3D volume aligned with the camera frustum, enabling efficient feature extraction for neural rendering. It solves the problem of irregular point cloud distribution by discretizing the view volume into a grid of frustum voxels and aggregating point features into these cells using distance-based weights. Unlike [Multi-Plane Point Cloud Voxelization and Weight Aggregation](12101-multi-plane-point-cloud-voxelization-and-weight-aggregation.md), which projects points onto parallel planes, this method restricts points to a camera frustum bounded by near and far depth planes, providing a more geometrically accurate representation for perspective views.

## How it works
**Inputs and Outputs:**
- **Input:** A 3D point cloud $C = \{p_i\}$, where each point $p_i$ has 3D coordinates $(x_i, y_i, z_i)$ and feature vector $f_i$. Camera parameters (intrinsics and extrinsics) defining the view frustum.
- **Output:** A 3D tensor of aggregated features with dimensions $P \times H \times W \times D_{feat}$, where $P$ is the number of depth planes, $H$ and $W$ are image height and width, and $D_{feat}$ is the feature dimension.

**Data Structures:**
- **Frustum Volume:** A 3D array with dimensions $(P, H, W)$. Each cell $(p, h, w)$ corresponds to a voxel in the camera frustum.
- **Point Features:** Each point $i$ has an initial feature vector of dimension 11, initialized as:
  - 5 dimensions: 0.5 (placeholder or positional encoding)
  - 3 dimensions: RGB color values
  - 3 dimensions: Viewpoint direction vector
  - Only the first 8 dimensions are updated during training [S1].

**Steps:**
1. **Frustum Definition:** Define the camera frustum using the minimum depth $z_{min}$ and maximum depth $z_{max}$ of the projected point cloud. The frustum length is $l = z_{max} - z_{min}$ [S1].
2. **Voxelization:** Divide the frustum into $P$ uniform slices along the z-axis. Each slice corresponds to a depth plane $p \in \{0, \dots, P-1\}$. The spatial resolution is $H \times W$, matching the image dimensions. This creates $P \times H \times W$ frustum voxels [S1].
3. **Point Projection:** For each point $i$, project its 3D coordinates onto the image plane to determine the pixel coordinates $(h_i, w_i)$. Determine the depth plane index $p_i$ based on the point's depth $z_i$ relative to the frustum bounds.
4. **Distance Calculation:** For each point $i$ assigned to voxel $(p, h, w)$, calculate two distances:
   - $D1(p,h,w)_i$: The Euclidean distance between the point's projection on the image plane and the center of the pixel $(h, w)$. $D1 \in (0, 1/\sqrt{2})$ [S1].
   - $D2(p,h,w)_i$: The depth difference between the point and the minimum depth point in the voxel. $D2 \in (0, l)$ [S1].
5. **Weight Calculation:** Compute the aggregation weight $w(p,h,w)_i$ for point $i$ in voxel $(p, h, w)$ using the formula:
   $$w(p,h,w)_i = (1 - D1(p,h,w)_i)^a \times \left(\frac{1}{1 + D2(p,h,w)_i}\right)^b$$
   where $a$ and $b$ are hyperparameters controlling the influence of parallel and vertical distances, respectively [S1].
6. **Feature Aggregation:** For each voxel $(p, h, w)$, aggregate the features of all points $i$ assigned to it:
   $$F(p,h,w) = \frac{\sum_{i \in Voxel(p,h,w)} w(p,h,w)_i \cdot f_i}{\sum_{i \in Voxel(p,h,w)} w(p,h,w)_i}$$
   If no points are assigned to a voxel, the feature vector is initialized to zero or a default value [G].

**Parameters:**
- $P$: Number of depth planes. Typical values: 32 [S1].
- $H, W$: Image height and width. Typical values: $480 \times 640$ for ScanNet, $512 \times 640$ for Matterport 3D [S1].
- $a, b$: Blending weight exponents. Typical values: $a=1, b=1$ [S1].

**Edge Cases and Pitfalls:**
- If $b \to \infty$, the method degenerates to selecting the closest point via z-buffer, which is not robust against geometry errors and causes temporal jitters [S1].
- Precision issues may arise if $D1$ or $D2$ are not normalized correctly. Ensure $D1$ is bounded by $(0, 1/\sqrt{2})$ and $D2$ by $(0, l)$ [S1].

## Subtopics

### [Multi-plane Neural Rendering](15529-multi-plane-neural-rendering.md)
A rendering technique using a U-Net-like 3D CNN backbone to predict multi-plane RGB images and blending weights, which are composited to form the final output image. It builds on the aggregated features from Frustum Voxelization and Feature Aggregation.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of points and voxels. The aggregation step requires iterating over all points and updating voxel features.
- **Memory Complexity:** $O(P \times H \times W \times D_{feat})$ for storing the frustum volume.
- **Performance:** Training takes approximately 41.5 hours per scene on a GeForce 1080 Ti [S1].
- **Strengths:** Efficiently handles sparse point clouds by restricting them to the camera frustum. The distance-based weighting provides smooth feature aggregation.
- **Limitations:** Sensitive to the choice of $b$; large values lead to z-buffer-like behavior. Requires careful initialization of point features.

## Background
Frustum Voxelization and Feature Aggregation was introduced in "Neural Point Cloud Rendering via Multi-Plane Projection" [S1]. It is part of a pipeline that combines point cloud rendering with neural networks to generate high-quality novel views. The method addresses the limitations of direct point cloud rendering by providing a structured representation that can be processed by 3D CNNs.
