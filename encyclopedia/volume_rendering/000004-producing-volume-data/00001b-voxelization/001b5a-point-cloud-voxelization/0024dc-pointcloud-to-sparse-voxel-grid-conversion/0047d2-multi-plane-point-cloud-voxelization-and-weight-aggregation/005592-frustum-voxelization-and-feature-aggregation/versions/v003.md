# Frustum Voxelization and Feature Aggregation

Also called: Feature Aggregation, Frustum Voxelization

## Overview
Frustum Voxelization and Feature Aggregation is a preprocessing method that maps a 3D point cloud into a structured 3D volume within the camera frustum to facilitate multi-plane neural rendering. It solves the problem of organizing sparse, noisy point cloud data for rendering by grouping points into voxels and computing aggregation weights based on spatial proximity. Unlike direct 2D projection methods that suffer from visibility verification issues and noise interference, this approach maintains all features within the field-of-view, allowing subsequent 3D convolutional networks to learn visibility and handle occlusions robustly [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D point cloud with associated features (e.g., RGB, viewpoint direction), camera parameters (intrinsics, extrinsics), and rendering bounds (minimum and maximum depth planes).
*   **Output:** A frustum volume of dimensions $P \times H \times W$, where each voxel contains aggregated features and blending weights for the corresponding multi-plane rendering step.

**Data Structures:**
The frustum volume is a 3D grid with dimensions $(P, H, W)$.
*   $P$: Number of depth planes (slices along the z-axis).
*   $H$: Height of the image resolution.
*   $W$: Width of the image resolution.
Each voxel $(p, h, w)$ stores aggregated point features. The source specifies a point feature dimension of 11, initialized as 0.5 (5 dimensions) + RGB (3 dimensions) + viewpoint direction (3 dimensions), though only the first 8 dimensions are updated during training [S1].

**Steps:**
1.  **Frustum Definition:** Define the camera frustum region bounded by the minimum and maximum depth planes of the projected point cloud [S1].
2.  **Voxelization:** Divide the frustum uniformly along the z-axis into $P$ slices. The spatial resolution of each slice corresponds to the image dimensions $H \times W$. This creates $P \times H \times W$ frustum voxels [S1].
3.  **Point Projection:** Project each 3D point from the point cloud onto the image plane to determine its corresponding pixel coordinates $(h, w)$ and depth $z$.
4.  **Distance Calculation:** For each point $i$ falling into a specific voxel $(p, h, w)$, calculate two distances:
    *   $D1(p,h,w)_i$: The Euclidean distance between the point's projection on the image plane and the center of the pixel $(h, w)$ in the parallel direction. $D1 \in (0, 1/\sqrt{2})$ [S1].
    *   $D2(p,h,w)_i$: The depth difference between the point and the minimum depth point within that voxel. $D2 \in (0, l)$, where $l$ is the length of the frustum along the z-axis [S1].
5.  **Weight Computation:** Compute the blending weight $w(p,h,w)_i$ for point $i$ in voxel $(p, h, w)$ using the formula:
    $$w(p,h,w)_i = (1 - D1(p,h,w)_i)^a \times \left(\frac{1}{1 + D2(p,h,w)_i}\right)^b$$
    where $a$ and $b$ are parameters controlling the blending weights for the parallel and vertical (depth) directions, respectively [S1].
6.  **Feature Aggregation:** Aggregate the features of all points falling into voxel $(p, h, w)$ using the computed weights. Points closer to the pixel center and with smaller depth differences receive higher weights.

**Parameters:**
*   $a$: Controls parallel direction blending. Typical value: $1$ [S1].
*   $b$: Controls vertical (depth) direction blending. Typical value: $1$ [S1].
*   $P$: Number of planes. Typical values: $32$ for ScanNet and Matterport 3D datasets [S1].
*   $H, W$: Image resolution. Typical values: $480 \times 640$ for ScanNet, $512 \times 640$ for Matterport 3D [S1].

**Pitfalls:**
*   If $b$ approaches infinity, the method degenerates to selecting the closest point via z-buffer (as in Aliev et al.), which is not robust against geometry errors and causes temporal jitters [S1].
*   Precision issues may arise if $D1$ or $D2$ are not normalized correctly relative to the bounds $(0, 1/\sqrt{2})$ and $(0, l)$ [S1].

**Pseudocode:**
```python
def frustum_voxelization_and_aggregation(points, features, camera_intrinsics, camera_extrinsics, min_depth, max_depth, P, H, W, a=1, b=1):
    """
    Voxelize point cloud into frustum volume and aggregate features.
    
    Args:
        points: Nx3 array of 3D point coordinates.
        features: Nx11 array of point features.
        camera_intrinsics: 3x3 matrix.
        camera_extrinsics: 4x4 matrix.
        min_depth: float, minimum depth of the frustum.
        max_depth: float, maximum depth of the frustum.
        P: int, number of depth planes.
        H: int, image height.
        W: int, image width.
        a: float, parallel blending parameter.
        b: float, vertical blending parameter.
        
    Returns:
        volume: P x H x W x 11 array, aggregated features.
        weights: P x H x W array, aggregated weights (optional, for debugging).
    """
    # Initialize volume
    volume = np.zeros((P, H, W, 11))
    weight_sum = np.zeros((P, H, W))
    
    # Frustum length
    l = max_depth - min_depth
    
    # Project points to image plane
    # Transform points to camera coordinates
    points_homogeneous = np.hstack([points, np.ones((points.shape[0], 1))])
    points_camera = (camera_extrinsics @ points_homogeneous.T).T[:, :3]
    
    # Project to 2D
    points_2d = (camera_intrinsics @ points_camera.T).T
    u = points_2d[:, 0] / points_2d[:, 2]
    v = points_2d[:, 1] / points_2d[:, 2]
    depth = points_2d[:, 2]
    
    # Map to pixel coordinates
    # Assuming standard image coordinate system where (0,0) is top-left
    # u, v are in pixels
    h_idx = np.floor(v).astype(int)
    w_idx = np.floor(u).astype(int)
    
    # Filter points within image bounds
    valid_mask = (h_idx >= 0) & (h_idx < H) & (w_idx >= 0) & (w_idx < W)
    valid_mask &= (depth >= min_depth) & (depth <= max_depth)
    
    points_camera_valid = points_camera[valid_mask]
    features_valid = features[valid_mask]
    h_idx_valid = h_idx[valid_mask]
    w_idx_valid = w_idx[valid_mask]
    depth_valid = depth[valid_mask]
    
    # Calculate plane index p for each point
    # Uniformly split frustum into P planes
    # Plane p corresponds to depth range [min_depth + p * (l/P), min_depth + (p+1) * (l/P))
    plane_indices = np.floor((depth_valid - min_depth) / (l / P)).astype(int)
    plane_indices = np.clip(plane_indices, 0, P - 1)
    
    # Pixel centers for D1 calculation
    pixel_centers_h = h_idx_valid + 0.5
    pixel_centers_w = w_idx_valid + 0.5
    
    # Calculate D1: distance in parallel direction (image plane)
    # D1 is Euclidean distance between point projection and pixel center
    D1 = np.sqrt((u[valid_mask] - pixel_centers_w)**2 + (v[valid_mask] - pixel_centers_h)**2)
    
    # Calculate D2: depth difference within the voxel
    # D2 is depth difference between point and minimum depth point in this voxel
    # Note: The source says "minimum depth point in this voxel". 
    # This implies we need to know the min depth of the voxel. 
    # Since voxels are uniform slices, the min depth of voxel p is min_depth + p * (l/P).
    voxel_min_depths = min_depth + plane_indices * (l / P)
    D2 = depth_valid - voxel_min_depths
    
    # Clip D1 and D2 to valid ranges as per source
    # D1 in (0, 1/sqrt(2)), D2 in (0, l)
    # Note: D1 can be 0 if point is exactly at center. Source says (0, ...), likely meaning non-negative.
    # We assume standard Euclidean distance which is >= 0.
    # D2 should be >= 0 since point is within the frustum and plane index is floor.
    
    # Compute weights
    # w = (1 - D1)^a * (1 / (1 + D2))^b
    # Handle D1 > 1 to avoid negative base for non-integer a? Source says D1 in (0, 1/sqrt(2)) approx 0.707.
    # So 1 - D1 is always positive.
    weights = ((1 - D1)**a) * ((1 / (1 + D2))**b)
    
    # Aggregate features
    # volume[p, h, w, :] += features[i] * weights[i]
    # weight_sum[p, h, w] += weights[i]
    
    # Using advanced indexing for aggregation
    # Flatten indices for vectorization
    p_flat = plane_indices
    h_flat = h_idx_valid
    w_flat = w_idx_valid
    
    # Accumulate weighted features
    for i in range(len(p_flat)):
        p = p_flat[i]
        h = h_flat[i]
        w = w_flat[i]
        w_val = weights[i]
        vol = features_valid[i] * w_val
        volume[p, h, w, :] += vol
        weight_sum[p, h, w] += w_val
        
    # Normalize by weight sum to get weighted average
    # Avoid division by zero
    weight_sum_safe = np.where(weight_sum > 0, weight_sum, 1)
    volume = volume / weight_sum_safe[:, :, :, np.newaxis]
    
    return volume, weight_sum
```

## Subtopics

### [Multi-plane Neural Rendering](15529-multi-plane-neural-rendering.md)
Multi-plane Neural Rendering is a deep learning pipeline that renders images from raw 3D point clouds by projecting features into a layered 3D volume within the camera frustum, rather than directly onto a 2D image plane. Unlike previous methods that project features directly to 2D and suffer from visibility verification problems and noise interference, this method maintains all features from points in the field-of-view, allowing a 3D CNN to automatically learn visibility and handle occlusions. It produces more stable renderings, particularly near object boundaries, and is robust to noisy and relatively sparse point clouds.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of points $N$ for projection and aggregation steps, $O(N)$. The volume size is $P \times H \times W$, so initialization and normalization are $O(PHW)$.
*   **Memory Complexity:** $O(PHW \times D)$, where $D$ is the feature dimension (11 in the source). For typical settings ($32 \times 480 \times 640 \times 11$ bytes), this is manageable but significant for high resolutions.
*   **Measured Performance:** Trained on GeForce 1080 Ti, taking ~41.5 hours per scene for 21 epochs [S1].
*   **Strengths:** Robust to noise and sparse point clouds; handles occlusions via 3D CNN; stable near boundaries [S1].
*   **Limitations:** Sensitive to parameter $b$; if $b \to \infty$, it degenerates to z-buffering, causing jitter [S1]. Requires careful initialization of features [S1].

## Background
The method was introduced in "Neural Point Cloud Rendering via Multi-Plane Projection" (CVPR 2020) [S1]. It builds on the idea of multi-plane rendering but adapts it to handle raw point clouds by voxelizing the frustum and aggregating features, addressing the limitations of direct 2D projection methods which struggle with visibility and noise [S1].
