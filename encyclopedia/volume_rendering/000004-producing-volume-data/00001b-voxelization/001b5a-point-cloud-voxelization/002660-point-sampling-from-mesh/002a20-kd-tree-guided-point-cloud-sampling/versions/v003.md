# KD-Tree Guided Point Cloud Sampling

Also called: sigma-based point cloud augmentation

## Overview
This method augments ground truth point clouds by generating samples near the original points, where the noise magnitude is scaled by local point density estimated via KD-tree nearest neighbor distances [S1, unofficial]. It prepares ground truth data for downstream voxelization or neural rendering pipelines by creating a denser, noise-perturbed dataset [S1, unofficial].

## How it works
**Inputs:** Ground truth point cloud from a `.ply`, `.xyz`, or `.npy` file [S1, unofficial].
**Outputs:** `.npz` file containing three arrays: `sample` (augmented points), `point` (original ground truth points), and `sample_near` (nearest ground truth point indices for each sample) [S1, unofficial].
**Data Structures:** Point cloud stored as an $(N, 3)$ array of `float32` values [S1, unofficial]. A KD-tree spatial index built on the normalized points for nearest neighbor queries [S1, unofficial].
**Parameters:** `K=51` nearest neighbors for density estimation [S1, unofficial]. `QUERY_EACH` augmentation passes, calculated as `1000000 // N` if `N <= 1000000`, else `1` [S1, unofficial]. Processing chunks of 60 points for noise generation and KD-tree queries split into 100 chunks to prevent memory overflow [S1, unofficial].
**Steps:**
1. Load the point cloud $P_{gt}$ of size $N$ from the specified file format [S1, unofficial].
2. Normalize to a unit cube by subtracting the center $C = \text{mean}(P_{gt})$ and dividing by the maximum dimension $D = \max(\text{max}(P_{gt}) - \text{min}(P_{gt}))$ [S1, unofficial].
3. Build a KD-tree on the normalized points $P_{norm}$ [S1, unofficial].
4. Query the KD-tree for $K=51$ nearest neighbors for each point to compute local sigma $\sigma_i$ as the distance to the 50th nearest neighbor (index 50 in the 0-indexed sorted distance array) [S1, unofficial]. Split this query into 100 chunks to avoid memory overflow [S1, unofficial].
5. Calculate `QUERY_EACH` [S1, unofficial]. For each pass, iterate through $P_{norm}$ in chunks of 60 points [S1, unofficial].
6. For each point in the chunk, generate noise $\epsilon \sim \mathcal{N}(0, 1)$ of shape $(3,)$ and compute the sample $p_{\text{sample}} = p_{\text{point}} + \sigma \cdot \epsilon$ [S1, unofficial].
7. Query the KD-tree for the nearest ground truth point for each generated sample to populate `sample_near` [S1, unofficial].
8. Save `sample`, `point`, and `sample_near` to an `.npz` file [S1, unofficial].
**Formula:** $x_{\text{sample}} = x_{\text{point}} + \sigma \cdot \mathcal{N}(0, 1)$, where $\sigma$ is the distance to the 50th nearest neighbor [S1, unofficial].
**Pitfalls:** KD-tree queries on large point clouds can cause memory overflow; split queries into 100 chunks [S1, unofficial]. Normalization maps points to a unit cube, ensuring consistent scale for downstream tasks [S1, unofficial].
**Pseudocode:**
```python
import numpy as np
from scipy.spatial import KDTree

def load_point_cloud(path):
    if path.endswith('.npy'):
        return np.load(path)
    return np.loadtxt(path, delimiter=' ')

def kd_tree_guided_sampling(input_path, output_path, k_neighbors=51, aug_chunk=60):
    points = load_point_cloud(input_path)
    N = points.shape[0]

    # Normalize to unit cube
    center = np.mean(points, axis=0)
    max_dim = np.ptp(points, axis=0).max()
    points_norm = (points - center) / max_dim

    # Build KD-tree
    tree = KDTree(points_norm)

    # Compute local sigma (distance to 50th neighbor)
    # Split query into 100 chunks to avoid memory overflow
    num_query_chunks = 100
    chunk_step = max(1, N // num_query_chunks)
    sigma = np.zeros(N, dtype=np.float32)

    for i in range(0, N, chunk_step):
        end = min(i + chunk_step, N)
        batch = points_norm[i:end]
        # Query k_neighbors + 1 to include self; 50th neighbor is at index 50
        dists, _ = tree.query(batch, k=k_neighbors + 1)
        sigma[i:end] = dists[:, 50].astype(np.float32)

    # Calculate augmentation passes
    query_each = 1000000 // N if N <= 1000000 else 1

    all_samples = []
    all_near_indices = []

    for _ in range(query_each):
        # Process points in chunks of 60
        for i in range(0, N, aug_chunk):
            end = min(i + aug_chunk, N)
            batch_pts = points_norm[i:end]
            batch_sig = sigma[i:end]

            # Generate noise and augment
            noise = np.random.normal(0.0, 1.0, size=(end - i, 3)).astype(np.float32)
            samples = batch_pts + batch_sig[:, np.newaxis] * noise

            # Find nearest ground truth point for each sample
            _, near_idx = tree.query(samples, k=1)

            all_samples.append(samples)
            all_near_indices.append(near_idx)

    # Save output
    np.savez(output_path,
             sample=np.vstack(all_samples),
             point=points_norm,
             sample_near=np.concatenate(all_near_indices))
```

## Subtopics

### [Point Cloud Normalization](7023-point-cloud-normalization.md)
Point Cloud Normalization standardizes the spatial distribution of 3D points to a canonical coordinate system and scale, ensuring consistent input for downstream voxelization or neural rendering pipelines. It differs from simple bounding-box normalization by offering multiple scaling strategies (average distance, max coordinate, or warp-based) to handle varying point densities and shapes [G]. This method prepares ground truth data for KD-Tree guided sampling by centering objects and constraining their extent.

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ for building the KD-tree, $O(N \cdot K \log N)$ for querying neighbors, where $N$ is the number of points and $K$ is the number of neighbors [G].
- **Memory Complexity:** $O(N)$ for storing points and sigma values [G].
- **Performance:** Efficient for point clouds up to a few million points, provided memory is managed via chunking [S1, unofficial].
- **Strengths:** Adapts to local density, providing more samples in sparse regions [S1, unofficial].
- **Limitations:** Computationally expensive for very large point clouds due to KD-tree queries [S1, unofficial].

## Background
This method preprocesses ground truth point clouds for tasks such as volume rendering or voxelization, where a denser and more uniformly distributed set of points is beneficial [S1, unofficial].
