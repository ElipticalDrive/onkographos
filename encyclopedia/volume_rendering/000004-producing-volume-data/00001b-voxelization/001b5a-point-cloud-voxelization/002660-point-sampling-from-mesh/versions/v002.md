# Point Sampling from Mesh
## Overview
Point Sampling from Mesh generates a discrete set of 3D coordinates on the surface of a polygon mesh [S1, unofficial]. It bridges continuous mesh representations and discrete point-based volume data structures for downstream voxelization or neural field training [S1, unofficial]. It differs from [Point Cloud Voxelization](1000-point-cloud-voxelization.md) by generating points from a mesh source rather than consuming an existing point cloud, and from [Interior Voxelize](995-interior-voxelize.md) by targeting the surface boundary rather than the volume interior [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A mesh defined by vertex positions $V \in \mathbb{R}^{N_v \times 3}$ and face indices $F \in \mathbb{N}^{N_f \times 3}$ [S1, unofficial].
- **Output:** A set of sampled points $P \in \mathbb{R}^{N_s \times 3}$, where $N_s$ is the requested number of points [S1, unofficial].

**Data Structures:**
The implementation relies on batching to manage memory [S1, unofficial]. The core data structure is a list of sampled point arrays, concatenated at the end [S1, unofficial]. For GPU execution, PyTorch3D `Meshes` objects are used [S1, unofficial]. For CPU execution, `trimesh.Trimesh` objects are used [S1, unofficial].

**Parameters:**
- `num_points`: Total number of points to sample. Default: 100,000,000 [S1, unofficial].
- `batch_size`: Number of points sampled per iteration to manage memory. Default: 10,000,000 [S1, unofficial].
- `device`: Execution device, either `'cpu'` or a GPU device identifier [S1, unofficial].

**Steps:**
1. Compute min and max bounding box coordinates from mesh vertices [S1, unofficial].
2. Convert vertices and faces to the appropriate tensor or object format for the selected device [S1, unofficial].
3. If `device` is not `'cpu'`, use PyTorch3D's `sample_points_from_meshes` in batches [S1, unofficial].
4. If `device` is `'cpu'`, use Trimesh's `sample_surface` in batches [S1, unofficial].
5. Concatenate all sampled point arrays and truncate to exactly `num_points` [S1, unofficial].

**Pseudocode:**
```python
import numpy as np
import torch

def sample_points_from_mesh(verts, faces, num_points=100000000, batch_size=10000000, device='cpu'):
    samples_list = []
    num_batches = (num_points + batch_size - 1) // batch_size

    if device != 'cpu':
        verts_cuda = torch.tensor(verts, dtype=torch.float32, device=device).unsqueeze(0)
        faces_cuda = torch.tensor(faces, dtype=torch.int64, device=device).unsqueeze(0)
        from pytorch3d.structures import Meshes
        from pytorch3d.ops import sample_points_from_meshes
        cu_mesh = Meshes(verts=verts_cuda, faces=faces_cuda)

        for i in range(num_batches):
            current_batch_size = min(batch_size, num_points - i * batch_size)
            if current_batch_size <= 0:
                break
            sampled_points = sample_points_from_meshes(cu_mesh, num_samples=current_batch_size)[0]
            samples_list.append(sampled_points.cpu().numpy())
    else:
        import trimesh
        mesh = trimesh.Trimesh(vertices=verts, faces=faces)
        for i in range(num_batches):
            current_batch_size = min(batch_size, num_points - i * batch_size)
            if current_batch_size <= 0:
                break
            samples_points = trimesh.sample.sample_surface(mesh, current_batch_size)[0]
            samples_list.append(samples_points)

    if not samples_list:
        return np.empty((0, 3))
    all_samples = np.concatenate(samples_list, axis=0)
    return all_samples[:num_points]
```

## Subtopics

### [KD-Tree Guided Point Cloud Sampling](4715-kd-tree-guided-point-cloud-sampling.md)
A variant that augments ground truth point clouds by generating samples near the original points, where the noise magnitude is scaled by local point density estimated via KD-tree nearest neighbor distances [G]. It solves the problem of sparse or unevenly distributed input points by creating a denser, noise-perturbed dataset for downstream voxelization or rendering tasks [G]. It differs from uniform sampling by adapting noise to local geometry density, ensuring samples cluster more tightly in sparse regions and spread out in dense regions [G].

### Latent Vector to Point Cloud Generation
A pipeline step that generates a mesh from a latent vector and then samples points from it [S2, unofficial]. It creates a temporary PLY mesh file using either `create_mesh` or `create_mesh_speedup` depending on the `meshcreator_type` [S2, unofficial]. If mesh creation fails, it returns `None` [S2, unofficial]. It then samples points from the PLY mesh using `trimesh.sample.sample_surface` [S2, unofficial]. Finally, it cleans up the temporary file, either removing it or renaming it to the provided `fname` [S2, unofficial].

### Gaussian Kernel Sampling for Simulation
Sampling points from NeuS mesh surface for simulation to ensure uniform distribution, separate from trained Gaussian kernels used for rendering [S3]. It initializes GMLS kernels on simulation points $S_s$ and finds $k$ nearest neighbors $\{p^0_{s,j}\}$ from $S_s$ for each rendering point $p_{r,i}$ in $S_r$ [S3]. As simulation proceeds, it updates rendering point $p_{r,j}$ by interpolating from evolved simulation positions $\{p^n_{s,j}\}$ using pre-built GMLS kernel [S3]. It interpolates deformation gradient $F$ in the same way as position, replacing physical quantity position $p$ with deformation gradient $F$ [S3]. Sampling from trained Gaussian kernels results in uneven distribution, sparsely sampled regions (especially thin parts), and inaccurate boundary descriptions, affecting simulation quality [S3].

## Operating characteristics
- **Time Complexity:** $O(N_s)$ for sampling $N_s$ points, assuming constant-time sampling per point from the underlying library [G]. The batching adds overhead proportional to the number of batches [S1, unofficial].
- **Memory Complexity:** $O(N_s)$ to store the output points [G]. Intermediate memory usage is $O(B_{batch})$ due to batching [S1, unofficial].
- **Strengths:** Simple to implement using existing libraries; supports large-scale point generation via batching [S1, unofficial].
- **Limitations:** Requires the mesh to be valid for the underlying library; GPU method requires PyTorch3D installation; CPU method may be slow for very high point counts [G].
- **When to Use:** When a discrete point representation of a mesh surface is needed for neural network input, point cloud processing, or as an intermediate step for voxelization [G].
- **When Not to Use:** When volume interior information is required (use [Interior Voxelize](995-interior-voxelize.md)); when rasterization-based coverage is needed for rendering (use [Rasterization-based Voxelization](908-rasterization-based-voxelization.md)) [G].

## Background
Point sampling from meshes is a fundamental operation in computer graphics and geometric deep learning [G]. It allows for the conversion of continuous surface representations into discrete point sets, which are easier to process with neural networks or for generating training data for implicit surface reconstruction [G]. The specific implementation details described here are derived from research repositories used in deep continuous functions and neural rendering pipelines [S1, S2, unofficial].
