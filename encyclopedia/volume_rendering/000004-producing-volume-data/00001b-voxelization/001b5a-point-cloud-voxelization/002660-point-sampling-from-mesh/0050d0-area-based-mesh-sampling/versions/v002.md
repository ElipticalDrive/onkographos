# Area-Based Mesh Sampling

Also called: Area-Based sampling

## Overview
Area-Based Mesh Sampling is a method to sample points from a mesh surface by distributing them proportionally to triangle area [S1]. It solves the problem of generating a point cloud from a triangular mesh for downstream volume rendering or voxelization tasks [S1]. It differs from KD-Tree Guided Point Cloud Sampling by relying on explicit area calculations rather than spatial data structures for distribution [S1].

## How it works
**Inputs:** A triangular mesh defined by vertices and faces; a surface density parameter $\rho$ (points per square unit) [S1].
**Outputs:** A set of 3D points sampled on the mesh surface [S1].

**Data Structures:**
*   **Mesh:** List of triangles, each defined by 3 vertices. Each triangle has an associated area $A_i$.
*   **Point Count:** For each triangle $i$, a floating-point number $m_i$ representing the expected number of points.

**Steps:**
1.  Calculate the area $A_i$ for each triangle $i$ in the mesh.
2.  Compute the required point count $m_i$ for each triangle using the density parameter $\rho$:
    $$ m_i = A_i \times \rho $$
    Here, $m_i \in \mathbb{R} \setminus \mathbb{Z}$ generally, as it is a real number not necessarily an integer [S1].
3.  Determine the integer base count $k_i = \lfloor m_i \rfloor$ and the fractional part $f_i = m_i - k_i$ for each triangle [S1].
4.  Sample $k_i$ points uniformly within triangle $i$.
5.  For each triangle $i$, perform a probabilistic check: generate a random number $r \in [0, 1)$. If $r < f_i$, sample one additional point uniformly within triangle $i$ [S1].
6.  Collect all sampled points into a point cloud.

**Pseudocode:**
```python
import random
import math

def sample_area_based(mesh, density):
    """
    mesh: list of triangles, where each triangle is a list of 3 vertices (x, y, z)
    density: float, points per square unit
    returns: list of points (x, y, z)
    """
    points = []
    
    for triangle in mesh:
        # Calculate area of the triangle
        v0, v1, v2 = triangle
        # Vector cross product magnitude / 2
        ax, ay, az = v1[0]-v0[0], v1[1]-v0[1], v1[2]-v0[2]
        bx, by, bz = v2[0]-v0[0], v2[1]-v0[1], v2[2]-v0[2]
        area = 0.5 * math.sqrt((ay*bz - az*by)**2 + (az*bx - ax*bz)**2 + (ax*by - ay*bx)**2)
        
        # Calculate expected number of points
        m = area * density
        k = int(math.floor(m))
        f = m - k
        
        # Sample k points uniformly
        for _ in range(k):
            points.append(sample_point_in_triangle(v0, v1, v2))
            
        # Probabilistic additional point
        if random.random() < f:
            points.append(sample_point_in_triangle(v0, v1, v2))
            
    return points

def sample_point_in_triangle(v0, v1, v2):
    """
    Uniformly sample a point inside a triangle using barycentric coordinates.
    """
    r1 = random.random()
    r2 = random.random()
    
    # Ensure uniform distribution
    if r1 + r2 > 1:
        r1 = 1 - r1
        r2 = 1 - r2
        
    # Barycentric coordinates
    w0 = 1 - r1 - r2
    w1 = r1
    w2 = r2
    
    x = w0*v0[0] + w1*v1[0] + w2*v2[0]
    y = w0*v0[1] + w1*v1[1] + w2*v2[1]
    z = w0*v0[2] + w1*v1[2] + w2*v2[2]
    
    return (x, y, z)
```

**Parameters:**
*   $\rho$ (density): Typical values depend on the desired resolution of the resulting volume or point cloud. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Zero Area Triangles:** Triangles with zero area (degenerate) will have $m_i=0$ and contribute no points. This is handled naturally by the formula.
*   **Precision:** Floating-point precision in area calculation and random number generation affects the exact count. The probabilistic step ensures the *expected* number of points matches the area proportion, but the actual count varies per triangle.
*   **Boundary Conditions:** The method samples strictly inside the triangles. Vertices and edges are not explicitly prioritized, though they are covered by the interior sampling.

## Subtopics

### [Poisson Disk Sampling](14313-poisson-disk-sampling.md)
Poisson disk sampling is a surface sampling method that uniformly distributes points on a mesh's surface with a minimum geodesic distance constraint of $2r$ between them, given a disk of radius $r$. It utilizes blue noise properties to reduce the effects of aliasing in the later steps of the resulting model. It differs from its parent, Area-Based Mesh Sampling, by enforcing a strict minimum distance constraint rather than relying solely on area-proportional probability, and from Fast Poisson Disk Sampling (2D) by operating on the curved surface of a 3D mesh rather than a flat 2D domain.

### GeoSplatting Vertex-Sampling
A temporary sampling strategy used during the first 5% of training to reduce memory costs when FlexiCubes isovalues are randomly initialized and produce excessive triangle slices [S2]. For each mesh vertex $v$ with normal $n_v$, it samples a single Gaussian point with mean $\mu=v$, normal $n=n_v$, scaling $s_x=s_y=\sqrt{\frac{k}{3}\sum_{F_i \in \text{Star}(v)} \text{Area}(F_i)}$, scaling $s_z=\delta_{jk}$, rotation $r_x=(0,0,1) \times n_v$, rotation $r_y=n_v \times r_x$, rotation $r_z=n_v$ [S2]. After the first 5% of training, it switches from vertex-sampling to face-sampling [S2].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of triangles $N$, $O(N)$, as each triangle is processed independently [S1].
*   **Memory Complexity:** Linear with respect to the number of output points, which is proportional to the total surface area and density [S1].
*   **Strengths:** Simple to implement; ensures uniform distribution relative to surface area; probabilistic step allows for exact expected counts [S1].
*   **Limitations:** Does not enforce minimum distance between points (unlike Poisson Disk); points may cluster in large triangles if not enough are sampled [S1].
*   **When to use:** When a uniform area-proportional distribution is sufficient and simplicity is preferred.
*   **When not to use:** When minimum distance constraints are required to avoid aliasing or clustering.
