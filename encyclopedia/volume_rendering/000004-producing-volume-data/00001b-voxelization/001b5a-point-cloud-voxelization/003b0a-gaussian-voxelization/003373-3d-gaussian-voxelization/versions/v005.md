# 3D Gaussian Voxelization

Also called: Voxelization of 3D Gaussians

## Overview
3D Gaussian Voxelization converts a continuous set of 3D Gaussian primitives into a discrete set of unique voxels and their associated features, enabling efficient processing by 3D neural networks [S1, unofficial]. It differs from standard point cloud voxelization by explicitly accounting for the spatial extent and shape of each Gaussian to determine voxel occupancy, and from splat-to-voxel transfer by focusing on feature embedding for network input rather than direct rasterization [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A list of 3D Gaussians, where each Gaussian contains parameters such as position, scale, and orientation. A `grid_size` float defining the physical dimensions of each voxel cell.
*   **Output:**
    *   `uni_voxels_xyz`: A list of tuples `(x, y, z)` representing the coordinates of unique voxels.
    *   `uni_voxel_feats`: A list of feature vectors corresponding to each unique voxel.
    *   `inverse_indices`: A list of integers mapping each originally generated voxel to its index in the unique voxel list.
    *   `num_voxels_per_g`: A list of integers indicating the number of voxels sampled from each 3D Gaussian.

**Data Structures:**
The implementation relies on three helper functions:
1.  `count_voxels_per_g(gaussians, grid_size)`: Determines the number of voxels required for each Gaussian based on the sampling shape.
2.  `compose_voxel_features(gaussians, num_voxels_per_g)`: Generates voxel coordinates and feature attributes for all Gaussians.
3.  `return_unique_voxels(voxels_xyz, voxel_feats)`: Deduplicates the generated voxels, aggregating features and creating the inverse index map.

**Parameters:**
*   `SAMPLE_SHAPE`: A literal type `["volume", "tri-plane", "tri-line", "center"]` controlling the geometric shape used for sampling voxels around each Gaussian. Default is `"center"` [S1, unofficial].
*   `grid_size`: Hyperparameter defining the physical size of each voxel cell [S1, unofficial].

**Algorithm Steps:**
1.  **Count Voxels:** For each Gaussian in the input list, determine the number of voxels it will occupy using `count_voxels_per_g`. This step uses `SAMPLE_SHAPE` to define the spatial footprint (e.g., a single center point, a line, a plane, or a volume) relative to the Gaussian's scale and orientation.
2.  **Compose Features:** Generate the specific voxel coordinates and associated feature values for all Gaussians using `compose_voxels_features`. This distributes the Gaussian's attributes (such as color, opacity, or higher-dimensional features) to the calculated voxel positions.
3.  **Deduplicate:** Pass the generated voxel coordinates and features to `return_unique_voxels`. This function identifies duplicate voxel entries (voxels occupied by multiple Gaussians or overlapping regions of a single Gaussian), aggregates their features (typically via summation or averaging, though specific aggregation logic is implementation-dependent), and constructs the `inverse_indices` map to track the origin of each unique voxel.

**Pseudocode:**
```python
from typing import List, Tuple
from typing_extensions import Literal

# Global configuration
SAMPLE_SHAPE: Literal["volume", "tri-plane", "tri-line", "center"] = "center"

def voxelization(gaussians: List[dict], grid_size: float) -> Tuple[List[Tuple[float, float, float]], List, List[int], List[int]]:
    """
    Convert a set of 3D Gaussians into a set of unique voxels and their associated features.
    
    Args:
        gaussians: List of 3D Gaussian parameters (e.g., position, scale, orientation, features).
        grid_size: Physical size of each voxel cell.
        
    Returns:
        uni_voxels_xyz: Coordinates of unique voxels.
        uni_voxel_feats: Feature vectors for unique voxels.
        inverse_indices: Mapping from original voxels to unique voxels.
        num_voxels_per_g: Number of voxels sampled per Gaussian.
    """
    # Step 1: Determine voxel count per Gaussian based on shape and size
    num_voxels_per_g = count_voxels_per_g(gaussians, grid_size)
    
    # Step 2: Generate voxel coordinates and features for all Gaussians
    # This produces a list of all generated voxels (including duplicates)
    all_voxels_xyz, all_voxel_feats = compose_voxel_features(gaussians, num_voxels_per_g)
    
    # Step 3: Deduplicate voxels and aggregate features
    uni_voxels_xyz, uni_voxel_feats, inverse_indices = return_unique_voxels(all_voxels_xyz, all_voxel_feats)
    
    return uni_voxels_xyz, uni_voxel_feats, inverse_indices, num_voxels_per_g

# Helper functions are assumed to be defined elsewhere in the implementation
# def count_voxels_per_g(gaussians, grid_size): ...
# def compose_voxel_features(gaussians, num_voxels_per_g): ...
# def return_unique_voxels(voxels_xyz, voxel_feats): ...
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point coordinates for voxel centers must be handled consistently to avoid splitting identical voxels due to minor numerical differences.
*   **Boundary Conditions:** Gaussians extending beyond the defined grid boundaries must be clipped or ignored to prevent out-of-bounds indexing.
*   **Feature Aggregation:** When multiple Gaussians contribute to the same voxel, the aggregation method (sum, mean, max) significantly impacts the resulting feature representation. The source notes do not specify the default aggregation strategy within `return_unique_voxels` [S1, unofficial].

## Subtopics

### GaGS
GaGS is a method that voxelizes a set of Gaussian distributions and employs sparse convolutions to extract geometry-aware features for deformation learning in dynamic scenes [S2]. It is chosen when the goal is to model spatial-temporal deformation using an implicit deformation field (e.g., an MLP) rather than static rendering [S2]. Unlike static voxelization, GaGS integrates the voxelization step directly into a learning pipeline for dynamic 3D Gaussians [S2].

## Operating characteristics
*   **Time Complexity:** Dominated by the voxel generation and deduplication steps. The complexity depends on the number of Gaussians, the average number of voxels per Gaussian (determined by `SAMPLE_SHAPE` and scale), and the efficiency of the hash-based or sorting-based deduplication.
*   **Memory Complexity:** Proportional to the total number of generated voxels before deduplication, and the number of unique voxels after deduplication. Sparse storage is implied by the use of unique voxel lists.
*   **Strengths:** Enables the use of efficient 3D convolutional networks on Gaussian representations. Reduces the computational burden of processing continuous Gaussians by discretizing them into a grid structure [S1, unofficial].
*   **Limitations:** The choice of `SAMPLE_SHAPE` and `grid_size` critically affects the fidelity of the representation. Coarse grids may lose detail, while fine grids increase memory usage. The method is primarily designed for feature embedding for neural networks, not for direct differentiable rendering [S1, unofficial].
*   **When to use:** When integrating 3D Gaussians into 3D CNNs or sparse convolutional networks for tasks like deformation learning or feature extraction [S1, unofficial][S2].
*   **When not to use:** For direct rasterization-based rendering where splatting is more appropriate, or when high-fidelity continuous representation is required without discretization loss.

## Background
The method was introduced in the context of "Quantile Rendering: Efficiently Embedding High-dimensional Feature on 3D Gaussian Splatting" [S1, unofficial]. It addresses the need to process 3D Gaussian Splatting data with 3D neural networks, which typically operate on voxel grids. The approach was also utilized in GaGS for dynamic scene modeling, where voxelization facilitates the extraction of geometry-aware features for deformation learning [S2].
