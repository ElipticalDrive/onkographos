# Point Cloud Voxelization

Also called: Pointcloud to Dense Voxel Grid Conversion, Voxelization from Point Cloud

## Overview
Point Cloud Voxelization converts an unstructured set of 3D points into a discrete volumetric grid representation suitable for rendering or processing [S2][S3, S5, unofficial]. It solves the problem of mapping continuous spatial data into a fixed-resolution domain by assigning each point to a specific voxel cell based on its coordinates [S2][S3, unofficial]. Unlike [Hard Voxelization](5345-hard-voxelization.md), which may imply a simpler binary occupancy model, this method often aggregates features (such as color or intensity) from multiple points within a single voxel [S2][S3, unofficial]. It differs from [Point Cloud to Sparse Voxel Grid Conversion](3416-pointcloud-to-sparse-oxel-grid-conversion.md) by typically producing a dense array structure, whereas the latter explicitly manages sparsity via hash maps or sparse arrays to save memory [S3, S4, unofficial].

## How it works
The method maps input points to a 3D grid defined by a bounding box and voxel size. It handles boundary conditions (clamping or discarding) and aggregates point attributes into the resulting voxels.

### Inputs and Outputs
**Inputs:**
*   `points`: Array of shape $(N, D)$, where $N$ is the number of points and $D \ge 3$. The first three columns are coordinates $(x, y, z)$. Remaining columns are features (e.g., color, intensity) [S3, S5, unofficial].
*   `voxel_size`: Scalar or vector $(3,)$ defining the physical size of a voxel. If scalar, isotropic; if vector, anisotropic $(s_x, s_y, s_z)$ [S3, S4, unofficial].
*   `grid_range` or `bounds`: Defines the spatial extent.
    *   Format A: `grid_range` as $(6,)$ array $[min_x, min_y, min_z, max_x, max_y, max_z]$ [S3, unofficial].
    *   Format B: `start_location` $(3,)$ and `end_location` $(3,)$ [S5, unofficial].
    *   Format C: Auto-computed bounding box from point extrema, aligned to voxel grid [S4, unofficial].
*   `segment_func` (optional): Aggregation function for features (e.g., mean, sum, min, max). Default is mean [S5, unofficial].

**Outputs:**
*   **Dense Grid:** A 4D tensor/array of shape $(N_x, N_y, N_z, F)$ containing aggregated features, where $F$ is the feature dimension [S5, unofficial].
*   **Sparse Representation:** A tuple of arrays:
    *   `voxels`: Shape $(V, M, D)$, storing point data for $V$ active voxels, with a maximum of $M$ points per voxel [S3, unofficial].
    *   `coordinates`: Shape $(V, 3)$, storing the integer grid indices of active voxels [S3, unofficial].
    *   `num_points_per_voxel`: Shape $(V,)$, storing the count of points in each active voxel [S3, unofficial].

### Data Structures
1.  **Dense Array:** A contiguous 4D array. Memory usage is $N_x \times N_y \times N_z \times F \times \text{sizeof}(type)$.
2.  **Sparse Hash Map / Lookup Table:** A 3D array `coor_to_voxelidx` of shape $(N_z, N_y, N_x)$ initialized to $-1$, mapping grid coordinates to a sparse index in the output arrays [S3, unofficial].
3.  **Point Indices List:** A dictionary or list of lists mapping voxel IDs to the indices of original points contained within them [S4, unofficial].

### Steps
1.  **Define Grid Dimensions:**
    Calculate the number of voxels in each dimension.
    $$ N_x = \lfloor \frac{max_x - min_x}{s_x} \rfloor, \quad N_y = \lfloor \frac{max_y - min_y}{s_y} \rfloor, \quad N_z = \lfloor \frac{max_z - min_z}{s_z} \rfloor $$
    If bounds are auto-computed from points, $min_x = \lfloor \min(x) / s_x \rfloor \cdot s_x$ and $max_x = \lceil \max(x) / s_x \rceil \cdot s_x$ [S4, unofficial].

2.  **Compute Voxel Coordinates:**
    For each point $p_i = (x_i, y_i, z_i)$, compute its grid index $(i, j, k)$:
    $$ i = \lfloor \frac{x_i - min_x}{s_x} \rfloor, \quad j = \lfloor \frac{y_i - min_y}{s_y} \rfloor, \quad k = \lfloor \frac{z_i - min_z}{s_z} \rfloor $$
    Cast to integer type [S3, S5, unofficial].

3.  **Handle Boundaries:**
    *   **Discard:** Points where $i < 0$ or $i \ge N_x$ (or similarly for $j, k$) are discarded [S3, unofficial].
    *   **Clamp:** Points outside bounds are clamped to the nearest valid index (0 or $N-1$) [S5, unofficial].
    *   **Julia Variant:** Uses 1-based indexing, so indices are $i+1$ [S4, unofficial].

4.  **Aggregate Features (Dense Mode):**
    *   Flatten the 3D index $(i, j, k)$ to a 1D segment ID:
        $$ \text{seg\_id} = i \cdot (N_y N_z) + j \cdot N_z + k $$
    *   Apply `segment_func` to aggregate features for all points sharing the same `seg_id` [S5, unofficial].
    *   Reshape the result back to $(N_x, N_y, N_z, F)$ [S5, unofficial].

5.  **Aggregate Features (Sparse Mode):**
    *   Initialize `coor_to_voxelidx` with $-1$.
    *   Initialize `voxels`, `coordinates`, and `num_points_per_voxel` arrays with capacity `max_num_voxels` [S3, unofficial].
    *   Iterate through points:
        *   Look up `voxel_idx = coor_to_voxelidx[i, j, k]`.
        *   If `voxel_idx == -1`:
            *   Assign `voxel_idx = current_voxel_count`.
            *   Increment `current_voxel_count`.
            *   If `current_voxel_count > max_num_voxels`, stop or handle overflow [S3, unofficial].
            *   Set `coor_to_voxelidx[i, j, k] = voxel_idx`.
            *   Store coordinates: `coordinates[voxel_idx] = [i, j, k]`.
        *   Store point data:
            *   If `num_points_per_voxel[voxel_idx] < max_points_in_voxel`:
                *   `voxels[voxel_idx, num_points_per_voxel[voxel_idx]] = p_i`.
                *   Increment `num_points_per_voxel[voxel_idx]`.
            *   Else, discard excess points [S3, unofficial].

### Pseudocode (Sparse Implementation)
```python
def point_cloud_voxelization_sparse(points, voxel_size, grid_range, max_points_in_voxel=60, max_num_voxels=20000):
    """
    Converts a point cloud to a sparse voxel grid.
    points: (N, D) array, first 3 cols are x,y,z.
    voxel_size: (3,) array [sx, sy, sz].
    grid_range: (6,) array [min_x, min_y, min_z, max_x, max_y, max_z].
    """
    # 1. Compute grid size
    grid_size = np.floor((grid_range[3:] - grid_range[:3]) / voxel_size).astype(np.int32)
    
    # 2. Initialize lookup table and output buffers
    # coor_to_voxelidx shape: (nz, ny, nx)
    coor_to_voxelidx = np.full((grid_size[2], grid_size[1], grid_size[0]), -1, dtype=np.int32)
    voxels = np.zeros((max_num_voxels, max_points_in_voxel, points.shape[1]), dtype=points.dtype)
    coordinates = np.zeros((max_num_voxels, 3), dtype=np.int32)
    num_points_per_voxel = np.zeros(max_num_voxels, dtype=np.int32)
    
    # 3. Compute initial coordinates
    # points_copy[:, :3] are x,y,z
    coor = np.floor((points[:, :3] - grid_range[:3]) / voxel_size).astype(np.int32)
    
    # 4. Mask points within bounds
    mask = (
        (coor[:, 0] >= 0) & (coor[:, 0] < grid_size[0]) &
        (coor[:, 1] >= 0) & (coor[:, 1] < grid_size[1]) &
        (coor[:, 2] >= 0) & (coor[:, 2] < grid_size[2])
    )
    coor = coor[mask]
    points_valid = points[mask]
    
    # 5. Iterate and fill
    voxel_num = 0
    for i, c in enumerate(coor):
        # Note: Some implementations reverse axis order (c[::-1]) for memory layout; 
        # here we assume standard (x,y,z) -> (0,1,2) indexing into the array.
        # Adjust indexing if your language/library uses (z,y,x) or row-major vs col-major.
        voxel_id = coor_to_voxelidx[c[2], c[1], c[0]] # Assuming shape (nz, ny, nx)
        
        if voxel_id == -1:
            voxel_id = voxel_num
            voxel_num += 1
            if voxel_num > max_num_voxels:
                break
            coor_to_voxelidx[c[2], c[1], c[0]] = voxel_id
            coordinates[voxel_id] = c
            
        n_pts = num_points_per_voxel[voxel_id]
        if n_pts < max_points_in_voxel:
            voxels[voxel_id, n_pts] = points_valid[i]
            num_points_per_voxel[voxel_id] += 1
            
    return voxels[:voxel_num], coordinates[:voxel_num], num_points_per_voxel[:voxel_num]
```

### Parameters
*   `voxel_size`: Typical values depend on scene scale (e.g., 0.05 for unit-cube models, 2.0 meters for LiDAR) [S2][S4, unofficial].
*   `max_points_in_voxel`: Default 60 [S3, unofficial]. Controls memory per voxel.
*   `max_num_voxels`: Default 20,000 [S3, unofficial]. Limits total output size.
*   `segment_func`: `tf.math.unsorted_segment_mean` is common for color averaging [S5, unofficial].

### Edge Cases and Pitfalls
*   **Boundary Handling:** Sources disagree on whether to discard or clamp out-of-bounds points. [S3, unofficial] discards them via a mask; [S5, unofficial] clamps them to the nearest edge voxel. Implementers must check the specific library behavior [S3, S5, unofficial].
*   **Capacity Limits:** If the number of occupied voxels exceeds `max_num_voxels`, the loop breaks, leaving subsequent points unprocessed [S3, unofficial]. Similarly, if a voxel contains more than `max_points_in_voxel` points, the excess are discarded [S3, unofficial].
*   **Precision:** Floating-point division followed by floor can suffer from precision errors near boundaries. Using integer arithmetic or careful epsilon handling is recommended [G].
*   **Axis Order:** Some implementations (e.g., [S3, unofficial]) reverse the coordinate axis order (`::-1`) to match specific memory layouts or library conventions. This must be consistent with the downstream renderer [S3, unofficial].

## Subtopics

### [Octree Construction for Point Clouds](1070-octree-construction-for-point-clouds.md)
Constructs a hierarchical octree from point clouds, recursively subdividing space. It enables efficient frustum culling and view-dependent sampling, reducing rendering load for large datasets compared to flat grids.

### [Point Cloud to Gaussian Converter](1788-point-cloud-to-gaussian-converter.md)
Transforms points into isotropic Gaussian ellipsoids for differentiable volume rendering. It uses soft, probabilistic kernels based on local point proximity, distinguishing it from hard voxelization by providing a continuous density field.

### [Point Resampling with Neighbor Masking](2710-point-resampling-with-neighbor-masking.md)
Resamples point clouds based on active/neighbor status and tetrahedral connectivity to control density. It is a preprocessing step for voxelization rather than the voxelization itself.

### [Voxels to Points Projection](3172-voxels-to-points-projection.md)
Projects features from a dense voxel grid back to specific points using pre-computed segment IDs. It is the inverse operation of voxelization.

### [Pointcloud to Sparse Voxel Grid Conversion](3416-pointcloud-to-sparse-voxel-grid-conversion.md)
Maps points to a sparse grid using hash maps, storing only occupied cells. It differs from dense voxelization by memory efficiency and from simple occupancy by storing averaged geometric/color data.

### [Point Sampling from Mesh](3786-point-sampling-from-mesh.md)
Generates points from a mesh surface. It is a source generator for point clouds, distinct from voxelization which consumes existing points.

### [Ray Model Voxelization](4688-ray-model-voxelization.md)
Converts LiDAR points to occupancy grids by tracing rays from sensor origins. It explicitly models free space, unlike hard voxelization which only marks occupied voxels.

### [Hard Voxelization](5345-hard-voxelization.md)
Assigns each point to a specific voxel cell based on coordinates and fixed size. It is the foundational discrete assignment step [G].

### [Voxel-based Void Ratio Computation](6679-voxel-based-void-ratio-computation.md)
Computes void ratio fields by binning particles and calculating solid volume via sphere-box intersection. It focuses on precise geometric volume accounting rather than visual approximation.

### [Point Cloud Cropping and Downsampling](7057-point-cloud-cropping-and-downsampling.md)
Prepares point clouds by removing points outside a volume and reducing density. It operates prior to voxelization to fit hardware limits.

## Operating characteristics
*   **Time Complexity:** $O(N)$ for computing coordinates and $O(V \cdot M)$ for filling sparse buffers, where $N$ is points, $V$ is active voxels, and $M$ is max points per voxel. Dense aggregation is $O(N)$ with a constant factor for hashing/segmentation [S3, S5, unofficial].
*   **Memory Complexity:**
    *   Dense: $O(N_x N_y N_z)$. Can be prohibitive for large volumes with high resolution [S5, unofficial].
    *   Sparse: $O(V \cdot M)$. Efficient if the scene is sparse [S3, unofficial].
*   **Performance:** JIT-compiled versions (e.g., Numba) offer significant speedups over pure Python by avoiding interpreter overhead [S3, unofficial]. GPU acceleration is possible via parallel reduction for dense grids [S6878].
*   **Strengths:** Simple to implement; efficient for uniform sampling; supports feature aggregation [S2][S5, unofficial].
*   **Limitations:** Fixed resolution limits detail; boundary handling varies; sparse methods require careful capacity management [S3, S5, unofficial].
*   **When to Use:** When a discrete, regular grid is required for downstream processing (e.g., 3D CNNs, ray marching on a grid) and the scene fits within memory constraints [S2][S5, unofficial].

## Background
Point cloud voxelization is a fundamental technique in 3D computer vision and graphics, originating from the need to process unstructured sensor data (LiDAR, depth cameras) for tasks like object recognition and rendering [S2][S4, unofficial]. Early implementations used simple bounding box alignment [S4, unofficial]. Modern pipelines often integrate it into deep learning frameworks (TensorFlow, PyTorch) for differentiable rendering or feature extraction [S5, S1, unofficial]. The method is widely used in autonomous driving (LiDAR processing) and 3D reconstruction [S3, S4, unofficial].
