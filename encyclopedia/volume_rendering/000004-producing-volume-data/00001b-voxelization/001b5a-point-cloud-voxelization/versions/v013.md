# Point Cloud Voxelization

Also called: Pointcloud to Dense Voxel Grid Conversion, Voxelization from Point Cloud

## Overview
Point Cloud Voxelization converts an unstructured set of 3D points into a structured discrete voxel grid by mapping each point to a grid cell based on its spatial coordinates [S2][S5, unofficial]. It solves the problem of bridging continuous, irregular point data with grid-based processing pipelines used in volume rendering, 3D object detection, and neural fields [S3, S5, unofficial]. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) which projects geometry through a camera, or [Voxel Carving](1213-voxel-carving.md) which infers volume from silhouettes, this method directly bins points into cells, often aggregating features (e.g., color, normals) via averaging or other segment functions [S2][S5, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A point cloud array `points` of shape $(N, D)$, where $N$ is the number of points and $D \ge 3$ (first 3 dimensions are $x, y, z$ coordinates) [S3, S5, unofficial]. Optional features may follow [S5, unofficial].
- **Parameters:**
  - `voxel_size`: Physical dimensions of a voxel, shape $(3,)$ [S3, S5, unofficial].
  - `grid_range` or `start_location`/`end_location`: Bounding box defining the spatial extent of the grid [S3, S5, unofficial].
  - `max_num_voxels`: Maximum number of occupied voxels to allocate [S3, unofficial].
  - `max_points_in_voxel`: Maximum points stored per voxel [S3, unofficial].
  - `segment_func`: Aggregation function for features (e.g., mean, sum) [S5, unofficial].
- **Output:** A voxel grid representation. Common formats include:
  1. **Dense Tensor:** A 4D tensor of shape $(G_x, G_y, G_z, F)$ containing aggregated features [S5, unofficial].
  2. **Sparse Structure:** Arrays of `voxels` (point data), `coordinates` (grid indices), and `num_points_per_voxel` counts [S3, unofficial].

**Data Structures:**
- **Coordinate Mapping:** World coordinate $x$ maps to grid index $idx$ via:
  $$ idx = \lfloor \frac{x - origin}{voxel\_size} \rfloor $$
  where $origin$ is the minimum bound of the grid [S1, S3, S5, unofficial].
- **Sparse Index Map:** A 3D array `coor_to_voxelidx` of shape $(G_z, G_y, G_x)$ initialized to $-1$, mapping grid coordinates to a sparse linear voxel index [S3, unofficial].
- **Voxel Storage:**
  - `voxels`: Array of shape $(max\_num\_voxels, max\_points\_in\_voxel, D)$ storing point data [S3, unofficial].
  - `coordinates`: Array of shape $(max\_num\_voxels, 3)$ storing the grid indices of active voxels [S3, unofficial].
  - `num_points_per_voxel`: Array of shape $(max\_num\_voxels)$ storing point counts per voxel [S3, unofficial].

**Steps:**
1. **Grid Size Calculation:** Compute the number of voxels per axis:
   $$ G = \lfloor \frac{grid\_range_{max} - grid\_range_{min}}{voxel\_size} \rfloor $$
   Cast to integer [S3, S5, unofficial].
2. **Coordinate Discretization:** For each point $p_i$, compute its grid coordinate:
   $$ c_i = \lfloor \frac{p_i[:3] - grid\_range_{min}}{voxel\_size} \rfloor $$
   Cast to integer [S3, S5, unofficial].
3. **Boundary Handling:**
   - **Discard:** Points where any coordinate $c_i < 0$ or $c_i \ge G$ are discarded via a boolean mask [S3, unofficial].
   - **Clamp:** Alternatively, points outside bounds are clamped to the nearest edge voxel (index 0 or $G-1$) [S5, unofficial].
4. **Index Mapping:** Flatten the 3D grid coordinate $(i, j, k)$ to a 1D segment ID:
   $$ segment\_id = i \cdot (G_y G_z) + j \cdot G_z + k $$
   [S5, unofficial]. Or map to a sparse voxel index using `coor_to_voxelidx` [S3, unofficial].
5. **Feature Aggregation:**
   - **Dense Output:** Use `segment_func` (e.g., `tf.math.unsorted_segment_mean`) to aggregate point features into the dense grid [S5, unofficial].
   - **Sparse Output:** Iterate through points. If the voxel is new (`coor_to_voxelidx` is $-1$), assign a new voxel ID. Store the point in `voxels` at the current `num_points_per_voxel` index, incrementing the count. Stop if `max_num_voxels` or `max_points_in_voxel` is exceeded [S3, unofficial].

**Pseudocode (Sparse Output):**
```python
import numpy as np

def point_cloud_voxelization(points, voxel_size, grid_range, max_num_voxels=20000, max_points_in_voxel=60):
    """
    Converts a point cloud to a sparse voxel grid.
    points: (N, D) array, first 3 cols are x,y,z.
    voxel_size: (3,) array.
    grid_range: (6,) array [min_x, min_y, min_z, max_x, max_y, max_z].
    """
    # 1. Compute grid size
    grid_size = np.floor((grid_range[3:] - grid_range[:3]) / voxel_size).astype(np.int32)
    
    # 2. Initialize structures
    # coor_to_voxelidx maps (z, y, x) to sparse voxel index
    coor_to_voxelidx = np.full((grid_size[2], grid_size[1], grid_size[0]), -1, dtype=np.int32)
    voxels = np.zeros((max_num_voxels, max_points_in_voxel, points.shape[1]), dtype=points.dtype)
    coordinates = np.zeros((max_num_voxels, 3), dtype=np.int32)
    num_points_per_voxel = np.zeros(max_num_voxels, dtype=np.int32)
    
    # 3. Discretize coordinates
    points_copy = points.copy()
    coor = np.floor((points_copy[:, :3] - grid_range[:3]) / voxel_size).astype(np.int32)
    
    # 4. Mask points within bounds
    mask = (
        (coor[:, 0] >= 0) & (coor[:, 0] < grid_size[0]) &
        (coor[:, 1] >= 0) & (coor[:, 1] < grid_size[1]) &
        (coor[:, 2] >= 0) & (coor[:, 2] < grid_size[2])
    )
    coor = coor[mask]
    points_copy = points_copy[mask]
    
    # 5. Iterate and assign
    voxel_num = 0
    for i, c in enumerate(coor):
        # Note: coor_to_voxelidx is indexed as [z, y, x]
        voxel_id = coor_to_voxelidx[c[2], c[1], c[0]]
        
        if voxel_id == -1:
            if voxel_num >= max_num_voxels:
                break
            voxel_id = voxel_num
            voxel_num += 1
            coor_to_voxelidx[c[2], c[1], c[0]] = voxel_id
            coordinates[voxel_id] = c
            
        n_pts = num_points_per_voxel[voxel_id]
        if n_pts < max_points_in_voxel:
            voxels[voxel_id, n_pts] = points_copy[i]
            num_points_per_voxel[voxel_id] += 1
            
    return voxels[:voxel_num], coordinates[:voxel_num], num_points_per_voxel[:voxel_num]
```

**Edge Cases and Pitfalls:**
- **Capacity Limits:** If the number of occupied voxels exceeds `max_num_voxels`, the loop breaks, leaving subsequent points unprocessed [S3, unofficial].
- **Point Overflow:** If a voxel contains more than `max_points_in_voxel` points, excess points are discarded [S3, unofficial].
- **Boundary Clipping:** Points outside `grid_range` are either discarded (masking) or clamped, affecting feature accuracy at boundaries [S3, S5, unofficial].
- **Axis Ordering:** Some implementations reverse coordinate axes (e.g., `[::-1]`) to match specific memory layouts or library conventions (e.g., Numpy vs. TensorFlow) [S3, S5, unofficial].

## Subtopics

### [Octree Construction for Point Clouds](1070-octree-construction-for-point-clouds.md)
Constructs a hierarchical spatial data structure (octree) to organize point clouds, recursively subdividing space into eight octants until a leaf condition is met. It differs from flat voxel grids by maintaining a list of points at each node and aggregating their average position and color for spatial queries.

### [Point Resampling with Neighbor Masking](2710-point-resampling-with-neighbor-masking.md)
Resamples a point cloud based on active and neighbor status to support partial, percentage, and full resampling strategies. It controls point density by selectively activating points tied to tetrahedral connectivity.

### [Voxels to Points Projection](3172-voxels-to-points-projection.md)
Maps features stored in a dense voxel grid back to the original points in a point cloud using pre-computed segment IDs or point-to-voxel mappings. It solves the problem of recovering per-point features after they have been aggregated into voxels, enabling downstream tasks like point-wise classification or regression. Unlike [Hard Voxelization](5345-hard-voxelization.md) which aggregates points into voxels, this method reverses the flow, projecting voxel data back to points. It differs from [Point Cloud Cropping and Downsampling](7057-point-cloud-cropping-and-downsampling.md) by preserving the full feature dimensionality and spatial correspondence rather than reducing point count.

### [Pointcloud to Sparse Voxel Grid Conversion](3416-pointcloud-to-sparse-voxel-grid-conversion.md)
Maps a set of 3D points into a sparse grid of voxel centers and associated features, retaining only occupied cells. It converts a point cloud into a sparse voxel grid representation, storing only voxels that contain points. This method serves as the core voxelization step in pipelines converting point clouds to sparse voxel representations for downstream rendering or USD export.

### [Point Sampling from Mesh](3786-point-sampling-from-mesh.md)
Generates a discrete set of 3D coordinates on the surface of a polygon mesh. It bridges continuous mesh representations and discrete point-based volume data structures for downstream voxelization or neural field training. It differs from [Point Cloud Voxelization](1000-point-cloud-voxelization.md) by generating points from a mesh source rather than consuming an existing point cloud, and from [Interior Voxelize](995-interior-voxelize.md) by targeting the surface boundary rather than the volume interior.

### [Ray Model Voxelization](4688-ray-model-voxelization.md)
Converts sparse LiDAR point clouds into dense 3D occupancy grids by tracing rays from sensor origins to detected points, classifying voxels as free, occupied, or unobserved. It differs from [Hard Voxelization](5345-hard-voxelization.md) by explicitly modeling the empty space between the sensor and the target points, rather than only marking voxels containing points, and from [Point Cloud to Gaussian Converter](1788-point-cloud-to-gaussian-converter.md) by producing discrete grid states rather than continuous density fields.

### [Hard Voxelization](5345-hard-voxelization.md)
Converts a continuous 3D point cloud into a discrete voxel grid by assigning each point to a specific voxel cell based on its spatial coordinates and a fixed voxel size [G]. This method serves as the foundational step for producing volume data from raw point clouds, building on [Point Cloud Voxelization](1000-point-cloud-voxelization.md) [G].

### [Voxel-based Void Ratio Computation](6679-voxel-based-void-ratio-computation.md)
Computes a void ratio field from a legacy ASCII VTK particle point cloud by binning particle centers into cubic voxels, calculating the solid volume via sphere-box intersection integration, and assigning the resulting void ratio to all particles in the voxel. It differs from [Hard Voxelization](5345-hard-voxelization.md) by accounting for partial sphere volumes at voxel boundaries using numerical integration, and from [Point Cloud to Gaussian Converter](1788-point-cloud-to-gaussian-converter.md) by focusing on precise geometric volume accounting rather than visual approximation.

### [Point Cloud Cropping and Downsampling](7057-point-cloud-cropping-and-downsampling.md)
Reduces the density of a point cloud by first restricting the points to a specific spatial volume (cropping) and then reducing the point count via either voxel-based binning or uniform random sampling. It serves as a preprocessing step for voxelization and registration, balancing computational load against geometric fidelity. It differs from [Octree Construction for Point Clouds](1070-octree-construction-for-point-clouds.md) by producing a flat list of points rather than a hierarchical structure, and from [Point Resampling with Neighbor Masking](2710-point-resampling-with-neighbor-masking.md) by using simpler spatial or uniform selection criteria rather than neighbor-aware masking.

### [Gaussian Voxelization](8884-gaussian-voxelization.md)
Gaussian Voxelization refers to a family of methods that convert continuous 3D Gaussian primitives (splat) or point clouds into discrete voxel representations. These methods solve the problem of bridging unstructured, differentiable Gaussian splats with structured, grid-based neural networks or collision detection systems. They distinguish themselves from hard voxelization by using soft, probabilistic kernels or explicit sampling shapes to determine voxel occupancy and feature aggregation, rather than simple point-in-box tests.

### Two-stage training with adaptive point cloud generation
Splits training into two stages. After stage 1, generates additional point clouds using noise and UDF gradient descent, filters by UDF threshold, and rebuilds a KD-tree for denser sampling in stage 2 [S6, unofficial]. In `gen_extra_pointcloud`, sample points and samples. Compute offsets and standard deviation. Generate noise with std scaled by `low_range`. Add noise to points. Compute UDF and gradient. Project samples to surface. Filter by `udf_sample < df_filter`. Repeat until `num_points` reached. Concatenate and remove outliers [S6, unofficial]. After stage 1, concatenate ground truth points with generated points, build cKDTree, and update dataset for stage 2 training [S6, unofficial]. Parameters include `low_range` (scaling factor for noise standard deviation) and `outlier` (distance truncation threshold for removing outliers) [S6, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ for coordinate mapping and masking, where $N$ is the number of points. Sparse assignment is $O(K)$ where $K$ is the number of valid points, but depends on hash map or array lookup efficiency [S3, S5, unofficial].
- **Memory Complexity:** $O(G_x G_y G_z)$ for the dense coordinate map or $O(V \cdot P)$ for sparse storage, where $V$ is the number of occupied voxels and $P$ is `max_points_in_voxel` [S3, unofficial].
- **Performance:** JIT-compiled versions (e.g., Numba) significantly reduce Python overhead, offering near-C performance [S3, unofficial].
- **Strengths:** Simple implementation, fast for dense point clouds, preserves per-point features via aggregation [S2][S5, unofficial].
- **Limitations:** Fixed resolution limits detail; sparse structures may have high memory overhead for very large grids with few points; boundary effects depend on clamping vs. discarding [S3, S5, unofficial].
- **When to Use:** When input is already a point cloud and grid-based processing is required (e.g., 3D CNNs, voxel rendering) [S5, unofficial].
- **When Not to Use:** When the input is a mesh (use [Mesh Voxelization](6514-mesh-voxelization.md)) or when hierarchical structures are preferred (use [Octree Construction](1070-octree-construction-for-point-clouds.md)) [S1, unofficial].

## Background
Originating from early 3D computer vision and graphics pipelines, point cloud voxelization is a standard preprocessing step for 3D object detection (e.g., in autonomous driving with LiDAR data) and volume rendering [S3, S5, unofficial]. Libraries like Open3D provide built-in methods (`create_from_point_cloud`) for this conversion [S2]. Recent implementations in deep learning frameworks (TensorFlow, PyTorch) optimize this step for differentiable training and GPU acceleration [S5, S6, unofficial].
