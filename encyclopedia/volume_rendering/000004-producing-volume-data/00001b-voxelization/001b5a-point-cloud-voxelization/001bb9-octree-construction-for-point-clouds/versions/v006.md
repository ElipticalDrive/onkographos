# Octree Construction for Point Clouds

Also called: Grid Initialization, Point Cloud Octree Construction, SVO Building, Sparse Voxel Octree (SVO) Construction

## Overview
This method constructs a hierarchical spatial data structure (octree) to organize point cloud objects for efficient rendering and culling [S1, unofficial][S2]. It solves the problem of inefficiently storing and querying large, sparse point clouds by recursively subdividing space into eight octants until a leaf condition is met [S1, unofficial][S2]. It sets itself apart from flat voxel grids by providing variable-resolution storage and from fixed-depth approaches by allowing dynamic termination based on point density or occupancy limits [S2].

## How it works
**Inputs:** A list of point cloud objects, where each object has a 3D position and color [S1, unofficial].
**Outputs:** A root node of an octree, where each node contains a list of points, an Axis-Aligned Bounding Box (AABB), and a bitmask of active children [S1, unofficial].

**Data Structures:**
*   `Point`: Contains `position` (vec3) and `color` (vec3) [G].
*   `AABB`: Contains `min` (vec3) and `max` (vec3) [G].
*   `Node`:
    *   `objects`: List of `Point` references [S1, unofficial].
    *   `aabb`: The `AABB` enclosing this node's space [S1, unofficial].
    *   `active_octants`: An 8-bit integer bitmask. Bit $i$ is set if child octant $i$ exists [S1, unofficial].
    *   `children`: Array of 8 pointers to `Node` (or null if not created) [G].
    *   `depth`: Integer depth level (root is 0) [G].
    *   `average_object`: A `Point` representing the average position and color of all objects in this node's list (used for culling/LOD) [S1, unofficial].
*   `Octant`: Enum mapping bits 0-7 to the 8 sub-volumes. $O_1=0x01$ (0b00000001) through $O_8=0x80$ (0b10000000) [S1, unofficial].

**Parameters:**
*   `MAX_LEAF_OBJECTS`: Maximum number of objects allowed in a leaf node before subdivision stops. Value: 5 [S1, unofficial].
*   `base_layer` and `voxel_size`: Determined from scene dimensions to establish initial spacing [S2].

**Algorithm:**
The construction follows a recursive top-down subdivision:
```python
def build_octree(points):
    if not points:
        return None
    # 1. Compute root AABB
    aabb_min = min(p.position for p in points)
    aabb_max = max(p.position for p in points)
    # 2. Square the root AABB
    longest_dim = max(aabb_max[i] - aabb_min[i] for i in range(3))
    center = (aabb_min + aabb_max) / 2.0
    aabb_min = center - longest_dim / 2.0
    aabb_max = center + longest_dim / 2.0
    # 3. Initialize root
    root = Node(objects=points, aabb=(aabb_min, aabb_max), depth=0, active_octants=0)
    # 4. Recursive build
    _build_node(root)
    return root

def _build_node(node):
    # Calculate average
    node.average_object = Point(
        position=mean(p.position for p in node.objects),
        color=mean(p.color for p in node.objects)
    )
    # Check termination
    if len(node.objects) <= MAX_LEAF_OBJECTS:
        return
    # Generate child AABBs
    child_aabbs = []
    for i in range(8):
        mid = (node.aabb.min + node.aabb.max) / 2.0
        child_aabbs.append(calculate_octant_aabb(node.aabb, mid, i))
    # Distribute points
    child_objs = [[] for _ in range(8)]
    for p in node.objects:
        for j in range(8):
            if child_aabbs[j].contains(p.position):
                child_objs[j].append(p)
                break
    # Clear current list
    node.objects.clear()
    # Create children
    for i in range(8):
        if len(child_objs[i]) > 0:
            child_node = Node(objects=child_objs[i], aabb=child_aabbs[i], depth=node.depth + 1, parent=node)
            node.children[i] = child_node
            node.active_octants |= (1 << i)
            _build_node(child_node)

def calculate_octant_aabb(parent, mid, octant_idx):
    # Standard 3D octant splitting based on bit flags [G]
    min_x = parent.min.x if octant_idx & 1 else mid.x
    max_x = mid.x if octant_idx & 1 else parent.max.x
    min_y = parent.min.y if octant_idx & 2 else mid.y
    max_y = mid.y if octant_idx & 2 else parent.max.y
    min_z = parent.min.z if octant_idx & 4 else mid.z
    max_z = mid.z if octant_idx & 4 else parent.max.z
    return AABB(min=vec3(min_x, min_y, min_z), max=vec3(max_x, max_y, max_z))

class AABB:
    def __init__(self, min, max):
        self.min = min
        self.max = max
    def contains(self, point):
        return (self.min.x <= point.x <= self.max.x and
                self.min.y <= point.y <= self.max.y and
                self.min.z <= point.z <= self.max.z)
```

**Pitfalls:**
*   **Boundary Assignment:** Points on octree boundaries must be assigned deterministically to avoid duplication or gaps. The method uses a "first-fit" strategy (lowest index $j$) [S1, unofficial].
*   **Isolated Points:** If the stop criterion is based solely on point count, isolated points may create disproportionately large octants, leading to inefficient rendering [S3, unofficial]. There is no universal rule for the stop condition [S3, unofficial].

## Subtopics

### [Octree-based Level of Detail and Culling](1079-octree-based-level-of-detail-and-culling.md)
This method reduces the rendering load of large point clouds by traversing a pre-built octree on the CPU to perform frustum culling and view-dependent sampling before uploading data to the GPU. It sets itself apart from GPU-based culling techniques by aggregating point data into cached averages at internal octree nodes, allowing the CPU to decide exactly which subset of points to render based on distance thresholds.

### [Octree Data Structure](1276-octree-data-structure.md)
The Octree Data Structure partitions 3D space into a hierarchical grid of voxels to organize point cloud objects for rendering. It recursively subdivides a bounding volume into eight octants until a leaf condition is met, where leaf nodes represent occupied voxels or empty space with surface distance metrics. It differs from its siblings by providing the foundational spatial indexing for voxelization and isosurfacing, whereas [Octree Construction for Point Clouds](1070-octree-construction-for-point-clouds.md) describes the build process and [Octree-based Level of Detail and Culling](1079-octree-based-level-of-detail-and-culling.md) describes traversal optimizations.

### [Octree Construction with Dynamic Depth Stop Criterion](12308-octree-construction-with-dynamic-depth-stop-criterion.md)
This method constructs a uniform-depth octree from a point cloud by dynamically determining the subdivision depth based on an occupancy ratio threshold, rather than using a fixed maximum depth or a simple point-count limit. It solves the problem of inconsistent voxel sizes and excessive memory usage caused by isolated points or arbitrary depth limits, ensuring all leaf nodes reside at the same level for compact storage. It differs from fixed-depth approaches by adapting to the geometric density of each pose, and from occupancy-count limits by preventing isolated points from creating disproportionately large octants.

### Hierarchical Rectilinear Grid (Octree)
A hierarchical extension using an octree data structure for the interpolated volume to avoid problems of interpolating from curvilinear volumes with irregular sampling densities [S4]. It creates the octree by adding sample points from the original curvilinear grid one by one to the (originally empty) octree [S4]. Whenever a particular partition of the octree contains more than a user-specified number of curvilinear data samples, it splits that node into eight subnodes [S4]. After all curvilinear samples are added, it calculates the estimated data value at the eight corners of each octree partition [S4]. It renders the resulting volume using a hierarchical volume ray-tracer or the coherent projection approach [S4]. To avoid interpolation errors in creating the octree, an alternative is to use the octree together with the original curvilinear volume and render using values from the original sample values [S4].

## Background
The octree was introduced as a hierarchical spatial data structure for organizing point cloud objects for rendering [S1, unofficial][S2]. The specific method of squaring the bounding box to ensure cubic voxels and using a point-count stop criterion was detailed in research on hardware-accelerated geometry instancing for surfel and voxel rendering of scanned 4D media [S3, unofficial]. The application of octrees to curvilinear volumes for volume rendering was also explored [S4].
