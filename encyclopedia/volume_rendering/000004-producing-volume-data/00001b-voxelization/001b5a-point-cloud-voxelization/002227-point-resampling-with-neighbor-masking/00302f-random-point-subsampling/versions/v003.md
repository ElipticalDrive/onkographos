# Random Point Subsampling

Also called: Random Subset Selection, Shuffle and Slice

## Overview
Random Point Subsampling selects a random subset of points from a given set of points without replacement [S1, unofficial]. It serves as a fundamental resampling primitive within Point Resampling with Neighbor Masking, providing a baseline strategy for reducing point cloud density by ignoring spatial distribution or error metrics [S1, unofficial]. Unlike Error-Driven Point Resampling & Grid Aggregation, which prioritizes geometric fidelity, or the A-buffer Sampling Method, which considers visibility, this method treats all input points as equally probable candidates for retention [S1, unofficial].

## How it works
**Inputs:**
- `points`: A tensor of shape $(M, 3)$ containing $M$ 3D points [S1, unofficial].
- `n_points`: The integer number of points to select [S1, unofficial].

**Outputs:**
- A tensor of shape $(n\_points, 3)$ containing the selected subset of points [S1, unofficial].

**Data Structures:**
- The input `points` tensor is assumed to be contiguous in memory to allow efficient indexing [S1, unofficial].
- A permutation array of indices is generated to shuffle the selection order [S1, unofficial].

**Steps:**
1. Generate a random permutation of indices for the input points tensor. This creates a shuffled ordering of the integers $0$ to $M-1$ [S1, unofficial].
2. Index the `points` tensor with the random permutation to shuffle the points. This reorders the rows of the tensor such that the original sequence is randomized [S1, unofficial].
3. Reshape the shuffled points tensor to ensure it is 2D with shape $(-1, 3)$. This step normalizes the tensor structure, handling cases where the input might have been flattened or multi-dimensional [S1, unofficial].
4. Return the first `n_points` rows of the reshuffled tensor as the selected subset [S1, unofficial].

**Pseudocode:**
```python
import torch

def random_point_subsampling(points: torch.Tensor, n_points: int) -> torch.Tensor:
    """
    Selects a random subset of points from a given set of points without replacement.
    
    Args:
        points: Tensor of shape (M, 3) containing M 3D points.
        n_points: Integer, the number of points to select.
        
    Returns:
        Tensor of shape (n_points, 3) containing the selected subset.
    """
    # Step 1: Generate a random permutation of indices
    # torch.randperm generates a random permutation of 0 to N-1
    M = points.shape[0]
    perm = torch.randperm(M, device=points.device)
    
    # Step 2: Index the points tensor with the random permutation
    shuffled_points = points[perm]
    
    # Step 3: Reshape the shuffled points tensor to ensure it is 2D (shape (-1, 3))
    # This handles potential edge cases where the tensor might not be strictly 2D
    shuffled_points = shuffled_points.view(-1, 3)
    
    # Step 4: Return the selected subset of points
    # We take the first n_points from the shuffled list
    selected_points = shuffled_points[:n_points]
    
    return selected_points
```

**Parameters:**
- `n_points`: The number of points to select. Typical values depend on the target density required by the downstream rendering or reconstruction algorithm [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `n_points` exceeds the total number of points $M$, the behavior is undefined in the source description [S1, unofficial]. In practice, one should clamp `n_points` to $M$ or raise an error [G].
- Precision issues are minimal as the operation relies on integer indexing and tensor reshaping, but the randomness source (e.g., `torch.randperm`) should be seeded for reproducibility if required [G].

## Subtopics

### Near Sampling
A site placement strategy where a proportion of sites are placed close to uniformly subsampled input point cloud data [S2]. It is effective in methods that can efficiently move sites during optimization, such as DCCVT, but may fail in methods like MTet or Voromesh that require accurate initial occupancy information [S2]. It is often combined with uniform grid sampling and iterative upsampling strategies [S2].

### Stratified Point Subsampling
A variant that ensures proportional representation from different labels or clusters. It initializes a random number generator, computes unique labels and their counts, calculates target counts based on proportions, and samples indices without replacement from each label's pool [S3, unofficial]. It handles deficits by distributing remaining samples, ensuring the final count matches `sample_size` [S3, unofficial]. This method is chosen when preserving class balance or cluster distribution is critical, unlike the pure randomness of the base method [S3, unofficial].

## Operating characteristics
**Time Complexity:** $O(M)$ to generate the permutation and index the tensor, where $M$ is the number of input points [S1, unofficial].
**Memory Complexity:** $O(M)$ to store the permutation array and the shuffled tensor [S1, unofficial].
**Strengths:** Simple to implement, computationally efficient, and unbiased with respect to point position [S1, unofficial].
**Limitations:** Ignores spatial distribution, potentially leading to clumping or gaps in the sampled subset, which can degrade rendering quality or reconstruction accuracy in non-uniform scenes [S1, unofficial].
**When to use:** When computational speed is paramount and the point cloud is uniformly distributed, or as a baseline for comparison [S1, unofficial].
**When not to use:** When the point cloud has significant density variations or when geometric fidelity is critical, in which case Error-Driven Point Resampling & Grid Aggregation or A-buffer Sampling Method are preferred [S1, unofficial].

## Background
Random Point Subsampling is a standard technique in point cloud processing, often used as a preprocessing step for neural surface reconstruction and volume rendering pipelines [S1, unofficial]. It is cited in the context of optimizing neural implicit surfaces, where it is used to manage the computational load of training by subsampling the input point cloud [S1, unofficial]. The method is also referenced in the context of differentiable voxelization and site placement strategies for centroidal Voronoi tessellation [S2].
