# Farthest Point Sampling Initialization

Also called: FPS Initialization, Farthest Point Sampling, Furthest Point Sampling, FurthestSampling

## Overview
Farthest Point Sampling Initialization is a method for selecting a subset of points from a point cloud such that they are maximally spread out in Euclidean space, ensuring maximum spatial coverage [S1][S2, unofficial]. It serves as the primary initialization step for primitive positions in neural rendering representations, replacing simpler nearest-neighbor heuristics to prevent the formation of overly small primitives [S1]. It builds on [Farthest Point Sampling (FPS)](7182-farthest-point-sampling-fps.md) by providing the specific iterative selection logic and CUDA-optimized implementation details required to generate the initial set of indices.

## How it works
### Inputs and Outputs
**Inputs:**
- `xyz`: A tensor of shape $(N, 3)$ containing the coordinates of $N$ points in 3D space [S2, unofficial].
- `offset`: An integer array of shape $(B+1)$ defining the start and end indices for $B$ batches in `xyz` [S2, unofficial].
- `new_offset`: An integer array of shape $(B+1)$ defining the output boundaries for the sampled points [S2, unofficial].
- `tmp`: A temporary float array of shape $(B, n_{max})$ initialized to a large value (e.g., $10^{10}$) to track minimum distances [S2, unofficial].

**Outputs:**
- `idx`: An integer array of shape $(M)$ containing the indices of the $M$ sampled points [S2, unofficial].

### Data Structures
- **Shared Memory (CUDA):**
  - `dists[block_size]`: Float array storing the best (maximum) distance found by each thread [S2, unofficial].
  - `dists_i[block_size]`: Integer array storing the corresponding point index for the best distance [S2, unofficial].
- **Block Size:** The number of threads per block, passed as a template parameter. Supported values are powers of 2 from 2 to 1024 [S2, unofficial].

### Algorithm Steps
1. **Batch Processing Setup:**
   - Extract batch size $B$ and point count $N$.
   - Reshape `xyz` to 2D $(B \times N, 3)$ and ensure it is contiguous [S2, unofficial].
   - Compute cumulative offsets for input and output batches [S2, unofficial].
   - Determine $n_{max}$, the maximum number of points in any single batch, by iterating through `offset` [S2, unofficial].

2. **Initialization:**
   - Initialize `tmp` with large values ($10^{10}$) to represent infinity [S2, unofficial].
   - For each batch $b$:
     - Set the first sampled index `idx[start_m]` to the first point of the current batch (`start_n`) [S2, unofficial].
     - Set the reference point `old` to the coordinates of this first point [S2, unofficial].

3. **Iterative Selection (CUDA Kernel `furthestsampling_cuda_kernel`):**
   - For each subsequent sample $j$ from `start_m + 1` to `end_m`:
     - **Distance Update:**
       - Threads iterate over all points $k$ in the current batch.
       - Compute squared Euclidean distance $d$ between point $k$ and the last selected point `old` [S2, unofficial].
       - Update `tmp[k]` to store the minimum distance from point $k$ to any selected point so far:
         $$ tmp[k] = \min(d, tmp[k]) $$
     - **Local Maximum Finding:**
       - Each thread finds the local maximum `best` and corresponding index `besti` among its assigned points where `tmp[k] > best` [S2, unofficial].
     - **Parallel Reduction:**
       - Use shared memory arrays `dists` and `dists_i` to combine local maxima into a global maximum.
       - Perform a series of `__update` calls, halving the active thread count (e.g., 1024 $\to$ 512 $\to$ ... $\to$ 1) [S2, unofficial].
       - The `__update` device function compares two entries in the shared memory arrays and keeps the one with the larger distance value [S2, unofficial].
     - **Selection:**
       - The index of the farthest point found (`dists_i[0]`) is stored in `idx[j]` [S2, unofficial].
       - Update `old` to the coordinates of the newly selected point for the next iteration [S2, unofficial].

4. **Completion:**
   - Return `idx` as long integers [S2, unofficial].

### Formula
The index of the $i$-th sampled point $I_i$ is computed as [S1]:
$$ I_i = \arg \max_{k \notin \{I_0, \dots, I_{i-1}\}} \min_{0 \le j < i} d(x_k, x_{I_j}) $$
where $d$ is the Euclidean distance metric [S1].

### Parameters
- **Number of Samples ($K$):** The total number of points to select. Not explicitly given as a default value in the sources, but determined by the output size $M$ [S2, unofficial].
- **Block Size:** Powers of 2 from 2 to 1024 [S2, unofficial].

### Edge Cases and Pitfalls
- **Batch Boundaries:** The algorithm must correctly handle variable batch sizes by using `offset` and `new_offset` arrays [S2, unofficial].
- **Precision:** Squared Euclidean distance is used to avoid square root computations during the inner loop, which is standard for distance comparisons [S2, unofficial].
- **Initialization:** The first point is arbitrarily chosen as the first point in the batch (`start_n`), which may bias the sampling if the input order is not random [S2, unofficial]. [G] In practice, shuffling the input points before initialization is recommended to mitigate this bias.

### Pseudocode
```python
import torch
import math

def farthest_point_sampling_initialization(xyz: torch.Tensor, offset: torch.Tensor, new_offset: torch.Tensor) -> torch.Tensor:
    """
    Implements Farthest Point Sampling Initialization for batched point clouds.
    
    Args:
        xyz: Tensor of shape (N, 3) containing point coordinates.
        offset: Tensor of shape (B+1) defining batch boundaries in xyz.
        new_offset: Tensor of shape (B+1) defining output boundaries.
        
    Returns:
        idx: Tensor of shape (M) containing sampled indices.
    """
    B = offset.shape[0] - 1
    N = xyz.shape[0]
    
    # Determine max points in any batch
    n_max = 0
    for b in range(B):
        n_batch = offset[b+1] - offset[b]
        if n_batch > n_max:
            n_max = n_batch
            
    # Initialize temporary distance array with large values
    # Shape: (B, n_max)
    tmp = torch.full((B, n_max), 1e10, dtype=torch.float32, device=xyz.device)
    
    # Output index array
    # Shape: (M) where M is sum of differences in new_offset
    M = new_offset[B] - new_offset[0]
    idx = torch.zeros(M, dtype=torch.long, device=xyz.device)
    
    # Process each batch
    current_idx_pos = 0
    for b in range(B):
        start_n = offset[b]
        end_n = offset[b+1]
        start_m = new_offset[b]
        end_m = new_offset[b+1]
        
        n_batch = end_n - start_n
        
        # Extract batch points
        xyz_batch = xyz[start_n:end_n] # Shape: (n_batch, 3)
        
        # Initialize first point
        idx[start_m] = start_n
        old_point = xyz_batch[0]
        
        # Initialize tmp for this batch
        # Note: In CUDA implementation, tmp is pre-allocated and passed. 
        # Here we simulate the logic for a single batch.
        # tmp[b, 0:n_batch] is already initialized to 1e10
        
        # Iterative sampling
        for j in range(start_m + 1, end_m):
            # Compute distances from all points to the last selected point
            # old_point is xyz_batch[0] initially, then updates
            # Compute squared Euclidean distance
            diff = xyz_batch - old_point.unsqueeze(0)
            dists = torch.sum(diff * diff, dim=1) # Shape: (n_batch)
            
            # Update tmp: min distance to any selected point
            # tmp[b, k] = min(dists[k], tmp[b, k])
            # We only need to update the current batch's tmp values
            current_tmp = tmp[b, :n_batch]
            tmp[b, :n_batch] = torch.minimum(dists, current_tmp)
            
            # Find the point with the maximum minimum distance
            best_dist, best_idx_local = torch.max(tmp[b, :n_batch], dim=0)
            best_idx_global = start_n + best_idx_local
            
            # Store the index
            idx[j] = best_idx_global
            
            # Update old_point for next iteration
            old_point = xyz_batch[best_idx_local]
            
    return idx
```

## Subtopics

### Nearest-Neighbor Scale Initialization
A complementary method where the scale of each primitive is initialized based on distances to its nearest neighbors in the FPS-ordered point cloud, creating a hierarchy where early points are larger [S1].

### Gaussian Splatting Densification
FPS initialization is often used in conjunction with densification strategies in 3D Gaussian Splatting to manage point cloud density during optimization [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(k \cdot n)$ per batch, where $k$ is the number of sampled points and $n$ is the number of points in the batch. Each sampling step requires $O(n)$ for distance calculation and $O(\log(\text{block\_size}))$ for reduction [S2, unofficial].
- **Memory Complexity:** $O(n_{max})$ for the temporary distance array `tmp` per batch, where $n_{max}$ is the maximum number of points in any batch [S2, unofficial].
- **Strengths:** Ensures uniform spatial coverage of the point cloud, which is critical for initializing neural rendering primitives to avoid artifacts and ensure stable optimization [S1].
- **Limitations:** Computationally expensive for large point clouds due to the iterative nature. The CUDA implementation requires careful management of shared memory and batch boundaries [S2, unofficial].
- **When to Use:** When initializing primitive positions for neural rendering or point cloud processing where uniform coverage is more important than speed.
- **When Not to Use:** When real-time performance is critical and approximate sampling is acceptable, or when the point cloud is extremely large and memory constraints prevent storing the full distance array.

## Background
Farthest Point Sampling was introduced as a method for uniformly subsampling point clouds [S2, unofficial]. It has been adopted in neural rendering techniques such as Nexels, where it is used to initialize the positions of neurally-textured surfels, replacing simpler nearest-neighbor initialization methods that can lead to small, inefficient primitives [S1]. The CUDA implementation described in the sources is part of the 4D Gaussian Splatting framework, which extends 3D Gaussian Splatting to dynamic scenes [S2, unofficial].
