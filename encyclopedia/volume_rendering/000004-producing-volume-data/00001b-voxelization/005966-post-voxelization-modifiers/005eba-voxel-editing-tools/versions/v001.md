# Voxel Editing Tools

Also called: Interactive voxel manipulation, Voxel eraser and paint

## Overview
Voxel Editing Tools provide interactive, post-voxelization modification of volumetric data, allowing users to surgically alter individual or grouped voxels for tasks such as surgical planning, artifact correction, or data abstraction [S1]. Unlike the parent [Post-Voxelization Modifiers](16402-post-voxelization-modifiers.md) which often apply algorithmic, non-interactive transformations (like LOD downsampling or statistical aggregation), this method relies on direct user input via a stylus or pointer to define local regions of influence [S1]. It distinguishes itself from siblings like [Avatar Head Data Variant Application](22734-avatar-head-data-variant-application.md) by focusing on arbitrary spatial manipulation (removal, transparency, recoloring) rather than variant-specific attribute mapping [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A fully populated voxel grid (or sparse representation) with initial attributes (solid/empty, material ID, density, color) [S1]. A user input device (stylus/pointer) providing 3D position and state (pressed/released) [S1].
*   **Output:** A modified voxel grid where specific voxels have their properties changed (e.g., set to transparent, recolored, or restored) [S1].

**Data Structures:**
*   **Voxel Grid:** Standard 3D array or sparse hash map storing voxel attributes. Each voxel must support at least:
    *   `opacity` or `is_solid` (boolean or float 0.0-1.0)
    *   `color` (RGB or RGBA)
    *   `original_values` (backup of initial state for restoration) [S1].
*   **Tool State:**
    *   `shape`: Enum {RECTANGULAR, CYLINDRICAL, SPHERICAL} [S1].
    *   `radius` or `dimensions`: Float or Vector3 defining tool size [S1].
    *   `mode`: Enum {INSPECT, EDIT} [S1].
    *   `is_active`: Boolean indicating if the tool switch is pressed [S1].

**Numbered Steps:**
1.  **Initialize Tool:** Set default `shape` (e.g., SPHERICAL) and `radius`. Initialize `mode` to INSPECT. Store a copy of the initial voxel grid as `original_grid` for restoration capabilities [S1].
2.  **Receive Input:** Get current 3D position $P$ from the stylus/pointer and the state of the tool switch $S$ (1 if pressed, 0 if not) [S1].
3.  **Adjust Size:** If the user performs a specific gesture (e.g., pointing direction change or scroll), update `radius`. The sources describe a stylus pointing upwards to enlarge and downwards to shrink [S1].
4.  **Determine Tool Volume:** Calculate the set of voxel indices $V_{tool}$ intersected by the tool shape centered at $P$ with current `radius` and `shape` [S1].
    *   For SPHERICAL: $V_{tool} = \{ v \mid \|v - P\| \le radius \}$
    *   For RECTANGULAR: $V_{tool} = \{ v \mid |v_x - P_x| \le r_x, |v_y - P_y| \le r_y, |v_z - P_z| \le r_z \}$
    *   For CYLINDRICAL: $V_{tool} = \{ v \mid \sqrt{(v_x - P_x)^2 + (v_y - P_y)^2} \le r_{cyl}, |v_z - P_z| \le r_{cyl\_height} \}$ (Axis alignment not specified, assume local orientation) [S1].
5.  **Execute Mode:**
    *   If `mode` is INSPECT ($S=0$): Do not modify the grid. During rendering, voxels in $V_{tool}$ are hidden (opacity set to 0.0 for rendering purposes only, or excluded from ray-casting) to reveal underlying tissue [S1].
    *   If `mode` is EDIT ($S=1$): For each voxel $v \in V_{tool}$, apply the edit operation:
        *   **Remove:** Set $v.opacity = 0.0$ (or mark as empty) [S1].
        *   **Paint:** Set $v.color = user\_selected\_color$ [S1].
        *   **Restore:** If a restoration command is issued, set $v = original\_grid[v]$ [S1].
6.  **Render/Update:** Refresh the visualization. In INSPECT mode, the view updates to show the "hole" created by the tool. In EDIT mode, the grid data is permanently modified until the next session or undo [S1].

**Parameters:**
*   **Tool Shapes:** Rectangular, Cylindrical, Spherical [S1].
*   **Size Control:** Dynamic, controlled by stylus orientation (up to enlarge, down to shrink) [S1].
*   **Typical Values:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Interaction Errors:** Users may accidentally modify voxels. This is mitigated by the ability to restore voxels to their original values from `original_grid` [S1].
*   **Boundary Conditions:** The tool shape may extend beyond the voxel grid boundaries. Implementation must clamp voxel indices to valid grid ranges [G].
*   **Precision:** Floating-point position $P$ must be accurately mapped to voxel indices. Rounding errors can cause "jitter" or missed voxels at boundaries [G].

**Pseudocode:**
```python
class VoxelEditor:
    def __init__(self, voxel_grid):
        self.grid = voxel_grid
        self.original_grid = copy(voxel_grid)
        self.tool_shape = "SPHERICAL"
        self.tool_radius = 1.0
        self.mode = "INSPECT"  # "INSPECT" or "EDIT"
        self.is_switch_pressed = False

    def update_tool_size(self, direction):
        """
        direction: +1 for enlarge (up), -1 for shrink (down)
        """
        self.tool_radius += 0.1 * direction
        if self.tool_radius < 0.1:
            self.tool_radius = 0.1

    def get_voxels_in_tool(self, position):
        """
        Returns list of voxel indices within the tool's shape centered at position.
        """
        voxels = []
        # Implementation depends on grid structure (dense vs sparse)
        # For dense grid:
        r = self.tool_radius
        if self.tool_shape == "SPHERICAL":
            min_x = floor(position.x - r)
            max_x = ceil(position.x + r)
            min_y = floor(position.y - r)
            max_y = ceil(position.y + r)
            min_z = floor(position.z - r)
            max_z = ceil(position.z + r)
            
            for x in range(min_x, max_x + 1):
                for y in range(min_y, max_y + 1):
                    for z in range(min_z, max_z + 1):
                        if is_valid_index(x, y, z):
                            dist_sq = (x - position.x)**2 + (y - position.y)**2 + (z - position.z)**2
                            if dist_sq <= r**2:
                                voxels.append((x, y, z))
        elif self.tool_shape == "RECTANGULAR":
            # Similar bounding box logic
            pass
        elif self.tool_shape == "CYLINDRICAL":
            # Similar logic with cylindrical constraint
            pass
        return voxels

    def process_input(self, position, switch_state):
        self.is_switch_pressed = switch_state
        
        # Determine mode based on switch state if not explicitly set by UI
        # Note: Source says "Without switch pressed: inspect mode... When switch is pressed: removes voxels"
        # This implies mode is dynamic based on switch, or switch toggles the action within a mode.
        # We follow the source: Switch OFF -> Inspect (Visual only). Switch ON -> Edit (Modify).
        
        voxels = self.get_voxels_in_tool(position)
        
        if not self.is_switch_pressed:
            # INSPECT MODE: Do not modify grid. 
            # Return voxels for rendering to hide them.
            return voxels, "HIDE"
        else:
            # EDIT MODE: Modify grid
            for v in voxels:
                # Default action is removal (transparency)
                self.grid[v].opacity = 0.0
                # Additional actions like painting would require extra UI input
                # self.grid[v].color = user_color
            return voxels, "MODIFY"

    def restore_voxels(self, voxels):
        """
        Restores specified voxels to their original state.
        """
        for v in voxels:
            self.grid[v] = self.original_grid[v]
```

## Subtopics

### [Dual-Mode Voxel Editing](22289-dual-mode-voxel-editing.md)
A workflow strategy separating voxel data into **View** (mesh-based rendering) and **Edit** (voxel-grid manipulation) states to balance performance and flexibility. It isolates heavy voxel computation to a single active object, avoiding the cost of scanning all chunks for every object update.

## Operating characteristics
*   **Time Complexity:** $O(N_{tool})$ per frame, where $N_{tool}$ is the number of voxels intersected by the tool shape. This is generally small compared to the total grid size, allowing for real-time interaction [S1].
*   **Memory Complexity:** $O(N_{grid})$ for the voxel grid plus $O(N_{grid})$ for the `original_grid` backup if restoration is required [S1].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Allows precise, user-driven modification of volume data for planning and correction. Supports immediate visual feedback (inspect mode) and permanent changes (edit mode) [S1].
*   **Limitations:** Performance may degrade if the tool size becomes very large or if the grid is extremely dense and sparse structures are not used. Restoration requires storing a full copy of the original data [S1].
*   **When to use:** Surgical planning (e.g., simulating craniotomies), correcting voxelization artifacts, or marking regions of interest [S1].
*   **When not to use:** When real-time performance on massive, unoptimized dense grids is critical and user interaction is not required [G].

## Background
Voxel Editing Tools were developed as part of the VIVIAN (Virtual Interactive Volume-based Neurosurgery) system for multimodal volume-based tumor neurosurgery planning [S1]. The system allows surgeons to interactively change voxel properties to simulate surgical procedures, such as turning voxels transparent to study anatomical relationships or removing tumor parts for approach planning [S1]. The method was described in the context of a virtual workbench for neurosurgery [S1].
