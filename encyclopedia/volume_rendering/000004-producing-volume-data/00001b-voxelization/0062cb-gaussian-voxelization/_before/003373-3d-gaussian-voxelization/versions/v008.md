# 3D Gaussian Voxelization

Also called: Voxelization of 3D Gaussians

## Overview
3D Gaussian Voxelization converts a continuous set of 3D Gaussian primitives into a discrete set of unique voxels and their associated features, enabling efficient processing by 3D neural networks [S1, unofficial]. It differs from standard point cloud voxelization by explicitly accounting for the spatial extent and shape of Gaussian distributions during sampling, rather than treating them as infinitesimal points. This method serves as a bridge between continuous Gaussian splatting representations and discrete voxel-based architectures [S1, unofficial].

## How it works
The method maps continuous Gaussian primitives $G_k$ (defined by mean $\mu_k$, covariance $\Sigma_k$, opacity $\alpha_k$, and features $F_k$) to a discrete voxel grid. The process involves determining the number of voxels per Gaussian based on a sampling shape, generating coordinates and features, and deduplicating the result to form a sparse voxel set.

**Inputs:**
- `gaussians`: A list of 3D Gaussian parameters. Each element is typically a dictionary or object containing at least a "scale" key (and possibly position or other attributes) needed by the sampling functions [S1, unofficial].
- `grid_size`: A float hyperparameter defining the physical size of each voxel cell [S1, unofficial].
- `SAMPLE_SHAPE`: A literal string controlling the geometric shape used for sampling voxels around each Gaussian. Options include `"volume"`, `"tri-plane"`, `"tri-line"`, and `"center"`. Default is `"center"` [S1, unofficial].

**Outputs:**
- `uni_voxels_xyz`: A list of tuples `(float, float, float)` representing the $(x, y, z)$ coordinates of the unique voxels.
- `uni_voxel_feats`: A list of feature vectors corresponding to each unique voxel.
- `inverse_indices`: A list of integers mapping each original generated voxel back to its corresponding index in the unique voxel list.
- `num_voxels_per_g`: A list of integers indicating the number of voxels sampled from each 3D Gaussian.

**Data Structures:**
The implementation relies on three logical stages. Intermediate data structures include a list of all generated voxel coordinates (before deduplication) and a parallel list of their associated features. The final output structures are the unique coordinate list, the aggregated feature list, and the inverse index map.

**Steps:**
1.  **Count Voxels:** Determine the number of voxels required for each Gaussian using `count_voxels_per_g(gaussians, grid_size)`. This function uses `SAMPLE_SHAPE` to decide how many discrete points to sample within the Gaussian's influence region [S1, unofficial].
2.  **Compose Features:** Generate voxel coordinates and features for all Gaussians using `compose_voxels_features(gaussians, num_voxels_per_g)`. This step produces the raw set of voxel positions and their initial feature values based on the Gaussian parameters [S1, unofficial].
3.  **Deduplicate:** Remove duplicate voxels using `return_unique_voxels(voxels_xyz, voxel_feats)`. This function identifies unique coordinates, aggregates their features (e.g., via summation or averaging, though specific aggregation logic is not detailed in the source), and computes the inverse index mapping from the original list to the unique list [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision in coordinate generation and deduplication can lead to incorrect merging or splitting of voxels.
- **Boundary Conditions:** The handling of voxels near the boundaries of the Gaussian's influence region depends on the `SAMPLE_SHAPE`.
- **Empty Gaussians:** Gaussians with zero scale or opacity may result in zero voxels, requiring careful handling in the `num_voxels_per_g` list.

## Subtopics

### GaGS
GaGS is a method that devises the voxelization of a set of Gaussian distributions, followed by the use of sparse convolutions to extract geometry-aware features, which are then utilized for deformation learning [S2]. It is specifically tailored for dynamic scenes, where 3D Gaussians are learned in a canonical space and used to model spatial-temporal deformation with an implicit deformation field (implemented as an MLP) [S2].
