# Gaussian Kernel Interpolation

Also called: voxelize via Gaussian kernel interpolation

## Overview
Gaussian Kernel Interpolation (GKI) is a method to voxelize a point-cloud variable by interpolating values from scattered points to voxel centers using a Gaussian weight function based on distance [S1, unofficial]. It produces smoother results than Nearest Neighbor (NN) interpolation, as the scatter plot comparing NN and GKI values deviates from the identity line [S1, unofficial].

## How it works
**Inputs:**
- `pts`: Array of shape $(N, 3)$ containing the coordinates of $N$ input points.
- `var`: Array of shape $(N,)$ containing the scalar variable value associated with each point in `pts`.
- `shape`: Tuple $(H, W, D)$ defining the dimensions of the output voxel grid in meters.
- `voxel_width`: Scalar defining the side length of cubic voxels.
- `k`: Integer defining the number of nearest neighbors to query.

**Outputs:**
- `voxel_grid`: Array of shape $(H, W, D)$ containing the interpolated variable values at each voxel center.

**Data Structures:**
- `vxl`: Array of shape $(M, 3)$ containing the 3D coordinates of all voxel centers, where $M$ is the total number of voxels.
- `tree`: A KD-Tree data structure built from `pts` for efficient nearest-neighbor queries.

**Parameters:**
- `voxel_width`: Typical value is 0.25 meters (25 cm) [S1, unofficial].
- `sigma`: The standard deviation of the Gaussian kernel. Set to `voxel_width / 2` [S1, unofficial].
- `k`: Typical value is 20 [S1, unofficial].

**Steps:**
1. **Define Voxel Bounds:** Create linear spaces for the X, Y, and Z dimensions from 0 to the respective shape dimensions, divided by `voxel_width`. The number of intervals is `int(dim / voxel_width) + 1`.
   $$
   vxb = \text{linspace}(0, \text{shape}[2], \text{int}(\text{shape}[2]/\text{voxel\_width}) + 1)
   $$
   $$
   vyb = \text{linspace}(0, \text{shape}[1], \text{int}(\text{shape}[1]/\text{voxel\_width}) + 1)
   $$
   $$
   vzb = \text{linspace}(0, \text{shape}[0], \text{int}(\text{shape}[0]/\text{voxel\_width}) + 1)
   $$
2. **Calculate Voxel Centers:** Compute the center coordinates by averaging adjacent bounds for each dimension. Use a meshgrid to create 3D arrays of these centers, then ravel them into a list of 3D points `vxl` of shape $(M, 3)$.
   $$
   vxc = \text{meshgrid}\left(\frac{vyb[1:] + vyb[:-1]}{2}, \frac{vzb[1:] + vzb[:-1]}{2}, \frac{vxb[1:] + vxb[:-1]}{2}\right)
   $$
   $$
   vxl = \text{concatenate}([vxc[0].\text{ravel}(), vxc[1].\text{ravel}(), vxc[2].\text{ravel()}], \text{axis}=1)
   $$
   *(Note: The source code uses `np.c_` to stack the raveled arrays column-wise.)*
3. **Build KD-Tree:** Construct a KD-Tree from the input point cloud `pts`.
4. **Query Nearest Neighbors:** Query the KD-Tree for the $k$ nearest neighbors for each voxel center in `vxl`. This returns distances `dd` of shape $(M, k)$ and indices `ii` of shape $(M, k)$.
5. **Compute Weights:** Calculate the Gaussian weight $w_i$ for each neighbor using its distance $r_i$ (from `dd`) and the kernel width $\sigma$.
   $$
   w_i = \exp\left(-\frac{r_i^2}{2\sigma^2}\right)
   $$
   The resulting weight array `wi` has shape $(M, k)$.
6. **Retrieve Variable Values:** Retrieve the variable values $v_i$ for the $k$ nearest neighbors using the indices `ii`. The resulting array `vi` has shape $(M, k)$.
7. **Interpolate:** Compute the interpolated value for each voxel by taking the weighted average of the neighbor values.
   $$
   V_{\text{voxel}} = \frac{\sum_{i=1}^{k} v_i w_i}{\sum_{i=1}^{k} w_i}
   $$
   This results in an array of shape $(M,)$.
8. **Reshape:** Reshape the resulting interpolated values array to match the 3D voxel grid dimensions `(shape[0], shape[1], shape[2])`.

**Pseudocode:**
```python
import numpy as np
from scipy.spatial import cKDTree as kdtree

def gaussian_kernel_interpolation(pts, var, shape, voxel_width, k=20):
    """
    Voxelize a point-cloud variable via Gaussian kernel interpolation.
    
    Args:
        pts: (N, 3) array of point coordinates.
        var: (N,) array of variable values at each point.
        shape: Tuple (H, W, D) defining the voxel grid dimensions in meters.
        voxel_width: Scalar, side length of cubic voxels.
        k: Integer, number of nearest neighbors to query.
        
    Returns:
        voxel_grid: (H, W, D) array of interpolated values.
    """
    # 1. Define Voxel Bounds
    # Note: Source uses int(dim/voxel_width) + 1 for number of bounds
    num_x = int(shape[2] / voxel_width) + 1
    num_y = int(shape[1] / voxel_width) + 1
    num_z = int(shape[0] / voxel_width) + 1
    
    vxb = np.linspace(0, shape[2], num_x)
    vyb = np.linspace(0, shape[1], num_y)
    vzb = np.linspace(0, shape[0], num_z)
    
    # 2. Calculate Voxel Centers
    # Average adjacent bounds
    centers_x = (vxb[1:] + vxb[:-1]) / 2
    centers_y = (vyb[1:] + vyb[:-1]) / 2
    centers_z = (vzb[1:] + vzb[:-1]) / 2
    
    # Meshgrid and ravel
    # Source order: X from vxb, Y from vyb, Z from vzb
    # np.meshgrid default indexing is 'xy', but source passes (vyb, vzb, vxb)
    # Let's follow source exactly:
    # vyc, vzc, vxc = np.meshgrid((vyb[1:]+vyb[:-1])/2,
    #                             (vzb[1:]+vzb[:-1])/2,
    #                             (vxb[1:]+vxb[:-1])/2)
    # This implies the meshgrid arguments are Y, Z, X centers.
    # Standard meshgrid with default indexing='xy' returns arrays where
    # the first two dims correspond to the first two inputs.
    # To get (X, Y, Z) coordinates in the final raveled array as (x, y, z):
    # We need to be careful with meshgrid output order.
    # Source: vxl = np.c_[vxc.ravel(), vyc.ravel(), vzc.ravel()]
    # So vxc is X-coords, vyc is Y-coords, vzc is Z-coords.
    
    vyc, vzc, vxc = np.meshgrid(centers_y, centers_z, centers_x)
    vxl = np.c_[vxc.ravel(), vyc.ravel(), vzc.ravel()]
    
    # 3. Build KD-Tree
    tree = kdtree(pts)
    
    # 4. Query Nearest Neighbors
    # dd: distances (M, k), ii: indices (M, k)
    dd, ii = tree.query(vxl, k=k)
    
    # 5. Compute Weights
    sigma = voxel_width / 2
    # w_i = exp(-r_i^2 / (2 * sigma^2))
    wi = np.exp(-dd**2 / (2 * sigma**2))
    
    # 6. Retrieve Variable Values
    # vi: (M, k)
    vi = var[ii]
    
    # 7. Interpolate
    # V_voxel = sum(vi * wi, axis=1) / sum(wi, axis=1)
    numerator = np.sum(vi * wi, axis=1)
    denominator = np.sum(wi, axis=1)
    
    # Handle potential division by zero if all weights are 0 (e.g., if k=0 or pts empty)
    # [G] Guard against division by zero
    denominator = np.where(denominator == 0, 1.0, denominator)
    
    var_gki = numerator / denominator
    
    # 8. Reshape
    # Source shape is (H, W, D) = (shape[0], shape[1], shape[2])
    voxel_grid = var_gki.reshape((shape[0], shape[1], shape[2]))
    
    return voxel_grid
```

**Edge Cases and Pitfalls:**
- Using a fixed number of nearest neighbors ($k$) instead of a spherical radius neighborhood means the neighbors might not form a sphere, potentially biasing the interpolation if the point distribution is non-uniform [S1, unofficial].
- If the point cloud is sparse, some voxels may have all zero weights if the $k$-nearest neighbors are too far away relative to $\sigma$, leading to NaN or undefined values if not handled [G].

## Operating characteristics
- **Time Complexity:** Dominated by the KD-Tree construction $O(N \log N)$ and the $M$ queries for $k$ neighbors, each taking $O(k \log N)$. Total time is approximately $O((N + M) \log N)$.
- **Memory Complexity:** $O(N)$ for the point cloud and KD-Tree, $O(M)$ for the voxel centers and output grid, and $O(M \cdot k)$ for intermediate neighbor arrays.
- **Measured Performance:** The source uses a point cloud of 1000 points and a grid derived from a $3 \times 4 \times 5$ meter volume with 0.25m voxels. Performance is noted as "speed and simplicity" compared to spherical radius queries [S1, unofficial].
- **Strengths:** Produces smoother results than Nearest Neighbor interpolation [S1, unofficial]. Simple to implement using standard KD-Tree libraries.
- **Limitations:** Bias in non-uniform point distributions due to fixed $k$ [S1, unofficial]. Computationally more expensive than NN due to weight calculations.
- **When to use:** When smooth interpolation of scalar fields from sparse point clouds is required and point distribution is relatively uniform.
- **When not to use:** When point distribution is highly non-uniform (consider radius-based queries) or when real-time performance is critical and NN is sufficient.
