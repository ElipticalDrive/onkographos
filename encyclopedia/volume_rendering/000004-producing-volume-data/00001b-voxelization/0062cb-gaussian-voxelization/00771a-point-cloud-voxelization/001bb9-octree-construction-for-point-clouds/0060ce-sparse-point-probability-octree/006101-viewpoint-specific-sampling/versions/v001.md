# Viewpoint-Specific Sampling

Also called: Viewpoint-Specific Sampling Re-weighting

## Overview
Viewpoint-Specific Sampling is a strategy for generating point clouds from a sparse point probability octree tailored to a specific camera viewpoint [S1]. It solves the problem of inefficient or low-quality reconstruction by ensuring samples are placed only within the view frustum, biased towards foreground regions, and adjusted for voxel size [S1]. It sets itself apart from uniform sampling by incorporating visibility, depth, and subdivision level into the probability distribution, and from static sampling by being dynamic to the camera pose [S1].

## How it works
**Inputs:**
*   Sparse Point Probability Octree $P$ containing leaf nodes with probabilities $p_i$ [S1].
*   Camera parameters: Intrinsic matrix $P$, extrinsic matrix $V$ [S1].
*   Parameter $\lambda_l$ (typical value: 0.5) [S1].

**Outputs:**
*   A list of 3D point positions sampled for the current viewpoint [S1].
*   (For inference) Averaged 2D feature images [S1].

**Data Structures:**
*   Leaf nodes in the octree store:
    *   $p_i$: Base probability mass.
    *   $l_i$: Subdivision level (depth in octree).
    *   Spatial extent (bounding box or center/size) for uniform sampling [S1].

**Steps:**

1.  **Visibility Check:** Determine if a leaf node $i$ is visible from the current camera. This is typically done by checking if the leaf's bounding box intersects the view frustum [S1].
2.  **Distance Calculation:** Compute $d_i$, the distance between the center of leaf node $i$ and the image plane (or camera center, depending on implementation detail, but the source specifies "image plane") [S1].
3.  **Re-weighting:** Compute the viewpoint-specific probability $\hat{p}_i$ for each leaf node using the formula:
    $$ \hat{p}_i = 1_{\text{visible}} \cdot \frac{p_i}{d_i \cdot 2^{l_i \cdot \lambda_l}} $$
    where:
    *   $1_{\text{visible}}$ is an indicator function (1 if visible, 0 otherwise) [S1].
    *   $d_i$ is the depth/distance term [S1].
    *   $l_i$ is the subdivision level [S1].
    *   $\lambda_l$ is the size re-weighting exponent [S1].
4.  **Normalization:** Normalize $\hat{p}_i$ across all visible leaves to form a valid probability distribution [S1].
5.  **Multinomial Sampling:** Perform multinomial sampling with replacement on the normalized $\hat{p}_i$ to select a list of leaf indices [S1].
6.  **Position Sampling:** For each selected leaf, uniformly sample a 3D position within the leaf's spatial extent [S1].

**Edge Cases and Pitfalls:**
*   **Depth Term Squaring:** Using $1/d_i^2$ for perspective cameras leads to worse results. The CNN hole-filler overemphasizes the background and fails to produce clean backgrounds with fewer samples [S1].
*   **Size Bias:** Using $\lambda_l = 2$ (overemphasizing smaller leaves) performs worse than $\lambda_l = 0.5$. Smaller leaves are more likely in well-observed regions; overemphasizing them places samples in already well-reconstructed areas, reducing benefit [S1].
*   **Visibility:** Samples outside the view frustum should not be placed [S1].

## Subtopics

### Viewpoint-Specific Sampling Re-weighting
This variant refers to the specific re-weighting scheme used in the method. It re-weights the point probability octree sampling using depth ($1/d_i$) and size ($1/2^{l_i \cdot \lambda_l}$) terms to improve reconstruction quality across viewpoints [S1]. The depth term is considered more important than the size term [S1]. The parameter $\lambda_l$ controls the size re-weighting exponent, with a typical value of 0.5 [S1]. A key pitfall is squaring the depth term ($1/d_i^2$), which causes worse results because the CNN hole-filler overemphasizes the background [S1]. Additionally, $\lambda_l = 0.5$ outperforms $\lambda_l = 2$ because overemphasizing smaller leaves places more samples in well-reconstructed areas, which is less beneficial than spreading samples to less observed regions [S1].

## Operating characteristics
*   **Time Complexity:** Dominated by the visibility check and multinomial sampling. Visibility check is $O(N)$ where $N$ is the number of leaves. Sampling is $O(M)$ where $M$ is the number of samples [S1].
*   **Memory Complexity:** $O(N)$ to store the octree and re-weighted probabilities [S1].
*   **Performance:** The method improves reconstruction quality compared to uniform sampling by focusing samples on relevant regions [S1].
*   **Strengths:** Avoids aliasing when combined with bilinear splatting; improves quality by regularizing appearance features across a larger volume [S1].
*   **Limitations:** Requires visibility checks; sensitive to parameter choices ($\lambda_l$, depth term formulation) [S1].
*   **When to use:** When rendering radiance fields from a sparse point probability octree and high-quality reconstruction is needed [S1].
*   **When not to use:** When computational resources are extremely limited and visibility checks are too expensive, or when uniform sampling is sufficient for low-quality previews [S1].

## Background
The method was introduced in the paper "INPC: Implicit Neural Point Clouds for Radiance Field Rendering" [S1]. It is part of a pipeline that uses a sparse octree to store point probabilities, which are then sampled into point clouds for rendering via differentiable bilinear point splatting [S1]. The approach addresses issues with aliasing and gradient approximation in one-pixel point rendering by using a bilinear formulation [S1].
