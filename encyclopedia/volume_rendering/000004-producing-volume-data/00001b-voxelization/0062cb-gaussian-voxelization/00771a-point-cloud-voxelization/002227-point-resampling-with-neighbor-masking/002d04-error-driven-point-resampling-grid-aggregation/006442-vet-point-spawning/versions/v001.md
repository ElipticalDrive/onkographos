# VET Point Spawning

Also called: Point Growing in VET Framework, Point Spawning in VET

## Overview
VET Point Spawning is a refinement step in the Visual Error Tomography (VET) pipeline that increases point cloud density in regions with high visual reconstruction error. It solves the problem of missing geometric details in neural rendering by selectively adding points where the rendered image deviates significantly from the ground truth. Unlike naive point-growing strategies or methods that unproject pixel errors into voxels (such as SNP), VET spawns points directly within error-weighted voxels, avoiding the need for aggressive thresholding or cleaning that typically degrades quality or inflates memory usage [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D voxel grid of normalized visual error values $E$, typically of resolution $512^3$. Each voxel $(x, y, z)$ contains a value $e_i \in [0, 1]$ representing the local error density [S1].
*   **Output:** A modified point cloud with additional points inserted into voxels with $e_i > 0$.

**Data Structures**
*   **Error Grid:** A 3D array of floats. The source specifies a fixed resolution of $512^3$ [S1].
*   **Point Cloud:** A list of 3D coordinates. The number of points remains comparable to the initial reconstruction after the full VET cycle (spawning + cleaning) [S1].

**Parameters**
*   $p_{max}$: Maximum number of points to spawn per voxel. Typical value: 10 [S1].
*   $n(x, y, z)$: Number of points to spawn in voxel $(x, y, z)$.

**Steps**
1.  **Normalize Error:** Ensure the error grid values $e_i$ are scaled to the range $[0, 1]$. The source notes that SSIM is the preferred error metric for this normalization as it guides spawning in thin locations effectively [S1].
2.  **Calculate Spawn Count:** For each voxel $(x, y, z)$ with error value $e_i$, compute the number of points to spawn:
    $$ n(x, y, z) = \lfloor e_i(x, y, z) \cdot p_{max} \rfloor $$
    If $n(x, y, z) = 0$, no points are added to this voxel [S1].
3.  **Spawn Points:** For each voxel where $n(x, y, z) > 0$, generate $n(x, y, z)$ new points. The positions of these points are distributed randomly within the boundaries of the voxel cell [S1].
4.  **Integration:** Add the newly spawned points to the existing point cloud. Note that this step is followed by an outlier removal strategy (described in the parent article's context) which cleans inaccurately placed points, making the randomness of spawning robust [S1].

**Pseudocode**
```python
def vet_point_spawning(error_grid_512x512x512, p_max=10):
    """
    Spawns points into a point cloud based on a normalized error grid.
    
    Args:
        error_grid: 3D numpy array of shape (512, 512, 512) with values in [0, 1].
        p_max: Maximum points per voxel (default 10).
        
    Returns:
        new_points: List of 3D coordinates (x, y, z) to be added to the cloud.
    """
    new_points = []
    
    # Iterate over all voxels in the 512^3 grid
    for x in range(512):
        for y in range(512):
            for z in range(512):
                e_i = error_grid[x, y, z]
                
                # Calculate number of points to spawn
                # Formula: floor(e_i * p_max)
                n_spawn = int(e_i * p_max)
                
                if n_spawn > 0:
                    # Determine voxel boundaries
                    # Assuming unit voxel size or normalized coordinates [0,1]
                    # The source says "randomly distributed in the cell"
                    # We assume the grid covers the bounding box of the scene.
                    # For implementation, one must map grid indices to world coordinates.
                    # Let's assume voxel_size is known or coordinates are normalized.
                    
                    # Generate n_spawn random points within this voxel
                    for _ in range(n_spawn):
                        # Random offset within the voxel
                        # If grid is normalized [0,1], voxel size is 1/512
                        voxel_size = 1.0 / 512.0
                        
                        # Random position within the voxel cell
                        rx = x + random.uniform(0, 1)
                        ry = y + random.uniform(0, 1)
                        rz = z + random.uniform(0, 1)
                        
                        # Convert to world coordinates if necessary
                        # [G] Assuming normalized coordinates for simplicity; 
                        # actual implementation requires scaling by voxel_size and offset.
                        world_x = rx * voxel_size
                        world_y = ry * voxel_size
                        world_z = rz * voxel_size
                        
                        new_points.append((world_x, world_y, world_z))
                        
    return new_points
```

**Edge Cases and Pitfalls**
*   **Scattering:** Unlike methods that unproject pixel errors and sum them into voxels (which scatters spawns over larger regions), VET confines spawns to specific voxels. This avoids the need for thresholding that might miss details [S1].
*   **Inaccuracy:** Adding too many or inaccurately placed points is not a critical issue because the VET framework includes a robust outlier removal strategy that cleans these points later [S1].
*   **Convergence:** The process is iterative. In practice, points are spawned only 1–3 times during training. Further spawning yields no significant improvement [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels ($512^3$) and the number of spawned points. The spawning step itself is fast, but the overall pipeline cost is dominated by the subsequent outlier removal and rendering [S1].
*   **Memory Complexity:** The memory footprint increases temporarily during spawning but returns to a level similar to the initial reconstruction after the cleaning step. There is no significant long-term impact on memory consumption or render times compared to the initial state [S1].
*   **Performance:** Using SSIM as the error metric yields the best rendering quality (PSNR, SSIM, LPIPS) by guiding points to thin structures [S1].
*   **Scaling:** The number of newly inserted points per step ranges from 10k to 2000k, depending on the error volume [S1].
*   **When to use:** Use when high-fidelity neural rendering is required and the initial point cloud (e.g., from sparse COLMAP) lacks detail. It is particularly effective for recovering thin structures.
*   **When not to use:** Avoid if memory or compute constraints are extremely tight and the initial reconstruction is already sufficient, as the spawning/cleaning cycle adds overhead. Also, naive point-growing strategies without VET's error-guided approach lead to significant point cloud bloat without quality gains [S1].

## Background
VET Point Spawning was introduced in the VET (Visual Error Tomography) framework for point cloud completion and high-quality neural rendering. The method addresses limitations in previous point-growing strategies (like those in PointNeRF or SNP) which suffered from scattered point distributions and significant increases in point cloud size without proportional quality improvements [S1]. The approach leverages a 3D error volume derived from multi-view rendering errors to guide refinement.
