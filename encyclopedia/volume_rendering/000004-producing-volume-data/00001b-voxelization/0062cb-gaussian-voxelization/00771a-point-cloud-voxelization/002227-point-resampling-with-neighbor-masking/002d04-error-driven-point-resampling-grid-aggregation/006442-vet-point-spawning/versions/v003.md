# VET Point Spawning

Also called: Point Growing in VET Framework, Point Spawning in VET

## Overview
VET Point Spawning is a process to add points to a point cloud based on a visual error volume to improve neural rendering quality [S1]. Unlike naive point-growing strategies or methods that unproject pixel errors into voxels (such as SNP), VET spawns points directly within error-weighted voxels, avoiding the need for aggressive thresholding or cleaning that typically degrades quality or inflates memory usage [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D voxel grid of normalized visual error values $E$, typically of resolution $512^3$ [S1]. Each voxel $(x, y, z)$ contains a value $e_i \in [0, 1]$ representing the local error density [S1].
*   **Output:** A modified point cloud with additional points inserted into voxels with $e_i > 0$ [S1].

**Data Structures**
*   **Error Grid:** A 3D array of floats with fixed resolution $512^3$ [S1].
*   **Point Cloud:** A collection of 3D coordinates that maintains a similar total count to the initial reconstruction after the full spawning and cleaning cycle [S1].

**Parameters**
*   $p_{max}$: Maximum number of points to spawn per voxel. Typical value: 10 [S1].
*   $n(x, y, z)$: Number of points to spawn in voxel $(x, y, z)$ [S1].

**Steps**
1.  **Normalize Error:** Scale the error grid values $e_i$ to the range $[0, 1]$ [S1]. The source notes that SSIM is the preferred error metric for this normalization as it guides spawning in thin locations effectively [S1].
2.  **Calculate Spawn Count:** For each voxel $(x, y, z)$ with error value $e_i$, compute the number of points to spawn:
    $$ n(x, y, z) = \lfloor e_i(x, y, z) \cdot p_{max} \rfloor $$
    If $n(x, y, z) = 0$, no points are added to this voxel [S1].
3.  **Spawn Points:** For each voxel where $n(x, y, z) > 0$, generate $n(x, y, z)$ new points [S1]. The positions of these points are distributed randomly within the boundaries of the voxel cell [S1].
4.  **Integration:** Add the newly spawned points to the existing point cloud [S1]. This step is followed by an outlier removal strategy which cleans inaccurately placed points, making the randomness of spawning robust [S1].

**Pseudocode**
```python
import random

def vet_point_spawning(error_grid, p_max=10):
    """
    Spawns points into a point cloud based on a normalized error grid.
    
    Args:
        error_grid: 3D array of shape (512, 512, 512) with values in [0, 1].
        p_max: Maximum points per voxel (default 10).
        
    Returns:
        new_points: List of 3D coordinates (x, y, z) to be added to the cloud.
    """
    new_points = []
    grid_size = error_grid.shape[0]  # Assumes cubic grid, typically 512
    voxel_size = 1.0 / grid_size
    
    for x in range(grid_size):
        for y in range(grid_size):
            for z in range(grid_size):
                e_i = error_grid[x, y, z]
                n_spawn = int(e_i * p_max)
                
                if n_spawn > 0:
                    for _ in range(n_spawn):
                        # Random position within the voxel cell [x, x+1) in grid coordinates
                        rx = x + random.uniform(0.0, 1.0)
                        ry = y + random.uniform(0.0, 1.0)
                        rz = z + random.uniform(0.0, 1.0)
                        
                        # Convert to world coordinates assuming scene bounding box is [0, 1]^3
                        world_x = rx * voxel_size
                        world_y = ry * voxel_size
                        world_z = rz * voxel_size
                        
                        new_points.append((world_x, world_y, world_z))
                        
    return new_points
```

**Edge Cases and Pitfalls**
*   **Scattering:** Unlike methods that unproject pixel errors and sum them into voxels (which scatters spawns over larger regions), VET confines spawns to specific voxels. This avoids the need for thresholding that might miss details [S1].
*   **Inaccuracy:** Adding too many or inaccurately placed points is not a critical issue because the VET framework includes a robust outlier removal strategy that cleans these points later [S1].
*   **Convergence:** The process is iterative. In practice, points are spawned only 1–3 times during training [S1]. Further spawning yields no significant improvement [S1].

## Subtopics

### Point Growing
A procedure to fill point cloud holes in textureless regions by adding new points during inverse rendering [S2]. It performs point growing every 500 iterations by sampling random rays and computing their first intersection with the geometry field [S2]. At each intersection, it adds a point if the distance to the closest point in the existing point cloud is greater than a threshold [S2]. For each new point, it initializes attributes by averaging those of its neighbors, computes a normal using Principal Component Analysis (PCA) [S2], then recomputes the area weights of the entire point cloud [S2]. The number of additional points grown is approximately 10% of the original dense point cloud from structure from motion [S2]. Unlike VET, this strategy increases point cloud sizes significantly compared to VET while facing similar reconstruction difficulties [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1].
*   **Memory Complexity:** The memory footprint increases temporarily during spawning but returns to a level similar to the initial reconstruction after the cleaning step. There is no significant long-term impact on memory consumption or render times compared to the initial state [S1].
*   **Performance:** Using SSIM as the error metric yields the best rendering quality (PSNR, SSIM, LPIPS) by guiding points to thin structures [S1].
*   **Scaling:** The number of newly inserted points per step ranges from 10k to 2000k, depending on the error volume [S1].
*   **When to use:** Use when high-fidelity neural rendering is required and the initial point cloud lacks detail [S1]. It is particularly effective for recovering thin structures [S1].
*   **When not to use:** Avoid naive point-growing strategies without VET's error-guided approach, as they lead to significant point cloud bloat without quality gains [S1].

## Background
VET Point Spawning was introduced in the VET (Visual Error Tomography) framework for point cloud completion and high-quality neural rendering [S1]. The method addresses limitations in previous point-growing strategies (like those in PointNeRF or SNP) which suffered from scattered point distributions and significant increases in point cloud size without proportional quality improvements [S1]. The approach leverages a 3D error volume derived from multi-view rendering errors to guide refinement [S1].
