# Voxels to Points Projection


## Overview
Voxels to Points Projection maps features from a dense 3D voxel grid back to specific points in an original point cloud using a pre-computed point-to-voxel mapping [S1, unofficial]. It solves the problem of aggregating dense voxel grid data onto sparse, unstructured point clouds, enabling downstream tasks like volume rendering or segmentation where point-wise features are required [S1, unofficial]. It differs from its parent, [Point Cloud Voxelization](1000-point-cloud-voxelization.md), by relying on a direct integer index mapping rather than geometric projection, making it suitable for cases where voxelization has already established a deterministic correspondence between points and voxels [S1, unofficial].

## How it works
**Inputs:**
1. `voxels`: A tensor of shape $[X, Y, Z, F]$ containing feature values for each voxel cell, where $X, Y, Z$ are grid dimensions and $F$ is the feature dimension [S1, unofficial].
2. `segment_ids`: A tensor of shape $[N]$ containing integer indices, where $N$ is the number of points in the original point cloud [S1, unofficial]. Each element `segment_ids[i]` is the linearized index of the voxel cell containing point $i$ [S1, unofficial].

**Outputs:**
1. `point_features`: A tensor of shape $[N, F]$ where each row $i$ contains the feature vector from the voxel cell identified by `segment_ids[i]` [S1, unofficial].

**Data Structures:**
- The voxel grid is treated as a dense 4D tensor [S1, unofficial].
- The segment IDs are a 1D integer array mapping point indices to linearized voxel indices [S1, unofficial]. The linearized index $L$ for a voxel at $(x, y, z)$ in a grid of size $(X, Y, Z)$ is calculated as $L = x \cdot (Y \cdot Z) + y \cdot Z + z$ [G].

**Steps:**
1. **Flatten the Voxel Grid:** Reshape the 4D voxel tensor $[X, Y, Z, F]$ into a 2D tensor of shape $[X \cdot Y \cdot Z, F]$ [S1, unofficial]. This creates a list of all voxel feature vectors, indexed by their linearized position [S1, unofficial].
2. **Gather Features:** Use the `segment_ids` tensor to index into the flattened voxel tensor [S1, unofficial]. For each point $i$, retrieve the feature vector at index `segment_ids[i]` from the flattened list [S1, unofficial].

**Pseudocode:**
```python
def voxels_to_points(voxels, segment_ids):
    # voxels: array of shape [X, Y, Z, F]
    # segment_ids: array of shape [N]
    # Step 1: Flatten spatial dimensions (X, Y, Z) into a single dimension.
    flattened_voxels = voxels.reshape(-1, voxels.shape[-1])
    # Step 2: Gather the feature vector for each point using its segment ID.
    point_features = flattened_voxels[segment_ids]
    return point_features
```

**Parameters:**
- `voxels`: Shape $[X, Y, Z, F]$. Data type `float32` [S1, unofficial].
- `segment_ids`: Shape $[N]$. Data type `int32` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Invalid Points:** If a point does not fall within the voxel grid bounds, its `segment_id` may be invalid or point to a background/empty voxel [S1, unofficial]. The basic implementation simply gathers whatever value is at that index [S1, unofficial]. Implementers should ensure `segment_ids` are clamped or masked if out-of-bounds indices are possible [G].
- **Precision:** The mapping relies on integer indices. Any mismatch between the voxelization step that generated `segment_ids` and this projection step will result in incorrect feature assignment [S1, unofficial].

## Subtopics

### [Voxel Value Lifting](8461-voxel-value-lifting.md)
Voxel Value Lifting maps per-voxel values (such as encoded predictions or features) back to the original point rows using a pre-computed point-to-voxel mapping. It solves the problem of aggregating dense voxel grid data onto sparse, unstructured point clouds, enabling downstream tasks like volume rendering or segmentation where point-wise features are required. It differs from its parent, [Voxels to Points Projection](3172-voxels-to-points-projection.md), by relying on a direct integer index mapping rather than geometric projection or segment IDs, making it suitable for cases where voxelization has already established a deterministic correspondence between points and voxels.

### Voxel-to-Point Interpolation via KNN
This variant avoids hard assignment by interpolating features from the $K$ nearest voxels to each point [S2, unofficial]. It is chosen when smooth transitions between voxel features are required or when points fall near voxel boundaries where hard assignment is unstable [S2, unofficial].
**Steps:**
1. Split voxel coordinates and features by batch ID into lists `voxel_coords_split` and `voxel_feats_split` [S2, unofficial].
2. Compute lengths of each batch's voxel list and pad them to a maximum length `max_T` using zero-padding [S2, unofficial].
3. Perform K-Nearest Neighbors (KNN) search between original points and padded voxel coordinates using `knn_points(original_pts, voxel_coords_padded, lengths2=voxel_lens, K=K_interp)` [S2, unofficial].
4. Gather features from the $K$ nearest voxels using `knn_gather(voxel_feats_padded, idx_chunk)` [S2, unofficial].
5. Compute interpolation weights as the reciprocal of distances, clamped to a minimum of $10^{-8}$, then normalized by summing over the $K$ dimension [S2, unofficial].
6. Compute interpolated features by summing the product of gathered features and weights over the $K$ dimension [S2, unofficial].
**Parameters:**
- `chunk_size`: Integer controlling the number of points processed in each chunk during interpolation, default 50,000 [S2, unofficial].
- `k_neighbors`: Attribute `self.k_neighbors` defining the number of neighbors $K$ for interpolation [S2, unofficial].
**Pitfalls:**
- Distances are clamped to a minimum of $10^{-8}$ to prevent division by zero during weight calculation [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The basic projection is $O(N)$ for gathering, where $N$ is the number of points, plus $O(XYZ)$ for flattening the voxel grid [S1, unofficial]. The KNN variant requires KNN search and interpolation over $K$ neighbors, plus padding overhead [S2, unofficial].
- **Memory Complexity:** Requires storing the full voxel grid $[X, Y, Z, F]$ and the segment IDs $[N]$ [S1, unofficial]. The KNN variant requires additional memory for padded voxel lists and intermediate KNN indices [S2, unofficial].

## Background
The method is implemented in TensorFlow 3D utilities within the `voxel_utils.py` module [S1, unofficial]. It is used in 3D deep learning pipelines where point clouds are voxelized for efficient convolutional processing and then projected back to points for loss computation or further point-based operations [S1, unofficial]. The KNN variant appears in recent research on voxel-based vision-language models to handle feature interpolation in 3D space [S2, unofficial].
