# Voxel Value Lifting
## Overview
Voxel Value Lifting maps per-voxel values (such as encoded predictions or features) back to the original point rows using a pre-computed point-to-voxel mapping [S1, unofficial]. It solves the problem of aggregating dense voxel grid data into a sparse point cloud structure, effectively reversing the voxelization step to restore point-level granularity [S1, unofficial]. It differs from its parent [Voxels to Points Projection](3172-voxels-to-points-projection.md) by operating on the output of voxelization to reconstruct point features, whereas the parent method projects features from a dense grid back to specific points using segment IDs. It is the inverse of [3D Feature Construction via Lifting and Voxelization](13053-3d-feature-construction-via-lifting-and-voxelization.md), which lifts 2D image features into 3D space [S1, unofficial].
## How it works
**Inputs:**
1. `voxel_values`: A 1D array of shape `[V]` or `[V, C]` containing values for each voxel, where `V` is the number of voxels. Data type is typically `float64` or `int64` depending on the value type [S1, unofficial].
2. `point_to_voxel`: A 1D integer array of shape `[N]`, where `N` is the number of points. Each element is the index of the voxel that the corresponding point belongs to. Valid indices are in `[0, V-1]`. Invalid points have a mapping of `-1` [S1, unofficial].

**Outputs:**
1. `lifted_values`: A 1D or 2D array of shape `[N]` or `[N, C]`. Each row `i` contains the value from the voxel indexed by `point_to_voxel[i]`. If `point_to_voxel[i] == -1`, the output is a designated fill value (e.g., ignore label) [S1, unofficial].

**Data Structures:**
- `point_to_voxel`: `int64` array. Stores the index of the voxel for each point.
- `voxel_values`: `float64` or `int64` array. Stores the aggregated value for each voxel.

**Steps:**
1. Initialize `lifted_values` with the fill value (e.g., `255` for ignore labels, or `0.0` for features) for all `N` points [S1, unofficial].
2. Identify valid point indices where `point_to_voxel[i] >= 0` [S1, unofficial].
3. For each valid point index `i`, retrieve the voxel index `v = point_to_voxel[i]`.
4. Assign `lifted_values[i] = voxel_values[v]` [S1, unofficial].
5. Points with `point_to_voxel[i] == -1` retain the fill value, ensuring they do not access out-of-bounds memory or retrieve incorrect data [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def lift_voxel_values(voxel_values: np.ndarray, point_to_voxel: np.ndarray, fill_value: float = 255.0) -> np.ndarray:
    """
    Maps per-voxel values back to point rows.
    
    Args:
        voxel_values: Array of shape (V,) or (V, C) containing voxel data.
        point_to_voxel: Array of shape (N,) containing voxel indices for each point. -1 indicates invalid.
        fill_value: Value to assign to points with invalid voxel mappings.
        
    Returns:
        Array of shape (N,) or (N, C) with lifted values.
    """
    N = point_to_voxel.shape[0]
    
    # Determine output shape based on voxel_values
    if voxel_values.ndim == 1:
        output_shape = (N,)
    else:
        output_shape = (N, voxel_values.shape[1])
        
    # Initialize with fill value
    lifted_values = np.full(output_shape, fill_value, dtype=voxel_values.dtype)
    
    # Identify valid points (mapping >= 0)
    valid_mask = point_to_voxel >= 0
    
    # Get valid voxel indices
    valid_voxel_indices = point_to_voxel[valid_mask]
    
    # Check for out-of-bounds indices (should not happen if voxelization is correct)
    if np.any(valid_voxel_indices >= voxel_values.shape[0]):
        raise IndexError("Voxel index out of bounds")
        
    # Lift values for valid points
    if voxel_values.ndim == 1:
        lifted_values[valid_mask] = voxel_values[valid_voxel_indices]
    else:
        lifted_values[valid_mask] = voxel_values[valid_voxel_indices]
        
    return lifted_values
```

**Parameters:**
- `fill_value`: Default value for invalid points. Typically `255` for segmentation ignore labels or `0.0` for continuous features [S1, unofficial].

**Edge Cases:**
- **Invalid Coordinates:** Points with non-finite coordinates or features are assigned `point_to_voxel` value `-1` during voxelization. Lifting must handle these to avoid out-of-bounds access [S1, unofficial].
- **Precision:** Coordinates and features normalize to `float64`; mappings and indices use `int64` [S1, unofficial].
- **Overflow:** Finite values in input must not exceed `float64` range during conversion [S1, unofficial].

## Subtopics

### [3D Feature Construction via Lifting and Voxelization](13053-3d-feature-construction-via-lifting-and-voxelization.md)
Constructs a structured 3D feature volume from unstructured point clouds derived from multi-view images. It differs by operating in the forward direction (2D to 3D), whereas Voxel Value Lifting operates in the reverse direction (voxel to point).

## Operating characteristics
**Time Complexity:** $O(N)$, where $N$ is the number of points. The operation involves a single pass over the `point_to_voxel` array to index into `voxel_values` [S1, unofficial].
**Memory Complexity:** $O(N)$ for the output array. The input `point_to_voxel` and `voxel_values` are read-only [S1, unofficial].
**Strengths:** Efficiently reconstructs point-level data from aggregated voxel data without re-computing spatial mappings. Preserves original point IDs and row positions [S1, unofficial].
**Limitations:** Requires pre-computed `point_to_voxel` mapping. Does not handle points that were not voxelized or were filtered out during voxelization (they remain as `-1` mappings) [S1, unofficial].
**When to Use:** When you have aggregated voxel features (e.g., from a 3D CNN) and need to project them back to the original sparse point cloud for further processing or visualization [S1, unofficial].
**When Not to Use:** When you need to generate voxel features from raw points (use voxelization) or when you need to project features from a dense grid to specific points using segment IDs (use [Voxels to Points Projection](3172-voxels-to-points-projection.md)) [S1, unofficial].

## Background
Voxel Value Lifting is a method used in point cloud processing pipelines, particularly in deep learning frameworks that operate on sparse voxel grids. It is part of the `pointcloud-core` library, which provides utilities for point cloud manipulation [S1, unofficial]. The method ensures that aggregated voxel data can be accurately mapped back to the original point cloud structure, maintaining the integrity of point-level information for tasks such as semantic segmentation or classification [S1, unofficial].
