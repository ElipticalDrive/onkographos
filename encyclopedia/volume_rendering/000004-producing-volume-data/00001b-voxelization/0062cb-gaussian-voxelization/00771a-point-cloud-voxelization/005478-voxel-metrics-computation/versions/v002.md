# Voxel Metrics Computation

Also called: Voxel Feature Aggregation via Formula

## Overview
Voxel Metrics Computation is a versatile voxelization function in the `lidR` R package that returns a `lasmetrics3d` object [S1]. It is designed for elaborate voxel metrics computation rather than simple grid binning [S1]. It differs from sibling methods like [Hard Voxelization](5345-hard-voxelization.md) by using a user-defined formula to compute arbitrary metrics per voxel instead of fixed aggregation rules [S1, S2].

## How it works
**Inputs and Outputs:**
- **Input:** A `LAS` object containing point cloud data, a `formula` specifying metrics to compute, and a `res` parameter for resolution [S1, S2].
- **Output:** A `lasmetrics3d` object containing the voxel grid and computed metrics [S1, S2].

**Data Structures:**
The `lasmetrics3d` object contains the voxel grid and the results of the formula evaluation for each voxel [S1]. A critical structural requirement is that it must contain a column named `N` (recording the number of points in each voxel) to be accepted by downstream functions like `lacunr::bounding_box()` [S1].

**Numbered Steps:**
1. **Grid Initialization:** Determine the bounding box of the input point cloud and divide the X and Y extents into bins based on the `res` parameter [S1, S2]. The bin count follows `lidR`'s specific alignment algorithm, which yields one more bin than standard floor-based binning for integer spans [S1, S2].
2. **Point Assignment:** Assign each point in the `LAS` object to a voxel bin based on its X and Y coordinates [S1, S2]. Points are grouped by their assigned voxel index [S1, S2].
3. **Metric Computation:** For each voxel containing points, evaluate the `formula` in the context of the subset of points belonging to that voxel [S1, S2]. The formula variables include point attributes such as `X`, `Y`, and `Z` [S1, S2].
4. **Result Construction:** Assemble the computed metrics and grid dimensions into a `lasmetrics3d` object [S1, S2].

**Formulas:**
- Bin count per dimension: $B = \lfloor (V_{\max} - V_{\min}) / \text{res} \rfloor + 1$, where $V$ is the coordinate axis ($X$ or $Y$), $V_{\max}$ and $V_{\min}$ are the point cloud extents, and $\text{res}$ is the resolution [S1, S2]. This alignment rule explains why a 12-meter span at 1-meter resolution produces 13 bins instead of 12 [S1, S2].
- Point assignment index: $I = \lfloor (V - V_{\min}) / \text{res} \rfloor$, clamped to $[0, B-1]$ to handle points exactly on the maximum boundary [G].

**Parameters:**
- `res`: The voxel resolution for the X and Y dimensions [S1, S2]. It accepts a single numeric value or a vector of length 2 [S1, S2]. If a single value is provided, it applies to both X and Y; if two values are provided, they apply to X and Y respectively [S1, S2]. The function permits at most two dimensions for resolution specification [S1, S2].
- `formula`: An R formula specifying the metrics to compute per voxel [S1]. The right-hand side must evaluate to a list of named values [S1]. For example, `~list(N = length(Z))` computes the point count [S1, S2].

**Edge Cases and Pitfalls:**
- **Missing 'N' Column:** If the output `lasmetrics3d` object is passed to `lacunr::bounding_box()`, it must contain a column named `N` recording the number of points in each voxel; failing to include this column will cause an error [S1].
- **Resolution Dimensions:** `voxel_metrics()` permits at most two dimensions for voxel resolution, unlike `voxelize()` which requires three [S1, S2].
- **Alignment Differences:** The alignment of the point cloud within the voxel grid differs from other tools like `lacunr::voxelize()`, resulting in different bin counts for the same input [S1, S2]. For example, a 12-meter span with 1-meter resolution yields 13 voxels in `lidR` but 12 in `voxelize()` [S1, S2].

**Pseudocode:**
```python
import math

def voxel_metrics(las_points, formula_func, res):
    """
    Compute voxel metrics for a point cloud.
    Args:
        las_points: List of dicts with keys 'X', 'Y', 'Z'.
        formula_func: Callable taking a dict of lists (X, Y, Z) and returning a dict of metrics.
        res: Resolution for X and Y. Scalar or tuple of two scalars.
    Returns:
        dict representing lasmetrics3d object with 'grid', 'res', 'dims'.
    """
    # 1. Determine grid dimensions
    x_min = min(p['X'] for p in las_points)
    x_max = max(p['X'] for p in las_points)
    y_min = min(p['Y'] for p in las_points)
    y_max = max(p['Y'] for p in las_points)

    if isinstance(res, (int, float)):
        res_x, res_y = res, res
    elif isinstance(res, tuple) and len(res) == 2:
        res_x, res_y = res
    else:
        raise ValueError("Resolution must be a scalar or a 2-tuple")

    # lidR alignment yields floor(span/res) + 1 for integer spans (e.g., 12m/1m -> 13 bins)
    num_bins_x = int(math.floor((x_max - x_min) / res_x)) + 1
    num_bins_y = int(math.floor((y_max - y_min) / res_y)) + 1

    # 2. Initialize grid
    grid = [[[] for _ in range(num_bins_y)] for _ in range(num_bins_x)]

    # 3. Assign points to voxels
    for p in las_points:
        vx = int(math.floor((p['X'] - x_min) / res_x))
        vy = int(math.floor((p['Y'] - y_min) / res_y))
        # Clamp to bounds to handle edge points exactly on max
        vx = min(vx, num_bins_x - 1)
        vy = min(vy, num_bins_y - 1)
        grid[vx][vy].append(p)

    # 4. Compute metrics
    metrics_grid = [[None for _ in range(num_bins_y)] for _ in range(num_bins_x)]
    for i in range(num_bins_x):
        for j in range(num_bins_y):
            points_in_voxel = grid[i][j]
            if points_in_voxel:
                subset = {
                    'X': [p['X'] for p in points_in_voxel],
                    'Y': [p['Y'] for p in points_in_voxel],
                    'Z': [p['Z'] for p in points_in_voxel]
                }
                metrics_grid[i][j] = formula_func(subset)
            else:
                metrics_grid[i][j] = None

    # 5. Return structured result
    return {
        'grid': metrics_grid,
        'res': res,
        'dims': (num_bins_x, num_bins_y)
    }
```

## Subtopics

### Building Envelope Voxel Metrics
A technique to extract physical and architectural building parameters from aerial LiDAR and property records by treating buildings as voxelized objects [S3]. Each building is treated as an object in a voxelized form consisting of 1m³ cubes [S3]. The calculation is completed by associating the number of voxels to the height equal to Digital Surface Model (DSM) [S3].

## Operating characteristics
- **Time Complexity:** Not given in the sources. The algorithm iterates over all points once for assignment and then evaluates the formula per voxel, so performance scales linearly with point count and depends on formula complexity.
- **Memory Complexity:** Not given in the sources. Storage scales with the number of voxels to hold the grid and computed metrics.
- **Strengths:** High flexibility in metric computation via user-defined formulas [S1, S2]. Integrated with the `lidR` ecosystem for LiDAR data processing [S1, S2].
- **Limitations:** Limited to 2D resolution specification [S1, S2]. Different alignment behavior compared to other voxelization tools may cause inconsistencies in cross-tool workflows [S1, S2]. R overhead may impact performance compared to compiled implementations [G].

## Background
The `voxel_metrics()` function is part of the `lidR` package for LiDAR data processing [S1, S2]. It was designed as a versatile alternative to simpler voxelization functions like `voxelize()`, which is adapted from the `voxels()` function originally written by J. Antonio Guzmán Q. for the `rTLS` package [S1, S2]. Both functions utilize different underlying algorithms and will not produce identical results from the same input data [S1, S2].
