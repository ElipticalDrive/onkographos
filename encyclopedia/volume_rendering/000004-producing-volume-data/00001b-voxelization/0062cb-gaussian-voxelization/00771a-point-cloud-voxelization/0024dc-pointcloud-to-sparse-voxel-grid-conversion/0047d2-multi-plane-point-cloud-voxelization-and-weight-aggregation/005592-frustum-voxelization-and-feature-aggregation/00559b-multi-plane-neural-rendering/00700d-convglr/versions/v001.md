# ConvGLR

Also called: Convolutional Global Latent Renderer, global latent neural rendering

## Overview
ConvGLR is a convolutional architecture for generalizable novel view synthesis that renders target views by operating on all camera rays jointly in a low-resolution latent space [S1, unofficial]. It solves the problem of grainy artifacts common in single-ray methods by learning a global rendering operator directly from a 5-dimensional Plane Sweep Volume (PSV) representation, rather than predicting radiance/density fields or layered representations [S1, unofficial]. Unlike its sibling [Multi-plane Neural Rendering](15529-multi-plane-neural-rendering.md), which uses a U-Net-like 3D CNN to predict multi-plane images, ConvGLR collapses the depth dimension progressively in a latent space to produce the final image without explicit alpha blending or volumetric integration [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $V$ input views, each of height $H$ and width $W$ with RGB channels, stacked into a 4D tensor $I \in \mathbb{R}^{V \times 3 \times H \times W}$ [S1, unofficial]. Camera parameters include intrinsic $K \in \mathbb{R}^{V \times 3 \times 3}$, rotation $R \in \mathbb{R}^{V \times 3 \times 3}$, and translation $t \in \mathbb{R}^{V \times 3 \times 1}$ [S1, unofficial]. Target view parameters are $K^*, R^*, t^*$ [S1, unofficial].
*   **Intermediate Representation:** A 5-dimensional Plane Sweep Volume (PSV) constructed by projecting input images onto a set of planes facing the target camera. The PSV has dimensions $[V, C, H, W, D]$, where $V$ is views, $C$ is channels, $H, W$ are spatial dimensions, and $D$ is depth [S1, unofficial]. The PSV implicitly encodes epipolar geometry: mixing across epipolar lines uses the view dimension, mixing along epipolar lines uses the depth dimension, and mixing between light rays uses the height and width dimensions [S1, unofficial].
*   **Output:** A rendered target image $\tilde{I}^*$ of dimensions $[1, 3, H, W]$ [S1, unofficial].

**Data Structures:**
The method operates on 5D tensors. To ensure memory efficiency, in-place viewing operations are used extensively, avoiding expensive reshape or transpose operations [S1, unofficial].

**Algorithm Steps:**
The method consists of four sequential steps: (1) Grouped PSV, (2) Multi-view matching, (3) Global latent rendering, and (4) Upsampling [S1, unofficial].

1.  **Grouped PSV:**
    *   Input: 5D PSV with dimensions $[batch, channels, height, width, DV]$.
    *   Operation: Concatenate views.
    *   Output: Dimensions $[batch, 3V, H, W, DG]$ [S1, unofficial].

2.  **Multi-view Matching:**
    *   Input: Output from Step 1.
    *   Operation: Apply a view convolution followed by 2 residual blocks (resblocks).
    *   Output: Dimensions $[batch, 3GV, H, W, DG]$ [S1, unofficial].

3.  **Global Latent Rendering:**
    *   Input: Output from Step 2.
    *   Operation: Apply a view convolution with stride 2, followed by 3 residual blocks. This step progressively collapses the depth dimension.
    *   Output: Dimensions $[batch, 2C, H/2, W/2, DG/2]$ [S1, unofficial].
    *   *Implementation Note:* Two implementations exist for this step. One uses shared weights over depths (using the batch dimension for parallel processing). The other uses specialized weights by moving depths to the channel dimension and using grouped convolutions. No significant performance difference was observed [S1, unofficial].

4.  **Upsampling:**
    *   Input: Output from Step 3.
    *   Operation: Apply a view convolution with stride 2, followed by 4 residual blocks.
    *   Output: Dimensions $[batch, 4C, H/4, W/4, DG/4]$ [S1, unofficial].
    *   *Final Upsampling:* Apply a view convolution, followed by 1 residual block, then nearest neighbor interpolation. Output: $[batch, 4C, H/2, W/2, DG/16]$ [S1, unofficial].
    *   *Final Output:* Apply a view convolution, followed by 2 residual blocks, then nearest neighbor interpolation. Output: $[batch, C, H, W, 3]$ [S1, unofficial].

**Shared Weights Implementation Structure (Global Latent Rendering):**
For the specialized weights implementation, the structure is as follows [S1, unofficial]:
*   Input: $[1, DG \times 4C, H/4, W/4]$.
*   Block 1: 1 resblock ($DG/2$ groups). Output: $[1, DG/2 \times 4C, H/4, W/4]$.
*   Block 2: 1 resblock ($DG/4$ groups). Output: $[1, DG/4 \times 4C, H/4, W/4]$.
*   Block 3: 1 resblock ($DG/8$ groups). Output: $[1, DG/8 \times 4C, H/4, W/4]$.
*   Block 4: 1 resblock ($DG/16$ groups). Output: $[1, DG/16 \times 4C, H/4, W/4]$.
*   Final Block: 1 resblock. Output: $[1, 4C, H/4, W/4]$ [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ConvGLR(nn.Module):
    def __init__(self, V, H, W, D, C_in=3, C_base=64):
        super().__init__()
        self.V = V
        self.H = H
        self.W = W
        self.D = D
        self.C_in = C_in
        self.C_base = C_base
        
        # Define residual block
        class ResBlock(nn.Module):
            def __init__(self, channels, groups=1):
                super().__init__()
                self.conv1 = nn.Conv3d(channels, channels, kernel_size=3, padding=1, groups=groups)
                self.conv2 = nn.Conv3d(channels, channels, kernel_size=3, padding=1, groups=groups)
                self.relu = nn.ReLU(inplace=True)
            
            def forward(self, x):
                out = self.relu(self.conv1(x))
                out = self.conv2(out)
                return self.relu(out + x)

        # Step 1: Grouped PSV (Concatenate views)
        # Input: [B, C_in, H, W, D] -> Output: [B, 3*V, H, W, D] (assuming C_in=3)
        # Note: The source describes this as concatenating views. 
        # In a 5D tensor [B, C, H, W, D], views are usually a separate dimension or part of C.
        # Based on source [S1, unofficial]: Input [batch, channels, height, width, DV] -> Output [batch, 3V, H, W, DG]
        # We assume the input PSV is already constructed. The "concatenate views" step likely refers to 
        # rearranging the view dimension into the channel dimension or similar.
        # For implementation clarity, we assume the input `psv` is [B, V, C_in, H, W, D] or similar.
        # The source says Input is 5D PSV [batch, channels, height, width, DV]. 
        # Let's assume the input `x` is [B, C_in*V, H, W, D] effectively, or we permute.
        # To match source dimensions exactly:
        # Step 1 Output: [B, 3V, H, W, DG]. DG is likely D or a grouped depth.
        # Let's assume DG = D for simplicity unless specified.
        
        # Step 2: Multi-view matching
        # View conv + 2 resblocks
        self.step2_conv = nn.Conv3d(3*V, 3*V, kernel_size=3, padding=1) # View conv
        self.step2_res1 = ResBlock(3*V)
        self.step2_res2 = ResBlock(3*V)
        
        # Step 3: Global latent rendering
        # View conv stride 2 + 3 resblocks
        self.step3_conv = nn.Conv3d(3*V, 2*C_base, kernel_size=3, stride=2, padding=1)
        self.step3_res1 = ResBlock(2*C_base)
        self.step3_res2 = ResBlock(2*C_base)
        self.step3_res3 = ResBlock(2*C_base)
        
        # Step 4: Upsampling
        # View conv stride 2 + 4 resblocks
        self.step4_conv = nn.Conv3d(2*C_base, 4*C_base, kernel_size=3, stride=2, padding=1)
        self.step4_res1 = ResBlock(4*C_base)
        self.step4_res2 = ResBlock(4*C_base)
        self.step4_res3 = ResBlock(4*C_base)
        self.step4_res4 = ResBlock(4*C_base)
        
        # Final Upsampling
        self.final_conv1 = nn.Conv3d(4*C_base, 4*C_base, kernel_size=3, padding=1)
        self.final_res1 = ResBlock(4*C_base)
        
        # Final Output
        self.final_conv2 = nn.Conv3d(4*C_base, C_base, kernel_size=3, padding=1)
        self.final_res2 = ResBlock(C_base)
        self.final_conv3 = nn.Conv3d(C_base, 3, kernel_size=1) # To get RGB

    def forward(self, psv):
        # psv shape: [B, C_in*V, H, W, D] or [B, V, C_in, H, W, D]?
        # Source says Input 5D PSV [batch, channels, height, width, DV].
        # Let's assume psv is [B, C_in*V, H, W, D] where C_in=3.
        
        # Step 1: Grouped PSV
        # Source: Input [batch, channels, height, width, DV] -> Output [batch, 3V, H, W, DG]
        # If input is [B, 3*V, H, W, D], this step might be a permutation or identity if DG=D.
        # We assume the input is already in the correct format for Step 2.
        x = psv 
        
        # Step 2: Multi-view matching
        x = self.step2_conv(x)
        x = self.step2_res1(x)
        x = self.step2_res2(x)
        
        # Step 3: Global latent rendering
        x = self.step3_conv(x)
        x = self.step3_res1(x)
        x = self.step3_res2(x)
        x = self.step3_res3(x)
        
        # Step 4: Upsampling
        x = self.step4_conv(x)
        x = self.step4_res1(x)
        x = self.step4_res2(x)
        x = self.step4_res3(x)
        x = self.step4_res4(x)
        
        # Final Upsampling
        x = self.final_conv1(x)
        x = self.final_res1(x)
        # Nearest neighbor interpolation to double spatial dims
        x = F.interpolate(x, scale_factor=2, mode='trilinear', align_corners=False)
        
        # Final Output
        x = self.final_conv2(x)
        x = self.final_res2(x)
        x = self.final_conv3(x)
        # Nearest neighbor interpolation to double spatial dims again
        x = F.interpolate(x, scale_factor=2, mode='trilinear', align_corners=False)
        
        # x shape: [B, 3, H, W, D] -> Permute to [B, 3, H, W] if D=1 or aggregate?
        # Source says Final Output: [batch, C, H, W, 3].
        # This implies the last dimension is RGB.
        # If D was collapsed, we might need to sum or select.
        # The source says "Output dimensions are [batch, C, H, W, 3]".
        # This suggests the depth dimension is fully collapsed or the output is 3D image + RGB channel?
        # Actually, standard image is [B, C, H, W]. The source says [batch, C, H, W, 3].
        # This is likely [B, Channels, H, W, RGB_channels].
        # If C=1, then [B, 1, H, W, 3].
        # We assume the depth dimension is handled by the convolutions and the final output is per-pixel RGB.
        # If the tensor still has a depth dimension, it needs to be removed.
        # Given "global latent rendering... collapsing the depth dimension", we assume D=1 at the end or summed.
        # For simplicity, if D>1, we might need to squeeze or sum.
        # Let's assume the final conv outputs [B, 1, H, W, 3] and we squeeze the 1.
        if x.shape[4] == 3:
            x = x.squeeze(1) # [B, H, W, 3]
            x = x.permute(0, 3, 1, 2) # [B, 3, H, W]
        return x
```

**Parameters:**
*   $V$: Number of input views.
*   $H, W$: Height and width of input images.
*   $D$: Number of depth planes in the PSV.
*   $C$: Base channel count for the network.
*   Typical values are not explicitly given in the sources, but the method is evaluated on DTU, RealForward Facing, Spaces, and ILSH datasets [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Memory efficiency is prioritized by using in-place viewing operations. Care must be taken to avoid out-of-memory errors with large batch sizes or high-resolution PSVs [S1, unofficial].
*   **Boundaries:** The method relies on the PSV construction. If the target view is outside the frustum of input views, the PSV may be empty or invalid.
*   **Degenerate Input:** If input views have incorrect camera parameters, the PSV projection will be incorrect, leading to poor rendering [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources, but the method emphasizes memory efficiency through in-place operations [S1, unofficial].
*   **Measured Performance:** Evaluated on DTU, RealForward Facing, Spaces, and ILSH datasets under sparse and generalizable setups [S1, unofficial].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Renders all camera rays jointly, avoiding grainy artifacts common in single-ray methods like GPNR and LFNR [S1, unofficial]. Does not require explicit volumetric rendering or layered representations like MPI [S1, unofficial].
*   **Limitations:** Relies on the quality of the PSV construction. Performance may degrade if the scene geometry is complex and the depth sampling is insufficient [S1, unofficial].
*   **When to use:** Generalizable novel view synthesis where high-quality textures and geometries are required, and computational resources allow for 3D convolutions [S1, unofficial].
*   **When not to use:** Real-time applications with strict memory constraints, or scenes with very sparse input views where PSV construction is ambiguous [S1, unofficial].

## Background
ConvGLR was introduced in the paper "Global Latent Neural Rendering" [S1, unofficial]. It addresses the limitations of scene-specific methods and generalizable methods that treat target images as collections of independent pixels. The method builds on the understanding that Plane Sweep Volumes (PSVs) implicitly encode epipolar geometry, allowing for efficient convolutional operations across views, depth, and spatial dimensions [S1, unofficial]. It is used in the context of generalizable novel view synthesis, competing with methods like GPNR, LFNR, RegNeRF, GeoNeRF, and MPI [S1, unofficial].
