# Frustum Voxelization and Feature Aggregation

Also called: Frustum Voxelization

## Overview
Frustum Voxelization and Feature Aggregation preprocesses a 3D point cloud by mapping its features into a structured 3D volume within the camera frustum for multi-plane neural rendering [S1]. It organizes sparse point cloud data by grouping points into voxels and computing aggregation weights based on spatial proximity to the voxel center and depth [S1]. Unlike direct 2D projection methods that suffer from visibility verification issues and noise interference, this approach aggregates features within the frustum volume, allowing subsequent 3D convolutional networks to exploit neighboring pixel and depth information to handle projection errors caused by geometry noise [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D point cloud with associated features (e.g., RGB, viewpoint direction), camera parameters (intrinsics, extrinsics), and rendering bounds (minimum and maximum depth planes) [S1].
*   **Output:** A frustum volume of dimensions $P \times H \times W$, where each voxel contains aggregated point features [S1].

**Data Structures:**
The frustum volume is a 3D grid with dimensions $(P, H, W)$ [S1].
*   $P$: Number of depth planes (slices along the z-axis) [S1].
*   $H$: Height of the image resolution [S1].
*   $W$: Width of the image resolution [S1].
Each voxel $(p, h, w)$ stores aggregated point features. The source specifies a point feature dimension of 11, initialized as 0.5 (5 dimensions) + RGB (3 dimensions) + viewpoint direction (3 dimensions), though only the first 8 dimensions are updated during training [S1].

**Steps:**
1.  **Frustum Definition:** Define the camera frustum region bounded by the minimum and maximum depth planes of the projected point cloud [S1].
2.  **Voxelization:** Divide the frustum uniformly along the z-axis into $P$ slices. The spatial resolution of each slice corresponds to the image dimensions $H \times W$, creating $P \times H \times W$ frustum voxels [S1].
3.  **Point Projection:** Project each 3D point from the point cloud onto the image plane to determine its corresponding pixel coordinates $(h, w)$ and depth $z$ [G].
4.  **Distance Calculation:** For each point $i$ falling into a specific voxel $(p, h, w)$, calculate two distances:
    *   $D1(p,h,w)_i$: The Euclidean distance between the point's projection on the image plane and the center of the pixel $(h, w)$ in the parallel direction. $D1 \in (0, 1/\sqrt{2})$ [S1].
    *   $D2(p,h,w)_i$: The depth difference between the point and the minimum depth plane of the voxel it occupies. $D2 \in (0, l)$, where $l$ is the length of the frustum along the z-axis [S1].
5.  **Weight Computation:** Compute the blending weight $w(p,h,w)_i$ for point $i$ in voxel $(p, h, w)$ using the formula:
    $$w(p,h,w)_i = (1 - D1(p,h,w)_i)^a \times \left(\frac{1}{1 + D2(p,h,w)_i}\right)^b$$
    where $a$ and $b$ are parameters controlling the blending weights for the parallel and vertical (depth) directions, respectively [S1].
6.  **Feature Aggregation:** Aggregate the features of all points falling into voxel $(p, h, w)$ using the computed weights, typically by computing a weighted average [G].

**Parameters:**
*   $a$: Controls parallel direction blending. Typical value: $1$ [S1].
*   $b$: Controls vertical (depth) direction blending. Typical value: $1$ [S1].
*   $P$: Number of planes. Typical values: $32$ for ScanNet and Matterport 3D datasets [S1].
*   $H, W$: Image resolution. Typical values: $480 \times 640$ for ScanNet, $512 \times 640$ for Matterport 3D [S1].

**Pitfalls:**
*   If $b$ approaches infinity, the method degenerates to selecting the closest point via z-buffer (as in Aliev et al.), which is not robust against geometry errors and causes temporal jitters [S1].

**Pseudocode:**
```python
import math

def frustum_voxelization_and_aggregation(points, features, camera_intrinsics, camera_extrinsics, min_depth, max_depth, P, H, W, a=1, b=1):
    """
    Voxelize point cloud into frustum volume and aggregate features.
    Args:
        points: List of (x, y, z) tuples.
        features: List of feature vectors (length 11).
        camera_intrinsics: 3x3 matrix (list of lists).
        camera_extrinsics: 4x4 matrix (list of lists).
        min_depth: float, minimum depth of the frustum.
        max_depth: float, maximum depth of the frustum.
        P: int, number of depth planes.
        H: int, image height.
        W: int, image width.
        a: float, parallel blending parameter.
        b: float, vertical blending parameter.
    Returns:
        volume: 3D list [P][H][W][11] of aggregated features.
        weight_sum: 3D list [P][H][W] of floats.
    """
    # Initialize volume [P][H][W][11] and weight sum [P][H][W]
    volume = [[[ [0.0] * 11 for _ in range(W)] for _ in range(H)] for _ in range(P)]
    weight_sum = [[[0.0] for _ in range(W)] for _ in range(H)] # Fixed dimensionality
    # Correct 3D list initialization for weight_sum
    weight_sum = [[[0.0] for _ in range(W)] for _ in range(H)] # This is HxW. I need P.
    # Proper initialization:
    weight_sum = [[[0.0] for _ in range(W)] for _ in range(H)] # I will use a dict for clarity and correctness
    weight_sum = {}
    for p in range(P):
        for h in range(H):
            for w in range(W):
                weight_sum[(p, h, w)] = 0.0

    l = max_depth - min_depth

    for i in range(len(points)):
        x, y, z = points[i]
        feat = features[i]

        # Transform to camera coordinates
        p_h = [x, y, z, 1.0]
        p_cam = [0.0, 0.0, 0.0, 0.0]
        for r in range(4):
            for c in range(4):
                p_cam[r] += camera_extrinsics[r][c] * p_h[c]
        p_cam = p_cam[:3]

        # Project to 2D
        u = (camera_intrinsics[0][0] * p_cam[0] + camera_intrinsics[0][1] * p_cam[1] + camera_intrinsics[0][2] * p_cam[2]) / p_cam[2]
        v = (camera_intrinsics[1][0] * p_cam[0] + camera_intrinsics[1][1] * p_cam[1] + camera_intrinsics[1][2] * p_cam[2]) / p_cam[2]
        depth = p_cam[2]

        # Check bounds
        if depth < min_depth or depth > max_depth:
            continue
        h_idx = int(math.floor(v))
        w_idx = int(math.floor(u))
        if h_idx < 0 or h_idx >= H or w_idx < 0 or w_idx >= W:
            continue

        # Plane index
        p_idx = int(math.floor((depth - min_depth) / (l / P)))
        if p_idx < 0: p_idx = 0
        if p_idx >= P: p_idx = P - 1

        # D1: distance to pixel center
        pixel_center_u = w_idx + 0.5
        pixel_center_v = h_idx + 0.5
        D1 = math.sqrt((u - pixel_center_u)**2 + (v - pixel_center_v)**2)

        # D2: depth difference within voxel
        voxel_min_depth = min_depth + p_idx * (l / P)
        D2 = depth - voxel_min_depth

        # Weight
        weight = ((1.0 - D1)**a) * ((1.0 / (1.0 + D2))**b)

        # Aggregate
        for d in range(11):
            volume[p_idx][h_idx][w_idx][d] += feat[d] * weight
        weight_sum[(p_idx, h_idx, w_idx)] += weight

    # Normalize
    for p in range(P):
        for h in range(H):
            for w in range(W):
                ws = weight_sum[(p, h, w)]
                if ws > 0:
                    inv_ws = 1.0 / ws
                    for d in range(11):
                        volume[p][h][w][d] *= inv_ws

    return volume, weight_sum
```

## Subtopics

### [Multi-plane Neural Rendering](15529-multi-plane-neural-rendering.md)
Multi-plane Neural Rendering is a deep learning pipeline that renders images from raw 3D point clouds by projecting features into a layered 3D volume within the camera frustum, rather than directly onto a 2D image plane. Unlike previous methods that project features directly to 2D and suffer from visibility verification problems and noise interference, this method maintains all features from points in the field-of-view, allowing a 3D CNN to automatically learn visibility and handle occlusions. It produces more stable renderings, particularly near object boundaries, and is robust to noisy and relatively sparse point clouds.

### Frustum Voxel Filtering
A module deployed to comprehensively exploit geometrical information in the fused 3D data volume $U_{t0}$ for coarse disparity estimation [S2]. Input: Fused 3D data volume $U_{t0}$. Output: Coarse disparity estimation $D_{t0} \in \mathbb{R}^{H_0 \times W_0}$ [S2].

## Operating characteristics
*   **Measured Performance:** Trained on a GeForce 1080 Ti, taking approximately 41.5 hours per scene for 21 epochs [S1].
*   **Strengths:** Robust to noise and relatively sparse point clouds; effectively exploits information from neighboring pixels and depth to handle projection errors caused by geometry noise [S1].
*   **Limitations:** Sensitive to parameter $b$; if $b \to \infty$, it degenerates to z-buffering, causing temporal jitters [S1].

## Background
The method was introduced in "Neural Point Cloud Rendering via Multi-Plane Projection" (CVPR 2020) [S1]. It adapts multi-plane rendering to handle raw point clouds by voxelizing the camera frustum and aggregating features, addressing the limitations of direct 2D projection methods which struggle with visibility verification and noise interference [S1].
