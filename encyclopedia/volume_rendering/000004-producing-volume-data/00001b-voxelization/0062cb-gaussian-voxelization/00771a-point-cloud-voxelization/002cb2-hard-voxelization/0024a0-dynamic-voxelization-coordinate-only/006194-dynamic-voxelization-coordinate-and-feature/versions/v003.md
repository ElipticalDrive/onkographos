# Dynamic Voxelization (Coordinate and Feature)

Also called: Dynamic Voxelization with Scatter Reduction

## Overview
Dynamic Voxelization (Coordinate and Feature) converts point clouds to variable-size voxel grids, decomposed into coordinate calculation, indexing, and scatter-reduction stages [S1, unofficial]. It differs from [Dynamic Voxelization (Coordinate Only)](3347-dynamic-voxelization-coordinate-only.md) by performing scatter-reduction on features during the voxelization process, rather than returning only coordinate mappings [G].

## How it works
The method processes a point cloud through three sequential stages [S1, unofficial].

### Inputs and Outputs
- **Input**: Point cloud tensor $P \in \mathbb{R}^{N \times D}$, where $N$ is the number of points and $D$ is the feature dimension [G].
- **Input**: Voxelization parameters: voxel size $v \in \mathbb{R}^3$ and point cloud range $R \in \mathbb{R}^6$ (min/max $x, y, z$) [G].
- **Output**: Voxel features tensor $V \in \mathbb{R}^{K \times F}$, where $K$ is the number of non-empty voxels and $F$ is the feature dimension [G].
- **Output**: Voxel coordinates tensor $C \in \mathbb{R}^{K \times 3}$, representing the grid indices of the non-empty voxels [G].

### Data Structures
- **Point Cloud**: A flat tensor of shape $(N, D)$ [G].
- **Voxel Coordinates**: A tensor of shape $(K, 3)$ storing integer grid indices $(i, j, k)$ for each non-empty voxel [G].
- **Routing Index**: A 1D tensor of shape $(N,)$ mapping each point to its target voxel index in the output feature tensor [G].

### Steps
1. **Calculate Target Coordinates**: For each point $p_n = (x_n, y_n, z_n, \dots)$, compute its voxel grid coordinates $(i_n, j_n, k_n)$ using the voxel size $v$ and range $R$:
   $$
   i_n = \left\lfloor \frac{x_n - R_{\min,x}}{v_x} \right\rfloor, \quad
   j_n = \left\lfloor \frac{y_n - R_{\min,y}}{v_y} \right\rfloor, \quad
   k_n = \left\lfloor \frac{z_n - R_{\min,z}}{v_z} \right\rfloor
   $$
   Clamp coordinates to valid range $[0, K_{\max}-1]$ where $K_{\max}$ is derived from the range and voxel size [G].
2. **Indexing**: Calculate the non-empty coors set and routing information using `torch.unique` [S1, unofficial]. This returns the unique voxel coordinates and an inverse index mapping each point to its target voxel row [G].
3. **Scatter-Reduction**: Dump pointwise features to voxelized features and perform reduction using `scatter_add_` or equivalent [S1, unofficial].

### Pseudocode
```python
import torch

def dynamic_voxelization_and_feature(
    points: torch.Tensor,
    voxel_size: torch.Tensor,
    point_cloud_range: torch.Tensor,
    reduce: str = "sum"
) -> tuple[torch.Tensor, torch.Tensor]:
    """
    points: (N, D) tensor, D >= 3
    voxel_size: (3,) tensor [vx, vy, vz]
    point_cloud_range: (6,) tensor [x_min, y_min, z_min, x_max, y_max, z_max]
    reduce: "sum" or "mean"
    Returns:
        coors: (K, 3) tensor of unique voxel coordinates
        features: (K, D) tensor of aggregated voxel features
    """
    # Step 1: Calculate target coordinates
    shifted = points[:, :3] - point_cloud_range[:3]
    coors_float = shifted / voxel_size
    coors_int = torch.floor(coors_float).int()
    max_coors = ((point_cloud_range[3:] - point_cloud_range[:3]) / voxel_size).int()
    coors_int = torch.clamp(coors_int, 0, max_coors - 1)
    
    # Step 2: Indexing
    coors_unique, inverse_indices = torch.unique(
        coors_int, dim=0, sorted=True, return_inverse=True
    )
    K = coors_unique.shape[0]
    N = points.shape[0]
    D = points.shape[1]
    
    # Step 3: Scatter-Reduction (sum)
    features = torch.zeros((K, D), dtype=points.dtype, device=points.device)
    features.scatter_add_(0, inverse_indices.unsqueeze(1).expand(-1, D), points)
    
    if reduce == "mean":
        ones = torch.ones((N,), dtype=points.dtype, device=points.device)
        counts = torch.zeros((K,), dtype=points.dtype, device=points.device)
        counts.scatter_add_(0, inverse_indices, ones)
        counts = torch.clamp(counts, min=1)
        features = features / counts.unsqueeze(1)
        
    return coors_unique, features
```

### Edge Cases and Pitfalls
- **Extreme Density**: Can be unstable when points are extremely dense, affecting voxelization efficiency [S1, unofficial].
- **Redundant Indexing**: Repeated scatter-reduces for the same point cloud require redundant indexing if not cached [S1, unofficial].
- **Precision**: Floating-point division in coordinate calculation may introduce small errors; clamping is essential to prevent out-of-bounds indices [G].

## Subtopics

### Dynamic Voxelization (Coordinate Only)
Computes only voxel coordinates without feature aggregation [G]. It sets itself apart by returning only coordinate mappings and skipping scatter-reduction [G]. Use when `max_points=-1` or when feature processing is handled separately [G]. [Link](3347-dynamic-voxelization-coordinate-only.md)

### Hard Voxelization
Assigns points to a fixed grid with max points per voxel [G]. It sets itself apart by producing a deterministic output size and a fixed grid structure [G]. Use when deterministic output size is required or for hardware acceleration [G]. [Link](3346-hard-voxelization.md)

## Operating characteristics
- **Time Complexity**: Indexing (`torch.unique`) is the most computationally expensive part; scatter-reduction itself is fast [S1, unofficial].
- **Memory Complexity**: Not given in the sources [S1, unofficial].
- **Performance**: The indexing step dominates runtime [S1, unofficial].
- **Strengths**: Handles variable-size voxel grids efficiently [S1, unofficial].
- **Limitations**: Can be unstable when points are extremely dense [S1, unofficial].

- **When Not to Use**: Not given in the sources [S1, unofficial].

## Background
Dynamic Voxelization was discussed in the context of MMDetection3D implementation improvements, where contributors suggested dividing the dynamic scatter op into indexing and scatter-reduction parts to address performance bottlenecks [S1, unofficial]. It was developed to provide a consistent implementation for 3D detection pipelines [S1, unofficial].
