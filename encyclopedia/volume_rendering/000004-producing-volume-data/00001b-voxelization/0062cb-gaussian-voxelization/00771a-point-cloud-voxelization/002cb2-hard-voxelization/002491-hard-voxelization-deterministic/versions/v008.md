# Hard Voxelization (Deterministic)

Also called: Point Cloud Voxelization via Histogramming, Voxel Grid Downsampling, Voxelization of unstructured 3D data, voxel aggregation, voxelize

## Overview
Hard Voxelization (Deterministic) converts an unstructured 3D point cloud into a fixed-size, regular 3D voxel grid by binning points based on spatial coordinates and aggregating their attributes [S1, S2, S4, unofficial]. It solves the problem of downsampling and structuring sparse point data for downstream processing, such as neural network input or volume rendering, by outputting a single representative point (typically the centroid) per occupied voxel [S1, S4, unofficial]. It is distinguished from its sibling [Fast Deterministic GPU Voxelization (Sort-Scatter)](3806-fast-deterministic-gpu-voxelization-sort-scatter.md) by its reliance on explicit sorting or unique-coordinate identification to guarantee bit-identical, reproducible output order, whereas the GPU variant uses a parallel sort-scatter pipeline for speed [S1, unofficial]. It differs from [Grid Pooling (Max Pooling over Points)](4327-grid-pooling-max-pooling-over-points.md) by computing centroids (averages) rather than max-pooling features [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A point cloud dataset containing $N$ points. Each point has 3D coordinates $(x, y, z)$ and optional attributes (features, labels, intensity).
*   **Parameters:**
    *   `voxel_size`: Scalar or vector $[v_x, v_y, v_z]$ defining the physical size of a voxel [S2, S3, unofficial]. Typical scalar value: 0.7 [S4, unofficial] or 0.5 [S5, unofficial].
    *   `coors_range`: Bounding box $[x_{min}, y_{min}, z_{min}, x_{max}, y_{max}, z_{max}]$ [S3, unofficial]. If not provided, it is computed from the data [S1, S4, unofficial].
    *   `max_points`: Maximum number of points to store per voxel. If -1, dynamic allocation is used, but hard voxelization typically enforces a limit [S3, unofficial].
    *   `max_voxels`: Maximum number of voxels to create. Points falling into voxels beyond this limit are dropped. Typical value: 20,000 [S3, unofficial].
    *   `ignore_label`: Integer label value to ignore during aggregation (default -1) [S2, unofficial].
*   **Outputs:**
    *   `voxels`: Tensor of aggregated point features grouped by voxel [S3, unofficial].
    *   `coors`: Tensor of voxel coordinates (indices) [S3, unofficial].
    *   `num_points_per_voxel`: Count of points per voxel [S3, unofficial].
    *   Alternatively, a 4D array containing coordinate grids and average attribute values [S4, unofficial].

**Data Structures:**
*   **Point Cloud:** Array of shape $[N, 3]$ for coordinates, and optionally $[N, F]$ for features [S2, S4, unofficial].
*   **Voxel Grid:** A 3D array or hash map mapping voxel indices $(i, j, k)$ to accumulated sums and counts [S1, S4, unofficial].
*   **Mapping:** An array mapping original point indices to unique voxel indices [S2, S3, unofficial].

**Steps:**

1.  **Validation and Masking:**
    Identify valid points. A point is valid if its coordinates and features are finite. Create a boolean mask `finite` where `finite[i]` is true if point $i$ is valid [S2, unofficial]. Points failing this mask are excluded from aggregation but may retain their original index mapping as -1 [S2, unofficial].

2.  **Bounding Box Computation:**
    Determine the spatial extent of the valid points.
    $$ x_{min} = \min_{i \in \text{finite}} x_i, \quad x_{max} = \max_{i \in \text{finite}} x_i $$
    (Similarly for $y$ and $z$) [S1, S4, unofficial].
    If a fixed `coors_range` is provided, use it; otherwise, use the computed min/max [S1, S3, unofficial].

3.  **Grid Dimension Calculation:**
    Calculate the number of voxels along each axis. Sources disagree on the rounding method:
    *   Method A (Ceiling): Ensures full coverage of the range.
        $$ \text{dim}_x = \max(1, \lceil \frac{x_{max} - x_{min}}{v_x} \rceil) $$ [S1, unofficial].
    *   Method B (Round):
        $$ \text{dim}_x = \text{round}\left(\frac{x_{max} - x_{min}}{v_x}\right) $$ [S3, unofficial].
    Ensure dimensions are at least 1 [S1, unofficial].

4.  **Coordinate Quantization:**
    Map each valid point to a discrete voxel index $(i, j, k)$.
    $$ i = \left\lfloor \frac{x - x_{min}}{v_x} \right\rfloor, \quad j = \left\lfloor \frac{y - y_{min}}{v_y} \right\rfloor, \quad k = \left\lfloor \frac{z - z_{min}}{v_z} \right\rfloor $$ [S1, S3, S4, unofficial].
    Points outside the range $R$ map to invalid indices (e.g., -1) and are filtered out [S3, unofficial].
    *Pitfall:* Quantized coordinates must fit in `int64`. If any value is $< -2^{63}$ or $\ge 2^{63}$, raise an error [S2, unofficial].

5.  **Unique Voxel Identification (Determinism Step):**
    To ensure deterministic output order, identify unique voxel coordinates and map original point indices to these unique voxels.
    *   Collect all valid voxel coordinates $(i, j, k)$.
    *   Sort them lexicographically or use a unique-finding algorithm (e.g., `np.unique` or `at::unique_dim`) to find the set of occupied voxels and an `inverse` array mapping each point to its unique voxel index [S2, S3, unofficial].
    *   Handle invalid coordinates (e.g., -1, -1, -1) by removing them from the unique list and adjusting the `inverse` mapping indices accordingly [S3, unofficial].

6.  **Attribute Aggregation:**
    Aggregate point attributes into the identified voxels.
    *   **Centroid Calculation:** Compute the sum of attributes and the count for each voxel.
        $$ \text{sum}_v = \sum_{p \in \text{voxel } v} \text{attr}_p, \quad \text{count}_v = \sum_{p \in \text{voxel } v} 1 $$ [S1, S4, unofficial].
    *   **Mean Calculation:**
        $$ \text{mean}_v = \frac{\text{sum}_v}{\text{count}_v} $$ [S4, unofficial].
    *   **Overflow Prevention:** To prevent overflow in naive summing or erasure of subnormal values in divide-before-sum, use a scaled-mean reduction [S2, unofficial].
        1.  Compute `maxima` for each feature across all points: `maxima[f] = max(|attr[f]|)`.
        2.  Normalize features: `norm_attr = attr / maxima`.
        3.  Accumulate normalized features: `norm_sum += norm_attr`.
        4.  Rescale: `mean_attr = (norm_sum / count) * maxima` [S2, unofficial].
    *   **Label Aggregation:** For labels, find the most frequent non-ignored label. On ties, choose the smallest numeric label using `np.lexsort` on `(-frequencies, pairs[:, 1])` [S2, unofficial].

7.  **Output Construction:**
    *   Construct the `voxels` tensor with shape $[M, \text{max\_points}, F]$ or $[M, F]$ depending on implementation, where $M$ is the number of unique voxels [S3, unofficial].
    *   Construct the `coors` tensor with shape $[M, 3]$ containing the voxel indices [S3, unofficial].
    *   Construct `num_points_per_voxel` with shape $[M]$ [S3, unofficial].
    *   Handle empty voxels (if any remain in a dense grid representation) by setting their average value to NaN [S4, unofficial].

**Pseudocode (NumPy-based Deterministic Implementation):**

```python
import numpy as np

def hard_voxelization_deterministic(points, voxel_size, coors_range=None, max_voxels=20000, max_points=100):
    """
    points: np.ndarray of shape (N, 3) or (N, 3+F)
    voxel_size: float or list [vx, vy, vz]
    coors_range: list [x_min, y_min, z_min, x_max, y_max, z_max]
    max_voxels: int
    max_points: int
    """
    N = points.shape[0]
    
    # 1. Validation
    # Assume points has shape (N, 3) for coords. If features exist, handle separately.
    coords = points[:, :3]
    
    # Check for finite coordinates
    finite_mask = np.isfinite(coords).all(axis=1)
    if not finite_mask.any():
        return np.empty((0, 3)), np.empty((0, 3)), np.empty((0,))
        
    valid_coords = coords[finite_mask]
    valid_indices = np.where(finite_mask)[0]
    
    # 2. Bounding Box
    if coors_range is None:
        x_min, y_min, z_min = valid_coords.min(axis=0)
        x_max, y_max, z_max = valid_coords.max(axis=0)
    else:
        x_min, y_min, z_min, x_max, y_max, z_max = coors_range
        
    # 3. Grid Dimensions (Using Ceiling as per S1, but S3 uses Round. 
    # Deterministic implementations often prefer explicit bounds. 
    # We use Ceiling to ensure coverage, clamped to max_voxels logic later if needed, 
    # but here we calculate grid size for indexing.)
    # Note: S3 calculates grid dims but uses a hash map or sparse structure in GPU. 
    # For dense numpy, we need dims.
    vx, vy, vz = voxel_size if isinstance(voxel_size, (list, tuple)) else [voxel_size]*3
    
    dim_x = int(np.ceil((x_max - x_min) / vx))
    dim_y = int(np.ceil((y_max - y_min) / vy))
    dim_z = int(np.ceil((z_max - z_min) / vz))
    
    dim_x = max(1, dim_x)
    dim_y = max(1, dim_y)
    dim_z = max(1, dim_z)
    
    # 4. Quantization
    # i = floor((x - x_min) / vx)
    xi = np.floor((valid_coords[:, 0] - x_min) / vx).astype(np.int64)
    yi = np.floor((valid_coords[:, 1] - y_min) / vy).astype(np.int64)
    zi = np.floor((valid_coords[:, 2] - z_min) / vz).astype(np.int64)
    
    # 5. Filter Out-of-Bounds
    # Points outside [0, dim-1] are invalid
    valid_x = (xi >= 0) & (xi < dim_x)
    valid_y = (yi >= 0) & (yi < dim_y)
    valid_z = (zi >= 0) & (zi < dim_z)
    valid_voxel_mask = valid_x & valid_y & valid_z
    
    final_coords = valid_coords[valid_voxel_mask]
    final_xi = xi[valid_voxel_mask]
    final_yi = yi[valid_voxel_mask]
    final_zi = zi[valid_voxel_mask]
    final_orig_indices = valid_indices[valid_voxel_mask]
    
    if final_coords.shape[0] == 0:
        return np.empty((0, 3)), np.empty((0, 3)), np.empty((0,))

    # 6. Unique Voxel Identification (Deterministic Sorting)
    # Combine coordinates into a single array for unique finding
    voxel_indices = np.stack([final_xi, final_yi, final_zi], axis=1)
    
    # Sort voxel indices to ensure deterministic order
    # np.unique returns sorted unique values
    unique_voxels, inverse_indices, counts = np.unique(voxel_indices, axis=0, return_inverse=True, return_counts=True)
    
    # unique_voxels is sorted lexicographically
    M = unique_voxels.shape[0]
    
    # Limit to max_voxels
    if M > max_voxels:
        # Deterministic drop: keep first max_voxels in sorted order
        keep_mask = np.zeros(M, dtype=bool)
        keep_mask[:max_voxels] = True
        unique_voxels = unique_voxels[keep_mask]
        counts = counts[keep_mask]
        # Adjust inverse_indices: map dropped voxels to -1 or handle carefully
        # For simplicity in this dense example, we just drop points in dropped voxels
        # Re-map inverse indices to the kept unique voxels
        # This requires a mapping from old unique index to new unique index
        # Since unique_voxels is sorted, we can use searchsorted or a dict
        # However, np.unique with return_inverse gives indices into the *original* unique set.
        # We need to map those to the new set.
        
        # Create a map from old index to new index
        # Since we kept the first max_voxels, index i < max_voxels maps to i.
        # Indices >= max_voxels are dropped.
        new_inverse = np.where(inverse_indices < max_voxels, inverse_indices, -1)
        
        # Filter points that belong to dropped voxels
        valid_point_mask = new_inverse != -1
        final_coords = final_coords[valid_point_mask]
        new_inverse = new_inverse[valid_point_mask]
        final_orig_indices = final_orig_indices[valid_point_mask]
        
        # Update counts for the kept voxels
        # Recount based on the filtered inverse_indices
        counts = np.bincount(new_inverse, minlength=max_voxels)[:max_voxels]
        M = unique_voxels.shape[0] # Should be <= max_voxels

    # 7. Aggregation
    # Calculate Centroid
    # Sum of coordinates
    sum_coords = np.zeros((M, 3))
    for k in range(3):
        # Scatter add
        np.add.at(sum_coords, new_inverse, final_coords[:, k])
        
    mean_coords = sum_coords / counts[:, None]
    
    # 8. Output Construction
    # coors: the voxel indices
    coors = unique_voxels
    
    # num_points_per_voxel
    num_points_per_voxel = counts
    
    # voxels: In this simple centroid example, voxels are the mean coordinates
    # If features were present, they would be aggregated similarly
    voxels = mean_coords
    
    return voxels, coors, num_points_per_voxel
```

## Subtopics

### [Fast Deterministic GPU Voxelization (Sort-Scatter)](3806-fast-deterministic-gpu-voxelization-sort-scatter.md)
A PyTorch-based method for converting 3D point clouds into a fixed-size voxel grid that achieves bit-identical output to a reference C++/CUDA implementation while providing a ~100× speedup. It replaces an $O(N^2)$ sequential CUDA kernel with a parallel pipeline of filtering, coordinate computation, stable sorting, and scattering. Unlike the standard `deterministic=False` path which relies on non-reproducible atomic operations, this method guarantees reproducibility by preserving original point order within voxels via stable sorting.

### [Grid Pooling (Max Pooling over Points)](4327-grid-pooling-max-pooling-over-points.md)
Grid Pooling aggregates point cloud features into a fixed-size 3D voxel grid by performing max-pooling within each grid cell. It maps a set of $N$ points with $C$-dimensional features to a $W \times H \times D$ grid where each cell stores the maximum feature value among points falling into that cell. It differs from its sibling [Hard Voxelization (Deterministic)](3321-hard-voxelization-deterministic.md) by explicitly tracking the index of the point that achieved the maximum value to enable differentiable backpropagation.

### [Grid-based Scene Cropping with KNN Precomputation](4462-grid-based-scene-cropping-with-knn-precomputation.md)
This method generates cropped point cloud datasets by dividing a normalized 3D scene into a structured grid, applying padding, and precomputing K-nearest neighbor (KNN) relationships for both input points and grid voxels to facilitate local feature grouping. It solves the problem of preparing fixed-size, spatially coherent data structures with relative coordinate offsets for deep learning models. It differs from its siblings, [Fast Deterministic GPU Voxelization (Sort-Scatter)](3806-fast-deterministic-gpu-voxelization-sort-scatter.md) and [Grid Pooling (Max Pooling over Points)](4327-grid-pooling-max-pooling-over-points.md), by explicitly precomputing KNN indices and relative coordinates for both points and voxels within a cropped region.

### [Nearest Neighbour Interpolation for Voxelization](6290-nearest-neighbour-interpolation-for-voxelization.md)
This method assigns attribute values (e.g., intensity, color) to voxel centers by identifying the single closest point in the original point cloud to each voxel center, rather than aggregating all points within the voxel volume. It is used when a specific point's value is preferred over an average, distinguishing it from histogramming methods that sum or average all points falling within a voxel.

### [Voxel Hashing and Mean Aggregation](11234-voxel-hashing-and-mean-aggregation.md)
This method converts a set of 3D points into a sparse voxel grid by mapping points to unique voxel identifiers via hashing and aggregating features using mean scattering. It differs from fixed-grid approaches by avoiding pre-allocated dense memory for empty space, instead dynamically allocating only for occupied voxels. It is chosen when memory efficiency for sparse point clouds is critical and mean aggregation is the desired feature reduction strategy.

### [Uniform Point Cloud Voxelization and Simplification](12099-uniform-point-cloud-voxelization-and-simplification.md)
A preprocessing technique to simplify large point clouds by voxelizing them and randomly sampling points within voxels to a target density, followed by re-projecting the simplified points onto multi-planes for aggregation weight calculation. It sets itself apart from sibling hard voxelization methods by introducing a probabilistic downsampling step based on local point density, rather than deterministic retention or max-pooling, and immediately projects the result into a multi-plane representation for subsequent neural rendering.

### [Hard Voxelization with Capacity Limits](12214-hard-voxelization-with-capacity-limits.md)
This method inserts 3D points into a sparse voxel grid structure while enforcing a strict maximum capacity of points per voxel. It differs from its parent [Hard Voxelization (Deterministic)](3321-hard-voxelization-deterministic.md) by explicitly managing chunk readiness for disk I/O and tracking insertion/rejection statistics, making it suitable for streaming or sliding-window scenarios where data availability is asynchronous.

### [Vectorized Voxelization](12528-vectorized-voxelization.md)
Vectorized Voxelization is a deterministic, CPU-based algorithm that converts a sparse 3D point cloud into a dense voxel grid by binning points into discrete cells and averaging their attributes (such as color). It solves the problem of efficiently aggregating unstructured point data into a regular grid structure suitable for downstream volume rendering or neural network processing, specifically optimizing for vectorized operations using NumPy. It differs from GPU-based sort-scatter methods by relying on CPU-side sorting and cumulative sums, and from simple hard voxelization by explicitly handling attribute averaging and density filtering in a single pass.

### [Point Cloud Voxelization with Adjacency Cleanup](13267-point-cloud-voxelization-with-adjacency-cleanup.md)
This method converts a set of 3D points into a fixed-size voxel grid by assigning points to discrete voxels and subsequently removing isolated, non-connected voxels to clean up noise. It extends [Hard Voxelization (Deterministic)](3321-hard-voxelization-deterministic.md) by adding a topological cleanup phase that eliminates single-voxel artifacts, distinguishing it from sibling methods like [Grid Pooling (Max Pooling over Points)](4327-grid-pooling-max-pooling-over-points.md) which aggregate values rather than filtering topology.

### Hard Voxelization (Non-Deterministic)
A faster, non-reproducible variant of hard voxelization that uses atomic operations or parallel reductions to assign points to voxels, avoiding the sorting/unique step of the deterministic version [S3, unofficial]. It differs from the deterministic version by using 'nondisterministic_' prefixed kernels for assignment, which are faster but not reproducible. The unique_dim step is still used to identify voxel coordinates, but the assignment logic is parallelized differently [S3, unofficial].

### Point Cloud Voxelization via Discretization and Accumulation
A method to convert a 3D point cloud into a binary voxel grid (occupancy grid) by discretizing point coordinates into a regular grid and marking voxels as occupied if they contain at least one point [S5, unofficial]. It initializes `voxelsize` (e.g., 0.5), extracts dimensions, defines bin edges, replaces coordinates with bin indices using `discretize`, and creates the binary grid `V` by thresholding the result of `accumarray` [S5, unofficial].

### Hybrid Coarse-to-Fine Update Strategy
A point cloud refinement algorithm that first coarsens a point cloud by voxel averaging, then removes outliers based on neighbor distance standard deviation, and finally refines positions by averaging neighbors [S6]. It partitions the 3D space into an $N \times N \times N$ voxel grid and computes the average position of points within each voxel [S6].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ or $O(N)$ depending on the unique-finding mechanism. Sorting-based approaches (like `np.unique`) are $O(N \log N)$ [S2, unofficial]. GPU implementations using sort-scatter can achieve $O(N \log N)$ with high parallelism [S1, unofficial].
*   **Memory Complexity:** $O(M \cdot F)$ for the output grid, where $M$ is the number of occupied voxels and $F$ is the feature dimension. The input is $O(N \cdot F)$. Sparse implementations (Voxel Hashing) reduce memory usage for empty space [S1, unofficial].
*   **Measured Performance:** A parallel CUDA implementation runs in ~0.04s per frame on CPU-equivalent logic but offloads to GPU for speed [S3, unofficial]. The GPU sort-scatter variant provides a ~100× speedup over sequential CPU implementations [S1, unofficial].
*   **Strengths:** Deterministic output order; handles unstructured data; reduces density significantly; suitable for neural network inputs.
*   **Limitations:** Fixed grid size may lead to wasted memory if sparse; boundary handling requires care; non-deterministic variants are faster but not reproducible [S3, unofficial].
*   **When to use:** When reproducible downsampling is required for debugging or training stability; when converting point clouds to regular grids for CNNs.
*   **When not to use:** When memory efficiency for extremely sparse data is critical (use Voxel Hashing); when max-pooling features is preferred (use Grid Pooling).

## Background
Hard Voxelization is a fundamental technique in 3D computer vision and point cloud processing. It is widely used in autonomous driving datasets (e.g., nuScenes, KITTI) for preprocessing LiDAR data [S1, S3, unofficial]. The method is implemented in various libraries, including PointCloud Workflows (PCW) and PointCloud Core [S2, unofficial], and is a core component of many 3D object detection networks (e.g., SECOND, PV-RCNN) which use voxelization to convert sparse LiDAR points into dense voxel grids for 3D CNNs [S1, S3, unofficial]. The deterministic variant was developed to address the non-reproducibility issues of atomic-based GPU implementations, ensuring consistent results across different hardware and software environments [S3, unofficial].
