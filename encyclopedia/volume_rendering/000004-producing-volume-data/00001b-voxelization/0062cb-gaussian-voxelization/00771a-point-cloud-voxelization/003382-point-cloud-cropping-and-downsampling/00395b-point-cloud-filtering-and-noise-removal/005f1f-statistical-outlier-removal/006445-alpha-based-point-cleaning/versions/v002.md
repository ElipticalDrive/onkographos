# Alpha-based Point Cleaning

Also called: Alpha Threshold Cleaning, Point Cleaning

## Overview
Alpha-based Point Cleaning is a procedure to remove outlier points from a point cloud based on a threshold applied to their learned opacity (alpha) values [S1]. It solves the problem of noisy initial reconstructions (e.g., from COLMAP) or spurious points generated during training (e.g., from spawning mechanisms) by explicitly identifying points with low confidence [S1]. It is a child of Statistical Outlier Removal, specifically utilizing the alpha parameter rather than statistical distance [Parent](17819-statistical-outlier-removal.md).

## How it works
**Inputs and Outputs:**
- Input: A point cloud $P$ where each point $p_i$ has a position, color, and an opacity value $\alpha_i$ (confidence) [S1].
- Output: A filtered subset $P' \subset P$ containing only points with $\alpha_i \ge T$ [S1].

**Data Structures:**
- The point cloud is stored as a list or array of structures. Each element contains:
  - `position`: 3D vector $(x, y, z)$.
  - `color`: 3D vector $(r, g, b)$.
  - `alpha`: Scalar float in $[0, 1]$, representing the point's opacity or confidence [G].
- Exact sizes and bit packing are Not given in the sources.

**Parameters:**
- $T$: The alpha threshold. The default value used in the source is $0.3$ [S1].
- $E_{clean}$: The frequency of cleaning steps during training. The source recommends removing points every $50$ epochs for faster training [S1].

**Steps:**
1. During neural rendering optimization, the opacity $\alpha_i$ of each point is adapted [S1].
2. At intervals of $E_{clean}$ epochs, iterate through all points $p_i$ in the active cloud [S1].
3. For each point, check if $\alpha_i < T$ [S1].
4. Mark points satisfying the condition as outliers [S1].
5. Remove all marked outliers from the active point cloud [S1].
6. Repeat steps 2–5 throughout training; the final rendering uses only opaque points [S1].

**Pseudocode:**
```python
def alpha_based_point_cleaning(points, threshold=0.3, current_epoch=0, clean_interval=50):
    if current_epoch % clean_interval != 0:
        return points
    cleaned = []
    for p in points:
        if p.alpha >= threshold:
            cleaned.append(p)
    return cleaned
```

**Edge Cases and Pitfalls:**
- On the Opera scene, COLMAP places points originating from water incorrectly on land; the cleaning strategy provides great cleanup in these water areas [S1].
- On the Playground scene, adding one million additional random points results in a final point cloud with almost no visible outliers after cleaning [S1].
- A threshold of $0.3$ works well across tested scenes, removing most outliers while leaving room for variance during training [S1].

## Subtopics

### Point Cleaning Confidence Threshold
This variant explicitly defines the threshold $T$ as a configurable parameter for controlling the trade-off between point cloud size and rendering quality [S1]. It sets apart from the general method by providing empirical data on how varying $T$ affects metrics like LPIPS and PSNR [S1]. It is chosen when one needs to aggressively reduce point cloud size or fine-tune the balance between detail and noise [S1].
- **Definition**: In every cleaning step, points with confidence below a threshold $T$ are removed [S1].
- **Parameter**: $T$ is the confidence threshold. The default used in experiments is $0.3$, which causes point clouds to be similarly sized as the initial COLMAP reconstruction. Thresholds up to $0.9$ still provide reasonable results and reduce point cloud size significantly [S1].
- **Performance Data (Garden Scene, 7.8M initial points)**:
  - $T=0.30$: 7.3M points, LPIPS 0.178, PSNR 23.70 [S1].
  - $T=0.90$: 2.6M points, LPIPS 0.200, PSNR 23.44 [S1].
  - $T=0.99$: 0.1M points, LPIPS 0.446, PSNR 19.08 [S1].
- **Link**: [Alpha-based Point Cleaning](17820-alpha-based-point-cleaning.md)

## Operating characteristics
- **Time Complexity**: $O(N)$ per cleaning step, where $N$ is the number of points. Cleaning is performed every $50$ epochs, accelerating subsequent training iterations [S1].
- **Memory Complexity**: $O(N)$ to store the point cloud. Cleaning reduces $N$, significantly reducing point cloud size [S1].
- **Measured Performance**: On the Garden scene, cleaning with $T=0.3$ reduced points from 7.8M to 7.3M with negligible impact on PSNR (23.70) and LPIPS (0.178) [S1]. On the Playground scene, adding 1 million random outliers resulted in a final cloud with almost no visible outliers after cleaning [S1]. On the Opera scene, it effectively cleaned up water-area artifacts from COLMAP [S1].
- **Strengths**: Explicitly leverages neural optimization to distinguish geometry from noise; effective against environment sphere artifacts and spawning outliers [S1].
- **Limitations**: Requires the optimization process to have converged sufficiently for alpha values to be meaningful; aggressive thresholds ($T > 0.9$) can degrade rendering quality significantly (e.g., PSNR drop to 19.08 at $T=0.99$) [S1].

## Background
Alpha-based Point Cleaning was introduced in the VET (Visual Error Tomography) paper by Linus Franke et al. [S1]. It is part of a pipeline that combines neural rendering with point cloud completion [S1]. The method builds on the observation that outlier points receive low or zero opacity during the optimization of point-based neural rendering [S1].
