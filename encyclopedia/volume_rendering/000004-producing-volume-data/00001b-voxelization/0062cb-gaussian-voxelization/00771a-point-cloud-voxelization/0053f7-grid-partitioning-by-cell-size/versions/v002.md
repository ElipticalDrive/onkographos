# Grid Partitioning by Cell Size


## Overview
Grid Partitioning by Cell Size converts a point cloud into a regular 3D voxel grid by partitioning the spatial extent defined by the cloud's bounding box or a user-specified origin into uniform cubic cells [S1, unofficial]. It solves the problem of discretizing continuous point data into a structured volume representation for downstream rendering or analysis [G]. It differs from [Octree Construction for Point Clouds](1070-octree-construction-for-point-clouds.md) by using a fixed-resolution regular grid rather than an adaptive hierarchical structure, and from [Point Resampling with Neighbor Masking](2710-point-resampling-with-neighbor-masking.md) by not explicitly handling neighbor interactions during the initial partitioning step [G].

## Shared principles
All variants in this family share the core mechanism of mapping 3D coordinates $(x, y, z)$ to integer voxel indices $(v_x, v_y, v_z)$ using a fixed spacing $s$ (cell length) [S1, unofficial]. The mapping is generally defined as:
$$ v_i = \lfloor (p_i - o_i) / s \rfloor $$
where $p_i$ is the point coordinate, $o_i$ is the grid origin, and $s$ is the cell size along axis $i$ [S1, unofficial]. The resulting indices are clamped or checked against the grid dimensions $D_x, D_y, D_z$ [S1, unofficial]. The output is typically a binary mask or a data array associated with the grid geometry [S1, unofficial].

```python
import math

def map_points_to_voxels(points, origin, spacing, dimensions):
    """
    Map 3D points to voxel indices using fixed cell spacing.
    Args:
        points: List of 3D coordinates (x, y, z).
        origin: Tuple (ox, oy, oz) of grid origin.
        spacing: Float cell size s.
        dimensions: Tuple (Dx, Dy, Dz) of grid dimensions.
    Returns:
        mask: 3D boolean array of shape (Dx, Dy, Dz).
    """
    if spacing <= 0:
        raise ValueError("Spacing must be strictly positive for standard mapping.")
    
    inv_spacing = 1.0 / spacing
    mask = [[[False for _ in range(dimensions[2])] for _ in range(dimensions[1])] for _ in range(dimensions[0])]
    
    for p in points:
        vx = int(math.floor((p[0] - origin[0]) * inv_spacing))
        vy = int(math.floor((p[1] - origin[1]) * inv_spacing))
        vz = int(math.floor((p[2] - origin[2]) * inv_spacing))
        
        vx = max(0, min(vx, dimensions[0] - 1))
        vy = max(0, min(vy, dimensions[1] - 1))
        vz = max(0, min(vz, dimensions[2] - 1))
        
        mask[vx][vy][vz] = True
    return mask
```

## Subtopics

### [Voxelize Point Cloud (Basic Mode)](15079-voxelize-point-cloud-basic-mode.md)
Voxelize Point Cloud (Basic Mode) determines grid dimensions dynamically based on a user-specified target number of cells per axis ($N$) and the point cloud's bounding box. It applies a fixed padding factor of $1.002$ to the bounding box extent after an initial preflight calculation, which can result in output dimensions that deviate from the requested $N$. Unlike the [Existing Partition Grid Mode](15084-voxelize-point-cloud-existing-partation-grid-mode.md), it does not validate for zero spacing during preflight, risking division-by-zero errors on degenerate inputs. It is chosen when a target resolution is desired rather than a physical cell size [G].

### [Voxelize Point Cloud (Advanced Mode)](15082-voxelize-point-cloud-advanced-mode.md)
Voxelize Point Cloud (Advanced Mode) maps a 3D point cloud to a regular grid using a user-defined cell length (spacing) parameter. It differs from [Basic Mode](15079-voxelize-point-cloud-basic-mode.md) by explicitly accepting a spacing parameter rather than deriving it from geometry, and from [Existing Partition Grid Mode](15084-voxelize-point-cloud-existing-partition-grid-mode.md) by not requiring an existing image geometry as a reference. Unlike the Existing Partition Grid path, which rejects zero spacing with an error, Advanced Mode allows zero spacing, resulting in a silent failure where all points are skipped.

### [Voxelize Point Cloud (Existing Partition Grid Mode)](15084-voxelize-point-cloud-existing-partition-grid-mode.md)
This method voxelizes a point cloud by mapping points into a pre-existing destination grid geometry defined by its origin, spacing, and dimensions. It differs from Basic Mode by requiring the grid structure to be provided externally rather than computed from the point bounds, and from Advanced Mode by focusing on the fundamental mapping and validation against a fixed grid. It solves the problem of integrating point data into a specific, pre-defined volumetric coordinate system.

### Partition Geometry Validation
Validation routines for grid parameters exhibit specific edge-case behaviors. `DataCheckNumberOfPartitions` takes `int32` values but casts them to `usize` before checking against `<= 0`, causing negative values like `-1` to become `2^64-1`, pass validation, and request a very large geometry [S1, unofficial]. `DataCheckCellLength` only rejects negative values, allowing zero cell length [S1, unofficial]. `DataCheckBoundingBoxCoords` only rejects `min > max`, allowing `min == max` [S1, unofficial].

### Optimal Grid Resolution
The cell edge length should be about the average size of the objects, e.g., measured by their bounding box [S2, unofficial]. Cells should be cuboid-like [S2, unofficial]. Too many cells cause slow traversal, heavy memory usage, and bad cache utilization, while too few cells cause too many objects per cell [S2, unofficial].

## Background
The methods are implemented within the `VoxelizePointCloudFilter` component [S1, unofficial]. The implementation supports multiple input geometries including Vertex, Edge, Triangle, Quad, Tetrahedral, and Hexahedral [S1, unofficial]. Not given in the sources.
