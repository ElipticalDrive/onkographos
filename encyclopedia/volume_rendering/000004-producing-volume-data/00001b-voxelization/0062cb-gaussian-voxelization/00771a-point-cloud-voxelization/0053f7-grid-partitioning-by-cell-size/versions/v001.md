# Grid Partitioning by Cell Size

Also called: Point Cloud Voxelization by Cell Size, Fixed-Grid Voxelization

## Overview
Grid Partitioning by Cell Size converts a point cloud into a regular 3D voxel grid by partitioning the spatial extent defined by the cloud's bounding box or a user-specified origin into uniform cubic cells. It solves the problem of discretizing continuous point data into a structured volume representation for downstream rendering or analysis. It differs from [Octree Construction for Point Clouds](1070-octree-construction-for-point-clouds.md) by using a fixed-resolution regular grid rather than an adaptive hierarchical structure, and from [Point Resampling with Neighbor Masking](2710-point-resampling-with-neighbor-masking.md) by not explicitly handling neighbor interactions during the initial partitioning step.

## Shared principles
All variants in this family share the core mechanism of mapping 3D coordinates $(x, y, z)$ to integer voxel indices $(v_x, v_y, v_z)$ using a fixed spacing $s$ (cell length). The mapping is generally defined as:
$$ v_i = \lfloor (p_i - o_i) / s \rfloor $$
where $p_i$ is the point coordinate, $o_i$ is the grid origin, and $s$ is the cell size along axis $i$. The resulting indices are clamped or checked against the grid dimensions $D_x, D_y, D_z$. The output is typically a binary mask or a data array associated with the grid geometry.

## Subtopics

### [Voxelize Point Cloud (Basic Mode)](15079-voxelize-point-cloud-basic-mode.md)
Converts a point cloud into a regular 3D grid by calculating voxel spacing from a user-specified number of cells per axis ($N$) and the cloud's bounding box, then applying a fixed padding to the extent before finalizing dimensions. Unlike the 'Existing Image Geometry' path which validates spacing > 0, Basic mode allows zero spacing if not fixed, leading to division by zero. It is chosen when a target resolution (number of cells) is desired rather than a physical cell size.

### [Voxelize Point Cloud (Advanced Mode)](15082-voxelize-point-cloud-advanced-mode.md)
Converts a point cloud into a voxel grid mask by accepting an explicit cell length parameter to define the voxel spacing. It differs from the "Existing Image Geometry" path, which derives spacing from a pre-existing image, by allowing dynamic spacing definition. Unlike its sibling [Voxelize Point Cloud (Basic Mode)](15079-voxelize-point-cloud-basic-mode.md), which likely uses fixed or derived geometry, this mode explicitly calculates spacing from the input parameter. It solves the problem of generating a voxel mask with user-defined resolution independent of the source geometry's native grid.

### Voxelize Point Cloud (Existing Partition Grid Mode)
#### definition
A voxelization mode that uses a pre-existing destination grid geometry. It validates that the grid's spacing is larger than zero [S1, unofficial].

#### pitfall
Rejects spacing that is not larger than zero with error code -45983 [S1, unofficial].

## Background
This family of methods is implemented in the simplnx framework, specifically within the `VoxelizePointCloudFilter` [S1, unofficial]. The implementation supports multiple input geometries including Vertex, Edge, Triangle, Quad, Tetrahedral, and Hexahedral [S1, unofficial]. The filter is designed to work with chunked data stores, requiring specific unit testing strategies involving exemplar comparisons and flat index assertions [S1, unofficial].
