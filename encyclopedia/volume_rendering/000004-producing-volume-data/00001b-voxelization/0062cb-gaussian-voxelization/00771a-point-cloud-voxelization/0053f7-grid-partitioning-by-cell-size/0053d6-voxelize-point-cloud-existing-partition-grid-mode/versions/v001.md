# Voxelize Point Cloud (Existing Partition Grid Mode)
Also called: Existing Image Geometry, Existing Partition Grid

## Overview
This method voxelizes a point cloud by mapping points into a pre-existing destination grid geometry defined by its origin, spacing, and dimensions [S1, unofficial]. It differs from Basic Mode by requiring the grid structure to be provided externally rather than computed from the point bounds, and from Advanced Mode by focusing on the fundamental mapping and validation against a fixed grid [S1, unofficial]. It solves the problem of integrating point data into a specific, pre-defined volumetric coordinate system [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A point cloud geometry (vertices) and an existing image geometry (defining the destination grid) [S1, unofficial].
- Output: A binary mask or data array associated with the grid geometry, where tuples correspond to voxels [S1, unofficial].

**Data Structures:**
- The destination grid is defined by:
  - Origin $(o_x, o_y, o_z)$
  - Spacing (cell size) $s$ (assumed uniform or axis-aligned per parent principles)
  - Dimensions $D_x, D_y, D_z$
- The output array has a tuple shape of $\{D_z, D_y, D_x\}$ (or $\{dims[2], dims[1], dims[0]\}$) [S1, unofficial].

**Steps:**
1. **Validate Grid Spacing:** Check that the grid spacing $s$ is strictly greater than zero. If $s \le 0$, abort with error code -45983 [S1, unofficial].
2. **Map Points to Indices:** For each point $p$ with coordinates $(p_x, p_y, p_z)$, compute the voxel indices $(v_x, v_y, v_z)$ using the parent's shared mapping formula:
   $$ v_i = \lfloor (p_i - o_i) / s \rfloor $$
   for $i \in \{x, y, z\}$ [S1, Parent, unofficial].
3. **Clamp/Check Bounds:** Verify that $0 \le v_i < D_i$ for all axes. Points outside the grid bounds are typically discarded or handled according to specific implementation guards [G].
4. **Write to Grid:** Set the corresponding voxel in the output array to the active value (e.g., 1 or true) [S1, unofficial].

**Parameters:**
- Grid Origin: Defined by the input image geometry [S1, unofficial].
- Grid Spacing: Defined by the input image geometry [S1, unofficial].
- Grid Dimensions: Defined by the input image geometry [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Invalid Spacing:** If the grid spacing is not larger than zero, the method rejects it with error code -45983 [S1, unofficial].
- **Shape Verification:** The output tuple shape must be explicitly checked as $\{dims[2], dims[1], dims[0]\}$ to ensure correct memory layout [S1, unofficial].
- **Origin Precision:** The grid origin may be padded (e.g., $\approx -0.01$) due to prior resizing operations; this padding is critical for correct alignment [S1, unofficial].

## Subtopics

### Point-Cloud Splatting for Grid Initialization
A strategy to initialize the occupancy grid by treating geometry points as finite-sized entities that splat to nearby grid cells within a radius, rather than as infinitesimal points, to complete small missing regions [S2]. It is chosen when the initial point cloud is sparse or noisy, leading to incomplete occupancy grids [S2]. The key parameter is the splatting radius, which defines the spatial extent for spreading point influence [S2]. A pitfall is the addition of empty grid cells, which is a trade-off for filling missing regions [S2]. This approach yields significant quantitative and qualitative performance improvements, though it cannot completely remove missing regions [S2].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of points, $O(N)$, where $N$ is the number of points in the cloud [S1, unofficial].
- **Memory Complexity:** Proportional to the volume of the destination grid, $O(D_x D_y D_z)$, for the output array [S1, unofficial].
- **Strengths:** Allows integration into pre-defined coordinate systems; simple and fast mapping [S1, unofficial].
- **Limitations:** Requires a valid pre-existing grid; sensitive to grid spacing validation [S1, unofficial].
- **When to Use:** When the target voxel grid geometry is already known or defined by another process [S1, unofficial].
- **When Not to Use:** When the grid geometry needs to be derived from the point cloud bounds (use Basic Mode) or when advanced features like density estimation are required (use Advanced Mode) [S1, unofficial].

## Background
This method is part of the VoxelizePointCloudFilter in the simplnx library, which supports various geometry types including Edge, Triangle, Quad, Tetrahedral, and Hexahedral [S1, unofficial]. It is designed to work with chunked data stores for out-of-core processing [S1, unofficial]. The validation logic (error code -45983) is specific to this implementation [S1, unofficial].
