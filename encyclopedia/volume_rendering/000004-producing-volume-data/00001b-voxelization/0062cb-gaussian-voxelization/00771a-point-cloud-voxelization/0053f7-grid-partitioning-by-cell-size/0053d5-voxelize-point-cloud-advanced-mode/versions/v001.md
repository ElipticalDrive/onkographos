# Voxelize Point Cloud (Advanced Mode)
Also called: Advanced partitioning mode
## Overview
This method converts a point cloud into a voxel grid mask by accepting an explicit cell length parameter to define the voxel spacing. It differs from the "Existing Image Geometry" path, which derives spacing from a pre-existing image, by allowing dynamic spacing definition. Unlike its sibling [Voxelize Point Cloud (Basic Mode)](15079-voxelize-point-cloud-basic-mode.md), which likely uses fixed or derived geometry, this mode explicitly calculates spacing from the input parameter. It solves the problem of generating a voxel mask with user-defined resolution independent of the source geometry's native grid.
## How it works
**Inputs:**
- Point cloud geometry (e.g., `VertexGeom`).
- `cell_length`: A scalar float representing the voxel side length.
- `origin`: The world-space origin of the voxel grid (default or specified).
- `dims`: The dimensions of the output grid (e.g., `[X, Y, Z]`).

**Outputs:**
- A binary mask image (or volume) where voxels containing points are marked as 1, and empty voxels are 0.
- The mask tuple shape is `[dims[2], dims[1], dims[0]]` (Z, Y, X order).

**Data Structures:**
- **Voxel Grid:** A 3D array of size $D_z \times D_y \times D_x$.
- **Point Cloud:** A list of 3D coordinates $(x, y, z)$.

**Algorithm:**
1. **Validate Input:** Check if `cell_length` is negative. If so, reject with an error. [S1, unofficial]
2. **Calculate Spacing:** Set spacing $s = \text{cell\_length}$. [S1, unofficial]
3. **Calculate Inverse Spacing:** Compute $s_{inv} = 1.0 / s$. [S1, unofficial]
4. **Initialize Mask:** Create a mask of size $D_z \times D_y \times D_x$ initialized to 0.
5. **Iterate Points:** For each point $P_i = (x_i, y_i, z_i)$ in the point cloud:
   a. **Compute Relative Coordinates:** Calculate offset from origin:
      $$ \Delta x = x_i - \text{origin}_x $$
      $$ \Delta y = y_i - \text{origin}_y $$
      $$ \Delta z = z_i - \text{origin}_z $$
   b. **Compute Voxel Indices:**
      $$ v_x = \lfloor \Delta x \cdot s_{inv} \rfloor $$
      $$ v_y = \lfloor \Delta y \cdot s_{inv} \rfloor $$
      $$ v_z = \lfloor \Delta z \cdot s_{inv} \rfloor $$
   c. **Boundary Check:** If $0 \le v_x < D_x$, $0 \le v_y < D_y$, and $0 \le v_z < D_z$:
      Set $\text{Mask}[v_z][v_y][v_x] = 1$.
   d. **Out-of-Bounds:** If indices are out of bounds, skip the point.
6. **Return Mask:** Output the binary mask.

**Parameters:**
- `cell_length`: Typical values depend on scene scale. Must be $> 0$.
- `origin`: Default often $[0, 0, 0]$ or derived from geometry bounds.

**Edge Cases and Pitfalls:**
- **Zero Cell Length:** If `cell_length` is 0, $s_{inv}$ becomes $\infty$. This results in voxel indices of $\pm \infty$ or NaN, causing all points to be skipped. The filter completes with an all-zero mask and only a warning, rather than an error. [S1, unofficial]
- **Negative Cell Length:** Rejected by `DataCheckCellLength`. [S1, unofficial]
- **Precision:** Floating-point precision errors in coordinate mapping may cause points near boundaries to be assigned to incorrect voxels. [G]

**Pseudocode:**
```python
def voxelize_point_cloud_advanced(points, cell_length, origin, dims):
    # dims is [X, Y, Z]
    X, Y, Z = dims
    
    # Validate cell_length
    if cell_length < 0:
        raise ValueError("Cell length must be non-negative")
    
    # Calculate spacing and inverse spacing
    spacing = cell_length
    spacing_inv = 1.0 / spacing
    
    # Initialize mask with zeros
    # Shape is [Z, Y, X]
    mask = [[ [0 for _ in range(X)] for _ in range(Y) ] for _ in range(Z)]
    
    for point in points:
        x, y, z = point
        
        # Calculate relative coordinates
        dx = x - origin[0]
        dy = y - origin[1]
        dz = z - origin[2]
        
        # Calculate voxel indices
        # Note: Using floor for index calculation
        vx = int(dx * spacing_inv)
        vy = int(dy * spacing_inv)
        vz = int(dz * spacing_inv)
        
        # Check for infinity or NaN (result of division by zero if spacing was 0)
        if not (isfinite(vx) and isfinite(vy) and isfinite(vz)):
            continue
            
        # Boundary check
        if 0 <= vx < X and 0 <= vy < Y and 0 <= vz < Z:
            mask[vz][vy][vx] = 1
            
    return mask
```
## Subtopics

### Voxelize Point Cloud (Bounding Box Mode)
A variant that accepts min/max bounding box coordinates instead of a cell length. If min equals max on any axis, the spacing becomes zero, causing all points to be skipped due to infinite/NaN coordinate mapping. The pitfall is identical to the Advanced Mode: `DataCheckBoundingBoxCoords` only rejects min > max, allowing min == max, which leads to an all-zero mask and a warning. [S1, unofficial]

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of points. Each point is processed once.
- **Memory Complexity:** $O(D_x D_y D_z)$ for the output mask.
- **Strengths:** Allows explicit control over voxel resolution.
- **Limitations:** Silent failure on zero spacing. No error thrown for degenerate bounding boxes (min == max).
- **When to use:** When explicit voxel size is required.
- **When not to use:** When robustness to zero-spacing inputs is critical without post-processing checks.
## Background
This mode is part of the `VoxelizePointCloudFilter` in the simplnx library. It was introduced to provide an alternative to deriving voxel geometry from existing images. The specific pitfall regarding zero spacing was identified in code review and testing (PR #1724). [S1, unofficial]
