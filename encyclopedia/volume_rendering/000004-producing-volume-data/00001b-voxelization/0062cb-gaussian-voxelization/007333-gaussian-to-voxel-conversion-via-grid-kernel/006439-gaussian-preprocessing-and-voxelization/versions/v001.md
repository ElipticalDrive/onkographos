# Gaussian Preprocessing and Voxelization
Also called: Gaussian to Voxel Space Conversion, preprocessCUDA

## Overview
This method computes the voxel-space bounding box and conic matrix for each Gaussian primitive to determine which voxels it overlaps, preparing data for rasterization [S1, unofficial]. It transforms 3D Gaussian parameters into a discrete voxel grid coordinate system, calculating the spatial extent and inverse covariance required for efficient voxel-based rendering [S1, unofficial]. It differs from [Gaussian Kernel Interpolation](17203-gaussian-kernel-interpolation.md) by using analytical bounding boxes and conic matrices rather than kernel density estimation, and from [3DGR-CT Gaussian Voxelization](20578-3dgr-ct-gaussian-voxelization.md) by focusing on pre-rasterization metadata generation rather than volumetric density reconstruction [S1, unofficial].

## How it works
**Inputs:**
- `orig_points`: Array of 3D positions, size $P \times 3$ [S1, unofficial].
- `scales`: Array of scale factors, size $P \times 3$ [S1, unofficial].
- `rotations`: Array of quaternion rotations, size $P \times 4$ [S1, unofficial].
- `scale_modifier`: Scalar modifier for scales [S1, unofficial].
- `voxel_sizes`: Physical size of the voxel grid, $(sVoxel_x, sVoxel_y, sVoxel_z)$ [S1, unofficial].
- `voxel_counts`: Number of voxels per axis, $(nVoxel_x, nVoxel_y, nVoxel_z)$ [S1, unofficial].
- `voxel_grid_center`: Center of the voxel grid in world space [S1, unofficial].
- `cov3D_precomp`: Optional precomputed 3D covariance matrices (6 floats each) [S1, unofficial].

**Outputs:**
- `radii`: Array of bounding radii in voxels, size $P$ [S1, unofficial].
- `touched_tiles`: Array of tile counts, size $P$ [S1, unofficial].
- `depth`: Array of original Z-coordinates, size $P$ [S1, unofficial].
- `voxel_positions`: Array of voxel-space centers, size $P \times 3$ [S1, unofficial].
- `conic_a`..`conic_f`: Inverse covariance elements (6 floats), size $P \times 6$ [S1, unofficial].
- `opacities`: Opacity values, size $P$ [S1, unofficial].

**Data Structures:**
- The voxel space covariance matrix `cov` is a $3 \times 3$ symmetric matrix.
- The inverse covariance (conic) matrix elements are stored as 6 floats: $a, b, c, d, e, f$ corresponding to the upper triangle of the inverse matrix.

**Steps:**

1.  **Initialization:** For each Gaussian index `idx` from $0$ to $P-1$:
    -   Initialize `radii[idx]`, `touched_tiles[idx]` to 0.
    -   If `idx >= P`, terminate loop [S1, unofficial].

2.  **Voxel Dimensions:** Compute the physical size of a single voxel:
    $$
    dVoxel_x = \frac{sVoxel_x}{nVoxel_x}, \quad dVoxel_y = \frac{sVoxel_y}{nVoxel_y}, \quad dVoxel_z = \frac{sVoxel_z}{nVoxel_z}
    $$
    [S1, unofficial]

3.  **Position Loading:** Load the original 3D point $p_{orig}$ from `orig_points` at index $3 \times idx$ [S1, unofficial].

4.  **Covariance Computation:**
    -   If `cov3D_precomp` is not null, load the precomputed 3D covariance matrix $Vrk$ (6 floats) for this Gaussian.
    -   Otherwise, compute $Vrk$ using `computeCov3D` from `scales`, `scale_modifier`, and `rotations` [S1, unofficial].
    -   $Vrk$ is constructed from elements $[0..5]$ of the covariance representation.

5.  **Voxel-Space Covariance Transformation:**
    -   Construct the voxel scaling matrix $M$, a diagonal matrix with entries $1/dVoxel_x, 1/dVoxel_y, 1/dVoxel_z$.
    -   Transform the 3D covariance $Vrk$ to voxel space:
        $$
        cov = M \cdot Vrk \cdot M^T
        $$
    [S1, unofficial]

6.  **Conic Matrix Calculation:**
    -   Extract elements of $cov$ into $a, b, c, d, e, f$ (symmetric $3 \times 3$ matrix).
    -   Compute the determinant $det$ of $cov$.
    -   If $det == 0.0f$, return (skip this Gaussian) [S1, unofficial].
    -   Compute the inverse of the $3 \times 3$ matrix $cov$. Let the inverse elements be $inv\_a \dots inv\_f$.
    -   Store these inverse elements as `conic_a`..`conic_f` for this Gaussian [S1, unofficial].
    -   *Note:* The rasterization uses the formula $-0.5 \times (conic\_a \cdot dx^2 + \dots + 2 \cdot conic\_b \cdot dx \cdot dy \dots)$, implying `conic` is the inverse covariance in voxel space [S1, unofficial].

7.  **Bounding Radius Calculation:**
    -   Calculate `max_scale` as the maximum of `scale.x`, `scale.y`, `scale.z` [S1, unofficial].
    -   Compute the bounding radius in voxels:
        $$
        my\_radius = \left\lceil \frac{3.0 \cdot max\_scale}{dVoxel_*} \right\rceil
        $$
        (Using the appropriate $dVoxel$ dimension if anisotropic, or typically the minimum/maximum depending on implementation specifics; the source implies a scalar radius derived from max scale and voxel dimensions) [S1, unofficial].

8.  **Voxel Position Transformation:**
    -   Transform $p_{orig}$ to voxel coordinates $point\_vol$ relative to the voxel grid center and size [S1, unofficial].

9.  **Boundary Check:**
    -   Check if the Gaussian's bounding box is completely outside the voxel grid bounds $[0, nVoxel_x] \times [0, nVoxel_y] \times [0, nVoxel_z]$.
    -   If outside, return (skip this Gaussian) [S1, unofficial].

10. **Overlap Box Computation:**
    -   Compute the min/max voxel indices (`cube_min`, `cube_max`) that the Gaussian's bounding box overlaps using `getCube` [S1, unofficial].
    -   If the volume of this box is 0, return (skip this Gaussian) [S1, unofficial].

11. **Output Storage:**
    -   Store `my_radius` in `radii[idx]`.
    -   Store the number of touched tiles (derived from `cube_min` and `cube_max`) in `touched_tiles[idx]`.
    -   Store the depth (Z-coordinate of $p_{orig}$) in `depth[idx]`.
    -   Store $point\_vol$ in `voxel_positions[idx]`.
    -   Store `conic_a`..`conic_f` in the respective output buffers.
    -   Store opacity in `opacities[idx]` [S1, unofficial].

**Pseudocode:**

```python
def gaussian_preprocessing_and_voxelization(
    orig_points,
    scales,
    rotations,
    scale_modifier,
    voxel_sizes,
    voxel_counts,
    voxel_grid_center,
    cov3D_precomp=None
):
    P = len(orig_points)
    radii = [0] * P
    touched_tiles = [0] * P
    depth = [0] * P
    voxel_positions = [[0.0, 0.0, 0.0] for _ in range(P)]
    conic = [[0.0] * 6 for _ in range(P)]
    opacities = [0.0] * P # Assuming opacity is available or passed separately

    # Voxel dimensions
    dVoxel_x = voxel_sizes[0] / voxel_counts[0]
    dVoxel_y = voxel_sizes[1] / voxel_counts[1]
    dVoxel_z = voxel_sizes[2] / voxel_counts[2]

    for idx in range(P):
        # 1. Initialize
        radii[idx] = 0
        touched_tiles[idx] = 0

        # 2. Load Position
        p_orig = orig_points[idx] # [x, y, z]

        # 3. Compute Covariance
        if cov3D_precomp is not None:
            Vrk = cov3D_precomp[idx] # 6 floats
        else:
            Vrk = compute_cov3d(scales[idx], rotations[idx], scale_modifier)

        # 4. Transform to Voxel Space
        # M is diagonal matrix with 1/dVoxel_*
        # cov = M * Vrk * M^T
        # Since Vrk is 3x3 symmetric, we can compute element-wise
        # Let Vrk elements be v00, v01, v02, v11, v12, v22
        # cov_ij = Vrk_ij / (dVoxel_i * dVoxel_j)
        
        # Extract Vrk elements (assuming order: xx, xy, xz, yy, yz, zz)
        v00, v01, v02, v11, v12, v22 = Vrk
        
        cov00 = v00 / (dVoxel_x * dVoxel_x)
        cov01 = v01 / (dVoxel_x * dVoxel_y)
        cov02 = v02 / (dVoxel_x * dVoxel_z)
        cov11 = v11 / (dVoxel_y * dVoxel_y)
        cov12 = v12 / (dVoxel_y * dVoxel_z)
        cov22 = v22 / (dVoxel_z * dVoxel_z)

        # 5. Compute Inverse (Conic)
        # Matrix: [[cov00, cov01, cov02],
        #          [cov01, cov11, cov12],
        #          [cov02, cov12, cov22]]
        
        det = (cov00 * (cov11 * cov22 - cov12 * cov12) -
               cov01 * (cov01 * cov22 - cov02 * cov12) +
               cov02 * (cov01 * cov12 - cov02 * cov11))
        
        if det == 0.0:
            continue # Skip Gaussian

        # Inverse elements (upper triangle)
        inv_a = (cov11 * cov22 - cov12 * cov12) / det
        inv_b = (cov02 * cov12 - cov01 * cov22) / det
        inv_c = (cov01 * cov12 - cov02 * cov11) / det
        inv_d = (cov00 * cov22 - cov02 * cov02) / det
        inv_e = (cov01 * cov02 - cov00 * cov12) / det
        inv_f = (cov00 * cov11 - cov01 * cov01) / det

        conic[idx] = [inv_a, inv_b, inv_c, inv_d, inv_e, inv_f]

        # 6. Bounding Radius
        max_scale = max(scales[idx][0], scales[idx][1], scales[idx][2])
        # Use minimum voxel dimension for conservative radius? 
        # Source says "ceil(3.0 * max_scale / dVoxel_*)". 
        # Assuming isotropic or using a representative dVoxel. 
        # For strict implementation, we might need to check all axes.
        # Let's assume dVoxel_min for safety or as per source implication.
        dVoxel_min = min(dVoxel_x, dVoxel_y, dVoxel_z)
        my_radius = int(math.ceil(3.0 * max_scale / dVoxel_min))

        # 7. Voxel Position
        # Transform p_orig to voxel coordinates relative to grid center
        # point_vol = (p_orig - voxel_grid_center) / voxel_sizes * voxel_counts
        # Or simply: (p_orig - voxel_grid_center) / dVoxel_*
        point_vol_x = (p_orig[0] - voxel_grid_center[0]) / dVoxel_x
        point_vol_y = (p_orig[1] - voxel_grid_center[1]) / dVoxel_y
        point_vol_z = (p_orig[2] - voxel_grid_center[2]) / dVoxel_z
        voxel_positions[idx] = [point_vol_x, point_vol_y, point_vol_z]

        # 8. Boundary Check
        # Check if bounding box is outside [0, nVoxel_*]
        # Bounding box in voxel space: [point_vol - radius, point_vol + radius]
        # This is a simplification; actual implementation uses getCube with conic matrix
        # For this step, we check if the center is reasonably within bounds
        if (point_vol_x < -my_radius or point_vol_x > voxel_counts[0] + my_radius or
            point_vol_y < -my_radius or point_vol_y > voxel_counts[1] + my_radius or
            point_vol_z < -my_radius or point_vol_z > voxel_counts[2] + my_radius):
            continue

        # 9. Compute Overlap Box
        cube_min, cube_max = get_cube(point_vol, my_radius, voxel_counts)
        
        # Check volume
        vol = (cube_max[0] - cube_min[0] + 1) * (cube_max[1] - cube_min[1] + 1) * (cube_max[2] - cube_min[2] + 1)
        if vol == 0:
            continue

        # 10. Store Results
        radii[idx] = my_radius
        touched_tiles[idx] = (cube_max[0] - cube_min[0] + 1) * (cube_max[1] - cube_min[1] + 1) # Simplified tile count
        depth[idx] = p_orig[2]
        opacities[idx] = 1.0 # Placeholder, actual opacity needed

    return radii, touched_tiles, depth, voxel_positions, conic, opacities

def get_cube(center, radius, voxel_counts):
    # Compute min/max voxel indices overlapping the bounding box
    # center is in voxel coordinates
    # radius is in voxels
    min_x = max(0, int(math.floor(center[0] - radius)))
    max_x = min(voxel_counts[0], int(math.ceil(center[0] + radius)))
    min_y = max(0, int(math.floor(center[1] - radius)))
    max_y = min(voxel_counts[1], int(math.ceil(center[1] + radius)))
    min_z = max(0, int(math.floor(center[2] - radius)))
    max_z = min(voxel_counts[2], int(math.ceil(center[2] + radius)))
    return (min_x, min_y, min_z), (max_x, max_y, max_z)
```

**Parameters:**
- `voxel_size`: Typical value 0.05 scene units [S2, unofficial].
- `scale_modifier`: Scalar applied to scales during covariance computation [S1, unofficial].

**Edge Cases and Pitfalls:**
- If the determinant of the voxel-space covariance matrix is 0, the Gaussian is skipped [S1, unofficial].
- If the bounding box volume is 0, the Gaussian is skipped [S1, unofficial].
- Cell size too fine can cause excessive runtime and memory exhaustion (e.g., "tree budget exceeded") [S2, unofficial].
- Grid bounds are often padded to power-of-two cubes, which may cause viewers to treat empty space outside the logical grid as solid [S2, unofficial].

## Subtopics

### Compact GPU Voxelization
A variant that optimizes memory usage and generation speed by stopping before exceeding 64 million sparse output records and checking pool-aware memory requirements for growth, compaction, and CUB workspace [S2, unofficial]. It rejects provably impossible mixed-leaf topology early and uses byte-identical output validation against reference implementations [S2, unofficial]. It is chosen when memory efficiency and fast generation on large scenes (e.g., 5M Gaussians) are critical [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Generation stops before exceeding 64 million sparse output records [S2, unofficial].
- Memory usage is monitored via pool-aware requirements for growth, compaction, and CUB workspace [S2, unofficial].

**Measured Performance:**
- On a 5M Gaussian scene at 0.05 resolution: 3.7 s runtime, ~2 GB VRAM [S2, unofficial].
- Before review fixes: 6.076 s, after: 1.461 s [S2, unofficial].
- Packing time: 2.024 s vs 0.326 s [S2, unofficial].
- Peak GPU memory: 1,956 MiB [S2, unofficial].
- CUDA fatbin size: ~249 KiB after separating host tensor preparation [S2, unofficial].
- Output is byte-identical to independently checked 600/600-cell reference [S2, unofficial].

**Scaling:**
- A cell size that is too fine burns time before failing (e.g., 0.005 on 5M scene ran 26 s, then failed) [S2, unofficial].
- `--auto` assumes metres and floors voxel size at 0.05, rounding to 0.01 [S2, unofficial].

**Strengths and Limitations:**
- Strengths: Fast generation, memory-efficient, byte-identical output [S2, unofficial].
- Limitations: Grid bounds padding can cause viewer artifacts; raw records are not treated as format nodes [S2, unofficial].

**When to Use:**
- Use for large-scale Gaussian splatting voxelization where memory and speed are critical [S2, unofficial].
- Avoid if extremely fine voxel resolutions are required without pre-estimation, as it may fail with "tree budget exceeded" [S2, unofficial].

## Background
This method originates from the preprocessing step in Gaussian Splatting rasterization pipelines, specifically designed to convert 3D Gaussian primitives into a voxel-space representation for efficient rendering [S1, unofficial]. The "Compact GPU Voxelization" variant was introduced in the context of optimizing collision and export pipelines for Gaussian splatting tools, with significant performance improvements reviewed and merged in late 2026 [S2, unofficial]. It is used in modern Gaussian Splatting renderers and tools that require voxel-based processing, such as collision detection and export [S2, unofficial].
