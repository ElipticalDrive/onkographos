# Splat Transform CLI

Also called: Splat Transform Voxelizer

## Overview
A command-line tool for converting between various Gaussian splat formats (PLY, SPLAT, KSPLAT, SOG, HTML) and generating voxel/collision data for downstream volume rendering and collision detection [S1]. It builds on [Voxel Format Generation](6914-voxel-format-generation.md) by providing the executable interface that produces the `.voxel.json` metadata and `.voxel.bin` binary data, optionally generating a `.collision.glb` mesh [S1]. It distinguishes itself from generic splat viewers by focusing on the transformation pipeline into structured voxel grids and navigable collision spaces [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Source splat files (PLY, SPLAT, KSPLAT, SOG, HTML), camera tracks (JSON), and CLI parameters.
*   **Outputs:** Converted splat formats (CSV, compressed PLY, standalone HTML), voxel data (`.voxel.json`, `.voxel.bin`), and collision meshes (`.collision.glb`) [S1].

**Data Structures:**
The tool uses a `CliOptions` structure to manage execution state. Key fields include:
*   `memoryBudgetBytes`: Ceiling for decimation residency, derived as $\min(48 \times 2^{30}, \lfloor \text{totalmem()} / 2 \rfloor)$ [S1].
*   `renderResidentBudget`: GPU-resident scene copy budget, identical to `memoryBudgetBytes` [S1].
*   `lodSelect`: List of Level of Detail indices to select [S1].
*   `viewerSettingsJson`: Path or content for viewer configuration [S1].

**Parameters:**
*   `--voxel-size <n>`: Voxel size for `.voxel.json`. Default: `0.05` [S1].
*   `--voxel-opacity <n>`: Opacity threshold for voxel inclusion. Default: `0.1` [S1].
*   `--voxel-floor-fill [size]`: Fills columns upward from the bottom until hitting solid geometry for exterior scenes. Patches XZ areas surrounded by floor within `2*size`. Default size: `1.6` [S1].
*   `--voxel-carve [h,r]`: Carves navigable space using capsule flood fill from the seed position. Default: height `1.6`, radius `0.2` [S1].
*   `--seed-pos <x,y,z>`: Seed position for voxel fill/carve operations and cluster filtering. Default: `0,0,0` [S1].
*   `--collision-mesh [smooth|faces]`: Generates collision mesh. Default: `smooth` [S1].
*   `--camera-fov`: Fallback FOV for poses lacking one [S1].
*   `--camera-up`: Fallback up vector for poses lacking one [S1].

**Algorithm Steps:**
1.  **Parse Inputs:** Read source splat file and camera track JSON. If the camera track path is a directory, resolve to `document.json` [S1].
2.  **Validate Camera Track:** Parse JSON. If `frames` are specified, validate format `^(\d+)(?:-(\d+))?$` [S1].
3.  **Validate Background:** Parse background color `r,g,b[,a]`. Ensure each channel is in $[0, 1]$. If `a` is missing, default to `1` [S1].
4.  **Initialize Options:** Set `memoryBudgetBytes` and `renderResidentBudget` based on system RAM, capped at 48 GiB [S1].
5.  **Voxel Generation:**
    *   Convert splats to voxel grid using `--voxel-size` and `--voxel-opacity` [S1].
    *   **External Fill Logic:** Use `--seed-pos` to verify volume enclosure. If the seed is reachable from outside, skip the fill operation [S1].
    *   **Floor Fill:** If `--voxel-floor-fill` is active, fill columns upward from the bottom until hitting solid geometry [S1].
    *   **Carving:** If `--voxel-carve` is active, perform capsule flood fill from `--seed-pos` with specified height and radius to carve navigable space [S1].
6.  **Collision Mesh:** If `--collision-mesh` is specified, generate `.collision.glb` using the selected smoothing mode [S1].
7.  **Format Conversion:** Convert between supported formats (PLY, SPLAT, KSPLAT, SOG, HTML, CSV) as requested [S1].

**Edge Cases and Pitfalls:**
*   **Invalid Background:** If background channels are outside $[0, 1]$ or format is incorrect, throw an error [S1].
*   **Invalid Frames:** If frame range regex does not match, throw an error [S1].
*   **Memory Exhaustion:** The tool caps memory usage to prevent OOM, but large scenes may still require careful `--select-lod` usage [S1].

## Subtopics

### Out-of-Core PLY to RAD LOD Conversion
A file conversion pipeline that processes large PLY Gaussian splat files into tiled, chunked RAD LOD format using an out-of-core bucketed builder to avoid RAM exhaustion [S2, unofficial]. It initializes `PlyToRadLodOptions` mapping CLI parameters (`tiles_x`, `tiles_y`, `chunk_size` derived from `rad_export_mode`, and `builder` type: Octree or Bhattacharyya) [S2, unofficial]. It attaches a progress callback reporting stage names and float progress values, then executes `convert_ply_to_rad_lod(input, output, options)` [S2, unofficial]. If conversion fails, it aborts the progress bar, logs the formatted error, and returns false to prevent partial output [S2, unofficial].

## Operating characteristics
*   **Memory Complexity:** Bounded by `memoryBudgetBytes`, which is $\min(48 \text{ GiB}, \lfloor \text{totalmem()} / 2 \rfloor)$ [S1].
*   **Performance:** Depends on input size and LOD selection. Out-of-core variants mitigate RAM exhaustion for large PLY files [S2, unofficial].
*   **Strengths:** Supports multiple input/output formats; provides explicit voxel and collision generation for volume rendering pipelines [S1].
*   **Limitations:** Memory usage is capped, which may limit processing of extremely large scenes without LOD selection [S1].
*   **When to use:** When converting Gaussian splats to voxel grids for collision detection or volume rendering [S1].
*   **When not to use:** When real-time rendering without voxelization is required, or when memory constraints cannot be met even with LOD selection [S1].

## Background
Originated as part of the PlayCanvas splat-transform library [S1]. It is used in web-based 3D applications and volume rendering pipelines to prepare Gaussian splat data for efficient collision detection and spatial queries [S1].
