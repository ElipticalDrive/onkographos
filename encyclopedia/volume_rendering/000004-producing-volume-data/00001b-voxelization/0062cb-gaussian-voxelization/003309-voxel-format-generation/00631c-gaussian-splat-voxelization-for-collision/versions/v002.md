# Gaussian Splat Voxelization for Collision

Also called: Voxalization for Collision, grid-based collision, voxel-based collision, walkalization

## Overview
This method converts 3D Gaussian Splat data into a three-dimensional grid of occupied cells (voxels) to automatically generate a collision structure [S1, unofficial]. It solves the problem of creating watertight collision shells for Gaussian splats, which lack explicit geometry, by allowing the Gaussian density data to build the shell automatically [S1, unofficial]. It differs from manual mesh construction by automating the generation of a collision mesh (e.g., ~10,000 triangles for a 3-million-splat scene) directly from volumetric data [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A Gaussian Splat file (e.g., `.ply`) and scene parameters (indoor/outdoor mode, voxel size, opacity threshold) [S1, unofficial].
*   **Output:** A collision mesh in GLB format [S1, unofficial]. Intermediate sparse voxel structures may be output as JSON and binary files (`.voxel.json`, `.voxel.bin`) for use in viewers like Super Splat [S1, unofficial].

**Data Structures**
*   **Voxel Grid:** A 3D grid covering the scene bounds, where each cell stores a density value accumulated from nearby Gaussians [S1, unofficial].
*   **Sparse Voxel Structure:** A representation of occupied voxels stored in JSON (metadata) and binary (data) formats for efficient processing and viewer integration [S1, unofficial].

**Parameters**
*   **Voxel Size:** Determines the resolution of the grid; smaller values yield finer structures [S1, unofficial].
*   **Opacity Threshold:** The density value a voxel must exceed to be considered solid [S1, unofficial].

**Algorithm Steps**
1.  **Grid Initialization:** Lay a 3D grid over the entire scene bounds [S1, unofficial].
2.  **Density Accumulation:** The GPU sweeps through the grid, summing the density contributions of all Gaussians overlapping each voxel [S1, unofficial].
3.  **Binary Classification:** Check if the accumulated density exceeds the opacity threshold; if yes, mark the voxel as solid, otherwise mark it as air [S1, unofficial].
4.  **Cleanup:** Automatically remove isolated voxels floating in air and fill tiny holes in the solid structure [S1, unofficial].
5.  **Scene-Specific Processing:**
    *   **Indoor Mode:**
        1.  **Exterior Fill:** Fluid flows in from outside the scene bounds, turning everything beyond the walls solid [S1, unofficial]. Walls are temporarily thickened to prevent fluid leaking through small caps or openings [S1, unofficial].
        2.  **Carving:** A seed point is positioned in free space inside the room [S1, unofficial]. A capsule expands from this seed, carving out reachable space [S1, unofficial]. The capsule only moves through open space; areas it cannot reach (e.g., inside walls, narrow gaps) become solid [S1, unofficial].
    *   **Outdoor Mode:**
        1.  **Floor Fill:** Use a special floor fill feature [S1, unofficial]. Walk up every column of voxels from below until hitting the first surface [S1, unofficial]. Everything underneath becomes solid ground [S1, unofficial]. Empty columns at the scene edges become invisible walls [S1, unofficial].
        2.  **Carving:** A seed point is placed in open space slightly above the ground [S1, unofficial]. A capsule expands from this seed [S1, unofficial]. Everything reached becomes the final collision surface [S1, unofficial].
6.  **Mesh Generation:** Merge the resulting voxels into larger rectangles to form a simple collision mesh [S1, unofficial].
7.  **Export:** Save the mesh as a GLB file [S1, unofficial].

    res_y = math.ceil((max_b[1] - min_b[1]) / voxel_size)
    res_z = math.ceil((max_b[2] - min_b[2]) / voxel_size)
    grid = [[[0.0 for _ in range(res_z)] for _ in range(res_y)] for _ in range(res_x)]
    
    # 2. Density Accumulation
    for y in range(res_y):
        for x in range(res_x):
            for z in range(res_z):
                center = (min_b[0] + x * voxel_size + voxel_size * 0.5,
                          min_b[1] + y * voxel_size + voxel_size * 0.5,

                for g in gaussian_splats:
                    if gaussian_overlaps_box(g, center, voxel_size):
                        density += gaussian_density_at(g, center)
                grid[y][x][z] = density

    # 3. Binary Classification
    solid_mask = [[[False for _ in range(res_z)] for _ in range(res_y)] for _ in range(res_x)]
    for y in range(res_y):
        for x in range(res_x):
            for z in range(res_z):
                if grid[y][x][z] > opacity_threshold:
                    solid_mask[y][x][z] = True

    # 4. Cleanup
    solid_mask = morphological_cleanup(solid_mask)

    # 5. Scene-Specific Processing

        solid_mask = carve_interior(solid_mask, seed, voxel_size)

**Edge Cases and Pitfalls**
*   **Precision:** Voxel size must be chosen carefully; too large loses detail, too small increases memory and computation [S1, unofficial].
*   **Boundaries:** In outdoor scenes, Gaussians may extend far into the distance, requiring spherical cropping or careful boundary definition to avoid excessive voxelization [S1, unofficial].
*   **Leakage:** In indoor scenes, small caps or openings can cause exterior fill to leak into the interior if walls are not sufficiently thickened [S1, unofficial].
*   **Narrow Gaps:** The carving phase may fail to carve narrow gaps if the capsule radius is too large, incorrectly marking them as solid [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of Gaussians and voxel grid resolution [S1, unofficial]. The GPU sweep is efficient, but cleanup and carving phases add complexity [S1, unofficial].
*   **Memory Complexity:** Proportional to the voxel grid size [S1, unofficial].
*   **Performance:** A room with ~3 million Gaussians produces a collision mesh of ~10,000 triangles, less than 200 kilobytes [S1, unofficial].
*   **Strengths:** Automates collision shell generation; produces lightweight meshes suitable for game engines [S1, unofficial].
*   **Limitations:** Requires careful parameter tuning (voxel size, threshold); may not capture fine details if voxel size is too large [S1, unofficial].
*   **When to Use:** When automatic collision generation for Gaussian splats is needed, especially for indoor or outdoor scenes where manual meshing is impractical [S1, unofficial].
*   **When Not to Use:** When high-fidelity collision geometry is required, or when the scene is extremely large and memory is constrained [S1, unofficial].

## Background
The method is implemented in **Splat Transform** (CLI and UI wrapper by Geeken Gifford) and **Super Splat** (web-based, processed by PlayCanvas server) [S1, unofficial]. It leverages the volumetric nature of Gaussian splats to create "walkable" surfaces, analogous to voxels in games like Minecraft [S1, unofficial]. The output GLB format is widely supported in game engines and 3D software [S1, unofficial].
