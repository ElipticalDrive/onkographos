# Voxel Atlas Construction
Also called: Compact Voxel Atlas JSON Format

## Overview
Voxel Atlas Construction is a data packaging method that aggregates individual voxelized asset files into a single, compact JSON file containing flat arrays of positions and colors [S1, unofficial]. It solves the performance bottleneck of loading and parsing numerous small JSON files by consolidating them into a unified structure optimized for rapid memory mapping and rendering [S1, unofficial]. Unlike raw voxelization methods that produce discrete grids, this method focuses on the serialization and aggregation of existing voxel data for efficient web or application loading [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A directory containing individual voxel JSON files (typically generated by a voxelization pipeline). Each file contains voxel data for a single asset.
- **Output:** A single JSON file (`voxel_atlas.json`) containing an object mapping asset names to their voxel data.

**Data Structures:**
The output is a JSON object where keys are asset names. Each value is an object with the following fields:
- `resolution` (int): The voxel grid resolution used for the asset.
- `count` (int): The number of voxels in the asset.
- `bounds` (object): An object with `min` and `max` keys, each holding an array of 3 integers representing the bounding box coordinates.
- `positions` (flat array of ints/floats): Interleaved x, y, z coordinates for each voxel. Format: `[x0, y0, z0, x1, y1, z1, ...]`.
- `colors` (flat array of ints/floats): Interleaved r, g, b values for each voxel. Format: `[r0, g0, b0, r1, g1, b1, ...]`.

**Steps:**
1. **Discovery:** Glob for all `*.json` files in the input directory. Sort them alphabetically. Filter out any file named `voxel_atlas.json` to prevent recursion.
2. **Initialization:** Create an empty dictionary `atlas` to store the aggregated data.
3. **Iteration:** For each valid JSON file:
    a. Load the JSON data.
    b. Extract the asset `name` (use the file stem if the `name` field is missing).
    c. Extract `resolution`, `count`, `bounds`, `positions`, and `colors` from the source file.
    d. Store these fields in the `atlas` dictionary under the key `name`.
4. **Serialization:** Create the parent directory for the output path if it does not exist. Write the `atlas` dictionary to the output file as formatted JSON.

**Pseudocode:**
```python
import json
import os
from pathlib import Path

def build_atlas(voxel_dir: str, output_path: str) -> None:
    """
    Combines individual voxel JSON files into a single compact atlas file.
    """
    voxel_path = Path(voxel_dir)
    atlas = {}
    
    # 1. Discovery
    json_files = sorted(voxel_path.glob("*.json"))
    if not json_files:
        print(f"No voxel JSON files found in {voxel_dir}")
        return

    # 2. Iteration
    for file_path in json_files:
        # Skip the atlas file itself
        if file_path.name == "voxel_atlas.json":
            continue
            
        with open(file_path, 'r') as f:
            data = json.load(f)
        
        # Extract name, defaulting to file stem
        name = data.get("name", file_path.stem)
        
        # Extract required fields
        # Note: Source assumes these keys exist in the input JSON
        asset_data = {
            "resolution": data["resolution"],
            "count": data["count"],
            "bounds": data["bounds"],
            "positions": data["positions"],
            "colors": data["colors"]
        }
        
        atlas[name] = asset_data
        print(f"  Added: {name} ({data['count']} voxels)")

    # 3. Serialization
    output_p = Path(output_path)
    output_p.parent.mkdir(parents=True, exist_ok=True)
    
    with open(output_p, 'w') as f:
        json.dump(atlas, f)
        
    size_kb = output_p.stat().st_size / 1024
    print(f"\nAtlas saved to {output_path}")
    print(f"  Assets: {len(atlas)}")
    print(f"  Size: {size_kb:.1f} KB")
```

**Parameters:**
- `voxel_dir`: Path to the directory containing individual voxel JSON files.
- `output_path`: Path where the resulting `voxel_atlas.json` will be saved.

**Edge Cases and Pitfalls:**
- **Missing Fields:** The method assumes input JSON files contain `resolution`, `count`, `bounds`, `positions`, and `colors`. If these are missing, the script will raise a `KeyError` [S1, unofficial].
- **Recursion:** The script explicitly skips `voxel_atlas.json` to prevent infinite loops if the output directory is the same as the input directory [S1, unofficial].
- **Data Types:** The source notes mention `positions` and `colors` as flat arrays of ints or floats. Consistency in data types (e.g., all ints vs. all floats) across assets is not enforced by the aggregation step but should be consistent in the source files [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of input files and the total number of voxels, as it involves reading, parsing, and writing JSON data.
- **Memory Complexity:** Proportional to the total size of all input JSON files loaded into memory. For very large assets, this may require significant RAM [S1, unofficial].
- **Performance:** In the context of the full pipeline (Image-to-Voxel), the atlas construction is a CPU-bound step that overlaps with GPU processing [S1, unofficial]. The aggregation itself is fast compared to the voxelization inference [S1, unofficial].
- **Strengths:** Significantly reduces I/O overhead for loading multiple assets. Simplifies data management by providing a single entry point for all voxel data [S1, unofficial].
- **Limitations:** Not suitable for dynamic updates where individual voxels need to be modified in place; the entire atlas may need to be rebuilt. The JSON format is not as compact as binary formats (e.g., FlatBuffers, Protobuf) for very large datasets [S1, unofficial].

## Background
This method is part of the `image-to-voxel` pipeline, an unofficial implementation for generating voxel assets from images using AI models like TripoSR [S1, unofficial]. The pipeline includes stages for image preparation, 3D inference, and voxelization, with the atlas construction serving as the final packaging step for efficient distribution [S1, unofficial]. It was developed to address the inefficiency of managing many small JSON files in web-based 3D applications [S1, unofficial].
