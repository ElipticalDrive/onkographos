# Voxel Atlas Construction
Also called: Compact Voxel Atlas JSON Format

## Overview
Voxel Atlas Construction aggregates individual voxelized asset files into a single compact JSON file containing flat arrays of positions and colors [S1, unofficial]. It consolidates numerous small JSON files into a unified structure optimized for efficient web loading [S1, unofficial]. Unlike discrete voxelization methods that generate grids from geometry, this method focuses on serializing and aggregating pre-existing voxel data for application loading [S1, unofficial].

## How it works
**Inputs and Outputs:**
The input is a directory containing individual voxel JSON files, where each file contains voxel data for a single asset [S1, unofficial]. The output is a single JSON file containing an object that maps asset names to their voxel data [S1, unofficial].

**Data Structures:**
The output is a JSON object where the keys are asset names [S1, unofficial]. Each value is an object with the following fields: `resolution` is an integer representing the voxel grid resolution used for the asset [S1, unofficial]. `count` is an integer representing the number of voxels in the asset [S1, unofficial]. `bounds` is an object with `min` and `max` keys, each holding an array of three integers representing the bounding box coordinates [S1, unofficial]. `positions` is a flat array of integers or floats containing interleaved x, y, z coordinates for each voxel in the format `[x0, y0, z0, x1, y1, z1, ...]` [S1, unofficial]. `colors` is a flat array of integers or floats containing interleaved r, g, b values for each voxel in the format `[r0, g0, b0, r1, g1, b1, ...]` [S1, unofficial].

**Steps:**
1. **Discovery:** Glob for all `*.json` files in the input directory, sort them alphabetically, and filter out any file named `voxel_atlas.json` to prevent recursion [S1, unofficial].
2. **Initialization:** Create an empty dictionary `atlas` to store the aggregated data [G].
3. **Iteration:** For each valid JSON file, load the JSON data [S1, unofficial]. Extract the asset `name` and use the file stem if the `name` field is missing [S1, unofficial]. Extract `resolution`, `count`, `bounds`, `positions`, and `colors` from the source file [S1, unofficial]. Store these fields in the `atlas` dictionary under the key `name` [S1, unofficial].
4. **Serialization:** Create the parent directory for the output path if it does not exist [S1, unofficial]. Write the `atlas` dictionary to the output file as formatted JSON [S1, unofficial].

**Pseudocode:**
```python
import json
from pathlib import Path

def build_atlas(voxel_dir: str, output_path: str) -> None:
    """
    Combines individual voxel JSON files into a single compact atlas file.
    """
    voxel_path = Path(voxel_dir)
    atlas = {}
    json_files = sorted(voxel_path.glob("*.json"))
    if not json_files:
        print(f"No voxel JSON files found in {voxel_dir}")
        return
    for file_path in json_files:
        if file_path.name == "voxel_atlas.json":
            continue
        with open(file_path, 'r') as f:
            data = json.load(f)
        name = data.get("name", file_path.stem)
        asset_data = {
            "resolution": data["resolution"],
            "count": data["count"],
            "bounds": data["bounds"],
            "positions": data["positions"],
            "colors": data["colors"]
        }
        atlas[name] = asset_data
        print(f"  Added: {name} ({data['count']} voxels)")
    output_p = Path(output_path)
    output_p.parent.mkdir(parents=True, exist_ok=True)
    with open(output_p, 'w') as f:
        json.dump(atlas, f)
    size_kb = output_p.stat().st_size / 1024
    print(f"\nAtlas saved to {output_path}")
    print(f"  Assets: {len(atlas)}")
    print(f"  Size: {size_kb:.1f} KB")
```

**Parameters:**
The `voxel_dir` parameter specifies the path to the directory containing individual voxel JSON files [S1, unofficial]. The `output_path` parameter specifies the path where the resulting atlas JSON file will be saved [S1, unofficial].

**Edge Cases and Pitfalls:**
The method assumes input JSON files contain `resolution`, `count`, `bounds`, `positions`, and `colors`, and direct dictionary access raises a `KeyError` if any are missing [G]. The script explicitly skips `voxel_atlas.json` to prevent infinite loops if the output directory is the same as the input directory [S1, unofficial]. The source notes describe `positions` and `colors` as flat arrays of integers in one context and floats in another, and consistency in data types across assets is not enforced by the aggregation step [S1, unofficial].

## Operating characteristics
The time complexity is not given in the sources, but standard JSON parsing and serialization scale linearly with the number of input files and total voxel count [G]. The memory complexity is not given in the sources, but it is proportional to the total size of all input JSON files loaded into memory [G]. In the full pipeline, CPU stages overlap with GPU processing to avoid idle time [S1, unofficial]. The aggregation step is fast compared to the voxelization inference [S1, unofficial]. The method reduces I/O overhead for loading multiple assets and provides a single entry point for all voxel data [S1, unofficial]. It is not suitable for dynamic updates where individual voxels need to be modified in place, as the entire atlas may need to be rebuilt [G]. The JSON format is less compact than binary formats for very large datasets [G].

## Background
This method is part of the `image-to-voxel` pipeline, which is an unofficial implementation for generating voxel assets from images using AI models like TripoSR [S1, unofficial]. The pipeline includes stages for image preparation, 3D inference, and voxelization, with the atlas construction serving as the final packaging step for efficient distribution [S1, unofficial].
