# Mask-based Voxel Filtering

Also called: Combiner shader, FSCombiner

## Overview
Mask-based Voxel Filtering is a fragment shader that combines an original volume dataset with a texture mask (SculptMap) to discard voxels marked for removal during visualization [S1]. It serves as the final composition stage in a volume sculpting pipeline, integrating visibility and material insertion masks generated by previous tools with the underlying volumetric data [S1].

## How it works
**Inputs and Outputs:**
The shader takes a vertex-to-fragment structure `vertex2fragment` containing texture coordinates `Tex0` (type `float2`, semantic `TEXCOORD0`) [S1]. It outputs a color value `Col` (type `float4`, semantic `COLOR0`) [S1].

**Data Structures and Uniforms:**
Three uniform textures are accessed [S1]:
1. `SculptMap`: A `sampler3D` bound to `TEXUNIT0` [S1]. It stores two masks: visibility information in the Alpha channel (A) and inserted material information in the Green channel (B) [S1].
2. `VolumeTex`: A `sampler3D` bound to `TEXUNIT1` [S1]. It holds the original volume dataset [S1].
3. `PolygonCoord`: A `sampler2D` bound to `TEXUNIT1` [S1]. It provides coordinate mapping for geometric operations [S1].

**Algorithm Steps:**
The shader processes the fragment as follows [S1]:
1. Sample the `SculptMap` at the input texture coordinates to retrieve the mask voxel:
   $$ \text{mask\_voxel} = \text{tex3D}(\text{SculptMap}, \text{v2f.Tex0}) $$
2. Sample the `VolumeTex` at the input texture coordinates to retrieve the original volume voxel:
   $$ \text{volume\_voxel} = \text{tex3D}(\text{VolumeTex}, \text{v2f.Tex0}) $$
3. Sample the `PolygonCoord` texture to obtain geometric coordinates:
   $$ \text{texCoord} = \text{tex2D}(\text{PolygonCoord}, \text{v2f.Tex0}) $$
4. Determine the output color based on the inserted material mask (`mask_voxel.b`) [S1]:
   * If `mask_voxel.b == 1.0`:
     * Set Alpha to $1.0$.
     * Set RGB to the input texture coordinates `v2f.Tex0.rgb` [S1].
   * Else:
     * Set RGB to the original volume voxel's RGB: `Col.rgb = volume_voxel.rgb` [S1].
     * Set Alpha to the product of the volume voxel's alpha and the floor of the visibility mask's alpha:
       $$ \text{Col.a} = \text{volume\_voxel.a} \times \lfloor \text{mask\_voxel.a} \rfloor $$

**Pseudocode:**
The following Python-like pseudocode implements the logic described in [S1].

```python
import math

class float4:
    """4-component vector type with fields r, g, b, a."""
    def __init__(self, r, g, b, a):
        self.r, self.g, self.b, self.a = r, g, b, a

def fs_combiner(v2f_Tex0, SculptMap, VolumeTex, PolygonCoord):
    """
    Mask-based Voxel Filtering (FSCombiner)
    v2f_Tex0: float2, texture coordinates from vertex shader
    SculptMap: 3D texture, visibility (A) and inserted material (B) masks
    VolumeTex: 3D texture, original volume data
    PolygonCoord: 2D texture, coordinate mapping
    """
    # 1. Sample masks and volume data
    mask_voxel = SculptMap.sample(v2f_Tex0)
    volume_voxel = VolumeTex.sample(v2f_Tex0)
    texCoord = PolygonCoord.sample(v2f_Tex0)

    # 2. Determine output based on inserted material mask (Channel B)
    if mask_voxel.b == 1.0:
        # Inserted material case
        Col_a = 1.0
        Col_rgb = (v2f_Tex0.r, v2f_Tex0.g, v2f_Tex0.b)
    else:
        # Standard visibility filtering case
        Col_rgb = (volume_voxel.r, volume_voxel.g, volume_voxel.b)
        # Alpha is volume alpha multiplied by floor of visibility mask alpha
        Col_a = volume_voxel.a * math.floor(mask_voxel.a)

    return float4(Col_rgb[0], Col_rgb[1], Col_rgb[2], Col_a)
```

**Edge Cases and Pitfalls:**
*   **Precision:** The visibility mask uses `floor(mask_voxel.a)`, implying binary visibility (0 or 1) [S1].
*   **Channel Usage:** The visibility mask is stored in Alpha (A) and inserted material in Green (B) [S1].
*   **Coordinate Mapping:** The `PolygonCoord` texture is sampled but is not directly used in the final color calculation for the basic combiner case [S1].

## Background
**Origin:**
The Mask-based Voxel Filtering (FSCombiner) was introduced in the context of "Volume sculpting based on geometric tools" [S1]. It is part of a pipeline that includes tools like Eraser, Digger, Clipper, and Filler, which modify a `SculptMap` texture [S1]. The `SculptMap` was modified to store two masks: visibility and inserted material, to support filling tools like Mirror and Filler [S1].

**History and Development:**
The method is described in a paper published in 2009 [S1]. It builds upon the Tagging Shader concept by using the tags (masks) to control the final rendering output [S1].

**Where it is used:**
It is used in volume sculpting applications for medical or scientific visualization, where users interactively modify volume data using geometric tools [S1].
