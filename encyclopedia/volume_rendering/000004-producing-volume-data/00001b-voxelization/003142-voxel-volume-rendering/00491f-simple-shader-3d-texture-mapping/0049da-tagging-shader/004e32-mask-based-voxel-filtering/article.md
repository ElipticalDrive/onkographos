# Mask-based Voxel Filtering

Also called: Combiner shader, FSCombiner

## Overview
Mask-based Voxel Filtering is a fragment shader that combines an original volume dataset with a texture mask (SculptMap) to discard voxels marked for removal or to insert new material during visualization [S1]. It serves as the final composition stage in a volume sculpting pipeline, integrating visibility and material insertion masks generated by previous tools (e.g., Eraser, Digger, Filler) with the underlying volumetric data [S1]. Unlike the Tagging Shader, which acts as a 3D stencil buffer to tag voxels, this shader performs the actual visual filtering and material replacement during the drawing phase [S1].

## How it works
**Inputs and Outputs:**
The shader takes a vertex-to-fragment structure `vertex2fragment` containing texture coordinates `Tex0` (type `float2`, semantic `TEXCOORD0`) [S1]. It outputs a color value `Col` (type `float4`, semantic `COLOR0`) [S1].

**Data Structures and Uniforms:**
Three uniform textures are accessed:
1.  `SculptMap`: A `sampler3D` bound to `TEXUNIT0`. It stores two masks: visibility information in the Alpha channel (A) and inserted material information in the Green channel (B) [S1].
2.  `VolumeTex`: A `sampler3D` bound to `TEXUNIT1`. It holds the original volume dataset [S1].
3.  `PolygonCoord`: A `sampler2D` bound to `TEXUNIT1`. It provides coordinate mapping for geometric operations [S1].

**Algorithm Steps:**
The shader processes the fragment as follows:

1.  Sample the `SculptMap` at the input texture coordinates to retrieve the mask voxel:
    $$ \text{mask\_voxel} = \text{tex3D}(\text{SculptMap}, \text{v2f.Tex0}) $$
2.  Sample the `VolumeTex` at the input texture coordinates to retrieve the original volume voxel:
    $$ \text{volume\_voxel} = \text{tex3D}(\text{VolumeTex}, \text{v2f.Tex0}) $$
3.  Sample the `PolygonCoord` texture to obtain geometric coordinates:
    $$ \text{texCoord} = \text{tex2D}(\text{PolygonCoord}, \text{v2f.Tex0}) $$
4.  Determine the output color based on the inserted material mask (`mask_voxel.b`):
    *   If `mask_voxel.b == 1.0f`:
        *   Set Alpha to 1.0.
        *   Set RGB to the input texture coordinates `v2f.Tex0.rgb` [S1].
    *   Else:
        *   Set RGB to the original volume voxel's RGB: `Col.rgb = volume_voxel.rgb`.
        *   Set Alpha to the product of the volume voxel's alpha and the floor of the visibility mask's alpha:
            $$ \text{Col.a} = \text{volume\_voxel.a} \times \lfloor \text{mask\_voxel.a} \rfloor $$

```python
def fs_combiner(v2f_Tex0, SculptMap, VolumeTex, PolygonCoord):
    """
    Mask-based Voxel Filtering (FSCombiner)
    v2f_Tex0: float2, texture coordinates from vertex shader
    SculptMap: 3D texture, visibility (A) and inserted material (B) masks
    VolumeTex: 3D texture, original volume data
    PolygonCoord: 2D texture, coordinate mapping
    """
    # 1. Sample masks and volume data
    mask_voxel = SculptMap.sample(v2f_Tex0) # Returns float4 (RGBA)
    volume_voxel = VolumeTex.sample(v2f_Tex0) # Returns float4 (RGBA)
    texCoord = PolygonCoord.sample(v2f_Tex0) # Returns float4 (RGBA), used as float3 xyz
    
    # 2. Determine output based on inserted material mask (Channel B)
    if mask_voxel.b == 1.0:
        # Inserted material case
        Col_a = 1.0
        Col_rgb = v2f_Tex0.rgb
    else:
        # Standard visibility filtering case
        Col_rgb = volume_voxel.rgb
        # Alpha is volume alpha multiplied by floor of visibility mask alpha
        Col_a = volume_voxel.a * floor(mask_voxel.a)
        
    return float4(Col_rgb, Col_a)
```

**Edge Cases and Pitfalls:**
*   **Precision:** The visibility mask uses `floor(mask_voxel.a)`, implying binary visibility (0 or 1). Floating-point inaccuracies in mask generation could lead to unexpected 0 values if the mask is not strictly clamped to [0,1] or if anti-aliasing is applied to the mask texture [S1].
*   **Channel Usage:** The visibility mask is stored in Alpha (A) and inserted material in Green (B). Confusing these channels will result in incorrect filtering or material insertion [S1].
*   **Coordinate Mapping:** The `PolygonCoord` texture is sampled but, in the core `FSCombiner` logic defined in the "step" notes, its result is not directly used in the final color calculation for the basic combiner case. ## Operating characteristics
**Time and Memory Complexity:**
The shader performs a constant number of texture lookups (3) and simple arithmetic operations per fragment. Time complexity is $O(1)$ per fragment. Memory complexity is dominated by the storage of the `SculptMap` and `VolumeTex` textures, which are $O(N)$ where $N$ is the number of voxels in the volume [S1].

**Measured Performance:**
Not given in the sources.

**Strengths and Limitations:**
*   **Strengths:** It allows for real-time visualization of sculpting operations by combining pre-computed masks with the volume data. It supports both visibility masking (erasing) and material insertion (filling) in a single pass [S1].
*   **Limitations:** The visibility is binary (via `floor`), limiting smooth transitions or partial visibility unless the mask itself is pre-filtered. The reliance on a separate `SculptMap` texture requires additional memory and synchronization between the sculpting tools and the rendering pipeline [S1].

**When to use it:**
Use this method when visualizing volume data that has been modified by geometric sculpting tools (Eraser, Digger, Filler) in a real-time application, specifically when the modifications are stored as binary masks in a 3D texture [S1].

## Background
**Origin:**
The Mask-based Voxel Filtering (FSCombiner) was introduced in the context of "Volume sculpting based on geometric tools" [S1]. It is part of a pipeline that includes tools like Eraser, Digger, Clipper, and Filler, which modify a `SculptMap` texture. The `SculptMap` was modified to store two masks: visibility and inserted material, to support filling tools like Mirror and Filler [S1].

**History and Development:**
The method is described in a paper published in 2009 (based on the source date and context of "Volume sculpting...") [S1]. It builds upon the Tagging Shader concept by using the tags (masks) to control the final rendering output.

**Where it is used:**
It is used in volume sculpting applications for medical or scientific visualization, where users interactively modify volume data using geometric tools [S1].
