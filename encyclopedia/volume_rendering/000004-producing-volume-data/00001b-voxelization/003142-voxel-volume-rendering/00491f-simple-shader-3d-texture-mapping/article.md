# Simple Shader (3D Texture Mapping)
Also called: TMSimpleShader, vzTMSimpleShader

## Overview
The Simple Shader performs basic volume rendering of a 3D scalar field by mapping the volume data to a 3D texture and rendering polygonal geometry generated from the volume's slicing [S1, S2]. It differs from advanced shading methods (such as gradient-based or tangent-space shading) by relying solely on the raw interpolated texel values without computing surface normals or applying complex transfer functions [S1]. It serves as the foundational rendering technique for voxel volumes, supporting both block-style and smooth compositing depending on the texture filtering settings [Parent].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D volume texture containing the scalar field data.
*   **Input:** Polygonal geometry representing the volume's bounding box or sliced surfaces.
*   **Output:** A 2D image with the volume rendered via alpha compositing.

**Data Structures**
The core data structure is the `vzParameterVolumeTexture`, which holds the 3D texture data [S1]. The geometry is typically a block or set of slices generated by the volume slicing process [S1, S2].

**Parameters**
*   `volume` (Type: `vzParameterVolumeTexture`): The volume data to be rendered [S1, S2].

**Algorithm Steps**
1.  **Generate Geometry:** Create polygonal geometry from the volumetric data. This is typically done by slicing the volumetric geometry, resulting in a set of polygons that represent the volume's extent [S1].
2.  **Create Shader Instance:** Instantiate the `vzTMSimpleShader` object [S2].
3.  **Create Appearance:** Create an `vzAppearance` object and attach the shader to it [S2].
4.  **Bind Parameter:** Attach the `volume` parameter (of type `vzParameterVolumeTexture`) to the appearance [S1, S2].
5.  **Attach to Shape:** Assign the appearance to the shape node containing the geometry [S2].
6.  **Render:** Render the geometry in back-to-front order with the `volume` texture bound as the current texture [S1]. The hardware interpolates the texel values across the polygons.

**Pseudocode**
The following C++-like pseudocode demonstrates the setup sequence required to render a volume using this shader, based on the provided examples [S2].

```cpp
// 1. Load volume data into a vzParameterVolumeTexture
vzParameterVolumeTexture* volume = loadVolumeFromFile("data.raw");

// 2. Create the shader instance
vzShader* shader = new vzTMSimpleShader();

// 3. Create the appearance and attach the shader
vzAppearance* appearance = new vzAppearance(shader);
shader->unref(); // Shader is now managed by appearance

// 4. Attach the volume parameter to the appearance
appearance->setParameter("volume", volume);
volume->unref(); // Volume is now managed by appearance

// 5. Create geometry (e.g., a block representing the volume bounds)
vzGeometry* geometry = new vzBlock();

// 6. Create the shape and attach geometry and appearance
vzShape* shape = new vzShape(geometry, appearance);
geometry->unref();
appearance->unref();

// 7. Render
// The render action (e.g., vzTMRenderAction) handles the back-to-front
// rendering and texture binding internally when drawing the shape.
renderAction->draw(shape);
```

**Edge Cases and Pitfalls**
*   **Texture Filtering:** The visual quality (block-style vs. smooth) depends on the 3D texture filtering mode (nearest vs. linear) set on the GPU [Parent].
*   **Back-to-Front Order:** Correct alpha compositing requires the geometry to be rendered in back-to-front order relative to the viewer [S1].

## Subtopics

### Tagging Shader
A variant that performs volumetric tagging using two perfectly overlapping volumes: a data volume and a tag volume acting as a 3D stencil buffer [S1]. If the value of the tag texel is greater than 0.5, the corresponding texel in the volume data is rendered; otherwise, it is masked out [S1]. This method avoids modifying the original volume data but incurs the overhead of storing an additional 3D texture [S1]. On non-GPU systems or those lacking fragment shader extensions (ARB_fragment_program/ATI_fragment_shader), it uses the OpenGL stencil buffer, requiring the application to ensure the appropriate visual is selected [S1].

### vzTMLUTShader
A variant that applies transfer functions to volume data using a 1D lookup table (LUT) mapped to interpolated texel values [S1]. It requires two parameters: `volume` and `lookup_table` [S1]. Unlike pre-computing colors for each texel, which requires huge computation and re-downloading the whole volume on transfer function changes, this shader applies the transfer function via OpenGL hardware, requiring only the LUT to be downloaded on changes [S1]. The implementation is system-dependent [S1].

## Operating characteristics
*   **Complexity:** Time complexity is linear with respect to the number of fragments/pixels covered by the volume geometry. Memory complexity is dominated by the storage of the 3D volume texture in GPU memory [S1].
*   **Performance:** This is the fastest rendering method among the built-in shaders because it offloads all computation to the texture hardware without requiring per-fragment gradient calculations or complex shading logic [S1].
*   **Limitations:** It does not support lighting, shadows, or surface normal estimation, resulting in a flat appearance unless the volume data itself encodes such information [S1]. It is suitable for quick visualization or when the volume data is already pre-shaded [S1].
*   **Hardware Dependency:** The quality and performance depend on the GPU's 3D texture support and filtering capabilities [S1].

## Background
The Simple Shader is part of the SGI OpenGL Volumizer library, specifically the Texture Mapping Render Action (TMRenderAction) [S1]. It was introduced as a basic volume rendering technique that leverages standard 3D texture mapping capabilities available in OpenGL hardware [S1, S2]. It is often used as a baseline for comparing more advanced shading techniques like gradient-based shading or tangent-space shading [S1].
