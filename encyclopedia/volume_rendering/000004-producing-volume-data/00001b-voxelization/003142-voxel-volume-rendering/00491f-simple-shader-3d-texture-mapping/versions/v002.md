# Simple Shader (3D Texture Mapping)
Also called: TMSimpleShader, vzTMSimpleShader

## Overview
The Simple Shader performs basic volume rendering of a 3D scalar field by mapping the volume texture onto polygonal geometry generated from slicing the volumetric data [S1, S2]. It solves the problem of visualizing voxel data without applying complex shading models or transfer functions, relying instead on the hardware's native 3D texture interpolation and blending capabilities [S1]. Unlike the Tagging Shader, which uses a secondary stencil volume to mask regions, or the LUT Shader, which applies dynamic color mapping, the Simple Shader renders the raw interpolated values directly [S1, S2]. It builds on [Voxel Volume Rendering](6488-voxel-volume-rendering.md) by utilizing the `vzTMRenderAction` infrastructure to handle the back-to-front sorting and compositing required for correct alpha blending [S1].

## How it works
The method relies on the `vzTMRenderAction` to generate the necessary geometry and manage the rendering pass. The implementation involves creating the shader object, attaching the volume data, and executing the render action.

**Inputs and Outputs:**
*   **Input:** A volume texture of type `vzParameterVolumeTexture` containing the scalar field data [S1, S2].
*   **Output:** A rasterized image of the volume rendered with simple alpha blending [S1].

**Data Structures:**
The core data structure is the `vzParameterVolumeTexture`, which holds the 3D texture data [S1, S2]. The shader itself is an instance of `vzTMSimpleShader`, which inherits from `vzShader` [S2]. The appearance object `vzAppearance` stores the shader and its parameters [S2].

**Steps:**
1.  **Load Volume Data:** Load the volumetric data from a file (e.g., TIFF) into a `vzParameterVolumeTexture` object using a loader [S2].
2.  **Create Shader:** Instantiate the `vzTMSimpleShader` [S2].
3.  **Create Appearance:** Create a `vzAppearance` object, passing the shader to its constructor [S2].
4.  **Attach Parameter:** Set the `volume` parameter on the appearance to the loaded `vzParameterVolumeTexture` [S2]. The parameter name must be exactly `"volume"` [S1, S2].
5.  **Generate Geometry:** The `vzTMRenderAction` generates polygonal geometry from the slicing of the volumetric geometry as described in the base 3D texture mapping section [S1]. This geometry represents the volume bounds [S1].
6.  **Render:** Execute the render action. The geometry is rendered in back-to-front order with the `"volume"` texture bound [S1]. The hardware performs the texture sampling and blending [S1].

**Pseudocode:**
```python
# 1. Load volume data
# Assuming a loader object exists that can read the file format
volume = loader.load_volume()
if volume is None:
    raise Error("Couldn't read volume data")

# 2. Create shader instance
shader = vzTMSimpleShader()

# 3. Create appearance with the shader
appearance = vzAppearance(shader)

# 4. Attach the volume parameter
# The parameter name is strictly "volume"
appearance.set_parameter("volume", volume)

# 5. Create geometry (handled by vzTMRenderAction internally, 
# but conceptually a block or sliced geometry representing the volume bounds)
geometry = vzBlock()

# 6. Create shape and manage in render action
shape = vzShape(geometry, appearance)
render_action = vzTMRenderAction(1)
render_action.manage(shape)

# 7. Render
# The render action handles back-to-front sorting and texture binding
render_action.begin_draw(VZ_RESTORE_GL_STATE_BIT)
render_action.draw()
render_action.end_draw()
```

**Parameters:**
*   `volume`: Type `vzParameterVolumeTexture`. Specifies the actual volume data to be rendered [S1]. This is the only required parameter for `vzTMSimpleShader` [S1].

**Edge Cases and Pitfalls:**
*   **Blending Order:** The geometry must be rendered in back-to-front order to ensure correct alpha blending [S1]. The `vzTMRenderAction` handles this sorting [S1].
*   **Texture Binding:** The `"volume"` texture must be bound during the rendering pass [S1].
*   **Data Type:** The volume data must be compatible with the `vzParameterVolumeTexture` type [S1, S2].

## Subtopics

### vzTMLUTShader
A shader that applies transfer functions to volume data using a 1D lookup table (LUT) mapped to interpolated texel values [S1]. It solves the problem of dynamic color mapping without the overhead of pre-computing colors for each texel [S1]. Unlike `vzTMSimpleShader`, which renders raw values, `vzTMLUTShader` maps scalar values to colors via a LUT [S1]. It requires two parameters: `volume` (`vzParameterVolumeTexture`) and `lookup_table` (`vzParameterLookupTable`) [S1]. A key advantage is that when the transfer function changes, only the LUT needs to be downloaded to texture memory, which is faster than re-downloading the entire volume texture [S1]. However, the process is system-dependent in its implementation via OpenGL hardware [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The rendering time depends on the resolution of the generated polygonal geometry and the cost of back-to-front sorting [S1].
*   **Memory Complexity:** Requires storing the `vzParameterVolumeTexture` in GPU memory [S1, S2].
*   **Measured Performance:** Not given in the sources. A 256 MB CT of a human head is rendered using this shader [S1].
*   **Strengths:** Simple implementation; leverages hardware texture interpolation and blending; no custom shading logic required [S1].
*   **Limitations:** No transfer function application; limited visual control compared to LUT or gradient shaders [S1].
*   **When to use:** When a quick visualization of raw volume data is needed without color mapping [S1].
*   **When not to use:** When specific tissue types or data ranges need to be highlighted via color mapping (use `vzTMLUTShader`) or when masking specific regions is required (use `vzTMTagShader`) [S1].

## Background
The Simple Shader is part of the SGI VolumePro or similar volumetric rendering toolkit, specifically within the `TMRenderAction` framework [S1]. It was documented in Chapter 4 of the SGI HTML manual "Texture Mapping Render Action" [S1]. The approach builds on the general technique of 3D texture mapping for volume rendering, where the volume is sliced into polygons and rendered with 3D textures [S1]. The `vzTMSimpleShader` class is a built-in shader provided by the toolkit [S1].
