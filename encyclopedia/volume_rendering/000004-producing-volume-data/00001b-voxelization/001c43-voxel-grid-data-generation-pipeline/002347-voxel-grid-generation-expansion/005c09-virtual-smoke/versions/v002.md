# Virtual Smoke

Also called: Volume Seedlings, Volume Seeds

## Overview
Virtual Smoke is an interactive 3D flow visualization technique that simulates the injection of colored smoke from a user-selected seed point into a fixed vector field, where the smoke color is mapped to a local scalar value [S1]. It solves the problem of simultaneously visualizing flow direction (via vector fields) and scalar properties (e.g., temperature, concentration) in large 3D datasets [S1]. Unlike [Volume Seedlings](2979-voxel-grid-generation-expansion.md), which uses a priority queue based on a "degree of interest," Virtual Smoke uses an event queue ordered by propagation time derived from velocity vectors to grow a control volume [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A fixed 3D vector field (velocity) $\vec{V}$, a scalar field $S$, and a user-selected seed voxel position $S_{pos}$ [S1].
*   **Output:** A rendered volume representing the "smoke" cloud, where opacity and color are determined by the scalar field and the propagation time [S1].

**Data Structures:**
1.  **Event Queue $Q$:** A priority queue storing voxels ordered by their propagation time [S1]. Each entry contains a voxel index and its associated propagation time $T$ [S1].
2.  **Propagation Time Array $T$:** A map where each voxel index maps to a scalar float representing the time taken for the "smoke" front to reach that voxel from the seed [S1]. Initialized to infinity, except for the seed [G].

**Algorithm Steps:**
1.  **Initialization:**
    *   Round the user-selected seed position to the nearest voxel position $S$ [S1].
    *   Initialize $T[S] = 0$ [S1].
    *   Insert $S$ into $Q$ with time $0$ [S1].
2.  **Control Volume Growth Loop:**
    *   While $Q$ is not empty:
        1.  Extract the event $P$ from $Q$ with the shortest propagation time $T[P]$ [S1].
        2.  For each of the 26 neighbors $P_i$ of $P$ (3D Moore neighborhood):
            *   Calculate the velocity component normal to the vector $(P_i - P)$ [S1].
            *   Calculate the distance $\delta_j$ between $P$ and $P_i$ [S1].
            *   Calculate the propagation time for the neighbor: $t[P_i] = \delta_j + T[P]$ [S1].
            *   If $P_i$ is not in $Q$:
                *   Insert $P_i$ into $Q$ with time $t[P_i]$ [S1].
            *   Else if $P_i$ is in $Q$ and $T[P_i] > t[P_i]$:
                *   Update $T[P_i] = t[P_i]$ [S1].
        3.  Render the region surrounding $P$ [S1].

**Pseudocode:**
```python
# Initialize
T = {voxel: float('inf') for voxel in all_voxels}
Q = PriorityQueue()
T[seed] = 0.0
Q.push(seed, 0.0)

while not Q.is_empty():
    P = Q.pop_min_time()  # Returns voxel with smallest T[P]
    
    # Render the region surrounding P
    render_region(P)
    
    # Check 26 neighbors (Moore neighborhood)
    for dx in (-1, 0, 1):
        for dy in (-1, 0, 1):
            for dz in (-1, 0, 1):
                if dx == 0 and dy == 0 and dz == 0:
                    continue
                P_i = voxel_at_offset(P, dx, dy, dz)
                if not is_in_bounds(P_i):
                    continue
                
                # Calculate distance delta_j between P and P_i
                delta_j = distance(P, P_i)
                t_new = delta_j + T[P]
                
                if P_i not in T or T[P_i] > t_new:
                    T[P_i] = t_new
                    Q.push(P_i, t_new)
```

**Particle Tracing Variant:**
Instead of visiting all 26 neighbors, the algorithm can visit one voxel at a time according to the local velocity to form a trace of particles [S1]. The trace is connected with small color-coded clouds [S1]. Ribbon-like paths can be emulated using multiple seeds [S1].

**Parameters:**
*   **Neighbor Connectivity:** 26 neighbors (3D Moore neighborhood) [S1].
*   **Rendering Region:** A cloud-like sphere around the voxel, highlighted according to user-controlled parameters (e.g., opacity matte as a function of distance from seed) [S1].

**Edge Cases and Pitfalls:**
*   **Steady-State Requirement:** The vector field must be fixed (steady-state) for the control volume growth algorithm to work as described [S1]. Dynamic fields require time-slicing [S1].
*   **Temporal Ordering:** If a voxel is visited from a different path, the new propagation time is compared to the existing one [S1]. The shorter time replaces the old one to ensure correct temporal ordering [S1].
*   **Scalar Field Conflict:** Using vector magnitude as the scalar field for color correctly shows speed but prohibits viewing other scalar fields (temperature, pressure) [S1]. The implementation typically uses a time display instead of dynamic delay to maintain near real-time performance [S1].

## Operating characteristics
*   **Performance:** Achieved ten or more frames per second on a Silicon Graphics GTX/240 [S1].
*   **Complexity:** A complete voxel-by-voxel growing sequence would take tens of minutes for a large data set (e.g., $10^6$ nodes) [S1]. However, near real-time animation is achieved by limiting the growth to the 26 nearest voxels around the seed point considered at each iteration and using ray-sample caching [S1].
*   **Strengths:** Interactive viewing of local flow patterns; simultaneous visualization of vector and scalar data; emulates particle tracing without geometrical primitives [S1].
*   **Limitations:** Requires fixed (steady-state) vector fields; full volume growth is computationally expensive; flow speed magnitude may not be correctly displayed if vector magnitude is not used as the scalar field [S1].
*   **When to use:** For interactive exploration of flow patterns in isolated areas of steady-state combustion simulations or other CFD data [S1].

## Background
*   **Origin:** Developed by Kwan-Liu Ma and Philip J. Smith at the University of Utah [S1].
*   **History:** The idea evolved from [Volume Seeds](2979-voxel-grid-generation-expansion.md) and Volume Seedlings, but the implementation is not tied to them [S1]. It was applied to steady flow data from combustion simulations, specifically for steady-state simulations of combustion performance in furnaces (pilot scale, utility boiler, cyclonic) [S1].
*   **Usage:** Used in combustion engineering simulations to visualize complex vector and scalar fields, including heat transfer and chemical reaction effects [S1].
