# Synthetic Phantom Generation
Also called: Sphere Phantom
## Overview
Synthetic Phantom Generation creates idealized 3D volume data, specifically consisting of spheres, to serve as ground truth for testing and validating CT reconstruction algorithms [S1, unofficial].
## How it works
### Inputs and Outputs
- **Inputs**: Volume dimension $D$ (size), and a list of sphere definitions, each containing center coordinates $(x, y, z)$ and radius $r$ [G].
- **Outputs**: A 3D array representing the synthetic CT phantom [S1, unofficial].

### Data Structures
- **Volume Grid**: A 3D array of shape $(D, D, D)$ initialized to zeros [S1, unofficial].
- **Sphere Definition**: Each sphere is defined by its center coordinates $(x, y, z)$ and radius $r$ [G].

### Steps
1. **Initialize Volume**: Create a 3D array of zeros with shape $(D, D, D)$ [S1, unofficial].
2. **Generate Spheres**: For each sphere $i$ with center $C_i=(x_c, y_c, z_c)$ and radius $r_i$:
   - Create coordinate grids covering the volume dimensions [G].
   - Calculate the squared Euclidean distance $d^2 = (x_v - x_c)^2 + (y_v - y_c)^2 + (z_v - z_c)^2$ for each voxel $(x_v, y_v, z_v)$ [G].
   - Set voxels where $d^2 \le r_i^2$ to 1.0 (or a specific attenuation coefficient) [G].
3. **Export**: Save the resulting volume array for use in reconstruction pipelines [S1, unofficial].

### Parameters
- **Size**: The dimension of the cubic volume [S1, unofficial].
- **Spheres**: List of `(x, y, z, r)` tuples defining sphere centers and radii [G].

### Edge Cases and Pitfalls
- **Boundary Conditions**: Ensure sphere centers and radii are defined such that spheres do not extend beyond the volume boundaries, or handle clipping explicitly [G].
- **Overlap**: If spheres overlap, the current implementation sets overlapping voxels to 1. For distinct materials, a different accumulation strategy is required [G].

### Pseudocode
```python
import numpy as np

def generate_sphere_phantom(size, spheres):
    # Initialize volume with zeros
    volume = np.zeros((size, size, size), dtype=np.float32)
    
    # Iterate over each sphere definition
    for x, y, z, radius in spheres:
        # Create coordinate grids for efficient distance calculation
        xx, yy, zz = np.meshgrid(
            np.arange(size), 
            np.arange(size), 
            np.arange(size), 
            indexing='ij'
        )
        
        # Calculate squared Euclidean distance from each voxel to sphere center
        dist_sq = (xx - x)**2 + (yy - y)**2 + (zz - z)**2
        
        # Set voxels inside the sphere to 1
        volume[dist_sq <= radius**2] = 1.0
        
    return volume
```
## Subtopics

### [Primitive-based Phantom Generation](18236-primitive-based-phantom-generation.md)
Generates 3D CT phantoms by combining mathematical primitives (spheres, spheroids, cuboids, cylinders, checkers) within a specified volume shape and geometry, using voxel coordinates in millimeters [G]. Choose this when you need varied shapes beyond spheres for more complex scene testing [G].

## Operating characteristics
- **Strengths**: Fast generation, analytically precise ground truth, easy to integrate with PyTorch-based reconstruction pipelines [S1, unofficial].
- **Limitations**: Limited to spherical shapes; does not model complex anatomical structures or material variations [S1, unofficial].
- **When to Use**: Validating reconstruction algorithms (FDK, iterative methods) where ground truth is required [S1, unofficial].
- **Time Complexity**: Not given in the sources. [S1, unofficial]
