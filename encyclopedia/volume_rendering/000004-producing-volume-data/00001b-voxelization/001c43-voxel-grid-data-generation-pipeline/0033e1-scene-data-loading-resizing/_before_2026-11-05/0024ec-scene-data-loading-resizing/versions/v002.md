# Scene Data Loading & Resizing
## Overview
This method loads Structure-from-Motion (SfM) data from a COLMAP reconstruction, resizes source images to a target resolution, and adjusts camera parameters and coordinate systems to match the rendering pipeline's requirements [S1, unofficial]. It serves as the initial data preparation step in the Voxel Grid Data Generation Pipeline, ensuring that image dimensions, intrinsics, and extrinsics are consistent with the target voxel grid scale [S1, unofficial]. It differs from [Voxel Grid Generation & Expansion](2979-voxel-grid-generation-expansion.md) by focusing on data ingestion and normalization rather than grid construction, and from [DCX Pipeline](3770-dcx-pipeline.md) by handling raw COLMAP binary models directly [S1, unofficial].
## How it works
**Inputs:**
- `model_path`: Path to the COLMAP model directory containing binary reconstruction files.
- `images_path`: Path to the directory containing source images.
- `target_res`: Target pixel size for the image's longest edge (typical: 400) [S1, unofficial].
- `max_points`: Maximum number of 3D points to load to prevent hardware overflow (typical: 1000) [S1, unofficial].

**Outputs:**
- `cam_infos`: A list of `CameraInfo` objects, one per image.
- `points`: A subsampled set of 3D points with normalized RGB values.

**Data Structures:**
- `CameraInfo`:
  - `R`: Rotation matrix, shape $(3, 3)$, `torch.float` [S1, unofficial].
  - `T`: Translation vector, shape $(3,)$, `torch.float` [S1, unofficial].
  - `fx`, `fy`: Focal lengths, `float` [S1, unofficial].
  - `cx`, `cy`: Principal point coordinates, `float` [S1, unofficial].
  - `width`, `height`: Resized image dimensions, `int` [S1, unofficial].
  - `image_path`: Absolute path to the image file, `str` [S1, unofficial].
  - `image_name`: Original filename, `str` [S1, unofficial].

**Steps:**
1. **Load Data:** Read COLMAP cameras, images, and 3D points using `read_model(path=model_path, ext=".bin")` [S1, unofficial].
2. **Iterate Images:** For each image in the reconstruction:
   a. Retrieve the corresponding camera model and image metadata [S1, unofficial].
   b. Calculate scale: $s = \frac{\text{target\_res}}{\max(\text{orig\_w}, \text{orig\_h})}$ [S1, unofficial].
   c. Compute new dimensions: $\text{new\_w} = \lfloor \text{orig\_w} \times s \rfloor$, $\text{new\_h} = \lfloor \text{orig\_h} \times s \rfloor$ [S1, unofficial].
   d. Convert quaternion $qvec$ to rotation matrix $R$ using `qvec2rotmat` [S1, unofficial].
   e. Adjust coordinate system: Negate the Y and Z axes of $R$ and $T$:
      $$R_{1:3, :} = -R_{1:3, :}$$
      $$T_{1:3} = -T_{1:3}$$
      [S1, unofficial]
   f. Scale intrinsics by $s$:
      - If model is `PINHOLE`: $f_x, f_y, c_x, c_y = \text{params}[0] \cdot s, \text{params}[1] \cdot s, \text{params}[2] \cdot s, \text{params}[3] \cdot s$ [S1, unofficial].
      - If model is `SIMPLE_PINHOLE`: $f_x = f_y = \text{params}[0] \cdot s$, $c_x, c_y = \text{params}[1] \cdot s, \text{params}[2] \cdot s$ [S1, unofficial].
      - Fallback: Treat as `SIMPLE_PINHOLE` [S1, unofficial].
   g. Construct `CameraInfo` with resized dimensions and adjusted parameters [S1, unofficial].
3. **Process Points:**
   a. Extract $xyz$ and $rgb$ from `points3D` [S1, unofficial].
   b. Normalize RGB: $\text{rgb} = \frac{\text{rgb}}{255.0}$ [S1, unofficial].
   c. If $\text{len(points)} > \text{max\_points}$, randomly subsample to `max_points` [S1, unofficial].

**Pseudocode:**
```python
import os
import torch
import numpy as np
from src.utils.read_write_model import read_model, qvec2rotmat

class CameraInfo:
    def __init__(self, R, T, fx, fy, cx, cy, width, height, image_path, image_name):
        self.R = R
        self.T = T
        self.fx = fx
        self.fy = fy
        self.cx = cx
        self.cy = cy
        self.width = width
        self.height = height
        self.image_path = image_path
        self.image_name = image_name

def fetch_scene_data(model_path, images_path, target_res=400, max_points=1000):
    cameras_extrinsic, images_intrinsic, points3D = read_model(path=model_path, ext=".bin")
    cam_infos = []

    for key in images_intrinsic:
        colmap_image = images_intrinsic[key]
        colmap_cam = cameras_extrinsic[colmap_image.camera_id]

        orig_w = colmap_cam.width
        orig_h = colmap_cam.height
        scale = target_res / max(orig_w, orig_h)
        new_w = int(orig_w * scale)
        new_h = int(orig_h * scale)

        R = np.array(torch.from_numpy(qvec2rotmat(colmap_image.qvec)).float())
        T = np.array(torch.from_numpy(colmap_image.tvec).float())
        R[1:3, :] *= -1
        T[1:3] *= -1

        R = torch.from_numpy(R).float()
        T = torch.from_numpy(T).float()

        params = colmap_cam.params
        if colmap_cam.model == "PINHOLE":
            fx, fy = params[0] * scale, params[1] * scale
            cx, cy = params[2] * scale, params[3] * scale
        else:
            fx = fy = params[0] * scale
            cx, cy = params[1] * scale, params[2] * scale

        img_path = os.path.join(images_path, colmap_image.name)
        cam_info = CameraInfo(R=R, T=T, fx=fx, fy=fy, cx=cx, cy=cy,
                              width=new_w, height=new_h,
                              image_path=img_path, image_name=colmap_image.name)
        cam_infos.append(cam_info)

    xyz = np.array([p.xyz for p in points3D.values()])
    rgb = np.array([p.rgb for p in points3D.values()]) / 255.0

    if len(xyz) > max_points:
        indices = np.random.choice(len(xyz), max_points, replace=False)
        xyz = xyz[indices]
        rgb = rgb[indices]

    return cam_infos, xyz, rgb
```

**Edge Cases:**
- If `orig_w` or `orig_h` is zero, scale calculation fails [G].
- If `max_points` is smaller than the number of points, random subsampling is used [S1, unofficial].
- Coordinate system adjustment assumes a specific COLMAP-to-renderer convention (Y/Z flip) [S1, unofficial].

## Subtopics

### [COLMAP Binary Model Parsing](3455-colmap-binary-model-parsing.md)
Parses COLMAP reconstruction files stored in binary format (`.bin`) into structured Python objects (`Camera`, `Image`, `Point3D`). It provides a memory-efficient alternative to text parsing for large-scale SfM/MVS datasets, serving as the primary data loading step in the [Scene Data Loading & Resizing](3420-scene-data-loading-resizing.md) pipeline.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of images and points [S1, unofficial].
- **Memory Complexity:** Proportional to the number of points and images [S1, unofficial].
- **Strengths:** Handles large datasets efficiently via binary parsing; ensures consistent coordinate systems and resolutions [S1, unofficial].
- **Limitations:** Requires COLMAP binary format; subsampling loses detail if `max_points` is too low [S1, unofficial].
- **When to use:** When preparing data for voxel-based rendering from SfM reconstructions [S1, unofficial].
- **When not to use:** If text-based COLMAP models are used without conversion; if exact point cloud preservation is required without subsampling [S1, unofficial].
## Background
Originated in the mini-splat project as a utility for loading COLMAP data for 3D Gaussian Splatting pipelines [S1, unofficial]. It addresses the need for standardized camera parameters and coordinate systems in volume rendering [S1, unofficial].
