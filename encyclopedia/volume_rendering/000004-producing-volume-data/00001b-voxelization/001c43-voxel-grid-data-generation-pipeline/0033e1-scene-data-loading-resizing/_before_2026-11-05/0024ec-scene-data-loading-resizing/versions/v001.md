# Scene Data Loading & Resizing


## Overview
This method loads COLMAP reconstruction data (cameras and 3D points) and prepares it for voxel grid generation by resizing images to a target resolution, adjusting the coordinate system to match the rendering convention, and subsampling the point cloud to fit hardware constraints [S1, unofficial]. It serves as the initial data ingestion step in the Voxel Grid Data Generation Pipeline, ensuring that subsequent voxelization steps operate on consistent, normalized data [1208-voxel-grid-data-generation-pipeline].

## How it works
**Inputs:**
- `model_path`: Path to the COLMAP model directory containing binary reconstruction files.
- `images_path`: Path to the directory containing the source images.
- `target_res`: Target pixel size for the image's long edge (typical value: 400) [S1, unofficial].
- `max_points`: Maximum number of 3D points to load to prevent hardware overflow (typical value: 1000) [S1, unofficial].

**Outputs:**
- `cam_infos`: A list of `CameraInfo` objects, one per image.
- `points`: A subsampled set of 3D points (xyz) and normalized colors (rgb).

**Data Structures:**
- `CameraInfo`:
  - `R`: Rotation matrix, shape $(3, 3)$, `torch.float32`.
  - `T`: Translation vector, shape $(3,)$, `torch.float32`.
  - `fx`, `fy`: Focal lengths, `float`.
  - `cx`, `cy`: Principal point coordinates, `float`.
  - `width`, `height`: Resized image dimensions, `int`.
  - `image_path`: String path to the image file.
  - `image_name`: String name of the image file.

**Steps:**
1. **Load COLMAP Data**: Read the reconstruction using `read_model(path=model_path, ext=".bin")`. This returns `cameras_extrinsic` (dictionary mapping camera ID to camera parameters), `images_intrinsic` (dictionary mapping image ID to image metadata including camera ID, quaternion, and translation), and `points3D` (dictionary mapping point ID to 3D point structure with xyz and rgb) [S1, unofficial].
2. **Iterate Images**: For each image in `images_intrinsic`:
   a. Retrieve the corresponding camera parameters from `cameras_extrinsic` using the image's `camera_id`.
   b. **Compute Scale**: Calculate `scale = target_res / max(orig_w, orig_h)`, where `orig_w` and `orig_h` are the original image dimensions from the camera parameters [S1, unofficial].
   c. **Compute New Dimensions**: `new_w = int(orig_w * scale)`, `new_h = int(orig_h * scale)` [S1, unofficial].
   d. **Convert Rotation**: Convert the image's quaternion `qvec` to a rotation matrix `R` using `qvec2rotmat`. Convert to `torch.float32` [S1, unofficial].
   e. **Adjust Coordinate System**: Negate the Y and Z axes of the rotation matrix `R` and translation vector `T`. Specifically: `R[1:3, :] *= -1` and `T[1:3] *= -1` [S1, unofficial]. This aligns the COLMAP coordinate system (Z-forward, Y-down) with the rendering convention (typically Z-back, Y-up or similar, depending on the specific renderer, but here explicitly negating Y and Z) [S1, unofficial].
   f. **Scale Intrinsics**: Extract intrinsic parameters `params` from the camera.
      - If model is `PINHOLE`: `fx = params[0] * scale`, `fy = params[1] * scale`, `cx = params[2] * scale`, `cy = params[3] * scale` [S1, unofficial].
      - If model is `SIMPLE_PINHOLE`: `fx = fy = params[0] * scale`, `cx = params[1] * scale`, `cy = params[2] * scale` [S1, unofficial].
      - Fallback: If model is neither, assume `SIMPLE_PINHOLE` scaling logic [S1, unofficial].
   g. **Construct CameraInfo**: Create a `CameraInfo` object with the adjusted `R`, `T`, scaled intrinsics, new dimensions, and image path [S1, unofficial].
3. **Process Points**:
   a. Extract `xyz` coordinates and `rgb` values from `points3D.values()` [S1, unofficial].
   b. Normalize RGB values: `rgb = rgb / 255.0` [S1, unofficial].
   c. **Subsample**: If the number of points exceeds `max_points`, randomly subsample the points to `max_points` [S1, unofficial].

**Pseudocode:**
```python
import os
import torch
import numpy as np
from src.utils.read_write_model import read_model, qvec2rotmat

class CameraInfo:
    def __init__(self, R, T, fx, fy, cx, cy, width, height, image_path, image_name):
        self.R = R
        self.T = T
        self.fx = fx
        self.fy = fy
        self.cx = cx
        self.cy = cy
        self.width = width
        self.height = height
        self.image_path = image_path
        self.image_name = image_name

def fetch_scene_data(model_path, images_path, target_res=400, max_points=1000):
    # 1. Load COLMAP data
    cameras_extrinsic, images_intrinsic, points3D = read_model(path=model_path, ext=".bin")
    
    cam_infos = []
    
    # 2. Process each image
    for key in images_intrinsic:
        colmap_image = images_intrinsic[key]
        colmap_cam = cameras_extrinsic[colmap_image.camera_id]
        
        # 2a. Compute scale and new dimensions
        orig_w = colmap_cam.width
        orig_h = colmap_cam.height
        scale = target_res / max(orig_w, orig_h)
        new_w = int(orig_w * scale)
        new_h = int(orig_h * scale)
        
        # 2b. Convert rotation and adjust coordinate system
        R = np.array(torch.from_numpy(qvec2rotmat(colmap_image.qvec)).float())
        T = np.array(torch.from_numpy(colmap_image.tvec).float())
        R[1:3, :] *= -1
        T[1:3] *= -1
        
        R = torch.from_numpy(R).float()
        T = torch.from_numpy(T).float()
        
        # 2c. Scale intrinsics
        params = colmap_cam.params
        if colmap_cam.model == "PINHOLE":
            fx, fy, cx, cy = params[0] * scale, params[1] * scale, params[2] * scale, params[3] * scale
        elif colmap_cam.model == "SIMPLE_PINHOLE":
            fx = fy = params[0] * scale
            cx, cy = params[1] * scale, params[2] * scale
        else:
            # Fallback for other models
            fx = fy = params[0] * scale
            cx, cy = params[1] * scale, params[2] * scale
            
        img_path = os.path.join(images_path, colmap_image.name)
        
        cam_info = CameraInfo(
            R=R, T=T, fx=fx, fy=fy, cx=cx, cy=cy,
            width=new_w, height=new_h,
            image_path=img_path, image_name=colmap_image.name
        )
        cam_infos.append(cam_info)
        
    # 3. Process points
    xyz = np.array([p.xyz for p in points3D.values()])
    rgb = np.array([p.rgb for p in points3D.values()]) / 255.0
    
    # Subsample if necessary
    if len(xyz) > max_points:
        indices = np.random.choice(len(xyz), max_points, replace=False)
        xyz = xyz[indices]
        rgb = rgb[indices]
        
    return cam_infos, xyz, rgb
```

**Edge Cases and Pitfalls:**
- **Coordinate System Mismatch**: Failing to negate Y and Z axes will result in incorrect camera poses relative to the scene [S1, unofficial].
- **Intrinsic Scaling**: Intrinsics must be scaled by the same factor as the image dimensions to maintain correct projection geometry [S1, unofficial].
- **Hardware Limits**: Ignoring `max_points` may lead to out-of-memory errors during voxel grid generation [S1, unofficial].
- **Image Resolution**: If `target_res` is too high, memory usage for image loading and voxelization may become prohibitive [S1, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of images and points. The dominant cost is reading the COLMAP model and resizing images (if done later, but intrinsics are adjusted here) [S1, unofficial].
- **Memory Complexity**: Proportional to the number of images and points. Subsampling limits point cloud memory usage [S1, unofficial].
- **Strengths**: Simple, robust handling of COLMAP data; ensures consistent coordinate systems and resolutions; prevents hardware overflow via subsampling [S1, unofficial].
- **Limitations**: Assumes COLMAP binary format; does not handle image resizing itself (only intrinsics adjustment); random subsampling may discard important geometric details [S1, unofficial].
- **When to Use**: When preparing data for voxel-based rendering methods that require COLMAP inputs and have strict memory constraints [S1, unofficial].
- **When Not to Use**: If the scene data is not in COLMAP format; if precise point cloud density is critical and random subsampling is unacceptable [S1, unofficial].
