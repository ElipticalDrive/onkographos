# Scene Data Loading & Resizing


## Overview
This method loads camera parameters and 3D point clouds from Structure-from-Motion (SfM) reconstructions, resizes input images to a target resolution, and adjusts coordinate systems to match rendering requirements. It solves the problem of heterogeneous input data formats and resolutions by normalizing them into a unified set of camera intrinsics/extrinsics and a subsampled point cloud suitable for voxel grid generation. It differs from sibling methods by focusing specifically on the I/O and normalization phase before grid expansion or specific pipeline optimizations like DCX.

## How it works
**Inputs:**
- `model_path`: Path to the COLMAP model directory containing binary reconstruction files.
- `images_path`: Path to the directory containing original source images.
- `target_res`: Target pixel size for the image long edge (typical: 400) [S1, unofficial].
- `max_points`: Maximum number of 3D points to load to prevent hardware overflow (typical: 1000) [S1, unofficial].

**Outputs:**
- `cam_infos`: A list of `CameraInfo` objects, one per image.
- `points`: A subsampled array of 3D points (xyz) and normalized colors (rgb).

**Data Structures:**
The primary output structure is `CameraInfo`, defined with the following fields:
- `R`: Rotation matrix, shape $(3, 3)$, type `torch.float` [S1, unofficial].
- `T`: Translation vector, shape $(3,)$, type `torch.float` [S1, unofficial].
- `fx`, `fy`: Focal lengths in pixels, type `float` [S1, unofficial].
- `cx`, `cy`: Principal point coordinates, type `float` [S1, unofficial].
- `width`, `height`: Resized image dimensions, type `int` [S1, unofficial].
- `image_path`: Absolute path to the resized image file, type `str` [S1, unofficial].
- `image_name`: Original filename, type `str` [S1, unofficial].

**Steps:**
1. **Load Raw Data**: Read COLMAP cameras, images, and 3D points using the binary model reader `read_model(path=model_path, ext=".bin")` [S1, unofficial]. This returns dictionaries for cameras, images, and points.
2. **Iterate Images**: For each image in the reconstruction:
    a. **Compute Scale**: Calculate the scaling factor based on the original image dimensions $(w, h)$ and `target_res`:
       $$ scale = \frac{target\_res}{\max(w, h)} $$
       [S1, unofficial]
    b. **Resize Dimensions**: Compute new dimensions:
       $$ new\_w = \lfloor w \times scale \rfloor $$
       $$ new\_h = \lfloor h \times scale \rfloor $$
       [S1, unofficial]
    c. **Coordinate Transformation**: Convert the image's quaternion $qvec$ to a rotation matrix $R$ using `qvec2rotmat`. Negate the Y and Z axes of both the rotation matrix $R$ and the translation vector $T$ to convert from COLMAP's coordinate system to the rendering system:
       $$ R_{new}[1:3, :] = -R_{old}[1:3, :] $$
       $$ T_{new}[1:3] = -T_{old}[1:3] $$
       [S1, unofficial]
    d. **Adjust Intrinsics**: Scale the intrinsic parameters by `scale`. The handling depends on the camera model:
       - **PINHOLE**: $fx, fy, cx, cy$ are scaled individually from `params[0:4]`.
       - **SIMPLE_PINHOLE**: $fx = fy = params[0] \times scale$, $cx = params[1] \times scale$, $cy = params[2] \times scale$.
       - **Fallback**: If the model is neither, apply the SIMPLE_PINHOLE logic as a default [S1, unofficial].
    e. **Construct CameraInfo**: Create the object with the transformed $R, T$, scaled intrinsics, new dimensions, and image path.
3. **Process Points**: Extract $xyz$ coordinates and $rgb$ values from the 3D points dictionary. Normalize RGB values to $[0, 1]$ by dividing by 255.0.
4. **Subsample Points**: If the number of points exceeds `max_points`, randomly subsample the points to the limit. If not, use all points [S1, unofficial].

**Pseudocode:**
```python
import os
import torch
import numpy as np
from PIL import Image
from src.utils.read_write_model import read_model, qvec2rotmat

class CameraInfo:
    def __init__(self, R, T, fx, fy, cx, cy, width, height, image_path, image_name):
        self.R = R
        self.T = T
        self.fx = fx
        self.fy = fy
        self.cx = cx
        self.cy = cy
        self.width = width
        self.height = height
        self.image_path = image_path
        self.image_name = image_name

def fetch_scene_data(model_path, images_path, target_res=400, max_points=1000):
    # 1. Load COLMAP data
    cameras_extrinsic, images_intrinsic, points3D = read_model(path=model_path, ext=".bin")
    cam_infos = []

    # 2. Process each image
    for key in images_intrinsic:
        colmap_image = images_intrinsic[key]
        colmap_cam = cameras_extrinsic[colmap_image.camera_id]

        # 2a. Scale calculation
        orig_w = colmap_cam.width
        orig_h = colmap_cam.height
        scale = target_res / max(orig_w, orig_h)
        new_w = int(orig_w * scale)
        new_h = int(orig_h * scale)

        # 2b. Rotation and Translation with coordinate adjustment
        R = np.array(torch.from_numpy(qvec2rotmat(colmap_image.qvec)).float())
        T = np.array(torch.from_numpy(colmap_image.tvec).float())
        R[1:3, :] *= -1
        T[1:3] *= -1
        R = torch.from_numpy(R).float()
        T = torch.from_numpy(T).float()

        # 2c. Intrinsic scaling
        params = colmap_cam.params
        if colmap_cam.model == "PINHOLE":
            fx, fy, cx, cy = params[0] * scale, params[1] * scale, params[2] * scale, params[3] * scale
        elif colmap_cam.model == "SIMPLE_PINHOLE":
            fx = fy = params[0] * scale
            cx, cy = params[1] * scale, params[2] * scale
        else:
            # Fallback for other models
            fx = fy = params[0] * scale
            cx, cy = params[1] * scale, params[2] * scale

        img_path = os.path.join(images_path, colmap_image.name)
        
        cam_info = CameraInfo(R=R, T=T, fx=fx, fy=fy, cx=cx, cy=cy,
                              width=new_w, height=new_h,
                              image_path=img_path, image_name=colmap_image.name)
        cam_infos.append(cam_info)

    # 3. Process 3D Points
    xyz = np.array([p.xyz for p in points3D.values()])
    rgb = np.array([p.rgb for p in points3D.values()]) / 255.0

    # 4. Subsample if necessary
    if len(xyz) > max_points:
        indices = np.random.choice(len(xyz), max_points, replace=False)
        xyz = xyz[indices]
        rgb = rgb[indices]
    
    return cam_infos, xyz, rgb
```

**Edge Cases and Pitfalls:**
- **Coordinate System Mismatch**: Failing to negate Y and Z axes results in inverted camera orientations relative to the scene [S1, unofficial].
- **Intrinsic Scaling**: Intrinsics must be scaled by the same factor as the image dimensions to maintain correct projection geometry [S1, unofficial].
- **Hardware Limits**: Loading all points without subsampling can cause out-of-memory errors on GPUs with limited VRAM, hence the `max_points` guard [S1, unofficial].

## Subtopics

### [COLMAP Binary Model Parsing](3455-colmap-binary-model-parsing.md)
Parses COLMAP reconstruction files stored in binary format (`.bin`) into structured Python objects (`Camera`, `Image`, `Point3D`). It provides a memory-efficient alternative to text parsing for large-scale SfM/MVS datasets, serving as the primary data loading step in the [Scene Data Loading & Resizing](3420-scene-data-loading-resizing.md) pipeline.

### [OpenSfM Reconstruction Loader & Coordinate Transformation](6855-opensfm-reconstruction-loader-coordinate-transformation.md)
Loads camera poses, intrinsics, and point clouds from OpenSfM's reconstruction.json and image_list.txt, converts poses to OpenGL-compatible coordinate system, normalizes focal lengths, and applies auto-scaling/centering to the scene.

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of images and points, $O(N_{images} + N_{points})$, dominated by file I/O and numpy/torch operations [S1, unofficial].
- **Memory Complexity**: Proportional to the size of the loaded point cloud and image metadata. Subsampling limits the point cloud memory footprint to $O(max\_points)$ [S1, unofficial].
- **Strengths**: Handles heterogeneous camera models (PINHOLE, SIMPLE_PINHOLE) and automatically normalizes coordinate systems and resolutions [S1, unofficial].
- **Limitations**: Tightly coupled to COLMAP's binary format structure. Does not handle OpenSfM or other SfM outputs natively without adaptation [S1, unofficial].
- **When to use**: When preparing data for Gaussian Splatting or NeRF-based volume rendering pipelines that require normalized camera parameters and a dense but bounded point cloud [S1, unofficial].

## Background
This method originates from the `mini-splat` project, which implements a lightweight Gaussian Splatting pipeline. It addresses the need for robust data loading from SfM reconstructions, specifically handling the coordinate system conversion and resolution normalization required for differentiable rendering [S1, unofficial].
