# OpenSfM Reconstruction Loader & Coordinate Transformation

Also called: OpenSfM Data Reading, OpenSfM Pose and Point Cloud Loading

## Overview
This method loads camera poses, intrinsics, and 3D point clouds from OpenSfM's `reconstruction.json` and `image_list.txt`, converting them into a format suitable for volume rendering or neural rendering pipelines. It specifically handles the conversion from OpenSfM's native coordinate system to an OpenGL-compatible system, normalizes focal lengths based on image dimensions, and applies auto-scaling to center and normalize the scene scale. It differs from generic COLMAP loaders by handling OpenSfM's specific JSON structure and coordinate conventions.

## How it works
**Inputs:**
- `projectRoot`: Path to the OpenSfM project directory.
- `reconstruction.json`: OpenSfM's reconstruction file containing camera poses, intrinsics, and 3D points.
- `image_list.txt`: (Optional but typical) Maps image filenames to absolute paths.
- `projectionType`: String, must be `"perspective"` or `"brown"`.

**Outputs:**
- `InputData` struct containing:
  - `cameras`: List of `Camera` objects with intrinsics, distortion coefficients, and poses.
  - `points`: 3D point cloud with XYZ coordinates and RGB values.
  - `translation`: 3D vector representing the scene center offset.
  - `scale`: Float representing the normalization scale factor.

**Data Structures:**
- `Camera`:
  - `fx, fy`: Focal lengths (normalized).
  - `cx, cy`: Principal point (normalized).
  - `k1, k2, k3, p1, p2`: Distortion coefficients.
  - `R`: 3x3 rotation matrix.
  - `T`: 3x1 translation vector.
  - `imagePath`: String path to the image.
- `Point`:
  - `xyz`: 3D position.
  - `rgb`: 3-channel uint8 color.

**Steps:**

1. **Validation and Path Resolution:**
   - Verify `reconstruction.json` exists and contains at least one reconstruction.
   - Read `image_list.txt` to map relative filenames to absolute paths. If `image_list.txt` is missing, attempt to locate images using standard OpenSfM folder structures (`masks/`, `mask/`, etc.) and extensions (`.png`, `.jpg`, etc.) [S1, unofficial].

2. **Camera Pose Extraction and Coordinate Conversion:**
   - For each shot in the reconstruction:
     - Extract the rotation vector (Rodrigues format) and translation vector.
     - Convert the Rodrigues rotation vector to a 3x3 rotation matrix $R$ using the standard Rodrigues formula [S1, unofficial].
     - Construct the world-to-camera matrix $W2C$:
       $$
       W2C = \begin{bmatrix} R & T \\ 0 & 1 \end{bmatrix}
       $$
     - Invert $W2C$ to obtain the camera-to-world pose $C2W = W2C^{-1}$ [S1, unofficial].
     - **Coordinate System Conversion:** OpenSfM uses an OpenCV-like coordinate system (Z-forward, Y-down). Convert to OpenGL (Z-back, Y-up) by negating the Y and Z axes of the camera-to-world pose. Specifically, for the 3x3 rotation part of $C2W$:
       $$
       R_{OpenGL} = R_{OpenCV} \cdot \begin{bmatrix} 1 & 0 & 0 \\ 0 & -1 & 0 \\ 0 & 0 & -1 \end{bmatrix}
       $$
       And adjust the translation vector $T_{C2W}$ accordingly to maintain the transformation integrity [S1, unofficial].

3. **Auto-Scaling and Centering:**
   - Compute the bounding box of all camera positions and 3D points.
   - Calculate the scene center (mean of camera positions and points) and the scene scale (max distance from center to any camera/point).
   - Store the `translation` (scene center) and `scale` factors.
   - Apply inverse transformation to all camera positions and 3D points:
     $$
     P_{normalized} = (P_{original} - translation) \cdot scale
     $$
   - Apply the same transformation to camera poses [S1, unofficial].

4. **Intrinsic Normalization:**
   - For each camera, compute the normalizer:
     $$
     normalizer = \max(width, height)
     $$
   - Normalize focal lengths and principal points:
     $$
     fx_{norm} = \frac{fx_{raw}}{normalizer}, \quad fy_{norm} = \frac{fy_{raw}}{normalizer}
     $$
     $$
     cx_{norm} = \frac{cx_{raw}}{normalizer}, \quad cy_{norm} = \frac{cy_{raw}}{normalizer}
     $$
   - Store normalized intrinsics [S1, unofficial].

5. **Point Cloud Processing:**
   - Extract XYZ and RGB from the reconstruction.
   - Apply the inverse scale and translation:
     $$
     xyz_{final} = (xyz_{raw} - translation) \cdot scale
     $$
   - Store RGB as uint8 [S1, unofficial].

6. **Distortion Coefficients:**
   - Load $k1, k2, k3$ (radial) and $p1, p2$ (tangential) from the JSON.
   - If `projectionType` is not `"perspective"` or `"brown"`, throw a `runtime_error` [S1, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np

def rodrigues_to_rotation(rvec):
    """Convert Rodrigues vector to 3x3 rotation matrix."""
    theta = np.linalg.norm(rvec)
    if theta < 1e-10:
        return np.eye(3)
    r = rvec / theta
    r_x = np.array([[0, -r[2], r[1]],
                    [r[2], 0, -r[0]],
                    [-r[1], r[0], 0]])
    R = np.eye(3) + np.sin(theta) * r_x + (1 - np.cos(theta)) * np.dot(r_x, r_x)
    return R

    cameras = []
    points = []
    all_positions = []
    
    # 2. Process Cameras
    for shot_id, shot in recon_data['shots'].items():
        # Extract intrinsics
        cam_data = recon_data['cameras'][shot['camera']]
        fx = cam_data['focal']
        fy = cam_data['focal'] # OpenSfM often assumes square pixels
        cx = cam_data['cx']
        cy = cam_data['cy']
        width = cam_data['width']
        height = cam_data['height']
        
        # Distortion
        k1 = cam_data.get('k1', 0.0)
        k2 = cam_data.get('k2', 0.0)
        k3 = cam_data.get('k3', 0.0)
        p1 = cam_data.get('p1', 0.0)
        p2 = cam_data.get('p2', 0.0)
        
        # Extract pose
        rvec = np.array(shot['rotation'])
        tvec = np.array(shot['translation'])
        
        R = rodrigues_to_rotation(rvec)
        
        # World-to-Camera
        W2C = np.eye(4)
        W2C[:3, :3] = R
        W2C[:3, 3] = tvec
        
        # Camera-to-World
        C2W = np.linalg.inv(W2C)
        
        # Coordinate conversion: OpenCV (Z forward, Y down) -> OpenGL (Z back, Y up)
        # Negate Y and Z axes of the camera pose
        C2W[0, 3] = C2W[0, 3] # X unchanged
        C2W[1, 3] = -C2W[1, 3] # Y inverted
        C2W[2, 3] = -C2W[2, 3] # Z inverted
        
        # Negate Y and Z in rotation matrix columns
        C2W[:3, 1] = -C2W[:3, 1]
        C2W[:3, 2] = -C2W[:3, 2]
        
        all_positions.append(C2W[:3, 3])
        
        # Store raw camera data for scaling
        cameras.append({
            'id': shot_id,
            'R_raw': C2W[:3, :3],
            'T_raw': C2W[:3, 3],
            'fx': fx, 'fy': fy, 'cx': cx, 'cy': cy,
            'width': width, 'height': height,
            'k1': k1, 'k2': k2, 'k3': k3, 'p1': p1, 'p2': p2,
            'image_path': shot.get('image', '')
        })
    
    # 3. Process Points
    for pid, point in recon_data['points'].items():
        xyz = np.array(point['xyz'])
        rgb = np.array(point['color'])
        points.append({'xyz': xyz, 'rgb': rgb})
        all_positions.append(xyz)
    
    # 4. Auto-Scaling
    all_positions = np.array(all_positions)
    center = np.mean(all_positions, axis=0)
    distances = np.linalg.norm(all_positions - center, axis=1)
    scale_factor = 1.0 / np.max(distances)
    
    translation = center
    scale = scale_factor
    
    # 5. Normalize and Store
    final_cameras = []
    for cam in cameras:
        # Transform pose
        R_final = cam['R_raw'] * scale
        T_final = (cam['T_raw'] - translation) * scale
        
        # Normalize intrinsics
        normalizer = max(cam['width'], cam['height'])
        fx_norm = cam['fx'] / normalizer
        fy_norm = cam['fy'] / normalizer
        cx_norm = cam['cx'] / normalizer
        cy_norm = cam['cy'] / normalizer
        
        final_cameras.append({
            'R': R_final,
            'T': T_final,
            'fx': fx_norm,
            'fy': fy_norm,
            'cx': cx_norm,
            'cy': cy_norm,
            'k1': cam['k1'],
            'k2': cam['k2'],
            'k3': cam['k3'],
            'p1': cam['p1'],
            'p2': cam['p2'],
            'image_path': cam['image_path']
        })
        
    final_points = []
    for pt in points:
        xyz_final = (pt['xyz'] - translation) * scale
        final_points.append({'xyz': xyz_final, 'rgb': pt['rgb']})
        
    return {
        'cameras': final_cameras,
        'points': final_points,
        'translation': translation,
        'scale': scale
    }
```

**Edge Cases and Pitfalls:**
- **Missing Image List:** If `image_list.txt` is absent, the loader must fallback to heuristic path resolution, which may fail if images are in non-standard locations [S1, unofficial].
- **Degenerate Rotation:** If the rotation vector norm is near zero, the Rodrigues conversion must handle the identity matrix case to avoid division by zero [S1, unofficial].
- **Coordinate System Mismatch:** Failing to negate Y and Z axes results in inverted camera orientations and incorrect volume rendering [S1, unofficial].
- **Projection Type:** The loader expects `"perspective"` or `"brown"`. Other types will cause a runtime error [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of cameras and points $O(N_c + N_p)$.
- **Memory Complexity:** Linear with respect to the number of cameras and points.
- **Strengths:** Handles OpenSfM's specific JSON structure and coordinate system automatically. Normalizes scene scale for numerical stability.
- **Limitations:** Requires `reconstruction.json` to be present. Auto-scaling may distort relative scales if the scene is not well-centered.
- **When to use:** When working with OpenSfM outputs and needing OpenGL-compatible poses.
- **When not to use:** When using COLMAP or NerfStudio formats directly (use sibling loaders).

## Background
OpenSfM is an open-source Structure-from-Motion library. The loader is part of the OpenSplat pipeline, which supports multiple SfM backends. The coordinate transformation is necessary because OpenSfM uses a right-handed coordinate system with Z-forward and Y-down (similar to OpenCV), while many rendering engines (like OpenGL-based ones) use Z-back and Y-up.
