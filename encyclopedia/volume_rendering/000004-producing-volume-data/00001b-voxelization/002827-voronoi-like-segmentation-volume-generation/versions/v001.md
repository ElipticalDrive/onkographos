# Voronoi-like Segmentation Volume Generation

Also called: Synthetic Segmentation Volume Generation, Voronoi-like volume creation

## Overview
Generates a 3D volume where each voxel is assigned the label of its nearest neighbor in a Poisson-disk-like point set [S1, unofficial]. It solves the problem of creating synthetic, spatially distributed segmentation masks for volume rendering or procedural generation [S1, unofficial]. It differs from standard voxelization by not mapping geometric primitives to occupancy, but rather by distributing seed points and assigning voxels based on proximity [S1, unofficial].

## How it works
**Inputs:**
- Grid dimensions: $W, H, D$ (width, height, depth in voxels).
- `points_per_million_voxels`: Density of seed points (default: 100) [S1, unofficial].
- `candidate_count`: Number of random candidates per seed point (default: 16) [S1, unofficial].

**Outputs:**
- `m_data`: A 1D array of size $W \times H \times D$ storing integer labels (indices of the nearest seed point) [S1, unofficial].

**Data Structures:**
- `points`: A list of 3D coordinates $(x, y, z)$ representing the generated seed points.
- `m_data`: Array indexed by $z \cdot (W \cdot H) + y \cdot W + x$ [S1, unofficial].

**Steps:**

1.  **Calculate Point Count:**
    $$ N_{points} = \left\lfloor \frac{W \cdot H \cdot D}{1,000,000} \cdot \text{points\_per\_million\_voxels} \right\rfloor $$
    [S1, unofficial]

2.  **Generate Poisson-like Point Set:**
    Initialize `points` as empty. For $i$ from $0$ to $N_{points} - 1$:
    a. Initialize `max_min_dist_sq` to $-\infty$ and `best_candidate` to null.
    b. Repeat `candidate_count` times:
       i. Generate random candidate $c = (x_c, y_c, z_c)$ where $x_c \in [0, W), y_c \in [0, H), z_c \in [0, D)$ [S1, unofficial].
       ii. Compute squared distance $d^2$ from $c$ to all existing points $p \in \text{points}$ (for $p < i$).
       iii. Find $d_{min}^2 = \min_{p} (d^2)$.
       iv. If $d_{min}^2 > \text{max\_min\_dist\_sq}$, set `max_min_dist_sq` = $d_{min}^2$ and `best_candidate` = $c$.
    c. Add `best_candidate` to `points`.
    [S1, unofficial]

3.  **Assign Voxel Labels:**
    For each voxel $(x, y, z)$:
    a. Initialize `min_dist_sq` to $\infty$ and `nearest_idx` to $-1$.
    b. For each point $p_j$ in `points` with index $j$:
       i. Compute squared Euclidean distance $d^2 = (x - p_j.x)^2 + (y - p_j.y)^2 + (z - p_j.z)^2$.
       ii. If $d^2 < \text{min\_dist\_sq}$, set `min_dist_sq` = $d^2$ and `nearest_idx` = $j$.
    c. Set `m_data[z * (W * H) + y * W + x]` = `nearest_idx` [S1, unofficial].

**Pseudocode:**
```python
def generate_voronoi_volume(W, H, D, points_per_million=100, candidate_count=16):
    # Step 1: Calculate point count
    total_voxels = W * H * D
    num_points = int((total_voxels / 1_000_000.0) * points_per_million)
    
    points = []
    
    # Step 2: Generate Poisson-like point set
    for i in range(num_points):
        max_min_dist_sq = -1.0
        best_candidate = None
        
        for _ in range(candidate_count):
            # Generate random candidate within bounds
            cx = random.uniform(0, W)
            cy = random.uniform(0, H)
            cz = random.uniform(0, D)
            
            # Compute min squared distance to existing points
            min_dist_sq = float('inf')
            for p in points:
                dx = cx - p[0]
                dy = cy - p[1]
                dz = cz - p[2]
                dist_sq = dx*dx + dy*dy + dz*dz
                if dist_sq < min_dist_sq:
                    min_dist_sq = dist_sq
            
            if min_dist_sq > max_min_dist_sq:
                max_min_dist_sq = min_dist_sq
                best_candidate = (cx, cy, cz)
        
        points.append(best_candidate)
    
    # Step 3: Assign voxel labels
    m_data = [0] * total_voxels
    
    for z in range(D):
        for y in range(H):
            for x in range(W):
                min_dist_sq = float('inf')
                nearest_idx = -1
                
                for j, p in enumerate(points):
                    dx = x - p[0]
                    dy = y - p[1]
                    dz = z - p[2]
                    dist_sq = dx*dx + dy*dy + dz*dz
                    
                    if dist_sq < min_dist_sq:
                        min_dist_sq = dist_sq
                        nearest_idx = j
                
                idx = z * (W * H) + y * W + x
                m_data[idx] = nearest_idx
                
    return m_data
```
[S1, unofficial]

**Edge Cases and Pitfalls:**
- **Performance:** The point generation step is $O(N_{points}^2 \cdot \text{candidate\_count})$ due to nearest neighbor checks against all previous points. The label assignment is $O(W \cdot H \cdot D \cdot N_{points})$ [S1, unofficial].
- **Acceleration:** For large volumes, an acceleration structure (e.g., KD-tree) is required for nearest neighbor searches, as the naive approach is prohibitively slow [S1, unofficial].
- **Boundaries:** Candidates are generated in $[0, W), [0, H), [0, D)$. Voxel indices are integers. The mapping assumes continuous coordinates for point generation and discrete for voxel assignment [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N_{points}^2 \cdot C + V \cdot N_{points})$ where $N_{points}$ is the number of seed points, $C$ is `candidate_count`, and $V$ is the total voxel count [S1, unofficial].
- **Memory Complexity:** $O(V + N_{points})$ for storing the volume data and the point set [S1, unofficial].
- **Performance:** The naive implementation is extremely slow for large volumes (e.g., $1000^3$ voxels) due to the $O(V \cdot N_{points})$ label assignment and $O(N_{points}^2)$ point generation [S1, unofficial].
- **Strengths:** Simple to implement; produces spatially distributed, non-overlapping regions [S1, unofficial].
- **Limitations:** Poor scalability; no acceleration structure in the basic method; discrete labels only [S1, unofficial].
- **When to use:** Small volumes or prototyping where performance is not critical [S1, unofficial].
- **When not to use:** Large-scale volumes or real-time applications [S1, unofficial].
