# Per-Pixel Linked List Voxelization

Also called: A-Buffer Ray Intersection List, ABuffer Voxel Output Representation & Traversal, Atomic Counter Voxelization, Linked List Voxel Output, Shader Storage Buffer Object Linked List Voxelization

## Overview
Per-Pixel Linked List Voxelization is a GPU-based technique that constructs a linked list of fragment depths per pixel using atomic counters and shader storage buffers, allowing for subsequent sorting and processing of depth-sorted voxels [S1, unofficial]. It differs from rasterization-based voxelization by explicitly managing overlapping geometry per pixel via dynamic linked lists rather than fixed-depth buffers or conservative rasterization rules, and it avoids the memory overhead of full A-Buffer color/depth textures by using compact integer arrays [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: A mesh (vertices, triangles) in model space, a model-to-clip transformation matrix, and framebuffer dimensions (width, height).
- Output: A `Voxelizer_ABufferLinkedList` structure containing `headPointers`, `nodePointers`, and `nodeData` arrays, representing the sorted voxel depths per pixel.

**Data structures:**
Three Shader Storage Buffer Objects (SSBOs) are used, bound at specific locations:
1.  `HeadPointers` (binding 1, `std430`): An array of `int` of size `width * height`. Each element stores the index of the first node in the linked list for the corresponding pixel. Initialized to `-1`.
2.  `NodePointers` (binding 2, `std430`): An array of `int` of size `maxFragments`. Each element stores the index of the next node in the linked list.
3.  `NodeData` (binding 3, `std430`): An array of `int` of size `maxFragments`. Each element stores the depth of the fragment, scaled by `framebufferWidth`.

A global atomic counter (`counter`, binding 0) is used to generate unique indices for each fragment.

**Parameters:**
- `framebufferWidth`: Uniform integer, the width of the framebuffer.
- `counter`: Atomic unsigned integer, initialized to 0.
- `maxFragments`: The maximum number of fragments the system can handle. The sorting algorithm uses a safety limit of 1024 iterations per list traversal to prevent infinite loops [S1, unofficial].

**Steps:**

1.  **Fragment Counting (Optional but implied by structure):**
    The source code includes a `FragCount.frag` shader that increments the atomic counter for each fragment to determine the total fragment count, which is used to allocate the `nodeData` and `nodePointers` arrays. This step is not strictly part of the linked list construction but is necessary for memory allocation.

2.  **Make Fragment List:**
    For each fragment generated by rasterizing the mesh:
    a.  Increment the global atomic counter to get a unique index `ucount`.
    b.  Calculate the head pointer index for the current pixel using fragment coordinates: `headPointerIndex = int(gl_FragCoord.x) + int(gl_FragCoord.y) * framebufferWidth`.
    c.  Atomically exchange the current head pointer value with the new fragment index to link the new node to the existing list: `prevPtr = atomicExchange(HeadPointers[headPointerIndex], count)`.
    d.  Set the next pointer of the new node to the previous head pointer: `NodePointers[count] = prevPtr`.
    e.  Store the depth data in the new node, scaled by framebuffer width: `NodeData[count] = int(depth * framebufferWidth)`.

3.  **Sort Fragment List:**
    For each pixel (processed via a screen quad):
    a.  Calculate the head pointer index: `headPointerIndex = int(gl_FragCoord.x) + int(gl_FragCoord.y) * framebufferWidth`.
    b.  Retrieve the head pointer: `headPtr = HeadPointers[headPointerIndex]`.
    c.  If `headPtr == -1`, discard the fragment (no nodes to sort).
    d.  Initialize the outer loop pointer to the head of the list: `outerPtr = headPtr`.
    e.  Iterate through the linked list using an outer loop with a safety counter (max 1024 iterations) to prevent infinite loops.
    f.  Inside the outer loop, initialize `smallestPtr` to `outerPtr` and `smallestData` to `NodeData[smallestPtr]`.
    g.  Initialize `innerPtr` to `NodePointers[outerPtr]`.
    h.  Iterate through the rest of the list using an inner loop with a safety counter (max 1024 iterations) to find the node with the smallest data value.
    i.  Inside the inner loop, if `NodeData[innerPtr] < smallestData`, update `smallestPtr` and `smallestData`.
    j.  Advance `innerPtr` to `NodePointers[innerPtr]`.
    k.  After the inner loop, if `smallestPtr != outerPtr`, swap `NodeData[smallestPtr]` and `NodeData[outerPtr]`.
    l.  Advance `outerPtr` to `NodePointers[outerPtr]`.

4.  **Traversal:**
    To access the sorted voxels for a pixel `(i, j)`:
    a.  Read the starting node index: `curPtr = headPointers[i + j * width]`.
    b.  The interval `[startVoxel, endVoxel)` represents the contiguous filled voxels along the ray for pixel `(i, j)`.
    c.  Advance the pointer by two hops: `curPtr = nodePointers[nodePointers[curPtr]]` (Note: This specific traversal logic is mentioned in the notes but the exact usage context is not fully detailed in the provided code snippets; it likely refers to a specific optimization or access pattern).

```python
# Initialization
HeadPointers = [-1] * (width * height)
NodePointers = [0] * maxFragments
NodeData = [0] * maxFragments
atomicCounter = 0

# Step 2: Make Fragment List (Fragment Shader)
def make_frag_list(depth, fragCoordX, fragCoordY):
    global atomicCounter
    ucount = atomicCounter
    atomicCounter += 1
    count = ucount
    
    headPointerIndex = fragCoordX + fragCoordY * framebufferWidth
    
    # Atomic exchange: set HeadPointers[headPointerIndex] to count, return old value
    prevPtr = HeadPointers[headPointerIndex]
    HeadPointers[headPointerIndex] = count
    
    NodePointers[count] = prevPtr
    NodeData[count] = int(depth * framebufferWidth)

# Step 3: Sort Fragment List (Fragment Shader for screen quad)
def sort_frag_list(fragCoordX, fragCoordY):
    headPointerIndex = fragCoordX + fragCoordY * framebufferWidth
    headPtr = HeadPointers[headPointerIndex]
    
    if headPtr == -1:
        return # Discard
    
    outerPtr = headPtr
    for _ in range(1024): # Safety limit
        if outerPtr == -1:
            break
            
        smallestPtr = outerPtr
        smallestData = NodeData[smallestPtr]
        
        innerPtr = NodePointers[outerPtr]
        for _ in range(1024): # Safety limit
            if innerPtr == -1:
                break
                
            innerData = NodeData[innerPtr]
            if innerData < smallestData:
                smallestPtr = innerPtr
                smallestData = innerData
                
            innerPtr = NodePointers[innerPtr]
            
        if smallestPtr != outerPtr:
            NodeData[smallestPtr] = NodeData[outerPtr]
            NodeData[outerPtr] = smallestData
            
        outerPtr = NodePointers[outerPtr]

# Step 4: Traversal
def traverse_pixel(i, j):
    curPtr = HeadPointers[i + j * width]
    while curPtr != -1:
        # Process NodeData[curPtr] as depth
        curPtr = NodePointers[curPtr]
```

## Operating characteristics
- **Time Complexity:** The sorting step is $O(N^2)$ in the worst case for a single pixel with $N$ fragments, due to the selection sort implementation. However, the safety limit of 1024 iterations caps the worst-case performance per pixel.
- **Memory Complexity:** $O(W \times H + F)$, where $W$ and $H$ are framebuffer dimensions and $F$ is the total number of fragments.
- **Strengths:** Handles overlapping geometry correctly per pixel. Efficient use of GPU parallelism for fragment processing.
- **Limitations:** Sorting is computationally expensive for pixels with many overlapping fragments. The fixed-size arrays require pre-allocation based on an estimate of fragment count.
- **When to use:** When accurate depth sorting of overlapping geometry is required per pixel, and the number of fragments per pixel is not excessively large.
- **When not to use:** For scenes with very high overdraw per pixel, where the $O(N^2)$ sorting becomes a bottleneck.
