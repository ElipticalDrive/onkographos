# Voxel Filtering

Also called: Voxel Predicate Filter

## Overview
Voxel Filtering iterates over a voxel grid to identify and return the linear indices of voxels that satisfy a user-defined predicate function [S1, unofficial]. It solves the problem of isolating relevant data from a dense grid, serving as a foundational step for sparse rendering or processing. It differs from its parent [Voxel Filled Check](1705-voxel-filled-check.md) by supporting arbitrary boolean conditions rather than simple occupancy checks, and from [Voxel Material Classification](3645-voxel-material-classification.md) by returning indices rather than class labels.

## How it works
**Inputs:**
- `grid`: A 3D array of voxel data (e.g., `CellType`).
- `predicate`: A callable function `func(cell) -> bool` that evaluates a single voxel [S1, unofficial].

**Outputs:**
- `indices`: A list of linear indices (integers) corresponding to voxels where `predicate` returns true [S1, unofficial].

**Data Structures:**
- The grid is treated as a contiguous array of size $N$. Linear index $i$ maps to 3D coordinates $(x, y, z)$ via standard row-major or column-major ordering depending on the implementation, but the algorithm operates on linear indices directly [S1, unofficial].

**Steps:**
1. Initialize an empty list `output_indices`.
2. Iterate $i$ from $0$ to $N-1$, where $N$ is the total number of voxels in the grid.
3. For each $i$, retrieve the voxel data `cell` at index $i$.
4. Evaluate `result = predicate(cell)`.
5. If `result` is true, append $i$ to `output_indices`.
6. Return `output_indices`.

**Pseudocode:**
```python
def voxel_filter(grid, predicate):
    """
    Returns linear indices of voxels satisfying the predicate.
    
    Args:
        grid: List or array of voxel data.
        predicate: Function taking a voxel and returning a boolean.
        
    Returns:
        List of integer indices.
    """
    output_indices = []
    n = len(grid)
    for i in range(n):
        cell = grid[i]
        if predicate(cell):
            output_indices.append(i)
    return output_indices
```

**Parameters:**
- `predicate`: A callable that takes a single voxel (CellType) as input and returns a boolean indicating whether the voxel satisfies the condition [S1, unofficial].

**Edge Cases and Pitfalls:**
- If the grid is empty, the function returns an empty list.
- The predicate must be deterministic and side-effect-free to ensure consistent results across parallel implementations.
- Precision issues in the predicate evaluation (e.g., floating-point comparisons) may lead to inconsistent filtering if thresholds are not handled carefully [G].

## Subtopics

### [Sample Uniform and Occupied Cells](4651-sample-uniform-and-occupied-cells.md)
This method generates a mixed set of voxel indices for volume rendering by combining uniformly sampled cells with cells known to be occupied by geometry. It filters out cells with invalid density values (specifically -1). It is chosen when adaptive sampling is needed to balance coverage of empty space and detail in occupied regions. Link: [Sample Uniform and Occupied Cells](4651-sample-uniform-and-occupied-cells.md).

### [Volume Subset Extraction](5602-volume-subset-extraction.md)
Volume Subset Extraction reduces a dense 3D voxel grid to a sparse list of significant voxels by applying a user-defined predicate, typically based on a transfer function. It solves the problem of rendering or processing large volumes by discarding empty or irrelevant data, enabling efficient splat-based rendering. It differs from [Voxel Filtering](4035-voxel-filtering.md) by specifically organizing the output into a 2D array of splat rows for rasterization, and from [Sample Uniform and Occupied Cells](4651-sample-uniform-and-occupied-cells.md) by using continuous transfer function evaluation rather than simple occupancy checks. Link: [Volume Subset Extraction](5602-volume-subset-extraction.md).

### [Empty-Brick Threshold Calculation](8812-empty-brick-threshold-calculation.md)
Computes the voxel intensity threshold below which a volume brick is considered empty and can be skipped during streaming. It determines a static cutoff value based on metadata and channel windows, enabling the renderer to avoid loading or processing bricks that contain no relevant data. Link: [Empty-Brick Threshold Calculation](8812-empty-brick-threshold-calculation.md).

#### Grid Homogenization
Sets all non-empty voxels to `VOXEL_FREE`, effectively removing fragment IDs and marking all occupied space as free. It is used to reset voxel states for re-processing or to clear fragment metadata without altering the grid structure. Steps: Iterate over all voxels. If a voxel is not `VOXEL_EMPTY`, set its value to `VOXEL_FREE`. Link: [Grid Homogenization](8812-empty-brick-threshold-calculation.md) (Note: No separate article exists; this is a minor variant).

## Operating characteristics
**Time Complexity:** $O(N)$, where $N$ is the total number of voxels, as every voxel must be visited to evaluate the predicate [S1, unofficial].
**Memory Complexity:** $O(K)$, where $K$ is the number of voxels satisfying the predicate, for the output list. The input grid is read-only.
**Measured Performance:** Not given in the sources.
**Scaling:** Performance scales linearly with grid size. Parallelization is straightforward as each voxel evaluation is independent.
**Strengths:** Simple, flexible, and allows arbitrary conditions.
**Limitations:** Requires full grid traversal, which can be expensive for very large volumes if the predicate is complex or if few voxels satisfy it.
**When to use:** When a sparse subset of voxels needs to be identified based on custom criteria.
**When not to use:** When the grid is extremely large and most voxels are empty; consider hierarchical structures or [Empty-Brick Threshold Calculation](8812-empty-brick-threshold-calculation.md) for skipping large empty regions.

## Background
Voxel Filtering is a general technique used in volume rendering and voxel-based graphics to isolate relevant data. The specific implementation described here is found in the 3DGS-FLoD project, which uses it for pruning and densification steps in 3D Gaussian Splatting optimization [S1, unofficial]. Grid Homogenization is used in VoxelFragmentML for managing voxel states [S2, unofficial].
