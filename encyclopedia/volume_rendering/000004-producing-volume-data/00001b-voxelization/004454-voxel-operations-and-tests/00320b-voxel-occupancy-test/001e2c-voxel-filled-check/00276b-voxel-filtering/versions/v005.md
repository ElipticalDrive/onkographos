# Voxel Filtering

Also called: Voxel Predicate Filter

## Overview
Voxel Filtering iterates over a voxel grid to identify and return the linear indices of voxels that satisfy a user-defined predicate function [S1, unofficial]. It solves the problem of isolating relevant data from a dense grid, serving as a general-purpose selection mechanism for subsequent rendering or processing steps [S1, unofficial]. Unlike [Voxel Filled Check](1705-voxel-filled-check.md), which typically returns a boolean status for a single voxel or a simple occupancy mask, Voxel Filtering produces a list of indices for all matching voxels, enabling batch processing of non-empty or significant cells [S1, unofficial].

## How it works
**Inputs:**
- `grid`: A 1D array or contiguous memory block representing the voxel grid. The layout is linear, mapping 3D coordinates $(x, y, z)$ to a linear index $i$.
- `predicate`: A callable function `func(cell)` that takes a single voxel's data (referred to as `CellType` in sources) as input and returns a boolean value [S1, unofficial].

**Outputs:**
- `indices`: A list or vector of linear indices corresponding to voxels where `predicate` returns `True` [S1, unofficial].

**Data Structures:**
- The grid is assumed to be stored in a linear array. The mapping from 3D coordinates $(x, y, z)$ to linear index $i$ is not explicitly defined in the sources, but standard row-major or column-major ordering is implied by the iteration order [S1, unofficial].
- The output is a dynamic list of integers.

**Steps:**
1. Initialize an empty output vector `indices`.
2. Determine the total number of voxels $N$ in the grid.
3. Loop over all elements in the data array from index $i = 0$ to $N-1$:
   a. Retrieve the voxel data `cell` at index $i$.
   b. Evaluate `result = predicate(cell)`.
   c. If `result` is `True`, append $i$ to `indices`.
4. Return `indices` [S1, unofficial].

**Pseudocode:**
```python
def voxel_filtering(grid, predicate):
    """
    Filters voxels based on a user-defined predicate.
    
    Args:
        grid: List or array of voxel data.
        predicate: Function that takes a voxel and returns True/False.
        
    Returns:
        List of linear indices of voxels satisfying the predicate.
    """
    indices = []
    # Determine grid size. In a real implementation, this might be grid.shape[0]
    # or derived from 3D dimensions.
    size = len(grid) 
    
    for i in range(size):
        cell = grid[i]
        if predicate(cell):
            indices.append(i)
            
    return indices
```

**Parameters:**
- `predicate`: A callable that defines the filtering condition. Typical predicates include checking for non-zero density, specific material IDs, or opacity thresholds [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Empty Grid:** If the grid is empty, the function returns an empty list.
- **No Matches:** If no voxels satisfy the predicate, the function returns an empty list.
- **Predicate Cost:** If the predicate is computationally expensive, this method may become a bottleneck as it evaluates the predicate for every voxel in the grid [S1, unofficial].

## Subtopics

### [Sample Uniform and Occupied Cells](4651-sample-uniform-and-occupied-cells.md)
This method generates a mixed set of voxel indices by combining uniformly sampled cells with cells known to be occupied by geometry. It filters out cells with invalid density values (specifically -1). It is chosen when a renderer needs to balance coverage of empty space with detail in occupied regions.

### [Volume Subset Extraction](5602-volume-subset-extraction.md)
Volume Subset Extraction reduces a dense 3D voxel grid to a sparse list of significant voxels by applying a user-defined predicate, typically based on a transfer function. It differs from Voxel Filtering by specifically organizing the output into a 2D array of splat rows for rasterization, and from Sample Uniform and Occupied Cells by using continuous transfer function evaluation rather than simple occupancy checks. It is chosen for efficient splat-based rendering of large volumes.

### [Empty-Brick Threshold Calculation](8812-empty-brick-threshold-calculation.md)
Computes the voxel intensity threshold below which a volume brick is considered empty and can be skipped during streaming. It determines a static cutoff value based on metadata and channel windows, enabling the renderer to avoid loading or processing bricks that contain no relevant data. It is chosen for optimizing streaming performance in large volume datasets.

### [Connected Component Labeling for Voxel Filtering](14971-connected-component-labeling-for-voxel-filtering.md)
Connected Component Labeling (CCL) for Voxel Filtering identifies and retains only the largest connected components of occupied voxels in a 3D boolean grid, filtering out small noise or isolated artifacts. It operates by performing a flood-fill traversal with a configurable neighborhood distance, enforcing spherical connectivity within cubic bounds to determine adjacency. Unlike sibling methods that sample uniformly or extract arbitrary subsets, this method specifically targets topological coherence, making it suitable for cleaning sparse voxel representations where small disconnected clusters represent noise rather than signal.

### Grid Homogenization
Sets all non-empty voxels to `VOXEL_FREE`, effectively removing fragment IDs and marking all occupied space as free [S2, unofficial]. It iterates over all voxels and, if a voxel is not `VOXEL_EMPTY`, sets its value to `VOXEL_FREE` [S2, unofficial]. This is used to reset voxel states after processing, ensuring no residual fragment data interferes with subsequent operations [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the total number of voxels in the grid, as every voxel must be visited and evaluated [S1, unofficial].
- **Memory Complexity:** $O(K)$, where $K$ is the number of voxels satisfying the predicate, for storing the output indices [S1, unofficial].
- **Strengths:** Simple to implement, flexible via the predicate function, and effective for general-purpose filtering [S1, unofficial].
- **Limitations:** Inefficient for very large grids if the predicate is complex or if the output list is very large, as it requires full traversal [S1, unofficial].
- **When to Use:** When a general selection of voxels based on arbitrary criteria is needed, or as a preprocessing step for more specialized methods [S1, unofficial].
- **When Not to Use:** When the grid is extremely large and sparse, and a sparse data structure (like a hash map or octree) is already available, as iterating over the dense grid is wasteful [S1, unofficial].

## Background
Voxel Filtering is a fundamental operation in voxel-based rendering pipelines, often used in conjunction with densification and pruning steps in 3D Gaussian Splatting variants [S1, unofficial]. The method is implemented in projects such as 3DGS-FLoD for managing voxel occupancy during optimization [S1, unofficial]. Grid Homogenization is used in voxel fragment processing pipelines to reset voxel states [S2, unofficial].
