# Connected Component Labeling for Voxel Filtering

Also called: CCL Voxel Filtering, Large Component Filtering, Max Connected Component Extraction

## Overview
Connected Component Labeling (CCL) for Voxel Filtering identifies and retains only the largest connected components of occupied voxels in a 3D boolean grid, filtering out small noise or isolated artifacts [S1, unofficial]. It operates by performing a flood-fill traversal with a configurable neighborhood distance, enforcing spherical connectivity within cubic bounds to determine adjacency [S1, unofficial]. Unlike sibling methods that sample uniformly or extract arbitrary subsets, this method specifically targets topological coherence, making it suitable for cleaning sparse voxel representations where small disconnected clusters represent noise rather than signal [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `voxels`, a boolean matrix of shape `[D, H, W]` representing the 3D voxel grid [S1, unofficial].
- Input: `distance`, an integer neighborhood radius for connectivity (default 3) [S1, unofficial].
- Input: `min_component_size`, an integer threshold for the minimum number of voxels required to retain a component (default 10) [S1, unofficial].
- Output: `filtered_voxels`, a boolean matrix of the same shape `[D, H, W]` containing only the retained large components [S1, unofficial].

**Data Structures:**
- `voxels_copy`: A boolean matrix of shape `[D, H, W]`, initialized as a copy of `voxels` [S1, unofficial]. Used to track visited status; a voxel is marked `False` once visited.
- `component`: A boolean matrix of shape `[D, H, W]`, initialized to all `False` [S1, unofficial]. Tracks the current connected component being explored.
- `stack`: A list of coordinates `[x, y, z]` used for depth-first traversal [S1, unofficial].
- `component_list`: A list of `component` matrices, storing all identified connected components [S1, unofficial].
- `max_component`: A boolean matrix of shape `[D, H, W]`, initialized to all `False` [S1, unofficial]. Accumulates the final filtered result.

**Steps:**
1. Assert `distance > 0` [S1, unofficial].
2. Initialize `voxels_copy` as a deep copy of the input `voxels` [S1, unofficial].
3. Initialize `component_list` as an empty list [S1, unofficial].
4. Iterate over all grid positions `(startx, starty, startz)` in the dimensions of `voxels` [S1, unofficial].
5. If `voxels_copy[startx, starty, startz]` is `False`, continue to the next position [S1, unofficial].
6. Initialize `component` as a zeroed boolean matrix of shape `[D, H, W]` [S1, unofficial].
7. Initialize `stack` with `[startx, starty, startz]` [S1, unofficial].
8. Mark `component[startx, starty, startz]` as `True` [S1, unofficial].
9. Mark `voxels_copy[startx, starty, startz]` as `False` to indicate it has been visited [S1, unofficial].
10. While `stack` is not empty:
    a. Pop `(x, y, z)` from `stack` [S1, unofficial].
    b. Retrieve the category/value of the voxel at `(x, y, z)` from the original `voxels` grid [S1, unofficial].
    c. Iterate through neighbor coordinates `(i, j, k)` in the cubic range `[x-distance, x+distance]` for all three axes (inclusive) [S1, unofficial].
    d. Calculate the squared Euclidean distance: $d^2 = (i-x)^2 + (j-y)^2 + (k-z)^2$ [S1, unofficial].
    e. If $d^2 > distance^2$, skip this neighbor [S1, unofficial].
    f. Check if `(i, j, k)` is within grid bounds and `voxels_copy[i, j, k]` is `True` (occupied and unvisited) [S1, unofficial].
    g. Check if the category/value of `voxels[i, j, k]` matches the category/value of `voxels[x, y, z]` [S1, unofficial].
    h. If both conditions are met:
        i. Mark `component[i, j, k]` as `True` [S1, unofficial].
        ii. Mark `voxels_copy[i, j, k]` as `False` [S1, unofficial].
        iii. Push `(i, j, k)` to `stack` [S1, unofficial].
11. After the stack is empty, append `component` to `component_list` [S1, unofficial].
12. Initialize `max_component` as a zeroed boolean matrix of shape `[D, H, W]` [S1, unofficial].
13. Iterate through each `component` in `component_list`:
    a. Calculate the size of the component: $size = \sum component$ (sum of `True` values) [S1, unofficial].
    b. If $size > min\_component\_size$, perform a logical OR with `max_component`: $max\_component = max\_component \lor component$ [S1, unofficial].
14. Return `max_component` as the filtered voxel grid [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def connected_component_labeling_filter(voxels, distance=3, min_component_size=10):
    """
    Filters a 3D boolean voxel grid by retaining only large connected components.
    
    Args:
        voxels (np.ndarray): Boolean array of shape (D, H, W).
        distance (int): Neighborhood radius for connectivity.
        min_component_size (int): Minimum voxel count to retain a component.
        
    Returns:
        np.ndarray: Filtered boolean array of shape (D, H, W).
    """
    if distance <= 0:
        raise ValueError("Distance must be greater than 0")
        
    # Copy input to track visited status
    voxels_copy = np.copy(voxels)
    component_list = []
    D, H, W = voxels.shape
    
    # Iterate over all voxels to find connected components
    for startx in range(D):
        for starty in range(H):
            for startz in range(W):
                # Skip if already visited or empty
                if not voxels_copy[startx, starty, startz]:
                    continue
                
                # Initialize new component and stack
                component = np.zeros((D, H, W), dtype=bool)
                stack = [[startx, starty, startz]]
                
                # Mark start node
                component[startx, starty, startz] = True
                voxels_copy[startx, starty, startz] = False
                
                # Get category of the starting voxel for consistency check
                start_category = voxels[startx, starty, startz]
                
                # Flood fill
                while len(stack) > 0:
                    x, y, z = stack.pop()
                    
                    # Define neighbor range based on distance
                    x_min = max(0, x - distance)
                    x_max = min(D, x + distance + 1)
                    y_min = max(0, y - distance)
                    y_max = min(H, y + distance + 1)
                    z_min = max(0, z - distance)
                    z_max = min(W, z + distance + 1)
                    
                    for i in range(x_min, x_max):
                        for j in range(y_min, y_max):
                            for k in range(z_min, z_max):
                                # Calculate squared Euclidean distance
                                dist_sq = (i - x)**2 + (j - y)**2 + (k - z)**2
                                
                                # Enforce spherical connectivity
                                if dist_sq > distance * distance:
                                    continue
                                
                                # Check bounds (already handled by range limits)
                                # Check if occupied and unvisited in copy
                                if voxels_copy[i, j, k]:
                                    # Check category consistency
                                    if voxels[i, j, k] == start_category:
                                        component[i, j, k] = True
                                        voxels_copy[i, j, k] = False
                                        stack.append([i, j, k])
                
                component_list.append(component)
    
    # Filter components by size
    max_component = np.zeros((D, H, W), dtype=bool)
    for component in component_list:
        if np.sum(component) > min_component_size:
            max_component = np.logical_or(max_component, component)
            
    return max_component
```

**Parameters:**
- `distance`: Integer, neighborhood radius for connectivity. Two blocks are connected if their squared Euclidean distance is $\le distance^2$ [S1, unofficial]. Default value is 3 [S1, unofficial].
- `min_component_size`: Integer, the minimum number of voxels required for a component to be retained. Default value is 10 [S1, unofficial].

**Edge Cases and Pitfalls:**
- The algorithm modifies `voxels_copy` in-place to prevent re-processing. If `voxels_copy` is not properly initialized as a copy, the original data may be corrupted or visited status may be lost [S1, unofficial].
- The neighbor check relies on bounds checking. If the grid boundaries are not handled correctly (e.g., negative indices or out-of-bounds access), errors will occur [S1, unofficial].
- The category/value check ensures that only voxels with the same semantic label are connected. If `voxels` contains multi-class data, this prevents merging distinct objects [S1, unofficial].
- The code snippet provided in the source cuts off before the final mask application, but the logic implies that `max_component` is the final output [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time Complexity: $O(D \cdot H \cdot W \cdot R^3)$, where $D, H, W$ are grid dimensions and $R$ is the `distance` radius. In the worst case, every voxel is visited, and for each, a cubic neighborhood of size $(2 \cdot distance + 1)^3$ is checked [S1, unofficial].
- Memory Complexity: $O(D \cdot H \cdot W \cdot C)$, where $C$ is the number of connected components. Each component is stored as a full boolean grid of the same size as the input [S1, unofficial]. This can be significant for large grids with many small components.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- The method scales linearly with the number of voxels but cubically with the neighborhood radius. For large `distance` values, performance degrades rapidly [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Effectively removes small noise and isolated artifacts. Configurable connectivity allows tuning for specific voxel resolutions [S1, unofficial].
- Limitations: High memory usage due to storing all components. Slow for large grids with many small components. The spherical connectivity check within a cubic range adds computational overhead [S1, unofficial].

**When to Use:**
- Use when the voxel grid contains significant noise or small disconnected artifacts that need to be removed while preserving the main object structure [S1, unofficial].
- Use when semantic consistency is required for connectivity (i.e., only voxels of the same class should be connected) [S1, unofficial].

**When Not to Use:**
- Do not use when memory is constrained, as storing all components requires significant RAM [S1, unofficial].
- Do not use when real-time performance is critical and the grid is large, due to the cubic neighborhood search [S1, unofficial].
