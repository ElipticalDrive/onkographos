# Volume Subset Extraction

Also called: Splat Subset Extraction, Volume Subset

## Overview
Volume Subset Extraction reduces a dense 3D voxel grid to a sparse set of voxels that satisfy a user-defined predicate, typically based on a transfer function evaluating density and gradient [S1, unofficial]. It solves the problem of rendering or processing large volumes by discarding empty or irrelevant voxels, storing the result as a 2D array of splat rows to enable efficient front-to-back or back-to-front traversal [S1, unofficial]. It differs from [Voxel Filtering](4035-voxel-filtering.md) by specifically structuring the output for splat-based rendering pipelines rather than returning a flat list of indices, and from [Sample Uniform and Occupied Cells](4651-sample-uniform-and-occupied-cells.md) by using a continuous transfer function threshold rather than simple occupancy checks [S1, unofficial].

## How it works
**Inputs:**
*   A 3D volume dataset defined on a regular grid.
*   A transfer function $t = F(V, p)$, where $V$ is the gradient vector and $p$ is the scalar density of a voxel [S1, unofficial].
*   A user-defined threshold $\tau$ [S1, unofficial].

**Outputs:**
*   A 2D array of splat rows. Each row corresponds to a specific depth or projection layer.
*   Each row contains a list of extracted voxels.
*   Each voxel stores its 3D location and normal vector [S1, unofficial].
*   Rows may contain different numbers of voxels; voxels within a row are not necessarily contiguous [S1, unofficial].

**Data Structure Layout:**
The subset is stored as a list of rows. Each row is a list of voxel records.
*   `Row`: List of `Voxel` objects.
*   `Voxel`: Struct containing:
    *   `location`: 3D coordinates $(x, y, z)$ [S1, unofficial].
    *   `normal`: 3D normal vector $(n_x, n_y, n_z)$ [S1, unofficial].
    *   *(Note: The source does not explicitly list density or gradient storage in the final subset, only location and normal, implying these are computed or passed during the splatting phase)* [S1, unofficial].

**Algorithm Steps:**
1.  Initialize an empty list of rows `Rows`.
2.  Determine the traversal order (front-to-back or back-to-front) based on the rendering or processing requirement [S1, unofficial].
3.  Iterate through all voxels in the volume grid according to the chosen traversal order.
4.  For each voxel at position $(x, y, z)$:
    a. Compute the gradient $V$ and density $p$ for the voxel [S1, unofficial].
    b. Evaluate the transfer function $t = F(V, p)$ [S1, unofficial].
    c. If $t > \tau$:
        i. Compute the normal vector $N$ for the voxel (method of computation not specified in source, assumed standard gradient-based normal) [G].
        ii. Create a `Voxel` record with `location` = $(x, y, z)$ and `normal` = $N$ [S1, unofficial].
        iii. Append the `Voxel` record to the appropriate row in `Rows` based on the traversal order (e.g., row index derived from depth) [S1, unofficial].
5.  Return `Rows` [S1, unofficial].

**Pseudocode:**
```python
def extract_volume_subset(volume, transfer_function, threshold, traversal_order='front_to_back'):
    """
    Extracts a subset of voxels from a 3D volume based on a transfer function threshold.
    
    Args:
        volume: 3D array of density values.
        transfer_function: Function F(V, p) returning a scalar t.
        threshold: Scalar threshold tau.
        traversal_order: 'front_to_back' or 'back_to_front'.
        
    Returns:
        rows: List of lists of Voxel dicts.
    """
    rows = []
    # Determine grid dimensions
    nx, ny, nz = volume.shape
    
    # Helper to get gradient V and density p
    # Note: Gradient computation method (e.g., central differences) is not specified in source [G]
    def get_voxel_properties(x, y, z):
        p = volume[x, y, z]
        # Compute gradient V from volume neighbors [G]
        V = compute_gradient(volume, x, y, z)
        return V, p

    # Helper to compute normal from gradient
    # Note: Normal computation is not specified in source [G]
    def compute_normal(V):
        return normalize(V)

    # Initialize rows based on traversal order
    # The source states rows are stored in a 2D array where each row contains extracted voxels.
    # The mapping of voxel to row index (e.g., by z-depth or projection) is implied but not detailed.
    # We assume a simple depth-based row assignment for front-to-back traversal.
    if traversal_order == 'front_to_back':
        depth_range = range(nz)
    else:
        depth_range = range(nz - 1, -1, -1)
        
    # Pre-allocate rows if possible, or use dynamic list
    # Source says "2D array of splat rows", but also "each row may contain a different numbers of voxels"
    # We use a list of lists.
    rows = [[] for _ in range(nz)]

    for z in depth_range:
        for y in range(ny):
            for x in range(nx):
                V, p = get_voxel_properties(x, y, z)
                t = transfer_function(V, p)
                if t > threshold:
                    normal = compute_normal(V)
                    voxel = {
                        'location': (x, y, z),
                        'normal': normal
                    }
                    rows[z].append(voxel)
                    
    return rows
```

**Parameters:**
*   Threshold $\tau$: User-defined value. Typical values are not given in the sources [S1, unofficial].
*   Transfer Function $F$: User-defined. Typical forms are not given [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Not specified [S1, unofficial].
*   **Boundaries:** Not specified [S1, unofficial].
*   **Degenerate Input:** If no voxels exceed the threshold, the result is an empty set of rows [S1, unofficial].

## Subtopics

### [Volume of Interest (VOI) Extraction with Sampling](12689-volume-of-interest-voi-extraction-with-sampling.md)
A technique to extract a rectangular sub-region from a 3D volume dataset and optionally downsample it using integer sampling rates. Unlike continuous interpolation-based cropping, this method uses integer strides for sampling, which is computationally simpler but limits resolution adjustments to integer factors.

### Data Subsetting for Plotting
A Python script that reduces large HPC simulation NetCDF files to laptop-sized subsets for plotting, cropping the z-dimension, selecting fields/records, and converting to float32 with zlib compression [S2, unofficial].
*   **Steps:** Select only requested fields and time records from the input file. Crop the z-dimension to the active layer (default `--zlim 5`). Convert data to float32 and apply zlib compression. Copy NetCDF groups (specifically `underlying_grid_reconstruction_kwargs`) with z and size rewritten to cropped values to preserve grid reconstruction. Include time-independent grid spacing variables (e.g., `Delta_x_caa`) required by `load_dataset_and_grid`. Drop `virtual_rank_files` metadata to avoid `check_rank_files` refusal when rank files are absent [S2, unofficial].
*   **Pitfalls:** Cropping z to exactly the plotted range (4) causes centred differences to become one-sided on boundaries, shifting Q values from $\pm 0.0726$ to $\pm 0.0727$. Using `--zlim 5` preserves bit-identical results [S2, unofficial].
*   **Performance:** Compression ratio of 2.15 GiB to 0.006 GiB (336x) on an $N_z=128$ test run with three records of nine fields [S2, unofficial].
*   **Reconstructed Domain:** The subset reconstructs $L_z = 7.81, z = \pm 3.91$ against the full file's $L_z = 25.0, z = \pm 12.5$, with $L_x/L_y$ unchanged [S2, unofficial].
*   **Usage:** Used to prepare data for X12 and X13 plotting scripts on laptop or CPU-only clusters [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels in the volume, $O(N)$, where $N$ is the total voxel count, as every voxel is evaluated [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of voxels exceeding the threshold. In the worst case (all voxels pass), it is $O(N)$; in the best case (none pass), it is $O(1)$ [S1, unofficial].
*   **Measured Performance:** Not given for the general method [S1, unofficial]. For the Data Subsetting variant, a 336x compression ratio was achieved on a specific HPC NetCDF file [S2, unofficial].
*   **Strengths:** Reduces data size for rendering/processing; supports efficient traversal orders; flexible transfer function [S1, unofficial].
*   **Limitations:** Requires recomputation of gradient/normal for each voxel; integer-only downsampling in VOI variant limits resolution flexibility [S1, unofficial].
*   **When to use:** When rendering sparse volumes or when data size is a bottleneck [S1, unofficial].
*   **When not to use:** When dense volume analysis is required or when non-integer downsampling is needed [S1, unofficial].

## Background
The method originates from work on splatting errors and antialiasing, specifically the "Splat Tenderer" approach [S1, unofficial]. It was used to render volumes such as a hollow tube checkerboard and terrain datasets, demonstrating antialiasing benefits through splatting [S1, unofficial]. The Data Subsetting variant was developed for batch rendering of 3D isosurface figures using X13 on CPU-only clusters, addressing the need to reduce large HPC NetCDF files for plotting [S2, unofficial].
