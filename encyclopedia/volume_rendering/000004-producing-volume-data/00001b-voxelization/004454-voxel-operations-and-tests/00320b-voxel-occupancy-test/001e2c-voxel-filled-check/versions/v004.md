# Voxel Filled Check

Also called: Filled, Intersection Detection, Voxel Occupancy Check

## Overview
Voxel Filled Check determines whether a specific voxel coordinate within a structured grid or hierarchical block (brick/chunk) is occupied. It solves the problem of quickly culling empty space during ray traversal or point-in-volume queries by testing a bitmask rather than loading full density values. It differs from [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by operating on discrete integer grid coordinates and bitmasks, and from [Voxel Visibility Culling](8235-voxel-visibility-culling.md) by returning a binary occupancy status for a single voxel rather than culling entire view-frustum-aligned blocks.

## How it works
The method checks occupancy by accessing a bitmask texture or array associated with a voxel block. It supports two modes: a metadata mode that checks semantic occupancy flags, and a raw bitmask mode that checks structural presence.

**Inputs:**
- `coord`: A 3D integer coordinate $(x, y, z)$ representing the voxel position.
- `option_.WithMeta()`: A boolean flag indicating whether to use voxel metadata.
- `voxel_metas_`: An array of metadata objects (used if `WithMeta()` is true).
- `output_lb_`, `output_ub_`: Lower and upper bounds defining the valid output region (used if `WithMeta()` is false).
- `mask_texture` or `voxel_batch`: The data structure containing the occupancy bitmask.

**Outputs:**
- A boolean or integer value (0 or 1) indicating if the voxel is filled.

**Data Structures:**
- **Bitmask Block**: A texture or array where each bit corresponds to a voxel in a local block of size $VX\_MASK\_EXT \times VX\_MASK\_EXT \times VX\_MASK\_EXT$.
- **Voxel Metadata**: An object containing semantic flags for occupancy.

**Steps:**
1. Determine the execution path based on `option_.WithMeta()`.
2. **If Metadata Mode is active:**
   - Retrieve the metadata object for the given `coord` from `voxel_metas_`.
   - Call the `Filled()` method on the metadata object.
   - Return the result.
3. **If Bitmask Mode is active:**
   - Calculate the local coordinate within the block:
     $$ local = coord \ \& \ (VX\_MASK\_EXT - 1) $$
     This extracts the lower bits of the coordinate, effectively computing $coord \mod VX\_MASK\_EXT$ for each dimension [S1, unofficial].
   - Calculate the linear index within the 3D bitmask block:
     $$ mask\_linear\_idx = local.x + local.y \cdot VX\_MASK\_EXT + local.z \cdot VX\_MASK\_EXT \cdot VX\_MASK\_EXT $$
     [S1, unofficial]
   - **Bounds Check:**
     - Verify if `coord` is within the valid output range defined by `output_lb_` and `output_ub_`.
     - If `coord` is outside these bounds, return 0 (not filled) [S2, unofficial].
   - **Bit Test:**
     - Determine the batch index: $batch\_idx = mask\_linear\_idx / kBatchSize$.
     - Determine the bit offset: $bit\_offset = mask\_linear\_idx \mod kBatchSize$.
     - Retrieve the integer word from the `voxel_batch` at `batch_idx`.
     - Extract the bit at `bit_offset` using a bitwise AND operation:
       $$ result = (voxel\_batch[batch\_idx] \gg bit\_offset) \ \& \ 1 $$
     - Return `result` [S2, unofficial].

**Pseudocode:**
```python
def voxel_filled_check(coord, option_with_meta, voxel_metas, output_lb, output_ub, voxel_batch, k_batch_size, vx_mask_ext):
    """
    Checks if a voxel at 'coord' is occupied.
    
    Args:
        coord (tuple): (x, y, z) integer coordinates.
        option_with_meta (bool): If True, use metadata mode.
        voxel_metas (list): Array of metadata objects.
        output_lb (tuple): Lower bounds (x, y, z).
        output_ub (tuple): Upper bounds (x, y, z).
        voxel_batch (list): List of integers representing the bitmask blocks.
        k_batch_size (int): Number of bits per integer in the batch.
        vx_mask_ext (int): Extent of the mask block (e.g., 8 or 16).
        
    Returns:
        int: 1 if filled, 0 otherwise.
    """
    if option_with_meta:
        # Metadata mode: check semantic flag in metadata object
        # Note: Exact indexing into voxel_metas depends on implementation details not fully specified in sources.
        # Assuming a direct mapping or lookup function exists.
        meta = get_metadata_for_coord(coord, voxel_metas) # [G] Helper to retrieve metadata
        return meta.filled()
    
    else:
        # Bitmask mode
        # 1. Calculate local coordinate within the block using bitwise AND
        local_x = coord[0] & (vx_mask_ext - 1)
        local_y = coord[1] & (vx_mask_ext - 1)
        local_z = coord[2] & (vx_mask_ext - 1)
        
        # 2. Calculate linear index in the 3D mask block
        mask_linear_idx = local_x + local_y * vx_mask_ext + local_z * vx_mask_ext * vx_mask_ext
        
        # 3. Bounds check
        if not (output_lb[0] <= coord[0] <= output_ub[0] and
                output_lb[1] <= coord[1] <= output_ub[1] and
                output_lb[2] <= coord[2] <= output_ub[2]):
            return 0
            
        # 4. Bit test
        batch_idx = mask_linear_idx // k_batch_size
        bit_offset = mask_linear_idx % k_batch_size
        
        # Retrieve the word and extract the bit
        word = voxel_batch[batch_idx]
        is_filled = (word >> bit_offset) & 1
        
        return is_filled
```

**Parameters:**
- `VX_MASK_EXT`: The side length of the voxel mask block. Typical values are powers of 2 (e.g., 8, 16) to allow efficient bitwise modulo operations [S1, unofficial].
- `kBatchSize`: The number of bits packed into a single integer word in the `voxel_batch` array. Typically 32 or 64 [S2, unofficial].
- `option_.WithMeta()`: Boolean flag. If true, the method bypasses the bitmask and checks a metadata structure [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Out-of-Bounds Coordinates:** If the coordinate falls outside `output_lb_` and `output_ub_`, the method must return 0 to prevent invalid memory access or false positives [S2, unofficial].
- **Bitwise Precision:** Ensure `VX_MASK_EXT` is a power of 2 to use the bitwise AND trick for modulo arithmetic. If not, standard modulo must be used [S1, unofficial].
- **Batch Indexing:** Division and modulo operations for `batch_idx` and `bit_offset` must be consistent with the storage layout of `voxel_batch`.

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel query. The calculation involves a constant number of bitwise operations, arithmetic, and array lookups.
- **Memory Complexity:** Depends on the storage of the bitmask. Typically, 1 bit per voxel is used, offering high compression compared to storing full density values.
- **Performance:** Extremely fast on both CPU and GPU due to minimal branching and simple arithmetic. The CUDA implementation (`intersect_occ_cuda`) leverages parallel execution for batched queries [S3, unofficial].
- **Strengths:** Low memory footprint, fast culling of empty space, simple implementation.
- **Limitations:** Only provides binary occupancy; does not provide density or material information unless combined with metadata mode. Requires careful handling of block boundaries and coordinate systems.

## Background
The method originates from voxel-based ray tracing and volume rendering systems, specifically those using hierarchical data structures like bricks or chunks to manage large voxel grids. It is a fundamental component in engines like vxray and voxelizer, where efficient empty space culling is critical for performance [S1, S2, unofficial]. The distinction between metadata-based and bitmask-based checks allows for flexibility in handling semantic occupancy (e.g., transparent vs. opaque) versus structural occupancy [S2, unofficial].
