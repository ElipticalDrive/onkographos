# Voxel Filled Check

Also called: Filled, Intersection Detection, Voxel Occupancy Check

## Overview
Voxel Filled Check determines whether a specific voxel, brick, or chunk within a structured grid is occupied by geometry or data [S1, unofficial][S3, unofficial]. It serves as the fundamental occupancy test for ray traversal and rendering, returning a boolean result for a given coordinate [S1, unofficial]. Unlike [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) which tests geometric primitives against bounds, or [Voxel Visibility Culling](8235-voxel-visibility-culling.md) which determines visibility along a ray, this method directly queries the discrete occupancy state of the voxel grid itself [S1, unofficial].

## How it works
**Inputs:**
- `coord`: A 3D integer coordinate $(x, y, z)$ representing the voxel to check.
- `mask`: A bitmask texture or array storing occupancy data for a block (brick/chunk) of voxels.
- `output_lb_`, `output_ub_`: Lower and upper bounds defining the valid output region (optional, depending on implementation).
- `option_.WithMeta()`: A boolean flag indicating whether voxel metadata is available and should be checked [S2, unofficial].
- `voxel_metas_`: An array of metadata objects associated with voxels (optional) [S2, unofficial].

**Outputs:**
- A boolean value (or integer 0/1) indicating if the voxel is occupied.

**Data Structures:**
- **Bitmask:** Occupancy is typically stored in a compact bitmask where each bit represents one voxel. The size of the mask depends on the block dimensions (e.g., $VX\_MASK\_EXT \times VX\_MASK\_EXT \times VX\_MASK\_EXT$).
- **Voxel Meta:** Optional structure containing additional properties per voxel, used if metadata checking is enabled [S2, unofficial].

**Steps:**
1. **Calculate Local Coordinate:** Determine the local position of the input coordinate within its block. This is done using a bitwise AND operation with the mask extent minus one:
   $$
   local = coord \ \& \ (VX\_MASK\_EXT - 1)
   $$
   This assumes $VX\_MASK\_EXT$ is a power of two [S1, unofficial].

2. **Calculate Linear Index:** Compute the linear index of the voxel within the bitmask array. The formula is:
   $$
   mask\_linear\_idx(coord) = local.x + local.y \cdot VX\_MASK\_EXT + local.z \cdot VX\_MASK\_EXT \cdot VX\_MASK\_EXT
   $$
   where $local = (local.x, local.y, local.z)$ [S1, unofficial].

3. **Check Metadata (Optional):** If `option_.WithMeta()` is true, retrieve the metadata for the voxel at the calculated index and call the `Filled()` function on that metadata. Return the result of this check [S2, unofficial].

4. **Check Bounds (Optional):** If metadata is not used, convert the linear index back to $(x, y, z)$ coordinates (or use the original `coord`). Check if the coordinate is within the valid output bounds defined by `output_lb_` and `output_ub_`. If the coordinate is out of bounds, return 0 (false) [S2, unofficial].

5. **Check Bitmask:** If the coordinate is within bounds, determine the batch index by dividing the linear index by the batch size ($kBatchSize$). Retrieve the corresponding integer from the voxel batch array. Use a bitwise AND operation with a mask corresponding to the bit position within that integer to check if the bit is set.
   $$
   is\_occupied = (voxel\_batch[index / kBatchSize] \ \& \ (1 \ll (index \ \% \ kBatchSize))) \neq 0
   $$
   Return the result [S2, unofficial].

**Pseudocode:**
```python
def voxel_filled_check(coord, mask, output_lb, output_ub, use_meta, voxel_metas, k_batch_size, vx_mask_ext):
    # Step 1: Calculate local coordinate within the block
    # Assuming vx_mask_ext is a power of 2
    local_x = coord.x & (vx_mask_ext - 1)
    local_y = coord.y & (vx_mask_ext - 1)
    local_z = coord.z & (vx_mask_ext - 1)
    
    # Step 2: Calculate linear index
    mask_linear_idx = local_x + local_y * vx_mask_ext + local_z * vx_mask_ext * vx_mask_ext
    
    # Step 3: Check metadata if enabled
    if use_meta:
        # Retrieve metadata for the voxel
        meta = voxel_metas[mask_linear_idx]
        # Call Filled() on the metadata
        return meta.filled()
    
    # Step 4: Check bounds
    # Convert linear index back to coordinates for bound check if necessary, 
    # or use original coord if bounds are defined in global space.
    # Here we assume output_lb/ub are global bounds.
    if not (output_lb.x <= coord.x <= output_ub.x and
            output_lb.y <= coord.y <= output_ub.y and
            output_lb.z <= coord.z <= output_ub.z):
        return False
    
    # Step 5: Check bitmask
    batch_index = mask_linear_idx // k_batch_size
    bit_offset = mask_linear_idx % k_batch_size
    
    # Retrieve the batch integer from the mask array
    batch_value = mask[batch_index]
    
    # Check if the specific bit is set
    is_set = (batch_value & (1 << bit_offset)) != 0
    
    return is_set
```

**Parameters:**
- `VX_MASK_EXT`: The dimension of the mask block (e.g., 8, 16). Must be a power of two for the bitwise optimization [S1, unofficial].
- `kBatchSize`: The number of bits stored in one integer of the `voxel_batch` array (typically 32 or 64) [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Out of Bounds:** If the input coordinate falls outside the defined output bounds (`output_lb_` to `output_ub_`), the function must return false to prevent accessing invalid memory or returning incorrect occupancy states [S2, unofficial].
- **Power of Two Assumption:** The bitwise calculation for `local` coordinates relies on `VX_MASK_EXT` being a power of two. If this is not the case, standard modulo and division operations must be used instead [S1, unofficial].
- **Metadata Consistency:** If metadata is used, the `Filled()` method within the metadata must be consistent with the bitmask definition. Discrepancies can lead to false negatives or positives [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel check, as it involves constant-time bitwise operations and array lookups [S1, unofficial][S2, unofficial].
- **Memory Complexity:** Depends on the storage format of the bitmask. Bit-packed storage reduces memory usage by a factor of $kBatchSize$ (e.g., 32 or 64) compared to boolean arrays [S2, unofficial].
- **Performance:** Highly efficient on both CPU and GPU due to minimal branching and cache-friendly access patterns when checking contiguous blocks [S1, unofficial][S3, unofficial].
- **Strengths:** Fast occupancy queries, low memory footprint with bitmasks, simple implementation [S1, unofficial].
- **Limitations:** Only provides binary occupancy; does not handle partial occupancy or material properties directly [S1, unofficial]. Requires careful handling of bounds and metadata if enabled [S2, unofficial].

## Background
Voxel Filled Check is a fundamental operation in voxel-based rendering and geometry processing. It is implemented in various open-source voxel rendering engines and libraries, such as vxray and voxelizer, to efficiently determine which voxels contain geometry during ray traversal or rasterization [S1, unofficial][S2, unofficial]. The method leverages bitmasks for compact storage and fast access, a common technique in high-performance graphics applications [S1, unofficial].
