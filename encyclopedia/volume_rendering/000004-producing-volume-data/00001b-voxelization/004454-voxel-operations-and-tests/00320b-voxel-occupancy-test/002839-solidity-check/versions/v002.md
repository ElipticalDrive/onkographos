# Solidity Check

Also called: Void Check with Boundary Handling

## Overview
Solidity Check determines if a voxel coordinate is solid or void while handling boundary conditions and coordinate wrapping [S2, unofficial]. It differs from [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by managing chunk-based spatial indexing and asymmetric boundary wrapping for X/Y versus Z axes [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- `x, y, z`: Integer world voxel coordinates.
- `map`: World structure containing `width`, `height`, `depth`, and chunk data.

**Outputs:**
- `bool`: `True` if the voxel is solid, `False` if it is void.

**Data Structures:**
The method relies on the `libvxl_map` structure [S2, unofficial]:
```python
class libvxl_map:
    width: int
    height: int
    depth: int
    chunks: list  # Array of chunk references
    geometry: list  # Geometry lookup table
    streamed: int
```
Position keys are encoded as 32-bit integers [S2, unofficial]:
$$ \text{pos\_key}(x,y,z) = (y \ll 20) \mid (x \ll 8) \mid z $$
Where $x$ and $y$ use 12 bits (0-4095) and $z$ uses 8 bits (0-255) [S2, unofficial].

**Steps:**
1. Calculate chunk index for the world position using `get_chunk_index` [S1, unofficial].
2. If `chunk_index` is $-1$ (out of bounds), return `True` (solid) to prevent rendering holes at world edges [S1, unofficial].
3. If $z < 0$, return `False` (void) [S2, unofficial].
4. If `map` is `null` or $z \ge \text{map->depth}$, return `True` (solid) [S2, unofficial].
5. Wrap coordinates: $x' = x \pmod{\text{map->width}}$, $y' = y \pmod{\text{map->height}}$, $z' = z$ [S2, unofficial].
6. Call `libvxl_geometry_get(x', y', z')` to retrieve voxel data [S2, unofficial].
7. Return `True` if solid, `False` if void. Per source notes, a non-zero voxel value yields `False` (void), while zero yields `True` (solid), indicating an inverted occupancy flag or void-check naming convention [S1, unofficial].

**Pseudocode:**
```python
def solidity_check(x: int, y: int, z: int, map: dict) -> bool:
    # Step 1: Calculate chunk index
    # Implementation not provided in sources [S1, unofficial]
    chunk_index = get_chunk_index(x, y, z)

    # Step 2: Out-of-bounds chunk check
    if chunk_index == -1:
        return True  # Treated as solid to prevent rendering holes [S1, unofficial]

    # Step 3: Z-axis boundary checks
    if z < 0:
        return False  # Below world is void [S2, unofficial]
    if map is None or z >= map["depth"]:
        return True   # Above world is solid [S2, unofficial]

    # Step 4: Coordinate wrapping
    x_wrapped = x % map["width"]
    y_wrapped = y % map["height"]
    z_wrapped = z

    # Step 5: Retrieve voxel data
    # Implementation not provided in sources [S2, unofficial]
    voxel_data = libvxl_geometry_get(x_wrapped, y_wrapped, z_wrapped)

    # Step 6: Determine solidity
    # Source notes state: return False if non-zero, else return True [S1, unofficial]
    return voxel_data == 0
```

**Parameters:**
- `CHUNK_SIZE`, `CHUNK_AREA`: Used in local index calculations (`x % CHUNK_SIZE + z % CHUNK_SIZE * CHUNK_SIZE + y % CHUNK_SIZE * CHUNK_AREA`) for direct chunk access, though the primary flow uses `libvxl_geometry_get` [S1, unofficial].

**Edge Cases:**
- Out-of-bounds X/Y coordinates wrap via modulo [S2, unofficial].
- Out-of-bounds Z is void if $z < 0$ and solid if $z \ge \text{depth}$ [S2, unofficial].
- Out-of-bounds chunks return solid [S1, unofficial].

## Subtopics

### [Surface Detection](5803-surface-detection.md)
Determines if a voxel coordinate lies on the boundary of a solid volume by checking its 6-connected neighborhood for non-solid neighbors. It distinguishes itself from its parent by inverting the logic: while the parent confirms if a voxel is solid, this method confirms if it is exposed to air.

## Operating characteristics
- **Time Complexity:** $O(1)$ assuming constant-time chunk lookup and modulo operations [G].
- **Memory Complexity:** $O(1)$ auxiliary space [G].
- **Strengths:** Handles asymmetric boundary conditions (wrapping X/Y, clamping Z) efficiently [S2, unofficial].
- **Limitations:** Relies on specific `libvxl` data structures and helper functions not fully detailed in the sources [S1, unofficial][S2, unofficial].
- **When to use:** When voxelizing or rendering volumes with wrapped horizontal boundaries and vertical limits [S1, unofficial][S2, unofficial].

## Background
The method originates from the `libvxl` library by xtreme8000 and is implemented in the `StanislavPetrovV/Minecraft` project [S1, unofficial][S2, unofficial]. It is used in voxel-based game engines and volume rendering systems to efficiently query voxel occupancy while managing world boundaries [S1, unofficial][S2, unofficial].
