# Point-in-Box Inclusion Test via Sorted Indices and Bisect

Also called: Efficient Voxel Query via Sorted Indices and Bisect, Range Query via Binary Search on Sorted Coordinates

## Overview
This method accelerates voxel occupancy tests by pre-sorting point cloud coordinates along each axis, enabling $O(\log N)$ range queries via binary search instead of $O(N)$ linear scans. It differs from the parent [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by optimizing the inner loop for repeated queries on static data, trading $O(N)$ preprocessing time for faster per-query performance.

## How it works
**Inputs and Outputs:**
- Input: A point cloud $P$ of $N$ points, where each point $p_i = (x_i, y_i, z_i)$.
- Input: A query box defined by $[x_{min}, x_{max}] \times [y_{min}, y_{max}] \times [z_{min}, z_{max}]$.
- Output: A subset of points $P_{in} \subseteq P$ such that $p_i \in P_{in}$ if and only if $x_{min} \le x_i \le x_{max}$, $y_{min} \le y_i \le y_{max}$, and $z_{min} \le z_i \le z_{max}$.

**Data Structures:**
Three sorted arrays of indices or coordinates are maintained:
- `sorted_x_pc`: Indices of points in $P$ sorted by $x$-coordinate.
- `sorted_y_pc`: Indices of points in $P$ sorted by $y$-coordinate.
- `sorted_z_pc`: Indices of points in $P$ sorted by $z$-coordinate.
Alternatively, the coordinates themselves can be stored in sorted arrays if only the count or existence is needed, but indices are required to retrieve the full point data.

**Steps:**
1. **Preprocessing (`__init__`):**
   - Extract $x$, $y$, and $z$ coordinates from $P$.
   - Create `sorted_x_pc` by sorting indices based on $x$ values.
   - Create `sorted_y_pc` by sorting indices based on $y$ values.
   - Create `sorted_z_pc` by sorting indices based on $z$ values.
   - [G] Handle empty point clouds by returning empty arrays.

2. **Query (`get_points_in_range`):**
   - For each axis $a \in \{x, y, z\}$:
     - Let $L_a$ and $H_a$ be the lower and upper bounds of the query box for axis $a$.
     - Use binary search to find the range of indices in the sorted array for axis $a$ that fall within $[L_a, H_a]$.
     - Specifically, find `idx_start` such that all points from `idx_start` to `idx_end` satisfy the condition.
     - `idx_start` is the index of the first element $\ge L_a$ (using `bisect_left`).
     - `idx_end` is the index of the first element $> H_a$ (using `bisect_right`).
     - The valid indices for axis $a$ are those in the range `[idx_start, idx_end)` in the sorted array for that axis.
   - Intersect the sets of indices from all three axes to find points satisfying all three conditions.
   - Return the points corresponding to the intersected indices.

**Pseudocode:**
```python
import bisect
import numpy as np

class VoxelQuery:
    def __init__(self, points: np.ndarray):
        """
        Initialize the voxel query structure.
        points: np.ndarray of shape (N, 3) containing (x, y, z) coordinates.
        """
        self.points = points
        self.N = points.shape[0]
        
        if self.N == 0:
            self.sorted_x_pc = np.array([], dtype=int)
            self.sorted_y_pc = np.array([], dtype=int)
            self.sorted_z_pc = np.array([], dtype=int)
            return

        # Create sorted indices for each axis
        self.sorted_x_pc = np.argsort(points[:, 0])
        self.sorted_y_pc = np.argsort(points[:, 1])
        self.sorted_z_pc = np.argsort(points[:, 2])
        
        # Extract sorted coordinates for binary search
        self.sorted_x_coords = points[self.sorted_x_pc, 0]
        self.sorted_y_coords = points[self.sorted_y_pc, 1]
        self.sorted_z_coords = points[self.sorted_z_pc, 2]

    def get_points_in_range(self, x_min: float, x_max: float, 
                            y_min: float, y_max: float, 
                            z_min: float, z_max: float) -> np.ndarray:
        """
        Find points within the specified 3D box.
        """
        if self.N == 0:
            return np.empty((0, 3), dtype=self.points.dtype)

        # Find ranges for each axis
        # x-axis
        x_start = bisect.bisect_left(self.sorted_x_coords, x_min)
        x_end = bisect.bisect_right(self.sorted_x_coords, x_max)
        x_indices = set(self.sorted_x_pc[x_start:x_end])

        # y-axis
        y_start = bisect.bisect_left(self.sorted_y_coords, y_min)
        y_end = bisect.bisect_right(self.sorted_y_coords, y_max)
        y_indices = set(self.sorted_y_pc[y_start:y_end])

        # z-axis
        z_start = bisect.bisect_left(self.sorted_z_coords, z_min)
        z_end = bisect.bisect_right(self.sorted_z_coords, z_max)
        z_indices = set(self.sorted_z_pc[z_start:z_end])

        # Intersect indices
        common_indices = x_indices & y_indices & z_indices
        
        # Return points
        if not common_indices:
            return np.empty((0, 3), dtype=self.points.dtype)
        
        return self.points[list(common_indices)]
```

**Parameters:**
- Typical values: None specific, depends on point cloud density and query box size.

**Edge Cases and Pitfalls:**
- Empty point cloud: Handled by returning empty arrays.
- Query box outside point cloud bounds: Binary search returns empty ranges, resulting in empty output.
- Precision: Floating-point comparisons should be consistent with the sorting precision. [G] Use `bisect_left` and `bisect_right` to handle boundary points correctly (inclusive lower, exclusive upper for the right bound logic in bisect, but the logic above handles inclusive bounds by using `bisect_right` for the upper bound).

## Subtopics

### Searchsorted
**Definition:** Uses `np.searchsorted` or similar functions to find insertion points for query values in sorted arrays.
**Details:** 
- Create index tensor `i` for the last dimension of `a` (sorted reference points).
- Compute boolean mask `v_ge_a` where `v >= a`.
- Compute `idx_lo` as max of indices where `v >= a`, handling out-of-range values.
- Compute `idx_hi` as min of indices where `v < a`, handling out-of-range values.
**Pitfall:** If `v` is out of range `[a[0], a[-1]]`, `idx_lo` and `idx_hi` are set to the first or last index of `a`. [S2, unofficial]
**When to choose:** When using vectorized operations (e.g., NumPy, PyTorch) for batched queries, as `searchsorted` can be more efficient for large batches than Python-level loops.

## Operating characteristics
**Time Complexity:**
- Preprocessing: $O(N \log N)$ for sorting.
- Query: $O(\log N)$ for binary search per axis, plus $O(K)$ to intersect sets and retrieve points, where $K$ is the number of candidate points. In the worst case, $K$ can be $O(N)$, but typically much smaller.

**Memory Complexity:**
- $O(N)$ to store sorted indices and coordinates.

**Measured Performance:**
- Not given in the sources. [S1, unofficial]

**Scaling:**
- Scales well with $N$ for preprocessing, but memory usage increases linearly.

**Strengths and Limitations:**
- Strengths: Fast query time for repeated queries on static data.
- Limitations: High preprocessing cost if data changes frequently. Memory overhead for storing sorted arrays.

**When to use:**
- Use when performing many range queries on a static point cloud.
- Not suitable for dynamic point clouds where points are frequently added or removed.
