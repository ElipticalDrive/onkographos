# Point-in-Box Inclusion Test

Also called: Point Array Box Partitioning, annBoxSplit

## Overview
The Point-in-Box Inclusion Test partitions a point array about an orthogonal bounding box, returning the count of points inside or on its boundary [S1, unofficial]. It differs from sibling methods like [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md) or [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md) by performing a direct, dimension-aware containment check optimized for in-place array partitioning rather than spatial acceleration or kernel approximation [G].

## How it works
**Inputs:**
- `PP`: An array of $N$ points, where each point $P_i$ has coordinates $(x_i, y_i, z_i)$ [G].
- `box`: An axis-aligned bounding box with a method `inside(dim, point)` that returns true if the point lies within the box bounds along the specified dimension `dim` [G].
- `dim`: The axis index (0, 1, or 2) to test for containment [G].

**Outputs:**
- `n_in`: The number of points inside or on the boundary of the box [S1, unofficial].
- The array `PP` is reordered in-place such that the first `n_in` points satisfy the containment condition, and the remaining points do not [S1, unofficial].

**Data Structures:**
- `PP` is stored as a contiguous block of memory. Each point is a tuple or struct of three floating-point values [G].

**Algorithm Steps:**
1. Initialize indices `l = 0` and `r = n - 1` [S1, unofficial].
2. Loop while `l < n` and `r >= 0`:
   a. Increment `l` while `l < n` and `box.inside(dim, PP[l])` is true [S1, unofficial].
   b. Decrement `r` while `r >= 0` and `box.inside(dim, PP[r])` is false [S1, unofficial].
   c. If `l > r`, break the loop [S1, unofficial].
   d. Swap `PP[l]` and `PP[r]` [S1, unofficial].
   e. Increment `l` and decrement `r` [S1, unofficial].
3. Set `n_in = l` [S1, unofficial].

**Pseudocode:**
```python
def point_in_box_inclusion_test(PP, box, dim):
    n = len(PP)
    l = 0
    r = n - 1
    while l < n and r >= 0:
        while l < n and box.inside(dim, PP[l]):
            l += 1
        while r >= 0 and not box.inside(dim, PP[r]):
            r -= 1
        if l > r:
            break
        PP[l], PP[r] = PP[r], PP[l]
        l += 1
        r -= 1
    n_in = l
    return n_in, PP
```

**Parameters:**
- `dim`: The spatial dimension to test. If not specified, all three dimensions are tested [G].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point comparisons for boundary inclusion must be consistent to avoid points being counted or missed due to rounding errors [G].
- **Empty Array:** If $N=0$, the loop condition `l < n` fails immediately, and `n_in` is 0 [G].
- **All Inside/Outside:** If all points are inside, `l` increments to `n` and the loop breaks, yielding `n_in = n`. If all are outside, `r` decrements to `-1` and the loop breaks, yielding `n_in = 0` [S1, unofficial].

## Subtopics

### [Point-in-Box Inclusion Test via Sorted Indices and Bisect](7081-point-in-box-inclusion-test-via-sorted-indices-and-bisect.md)
This method performs point-in-box inclusion tests by pre-sorting point cloud coordinates along each axis and using binary search to determine occupancy. It differs from the parent method by explicitly leveraging sorted index arrays and bisect operations to handle range queries, rather than generic partitioning logic. Choose it when repeatedly querying static point sets for bounding box occupancy, as it reduces the search space to $O(\log N)$ per axis at the cost of $O(N \log N)$ preprocessing [G].

### Point-in-Box Inclusion Test with Dimension Selection
This variant finds the spatial dimension with the largest spread among all dimensions in a point set [S1, unofficial]. It is used to prioritize partitioning along the axis with the greatest variance, improving balance in subsequent hierarchical structures [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ per query for the basic partitioning method, where $N$ is the number of points [S1, unofficial]. The sorted variant requires $O(N \log N)$ preprocessing but $O(\log N)$ per query [G].
- **Memory Complexity:** $O(1)$ auxiliary space for the in-place partitioning method [S1, unofficial]. The sorted variant requires $O(N)$ space for indices [G].
- **Strengths:** Simple implementation, low memory overhead, and effective for one-time occupancy checks [G].
- **Limitations:** Linear scan is slow for repeated queries on large static datasets [G].
- **When to use:** Use the basic method for single-pass voxelization or memory-constrained environments. Use the sorted variant for scenes with static geometry and frequent occupancy queries [G].

## Background
The method originates from computational geometry techniques for point set partitioning, specifically implemented in dual contouring and voxelization pipelines [S1, unofficial][S2, unofficial]. It is used as a fundamental primitive for voxel occupancy testing and spatial partitioning in 3D rendering [S2, unofficial].
