# Voxel Edit Brush Operations

Also called: Place/Carve/Fill/Paint, Real-time Voxel Editing, VoxelEdit

## Overview
Voxel Edit Brush Operations provide a runtime pipeline for modifying unbounded voxel grids using spherical, cubic, or span-based brushes [S2]. Unlike static voxelization, this method supports interactive, frame-accumulated strokes that commit atomic commands, enabling lossless undo/redo on sparse volumes [S1, unofficial]. It distinguishes itself by addressing the grid using unbounded world-space coordinates rather than chunk-local indices, ensuring consistent behavior across chunk boundaries [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A world-space ray (origin, direction), a brush type (Place, Carve, Fill, Paint), a brush radius, and a material ID [S1, unofficial][S2].
*   **Output:** Modified voxel data in affected chunks and a `VoxelEditCommand` for undo/redo history [S1, unofficial].

**Data Structures:**
*   **VoxelGrid:** An unbounded grid accessed via world-space coordinates $(x, y, z)$. It is composed of chunks (e.g., 32x32x32 cells) [S1, unofficial].
*   **VoxelEditCommand:** An atomic record of changes, containing the list of modified chunks and their previous states (snapshots) [S1, unofficial].
*   **Stroke Buffer:** Accumulates edits per frame [S1, unofficial].

**Steps:**
1.  **Raycasting:** Cast a ray from the camera through the mouse cursor into the voxel terrain's local space [S1, unofficial]. The raycast returns the hit grid cell, the entered face normal, the distance, and the world point [S1, unofficial].
2.  **Coordinate Mapping:** Convert the hit world point to unbounded grid coordinates $(x, y, z)$ [S1, unofficial]. Do not use chunk-local indices [S1, unofficial].
3.  **Stroke Accumulation:** For each frame, calculate the voxels affected by the brush centered at the hit point with the specified radius and type (sphere, cube, span, rectangle) [S2]. Add these modifications to the current stroke buffer [S1, unofficial].
4.  **Command Commit:** On mouse release, push the accumulated stroke as a single `VoxelEditCommand` [S1, unofficial].
5.  **Chunk Snapshotting:** Before applying the command, snapshot the state of all affected chunks [S1, unofficial]. Only chunks with actual cell changes are kept in the snapshot to maintain proportionality [S1, unofficial].
6.  **Application:** Apply the edits to the voxel grid [S2].
7.  **Dirty Region Marking:** Use `VoxelOverride` to mark the owning chunk and any existing neighbor across a shared face as dirty [S1, unofficial]. This ensures that only a ring of chunks around the edit is rebuilt during remeshing [S1, unofficial].
8.  **Remeshing:** Rebuild meshes for dirty chunks, pruning any chunks that no longer exist [S1, unofficial].

**Formulas:**
*   **Brush Volume:** For a spherical brush, a voxel at grid position $\mathbf{v}$ is affected if:
    $$ \|\mathbf{v} - \mathbf{c}\| \leq r $$
    where $\mathbf{c}$ is the center of the brush in grid coordinates and $r$ is the brush radius [S1, unofficial].
*   **World-to-Grid:**
    $$ \mathbf{v} = \lfloor \mathbf{p}_{world} / \text{voxel\_size} \rfloor $$
    where $\mathbf{p}_{world}$ is the world point of the brush center [S1, unofficial].

**Parameters:**
*   **Brush Radius:** A world-space radius defining the spherical area of influence [S1, unofficial].
*   **Brush Type:** Place, Carve, Fill, Paint, Span, Cube, Rectangle [S1, unofficial][S2].
*   **Material ID:** Identifies the material to place or paint [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Chunk Boundaries:** Addressing must use unbounded world-grid coordinates to avoid behavior changes at 32-cell boundaries [S1, unofficial].
*   **Undo Losslessness:** Undoing an edit that created a new chunk must remove the chunk entirely, not leave an empty allocation [S1, unofficial].
*   **Mesh Pruning:** If mesh pruning is removed, undoing a delete may leave the mesh of a deleted chunk drawn [S1, unofficial].
*   **Negative Coordinates:** Negative grid coordinates must map correctly to their respective chunks [S1, unofficial].

**Pseudocode:**
```python
def process_voxel_edit(ray_origin, ray_direction, brush_radius, brush_type, material_id):
    # 1. Raycast to find hit point
    hit = raycast_terrain(ray_origin, ray_direction)
    if not hit.hit:
        return

    # 2. Convert hit point to world grid coordinates
    # Note: EditorLayer transforms mouse ray into voxel terrain's local space
    world_point = hit.world_point
    grid_coords = world_to_grid(world_point)
    
    # 3. Determine affected voxels based on brush type and radius
    affected_voxels = get_brush_voxels(grid_coords, brush_radius, brush_type)
    
    # 4. Accumulate into stroke buffer
    stroke_buffer.add(affected_voxels, material_id)

def commit_voxel_edit(stroke_buffer):
    # 5. Snapshot affected chunks
    affected_chunks = get_chunks_from_voxels(stroke_buffer.voxels)
    snapshots = {}
    for chunk in affected_chunks:
        snapshots[chunk.id] = chunk.snapshot()
        
    # 6. Apply edits
    for voxel in stroke_buffer.voxels:
        apply_edit(voxel, stroke_buffer.material_id)
        
    # 7. Create and push command
    command = VoxelEditCommand(affected_chunks, snapshots)
    undo_stack.push(command)
    
    # 8. Mark dirty regions
    for chunk in affected_chunks:
        chunk.mark_dirty()
        mark_neighbors_dirty(chunk)
        
    # 9. Clear stroke buffer
    stroke_buffer.clear()

def undo_voxel_edit():
    command = undo_stack.pop()
    # Restore snapshots
    for chunk_id, snapshot in command.snapshots.items():
        chunk = get_chunk(chunk_id)
        if chunk is None:
            # If chunk was created by the edit, remove it
            remove_chunk(chunk_id)
        else:
            chunk.restore(snapshot)
        chunk.mark_dirty()
        mark_neighbors_dirty(chunk)
```

## Operating characteristics
*   **Time Complexity:** Depends on the number of voxels in the brush volume and the number of affected chunks. Remeshing is localized to dirty chunks and their neighbors [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of modified chunks and the size of their snapshots [S1, unofficial]. Sparse volumes keep snapshots proportional to the edit [S1, unofficial].
*   **Performance:** Byte-equality validated against reference implementation (voxlap C's `setspans`) [S2].
*   **Strengths:** Lossless undo/redo, consistent behavior across chunk boundaries, localized remeshing [S1, unofficial].
*   **Limitations:** Requires snapshotting chunks for undo, which can be memory-intensive for large edits [S1, unofficial].

## Background
This method is part of a real-time voxel editing pipeline, often used in terrain editors and destructible environments [S1, unofficial][S2]. It builds on [Sphere Carving](2377-sphere-carving.md) by generalizing the operation to multiple brush types and adding a robust undo/redo system [S1, unofficial].
