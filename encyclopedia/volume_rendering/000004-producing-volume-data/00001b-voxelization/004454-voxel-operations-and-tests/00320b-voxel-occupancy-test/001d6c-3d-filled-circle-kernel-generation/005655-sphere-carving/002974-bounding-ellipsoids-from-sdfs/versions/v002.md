# Bounding Ellipsoids from SDFs

Also called: Ellipsoid Bounding Volume, Minimum-Volume Enclosing Ellipsoid for SDFs

## Overview
This method generates a conservative Signed Distance Function (SDF) for a shape by approximating its geometry with a minimum-volume enclosing ellipsoid [S1, S2]. It replaces the convex hull generation step in the Sphere Carving pipeline with an ellipsoid bounding volume, offering constant-time evaluation and a compact memory footprint compared to $n$-face convex polyhedra [S1, S2].

## How it works
**Inputs:**
- A point set $P$ representing the surface of the target shape [S1, S2].
- Ellipsoid parameters: center $\mathbf{c}$, rotation matrix $\mathbf{R}$, diagonal matrix $\mathbf{D}$, and axis lengths $a, b, c$ with $a < b < c$ [S1, S2].

**Outputs:**
- A 1-Lipschitz (conservative) SDF function $d(\mathbf{p}, \mathcal{E})$ [S1, S2].

**Data Structures:**
- **Center ($\mathbf{c}$):** A 3D vector $(c_x, c_y, c_z)$ [S1, S2].
- **Rotation Matrix ($\mathbf{R}$):** A $3 \times 3$ orthogonal matrix defining the orientation of the ellipsoid axes [S1, S2].
- **Diagonal Matrix ($\mathbf{D}$):** A $3 \times 3$ diagonal matrix with entries $1/a, 1/b, 1/c$ [S1, S2].
- **Axis Lengths:** Scalars $a, b, c$ representing the semi-axis lengths, strictly ordered $a < b < c$ [S1, S2].

**Algorithm Steps:**
1. **Generate Point Set:** Obtain a point set $P$ close to the shape surface, typically via the approximate convex decomposition or sphere carving iterations described in the parent method [S1, S2].
2. **Compute Minimum-Volume Enclosing Ellipsoid (MVEE):** Replace the standard convex hull generation step with an MVEE algorithm applied to point set $P$ [S1, S2]. This yields the center $\mathbf{c}$, rotation $\mathbf{R}$, and axis lengths $a, b, c$ [S1, S2].
3. **Construct Transformation Matrix:** Compute $\mathbf{A} = \mathbf{D} \mathbf{R}^T$, where $\mathbf{D} = \text{diag}(1/a, 1/b, 1/c)$ [S1, S2].
4. **Evaluate SDF:** For any query point $\mathbf{p}$, compute the distance using the defined formula [S1, S2].

**Formula:**
The signed distance function for an ellipsoid $\mathcal{E}$ is defined as [S1, S2]:

$$d(\mathbf{p}, \mathcal{E}) = a (\|\mathbf{A}(\mathbf{p} - \mathbf{c})\| - 1)$$

Where:
- $\mathbf{p}$ is the query point [S1, S2].
- $a$ is the smallest semi-axis length [S1, S2].
- $\mathbf{c}$ is the center of the ellipsoid [S1, S2].
- $\mathbf{A} = \mathbf{D}(1/a, 1/b, 1/c) \mathbf{R}^T$ [S1, S2].
- $\|\cdot\|$ denotes the Euclidean norm [S1, S2].

**Pseudocode:**
```python
def ellipsoid_sdf(p, c, R, a, b, c_axis):
    """
    Computes the conservative SDF for an ellipsoid.
    
    Args:
        p: Query point (vec3)
        c: Ellipsoid center (vec3)
        R: Rotation matrix (3x3)
        a: Smallest semi-axis length
        b: Middle semi-axis length
        c_axis: Largest semi-axis length
        
    Returns:
        Conservative signed distance
    """
    # Step 1: Translate point to ellipsoid space
    diff = p - c
    
    # Step 2: Rotate point into ellipsoid's local frame (R^T @ diff)
    rotated_diff = R.T @ diff
    
    # Step 3: Scale by inverse axis lengths (D @ rotated_diff)
    scaled_x = rotated_diff[0] / a
    scaled_y = rotated_diff[1] / b
    scaled_z = rotated_diff[2] / c_axis
    
    # Step 4: Compute Euclidean norm
    norm_val = (scaled_x**2 + scaled_y**2 + scaled_z**2)**0.5
    
    # Step 5: Apply scaling factor 'a' and offset
    distance = a * (norm_val - 1.0)
    
    return distance
```

**Edge Cases and Pitfalls:**
- **Conservatism:** The function is 1-Lipschitz, meaning it is conservative (overestimates distance) [S1, S2]. The degree of conservatism depends on the relative axis lengths $a, b, c$ [S1, S2]. Highly elongated ellipsoids may be less accurate approximations of complex shapes compared to convex polyhedra [S1, S2].

## Operating characteristics
- **Time Complexity:** Evaluation requires approximately 4 scalar products and one square root [S1, S2]. This is constant time $O(1)$ with respect to the number of faces, unlike convex polyhedra which require $n$ scalar products for $n$ faces [S1, S2].
- **Memory Complexity:** Ellipsoids are more compact in memory than convex polyhedra, requiring only storage for the center, rotation matrix, and three axis lengths [S1, S2].
- **Performance:** The GPU implementation performs well for most models [S1, S2]. However, overly conservative SDFs (e.g., ship models) may require more iterations in the parent Sphere Carving algorithm to converge, similar to slow Sphere Tracing [S1, S2].
- **Strengths:** Computational efficiency, low memory footprint, and simplicity of implementation [S1, S2].
- **Limitations:** Potentially less geometric fidelity than convex polyhedra, especially when the relative axis lengths cause high conservatism [S1, S2].

## Background
This method is described in "Sphere Carving: Bounding Volumes for Signed Distance Fields" [S1, S2]. It is presented as one of several bounding volume types (alongside oriented bounding boxes, k-dops, and convex polyhedra) that can be generated from a point set $P$ [S1, S2]. The approach leverages the mathematical properties of ellipsoids to provide a smooth, conservative distance field suitable for voxel-based rendering and physics [S1, S2].
