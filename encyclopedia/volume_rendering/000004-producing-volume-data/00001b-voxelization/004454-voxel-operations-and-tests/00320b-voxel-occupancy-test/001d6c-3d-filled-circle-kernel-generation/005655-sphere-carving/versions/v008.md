# Sphere Carving

Also called: Carve Sphere, Iterative Sphere Carving, SVO Sphere Carving, SVO modification, Voxel Destruction via SVO, Voxel Sphere Removal, voxel removal

## Overview
Sphere Carving is a voxel operation that removes solid voxels within a spherical radius from a center point in a chunk, primarily used for destructible terrain scenarios [S1, S3, unofficial]. It differs from its sibling [3D Binary Sphere Kernel Generation](4654-3d-binary-sphere-kernel-generation.md), which generates a static binary mask, by actively modifying the voxel grid state (setting voxels to 0/air) and returning metadata about the destruction [S1, S3, unofficial]. It also differs from [Voxel Deformation with Spherical Falloff](4413-voxel-deformation-with-spherical-falloff.md), which uses continuous soft falloff for reversible editing, by performing hard-edged binary removal [S1, unofficial].

## How it works
Sphere Carving operates on a voxel chunk (or Sparse Voxel Octree node) to remove solid voxels intersected by a query sphere [S3, unofficial].

**Inputs and Outputs:**
*   **Inputs:**
    *   `chunk`: The voxel data structure to modify [S1, S3, unofficial].
    *   `cx, cy, cz`: The world-space or local-space center coordinates of the carving sphere [S1, S3, unofficial].
    *   `radius`: The radius of the sphere to carve [S1, S3, unofficial].
    *   `vox_size`: The world size of a single voxel (used to convert world radius to grid units) [S3, unofficial].
    *   `grid_dim`: The dimensions of the voxel grid [S3, unofficial].
*   **Outputs:**
    *   Modified `chunk` with solid voxels inside the sphere set to 0 (air) [S1, S3, unofficial].
    *   `removed_count`: The number of solid voxels removed [S1, S3, unofficial].
    *   `gib_positions`: A list of world positions of the removed voxels, used for spawning debris [S3, unofficial].

**Data Structures:**
*   **Voxel Chunk:** A 3D array or sparse structure where each element represents a voxel. A value of 0 typically denotes air/empty space, while non-zero values denote solid material [S1, S3, unofficial].
*   **VoxObject (Contextual):** In SVO implementations, the chunk is often part of a `VoxObject` struct containing `origin`, `rotation`, `vox_size`, `grid_dim`, `svo` (the octree), `solid_count`, and `dirty` flags [S3, unofficial].

**Steps:**
1.  **Calculate Grid Radius:** Convert the world-space radius to grid units. [S3, unofficial]
    $$ r_{grid} = \frac{radius}{vox\_size} $$
    $$ r2 = r_{grid} \times r_{grid} $$
2.  **Determine Bounding Box:** Calculate the axis-aligned bounding box (AABB) of the sphere in grid coordinates, clamped to the grid dimensions $[0, grid\_dim - 1]$. [S1, S3, unofficial]
    $$ lo(v) = \max(0, \lfloor v - r_{grid} \rfloor) $$
    $$ hi(v) = \min(grid\_dim - 1, \lceil v + r_{grid} \rceil) $$
    Where $v$ is the center coordinate ($cx, cy, cz$) [S1, S3, unofficial].
3.  **Iterate Voxels:** Loop through all voxel indices $(x, y, z)$ within the bounding box [S3, unofficial].
4.  **Distance Check:** For each voxel, calculate the squared distance from the voxel center to the sphere center. [S3, unofficial]
    $$ dx = x + 0.5 - cx $$
    $$ dy = y + 0.5 - cy $$
    $$ dz = z + 0.5 - cz $$
    $$ dist2 = dx^2 + dy^2 + dz^2 $$
    If $dist2 > r2$, continue to the next voxel [S1, S3, unofficial].
5.  **Remove Voxel:** If the voxel is solid (value $\neq 0$):
    *   Set `chunk.set(x, y, z, 0)` to remove it [S1, unofficial].
    *   Calculate the world position of the removed voxel [S3, unofficial].
    *   Add the world position to `gib_positions` [S3, unofficial].
    *   Increment `removed_count` [S1, S3, unofficial].
6.  **Update State:** After the loop, if `removed_count > 0`:
    *   Update `solid_count` by subtracting `removed_count` [S3, unofficial].
    *   Mark the object/mesh as `dirty` to trigger a rebuild or update [S3, unofficial].
    *   Return `removed_count` and `gib_positions` [S1, S3, unofficial].

**Pseudocode:**
```python
import math

def sphere_carving(chunk, cx, cy, cz, radius, vox_size, grid_dim):
    # 1. Calculate grid radius
    r_grid = radius / vox_size
    r2 = r_grid * r_grid
    
    removed_count = 0
    gib_positions = []
    
    # 2. Determine bounding box
    lo_x = max(0, math.floor(cx - r_grid))
    hi_x = min(grid_dim - 1, math.ceil(cx + r_grid))
    lo_y = max(0, math.floor(cy - r_grid))
    hi_y = min(grid_dim - 1, math.ceil(cy + r_grid))
    lo_z = max(0, math.floor(cz - r_grid))
    hi_z = min(grid_dim - 1, math.ceil(cz + r_grid))
    
    # 3. Iterate voxels
    for z in range(lo_z, hi_z + 1):
        for y in range(lo_y, hi_y + 1):
            for x in range(lo_x, hi_x + 1):
                # 4. Distance check
                dx = (x + 0.5) - cx
                dy = (y + 0.5) - cy
                dz = (z + 0.5) - cz
                dist2 = dx*dx + dy*dy + dz*dz
                
                if dist2 <= r2:
                    # 5. Remove voxel if solid
                    if chunk.get(x, y, z) != 0:
                        chunk.set(x, y, z, 0)
                        
                        # Calculate world position for gib
                        world_x = (x + 0.5) * vox_size
                        world_y = (y + 0.5) * vox_size
                        world_z = (z + 0.5) * vox_size
                        gib_positions.append((world_x, world_y, world_z))
                        
                        removed_count += 1
    
    # 6. Update state
    if removed_count > 0:
        chunk.solid_count -= removed_count
        chunk.dirty = True
        
    return removed_count, gib_positions
```

**Parameters:**
*   `radius`: Radius of the carving sphere [S1, S3, unofficial].
*   `vox_size`: World units per voxel [S3, unofficial].
*   `grid_dim`: Power-of-two grid size [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Clamping:** The bounding box must be strictly clamped to $[0, grid\_dim - 1]$ to prevent out-of-bounds memory access [S1, S3, unofficial].
*   **Precision:** Using squared distances avoids expensive square root operations [S1, S3, unofficial].
*   **Empty Chunks:** If the chunk contains no solid voxels, the loop completes with `removed_count = 0`, and no state update is needed [S3, unofficial].

## Subtopics

### [Voxel Deformation with Spherical Falloff](4413-voxel-deformation-with-spherical-falloff.md)
Voxel Deformation with Spherical Falloff modifies scalar voxel values (typically density) within a spherical region around a 3D hit point to add or remove terrain mass, creating smooth edges for digging or building operations. It differs from [Sphere Carving](2377-sphere-carving.md), which removes solid voxels within a binary radius, by using a continuous soft falloff to allow gradual mass modification and reversible editing. It serves as the core mechanism for [Voxel Edit Brush Operations](6271-voxel-edit-brush-operations.md), enabling real-time interaction with the density field.

### [Bounding Ellipsoids from SDFs](4529-bounding-ellipsoids-from-sdfs.md)
This method generates a conservative Signed Distance Function (SDF) for a shape by approximating its geometry with a minimum-volume enclosing ellipsoid. It serves as an alternative to convex polyhedra or oriented bounding boxes within the Sphere Carving pipeline. Unlike convex hulls which require $n$ scalar products for $n$ faces, ellipsoids offer a more compact memory footprint and constant-time evaluation complexity, making them suitable for real-time applications where geometric fidelity is balanced against computational cost.

### [Voxel Edit Brush Operations](6271-voxel-edit-brush-operations.md)
Voxel Edit Brush Operations provide a set of interactive tools (Place, Carve, Fill, Paint) for modifying unbounded 3D voxel grids using world-space spherical or cylindrical selection volumes. The method solves the problem of real-time, view-independent sculpting and material insertion in volumetric data, ensuring consistent behavior across chunk boundaries by addressing voxels via unbounded world-grid coordinates rather than local indices. Unlike parent methods that may rely on sparse structures or offline processing, this approach utilizes dense 3D textures for mask lookups to enable O(1) per-fragment operations.

### [Procedural Sphere Placement](8171-procedural-sphere-placement.md)
Procedural Sphere Placement populates a 3D voxel grid with spherical voids (density 0) inside a background field (density 255), using pre-sampled coordinates and random radii. Not given in the sources.

### Voxel Annihilation
Voxel Annihilation removes all solid voxels from the entire SVO grid, used when a hit's effective power is overwhelmingly larger than the object's hp [S3, unofficial]. It iterates through all grid indices $(x, y, z)$ from 0 to `grid_dim` [S3, unofficial]. If the voxel at $(x, y, z)$ is solid, it is removed from the SVO, its world position is calculated, and it is added to `gib_positions` [S3, unofficial]. After the loop, `solid_count` is set to 0 and `dirty` is set to true [S3, unofficial].

### Collision and Destructibility with Empty Zones
This method integrates KRS into collision detection by creating empty zones via unbounding spheres and substituting them with physically simulated kernel instances [S5]. It creates empty zones by specifying unbounding spheres over subsets of the KRS, skips these regions during sphere tracing, substitutes the subset of the KRS within these empty zones with instances of kernel geometry rendered incrementally, and applies physical simulation to these solid instances [S5]. A pitfall is that KRS is not locally controllable [S5]. An example is a tree branch breaking by covering the complete tree with an empty sphere and building an identical tree of rigid body branches and leaves independently [S5].

### Boolean Geometry Terrain Subtraction
This method supports perfect spherical or smooth tunnel generation by subtracting geometric primitives from the terrain using boolean operations [S6, unofficial]. It defines a center point and radius to subtract a sphere, or defines a line to subtract voxels based on distance from the line to create a pill shape (line with spherical ends) [S6, unofficial]. Supported boolean operations include sphere subtraction and line/pill subtraction [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** The basic voxel iteration is $O(r^3)$ where $r$ is the radius in voxels, as it visits every voxel in the bounding box [S1, S3, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary memory for loop variables. Returning `gib_positions` requires $O(k)$ memory where $k$ is the number of removed voxels [S3, unofficial]. Source [S1, unofficial] returns only the removal count.
*   **Performance:** The operation is efficient for real-time destructible terrain. Clamping the bounding box ensures no out-of-bounds checks are needed inside the loop, optimizing performance [S1, S3, unofficial].
*   **Strengths:** Simple to implement, deterministic, and provides explicit feedback on destroyed voxels (positions) for visual effects (gibs) [S1, S3, unofficial].
*   **Limitations:** It is a binary operation (solid/air) and does not support partial destruction or smooth erosion without additional logic [S1, unofficial]. It requires the caller to manage the coordinate transformation (world to local/grid) if the chunk uses a local coordinate system [S3, unofficial].

## Background
Sphere Carving is a fundamental voxel operation used in voxel-based games and simulations for destructible environments [S1, S3, unofficial]. It is implemented in engines like Prometheus Engine for handling object destruction [S3, unofficial] and in voxel terrain systems like dVoxels for cave generation and player interaction [S1, unofficial]. The method is distinct from the "Sphere Carving" algorithm for bounding volume generation for SDFs [S2], which uses a similar name but serves a different purpose (computing bounding proxies for acceleration). In the context of voxel occupancy, it is a direct application of the 3D filled circle kernel logic to modify grid state [S1, S3, unofficial].
