# Broad-phase Collision Detection (Sweep and Prune)

Also called: GPU Broad-phase collision system, Sweep and Prune

## Overview
A broad-phase collision detection algorithm that sorts projected extents of objects' bounding boxes on cartesian axes to determine overlaps [S1, unofficial]. It differs from narrow-phase methods by identifying potential collisions without precise geometric intersection tests, serving as a filter to reduce the complexity of the subsequent narrow-phase stage [S1, unofficial].

## How it works
**Inputs:** A set of objects, each represented by an Axis-Aligned Bounding Box (AABB).
**Outputs:** A list of object pairs whose AABBs overlap in all three dimensions (x, y, and z).

**Data Structures:**
1.  **AABB List:** Each object $i$ has an AABB defined by minimum and maximum coordinates $(min_x, min_y, min_z)$ and $(max_x, max_y, max_z)$.
2.  **Record List:** A flat list of records generated from the AABBs. Each AABB contributes two records. A record contains:
    *   `coordinate`: The float value of the min or max extent.
    *   `object_id`: The integer index of the object.
    *   `type_bit`: A boolean or integer flag (0 for min, 1 for max) indicating if the coordinate is the minimum or maximum bound.

**Algorithm Steps:**

1.  **Compute AABBs:** Calculate the AABB for each object. On a GPU, this is typically done using parallel reduction to find the global minimum and maximum coordinates of the mesh vertices [S1, unofficial].
2.  **Generate Records:** Create the record list. For each object $i$ with bounds $[min, max]$, add two records:
    *   Record A: `(min_x, i, min_bit)`
    *   Record B: `(max_x, i, max_bit)`
    *   Repeat for y and z dimensions in separate passes or interleaved lists.
3.  **Sort:** Sort the record list based on the `coordinate` field in ascending order. Radix sort is commonly used for efficiency on GPUs [S1, unofficial].
4.  **Scan for Overlaps (X-axis):**
    *   Iterate through the sorted list.
    *   Identify "out-of-order" indices. An out-of-order condition occurs when a record with `type_bit == min` for object $A$ is followed by a record with `type_bit == min` for object $B$ (where $A \neq B$) before the `max` record for object $A$ is encountered.
    *   Specifically, if the current record is a `min` for object $A$, and the previous record was a `min` for object $B$, then objects $A$ and $B$ overlap in the x-projection.
    *   Use the `type_bit` to ensure each pair is detected only once (e.g., only process when the current record is a `min` and the previous was a `min` of a different object).
5.  **Filter by Axis:**
    *   Generate a new list of object pairs that overlap in the x-dimension.
    *   Repeat steps 2-4 for the y-dimension, using the list of pairs from the x-step as the input candidates.
    *   Repeat steps 2-4 for the z-dimension, using the list of pairs from the y-step as the input candidates.
6.  **Return:** The final list of object pairs that overlap in all three dimensions is returned for narrow-phase collision detection on the CPU [S1, unofficial].

**Pseudocode:**

```python
def broad_phase_sweep_and_prune(objects):
    """
    objects: List of objects, each having an AABB with min and max vectors.
    Returns: List of pairs (i, j) of overlapping object indices.
    """
    # Step 1 & 2: Generate records for a specific axis (e.g., X)
    # Returns a list of tuples: (coordinate, object_index, is_min)
    def generate_records(axis='x'):
        records = []
        for idx, obj in enumerate(objects):
            if axis == 'x':
                min_val = obj.aabb.min.x
                max_val = obj.aabb.max.x
            elif axis == 'y':
                min_val = obj.aabb.min.y
                max_val = obj.aabb.max.y
            else: # axis == 'z'
                min_val = obj.aabb.min.z
                max_val = obj.aabb.max.z
            
            records.append((min_val, idx, True))  # True for min
            records.append((max_val, idx, False)) # False for max
        return records

    # Step 3: Sort records
    def sort_records(records):
        # Stable sort by coordinate
        return sorted(records, key=lambda r: r[0])

    # Step 4: Scan for overlaps
    def find_overlaps(records):
        overlaps = set()
        # Track active objects (those whose min has been seen but max has not)
        # In a sweep and prune, we look for min-min conflicts in the sorted list
        # if we process strictly by coordinate.
        # However, the source describes scanning for out-of-order indices.
        # A standard sweep and prune maintains an active list.
        # Based on [S1, unofficial]: "scan for a min index of one bounding box 
        # not being followed by the max index of the same AABB but by an index 
        # of another AABB."
        
        # We iterate through the sorted list.
        # If we see a MIN for object A, and the previous element was a MIN for object B,
        # then A and B are overlapping in this axis.
        
        active_min_indices = [] # List of object indices currently in the sweep line (min seen, max not)
        
        for coord, obj_idx, is_min in records:
            if is_min:
                # This object just entered the sweep line
                # Check against all other objects currently in the sweep line
                for other_idx in active_min_indices:
                    if other_idx != obj_idx:
                        overlaps.add((min(obj_idx, other_idx), max(obj_idx, other_idx)))
                active_min_indices.append(obj_idx)
            else:
                # This object is leaving the sweep line
                if obj_idx in active_min_indices:
                    active_min_indices.remove(obj_idx)
        
        return list(overlaps)

    # Initial list of all pairs (or just indices 0..N-1 if starting from scratch)
    # The source implies repeating the process. 
    # Usually, broad phase starts with all objects.
    # Let's assume we start with all pairs for the first axis, or just all objects.
    # The source says: "Generate a new list of AABBs which overlap... 
    # This entire process is repeated in y- and z-direction using the overlap list of the previous scan"
    
    # To implement "using the overlap list of the previous scan", we filter objects.
    # But standard SAP works on all objects. The source likely implies a hierarchical 
    # or iterative filtering. Given the text "From the AABBs associated with the 
    # out of order indices a new list of AABBs... is generated", it suggests filtering.
    
    # Let's implement the iterative filtering as described.
    
    # Start with all objects
    current_candidates = list(range(len(objects)))
    
    for axis in ['x', 'y', 'z']:
        # Filter objects to only those in current_candidates
        candidate_objects = [objects[i] for i in current_candidates]
        
        # We need to map back to original indices
        # Re-generate records for these candidates
        records = []
        for local_idx, orig_idx in enumerate(current_candidates):
            obj = objects[orig_idx]
            if axis == 'x':
                min_val = obj.aabb.min.x
                max_val = obj.aabb.max.x
            elif axis == 'y':
                min_val = obj.aabb.min.y
                max_val = obj.aabb.max.y
            else:
                min_val = obj.aabb.min.z
                max_val = obj.aabb.max.z
            
            records.append((min_val, orig_idx, True))
            records.append((max_val, orig_idx, False))
            
        sorted_records = sort_records(records)
        overlaps = find_overlaps(sorted_records)
        
        # The overlaps are pairs. We need to generate the next candidate list.
        # The source says "return the small list of actually overlapping AABBs".
        # This implies the output of this stage is the pairs.
        # But it also says "repeated... using the overlap list".
        # This suggests the 'overlap list' is the set of pairs.
        # For the next axis, we only test pairs that passed the previous axis.
        
        if axis == 'x':
            # First axis: all pairs are potential. 
            # But we need to pass pairs to the next stage.
            # The find_overlaps returns pairs.
            next_candidates_pairs = overlaps
        else:
            # For Y and Z, we only test pairs that survived the previous axis.
            # But the algorithm needs to re-run the sweep on the objects involved?
            # No, it re-runs the sweep on the *pairs*? 
            # Actually, standard SAP doesn't work on pairs. It works on objects.
            # The source description is slightly ambiguous: "repeated in y- and z-direction 
            # using the overlap list of the previous scan".
            # This likely means: 
            # 1. Find X-overlaps.
            # 2. For Y, only check pairs that overlapped in X.
            # 3. For Z, only check pairs that overlapped in X and Y.
            
            # To do this efficiently, we don't re-sweep all objects. 
            # We just check the Y and Z bounds of the pairs found in the previous step.
            # However, the source says "Generate a new list of AABBs... This entire process is repeated".
            # This implies a full sweep on a subset.
            
            # Let's stick to the source's literal instruction:
            # "From the AABBs associated with the out of order indices a new list of AABBs 
            # which overlap in x projection is generated."
            # This new list is used for the next axis.
            
            # So, for Y, we take the objects involved in X-overlaps? 
            # Or the pairs? 
            # If we take the pairs, we can't do a sweep.
            # We must take the objects.
            
            # Let's assume the "overlap list" refers to the set of objects that are part of 
            # any overlap in the previous axis.
            unique_objects_in_overlaps = set()
            for p1, p2 in overlaps:
                unique_objects_in_overlaps.add(p1)
                unique_objects_in_overlaps.add(p2)
            
            current_candidates = list(unique_objects_in_overlaps)
            
            # Re-run sweep on these candidates
            records = []
            for local_idx, orig_idx in enumerate(current_candidates):
                obj = objects[orig_idx]
                if axis == 'x':
                    min_val = obj.aabb.min.x
                    max_val = obj.aabb.max.x
                elif axis == 'y':
                    min_val = obj.aabb.min.y
                    max_val = obj.aabb.max.y
                else:
                    min_val = obj.aabb.min.z
                    max_val = obj.aabb.max.z
                
                records.append((min_val, orig_idx, True))
                records.append((max_val, orig_idx, False))
                
            sorted_records = sort_records(records)
            overlaps = find_overlaps(sorted_records)
            
            if axis == 'z':
                final_overlaps = overlaps
                break

    return final_overlaps
```

**Parameters:**
*   Sorting Algorithm: Radix sort is preferred for GPU implementation [S1, unofficial].
*   Data Size: Performance scales with the number of objects; GPU becomes more efficient with increasing data size [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision in coordinate comparisons can lead to missed overlaps or false positives. [G] Use epsilon comparisons if necessary.
*   **Degenerate AABBs:** Objects with zero volume (min == max) should be handled carefully to avoid empty intervals. [G] Treat as a single point or exclude.
*   **Sorting Cost:** Sorting accounts for approximately 70% of the overall performance [S1, unofficial].

## Subtopics

### Narrow-phase Collision Detection
Determines precise intersection points and normals for the pairs identified by the broad phase. Choose when exact collision response is needed. See [Narrow-phase Collision Detection](5414-narrow-phase-collision-detection.md).

### Spatial Partitioning (Grid/Tree)
Alternative broad-phase methods using spatial structures. Choose when objects are static or move slowly. See [Spatial Partitioning](5412-spatial-partitioning.md).

## Operating characteristics
*   **Time Complexity:** Dominated by sorting, typically $O(N \log N)$ or $O(N)$ with radix sort, where $N$ is the number of objects. The scan is $O(N)$.
*   **Memory Complexity:** $O(N)$ for storing records and overlap lists.
*   **Measured Performance:** On an NVIDIA Quadro FX 5600, the GPU implementation showed a 1.5x to 2.0x speedup compared to a highly optimized CPU implementation using an AMD Opteron 275 processor with 6 GB memory [S1, unofficial].
*   **Scaling:** The GPU approach becomes more efficient with increasing data size [S1, unofficial].
*   **Strengths:** Efficient for dynamic scenes with many objects; leverages GPU parallelism for sorting.
*   **Limitations:** Sorting is the bottleneck (70% of performance) [S1, unofficial]. Requires careful implementation to handle out-of-order indices correctly.

## Background
The sweep and prune strategy is a proven broad-phase algorithm. The specific GPU implementation described was developed by Linh et al. and published in *Computer Graphics Forum* (2009) [S1, unofficial]. It was designed to accelerate collision detection by embedding an optimized GPU-based radix sorting system as the core algorithm [S1, unofficial].
