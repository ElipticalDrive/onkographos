# Voxel Occupancy Test

Also called: Inclusion Test

## Overview
The Voxel Occupancy Test determines whether a set of query points lies within any occupied voxel of a pre-existing voxel grid. It solves the problem of fast spatial containment queries for point clouds or particle systems against a discretized volume. It differs from [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) and [Interior Voxelize](995-interior-voxelize.md) by not generating the grid itself, but rather querying an existing structure. It differs from [VoxelGrid from Mesh (Ray Method)](1012-voxelgrid-from-mesh-ray-method.md) by operating on discrete point queries rather than continuous ray intersections.

## How it works
**Inputs:**
1. A voxel grid data structure containing occupied voxels.
2. An array of query points $P$ with shape $(N, 3)$, where each row is a coordinate $(x, y, z)$.

**Outputs:**
1. A boolean array $B$ of length $N$, where $B[i]$ is `True` if point $P[i]$ is inside an occupied voxel, and `False` otherwise.

**Data Structures:**
The voxel grid typically stores occupancy in a sparse hash map or a dense array, indexed by voxel coordinates. Voxel coordinates $(v_x, v_y, v_z)$ are derived from world coordinates $(x, y, z)$ and the voxel size $s$ via:
$$ v_x = \lfloor x / s \rfloor, \quad v_y = \lfloor y / s \rfloor, \quad v_z = \lfloor z / s \rfloor $$
Note: Floor division behavior for negative coordinates must be consistent with the grid's creation method.

**Steps:**
1. For each query point $P[i] = (x_i, y_i, z_i)$:
2. Compute the voxel indices $(v_{x,i}, v_{y,i}, v_{z,i})$ using the voxel size $s$ associated with the grid.
3. Check if the voxel at $(v_{x,i}, v_{y,i}, v_{z,i})$ is marked as occupied in the grid's storage.
4. Set $B[i]$ to `True` if occupied, `False` otherwise.

**Pseudocode:**
```python
def voxel_occupancy_test(voxel_grid, query_points, voxel_size):
    """
    voxel_grid: A data structure supporting lookup by voxel index (e.g., set of tuples or hash map).
    query_points: List of (x, y, z) tuples or array of shape (N, 3).
    voxel_size: Float, the side length of a single voxel.
    
    Returns:
    bool_array: List of booleans corresponding to each query point.
    """
    results = []
    for point in query_points:
        x, y, z = point
        
        # Compute voxel indices
        # Using floor division to map continuous coordinates to discrete grid indices
        vx = int(x // voxel_size)
        vy = int(y // voxel_size)
        vz = int(z // voxel_size)
        
        # Check if this voxel is occupied in the grid
        # Implementation detail: The specific lookup mechanism depends on the grid's internal storage
        # (e.g., hash set, sparse array, or dense array).
        is_occupied = voxel_grid.contains(vx, vy, vz)
        
        results.append(is_occupied)
        
    return results
```

**Parameters:**
- `voxel_size`: Must match the resolution used to create the `voxel_grid`. Mismatched sizes lead to incorrect index mapping.

**Edge Cases and Pitfalls:**
- **Negative Coordinates:** Floor division for negative numbers behaves differently in some languages (e.g., Python's `//` vs C++'s `/`). Ensure the index calculation matches the grid's coordinate system origin and direction.
- **Boundary Conditions:** Points exactly on voxel boundaries may be assigned to different voxels depending on the floor/ceil implementation. Consistency with the voxelization method is critical.
- **Empty Grid:** If the grid has no occupied voxels, the output is all `False`.

## Subtopics

### [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md)
The Point-in-Box Inclusion Test determines which points from a given array lie within an orthogonal bounding box. It serves as the core primitive for Voxel Occupancy Test, filtering points to identify voxel occupancy. Unlike [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md) which uses distance metrics, this method relies on strict axis-aligned boundary checks. It differs from [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md) by operating on a static point array rather than dynamic collision shapes.

### [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md)
This method generates a 3D binary kernel (mask) where voxels within a specified Euclidean distance from the center are set to 1, and others are set to 0. It solves the problem of defining a discrete spherical occupancy region for voxel-based operations, such as smoothing, collision detection, or volume initialization. It differs from its sibling [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by using radial distance rather than axis-aligned bounds, and from its sibling [Voxel Filled Check](1705-voxel-filled-check.md) by generating a full kernel array rather than testing a single point.

### [Voxel Filled Check](1705-voxel-filled-check.md)

### [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md)
The Sparse AABB Collision Test determines whether an Axis-Aligned Bounding Box (AABB) intersects any occupied voxels within a sparse volume representation. It solves the problem of static collision detection for volumetric objects by iterating through the voxel grid defined by the AABB's bounds. It differs from its sibling [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by evaluating a continuous volume rather than discrete points, and from [Voxel Filled Check](1705-voxel-filled-check.md) by supporting heterogeneous voxel types (solid, liquid, unknown) and caching terrain noise evaluation per column to optimize performance.

### [Solidity Check](4229-solidity-check.md)
Solidity Check determines if a specific voxel coordinate in a 3D world is occupied by solid geometry or is void (empty). It solves the problem of boundary condition handling during voxel traversal, ensuring that out-of-bounds regions are treated consistently to prevent rendering artifacts. It differs from its sibling [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by explicitly managing chunk-based spatial indexing and asymmetric boundary wrapping for X/Y versus Z axes, rather than simple AABB containment.

### [Sphere-Clamped Voxel Neighbor Search](5131-sphere-clamped-voxel-neighbor-search.md)
Sphere-Clamped Voxel Neighbor Search finds the closest voxel cell to a query point within a specified radius, constrained to the grid boundaries. It solves the problem of locating the nearest occupied or valid material cell in a voxelized environment for operations like ray casting or neighbor lookups. It differs from [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by using a spherical distance metric and from [Voxel Filled Check](1705-voxel-filled-check.md) by returning the specific closest cell rather than a boolean occupancy status.

## Operating characteristics
- **Time Complexity:** $O(N)$ for $N$ query points, assuming $O(1)$ average-case lookup in the voxel grid's underlying storage (e.g., hash map).
- **Memory Complexity:** $O(1)$ additional memory per query point, excluding the storage of the result array.
- **Strengths:** Extremely fast for point containment queries; leverages existing voxelization structures.
- **Limitations:** Only works for point queries; does not handle partial voxel occupancy or continuous geometry directly.
- **When to use:** When you need to test if particles or points lie inside a pre-computed voxel volume.
- **When not to use:** For continuous collision detection or ray tracing; use [VoxelGrid from Mesh (Ray Method)](1012-voxelgrid-from-mesh-ray-method.md) or [Raycasting](908-rasterization-based-voxelization.md) instead.

## Background
The Voxel Occupancy Test is a fundamental operation in voxel-based graphics and simulation, often implemented as a method on voxel grid data structures. It is commonly used in point cloud processing, physics simulations, and spatial queries. The method `check_if_included` is explicitly documented in the Open3D library [S1]. The concept of simple grid checks for collision is also noted in the context of voxel game engines [S2, unofficial].
