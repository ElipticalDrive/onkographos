# Sphere-Clamped Voxel Neighbor Search
## Overview
Sphere-Clamped Voxel Neighbor Search retrieves the voxel cell whose center is closest to a query point, restricted to a spherical search radius and bounded by the grid extents [S1, unofficial]. It finds the nearest valid material cell within a local neighborhood [S1, unofficial]. It differs from [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by enforcing a spherical distance constraint rather than an axis-aligned bounding box, and from [Moore Neighbourhood Sampling](16763-moore-neighbourhood-sampling.md) by returning only the single closest valid cell rather than all 27 neighbors [S1, unofficial].

## How it works
**Inputs:**
- `query_pt`: Query point in world coordinates ($\mathbb{R}^3$) [S1, unofficial].
- `radius`: Search radius in world units [S1, unofficial].
- `p`: Grid parameters including `voxel_size_m` (X/Z cell width), `height_step_m` (Y cell height), `base_depth_m` (Y-axis offset), `extent` (X/Z grid dimension), and `height_cells` (Y grid dimension) [S1, unofficial].
- `grid`: Spatial data structure providing `column_center_x(ix)`, `column_center_z(iz)`, `cell_bottom_y(iy)`, and `cell_index(ix, iy, iz)` [S1, unofficial].
- `mats`: Linear array of material objects indexed by linear cell index [S1, unofficial].
- `pred`: Predicate function `bool(VoxMat)` determining if a material is valid for selection [S1, unofficial].

**Outputs:**
- `best`: The world coordinates of the center of the closest valid cell, or `None` if no cell is found within the sphere [S1, unofficial].

**Data Structures:**
- The grid is stored as a linear array `mats` of material objects [S1, unofficial].
- 3D voxel coordinates $(ix, iy, iz)$ are mapped to a linear index via `grid.cell_index(ix, iy, iz)` [S1, unofficial].
- Coordinate conversion functions map integer voxel indices to world coordinates:
  - $cx = \text{grid.column\_center\_x}(ix)$ [S1, unofficial]
  - $cz = \text{grid.column\_center\_z}(iz)$ [S1, unofficial]
  - $cy = \text{grid.cell\_bottom\_y}(iy) + 0.5 \times p.\text{height\_step\_m}$ [S1, unofficial]

**Steps:**
1. Compute the integer bounding box of the search sphere clamped to the grid extents [S1, unofficial].
   - For X and Z axes:
     $$ ix_0 = \text{clamp}\left(\left\lfloor \frac{\text{query\_pt}.x - \text{radius} + 0.5 \times p.\text{voxel\_size\_m}}{p.\text{voxel\_size\_m}} \right\rfloor, 0, p.\text{extent} - 1\right) $$
     $$ ix_1 = \text{clamp}\left(\left\lfloor \frac{\text{query\_pt}.x + \text{radius} + 0.5 \times p.\text{voxel\_size\_m}}{p.\text{voxel\_size\_m}} \right\rfloor, 0, p.\text{extent} - 1\right) $$
     $$ iz_0 = \text{clamp}\left(\left\lfloor \frac{\text{query\_pt}.z - \text{radius} + 0.5 \times p.\text{voxel\_size\_m}}{p.\text{voxel\_size\_m}} \right\rfloor, 0, p.\text{extent} - 1\right) $$
     $$ iz_1 = \text{clamp}\left(\left\lfloor \frac{\text{query\_pt}.z + \text{radius} + 0.5 \times p.\text{voxel\_size\_m}}{p.\text{voxel\_size\_m}} \right\rfloor, 0, p.\text{extent} - 1\right) $$
   - For Y axis:
     $$ iy_0 = \text{clamp}\left(\left\lfloor \frac{\text{query\_pt}.y - \text{radius} + p.\text{base\_depth\_m}}{p.\text{height\_step\_m}} \right\rfloor, 0, p.\text{height\_cells} - 1\right) $$
     $$ iy_1 = \text{clamp}\left(\left\lfloor \frac{\text{query\_pt}.y + \text{radius} + p.\text{base\_depth\_m}}{p.\text{height\_step\_m}} \right\rfloor, 0, p.\text{height\_cells} - 1\right) $$
   - The term $0.5 \times p.\text{voxel\_size\_m}$ represents half the voxel size, used to align the floor/ceiling of the search range with voxel boundaries [S1, unofficial]. The Y-axis uses `base_depth_m` instead of half-height, implying an offset coordinate system [S1, unofficial].
2. Initialize `best` to `None`, `best2` to $\infty$, and `found` to `false` [S1, unofficial].
3. Iterate through all integer coordinates $(ix, iy, iz)$ such that $ix_0 \le ix \le ix_1$, $iy_0 \le iy \le iy_1$, and $iz_0 \le iz \le iz_1$ [S1, unofficial].
4. For each cell, compute the linear index `idx = grid.cell_index(ix, iy, iz)` and retrieve the material `m = mats[idx]` [S1, unofficial].
5. If `pred(m)` is false, continue to the next cell [S1, unofficial].
6. Compute the center coordinates of the current cell:
   - $cx = \text{grid.column\_center\_x}(ix)$ [S1, unofficial]
   - $cz = \text{grid.column\_center\_z}(iz)$ [S1, unofficial]
   - $cy = \text{grid.cell\_bottom\_y}(iy) + 0.5 \times p.\text{height\_step\_m}$ [S1, unofficial]
7. Compute the squared Euclidean distance from `query_pt` to the cell center:
   - $dx = cx - \text{query\_pt}.x$
   - $dy = cy - \text{query\_pt}.y$
   - $dz = cz - \text{query\_pt}.z$
   - $d2 = dx^2 + dy^2 + dz^2$ [S1, unofficial]
8. If $d2 \le \text{radius}^2$ and (`!found` or $d2 < \text{best2}$):
   - Update `best2 = d2`
   - Update `best = (cx, cy, cz)`
   - Set `found = true` [S1, unofficial]
   - The strict inequality $d2 < \text{best2}$ ensures that if multiple cells are equidistant, the first one encountered in the iteration order (lowest index) is retained [S1, unofficial].
9. After the loop, if `found` is true, return `best`. Otherwise, return `None` [S1, unofficial].

**Pseudocode:**
```python
import math

def clamp(val, min_val, max_val):
    return max(min_val, min(val, max_val))

def sphere_clamped_voxel_neighbor_search(query_pt, radius, p, grid, mats, pred):
    r2 = radius * radius
    half_voxel = 0.5 * p.voxel_size_m
    
    ix0 = clamp(math.floor((query_pt.x - radius + half_voxel) / p.voxel_size_m), 0, p.extent - 1)
    ix1 = clamp(math.floor((query_pt.x + radius + half_voxel) / p.voxel_size_m), 0, p.extent - 1)
    iz0 = clamp(math.floor((query_pt.z - radius + half_voxel) / p.voxel_size_m), 0, p.extent - 1)
    iz1 = clamp(math.floor((query_pt.z + radius + half_voxel) / p.voxel_size_m), 0, p.extent - 1)
    
    iy0 = clamp(math.floor((query_pt.y - radius + p.base_depth_m) / p.height_step_m), 0, p.height_cells - 1)
    iy1 = clamp(math.floor((query_pt.y + radius + p.base_depth_m) / p.height_step_m), 0, p.height_cells - 1)
    
    best = None
    best2 = float('inf')
    found = False
    
    for iy in range(iy0, iy1 + 1):
        for ix in range(ix0, ix1 + 1):
            for iz in range(iz0, iz1 + 1):
                idx = grid.cell_index(ix, iy, iz)
                m = mats[idx]
                
                if not pred(m):
                    continue
                
                cx = grid.column_center_x(ix)
                cz = grid.column_center_z(iz)
                cy = grid.cell_bottom_y(iy) + 0.5 * p.height_step_m
                
                dx = cx - query_pt.x
                dy = cy - query_pt.y
                dz = cz - query_pt.z
                d2 = dx*dx + dy*dy + dz*dz
                
                if d2 <= r2 and (not found or d2 < best2):
                    best2 = d2
                    best = (cx, cy, cz)
                    found = True
                    
    return best if found else None
```

**Parameters:**
- `radius`: Search radius in world units [S1, unofficial].
- `query_pt`: Query point [S1, unofficial].
- `p.voxel_size_m`: Width of a voxel in X/Z dimensions [S1, unofficial].
- `p.height_step_m`: Height of a voxel in Y dimension [S1, unofficial].
- `p.base_depth_m`: Offset for Y-axis voxel indexing. Clamped to $[0.5, 100.0]$ in configuration [S1, unofficial].
- `p.extent`: Number of voxels in X and Z dimensions [S1, unofficial].
- `p.height_cells`: Number of voxels in Y dimension. Clamped to $[16, 512]$ in configuration [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point division and floor operations may cause off-by-one errors at boundaries. The clamping to grid extents prevents out-of-bounds access but may exclude valid neighbors if the query point is very close to the edge [S1, unofficial].
- **Ties:** The strict inequality $d2 < \text{best2}$ means that if two cells are exactly equidistant, the one with the lower linear index (determined by iteration order) is chosen [S1, unofficial].
- **Empty Grid:** If no cells satisfy the predicate or are within the radius, the function returns `None` [S1, unofficial].
- **Degenerate Input:** If `radius` is 0, only the cell containing `query_pt` (if any) is considered. If `voxel_size_m` or `height_step_m` is 0, division by zero occurs [G].

## Subtopics

### [PBF Displacement Calculation with Grid-Based Neighbor Search](9026-pbf-displacement-calculation-with-grid-based-neighbor-search.md)
PBF Displacement Calculation with Grid-Based Neighbor Search is a particle-based fluid simulation step that calculates particle displacements to enforce incompressibility via density constraints. It operates by using a spatial hash grid to identify neighboring particles within a search radius and applying separation forces to push particles apart if they are too close.

### [Moore Neighbourhood Sampling](16763-moore-neighbourhood-sampling.md)
Moore Neighbourhood Sampling reads the values of all 27 voxels in a 3x3x3 block centered on a target voxel, returning both the data and a bitmask indicating which neighbors are non-empty [G]. It serves as the foundational data access primitive for local voxel operations, such as the Sphere-Clamped Voxel Neighbor Search [G]. It is distinguished from its sibling [PBF Displacement Calculation with Grid-Based Neighbor Search](9026-pbf-displacement-calculation-with-grid-based-neighbor-search.md) by its fixed, exhaustive 27-neighbor scope rather than a physics-based radius search [G].

### Voxel Caching for Haptic Collision Detection
Voxel Caching for Haptic Collision Detection is an iterative, step-based approach to find the nearest voxels to a burr-head for caching, minimizing the number of voxels the haptic thread needs to investigate for collisions [S2, book]. Let $r$ be the burr radius. The loop iterates through distances $3r, 5r, 7r$, etc. (incrementing by $2r$), looking for any voxels within that distance of the burr-head center [S2, book]. If at least one voxel is found at the current distance, it is sent to the haptic thread for caching and the loop stops [S2, book]. If no voxels are found within $23r$ of the burr-head, the search quits, as experimentation determined that beyond this distance the voxel set is sufficiently far that the tool is unlikely to contact objects between cache updates, even at high speeds [S2, book]. If collision detection uses the triangle mesh method, all triangles part of the mesh within the same "nearest distance" to the burr head are also sent to the haptic thread for caching [S2, book].

## Operating characteristics
- **Time Complexity:** $O(R^3)$, where $R$ is the number of voxels along one axis of the search sphere [G]. Specifically, it iterates over the bounding box of the sphere, which contains approximately $\frac{4}{3}\pi r^3$ voxels, where $r$ is the radius in voxel units [G].
- **Memory Complexity:** $O(1)$ auxiliary space, excluding the grid storage [G].
- **Measured Performance:** Not given in the sources [G].
- **Scaling:** Performance scales linearly with the volume of the search sphere. For large radii, this becomes expensive compared to sparse data structures [G].
- **Strengths:** Simple to implement, robust to grid boundaries, and provides a deterministic result for the closest cell [G].
- **Limitations:** Inefficient for sparse grids as it iterates over empty space. Does not support early termination based on distance if the bounding box is large [G].
- **When to Use:** When a single closest neighbor within a spherical radius is needed, and the grid is dense or the search radius is small [G].
- **When Not to Use:** For sparse grids with large search radii, or when multiple neighbors are required [G].

## Background
The method is derived from the voxel ocean simulation codebase, specifically the neighbor search logic used for fluid or particle interactions [S1, unofficial]. It is part of a larger system that includes voxelization, marching, and rendering configurations [S1, unofficial]. The implementation uses a clamped bounding box approach to efficiently limit the search space to a sphere, avoiding the need for more complex spatial partitioning structures like KD-trees or octrees for small-scale searches [G].
