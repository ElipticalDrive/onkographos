# Moore Neighbourhood Sampling


## Overview
Moore Neighbourhood Sampling reads all 27 voxels in a 3x3x3 block centered on a target voxel, returning their values and a bitmask of non-empty voxels [S1, unofficial]. It provides a fixed, exhaustive 27-neighbor scope, distinguishing it from radius-based alternatives like [PBF Displacement Calculation with Grid-Based Neighbor Search](9026-pbf-displacement-calculation-with-grid-based-neighbor-search.md) [G].

## How it works
**Inputs:**
- `voxels`: A flat array of 27 voxel values representing the 3x3x3 block.
- `center`: The 3D integer coordinates $(v_x, v_y, v_z)$ of the central voxel.
- `VOXEL_EMPTY`: The sentinel value representing an empty voxel.

**Outputs:**
- `neighbours`: An array of 27 voxel values.
- `mask`: A 32-bit unsigned integer bitmask.

**Data Structures:**
The output is encapsulated in a `MooreNeighbourhood` struct:
```python
class MooreNeighbourhood:
    neighbours: list[int]  # Values of the 27 voxels
    mask: int              # Bitmask: bit i is 1 if neighbours[i] != VOXEL_EMPTY
```

**Linear Indexing Logic:**
The 27 neighbors are indexed linearly from $i = 0$ to $26$ [S1, unofficial]. The mapping between linear index $i$ and 3D offset $(dx, dy, dz)$ is defined as follows [S1, unofficial]:

1.  **Linear to Offset:**
    Given linear index $i$:
    $$ z = \lfloor i / 9 \rfloor $$
    $$ y = \lfloor (i \pmod 9) / 3 \rfloor $$
    $$ x = i \pmod 3 $$
    The offset vector is $(x-1, y-1, z-1)$ [S1, unofficial].

2.  **Offset to Linear:**
    Given offset vector $v = (v_x, v_y, v_z)$ where $v_x, v_y, v_z \in \{-1, 0, 1\}$:
    $$ \text{linear\_index} = u32(v_x + 1) + 3 \cdot u32(v_y + 1) + 9 \cdot u32(v_z + 1) $$
    Here, $u32(\cdot)$ denotes casting to unsigned 32-bit integer to handle potential negative values in intermediate calculations if implemented in languages with signed arithmetic, though in Python-like pseudocode, standard integer arithmetic suffices [S1, unofficial].

**Algorithm Steps:**
1.  Initialize `neighbours` array of size 27 and `mask` to 0 [S1, unofficial].
2.  For each $i$ from 0 to 26:
    a. Calculate offset $(dx, dy, dz)$ using the Linear to Offset formula [S1, unofficial].
    b. Calculate neighbor position $u = (v_x + dx, v_y + dy, v_z + dz)$ [S1, unofficial].
    c. Calculate linear index $idx$ for $u$ using the Offset to Linear formula [S1, unofficial].
    d. Read `value = voxels[idx]` [S1, unofficial].
    e. Set `neighbours[i] = value` [S1, unofficial].
    f. If `value != VOXEL_EMPTY`, set bit $i$ in `mask` (i.e., `mask |= (1 << i)`) [S1, unofficial].
3.  Return `MooreNeighbourhood(neighbours, mask)` [S1, unofficial].

**Pseudocode:**
```python
def moore_neighbourhood_sampling(voxels_3x3x3, center, voxel_empty):
    neighbours = [0] * 27
    mask = 0
    
    for i in range(27):
        # Linear index i to 3D offset
        z = i // 9
        y = (i % 9) // 3
        x = i % 3
        
        # Offset vector relative to center
        dx = x - 1
        dy = y - 1
        dz = z - 1
        
        # Neighbor position
        ux = center[0] + dx
        uy = center[1] + dy
        uz = center[2] + dz
        
        # Neighbor position to linear index (maps offsets -1,0,1 to 0,1,2)
        linear_idx = (dx + 1) + 3 * (dy + 1) + 9 * (dz + 1)
        
        # Read value from the 3x3x3 block
        value = voxels_3x3x3[linear_idx]
        
        neighbours[i] = value
        
        if value != voxel_empty:
            mask |= (1 << i)
            
    return MooreNeighbourhood(neighbours, mask)
```
*[G] The source [S1, unofficial] provides the mapping logic for the 3x3x3 block but does not explicitly detail the global array bounds checking or the global-to-linear conversion for the `voxels` array itself. An implementer must add boundary checks for `ux, uy, uz` against the volume dimensions before accessing the global `voxels` array.*

## Subtopics

### Von Neumann Neighbourhood Extraction
Extracts the 6 face-adjacent voxels from a Moore neighbourhood result [S1, unofficial]. It returns the values at specific indices corresponding to the $\pm x, \pm y, \pm z$ directions [S1, unofficial]. The indices in the 27-element Moore array are `[12, 14, 10, 16, 4, 22]`, corresponding to directions `-x, x, -y, y, -z, z` respectively [S1, unofficial]. A precomputed bitmask `VON_NEUMANN_MASK` (value `4281360u`) has bits 12, 14, 10, 16, 4, and 22 set, allowing for efficient filtering of the Moore mask to identify which face neighbors are non-empty [S1, unofficial].

## Operating characteristics
**Time Complexity:** $O(1)$, as it always accesses exactly 27 voxels [G].
**Memory Complexity:** $O(1)$, requiring storage for 27 values and one 32-bit integer [G].
**Strengths:** Provides complete local context for voxel-based algorithms; the bitmask allows for efficient conditional processing of only occupied neighbors [G].
**Limitations:** Accesses empty voxels unnecessarily if the neighborhood is sparse; requires boundary handling for voxels at the edge of the volume [G].

## Background
Originating from implementations in GPU-based voxel terrain rendering, this method is documented in the `wgpu-voxel-terrain` repository [S1, unofficial]. It is used as a low-level primitive for spatial queries in voxel grids, enabling higher-level operations like neighbor searches for physics or rendering [G].
