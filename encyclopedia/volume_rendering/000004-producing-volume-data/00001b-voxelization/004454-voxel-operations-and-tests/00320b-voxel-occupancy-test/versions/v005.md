# Voxel Occupancy Test
Also called: Inclusion Test, Void Check, Voxel Occlusion Query

## Overview
The Voxel Occupancy Test determines whether a given set of continuous world-space points lies within any occupied voxel of a pre-computed voxel grid [S1]. It solves the problem of spatial querying for point-in-volume containment, serving as a fundamental primitive for collision detection, point cloud filtering, and visibility culling [S1]. Unlike [Voxel Visibility Culling](8235-voxel-visibility-culling.md), which filters voxels based on scalar field thresholds to find surface-adjacent cells, this method performs a direct binary containment check against the discrete occupancy mask [S1]. It differs from [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md) by operating on discrete point queries rather than continuous bounding box intersections [S1].

## How it works
**Inputs and Outputs:**
- Input: An array of $N$ query points, represented as an $(N, 3)$ matrix of floating-point world coordinates $P = \{p_0, p_1, \dots, p_{N-1}\}$ [S1].
- Input: A voxel grid structure containing the occupancy data and grid parameters (origin, resolution, voxel size) [S1].
- Output: A boolean array $B$ of length $N$, where $B_i = \text{true}$ if point $p_i$ is contained in an occupied voxel, and $\text{false}$ otherwise [S1].

**Data Structures:**
The voxel grid is typically stored as a structured 3D array or texture. In the implementation referenced by [S2, unofficial], the occupancy data is stored in a texture `voxel_world` with integer coordinates. The occupancy value is packed into the red channel of a vector, masked by `0xFFu` to ensure a binary 0 or 1 result [S2, unofficial].

**Steps:**
1.  **Coordinate Mapping**: For each query point $p_i = (x, y, z)$, map the world coordinates to integer grid indices $(i, j, k)$. This assumes the grid origin is at $(0,0,0)$ and the voxel size is uniform, as implied by the bounds check in [S2, unofficial] which compares directly against `texture_size` [S2, unofficial].
    $$ i = \lfloor x / \text{voxel\_size} \rfloor, \quad j = \lfloor y / \text{voxel\_size} \rfloor, \quad k = \lfloor z / \text{voxel\_size} \rfloor $$
    [G] If the grid has a non-zero origin, subtract the origin coordinates before division.

2.  **Boundary Check**: Verify that the computed grid indices $(i, j, k)$ lie within the valid bounds of the voxel grid. Let $W, H, D$ be the dimensions of the grid along the X, Y, and Z axes respectively.
    - If $i < 0$ or $i \ge W$, the point is outside the grid.
    - If $j < 0$ or $j \ge H$, the point is outside the grid.
    - If $k < 0$ or $k \ge D$, the point is outside the grid.
    - If any condition is true, the point is not included. Return $\text{false}$ (or 0.0) [S2, unofficial].

3.  **Occupancy Lookup**: Access the voxel data at the integer coordinates. In the specific implementation from [S2, unofficial], the coordinates are accessed as `vec3<i32>(pos.zyx)`, indicating a ZYX memory layout or coordinate system convention (common in OpenGL/Direct3D textures where Z is the depth/texture layer) [S2, unofficial].
    - Retrieve the voxel value $v$.
    - Extract the occupancy bit: $o = v \ \& \ 0xFFu$ [S2, unofficial].
    - Convert to float and clamp: $result = \min(f32(o), 1.0)$ [S2, unofficial].

4.  **Result Assignment**: Assign the result to the output array $B_i$. If the implementation uses floating-point returns (as in [S2, unofficial]), $1.0$ indicates inclusion and $0.0$ indicates exclusion. Otherwise, convert to boolean [S1].

**Pseudocode:**
```python
def voxel_occupancy_test(queries, voxel_grid):
    """
    queries: list of (x, y, z) tuples or (N, 3) array
    voxel_grid: object containing .width, .height, .depth, .voxel_size, .origin, and .get_occupancy(x, y, z)
    """
    results = []
    for p in queries:
        # 1. Coordinate Mapping
        # [G] Assuming origin is (0,0,0) for simplicity based on S2's direct comparison.
        # If origin exists: x -= origin.x, etc.
        ix = int(p[0] / voxel_grid.voxel_size)
        iy = int(p[1] / voxel_grid.voxel_size)
        iz = int(p[2] / voxel_grid.voxel_size)
        
        # 2. Boundary Check
        if (ix < 0 or ix >= voxel_grid.width or
            iy < 0 or iy >= voxel_grid.height or
            iz < 0 or iz >= voxel_grid.depth):
            results.append(False)
            continue
            
        # 3. Occupancy Lookup
        # [G] The specific bit-packing logic (R & 0xFF) from S2 is abstracted here.
        # The core logic is checking if the voxel at (ix, iy, iz) is occupied.
        # Note: S2 uses zyx order for texture lookup. Adjust indexing if necessary.
        is_occupied = voxel_grid.get_occupancy(ix, iy, iz)
        
        # 4. Result Assignment
        results.append(is_occupied)
        
    return results
```

**Parameters:**
- `voxel_size`: The physical dimension of a voxel. Must be consistent with the grid creation [S1].
- `texture_size` / Grid Dimensions: The number of voxels along each axis [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Out-of-Bounds**: Points outside the grid bounds must be handled explicitly to avoid memory access violations. The check `pos < 0.0 or pos >= texture_size` is critical [S2, unofficial].
- **Coordinate System Order**: The source [S2, unofficial] uses `pos.zyx` for texture lookup, which may differ from standard Cartesian $(i, j, k)$ or $(x, y, z)$ array indexing. Implementers must verify the memory layout of their voxel grid [S2, unofficial].
- **Precision**: Floating-point division and floor operations can introduce off-by-one errors for points exactly on voxel boundaries. Using consistent floor logic is required [G].

## Operating characteristics
- **Time Complexity**: $O(N)$ for $N$ query points, assuming $O(1)$ grid lookup [S1].
- **Memory Complexity**: $O(1)$ auxiliary space per query, dominated by the storage of the voxel grid itself [S1].
- **Performance**: Fast for dense grids and small query sets. Performance degrades if the grid lookup involves complex sparse structures or cache misses [S1].
- **Strengths**: Simple to implement, deterministic, and fast for point containment [S1].
- **Limitations**: Only works for points; does not handle continuous primitives (lines, triangles) directly without sampling [S1]. Dependent on the resolution of the voxel grid [S1].

## Background
The method is implemented in the Open3D library as `check_if_included`, allowing users to test if points from a point cloud are within an occupied voxel grid created via `create_from_point_cloud` [S1]. It is also used in voxel-based game engines for physics and collision detection, where occupancy is stored in textures and queried via shader code [S2, unofficial].
