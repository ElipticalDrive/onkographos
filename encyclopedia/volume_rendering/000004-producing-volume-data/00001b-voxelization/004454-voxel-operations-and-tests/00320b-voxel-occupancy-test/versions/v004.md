# Voxel Occupancy Test

Also called: Inclusion Test, Void Check, Voxel Occlusion Query

## Overview
The Voxel Occupancy Test determines whether a given set of continuous 3D points lies within any occupied voxel of a pre-computed voxel grid [S1]. It solves the problem of spatial querying for point clouds or ray origins against a discrete volumetric representation, returning a boolean mask indicating inclusion [S1]. Unlike [Voxel Filled Check](1705-voxel-filled-check.md), which tests the binary state of pre-computed occupancy masks at discrete grid indices, this method operates on continuous spatial coordinates and maps them to the grid structure [S1][S2, unofficial]. It differs from [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by specifically utilizing the voxel grid's internal data structures for validation rather than simple axis-aligned bounding box arithmetic [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of query points $P = \{p_0, p_1, \dots, p_{n-1}\}$, where each $p_i = (x_i, y_i, z_i)$ is a 3D coordinate in world space, typically provided as an $(n, 3)$ array [S1].
*   **Input:** A voxel grid structure $V$ containing the spatial domain definition (bounding box, resolution) and the occupancy data (e.g., a texture or sparse array) [S1][S2, unofficial].
*   **Output:** A boolean array $B$ of length $n$, where $B[i] = \text{true}$ if point $p_i$ is inside an occupied voxel, and $\text{false}$ otherwise [S1].

**Data Structures:**
The voxel grid $V$ is defined by:
*   `texture_size`: A 3D vector $(N_x, N_y, N_z)$ representing the number of voxels along each axis [S2, unofficial].
*   `voxel_world`: A 3D texture or array storing voxel data. In the reference implementation, this is sampled using integer coordinates [S2, unofficial].

**Algorithm Steps:**
1.  **Coordinate Transformation:** For each query point $p_i = (x_i, y_i, z_i)$, determine if it falls within the global bounds of the voxel grid. The bounds are defined by $[0, N_x) \times [0, N_y) \times [0, N_z)$ in grid indices [S2, unofficial].
2.  **Boundary Check:** If any component of the point's grid-indexed position is less than 0.0 or greater than or equal to the corresponding dimension in `texture_size`, the point is outside the grid. Return $\text{false}$ for this point [S2, unofficial].
3.  **Index Conversion:** Convert the continuous world coordinates to integer grid indices. The reference implementation uses `vec3<i32>(pos.zyx)`, implying a specific coordinate system mapping (likely ZYX order for texture sampling) [S2, unofficial]. Let the integer indices be $(u, v, w)$.
4.  **Voxel Sampling:** Sample the voxel data at indices $(u, v, w)$ from `voxel_world` [S2, unofficial].
5.  **Occupancy Evaluation:** Extract the occupancy value. The reference implementation uses the red channel `voxel.r` masked with `0xFFu` and clamped to 1.0:
    $$ \text{occupied} = \min(\text{f32}(\text{voxel}.r \ \& \ 0xFFu), 1.0) $$
    If $\text{occupied} > 0$, the point is inside an occupied voxel [S2, unofficial].
6.  **Result Assignment:** Set $B[i] = \text{occupied}$ [S1].

**Pseudocode:**
```python
def voxel_occupancy_test(queries: List[Tuple[float, float, float]], 
                         voxel_grid: VoxelGrid) -> List[bool]:
    """
    Tests if points are within an occupied voxel.
    
    Args:
        queries: An (n, 3) array of 3D coordinates.
        voxel_grid: The voxel grid structure containing texture_size and voxel_world.
        
    Returns:
        A boolean array indicating inclusion.
    """
    n = len(queries)
    results = [False] * n
    
    # Extract grid dimensions
    tex_size = voxel_grid.texture_size # (Nx, Ny, Nz)
    voxel_world = voxel_grid.voxel_world # 3D texture/array
    
    for i in range(n):
        x, y, z = queries[i]
        
        # Step 1 & 2: Check bounds
        # Note: The reference [S2, unofficial] checks against texture_size directly.
        # This implies the input coordinates are already in grid-index space 
        # or the implementation assumes a unit grid [0,1] mapped to indices.
        # Based on [S2, unofficial]: "if any component of pos is less than 0.0 or >= texture_size"
        if x < 0.0 or x >= tex_size.x:
            results[i] = False
            continue
        if y < 0.0 or y >= tex_size.y:
            results[i] = False
            continue
        if z < 0.0 or z >= tex_size.z:
            results[i] = False
            continue
            
        # Step 3: Convert to integer indices
        # Reference uses vec3<i32>(pos.zyx), suggesting ZYX order for sampling
        u = int(z)
        v = int(y)
        w = int(x)
        
        # Step 4: Sample voxel
        # Assuming voxel_world supports 3D indexing
        voxel = voxel_world[u, v, w]
        
        # Step 5: Evaluate occupancy
        # Reference: min(f32(voxel.r & 0xFFu), 1.0)
        occupancy = min(voxel.r & 0xFF, 1.0)
        
        # Step 6: Assign result
        results[i] = occupancy > 0.0
        
    return results
```

**Parameters:**
*   `texture_size`: Not given in the sources.
*   `voxel_world` format: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Boundary Precision:** Points exactly on the boundary (e.g., $x = N_x$) are considered outside [S2, unofficial]. Floating-point precision errors near boundaries may cause inconsistent results if coordinates are not properly rounded or floored before indexing [G].
*   **Coordinate Order:** The reference implementation uses `pos.zyx` for indexing [S2, unofficial]. Implementers must ensure their coordinate system (X, Y, Z) matches the expected sampling order of the voxel texture to avoid axis swapping errors [G].
*   **Out-of-Bounds Access:** Failing to check bounds before accessing `voxel_world` will cause memory errors or undefined behavior [S2, unofficial].

## Subtopics

### [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md)
The Point-in-Box Inclusion Test determines which points from a given array lie within an orthogonal bounding box. It serves as the core primitive for Voxel Occupancy Test, filtering points to identify voxel occupancy. Unlike 3D Filled Circle Kernel Generation which uses distance metrics, this method relies on strict axis-aligned boundary checks. It differs from Sparse AABB Collision Test by operating on a static point array rather than dynamic collision shapes [1400-point-in-box-inclusion-test.md].

### [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md)
This method generates a 3D binary kernel where elements within a specified radius from the center are set to 1, and others are set to 0, with the center element explicitly set to 0. It solves the problem of defining a discrete spherical occupancy region for voxel-based operations [G]. Not given in the sources are comparisons to sibling methods [1520-3d-filled-circle-kernel-generation.md].

### [Voxel Filled Check](1705-voxel-filled-check.md)
Voxel Filled Check determines whether a specific voxel, brick, or chunk within a structured volume grid is occupied by geometry or data. It serves as the fundamental occupancy test in voxelized volume rendering, allowing ray tracers to skip empty space and accelerate traversal. It differs from Point-in-Box Inclusion Test by operating on discrete integer grid indices and bitmask structures rather than continuous spatial queries, and from Voxel Occupancy Test by specifically focusing on the binary state of pre-computed occupancy masks (bits) rather than general point containment [1705-voxel-filled-check.md].

### [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md)
The Sparse AABB Collision Test determines whether an Axis-Aligned Bounding Box (AABB) intersects any occupied voxels within a sparse volume representation. It solves static collision detection for volumetric objects by iterating through the voxel grid defined by the AABB's bounds. It differs from its sibling Point-in-Box Inclusion Test by evaluating a continuous volume rather than discrete points, and from Voxel Filled Check by supporting heterogeneous voxel types (solid, liquid, unknown) and caching terrain noise evaluation per column to optimize performance [G] [3047-sparse-aabb-collision-test.md].

### [Solidity Check](4229-solidity-check.md)
Solidity Check determines if a specific voxel coordinate in a 3D world is occupied by solid geometry or is void (empty). It solves the problem of boundary condition handling during voxel traversal, ensuring that out-of-bounds regions are treated consistently to prevent rendering artifacts. It differs from its sibling Point-in-Box Inclusion Test by explicitly managing chunk-based spatial indexing and asymmetric boundary wrapping for X/Y versus Z axes, rather than simple AABB containment [4229-solidity-check.md].

### [Sphere-Clamped Voxel Neighbor Search](5131-sphere-clamped-voxel-neighbor-search.md)
Sphere-Clamped Voxel Neighbor Search finds the closest voxel cell to a query point within a specified radius, constrained to the grid boundaries. It solves the problem of locating the nearest occupied or valid material cell in a voxelized environment for operations like ray casting or neighbor lookups. It differs from Point-in-Box Inclusion Test by using a spherical distance metric and from Voxel Filled Check by returning the specific closest cell rather than a boolean occupancy status [5131-sphere-clamped-voxel-neighbor-search.md].

### [Voxel Collision Test](5774-voxel-collision-test.md)
A method to determine if a vertical column of voxels at a specific world XZ position contains any solid geometry between two world Y heights ($slab_{lo}$ and $slab_{hi}$). It solves the problem of collision detection in voxel-based environments, specifically allowing entities to walk through carved-out holes or gaps in terrain. Unlike general point-in-voxel tests which check a single coordinate, this method iterates along the Y-axis to detect occupancy within a vertical slab [5774-voxel-collision-test.md].

### [Mask Cache Lookup](6434-mask-cache-lookup.md)
Mask Cache Lookup tests if query points lie within occupied voxels by indexing a 3D boolean occupancy grid. It converts world coordinates to grid indices and performs a direct memory lookup. It differs from Point-in-Box Inclusion Test by using a discrete grid structure rather than continuous bounding volumes, and from Voxel Filled Check by explicitly handling the coordinate transformation and bounds checking in a single pass [6434-mask-cache-lookup.md].

## Operating characteristics
*   **Time Complexity:** $O(n)$, where $n$ is the number of query points, assuming $O(1)$ grid indexing and texture sampling [S1][S2, unofficial].
*   **Memory Complexity:** $O(n)$ for the output boolean array. The voxel grid storage is external to the test itself.
*   **Performance:** Performance is dominated by memory access patterns to `voxel_world`. Coherent query points (spatially clustered) may benefit from cache locality [G].
*   **Strengths:** Simple to implement; efficient for batched point queries; leverages existing voxel grid structures [S1].
*   **Limitations:** Requires a pre-computed voxel grid; does not handle dynamic geometry without grid updates; precision issues at boundaries [S2, unofficial].
*   **When to use:** When querying a large number of points against a static voxel grid for inclusion checks [S1].
*   **When not to use:** For dynamic scenes requiring frequent grid updates; for queries requiring precise geometric intersection rather than discrete voxel inclusion.

## Background
The Voxel Occupancy Test is a fundamental operation in voxel-based rendering and simulation, enabling efficient spatial queries against discrete volumetric data. It is implemented in libraries such as Open3D, which provides the `check_if_included` method for `VoxelGrid` objects [S1]. The method is also used in game engines and physics simulations for collision detection and visibility culling, as seen in the Bevy Voxel Engine and Isosurface generation tools [S2, S3, unofficial].
