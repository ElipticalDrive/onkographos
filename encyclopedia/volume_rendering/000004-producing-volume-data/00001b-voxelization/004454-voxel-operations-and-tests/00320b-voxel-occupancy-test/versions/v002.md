# Voxel Occupancy Test

Also called: Inclusion Test, Void Check, Voxel Occlusion Query

## Overview
The Voxel Occupancy Test determines whether a given set of continuous 3D points lies within any occupied voxel of a pre-computed voxel grid [S1]. It solves the problem of spatial querying for point-in-volume containment, serving as a fundamental primitive for collision detection, point cloud filtering, and ray casting acceleration [S1]. Unlike [Rasterization-based Voxelization](908-rasterization-based-voxelization.md) which generates the grid from primitives, this method queries an existing discrete structure [S1]. It differs from [Voxel Filled Check](1705-voxel-filled-check.md) by operating on arbitrary input points rather than checking specific grid indices, and from [Voxel Collision Test](5774-voxel-collision-test.md) by returning a binary presence status rather than interaction logic [S1][S2, unofficial].

## How it works
The method maps continuous world coordinates to discrete integer grid indices and performs a lookup in the occupancy data structure.

**Inputs and Outputs:**
*   **Input:** An array of $N$ points, `queries`, with shape $(N, 3)$, representing world-space coordinates $(x, y, z)$ [S1].
*   **Input:** A voxel grid data structure (e.g., `voxel_grid`) containing the occupancy information and grid parameters (origin, size, resolution) [S1].
*   **Output:** A boolean array `output` of shape $(N,)$, where `output[i]` is `True` if `queries[i]` is inside an occupied voxel, and `False` otherwise [S1].

**Data Structures:**
The voxel grid typically stores occupancy as a dense or sparse array. In the Open3D implementation, the grid is an abstract structure that maps coordinates to occupied cells [S1]. In shader-based implementations (e.g., Bevy Voxel Engine), the grid is stored in a 3D texture (`voxel_world`) where each texel contains an 8-bit occupancy mask [S2, unofficial].

**Steps:**
1.  **Coordinate Mapping:** For each point $p = (x, y, z)$ in `queries`, compute the corresponding voxel grid indices $(i, j, k)$.
    *   In standard implementations (Open3D), the grid handles the mapping internally based on the voxel size and bounding box defined during creation [S1].
    *   In explicit shader implementations, the mapping uses a scale and shift derived from the voxel size and grid origin:
        $$ i = \lfloor \frac{x - origin_x}{voxel\_size} \rfloor $$
        $$ j = \lfloor \frac{y - origin_y}{voxel\_size} \rfloor $$
        $$ k = \lfloor \frac{z - origin_z}{voxel\_size} \rfloor $$
        [S1][S3, unofficial]
2.  **Boundary Check:** Verify if the computed indices $(i, j, k)$ are within the valid bounds of the grid $[0, W) \times [0, H) \times [0, D)$, where $W, H, D$ are the grid dimensions [S2, S3, unofficial].
    *   If any index is out of bounds, the point is not included [S2, S3, unofficial].
3.  **Occupancy Lookup:**
    *   **Dense/Grid Lookup:** Access the occupancy value at $(i, j, k)$ in the grid's data structure [S1].
    *   **Texture Lookup (Shader):** Sample the 3D texture at integer coordinates `vec3<i32>(k, j, i)` (note: texture coordinate order may vary, e.g., ZYX in some engines) [S2, unofficial].
    *   Extract the occupancy bit. In the Bevy implementation, the occupancy is stored in the least significant bit of the texel's red channel: `occupancy = voxel.r & 0xFFu` [S2, unofficial].
4.  **Result Assignment:** Set `output[n]` to `True` if the occupancy value is non-zero, and `False` otherwise [S1][S2, unofficial].

**Pseudocode:**
```python
def voxel_occupancy_test(queries: List[Tuple[float, float, float]], 
                         voxel_grid: VoxelGrid) -> List[bool]:
    """
    Tests if points in queries are within occupied voxels of voxel_grid.
    
    Args:
        queries: List of (x, y, z) world coordinates.
        voxel_grid: A voxel grid object containing occupancy data and grid parameters.
        
    Returns:
        List of booleans indicating occupancy.
    """
    results = []
    
    # Get grid parameters from voxel_grid
    # Note: Exact attributes depend on implementation (e.g., Open3D vs custom shader)
    # For Open3D-like API:
    # voxel_grid.voxel_size
    # voxel_grid.get_bounding_box() -> min_point, max_point
    # voxel_grid.get_voxel_count() -> (nx, ny, nz)
    
    # Implementation detail: The specific mapping logic is encapsulated in the 
    # voxel_grid's internal structure. We assume a generic interface.
    
    for point in queries:
        x, y, z = point
        
        # 1. Map world coordinates to grid indices
        # Formula: idx = floor((coord - origin) / voxel_size)
        # [G] Assuming voxel_grid provides a method to convert world to index
        # or we compute it manually if parameters are exposed.
        
        # Manual calculation example if parameters are known:
        # origin = voxel_grid.min_point
        # voxel_size = voxel_grid.voxel_size
        # i = int(floor((x - origin.x) / voxel_size))
        # j = int(floor((y - origin.y) / voxel_size))
        # k = int(floor((z - origin.z) / voxel_size))
        
        # Using a hypothetical grid method for robustness
        try:
            i, j, k = voxel_grid.world_to_index(x, y, z)
        except CoordinateMappingError:
            # Fallback or error handling if mapping fails
            results.append(False)
            continue
            
        # 2. Boundary Check
        if not voxel_grid.is_in_bounds(i, j, k):
            results.append(False)
            continue
            
        # 3. Occupancy Lookup
        # Check if the voxel at (i, j, k) is occupied
        is_occupied = voxel_grid.is_occupied(i, j, k)
        
        # 4. Result Assignment
        results.append(is_occupied)
        
    return results
```

**Parameters:**
*   `voxel_size`: The physical dimension of a voxel. Determines the resolution of the grid [S1].
*   `grid_dimensions`: The number of voxels along each axis $(N_x, N_y, N_z)$ [S1].

**Edge Cases and Pitfalls:**
*   **Out-of-Bounds:** Points outside the voxel grid's bounding box must be handled explicitly to avoid memory access violations [S2, S3, unofficial].
*   **Precision:** Floating-point precision errors in coordinate mapping can lead to incorrect index calculation, especially for points near voxel boundaries [G].
*   **Empty Grid:** If the voxel grid is empty, all queries return `False` [S1].

## Subtopics

### Mask Cache Lookup
A variant that uses a pre-computed 3D boolean grid (world) to store occupancy. It converts world coordinates to grid indices using scale and shift parameters, checks bounds, and performs a row-major lookup in the boolean array [S3, unofficial]. It is optimized for batch processing of points [S3, unofficial].

### [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md)
Determines if an Axis-Aligned Bounding Box (AABB) intersects any occupied voxels. It iterates through the voxel grid defined by the AABB's bounds. It supports heterogeneous voxel types and caches terrain noise evaluation per column [G].

### [Solidity Check](4229-solidity-check.md)
Determines if a voxel coordinate is occupied by solid geometry or void. It manages chunk-based spatial indexing and asymmetric boundary wrapping for X/Y versus Z axes.

### [Sphere-Clamped Voxel Neighbor Search](5131-sphere-clamped-voxel-neighbor-search.md)
Finds the closest voxel cell to a query point within a specified radius, constrained to grid boundaries. It uses a spherical distance metric and returns the specific closest cell rather than a boolean status.

### [Voxel Collision Test](5774-voxel-collision-test.md)
Determines if a point or trajectory intersects with occupied voxels. It often implies interaction logic (such as bouncing) or trajectory traversal, distinguishing it from the binary presence check of the standard Voxel Occupancy Test.

## Operating characteristics
*   **Time Complexity:** $O(N)$ for $N$ query points, assuming $O(1)$ grid lookup [S1].
*   **Memory Complexity:** Depends on the voxel grid storage. Dense grids use $O(W \times H \times D)$ memory [S1]. Sparse grids use less memory proportional to the number of occupied voxels [S1].
*   **Performance:** Fast for dense grids with small voxel sizes, but memory intensive for high-resolution grids [S1]. Shader-based implementations (e.g., Bevy) are efficient on GPU but require texture sampling [S2, unofficial].
*   **Strengths:** Simple, fast, and widely supported [S1].
*   **Limitations:** Requires pre-computed voxel grid [S1]. Precision issues near boundaries [G].

## Background
The Voxel Occupancy Test is a fundamental operation in voxel-based graphics and simulation. It is commonly used in conjunction with voxelization methods to query the resulting grid [S1]. The Open3D library provides a built-in `check_if_included` method for this purpose [S1]. Shader-based implementations are used in real-time voxel engines like Bevy Voxel Engine for dynamic collision and visibility checks [S2, unofficial].
