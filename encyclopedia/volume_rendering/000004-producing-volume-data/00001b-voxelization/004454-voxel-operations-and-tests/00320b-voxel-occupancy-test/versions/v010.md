# Voxel Occupancy Test

Also called: Inclusion Test, Void Check, Voxel Occlusion Query

## Overview
The Voxel Occupancy Test determines whether a given continuous 3D point lies within an occupied voxel of a discrete voxel grid. It solves the problem of spatial containment queries for point clouds or ray origins against a pre-computed voxelized representation. Unlike sibling methods that may use spatial acceleration structures or kernel approximations, this method performs a direct geometric containment check by mapping continuous coordinates to discrete grid indices and querying the occupancy state [S1]. It serves as the core primitive for voxel occupancy tests, often optimized via in-place partitioning to support subsequent sorting or hierarchical decomposition [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A set of query points $P$, represented as an $(n, 3)$ array of floating-point coordinates $(x, y, z)$ in world space [S1].
- **Output:** A boolean array of length $n$, where each element indicates whether the corresponding point is inside an occupied voxel [S1].
- **Data Structures:**
    - `voxel_world`: A texture or grid storing voxel data. The occupancy is typically stored in the red channel (`r`) as an unsigned integer or byte [S2, unofficial].
    - `voxel_uniforms.texture_size`: A 3D vector defining the dimensions of the voxel grid in voxels [S2, unofficial].

**Steps:**
1.  **Coordinate Transformation:** Map the continuous world coordinates of the query point to integer voxel indices. The mapping depends on the coordinate system convention. In the referenced implementation, the ZYX order is used for indexing: $i = \lfloor z \rfloor, j = \lfloor y \rfloor, k = \lfloor x \rfloor$ [S2, unofficial].
2.  **Boundary Check:** Verify if the integer indices lie within the valid range of the voxel grid. If any component of the position is less than 0.0 or greater than or equal to `voxel_uniforms.texture_size`, the point is outside the grid [S2, unofficial].
3.  **Voxel Access:** Load the voxel value at the calculated integer coordinates from `voxel_world` [S2, unofficial].
4.  **Occupancy Evaluation:** Extract the occupancy bit from the loaded voxel data. The occupancy is determined by the least significant 8 bits of the red channel: $v = \text{voxel.r} \ \& \ 0xFFu$ [S2, unofficial].
5.  **Normalization:** Convert the integer occupancy value to a normalized float in the range $[0, 1]$ using $min(f32(v), 1.0)$ [S2, unofficial]. A value of 1.0 indicates the point is inside an occupied voxel; 0.0 indicates it is in void space.

**Pseudocode:**
```python
def voxel_occupancy_test(queries: List[Tuple[float, float, float]], 
                         voxel_world: Grid, 
                         texture_size: Tuple[int, int, int]) -> List[bool]:
    """
    Test if points are within an occupied voxel.
    
    Args:
        queries: (n, 3) array of float coordinates (x, y, z).
        voxel_world: 3D grid storing voxel data.
        texture_size: (width, height, depth) of the voxel grid.
        
    Returns:
        List of booleans indicating occupancy.
    """
    results = []
    
    for x, y, z in queries:
        # Step 1 & 2: Boundary Check
        # Check if any component is out of bounds [0, texture_size)
        if (x < 0.0 or x >= texture_size[0] or
            y < 0.0 or y >= texture_size[1] or
            z < 0.0 or z >= texture_size[2]):
            results.append(False)
            continue
            
        # Step 1: Coordinate Transformation (ZYX order per source)
        # Note: Source uses vec3<i32>(pos.zyx), implying z is first index, y second, x third.
        # Assuming texture_size is (width, height, depth) corresponding to x, y, z dimensions.
        # Indexing: voxel_world[z, y, x]
        ix = int(x)
        iy = int(y)
        iz = int(z)
        
        # Step 3: Voxel Access
        # Load voxel from texture at integer coordinates
        voxel = voxel_world[iz, iy, ix]
        
        # Step 4 & 5: Occupancy Evaluation and Normalization
        # Extract red channel, mask lower 8 bits, normalize to 0.0 or 1.0
        occupancy = min(float(voxel.r & 0xFF), 1.0)
        
        results.append(occupancy > 0.0)
        
    return results
```

**Parameters:**
- `texture_size`: The dimensions of the voxel grid. Typical values depend on the scene resolution [S2, unofficial].
- `voxel_world`: The storage format for voxel data. Typically a 3D texture or array [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** Points exactly on the boundary (e.g., $x = \text{width}$) are considered outside the grid [S2, unofficial].
- **Coordinate System:** The indexing order (ZYX vs XYZ) must match the storage layout of `voxel_world` [S2, unofficial].
- **Data Type:** The occupancy is stored in the red channel as an integer. Bit masking is required to extract the relevant bits [S2, unofficial].

## Subtopics

### [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md)
The Point-in-Box Inclusion Test partitions a set of points by determining which lie within an orthogonal bounding box. It serves as the core primitive for voxel occupancy tests, returning the count of points inside or on the boundary of the box. Unlike sibling methods that may use spatial acceleration structures or kernel approximations, this method performs a direct geometric containment check, often optimized via in-place partitioning to support subsequent sorting or hierarchical decomposition.

### [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md)
3D Filled Circle Kernel Generation produces binary occupancy masks or synthetic volume data representing a sphere within a voxel grid, primarily to optimize ray casting in volume rendering by precomputing voxel offsets. It differs from its sibling [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by using a radial distance threshold rather than axis-aligned bounds, and from [Voxel Filled Check](1705-voxel-filled-check.md) by explicitly generating the kernel data structure rather than querying an existing one. The method supports two distinct output modes: a static binary occupancy field for general sphere representation and directional entry/exit offset arrays for optimized traversal.

### [Voxel Filled Check](1705-voxel-filled-check.md)
Voxel Filled Check determines whether a specific voxel, brick, or chunk within a structured volume grid is occupied by geometry or data. It acts as a binary occupancy test for pre-computed voxel masks.

### [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md)
The Sparse AABB Collision Test determines whether an Axis-Aligned Bounding Box (AABB) intersects any occupied voxels within a sparse volume representation. It solves static collision detection for volumetric objects by iterating through the voxel grid defined by the AABB's bounds. It differs from its sibling [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by evaluating a continuous volume rather than discrete points, and from [Voxel Filled Check](1705-voxel-filled-check.md) by supporting heterogeneous voxel types (solid, liquid, unknown) and caching terrain noise evaluation per column to optimize performance [G].

### [Solidity Check](4229-solidity-check.md)
Solidity Check determines whether a specific voxel coordinate in a 3D world is occupied by solid geometry or is empty space (void). It serves as the final step in voxel occupancy testing, resolving whether a point lies within a solid volume. It differs from general occupancy tests by explicitly handling boundary conditions, coordinate wrapping, and chunk-based data structures to prevent rendering artifacts at world edges.

### [Sphere-Clamped Voxel Neighbor Search](5131-sphere-clamped-voxel-neighbor-search.md)
Sphere-Clamped Voxel Neighbor Search finds the closest occupied voxel cell to a query point within a spherical radius, constrained to the grid boundaries. It differs from [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by returning the nearest neighbor rather than a binary occupancy result, and from [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md) by performing a runtime search for a specific query point rather than precomputing a static kernel. It serves as the spatial lookup primitive for [PBF Displacement Calculation with Grid-Based Neighbor Search](9026-pbf-displacement-calculation-with-grid-based-neighbor-search.md).

### [Voxel Collision Test](5774-voxel-collision-test.md)
A Voxel Collision Test determines if a solid voxel exists within a specific spatial region, typically a vertical column defined by world XZ coordinates and a Y-axis slab range. It solves the problem of detecting physical obstructions in voxel-based environments, enabling mechanics such as walking through carved-out holes or detecting ground contact for entity physics. It differs from the parent [Voxel Occupancy Test](1281-voxel-occupancy-test.md), which tests individual points, by aggregating occupancy over a continuous volume (a column or slab) to return a single binary result for the region.

### [Mask Cache Lookup](6434-mask-cache-lookup.md)
Mask Cache Lookup looks up occupancy information in a 3D boolean grid for a set of 3D points, converting world coordinates to grid indices. It differs from [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by using a discrete grid structure rather than continuous bounding volumes, and from [Voxel Filled Check](1705-voxel-filled-check.md) by explicitly handling the coordinate transformation and bounds checking in a single pass [G].

### [Voxel Visibility Culling](8235-voxel-visibility-culling.md)
Voxel Visibility Culling is a preprocessing step in volume rendering that discards voxels determined to be occluded or geometrically irrelevant before the final rendering pass. It solves the problem of unnecessary computation by reducing the set of active voxels to only those contributing to the final image. It differs from sibling methods like [Voxel Occupancy Test](1281-voxel-occupancy-test.md) (which tests point containment) and [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md) (which tests bounding box intersections) by specifically targeting voxels that do not contribute to the visible surface or camera view based on scalar field values or spatial proximity.

## Operating characteristics
- **Time Complexity:** $O(n)$ for $n$ query points, as each point requires a constant number of arithmetic operations and a single texture lookup [S1][S2, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space per query, assuming the voxel grid is pre-loaded [S1][S2, unofficial].
- **Measured Performance:** Performance depends on the efficiency of the texture lookup and boundary checks. In the referenced implementation, the test is performed on a GPU using a compute shader or similar parallel processing unit [S2, unofficial].
- **Strengths:** Simple implementation, fast for dense grids, no additional data structures required beyond the voxel grid itself [S1][S2, unofficial].
- **Limitations:** Does not scale well for very sparse grids or large empty spaces, as every query still performs a lookup [S1]. Boundary conditions must be carefully handled [S2, unofficial].
- **When to Use:** When point containment queries are needed against a dense voxel grid, such as in voxel carving or point cloud processing [S1].
- **When Not to Use:** For sparse grids where acceleration structures (e.g., BVH, Octree) would be more efficient [S1].

## Background
The Voxel Occupancy Test is a fundamental operation in voxel-based graphics and geometry processing. It is commonly used in conjunction with voxelization techniques to determine if points from a point cloud or mesh lie within the voxelized representation of the geometry [S1]. The method is implemented in libraries such as Open3D, where it is exposed as `check_if_included` [S1]. The underlying principle of mapping continuous coordinates to discrete grid indices and querying occupancy is widely used in various graphics applications, including collision detection, spatial partitioning, and volume rendering [S2, unofficial].
