# Voxel Occupancy Test

Also called: Voxel Mask, Voxel Mask Output

## Overview
The Voxel Occupancy Test determines whether discrete query points lie within occupied voxels of a 3D grid, producing a binary mask that flags voxels containing one or more input points [S1][S4, unofficial]. It differs from sibling methods like [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md) by operating on a pre-constructed voxel grid structure rather than explicit geometric primitives, and from [Voxel Filled Check](1705-voxel-filled-check.md) by aggregating multiple points into a single occupancy flag per voxel rather than querying a static state [S1][S4, unofficial]. The primary trade-off is that it requires an existing voxelization of the scene or point cloud, making it a post-processing step for spatial queries rather than a primitive containment test [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A point cloud represented as an $(N, 3)$ array of coordinates, where $N$ is the number of points [S1].
- **Input:** A voxel grid data structure (e.g., a sparse or dense hash map, or a 3D texture) representing the spatial domain [S1].
- **Output:** A binary array (bool or UInt8) of length $N$ or corresponding to the grid cells, where `1` (or `True`) indicates the point lies within an occupied voxel, and `0` (or `False`) indicates it does not [S1][S4, unofficial]. If multiple points map to the same voxel, they collapse to a single `1` in the voxel mask [S4, unofficial].

**Data Structures:**
The voxel grid is typically stored as a hash map from integer indices $(i, j, k)$ to a boolean or integer value, or as a dense 3D array if the domain is small and fixed [S1]. In GPU implementations, it may be stored as a 3D texture (e.g., `texture3D`) or a structured buffer [S2, unofficial][S3, unofficial].

**Steps:**
1. **Coordinate Mapping:** For each query point $P_n = (x_n, y_n, z_n)$, map the continuous world coordinates to discrete voxel indices $(i, j, k)$. This involves subtracting the grid origin and dividing by the voxel size (spacing) [G].
   $$ i = \lfloor \frac{x_n - O_x}{S_x} \rfloor, \quad j = \lfloor \frac{y_n - O_y}{S_y} \rfloor, \quad k = \lfloor \frac{z_n - O_z}{S_z} \rfloor $$
   where $O$ is the origin and $S$ is the spacing (voxel size) [G].
2. **Boundary Check:** Verify that the computed indices $(i, j, k)$ are within the valid bounds of the voxel grid. If any index is less than 0 or greater than or equal to the grid dimensions, the point is considered outside the grid [S2, unofficial].
3. **Occupancy Query:** Check if the voxel at $(i, j, k)$ is marked as occupied.
   - In a dense grid, this is a direct array lookup [S1].
   - In a sparse grid, this is a hash map lookup [S1].
   - In a GPU shader, this is a texture sample [S2, unofficial].
4. **Result Assignment:**
   - If the voxel is occupied, set the output for point $P_n$ to `1` (or `True`) [S1][S4, unofficial].
   - If the voxel is empty or the point is out of bounds, set the output to `0` (or `False`) [S1][S4, unofficial].
   - Note: The output array is often indexed by point order, not voxel order [S4, unofficial].

**Pseudocode:**
```python
def voxel_occupancy_test(points, voxel_grid, origin, spacing):
    """
    Test if points are within occupied voxels.
    
    Args:
        points: (N, 3) array of float coordinates.
        voxel_grid: A data structure supporting 'is_occupied(i, j, k)' lookup.
        origin: (3,) array of float, the minimum corner of the voxel grid.
        spacing: (3,) array of float, the size of each voxel.
        
    Returns:
        occupancy: (N,) boolean array.
    """
    N = points.shape[0]
    occupancy = np.zeros(N, dtype=bool)
    
    # Pre-calculate inverse spacing for division
    inv_spacing = 1.0 / spacing
    
    for n in range(N):
        p = points[n]
        
        # 1. Coordinate Mapping
        # Convert world coordinates to voxel indices
        # Using floor division to map to integer grid cells
        indices = np.floor((p - origin) * inv_spacing).astype(int)
        i, j, k = indices
        
        # 2. Boundary Check
        # Check if indices are within grid bounds
        # Assuming voxel_grid has dimensions dim_x, dim_y, dim_z
        # These must be known from the voxel_grid structure
        if (i < 0 or i >= voxel_grid.dim_x or
            j < 0 or j >= voxel_grid.dim_y or
            k < 0 or k >= voxel_grid.dim_z):
            occupancy[n] = False
            continue
            
        # 3. Occupancy Query
        # Check if the voxel at (i, j, k) is occupied
        if voxel_grid.is_occupied(i, j, k):
            occupancy[n] = True
        else:
            occupancy[n] = False
            
    return occupancy
```

**Parameters:**
- **Voxel Size (Spacing):** Determines the resolution of the grid. Smaller sizes increase accuracy but also memory and computation cost [S1].
- **Origin:** The world coordinate of the $(0,0,0)$ voxel index [G].

**Edge Cases and Pitfalls:**
- **Out-of-Bounds Points:** Points outside the grid bounds are silently dropped or marked as false, depending on implementation [S2, unofficial][S4, unofficial].
- **Non-Finite Coordinates:** Points with NaN or Inf coordinates should be skipped or handled explicitly to avoid undefined behavior [S4, unofficial].
- **Precision Issues:** Floating-point precision errors in coordinate mapping can cause points near voxel boundaries to be assigned to incorrect voxels [G]. Using epsilon adjustments or consistent floor/ceil logic is recommended [G].
- **I/O Performance:** If the point cloud is spatially unsorted, writes to the output mask (if indexed by voxel) or reads from the grid may be scattered, leading to cache misses or I/O bottlenecks in out-of-core storage [S4, unofficial]. Pre-sorting points spatially can mitigate this [S4, unofficial].

## Subtopics

### Voxel Contains Scene Geometry Test
A method to determine if any scene geometry exists inside a voxel, used to flag voxels for subdivision [S6, unofficial]. It differs from the basic occupancy test by querying the scene's depth or using occlusion queries rather than a pre-computed point cloud mask [S6, unofficial]. Steps include: 1) Sampling scene depth at the voxel corners using a cubemap, where only specific texels are used to test for intersection [S6, unofficial]. 2) Alternatively, placing a camera at the voxel center, rendering quads for the voxel faces, then rendering the scene, and checking if any draw calls pass the occlusion query [S6, unofficial]. If the query passes, the voxel contains geometry [S6, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ for $N$ query points, assuming $O(1)$ voxel grid lookup [S1].
- **Memory Complexity:** $O(V)$ for the voxel grid storage, where $V$ is the number of voxels, plus $O(N)$ for the output mask [S1][S4, unofficial].
- **Performance:** Performance is heavily dependent on the voxel grid's sparsity and the efficiency of the lookup structure (hash map vs. dense array) [S1]. GPU implementations using texture sampling can be very fast for large $N$ [S2, unofficial][S3, unofficial].
- **Strengths:** Fast containment queries for point clouds; simple binary output [S1][S4, unofficial].
- **Limitations:** Requires pre-voxelization; sensitive to voxel size and origin alignment [S1][S4, unofficial].
- **When to Use:** When you need to quickly determine which points in a cloud fall within a voxelized representation of a scene or object [S1].
- **When Not to Use:** When the voxel grid is not available or when precise geometric intersection (not just grid cell containment) is required [S1].

## Background
The Voxel Occupancy Test is a fundamental operation in voxel-based rendering and spatial data structures. It is commonly used in point cloud processing, voxel carving, and adaptive subdivision [S1][S6, unofficial]. The method is implemented in libraries like Open3D, which provides a `check_if_included` function for voxel grids [S1][S5]. In game development and real-time rendering, it is used for culling, collision detection, and irradiance volume computation [S6, unofficial]. The concept of mapping points to grid cells and testing occupancy is a core primitive in voxelization pipelines [S4, unofficial].
