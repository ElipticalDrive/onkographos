# Entity Collision & Movement

Also called: Entity Physics, Grid-Based Movement, Player Movement & Collision, Voxel Entity Physics

## Overview
Entity Collision & Movement handles the physics simulation and spatial validation of an entity within a voxel grid, ensuring it moves correctly without intersecting solid blocks. It distinguishes itself from sibling methods by combining axis-aligned movement with a specific "slide" collision resolution strategy (attempting full movement, then X-only, then Z-only) and ground detection logic, building on [Voxel Collision Test](5774-voxel-collision-test.md).

## How it works
**Inputs:** Entity position ($\mathbf{p}$), velocity ($\mathbf{v}$), input direction/movement vector, yaw angle ($\theta$), time step ($dt$), and the voxel world data (chunks/blocks).
**Outputs:** Updated entity position, velocity, and ground state ($onGround$).

**Data Structures:**
*   **Entity State:**
    *   `position`: `glm::vec3` (x, y, z floats).
    *   `velocity`: `glm::vec3` (x, y, z floats).
    *   `onGround`: `bool`.
*   **World Data:**
    *   `chunks`: List of `Chunk` objects.
    *   `Chunk`: Contains `blocks` array (3D voxel data) and `position` (chunk coordinates).
    *   `blockAt(goal, chunks)`: Helper function returning block ID (255 for air). It computes chunk indices via $\lfloor x / \text{CHUNK\_SIZE} \rfloor$ and $\lfloor z / \text{CHUNK\_SIZE} \rfloor$, locates the chunk, and accesses `blocks[localX][localY][localZ]` [S2, unofficial].

**Parameters:**
*   `MOVE_SPEED`: 10 [S2, unofficial].
*   `JUMP_POWER`: 10 [S2, unofficial].
*   `GRAVITY`: 30 [S2, unofficial].
*   `ENTITY_HEIGHT`: 2 [S2, unofficial].

**Steps:**

1.  **Gravity & Ground Detection:**
    *   Apply gravity: $v_y \leftarrow v_y - \text{GRAVITY} \times dt$ [S2, unofficial].
    *   Check ground: Query block at `position - (0, ENTITY_HEIGHT, 0)` [S2, unofficial].
    *   If block is solid (not 255):
        *   Set $onGround = \text{true}$ [S2, unofficial].
        *   If $v_y < 0$, set $v_y = 0$ [S2, unofficial].
        *   Snap $y$ position: $y \leftarrow \lceil y \rceil$ [S2, unofficial].
    *   Else (not on ground):
        *   Update position: $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{v} \times dt$ [S2, unofficial].
    *   **Fall-off Reset:** If $y < 0$, set $y = 100$ and $v_y = 0$ [S2, unofficial].

2.  **Movement Calculation:**
    *   Compute horizontal direction vector from input and yaw [S2, unofficial].
    *   Calculate movement change vector $\Delta \mathbf{p}$:
        *   Front vector: $\mathbf{f} = (\cos \theta, 0, \sin \theta)$ [S2, unofficial].
        *   Right vector: $\mathbf{r} = \text{normalize}(\mathbf{f} \times (0,1,0))$ [S2, unofficial].
        *   $\Delta \mathbf{p} = \mathbf{f} \times (-\text{input\_z} \times \text{MOVE\_SPEED} \times dt) + \mathbf{r} \times (\text{input\_x} \times \text{MOVE\_SPEED} \times dt)$ [S2, unofficial].
        *   *Note:* S1 uses a similar trigonometric approach for forward/strafe increments: $x_{inc} = \cos(\theta) \times \text{speed} + \cos(\theta - \pi/2) \times \text{crab}$ [S1, unofficial].

3.  **Collision Resolution (Slide):**
    *   Define `goal` as the current position adjusted for entity height: $\mathbf{g} = \mathbf{p} - (0, \text{ENTITY\_HEIGHT} - 0.5, 0)$ [S2, unofficial].
    *   **Attempt Full Move:** Check `blockAt(g + \Delta \mathbf{p})`.
        *   If air (255): Update $\mathbf{p} \leftarrow \mathbf{g} + \Delta \mathbf{p} + (0, \text{ENTITY\_HEIGHT} - 0.5, 0)$ [S2, unofficial].
        *   Else (collision):
            *   **Slide X:** Set $\Delta \mathbf{p}_x = 0$. Check `blockAt(g + \Delta \mathbf{p}_x)`.
                *   If air: Update $\mathbf{p}$ [S2, unofficial].
                *   Else:
                    *   **Slide Z:** Set $\Delta \mathbf{p}_z = 0$ (keeping X zeroed). Check `blockAt(g + \Delta \mathbf{p}_{xz})`.
                        *   If air: Update $\mathbf{p}$ [S2, unofficial].
                        *   Else: Do not move [S2, unofficial].

4.  **Jumping:**
    *   If $onGround$ and jump input: $v_y \leftarrow \text{JUMP\_POWER}$ [S2, unofficial].

5.  **Angle Wrapping (S1 specific):**
    *   If $\theta \ge 2\pi$ or $\theta \le -2\pi$, reset $\theta = 0$ [S1, unofficial].

**Pseudocode:**
```python
def update_entity(entity, chunks, dt, input_dir, yaw):
    # 1. Gravity and Ground Check
    entity.velocity.y -= GRAVITY * dt
    
    # Check block below entity feet
    # Adjust goal for entity height offset
    goal_y = entity.position.y - (ENTITY_HEIGHT - 0.5)
    block_below = block_at(entity.position.x, goal_y, entity.position.z, chunks)
    
    if block_below != 255:  # Solid block
        entity.on_ground = True
        if entity.velocity.y < 0:
            entity.velocity.y = 0
        entity.position.y = math.ceil(entity.position.y)
    else:
        # Apply velocity if not on ground
        entity.position += entity.velocity * dt
        entity.on_ground = False

    # Fall-off reset
    if entity.position.y < 0:
        entity.position.y = 100
        entity.velocity.y = 0

    # 2. Movement Calculation
    # Compute front and right vectors
    front = vec3(math.cos(yaw), 0, math.sin(yaw))
    up = vec3(0, 1, 0)
    right = normalize(cross(front, up))
    
    # Calculate change vector based on input and speed
    # input_dir is normalized (x, z)
    change = front * (-input_dir.z * MOVE_SPEED * dt) + right * (input_dir.x * MOVE_SPEED * dt)
    
    # 3. Collision Resolution
    # Goal position for collision check (feet level)
    check_goal = entity.position - vec3(0, ENTITY_HEIGHT - 0.5, 0)
    
    # Try full move
    if block_at(check_goal.x + change.x, check_goal.y, check_goal.z + change.z, chunks) == 255:
        entity.position = check_goal + change + vec3(0, ENTITY_HEIGHT - 0.5, 0)
    else:
        # Try sliding X
        change_x_zeroed = vec3(0, change.y, change.z)
        if block_at(check_goal.x + change_x_zeroed.x, check_goal.y, check_goal.z + change_x_zeroed.z, chunks) == 255:
            entity.position = check_goal + change_x_zeroed + vec3(0, ENTITY_HEIGHT - 0.5, 0)
        else:
            # Try sliding Z
            change_z_zeroed = vec3(change.x, change.y, 0)
            if block_at(check_goal.x + change_z_zeroed.x, check_goal.y, check_goal.z + change_z_zeroed.z, chunks) == 255:
                entity.position = check_goal + change_z_zeroed + vec3(0, ENTITY_HEIGHT - 0.5, 0)
            # Else: blocked completely

def jump(entity):
    if entity.on_ground:
        entity.velocity.y = JUMP_POWER
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per frame per entity, assuming chunk lookup is $O(1)$ via direct indexing or hash map. The collision check performs up to 3 block lookups.
*   **Memory Complexity:** $O(1)$ additional memory per entity.
*   **Strengths:** Simple to implement; provides "slide" behavior which feels natural for grid-based movement; handles gravity and ground detection robustly.
*   **Limitations:** Axis-aligned only (no diagonal sliding or rotation-based collision); does not handle steep slopes or stairs automatically; "snap to ceiling" logic may cause jitter if not handled carefully [S2, unofficial].
*   **When to use:** Simple voxel games, roguelikes, or prototypes where high-fidelity physics is not required.
*   **When not to use:** Games requiring smooth slope walking, complex character controllers, or non-axis-aligned movement.

## Background
This method is derived from early voxel engine implementations, specifically those found in educational or prototype repositories. The specific implementation details (chunk-based block lookup, slide collision, and parameter values) come from the "VoxelEngine" project [S2, unofficial]. The trigonometric movement approach is also seen in raycasting prototypes [S1, unofficial].
