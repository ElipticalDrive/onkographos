# Voxel Collision Test

Also called: Grid Check, Voxel Column Collision, vertical column check

## Overview
A Voxel Collision Test determines if a solid obstruction exists within a specific spatial region of a voxel grid, typically defined by a vertical column between two Y-heights at a given XZ position [S2, S3, unofficial]. Unlike the parent [Voxel Occupancy Test](1281-voxel-occupancy-test.md), which checks if a single point lies within an occupied voxel, this method aggregates occupancy along a dimension to support physics interactions such as walking, falling, or sliding against terrain [S2, unofficial]. It distinguishes itself from raycasting by treating the voxel grid as a solid volume rather than a surface, allowing it to detect collisions even when the ray passes through empty space or holes in the geometry [S2, S3, unofficial].

## How it works
The method operates on an axis-aligned voxel grid where each voxel is marked as either solid or empty. The primary use case is checking a vertical column for solidity, often to determine if a character or object can stand at a specific location or if a vertical movement is blocked.

**Inputs:**
- `grid`: A 3D array or sparse structure representing the voxel world.
- `world_xz`: A 2D vector $(x, z)$ representing the horizontal world position.
- `slab_lo`: A float representing the lower Y-bound of the collision check in world coordinates.
- `slab_hi`: A float representing the upper Y-bound of the collision check in world coordinates.
- `self.origin`: The world-space origin of the voxel grid.
- `self.rotation`: The rotation matrix (or quaternion) transforming world space to local grid space.
- `self.vox_size`: The side length of a single voxel.
- `self.grid_dim`: The dimensions of the grid (assumed cubic $N \times N \times N$ for simplicity, or separate $D_x, D_y, D_z$).

**Outputs:**
- `bool`: `true` if any voxel in the specified column is solid; `false` otherwise.

**Data Structures:**
The grid is typically stored as a dense 3D array `bool grid[D_x][D_y][D_z]` or a flattened 1D array. Each element indicates occupancy.

**Steps:**
1.  **Transform World XZ to Local Space:**
    Create a temporary 3D vector `p` using the world XZ coordinates and a Y of 0.0. Transform this vector into the grid's local coordinate system by subtracting the grid origin and applying the inverse rotation:
    $$
    p = (world\_xz.x, 0.0, world\_xz.y)
    $$
    $$
    local = R^{-1} \cdot (p - origin)
    $$
    where $R^{-1}$ is the inverse rotation matrix.

2.  **Calculate Local Grid X and Z Indices:**
    Convert the local X and Z coordinates to floating-point grid indices. This involves shifting by half the grid dimension to center the coordinate system (assuming the grid is centered at the origin in local space) and dividing by the voxel size:
    $$
    lx_f = \frac{local.x + \frac{D_x}{2}}{vox\_size}
    $$
    $$
    lz_f = \frac{local.z + \frac{D_z}{2}}{vox\_size}
    $$
    *Note: If the grid is not centered, the offset term $\frac{D}{2}$ is replaced by the appropriate corner offset.*

3.  **Check XZ Bounds:**
    If $lx_f < 0$ or $lx_f \ge D_x$ or $lz_f < 0$ or $lz_f \ge D_z$, the position is outside the grid horizontally. Return `false` (or handle as out-of-bounds error).

4.  **Transform Slab Y to Local Grid Y Indices:**
    Convert the world-space slab bounds ($slab\_lo, slab\_hi$) to local grid Y indices. This requires transforming the world Y values into the local space. If the grid rotation only affects XZ (e.g., a flat terrain grid), the Y axis might remain aligned. However, for a general rotation, the Y bounds must also be transformed. Assuming a standard vertical column check where Y is aligned or the rotation is identity for Y:
    $$
    ly\_lo\_f = \frac{slab\_lo - origin.y + \frac{D_y}{2}}{vox\_size}
    $$
    $$
    ly\_hi\_f = \frac{slab\_hi - origin.y + \frac{D_y}{2}}{vox\_size}
    $$
    *If the grid is rotated, $slab\_lo$ and $slab\_hi$ must be transformed by $R^{-1}$ first to get their local Y components.*

5.  **Clamp Y Indices to Grid Bounds:**
    Convert floating-point indices to integer grid indices and clamp them to the valid range $[0, D_y - 1]$:
    $$
    ly\_lo = \max(0, \lfloor ly\_lo\_f \rfloor)
    $$
    $$
    ly\_hi = \min(D_y - 1, \lceil ly\_hi\_f \rceil)
    $$

6.  **Iterate and Check:**
    Iterate through the Y indices from $ly\_lo$ to $ly\_hi$ inclusive. For each $y$, check the voxel at $(lx, y, lz)$ in the grid. If any voxel is solid, return `true`. If the loop completes without finding a solid voxel, return `false`.

**Pseudocode:**
```python
def voxel_collision_test(grid, world_xz, slab_lo, slab_hi, origin, rotation_inv, vox_size, grid_dim):
    # 1. Transform World XZ to Local Space
    # p is (world_xz.x, 0.0, world_xz.y)
    p = Vector3(world_xz.x, 0.0, world_xz.y)
    local = rotation_inv * (p - origin)
    
    # 2. Calculate Local Grid X and Z Indices
    half_x = grid_dim[0] / 2.0
    half_y = grid_dim[1] / 2.0
    half_z = grid_dim[2] / 2.0
    
    lx_f = (local.x + half_x) / vox_size
    lz_f = (local.z + half_z) / vox_size
    
    # 3. Check XZ Bounds
    if lx_f < 0 or lx_f >= grid_dim[0] or lz_f < 0 or lz_f >= grid_dim[2]:
        return False
        
    lx = int(lx_f)
    lz = int(lz_f)
    
    # 4. Transform Slab Y to Local Grid Y Indices
    # Assuming Y is not rotated relative to world for this specific column check variant
    # If rotation affects Y, transform slab_lo and slab_hi points by rotation_inv first
    ly_lo_f = (slab_lo - origin.y + half_y) / vox_size
    ly_hi_f = (slab_hi - origin.y + half_y) / vox_size
    
    # 5. Clamp Y Indices to Grid Bounds
    ly_lo = max(0, int(math.floor(ly_lo_f)))
    ly_hi = min(grid_dim[1] - 1, int(math.ceil(ly_hi_f)))
    
    # 6. Iterate and Check
    for y in range(ly_lo, ly_hi + 1):
        if grid[lx][y][lz]:
            return True
            
    return False
```

**Edge Cases and Pitfalls:**
-   **Precision:** Floating-point errors in coordinate transformation can cause off-by-one errors in grid indexing. Using `floor` for lower bounds and `ceil` for upper bounds helps ensure coverage.
-   **Rotation:** If the voxel grid is rotated, the "vertical" column in world space may not align with the grid's Y-axis. The transformation in Step 1 and 4 must account for the full 3D rotation.
-   **Slab Height:** If $slab\_lo \ge slab\_hi$, the range is invalid. Return `false` or handle as error.
-   **Out of Bounds:** Horizontal positions outside the grid must be handled explicitly to avoid array index errors.

## Subtopics

### [Entity Collision & Movement](11316-entity-collision-movement.md)
Entity Collision & Movement handles the physics simulation and positional updates of an entity within a voxel grid, ensuring it moves correctly without intersecting solid blocks. It distinguishes itself from simple raycasting by integrating gravity, ground detection, and axis-aligned sliding against voxel walls. It uses the Voxel Collision Test to determine if a proposed movement vector intersects any solid voxels, allowing for smooth sliding along surfaces rather than rigid stopping.

### Solid Voxel Particle Physics
Solid Voxel Particle Physics detects collisions and makes particles bounce based on solid voxelization with normals, treating concave regions and dynamic deformation [S3, unofficial]. It recomputes density and normals at every frame to allow dynamic deformation and evaluates normals only when a particle enters in contact with a surface [S3, unofficial]. This approach provides uniform quality in all directions compared to depth peeling (which suffers from resolution/hole issues) or clipping planes (which have restricted z-axis info) [S3, unofficial]. It allows for consistent back integration and can be combined with movement extraction steps like sampling motion at coarse levels [S3, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(N_y)$ where $N_y$ is the number of voxels in the vertical column, determined by the height of the slab and voxel size. In the worst case, this is $O(D_y)$.
-   **Memory Complexity:** $O(1)$ auxiliary space, assuming the grid is accessed directly.
-   **Performance:** Very fast for small slabs. Performance degrades linearly with slab height. For large scenes, sparse voxel structures can reduce the average case but add lookup overhead.
-   **Strengths:** Simple to implement, robust for axis-aligned checks, handles concave geometry naturally.
-   **Limitations:** Only checks a single column; does not handle diagonal collisions or complex shapes without multiple tests. Resolution-dependent; small objects may pass through if they fit within a single voxel.
-   **When to Use:** Character movement, terrain collision, simple physics simulations.
-   **When Not to Use:** High-precision collision detection, diagonal movement, or when object size is smaller than voxel size.

## Background
The concept of using voxel grids for collision detection originated in early voxel-based games and simulations. The "noa" voxel game engine presentation by Andy Hall (2015) explicitly lists "Collision tests: simple grid check" as a fundamental algorithm extending from 2D cases [S1, unofficial]. The implementation details in the Prometheus Engine (elyssov) demonstrate a practical application for character movement, using vertical column checks to allow walking through carved-out holes [S2, unofficial]. The technique was further generalized for GPU particle systems in "Single-pass GPU Solid Voxelization and Applications" (2009), which used solid voxelization with normals for efficient particle collision detection, highlighting its ability to handle concave regions and dynamic deformation [S3, unofficial].
