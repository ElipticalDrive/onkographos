# Voxel Collision Test

Also called: Grid Check, Voxel Column Collision, vertical column check

## Overview
A Voxel Collision Test determines if a solid voxel exists within a specific spatial region, typically a vertical column defined by world XZ coordinates and a Y-axis slab range [S2, unofficial]. It solves the problem of detecting physical obstructions in voxel-based environments, enabling mechanics such as walking through carved-out holes or detecting ground contact for entity physics [S2, unofficial][S4, unofficial]. It differs from the parent [Voxel Occupancy Test](1281-voxel-occupancy-test.md), which tests individual points, by aggregating occupancy over a continuous volume (a column or slab) to return a single binary result for the region [G].

## How it works
The method maps world-space coordinates to local voxel grid indices and iterates through the occupied cells within the defined bounds [S2, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `world_xz`: A 2D position $(x, z)$ in world coordinates.
    *   `slab_lo`, `slab_hi`: The lower and upper Y bounds in world coordinates [S2, unofficial].
    *   `grid_origin`: The world position of the voxel grid's origin.
    *   `vox_size`: The side length of a single voxel.
    *   `grid_dim`: The dimensions of the voxel grid $(D_x, D_y, D_z)$.
    *   `grid_data`: A 3D array or sparse structure storing voxel states (e.g., solid/empty) [G].
    *   `rotation`: (Optional) The orientation of the voxel grid relative to the world, if the grid is not axis-aligned with the world axes [S2, unofficial].
*   **Outputs**:
    *   `collision`: A boolean indicating if any voxel in the column is solid [S2, unofficial].

### Data Structures
*   **Voxel Grid**: A 3D array `grid[D_x][D_y][D_z]` where each element is a boolean or integer flag. `true` or non-zero indicates a solid voxel; `false` or zero indicates empty space [G].
*   **Local Coordinates**: Temporary floating-point vectors used to map world positions to grid indices [G].

### Steps
1.  **Coordinate Transformation**: Convert the world XZ position and slab Y bounds into the voxel grid's local coordinate system. Construct a 3D vector $P_{xz} = (world\_xz.x, 0.0, world\_xz.y)$ and transform it: $P_{local} = R^{-1} \cdot (P_{xz} - grid\_origin)$, where $R$ is the grid's rotation matrix [S2, unofficial]. The Y bounds are transformed only by translation: $y_{local\_lo} = slab\_lo - grid\_origin.y$ and $y_{local\_hi} = slab\_hi - grid\_origin.y$ [S2, unofficial].
2.  **Calculate Grid Indices**: Convert local coordinates to floating-point grid indices: $lx_f = \frac{local.x + half\_grid}{vox\_size}$, $lz_f = \frac{local.z + half\_grid}{vox\_size}$, $ly\_lo_f = \frac{y_{local\_lo} + half\_grid}{vox\_size}$, $ly\_hi_f = \frac{y_{local\_hi} + half\_grid}{vox\_size}$, where $half\_grid = 0.5 \times vox\_size$ [S2, unofficial].
3.  **Boundary Check (XZ)**: If $local.x < 0$ or $local.x \ge D_x$ or $local.z < 0$ or $local.z \ge D_z$, return `false` [S2, unofficial].
4.  **Calculate Y Bounds**: Convert floating-point Y indices to integer grid indices: $ly\_lo = \lfloor ly\_lo_f \rfloor$, $ly\_hi = \lceil ly\_hi_f \rceil$. Clamp $ly\_lo$ to $[0, D_y - 1]$ and $ly\_hi$ to $[0, D_y - 1]$ [S2, unofficial].
5.  **Iterate and Test**: Loop through Y indices from $ly\_lo$ to $ly\_hi$. For each $y$, check `grid[round(lx_f)][y][round(lz_f)]`. If the voxel is solid, return `true` [S2, unofficial].
6.  **Return**: If the loop completes without finding a solid voxel, return `false` [S2, unofficial].

### Pseudocode
```python
def voxel_collision_test(world_xz, slab_lo, slab_hi, grid_origin, vox_size, grid_dim, grid_data, rotation=None):
    # 1. Coordinate Transformation
    if rotation is None:
        local_x = world_xz[0] - grid_origin[0]
        local_z = world_xz[1] - grid_origin[2]
    else:
        p_world = (world_xz[0], 0.0, world_xz[1])
        p_local = rotation.inverse() * (p_world - grid_origin)
        local_x = p_local[0]
        local_z = p_local[2]
    local_y_lo = slab_lo - grid_origin[1]
    local_y_hi = slab_hi - grid_origin[1]

    half_grid = 0.5 * vox_size

    # 2. Calculate Grid Indices
    lx_f = (local_x + half_grid) / vox_size
    lz_f = (local_z + half_grid) / vox_size
    ly_lo_f = (local_y_lo + half_grid) / vox_size
    ly_hi_f = (local_y_hi + half_grid) / vox_size

    # 3. Boundary Check (XZ)
    dx, dy, dz = grid_dim
    if local_x < 0 or local_x >= dx or local_z < 0 or local_z >= dz:
        return False

    # 4. Calculate Y Bounds
    import math
    ly_lo = math.floor(ly_lo_f)
    ly_hi = math.ceil(ly_hi_f)
    ly_lo = max(0, ly_lo)
    ly_hi = min(dy - 1, ly_hi)

    if ly_lo > ly_hi:
        return False

    # 5. Iterate and Test
    ix = round(lx_f)
    iz = round(lz_f)
    ix = max(0, min(ix, dx - 1))
    iz = max(0, min(iz, dz - 1))

    for y in range(ly_lo, ly_hi + 1):
        if grid_data[ix][y][iz]:
            return True

    return False
```

### Parameters
*   `vox_size`: Typically $1.0$ unit per voxel in world space [G].
*   `half_grid`: $0.5 \times vox\_size$ [S2, unofficial].

### Edge Cases and Pitfalls
*   **Precision**: Floating-point errors in index calculation can lead to off-by-one errors. Using `floor` and `ceil` correctly handles the slab boundaries [G].
*   **Out of Bounds**: If the XZ position is outside the grid, the test must return `false` rather than crashing [S2, unofficial].
*   **Empty Slab**: If `slab_lo` and `slab_hi` are equal or inverted after clamping, the loop range is empty [G].
*   **Rotation**: The rotation is applied only to the XZ position (Y is set to 0), and Y bounds are transformed only by translation [S2, unofficial].

## Subtopics

### Solid Voxel Particle Physics
A variant used for GPU particle systems where collisions are detected against a solid voxelization with normals [S3, unofficial]. It treats concave regions and dynamic deformation seamlessly [S3, unofficial]. Normals are recomputed every frame, and evaluated only when a particle enters contact with a surface [S3, unofficial]. It offers uniform quality in all directions, unlike depth peeling or clipping planes, allowing consistent back integration [S3, unofficial].

### Entity Collision & Movement
A variant used for entity physics including gravity, ground detection, and axis-aligned movement with wall-sliding [S4, unofficial]. It checks blocks at specific offsets (e.g., below the entity) to determine if the entity is on the ground [S4, unofficial]. If a collision is detected during movement, it attempts to slide along the X or Z axis [S4, unofficial]. It uses a block ID of 255 to represent air [S4, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(D_y)$ for a full column scan, where $D_y$ is the height of the grid. In practice, it is $O(h)$ where $h$ is the number of voxels in the slab [G].
*   **Memory Complexity**: $O(1)$ auxiliary space, assuming the grid data is pre-loaded [G].
*   **Strengths**: Simple to implement, robust for axis-aligned grids, handles concave geometry naturally [G].
*   **Limitations**: Does not provide collision normals or precise contact points, only binary occupancy. Performance degrades with very tall slabs or high-resolution grids [G].
*   **When to use**: Ground detection, simple obstacle avoidance, voxel-based physics [G].
*   **When not to use**: When precise collision normals are required (use raycasting or signed distance fields), or when the grid is extremely sparse and dense (use spatial hashing or BVH) [G].

## Background
The method is a fundamental operation in voxel-based game engines and simulations. It is often referred to as a "grid check" in the context of voxel games like *noa* [S1, unofficial]. It is used in various implementations, from simple 2D heightmap checks to 3D entity physics in engines like *VoxelEngine* [S4, unofficial]. It is also applied in GPU particle simulations using solid voxelization [S3, unofficial].
