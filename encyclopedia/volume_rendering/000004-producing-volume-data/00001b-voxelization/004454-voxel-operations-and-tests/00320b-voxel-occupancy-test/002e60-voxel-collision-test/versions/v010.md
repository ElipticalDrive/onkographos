# Voxel Collision Test

Also called: Grid Check, Voxel Column Collision, vertical column check

## Overview
A Voxel Collision Test determines if a specific spatial region within a voxel grid contains any occupied (solid) voxels [S1, S2, unofficial]. It solves the problem of detecting intersections between geometric primitives (such as vertical slabs or particles) and a discrete voxelized environment [S2, S3, unofficial]. Unlike the parent [Voxel Occupancy Test](1281-voxel-occupancy-test.md), which tests individual points for containment, this method tests a continuous range or volume against the grid structure [G]. It differs from [Raycasting](1281-voxel-occupancy-test.md) (often implemented as line rasterization) by evaluating a column or volume rather than a single line, and from [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md) by operating on dense or structured grid coordinates rather than bounding volume hierarchies [S1, G, unofficial].

## How it works
The method operates by mapping world-space coordinates to local grid indices and iterating through the relevant voxels to check for occupancy [S2, unofficial].

### Inputs and Outputs
- **Inputs**:
  - World-space horizontal position $(x, z)$ [S2, unofficial].
  - World-space height bounds $y_{lo}$ and $y_{hi}$ defining a vertical slab [S2, unofficial].
  - Grid parameters: origin $(o_x, o_y, o_z)$, voxel size $s$, grid dimensions $(D_x, D_y, D_z)$, rotation matrix $R$, and half-grid offset $h$ [S2, unofficial].
  - Occupancy data: A 3D array or hash map indicating solid voxels [G].
- **Outputs**:
  - Boolean: `true` if any voxel in the tested region is solid; `false` otherwise [S2, unofficial].

### Data Structures
The grid is typically stored as a dense 3D array `grid[D_x][D_y][D_z]` where each element is a boolean or integer flag indicating occupancy [G]. For sparse implementations, a hash map mapping `(x, y, z)` tuples to occupancy flags is used [G].

### Steps
1. **Coordinate Transformation**: Convert world-space horizontal coordinates to the grid's local coordinate system [S2, unofficial].
   - Construct a local position vector $p = (x, 0, z)$ [S2, unofficial].
   - Apply the inverse rotation and subtract the origin: $p_{local} = R^{-1} \cdot (p - origin)$ [S2, unofficial].
2. **Grid Index Calculation**: Convert local coordinates to floating-point grid indices [S2, unofficial].
   - $lx_f = \frac{p_{local,x} + h}{s}$
   - $lz_f = \frac{p_{local,z} + h}{s}$
   - $ly_{lo,f} = \frac{y_{lo} - o_y + h}{s}$ [S2, unofficial]
   - $ly_{hi,f} = \frac{y_{hi} - o_y + h}{s}$ [S2, unofficial]
   *(Note: $h$ represents half the physical grid size, aligning the grid center with the origin [G].)*
3. **Bounds Checking**: Verify if the horizontal floating-point indices $(lx_f, lz_f)$ fall within the grid dimensions $[0, D_x)$ and $[0, D_z)$ [S2, unofficial]. If outside, return `false` (no collision) [S2, unofficial].
4. **Index Clamping**: Clamp the floating-point Y indices to valid integer grid bounds [S2, unofficial].
   - $ly_{lo} = \max(0, \lfloor ly_{lo,f} \rfloor)$ [S2, unofficial]
   - $ly_{hi} = \min(D_y - 1, \lceil ly_{hi,f} \rceil)$ [S2, unofficial]
5. **Iteration and Check**: Iterate through all integer Y indices $k$ from $ly_{lo}$ to $ly_{hi}$ [S2, unofficial].
   - Check the voxel at $(\lfloor lx_f \rfloor, k, \lfloor lz_f \rfloor)$ [S2, unofficial].
   - If the voxel is solid, return `true` [S2, unofficial].
6. **Result**: If the loop completes without finding a solid voxel, return `false` [S2, unofficial].

### Pseudocode
```python
def voxel_collision_test(world_x, world_z, world_y_lo, world_y_hi, grid):
    # 1. Transform to local coordinates
    local = grid.rot_inv * (Vec3(world_x, 0.0, world_z) - grid.origin)
    
    # 2. Calculate floating-point grid indices
    lx_f = (local.x + grid.half_grid) / grid.vox_size
    lz_f = (local.z + grid.half_grid) / grid.vox_size
    
    # 3. Check horizontal bounds
    if lx_f < 0 or lx_f >= grid.dim_x or lz_f < 0 or lz_f >= grid.dim_z:
        return False

    # 4. Convert Y bounds to local grid indices
    ly_lo_f = (world_y_lo - grid.origin.y + grid.half_grid) / grid.vox_size
    ly_hi_f = (world_y_hi - grid.origin.y + grid.half_grid) / grid.vox_size

    # 5. Clamp to integer bounds
    ly_lo = max(0, int(floor(ly_lo_f)))
    ly_hi = min(grid.dim_y - 1, int(ceil(ly_hi_f)))

    # 6. Iterate and check
    ix = int(floor(lx_f))
    iz = int(floor(lz_f))
    
    for y in range(ly_lo, ly_hi + 1):
        if grid.is_solid(ix, y, iz):
            return True
            
    return False
```
*(Note: `Vec3`, matrix multiplication, `floor`, and `ceil` are standard mathematical/vector operations [G].)*

### Parameters and Edge Cases
- **Voxel Size**: Determines resolution. Smaller sizes increase accuracy but memory usage and iteration count [G].
- **Precision**: Floating-point to integer conversion must handle boundary cases carefully. Using `floor` for start and `ceil` for end ensures full coverage of the slab [S2, unofficial].
- **Degenerate Input**: If $y_{lo} > y_{hi}$, the range is invalid and should return `false` or raise an error [G].
- **Out-of-Bounds**: Horizontal coordinates outside the grid must be handled explicitly to avoid memory access violations [S2, unofficial].

## Subtopics

### [Entity Collision & Movement](11316-entity-collision-movement.md)
Entity Collision & Movement is a discrete-time physics solver for voxel-based environments that handles collision detection, response, step-height climbing, and crouching for dynamic hitboxes against static voxel chunks and other dynamic solid hitboxes. It differs from simple grid checks by integrating gravity, ground detection, and axis-aligned movement with wall-sliding collision detection against voxel blocks. It builds on [Voxel Collision Test](5774-voxel-collision-test.md) by extending simple occupancy checks into a full state-based simulation loop [G].

### [Sphere-Voxel Collision Detection via Displacement Averaging](17929-sphere-voxel-collision-detection-via-displacement-averaging.md)
A collision detection method for a sphere moving through a voxel grid that calculates a displacement vector representing the push-out needed to resolve penetration by averaging displacements from all intersected voxel faces. It differs from simple boolean occupancy tests by providing a continuous resolution vector, allowing the sphere to be pushed out of the voxel structure rather than merely detecting overlap.

### [Haptic Collision Detection (Voxel-Only)](20786-haptic-collision-detection-voxel-only.md)
This method computes intersection points and force-feedback vectors between a haptic burr tool and a virtual object represented solely by a voxel set, enabling realistic tactile interaction during virtual carving. It distinguishes itself from sibling methods by relying exclusively on volumetric data for collision resolution, avoiding supplemental polygonal mesh information. Unlike [Entity Collision & Movement](11316-entity-collision-movement.md) which may use complex physics engines, or [Sphere-Voxel Collision Detection via Displacement Averaging](17929-sphere-voxel-collision-detection-via-displacement-averaging.md) which averages displacements, this method uses an "anchor-based" approach to determine force direction, ensuring stability in complex geometries like tight corners or pits.

## Operating characteristics
- **Time Complexity**: $O(D_y)$ for a vertical column test, where $D_y$ is the height of the grid in voxels [G]. For a full volume test, it is $O(D_x D_y D_z)$ [G].
- **Memory Complexity**: $O(D_x D_y D_z)$ for dense grids [G]. Sparse implementations use $O(N)$ where $N$ is the number of occupied voxels [G].
- **Performance**: Very fast for sparse checks or when early-out conditions are met [G]. The bottleneck in particle systems is often the rendering (billboarding) rather than the collision test itself [S3, unofficial].
- **Strengths**: Simple to implement, robust for axis-aligned movements, handles concave geometry naturally [S3, unofficial].
- **Limitations**: Resolution-dependent; may miss thin features smaller than a voxel [G]. Does not provide contact normals or penetration depth without extension [G].

## Background
The Voxel Collision Test is a fundamental operation in voxel-based game engines and simulations [S1, S2, S3, unofficial]. It is often referred to as a "simple grid check" in the context of early voxel engines like noa [S1, unofficial]. It is used in physics simulations for entities [S2, unofficial] and GPU particle systems [S3, unofficial]. The method extends naturally from 2D collision checks used in tile-based games [S1, unofficial].
