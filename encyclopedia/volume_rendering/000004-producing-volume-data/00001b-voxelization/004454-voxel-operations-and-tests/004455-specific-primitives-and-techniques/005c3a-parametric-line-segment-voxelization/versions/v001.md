# Parametric Line Segment Voxelization

Also called: 3D line segment 3D raster decomposition, Parametric Method

## Overview
The Parametric Method is an algorithm for generating a 3D line segment primitive by computing points along the segment using a parameter $t$, then mapping these points to voxels [S1, unofficial]. It is identified as having the best performance characteristics in terms of speed and potential for parallelization in GPGPU implementation compared to other methods like the seven-neighbor search [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Start point $S$, End point $E$ of the line segment.
*   **Output:** Array of voxels $V(k)$ representing the 3D raster decomposition of the segment [S1, unofficial].

**Data Structures**
*   **Points:** $S$ and $E$ are 3D coordinates (vectors).
*   **Voxels:** The output is an array where each element corresponds to a voxel coordinate or index along the segment.
*   **Parameters:**
    *   $N$: The number of steps or voxels in the decomposition, defined as $N = \text{int}(\|E - S\|)$, where $\|E - S\|$ is the Euclidean distance (magnitude) of the vector $E-S$ [S1, unofficial].
    *   $W$: The step vector (guiding vector), defined as $W = \frac{E - S}{N}$ [S1, unofficial].

**Numbered Steps**
1.  Initialize the start point $S$ and end point $E$ of the line segment [S1, unofficial].
2.  Compute the length of the segment vector $E - S$ and define $N$ as the integer part of this length: $N = \text{int}(\|E - S\|)$ [S1, unofficial].
3.  Compute the step vector $W$ using the formula:
    $$W = \frac{E - S}{N}$$
    [S1, unofficial]
4.  Loop for $k$ from $0$ to $N$ (inclusive):
    *   Compute the point $G_k$ on the segment:
        $$G_k = S + W \cdot k$$
        [S1, unofficial]
    *   Map $G_k$ to the corresponding voxel coordinate. The text states that $G_k$ points "consistently run through all unknown voxels of the SE line segment 3D raster decomposition" [S1, unofficial]. The output array $V(k)$ stores these voxel assignments [S1, unofficial].

**Formulas**
*   **Parametric Position:** An arbitrary point $G$ on the line segment is defined as:
    $$G = E t + S(1 - t) = S + (E - S) \cdot t, \quad 0 \le t \le 1$$
    where $S$ and $E$ are the Start and End points, and $t$ is a parameter [S1, unofficial].
*   **Step Parameter:** The parameter $t_k$ for the $k$-th step is computed as:
    $$t_k = \frac{k}{N}$$
    where $N = \text{int}(\|E - S\|)$ and $k = 0, 1, 2, ..., N$ [S1, unofficial].
*   **Point Calculation:** The point $G_k$ is calculated as:
    $$G_k = S + W \cdot k$$
    where $W = \frac{E - S}{N}$ [S1, unofficial]. This is equivalent to $G_k = S + (E - S) \cdot \frac{k}{N}$ [S1, unofficial].

**Pseudocode**
```python
def parametric_line_voxelization(S, E):
    """
    Generates voxel coordinates for a 3D line segment using the Parametric Method.
    
    Args:
        S (tuple/list): Start point (x, y, z).
        E (tuple/list): End point (x, y, z).
        
    Returns:
        list: List of voxel coordinates (or indices, depending on mapping implementation) 
              for each step k from 0 to N.
    """
    # Compute vector from S to E
    dx = E[0] - S[0]
    dy = E[1] - S[1]
    dz = E[2] - S[2]
    
    # Compute Euclidean length
    length_sq = dx*dx + dy*dy + dz*dz
    length = length_sq ** 0.5
    
    # Define N as integer part of length
    N = int(length)
    
    # Handle degenerate case where length is 0
    if N == 0:
        # Return the voxel containing S (or E, as they are the same)
        # Mapping to voxel requires floor or round depending on coordinate system.
        # Assuming standard voxelization where voxel index is floor of coordinate.
        return [voxel_from_point(S)]
    
    # Compute step vector W
    Wx = dx / N
    Wy = dy / N
    Wz = dz / N
    
    voxels = []
    
    # Loop for k from 0 to N
    for k in range(N + 1):
        # Compute point G_k
        Gx = S[0] + Wx * k
        Gy = S[1] + Wy * k
        Gz = S[2] + Wz * k
        
        # Map point to voxel
        # Note: The source does not specify the exact voxel mapping function (e.g., floor, round).
        # Standard practice is floor for lower-left corner alignment.
        voxel = voxel_from_point((Gx, Gy, Gz))
        voxels.append(voxel)
        
    return voxels
```

**Edge Cases and Pitfalls**
*   **Zero Length:** If $S = E$, $N=0$. The loop runs for $k=0$, returning the voxel containing the point.
*   **Multiple Segments with Different Lengths:** When generating multiple segments with different lengths, the number of streams (blocks) determining voxel counts is equal to the maximum length of all segments. This creates redundant computations for shorter segments [S1, unofficial].
*   **Branch Divergence:** In GPU implementations for multiple segments, branching in the kernel (checking if $k < n[i]$ for each segment's length $n[i]$) causes diverging streams, negatively affecting overall speed [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per segment, where $N$ is the length of the segment in voxels. For multiple segments, it is proportional to the sum of lengths, but GPU implementation may pad to the maximum length, leading to $O(N_{max} \times M)$ where $M$ is the number of segments if not handled carefully [S1, unofficial].
*   **Memory Complexity:** $O(N)$ to store the output voxel array for a single segment.
*   **Performance:** The method possesses the best performance characteristics in terms of speed and potential for parallelization in GPGPU implementation compared to the "seven neighboring voxels-applicants" method [S1, unofficial].
*   **Parallelization:** The search for a certain voxel does not depend on the search for neighboring voxels, allowing for high parallelization potential [S1, unofficial].
*   **Strengths:** High speed, excellent parallelization suitability for GPU, simple computation.
*   **Limitations:** Redundant computation for short segments in batch processing; branch divergence in GPU kernels if segment lengths vary significantly [S1, unofficial].
*   **When to Use:** When generating 3D line segments for volume visualization on GPU, especially when performance and parallelization are critical [S1, unofficial].
*   **When Not to Use:** When memory bandwidth is extremely constrained and segment lengths vary wildly, causing significant padding overhead; or when exact topological connectivity (like the 7-neighbor method might provide) is required for subsequent processing steps that depend on neighbor relationships [S1, unofficial].

## Background
*   **Origin:** The method is part of a generalized method for generating arbitrary 3D volume graphics primitives $\Gamma(x,y,z)$ bounded by surface $P(x,y,z)$ and curve $\Phi(x,y,z)$ [S1, unofficial].
*   **History:** Developed and theoretically investigated by Anas M. Al-Oraiqat and Sergii A. Zori [S1, unofficial]. It was evaluated against other algorithms like the "seven neighboring voxels-applicants" method [S1, unofficial].
*   **Usage:** Used for GPGPU generation of 3D line segments for volume visualization in 3D graphics systems [S1, unofficial]. Experiments were conducted on NVIDIA GPUs including GeForce GTX 260, 1050, 760, and 1070i [S1, unofficial].
