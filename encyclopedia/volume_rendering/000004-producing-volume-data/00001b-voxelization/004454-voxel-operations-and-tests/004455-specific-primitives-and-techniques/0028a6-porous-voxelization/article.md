# Porous Voxelization

Also called: Random Voxel Dropping

## Overview
Porous Voxelization generates porous or sponge-like voxel meshes by randomly discarding voxels during the voxelization process based on a spatial hash of their coordinates [S1, unofficial]. It differs from standard voxelization, which retains all computed voxels, by selectively removing voxels to create a distributed porosity without requiring global connectivity analysis [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A mesh or geometric primitive to be voxelized, and an optional porosity parameter $p \in [0.0, 1.0]$ [S1, unofficial].
- Output: A set of voxel indices representing the object, with a subset removed based on the porosity threshold [S1, unofficial].

**Data Structures:**
- Voxel coordinates $(x, y, z)$, represented as integers corresponding to grid indices [S1, unofficial].
- Porosity parameter $p$, stored as `Option<f64>`; if `None`, no voxels are dropped [S1, unofficial].

**Steps:**
1. Iterate over each voxel $(x, y, z)$ generated by the underlying solid or surface voxelization loop [S1, unofficial].
2. Compute a scalar $\text{dot}$ derived from the voxel coordinates $(x, y, z)$ [S1, unofficial].
3. Compute a hash value $h$ using the deterministic pseudo-random function: $h = | \text{fract}( \sin(\text{dot}) \times 43758.5453 ) |$ [S1, unofficial].
4. If porosity is `Some(p)`, keep the voxel if $h \ge p$, otherwise discard it [S1, unofficial].
5. If porosity is `None`, keep the voxel [S1, unofficial].

**Parameters:**
- `porosity`: `Option<f64>`. Valid values are in the range $[0.0, 1.0]$ [S1, unofficial].
  - $0.0$: All voxels are kept since $h \ge 0.0$ is always true for absolute fractional parts [S1, unofficial].
  - $1.0$: No voxels are kept since $h < 1.0$ is always true, making $h \ge 1.0$ never true [S1, unofficial].
  - Typical values: $0.5$ results in approximately $50\%$ of voxels being dropped [S1, unofficial].

**Edge Cases and Pitfalls:**
- Invalid porosity values (outside $[0.0, 1.0]$ or `NaN`) passed directly to the library API bypass validation, leading to misleading results [S1, unofficial].
  - $p > 1.0$ (e.g., $1.5$): The condition $h \ge p$ is never met, effectively dropping all voxels [S1, unofficial].
  - $p < 0.0$ (e.g., $-0.5$) or `NaN`: The condition $h \ge p$ effectively disables dropping [S1, unofficial].
- The hash function is deterministic for the same voxel coordinates to ensure consistent results across runs [S1, unofficial].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
import math

def porous_voxelization(candidate_voxels, porosity=None):
    """
    Apply porous voxelization to a list of candidate voxel coordinates.
    
    Args:
        candidate_voxels: List of (x, y, z) integer tuples from a base voxelizer.
        porosity: Optional float in [0.0, 1.0]. If None, no voxels are dropped.
        
    Returns:
        List of (x, y, z) tuples that pass the porosity filter.
    """
    kept_voxels = []
    for x, y, z in candidate_voxels:
        # Compute scalar dot product from coordinates (standard linear combination)
        dot = x * 1.0 + y * 2.0 + z * 3.0
        # Compute hash: fractional part of sine scaled by constant, then absolute
        hash_val = abs(math.sin(dot) * 43758.5453 % 1.0)
        
        # Apply porosity filter
        if porosity is None or hash_val >= porosity:
            kept_voxels.append((x, y, z))
    return kept_voxels
```

## Subtopics

### [Random Packed-Sphere Porous Geometry Generator](21268-random-packed-sphere-porous-geometry-generator.md)
Generates voxelized representations of porous media by packing spheres into a volume with fixed or variable radii to match a target porosity. It differs from standard binary voxelization by incorporating a distance-rejection check for sphere placement and a grid-averaging step to smooth discrete boundaries. Choose this method when physically realistic porous structures are required rather than simple random porosity.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of voxels generated by the standard voxelization process [S1, unofficial]. The hash computation is $O(1)$ per voxel [S1, unofficial].
- **Memory Complexity:** $O(K)$, where $K$ is the number of voxels kept after porosity filtering [S1, unofficial].
- **Strengths:** Creates a visually porous structure without complex connectivity analysis [S1, unofficial]. Deterministic results for the same input and porosity value [S1, unofficial]. Simple to implement as a post-processing step or integrated into the voxelization loop [S1, unofficial].
- **Limitations:** May create disconnected components or holes that are not physically meaningful. Invalid porosity values can lead to unexpected results if not validated [S1, unofficial]. The distribution of pores is pseudo-random and may not match specific material properties [S1, unofficial].
- **When to use:** When a sponge-like or porous appearance is desired for visual effects or simplified simulation, and exact physical porosity is not critical [S1, unofficial].
- **When not to use:** When physical accuracy of pore structure is required, or when connectivity of the voxel set is critical [S1, unofficial].

## Background
Porous Voxelization was implemented in the `voxelizer-rs` project (lhemerly/voxelizer-rs) as part of Pull Request #179, added to the `MeshProcessor::voxelize` method and CLI interface [S1, unofficial]. It was introduced to allow for random voxel dropping during voxelization, resulting in porous/sponge-like generated meshes [S1, unofficial].
