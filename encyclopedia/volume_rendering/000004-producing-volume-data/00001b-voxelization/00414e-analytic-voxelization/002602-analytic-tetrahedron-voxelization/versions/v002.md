# Analytic Tetrahedron Voxelization

Also called: Exact Conservative Voxelization of Tetrahedra, Graph-traversal voxelization, Remeshing-based voxelization, analytic volume sampling of tetrahedra, voxelization of tetrahedra

## Overview
Analytic Tetrahedron Voxelization is a method for robustly intersecting convex polyhedra (specifically tetrahedra) and computing polynomial integrals over the resulting intersection domain to achieve physically conservative voxelization [S1, unofficial]. Unlike standard binary voxelization which only stores occupancy, this method computes exact mass-conservative moments (volume, linear, and quadratic) for each grid cell, ensuring the total mass in the grid exactly equals the integral of the input density field [S1, unofficial]. It sets itself apart from siblings like [Monte Carlo 2D Voxelization](1734-monte-carlo-2d-voxelization.md) by providing deterministic, exact conservation without statistical noise, and from [Analytic Moment Voxelization](3307-analytic-moment-voxelization.md) by focusing specifically on the robust geometric clipping of tetrahedra using planar graph representations [S1, unofficial].

## How it works
The method voxelizes a single tetrahedron onto a destination Cartesian grid by computing physically conservative moments for a specified polynomial order [S2, unofficial]. It relies on a unified framework for intersecting convex polyhedra via successive clipping against faces, coupled with an integration routine on the same planar graph representation [S1, unofficial].

### Inputs and Outputs
**Inputs:**
*   **Tetrahedron Vertices:** Four 3D points $v_0, v_1, v_2, v_3$.
*   **Grid Parameters:** Dimensions $n = (n_x, n_y, n_z)$, cell sizes $d = (d_x, d_y, d_z)$, and polynomial order $p \in \{0, 1, 2\}$ [S2, unofficial].
*   **Coordinate System:** The grid covers a specific domain (e.g., $[-1, 1]^3$ or unit cube). World coordinates map to grid indices via $idx = \lfloor (x + 1) / \text{step} \rfloor$ [S1, unofficial].

**Outputs:**
*   **Moments:** A buffer `grid.moments` storing the integrated moments for each voxel. For polynomial order $p$, the number of moments per voxel is $(p+1)(p+2)(p+3)/6$. For $p=2$, this includes constant (volume), linear ($x,y,z$), and quadratic ($x^2, y^2, z^2, xy, xz, yz$) terms [S2, unofficial].

### Data Structures
The implementation uses specific structures to manage geometry and grid state [S2, unofficial]:

1.  **`r3d_plane`**: Defines a clip plane.
    *   `n`: Unit normal vector $(n_x, n_y, n_z)$.
    *   `d`: Signed distance to the origin.
2.  **`r3d_orientation`**: Tracks the status of a vertex relative to clip planes.
    *   `fdist[4]`: Signed distances to the four clip planes.
    *   `fflags`: Bit flags (4 bits) indicating if the vertex is inside ($1$) or outside ($0$) each plane.
3.  **`r3d_dest_grid`**: The output grid container.
    *   `n`: Grid dimensions $(n_x, n_y, n_z)$.
    *   `d`: Cell sizes $(d_x, d_y, d_z)$.
    *   `polyorder`: Integer $0, 1,$ or $2$.
    *   `moments`: Array of pointers `r3d_real* moments[10]` (gridded moments in row-major C order, size at least $n_x n_y n_z$).
    *   `orient`: Buffer for gridpoint orientation checks, size at least $(n_x+1)(n_y+1)(n_z+1)$.
    *   `bufsz`: Buffer size.

### Algorithm Steps

1.  **Orientation Check:** Ensure the tetrahedron vertices are oriented such that the volume is positive. If `r3du_orient(v0, v1, v2, v3)` returns negative, swap vertices $v_2$ and $v_3$ [S2, unofficial].
2.  **Face Conversion:** Convert the vertex representation to a face representation using `r3du_tet_faces_from_verts` to obtain the four clip planes defining the tetrahedron [S2, unofficial].
3.  **Voxel Search:** Identify voxels that intersect the tetrahedron. Two search strategies are supported [S1, unofficial]:
    *   **Brute-Force:** Check every grid point against each tetrahedron face. Scales as $g^3$.
    *   **Binary Space Partitioning (BSP):** Use a spatial tree to prune empty regions. Scales as $g^2 \log g$. BSP overtakes brute-force at grid resolution $128^3$ [S1, unofficial].
4.  **Orientation Initialization:** For each voxel (or BSP node), compute the `r3d_orientation` for its corners. Calculate signed distances $g_{or} = \mathbf{d} + \mathbf{g}_{pt} \cdot \mathbf{n}$ for each face $f$ and corner $v$. Set `fflags` bit $f$ to $1$ if $g_{or} > 0$, else $0$ [S2, unofficial].
5.  **Classification:** Determine the voxel type based on the bitwise AND (`andcmp`) and OR (`orcmp`) of the corner flags [S2, unofficial]:
    *   **Type 1 (Interior):** `andcmp == 0x0f`. All corners are inside. The voxel is fully contained.
    *   **Type 3 (Boundary):** `orcmp == 0x0f` is false, but `andcmp` is not $0x0f$. The voxel intersects the boundary.
    *   **Type 0 (Exterior):** `orcmp == 0x00`. All corners are outside. Ignore.
6.  **Reduction (Interior Voxels):** For Type 1 voxels, compute analytic moments directly without clipping. For a voxel at index $(i, j, k)$ with cell size $d$, the moments are [S2, unofficial]:
    *   Volume ($M_0$): $d_x d_y d_z$
    *   Linear ($M_1$): $M_0 \cdot (i + 0.5) d_x$ (for x), similarly for y, z.
    *   Quadratic ($M_2$):
        *   $x^2$: $M_0 \cdot \frac{1}{3} d_x^2 (1 + 3i + 3i^2)$
        *   $y^2$: $M_0 \cdot \frac{1}{3} d_y^2 (1 + 3j + 3j^2)$
        *   $xy$: $M_0 \cdot \frac{1}{4} d_x d_y (1 + 2i)(1 + 2j)$
    *   Add these to `grid.moments` [S2, unofficial].
7.  **Clipping and Integration (Boundary Voxels):** For Type 3 voxels, perform exact clipping [S1, unofficial]:
    *   **Graph Representation:** Store the polyhedron using vertex locations and neighbors, coupled with the clipping algorithm to ensure topological validity [S1, unofficial].
    *   **Clipping Operation:** Successively clip the voxel (initially a unit cube or grid cell) against the tetrahedron's faces. Use a depth-first graph traversal on the planar graph representation to insert new vertices in correct order on the fly, avoiding post-clipping reordering [S1, unofficial]. This ensures robustness against geometric degeneracies (e.g., vertices on clip planes) without auxiliary checks or high-precision arithmetic [S1, unofficial].
    *   **Integration:** Compute the polynomial integrals over the resulting clipped polyhedron. The clipping routine is coupled with the integration routine on the same planar graph representation [S1, unofficial].
    *   **Local Frame:** Shift the clipped geometry to a local coordinate frame prior to integration. Note: Cancellation errors may arise here, reducing accuracy to a few orders of magnitude below machine precision, though the reduction process itself is accurate [S1, unofficial].
    *   **Accumulation:** Add the computed moments to `grid.moments` [S2, unofficial].

### Pseudocode

```python
def r3d_voxelize_tet(verts, grid):
    """
    Voxelize a tetrahedron onto a Cartesian grid.
    verts: list of 4 vectors [v0, v1, v2, v3]
    grid: r3d_dest_grid structure
    """
    # 1. Orientation Check
    if r3du_orient(verts[0], verts[1], verts[2], verts[3]) < 0:
        swap(verts[2], verts[3])

    # 2. Face Conversion
    faces = r3du_tet_faces_from_verts(verts)
    # faces is an array of 4 r3d_plane structures

    # 3. Search Strategy Selection
    # Use BSP if grid resolution > 128^3, else Brute-Force
    if grid.n.x > 128 and grid.n.y > 128 and grid.n.z > 128:
        voxels_to_process = bsp_search(faces, grid)
    else:
        voxels_to_process = brute_force_search(faces, grid)

    # 4. Process Voxels
    for voxel in voxels_to_process:
        # 5. Orientation Initialization for voxel corners
        orient_flags = compute_corner_orientations(voxel, faces)
        
        andcmp = orient_flags[0] & orient_flags[1] & orient_flags[2] & orient_flags[3]
        orcmp = orient_flags[0] | orient_flags[1] | orient_flags[2] | orient_flags[3]

        if andcmp == 0x0F:
            # Type 1: Interior
            reduce_interior_voxel(voxel, grid, faces)
        elif orcmp != 0x00:
            # Type 3: Boundary
            clip_and_integrate_voxel(voxel, grid, faces)
        # else: Type 0: Exterior, skip

def reduce_interior_voxel(voxel, grid, faces):
    """Compute analytic moments for a fully contained voxel."""
    i, j, k = voxel.index
    dx, dy, dz = grid.d
    vol = dx * dy * dz
    
    # Constant moment
    grid.moments[0][voxel.index] += vol
    
    # Linear moments
    if grid.polyorder >= 1:
        grid.moments[1][voxel.index] += vol * dx * (i + 0.5)
        grid.moments[2][voxel.index] += vol * dy * (j + 0.5)
        grid.moments[3][voxel.index] += vol * dz * (k + 0.5)
        
    # Quadratic moments
    if grid.polyorder >= 2:
        grid.moments[4][voxel.index] += vol * (1/3) * dx**2 * (1 + 3*i + 3*i**2)
        grid.moments[5][voxel.index] += vol * (1/3) * dy**2 * (1 + 3*j + 3*j**2)
        grid.moments[6][voxel.index] += vol * (1/3) * dz**2 * (1 + 3*k + 3*k**2)
        grid.moments[7][voxel.index] += vol * 0.25 * dx * dy * (1 + 2*i) * (1 + 2*j)
        grid.moments[8][voxel.index] += vol * 0.25 * dx * dz * (1 + 2*i) * (1 + 2*k)
        grid.moments[9][voxel.index] += vol * 0.25 * dy * dz * (1 + 2*j) * (1 + 2*k)

def clip_and_integrate_voxel(voxel, grid, faces):
    """Clip voxel against tetrahedron faces and integrate."""
    # Initialize voxel as a unit cube or grid-aligned box
    polyhedron = voxel_to_polyhedron(voxel)
    
    # Successive clipping using depth-first graph traversal
    # This modifies polyhedron in-place, maintaining topological validity
    for face in faces:
        polyhedron = clip_polyhedron_against_plane(polyhedron, face)
        
    # Compute moments over the resulting clipped polyhedron
    moments = integrate_polyhedron_moments(polyhedron, grid.polyorder)
    
    # Accumulate to grid
    for m in range(len(moments)):
        grid.moments[m][voxel.index] += moments[m]
```

### Parameters and Typical Values
*   **Polynomial Order ($p$):** $0$ (constant/volume), $1$ (linear), $2$ (quadratic) [S2, unofficial].
*   **Grid Resolution:** Tests performed on $128^3$ and up to $1024^3$ [S1, unofficial].
*   **Precision:** Double precision is recommended for accuracy; single precision yields errors of $\sim 10^{-4}$ for quadratic moments [S1, unofficial].

### Edge Cases and Pitfalls
*   **Geometric Degeneracy:** Vertices lying exactly on clip planes or grid boundaries. The method is immune to these degeneracies due to the graph-traversal clipping approach, which maintains topological consistency [S1, unofficial].
*   **Cancellation Errors:** Shifting voxels to a local coordinate frame prior to integration can cause cancellation errors, reducing accuracy to a few orders of magnitude below machine precision [S1, unofficial].
*   **Search Performance:** Brute-force search is faster for coarse grids due to BSP overhead. BSP only becomes faster at $128^3$ resolution [S1, unofficial].

## Subtopics

### [Exact General Remeshing Scheme for Conservative Voxelization](3774-exact-general-remeshing-scheme-for-conservative-voxelization.md)
This method voxelizes a single tetrahedron onto a Cartesian grid by computing physically conservative moments (volume, linear, quadratic) for a specified polynomial order. It ensures that the total mass in each grid cell exactly equals the integral of the input density field over the cell, avoiding aliasing noise. Unlike standard rasterization or Sutherland-Hodgman clipping, which can fail due to geometric degeneracy and roundoff errors, this scheme uses planar graph representations to maintain topological consistency during clipping, guaranteeing robustness even when vertices lie on clip planes.

## Operating characteristics
*   **Time Complexity:** Clipping and reduction operations scale roughly quadratically with the grid dimension $g$ ($O(g^2)$), corresponding to the surface area of the tetrahedra in units of squared grid spacing [S1, unofficial].
    *   **Brute-Force Search:** Scales as $O(g^3)$ [S1, unofficial].
    *   **BSP Search:** Scales as $O(g^2 \log g)$ [S1, unofficial].
*   **Memory Complexity:** Linear in the number of voxels $N = n_x n_y n_z$ for storing moments and orientation buffers [S2, unofficial].
*   **Measured Performance:** On a $128^3$ grid with $10^5$ random tetrahedra, the method produces $\sim 2.3 \times 10^4$ interior and $\sim 1.5 \times 10^4$ boundary voxels per tetrahedron [S1, unofficial]. It is 3-4 times faster than López and Hernández (2008) for clipping, and 2 times faster overall [S1, unofficial].
*   **Accuracy:** The method is "physically conservative," meaning the sum of voxelized moments equals the analytic moments of the tetrahedron up to floating-point precision [S2, unofficial]. Maximum fractional errors on a $128^3$ grid are $\sim 10^{-12}$ for constant/linear moments and $\sim 10^{-4}$ for quadratic moments in single precision [S1, unofficial].
*   **Strengths:** Robustness to degeneracy, exact conservation, no need for high-precision arithmetic or auxiliary checks.
*   **Limitations:** Cancellation errors in local frame integration reduce quadratic moment accuracy. BSP overhead makes brute-force preferable for coarse grids.

## Background
The method was introduced in a paper by an unspecified author (cited as [S1, unofficial]) focusing on cosmological N-body systems. It builds on the ideas of Sugihara (1994) for planar graph representation and the clipping operation of Stephenson and Christiansen (1975), as implemented by López and Hernández (2008). The problem of computing exact intersection volumes between polyhedra has been studied by Dukowicz and Kodis (1987), Dukowicz et al. (1991), and Grandy (1999) [S1, unofficial]. The C implementation `r3d` is available from Los Alamos National Laboratory [S2, unofficial].
