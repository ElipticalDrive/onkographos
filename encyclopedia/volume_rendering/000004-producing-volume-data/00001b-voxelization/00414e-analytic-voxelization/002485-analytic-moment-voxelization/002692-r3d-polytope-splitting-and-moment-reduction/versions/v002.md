# R3D Polytope Splitting and Moment Reduction

Also called: voxel moment accumulation

## Overview
R3D Polytope Splitting and Moment Reduction is a voxelization technique that computes exact coordinate moments of the intersection between a 3D polytope and a Cartesian grid by recursively splitting the polytope along grid axes until it fits within a single voxel, then reducing the polytope's moments to that voxel [S1, unofficial]. It builds on [Analytic Moment Voxelization](3307-analytic-moment-voxelization.md) by providing the specific geometric splitting and moment accumulation logic required to handle arbitrary convex polyhedra [S1, unofficial]. It differs from [Polynomial Field Integration via Coordinate Moments](3791-polynomial-field-integration-via-coordinate-moments.md) by focusing on the spatial decomposition of the domain (voxels) rather than the integration of a field over a fixed domain [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- `poly`: A convex 3D polytope defined by a list of vertices and their connectivity.
- `moments`: An array to store the computed coordinate moments.
- `polyorder`: The highest order of moments to compute.
- `dest_grid`: The output grid storing accumulated moments.
- `d`: Grid spacing vector $(dx, dy, dz)$.
- `ibox`: The bounding box of the current polytope in voxel coordinates.
- `dmax`: The maximum dimension of the bounding box in voxels.

**Outputs:**
- `moments`: Filled with the moments of the polytope's intersection with the current voxel.
- `dest_grid`: Updated with the moments from the current voxel.

### Data Structures
The implementation relies on the following structures [S1, unofficial]:

```c
typedef struct {
    r3d_real x, y, z; // Real coordinates
} r3d_rvec3;

typedef struct {
    r3d_int i, j, k; // Integer voxel indices
} r3d_dvec3;

typedef struct {
    r3d_real d;       // Plane constant
    r3d_rvec3 n;      // Plane normal
} r3d_plane;

typedef struct {
    r3d_rvec3 pos;    // Vertex position
    r3d_int pnbrs[3]; // Neighbor vertex indices
} r3d_vertex;

typedef struct {
    r3d_int nverts;   // Number of vertices
    r3d_vertex verts[]; // Flexible array member for vertices
} r3d_poly;
```
*Note: `r3d_real` is `double` by default, or `float` if compiled with `-DSINGLE_PRECISION` [S1, unofficial]. `R3D_MAX_VERTS` limits the vertex buffer size (default 512) [S1, unofficial].*

### Algorithm Steps

1.  **Bounding Box Computation (`r3d_get_ibox`)**:
    Compute the integer bounding box `ibox[2]` for a polytope [S1, unofficial]. Initialize `rbox[0]` to $1.0 \times 10^{30}$ and `rbox[1]` to $-1.0 \times 10^{30}$ for all 3 dimensions [S1, unofficial]. Iterate over all vertices to find min/max coordinates [S1, unofficial]. Compute:
    $$ \text{ibox}[0].\text{ijk}[i] = \lfloor \text{rbox}[0].\text{xyz}[i] / d.\text{xyz}[i] \rfloor $$
    $$ \text{ibox}[1].\text{ijk}[i] = \lceil \text{rbox}[1].\text{xyz}[i] / d.\text{xyz}[i] \rceil $$
    [S1, unofficial]

2.  **Clamping (`r3d_clamp_ibox`)**:
    Clamp the polytope's `ibox` to a `clampbox` [S1, unofficial]. If `ibox` is completely outside `clampbox` (i.e., $\text{ibox}[1].\text{ijk}[i] \le \text{clampbox}[0].\text{ijk}[i]$ or $\text{ibox}[0].\text{ijk}[i] \ge \text{clampbox}[1].\text{ijk}[i]$), clear `ibox` and set `poly->nverts = 0` [S1, unofficial]. If $\text{ibox}[0].\text{ijk}[i] < \text{clampbox}[0].\text{ijk}[i]$, add a clipping plane with $d = -\text{clampbox}[0].\text{ijk}[i] \cdot d.\text{xyz}[i]$ and $n.\text{xyz}[i] = 1.0$ [S1, unofficial]. If $\text{ibox}[1].\text{ijk}[i] > \text{clampbox}[1].\text{ijk}[i]$, add a plane with $d = \text{clampbox}[1].\text{ijk}[i] \cdot d.\text{xyz}[i]$ and $n.\text{xyz}[i] = -1.0$ [S1, unofficial]. If planes were added, call `r3d_clip(poly, boxfaces, nboxclip)` [S1, unofficial].

3.  **Main Loop (Splitting)**:
    Maintain a stack of polytopes to process [S1, unofficial]. For each polytope on the stack:
    -   If `dmax == 1` (single voxel):
        Call `r3d_reduce(&stack[nstack].poly, moments, polyorder)` to compute moments [S1, unofficial].
        Accumulate moments into `dest_grid` using the index macro:
        $$ \text{gind}(ii, jj, kk, mm) = \text{nmom} \cdot ((ii - \text{ibox}[0].i) \cdot \text{gridsz}.j \cdot \text{gridsz}.k + (jj - \text{ibox}[0].j) \cdot \text{gridsz}.k + (kk - \text{ibox}[0].k)) + mm $$
        [S1, unofficial]
    -   If `dmax > 1`:
        Split the polytope along the axis `spax` at coordinate $c = d.\text{xyz}[\text{spax}] \cdot (\text{stack}[nstack].\text{ibox}[0].\text{ijk}[\text{spax}] + \text{dmax}/2)$ using `r3d_split_coord` [S1, unofficial]. This produces two child polytopes `children[0]` and `children[1]` [S1, unofficial].
        Update the bounding box indices for the children [S1, unofficial]. Copy the parent `ibox` to both.
        For `children[0]`: subtract $(\text{dmax} - \text{dmax}/2)$ from $\text{children}[0].\text{ibox}[1].\text{ijk}[\text{spax}]$ [S1, unofficial].
        For `children[1]`: add $\text{dmax}/2$ to $\text{children}[1].\text{ibox}[0].\text{ijk}[\text{spax}]$ [S1, unofficial].
        Increment `nstack` by 2 to push children to the stack [S1, unofficial].

4.  **Coordinate Splitting (`r3d_split_coord`)**:
    -   Calculate signed distances: $\text{sdists}[v] = \text{vertbuffer}[v].\text{pos}.\text{xyz}[\text{ax}] - \text{coord}$ for all vertices [S1, unofficial].
    -   Mark $\text{side}[v] = 1$ if $\text{sdists}[v] > 0.0$ [S1, unofficial]. Count `nright`.
    -   **Edge Cases**: If `nright == 0`, copy `inpoly` to `outpolys[0]` and set `outpolys[1]->nverts = 0`. If `nright == *nverts`, copy `inpoly` to `outpolys[1]` and set `outpolys[0]->nverts = 0` [S1, unofficial].
    -   **Bisecting Edges**: Iterate over all vertices `vcur`. If `side[vcur]` is false, iterate over its 3 neighbors `np`. If neighbor `vnext` has `side[vnext]` true, bisect the edge using linear interpolation to find the intersection point [G]. Add new vertex to buffer, link it to `vcur` and `vnext`, increment `*nverts`. Set `side[*nverts] = 1`. Update neighbor pointers for `vcur` and `vnext` to include the new vertex [S1, unofficial].
    -   **Face Traversal**: For each new vertex (`vstart` from `onv` to `*nverts-1`), traverse the face to find new neighbor links. Start at `vcur = vstart`, `vnext = vertbuffer[vcur].pnbrs[0]`. Loop: find `np` such that `vertbuffer[vnext].pnbrs[np] == vcur`. Move `vcur = vnext`. Set `pnext = (np+1)%3`. Set `vnext = vertbuffer[vcur].pnbrs[pnext]`. Continue while `vcur < onv`. Finally, link `vertbuffer[vstart].pnbrs[2] = vcur` and `vertbuffer[vcur].pnbrs[1] = vstart` [S1, unofficial].
    -   **Compression**: Iterate `v` from 0 to `onv-1`. Get `cside = side[v]`. Copy `vertbuffer[v]` to `outpolys[cside]->verts[outpolys[cside]->nverts]`. Update `side[v]` to the new index (`outpolys[cside]->nverts`++). Increment `outpolys[cside]->nverts` [S1, unofficial].
    -   **Reindexing**: For each vertex `v` in `outpolys[0]`, update its 3 `pnbrs` entries using the `side[]` array: `outpolys[0]->verts[v].pnbrs[np] = side[outpolys[0]->verts[v].pnbrs[np]]`. Do the same for `outpolys[1]` [S1, unofficial].

5.  **Moment Reduction (`r3d_reduce`)**:
    Compute the moments of the polytope. This involves decomposing the polytope into tetrahedra and computing the moments for each tetrahedron. The moments for a tetrahedron with vertices $v_0, v_1, v_2, v_3$ are computed using the local volume `locvol` and specific polynomial combinations of vertex coordinates. For example, moments 8, 9, and 10 are computed as [S1, unofficial]:
    $$ \text{moments}[8] += \text{locvol} \cdot 0.05 \cdot (v_2.y \cdot v_0.z + v_2.y \cdot v_1.z + 2 \cdot v_2.y \cdot v_2.z + v_0.y \cdot (2 \cdot v_0.z + v_1.z + v_2.z) + v_1.y \cdot (v_0.z + 2 \cdot v_1.z + v_2.z)) $$
    $$ \text{moments}[9] += \text{locvol} \cdot 0.05 \cdot (v_2.x \cdot v_0.z + v_2.x \cdot v_1.z + 2 \cdot v_2.x \cdot v_2.z + v_0.x \cdot (2 \cdot v_0.z + v_1.z + v_2.z) + v_1.x \cdot (v_0.z + 2 \cdot v_1.z + v_2.z)) $$
    (Other moments follow similar patterns based on the polynomial order) [S1, unofficial].

### Pseudocode
```python
class r3d_vertex:
    def __init__(self, pos, pnbrs):
        self.pos = pos
        self.pnbrs = pnbrs

class r3d_rvec3:
    def __init__(self, x, y, z):
        self.x = x
        self.y = y
        self.z = z
    def __getitem__(self, idx):
        return [self.x, self.y, self.z][idx]
    def __sub__(self, other):
        return r3d_rvec3(self.x - other.x, self.y - other.y, self.z - other.z)
    def __add__(self, other):
        return r3d_rvec3(self.x + other.x, self.y + other.y, self.z + other.z)
    def __mul__(self, s):
        return r3d_rvec3(self.x * s, self.y * s, self.z * s)

def wav(p1, d1, p2, d2):
    # Linear interpolation to find intersection point on plane [G]
    t = d1 / (d1 - d2)
    return p1 + (p2 - p1) * t

def r3d_split_coord(inpoly, ax, coord, outpolys):
    nverts = inpoly.nverts
    vertbuffer = inpoly.verts
    side = [0] * nverts
    sdists = [0.0] * nverts
    
    for v in range(nverts):
        sdists[v] = vertbuffer[v].pos.xyz[ax] - coord
        if sdists[v] > 0.0:
            side[v] = 1
            
    nright = sum(side)
    
    if nright == 0:
        outpolys[0] = inpoly
        outpolys[1].nverts = 0
        return
        
    if nright == nverts:
        outpolys[1] = inpoly
        outpolys[0].nverts = 0
        return
        
    # Bisect edges and create new vertices
    onv = nverts
    for vcur in range(nverts):
        if side[vcur] == 0:
            for np in range(3):
                vnext = vertbuffer[vcur].pnbrs[np]
                if side[vnext] == 1:
                    newpos = wav(vertbuffer[vcur].pos, -sdists[vnext], 
                                 vertbuffer[vnext].pos, sdists[vcur])
                    new_v = r3d_vertex(pos=newpos, pnbrs=[0,0,0])
                    vertbuffer.append(new_v)
                    side.append(1)
                    onv += 1
                    
    # Traverse faces to update neighbor links for new vertices
    for vstart in range(nverts, onv):
        vcur = vstart
        vnext = vertbuffer[vcur].pnbrs[0]
        while vcur < onv:
            for np in range(3):
                if vertbuffer[vnext].pnbrs[np] == vcur:
                    break
            vcur = vnext
            pnext = (np + 1) % 3
            vnext = vertbuffer[vcur].pnbrs[pnext]
        vertbuffer[vstart].pnbrs[2] = vcur
        vertbuffer[vcur].pnbrs[1] = vstart
        
    # Compress vertices
    outpolys[0].nverts = 0
    outpolys[1].nverts = 0
    for v in range(nverts):
        cside = side[v]
        outpolys[cside].verts[outpolys[cside].nverts] = vertbuffer[v]
        side[v] = outpolys[cside].nverts
        outpolys[cside].nverts += 1
        
    # Reindex neighbor pointers
    for poly in outpolys:
        for v in range(poly.nverts):
            for np in range(3):
                poly.verts[v].pnbrs[np] = side[poly.verts[v].pnbrs[np]]
```

### Parameters
- `R3D_MAX_VERTS`: Static size array limit for storing vertices of 3D polyhedra. Default value is 512. Configurable via CMake command line: `cmake -DR3D_MAX_VERTS=N ..` [S1, unofficial].
- `SHIFT_POLY`: Boolean CMake option (`-DSHIFT_POLY=True`). Shifts polytopes to the origin to improve accuracy of moment calculations for small polytopes far from the origin. Computationally costly for high-order moments [S1, unofficial].

### Edge Cases and Pitfalls
- If `nright == 0` (polytope entirely on negative side), copy `inpoly` to `outpolys[0]` and set `outpolys[1]->nverts = 0`. If `nright == *nverts` (entirely on positive side), copy `inpoly` to `outpolys[1]` and set `outpolys[0]->nverts = 0` [S1, unofficial].
- Precision issues may arise for small polytopes far from the origin; use `SHIFT_POLY` to mitigate [S1, unofficial].
- The vertex buffer size is limited by `R3D_MAX_VERTS`; ensure this is sufficient for the complexity of the polytopes being processed [S1, unofficial].

## Operating characteristics
- **Time Complexity**: The splitting process is recursive, with depth proportional to the logarithm of the grid resolution in the worst case. Each split involves linear operations in the number of vertices. Moment reduction is linear in the number of tetrahedra.
- **Memory Complexity**: Memory usage is proportional to the number of vertices in the polytopes being processed, limited by `R3D_MAX_VERTS`. The stack depth is proportional to the grid resolution.
- **Measured Performance**: Not given in the sources.
- **Scaling**: Scales with the number of voxels and the complexity of the polytopes.
- **Strengths**: Exact computation of moments, geometric robustness.
- **Limitations**: High computational cost for high-order moments, especially with `SHIFT_POLY`. Limited by `R3D_MAX_VERTS`.
- **When to use**: When exact moment computation is required for volume rendering, particularly for high-quality anti-aliasing.
- **When not to use**: When performance is critical and approximate methods are acceptable.

## Background
The R3D library was developed by Devon Powell at Stanford University in 2014-2015 [S1, unofficial]. It provides routines for fast, geometrically robust clipping operations and analytic volume/moment computations over convex polyhedra in 3D. It includes a wrapper function for physically conservative voxelization (volume sampling) of tetrahedra to a Cartesian grid [S1, unofficial].
