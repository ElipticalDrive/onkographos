# Multi-Plane Projection Voxelization and Aggregation

Also called: MPP Pre-processing

## Overview
Multi-Plane Projection Voxelization and Aggregation (MPP) converts multi-view RGB-D images into a volumetric representation suitable for neural rendering by projecting 2D pixels into 3D space and aggregating them onto a set of parallel planes [S1, unofficial]. Unlike standard voxelization methods that fill a 3D grid directly, MPP reduces memory overhead by storing data on $N$ discrete planes, making it efficient for large-scale scenes [S1, unofficial]. It is specifically designed to handle the sparsity of real-world scans by weighting contributions based on horizontal and vertical distances to the nearest depth plane [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
- A set of $M$ RGB-D images with known camera poses.
- For each view $i$:
  - Image dimensions: $H \times W$.
  - Intrinsic matrix $K_i$ ($3 \times 3$).
  - Extrinsic matrix $E_i$ ($4 \times 4$), mapping world coordinates to camera coordinates.
  - Depth map $D_i$ ($H \times W$), where values represent distance from the camera center.
  - Color image $C_i$ ($H \times W \times 3$).
- Hyperparameters:
  - `num_planes`: Number of parallel planes (typically 32) [S1, unofficial].
  - `a`: Horizontal distance weighting exponent (typically 1) [S1, unofficial].
  - `b`: Vertical distance weighting exponent (typically 1) [S1, unofficial].

**Outputs:**
- A pre-computed voxelization data structure (stored as `.npz`) containing:
  - `u`, `v`: Pixel coordinates of projected points.
  - `d`: Depth values.
  - `select_index`: Indices mapping points to specific planes/groups.
  - `group_belongs`: Group assignment for each point.
  - `index_in_each_group`: Local index within a group.
  - `distance`: Vertical distance to the minimum depth in the group.
  - `each_split_max_num`: Maximum number of points per split.
  - `delta`: Step size for volume rendering integration.
- Aggregation weights:
  - `weight_average`: Normalized weights for each point.
  - `distance_to_depth_min`: Vertical distance to the nearest depth plane.

### Data Structures
The method relies on two main data structures stored in NumPy `.npz` format:

1. **Voxelization Data**:
   - `u`: Array of shape $(P,)$, float32, horizontal pixel coordinates.
   - `v`: Array of shape $(P,)$, float32, vertical pixel coordinates.
   - `d`: Array of shape $(P,)$, float32, depth values.
   - `select_index`: Array of shape $(P,)$, uint32, index of the plane/group.
   - `group_belongs`: Array of shape $(P,)$, uint32, group identifier.
   - `index_in_each_group`: Array of shape $(P,)$, uint32, position within the group.
   - `distance`: Array of shape $(P,)$, float32, vertical distance to min depth.
   - `each_split_max_num`: Scalar or array, max points per split.
   - `delta`: Array of shape $(P,)$, float32, integration step size.

2. **Aggregation Data**:
   - `weight_average`: Array of shape $(P,)$, float32, normalized weights.
   - `distance_to_depth_min`: Array of shape $(P,)$, float32, vertical distance.

### Steps

1. **Preprocessing and Projection**:
   - For each view $i$, load the image, depth map, and camera parameters.
   - Skip views with invalid poses (e.g., $E_i[0,0] < -10^{10}$) to prevent numerical errors [S1, unofficial].
   - Optionally subsample pixels using a random mask with proportion `random_select_proportion` (e.g., 0.1) to reduce resource usage [S1, unofficial].
   - Construct pixel grid coordinates $(u, v)$ for all pixels in the image.
   - Compute the transformation matrix $T_i = K_i E_i^{-1}$ [S1, unofficial].
   - Project 3D points to image space:
     $$
     \begin{bmatrix} x' \\ y' \\ z' \end{bmatrix} = T_i \begin{bmatrix} X \\ Y \\ Z \\ 1 \end{bmatrix}
     $$
     where $(X, Y, Z)$ are world coordinates derived from depth $D_i$ and pixel $(u, v)$:
     $$
     X = K_i^{-1}[0,0] \cdot \frac{u - K_i[0,2]}{D_i[u,v]} + X_c
     $$
     $$
     Y = K_i^{-1}[1,1] \cdot \frac{v - K_i[1,2]}{D_i[u,v]} + Y_c
     $$
     $$
     Z = \frac{1}{D_i[u,v]} + Z_c
     $$
     (Note: The source code implies a direct projection using `transform_matrix.dot(point_clouds)` where `point_clouds` are homogeneous coordinates [S1, unofficial].)
   - Extract depth $z'$ from the projected points.

2. **Plane Assignment and Grouping**:
   - Define $N$ parallel planes (e.g., along the Z-axis or a specific view direction).
   - Assign each projected point to one of the $N$ planes based on its 3D coordinate.
   - Group points by plane. Within each plane, further group points by spatial proximity or grid cell (details on grid size are not explicitly given, but `index_in_each_group` implies local indexing [S1, unofficial]).

3. **Distance Calculation**:
   - For each group, find the minimum depth $d_{min}$:
     $$
     d_{min}^{(g)} = \min_{p \in g} d_p
     $$
   - Compute vertical distance for each point $p$ in group $g$:
     $$
     \text{distance}_p = d_p - d_{min}^{(g)}
     $$

4. **Weight Calculation**:
   - Compute horizontal weight $w_1$ based on distance from the center of the group or plane (not explicitly defined in source, but implied by `distance` variable usage [S1, unofficial]). The source uses `distance` for both horizontal and vertical, but distinguishes via `a` and `b`. Let $dist_h$ be horizontal distance and $dist_v$ be vertical distance.
     $$
     w_1 = (1 - dist_h)^a
     $$
     $$
     w_2 = \frac{1}{(1 + dist_v)^b}
     $$
   - Combine weights:
     $$
     w_{renew} = w_1 \times w_2
     $$
   - Normalize weights per group:
     $$
     w_{avg}^{(g)} = \frac{w_{renew}^{(g)}}{\sum_{p \in g} w_{renew}^{(p)}}
     $$

5. **Output Generation**:
   - Save `u`, `v`, `d`, `select_index`, `group_belongs`, `index_in_each_group`, `distance`, `each_split_max_num`, `delta` to the voxelization NPZ file.
   - Save `weight_average` and `distance_to_depth_min` to the aggregation NPZ file.

### Pseudocode

```python
import numpy as np

def mpp_voxelization_and_aggregation(images, depths, intrinsics, extrinsics, num_planes=32, a=1, b=1):
    """
    Perform Multi-Plane Projection Voxelization and Aggregation.
    
    Args:
        images: List of RGB images.
        depths: List of depth maps.
        intrinsics: List of 3x3 intrinsic matrices.
        extrinsics: List of 4x4 extrinsic matrices.
        num_planes: Number of parallel planes.
        a: Horizontal distance weighting exponent.
        b: Vertical distance weighting exponent.
        
    Returns:
        voxelization_data: Dict with keys u, v, d, select_index, etc.
        aggregation_data: Dict with keys weight_average, distance_to_depth_min.
    """
    all_u = []
    all_v = []
    all_d = []
    all_colors = []
    
    for i in range(len(images)):
        # Skip invalid poses
        if extrinsics[i][0, 0] < -1e10:
            continue
            
        H, W = images[i].shape[:2]
        K = intrinsics[i]
        E = extrinsics[i]
        
        # Create pixel grid
        u, v = np.meshgrid(np.arange(W), np.arange(H))
        u_flat = u.flatten()
        v_flat = v.flatten()
        
        # Get depth values
        depth_flat = depths[i].flatten()
        
        # Filter valid depth pixels
        valid_mask = depth_flat > 0
        u_flat = u_flat[valid_mask]
        v_flat = v_flat[valid_mask]
        depth_flat = depth_flat[valid_mask]
        
        # Compute 3D points in camera space
        # X = (u - cx) * Z / fx
        # Y = (v - cy) * Z / fy
        # Z = depth
        fx, fy = K[0, 0], K[1, 1]
        cx, cy = K[0, 2], K[1, 2]
        
        X_cam = (u_flat - cx) * depth_flat / fx
        Y_cam = (v_flat - cy) * depth_flat / fy
        Z_cam = depth_flat
        
        # Convert to homogeneous coordinates
        points_cam = np.vstack([X_cam, Y_cam, Z_cam, np.ones_like(Z_cam)])
        
        # Transform to world space
        # E is world-to-camera, so inverse is camera-to-world
        E_inv = np.linalg.inv(E)
        points_world = E_inv @ points_cam
        
        # Project to image space for verification or further processing
        # T = K @ E_inv
        T = K @ E_inv
        points_image = T @ points_world
        
        # Extract depth from projected points (z-coordinate)
        depth_proj = points_image[2, :]
        
        # Store data
        all_u.append(u_flat)
        all_v.append(v_flat)
        all_d.append(depth_proj)
        all_colors.append(images[i][valid_mask])
        
    # Concatenate all points
    u = np.concatenate(all_u)
    v = np.concatenate(all_v)
    d = np.concatenate(all_d)
    colors = np.concatenate(all_colors)
    
    # Assign to planes (simplified: based on Z coordinate)
    # Determine plane boundaries
    z_min, z_max = np.min(d), np.max(d)
    plane_step = (z_max - z_min) / num_planes
    plane_indices = np.floor((d - z_min) / plane_step).astype(np.uint32)
    plane_indices = np.clip(plane_indices, 0, num_planes - 1)
    
    # Group points by plane
    groups = {}
    for idx, (u_val, v_val, d_val, color, plane_idx) in enumerate(zip(u, v, d, colors, plane_indices)):
        if plane_idx not in groups:
            groups[plane_idx] = []
        groups[plane_idx].append((u_val, v_val, d_val, color, idx))
        
    # Calculate weights and distances
    weight_average = np.zeros(len(u))
    distance_to_depth_min = np.zeros(len(u))
    
    for plane_idx, points in groups.items():
        if not points:
            continue
            
        points = np.array(points)
        u_g = points[:, 0]
        v_g = points[:, 1]
        d_g = points[:, 2]
        colors_g = points[:, 3]
        indices_g = points[:, 4].astype(np.uint32)
        
        # Find min depth in group
        d_min = np.min(d_g)
        
        # Vertical distance
        dist_v = d_g - d_min
        distance_to_depth_min[indices_g] = dist_v
        
        # Horizontal distance (simplified: distance from center of bounding box of group)
        u_center = np.mean(u_g)
        v_center = np.mean(v_g)
        dist_h = np.sqrt((u_g - u_center)**2 + (v_g - v_center)**2)
        
        # Calculate weights
        # Note: Source uses (1-distance)**a, assuming distance is normalized or small
        # If dist_h is large, this can be negative. Source implies distance is normalized or small.
        # We assume dist_h is normalized to [0, 1] or small enough.
        # For implementation, we clamp or normalize.
        # Source code: weight_1 = (1-distance)**a
        # We need to normalize dist_h to [0, 1] for this to make sense.
        dist_h_norm = dist_h / (np.max(dist_h) + 1e-8)
        
        weight_1 = (1 - dist_h_norm)**a
        weight_2 = 1 / (1 + dist_v)**b
        
        weight_renew = weight_1 * weight_2
        
        # Normalize weights per group
        weight_sum = np.sum(weight_renew)
        if weight_sum > 0:
            weight_avg = weight_renew / weight_sum
        else:
            weight_avg = np.zeros_like(weight_renew)
            
        weight_average[indices_g] = weight_avg
        
    # Prepare output data
    voxelization_data = {
        'u': u,
        'v': v,
        'd': d,
        'select_index': plane_indices,
        'group_belongs': plane_indices,
        'index_in_each_group': np.arange(len(u), dtype=np.uint32),
        'distance': distance_to_depth_min,
        'each_split_max_num': np.array([len(points) for points in groups.values()], dtype=np.uint32),
        'delta': np.array([1.0] * len(u), dtype=np.float32) # Placeholder for delta
    }
    
    aggregation_data = {
        'weight_average': weight_average,
        'distance_to_depth_min': distance_to_depth_min
    }
    
    return voxelization_data, aggregation_data
```

### Edge Cases and Pitfalls
- **Invalid Camera Poses**: Check for invalid extrinsic matrices (e.g., values $< -10^{10}$) and skip them to avoid numerical errors [S1, unofficial].
- **Data Types**: Use `np.uint32` for indices to save memory, but be aware it consumes more resources than `uint16` if indices are small [S1, unofficial].
- **Depth Scaling**: Depth maps may require scaling (e.g., dividing by 4000 or 1000) depending on the sensor [S1, unofficial].
- **Weight Normalization**: Ensure weights are normalized per group to prevent bias towards larger groups [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
- **Time Complexity**: $O(M \cdot H \cdot W)$ for projection, where $M$ is the number of views, $H$ and $W$ are image dimensions. Aggregation is $O(P)$, where $P$ is the total number of projected points.
- **Memory Complexity**: $O(P)$ for storing voxelization data, where $P$ is the number of projected points. Using `uint32` for indices increases memory usage [S1, unofficial].

### Measured Performance
- Tested on Matterport3D and ScanNet datasets [S1, unofficial].
- Uses 32 planes for typical scenes [S1, unofficial].
- Random subsampling (10% of pixels) reduces memory usage significantly [S1, unofficial].

### Strengths and Limitations
- **Strengths**: Efficient for large-scale scenes, reduces memory overhead by using planes instead of a full 3D grid, handles sparsity well.
- **Limitations**: Requires accurate depth maps, sensitive to camera pose errors, may lose detail if subsampling is too aggressive.

### When to Use
- Use for large-scale indoor/outdoor scene reconstruction where memory is a constraint.
- Suitable for neural rendering pipelines that require pre-computed voxel data.

### When Not to Use
- Avoid for scenes with significant occlusions or dynamic objects.
- Not suitable for real-time applications without further optimization.

## Background

### Origin
Multi-Plane Projection Voxelization and Aggregation was introduced in the context of neural radiance fields (NeRF) for large-scale scene reconstruction [S1, unofficial]. It was developed to address the memory limitations of standard voxel-based methods when applied to high-resolution, large-scale datasets like Matterport3D and ScanNet [S1, unofficial].

### History and Development
The method builds on earlier work in multi-view stereo and neural rendering, adapting the concept of plane-sweeping and voxelization to a more efficient, plane-based representation [S1, unofficial]. It has been used in projects like PCMP-NeRF [S1, unofficial].

### Applications
- Large-scale scene reconstruction.
- Neural rendering of indoor and outdoor environments.
- Pre-processing for neural radiance fields.
