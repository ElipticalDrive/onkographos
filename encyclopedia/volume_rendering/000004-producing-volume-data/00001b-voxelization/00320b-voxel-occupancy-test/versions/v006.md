# Voxel Occupancy Test
Also called: Inclusion Test, Void Check, Voxel Occlusion Query

## Overview
The Voxel Occupancy Test determines whether a given query point lies within an occupied voxel of a pre-computed voxel grid. It solves the problem of spatial containment queries for discrete volumetric data, returning a binary result (occupied or empty) for each input coordinate. Unlike [Analytic Voxelization](10493-analytic-voxelization.md) which computes occupancy on-the-fly via signed distance functions, or [Point Cloud Voxelization](1000-point-cloud-voxelization.md) which generates the grid, this method performs a direct lookup against an existing discrete structure. It differs from [Voxel Visibility Culling](8235-voxel-visibility-culling.md) by testing for general volume inclusion rather than surface-adjacency based on scalar thresholds.

## How it works
The method maps continuous world coordinates to discrete grid indices and performs a bounds check followed by a texture or array lookup. The implementation varies slightly depending on whether the voxel grid is stored as a dense array or a texture buffer, but the logical steps remain consistent.

**Inputs and Outputs:**
*   **Input:** A set of query points $P = \{p_1, p_2, \dots, p_n\}$, where each $p_i = (x, y, z)$ is a 3D vector in world space.
*   **Input:** A voxel grid structure $V$ containing occupancy data, defined by a bounding box, resolution $(N_x, N_y, N_z)$, and voxel size $s$.
*   **Output:** A boolean array $B = \{b_1, b_2, \dots, b_n\}$, where $b_i = \text{true}$ if $p_i$ is inside an occupied voxel, and $\text{false}$ otherwise.

**Data Structures:**
The voxel grid $V$ is typically represented as a 3D array or texture.
*   **Dense Array:** A 3D array `voxel_world` of size $N_x \times N_y \times N_z$. Each element stores occupancy status. In some implementations (e.g., GPU textures), the value may be packed into a color channel where the red channel `r` encodes occupancy intensity [S2, unofficial].
*   **Grid Parameters:**
    *   `voxel_size`: The physical size of one voxel unit.
    *   `texture_size` or `grid_dims`: The integer dimensions $(N_x, N_y, N_z)$ of the grid.
    *   `origin`: The world coordinate of the grid's minimum corner (often $(0,0,0)$ or the bounding box min).

**Numbered Steps:**
1.  **Coordinate Transformation:** Convert the world coordinate $p = (x, y, z)$ to grid indices $(i, j, k)$.
    $$ i = \lfloor \frac{x - x_{min}}{s} \rfloor $$
    $$ j = \lfloor \frac{y - y_{min}}{s} \rfloor $$
    $$ k = \lfloor \frac{z - z_{min}}{s} \rfloor $$
    Where $(x_{min}, y_{min}, z_{min})$ is the grid origin and $s$ is the voxel size. If the grid origin is $(0,0,0)$, this simplifies to $i = \lfloor x/s \rfloor$.

2.  **Boundary Check:** Verify if the computed indices $(i, j, k)$ lie within the valid range of the grid.
    $$ 0 \le i < N_x $$
    $$ 0 \le j < N_y $$
    $$ 0 \le k < N_z $$
    If any index is outside these bounds, the point is outside the voxel grid. Return `false` (or `0.0` in float-based implementations) [S2, unofficial].

3.  **Occupancy Lookup:** Access the voxel data at index $(i, j, k)$.
    *   If stored as a boolean array: Return `voxel_world[i][j][k]`.
    *   If stored as a texture (e.g., RGBA): Sample the texture at integer coordinates. The occupancy is often derived from the red channel `r`. The value is normalized to $[0, 1]$ and clamped.
        $$ \text{occupancy} = \min(\frac{\text{voxel.r}}{255.0}, 1.0) $$
        Return `true` if $\text{occupancy} > 0$, else `false` [S2, unofficial]. Note: Some implementations use `vec3<i32>(pos.zyx)` for texture sampling, implying a specific memory layout (e.g., Z-major or YXZ packing) [S2, unofficial].

4.  **Result Aggregation:** For a batch of $n$ points, repeat steps 1-3 for each point and store the results in the output boolean array.

**Pseudocode:**
```python
def voxel_occupancy_test(queries, voxel_grid):
    """
    queries: list of (x, y, z) tuples
    voxel_grid: object containing:
        - origin: (x_min, y_min, z_min)
        - voxel_size: float s
        - dimensions: (Nx, Ny, Nz)
        - data: 3D array or texture lookup function
    """
    x_min, y_min, z_min = voxel_grid.origin
    s = voxel_grid.voxel_size
    Nx, Ny, Nz = voxel_grid.dimensions
    results = []

    for p in queries:
        x, y, z = p
        
        # Step 1: Coordinate Transformation
        i = int((x - x_min) / s)
        j = int((y - y_min) / s)
        k = int((z - z_min) / s)
        
        # Step 2: Boundary Check
        if i < 0 or i >= Nx or j < 0 or j >= Ny or k < 0 or k >= Nz:
            results.append(False)
            continue
            
        # Step 3: Occupancy Lookup
        # Assuming dense array access for clarity; texture logic varies by API
        voxel_value = voxel_grid.data[i][j][k]
        
        # Handle packed integer/float formats if necessary
        # Example: if voxel_value is an integer 0-255
        if isinstance(voxel_value, int):
            occupancy = min(voxel_value / 255.0, 1.0)
        else:
            occupancy = voxel_value
            
        results.append(occupancy > 0.0)
        
    return results
```

**Parameters with Typical Values:**
*   `voxel_size`: Depends on the scene scale. Common values range from $0.01$ to $1.0$ units.
*   `grid_dimensions`: Determined by the bounding box size divided by `voxel_size`.

**Edge Cases and Pitfalls:**
*   **Precision Errors:** Floating-point division and floor operations can cause off-by-one errors at boundaries. Using epsilon comparisons or consistent floor logic is critical [G].
*   **Coordinate System Mismatch:** Texture sampling often expects specific index orders (e.g., ZYX vs XYZ). Mismatching the index order leads to incorrect lookups [S2, unofficial].
*   **Out-of-Bounds Access:** Failing to check bounds before accessing the array/texture causes crashes or undefined behavior.

## Subtopics

### [Point-in-Box Inclusion Test](1400-point-in-box-inclusion-test.md)
Partitions points by orthogonal bounding boxes. It is the core primitive for voxel occupancy, returning counts of points inside a box. It differs by performing direct geometric containment checks, often optimized for sorting.

### [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md)
Generates a 3D binary kernel for spherical occupancy regions. It differs by defining a discrete spherical region rather than a single voxel containment.

### [Voxel Filled Check](1705-voxel-filled-check.md)
Determines if a specific voxel/chunk is occupied. It acts as a binary test for pre-computed masks, similar to the core test but often applied to larger chunks.

### [Sparse AABB Collision Test](3047-sparse-aabb-collision-test.md)
Tests if an AABB intersects any occupied voxels in a sparse volume. It differs by evaluating a continuous volume (AABB) rather than discrete points.

### [Solidity Check](4229-solidity-check.md)
Determines if a voxel is solid geometry or void. It differs by explicitly handling boundary conditions and chunk-based data structures to prevent artifacts.

### [Sphere-Clamped Voxel Neighbor Search](5131-sphere-clamped-voxel-neighbor-search.md)
Finds the closest occupied voxel within a spherical radius. It differs by returning the nearest neighbor rather than a binary result.

### [Voxel Collision Test](5774-voxel-collision-test.md)
Tests a vertical column of voxels for solid geometry between two Y heights. It differs by iterating along an axis to detect occupancy within a slab.

### [Mask Cache Lookup](6434-mask-cache-lookup.md)
Tests points against a 3D boolean occupancy grid. It differs by explicitly handling coordinate transformation and bounds checking in a single pass, often optimized for caching.

### [Voxel Visibility Culling](8235-voxel-visibility-culling.md)
Discards voxels not contributing to the final image. It differs by filtering for surface-adjacent voxels based on scalar thresholds, not just inclusion.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query point for lookup, assuming direct array access. For $n$ points, the total time is $O(n)$.
*   **Memory Complexity:** $O(N_x N_y N_z)$ for the voxel grid storage. The query processing uses $O(n)$ for the output array.
*   **Measured Performance:** Performance is dominated by memory access patterns. On CPU, cache locality of the 3D array affects speed. On GPU, texture sampling is highly optimized but requires correct coordinate transformation and bounds checking [S2, unofficial].
*   **Strengths:** Fast, deterministic, and simple to implement. Ideal for point-in-volume queries.
*   **Limitations:** Requires pre-computed voxel grid. Does not provide information about the *type* of geometry (e.g., material) unless the voxel data stores more than binary occupancy.
*   **When to Use:** When you need to quickly check if points lie inside a known volumetric shape.
*   **When Not to Use:** When the geometry is dynamic and voxelization is too expensive, or when you need continuous collision detection rather than discrete checks.

## Background
The Voxel Occupancy Test is a fundamental operation in voxel-based rendering and simulation. It is closely associated with the Open3D library, which provides the `check_if_included` method for `VoxelGrid` objects [S1]. The method is also used in voxel engines for collision detection and spatial queries, as seen in implementations like the Bevy Voxel Engine [S2, unofficial]. The technique relies on the discretization of space, a concept central to [Voxelization](12-voxelization.md).
