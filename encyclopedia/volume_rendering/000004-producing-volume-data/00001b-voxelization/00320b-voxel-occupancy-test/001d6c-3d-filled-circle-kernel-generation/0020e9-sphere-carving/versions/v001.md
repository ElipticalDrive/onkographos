# Sphere Carving

Also called: Carve Sphere, Voxel Sphere Removal

## Overview
Sphere Carving removes solid voxels within a spherical radius from a center point in a voxel chunk, primarily used for destructible terrain scenarios [S1, unofficial]. It differs from its parent [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md) by operating directly on the chunk data to modify state (removing voxels) rather than generating a static binary kernel, and from its sibling [3D Binary Sphere Kernel Generation](4654-3d-binary-sphere-kernel-generation.md) by returning a count of removed elements rather than a mask [S1, unofficial].

## How it works
**Inputs:**
- `chunk`: The voxel chunk data structure to modify.
- `cx, cy, cz`: The integer or floating-point center coordinates of the sphere.
- `radius`: The radius of the sphere to carve.

**Outputs:**
- The modified `chunk` with voxels set to 0 (air) inside the sphere.
- An integer count of the number of solid voxels removed.

**Data Structures:**
The `chunk` is assumed to be a 3D array or linear buffer indexed by `(x, y, z)`. The specific internal layout (e.g., row-major vs column-major) is not specified in the sources, but access is via `chunk.get(x, y, z)` and `chunk.set(x, y, z, value)` [S1, unofficial]. A value of `0` represents air/empty space; any non-zero value represents solid material [S1, unofficial].

**Algorithm Steps:**
1. Calculate the squared radius: $r_2 = \text{radius} \times \text{radius}$.
2. Determine the bounding box of the sphere within the chunk boundaries for each axis $v \in \{x, y, z\}$:
   - Lower bound: $\text{lo}(v) = \max(0, \lfloor v - \text{radius} \rfloor)$
   - Upper bound: $\text{hi}(v) = \min(\text{chunk.size} - 1, \lceil v + \text{radius} \rceil)$
3. Initialize a counter `removed_count` to 0.
4. Iterate through the bounding box:
   - For $z$ from $\text{lo}(cz)$ to $\text{hi}(cz)$:
     - For $y$ from $\text{lo}(cy)$ to $\text{hi}(cy)$:
       - For $x$ from $\text{lo}(cx)$ to $\text{hi}(cx)$:
         - Calculate the squared distance from the center: $d_2 = (x - cx)^2 + (y - cy)^2 + (z - cz)^2$.
         - If $d_2 > r_2$, continue to the next voxel.
         - If `chunk.get(x, y, z)` is not 0:
           - Increment `removed_count`.
           - Set `chunk.set(x, y, z, 0)`.
5. Return `removed_count`.

**Pseudocode:**
```python
def sphere_carving(chunk, cx, cy, cz, radius):
    r2 = radius * radius
    removed_count = 0
    
    # Calculate bounds for each axis
    lo_x = max(0, floor(cx - radius))
    hi_x = min(chunk.size_x - 1, ceil(cx + radius))
    
    lo_y = max(0, floor(cy - radius))
    hi_y = min(chunk.size_y - 1, ceil(cy + radius))
    
    lo_z = max(0, floor(cz - radius))
    hi_z = min(chunk.size_z - 1, ceil(cz + radius))
    
    for z in range(lo_z, hi_z + 1):
        dz = z - cz
        dz2 = dz * dz
        for y in range(lo_y, hi_y + 1):
            dy = y - cy
            dy2 = dy * dy
            for x in range(lo_x, hi_x + 1):
                dx = x - cx
                d2 = dx*dx + dy2 + dz2
                
                if d2 > r2:
                    continue
                
                if chunk.get(x, y, z) != 0:
                    removed_count += 1
                    chunk.set(x, y, z, 0)
                    
    return removed_count
```

**Parameters:**
- `radius`: The radius of the carving sphere. Typical values depend on the desired granularity of destruction [S1, unofficial].
- `cx, cy, cz`: Center coordinates. If floating-point, they are used in distance calculations but voxel indices are integers [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Clamping:** The bounds must be clamped to the chunk dimensions to prevent out-of-bounds access [S1, unofficial].
- **Precision:** Using squared distances avoids square roots, improving performance and avoiding floating-point precision issues near the boundary [S1, unofficial].
- **Degenerate Input:** A radius of 0 results in no voxels being removed (except potentially the center if strictly less than, but the condition is $d_2 > r_2$, so if $r_2=0$, only $d_2=0$ passes, but the check is `if d2 > r2 continue`, so $d_2=0$ is not $>0$, so it proceeds. If center is solid, it is removed. If radius is 0, only the exact center voxel is checked) [S1, unofficial].

## Subtopics

### [Voxel Deformation with Spherical Falloff](4413-voxel-deformation-with-spherical-falloff.md)
Voxel Deformation with Spherical Falloff modifies scalar voxel values within a spherical region around a 3D hit point to add or remove terrain mass, enabling real-time digging and building operations. It sets itself apart from its parent [Sphere Carving](2377-sphere-carving.md) by using a continuous soft falloff function to create smooth edges rather than binary inclusion/exclusion, and by supporting additive (build) as well as subtractive (dig) operations.

### Bounding Ellipsoids from SDFs
Generating a bounding volume as a union of ellipsoids by replacing the convex hull generation step with minimum-volume enclosing ellipsoid generation on the point set $P$ [S2]. The signed distance function for an ellipsoid $E$ is defined as $d(\mathbf{p}, \mathcal{E}) = a (\|\mathbf{A}(\mathbf{p} - \mathbf{c})\| - 1)$, where $\mathbf{A} = \mathbf{D}(1/a, 1/b, 1/c) \mathbf{R}^t$ [S2]. This function is 1-Lipschitz (conservative) [S2]. Evaluation requires approximately 4 scalar products and one square root [S2]. Ellipsoids are more compact in memory and computationally more efficient than convex polyhedra (which require $n$ scalar products for $n$ faces), though potentially more conservative depending on axis lengths [S2].

## Operating characteristics
- **Time Complexity:** $O(r^3)$ where $r$ is the radius, as it iterates over the bounding box of the sphere.
- **Memory Complexity:** $O(1)$ auxiliary space, modifying the chunk in place.
- **Performance:** The use of squared distance comparisons avoids expensive square root operations [S1, unofficial].
- **Strengths:** Simple to implement, efficient for small to medium radii, suitable for real-time destructible terrain [S1, unofficial].
- **Limitations:** Binary removal (hard edges) unless combined with falloff techniques [S1, unofficial]. Performance degrades with very large radii due to the cubic growth of the bounding box volume.

## Background
Sphere Carving is a fundamental operation in voxel-based game engines and simulations, particularly for destructible environments. It is often used in conjunction with voxelization and geometry processing pipelines [S1, unofficial]. The technique is closely related to sphere tracing in ray marching, where spheres are used to approximate shapes, but here it is applied to discrete voxel data [S2].
