# 3D Gaussian Kernel Generation
Also called: 3D Gaussian Smoothing Kernel, Zero-Center Gaussian Kernel

## Overview
Generates a 3D Gaussian kernel for smoothing operations, with the center element set to zero [S1, unofficial]. It differs from its sibling [3D Filled Circle Kernel Generation](1520-3d-filled-circle-kernel-generation.md) by using a continuous probability density function for weighted smoothing rather than a binary occupancy mask, and from [Sphere Carving](2377-sphere-carving.md) by providing smooth falloff instead of hard geometric boundaries.

## How it works
**Inputs:**
- `size`: Integer kernel dimension (assumed cubic). Default: 3 [S1, unofficial].
- `sigma`: Float standard deviation. Default: 1.0 [S1, unofficial].

**Outputs:**
- A 3D tensor of shape `(size, size, size)` containing normalized Gaussian weights with the center element explicitly set to 0.

**Data Structures:**
- A 3D array of floating-point values. No bit-packing is specified; standard float32 or float64 is implied by the use of `exp` and division [S1, unofficial].

**Steps:**
1. Define the coordinate range: Create a linear space from $-\lfloor \text{size}/2 \rfloor$ to $\lfloor \text{size}/2 \rfloor$. Let $N = \lfloor \text{size}/2 \rfloor$. The indices $i, j, k$ range from $-N$ to $N$.
2. Generate a 3D meshgrid of coordinates $(x, y, z)$ covering all integer positions in the kernel volume.
3. Compute the radial distance $d$ from the center $(0,0,0)$ for each coordinate:
   $$ d = \sqrt{x^2 + y^2 + z^2} $$
4. Compute the unnormalized Gaussian value for each element:
   $$ w = \exp\left(-\frac{d^2}{2\sigma^2}\right) $$
5. Set the center element (where $x=y=z=0$) to 0. This modifies the weight at the origin to $w_{0,0,0} = 0$, regardless of the calculated Gaussian value [S1, unofficial].
6. Normalize the kernel by dividing all elements by the sum of all elements in the kernel:
   $$ w_{final} = \frac{w}{\sum_{x,y,z} w} $$

**Pseudocode:**
```python
import math

def generate_3d_gaussian_kernel(size: int = 3, sigma: float = 1.0) -> list:
    """
    Generates a 3D Gaussian kernel with the center element set to zero.
    
    Args:
        size: Kernel dimension (cubic).
        sigma: Standard deviation.
        
    Returns:
        A 3D list of normalized weights.
    """
    half_size = size // 2
    kernel = []
    
    # Step 1 & 2: Iterate through coordinates from -half_size to half_size
    for x in range(-half_size, half_size + 1):
        row = []
        for y in range(-half_size, half_size + 1):
            col = []
            for z in range(-half_size, half_size + 1):
                # Step 3: Compute radial distance
                d_sq = x*x + y*y + z*z
                d = math.sqrt(d_sq)
                
                # Step 4: Compute Gaussian value
                # Avoid division by zero if sigma is 0, though default is 1.0
                if sigma == 0:
                    val = 0.0
                else:
                    val = math.exp(-(d_sq) / (2 * sigma * sigma))
                
                # Step 5: Set center element to 0
                if x == 0 and y == 0 and z == 0:
                    val = 0.0
                
                col.append(val)
            row.append(col)
        kernel.append(row)
    
    # Step 6: Normalize by sum of all elements
    total_sum = 0.0
    for x in range(size):
        for y in range(size):
            for z in range(size):
                total_sum += kernel[x][y][z]
    
    if total_sum == 0:
        # Edge case: if all values are 0 (e.g., sigma=0 and size=1), return zeros
        return kernel
    
    for x in range(size):
        for y in range(size):
            for z in range(size):
                kernel[x][y][z] /= total_sum
                
    return kernel
```

**Parameters:**
- `size`: Default 3 [S1, unofficial].
- `sigma`: Default 1.0 [S1, unofficial].

**Edge Cases:**
- If `sigma` is 0, the exponential term becomes 0 for all $d > 0$ and 1 for $d=0$. However, the center is forced to 0, resulting in a kernel of all zeros. Normalization by zero sum requires a guard [G].
- Boundary conditions: The kernel is centered at $(0,0,0)$ relative to the array indices. For odd sizes, the center is exact. For even sizes, the center is ambiguous; the code uses integer division `size // 2` to define the range, effectively placing the "center" logic at index 0 relative to the symmetric range $[-N, N]$.

## Subtopics

### [Elliptical Gaussian Light Source Generation](5806-elliptical-gaussian-light-source-generation.md)
Generates spatially distributed light sources using either Poisson disk or uniform sampling, then constructs a luminance field by evaluating scaled multivariate Gaussian probability density functions (PDFs) at query points. It differs from its parent [3D Gaussian Kernel Generation](2297-3d-gaussian-kernel-generation.md) by treating the Gaussian as an emission model for light sources rather than a smoothing kernel, and by supporting spatially varying elliptical covariances via eigen-decomposition.

### [Separable Component-Wise Convolution](7446-separable-component-wise-convolution.md)
Separable component-wise convolution is a computationally efficient method for applying 3D Gaussian smoothing to volumes represented as decomposed low-rank tensors. It solves the problem of high computational cost and memory usage associated with naively convolving a 3D kernel on a reconstructed tensor volume. Unlike traditional separated kernel convolution which only exploits kernel separability, this method distributes the convolution across individual tensor components by leveraging the separability of the input signal itself, thereby preserving the space compression advantage of the low-rank representation.

## Operating characteristics
- **Time Complexity:** $O(\text{size}^3)$ to generate the kernel. Convolution using this kernel is $O(\text{size}^3 \cdot N)$ for $N$ voxels.
- **Memory Complexity:** $O(\text{size}^3)$ to store the kernel.
- **Strengths:** Provides smooth, isotropic smoothing. The zero-center modification prevents the kernel from reinforcing the center value directly, which can be useful in specific gradient-based or difference-of-Gaussians contexts.
- **Limitations:** The explicit zeroing of the center element breaks the standard property of a Gaussian kernel where the center is the maximum weight. This may lead to unexpected artifacts if the user assumes a standard Gaussian blur. Not given in the sources: performance on GPU vs CPU.
- **When to use:** When smoothing is required but the direct contribution of the center voxel must be nullified.
- **When not to use:** For standard image or volume blurring where preserving the center intensity is desired.
