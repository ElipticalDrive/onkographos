# Blob Field Generation

Also called: Inverse Distance Weighting for Isosurfaces, Inverse Square Blob Field, Metaball Scalar Field Construction, Procedural Blob Field

## Overview
Blob Field Generation is a procedural method for constructing a 3D scalar field by summing inverse-squared Euclidean distance contributions from a set of source points (metaballs) [S1, S2, unofficial]. It solves the problem of defining smooth, organic implicit surfaces for isosurface extraction algorithms like Marching Cubes [S1, S2, unofficial].

## How it works
**Inputs and outputs:**
*   Inputs: A set of $N$ source points $\mathbf{P}_i = (x_i, y_i, z_i)$, an evaluation point $\mathbf{V} = (x, y, z)$, a time parameter $t$, and optional floor plane coordinates [S1, S2, unofficial].
*   Outputs: A scalar field value $f(\mathbf{V})$ representing the density at $\mathbf{V}$ [S2, unofficial].

**Data structures:**
*   `SourcePoint`: A tuple or structure containing three floating-point coordinates $(x, y, z)$ [S2, unofficial].
*   `Weights`: An array of floating-point values corresponding to each source point [S2, unofficial].

**Numbered steps:**
1. Normalize voxel coordinates to the range $[0, 1]$ [S1, unofficial].
2. For each blob $i$, calculate its position $(x_i, y_i, z_i)$ using sinusoidal functions of time $t$ and index $i$ [S1, unofficial].
3. Compute the squared distance $d_i^2 = (x - x_i)^2 + (y - y_i)^2 + (z - z_i)^2$ [S1, unofficial].
4. Compute the blob contribution $v_i = \text{strength} / (0.000001 + d_i^2) - 12.0$ [S1, unofficial].
5. If $v_i > 0$, add $v_i$ to the total field accumulator [S1, unofficial].
6. Compute the floor distance $f_y = y - y_{floor}$ [S1, unofficial].
7. Compute the floor contribution $v_{floor} = 2.0 / (0.0001 + f_y^2) - 12.0$ [S1, unofficial].
8. If $v_{floor} > 0$, add $v_{floor}$ to the total field accumulator [S1, unofficial].
9. Return the accumulator value [S1, unofficial].

**Formulas:**
The core field function sums conditional inverse-squared distance contributions from source points and an optional floor plane [S1, S2, unofficial]:
$$ f(\mathbf{V}) = \sum_{i=0}^{N-1} \max(0, v_i) + \max(0, v_{floor}) $$
Where the blob contribution is:
$$ v_i = \frac{w_i}{\epsilon_{blob} + d_i^2} - C $$
And the floor contribution is:
$$ v_{floor} = \frac{w_{floor}}{\epsilon_{floor} + f_y^2} - C $$
Here, $d_i^2$ is the squared Euclidean distance between $\mathbf{V}$ and $\mathbf{P}_i$ [S2, unofficial], $f_y$ is the vertical distance to the floor plane, $w_i$ and $w_{floor}$ are weights, $\epsilon$ values are small constants to prevent division by zero, and $C$ is a constant offset [S1, unofficial]. Alternative distance metrics replace the Euclidean calculation to change isosurface shape [S2, unofficial].

**Parameters:**
*   $w_i$ (strength): Calculated as $1.2 / ((\sqrt{N} - 1) / 4 + 1)$ in one implementation [S1, unofficial]. Alternative example weights are $0.5, 1.0, 1.5$ [S2, unofficial].
*   $w_{floor}$: Fixed at $2.0$ [S1, unofficial].
*   $\epsilon_{blob}$: $0.000001$ [S1, unofficial].
*   $\epsilon_{floor}$: $0.0001$ [S1, unofficial].
*   $C$: $12.0$ [S1, unofficial].
*   $N$: Number of blobs; typical examples use $N=3$ [S2, unofficial].

**Edge cases and pitfalls:**
*   Division by zero occurs if the evaluation point coincides exactly with a source point, causing the distance term to be zero and the value to approach infinity [S2, unofficial]. The epsilon constants in the denominators prevent this singularity [S1, unofficial].
*   Standard Euclidean distance produces spherical blobs; using Taxicab (Manhattan) or Max-metric distances instead produces cubic ("Minecraft-like") isosurfaces [S2, unofficial].
*   Floating-point precision limits may affect the smoothness of isosurface extraction near singularities [G].

**Pseudocode:**
```python
def evaluate_blob_field(x, y, z, source_points, weights, floor_y, num_blobs, time):
    """
    Evaluates the scalar field value at point (x, y, z) based on inverse squared distance to source points.
    Matches the procedural steps and formulas from the reference implementation.
    """
    accumulator = 0.0
    epsilon_blob = 1e-6
    epsilon_floor = 1e-4
    offset = 12.0
    
    # Step 1: Normalize coordinates to [0, 1]
    nx, ny, nz = x, y, z  # Assuming input is already normalized or grid coordinates map directly
    
    # Step 2: Calculate blob positions using sinusoidal functions of time and index
    # (Exact sinusoidal formulas are implementation-specific; positions are passed as source_points)
    
    # Steps 3-5: Sum blob contributions
    for i in range(len(source_points)):
        px, py, pz = source_points[i]
        w = weights[i]
        
        dx = nx - px
        dy = ny - py
        dz = nz - pz
        dist_sq = dx*dx + dy*dy + dz*dz
        
        v_i = w / (epsilon_blob + dist_sq) - offset
        if v_i > 0:
            accumulator += v_i
            
    # Steps 6-8: Floor effect
    fy = ny - floor_y
    floor_val = 2.0 / (epsilon_floor + fy*fy) - offset
    if floor_val > 0:
        accumulator += floor_val
        
    return accumulator
```
