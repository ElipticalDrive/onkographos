# Implicit Field Composition

Also called: Density Function Composition, Density Function for Scene Generation, Implicit Field Combination

## Overview
Implicit Field Composition constructs a single signed distance field (SDF) by combining multiple geometric primitives and procedural noise functions using Boolean set operations [S1, S2, unofficial]. It solves the problem of generating complex, hybrid scenes (e.g., terrain intersecting with rigid structures) from analytic components without requiring explicit mesh generation or voxelization during the definition phase [S1, S2, unofficial]. It differs from [Procedural and implicit volumes](13-procedural-and-implicit-volumes.md) by explicitly targeting signed distance metrics for dual contouring or ray marching, rather than scalar density values for volume rendering, and from [Implicit Surface Primitives](1800-implicit-surface-primitives.md) by supporting non-geometric noise-based fields in the composition [S1, S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A 3D position vector $\mathbf{p}$ (world space).
*   **Output**: A scalar signed distance value $d(\mathbf{p})$.

**Data Structures**
No persistent data structures are required for the evaluation itself. The method is stateless and procedural [S1, S2, unofficial].

**Parameters**
*   **Fractal Noise**:
    *   `octaves`: 4 [S1, S2, unofficial]
    *   `frequency`: 0.5343 [S1, S2, unofficial]
    *   `lacunarity`: 2.2324 [S1, S2, unofficial]
    *   `persistence`: 0.68324 [S1, S2, unofficial]
    *   `scale`: $1/128$ [S1, S2, unofficial]
*   **Cuboid**:
    *   `origin`: $(-4, 10, -4)$ [S1, S2, unofficial]
    *   `halfDimensions`: $(12, 12, 12)$ [S1, S2, unofficial]
*   **Sphere**:
    *   `origin`: $(15, 2.5, 1)$ [S1, S2, unofficial]
    *   `radius`: $16$ [S1, S2, unofficial]

**Steps**
1.  **Evaluate Terrain Noise**: Compute a fractal noise value based on the horizontal components of $\mathbf{p}$.
2.  **Compute Terrain SDF**: Subtract the scaled noise from the vertical component $y$ to create a height-field-like distance field.
3.  **Compute Primitive SDFs**: Evaluate the signed distance for the cuboid and the sphere at $\mathbf{p}$.
4.  **Combine Fields**: Apply Boolean operations to merge the fields into a single SDF.

**Formulas**
*   **Fractal Noise**:
    $$ N(\mathbf{p}) = 0.5 + 0.5 \sum_{i=0}^{octaves-1} \text{Perlin}(\mathbf{p}_{scaled} \cdot f^i) \cdot a^i $$
    Where $\mathbf{p}_{scaled} = \mathbf{p}_{xy} \cdot \text{scale}$, $f$ is frequency, and $a$ is persistence [S1, S2, unofficial].
*   **Terrain SDF**:
    $$ d_{terrain}(\mathbf{p}) = p_y - 20 \cdot N(\mathbf{p}) $$
    [S1, S2, unofficial]
*   **Cuboid SDF**:
    $$ \mathbf{l} = \mathbf{p} - \mathbf{o}_{cube} $$
    $$ \mathbf{d} = (|\mathbf{l}| - \mathbf{h}) $$
    $$ m = \max(d_x, d_y, d_z) $$
    $$ d_{cube}(\mathbf{p}) = \min(m, \|\mathbf{d}_{pos}\|) $$
    Where $\mathbf{d}_{pos}$ is $\mathbf{d}$ with negative components clamped to 0 [S1, S2, unofficial].
*   **Sphere SDF**:
    $$ d_{sphere}(\mathbf{p}) = \|\mathbf{p} - \mathbf{o}_{sphere}\| - r $$
    [S1, S2, unofficial]
*   **Composition**:
    $$ d_{final}(\mathbf{p}) = \max(-d_{cube}(\mathbf{p}), \min(d_{sphere}(\mathbf{p}), d_{terrain}(\mathbf{p}))) $$
    [S1, S2, unofficial]

```python
def fractal_noise(position_xy, octaves=4, frequency=0.5343, lacunarity=2.2324, persistence=0.68324, scale=1.0/128.0):
    p = position_xy * scale
    noise_val = 0.0
    amplitude = 1.0
    p *= frequency
    
    for _ in range(octaves):
        noise_val += perlin_2d(p.x, p.y) * amplitude
        p *= lacunarity
        amplitude *= persistence
        
    return 0.5 + 0.5 * noise_val

def cuboid_sdf(position, origin, half_dimensions):
    local_pos = position - origin
    abs_local = [abs(x) for x in local_pos]
    d = [abs_local[i] - half_dimensions[i] for i in range(3)]
    
    m = max(d)
    
    # d_pos is d with negative values clamped to 0
    d_pos = [max(0, x) for x in d]
    dist_pos = math.sqrt(sum(x*x for x in d_pos))
    
    return min(m, dist_pos)

def sphere_sdf(position, origin, radius):
    return math.sqrt(sum((position[i] - origin[i])**2 for i in range(3))) - radius

def terrain_sdf(position, octaves=4, frequency=0.5343, lacunarity=2.2324, persistence=0.68324):
    noise = fractal_noise((position.x, position.z), octaves, frequency, lacunarity, persistence)
    return position.y - 20.0 * noise

def implicit_field_composition(position):
    # Parameters from sources [S1, S2, unofficial]
    cube_origin = (-4.0, 10.0, -4.0)
    cube_half_dims = (12.0, 12.0, 12.0)
    
    sphere_origin = (15.0, 2.5, 1.0)
    sphere_radius = 16.0
    
    d_cube = cuboid_sdf(position, cube_origin, cube_half_dims)
    d_sphere = sphere_sdf(position, sphere_origin, sphere_radius)
    d_terrain = terrain_sdf(position)
    
    # Composition: max(-cube, min(sphere, terrain))
    # Note: -cube is used to invert the cuboid for union/intersection logic 
    # consistent with the source code's max(-cuboid, ...) pattern.
    return max(-d_cube, min(d_sphere, d_terrain))
```

**Edge Cases and Pitfalls**
*   **Precision**: The cuboid SDF calculation involves `max` and `min` of potentially small differences. Standard float precision is sufficient for the given parameter scales [S1, S2, unofficial].
*   **Boundary Continuity**: The composition uses `max` and `min` (Boolean union/intersection). The resulting field is $C^0$ continuous but not $C^1$ at the boundaries where primitives intersect, which is standard for SDF composition [S1, S2, unofficial].
*   **Noise Domain**: The noise is evaluated only on $x$ and $z$, treating $y$ as the height axis. Using 3D noise would require a different function signature [S1, S2, unofficial].

## Subtopics

### Fractal Noise Generation
Generates the procedural terrain component. It differs from simple noise by summing octaves with lacunarity and persistence. Choose when organic, height-based geometry is needed. See [Procedural Noise Functions](1799-procedural-noise-functions.md).

### Primitive SDFs
Provides the rigid geometric components (cube, sphere). They differ from noise by being exact analytic distances. Choose when precise, hard-edged geometry is required. See [Implicit Surface Primitives](1800-implicit-surface-primitives.md).

### Boolean SDF Operations
The method of combining fields using `max` (union) and `min` (intersection). It differs from mesh boolean operations by being differentiable almost everywhere. Choose when creating hybrid scenes from analytic shapes. See [Signed Distance Function (SDF) Generation and Processing](5342-signed-distance-function-sdf-generation-and-processing.md).

## Operating characteristics
*   **Time Complexity**: $O(1)$ per evaluation point. The cost is dominated by the noise evaluation, which is $O(\text{octaves})$. With 4 octaves, this is constant and very fast [S1, S2, unofficial].
*   **Memory Complexity**: $O(1)$. No grid or mesh data is stored during evaluation [S1, S2, unofficial].
*   **Performance**: Extremely fast for ray marching or dual contouring as it avoids grid traversal or mesh lookups. Performance is limited by the cost of the Perlin noise function [S1, S2, unofficial].
*   **Strengths**: Infinite resolution, no storage overhead, easy to modify parameters for artistic control [S1, S2, unofficial].
*   **Limitations**: The resulting field is only $C^0$ continuous at intersections, which may cause artifacts in gradient-based rendering if not handled by the renderer. The noise is 2D-based for terrain, limiting vertical complexity [S1, S2, unofficial].
*   **When to use**: When generating scenes for dual contouring or ray marching where memory is constrained or infinite detail is desired.
*   **When not to use**: When $C^1$ continuity is strictly required across all boundaries, or when the scene geometry is too complex for analytic primitives.

## Background
The method is demonstrated in open-source dual contouring implementations, specifically `DualContouringSample` by Nick Gildrea and `DualContouringCSharp` by Tuckbone [S1, S2, unofficial]. These projects use the composition to create a test scene combining a procedural terrain with a cuboid and a sphere to validate the dual contouring mesh extraction algorithm [S1, S2, unofficial]. The technique leverages standard SDF Boolean operations and fractal noise, common in procedural generation literature [S1, S2, unofficial].
