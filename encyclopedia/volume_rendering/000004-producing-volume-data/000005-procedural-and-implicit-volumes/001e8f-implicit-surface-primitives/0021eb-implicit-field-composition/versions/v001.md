# Implicit Field Composition

Also called: Density Function Composition, Density Function for Scene Generation, Implicit Field Combination

## Overview
Implicit Field Composition constructs a single signed distance field (SDF) by combining multiple geometric primitives and procedural noise functions using Boolean set operations. It solves the problem of generating complex, hybrid scenes (e.g., terrain intersecting with structures) from simple, analytically defined components. It differs from [Procedural Volume Rendering with Noise Perturbation](1370-procedural-volume-rendering.md) by composing the field values directly rather than perturbing a base volume, and from [Distance to Hypertextures](1555-distance-to-hypertextures.md) by using exact analytical SDFs for primitives instead of texture-based distance approximations.

## How it works
**Inputs and Outputs:**
- Input: A query point $P$ in 3D world space.
- Output: A scalar signed distance value $d(P)$.

**Data Structures:**
No persistent data structures are required for the evaluation itself. The method relies on local computation of primitive SDFs and noise values.

**Parameters:**
- Fractal Noise:
  - `octaves`: 4 [S2, unofficial]
  - `frequency`: 0.5343 [S2, unofficial]
  - `lacunarity`: 2.2324 [S2, unofficial]
  - `persistence`: 0.68324 [S2, unofficial]
  - `scale`: $1/128$ [S1, S2, unofficial]
- Cuboid:
  - `origin`: $(-4, 10, -4)$ [S2, unofficial]
  - `halfDimensions`: $(12, 12, 12)$ [S2, unofficial]
- Sphere:
  - `origin`: $(15, 2.5, 1)$ [S2, unofficial]
  - `radius`: $16$ [S2, unofficial]

**Steps:**
1. **Compute Terrain SDF:**
   Calculate a height-field-like terrain using fractal noise. The terrain surface is defined at $y = 20 \cdot \text{noise}$. The SDF is the vertical distance from the query point to this surface.
   $$ \text{terrain}(P) = P_y - 20 \cdot N(P_x, P_z) $$
   Where $N$ is the fractal noise function evaluated at the horizontal coordinates of $P$.

2. **Compute Fractal Noise $N$:**
   Initialize `noise = 0`, `amplitude = 1`, and $p = (P_x, P_z) \cdot \text{scale}$.
   For $i$ from 0 to `octaves` - 1:
   $$ \text{noise} \leftarrow \text{noise} + \text{Perlin}(p) \cdot \text{amplitude} $$
   $$ p \leftarrow p \cdot \text{lacunarity} $$
   $$ \text{amplitude} \leftarrow \text{amplitude} \cdot \text{persistence} $$
   Normalize the result to $[0, 1]$:
   $$ N = 0.5 + 0.5 \cdot \text{noise} $$

3. **Compute Cuboid SDF:**
   Calculate the signed distance to an axis-aligned cuboid.
   $$ \text{local\_pos} = P - \text{origin}_{\text{cuboid}} $$
   $$ d = (| \text{local\_pos}_x |, | \text{local\_pos}_y |, | \text{local\_pos}_z |) - \text{halfDimensions} $$
   $$ m = \max(d_x, d_y, d_z) $$
   $$ \text{cuboid}(P) = \min(m, \| \max(d, 0) \|) $$
   Note: $\max(d, 0)$ is component-wise. If $P$ is inside, $d < 0$, so $\max(d, 0) = 0$, and the distance is $m$ (negative). If outside, the distance is the Euclidean norm of the positive components.

4. **Compute Sphere SDF:**
   Calculate the signed distance to a sphere.
   $$ \text{sphere}(P) = \| P - \text{origin}_{\text{sphere}} \| - \text{radius} $$

5. **Combine Fields:**
   Apply Boolean operations to merge the components. The standard composition in the reference implementation is:
   $$ \text{result}(P) = \max( -\text{cuboid}(P), \min( \text{sphere}(P), \text{terrain}(P) ) ) $$
   This effectively subtracts the cuboid from the union of the sphere and terrain.

**Pseudocode:**
```python
def implicit_field_composition(P: Vector3) -> float:
    # 1. Terrain
    terrain = compute_terrain(P)
    
    # 2. Cuboid
    cuboid = compute_cuboid(P)
    
    # 3. Sphere
    sphere = compute_sphere(P)
    
    # 4. Combine
    # Union of sphere and terrain, then subtract cuboid
    # min(a, b) is intersection, max(a, b) is union
    # To subtract cuboid: max(-cuboid, union)
    return max(-cuboid, min(sphere, terrain))

def compute_terrain(P: Vector3) -> float:
    # Terrain is y - height. Height is 20 * noise
    noise_val = fractal_noise(P.x, P.z)
    return P.y - 20.0 * noise_val

def fractal_noise(x: float, y: float) -> float:
    scale = 1.0 / 128.0
    p = Vector2(x * scale, y * scale)
    noise = 0.0
    amplitude = 1.0
    frequency = 0.5343
    lacunarity = 2.2324
    persistence = 0.68324
    octaves = 4
    
    p *= frequency
    
    for i in range(octaves):
        noise += perlin_noise(p.x, p.y) * amplitude
        p *= lacunarity
        amplitude *= persistence
        
    return 0.5 + 0.5 * noise

def compute_cuboid(P: Vector3) -> float:
    origin = Vector3(-4.0, 10.0, -4.0)
    half_dims = Vector3(12.0, 12.0, 12.0)
    
    local_pos = P - origin
    d = Vector3(
        abs(local_pos.x) - half_dims.x,
        abs(local_pos.y) - half_dims.y,
        abs(local_pos.z) - half_dims.z
    )
    
    m = max(d.x, max(d.y, d.z))
    
    # Component-wise max with 0
    pos_d = Vector3(
        max(d.x, 0.0),
        max(d.y, 0.0),
        max(d.z, 0.0)
    )
    
    return min(m, length(pos_d))

def compute_sphere(P: Vector3) -> float:
    origin = Vector3(15.0, 2.5, 1.0)
    radius = 16.0
    return length(P - origin) - radius
```

**Edge Cases and Pitfalls:**
- **Precision:** The terrain SDF is not a true Euclidean signed distance field; it is a vertical distance approximation. This can cause artifacts in normal estimation if true normals are required [G].
- **Boundaries:** The cuboid and sphere are defined by specific origins and dimensions. Query points far from these primitives will return large distance values.
- **Degenerate Input:** If `octaves` is 0, noise is 0, terrain is flat at $y=0$.

## Operating characteristics
- **Time Complexity:** $O(O \cdot N)$ where $O$ is the number of octaves and $N$ is the cost of the base noise function (e.g., Perlin). The geometric primitives are $O(1)$.
- **Memory Complexity:** $O(1)$ for evaluation. No storage of the field is required.
- **Strengths:** Analytical precision for primitives; easy to modify scene composition by changing parameters; no mesh generation overhead for evaluation.
- **Limitations:** Terrain is not a true Euclidean SDF; complex Boolean operations can create non-smooth transitions if not carefully blended (though min/max are sharp); limited to the primitives defined.
- **When to use:** When generating SDFs for dual contouring or ray marching from simple geometric and noise components.
- **When not to use:** When true Euclidean distance to complex terrain is required, or when the scene is too complex for analytical definitions.

## Background
Implicit Field Composition is a technique used in procedural geometry generation, particularly in the context of dual contouring. It was demonstrated in the `DualContouringSample` [S1, unofficial] and `DualContouringCSharp` [S2, unofficial] repositories. These implementations combine fractal noise for terrain with basic SDF primitives (cuboid, sphere) to create a hybrid scene suitable for mesh extraction via dual contouring. The method relies on the properties of SDFs under Boolean operations: union is `min`, intersection is `max`, and subtraction is `max(-A, B)`.
