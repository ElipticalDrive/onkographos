# Implicit Field Composition

Also called: Density Function Composition, Density Function for Scene Generation, Implicit Field Combination

## Overview
Implicit Field Composition constructs a complex volumetric or surface field by combining multiple primitive scalar fields (such as terrain, spheres, and cuboids) using Boolean set operations. It solves the problem of defining intricate scene geometry analytically without explicit mesh storage, serving as the primary input for marching cubes or dual contouring algorithms. It is distinguished from sibling methods by its explicit use of Boolean logic (max/min) to merge distinct geometric primitives, whereas siblings like [Procedural Volume Rendering with Noise Perturbation](1370-procedural-volume-rendering-with-noise-perturbation.md) focus on perturbing a single field, and [Distance to Hypertextures](1555-distance-to-hypertextures.md) focuses on distance transformations to texture maps.

## How it works
**Inputs:**
- Query point $\mathbf{x} \in \mathbb{R}^3$.
- Primitive parameters: origins, dimensions, radii, and noise coefficients.

**Outputs:**
- Scalar value $f(\mathbf{x})$ representing the signed distance or density at $\mathbf{x}$.

**Data Structures:**
- No persistent data structures are required for the evaluation itself. The method is stateless and analytic.

**Steps:**
1.  **Evaluate Terrain Field:** Compute a fractal noise-based height field.
    -   Scale position: $\mathbf{p} = (x, z) \cdot \text{SCALE}$.
    -   Compute Fractal Noise (see Formula below).
    -   Terrain value: $T(\mathbf{x}) = y - (H \cdot N(\mathbf{p}))$, where $H$ is a height multiplier.
2.  **Evaluate Primitive Fields:**
    -   **Sphere:** $S(\mathbf{x}) = \|\mathbf{x} - \mathbf{o}_s\| - r_s$.
    -   **Cuboid:** Compute local position $\mathbf{l} = \mathbf{x} - \mathbf{o}_c$. Compute distance to box surface $D_{box}$.
3.  **Combine Fields:** Apply Boolean operations to merge the fields into a single implicit function.

**Formulas:**

*Fractal Noise (FBM):*
$$N(\mathbf{p}) = 0.5 + 0.5 \sum_{i=0}^{n-1} \text{noise}(\mathbf{p} \cdot f) \cdot a_i$$
Where:
-   $n$ is the number of octaves.
-   $f$ is the base frequency.
-   $a_i = \text{persistence}^i$ is the amplitude for octave $i$.
-   $\mathbf{p}$ is scaled by $\text{lacunarity}^i$ each iteration.
-   $\text{noise}(\cdot)$ is a base noise function (e.g., Perlin or Simplex) [S1, S2, unofficial].

*Cuboid Signed Distance:*
Let $\mathbf{l} = \mathbf{x} - \mathbf{o}_c$ and $\mathbf{h}$ be the half-dimensions.
$$\mathbf{d} = (|\mathbf{l}_x| - h_x, |\mathbf{l}_y| - h_y, |\mathbf{l}_z| - h_z)$$
$$m = \max(d_x, d_y, d_z)$$
$$C(\mathbf{x}) = \min(m, \|\mathbf{d}_{\text{pos}}\|)$$
Where $\mathbf{d}_{\text{pos}}$ is the vector $\mathbf{d}$ with negative components clamped to 0 [S2, unofficial].

*Composition Logic:*
The final field $F(\mathbf{x})$ combines the terrain ($T$), a cuboid ($C$), and a sphere ($S$). The sources provide two variations of the Boolean logic:
1.  $F(\mathbf{x}) = \max(-C(\mathbf{x}), \min(S(\mathbf{x}), T(\mathbf{x})))$ [S1, S2, unofficial].
    -   This logic effectively creates a union with the terrain and sphere, while the cuboid acts as a "hole" or subtractive volume depending on the sign convention of the primitives. Note that $-C(\mathbf{x})$ inverts the cuboid's distance field, turning it into a potential union component if the other fields are positive, or a subtraction if interpreted as a mask. The specific semantic meaning (union/intersection) depends on the global sign convention of the renderer (e.g., positive = inside vs. negative = inside).

**Parameters (Typical Values from Sources):**
-   **Noise:** octaves=4, frequency=0.5343, lacunarity=2.2324, persistence=0.68324, SCALE=1/128 [S2, unofficial].
-   **Terrain Height Multiplier:** 20.0 [S1, S2, unofficial].
-   **Cuboid:** origin=(-4, 10, -4), halfDimensions=(12, 12, 12) [S2, unofficial].
-   **Sphere:** origin=(15, 2.5, 1), radius=16 [S2, unofficial].

**Pseudocode:**

```python
def evaluate_implicit_field(x, y, z):
    # 1. Terrain Evaluation
    scale = 1.0 / 128.0
    p_2d = (x * scale, z * scale)
    terrain_height = fractal_noise(p_2d, octaves=4, freq=0.5343, lac=2.2324, pers=0.68324)
    terrain_val = y - (20.0 * terrain_height)

    # 2. Sphere Evaluation
    sphere_origin = (15.0, 2.5, 1.0)
    sphere_radius = 16.0
    dx_s = x - sphere_origin[0]
    dy_s = y - sphere_origin[1]
    dz_s = z - sphere_origin[2]
    sphere_val = sqrt(dx_s**2 + dy_s**2 + dz_s**2) - sphere_radius

    # 3. Cuboid Evaluation
    cuboid_origin = (-4.0, 10.0, -4.0)
    half_dims = (12.0, 12.0, 12.0)
    lx = abs(x - cuboid_origin[0]) - half_dims[0]
    ly = abs(y - cuboid_origin[1]) - half_dims[1]
    lz = abs(z - cuboid_origin[2]) - half_dims[2]
    
    max_dist = max(lx, ly, lz)
    pos_dist_sq = 0.0
    if lx > 0: pos_dist_sq += lx**2
    if ly > 0: pos_dist_sq += ly**2
    if lz > 0: pos_dist_sq += lz**2
    pos_dist = sqrt(pos_dist_sq)
    
    cuboid_val = min(max_dist, pos_dist)

    # 4. Composition
    # Logic: max(-cuboid, min(sphere, terrain))
    # Note: -cuboid inverts the distance. If cuboid_val is positive (outside), -cuboid is negative.
    # This typically implies the cuboid is subtracted from the union of sphere and terrain,
    # or acts as a mask depending on the marching cube threshold.
    result = max(-cuboid_val, min(sphere_val, terrain_val))
    
    return result

def fractal_noise(p_2d, octaves, freq, lac, pers):
    p = (p_2d[0] * freq, p_2d[1] * freq)
    noise_sum = 0.0
    amplitude = 1.0
    
    for i in range(octaves):
        # Base noise function (e.g., Perlin)
        n = perlin_noise(p[0], p[1])
        noise_sum += n * amplitude
        p = (p[0] * lac, p[1] * lac)
        amplitude *= pers
        
    return 0.5 + 0.5 * noise_sum
```

**Edge Cases:**
-   **Precision:** Near the boundaries of primitives, the distance functions are non-differentiable (kinks). Dual contouring handles this via QEF (Quadratic Error Function) minimization, but standard marching cubes may produce artifacts [S1, S2, unofficial].
-   **Degenerate Input:** If the query point is exactly on the boundary, the value is 0. Floating point errors may cause the point to be classified as inside or outside inconsistently.

## Operating characteristics
-   **Time Complexity:** $O(O \cdot N)$, where $O$ is the number of octaves and $N$ is the cost of the base noise function per query. The Boolean operations are $O(1)$.
-   **Memory Complexity:** $O(1)$ for the evaluator itself. No storage of the field is required; it is computed on-the-fly.
-   **Strengths:** Infinite resolution, seamless tiling (if noise is periodic or domain-warped), and compact representation of complex scenes.
-   **Limitations:** Evaluation is computationally expensive per pixel/voxel compared to texture lookups. Discontinuities in derivatives at Boolean boundaries can cause shading artifacts or meshing errors if not handled by robust solvers like Dual Contouring.
-   **When to use:** When procedural generation of complex, multi-material, or boolean-combined geometry is required without pre-baking meshes.
-   **When not to use:** When performance is critical and the geometry is static (bake to mesh/texture instead) or when the scene is purely data-driven (use voxel grids).

## Background
Implicit Field Composition is a foundational technique in procedural modeling and ray marching. It relies on the mathematical properties of Signed Distance Functions (SDFs) and Boolean algebra. The specific implementation details (combining terrain, cuboids, and spheres via max/min) are documented in open-source dual contouring samples [S1, S2, unofficial]. The use of Fractal Brownian Motion (FBM) for terrain generation dates back to early procedural graphics [S5, S6, unofficial].
