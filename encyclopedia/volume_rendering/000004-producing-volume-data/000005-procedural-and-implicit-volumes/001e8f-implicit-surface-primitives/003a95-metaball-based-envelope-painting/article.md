# Metaball-based Envelope Painting

Also called: 3D Envelope Painting, 3D Painting Metaphor for Envelope Definition, 3D Painting Metaphor for VOI Definition, Metaball-based envelope definition, Thick Paint Metaphor, Volume Painting

## Overview
Metaball-based Envelope Painting is an interaction model for defining a Volume of Interest (VOI) or Region of Interest (ROI) within unsegmented volumetric data by "painting" an implicit envelope around features of interest [S1][S2, unofficial]. It solves the problem of intuitive, context-preserving volume exploration by replacing complex transfer function tuning with a direct spatial marking metaphor [S1]. Unlike techniques using independent surface-bound brushes or fixed-depth peeling regions, this method uses a higher-level shape representation (Metaballs) to create organic, merging envelopes that allow for real-time previewing of the visualization effect before final deposition [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric dataset $V$, camera parameters, user input (mouse position, button states).
*   **Output:** A composite image showing the volume with two distinct visualization styles: one for the interior of the envelope (VOI) and one for the exterior, combined via depth peeling.

**Data Structures:**
*   **Metaball List:** A dynamic list of metaball primitives. Each metaball $M_i$ is defined by:
    *   Center position $\vec{c}_i \in \mathbb{R}^3$.
    *   Radius/Scale $r_i \in \mathbb{R}^+$.
    *   Polarity $p_i \in \{+1, -1\}$ (positive for painting, negative for erasing) [S2, unofficial].
    *   Shape type: Quadric (spherical) or Superquadric (cylindrical/disk) [S1].
*   **Vertex Buffer:** A GPU memory buffer storing the polygonal mesh of the envelope's isosurface, generated by Marching Cubes [S1].
*   **Position/Normal Maps:** On-the-fly generated textures storing the surface position and normal vectors for 3D surface painting mode [S1].

**Mathematical Definition:**
The envelope is defined by a scalar field function $f(\vec{x})$ constructed from the sum of individual metaball fields. The surface is the isosurface where $f(\vec{x}) = 0$ (or a specific threshold) [S1][S2, unofficial].

The field falloff for a single metaball is modeled using the six-degree Wyvill polynomial [S1]:
$$ f_i(\vec{x}) = \frac{6r_i^6 - 15r_i^4|\vec{x}-\vec{c}_i|^2 + 10r_i^3|\vec{x}-\vec{c}_i|^3}{|\vec{x}-\vec{c}_i|^6} $$
where $|\vec{x}-\vec{c}_i|$ is the distance from point $\vec{x}$ to the metaball center $\vec{c}_i$, and $r_i$ is the radius of the metaball [S1].

The total field is the sum of all active metaballs:
$$ f(\vec{x}) = \sum_{i} p_i \cdot f_i(\vec{x}) $$
where $p_i$ is the polarity (+1 or -1) [S2, unofficial].

**Parameters:**
*   **Brush Tip Shape:** Spherical (default, quadric) or Cylindrical (superquadric, used in 3D Surface Painting Mode) [S1][S2, unofficial].
*   **Brush Tip Polarity:** Positive (paint/add) or Negative (erase/remove) [S2, unofficial].
*   **Cylinder Height:** Adjustable parameter for cylindrical brushes to control penetration depth into the volume surface [S2, unofficial].
*   **MIDA Parameters:** Two separate sets of Maximum Intensity Difference Accumulation (MIDA) visualization parameters are used: one for inside the envelope, one for outside [S1].

**Steps:**
1.  **Initialization:** Load volumetric data and initialize MIDA visualization parameters for inside and outside regions. Initialize an empty Metaball List. Generate position and normal maps for the volume surface [S1].
2.  **Preview (Move):** As the user moves the mouse, calculate the 3D position of the brush tip $\vec{c}_{tip}$.
    *   In **3D Free-hand Mode**: The depth is determined by ray casting or user control.
    *   In **3D Surface Painting Mode**: The depth is overridden by the depth value of the object's surface at the projected position, retrieved from the position map. The brush orientation aligns with the surface normal from the normal map [S1].
    *   In **2D Screen Painting Mode**: The depth is constant (or discarded), acting as a 2D stencil [S1].
    *   Construct a temporary metaball $M_{tip}$ at $\vec{c}_{tip}$ with current brush parameters.
    *   Evaluate $f(\vec{x})$ for all voxels/samples. Visualize the volume using the "inside" MIDA parameters for regions where $f(\vec{x})$ indicates inclusion (based on the preview blob) and "outside" parameters otherwise. This provides real-time feedback [S1][S2, unofficial].
3.  **Deposit (Click):** If the user clicks (e.g., holding Alt key) [S2, unofficial]:
    *   Add $M_{tip}$ to the Metaball List.
    *   If polarity is negative, remove overlapping metaballs or negate their contribution [S2, unofficial].
4.  **Surface Extraction:**
    *   Compute the isosurface of the current Metaball List using the Marching Cubes algorithm [S1].
    *   Implement a fast GLSL shader version of Marching Cubes to extract the iso-surface [S1].
    *   Capture the resulting geometry into a memory vertex buffer. Reuse this buffer for subsequent frames to avoid recomputation [S1].
5.  **Rendering:**
    *   Render the volumetric data using the chosen DVR technique (e.g., MIDA) [S1].
    *   Render the polygonal envelope geometry using Front-to-Back Depth Peeling. This combines the polygon-based envelope geometry and volumetric DVR geometry layer by layer from the camera position, filling gaps between layers with DVR results [S1].
    *   Apply the "inside" visualization style to the volume parts enclosed by the envelope and the "outside" style to the rest. In 2D mode, the stencil applies the inside style all the way through the volume (X-ray style) [S1][S2, unofficial].
6.  **Editing (Optional):**
    *   To carve/peel volume data, set the mapped data intensity range to zero for parts inside or outside the envelope [S1].

```python
# Global State
metaballs = [] # List of Metaball objects
inside_params = MIDA_Params()
outside_params = MIDA_Params()
vertex_buffer = None # GPU buffer for envelope mesh
pos_map = Texture() # 3D texture of surface positions
norm_map = Texture() # 3D texture of surface normals

class Metaball:
    def __init__(self, center, radius, polarity=1, shape='quadric'):
        self.center = center
        self.radius = radius
        self.polarity = polarity
        self.shape = shape

def wyvill_field(x, metaball):
    dist_sq = dot(x - metaball.center, x - metaball.center)
    dist = sqrt(dist_sq)
    if dist == 0: return 1.0 # Singularity handling [G]
    r = metaball.radius
    # Six-degree Wyvill polynomial
    term1 = 6 * r**6
    term2 = 15 * r**4 * dist_sq
    term3 = 10 * r**3 * dist**3
    numerator = term1 - term2 + term3
    denominator = dist**6
    return numerator / denominator

def evaluate_field(x):
    total = 0.0
    for mb in metaballs:
        total += mb.polarity * wyvill_field(x, mb)
    return total

def is_inside(x):
    # Convention: positive field value indicates inside for standard metaballs
    # Note: Polarity handles negative brushes
    return evaluate_field(x) > 0

def get_brush_tip_position(mouse_x, mouse_y, mode):
    if mode == '2D_SCREEN':
        # Constant depth or ray cast to infinity
        return ray_cast_at_depth(mouse_x, mouse_y, depth=constant_depth)
    elif mode == '3D_SURFACE':
        # Override depth with surface depth
        depth = pos_map.sample_at_screen(mouse_x, mouse_y)
        normal = norm_map.sample_at_screen(mouse_x, mouse_y)
        return ray_cast_at_depth(mouse_x, mouse_y, depth=depth), normal
    else: # 3D_FREEHAND
        return ray_cast_at_depth(mouse_x, mouse_y, depth=user_controlled)

def render_frame(camera, volume_data):
    # 1. Update Envelope Geometry if metaballs changed
    if metaballs_changed:
        # Extract isosurface using GLSL Marching Cubes
        mesh = glsl_marching_cubes(metaballs, isovalue=0.0)
        vertex_buffer = mesh.to_vertex_buffer()
        metaballs_changed = False

    # 2. Render Volume with Depth Peeling
    # Render layers from front to back
    for layer in depth_peeling_layers(camera):
        # Determine if layer is inside or outside envelope
        # This requires checking the envelope mesh against the layer geometry
        # Simplified: Use stencil or depth test against envelope mesh
        
        # Sample volume
        color = sample_volume(volume_data, layer.position, inside_params if is_inside(layer.position) else outside_params)
        
        # Blend with envelope geometry if present
        if vertex_buffer:
            color = blend_with_envelope(color, layer.position, vertex_buffer)
            
        write_to_framebuffer(color)

def on_mouse_move(mouse_x, mouse_y):
    tip_pos, tip_normal = get_brush_tip_position(mouse_x, mouse_y, current_mode)
    
    # Create temporary preview metaball
    preview_mb = Metaball(tip_pos, brush_radius, brush_polarity, brush_shape)
    
    # Temporarily add to list for evaluation
    metaballs.append(preview_mb)
    
    # Render preview (real-time visualization of inside style)
    render_frame(camera, volume_data)
    
    # Remove preview metaball
    metaballs.pop()

def on_mouse_click(mouse_x, mouse_y):
    # Deposit the brush stroke
    tip_pos, tip_normal = get_brush_tip_position(mouse_x, mouse_y, current_mode)
    
    if current_mode == '3D_SURFACE':
        # Adjust shape to cylinder aligned with normal
        shape = 'superquadric'
        # Orient cylinder along tip_normal [S1]
    else:
        shape = 'quadric'
        
    new_mb = Metaball(tip_pos, brush_radius, brush_polarity, shape)
    metaballs.append(new_mb)
    metaballs_changed = True
```

**Edge Cases and Pitfalls:**
*   **Singularity:** The Wyvill polynomial has a singularity at the center of the metaball ($|\vec{x}-\vec{c}_i|=0$). A guard value (e.g., returning 1.0) is required [G].
*   **2D Mode Depth:** In 2D Screen Painting Mode, depth information is discarded, applying the visualization effect through the entire volume along the ray (X-ray style) [S2, unofficial].
*   **Performance:** Geometry recomputation is avoided by reusing the vertex buffer, but updating the buffer when metaballs change can be costly if done every frame [S1].
*   **Precision:** The six-degree polynomial can suffer from floating-point precision issues at large distances or very small radii [G].

## Subtopics

### [3D Painting Metaphor for ROI Definition](11204-3d-painting-metaphor-for-roi-definition.md)
This method allows users to define a Region of Interest (ROI) by placing brush strokes directly in the visualization space, creating an implicit envelope that encloses features of interest without requiring complex parameter tweaking. It differs from traditional transfer function specification by replacing 2D histogram curve manipulation with direct spatial marking, eliminating the need for volumetric data representation knowledge. It builds on [Metaball-based Envelope Painting](8803-metaball-based-envelope-painting.md) by providing the interaction model that generates the metaball parameters.

### Metaball Envelope Merging
The envelope is defined by a series of metaballs. The brush tip acts as the first metaball, defining the attributes (size, parameters) for every new metaball added to the series [S2, unofficial]. Merging influence is determined by the size of the metaball and its proximity to other metaballs. Larger and closer metaballs have a greater merging factor [S2, unofficial]. The specific mathematical form of the field function is a parameter of the metaball implementation [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time preview requires evaluating the field function for all visible voxels/samples per frame. The complexity is $O(N \cdot M)$ where $N$ is the number of samples and $M$ is the number of metaballs. Marching Cubes extraction is $O(V)$ where $V$ is the volume resolution, but optimized via GPU shaders and buffer reuse [S1].
*   **Memory Complexity:** $O(M)$ for storing metaball parameters. $O(V)$ for position/normal maps and vertex buffers [S1].
*   **Strengths:** Intuitive interaction, real-time preview, organic shapes, flexibility in envelope definition, independence from specific DVR techniques [S1].
*   **Limitations:** Requires GPU acceleration for real-time performance (GLSL shaders). 2D mode loses depth information [S1][S2, unofficial].
*   **When to use:** Interactive exploration of unsegmented volumetric data, defining contextual views, volume carving/peeling [S1].
*   **When not to use:** When precise, non-organic geometric boundaries are required, or when hardware does not support real-time GPU-based Marching Cubes [S1].

## Background
Metaball-based Envelope Painting was introduced by L. Faynshteyn and T. McInerney in 2012 [S1]. It combines the Maximum Intensity Difference Accumulation (MIDA) visualization algorithm with a 3D interaction model based on a painting metaphor [S1]. The technique was validated through a user study involving 11 subjects (10 undergraduate, 1 graduate) from computer science departments [S1]. It builds on the concept of Metaballs as implicit surfaces [S2, unofficial] and extends previous techniques like independent surface-bound brushes and depth-fixed peeling regions [S1].
