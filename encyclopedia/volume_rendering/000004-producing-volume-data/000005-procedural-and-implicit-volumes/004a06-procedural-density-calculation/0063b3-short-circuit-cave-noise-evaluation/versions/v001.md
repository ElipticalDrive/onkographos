# Short-circuit Cave Noise Evaluation

Also called: Deterministic fixed-point cave density field optimization, Lazy cave generation sampling

## Overview
Short-circuit Cave Noise Evaluation is an optimization for procedural cave generation that avoids computing the second trilinear noise field when the first band check fails, reducing per-voxel generation cost [S1, unofficial]. It differs from eager evaluation by deferring `field_b` computation until `cond_a` passes, leveraging short-circuit logic to skip expensive trilinear sampling in the common case where `band_a` fails [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: A 3D chunk of voxels (typically $32 \times 32 \times 32$).
- **Output**: A boolean `tunnel` value for each solid voxel indicating if it should be carved.

**Data Structures**
- **Chunk**: A 3D array of voxels. Each voxel is processed if it is "solid" (i.e., not already determined to be air or outside the surface-roof/bedrock-floor bounds).
- **Noise Fields**: Two trilinear noise fields, `field_a` and `field_b`. Each field requires 8 hash samples for trilinear interpolation [S1, unofficial].
- **Constants**:
  - `NOISE_MID`: Reference value for band checks, relative to the full 0-65535 hash range [S1, unofficial].
  - `hash_samples`: Fixed at 8 [S1, unofficial].

**Steps**
1. Iterate over every voxel in the chunk.
2. Check if the voxel is solid (past surface-roof and bedrock-floor checks). If not, skip.
3. Evaluate `cond_a` using `field_a`.
   - `cond_a` is a narrow band check around `NOISE_MID` relative to the 0-65535 hash range [S1, unofficial].
4. If `cond_a` fails:
   - Skip computing `field_b`.
   - Set `tunnel = false`.
5. If `cond_a` passes:
   - Compute `field_b` (8 hash samples) [S1, unofficial].
   - Evaluate `cond_b` using `field_b` (same narrow band check logic as `cond_a`) [S1, unofficial].
   - Set `tunnel = cond_a && cond_b` [S1, unofficial].

**Formula**
$$ tunnel = cond_a \land cond_b $$
where `cond_a` and `cond_b` are narrow band checks around `NOISE_MID` relative to the full 0-65535 hash range [S1, unofficial].

**Edge Cases and Pitfalls**
- **Eager Evaluation**: Computing `field_b` before the logical AND operator causes unnecessary computation even when `cond_a` fails, as seen in the initial Rust implementation [S1, unofficial].
- **Chunk Generation Cost**: Chunk generation runs on every solid voxel past surface-roof and bedrock-floor checks, making the noise evaluation the single largest cost during generation [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Reduced from $O(V)$ with unconditional dual-field evaluation to $O(V)$ with short-circuit evaluation, where $V$ is the number of solid voxels per chunk [S1, unofficial]. The constant factor is significantly reduced because `field_b` is often skipped.
- **Memory Complexity**: Memory layout remains unchanged [S1, unofficial].
- **Strengths**: Significantly reduces per-voxel generation cost by avoiding expensive trilinear sampling in the common case where `band_a` fails [S1, unofficial].
- **Limitations**: The optimization is specific to the cave generation logic and does not apply to other procedural volume generation methods [S1, unofficial].
- **When to Use**: Use when generating procedural caves in voxel worlds, especially when performance is critical and the majority of voxels do not form tunnels [S1, unofficial].
- **When Not to Use**: Do not use if the cave generation logic requires both noise fields to be computed for other reasons (e.g., visualization, debugging) [S1, unofficial].

## Background
Short-circuit Cave Noise Evaluation was introduced in the TEKNIK project to address performance issues in procedural cave generation [S1, unofficial]. The optimization was identified as the main cause of lag on both surface and underground chunks, as even surface-area chunks with no visible caves paid the per-voxel cost during generation [S1, unofficial]. The fix was applied to both GDScript and Rust implementations, with GDScript serving as the parity reference [S1, unofficial].
