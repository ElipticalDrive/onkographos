# Ellipsoid Fitting and Rotation for Cloud Meshes

Also called: Cloud Generation from 3D Meshes, Mesh Decimation and Ellipsoid Smoothing, Mesh-to-Ellipsoid conversion, Rodrigues' Rotation Formula for Cloud Geometry, Triangle-based ellipsoid cloud generation

## Overview
This method converts high-resolution 3D meshes (e.g., from Blender or Maya) into volumetric cloud geometry by replacing triangle faces with fitted ellipsoids [S1]. It solves the problem of rendering complex, organic shapes in real-time by decimating the input mesh and approximating its surface with smooth primitives [S1]. Unlike raw mesh rendering, this approach acts as a real-time filter that produces softer, cumuliform shapes suitable for smoke and cloud simulation [S1].

## How it works
**Inputs:** A decimated 3D mesh consisting of $N$ triangles, where each triangle has vertices $\mathbf{v}_1, \mathbf{v}_2, \mathbf{v}_3$ [S1].
**Outputs:** A set of ellipsoid parameters (center, radii, rotation matrix) for each triangle, ready for GPU rendering [S1].

**Data Structures:**
*   **Triangle:** Struct containing three 3D vertex coordinates $\mathbf{v}_i \in \mathbb{R}^3$ [S1].
*   **Ellipsoid:** Struct containing:
    *   Center $\mathbf{c} \in \mathbb{R}^3$ [S1].
    *   Radii $(a, b, c) \in \mathbb{R}^3$ [S1].
    *   Rotation Matrix $\mathbf{R} \in \mathbb{R}^{3 \times 3}$ [S1].

**Steps:**

1.  **Mesh Decimation:** Reduce the input mesh to 300–700 triangles (or $\le 1000$) to ensure real-time performance [S1]. A decimation rate of 80–95% is acceptable [S1].
2.  **Barycenter Calculation:** For each triangle, compute the barycenter $\mathbf{B}$ [S1]:
    $$ \mathbf{B} = \frac{\mathbf{v}_1 + \mathbf{v}_2 + \mathbf{v}_3}{3} \quad \text{(Eq. 22)} $$
3.  **Scaling:** Scale the triangle vertices relative to the barycenter using a scale factor $s$ [S1]. The factor $s$ typically falls in the range $(0.1, 2]$ [S1]. The scaled vertices $\mathbf{v}'_i$ are calculated as:
    $$ \mathbf{v}'_i = \mathbf{B} + s(\mathbf{v}_i - \mathbf{B}) \quad \text{(Eq. 23, 24)} $$
4.  **Radii Determination:** Calculate the maximum distance from the barycenter to any scaled vertex [S1]. This distance defines the maximum radius of the circumscribing ellipsoid [S1]. The radii $(a, b, c)$ are derived from this maximum extent [S1].
5.  **Rotation Optimization:** Align the ellipsoid's maximum radius with the direction of the maximum distance from the barycenter to the triangle vertices to produce a softer shape [S1]. This uses Rodrigues' Rotation Formula [S1]:
    *   **Axis and Angle:** Calculate the rotation axis $\mathbf{k}$ and angle $\theta$ using cross and dot products of the relevant direction vectors [S1]:
        $$ \mathbf{k} = \frac{\mathbf{u} \times \mathbf{v}}{\|\mathbf{u} \times \mathbf{v}\|}, \quad \theta = \arccos\left(\frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| \|\mathbf{v}\|}\right) \quad \text{(Eq. 27, 28)} $$
        where $\mathbf{u}$ is the ellipsoid's initial principal axis and $\mathbf{v}$ is the vector from the barycenter to the furthest scaled vertex [S1].
    *   **Skew-Symmetric Matrix:** Compute matrix $\mathbf{A}$ corresponding to the axis vector $\mathbf{x}$ (where $\mathbf{x}$ is the normalized rotation axis) [S1]:
        $$ \mathbf{A} = \begin{bmatrix} 0 & -x_z & x_y \\ x_z & 0 & -x_x \\ -x_y & x_x & 0 \end{bmatrix} \quad \text{(Eq. 30)} $$
    *   **Rotation Matrix:** Calculate $\mathbf{R}$ using the exponential map (Rodrigues' formula) [S1]:
        $$ \mathbf{R} = \mathbf{I} + (\sin \theta)\mathbf{A} + (1 - \cos \theta)\mathbf{A}^2 \quad \text{(Eq. 29)} $$
6.  **GPU Transfer:** Pre-calculate formulas (1)–(3) on the CPU [S1]. Only the final rotation matrix $\mathbf{R}$ is passed to the GPU for rendering [S1].

**Pseudocode:**

```python
import math

def vec_add(a, b):
    return (a[0] + b[0], a[1] + b[1], a[2] + b[2])

def vec_sub(a, b):
    return (a[0] - b[0], a[1] - b[1], a[2] - b[2])

def vec_scale(a, s):
    return (a[0] * s, a[1] * s, a[2] * s)

def vec_dot(a, b):
    return a[0] * b[0] + a[1] * b[1] + a[2] * b[2]

def vec_cross(a, b):
    return (a[1] * b[2] - a[2] * b[1],
            a[2] * b[0] - a[0] * b[2],
            a[0] * b[1] - a[1] * b[0])

def vec_norm(a):
    return math.sqrt(vec_dot(a, a))

def vec_normalize(a):
    n = vec_norm(a)
    if n < 1e-9:
        return (0.0, 0.0, 0.0)
    return (a[0] / n, a[1] / n, a[2] / n)

def compute_barycenter(v1, v2, v3):
    return vec_scale(vec_add(vec_add(v1, v2), v3), 1.0 / 3.0)

def scale_triangle(v1, v2, v3, barycenter, scale_factor):
    v1_s = vec_add(barycenter, vec_scale(vec_sub(v1, barycenter), scale_factor))
    v2_s = vec_add(barycenter, vec_scale(vec_sub(v2, barycenter), scale_factor))
    v3_s = vec_add(barycenter, vec_scale(vec_sub(v3, barycenter), scale_factor))
    return v1_s, v2_s, v3_s

def get_max_radius(barycenter, v1, v2, v3):
    d1 = vec_norm(vec_sub(v1, barycenter))
    d2 = vec_norm(vec_sub(v2, barycenter))
    d3 = vec_norm(vec_sub(v3, barycenter))
    return max(d1, d2, d3)

def compute_rotation_matrix(u, v):
    u_norm = vec_normalize(u)
    v_norm = vec_normalize(v)
    cross = vec_cross(u_norm, v_norm)
    dot = vec_dot(u_norm, v_norm)
    
    if vec_norm(cross) < 1e-6:
        if dot > 0:
            return ((1,0,0), (0,1,0), (0,0,1))
        else:
            # [G] Fallback for 180-degree rotation: use arbitrary orthogonal axis
            axis = (1.0, 0.0, 0.0)
            if abs(vec_dot(axis, u_norm)) > 0.9:
                axis = (0.0, 1.0, 0.0)
            axis = vec_sub(axis, vec_scale(u_norm, vec_dot(axis, u_norm)))
            axis = vec_normalize(axis)
            cross = axis
            theta = math.pi
    else:
        cross = vec_normalize(cross)
        theta = math.acos(max(-1.0, min(1.0, dot)))

    x = cross
    A = ((0.0, -x[2], x[1]),
         (x[2], 0.0, -x[0]),
         (-x[1], x[0], 0.0))
    
    # Matrix multiplication A^2
    A2 = ((A[0][0]*A[0][0] + A[0][1]*A[1][0] + A[0][2]*A[2][0],
           A[0][0]*A[0][1] + A[0][1]*A[1][1] + A[0][2]*A[2][1],
           A[0][0]*A[0][2] + A[0][1]*A[1][2] + A[0][2]*A[2][2]),
          (A[1][0]*A[0][0] + A[1][1]*A[1][0] + A[1][2]*A[2][0],
           A[1][0]*A[0][1] + A[1][1]*A[1][1] + A[1][2]*A[2][1],
           A[1][0]*A[0][2] + A[1][1]*A[1][2] + A[1][2]*A[2][2]),
          (A[2][0]*A[0][0] + A[2][1]*A[1][0] + A[2][2]*A[2][0],
           A[2][0]*A[0][1] + A[2][1]*A[1][1] + A[2][2]*A[2][1],
           A[2][0]*A[0][2] + A[2][1]*A[1][2] + A[2][2]*A[2][2]))
           
    I = ((1,0,0), (0,1,0), (0,0,1))
    sin_t = math.sin(theta)
    cos_t = math.cos(theta)
    
    R = ((I[0][0] + sin_t * A[0][0] + (1 - cos_t) * A2[0][0],
          I[0][1] + sin_t * A[0][1] + (1 - cos_t) * A2[0][1],
          I[0][2] + sin_t * A[0][2] + (1 - cos_t) * A2[0][2]),
         (I[1][0] + sin_t * A[1][0] + (1 - cos_t) * A2[1][0],
          I[1][1] + sin_t * A[1][1] + (1 - cos_t) * A2[1][1],
          I[1][2] + sin_t * A[1][2] + (1 - cos_t) * A2[1][2]),
         (I[2][0] + sin_t * A[2][0] + (1 - cos_t) * A2[2][0],
          I[2][1] + sin_t * A[2][1] + (1 - cos_t) * A2[2][1],
          I[2][2] + sin_t * A[2][2] + (1 - cos_t) * A2[2][2]))
    return R

def fit_ellipsoid_to_triangle(v1, v2, v3, scale_factor=1.0):
    B = compute_barycenter(v1, v2, v3)
    v1_s, v2_s, v3_s = scale_triangle(v1, v2, v3, B, scale_factor)
    max_r = get_max_radius(B, v1_s, v2_s, v3_s)
    
    # Not given in the sources. The evidence states the max distance is used to calculate radii (a, b, c),
    # but does not specify how the minor radii are derived from the maximum extent.
    radii = (max_r, max_r, max_r)

    dists = [vec_norm(vec_sub(v1_s, B)), vec_norm(vec_sub(v2_s, B)), vec_norm(vec_sub(v3_s, B))]
    max_idx = dists.index(max(dists))
    max_vertex = [v1_s, v2_s, v3_s][max_idx]
    target_dir = vec_sub(max_vertex, B)
    
    # [G] Source does not specify the initial principal axis; using a default vector.
    initial_axis = (0.0, 0.0, 1.0)
    R = compute_rotation_matrix(initial_axis, target_dir)
    return {'center': B, 'radii': radii, 'rotation_matrix': R}
```

**Parameters:**
*   **Scale Factor ($s$):** Typically in the range $(0.1, 2]$ [S1].
*   **Mesh Resolution:** 300–700 triangles after decimation [S1]. Up to 1000 triangles is the upper limit for standard GPUs [S1].

**Edge Cases and Pitfalls:**
*   **Performance:** Without pre-calculation on the CPU and decimation, performance is hindered on lower-speed GPUs [S1].
*   **Precision:** The rotation calculation relies on stable cross/dot products; parallel vectors require special handling [G].
*   **Boundary:** The method assumes the input mesh is already decimated. Fitting to high-poly meshes directly is not supported [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1].
*   **Memory Complexity:** Not given in the sources [S1].
*   **Performance:** Significantly improves performance on lower-end GPUs by reducing vertex count and simplifying geometry to ellipsoids [S1]. Benchmarks confirm no hindrance on lower-speed hardware [S1].
*   **Strengths:** Real-time capability; produces soft, organic cloud shapes; leverages standard 3D modeling tools [S1].
*   **Limitations:** Requires manual or automated decimation; approximation error increases with high decimation rates (>95%) though visual quality remains acceptable [S1].

## Background
This method was introduced in the context of real-time GPU volumetric cloud rendering, specifically for generating "suggestive cumuliforms" [S1]. It allows artists to use standard 3D modeling software (Blender, Maya) to create cloud shapes, which are then converted into volumetric primitives for rendering [S1]. The technique is part of a broader set of geometry innovations for real-time cloud rendering [S1].
