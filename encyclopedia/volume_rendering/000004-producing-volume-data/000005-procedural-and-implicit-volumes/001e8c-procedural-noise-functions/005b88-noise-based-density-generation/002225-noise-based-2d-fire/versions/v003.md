# Noise-based 2D Fire

Also called: 2D Fire Texture Generation, Voronoi-Perlin Fire Noise

## Overview
Noise-based 2D Fire is a procedural technique for generating the base density and color texture of volumetric fire, serving as the input for constructing 3D cylindrical fire volumes [S1, unofficial]. It distinguishes itself from sprite-based systems by providing a continuous, artifact-free texture that supports dynamic scaling, and from photo-realistic fluid simulations by offering real-time performance with artist-controllable aesthetics [S1, unofficial]. The method combines multiple noise functions to create turbulent micro-details, which are then mapped onto a 2D profile to drive the visual appearance of the flame [S1, unofficial].

## How it works
The method generates a 2D texture that defines the fire's shape, color, and intensity. This texture is subsequently used to map colors onto a 3D lattice surrounding a central curve [S1, unofficial]. The generation involves creating noise fields, combining them, and applying a color gradient.

### Inputs and Outputs
*   **Inputs**:
    *   2D UV coordinates for the texture space.
    *   Noise parameters: frequency, scale, and time offset.
    *   A standard UV texture for interpolation.
    *   A color gradient definition.
*   **Outputs**:
    *   A 2D color texture (Fire Profile Texture) where pixel values represent the fire's color and intensity [S1, unofficial].

### Data Structures
*   **Noise Space**: A coordinate system $(x, y, t)$ where $x$ and $y$ are spatial dimensions and $t$ is time.
*   **Fire Profile Texture**: A 2D image buffer storing RGBA values. The horizontal axis represents the radial distance from the fire center, and the vertical axis represents the height along the fire [S1, unofficial].

### Steps
1.  **Generate Noise Fields**:
    *   Generate a Perlin noise field for turbulent detail.
    *   Generate a Voronoi noise field for cellular structure.
2.  **Scale and Offset Noise Space**:
    *   Scale the horizontal ($x$) and vertical ($y$) axes of the noise space by the fire's radius and length, respectively.
    *   Multiply the scaled noise coordinates by an application-specific frequency factor to adjust the level of detail.
    *   Add a time offset to the vertical axis (e.g., $-time$) to create an upward flow effect.
    *   Add a unique constant offset to the noise position for each fire instance to ensure uniqueness.
3.  **Combine Noise Functions**:
    *   Multiply the Voronoi noise texture by the Perlin noise texture.
4.  **Modify UV Coordinates**:
    *   Interpolate the product of the combined noises with a standard UV texture to create a modified UV coordinate. This step warps the sampling coordinates based on the noise values to create organic, fire-like variations.
5.  **Sample Fire Profile**:
    *   Sample a single Gaussian blob using the modified UV coordinates to create fire-like density variations.
6.  **Apply Color Gradient**:
    *   Apply a color gradient to the result to give the fire its characteristic orange color. Artists can customize the look by editing the Fire Profile Texture directly.

### Formulas
Not given in the sources. The method relies on interpolating the noise product with UV coordinates and sampling a Gaussian profile, but exact mathematical expressions for the interpolation weights or Gaussian parameters are not provided.

### Parameters
*   **Frequency**: Controls the spatial frequency of micro-level detail. Scaled to world coordinates to eliminate stretching.
*   **Time Offset**: Used to create upward flow; the vertical axis is offset by $-time$.
*   **Instance Offset**: A constant added to the noise position for each fire instance to ensure uniqueness.
*   **Color Gradient**: Defines the color mapping for the fire profile.

### Edge Cases and Pitfalls
*   **Stretching Artifacts**: If the noise space is not dynamically scaled according to the fire's radius and length, enlarging the fire will cause visible stretching artifacts.
*   **Boundary Conditions**: The unit fire volume has specific coordinate ranges. Sampling outside these ranges requires clamping or wrapping logic in the texture lookup.
*   **Precision**: Standard Perlin Noise may cause bottlenecks on GPUs due to chained table lookups; M-Noise is recommended for hardware acceleration.

### Pseudocode
```python
import math

def hash2d(x, y):
    """Simple 2D hash function for noise generation."""
    n = x * 12.9898 + y * 78.233
    return (math.sin(n) * 43758.5453) % 1

def lerp(a, b, t):
    """Linear interpolation."""
    return a + t * (b - a)

def smooth_noise_2d(x, y):
    """Generates a smooth pseudo-random value using linear interpolation."""
    ix, iy = int(math.floor(x)), int(math.floor(y))
    fx, fy = x - ix, y - iy
    # Smoothstep fade function
    fx = fx * fx * (3 - 2 * fx)
    fy = fy * fy * (3 - 2 * fy)
    
    n00 = hash2d(ix, iy)
    n10 = hash2d(ix + 1, iy)
    n01 = hash2d(ix, iy + 1)
    n11 = hash2d(ix + 1, iy + 1)
    
    nx0 = lerp(n00, n10, fx)
    nx1 = lerp(n01, n11, fx)
    return lerp(nx0, nx1, fy)

def generate_noise_2d_fire(width, height, radius, length, time, frequency, burning_speed, instance_offset):
    """
    Generates a 2D fire texture using combined noise functions.
    
    Args:
        width (int): Width of the output texture.
        height (int): Height of the output texture.
        radius (float): Current radius of the fire.
        length (float): Current length of the fire.
        time (float): Current simulation time.
        frequency (float): Application-specific spatial frequency.
        burning_speed (float): Parameter controlling flicker speed.
        instance_offset (float): Unique offset for this fire instance.
        
    Returns:
        list: 2D list of RGB colors representing the fire texture.
    """
    texture = [[(0.0, 0.0, 0.0) for _ in range(width)] for _ in range(height)]
    
    scale_x = radius
    scale_y = length
    
    for y in range(height):
        for x in range(width):
            u = x / width
            v = y / height
            
            noise_x = u * frequency / scale_x
            noise_y = v * frequency / scale_y
            
            noise_y -= time * burning_speed
            noise_y += instance_offset
            
            perlin_val = smooth_noise_2d(noise_x, noise_y)
            voronoi_val = smooth_noise_2d(noise_x * 1.5, noise_y * 1.5)
            
            combined_noise = perlin_val * voronoi_val
            
            modified_u = u + combined_noise * 0.1
            modified_v = v + combined_noise * 0.1
            
            radial_dist = math.sqrt(modified_u**2 + modified_v**2)
            gaussian_blob = math.exp(-radial_dist**2 / 0.1)
            
            intensity = gaussian_blob * combined_noise
            r = intensity * 1.0
            g = intensity * 0.5
            b = intensity * 0.1
            
            texture[y][x] = (r, g, b)
            
    return texture
```

## Subtopics

### [Real-Time Procedural Volumetric Fire](16933-real-time-procedural-volumetric-fire.md)
A method for producing real-time procedural volumetric fire using hardware acceleration, Improved Perlin Noise, and a realistic particle simulation to create vibrant volumetric fire with bi-directional environmental macro-interactivity. It constructs an arbitrarily detailed lattice around a central curve, slicing it into quadrilateral planar polygons rendered into a unit fire volume. Unlike sprite systems, it avoids common artifacts, and unlike true photo-realistic fire simulation, it avoids high computational costs. It builds on Noise-based 2D Fire by extending the 2D noise application into a 3D volumetric lattice structure. Choose this variant when a full 3D volumetric lattice with environmental interaction is required instead of a flat 2D profile.

## Operating characteristics
*   **Time Complexity**: The generation is performed per-pixel in a pixel shader, making it $O(N)$ where $N$ is the number of pixels in the texture. The complexity of the noise function is constant per pixel.
*   **Memory Complexity**: $O(W \times H)$ for the 2D texture storage, where $W$ and $H$ are the texture dimensions.
*   **Performance**: Real-time performance is achieved through hardware acceleration (GPU shaders) [S1, unofficial]. M-Noise is specifically designed to avoid bottlenecks associated with standard Perlin Noise on GPUs.
*   **Strengths**:
    *   Real-time rendering capability.
    *   Artist-controllable appearance via 2D texture editing.
    *   Dynamic scaling without stretching artifacts.
    *   Supports bi-directional environmental interaction.
*   **Limitations**:
    *   Not physically accurate; relies on artistic approximation.
    *   Requires a 3D lattice construction for the final volume, adding complexity to the rendering pipeline.
*   **When to Use**: Real-time applications (games, interactive simulations) where visual appeal and performance are prioritized over physical accuracy.
*   **When Not to Use**: Offline rendering requiring photo-realistic fire simulation, or scenes where physical accuracy is critical.

## Background
The method was developed by Fuller, Krishnan, Mahrous, Hamann, and Joy at UC Davis, as presented in their 2006 paper "Real-Time Procedural Volumetric Fire" [S1, unofficial]. It was designed to address the limitations of sprite-based fire systems (artifacts) and physical simulations (computational cost) [S1, unofficial]. The approach leverages "Improved Perlin Noise" and a particle simulation to create vibrant, interactive fire [S1, unofficial]. Subsequent variations and implementations have been documented in unofficial reports and GitHub projects, such as the "Fire Simulation and Rendering" project [S1, unofficial].
