# Noise-based 2D Fire

Also called: 2D Fire Texture Generation, Voronoi-Perlin Fire Noise

## Overview
Noise-based 2D Fire is a procedural technique for generating the base density and color texture of volumetric fire, serving as the input for constructing 3D cylindrical fire volumes [S1, unofficial]. It distinguishes itself from sprite-based systems by providing a continuous, artifact-free texture that supports dynamic scaling, and from photo-realistic fluid simulations by offering real-time performance with artist-controllable aesthetics [S1, unofficial]. The method combines multiple noise functions to create turbulent micro-details, which are then mapped onto a 2D profile to drive the visual appearance of the flame [S1, unofficial].

## How it works
The method generates a 2D texture that defines the fire's shape, color, and intensity, which is subsequently used to map colors onto a 3D lattice surrounding a central curve [S1, unofficial]. The generation involves creating noise fields, combining them, and applying a color gradient [S1, unofficial].

### Inputs and Outputs
*   **Inputs**: Voronoi noise texture, Perlin noise texture, a standard UV texture for interpolation, and a color gradient definition [S1, unofficial].
*   **Outputs**: A 2D color texture where pixel values represent the fire's color and intensity [S1, unofficial].

### Data Structures
*   **Noise Space**: A coordinate system $(x, y, t)$ where $x$ and $y$ are spatial dimensions and $t$ is time [G].
*   **Fire Profile Texture**: A 2D image buffer storing RGBA values, where the horizontal axis represents radial distance from the fire center and the vertical axis represents height along the fire [S1, unofficial].

### Steps
1.  **Generate Noise Fields**: Generate a Perlin noise field for turbulent detail and a Voronoi noise field for cellular structure [S1, unofficial].
2.  **Combine Noise Functions**: Multiply the Voronoi noise texture by the Perlin noise texture [S1, unofficial].
3.  **Modify UV Coordinates**: Interpolate the product of the combined noises with a standard UV texture to create a modified UV coordinate [S1, unofficial].
4.  **Sample Fire Profile**: Sample a single Gaussian blob using the modified UV coordinates to create fire-like variations [S1, unofficial].
5.  **Apply Color Gradient**: Apply a color gradient to the result to give the fire its characteristic orange color [S1, unofficial].

### Pseudocode
```python
import math

def lerp(a, b, t):
    return a + t * (b - a)

def generate_perlin_noise(width, height):
    # Standard 2D Perlin noise generation for turbulent detail [G]
    return [[0.0 for _ in range(width)] for _ in range(height)]

def generate_voronoi_noise(width, height):
    # Standard 2D Voronoi noise generation for cellular structure [G]
    return [[0.0 for _ in range(width)] for _ in range(height)]

def generate_2d_fire(width, height, uv_texture, color_gradient):
    # Step 1: Generate noise textures
    perlin_tex = generate_perlin_noise(width, height)
    voronoi_tex = generate_voronoi_noise(width, height)
    
    # Step 2: Multiply the Voronoi noise texture by the Perlin noise texture
    combined_noise = [[perlin_tex[y][x] * voronoi_tex[y][x] for x in range(width)] for y in range(height)]
    
    # Step 3: Interpolate the product of the combined noises with a standard UV texture
    # to create a modified UV coordinate. Exact interpolation weights not given [S1, unofficial]
    modified_uv = [[lerp(uv_texture[y][x], combined_noise[y][x], 0.5) for x in range(width)] for y in range(height)]
    
    # Step 4: Sample a single Gaussian blob using the modified UV coordinates
    # to create fire-like variations. Gaussian parameters not given [S1, unofficial]
    fire_density = [[math.exp(-(modified_uv[y][x][0]**2 + modified_uv[y][x][1]**2)) for x in range(width)] for y in range(height)]
    
    # Step 5: Apply a color gradient to give an orange color to the result
    result = [[color_gradient.sample(fire_density[y][x]) for x in range(width)] for y in range(height)]
    return result
```

## Subtopics

### [Real-Time Procedural Volumetric Fire](16933-real-time-procedural-volumetric-fire.md)
A method for producing real-time procedural volumetric fire using hardware acceleration, Improved Perlin Noise, and a realistic particle simulation to create vibrant volumetric fire with bi-directional environmental macro-interactivity. It constructs an arbitrarily detailed lattice around a central curve, slicing it into quadrilateral planar polygons rendered into a unit fire volume. Unlike sprite systems, it avoids common artifacts, and unlike true photo-realistic fire simulation, it avoids high computational costs. It builds on Noise-based 2D Fire by extending the 2D noise application into a 3D volumetric lattice structure. Choose this variant when a full 3D volumetric lattice with environmental interaction is required instead of a flat 2D profile.

## Operating characteristics
*   **Time Complexity**: The generation is performed per-pixel in a pixel shader, making it $O(N)$ where $N$ is the number of pixels in the texture [S1, unofficial].
*   **Memory Complexity**: $O(W \times H)$ for the 2D texture storage, where $W$ and $H$ are the texture dimensions [S1, unofficial].
*   **Performance**: Real-time performance is achieved through hardware acceleration (GPU shaders) [S1, unofficial].
*   **Strengths**: Real-time rendering capability, artist-controllable appearance via 2D texture editing, and dynamic scaling without stretching artifacts [S1, unofficial].
*   **Limitations**: Not physically accurate, relies on artistic approximation, and requires a 3D lattice construction for the final volume [S1, unofficial].
*   **When to Use**: Real-time applications (games, interactive simulations) where visual appeal and performance are prioritized over physical accuracy [S1, unofficial].
*   **When Not to Use**: Offline rendering requiring photo-realistic fire simulation, or scenes where physical accuracy is critical [S1, unofficial].
