# Perlin-Worley Noise for Cloud Density

Also called: Base Density Noise, Base Density Noise Calculation, Perlin-Worley Noise

## Overview
This method builds on [Procedural Noise Functions](1799-procedural-noise-functions.md) to generate the base density field for volumetric cloud rendering by combining the structural continuity of Perlin noise with the billowy, cellular detail of Worley noise [S2]. It differs from standard gradient-based noise by using Worley noise to modulate the amplitude of Perlin noise, creating organic cloud shapes that retain large-scale connectedness while exhibiting high-frequency billowiness at the edges [S2]. It serves as the primary input for the cloud density calculation in real-time volumetric rendering pipelines [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D texture containing four channels (RGBA) of pre-computed noise values [S2].
*   **Output:** A scalar density value $D$ for a given 3D coordinate $\mathbf{P}$ [S2].

**Data Structures**
The base density noise is stored in a 3D texture with the following layout [S2]:
*   **Red (R) Channel:** Stores the low-frequency Perlin-Worley base noise [S2].
*   **Green (G) Channel:** Stores Worley noise at an increasing frequency [S2].
*   **Blue (B) Channel:** Stores Worley noise at a higher frequency than G [S2].
*   **Alpha (A) Channel:** Stores Worley noise at the highest frequency among the three [S2].
*   **Format:** The texture must be tileable [S1, unofficial]. A typical implementation uses a $128 \times 128 \times 128$ texture, which is small enough for web performance but large enough to hold 2–3 Fractal Brownian Motion (FBM) levels [S1, unofficial].

**Steps**
1.  **Sample Channels:** Retrieve the four noise values at coordinate $\mathbf{P}$ [S2].
2.  **Compute High-Frequency Worley:** Combine the three Worley channels into a single high-frequency detail term $N_{WHF}$ [S2].
3.  **Apply Density Offset:** Add the configurable offset $\delta$ to the base Perlin-Worley value [S2].
4.  **Remap to Base Noise:** Remap the offset Perlin-Worley value from its original range $[0, 1]$ to a new range where the minimum is determined by $N_{WHF}$ and the maximum is $1$ [S2].

**Formulas**
The core remapping operation is defined as [G]:
$$ \text{Remap}(v, \text{oldMin}, \text{oldMax}, \text{newMin}, \text{newMax}) = \frac{v - \text{oldMin}}{\text{oldMax} - \text{oldMin}} \times (\text{newMax} - \text{newMin}) + \text{newMin} $$

Substituting the specific values for the base density calculation [S2]:
$$ D = \frac{(N_{PW} + \delta) - 0}{1 - 0} \times (1 - N_{WHF}) + N_{WHF} $$
$$ D = (N_{PW} + \delta)(1 - N_{WHF}) + N_{WHF} $$

**Parameters**
*   **Density Offset ($\delta$):** A configurable scalar added to the Perlin-Worley value before final remapping [S2].
*   **Worley Weights:** The high-frequency Worley combination uses fixed weights: $w_1 = 0.625$, $w_2 = 0.25$, $w_3 = 0.125$ [S2].

**Edge Cases and Pitfalls**
*   **Precision:** Storing noise in 8-bit channels limits detail to 256 discrete values; 32-bit floating-point formats are recommended for finer resolution [S2].
*   **Tileability:** The 3D texture must be tileable to allow sampling at different frequencies in the shader without visible seams [S1, unofficial].
*   **Resolution:** A $128^3$ texture is considered small for web performance but may lack fine features; it is sufficient for 2–3 FBM levels [S1, unofficial].

**Pseudocode**
```python
def compute_cloud_density(P, texture, density_offset):
    """
    Computes cloud density using Perlin-Worley noise stored in a 3D texture.
    
    Args:
        P: 3D vector (x, y, z) coordinate to sample.
        texture: 3D texture object with .sample(x, y, z) returning (r, g, b, a).
        density_offset: Scalar float added to the base Perlin-Worley value.
        
    Returns:
        float: The final base density value.
    """
    # 1. Sample the four channels
    r, g, b, a = texture.sample(P.x, P.y, P.z)
    
    # 2. Compute High-Frequency Worley (N_WHf)
    # Weights: 0.625, 0.25, 0.125
    n_whf = 0.625 * g + 0.25 * b + 0.125 * a
    
    # 3. Apply density offset to Perlin-Worley (R channel)
    n_pw = r + density_offset
    
    # 4. Remap: [0, 1] -> [n_whf, 1]
    # Formula: (n_pw - 0) / (1 - 0) * (1 - n_whf) + n_whf
    density = n_pw * (1.0 - n_whf) + n_whf
    
    return density
```

## Operating characteristics
*   **Time and Memory Complexity:** Memory scales linearly with texture resolution and channel count (4 channels per voxel). Time complexity is $O(1)$ per sample, consisting of a single 3D texture lookup and simple arithmetic [S1, unofficial][S2].
*   **Measured Performance:** The method is efficient enough for real-time rendering, particularly on web platforms where texture size is constrained [S1, unofficial].
*   **Scaling:** Higher detail is achieved by sampling the tileable texture at increased frequencies in the shader rather than generating larger textures [S1, unofficial].
*   **Strengths:** Perlin provides structural continuity, while Worley adds organic billowiness [S2].
*   **Limitations:** 8-bit channel storage limits precision to 256 discrete values, and the method relies on pre-computed textures requiring offline generation or complex runtime pipelines [S2].
*   **When to Use:** Ideal for real-time volumetric cloud rendering where performance is critical and organic, billowy shapes are desired [S1, unofficial][S2].
*   **When Not to Use:** Unsuitable for offline rendering requiring maximum photorealistic detail or when dynamic, non-tileable noise is required [S2].

## Background
The technique originates from the Nubis cloud rendering engine used by Guerrilla Games [S2]. It is documented in a tutorial repository [S2] and discussed in the context of efficient volumetric clouds for web platforms [S1, unofficial]. The approach leverages Fractal Brownian Motion (FBM) to combine noise frequencies, a standard technique in procedural generation [S2].
