# Gray-Scott Reaction-Diffusion

Also called: Gray-Scott Reaction-Diffusion Simulation, Reaction-Diffusion System, Turing Patterns Simulation

## Overview
The Gray-Scott model is a 3D reaction-diffusion system that simulates the interaction of two chemical species, $U$ and $V$, to generate organic, self-organizing patterns such as spots, stripes, and coral-like structures [S1, S2, unofficial]. It solves the problem of generating complex, naturalistic volumetric textures by replacing standard white noise with Turing patterns, which provide smoother, large-scale structures better suited for representing tensor fields or biological materials [S1, S2, unofficial]. Unlike its sibling [Turing Reaction-Diffusion Noise Generation](12185-turing-reaction-diffusion-noise-generation.md), which focuses on initial noise generation for tensor fields, the Gray-Scott method explicitly implements the feed-kill dynamics of the Gray-Scott equations to produce distinct morphological regimes based on parameter tuning [S1, S2, unofficial].

## How it works
The method simulates the evolution of two concentration fields, $U$ (substrate) and $V$ (catalyst), on a cubic grid using explicit Euler time integration and a 7-point stencil finite difference approximation for the Laplacian operator [S1, unofficial].

### Inputs and Outputs
**Inputs:**
- `size`: Integer, the dimension of the cubic grid ($N \times N \times N$).
- `config`: Object containing simulation parameters:
  - `feed` ($f$): Feed rate of chemical $U$.
  - `kill` ($k$): Kill rate of chemical $V$.
  - `du` ($D_u$): Diffusion coefficient for $U$.
  - `dv$ ($D_v$): Diffusion coefficient for $V$.
  - `dt` ($\Delta t$): Time step size.
  - `dx` ($\Delta x$): Grid spacing.
  - `boundary`: String, either `'periodic'` or `'neumann'` (default).
- `initial_state`: Optional initial concentrations for $U$ and $V$. If not provided, defaults are assumed (typically $U=1, V=0$ with small perturbations, though specific initialization is not detailed in sources [S1, S2, unofficial]).

**Outputs:**
- `u`: Final concentration field of chemical $U$ (Float32Array).
- `v`: Final concentration field of chemical $V$ (Float32Array).
- `byte_buffer`: Uint8Array of length $size^3$, where each element is the 8-bit representation of $V$ scaled to $[0, 255]$.
- `metrics`: Object containing `max`, `avg`, `active` (count where $V \ge threshold$), and performance data.

### Data Structures
1.  **Field Arrays**: Four `Float32Array` of length $count = size^3$:
    -   `u`: Current concentration of $U$.
    -   `v`: Current concentration of $V$.
    -   `nextU`: Temporary storage for updated $U$.
    -   `nextV`: Temporary storage for updated $V$.
2.  **Neighbor Arrays**: Two `Int32Array` of length $size$:
    -   `neighborMinus`: Precomputed indices for the negative direction (left/down/back).
    -   `neighborPlus`: Precomputed indices for the positive direction (right/up/front).
3.  **Output Buffer**: `Uint8Array` of length $count$ for visualization.

### Parameters
-   $f$ (`config.feed`): Typical usage `Number(config.feed)`.
-   $k$ (`config.kill`): Typical usage `Number(config.kill)`.
-   $D_u$ (`config.du`): Typical usage `Number(config.du)`.
-   $D_v$ (`config.dv`): Typical usage `Number(config.dv)`.
-   $\Delta t$ (`config.dt`): Typical usage `Number(config.dt)`.
-   $\Delta x$ (`config.dx`): Retrieved via `currentDx()`, which returns `Math.max(1e-6, Number(config?.dx) || LEGACY_DX)`.
-   Boundary: `'periodic'` or `'neumann'`.

### Formulas
The Laplacian operator $\nabla^2$ is approximated using the 7-point stencil:
$$ \nabla^2 C = \frac{C_{x-\Delta x} + C_{x+\Delta x} + C_{y-\Delta y} + C_{y+\Delta y} + C_{z-\Delta z} + C_{z+\Delta z} - 6C_{x,y,z}}{\Delta x^2} $$

Let $invDx2 = 1 / (\Delta x \cdot \Delta x)$.

For a cell at index $i$ corresponding to coordinates $(x, y, z)$:
1.  **Laplacian of U**:
    $$ lapU = (u[x_m, y, z] + u[x_p, y, z] + u[x, y_m, z] + u[x, y_p, z] + u[x, y, z_m] + u[x, y, z_p] - 6 \cdot u_c) \cdot invDx2 $$
2.  **Laplacian of V**:
    $$ lapV = (v[x_m, y, z] + v[x_p, y, z] + v[x, y_m, z] + v[x, y_p, z] + v[x, y, z_m] + v[x, y, z_p] - 6 \cdot v_c) \cdot invDx2 $$
3.  **Reaction Term**:
    $$ reaction = u_c \cdot v_c \cdot v_c $$
    Where $u_c = u[i]$ and $v_c = v[i]$.

4.  **Update Equations**:
    $$ u_{next}[i] = \text{clamp01}\left( u_c + \Delta t \cdot (D_u \cdot lapU - reaction + f \cdot (1 - u_c)) \right) $$
    $$ v_{next}[i] = \text{clamp01}\left( v_c + \Delta t \cdot (D_v \cdot lapV + reaction - (f + k) \cdot v_c) \right) $$

Where $\text{clamp01}(x) = \max(0, \min(1, x))$.

### Algorithm Steps
1.  **Initialize Neighbor Arrays**:
    -   If `boundary` is `'periodic'`:
        -   `neighborMinus[i] = i - 1` if $i > 0$, else `size - 1`.
        -   `neighborPlus[i] = i + 1` if $i < size - 1$, else `0`.
    -   If `boundary` is `'neumann'` (default):
        -   `neighborMinus[i] = i - 1` if $i > 0$, else `i`.
        -   `neighborPlus[i] = i + 1` if $i < size - 1$, else `i`.
2.  **Compute Inverse Squared Spacing**:
    -   `invDx2 = 1.0 / (dx * dx)`.
3.  **Initialize Fields**:
    -   Allocate `u`, `v`, `nextU`, `nextV` as `Float32Array` of length `size*size*size`.
    -   Initialize with default values (e.g., $U=1, V=0$) or provided initial state. [G] *Note: Specific initialization logic (e.g., random perturbation) is not detailed in sources, but is required for pattern formation.*
4.  **Simulation Loop** (for each time step):
    -   Iterate over all grid coordinates $x, y, z$ from $0$ to $size-1$.
    -   Calculate linear index $i = x + y \cdot size + z \cdot size \cdot size$.
    -   Get neighbor indices:
        -   $x_m = neighborMinus[x]$, $x_p = neighborPlus[x]$
        -   $y_m = neighborMinus[y]$, $y_p = neighborPlus[y]$
        -   $z_m = neighborMinus[z]$, $z_p = neighborPlus[z]$
    -   Calculate neighbor linear indices:
        -   $idx_{xm} = x_m + y \cdot size + z \cdot size \cdot size$
        -   $idx_{xp} = x_p + y \cdot size + z \cdot size \cdot size$
        -   $idx_{ym} = x + y_m \cdot size + z \cdot size \cdot size$
        -   $idx_{yp} = x + y_p \cdot size + z \cdot size \cdot size$
        -   $idx_{zm} = x + y \cdot size + z_m \cdot size \cdot size$
        -   $idx_{zp} = x + y \cdot size + z_p \cdot size \cdot size$
    -   Retrieve current values: $u_c = u[i]$, $v_c = v[i]$.
    -   Compute Laplacians:
        -   $lapU = (u[idx_{xm}] + u[idx_{xp}] + u[idx_{ym}] + u[idx_{yp}] + u[idx_{zm}] + u[idx_{zp}] - 6 \cdot u_c) \cdot invDx2$
        -   $lapV = (v[idx_{xm}] + v[idx_{xp}] + v[idx_{ym}] + v[idx_{yp}] + v[idx_{zm}] + v[idx_{zp}] - 6 \cdot v_c) \cdot invDx2$
    -   Compute Reaction: $reaction = u_c \cdot v_c \cdot v_c$.
    -   Update Next Values:
        -   $nextU[i] = \text{clamp01}(u_c + dt \cdot (du \cdot lapU - reaction + f \cdot (1 - u_c)))$
        -   $nextV[i] = \text{clamp01}(v_c + dt \cdot (dv \cdot lapV + reaction - (f + k) \cdot v_c))$
    -   Swap Buffers:
        -   `u = nextU`, `v = nextV` (or copy values back to `u` and `v` and reuse old arrays as `nextU`/`nextV`).
5.  **Post-Frame Processing**:
    -   Iterate over all cells to compute metrics.
    -   Calculate `max`, `sum`, and `active` count (where $v[i] \ge threshold$).
    -   Convert $v[i]$ to 8-bit integer: `bytes[i] = Math.max(0, Math.min(255, Math.round(v[i] * 255)))`.
    -   Send frame data to main thread (if using Web Workers) with type `'frame'`, including `size`, `stepCount`, `bytes.buffer`, and metrics. Transfer ownership of `bytes.buffer`.

### Pseudocode
```python
def gray_scott_simulation(size, config, num_steps):
    # Parameters
    f = float(config['feed'])
    k = float(config['kill'])
    du = float(config['du'])
    dv = float(config['dv'])
    dt = float(config['dt'])
    dx = max(1e-6, float(config.get('dx', 1.0)))
    boundary = config.get('boundary', 'neumann')
    invDx2 = 1.0 / (dx * dx)
    
    count = size * size * size
    
    # Data Structures
    u = [0.0] * count
    v = [0.0] * count
    nextU = [0.0] * count
    nextV = [0.0] * count
    
    # Initialize Fields [G]
    # Typically U=1.0, V=0.0 with small random perturbation in V for pattern initiation
    for i in range(count):
        u[i] = 1.0
        v[i] = 0.0
        # Example perturbation:
        # if random() < 0.5: v[i] = 0.02
        
    # Neighbor Arrays
    neighborMinus = [0] * size
    neighborPlus = [0] * size
    
    for i in range(size):
        if boundary == 'periodic':
            neighborMinus[i] = (i - 1) % size
            neighborPlus[i] = (i + 1) % size
        else: # neumann
            neighborMinus[i] = max(0, i - 1)
            neighborPlus[i] = min(size - 1, i + 1)
            
    # Simulation Loop
    for step in range(num_steps):
        for z in range(size):
            z_base = z * size * size
            z_m = neighborMinus[z]
            z_p = neighborPlus[z]
            z_m_base = z_m * size * size
            z_p_base = z_p * size * size
            
            for y in range(size):
                y_base = y * size
                y_m = neighborMinus[y]
                y_p = neighborPlus[y]
                y_m_base = y_m * size
                y_p_base = y_p * size
                
                for x in range(size):
                    i = x + y_base + z_base
                    x_m = neighborMinus[x]
                    x_p = neighborPlus[x]
                    
                    # Neighbors
                    idx_xm = x_m + y_base + z_base
                    idx_xp = x_p + y_base + z_base
                    idx_ym = x + y_m_base + z_base
                    idx_yp = x + y_p_base + z_base
                    idx_zm = x + y_base + z_m_base
                    idx_zp = x + y_base + z_p_base
                    
                    uc = u[i]
                    vc = v[i]
                    
                    # Laplacians
                    lapU = (u[idx_xm] + u[idx_xp] + u[idx_ym] + u[idx_yp] + u[idx_zm] + u[idx_zp] - 6 * uc) * invDx2
                    lapV = (v[idx_xm] + v[idx_xp] + v[idx_ym] + v[idx_yp] + v[idx_zm] + v[idx_zp] - 6 * vc) * invDx2
                    
                    # Reaction
                    reaction = uc * vc * vc
                    
                    # Update
                    nextU[i] = max(0.0, min(1.0, uc + dt * (du * lapU - reaction + f * (1 - uc))))
                    nextV[i] = max(0.0, min(1.0, vc + dt * (dv * lapV + reaction - (f + k) * vc)))
                    
        # Swap buffers
        u, nextU = nextU, u
        v, nextV = nextV, v
        
    # Post-processing
    byte_buffer = [0] * count
    max_v = 0.0
    sum_v = 0.0
    active_count = 0
    threshold = 0.1 # Example threshold, not specified in sources
    
    for i in range(count):
        val = v[i]
        byte_buffer[i] = max(0, min(255, round(val * 255)))
        if val > max_v: max_v = val
        sum_v += val
        if val >= threshold: active_count += 1
        
    avg_v = sum_v / count
    
    return u, v, byte_buffer, {'max': max_v, 'avg': avg_v, 'active': active_count}
```

### Edge Cases and Pitfalls
-   **Grid Spacing**: $dx$ must not be zero or negative. The implementation ensures $dx \ge 10^{-6}$ [S1, unofficial].
-   **Field Bounds**: Field values must remain within $[0, 1]$. The `clamp01` function is applied to both $U$ and $V$ updates to prevent numerical instability [S1, unofficial].
-   **Stability**: Explicit Euler integration is conditionally stable. If $dt$ is too large relative to $dx$ and diffusion coefficients, the simulation may diverge. The sources do not specify a stability criterion (e.g., CFL condition) [S1, S2, unofficial].

## Operating characteristics
-   **Time Complexity**: $O(N^3)$ per time step, where $N$ is the grid size. Each cell requires a constant number of operations (6 neighbors, 2 Laplacians, 1 reaction, 2 updates).
-   **Memory Complexity**: $O(N^3)$ for storing the four field arrays (`u`, `v`, `nextU`, `nextV`) and neighbor arrays. For a $512^3$ grid, this is approximately $4 \times 512^3 \times 4$ bytes $\approx 2$ GB for floats, plus overhead.
-   **Measured Performance**:
    -   On CPU (Processing 4.3): A $512 \times 512 \times 512$ grid updates at 200 fps using optimized arrays [S2, unofficial]. *Note: The source specifies 2D grid dimensions (512x512) but the method is 3D. It is unclear if this refers to a 2D slice or a 3D volume. The source states "512x512 grid", which is ambiguous for a 3D method. Given the context of "3D reaction-diffusion system" in [S1, unofficial], it is likely a 2D slice or a typo in the source. However, the method is defined as 3D.*
    -   On GPU (Fragment Shader): The same simulation runs at 4K resolution on modern GPUs [S2, unofficial].
-   **Strengths**: Produces highly organic, complex patterns suitable for camouflage, biological textures, and abstract backgrounds. Efficient on GPUs due to regular memory access patterns.
-   **Limitations**: Explicit Euler integration limits the time step size for stability. High resolution requires significant memory and compute power. Parameter space is large and sensitive; small changes in $f$ and $k$ can lead to drastically different patterns (e.g., spots, stripes, mazes, or extinction) [S1, S2, unofficial].
-   **When to Use**: When organic, self-organizing patterns are desired for volumetric textures, especially for biological or naturalistic materials.
-   **When Not to Use**: When strict physical accuracy of chemical reactions is required (this is a simplified model). When real-time performance on low-end hardware is critical at high resolutions.

## Background
The Gray-Scott model is a mathematical model of a reaction-diffusion system, first proposed by Peter Gray and Scott M. Scott in 1983 [S1, S2, unofficial]. It is a variant of the Turing reaction-diffusion system, which was originally proposed by Alan Turing in 1952 to explain morphogenesis. The Gray-Scott model is particularly notable for its rich variety of patterns, including spots, stripes, and coral-like structures, depending on the feed and kill rates. It has been widely used in computer graphics for generating procedural textures and in demoscene productions for its visual appeal and computational efficiency [S2, unofficial]. The implementation described here is based on an unofficial GitHub repository [S1, unofficial] and a procedural graphics guide [S2, unofficial].
