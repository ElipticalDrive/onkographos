# Procedural Noise Functions

Also called: Procedural Noise, Procedural Textures, Noise Fields

## Overview
Procedural noise functions generate continuous or discrete scalar fields from spatial coordinates without storing explicit geometry or heightmaps, solving the problem of creating organic, non-repetitive, or structured volumetric detail (such as clouds, smoke, terrain, and cellular structures) in real-time rendering [S1, S2, S3, S4, S5, S6, unofficial][S7]. Unlike static texture lookups, these methods evaluate mathematical functions on-the-fly, allowing for infinite resolution and seamless tiling [S1, S3, unofficial]. This family is distinct from [Gradient-based Noise (Perlin/Simplex)](3860-gradient-based-noise-perlin-simplex.md) in that it encompasses not only gradient-interpolated fields but also distance-based cellular patterns, trigonometric periodic structures, and flow-advection techniques [S1, S2, S4, unofficial][S7].

## Shared principles
All procedural noise methods share the core mechanism of mapping a query point $P = (x, y, z)$ to a scalar value $V$ through deterministic mathematical operations, ensuring that nearby points yield similar values (coherence) or structured differences, depending on the variant [S1, S2, S3, S4, S5, S6, unofficial][S7].

1.  **Coordinate Normalization:** Input coordinates are often normalized or wrapped to fit specific grid or periodic structures. For grid-based noise, integer cell coordinates are derived via floor operations, while fractional parts determine interpolation weights or distance vectors [S1, S4, S5, unofficial].
2.  **Hashing and Randomness:** To introduce pseudo-randomness without storing large lookup tables, integer coordinates are hashed into floating-point values. Common hash functions use trigonometric operations (e.g., `sin(dot(p, float2(12.9898, 78.233))) * 43758.5453`) or linear congruential generators to produce uniform random values in $[0, 1]$ or $[-1, 1]$ [S4, unofficial][S7].
3.  **Interpolation and Smoothing:** When using grid-based values, smooth transitions are achieved via Hermite interpolation or polynomial falloff functions (e.g., $3t^2 - 2t^3$) to eliminate visible grid artifacts [S5, unofficial][S7].
4.  **Fractal Brownian Motion (FBM):** Complex detail is often generated by summing multiple octaves of a base noise function at different frequencies and amplitudes: $V = \sum_{i=0}^{n} a_i \cdot \text{noise}(f_i \cdot P)$, where $a_i$ is the amplitude and $f_i$ is the frequency (lacunarity) of octave $i$ [S5, S6, unofficial][S7].
5.  **Domain Warping and Advection:** To simulate motion or turbulence, the input coordinates to the noise function are displaced by another noise field or a flow vector, creating non-linear distortions in the resulting density field [S1, S5, unofficial][S7].

## Subtopics

### [Worley Noise](1726-worley-noise.md)
Worley Noise generates cellular patterns by computing the distance from a query point to the nearest feature points in a grid of pseudo-random locations. It is primarily used for smoke, clouds, and cellular structures. Unlike gradient-based noise, it produces distinct cell boundaries defined by distance metrics (Euclidean, Manhattan, or Chebyshev) rather than interpolated gradients. It differs from Value Noise by relying on spatial proximity to discrete points rather than interpolated grid values.

### [Local Cloud Flow with FlowMap](2258-local-cloud-flow-with-flowmap.md)
This technique simulates small-scale, local turbulence in volumetric clouds by offsetting noise sampling coordinates using a pre-computed 2D flow direction texture. It addresses the problem of static cloud details by introducing spatially varying wind vectors, distinct from global advection. It differs from Global Cloud Flow by using per-pixel texture lookups for flow direction, making it suitable for scenes requiring local turbulence.

### [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md)
This method creates volumetric structures by evaluating trigonometric functions against voxel coordinates to determine occupancy and material properties. It solves the problem of generating deterministic, periodic 3D patterns without storing explicit geometry, relying on real-time evaluation of sine and cosine functions. Unlike gradient-based noise, it generates rigid, repeating wave patterns defined by specific harmonic combinations.

### [2D White Noise Texture Generation](2485-2d-white-noise-texture-generation.md)
This process creates a 2D texture filled with uncorrelated random values, typically used for noise-based effects like SSAO variation, dithering, or fine detail in volumetric rendering. It differs from gradient-based or value noise by providing high-frequency randomness without spatial coherence or smoothness.

### [Vortex Flow Function](2538-vortex-flow-function.md)
The Vortex Flow Function generates gas animation by moving sample points through a static noise space along a helical or rotational path, optionally modified by noise to simulate turbulence. It solves the problem of creating convincing swirling, rising, or rolling gas motion (such as steam, fog, or smoke) without requiring expensive fluid simulation data. It sets itself apart from static procedural volumes by introducing time-dependent spatial deformation, and from other flow methods like Spot Noise by explicitly modeling rotational dynamics around an axis.

### [Spherical Density Ramp with Noise](2610-spherical-density-ramp-with-noise.md)
This is a procedural volume density function that confines gas to a slab region using a spherical distance ramp and an offset table, simulating steam rising from a source. It differs from its parent, Procedural Noise Functions, by adding spatial confinement and vertical falloff to the base turbulence, and from Worley Noise by using a deterministic distance-based ramp rather than cell-based proximity.

### [Spot Noise](2959-spot-noise.md)
A sparse convolution noise with a flexible kernel formulation where a uniform distribution of impulses is convolved with an arbitrary kernel spatially defined.

### [Mandelbulb Fractal Generation](3327-mandelbulb-fractal-generation.md)
Generates a 3D fractal by iteratively applying a polar coordinate power transformation to a complex 3D point.

### [Gradient-based Noise (Perlin/Simplex)](3860-gradient-based-noise-perlin-simplex.md)
Gradient-based noise generates continuous scalar fields by interpolating dot products of random gradient vectors and distance vectors from grid vertices. It solves the problem of generating natural-looking volumetric textures (e.g., clouds, terrain, smoke) that lack the repetitive, uniform appearance of single-layer white noise. It differs from Value Noise by using gradient vectors and dot products rather than scalar values at lattice points, and from Worley Noise by producing smooth, correlated fields rather than cellular patterns.

### [Value Noise](4008-value-noise.md)
Generates pseudo-random, spatially continuous signals by placing random scalars at integer lattice points and smoothly interpolating between them using Hermite interpolation.

### Noise Coordinate Systems
- **Definition:** Tying noise functions to a coordinate system for geometric primitives, requiring smooth and quick transformations in and out of the local space [S1, unofficial].
- **Steps:**
    - For a sphere: Use object space as the noise coordinate space. Transformations are simple matrix multiplications [S1, unofficial].
    - For a curve/spline: Use a coordinate system deforming with the spline. Range is $[0,1]$ along the spline and $[-1,1]$ along the two radius axes. Basis vectors are Tangent (T), Normal (N), and Cross(N, T) [S1, unofficial].
    - For a surface patch: Range is $[0,1]$ along each surface dimension and $[-1,1]$ along the normal. Basis vectors are dP/du, dP/dv, and Normal (N) [S1, unofficial].
- **Pitfall:** Transformations for curves and surfaces are costly compared to spheres, especially for surfaces composed of arbitrary parametric primitives requiring search [S1, unofficial].

### Noise-based 2D Fire
- **Steps:**
    - Multiply Voronoi noise and Perlin noise textures [S2, unofficial].
    - Interpolate the product of the noises with a standard UV texture to create a modified UV coordinate [S2, unofficial].
    - Sample a single Gaussian blob using the modified UV to create fire-like variations [S2, unofficial].
    - Apply a color gradient to give an orange color to the result [S2, unofficial].

### Two-rate Field Generation
- **Steps:**
    - Evaluate continent- and range-wide octaves at lattice nodes and blend them [S4, unofficial].
    - For each level, run a compiled column program instead of walking the octave table [S4, unofficial].
    - Erosion: Erosion octaves step their corners and share steering [S4, unofficial].
- **Pitfall:** Precision: Results must remain bit-exact between CPU and GPU implementations [S4, unofficial].
- **Performance:** Generation speed improved from 41–43 µs per tile to 32–34 µs per tile [S4, unofficial].

### Cloud Noise Generation
- **Definition:** A noise function designed for 3D volumetric clouds that samples a 2D texture slice based on 3D coordinates to generate organic randomness [S5, unofficial].
- **Steps:**
    - Compute integer part `p` and fractional part `f` of the input 3D coordinate `x` [S5, unofficial].
    - Compute smooth interpolation factor `u` using the formula `f * f * (3. - 2. * f)` [S5, unofficial].
    - Calculate 2D UV coordinates by combining `p.xy` with `p.z` scaled by `vec2(37.0, 239.0)` and adding `u.xy` [S5, unofficial].
    - Sample the `uNoise` texture at `(uv + 0.5) / 256.0` with LOD 0.0, returning the `.yx` components [S5, unofficial].
    - Mix the two texture components `tex.x` and `tex.y` using `u.z` as the weight, then scale the result to the range $[-1, 1]$ by multiplying by 2.0 and subtracting 1.0 [S5, unofficial].
- **Code:**
    ```glsl
    float noise(vec3 x ) {
      vec3 p = floor(x);
      vec3 f = fract(x);
      vec2 u = f * f * (3. - 2. * f);
      vec2 uv = (p.xy + vec2(37.0, 239.0) * p.z) + u.xy;
      vec2 tex = textureLod(uNoise,(uv + 0.5) / 256.0, 0.0).yx;
      return mix( tex.x, tex.y, u.z ) * 2.0 - 1.0;
    }
    ```

### Volumetric Density Generation
- **Definition:** Generates a patchy volumetric density field from noise by applying a power function and a threshold [S6, unofficial].
- **Steps:**
    - Compute noise: `noise = fbm(pos, 3.0, 2)` [S6, unofficial].
    - Remap from $[-1, 1]$ to $[0, 1]$: `noise = noise * 0.5 + 0.5` [S6, unofficial].
    - Apply power function with exponent 2.5 to create sparse regions near 0: `density = pow(noise, 2.5)` [S6, unofficial].
    - Threshold: if `density < 0.15`, set `density = 0.0` [S6, unofficial].
    - Scale by `base_density` (default 0.8) and clamp to $[0, 1]$ [S6, unofficial].

## Background
Procedural noise functions originated in the field of computer graphics for texture synthesis and terrain generation. Ken Perlin introduced Perlin Noise in 1985 for the movie *Tron* to generate procedural textures [S1, S2, unofficial, S4, unofficial, S10, unofficial]. Simplex Noise was later developed by Perlin in 2001 to address artifacts and computational inefficiencies in high dimensions [S1, S2, S4, unofficial]. Worley Noise, named after Steven Worley, was introduced in 1996 for generating cellular patterns [S1, S2, S4, unofficial][S7]. These methods have become standard in volume rendering for creating natural-looking effects such as clouds, smoke, and fire, as detailed in production fundamentals [S1, S2, S3, S4, S5, S6, unofficial][S7].
