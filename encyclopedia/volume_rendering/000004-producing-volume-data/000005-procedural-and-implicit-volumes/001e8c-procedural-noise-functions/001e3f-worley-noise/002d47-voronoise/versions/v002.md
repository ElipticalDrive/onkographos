# Voronoise

Also called: Voronoi-Noise Hybrid
## Overview
Voronoise is a procedural noise function that unifies value noise and Voronoi cellular patterns through a single interpolation parameter [S1]. It solves the problem of needing distinct noise types for continuous textures and cellular structures by providing a smooth transition between them [S1]. Unlike standard Worley noise which only returns distance metrics, Voronoise returns a continuous scalar value suitable for fractal Brownian motion (FBM) accumulation, distinguishing it from its parent [1726-worley-noise.md] and sibling [2982-animated-worley-noise-texture-generation.md] [S1].

## How it works
**Inputs:**
- `p`: Input coordinate (`vec2` or `vec3`) [S1].
- `u`: Interpolation parameter. `u=0` yields pure value noise; `u=1` yields pure Voronoi pattern [S1].
- `v`: Smoothness parameter. `v=0` yields sharp cells; `v=1` yields smooth noise [S1].

**Outputs:**
- A scalar float value [S1].

**Data Structures:**
- `hash32(p)`: A hash function mapping integer coordinates to a pseudo-random `vec3` [S1].
- `smoothstep(edge0, edge1, x)`: A standard smooth interpolation function [G].

**Steps:**
1. Calculate the exponent `k` based on smoothness `v`:
   $$ k = 1.0 + 63.0 \cdot (1.0 - v)^6 $$
2. Decompose input `p` into integer part `i` and fractional part `f`:
   $$ i = \lfloor p \rfloor $$
   $$ f = p - i $$
3. Initialize accumulator `a` to a zero `vec2` [S1].
4. Iterate over a 5x5 grid of lattice offsets `g` ranging from -2 to 2 in both dimensions:
   a. Compute hash vector `o` for lattice point `i + g`, scaling its x and y components by `u` while leaving z at 1.0:
      $$ o = \text{hash32}(i + g) \cdot (u, u, 1.0) $$
   b. Compute distance vector `d` from the fractional coordinate `f` to the perturbed lattice point:
      $$ d = g - f + o_{xy} $$
      where $o_{xy}$ are the x and y components of `o` [S1].
   c. Compute weight `w` using the length of `d`:
      $$ w = (1.0 - \text{smoothstep}(0.0, 1.414, \|d\|))^k $$
      The threshold 1.414 corresponds to $\sqrt{2}$, the distance to the diagonal neighbor in a unit grid [S1].
   d. Accumulate weighted hash values into `a`:
      $$ a += (o_z \cdot w, w) $$
      where $o_z$ is the z-component of `o` [S1].
5. Return the weighted average:
   $$ \text{result} = \frac{a_x}{a_y} $$

**Pseudocode:**
```python
def voronoise(p: vec2, u: float, v: float) -> float:
    # Calculate exponent k for smoothness control
    k = 1.0 + 63.0 * pow(1.0 - v, 6.0)
    
    # Decompose coordinate
    i = floor(p)
    f = fract(p)
    
    # Accumulator for weighted sum
    a = vec2(0.0)
    
    # Iterate over 5x5 neighborhood
    for y in range(-2, 3):
        for x in range(-2, 3):
            g = vec2(float(x), float(y))
            
            # Hash lattice point and scale by u
            o = hash32(i + g) * vec3(u, u, 1.0)
            
            # Distance from fractional part to perturbed lattice point
            d = g - f + vec2(o.x, o.y)
            
            # Weight calculation
            dist = length(d)
            s = smoothstep(0.0, 1.414, dist)
            w = pow(1.0 - s, k)
            
            # Accumulate: x component is hash z * weight, y component is weight
            a += vec2(o.z * w, w)
            
    # Return weighted average
    return a.x / a.y

def hash32(p: vec2) -> vec3:
    # Implementation from [S1]
    p3 = fract(vec3(p.xyx) * vec3(0.1031, 0.1030, 0.0973))
    p3 += dot(p3, p3.yxz + 33.33)
    return fract((p3.xxy + p3.yzz) * p3.zyx)

def smoothstep(edge0: float, edge1: float, x: float) -> float:
    # Standard smooth interpolation [G]
    t = clamp((x - edge0) / (edge1 - edge0), 0.0, 1.0)
    return t * t * (3.0 - 2.0 * t)
```

**Edge Cases and Pitfalls:**
- Division by zero: If `a.y` is zero, the result is undefined. This occurs if no lattice points contribute weight (e.g., if `k` is extremely large and `v` is 0, causing weights to vanish outside the immediate cell) [G]. Guard against `a.y < epsilon` before division.
- Precision: The hash function uses floating-point arithmetic which may vary across platforms if not standardized. The source uses a specific sin-free hash [S1].

### Metallic Flake Procedural Layer
A procedural sparkle layer for metallic paints using 3D Voronoi cells to distribute flakes with varying density, size, orientation, and color [S2, unofficial]. It generates 3D Voronoi cells to determine flake positions, assigns properties (density, size, orientation spread, color) to each flake, and replaces the base BSDF lobe under a clear coat with a narrow GGX flake lobe [S2, unofficial]. This variant applies the Voronoi structure to micro-facet distribution rather than scalar noise interpolation [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample, requiring exactly 25 hash lookups and distance calculations due to the fixed 5x5 grid [S1, G].
- **Memory Complexity:** $O(1)$ auxiliary memory [G].
- **Strengths:** Provides a continuous transition between value noise and Voronoi patterns, allowing for organic cellular structures that retain the smoothness of value noise [S1]. Suitable for FBM accumulation due to its scalar output [S1].
- **Limitations:** The 5x5 grid is computationally expensive compared to simpler noise functions. The interpolation parameter `u` requires careful tuning to avoid discontinuities if derivatives are needed [G].
- **When to use:** When a texture requires both cellular structure and smooth, continuous variation, such as in organic materials or procedural terrain blending [G].
- **When not to use:** When strict Voronoi cell boundaries are required without smoothing, or when performance is critical and a smaller neighborhood is acceptable [G].

## Background
Voronoise was introduced as part of a unified framework for procedural noise functions, specifically designed to bridge the gap between value noise and Voronoi patterns [S1]. It is documented in the MiniMax-AI skills repository [S1]. The method leverages the properties of hash functions and weighted averaging to create a hybrid noise that can be smoothly interpolated between two distinct visual regimes [S1].
