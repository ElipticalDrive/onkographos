# Voronoise

Also called: Voronoi-Noise Hybrid
## Overview
Voronoise is a procedural noise function that unifies value noise and Voronoi cellular patterns through a single interpolation parameter [S1]. It solves the problem of needing distinct noise types for continuous textures and cellular structures by providing a smooth transition between them [S1]. Unlike standard Worley noise which only returns distance metrics, Voronoise returns a continuous scalar value suitable for fractal Brownian motion (FBM) accumulation, distinguishing it from its parent [1726-worley-noise.md] and sibling [2982-animated-worley-noise-texture-generation.md].

## How it works
**Inputs:**
- `p`: Input coordinate (vec2 or vec3).
- `u`: Interpolation parameter. `u=0` yields pure value noise; `u=1` yields pure Voronoi pattern [S1].
- `v`: Smoothness parameter. `v=0` yields sharp cells; `v=1` yields smooth noise [S1].

**Outputs:**
- A scalar float value in the range [0, 1].

**Data Structures:**
- `hash32(p)`: A hash function mapping integer coordinates to a pseudo-random vector. For 2D input `p`, it returns a `vec3` [S1].
- `smoothstep(edge0, edge1, x)`: Standard smooth interpolation function [S1].

**Steps:**
1. Calculate the exponent `k` based on smoothness `v`:
   $$ k = 1.0 + 63.0 \cdot (1.0 - v)^6 $$
2. Decompose input `p` into integer part `i` and fractional part `f`:
   $$ i = \lfloor p \rfloor $$
   $$ f = p - i $$
3. Initialize accumulator `a` to zero vector [S1].
4. Iterate over a 5x5 grid of lattice offsets `g` ranging from -2 to 2 in both dimensions:
   a. Compute hash vector `o` for lattice point `i + g`:
      $$ o = \text{hash32}(i + g) $$
      Scale `o` such that its x and y components are multiplied by `u`, and z remains 1.0. Note: The source code applies `vec3(u, u, 1.0)` to the hash result [S1].
   b. Compute distance vector `d` from the fractional coordinate `f` to the perturbed lattice point:
      $$ d = g - f + o_{xy} $$
      where $o_{xy}$ are the x and y components of `o`.
   c. Compute weight `w` using the length of `d`:
      $$ w = (1.0 - \text{smoothstep}(0.0, 1.414, \|d\|))^k $$
      The threshold 1.414 corresponds to $\sqrt{2}$, the distance to the diagonal neighbor in a unit grid [S1].
   d. Accumulate weighted hash values into `a`:
      $$ a += \text{vec2}(o_z \cdot w, w) $$
      where $o_z$ is the z-component of `o`.
5. Return the weighted average:
   $$ \text{result} = \frac{a_x}{a_y} $$

**Pseudocode:**
```python
def voronoise(p: vec2, u: float, v: float) -> float:
    # Calculate exponent k for smoothness control
    k = 1.0 + 63.0 * pow(1.0 - v, 6.0)
    
    # Decompose coordinate
    i = floor(p)
    f = fract(p)
    
    # Accumulator for weighted sum
    a = vec2(0.0)
    
    # Iterate over 5x5 neighborhood
    for y in range(-2, 3):
        for x in range(-2, 3):
            g = vec2(float(x), float(y))
            
            # Hash lattice point
            o = hash32(i + g)
            
            # Apply interpolation parameter u to spatial components
            # Source code: hash32(i + g) * vec3(u, u, 1.0)
            # This implies the hash output is scaled. 
            # Assuming hash32 returns vec3, we scale x,y by u, keep z as 1.0
            o_scaled = vec3(o.x * u, o.y * u, o.z)
            
            # Distance from fractional part to perturbed lattice point
            d = g - f + vec2(o_scaled.x, o_scaled.y)
            
            # Weight calculation
            # smoothstep(0.0, 1.414, length(d))
            # 1.414 is approx sqrt(2)
            dist = length(d)
            s = smoothstep(0.0, 1.414, dist)
            w = pow(1.0 - s, k)
            
            # Accumulate: x component is hash z * weight, y component is weight
            a += vec2(o_scaled.z * w, w)
            
    # Return weighted average
    return a.x / a.y

def hash32(p: vec2) -> vec3:
    # Implementation from [S1]
    p3 = fract(vec3(p.xyx) * vec3(0.1031, 0.1030, 0.0973))
    p3 += dot(p3, p3.yxz + 33.33)
    return fract((p3.xxy + p3.yzz) * p3.zyx)
```

**Edge Cases and Pitfalls:**
- Division by zero: If `a.y` is zero, the result is undefined. This occurs if no lattice points contribute weight (e.g., if `k` is extremely large and `v` is 0, causing weights to vanish outside the immediate cell). [G] Guard against `a.y < epsilon`.
- Precision: The hash function uses floating-point arithmetic which may vary across platforms if not standardized. The source uses a specific sin-free hash [S1].

### Metallic Flake Procedural Layer
A procedural sparkle layer for metallic paints using 3D Voronoi cells to distribute flakes with varying density, size, orientation, and color [S2, unofficial]. It generates 3D Voronoi cells to determine flake positions, assigns properties (density, size, orientation spread, color) to each flake, and replaces the base BSDF lobe under a clear coat with a narrow GGX flake lobe [S2, unofficial]. This variant applies the Voronoi structure to micro-facet distribution rather than scalar noise interpolation.

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample, but with a constant factor of 25 hash lookups and distance calculations (5x5 grid).
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Performance:** The 5x5 grid is larger than the 3x3 grid often used in standard Worley noise, increasing computational cost but improving smoothness and reducing artifacts [S1].
- **Strengths:** Provides a continuous transition between value noise and Voronoi patterns, allowing for organic cellular structures that retain the smoothness of value noise [S1]. Suitable for FBM accumulation due to its scalar output [S1].
- **Limitations:** The 5x5 grid is computationally expensive compared to simpler noise functions. The interpolation parameter `u` requires careful tuning to avoid discontinuities if derivatives are needed.
- **When to use:** When a texture requires both cellular structure and smooth, continuous variation, such as in organic materials or procedural terrain blending.
- **When not to use:** When strict Voronoi cell boundaries are required without smoothing, or when performance is critical and a smaller neighborhood is acceptable.

## Background
Voronoise was introduced as part of a unified framework for procedural noise functions, specifically designed to bridge the gap between value noise and Voronoi patterns [S1]. It is documented in the MiniMax-AI skills repository [S1]. The method leverages the properties of hash functions and weighted averaging to create a hybrid noise that can be smoothly interpolated between two distinct visual regimes [S1].
