# Worley Noise

Also called: F1 Noise, Voronoi Noise, Cellular Noise, Cellular Worley noise, Voronoi F1 distance noise, Voronoï F1 distance noise

## Overview
Worley Noise is a procedural noise generation technique that creates cellular patterns by computing the distance from a query point to the nearest feature point in a grid of pseudo-random locations [S1, S2, S4, S7, unofficial]. It is primarily used to generate volumetric density and detail for effects like smoke, clouds, and cellular structures [S1, S7, unofficial]. Unlike gradient-based noise [Gradient-based Noise (Perlin/Simplex)](3860-gradient-based-noise-perlin-simplex.md) which produces smooth, flowing variations, Worley Noise produces distinct, cell-like boundaries defined by distance metrics [S2, S7, unofficial]. It differs from Value Noise [Value Noise](4008-value-noise.md) by relying on spatial proximity to discrete points rather than interpolated grid values [S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- Query point $P = (x, y, z)$ in 3D space [S4, unofficial].
- Cell size (grid resolution) defining the spacing of the feature point grid [S1, S5, unofficial].
- Distance metric: Euclidean, Manhattan, or Chebyshev [S2, unofficial].
- Combination method: D0 (closest), D1_D0 (second closest minus closest), or D2_D0 [S2, unofficial].
- Amplitude scaling factor [S2, unofficial].

**Outputs:**
- A scalar noise value representing the cellular pattern intensity [S2, S3, unofficial].

### Data Structures
**Feature Point Buffer:**
- A structured buffer storing random feature points [S1, unofficial].
- **2D Layout:** Stride `sizeof(float) * 2`. Contains $(x, y)$ coordinates in $[0, 1]$ [S1, unofficial].
- **3D Layout:** Stride `sizeof(float) * 3`. Contains $(x, y, z)$ coordinates in $[0, 1]$ [S1, unofficial].
- **Generation:** Points are generated by dividing the spatial extent by the cell size to determine the count, then filling the buffer with random floats [S1, unofficial].

**Distance Array:**
- A vector storing distances to the $N$ closest feature points found so far [S2, unofficial].
- **Layout:** `Vector3` (or similar array) initialized to `{Infinity, Infinity, ...}` [S2, unofficial].
- Index 0 holds the distance to the closest point ($d_0$), Index 1 to the second closest ($d_1$), etc. [S2, unofficial].

### Hashing Function
To avoid storing all feature points in memory for large volumes, feature points are often generated on-the-fly using a hash function from integer cell coordinates [S4, S6, unofficial].

**Hash Formula (3D):**
Given integer cell coordinates $(ix, iy, iz)$:
1. Calculate intermediate value:
   $$ x = (ix \cdot 127.1 + iy \cdot 311.7 + iz \cdot 74.7) \% 289.0 $$
2. Compute random component:
   $$ x = \sin(x) \cdot 43758.5453 $$
   $$ rx = x - \lfloor x \rfloor $$
3. Repeat for $y$ and $z$ using coefficients:
   - $y$: $269.5, 183.3, 246.1$
   - $z$: $113.5, 271.9, 124.6$
   - Resulting vector $[rx, ry, rz] \in [0, 1]^3$ [S4, unofficial].

*Note: Alternative 2D hash using `sin(dot(cell, float2(12.9898, 78.233))) * 43758.5453` is also cited [S6, unofficial].*

### Algorithm Steps
1. **Normalize Coordinates:** Convert world position to cell space:
   $$ u = \frac{x}{\text{cellSize}}, \quad v = \frac{y}{\text{cellSize}}, \quad w = \frac{z}{\text{cellSize}} $$
   [S5, unofficial]

2. **Identify Base Cell:** Determine the integer cell containing the query point:
   $$ \text{cellX} = \lfloor u \rfloor, \quad \text{cellY} = \lfloor v \quad \text{cellZ} = \lfloor w \rfloor $$
   [S5, unofficial]

3. **Initialize Distance Tracking:** Set minimum distance to infinity or a large value [S5, unofficial]. Initialize distance array for multiple closest points if using D1_D0 or D2_D0 [S2, unofficial].

4. **Iterate Neighborhood:** Loop over neighboring cells to find the nearest feature point.
   - **Standard 3D:** Iterate offsets $i, j, k \in \{-1, 0, 1\}$ (3x3x3 neighborhood) [S3, S4, unofficial].
   - **Alternative 2D:** Iterate offsets $i, j \in \{-1, 0, 1\}$ (3x3 neighborhood) [S2, unofficial]. Some implementations use a 5x5 neighborhood [S6, unofficial].
   - Calculate neighbor cell coordinates:
     $$ \text{neighborX} = \text{cellX} + i, \quad \text{neighborY} = \text{cellY} + j, \quad \text{neighborZ} = \text{cellZ} + k $$
     [S2, S4, unofficial]

5. **Generate Feature Point:** Hash the neighbor cell coordinates to get the feature point $F = (rx, ry, rz)$ [S4, unofficial].

6. **Calculate Distance:**
   - Compute fractional part of query point:
     $$ fx = x - \lfloor x \rfloor, \quad fy = y - \lfloor y \rfloor, \quad fz = z - \lfloor z \rfloor $$
     [S4, unofficial]
   - Compute distance vector from query point to feature point. The feature point $F$ is relative to the cell center. The vector from the query point to the feature point in the neighbor cell is:
     $$ dx = i + rx - fx $$
     $$ dy = j + ry - fy $$
     $$ dz = k + rz - fz $$
     [S4, unofficial]
   - Compute distance using the selected metric [S2, unofficial]:
     - **Euclidean:** $d = \sqrt{dx^2 + dy^2 + dz^2}$
     - **Manhattan:** $d = |dx| + |dy| + |dz|$
     - **Chebyshev:** $d = \max(|dx|, |dy|, |dz|)$
     [S2, unofficial]
   - *Pitfall:* Ensure squared distance calculations use $dz^2$, not $dz \cdot dy$ [S4, unofficial].

7. **Update Minimums:**
   - If using D0: Update minimum distance if $d < \text{minDist}$ [S5, unofficial].
   - If using D1_D0 or D2_D0: Insert $d$ into the sorted distance array, maintaining order [S2, unofficial].

8. **Combine Distances:**
   - **D0:** $output = d_0$
   - **D1_D0:** $output = d_1 - d_0$
   - **D2_D0:** $output = d_2 - d_0$
   [S2, unofficial]

9. **Scale and Normalize:**
   - Multiply by Amplitude [S2, unofficial].
   - Normalize to $[0, 1]$ by dividing by the maximum possible distance in a unit cube ($\sqrt{3}$ for Euclidean) and clamping [S5, unofficial].
   - Optionally invert: $1 - normalized$ to make points close to centers bright [S5, unofficial].

### Pseudocode
```python
def worley_noise(x, y, z, cell_size, distance_metric="euclidean", combination="D0", amplitude=1.0):
    # 1. Normalize to cell space
    u = x / cell_size
    v = y / cell_size
    w = z / cell_size
    
    # 2. Base cell
    cx = floor(u)
    cy = floor(v)
    cz = floor(w)
    
    # 3. Fractional part of query point
    fx = x - floor(x) # Note: using original x,y,z for fractional part relative to grid origin
    fy = y - floor(y)
    fz = z - floor(z)
    
    # Actually, fractional part relative to the cell origin is:
    fx = u - cx
    fy = v - cy
    fz = w - cz
    
    # 4. Initialize distances
    # For D0, we just need min_d. For D1_D0, we need an array.
    # Using a simple list for up to 3 closest points.
    distances = [float('inf'), float('inf'), float('inf')]
    
    # 5. Iterate 3x3x3 neighborhood
    for i in range(-1, 2):
        for j in range(-1, 2):
            for k in range(-1, 2):
                # Neighbor cell coordinates
                nx = cx + i
                ny = cy + j
                nz = cz + k
                
                # 6. Hash to get feature point
                rx, ry, rz = hash_cell(nx, ny, nz)
                
                # 7. Distance vector
                # Feature point is at (rx, ry, rz) within the cell (nx, ny, nz)
                # Query point is at (fx, fy, fz) within the cell (cx, cy, cz)
                # Relative vector: (nx + rx - fx, ny + ry - fy, nz + rz - fz)
                dx = i + rx - fx
                dy = j + ry - fy
                dz = k + rz - fz
                
                # 8. Compute distance
                if distance_metric == "euclidean":
                    d = sqrt(dx*dx + dy*dy + dz*dz)
                elif distance_metric == "manhattan":
                    d = abs(dx) + abs(dy) + abs(dz)
                elif distance_metric == "chebyshev":
                    d = max(abs(dx), abs(dy), abs(dz))
                else:
                    d = sqrt(dx*dx + dy*dy + dz*dz) # Default Euclidean
                
                # 9. Update distances array
                # Insert d into sorted list, keeping only top 3
                distances.append(d)
                distances.sort()
                distances = distances[:3]
    
    # 10. Combine
    if combination == "D0":
        result = distances[0]
    elif combination == "D1_D0":
        result = distances[1] - distances[0]
    elif combination == "D2_D0":
        result = distances[2] - distances[0]
    else:
        result = distances[0]
        
    # 11. Scale
    result = result * amplitude
    
    # 12. Normalize (Optional, depends on usage)
    # Max Euclidean distance in unit cube is sqrt(3)
    # result = clamp(result / sqrt(3), 0.0, 1.0)
    
    return result

def hash_cell(ix, iy, iz):
    # Hash function from [S4, unofficial]
    x = (ix * 127.1 + iy * 311.7 + iz * 74.7) % 289.0
    x = sin(x) * 43758.5453
    rx = x - floor(x)
    
    y = (ix * 269.5 + iy * 183.3 + iz * 246.1) % 289.0
    y = sin(y) * 43758.5453
    ry = y - floor(y)
    
    z = (ix * 113.5 + iy * 271.9 + iz * 124.6) % 289.0
    z = sin(z) * 43758.5453
    rz = z - floor(z)
    
    return rx, ry, rz
```

### Parameters
- **Cell Size:** Defines the grid resolution. Smaller cells create finer cellular detail [S1, unofficial].
- **Amplitude:** Multiplier for the final distance value [S2, unofficial].
- **Distance Metric:** Euclidean (smoothest), Manhattan (blocky), Chebyshev (square/cubic) [S2, unofficial].
- **Combination:** D0 (standard cellular), D1_D0 (edges/boundaries), D2_D0 (more complex patterns) [S2, unofficial].
- **Frequency:** Scaling factor applied to coordinates before sampling. A default multiplier of 0.75f is sometimes used to match other noise algorithms [S2, unofficial].
- **Animation:** Sample coordinates can be scrolled by time (`_Time`) to animate the noise field [S6, unofficial].

### Edge Cases and Pitfalls
- **Distance Calculation Typo:** A common bug in 3D implementations is using `dz * dy` instead of `dz * dz` in the Euclidean distance formula [S4, unofficial].
- **Boundary Conditions:** When iterating neighbors, ensure indices are clamped or handled correctly if the volume is bounded [S5, unofficial].
- **Precision:** Using squared distances for comparisons can avoid expensive square roots, but the final output requires the actual distance for correct scaling and combination [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample, as it iterates a fixed neighborhood (e.g., 27 cells for 3x3x3) [S3, S4, unofficial].
- **Memory Complexity:** $O(1)$ if using hash-based generation, or $O(N)$ if pre-computing and storing a buffer of feature points [S1, unofficial].
- **Performance:** Optimized for GPU implementation via compute shaders, dispatching thread groups to process volume slices or rays [S1, S6, unofficial].
- **Strengths:** Produces distinct, organic cellular patterns suitable for smoke, clouds, and cellular materials [S1, S7, unofficial]. Fast to evaluate [S7, unofficial].
- **Limitations:** Lacks the smooth, directional flow of gradient noise [S2, unofficial]. The pattern is deterministic based on the hash, which can lead to repetitive artifacts if not varied [S6, unofficial].

## Background
Worley Noise was introduced by Steven Worley in 1996 in the paper "A Cellular Texture Basis Function" [S5, S7, unofficial]. It is based on Voronoi diagrams, where the space is partitioned into cells around random feature points [S2, S7, unofficial]. The method is widely used in procedural generation for volumetric effects, particularly in real-time rendering of clouds and smoke [S1, S7, unofficial].
