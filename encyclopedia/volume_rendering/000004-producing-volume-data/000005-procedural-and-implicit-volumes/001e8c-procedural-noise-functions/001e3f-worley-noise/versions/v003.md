# Worley Noise

Also called: F1 Noise, Voronoi Noise, Cellular Noise, Cellular Worley noise, Voronoi F1 distance noise, Voronoï F1 distance noise

## Overview
Worley Noise is a procedural noise generation technique that creates cellular patterns by computing the distance from a query point to the nearest feature point in a grid of pseudo-random locations [S1, S2, S4, S7, unofficial]. It solves the problem of generating structured, organic-looking density variations for volumetric data, such as cloud boundaries or smoke turbulence, where uniform noise lacks the distinct "cellular" structure [S1, S7, unofficial]. Unlike Gradient-based Noise (Perlin/Simplex) which produces smooth, continuous gradients, Worley Noise produces sharp, cell-like boundaries defined by distance metrics, making it distinct from its sibling [Value Noise](4008-value-noise.md) which relies on interpolated grid values [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $P = (x, y, z)$ in 3D space; cell size (grid resolution); distance metric (Euclidean, Manhattan, Chebyshev); combination method (D0, D1_D0, etc.) [S2, S4, unofficial].
*   **Output:** A scalar value representing the distance to the nearest feature point (F1) or a combination of distances [S2, S4, unofficial].

**Data Structures:**
*   **Feature Point Buffer:** A structured buffer storing random feature points. For 3D, each point is a vector $(rx, ry, rz)$ with components in $[0, 1]$ [S1, S5, unofficial]. The buffer is typically pre-computed or generated on-the-fly via hashing [S4, S7, unofficial].
*   **Distance Array:** A vector storing distances to the closest feature points found so far. Initialized to $\{\infty, \infty, \dots\}$ [S2, unofficial].

**Numbered Steps:**
1.  **Coordinate Normalization:** Normalize the world position $P$ to cell space by dividing by the cell size: $u = x / \text{cellSize}, v = y / \text{cellSize}, w = z / \text{cellSize}$ [S5, unofficial].
2.  **Cell Identification:** Determine the integer grid cell containing the query point: $(ix, iy, iz) = (\lfloor u \rfloor, \lfloor v \rfloor, \lfloor w \rfloor)$ [S4, S5, unofficial].
3.  **Fractional Part:** Compute the fractional part of the query point within the cell: $(fx, fy, fz) = (u - ix, v - iy, w - iz)$ [S4, unofficial].
4.  **Neighborhood Iteration:** Iterate over neighboring integer cells $(i, j, k)$ where $i, j, k \in \{-1, 0, 1\}$ (a 3x3x3 neighborhood) [S3, S4, S6, unofficial].
5.  **Feature Point Hashing:** For each neighbor cell $(ix+i, iy+j, iz+k)$, hash the integer coordinates to generate a pseudo-random feature point $(rx, ry, rz) \in [0, 1]^3$ [S4, unofficial].
    *   Hashing Formula (from [S4, unofficial]):
        $$
        \begin{aligned}
        x &= (ix \cdot 127.1 + iy \cdot 311.7 + iz \cdot 74.7) \% 289.0 \\
        x &= \sin(x) \cdot 43758.5453 \\
        rx &= x - \lfloor x \rfloor
        \end{aligned}
        $$
        Repeat for $y$ and $z$ using different coefficients (e.g., $269.5/183.3/246.1$ and $113.5/271.9/124.6$) [S4, unofficial].
6.  **Distance Calculation:** Compute the distance vector from the query point's fractional part to the feature point, accounting for the neighbor offset:
    $$
    \begin{aligned}
    dx &= i + rx - fx \\
    dy &= j + ry - fy \\
    dz &= k + rz - fz
    \end{aligned}
    $$
    Compute the distance $d$ using the selected metric (e.g., Euclidean: $d = \sqrt{dx^2 + dy^2 + dz^2}$) [S2, S4, unofficial].
    *   *Pitfall:* Ensure correct squaring of components (e.g., $dz^2$, not $dz \cdot dy$) [S4, unofficial].
7.  **Minimum Tracking:** Update the minimum distance found so far. If tracking multiple distances (for D1_D0), maintain a sorted list of the closest distances [S2, S4, unofficial].
8.  **Combination:** Combine the tracked distances based on the chosen method:
    *   **D0:** Output $d_0$ (distance to closest) [S2, unofficial].
    *   **D1_D0:** Output $d_1 - d_0$ (distance to second closest minus closest) [S2, unofficial].
9.  **Scaling:** Multiply the result by an amplitude parameter and optionally invert or normalize to $[0, 1]$ [S2, S5, unofficial].

**Pseudocode:**
```python
def worley_noise_3d(x, y, z, cell_size, distance_metric='euclidean', combination='D0'):
    # 1. Normalize to cell space
    u = x / cell_size
    v = y / cell_size
    w = z / cell_size
    
    # 2. Identify integer cell
    ix = floor(u)
    iy = floor(v)
    iz = floor(w)
    
    # 3. Fractional part
    fx = u - ix
    fy = v - iy
    fz = w - iz
    
    # Initialize distances
    # For D0, we only need min_dist. For D1_D0, we need f1 and f2.
    f1 = float('inf')
    f2 = float('inf')
    
    # 4. Iterate over 3x3x3 neighborhood
    for i in range(-1, 2):
        for j in range(-1, 2):
            for k in range(-1, 2):
                # 5. Hash cell coordinates to feature point
                cell_x = ix + i
                cell_y = iy + j
                cell_z = iz + k
                
                # Simple hash function (from [S4, unofficial])
                rx = hash_3d_to_float(cell_x, cell_y, cell_z)
                ry = hash_3d_to_float(cell_x + 1000, cell_y + 1000, cell_z + 1000)
                rz = hash_3d_to_float(cell_x + 2000, cell_y + 2000, cell_z + 2000)
                
                # 6. Distance vector
                dx = i + rx - fx
                dy = j + ry - fy
                dz = k + rz - fz
                
                # 7. Compute distance
                if distance_metric == 'euclidean':
                    dist = sqrt(dx*dx + dy*dy + dz*dz)
                elif distance_metric == 'manhattan':
                    dist = abs(dx) + abs(dy) + abs(dz)
                elif distance_metric == 'chebyshev':
                    dist = max(abs(dx), abs(dy), abs(dz))
                else:
                    dist = sqrt(dx*dx + dy*dy + dz*dz) # Default Euclidean
                
                # 8. Update minimums
                if dist < f1:
                    f2 = f1
                    f1 = dist
                elif dist < f2:
                    f2 = dist
    
    # 9. Combine
    if combination == 'D0':
        return f1
    elif combination == 'D1_D0':
        return f2 - f1
    else:
        return f1

def hash_3d_to_float(ix, iy, iz):
    x = (ix * 127.1 + iy * 311.7 + iz * 74.7) % 289.0
    x = sin(x) * 43758.5453
    return x - floor(x)
```

## Subtopics

### [Animated Worley Noise Texture Generation](2982-animated-worley-noise-texture-generation.md)
Generates a 2D Worley noise texture to break up smoke silhouettes, updated per frame via compute shader. It differs from the parent [Worley Noise](1726-worley-noise.md) by explicitly incorporating a time uniform to animate the point positions, and from [Voronoise](5519-voronoise.md) by returning raw distance values rather than smoothed vector displacements.

### [Voronoise](5519-voronoise.md)
Voronoise is a procedural noise function that unifies value noise and Voronoi cellular patterns through a single interpolation parameter. It solves the problem of needing distinct noise types for continuous textures and cellular structures by providing a smooth transition between them. Unlike standard Worley noise which only returns distance metrics, Voronoise returns a continuous scalar value suitable for fractal Brownian motion (FBM) accumulation, distinguishing it from its parent [1726-worley-noise.md] and sibling [2982-animated-worley-noise-texture-generation.md].

### Worley Edge Erosion (F2 - F1)
Generates crystalline edge erosion textures for cloud boundary curling by computing the difference between the second nearest neighbor distance (F2) and the nearest neighbor distance (F1) [S4, unofficial]. It is implemented by tracking the two smallest distances ($f1, f2$) during the neighborhood search and returning $\max(0.0, \min(1.0, f2 - f1))$ [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, proportional to the size of the neighborhood search (e.g., 27 iterations for a 3x3x3 grid) [S3, S4, unofficial].
*   **Memory Complexity:** $O(1)$ if feature points are hashed on-the-fly; $O(N)$ if pre-computed feature points are stored in a buffer, where $N$ is the number of cells [S1, S5, unofficial].
*   **Performance:** Optimized for GPU implementation using compute shaders, allowing parallel evaluation of noise values for volumetric raymarching [S1, S5, unofficial].
*   **Strengths:** Produces distinct cellular patterns suitable for organic structures like clouds, smoke, and cellular materials [S1, S7, unofficial].
*   **Limitations:** The sharp boundaries of F1 noise may appear unnatural without smoothing or combination with other noise types (like D1_D0) [S2, unofficial].
*   **When to use:** When cellular, structured noise is required for volumetric density or surface detail [S1, unofficial].
*   **When not to use:** When smooth, continuous gradients are preferred (use Perlin/Simplex) [S2, unofficial].

## Background
Worley Noise was introduced by Steven Worley in 1996 in the paper "A Cellular Texture Basis Function" [S5, unofficial]. It is widely used in computer graphics for generating procedural textures and volumetric data, particularly for simulating clouds, smoke, and other natural phenomena with cellular structures [S1, S7, unofficial].
