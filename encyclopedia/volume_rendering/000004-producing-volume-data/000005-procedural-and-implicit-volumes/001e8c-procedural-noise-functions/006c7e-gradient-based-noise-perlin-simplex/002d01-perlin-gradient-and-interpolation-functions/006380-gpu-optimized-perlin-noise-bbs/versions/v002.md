# GPU-Optimized Perlin Noise (BBS)

Also called: Modified Noise, Blum-Blum-Shub Perlin Noise

## Overview
GPU-Optimized Perlin Noise (BBS), also known as Modified Noise, is a procedural noise function designed for efficient direct computation on GPUs by eliminating permutation table lookups [S1, unofficial]. It replaces hash lookups with a computable Blum-Blum-Shub (BBS) generator and selects gradients from hypercube corners, enabling dimension reducibility to optimize 3D noise via 2D texture lookups [S1, unofficial]. It differs from [Improved Perlin Noise](17170-improved-perlin-noise.md) by using corner gradients instead of unit sphere vectors and from [3D Perlin Noise](11323-3d-perlin-noise.md) by its specific GPU-oriented hashing and texture optimization strategies [S1, unofficial].

## How it works
**Inputs:** A 3D point $p = (p_x, p_y, p_z)$ [S1, unofficial].
**Outputs:** A scalar noise value $N(p)$ [S1, unofficial].

**Data Structures:**
*   **Modulus $M$:** A composite number $M = pq$ where $p$ and $q$ are large primes [S1, unofficial].
*   **Textures (Optional Optimization):**
    *   `tex_2d`: Stores 2D noise values $N_{2D}(x, y)$ [S1, unofficial].
    *   `tex_zgrad`: Stores z-gradient values $\frac{\partial N}{\partial z}$ at integer $z$ slices [S1, unofficial].
    *   Alternatively, a single 2-channel texture storing both [S1, unofficial].

**Parameters:**
*   $M$: Modulus for BBS generator. Not given in the sources.
*   Precision mode: "Exact" (5-instruction) or "Inexact" (4-instruction) modulo [S1, unofficial].

**Steps:**

1.  **Integer and Fractional Parts:**
    Compute integer coordinates $i = \lfloor p \rfloor$ and fractional coordinates $f = p - i$ [S1, unofficial].
    Let $i_x, i_y, i_z$ be the integer components and $f_x, f_y, f_z$ be the fractional components [S1, unofficial].

2.  **Hash Construction:**
    Define the hash function using the Blum-Blum-Shub generator:
    $$ \text{hash}(x) = x^2 \bmod M $$
    Construct multidimensional hashes for lattice corners recursively:
    $$ \text{hash3}(x, y, z) = \text{hash}(\text{hash}(\text{hash}(x+1) + y+1) + z+1) $$
    The source uses $p_i + 1$ in the hash construction, implying the hash is computed on the integer lattice indices offset by 1 [S1, unofficial].

3.  **Gradient Selection:**
    Gradients are selected from the 8 corners of the unit hypercube surrounding $p$ [S1, unofficial]. For a corner defined by bits $j, k, l \in \{0, 1\}$, the gradient vector $g_{jkl}$ has components $\pm 1$:
    $$ g_{jkl} = [(-1)^j, (-1)^k, (-1)^l] $$
    The dot product with the fractional offset $f = p - i$ simplifies to additions and subtractions:
    $$ \text{grad3D}(f) = \pm f_x \pm f_y \pm f_z $$
    The signs are determined by the corner's bit indices [S1, unofficial].

4.  **Dimension Reducibility Optimization (3D):**
    To reduce texture lookups, 3D noise is computed using 2D noise and z-gradients [S1, unofficial].
    Compute the hash for the current and next integer $z$-slice:
    $$ h_0 = \text{hash}(i_z + 1) $$
    $$ h_1 = \text{hash}(i_z + 2) $$
    Index the 2D textures using the $x, y$ coordinates and the $z$-hash:
    $$ c_0 = (i_x, i_y, h_0) $$
    $$ c_1 = (i_x, i_y, h_1) $$
    Retrieve 2D noise values $n_0 = \text{tex\_2d}(c_0)$, $n_1 = \text{tex\_2d}(c_1)$ and z-gradients $g_0 = \text{tex\_zgrad}(c_0)$, $g_1 = \text{tex\_zgrad}(c_1)$ [S1, unofficial].

5.  **Interpolation:**
    Perform trilinear interpolation. The final 3D noise using separate 2D noise and z-gradient textures is:
    $$ N(p) = \text{lerp}(f_z, n_0 + f_z \cdot g_0, n_1 + f_z \cdot g_1) $$
    The source provides this formula (19), noting that the 2D noise and gradient are pre-combined or accessed such that the final step is a linear interpolation between the two $z$-slices, where each slice value includes the $z$-gradient contribution [S1, unofficial].

6.  **Modulo Implementation:**
    *   **Exact (5-instruction):** $i \bmod M = i - \lfloor i/M \rfloor \cdot M$. Used for 2D noise to ensure periodicity at $M$ [S1, unofficial].
    *   **Inexact (4-instruction):** $i \bmod M = \text{frac}(i/M) \cdot M$. Used for 3D+ where precision loss is less critical [S1, unofficial].

**Pseudocode:**

```python
def bbs_mod_exact(x, M):
    return x - (x // M) * M

def bbs_mod_inexact(x, M):
    return (x / M - (x // M)) * M

def bbs_hash(x, M, exact=True):
    mod = bbs_mod_exact if exact else bbs_mod_inexact
    return mod(x * x, M)

def hash3(x, y, z, M, exact=True):
    h = bbs_hash(x + 1, M, exact)
    h = bbs_hash(h + y + 1, M, exact)
    return bbs_hash(h + z + 1, M, exact)

def fade(t):
    return t * t * t * (t * (t * 6 - 15) + 10)  # Standard Perlin fade [G]

def lerp(t, a, b):
    return a + t * (b - a)

def grad3d(fx, fy, fz, corner_bits):
    sx = 1 if corner_bits[0] == 0 else -1
    sy = 1 if corner_bits[1] == 0 else -1
    sz = 1 if corner_bits[2] == 0 else -1
    return sx * fx + sy * fy + sz * fz

def noise_3d(p, M, exact=True):
    ix, iy, iz = int(p[0]), int(p[1]), int(p[2])
    fx, fy, fz = p[0] - ix, p[1] - iy, p[2] - iz

    # Compute hashes for the 8 corners of the unit hypercube
    h000 = hash3(ix, iy, iz, M, exact)
    h100 = hash3(ix + 1, iy, iz, M, exact)
    h010 = hash3(ix, iy + 1, iz, M, exact)
    h110 = hash3(ix + 1, iy + 1, iz, M, exact)
    h001 = hash3(ix, iy, iz + 1, M, exact)
    h101 = hash3(ix + 1, iy, iz + 1, M, exact)
    h011 = hash3(ix, iy + 1, iz + 1, M, exact)
    h111 = hash3(ix + 1, iy + 1, iz + 1, M, exact)

    # Compute gradient dot products for each corner
    u000 = grad3d(fx, fy, fz, (h000 % 2, (h000 >> 1) % 2, (h000 >> 2) % 2))
    u100 = grad3d(fx - 1, fy, fz, (h100 % 2, (h100 >> 1) % 2, (h100 >> 2) % 2))
    u010 = grad3d(fx, fy - 1, fz, (h010 % 2, (h010 >> 1) % 2, (h010 >> 2) % 2))
    u110 = grad3d(fx - 1, fy - 1, fz, (h110 % 2, (h110 >> 1) % 2, (h110 >> 2) % 2))
    u001 = grad3d(fx, fy, fz - 1, (h001 % 2, (h001 >> 1) % 2, (h001 >> 2) % 2))
    u101 = grad3d(fx - 1, fy, fz - 1, (h101 % 2, (h101 >> 1) % 2, (h101 >> 2) % 2))
    u011 = grad3d(fx, fy - 1, fz - 1, (h011 % 2, (h011 >> 1) % 2, (h011 >> 2) % 2))
    u111 = grad3d(fx - 1, fy - 1, fz - 1, (h111 % 2, (h111 >> 1) % 2, (h111 >> 2) % 2))

    # Fade and interpolate
    fx, fy, fz = fade(fx), fade(fy), fade(fz)
    ux00 = lerp(fx, u000, u100)
    ux10 = lerp(fx, u010, u110)
    ux01 = lerp(fx, u001, u101)
    ux11 = lerp(fx, u011, u111)
    uy0 = lerp(fy, ux00, ux10)
    uy1 = lerp(fy, ux01, ux11)
    return lerp(fz, uy0, uy1)
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The BBS hash involves squaring and modulo, which is more expensive than a simple table lookup but avoids memory latency [S1, unofficial].
*   **Memory Complexity:** $O(1)$ if purely computed. $O(1)$ with texture optimization (storing 2D slices) [S1, unofficial].
*   **Performance:** The 4-instruction modulo is faster but inexact. The 5-instruction modulo is exact but slower. Texture lookups accelerate 3D noise by reducing dependent lookups [S1, unofficial].
*   **Strengths:** No permutation table required; suitable for GPUs with limited constant memory; dimension reducibility reduces texture fetches [S1, unofficial].
*   **Limitations:** Axis-aligned clumping is visible in 2D results; the inexact modulo causes non-repeating noise at modulus $M$ in lower dimensions [S1, unofficial].
*   **When to use:** When GPU constant memory is constrained and a permutation table cannot be stored; for 3D/4D turbulence where clumping is less noticeable [S1, unofficial].
*   **When not to use:** When exact periodicity at a specific modulus is required in 2D; when visual quality in 2D is critical due to clumping [S1, unofficial].

## Background
Modified Noise is described in a thesis on real-time volumetric rendering [S1, unofficial]. It modifies Perlin's improved noise to be more suitable for GPU implementation by removing table lookups and using the Blum-Blum-Shub generator [S1, unofficial].
