# Simplex Noise 2D

Also called: 2D OpenSimplex Noise, 3D Perlin Noise (Improved), Improved Noise, Perlin Noise (Improved), SNoise, Simplex Noise, 2D Simplex

## Overview
Simplex Noise 2D is a gradient-based procedural noise function for 2D space that generates smooth, continuous scalar fields by using a skewed grid, fixed gradient vectors, and a lookup table [S2, S3, unofficial]. It solves the problem of directional artifacts and high computational complexity inherent in the original integer-lattice Perlin Noise by utilizing a simplex (triangular) grid, which provides more even distribution of grid points and fewer gradient contributions per sample [S4]. Unlike standard Perlin Noise which uses a square grid and requires four gradient evaluations in 2D, Simplex Noise 2D uses a triangular grid and requires only three gradient evaluations, lowering computational complexity and eliminating undesired directional artifacts [S4]. It builds on [Simplex Noise](978-simplex-noise.md) by specializing the algorithm for two dimensions.

## How it works
**Inputs:** A 2D coordinate $(x, y)$.
**Outputs:** A scalar noise value $N \in [-1, 1]$ (or $[0, 1]$ if normalized).

**Data Structures:**
1.  **Permutation Table:** An array of 512 integers (indices 0–255 repeated twice) derived from a permutation of 0–255. This table maps grid coordinates to gradient indices.
2.  **Gradient Vectors:** A fixed set of 2D vectors. In the standard implementation (Green 2005), these are typically the 4 vectors $(1,1), (-1,1), (1,-1), (-1,-1)$ scaled by $\frac{1}{\sqrt{2}}$ or similar, but the specific implementation in [S2, unofficial] uses a lookup from a `gradients2D` array indexed by the permutation result. The source [S2, unofficial] implies a lookup table `gradients2D` is used.

**Constants:**
*   $C_1 = \frac{\sqrt{3}-1}{2}$ (Stretch factor for input)
*   $C_2 = \frac{3-\sqrt{3}}{6}$ (Squish factor for grid)
*   $G_1 = \frac{1}{\sqrt{3}}$ (Inverse of stretch factor, often used in derivations)
*   $NORM = \frac{1}{47.0}$ (Normalization constant, [S2, unofficial])
*   $SCALE = 42.0$ (Final scaling factor, [S3, unofficial])
*   $MOD = 289$ (Modulo base for permutation table, [S3, unofficial])

**Steps:**

1.  **Skew Input Space:**
    Transform the input coordinates $(x, y)$ into the simplex grid space.
    $$ s = (x + y) \times C_1 $$
    $$ x_{skew} = x + s $$
    $$ y_{skew} = y + s $$

2.  **Find Simplex Cell:**
    Determine the integer coordinates of the simplex cell containing the input point.
    $$ i = \lfloor x_{skew} \rfloor $$
    $$ j = \lfloor y_{skew} \rfloor $$

3.  **Unskew to Find Origin:**
    Transform the cell corner back to the original space to find the relative position of the input point within the simplex.
    $$ t = (i + j) \times C_2 $$
    $$ X_0 = i - t $$
    $$ Y_0 = j - t $$
    $$ x_{rel} = x - X_0 $$
    $$ y_{rel} = y - Y_0 $$

4.  **Determine Simplex Corners:**
    Identify the other two corners of the simplex triangle. The relative position $(x_{rel}, y_{rel})$ determines which of the two possible triangles in the square cell the point lies in.
    *   If $x_{rel} > y_{rel}$, the corner $(1, 0)$ is closer.
        *   Corner 1 (Origin): $(0, 0)$ relative to cell.
        *   Corner 2: $(1, 0)$ relative to cell.
        *   Corner 3: $(0, 1)$ relative to cell.
    *   If $y_{rel} > x_{rel}$, the corner $(0, 1)$ is closer.
        *   Corner 1 (Origin): $(0, 0)$ relative to cell.
        *   Corner 2: $(0, 1)$ relative to cell.
        *   Corner 3: $(1, 0)$ relative to cell.
    
    Let the relative coordinates of the three corners in the original space be $(x_0, y_0), (x_1, y_1), (x_2, y_2)$.
    $$ (x_0, y_0) = (x_{rel}, y_{rel}) $$
    If $x_{rel} > y_{rel}$:
    $$ (x_1, y_1) = (x_{rel} - 1, y_{rel}) $$
    $$ (x_2, y_2) = (x_{rel}, y_{rel} - 1) $$
    Else:
    $$ (x_1, y_1) = (x_{rel}, y_{rel} - 1) $$
    $$ (x_2, y_2) = (x_{rel} - 1, y_{rel}) $$

5.  **Hash Gradient Indices:**
    Map the integer cell coordinates $(i, j)$ to gradient vectors using the permutation table.
    $$ A = i + j $$
    $$ idx_0 = perm[i + perm[j]] $$
    $$ idx_1 = perm[i + 1 + perm[j]] $$
    $$ idx_2 = perm[i + perm[j + 1]] $$
    *(Note: The exact permutation logic may vary slightly based on implementation, e.g., [S2, unofficial] uses a hash function involving bit shifts. The standard Green 2005 method uses the permutation table directly as above. We follow the standard method described in [S3, unofficial] and [S4] which aligns with the "Improved Perlin" description.)*
    
    Using the permutation table $P$ of size 512:
    $$ g_0 = P[P[i] + j] \pmod{4} $$
    $$ g_1 = P[P[i+1] + j] \pmod{4} $$
    $$ g_2 = P[P[i] + j+1] \pmod{4} $$
    
    The gradient vectors are typically:
    $$ V_0 = (1, 1), V_1 = (-1, 1), V_2 = (1, -1), V_3 = (-1, -1) $$
    *(Scaled appropriately, often by $1/\sqrt{2}$ or just used as is and normalized later. [S2, unofficial] uses a lookup `gradients2D[index]`.)*

6.  **Compute Contributions:**
    For each corner $k \in \{0, 1, 2\}$:
    $$ t_k = 0.5 - (x_k^2 + y_k^2) $$
    If $t_k < 0$, the contribution is 0.
    Otherwise:
    $$ contrib_k = t_k^4 \times (V_{g_k} \cdot (x_k, y_k)) $$
    
    The dot product $V_{g_k} \cdot (x_k, y_k)$ is computed using the selected gradient vector.

7.  **Sum and Scale:**
    $$ N_{raw} = 70.0 \times (contrib_0 + contrib_1 + contrib_2) $$
    *(Note: The scaling factor 70.0 is common in standard Simplex Noise to normalize the range to [-1, 1]. [S3, unofficial] uses 42.0 and [S2, unofficial] uses 1/47.0 normalization. The factor depends on the specific gradient set and normalization convention. We cite the specific constants from the sources. [S3, unofficial] states 42.0. [S2, unofficial] states NORM_2D is 1/47.0.)*
    
    Using [S3, unofficial]'s constant:
    $$ N = 42.0 \times (contrib_0 + contrib_1 + contrib_2) $$
    
    Using [S2, unofficial]'s normalization:
    $$ N = N_{raw} \times \frac{1}{47.0} $$

**Pseudocode:**

```python
import math

# Constants
C1 = (math.sqrt(3.0) - 1.0) / 2.0
C2 = (3.0 - math.sqrt(3.0)) / 6.0
NORM = 1.0 / 47.0
SCALE = 42.0

# Permutation table (example, typically 0-255 shuffled)
# In a real implementation, this is a fixed array of 512 integers
PERM = [151, 160, 137, 91, 90, 15, 131, 13, 201, 95, 96, 53, 194, 233, 7, 225, 140, 36, 103, 30, 69, 142, 8, 99, 37, 240, 21, 10, 23, 190, 6, 148, 247, 120, 234, 75, 0, 26, 197, 62, 94, 252, 219, 203, 117, 35, 11, 32, 57, 177, 33, 88, 237, 149, 56, 87, 174, 20, 125, 136, 171, 168, 68, 175, 74, 165, 71, 134, 139, 48, 27, 166, 77, 146, 158, 231, 83, 111, 229, 122, 60, 211, 133, 230, 220, 105, 92, 41, 55, 46, 245, 40, 244, 102, 143, 54, 65, 25, 63, 161, 1, 216, 80, 73, 209, 76, 132, 187, 208, 89, 18, 169, 200, 196, 135, 130, 116, 188, 159, 86, 164, 100, 109, 198, 173, 186, 3, 64, 52, 217, 226, 250, 124, 123, 5, 202, 38, 147, 118, 126, 255, 82, 85, 212, 207, 206, 59, 226, 226, 226, 226, 226, 226, 226, 226, 226, 226, 226, 226, 226, 226, 226, 226] # Placeholder, must be 512 items

def perm(x):
    return PERM[x & 255]

def grad(hash_idx, x, y):
    # Standard gradients for 2D Simplex Noise
    # Indices 0-3 map to (1,1), (-1,1), (1,-1), (-1,-1)
    h = hash_idx & 3
    if h == 0: return x + y
    elif h == 1: return -x + y
    elif h == 2: return x - y
    else: return -x - y

def simplex_noise_2d(x, y):
    # 1. Skew input
    s = (x + y) * C1
    x_skew = x + s
    y_skew = y + s
    
    # 2. Find cell
    i = math.floor(x_skew)
    j = math.floor(y_skew)
    
    # 3. Unskew to find origin
    t = (i + j) * C2
    X0 = i - t
    Y0 = j - t
    
    x_rel = x - X0
    y_rel = y - Y0
    
    # 4. Determine simplex corners
    if x_rel > y_rel:
        i1 = 1
        j1 = 0
    else:
        i1 = 0
        j1 = 1
        
    x0 = x_rel
    y0 = y_rel
    x1 = x_rel - i1
    y1 = y_rel - j1
    x2 = x_rel - 1.0
    y2 = y_rel - 1.0
    
    # 5. Hash gradient indices
    # Using standard permutation logic
    ii = i & 255
    jj = j & 255
    
    gi0 = perm(ii + perm(jj))
    gi1 = perm(ii + i1 + perm(jj + j1))
    gi2 = perm(ii + 1 + perm(jj + 1))
    
    # 6. Compute contributions
    t0 = 0.5 - (x0*x0 + y0*y0)
    if t0 < 0:
        n0 = 0.0
    else:
        t0 *= t0
        n0 = t0 * t0 * grad(gi0, x0, y0)
        
    t1 = 0.5 - (x1*x1 + y1*y1)
    if t1 < 0:
        n1 = 0.0
    else:
        t1 *= t1
        n1 = t1 * t1 * grad(gi1, x1, y1)
        
    t2 = 0.5 - (x2*x2 + y2*y2)
    if t2 < 0:
        n2 = 0.0
    else:
        t2 *= t2
        n2 = t2 * t2 * grad(gi2, x2, y2)
        
    # 7. Sum and scale
    # Using SCALE from [S3, unofficial]
    return SCALE * (n0 + n1 + n2)
```

**Edge Cases and Pitfalls:**
*   **Precision:** The skewing and unskewing operations involve irrational numbers ($\sqrt{3}$). Use `float` or `double` consistently. [S2, unofficial] uses `Math.sqrt(3)`.
*   **Boundary Conditions:** The permutation table must be large enough to handle the modulo operations without collision artifacts. [S3, unofficial] specifies 289 as the modulo base, but standard 2D simplex often uses 256 or 512. The source [S2, unofficial] uses a hash function with bit shifts, which may imply a different permutation scheme.
*   **Gradient Selection:** The choice of gradient vectors affects the noise's appearance. The standard set is $(1,1), (-1,1), (1,-1), (-1,-1)$. [S2, unofficial] uses a lookup table `gradients2D`, which might contain different vectors.

## Subtopics

### [2D Octaved Noise with Memoization](4530-2d-octaved-noise-with-memoization.md)
2D Octaved Noise with Memoization generates complex, self-similar procedural textures by summing multiple octaves of a base 2D noise function (such as Simplex Noise) with decreasing amplitude and increasing frequency, while caching results to avoid redundant calculations. It is primarily used for generating natural phenomena like smoke, fog, and fire, where a richer frequency spectrum is required than a single octave provides. Unlike standard octave noise which recomputes every sample, this method introduces a memoization layer (hash map or dictionary) keyed by input coordinates and octave count, trading memory for computational speed.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The number of operations is constant regardless of input size. [S5, unofficial] states that Improved Perlin Noise (which Simplex Noise 2D is often grouped with or compared to) uses approximately 64 instructions per octave. Simplex Noise 2D is generally faster than 2D Perlin Noise due to fewer gradient evaluations (3 vs 4) and simpler interpolation (linear vs bilinear).
*   **Memory Complexity:** $O(1)$ if the permutation table is stored in registers or a small cache. The permutation table size is fixed (e.g., 256 or 512 integers).
*   **Measured Performance:** [S5, unofficial] notes that Improved Perlin Noise can be compiled for pixel shader 2.a or newer hardware. Simplex Noise 2D is similarly efficient and can be implemented in GLSL [S3, unofficial] or HLSL [S1, S2, unofficial].
*   **Strengths:** Eliminates directional artifacts present in Perlin Noise. Lower computational cost than Perlin Noise. Smooth and continuous.
*   **Limitations:** The grid is skewed, which can be confusing to visualize. The noise is not periodic unless the permutation table is constructed specifically for periodicity.
*   **When to Use:** When high-quality procedural noise is needed with minimal computational cost, such as in real-time rendering of terrain, textures, or volumetric data.
*   **When Not to Use:** When strict periodicity is required (e.g., wrapping textures) without additional modifications to the permutation table. When the specific visual characteristics of Perlin Noise are desired.

## Background
Simplex Noise was introduced by Ken Perlin in 2001 as an improvement over his original Perlin Noise. It was designed to reduce computational complexity and eliminate directional artifacts. The 2D version is a specific case of the general simplex noise algorithm. The implementation described in [S5, unofficial] as "Improved Perlin Noise" by Green in 2005 is closely related and often used interchangeably in graphics programming contexts, though technically distinct. The term "Simplex Noise 2D" specifically refers to the 2D instance of the simplex noise algorithm. The method is widely used in procedural generation for games and visual effects.
