# 2D Octaved Noise with Memoization

Also called: Multi-octave noise, Octave Noise, Fractal Noise with Caching

## Overview
2D Octaved Noise with Memoization generates complex, self-similar noise patterns by summing multiple weighted layers (octaves) of a base 2D noise function, where each layer has frequency content limited to a specific range [S1]. It solves the problem of computationally expensive procedural texture generation by caching previously computed noise values for specific coordinate-octave combinations to avoid redundant calculations [S3, unofficial]. Unlike standard octave noise which recomputes base noise for every sample, this method uses a cache to store and retrieve results, improving performance for repeated queries [S3, unofficial].

## How it works
**Inputs:**
- Base coordinates $(x, y)$ in 2D space [S4, unofficial].
- Number of octaves $n_{octaves}$ [S4, unofficial].
- Scale $S$ (spatial frequency divisor) [S4, unofficial].
- Persistence $p$ (amplitude decay factor) [S4, unofficial].
- Lacunarity $L$ (frequency multiplication factor) [S4, unofficial].
- Cache data structure mapping keys to noise values [S3, unofficial].

**Outputs:**
- A single scalar noise value normalized to a consistent range, typically $[0, 1]$ after post-processing [S4, unofficial].

**Data Structures:**
- **Cache:** A hash map or dictionary mapping a composite key to a floating-point value. The key format is a string combining coordinates and octave count, e.g., `f"{x},{y},{n_octaves}"` [S3, unofficial].
- **Noise Grid (for grid-based variants):** A 1D array (e.g., `std::vector<float>`) accessed via helper functions that map 2D coordinates $(x, y)$ to a 1D index using $index = x \cdot width + y$ [S2, unofficial].

**Parameters:**
- $S$ (Scale): Controls the spatial frequency of the base noise. Default: $0.0001$. Must be strictly greater than $0$ [S4, unofficial].
- $p$ (Persistence): Amplitude decay factor per octave. Default: $0.5$ [S4, unofficial].
- $L$ (Lacunarity): Frequency multiplication factor per octave. Default: $2.0$ [S4, unofficial].
- $w_i$ (Weights): Control the contribution of each band to the final result. Perlin initially used $1/2^i$, but typical tools expose them directly to the user [S1].

**Algorithm Steps:**

1.  **Key Generation:** Create a unique cache key for the current request using the input coordinates and octave count: `key = f"{x},{y},{n_octaves}"` [S3, unofficial].
2.  **Cache Check:** Look up `key` in the cache. If found, return the cached value immediately [S3, unofficial].
3.  **Initialization:** Set `result = 0.0`, `total_amplitude = 0.0`, `current_amplitude = 1.0`, and `current_frequency = 1.0` [S4, unofficial].
4.  **Octave Loop:** Iterate $o$ from $0$ to $n_{octaves} - 1$:
    a.  **Coordinate Scaling:** Calculate scaled coordinates for the current octave: $sx = ((x + offset_x) / S) \cdot current\_frequency$ and $sy = ((y + offset_y) / S) \cdot current\_frequency$ [S4, unofficial].
    b.  **Base Noise Evaluation:** Compute the base noise value $N_o$ at $(sx, sy)$. For grid-based implementations, determine the grid period $P = 2^o$, identify the four surrounding grid points using modulo arithmetic with the grid dimensions, and perform bilinear interpolation: first horizontally between top-left and top-right, then between bottom-left and bottom-right, then vertically between the two horizontal results [S2, unofficial].
    c.  **Accumulation:** Add the weighted noise to the result: $result += N_o \cdot current\_amplitude$. Add the current amplitude to the total: $total\_amplitude += current\_amplitude$ [S4, unofficial].
    d.  **Update for Next Octave:** Update amplitude: $current\_amplitude = current\_amplitude \cdot p$. Update frequency: $current\_frequency = current\_frequency \cdot L$ [S4, unofficial].
5.  **Normalization:** Normalize the result by the total accumulated amplitude: $ans = result / total\_amplitude$ [S3, unofficial]. Some implementations apply additional rescaling to $[0, 1]$ using linear interpolation [S4, unofficial].
6.  **Cache Storage:** Store `ans` in the cache under `key` [S3, unofficial].
7.  **Return:** Return `ans` [S3, unofficial].

**Pseudocode:**

```python
def generate_octaved_noise(x, y, n_octaves, scale, persistence, lacunarity, cache, grid, width, height):
    """
    Generates 2D octaved noise with memoization.
    
    Args:
        x, y: Input coordinates.
        n_octaves: Number of octaves to sum.
        scale: Spatial scale factor.
        persistence: Amplitude decay factor.
        lacunarity: Frequency multiplication factor.
        cache: Dictionary mapping keys to noise values.
        grid: 1D array of random values for the noise grid.
        width, height: Dimensions of the noise grid.
        
    Returns:
        Normalized noise value.
    """
    # 1. Key Generation
    key = f"{x},{y},{n_octaves}"
    
    # 2. Cache Check
    if key in cache:
        return cache[key]
    
    # 3. Initialization
    result = 0.0
    total_amplitude = 0.0
    current_amplitude = 1.0
    current_frequency = 1.0
    
    # 4. Octave Loop
    for o in range(n_octaves):
        # a. Coordinate Scaling
        sx = ((x + o) / scale) * current_frequency
        sy = ((y + o) / scale) * current_frequency
        
        # b. Base Noise Evaluation (Grid-based bilinear interpolation)
        period = 2 ** o
        x0 = int(x * period) % width
        y0 = int(y * period) % height
        x1 = (x0 + 1) % width
        y1 = (y0 + 1) % height
        
        # Map 2D grid indices to 1D array
        v00 = grid[y0 * width + x0]
        v10 = grid[y0 * width + x1]
        v01 = grid[y1 * width + x0]
        v11 = grid[y1 * width + x1]
        
        # Bilinear interpolation
        # Horizontal interpolation
        top = v00 + (v10 - v00) * (sx - int(sx))
        bottom = v01 + (v11 - v01) * (sx - int(sx))
        # Vertical interpolation
        noise_value = top + (bottom - top) * (sy - int(sy))
        
        # c. Accumulation
        result += noise_value * current_amplitude
        total_amplitude += current_amplitude
        
        # d. Update for Next Octave
        current_amplitude *= persistence
        current_frequency *= lacunarity
        
    # 5. Normalization
    if total_amplitude == 0:
        ans = 0.0
    else:
        ans = result / total_amplitude
        
    # 6. Cache Storage
    cache[key] = ans
    
    # 7. Return
    return ans
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** Scale must be strictly greater than zero; otherwise, division by zero occurs during coordinate scaling [S4, unofficial].
- **Negative Weights:** Negative weights cannot cancel energy from a frequency band because noise has random phase. To produce a spectrum with no energy at some frequencies, the primitive noise function must be band-pass rather than merely band-limited [S1].

## Subtopics

### Normalized Octave Noise
Scales the octave noise result by the maximum possible amplitude to ensure the output range is consistent regardless of the number of octaves or persistence value [S5, unofficial]. The exact formula for the maximum amplitude helper is not given in the sources. This variant is useful when a fixed output range is required independent of the fractal dimension settings.

## Operating characteristics
- **Time Complexity:** $O(n_{octaves})$ per unique coordinate query. With memoization, repeated queries for the same coordinates are $O(1)$ [G].
- **Memory Complexity:** $O(N)$ where $N$ is the number of unique cached coordinate-octave combinations [G].
- **Performance:** Significantly faster than non-cached octave noise for static scenes or repeated sampling of the same regions. Performance degrades if the cache misses frequently due to high variability in input coordinates [G].
- **Strengths:** Consistent output range (with normalization), efficient for repeated queries, smooth transitions between octaves [G].
- **Limitations:** High memory usage for large caches, potential cache thrashing in dynamic scenes [G].
- **When to Use:** Static terrain generation, procedural texture baking, scenes where noise values are sampled repeatedly [G].
- **When Not to Use:** Highly dynamic scenes with unique coordinates every frame, memory-constrained environments [G].

## Background
The concept of summing octaves of noise was introduced by Ken Perlin in 1985 [S1]. Goldberg et al. used weighted octave noise to cancel mapping distortions and dynamically adapt noise to viewing conditions [S1].
