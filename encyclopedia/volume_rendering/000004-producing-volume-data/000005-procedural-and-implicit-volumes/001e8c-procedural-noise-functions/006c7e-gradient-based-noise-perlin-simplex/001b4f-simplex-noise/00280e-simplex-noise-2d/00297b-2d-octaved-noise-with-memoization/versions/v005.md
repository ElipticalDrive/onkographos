# 2D Octaved Noise with Memoization

Also called: 2D OpenSimplex Noise with Memoization, Fractal Noise with Caching, Octave Noise, Perlin-like Noise Generation

## Overview
A fractal noise generator that sums multiple octaves of a base 2D noise function with decreasing amplitude and increasing frequency, caching results to avoid redundant calculations [S2, unofficial]. It builds on [Simplex Noise 2D](4155-simplex-noise-2d.md) to provide spatially coherent procedural textures. Unlike standard octave noise which recomputes base noise for every sample, this method caches the final accumulated result for specific coordinate and octave combinations, optimizing repeated queries for the same parameters [S2, unofficial].

## How it works
**Inputs:**
- `a`, `b`: 2D spatial coordinates.
- `n_octaves`: Number of octaves to sum.
- `wavelength`: Spatial scale factor for the base noise frequency [S2, unofficial].
- `amp`: Base amplitude multiplier [S2, unofficial].
- `width`, `height`: Dimensions of the noise grid for periodic boundary conditions [S1, unofficial].

**Outputs:**
- A single normalized float value representing the fractal noise at `(a, b)`.

**Data Structures:**
- `noise_data`: A `std::vector<float>` storing the base noise values [S1, unofficial].
- `cache`: A hash map (or dictionary) mapping string keys to float values, storing computed octave results [S2, unofficial].
- `get(x, y)`: Helper function mapping 2D coordinates to 1D index: `index = x * width + y` [S1, unofficial].

**Steps:**

1. **Generate Base Noise (if not cached or initial):**
   The base noise grid is filled with random values.
   - For each cell in the grid, generate a random value $0.0$ or $1.0$ using `rand() % 2` [S1, unofficial].

2. **Calculate Smooth Noise for a Specific Octave:**
   Function `generateSmoothNoise(octave, a, b)`:
   - Determine period: $P = 2^{\text{octave}}$ [S1, unofficial].
   - Determine frequency: $f = 1.0 / P$ [S1, unofficial].
   - Calculate sample coordinates:
     - $x_0 = \lfloor a \cdot f \rfloor$
     - $x_1 = x_0 + 1$
     - $y_0 = \lfloor b \cdot f \rfloor$
     - $y_1 = y_0 + 1$
   - Wrap coordinates using modulo arithmetic with grid dimensions:
     - $x_0 = x_0 \pmod{\text{width}}$
     - $x_1 = x_1 \pmod{\text{width}}$
     - $y_0 = y_0 \pmod{\text{height}}$
     - $y_1 = y_1 \pmod{\text{height}}$
   - Retrieve base noise values:
     - $n_{00} = \text{get}(x_0, y_0)$
     - $n_{10} = \text{get}(x_1, y_0)$
     - $n_{01} = \text{get}(x_0, y_1)$
     - $n_{11} = \text{get}(x_1, y_1)$
   - Perform bilinear interpolation:
     - Interpolate horizontally at top: $top = n_{00} + (n_{10} - n_{00}) \cdot (a \cdot f - \lfloor a \cdot f \rfloor)$ [S1, unofficial].
     - Interpolate horizontally at bottom: $bottom = n_{01} + (n_{11} - n_{01}) \cdot (a \cdot f - \lfloor a \cdot f \rfloor)$ [S1, unofficial].
     - Interpolate vertically: $result = top + (bottom - top) \cdot (b \cdot f - \lfloor b \cdot f \rfloor)$ [S1, unofficial].
   - Return $result$.

3. **Generate Fractal Noise with Memoization:**
   Function `generate(a, b, n_octaves)`:
   - Construct cache key: $key = \text{"}a\text{,"} + b + \text{","} + n\_octaves$ [S2, unofficial].
   - Check cache:
     - If $key$ exists in cache, return cached value [S2, unofficial].
   - Initialize accumulators:
     - $res = 0.0$
     - $sum\_amp = 0.0$
   - Iterate octaves $o$ from $0$ to $n\_octaves - 1$:

## Subtopics

### Normalized Octave Noise
Scales the octave noise result by the maximum possible amplitude to ensure the output range is consistent regardless of the number of octaves or persistence value [S3, unofficial].
- **Formula:** $\text{result} = \frac{\text{octave3D}(x, y, z, \text{octaves}, \text{persistence})}{\text{MaxAmplitude}(\text{octaves}, \text{persistence})}$ [S3, unofficial].
- **Parameter:** `MaxAmplitude`: A helper function that calculates the sum of amplitudes for the given number of octaves and persistence, used for normalization [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot O)$ for generating $N$ points with $O$ octaves without cache. With cache, subsequent queries for the same key are $O(1)$ [S2, unofficial].
- **Memory Complexity:** $O(W \cdot H)$ for the base noise grid plus $O(K)$ for the cache, where $K$ is the number of unique keys stored [S1, unofficial][S2, unofficial].
- **Strengths:** Caching avoids redundant calculations for repeated samples, improving performance in static scenes or repeated queries [S2, unofficial].
- **Limitations:** Cache can grow unbounded if keys are not managed; periodic boundary conditions may introduce visible seams if not handled carefully [S1, unofficial].

## Background
Originating from implementations in voxel engine projects, this method combines fractal Brownian motion (fBm) techniques with memoization for performance [S1, unofficial][S2, unofficial]. It is used in procedural terrain generation and texture synthesis within voxel-based environments [S1, unofficial][S2, unofficial].
