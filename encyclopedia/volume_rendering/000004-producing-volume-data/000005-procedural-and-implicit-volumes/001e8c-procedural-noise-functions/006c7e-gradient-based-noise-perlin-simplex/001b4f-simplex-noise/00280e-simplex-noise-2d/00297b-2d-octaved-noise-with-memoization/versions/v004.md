# 2D Octaved Noise with Memoization

Also called: 2D OpenSimplex Noise with Memoization, Fractal Noise with Caching, Octave Noise, Perlin-like Noise Generation

## Overview
2D Octaved Noise with Memoization generates complex, self-similar procedural textures by summing multiple octaves of a base 2D noise function (such as Simplex Noise) with decreasing amplitude and increasing frequency, while caching results to avoid redundant calculations [S4, unofficial]. It is primarily used for generating natural phenomena like smoke, fog, and fire, where a richer frequency spectrum is required than a single octave provides [S1]. Unlike standard octave noise which recomputes every sample, this method introduces a memoization layer (hash map or dictionary) keyed by input coordinates and octave count, trading memory for computational speed [S4, unofficial].

## How it works
**Inputs:**
- $(a, b)$: The 2D spatial coordinates to evaluate.
- $n_{octaves}$: The number of octaves to combine.
- $wavelength$: The spatial scale factor for the base noise frequency [S4, unofficial].
- $amp$: The initial amplitude for the first octave [S4, unofficial].
- $lacunarity$: The frequency multiplier for each subsequent octave (typically 2.0) [S1].
- $gain$: The amplitude multiplier for each subsequent octave (typically $1/lacunarity$) [S1].
- $noise(x, y)$: The underlying base 2D noise function (e.g., Simplex Noise) [S4, unofficial].

**Outputs:**
- A single floating-point value representing the fractal noise at $(a, b)$.

**Data Structures:**
- `cache`: A hash map (dictionary) mapping string keys to float values. The key is formatted as `${a},${b},${n_octaves}` [S4, unofficial].
- `grid_`: A 2D float array of size `[width][height]` used by the underlying noise generator if it employs a grid-based approach (e.g., Perlin-like midpoint displacement) [S2, unofficial]. If the base noise is gradient-based (Simplex), this structure is internal to the base noise implementation [S3, unofficial].

**Parameters:**
- $n_{octaves}$: Integer, typically 4–8 for visual detail [S1].
- $wavelength$: Float, controls the base frequency [S4, unofficial].
- $amp$: Float, initial amplitude [S4, unofficial].
- $lacunarity$: Float, frequency multiplier [S1].
- $gain$: Float, amplitude multiplier [S1].

**Algorithm Steps:**

1.  **Cache Key Generation**: Construct a unique key for the current query.
    $$ key = \text{string}(a) + "," + \text{string}(b) + "," + \text{string}(n_{octaves}) $$
    [S4, unofficial]

2.  **Cache Check**: Look up `key` in `cache`. If found, return the cached value immediately [S4, unofficial].

3.  **Initialization**: Initialize `res = 0.0`, `sum_amp = 0.0`, `amp_local = amp` [S4, unofficial].

4.  **Octave Loop**: Iterate $o$ from $0$ to $n_{octaves} - 1$:
    a.  **Calculate Local Amplitude**:
        $$ amp_{local} = \frac{1}{o + 1} \times amp $$
        *Note: Source [S4, unofficial] uses `1/oct` which is undefined for $o=0$. Standard practice and the context of "decreasing amplitude" implies a decay factor. If $lacunarity$ and $gain$ are used, the formula is $amp_{local} = amp \times gain^o$. The source [S4, unofficial] snippet `amp_local = (1/oct)*this.amp` is likely a simplified or erroneous representation of persistence. We use the standard gain-based formula for correctness, or if strictly following [S4, unofficial]'s intent of decreasing weight, use $amp \times (1/2)^o$ assuming lacunarity=2. Given [S1] states gain is generally $1/lacunarity$, we use:*
        $$ amp_{local} = amp \times gain^o $$
        [S1][S4, unofficial]
    b.  **Accumulate Amplitude**:
        $$ sum\_amp = sum\_amp + amp_{local} $$
        [S4, unofficial]
    c.  **Evaluate Base Noise**:
        Calculate the scaled coordinates for the current octave:
        $$ x_{scaled} = o \times \frac{a}{wavelength} $$
        $$ y_{scaled} = o \times \frac{b}{wavelength} $$
        *Note: Source [S4, unofficial] uses `oct*(a/this.wavelength)`. This implies the frequency increases linearly with octave index $o$, which is a specific variant. Standard fractal noise uses $lacunarity^o$. We follow the source's explicit formula but note the deviation from standard lacunarity-based scaling if $lacunarity \neq 1$. If $lacunarity$ is provided, the standard formula is $lacunarity^o \times a / wavelength$. We provide the source's explicit logic:*
        $$ val = noise(x_{scaled}, y_{scaled}) $$
        [S4, unofficial]
    d.  **Accumulate Result**:
        $$ res = res + amp_{local} \times val $$
        [S4, unofficial]

5.  **Normalization**:
    $$ ans = \frac{res}{sum\_amp} $$
    [S4, unofficial]

6.  **Cache Storage**: Store `ans` in `cache` with `key` [S4, unofficial].

7.  **Return**: Return `ans` [S4, unofficial].

**Pseudocode:**

```python
def octave_noise_memoized(a, b, n_octaves, wavelength, amp, gain, noise_func, cache):
    """
    Computes 2D octaved noise with memoization.
    
    Args:
        a, b: Input coordinates.
        n_octaves: Number of octaves.
        wavelength: Spatial scale factor.
        amp: Initial amplitude.
        gain: Amplitude multiplier per octave (typically 1/lacunarity).
        noise_func: Base 2D noise function.
        cache: Dictionary for memoization.
        
    Returns:
        Normalized fractal noise value.
    """
    # Step 1: Generate cache key
    key = f"{a},{b},{n_octaves}"
    
    # Step 2: Check cache
    if key in cache:
        return cache[key]
    
    # Step 3: Initialize accumulators
    res = 0.0
    sum_amp = 0.0
    current_amp = amp
    
    # Step 4: Iterate octaves
    for o in range(n_octaves):
        # Calculate local amplitude using gain
        # Note: Source [S4, unofficial] uses (1/oct)*amp which is problematic for o=0.
        # Standard definition [S1] uses gain^o. We use gain^o for correctness.
        amp_local = current_amp * (gain ** o)
        
        # Accumulate amplitude
        sum_amp += amp_local
        
        # Calculate scaled coordinates
        # Source [S4, unofficial] uses: oct * (a / wavelength)
        # This implies frequency = o / wavelength. 
        # Standard lacunarity would be: (lacunarity^o) * (a / wavelength)
        # We follow the source's explicit coordinate scaling logic:
        x_scaled = o * (a / wavelength)
        y_scaled = o * (b / wavelength)
        
        # Evaluate base noise
        val = noise_func(x_scaled, y_scaled)
        
        # Accumulate result
        res += amp_local * val
        
        # Update current_amp for next iteration if gain is not applied via power
        # In the gain^o model, current_amp doesn't change, but amp_local does.
        # If using a multiplicative gain per step:
        current_amp = current_amp * gain 

    # Step 5: Normalize
    if sum_amp == 0:
        ans = 0.0
    else:
        ans = res / sum_amp
        
    # Step 6: Cache result
    cache[key] = ans
    
    # Step 7: Return
    return ans
```

**Edge Cases and Pitfalls:**
- **Division by Zero**: If `sum_amp` is zero (e.g., if all amplitudes are zero), the normalization step must handle this to avoid NaN [S4, unofficial].
- **Cache Key Precision**: Floating-point coordinates $a, b$ should be quantized or rounded before creating the cache key to ensure consistent hits, as floating-point arithmetic is not associative [S4, unofficial].
- **Memory Usage**: The cache grows with the number of unique queries. For large terrains or continuous rendering, a Least Recently Used (LRU) eviction policy is recommended, though not specified in the sources [S4, unofficial].
- **Base Noise Choice**: The method assumes the base noise function is continuous and bounded. If the base noise is unbounded, the normalization may not produce a consistent range [S1].

## Subtopics

### Normalized Octave Noise
Scales the octave noise result by the maximum possible amplitude to ensure the output range is consistent regardless of the number of octaves or persistence value [S5, unofficial]. The formula is $result = octave3D(x, y, z, octaves, persistence) / MaxAmplitude(octaves, persistence)$ [S5, unofficial]. $MaxAmplitude$ is a helper function that calculates the sum of amplitudes for the given number of octaves and persistence [S5, unofficial]. This variant is useful when a fixed output range (e.g., [0, 1]) is required for texture blending or lighting calculations [S5, unofficial].

## Operating characteristics
- **Time Complexity**: $O(n_{octaves})$ per unique query after caching. Without caching, it is $O(n_{octaves} \times T_{base})$, where $T_{base}$ is the cost of the base noise function. With caching, repeated queries for the same $(a, b, n_{octaves})$ are $O(1)$ [S4, unofficial].
- **Memory Complexity**: $O(N)$, where $N$ is the number of unique cached queries. Each entry stores a string key and a float value [S4, unofficial].
- **Performance**: Memoization significantly speeds up rendering of static or slowly changing scenes where the same noise values are requested multiple times (e.g., volume rendering steps) [S4, unofficial].
- **Strengths**: Reduces redundant computation; produces complex, natural-looking textures suitable for fire, smoke, and terrain [S1][S4, unofficial].
- **Limitations**: High memory usage for large, dense caches; cache misses result in full computation; the specific coordinate scaling in [S4, unofficial] ($o \times a/wavelength$) may not produce the standard fractal Brownian motion (fBm) spectrum if lacunarity is not 1 [S4, unofficial].

## Background
The concept of combining multiple octaves of noise to create complex spectra was introduced in the context of volumetric fire rendering, where it is referred to as "turbulence" [S1]. The specific implementation with memoization for 2D noise appears in web-based voxel terrain projects, aiming to optimize procedural generation [S4, unofficial]. The underlying base noise functions (Simplex, Perlin) have been developed since the 1980s, with Simplex Noise introduced by Ken Perlin in 2001 to address artifacts in classic Perlin noise [S1][S3, unofficial]. The memoization technique is a general software optimization pattern applied here to procedural noise generation [S4, unofficial].
