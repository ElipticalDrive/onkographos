# 3D Perlin-like Noise and Fractal Brownian Motion (FBM)

Also called: 3D Perlin-like Noise, Fractal Brownian Motion, Fractional Brownian Motion

## Overview
3D Perlin-like Noise generates smooth, pseudo-random scalar values on a 3D unit lattice using gradient interpolation and trilinear blending [S1, S2, S4, unofficial]. Fractal Brownian Motion (FBM) constructs multi-scale, self-similar detail by summing multiple octaves of this base noise with increasing frequency and decreasing amplitude [S3][S5, S6, S7, S8, S10, S14, S18, unofficial]. It solves the problem of creating organic, continuous volumetric structures (such as clouds, terrain, or fog) that lack the repetitive tiling artifacts of simple value noise [S3][S18, unofficial]. It is distinguished from [Simplex Noise](978-simplex-noise.md) by its reliance on a cubic grid and trilinear interpolation rather than a tetrahedral grid and linear interpolation, and from [Value-Noise FBM Texture Generation](16950-value-noise-fbm-texture-generation.md) by using gradient vectors at lattice corners instead of scalar values, providing higher frequency detail at the cost of increased computational overhead per sample [S1, S13, S14, unofficial].

## How it works
The method consists of two parts: the base gradient noise evaluation and the FBM octave summation [S3][S18, unofficial].

### Inputs and Outputs
*   **Input**: A 3D query point $\mathbf{p} = (x, y, z)$, the number of octaves $n$, and parameters for frequency scaling (lacunarity) and amplitude decay (persistence/gain) [S3][S5, S8, S18, unofficial].
*   **Output**: A single scalar value representing the noise intensity at $\mathbf{p}$.

### Data Structures
1.  **Permutation Table**: An array of size 256 (or 512 to handle overflow) containing a shuffled permutation of integers $0..255$ [S11, unofficial]. This maps integer coordinates to gradient indices without using modulo operations [S6, S11, S13, unofficial].
    *   Layout: `int perm[512]` or `std::array<std::uint8_t, 256> m_permutation` [S6, S11, unofficial].
2.  **Gradient Vectors**: A set of pseudo-random vectors assigned to each lattice point [G].
    *   Layout: `Vector3 ranvec[256]` where each vector is normalized [S13, unofficial].

### Base Noise Evaluation (Perlin-like)
The base noise function $N(\mathbf{p})$ evaluates the contribution of the 8 corners of the unit cube containing $\mathbf{p}$ [S1, S2, unofficial].

1.  **Grid Coordinates**: Compute the integer coordinates of the cell containing $\mathbf{p}$ and the fractional offset within the cell:
    $$ i = \lfloor \mathbf{p} \rfloor, \quad \mathbf{f} = \mathbf{p} - i $$
    where $i = (i_x, i_y, i_z)$ and $\mathbf{f} = (f_x, f_y, f_z)$ [S2, S4, S6, unofficial].
2.  **Hashing**: Map the integer coordinates to gradient indices using the permutation table. To avoid out-of-bounds access, indices are masked (e.g., `& 255`) [S11, S13, unofficial]:
    $$ \text{index}_x = i_x \& 255, \quad \text{index}_y = i_y \& 255, \quad \text{index}_z = i_z \& 255 $$
    The gradient index for a corner $(dx, dy, dz)$ is:
    $$ h(dx, dy, dz) = \text{perm}[\text{perm}[\text{perm}[\text{index}_x + dx] + \text{index}_y + dy] + \text{index}_z + dz] $$
    where $dx, dy, dz \in \{0, 1\}$ [S11, S13, unofficial].
3.  **Gradient Retrieval**: Retrieve the gradient vector $\mathbf{g}_{dx,dy,dz}$ corresponding to the hash $h(dx, dy, dz)$ [S13, unofficial].
4.  **Dot Product Contribution**: Calculate the contribution from each corner $k \in \{0..7\}$:
    $$ n_k = \mathbf{g}_k \cdot (\mathbf{p} - \mathbf{v}_k) $$
    where $\mathbf{v}_k$ is the position of the corner (integer coordinates) [S15, unofficial].
5.  **Smoothing/Fade**: Apply a quintic fade function to the fractional coordinates to ensure $C^1$ continuity:
    $$ u = 6f_x^5 - 15f_x^4 + 10f_x^3 $$
    $$ v = 6f_y^5 - 15f_y^4 + 10f_y^3 $$
    $$ w = 6f_z^5 - 15f_z^4 + 10f_z^3 $$
    [S1, S11, S19, unofficial].
6.  **Interpolation**: Perform trilinear interpolation of the 8 corner contributions using the fade values $u, v, w$:
    $$ \text{lerp}(a, b, t) = a + t(b - a) $$
    $$ \text{result} = \text{lerp}(\text{lerp}(\text{lerp}(n_{000}, n_{100}, u), \text{lerp}(n_{010}, n_{110}, u), v), \text{lerp}(\text{lerp}(n_{001}, n_{101}, u), \text{lerp}(n_{011}, n_{111}, u), v), w) $$
    [S1, S2, S13, unofficial].

### Fractal Brownian Motion (FBM) Summation
FBM combines multiple octaves of the base noise $N$ to create fractal detail [S3].

1.  **Initialization**: Set `sum = 0.0`, `amplitude = 0.5` (or 1.0 depending on normalization), `frequency = 1.0` (or base frequency) [S5, S8, S18, unofficial].
2.  **Octave Loop**: For each octave $i$ from $0$ to $n-1$:
    *   Evaluate base noise at the scaled position: $val = N(\mathbf{p} \cdot \text{frequency})$ [S8, S18, unofficial].
    *   Add weighted contribution: `sum += val * amplitude` [S5, S8, unofficial].
    *   Update parameters for next octave:
        $$ \text{frequency} \leftarrow \text{frequency} \times \text{lacunarity} $$
        $$ \text{amplitude} \leftarrow \text{amplitude} \times \text{persistence} $$
        [S5, S7, S8, S18, unofficial].
3.  **Normalization**: Optionally normalize the result by the maximum possible amplitude sum to keep values in a consistent range:
    $$ \text{max\_amp} = \sum_{i=0}^{n-1} \text{persistence}^i $$
    $$ \text{result} = \text{sum} / \text{max\_amp} $$
    [S6, unofficial].

### Parameters
*   **Octaves ($n$)**: Number of noise layers [S9, unofficial]. Typical values: 4–7 [S9, S13, S18, unofficial].
*   **Lacunarity**: Frequency multiplier per octave. Typical value: 2.0 [S7, unofficial][S22].
*   **Persistence (Gain)**: Amplitude multiplier per octave [S9, unofficial]. Typical value: 0.5 [S6, S7, unofficial][S22].
*   **$\beta$ (Beta)**: In the formal definition $B_n(\mathbf{p}) = \sum_{i=1}^n \frac{noise(2^{i-1}\mathbf{p})}{2^{\beta(i-1)}}$, $\beta=1$ corresponds to $1/f$ noise [S3].

### Edge Cases and Pitfalls
*   **Single Octave Limit**: Some implementations (e.g., `fbm3` in [S1, unofficial]) only support a single octave, reducing frequency detail [S1, S2, unofficial].
*   **Hash Function Portability**: Hash functions using trigonometric functions (e.g., `sin`) may produce different results across different GPU architectures [S19, unofficial].
*   **Division by Zero**: Vector normalization or division operations must guard against zero vectors/norms [S13, unofficial].
*   **Boundary Conditions**: When sampling outside defined bounds (e.g., cloud height limits), density should be explicitly clamped to 0 [S18, unofficial].
*   **Integer Overflow**: Corner indices must be masked (e.g., `& 255`) to prevent out-of-bounds access in permutation tables [S13, unofficial].

```python
def fade(t):
    """Quintic fade function for C1 continuity."""
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

def lerp(t, a, b):
    """Linear interpolation."""
    return a + t * (b - a)

def grad(hash_val, x, y, z):
    """
    Compute dot product of gradient and distance vector.
    Uses 12 common 3D gradients (face diagonals).
    """
    h = hash_val & 15
    u = x if h < 8 else y
    v = y if h < 4 else (x if h == 12 or h == 14 else z)
    return (u if (h & 1) == 0 else -u) + (v if (h & 2) == 0 else -v)

def perlin_noise(x, y, z):
    """
    Evaluate 3D Perlin noise at point (x, y, z).
    Assumes global permutation table `PERM` of size 512.
    """
    # 1. Grid coordinates
    xi = math.floor(x) & 255
    yi = math.floor(y) & 255
    zi = math.floor(z) & 255
    
    # 2. Fractional coordinates
    xf = x - math.floor(x)
    yf = y - math.floor(y)
    zf = z - math.floor(z)
    
    # 3. Fade curves
    u = fade(xf)
    v = fade(yf)
    w = fade(zf)
    
    # 4. Hashing corners
    aaa = PERM[PERM[PERM[xi] + yi] + zi]
    aba = PERM[PERM[PERM[xi] + yi + 1] + zi]
    aab = PERM[PERM[PERM[xi] + yi] + zi + 1]
    abb = PERM[PERM[PERM[xi] + yi + 1] + zi + 1]
    baa = PERM[PERM[PERM[xi + 1] + yi] + zi]
    bba = PERM[PERM[PERM[xi + 1] + yi + 1] + zi]
    bab = PERM[PERM[PERM[xi + 1] + yi] + zi + 1]
    bbb = PERM[PERM[PERM[xi + 1] + yi + 1] + zi + 1]
    
    # 5. Gradient contributions
    x1 = lerp(grad(aaa, xf, yf, zf), grad(baa, xf - 1, yf, zf), u)
    x2 = lerp(grad(aba, xf, yf - 1, zf), grad(bba, xf - 1, yf - 1, zf), u)
    y1 = lerp(x1, x2, v)
    
    x3 = lerp(grad(aab, xf, yf, zf - 1), grad(bab, xf - 1, yf, zf - 1), u)
    x4 = lerp(grad(abb, xf, yf - 1, zf - 1), grad(bbb, xf - 1, yf - 1, zf - 1), u)
    y2 = lerp(x3, x4, v)
    
    # 6. Final interpolation
    return lerp(y1, y2, w)

def fbm(x, y, z, octaves=4, lacunarity=2.0, persistence=0.5):
    """
    Evaluate Fractal Brownian Motion.
    """
    total = 0.0
    amplitude = 0.5
    frequency = 1.0
    
    for i in range(octaves):
        total += perlin_noise(x * frequency, y * frequency, z * frequency) * amplitude
        frequency *= lacunarity
        amplitude *= persistence
        
    return total
```

## Subtopics

### [Noise Field Generator](1302-noise-field-generator.md)
Produces a 3D scalar field by summing multiple octaves of gradient-based noise (typically Simplex or Perlin) with varying frequencies and amplitudes, often combined with a linear vertical gradient. It solves the problem of generating realistic, multi-scale organic structures (such as clouds or terrain) in procedural volumes. It is distinguished from [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by its specific implementation of layered Simplex noise with vertical gradient offsets for volumetric density, and from [Global Cloud Cover with Curl Noise](1711-global-cloud-cover-with-curl-noise.md) by its reliance on scalar summation rather than divergence-free vector fields.

### [Global Cloud Cover with Curl Noise](1711-global-cloud-cover-with-curl-noise.md)
Generates global cloud patterns by applying procedural noise to volumetric air blocks within a specified height range, marking the top layer in a cloud map. It creates 2D cloud patterns on a spherical surface by combining octaves of mixed Perlin and Worley noise, subtracting a threshold, and clamping the result.

### [3D Perlin-Worley Noise Texture Generation](2355-3d-perlin-worley-noise-texture-generation.md)
This method generates 3D volumetric density maps for procedural cloud rendering by combining low-frequency Perlin noise for broad cloud mass with inverted Worley (cellular) noise to carve hollows, producing a puffy cumulus appearance. It differs from pure Perlin noise methods by introducing cellular structures that define cloud edges and internal voids, and from pure Worley methods by retaining the organic, continuous mass of gradient-based noise. It builds on [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by using fBm principles to sum multiple noise octaves.

### [Voxel World Generation with Perlin Noise](2556-voxel-world-generation-with-perlin-noise.md)
This method generates a 3D voxel-based world by evaluating fractal Brownian motion (fBm) noise against a threshold to determine voxel existence and material type (stone, dirt, grass). It solves the problem of creating coherent, organic volumetric structures (such as 'blobby' cave systems) from procedural noise, similar to Dungeon Generation (DRG) techniques. It differs from simple binary voxel placement by incorporating multi-directional noise sampling and spatial constraints (like a central spawn room) to ensure playable geometry.

### [Ridged Multifractal](4249-ridged-multifractal.md)
Ridged Multifractal is a fractal noise technique that generates sharp, ridge-like structures by applying a non-linear transformation to the absolute value of base noise, combined with inter-octave feedback. Unlike standard FBM which produces soft, cloud-like volumes, Ridged Multifractal creates high-contrast linear features suitable for terrain ridges or lightning. It builds on [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by replacing the linear summation with a ridge-specific kernel and a multiplicative feedback loop.

### [Value-Noise FBM Texture Generation](16950-value-noise-fbm-texture-generation.md)
Value-Noise FBM Texture Generation creates procedural volumetric textures by summing multiple octaves of value noise, where each octave uses a grid of pre-generated random scalar values interpolated via bilinear filtering. It differs from gradient-based noise (e.g., Perlin) by using scalar values at grid corners rather than gradient vectors, resulting in smoother, cloud-like appearances with lower computational overhead per sample. It is distinct from Worley noise, which uses distance to nearest grid point, and is typically chosen for atmospheric effects where smooth, organic transitions are required.

### [3D Noise Generation with Box Filtering](1323-3d-noise-generation-with-box-filtering.md)
Generates a 3D tiling noise volume and applies a 3×3×3 box blur to hide trilinear interpolation grid artifacts, as advised for procedural volume rendering.
1.  Initialize a 3D array of floats with uniform random values in [0,1] using a seeded PRNG.
2.  For each voxel $(x,y,z)$, compute the average of its 3×3×3 neighborhood $(dx,dy,dz \in [-1,1])$.
3.  Wrap coordinates modulo $d$ (noise dimension) to ensure tiling.
4.  Convert the averaged float to uint8_t in [0,255] and store in the output buffer.
Formula: $v_{out}(x,y,z,c) = \frac{1}{27} \sum_{dx=-1}^{1} \sum_{dy=-1}^{1} \sum_{dz=-1}^{1} v_{in}((x+dx)\%d, (y+dy)\%d, (z+dz)\%d, c) \cdot 255$, where $d$ is the noise dimension, $c$ is the RGBA channel, and $\%$ denotes modulo wrapping for tiling. Parameter: `seed` (uint32_t) for reproducible generation.

### FBM BVH Construction
A specific application of the BVH method to Fractional Brownian Motion (FBM), where octaves are presorted by range and have analytic bounds, requiring no memory storage for bounds [S3].
1.  Presort octaves by range of values (higher to lower) [S3]. This provides the optimal evaluation order for FBM [S3].
2.  Use the analytic expressions for $\Delta_i$ and $s(i,n)$ to compute BVH bounds [S3]. No memory is needed to store them [S3].
3.  For FBM with $\beta=1$, all octaves share the same Lipschitz constant [S3]. Presorting by range of value corresponds to the optimal pre-sorted order for step size maximization [S3].
Formula: For FBM, the function is the octave $o_i$, and the range is $\Delta_{f_i} = \frac{1}{2^{i-1}}$. The sum of ranges from $i$ to $j$ is $s(i, j) = \sum_{m=i}^j \frac{1}{2^{m-1}} = 2 - \frac{1}{2^{j-1}}$ [S3]. For FBM with Lipschitz noise constant $\lambda_{noise}$, the Lipschitz constant of octave $i$ is $\lambda_{f_i} = \lambda_{noise}$, and the total Lipschitz constant is $\lambda_{B_n} = n \cdot \lambda_{noise}$ [S3].

### High Frequency Surface Noise Remapping
Introducing high frequency noise on cloud surfaces by remapping the noise value using a range defined by low frequency noise, used by Guerilla Games [S23, unofficial].
Code: `float density = clamp(remap(noise, 1 - base, 1.0, 0.0, cap), 0.0, cap);` where `remap` linearly maps `value` from `[original_min, original_max]` to `[new_min, new_max]` [S23, unofficial].

### Derivative Erosion FBM
FBM that accumulates derivatives across octaves [S24]. The derivative magnitude dampens amplitude via `1/(1+|grad|^2)`, creating realistic erosion patterns where steep slopes stay smooth [S24].
1.  Initialize `value=0.0`, `deriv=vec2(0.0)`, `amplitude=0.5` [S24].
2.  Loop `octaves`.
3.  Get `n = noisedQ(p * frequency)` [S24].
4.  Accumulate `deriv += n.yz` [S24].
5.  Add `amplitude * n.x / (1.0 + dot(deriv, deriv))` to `value` [S24].
6.  Update `frequency *= 2.0`, `amplitude *= 0.5`, `p = rot * p` [S24].

### Tileable Volume Noise Generation
A compute shader process that generates four specific noise textures used for volumetric cloud rendering, including Perlin-Worley FBM, Worley FBM, Curl Noise, and Weather Data [S25, unofficial].
Layout:
*   PerlinWorleyFBM texture: 128×128×128 resolution, RGBA8 format [S25, unofficial]. Channel mapping: R=Perlin-Worley, G/B/A=3 layers of Worley FBM [S25, unofficial].
*   WorleyFBM texture: 32×32×32 resolution, RGBA8 format [S25, unofficial]. Content: 3 layers of Worley FBM used for erosion [S25, unofficial].
*   CurlNoise texture: 128×128 resolution, RGBA8 format [S25, unofficial]. Status: Reserved [S25, unofficial].
*   WeatherData texture: 2048×2048 resolution, RGBA8 format [S25, unofficial]. Channel mapping: R=coverage, G=type/rain, B=reserved [S25, unofficial].

### Perlin Noise Erosion
A technique to erode the surface of an SDF by adding negative Perlin noise values to the signed distance, effectively pushing the surface outward where noise is negative [S26, unofficial].
1.  Check if `noise_amplitude > 0.0f`. If so, proceed [S26, unofficial].
2.  Sample 3D Perlin noise using FBM (Fractional Brownian Motion) at `pos` scaled by `noise_scale` [S6, unofficial]. Parameters: 4 octaves, 2.0 lacunarity, 0.5 gain [S26, unofficial].
3.  Check if `noise_value < 0.0f`. If so, apply erosion [S26, unofficial].
4.  Update `min_dist` by adding the scaled negative noise: `min_dist += -noise_value * noise_amplitude` [S26, unofficial].
Parameters: `noise_amplitude` (magnitude of erosion), `noise_scale` (frequency scaling) [S26, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(n \cdot k)$ per sample, where $n$ is the number of octaves and $k$ is the cost of the base noise evaluation (constant for fixed lattice size) [S3]. FBM requires $n$ calls to the base noise function [S3][S6, unofficial].
*   **Memory Complexity**: $O(1)$ for the algorithm itself, plus $O(P)$ for the permutation table where $P$ is the table size (typically 256 or 512) [S6, S11, S13, unofficial].
*   **Measured Performance**: Performance depends heavily on the hash function implementation [S19, unofficial]. Hash functions using trigonometric functions (`sin`) can cause unexpected behavior and performance variations across different GPU architectures [S19, unofficial].
*   **Scaling**: FBM scales well with octaves to add detail, but high octave counts increase computational cost linearly [S3][S6, unofficial].
*   **Strengths**: Produces smooth, continuous, organic-looking noise with high-frequency detail via fractal summation [S3][S18, unofficial].
*   **Limitations**: Single-octave implementations lack detail [S1, unofficial]. Trilinear interpolation can introduce grid artifacts, mitigated by box filtering or higher-order interpolation [S24]. Tiling requires careful handling of boundaries or post-processing blur [S24].
*   **When to Use**: Ideal for procedural generation of natural phenomena (clouds, terrain, smoke) where organic, multi-scale detail is required [S3][S18, unofficial].
*   **When Not to Use**: When strict tiling without post-processing is required without additional steps [S24], or when computational resources are extremely limited and lower-frequency detail is sufficient [S14, unofficial].

## Background
FBM was introduced as a method to generate fractal-like noise with many frequencies by summing variations of a single base noise function [S3]. It has been used extensively in computer graphics to create stochastic patterns with details at potentially many different scales [S3]. The base Perlin noise algorithm was developed by Ken Perlin [S11, unofficial]. The specific FBM formulation with $\beta=1$ corresponds to $1/f$ noise, commonly found in nature [S3].
