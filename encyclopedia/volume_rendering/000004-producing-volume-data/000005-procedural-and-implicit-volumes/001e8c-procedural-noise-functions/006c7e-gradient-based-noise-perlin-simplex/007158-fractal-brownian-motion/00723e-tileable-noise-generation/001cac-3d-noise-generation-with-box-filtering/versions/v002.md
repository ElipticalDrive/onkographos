# 3D Noise Generation with Box Filtering

Also called: Box-blurred random noise, Tiling noise volume generation

## Overview
This method generates a 3D tiling noise volume by initializing a grid with uniform random values and applying a 3×3×3 box blur to hide trilinear interpolation grid artifacts [S1, unofficial]. It enforces seamless tiling via modulo coordinate wrapping before averaging [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `dim` (integer, noise volume dimension), `seed` (uint32_t, PRNG seed).
- Output: A 3D buffer of size $dim \times dim \times dim$ with 4 channels (RGBA), stored as `uint8_t` in $[0, 255]$ [S1, unofficial].

**Data Structures:**
- `raw`: A 1D array of floats of size $dim^3 \times 4$, storing initial random values in $[0, 1]$ [S1, unofficial].
- `out`: A 1D array of `uint8_t` of size $dim^3 \times 4$, storing the final blurred values [S1, unofficial].

**Steps:**
1. **Initialization**: Create a seeded pseudo-random number generator (PRNG) using `seed` and fill the `raw` array with uniform random floats in $[0, 1]$ [S1, unofficial].
2. **Box Filtering**: For each voxel $(x, y, z)$ and channel $c \in \{0, 1, 2, 3\}$, compute the average of the 27 neighbors in the 3×3×3 neighborhood [S1, unofficial].
3. **Coordinate Wrapping**: Wrap coordinates modulo `dim` to ensure tiling [S1, unofficial].
4. **Quantization**: Convert the averaged float value to an 8-bit integer in $[0, 255]$ and store in `out` [S1, unofficial].

**Formula:**
The value at output coordinate $(x, y, z)$ for channel $c$ is:
$$
v_{out}(x,y,z,c) = \frac{1}{27} \sum_{dx=-1}^{1} \sum_{dy=-1}^{1} \sum_{dz=-1}^{1} v_{in}((x+dx)\%d, (y+dy)\%d, (z+dz)\%d, c) \cdot 255
$$
where $d$ is the noise dimension, $c$ is the RGBA channel index, and $\%$ denotes modulo wrapping [S1, unofficial].

**Parameters:**
- `seed`: `uint32_t`. Typical value: any 32-bit integer for reproducibility [S1, unofficial].
- `dim`: Integer. Typical value: Not given in the sources.

**Pseudocode:**
```python
def generate_tiling_noise(dim: int, seed: int) -> list:
    import random
    if dim <= 0:
        raise ValueError("dim must be greater than 0") # [G]
    random.seed(seed)
    
    raw_size = dim * dim * dim * 4
    raw = [random.uniform(0.0, 1.0) for _ in range(raw_size)]
    out = [0] * raw_size
    
    for z in range(dim):
        for y in range(dim):
            for x in range(dim):
                for c in range(4):
                    total = 0.0
                    for dx in (-1, 0, 1):
                        for dy in (-1, 0, 1):
                            for dz in (-1, 0, 1):
                                wx = (x + dx + dim) % dim
                                wy = (y + dy + dim) % dim
                                wz = (z + dz + dim) % dim
                                idx = ((wz * dim + wy) * dim + wx) * 4 + c
                                total += raw[idx]
                    
                    avg = total / 27.0
                    out_val = int(avg * 255)
                    if out_val < 0:
                        out_val = 0
                    elif out_val > 255:
                        out_val = 255
                    out_idx = ((z * dim + y) * dim + x) * 4 + c
                    out[out_idx] = out_val
    return out
```

**Edge Cases and Pitfalls:**
- **Precision**: Floating point accumulation in the sum may introduce minor errors; using `float` is sufficient for 27 additions [S1, unofficial].
- **Boundaries**: Modulo wrapping is critical for tiling [S1, unofficial].
- **Degenerate Input**: `dim` must be $> 0$. If `dim` is 1, the box filter averages the single value with itself 27 times, resulting in the same value [G].

## Subtopics

### 3D Texture Noise
A variant that pre-computes a 64×64×64 3D texture of random values and pre-filters it to avoid linear interpolation artifacts during runtime [S2, unofficial]. At runtime, it performs 4 lookups into this single texture to produce turbulence [S2, unofficial]. It is chosen when runtime performance is critical and the noise pattern can be pre-computed [S2, unofficial].

## Operating characteristics
- **Time Complexity**: $O(dim^3)$, as each voxel requires 27 lookups and an average [S1, unofficial].
- **Memory Complexity**: $O(dim^3)$ for storing the raw and output buffers [S1, unofficial].
- **Performance**: Not given in the sources.
- **Strengths**: Simple to implement; effectively hides trilinear interpolation artifacts; supports seamless tiling [S1, unofficial].
