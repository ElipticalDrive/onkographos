# Modified Noise (Dimension-Reducible)

Also called: Dimension-reducible noise

## Overview
Modified Noise is a gradient-based procedural noise function designed to optimize 3D noise calculation on GPUs by exploiting dimension reducibility [S1, unofficial]. It differs from standard Perlin noise by selecting gradient vectors from the corners of a unit-n cube rather than the edge centers, a geometric constraint required to decompose 3D evaluation into independent 2D noise and 1D gradient lookups [S1, unofficial]. This allows the noise to be stored in 2D textures (or a single 2-channel texture) and computed with minimal texture fetches, making it suitable for real-time volumetric rendering of effects like fire and smoke [S1, unofficial].

## How it works
Modified Noise computes a scalar value $n(\mathbf{P})$ at a query point $\mathbf{P} = (x, y, z)$ by reducing the 3D problem into two 2D hash lookups and a linear interpolation along the $z$-axis [S1, unofficial].

### Inputs and Outputs
- **Input**: Query point $\mathbf{P} = (x, y, z)$.
- **Output**: Scalar noise value $n(\mathbf{P})$.

### Data Structures
The method relies on pre-computed or on-the-fly hash generation [S1, unofficial]. For performance, gradients are typically pre-baked into textures [S1, unofficial].
1. **2D Noise Texture ($T_{noise}$)**: Stores the 2D noise contribution for integer $z$ slices [S1, unofficial].
2. **Z-Gradient Texture ($T_{zgrad}$)**: Stores the gradient contribution along the $z$-axis for integer $z$ slices [S1, unofficial].
3. **Alternative Single Texture ($T_{combined}$)**: A 2-channel texture where each texel returns a pair $(v, g)$ [S1, unofficial].

### Hash Function
The hash function maps integer coordinates to gradient indices [S1, unofficial]. The source specifies a simple modular hash:
$$ \text{hash}(i) = i^2 \mod M $$
where $M$ is the size of the hash table/texture dimension [S1, unofficial].

For a query point $\mathbf{P}$, let $p_x, p_y, p_z$ be the integer coordinates of the cell corners [S1, unofficial]. The 2D hash terms for the integer $z$ values below ($c_0$) and above ($c_1$) the noise argument are computed as:
$$ c_0 = (p_x, p_y, \text{hash}(p_z)) $$
$$ c_1 = (p_x, p_y, \text{hash}(p_z + 1)) $$
The lookup coordinates for the 2D textures are determined by the $x, y$ coordinates and the hashed $z$ index [S1, unofficial].

### Interpolation
The final value is interpolated along the fractional $z$ component ($p_{zf} = z - \lfloor z \rfloor$) using a polynomial interpolation function `flerp` [S1, unofficial].

The `flerp` function is defined as:
$$ \text{flerp}(t, a, b) = (1 - \text{polynomial}(t)) \cdot a + \text{polynomial}(t) \cdot b $$
where $\text{polynomial}(t)$ is either a Cubic Hermite or Quintic Hermite polynomial [S1, unofficial].

### Algorithm Steps
1. **Decompose Input**: Extract integer parts $p_x, p_y, p_z$ and fractional part $p_{zf}$ from $\mathbf{P}$ [S1, unofficial].
2. **Compute Hash Indices**: Calculate $h_0 = \text{hash}(p_z)$ and $h_1 = \text{hash}(p_z + 1)$ [S1, unofficial].
3. **Define Lookup Coordinates**: Set $c_0 = (p_x, p_y, h_0)$ and $c_1 = (p_x, p_y, h_1)$ for the 2D texture lookups [S1, unofficial].
4. **Lookup Values**: Retrieve $v_0, g_0$ from $c_0$ and $v_1, g_1$ from $c_1$ [S1, unofficial].
5. **Interpolate**: Compute $val_0 = v_0 + p_{zf} \cdot g_0$ and $val_1 = v_1 + p_{zf} \cdot g_1$, then $n(\mathbf{P}) = \text{flerp}(p_{zf}, val_0, val_1)$ [S1, unofficial].

### Pseudocode
```python
def modified_noise_3d(x, y, z, hash_table_size=256, noise_data=None, zgrad_data=None):
    """
    Computes Modified Noise at point (x, y, z).
    Assumes pre-baked data structures noise_data and zgrad_data are accessible.
    """
    # 1. Decompose coordinates
    px = int(x) if x >= 0 else int(x) - 1
    py = int(y) if y >= 0 else int(y) - 1
    pz = int(z) if z >= 0 else int(z) - 1
    pzf = z - pz  # Fractional z component

    # 2. Compute hash indices for z-slices
    # Hash function: h(i) = i^2 mod M
    h0 = (pz * pz) % hash_table_size
    h1 = ((pz + 1) * (pz + 1)) % hash_table_size

    # 3. Determine 2D lookup coordinates
    c0 = (px, py, h0)
    c1 = (px, py, h1)

    # 4. Lookup values from textures
    v0, g0 = lookup_combined_texture(c0, noise_data, zgrad_data)
    v1, g1 = lookup_combined_texture(c1, noise_data, zgrad_data)

    # 5. Interpolate along Z
    val0 = v0 + pzf * g0
    val1 = v1 + pzf * g1

    # 6. Apply polynomial interpolation (flerp)
    poly = quintic_hermite(pzf)
    result = (1 - poly) * val0 + poly * val1
    return result

def quintic_hermite(t):
    return 6 * t**5 - 15 * t**4 + 10 * t**3

def lookup_combined_texture(coord, noise_data, zgrad_data):
    """
    Retrieves noise and z-gradient values from pre-baked data structures.
    Returns (noise_value, z_gradient_value)
    """
    px, py, h = coord
    # Simple array lookup for demonstration; replaces GPU texture fetch
    v = noise_data[px % len(noise_data)][py % len(noise_data)][h]
    g = zgrad_data[px % len(zgrad_data)][py % len(zgrad_data)][h]
    return v, g
```

### Parameters and Edge Cases
- **Hash Table Size ($M$)**: Determines the period of the noise [S1, unofficial]. Typical values are powers of 2 (e.g., 256, 512) for efficient modulo operations [G].
- **Polynomial Choice**: The source mentions both Cubic and Quintic Hermite polynomials for `flerp` [S1, unofficial].
- **Precision**: Using `x^2 mod M` can introduce patterns if $M$ is not chosen carefully (e.g., if $M$ shares factors with the coordinate range) [S1, unofficial].
- **Boundary Conditions**: The hash function must handle negative integer coordinates correctly [G].

## Operating characteristics
- **Time Complexity**: $O(1)$ per noise evaluation [S1, unofficial]. The cost is dominated by two texture lookups and a few arithmetic operations [S1, unofficial].
- **Memory Complexity**: $O(N^2)$ for 2D textures, where $N$ is the resolution of the hash table/texture [S1, unofficial]. This is significantly less than the $O(N^3)$ required for a full 3D texture [S1, unofficial].
- **Performance**: Optimized for GPUs [S1, unofficial]. The source notes that the low-level OpenGL shader code for 2D Modified noise is 45 instructions, which is too many for a function used several times for the same pixel; this is handled by pre-baking the gradient texture using the hash procedure [S1, unofficial].
- **Strengths**: Dimension reducibility allows efficient storage and computation [S1, unofficial]. It produces a "fluid" character with large, solid parts that separate naturally, making it suitable for fire and smoke [S1, unofficial].
- **Limitations**: Requires pre-computation or texture storage for optimal performance [S1, unofficial]. The visual character differs from Perlin noise due to corner-based gradient selection, which may not be desirable for all applications [S1, unofficial].

## Background
Modified Noise was introduced in the context of real-time volumetric rendering of fire in a production system [S1, unofficial]. It was developed to address the performance constraints of rendering complex volumetric effects like fire, smoke, and fog on hardware with limited texture bandwidth and instruction count [S1, unofficial]. The method exploits the dimension reducibility property to store 3D noise data in 2D textures, optimizing the calculation process [S1, unofficial]. It is distinct from Perlin noise in its gradient selection strategy, picking gradients from the corners of a unit-n cube to satisfy the dimension reducibility requirement [S1, unofficial].
