# Gradient-based Noise (Perlin/Simplex)


## Overview
Gradient-based noise generates smooth, continuous scalar fields by interpolating dot products of pseudo-random gradient vectors assigned to lattice points [G]. It solves the problem of creating organic, non-repetitive procedural textures for volume rendering, avoiding the blocky artifacts of value noise and the directional bias of simple linear interpolation [G]. It is distinguished from [Value Noise](4008-value-noise.md) by using gradient vectors at lattice corners rather than scalar values, providing higher frequency detail and $C^1$ continuity [G].

## Shared principles
The family shares the following mechanism, terms, and math:

1.  **Gradient Assignment**: Each integer lattice point (vertex) in the domain is assigned a pseudo-random gradient vector $\mathbf{g}$ [G].
2.  **Dot Product Contribution**: The noise value at a query point $\mathbf{P}$ is derived from the dot product between the gradient vector $\mathbf{g}_i$ at a lattice corner $i$ and the distance vector $\mathbf{d}_i = \mathbf{P} - \mathbf{V}_i$ from that corner to $\mathbf{P}$:
    $$ n_i = \mathbf{g}_i \cdot \mathbf{d}_i $$ [G].
3.  **Smoothing/Fade Function**: To ensure smooth transitions ($C^1$ continuity), the fractional coordinates of $\mathbf{P}$ within the cell are passed through a fade function $f(t)$ before interpolation [G]. The quintic function $f(t) = 6t^5 - 15t^4 + 10t^3$ is standard for Perlin variants, while Simplex uses a different geometric approach [G].
4.  **Interpolation**: The contributions from the cell corners are combined using linear interpolation (`lerp`) along the axes, weighted by the fade values [G].
5.  **Hashing**: Integer coordinates are mapped to gradient indices using a permutation table to avoid modulo operations and ensure uniform distribution [G].

## Subtopics

### [Simplex Noise](978-simplex-noise.md)
Simplex Noise is a gradient-based procedural noise function that generates smooth, continuous scalar fields by mapping input coordinates to a skewed simplex lattice (triangles in 2D, tetrahedra in 3D, pentachora in 4D) and summing weighted dot products of gradient vectors. It solves the problem of directional artifacts and high computational complexity inherent in the original integer-lattice Perlin Noise by utilizing a simplex grid, which provides a more even distribution of grid points and fewer gradient contributions per sample. Unlike standard Perlin Noise which uses a square grid and requires four gradient evaluations in 2D, Simplex Noise 2D uses a triangular grid and requires only three gradient evaluations, lowering computational complexity and eliminating undesired directional artifacts. It scales to higher dimensions ($n$) with complexity $O(n^2)$ compared to $O(n 2^n)$ for classic noise, making it easier to implement in hardware and suitable for higher-dimensional volume rendering.

### [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md)
3D Perlin-like Noise generates smooth, pseudo-random scalar values on a 3D unit lattice using gradient interpolation, while Fractal Brownian Motion (FBM) constructs multi-scale, self-similar detail by summing multiple octaves of this base noise with increasing frequency and decreasing amplitude. It solves the problem of creating organic, continuous volumetric structures (such as clouds, terrain, or fog) that lack the repetitive tiling artifacts of simple value noise. It is distinguished from [Simplex Noise](978-simplex-noise.md) by its reliance on a cubic grid and trilinear interpolation rather than a tetrahedral grid and linear interpolation, and from [Value-Noise FBM Texture Generation](16950-value-noise-fbm-texture-generation.md) by using gradient vectors at lattice corners instead of scalar values, providing higher frequency detail at the cost of increased computational overhead per sample.

### [Improved Perlin Noise (4D)](3723-improved-perlin-noise-4d.md)
Improved Perlin Noise (4D) is a procedural noise function that generates smooth, continuous random values by interpolating dot products of gradient vectors at the corners of a 4D hypercube. It extends the 3D Improved Perlin Noise algorithm to four dimensions, primarily to support time-varying texture generation and animation by treating time as the fourth spatial axis. Unlike its 3D sibling, it requires handling 16 corners and 4D gradient vectors, often optimized for graphics hardware using texture-based lookup tables to avoid branching.

### [Value Noise](4008-value-noise.md)
Value Noise generates pseudo-random, spatially continuous scalar fields by assigning random values to integer lattice points and smoothly interpolating between them using Hermite interpolation. It differs from Gradient-based Noise (Perlin/Simplex) by using scalar lattice values instead of gradient vectors, making it computationally simpler but potentially prone to axis-aligned artifacts if the smoothing function is insufficient.

### [Perlin Noise 2D](4211-perlin-noise-2d.md)
Perlin Noise 2D is a lattice gradient noise function that generates smooth, pseudo-random scalar values by interpolating dot products of gradient vectors and distance vectors at the corners of the integer lattice cell containing the query point. It solves the problem of creating continuous, coherent procedural textures for volumetric data (such as clouds, terrain, or smoke) without the repeating patterns of simple value noise. It sets itself apart from its sibling [Simplex Noise](978-simplex-noise.md) by using a square grid topology and cubic/quintic interpolation, whereas Simplex uses a triangular grid to reduce directional artifacts. It is distinguished from [Improved Perlin Noise (4D)](3723-improved-perlin-noise-4d.md) by operating in two dimensions, resulting in lower computational cost but potentially higher grid-oriented artifacts.

### [Perlin Gradient and Interpolation Functions](5415-perlin-gradient-and-interpolation-functions.md)
This article defines the core mathematical primitives—gradient selection, fading (smoothing), and linear interpolation—used to construct gradient-based noise functions like Perlin noise. It solves the problem of generating continuous, differentiable scalar fields from discrete lattice points by ensuring $C^1$ continuity (smooth first derivatives) to eliminate grid-aligned artifacts. It differs from sibling methods primarily in its specific choice of the quintic fade polynomial and the 12-gradient vector set for 3D, whereas Simplex noise uses a different lattice structure and interpolation geometry.

### [Curl Noise](17018-curl-noise.md)
Curl noise is a procedural noise function designed to generate time-varying, incompressible turbulent velocity fields. It solves the problem of creating visually plausible fluid-like motion without the computational cost of solving the Navier-Stokes equations. Unlike standard gradient noise which produces scalar fields, curl noise produces vector fields where the divergence is identically zero, ensuring the flow is solenoidal.

### Gradient Displacement Noise
#### definition
- [S1] Simulates fluid transport by displacing coordinates using per-octave gradient vectors derived from noise.
#### step
- [S1] Loop from $i = 1.0$ to $7.0$.
- [S1] Compute gradient vector `gr` using `gradn` with time-modulated position.
- [S1] Scale gradient by a matrix generated by `makem2` with time-modulated parameters.
- [S1] Update position `p` by adding half the gradient.
- [S1] Accumulate result `rz` using a sinusoidal function of noise at `p`, divided by `z`.
- [S1] Mix current position `p` with base position `bp` using factor 0.77.
- [S1] 1. Compute gradient `gr = gradn(i * p * 0.34 + time * 1.0)` using finite differences of noise [G]. 2. Rotate gradient using `makem2`. 3. Displace `p += gr * GRAD_SCALE`. 4. Accumulate sinusoidal ridged noise. 5. Mix displaced `p` with base `bp` using `ADVECTION` [G]. 6. Scale `z`, `p`, and `bp` for next octave [G].
#### parameter
- [S1] FLOW_SPEED=0.6, BASE_SPEED=1.9, ADVECTION=0.77, GRAD_SCALE=0.5.

### Hash-based Value Noise
#### definition
- [S2, unofficial] A simpler 3D noise function using 1D hash interpolation, often called Simplex-like or Value Noise.
#### step
- [S2, unofficial] Define `step = float3(110, 241, 171)`. Compute integer part `i = floor(x)` and fractional part `f = frac(x)` [G].
- [S2, unofficial] Compute smooth interpolation weights: `u = f * f * (3.0 - 2.0 * f)`.
- [S2, unofficial] Perform 3D trilinear interpolation of hash values at the 8 corners of the unit cube using `hash(n + dot(step, float3(x,y,z)))`.

### Perlin-Worley Blend
#### definition
- [S3, unofficial] A hybrid noise technique that blends Perlin and Worley noise using a linear step function based on a weight parameter.
#### step
- [S3, unofficial] Calculate the Perlin component using fBm with its specific parameters: `float perlin = fBm(getPerlinNoise, channelConfig.seed, pos, glm::vec3(1.0f), channelConfig.perlinOctaveCount, channelConfig.perlinFrequency, channelConfig.perlinLacunarity, channelConfig.perlinPersistence);`
- [S3, unofficial] Calculate the Worley component using fBm and invert it: `float worley = 1.0 - fBm(getWorleyNoise, channelConfig.seed, pos, glm::vec3(1.0f), channelConfig.worleyOctaveCount, channelConfig.worleyFrequency, channelConfig.worleyLacunarity, channelConfig.worleyPersistence);`
- [S3, unofficial] Compute the final noise value using a linear step function: `noise = linearStep((1.0f - worley) * channelConfig.worleyWeight, 1.0f, perlin);`
#### parameter
- [S3, unofficial] worleyWeight: A float parameter controlling the blend between Perlin and Worley noise.

### Multiplicative Perlin Noise
#### definition
- [S4, unofficial] A noise model where octaves are shifted to a positive range and multiplied together instead of added, allowing for a larger dynamic range and non-symmetric distribution.
#### step
- [S4, unofficial] Generate each octave's Perlin noise, which has a range of [-1, 1] and a mean of 0.
- [S4, unofficial] Add 1 to each octave's value to shift the range to [0, 2] and the mean to 1.
- [S4, unofficial] Multiply all the shifted octaves together to form the final result.
#### formula
- [S4, unofficial] Expected value is 1, derived from the product of expected values of independent random variables (each octave mean is 1).
#### parameter
- [S4, unofficial] Number of octaves $n$: Determines the theoretical maximum range of $[0, 2^n]$.
#### pitfall
- [S4, unofficial] The actual upper bound is lower than the theoretical $2^n$ because Perlin noise rarely generates extreme values close to -1 or 1.
- [S4, unofficial] Lack of extreme values in Perlin noise results in a lack of true 'empty zones' (values near 0) in the multiplicative result, impacting transmittance calculations.

## Background
Gradient-based noise was introduced by Ken Perlin in 1985 for the movie *Tron* [G]. Simplex Noise was later introduced by Perlin in 2001 to address the directional artifacts and high computational cost of the original grid-based approach [S4, unofficial].
