# Fractal Brownian Motion (fBm) with Perlin Noise

Also called: FBM noise, Fractal Brownian Motion, Fractal Noise, Multi-octave Perlin Noise, Octave Noise, Weighted sum of band-pass noises, octaves

## Overview
Fractal Brownian Motion (fBm) with Perlin Noise is a procedural technique that generates complex, self-similar noise patterns by summing multiple octaves of a base gradient noise function, typically Perlin Noise [S1, unofficial][S5, S9]. It solves the problem of creating natural-looking, detailed textures (such as terrain, clouds, or wood grain) from a simple, smooth noise primitive [S2, S4, unofficial]. Unlike standard Perlin noise, which produces smooth but potentially repetitive patterns, fBm introduces high-frequency detail at smaller scales, mimicking the fractal nature of natural phenomena [S2, unofficial][S9]. It differs from the Turbulence Function [Turbulence Function](16932-turbulence-function.md) primarily in that standard fBm sums signed noise values, whereas turbulence sums the absolute values of noise to create a "white-noise" or billowy effect [S1, S3, unofficial].

## How it works
fBm constructs a composite noise value by iteratively evaluating a base noise function (e.g., Perlin Noise 2D [Perlin Noise 2D](4211-perlin-noise-2d.md)) at increasing frequencies and decreasing amplitudes. The process is defined by a set of parameters controlling the number of layers, the rate of amplitude decay, and the rate of frequency increase.

### Inputs and Outputs
*   **Input:**
    *   `p`: The input coordinate (vector of dimension $d$, typically 2D or 3D).
    *   `octaves`: Integer count of noise layers to sum ($N$).
    *   `persistence`: Float amplitude decay factor per octave ($A$).
    *   `lacunarity`: Float frequency increase factor per octave ($f$).
    *   `seed`: Optional integer for randomizing the gradient table of the base noise.
*   **Output:**
    *   `value`: A scalar float representing the composite noise value. The range depends on normalization; unnormalized, it is roughly $[-\sum A^i, \sum A^i]$.

### Data Structures
No complex data structures are required beyond the state variables for the loop. The base Perlin noise function requires a permutation table (array of 256 integers) and gradient vectors, as defined in [Perlin Noise 2D](4211-perlin-noise-2d.md).

### Parameters and Typical Values
*   **Octaves ($N$):** Number of iterations. Typical range: 1–8 for performance, up to 12+ for high detail [S2, S4, unofficial].
*   **Persistence ($A$):** Amplitude multiplier. Typical value: $0.5$ (halving amplitude each octave) [S2, S7, unofficial][S9].
*   **Lacunarity ($f$):** Frequency multiplier. Typical value: $2.0$ (doubling frequency each octave) [S2, unofficial][S9]. Note: For tiling textures, lacunarity must be a power of 2 [S6, unofficial].
*   **Weight ($w_i$):** In general fBm, the weight of octave $i$ is $A^i$. Perlin originally proposed $1/2^i$ for $1/f$ spectral content [S5].

### Algorithm Steps
1.  Initialize `total_value` to $0.0$.
2.  Initialize `current_amplitude` to $1.0$.
3.  Initialize `current_frequency` to $1.0$.
4.  Initialize `current_position` to `p`.
5.  Initialize `max_possible_value` to $0.0$ (for normalization).
6.  Loop `i` from $0$ to `octaves` - 1:
    a.  Evaluate the base noise function at `current_position * current_frequency`. Let this be `n`.
    b.  Compute the weighted contribution: `contribution = n * current_amplitude`.
    c.  Add `contribution` to `total_value`.
    d.  Add `current_amplitude` to `max_possible_value`.
    e.  Update `current_amplitude` by multiplying by `persistence` ($A$).
    f.  Update `current_frequency` by multiplying by `lacunarity` ($f$).
    g.  (Optional) Transform `current_position` to avoid alignment artifacts (e.g., rotation or shifting) [S3, S4, unofficial].
7.  Normalize `total_value` by dividing by `max_possible_value` (if `max_possible_value` > 0) to ensure consistent output range regardless of octaves [S2, S6, unofficial].
8.  Return `total_value`.

### Formulas
The general mathematical definition of fBm is:
$$ \text{FBM}(\mathbf{x}) = \sum_{i=0}^{N-1} w_i N(2^i \mathbf{x}) $$
where $N$ is the band-pass noise function, $w_i$ is the weight of band $i$ (typically $A^i$), and $2^i$ represents the frequency scaling [S5].

A common specific implementation with $A=0.5$ and $f=2$ is:
$$ \text{Fractal} = A \cdot \text{Noise}(\mathbf{p}, 1) + A^2 \cdot \text{Noise}(\mathbf{p}, f) + A^3 \cdot \text{Noise}(\mathbf{p}, f^2) + \dots $$

### Pseudocode
```python
def fbm_perlin(p, octaves, persistence, lacunarity, seed):
    """
    Computes Fractal Brownian Motion using Perlin Noise.
    
    Args:
        p: Input coordinate (vec2 or vec3).
        octaves: Number of octaves (int).
        persistence: Amplitude decay factor (float, e.g., 0.5).
        lacunarity: Frequency increase factor (float, e.g., 2.0).
        seed: Random seed for the base noise function.
        
    Returns:
        Normalized noise value in range [-1, 1] (or [0, 1] if abs is used).
    """
    total_value = 0.0
    current_amplitude = 1.0
    current_frequency = 1.0
    max_possible_value = 0.0
    
    # Optional: Shift to avoid grid alignment artifacts
    shift = vec3(100.0, 100.0, 100.0) 
    
    for i in range(octaves):
        # Scale position by frequency
        scaled_p = p * current_frequency
        
        # Optional: Add shift to position for variation between octaves
        # scaled_p = scaled_p + shift
        
        # Evaluate base Perlin noise
        # Note: PerlinNoise2D or PerlinNoise3D must be defined elsewhere
        noise_val = perlin_noise(scaled_p, seed)
        
        # Add weighted contribution
        total_value += noise_val * current_amplitude
        
        # Accumulate max possible value for normalization
        max_possible_value += current_amplitude
        
        # Update amplitude and frequency for next octave
        current_amplitude *= persistence
        current_frequency *= lacunarity
        
        # Optional: Rotate position to break symmetry
        # p = rotate(p, PI / 4.0) 
        
    # Normalize result
    if max_possible_value > 0:
        total_value /= max_possible_value
        
    return total_value
```

### Edge Cases and Pitfalls
*   **Performance:** High octave counts significantly reduce frame rate, especially in raymarchers where the noise function is evaluated per pixel/sample [S4, unofficial].
*   **Aliasing:** The fractal summation must be cut off when the frequency becomes too large for the noise to be properly represented between neighboring pixels (Nyquist limit) [S9].
*   **Tiling:** For periodic textures, lacunarity must be a power of 2 to ensure the texture tiles properly [S6, unofficial].
*   **Turbulence vs. Standard FBM:** Using `abs(noise)` creates a "turbulence" effect (white-noise-like, billowy), while signed noise creates cloudy or terrain-like structures [S1, S3, unofficial].
*   **Band-pass Requirement:** The primitive noise function must be band-pass (zero energy outside a specific frequency interval) rather than merely band-limited to prevent energy overlap between octaves [S5].

## Subtopics

### [Turbulence Function](16932-turbulence-function.md)
A variant of fBm that sums the absolute values of noise octaves (`abs(noise)`), creating a white-noise-like, billowy texture suitable for clouds or fire, rather than the signed, cloudy/terrain-like appearance of standard fBm. Choose this when you need high-contrast, fragmented details.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot C)$, where $N$ is the number of octaves and $C$ is the cost of a single base noise evaluation (which involves hashing, interpolation, etc.).
*   **Memory Complexity:** $O(1)$ for the fBm loop itself, plus $O(1)$ for the base noise permutation table (256 entries).
*   **Performance:** Performance degrades linearly with the number of octaves. In real-time rendering, high octave counts (e.g., >8) can cause significant GPU load, particularly in raymarched scenes where the function is called per fragment [S4, unofficial].
*   **Strengths:** Produces highly detailed, natural-looking, self-similar patterns with few parameters.
*   **Limitations:** Can appear repetitive if not combined with other techniques (e.g., domain warping or turbulence). High frequencies may alias if not clamped.
*   **When to use:** Procedural terrain generation, cloud rendering, wood/marble textures, and any scenario requiring multi-scale natural detail.
*   **When not to use:** When strict periodicity is required with non-power-of-2 lacunarity, or when computational budget is extremely tight and low-frequency detail suffices.

## Background
Fractal Brownian Motion was introduced by Ken Perlin in 1985 [S5][S8, unofficial]. It was designed to generate realistic textures by combining noise functions at different scales, mimicking the fractal properties found in nature. The technique is a cornerstone of procedural generation in computer graphics, widely used in film, games, and scientific visualization. It builds on the foundation of gradient noise functions like Perlin Noise [Perlin Noise 2D](4211-perlin-noise-2d.md).
