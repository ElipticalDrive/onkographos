# Fractal Brownian Motion (fBm) with Perlin Noise

Also called: Fractal Brownian Motion, Fractal Noise, Octave Noise, Multi-octave Perlin Noise

## Overview
Fractal Brownian Motion (fBm) is a technique for generating self-similar, multi-scale noise by summing multiple octaves of a base noise function, where each octave has increasing frequency and decreasing amplitude [S2, S3, S5, unofficial][S6, S10]. It solves the problem of creating natural-looking, detailed procedural textures (such as terrain, clouds, or fire) that simple single-octave noise cannot provide [S3, S5, unofficial]. Unlike simple Perlin noise, which produces smooth but uniform patterns, fBm mimics natural fractal phenomena by adding fine micro-details to coarse macro-structures [S1][S3, unofficial]. It is distinguished from other fractal methods by its specific use of gradient-based noise (like Perlin) as the base primitive and its characteristic geometric scaling of frequency and amplitude [S6, S10].

## How it works
**Inputs and Outputs:**
*   **Input:** A base position $\mathbf{p}$ (2D, 3D, or 4D), the number of octaves $N$, a persistence factor $P$ (amplitude decay), and a lacunarity factor $L$ (frequency increase). Optionally, a seed or time variable for animation [S1][S3, S5, S7, S9, unofficial].
*   **Output:** A scalar noise value, typically normalized to $[0, 1]$ or $[-1, 1]$ [S3, S4, S7, unofficial].

**Data Structures:**
No complex data structures are required for the evaluation itself; it is a stateless function that calls the base Perlin noise function [S5, S7, unofficial]. However, implementations may cache permutation tables for the base Perlin noise [S3, unofficial].

**Parameters:**
*   **Octaves ($N$):** The number of noise layers to sum. Typical range: 1 to 8, or up to 12 for high detail [S3, S5, unofficial]. Values $\ge 3$ are recommended for realistic fire; $\le 2$ for stylized results [S1].
*   **Persistence ($P$):** The factor by which amplitude decreases per octave. Typical value: $0.5$ [S3, S8, unofficial][S10].
*   **Lacunarity ($L$):** The factor by which frequency increases per octave. Typical value: $2.0$ [S1][S3, unofficial][S10]. Note: For tiling noise, lacunarity must be a power of 2 [S7, unofficial].
*   **Frequency Multiplier ($f$):** Sometimes used instead of lacunarity; common value $2$ [S10].
*   **Amplitude Multiplier ($A$):** Commonly $0.5$ [S10].

**Algorithm Steps:**
1.  Initialize `value = 0.0`, `amplitude = 1.0`, `frequency = 1.0` (or `frequency = lacunarity` depending on implementation style) [S2, S4, S8, unofficial].
2.  Loop for `i` from `0` to `octaves - 1`:
    a.  Evaluate the base noise function $N$ at the current scaled position: $n = N(\mathbf{p} \times \text{frequency})$ [S5, unofficial][S6][S8, unofficial].
    b.  Add the weighted noise to the sum: `value += amplitude * n` [S2, S4, S8, unofficial].
    c.  Update amplitude: `amplitude *= persistence` (or `amplitude *= 0.5`) [S2, S3, S4, S5, S8, unofficial].
    d.  Update frequency: `frequency *= lacunarity` (or `frequency *= 2.0`) [S3, S4, S5, S7, S8, unofficial].
3.  Normalize the result. Common normalizations include dividing by the sum of amplitudes or clamping to $[0, 1]$ [S3, S7, unofficial]. If using turbulence (absolute value), return `value` or `value * 2 - 1` [S4, S7, unofficial].

**Formulas:**
The general summation is defined as [S6, S10]:
$$ \text{FBM}(\mathbf{p}) = \sum_{i=0}^{N-1} A^i \cdot N(L^i \cdot \mathbf{p}) $$
Where $A$ is the amplitude multiplier (persistence) and $L$ is the frequency multiplier (lacunarity) [S10].

Perlin originally proposed weights $w_i = 1/2^i$ for $1/f$ spectral content [S6].

**Turbulence:**
A common variant uses the absolute value of the noise to create "turbulence" (white-noise-like texture rather than cloudy) [S2, unofficial]:
$$ \text{Turbulence}(\mathbf{p}) = \sum_{i=0}^{N-1} A^i \cdot |N(L^i \cdot \mathbf{p})| $$

**Pseudocode:**
```python
def fbm_perlin(p, octaves, persistence, lacunarity, noise_func):
    """
    p: input position (vec2 or vec3)
    octaves: int, number of octaves
    persistence: float, amplitude decay (e.g., 0.5)
    lacunarity: float, frequency increase (e.g., 2.0)
    noise_func: function that takes a position and returns float noise in [-1, 1]
    """
    total = 0.0
    amplitude = 1.0
    frequency = 1.0
    
    # Pre-calculate max possible value for normalization if desired
    # max_value = sum(amplitude * persistence^i for i in range(octaves))
    
    for i in range(octaves):
        # Evaluate base noise at scaled position
        noise_val = noise_func(p * frequency)
        
        # Add weighted noise
        total += amplitude * noise_val
        
        # Update amplitude and frequency for next octave
        amplitude *= persistence
        frequency *= lacunarity
        
    # Optional: Normalize to [0, 1] or [-1, 1]
    # Example normalization to [0, 1] assuming noise is in [-1, 1]
    # total = (total / max_value + 1.0) * 0.5
    
    return total
```

**Edge Cases and Pitfalls:**
*   **High Octave Counts:** Significantly reduce frame rate due to nested loop complexity in raymarchers or pixel shaders [S5, unofficial].
*   **Aliasing:** The fractal summation must be cut off when the frequency becomes too large for the noise to be properly represented between neighboring pixels (Nyquist limit) [S10].
*   **Tiling:** Lacunarity must be a power of 2 for the noise to tile properly if periodicity is required [S7, unofficial].
*   **Negative Weights:** Negative weights cannot cancel energy from a frequency band because noise has random phase; the primitive noise function must be band-pass rather than merely band-limited to remove energy at specific frequencies [S6].
*   **Stretching Artifacts:** Enlarging the volume (e.g., fire radius) can stretch noise effects, creating visual artifacts. This is addressed by dynamically scaling "noise space" according to the object's dimensions [S1].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of octaves. Each octave requires one evaluation of the base noise function [S5, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space, excluding the base noise function's internal tables (e.g., permutation table) [S3, S7, unofficial].
*   **Performance:** On nVidia GeForce 7800 GT, 3 octaves of Improved Perlin Noise yielded 66 FPS for a unit fire volume, while M-Noise yielded 141 FPS [S1]. M-Noise is more efficient (~40 instructions/octave) than Improved Perlin (~64 instructions/octave) [S1].
*   **Strengths:** Produces natural, self-similar detail at multiple scales, mimicking natural terrain and fire [S3, unofficial][S1].
*   **Limitations:** High octave counts are computationally expensive [S5, unofficial]. Requires careful handling of frequency scaling to avoid aliasing [S10].

## Background
Fractal Brownian Motion was introduced by Perlin in 1985 [S6, Per85]. It is based on the concept of fractal phenomena described by Mandelbrot [S1]. The technique is widely used in procedural generation for terrain, clouds, and volumetric effects like fire [S1][S5, unofficial][S6]. Goldberg et al. used it to cancel mapping distortions by dynamically adapting weights [S6].

## Subtopics

### Turbulence
A variant of fBm that uses the absolute value of the noise, creating a white-noise-like texture rather than a cloudy one [S2, unofficial].

### M-Noise
A more efficient hardware-friendly approximation of Perlin noise used in fBm, requiring fewer instructions and texture lookups than Improved Perlin Noise [S1].
