# Gradient-based Noise (Perlin/Simplex)

Also called: Gradient Noise, Perlin Noise, Simplex Noise

## Overview
Gradient-based noise functions generate smooth, continuous scalar fields by interpolating dot products of pseudo-random gradient vectors at grid vertices [S1]. They solve the problem of creating coherent, natural-looking procedural textures and volumetric densities without storing large lookup tables [S1]. They are distinguished from Value Noise by using directional gradient vectors rather than scalar corner values, and from Worley Noise by their reliance on grid interpolation rather than distance to nearest seed points [S2, unofficial].

## Shared principles
All gradient-based noise methods share the core mechanism of mapping a query point $P = (x, y, z)$ to a scalar value $V$ through deterministic mathematical operations, ensuring that nearby points yield similar values (coherence) or structured differences, depending on the variant [S1, S2, S3, S4, S5, S6, unofficial][S7].

1.  **Coordinate Normalization:** Input coordinates are often normalized or wrapped to fit specific grid or periodic structures. For grid-based noise, integer cell coordinates are derived via floor operations, while fractional parts determine interpolation weights or distance vectors [S1, S4, S5, unofficial].
2.  **Hashing and Randomness:** To introduce pseudo-randomness without storing large lookup tables, integer coordinates are hashed into floating-point values. Common hash functions use trigonometric operations (e.g., `sin(dot(p, float2(12.9898, 78.233))) * 43758.5453`) or linear congruential generators to produce uniform random values in $[0, 1]$ or $[-1, 1]$ [S4, unofficial][S7].
3.  **Interpolation and Smoothing:** When using grid-based values, smooth transitions are achieved via Hermite interpolation or polynomial falloff functions (e.g., $3t^2 - 2t^3$) to eliminate visible grid artifacts [S5, unofficial][S7].
4.  **Fractal Brownian Motion (FBM):** Complex detail is often generated by summing multiple octaves of a base noise function at different frequencies and amplitudes: $V = \sum_{i=0}^{n} a_i \cdot \text{noise}(f_i \cdot P)$, where $a_i$ is the amplitude and $f_i$ is the frequency (lacunarity) of octave $i$ [S5, S6, unofficial][S7].
5.  **Domain Warping and Advection:** To simulate motion or turbulence, the input coordinates to the noise function are displaced by another noise field or a flow vector, creating non-linear distortions in the resulting density field [S1, S5, unofficial][S7].

## Subtopics

### [Simplex Noise](978-simplex-noise.md)
Simplex Noise is a gradient-based procedural noise function that generates smooth, continuous scalar fields in 2D, 3D, and 4D space. It solves the directional artifacts inherent in earlier grid-based noise functions (like Perlin Noise) by using a skewed simplex grid (triangles in 2D, tetrahedra in 3D) instead of a cubic grid, which reduces computational complexity and improves isotropy. It is primarily used for terrain generation, texture synthesis, and as a density function $f(x,y,z)$ for implicit surfaces or voxel terrain.

### [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md)
3D Perlin-like Noise generates smooth pseudo-random scalar values on a 3D unit lattice using hash-derived corner values, Hermite smoothing, and trilinear interpolation. Fractal Brownian Motion (FBM) constructs multi-scale fractal noise by summing multiple octaves of a base noise function (typically Perlin or Simplex) with increasing frequency and decreasing amplitude. Together, they solve the problem of generating realistic, continuous, and self-similar volumetric structures (such as clouds, fog, or terrain density) without storing large texture maps. They are distinguished from [Simplex Noise](978-simplex-noise.md) by their reliance on a cubic grid and trilinear interpolation rather than a simplex grid and tetrahedral interpolation, and from [Ridged Multifractal](4249-ridged-multifractal.md) by their linear summation which produces soft, cloud-like volumes rather than sharp ridges.

### [Improved Perlin Noise (4D)](3723-improved-perlin-noise-4d.md)
Improved Perlin Noise (4D) is a procedural noise function that extends the 3D gradient-based noise algorithm into four dimensions to generate smooth, coherent random values for time-varying texture generation and volumetric data. It differs from its 3D sibling by treating time as a fourth spatial axis, allowing for continuous animation without temporal aliasing, and utilizes GPU-optimized texture-based lookups for permutation and gradient tables to minimize branching and improve performance over traditional array-based implementations.

### [Perlin Noise 2D](4211-perlin-noise-2d.md)
Perlin Noise 2D is a gradient-based procedural noise function that generates smooth, continuous scalar values by interpolating dot products of gradient vectors and distance vectors at the corners of a unit grid cell. It solves the problem of creating coherent, non-repeating natural-looking textures or heightmaps in 2D space, distinguishing itself from its siblings by using an axis-aligned square grid and quintic interpolation. Unlike Simplex Noise, it does not use triangular tiling, making it susceptible to directional artifacts along the axes if lower-order fade functions are used.

### [Perlin Gradient and Interpolation Functions](5415-perlin-gradient-and-interpolation-functions.md)
This article defines the core mathematical primitives—gradient selection, linear interpolation, and smooth fade curves—used to construct classic Perlin noise. It solves the problem of blending directional dot-product contributions from grid vertices into a continuous scalar field. It differs from [Simplex Noise](978-simplex-noise.md) by using a hypercubic grid and axis-aligned gradients, and from [Improved Perlin Noise (4D)](3723-improved-perlin-noise-4d.md) by focusing on the foundational 3D/2D implementations rather than higher-dimensional or specific optimized variants.

### Gradient Displacement Noise
- **Definition:** Simulates fluid transport by displacing coordinates using per-octave gradient vectors derived from noise [S1].
- **Step:** Loop from $i = 1.0$ to $7.0$. Compute gradient vector `gr` using `gradn` with time-modulated position. Scale gradient by a matrix generated by `makem2` with time-modulated parameters. Update position `p` by adding half the gradient. Accumulate result `rz` using a sinusoidal function of noise at `p`, divided by `z`. Mix current position `p` with base position `bp` using factor $0.77$ [S1]. Specifically: 1. Compute gradient `gr = gradn(i * p * 0.34 + time * 1.0)` using finite differences of noise. 2. Rotate gradient using `makem2`. 3. Displace `p += gr * GRAD_SCALE`. 4. Accumulate sinusoidal ridged noise. 5. Mix displaced `p` with base `bp` using `ADVECTION`. 6. Scale `z`, `p`, and `bp` for next octave [S1].
- **Parameter:** `FLOW_SPEED=0.6`, `BASE_SPEED=1.9`, `ADVECTION=0.77`, `GRAD_SCALE=0.5` [S1].

### Hash-based Value Noise
- **Definition:** A simpler 3D noise function using 1D hash interpolation, often called Simplex-like or Value Noise [S2, unofficial].
- **Step:** Define `step = float3(110, 241, 171)`. Compute integer part `i = floor(x)` and fractional part `f = frac(x)`. Compute smooth interpolation weights: `u = f * f * (3.0 - 2.0 * f)`. Perform 3D trilinear interpolation of hash values at the 8 corners of the unit cube using `hash(n + dot(step, float3(x,y,z)))` [S2, unofficial].

## Background
Gradient-based noise was introduced by Ken Perlin in 1985 for the movie *Tron* [S1]. Simplex Noise was introduced by Perlin in 2001 to address the grid-aligned artifacts of the original Perlin noise [S2, unofficial]. These methods are foundational in procedural generation for games, VFX, and scientific visualization [S3, unofficial].
