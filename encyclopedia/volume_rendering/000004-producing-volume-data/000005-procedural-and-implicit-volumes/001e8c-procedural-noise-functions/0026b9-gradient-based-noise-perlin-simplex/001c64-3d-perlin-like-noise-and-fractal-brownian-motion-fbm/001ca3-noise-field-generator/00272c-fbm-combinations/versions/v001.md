# FBM Combinations

Also called: FBM Application Pipeline, FBM Integration Techniques

## Overview
FBM Combinations refers to the integration of Fractal Brownian Motion (FBM) noise fields with various rendering and geometric techniques to produce complex volumetric and surface effects. It solves the problem of generating realistic, multi-scale detail in procedural volumes and surfaces by layering noise frequencies and combining them with lighting, geometry, and color mapping. It is distinguished from [Terrain Heightmap Generation via Noise](4214-terrain-heightmap-generation-via-noise.md) by its focus on volumetric density and lighting integration rather than pure heightfield displacement, and from [Domain Warped FBM](4493-domain-warped-fbm.md) by its reliance on standard layered sampling rather than recursive coordinate distortion.

## How it works
The method combines the scalar field output of a Noise Field Generator with raymarching, normal estimation, color mapping, and lighting models.

**Inputs and Outputs:**
- Input: 3D position $p$, ray direction $d$, eye position $eye$, light direction $L$, FBM function $f(p)$, epsilon $\epsilon$.
- Output: Color $C$, density $\alpha$, normal $n$.

**Data Structures:**
- Position $p$: `vec3` (float x, y, z).
- Normal $n$: `vec3` (normalized float x, y, z).
- Color $C$: `vec3` (float r, g, b).
- Density $\alpha$: `float` (0.0 to 1.0).

**Steps:**

1. **Raymarching Setup**: Initialize ray origin $O$ and direction $D$. Determine step size $dt$.
   - Adaptive step size: $dt = \max(0.05, 0.02 \cdot t)$, where $t$ is distance along ray [S1].
   - LOD selection: $oct = 5 - \lfloor \log_2(1.0 + t \cdot 0.5) \rfloor$ [S1].

2. **FBM Evaluation**: Evaluate the noise field $f(p)$ at current position $p$.
   - The Noise Field Generator provides the base FBM value [Parent].

3. **Normal Estimation**: Compute surface or density gradient using finite differences.
   - Directional derivative approximation (1 sample):
     $$ n = \text{normalize}(vec3(f(p + \epsilon \cdot ex) - f(p), \epsilon, f(p + \epsilon \cdot ey) - f(p))) $$
     where $ex, ey$ are small perturbations [S1].
   - Full gradient (3 samples) is also possible but more expensive [S1].

4. **Lighting Integration**:
   - **Volumetric Lighting**: Approximate illumination by calculating density difference along the light direction $L$ [S1].
   - **Surface Lighting**: Use $n$ for standard shading models.

5. **Color Mapping**: Map noise values to RGB using power curves.
   - Example (flame-like): $C = vec3(1.5 \cdot c, 1.5 \cdot c^3, c^6)$ [S1].
   - Example (inverse): $C = vec3(k)/r \cdot z$ [S1].

6. **Fresnel Effect (for water/surfaces)**:
   - $Fresnel = pow(1.0 - \text{dot}(n, -eye), 3.0)$ [S1].

7. **Multi-layer Compositing**: Combine shape, ridged, and color layers.
   - Shape layer (low freq) + ridged layer (mid freq) + color layer (high freq) [S1].

8. **Early Termination**: If accumulated density $\alpha > 0.99$, break raymarching loop [S1].

**Pseudocode:**
```python
def fbm_combinations(ray_origin, ray_dir, light_dir, eye_pos, noise_func, epsilon=0.01):
    t = 0.0
    accumulated_alpha = 0.0
    final_color = vec3(0.0)
    
    while t < MAX_DISTANCE and accumulated_alpha < 0.99:
        # Adaptive step size
        dt = max(0.05, 0.02 * t)
        pos = ray_origin + ray_dir * t
        
        # Evaluate FBM
        noise_val = noise_func(pos)
        
        # Estimate normal using finite differences
        # Using directional derivative approximation for efficiency
        ex = vec3(epsilon, 0.0, 0.0)
        ey = vec3(0.0, epsilon, 0.0)
        normal = normalize(vec3(
            noise_func(pos + ex) - noise_func(pos),
            epsilon,
            noise_func(pos + ey) - noise_func(pos)
        ))
        
        # Lighting calculation
        # Volumetric lighting approximation
        light_diff = noise_func(pos + light_dir * epsilon) - noise_func(pos)
        illumination = light_diff * dot(normal, light_dir)
        
        # Color mapping
        color = vec3(1.5 * noise_val, 1.5 * noise_val**3, noise_val**6)
        
        # Fresnel for water-like surfaces
        fresnel = pow(1.0 - dot(normal, -normalize(eye_pos - pos)), 3.0)
        
        # Composite
        final_color += color * illumination * (1.0 - accumulated_alpha)
        accumulated_alpha += noise_val * dt
        
        t += dt
        
    return final_color, accumulated_alpha
```

**Parameters:**
- $\epsilon$: Finite difference step size. Typical value: 0.01 [S1].
- $dt$: Step size. Adaptive formula provided [S1].
- $oct$: LOD level. Formula provided [S1].

**Edge Cases:**
- Precision issues in finite differences if $\epsilon$ is too small or too large [S1].
- Early termination threshold (0.99) prevents over-saturation [S1].
- LOD calculation may produce negative octaves if $t$ is very large; clamp required [G].

## Subtopics

### [Pseudo-Volume Noise Compositing](7075-pseudo-volume-noise-compositing.md)
A procedural noise generation technique that composites four layered noise samples over a pseudo-3D position field, applies a multiplicative cell mask, and combines them to produce a volumetric-like texture output.

## Operating characteristics
- **Time Complexity**: Linear with respect to raymarching steps. Each step involves FBM evaluation and finite difference calculations.
- **Memory Complexity**: Low, as it is procedural and does not store voxel grids.
- **Performance**: Directional derivative (1 sample) is faster than full gradient (3 samples) [S1]. Adaptive step size improves performance in low-detail areas [S1].
- **Strengths**: Real-time capable, high visual quality, flexible integration with lighting and color.
- **Limitations**: Sensitive to $\epsilon$ choice, LOD artifacts if not managed, early termination may cause banding if not handled carefully.

## Background
The techniques described in FBM Combinations are derived from procedural noise shader development practices, particularly those used in real-time rendering and demoscene programming. The specific combinations of FBM with raymarching, finite-difference normals, and power-curve color mapping are documented in shader development resources [S1].
