# Noise Field Generator

Also called: Layered Simplex Noise with Gradient, SimplexNoise3D

## Overview
The Noise Field Generator creates a 3D scalar field for volumetric rendering by summing multiple octaves of gradient-based noise (typically Simplex or Perlin) with varying frequencies and amplitudes, often combined with a linear vertical gradient [S2, unofficial][S3]. It solves the problem of generating natural-looking, multi-scale volumetric textures such as clouds, terrain, or smoke, where single-octave noise lacks sufficient detail [S4, S5, unofficial]. It differs from its parent [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by explicitly incorporating a vertical gradient offset and specific gradient-based noise implementations (like Simplex) into the field generation pipeline, rather than just generic FBM summation [S2, unofficial].

## How it works
**Inputs:**
- `Dims`: 3D integer vector defining the voxel grid dimensions $(D_x, D_y, D_z)$ [S1, S2, unofficial].
- `Scale`: Spatial scaling factor for the noise field [S2, unofficial].
- `Time`: Time variable for animated noise offsets [S2, S4, unofficial].
- `Octaves`: Number of noise layers to sum (typically 4–6) [S3][S4, S5, unofficial].
- `Gain`: Amplitude multiplier per octave (typically 0.5) [S3][S5, unofficial].
- `Lacunarity`: Frequency multiplier per octave (typically 2.0 or slightly varied) [S3][S4, S5, unofficial].
- `NoiseFunction`: A gradient-based noise function (e.g., SimplexNoise) returning values in $[-1, 1]$ or $[0, 1]$ [S2, unofficial][S3].

**Outputs:**
- `Voxels`: A flat 1D array or structured buffer of floats, size $D_x \times D_y \times D_z$, storing the scalar field values [S1, S2, unofficial].

**Data Structures:**
- The output is a linearized 3D grid. Index mapping for voxel $(x, y, z)$ is:
  $$ \text{index} = x + D_x \times (y + D_y \times z) $$
  [S1, S2, unofficial].

**Algorithm Steps:**
1. **Initialize Accumulator:** Set `value` to the vertical gradient component. For a centered coordinate system, this is often `-p.y` or a scaled version thereof [S2, unofficial].
2. **Iterate Octaves:** Loop $i$ from 0 to `Octaves` - 1.
3. **Compute Coordinate:** Calculate the query point $q$.
   - Base position $p$ is derived from voxel indices, scaled and centered:
     $$ p = \text{Scale} \times (\text{id} + 0.5 - \text{Dims} / 2) $$
     [S2, unofficial].
   - Apply time-based drift and frequency scaling:
     $$ q = p \times \text{frequency}_i + \text{offset}_i \times \text{Time} $$
     [S2, S4, unofficial].
     *Note:* In some implementations, the coordinate is rotated between octaves to break axis-aligned artifacts [S3].
4. **Sample Noise:** Evaluate the noise function at $q$:
     $$ n = \text{NoiseFunction}(q) $$
     [S2, S4, unofficial].
5. **Accumulate:** Add the weighted noise to the value:
     $$ \text{value} += n \times \text{amplitude}_i $$
     [S2, S4, unofficial].
6. **Update Parameters:**
   - Frequency: $\text{frequency}_{i+1} = \text{frequency}_i \times \text{Lacunarity}$ [S5, unofficial].
   - Amplitude: $\text{amplitude}_{i+1} = \text{amplitude}_i \times \text{Gain}$ [S5, unofficial].
   - *Variation:* Lacunarity may vary per octave (e.g., 2.02, 2.03) to break self-similarity [S3][S4, unofficial].
7. **Store:** Write `value` to the output buffer at the calculated index [S1, S2, unofficial].

**Pseudocode:**
```python
def generate_noise_field(Dims, Scale, Time, Octaves, Gain, Lacunarity, NoiseFunction):
    """
    Generates a 3D scalar field using layered noise with gradient.
    Dims: tuple (dx, dy, dz)
    Scale: float
    Time: float
    Octaves: int
    Gain: float (amplitude decay)
    Lacunarity: float (frequency increase)
    NoiseFunction: callable taking (x, y, z) -> float
    """
    dx, dy, dz = Dims
    total_voxels = dx * dy * dz
    voxels = [0.0] * total_voxels
    
    # Initial amplitude and frequency
    amplitude = 1.0
    frequency = 1.0
    
    # Optional: Rotation matrix to break artifacts (2D example, extend to 3D if needed)
    # For 3D, a 3x3 rotation matrix or specific axis offsets are used [S2, unofficial][S3]
    
    for x in range(dx):
        for y in range(dy):
            for z in range(dz):
                # 1. Compute centered world position
                # id is (x, y, z)
                px = Scale * (x + 0.5 - dx / 2.0)
                py = Scale * (y + 0.5 - dy / 2.0)
                pz = Scale * (z + 0.5 - dz / 2.0)
                
                # 2. Initialize value with vertical gradient
                value = -py 
                
                # 3. Accumulate octaves
                current_amplitude = amplitude
                current_frequency = frequency
                q_x = px
                q_y = py
                q_z = pz
                
                for i in range(Octaves):
                    # Apply time offset and frequency scaling
                    # Specific offsets vary by implementation [S2, S4, unofficial]
                    # Example from [S4, unofficial]: q += time * 0.5 * vec3(1.0, -0.2, -1.0)
                    # Example from [S2, unofficial]: p * freq + vec3(offset) * Time
                    
                    # Simplified generic step:
                    noise_val = NoiseFunction(q_x * current_frequency, 
                                              q_y * current_frequency, 
                                              q_z * current_frequency)
                    
                    value += noise_val * current_amplitude
                    
                    # Update for next octave
                    q_x *= current_frequency
                    q_y *= current_frequency
                    q_z *= current_frequency
                    
                    # Apply rotation or specific axis drift if required by variant
                    # e.g., q = m * q for 2D rotation [S3]
                    
                    current_amplitude *= Gain
                    current_frequency *= Lacunarity
                
                # 4. Store result
                index = x + dx * (y + dy * z)
                voxels[index] = value
                
    return voxels
```

**Edge Cases and Pitfalls:**
- **Axis-aligned artifacts:** Standard FBM without rotation produces visible grid patterns. A rotation matrix (e.g., `mat2(1.6, 1.2, -1.2, 1.6)` for 2D, or equivalent 3D rotation) must be applied to coordinates between octaves [S3].
- **Precision:** Using `sin`-based hashes can suffer from precision issues on some hardware; sin-free hashes are preferred for stability [S3].
- **Boundary Conditions:** The centered coordinate calculation `id + 0.5 - Dims / 2` ensures the noise field is centered around the origin, preventing bias at the edges [S2, unofficial].

## Subtopics

### [Terrain Heightmap Generation via Noise](4214-terrain-heightmap-generation-via-noise.md)
Generates a 2D heightmap by sampling a 3D noise field (or 2D FBM) at world coordinates, mapping the output to a vertical range. It differs from the 3D Noise Field Generator by operating on 2D coordinates and outputting a single height value per pixel rather than a 3D scalar volume.

### [Domain Warped FBM](4493-domain-warped-fbm.md)
Feeds the output of a noise function back as a coordinate offset to distort the sampling domain ($p + \text{fbm}(p)$), creating organic, fluid-like patterns. It differs from standard FBM by introducing non-linear spatial distortion that mimics turbulent flow, whereas standard FBM simply layers noise at different scales.

### FBM Combinations
Combines FBM with raymarching for height/density fields, finite-difference normals for lighting, and color mapping using power curves [S3]. It extends the basic generator by integrating the noise field into a full rendering pipeline (intersection, shading, compositing) [S3].

### Absolute Noise Sum
A variant that sums the absolute values of noise octaves ($\sum |\text{noise}(p)|$), resulting in a range of $[0, 1]$ and creating "cloudy" or "rough" textures [S6, unofficial]. It differs from standard FBM by removing negative values, which emphasizes ridges and high-frequency detail [S6, unofficial].

### Ocean Wave Octave
Uses specialized noise functions (`sea_octave`) that combine noise with trigonometric functions (`sin`, `cos`) to create peaked wave crests [S3]. It differs from standard gradient noise by explicitly modeling wave propagation and choppy water surfaces [S3].

### Bounded Perlin Noise Texture
Maps 3D points to RGB colors using Perlin noise, scaled and bounded within a specific region [S7, unofficial]. It differs from the scalar field generator by outputting color textures directly and managing spatial bounds explicitly [S7, unofficial].

## Operating characteristics
- **Time Complexity:** $O(V \times O)$, where $V$ is the number of voxels ($D_x D_y D_z$) and $O$ is the number of octaves [S5, unofficial].
- **Memory Complexity:** $O(V)$ for storing the voxel grid [S2, unofficial].
- **Performance:** More computationally intensive than single-octave noise due to multiple samples per voxel [S5, unofficial]. Reducing octave count is the primary optimization [S3].
- **Strengths:** Produces highly realistic, multi-scale natural textures (clouds, terrain) [S5, unofficial].
- **Limitations:** High memory usage for large 3D grids; sensitive to parameter tuning (Gain, Lacunarity) for desired aesthetic [S3][S5, unofficial].

## Background
The method originates from the use of Fractal Brownian Motion (FBM) in procedural texture synthesis, popularized by Ken Perlin and others for generating natural phenomena [S3][S5, unofficial]. The specific implementation using Simplex noise with vertical gradients is often found in GPU-based volume rendering and marching cubes implementations [S2, unofficial]. It is widely used in real-time graphics for cloud rendering, terrain generation, and volumetric effects [S4, S5, unofficial].
