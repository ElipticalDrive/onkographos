# Noise Field Generator

Also called: Layered Simplex Noise with Gradient, SimplexNoise3D, Perlin Volume Generation

## Overview
Generates a 3D scalar field using layered Simplex noise, offset by a linear vertical gradient [S2, unofficial]. It differs from standard Perlin noise implementations by utilizing Simplex noise for its directional consistency and combining two distinct octaves with specific spatial offsets and time-varying gradients to create volumetric texture synthesis suitable for marching cubes or ray marching [S2, unofficial].

## How it works
**Inputs:**
- `Dims`: 3D integer vector defining the voxel grid dimensions $(D_x, D_y, D_z)$.
- `Scale`: Spatial scaling factor for the noise field [S2, unofficial].
- `Time`: A scalar value used to offset the noise gradients, allowing for animation [S2, unofficial].
- `id`: The 3D integer coordinate of the current voxel $(x, y, z)$, ranging from $0$ to $Dims - 1$ [S2, unofficial].

**Outputs:**
- `Voxels`: A flat `RWStructuredBuffer<float>` (or equivalent 1D array) storing the computed scalar value for each voxel [S2, unofficial]. The index into this buffer is calculated as $id.x + Dims.x \times (id.y + Dims.y \times id.z)$ [S2, unofficial].

**Data Structures:**
- The output is a 1D array of floats. The memory layout is row-major (or column-major depending on interpretation, but explicitly defined by the index formula) where the z-axis is the slowest varying dimension, y is intermediate, and x is the fastest [S2, unofficial].

**Algorithm Steps:**
1.  **Compute Centered World Position:**
    Calculate the position $p$ in world space. The formula centers the grid around the origin:
    $$ p = \text{Scale} \times (id + 0.5 - \frac{\text{Dims}}{2}) $$
    Here, $id + 0.5$ centers the sample within the voxel, and $\text{Dims}/2$ shifts the origin to the center of the grid [S2, unofficial].

2.  **Initialize Value with Vertical Gradient:**
    Set the base value to a linear vertical gradient:
    $$ \text{value} = -p.y $$
    This creates a density or height variation that decreases as $y$ increases [S2, unofficial].

3.  **Add First Octave of Simplex Noise:**
    Sample the Simplex noise function at a scaled position with a specific gradient offset:
    $$ \text{value} \leftarrow \text{value} + \text{SimplexNoise}(p \times 0.83 + \mathbf{g}_1 \times \text{Time}) \times 0.5 $$
    Where $\mathbf{g}_1 = (-0.37, -0.12, 0)$ [S2, unofficial].

4.  **Add Second Octave of Simplex Noise:**
    Sample the Simplex noise function at a different scaled position with a different gradient offset:
    $$ \text{value} \leftarrow \text{value} + \text{SimplexNoise}(p \times 0.72 + \mathbf{g}_2 \times \text{Time}) \times 0.5 $$
    Where $\mathbf{g}_2 = (0.21, 0.07, 0)$ [S2, unofficial].

5.  **Write Result:**
    Store the final `value` in the output buffer at the index corresponding to `id` [S2, unofficial].

**Pseudocode:**
```python
def compute_noise_field(Dims, Scale, Time, Voxels):
    """
    Computes the noise field for a 3D voxel grid.
    
    Args:
        Dims: tuple (Dx, Dy, Dz) of integers
        Scale: float, spatial scaling factor
        Time: float, time offset for animation
        Voxels: list or array of size Dx * Dy * Dz to store results
    """
    # Pre-calculate center offset
    center_x = Dims[0] / 2.0
    center_y = Dims[1] / 2.0
    center_z = Dims[2] / 2.0
    
    # Gradient vectors for the two octaves
    g1 = (-0.37, -0.12, 0.0)
    g2 = (0.21, 0.07, 0.0)
    
    # Scale factors for the two octaves
    scale1 = 0.83
    scale2 = 0.72
    
    # Amplitude for both octaves
    amp = 0.5
    
    for z in range(Dims[2]):
        for y in range(Dims[1]):
            for x in range(Dims[0]):
                # 1. Compute centered world position
                # id + 0.5 - Dims / 2
                px = (x + 0.5 - center_x) * Scale
                py = (y + 0.5 - center_y) * Scale
                pz = (z + 0.5 - center_z) * Scale
                
                p = (px, py, pz)
                
                # 2. Initialize value with vertical gradient
                value = -py
                
                # 3. Add first octave
                # p * 0.83 + g1 * Time
                arg1_x = px * scale1 + g1[0] * Time
                arg1_y = py * scale1 + g1[1] * Time
                arg1_z = pz * scale1 + g1[2] * Time
                
                # SimplexNoise is assumed to be a standard 3D simplex noise function
                # returning a value typically in [-1, 1] or [0, 1] depending on implementation.
                # The source uses SimplexNoise(p * 0.83 + ...) * 0.5
                noise1 = simplex_noise_3d(arg1_x, arg1_y, arg1_z)
                value += noise1 * amp
                
                # 4. Add second octave
                # p * 0.72 + g2 * Time
                arg2_x = px * scale2 + g2[0] * Time
                arg2_y = py * scale2 + g2[1] * Time
                arg2_z = pz * scale2 + g2[2] * Time
                
                noise2 = simplex_noise_3d(arg2_x, arg2_y, arg2_z)
                value += noise2 * amp
                
                # 5. Write result
                # Index: id.x + Dims.x * (id.y + Dims.y * id.z)
                idx = x + Dims[0] * (y + Dims[1] * z)
                Voxels[idx] = value
```

**Edge Cases and Pitfalls:**
- **Precision:** The calculation involves floating-point arithmetic. Ensure that `Scale` and `Time` are handled with sufficient precision to avoid jittering in the noise field [S2, unofficial].
- **Boundary Conditions:** The formula $id + 0.5 - \text{Dims}/2$ ensures that the center of the grid is at $(0,0,0)$. If `Dims` is even, the center is between voxels; if odd, it is at the central voxel. This is handled correctly by the formula [S2, unofficial].
- **Simplex Noise Implementation:** The `SimplexNoise` function must be a standard 3D Simplex Noise implementation. The source code snippet implies a specific implementation (likely from the `ComputeMarchingCubes` repository) which may have specific normalization or range characteristics [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N = D_x \times D_y \times D_z$ is the total number of voxels. Each voxel requires a constant number of operations (two Simplex noise evaluations and some arithmetic) [S2, unofficial].
- **Memory Complexity:** $O(N)$ for the output buffer `Voxels` [S2, unofficial].
- **Performance:** The method is designed for GPU execution using compute shaders, with a thread group size of $[8, 8, 8]$ [S2, unofficial]. This allows for efficient parallel processing of the voxel grid.
- **Strengths:** The use of Simplex noise provides better directional consistency than Perlin noise. The layered approach with two octaves and gradient offsets creates a more complex and natural-looking volumetric texture. The vertical gradient adds a sense of height or density variation [S2, unofficial].
- **Limitations:** The method is specific to 3D volumes. The use of `Time` introduces animation, which may not be desired for static textures. The specific coefficients ($0.83, 0.72, -0.37$, etc.) are tuned for a specific aesthetic and may not be suitable for all use cases [S2, unofficial].

## Background
The method is derived from the `ComputeMarchingCubes` repository by Keijiro [S2, unofficial]. It is used in the context of procedural volume generation, specifically for creating textures that can be visualized using marching cubes or similar surface extraction techniques. The use of Simplex noise and layered octaves is a common technique in procedural generation for creating natural-looking terrain and textures [S2, unofficial].
