# Noise Field Generator

Also called: Fractal Brownian Motion, Layered Simplex Noise with Gradient, Multioctave Noise, SimplexNoise3D, Perlin Volume Generation, Standard FBM

## Overview
The Noise Field Generator produces a 3D scalar field by summing multiple octaves of gradient-based noise (typically Simplex or Perlin), where each octave scales frequency and amplitude to create multi-scale detail [S2, unofficial][S3][S4, unofficial]. It solves the problem of generating natural-looking volumetric textures (such as soft clouds or terrain density) that lack the repetitive, uniform appearance of single-layer noise [S3][S4, unofficial]. It differs from its parent, [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md), by explicitly defining the multi-octave summation loop, the specific scaling of frequency (lacunarity) and amplitude (gain), and the optional vertical gradient offset used to break symmetry in volumetric data [S2, unofficial][S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D coordinate $p = (x, y, z)$, a base noise function $N(p)$ (e.g., Simplex or Perlin), the number of octaves $O$, the gain (amplitude multiplier) $G$, and the lacunarity (frequency multiplier) $L$. Optional: a vertical gradient offset $k_y$ and a rotation matrix $M$ for 2D projections or to break axis alignment [S2, unofficial][S3][S4, unofficial].
*   **Output:** A scalar value $f(p)$ representing the noise intensity at $p$. For volume generation, this is computed for every voxel in a grid and stored in a structured buffer [S1, S2, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 1D array or `RWStructuredBuffer<float>` of size $D_x \times D_y \times D_z$, where each element stores the computed scalar value [S1, S2, unofficial].
*   **Thread Group:** For GPU implementation, a 3D thread group of size $[8, 8, 8]$ is typical [S2, unofficial].

**Parameters:**
*   **Octaves ($O$):** Number of noise layers. Typical value: 4–5 [S3][S4, unofficial].
*   **Gain ($G$):** Amplitude multiplier per octave. Typical value: 0.5 [S3][S4, unofficial].
*   **Lacunarity ($L$):** Frequency multiplier per octave. Typical value: 2.0 [S3][S4, unofficial].
*   **Noise Scale:** Spatial frequency multiplier for the base coordinate. Typical value: 0.05 for terrain, or derived from world scale [S1, S2, unofficial].
*   **Vertical Gradient Offset ($k_y$):** A linear term added to break vertical symmetry. Typical value: $-p.y$ or similar linear slope [S2, unofficial].

**Algorithm Steps:**
1.  **Initialize:** Set the accumulated value $f = 0.0$ and current amplitude $a = 0.5$ (or 1.0 for absolute variants) [S3][S5, unofficial].
2.  **Loop Octaves:** For each octave $i$ from 0 to $O-1$:
    a.  **Sample:** Compute the base noise value $n = N(p)$ [S3].
    b.  **Accumulate:** Add the weighted noise to the result: $f \leftarrow f + a \cdot n$ [S3].
    c.  **Transform Coordinate:** Update $p$ for the next octave.
        *   Standard FBM: Scale $p$ by lacunarity $L$ and optionally rotate using matrix $M$ to prevent axis-aligned artifacts [S3].
        *   Alternative: $p \leftarrow p \cdot L$ [S1, unofficial].
    d.  **Scale Amplitude:** Update amplitude: $a \leftarrow a \cdot G$ [S3].
3.  **Apply Gradient (Optional):** If generating volumetric data with vertical bias, add a linear gradient: $f \leftarrow f + k_y \cdot p.y$ [S2, unofficial].
4.  **Return:** Output $f$ [S3].

**Pseudocode:**
```python
def noise_field_generator(p, octaves, gain, lacunarity, noise_func, use_rotation=False, rotation_matrix=None, vertical_gradient=False):
    """
    Generates a 3D scalar field value using Fractal Brownian Motion.
    
    Args:
        p (vec3): Input 3D coordinate.
        octaves (int): Number of noise layers.
        gain (float): Amplitude multiplier per octave.
        lacunarity (float): Frequency multiplier per octave.
        noise_func (function): A function that takes a vec3 and returns a scalar noise value.
        use_rotation (bool): Whether to rotate coordinates between octaves.
        rotation_matrix (mat2): 2x2 rotation+scale matrix (for 2D projection or xz-plane).
        vertical_gradient (bool): Whether to add a vertical linear gradient.
        
    Returns:
        float: The accumulated noise value.
    """
    f = 0.0
    a = 0.5  # Initial amplitude
    
    # Use a copy of p to avoid modifying the input
    current_p = p
    
    for i in range(octaves):
        # Sample base noise
        n = noise_func(current_p)
        
        # Accumulate weighted noise
        f += a * n
        
        # Update coordinate for next octave
        if use_rotation and rotation_matrix is not None:
            # Apply rotation and scaling (lacunarity)
            # Note: rotation_matrix typically includes the lacunarity scale factor
            # e.g., mat2(1.6, 1.2, -1.2, 1.6) for lacunarity ~2.0
            current_p.xz = rotation_matrix * current_p.xz
            # If 3D rotation is needed, extend matrix or apply 3D rotation
        else:
            # Standard lacunarity scaling
            current_p = current_p * lacunarity
            
        # Update amplitude
        a *= gain
        
    # Apply vertical gradient if requested
    if vertical_gradient:
        f += -current_p.y  # Linear gradient offset
        
    return f
```

**Edge Cases and Pitfalls:**
*   **Axis-Aligned Artifacts:** Without inter-octave rotation, the noise may exhibit visible grid-aligned patterns. A rotation matrix with determinant 2.0 (e.g., `mat2(1.6, 1.2, -1.2, 1.6)`) breaks self-similarity and alignment [S3].
*   **Precision:** High octaves with high lacunarity can lead to floating-point precision issues in the hash function. Using sin-free hash functions (e.g., `fract(p * 0.1031) + dot mixing`) is more stable cross-platform [S3].
*   **Range:** Standard FBM ranges from approximately -1 to 1 (depending on the base noise range). Absolute variants range from 0 to 1 [S5, unofficial].

## Subtopics

### FBM Combinations
Combines FBM with other techniques such as raymarching for height/density fields, finite-difference normals for lighting, color mapping using power curves, Fresnel for water surfaces, and multi-layer compositing (shape, ridged, color) [S3].

### Absolute Noise Sum
A variant that sums the absolute values of noise octaves ($\sum |N(p)| \cdot a$), resulting in a range of 0.0 to 1.0 and producing "cloudy" or "rough" textures with sharp ridges [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(O \cdot N)$, where $O$ is the number of octaves and $N$ is the number of voxels. Each voxel requires $O$ noise evaluations [S4, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the voxel grid [S2, unofficial].
*   **Performance:** More computationally intensive than single-layer noise due to multiple samples per voxel, but produces more realistic results [S4, unofficial]. GPU implementations using compute shaders (e.g., 8x8x8 thread groups) are efficient for large volumes [S2, unofficial].
*   **Strengths:** Generates natural-looking, multi-scale detail suitable for clouds, terrain, and smoke [S3][S4, unofficial].
*   **Limitations:** Computationally expensive for high-resolution volumes or many octaves. Requires careful tuning of gain and lacunarity to avoid overly noisy or overly smooth results [S4, unofficial].

## Background
Fractal Brownian Motion (fBm) was introduced by Benoit Mandelbrot in the context of fractal geometry and natural phenomena [S4, unofficial]. It has become a standard technique in procedural generation for computer graphics, particularly in volumetric rendering and terrain generation, due to its ability to simulate the self-similar structure of natural objects [S3][S4, unofficial]. The method is widely used in tools like Unity's Procedural Terrain Generation and GPU-based marching cubes implementations [S2, S5, unofficial].
