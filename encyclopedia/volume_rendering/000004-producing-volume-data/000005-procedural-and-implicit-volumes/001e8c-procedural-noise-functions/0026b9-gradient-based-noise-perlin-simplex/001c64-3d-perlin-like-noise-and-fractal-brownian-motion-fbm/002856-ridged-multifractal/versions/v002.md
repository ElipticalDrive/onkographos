# Ridged Multifractal

Also called: Ridged FBM, Ridged Noise, ridgedmf

## Overview
Ridged Multifractal is a fractal noise technique that generates sharp, ridge-like structures by applying a non-linear transformation to the absolute value of base noise, combined with inter-octave feedback [S1, unofficial]. Unlike standard FBM which produces soft, cloud-like volumes, Ridged Multifractal creates high-contrast linear features suitable for terrain ridges or lightning [S2]. It builds on [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by replacing the linear summation with a ridge-specific kernel and a multiplicative feedback loop [S1, unofficial].

## How it works
**Inputs and Outputs**
- Input: 3D coordinate $p$, number of octaves $N$, initial frequency, lacunarity $L$, gain $G$, ridge offset $O$, and a base noise function returning values in $[-1, 1]$ or $[0, 1]$ [S1, unofficial].
- Output: Scalar field value representing the ridged structure intensity [S1, unofficial].

**Data Structures**
- Standard floating-point accumulators for `sum`, `freq`, `amp`, and `prev` [S1, unofficial].

**Parameters**
- $O$ (Offset): Controls ridge sharpness, typically $1.0$ [S1, unofficial].
- $L$ (Lacunarity): Frequency scaling per octave, typically $2.0$ [S2].
- $G$ (Gain): Amplitude scaling per octave, typically $0.5$ [S1, unofficial].
- $N$ (Octaves): Number of summation layers [S1, unofficial].

**Algorithm Steps**
1. Initialize `sum = 0`, `freq = Frequency`, `amp = 0.5`, `prev = 1.0` [S1, unofficial].
2. Loop for $i$ from $0$ to $N-1$:
   a. Compute base noise: $h = \text{noise}(p \times \text{freq})$ [S1, unofficial].
   b. Apply ridge transformation: $h_{\text{abs}} = |h|$, $h_{\text{ridge}} = (O - h_{\text{abs}})^2$ [S1, unofficial].
   c. Apply feedback and accumulate: $\text{sum} \leftarrow \text{sum} + h_{\text{ridge}} \times \text{amp} \times \text{prev}$ [S1, unofficial].
   d. Update feedback: $\text{prev} \leftarrow h_{\text{ridge}}$ [S1, unofficial].
   e. Update frequency: $\text{freq} \leftarrow \text{freq} \times L$ [S1, unofficial].
   f. Update amplitude: $\text{amp} \leftarrow \text{amp} \times G$ [S1, unofficial].
3. Return `sum` [S1, unofficial].

**Pseudocode**
```python
def ridged_multifractal(p, octaves, frequency, lacunarity, gain, offset, noise_func):
    sum_val = 0.0
    freq = frequency
    amp = 0.5
    prev = 1.0
    
    for _ in range(octaves):
        h = noise_func(p * freq)
        h_abs = abs(h)
        h_ridge = (offset - h_abs) ** 2
        sum_val += h_ridge * amp * prev
        prev = h_ridge
        freq *= lacunarity
        amp *= gain
        
    return sum_val
```

**Edge Cases and Pitfalls**
- When using the output for coloring, divide by $\max(\text{value}, 0.05)$ to prevent division by zero [S2].

## Operating characteristics
Time complexity is $O(N)$ per sample, where $N$ is the number of octaves, as each octave requires one noise evaluation and constant-time arithmetic [S1, unofficial]. Memory complexity is $O(1)$ auxiliary space, requiring only standard floating-point accumulators [S1, unofficial]. The method produces highly realistic terrain ridges and lightning effects but is less suitable for soft volumetric features like clouds [S2].

## Background
Ridged Multifractal was introduced as a variant of Fractal Brownian Motion (FBM) to address the need for sharp, linear features in procedural generation [S1, unofficial]. It is widely used in terrain synthesis and visual effects [S2]. The technique relies on the absolute value of noise to create V-shaped ridges at zero crossings, distinguishing it from standard FBM which produces soft, isotropic noise [S2]. The feedback mechanism, where the output of one octave influences the amplitude of the next, enhances the structural coherence of the ridges [S1, unofficial].
