# 3D Perlin-like Noise and Fractal Brownian Motion (FBM)

Also called: Fractal Brownian Motion, Fractional Brownian Motion, 3D Perlin Noise, 3D Perlin-like Noise

## Overview
3D Perlin-like Noise generates smooth pseudo-random scalar values on a 3D unit lattice using hash-derived corner gradients, Hermite smoothing, and trilinear interpolation [S1, S2, S4, S12, unofficial]. Fractal Brownian Motion (FBM) constructs multi-scale fractal detail by summing multiple octaves of a base noise function (such as Perlin or Simplex) with increasing frequency and decreasing amplitude [S3][S6, S8, unofficial]. Together, they solve the problem of generating natural-looking, continuous volumetric textures (e.g., clouds, terrain, smoke) that lack sufficient detail when using single-octave noise [S4, S5, S16, unofficial]. This method differs from its siblings like [Simplex Noise](978-simplex-noise.md) by relying on a cubic lattice structure and trilinear interpolation rather than a simplex grid, and from [Improved Perlin Noise (4D)](3723-improved-perlin-noise-4d.md) by operating in three dimensions [S1, S12, unofficial].

## How it works
**Inputs:**
*   `p`: Input 3D coordinate vector $(x, y, z)$.
*   `octaves`: Number of noise layers to sum (integer, typically 3–7) [S5, S12, unofficial].
*   `persistence`: Amplitude decay factor per octave (float, typically 0.5) [S6, unofficial].
*   `lacunarity`: Frequency multiplier per octave (float, typically 2.0) [S7, unofficial].
*   `scale`: Initial spatial scaling factor (float, optional) [S5, unofficial].

**Outputs:**
*   `value`: A scalar float representing the noise density. Range is typically $[-1, 1]$ for a single octave, or normalized to $[0, 1]$ or $[-1, 1]$ for FBM depending on implementation [S6, S16, unofficial].

**Data Structures:**
1.  **Permutation Table (`perm`):** An array of 256 integers, initialized with a shuffled sequence of 0–255 (often doubled to 512 entries to handle overflow without modulo) [S11, S12, unofficial].
2.  **Gradient Vectors (`ranvec`):** An array of 256 random 3D vectors, normalized to unit length, stored in `ranvec[i]` [S12, unofficial].
3.  **Hash Function:** A deterministic function mapping integer coordinates to gradient indices. A common implementation uses prime multiplication and fractal sine hashing [S4, S17, unofficial]:
    $$ \text{hash}(x, y, z) = \text{fract}(\sin(\text{dot}((x,y,z), \text{vec3}(127.1, 311.7, 74.7))) \times 43758.5453) $$
    [S4, S17, unofficial]

**Algorithm Steps:**

1.  **Base Noise Evaluation (`noise3`):**
    1.  Compute integer lattice coordinates: $i = \lfloor p \rfloor$ and fractional offset: $f = p - i$ [S2, S4, unofficial].
    2.  Apply Hermite smoothing to $f$: $s = f \cdot f \cdot (3.0 - 2.0 \cdot f)$ [S1, S2, unofficial]. This creates an S-curve weighting function [S12, unofficial].
    3.  Retrieve hash values for the 8 corners of the unit cube containing $p$. For each corner $(dx, dy, dz) \in \{0,1\}^3$, compute the gradient index:
        $$ \text{idx} = \text{perm}[ (i.x + dx) \oplus \text{perm}[ (i.y + dy) \oplus \text{perm}[ i.z + dz ] ] ] $$
        [S11, S12, unofficial]
    4.  Retrieve the gradient vector for each corner: $g_{dx,dy,dz} = \text{ranvec}[\text{idx}]$ [S12, unofficial].
    5.  Compute the dot product between each gradient vector and the vector from the corner to the sample point: $d_{dx,dy,dz} = \text{dot}(g_{dx,dy,dz}, p - (i + (dx, dy, dz)))$ [S12, S14, unofficial].
    6.  Perform trilinear interpolation of the 8 dot products using the smoothed coordinates $s_x, s_y, s_z$:
        *   Interpolate along X: $v_0 = \text{lerp}(d_{0,0,0}, d_{1,0,0}, s_x)$, $v_1 = \text{lerp}(d_{0,1,0}, d_{1,1,0}, s_x)$, etc.
        *   Interpolate along Y: $v_{00} = \text{lerp}(v_0, v_1, s_y)$, $v_{01} = \text{lerp}(v_2, v_3, s_y)$.
        *   Interpolate along Z: $\text{result} = \text{lerp}(v_{00}, v_{01}, s_z)$ [S1, S2, S12, unofficial].

2.  **FBM Summation:**
    1.  Initialize `sum = 0.0`, `amplitude = 0.5`, `frequency = 1.0`, and `position = p / scale` [S5, S8, unofficial].
    2.  Loop for `i` from 0 to `octaves - 1`:
        *   Evaluate base noise: `n = noise3(position * frequency)` [S8, unofficial].
        *   Add weighted contribution: `sum += n * amplitude` [S5, S8, unofficial].
        *   Update parameters: `frequency *= lacunarity`, `amplitude *= persistence` [S7, S8, unofficial].
        *   Optional: Apply non-linear transformations or weight maps to `n` before adding (e.g., turbulence or ridged variants) [S10, S18, unofficial].
    3.  Normalize the result if necessary. The maximum possible amplitude is $\sum_{i=0}^{octaves-1} \text{persistence}^i$. To normalize to $[-1, 1]$, divide by this sum [S6, unofficial].

**Pseudocode:**

```python
def hash13(x, y, z):
    # Deterministic hash using sine and fract
    q = fract(vec3(x, y, z) * vec3(127.1, 311.7, 74.7))
    return fract((q.x + q.y) * q.z + dot(q, q.yzx + 33.33))

def noise3(p, perm, ranvec):
    i = floor(p)
    f = fract(p)
    
    # Hermite smoothing
    s = f * f * (3.0 - 2.0 * f)
    
    # Get 8 corner indices
    # Using bitwise AND with 255 for wrapping, assuming perm size 256
    ix = int(i.x) & 255
    iy = int(i.y) & 255
    iz = int(i.z) & 255
    
    # Calculate gradient indices for all 8 corners
    # This mimics the standard Perlin permutation logic
    def get_grad(dx, dy, dz):
        idx = perm[ix + dx]
        idx = perm[idx + iy + dy]
        idx = perm[idx + iz + dz]
        return ranvec[idx]

    # Dot products for 8 corners
    # Corner (0,0,0)
    g000 = get_grad(0, 0, 0)
    d000 = dot(g000, p - vec3(ix, iy, iz))
    
    # Corner (1,0,0)
    g100 = get_grad(1, 0, 0)
    d100 = dot(g100, p - vec3(ix + 1, iy, iz))
    
    # Corner (0,1,0)
    g010 = get_grad(0, 1, 0)
    d010 = dot(g010, p - vec3(ix, iy + 1, iz))
    
    # Corner (1,1,0)
    g110 = get_grad(1, 1, 0)
    d110 = dot(g110, p - vec3(ix + 1, iy + 1, iz))
    
    # Corner (0,0,1)
    g001 = get_grad(0, 0, 1)
    d001 = dot(g001, p - vec3(ix, iy, iz + 1))
    
    # Corner (1,0,1)
    g101 = get_grad(1, 0, 1)
    d101 = dot(g101, p - vec3(ix + 1, iy, iz + 1))
    
    # Corner (0,1,1)
    g011 = get_grad(0, 1, 1)
    d011 = dot(g011, p - vec3(ix, iy + 1, iz + 1))
    
    # Corner (1,1,1)
    g111 = get_grad(1, 1, 1)
    d111 = dot(g111, p - vec3(ix + 1, iy + 1, iz + 1))
    
    # Trilinear interpolation
    nx00 = mix(d000, d100, s.x)
    nx10 = mix(d010, d110, s.x)
    nx01 = mix(d001, d101, s.x)
    nx11 = mix(d011, d111, s.x)
    
    nxy0 = mix(nx00, nx10, s.y)
    nxy1 = mix(nx01, nx11, s.y)
    
    return mix(nxy0, nxy1, s.z)

def fbm(p, octaves, persistence, lacunarity, scale, perm, ranvec):
    value = 0.0
    amplitude = 0.5
    frequency = 1.0
    position = p / scale
    
    for i in range(octaves):
        value += amplitude * noise3(position * frequency, perm, ranvec)
        amplitude *= persistence
        frequency *= lacunarity
        # Optional: Add shift to prevent octave alignment artifacts
        # position = position * 2.0 + vec3(100.0) 
        # [S5, unofficial]
        
    # Normalize to [-1, 1]
    max_amp = 0.0
    for i in range(octaves):
        max_amp += persistence ** i
    return value / max_amp
```

**Edge Cases and Pitfalls:**
*   **Single Octave Limit:** Some implementations (e.g., `fbm3` in [S1, unofficial]) return only `0.5 * noise3(p)`, lacking multi-octave detail [S1, S11, unofficial].
*   **Division by Zero:** Vector normalization or division operations must guard against zero vectors, throwing errors or returning defaults [S12, unofficial].
*   **Boundary Conditions:** If sampling outside defined bounds (e.g., cloud height limits), return 0.0 density [S16, unofficial].
*   **Hash Consistency:** Hash functions using trigonometric functions may behave inconsistently across different GPU architectures [S17, unofficial].
*   **Integer Overflow:** Corner index computation must mask with `& 255` to prevent out-of-bounds access when coordinates exceed table size [S12, unofficial].

## Subtopics

### [Noise Field Generator](1302-noise-field-generator.md)
The Noise Field Generator creates a 3D scalar field for volumetric rendering by summing multiple octaves of gradient-based noise (typically Simplex or Perlin) with varying frequencies and amplitudes, often combined with a linear vertical gradient. It solves the problem of generating natural-looking, multi-scale volumetric textures such as clouds, terrain, or smoke, where single-octave noise lacks sufficient detail. It differs from its parent [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by explicitly incorporating a vertical gradient offset and specific gradient-based noise implementations (like Simplex) into the field generation pipeline, rather than just generic FBM summation.

### [Global Cloud Cover with Curl Noise](1711-global-cloud-cover-with-curl-noise.md)
Generating global cloud patterns by adding octaves of mixed Perlin and Worley noise, subtracting a threshold, and clamping to create 2D patterns on a spherical surface, restricted between bottom and top heights.

### [3D Perlin-Worley Noise Texture Generation](2355-3d-perlin-worley-noise-texture-generation.md)
This method generates 3D volumetric density maps for procedural textures, specifically targeting cloud-like structures, by combining low-frequency Perlin noise for broad mass with inverted Worley (cellular) noise to carve hollows. It differs from pure Perlin noise by introducing cellular erosion for puffy cumulus appearances and from pure Worley by retaining large-scale continuity. It builds on [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by adding a secondary Worley noise layer for detail erosion.

### [Voxel World Generation with Perlin Noise](2556-voxel-world-generation-with-perlin-noise.md)
This method generates a 3D voxel-based world by evaluating fractal Brownian motion (fBm) noise against a threshold to determine voxel existence and material type (stone, dirt, grass). It differs from sibling methods like the [Noise Field Generator](1302-noise-field-generator.md) by explicitly mapping noise values to discrete material layers based on vertical position and local neighborhood checks, rather than producing a continuous scalar field or texture. It builds on [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) to provide the underlying pseudo-random noise function.

### [Ridged Multifractal](4249-ridged-multifractal.md)
Ridged Multifractal is a fractal noise technique that generates sharp, ridge-like structures by applying a non-linear transformation to the absolute value of base noise, combined with inter-octave feedback. Unlike standard FBM which produces soft, cloud-like volumes, Ridged Multifractal creates high-contrast linear features suitable for terrain ridges or lightning. It builds on [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by replacing the linear summation with a ridge-specific kernel and a multiplicative feedback loop.

### 3D Noise Generation with Box Filtering
Generates a 3D tiling noise volume and applies a 3×3×3 box blur to hide trilinear interpolation grid artifacts, as advised for procedural volume rendering [S21, unofficial].
1.  Initialize a 3D array of floats with uniform random values in [0,1] using a seeded PRNG.
2.  For each voxel $(x,y,z)$, compute the average of its 3×3×3 neighborhood $(dx,dy,dz \in [-1,1])$.
3.  Wrap coordinates modulo $d$ to ensure tiling.
4.  Convert the averaged float to uint8_t in [0,255] and store in the output buffer.
Formula: $v_{out}(x,y,z,c) = \frac{1}{27} \sum_{dx=-1}^{1} \sum_{dy=-1}^{1} \sum_{dz=-1}^{1} v_{in}((x+dx)\%d, (y+dy)\%d, (z+dz)\%d, c) \cdot 255$, where $d$ is the noise dimension, $c$ is the RGBA channel, and $\%$ denotes modulo wrapping for tiling [S21, unofficial]. Parameter: `seed` (uint32_t) for reproducible generation [S21, unofficial].

### FBM BVH Construction
A specific application of the BVH method to Fractional Brownian Motion (FBM), where octaves are presorted by range and have analytic bounds, requiring no memory storage for bounds [S3].
1.  Presort octaves by range of values (higher to lower). This provides the optimal evaluation order for FBM [S3].
2.  Use the analytic expressions for $\Delta_i$ and $s(i,n)$ to compute BVH bounds. No memory is needed to store them [S3].
3.  For FBM with $\beta=1$, all octaves share the same Lipschitz constant. Presorting by range of value corresponds to the optimal pre-sorted order for step size maximization [S3].
Formula: For FBM, the function is the octave $o_i$, and the range is $\Delta_{f_i} = \frac{1}{2^{i-1}}$. The sum of ranges from $i$ to $j$ is $s(i, j) = \sum_{m=i}^j \frac{1}{2^{m-1}} = 2 - \frac{1}{2^{j-1}}$ [S3]. For FBM with Lipschitz noise constant $\lambda_{noise}$, the Lipschitz constant of octave $i$ is $\lambda_{f_i} = \lambda_{noise}$, and the total Lipschitz constant is $\lambda_{B_n} = n \cdot \lambda_{noise}$ [S3].

### High Frequency Surface Noise Remapping
Introducing high frequency noise on cloud surfaces by remapping the noise value using a range defined by low frequency noise, used by Guerilla Games [S20, unofficial].
Code: `float density = clamp(remap(noise, 1 - base, 1.0, 0.0, cap), 0.0, cap);` where `remap` linearly maps values from `[original_min, original_max]` to `[new_min, new_max]` [S20, unofficial].

### Derivative Erosion FBM
FBM that accumulates derivatives across octaves. The derivative magnitude dampens amplitude via `1/(1+|grad|^2)`, creating realistic erosion patterns where steep slopes stay smooth [S22].
1.  Initialize `value=0.0`, `deriv=vec2(0.0)`, `amplitude=0.5`.
2.  Loop `octaves`.
3.  Get `n = noisedQ(p * frequency)`.
4.  Accumulate `deriv += n.yz`.
5.  Add `amplitude * n.x / (1.0 + dot(deriv, deriv))` to `value`.
6.  Update `frequency *= 2.0`, `amplitude *= 0.5`, `p = rot * p` [S22].

## Operating characteristics
*   **Time Complexity:** $O(O \cdot N)$, where $O$ is the number of octaves and $N$ is the number of evaluation points (voxels or ray samples). Each octave requires a constant number of hash lookups and interpolations [S3][S6, unofficial].
*   **Memory Complexity:** $O(1)$ for on-the-fly evaluation (GPU shaders) or $O(D^3)$ for pre-computed 3D textures, where $D$ is the dimension of the noise map [S15, S17, unofficial].
*   **Measured Performance:** Default octaves in compute shaders are often 4 [S8, unofficial]. Typical FBM octave count is 4–7 [S12, S16, unofficial].
*   **Strengths:** Generates continuous, smooth, and natural-looking stochastic patterns with details at multiple scales [S3][S18, unofficial]. Efficient to evaluate on GPUs [S17, unofficial].
*   **Limitations:** Single-octave variants lack detail [S1, unofficial]. Hash functions may vary across hardware [S17, unofficial]. Requires careful normalization to maintain consistent amplitude across octaves [S6, unofficial].
*   **When to Use:** Procedural texture generation, volumetric cloud/terrain synthesis, and implicit surface definition [S3][S16, unofficial].
*   **When Not to Use:** When discrete, cellular structures are needed (use Worley) or when sharp ridges are required (use Ridged Multifractal) [S2, S20, unofficial].

## Background
Originating from Ken Perlin's work on gradient noise, FBM was introduced as a method to create fractal-like noise by summing multiple octaves of a base noise function [S3]. It has been used extensively in computer graphics to create stochastic patterns with details at potentially many different scales [S3]. The technique is foundational for procedural generation in games and film, enabling the creation of complex natural phenomena like clouds, terrain, and smoke from simple mathematical functions [S4, S16, unofficial].
