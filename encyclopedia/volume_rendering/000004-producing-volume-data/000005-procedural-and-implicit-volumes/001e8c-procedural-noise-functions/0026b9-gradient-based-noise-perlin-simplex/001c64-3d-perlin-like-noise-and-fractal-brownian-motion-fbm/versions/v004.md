# 3D Perlin-like Noise and Fractal Brownian Motion (FBM)

Also called: Fractal Brownian Motion, Fractional Brownian Motion, 3D Perlin Noise, 3D Perlin-like Noise

## Overview
3D Perlin-like Noise generates smooth pseudo-random scalar values on a 3D unit lattice using hash-derived corner gradients, Hermite smoothing, and trilinear interpolation [S1, S2, S4, S6, S12, unofficial]. Fractal Brownian Motion (FBM) constructs multi-scale fractal noise by summing multiple octaves of a base noise function (typically Perlin or Simplex) with increasing frequency and decreasing amplitude [S3][S7, S8, S10, unofficial]. This method solves the problem of generating natural-looking, self-similar volumetric textures (e.g., clouds, terrain, smoke) that single-octave noise lacks [S4, S5, S16, unofficial]. It differs from its parent [Gradient-based Noise (Perlin/Simplex)](3860-gradient-based-noise-perlin-simplex.md) by explicitly combining multiple frequency bands into a single fractal signal, and from siblings like [Simplex Noise](978-simplex-noise.md) by relying on the cubic lattice structure of Perlin noise rather than the hexagonal grid of Simplex.

## How it works
**Inputs:**
- `p`: Input 3D coordinate vector $(x, y, z)$.
- `octaves`: Integer count of noise layers ($n \in \mathbb{N}^+$).
- `frequency` ($\lambda$): Initial frequency multiplier (default 1.0 or specific scale).
- `persistence` ($\gamma$): Amplitude decay factor per octave (default 0.5).
- `lacunarity` ($L$): Frequency multiplier per octave (default 2.0).
- `base_noise`: A gradient-based noise function (e.g., Perlin) returning values in $[-1, 1]$ or $[0, 1]$.

**Outputs:**
- `result`: A single scalar value representing the fractal noise at `p`.

**Data Structures:**
1. **Permutation Table (`perm`):** An array of 256 integers, initialized with a shuffled sequence of 0–255 (often doubled to 512 entries to handle overflow without modulo) [S6, S11, S12, unofficial].
2. **Gradient Vectors (`ranvec`):** An array of 256 random 3D vectors, normalized to unit length, stored in `ranvec[i]` [S12, unofficial].
3. **Hash Function:** A deterministic function mapping integer coordinates to gradient indices. Common implementation uses prime multiplication and fractal extraction:
   $$ \text{hash}(x, y, z) = \text{fract}(\sin(\text{dot}((x,y,z), (127.1, 311.7, 74.7))) \times 43758.5453) $$ [S4, S16, S17, unofficial].

**Algorithm Steps:**

1. **Initialize Accumulators:**
   Set `sum = 0.0`, `amplitude = 0.5` (or 1.0 depending on base noise range), `frequency = initial_frequency`.

2. **Loop Over Octaves:**
   For $i$ from 0 to `octaves` - 1:
   
   a. **Evaluate Base Noise:**
      Compute $n = \text{base\_noise}(p \times \text{frequency})$.
      If the base noise returns $[0, 1]$, normalize to $[-1, 1]$ or scale appropriately.
      
   b. **Accumulate:**
      Add the weighted noise to the sum:
      $$ \text{sum} \leftarrow \text{sum} + \text{amplitude} \times n $$
      
   c. **Update Parameters:**
      $$ \text{frequency} \leftarrow \text{frequency} \times \text{lacunarity} $$
      $$ \text{amplitude} \leftarrow \text{amplitude} \times \text{persistence} $$
      
   d. **Optional Position Shift:**
      To avoid periodic alignment artifacts, add a random shift to $p$ each octave:
      $$ p \leftarrow p \times \text{lacunarity} + \text{shift} $$
      where `shift` is a fixed random vector (e.g., $(100, 100, 100)$) [S5, S16, unofficial].

3. **Return Result:**
   Return `sum`.

**Base Noise Implementation (Perlin-like):**
The base noise function `base_noise(p)` operates as follows [S1, S2, S4, S12, unofficial]:

1. **Grid Coordinates:**
   Compute integer lattice coordinates $i = \lfloor p \rfloor$ and fractional offset $f = p - i$ [S2, S4, unofficial].
   
2. **Smoothing:**
   Apply Hermite smoothing to $f$:
   $$ s = f \cdot f \cdot (3.0 - 2.0 \cdot f) $$ [S1, S2, S12, unofficial].
   This creates the S-curve weighting function $uu = u^2(3-2u)$ [S12, unofficial].

3. **Hashing Corners:**
   Retrieve hash values for the 8 corners of the unit cube containing $p$. Indices are computed by adding 0 or 1 to $i$ and masking with 255 (or 511 if using doubled table) to wrap around [S11, S12, unofficial]:
   $$ \text{index} = \text{perm}[ (i_x + dx) \oplus (i_y + dy) \oplus (i_z + dz) ] $$
   where $dx, dy, dz \in \{0, 1\}$ [S11, S12, unofficial].

4. **Gradient Retrieval:**
   Map the hash index to a random gradient vector $g$ from `ranvec` [S12, unofficial].

5. **Dot Products:**
   Compute the dot product between each gradient vector $g$ and the vector from the corner to the sample point $(f - \text{corner})$ [S12, S14, unofficial].

6. **Trilinear Interpolation:**
   Interpolate the 8 dot products using the smoothed fractional coordinates $s_x, s_y, s_z$ [S1, S2, S12, unofficial]:
   - Interpolate along X: $l_1 = \text{mix}(d_{000}, d_{100}, s_x)$, etc.
   - Interpolate along Y: $l_2 = \text{mix}(l_1, l_3, s_y)$, etc.
   - Interpolate along Z: $\text{result} = \text{mix}(l_2, l_4, s_z)$.

**Pseudocode:**

```python
def perlin_noise_3d(p, perm, ranvec):
    """
    Evaluates 3D Perlin-like noise at point p.
    perm: list of 512 integers (shuffled 0-255 doubled)
    ranvec: list of 256 vec3 (normalized random gradients)
    """
    # 1. Grid coordinates
    i = floor(p)
    f = p - i
    
    # 2. Smoothing
    u = f.x * f.x * (3.0 - 2.0 * f.x)
    v = f.y * f.y * (3.0 - 2.0 * f.y)
    w = f.z * f.z * (3.0 - 2.0 * f.z)
    
    # 3. Hashing corners
    # Masking with 511 assumes perm has 512 entries
    A = perm[i.x & 511] + (i.y & 511)
    AA = perm[A] + (i.z & 511)
    AB = perm[A + 1] + (i.z & 511)
    B = perm[i.x + 1 & 511] + (i.y & 511)
    BA = perm[B] + (i.z & 511)
    BB = perm[B + 1] + (i.z & 511)
    
    # 4. Gradient dot products
    # Helper to get gradient contribution
    def grad(hash_val, x, y, z):
        g_idx = hash_val & 255
        g = ranvec[g_idx]
        return g.x * x + g.y * y + g.z * z

    d000 = grad(perm[AA], f.x, f.y, f.z)
    d100 = grad(perm[BA], f.x - 1, f.y, f.z)
    d010 = grad(perm[AB], f.x, f.y - 1, f.z)
    d110 = grad(perm[BB], f.x - 1, f.y - 1, f.z)
    d001 = grad(perm[AA + 1], f.x, f.y, f.z - 1)
    d101 = grad(perm[BA + 1], f.x - 1, f.y, f.z - 1)
    d011 = grad(perm[AB + 1], f.x, f.y - 1, f.z - 1)
    d111 = grad(perm[BB + 1], f.x - 1, f.y - 1, f.z - 1)
    
    # 5. Trilinear interpolation
    # Interpolate X
    nx00 = d000 + u * (d100 - d000)
    nx10 = d010 + u * (d110 - d010)
    nx01 = d001 + u * (d101 - d001)
    nx11 = d011 + u * (d111 - d011)
    
    # Interpolate Y
    nxy0 = nx00 + v * (nx10 - nx00)
    nxy1 = nx01 + v * (nx11 - nx01)
    
    # Interpolate Z
    return nxy0 + w * (nxy1 - nxy0)

def fbm_3d(p, octaves, base_freq, persistence, lacunarity, perm, ranvec, shift=None):
    """
    Evaluates Fractal Brownian Motion using 3D Perlin-like noise.
    """
    total = 0.0
    amplitude = 0.5
    frequency = base_freq
    current_p = p
    
    for i in range(octaves):
        # Evaluate base noise
        noise_val = perlin_noise_3d(current_p * frequency, perm, ranvec)
        
        # Accumulate
        total += amplitude * noise_val
        
        # Update parameters
        frequency *= lacunarity
        amplitude *= persistence
        
        # Optional shift to prevent periodicity
        if shift is not None:
            current_p = current_p * lacunarity + shift
        else:
            current_p = current_p * lacunarity
            
    return total
```

**Parameters with Typical Values:**
- `octaves`: 4–7 [S8, S12, S16, unofficial].
- `persistence` ($\gamma$): 0.5 [S5, S6, S7, S16, unofficial].
- `lacunarity` ($L$): 2.0 [S7, S8, unofficial].
- `base_frequency`: 0.01–1.0 depending on scene scale [S11, S17, unofficial].

**Edge Cases and Pitfalls:**
- **Periodicity:** Without random shifts between octaves, FBM can exhibit visible periodic artifacts [S5, S16, unofficial].
- **Precision:** High octaves with high frequencies can lead to floating-point precision loss in gradient dot products [S12, unofficial].
- **Boundary Access:** Integer overflow or out-of-bounds access when computing corner indices is prevented by masking with `& 255` (or `& 511`), assuming a permutation table size of 256 or 512 [S6, S12, unofficial].
- **Single Octave Limit:** Some simplified implementations (e.g., `fbm3`) only use a single octave, reducing detail [S1, S11, unofficial].
- **GPU Hash Variance:** Hash functions using trigonometric functions may behave differently across GPU architectures [S17, unofficial].

### 3D Noise Generation with Box Filtering
Generates a 3D tiling noise volume and applies a 3×3×3 box blur to hide trilinear interpolation grid artifacts, as advised for procedural volume rendering [S21, unofficial].
1. Initialize a 3D array of floats with uniform random values in [0,1] using a seeded PRNG.
2. For each voxel $(x,y,z)$, compute the average of its 3×3×3 neighborhood $(dx,dy,dz \in [-1,1])$.
3. Wrap coordinates modulo `dim` to ensure tiling.
4. Convert the averaged float to uint8_t in [0,255] and store in the output buffer.
Formula: $v_{out}(x,y,z,c) = \frac{1}{27} \sum_{dx=-1}^{1} \sum_{dy=-1}^{1} \sum_{dz=-1}^{1} v_{in}((x+dx)\%d, (y+dy)\%d, (z+dz)\%d, c) \cdot 255$, where $d$ is the noise dimension, $c$ is the RGBA channel, and $\%$ denotes modulo wrapping for tiling [S21, unofficial].
Parameter: `seed` (uint32_t) for reproducible generation [S21, unofficial].
Code:
```python
import numpy as np
def generate_tiled_noise(dim, seed):
    rng = np.random.RandomState(seed)
    raw = rng.uniform(0.0, 1.0, size=(dim, dim, dim, 4))
    out = np.zeros((dim, dim, dim, 4), dtype=np.uint8)
    for z in range(dim):
        for y in range(dim):
            for x in range(dim):
                sum_val = 0.0
                for dz in range(-1, 2):
                    for dy in range(-1, 2):
                        for dx in range(-1, 2):
                            wx = (x + dx) % dim
                            wy = (y + dy) % dim
                            wz = (z + dz) % dim
                            sum_val += raw[wz, wy, wx, 0] # Example channel
                out[z, y, x, 0] = int(sum_val / 27.0 * 255)
    return out
```

### FBM BVH Construction
A specific application of the BVH method to Fractional Brownian Motion (FBM), where octaves are presorted by range and have analytic bounds, requiring no memory storage for bounds [S3].
1. Presort octaves by range of values (higher to lower). This provides the optimal evaluation order for FBM [S3].
2. Use the analytic expressions for $\Delta_i$ and $s(i,n)$ to compute BVH bounds. No memory is needed to store them [S3].
3. For FBM with $\beta=1$, all octaves share the same Lipschitz constant. Presorting by range of value corresponds to the optimal pre-sorted order for step size maximization [S3].
Formula: For FBM, the function is the octave $o_i$, and the range is $\Delta_{f_i} = \frac{1}{2^{i-1}}$. The sum of ranges from $i$ to $j$ is $s(i, j) = \sum_{m=i}^j \frac{1}{2^{m-1}} = 2 - \frac{1}{2^{j-1}}$ [S3]. For FBM with Lipschitz noise constant $\lambda_{noise}$, the Lipschitz constant of octave $i$ is $\lambda_{f_i} = \lambda_{noise}$, and the total Lipschitz constant is $\lambda_{B_n} = n \cdot \lambda_{noise}$ [S3].

### High Frequency Surface Noise Remapping
Introducing high frequency noise on cloud surfaces by remapping the noise value using a range defined by low frequency noise, used by Guerilla Games [S20, unofficial].
Code:
```python
def remap(value, original_min, original_max, new_min, new_max):
    return new_min + (value - original_min) / (original_max - original_min) * (new_max - new_min)

def high_freq_remapped_noise(noise_val, base_val, cap):
    density = clamp(remap(noise_val, 1 - base_val, 1.0, 0.0, cap), 0.0, cap)
    return density
```

### Derivative Erosion FBM
FBM that accumulates derivatives across octaves. The derivative magnitude dampens amplitude via `1/(1+|grad|^2)`, creating realistic erosion patterns where steep slopes stay smooth [S22].
1. Initialize `value=0.0`, `deriv=vec2(0.0)`, `amplitude=0.5`.
2. Loop `octaves`.
3. Get `n = noisedQ(p * frequency)`.
4. Accumulate `deriv += n.yz`.
5. Add `amplitude * n.x / (1.0 + dot(deriv, deriv))` to `value`.
6. Update `frequency *= 2.0`, `amplitude *= 0.5`, `p = rot * p`.

## Operating characteristics
- **Time Complexity:** $O(octaves \cdot N)$, where $N$ is the number of sample points. Each octave requires one base noise evaluation, which is $O(1)$ for fixed lattice size [S3][S6, unofficial].
- **Memory Complexity:** $O(1)$ for the algorithm itself, plus $O(P)$ for the permutation table and gradient vectors, where $P=256$ or $512$ [S6, S12, unofficial].
- **Measured Performance:** On modern GPUs, FBM with 4–7 octaves is highly parallelizable and fits in cache. Performance is limited by memory bandwidth if sampling large volumes, but compute-bound for small samples [S17, unofficial][S3].
- **Scaling:** Linear with the number of octaves. Doubling octaves doubles compute time.
- **Strengths:** Generates natural-looking, multi-scale detail; computationally efficient; easy to implement [S3][S8, unofficial].
- **Limitations:** Can exhibit periodic artifacts if not shifted; high frequencies may suffer from precision loss; not inherently band-limited without filtering [S1, S12, S17, unofficial].
- **When to Use:** Procedural texture generation, volumetric cloud/terrain synthesis, shader-based effects [S3][S16, S17, unofficial].
- **When Not to Use:** When strict band-limiting is required without post-processing; when deterministic tiling is needed without box filtering [S21, S1, unofficial].

## Background
Originated from Ken Perlin's work on noise functions for computer graphics [S1, S6, unofficial]. FBM was introduced as a method to combine multiple octaves of noise to create fractal-like patterns [S3]. It has been used extensively in computer graphics to create stochastic patterns with details at potentially many different scales [S3]. The specific implementation using Hermite smoothing and trilinear interpolation on a cubic lattice is the standard "Perlin Noise" [S1, S2, S4, S12, unofficial].
