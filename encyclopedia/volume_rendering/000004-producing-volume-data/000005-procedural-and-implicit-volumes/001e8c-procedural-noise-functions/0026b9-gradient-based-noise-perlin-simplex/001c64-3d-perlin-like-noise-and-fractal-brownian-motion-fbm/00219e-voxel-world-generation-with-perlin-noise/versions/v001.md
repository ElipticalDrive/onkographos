# Voxel World Generation with Perlin Noise

Also called: Terrain Generation, World Generation

## Overview
This method generates a 3D voxel-based world by evaluating fractal Brownian motion (fBm) noise against a threshold to determine voxel existence and material type (stone, dirt, grass) [S1, unofficial]. It differs from sibling methods like the [Noise Field Generator](1302-noise-field-generator.md) by explicitly mapping noise values to discrete material layers based on vertical position and local neighborhood checks, rather than producing a continuous scalar field or texture [S1, unofficial]. It builds on [3D Perlin-like Noise and Fractal Brownian Motion (FBM)](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) to provide the underlying pseudo-random noise function [S1, unofficial].

## How it works
**Inputs:**
- `WorldGenerationData`: Struct containing `arity` (number of octaves), `gain` (amplitude multiplier per octave), `frequency` (base frequency), `threshold` (noise value cutoff for existence), and `seed` [S1, unofficial].
- `SceneData`: Struct containing world dimensions (`worldWidth`, `worldHeight`), rendering parameters, and camera data [S1, unofficial].
- Voxel storage: A `texture_storage_3d<r32uint, read_write>` buffer where each 32-bit uint stores data for 4 voxels packed in (x,z) pairs [S1, unofficial].

**Outputs:**
- Populated voxel buffer where each voxel is assigned a type ID (0: empty, 1: stone, 3: dirt, 7: grass) [S1, unofficial].

**Data Structures:**
- `WorldGenerationData`:
  - `arity: f32`
  - `gain: f32`
  - `frequency: f32`
  - `threshold: f32`
  - `seed: f32`
- Voxel Packing Layout (within a single `u32`):
  - Bits 0-7: Voxel at local offset (0,0)
  - Bits 8-15: Voxel at local offset (0,1)
  - Bits 16-23: Voxel at local offset (1,0)
  - Bits 24-31: Voxel at local offset (1,1)
  - Each 8-bit slot stores the voxel type ID [S1, unofficial].

**Algorithm Steps:**
1. The compute shader entry point `ComputeMain` is invoked with a workgroup size of (8, 4, 8) [S1, unofficial].
2. For each workgroup, calculate the base voxel position:
   - `voxelPos.x = texelPos.x * 2`
   - `voxelPos.y = texelPos.y`
   - `voxelPos.z = texelPos.z * 2`
3. Loop over a 2x2 block of voxels in the x and z dimensions:
   ```python
   for x in range(2):
       for z in range(2):
           offsetVoxelPos = (voxelPos.x + x, voxelPos.y, voxelPos.z + z)
           noiseValue = GetVoxelNoise(offsetVoxelPos)
           
           # Check existence
           if not (noiseValue > threshold and offsetVoxelPos.y < worldGenerationData.ceiling):
               SetVoxel(offsetVoxelPos, 0) # Empty
               continue
           
           # Determine material
           voxelColor = 1 # Default: Stone
           
           # Check 5 voxels above (y+1 to y+5)
           hasExposedSide = False
           for dy in range(1, 6):
               checkPos = (offsetVoxelPos.x, offsetVoxelPos.y + dy, offsetVoxelPos.z)
               if not (GetVoxelNoise(checkPos) > threshold and checkPos.y < worldGenerationData.ceiling):
                   hasExposedSide = True
                   break
           
           if hasExposedSide:
               voxelColor = 3 # Dirt
           
           # Check for grass
           immediateAbovePos = (offsetVoxelPos.x, offsetVoxelPos.y + 1, offsetVoxelPos.z)
           immediateAboveExposed = not (GetVoxelNoise(immediateAbovePos) > threshold and immediateAbovePos.y < worldGenerationData.ceiling)
           
           if immediateAboveExposed or offsetVoxelPos.y == worldGenerationData.ceiling - 1:
               voxelColor = 7 # Grass
           
           # Pack and store
           SetVoxel(offsetVoxelPos, voxelColor)
   ```
4. `GetVoxelNoise(pos)` evaluates the fBm noise function using the `WorldGenerationData` parameters [S1, unofficial].
5. `SetVoxel(pos, type)` updates the packed 32-bit value in the storage texture at the appropriate texel and bit position [S1, unofficial].

**Pseudocode for Noise Evaluation:**
The noise function `snoise` is a 3D Perlin-like gradient noise implementation [S1, unofficial]. The fBm summation is defined as:

$$ \text{fbm}(p) = \sum_{i=0}^{n-1} \text{amplitude}_i \cdot \text{snoise}(p \cdot \text{frequency}_i) $$

Where:
- $n$ is `arity` (octaves).
- $\text{frequency}_i = \text{base\_frequency} \cdot \text{lacunarity}^i$
- $\text{amplitude}_i = \text{gain}^i$

```python
def snoise(v: vec3<f32>) -> f32:
    # Implementation from [S1, unofficial]
    C = vec2<f32>(1.0 / 6.0, 1.0 / 3.0)
    D = vec4<f32>(0.0, 0.5, 1.0, 2.0)
    i = floor(v + dot(v, C.yyy))
    x0 = v - i + dot(i, C.xxx)
    g = step(x0.yzx, x0.xyz)
    l = vec3<f32>(1.0) - g
    i1 = min(g.xyz, l.zxy)
    i2 = max(g.xyz, l.zxy)
    x1 = x0 - i1 + C.xxx
    x2 = x0 - i2 + C.yyy
    x3 = x0 - D.yyy
    i = mod289(i)
    p = permute(permute(permute(i.z + vec4<f32>(0.0, i1.z, i2.z, 1.0)) + i.y + vec4<f32>(0.0, i1.y, i2.y, 1.0)) + i.x + vec4<f32>(0.0, i1.x, i2.x, 1.0))
    n_ = 0.142857142857
    ns = n_ * D.wyz - D.xzx
    j = p - 49.0 * floor(p * ns.z * ns.z)
    x_ = floor(j * ns.z)
    y_ = floor(j - 7.0 * x_)
    x = x_ * ns.x + ns.yyyy
    y = y_ * ns.x + ns.yyyy
    h = vec4<f32>(1.0) - abs(x) - abs(y)
    b0 = vec4<f32>(x.xy, y.xy)
    b1 = vec4<f32>(x.zw, y.zw)
    s0 = floor(b0) * 2.0 + vec4<f32>(1.0)
    s1 = floor(b1) * 2.0 + vec4<f32>(1.0)
    sh = -step(h, vec4<f32>(0.0))
    a0 = b0.xzyw + s0.xzyw * sh.xxyy
    a1 = b1.xzyw + s1.xzyw * sh.zzww
    p0 = vec3<f32>(a0.xy, h.x)
    p1 = vec3<f32>(a0.zw, h.y)
    p2 = vec3<f32>(a1.xy, h.z)
    p3 = vec3<f32>(a1.zw, h.w)
    norm = taylorInvSqrt(vec4<f32>(dot(p0, p0), dot(p1, p1), dot(p2, p2), dot(p3, p3)))
    p0 *= norm.x
    p1 *= norm.y
    p2 *= norm.z
    p3 *= norm.w
    m = max(0.5 - vec4<f32>(dot(x0, x0), dot(x1, x1), dot(x2, x2), dot(x3, x3)), vec4<f32>(0.0))
    m = m * m
    return 105.0 * dot(m * m, vec4<f32>(dot(p0, x0), dot(p1, x1), dot(p2, x2), dot(p3, x3)))

def fbm(pos: vec3<f32>, octaves: u32, lacunarity: f32, gain: f32, base_frequency: f32, seed: f32) -> f32:
    amplitude = 1.0
    frequency = base_frequency
    sum = 0.0
    p = pos
    for i in range(octaves):
        sum += amplitude * snoise_seeded(p * frequency, seed)
        frequency *= lacunarity
        amplitude *= gain
    return sum

def SetVoxel(voxelPos: vec3<u32>, voxelType: u32):
    texelPos = (voxelPos.x >> 1, voxelPos.y, voxelPos.z >> 1)
    packedVoxel = textureLoad(voxels, texelPos).r
    mask = 0xFF
    xOdd = voxelPos.x & 0x1
    zOdd = (voxelPos.z & 0x1) << 1
    shiftCount = (xOdd | zOdd) * 8
    mask = mask << shiftCount
    mask = ~mask
    packedVoxel &= mask
    packedVoxel |= voxelType << shiftCount
    textureStore(voxels, texelPos, vec4<u32>(packedVoxel, 0, 0, 0))
```

**Edge Cases and Pitfalls:**
- **Precision:** The noise function uses `mod289` and floating-point arithmetic which may introduce small discontinuities or precision errors at large coordinates [S1, unofficial].
- **Boundaries:** The world generation is bounded by `worldGenerationData.ceiling`. Voxels above this height are always empty [S1, unofficial].
- **Material Logic:** The material determination relies on checking 5 voxels above. If the noise function is not monotonic or has sharp transitions, this may lead to unexpected material distributions [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \cdot H \cdot D)$ where $W, H, D$ are world dimensions. Each voxel requires one fBm evaluation and a few neighbor checks.
- **Memory Complexity:** $O(W \cdot H \cdot D / 4)$ due to packing 4 voxels per 32-bit integer.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Performance scales linearly with world volume. The use of compute shaders allows for parallel generation.
- **Strengths:** Efficient generation of large voxel worlds; simple material logic; parallelizable.
- **Limitations:** Fixed material types; noise artifacts may be visible; requires careful tuning of noise parameters for desired terrain shape.
- **When to use:** When generating large, procedurally generated voxel worlds with simple terrain features.
- **When not to use:** When complex, non-procedural terrain editing is required or when high-fidelity, non-repetitive terrain is needed.

## Background
This method is implemented in the `webgpu-voxel-raymarching` project by James Kiernan [S1, unofficial]. It uses a compute shader to generate the voxel data, which is then rendered using ray marching [S1, unofficial]. The noise function is a 3D Perlin-like gradient noise, and the world generation uses fBm to create natural-looking terrain [S1, unofficial].
