# Simplex Noise 2D

Also called: 2D OpenSimplex Noise, 3D Perlin Noise (Improved), Improved Noise, Perlin Noise (Improved), SNoise, Simplex Noise, 2D Simplex

## Overview
Simplex Noise 2D is a gradient-based procedural noise function for 2D space that generates smooth, continuous scalar values [S2, S3, unofficial]. It uses a skewed triangular grid and fixed gradient vectors to compute noise efficiently [S2, unofficial].

## How it works
**Inputs:** A 2D coordinate vector $v = (x, y)$.
**Outputs:** A scalar noise value $N$.

**Data Structures:**
1.  **Permutation Table:** An array of 512 integers (typically `uint8` or `uint16`), derived from a standard permutation of 0–255 repeated twice to handle overflow without modulo during the permutation step [S3, unofficial].
2.  **Gradient Vectors:** A fixed set of 2D vectors, typically 4 or 8, mapped via the permutation table [S2, unofficial].

**Constants:**
*   $C = (1/6, 1/3)$
*   $D = (0, 0.5, 1, 2)$
*   $STRETCH\_2D = (\frac{1}{\sqrt{3}} - 1) / 2 \approx -0.0944$ [S2, unofficial]
*   $SQUISH\_2D = (\sqrt{3} - 1) / 2 \approx 0.3660$ [S2, unofficial]
*   $NORM\_2D = 1/47.0$ [S2, unofficial]
*   $SCALE = 42.0$ [S3, unofficial]

**Steps:**
1.  **Stretch:** Map the input square into a skewed hexagonal grid.
    $$ s = (x + y) \times STRETCH\_2D $$
    $$ x_s = x + s $$
    $$ y_s = y + s $$ [S2, S3, unofficial]
2.  **Grid Cell Identification:** Find the integer coordinates of the simplex triangle containing the input point.
    $$ i_x = \lfloor x_s \rfloor $$
    $$ i_y = \lfloor y_s \rfloor $$ [S2, S3, unofficial]
3.  **Unstretch to Original Space:** Calculate the position of the grid cell origin in the original space and the relative vector to the input point.
    $$ t = (i_x + i_y) \times SQUISH\_2D $$
    $$ X_0 = i_x - t $$
    $$ Y_0 = i_y - t $$
    $$ x_0 = x - X_0 $$
    $$ y_0 = y - Y_0 $$ [S2, S3, unofficial]
4.  **Simplex Type Determination:** Determine which of the two triangles in the square cell the point falls into by comparing $x_0$ and $y_0$. This determines the indices of the two "inner" corners ($i_1, i_2$) relative to the origin.
    $$ g = \text{step}(y_0, x_0) $$
    $$ l = 1 - g $$
    $$ i_1 = (g, l) $$
    $$ i_2 = (l, g) $$ [S3, unofficial]
5.  **Unstretch to Original Space (Other Corners):** Calculate the coordinates of the two inner corners in the original unskewed space.
    $$ x_1 = x_0 - i_{1x} + SQUISH\_2D $$
    $$ y_1 = y_0 - i_{1y} + SQUISH\_2D $$
    $$ x_2 = x_0 - i_{2x} + SQUISH\_2D $$
    $$ y_2 = y_0 - i_{2y} + SQUISH\_2D $$ [S2, S3, unofficial]
6.  **Gradient Lookup:** Map the grid corners to gradient vectors using the permutation table. Hash the integer coordinates $(i_x, i_y)$ and the inner corner offsets to get gradient indices for the three contributing corners [S2, S3, unofficial].
7.  **Contribution Calculation:** For each of the three corners, calculate the contribution to the noise value.
    $$ m_k = \max(0.6 - (x_k^2 + y_k^2), 0.0) $$
    $$ c_k = m_k^2 \times (G_k \cdot (x_k, y_k)) $$ [S1, S3, unofficial]
8.  **Scale:** Combine contributions and apply normalization.
    $$ N = SCALE \times \sum_{k=0}^{2} c_k \times NORM\_2D $$ [S2, S3, unofficial]

**Formula:**
The noise value is calculated as $N = 42.0 \times \sum_{i=0}^{2} m_i^2 (p_i \cdot x_i)$, where $m_i = \max(0.6 - |x_i|^2, 0)$ [S3, unofficial].

**Parameters:**
*   $STRETCH\_2D$: Grid stretching factor [S2, unofficial]
*   $SQUISH\_2D$: Grid squishing factor [S2, unofficial]
*   $NORM\_2D$: Normalization constant [S2, unofficial]
*   $SCALE$: Final scaling factor [S3, unofficial]
*   Permutation table size: 512 (to avoid modulo during permutation) [S3, unofficial]

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point coordinates for the skewed grid can lose precision at very large coordinate values. Using integer arithmetic for grid cell indices ($i_x, i_y$) is critical [G].
*   **Gradient Selection:** The mapping from hash to gradient vector must be consistent across implementations. The standard integer gradients $(1,1), (-1,1), (1,-1), (-1,-1)$ are often used, with normalization handled by $NORM\_2D$ [G].
*   **Boundary Conditions:** The permutation table must handle indices correctly. A table of size 512 (two copies of 0-255) avoids modulo operations during the permutation step, improving performance and correctness [S3, unofficial].
*   **Cutoff:** Contributions where $m_k \le 0$ must be explicitly discarded to prevent bleeding artifacts from distant corners [S1, S3, unofficial].

**Pseudocode:**
```python
import math

def simplex_noise_2d(x, y, perm_table):
    # Constants
    F2 = -0.09440115521960805  # STRETCH_2D
    G2 = 0.3660254037844386    # SQUISH_2D
    NORM_2D = 1.0 / 47.0
    SCALE = 42.0
    
    # 1. Stretch
    s = (x + y) * F2
    xs = x + s
    ys = y + s
    
    # 2. Floor
    i_x = math.floor(xs)
    i_y = math.floor(ys)
    
    # 3. Unstretch
    t = (i_x + i_y) * G2
    X0 = i_x - t
    Y0 = i_y - t
    x0 = x - X0
    y0 = y - Y0
    
    # 4. Determine simplex type
    g = 1.0 if x0 > y0 else 0.0
    l = 1.0 - g
    i1 = (g, l)
    i2 = (l, g)
    
    # 5. Relative positions for other corners
    x1 = x0 - i1[0] + G2
    y1 = y0 - i1[1] + G2
    x2 = x0 - i2[0] + G2
    y2 = y0 - i2[1] + G2
    
    # 6. Gradient lookup
    # Standard permutation table lookup (size 512, mod 256 for indexing)
    def get_hash(ix, iy):
        return perm_table[(perm_table[ix & 255] + iy) & 255] % 4
        
    idx0 = get_hash(i_x, i_y)
    idx1 = get_hash(i_x + i1[0], i_y + i1[1])
    idx2 = get_hash(i_x + i2[0], i_y + i2[1])
    
    # Fixed gradient vectors
    gradients = [(1, 1), (-1, 1), (1, -1), (-1, -1)]
    
    # 7. Contribution calculation
    def contribution(dx, dy, grad_idx):
        attn = 0.6 - (dx*dx + dy*dy)
        if attn <= 0:
            return 0.0
        attn_sq = attn * attn
        gx, gy = gradients[grad_idx]
        return attn_sq * attn_sq * (gx * dx + gy * dy)
        
    val = contribution(x0, y0, idx0) + contribution(x1, y1, idx1) + contribution(x2, y2, idx2)
    
    # 8. Scale
    return val * SCALE * NORM_2D
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The algorithm performs a fixed number of arithmetic operations and table lookups regardless of input magnitude [G].
*   **Memory Complexity:** $O(1)$ for the algorithm state, plus $O(1)$ for the fixed-size permutation table (512 entries) [G].
*   **Performance:** Requires 3 gradient evaluations and dot products per sample, compared to 4 for grid-based Perlin Noise, making it computationally lighter [G].
*   **Strengths:** Smooth, continuous output; reduced directional artifacts compared to grid-based noise; highly efficient for shader and CPU implementation [G].
*   **Limitations:** Not inherently periodic; requires coordinate wrapping or tiling techniques for seamless textures [G].
*   **When to use:** Procedural terrain generation, texture synthesis, and applications requiring smooth scalar fields in 2D [G].
*   **When not to use:** When strict periodicity is required without additional wrapping logic, or when higher-dimensional noise is needed [G].
