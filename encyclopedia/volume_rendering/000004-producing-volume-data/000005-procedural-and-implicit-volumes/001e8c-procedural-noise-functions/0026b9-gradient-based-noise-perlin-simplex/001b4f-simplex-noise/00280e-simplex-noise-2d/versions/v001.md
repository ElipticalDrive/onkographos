# Simplex Noise 2D

Also called: 2D OpenSimplex Noise, 3D Perlin Noise (Improved), Improved Noise, Perlin Noise (Improved), SNoise, Simplex Noise, 2D Simplex

## Overview
Simplex Noise 2D is a gradient-based procedural noise function that generates smooth, continuous scalar fields in two-dimensional space [S2, unofficial]. It solves the directional artifacts inherent in earlier grid-based noise functions (like Perlin Noise) by using a skewed triangular grid instead of a square grid, which reduces computational complexity and improves isotropy [S2, unofficial]. It is primarily used for terrain generation, texture synthesis, and as a density function $f(x,y)$ for implicit surfaces or voxel terrain [S3, unofficial].

## How it works
**Inputs:** Continuous 2D coordinates $(x, y)$.
**Outputs:** A normalized scalar value $N \in [-1, 1]$ (or $[0, 1]$ if remapped).

**Data Structures:**
1.  **Permutation Table:** An array of integers, typically size 512 (to handle wrap-around), containing a shuffled sequence of integers $0 \dots 255$. This table maps grid coordinates to gradient indices.
2.  **Gradient Vectors:** A fixed set of 2D vectors. In the standard implementation, these are the 4 vectors $(1,1), (-1,1), (1,-1), (-1,-1)$ and their permutations, or a specific set derived from the permutation table.

**Constants:**
*   $C_{2D} = \left(\frac{1}{6}, \frac{1}{3}\right)$: Skewing and unskewing factors.
*   $D_{2D} = (0, 0.5, 1, 2)$: Helper vector for corner offsets.
*   $STRETCH_2D = \frac{1/\sqrt{3} - 1}{2}$: Factor to stretch the input space into the skewed simplex grid.
*   $SQUISH_2D = \frac{\sqrt{3} - 1}{2}$: Factor to squish the grid back to Euclidean space.
*   $NORM_2D = 1/47$: Normalization constant to scale the final output to $[-1, 1]$.
*   $MOD_289 = 289$: Modulo base for permutation table indexing.

**Steps:**

1.  **Skew Input Space:**
    Calculate the skewed coordinates $(x_s, y_s)$ by stretching the input $(x, y)$:
    $$ s = (x + y) \times STRETCH_2D $$
    $$ x_s = x + s $$
    $$ y_s = y + s $$

2.  **Identify Simplex Cell:**
    Find the integer grid cell containing the skewed point:
    $$ i_x = \lfloor x_s \rfloor $$
    $$ i_y = \lfloor y_s \rfloor $$
    The cell is a triangle within the skewed grid. The three corners of the simplex triangle containing the point are determined by comparing the relative positions within the cell.

3.  **Unskew to Get Relative Coordinates:**
    Calculate the "squish" offset to return to Euclidean coordinates:
    $$ t = (i_x + i_y) \times SQUISH_2D $$
    $$ X_0 = i_x - t $$
    $$ Y_0 = i_y - t $$
    Calculate the relative position of the input point within the unskewed cell:
    $$ x_0 = x - X_0 $$
    $$ y_0 = y - Y_0 $$

4.  **Determine Corner Contributions:**
    Identify the two other corners of the simplex triangle adjacent to the origin corner $(X_0, Y_0)$. The relative vectors from the origin to these corners are:
    *   Corner 1 (closest to origin): Determine by comparing $x_0$ and $y_0$.
        If $x_0 > y_0$, the first corner is $(1, 0)$ in skewed space, else $(0, 1)$.
        Let $i_1$ be the offset vector to the first corner, and $i_2$ be the offset to the second corner.
        $$ i_1 = \begin{cases} (1, 0) & \text{if } x_0 > y_0 \\ (0, 1) & \text{if } x_0 \le y_0 \end{cases} $$
        $$ i_2 = \begin{cases} (0, 1) & \text{if } x_0 > y_0 \\ (1, 0) & \text{if } x_0 \le y_0 \end{cases} $$
    Calculate the relative coordinates for all three corners:
    $$ x_1 = x_0 - i_{1x} + SQUISH_2D $$
    $$ y_1 = y_0 - i_{1y} + SQUISH_2D $$
    $$ x_2 = x_0 - i_{2x} + 2 \times SQUISH_2D $$
    $$ y_2 = y_0 - i_{2y} + 2 \times SQUISH_2D $$
    *(Note: The origin corner is $(x_0, y_0)$. The other two are shifted by the squish factor and the integer offsets.)*

5.  **Hash and Gradient Selection:**
    Compute hash values for the three corners to select gradient vectors. The hash is typically computed using the permutation table:
    $$ h_0 = \text{perm}((i_x + \text{perm}(i_y)) \pmod{256}) $$
    $$ h_1 = \text{perm}((i_x + i_{1x} + \text{perm}(i_y + i_{1y})) \pmod{256}) $$
    $$ h_2 = \text{perm}((i_x + i_{2x} + \text{perm}(i_y + i_{2y})) \pmod{256}) $$
    Map these hashes to gradient vectors. A common set of 2D gradients for Simplex Noise is:
    $$ G = \{ (1,1), (-1,1), (1,-1), (-1,-1) \} $$
    The specific gradient $g_k$ for corner $k$ is selected from $G$ based on $h_k \pmod 4$.

6.  **Calculate Contributions:**
    For each corner $k \in \{0, 1, 2\}$, calculate the distance squared from the input point to the corner:
    $$ r_k^2 = x_k^2 + y_k^2 $$
    Calculate the attenuation factor. Contributions are zero if the point is outside the influence radius (usually 0.5):
    $$ t_k = 0.5 - r_k^2 $$
    If $t_k < 0$, the contribution $n_k = 0$.
    Otherwise:
    $$ n_k = t_k^4 \times \text{dot}(g_k, (x_k, y_k)) $$

7.  **Final Result:**
    Sum the contributions and normalize:
    $$ N = 70 \times (n_0 + n_1 + n_2) $$
    *(Note: The scaling factor 70 is derived from $1/NORM_2D$ or similar normalization constants depending on the specific gradient set used. Some implementations use 42.0 or other factors. The source [S3, unofficial] cites 42.0, while [S2, unofficial] cites $1/47$ normalization. We use the standard 70 for the 4-gradient set, or adjust based on the specific gradient set defined in the implementation. If using the specific gradients from [S3, unofficial], the factor is 42.0.)*

    **Pseudocode:**

```python
import math

# Constants
STRETCH_2D = (1.0 / math.sqrt(3.0) - 1.0) / 2.0
SQUISH_2D = (math.sqrt(3.0) - 1.0) / 2.0
NORM_2D = 1.0 / 47.0
FACTOR_2D = 70.0 # Standard scaling for 4-gradient set. If using 42.0, replace.

# Permutation table (example, should be size 512)
PERM = [0, 1, 2, ..., 255] * 2 

def grad(hash_val, x, y):
    """Converts a hash value into a gradient vector."""
    h = hash_val & 3
    if h == 0: return (1, 1)
    if h == 1: return (-1, 1)
    if h == 2: return (1, -1)
    return (-1, -1)

def simplex_noise_2d(x, y):
    # 1. Skew input
    s = (x + y) * STRETCH_2D
    i = math.floor(x + s)
    j = math.floor(y + s)
    
    # 2. Unskew
    t = (i + j) * SQUISH_2D
    X0 = i - t
    Y0 = j - t
    x0 = x - X0
    y0 = y - Y0
    
    # 3. Determine simplex corners
    if x0 > y0:
        i1 = 1
        j1 = 0
    else:
        i1 = 0
        j1 = 1
        
    # 4. Relative coordinates of other corners
    x1 = x0 - i1 + SQUISH_2D
    y1 = y0 - j1 + SQUISH_2D
    x2 = x0 - 1.0 + 2.0 * SQUISH_2D
    y2 = y0 - 1.0 + 2.0 * SQUISH_2D
    
    # 5. Hashes
    ii = i & 255
    jj = j & 255
    gi0 = PERM[ii + PERM[jj]] % 4
    gi1 = PERM[ii + i1 + PERM[jj + j1]] % 4
    gi2 = PERM[ii + 1 + PERM[jj + 1]] % 4
    
    # 6. Contributions
    n0 = 0.0
    n1 = 0.0
    n2 = 0.0
    
    # Corner 0
    t0 = 0.5 - x0*x0 - y0*y0
    if t0 >= 0:
        t0 *= t0
        n0 = t0 * t0 * (grad(gi0, x0, y0)[0]*x0 + grad(gi0, x0, y0)[1]*y0)
        
    # Corner 1
    t1 = 0.5 - x1*x1 - y1*y1
    if t1 >= 0:
        t1 *= t1
        n1 = t1 * t1 * (grad(gi1, x1, y1)[0]*x1 + grad(gi1, x1, y1)[1]*y1)
        
    # Corner 2
    t2 = 0.5 - x2*x2 - y2*y2
    if t2 >= 0:
        t2 *= t2
        n2 = t2 * t2 * (grad(gi2, x2, y2)[0]*x2 + grad(gi2, x2, y2)[1]*y2)
        
    # 7. Final value
    return FACTOR_2D * (n0 + n1 + n2)
```

**Edge Cases and Pitfalls:**
*   **Precision:** Near the boundaries of the simplex cells, floating-point precision errors can cause discontinuities. Using double precision for intermediate calculations can mitigate this.
*   **Gradient Set:** The choice of gradient vectors affects the visual quality. The 4-vector set $(1,1), (-1,1), (1,-1), (-1,-1)$ is standard for 2D. Using more gradients (e.g., 8) can reduce artifacts but increases computation.
*   **Normalization:** The final scaling factor depends on the gradient set and the number of corners. Using the wrong factor will result in incorrect amplitude.

## Subtopics

### 2D Octaved Noise with Memoization
A fractal noise generator that sums multiple octaves of the base 2D Simplex Noise. It decreases amplitude and increases frequency for each octave to create more detailed, natural-looking patterns. It uses memoization to cache results for identical inputs and octave counts, avoiding redundant calculations [S2, unofficial].
*   **When to choose:** When generating terrain, clouds, or textures requiring multi-scale detail.
*   **Details:**
    *   **Cache Key:** `${x},${y},${n\_octaves}` [S2, unofficial].
    *   **Loop:** Iterate $o$ from $0$ to $n\_octaves - 1$.
    *   **Amplitude:** $amp_{local} = (1/o) \times amp$ (Note: source [S2, unofficial] uses `1/oct` which might be a typo for $1/2^o$ or similar, but we follow the source).
    *   **Frequency:** $freq = o / wavelength$.
    *   **Accumulation:** $res += amp_{local} \times noise(oct \times (x/wavelength), oct \times (y/wavelength))$ [S2, unofficial].
    *   **Normalization:** $ans = res / sum\_amp$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The number of operations is constant regardless of input coordinates, involving a few arithmetic operations, a hash lookup, and a dot product.
*   **Memory Complexity:** $O(1)$ for the algorithm itself, plus $O(N)$ for the permutation table (typically 512 integers).
*   **Performance:** Significantly faster than Perlin Noise in higher dimensions due to fewer corners (3 in 2D vs 4 in 2D for Perlin). In 2D, the performance difference is marginal, but Simplex Noise scales much better to 3D and higher dimensions.
*   **Strengths:** Directional artifacts are minimized. Smooth and continuous. Efficient.
*   **Limitations:** The skewed grid can be harder to visualize and debug than the square grid of Perlin Noise. The hash function can introduce subtle patterns if not implemented carefully.
*   **When to use:** When isotropic noise is required, or when extending to 3D/4D where Simplex's efficiency shines.
*   **When not to use:** If strict compatibility with existing Perlin Noise implementations is required.

## Background
Simplex Noise was introduced by Ken Perlin in 2001 as an improvement over his original Perlin Noise [S1, unofficial]. It was designed to reduce the computational cost of noise generation in higher dimensions and to eliminate the directional artifacts present in the original algorithm. The 2D version is the simplest form of the algorithm, using a triangular grid. It has become a standard in procedural generation for games and graphics [S3, unofficial].
