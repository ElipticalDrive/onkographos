# Improved Perlin Noise (4D)

Also called: 4D Perlin Noise

## Overview
Improved Perlin Noise (4D) is a procedural noise function that generates smooth, continuous random values in four dimensions by interpolating dot products of gradient vectors at the corners of a 4D hypercube [S1, unofficial]. It extends the 3D Improved Perlin Noise algorithm to support time-varying texture generation and 4D volume data synthesis, where the fourth dimension typically represents time [S1, unofficial]. Unlike its 3D sibling, it utilizes a 4D gradient set and a specific permutation hashing strategy optimized for GPU texture lookups to maintain performance [S2, unofficial].

## How it works
The method evaluates noise at a 4D point $p = (x, y, z, w)$ by identifying the unit hypercube containing $p$, hashing the 16 corner coordinates to retrieve gradient vectors, computing dot products, and interpolating the results using a quintic fade function [S1, unofficial].

### Inputs and Outputs
- **Input**: A 4D coordinate vector $p = (x, y, z, w)$ [S1, unofficial].
- **Output**: A scalar noise value $n \in [-1, 1]$ [S1, unofficial].

### Data Structures
The implementation relies on pre-computed lookup tables stored in GPU textures to avoid branching and array indexing overhead [S2, unofficial].

1.  **Permutation Table 1D (`_PermTable1D`)**:
    -   Format: `Texture2D` of size $SIZE \times 1$ (e.g., $256 \times 1$).
    -   Layout: Stores 1D permutation indices in the Alpha channel. Values are normalized to $[0, 1]$ [S2, unofficial].
    -   Access: Sampled at `float2(x, 0)` [S1, unofficial].

2.  **Permutation Table 2D (`_PermTable2D`)**:
    -   Format: `Texture2D` of size $SIZE \times SIZE$ (e.g., $256 \times 256$).
    -   Layout: Stores precomputed 2D permutation sums in RGBA channels. Each pixel stores $(AA, AB, BA, BB)$ where:
        -   $AA = \text{perm}(\text{perm}(x) + y)$
        -   $AB = \text{perm}(\text{perm}(x) + y + 1)$
        -   $BA = \text{perm}(\text{perm}(x + 1) + y)$
        -   $BB = \text{perm}(\text{perm}(x + 1) + y + 1)$
    -   Values are normalized to $[0, 1]$ [S2, unofficial].

3.  **Gradient Table 4D (`_Gradient4D`)**:
    -   Format: `Texture2D` of size $SIZE \times 1$ (e.g., $32 \times 1$ or similar, depending on gradient count).
    -   Layout: Stores 4D gradient vectors in RGBA channels. Contains 32 distinct gradient vectors normalized to $[0, 1]$ [S2, unofficial].
    -   Access: Sampled at `float2(x, 0)` [S1, unofficial].

### Parameters
-   `_Frequency`: Scaling factor for the input coordinate. Default: $1.0$ [S2, unofficial].
-   `_Lacunarity`: Multiplier for frequency in each octave of fractal noise. Default: $2.0$ [S2, unofficial].
-   `_Gain`: Multiplier for amplitude in each octave. Default: $0.5$ [S2, unofficial].
-   `_Time`: Optional 4th dimension input for time-varying noise [S1, unofficial].

### Algorithm Steps

1.  **Locate Hypercube and Relative Position**:
    Compute the integer grid coordinates $P$ of the hypercube containing $p$ and the relative position $p_{rel}$ within the unit hypercube [S1, unofficial].
    $$ P = \text{fmod}(\lfloor p \rfloor, 256.0) $$
    $$ p_{rel} = p - \lfloor p \rfloor $$

2.  **Compute Fade Curves**:
    Calculate the quintic fade values $f$ for each dimension to ensure $C^2$ continuity [S1, unofficial].
    $$ f(t) = 6t^5 - 15t^4 + 10t^3 $$
    $$ f = (f(p_{rel}.x), f(p_{rel}.y), f(p_{rel}.z), f(p_{rel}.w)) $$

3.  **Normalize Coordinates for Lookup**:
    Normalize $P$ to $[0, 1]$ for texture sampling [S1, unofficial].
    $$ P_{norm} = P / 256.0 $$

4.  **Hash Corner Coordinates**:
    Compute the hash indices for the 16 corners of the 4D hypercube using the permutation tables [S1, unofficial].
    -   Hash XY to get Z-offsets:
        $$ AA = \text{perm2d}(P_{norm}.xy) + P_{norm}.z $$
    -   Compute 16 corner hashes by adding $P_{norm}.w$ and incrementing components by $one = 1.0/256.0$:
        $$ AAA = \text{perm}(AA.x) + P_{norm}.w $$
        $$ AAB = \text{perm}(AA.x + one) + P_{norm}.w $$
        $$ ABA = \text{perm}(AA.y) + P_{norm}.w $$
        $$ ABB = \text{perm}(AA.y + one) + P_{norm}.w $$
        $$ BAA = \text{perm}(AA.z) + P_{norm}.w $$
        $$ BAB = \text{perm}(AA.z + one) + P_{norm}.w $$
        $$ BBA = \text{perm}(AA.w) + P_{norm}.w $$
        $$ BBB = \text{perm}(AA.w + one) + P_{norm}.w $$
        The "plus one" variants (e.g., $AAA+one$) are computed similarly by adding $one$ to the respective component before hashing or by using the precomputed 2D table offsets [S1, unofficial].

5.  **Compute Gradient Contributions**:
    For each corner, retrieve the gradient vector $g$ from `_Gradient4D` and compute the dot product with the vector from the corner to the point $p$ [S1, unofficial].
    $$ g = (\text{Sample}(\_Gradient4D, x) \times 2.0 - 1.0) $$
    $$ \text{grad}(corner, p) = \text{dot}(g, p - \text{corner\_pos}) $$
    Note: The gradient vector is unpacked from $[0, 1]$ to $[-1, 1]$ [S1, unofficial]. The corner positions are offsets like $(0,0,0,0)$, $(1,0,0,0)$, etc., relative to the base hypercube [S1, unofficial].

6.  **Interpolate**:
    Perform nested linear interpolation (lerp) across the 4D hypercube using the fade values $f$ [S1, unofficial].
    $$ n = \text{lerp}( \text{lerp}( \text{lerp}( \text{lerp}( \text{grad}(AAA, p), \text{grad}(BAA, p + (-1,0,0,0)), f.x ), \text{lerp}( \text{grad}(ABA, p + (0,-1,0,0)), \text{grad}(BBA, p + (-1,-1,0,0)), f.x ), f.y ), \text{lerp}( \text{grad}(AAB, p + (0,0,-1,0)), \text{grad}(BAB, p + (-1,0,-1,0)), f.x ), \text{lerp}( \text{grad}(ABB, p + (0,-1,-1,0)), \text{grad}(BBB, p + (-1,-1,-1,0)), f.x ), f.y ), f.z ), \text{lerp}( \text{lerp}( \text{lerp}( \text{grad}(AAA+one, p + (0,0,0,-1)), \text{grad}(BAA+one, p + (-1,0,0,-1)), f.x ), \text{lerp}( \text{grad}(ABA+one, p + (0,-1,0,-1)), \text{grad}(BBA+one, p + (-1,-1,0,-1)), f.x ), f.y ), \text{lerp}( \text{grad}(AAB+one, p + (0,0,-1,-1)), \text{grad}(BAB+one, p + (-1,0,-1,-1)), f.x ), \text{lerp}( \text{grad}(ABB+one, p + (0,-1,-1,-1)), \text{grad}(BBB+one, p + (-1,-1,-1,-1)), f.x ), f.y ), f.z ), f.w ) $$

    """Quintic interpolation function."""
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

    """Lookup 1D permutation value from texture."""

    """Lookup 2D permutation values from texture."""

### Edge Cases and Pitfalls
-   **Gradient Normalization**: Gradient vectors must be normalized or scaled appropriately to ensure consistent noise amplitude across the range $[-1, 1]$ [S2, unofficial]. The source implementation scales sampled values from $[0, 1]$ to $[-1, 1]$ [S1, unofficial].
-   **Precision**: Using `fmod` and floating-point arithmetic for large coordinates can lead to precision loss. The modulo 256 operation helps keep indices small but requires careful handling of negative inputs if `floor` behaves differently than expected in the target language [S1, unofficial].
-   **Boundary Conditions**: The permutation tables use wrap-around sampling (`_PointRepeat` or similar) to handle indices that might exceed table bounds, ensuring seamless tiling [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: $O(1)$ per evaluation, as it involves a fixed number of texture lookups and arithmetic operations (16 gradient evaluations, 15 lerp operations) [S1, unofficial].
-   **Memory Complexity**: $O(1)$ auxiliary memory, dominated by the size of the permutation and gradient lookup tables (e.g., $256 \times 256$ for 2D perm, $32 \times 1$ for 4D gradients) [S2, unofficial].
-   **Performance**: GPU-based implementations using texture lookups avoid branching and are significantly faster than traditional array-based lookups [S2, unofficial]. The use of `numthreads(8,8,8)` in compute shaders allows for efficient parallel processing of 3D/4D volumes [S1, unofficial].
-   **Strengths**: Smooth $C^2$ continuity, efficient GPU implementation, supports time-varying (4D) noise for animation [S1, unofficial].
-   **Limitations**: Higher computational cost than 3D noise due to the extra dimension and 16 corners. The 4D gradient set is larger and more complex to generate than 3D [S1, unofficial].

## Background
Improved Perlin Noise (4D) is an extension of Ken Perlin's Improved Perlin Noise, which replaced the original cubic interpolation with a quintic fade function to reduce artifacts [S1, unofficial]. The 4D variant is specifically designed for time-varying texture generation and is implemented in GPU compute shaders for real-time volume rendering and marching cubes mesh generation [S1, unofficial]. The specific implementation detailed in the sources is part of a GPU-based marching cubes project, optimized for Unity's shader model [S1, unofficial].
