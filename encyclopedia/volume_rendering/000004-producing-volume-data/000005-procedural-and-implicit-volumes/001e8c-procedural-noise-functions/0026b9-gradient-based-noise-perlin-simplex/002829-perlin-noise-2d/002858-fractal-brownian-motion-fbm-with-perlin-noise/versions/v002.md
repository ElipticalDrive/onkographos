# Fractal Brownian Motion (fBm) with Perlin Noise

Also called: Fractal Brownian Motion (FBM), Fractal Noise, FractalPerlin2D, Layered Perlin Noise, Multi-octave Perlin Noise, Procedural Noise and FBM, Turbulence

## Overview
Fractal Brownian Motion (fBm) with Perlin Noise is a procedural technique that generates rougher, more natural-looking noise by summing multiple octaves of a base gradient noise function, specifically Perlin Noise 2D, with decreasing amplitude and increasing frequency [S1, S2, S4, unofficial][S5]. It solves the problem of simple noise appearing too synthetic or lacking fine detail by introducing self-similar detail at multiple scales, mimicking natural phenomena like terrain or clouds [S2, unofficial][S5]. It sets itself apart from standard Perlin noise by producing a hierarchical structure of detail, and from other fBm variants (like those using Worley noise) by retaining the connectedness and billowiness characteristic of gradient-based interpolation [S5].

## How it works
### Inputs and Outputs
- **Inputs**:
  - `p`: The input coordinate (2D vector for base Perlin, or 3D if extended, but primarily defined here in the context of 2D Perlin).
  - `octaves`: The number of noise layers to sum (integer).
  - `persistence`: The factor by which amplitude decreases per octave (float).
  - `lacunarity`: The factor by which frequency increases per octave (float).
  - `seed`: Optional seed for the underlying Perlin noise permutation table.
- **Outputs**:
  - A single scalar value representing the fractal noise at `p`. The range depends on normalization; typically normalized to $[-1, 1]$ or $[0, 1]$ depending on implementation [S2, S3, unofficial].

### Data Structures
- **Permutation Table**: An array of 256 integers (or 512 to avoid wrapping logic) used by the underlying Perlin Noise 2D to map grid coordinates to gradient vectors. This is inherited from [Perlin Noise 2D](4211-perlin-noise-2d.md).
- **Settings Object**: A structure containing `Octaves` (default varies, often 5-8), `Persistence` (default 0.5), and `Lacunarity` (default 2.0) [S2, S3, unofficial].

### Formulas
The general mathematical definition of fBm is a summation of noise functions at different scales [S5]:

$$
\text{FBM}(p) = \sum_{i=0}^{N-1} A_i \cdot \text{Noise}(p \cdot F_i)
$$

Where:
- $N$ is the number of octaves.
- $A_i$ is the amplitude of octave $i$.
- $F_i$ is the frequency of octave $i$.
- $\text{Noise}$ is the base Perlin Noise 2D function.

Typical parameter relationships [S5]:
- $A_i = A_0 \cdot \text{Persistence}^i$
- $F_i = F_0 \cdot \text{Lacunarity}^i$

Common default values are $A_0 = 1.0$ (or 0.5 depending on normalization strategy), $\text{Persistence} = 0.5$, and $\text{Lacunarity} = 2.0$ [S2, S4, unofficial][S5].

### Parameters
- **Octaves**: Number of layers. Range: 1 to 8 (typical). Default: 5 [S2, S3, unofficial].
- **Persistence**: Amplitude decay factor. Typical value: 0.5 [S2, S4, unofficial][S5].
- **Lacunarity**: Frequency multiplier. Typical value: 2.0 [S2, unofficial][S5].

### Steps
1. Initialize `total_value = 0.0`.
2. Initialize `current_frequency = 1.0`.
3. Initialize `current_amplitude = 1.0` (or 0.5, depending on desired initial scale; 0.5 is common in some implementations to keep initial values bounded) [S3, S4, unofficial].
4. Initialize `max_possible_value = 0.0` (for normalization).
5. Loop `i` from 0 to `octaves - 1`:
    a. Calculate the scaled position: `scaled_p = p * current_frequency`.
    b. Evaluate the base Perlin Noise 2D at `scaled_p`: `noise_val = Perlin2D(scaled_p, seed)`.
    c. Add the weighted noise to the total: `total_value += current_amplitude * noise_val`.
    d. Update the maximum possible value for normalization: `max_possible_value += current_amplitude`.
    e. Update amplitude for the next octave: `current_amplitude *= persistence`.
    f. Update frequency for the next octave: `current_frequency *= lacunarity`.
6. Normalize the result: `result = total_value / max_possible_value` (if `max_possible_value > 0`, else 0) [S2, unofficial].
    - *Note*: Some implementations do not normalize and instead return the raw sum, or apply a different normalization range (e.g., $[-1, 1]$ by multiplying by 2 and subtracting 1 if the base noise is $[0, 1]$ or similar) [S3, unofficial]. The standard Perlin 2D returns roughly $[-1, 1]$, so normalization to $[-1, 1]$ is often implicit if amplitudes sum to 1. If amplitudes sum to $<1$, the range is compressed.
7. Return `result`.

### Pseudocode
```python
def fractal_perlin_2d(p, octaves, persistence=0.5, lacunarity=2.0, seed=0):
    """
    Computes Fractal Brownian Motion using Perlin Noise 2D.
    
    Args:
        p: tuple (x, y) - Input coordinate.
        octaves: int - Number of octaves (1-8 typical).
        persistence: float - Amplitude decay factor (default 0.5).
        lacunarity: float - Frequency multiplier (default 2.0).
        seed: int - Seed for Perlin noise generation.
        
    Returns:
        float - Normalized fBm value.
    """
    total_value = 0.0
    current_frequency = 1.0
    current_amplitude = 1.0
    max_possible_value = 0.0
    
    # Ensure octaves is within a reasonable range
    octaves = max(1, min(octaves, 8))
    
    for i in range(octaves):
        # Scale the input position by the current frequency
        scaled_p = (p[0] * current_frequency, p[1] * current_frequency)
        
        # Evaluate base Perlin Noise 2D
        # Assumes Perlin2D is defined in parent article [Perlin Noise 2D]
        noise_val = perlin_2d(scaled_p[0], scaled_p[1], seed)
        
        # Accumulate weighted noise
        total_value += current_amplitude * noise_val
        
        # Track max possible value for normalization
        max_possible_value += current_amplitude
        
        # Update parameters for next octave
        current_amplitude *= persistence
        current_frequency *= lacunarity
        
        # Pitfall: Stop if frequency is too high to be represented between pixels
        # This is a heuristic check; in practice, floating point precision limits
        # or aliasing may occur.
        if current_frequency > 1000.0: # Arbitrary high threshold for stability
            break
            
    # Normalize result
    if max_possible_value > 0:
        return total_value / max_possible_value
    else:
        return 0.0
```

### Edge Cases and Pitfalls
- **Aliasing**: The fractal summation must be cut off when the frequency becomes too large for the noise to be properly represented between neighboring pixels [S5]. High frequencies can cause aliasing artifacts.
- **Turbulence vs. Standard FBM**: Using `abs(noise)` instead of signed noise creates a "turbulence" effect, resulting in a white-noise-like texture rather than a cloudy one [S1, unofficial]. The pseudocode above uses signed noise for standard fBm.
- **Normalization**: If the base Perlin noise range is not exactly $[-1, 1]$ or if amplitudes do not sum to 1, the output range may vary. Normalization by `max_possible_value` ensures consistent output range regardless of persistence [S2, unofficial].
- **Precision**: At very high frequencies, floating-point precision errors in the Perlin noise interpolation may become visible.

## Subtopics

### Turbulence
A variant of fBm that uses the absolute value of the noise function (`abs(noise)`) at each octave. This creates a white-noise-like texture with sharp peaks, distinct from the cloudy, signed noise of standard fBm [S1, unofficial].

### Worley fBm
Uses Worley noise instead of Perlin noise as the base function. This results in cellular patterns rather than smooth gradients, useful for different types of procedural textures [S5].

## Operating characteristics
- **Time Complexity**: $O(O \cdot C)$, where $O$ is the number of octaves and $C$ is the cost of a single Perlin noise evaluation (constant for fixed grid size). Linear with respect to octaves.
- **Memory Complexity**: $O(1)$ additional memory beyond the permutation table of the base Perlin noise.
- **Measured Performance**: Performance is dominated by the base Perlin noise evaluation. On modern CPUs, a single Perlin 2D evaluation is very fast. The loop overhead is negligible for small $O$ (e.g., 5-8).
- **Scaling**: Scales linearly with the number of octaves. Increasing lacunarity does not change computational cost but affects visual detail.
- **Strengths**: Produces natural-looking, multi-scale detail; simple to implement; computationally inexpensive.
- **Limitations**: Can alias at high frequencies; requires careful tuning of persistence and lacunarity for desired aesthetic; not strictly self-similar in a mathematical sense (unlike true Brownian motion) but approximates it visually.
- **When to use**: Procedural terrain generation, cloud density, wood grain, marble textures.
- **When not to use**: When strict mathematical self-similarity is required, or when performance is critical and only a single scale of noise is needed.

## Background
Fractal Brownian Motion (fBm) is a technique inspired by the mathematical concept of Brownian motion, adapted for procedural texture generation. It was popularized in computer graphics by Ken Perlin and others in the 1980s and 1990s for generating natural-looking textures. The specific combination with Perlin Noise leverages the smoothness and continuity of Perlin's gradient noise to create coherent, multi-scale structures. It is widely used in volume rendering for cloud simulation, terrain heightmaps, and material shading.
