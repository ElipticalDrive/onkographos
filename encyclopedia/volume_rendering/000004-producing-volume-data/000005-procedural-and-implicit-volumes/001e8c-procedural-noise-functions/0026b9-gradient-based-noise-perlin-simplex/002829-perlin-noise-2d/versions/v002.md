# Perlin Noise 2D

Also called: 2D Perlin Noise, RawPerlin2D

## Overview
Perlin Noise 2D is a gradient noise function that generates smooth, continuous random values by interpolating dot products of gradient vectors and distance vectors at the corners of the unit grid cell containing the query point [S1, unofficial]. It is the foundational 2D primitive for procedural texture generation in volume rendering, providing the base frequency component for fractal Brownian motion (fBm) [S1, S2, S3, unofficial]. It differs from Simplex Noise by using an axis-aligned grid and cubic interpolation, which is computationally simpler but produces directional artifacts along the axes [S1, unofficial].

## How it works
**Inputs:**
- `X`, `Y`: Floating-point coordinates in 2D space.
- `Seed`: Integer seed for the permutation table generation.

**Outputs:**
- `Result`: A floating-point value in the range $[-1, 1]$ (typically, depending on gradient normalization, though the standard implementation yields values roughly in this range).

**Data Structures:**
- `Permutation Table`: An array of 512 `uint8` values. It consists of two concatenated copies of a shuffled permutation of indices $0$ to $255$. This doubling avoids modulo operations when accessing indices near the grid boundary.

**Steps:**
1.  **Initialize Permutation Table**: If not already cached for the given `Seed`, generate the table.
    - Create array `P` of size 256 initialized to $[0, 1, ..., 255]$.
    - Use a seeded random number generator to shuffle `P` using Fisher-Yates shuffle.
    - Copy `P` into `OutTable[0...255]` and `OutTable[256...511]`.
2.  **Grid Coordinates**: Compute the integer coordinates of the cell containing $(X, Y)$.
    - $XI = \lfloor X \rfloor \pmod{256}$ (implemented as `floor(X) & 255`).
    - $YI = \lfloor Y \rfloor \pmod{256}$ (implemented as `floor(Y) & 255`).
3.  **Fractional Coordinates**: Compute the position within the cell.
    - $XF = X - \lfloor X \rfloor$.
    - $YF = Y - \lfloor Y \rfloor$.
4.  **Fade Values**: Apply the smoothstep-like fade function to reduce grid alignment artifacts.
    - $U = \text{Fade}(XF)$.
    - $V = \text{Fade}(YF)$.
5.  **Gradient Index Lookup**: Determine the gradient indices for the four corners of the cell using the permutation table.
    - $AA = P[P[XI] + YI]$
    - $AB = P[P[XI] + YI + 1]$
    - $BA = P[P[XI + 1] + YI]$
    - $BB = P[P[XI + 1] + YI + 1]$
6.  **Gradient Dot Products**: Compute the dot product of the gradient vector (selected by hash) and the distance vector from the corner to the point.
    - $G_{AA} = \text{Grad}(AA, XF, YF)$
    - $G_{BA} = \text{Grad}(BA, XF - 1, YF)$
    - $G_{AB} = \text{Grad}(AB, XF, YF - 1)$
    - $G_{BB} = \text{Grad}(BB, XF - 1, YF - 1)$
7.  **Interpolation**:
    - Interpolate along the X-axis:
        - $L_1 = \text{Lerp}(U, G_{AA}, G_{BA})$
        - $L_2 = \text{Lerp}(U, G_{AB}, G_{BB})$
    - Interpolate along the Y-axis:
        - $\text{Result} = \text{Lerp}(V, L_1, L_2)$

**Formulas:**
- **Fade**: $F(t) = 6t^5 - 15t^4 + 10t^3$ [S1, unofficial].
- **Lerp**: $L(t, A, B) = A + t(B - A)$ [S1, unofficial].
- **Grad**: The gradient function maps a 3-bit hash to one of 8 2D vectors. Let $h = \text{Hash} \ \& \ 7$ [S1, unofficial]:
  $$
  \text{Grad}(h, x, y) = 
  \begin{cases} 
  x + y & \text{if } h = 0 \\
  x - y & \text{if } h = 1 \\
  -x + y & \text{if } h = 2 \\
  -x - y & \text{if } h = 3 \\
  x & \text{if } h = 4 \\
  -x & \text{if } h = 5 \\
  y & \text{if } h = 6 \\
  -y & \text{otherwise}
  \end{cases}
  $$
  [S1, unofficial].

**Pseudocode:**
```python
def fade(t):
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

def lerp(t, a, b):
    return a + t * (b - a)

def grad(hash_val, x, y):
    h = hash_val & 7
    if h == 0: return x + y
    if h == 1: return x - y
    if h == 2: return -x + y
    if h == 3: return -x - y
    if h == 4: return x
    if h == 5: return -x
    if h == 6: return y
    return -y

def perlin_2d(x, y, seed):
    # 1. Build Permutation Table if needed
    # In a real implementation, this would be cached or passed as an argument.
    # Here we assume a global or class-level permutation table 'P' of size 512
    # is initialized based on 'seed'.
    
    # 2. Grid coordinates
    xi = int(x) & 255
    yi = int(y) & 255
    
    # 3. Fractional coordinates
    xf = x - int(x)
    yf = y - int(y)
    
    # 4. Fade values
    u = fade(xf)
    v = fade(yf)
    
    # 5. Gradient indices
    aa = P[P[xi] + yi]
    ab = P[P[xi] + yi + 1]
    ba = P[P[xi + 1] + yi]
    bb = P[P[xi + 1] + yi + 1]
    
    # 6. Gradient dot products
    g_aa = grad(aa, xf, yf)
    g_ba = grad(ba, xf - 1.0, yf)
    g_ab = grad(ab, xf, yf - 1.0)
    g_bb = grad(bb, xf - 1.0, yf - 1.0)
    
    # 7. Interpolation
    x_lerp_1 = lerp(u, g_aa, g_ba)
    x_lerp_2 = lerp(u, g_ab, g_bb)
    result = lerp(v, x_lerp_1, x_lerp_2)
    
    return result
```

**Parameters:**
- `Seed`: Any integer. Typical values are arbitrary constants or time-based seeds.
- `Permutation Table Size`: Fixed at 512 entries [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Conditions**: The permutation table must be doubled to 512 entries to handle cases where $XI+1$ or $YI+1$ exceeds 255, avoiding expensive modulo operations inside the hot loop [S1, unofficial].
- **Precision**: Using `floor` and bitwise AND on negative coordinates requires care. The implementation uses `int(x) & 255`, which behaves correctly for negative numbers in two's complement if `int()` truncates towards zero (as in C++/Python `int()` on floats) combined with the specific bitwise logic, but standard `floor` is safer for mathematical correctness across all quadrants [G]. The source code uses `FMath::FloorToInt` which floors towards negative infinity, then masks with 255.

## Subtopics

### [Fractal Brownian Motion (fBm) with Perlin Noise](4253-fractal-brownian-motion-fbm-with-perlin-noise.md)
Fractal Brownian Motion (fBm) with Perlin Noise is a procedural technique that generates rougher, more natural-looking noise by summing multiple octaves of base Perlin noise with increasing frequency and decreasing amplitude. It builds on [Perlin Noise 2D](4211-perlin-noise-2d.md) to produce self-similar detail at multiple scales, mimicking natural phenomena like terrain or clouds. Unlike simple Perlin noise, fBm creates a hierarchical structure where fine details are layered over coarse shapes.

## Operating characteristics
- **Time Complexity**: $O(1)$ per query. The computation involves a fixed number of arithmetic operations, table lookups, and interpolations, independent of the resolution or scene complexity.
- **Memory Complexity**: $O(1)$ auxiliary space for the permutation table (512 bytes).
- **Performance**: Very fast on modern CPUs due to lack of branching in the core interpolation logic (if implemented with bitwise ops) and minimal memory access. The gradient function has a small switch statement which may branch, but the branch predictor handles the uniform distribution of hashes well.
- **Strengths**: Simple to implement; produces smooth, continuous results; widely supported and understood.
- **Limitations**: Exhibits directional artifacts along the grid axes (diagonal seams) due to the square grid structure and the specific gradient selection [S1, unofficial]. Less efficient in higher dimensions compared to Simplex Noise.
- **When to use**: When 2D procedural textures are needed and performance is critical, or when integrating with existing systems expecting standard Perlin noise.
- **When not to use**: When isotropic noise is required (use Simplex Noise) or when generating 3D volumes directly without dimensionality reduction.

## Background
Perlin Noise was introduced by Ken Perlin in 1985 for the movie *Tron* [S1, unofficial]. The 2D version described here is the "Improved Perlin Noise" (1985/2002), which uses the quintic fade function $6t^5 - 15t^4 + 10t^3$ to reduce grid artifacts compared to the original cubic interpolation [S1, unofficial]. It remains a standard component in procedural generation libraries for games and VFX.
