# Perlin Noise 2D

Also called: 2D Perlin Noise, RawPerlin2D

## Overview
Perlin Noise 2D is a gradient-based procedural noise function that generates smooth, continuous scalar values by interpolating dot products of gradient vectors and distance vectors at the corners of the grid cell containing the query point [S1, unofficial]. It solves the problem of generating coherent, deterministic random fields for texture synthesis and terrain generation, distinguishing itself from its siblings by using a fixed square grid with 8 specific gradient directions and quintic interpolation [S1, unofficial]. Unlike Simplex Noise, it does not use a simplex lattice, making it computationally simpler but potentially more prone to directional artifacts [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Query point $P = (X, Y)$ where $X, Y \in \mathbb{R}$; Seed $S \in \mathbb{Z}$ for permutation table generation.
- Output: Scalar value $V \in [-1, 1]$ (normalized range depends on gradient selection, typically bounded by $\sqrt{2}$ or $1$ depending on implementation, but the provided source normalizes via the specific gradient set).

**Data Structures:**
- **Permutation Table (`P`):** An array of 512 `uint8` values. Indices 0–255 contain a shuffled permutation of 0–255. Indices 256–511 are a duplicate of 0–255 to handle boundary conditions without modulo operations [S1, unofficial].
- **Gradient Set:** 8 fixed 2D vectors derived from the low 3 bits of the hash index [S1, unofficial]:
  - $0: (1, 1)$
  - $1: (1, -1)$
  - $2: (-1, 1)$
  - $3: (-1, -1)$
  - $4: (1, 0)$
  - $5: (-1, 0)$
  - $6: (0, 1)$
  - $7: (0, -1)$

**Algorithm Steps:**
1.  **Initialize Permutation Table:** Create a table `P` of size 512. Shuffle indices 0–255 using a seeded random number generator (e.g., Fisher-Yates shuffle). Copy the first 256 entries to indices 256–511 [S1, unofficial].
2.  **Grid Cell Identification:** Compute integer coordinates of the cell containing $P$:
    $$XI = \lfloor X \rfloor \pmod{256}$$
    $$YI = \lfloor Y \rfloor \pmod{256}$$
    *Note: In the reference implementation, bitwise AND with 255 (`& 255`) is used for modulo 256 [S1, unofficial].*
3.  **Fractional Coordinates:** Compute the position of $P$ within the cell:
    $$XF = X - \lfloor X \rfloor$$
    $$YF = Y - \lfloor Y \rfloor$$
4.  **Fade Function:** Apply the quintic fade function to $XF$ and $YF$ to ensure smooth derivatives:
    $$U = 6U^5 - 15U^4 + 10U^3$$
    $$V = 6V^5 - 15V^4 + 10V^3$$
    where $U = XF$ and $V = YF$ before fading [S1, unofficial].
5.  **Hash Lookup:** Compute hash values for the four corners of the cell using the permutation table:
    $$AA = P[P[XI] + YI]$$
    $$AB = P[P[XI] + YI + 1]$$
    $$BA = P[P[XI + 1] + YI]$$
    $$BB = P[P[XI + 1] + YI + 1]$$
6.  **Gradient Dot Products:** Compute the dot product of the gradient vector (selected by the hash) and the distance vector from the corner to $P$:
    -   $G_{AA} = \text{Grad}(AA, XF, YF)$
    -   $G_{BA} = \text{Grad}(BA, XF - 1, YF)$
    -   $G_{AB} = \text{Grad}(AB, XF, YF - 1)$
    -   $G_{BB} = \text{Grad}(BB, XF - 1, YF - 1)$
    
    The `Grad` function maps the hash index $h$ to a vector and computes the dot product with $(x, y)$ [S1, unofficial]:
    $$
    \text{Grad}(h, x, y) = 
    \begin{cases} 
    x + y & \text{if } h \& 7 == 0 \\
    x - y & \text{if } h \& 7 == 1 \\
    -x + y & \text{if } h \& 7 == 2 \\
    -x - y & \text{if } h \& 7 == 3 \\
    x & \text{if } h \& 7 == 4 \\
    -x & \text{if } h \& 7 == 5 \\
    y & \text{if } h \& 7 == 6 \\
    -y & \text{otherwise}
    \end{cases}
    $$
7.  **Interpolation:** Interpolate the results along the X axis, then the Y axis:
    $$L_x = \text{Lerp}(U, G_{AA}, G_{BA})$$
    $$L_y = \text{Lerp}(U, G_{AB}, G_{BB})$$
    $$V = \text{Lerp}(V, L_x, L_y)$$
    where $\text{Lerp}(t, a, b) = a + t(b - a)$ [S1, unofficial].

**Pseudocode:**
```python
def perlin_noise_2d(x: float, y: float, seed: int) -> float:
    # 1. Initialize Permutation Table
    # In a real implementation, this is cached or precomputed.
    p = list(range(256))
    # Fisher-Yates shuffle with seed
    rng = Random(seed)
    for i in range(255, 0, -1):
        j = rng.randint(0, i)
        p[i], p[j] = p[j], p[i]
    # Double the table
    p = p + p

    # 2. Grid Cell and Fractional Parts
    xi = int(x) & 255
    yi = int(y) & 255
    xf = x - int(x)
    yf = y - int(y)

    # 3. Fade Function
    u = fade(xf)
    v = fade(yf)

    # 4. Hash Lookups
    aa = p[p[xi] + yi]
    ab = p[p[xi] + yi + 1]
    ba = p[p[xi + 1] + yi]
    bb = p[p[xi + 1] + yi + 1]

    # 5. Gradient Dot Products
    g_aa = grad(aa, xf, yf)
    g_ba = grad(ba, xf - 1, yf)
    g_ab = grad(ab, xf, yf - 1)
    g_bb = grad(bb, xf - 1, yf - 1)

    # 6. Interpolation
    x_lerp_1 = lerp(u, g_aa, g_ba)
    x_lerp_2 = lerp(u, g_ab, g_bb)
    result = lerp(v, x_lerp_1, x_lerp_2)

    return result

def fade(t: float) -> float:
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

def lerp(t: float, a: float, b: float) -> float:
    return a + t * (b - a)

def grad(hash_val: int, x: float, y: float) -> float:
    h = hash_val & 7
    u = x if h < 4 else y
    v = y if h < 4 else x
    return (u if (h & 1) == 0 else -u) + (v if (h & 2) == 0 else -v)
```

**Parameters:**
- `seed`: Integer seed for permutation table generation. Default: Not specified [S1, unofficial].
- `x, y`: Floating-point coordinates.

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** The permutation table must be doubled to 512 entries to handle cases where $XI+1$ or $YI+1$ exceeds 255, avoiding expensive modulo operations in the hot loop [S1, unofficial].
- **Precision:** Using `int()` for floor is standard, but negative coordinates require careful handling of bitwise AND with 255 to ensure correct wrapping (e.g., `-1 & 255` is `255` in two's complement, which is correct for wrapping) [S1, unofficial].

## Subtopics

### [Fractal Brownian Motion (fBm) with Perlin Noise](4253-fractal-brownian-motion-fbm-with-perlin-noise.md)
Fractal Brownian Motion (fBm) with Perlin Noise is a procedural technique that generates rougher, more natural-looking noise by summing multiple octaves of base Perlin noise with increasing frequency and decreasing amplitude. It builds on [Perlin Noise 2D](4211-perlin-noise-2d.md) to produce self-similar detail at multiple scales, mimicking natural phenomena like terrain or clouds. Unlike simple Perlin noise, fBm creates a hierarchical structure where fine details are layered over coarse shapes.

## Operating characteristics
- **Time Complexity:** $O(1)$ per query, as it involves a fixed number of arithmetic operations and table lookups regardless of input scale.
- **Memory Complexity:** $O(1)$ for the permutation table (512 bytes).
- **Performance:** Very fast on modern CPUs due to lack of branching in the core interpolation and efficient use of bitwise operations [S1, unofficial].
- **Strengths:** Simple to implement, deterministic, smooth derivatives [S1, unofficial].
- **Limitations:** Directional artifacts (grid-aligned lines) are more visible than in Simplex Noise due to the square grid structure [S1, unofficial].

## Background
Perlin Noise was introduced by Ken Perlin in 1985 for the movie *Tron* [S1, unofficial]. The 2D variant described here is a common implementation found in game development and procedural generation libraries, often referred to as "Classic Perlin Noise" or "Improved Perlin Noise" (referring to the 1985 improved version with the fade function) [S1, unofficial]. The specific implementation provided in the source is from a Unreal Engine 5 Minecraft clone project [S1, unofficial].
