# Perlin Noise 2D

Also called: 2D Perlin Noise, RawPerlin2D

## Overview
Perlin Noise 2D is a gradient noise function that generates smooth, continuous random scalar values by interpolating dot products of gradient vectors and distance vectors at the corners of the grid cell containing the query point [S1, unofficial]. It builds on [Gradient-based Noise (Perlin/Simplex)](3860-gradient-based-noise-perlin-simplex.md) by specializing the general framework to two dimensions. Unlike [Simplex Noise](978-simplex-noise.md), which uses a simplex grid to reduce directional artifacts, Perlin Noise 2D operates on a standard square grid, relying on specific smooth interpolation functions to maintain coherence [S1, unofficial].

## How it works
**Inputs:** Query coordinates $X, Y \in \mathbb{R}$; a seed integer for permutation table generation.
**Outputs:** A scalar value $V \in [-1, 1]$.

**Data Structures:**
*   **Permutation Table:** An array `P` of 512 `uint8` values. Indices 0–255 contain a shuffled permutation of 0–255. Indices 256–511 are a duplicate of 0–255 to handle boundary conditions without modulo operations [S1, unofficial].

**Steps:**
1.  **Initialize Permutation Table:** Create a table `P` of size 256 initialized to $[0, 1, \dots, 255]$. Shuffle it using a seeded random number generator (e.g., Fisher-Yates). Duplicate the table to size 512: `P[i+256] = P[i]` for $i \in [0, 255]$ [S1, unofficial].
2.  **Grid Coordinates:** Compute integer cell coordinates:
    $$XI = \lfloor X \rfloor \pmod{256}$$
    $$YI = \lfloor Y \rfloor \pmod{256}$$
    Using bitwise AND (`& 255`) is equivalent to modulo 256 for positive integers and avoids expensive division [S1, unofficial].
3.  **Fractional Coordinates:** Compute the position within the cell:
    $$XF = X - \lfloor X \rfloor$$
    $$YF = Y - \lfloor Y \rfloor$$
4.  **Fade Values:** Apply the smooth fade function to the fractional coordinates to determine interpolation weights:
    $$U = \text{Fade}(XF)$$
    $$V = \text{Fade}(YF)$$
5.  **Gradient Indices:** Lookup the gradient indices for the four corners of the cell using the permutation table:
    $$AA = P[P[XI] + YI]$$
    $$AB = P[P[XI] + YI + 1]$$
    $$BA = P[P[XI + 1] + YI]$$
    $$BB = P[P[XI + 1] + YI + 1]$$
6.  **Gradient Dot Products:** Compute the dot product of the gradient vector (determined by the hash) and the distance vector from the corner to the query point:
    *   Corner $(0,0)$: $G_{AA} = \text{Grad}(AA, XF, YF)$
    *   Corner $(1,0)$: $G_{BA} = \text{Grad}(BA, XF - 1, YF)$
    *   Corner $(0,1)$: $G_{AB} = \text{Grad}(AB, XF, YF - 1)$
    *   Corner $(1,1)$: $G_{BB} = \text{Grad}(BB, XF - 1, YF - 1)$
7.  **Interpolation:** Interpolate along the X-axis, then the Y-axis:
    $$L_X = \text{Lerp}(U, G_{AA}, G_{BA})$$
    $$R_X = \text{Lerp}(U, G_{AB}, G_{BB})$$
    $$V = \text{Lerp}(V, L_X, R_X)$$

**Formulas:**
*   **Fade:** $F(t) = 6t^5 - 15t^4 + 10t^3$ [S1, unofficial].
*   **Lerp:** $L(t, A, B) = A + t(B - A)$ [S1, unofficial].
*   **Grad:** The gradient function maps a hash integer to a dot product. For 2D, the low 3 bits of the hash determine the direction [S1, unofficial]:
    $$
    \text{Grad}(h, x, y) = 
    \begin{cases} 
    x + y & h \& 7 == 0 \\
    x - y & h \& 7 == 1 \\
    -x + y & h \& 7 == 2 \\
    -x - y & h \& 7 == 3 \\
    x & h \& 7 == 4 \\
    -x & h \& 7 == 5 \\
    y & h \& 7 == 6 \\
    -y & \text{otherwise}
    \end{cases}
    $$

**Pseudocode:**
```python
def fade(t):
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

def lerp(t, a, b):
    return a + t * (b - a)

def grad(hash_val, x, y):
    h = hash_val & 7
    if h == 0: return x + y
    if h == 1: return x - y
    if h == 2: return -x + y
    if h == 3: return -x - y
    if h == 4: return x
    if h == 5: return -x
    if h == 6: return y
    return -y

def perlin_2d(x, y, perm_table):
    # 1. Grid coordinates
    xi = int(x) & 255
    yi = int(y) & 255
    
    # 2. Fractional coordinates
    xf = x - int(x)
    yf = y - int(y)
    
    # 3. Fade values
    u = fade(xf)
    v = fade(yf)
    
    # 4. Gradient indices
    aa = perm_table[perm_table[xi] + yi]
    ab = perm_table[perm_table[xi] + yi + 1]
    ba = perm_table[perm_table[xi + 1] + yi]
    bb = perm_table[perm_table[xi + 1] + yi + 1]
    
    # 5. Gradient dot products
    g_aa = grad(aa, xf, yf)
    g_ba = grad(ba, xf - 1.0, yf)
    g_ab = grad(ab, xf, yf - 1.0)
    g_bb = grad(bb, xf - 1.0, yf - 1.0)
    
    # 6. Interpolation
    x1 = lerp(u, g_aa, g_ba)
    x2 = lerp(u, g_ab, g_bb)
    result = lerp(v, x1, x2)
    
    return result
```

## Subtopics

### [Fractal Brownian Motion (fBm) with Perlin Noise](4253-fractal-brownian-motion-fbm-with-perlin-noise.md)
Fractal Brownian Motion (fBm) with Perlin Noise is a procedural technique that generates rougher, more natural-looking noise by summing multiple octaves of base Perlin noise with increasing frequency and decreasing amplitude. It builds on [Perlin Noise 2D](4211-perlin-noise-2d.md) to produce self-similar detail at multiple scales, mimicking natural phenomena like terrain or clouds. Unlike simple Perlin noise, fBm creates a hierarchical structure where fine details are layered over coarse shapes.

## Operating characteristics
**Time Complexity:** $O(1)$ per query. The computation involves a fixed number of arithmetic operations and table lookups, independent of resolution [S1, unofficial].
**Memory Complexity:** $O(1)$ for the permutation table (512 bytes). No spatial data structures are required [S1, unofficial].
**Strengths:** Produces smooth, continuous values with no visible seams at integer boundaries when the fade function is applied correctly. Simple to implement and fast [S1, unofficial].
**Limitations:** Exhibits directional artifacts (grid-aligned patterns) due to the square grid structure, which can be noticeable in textures or terrain [S1, unofficial]. The range of output values is typically $[-1, 1]$ but depends on the specific gradient set and interpolation [S1, unofficial].
**When to use:** When a simple, fast, and smooth noise function is needed for 2D procedural generation, and directional artifacts are acceptable or mitigated by further processing (e.g., domain warping) [S1, unofficial].
**When not to use:** When high-quality isotropic noise is required without post-processing; [Simplex Noise](978-simplex-noise.md) is preferred in such cases [S1, unofficial].

## Background
Perlin Noise was introduced by Ken Perlin in 1985 for the movie *Tron* [S1, unofficial]. The 2D variant is the foundational implementation of gradient noise, later extended to 3D and improved with better interpolation functions (e.g., the 6th-order polynomial used in the source) [S1, unofficial]. It remains a standard technique in procedural content generation for games and simulations [S1, unofficial].
