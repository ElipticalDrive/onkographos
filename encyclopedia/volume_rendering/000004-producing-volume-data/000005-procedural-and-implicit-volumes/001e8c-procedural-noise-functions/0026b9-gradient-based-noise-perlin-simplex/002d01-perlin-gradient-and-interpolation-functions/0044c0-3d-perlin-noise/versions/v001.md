# 3D Perlin Noise
Also called: BasicPerlinNoise::noise3D

## Overview
3D Perlin Noise generates a continuous scalar value for 3D space by interpolating gradient vectors assigned to lattice points using cubic smoothing functions [S1, unofficial]. It differs from its sibling [Simplex Noise](5416-simplex-noise.md) by using an axis-aligned cubic lattice and standard trilinear interpolation of gradients, whereas Simplex Noise uses a simplex grid and different interpolation to reduce directional artifacts [S1, unofficial].

## How it works
**Inputs and Outputs**
- Input: A 3D point $(x, y, z)$ in continuous space.
- Output: A scalar noise value $N(x, y, z)$, typically in the range $[-1, 1]$ or $[0, 1]$ depending on post-processing.

**Data Structures**
The method relies on a permutation table to map integer coordinates to gradient vectors.
- **Permutation Table**: An array of 256 integers (typically `uint8_t` or `int32_t`). The standard implementation uses a shuffled permutation of $0 \dots 255$ to ensure uniform distribution of gradients. Let this table be $P$.
- **Gradient Vectors**: For 3D Perlin noise, there are 12 standard gradient vectors. These are usually defined as permutations of $(\pm 1, \pm 1, 0)$ and $(\pm 1, 0, \pm 1)$ and $(0, \pm 1, \pm 1)$. Let $G[i]$ be the gradient vector selected by index $i \in [0, 11]$.

**Algorithm Steps**
1. **Integer and Fractional Parts**: Compute the integer coordinates of the lattice cube containing the point and the fractional offset within the cube.
   $$
   X = \lfloor x \rfloor, \quad Y = \lfloor y \rfloor, \quad Z = \lfloor z \rfloor
   $$
   $$
   x_f = x - X, \quad y_f = y - Y, \quad z_f = z - Z
   $$
   The fractional parts $x_f, y_f, z_f$ lie in $[0, 1)$.

2. **Fade Functions**: Apply the cubic smoothing function (fade function) to the fractional parts to ensure $C^1$ continuity. The standard Perlin fade function is:
   $$
   u = 6t^5 - 15t^4 + 10t^3
   $$
   where $t$ is the fractional component ($x_f, y_f, z_f$). Let the faded values be $u, v, w$.

3. **Permutation Lookup**: Determine the indices of the 8 corners of the unit cube. The permutation table is used to map the integer coordinates to gradient indices. The indices are computed using bitwise AND with 255 (equivalent to modulo 256 for positive integers) to handle wrapping:
   $$
   A = P[X \& 255] + Y
   $$
   $$
   B = P[(X + 1) \& 255] + Y
   $$
   $$
   AA = P[A \& 255] + Z
   $$
   $$
   AB = P[(A + 1) \& 255] + Z
   $$
   $$
   BA = P[B \& 255] + Z
   $$
   $$
   BB = P[(B + 1) \& 255] + Z
   $$
   The final gradient indices for the 8 corners are:
   - Corner $(0,0,0)$: $P[AA \& 255]$
   - Corner $(1,0,0)$: $P[BA \& 255]$
   - Corner $(0,1,0)$: $P[AB \& 255]$
   - Corner $(1,1,0)$: $P[BB \& 255]$
   - Corner $(0,0,1)$: $P[(AA + 1) \& 255]$
   - Corner $(1,0,1)$: $P[(BA + 1) \& 255]$
   - Corner $(0,1,1)$: $P[(AB + 1) \& 255]$
   - Corner $(1,1,1)$: $P[(BB + 1) \& 255]$

4. **Gradient Dot Products**: Compute the dot product of the gradient vector at each corner with the distance vector from that corner to the sample point. Let $G_k$ be the gradient vector for corner $k$. The distance vectors are:
   - $d_0 = (x_f, y_f, z_f)$
   - $d_1 = (x_f - 1, y_f, z_f)$
   - $d_2 = (x_f, y_f - 1, z_f)$
   - $d_3 = (x_f - 1, y_f - 1, z_f)$
   - $d_4 = (x_f, y_f, z_f - 1)$
   - $d_5 = (x_f - 1, y_f, z_f - 1)$
   - $d_6 = (x_f, y_f - 1, z_f - 1)$
   - $d_7 = (x_f - 1, y_f - 1, z_f - 1)$

   The contributions are:
   $$
   p_0 = G_0 \cdot d_0, \quad p_1 = G_1 \cdot d_1, \quad p_2 = G_2 \cdot d_2, \quad p_3 = G_3 \cdot d_3
   $$
   $$
   p_4 = G_4 \cdot d_4, \quad p_5 = G_5 \cdot d_5, \quad p_6 = G_6 \cdot d_6, \quad p_7 = G_7 \cdot d_7
   $$

5. **Trilinear Interpolation**: Interpolate the 8 values along the X, Y, and Z axes using the fade values $u, v, w$.
   - X-axis interpolation:
     $$
     q_0 = \text{Lerp}(p_0, p_1, u)
     $$
     $$
     q_1 = \text{Lerp}(p_2, p_3, u)
     $$
     $$
     q_2 = \text{Lerp}(p_4, p_5, u)
     $$
     $$
     q_3 = \text{Lerp}(p_6, p_7, u)
     $$
   - Y-axis interpolation:
     $$
     r_0 = \text{Lerp}(q_0, q_1, v)
     $$
     $$
     r_1 = \text{Lerp}(q_2, q_3, v)
     $$
   - Z-axis interpolation:
     $$
     N(x, y, z) = \text{Lerp}(r_0, r_1, w)
     $$
   Where $\text{Lerp}(a, b, t) = a + t(b - a)$.

**Pseudocode**
```python
def fade(t):
    # Cubic smoothing function
    return t * t * t * (t * (t * 6 - 15) + 10)

def lerp(t, a, b):
    return a + t * (b - a)

def grad(hash_val, x, y, z):
    # Select gradient vector based on hash_val (0-11)
    # Standard 3D gradients: permutations of (1,1,0), (1,0,1), (0,1,1), etc.
    h = hash_val & 15
    u = x if h < 8 else y
    v = y if h < 4 else (x if h == 12 or h == 14 else y)
    
    # Determine sign based on the least significant bit
    if (h & 1) == 0:
        u = -u
    if (h & 2) == 0:
        v = -v
        
    return u + v

def perlin_noise_3d(x, y, z, perm_table):
    # 1. Integer and fractional parts
    X = int(floor(x))
    Y = int(floor(y))
    Z = int(floor(z))
    
    x_f = x - X
    y_f = y - Y
    z_f = z - Z
    
    # 2. Fade values
    u = fade(x_f)
    v = fade(y_f)
    w = fade(z_f)
    
    # 3. Permutation lookups
    # Masking with 255 is equivalent to modulo 256 for positive indices
    A = (perm_table[X & 255] + Y) & 255
    B = (perm_table[(X + 1) & 255] + Y) & 255
    
    AA = (perm_table[A] + Z) & 255
    AB = (perm_table[(A + 1) & 255] + Z) & 255
    BA = (perm_table[B] + Z) & 255
    BB = (perm_table[(B + 1) & 255] + Z) & 255
    
    # 4. Gradient dot products
    p0 = grad(perm_table[AA], x_f, y_f, z_f)
    p1 = grad(perm_table[BA], x_f - 1, y_f, z_f)
    p2 = grad(perm_table[AB], x_f, y_f - 1, z_f)
    p3 = grad(perm_table[BB], x_f - 1, y_f - 1, z_f)
    
    p4 = grad(perm_table[(AA + 1) & 255], x_f, y_f, z_f - 1)
    p5 = grad(perm_table[(BA + 1) & 255], x_f - 1, y_f, z_f - 1)
    p6 = grad(perm_table[(AB + 1) & 255], x_f, y_f - 1, z_f - 1)
    p7 = grad(perm_table[(BB + 1) & 255], x_f - 1, y_f - 1, z_f - 1)
    
    # 5. Interpolation
    q0 = lerp(u, p0, p1)
    q1 = lerp(u, p2, p3)
    q2 = lerp(u, p4, p5)
    q3 = lerp(u, p6, p7)
    
    r0 = lerp(v, q0, q1)
    r1 = lerp(v, q2, q3)
    
    return lerp(w, r0, r1)
```

**Parameters**
- **Persistence**: Not applicable to a single octave. Used in octave summation.
- **Octaves**: Not applicable to a single octave. Used in octave summation.
- **Lacunarity**: Not applicable to a single octave. Used in octave summation.

**Edge Cases and Pitfalls**
- **Precision**: Floating-point precision errors can accumulate in high-resolution or large-coordinate scenarios. Using double precision is recommended for large worlds [S1, unofficial].
- **Boundaries**: The permutation table wrapping ensures continuity across integer boundaries. However, if the permutation table is not properly shuffled, artifacts may appear.
- **Degenerate Input**: The method is well-defined for all real inputs.

## Operating characteristics
- **Time Complexity**: $O(1)$ per sample. The number of operations is constant regardless of the input coordinates.
- **Memory Complexity**: $O(1)$ auxiliary space, plus $O(1)$ for the permutation table (256 entries).
- **Performance**: Very fast, suitable for real-time applications. The main cost is the arithmetic operations and table lookups.
- **Strengths**: Continuous derivatives ($C^1$), isotropic appearance (though less so than Simplex Noise), well-understood.
- **Limitations**: Directional artifacts along the axes are more pronounced than in Simplex Noise. The cubic interpolation is slightly more expensive than the linear interpolation used in some other noise variants.
- **When to use**: When $C^1$ continuity is required and the performance overhead of Simplex Noise is not justified, or when compatibility with existing Perlin-based systems is needed.
- **When not to use**: When directional artifacts are unacceptable, or when higher dimensional noise is needed (Simplex Noise scales better to higher dimensions).

## Background
3D Perlin Noise was introduced by Ken Perlin in 1985 for the movie *Tron* [S1, unofficial]. It has become a standard technique in procedural generation for textures, terrain, and other natural-looking patterns. The method described here is the standard implementation found in many graphics libraries and engines [S1, unofficial].
