# Perlin Gradient and Interpolation Functions

Also called: Fade, Grad, Lerp

## Overview
This article defines the core mathematical primitives of classic 3D Perlin noise: the gradient vector selection, the dot product computation, and the quintic fade (smoothing) function used to interpolate between gradient contributions. It solves the problem of generating coherent, continuous scalar fields from discrete grid points by ensuring $C^1$ continuity (smooth first derivatives) across cell boundaries, which eliminates visible grid artifacts in the resulting volume density [S1, S3, unofficial]. It differs from Simplex noise by using a cubic grid topology and from improved 4D Perlin noise by focusing on the specific 3D gradient set and quintic interpolation curve [S1, S3, unofficial].

## How it works
**Inputs:**
- Query point $P = (x, y, z)$ in continuous space.
- A permutation table $P_{table}$ of size 512 (or 256 extended), containing integers $0..255$.
- A hash function $H(i)$ that maps an integer index to a value in $0..255$ using the permutation table (e.g., $H(i) = P_{table}[i \& 255]$).

**Outputs:**
- Scalar noise value $V \in [-1, 1]$.
- (Optional) Gradient vector $\mathbf{g}$ associated with a specific hash.

**Data Structures:**
- **Permutation Table:** An array of 256 or 512 integers. Standard implementations use 512 to avoid modulo operations for wrapping.
- **Gradient Set:** In 3D, 12 gradient vectors are used. They are defined by permutations of $(\pm 1, 0, 0)$, $(0, \pm 1, 0)$, and $(0, 0, \pm 1)$.

**Numbered Steps:**

1.  **Coordinate Decomposition:**
    Compute the integer cell coordinates and the fractional offset within the cell:
    $$
    i = \lfloor x \rfloor, \quad j = \lfloor y \rfloor, \quad k = \lfloor z \rfloor
    $$
    $$
    X = x - i, \quad Y = y - j, \quad Z = z - k
    $$
    The fractional coordinates $X, Y, Z$ lie in $[0, 1)$.

2.  **Fade Function Application:**
    Apply the quintic interpolation polynomial to each fractional coordinate to obtain smooth weights $u, v, w$. This function ensures $C^1$ continuity and zero derivatives at the boundaries $0$ and $1$ [S1, S3, unofficial]:
    $$
    u = 6X^5 - 15X^4 + 10X^3
    $$
    $$
    v = 6Y^5 - 15Y^4 + 10Y^3
    $$
    $$
    w = 6Z^5 - 15Z^4 + 10Z^3
    $$
    *Note: The original Perlin paper used $3t^2 - 2t^3$, but the quintic version is preferred for better visual results and smoother derivatives [S3, unofficial].*

3.  **Hashing Corner Indices:**
    Compute the hash values for the 8 corners of the unit cube containing $P$. The hash combines the integer coordinates with the permutation table:
    $$
    A = H(i) + j
    $$
    $$
    AA = H(A) + k
    $$
    $$
    AB = H(A + 1) + k
    $$
    $$
    B = H(i + 1) + j
    $$
    $$
    BA = H(B) + k
    $$
    $$
    BB = H(B + 1) + k
    $$
    These indices $AA, AB, BA, BB, \dots$ are used to look up gradient vectors.

4.  **Gradient Selection and Dot Product:**
    For each corner, retrieve the hash value $h$ and compute the dot product between the gradient vector $\mathbf{g}_h$ and the distance vector from the corner to $P$.
    
    The gradient vector $\mathbf{g}_h$ is derived from $h \pmod{15}$ (or $h \& 15$) [S1, unofficial]:
    - Let $h' = h \& 15$.
    - Determine components $u, v$ based on $h'$:
      $$
      u = \begin{cases} X_{corner} & \text{if } h' < 8 \\ Y_{corner} & \text{if } h' \ge 8 \end{cases}
      $$
      $$
      v = \begin{cases} Y_{corner} & \text{if } h' < 4 \\ Z_{corner} & \text{if } h' == 12 \text{ or } h' == 14 \\ X_{corner} & \text{otherwise} \end{cases}
      $$
      *(Where $X_{corner}, Y_{corner}, Z_{corner}$ are the components of the distance vector from the specific corner to $P$)*.
    - Apply signs based on the least significant bits of $h'$:
      $$
      \text{sign}_u = (h' \& 1) ? -1 : 1
      $$
      $$
      \text{sign}_v = (h' \& 2) ? -1 : 1
      $$
    - The dot product contribution is:
      $$
      \text{contrib} = (\text{sign}_u \cdot u) + (\text{sign}_v \cdot v)
      $$

5.  **Trilinear Interpolation:**
    Interpolate the 8 corner contributions using the fade weights $u, v, w$. This is equivalent to a trilinear interpolation in the unit cube:
    $$
    V = \text{Lerp}(\text{Lerp}(\text{Lerp}(c_{000}, c_{100}, u), \text{Lerp}(c_{010}, c_{110}, u), v), \dots, w)
    $$
    Where $c_{ijk}$ is the dot product contribution from the corner $(i, j, k)$.
    
    Explicitly:
    $$
    \begin{aligned}
    x_0 &= \text{Lerp}(c_{000}, c_{100}, u) \\
    x_1 &= \text{Lerp}(c_{010}, c_{110}, u) \\
    x_2 &= \text{Lerp}(c_{001}, c_{101}, u) \\
    x_3 &= \text{Lerp}(c_{011}, c_{111}, u) \\
    y_0 &= \text{Lerp}(x_0, x_1, v) \\
    y_1 &= \text{Lerp}(x_2, x_3, v) \\
    V &= \text{Lerp}(y_0, y_1, w)
    \end{aligned}
    $$

**Pseudocode:**

```python
def fade(t):
    """Quintic interpolation function for C1 continuity."""
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

def lerp(a, b, t):
    """Linear interpolation."""
    return a + (b - a) * t

def grad(hash_val, x, y, z):
    """
    Compute dot product of gradient vector and distance vector.
    hash_val: integer hash (0-255)
    x, y, z: components of the distance vector from the grid point to P
    """
    h = hash_val & 15  # Use only lower 4 bits
    u = x if h < 8 else y
    v = y if h < 4 else (z if h == 12 or h == 14 else x)
    
    # Apply sign based on bits 0 and 1
    sign_u = -1 if (h & 1) else 1
    sign_v = -1 if (h & 2) else 1
    
    return (sign_u * u) + (sign_v * v)

def perlin_noise(x, y, z, perm_table):
    """
    Classic 3D Perlin Noise with quintic fade.
    perm_table: list of 256 or 512 integers
    """
    # 1. Integer coordinates
    xi = int(x) & 255
    yi = int(y) & 255
    zi = int(z) & 255
    
    # 2. Fractional coordinates
    xf = x - int(x)
    yf = y - int(y)
    zf = z - int(z)
    
    # 3. Fade curves
    u = fade(xf)
    v = fade(yf)
    w = fade(zf)
    
    # 4. Hashing
    # Ensure perm_table is large enough or handle wrapping
    p = perm_table
    A = p[xi] + yi
    AA = p[A] + zi
    AB = p[A + 1] + zi
    B = p[xi + 1] + yi
    BA = p[B] + zi
    BB = p[B + 1] + zi
    
    # 5. Gradient contributions
    # Distance vectors from corners to P
    # Corner 000: (xf, yf, zf)
    # Corner 100: (xf-1, yf, zf)
    # etc.
    
    g000 = grad(p[AA], xf, yf, zf)
    g100 = grad(p[BA], xf - 1, yf, zf)
    g010 = grad(p[AB], xf, yf - 1, zf)
    g110 = grad(p[BB], xf - 1, yf - 1, zf)
    g001 = grad(p[AA + 1], xf, yf, zf - 1)
    g101 = grad(p[BA + 1], xf - 1, yf, zf - 1)
    g011 = grad(p[AB + 1], xf, yf - 1, zf - 1)
    g111 = grad(p[BB + 1], xf - 1, yf - 1, zf - 1)
    
    # 6. Interpolation
    x1 = lerp(g000, g100, u)
    x2 = lerp(g010, g110, u)
    y1 = lerp(x1, x2, v)
    
    x1 = lerp(g001, g101, u)
    x2 = lerp(g011, g111, u)
    y2 = lerp(x1, x2, v)
    
    result = lerp(y1, y2, w)
    
    return result
```

**Edge Cases and Pitfalls:**
- **Precision:** Using floating-point coordinates directly can cause precision issues at large coordinate values. It is recommended to use integer arithmetic for the hash lookup indices and only convert to float for the fractional parts [S1, unofficial].
- **Periodicity:** The standard implementation is not periodic. To create seamless textures, the permutation table must be constructed such that $P[i] = P[i + 256]$ or by using a toroidal wrapping scheme for the hash indices [S1, unofficial].
- **Gradient Set:** The 12-gradient set is a heuristic. It is not a true random set of vectors on the unit sphere, but it provides good visual results with low computational cost [S1, unofficial].

## Subtopics

### Quintic Noise
Noise using quintic interpolation ($6t^5 - 15t^4 + 10t^3$) to achieve $C^2$ continuity in the derivative of the fade function, which eliminates visible grid artifacts in the gradient field compared to the $C^1$ Hermite interpolation ($3t^2 - 2t^3$) [S2]. It is chosen when smooth derivatives are required for physics simulations or advanced shading, at the cost of slightly higher computation time [S2].

### Improved Smoothing Function
The replacement of the original Perlin smoothing function $f(x) = 3x^2 - 2x^3$ with the quintic function $f(x) = 6x^5 - 15x^4 + 10x^3$. This variant improves the curve of the interpolation, providing better visual results and smoother transitions, and is the standard implementation in modern procedural noise tools [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per query point. The cost is dominated by a fixed number of hash lookups, arithmetic operations, and interpolations, independent of the grid size.
- **Memory Complexity:** $O(1)$ auxiliary space, requiring only a small permutation table (256 or 512 integers).
- **Performance:** Very fast on modern CPUs and GPUs. The quintic fade requires more multiplications than the cubic fade, but the difference is negligible in practice [S3, unofficial].
- **Strengths:** High coherence, smooth gradients, low memory footprint, easy to implement.
- **Limitations:** Visible grid artifacts (linear seams) if the fade function is not smooth enough; not isotropic (grid-aligned artifacts are visible); lower computational complexity than Simplex noise in higher dimensions [S3, unofficial].
- **When to use:** General-purpose procedural textures, terrain generation, and volume density fields where isotropy is not critical.
- **When not to use:** When isotropic noise is required (use Simplex), or when $C^2$ continuity is strictly needed without the grid structure (use Quintic Noise variants or other methods).

## Background
Classic Perlin noise was introduced by Ken Perlin in 1985 for the movie *Tron* [S1, unofficial]. The original implementation used a cubic smoothing function ($3t^2 - 2t^3$) [S3, unofficial]. In 2002, Perlin published "Improved Noise," which introduced the quintic smoothing function ($6t^5 - 15t^4 + 10x^3$) and a better gradient set, significantly improving visual quality [S3, unofficial]. This method remains a foundational technique in procedural generation for volume rendering and computer graphics [S1, S3, unofficial].
