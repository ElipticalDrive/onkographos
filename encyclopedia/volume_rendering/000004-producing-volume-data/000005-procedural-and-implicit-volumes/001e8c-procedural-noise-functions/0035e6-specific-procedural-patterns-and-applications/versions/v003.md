# Specific Procedural Patterns and Applications

Also called: Procedural Volume Patterns, Procedural Density Functions

## Overview
This family encompasses specific mathematical constructions and application-specific noise functions used to generate volumetric data, density fields, and structural patterns directly from coordinates. It solves the problem of creating deterministic, complex 3D structures (such as clouds, fractals, or tiled terrains) without storing explicit geometry or heightmaps, relying instead on real-time evaluation of trigonometric, iterative, or texture-based functions [S1, unofficial][S2, unofficial]. It differs from general gradient-based noise [3860-gradient-based-noise-perlin-simplex.md] by applying domain-specific transformations (e.g., polar power mapping for fractals, spherical ramps for gas) rather than generic lattice interpolation.

## Shared principles
The family shares the following mechanism, terms, and math:

1.  **Gradient Assignment**: Each integer lattice point (vertex) in the domain is assigned a pseudo-random gradient vector $\mathbf{g}$. In 3D, common sets include 12 face diagonals of a cube or 12 axis-aligned vectors [S1, unofficial][S2, unofficial].
2.  **Dot Product Contribution**: The noise value at a query point $\mathbf{P}$ is derived from the dot product between the gradient vector $\mathbf{g}_i$ at a lattice corner $i$ and the distance vector $\mathbf{d}_i = \mathbf{P} - \mathbf{V}_i$ from that corner to $\mathbf{P}$:
    $$ n_i = \mathbf{g}_i \cdot \mathbf{d}_i $$
3.  **Smoothing/Fade Function**: To ensure smooth transitions ($C^1$ continuity), the fractional coordinates of $\mathbf{P}$ within the cell are passed through a fade function $f(t)$ before interpolation. The quintic function $f(t) = 6t^5 - 15t^4 + 10t^3$ is standard for Perlin variants, while Simplex uses a different geometric approach [S1, unofficial][S2, unofficial].
4.  **Interpolation**: The contributions from the cell corners are combined using linear interpolation (`lerp`) along the axes, weighted by the fade values [S1, unofficial][S2, unofficial].
5.  **Hashing**: Integer coordinates are mapped to gradient indices using a permutation table to avoid modulo operations and ensure uniform distribution [S1, unofficial][S2, unofficial].

## Subtopics

### [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md)
Creates volumetric structures by evaluating trigonometric functions against voxel coordinates to determine occupancy and material properties. It solves the problem of generating deterministic, periodic 3D patterns without storing explicit geometry, relying instead on real-time evaluation of sine functions. It differs from siblings like [Spherical Density Ramp with Noise](2610-spherical-density-ramp-with-noise.md) by using trigonometric interference for shape definition rather than radial ramps. See [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md).

### [Spherical Density Ramp with Noise](2610-spherical-density-ramp-with-noise.md)
Is a procedural volume density function that confines a gas to a slab region using a spherical distance ramp and an offset table, simulating steam rising from a source. It differs from siblings like [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md) and [Mandelbulb Fractal Generation](3327-mandelbulb-fractal-generation.md) by applying a deterministic spherical falloff combined with a discrete random offset table to modulate base turbulence density, avoiding complex flow advection. See [Spherical Density Ramp with Noise](2610-spherical-density-ramp-with-noise.md).

### [Mandelbulb Fractal Generation](3327-mandelbulb-fractal-generation.md)
Generates a 3D fractal by iteratively applying a polar coordinate power transformation to a 3D point. It differs from its siblings, such as [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md) and [Spherical Density Ramp with Noise](2610-spherical-density-ramp-with-noise.md), by mapping coordinates through continuous spherical power functions rather than trigonometric sampling or radial ramps. See [Mandelbulb Fractal Generation](3327-mandelbulb-fractal-generation.md).

### [Volumetric Density Generation](4894-volumetric-density-generation.md)
Creates a patchy, heterogeneous volumetric density field from procedural noise by applying a power function and a threshold to sparse regions. It differs from its siblings by relying on a simple power-law remapping and hard thresholding on a single FBM noise field, whereas [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md) uses trigonometric interference, [Spherical Density Ramp with Noise](2610-spherical-density-ramp-with-noise.md) adds geometric confinement, and [Mandelbulb Fractal Generation](3327-mandelbulb-fractal-generation.md) uses iterative coordinate transformations. See [Volumetric Density Generation](4894-volumetric-density-generation.md).

### [Aperiodic Tiling with Edge Matching](10394-aperiodic-tiling-with-edge-matching.md)
Is a method to map pre-shaded textures onto terrain or volume surfaces without visible repetition artifacts by using aperiodic tiling schemes with specific boundary conditions. Unlike standard periodic wrapping which creates obvious seams, this method ensures that objects crossing tile boundaries are correctly replicated on "twin" edges while preventing correlation artifacts at corners. It is distinct from sibling methods like [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md) because it relies on pre-computed, static texture patterns rather than on-the-fly mathematical noise functions. See [Aperiodic Tiling with Edge Matching](10394-aperiodic-tiling-with-edge-matching.md).

### Cloud Noise Generation
#### definition
A noise function designed for 3D volumetric clouds that samples a 2D texture slice based on 3D coordinates to generate organic randomness [S1, unofficial].
#### step
Compute integer part `p` and fractional part `f` of the input 3D coordinate `x`. Compute smooth interpolation factor `u` using the formula `f * f * (3. - 2. * f)`. Calculate 2D UV coordinates by combining `p.xy` with `p.z` scaled by `vec2(37.0, 239.0)` and adding `u.xy`. Sample the `uNoise` texture at `(uv + 0.5) / 256.0` with LOD 0.0, returning the `.yx` components. Mix the two texture components `tex.x` and `tex.y` using `u.z` as the weight, then scale the result to the range [-1, 1] by multiplying by 2.0 and subtracting 1.0 [S1, unofficial].
#### code
```glsl
float noise(vec3 x ) {
  vec3 p = floor(x);
  vec3 f = fract(x);
  vec2 u = f * f * (3. - 2. * f);
  vec2 uv = (p.xy + vec2(37.0, 239.0) * p.z) + u.xy;
  vec2 tex = textureLod(uNoise,(uv + 0.5) / 256.0, 0.0).yx;
  return mix( tex.x, tex.y, u.z ) * 2.0 - 1.0;
}
```

### Environment Constraints Generation
#### definition
Determines initial constraints that define the overall look of the world by projecting a smooth noise function onto the horizontal plane [S2, unofficial].
#### parameter
Noise function: Simplex noise. Inlandness: 1.0 (inland), 0.5 (coastal), 0.0 (submerged). Temperature: 1.0 (hot), 0.5 (temperate), 0.0 (cold). Lushness: 1.0 (densely packed with flora), 0.0 (barren) [S2, unofficial].

## Background
Originating from techniques used in real-time raymarching and procedural generation engines, these patterns address the need for organic, non-repetitive visual complexity in volumetric rendering. The cloud noise variant [S1, unofficial] was adapted from Shadertoy demos to provide convincing cloud patterns via 2D texture slicing. The environment constraints method [S2, unofficial] is part of the DigBuild engine's world generation pipeline, using noise to drive biome and terrain attributes.
