# Redshift Environment Object

Also called: God Rays

## Overview
The Redshift Environment Object fills the entire scene or a height-limited layer with a homogeneous scattering medium, eliminating the need for voxel data for uniform media such as atmospheric haze and fog [S1, unofficial][S2]. It is primarily used for volumetric lighting, specifically god rays, which are visible light beams created when light passes through a thin scattering medium [S1, unofficial][S2]. Unlike the Redshift Clouds Object, which generates procedural skies, the Environment Object provides a uniform background medium that interacts with light sources to create visible light shafts and volumetric shadows [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Scene geometry, light sources, and parameter values for scattering [S1, unofficial].
*   **Output:** A rendered image with a uniform scattering medium affecting all rays passing through the defined volume [S1, unofficial][S2].

**Data Structures:**
The object implicitly defines the volume based on scene bounds or a height limit without using voxel grids or point clouds [S1, unofficial][S2].

**Parameters:**
*   **Scattering Value:** Controls the amount of scattering in the medium; even small values are powerful [S1, unofficial].
*   **Height Limit:** Defines whether the volume fills the entire scene or only a specific height layer [S1, unofficial][S2].

**Steps:**
1.  Add a Redshift Environment Object to the scene hierarchy [S1, unofficial][S2].
2.  Configure the object to fill the scene or a height-limited layer [S1, unofficial][S2].
3.  Set the Scattering Value to the desired intensity [S1, unofficial].
4.  For god rays, add a strong, partially blocked light source such as a sun through a window [S1, unofficial].
5.  Render the scene; rays passing through the medium will scatter, making light beams and volumetric shadows appear naturally [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Performance:** Volumes are expensive because rays are sampled at many points along their path and can scatter many times inside dense media [S1, unofficial].
*   **Density:** High density or high scattering values significantly increase render times [S1, unofficial].
*   **Lighting:** God rays require a strong, partially blocked light source; without obstruction, the effect may not be visible [S1, unofficial].
*   **Optimization:** To speed up rendering, keep simulations as high resolution as needed, use a moderate Volume Trace Depth, leave Extinction Falloff at its default, lower Shadow Density Scale instead of adding bounces, and let the GPU and denoiser handle the rest [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering time increases with volume density and scattering value, as rays are sampled along their path and can scatter multiple times in dense media [S1, unofficial].
*   **Memory Complexity:** Low, as no voxel data is stored and the volume is defined procedurally [S1, unofficial][S2].
*   **Strengths:** Simple setup for atmospheric effects; no need for external voxel data; effective for god rays [S1, unofficial][S2].
*   **Limitations:** Designed for homogeneous volumes; it cannot represent complex, non-uniform density variations natively [S1, unofficial][S2].
*   **When to Use:** For atmospheric haze, fog, and volumetric lighting (god rays) [S1, unofficial][S2].
*   **When Not to Use:** For complex, non-uniform volumes like clouds or smoke, which require procedural or voxel-based approaches [S1, unofficial][S2].

## Background
The Redshift Environment Object is part of the Maxon Redshift renderer's volumetric rendering system [S1, unofficial][S2]. It provides a method to simulate atmospheric effects without the complexity of voxel-based volumes [S1, unofficial][S2]. It is used in scenes requiring atmospheric perspective and volumetric lighting [S1, unofficial][S2].
