# Sine-based procedural voxel generation

Also called: Trigonometric voxel pattern

## Overview
Sine-based procedural voxel generation creates volumetric structures by evaluating trigonometric functions against voxel coordinates to determine occupancy and material properties [S1, unofficial]. It solves the problem of generating deterministic, periodic 3D patterns without storing explicit geometry or heightmaps, relying instead on real-time evaluation of sine and cosine functions [S1, unofficial]. Unlike gradient-based noise methods which produce organic, non-periodic textures, this method generates rigid, repeating wave patterns defined by specific harmonic combinations [S1, unofficial].

## How it works
**Inputs:**
- `pos`: 3D voxel coordinate $(pos_x, pos_y, pos_z)$.
- `width`: The width of the repeating pattern unit (integer).

**Outputs:**
- A voxel state: either "empty" or a "leaf" with RGBA color values.

**Data Structures:**
- No persistent data structures are required; the method is stateless and evaluates per-voxel.

**Parameters:**
- `mod`: Calculated as `width / 8`.
- `value`: Constant `0x20` (32 in decimal) used for color scaling [S1, unofficial].

**Steps:**
1.  Compute the modulo divisor: $mod = \lfloor width / 8 \rfloor$.
2.  Normalize the local coordinates within the modulo block to the range $[-1, 1]$:
    $$xx = \frac{(pos_x \pmod{mod}) \cdot 2}{mod} - 1$$
    $$yy = \frac{(pos_y \pmod{mod}) \cdot 2}{mod} - 1$$
    $$zz = \frac{(pos_z \pmod{mod}) \cdot 2}{mod} - 1$$
3.  Compute the dynamic radius of the structure at this position:
    $$radius = \left( \sin\left( \frac{pos_x + pos_y + pos_z}{5 \cdot mod} \right) + 1 \right) \cdot 0.3$$
    *Note: The source formula divides the sum of coordinates by 5, but the normalization step divides by `mod`. The source code snippet implies the argument to sine is `(pos.x/mod + pos.y/mod + pos.z/mod)/5`.*
4.  Evaluate the occupancy condition. The voxel is **empty** if either:
    - The squared Euclidean distance from the center exceeds the radius: $xx^2 + yy^2 + zz^2 > radius$
    - OR the secondary sine function is negative: $\sin\left( \frac{pos_x \cdot 16 + pos_y \cdot 20 + pos_z \cdot 30}{width} \right) < 0$
5.  If the voxel is not empty, return a leaf with color components scaled by position:
    $$R = \frac{pos_x}{mod} \cdot 0x20$$
    $$G = \frac{pos_y}{mod} \cdot 0x20$$
    $$B = \frac{pos_z}{mod} \cdot 0x20$$
    $$A = 255$$
    *Note: Color values should be clamped to [0, 255] if the source coordinates exceed `mod`.*

**Pseudocode:**
```python
def sine_based_voxel(pos_x, pos_y, pos_z, width):
    # Step 1: Compute mod
    mod = width // 8
    
    # Step 2: Normalize coordinates
    # Use modulo operator to wrap coordinates into the [0, mod) range
    local_x = pos_x % mod
    local_y = pos_y % mod
    local_z = pos_z % mod
    
    xx = (local_x * 2.0 / mod) - 1.0
    yy = (local_y * 2.0 / mod) - 1.0
    zz = (local_z * 2.0 / mod) - 1.0
    
    # Step 3: Compute radius
    # Note: Source divides coordinate sum by mod inside the sine argument
    arg_radius = (pos_x / mod + pos_y / mod + pos_z / mod) / 5.0
    radius = (sin(arg_radius) + 1.0) * 0.3
    
    # Step 4: Check occupancy
    # Condition 1: Distance from center
    dist_sq = xx*xx + yy*yy + zz*zz
    
    # Condition 2: Secondary sine check
    arg_secondary = (pos_x * 16 + pos_y * 20 + pos_z * 30) / width
    sine_check = sin(arg_secondary)
    
    if dist_sq > radius or sine_check < 0:
        return None # Empty
    
    # Step 5: Return leaf with color
    # Color scaling
    r = (pos_x / mod) * 0x20
    g = (pos_y / mod) * 0x20
    b = (pos_z / mod) * 0x20
    a = 255
    
    # Clamp colors to valid byte range [0, 255]
    r = max(0, min(255, r))
    g = max(0, min(255, g))
    b = max(0, min(255, b))
    
    return (r, g, b, a)
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `width` is 0 or `mod` becomes 0, division errors occur. Ensure `width >= 8`.
- **Color Clamping:** The formula $R = \frac{pos_x}{mod} \cdot 0x20$ can exceed 255 if $pos_x > 12 \cdot mod$. Clamping is necessary for valid RGBA output.
- **Periodicity:** The pattern repeats every `mod` units in each axis due to the modulo operation in normalization, but the radius and secondary sine checks depend on absolute coordinates, creating a larger global period.

## Subtopics

### [Procedural Tree Voxel Generation](4445-procedural-tree-voxel-generation.md)
Procedural Tree Voxel Generation is a recursive algorithm that constructs tree structures by drawing tapered branches as sequences of spheres and spawning sub-branches at intermediate points. It differs from its parent, [Sine-based procedural voxel generation](2477-sine-based-procedural-voxel-generation.md), by introducing hierarchical branching logic and variable thickness, rather than relying solely on periodic functions for shape definition. It is distinct from [Simple Heightmap Voxel Generation](4649-simple-heightmap-voxel-generation.md) which generates terrain, and [Asymmetric Wing Stroke](5094-asymmetric-wing-stroke.md) which generates aerodynamic surfaces.

### [Simple Heightmap Voxel Generation](4649-simple-heightmap-voxel-generation.md)
Simple Heightmap Voxel Generation is a procedural method for creating a 2D terrain mesh within a 3D voxel space by calculating vertex heights using sine and cosine functions based on world coordinates. It solves the problem of generating a deterministic, smooth terrain surface for volume rendering or mesh extraction without storing explicit heightmap data, relying instead on real-time evaluation of trigonometric functions. Unlike [Random Heightmap Terrain Generation](5094-random-heightmap-terrain-generation.md), which uses stochastic values, this method produces a continuous, periodic wave pattern. It differs from [Procedural Tree Voxel Generation](4445-procedural-tree-voxel-generation.md) and [Asymmetric Wing Stroke](5094-asymmetric-wing-stroke.md) by focusing on planar, grid-aligned terrain rather than complex 3D structures or organic shapes.

### [Asymmetric Wing Stroke](5094-asymmetric-wing-stroke.md)
The Asymmetric Wing Stroke is a time-dependent parametric function $p(t)$ that generates non-sinusoidal, biologically plausible flapping or swimming motions for procedural volume rendering. It solves the "robotic" appearance of symmetric sine waves by mimicking the "snap and coast" kinematics of real organisms (jellyfish bells or insect wings), where the power stroke is rapid and the recovery stroke is slow. It differs from standard sinusoidal oscillation by enforcing a specific duty cycle asymmetry, and from rigid-body animation by providing a continuous scalar field driver that can be mapped to deformation parameters like radius or span angle.

### Displacement Noise
Displacement Noise is a harmonic trigonometric displacement noise technique for adding organic or porous textures. It is defined by the formula $amp \cdot \sin(freq \cdot x) \cdot \sin(freq \cdot y) \cdot \sin(freq \cdot z)$ [S2, unofficial]. It is implemented as a function taking a 3D point, frequency, and amplitude, returning a scalar displacement value [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel. The method involves a fixed number of arithmetic operations, modulo, and sine evaluations.
- **Memory Complexity:** $O(1)$. No auxiliary data structures are stored.
- **Strengths:** Extremely fast evaluation; deterministic and reproducible; low memory footprint.
- **Limitations:** Produces rigid, periodic patterns that may look artificial; lacks the organic variation of gradient-based noise; color mapping is linear and may require post-processing for visual appeal.
- **When to use:** Ideal for generating regular, repeating volumetric structures, grid-like patterns, or as a base for displacement where periodicity is desired.
- **When not to use:** When organic, non-repeating textures are required; when high-frequency detail without aliasing is needed (sine waves alias severely if not filtered).

## Background
The method originates from the `zazen` project by Gabriel Muller, which implements voxel rendering techniques using trigonometric functions for procedural generation [S1, unofficial]. It is part of a broader class of procedural noise functions that use harmonic sums to define scalar fields.
