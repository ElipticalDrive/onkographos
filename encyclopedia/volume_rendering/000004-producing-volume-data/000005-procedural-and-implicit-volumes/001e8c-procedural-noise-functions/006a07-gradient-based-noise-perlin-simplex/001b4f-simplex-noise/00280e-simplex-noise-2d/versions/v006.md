# Simplex Noise 2D

Also called: 2D OpenSimplex Noise, 3D Perlin Noise (Improved), Improved Noise, Perlin Noise (Improved), SNoise, Simplex Noise, 2D Simplex

## Overview
Simplex Noise 2D is a gradient-based procedural noise function for 2D space that generates smooth, continuous scalar fields by using a skewed grid, fixed gradient vectors, and a lookup table [S2, unofficial]. It solves the problem of directional artifacts and high computational complexity inherent in the original integer-lattice Perlin noise by utilizing a simplex (triangular) grid [S4]. Unlike its sibling [Simplex Noise](978-simplex-noise.md) which operates in 3D, this 2D variant specifically targets planar density generation for terrain or texture mapping [S3, unofficial]. It differs from standard Perlin noise by eliminating the cubic grid structure, thereby reducing the number of corner contributions from four to three and lowering computational overhead [S4].

## How it works
**Inputs:** A 2D coordinate vector $v = (x, y)$.
**Outputs:** A scalar noise value $N \in [-1, 1]$ (normalized).

**Data Structures:**
1.  **Permutation Table:** An array of 256 integers (or a function equivalent to `permute(i) = p[i % 256]`) used to map grid coordinates to gradient indices. The modulo base is 289 [S3, unofficial].
2.  **Gradient Vectors:** A fixed set of 2D vectors. In the standard implementation, these are typically the 4 vectors $(1,1), (-1,1), (1,-1), (-1,-1)$ normalized, or a specific subset derived from the permutation table [S2, S3, unofficial]. Note: Source [S2, unofficial] implies a lookup `gradients2D[index]` and `gradients2D[index + 1]`, suggesting a specific encoding or pair-based gradient selection, while [S3, unofficial] describes constructing vectors from permutation results. The standard Simplex Noise definition uses 4 gradients in 2D. We follow the standard algorithmic structure derived from the steps below, which aligns with [S3, unofficial] and [S4], while incorporating the specific constants from [S2, unofficial].

**Constants:**
*   $C_1 = \frac{\sqrt{3} - 1}{2}$ (Stretch factor for input) [S2, unofficial]
*   $C_2 = \frac{3 - \sqrt{3}}{6}$ (Squish factor for grid) [S2, unofficial]
*   $D = \frac{1}{6}$ [S1, S3, unofficial]
*   $NORM\_2D = \frac{1}{47.0}$ [S2, unofficial]
*   $SCALE = 42.0$ [S3, unofficial]
*   $MOD289 = 289.0$ [S3, unofficial]

**Steps:**

1.  **Stretch Input:**
    Apply a non-uniform scaling to the input coordinates to map the square input domain into a skewed simplex grid.
    $$ s = (x + y) \times C_1 $$
    $$ x_s = x + s $$
    $$ y_s = y + s $$
    [S2, unofficial]

2.  **Grid Cell Identification:**
    Find the integer coordinates of the simplex cell containing the input point.
    $$ i = \lfloor x_s \rfloor $$
    $$ j = \lfloor y_s \rfloor $$
    [S2, unofficial]

3.  **Squish and Relative Coordinates:**
    Map the integer grid back to the original space to find the relative position within the simplex.
    $$ t = (i + j) \times C_2 $$
    $$ X_0 = i - t $$
    $$ Y_0 = j - t $$
    $$ x_{in} = x - X_0 $$
    $$ y_{in} = y - Y_0 $$
    [S2, unofficial]

4.  **Determine Simplex Corners:**
    Identify the three corners of the simplex triangle. The simplex grid in 2D has three corners: the origin $(0,0)$ relative to the cell, and two others determined by the position of $(x_{in}, y_{in})$ relative to the diagonal.
    
    Determine which half of the square the point lies in to select the second and third corners.
    $$ \text{if } (x_{in} > y_{in}): $$
    $$ \quad i_1 = (1, 0) $$
    $$ \quad i_2 = (1, 1) $$
    $$ \text{else:} $$
    $$ \quad i_1 = (0, 1) $$
    $$ \quad i_2 = (0, 0) $$
    [S2, S3 logic, unofficial]
    
    *Note: Source [S3, unofficial] uses a more complex step/min/max logic for 3D which generalizes to 2D. The logic above is the standard 2D simplification of determining the "inner" and "outer" corners of the simplex.*
    
    Calculate the relative coordinates of the three corners with respect to the input point:
    $$ x_0 = (x_{in} - i_1.x, y_{in} - i_1.y) $$
    $$ x_1 = (x_{in} - i_2.x, y_{in} - i_2.y) $$
    $$ x_2 = (x_{in} - 1, y_{in} - 1) $$
    *Correction based on [S3, unofficial] and standard definition:*
    The corners are:
    1.  $(0,0)$ relative to cell origin.
    2.  The "inner" corner $(1,0)$ or $(0,1)$.
    3.  The "outer" corner $(1,1)$.
    
    Let's define the vectors from the input point to the corners:
    $$ v_0 = (x_{in}, y_{in}) $$
    $$ v_1 = (x_{in} - i_1.x, y_{in} - i_1.y) $$
    $$ v_2 = (x_{in} - 1, y_{in} - 1) $$
    [S2, S3, unofficial]

5.  **Gradient Indexing:**
    Hash the cell coordinates to select gradient vectors.
    $$ hash = \text{permute}(\text{permute}(i + j) + i) $$
    [S2, S3, unofficial]
    
    The gradient vectors are selected from a predefined set based on the hash. In standard Simplex Noise, there are 4 gradients: $g_0=(1,1), g_1=(-1,1), g_2=(1,-1), g_3=(-1,-1)$. The hash determines which gradient is assigned to which corner.
    
    *Source [S2, unofficial] mentions a linked list lookup `lookup[hash]`, which suggests a specific implementation variant (possibly OpenSimplex or a sparse hash). However, the core Simplex algorithm [S3, unofficial][S4] uses direct permutation. We provide the standard permutation-based method as it is the canonical "Simplex Noise" [S4].*
    
    Assign gradients $p_0, p_1, p_2$ to corners $v_0, v_1, v_2$.
    $$ p_0 = \text{get\_gradient}(hash) $$
    $$ p_1 = \text{get\_gradient}(hash + 1) $$
    $$ p_2 = \text{get\_gradient}(hash + 2) $$
    [S3, unofficial]

6.  **Contribution Calculation:**
    For each corner, calculate the contribution to the final noise value.
    
    Calculate the squared distance from the input point to the corner:
    $$ r_0 = v_0 \cdot v_0 $$
    $$ r_1 = v_1 \cdot v_1 $$
    $$ r_2 = v_2 \cdot v_2 $$
    
    Calculate the attenuation factor (falloff). Contributions are zero if the distance is greater than 0.5 (in the skewed space, this corresponds to the radius of influence).
    $$ m_0 = \max(0.5 - r_0, 0.0) $$
    $$ m_1 = \max(0.5 - r_1, 0.0) $$
    $$ m_2 = \max(0.5 - r_2, 0.0) $$
    [S3, unofficial][S4]
    
    *Note: Source [S3, unofficial] uses $0.6$ in the formula $N = 42.0 \times \dots$ with $m_i = \text{clamp}(0.6 - |x_i|^2, 0, 1)$. Source [S2, unofficial] uses `attn = 2 - dx*dx - dy*dx` and checks `attn > 0`. The standard Ken Perlin Simplex Noise uses a cutoff of 0.5 in the skewed space, which translates to a radius of 0.5. The factor 0.6 in [S3, unofficial] might be a specific variant or error. We stick to the standard 0.5 cutoff for correctness with [S4], but acknowledge [S3, unofficial]'s 0.6.*
    
    Square the attenuation factor twice (as per [S3, unofficial] and standard implementation):
    $$ m_0 = m_0 \times m_0 $$
    $$ m_1 = m_1 \times m_1 $$
    $$ m_2 = m_2 \times m_2 $$
    
    Calculate the dot product of the gradient and the vector:
    $$ contrib_0 = m_0 \times (p_0 \cdot v_0) $$
    $$ contrib_1 = m_1 \times (p_1 \cdot v_1) $$
    $$ contrib_2 = m_2 \times (p_2 \cdot v_2) $$
    [S3, unofficial]

7.  **Final Value:**
    Sum the contributions and scale.
    $$ N = 42.0 \times (contrib_0 + contrib_1 + contrib_2) $$
    [S3, unofficial]
    
    Normalize if required (Source [S2, unofficial] suggests `NORM_2D = 1/47.0` and optional remapping). The standard range is $[-1, 1]$.
    $$ N_{final} = N \times NORM\_2D $$
    [S2, unofficial]

**Pseudocode:**

```python
import math

# Constants
C1 = (math.sqrt(3.0) - 1.0) / 2.0
C2 = (3.0 - math.sqrt(3.0)) / 6.0
NORM_2D = 1.0 / 47.0
SCALE = 42.0

# Permutation table (example 256 entries, typically derived from a seed)
# In a real implementation, this is a fixed array or a hash function.
# Here we assume a function permute(i) that returns an index in [0, 255].
def permute(i):
    # Placeholder for actual permutation table lookup
    return i % 256 

def get_gradient(hash_val, corner_index):
    """
    Returns the gradient vector for a given hash and corner.
    Standard Simplex 2D uses 4 gradients: (1,1), (-1,1), (1,-1), (-1,-1).
    """
    # Simplified gradient selection based on hash
    # This is a common implementation detail; exact mapping varies.
    # We use the lower 2 bits of the hash to select one of 4 gradients.
    grad_idx = hash_val & 3
    
    if grad_idx == 0:
        return (1.0, 1.0)
    elif grad_idx == 1:
        return (-1.0, 1.0)
    elif grad_idx == 2:
        return (1.0, -1.0)
    else:
        return (-1.0, -1.0)

def simplex_noise_2d(x, y):
    # 1. Stretch input
    stretch_offset = (x + y) * C1
    xs = x + stretch_offset
    ys = y + stretch_offset
    
    # 2. Grid cell indices
    i = math.floor(xs)
    j = math.floor(ys)
    
    # 3. Squish offset and relative coordinates
    squish_offset = (i + j) * C2
    X0 = i - squish_offset
    Y0 = j - squish_offset
    
    x_in = x - X0
    y_in = y - Y0
    
    # 4. Determine simplex corners
    # Determine which half of the square the point is in
    if x_in > y_in:
        i1 = (1, 0)
        i2 = (1, 1)
    else:
        i1 = (0, 1)
        i2 = (0, 0)
        
    # Relative coordinates of the three corners
    v0 = (x_in, y_in)
    v1 = (x_in - i1[0], y_in - i1[1])
    v2 = (x_in - 1, y_in - 1)
    
    # 5. Gradient indexing
    # Hash the cell coordinates
    hash_val = permute(permute(i + j) + i)
    
    # Get gradients for each corner
    # Note: In standard Simplex, the gradient for the origin (v0) is determined by the hash.
    # The gradients for v1 and v2 are often derived or selected from a subset.
    # Here we use a simplified selection for demonstration.
    p0 = get_gradient(hash_val, 0)
    p1 = get_gradient(hash_val + 1, 1)
    p2 = get_gradient(hash_val + 2, 2)
    
    # 6. Contribution calculation
    # Calculate squared distances
    r0 = v0[0]*v0[0] + v0[1]*v0[1]
    r1 = v1[0]*v1[0] + v1[1]*v1[1]
    r2 = v2[0]*v2[0] + v2[1]*v2[1]
    
    # Calculate attenuation factors (cutoff 0.5)
    m0 = max(0.5 - r0, 0.0)
    m1 = max(0.5 - r1, 0.0)
    m2 = max(0.5 - r2, 0.0)
    
    # Square twice
    m0 = m0 * m0 * m0 * m0
    m1 = m1 * m1 * m1 * m1
    m2 = m2 * m2 * m2 * m2
    
    # Dot products
    contrib0 = m0 * (p0[0]*v0[0] + p0[1]*v0[1])
    contrib1 = m1 * (p1[0]*v1[0] + p1[1]*v1[1])
    contrib2 = m2 * (p2[0]*v2[0] + p2[1]*v2[1])
    
    # 7. Final value
    raw = SCALE * (contrib0 + contrib1 + contrib2)
    
    # Normalize
    result = raw * NORM_2D
    
    return result
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision errors can cause discontinuities at grid boundaries if not handled carefully. Using double precision for intermediate calculations is recommended [G].
*   **Gradient Selection:** The mapping from hash to gradient vector must be consistent. Incorrect mapping leads to directional artifacts [S4].
*   **Cutoff Value:** The cutoff value for the attenuation factor (0.5 in standard Simplex) is critical. Using 0.6 as in [S3, unofficial] changes the support region and amplitude.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The number of operations is constant regardless of resolution, dominated by a few arithmetic operations and a hash lookup [S4].
*   **Memory Complexity:** $O(1)$ for the algorithm itself, plus $O(N)$ for the permutation table (typically 256 entries) [S3, unofficial].
*   **Measured Performance:** Significantly faster than 3D Perlin noise due to lower dimensionality and fewer corner contributions (3 vs 4 in 3D, 4 in 2D Perlin) [S4].
*   **Strengths:** Eliminates directional artifacts present in Perlin noise; computationally efficient; smooth and continuous [S4].
*   **Limitations:** The simplex grid is less intuitive than the integer grid; gradient selection can be complex to implement correctly [S4].
*   **When to use:** Ideal for 2D procedural textures, terrain heightmaps, and density fields where performance and artifact-free noise are required [S3, unofficial].
*   **When not to use:** If 3D spatial coherence is needed, use [Simplex Noise](978-simplex-noise.md). If exact reproducibility of Perlin noise is required for compatibility, use Perlin noise.

## Background
Simplex Noise was introduced by Ken Perlin in 2001 as an improvement over his original Perlin noise [S4]. It was designed to reduce computational complexity and eliminate directional artifacts associated with the integer lattice used in the original noise function [S4]. The algorithm uses a simplex grid (triangles in 2D, tetrahedra in 3D) which is more evenly packed than the square/cubic grid [S4]. It is widely used in procedural generation for games and simulations [S3, unofficial].
