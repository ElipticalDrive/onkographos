# Value Noise

Also called: Grid Noise

## Overview
Value Noise generates pseudo-random, spatially continuous scalar fields by assigning random values to integer lattice points and smoothly interpolating between them using Hermite interpolation [S1]. It differs from Gradient-based Noise (Perlin/Simplex) by using scalar lattice values instead of gradient vectors, making it computationally simpler but potentially prone to axis-aligned artifacts if the smoothing function is insufficient [S1].

## How it works
**Inputs:** A query point $\mathbf{P}$ (typically 2D or 3D vector) [S1].
**Outputs:** A scalar noise value $N(\mathbf{P})$ in the range $[0, 1)$ depending on the hash function [S1].

**Data Structures:**
*   **Hash Function:** A deterministic function mapping integer coordinates to pseudo-random floats [S1].
    *   Input: Integer vector $\mathbf{p}$.
    *   Output: Float $h \in [0, 1)$.
    *   Formula: $h = \text{fract}(\sin(\mathbf{p} \cdot \mathbf{c}) \times 43758.5453123)$, where $\mathbf{c}$ is a constant vector (e.g., $(127.1, 311.7)$ in 2D) [S1].

**Steps:**
1.  **Lattice Coordinate Extraction:** Compute the integer lattice coordinates $\mathbf{p}$ and the fractional offset $\mathbf{f}$ within the cell:
    $$ \mathbf{p} = \lfloor \mathbf{P} \rfloor $$
    $$ \mathbf{f} = \mathbf{P} - \mathbf{p} $$
2.  **Smoothing (Fade):** Apply the cubic Hermite smoothing function to $\mathbf{f}$ to ensure $C^1$ continuity and avoid visible grid artifacts associated with standard bilinear interpolation [S1].
    $$ \mathbf{f} = \mathbf{f} \times \mathbf{f} \times (3.0 - 2.0 \times \mathbf{f}) $$
3.  **Hash Retrieval:** Retrieve the pseudo-random scalar values for the four corners of the cell containing $\mathbf{P}$. Let $h(\mathbf{v})$ be the hash function for vector $\mathbf{v}$:
    $$ a = h(\mathbf{p} + (0, 0)) $$
    $$ b = h(\mathbf{p} + (1, 0)) $$
    $$ c = h(\mathbf{p} + (0, 1)) $$
    $$ d = h(\mathbf{p} + (1, 1)) $$
4.  **Interpolation:** Perform bilinear interpolation using the smoothed fractional coordinates $\mathbf{f} = (f_x, f_y)$:
    $$ \text{mix}_x = \text{lerp}(a, b, f_x) $$
    $$ \text{mix}_y = \text{lerp}(c, d, f_x) $$
    $$ N(\mathbf{P}) = \text{lerp}(\text{mix}_x, \text{mix}_y, f_y) $$
    Where $\text{lerp}(u, v, t) = u(1-t) + vt$ [S1].

**Pseudocode:**
```python
import math

def hash(p):
    """Deterministic hash mapping integer vector p to float [0, 1)."""
    c = (127.1, 311.7)
    h = p[0] * c[0] + p[1] * c[1]
    val = math.sin(h) * 43758.5453123
    return val - math.floor(val)

def value_noise(x, y):
    """Computes 2D Value Noise at point (x, y)."""
    # 1. Lattice coordinates and fractional offset
    p_x = math.floor(x)
    p_y = math.floor(y)
    f_x = x - p_x
    f_y = y - p_y

    # 2. Cubic Hermite smoothing (C1 continuity) [S1]
    f_x = f_x * f_x * (3.0 - 2.0 * f_x)
    f_y = f_y * f_y * (3.0 - 2.0 * f_y)

    # 3. Hash lattice corners
    a = hash((p_x, p_y))
    b = hash((p_x + 1, p_y))
    c = hash((p_x, p_y + 1))
    d = hash((p_x + 1, p_y + 1))

    # 4. Bilinear Interpolation
    mix_x = a + (b - a) * f_x
    mix_y = c + (d - c) * f_x
    result = mix_x + (mix_y - mix_x) * f_y

    return result
```

**Edge Cases and Pitfalls:**
*   **Continuity:** Standard bilinear interpolation is only $C^0$ continuous, leading to visible grid artifacts [S1]. The Hermite smoothing step is required to achieve $C^1$ continuity [S1].
*   **Hash Function Precision:** The sine-based hash function is sensitive to floating-point precision issues on some hardware [S1]. A sin-free hash function is described as cross-platform stable [S1].
*   **Range:** The output range depends on the hash function [S1]. The sine-based hash yields $[0, 1)$ [S1].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query [G]. Requires a constant number of hash lookups (4 in 2D, 8 in 3D) and arithmetic operations [G].
*   **Memory Complexity:** $O(1)$ if the hash function is stateless [G]. If a permutation table is used for hashing, memory is $O(N)$ where $N$ is the table size [G].
*   **Strengths:** Simple to implement; computationally inexpensive; produces smooth, continuous fields suitable for procedural textures and terrain [S1].
*   **Limitations:** Can exhibit axis-aligned artifacts (grid-like patterns) more readily than gradient-based noise if the smoothing function is not carefully chosen [S1]. The randomness is limited by the hash function's quality [G].
*   **When to Use:** Real-time GPU rendering where performance is critical; simple procedural textures; as a base for Fractal Brownian Motion (FBM) [S1].
*   **When Not to Use:** When high-quality, isotropic noise is required without post-processing; when derivatives are needed without additional computation (use Gradient-based Noise or Derivative FBM variants) [G].

## Background
Value Noise is a foundational procedural noise technique used in computer graphics for generating natural-looking textures and terrain [G]. It was popularized in the context of real-time GPU rendering, where its simplicity allows for efficient implementation in shaders [S1]. It serves as the basis for more complex techniques like Fractal Brownian Motion (FBM) and domain warping [S1].
