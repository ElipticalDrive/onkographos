# Perlin Noise 2D

Also called: 2D Perlin Noise, Perlin Noise (Improved), Improved Perlin Noise, Perlin's noise function, Noise (Perlin)

## Overview
Perlin Noise 2D is a lattice gradient noise function that generates smooth, pseudo-random values by interpolating dot products of gradient vectors and distance vectors at the four nearest integer lattice points in 2D space [S3, S4][S7, unofficial]. It solves the problem of generating continuous, coherent noise for procedural generation, replacing or modulating repeating textures with controlled randomness to simulate natural phenomena [S1, S7, unofficial]. Unlike its sibling [Simplex Noise](978-simplex-noise.md), which uses a triangular grid to reduce directional artifacts, Perlin Noise 2D operates on a square grid and relies on a quintic fade function and specific gradient sets to achieve $C^1$ continuity [S3, S4]. It builds on the shared principles of [Gradient-based Noise (Perlin/Simplex)](3860-gradient-based-noise-perlin-simplex.md).

## How it works
**Inputs:** Query point coordinates $(X, Y)$; a seeded permutation table (or hash function); optional persistence and octave count for fractal noise.
**Outputs:** A scalar noise value, typically in the range $[-1, 1]$ or $[0, 1]$ [S1, unofficial][S6, book].

**Data Structures:**
*   **Permutation Table:** An array of 512 `uint8_t` values. It is constructed by shuffling indices $0-255$ twice (concatenating the shuffled array to itself) to handle boundary conditions where $XI+1$ or $YI+1$ exceeds 255, avoiding modulo operations in the hot loop [S2, unofficial]. The table contains a permutation of integers $0-255$ [S7, unofficial].
*   **Gradient Set:** In 2D, the gradient is derived from the low 3 bits of the hash index, selecting one of 8 directions: $(\pm 1, \pm 1)$ and $(\pm 1, 0), (0, \pm 1)$ [S2, unofficial]. Note that 3D implementations often use 12 edge vectors of a cube [S3, S4], but 2D uses the 2D projection or specific 2D set.

**Numbered Steps:**
1.  **Initialize Permutation Table:** If not cached, build the table. Create array $P[0..255]$ with $P[i]=i$. Shuffle using Fisher-Yates with a seed. Copy $P$ to $OutTable[0..255]$ and $OutTable[256..511]$ [S2, S7, unofficial].
2.  **Compute Integer Grid Coordinates:** $XI = \lfloor X \rfloor \pmod{256}$, $YI = \lfloor Y \rfloor \pmod{256}$. Using the doubled table, this is implemented as $XI = \lfloor X \rfloor \& 255$, $YI = \lfloor Y \rfloor \& 255$ [S2, unofficial].
3.  **Compute Fractional Coordinates:** $XF = X - \lfloor X \rfloor$, $YF = Y - \lfloor Y \rfloor$ [S2, unofficial].
4.  **Compute Fade Values:** $U = Fade(XF)$, $V = Fade(YF)$, where $Fade(t) = 6t^5 - 15t^4 + 10t^3$ [S2, S7, unofficial]. This quintic polynomial ensures $C^1$ continuity by eliminating discontinuities in second and third order derivatives [S1, unofficial].
5.  **Lookup Gradient Indices:**
    *   $AA = P[P[XI] + YI]$
    *   $AB = P[P[XI] + YI + 1]$
    *   $BA = P[P[XI + 1] + YI]$
    *   $BB = P[P[XI + 1] + YI + 1]$
    [S2, unofficial]. These indices map the lattice corners to gradient vectors.
6.  **Compute Gradient Dot Products:** Calculate the contribution from each of the four corners using the `Grad` function:
    *   $n_{AA} = Grad(AA, XF, YF)$
    *   $n_{BA} = Grad(BA, XF - 1, YF)$
    *   $n_{AB} = Grad(AB, XF, YF - 1)$
    *   $n_{BB} = Grad(BB, XF - 1, YF - 1)$
    [S2, unofficial].
7.  **Interpolate:**
    *   $X_1 = Lerp(U, n_{AA}, n_{BA})$
    *   $X_2 = Lerp(U, n_{AB}, n_{BB})$
    *   $Result = Lerp(V, X_1, X_2)$
    [S2, unofficial].

**Formulas:**
*   **Fade:** $Fade(t) = 6t^5 - 15t^4 + 10t^3$ [S2, unofficial].
*   **Lerp:** $Lerp(T, A, B) = A + T(B - A)$ [S2, unofficial].
*   **Grad (2D):**
    $$
    Grad(Hash, X, Y) = \begin{cases} 
    X + Y & \text{if } Hash \& 7 == 0 \\
    X - Y & \text{if } Hash \& 7 == 1 \\
    -X + Y & \text{if } Hash \& 7 == 2 \\
    -X - Y & \text{if } Hash \& 7 == 3 \\
    X & \text{if } Hash \& 7 == 4 \\
    -X & \text{if } Hash \& 7 == 5 \\
    Y & \text{if } Hash \& 7 == 6 \\
    -Y & \text{otherwise}
    \end{cases}
    $$
    [S2, unofficial]. This selects from 8 gradient directions based on the 3 least significant bits of the hash.

**Parameters:**
*   **Persistence:** Default 0.5. Controls amplitude decay in fractal noise [S7, unofficial].
*   **Octaves:** Number of layers. Default varies by implementation [S7, unofficial].
*   **Seed:** Integer used to initialize the permutation table [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero at Lattice Points:** The noise value is exactly zero at every integer lattice point, causing undesired artifacts in amplitude distribution and non-Gaussian statistics [S3, S4].
*   **Axis-Aligned Anisotropy:** Perlin noise exhibits undesired axis-aligned anisotropy caused by correlation in the hash function, visible as horizontal features in the periodogram [S3].
*   **Grid-Oriented Artifacts:** Original Perlin noise had grid artifacts; the improved version uses fixed gradient directions and the quintic fade to mitigate this [S1, unofficial].
*   **Periodicity:** The noise is periodic with period 256 (due to the permutation table size) unless a larger table or wrapping is implemented [S1, unofficial][S4].

**Pseudocode:**
```python
def fade(t):
    return 6 * t**5 - 15 * t**4 + 10 * t**3

def lerp(t, a, b):
    return a + t * (b - a)

def grad(hash_val, x, y):
    h = hash_val & 7
    if h == 0: return x + y
    if h == 1: return x - y
    if h == 2: return -x + y
    if h == 3: return -x - y
    if h == 4: return x
    if h == 5: return -x
    if h == 6: return y
    return -y

def perlin_2d(x, y, perm_table):
    # 1. Integer coordinates
    xi = int(x) & 255
    yi = int(y) & 255
    
    # 2. Fractional coordinates
    xf = x - int(x)
    yf = y - int(y)
    
    # 3. Fade values
    u = fade(xf)
    v = fade(yf)
    
    # 4. Gradient indices
    aa = perm_table[perm_table[xi] + yi]
    ab = perm_table[perm_table[xi] + yi + 1]
    ba = perm_table[perm_table[xi + 1] + yi]
    bb = perm_table[perm_table[xi + 1] + yi + 1]
    
    # 5. Gradient dot products
    g_aa = grad(aa, xf, yf)
    g_ba = grad(ba, xf - 1, yf)
    g_ab = grad(ab, xf, yf - 1)
    g_bb = grad(bb, xf - 1, yf - 1)
    
    # 6. Interpolation
    x1 = lerp(u, g_aa, g_ba)
    x2 = lerp(u, g_ab, g_bb)
    result = lerp(v, x1, x2)
    
    return result
```

## Subtopics

### [Fractal Brownian Motion (fBm) with Perlin Noise](4253-fractal-brownian-motion-fbm-with-perlin-noise.md)
Fractal Brownian Motion (fBm) with Perlin Noise is a procedural technique that generates complex, self-similar noise patterns by summing multiple octaves of a base gradient noise function (typically Perlin Noise) with increasing frequency and decreasing amplitude. It solves the problem of creating natural-looking, detailed volumetric structures (such as terrain, smoke, or clouds) that simple Perlin noise cannot provide due to its lack of multi-scale detail. Unlike standard Perlin noise, which produces a single scale of variation, fBm mimics natural fractal phenomena by layering fine details over coarse structures.

### [Wavelet Noise](16942-wavelet-noise.md)
Wavelet noise is an explicit noise function introduced by Cook and DeRose that generates values by representing the noise field as a quadratic B-spline surface, achieving near-perfect band-limiting to solve the aliasing and detail loss inherent in weakly band-limited methods like [Perlin Noise 2D](4211-perlin-noise-2d.md). It differs from siblings such as [Fractal Brownian Motion (fBm) with Perlin Noise](4253-fractal-brownian-motion-fbm-with-perlin-noise.md) by providing strict spectral control via a weighted sum and supporting solid noise with isotropic filtering.

### M-Noise
M-Noise is a procedural shader algorithm that increases realism by interpolating pre-calculated gradient vectors to construct values varying pseudorandomly over space and time, applied to flame pixels for local turbulence [S8]. M-Noise is preferred over standard Perlin Noise on GPUs because it avoids chained table look-ups that cause bottlenecks, making it faster and better suited for 3D/4D noise not easily stored in textures [S8]. It is applied to each pixel in the volumetric rendering step to provide local turbulent detail via pseudorandom gradients [S8].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample for a single octave. Requires approximately 64 instructions per octave on GPU hardware [S5, unofficial].
*   **Memory Complexity:** $O(N)$ where $N$ is the period (typically 256 for the permutation table) [S3, S4].
*   **Measured Performance:** Generally faster than sparse convolution noise, wavelet noise, and better gradient noise, but slower than anisotropic noise [S3, S4].
*   **Strengths:** Fast, simple, widely supported, produces smooth continuous noise [S3].
*   **Limitations:** Weakly band-pass, leading to aliasing and detail loss [S3]. Non-Gaussian amplitude distribution [S3, S4]. Axis-aligned anisotropy [S3]. Zero values at lattice points [S3].
*   **When to use:** When computational efficiency is critical and visual artifacts from anisotropy or lattice points are acceptable or masked by other effects.
*   **When not to use:** When strict band-limiting is required (use Wavelet Noise) or when Gaussian amplitude distribution is needed (use Better Gradient Noise or Wavelet Noise) [S3, S4].

## Background
Perlin Noise was introduced by Ken Perlin in 1985 [S3, S4]. It received an Academy Award for technical achievement [S1, unofficial]. The "Improved" version, which uses the quintic fade function and specific gradient sets, was described by Green in 2005 in 'Implementing improved perlin noise' (GPU Gems 2) [S5, unofficial]. It has been widely used in the film industry, commercials, and computer graphics for many years [S1, unofficial]. It is implemented in libraries such as the NoiseGenerator class for CloudPlane and CloudDome in Delta3D/OpenSceneGraph [S1, unofficial].
