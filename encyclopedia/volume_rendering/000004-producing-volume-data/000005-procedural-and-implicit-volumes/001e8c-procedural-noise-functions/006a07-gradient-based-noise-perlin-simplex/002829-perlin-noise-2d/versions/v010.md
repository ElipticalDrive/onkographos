# Perlin Noise 2D

Also called: 2D Perlin Noise, Perlin Noise (Improved), Perlin's noise function, Noise (Perlin), Improved Perlin Noise, Improved Noise, SIVPerlin, RawPerlin2D, BasicPerlinNoise

## Overview
Perlin Noise 2D is a gradient-based procedural noise function that generates smooth, continuous pseudo-random values by interpolating dot products of gradient vectors and distance vectors at the corners of the integer lattice cell containing the query point [S3][S6, unofficial]. It solves the problem of generating coherent, non-repeating noise for procedural generation, replacing or modulating repeating textures with controlled randomness to simulate natural phenomena [S1, S6, unofficial]. Unlike its predecessor (original Perlin noise), the "Improved" variant uses a quintic fade function and a specific set of 2D gradients to eliminate grid-oriented artifacts and discontinuities in higher-order derivatives [S1, unofficial][S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D query point $\mathbf{P} = (X, Y)$, a seed (integer) for permutation table generation, and optionally a persistence factor if used within Fractal Brownian Motion (fBm).
*   **Output:** A scalar noise value $N(X, Y)$, typically in the range $[-1, 1]$ or $[0, 1]$ [S1, unofficial][S5, book].

**Data Structures:**
*   **Permutation Table:** An array of 512 bytes (`uint8_t`). It is constructed by shuffling the integers $0$ to $255$ and duplicating the result. The duplication handles boundary conditions where $X+1$ or $Y+1$ exceeds 255, avoiding modulo operations in the hot loop [S2, S6, unofficial].
    *   Layout: `P[0...255]` contains the shuffled permutation; `P[256...511]` is a copy of `P[0...255]`.
    *   Initialization: The table is initialized using a seeded random stream (e.g., Fisher-Yates shuffle) [S2, S6, unofficial].

**Algorithm Steps:**
1.  **Grid Coordinate Calculation:** Compute the integer coordinates of the cell containing $\mathbf{P}$ and the fractional coordinates within the cell.
    $$ XI = \lfloor X \rfloor \pmod{256} $$
    $$ YI = \lfloor Y \rfloor \pmod{256} $$
    $$ XF = X - \lfloor X \rfloor $$
    $$ YF = Y - \lfloor Y \rfloor $$
    *Note: The modulo is implicitly handled by the 512-entry permutation table via bitwise AND with 255 (`& 255`) if the table is accessed with indices potentially exceeding 255, or explicitly if the table is size 256 [S2, S6, unofficial].*

2.  **Gradient Index Lookup:** Determine the permutation indices for the four corners of the cell using the permutation table $P$.
    $$ AA = P[P[XI] + YI] $$
    $$ AB = P[P[XI] + YI + 1] $$
    $$ BA = P[P[XI + 1] + YI] $$
    $$ BB = P[P[XI + 1] + YI + 1] $$

3.  **Fade Function:** Apply the quintic fade function to the fractional coordinates to ensure $C^1$ continuity.
    $$ U = Fade(XF) = 6XF^5 - 15XF^4 + 10XF^3 $$
    $$ V = Fade(YF) = 6YF^5 - 15YF^4 + 10YF^3 $$

4.  **Gradient Dot Products:** Compute the contribution from each corner. The gradient function $Grad(hash, x, y)$ selects two components from the gradient vector based on the hash bits. For 2D, the standard implementation uses 8 gradient directions derived from the low 3 bits of the hash [S2, S6, unofficial].
    $$ G_{AA} = Grad(AA, XF, YF) $$
    $$ G_{BA} = Grad(BA, XF - 1, YF) $$
    $$ G_{AB} = Grad(AB, XF, YF - 1) $$
    $$ G_{BB} = Grad(BB, XF - 1, YF - 1) $$

    The `Grad` function definition (from [S2, unofficial]):
    ```python
    def Grad(hash, x, y):
        h = hash & 7
        if h == 0: return x + y
        if h == 1: return x - y
        if h == 2: return -x + y
        if h == 3: return -x - y
        if h == 4: return x
        if h == 5: return -x
        if h == 6: return y
        return -y
    ```
    *Note: Some implementations (e.g., SIVPerlin) use a 3D gradient function even for 2D noise, defaulting the Z coordinate to a constant (e.g., 0.12345) to increase entropy [S6, unofficial]. The 2D-specific gradient set above is more common for pure 2D implementations [S2, unofficial].*

5.  **Interpolation:** Interpolate the contributions along the X axis, then along the Y axis.
    $$ IX = Lerp(U, G_{AA}, G_{BA}) $$
    $$ IY = Lerp(U, G_{AB}, G_{BB}) $$
    $$ Result = Lerp(V, IX, IY) $$

    The `Lerp` function definition:
    ```python
    def Lerp(t, a, b):
        return a + t * (b - a)
    ```

**Parameters:**
*   **Seed:** Integer used to initialize the permutation table. Default is often 0 or a fixed value for reproducibility [S2, S6, unofficial].
*   **Persistence:** Used in fBm (see Subtopics). Default 0.5 [S6, unofficial].

**Edge Cases and Pitfalls:**
*   **Lattice Points:** The noise value is exactly zero at every integer lattice point, which can cause undesired artifacts in amplitude distribution [S3].
*   **Anisotropy:** Perlin noise exhibits undesired axis-aligned anisotropy caused by correlation in the hash function [S3].
*   **Band-pass:** It is only weakly band-pass, which may lead to aliasing and detail loss compared to wavelet noise [S3].
*   **Non-tileable:** Standard implementation is not tileable. To create tileable noise, axis wrapping must be applied [S1, unofficial].

## Subtopics

### [Fractal Brownian Motion (fBm) with Perlin Noise](4253-fractal-brownian-motion-fbm-with-perlin-noise.md)
Fractal Brownian Motion (fBm) with Perlin Noise is a procedural technique that generates complex, self-similar noise patterns by summing multiple octaves of a base gradient noise function (typically Perlin Noise) with increasing frequency and decreasing amplitude. It solves the problem of creating natural-looking, detailed volumetric structures (such as terrain, smoke, or clouds) that simple Perlin noise cannot provide due to its lack of multi-scale detail. Unlike standard Perlin noise, which produces a single scale of variation, fBm mimics natural fractal phenomena by layering fine details over coarse structures.

### Wavelet Noise
Wavelet Noise is a noise function introduced by Cook and DeRose [CD05] in 2005 that is almost perfectly band-limited, addressing aliasing and detail loss in Perlin noise [S3]. It uses a small precomputed volume of noise coefficients tiled across space. During runtime, values are computed using quadratic B-spline evaluation on these coefficients [S3].

### M-Noise
M-Noise is a procedural shader algorithm that increases realism by interpolating pre-calculated gradient vectors to construct values varying pseudorandomly over space and time, applied to flame pixels for local turbulence [S7]. It is preferred over standard Perlin Noise on GPUs because it avoids chained table look-ups that cause bottlenecks, making it faster and better suited for 3D/4D noise not easily stored in textures [S7].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. Requires approximately 64 instructions per octave on GPU hardware (Pixel Shader 2.a or newer) [S4, unofficial].
*   **Memory Complexity:** $O(1)$ storage for the permutation table (512 bytes) [S3][S6, unofficial].
*   **Performance:** Generally faster than sparse convolution, wavelet, and better gradient noise, but slower than anisotropic noise [S3].
*   **Strengths:** Simple to implement, computationally efficient, produces smooth and coherent noise suitable for natural phenomena [S3].
*   **Limitations:** Exhibits axis-aligned anisotropy, is only weakly band-pass (aliasing risk), and has a non-Gaussian amplitude distribution [S3].
*   **When to use:** When computational efficiency is critical and the visual artifacts (anisotropy, aliasing) are acceptable or masked by other scene elements.
*   **When not to use:** When strict band-limiting is required (use Wavelet Noise) or when GPU texture lookup bottlenecks are a concern (use M-Noise).

## Background
Perlin noise was introduced by Ken Perlin in 1985 [Per85, Per02] and received an Academy Award for technical achievement [S1, unofficial]. The "Improved" version, which uses the quintic fade function and the specific gradient sets described above, was described by Green in 2005 in 'Implementing improved perlin noise' (GPU Gems 2) [S4, unofficial]. It has become the workhorse of the industry for procedural generation in film, games, and volumetric rendering [S3].
