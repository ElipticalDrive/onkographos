# Perlin Noise 2D

Also called: 2D Perlin Noise, BasicPerlinNoise, RawPerlin2D, SIVPerlin

## Overview
Perlin Noise 2D is a gradient-based procedural noise function that generates smooth, continuous pseudo-random values in the range $(-1, 1)$ by interpolating dot products of gradient vectors at lattice corners [S3, book][S4, unofficial]. It solves the problem of creating coherent, band-limited textures for procedural generation, such as terrain heightmaps or cloud layers, by ensuring $C^1$ continuity across integer grid boundaries [S4, unofficial]. It is distinguished from its sibling [Simplex Noise](978-simplex-noise.md) by its use of a square lattice and trilinear interpolation, and from [3D Perlin-like Noise](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md) by its two-dimensional domain [S2].

## How it works
**Inputs:** A query point $\mathbf{P} = (X, Y)$ and a permutation table (or seed to generate it).
**Outputs:** A scalar noise value $N(X, Y) \in (-1, 1)$.

**Data Structures:**
*   **Permutation Table:** An array of 512 bytes (`uint8_t`). The first 256 entries are a shuffled permutation of integers $0 \dots 255$. The second 256 entries are an exact copy of the first, allowing boundary checks to be handled via bitwise AND without modulo operations [S1, S4, unofficial].
*   **Gradient Set:** 8 distinct 2D gradient vectors derived from the low 3 bits of the hash index [S1, unofficial].

**Steps:**

1.  **Initialize Permutation Table:**
    Create an array `P` of size 256 containing integers $0 \dots 255$. Shuffle `P` using a seeded random number generator (e.g., Fisher-Yates). Copy `P` into `OutTable` such that `OutTable[i] = P[i]` and `OutTable[i+256] = P[i]` for $i \in [0, 255)$ [S1, S4, unofficial].

2.  **Compute Integer and Fractional Coordinates:**
    Calculate the integer grid coordinates and the fractional offset within the cell:
    $$ XI = \lfloor X \rfloor \pmod{256} $$
    $$ YI = \lfloor Y \rfloor \pmod{256} $$
    $$ XF = X - \lfloor X \rfloor $$
    $$ YF = Y - \lfloor Y \rfloor $$
    *Note: In implementation, $\lfloor X \rfloor \pmod{256}$ is often implemented as `(int)floor(X) & 255` assuming positive inputs or careful handling of negative numbers, leveraging the doubled table size [S1, unofficial].*

3.  **Compute Fade Values:**
    Apply the quintic fade function to the fractional coordinates to ensure smooth derivatives:
    $$ U = 6U^5 - 15U^4 + 10U^3 $$
    $$ V = 6V^5 - 15V^4 + 10V^3 $$
    where $U = XF$ and $V = YF$ [S1, S4, unofficial].

4.  **Lookup Gradient Indices:**
    Map the grid coordinates to gradient indices using the permutation table:
    $$ A = P[XI] + YI $$
    $$ B = P[XI + 1] + YI $$
    $$ AA = P[A] $$
    $$ AB = P[A + 1] $$
    $$ BA = P[B] $$
    $$ BB = P[B + 1] $$
    All additions are modulo 256, handled by the doubled table size via bitwise AND with 255 [S1, unofficial].

5.  **Compute Gradient Dot Products:**
    Calculate the contribution from each of the four corners of the unit square. The gradient function `Grad(hash, x, y)` selects a vector from the set $\{ (\pm 1, \pm 1), (\pm 1, 0), (0, \pm 1) \}$ based on `hash & 7` [S1, unofficial]:
    $$ \text{Grad}(h, x, y) = \begin{cases} x + y & h=0 \\ x - y & h=1 \\ -x + y & h=2 \\ -x - y & h=3 \\ x & h=4 \\ -x & h=5 \\ y & h=6 \\ -y & h=7 \end{cases} $$
    
    The dot products for the four corners are:
    $$ g_{AA} = \text{Grad}(AA, XF, YF) $$
    $$ g_{BA} = \text{Grad}(BA, XF - 1, YF) $$
    $$ g_{AB} = \text{Grad}(AB, XF, YF - 1) $$
    $$ g_{BB} = \text{Grad}(BB, XF - 1, YF - 1) $$

6.  **Interpolate:**
    Perform trilinear interpolation (bilinear in 2D) using the fade values $U$ and $V$:
    $$ \text{Lerp}(t, a, b) = a + t(b - a) $$
    $$ \text{Result} = \text{Lerp}(V, \text{Lerp}(U, g_{AA}, g_{BA}), \text{Lerp}(U, g_{AB}, g_{BB})) $$

**Pseudocode:**

```python
def fade(t):
    # Quintic interpolation function for C1 continuity
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

def lerp(t, a, b):
    # Linear interpolation
    return a + t * (b - a)

def grad(hash_val, x, y):
    # 2D gradient selection based on low 3 bits of hash
    h = hash_val & 7
    if h == 0: return x + y
    if h == 1: return x - y
    if h == 2: return -x + y
    if h == 3: return -x - y
    if h == 4: return x
    if h == 5: return -x
    if h == 6: return y
    return -y

def perlin_2d(x, y, perm_table):
    # perm_table is size 512: P[0..255] and P[256..511] are identical
    
    # 1. Integer and fractional coordinates
    xi = int(x) & 255
    yi = int(y) & 255
    
    xf = x - int(x)
    yf = y - int(y)
    
    # 2. Fade values
    u = fade(xf)
    v = fade(yf)
    
    # 3. Gradient indices
    aa = perm_table[perm_table[xi] + yi]
    ab = perm_table[perm_table[xi] + yi + 1]
    ba = perm_table[perm_table[xi + 1] + yi]
    bb = perm_table[perm_table[xi + 1] + yi + 1]
    
    # 4. Gradient dot products
    g_aa = grad(aa, xf, yf)
    g_ba = grad(ba, xf - 1.0, yf)
    g_ab = grad(ab, xf, yf - 1.0)
    g_bb = grad(bb, xf - 1.0, yf - 1.0)
    
    # 5. Interpolation
    x_lerp_1 = lerp(u, g_aa, g_ba)
    x_lerp_2 = lerp(u, g_ab, g_bb)
    
    result = lerp(v, x_lerp_1, x_lerp_2)
    
    return result
```

## Subtopics

### [Fractal Brownian Motion (fBm) with Perlin Noise](4253-fractal-brownian-motion-fbm-with-perlin-noise.md)
Fractal Brownian Motion (fBm) is a technique for generating self-similar, multi-scale noise by summing multiple octaves of a base noise function, where each octave has increasing frequency and decreasing amplitude. It solves the problem of creating natural-looking, detailed procedural textures (such as terrain, clouds, or fire) that simple single-octave noise cannot provide. Unlike simple Perlin noise, which produces smooth but uniform patterns, fBm mimics natural fractal phenomena by adding fine micro-details to coarse macro-structures. It is distinguished from other fractal methods by its specific use of gradient-based noise (like Perlin) as the base primitive and its characteristic geometric scaling of frequency and amplitude.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query point. The computation involves a fixed number of arithmetic operations and table lookups regardless of the input coordinates.
*   **Memory Complexity:** $O(1)$ for the permutation table (512 bytes). No spatial data structures are required.
*   **Performance:** Extremely fast on modern CPUs due to lack of branching in the core evaluation loop (if `grad` is unrolled or switch-based) and minimal memory bandwidth usage.
*   **Strengths:** Produces visually pleasing, smooth noise with no visible seams. Statistically invariant under rotation and translation [S3, book].
*   **Limitations:** Prone to aliasing and detail loss at high frequencies because it is only weakly band-limited [S2]. Directional artifacts can appear along the axes due to the square lattice structure [S2].
*   **When to use:** Ideal for 2D procedural textures, heightmaps, and simple noise-based effects where performance is critical and extreme high-frequency detail is not required.
*   **When not to use:** For 3D volumes, use [3D Perlin-like Noise](1260-3d-perlin-like-noise-and-fractal-brownian-motion-fbm.md). For higher quality with fewer artifacts, consider [Simplex Noise](978-simplex-noise.md). For band-limited noise, consider [Wavelet Noise](2d-wavelet-noise.md) (if available) or [Improved Perlin Noise (4D)](3723-improved-perlin-noise-4d.md) variants.

## Background
Perlin noise was introduced by Ken Perlin in 1985 [S2]. It was originally developed for the movie *Tron* to generate texture maps. The algorithm was later refined and popularized in Perlin's 1997 paper "Improving Noise" [Per02], which introduced the quintic fade function and the specific gradient set used in the standard implementation. It has become the de facto standard for procedural texture generation in computer graphics. Variants like [Simplex Noise](978-simplex-noise.md) were developed to address its directional artifacts and computational cost in higher dimensions [S2].
