# 3D Perlin-like Noise and Fractal Brownian Motion (FBM)

Also called: 3D Noise, 3D Perlin-like Noise, Fractal Brownian Motion, Fractional Brownian Motion, Volume Noise Source, Volumetric Noise

## Overview
3D Perlin-like Noise generates smooth pseudo-random scalar values on a 3D unit lattice using hash-derived corner values, Hermite smoothing, and trilinear interpolation [S2, unofficial][S4, unofficial]. Fractal Brownian Motion (FBM) constructs multi-scale fractal noise by summing multiple octaves of a base noise function with increasing frequency and decreasing amplitude [S3][S7, unofficial]. Together, they solve the problem of generating realistic, self-similar organic structures (such as clouds, terrain, or fog) in procedural volumes [S3][S5, unofficial]. Unlike [Simplex Noise](978-simplex-noise.md), which uses a simplex grid to reduce directional artifacts, this method relies on the standard cubic lattice and trilinear interpolation [S2, unofficial]. It differs from [Ridged Multifractal](4249-ridged-multifractal.md) by producing soft, cloud-like volumes rather than sharp, ridge-like features [S2, unofficial].

## How it works
**Inputs:** Query point $\mathbf{p} \in \mathbb{R}^3$; number of octaves $n$; persistence (amplitude decay) $\alpha$; lacunarity (frequency gain) $\gamma$; base noise function $N(\mathbf{p})$ returning values in $[-1, 1]$ or $[0, 1]$.
**Outputs:** Scalar value $V \in \mathbb{R}$.

**Data Structures:**
*   **Permutation Table:** An array of 256 integers, shuffled permutation of $0..255$, often doubled to 512 to handle overflow without modulo [S11, unofficial][S13, unofficial].
*   **Gradient Vectors:** 256 random 3D vectors $\mathbf{g}_i$ normalized to unit length, or hash-derived values [S13, unofficial].

**Base Noise Step (Perlin-like):**
1.  Compute integer lattice coordinates $\mathbf{i} = \lfloor \mathbf{p} \rfloor$ and fractional offset $\mathbf{f} = \mathbf{p} - \mathbf{i}$ [S2, unofficial][S4, unofficial].
2.  Map $\mathbf{i}$ to permutation indices using bitwise AND with 255 (or 511 for doubled table) to avoid modulo [S6, unofficial][S13, unofficial].
3.  Retrieve hash values for the 8 corners of the unit cube containing $\mathbf{p}$ using the permutation table [S1, unofficial][S2, unofficial].
4.  Apply Hermite smoothing (Quintic) to $\mathbf{f}$: $\mathbf{u} = 6\mathbf{f}^5 - 15\mathbf{f}^4 + 10\mathbf{f}^3$ [S1, unofficial][S20, unofficial].
5.  Perform trilinear interpolation of the 8 corner values using $\mathbf{u}$ [S1, unofficial][S2, unofficial].

**FBM Step:**
1.  Initialize `sum = 0`, `amplitude = 1.0`, `frequency = 1.0`, `position = p` [S8, unofficial][S10, unofficial].
2.  Loop for $i$ from $0$ to $n-1$:
    *   Evaluate base noise: $val = N(\mathbf{p} \times \text{frequency})$ [S8, unofficial].
    *   Add to sum: `sum += val * amplitude` [S8, unofficial].
    *   Update amplitude: `amplitude *= alpha` [S8, unofficial].
    *   Update frequency: `frequency *= gamma` [S8, unofficial].
    *   (Optional) Add random offset to position to prevent octave alignment artifacts [S5, unofficial][S9, unofficial].

**Formulas:**
The standard FBM definition with lacunarity parameter $\beta$ is [S3]:
$$ B_n(\mathbf{p}) = \sum_{i=1}^n o_i(\mathbf{p}), \quad \text{with } o_i(\mathbf{p}) = \frac{noise(2^{i-1}\mathbf{p})}{2^{\beta(i-1)}} $$
Where $\beta=1$ corresponds to $1/f$ noise [S3].

**Parameters:**
*   **Octaves ($n$):** Number of layers. Default 4–7 [S13, unofficial][S19, unofficial].
*   **Persistence ($\alpha$):** Amplitude decay. Default 0.5 [S5, unofficial][S6, unofficial].
*   **Lacunarity ($\gamma$):** Frequency gain. Default 2.0 [S7, unofficial].
*   **Seed:** Integer used to initialize the permutation table [S22, unofficial].

**Edge Cases and Pitfalls:**
*   **Single Octave Limit:** Some implementations (e.g., `fbm3`) return only a single octave scaled by 0.5, reducing detail [S1, unofficial][S19, unofficial].
*   **Hash Portability:** Hash functions using trigonometric functions (e.g., `sin`) may behave inconsistently across different GPU architectures [S20, unofficial].
*   **Division by Zero:** Vector normalization or division operations must guard against zero vectors/norms [S13, unofficial].
*   **Boundary Conditions:** Integer overflow or out-of-bounds access when computing corner indices is prevented by masking with `& 255` [S13, unofficial].
*   **Tiling:** Standard Perlin noise is not tileable. For tiling, specific techniques like box filtering or coordinate rotation are required [S27, unofficial].

**Pseudocode:**
```python
def fade(t):
    # Quintic smoothstep for C1 continuity
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0)

def lerp(t, a, b):
    return a + t * (b - a)

def grad(hash_val, x, y, z):
    # Simplified gradient: use hash to select from a fixed set of vectors
    # e.g., 12 face diagonals or 12 axis-aligned vectors [G]
    h = hash_val & 15
    u = x if h < 8 else y
    v = y if h < 4 else (x if h == 12 or h == 14 else z)
    return (u if (h & 1) == 0 else -u) + (v if (h & 2) == 0 else -v)

def noise3d(p, perm_table):
    # 1. Integer and fractional parts
    i = floor(p)
    f = p - i
    
    # 2. Fade function
    u = fade(f)
    
    # 3. Hash corners
    # perm_table is size 512 (doubled)
    a = perm_table[i.x & 255]
    aa = perm_table[a + (i.y & 255)]
    ab = perm_table[a + ((i.y + 1) & 255)]
    b = perm_table[(i.x + 1) & 255]
    ba = perm_table[b + (i.y & 255)]
    bb = perm_table[b + ((i.y + 1) & 255)]
    
    # 4. Gradient contributions
    x1 = lerp(u.x, grad(perm_table[aa + (i.z & 255)], f.x, f.y, f.z),
                  grad(perm_table[ba + (i.z & 255)], f.x - 1, f.y, f.z))
    x2 = lerp(u.x, grad(perm_table[ab + (i.z & 255)], f.x, f.y, f.z - 1),
                  grad(perm_table[bb + (i.z & 255)], f.x - 1, f.y, f.z - 1))
    
    # 5. Final interpolation
    return lerp(u.z, x1, x2)

def fbm(p, octaves, persistence, lacunarity, perm_table):
    total = 0.0
    amplitude = 1.0
    frequency = 1.0
    position = p
    
    for i in range(octaves):
        total += noise3d(position, perm_table) * amplitude
        position *= lacunarity
        amplitude *= persistence
        
    return total
```

## Subtopics

### [Noise Field Generator](1302-noise-field-generator.md)
Produces a 3D scalar field by summing multiple octaves of gradient-based noise (typically Simplex or Perlin) with varying frequencies and amplitudes, often combined with a linear vertical gradient. It solves the problem of generating realistic, multi-scale organic structures (such as clouds or terrain) in procedural volumes. It is distinguished from 3D Perlin-like Noise and FBM by its specific implementation of layered Simplex noise with vertical gradient offsets for volumetric density, and from Global Cloud Cover with Curl Noise by its reliance on scalar summation rather than divergence-free vector fields.

### [Global Cloud Cover with Curl Noise](1711-global-cloud-cover-with-curl-noise.md)
Generates global cloud patterns by applying procedural noise to volumetric air blocks within a specified height range, marking the top layer in a cloud map. It creates 2D cloud patterns on a spherical surface by combining octaves of mixed Perlin and Worley noise, subtracting a threshold, and clamping the result.

### [3D Perlin-Worley Noise Texture Generation](2355-3d-perlin-worley-noise-texture-generation.md)
Generates 3D volumetric density maps for procedural cloud rendering by combining low-frequency Perlin noise for broad cloud mass with inverted Worley (cellular) noise to carve hollows, producing a puffy cumulus appearance. It differs from pure Perlin noise methods by introducing cellular structures that define cloud edges and internal voids, and from pure Worley methods by retaining the organic, continuous mass of gradient-based noise. It builds on 3D Perlin-like Noise and FBM by using fBm principles to sum multiple noise octaves.

### [Voxel World Generation with Perlin Noise](2556-voxel-world-generation-with-perlin-noise.md)
Generates a 3D voxel-based world by evaluating fractal Brownian motion (fBm) noise against a threshold to determine voxel existence and material type (stone, dirt, grass). It solves the problem of creating coherent, organic volumetric structures (such as 'blobby' cave systems) from procedural noise, similar to Dungeon Generation (DRG) techniques. It differs from simple binary voxel placement by incorporating multi-directional noise sampling and spatial constraints (like a central spawn room) to ensure playable geometry.

### [Ridged Multifractal](4249-ridged-multifractal.md)
Ridged Multifractal is a fractal noise technique that generates sharp, ridge-like structures by applying a non-linear transformation to the absolute value of base noise, combined with inter-octave feedback. Unlike standard FBM which produces soft, cloud-like volumes, Ridged Multifractal creates high-contrast linear features suitable for terrain ridges or lightning. It builds on 3D Perlin-like Noise and FBM by replacing the linear summation with a ridge-specific kernel and a multiplicative feedback loop.

### 3D Noise Generation with Box Filtering
Generates a 3D tiling noise volume and applies a 3×3×3 box blur to hide trilinear interpolation grid artifacts, as advised for procedural volume rendering [S27, unofficial]. It initializes a 3D array of floats with uniform random values in [0,1] using a seeded PRNG, then for each voxel computes the average of its 3×3×3 neighborhood, wrapping coordinates modulo dimension to ensure tiling [S27, unofficial]. The formula is $v_{out}(x,y,z,c) = \frac{1}{27} \sum_{dx=-1}^{1} \sum_{dy=-1}^{1} \sum_{dz=-1}^{1} v_{in}((x+dx)\%d, (y+dy)\%d, (z+dz)\%d, c) \cdot 255$ [S27, unofficial].

### FBM BVH Construction
A specific application of the BVH method to Fractional Brownian Motion (FBM), where octaves are presorted by range and have analytic bounds, requiring no memory storage for bounds [S3]. For FBM with $\beta=1$, all octaves share the same Lipschitz constant. The range of octave $i$ is $\Delta_{f_i} = \frac{1}{2^{i-1}}$, and the sum of ranges from $i$ to $j$ is $s(i, j) = 2 - \frac{1}{2^{j-1}}$ [S3]. This allows for optimal evaluation order in sphere tracing without storing bounds [S3].

### High Frequency Surface Noise Remapping
Introducing high frequency noise on cloud surfaces by remapping the noise value using a range defined by low frequency noise, used by Guerilla Games [S26, unofficial]. The density is calculated as `clamp(remap(noise, 1 - base, 1.0, 0.0, cap), 0.0, cap)` [S26, unofficial].

### Derivative Erosion FBM
FBM that accumulates derivatives across octaves. The derivative magnitude dampens amplitude via `1/(1+|grad|^2)`, creating realistic erosion patterns where steep slopes stay smooth [S28]. It initializes a derivative accumulator and loops through octaves, accumulating y and z components of the noise vector into the derivative, and adding `amplitude * n.x / (1.0 + dot(deriv, deriv))` to the value [S28].

### Tileable Volume Noise Generation
A compute shader process that generates four specific noise textures used for volumetric cloud rendering, including Perlin-Worley FBM, Worley FBM, Curl Noise, and Weather Data [S29, unofficial]. The PerlinWorleyFBM texture is 128×128×128 resolution, RGBA8 format, with R=Perlin-Worley and G/B/A=3 layers of Worley FBM [S29, unofficial].

### Perlin Noise Erosion
A technique to erode the surface of an SDF by adding negative Perlin noise values to the signed distance, effectively pushing the surface outward where noise is negative [S30, unofficial]. It samples 3D Perlin noise using FBM (4 octaves, 2.0 lacunarity, 0.5 gain) at `pos` scaled by `noise_scale`, and if `noise_value < 0.0f`, updates `min_dist` by adding `-noise_value * noise_amplitude` [S30, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(n \cdot k)$ where $n$ is the number of octaves and $k$ is the cost of the base noise function (constant for fixed lattice size).
*   **Memory Complexity:** $O(1)$ for on-the-fly evaluation, or $O(D^3)$ for pre-computed volume textures of dimension $D$ [S14, unofficial].
*   **Performance:** On-the-fly evaluation in shaders is efficient but can cause frame freezes if generating large 3D textures at runtime [S24]. Pre-computed textures avoid runtime cost but require significant memory and cannot be mipmapped in some formats (e.g., DDS) [S14, unofficial].
*   **Strengths:** Produces natural-looking, multi-scale detail; computationally inexpensive per sample; easy to tune via persistence and lacunarity.
*   **Limitations:** Standard Perlin noise is not tileable without modification [S27, unofficial]; hash functions using trigonometry may lack portability [S20, unofficial]; single-octave implementations lack detail [S1, unofficial].
*   **When to Use:** Generating organic volumetric density for clouds, fog, terrain, and marble.
*   **When Not to Use:** When tileable textures are required without post-processing [S27, unofficial]; when sharp, ridge-like features are needed (use Ridged Multifractal) [S2, unofficial].

## Background
FBM was introduced by Benoît Mandelbrot in the context of fractional Brownian motion in stochastic processes [S3]. In computer graphics, it was popularized by Ken Perlin for generating procedural textures and noise fields [S11, unofficial]. The 3D Perlin noise variant using gradient vectors and trilinear interpolation on a cubic lattice is a standard technique for generating smooth, continuous scalar fields [S6, unofficial][S13, unofficial]. It is widely used in volumetric rendering for cloud, fog, and terrain generation [S24][S3].
