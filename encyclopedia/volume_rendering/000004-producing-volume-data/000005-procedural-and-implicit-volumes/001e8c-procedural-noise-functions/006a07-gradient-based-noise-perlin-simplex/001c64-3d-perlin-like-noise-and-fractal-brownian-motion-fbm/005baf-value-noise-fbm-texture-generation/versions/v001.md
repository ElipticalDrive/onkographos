# Value-Noise FBM Texture Generation

Also called: Cloud Texture Generator, Procedural Cloud Noise Texture Generation, Value-Noise FBM

## Overview
Value-Noise FBM Texture Generation creates procedural volumetric textures by summing multiple octaves of value noise, where each octave uses a grid of pre-generated random scalar values interpolated via bilinear filtering. It differs from gradient-based noise (e.g., Perlin) by using scalar values at grid corners rather than gradient vectors, resulting in smoother, cloud-like appearances with lower computational overhead per sample [S1, unofficial]. It is distinct from Worley noise, which uses distance to nearest grid point, and is typically chosen for atmospheric effects where smooth, organic transitions are required [S1, S3, unofficial].

## How it works
**Inputs:**
- `N`: Output texture resolution (e.g., 256 for 2D, 128 for 3D volume) [S1, S3, unofficial].
- `octaves`: Number of noise layers (e.g., 6) [S1, S3, unofficial].
- `initial_cells`: Starting grid density for the first octave (e.g., 4) [S1, unofficial].
- `seed`: Integer seed for deterministic generation (e.g., 7) [S1, S2, unofficial].
- `persistence`: Amplitude decay factor per octave (e.g., 0.5) [S1, S3, unofficial].
- `initial_frequency`: Frequency multiplier for the first octave (e.g., 6) [S3, unofficial].

**Outputs:**
- A texture map (2D `DataTexture` or 3D volume) with values normalized to [0, 255] [S1, S3, unofficial].

**Data Structures:**
- `grid[octaves][cells][cells]`: 2D array of random floats for 2D generation. For 3D, `grid[octaves][cells][cells][cells]`.
- `field[N*N]` or `field[N*N*N]`: Accumulator array for the final noise field.

**Steps:**
1. **Initialize PRNG:** Use a linear congruential generator (LCG) with seed `s`.
   $$ s_{new} = (s_{old} \times 1103515245 + 12345) \pmod{2^{31}} $$
   Return $s_{new} / 2^{31}$ for a float in [0, 1) [S1, unofficial].
2. **Generate Grids:** For each octave $o$ from 0 to `octaves`-1:
   - Calculate grid size $C_o = \text{initial\_cells} \times 2^o$ [S1, unofficial].
   - Fill a $C_o \times C_o$ grid with random floats using the PRNG [S1, unofficial].
3. **Interpolate Octaves:** Initialize `field` to zero. Set `amp = 1.0` [S1, unofficial].
   - For each octave $o$:
     - Calculate step size $step = N / C_o$ [S1, unofficial].
     - For each pixel $(x, y)$ in the output grid:
       - Compute fractional coordinates: $fx = x / step$, $fy = y / step$ [S1, unofficial].
       - Get integer indices: $ix = \lfloor fx \rfloor$, $iy = \lfloor fy \rfloor$ [S1, unofficial].
       - Compute interpolation factors: $tx = fx - ix$, $ty = fy - iy$ [S1, unofficial].
       - Apply smoothstep to factors:
         $$ tx = 3tx^2 - 2tx^3 $$
         $$ ty = 3ty^2 - 2ty^3 $$
       - Fetch corner values from the octave's grid using modulo arithmetic for wrapping:
         $$ a = grid[o][ix \pmod{C_o}][iy \pmod{C_o}] $$
         $$ b = grid[o][(ix+1) \pmod{C_o}][iy \pmod{C_o}] $$
         $$ c = grid[o][ix \pmod{C_o}][(iy+1) \pmod{C_o}] $$
         $$ d = grid[o][(ix+1) \pmod{C_o}][(iy+1) \pmod{C_o}] $$
       - Perform bilinear interpolation:
         $$ val = (a(1-tx) + b(tx))(1-ty) + (c(1-tx) + d(tx))ty $$
       - Add weighted contribution: `field[y*N+x] += amp * val` [S1, unofficial].
     - Decay amplitude: `amp *= persistence` [S1, S3, unofficial].
4. **Normalize:** Sum all amplitudes used: $total = \sum_{o=0}^{octaves-1} persistence^o$.
   - For each pixel $i$:
     $$ v = \text{round}(field[i] / total \times 255) $$
     $$ v = \max(0, \min(255, v)) $$
5. **Texture Creation:**
   - For 2D: Create a `DataTexture` of size $N \times N$ with RGBA format, where R=G=B=v, A=255 [S1, unofficial].
   - For 3D: Create a 3D texture with DDS format, storing only in the ALPHA channel to save memory [S3, unofficial].

**Pseudocode:**
```python
def value_noise_fbm(N, octaves, initial_cells, seed, persistence, initial_frequency=1.0):
    # 1. Initialize PRNG
    def next_rand(s):
        s = (s * 1103515245 + 12345) & 0x7fffffff
        return s / 0x7fffffff, s

    rng_state = seed
    grids = []
    
    # 2. Generate Grids
    current_cells = initial_cells
    for o in range(octaves):
        grid = []
        for y in range(current_cells):
            row = []
            for x in range(current_cells):
                val, rng_state = next_rand(rng_state)
                row.append(val)
            grid.append(row)
        grids.append(grid)
        current_cells *= 2  # Double grid size for next octave [S1, unofficial]

    # 3. Interpolate
    field_size = N * N
    field = [0.0] * field_size
    amp = 1.0
    
    for o in range(octaves):
        grid = grids[o]
        cells = len(grid)
        step = N / cells
        
        for y in range(N):
            for x in range(N):
                fx = x / step
                fy = y / step
                
                ix = int(fx)
                iy = int(fy)
                
                tx = fx - ix
                ty = fy - iy
                
                # Smoothstep
                tx = tx * tx * (3 - 2 * tx)
                ty = ty * ty * (3 - 2 * ty)
                
                # Wrap-around indices
                ix1 = ix % cells
                iy1 = iy % cells
                ix2 = (ix + 1) % cells
                iy2 = (iy + 1) % cells
                
                # Fetch corners
                a = grid[iy1][ix1]
                b = grid[iy1][ix2]
                c = grid[iy2][ix1]
                d = grid[iy2][ix2]
                
                # Bilinear interpolation
                val = (a * (1 - tx) + b * tx) * (1 - ty) + (c * (1 - tx) + d * tx) * ty
                
                field[y * N + x] += amp * val
        
        amp *= persistence

    # 4. Normalize
    total_amp = sum(persistence ** o for o in range(octaves))
    result = []
    for v in field:
        normalized = v / total_amp * 255
        result.append(max(0, min(255, int(round(normalized)))))
    
    return result
```

**Parameters:**
- `persistence`: 0.5 is standard for cloud-like structures [S1, S3, unofficial].
- `initial_frequency`: 6 is used for high-frequency detail in volume clouds [S3, unofficial].
- `initial_cells`: 4, doubling each octave [S1, unofficial].

**Edge Cases:**
- **Boundary Wrapping:** Modulo arithmetic ensures seamless tiling [S1, unofficial].
- **Precision:** Accumulating floats in `field` may lose precision for large $N$; use double precision if necessary [G].
- **DDS Mipmaps:** 3D DDS textures do not support mipmaps in many drivers; use LINEAR filtering instead of mipmap filtering [S3, unofficial].

## Subtopics

### CPU Value-Noise FBM World Generation
A dependency-free CPU implementation that generates per-body heightfields and cave structures by writing directly into a packed voxel array. It uses a deterministic seed and a shared BiomeProfile to produce distinct worlds per celestial body. Unlike the GPU-oriented texture generation, this method operates on sparse voxel grids and integrates with chunk-based streaming systems [S2, unofficial].

### CloudDome Volume Texture Generation
Generates 3D volume noise textures for atmospheric cloud domes. It uses 6 octaves, initial frequency 6, initial amplitude 0.7, and persistence 0.5. The default resolution is 128 to balance memory and visual quality. The output is stored in DDS format with only the ALPHA channel used to minimize size. Due to driver limitations with `gluBuild3DMipMapLevels`, mipmaps are disabled, and LINEAR filtering is used for both minification and magnification [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N^2 \cdot \text{octaves})$ for 2D, $O(N^3 \cdot \text{octaves})$ for 3D, where $N$ is resolution. Each sample requires bilinear interpolation and smoothstep evaluation [S1, S3, unofficial].
- **Memory Complexity:** $O(N^2 \cdot \text{octaves})$ for grid storage if all octaves are kept in memory, or $O(N^2)$ if grids are generated and discarded per octave. The output texture is $O(N^2)$ or $O(N^3)$ [S1, S3, unofficial].
- **Performance:** On a 256x256 2D texture, generation is fast enough for runtime initialization. For 3D volumes at 128^3, generation time is significant but acceptable for pre-generation or low-frequency updates [S3, unofficial].
- **Strengths:** Seamless tiling, smooth gradients, low memory footprint compared to gradient noise (no vector storage), easy to implement on CPU or GPU [S1, S3, unofficial].
- **Limitations:** Less directional control than Perlin noise; smoothstep interpolation can introduce slight blurring at high frequencies; 3D mipmapping support is limited in standard formats [S3, unofficial].
- **When to Use:** Cloud textures, terrain heightmaps, procedural materials requiring smooth, organic patterns.
- **When Not to Use:** When sharp, directional features are needed (use Perlin or Worley); when high-frequency detail is critical without blurring (use higher octaves or gradient noise).

## Background
Value-Noise FBM was popularized in procedural texture generation for computer graphics, particularly in the context of cloud rendering and terrain synthesis. The specific implementation using LCG-based PRNG and bilinear interpolation with smoothstep is documented in early voxel game development and atmospheric simulation research [S1, S3, unofficial]. The method is a staple in real-time graphics due to its balance of visual quality and computational efficiency [S2, S3, unofficial].
