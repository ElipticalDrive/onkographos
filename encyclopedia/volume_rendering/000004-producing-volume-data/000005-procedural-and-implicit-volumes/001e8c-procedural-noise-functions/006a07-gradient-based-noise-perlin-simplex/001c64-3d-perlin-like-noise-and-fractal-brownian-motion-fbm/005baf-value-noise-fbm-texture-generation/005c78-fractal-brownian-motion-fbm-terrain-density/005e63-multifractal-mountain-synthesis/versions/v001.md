# Multifractal Mountain Synthesis

Also called: Seeded gradient-noise ridged/hybrid multifractal synthesis

## Overview
Multifractal Mountain Synthesis generates terrain height fields by combining seeded gradient noise (specifically Perlin-like noise) with ridged and hybrid multifractal components, enhanced by domain warping, a super-elliptical peak mask, and a directional tilt gradient [S1, unofficial]. It differs from standard Fractal Brownian Motion (FBM) Terrain Density by explicitly modeling mountainous topography through ridged noise structures and hybrid multifractal weighting, rather than simple additive summation, allowing for sharper peaks and more realistic geological features [S1, unofficial].

## How it works
**Inputs:**
- Domain size: $W \times H \times D$ (e.g., $100 \times 64 \times 100$ meters) [S1, unofficial].
- Grid resolution: $N_x \times N_y \times N_z$ (up to $288^2$ class grids, ~24M cells) [S1, unofficial].
- Octave count: Auto-clamped such that the smallest feature is at least 3 voxels in size [S1, unofficial].
- Tilt vector: Directional tilt gradient applied to the terrain [S1, unofficial].
- Peak mask: Super-elliptical shape parameters [S1, unofficial].
- Preset configuration: Sparse parameter overlay defining peak arrangement and weights [S1, unofficial].

**Outputs:**
- Signed Distance Field (SDF) representing the terrain surface [S1, unofficial].
- Optional OBJ surface export with normals and UVs [S1, unofficial].

**Data Structures:**
- The terrain is stored as a 3D voxel grid of signed distances.
- Presets are stored as sparse parameter overlays mapping to specific peak arrangements (single, twin, ridge, 5-peak) [S1, unofficial].

**Steps:**
1. **Initialize Domain:** Create a 3D grid of size $N_x \times N_y \times N_z$. Initialize the SDF to zero or a base plane [G].
2. **Apply Tilt:** Apply a directional tilt gradient to the coordinate space. For a point $\mathbf{p} = (x, y, z)$ and tilt vector $\mathbf{t} = (t_x, t_y, t_z)$, the tilted coordinate $\mathbf{p}'$ is adjusted to introduce asymmetry [S1, unofficial].
3. **Generate Base Noise:** Compute seeded gradient noise (Perlin-like) at multiple octaves. The octave count is determined by the domain size and resolution to ensure features $\ge 3$ voxels [S1, unofficial].
4. **Domain Warp:** Apply domain warping to the noise coordinates to introduce organic complexity and ridged structures [S1, unofficial].
5. **Hybrid Multifractional Combination:** Combine the noise values using a hybrid multifractal formula. This typically involves multiplying noise values by their own derivatives or previous octave values to create ridges and peaks [S1, unofficial].
6. **Apply Peak Mask:** Apply a super-elliptical peak mask to the resulting height field. The mask $M(\mathbf{p})$ is defined by super-elliptical parameters, shaping the overall mountain profile [S1, unofficial].
7. **Apply Preset Weights:** If a preset is selected (e.g., Alpine Horn, Twin Summits), apply sparse parameter overlays to adjust weights and offsets for specific peak arrangements (single, twin summits, ridge line, 5-peak range). Offsets are rotated according to the tilt bearing [S1, unofficial].
8. **Finalize SDF:** The resulting height field is converted into a Signed Distance Field. Narrow-band fast-sweeping Godunov redistancing is applied to ensure $|\nabla d| \approx 1$ [S1, unofficial].

**Pseudocode:**
```python
def synthesize_multifractal_mountain(domain_size, resolution, tilt_vector, preset_config):
    # Initialize grid
    grid = zeros(resolution)
    
    # Auto-clamp octaves based on resolution to ensure min feature size of 3 voxels
    octaves = auto_clamp_octaves(resolution, min_feature_voxels=3)
    
    # Apply tilt to coordinate space
    tilted_coords = apply_tilt(domain_size, resolution, tilt_vector)
    
    # Generate base noise with domain warping
    noise_field = generate_ridged_hybrid_noise(tilted_coords, octaves)
    
    # Apply super-elliptical peak mask
    peak_mask = create_super_elliptical_mask(resolution)
    masked_noise = noise_field * peak_mask
    
    # Apply preset-specific peak arrangements and weights
    if preset_config is not None:
        arrangement = preset_config.arrangement # e.g., 'twin_summits'
        weights = preset_config.weights
        offsets = rotate_offsets(preset_config.offsets, tilt_vector.bearing)
        masked_noise = apply_peak_arrangement(masked_noise, arrangement, weights, offsets)
    
    # Convert to SDF and redistancing
    sdf = height_to_sdf(masked_noise)
    sdf = godunov_redistancing(sdf)
    
    return sdf
```

**Parameters:**
- Octave count: Auto-clamped [S1, unofficial].
- Relief: 20-24 meters achieved across all arrangements [S1, unofficial].
- Presets: Alpine Horn, Twin Summits, Desert Mesa, Volcanic Cone, Rolling Range [S1, unofficial].

**Edge Cases:**
- Precision: SDF redistancing ensures gradient magnitude is approximately 1 [S1, unofficial].
- Boundaries: Domain warping and tilt must be handled carefully at grid boundaries to avoid artifacts [G].

## Subtopics

### Terrain Presets and Peak Arrangements
Configures peak arrangements (single, twin summits, ridge line, 5-peak range) with offsets rotated with the tilt bearing and weights calibrated for full relief [S1, unofficial]. Implemented as sparse param overlays. Five presets are available: Alpine Horn, Twin Summits, Desert Mesa, Volcanic Cone, Rolling Range [S1, unofficial]. Relief validation shows 20-24 m relief achieved across all four arrangements [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Up to ~24M cells for $288^2$ class grids [S1, unofficial].
- **Performance:** Runs in a Web Worker with zero dependencies [S1, unofficial].
- **Strengths:** True 3D SDF voxelisation, SDF-native hydraulic erosion, realistic mountain shapes via ridged/hybrid multifractal synthesis [S1, unofficial].
- **Limitations:** Unofficial source, browser-based implementation may have performance constraints on low-end devices [S1, unofficial].
- **When to use:** When realistic, eroded mountain terrain is needed in a 3D volume rendering context with SDF support [S1, unofficial].
