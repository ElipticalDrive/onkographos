# Simple Heightmap Voxel Generation

Also called: Sine Terrain Grid

## Overview
Simple Heightmap Voxel Generation is a procedural method for creating a 2D terrain mesh within a 3D voxel space by calculating vertex heights using sine and cosine functions based on world coordinates [S1, unofficial]. It solves the problem of generating a deterministic, smooth terrain surface for volume rendering or mesh extraction without storing explicit heightmap data, relying instead on real-time evaluation of trigonometric functions [S1, unofficial]. Unlike [Random Heightmap Terrain Generation](5094-random-heightmap-terrain-generation.md), which uses stochastic values, this method produces a continuous, periodic wave pattern [S1, unofficial]. It differs from [Procedural Tree Voxel Generation](4445-procedural-tree-voxel-generation.md) and [Asymmetric Wing Stroke](5094-asymmetric-wing-stroke.md) by focusing on planar, grid-aligned terrain rather than complex 3D structures or organic shapes [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Integer world coordinates $(x, z)$ within a defined grid area; fixed frequency and amplitude parameters.
- **Output:** A flat float array (vertex buffer) containing triangle vertices for the terrain mesh.

**Data Structures:**
- **Vertex Buffer:** A 1D array of floats. Each quad (unit square in the XZ plane) is represented by 6 vertices (2 triangles). Each vertex consists of 3 floats $(x, y, z)$. The buffer is filled sequentially [S1, unofficial].
- **Grid Layout:** The world is divided into chunks. Each chunk is $16 \times 16$ vertices. The example implementation uses a $2 \times 2$ chunk grid, resulting in a $32 \times 32$ world area [S1, unofficial].

**Parameters:**
- **Chunk Size:** 16 vertices per side [S1, unofficial].
- **Frequency Factor:** $0.15$ used in the sine and cosine arguments [S1, unofficial].
- **Amplitude:** $2.0$ multiplier for the height calculation [S1, unofficial].
- **Base Height:** $0.0$ offset [S1, unofficial].

**Algorithm Steps:**
1. Initialize an index counter `index` to 0 for the output buffer [S1, unofficial].
2. Iterate over chunk coordinates `chunkX` from 0 to 1 and `chunkZ` from 0 to 1 [S1, unofficial].
3. For each chunk, iterate over local coordinates `x` from 0 to 15 and `z` from 0 to 15 [S1, unofficial].
4. Calculate world coordinates:
   $$ worldX = chunkX \times 16 + x $$
   $$ worldZ = chunkZ \times 16 + z $$
5. Calculate the height $h$ for the current vertex using the sine and cosine functions:
   $$ h = 0.0 + (\sin(worldX \times 0.15) + \cos(worldZ \times 0.15)) \times 2.0 $$
   Note: The height calculation in the source code uses the same height value for all four corners of the quad, resulting in a flat, tilted triangle pair rather than a smoothly interpolated surface [S1, unofficial].
6. Write the first triangle (indices 0, 1, 2) to the buffer:
   - Vertex 0: $(worldX, h, worldZ)$
   - Vertex 1: $(worldX+1, h, worldZ)$
   - Vertex 2: $(worldX, h, worldZ+1)$
7. Write the second triangle (indices 3, 4, 5) to the buffer:
   - Vertex 3: $(worldX+1, h, worldZ)$
   - Vertex 4: $(worldX+1, h, worldZ+1)$
   - Vertex 5: $(worldX, h, worldZ+1)$
8. Increment the buffer index by 6 vertices (18 floats) after writing each quad [S1, unofficial].

**Pseudocode:**
```python
import math

def generate_simple_heightmap(chunk_x_max=2, chunk_z_max=2, chunk_size=16, frequency=0.15, amplitude=2.0, base_height=0.0):
    """
    Generates a voxel terrain mesh using sine/cosine height functions.
    
    Args:
        chunk_x_max: Number of chunks along X axis.
        chunk_z_max: Number of chunks along Z axis.
        chunk_size: Vertices per chunk side.
        frequency: Factor for sine/cosine arguments.
        amplitude: Multiplier for height.
        base_height: Base Y offset.
        
    Returns:
        list: Flat list of floats representing vertices (x, y, z) for triangles.
    """
    buffer = []
    
    for chunk_x in range(chunk_x_max):
        for chunk_z in range(chunk_z_max):
            for x in range(chunk_size):
                for z in range(chunk_size):
                    # Calculate world coordinates
                    world_x = chunk_x * chunk_size + x
                    world_z = chunk_z * chunk_size + z
                    
                    # Calculate height based on world coordinates
                    # Note: The source uses the same height for all corners of the quad
                    height = base_height + (math.sin(world_x * frequency) + math.cos(world_z * frequency)) * amplitude
                    
                    # Define the 4 corners of the quad
                    # All corners use the same height calculated at (world_x, world_z)
                    v0 = [world_x, height, world_z]
                    v1 = [world_x + 1, height, world_z]
                    v2 = [world_x, height, world_z + 1]
                    v3 = [world_x + 1, height, world_z + 1]
                    
                    # Triangle 1: v0, v1, v2
                    buffer.extend(v0)
                    buffer.extend(v1)
                    buffer.extend(v2)
                    
                    # Triangle 2: v1, v3, v2
                    buffer.extend(v1)
                    buffer.extend(v3)
                    buffer.extend(v2)
                    
    return buffer
```

**Edge Cases and Pitfalls:**
- **Precision:** The use of integer coordinates for sine/cosine arguments can lead to aliasing if the frequency is high, but with $0.15$, the pattern is smooth [S1, unofficial].
- **Flat Quads:** The implementation calculates a single height value for the entire quad based on the bottom-left corner $(worldX, worldZ)$. This results in a "stepped" or "tilted" appearance rather than a smooth surface, as the other three corners of the quad share this height [S1, unofficial]. To smooth this, height should be calculated for each corner individually.
- **Boundary Conditions:** The loop bounds are strict ($0$ to $15$ for local, $0$ to $1$ for chunks). No padding or overlap is handled [S1, unofficial].

## Subtopics

### Procedural Voxel Map Generation
Generates a 3D voxel map by applying a procedural color function and randomly placing solid rectangular blocks within defined bounds [S3, unofficial]. Unlike the heightmap method which generates a surface mesh, this method populates a volume with discrete blocks [S3, unofficial]. It uses a deterministic hash for vein generation: $((x \times 17) \oplus (y \times 31) \oplus (z \times 47)) \cdot \text{wrapping\_mul}(0x45d9f3b)$ [S3, unofficial]. It also calculates pulse and swirl components using sine functions: $\text{pulse} = \sin(x^2 + y^2 + z \times 19)$ and $\text{swirl} = \sin((x - y) \times 0.11 + z \times 0.27)$ [S3, unofficial]. RGB channels are computed with a fade factor of $z / 63.0$ [S3, unofficial]. The algorithm initializes a flat map at Z-height 63, loops 2048 times to sample random booleans for solidity, generates random start/end coordinates clamped to `VSID` and `MAXZDIM`, and calls `map.set_rect` with bounds and color set [S3, unofficial]. Parameters include `VSID` (horizontal size), `MAXZDIM` (vertical size), and 2048 random blocks [S3, unofficial].

### Random Heightmap Terrain Generation
Generates a grid mesh with vertices assigned random heights within a specified range [S2, unofficial]. It differs from Simple Heightmap Voxel Generation by using `Math.random()` instead of deterministic sine/cosine functions [S2, unofficial]. The grid size is defined by `xDetail` and `zDetail` segments, with world dimensions `xWidth` and `zWidth` [S2, unofficial]. Vertices are stored in an array of size $(xDetail + 1) \times (zDetail + 1)$ [S2, unofficial]. The world coordinates for a vertex are calculated as:
$$ tempX = \frac{iX}{xDetail} \times xWidth - \frac{xWidth}{2} $$
$$ tempZ = \frac{iZ}{zDetail} \times zWidth - \frac{zWidth}{2} $$
$$ tempY = height \times (2 \times (\text{Math.random()} - 0.5)) $$
where `height` is the maximum absolute height [S2, unofficial]. Faces are generated using a standard diagonal split, and normals are computed via cross product of edge vectors [S2, unofficial]. The layout stores face objects with vertex indices (A, B, C) and normal components (NX, NY, NZ) [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of quads (vertices). The calculation per vertex is constant time, involving a few trigonometric functions and arithmetic operations [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the output vertex buffer. The buffer size is $6 \times 16 \times 16 \times 2 \times 3$ floats for the example $2 \times 2$ chunk grid, totaling 192 vertices or 576 floats [S1, unofficial].
- **Performance:** The method is extremely fast as it involves no complex noise lookups or interpolation, only basic trigonometry [S1, unofficial]. It is suitable for real-time generation in web assembly or mobile environments [S1, unofficial].
- **Strengths:** Deterministic, easy to implement, low memory footprint, no need for external noise libraries [S1, unofficial].
- **Limitations:** The resulting terrain is periodic and repetitive, lacking natural variation. The flat-quad implementation (using a single height per quad) results in a non-smooth surface [S1, unofficial]. It is not suitable for generating complex, organic terrain features [S1, unofficial].

## Background
The method originates from a WebAssembly-based Minecraft-like voxel engine implementation [S1, unofficial]. It was designed to provide a simple, deterministic terrain generation technique for a 2D chunk-based system [S1, unofficial]. The specific implementation uses a $2 \times 2$ chunk grid with $16 \times 16$ vertices per chunk, outputting a flat float array for rendering [S1, unofficial]. The approach is a basic example of procedural geometry generation, relying on the periodic nature of sine and cosine functions to create a wave-like terrain [S1, unofficial].
