# Noise Texture Advection

Also called: Euler Integration Advection, Image-Space Advection with Euler Integration, Euler Integration, Parallel Noise Advection

## Overview
Noise Texture Advection directly advects a geometry-mapped noise input texture along projected eigenvector fields using simple Euler integration, rather than calculating streamlines at each position as in traditional Line Integral Convolution (LIC) [S1, book][S2, unofficial]. This method leverages the parallel architecture of GPUs to perform the advection for each pixel simultaneously, achieving results equivalent to locally filtering data along precomputed streamlines [S1, book][S2, unofficial]. It is used within the Local Cloud Flow with FlowMap pipeline to simulate local cloud movement and fabric-like textures on arbitrary surfaces [S1, book][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A geometry-mapped noise texture $\beta$, where $\beta_{x,y}$ is the noise value at pixel $(x,y)$. Projected eigenvector fields $v'_\lambda$ for each eigenvector $\lambda \in \{\lambda_1, \lambda_2\}$.
*   **Output:** Two advection textures (or channels), one for each eigenvector field, containing the advected noise values.

**Data Structures:**
*   **Advection Textures:** Separate input and output fields $P_i^\lambda$ are required for each eigenvector field $\lambda$. The iteration updates these fields in place or using ping-pong buffers.
*   **Field Layout:** After $N$ iterations, the resulting texture stores the final advected values. For example, after 10 iterations, the red channel may contain $P_{\lambda_1}^9$ and the green channel $P_{\lambda_2}^9$ [S1, book].

**Parameters:**
*   **$k$ (Mixing Factor):** Determines the ratio between the original input noise $\beta$ and the previously advected image. A smaller $k$ results in a smoother, more blurred advection; a larger $k$ results in a coarser, more contrast-rich image [S2, unofficial]. Typical value: $0.05$ [S2, unofficial].
*   **Iteration Limit:** The process iterates until a convergence threshold is met or a fixed number of steps is reached [S1, book][S2, unofficial].

**Algorithm Steps:**
1.  **Initialization:** For each pixel $(x,y)$ and each eigenvector field $\lambda \in \{\lambda_1, \lambda_2\}$, initialize the advection field $P_0^\lambda$ with the input noise:
    $$ P_0^\lambda = \beta_{x,y} $$
2.  **Iteration:** For iteration $i = 0, 1, \dots$:
    a. Calculate the new value $P_{i+1}^\lambda$ using the Euler integration formula:
    $$ P_{i+1}^\lambda = k \cdot \beta_{x,y} + (1-k) \cdot \frac{f_{P_i^\lambda}(x + v'_{\lambda_x}, y + v'_{\lambda_y}) + f_{P_i^\lambda}(x - v'_{\lambda_x}, y - v'_{\lambda_y})}{2} $$
    where $f_{P_i^\lambda}$ is the continuous mapping function (interpolation) of the field $P_i^\lambda$ [S1, book][S2, unofficial].
    b. **Termination Check:** Stop if the change in value $|P_{i+1}^\lambda - P_i^\lambda|$ exceeds a predefined threshold or if the maximum iteration count is reached [S1, book][S2, unofficial].
3.  **Completion:** The final values $P_{final}^\lambda$ are stored in the respective output textures.

**Pseudocode:**
```python
def advect_noise_texture(beta, eigenvectors, k, max_iterations, threshold):
    """
    Advects a noise texture beta along eigenvector fields using Euler integration.
    
    Args:
        beta: 2D array of input noise values, shape (H, W).
        eigenvectors: Dictionary mapping lambda to 2D vector fields (dx, dy), shape (H, W, 2).
        k: Mixing factor (float).
        max_iterations: Integer limit for iterations.
        threshold: Float for convergence check.
        
    Returns:
        advected_fields: Dictionary mapping lambda to 2D array of advected noise.
    """
    advected_fields = {}
    
    for lambda_name, (dvx, dvy) in eigenvectors.items():
        # Initialize P with beta
        P_prev = beta.copy()
        P_next = P_prev.copy()
        
        for i in range(max_iterations):
            # Calculate displacements
            # Note: v' is the projected eigenvector. 
            # We assume dvx, dvy are the components v'_lambda_x, v'_lambda_y
            x_disp = dvx
            y_disp = dvy
            
            # Sample forward and backward positions
            # Using bilinear interpolation for continuity f_P
            # Forward: (x + dvx, y + dvy)
            # Backward: (x - dvx, y - dvy)
            
            # To implement interpolation without external libraries:
            # We need to sample P_prev at (x + dvx, y + dvy) and (x - dvx, y - dvy)
            # This requires handling boundary conditions (e.g., clamp or wrap)
            
            forward_samples = interpolate_2d(P_prev, x_disp, y_disp)
            backward_samples = interpolate_2d(P_prev, -x_disp, -y_disp)
            
            # Average of forward and backward
            advected_part = (forward_samples + backward_samples) / 2.0
            
            # Mix with original noise
            P_next = k * beta + (1 - k) * advected_part
            
            # Check convergence
            diff = abs(P_next - P_prev)
            if max(diff.flatten()) < threshold:
                break
                
            P_prev = P_next
            
        advected_fields[lambda_name] = P_next
        
    return advected_fields
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The interpolation function $f_P$ must handle positions outside the domain $[0,1] \times [0,1]$. Common strategies include clamping, wrapping, or discarding pixels near boundaries [S1, book][S2, unofficial].
*   **Eigenvector Orientation:** Eigenvectors $v'_\lambda$ do not have a fixed orientation. Therefore, advection must be performed in both directions ($+v'_\lambda$ and $-v'_\lambda$) and averaged to ensure symmetry [S1, book][S2, unofficial].
*   **Precision:** Floating-point precision errors can accumulate over many iterations. Using a threshold for convergence helps prevent infinite loops and controls the level of detail [S1, book].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot I \cdot H \cdot W)$, where $N$ is the number of eigenvector fields (typically 2), $I$ is the number of iterations, and $H \cdot W$ is the image resolution. Each iteration involves two texture lookups and arithmetic operations per pixel.
*   **Memory Complexity:** $O(H \cdot W)$ per eigenvector field for storing the input and output advection textures.
*   **Performance:** The method is highly parallelizable and can be performed on GPUs at hundreds of iterations per second, making it suitable for real-time or near-real-time visualization [S1, book][S2, unofficial].
*   **Strengths:** Simple implementation, efficient on GPUs, avoids the complexity of streamline calculation [S1, book][S2, unofficial].
*   **Limitations:** The quality depends on the number of iterations and the mixing factor $k$. Too few iterations may result in insufficient advection, while too many may cause blurring [S2, unofficial]. The method assumes the eigenvector fields are already projected to image space [S2, unofficial].

## Background
Noise Texture Advection was introduced in the context of fabric-like visualization of tensor field data on arbitrary surfaces in image space [S1, book][S2, unofficial]. It was developed to leverage the parallel processing capabilities of modern GPUs for visualizing tensor fields without the overhead of traditional LIC methods [S1, book][S2, unofficial]. The method is part of a broader pipeline for image-space tensor field visualization [S1, book][S2, unofficial].
