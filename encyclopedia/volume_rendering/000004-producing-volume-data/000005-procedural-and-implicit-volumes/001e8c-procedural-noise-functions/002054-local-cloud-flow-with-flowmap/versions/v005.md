# Local Cloud Flow with FlowMap

Also called: FlowMap Cloud Movement, Noise Texture Flow Offset

## Overview
Local Cloud Flow with FlowMap simulates localized cloud movement, such as swirls and eddies, by using a FlowMap texture to store flow directions [S1, unofficial]. It applies per-pixel, spatially varying flow vectors derived from a texture lookup, contrasting with global flow methods that apply uniform vector offsets [S1, unofficial]. To balance performance, the FlowMap is applied only to Shape Noise, while other noise textures remain static [S1, unofficial].

## How it works
**Inputs:**
- `time`: A floating-point time variable.
- `worldPos`: The 3D world position of the raymarching sample point.
- `flowMap`: A 2D texture storing 3D flow direction vectors.
- `noiseTexture`: The procedural or sampled noise texture (specifically Shape Noise).

**Outputs:**
- `finalNoiseValue`: The noise value at the advected coordinate.

**Data Structures:**
- `flowMap`: 2D texture, UV coordinates derived from world XZ. Stores 3D vectors $(u, v, w)$.
- `noiseTexture`: 3D or 2D texture, sampled at coordinates offset by the flow.

**Steps:**
1.  **Calculate UV Coordinates**: Extract the X and Z components of the world position to form 2D UV coordinates for the FlowMap [S1, unofficial].
    $$ \text{uv} = (\text{worldPos}.x, \text{worldPos}.z) $$
2.  **Sample Flow Direction**: Sample the FlowMap at `uv` to obtain a 3D flow direction vector $\mathbf{f}$ [S1, unofficial].
    $$ \mathbf{f} = \text{Sample}(\text{flowMap}, \text{uv}) $$
3.  **Compute Time-Offset Coordinates**: To prevent severe stretching of noise features over time, the flow is repeated over a short distance using the fractional part of time [S1, unofficial].
    $$ t_1 = \text{fract}(\text{time}) $$
    $$ t_2 = \text{fract}(\text{time} + 0.5) $$
    The noise sampling coordinates are offset by the flow direction scaled by these time fractions [S1, unofficial]. Let $\mathbf{P}$ be the original noise coordinate (derived from `worldPos`) [S1, unofficial].
    $$ \mathbf{P}_1 = \mathbf{P} + \mathbf{f} \cdot t_1 $$
    $$ \mathbf{P}_2 = \mathbf{P} + \mathbf{f} \cdot t_2 $$
4.  **Sample Noise Textures**: Sample the Shape Noise texture at both offset coordinates [S1, unofficial].
    $$ n_1 = \text{Sample}(\text{noiseTexture}, \mathbf{P}_1) $$
    $$ n_2 = \text{Sample}(\text{noiseTexture}, \mathbf{P}_2) $$
5.  **Interpolate**: Interpolate between the two noise samples to achieve a smooth flow effect [S1, unofficial]. The interpolation weight is typically a fixed blend factor or derived from the fractional time step [G].
    $$ \text{blend} = 0.5 $$
    $$ \text{finalNoiseValue} = \text{lerp}(n_1, n_2, \text{blend}) $$

**Parameters:**
- `time`: Controls the speed and phase of the flow.

**Edge Cases and Pitfalls:**
- **Stretching**: Without the `fract(time)` mechanism, noise textures stretch severely over time due to varying flow directions and speeds [S1, unofficial].
- **Performance**: Applying FlowMap to all noise textures is expensive. It is recommended to apply it only to Shape Noise, leaving other textures (like detail noise) unchanged [S1, unofficial].
- **Y-Axis Flow**: The Y component of the flow vector can control vertical rolling of the noise, affecting the overall cloud distribution over time [S1, unofficial].

**Pseudocode:**
```python
def local_cloud_flow(time, world_pos, flow_map, noise_texture):
    # 1. Calculate UV from world XZ components [S1, unofficial]
    uv = (world_pos.x, world_pos.z)
    
    # 2. Sample flow direction from FlowMap (standard 3D vector texture lookup) [G]
    flow_dir = flow_map.sample_3d(uv)
    
    # 3. Compute time offsets to prevent stretching [S1, unofficial]
    t1 = time % 1.0
    t2 = (time + 0.5) % 1.0
    
    # 4. Calculate offset noise coordinates [S1, unofficial]
    base_noise_coord = world_pos
    p1 = base_noise_coord + flow_dir * t1
    p2 = base_noise_coord + flow_dir * t2
    
    # 5. Sample noise textures at both coordinates (standard noise evaluation) [G]
    n1 = noise_texture.evaluate(p1)
    n2 = noise_texture.evaluate(p2)
    
    # 6. Interpolate for smooth flow [S1, unofficial]
    # Blend weight is typically fixed or derived from time [G]
    blend = 0.5
    final_value = n1 + blend * (n2 - n1)
    
    return final_value
```

## Subtopics

### [Global Cloud Flow](2270-global-cloud-flow.md)
Simulates global cloud movement by offsetting noise texture sampling coordinates over time using two global wind speeds. It differs from Local Cloud Flow with FlowMap by applying uniform vector offsets instead of per-pixel texture lookups.

### [Noise Texture Advection](10551-noise-texture-advection.md)
Directly advecting the noise input texture with given vector fields using simple Euler integration, rather than calculating streamlines at each position. This is performed in parallel for each pixel on the GPU.

## Operating characteristics
- **Performance**: Applying FlowMap to all noise textures is computationally expensive due to additional texture lookups and coordinate calculations; it is typically applied only to Shape Noise to balance quality and performance [S1, unofficial].
- **Visual Quality**: Not given in the sources.
- **Limitations**: Not given in the sources.

## Background
This method is used in real-time volume rendering of clouds to simulate local atmospheric dynamics [S1, unofficial]. It builds on the principles of procedural noise functions by introducing spatially varying advection vectors [S1, unofficial].
