# TetraSDF Skeleton Generation

## Overview
This method extracts the topological skeleton (centerlines) of a Signed Distance Function (SDF) volume by identifying grid points where the SDF value is near zero, using a geometric approach based on plane intersections. It differs from standard marching cubes or medial axis transforms by explicitly constructing candidate points via the intersection of axis-aligned and diagonal planes, filtering them against the SDF network, and deduplicating via coordinate rounding. It builds on [RobotSDF](13070-robotsdf.md) by operating on the SDF values produced by that parent method.

## How it works
**Inputs:**
- `sdf_net`: A neural network function $SDF(x)$ returning scalar SDF values for input points $x \in \mathbb{R}^3$.
- `res_levels`: List of integers defining grid resolutions, e.g., `[2, 5, 12, 32]`.
- `use_A`: Boolean flag to apply an optional transformation matrix $A$ to normal vectors.
- `tol_geom`: Geometric tolerance for bounding box checks (default $10^{-6}$).
- `tol_dir`: Determinant threshold to skip degenerate plane triplets (default $10^{-12}$).
- `eps_sdf`: SDF threshold for filtering, scaled by resolution (see parameters).

**Outputs:**
- `skeleton_points`: A tensor of shape $(N, 3)$ containing 3D coordinates of skeleton vertices.

**Data Structures:**
- `planes_u`: A dictionary mapping each normal vector $n$ to its corresponding offset $d$, forming plane equations $n \cdot x + d = 0$.
- `valid_u`: A list of 3D points in the normalized domain $[0, 1]^3$ that satisfy the geometric and SDF constraints.

**Parameters:**
- `eps_sdf`: Scales with the maximum resolution in `res_levels` ($max\_res$):
  - $5 \times 10^{-1}$ if $max\_res < 40$
  - $1 \times 10^{-1}$ if $max\_res < 80$
  - $5 \times 10^{-2}$ otherwise.

**Steps:**

1. **Define Normal Vectors:**
   Define 6 normal vectors for axis-aligned and diagonal directions:
   $$
   N = \left\{ \begin{bmatrix} 1 \\ 0 \\ 0 \end{bmatrix}, \begin{bmatrix} 0 \\ 1 \\ 0 \end{bmatrix}, \begin{bmatrix} 0 \\ 0 \\ 1 \end{bmatrix}, \begin{bmatrix} 1 \\ -1 \\ 0 \end{bmatrix}, \begin{bmatrix} 1 \\ 0 \\ -1 \end{bmatrix}, \begin{bmatrix} 0 \\ 1 \\ -1 \end{bmatrix} \right\}
   $$
   Normalize each vector. If `use_A` is enabled, transform each normal $n$ by matrix $A$: $n' = A n$.

2. **Compute Offsets:**
   For each normal $n \in N$, compute offset values $d$ based on `res_levels`. This involves calculating grid-aligned offsets with optional center shifts and test bands using helper functions `_make_axis_offsets_filtered` or `_make_diag_offsets_filtered`. The exact implementation of these helpers is not provided in the source notes, but they generate $d$ values corresponding to the grid spacing defined by `res_levels`.

3. **Form Plane Equations:**
   Store the pairs $(n, d)$ in `planes_u`. Each plane equation is $n \cdot x + d = 0$.

4. **Iterate Over Triplets:**
   Iterate over all combinations of 3 normals $(n_1, n_2, n_3)$ from $N$.
   - Form the matrix $M$ with rows $n_1, n_2, n_3$.
   - Compute the determinant $\det(M)$.
   - If $|\det(M)| \le tol\_dir$, skip this triplet to avoid numerical instability [S1, unofficial].
   - Otherwise, compute the inverse matrix $M^{-1}$.

5. **Compute 3D Grid of Offsets:**
   - Create a 3D grid of offsets $D$ using `meshgrid` based on the offsets $d$ associated with the three normals in the triplet.
   - Stack $D$ into a tensor and transform to the parameter space $u$ using $u = D M^{-T}$ (where $M^{-T}$ is the transpose of the inverse). Note: The source specifies $u = D @ M^{-T}$, implying $D$ is treated as a matrix of coordinates to be transformed.

6. **Filter Points:**
   - Apply a mask to keep points inside the unit cube $[0, 1]^3$:
     $$
     mask = (u \ge -tol\_geom) \text{ and } (u \le 1 + tol\_geom)
     $$
   - If a network `sdf_net` is provided:
     - Transform $u$ to world space: $x_{world} = u \times 2.0 - 1.0$.
     - Evaluate $SDF(x_{world})$.
     - Keep points where $|SDF(x_{world})| < eps\_sdf$.

7. **Deduplicate:**
   - Collect all valid $u$ points.
   - Round coordinates to a specified number of decimal places (implementation detail not specified in source, but implied by "round to decimal places").
   - Deduplicate using `torch.unique`.

8. **Return:**
   - Return the deduplicated set of skeleton points. If no points are found, return an empty tensor [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of plane triplets ($6 \choose 3$ = 20) and the number of offsets per plane (proportional to $\sum res\_levels$). The SDF evaluation is the most expensive step, scaling with the number of candidate points.
- **Memory Complexity:** Proportional to the number of candidate points generated before filtering.
- **Strengths:** Efficiently samples the skeleton by leveraging geometric constraints. GPU-accelerated via PyTorch.
- **Limitations:** Relies on the quality of the SDF network. Degenerate plane triplets are skipped, which may miss some skeleton parts if the geometry is complex. The method is sensitive to the choice of `res_levels` and `eps_sdf`.

## Background
TetraSDF is a method for generating signed distance functions for robot models. The skeleton generation method is part of the TetraSDF framework, developed by NAVER Corp. It is designed to extract topological features from the SDF volume for further processing or visualization.
