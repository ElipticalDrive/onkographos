# RobotSDF

Also called: Robot Model to SDF

## Overview
RobotSDF generates a Signed Distance Field (SDF) representation for a multi-link robot model described by a kinematic chain, conditioned on a specific joint configuration [S1, unofficial]. It solves the problem of creating differentiable, batched geometric representations of articulated robots for tasks such as collision checking and motion planning. It differs from static SDF methods by dynamically composing link-level SDFs via forward kinematics transforms, allowing the geometry to change with joint angles [S1, unofficial].

## How it works
**Inputs:**
- `chain`: A `pytorch_kinematics.Chain` object describing the robot. Links must have mesh geometry; non-mesh geometries are ignored [S1, unofficial].
- `default_joint_config`: Optional initial joint values (None defaults to zeros) [S1, unofficial].
- `path_prefix`: String path prefix for resolving relative mesh file paths in the URDF [S1, unofficial].
- `link_sdf_cls`: Factory class for individual link SDFs. Defaults to `sdf.MeshSDF`. Can be replaced by `pv.cache_link_sdf_factory` to use `CachedSDF` or `TSDF` for performance [S1, unofficial].
- `points_in_object_frame`: Query points $\mathbf{P} \in \mathbb{R}^{N \times 3}$ in the robot's base/object frame [S1, unofficial].
- `joint_config`: Joint angles $\mathbf{q} \in \mathbb{R}^{M}$ or batched $\mathbf{Q} \in \mathbb{R}^{B \times M}$ [S1, unofficial].
- `compute_grad`: Boolean flag to compute gradients [S1, unofficial].

**Outputs:**
- `distance`: SDF values $d \in \mathbb{R}^{N}$ (or $\mathbb{R}^{B \times N}$ for batched) [S1, unofficial].
- `gradient`: SDF gradients $\nabla d \in \mathbb{R}^{N \times 3}$ (or $\mathbb{R}^{B \times N \times 3}$) if `compute_grad` is True [S1, unofficial].

**Data Structures:**
- `ComposedSDF`: Holds a list of link SDFs and their corresponding object-to-link transformation matrices [S1, unofficial].
- `MeshObjectFactory`: Manages the underlying mesh geometry and raycasting scene for a single link [S1, unofficial].

**Steps:**

1.  **Initialization**:
    - Iterate over frame names in the `chain`.
    - For each visual geometry of type 'mesh', create a `MeshObjectFactory` and instantiate the link SDF using `link_sdf_cls`.
    - Store the link SDFs, offsets, and link names.
    - Stack offset transforms and create a `ComposedSDF` instance from the list of link SDFs and object-to-link frames [S1, unofficial].

2.  **Configure Joint State (`set_joint_configuration`)**:
    - If `joint_config` has multiple batch dimensions, save them in `configuration_batch` and reshape to $(-1, M)$ [S1, unofficial].
    - Compute forward kinematics using `pk`'s `SerialChain`. If `SerialChain`, use `end_only=False`; otherwise use default [S1, unofficial].
    - Extract transformation matrices $T_{link}$ for each link name.
    - Inverse the offset transforms and compose with link transforms to get object-to-link frames $T_{obj \to link}$ [S1, unofficial].
    - If `configuration_batch` exists, expand offset transform matrix dimensions and repeat to match batch size before reshaping [S1, unofficial].

3.  **Query (`__call__`)**:
    - Pass `points_in_object_frame` and `compute_grad` flag to the underlying `ComposedSDF` [S1, unofficial].
    - The `ComposedSDF` transforms points to each link's local frame, queries the link SDF, and aggregates results (typically taking the minimum distance) [S1, unofficial].

4.  **Optimization (`compile`)**:
    - For each link SDF, if it is a `CachedSDF`, compile its `_forward_no_grad` method using `torch.compile` for faster queries [S1, unofficial].

**Pseudocode:**

```python
import torch
import pytorch_kinematics as pk
from pytorch_volumetric import sdf

class RobotSDF:
    def __init__(self, chain, default_joint_config=None, path_prefix='',
                 link_sdf_cls=sdf.MeshSDF):
        self.chain = chain
        self.path_prefix = path_prefix
        self.link_sdf_cls = link_sdf_cls
        
        # Initialization: Build link SDFs
        self.link_sdfs = []
        self.link_names = []
        self.offset_transforms = []
        
        # Iterate over frames in the chain
        for frame_name in chain.frame_names:
            # Get visual geometry; ignore non-mesh
            geom = chain.get_visual_geometry(frame_name)
            if geom is not None and geom.type == 'mesh':
                # Create factory and SDF
                factory = sdf.MeshObjectFactory(geom, path_prefix)
                link_sdf = link_sdf_cls(factory)
                self.link_sdfs.append(link_sdf)
                self.link_names.append(frame_name)
                # Store offset transform (identity or defined in URDF)
                self.offset_transforms.append(torch.eye(4))
        
        # Create ComposedSDF
        self.composed_sdf = sdf.ComposedSDF(self.link_sdfs, self.offset_transforms)
        
        # Set default config
        if default_joint_config is not None:
            self.set_joint_configuration(default_joint_config)

    def set_joint_configuration(self, joint_config):
        """Compute forward kinematics and update link transforms."""
        # Handle batched configs
        if joint_config.dim() > 1:
            self.configuration_batch = joint_config
            joint_config = joint_config.reshape(-1, joint_config.shape[-1])
        
        # Compute FK
        fk_result = self.chain.forward_kinematics(joint_config, end_only=False)
        
        # Extract transforms for each link
        link_transforms = []
        for name in self.link_names:
            # Get 4x4 matrix for this link
            T = fk_result[name]
            link_transforms.append(T)
        
        # Compose with offsets to get object-to-link frames
        # T_obj_to_link = T_offset_inv @ T_link
        # Note: Implementation details depend on how offsets are stored in ComposedSDF
        self.composed_sdf.update_transforms(link_transforms)

    def __call__(self, points_in_object_frame, compute_grad=False):
        """Query the SDF."""
        # Ensure tensor
        if not isinstance(points_in_object_frame, torch.Tensor):
            points_in_object_frame = torch.tensor(points_in_object_frame, dtype=torch.float32)
        
        # Query composed SDF
        distance, gradient = self.composed_sdf(points_in_object_frame, compute_grad=compute_grad)
        
        return distance, gradient

    def compile(self):
        """Compile cached SDFs for speedup."""
        for link_sdf in self.link_sdfs:
            if isinstance(link_sdf, sdf.CachedSDF):
                link_sdf.compile()
```

**Parameters:**
- `resolution`: Grid resolution for `CachedSDF`/`TSDF`. Default 0.02 [S1, unofficial].
- `truncation_distance`: Truncation distance for `TSDF`. Default 0.1 [S1, unofficial].

**Edge Cases and Pitfalls:**
- Non-mesh geometries in the URDF are ignored [S1, unofficial].
- Points very close to the surface ($|d| < 10^{-3}$) may have noisy gradients from closest-point raycasting; the implementation uses surface normals for these points [S1, unofficial].
- Precision issues may arise if ray destinations are not sufficiently outside the object; noise is added to ray destinations to reduce artifacts [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Query time depends on the number of links $L$ and the cost of the underlying link SDF. For `MeshSDF`, it is $O(L \cdot N)$ where $N$ is the number of query points. For `CachedSDF`/`TSDF`, it is $O(L \cdot N)$ but with a smaller constant due to grid lookup.
- **Memory Complexity**: $O(L \cdot V)$ where $V$ is the voxel grid size for cached SDFs. `MeshSDF` stores mesh data, which is typically smaller than voxel grids for simple geometries but larger for high-res meshes.
- **Measured Performance**: Using `TSDF` with `torch.compile` provides approximately 2x GPU speedup on no-grad queries compared to `MeshSDF` [S1, unofficial].
- **Strengths**: Differentiable, supports batched queries, integrates with kinematic chains.
- **Limitations**: Requires mesh geometry; non-mesh geometries are ignored. Performance degrades with many links or high-resolution cached SDFs.
- **When to use**: Robot collision checking, motion planning, differentiable simulation.
- **When not to use**: Static objects, non-mesh geometries, real-time applications with strict latency constraints without caching.

## Background
RobotSDF is part of the `pytorch_volumetric` library developed by the UM-ARM-Lab [S1, unofficial]. It leverages `pytorch_kinematics` for forward kinematics and provides a PyTorch-native interface for robot geometry representation. The method was designed to facilitate differentiable robotics applications, such as learning-based control and planning, where gradient information through the robot's geometry is required [S1, unofficial].
