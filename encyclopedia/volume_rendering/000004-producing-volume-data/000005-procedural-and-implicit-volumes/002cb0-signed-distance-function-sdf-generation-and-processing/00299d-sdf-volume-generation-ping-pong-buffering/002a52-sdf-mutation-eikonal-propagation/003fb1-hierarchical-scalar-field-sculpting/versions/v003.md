# Hierarchical Scalar Field Sculpting

Also called: Resolution Adaptive Volume Sculpting, ntree subdivision

## Overview
Hierarchical Scalar Field Sculpting is a method for interactive 3D modeling where the user modifies a scalar field representing material density using localized tools [S1]. It solves the trade-off between global resolution limits and interactive performance by using an adaptive hierarchical grid (ntree) that subdivides only where necessary [S1]. It differs from fixed-resolution sculpting by allowing local refinement to capture tool details, and from pure octree methods by using a fixed $n=4$ subdivision factor and direct subsampling of field values to ensure vertical independence between hierarchy levels [S1].

## How it works

### Inputs and Outputs
*   **Input:** A hierarchical scalar field representation (ntree), a Tool (scalar field function), and an Action (combination logic) [S1].
*   **Output:** Modified scalar field values, gradients, and colors at the vertices of the ntree structure [S1].

### Data Structures

**Vertex Structure**
Stores the state of a sampling point in the regular grid basis [S1].
*   `field_value`: Scalar density value.
*   `gradient`: Vector gradient of the field.
*   `color`: Color attribute.
*   `timestamp`: Used to prevent redundant updates on shared vertices [S1].

**ntree Cell Structure**
A hierarchical space partitioning structure resembling Recursive Grids [S1].
*   `children`: A set of sub-cells (successors). Unlike octrees where nodes are replaced, cells are enriched with children [S1].
*   `subdivision_factor`: Fixed at $n=4$ per dimension [S1].
*   `size`: Current cell dimension.
*   `vertices`: References to Vertex nodes. Vertices are shared among common faces or edges between adjacent Cells of the same level to reduce memory overhead [S1].

**Vertex Cache**
*   Implemented as a hash map indexed by the memory addresses of Vertices [S1].
*   Maps the Vertex state (field value, gradient, color) *prior* to the current tool's modification [S1].
*   One cache is created per Tool-Action application couple to support interpolation during subdivision and undo operations [S1].

### The Tool: Wyvill's Ellipsoidal Field
The tool is a scalar field $f(p)$ positioned, oriented, and scaled [S1]. The implementation uses Wyvill's field function, which is computationally cheap (uses squared distance), has a spatially limited domain of influence, and is bell-shaped with $C^1$ variations for smooth blending [S1].

$$
f(p) = \begin{cases} 
0 & \text{if } d \ge 1 \\
3 \cdot \left( 1 - \frac{2}{9}d^2 + \frac{7}{9}d^4 - \frac{4}{9}d^6 \right) & \text{otherwise}
\end{cases}
$$

Where $p$ is the query point and $d^2$ is the squared distance from the tool center, normalized by the tool's scale [S1].

### The Action
An Action takes a Tool and a Vertex as arguments [S1]. It computes the tool's contribution at the vertex and combines it with current vertex attributes [S1].
*   **AddAction Example:**
    1.  Compute tool value $v_t = \text{Tool}(v.\text{position})$ [S1].
    2.  Compute new field value $v_{new} = v.\text{field\_value} + v_t$ [S1].
    3.  Clamp $v_{new}$ between 0 and 3 [S1].
    4.  Use $v.\text{field\_value}$ and $v_{new}$ as weights to sum up attributes (gradient, color) [S1].
    5.  Update vertex attributes [S1].

### Parameters
*   **Field Clamping Range:** $[0, 3]$. Prevents negative values (which would block material creation) and excessive positive values (which would block material removal) [S1].
*   **Iso-value:** 1.5. Defines the object's surface [S1].
*   **Min Resolution:** The smallest cell size to reach to capture tool features [S1].
*   **Max Resolution:** The largest cell size (smallest depth) not to overpass [S1]. Prevents infinite subdivision loops caused by subtractive tools creating discontinuities [S1]. Expressed as a constant factor depending on the tool's scale [S1].

### Algorithm Steps

1.  **Initialization:** Create a Vertex Cache storing the current state of all vertices in the affected region [S1].
2.  **Apply Tool (Recursive):**
    *   For the current Cell, iterate over all its Vertices [S1].
    *   Apply the Action: `a.update(t, v)` [S1].
    *   If the Cell has no children, test for subdivision (`checkSubdivide`) [S1].
    *   If the Cell has children, recursively apply the tool to all children [S1].
3.  **Subdivision Test (`checkSubdivide`):**
    *   If `Cell.size > t.getMinResolution()`: Subdivide the cell [S1].
    *   Else if `Cell.size < t.getMaxResolution()`:
        *   Estimate discrepancy. If `discrepancy > acceptableDiscrepancy`: Subdivide [S1].
    *   *Note:* Subdivision creates new vertices [S1]. These are initialized by interpolating the *cached pre-update* field values from the parent level to ensure the tool's modification is added correctly on top of the previous state [S1].
4.  **Simplification Pass (Idle):**
    *   Conducted separately at idle moments [S1].
    *   Destroys every Cell that does not cross the surface (iso-value 1.5) AND whose children do not cross the surface [S1].
    *   Cannot be done during active interaction because finer levels might add surface details that would be lost if coarser levels were simplified prematurely [S1].

    """Recursively applies a tool to a cell and its children. Updates vertices first, then recurses to children."""

        check_subdivide(cell, tool)
    if cell.has_children():

### Edge Cases and Pitfalls
*   **Irreversibility:** Field clamping makes the operation non-invertible. Reverse actions cannot simply subtract the tool value [S1]. The Vertex Cache is required to store pre-update states for correct interpolation during subdivision and for Undo operations [S1].
*   **Infinite Subdivision:** Subtractive tools can create discontinuities [S1]. The `Max Resolution` limit prevents infinite subdivision loops [S1].
*   **Shared Vertex Updates:** When subdividing, shared vertices between adjacent cells must be updated only once [S1]. A timestamp comparison prevents redundant computations [S1].
*   **Undo Mechanism:** Undo is treated as a special Action [S1]. Undo files store modified vertex addresses (not memory pointers, as vertices may be reallocated) [S1]. The undo action uses the current tool's contribution to weight the reversal, enabling "Progressive Undo" and "Local Undo" [S1].

## Subtopics

### Volume Sculpting
A free-form interactive modeling technique based on sculpting and painting a voxel-based solid material, allowing exploration of inner structures by gradually removing material [S2, unofficial]. Carving positions a pre-existing volume-sampled tool relative to the object and performs a Boolean subtraction between the two independent volume buffers [S2, unofficial]. Sawing generates a volume-sampled tool on-the-fly using a user interface to remove a whole chunk of material at once [S2, unofficial]. To prevent object space aliasing and achieve interactive speed during sawing, 3D splatting is employed [S2, unofficial]. Localized rendering is used to reproject only pixels affected by the localized sculpting actions (carving/sawing) [S2, unofficial].

## Operating characteristics

*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Interactive visual feedback (updating coarse levels first), smooth blending ($C^1$ continuity), local detail capture [S1].
*   **Limitations:** Simplification is drastic (destroys non-surface cells), requires explicit caching for subdivision correctness, fixed subdivision factor ($n=4$) may not be optimal for all shapes [S1].
*   **When to use:** Interactive sculpting of organic shapes where local detail is needed without global high resolution [S1].
*   **When not to use:** When strict topological control is required (simplification is destructive), or when the scene is static and pre-computed [S1].

## Background

*   **Origin:** Proposed by Eric Ferley, Marie-Paule Cani, and Jean-Dominique Gascuel [S1].
*   **Paper:** "Resolution Adaptive Volume Sculpting" (2001/2002) [S1].
*   **History:** Builds on earlier work using hash-based grids for unlimited spatial extent. The method was developed to allow interactive editing of complex sculptures by adapting resolution to the tool's influence [S1].
*   **Usage:** Used in 3D modeling software for sculpting organic shapes, particularly in academic research on implicit surface modeling [S1].
