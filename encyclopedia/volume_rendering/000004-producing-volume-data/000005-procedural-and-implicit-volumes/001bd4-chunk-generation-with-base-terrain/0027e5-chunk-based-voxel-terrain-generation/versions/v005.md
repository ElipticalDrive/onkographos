# Chunk-Based Voxel Terrain Generation

Also called: Procedural voxel placement, Voxel Terrain Generation, Voxel Terrain Generation via Chunked Noise Sampling, VoxelChunk generation

## Overview
Chunk-Based Voxel Terrain Generation is a procedural technique that constructs a 3D voxel world by sampling 3D noise functions to determine block density and height, then filtering these values against thresholds to place solid blocks [S1, S3, unofficial]. It differs from static generation by organizing the output into fixed-size chunks, enabling efficient memory management and localized updates, and from pure implicit volumes by explicitly discretizing the space into a grid of binary or typed voxels rather than a continuous field [S1, S3, unofficial]. It builds on [Chunk Generation with Base Terrain](1110-chunk-generation-with-base-terrain.md) by adding biome logic, run-length encoding, and explicit face culling for mesh generation.

## How it works
**Inputs:**
- World seed (integer).
- Configuration parameters: `max_elevation`, `world_size` (X/Z extent), `water_level`, `equator_temp`, `temp_decay_coeff`, `chunk_size` (default 8 or 32), `render_distance` (default 256), `cut_off` (default -0.75), `terrain_scope` (default 1.0) [S1, S2, S3, unofficial].
- Player position (for chunk loading/unloading) [S2, unofficial].

**Outputs:**
- A set of `VoxelChunk` objects, each containing a dense voxel grid and a mesh of visible faces [S1, S2, unofficial].

**Data Structures:**
1.  **Voxel Grid:** A 1D array of size $N^3$ (where $N$ is `chunk_size`) storing voxel types as `Uint8` indices [S1, unofficial].
2.  **Chunk Cache:** A map from chunk coordinates $(cx, cy, cz)$ to `ChunkCacheItem` [S1, unofficial].
    -   `enc`: `Uint16Array` containing Run-Length Encoded (RLE) data of the voxel grid.
    -   `faces`: `Map<VoxelID, number[]>` storing packed face data.
    -   `n`: Total face count.
    -   `is_empty`: Boolean flag.
3.  **Packed Face Data:** An array of 5 numbers per face: $(x, y, z, \text{voxel\_id}, \text{direction\_index})$ [S1, unofficial].
4.  **Mesh Buffers:**
    -   `position_buffer`: `Float32Array` of size $V \times 3$.
    -   `vert_id_buffer`: `Float32Array` of size $V$.
    -   `packed_buffer`: `Float32Array` of size $V$.
    -   `index_buffer`: `Uint16Array` of size $F \times 6$ (2 triangles per face) [S1, unofficial].

**Steps:**

1.  **Initialize Noise Functions:**
    -   Create height noise from `seed` [S1, unofficial].
    -   Create moisture noise from `seed` shuffled by 10 [S1, unofficial].
    -   Create "wackiness" noise from moisture seed shuffled by 10 [S1, unofficial].
    -   Initialize `OctavedNoise2d` instances with specific frequencies/amplitudes:
        -   Height: frequency 1.2, amplitude 400.
        -   Moisture: frequency 1.0, amplitude 200.
        -   Wackiness: frequency 1.0, amplitude 20 [S1, unofficial].
    -   Define temperature function: $T(z) = \text{clamp}(E - |z - Z_{eq}| \cdot D, 0, 1)$, where $E$ is `equator_temp`, $Z_{eq}$ is `world_size`/2, and $D$ is `temp_decay_coeff` [S1, unofficial].

2.  **Calculate Chunk-Level Wackiness:**
    -   Evaluate wackiness noise at $(cx/100, cz/100)$ [S1, unofficial].
    -   Map result to exponent `chunk_exp`:
        -   $< 0.2 \rightarrow 16$
        -   $< 0.4 \rightarrow 8$
        -   $< 0.6 \rightarrow 2$
        -   $> 0.8 \rightarrow 0.5$
        -   Else $\rightarrow$ raw value [S1, unofficial].

3.  **Generate Voxel Data:**
    -   For each voxel $(x, y, z)$ in the chunk ($0 \le x,y,z < N$):
        -   Calculate world coordinates: $W_x = cx \cdot N + x$, $W_z = cz \cdot N + z$, $W_y = cy \cdot N + y$ [S1, unofficial].
        -   Evaluate height noise at $(W_x, W_z)$ [S1, unofficial].
        -   Calculate terrain height: $H = (\text{noise}(W_x, W_z))^{\text{chunk\_exp}} \cdot \text{max\_elevation}$ [S1, unofficial].
        -   Determine voxel type using `determineGeneratedVoxel(H, wackiness, W)` [S1, unofficial]:
            -   If $W_y < \text{water\_level}$:
                -   If $W_y \ge H$: WATER.
                -   If $W_y + 2 \ge H$: SAND.
                -   If $W_y + 8 \ge H$: MUD.
                -   If $W_y + 14 \ge H$: SANDSTONE.
                -   Else: STONE.
            -   If $W_y > H$: AIR.
            -   Else (land):
                -   Get moisture $M = \text{moisture}(W_x, W_z)$ and temperature $T = T(W_z)$ [S1, unofficial].
                -   If $M \le 0.3$ and $T \ge 0.7$ (Desert):
                    -   If $W_y + 3 \ge H$: SAND.
                    -   If $W_y + 7 \ge H$: SANDSTONE.
                    -   Else: STONE.
                -   If $M \le 0.4$ and $T \le 0.3$ (Tundra):
                    -   If $W_y + 1 \ge H$: SNOW.
                    -   If $W_y + 6 \ge H$: PACKED_DIRT.
                    -   Else: STONE.
                -   If $M > 0.7$ and wackiness $> 0.7$ and $T > 0.7$ (Jungle/Mushroom):
                    -   If $W_y + 1 \ge H$: MYCELIUM.
                    -   If $W_y + 7 \ge H$: DIRT.
                    -   Else: STONE.
                -   Else (Default/Jungle):
                    -   If $W_y + 1 \ge H$: GRASS/FERTILE_DIRT.
                    -   Else: DIRT/STONE (implementation varies, typically dirt then stone) [S1, unofficial].
        -   Store voxel type in grid [S1, unofficial].

4.  **Encode and Cache:**
    -   Run-length encode the voxel grid into `enc` [S1, unofficial].
    -   If RLE length is 2 and second element is AIR, flag `is_empty = true` [S1, unofficial].
    -   Identify visible faces:
        -   For each non-AIR/non-WATER voxel, check 6 neighbors [S1, unofficial].
        -   If neighbor is OOB or AIR/WATER, face is visible [S1, unofficial].
        -   Pack face data $(x, y, z, \text{voxel\_id}, \text{dir})$ into `faces` map [S1, unofficial].
    -   Generate mesh geometry:
        -   For each visible face, create 4 vertices (quad corners) [S1, unofficial].
        -   Store positions, vertex IDs, and packed data in buffers [S1, unofficial].
        -   Generate 2 triangles (6 indices) per face [S1, unofficial].

5.  **Manage Loading/Unloading (Runtime):**
    -   Initialize a loading threshold `Area3D` with a sphere shape of radius $R = \text{render\_distance} \cdot 0.25$ [S2, unofficial].
    -   Position sphere at player [S2, unofficial].
    -   On player movement, start background thread [S2, unofficial]:
        -   Wait for previous thread to finish [S2, unofficial].
        -   Get chunks to load within threshold [S2, unofficial].
        -   Sort chunks by distance to player [S2, unofficial].
        -   Iterate sorted chunks:
            -   Check if player position changed; if so, abort [S2, unofficial].
            -   Compute chunk position and generate chunk [S2, unofficial].
            -   Instantiate `VoxelChunk`, populate voxels, generate mesh, add to scene tree [S2, unofficial].
    -   Remove chunks outside threshold [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N^3)$ per chunk for generation, where $N$ is chunk size. Mesh generation is $O(F)$ where $F$ is number of visible faces.
- **Memory Complexity:** $O(N^3)$ for voxel grid, $O(F)$ for mesh. RLE compression reduces storage for homogeneous chunks.
- **Performance:** Depends on chunk size and noise evaluation speed. Godot 4 C++ implementation [S2, unofficial] allows real-time loading.
- **Strengths:** Efficient memory usage via chunks, localized updates, simple meshing via face culling.
- **Limitations:** Dense voxel grid can be memory-intensive for large chunks. Noise evaluation can be CPU-bound.
- **When to use:** Real-time voxel worlds with dynamic terrain.
- **When not to use:** Static, high-poly terrain where meshing is preferred over voxels.

## Background
Originated from Minecraft-like voxel games. Implemented in Godot 4 C++ extension [S2, unofficial] and WebGL [S1, unofficial]. Uses octaved noise for terrain shaping [S1, unofficial].
