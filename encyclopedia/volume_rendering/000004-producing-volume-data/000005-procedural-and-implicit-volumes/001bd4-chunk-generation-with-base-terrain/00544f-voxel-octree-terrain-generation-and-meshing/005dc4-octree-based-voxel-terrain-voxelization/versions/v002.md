# Octree-based Voxel Terrain Voxelization

Also called: Recursive Octree Voxelization for Terrain, Surface-Intersecting Octree Terrain Voxelization

## Overview
This method constructs a voxel terrain representation by recursively subdividing an octree based on surface intersection tests [S1, unofficial]. It solves the problem of efficiently generating a sparse voxel grid for procedural terrain by only allocating memory for nodes that contain or intersect the terrain surface, rather than filling a dense volume [S1, unofficial]. It differs from dense voxelization by using adaptive depth, though this introduces specific edge cases regarding noise-induced gaps that require careful handling of subdivision criteria [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A terrain bounding box (typically rectangular), a surface definition function (e.g., Perlin noise heightmap), and a target voxel resolution (e.g., 1 m³) [S1, unofficial].
*   **Output:** An octree structure where leaf nodes represent either solid ground, empty air, or surface-intersecting chunks ready for meshing [S1, unofficial]. Each node contains a `voxel_index` indicating its rendering state [S1, unofficial].

**Data Structures:**
*   **Octree Node:**
    *   `bounds`: Axis-aligned bounding box (AABB) defining the spatial extent [S1, unofficial].
    *   `children`: Array of 8 child nodes (null if leaf) [S1, unofficial].
    *   `voxel_index`: Integer flag set by `intersects_surface()` indicating how the node is to be rendered later [S1, unofficial].
    *   `depth`: Current subdivision level [S1, unofficial].

**Algorithm Steps:**
1.  **Initialize Root Nodes:** Create an octree parent node for the terrain; if the terrain is rectangular rather than cubic, create more than one parent node to compose the rectangle [S1, unofficial]. Example: For a $2048 \times 1024 \times 2048$ terrain, create four parent nodes each with a size of $1024 \times 1024 \times 1024$ [S1, unofficial].
2.  **Subdivide to Component Level:** Subdivide the parent node to a level where each node represents a portion of the terrain called a component (or chunk); each component has the potential to be a model with one mesh forming the surface [S1, unofficial].
3.  **Recursive Subdivision:** Execute a recursive function that checks each component to see if it intersects the surface; if it does, subdivide it by adding eight children, which are then also checked [S1, unofficial].
4.  **Alternative Bottom-Up Approach:** Test all nodes at the lowest depth required (depending on LOD), cache the result, work back up to the root node, create parent nodes for a collection of eight nodes only if they represent a surface, and delete those complete in air or solid ground [S1, unofficial].

**Formulas and Parameters:**
*   **Voxel Size:** Typically 1 m³, determining the minimum leaf node dimension [S1, unofficial].
*   **Terrain Dimensions:** Example given as $2048 \times 1024 \times 2048$ [S1, unofficial].
*   **voxel_index:** A value set by the `intersects_surface()` function that indicates how the node is to be rendered later [S1, unofficial].

**Pitfalls and Edge Cases:**
*   **Noise-Induced Gaps:** Gaps appear when noise is added because a node's corners may all be inside or outside the surface, yet a child node may still represent the surface due to the random nature of the noise [S1, unofficial].
*   **Memory vs. Accuracy Trade-off:** Subdividing every node until the surface depth (voxel size, usually 1 m³) is reached avoids gaps but takes more time and uses more memory compared to selective subdivision [S1, unofficial].
*   **Prediction Difficulty:** Predicting whether a node intersects a Perlin Noise sample based on its frequency, amplitude, and octaves without sampling is complex and prone to error [S1, unofficial].

**Pseudocode:**
```python
class Node:
    def __init__(self, bounds, depth=0):
        self.bounds = bounds  # (min_x, min_y, min_z, max_x, max_y, max_z)
        self.children = [None] * 8
        self.voxel_index = 0
        self.depth = depth

def get_node_corners(node):
    """Returns the 8 corner coordinates of a node's AABB."""
    min_x, min_y, min_z, max_x, max_y, max_z = node.bounds
    return [
        (min_x, min_y, min_z), (max_x, min_y, min_z),
        (min_x, max_y, min_z), (max_x, max_y, min_z),
        (min_x, min_y, max_z), (max_x, min_y, max_z),
        (min_x, max_y, max_z), (max_x, max_y, max_z)
    ]

def intersects_surface(node, surface_func):
    """
    Determines if a node intersects the terrain surface.
    Returns (bool intersects, int voxel_index).
    """
    corners = get_node_corners(node)
    values = [surface_func(c) for c in corners]
    if min(values) <= 0 <= max(values):
        return True, 1  # 1 represents INTERSECTING
    elif all(v > 0 for v in values):
        return False, 2  # 2 represents INSIDE (above surface)
    else:
        return False, 3  # 3 represents OUTSIDE (below surface)

def create_children(node):
    """Splits an AABB into 8 equal octants."""
    min_x, min_y, min_z, max_x, max_y, max_z = node.bounds
    mid_x, mid_y, mid_z = (min_x+max_x)/2, (min_y+max_y)/2, (min_z+max_z)/2
    children_bounds = [
        (min_x, min_y, min_z, mid_x, mid_y, mid_z),
        (mid_x, min_y, min_z, max_x, mid_y, mid_z),
        (min_x, mid_y, min_z, mid_x, max_y, mid_z),
        (mid_x, mid_y, min_z, max_x, max_y, mid_z),
        (min_x, min_y, mid_z, mid_x, mid_y, max_z),
        (mid_x, min_y, mid_z, max_x, mid_y, max_z),
        (min_x, mid_y, mid_z, mid_x, max_y, max_z),
        (mid_x, mid_y, mid_z, max_x, max_y, max_z)
    ]
    return [Node(b, node.depth + 1) for b in children_bounds]

def voxelize_terrain(terrain_bounds, surface_func, max_depth):
    """
    Main entry point for octree-based voxel terrain voxelization.
    """
    root_nodes = []
    width = terrain_bounds[3] - terrain_bounds[0]
    height = terrain_bounds[4] - terrain_bounds[1]
    depth = terrain_bounds[5] - terrain_bounds[2]
    
    # If terrain is not a power-of-two cube, split into multiple roots
    if width == height == depth and (width & (width - 1)) == 0:
        root = Node(terrain_bounds, depth=0)
        root_nodes.append(root)
    else:
        # Create multiple parent nodes to cover rectangular bounds
        # Standard grid splitting into power-of-two cubes
        step = 1
        while step * 2 <= max(width, height, depth):
            step *= 2
        for x in range(0, width, step):
            for y in range(0, height, step):
                for z in range(0, depth, step):
                    b = (x, y, z, min(x+step, width), min(y+step, height), min(z+step, depth))
                    root_nodes.append(Node(b, depth=0))

    for root in root_nodes:
        subdivide(root, surface_func, max_depth)
    return root_nodes

def subdivide(node, surface_func, max_depth):
    """
    Recursively subdivides the octree node if it intersects the surface.
    """
    intersects, voxel_index = intersects_surface(node, surface_func)
    node.voxel_index = voxel_index

    if intersects:
        if node.depth < max_depth:
            children = create_children(node)
            for child in children:
                subdivide(child, surface_func, max_depth)
            node.children = children
        else:
            # Reached target voxel size
            pass
    else:
        # Node is fully inside or outside; do not subdivide
        pass
```

## Operating characteristics
*   **Time Complexity:** Depends heavily on the surface complexity and the subdivision strategy [S1, unofficial]. Selective subdivision is faster but risks gaps [S1, unofficial]. Full subdivision to voxel size is $O(N)$ where $N$ is the number of voxels at the target resolution, which is significantly slower than sparse methods [S1, unofficial].
*   **Memory Complexity:** Sparse [S1, unofficial]. Only nodes intersecting the surface or below it are allocated [S1, unofficial]. However, if full subdivision is used to avoid gaps, memory usage approaches that of a dense grid [S1, unofficial].
*   **Strengths:** Efficient for large terrains with sparse surface detail [S1, unofficial]. Adaptive resolution allows for high detail near the surface and coarser representation deeper underground [S1, unofficial].
*   **Limitations:** Prone to gaps when using high-frequency noise if intersection tests are not robust [S1, unofficial]. Performance degrades if the surface is highly complex or if full subdivision is required [S1, unofficial].
*   **When to use:** When memory efficiency is critical and the terrain surface is relatively smooth or low-frequency [S1, unofficial].
*   **When not to use:** When using high-frequency noise and gaps are unacceptable, unless the performance cost of full subdivision is acceptable [S1, unofficial].

## Background
This method was developed as part of the Voxel Terrain system for the Ultra game engine, specifically for VR optimization [S1, unofficial]. It was documented in a blog post by the developer of "The Seventh World" project [S1, unofficial]. The approach addresses the challenges of generating voxel terrain efficiently for real-time rendering, balancing memory usage with visual fidelity [S1, unofficial]. The specific issues with noise-induced gaps highlight the difficulties of adaptive voxelization with procedural surfaces [S1, unofficial].
