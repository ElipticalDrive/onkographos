# Chunked Voxel Evaluation (Top-Down Procedural Generation)

Also called: Chunked Evaluation, Top-Down Procedural Generation

## Overview
This method generates voxel data on-demand by evaluating procedural objects within specific spatial chunks based on camera locality, rather than pre-generating the entire world. It solves the problem of efficiently rendering large-scale procedural structures (such as trees or buildings) that span multiple chunks without explicit geometric splitting. It differs from [Procedural Terrain Heightmap Generation](1850-procedural-terrain-heightmap-generation.md) by operating on full 3D volumetric primitives defined by high-level parameters, and from [Voxel Evaluation with AABB Culling](2415-voxel-evaluation-with-aabb-culling.md) by explicitly managing chunk redundancy for seamless normal calculation [S1, unofficial].

## How it works
The method operates in a top-down fashion: high-level structural parameters are defined on the CPU (C++), and voxel-level evaluation occurs in the GPU shader (GLSL) for chunks near the camera.

**Inputs and Outputs:**
*   **Input:** Camera position, chunk grid coordinates, list of active procedural objects with their parameters.
*   **Output:** Voxel density/normal data for the current chunk.

**Data Structures:**
*   **Object Definition (CPU):** Each procedural object (e.g., a tree branch) is defined by high-level parameters: start point, end point, control points, start thickness, end thickness, and a computed bounding box [S1, unofficial].
*   **Chunk Definition:** Each chunk has a defined world-space bounding box (start and end coordinates) [S1, unofficial].
*   **Shader Input:** A list of active objects and the current chunk's bounding box [S1, unofficial].

**Steps:**
1.  **Define High-Level Structures (CPU):** Generate the world map, place cities/roads, and define neighborhood layouts. For each object (e.g., tree branch), compute its bounding box in world space [S1, unofficial].
2.  **Determine Active Chunks:** Identify which chunks intersect with the bounding boxes of active objects. Only these chunks require evaluation [S1, unofficial].
3.  **Pass Parameters to GPU:** Send the list of active objects and their parameters to the shader [S1, unofficial].
4.  **Evaluate Per Chunk (GPU):** For each active chunk:
    a.  Define the chunk's world-space bounding box (start and end coordinates) [S1, unofficial].
    b.  Derive relative (object) coordinates for each voxel within the chunk based on the bounding box [S1, unofficial].
    c.  Evaluate each active object against the current chunk's voxels. Determine if a voxel lies within the object's geometry using the object's parameters (bounds, control points, thicknesses) [S1, unofficial].
    d.  Generate voxel representation (density/normal) for the chunk [S1, unofficial].
5.  **Render:** Render the chunk within its bounds. Note that chunks are generated with redundant voxels (1.25x dimensions) to allow seamless normal calculation in the shader [S1, unofficial].

**Parameters:**
*   **Generation Order:** Top-down [S1, unofficial].
*   **Determinism:** All generation is deterministic based on a seed [S1, unofficial].
*   **Chunk Redundancy Factor:** Approximately 1.25x in dimensions to ensure seamless normals [S1, unofficial].

## Subtopics

### [Chunk Redundancy for Seamless Normals](15485-chunk-redundancy-for-seamless-normals.md)
Generates chunks with redundant voxels beyond their render bounds to allow seamless normal calculation inside the shader.

## Operating characteristics
*   **Time Complexity:** O(N * M) where N is the number of active chunks and M is the number of voxels per chunk. Evaluation is per-voxel, per-object.
*   **Memory Complexity:** O(N) for storing active object parameters. Voxel data is generated on-demand.
*   **Performance:** Efficient for sparse or large-scale worlds as only nearby chunks are evaluated. Deterministic generation allows regeneration.
*   **Strengths:** No need for pre-generation; handles objects spanning multiple chunks seamlessly; parallelizable chunk generation.
*   **Limitations:** Requires redundant voxel generation for normals; shader evaluation can be costly for complex objects.
*   **When to use:** Large procedural worlds with dynamic camera movement; objects spanning multiple chunks.
*   **When not to use:** Static, small-scale worlds; objects with extremely complex per-voxel evaluation.

## Background
Originated in the development of VoxelQuest, an unofficial voxel engine. The method was described in a blog post by the developer in 2014. It addresses the challenges of procedural generation in voxel engines by combining high-level CPU-side structure generation with low-level GPU-side voxel evaluation.
