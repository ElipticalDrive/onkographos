# Biome and Voxel Layer Determination

Also called: Biome-based Voxel Classification, Voxel Type Assignment Logic

## Overview
This method assigns the type of each voxel in a procedural world based on its vertical position relative to the generated terrain surface (`genHeight`) and biome parameters derived from noise functions (moisture, temperature, wackiness) [S1, unofficial]. It solves the problem of creating varied, biologically plausible terrain structures (such as underwater layers, deserts, and jungles) without hard-coding specific coordinates [S1, unofficial]. It differs from its sibling [Procedural Tree Generation](4826-procedural-tree-generation.md) by focusing on static ground composition and layering rather than organic structure placement [S1, unofficial].

## How it works
**Inputs:**
- `genHeight`: The generated terrain surface height at the current `(x, z)` coordinate, obtained from the heightmap [S1, unofficial].
- `moisture`: A noise value representing biome moisture [S1, unofficial].
- `temperature`: A noise value representing biome temperature [S1, unofficial].
- `wackiness`: A noise value used for jungle/mushroom variation [S1, unofficial].
- `y`: The vertical coordinate of the voxel being evaluated [S1, unofficial].
- `water_level`: The global water level threshold [S1, unofficial].
- `config`: Configuration object containing `equator_temp`, `temp_decay_coeff`, `world_size` [S1, unofficial].

**Outputs:**
- `VoxelID`: An integer identifier for the block type (e.g., AIR, STONE, GRASS, SAND) [S1, unofficial].

**Data Structures:**
- Biome parameters are derived from 2D noise functions (e.g., `OctavedNoise2d`) seeded from a global world seed [S1, unofficial].
- Terrain height is computed on-demand or cached per chunk rather than stored as a global 2D array in the provided implementation [S1, unofficial].

**Parameters:**
- `equator_temp`: Base temperature at the world equator (typically 1.0) [S1, unofficial].
- `temp_decay_coeff`: Coefficient for temperature falloff from the equator (typically 0.1) [S1, unofficial].
- `world_size`: The total size of the world in X/Z dimensions [S1, unofficial].

**Steps:**

1. **Calculate Temperature:**
   Compute the temperature at the current `z` coordinate using the formula:
   $$
   \text{temperature} = \text{clamp}\left(\text{equator\_temp} - \left| z - \frac{\text{world\_size}}{2} \right| \times \text{temp\_decay\_coeff}, 0, 1\right)
   $$
   [S1, unofficial].

2. **Determine Biome Type:**
   Classify the biome based on `moisture`, `temperature`, and `wackiness` thresholds:
   - **Desert:** `moisture <= 0.3` AND `temperature >= 0.7` [S1, unofficial].
   - **Tundra:** `moisture <= 0.4` AND `temperature <= 0.3` [S1, unofficial].
   - **Jungle/Mushroom:** `moisture > 0.7` [S1, unofficial].
     - If `wackiness > 0.7` AND `temperature > 0.7`: Mushroom Biome [S1, unofficial].
     - Else: Jungle Biome [S1, unofficial].
   - **Default:** Any other combination [S1, unofficial].

3. **Assign Voxel Type based on Height (`y`) and Biome:**
   Evaluate `y` relative to `genHeight` and `water_level`:

   - **Underwater Logic:**
     If `y < water_level`:
     - If `y >= genHeight`: Return `WATER` [S1, unofficial].
     - If `y + 2 >= genHeight`: Return `SAND` [S1, unofficial].
     - If `y + 8 >= genHeight`: Return `MUD` [S1, unofficial].
     - If `y + 14 >= genHeight`: Return `SANDSTONE` [S1, unofficial].
     - Else: Return `STONE` [S1, unofficial].

   - **Sky/Air Logic:**
     If `y > genHeight`: Return `AIR` [S1, unofficial].

   - **Desert Biome:**
     - If `y + 3 >= genHeight`: Return `SAND` [S1, unofficial].
     - If `y + 7 >= genHeight`: Return `SANDSTONE` [S1, unofficial].
     - Else: Return `STONE` [S1, unofficial].

   - **Tundra Biome:**
     - If `y + 1 >= genHeight`: Return `SNOW` [S1, unofficial].
     - If `y + 6 >= genHeight`: Return `PACKED_DIRT` [S1, unofficial].
     - Else: Return `STONE` [S1, unofficial].

   - **Jungle/Mushroom Biome:**
     - If `y + 1 >= genHeight`:
       - If Mushroom Biome: Return `MYCELIUM` [S1, unofficial].
       - Else (Jungle Biome): Return `GRASS` [S1, unofficial].
     - Else: Return `DIRT` [S1, unofficial].

   - **Default Biome:**
     - If `y + 1 >= genHeight`: Return `GRASS` [S1, unofficial].
     - If `y + 6 >= genHeight`: Return `DIRT` [S1, unofficial].
     - Else: Return `STONE` [S1, unofficial].

**Pseudocode:**

```python
VOXEL_TYPES = {
    "WATER": 0, "SAND": 1, "MUD": 2, "SANDSTONE": 3, "STONE": 4,
    "AIR": 5, "SNOW": 6, "PACKED_DIRT": 7, "MYCELIUM": 8,
    "GRASS": 9, "DIRT": 10, "FERTILE_DIRT": 11
}

def clamp(value, min_val, max_val):
    if value < min_val:
        return min_val
    if value > max_val:
        return max_val
    return value

def determine_voxel_type(x, y, z, gen_height, moisture, wackiness, config):
    # Step 1: Calculate Temperature
    eq = config.world_size / 2
    temp = config.equator_temp - abs(z - eq) * config.temp_decay_coeff
    temperature = clamp(temp, 0, 1)

    # Step 2: Determine Biome
    is_desert = moisture <= 0.3 and temperature >= 0.7
    is_tundra = moisture <= 0.4 and temperature <= 0.3
    is_jungle_mushroom = moisture > 0.7
    is_mushroom = is_jungle_mushroom and wackiness > 0.7 and temperature > 0.7
    is_jungle = is_jungle_mushroom and not is_mushroom

    # Step 3: Assign Voxel Type
    if y < config.water_level:
        # Underwater logic
        if y >= gen_height:
            return VOXEL_TYPES["WATER"]
        elif y + 2 >= gen_height:
            return VOXEL_TYPES["SAND"]
        elif y + 8 >= gen_height:
            return VOXEL_TYPES["MUD"]
        elif y + 14 >= gen_height:
            return VOXEL_TYPES["SANDSTONE"]
        else:
            return VOXEL_TYPES["STONE"]
    
    if y > gen_height:
        # Sky/Air logic
        return VOXEL_TYPES["AIR"]

    if is_desert:
        if y + 3 >= gen_height:
            return VOXEL_TYPES["SAND"]
        elif y + 7 >= gen_height:
            return VOXEL_TYPES["SANDSTONE"]
        else:
            return VOXEL_TYPES["STONE"]
            
    if is_tundra:
        if y + 1 >= gen_height:
            return VOXEL_TYPES["SNOW"]
        elif y + 6 >= gen_height:
            return VOXEL_TYPES["PACKED_DIRT"]
        else:
            return VOXEL_TYPES["STONE"]
            
    if is_jungle_mushroom:
        if y + 1 >= gen_height:
            if is_mushroom:
                return VOXEL_TYPES["MYCELIUM"]
            else:
                return VOXEL_TYPES["GRASS"]
        else:
            return VOXEL_TYPES["DIRT"]
            
    # Default biome
    if y + 1 >= gen_height:
        return VOXEL_TYPES["GRASS"]
    elif y + 6 >= gen_height:
        return VOXEL_TYPES["DIRT"]
    else:
        return VOXEL_TYPES["STONE"]
```

**Edge Cases and Pitfalls:**
- **Precision:** The offsets (e.g., `y + 1`) are integer additions applied to voxel coordinates [S1, unofficial].
- **Boundaries:** The temperature calculation assumes `z` is within `[0, world_size]` [S1, unofficial].
- **Degenerate Input:** If `gen_height` is undefined, the logic fails; it must be computed from the heightmap or noise function before evaluation [S1, unofficial].

## Subtopics

### Depth-Dependent Ore Distribution
Generates ore distribution by seeding blocks based on depth-dependent frequency and weighting ore types by their desired depth ranges [S2, unofficial]. It loops through `x` and `z` coordinates, then iterates `y` from 0 to `terrainHeight` inclusive [S2, unofficial]. It calculates `currentDepthPercent = 1 - (y / terrainHeight)` and adjusts seed frequency using `defaultSeedDensity * MapRange(currentDepthPercent, 0, 1, 1, densityDepthMultiplier)` [S2, unofficial]. For each ore type, it calculates a probability multiplier based on the distance from the ore's desired depth center and radius: `probabilityMult = 1 - (abs(center - currentDepthPercent) / radius)`, clamped to `[0, 1]` [S2, unofficial]. The final ore probability is `probabilityMult * defaultOreProbabilities[o]` [S2, unofficial]. An ore type is selected using `WeightedRandomChoice(currentOreProbabilities)` and placed at `(x, y, z)` [S2, unofficial]. This method is distinct from biome-based surface layering as it operates on vertical depth within the solid terrain rather than surface biome conditions [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel for biome determination, as it involves a fixed number of comparisons and arithmetic operations [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space, as it does not require additional data structures beyond the input parameters [S1, unofficial].
- **Measured Performance:** Not given in the sources [S1, S2, unofficial].
- **Strengths:** Simple to implement, computationally inexpensive, allows for diverse terrain types through parameter tuning [S1, unofficial].
- **Limitations:** Does not handle ore distribution (requires separate logic like Depth-Dependent Ore Distribution) [S2, unofficial]. Biome transitions are abrupt based on noise thresholds [S1, unofficial].
- **When to Use:** Ideal for voxel worlds where terrain variety is driven by surface conditions (biomes) rather than deep geological structures [S1, unofficial].
- **When Not to Use:** When complex underground structures or smooth biome blending are required [S1, S2, unofficial].

## Background
Originated in the open-source project `web_voxel_terrain` by Andrew Bloese in January 2025 [S1, unofficial]. The method is part of a procedural voxel world generation pipeline that uses octaved noise functions for terrain height, moisture, and wackiness [S1, unofficial]. It is designed for client-side rendering in web browsers using Three.js [S1, unofficial]. The approach is inspired by classic voxel games like Minecraft but adapted for procedural generation with specific biome parameters [S1, unofficial].
