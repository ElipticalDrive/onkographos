# Procedural Tree Generation

Also called: Bezier Curve Tree Generation, Quadratic Bezier Tree, Tree Generation

## Overview
Procedural tree generation places voxel-based trees onto a terrain surface by identifying valid ground positions and filling a defined volume with trunk and leaf blocks [S2, unofficial]. It differs from sibling methods like [Deterministic Fixture Worlds](3941-deterministic-fixture-worlds.md) by focusing on organic, vertical structures rather than static geometric fixtures, and from [Biome and Voxel Layer Determination](4167-biome-and-voxel-layer-determination.md) by operating on specific placement logic rather than global layer composition [G]. The primary challenge is ensuring trees fit within chunk boundaries and do not intersect with existing geometry [S1, S2, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- `globalX`, `globalZ`: The integer world coordinates of the chunk or placement origin [S2, unofficial].
- `terrainHeight`: The height of the ground block at the placement coordinate [S1, S2, unofficial].
- `chunkWidth`, `chunkHeight`: Dimensions of the voxel chunk [S2, unofficial].
- `TREE_PROBABILITY`: A float between 0 and 1 determining the likelihood of tree generation at a valid spot [S1, unofficial].
- `TREE_HEIGHT`: The height of the trunk in blocks [S1, unofficial].
- `world.ShouldPlaceTree(globalX, globalZ)`: A boolean function determining if a tree is allowed at this location (e.g., biome checks) [S2, unofficial].

**Outputs:**
- Modified voxel array where `DIRT` (base), `WOOD` (trunk), and `LEAVES` (canopy) blocks are set [S1, S2, S4, unofficial].

### Data Structures
- `voxels`: A 3D array or flattened 1D array representing the chunk [G].
- `BlockType`: Enum or integer constants for `DIRT`, `WOOD`, `LEAVES`, `AIR` (0) [S4, unofficial].

### Steps
1. **Validation**: Check if the surface block at `(globalX, globalZ)` is `GRASS` [S1, unofficial].
2. **Probability Check**: Generate a random number `rnd`. If `rnd > TREE_PROBABILITY`, abort [S1, unofficial].
3. **Boundary Check**: Ensure the tree fits within the chunk [S1, S2, unofficial].
   - Check `y + TREE_HEIGHT` against `chunkHeight` [S1, unofficial].
   - Check `x` and `z` offsets against chunk borders to prevent leaf overflow (e.g., `x < 2` or `x > chunkWidth - 3`) [S2, unofficial].
4. **Placement Logic**:
   - **Base**: Place `DIRT` at `(x, terrainHeight, z)` [S1, unofficial].
   - **Trunk**: Place `WOOD` from `terrainHeight + 1` to `terrainHeight + TREE_HEIGHT` (or similar range depending on variant) [S1, S2, unofficial].
   - **Canopy**: Place `LEAVES` in a shape defined by the specific variant (cone, box, ball) [S1, S2, S4, unofficial].

### Formulas and Parameters
- **Trunk Height**: `trunkHeight = 4` (typical value in [S2, unofficial]).
- **Canopy Shape (Cone Variant)**: Uses Manhattan distance `distance = |offsetX| + |offsetZ|` [S2, unofficial].
- **Canopy Shape (Ball Variant)**: Euclidean distance squared `distSq = (baseX - x)^2 + (baseZ - z)^2 + (baseY + height - y)^2` compared to `radius^2` [S4, unofficial].
- **Canopy Shape (Box Variant)**: Rectangular bounds `baseX ± leafWidth`, `baseZ ± leafWidth`, `baseY + trunkHeight ± leafHeight` [S4, unofficial].

### Edge Cases and Pitfalls
- **Chunk Overflow**: Trees placed near chunk edges must be clipped or prevented to avoid visual seams or out-of-bounds writes [S2, unofficial].
- **Precision**: Integer arithmetic is sufficient for block placement [G].
- **Degenerate Input**: If `terrainHeight` is invalid (e.g., below sea level or above chunk height), placement must fail gracefully [G].

### Pseudocode
```python
import random

# Constants
AIR = 0
DIRT = 1
WOOD = 2
LEAVES = 3
GRASS = 4

def get_block(voxels, x, y, z):
    return voxels[x, y, z]

def set_block(voxels, x, y, z, block_type):
    voxels[x, y, z] = block_type

def place_tree(voxels, global_x, global_z, terrain_height, chunk_width, chunk_height, tree_height):
    # 1. Validation
    if get_block(voxels, global_x, terrain_height, global_z) != GRASS:
        return False

    # 2. Probability Check
    if random.random() > 0.5:  # TREE_PROBABILITY not given in sources [G]
        return False

    # 3. Boundary Check
    if global_x < 2 or global_x > chunk_width - 3:
        return False
    if global_z < 2 or global_z > chunk_width - 3:
        return False
    if terrain_height + tree_height + 1 >= chunk_height:
        return False

    # 4. Place Base
    set_block(voxels, global_x, terrain_height, global_z, DIRT)

    # 5. Place Trunk
    for y in range(terrain_height + 1, terrain_height + tree_height + 1):
        set_block(voxels, global_x, y, global_z, WOOD)

    # 6. Place Canopy (Cone/Manhattan variant from [S2, unofficial])
    trunk_height = 4
    for leaf_y in range(terrain_height + trunk_height - 1, terrain_height + trunk_height + 2):
        for offset_z in range(-2, 3):
            for offset_x in range(-2, 3):
                distance = abs(offset_x) + abs(offset_z)
                if distance > 3:
                    continue
                set_block(voxels, global_x + offset_x, leaf_y, global_z + offset_z, LEAVES)

    return True
```

## Subtopics

### [PlaceTreeCone](5090-placetreecone.md)
PlaceTreeCone generates a procedural voxel tree consisting of a trunk and a leaf canopy shaped as a truncated cone. It places wood blocks for the trunk and leaf blocks in a conical shape, respecting chunk boundaries. The method is distinguished by two documented implementations: a radial gradient with a circular cross-section check, and a fixed Manhattan distance heuristic for the canopy shape. When to choose it: Not given in the sources. [PlaceTreeCone](5090-placetreecone.md)

### PlaceTreeBall
PlaceTreeBall generates a tree with a spherical leaf canopy by checking the squared Euclidean distance from the center of the leaf volume [S4, unofficial]. It is distinguished by its constant-radius spherical shape compared to the tapered cone of PlaceTreeCone [G]. When to choose it: Not given in the sources.

### PlaceTreeBox
PlaceTreeBox generates a tree with a rectangular prism leaf canopy by iterating over a 3D box centered on the trunk and placing leaf blocks probabilistically [S4, unofficial]. It is distinguished by its simple, blocky shape compared to the curved profiles of PlaceTreeCone and PlaceTreeBall [G]. When to choose it: Not given in the sources.

## Background
Procedural tree generation is a staple of voxel-based games like Minecraft [G]. The base placement logic originates from implementations that check for grass blocks and apply probability thresholds [S1, unofficial]. Chunk boundary checks to prevent leaf overflow were introduced to maintain visual consistency across chunk borders [S2, unofficial]. Advanced variants utilize quadratic Bezier curves for branch generation and distance calculations for wood rings and bark [S3, unofficial]. The specific variants (Cone, Ball, Box) represent common simplifications used in voxel engines to balance visual appeal with computational cost [G].
