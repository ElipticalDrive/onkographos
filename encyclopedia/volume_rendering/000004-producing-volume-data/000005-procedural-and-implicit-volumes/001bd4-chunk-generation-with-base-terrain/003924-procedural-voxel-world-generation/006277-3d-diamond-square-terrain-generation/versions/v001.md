# 3D Diamond-Square Terrain Generation

Also called: 3D Diamond-Square, Modified Diamond Square

## Overview
3D Diamond-Square is a procedural generation method that produces a 3-dimensional map of a fractal surface using voxels, allowing for the generation of relief structures such as caves, canyons, and quarries that cannot be generated using a regular 2D elevation map [S1]. Unlike its 2D predecessor, which generates heightmaps, this method fills a volumetric grid, enabling complex internal geometry [S1]. It sets itself apart from sibling methods like [Procedural Voxel World Generation](3891-procedural-voxel-world-generation.md) by providing the underlying geometric structure (the "skeleton" of solid vs. empty space) rather than determining block types based on density thresholds alone.

## How it works
**Inputs and Outputs:**
*   **Input:** A cubic 3D grid of dimensions $(2^n + 1) \times (2^n + 1) \times (2^n + 1)$ for some integer $n \ge 1$. A boolean data type is used for storage [S1].
*   **Output:** A fully populated 3D boolean array where `true` represents solid voxel space and `false` represents empty space [S1].

**Data Structures:**
*   `Grid[x][y][z]`: A 3D array of booleans. The indices range from $0$ to $2^n$.
*   The algorithm operates on "cubes" defined by their corner vertices. In the first iteration, the entire grid forms one large cube. In subsequent iterations, the grid is subdivided into smaller cubes.

**Parameters:**
*   $n$: The recursion depth or subdivision level. The grid size is $N = 2^n + 1$.
*   $H_{limit}$: The height limit or density threshold. The random value $R$ decreases as the height limit is approached, tending to zero after the height limit [S1]. [G] The specific formula for $R$'s decay is not given in the sources, but it is implied to be a function of the current iteration step or distance from the boundary.

**Steps:**
The algorithm proceeds through recursive subdivision. In each level of recursion, the grid is divided into 8 sub-cubes. For each sub-cube, three steps are performed in order: Center, Diamond, and Square. This process repeats until all points in the 3D grid are assigned values [S1].

1.  **Initialization:**
    *   Assign the value `true` to the eight corner points of the 3D array (indices $(0,0,0), (0,0,N), (0,N,0), (0,N,N), (N,0,0), (N,0,N), (N,N,0), (N,N,N)$) [S1].
    *   Assign the value `false` to the top surface points (where $z = N$ or $z=0$ depending on coordinate system orientation, but specifically the "top surface" as defined by the source) and `true` to the lower surface points [S1]. [G] Standard interpretation suggests the "bottom" of the world is solid (`true`) and the "top" is air (`false`), creating a base terrain.

        **Step A: Center Step**
        *   Identify the median point (center) of the cube: $C = (x + step, y + step, z + step)$.

## Operating characteristics
*   **Time Complexity:** The algorithm requires approximately $n^3 - n^2$ more actions than the original 2D diamond-square algorithm due to operating in 3D space [S1].
*   **Memory Usage:** The algorithm uses a boolean data type but consumes a lot of RAM to process the 3D grid [S1].
*   **Strengths:** Generates complex 3D relief structures (caves, canyons, quarries) that 2D heightmaps cannot produce [S1].
*   **Limitations:**
    *   **Flying Structures:** The algorithm tends to create disconnected "flying" structures that must be removed using a separate auxiliary algorithm/script [S1].
    *   **Control:** Less control than the original algorithm, which had a single random factor multiplier. The modified algorithm's randomness can lead to unrealistic structures [S1].
    *   **Speed:** Slower than 2D variants due to the cubic increase in operations [S1].

## Background
The Modified Diamond-Square algorithm was presented by V.O. Pozdeev and colleagues in 2019 [S1]. It is an extension of the original Diamond-Square algorithm (2D) to 3D space, specifically designed for procedural generation in game systems and multimedia applications [S1]. It was implemented in the Unity environment for building game levels and constructing 3D maps of fractal surfaces [S1].
