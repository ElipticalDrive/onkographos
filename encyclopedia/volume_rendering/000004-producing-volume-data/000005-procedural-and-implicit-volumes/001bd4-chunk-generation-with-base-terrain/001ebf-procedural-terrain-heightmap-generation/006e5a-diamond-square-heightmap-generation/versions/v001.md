# Diamond-Square Heightmap Generation

Also called: Midpoint Displacement, Random Midpoint Displacement

## Overview
Diamond-Square Heightmap Generation is a procedural terrain generation algorithm that creates a heightmap by recursively subdividing a grid and displacing the center of diamond and square shapes with an average of surrounding points plus a random offset [S1, unofficial]. It differs from noise-based siblings like [Terrain Generation via Noise](2412-terrain-generation-via-noise.md) by using a deterministic geometric subdivision pattern rather than continuous function evaluation, and from [Smooth Terrain Grid](5026-smooth-terrain-grid.md) by its explicit recursive structure. The method is primarily chosen when a structured, grid-aligned heightmap with specific boundary wrapping properties is required for chunk-based volume rendering.

## How it works
**Inputs:**
- `dimensions`: A 2D integer vector $(D_x, D_y)$ specifying the grid size. $D_x$ and $D_y$ must be of the form $2^n + 1$ for some integer $n \ge 1$.
- `SEED`: A floating-point value representing the initial height for the four corners. Typical value: `rand() % 10 + 55` [S1, unofficial].
- `initial_h`: The initial maximum random offset range. Typical value: $20.0$ [S1, unofficial].

**Outputs:**
- `height_map`: A 1D array of doubles representing the 2D heightmap grid. The array size is $D_x \times D_y$. Access to coordinate $(x, y)$ is calculated as:
  $$ \text{index} = (x \ \& \ (D_x - 1)) + (y \ \& \ (D_y - 1)) \times D_x $$
  This bitwise indexing implies that $D_x$ and $D_y$ are powers of two plus one, but the wrapping logic treats the grid as toroidal (wrapped) [S1, unofficial].

**Data Structures:**
- `height_map`: 1D array of `double`.
- `sideLength`: Integer, current subdivision step size.
- `h`: Float, current random offset magnitude.

**Algorithm Steps:**
1. **Initialization**: Set the four corners of the grid to `SEED`.
   - `SetSample(0, 0, SEED)`
   - `SetSample(0, D_y - 1, SEED)`
   - `SetSample(D_x - 1, 0, SEED)`
   - `SetSample(D_x - 1, D_y - 1, SEED)`
   [S1, unofficial]

2. **Iteration**: Loop while `sideLength >= 2`.
   - Halve `sideLength`: `sideLength /= 2`.
   - Halve `h`: `h /= 2.0`.
   - Calculate `halfSide = sideLength / 2`.

3. **Square Step**: Iterate through the grid to calculate the centers of the squares formed by the previous iteration's points.
   - The loop structure iterates $y$ and $x$ such that they align with the centers of the squares.
   - For each center $(x, y)$:
     - Identify the four corners: top-left $(x - \text{halfSide}, y - \text{halfSide})$, top-right $(x + \text{halfSide}, y - \text{halfSide})$, bottom-left $(x - \text{halfSide}, y + \text{halfSide})$, bottom-right $(x + \text{halfSide}, y + \text{halfSide})$.
     - Handle boundary wrapping for these corners using modulo arithmetic or bitwise AND if coordinates exceed bounds [S1, unofficial].
     - Calculate average:
       $$ \text{avg} = \frac{1}{4} (h_{tl} + h_{tr} + h_{bl} + h_{br}) $$
     - Generate random offset:
       $$ \text{offset} = (\text{rand}() \times 2 \times h) - h $$
       where $\text{rand}()$ returns a value in $[0, 1]$ [S1, unofficial].
     - Set sample:
       $$ \text{SetSample}(x, y, \text{avg} + \text{offset}) $$
   [S1, unofficial]

4. **Diamond Step**: Iterate through the grid to calculate the centers of the diamonds.
   - The loop structure iterates $x$ and $y$ such that they align with the midpoints of the edges of the previous squares.
   - For each center $(x, y)$:
     - Identify the four surrounding points: top $(x, y - \text{halfSide})$, right $(x + \text{halfSide}, y)$, bottom $(x, y + \text{halfSide})$, left $(x - \text{halfSide}, y)$.
     - Handle boundary wrapping for these points [S1, unofficial].
     - Calculate average:
       $$ \text{avg} = \frac{1}{4} (h_{top} + h_{right} + h_{bottom} + h_{left}) $$
     - Generate random offset (same formula as above).
     - Set sample:
       $$ \text{SetSample}(x, y, \text{avg} + \text{offset}) $$
   [S1, unofficial]

5. **Edge Wrapping**: The implementation explicitly handles edge wrapping. If a coordinate is $0$, the value at $D_x - 1$ (or $D_y - 1$) is used for the opposite side, creating a toroidal topology [S1, unofficial].

def diamond_square_heightmap(dimensions_x, dimensions_y, seed, initial_h):
    # dimensions must be 2^n + 1
    side_length = dimensions_x # Assuming square grid for simplicity, or max(dimensions_x, dimensions_y)
    h = initial_h
    
    # Initialize height_map array
    height_map = [0.0] * (dimensions_x * dimensions_y)
    
    # Helper to set sample with wrapping
    def set_sample(x, y, value):
        # Wrap coordinates
        wx = x & (dimensions_x - 1)
        wy = y & (dimensions_y - 1)
        height_map[wy * dimensions_x + wx] = value
        
    # Helper to get sample with wrapping
    def get_sample(x, y):
        wx = x & (dimensions_x - 1)
        wy = y & (dimensions_y - 1)
        return height_map[wy * dimensions_x + wx]

    # Initialize corners
    set_sample(0, 0, seed)
    set_sample(0, dimensions_y - 1, seed)
    set_sample(dimensions_x - 1, 0, seed)
    set_sample(dimensions_x - 1, dimensions_y - 1, seed)

    while side_length >= 2:
        half_side = side_length // 2
        h = h / 2.0
        
        # Square Step
        # Iterate over centers of squares
        # The loop structure in source: for (int y = (x + halfSide) % sideLength; y < DATA_SIZE - 1; y += sideLength)
        # This implies a specific traversal order. We will iterate x and y in steps of side_length
        for y in range(half_side, dimensions_y, side_length):
            for x in range(half_side, dimensions_x, side_length):
                # Get four corners
                tl = get_sample(x - half_side, y - half_side)
                tr = get_sample(x + half_side, y - half_side)
                bl = get_sample(x - half_side, y + half_side)
                br = get_sample(x + half_side, y + half_side)
                
                avg = (tl + tr + bl + br) / 4.0
                offset = (random_float() * 2 * h) - h
                set_sample(x, y, avg + offset)

        # Diamond Step
        # Iterate over midpoints of edges
        for y in range(0, dimensions_y, side_length):
            for x in range(half_side, dimensions_x, side_length):
                # Get four surrounding points
                top = get_sample(x, y - half_side)
                right = get_sample(x + half_side, y)
                bottom = get_sample(x, y + half_side)
                left = get_sample(x - half_side, y)
                
                avg = (top + right + bottom + left) / 4.0
                offset = (random_float() * 2 * h) - h
                set_sample(x, y, avg + offset)
                
        # Note: The source code loop for y in diamond step might differ slightly in start index.
        # Standard diamond-square alternates. The source implies a specific interleaved loop.
        # Re-evaluating source loop:
        # for (int y = (x + halfSide) % sideLength; y < DATA_SIZE - 1; y += sideLength)
        # This suggests the loops are nested and dependent.
        # A more robust interpretation of the source's "Square step" and "Diamond step" logic:
        
        # Reset for Diamond Step based on source structure
        for x in range(0, dimensions_x, side_length):
            for y in range((x + half_side) % side_length, dimensions_y, side_length):
                # Diamond points
                top = get_sample(x, y - half_side)
                right = get_sample(x + half_side, y)
                bottom = get_sample(x, y + half_side)
                left = get_sample(x - half_side, y)
                
                avg = (top + right + bottom + left) / 4.0
                offset = (random_float() * 2 * h) - h
                set_sample(x, y, avg + offset)

        side_length = side_length // 2

    return height_map

**Parameters:**
- `dimensions_x`, `dimensions_y`: Grid dimensions. Must be $2^n + 1$.
- `seed`: Initial corner height. Typical: `rand() % 10 + 55` [S1, unofficial].
- `initial_h`: Initial roughness. Typical: $20.0$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Boundary Wrapping**: The algorithm uses bitwise AND for indexing, which requires dimensions to be powers of two. However, the logical dimensions are $2^n + 1$. The source code uses `dimensions.x - 1` for masking, which works if `dimensions.x` is a power of two. This implies the grid is treated as having size $2^n$ for indexing purposes, but the logical size is $2^n + 1$. This is a potential source of confusion. The source explicitly handles wrapping for edges using modulo arithmetic in the loop conditions [S1, unofficial].
- **Precision**: Using `double` for height values helps maintain precision during recursive averaging.
- **Degenerate Input**: If dimensions are not of the form $2^n + 1$, the algorithm may fail or produce incorrect results due to the bitwise wrapping and subdivision logic.

## Operating characteristics
- **Time Complexity**: $O(N^2)$ where $N$ is the side length of the grid. Each cell is visited a constant number of times.
- **Memory Complexity**: $O(N^2)$ for the heightmap storage.
- **Performance**: The algorithm is computationally inexpensive and suitable for real-time generation. The use of bitwise operations for wrapping can be faster than modulo arithmetic.
- **Strengths**: Simple to implement, produces fractal-like terrain, easy to parallelize (each step depends only on the previous step's values).
- **Limitations**: The resulting terrain is periodic (toroidal) due to the wrapping. The roughness is controlled by a single parameter `h`, which may not provide enough control for complex terrain features compared to noise-based methods.
- **When to use**: When a simple, structured heightmap is needed, or when toroidal wrapping is desired.
- **When not to use**: When non-periodic boundaries are required, or when more complex terrain features are needed.

## Background
The Diamond-Square algorithm was introduced by Michael F. Diamond and John F. Square in the context of terrain generation. It is a variation of the Midpoint Displacement algorithm. The specific implementation details provided in the sources are from an unofficial GitHub repository [S1, unofficial].
