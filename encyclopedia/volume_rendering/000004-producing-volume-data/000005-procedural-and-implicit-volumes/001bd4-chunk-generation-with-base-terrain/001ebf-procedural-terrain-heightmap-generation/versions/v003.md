# Procedural Terrain Heightmap Generation

Also called: FBM Heightmap Chunk Generation, Procedural World Generation

## Overview
Procedural Terrain Heightmap Generation creates voxel terrain chunks by sampling a 2D noise function to determine column heights, then filling solid blocks from a base level up to the computed height for each $(x,z)$ position within the chunk [S1, S2, unofficial]. It solves the problem of creating deterministic, pseudo-random terrain geometry by leveraging the property that a fixed input yields the same output, allowing terrain data to be preserved across frames without change [G]. It sets itself apart from [Procedural Terrain Feature Generation](2572-procedural-terrain-feature-generation.md) by focusing on continuous height variation rather than discrete feature placement, and from [Heightmap generation via circular displacements](5186-heightmap-generation-via-circular-displacements.md) by using gradient-based noise functions rather than radial displacement patterns [G].

## How it works
**Inputs:**
- Chunk coordinates $(cx, cz)$ defining the chunk's position in the world grid [S1, S2, unofficial].
- Chunk dimensions: width $W$, height $H$, depth $D$ (typically $16 \times 64 \times 16$ blocks) [S2, unofficial].
- Noise generator state initialized with a seed, frequency, and noise type (e.g., OpenSimplex2) [S2, unofficial].
- Optional: Image files for heightmap and colormap sampling [S3, unofficial].

**Outputs:**
- A 3D voxel array `block_data` of size $W \times H \times D$, where each element is an integer representing the block type (0: air, 1: grass, 2: dirt, 3: stone, 4: water) [S1, S2, unofficial].

**Data Structures:**
- `block_data`: A 3D array indexed as `block_data[x][y][z]` with layout $[W][H][D]$ [S2, unofficial].
- `noise_state`: Holds parameters for the noise function, including `seed`, `frequency`, and `noise_type` [S2, unofficial].

**Steps:**

1. **Initialize Data:** Set all entries in `block_data` to 0 (air) [S2, unofficial].
2. **Iterate Chunk Grid:** Loop through each column position $(x, z)$ where $x \in [0, W-1]$ and $z \in [0, D-1]$ [S1, S2, unofficial].
3. **Calculate World Coordinates:** Compute the world-space coordinates for the current column:
   $$ wx = cx \times W + x $$
   $$ wz = cz \times D + z $$
   [S1, S2, unofficial].
4. **Sample Noise for Height:**
   - **Method A (Noise Function):** Sample the 2D noise function at $(wx, wz)$ scaled by frequency [S1, S2, unofficial]. Apply fractal Brownian motion (FBM) if required [S1, unofficial]. Scale the result and offset it to fit the desired height range [S1, S2, unofficial].
     $$ h = \lfloor \text{fbm}(wx / 80, wz / 80) \times 60 \rfloor + 60 $$
     Where 80 is the scale divisor, 60 is the multiplier, and 60 is the offset [S1, unofficial]. Alternatively, using a normalized noise output $n \in [-1, 1]$, scale by 4 and add 5, then cast to int [S2, unofficial].
   - **Method B (Image Sampling):** If using image-based generation, calculate pixel indices from $(x, z)$ relative to the image grid size, extract the grayscale value, and map it to a height scale [S3, unofficial].
5. **Fill Voxel Column:**
   - For $y$ from 0 to $h$:
     - If $y == h$: Set `block_data[x][y][z]` to 1 (grass) [S1, unofficial].
     - Else if $y > h - 4$: Set `block_data[x][y][z]` to 2 (dirt) [S1, unofficial].
     - Else: Set `block_data[x][y][z]` to 3 (stone) [S1, unofficial].
   - For $y$ from $h + 1$ to $H_{water}$ (e.g., 70):
     - Set `block_data[x][y][z]` to 4 (water) [S1, unofficial].
   - For $y > H_{water}$: Leave as 0 (air) [S1, unofficial].
6. **Edge Cases:** If using image sampling, handle CORS restrictions by falling back to mathematical terrain generation (e.g., using `Math.sin` and `Math.cos`) [S3, unofficial]. Clamp computed height to chunk vertical bounds to prevent out-of-bounds writes [G].

**Pseudocode:**

```python
import math

def noise_2d(x, y):
    """Simple pseudo-random 2D noise returning values in [-1, 1]."""
    return (math.sin(x * 12.9898 + y * 78.233) * 43758.5453 % 1.0) * 2.0 - 1.0

def fbm(x, y, octaves=3, persistence=0.5, lacunarity=2.0):
    """Simple 3-octave fractal Brownian motion returning values in [-1, 1]."""
    value = 0.0
    amplitude = 1.0
    frequency = 1.0
    for _ in range(octaves):
        value += amplitude * noise_2d(x * frequency, y * frequency)
        amplitude *= persistence
        frequency *= lacunarity
    return value

def generate_chunk(cx, cz, chunk_width, chunk_height, chunk_depth, water_level=70):
    # Initialize block data with air (0)
    block_data = [[[0 for z in range(chunk_depth)] for y in range(chunk_height)] for x in range(chunk_width)]
    
    # Iterate over each column in the chunk
    for x in range(chunk_width):
        for z in range(chunk_depth):
            # Calculate world coordinates
            wx = cx * chunk_width + x
            wz = cz * chunk_depth + z
            
            # Sample noise to get height
            noise_val = fbm(wx / 80.0, wz / 80.0)
            h = int(math.floor(noise_val * 60)) + 60
            
            # Clamp height to chunk bounds to prevent out-of-bounds writes [G]
            h = max(0, min(h, chunk_height - 1))
            
            # Fill the column
            for y in range(chunk_height):
                if y <= h:
                    if y == h:
                        block_data[x][y][z] = 1  # Grass
                    elif y > h - 4:
                        block_data[x][y][z] = 2  # Dirt
                    else:
                        block_data[x][y][z] = 3  # Stone
                elif y <= water_level:
                    block_data[x][y][z] = 4  # Water
                else:
                    block_data[x][y][z] = 0  # Air
                    
    return block_data
```

**Parameters:**
- `chunk_width`, `chunk_height`, `chunk_depth`: Dimensions of the chunk in blocks. Typical values: $16 \times 64 \times 16$ [S2, unofficial].
- `noise.frequency`: Controls terrain roughness/scale. Typical value: $0.025$ [S2, unofficial].
- `noise.noise_type`: The algorithm used for noise generation. Typical value: `OPENSIMPLEX2` [S2, unofficial].
- `water_level`: The Y-coordinate above which air is generated and below which water is generated if the terrain height is lower. Typical value: $70$ [S1, unofficial].

## Subtopics

### [Terrain Generation via Noise](2412-terrain-generation-via-noise.md)
Terrain Generation via Noise generates a 3D voxel volume from a 2D noise heightmap, extruding terrain-like structures into voxel space. It solves the problem of creating deterministic, pseudo-random terrain geometry by leveraging the property that a fixed input yields the same output, allowing terrain data to be preserved across frames without change. It sets itself apart from [Procedural Terrain Feature Generation](2572-procedural-terrain-feature-generation.md) by focusing on continuous height variation rather than discrete feature placement, and from [Heightmap generation via circular displacements](5186-heightmap-generation-via-circular-displacements.md) by using gradient-based noise functions rather than radial displacement patterns [G].

### [Procedural Terrain Feature Generation](2572-procedural-terrain-feature-generation.md)
Procedural Terrain Feature Generation is a method for creating specific volumetric structures, primarily cliffs and overhangs, by approximating their topology as a bicubic Bézier surface combined with a parabolic plateau function. It produces local delta values (additive blending) applied directly to volumetric data, allowing for nondestructive editing where parameters can be adjusted and transformations applied before surface extraction. It differs from general noise-based terrain generation by focusing on explicit geometric primitives for sharp features rather than stochastic displacement.

### [Heightmap generation via circular displacements](5186-heightmap-generation-via-circular-displacements.md)
This method generates a procedural terrain heightmap by iteratively applying overlapping circular displacement functions to a flat vertex grid. It solves the problem of creating varied, organic-looking terrain geometry without relying on frequency-domain noise synthesis. Unlike [Terrain Generation via Noise](2412-terrain-generation-via-noise.md), which uses continuous scalar fields, this approach constructs height by accumulating discrete, localized circular perturbations defined by random centers, radii, and signs [G].

### Terrain Generation via Image Sampling
A method to dictate voxel Y-axis height and vertex colors by extracting raw pixel arrays from 2D .png files (grayscale heightmap and RGB colormap) using `getImageData()` [S3, unofficial]. It loads heightmap and colormap images, extracts pixel data, and iterates through the grid to calculate world positions, Y scales, and colors based on pixel values [S3, unofficial]. If local image sampling fails due to CORS restrictions, the engine falls back to a mathematical terrain generation using `Math.sin` and `Math.cos` [S3, unofficial].

### Cliffs Layer
A terrain layer that creates escarpments by stepping into terraces of a specific height, joined by cliffs over the last portion of each step [S4, unofficial]. Implementation uses integer terracing in 32 bits, identical on CPU (`landform::terrace`) and GPU (`landform_terrace`), with the riser share riding in the stack layer's kind bits [S4, unofficial]. A boundary pitfall is that a terrace moves a height by less than a step and is not Lipschitz, so each level's margin grows by two steps to contain it [S4, unofficial].

### Smooth Terrain Grid
Generates a terrain grid with smoothed heights using interpolation between random sample points [S5, unofficial]. It validates the interval (setting it to 2 if $\le 0$ or odd), generates sample vertices at specific indices, assigns random heights, and generates in-between vertices by averaging neighbors [S5, unofficial]. Quads are split diagonally based on vertex parity (top-left to bottom-right for same-parity, top-right to bottom-left for opposite-parity) [S5, unofficial]. The `interval` parameter controls the spacing between random sample points and must be even and positive [S5, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \times H \times D)$ per chunk, where $W, H, D$ are chunk dimensions [G]. The noise sampling is $O(1)$ per column, and filling the column is $O(H)$ [G].
- **Memory Complexity:** $O(W \times H \times D)$ to store the voxel data [G].
- **Measured Performance:** Not given in the sources [G].
- **Scaling:** Performance scales linearly with chunk size [G]. Larger chunks require more memory and computation but reduce overhead from chunk management [G].
- **Strengths:** Deterministic output, simple implementation, efficient for generating large, continuous terrains [G].
- **Limitations:** Limited to heightmap-based terrain, may not support complex overhangs or caves without additional layers (e.g., [Procedural Cave Generation](2579-procedural-cave-generation.md)) [G].
- **When to Use:** Ideal for open-world games or simulations requiring vast, consistent landscapes [G].
- **When Not to Use:** When complex, non-heightmap-based features (e.g., caves, intricate structures) are required [G].

## Background
Procedural terrain generation using noise functions has been a staple in computer graphics and game development for decades [G]. The specific implementation described here, using FBM and OpenSimplex2 noise, is commonly found in indie voxel engine tutorials and open-source projects [S1, S2, S3, S4, S5, unofficial]. The use of image sampling for terrain generation is a technique employed in WebGL-based voxel engines to allow for artist-defined landscapes [S3, unofficial].
