# Heightmap generation via circular displacements

Also called: Circular displacement heightmap, Cosine-based terrain displacement

## Overview
This method generates a procedural terrain heightmap by iteratively applying overlapping circular displacement functions to a flat vertex grid. It solves the problem of creating varied, organic-looking terrain geometry without relying on frequency-domain noise synthesis. Unlike [Terrain Generation via Noise](2412-terrain-generation-via-noise.md), which uses continuous scalar fields, this approach constructs height by accumulating discrete, localized circular perturbations defined by random centers, radii, and signs.

## How it works

### Inputs and outputs
**Inputs:**
- Grid dimensions: `MAP_SIZE` (world units), `MAP_NUM_VERTICES` (vertices per side).
- Displacement parameters: `MAX_CIRCLE_SIZE`, `MAX_DISPLACEMENT`, `DISPLACEMENT_SIGN_LIMIT`, `MAX_ITER`.
- Random number generator state.

**Outputs:**
- A 2D grid of vertices `map_vertices` with layout `[3][MAP_NUM_VERTICES][MAP_NUM_VERTICES]` (or flattened equivalent), where index 1 represents the height ($y$).
- A list of triangle indices defining the mesh topology.

### Data structures
The vertex buffer is a 3-component array per vertex. The source code uses a layout `map_vertices[component][vertex_index]`.
- `map_vertices[0]`: x-coordinate.
- `map_vertices[1]`: y-coordinate (height).
- `map_vertices[2]`: z-coordinate.

The index buffer is generated once to define a fan-like triangulation of the grid cells.

### Parameters
Typical values from the reference implementation [S1, unofficial]:
- `MAP_SIZE = 10.0f`
- `MAP_NUM_VERTICES = 80`
- `MAX_CIRCLE_SIZE = 5.0f`
- `MAX_DISPLACEMENT = 1.0f`
- `DISPLACEMENT_SIGN_LIMIT = 0.3f`
- `MAX_ITER = 200`
- `NUM_ITER_AT_A_TIME = 1`

### Steps

1. **Initialize Grid:** Create a flat grid of `MAP_NUM_VERTICES` vertices.
   - Spacing: $s = \frac{MAP\_SIZE}{MAP\_NUM\_VERTICES - 1}$.
   - For each vertex $i$ in row-major order (row $r$, col $c$):
     - $x = c \cdot s$
     - $z = r \cdot s$
     - $y = 0.0$
2. **Generate Indices:** Create triangle indices for the grid.
   - Close top edge and right edge connections if required by the specific mesh topology (source notes mention closing edges, but standard grid triangulation usually implies internal cells).
   - For each cell $(i, j)$ where $0 \le i < MAP\_NUM\_VERTICES - 1$ and $0 \le j < MAP\_NUM\_VERTICES - 1$:
     - Let $ref = i \cdot MAP\_NUM\_VERTICES + j$.
     - Add indices for the triangle formed by $(ref, ref+1, ref+MAP\_NUM\_VERTICES)$ and $(ref+1, ref+MAP\_NUM\_VERTICES+1, ref+MAP\_NUM\_VERTICES)$? The source notes specify: "add indices for (ref, ref+1), (ref, ref+MAP_NUM_VERTICES), (ref, ref+MAP_NUM_VERTICES+1)". This describes a fan from the top-left corner of the cell, or potentially a specific triangulation pattern. Standard implementation usually creates two triangles per quad. The note lists 3 indices, implying a single triangle or a specific fan structure. Given "grid fan", it likely implies a specific connectivity. We will assume standard quad-to-triangle conversion unless "fan" implies a specific radial structure from a center, but the context "for each cell" suggests local triangulation. The source explicitly lists three index tuples. We will implement the addition of these indices as described.
3. **Iterative Displacement:** Repeat `MAX_ITER` times:
   - **Generate Circle Parameters:**
     - $center\_x = \text{random}([0, MAP\_SIZE])$
     - $center\_z = \text{random}([0, MAP\_SIZE])$
     - $circle\_size = \text{random}([0, MAX\_CIRCLE\_SIZE])$
     - Determine sign: if $\text{random}([0, 1]) < DISPLACEMENT\_SIGN\_LIMIT$, then $sign = -1.0$, else $sign = 1.0$.
     - $disp = sign \cdot (MAX\_DISPLACEMENT \cdot \text{random}([0, 1]))$
   - **Apply Displacement:** For each vertex $v$ at $(x_v, y_v, z_v)$:
     - Compute distance components: $dx = center\_x - x_v$, $dz = center\_z - z_v$.
     - Compute normalized distance parameter $pd$:
       $$pd = \frac{2 \sqrt{dx^2 + dz^2}}{circle\_size}$$
     - If $|pd| \le 1.0$:
       - Compute height change:
         $$new\_height = disp + \cos(pd \cdot \pi) \cdot disp$$
         Simplified: $new\_height = disp \cdot (1 + \cos(pd \cdot \pi))$
       - Update height: $y_v \leftarrow y_v + new\_height$

### Pseudocode

```python
import math
import random

def generate_heightmap(map_size, map_num_vertices, max_circle_size, max_displacement, displacement_sign_limit, max_iter):
    # 1. Initialize Grid
    spacing = map_size / (map_num_vertices - 1)
    # map_vertices layout: [3][num_vertices][num_vertices] -> [y][x][z] in source, 
    # but source uses map_vertices[component][vertex_index]. 
    # Let's use a list of vertex objects or flat arrays for clarity.
    # Source: map_vertices[0] is x, [1] is y, [2] is z.
    # Flattened index: ii = i * map_num_vertices + j
    
    num_vertices = map_num_vertices * map_num_vertices
    vertices_x = [0.0] * num_vertices
    vertices_y = [0.0] * num_vertices
    vertices_z = [0.0] * num_vertices
    
    for i in range(map_num_vertices):
        for j in range(map_num_vertices):
            idx = i * map_num_vertices + j
            vertices_x[idx] = j * spacing
            vertices_z[idx] = i * spacing
            vertices_y[idx] = 0.0
            
    # 2. Generate Indices (Grid Fan/Cell Triangulation)
    indices = []
    # Source notes: "close top edge, close right edge" - ambiguous, assuming standard internal cells
    # "for each cell (i, j)... add indices for (ref, ref+1), (ref, ref+MAP_NUM_VERTICES), (ref, ref+MAP_NUM_VERTICES+1)"
    # This looks like a specific triangulation. 
    for i in range(map_num_vertices - 1):
        for j in range(map_num_vertices - 1):
            ref = i * map_num_vertices + j
            # Triangle 1
            indices.append(ref)
            indices.append(ref + 1)
            indices.append(ref + map_num_vertices)
            # Triangle 2? The source lists 3 indices. A quad needs 2 triangles (6 indices).
            # The source note might be incomplete or describing a fan from a specific corner.
            # However, "grid fan" might imply a different topology. 
            # Given the ambiguity, we implement the explicit indices listed.
            # If this is a quad, we need a second triangle. 
            # Standard: (ref, ref+1, ref+map_num_vertices) and (ref+1, ref+map_num_vertices+1, ref+map_num_vertices)
            # The source lists: (ref, ref+1), (ref, ref+MAP_NUM_VERTICES), (ref, ref+MAP_NUM_VERTICES+1).
            # This forms a triangle (ref, ref+1, ref+map_num_vertices+1) and (ref, ref+map_num_vertices, ref+map_num_vertices+1)?
            # Let's stick to the explicit list: 
            # Triangle A: ref, ref+1, ref+map_num_vertices
            # Triangle B: ref, ref+map_num_vertices, ref+map_num_vertices+1
            # This covers the quad.
            indices.append(ref + 1)
            indices.append(ref + map_num_vertices)
            indices.append(ref + map_num_vertices + 1)

    # 3. Iterative Displacement
    for _ in range(max_iter):
        # Generate random circle parameters
        center_x = random.uniform(0, map_size)
        center_z = random.uniform(0, map_size)
        circle_size = random.uniform(0, max_circle_size)
        
        # Avoid division by zero
        if circle_size == 0:
            continue
            
        rand_val = random.random()
        if rand_val < displacement_sign_limit:
            sign = -1.0
        else:
            sign = 1.0
            
        disp = sign * (max_displacement * random.random())
        
        # Apply to all vertices
        for ii in range(num_vertices):
            dx = center_x - vertices_x[ii]
            dz = center_z - vertices_z[ii]
            
            # pd = 2 * sqrt(dx^2 + dz^2) / circle_size
            pd = (2.0 * math.sqrt(dx * dx + dz * dz)) / circle_size
            
            if abs(pd) <= 1.0:
                # new_height = disp + cos(pd * pi) * disp
                # new_height = disp * (1 + cos(pd * pi))
                new_height = disp * (1.0 + math.cos(pd * math.pi))
                vertices_y[ii] += new_height
                
    return vertices_x, vertices_y, vertices_z, indices
```

### Edge cases and pitfalls
- **Zero Circle Size:** If `circle_size` is 0, division by zero occurs in the calculation of $pd$. The implementation must skip or clamp such iterations [S1, unofficial].
- **Precision:** The use of `float` (32-bit) in the source code [S1, unofficial] may lead to precision issues in large terrains or with many iterations. Accumulating small displacements can result in drift or quantization artifacts.
- **Boundary Effects:** Vertices on the edge of the grid may receive fewer displacements if random centers are uniformly distributed within the grid bounds, potentially leading to slightly flatter edges.
- **Cosine Argument:** The formula uses $pd \cdot \pi$. Since $pd \in [0, 1]$ inside the circle, the argument is $[0, \pi]$. $\cos(0)=1 \implies new\_height = 2 \cdot disp$. $\cos(\pi)=-1 \implies new\_height = 0$. This creates a "dome" or "bowl" shape depending on the sign of `disp`.

## Operating characteristics

- **Time Complexity:** $O(MAX\_ITER \cdot N)$, where $N$ is the number of vertices. Each iteration scans all vertices.
- **Memory Complexity:** $O(N)$ for vertex storage and $O(N)$ for indices (constant factor).
- **Performance:** The method is CPU-bound due to the per-vertex loop in each iteration. For `MAP_NUM_VERTICES = 80` ($N=6400$) and `MAX_ITER = 200`, the total operations are roughly $1.28 \times 10^6$ distance calculations. This is fast on modern CPUs.
- **Strengths:** Simple to implement; produces organic, varied terrain; no frequency tuning required.
- **Limitations:** The resulting terrain is not stationary (changes with each generation); lacks large-scale structural control compared to noise-based methods; edges may be less detailed.

## Background

This method originates from the `voxel-engine` project by EmaMaker [S1, unofficial]. It is used in the context of procedural chunk generation for voxel-based games, specifically as a base terrain layer before further feature generation. It serves as an alternative to noise-based heightmaps, offering a different aesthetic and computational profile.
