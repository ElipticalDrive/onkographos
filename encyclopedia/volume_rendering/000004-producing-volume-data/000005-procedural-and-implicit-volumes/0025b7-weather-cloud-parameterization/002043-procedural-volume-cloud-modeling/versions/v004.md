# Procedural Volume Cloud Modeling

Also called: Cloud Density Field Generation, Density Sampling and Weather

## Overview
Procedural Volume Cloud Modeling generates a volumetric density field for clouds by evaluating mathematical noise functions and physical parameters at arbitrary points in space, rather than relying on pre-baked voxel grids or static distance fields [S1, S2, unofficial]. It solves the problem of creating infinite, high-resolution cloud structures that can be animated and varied dynamically without storing massive 3D textures [S2, unofficial]. Unlike [Volumetric Cloud Raymarching](1248-volumetric-cloud-raymarching.md), which focuses on the integration of light through an existing density field, this method defines the density itself. It differs from [Atmospheric Height Gradient](4813-atmospheric-height-gradient.md) by incorporating spatial noise and weather maps to create localized cloud structures rather than just global vertical attenuation [S1, S2, unofficial].

## How it works
**Inputs:**
*   World-space position $P = (x, y, z)$ [S1, S2, unofficial].
*   Time $t$ for animation [S1, S2, unofficial].
*   Wind vectors $\vec{w}$ for erosion and flow [S1, S2, unofficial].
*   Cloud Map texture $T_{cloud}$ (2D, RGBA) [S2, unofficial].
*   Cloud Lut texture $T_{lut}$ (2D, RGB) [S2, unofficial].
*   Noise textures: Base Shape Noise $T_{shape}$ (3D, Perlin-Worley) and Detail Noise $T_{detail}$ (3D, Perlin) [S1, S2, unofficial].

**Outputs:**
*   Cloud density $\rho$ at point $P$ [S1, S2, unofficial].
*   Optional: Cloud type, wetness, and erosion factors for shading [S2, unofficial].

**Data Structures:**
1.  **Cloud Map ($T_{cloud}$):** A 2D texture where channels store:
    *   R: Cloud Coverage [S2, unofficial].
    *   G: Cloud Type (0.0–1.0) [S2, unofficial].
    *   B: Cloud Erosion [S2, unofficial].
    *   A: Cloud Wetness [S2, unofficial].
2.  **Cloud Lut ($T_{lut}$):** A 2D texture defining distribution of cloud types and heights. Channels store:
    *   R: Density [S2, unofficial].
    *   G: Erosion [S2, unofficial].
    *   B: Ambient Occlusion [S2, unofficial].
3.  **Noise Textures:** Must be tileable [S2, unofficial]. $T_{shape}$ uses fractal Perlin-Worley noise; $T_{detail}$ uses fractal Perlin noise [S1, S2, unofficial].

**Algorithm Steps:**

1.  **Height Gradient Attenuation:**
    Calculate vertical attenuation to enforce flat cloud bases and rounded tops. Let $y$ be the height relative to the cloud layer base. Apply a remap function $H(y)$ [S1, unofficial].
    *   *Note:* Specific remap functions are not detailed in sources, but typically involve a smoothstep or sigmoid function that is 0 below the base and decays above the top [G].

2.  **Weather Map Sampling:**
    Sample the 2D Cloud Map $T_{cloud}$ using horizontal coordinates $(x, z)$ scaled to the map's resolution. Retrieve Coverage ($C$), Type ($Type$), Erosion ($E_{map}$), and Wetness ($W$) [S1, S2, unofficial].

3.  **Base Noise Sampling (Shape):**
    Sample the primary 3D Perlin-Worley noise texture $T_{shape}$ using low-frequency coordinates to generate the basic cloud shape. Coordinates are tiled across kilometers [S1, S2, unofficial].
    $$ N_{shape} = \text{Sample}(T_{shape}, P \cdot \text{Scale}_{shape}) $$

4.  **Cloud Type Mapping:**
    Map the sampled $Type$ value to specific cloud layers to adjust density and erosion parameters [S2, unofficial]:
    *   $0.0 \le Type < 0.125$: Cirrus (High altitude, low coverage, high erosion) [S2, unofficial].
    *   $0.125 \le Type < 0.25$: Cirrus + Cumulus [S2, unofficial].
    *   $0.25 \le Type < 0.5$: Cumulus [S2, unofficial].
    *   $0.5 \le Type \le 1.0$: Cumulonimbus (Low altitude, high coverage, low erosion) [S2, unofficial].
    *   *Note:* For complex shapes like Cumulonimbus, coverage and erosion are adjusted based on height: high altitude has low coverage and high erosion; low altitude has high coverage and low erosion [S2, unofficial].

5.  **Erosion (Detail):**
    Sample the secondary Worley noise texture $T_{detail}$, scaled up by frequency, to erode the edges of the base shape. This is driven by wind vectors $\vec{w}$ and time $t$ [S1, S2, unofficial].
    $$ N_{detail} = \text{Sample}(T_{detail}, P \cdot \text{Scale}_{detail} + \vec{w} \cdot t) $$
    The erosion factor $E$ is derived from $N_{detail}$ and the $E_{map}$ from the Cloud Map [S1, S2, unofficial].

6.  **Density Composition:**
    Combine the shape noise, erosion, and weather map values to compute final density.
    *   *Pitfall:* The Cloud Lut G channel (Erosion) affects both detail noise and shape noise calculations [S2, unofficial].
    $$ \rho = C \cdot N_{shape} \cdot (1 - E) \cdot H(y) $$
    *Note:* Exact weighting of Lut channels vs. Map channels is implementation-specific, but Lut provides density/erosion/AO multipliers [S2, unofficial].

**Pseudocode:**

```python
def SampleCloudDensity(P, t, wind, T_cloud, T_lut, T_shape, T_detail):
    # 1. Height Gradient
    # Assuming P.y is height relative to cloud base
    height_factor = HeightRemap(P.y) 
    
    # 2. Weather Map Sampling
    # Map world XZ to 2D UV for Cloud Map
    uv_cloud = WorldToCloudUV(P.x, P.z)
    cloud_data = SampleTexture2D(T_cloud, uv_cloud)
    coverage = cloud_data.r
    cloud_type = cloud_data.g
    erosion_map = cloud_data.b
    wetness = cloud_data.a
    
    # 3. Base Noise Sampling
    # Low frequency for large scale
    shape_uv = P * ShapeScale
    # Add wind/time for global flow if needed
    shape_uv += wind.xy * t * ShapeFlowSpeed
    noise_shape = SampleTexture3D(T_shape, shape_uv)
    
    # 4. Cloud Type Adjustment
    # Adjust coverage and erosion based on type and height
    if cloud_type < 0.125:
        # Cirrus
        coverage *= 0.3
        erosion_map *= 1.5
    elif cloud_type < 0.5:
        # Cumulus
        coverage *= 0.8
        erosion_map *= 1.0
    else:
        # Cumulonimbus
        coverage *= 1.2
        erosion_map *= 0.5
        
    # Height-based adjustment for complex shapes
    if P.y > HighAltitudeThreshold:
        coverage *= 0.5
        erosion_map *= 1.2
    else:
        coverage *= 1.0
        erosion_map *= 0.8
        
    # 5. Erosion (Detail Noise)
    # High frequency for detail
    detail_uv = P * DetailScale
    detail_uv += wind.xy * t * DetailFlowSpeed
    noise_detail = SampleTexture3D(T_detail, detail_uv)
    
    # Combine erosion from map and detail noise
    # Pitfall: Lut G channel (Erosion) affects both
    lut_data = SampleTexture2D(T_lut, vec2(cloud_type, P.y))
    erosion_lut = lut_data.g
    erosion = 1.0 - (noise_detail * erosion_map * erosion_lut)
    
    # 6. Final Density
    density = coverage * noise_shape * erosion * height_factor
    
    return density
```

## Subtopics

### [IsimCloudTexture density evaluation](3530-isimcloudtexture-density-evaluation.md)
IsimCloudTexture density evaluation computes the volumetric density of a cloud at a given point in space by combining geometric primitives (text segments or implicit cloud bodies), fractal Brownian motion (FBM) noise, and depth-based fading. It differs from general procedural gas modeling by focusing on specific cloud structures (text-based or layered bodies) and from simple cloud density sampling by generating the density field procedurally via CUDA kernels rather than sampling pre-baked data. The method outputs a grayscale density value (replicated to RGB) suitable for volume rendering.

### [Procedural Gas Modeling via Turbulence](3551-procedural-gas-modeling-via-turbulence.md)
Procedural Gas Modeling via Turbulence is a method for generating volumetric gas density by evaluating a turbulence function and mapping the result through a precomputed power table. It solves the problem of efficiently computing realistic gas density fields for volume rendering by replacing expensive per-sample power function calls with a lookup table. Unlike sibling methods that may rely on 3D textures or distance fields, this approach computes density analytically at any point in space using mathematical shaping functions.

### [Cloud Density Sampling](4806-cloud-density-sampling.md)
Cloud Density Sampling generates the base volumetric density of clouds by combining low-frequency 3D noise textures using a weighted sum (Fractal Brownian Motion, FBM) and remapping the result to control cloud shape and coverage. It differs from its siblings by explicitly separating the generation of the base cloud structure (via low-frequency textures and height gradients) from high-frequency detail (via curl noise displacement and high-frequency textures) and by using a specific channel-weighted FBM from a single RGBA texture sample rather than procedural noise functions. It builds on [Procedural Volume Cloud Modeling](2256-procedural-volume-cloud-modeling.md) by providing the specific evaluation routine for the density field.

### Cumulus Cloud Rendering Configuration
Uses $N = 2$, $M = 32$, and 5 octaves of Perlin noise to simulate enhanced cumulus cloud, with a virtual resolution of $2048^3$ [S3, unofficial]. Used to encode cloud details in [BNM* 08] for multiple scattering in clouds [S3, unofficial].

### Physical Cloud Model (Cumulus Convection)
A physical model where a constant heat source is applied at the base, representing sunlight heating the earth [S4, unofficial]. Evaporation occurs until air is saturated or all liquid water is evaporated [S4, unofficial]. The saturation mixing ratio is defined by $q_s = A \exp(-\alpha z)$ [S4, unofficial]. The liquid water mixing ratio is $q_l = \max(q - q_s, 0)$ [S4, unofficial]. Parameters include Latent heat of vaporization $L_v$, Specific heat of air $c_p$, and Friction timescale $t_s$ [S4, unofficial]. Boundary conditions are $q_0 = 0.02$ at the bottom level and $q_0 = 0.002$ at the top level [S4, unofficial]. Coriolis effects are ignored for computational efficiency [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, as it involves texture lookups and noise evaluations. However, high-frequency noise and multiple octaves increase the constant factor [S3, unofficial].
*   **Memory Complexity:** Low. Only requires storing 2D/3D noise textures and small 2D lookup tables (Cloud Map, Cloud Lut), unlike voxel-based methods which require $O(N^3)$ memory [S2, S3, unofficial].
*   **Performance:** Frame rates can be low (e.g., ~20 FPS for $1024^3$ volume) if complex computations are performed on the GPU without optimization [S3, unofficial]. On-the-fly noise creation on the GPU is more efficient than CPU evaluation and transfer [S3, unofficial].
*   **Strengths:** Infinite resolution, no storage limits for volume size, easy animation via time-based coordinate offsets [S2, unofficial].
*   **Limitations:** Requires careful tuning of noise parameters; performance degrades with high-frequency detail and multiple scattering calculations [S3, unofficial].

## Background
Procedural volume cloud modeling emerged as a solution to the memory and resolution limitations of voxel-based cloud rendering. Early methods relied on 3D textures storing density or distance fields [S2, unofficial]. The approach described here, particularly the use of Perlin-Worley noise and Cloud Maps, is heavily influenced by Unity HDRP's volumetric cloud implementation [S2, unofficial]. Physical models, such as the cumulus convection model by [S4, unofficial], provide a theoretical basis for density generation based on thermodynamic principles, though procedural noise methods are more common in real-time graphics due to performance [S4, S2, unofficial].
