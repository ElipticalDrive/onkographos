# Procedural Volume Cloud Modeling

Also called: Cloud Density Field Generation, Density Sampling and Weather

## Overview
Procedural Volume Cloud Modeling constructs the volumetric density field of clouds by evaluating mathematical functions at arbitrary points in space, primarily using 3D noise textures or procedural noise functions [S1, S2, unofficial]. It solves the problem of generating infinite-resolution, coherent cloud geometry without relying on pre-baked voxel grids or static meshes [S2, unofficial]. It differs from [Volumetric Cloud Raymarching](1248-volumetric-cloud-raymarching.md) by focusing on the *generation* of the density function rather than the integration of light through it, and from [Atmospheric Height Gradient](4813-atmospheric-height-gradient.md) by incorporating multi-channel weather maps and specific cloud-type logic [S1, S2, unofficial].

## How it works
**Inputs:**
*   World-space position $P$.
*   Time $t$ and wind velocity vectors $V_{global}, V_{detail}$.
*   Cloud Map: A 2D texture (RGBA) storing Coverage, Type, Erosion, and Wetness [S2, unofficial].
*   Cloud Lut: A texture defining distribution of cloud types and heights, with RGB channels storing Density, Erosion, and Ambient Occlusion [S2, unofficial].
*   Noise Textures: Tileable 3D textures for Shape Noise (Fractal Perlin-Worley) and Detail Noise (Fractal Perlin) [S2, unofficial].

**Outputs:**
*   Scalar density value $\rho(P)$ at point $P$.

**Data Structures:**
*   **Cloud Map:** 2D texture.
    *   R: Cloud Coverage (0.0–1.0) [S2, unofficial].
    *   G: Cloud Type (0.0–1.0) [S2, unofficial].
    *   B: Cloud Erosion (0.0–1.0) [S2, unofficial].
    *   A: Cloud Wetness (0.0–1.0) [S2, unofficial].
*   **Cloud Lut:** Texture.
    *   R: Density [S2, unofficial].
    *   G: Erosion [S2, unofficial].
    *   B: Ambient Occlusion [S2, unofficial].

**Steps:**

1.  **Height Gradient Attenuation:**
    Calculate the vertical position relative to the cloud layer base $H_{base}$ and top $H_{top}$. Apply a vertical remap function to enforce flat cloud bases and rounded tops [S1, unofficial].
    $$
    h_{norm} = \text{clamp}\left(\frac{P_y - H_{base}}{H_{top} - H_{base}}, 0.0, 1.0\right)
    $$
    $$
    H_{fade} = \text{smoothstep}(0.0, 0.1, h_{norm}) \times (1.0 - \text{smoothstep}(0.9, 1.0, h_{norm}))
    $$
    [G] `smoothstep` is the standard Hermite interpolation: $3t^2 - 2t^3$.

2.  **Weather Map Sampling:**
    Sample the 2D Cloud Map at the projected horizontal coordinates of $P$ (typically $P_x, P_z$ or UVs derived from world position) to retrieve Coverage ($C$), Type ($T$), Erosion ($E_{map}$), and Wetness ($W$) [S1, S2, unofficial].

3.  **Base Noise Sampling (Shape):**
    Sample the primary 3D Shape Noise texture using low-frequency coordinates to tile across kilometers. The coordinates are offset by global wind and time [S1, S2, unofficial].
    $$
    N_{shape} = \text{SamplePerlinWorley}(P \cdot S_{shape} + V_{global} \cdot t)
    $$
    where $S_{shape}$ is the shape noise scale [S1, unofficial].

4.  **Erosion (Detail):**
    Sample the secondary 3D Detail Noise texture (Fractal Perlin) scaled up by frequency. This noise erodes the edges of the base shape based on wind vectors and time [S1, unofficial].
    $$
    N_{detail} = \text{SamplePerlin}(P \cdot S_{detail} + V_{detail} \cdot t)
    $$
    [S2, unofficial] notes that the Cloud Lut G channel (Erosion) affects both detail noise and shape noise calculations.

5.  **Cloud Type and Layer Logic:**
    Map the Cloud Type $T$ to specific cloud layers. The following mapping is standard [S2, unofficial]:
    *   $0.0 \le T < 0.125$: Cirrus (High altitude, low coverage, high erosion)
    *   $0.125 \le T < 0.25$: Cirrus + Cumulus
    *   $0.25 \le T < 0.5$: Cumulus
    *   $0.5 \le T \le 1.0$: Cumulonimbus (Low altitude, high coverage, low erosion)
    
    For complex shapes like Cumulonimbus, adjust noise coverage and erosion based on height: high altitude has low coverage and high erosion; low altitude has high coverage and low erosion [S2, unofficial].

6.  **Density Composition:**
    Combine the sampled values. The final density $\rho$ is typically a product of the height fade, coverage, shape noise, and erosion factors.
    $$
    \rho = H_{fade} \cdot C \cdot N_{shape} \cdot (1.0 - E_{map} \cdot N_{detail})
    $$
    [G] The exact combination formula (additive vs multiplicative) varies by implementation; the above represents the common "erosion" model where detail noise subtracts from the base shape.

7.  **Output:**
    Return $\rho$. If RGB is required, replicate $\rho$ to all channels [S1, unofficial].

**Parameters:**
*   $S_{shape}$: Shape noise scale. Typical values depend on scene scale; must be low enough to tile seamlessly [S1, S2, unofficial].
*   $S_{detail}$: Detail noise scale. Higher frequency than shape noise [S1, unofficial].
*   $V_{global}$: Global wind velocity vector [S1, unofficial].
*   $V_{detail}$: Detail wind velocity vector [S1, unofficial].
*   $t$: Simulation time [S1, unofficial].

**Pitfalls:**
*   **Non-tilable Noise:** Noise textures must be tileable to avoid seams when tiling across kilometers [S2, unofficial].
*   **Lut Channel Confusion:** The Cloud Lut G channel (Erosion) influences both detail and shape noise calculations; misinterpreting this leads to incorrect cloud structures [S2, unofficial].
*   **Precision:** At very large scales, floating-point precision in world coordinates may cause noise artifacts; consider using local coordinates relative to a chunk or tile [G].

```python
def SampleCloudDensity(P, t, V_global, V_detail, CloudMap, CloudLut, ShapeNoise, DetailNoise):
    # 1. Height Gradient
    h_norm = clamp((P.y - H_base) / (H_top - H_base), 0.0, 1.0)
    H_fade = smoothstep(0.0, 0.1, h_norm) * (1.0 - smoothstep(0.9, 1.0, h_norm))
    
    # 2. Weather Map Sampling
    # Project P to 2D UVs for CloudMap (implementation depends on world-to-UV mapping)
    uv = get_cloud_map_uv(P)
    coverage, cloud_type, erosion_map, wetness = CloudMap.sample(uv)
    
    # 3. Base Noise Sampling
    shape_coord = P * ShapeScale + V_global * t
    noise_shape = SamplePerlinWorley(ShapeNoise, shape_coord)
    
    # 4. Erosion
    detail_coord = P * DetailScale + V_detail * t
    noise_detail = SamplePerlin(DetailNoise, detail_coord)
    
    # 5. Cloud Type Logic (Simplified)
    # Adjust coverage and erosion based on height and type
    if cloud_type > 0.5: # Cumulonimbus
        # High erosion at high altitude, low at low
        erosion_factor = erosion_map * (1.0 - h_norm) 
        coverage_factor = coverage * h_norm
    else:
        erosion_factor = erosion_map
        coverage_factor = coverage
        
    # Lut G channel (Erosion) affects both
    lut_erosion = CloudLut.sample(P).G
    erosion_factor *= lut_erosion
    
    # 6. Density Composition
    density = H_fade * coverage_factor * noise_shape * (1.0 - erosion_factor * noise_detail)
    
    return density
```

## Subtopics

### [IsimCloudTexture density evaluation](3530-isimcloudtexture-density-evaluation.md)
Computes volumetric density by combining geometric primitives (text segments or implicit cloud bodies), fractal Brownian motion (FBM) noise, and depth-based fading. It differs from general procedural gas modeling by focusing on specific cloud structures and from simple cloud density sampling by generating the density field procedurally via CUDA kernels rather than sampling pre-baked data. The method outputs a grayscale density value (replicated to RGB) suitable for volume rendering.

### [Procedural Gas Modeling via Turbulence](3551-procedural-gas-modeling-via-turbulence.md)
Generates volumetric gas density by evaluating a turbulence function and mapping the result through a precomputed power table. It solves the problem of efficiently computing realistic gas density fields by replacing expensive per-sample power function calls with a lookup table. Unlike sibling methods that may rely on 3D textures or distance fields, this approach computes density analytically at any point in space using mathematical shaping functions.

### [Cloud Density Sampling](4806-cloud-density-sampling.md)
Generates the base volumetric density of clouds by combining low-frequency 3D noise textures using a weighted sum (Fractal Brownian Motion, FBM) and remapping the result to control cloud shape and coverage. It differs from its siblings by explicitly separating the generation of the base cloud structure (via low-frequency textures and height gradients) from high-frequency detail (via curl noise displacement and high-frequency textures) and by using a specific channel-weighted FBM from a single RGBA texture sample rather than procedural noise functions. It builds on [Procedural Volume Cloud Modeling](2256-procedural-volume-cloud-modeling.md) by providing the specific evaluation routine for the density field.

### Cumulus Cloud Rendering Configuration
Uses $N=2$, $M=32$, and 5 octaves of Perlin noise to simulate enhanced cumulus clouds, with a virtual resolution of $2048^3$ [S3, unofficial]. Used to encode cloud details for multiple scattering calculations [S3, unofficial].

### Physical Cloud Model (Cumulus Convection)
Applies a constant heat source at the base of the model, representing sunlight heating the earth [S4, unofficial]. Evaporation occurs until air is saturated or all liquid water is evaporated [S4, unofficial]. The saturation mixing ratio is defined as $q_s = A \exp(-\alpha z)$ [S4, unofficial]. The liquid water mixing ratio is $q_l = \max(q - q_s, 0)$ [S4, unofficial]. Parameters include latent heat of vaporization $L_v$, specific heat of air $c_p$, and friction timescale $t_s$ [S4, unofficial]. Boundary conditions set $q_0 = 0.02$ at the bottom and $q_0 = 0.002$ at the top [S4, unofficial]. Coriolis effects are ignored for computational efficiency [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, as it involves a fixed number of noise evaluations and arithmetic operations [S1, S2, unofficial].
*   **Memory Complexity:** Depends on the storage of noise textures and Cloud Maps. 3D noise textures can be large, but procedural generation allows for on-the-fly evaluation if textures are not stored [S3, unofficial].
*   **Performance:** Real-time capable on PC/Console hardware when using optimized noise functions and tileable textures [S2, unofficial]. Frame rates can drop to ~20 FPS for high-resolution ($1024^3$) volumes if computed on CPU, but GPU evaluation is significantly faster [S3, unofficial].
*   **Strengths:** Infinite resolution, coherent geometry, easy control via weather maps, and efficient streaming [S1, S2, unofficial].
*   **Limitations:** Requires careful tuning of noise parameters to avoid artifacts; erosion logic can be complex to balance [S2, unofficial].

## Background
Originating from the need for realistic, real-time volumetric clouds in games and simulations, this method draws from early work on procedural noise [S1, S2, unofficial]. Unity HDRP 12.0 popularized the use of 3D Perlin-Worley noise for cloud modeling [S2, unofficial]. Physical models, such as those by [S4, unofficial], provide the thermodynamic basis for cumulus convection, though procedural methods often approximate these effects for performance.
