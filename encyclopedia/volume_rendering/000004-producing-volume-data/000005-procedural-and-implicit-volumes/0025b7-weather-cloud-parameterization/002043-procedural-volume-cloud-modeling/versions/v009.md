# Procedural Volume Cloud Modeling

Also called: Cloud Density Field Generation, Density Sampling and Weather

## Overview
Procedural Volume Cloud Modeling generates the volumetric density field of clouds by evaluating mathematical noise functions and physical parameters at arbitrary points in space, rather than sampling pre-baked 3D textures [S2, unofficial]. It solves the problem of constructing spatially coherent cloud layers with dynamic control over morphology, coverage, and erosion [S2, unofficial]. It differs from [Volumetric Cloud Raymarching](1248-volumetric-cloud-raymarching.md) by focusing on the generation of the density scalar field itself, whereas raymarching focuses on the integration of light through that field [G]. It differs from [Cloud Density Sampling](4806-cloud-density-sampling.md) by explicitly integrating wind skew, time-based movement, and specific channel-weighted Fractal Brownian Motion (FBM) calculations directly into the density evaluation step [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** World-space position $P$, time $t$, wind velocity vector $\vec{W}$, and a configuration structure containing global physical parameters (see Parent: [Weather & Cloud Parameterization](3617-weather-cloud-parameterization.md)) [S1, unofficial].
*   **Outputs:** A scalar density value $\rho \in [0, 1]$ [S1, unofficial].

**Data Structures:**
1.  **Cloud Map:** A 2D texture (4 channels RGBA) storing spatial attributes [S2, unofficial]:
    *   R: Cloud Coverage
    *   G: Cloud Type
    *   B: Cloud Erosion
    *   A: Cloud Wetness
2.  **Cloud Lut:** A texture defining the distribution of cloud types and heights [S2, unofficial]:
    *   R: Density
    *   G: Erosion
    *   B: Ambient Occlusion
3.  **Noise Textures:**
    *   **Shape Noise:** Fractal Perlin-Worley noise (Tileable) [S2, unofficial].
    *   **Detail Noise:** Fractal Perlin noise (Tileable) [S2, unofficial].

**Numbered Steps:**
1.  **Height Gradient Attenuation:** Attenuate the density using vertical remap functions to enforce flat cloud bases and rounded tops [S1, unofficial].
2.  **Weather Map Sampling:** Sample a 2D weather texture containing coverage, precipitation, and cloud-type attributes [S1, unofficial]. Map `cloudType` to specific layer behaviors: $0.0-0.125$ (Cirrus), $0.125-0.25$ (Cirrus+Cumulus), $0.25-0.5$ (Cumulus), $0.5-1.0$ (Cumulonimbus) [S2, unofficial].
3.  **Base Noise Sampling:** Sample the primary 3D Perlin-Worley texture using low coordinates (tiling across kilometers) [S1, unofficial].
4.  **Erosion and Detail:** Sample the secondary Worley noise texture, scaled up by frequency, to erode the edges of the base shape based on wind vectors and time [S1, unofficial]. For Cumulonimbus types, adjust coverage and erosion based on height: high altitude has low coverage and high erosion; low altitude has high coverage and low erosion [S2, unofficial].
5.  **Final Density Composition:** Combine the attenuated base density, weather coverage, and erosion results [S1, unofficial]. The Cloud Lut G channel (Erosion) affects both detail noise and shape noise calculations [S2, unofficial].

**Formulas:**
*   **Height Gradient:**
    $$ \rho_{height} = \text{Remap}(z, \text{baseHeight}, \text{baseHeight} + \text{thickness}) $$
    Where $\text{Remap}$ applies a vertical remap function to enforce flat cloud bases and rounded tops [S1, unofficial].
*   **Liquid Water Mixing Ratio (Physical Model Variant):**
    $$ q_l = \max(q - q_s, 0) $$
    Where $q$ is total water mixing ratio and $q_s$ is saturation mixing ratio [S3, unofficial].

**Parameters:**
*   `cloudType`: Float $[0, 1]$ that interpolates between cloud behaviors [S1, unofficial].
*   `baseHeight`: Vertical altitude of the cloud layer base [S1, unofficial].
*   `thickness`: Vertical extent of the layer [S1, unofficial].
*   `windX`, `windZ`: Horizontal wind velocity components used for advection of noise textures over time [S1, unofficial].
*   `coverage`: Float $[0, 1]$ that shifts the weather map's coverage threshold [S1, unofficial].
*   `erosion`: Controls how much detail noise erodes cloud edges [S1, unofficial].
*   `resolution`: Must be exactly 64, 128, or 256 if generating pre-baked textures [S2, unofficial].
*   `shape_strength`, `detail_strength`, `disturbance_strength`: Must be within $[0.0, 2.0]$ [S2, unofficial].

**Pitfalls:**
*   **Cloud Lut G Channel:** The Erosion value in the Cloud Lut G channel affects both detail noise and shape noise calculations, which can lead to unexpected over-erosion if not carefully balanced [S2, unofficial].
*   **Boundary Conditions:** For physical models, saturation mixing ratio $q_s$ follows $q_s = A \exp(-\alpha z)$ [S3, unofficial]. Boundary conditions are $q_0 = 0.02$ at the bottom and $q_0 = 0.002$ at the top [S3, unofficial].
*   **Coriolis Effects:** Ignored for computational efficiency in simple physical models [S3, unofficial].

**Pseudocode:**
```python
def SampleCloudDensity(world_pos, time, wind, config):
    # 1. Height Gradient Attenuation
    z = world_pos.y
    height_ratio = clamp((z - config.baseHeight) / config.thickness, 0.0, 1.0)
    # Vertical remap function to enforce flat cloud bases and rounded tops [S1, unofficial]
    height_factor = height_ratio * height_ratio * (3.0 - 2.0 * height_ratio)

    # 2. Weather Map Sampling
    # Sample 2D Cloud Map: R=Coverage, G=Cloud Type, B=Erosion, A=Wetness [S2, unofficial]
    # UV mapping uses world-space XZ coordinates scaled for tiling [S1, unofficial]
    uv = world_pos.xz * config.noise_scale_low
    weather = SampleCloudMap(uv)
    coverage = weather.r
    cloud_type = weather.g
    erosion = weather.b

    # Map cloud type to layer behavior [S2, unofficial]
    if cloud_type < 0.125:
        layer_type = "CIRRUS"
    elif cloud_type < 0.25:
        layer_type = "CIRRUS_CUMULUS"
    elif cloud_type < 0.5:
        layer_type = "CUMULUS"
    else:
        layer_type = "CUMULONIMBUS"

    # 3. Base Noise Sampling
    # Primary 3D Perlin-Worley texture using low coordinates (tiling across kilometers) [S1, unofficial]
    base_noise = EvaluateFractalPerlinWorley(world_pos.xz * config.noise_scale_low)
    # Apply coverage threshold
    density = 1.0 if base_noise >= (1.0 - coverage) else 0.0

    # 4. Erosion and Detail
    # Secondary Worley noise texture, scaled up by frequency, eroding edges based on wind vectors and time [S1, unofficial]
    advected_pos = world_pos.xz + wind.xz * time
    detail_noise = EvaluateFractalPerlin(advected_pos * config.noise_scale_high)

    # Apply erosion
    # Cloud Lut G channel (Erosion) affects both detail noise and shape noise calculations [S2, unofficial]
    erosion_factor = 1.0 - erosion
    density *= (1.0 - erosion_factor * detail_noise)

    # Cumulonimbus specific height-based adjustment [S2, unofficial]
    if layer_type == "CUMULONIMBUS":
        cumulo_height_ratio = (z - config.baseHeight) / config.thickness
        # High altitude: low coverage, high erosion; Low altitude: high coverage, low erosion
        height_coverage = 1.0 - cumulo_height_ratio
        height_erosion = cumulo_height_ratio
        density *= height_coverage
        density *= (1.0 - height_erosion * detail_noise)

    # 5. Final Density Composition: Combine the attenuated base density, weather coverage, and erosion results [S1, unofficial]
    final_density = density * height_factor * config.density_multiplier
    return final_density
```

## Subtopics

### [Cumulus Cloud Rendering Configuration](2897-cumulus-cloud-rendering-configuration.md)
This configuration defines the specific procedural noise parameters used to generate the density field for cumulus clouds within the Ray-Guided Streaming framework [2897-cumulus-cloud-rendering-configuration.md]. It serves as a concrete instantiation of procedural volume cloud modeling, specifically tailored to encode cloud details for multiple scattering simulations [2897-cumulus-cloud-rendering-configuration.md]. It differs from general gas modeling by focusing on the specific fractal noise parameters required for the distinct morphology of cumulus formations rather than generic turbulence [2897-cumulus-cloud-rendering-configuration.md]. When to choose it: Use when rendering cumulus formations that require precise fractal noise tuning for multiple scattering pipelines [2897-cumulus-cloud-rendering-configuration.md].

### [IsimCloudTexture density evaluation](3530-isimcloudtexture-density-evaluation.md)
IsimCloudTexture density evaluation computes the volumetric density of a cloud at a given point in space by combining geometric primitives (text segments or implicit cloud bodies), fractal Brownian motion (FBM) noise, and depth-based fading. It differs from general procedural gas modeling by focusing on specific cloud structures (text-based or layered bodies) and from simple cloud density sampling by generating the density field procedurally via CUDA kernels rather than sampling pre-baked data. The method outputs a grayscale density value (replicated to RGB) suitable for volume rendering. When to choose it: Use when hardware-accelerated CUDA evaluation of structured cloud bodies is required.

### [Procedural Gas Modeling via Turbulence](3551-procedural-gas-modeling-via-turbulence.md)
Procedural Gas Modeling via Turbulence generates volumetric gas density by evaluating a turbulence function and mapping the result through a precomputed power table. It solves the problem of efficiently computing realistic gas density fields for volume rendering by replacing expensive per-sample power function calls with a lookup table. When to choose it: Use when performance is critical and gas density requires fast power-table lookups instead of direct evaluation.

### [Cloud Density Sampling](4806-cloud-density-sampling.md)
Cloud Density Sampling generates the base volumetric density of clouds by combining low-frequency 3D noise textures using a weighted sum (Fractal Brownian Motion, FBM) and remapping the result to control cloud shape and coverage. It samples cloud density using low-frequency and high-frequency noise textures, applying height gradients, wind skew, and coverage masking. It differs from generic noise-based volume generation by integrating wind skew, time-based movement, and specific channel-weighted FBM calculations directly into the density evaluation step. When to choose it: Use when standard FBM-based cloud density generation with integrated wind and height masking is sufficient.

### [Finite Layer Cloud Shape Generation](8292-finite-layer-cloud-shape-generation.md)
Finite Layer Cloud Shape Generation is a procedural method for constructing the 3D volume shapes of stratiform cloud types (Cirrus, Altostratus, Nimbostratus, Stratocumulus, Stratus) by assembling a chain of connected 3D ellipsoidal lobes. It solves the problem of generating natural-looking cloud edges without degenerating into a simple extruded cylinder along the vertical Z-axis, which is a common artifact when using simple 2D contour extrusion. It differs from its sibling [Cumulonimbus and Cumulus Shape Generation](8296-cumulonimbus-and-cumulus-shape-generation.md), which uses hierarchical particle-based turbulence for convective shapes, by relying on deterministic geometric lobes with controlled vertical presence variation. When to choose it: Use when rendering stratiform cloud layers that require deterministic lobe assembly rather than particle turbulence.

### Physical Cloud Model (Cumulus Convection)
This variant models cumulus clouds using physical equations of convection rather than pure noise [S3, unofficial].
**Steps:**
1. Apply a constant heat source at the base of the model, representing sunlight heating the earth [S3, unofficial].
2. Evaporation occurs until air is saturated or all liquid water is evaporated [S3, unofficial].
**Formulas:**
*   Saturation mixing ratio: $q_s = A \exp(-\alpha z)$ [S3, unofficial].
*   Liquid water mixing ratio: $q_l = \max(q - q_s, 0)$ [S3, unofficial].
**Parameters:**
*   $L_v$: Latent heat of vaporization of water [S3, unofficial].
*   $c_p$: Specific heat of air at constant pressure [S3, unofficial].
*   $t_s$: Friction timescale [S3, unofficial].
*   Boundary conditions: $q_0 = 0.02$ at bottom level, $q_0 = 0.002$ at top level [S3, unofficial].
**Pitfalls:**
*   Coriolis effects are ignored for computational efficiency [S3, unofficial].

## Background
Procedural volume cloud modeling originated from the need to create realistic, dynamic clouds in real-time graphics [G]. Early methods relied on 3D textures, but procedural noise-based approaches became popular with the advent of more powerful GPUs and shader languages [S2, unofficial]. Unity HDRP 12.0 introduced a widely adopted procedural cloud modeling technique using Perlin-Worley noise [S2, unofficial]. The physical cloud model variant traces back to SIGGRAPH '84, which used a convective model to simulate cumulus clouds [S3, unofficial].
