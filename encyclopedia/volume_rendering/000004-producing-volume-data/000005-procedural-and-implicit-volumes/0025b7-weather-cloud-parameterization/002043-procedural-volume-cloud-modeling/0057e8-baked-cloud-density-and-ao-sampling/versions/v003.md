# Baked Cloud Density and AO Sampling

Also called: 3D Worley cell volume rendering, Baked Density and AO Sampling, Direct 3D Weather Volume Rendering with Analytical SDF, Direct 3D weather volume model, Minimal Cloud Density Function Optimization, calculateCloudDensityMinimal

## Overview
This method replaces procedural noise evaluation with precomputed 3D volume textures containing analytical cloud density and Signed Distance Fields (SDF) derived from tileable 3D Worley cells [S1, unofficial]. It solves the performance bottleneck of real-time procedural cloud rendering by baking physical density and local Ambient Occlusion (AO) into a 3D texture, allowing raymarchers to sample data directly [S2, unofficial]. Unlike its siblings [Cumulus Cloud Rendering Configuration](2897-cumulus-cloud-rendering-configuration.md), [IsimCloudTexture density evaluation](3530-isimcloudtexture-density-evaluation.md), [Procedural Gas Modeling via Turbulence](3551-procedural-gas-modeling-via-turbulence.md), [Cloud Density Sampling](4806-cloud-density-sampling.md), [Physical Cloud Model (Cumulus Convection)](6212-physical-cloud-model-cumulus-convection.md), and [Finite Layer Cloud Shape Generation](8292-finite-layer-cloud-shape-generation.md) that rely on procedural noise or 2D heightmaps, this approach uses horizontal tiling and full advection support for efficient space skipping [S1, unofficial].

## How it works
The method consists of two phases: Baking (precomputation) and Raymarching (runtime sampling) [S1, S2, unofficial].

### Inputs and Outputs
*   **Inputs:** Weather map coordinates, world scale (`props.worldScale`), cellular frequency (`freq = 4.0`), horizontal tile count (`uCloudVolumeTiles = 4.0`) [S1, unofficial].
*   **Outputs:** A 3D volume texture where:
    *   Alpha channel (`A`) stores analytical physical density [S1, unofficial].
    *   Blue channel (`B`) stores the 3D SDF [S1, unofficial].
    *   During the shadow bake pass, the B channel also stores shadow transmittance and AO [S2, unofficial].

### Data Structures
*   **3D Volume Texture:** Stores density and SDF [S1, unofficial].
*   **Properties (`props`):** Contains `worldScale` [S1, unofficial].

### Parameters
*   `uCloudVolumeTiles = 4.0`: Governs 3D horizontal texture coordinate wrapping [S1, unofficial].
*   `freq = 4.0`: Cellular frequency used for SDF scaling [S1, unofficial].
*   `SDF Multiplier = 0.4`: Conservative multiplier applied to `d3d` in sphere tracing step size computation [S1, unofficial].
*   `Max Step Cap = 2000.0 * props.worldScale`: Maximum skip step size per iteration [S1, unofficial].

### Steps

#### 1. Baking Analytical Density and SDF
The baking process evaluates analytical functions and writes them to the 3D texture [S1, unofficial].

1.  **Evaluate Analytical Cloud 3D:** Call `getAnalyticalCloud3D` at each voxel position [S1, unofficial]. This function evaluates tileable 3D Worley cells, 3D SDF, and physical density with vertical layer boundaries [S1, unofficial].
2.  **Scale SDF:** Inside `getAnalyticalCloud3D`, divide the cellular SDF value (`cell_sdf`) by the cellular frequency (`freq = 4.0`) to match meters correctly [S1, unofficial].
    $$ SDF_{scaled} = \frac{cell\_sdf}{4.0} $$
3.  **Write to Texture:** In `cloud_3d_volume_bake.comp`:
    *   Write the analytical density to the texture's Alpha channel [S1, unofficial].
    *   Write the 3D SDF to the texture's Blue channel [S1, unofficial].

#### 2. Raymarching with Space Skipping
During rendering, the raymarcher queries the precomputed 3D texture [S1, unofficial].

1.  **Query SDF:** Call `getCloud3DSDF` to query the precomputed 3D texture SDF with internal advection support [S1, unofficial].
    *   **Continuity:** Do **not** apply a `distY > 100.0 * props.worldScale` threshold check. This ensures a mathematically continuous distance field across the entire domain [S1, unofficial].
2.  **Compute Step Size:** Calculate the sphere tracing step size using the queried SDF (`d3d`):
    $$ step = \max(baseStepSize, 0.4 \times d3d) $$
    *   Apply a cap: `step = min(step, 2000.0 * props.worldScale)` [S1, unofficial].
3.  **Advance Ray:**
    *   If outside the cloud mass (`d3d > 0.0`), advance the ray by `step` [S1, unofficial]. This skips directly to the exact boundary of the cloud mass [S1, unofficial].
    *   If inside the cloud mass, use `baseStepSize` for standard volumetric stepping [G].
4.  **Sample Density:** Read the precomputed physical density and local AO directly from the 3D volume texture (Alpha channel) [S1, S2, unofficial].
    *   Bypass old multi-octave 2D-based heightmap evaluation in `calculateCloudDensity` and `calculateCloudDensityMinimal` [S1, unofficial].

def raymarch_cloud(ray_origin, ray_direction, texture, props, baseStepSize=0.5, MAX_DISTANCE=10000.0, THRESHOLD=0.001):
    """
    Raymarches through the baked cloud volume using SDF space skipping.
    """
    maxStepCap = 2000.0 * props.worldScale
    sdf_multiplier = 0.4
    
    t = 0.0
    color = vec3(0.0)
    transmittance = 1.0
    
    while t < MAX_DISTANCE and transmittance > 0.01:
        # 1. Query SDF from texture (with advection)
        pos = ray_origin + ray_direction * t
        d3d = get_cloud_3d_sdf(pos, texture)
        
        # 2. Compute step size
        # Outside cloud mass (d3d > 0.0): skip using SDF
        # Inside cloud mass (d3d <= 0.0): use fixed base step
        if d3d > 0.0:
            step = max(baseStepSize, sdf_multiplier * d3d)
        else:
            step = baseStepSize
        step = min(step, maxStepCap)
        
        # 3. Advance ray
        t += step
        
        # 4. Sample density and AO
        pos = ray_origin + ray_direction * t
        density = texture[pos].a
        ao = texture[pos].b
        
        # Accumulate color/transmittance based on density and AO
        # Sources do not specify the exact accumulation formula [G]
        alpha = 1.0 - exp(-density * step)
        color += alpha * transmittance * vec3(1.0) # Simplified color contribution
        transmittance *= (1.0 - alpha)
        
        if density < THRESHOLD:
            break
            
    return color

def get_cloud_3d_sdf(pos, texture):
    """
    Queries the precomputed 3D texture SDF.
    No distY > 100.0 * worldScale check is performed [S1, unofficial].
    """
    return texture[pos].b

### Edge Cases and Pitfalls
*   **Visual Distortion:** Caused by missing steps during camera movement [S1, unofficial]. Resolved by succinct stepping that skips directly to the exact boundary of the cloud mass using `max(baseStepSize, d3d)` [S1, unofficial].
*   **Viewpoint-dependent Banding:** Caused by non-continuous SDF domains or overshooting boundaries due to noise domain warping and non-linear height gradients [S1, unofficial]. Eliminated by:
    1.  Removing the `distY > 100.0 * props.worldScale` threshold check in `getCloud3DSDF` [S1, unofficial].
    2.  Using a conservative `0.4` multiplier on `d3d` and a `2000.0 * props.worldScale` cap on step size [S1, unofficial].
*   **SDF Scaling:** Incorrect meter matching if `cell_sdf` is not divided by `freq = 4.0` [S1, unofficial].

## Operating characteristics
*   **Performance:** Massive performance gains compared to procedural evaluation because it samples precomputed data instead of evaluating noise and density [S2, unofficial].
*   **Memory:** Requires storage for a 3D volume texture containing density and SDF [S1, unofficial].
*   **Strengths:** Efficient space skipping, continuous SDF domain, elimination of viewpoint-dependent banding [S1, unofficial].
*   **Limitations:** Requires baking phase; less flexible than procedural methods for dynamic changes not covered by advection [S1, S2, unofficial].

## Background
This method was introduced in a pull request by `ricecake` (via `Jules`) in July 2026, transitioning the volumetric cloud rendering system from a 2D weather/SDF-based model to a direct 3D weather volume model [S1, unofficial]. It was further enhanced to include precomputed density, 3D AO, and shadow transmittance [S2, unofficial]. It is used in the `boidsish` project [S1, S2, unofficial].
