# Atmospheric Height Gradient

Also called: Cloud Type Vertical Profile, GetDensityHeightGradientForPoint, GetGradientHeightFactor, Height Density Gradient, Vertical Density Profile Gradient

## Overview
The Atmospheric Height Gradient method defines the vertical density distribution profile for volumetric cloud layers based on cloud type (Stratus, Cumulus, Cumulonimbus, Cirrus) [S1, S2, unofficial]. It computes a scalar shape factor representing the relative density at a given altitude within a cloud layer, creating bell-shaped or plateau-shaped distributions [S1, S2, unofficial]. It differs from [Volumetric Cloud Raymarching](1248-volumetric-cloud-raymarching.md) by providing the underlying scalar field definition rather than the integration technique, and from [Procedural Volume Cloud Modeling](2256-procedural-volume-cloud-modeling.md) by focusing specifically on the vertical stratification logic rather than horizontal noise composition.

## How it works
**Inputs:**
- `altitude`: The vertical position of the query point (in km or normalized 0-1 range depending on implementation variant).
- `cloud_type`: Identifier for the cloud layer type (e.g., Stratus, Cumulus, Cumulonimbus, Cirrus).
- `layer_bounds`: The bottom and top altitude limits for the specific cloud layer.

**Outputs:**
- `density_gradient`: A scalar value in $[0, 1]$ (or slightly above for anvil effects) representing the vertical density weight.

**Data Structures:**
The method relies on a preset structure defining physical bounds and visual multipliers for each cloud type.

```python
struct CloudAltitudeLayer:
    bottomAltitudeKm: float
    topAltitudeKm: float
    coverage: float
    densityMultiplier: float
    precipitationFactor: float
```

**Preset Values:**
The following presets are defined in the sources [S2, unofficial]:

| Cloud Type | Bottom (km) | Top (km) | Coverage | Density Multiplier | Precipitation Factor |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Stratus | 1.0 | 2.2 | 0.85 | 0.6 | 0.1 |
| Cumulus | 1.5 | 4.5 | 0.45 | 1.2 | 0.0 |
| Cumulonimbus | 1.2 | 9.0 | 0.70 | 2.5 | 0.85 |
| Cirrus | 7.0 | 10.5 | 0.30 | 0.25 | 0.0 |

**Algorithm Steps:**
The implementation varies slightly between two primary variants found in the sources. Variant 1 (S1) uses explicit time-width parameters for smooth transitions, while Variant 2 (S2) uses analytic trigonometric functions based on altitude fraction.

**Variant 1: Explicit Transition Widths (S1)**
1.  **Boundary Check:** If `altitude` < `bottom` or `altitude` > `top`, return 0.0.
2.  **Cloud Type Selection:** Determine cloud type from input or metadata (e.g., `weather_data.z`).
    -   If `weather_data.z` < 0.1, type = Stratus (0).
    -   If `weather_data.z` > 0.9, type = Cumulonimbus (2).
    -   Otherwise, type = Cumulus (1).
3.  **Rise Phase:**
    -   If `altitude` < `starttimeup`, return 0.0.
    -   If `starttimeup` <= `altitude` < `starttimeup` + `timewidthup`:
        -   Calculate factor: $F = \frac{2\pi}{2 \cdot \text{timewidthup}}$
        -   Calculate gradient: $G = 0.5 \cdot \sin(F \cdot \text{altitude} - \frac{\pi}{2} - F \cdot \text{starttimeup}) + 0.5$
        -   Return $G$.
4.  **Plateau Phase:**
    -   If `starttimeup` + `timewidthup` <= `altitude` < `starttimedown`, return 1.0.
5.  **Fall Phase:**
    -   If `starttimedown` <= `altitude` < `starttimedown` + `timewidthup`:
        -   Calculate factor: $F = \frac{2\pi}{2 \cdot \text{timewidthup}}$
        -   Calculate gradient: $G = 0.5 \cdot \sin(F \cdot \text{altitude} - \frac{\pi}{2} - F \cdot (\text{starttimedown} + \text{timewidthup})) + 0.5$
        -   Return $G$.
6.  **Termination:** If `altitude` >= `starttimedown` + `timewidthup`, return 0.0.

**Variant 2: Altitude Fraction Analytic (S2)**
1.  **Boundary Check:** If `altitude` < `bottomAltitudeKm` or `altitude` > `topAltitudeKm`, return 0.0.
2.  **Normalize Height:** Calculate height fraction $h$:
    $$h = \frac{\text{altitude} - \text{bottomAltitudeKm}}{\text{topAltitudeKm} - \text{bottomAltitudeKm}}$$
3.  **Compute Shape Factor:** Based on `cloud_type`:
    -   **Stratus:** Return $\sin(h \cdot \pi) \cdot 0.9$.
    -   **Cumulus:** Return $\sin(h^{0.7} \cdot \pi)$.
    -   **Cumulonimbus:**
        -   If $h > 0.8$, return 1.2 (anvil flare).
        -   Else, return $0.6 + 0.4 \cdot \sin(h \cdot \pi)$.
    -   **Cirrus:** (Not explicitly detailed in S2 notes, but implied by preset structure; typically low density).
4.  **Alternative Simplified S2 Approach:** Some implementations use a simpler rise/fall product:
    -   Rise factor: $R = \min(h / 0.15, 1.0)$
    -   Fall factor: $F = \min((1.0 - h) / 0.35, 1.0)$
    -   Return $R \cdot F$.

**Parameters (Variant 1 Specific):**
-   **Stratus:** `timewidthup`=0.08, `starttimeup`=0.08, `starttimedown`=0.2.
-   **Cumulus:** `timewidthup`=0.14, `starttimeup`=0.1, `starttimedown`=0.5.
-   **Cumulonimbus:** `timewidthup`=0.2, `starttimeup`=0.10, `starttimedown`=0.7.

**Edge Cases and Pitfalls:**
-   **Precision:** Division by zero if `topAltitudeKm` equals `bottomAltitudeKm`. Guard against this by returning 0.0 or a default value.
-   **Anvil Flare:** The Cumulonimbus anvil effect (returning > 1.0) requires the renderer to handle density values exceeding the standard [0,1] range, or the value should be clamped if used as a strict multiplier.
-   **Discontinuity:** Variant 1 requires careful alignment of `starttimeup`, `timewidthup`, and `starttimedown` to ensure the plateau exists (i.e., `starttimeup` + `timewidthup` < `starttimedown`).

## Subtopics

### Cumulonimbus Anvil Profile
A specialized sub-profile for Cumulonimbus clouds that extends the density gradient above the main cloud top (altitude fraction > 0.8) to simulate the spreading anvil shape. It returns a value of 1.2, exceeding the standard bell curve, to create a wider, flatter top. Choose this when rendering realistic thunderstorm clouds with overshooting tops. [S2, unofficial]

### Stratus Flat Sheet Profile
A sub-profile for Stratus clouds that uses a simple sine wave scaled by 0.9 to create a relatively flat, uniform layer with soft vertical edges. Choose this for overcast skies or low-level fog banks where vertical density variation is minimal. [S2, unofficial]

## Operating characteristics
-   **Time Complexity:** $O(1)$. The calculation involves a constant number of arithmetic operations, comparisons, and trigonometric functions.
-   **Memory Complexity:** $O(1)$. Only local variables and a small lookup table for presets are required.
-   **Performance:** Extremely fast, suitable for per-fragment or per-voxel evaluation in real-time rendering.
-   **Strengths:** Analytic definition allows for infinite resolution without sampling artifacts. Simple to implement and integrate into raymarching loops.
-   **Limitations:** Does not account for horizontal variability or turbulence; must be combined with noise functions (see [Procedural Volume Cloud Modeling](2256-procedural-volume-cloud-modeling.md)) for organic appearance.
-   **When to use:** When defining the base vertical density falloff for cloud layers before applying horizontal noise.
-   **When not to use:** When horizontal coherence or detailed cloud geometry is required without additional noise composition.

## Background
The method originates from real-time volumetric cloud rendering techniques, specifically those aiming to simulate diverse cloud types with distinct vertical profiles. It is implemented in projects such as `realtime-volumetric-cloudscapes` [S1, unofficial] and `volumetric-clouds-wgsl` [S2, unofficial]. The approach separates the vertical stratification logic from horizontal noise generation, allowing for modular cloud type definition.
