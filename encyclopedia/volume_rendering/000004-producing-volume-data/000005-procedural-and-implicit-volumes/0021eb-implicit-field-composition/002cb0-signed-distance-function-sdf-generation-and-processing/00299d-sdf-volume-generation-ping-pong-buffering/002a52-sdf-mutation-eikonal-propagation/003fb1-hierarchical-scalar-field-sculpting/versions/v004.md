# Hierarchical Scalar Field Sculpting

Also called: Resolution Adaptive Volume Sculpting, ntree subdivision

## Overview
Hierarchical Scalar Field Sculpting is a procedural volume modeling technique that allows interactive modification of a scalar field representing volumetric material density [S1]. It solves the trade-off between modeling detail and interactive performance by using an adaptive hierarchical grid that refines only where the sculpting tool influences the field [S1]. It sets itself apart from fixed-resolution voxel sculpting by dynamically adjusting sampling density based on tool proximity and field complexity, and from pure implicit surface modeling by maintaining an explicit, editable volume buffer that supports direct Boolean-like operations and localized updates [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A hierarchical scalar field representation, a sculpting tool (defined by position, orientation, scale, and shape), and an action (defining how the tool modifies the field, e.g., Add, Subtract).
*   **Output:** An updated scalar field with modified vertex values, gradients, and colors, potentially with a refined hierarchical structure.

**Data Structures:**
1.  **Vertex:** Stores the scalar field value, field gradient, and color [S1].
2.  **ntree Cell:** A hierarchical node structure. A Cell contains its own Vertices and a list of sub-cells (children) [S1]. The structure uses a constant subdivision factor $n=4$ per dimension [S1]. Unlike octrees, Cells are enriched with successors rather than replaced, resembling Recursive Grids [S1].
3.  **Vertex Cache:** An STL hash map indexed by memory addresses of Vertices. It maps the Vertex state (field value, gradient, color) prior to the current tool's modification [S1]. One cache is created per Tool-Action application pair [S1].

**Parameters:**
*   **Field Clamping Range:** $[0, 3]$ [S1]. Values are clamped to prevent negative fields (which block new material creation) and excessive positive fields (which block material removal) [S1].
*   **Iso-value:** $1.5$ defines the object's surface [S1].
*   **Min Resolution:** The largest cell size allowed, determined by the tool's minimum security cell size to capture features [S1].
*   **Max Resolution:** The smallest cell size allowed, determined by a constant factor of the tool's scale to prevent infinite subdivision loops caused by discontinuities [S1].
*   **Acceptable Discrepancy:** A threshold for `estimateDiscrepancy()` to determine if further subdivision is necessary [S1].

**Tool Definition (Wyvill's Field Function):**
The tool is an ellipsoidal scalar field based on Wyvill's function [S1]. For a query point $p$, let $d^2$ be the squared distance from the tool's center (normalized by the tool's scale) [S1]. The field value $f(p)$ is:
$$
f(p) = \begin{cases} 
0 & \text{if } d^2 \ge 1 \\
3 \cdot \left( 1 - \frac{2}{9}d^2 + \frac{17}{9}d^4 - \frac{4}{9}d^6 \right) & \text{otherwise}
\end{cases}
$$
This function is computationally cheap (uses squared distance), has a spatially limited domain of influence, and is bell-shaped with $C^1$ variations for smooth blending [S1].

**Algorithm Steps:**

1.  **Initialization:** Create a Vertex Cache for the current Tool-Action pair. Store the current state of all affected Vertices in the cache [S1].
2.  **Apply Tool (Recursive):** Call `Cell::apply(Tool t, Action a)` on the root Cell [S1].
    *   For each Vertex $v$ in the current Cell, call `a.update(t, v)` [S1].
    *   If the Cell has no children, call `checkSubdivide(t)` [S1].
    *   If the Cell has children, recursively call `child.apply(t, a)` for each child [S1].
3.  **Subdivision Check:** In `Cell::checkSubdivide(Tool t)`:
    *   If `Cell.size > t.getMinResolution()`, call `subdivide()` [S1].
    *   Else, if `Cell.size < t.getMaxResolution()`:
        *   If `estimateDiscrepancy() > acceptableDiscrepancy`, call `subdivide()` [S1].
4.  **Subdivision Logic:**
    *   Create sub-cells with subdivision factor $n=4$ [S1].
    *   Share Vertex nodes among common faces or edges between adjacent Cells of the same level to minimize memory and update costs [S1].
    *   Initialize new Vertices in sub-cells by interpolating the field values from the parent Cell's Vertices *as they were before the current tool application* (retrieved from the Vertex Cache) [S1]. This ensures the tool's modification is correctly added to the refined geometry [S1].
5.  **Simplification Pass (Idle):** At idle moments, perform a simplification pass over the whole field [S1]. Destroy every Cell that does not cross the surface (iso-value 1.5) and whose children also do not cross the surface [S1]. This pass cannot be interleaved with subdivision because finer levels might add details that require coarser levels to remain [S1].

**Edge Cases and Pitfalls:**
*   **Infinite Subdivision:** Subtractive tools can create discontinuities, leading to infinite subdivision. Mitigated by `Max Resolution` [S1].
*   **Irreversibility:** Field clamping makes the tool application non-reversible. Mitigated by explicit Vertex Caching of pre-update states [S1].
*   **Simplification Timing:** Simplification cannot occur during subdivision because finer levels might add details. It must be done in a separate pass at idle moments [S1].
*   **Update Order:** Coarser levels must be updated first to provide interactive visual feedback. This requires careful initialization of new vertices from cached pre-update values [S1].

## Subtopics

### [Volume Sculpting](11209-volume-sculpting.md)
Volume sculpting is a free-form interactive modeling technique based on the metaphor of sculpting and painting a voxel-based solid material, such as a block of marble or wood. It solves the difficulty of modeling topologically complex and highly-detailed objects in traditional CAD systems and enables scientists and physicians to explore inner structures of volumetric datasets by gradually removing material. It sets itself apart from surface-based sculpting by operating directly on the volume buffer, allowing for localized rendering updates and Boolean operations between independent volume buffers.

## Operating characteristics
*   **Time Complexity:** Depends on the number of active cells and vertices. Tool application is recursive, visiting only cells within the tool's domain of influence. Subdivision adds overhead but is bounded by resolution limits. Simplification is a global pass but occurs at idle moments [S1].
*   **Memory Complexity:** Proportional to the number of vertices and cells in the active region. Vertex sharing reduces memory usage for adjacent cells [S1].
*   **Performance:** Provides interactive visual feedback by updating coarser levels first [S1]. The use of Wyvill's function (squared distance) is computationally cheap [S1].
*   **Strengths:** Adaptive resolution captures fine details where needed; direct volume manipulation allows for complex Boolean operations and inner structure exploration; smooth blending due to $C^1$ continuity of the tool function [S1].
*   **Limitations:** Simplification is drastic and global; requires careful management of vertex caching for undo and subdivision initialization; not given in the sources for specific hardware performance metrics.

## Background
Hierarchical Scalar Field Sculpting, also known as Resolution Adaptive Volume Sculpting, was introduced by Eric Ferley, Marie-Paule Cani, and Jean-Dominique Gascuel [S1]. The method builds on earlier work in tool-guided sculpting and hierarchical scalar field representations [S1]. It addresses the limitations of fixed-resolution voxel grids in interactive modeling by introducing adaptive subdivision [S1]. The technique is used in volumetric modeling systems for creating complex sculptures and editing mesh-converted models [S1].
