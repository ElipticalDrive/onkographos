# Swept Volumes via Spacetime Numerical Continuation

Also called: Spacetime Numerical Continuation, Swept Volume Continuation

## Overview
Swept Volumes via Spacetime Numerical Continuation computes the swept volume of a moving shape (brush) by solving for the minimum signed distance function (SDF) over time using numerical continuation, outputting sparse cells representing the spacetime trajectory [S1, unofficial]. It generates a sparse, trajectory-based representation suitable for dual contouring rather than a dense hierarchical grid [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A brush mesh (ideally watertight), a time-varying transform path, and a grid resolution parameter `eps`.
*   **Output:** Sparse data structures: `CS` (cell values/SDF), `CV` (cell vertex times/argmins), and `CI` (cell indices/topology) [S1, unofficial].

**Data Structures:**
The output is sparse, avoiding dense grid stamping [S1, unofficial]. For Dual Contouring, the connectivity must be formatted as unique edges (`#edges x 2`) rather than cells (`#cells x 8`) to prevent torn/holey meshes [S1, unofficial].

**Steps:**
1.  **Define Transform Functor:** Implement a functor `SweptTransform` with the signature `void(t, A, Adot)`. This function fills a 4x4 pose matrix `A` and its time-derivative `Adot` for a given time `t` [S1, unofficial].
2.  **Run Continuation:** Execute the spacetime numerical continuation body. This generates the sparse output data structures `CS`, `CV`, and `CI` by tracing the trajectory of the brush surface [S1, unofficial].
3.  **Contouring (Mesh Generation):**
    *   **Dual Contouring (Recommended for sharp features):** Root-find each crossing with the continuation's own SDF, warm-started from the local argmin time stored in `CV`. Compute the analytic normal at the argmin pose [S1, unofficial].
    *   **Marching Cubes:** Uses linear interpolation of crossings. No root finding is required as crossings are already at the continuation tolerance [S1, unofficial].

**Formulas:**
The swept SDF is defined as [S1, unofficial]:
$$f(P) = \min_t g(P,t)$$
where $g$ is the distance to the brush at time $t$. At the argmin pose $t^*$ (where $dg/dt=0$), the gradient is [S1, unofficial]:
$$df/dP = dg/dP$$
The analytic normal is computed as [S1, unofficial]:
$$s \frac{P - c_{\text{world}}}{\|P - c_{\text{world}}\|}$$
where $s$ is the sign, $P$ is the grid vertex, and $c_{\text{world}}$ is the closest surface point from an AABB query [S1, unofficial].

**Parameters:**
*   `eps`: Grid resolution parameter. Typically set to 0.015 for high-quality demos (~55k verts, ~40s compute with 400 seeds) [S1, unofficial].

**Pitfalls:**
*   **Non-watertight brushes:** Overlapping geometry causes winding numbers $w > 1$, corrupting the signed distance field if computed as $s = 1 - 2w$. Fix: clamp the sign via $w > 0.5$ threshold [S1, unofficial].
*   **Interior faces:** Non-manifold soups create spurious local minima in the distance-over-t objective, causing the brush to poke out of the swept volume. Fix: build the brush as a single watertight mesh [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but performance is dominated by the transform functor calls [S1, unofficial]. NativeTransform via `numba.cfunc` is ~28 ns/call, compared to ~33 ns for a C++ baseline (0.8x speed) and ~180x slower for a Python callable [S1, unofficial].
*   **Memory Complexity:** Sparse output (CS, CV, CI), avoiding dense grid storage [S1, unofficial].
*   **Measured Performance:** With `eps=0.015`, ~55k verts, and 400 seeds, compute time is ~40s [S1, unofficial].
*   **Accuracy:** Analytic validation shows a translating cube's swept volume (a box) is dual-contoured to within 1e-4 of the true box [S1, unofficial]. On smooth analytic torus, deviation stays at the ~1e-3 continuation tolerance at every resolution (0.04/0.02/0.01) [S1, unofficial].
*   **Strengths:** Crisp sharp features via analytic normals in Dual Contouring; sparse representation; high performance with native transform wrappers [S1, unofficial].
*   **Limitations:** Requires watertight brushes to avoid winding number corruption and spurious local minima; Dual Contouring requires careful connectivity handling (unique edges) [S1, unofficial].
*   **When to use:** When sharp features are required and the brush motion is complex; when sparse representation is preferred [S1, unofficial].
*   **When not to use:** When the brush is non-manifold and cannot be easily made watertight; when simpler linear interpolation (Marching Cubes) is sufficient for the required visual fidelity [S1, unofficial].

## Background
The method was presented at SIGGRAPH 2021 and authored by Silvia Sellán, Noam Aigerman and Alec Jacobson [S1, unofficial]. It builds on the principles of spacetime numerical continuation to solve for the minimum signed distance function over time [S1, unofficial].
