# Virtual Volume Sculpting (Reverse Engineering)

Also called: 3D Rubbing, Freehand Volume Removing, Haptic Volume Sculpting, Reverse Engineering by Virtual Volume Sculpting, Subtractive Modeling, Virtual Volume Sculpting for Reverse Engineering

## Overview
Virtual Volume Sculpting is a reverse engineering methodology that generates a volumetric representation of a physical object by subtractively modeling a virtual voxel block ("virtual clay") using a tracked probe, rather than directly digitizing surface points [S1]. It differs from conventional reverse engineering, which outputs surface meshes from noisy point clouds requiring segmentation and fitting, by producing a volume representation directly and eliminating point cloud processing [S1]. Unlike mass-spring models that rely on penetration depth, this method uses material removal rate to define force, reflecting plastic deformation in milling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A physical object fixed in a digitizer workspace; a 6DOF haptic device with a probe; user-defined voxel resolution.
*   **Output:** A voxel array representing the physical object; optionally, a triangular mesh via isosurface extraction.

**Data Structures:**
The virtual clay is stored using **Spatial Run-Length Encoding (S-RLE)** [S1]. This consists of two cross-referenced databases:
1.  **Position Array (Geometrical Domain):** A stack of lists recording runs as tuples $(z_k, y_j: x_{start}, x_{end})$ [S1].
2.  **Property List (Physical Domain):** A table describing physical properties of each element [S1].

**Parameters:**
*   **Probe Diameter ($d_m$):** Typically 6.5 mm, 6.0 mm, or 0.5 mm. Larger probes remove material faster but leave larger under-cuts; smaller probes are slower but more precise [S1].
*   **Haptic Period ($\Delta t$):** Must be less than 1 ms to ensure stable force feedback [S1].
*   **Probe Velocity ($v$):** Assumed 100 mm/s, resulting in displacement $< 0.1$ mm per haptic cycle [S1].
*   **Force Constant ($k$):** Reflects virtual clay hardness. Small for preliminary fast removal, large for finishing stages [S1].
*   **Haptic Update Rate:** Sustained at 900 Hz or higher [S1].

**Steps:**
1.  **Calibration and Setup:** Calibrate the tool and fix the physical model in the digitizer workspace [S1].
2.  **Bounding Box Measurement:** Measure the width, length, and height of the physical model using a dedicated fixture and sliding plates [S1].
3.  **Virtual Clay Generation:** Generate a virtual clay voxel block with user-defined resolution that encloses the measured bounding box [S1].
4.  **Probe Position Calculation:** Map the physical tracker's movements to a virtual tracker. Calculate the probe tip position $P$ from the Haptic Interface Point (HIP) position $S$ using:
    $$ P = S + SP \times s_r $$
    where $SP$ is the distance from $S$ to $P$, and $s_r$ is the orientation vector of the PHANToM axis 4 [S1].
5.  **Swept Volume Removal:** For each haptic cycle, determine the swept volume of the virtual tracker between positions $P_1$ (at $t$) and $P_2$ (at $t+\Delta t$). The swept volume consists of the probe head spheres at $P_1$ and $P_2$, and a cylinder connecting them with radius $r$ (probe radius) and axis along vector $P_1P_2$ [S1].
6.  **Voxel Removal Condition:** A voxel $Q$ is removed if it satisfies the following condition:
    $$ d_1 < r \quad \text{AND} \quad d_2 < r \quad \text{AND} \quad (d_1 < 0 \quad \text{OR} \quad d_2 < 0) $$
    where $d_1$ and $d_2$ are the directional distances from voxel center $Q$ to the bottom and top circles of the swept cylinder, respectively [S1].
    The directional distance $d_1$ is calculated as:
    $$ d_1 = \frac{PP_{12} \times QP}{|PP_{12}|} $$
    where $PP_{12}$ is the vector from $P_1$ to $P_2$, and $QP$ is the vector from $Q$ to $P_1$ [S1].
7.  **Force Feedback:** Calculate the number of voxels removed ($N$) in the cycle. The feedback force $F$ is:
    $$ F = k N $$
    The direction of $F$ is opposite to $P_1P_2$ [S1].
8.  **Iteration:** Repeat steps 5-7 until no more virtual clay can be removed (i.e., the virtual tracker has swept the entire initial volume) [S1].
9.  **Under-cut Handling:** If under-cuts remain due to tool inaccessibility (curvature radii smaller than probe tip radius), switch to a smaller probe tip and repeat removal [S1].
10. **Mesh Extraction (Optional):** Generate triangular meshes from the final volume representation using marching cube family algorithms [S1].

**Pseudocode:**
The core voxel removal logic for a single voxel $p$ within the S-RLE structure $V$ is defined in Algorithm 1 [S1]:

```python
def Removing(p, V):
    """
    Removes voxel p from the S-RLE volume V.
    Returns:
        1: if p was a head or tail voxel (run shortened)
        2: if p was an internal voxel (run split)
        3: if p was not in V (failure)
    """
    ret = 0
    # Locate the run R containing p
    # R is defined as (u', u'': v, w) representing x range [u', u''] at y=v, z=w
    R = locating(p, V)
    
    if R is not None:
        # p is in V
        if p.x == R.u_prime:
            # p is the head voxel
            # Shorten the run by incrementing start x
            replace_run(V, R, (R.u_prime + 1, R.u_double_prime, R.v, R.w))
            ret = 1
        elif p.x == R.u_double_prime:
            # p is the tail voxel
            # Shorten the run by decrementing end x
            replace_run(V, R, (R.u_prime, R.u_double_prime - 1, R.v, R.w))
            ret = 1
        else:
            # p is neither head nor tail
            # Break R into two runs R1 and R2
            # R1: [u', p.x]
            # R2: [p.x, u''] -> Note: Source says R2(x, u''), implying p.x is the start of R2
            # However, standard run logic usually excludes the removed point.
            # Source: "add run R1(u', x : v, w) into V; add run R2(x, u": v, w) into V"
            # This implies the removed voxel x is the boundary. 
            # If R is (u', u''), and p is at x, R1 ends at x, R2 starts at x?
            # Usually runs are inclusive. If p is removed, R1 should be (u', x-1) and R2 (x+1, u'').
            # But source code explicitly uses x. We follow source literal.
            remove_run(V, R)
            add_run(V, (R.u_prime, p.x, R.v, R.w))
            add_run(V, (p.x, R.u_double_prime, R.v, R.w))
            ret = 2
    else:
        # p is not in V
        ret = 3
        
    return ret
```

**Edge Cases and Pitfalls:**
*   **Under-cuts:** Occur when geometric feature curvature radii are smaller than the probe tip radius, leaving residual volume [S1].
*   **Invalid Removal:** Attempting to remove a voxel $p \notin V$ results in failure (`ret = 3`) [S1].
*   **Isolated Volumes:** Connectivity destruction may generate isolated volumes. These require separate handling, such as cropping or manual selection [S1].

## Operating characteristics
*   **Time Complexity:** Not explicitly given in the sources. The complexity depends on the S-RLE lookup and run splitting operations.
*   **Memory Complexity:** Depends on the S-RLE structure, which compresses contiguous voxels into runs.
*   **Performance:** Haptic update rate sustained at 900 Hz or higher in experiments [S1].
*   **Strengths:** Eliminates point cloud segmentation and surface fitting; avoids redundant scanning points by using the emerging model as a visual guide; provides intuitive human-machine interaction via haptic feedback [S1].
*   **Limitations:** Under-cuts are inherent to the probe geometry; resolution is limited by voxel size; manual freehand scanning requires user skill [S1].
*   **When to use:** When a direct volume representation is needed, or when point cloud noise is a concern. Suitable for objects where surface fitting is difficult.
*   **When not to use:** When high-precision surface meshes are required directly without post-processing; when under-cuts are critical and cannot be addressed with smaller probes.

## Background
Virtual Volume Sculpting for Reverse Engineering was proposed by Zhengyi Yang and Yonghua Chen from The University of Hong Kong in 2004 [S1]. It synthesizes techniques from volume sculpting and reverse engineering to create a subtractive modeling process. The method uses a refitted PHANToM Desktop haptic device with 6DOF position/orientation sensing [S1]. It was implemented using the Visualization Toolkit (VTK) and a custom haptic rendering loop decoupled from the graphic loop to achieve high update rates [S1].
