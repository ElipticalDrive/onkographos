# Script-to-Shader SDF Preprocessor

Also called: Animate() Construct, SDF Script Compiler, loadTxtFragFile

## Overview
The Script-to-Shader SDF Preprocessor is a C++ utility that parses a custom high-level script language to generate GLSL code for Signed Distance Function (SDF) scene composition [S2, unofficial]. It solves the problem of manually writing complex, nested GLSL SDF logic by allowing users to define scenes using declarative markers for boolean operations, loops, and materials [S2, unofficial]. It sets itself apart from sibling methods like [Volume SDF](11033-volume-sdf.md) or [RobotSDF](13070-robotsdf.md) by operating at the shader source generation stage rather than producing volumetric data or runtime geometry; it transforms a textual description of a scene into a functional fragment shader capable of rendering implicit surfaces [S2, unofficial]. The method also incorporates an `Animate()` construct to facilitate interactive edits and animations of the output GLSL shader by exposing input/output variables [S1].

## How it works
The method takes a dummy GLSL fragment shader template (`realCode`) and a custom script file (`psCode`) as input, and outputs a complete, valid GLSL fragment shader as output [S2, unofficial].

### Data Structures
The implementation relies on string manipulation and lambda functions within a C++ context [S2, unofficial]. Key internal states include:
- `realCode`: The GLSL template string, modified in place.
- `psCode`: The script source string.
- `sceneR`: The insertion point index in `realCode` where generated SDF logic is placed.
- `lightCnt`: An integer counter tracking the number of light environments defined.
- `mtlNo`: An integer material identifier used in generated function calls.

### Steps
1. **Load Inputs**: Read the dummy GLSL fragment shader into `realCode` and the custom script into `psCode` [S2, unofficial].
2. **Define Environment Handler**: Create a lambda `setUpEnv(envName)` that searches `realCode` for the marker `!(envName)` [S2, unofficial]. It scans `psCode` for the marker `#envName`, extracts the content between the opening `{` and closing `}` associated with that marker in the script, and inserts this extracted content into `realCode` at the `!(envName)` position [S2, unofficial]. If `envName` is `"light"`, it increments `lightCnt` [S2, unofficial].
3. **Process Environments**: Call `setUpEnv("material")` followed by `setUpEnv("light")` to inject material and lighting definitions into the shader template [S2, unofficial].
4. **Identify Insertion Point**: Locate the marker `!(sceneSDF)` in `realCode`. This index becomes `sceneR`, the location where the generated SDF composition code will be inserted [S2, unofficial].
5. **Define Function Parser**: Create a lambda `findFunc` that parses markers starting with `#` in `psCode` [S2, unofficial]. It identifies boolean operations: `opU` (union), `opS` (subtract), `opI` (intersect), and `opUs` (smooth union) [S2, unofficial]. It converts script syntax into corresponding GLSL function calls [S2, unofficial].
6. **Main Parsing Loop**: Iterate through `psCode` handling specific markers: `@i` generates `for` loop structures in the output GLSL [S2, unofficial]. `#` triggers function definition parsing via `findFunc` [S2, unofficial]. `!` inserts the subsequent line directly into the output [S2, unofficial].
7. **Insert Generated Code**: Append the code generated in steps 5-6 to `realCode` at the `sceneR` position [S2, unofficial].
8. **Return Result**: Return the modified `realCode` as the final shader source [S2, unofficial].

### Formulas
The smooth union operation `opUs` uses a blending parameter $k$ [S2, unofficial]. The GLSL implementation corresponds to the following mathematical operation for inputs $a$ and $b$:

$$ f = \min(a, b) - k \cdot \max(0, \min(a, b)) $$

Where:
- $a, b$: The signed distance values of the two primitives being combined.
- $k$: The smoothness parameter, parsed from the script using `sscanf(..., "#k%f", &k)` [S2, unofficial].

### Parameters
- `k`: A float value controlling the smoothness of the union operation for `opUs`. Parsed directly from the script file [S2, unofficial].
- `prefix`: A string defining the directory path for shader files, formatted as `shaders/%s/%s.glsl` [S2, unofficial].

### Pseudocode
```python
def script_to_shader(real_code: str, ps_code: str) -> str:
    """
    Parses a custom script language to generate GLSL code for SDF scene composition.
    Implements steps 1-8 from the source specification [S2, unofficial].
    """
    light_cnt = 0
    mtl_no = 0  # Assumed initial material number [G]
    
    # Step 2: Define setUpEnv lambda
    def setUpEnv(env_name: str):
        nonlocal light_cnt
        marker = f"!( {env_name} )"
        if marker not in real_code:
            return
        # Find corresponding block in ps_code
        env_marker = f"#{env_name}"
        start_idx = ps_code.find(env_marker)
        if start_idx == -1:
            return
        brace_start = ps_code.find('{', start_idx)
        if brace_start == -1:
            return
        depth = 0
        end_idx = brace_start
        for j in range(brace_start, len(ps_code)):
            if ps_code[j] == '{':
                depth += 1
            elif ps_code[j] == '}':
                depth -= 1
                if depth == 0:
                    end_idx = j
                    break
        block_content = ps_code[brace_start+1:end_idx]
        # Insert into real_code
        real_code = real_code.replace(marker, block_content)
        if env_name == "light":
            light_cnt += 1

    # Step 3: Process environments
    setUpEnv("material")
    setUpEnv("light")

    # Step 4: Find insertion point
    scene_marker = "!(sceneSDF)"
    if scene_marker not in real_code:
        raise ValueError("Scene SDF marker not found in template")
    scene_r = real_code.find(scene_marker)
    
    # Step 5 & 6: Parse functions and main loop
    generated_sdf_code = ""
    i = 0
    while i < len(ps_code):
        char = ps_code[i]
        
        if char == '@':
            # Handle @i as for loop generation [S2, unofficial]
            # Extract loop parameters and generate GLSL for loop
            # Source does not specify exact loop parameter syntax; standard for-loop generation assumed [G]
            loop_end = ps_code.find('\n', i)
            if loop_end == -1: loop_end = len(ps_code)
            generated_sdf_code += f"for {ps_code[i+1:loop_end]} {{\n"
            i = loop_end + 1
            
        elif char == '#':
            # Handle function definition [S2, unofficial]
            # Identify operation type
            func_end = ps_code.find(' ', i)
            if func_end == -1: func_end = len(ps_code)
            func_type = ps_code[i+1:func_end].strip()
            
            if func_type == "opU":
                # Union: min(a, b)
                # Source snippet: funcStr += ... "(mint, vec2(fSDF(...), mtlNo))"
                arg_end = ps_code.find(' ', func_end)
                if arg_end == -1: arg_end = len(ps_code)
                arg1 = ps_code[func_end+1:arg_end].strip()
                generated_sdf_code += f"min({arg1}, vec2(fSDF(...), {mtl_no}))\n"
                i = arg_end + 1
                
            elif func_type in ["opS", "opI"]:
                # Subtract/Intersect: opU(mint, opU(..., ...))
                # Source snippet shows nested opU calls for S/I
                # Exact argument parsing logic is not fully detailed in the source [S2, unofficial]
                generated_sdf_code += f"// op{func_type} generation placeholder based on source structure [S2, unofficial]\n"
                i = func_end + 1
                
            elif func_type == "opUs":
                # Smooth Union: min(a,b) - k * max(0, min(a,b))
                # Parse k parameter
                k_val = 0.1  # Default k if not parsed [G]
                k_idx = ps_code.find('#k', i)
                if k_idx != -1:
                    k_end = ps_code.find('\n', k_idx)
                    if k_end == -1: k_end = len(ps_code)
                    try:
                        k_val = float(ps_code[k_idx+2:k_end].strip())
                    except ValueError:
                        pass
                arg_end = ps_code.find(' ', func_end)
                if arg_end == -1: arg_end = len(ps_code)
                arg1 = ps_code[func_end+1:arg_end].strip()
                generated_sdf_code += f"min({arg1}, vec2(fSDF(...), {mtl_no})) - {k_val} * max(0.0, min({arg1}, vec2(fSDF(...), {mtl_no})))\n"
                i = arg_end + 1
                
        elif char == '!':
            # Direct line insertion [S2, unofficial]
            line_end = ps_code.find('\n', i)
            if line_end == -1: line_end = len(ps_code)
            generated_sdf_code += ps_code[i+1:line_end] + "\n"
            i = line_end + 1
            
        else:
            i += 1

    # Step 7: Insert generated code
    final_code = real_code[:scene_r] + generated_sdf_code + real_code[scene_r + len(scene_marker):]
    
    return final_code
```

### Pitfalls
- **Marker Conflicts**: The script parser uses fixed string markers (`@i`, `#`, `!`) which can conflict with standard GLSL syntax if not carefully escaped or structured in the script file [S2, unofficial].
- **Sub-function Assumptions**: The `findSubFunc` lambda assumes specific marker formats (`m` for matrix, `v` for vector) and may break if the script deviates from these expected formats [S2, unofficial].

## Subtopics

### SDF to Density Conversion
Converts the scalar SDF field into density values for volume rendering. Choose this when you need to render the SDF as a volumetric cloud or fog rather than a surface. [SDF to Density Conversion](1282-sdf-to-density-conversion.md)

### Constrained Jacobi Smoothing for SDFs
Applies smoothing to the SDF field to reduce aliasing and improve normal estimation. Choose this when the generated SDF is too noisy or jagged for ray marching. [Constrained Jacobi Smoothing for SDFs](1583-constrained-jacobi-smoothing-for-sdfs.md)

### SDF Volume Generation & Ping-Pong Buffering
Generates the SDF volume data using GPU ping-pong buffers. Choose this when you need to pre-compute the SDF into a texture for ray marching, rather than computing it in the shader. [SDF Volume Generation & Ping-Pong Buffering](4570-sdf-volume-generation-ping-pong-buffering.md)

### Volume SDF
Renders SDFs directly as volumes. Choose this for specific volumetric rendering techniques that utilize the SDF as a density proxy. [Volume SDF](11033-volume-sdf.md)

### RobotSDF
Specialized SDF generation for robotic environments. Choose this when the scene consists of robot kinematics or specific industrial geometries. [RobotSDF](13070-robotsdf.md)

### Volume Fairing via Signed Distance Functions
Smooths and fairing volumetric data using SDF properties. Choose this for cleaning up noisy volumetric scans. [Volume Fairing via Signed Distance Functions](14492-volume-fairing-via-signed-distance-functions.md)

## Background
The method originates from an unofficial C++ implementation found in the `trimesh33/sdf` repository [S2, unofficial]. It is designed to work with GLUT 3.1+ and Mesa 2.5+ environments, leveraging early GLUT 4 routines and signal handling [S2, unofficial]. The approach is part of a broader effort to simplify SDF scene composition in real-time graphics by abstracting the GLSL boilerplate [S2, unofficial]. The `Animate()` construct was added to the DSL to facilitate easier interactive edits and animations of the output GLSL shader, as the compiler-generated code is less readable than manually written programs [S1].
