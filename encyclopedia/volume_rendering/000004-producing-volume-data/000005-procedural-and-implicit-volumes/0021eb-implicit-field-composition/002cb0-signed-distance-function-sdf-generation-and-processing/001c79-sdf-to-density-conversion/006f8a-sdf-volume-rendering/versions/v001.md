# SDF Volume Rendering

Also called: Volume SDF Rendering, Signed Distance Field Volume Rendering, Volume Rendering from SDF, SDF → density volume rendering

## Overview
SDF Volume Rendering is a technique that integrates color and density along rays sampled from an implicit Signed Distance Function (SDF) [S1, unofficial]. It converts SDF values to density using a Laplace distribution CDF and aggregates color using standard volume rendering weights [S1, unofficial]. Unlike standard volume rendering which uses raw density fields, this method leverages the geometric priors of the SDF to better recover underlying geometry [S6]. It differs from [SDF Alpha Computation](3643-sdf-alpha-computation.md) by explicitly converting distance to volumetric density for integration rather than computing alpha directly for compositing [S3].

## How it works
**Inputs:**
- Ray bundle containing origins $\mathbf{o}$ and directions $\boldsymbol{\omega}$ [S7, unofficial].
- Implicit SDF function $f(\mathbf{x})$ returning signed distance and optionally color/features [S1, unofficial].
- Parameters $\alpha$ (scaling factor) and $\beta$ (scale parameter for Laplace distribution) [S1, unofficial].
- Small constant $\epsilon = 10^{-10}$ for numerical stability [S1, unofficial].

**Outputs:**
- Rendered color tensor of shape $(H, W, 3)$ [S7, unofficial].

**Data Structures:**
- `RayBundle`: Contains `origins` (shape $N, 3$), `directions` (shape $N, 3$), and `sample_points` (shape $N, D, 3$) [S7, unofficial].
- `deltas`: Tensor of shape $(N, D, 1)$ representing segment lengths [S1, unofficial].

**Steps:**

1. **Ray Sampling:** Sample points along rays using a sampler (e.g., StratifiedRaysampler) to get `sample_points` and depth values [S1, unofficial].
2. **SDF Evaluation:** Query the implicit function for distance and color at sample points:
   $$ \text{distance}, \text{color} = \text{implicit\_fn}(\text{sample\_points}) $$
   [S1, unofficial]
3. **Delta Computation:** Compute segment lengths $\Delta t$ from depth values. For $D$ points, concatenate differences between consecutive depth values with a large constant ($10^{10}$) at the end to handle the last segment [S1, unofficial].
   $$ \delta_i = t_{i+1} - t_i \quad \text{for } i < D-1 $$
   $$ \delta_{D-1} = 10^{10} $$
   [S1, unofficial]
   This large value ensures that if a ray does not hit a surface within the sampled range, the transmittance decays sufficiently, preventing artifacts from the infinite tail of the ray [S1, unofficial].
4. **SDF to Density Conversion:** Convert signed distance $d$ to density $\rho$ using the Laplace distribution CDF [S1, unofficial]:
   $$ \rho = \alpha \cdot \text{CDF}_{\text{Laplace}(0, \beta)}(-d) $$
   [S1, unofficial]
   Explicitly:
   $$ \rho = \begin{cases} 0.5 \alpha e^{-d/\beta} & d > 0 \\ \alpha (1 - 0.5 e^{d/\beta}) & d \le 0 \end{cases} $$
   [S4, unofficial]
5. **Transmittance and Weight Calculation:** Initialize $T_0 = 1$. For $i$ from 1 to $D$:
   $$ T_i = T_{i-1} \cdot \exp(-\rho_{i-1} \cdot \delta_{i-1} + \epsilon) $$
   [S1, unofficial]
   Weights are:
   $$ w_i = T_i \cdot (1 - \exp(-\rho_i \cdot \delta_i + \epsilon)) $$
   [S1, unofficial]
6. **Color Aggregation:** Aggregate color by summing the product of weights and per-sample colors:
   $$ C = \sum_{i=1}^N w_i \cdot \text{color}_i $$
   [S1, unofficial]

**Pseudocode:**

```python
import torch
import torch.nn.functional as F

def sdf_volume_rendering(ray_bundle, implicit_fn, alpha, beta, eps=1e-10):
    """
    ray_bundle: object with origins (N, 3), directions (N, 3), and sample_points (N, D, 3)
    implicit_fn: callable returning (distance, color) for points
    alpha: scaling factor
    beta: scale parameter for Laplace distribution
    eps: small constant for stability
    """
    # 1. Get sample points and depths from ray_bundle
    sample_points = ray_bundle.sample_points  # (N, D, 3)
    depths = sample_points[..., 0] * ray_bundle.directions[..., 0] + \
             sample_points[..., 1] * ray_bundle.directions[..., 1] + \
             sample_points[..., 2] * ray_bundle.directions[..., 2]
    # Note: Assuming ray_bundle provides depths or they are computed from origins and directions
    # In many implementations, ray_bundle.sample_points are pre-computed along the ray.
    # We need depths to compute deltas. Let's assume ray_bundle has a 'depths' attribute or we compute it.
    # For simplicity, if sample_points are along the ray, we can compute depths as dot product with direction if origin is 0,
    # but generally ray_bundle should provide depths. Let's assume ray_bundle.depths exists (N, D).
    if not hasattr(ray_bundle, 'depths'):
        # Fallback: compute depths if origins are zero or known. 
        # Standard RayBundle usually has depths. We will assume it does for correctness.
        raise ValueError("RayBundle must have 'depths' attribute of shape (N, D)")
    depths = ray_bundle.depths  # (N, D)

    # 2. Evaluate SDF
    # implicit_fn returns distance and color
    # distance: (N, D), color: (N, D, 3)
    distance, color = implicit_fn(sample_points)

    # 3. Compute deltas
    # deltas = torch.cat((depths[..., 1:] - depths[..., :-1], 1e10 * torch.ones_like(depths[..., :1])), dim=-1)
    # Shape: (N, D)
    deltas = torch.cat((depths[..., 1:] - depths[..., :-1], 1e10 * torch.ones_like(depths[..., :1])), dim=-1)
    deltas = deltas.unsqueeze(-1)  # (N, D, 1)

    # 4. Convert SDF to density
    # rho = alpha * CDF_Laplace(-distance)
    # Laplace CDF: 0.5 * exp(-|x|/b) for x<0, 1 - 0.5 * exp(x/b) for x>=0? 
    # Wait, Laplace(0, beta) CDF:
    # if x < 0: 0.5 * exp(x/beta)
    # if x >= 0: 1 - 0.5 * exp(-x/beta)
    # We want CDF(-d). Let x = -d.
    # if -d < 0 => d > 0: 0.5 * exp(-d/beta)
    # if -d >= 0 => d <= 0: 1 - 0.5 * exp(d/beta)
    # This matches the formula in [S4, unofficial].
    density = torch.where(
        distance > 0,
        0.5 * torch.exp(-distance / beta),
        1 - 0.5 * torch.exp(distance / beta),
    ) * alpha

    # 5. Compute transmittance and weights
    # T_0 = 1
    # T_i = T_{i-1} * exp(-rho_{i-1} * delta_{i-1} + eps)
    # w_i = T_i * (1 - exp(-rho_i * delta_i + eps))
    
    # Initialize T
    T = torch.ones_like(density[..., 0])  # (N,)
    T = T.unsqueeze(-1)  # (N, 1)
    
    weights_list = []
    T_prev = T
    
    for i in range(density.shape[1]):
        # T_i = T_{i-1} * exp(-rho_{i-1} * delta_{i-1} + eps)
        # Note: The loop index i in the formula corresponds to sample i.
        # T_i is transmittance BEFORE sample i.
        # T_0 = 1.
        # For i=0: T_0 = 1. w_0 = T_0 * (1 - exp(-rho_0 * delta_0 + eps))
        # For i=1: T_1 = T_0 * exp(-rho_0 * delta_0 + eps). w_1 = T_1 * (1 - exp(-rho_1 * delta_1 + eps))
        
        # Calculate weight for current sample i
        # w_i = T_i * (1 - exp(-rho_i * delta_i + eps))
        # But T_i is computed from previous step.
        # Let's adjust loop to match standard volume rendering accumulation.
        
        # Actually, standard code:
        # T.append(T_im1 * exp(-rho_{i-1} * delta_{i-1}))
        # weights = T * (1 - exp(-rho * delta))
        
        # Let's follow [S1, unofficial] code structure:
        # T is a list. T[0] = 1.
        # For i in 1..D: T[i] = T[i-1] * exp(-rho[i-1] * delta[i-1])
        # weights[i] = T[i] * (1 - exp(-rho[i] * delta[i]))
        
        pass # We will compute vectorized below for efficiency, but loop is clearer for explanation.
    
    # Vectorized implementation
    # T_i = product_{j=0}^{i-1} exp(-rho_j * delta_j + eps)
    # log_T_i = sum_{j=0}^{i-1} (-rho_j * delta_j + eps)
    # T_i = exp(log_T_i)
    
    # Exponent term
    exponent = -density * deltas + eps  # (N, D, 1)
    
    # Cumulative sum of exponents for T
    # T_i = exp(sum_{j=0}^{i-1} exponent_j)
    # We need cumulative sum along D dimension, but T_i uses j < i.
    # So for i=0, sum is empty -> 0 -> exp(0)=1.
    # For i=1, sum is exponent_0.
    
    # Shift exponent to compute T
    # T[i] = exp(cumsum(exponent[:, :i]))
    
    # Let's compute cumulative sum
    cumsum_exponent = torch.cumsum(exponent, dim=1)  # (N, D, 1)
    # T[i] corresponds to cumsum up to i-1.
    # So T = exp(cumsum_exponent shifted by 1)
    # T_0 = 1
    # T_1 = exp(exponent_0)
    # T_i = exp(sum_{j=0}^{i-1} exponent_j)
    
    # Create T tensor
    # T = torch.cat([torch.ones(N, 1, 1), torch.exp(cumsum_exponent[:, :-1, :])], dim=1)
    # But cumsum_exponent[:, i-1] is sum_{j=0}^{i-1} exponent_j.
    # So T[:, i] = exp(cumsum_exponent[:, i-1]) for i>0.
    
    # Efficient way:
    # log_T = torch.cat([torch.zeros(N, 1, 1), cumsum_exponent[:, :-1, :]], dim=1)
    # T = torch.exp(log_T)
    
    # However, [S1, unofficial] code:
    # T.append(T_im1 * torch.exp(-rays_density[:, i-1] * deltas[:, i-1]+eps))
    # This implies T[i] is computed from T[i-1].
    
    # Let's stick to the loop for clarity in pseudocode if vectorization is complex, 
    # but vectorization is preferred.
    
    # Re-evaluating [S1, unofficial] code:
    # T = [1]
    # for i in 1..D:
    #    T.append(T[-1] * exp(-rho[i-1] * delta[i-1] + eps))
    # weights = T * (1 - exp(-rho * delta + eps))
    
    # So T has length D+1. T[0]=1. T[1] = T[0]*exp(-rho[0]*delta[0]).
    # weights[i] = T[i] * (1 - exp(-rho[i]*delta[i])).
    
    # Vectorized:
    # T_shifted = torch.cat([torch.zeros(N, 1, 1), cumsum_exponent[:, :-1, :]], dim=1)
    # T = torch.exp(T_shifted)
    # weights = T * (1 - torch.exp(exponent))
    
    # Wait, cumsum_exponent[:, i] is sum_{j=0}^i exponent_j.
    # We want T[i] = exp(sum_{j=0}^{i-1} exponent_j).
    # So T[i] = exp(cumsum_exponent[:, i-1]) for i>0.
    # T[0] = 1.
    
    # Let's compute T
    # T = torch.zeros(N, D, 1)
    # T[:, 0, :] = 1
    # T[:, 1:, :] = torch.exp(cumsum_exponent[:, :-1, :])
    
    # Actually, simpler:
    # log_T = torch.cat([torch.zeros(N, 1, 1), cumsum_exponent[:, :-1, :]], dim=1)
    # T = torch.exp(log_T)
    
    # But cumsum_exponent[:, i-1] is sum_{j=0}^{i-1} exponent_j.
    # So log_T[:, i] = sum_{j=0}^{i-1} exponent_j.
    # T[:, i] = exp(sum_{j=0}^{i-1} exponent_j).
    
    # Correct.
    
    log_T = torch.cat([torch.zeros_like(exponent[:, :1, :]), cumsum_exponent[:, :-1, :]], dim=1)
    T = torch.exp(log_T)
    
    weights = T * (1 - torch.exp(exponent))
    
    # 6. Aggregate color
    # color: (N, D, 3)
    # weights: (N, D, 1)
    # result: (N, 3)
    color = torch.sum(weights * color, dim=1)
    
    return color
```

## Subtopics

### [VolSDF Volume Rendering](2551-volsdf-volume-rendering.md)
VolSDF Volume Rendering performs volume integration using Signed Distance Functions (SDFs) as the underlying geometric representation instead of raw density fields. It addresses optimization instability by converting SDF values into volumetric densities using learnable scaling and shrinking coefficients before applying standard alpha compositing. Unlike [Volume SDF Rendering](1344-volume-sdf-rendering.md), VolSDF explicitly learns these coefficients to ensure alpha-invariance, meaning the magnitude of the volume density function is globally tied to its sharpness.

### NeUDF
NeUDF is a neural rendering framework that reconstructs surfaces with arbitrary topologies, including open surfaces, from multi-view 2D image supervision by leveraging the Unsigned Distance Function (UDF) as the implicit surface representation [S1, unofficial]. Unlike its sibling [Volume SDF Rendering](1344-volume-sdf-rendering.md), which is limited to closed (watertight) surfaces, NeUDF resolves the ambiguity of surface orientation in open structures by introducing a specialized "Udensity" probability density function and a normal regularization strategy [S1, unofficial]. It differs from naive extensions of SDF-based rendering by avoiding spurious surfaces in void regions through an unbiased, occlusion-aware weighting paradigm tailored for UDFs [S1, unofficial].

### [SRDF-based Volume Rendering](15314-srdf-based-volume-rendering.md)
SRDF-based Volume Rendering is a neural scene reconstruction technique that models volume density using a Ray-Specific Signed Distance Function (SRDF) rather than a global Signed Distance Function (SDF). It solves the problem of false local maxima in volume density caused by surfaces not intersecting the camera ray, which leads to inaccurate depth and noisy surface reconstruction in multi-object indoor scenes. Unlike standard SDF-based methods where density is derived from a global field, SRDF computes the shortest distance to the surface *along the sampled ray direction*, ensuring that density peaks only around the actual surface intersection. This method is distinct from [NeUDF](3821-neudf.md) by explicitly decoupling the ray-specific density modeling from the global surface representation.

### [Learnable Alpha/Beta SDF Density Modulation](18988-learnable-alpha-beta-sdf-density-modulation.md)
This method modulates volume density in a Signed Distance Function (SDF) representation using two separate learnable parameters, $\alpha$ and $\beta$, rather than tying them equal as in prior work. It solves the convergence instability issues found in methods that use a single tied parameter by allowing independent optimization of the density scale and shape. It differs from [VolSDF Volume Rendering](2551-volsdf-volume-rendering.md) by decoupling the $\alpha$ and $\beta$ parameters.

### Chunked VolSDF Rendering
Chunked VolSDF Rendering processes rays in chunks to manage memory usage during training. It gets the total number of rays $N$ from `ray_bundle.origins.shape[0]`, initializes an empty list `chunk_colors`, and loops over chunks. For each chunk, it slices the `ray_bundle`, calls the parent forward method to get `cur_color`, appends it to the list, and finally concatenates all chunk colors along dimension 0 [S7, unofficial]. The parameter `chunk_size` defines the maximum number of rays processed in a single forward pass [S7, unofficial].

### NeuS Volume Rendering Transformation
NeuS Volume Rendering Transformation is a method that transforms Signed Distance Function (SDF) values into volumetric densities for alpha compositing, ensuring the CDF of volume rendering matches a scaled, flipped sigmoid shape [S9]. The transmittance $T(t)$ is related to the SDF $S(t)$ by $1 - T(t) = \text{sigmoid}(s \cdot -SDF(t))$, where $s$ is a global scaling coefficient [S9]. The weighting function $w(t)$ (derivative of CDF) has local maxima at SDF value 0 [S9]. NeuS ties the magnitude of volume density globally to its sharpness via the sigmoid parameter $s$, which is an alpha-invariant formulation by default but restrictive [S9].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of samples per ray and the number of rays. The SDF evaluation is the dominant cost if the implicit function is complex (e.g., a deep MLP).
- **Memory Complexity:** Linear with respect to the number of samples and rays, as all distances, colors, and transmittances must be stored for backpropagation. Chunking can reduce peak memory usage [S7, unofficial].
- **Strengths:** Better recovery of underlying geometry compared to direct density encoding [S6]. The SDF provides a strong geometric prior, leading to sharper surfaces and better regularization [S5].
- **Limitations:** Requires careful tuning of $\alpha$ and $\beta$ or learning them. The assumption that density is derived from a global SDF may not hold for open surfaces or complex topologies without modifications like NeUDF [S1, unofficial].
- **When to use:** When geometric accuracy is prioritized over appearance flexibility, or when training from multi-view images where surface reconstruction is the goal [S7, unofficial].
- **When not to use:** For open surfaces (use NeUDF) or when ray-specific density modeling is needed to avoid false maxima (use SRDF) [S1, unofficial].

## Background
Originating from the need to improve geometric reconstruction in neural rendering, SDF Volume Rendering was introduced as an alternative to NeRF's direct density encoding. VolSDF [S2, unofficial] and NeuS [S9] demonstrated that modeling density as a transformed function of an implicit SDF enables better recovery of underlying geometry [S6]. The method maps the SDF to a volume density function, assigning a value of 1 to points on the zero-level set and 0 to points far from this set [S5]. It is widely used in neural surface reconstruction from multi-view images [S7, unofficial].
