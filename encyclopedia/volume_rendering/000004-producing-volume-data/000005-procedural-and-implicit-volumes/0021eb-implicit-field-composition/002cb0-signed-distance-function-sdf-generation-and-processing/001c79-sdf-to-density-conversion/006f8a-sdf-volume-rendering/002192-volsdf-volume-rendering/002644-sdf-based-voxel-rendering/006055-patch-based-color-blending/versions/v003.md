# Patch-based Color Blending


## Overview
Patch-based Color Blending is a technique for jointly evaluating local and contextual radiance consistency to produce more reliable color predictions than single-pixel blending [S1]. It renders colors for a local patch of size $k \times k$ instead of a single pixel, leveraging the local surface assumption and homography transformation to efficiently derive colors from multiple input views [S1]. This method is chosen when regions have weak texture or changing intensity, as it produces more informative and consistent shape context by incorporating neighboring geometric information [S1].

## How it works
**Inputs:**
- A query ray $r$ and a set of sampled points $q$ along the ray [S1].
- A signed distance function (SDF) network $s(\cdot)$ to estimate normals [S1].
- $N$ input views $\{I_i\}_{i=0}^{N-1}$ with known poses and intrinsic matrices [S1].
- Blending weights $w_i$ for each input view [S1].
- Patch dimension $k$ [S1].

**Outputs:**
- Final predicted patch colors for the ray, aggregated via volume rendering [S1].

**Data Structures:**
- **Local Plane Points:** A set of 2D coordinates $\mathcal{P}_q$ centered at $q$ on the tangent plane defined by normal $n_q$, representing a $k \times k$ grid [S1].
- **Homography Matrix $H$:** A $3 \times 3$ matrix mapping points from the rendered view $I_r$ to input view $I_i$ [S1].

**Steps:**

1.  **Estimate Normal:** For a sampled point $q$ on the query ray, compute the spatial gradient of the SDF network to estimate the surface normal direction $n_q$:
    $$ n_q = \nabla s(q) $$
    [S1]

2.  **Define Local Plane Points:** Select a set of points $\mathcal{P}_q$ on the local plane defined by $(q, n_q)$ [S1].

3.  **Compute Homography:** For each input view $I_i$ (where $i \neq r$), compute the homography matrix $H$ between the rendered view $I_r$ and $I_i$, induced by the local plane $(q, n_q)$:
    $$ H = K \left( R_i + \frac{t_i n_q^T R_r^T}{n_q^T (q + R_r^T t_r)} \right) K^{-1} $$
    where:
    - $K$ is the camera intrinsic matrix [S1].
    - $R_i$ is the $3 \times 3$ rotation matrix of $I_i$ relative to $I_r$ [S1].
    - $t_i$ is the 3D translation vector of $I_i$ relative to $I_r$ [S1].
    - $(R_r, t_r)$ is the pose of the rendered view $I_r$ in the world coordinate system [S1].
    - $n_q$ is the normal vector at $q$ [S1].
    [S1]

4.  **Project and Interpolate Colors:** Apply the homography $H$ to the set of points $\mathcal{P}_q$ to obtain their projected pixel locations in view $I_i$ [S1]. For each point in $\mathcal{P}_q$, obtain its color by interpolation on the input image $I_i$ [S1]. Specifically, for the center point $q$, the projected pixel location $H_q$ on the view $I_i$ is obtained by the matrix product of $H$ and $q$ (in homogeneous coordinates), and its color is interpolated [S1].

5.  **Assign Blending Weights:** Assign the same blending weights $w_i$ to all points on the local plane $\mathcal{P}_q$ [S1]. This requires only one query of the blending weights for the entire patch [S1].

6.  **Blend Patch Colors:** Blend the patch colors interpolated from each of the $N-1$ input views $\{I_i\}_{i=0}^{N-1}$ using the blending weights $w_i$ to obtain the final patch colors for point $q$ [S1]. Let $C_i(p)$ be the color of point $p \in \mathcal{P}_q$ in view $I_i$ [S1]. The blended color for point $p$ is:
    $$ C_{patch}(p) = \sum_{i=0}^{N-1} w_i C_i(p) $$
    [S1]

7.  **Volume Rendering Aggregation:** Use SDF-based volume rendering to aggregate the interpolated patch colors of all points sampled in the query ray $r$ to generate the final predicted patch colors of the ray [S1].

**Pseudocode:**

```python
import numpy as np

def generate_patch_grid(q_2d, k):
    """Generate k x k grid of 2D homogeneous coordinates centered at q_2d."""
    half = (k - 1) / 2.0
    grid = []
    for dy in range(k):
        for dx in range(k):
            x = q_2d[0] + (dx - half)
            y = q_2d[1] + (dy - half)
            grid.append([x, y, 1.0])
    return np.array(grid)

def compute_homography(K, R_i, t_i, n_q, q_3d, R_r, t_r):
    """Compute plane-induced homography H from rendered view I_r to input view I_i."""
    denom = np.dot(n_q, q_3d + R_r.T @ t_r)
    # t_i is (3,), n_q^T R_r^T is (3,). Outer product gives (3,3) matrix.
    num_term = np.outer(t_i, n_q @ R_r.T)
    inner_matrix = R_i + num_term / denom
    H = K @ inner_matrix @ np.linalg.inv(K)
    return H

def interpolate_colors(image, projected_points):
    """Nearest-neighbor interpolation of image at projected_points (N, 2)."""
    h, w, _ = image.shape
    ys = np.clip(projected_points[:, 0], 0, h - 1).astype(int)
    xs = np.clip(projected_points[:, 1], 0, w - 1).astype(int)
    return image[ys, xs]

def patch_based_color_blending(q_3d, q_2d, n_q, K, poses, images, weights, k, R_r, t_r):
    """
    q_3d: 3D point on the ray
    q_2d: 2D projection of q_3d in rendered view I_r (homogeneous)
    n_q: Normal vector at q
    K: Intrinsic matrix (3x3)
    poses: List of (R_i, t_i) for each input view i
    images: List of input images I_i
    weights: Blending weights w_i for each view
    k: Patch dimension (k x k)
    R_r, t_r: Pose of the rendered view I_r
    """
    patch_points = generate_patch_grid(q_2d, k)
    blended_patch_colors = np.zeros((k * k, 3))

    for i, (R_i, t_i) in enumerate(poses):
        # Step 3: Compute Homography H
        H = compute_homography(K, R_i, t_i, n_q, q_3d, R_r, t_r)

        # Step 4: Project and Interpolate Colors
        projected = patch_points @ H.T
        projected_2d = projected[:, :2] / projected[:, 2:3]
        colors_i = interpolate_colors(images[i], projected_2d)

        # Step 5 & 6: Assign Weights and Blend Patch Colors
        blended_patch_colors += weights[i] * colors_i

    return blended_patch_colors
```

**Parameters:**
- Patch size $k \times k$: The dimension of the patch used for blending [S1].

## Operating characteristics
- **Time Complexity:** Not given in the sources. [S1]
- **Memory Complexity:** Not given in the sources. [S1]
- **Strengths:** Produces more reliable color predictions in regions with weak texture or changing intensity by leveraging contextual information [S1]. Enforces better geometric consistency [S1].
- **Limitations:** Computationally more expensive than pixel-based blending due to processing $k^2$ points per sample and computing homographies for each view [S1].
- **When to Use:** When high-quality color synthesis is needed in textureless or low-texture regions [S1].

## Background
Patch-based Color Blending was introduced in the SparseNeuS paper by Xiaoxiao Long, Cheng Lin, Peng Wang, Taku Komura, and Wenping Wang in 2022 [S1]. It is part of the SparseNeuS framework for fast generalizable neural surface reconstruction from sparse views [S1]. The method builds on SDF-based voxel rendering and aims to improve color prediction reliability by considering local context [S1].
