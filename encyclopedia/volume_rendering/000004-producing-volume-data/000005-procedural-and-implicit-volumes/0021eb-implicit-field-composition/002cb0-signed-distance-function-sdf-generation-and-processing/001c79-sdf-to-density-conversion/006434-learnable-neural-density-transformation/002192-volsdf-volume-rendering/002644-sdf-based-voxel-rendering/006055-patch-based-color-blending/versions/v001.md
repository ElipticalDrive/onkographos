# Patch-based Color Blending

Also called: Patch-based Volume Rendering, Homography-based Patch Blending

## Overview
Patch-based Color Blending is a technique for jointly evaluating local and contextual radiance consistency to produce more reliable color predictions than single-pixel blending [S1]. It renders colors for a local patch of size $k \times k$ instead of a single pixel, leveraging the local surface assumption and homography transformation to efficiently derive colors from multiple input views [S1]. This method is chosen when regions have weak texture or changing intensity, as it produces more informative and consistent shape context by incorporating neighboring geometric information [S1].

## How it works
**Inputs:**
- A query ray $r$ and a set of sampled points $q$ along the ray.
- A signed distance function (SDF) network $s(\cdot)$ to estimate normals.
- $N$ input views $\{I_i\}_{i=0}^{N-1}$ with known poses and intrinsic matrices.
- Blending weights $w_i$ for each input view (computed via a separate weight prediction module, assumed available).
- Patch dimension $k$ (odd integer, e.g., 3, 5).

**Outputs:**
- Final predicted patch colors for the ray, aggregated via volume rendering.

**Data Structures:**
- **Local Plane Points:** A set of 3D points $\mathcal{P}_q$ centered at $q$ on the tangent plane defined by normal $n_q$. For a $k \times k$ patch, this contains $k^2$ points.
- **Homography Matrix $H$:** A $3 \times 3$ matrix mapping points from the rendered view $I_r$ to input view $I_i$.

**Steps:**

1.  **Estimate Normal:** For a sampled point $q$ on the query ray, compute the spatial gradient of the SDF network to estimate the surface normal direction $n_q$:
    $$ n_q = \nabla s(q) $$
    [S1]

2.  **Define Local Plane Points:** Select a set of points $\mathcal{P}_q$ on the local plane defined by $(q, n_q)$. These points represent the $k \times k$ patch centered at $q$. The points are typically generated by offsetting $q$ along the tangent basis vectors of the plane [S1].

3.  **Compute Homography:** For each input view $I_i$ (where $i \neq r$), compute the homography matrix $H$ between the rendered view $I_r$ and $I_i$, induced by the local plane $(q, n_q)$:
    $$ H = K \left( R_i + \frac{t_i n_q^T R_r^T}{n_q^T (q + R_r^T t_r)} \right) K^{-1} $$
    where:
    - $K$ is the camera intrinsic matrix.
    - $R_i$ is the $3 \times 3$ rotation matrix of $I_i$ relative to $I_r$.
    - $t_i$ is the 3D translation vector of $I_i$ relative to $I_r$.
    - $(R_r, t_r)$ is the pose of the rendered view $I_r$ in the world coordinate system.
    - $n_q$ is the normal vector at $q$.
    [S1]

4.  **Project and Interpolate Colors:** Apply the homography $H$ to the set of points $\mathcal{P}_q$ to obtain their projected pixel locations in view $I_i$. For each point in $\mathcal{P}_q$, obtain its color by interpolation on the input image $I_i$. Specifically, for the center point $q$, the projected pixel location $H_q$ is obtained by the matrix product of $H$ and $q$ (in homogeneous coordinates), and its color is interpolated [S1].

5.  **Assign Blending Weights:** Assign the same blending weights $w_i$ to all points on the local plane $\mathcal{P}_q$. This requires only one query of the blending weights for the entire patch, assuming the weight prediction is based on the central point $q$ [S1].

6.  **Blend Patch Colors:** Blend the patch colors interpolated from each of the $N-1$ input views $\{I_i\}_{i=0}^{N-1}$ using the blending weights $w_i$ to obtain the final patch colors for point $q$. Let $C_i(p)$ be the color of point $p \in \mathcal{P}_q$ in view $I_i$. The blended color for point $p$ is:
    $$ C_{patch}(p) = \sum_{i=0}^{N-1} w_i C_i(p) $$
    [S1]

7.  **Volume Rendering Aggregation:** Use SDF-based volume rendering to aggregate the interpolated patch colors of all points sampled in the query ray $r$ to generate the final predicted patch colors of the ray. This follows the standard volume rendering integral, but using the patch colors $C_{patch}$ instead of single-pixel colors [S1].

**Pseudocode:**

```python
def patch_based_color_blending(q, n_q, K, poses, images, weights, k):
    """
    q: 3D point on the ray
    n_q: Normal vector at q
    K: Intrinsic matrix (3x3)
    poses: List of (R_i, t_i) for each input view i
    images: List of input images I_i
    weights: Blending weights w_i for each view
    k: Patch dimension (k x k)
    """
    # Step 2: Generate local plane points
    # Generate k x k grid of points on the tangent plane at q with normal n_q
    # This requires constructing a local basis from n_q and offsetting by patch size
    patch_points = generate_local_plane_points(q, n_q, k)
    
    blended_patch_colors = []
    
    # Step 3-6: For each input view
    for i, (R_i, t_i) in enumerate(poses):
        # Step 3: Compute Homography H
        # R_r, t_r are the pose of the rendered view (assumed known or identity if local)
        # Note: The formula uses R_r and t_r. In the context of the paper, 
        # these refer to the target view's pose relative to world.
        # Assuming R_r, t_r are available from the rendering context.
        H = compute_homography(K, R_i, t_i, R_r, t_r, n_q, q)
        
        # Step 4: Project points and interpolate colors
        # Project all points in patch_points to view i using H
        projected_points = apply_homography(H, patch_points)
        
        # Interpolate colors from image I_i for each projected point
        # Handle boundary checks and invalid projections
        colors_i = interpolate_colors(images[i], projected_points)
        
        # Step 5: Assign weights (same for all points in patch)
        w_i = weights[i]
        
        # Step 6: Blend colors from this view
        # C_patch(p) = sum(w_i * C_i(p)) across views
        # We accumulate this contribution
        blended_patch_colors.append(w_i * colors_i)
        
    # Sum contributions from all views
    final_patch_colors = sum(blended_patch_colors)
    
    return final_patch_colors

def compute_homography(K, R_i, t_i, R_r, t_r, n_q, q):
    """
    Computes H = K * (R_i + (t_i * n_q^T * R_r^T) / (n_q^T * (q + R_r^T * t_r))) * K^-1
    """
    # Calculate denominator: n_q^T * (q + R_r^T * t_r)
    # Note: q and t_r are column vectors. n_q is column vector.
    # The term (q + R_r^T * t_r) is a 3x1 vector.
    # n_q^T is 1x3. Result is scalar.
    denom = np.dot(n_q.T, q + R_r.T @ t_r)
    
    # Calculate numerator term: t_i * n_q^T * R_r^T
    # t_i is 3x1, n_q^T is 1x3, R_r^T is 3x3.
    # Result is 3x3 matrix.
    num_term = t_i @ (n_q.T @ R_r.T)
    
    # Calculate inner matrix: R_i + num_term / denom
    inner_matrix = R_i + num_term / denom
    
    # Final H = K * inner_matrix * K^-1
    H = K @ inner_matrix @ np.linalg.inv(K)
    
    return H
```

**Parameters:**
- Patch size $k \times k$: The dimension of the patch used for blending. Typical values are small odd integers (e.g., 3, 5) to capture local context without excessive computational cost [S1].

**Edge Cases and Pitfalls:**
- **Normal Estimation:** If the SDF gradient $\nabla s(q)$ is zero or noisy, the normal $n_q$ will be inaccurate, leading to incorrect homography and misaligned patches [S1].
- **Homography Singularity:** If the denominator $n_q^T (q + R_r^T t_r)$ is close to zero, the homography becomes unstable. This occurs when the local plane is parallel to the ray direction or the camera center lies on the local plane [S1].
- **Boundary Conditions:** Points in the patch may project outside the image boundaries of input views. Interpolation should handle these cases (e.g., by ignoring or padding) [S1].
- **Weight Consistency:** The assumption that all points in the patch share the same blending weights may not hold if the patch spans regions with significantly different visibility or texture quality [S1].

## Operating characteristics
- **Time Complexity:** Higher than pixel-based blending due to the need to process $k^2$ points per sample and compute homographies for each view. However, the homography allows efficient batched interpolation.
- **Memory Complexity:** Requires storing the patch points and intermediate projected coordinates.
- **Strengths:** Produces more reliable color predictions in regions with weak texture or changing intensity by leveraging contextual information [S1]. Enforces better geometric consistency [S1].
- **Limitations:** Computationally more expensive than pixel-based blending. Sensitive to normal estimation errors [S1].
- **When to Use:** When high-quality color synthesis is needed in textureless or low-texture regions, and computational resources allow for the additional cost [S1].
- **When Not to Use:** When real-time performance is critical and texture is rich and stable, pixel-based blending may suffice [S1].

## Background
Patch-based Color Blending was introduced in the SparseNeuS paper by Xiaoxiao Long, Cheng Lin, Peng Wang, Taku Komura, and Wenping Wang in 2022 [S1]. It is part of the SparseNeuS framework for fast generalizable neural surface reconstruction from sparse views. The method builds on SDF-based voxel rendering and aims to improve color prediction reliability by considering local context [S1].
