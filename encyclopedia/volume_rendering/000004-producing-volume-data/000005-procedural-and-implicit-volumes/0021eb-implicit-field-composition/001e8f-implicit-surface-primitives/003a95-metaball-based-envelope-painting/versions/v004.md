# Metaball-based Envelope Painting

Also called: 3D Envelope Painting, 3D Painting Metaphor for Envelope Definition, 3D Painting Metaphor for VOI Definition, Metaball-based envelope definition, Thick Paint Metaphor, Volume Painting

## Overview
Metaball-based Envelope Painting is an interaction model for defining a Volume of Interest (VOI) or Region of Interest (ROI) within unsegmented volumetric data by "painting" an implicit envelope around features of interest [S1][S2, unofficial]. It solves the problem of intuitive, context-preserving volume exploration by replacing complex transfer function tuning with a direct spatial marking metaphor [S1]. Unlike techniques using independent surface-bound brushes or fixed-depth peeling regions, this method uses a higher-level shape representation (Metaballs) to create organic, merging envelopes that allow for real-time previewing of the visualization effect before final deposition [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric dataset $V$, camera parameters, user input (mouse position, button states) [S1][S2, unofficial].
*   **Output:** A composite image showing the volume with two distinct visualization styles: one for the interior of the envelope (VOI) and one for the exterior, combined via depth peeling [S1].

**Data Structures:**
*   **Metaball List:** A dynamic list of metaball primitives [S1]. Each metaball $M_i$ is defined by:
    *   Center position $\vec{c}_i \in \mathbb{R}^3$ [S1].
    *   Radius/Scale $r_i \in \mathbb{R}^+$ [S1].
    *   Polarity $p_i \in \{+1, -1\}$ (positive for painting, negative for erasing) [S2, unofficial].
    *   Shape type: Quadric (spherical) or Superquadric (cylindrical/disk) [S1].
*   **Vertex Buffer:** A GPU memory buffer storing the polygonal mesh of the envelope's isosurface, generated by Marching Cubes [S1].
*   **Position/Normal Maps:** On-the-fly generated textures storing the surface position and normal vectors for 3D surface painting mode [S1].

**Mathematical Definition:**
The envelope is defined by a scalar field function $f(\vec{x})$ constructed from the sum of individual metaball fields [S1]. The surface is the isosurface where $f(\vec{x}) = 0$ (or a specific threshold) [S1][S2, unofficial].

The field falloff for a single metaball is modeled using the six-degree Wyvill polynomial [S1]:
$$ f_i(\vec{x}) = \frac{6r_i^6 - 15r_i^4|\vec{x}-\vec{c}_i|^2 + 10r_i^3|\vec{x}-\vec{c}_i|^3}{|\vec{x}-\vec{c}_i|^6} $$
where $|\vec{x}-\vec{c}_i|$ is the distance from point $\vec{x}$ to the metaball center $\vec{c}_i$, and $r_i$ is the radius of the metaball [S1].

The total field is the sum of all active metaballs:
$$ f(\vec{x}) = \sum_{i} p_i \cdot f_i(\vec{x}) $$
where $p_i$ is the polarity (+1 or -1) [S2, unofficial].

**Parameters:**
*   **Brush Tip Shape:** Spherical (default, quadric) or Cylindrical (superquadric, used in 3D Surface Painting Mode) [S1][S2, unofficial].
*   **Brush Tip Polarity:** Positive (paint/add) or Negative (erase/remove) [S2, unofficial].
*   **Cylinder Height:** Adjustable parameter for cylindrical brushes to control penetration depth into the volume surface [S2, unofficial].
*   **MIDA Parameters:** Two separate sets of Maximum Intensity Difference Accumulation (MIDA) visualization parameters are used: one for inside the envelope, one for outside [S1].

**Steps:**
1.  **Initialization:** Load volumetric data and initialize MIDA visualization parameters for inside and outside regions [S1]. Initialize an empty Metaball List [S1]. Generate position and normal maps for the volume surface [S1].
2.  **Preview (Move):** As the user moves the mouse, calculate the 3D position of the brush tip $\vec{c}_{tip}$ [S1]. In **3D Free-hand Mode**: The depth is determined by ray casting or user control [S1]. In **3D Surface Painting Mode**: The depth is overridden by the depth value of the object's surface at the projected position, retrieved from the position map [S1]. The brush orientation aligns with the surface normal from the normal map [S1]. In **2D Screen Painting Mode**: The depth is constant (or discarded), acting as a 2D stencil [S1]. Construct a temporary metaball $M_{tip}$ at $\vec{c}_{tip}$ with current brush parameters [S1]. Evaluate $f(\vec{x})$ for all voxels/samples [S1]. Visualize the volume using the "inside" MIDA parameters for regions where $f(\vec{x})$ indicates inclusion (based on the preview blob) and "outside" parameters otherwise [S1]. This provides real-time feedback [S1][S2, unofficial].
3.  **Deposit (Click):** If the user clicks (e.g., holding Alt key) [S2, unofficial]: Add $M_{tip}$ to the Metaball List [S1]. If polarity is negative, negate the contribution of the new metaball to erase previous painting operations [S2, unofficial].
4.  **Surface Extraction:** Compute the isosurface of the current Metaball List using the Marching Cubes algorithm [S1]. Implement a fast GLSL shader version of Marching Cubes to extract the iso-surface [S1]. Capture the resulting geometry into a memory vertex buffer [S1]. Reuse this buffer for subsequent frames to avoid recomputation [S1].
5.  **Rendering:** Render the volumetric data using the chosen DVR technique (e.g., MIDA) [S1]. Render the polygonal envelope geometry using Front-to-Back Depth Peeling [S1]. This combines the polygon-based envelope geometry and volumetric DVR geometry layer by layer from the camera position, filling gaps between layers with DVR results [S1]. Apply the "inside" visualization style to the volume parts enclosed by the envelope and the "outside" style to the rest [S1]. In 2D mode, the stencil applies the inside style all the way through the volume (X-ray style) [S1][S2, unofficial].
6.  **Editing (Optional):** To carve/peel volume data, set the mapped data intensity range to zero for parts inside or outside the envelope [S1].

**Pseudocode:**

```python
# Global State
metaballs = []
inside_params = {"min": 0.0, "max": 1.0}
outside_params = {"min": 0.0, "max": 1.0}
vertex_buffer = None
pos_map = {"width": 0, "height": 0, "data": []}
norm_map = {"width": 0, "height": 0, "data": []}
current_mode = "3D_FREEHAND"
brush_radius = 1.0
brush_polarity = 1
brush_shape = "quadric"
constant_depth = 10.0
metaballs_changed = False

class Metaball:
    def __init__(self, center, radius, polarity=1, shape='quadric'):
        self.center = center
        self.radius = radius
        self.polarity = polarity
        self.shape = shape

def wyvill_field(x, metaball):
    dx, dy, dz = x[0]-metaball.center[0], x[1]-metaball.center[1], x[2]-metaball.center[2]
    dist_sq = dx*dx + dy*dy + dz*dz
    dist = dist_sq ** 0.5
    if dist < 1e-6: return 1.0
    r = metaball.radius
    numerator = 6*r**6 - 15*r**4*dist_sq + 10*r**3*dist**3
    denominator = dist**6
    return numerator / denominator

def evaluate_field(x):
    total = 0.0
    for mb in metaballs:
        total += mb.polarity * wyvill_field(x, mb)
    return total

def is_inside(x):
    return evaluate_field(x) > 0

def ray_cast_at_depth(screen_x, screen_y, depth):
    return [screen_x * depth, screen_y * depth, depth]

def glsl_marching_cubes(mb_list, isovalue):
    return []

def sample_volume(volume_data, pos, params):
    return [0.0, 0.0, 0.0]

def write_to_framebuffer(color):
    pass

def blend_with_envelope(color, pos, mesh):
    return color

def get_brush_tip_position(screen_x, screen_y):
    if current_mode == "2D_SCREEN":
        return ray_cast_at_depth(screen_x, screen_y, constant_depth), None
    elif current_mode == "3D_SURFACE":
        idx = int(screen_y)*pos_map["width"] + int(screen_x)
        depth = pos_map["data"][idx]
        normal = norm_map["data"][idx]
        return ray_cast_at_depth(screen_x, screen_y, depth), normal
    else:
        return ray_cast_at_depth(screen_x, screen_y, constant_depth), None

def render_frame(camera, volume_data):
    global vertex_buffer, metaballs_changed
    if metaballs_changed:
        mesh = glsl_marching_cubes(metaballs, 0.0)
        vertex_buffer = mesh
        metaballs_changed = False
    for layer in range(10):
        layer_pos = [0.0, 0.0, layer * 0.1]
        color = sample_volume(volume_data, layer_pos, inside_params if is_inside(layer_pos) else outside_params)
        if vertex_buffer:
            color = blend_with_envelope(color, layer_pos, vertex_buffer)
        write_to_framebuffer(color)

def on_mouse_move(screen_x, screen_y):
    tip_pos, tip_normal = get_brush_tip_position(screen_x, screen_y)
    preview_mb = Metaball(tip_pos, brush_radius, brush_polarity, brush_shape)
    metaballs.append(preview_mb)
    render_frame(camera, volume_data)
    metaballs.pop()

def on_mouse_click(screen_x, screen_y):
    tip_pos, tip_normal = get_brush_tip_position(screen_x, screen_y)
    shape = "superquadric" if current_mode == "3D_SURFACE" else "quadric"
    new_mb = Metaball(tip_pos, brush_radius, brush_polarity, shape)
    metaballs.append(new_mb)
    metaballs_changed = True
```

**Edge Cases and Pitfalls:**
*   **Singularity:** The Wyvill polynomial has a singularity at the center of the metaball ($|\vec{x}-\vec{c}_i|=0$). A guard value (e.g., returning 1.0) is required [G].
*   **2D Mode Depth:** In 2D Screen Painting Mode, depth information is discarded, applying the visualization effect through the entire volume along the ray (X-ray style) [S1][S2, unofficial].
*   **Performance:** Geometry recomputation is avoided by reusing the vertex buffer, requiring updates only when the metaball list changes [S1].
*   **Precision:** The six-degree polynomial can suffer from floating-point precision issues at large distances or very small radii [G].
*   **Negative Polarity:** A negative brush tip does not remove existing metaballs; it adds a metaball with negative weight to negate the field locally [S2, unofficial].

## Subtopics

### [3D Painting Metaphor for ROI Definition](11204-3d-painting-metaphor-for-roi-definition.md)
This method allows users to define a Region of Interest (ROI) by placing brush strokes directly in the visualization space, creating an implicit envelope that encloses features of interest without requiring complex parameter tweaking. It differs from traditional transfer function specification by replacing 2D histogram curve manipulation with direct spatial marking, eliminating the need for volumetric data representation knowledge. It builds on [Metaball-based Envelope Painting](8803-metaball-based-envelope-painting.md) by providing the interaction model that generates the metaball parameters.

### Metaball Envelope Merging
The envelope is defined by a series of metaballs [S1]. The brush tip acts as the first metaball, defining the attributes (size, parameters) for every new metaball added to the series [S2, unofficial]. Merging influence is determined by the size of the metaball and its proximity to other metaballs [S2, unofficial]. Larger and closer metaballs have a greater merging factor [S2, unofficial]. The specific mathematical form of the field function is a parameter of the metaball implementation [S2, unofficial].

### Envelope Painting
A 3D exploration task that exposes features of interest by completely removing occluding parts of the volume, often used to examine the outline or shape of internal structures [S2, unofficial]. Paint a 3D envelope around the parts of the volume to be removed using free-hand or surface painting modes [S2, unofficial]. Adjust the MIDA sliders for the volume enclosed by the envelope to set the visible sub-range of volume values to 0 (an empty range where min and max are the same) [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time preview requires evaluating the field function for visible voxels/samples per frame [S1]. Marching Cubes extraction is optimized via GPU shaders and buffer reuse [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Intuitive interaction, real-time preview, organic shapes, flexibility in envelope definition, independence from specific DVR techniques [S1].
*   **Limitations:** Requires GPU acceleration for real-time performance (GLSL shaders). 2D mode loses depth information [S1][S2, unofficial].
*   **When to use:** Interactive exploration of unsegmented volumetric data, defining contextual views, volume carving/peeling [S1].
*   **When not to use:** Not given in the sources.

## Background
Metaball-based Envelope Painting was introduced by L. Faynshteyn and T. McInerney in 2012 [S1]. It combines the Maximum Intensity Difference Accumulation (MIDA) visualization algorithm with a 3D interaction model based on a painting metaphor [S1]. The technique was validated through a user study involving 11 subjects (10 undergraduate, 1 graduate) from computer science departments [S1]. It builds on the concept of Metaballs as implicit surfaces [S2, unofficial] and extends previous techniques like independent surface-bound brushes and depth-fixed peeling regions [S1].
