# Blob Field Generation

Also called: Inverse Distance Weighting for Isosurfaces, Inverse Square Blob Field, Metaball Scalar Field Construction, Procedural Blob Field

## Overview
Blob Field Generation is a procedural method for constructing a 3D scalar field by summing inverse-square distance contributions from a set of source points (blobs), creating smooth, organic "metaball" shapes suitable for isosurface extraction via Marching Cubes [S1, S2, unofficial]. It differs from Radial Gaussian Density Field Generation by using $1/r^2$ falloff instead of exponential decay, resulting in sharper, more compact isosurfaces with heavier tails, and from Fuzzy Metaballs Hyper-parameters by relying on explicit inverse-distance weighting rather than probabilistic or fuzzy logic blending [S1, S2, unofficial][S3].

## How it works
**Inputs:**
- A set of $N$ source points (blob centers) $P_i = (x_i, y_i, z_i)$ for $i \in \{0, \dots, N-1\}$ [S2, unofficial].
- A query point $Q = (x, y, z)$ in 3D space [S2, unofficial].
- A time parameter $t$ for animated blob positions [S1, unofficial].
- Optional: Boolean flag to enable a floor effect [S1, unofficial].

**Outputs:**
- A scalar field value $f(x, y, z)$ [S2, unofficial].

**Data Structures:**
- `sSourcePoint`: An array of $N$ structures, each containing three floating-point coordinates $(fX, fY, fZ)$ [S2, unofficial].
- `numBlobs`: Integer count of source points [S1, unofficial].

**Steps:**
1. **Normalize Coordinates:** Scale the query point coordinates to the range $[0, 1]$ [S1, unofficial].
2. **Calculate Strength:** Compute a uniform strength value using the number of blobs: $strength = 1.2 / ((\sqrt{numBlobs} - 1) / 4 + 1)$ [S1, unofficial].
3. **Initialize Total:** Set the total field value to $0.0$ [S1, unofficial].
4. **Iterate Blobs:** For each blob $i$ from $0$ to $N-1$:
   a. Compute blob position $(bx, by, bz)$ using sinusoidal functions of time and index $i$ [S1, unofficial].
   b. Calculate squared Euclidean distance: $distSq = (x - bx)^2 + (y - by)^2 + (z - bz)^2$ [S1, S2, unofficial].
   c. Compute blob value: $v = strength / (0.000001 + distSq) - 12.0$ [S1, unofficial].
   d. If $v > 0$, add $v$ to the total field value [S1, unofficial].
5. **Optional Floor Effect:** If enabled, compute floor distance using the normalized y-coordinate: $fy = y$ [S1, unofficial]. Calculate floor value: $floorVal = 2.0 / (0.0001 + fy^2) - 12.0$ [S1, unofficial]. If $floorVal > 0$, add it to the total field value [S1, unofficial].
6. **Return:** Return the total field value [S1, S2, unofficial].

**Formulas:**
- General Inverse Square Field:
  $$f(x,y,z) = \sum_{i} \frac{w_i}{(x - x_i)^2 + (y - y_i)^2 + (z - z_i)^2}$$
  [S2, unofficial].
- Distance Metrics for Non-Spherical Shapes:
  - Euclidean: $dist(p1, p2) = \sqrt{(p1.x - p2.x)^2 + (p1.y - p2.y)^2 + (p1.z - p2.z)^2}$ [S2, unofficial].
  - Taxicab (Manhattan): $dist1(p1, p2) = |p1.x - p2.x| + |p1.y - p2.y| + |p1.z - p2.z|$ [S2, unofficial].
  - Max-Metric: $distMax(p1, p2) = \max(|p1.x - p2.x|, |p1.y - p2.y|, |p1.z - p2.z|)$ [S2, unofficial].

**Parameters:**
- `epsilon` ($\epsilon$): Small constant to prevent division by zero. Value $0.000001$ is used for blobs, and $0.0001$ for the floor effect [S1, unofficial].
- `offset`: Constant subtracted from the field value to control the isovalue threshold. Value $12.0$ is used [S1, unofficial].
- `time` ($t$): Drives sinusoidal animation of blob positions [S1, unofficial].
- `alpha`: Constant for fading effect in cloud variants. Value $0.6$ used in tests [S3].

**Pseudocode:**
```python
def evaluate_blob_field(x, y, z, num_blobs, time, use_floor=False):
    # Normalize coordinates to [0, 1] [S1, unofficial]
    x_n, y_n, z_n = x, y, z
    
    # Calculate uniform strength [S1, unofficial]
    strength = 1.2 / ((num_blobs ** 0.5 - 1) / 4 + 1)
    
    total_field = 0.0
    
    # Iterate over all blobs
    for i in range(num_blobs):
        # Compute blob position using sinusoidal functions of time and index i [S1, unofficial]
        bx, by, bz = 0.0, 0.0, 0.0  # Placeholder for sinusoidal position calculation [S1, unofficial]
        
        dx = x_n - bx
        dy = y_n - by
        dz = z_n - bz
        dist_sq = dx*dx + dy*dy + dz*dz
        
        # Compute blob contribution with epsilon and offset [S1, unofficial]
        v = strength / (0.000001 + dist_sq) - 12.0
        if v > 0:
            total_field += v
            
    # Optional floor effect [S1, unofficial]
    if use_floor:
        fy = y_n
        floor_val = 2.0 / (0.0001 + fy*fy) - 12.0
        if floor_val > 0:
            total_field += floor_val
            
    return total_field
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If the evaluation point coincides exactly with a source point, the distance term becomes zero, causing the value to approach infinity [S2, unofficial]. A small epsilon must be added to the denominator [S1, unofficial].
- **Metric Selection:** Using standard Euclidean distance creates spherical metaballs. To create cubic or "Minecraft-like" isosurfaces, Taxicab or Max-metric distances should be used instead [S2, unofficial].

## Subtopics

### Cumuliforms with Optimized Metaballs
Applies Blinn's metaball technique for organic n-dimensional objects to generate cumulus clouds [S3]. It differs from other methods by using optimized equations and pre-calculating the mean value on the CPU for high performance [S3]. The field is evaluated as $f(x) = \sum_i \frac{r_i^2}{|x - c_i|^2}$, where $r_i$ is the sphere radius and $c_i$ is the center [S3]. A constant $\alpha = 0.6$ adjusts the fading effect at the cloud edges [S3]. Render quality is sufficient but lower than Algorithm 1, using only six spheres with randomized radii [S3].

## Operating characteristics
- **Time Complexity:** $O(N)$ per query point, where $N$ is the number of blobs [S2, unofficial].
- **Memory Complexity:** $O(N)$ to store source points and weights [S2, unofficial].
- **Performance:** High performance, especially when mean values are pre-calculated on the CPU [S3].
- **Strengths:** Simple to implement, produces smooth organic shapes, computationally efficient [S1, unofficial][S3].
- **Limitations:** Sharp falloff can lead to aliasing if not sampled finely; singularities require handling [S2, unofficial].
- **Use Cases:** Isosurface generation for organic shapes, cloud rendering [S1, unofficial][S3].
- **When Not to Use:** When exponential falloff (Gaussian) is preferred for softer edges, or when complex procedural noise is needed [S2, unofficial][S3].

## Background
Originated from Blinn's metaball technique for creating organic-looking n-dimensional objects [S3]. The inverse square distance method is commonly used in conjunction with the Marching Cubes algorithm for isosurface extraction [S1, S2, unofficial]. It has been applied in computer graphics for generating clouds and organic shapes [S1, unofficial][S3].
