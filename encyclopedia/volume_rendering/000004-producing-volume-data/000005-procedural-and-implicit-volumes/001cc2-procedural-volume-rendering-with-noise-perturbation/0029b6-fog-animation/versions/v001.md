# Fog Animation
Also called: Solid Space Animation: Moving Point

## Overview
Fog Animation generates the appearance of moving gaseous volumes by perturbing the spatial coordinates of the evaluation point before sampling a static turbulence function, effectively moving the point through a "solid space" texture [S1, unofficial]. Unlike methods that animate the noise function itself, this approach creates motion by shifting the sampling domain, producing upward-swirling gas movement suitable for real-time fog and smoke [S1, unofficial]. It is a specific application of Procedural Volume Rendering with Noise Perturbation [1370-procedural-volume-rendering-with-noise-perturbation.md] tailored for transparency-based fog effects.

## How it works
**Inputs:**
- `pnt`: 3D point in world space ($x, y, z$).
- `frame_num`: Integer current animation frame.
- `transp`: Output pointer to a float representing transparency.

**Parameters:**
- `SWIRL_FRAMES`: Integer controlling the period of the helical swirl. Typical value: 126 [S1, unofficial].
- `SWIRL_AMOUNT`: Float controlling the speed of the swirling effect. Typical value: $2\pi/126$ (implied by modulo arithmetic for full rotation) [S1, unofficial].
- `RAD1`: Float, radius of the helix in the X direction. Typical value: 0.5 [S1, unofficial].
- `RAD2`: Float, radius of the helix in the Z direction. Typical value: 2.0 [S1, unofficial].
- `DOWN_AMOUNT`: Float, downward movement speed per frame. Typical value: 0.01 [S1, unofficial].
- `turbulence(p, scale)`: A function returning a scalar noise value at point `p` with frequency `scale`.

**Data Structures:**
- `direction`: 3D vector ($x, y, z$).
- `cyl`: 3D vector ($x, y, z$) representing cylindrical offset.
- `tmp`: Float scalar.

**Steps:**
1. **Perturb Input Point:** Modify the input point `pnt` to introduce local turbulence and drift.
   - $pnt.x \leftarrow pnt.x + 2.0 + \text{turbulence}(pnt, 0.1)$
   - $tmp \leftarrow \text{noise\_it}(pnt)$
   - $pnt.y \leftarrow pnt.y + 4.0 + tmp$
   - $pnt.z \leftarrow pnt.z - 2.0 - tmp$
   *Note: `noise_it` is a specific noise function cited in the source [S1, unofficial]. If unavailable, use a standard isotropic noise function.*

2. **Calculate Helical Path Components:** Determine the position on a helix based on the current frame.
   - $\theta \leftarrow (\text{frame\_num} \pmod{\text{SWIRL\_FRAMES}}) \times \text{SWIRL\_AMOUNT}$
   - $cyl.x \leftarrow \text{RAD1} \times \cos(\theta)$
   - $cyl.z \leftarrow \text{RAD2} \times \sin(\theta)$

3. **Calculate Direction Vector:** Combine the perturbed point with the helical offset and a downward drift.
   - $direction.x \leftarrow pnt.x + cyl.x$
   - $direction.y \leftarrow pnt.y - (\text{frame\_num} \times \text{DOWN\_AMOUNT})$
   - $direction.z \leftarrow pnt.z + cyl.z$

4. **Calculate Transparency:** Sample turbulence at the direction vector and apply non-linear transformations to map the result to a transparency value.
   - $t \leftarrow \text{turbulence}(direction, 0.015)$
   - $t \leftarrow 1.0 - (t \times t \times 0.275)$
   - $\text{transp} \leftarrow t \times t \times t$

**Pseudocode:**
```python
def fog_animation(pnt: Vector3, frame_num: int) -> float:
    # Step 1: Perturb input point
    # turbulence(p, scale) returns a scalar noise value
    # noise_it(p) is a specific noise function from the source [S1, unofficial]
    pnt_x = pnt.x + 2.0 + turbulence(pnt, 0.1)
    tmp = noise_it(pnt)
    pnt_y = pnt.y + 4.0 + tmp
    pnt_z = pnt.z - 2.0 - tmp
    
    # Step 2: Calculate helical path components
    theta = (frame_num % SWIRL_FRAMES) * SWIRL_AMOUNT
    cyl_x = RAD1 * math.cos(theta)
    cyl_z = RAD2 * math.sin(theta)
    
    # Step 3: Calculate direction vector
    direction_x = pnt_x + cyl_x
    direction_y = pnt_y - (frame_num * DOWN_AMOUNT)
    direction_z = pnt_z + cyl_z
    
    # Step 4: Calculate transparency
    t = turbulence(Vector3(direction_x, direction_y, direction_z), 0.015)
    t = 1.0 - (t * t * 0.275)
    transp = t * t * t
    
    return transp
```

**Edge Cases and Pitfalls:**
- **Precision:** The cubic mapping of transparency ($t^3$) can result in very low values for small $t$, potentially causing fog to disappear if the turbulence amplitude is low.
- **Boundary Conditions:** The modulo operation on `frame_num` ensures the swirl repeats every `SWIRL_FRAMES`. If `frame_num` is negative, ensure the modulo operator behaves correctly for the target language (e.g., Python's `%` vs C++'s `%`).
- **Noise Function Dependency:** The method relies on `noise_it` and `turbulence`. If `noise_it` is not available, substitute with a standard Perlin or Simplex noise function, though the visual result may differ slightly [S1, unofficial].

## Subtopics

### Marble Forming with Heat
A variant that animates marble textures by simulating heating and cooling effects. It calculates a `glow_percent` based on `frame_num`, `start_frame`, `end_frame`, and `heat_length`. If outside the heat range, `glow_percent=0`. In the start heating phase, `glow_percent = 1.0 - ease(((start_frame+heat_length/2-frame_num)/heat_length), 0.4, 0.6)`. In the end cooling phase, `glow_percent = ease(((frame_num-(end_frame-heat_length/2))/heat_length), 0.4, 0.6)`. Otherwise, `glow_percent=1.0`. Turbulence is applied with ease-in/ease-out: `turb_percent=ease(turb_percent, 0.3, 0.7)`. The color is computed as `marble_color(sin((pnt.y + turb_percent*3.0*turbulence(pnt, .0125) - displacement)*M_PI))` and blended with a glow color (R:1.0, G:0.4, B:0.8) weighted by `0.5*glow_percent` [S1, unofficial].

### Moving Marble
A variant that moves the point along a helical path to create a swirling marble effect. It calculates a displacement based on `frame_num` relative to `start_frame` and `end_frame`. A helical path is computed using `theta = (frame_num%SWIRL_FRAMES)*SWIRL_AMOUNT`, with radii `RAD1` and `RAD2`, and downward drift `DOWN_AMOUNT`. Randomness is added via `fast_noise(pnt)`. The final color is `marble_color(sin((pnt.y + 3.0*turbulence(direction, .0125))*M_PI))` where `direction` is the sum of `pnt` and the helical path [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample, assuming constant-time noise evaluation. The method involves a fixed number of arithmetic operations and noise calls.
- **Memory Complexity:** $O(1)$, as it does not require storing volume data or large lookup tables, only static parameters.
- **Performance:** Suitable for real-time rendering due to its procedural nature and lack of ray-marching or grid traversal. Performance depends heavily on the efficiency of the `turbulence` and `noise_it` functions.
- **Strengths:** Simple to implement, low memory footprint, produces organic, swirling motion without animating the noise field itself.
- **Limitations:** The motion is constrained to the specific helical and drift patterns defined; less flexible than general noise animation. The transparency mapping is fixed and may not suit all fog densities.

## Background
The method originates from David Ebert's work on procedural modeling, animation, and rendering of gases, fluids, and textures [S1, unofficial]. It was introduced as a technique for animating solid space functions to create realistic fog and smoke effects by moving the evaluation point through a static texture space. The approach is similar to Gardner's cloud technique but uses turbulence for transparency control instead of Fourier synthesis [S1, unofficial].
