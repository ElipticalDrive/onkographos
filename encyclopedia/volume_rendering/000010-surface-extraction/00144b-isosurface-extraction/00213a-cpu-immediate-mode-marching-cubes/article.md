# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals for each voxel and renders them directly via immediate-mode draw calls (e.g., WebGL `gl.drawArrays`) without storing a persistent mesh buffer in system memory [S1, unofficial]. It differs from sibling methods like [Preprocessed Marching Cubes](3765-preprocessed-marching-cubes.md) or [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by performing the entire field evaluation, topology lookup, and geometry upload on the CPU every frame, making it a simple reference implementation but limited by CPU bottlenecks at high resolutions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D grid of voxels, each containing a scalar field value $V$. The scalar field is typically generated by accumulating contributions from metaballs and a floor term [S1, unofficial].
*   **Output:** A stream of triangles (positions and normals) rendered immediately to the GPU.

**Data Structures:**
The implementation uses fixed-size typed arrays to batch geometry before flushing to the GPU [S1, unofficial].
*   `maxCount`: Integer, typically 4096 [S1, unofficial].
*   `posArray`: `Float32Array` of size `maxCount * 3` [S1, unofficial].
*   `normalArray`: `Float32Array` of size `maxCount * 3` [S1, unofficial].
*   `uvArray`: `Float32Array` of size `maxCount * 2` [S1, unofficial].
*   `colorArray`: `Float32Array` of size `maxCount * 4` [S1, unofficial].
*   `count`: Integer, tracking the number of vertices added to the current batch [S1, unofficial].
*   `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated [S1, unofficial].

**Algorithm Steps:**
1.  **Field Generation:** For each voxel in the 3D grid, compute the scalar field value $V$ by summing contributions from all metaballs and a floor term [S1, unofficial].
2.  **Case Index Calculation:** For each voxel, determine the 8-bit case index $C$ based on the sign of $V(v_i) - I$ at the 8 vertices $v_i$ ($i=0..7$), using the standard vertex ordering [Parent].
3.  **Lookup and Interpolation:** Use the `edgeTable` and `triangleTable` from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) to identify intersected edges and triangle connectivity. Interpolate vertex positions and compute normals at edge intersections [S1, unofficial].
4.  **Batching and Rendering:**
    *   Initialize the batch: Set primitive type (e.g., `TRIANGLES`), primitive size (3), and reset `count` and attribute flags [S1, unofficial].
    *   For each triangle vertex:
        *   Store position $(x, y, z)$ in `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]` and set `hasPos = true` [S1, unofficial].
        *   Store normal $(n_x, n_y, n_z)$ in `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]` and set `hasNormal = true` [S1, unofficial].
        *   Increment `count` [S1, unofficial].
    *   **Overflow Check:** If `count >= maxCount - 3`, flush the buffer immediately to ensure space for the next triangle [S1, unofficial].
    *   **Flush:** If `count > 0`:
        *   Zero out remaining entries in `posArray` from `count*3` to `length` [S1, unofficial].
        *   Bind `posArray` and `normalArray` to WebGL buffers using `gl.bufferData` with `DYNAMIC_DRAW` [S1, unofficial].
        *   Enable vertex attribute arrays and set pointers for enabled attributes [S1, unofficial].
        *   Call `gl.drawArrays` with the primitive type, offset 0, and count [S1, unofficial].
        *   Reset `count` to 0 [S1, unofficial].

def cpu_immediate_marching_cubes(grid, isovalue, max_count=4096):
    """
    Renders marching cubes mesh using immediate mode batching.
    grid: 3D array of scalar values.
    isovalue: The threshold for surface extraction.
    max_count: Maximum vertices per batch.
    """
    pos_array = [0.0] * (max_count * 3)
    normal_array = [0.0] * (max_count * 3)
    count = 0
    has_pos = False
    has_normal = False
    
    # Precomputed tables from parent article
    edge_table = get_edge_table()
    triangle_table = get_triangle_table()
    
    # Iterate over all voxels
    for x in range(grid.width - 1):
        for y in range(grid.height - 1):
            for z in range(grid.depth - 1):
                # 1. Field Generation (if not precomputed)
                # V = compute_scalar_field(x, y, z, blobs, floor_term)
                
                # 2. Case Index Calculation
                case_index = 0
                for i in range(8):
                    # Standard vertex ordering assumed
                    v_val = grid.get_value(x, y, z, i)
                    if v_val < isovalue: # Or > depending on convention
                        case_index |= (1 << i)
                
                # 3. Lookup and Interpolation
                edges = edge_table[case_index]
                if edges == 0:
                    continue
                
                triangles = triangle_table[case_index]
                tri_count = 0
                while tri_count < 15 and triangles[tri_count] != -1:
                    e1 = triangles[tri_count]
                    e2 = triangles[tri_count + 1]
                    e3 = triangles[tri_count + 2]
                    
                    if e1 == -1 or e2 == -1 or e3 == -1:
                        break
                    
                    # Interpolate vertices for edges e1, e2, e3
                    p1, n1 = interpolate_vertex(x, y, z, e1, grid, isovalue)
                    p2, n2 = interpolate_vertex(x, y, z, e2, grid, isovalue)
                    p3, n3 = interpolate_vertex(x, y, z, e3, grid, isovalue)
                    
                    # 4. Add to Batch
                    add_vertex(pos_array, normal_array, p1, n1, count)
                    add_vertex(pos_array, normal_array, p2, n2, count)
                    add_vertex(pos_array, normal_array, p3, n3, count)
                    
                    count += 3
                    
                    # Overflow check
                    if count >= max_count - 3:
                        flush_and_render(pos_array, normal_array, count, has_pos, has_normal)
                        count = 0
                        has_pos = False
                        has_normal = False
                    
                    tri_count += 3
                
    # Final flush
    if count > 0:
        flush_and_render(pos_array, normal_array, count, has_pos, has_normal)

    """
    Interpolates the vertex position and normal on the specified edge of the voxel.
    Edge indices 0-11 correspond to the standard marching cubes edge numbering.
    """
    # Determine the two vertices of the edge
    v1_idx, v2_idx = get_edge_vertices(edge_index)
    
    p1 = grid.get_vertex_position(x, y, z, v1_idx)
    p2 = grid.get_vertex_position(x, y, z, v2_idx)
    
    v1 = grid.get_value(x, y, z, v1_idx)
    v2 = grid.get_value(x, y, z, v2_idx)

*   `maxCount`: Buffer size limit. Default 4096 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** The code checks `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous. The standard LUT uses a fixed triangulation, which can cause cracks or holes if adjacent voxels resolve the ambiguity differently [Parent].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once. The constant factor is high due to CPU-side interpolation and memory management.
*   **Memory Complexity:** $O(1)$ auxiliary memory for the batch buffer (fixed size, e.g., 4096 vertices), plus $O(N)$ for the scalar field grid [S1, unofficial].
*   **Performance:** Limited by CPU bottlenecks at high resolutions or blob counts [S1, unofficial]. Suitable for low-resolution grids or educational purposes.
*   **Strengths:** Simple implementation, no persistent mesh storage, easy to debug.
*   **Limitations:** Poor scalability, high CPU usage, frequent GPU buffer updates.

## Background
The CPU Immediate Mode Marching Cubes implementation is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript [S1, unofficial]. It serves as a reference implementation for comparing against GPU-accelerated variants. The underlying algorithm is based on the classic Marching Cubes method by Lorensen and Cline (1987), with lookup tables from Paul Bourke [S1, unofficial].
