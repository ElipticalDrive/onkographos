# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It serves as a reference implementation for comparison against GPU-accelerated variants, computing the 3D scalar field and marching cubes extraction entirely on the CPU each frame [S1, unofficial]. Unlike modern deferred or tiled approaches, it batches geometry into fixed-size buffers and flushes them to the GPU immediately upon reaching capacity or frame completion [S1, unofficial].

## How it works
The method processes a 3D grid of voxels, computing a scalar field for each, determining isosurface intersections using lookup tables, and streaming the resulting triangles to the GPU.

**Inputs and Outputs**
*   **Input**: A 3D grid of resolution $N_x \times N_y \times N_z$. A set of metaball sources (position, radius, strength) and a floor term. An isovalue $I$.
*   **Output**: A stream of triangle vertices and normals rendered to the screen.

**Data Structures**
The implementation relies on the precomputed data structures from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md):
1.  **Edge Intersection Table (`edgeTable`)**: 256 entries, 12-bit bitmasks [S4, S12, unofficial].
2.  **Triangle Connection Table (`triangleTable`)**: $256 \times 16$ array, terminated by `-1` [S8, S12, unofficial].

**Immediate Mode Buffers**
The CPU maintains fixed-size typed arrays to batch geometry before sending it to the GPU [S1, unofficial]:
*   `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
*   `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(n_x, n_y, n_z)$.
*   `uvArray`: `Float32Array` of size `maxCount * 2`. (Optional, not always used in basic metaball demos).
*   `colorArray`: `Float32Array` of size `maxCount * 4`. (Optional).
*   `maxCount`: Typically 4096 vertices [S1, unofficial].
*   `count`: Integer tracking the number of vertices currently in the buffer.

**Numbered Steps**

1.  **Initialize Batching**:
    *   Set primitive type `prim` to `TRIANGLES`.
    *   Set `primsize` to 3.
    *   Reset `count` to 0.
    *   Reset flags `hasPos`, `hasNormal`, `hasUV`, `hasColor` to `false` [S1, unofficial].

2.  **Field Generation**:
    *   For each voxel $(i, j, k)$ in the grid:
        *   Initialize scalar value $V = 0$.
        *   For each metaball source $m$ with center $C_m$ and radius $R_m$:
            *   Calculate distance $d = \| P_{ijk} - C_m \|$.
            *   If $d < R_m$, add contribution (e.g., $1 - (d/R_m)^2$) to $V$ [S1, unofficial].
        *   Add floor term to $V$ if applicable [S1, unofficial].
        *   Store $V$ in the scalar field grid.

3.  **Marching Cubes Extraction**:
    *   For each voxel $(i, j, k)$:
        *   Retrieve scalar values $V_0 \dots V_7$ at the 8 corners.
        *   Compute case index $C$: If $V_i < I$, set bit $i$ of $C$ to 1, else 0 [S7, S8, S12, unofficial].
        *   Look up `edgeTable[C]` to determine intersected edges.
        *   Look up `triangleTable[C]` to determine triangle connectivity.
        *   For each triangle triplet $(e_a, e_b, e_c)$ in the table (until `-1`):
            *   Interpolate vertex positions $P_a, P_b, P_c$ on edges $e_a, e_b, e_c$ using linear interpolation:
                $$ P = V_{start} + \frac{I - V_{start}}{V_{end} - V_{start}} (V_{end} - V_{start}) $$
                (Note: Standard linear interpolation formula for position along edge).
            *   Compute vertex normals by averaging gradients or interpolating field gradients at intersection points [S1, unofficial].
            *   **Add Vertex Position**: Store $P_a$ into `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos = true`. Increment `count`.
            *   **Add Vertex Normal**: Store $N_a$ into `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal = true`.
            *   **Add Triangle**: Copy positions and normals for $P_a, P_b, P_c$ into the arrays. Increment `count` by 3.
            *   **Check Buffer Overflow**: If `count >= maxCount - 3`, call `draw()` to flush the buffer [S1, unofficial].

4.  **Flush and Render**:
    *   If `count == 0`, return.
    *   Zero out remaining entries in `posArray` and `normalArray` from `count*3` to `length` to prevent garbage data [S1, unofficial].
    *   Bind `posBuf` and `normalBuf` (WebGLBuffer objects) using `gl.bufferData` with `DYNAMIC_DRAW` hint, uploading the current `posArray` and `normalArray` data [S1, unofficial].
    *   Enable vertex attribute arrays for position and normal.
    *   Set pointers to the buffer data.
    *   Call `gl.drawArrays` with `prim`, offset 0, and count [S1, unofficial].
    *   Reset `count` to 0 [S1, unofficial].

**Pseudocode**

```python
# Constants
MAX_COUNT = 4096
PRIM_SIZE = 3

# Data structures
pos_array = [0.0] * (MAX_COUNT * 3)
normal_array = [0.0] * (MAX_COUNT * 3)
count = 0
has_pos = False
has_normal = False

def add_vertex_position(x, y, z):
    global count, has_pos
    idx = count * 3
    pos_array[idx] = x
    pos_array[idx + 1] = y
    pos_array[idx + 2] = z
    has_pos = True
    count += 1

def add_vertex_normal(nx, ny, nz):
    global count, has_normal
    idx = count * 3
    normal_array[idx] = nx
    normal_array[idx + 1] = ny
    normal_array[idx + 2] = nz
    has_normal = True

def flush_and_render(gl, pos_buf, normal_buf):
    global count, has_pos, has_normal
    
    if count == 0:
        return

    # Zero out unused buffer space
    for i in range(count * 3, len(pos_array)):
        pos_array[i] = 0.0
        normal_array[i] = 0.0

    # Upload data to GPU
    if has_pos:
        gl.buffer_data(gl.ARRAY_BUFFER, pos_array, gl.DYNAMIC_DRAW)
        gl.enable_vertex_attrib_array(0) # Position
        gl.vertex_attrib_pointer(0, 3, gl.FLOAT, False, 0, 0)
    
    if has_normal:
        gl.buffer_data(gl.ARRAY_BUFFER, normal_array, gl.DYNAMIC_DRAW)
        gl.enable_vertex_attrib_array(1) # Normal
        gl.vertex_attrib_pointer(1, 3, gl.FLOAT, False, 0, 0)

    # Draw
    gl.draw_arrays(gl.TRIANGLES, 0, count)

    # Reset state
    count = 0
    has_pos = False
    has_normal = False

def process_voxel(i, j, k, grid, isovalue, edge_table, triangle_table):
    global count
    
    # 1. Get corner values
    v = [grid[i][j][k], grid[i+1][j][k], grid[i+1][j+1][k], grid[i][j+1][k],
         grid[i][j][k+1], grid[i+1][j][k+1], grid[i+1][j+1][k+1], grid[i][j+1][k+1]]
    
    # 2. Case index
    c = 0
    for idx in range(8):
        if v[idx] < isovalue:
            c |= (1 << idx)
            
    # 3. Lookup triangles
    tri_conn = triangle_table[c]
    idx_ptr = 0
    
    while idx_ptr < 16:
        e1 = tri_conn[idx_ptr]
        if e1 == -1:
            break
        e2 = tri_conn[idx_ptr + 1]
        e3 = tri_conn[idx_ptr + 2]
        
        # Interpolate vertices for edges e1, e2, e3
        # (Implementation depends on specific edge-to-vertex mapping)
        p1, n1 = interpolate_vertex(e1, v)
        p2, n2 = interpolate_vertex(e2, v)
        p3, n3 = interpolate_vertex(e3, v)
        
        # Add vertices
        add_vertex_position(*p1)
        add_vertex_normal(*n1)
        add_vertex_position(*p2)
        add_vertex_normal(*n2)
        add_vertex_position(*p3)
        add_vertex_normal(*n3)
        
        # Check buffer overflow
        if count >= MAX_COUNT - 3:
            flush_and_render(gl, pos_buf, normal_buf)
            
        idx_ptr += 3

def render_frame(gl, grid, isovalue, edge_table, triangle_table, pos_buf, normal_buf):
    global count, has_pos, has_normal
    count = 0
    has_pos = False
    has_normal = False
    
    # Process all voxels
    for i in range(Nx - 1):
        for j in range(Ny - 1):
            for k in range(Nz - 1):
                process_voxel(i, j, k, grid, isovalue, edge_table, triangle_table)
                
    # Final flush
    flush_and_render(gl, pos_buf, normal_buf)
```

**Edge Cases and Pitfalls**
*   **Buffer Overflow**: The code checks `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].
*   **Ambiguity**: Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous. The standard LUT uses a fixed triangulation, which can cause cracks if adjacent voxels resolve ambiguities differently [S7, S8, unofficial].
*   **Precision**: Linear interpolation assumes the isosurface is locally planar. High curvature may require higher resolution or adaptive methods.

## Operating characteristics
*   **Time Complexity**: $O(N_x N_y N_z \cdot B)$, where $B$ is the number of blobs. Each voxel requires iterating over all blobs to compute the scalar field.
*   **Memory Complexity**: $O(N_x N_y N_z)$ for the scalar field grid, plus $O(\text{maxCount})$ for the immediate mode buffers.
*   **Measured Performance**: Limited by CPU bottlenecks at high resolutions or blob counts [S1, unofficial]. Suitable for low-resolution previews or small scenes.
*   **Strengths**: Simple implementation, easy to debug, minimal GPU memory usage for geometry storage.
*   **Limitations**: Poor scalability with grid resolution and blob count. High CPU-GPU transfer overhead due to frequent buffer updates.
*   **When to Use**: Reference implementation, educational purposes, low-performance targets, or small scenes where GPU acceleration is unavailable.
*   **When Not to Use**: High-resolution volumetric data, real-time applications with many dynamic objects, or large-scale simulations.

## Background
The CPU Immediate Mode Marching Cubes approach is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript [S1, unofficial]. It utilizes the classic Marching Cubes algorithm and lookup tables originally described by Paul Bourke [S1, unofficial]. The method was popularized in early WebGL demos as a way to demonstrate real-time volumetric rendering on the CPU before GPU-based techniques became dominant.
