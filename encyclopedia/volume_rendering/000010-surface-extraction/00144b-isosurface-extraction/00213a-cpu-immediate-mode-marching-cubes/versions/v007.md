# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by using precomputed tables to determine edge intersections and interpolating vertex positions [S1, unofficial]. Unlike GPU-accelerated variants that compute geometry on the GPU, this method performs field generation and geometry assembly on the CPU, batching vertices into small buffers to minimize draw calls [S1, unofficial]. It serves primarily as a reference implementation and for performance comparison against GPU pipelines [S1, unofficial].

## How it works
**Inputs and Outputs**:
*   **Input**: A 3D scalar field grid (voxels), an isovalue $I$, and a list of metaball sources (for field generation).
*   **Output**: A stream of triangle vertices and normals rendered to the screen.

**Data Structures**:
The implementation uses a fixed-size batching buffer to hold vertex attributes before flushing to the GPU [S1, unofficial].
*   `maxCount`: Integer, typically 4096 [S1, unofficial].
*   `posArray`: `Float32Array` of size `maxCount * 3` [S1, unofficial].
*   `normalArray`: `Float32Array` of size `maxCount * 3` [S1, unofficial].
*   `uvArray`: `Float32Array` of size `maxCount * 2` [S1, unofficial].
*   `colorArray`: `Float32Array` of size `maxCount * 4` [S1, unofficial].
*   `count`: Integer, tracking the number of vertices currently in the buffer [S1, unofficial].
*   `prim`: Primitive type (e.g., `TRIANGLES`) [S1, unofficial].
*   `primsize`: Integer, 3 for triangles [S1, unofficial].
*   `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated [S1, unofficial].

**Steps**:

1.  **Field Generation**: For each voxel in the 3D grid, compute the scalar field value $V$ by accumulating contributions from all metaballs and a floor term [S1, unofficial].
2.  **Batch Initialization**: Set `prim` to the primitive type, `primsize` to 3, reset `count` to 0, and reset `hasPos`, `hasNormal`, `hasUV`, `hasColor` to false [S1, unofficial].
3.  **Voxel Processing**: Iterate through each voxel in the grid:
    a. Calculate the 8-bit case index $C$ based on the scalar field values $V$ at the 8 vertices relative to the isovalue $I$ [S12, unofficial].
    b. Look up the `edgeTable` using $C$ to determine which edges are intersected [S8, unofficial].
    c. Look up the `triangleTable` using $C$ to get the sequence of edge indices forming triangles [S8, unofficial].
    d. For each triangle triplet $(e_a, e_b, e_c)$ in the table:
        i. Interpolate the vertex positions and normals on the intersected edges [S1, unofficial].
        ii. Call `addVertexPosition` for each vertex.
        iii. Call `addVertexNormal` for each vertex.
        iv. Call `addTriangle` to commit the three vertices to the buffer.
4.  **Buffer Management**: After processing all voxels, flush the remaining buffer.

**Edge Cases and Pitfalls**:
*   **Buffer Overflow**: The code checks if `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].
*   **Ambiguity**: Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous. The standard LUT uses a fixed triangulation, which can cause cracks or holes if adjacent voxels resolve the ambiguity differently [S7, S8, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of voxels, as each voxel is processed once [S1, unofficial].
*   **Memory Complexity**: $O(1)$ auxiliary memory (fixed-size buffers) plus $O(V)$ for the scalar field grid, where $V$ is the number of voxels [S1, unofficial].
*   **Measured Performance**: Limited in performance at high resolutions or blob counts due to CPU bottlenecks [S1, unofficial].
*   **Strengths**: Simple implementation, serves as a good reference, minimal CPU-GPU transfer (only small uniform and texture updates per frame) [S1, unofficial].
*   **Limitations**: CPU-bound, poor scalability to high resolutions [S1, unofficial].
*   **When to use**: For reference implementations, comparison with GPU methods, or low-resolution scenes [S1, unofficial].
*   **When not to use**: For high-resolution scenes or real-time applications requiring high performance [S1, unofficial].

## Background
The CPU Immediate Mode Marching Cubes method is inspired by Gregg Tavares' (Greggman) metaballs demo [S1, unofficial]. It uses classic Marching Cubes tables from Paul Bourke [S1, unofficial]. The implementation is part of the WebGL2-GPU-Marching-Cubes project by 3merillon [S1, unofficial].
