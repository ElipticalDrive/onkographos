# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It differs from modern GPU-accelerated or persistent-buffer approaches by performing all field generation and geometry calculation on the CPU, batching geometry into small buffers for frequent, small draw calls [S1, unofficial]. This makes it a valuable reference implementation for comparison, though it is limited in performance at high resolutions or high blob counts due to CPU bottlenecks [S1, unofficial].

## How it works
The method operates on a discretized 3D grid (typically a regular Cartesian grid) where each voxel stores a scalar value. It iterates over every cell in the grid, determines the isosurface intersection using the standard Marching Cubes lookup tables, and immediately streams the resulting triangles to the GPU for rendering [S1, unofficial].

### Inputs and Outputs
*   **Input**: A 3D scalar field $V(x,y,z)$ defined on a grid of size $N_x \times N_y \times N_z$. The field is typically generated from metaballs (sum of Gaussian-like contributions) and a floor term [S1, unofficial].
*   **Output**: A stream of triangles rendered to the screen. No persistent mesh data structure is retained between frames [S1, unofficial].

### Data Structures
The implementation uses typed arrays to store vertex attributes for batching. The maximum number of vertices per batch is `maxCount` = 4096 [S1, unofficial].

*   `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
*   `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(n_x, n_y, n_z)$.
*   `uvArray`: `Float32Array` of size `maxCount * 2`. (Optional, for UV coordinates).
*   `colorArray`: `Float32Array` of size `maxCount * 4`. (Optional, for vertex colors).
*   `count`: Integer tracking the number of vertices currently in the batch.

### Algorithm Steps

1.  **Field Generation**: For each voxel $(i, j, k)$ in the grid, compute the scalar value $V_{ijk}$ by accumulating contributions from all metaballs and adding a floor term [S1, unofficial].
    $$ V_{ijk} = \sum_{b} \text{contribution}(b, P_{ijk}) + \text{floor\_term} $$
    Where $P_{ijk}$ is the world position of the voxel center.

2.  **Batch Initialization**:
    *   Set primitive type `prim` (e.g., `TRIANGLES`).
    *   Set `primsize` (3 for triangles).
    *   Reset `count` to 0.
    *   Reset flags `hasPos`, `hasNormal`, `hasUV`, `hasColor` to false.

3.  **Grid Traversal**: Iterate over every cell $(i, j, k)$ in the grid, where $0 \le i < N_x-1$, $0 \le j < N_y-1$, $0 \le k < N_z-1$.

4.  **Cube Case Evaluation**:
    *   Retrieve the 8 scalar values at the corners of the current cube cell.
    *   Determine the cube index (0-255) by comparing each corner value to the isovalue (threshold).
    *   Use precomputed Marching Cubes tables (e.g., Paul Bourke's tables) to identify which edges are intersected and which triangles to generate [S1, unofficial].

5.  **Vertex Interpolation**:
    *   For each intersected edge, interpolate the vertex position $P$ and normal $N$ using the scalar values at the edge endpoints.
    *   Position interpolation:
        $$ P = P_1 + \frac{I - V_1}{V_2 - V_1} (P_2 - P_1) $$
        Where $P_1, P_2$ are corner positions, $V_1, V_2$ are corner scalar values, and $I$ is the isovalue.
    *   Normal interpolation: Interpolate normals similarly using the gradient or stored corner normals.

6.  **Batching and Rendering**:
    *   For each generated triangle (3 vertices):
        *   Add vertex positions to `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos = true`.
        *   Add vertex normals to `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal = true`.
        *   Increment `count` by 3.
        *   **Overflow Check**: If `count >= maxCount - 3`, flush the buffer (see Step 7).

7.  **Flush and Draw**:
    *   If `count == 0`, return.
    *   Zero out remaining entries in `posArray` and `normalArray` from `count*3` to `maxCount*3` to prevent garbage data.
    *   Bind `posBuf` and `normalBuf` using `gl.bufferData` with `DYNAMIC_DRAW`.
    *   Enable vertex attribute arrays for position and normal.
    *   Call `gl.drawArrays` with `prim`, offset 0, and count.
    *   Reset `count` to 0.

### Pseudocode

```python
# Constants
MAX_COUNT = 4096
PRIM_SIZE = 3  # For triangles

# Data structures
pos_array = Float32Array(MAX_COUNT * 3)
normal_array = Float32Array(MAX_COUNT * 3)
count = 0
has_pos = False
has_normal = False

def begin_batch():
    global count, has_pos, has_normal
    count = 0
    has_pos = False
    has_normal = False

def add_vertex(x, y, z, nx, ny, nz):
    global count, has_pos, has_normal
    idx = count * 3
    pos_array[idx] = x
    pos_array[idx + 1] = y
    pos_array[idx + 2] = z
    normal_array[idx] = nx
    normal_array[idx + 1] = ny
    normal_array[idx + 2] = nz
    has_pos = True
    has_normal = True
    count += 1
    if count >= MAX_COUNT - PRIM_SIZE:
        flush_and_draw()

def flush_and_draw(gl, pos_buf, normal_buf, shader_program):
    global count, has_pos, has_normal
    if count == 0:
        return

    # Zero out unused buffer space
    for i in range(count * 3, MAX_COUNT * 3):
        pos_array[i] = 0.0
        normal_array[i] = 0.0

    # Upload data to GPU
    gl.bufferData(gl.ARRAY_BUFFER, pos_array, gl.DYNAMIC_DRAW)
    gl.bufferData(gl.ARRAY_BUFFER, normal_array, gl.DYNAMIC_DRAW)

    # Set up vertex attributes
    gl.enableVertexAttribArray(shader_program.position_location)
    gl.vertexAttribPointer(shader_program.position_location, 3, gl.FLOAT, False, 0, 0)

    gl.enableVertexAttribArray(shader_program.normal_location)
    gl.vertexAttribPointer(shader_program.normal_location, 3, gl.FLOAT, False, 0, 0)

    # Draw
    gl.drawArrays(gl.TRIANGLES, 0, count)

    # Reset state
    count = 0
    has_pos = False
    has_normal = False

def render_frame(gl, grid, isovalue, shader_program):
    begin_batch()
    
    # Iterate over grid cells
    for x in range(grid.width - 1):
        for y in range(grid.height - 1):
            for z in range(grid.depth - 1):
                # Get 8 corner values
                vals = [
                    grid.value(x, y, z), grid.value(x+1, y, z),
                    grid.value(x, y+1, z), grid.value(x+1, y+1, z),
                    grid.value(x, y, z+1), grid.value(x+1, y, z+1),
                    grid.value(x, y+1, z+1), grid.value(x+1, y+1, z+1)
                ]
                
                # Determine cube index
                cube_index = 0
                for i in range(8):
                    if vals[i] < isovalue:
                        cube_index |= (1 << i)
                
                # Get triangles for this cube index
                triangles = marching_cubes_table[cube_index]
                
                for tri in triangles:
                    # Interpolate vertices for the triangle
                    v0 = interpolate_vertex(vals, tri[0], grid, isovalue)
                    v1 = interpolate_vertex(vals, tri[1], grid, isovalue)
                    v2 = interpolate_vertex(vals, tri[2], grid, isovalue)
                    
                    add_vertex(v0.x, v0.y, v0.z, v0.nx, v0.ny, v0.nz)
                    add_vertex(v1.x, v1.y, v1.z, v1.nx, v1.ny, v1.nz)
                    add_vertex(v2.x, v2.y, v2.z, v2.nx, v2.ny, v2.nz)
    
    flush_and_draw(gl, pos_buf, normal_buf, shader_program)

def interpolate_vertex(vals, edge_index, grid, isovalue):
    # Determine the two endpoints of the edge
    p1, p2 = edge_endpoints[edge_index]
    v1, v2 = vals[p1], vals[p2]
    
    # Linear interpolation factor
    t = (isovalue - v1) / (v2 - v1)
    
    # Interpolate position
    x = p1.x + t * (p2.x - p1.x)
    y = p1.y + t * (p2.y - p1.y)
    z = p1.z + t * (p2.z - p1.z)
    
    # Interpolate normal (assuming corner normals are available or computed from gradient)
    nx = p1.nx + t * (p2.nx - p1.nx)
    ny = p1.ny + t * (p2.ny - p1.ny)
    nz = p1.nz + t * (p2.nz - p1.nz)
    
    return Vertex(x, y, z, nx, ny, nz)
```

### Edge Cases and Pitfalls
*   **Buffer Overflow**: The code checks if `count >= maxCount - 3` before adding a triangle to ensure there is space for 3 vertices. If exceeded, it flushes immediately [S1, unofficial].
*   **Precision**: Linear interpolation assumes the scalar field is smooth. Discontinuities or very steep gradients may cause artifacts.
*   **Boundary Conditions**: The grid traversal must handle the boundaries correctly, typically by iterating up to $N-1$ for a grid of size $N$.

## Operating characteristics
*   **Time Complexity**: $O(N_x N_y N_z)$ for field generation and mesh extraction. The constant factor is high due to CPU-side calculations and frequent GPU driver overhead from small draw calls.
*   **Memory Complexity**: $O(N_x N_y N_z)$ for the scalar field storage. The batch buffer is fixed at $O(1)$ relative to the grid size (4096 vertices).
*   **Performance**: Limited by CPU bottlenecks. Performance degrades significantly with high grid resolutions (e.g., 128³) or large numbers of metaballs (e.g., 100) [S1, unofficial].
*   **Strengths**: Simple implementation, easy to debug, serves as a good reference for GPU implementations.
*   **Limitations**: Poor scalability, high CPU usage, limited by batch size.
*   **When to Use**: Educational purposes, reference implementations, or low-resolution previews.
*   **When Not to Use**: Production applications requiring high resolution or real-time performance with complex scenes.

## Background
The CPU Immediate Mode Marching Cubes method is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript [S1, unofficial]. It uses classic Marching Cubes tables from Paul Bourke [S1, unofficial]. The implementation is part of the `WebGL2-GPU-Marching-Cubes` project by 3merillon [S1, unofficial].
