# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals for each voxel and renders them directly via immediate-mode draw calls (e.g., WebGL `gl.drawArrays`) without storing a persistent mesh buffer [S1, unofficial]. It serves as a reference implementation for comparing CPU versus GPU performance in metaball and scalar field rendering [S1, unofficial]. Unlike modern indexed-buffer approaches, it relies on tight batching and frequent buffer flushes to manage memory constraints on the CPU side [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field grid (voxels), an isovalue $I$, and a list of metaball sources (position, radius, strength) if applicable.
*   **Output:** A stream of triangles (positions and normals) rendered to the screen.

**Data Structures:**
The implementation relies on the standard Marching Cubes Lookup Tables defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md):
1.  `edgeTable`: 256-entry array of 12-bit integers.
2.  `triangleTable`: 256x16 array of integers, terminated by `-1`.

**Buffer Layout (Immediate Mode):**
To support immediate rendering, the CPU maintains fixed-size typed arrays in memory [S1, unofficial]:
*   `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
*   `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(n_x, n_y, n_z)$.
*   `uvArray`: `Float32Array` of size `maxCount * 2`. (Optional, not always used in basic metaball demos).
*   `colorArray`: `Float32Array` of size `maxCount * 4`. (Optional).
*   `maxCount`: A constant defining the buffer capacity, typically 4096 vertices [S1, unofficial].
*   `count`: An integer tracking the number of vertices currently stored in the arrays, initialized to 0.

**Algorithm Steps:**

1.  **Field Generation:**
    For each voxel in the 3D grid, compute the scalar field value $V$ at its 8 corners. If using metaballs, accumulate contributions from all blobs and a floor term:
    $$ V(p) = \sum_{i} \frac{r_i^2}{\|p - c_i\|^2} + V_{floor} $$
    where $c_i$ is the center and $r_i$ is the radius of blob $i$ [S1, unofficial].

2.  **Case Index Calculation:**
    For each voxel, determine the 8-bit case index $C$ by comparing corner values $V(v_j)$ to the isovalue $I$. If $V(v_j) < I$, set bit $j$ of $C$ to 1; otherwise 0 [S7, S8, S12, unofficial].

3.  **Lookup and Interpolation:**
    Use $C$ to index `triangleTable`. Iterate through the triplets $(a, b, c)$ until `-1` is encountered. For each edge index $e \in \{a, b, c\}$:
    *   Identify the two vertices of the cube connected by edge $e$.
    *   Interpolate the intersection point $P$ and normal $N$ using linear interpolation based on the scalar values at the edge endpoints [S1, unofficial].

4.  **Immediate Mode Batching:**
    For each generated triangle vertex:
    *   **Check Buffer Space:** If `count >= maxCount - 3`, flush the buffer (see Step 6).
    *   **Store Position:** Write $P.x, P.y, P.z$ to `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos = true`.
    *   **Store Normal:** Write $N.x, N.y, N.z$ to `normalArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal = true`.
    *   **Advance Count:** Increment `count` by 1.

5.  **Triangle Assembly:**
    After computing the 3 vertices of a triangle, ensure they are contiguous in the buffer. If the buffer is full, flush before starting the next triangle.

6.  **Flush and Render:**
    When `count > 0` (either due to buffer full or end of frame):
    *   Bind `posArray` to a WebGL buffer using `gl.bufferData` with `DYNAMIC_DRAW`.
    *   Bind `normalArray` similarly if `hasNormal` is true.
    *   Enable vertex attribute arrays and set pointers to the buffer data.
    *   Call `gl.drawArrays(gl.TRIANGLES, 0, count)`.
    *   Reset `count` to 0 and clear flags.

**Pseudocode:**

```python
# Constants
MAX_COUNT = 4096
POS_ARRAY_SIZE = MAX_COUNT * 3
NORMAL_ARRAY_SIZE = MAX_COUNT * 3

# State
pos_array = [0.0] * POS_ARRAY_SIZE
normal_array = [0.0] * NORMAL_ARRAY_SIZE
count = 0
has_pos = False
has_normal = False

def flush_and_render(gl, primitive_type):
    global count, has_pos, has_normal
    if count == 0:
        return
    
    # Bind position buffer
    gl.buffer_data(gl.ARRAY_BUFFER, pos_array[:count * 3], gl.DYNAMIC_DRAW)
    gl.enable_vertex_attrib_array(0) # Position attribute
    gl.vertex_attrib_pointer(0, 3, gl.FLOAT, False, 0, 0)
    
    # Bind normal buffer if available
    if has_normal:
        gl.buffer_data(gl.ARRAY_BUFFER, normal_array[:count * 3], gl.DYNAMIC_DRAW)
        gl.enable_vertex_attrib_array(1) # Normal attribute
        gl.vertex_attrib_pointer(1, 3, gl.FLOAT, False, 0, 0)
        
    # Draw
    gl.draw_arrays(primitive_type, 0, count)
    
    # Reset
    count = 0
    has_pos = False
    has_normal = False

def add_vertex(pos, normal):
    global count, has_pos, has_normal
    
    # Check for overflow before adding
    if count >= MAX_COUNT - 3:
        flush_and_render(gl, gl.TRIANGLES)
        
    # Store position
    idx = count * 3
    pos_array[idx] = pos[0]
    pos_array[idx+1] = pos[1]
    pos_array[idx+2] = pos[2]
    has_pos = True
    
    # Store normal
    normal_array[idx] = normal[0]
    normal_array[idx+1] = normal[1]
    normal_array[idx+2] = normal[2]
    has_normal = True
    
    count += 1

def process_voxel(v0, v1, v2, v3, v4, v5, v6, v7, isovalue):
    # 1. Calculate Case Index
    case_index = 0
    if v0 < isovalue: case_index |= 1
    if v1 < isovalue: case_index |= 2
    if v2 < isovalue: case_index |= 4
    if v3 < isovalue: case_index |= 8
    if v4 < isovalue: case_index |= 16
    if v5 < isovalue: case_index |= 32
    if v6 < isovalue: case_index |= 64
    if v7 < isovalue: case_index |= 128
    
    # 2. Lookup Triangles
    tri_table = get_triangle_table() # From parent article
    edges = tri_table[case_index]
    
    i = 0
    while edges[i] != -1:
        e1 = edges[i]
        e2 = edges[i+1]
        e3 = edges[i+2]
        i += 3
        
        # 3. Interpolate Vertices for each edge
        # Helper to interpolate edge between two corners
        def interp_edge(edge_idx, val1, val2, p1, p2):
            t = (isovalue - val1) / (val2 - val1)
            p = lerp(p1, p2, t)
            n = lerp(normal(p1), normal(p2), t) # Normal interpolation
            return p, n
            
        # Get corner values and positions
        corners = [v0, v1, v2, v3, v4, v5, v6, v7]
        positions = [get_voxel_corner_pos(j) for j in range(8)]
        normals = [compute_gradient_normal(j) for j in range(8)] # Or from field
        
        p1, n1 = interp_edge(e1, corners[e1], corners[get_edge_other(e1)], positions[e1], positions[get_edge_other(e1)])
        p2, n2 = interp_edge(e2, corners[e2], corners[get_edge_other(e2)], positions[e2], positions[get_edge_other(e2)])
        p3, n3 = interp_edge(e3, corners[e3], corners[get_edge_other(e3)], positions[e3], positions[get_edge_other(e3)])
        
        # 4. Add to Immediate Buffer
        add_vertex(p1, n1)
        add_vertex(p2, n2)
        add_vertex(p3, n3)
```

**Parameters:**
*   `maxCount`: 4096 (typical for WebGL immediate mode demos) [S1, unofficial].
*   `primsize`: 3 for triangles [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** The code must check `count >= maxCount - 3` before adding a vertex to ensure space for a full triangle. If exceeded, it flushes immediately [S1, unofficial].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points. The standard LUT uses a fixed triangulation, which can cause cracks if adjacent voxels resolve ambiguity differently [S7, S8, unofficial].
*   **Precision:** Linear interpolation assumes the field is smooth. Discontinuities in the scalar field can lead to incorrect normals.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels. Each voxel is processed once.
*   **Memory Complexity:** $O(1)$ auxiliary memory (fixed-size buffers) plus $O(V)$ for the scalar field grid.
*   **Performance:** Limited by CPU bottlenecks at high resolutions or high blob counts. The frequent `gl.bufferData` and `gl.drawArrays` calls create significant overhead compared to GPU-based approaches [S1, unofficial].
*   **Strengths:** Simple implementation, easy to debug, serves as a good reference for algorithm correctness.
*   **Limitations:** Poor scalability, high CPU usage, limited by buffer size (requires frequent flushing).
*   **When to use:** Educational purposes, reference implementations, or low-resolution real-time demos where GPU shaders are not available or too complex.
*   **When not to use:** High-resolution volume rendering, large scenes, or performance-critical applications.

## Background
The CPU Immediate Mode Marching Cubes approach is inspired by Gregg Tavares' (Greggman) metaballs demo, which demonstrated real-time metaball rendering in JavaScript using WebGL immediate mode [S1, unofficial]. It builds on the classic Marching Cubes algorithm by Lorensen and Cline (1987) and the lookup table configurations provided by Paul Bourke [S1, unofficial]. This method was popular in early WebGL experiments to showcase the capabilities of client-side rendering without complex geometry management.
