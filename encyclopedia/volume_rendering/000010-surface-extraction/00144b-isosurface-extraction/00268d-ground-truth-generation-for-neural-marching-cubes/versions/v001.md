# Ground Truth Generation for Neural Marching Cubes

Also called: LOD ground truth generation, NMC GT preprocessing

## Overview
This method generates the supervised training data (ground truth) required to train a Convolutional Neural Network (CNN) to predict Marching Cubes (MC) configurations for implicit surfaces, as introduced in Neural Marching Cubes (NMC) [S1, unofficial]. It solves the problem of mapping high-resolution surface representations (voxels and intersection points) to the discrete and continuous parameters expected by the MC algorithm for each grid cell. It differs from standard isosurface extraction by producing a multi-resolution dataset (LOD) stored in HDF5, rather than a single mesh, enabling the network to learn both topological case IDs and geometric vertex/plane parameters [S1, unofficial].

## How it works
The method processes high-resolution input data to produce ground truth arrays for target grid resolutions (typically 32 or 64). It handles the misalignment between the input voxel grid and the target MC grid cells through specific filtering and sampling strategies.

### Inputs and Outputs
**Inputs:**
1.  **High-resolution voxels:** A binary or signed distance field (SDF) grid at resolution $R_{high}$ (e.g., 1024).
2.  **Surface intersections:** A list of 3D points $(x, y, z)$ representing the intersection of the implicit surface with the voxel edges.
3.  **Target grid sizes:** A list of resolutions $G \in \{32, 64\}$ [S1, unofficial].
4.  **LUT Configurations:** A lookup table mapping the 32,768 possible voxel occupancy patterns (2^15 for the standard MC case, or simplified variants) to integer parameters [S1, unofficial].
5.  **LUT Tessellations:** A lookup table mapping occupancy patterns to triangle vertex indices [S1, unofficial].

**Outputs:**
HDF5 files containing per-grid-cell ground truth data for each target resolution $G$:
*   `_case_id`: Integer case ID for each cell.
*   `_int`: Integer parameters (vertex counts).
*   `_float`: Float parameters (vertex positions, plane parameters).
*   `_sdf`: SDF values at grid vertices.
*   `_voxel`: Voxel occupancy data.

### Data Structures and Layout
The ground truth is stored in HDF5 datasets. For a target grid size $G$, the layout is as follows [S1, unofficial]:

1.  **`_case_id`**: Shape $(G+1)^3$, type `int32`. Stores the MC case ID for each cell.
2.  **`_int`**: Shape $(G+1)^3 \times (\text{num\_of\_int\_params} - 1)$, type `int32`.
    *   $\text{num\_of\_int\_params} = 4$ (Case ID, corner vertex count, face vertex count, internal vertex count).
    *   The first column (Case ID) is stored in `_case_id`, so this array stores the remaining 3 counts.
3.  **`_float`**: Shape $(G+1)^3 \times \text{num\_of\_float\_params}$, type `float32`.
    *   $\text{num\_of\_float\_params} = 49$.
    *   Breakdown:
        *   8 corner vertices $\times$ 3 coordinates = 24.
        *   3 face vertices $\times$ 1 coordinate (depth/parameter) = 3.
        *   12 edge plane parameters $\times$ 2 coordinates = 24.

"8 corner vertices * 3 coords, 3 face vertices * 1 coord, 12 edge plane params * 2 coords". $24+3+24=51$. The note says `num_of_float_params = 8*3+3*1+12*2`. This sums to 51.
4.  **`_sdf`**: Shape $(G+1)^3$, type `float32`. SDF values at grid vertices.
5.  **`_voxel`**: Shape $(G+1)^3$, type `uint8`. Voxel occupancy.

### Parameters
*   `cell_size`: Ratio between grid cell size and base voxel size. Default 8 [S1, unofficial].
*   `grid_size_list`: List of target resolutions. Default `[32, 64]` [S1, unofficial].
*   `configs`: Array of shape $32768 \times 3$, storing `[case_id, #insideCC, #outsideCC]` for all 2^15 patterns [S1, unofficial].
*   `tessellations`: Array of shape $32768 \times \text{max\_num\_of\_triangles} \times 3$, storing triangle vertex indices [S1, unofficial].

### Steps

1.  **Downsample Intersection Points:**
    Filter the high-resolution intersection points to retain only those aligned with the target grid. For a target grid size $G$ and high-res size $R_{high}$, calculate `downscale` = $R_{high} / G$. Keep points where coordinates are multiples of `downscale`. Normalize coordinates to the range $[0, G]$ or $[0, 1]$ depending on implementation convention (NMC typically uses normalized or grid-indexed coordinates) [S1, unofficial].

2.  **Map Points to Cells:**
    Use a utility function (e.g., `cutils.get_intersection_points_in_cells`) to assign each filtered intersection point to its corresponding grid cell in the target resolution. Store these in `LOD_intersection_pointer` (indices) and `LOD_intersection_data` (coordinates) [S1, unofficial].

3.  **Sample Voxels:**
    Sample the high-resolution voxel grid onto the target grid vertices. Handle the misalignment between voxel centers and grid vertices by padding or offsetting. This is typically done via a function like `cutils.get_input_voxel` [S1, unofficial].

4.  **Compute Ground Truth Parameters:**
    Call the ground truth generation utility (e.g., `cutils.get_gt`) with the downsampled voxels, intersection data, and LUT configurations. For each cell:
    *   Determine the **Case ID** based on the voxel occupancy pattern of the cell's 8 corners.
    *   Determine **Integer Parameters**: Count the number of vertices inside the cell (`#insideCC`), outside the cell (`#outsideCC`), and internal vertices (if applicable).
    *   Determine **Float Parameters**:
        *   **Corner Vertices**: The 3D coordinates of the 8 cell corners.
        *   **Face Vertices**: The intersection points on the cell faces. If multiple intersections exist, specific selection logic (often based on the MC case) is applied. The "1 coord" likely refers to a parameter along the edge or a specific depth value if not storing full 3D coordinates for face vertices, but standard MC stores 3D positions. The source note `3*1` suggests a simplified representation or specific parameterization. *Note: Standard MC stores 3D positions for all vertices. The source note `3*1` is ambiguous. It might refer to a specific parameterization used in NMC-lite or a simplified storage. Given `12*2` for edge planes, it implies a plane equation representation for edges. We will follow the source's explicit count: 3 face vertices with 1 coordinate each.*
        *   **Edge Plane Parameters**: For each of the 12 edges, store 2 parameters defining the plane (e.g., normal components or distance and angle) [S1, unofficial].

5.  **Store to HDF5:**
    Write the computed arrays to the HDF5 file with the layout defined above [S1, unofficial].

### Edge Cases and Pitfalls
*   **Voxel-Cell Misalignment:** Voxels and Marching Cubes cells are not inherently aligned. The method handles this by padding or offsetting during voxel sampling via `cutils.get_input_voxel` [S1, unofficial].
*   **Precision:** Use `float32` for coordinates and parameters to match the network's expected input precision.
*   **Empty Cells:** Cells with no surface intersection should still have valid case IDs (likely 0 or 255) and zeroed float parameters.
*   **Boundary Conditions:** The grid size is $G+1$ to include boundary vertices. Ensure indices do not go out of bounds.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of high-resolution voxels and intersection points, plus linear with respect to the target grid size for the final parameter computation. The downsampling and mapping steps are efficient.
*   **Memory Complexity:** Proportional to the target grid size cubed $(G+1)^3$ times the number of parameters per cell. For $G=64$, this is manageable.
*   **Strengths:** Provides a consistent, multi-resolution dataset for training CNNs. Handles the complexity of MC configurations automatically.
*   **Limitations:** Requires high-resolution input data. The specific parameterization (e.g., 3 face vertices with 1 coord) is specific to NMC and may not be directly transferable to other MC variants without modification.
*   **When to use:** When training a CNN for Neural Marching Cubes or similar learning-based isosurface extraction methods.
*   **When not to use:** When a single high-quality mesh is needed without training a network.

## Background
Neural Marching Cubes (NMC) was introduced by Zhiqin Chen and Hao Zhang in 2021 [S1, unofficial]. The method uses a CNN to predict the topological case and geometric parameters of Marching Cubes directly from voxel inputs, bypassing the need for explicit surface extraction algorithms during inference. The ground truth generation method is a crucial preprocessing step to create the training dataset for this network.
