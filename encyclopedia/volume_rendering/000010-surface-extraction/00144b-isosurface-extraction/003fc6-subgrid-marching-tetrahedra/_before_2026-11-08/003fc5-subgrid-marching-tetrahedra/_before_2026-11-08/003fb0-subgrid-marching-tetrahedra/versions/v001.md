# Subgrid Marching Tetrahedra

Also called: Subgrid MT, Subgrid Marching Scheme

## Overview
Subgrid Marching Tetrahedra is a surface extraction method that recovers a manifold, intersection-free triangle mesh from the points where edges of a tetrahedral grid pierce a continuous surface [S1, unofficial]. Unlike classic marching cubes or tets, this scheme allows arbitrarily many surface patches within a single cell, capturing fine features and thin sheets that are typically lost due to Nyquist–Shannon limits [S1, unofficial]. It requires neither a well-defined inside/outside classification (allowing surfaces with boundary) nor consistently-oriented input geometry, while retaining the local, parallel nature of classic marching by performing reconstruction independently per tet [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral grid and a continuous surface defined by its intersections with the grid edges. The surface may be given as exact intersection points or approximated via 1D marching along edges if exact intersections are unavailable [S1, unofficial].
*   **Output:** A conforming, manifold, intersection-free triangle mesh [S1, unofficial].

**Data Structures:**
The core data structure is the **normal coordinate** encoding. For each tetrahedron, the connectivity of the surface is encoded using arbitrary integer intersection counts along each of the 6 grid edges [S1, unofficial].
*   **Edge Intersection Count:** An integer $n_e \ge 0$ representing the number of times the surface pierces edge $e$.
*   **Connectivity State:** The tuple of 6 integers $(n_{e_0}, n_{e_1}, \dots, n_{e_5})$ defines the topological configuration of the surface within the tetrahedron [S1, unofficial].

**Numbered Steps:**
1.  **Determine Edge Intersections:** For each edge of the tetrahedral grid, determine the points where the surface intersects the edge. If exact intersections are not available, perform 1D marching along the grid edges to approximate these points [S1, unofficial].
2.  **Count Intersections:** For each tetrahedron, count the number of intersection points on each of its 6 edges. Let $n_i$ be the count for edge $i$.
3.  **Encode Connectivity:** Store the tuple $(n_0, n_1, n_2, n_3, n_4, n_5)$ for each tetrahedron. This generalization of normal coordinates from geometric topology encodes the surface connectivity [S1, unofficial].
4.  **Lookup Spanning Surface:** Use the intersection count tuple to look up the corresponding spanning surface configuration from a precomputed table. The table maps each valid tuple of intersection counts to a set of triangles that interpolate the intersection points on the tetrahedron boundary [S1, unofficial]. The table must handle arbitrary complexity, including multiple disjoint patches [S1, unofficial].
5.  **Generate Triangles:** For each tetrahedron, generate the triangles specified by the lookup table. The triangles connect the intersection points on the edges of the tetrahedron [S1, unofficial].
6.  **Assemble Mesh:** Combine the triangles from all tetrahedra. Since the reconstruction is performed independently per tetrahedron and the intersection points on shared edges are consistent (due to the 1D marching or exact intersection calculation), the resulting mesh is conforming across tetrahedron boundaries [S1, unofficial].

**Formulas:**
*   **Intersection Count:** $n_e = \text{count}(\{p \mid p \in \text{edge}_e \cap \text{surface}\})$ [S1, unofficial].
*   **Spanning Surface Lookup:** $T = \mathcal{L}(n_0, n_1, n_2, n_3, n_4, n_5)$, where $\mathcal{L}$ is the lookup function mapping intersection counts to a set of triangles $T$ [S1, unofficial].

**Parameters:**
*   **Grid Resolution:** The method's accuracy scales with the grid resolution. For example, on a $180^3$ grid, the error is comparable to classic MT on a $500^3$ grid [S1, unofficial].
*   **Maximum Intersection Count:** The lookup table must support arbitrary intersection counts. The supplement provides tables up to a maximum intersection count, though the exact maximum is not specified in the abstract [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Inside/Outside Ambiguity:** Classic marching relies on inside/outside classification, which fails for surfaces with boundary. Subgrid MT avoids this by using intersection counts [S1, unofficial].
*   **Interpolation Errors:** Classic marching uses interpolated nodal values to estimate intersection locations, leading to geometric errors. Subgrid MT reconstructs geometry directly from intersection points, avoiding this error [S1, unofficial].
*   **Thin Features:** Classic marching may miss thin sheets or small topological features. Subgrid MT captures these by allowing multiple intersections per edge [S1, unofficial].

```python
    """
    Reconstructs a manifold mesh from edge-surface intersections.
    
    Args:
        tetrahedral_grid: List of tetrahedra, each defined by 4 vertex indices.
        surface_intersections: Dictionary mapping edge indices to lists of intersection points.
        
    Returns:
        List of triangles (each a tuple of 3 vertex positions).
    """
    triangles = []
    
    # Precomputed lookup table mapping intersection counts to triangles
    # This table must be generated separately and included.
    # Key: tuple of 6 integers (n0, n1, n2, n3, n4, n5)
    # Value: list of triangles, each triangle is a list of 3 points
    spanning_surface_table = load_spanning_surface_table()
    
    for tet in tetrahedral_grid:
        # Get the 6 edges of the tetrahedron
        edges = get_edges(tet)
        
        # Count intersections on each edge
        intersection_counts = []
        intersection_points = []
        for edge in edges:
            points = surface_intersections.get(edge, [])
            intersection_counts.append(len(points))
            intersection_points.append(points)
        
        # Create the key for the lookup table
        key = tuple(intersection_counts)
        
        # Lookup the spanning surface
        if key in spanning_surface_table:
            surface_triangles = spanning_surface_table[key]
            triangles.extend(surface_triangles)
        else:
            # Handle invalid or unsupported intersection count configurations
            # This should not happen if the table is comprehensive
            pass
            
    return triangles

def get_edges(tet):
    """Returns the 6 edges of a tetrahedron defined by 4 vertex indices."""
    v0, v1, v2, v3 = tet
    return [
        (v0, v1), (v0, v2), (v0, v3),
        (v1, v2), (v1, v3),
        (v2, v3)
    ]
```

## Operating characteristics
*   **Time Complexity:** Linear in the number of tetrahedra, as reconstruction is performed independently per tet [S1, unofficial].
*   **Memory Complexity:** Linear in the number of tetrahedra for the grid and output mesh. The lookup table size depends on the maximum intersection count supported, which can be large if arbitrary counts are allowed [S1, unofficial].
*   **Measured Performance:** On a $180^3$ grid, subgrid MT achieves comparable error to classic MT on a $500^3$ grid [S1, unofficial]. In a complex jet engine model, subgrid MT captures small details at $100^3$ resolution that classic MT misses even at $500^3$ [S1, unofficial].
*   **Strengths:** Captures fine features and thin sheets; no inside/outside classification required; handles surfaces with boundary; high accuracy at coarse resolutions [S1, unofficial].
*   **Limitations:** Requires a comprehensive lookup table for arbitrary intersection counts; may produce more triangles than classic marching for simple surfaces [S1, unofficial].
*   **When to Use:** When capturing thin features, complex topology, or surfaces with boundary is critical, and high accuracy at coarse resolutions is needed [S1, unofficial].
*   **When Not to Use:** When computational resources are extremely limited and the surface is simple, classic marching may be sufficient [S1, unofficial].

## Background
Subgrid Marching Tetrahedra was introduced by Hossein Baktash, Mark Gillespie, and Keenan Crane in 2026 [S1, unofficial]. It is published in ACM Transactions on Graphics [S1, unofficial]. The method generalizes normal coordinates from geometric topology to encode surface connectivity via arbitrary integer intersection counts [S1, unofficial]. It is a drop-in replacement for standard marching, retaining the local, parallel nature of classic marching while asymptotically reducing the number of samples relative to regular grid refinement [S1, unofficial]. The method can also be applied on a triangular grid in 2D [S1, unofficial].
