# Isosurface Rendering

Also called: PBNJ Isosurface, Polygonal Surface Mesh Rendering from Volume, Volumetric Isosurface Rendering

## Overview
Isosurface rendering extracts and visualizes a specific scalar value (the isovalue) from a 3D volume dataset, representing it as a continuous surface [S1, unofficial]. Unlike direct volume rendering which accumulates light along rays, this method renders only the extracted boundary, requiring explicit lighting calculations to convey shape and depth [S5, unofficial]. It is distinguished from sibling methods like [Optimized Mesh Reference](1888-optimized-mesh-reference.md) by its procedural generation of smooth surfaces at render time, avoiding the jagged artifacts of discrete voxel or coarse polygonal approximations [S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume grid (voxels), a threshold value (isovalue), and camera/lighting parameters.
*   **Output:** A rendered image of the isosurface with shading and material properties.

**Data Structures:**
*   **Volume Data:** A 3D array of scalar values. In some implementations (e.g., Unity shader optimizations), gradients are pre-computed and stored in the RGB channels of a texture, while the scalar density value is stored in the Alpha channel [S5, unofficial].
*   **Geometry:** In API-based approaches (e.g., OSPRay), an `isosurfaces` geometry object is created, which internally references the volume data and the list of isovalues [S2, unofficial].

**Steps:**
1.  **Ray Initialization:** For each pixel, cast a ray from the eye into the scene. Ideally, start the ray at the point where it intersects the front face of the volume bounding box [S5, unofficial].
2.  **Ray Marching:** Advance the ray through the volume in discrete steps. The step size is controlled by a `Step %` parameter, which defines the step length as a percentage of the voxel size [S3].
3.  **Threshold Check:** At each step, sample the voxel density at the current ray position.
4.  **Surface Detection:** If the sampled density exceeds the specified isovalue (threshold), the ray has hit the isosurface. Stop marching [S5, unofficial].
5.  **Normal Calculation:** Compute the surface normal at the hit point. This is done by calculating the gradient of the scalar field:
    *   Compare the data values of the current voxel with its neighbors along the X, Y, and Z axes [S5, unofficial].
    *   The gradient vector $\nabla f$ points in the direction of the greatest rate of increase. If data values decrease towards the positive X-axis, the normal component points in the positive X direction [S5, unofficial].
    *   *Note:* Calculating this gradient in the shader is expensive. A common optimization is to pre-calculate gradients and store them in the texture's RGB channels, storing the scalar value in the Alpha channel [S5, unofficial].
6.  **Lighting and Shading:** Calculate the color of the hit point using lighting models:
    *   **Diffuse Lighting:** $I_d = K_d \cdot \max(0, \text{dot}(n, l))$, where $K_d$ is the diffuse constant (often 1), $n$ is the normalized surface normal, and $l$ is the normalized direction to the light source [S5, unofficial].
    *   **Specular Lighting:** Controlled by specular intensity ($K_s$) and shininess ($N_s$). In OSPRay, $N_s$ is typically set to 10 [S2, unofficial].
    *   **Ambient Lighting:** Added as a base illumination, controlled by an ambient coefficient (default 0.3) [S4, unofficial].
7.  **Color Mapping:** Apply a transfer function to map the density value to color and opacity, allowing specific features (e.g., bones vs. skin) to be highlighted [S5, unofficial].

**Pseudocode:**
```python
def render_isosurface(volume, isovalue, camera, lights, step_size):
    """
    Renders an isosurface from a volume using ray marching.
    
    Args:
        volume: 3D array of scalar values.
        isovalue: Threshold for surface extraction.
        camera: Camera object with position, direction, and view parameters.
        lights: List of light sources.
        step_size: Distance to march per step (e.g., 0.5 * voxel_size).
    
    Returns:
        Image buffer.
    """
    image_width = camera.width
    image_height = camera.height
    image = zeros((image_height, image_width, 3))

    for y in range(image_height):
        for x in range(image_width):
            # 1. Generate ray
            ray_origin = camera.get_origin(x, y)
            ray_direction = camera.get_direction(x, y)
            ray_direction = normalize(ray_direction)

            # 2. Ray Marching
            t = 0.0
            hit = False
            hit_normal = None
            hit_density = 0.0
            
            # Start from front face of bounding box (simplified)
            t = get_front_face_intersection(ray_origin, ray_direction, volume.bounds)
            
            while t < volume.bounds.max_depth and not hit:
                # Sample volume at current position
                pos = ray_origin + ray_direction * t
                density = sample_volume(volume, pos)
                
                # 3. Check threshold
                if density > isovalue:
                    hit = True
                    hit_density = density
                    # 4. Calculate Normal
                    hit_normal = compute_gradient(volume, pos)
                    hit_normal = normalize(hit_normal)
                    break
                
                t += step_size

            if hit:
                # 5. Lighting Calculation
                color = vec3(0.0, 0.0, 0.0)
                
                # Ambient
                color += volume.ambient * vec3(1.0, 1.0, 1.0)
                
                for light in lights:
                    light_dir = normalize(light.position - pos)
                    # Diffuse
                    diff = max(dot(hit_normal, light_dir), 0.0)
                    color += volume.diffuse * diff * light.color
                    
                    # Specular (simplified Blinn-Phong)
                    view_dir = normalize(camera.position - pos)
                    half_dir = normalize(light_dir + view_dir)
                    spec = pow(max(dot(hit_normal, half_dir), 0.0), volume.specular_power)
                    color += volume.specular * spec * light.color
                
                # 6. Apply Transfer Function
                final_color = apply_transfer_function(color, hit_density)
                image[y, x] = final_color

    return image

def compute_gradient(volume, pos):
    """
    Computes the gradient (normal) by comparing neighbor values.
    """
    # Get voxel coordinates
    ix, iy, iz = world_to_voxel_coords(pos, volume)
    
    # Sample neighbors (with boundary checks)
    val_center = sample_volume(volume, pos)
    val_x_plus = sample_volume(volume, pos + vec3(volume.voxel_size, 0, 0))
    val_x_minus = sample_volume(volume, pos - vec3(volume.voxel_size, 0, 0))
    val_y_plus = sample_volume(volume, pos + vec3(0, volume.voxel_size, 0))
    val_y_minus = sample_volume(volume, pos - vec3(0, volume.voxel_size, 0))
    val_z_plus = sample_volume(volume, pos + vec3(0, 0, volume.voxel_size))
    val_z_minus = sample_volume(volume, pos - vec3(0, 0, volume.voxel_size))
    
    # Central difference approximation
    grad_x = val_x_plus - val_x_minus
    grad_y = val_y_plus - val_y_minus
    grad_z = val_z_plus - val_z_minus
    
    return vec3(grad_x, grad_y, grad_z)
```

**Parameters:**
*   **Isovalue:** The scalar threshold for extraction. In OSPRay, this is an array of floats `isoValues` [S2, unofficial].
*   **Step % (`rendstep`):** Percentage of cell size for ray marching step. Lower values capture smaller details but increase render time [S3].
*   **Sampler Type:** Blending method between voxels (Box, Linear, Spherical). Affects smoothness and speed [S3].
*   **Lighting Coefficients:**
    *   `ambient`: Default 0.3 [S4, unofficial].
    *   `diffuse`: Default 0.6 [S4, unofficial].
    *   `specular`: Default 0.05 (coefficient) or 0.1 (intensity parameter in OSPRay) [S2, unofficial][S4, unofficial].
    *   `specular_power`: Default 1 [S4, unofficial].
*   **Interpolation:** Shading type ('phong', 'flat', 'gouraud') [S4, unofficial].

**Edge Cases and Pitfalls:**
*   **Gradient Calculation Cost:** Computing gradients in the shader is expensive. Pre-computing and storing them in texture channels trades memory for performance [S5, unofficial].
*   **Jagged Artifacts:** If the mesh mode produces jagged results, isosurface mode provides a smoother result but is slower [S3].
*   **Boundary Artifacts:** Sharp edges at the volume boundary can be mitigated using a "Border Fade" parameter to make boundary voxels transparent [S3].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the average ray length within the volume. The step size (`Step %`) directly impacts performance; smaller steps increase cost [S3].
*   **Memory Complexity:** Depends on the volume storage. If gradients are pre-computed, memory usage increases by a factor of 3 (RGB for gradient, A for density) [S5, unofficial].
*   **Performance:** Slower than Mesh mode rendering because it computes the surface procedurally at render time rather than using a pre-existing polygonal mesh [S3].
*   **Strengths:** Produces smooth surfaces without the jagged edges of discrete voxel rendering; allows for dynamic threshold adjustment [S3].
*   **Limitations:** Requires lighting calculations for visual quality; sensitive to step size for detail capture [S5, unofficial].
*   **When to Use:** Virtual endoscopy, medical visualization where smooth surfaces are critical, or when mesh smoothing is too slow/impossible [S1, unofficial][S3].
*   **When Not to Use:** When real-time performance is critical and pre-computed meshes are available; when internal volume structure (not just surface) needs to be visualized.

## Background
Isosurface rendering is a fundamental technique in volume visualization, formally defined as rendering surfaces where $f(x, y, z) = \text{const}$ [S1, unofficial]. It is widely used in scientific visualization and medical imaging. The technique has been adapted for interactive rendering on GPUs, moving from CPU-based ray tracing to hardware-accelerated shaders [S1, unofficial]. Implementations exist in various frameworks, including OSPRay (using `ospNewGeometry` with type "isosurfaces") and Unity3D (using custom shaders) [S2, unofficial][S5, unofficial].
