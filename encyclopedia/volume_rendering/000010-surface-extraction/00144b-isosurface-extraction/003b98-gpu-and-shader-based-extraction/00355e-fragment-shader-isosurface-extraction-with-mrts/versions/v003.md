# Fragment Shader Isosurface Extraction with MRTs

Also called: Fragment Shader Isosurface Extraction

## Overview
This method computes isosurfaces from unstructured tetrahedral grids using fragment shaders and Multiple Render Targets (MRTs), enabling the generated geometry to be reused via render-to-vertex-arrays [S1, unofficial][S2, unofficial]. It distinguishes itself from sibling methods by decoupling surface extraction from immediate rasterization; instead of emitting triangles directly to the screen, it writes vertex positions to texture buffers, allowing for flexible post-processing and view-independent extraction [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral grid where each tetrahedron contains scalar values at its four vertices.
*   **Output:** A coherent mesh representing the isosurface, rendered from the generated vertex arrays.

**Data Structures:**
1.  **Marching Tetrahedra Tables:** Stored as textures [S1, unofficial][S2, unofficial].
2.  **Mesh Information:** Stored in textures following a compact representation framework [66] to reduce memory footprint [S1, unofficial][S2, unofficial].
3.  **Render Targets (MRTs):** Four separate render targets (textures) are allocated to store the resulting vertices [S1, unofficial][S2, unofficial].

**Algorithm Steps:**
1.  **Setup:** Bind the marching tetrahedra tables and mesh information textures [S1, unofficial][S2, unofficial]. Configure the fragment shader to access these textures [G].
2.  **Rasterization of Tetrahedra:** Draw a single quadrilateral for each tetrahedron in the grid [S1, unofficial][S2, unofficial].
3.  **Fragment Shader Execution:** For each fragment generated by the quadrilateral:
    *   Interpolate the scalar values at the four vertices of the tetrahedron [G].
    *   Determine the intersection points of the isosurface with the tetrahedron edges using linear interpolation [G].
    *   Consult the marching tetrahedra table (stored in texture) to determine which edges are intersected [S1, unofficial][S2, unofficial].
    *   Compute the exact 3D coordinates of the intersection points [G].
    *   Produce up to four vertices representing the isosurface segments within the tetrahedron [S1, unofficial][S2, unofficial].
4.  **MRT Writing:** Write the computed vertices into the four MRTs [S1, unofficial][S2, unofficial].
5.  **Mesh Assembly:** Bind the MRTs as vertex arrays [S1, unofficial][S2, unofficial]. Render these vertex arrays to produce the final isosurface mesh [S1, unofficial][S2, unofficial].

**Pseudocode:**

def fragment_shader(tetrahedron_vertices, scalar_values, isovalue, marching_table_texture):
    """
    Computes isosurface vertices for a single tetrahedron.
    tetrahedron_vertices: Array of 4 vec3 positions.
    scalar_values: Array of 4 floats.
    isovalue: The threshold scalar value.
    marching_table_texture: Texture containing topology data.
    """
    case_index = 0
    for i in range(4):
        if scalar_values[i] < isovalue:
            case_index |= (1 << i)
    
    intersected_edges = marching_table_texture.sample(case_index)
    
    vertices = []
    for edge in intersected_edges:
        v1 = tetrahedron_vertices[edge.v1]
        v2 = tetrahedron_vertices[edge.v2]
        s1 = scalar_values[edge.v1]
        s2 = scalar_values[edge.v2]
        t = (isovalue - s1) / (s2 - s1)
        vertices.append(mix(v1, v2, t))
    return vertices

**Edge Cases and Pitfalls:**
*   **Precision:** Linear interpolation assumes linear scalar variation within the tetrahedron, which may not hold for complex fields [G].
*   **Memory:** The technique is limited by the amount of video memory available for the MRTs and texture storage [S1, unofficial][S2, unofficial].
*   **CPU-GPU Transfer:** Performance is impacted by the speed of CPU-GPU memory transfers if data needs to be moved between host and device [S1, unofficial][S2, unofficial].

## Subtopics

### Rasterization-based Isosurface Extraction (Alpha-Test/Stencil)
An early technique that computes plane-tetrahedra intersections using rasterization hardware with alpha-test and stencil buffer functionality, without programmable shaders [S1, unofficial]. It draws the back and front faces of a given cell in order, with the interpolated scalar value stored at the alpha component [S1, unofficial]. The alpha-test is configured to reject fragments less than the desired isovalue [S1, unofficial]. The combination of results from back and front faces is obtained using a XOR operation on the stencil buffer [S1, unofficial]. This algorithm runs in two passes (the first sets the stencil buffer) and renders an average of 5 to 7 triangles per tetrahedron [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of tetrahedra, as each tetrahedron is processed once [G].
*   **Memory Complexity:** Proportional to the number of tetrahedra and the size of the MRTs and texture storage [G].
*   **Performance:** The method is efficient in leveraging GPU parallelism but is limited by video memory capacity and CPU-GPU transfer speeds [S1, unofficial][S2, unofficial].
*   **Strengths:** Allows for view-independent extraction and flexible post-processing via render-to-vertex-arrays [S1, unofficial][S2, unofficial].
*   **Limitations:** High memory usage due to MRTs and texture storage; potential bottlenecks in CPU-GPU data transfer [S1, unofficial][S2, unofficial].
*   **When to Use:** When flexible post-processing or view-independent extraction is required, and sufficient GPU memory is available [G].
*   **When Not to Use:** When memory is constrained or when immediate rasterization without intermediate storage is preferred [G].

## Background
This technique was proposed in [33] as a solution to compute isosurfaces using fragment shaders, allowing results to be reused with render-to-vertex-arrays functionality [S1, unofficial][S2, unofficial]. It builds on the framework outlined in [66] for representing mesh information in textures, but introduces a more compact representation to reduce memory footprint [S1, unofficial][S2, unofficial]. The method is part of the broader effort to push volume rendering computations to the GPU, leveraging programmable shaders for greater flexibility and performance compared to early rasterization-based methods [S1, unofficial].
