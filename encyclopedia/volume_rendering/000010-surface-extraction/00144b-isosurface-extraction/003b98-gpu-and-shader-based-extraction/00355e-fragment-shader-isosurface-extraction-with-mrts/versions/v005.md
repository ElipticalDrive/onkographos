# Fragment Shader Isosurface Extraction with MRTs

Also called: Fragment Shader Isosurface Extraction, Fragment Shader Isosurface with MRTs

## Overview
This method extracts isosurfaces from unstructured grids by leveraging fragment shaders and Multiple Render Targets (MRTs) to compute vertex data directly on the GPU, allowing results to be reused with render-to-vertex-arrays functionality [S1, S2, S3, unofficial]. It solves the problem of inefficient post-processing by avoiding the transfer of intermediate position data to CPU memory, instead writing extracted vertices directly into GPU memory targets [S1, S2, S3, unofficial]. Unlike [Marching Cubes with Gaussian Deformation](3769-marching-cubes-with-gaussian-deformation.md) which operates on structured grids, this approach is designed for unstructured tetrahedral grids, and unlike [Rasterization-based Isosurface Extraction (Alpha-Test/Stencil)](8487-rasterization-based-isosurface-extraction-alpha-test-stencil.md), it utilizes programmable fragment shaders rather than legacy fixed-function pipeline states [S1, S2, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh represented in a compact texture format following the framework in [66] (as cited in [S1, S2, S3, unofficial]), and marching tetrahedra lookup tables stored as textures [S1, S2, S3, unofficial].
*   **Output:** A set of vertices representing the isosurface, stored in four MRT targets, which are subsequently bound as vertex arrays for rendering [S1, S2, S3, unofficial].

**Data Structures:**
1.  **Mesh Information Texture:** Stores the tetrahedral mesh data. The sources specify a "compact representation" to reduce memory footprint, based on the framework in [66], but do not provide the exact field layout, bit-packing, or size of this texture [S1, S2, S3, unofficial].
2.  **Marching Tetrahedra Table Texture:** Stores the lookup tables required for the marching tetrahedra algorithm [S1, S2, S3, unofficial]. The exact layout (e.g., number of entries, data type per entry) is not specified in the sources [S1, S2, S3, unofficial].

**Algorithm Steps:**
1.  **Setup MRTs:** Configure the graphics pipeline to write to four distinct render targets (MRTs) [S1, S2, S3, unofficial].
2.  **Rasterization:** Draw a single quadrilateral for each tetrahedron in the mesh [S1, S2, S3, unofficial].
3.  **Fragment Shader Execution:** For each fragment generated by the quadrilateral:
    a.  Identify the specific tetrahedron associated with the fragment [S1, S2, S3, unofficial].
    b.  Sample the mesh information texture to retrieve the scalar values at the tetrahedron's vertices [S1, S2, S3, unofficial].
    c.  Determine the intersection of the isosurface with the tetrahedron edges using the scalar values [S1, S2, S3, unofficial].
    d.  Consult the marching tetrahedra table texture to determine the topology of the intersection [S1, S2, S3, unofficial].
    e.  Compute the coordinates of the intersection points (up to four vertices per tetrahedron) [S1, S2, S3, unofficial].
    f.  Write the computed vertices into the four MRTs [S1, S2, S3, unofficial].
4.  **Vertex Array Binding:** Bind the resulting MRTs as vertex arrays [S1, S2, S3, unofficial].
5.  **Final Rendering:** Render the bound vertex arrays to produce the final isosurface geometry [S1, S2, S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Limitations:** The technique is limited by the amount of memory available in the graphics card [S1, S2, S3, unofficial].
*   **Transfer Speed:** Performance is limited by the speed of CPU-GPU memory transfers, particularly if intermediate data were to be copied to CPU memory, which this method aims to avoid [S1, S2, S3, unofficial].
*   **Self-Occlusion:** Isosurfaces often exhibit large amounts of self-occlusion. Extracting the entire isosurface in a view-independent manner generates occluded elements that do not contribute to the final image [S1, S2, S3, unofficial].

## Subtopics

### [Rasterization-based Isosurface Extraction (Alpha-Test/Stencil)](8487-rasterization-based-isosurface-extraction-alpha-test-stencil.md)
This method extracts isosurfaces from unstructured grids by leveraging fixed-function rasterization hardware, specifically the alpha-test and stencil buffer, without relying on programmable fragment shaders. It solves the problem of computing plane-tetrahedron intersections by encoding scalar values in the alpha channel and using bitwise operations to isolate intersection fragments. Unlike modern shader-based approaches, it relies on legacy graphics pipeline states, making it suitable for hardware lacking programmable shading capabilities.

## Background
This technique was proposed in [33] (as cited in [S1, S2, S3, unofficial]) as a solution to compute isosurfaces using fragment shaders. It builds on the framework outlined in [66] (as cited in [S1, S2, S3, unofficial]) for representing mesh information in textures, adapting it to a more compact representation. The method is part of the broader field of GPU-based volume rendering of unstructured grids [S1, S2, S3, unofficial].
