# Fragment Shader Isosurface Extraction with MRTs

Also called: Fragment Shader Isosurface Extraction

## Overview
This method extracts isosurfaces from unstructured grids (specifically tetrahedral meshes) by leveraging fragment shaders and Multiple Render Targets (MRTs) to compute vertex positions directly in the GPU, avoiding intermediate CPU-GPU transfers [S1, S2, unofficial]. It differs from sibling methods like [GPU Marching Cubes with Atomic Counter Emission](4082-gpu-marching-cubes-with-atomic-counter-emission.md) by using parallel fragment outputs for vertex storage rather than atomic counters for dynamic list building, and from [Transvoxel](6277-transvoxel.md) by operating on fixed tetrahedral cells rather than adaptive voxel hierarchies.

## How it works
**Inputs:**
*   Tetrahedral mesh topology (vertices and connectivity).
*   Scalar field values associated with mesh vertices.
*   Target isovalue.

**Outputs:**
*   A set of vertices representing the isosurface, stored in GPU memory as vertex arrays ready for rendering.

**Data Structures:**
1.  **Mesh Information Texture:** Stores the scalar field and tetrahedral connectivity. The layout follows the framework in [66] but uses a more compact representation to reduce memory footprint [S1, S2, unofficial].
2.  **Marching Tetrahedra Tables Texture:** Stores the precomputed lookup tables for the Marching Tetrahedra algorithm, indexed by the configuration of scalar values relative to the isovalue [S1, S2, unofficial].

**Algorithm Steps:**
1.  **Preparation:** Load the compact mesh information and marching tetrahedra tables into GPU textures [S1, S2, unofficial].
2.  **Rasterization:** Draw a single quadrilateral for each tetrahedron in the mesh. The quadrilateral serves as a coverage area for the fragment shader to process the tetrahedron [S1, S2, unofficial].
3.  **Fragment Shader Execution:** For each fragment generated by the quadrilateral:
    *   Identify the specific tetrahedron being processed (via the fragment's position or associated data).
    *   Sample the scalar values at the tetrahedron's vertices.
    *   Determine the intersection configuration of the isosurface with the tetrahedron edges.
    *   Compute the exact 3D coordinates of the intersection points.
    *   Produce up to four vertices (intersection points) for the current tetrahedron [S1, S2, unofficial].
4.  **MRT Output:** Write the computed vertices into four separate render targets (MRTs) simultaneously. Each MRT target stores one potential vertex position for the tetrahedron [S1, S2, unofficial].
5.  **Final Rendering:** Bind the four MRT textures as vertex arrays. Render these vertex arrays to produce the final isosurface geometry [S1, S2, unofficial].

**Pseudocode:**
```python
# Vertex Shader
# Passes the tetrahedron ID and necessary data to the fragment shader
# via varying variables. Draws one quad per tetrahedron.

# Fragment Shader
void main() {
    // 1. Retrieve tetrahedron data from textures
    // Assuming 'tetraID' is passed from vertex shader
    vec4 v0 = sampleScalarField(tetraID, 0);
    vec4 v1 = sampleScalarField(tetraID, 1);
    vec4 v2 = sampleScalarField(tetraID, 2);
    vec4 v3 = sampleScalarField(tetraID, 3);
    
    // 2. Determine configuration
    // Compare scalar values to isovalue
    int config = 0;
    if (v0.w > isovalue) config |= 1;
    if (v1.w > isovalue) config |= 2;
    if (v2.w > isovalue) config |= 4;
    if (v3.w > isovalue) config |= 8;
    
    // 3. Lookup intersection points
    // Use 'config' to index into the Marching Tetrahedra Table texture
    // The table returns indices of edges that intersect the isosurface
    int edgeIndices[4]; // Max 4 intersections per tetrahedron
    int numIntersections = lookupMarchingTetrahedraTable(config, edgeIndices);
    
    // 4. Compute intersection positions
    // Interpolate along the edges defined by edgeIndices
    vec3 positions[4];
    for (int i = 0; i < numIntersections; i++) {
        int e0 = edgeIndices[i] / 2;
        int e1 = edgeIndices[i] % 2;
        vec3 p0 = getVertexPosition(e0); // From mesh texture
        vec3 p1 = getVertexPosition(e1); // From mesh texture
        float s0 = getScalarValue(e0);
        float s1 = getScalarValue(e1);
        float t = (isovalue - s0) / (s1 - s0);
        positions[i] = mix(p0, p1, t);
    }
    
    // 5. Write to MRTs
    // Each MRT target gets one vertex position
    // If numIntersections < 4, remaining targets get undefined or zero values
    // which are filtered out during final rendering or handled by the caller
    if (numIntersections > 0) gl_FragData[0] = vec4(positions[0], 1.0);
    else gl_FragData[0] = vec4(0.0, 0.0, 0.0, 0.0); // [G] Guard against empty output
    
    if (numIntersections > 1) gl_FragData[1] = vec4(positions[1], 1.0);
    else gl_FragData[1] = vec4(0.0, 0.0, 0.0, 0.0); // [G] Guard
    
    if (numIntersections > 2) gl_FragData[2] = vec4(positions[2], 1.0);
    else gl_FragData[2] = vec4(0.0, 0.0, 0.0, 0.0); // [G] Guard
    
    if (numIntersections > 3) gl_FragData[3] = vec4(positions[3], 1.0);
    else gl_FragData[3] = vec4(0.0, 0.0, 0.0, 0.0); // [G] Guard
}
```

**Parameters:**
*   **Isovalue:** The scalar threshold for extraction.
*   **MRT Count:** Fixed at 4 to accommodate the maximum number of intersections per tetrahedron [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Limitations:** The technique is limited by the amount of video memory available on the graphics card, as it stores mesh data and MRTs in GPU memory [S1, S2, unofficial].
*   **CPU-GPU Transfer Speed:** Performance is impacted by the speed of CPU-GPU memory transfers if data needs to be updated frequently [S1, S2, unofficial].
*   **Degenerate Cases:** If a vertex lies exactly on the isovalue, special handling is required to avoid ambiguity in edge intersection calculation [G].

## Subtopics

### Rasterization-based Isosurface Extraction (Alpha-Test/Stencil)
An early technique that computes plane-tetrahedra intersections using fixed-function rasterization hardware with alpha-test and stencil buffers, without programmable shaders [S1, unofficial]. It draws the back and front faces of a cell in order, storing an interpolated scalar value in the alpha component, and configures the alpha-test to reject fragments below the isovalue [S1, unofficial]. The final intersection is obtained by performing a XOR operation on the stencil buffer between the back and front face passes [S1, unofficial]. This method runs in two passes and renders an average of 5 to 7 triangles per cell [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of tetrahedra, as each tetrahedron is processed in parallel by a fragment shader invocation [S1, S2, unofficial].
*   **Memory Complexity:** Proportional to the size of the tetrahedral mesh, plus the overhead of four render targets (MRTs) for vertex storage [S1, S2, unofficial].
*   **Performance:** Efficient for large datasets due to parallel fragment processing, but constrained by GPU memory capacity [S1, S2, unofficial].
*   **Strengths:** Avoids CPU-GPU bottlenecks by keeping data on the GPU; allows direct reuse of results via render-to-vertex-arrays [S1, S2, unofficial].
*   **Limitations:** High memory usage due to MRTs and texture storage; limited by VRAM size and PCIe transfer speeds if data is updated [S1, S2, unofficial].
*   **When to Use:** When real-time or near-real-time extraction from large unstructured grids is required and sufficient GPU memory is available.
*   **When Not to Use:** When GPU memory is insufficient for the dataset or when frequent CPU-GPU data transfers are a bottleneck.

## Background
This method was proposed in [33] as a solution to compute isosurfaces using fragment shaders, enabling results to be reused with render-to-vertex-arrays functionality [S1, S2, unofficial]. It builds on earlier work by [69] and [58], which explored rasterization hardware without programmable shaders, and [66], which outlined the framework for storing mesh information in textures [S1, unofficial]. The technique represents a shift towards fully GPU-based pipelines for volume rendering of unstructured grids, reducing reliance on CPU-side processing [S1, S2, unofficial].
