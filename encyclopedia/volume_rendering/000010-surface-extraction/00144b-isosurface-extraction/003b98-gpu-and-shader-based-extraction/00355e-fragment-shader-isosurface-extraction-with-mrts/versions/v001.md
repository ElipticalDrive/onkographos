# Fragment Shader Isosurface Extraction with MRTs

Also called: Fragment Shader Isosurface Extraction

## Overview
This method computes isosurfaces from unstructured tetrahedral grids using fragment shaders and Multiple Render Targets (MRTs), enabling the generated geometry to be directly reused via render-to-vertex-arrays [S1, unofficial]. It distinguishes itself from sibling methods by performing the entire extraction and mesh assembly pipeline on the GPU, avoiding CPU-GPU synchronization bottcks associated with hybrid approaches [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral grid (unstructured volume data) and an isovalue.
*   **Output:** A triangle mesh representing the isosurface.

**Data Structures:**
1.  **Mesh Information:** Stored in GPU textures. The layout follows the framework in [66] but uses a more compact representation to reduce memory footprint [S1, unofficial].
2.  **Marching Tetrahedra Tables:** Stored as textures to allow efficient lookup of edge intersections within the shader [S1, unofficial].

**Steps:**
1.  **Setup:** Bind the mesh information and marching tetrahedra tables as textures. Configure the fragment shader to use MRTs.
2.  **Rasterization:** Draw a single quadrilateral per tetrahedron in the scene [S1, unofficial].
3.  **Fragment Shader Execution:** For each fragment generated by the quadrilateral:
    *   The shader determines which tetrahedron the fragment belongs to.
    *   It extracts the isosurface for that specific tetrahedron.
    *   It computes up to four vertices resulting from the intersection of the isosurface with the tetrahedron edges [S1, unofficial].
4.  **MRT Writing:** Write the computed vertices into four separate render targets (MRTs) corresponding to the potential vertices [S1, unofficial].
5.  **Assembly:** Bind the resulting MRTs as vertex arrays.
6.  **Rendering:** Render the vertex arrays to produce the final isosurface mesh [S1, unofficial].

**Pseudocode:**
```python
# Pseudocode for the fragment shader logic
def fragment_shader(tet_index, barycentric_coords):
    # 1. Retrieve tetrahedron vertices and scalar values from texture
    # Assuming a compact texture layout for mesh info [S1, unofficial]
    v0, v1, v2, v3 = get_tet_vertices(tet_index)
    s0, s1, s2, s3 = get_tet_scalars(tet_index)
    
    # 2. Determine intersection edges using Marching Tetrahedra Table
    # Table is stored in a texture [S1, unofficial]
    case_id = get_marching_case(s0, s1, s2, s3, isovalue)
    edge_indices = lookup_marching_table(case_id)
    
    # 3. Compute intersection points
    vertices = []
    for edge_idx in edge_indices:
        p_start, p_end = get_edge_points(edge_idx, v0, v1, v2, v3)
        s_start, s_end = get_edge_scalars(edge_idx, s0, s1, s2, s3)
        
        # Linear interpolation to find intersection
        t = (isovalue - s_start) / (s_end - s_start)
        intersection_point = lerp(p_start, p_end, t)
        vertices.append(intersection_point)
        
    # 4. Write up to 4 vertices to MRTs
    # MRT 0, 1, 2, 3 correspond to the potential output vertices
    for i in range(4):
        if i < len(vertices):
            write_mrt(i, vertices[i])
        else:
            write_mrt(i, vec3(0.0)) # Or discard, depending on driver behavior
```

**Parameters:**
*   **Isovalue:** The scalar threshold for extraction.
*   **MRT Count:** Fixed at 4 to accommodate the maximum number of vertices per tetrahedron [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Limits:** The technique is limited by the amount of memory available in the graphics card [S1, unofficial].
*   **Transfer Speed:** Performance is constrained by the speed of CPU-GPU memory transfers if data needs to be synchronized [S1, unofficial].
*   **Degenerate Cases:** The method assumes standard tetrahedra; degenerate tetrahedra may require special handling in the texture layout or shader logic (not specified in sources) [G].

## Subtopics

### Rasterization-based Isosurface Extraction (Alpha-Test/Stencil)
An early technique that computes plane-tetrahedra intersections without programmable shaders, using rasterization hardware with alpha-test and stencil buffer functionality [S1, unofficial]. It draws the back and front faces of a given cell in order, with the interpolated scalar value stored at the alpha component. An alpha-test rejects fragments less than the desired isovalue. The combination of results from back and front faces is obtained using a XOR operation on the stencil buffer. The algorithm runs in two passes (the first sets the stencil buffer) and renders 5 to 7 triangles on average [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Dependent on the texture size for mesh information and marching tables. The compact representation aims to minimize this footprint [S1, unofficial].
*   **Performance:** Limited by GPU memory capacity and CPU-GPU transfer speeds [S1, unofficial].
*   **Strengths:** Allows full GPU processing of extraction and mesh assembly, avoiding CPU bottlenecks. Results are directly usable as vertex arrays [S1, unofficial].
*   **Limitations:** High memory usage on the GPU; potential latency in data transfer if hybrid approaches are mixed [S1, unofficial].
*   **When to use:** When full GPU pipeline is desired and sufficient VRAM is available.
*   **When not:** When memory is constrained or CPU-GPU synchronization is unavoidable for other pipeline stages.

## Background
This method was proposed in [33] as a solution to compute isosurfaces using fragment shaders, allowing results to be reused with render-to-vertex-arrays functionality [S1, unofficial]. It builds on the framework outlined in [66] for representing mesh information in textures, adapting it for compactness [S1, unofficial]. The approach is part of the broader trend of pushing volume rendering and extraction workloads to the GPU to leverage parallel processing capabilities [S1, unofficial].
