# Marching Cubes with Gaussian Deformation

Also called: Geometry Shader Marching Cubes, Marching Cubes Geometry Shader Variant, Marching Cubes with Brush Deformation

## Overview
This method extracts an isosurface from a scalar field using a GPU geometry shader, applying a Gaussian-based deformation to the resulting mesh vertices along a user-defined force vector [S1, unofficial]. It differs from standard Marching Cubes by integrating the deformation directly into the primitive generation stage, allowing for real-time, procedural modification of the surface topology without pre-computing a deformed scalar field [S1, unofficial]. It builds on [GPU and Shader-Based Extraction](9036-gpu-and-shader-based-extraction.md) by utilizing the geometry shader's ability to generate new primitives and modify vertex attributes on the fly [G].

## How it works

### Inputs and Outputs
**Inputs:**
*   A point cloud representing voxel grid positions, where each point corresponds to a cube in the scalar field [S1, unofficial].
*   A scalar field function $f(\mathbf{p})$ defined analytically (e.g., a sphere function) [S1, unofficial].
*   Uniform parameters: grid size ($s$), deformation force vector ($\mathbf{F}$), and Gaussian width ($\sigma$) [S1, unofficial].
*   Lookup tables for edge and triangle configurations stored in 2D integer textures [S1, unofficial].

**Outputs:**
*   A `TriangleStream` of deformed mesh vertices in clip space [S1, unofficial].

### Data Structures
**Lookup Tables:**
The standard Marching Cubes edge and triangle tables are stored in 2D textures to allow efficient GPU access via `texelFetch` [S1, unofficial].
*   `edgeTableTex`: Stores the 256x16 edge configuration table. Accessed as `texelFetch(edgeTableTex, ivec2(cubeIndex, 0), 0).r` [S1, unofficial].
*   `triTableTex`: Stores the 256x5 triangle configuration table. Accessed as `texelFetch(triTableTex, ivec2(cubeIndex, 0), 0).r` [S1, unofficial].

**Edge Vertex Mapping:**
A static array `cube_diff_indices` of size 24 maps the 12 cube edges to their two endpoint vertex indices [S1, unofficial]. The layout is:
`{0,1, 1,2, 2,3, 3,0, 4,5, 5,6, 6,7, 7,4, 0,4, 1,5, 2,6, 3,7}` [S1, unofficial].

**Shader Structures:**
*   **Vertex Shader:** Transforms vertex position to world space using `unity_ObjectToWorld` and passes normal and texcoord unchanged [S2, unofficial].
*   **Geometry Shader Input:** A single point representing a voxel grid position [S1, unofficial].
*   **Geometry Shader Output:** A structure containing `pos` (clip space), `uv`, and `col` [S2, unofficial].

### Formulas
**Scalar Field Evaluation:**
The scalar field value at a point $\mathbf{p}$ is computed as [S1, unofficial]:
$$ f(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - (r + s\sqrt{3}) $$
where $\mathbf{c} = (0, 0, -20)$ is the sphere center, $r = 4.0$ is the radius, and $s$ is the grid size (voxel edge length) [S1, unofficial].

**Linear Interpolation:**
The intersection point $\mathbf{v}$ on an edge between vertices $\mathbf{p}_1$ and $\mathbf{p}_2$ is calculated as [S1, unofficial]:
$$ \mathbf{v} = (1 - \alpha)\mathbf{p}_1 + \alpha\mathbf{p}_2 $$
where $\alpha = \frac{|f(\mathbf{p}_1)|}{|f(\mathbf{p}_1)| + |f(\mathbf{p}_2)|}$ [S1, unofficial].

**Gaussian Deformation:**
The undeformed vertex position $\mathbf{p}$ is displaced to $\mathbf{p}'$ by [S1, unofficial]:
$$ \mathbf{p}' = \mathbf{p} + \mathbf{F} \cdot 5 \cdot \mathcal{N}(\sigma, d_{\perp}^2) $$
where $\mathcal{N}(\sigma, x) = \frac{e^{-x / (2\sigma^2)}}{\sigma\sqrt{2\pi}}$ is the Gaussian distribution, and $d_{\perp}^2$ is the squared perpendicular distance from $\mathbf{p}$ to the force vector line passing through $\mathbf{c}$ [S1, unofficial]:
$$ d_{\perp}^2 = \|\mathbf{p} - \mathbf{c}\|^2 - \frac{((\mathbf{p} - \mathbf{c}) \cdot \mathbf{F})^2}{\|\mathbf{F}\|^2} $$
Note: The source notes contain a typo in the dot product term ($\mathbf{F}^2$ instead of $(\mathbf{p}-\mathbf{c})\cdot\mathbf{F}$), but the geometric definition of perpendicular distance requires the projection of the displacement vector onto the force vector [S1, unofficial].

### Parameters
*   `gridSize` ($s$): Voxel edge length. Typical value: 0.25 [S1, unofficial].
*   `sigma` ($\sigma$): Gaussian width controlling deformation falloff. Typical value: 0.8 [S1, unofficial].
*   `i_force` ($\mathbf{F}$): Uniform `vec3` defining the direction and magnitude of the deformation brush [S1, unofficial].
*   `lightPos`: Light position in world space for fragment shading [S2, unofficial].

### Steps
1.  **Vertex Shader:** Transform the input point position from object space to world space using `unity_ObjectToWorld` [S2, unofficial].
2.  **Geometry Shader Entry:** For each input point (voxel grid position), compute the cube index by evaluating $f(\mathbf{p})$ at the 8 corners of the cube defined by the grid size [S1, unofficial]. If $f(\mathbf{p}_{corner}) < 0.0$, set the corresponding bit in the cube index [S1, unofficial].
3.  **Edge Intersection:** Look up the edge table using the cube index [S1, unofficial]. If the result is 0, discard the primitive [S1, unofficial]. Otherwise, iterate over the 12 edges [S1, unofficial]. If the $i$-th bit is set, compute the interpolated vertex position $\mathbf{v}$ using linear interpolation [S1, unofficial].
4.  **Deformation:** For each interpolated vertex $\mathbf{v}$, apply the Gaussian deformation formula to obtain $\mathbf{v}'$ [S1, unofficial].
5.  **Triangle Generation:** Look up the triangle table using the cube index [S1, unofficial]. Iterate through the table in steps of 3 [S1, unofficial]. For each valid triangle vertex index, retrieve the undeformed position, apply the deformation function, set the output position, emit the vertex, and end the primitive after three vertices [S1, unofficial].
6.  **Primitive Emission:** After emitting three vertices, end the primitive [S1, unofficial].
7.  **Fragment Shader:** Compute lighting using a normalized light vector $\mathbf{L}$ derived from `lightPos` and the input position [S2, unofficial]. Calculate diffuse lighting as $\max(\mathbf{N} \cdot \mathbf{L}, 0)$ [S2, unofficial]. Sample a sprite texture and multiply by the diffuse light [S2, unofficial].

### Pseudocode
```python
import math

def scalar_field(p, center, radius, grid_size):
    return math.sqrt(sum((p[i] - center[i])**2 for i in range(3))) - (radius + grid_size * math.sqrt(3))

def get_cube_corner(center, i, grid_size):
    x = ((i & 1) * grid_size) - grid_size / 2.0
    y = (((i >> 1) & 1) * grid_size) - grid_size / 2.0
    z = (((i >> 2) & 1) * grid_size) - grid_size / 2.0
    return (center[0] + x, center[1] + y, center[2] + z)

def gaussian_deform(p, center, force, sigma):
    if math.sqrt(sum(f**2 for f in force)) == 0:
        return p
    diff = (p[0]-center[0], p[1]-center[1], p[2]-center[2])
    diff_norm_sq = sum(d**2 for d in diff)
    dot_prod = sum(d*f for d, f in zip(diff, force))
    force_norm_sq = sum(f**2 for f in force)
    d_perp_sq = diff_norm_sq - (dot_prod**2) / force_norm_sq
    gaussian_val = math.exp(-d_perp_sq / (2 * sigma**2)) / (sigma * math.sqrt(2 * math.pi))
    return (p[0] + force[0] * 5 * gaussian_val,
            p[1] + force[1] * 5 * gaussian_val,
            p[2] + force[2] * 5 * gaussian_val)

def geometry_shader_process(point_pos, grid_size, center, radius, force, sigma, edge_vertex_map, tri_table):
    cube_index = 0
    for i in range(8):
        corner = get_cube_corner(point_pos, i, grid_size)
        if scalar_field(corner, center, radius, grid_size) < 0.0:
            cube_index |= (1 << i)

    # In actual GPU code: edge_config = texelFetch(edgeTableTex, ivec2(cubeIndex, 0), 0).r

def run_marching_cubes_deformation(point_pos, grid_size, center, radius, force, sigma, edge_table_tex, tri_table_tex):
    cube_index = 0
    for i in range(8):
        corner = get_cube_corner(point_pos, i, grid_size)
        if scalar_field(corner, center, radius, grid_size) < 0.0:
            cube_index |= (1 << i)
    
    edge_config = edge_table_tex[cube_index]
    if edge_config == 0:
        return []
    
    intersections = [None] * 12
    for edge in range(12):
        if (edge_config >> edge) & 1:
            v1_idx = edge * 2
            v2_idx = edge * 2 + 1
            p1 = get_cube_corner(point_pos, v1_idx, grid_size)
            p2 = get_cube_corner(point_pos, v2_idx, grid_size)
            f1 = scalar_field(p1, center, radius, grid_size)
            f2 = scalar_field(p2, center, radius, grid_size)
            denom = abs(f1) + abs(f2)
            if denom == 0:
                continue
            alpha = abs(f1) / denom
            v = (p1[0]*(1-alpha) + p2[0]*alpha,
                 p1[1]*(1-alpha) + p2[1]*alpha,
                 p1[2]*(1-alpha) + p2[2]*alpha)
            intersections[edge] = v
    
    tri_config = tri_table_tex[cube_index]
    triangles = []
    idx = 0
    while idx < 3:
        e1 = tri_config[idx]
        if e1 == -1:
            break
        e2 = tri_config[idx+1]
        e3 = tri_config[idx+2]
        v1 = gaussian_deform(intersections[e1], center, force, sigma)
        v2 = gaussian_deform(intersections[e2], center, force, sigma)
        v3 = gaussian_deform(intersections[e3], center, force, sigma)
        triangles.append((v1, v2, v3))
        idx += 3
    return triangles
```

### Edge Cases and Pitfalls
*   **Zero Force Vector:** If $\mathbf{F}$ is zero, the division by $\|\mathbf{F}\|$ in the deformation formula causes a NaN [S1, unofficial].
*   **Degenerate Interpolation:** If both scalar field values at an edge's endpoints are exactly 0.0, the interpolation denominator becomes 0.0, causing a division by zero [S1, unofficial].
*   **Matrix Multiplication Order:** In Unity-based implementations, the geometry shader may incorrectly use `mul(UNITY_MATRIX_MVP, unity_WorldToObject)` [S2, unofficial].
*   **Backward Pushing:** If the dot product of the displacement vector and force is non-positive, the deformation is skipped to prevent backward pushing [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel processed by the geometry shader, as it performs a fixed number of texture fetches and arithmetic operations regardless of grid resolution [S1, unofficial].
*   **Memory Complexity:** Depends on the storage of the lookup tables in textures (constant size) and the input point cloud ($O(N)$) [S1, unofficial].
*   **Strengths:** Real-time deformation of isosurfaces without pre-computation; efficient GPU-based implementation using geometry shaders [S1, unofficial].
*   **Limitations:** Limited to specific scalar field definitions (e.g., sphere function in the source); potential for numerical instability with zero force or degenerate edges; matrix transformation errors in certain engine contexts [S1, S2, unofficial].
*   **When to Use:** Real-time deformable terrain or mesh interaction where a Gaussian brush effect is desired [S1, unofficial].
*   **When Not to Use:** When high-precision scalar field evaluation is required for complex geometries, or when the force vector might be zero without proper guarding [S1, unofficial].

## Background
*   **Origin:** This method was implemented in the NtslMaterial geometry shader for real-time deformable terrain/mesh interaction in a custom OpenGL 3.3+ application [S1, unofficial].
*   **History:** The implementation is part of the `ntsl-graphics` project, which explores shader-based graphics techniques [S1, unofficial]. A related Unity-based implementation exists in `UnityGPUMarchingCubes`, though it focuses more on sprite rendering and may contain matrix transformation errors [S2, unofficial].
*   **Usage:** Used in custom OpenGL applications for interactive 3D modeling and terrain deformation [S1, unofficial].
