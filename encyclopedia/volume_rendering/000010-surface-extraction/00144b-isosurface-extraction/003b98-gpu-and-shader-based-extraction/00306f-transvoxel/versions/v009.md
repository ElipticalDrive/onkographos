# Transvoxel

Also called: LOD-aware Marching Cubes, Transvoxel Geometry Shader Implementation, Transvoxel Marching Cubes

## Overview
Transvoxel is a level-of-detail (LOD) aware surface extraction method that extends Marching Cubes to handle voxel grids where neighboring cells have different resolutions [S1]. It solves the problem of non-watertight meshes and visual artifacts at LOD boundaries by introducing a specific set of polygon configurations for "transition cells" that connect meshes of differing grid densities [S1]. Unlike standard Marching Cubes, which assumes a uniform grid, Transvoxel dynamically adjusts vertex positions and normals in the geometry shader to maintain surface continuity when adjacent voxels have different LODs [S2, unofficial].

## How it works
**Inputs:**
- A 3D voxel grid with associated scalar values.
- A voxel size and a base position.
- A LOD function `lod_function(vec3)` that returns the LOD level for a given voxel coordinate.
- An isovalue threshold for surface extraction.
- Pre-computed transition cell lookup tables (`transitionCellClass`, `transitionCellData`, `transitionCellVertexData`) [S2, unofficial].

**Outputs:**
- A stream of vertices (position, normal) forming a watertight triangle mesh.

**Data Structures:**
- `transvoxel_adjust`: An array of size 13 (indices 0-12) storing adjustment offsets for sampling positions. Indices 0-8 correspond to standard MC corners, 9-12 are additional transition points.
- `corner_sample`: An array of size 13 storing sampled scalar values.
- `transvoxel_cell_multiplier`: A scaling factor for LOD transitions [S2, unofficial].

**Numbered Steps:**

1.  **Voxel Positioning:** Calculate the base voxel position by rounding down the current position to the nearest multiple of $2 \times \text{voxel\_size}$:
    $$ x_{base} = (x - (x \% 2)) \times \text{voxel\_size} $$
    Determine the LOD of the current voxel using `lod_function(vec3(x_base, y_base, z_base))` and store in `voxel_size_lod` [S2, unofficial].

2.  **Transition Detection:**
    - If `voxel_size_lod == 2` and any coordinate is odd (`x % 2 == 1 || y % 2 == 1 || z % 2 == 1`), set `draw_voxel = false` and calculate `pos` offset based on parity bits [S2, unofficial].
    - If `voxel_size_lod == 2`, query the LOD of six neighbors (left, right, down, top, front, back) at distance $2 \times \text{voxel\_size}$ [S2, unofficial].
    - If a neighbor (e.g., `lod_left == 1`) has lower resolution, add `transvoxel_size` to specific indices of `transvoxel_adjust` array and set `transvoxel = true` [S2, unofficial].

3.  **Sampling:**
    - Sample the volume at 13 positions: 8 corners, 4 face centers (indices 1, 3, 5, 7), 1 center (index 4), and 4 additional positions defined by `transvoxel_adjust` (indices 9-12) [S2, unofficial].
    - Compute `left_index` by iterating `i` from 0 to 8, sampling `corner_sample[i]`, and setting bit `k` if `corner_sample[i] < iso_value` [S2, unofficial].
    - Copy corner samples to indices 9-12:
      ```python
      corner_sample[9] = corner_sample[0]
      corner_sample[10] = corner_sample[2]
      corner_sample[11] = corner_sample[4]
      corner_sample[12] = corner_sample[6]
      ```
    - Sample the volume at positions 9-12 [S2, unofficial].

4.  **Lookup:**
    - If `left_index != 0 && left_index != 511`, fetch `trans_cell_class` from `transitionCellClass` texture using `left_index` [S2, unofficial].
    - Fetch `geometry_count` from `transitionCellData` using `trans_cell_class & 0x7F`, then derive `trans_vertex_count = geometry_count >> 4` and `trans_triangle_count = geometry_count & 0x0F` [S2, unofficial].
    - Fetch 12 vertex data entries from `transitionCellVertexData` using `left_index` [S2, unofficial].

5.  **Vertex Generation:**
    - For each vertex `i` from 0 to `trans_vertex_count - 1`:
        - Fetch vertex index, break if 0.
        - Extract `corner_1` and `corner_2`.
        - Interpolate vertex position if signs differ or use endpoint if values are close [S2, unofficial].
    - For each triangle:
        - Fetch 3 vertex indices from `transitionCellData`.
        - Retrieve positions.
        - Compute normal via cross product.
        - Emit vertices [S2, unofficial].

6.  **Standard MC Adjustment (if `transvoxel` is true):**
    - Compute adjusted vertex positions `a_adj` and `b_adj` using `transvoxel_adjust` and `transvoxel_cell_multiplier` [S2, unofficial].
    - Compute normals for adjusted vertices by interpolating gradients: `normal_a` and `normal_b` are computed via `compute_gradient`, then interpolated based on `iso_value` [S2, unofficial].
    - If `project_transvoxel == 1`, project adjusted vertices onto the triangle plane defined by the interpolated normal [S2, unofficial].

**Pseudocode:**

```python
def transvoxel_extract(x, y, z, voxel_size, iso_value, lod_function, 
                       transitionCellClass, transitionCellData, transitionCellVertexData):
    # 1. Base Positioning
    x_base = (x - (x % 2)) * voxel_size
    y_base = (y - (y % 2)) * voxel_size
    z_base = (z - (z % 2)) * voxel_size
    
    lod = lod_function(vec3(x_base, y_base, z_base))
    transvoxel = False
    transvoxel_adjust = [0.0] * 13
    
    # 2. Transition Detection
    if lod == 2 and (x % 2 == 1 or y % 2 == 1 or z % 2 == 1):
        # Skip drawing, handle offset
        return []
        
    if lod == 2:
        # Query neighbors at distance 2 * voxel_size
        lod_left = lod_function(vec3(x_base - 2*voxel_size, y_base, z_base))
        lod_right = lod_function(vec3(x_base + 2*voxel_size, y_base, z_base))
        lod_down = lod_function(vec3(x_base, y_base - 2*voxel_size, z_base))
        lod_top = lod_function(vec3(x_base, y_base + 2*voxel_size, z_base))
        lod_front = lod_function(vec3(x_base, y_base, z_base - 2*voxel_size))
        lod_back = lod_function(vec3(x_base, y_base, z_base + 2*voxel_size))
        
        # Adjust if neighbor has lower resolution
        if lod_left < lod:
            transvoxel_adjust[0] += transvoxel_size # Example adjustment
            transvoxel = True
        # ... similar checks for other neighbors ...

    # 3. Sampling
    corner_sample = [0.0] * 13
    
    # Sample 8 corners (indices 0-7)
    for i in range(8):
        pos = get_corner_position(i, x_base, y_base, z_base, voxel_size)
        corner_sample[i] = sample_volume(pos)
        
    # Sample face centers (indices 1,3,5,7) - Note: indices may vary by implementation
    # Assuming specific mapping from notes: indices 1,3,5,7 are face centers
    # This part requires precise coordinate mapping not fully detailed in notes
    # [G] Standard MC face centers are midpoints of edges. 
    # The notes specify indices 1,3,5,7 as face centers. 
    # We assume these are pre-defined positions relative to the cell.
    corner_sample[1] = sample_volume(get_face_center(1, x_base, y_base, z_base, voxel_size))
    corner_sample[3] = sample_volume(get_face_center(3, x_base, y_base, z_base, voxel_size))
    corner_sample[5] = sample_volume(get_face_center(5, x_base, y_base, z_base, voxel_size))
    corner_sample[7] = sample_volume(get_face_center(7, x_base, y_base, z_base, voxel_size))
    
    # Sample center (index 4)
    corner_sample[4] = sample_volume(vec3(x_base + voxel_size, y_base + voxel_size, z_base + voxel_size))
    
    # Copy corners to 9-12
    corner_sample[9] = corner_sample[0]
    corner_sample[10] = corner_sample[2]
    corner_sample[11] = corner_sample[4]
    corner_sample[12] = corner_sample[6]
    
    # Sample additional positions 9-12
    for i in range(9, 13):
        pos = get_additional_position(i, x_base, y_base, z_base, voxel_size, transvoxel_adjust)
        corner_sample[i] = sample_volume(pos)
        
    # Compute left_index
    left_index = 0
    for i in range(9): # 0 to 8
        if corner_sample[i] < iso_value:
            left_index |= (1 << i)
            
    if left_index == 0 or left_index == 511:
        return []
        
    # 4. Lookup
    trans_cell_class = transitionCellClass[left_index]
    geometry_count = transitionCellData[trans_cell_class & 0x7F]
    trans_vertex_count = geometry_count >> 4
    trans_triangle_count = geometry_count & 0x0F
    
    vertex_data = transitionCellVertexData[left_index] # 12 entries
    
    vertices = []
    
    # 5. Vertex Generation
    for i in range(trans_vertex_count):
        v_idx = vertex_data[i]
        if v_idx == 0:
            break
        corner_1, corner_2 = extract_corners(v_idx)
        # Interpolate position
        pos = interpolate_position(corner_1, corner_2, corner_sample)
        normal = compute_normal(pos, corner_sample)
        vertices.append((pos, normal))
        
    # 6. Triangle Emission
    triangles = []
    for t in range(trans_triangle_count):
        v0_idx, v1_idx, v2_idx = get_triangle_indices(t, transitionCellData)
        p0, n0 = vertices[v0_idx]
        p1, n1 = vertices[v1_idx]
        p2, n2 = vertices[v2_idx]
        
        # Compute normal via cross product
        e1 = p1 - p0
        e2 = p2 - p0
        normal = cross(e1, e2)
        normal = normalize(normal)
        
        triangles.append((p0, n0, p1, n1, p2, normal))
        
    # 7. Standard MC Adjustment if transvoxel
    if transvoxel:
        adjusted_triangles = []
        for tri in triangles:
            p0, n0, p1, n1, p2, n2 = tri
            # Compute adjusted positions
            a_adj = adjust_vertex(p0, transvoxel_adjust, transvoxel_cell_multiplier)
            b_adj = adjust_vertex(p1, transvoxel_adjust, transvoxel_cell_multiplier)
            # ... adjust p2 ...
            
            # Compute normals
            normal_a = compute_gradient(a_adj, corner_sample)
            normal_b = compute_gradient(b_adj, corner_sample)
            
            # Interpolate normals
            normal_a = interpolate_normal(normal_a, normal_b, iso_value)
            
            # Project if needed
            if project_transvoxel:
                a_adj = project_to_plane(a_adj, normal_a)
                b_adj = project_to_plane(b_adj, normal_a)
                
            adjusted_triangles.append((a_adj, normal_a, b_adj, normal_a, p2, n2))
        return adjusted_triangles
        
    return triangles
```

**Parameters:**
- `iso_value`: The threshold for surface extraction. Typical values depend on the data range [S2, unofficial].
- `voxel_size`: The physical size of a voxel.
- `project_transvoxel`: Boolean flag (1 or 0) to enable projection of adjusted vertices onto the triangle plane [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision errors in interpolation and gradient calculation can cause small gaps or overlaps at LOD boundaries [S2, unofficial].
- **Boundaries:** The method assumes a valid voxel grid. Out-of-bounds queries for neighbors must be handled (e.g., by clamping or returning a default LOD) [S2, unofficial].
- **Degenerate Input:** If `left_index` is 0 or 511, no surface exists in the cell, and the function returns empty [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of voxels processed, but with a higher constant factor due to neighbor lookups and transition cell handling [S2, unofficial].
- **Memory Complexity:** Requires storage for the voxel grid and transition cell lookup tables. The lookup tables are pre-computed and static [S2, unofficial].
- **Measured Performance:** Performance depends on the GPU's ability to handle the geometry shader and texture lookups. The method is efficient for large terrains with varying LODs [S2, unofficial].
- **Scaling:** Scales well with LOD, as higher LODs process fewer voxels. The transition handling adds overhead only at LOD boundaries [S2, unofficial].
- **Strengths:** Produces watertight meshes across LOD boundaries; integrates well with GPU geometry shaders; suitable for terrain rendering [S1][S2, unofficial].
- **Limitations:** Requires pre-computed transition cell data; complex implementation compared to standard Marching Cubes; potential for visual artifacts if projection is not enabled [S2, unofficial].
- **When to use:** When rendering large voxel-based terrains or volumes with varying levels of detail [S1][S2, unofficial].
- **When not to use:** For uniform grids where standard Marching Cubes suffices; for scenes requiring dynamic LOD changes without pre-computed transition data [S2, unofficial].

## Background
The Transvoxel algorithm was introduced as a solution to the LOD problem in voxel-based rendering, specifically to connect meshes of different LODs without gaps [S1]. It extends the Marching Cubes technique by introducing a new set of polygon configurations for transition cells [S1]. The method has been implemented in various contexts, including WebGL for volumetric terrain rendering [S1] and as a geometry shader implementation for OpenGL [S2, unofficial].
