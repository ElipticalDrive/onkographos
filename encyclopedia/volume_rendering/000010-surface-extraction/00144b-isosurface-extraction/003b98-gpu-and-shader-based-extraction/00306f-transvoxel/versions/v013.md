# Transvoxel

Also called: LOD-aware Marching Cubes, Transvoxel Geometry Shader Implementation, Transvoxel Marching Cubes

## Overview
Transvoxel is an extension to the Marching Cubes technique that introduces a specific set of polygon configurations for "transition cells" to connect meshes generated at different levels of detail (LODs) within a voxel grid [S1]. It solves the problem of non-watertight surfaces and visible artifacts that occur when neighboring voxels have different resolutions, ensuring a continuous, manifold surface [S2, unofficial]. Unlike standard Marching Cubes which assumes a uniform grid, Transvoxel dynamically adapts vertex positions and normals at LOD boundaries to maintain geometric continuity [S2, unofficial].

## How it works
**Inputs:**
- A 3D voxel grid (implicit function or scalar field) [S2, unofficial].
- A level-of-detail function `lod_function(x, y, z)` that returns the LOD index for a given voxel coordinate [S2, unofficial].
- An isovalue threshold for surface extraction [S2, unofficial].
- A maximum LOD depth (typically 2 or 3, where LOD 0 is finest, LOD 2 is coarsest) [S2, unofficial].
- A base `voxel_size` defining the physical scale of the grid cells.

**Outputs:**
- A stream of triangles (positions, normals) representing the isosurface [S2, unofficial].

**Data Structures:**
- `transitionCellClass`: A lookup texture or array mapping a 9-bit index (derived from corner samples) to a transition cell configuration ID [S2, unofficial].
- `transitionCellData`: An array storing geometry counts for each transition cell class. Format: `geometry_count = (trans_vertex_count << 4) | trans_triangle_count` [S2, unofficial].
- `transitionCellVertexData`: An array storing vertex definitions for transition cells. Each entry contains indices referencing corner or face vertices [S2, unofficial].
- `transvoxel_adjust`: An array used to offset sampling positions for transition cells [S2, unofficial].

**Algorithm Steps:**

1.  **Voxel Positioning and LOD Determination:**
    For each voxel in the grid, calculate the base position aligned to the current LOD's resolution [S2, unofficial].
    $$ x_{base} = (x - (x \pmod 2)) \times \text{voxel\_size} $$
    $$ y_{base} = (y - (y \pmod 2)) \times \text{voxel\_size} $$
    $$ z_{base} = (z - (z \pmod 2)) \times \text{voxel\_size} $$
    Determine the LOD of the current voxel:
    $$ \text{voxel\_size\_lod} = \text{lod\_function}(x_{base}, y_{base}, z_{base}) $$

2.  **Transition Cell Identification:**
    If `voxel_size_lod` is the maximum LOD (e.g., 2) and any coordinate of the voxel index is odd, the voxel is a transition cell [S2, unofficial].
    - Set `draw_voxel = false` for standard processing [S2, unofficial].
    - Calculate `pos` offset based on parity bits of the coordinates [S2, unofficial].
    - Query the LOD of the six immediate neighbors (left, right, down, top, front, back) at distance `2 * voxel_size` [S2, unofficial].
    - If a neighbor has a lower resolution (higher LOD index), add `transvoxel_size` to specific indices of the `transvoxel_adjust` array and set `transvoxel = true` [S2, unofficial].

3.  **Volume Sampling:**
    Sample the volume at 13 positions:
    - 8 corners of the voxel.
    - 4 face centers (indices 1, 3, 5, 7 in the standard MC edge list context, corresponding to specific faces) [S2, unofficial].
    - 1 center point (index 4).
    - 4 additional positions defined by `transvoxel_adjust` (indices 9-12), used to capture geometry in the transition region [S2, unofficial].

4.  **Corner Index Calculation:**
    Compute `left_index` by iterating `i` from 0 to 8, sampling `corner_sample[i]`, and setting bit `k` if `corner_sample[i] < iso_value` [S2, unofficial].
    
    Copy corner samples to indices 9-12 for transition sampling:
    ```python
    corner_sample[9] = corner_sample[0]
    corner_sample[10] = corner_sample[2]
    corner_sample[11] = corner_sample[4]
    corner_sample[12] = corner_sample[6]
    ```
    Sample the volume at positions 9-12 using the adjusted offsets [S2, unofficial].

5.  **Transition Cell Configuration Lookup:**
    If `left_index != 0` and `left_index != 511` (empty or full):
    - Fetch `trans_cell_class` from `transitionCellClass` texture using `left_index` [S2, unofficial].
    - Fetch `geometry_count` from `transitionCellData` using `trans_cell_class & 0x7F` [S2, unofficial].
    - Derive vertex and triangle counts:
      $$ \text{trans\_vertex\_count} = \text{geometry\_count} \gg 4 $$
      $$ \text{trans\_triangle\_count} = \text{geometry\_count} \& 0x0F $$
    - Fetch 12 vertex data entries from `transitionCellVertexData` using `left_index` [S2, unofficial].

6.  **Vertex Generation for Transition Cells:**
    For each vertex `i` from 0 to `trans_vertex_count - 1`:
    - Fetch vertex index. Break if 0.
    - Extract `corner_1` and `corner_2`.
    - If signs of the samples at `corner_1` and `corner_2` differ, interpolate the vertex position along the edge.
    - If values are close to the isovalue, use the endpoint.

7.  **Standard Marching Cubes Processing (Non-Transition):**
    If `transvoxel` is false:
    - Perform standard Marching Cubes lookup and vertex interpolation.
    - If `transvoxel` is true (but not a transition cell configuration), compute adjusted vertex positions `a_adj` and `b_adj` using `transvoxel_adjust` and `transvoxel_cell_multiplier`.

8.  **Normal Computation and Projection:**
    - Compute normals for adjusted vertices by interpolating gradients: `normal_a` and `normal_b` are computed via `compute_gradient`, then interpolated based on `iso_value`.
    - If `project_transvoxel == 1`, project adjusted vertices onto the triangle plane defined by the interpolated normal to ensure coplanarity and reduce gaps.

9.  **Emission:**
    For each triangle in the transition cell configuration:
    - Fetch 3 vertex indices from `transitionCellData`.
    - Retrieve positions and normals.
    - Compute normal via cross product if not pre-computed.
    - Emit vertices.

**Pseudocode:**

```python
def transvoxel_extract(voxel_grid, lod_function, iso_value, voxel_size, max_lod=2):
    triangles = []
    
    # Helper definitions for self-contained execution
    def get_corner_pos(i, xb, yb, zb, vs):
        return (xb + (i & 1) * vs, yb + ((i >> 1) & 1) * vs, zb + ((i >> 2) & 1) * vs)
    
    def get_face_pos(i, xb, yb, zb, vs):
        offsets = {1: (0.5, 0, 0), 3: (0, 0.5, 0), 5: (0, 0, 0.5), 7: (0.5, 0.5, 0)}
        return (xb + offsets[i][0]*vs, yb + offsets[i][1]*vs, zb + offsets[i][2]*vs)
    
    def get_center_pos(xb, yb, zb, vs):
        return (xb + 0.5*vs, yb + 0.5*vs, zb + 0.5*vs)
    
    def get_adjusted_pos(i, xb, yb, zb, adj):
        # Applies transvoxel_adjust offsets to base position [G]
        return (xb + adj[0], yb + adj[1], zb + adj[2])
    
    def sample_volume(pos):
        # Trilinear interpolation or direct grid lookup [G]
        return 0.0
    
    def lookup_transition_class(idx):
        # Texture/array lookup for transition cell class ID [G]
        return 0
    
    def lookup_transition_data(cls):
        # Texture/array lookup for geometry count [G]
        return 0
    
    def lookup_transition_vertex_data(idx, i):
        # Fetches vertex index data [G]
        return (0, 0)
    
    def extract_corners(v_idx):
        return (0, 1)
    
    def interpolate_edge(c1, c2, s1, s2, iso):
        t = (iso - s1) / (s2 - s1) if abs(s2 - s1) > 1e-6 else 0.5
        p1 = get_corner_pos(c1, 0, 0, 0, 1)
        p2 = get_corner_pos(c2, 0, 0, 0, 1)
        return (p1[0] + t*(p2[0]-p1[0]), p1[1] + t*(p2[1]-p1[1]), p1[2] + t*(p2[2]-p1[2]))
    
    def compute_gradient(pos, grid):
        # Central difference gradient approximation [G]
        return (0, 0, 1)
    
    def lookup_transition_triangles(cls, t):
        # Fetches triangle vertex indices [G]
        return (0, 1, 2)

    # Iterate over all voxels
    for x, y, z in voxel_grid.coordinates:
        # 1. Base position and LOD
        x_base = (x - (x % 2)) * voxel_size
        y_base = (y - (y % 2)) * voxel_size
        z_base = (z - (z % 2)) * voxel_size
        
        lod = lod_function(x_base, y_base, z_base)
        
        # 2. Transition Cell Check
        is_transition = False
        transvoxel_adjust = [0.0] * 12
        
        if lod == max_lod:
            if x % 2 == 1 or y % 2 == 1 or z % 2 == 1:
                is_transition = True
                # Check six neighbors at distance 2 * voxel_size
                neighbor_offsets = [(2,0,0), (-2,0,0), (0,2,0), (0,-2,0), (0,0,2), (0,0,-2)]
                for dx, dy, dz in neighbor_offsets:
                    nx, ny, nz = x_base + dx * voxel_size, y_base + dy * voxel_size, z_base + dz * voxel_size
                    n_lod = lod_function(nx, ny, nz)
                    if n_lod > lod: # Neighbor is coarser
                        # Add adjustment based on direction
                        transvoxel_adjust[0] = voxel_size * 0.5
                        
        # 3. Sampling
        samples = [0.0] * 13
        # Sample 8 corners
        for i in range(8):
            samples[i] = sample_volume(get_corner_pos(i, x_base, y_base, z_base, voxel_size))
            
        # Sample face centers and center
        samples[1] = sample_volume(get_face_pos(1, x_base, y_base, z_base, voxel_size))
        samples[3] = sample_volume(get_face_pos(3, x_base, y_base, z_base, voxel_size))
        samples[5] = sample_volume(get_face_pos(5, x_base, y_base, z_base, voxel_size))
        samples[7] = sample_volume(get_face_pos(7, x_base, y_base, z_base, voxel_size))
        samples[4] = sample_volume(get_center_pos(x_base, y_base, z_base, voxel_size))
        
        # Copy corners for transition sampling
        samples[9] = samples[0]
        samples[10] = samples[2]
        samples[11] = samples[4]
        samples[12] = samples[6]
        
        # Sample adjusted positions if transition
        if is_transition:
            for i in range(4):
                samples[9+i] = sample_volume(get_adjusted_pos(i, x_base, y_base, z_base, transvoxel_adjust))
                
        # 4. Corner Index
        left_index = 0
        for i in range(8):
            if samples[i] < iso_value:
                left_index |= (1 << i)
                
        # 5. Lookup and Generate
        if left_index != 0 and left_index != 511:
            if is_transition:
                trans_cell_class = lookup_transition_class(left_index)
                geometry_count = lookup_transition_data(trans_cell_class)
                trans_vertex_count = geometry_count >> 4
                trans_triangle_count = geometry_count & 0x0F
                
                vertices = []
                for i in range(trans_vertex_count):
                    v_idx = lookup_transition_vertex_data(left_index, i)
                    c1, c2 = extract_corners(v_idx)
                    # Fixed boolean logic: checks if signs differ across the isovalue
                    if (samples[c1] < iso_value) != (samples[c2] < iso_value):
                        pos = interpolate_edge(c1, c2, samples[c1], samples[c2], iso_value)
                        normal = compute_gradient(pos, voxel_grid)
                        vertices.append((pos, normal))
                    else:
                        vertices.append((get_corner_pos(c1, x_base, y_base, z_base, voxel_size), compute_gradient(get_corner_pos(c1, x_base, y_base, z_base, voxel_size), voxel_grid)))
                        
                for t in range(trans_triangle_count):
                    v0, v1, v2 = lookup_transition_triangles(trans_cell_class, t)
                    triangles.append((vertices[v0], vertices[v1], vertices[v2]))
            else:
                # Standard Marching Cubes lookup and vertex interpolation [G]
                pass
                
    return triangles
```

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point errors in interpolation can cause gaps at LOD boundaries. Projecting vertices onto the triangle plane (`project_transvoxel == 1`) mitigates this [S2, unofficial].
- **Degenerate Input:** If `left_index` is 0 or 511, no geometry is generated for that cell. Ensure the LOD function does not create isolated voxels with no neighbors.

### [Transvoxel Smooth Terrain Texturing](7280-transvoxel-smooth-terrain-texturing.md)
This method applies procedural and texture-based shading to the geometry generated by the Transvoxel algorithm, ensuring that material appearance (grass, stone, forest) blends smoothly across level-of-detail (LOD) boundaries and terrain slopes. It distinguishes itself from standard voxel texturing by combining triplanar mapping with a slope-aware material blending system that adapts to the local surface orientation, preventing texture stretching and maintaining visual continuity despite the irregular vertex distribution of the Transvoxel mesh.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels. The constant factor is higher than standard Marching Cubes due to neighbor lookups and transition cell processing.
- **Memory Complexity:** $O(N)$ for the voxel grid, plus $O(1)$ for the transition cell lookup tables (which are small and fixed size).
- **Measured Performance:** Performance depends heavily on the sparsity of LOD transitions. In uniform regions, it behaves like standard MC. In complex terrain with frequent LOD changes, the overhead of transition cell generation increases.
- **Strengths:** Generates watertight meshes across LOD boundaries; suitable for real-time rendering of large terrains; GPU-friendly implementation using geometry shaders.
- **Limitations:** Requires pre-computed or efficiently computable LOD function; transition cells add complexity to the shader; may produce slightly distorted geometry at LOD boundaries if projection is not used.
- **When to use:** Large-scale terrain rendering where LOD is essential for performance and visual continuity is critical.
- **When not to use:** Static, low-resolution scenes where LOD is not needed; scenes with sharp features that require higher-order interpolation than linear MC provides.

## Background
The Transvoxel algorithm was introduced as a solution to the LOD problem in volumetric terrain rendering [S1]. It extends the Marching Cubes technique by adding specific polygon configurations for transition cells [S1]. The method has been implemented in various contexts, including WebGL-based terrain rendering [S1] and GPU geometry shader implementations [S2, unofficial]. It is particularly relevant in the field of real-time terrain visualization where dynamic LOD is required.
