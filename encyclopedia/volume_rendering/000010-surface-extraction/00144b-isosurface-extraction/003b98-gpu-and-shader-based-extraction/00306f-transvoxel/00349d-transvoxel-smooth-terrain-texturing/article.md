# Transvoxel Smooth Terrain Texturing

Also called: Surface Color Blending

## Overview
This method applies procedural and texture-based shading to the geometry generated by the Transvoxel algorithm, ensuring that material appearance (grass, stone, forest) blends smoothly across level-of-detail (LOD) boundaries and terrain slopes. It distinguishes itself from standard voxel texturing by combining triplanar mapping with a slope-aware material blending system that adapts to the local surface orientation, preventing texture stretching and maintaining visual continuity despite the irregular vertex distribution of the Transvoxel mesh.

## How it works
The method operates in the vertex and fragment shaders of the Transvoxel renderer. It computes material weights based on block type, slope, and procedural noise, then blends between base colors or texture samples.

### Inputs and Outputs
**Inputs:**
- `VERTEX`: The base vertex position in local space.
- `CUSTOM0`: Custom attribute data required by the Transvoxel position calculation (e.g., LOD level, block coordinates).
- `NORMAL`: The interpolated vertex normal.
- `MODEL_MATRIX`, `VIEW_MATRIX`, `INV_VIEW_MATRIX`: Transformation matrices.
- `u_texture_top`, `u_texture_sides`: Sampler2D for top and side textures (in the basic terrain variant).
- `u_albedo_array`: Sampler2DArray for multi-material texturing (in the advanced variant).
- `gen`: A global generation context providing block definitions and seeds.

**Outputs:**
- `ALBEDO`: The final surface color (RGB).
- `VERTEX`: The transformed vertex position.
- `NORMAL`: The transformed normal.

### Data Structures
No complex persistent data structures are defined in the shader code itself. The method relies on:
- `v_world_pos`: Varying `vec3` storing the world-space position.
- `v_vertex_pos_model`: Varying `vec3` storing the model-space vertex position.
- `v_material_indices`: Varying `vec4` storing material IDs for each vertex corner (used in texture array variant).
- `v_material_weights`: Varying `vec4` storing the blending weights for each material (used in texture array variant).

### Steps

1. **Position Calculation**: Compute the final vertex position using the Transvoxel helper function.
   ```glsl
   VERTEX = get_transvoxel_position(VERTEX, CUSTOM0);
   ```

2. **World Position**: Transform the vertex to world space for texture sampling.
   ```glsl
   v_world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
   ```

3. **Normal Calculation**: Compute the surface normal in view space using the Transvoxel helper, then transform it to world space for triplanar mapping.
   ```glsl
   NORMAL = get_voxel_normal_view(v_vertex_pos_model, NORMAL, VIEW_MATRIX * MODEL_MATRIX);
   vec3 normal = (INV_VIEW_MATRIX * vec4(NORMAL, 0.0)).xyz;
   ```

4. **Material Blending (Procedural Terrain Variant)**:
   Determine the base block type and apply slope/noise-based blending.
   
   a. **Base Color**: Get the top block color.
   ```glsl
   int topBlockId = gen.topBlock(x, z, Math.floor(h), 0);
   vec3 baseColor = srgb(topBlockId);
   ```
   
   b. **Grass Blending**: If the block is grass, blend dry-grass patches and forest areas.
   ```glsl
   // Dry grass patches
   float pa = smooth(fbm(x*0.07, z*0.07, 999, 2), 0.35, 0.7) * 0.6;
   
   // Forest blending
   float forest = fbm(x*0.05 + 100, z*0.05, gen.seed + 3, 2);
   float fk = smooth(forest, 0.5, 0.62) * 0.75 * (1 - smooth(h, 170, 190)) + 0.08;
   vec3 leafColor = (forest > 0.6) ? LEAF_DARK : LEAF;
   
   // Terraced slopes
   float sk = smooth(slope, 0.5, 2.2) * 0.55;
   
   // Steep ground to stone
   float st = smooth(slope, 2.1, 3.3);
   vec3 stoneColor = mix(stoneTop, stoneSide, st);
   ```
   
   c. **Stone Blending**: If the block is stone, blend side color based on slope.
   ```glsl
   float slopeBlend = smooth(slope, 1, 4) * 0.6;
   ```

5. **Triplanar Mapping Setup**:
   a. **Topness**: Calculate a factor based on the Y component of the normal to blend between top and side textures.
   ```glsl
   float topness_midlevel = 0.5;
   float topness_smoothness = 0.04;
   float topness_min = topness_midlevel - topness_smoothness;
   float topness_max = topness_midlevel + topness_smoothness;
   float topness = smoothstep(topness_min, topness_max, normal.y);
   ```
   
   b. **Blending Factors**: Compute triplanar blending weights.
   ```glsl
   float triplanar_sharpness = 8.0;
   vec3 blending = get_triplanar_blend(normal, triplanar_sharpness);
   ```

6. **Texture Sampling**:
   a. **Basic Variant**: Sample top and side textures.
   ```glsl
   vec3 wpos = v_world_pos * 0.2;
   vec3 top_col = texture_triplanar(u_texture_top, wpos, blending).rgb;
   vec3 side_col = texture_triplanar(u_texture_sides, wpos, blending).rgb;
   ALBEDO = mix(side_col, top_col, topness);
   ```
   
   b. **Texture Array Variant**: Sample multiple materials from a texture array using material indices and weights.
   ```glsl
   vec3 col0 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.x).rgb;
   vec3 col1 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.y).rgb;
   vec3 col2 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.z).rgb;
   vec3 col3 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.w).rgb;
   
   vec4 weights = v_material_weights;
   weights /= (weights.x + weights.y + weights.z + weights.w + 0.00001);
   
   ALBEDO = col0 * weights.r + col1 * weights.g + col2 * weights.b + col3 * weights.a;
   ```

7. **LOD Fade Discard**: Discard fragments in LOD transition zones if necessary.
   ```glsl
   if (get_lod_fade_discard(SCREEN_UV)) { discard; }
   ```

### Formulas
- **Smoothstep**:
  $$t = \min(1, \max(0, \frac{x-a}{b-a}))$$
  $$result = t^2(3-2t)$$
  Where $x$ is the input value, $a$ is the lower bound, and $b$ is the upper bound.

- **Procedural Noise (FBM)**:
  Fractal Brownian Motion is used for grass patches and forest distribution.
  - Grass patch noise: `fbm(x*0.07, z*0.07, 999, 2)`
  - Forest noise: `fbm(x*0.05+100, z*0.05, gen.seed+3, 2)`
  Parameters: Scale factors, seed, and number of octaves (2).

### Parameters
- `topness_midlevel`: 0.5
- `topness_smoothness`: 0.04
- `topness_min`: 0.46
- `topness_max`: 0.54
- `triplanar_sharpness`: 8.0
- Grass patch noise scale: `0.07`
- Forest noise scale: `0.05`
- Grass seed: `999`
- Forest seed offset: `gen.seed + 3`
- Noise octaves: `2`
- Texture world scale: `0.2`

### Edge Cases and Pitfalls
- **Precision**: The `topness` calculation uses a narrow range (`0.46` to `0.54`) to avoid artifacts on flat surfaces. If the normal Y component is exactly 0.5, the result is 0.5.
- **Normalization**: In the texture array variant, material weights are normalized with a small epsilon (`0.00001`) to prevent division by zero.
- **LOD Fade**: The `get_lod_fade_discard` function must be implemented to handle visual popping at LOD boundaries. If not handled, textures may appear to flicker or tear.
- **Slope Calculation**: The `slope` variable must be derived from the normal or height difference. The exact formula for `slope` is not provided in the sources but is assumed to be a scalar value representing the steepness of the terrain.

## Subtopics

## Operating characteristics
- **Time Complexity**: O(1) per vertex/fragment, as it involves a fixed number of texture samples and procedural noise evaluations.
- **Memory Complexity**: O(1) additional memory per vertex, storing world position and normal.
- **Performance**: The procedural variant is lightweight, relying on simple noise functions. The texture array variant requires multiple texture samples (up to 4) and blending, which may be more expensive on older hardware.
- **Strengths**: Provides visually rich, natural-looking terrain without requiring complex UV unwrapping. Handles LOD transitions smoothly by blending materials based on slope and orientation.
- **Limitations**: Procedural noise can be computationally intensive if high-frequency details are required. The method assumes a consistent world-space coordinate system for texture sampling.

## Background
This method is part of the Zylann's Voxel Game project, an open-source voxel engine. It builds on the Transvoxel algorithm for geometry generation [S1, unofficial]. The procedural texturing approach is inspired by standard terrain rendering techniques, adapted for the dynamic, LOD-based mesh structure of Transvoxel. The texture array variant allows for more complex material definitions, such as those found in modern voxel editors [S1, unofficial].
