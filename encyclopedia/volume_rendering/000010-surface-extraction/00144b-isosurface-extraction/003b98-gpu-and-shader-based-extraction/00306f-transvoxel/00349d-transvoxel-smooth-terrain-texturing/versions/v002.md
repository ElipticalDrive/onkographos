# Transvoxel Smooth Terrain Texturing


## Overview
This method applies triplanar texturing to surfaces extracted by the Transvoxel algorithm for terrain rendering, blending "top" and "side" textures (or a material array) using a "topness" factor derived from the surface normal [S1, unofficial]. It builds on [Transvoxel](6277-transvoxel.md) for geometry generation [S1, unofficial].

## How it works
**Inputs:** Vertex position in local space (`VERTEX`), vertex normal in local space (`NORMAL`), model matrix (`MODEL_MATRIX`), view matrix (`VIEW_MATRIX`), texture samplers (`u_texture_top`, `u_texture_sides`, or `u_albedo_array`), and parameters (`triplanar_sharpness = 8.0`, `topness_midlevel = 0.5`, `topness_smoothness = 0.04`) [S1, unofficial].

**Outputs:** Fragment color (`ALBEDO`) [S1, unofficial].

**Data Structures:** Varying variables passed from vertex to fragment shader: `v_world_pos` (world-space position), `v_vertex_pos_model` (model-space position), `v_material_indices` (material array indices), `v_material_weights` (material array weights) [S1, unofficial].

**Steps:**

1. **Position & Normal Computation:** Compute the final vertex position and world-space coordinates. Transform the surface normal to world space for triplanar mapping [S1, unofficial].
```python
VERTEX = get_transvoxel_position(VERTEX, CUSTOM0)
v_vertex_pos_model = VERTEX
v_world_pos = (MODEL_MATRIX @ [VERTEX.x, VERTEX.y, VERTEX.z, 1.0])[:3]

NORMAL = get_voxel_normal_view(v_vertex_pos_model, NORMAL, VIEW_MATRIX @ MODEL_MATRIX)
normal = (INV_VIEW_MATRIX @ [NORMAL.x, NORMAL.y, NORMAL.z, 0.0])[:3]
```

2. **Topness Calculation:** Calculate a blending factor based on the Y-component of the world-space normal using a smoothstep function with a narrow range [S1, unofficial].
```python
topness_min = 0.46
topness_max = 0.54
topness = smoothstep(topness_min, topness_max, normal.y)
```

3. **Triplanar Blending Factors:** Compute blending weights for the X, Y, and Z axes based on the normal and sharpness parameter [S1, unofficial].
```python
blending = get_triplanar_blend(normal, 8.0)
```

4. **Texture Sampling & Color Blending:** Scale the world position for texture sampling. Sample the top and side textures using triplanar mapping, then mix the colors based on the topness factor [S1, unofficial].
```python
wpos = v_world_pos * 0.2
top_col = texture_triplanar(u_texture_top, wpos, blending)
side_col = texture_triplanar(u_texture_sides, wpos, blending)
ALBEDO = mix(side_col, top_col, topness)
```

**Alternative: Material Array Blending:** If using a material array (`u_albedo_array`), sample the array using material indices and weights, then normalize the weights with a safety margin to prevent division-by-zero errors [S1, unofficial].
```python
col0 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.x)
col1 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.y)
col2 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.z)
col3 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.w)

weights = v_material_weights
weights /= (weights.x + weights.y + weights.z + weights.w + 0.00001)

ALBEDO = col0 * weights.r + col1 * weights.g + col2 * weights.b + col3 * weights.a
```

5. **LOD Fade Discard:** Discard fragments that are in the LOD transition zone to avoid visual artifacts [S1, unofficial].
```python
if get_lod_fade_discard(SCREEN_UV):
    return
```

**Edge Cases and Pitfalls:**
- **Precision:** The topness calculation uses `smoothstep` with a narrow range (`0.46` to `0.54`). Ensure normal vectors are normalized before use [G].
- **Boundaries:** The LOD fade discard check prevents rendering in regions where the geometry is being transitioned between LOD levels [S1, unofficial].
- **Degenerate Input:** If the normal is zero or undefined, the topness and blending factors may be incorrect. The Transvoxel helper should handle this, but fallback values should be considered [G].

## Subtopics

### [Smooth Material Texturing with Texture Array](7282-smooth-material-texturing-with-texture-array.md)
This method applies multi-material texturing to surfaces extracted by the Transvoxel algorithm using a texture array and triplanar mapping. It solves the problem of seamlessly blending multiple material types (e.g., grass, dirt, rock) on a dynamically changing isosurface. It differs from standard single-texture approaches by supporting up to four distinct materials per vertex, blended via weights stored in vertex attributes, and uses triplanar projection to avoid UV seams on complex geometry.

## Operating characteristics
- **Time Complexity:** O(1) per vertex and fragment, dominated by texture sampling and matrix multiplications [G].
- **Memory Complexity:** O(1) additional memory per vertex/fragment, plus texture memory for top/side textures or material array [G].
- **Performance:** Efficient on modern GPUs due to parallel texture sampling. The use of triplanar mapping avoids UV unwrapping overhead [G].
- **Strengths:** Seamless texturing across LOD boundaries, orientation-aware material blending, simple implementation [G].
- **Limitations:** Triplanar mapping can cause stretching on highly curved surfaces; topness factor is a simple heuristic and may not capture complex material distributions [G].

## Background
This method is part of the Zylann's VoxelGame project, an open-source voxel engine for Godot. It extends the Transvoxel algorithm to provide high-quality terrain texturing. The approach is documented in the project's source code and shader files [S1, unofficial].
