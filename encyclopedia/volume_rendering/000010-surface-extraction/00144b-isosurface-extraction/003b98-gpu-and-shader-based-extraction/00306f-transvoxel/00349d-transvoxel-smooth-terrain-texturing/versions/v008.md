# Transvoxel Smooth Terrain Texturing

Also called: Surface Color Blending

## Overview
This method applies procedural and texture-based shading to the geometry generated by the Transvoxel algorithm, ensuring material appearance blends smoothly across level-of-detail boundaries and terrain slopes [S2, S3, unofficial]. It distinguishes itself from standard voxel texturing by combining triplanar mapping with a slope-aware material blending system that adapts to the local surface orientation [S2, unofficial]. The method operates in the vertex and fragment shaders of the Transvoxel renderer [S2, unofficial].

## How it works
**Inputs and Outputs:**
- `VERTEX`: Base vertex position in local space [S2, unofficial].
- `CUSTOM0`: Custom attribute data required by the Transvoxel position calculation [S2, unofficial].
- `NORMAL`: Interpolated vertex normal [S2, unofficial].
- `MODEL_MATRIX`, `VIEW_MATRIX`, `INV_VIEW_MATRIX`: Transformation matrices [S2, unofficial].
- `u_texture_top`, `u_texture_sides`: Sampler2D for top and side textures in the basic terrain variant [S2, unofficial].
- `u_albedo_array`: Sampler2DArray for multi-material texturing in the texture array variant [S2, unofficial].
- `gen`: Global generation context providing block definitions and seeds [S3, unofficial].
- Outputs: `ALBEDO` (final surface color), `VERTEX` (transformed position), `NORMAL` (transformed normal) [S2, unofficial].

**Data Structures:**
- `v_world_pos`: Varying `vec3` storing the world-space position [S2, unofficial].
- `v_vertex_pos_model`: Varying `vec3` storing the model-space vertex position [S2, unofficial].
- `v_material_indices`: Varying `vec4` storing material IDs for each vertex corner in the texture array variant [S2, unofficial].
- `v_material_weights`: Varying `vec4` storing the blending weights for each material in the texture array variant [S2, unofficial].

**Numbered Steps:**
1. **Position & World Space**: Compute the final vertex position using the Transvoxel helper, then transform to world space for texture sampling [S2, unofficial].
   ```python
   VERTEX = get_transvoxel_position(VERTEX, CUSTOM0)  # [G] Transvoxel LOD position helper
   v_vertex_pos_model = VERTEX
   v_world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz
   ```
2. **Normal & Triplanar Setup**: Compute the surface normal in view space using the Transvoxel helper, transform to world space, scale for sampling, calculate topness, and compute triplanar blending factors [S2, unofficial].
   ```python
   NORMAL = get_voxel_normal_view(v_vertex_pos_model, NORMAL, VIEW_MATRIX * MODEL_MATRIX)  # [G] Transvoxel normal helper
   normal = (INV_VIEW_MATRIX * vec4(NORMAL, 0.0)).xyz
   wpos = v_world_pos * 0.2

   topness_midlevel = 0.5
   topness_smoothness = 0.04
   topness_min = topness_midlevel - topness_smoothness
   topness_max = topness_midlevel + topness_smoothness
   topness = smoothstep(topness_min, topness_max, normal.y)

   triplanar_sharpness = 8.0
   blending = get_triplanar_blend(normal, triplanar_sharpness)  # [G] Standard triplanar weight calculation
   ```
3. **Procedural Material Blending (Terrain Variant)**: Determine the base block type and apply slope/noise-based blending for grass, forest, and stone [S3, unofficial].
   ```python
   top_block_id = gen.topBlock(x, z, Math.floor(h), 0)
   base_color = srgb(top_block_id)

   pa = smooth(fbm(x*0.07, z*0.07, 999, 2), 0.35, 0.7) * 0.6
   forest = fbm(x*0.05 + 100, z*0.05, gen.seed + 3, 2)
   fk = smooth(forest, 0.5, 0.62) * 0.75 * (1 - smooth(h, 170, 190)) + 0.08
   leaf_color = LEAF_DARK if forest > 0.6 else LEAF
   sk = smooth(slope, 0.5, 2.2) * 0.55
   st = smooth(slope, 2.1, 3.3)
   stone_color = mix(stone_top, stone_side, st)
   ```
4. **Texture Sampling & Final Color**: Sample top and side textures using triplanar mapping and mix based on `topness` [S2, unofficial]. For the texture array variant, sample four materials and blend using normalized weights [S2, unofficial].
   ```python
   # Basic Variant
   top_col = texture_triplanar(u_texture_top, wpos, blending).rgb
   side_col = texture_triplanar(u_texture_sides, wpos, blending).rgb
   ALBEDO = mix(side_col, top_col, topness)

   # Texture Array Variant
   col0 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.x).rgb
   col1 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.y).rgb
   col2 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.z).rgb
   col3 = texture_triplanar(u_albedo_array, wpos, blending, v_material_indices.w).rgb

   weights = v_material_weights
   weights /= (weights.x + weights.y + weights.z + weights.w + 0.00001)  # [S2, unofficial]
   ALBEDO = col0 * weights.r + col1 * weights.g + col2 * weights.b + col3 * weights.a
   ```
5. **LOD Fade Discard**: Discard fragments in LOD transition zones if necessary [S2, unofficial].
   ```python
   if get_lod_fade_discard(SCREEN_UV):  # [G] LOD transition discard helper
       discard
   ```

**Formulas:**
- **Smoothstep**: $t = \min(1, \max(0, \frac{x-a}{b-a}))$, $result = t^2(3-2t)$ [S3, unofficial]. Where $x$ is the input value, $a$ is the lower bound, and $b$ is the upper bound [S3, unofficial].
- **Procedural Noise (FBM)**: Fractal Brownian Motion is used for grass patches and forest distribution [S3, unofficial]. Grass patch noise: `fbm(x*0.07, z*0.07, 999, 2)` [S3, unofficial]. Forest noise: `fbm(x*0.05+100, z*0.05, gen.seed+3, 2)` [S3, unofficial]. Parameters include scale factors, seed, and number of octaves (2) [S3, unofficial].

**Parameters:**
- `topness_midlevel`: 0.5 [S2, unofficial].
- `topness_smoothness`: 0.04 [S2, unofficial].
- `topness_min`: 0.46 [S2, unofficial].
- `topness_max`: 0.54 [S2, unofficial].
- `triplanar_sharpness`: 8.0 [S2, unofficial].
- Grass patch noise scale: `0.07` [S3, unofficial].
- Forest noise scale: `0.05` [S3, unofficial].
- Grass seed: `999` [S3, unofficial].
- Forest seed offset: `gen.seed + 3` [S3, unofficial].
- Noise octaves: `2` [S3, unofficial].
- Texture world scale: `0.2` [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Precision**: The `topness` calculation uses a narrow range (`0.46` to `0.54`) to avoid artifacts on flat surfaces [S2, unofficial]. If the normal Y component is exactly 0.5, the result is 0.5 [S2, unofficial].
- **Normalization**: In the texture array variant, material weights are normalized with a small epsilon (`0.00001`) to prevent division by zero [S2, unofficial].
- **LOD Fade**: The `get_lod_fade_discard` function must be implemented to handle visual popping at LOD boundaries [S2, unofficial]. If not handled, textures may appear to flicker or tear [S2, unofficial].
- **Slope Calculation**: The `slope` variable must be derived from the normal or height difference [S3, unofficial]. The exact formula for `slope` is not provided in the sources but is assumed to be a scalar value representing the steepness of the terrain [S3, unofficial].

## Subtopics

### [Smooth Material Texturing with Texture Array](7282-smooth-material-texturing-with-texture-array.md)
Uses a `Sampler2DArray` and per-vertex material indices/weights to blend up to four distinct materials per fragment, enabling complex multi-layer terrain definitions. Choose this when supporting diverse biomes or editor-defined material slots is required.

## Operating characteristics
- **Time Complexity**: O(1) per vertex and fragment, as it involves a fixed number of texture samples and procedural noise evaluations [G].
- **Memory Complexity**: O(1) additional memory per vertex, storing world position, normal, and material weights [G].
- **Performance**: The procedural variant is lightweight, relying on simple noise functions [S3, unofficial]. The texture array variant requires multiple texture samples (up to 4) and blending, which may be more expensive on older hardware [S2, unofficial].
- **Strengths**: Provides visually rich, natural-looking terrain without requiring complex UV unwrapping [S2, unofficial]. Handles LOD transitions smoothly by blending materials based on slope and orientation [S3, unofficial].
- **Limitations**: Procedural noise can be computationally intensive if high-frequency details are required [G]. The method assumes a consistent world-space coordinate system for texture sampling [G].

## Background
This method is part of Zylann's Voxel Game project, an open-source voxel engine [S2, unofficial]. It builds on the Transvoxel algorithm for geometry generation and LOD seam resolution [S1, unofficial]. The procedural texturing approach is inspired by standard terrain rendering techniques, adapted for the dynamic, LOD-based mesh structure of Transvoxel [S3, unofficial]. The texture array variant extends the system to support multi-material blending via indices and weights [S2, unofficial].
