# GPU Marching Cubes with Atomic Counter Emission

Also called: atomic-counter MC, indirect-draw MC, r=mesh

## Overview
GPU Marching Cubes with Atomic Counter Emission is a real-time isosurface extraction technique that eliminates the need for prefix sums or histogram pyramids by using atomic operations to reserve vertex slots directly within indirect draw arguments [S1, unofficial]. It processes one grid cell per compute thread, emitting interpolated vertices into a fixed-capacity pool buffer, which is then rendered via `drawIndirect` [S1, unofficial]. Unlike sibling methods that rely on pre-computed global counts or hierarchical histograms to determine output offsets, this method dynamically allocates space per-voxel in parallel, making it suitable for highly dynamic scenes where the number of surface voxels fluctuates significantly [S1, unofficial].

## How it works
**Inputs:**
*   A tent-blurred density grid (scalar field) [S1, unofficial].
*   An isosurface threshold parameter $\tau$ (exposed as `?iso=`) [S1, unofficial].
*   Grid dimensions $W \times H \times D$ [S1, unofficial].

**Outputs:**
*   A vertex pool buffer containing positions and gradient normals [S1, unofficial].
*   An indirect draw argument buffer specifying the vertex count and primitive topology [S1, unofficial].

**Data Structures:**

1.  **Indirect Draw Argument Buffer (`args`):**
    *   Layout: 5 unsigned 32-bit integers (standard `drawIndirect` structure plus overflow flag) [S1, unofficial].
    *   `args[0]`: Vertex count (total vertices emitted, must be a multiple of 3) [S1, unofficial].
    *   `args[1]`: Instance count (typically 1) [S1, unofficial].
    *   `args[2]`: First vertex index (offset into vertex pool) [S1, unofficial].
    *   `args[3]`: First instance index [S1, unofficial].
    *   `args[4]`: Overflow flag (1 if vertex count exceeded pool cap, 0 otherwise) [S1, unofficial].

2.  **Vertex Pool Buffer:**
    *   Capacity: 1.5 million vertices (48 MB) [S1, unofficial].
    *   Layout: Array of structures containing:
        *   `position`: `vec3<f32>` (8 bytes)
        *   `normal`: `vec3<f32>` (8 bytes)
        *   Total size per vertex: 16 bytes (assuming packed floats) or 24 bytes if aligned [S1, unofficial]. *Note: Source specifies 48 MB for 1.5M vertices, implying 32 bytes per vertex (8 bytes pos + 8 bytes normal + 16 bytes padding/alignment) or similar packing. We assume standard `vec3` padding to 16-byte boundaries.*

3.  **Marching Cubes Lookup Tables:**
    *   Generated at load time rather than hardcoded [S1, unofficial].
    *   Generation process: Marching squares per cube face $\rightarrow$ closed loops $\rightarrow$ fan triangulation [S1, unofficial].
    *   Ambiguity handling: Rotation-invariant rule for ambiguous faces (always separating the diagonal) to ensure crack-free topology [S1, unofficial].
    *   Validation: Asserted against all 256 cases for cut-edge set consistency [S1, unofficial].

**Algorithm Steps:**

1.  **Dispatch:** Launch a compute shader with one thread group per grid cell (or one thread per cell depending on implementation granularity, typically one thread per voxel for simplicity in this context) [S1, unofficial].

2.  **Classification:**
    *   Sample the 8 corner densities of the current voxel from the tent-blurred density grid [S1, unofficial].
    *   Handle out-of-range samples (boundary conditions) as density 0 to cap the isosurface against walls [S1, unofficial].
    *   Compare each corner density $V_i$ against the isovalue $\tau$.
    *   Compute the 8-bit case index $C$ [S1, Parent, unofficial].

3.  **Lookup:**
    *   Use $C$ to index into the pre-generated `triangleTable` [S1, Parent, unofficial].
    *   Identify the intersecting edges (up to 12) and the resulting triangles (up to 5) [S1, Parent, unofficial].

4.  **Slot Reservation:**
    *   Calculate the number of vertices required for the current voxel ($N_v$). Each triangle requires 3 vertices. If the voxel has $N_t$ triangles, $N_v = 3 \times N_t$ [S1, unofficial].
    *   Perform an atomic addition on the vertex count in the indirect draw argument buffer:
        $$ \text{atomicAdd}(\&\text{args}[0], N_v) $$
    *   This reserves space in the global vertex pool without requiring a prefix sum [S1, unofficial].

5.  **Vertex Emission:**
    *   For each intersecting edge, compute the intersection point $\mathbf{p}$ and the gradient normal $\mathbf{n}$ [S1, Parent, unofficial].
    *   **Caching:** Cache interpolated position and normal per unique cut edge to avoid recomputation if multiple triangles share an edge [S1, unofficial].
    *   Write the vertex data (position and normal) into the vertex pool buffer at the offset returned by the atomic operation (or a derived offset based on the pre-increment value) [S1, unofficial].
    *   *Note: The source implies writing directly into the pool. In a standard atomic counter pattern, the thread uses the return value of `atomicAdd` (the old value) as the base offset for its vertices.*

6.  **Finalization:**
    *   Launch a finalize kernel with one thread [S1, unofficial].
    *   Read the total vertex count from `args[0]` [S1, unofficial].
    *   If the count exceeds the pool cap (1.5 million vertices):
        *   Set `args[4]` (overflow flag) to 1 [S1, unofficial].
        *   Clamp `args[0]` to the maximum multiple of 3 less than or equal to the cap [S1, unofficial].
    *   If the count is within bounds, set `args[4]` to 0 [S1, unofficial].

7.  **Rendering:**
    *   Execute `drawIndirect` using the `args` buffer [S1, unofficial].
    *   The renderer pulls vertices from the pool buffer [S1, unofficial].
    *   Depth-test the mesh against the raytraced scene background in the same pass [S1, unofficial].

**Vertex Interpolation Formula:**
For an edge between vertices $\mathbf{p}_1$ and $\mathbf{p}_2$ with scalar values $V_1$ and $V_2$:
$$
\mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1)
$$
The normal $\mathbf{n}$ is computed via gradient interpolation (e.g., central differences on the density grid) [S1, Parent, unofficial].

**Edge Cases and Pitfalls:**
*   **Overflow:** If the pre-clamp vertex count exceeds 1.5 million, the overflow flag is raised. The count is clamped to ensure only whole triangles are drawn, preventing garbage rendering [S1, unofficial].
*   **Overflow Flag Location:** The overflow flag is stored in `args[4]`, not `firstInstance` (`args[3]`), because a non-zero `firstInstance` no-ops the indirect draw without the `indirect-first-instance` feature [S1, unofficial].
*   **Wall Capping:** Lattice index 0 is treated as outside density (0) to cap the isosurface on all six walls. Blur bleed outside the walls (cells $2 \dots \text{GRID}-2$) is discarded [S1, unofficial].
*   **Ambiguity:** The load-time generated table uses a rotation-invariant ambiguity rule to prevent cracks [S1, unofficial].

**Pseudocode:**

```python
# Compute Shader: One thread per voxel (x, y, z)

# Constants
MAX_VERTICES = 1500000
ISOVAL = ?iso= # Passed as uniform

# Global Buffers
density_grid: Texture3D<f32>
vertex_pool: Buffer<vec3<f32>, vec3<f32>> # Position, Normal
args_buffer: Buffer<vec4<u32>> # args[0]=count, args[4]=overflow

# Helper: Get density at (x,y,z), treating out-of-bounds as 0
fn get_density(x, y, z) -> f32:
    if x < 0 or x >= GRID_W or y < 0 or y >= GRID_H or z < 0 or z >= GRID_D:
        return 0.0
    return density_grid.sample(x, y, z)

# Helper: Linear interpolation
fn lerp(a, b, t) -> f32:
    return a + t * (b - a)

# Helper: Compute normal via gradient
fn compute_normal(x, y, z) -> vec3<f32>:
    # Central differences
    dx = get_density(x+1, y, z) - get_density(x-1, y, z)
    dy = get_density(x, y+1, z) - get_density(x, y-1, z)
    dz = get_density(x, y, z+1) - get_density(x, y, z-1)
    return normalize(vec3<f32>(dx, dy, dz))

# Main Kernel
fn main(x: u32, y: u32, z: u32) {
    # 1. Sample corners
    # Vertex indices 0-7 based on standard MC ordering
    v0 = get_density(x, y, z)
    v1 = get_density(x+1, y, z)
    v2 = get_density(x+1, y+1, z)
    v3 = get_density(x, y+1, z)
    v4 = get_density(x, y, z+1)
    v5 = get_density(x+1, y, z+1)
    v6 = get_density(x+1, y+1, z+1)
    v7 = get_density(x, y+1, z+1)

    # 2. Compute case index C
    C = 0
    if v0 < ISOVAL: C |= 1 << 0
    if v1 < ISOVAL: C |= 1 << 1
    if v2 < ISOVAL: C |= 1 << 2
    if v3 < ISOVAL: C |= 1 << 3
    if v4 < ISOVAL: C |= 1 << 4
    if v5 < ISOVAL: C |= 1 << 5
    if v6 < ISOVAL: C |= 1 << 6
    if v7 < ISOVAL: C |= 1 << 7

    # 3. Lookup triangles
    # triangleTable[C] returns a list of edge indices
    # Each triplet forms a triangle
    triangles = triangleTable[C]
    
    # 4. Reserve slots
    # Each triangle has 3 vertices
    num_triangles = count_triangles(triangles)
    num_vertices = num_triangles * 3
    
    # Atomic add to get base offset for this voxel's vertices
    base_offset = atomicAdd(args_buffer[0], num_vertices)
    
    # 5. Emit vertices
    current_vertex_idx = base_offset
    for each triangle in triangles:
        e0 = triangle[0]
        e1 = triangle[1]
        e2 = triangle[2]
        
        # Get edge endpoints and interpolate
        # Edge indices 0-11 map to specific vertex pairs
        p0, n0 = get_edge_vertex(e0, x, y, z)
        p1, n1 = get_edge_vertex(e1, x, y, z)
        p2, n2 = get_edge_vertex(e2, x, y, z)
        
        # Write to pool
        vertex_pool[current_vertex_idx].position = p0
        vertex_pool[current_vertex_idx].normal = n0
        current_vertex_idx += 1
        
        vertex_pool[current_vertex_idx].position = p1
        vertex_pool[current_vertex_idx].normal = n1
        current_vertex_idx += 1
        
        vertex_pool[current_vertex_idx].position = p2
        vertex_pool[current_vertex_idx].normal = n2
        current_vertex_idx += 1

# Helper: Get interpolated vertex for an edge
# Edge indices: 0-3 (bottom), 4-7 (top), 8-11 (vertical)
fn get_edge_vertex(edge_idx, x, y, z) -> (vec3<f32>, vec3<f32>):
    # Define corner positions and densities
    corners = [
        (vec3<f32>(x, y, z), v0),
        (vec3<f32>(x+1, y, z), v1),
        (vec3<f32>(x+1, y+1, z), v2),
        (vec3<f32>(x, y+1, z), v3),
        (vec3<f32>(x, y, z+1), v4),
        (vec3<f32>(x+1, y, z+1), v5),
        (vec3<f32>(x+1, y+1, z+1), v6),
        (vec3<f32>(x, y+1, z+1), v7)
    ]
    
    # Map edge index to corner indices
    edge_map = [
        (0, 1), (1, 2), (2, 3), (3, 0), # Bottom
        (4, 5), (5, 6), (6, 7), (7, 4), # Top
        (0, 4), (1, 5), (2, 6), (3, 7)  # Vertical
    ]
    
    c1_idx, c2_idx = edge_map[edge_idx]
    p1, d1 = corners[c1_idx]
    p2, d2 = corners[c2_idx]
    
    # Interpolate position
    t = (ISOVAL - d1) / (d2 - d1)
    pos = lerp_vec3(p1, p2, t)
    
    # Interpolate normal (simplified: average of corner normals or gradient)
    # Source says "gradient normal", so we compute gradient at intersection
    # For simplicity in pseudocode, we approximate or use cached gradient
    # In practice, compute gradient at pos using central differences on density grid
    norm = compute_normal(pos.x, pos.y, pos.z)
    
    return (pos, norm)

# Finalize Kernel: One thread
fn finalize() {
    count = args_buffer[0]
    if count > MAX_VERTICES:
        args_buffer[4] = 1 # Overflow flag
        # Clamp to largest multiple of 3 <= MAX_VERTICES
        args_buffer[0] = (MAX_VERTICES / 3) * 3
    else:
        args_buffer[4] = 0
}
```

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed by one thread. The atomic operations are $O(1)$ amortized.
*   **Memory Complexity:** $O(V_{pool})$ where $V_{pool}$ is the fixed vertex pool size (1.5 million vertices) [S1, unofficial].
*   **Performance:** 4.12 ms/frame at $128^3$ resolution and $384^2$ screen size on M-series hardware [S1, unofficial].
*   **Strengths:**
    *   No prefix sum required, reducing memory bandwidth and latency associated with histogram/pyramid construction [S1, unofficial].
    *   Simple implementation on GPU compute shaders [S1, unofficial].
    *   Handles dynamic scenes well due to per-frame atomic allocation [S1, unofficial].
*   **Limitations:**
    *   Fixed vertex pool size (1.5M) can lead to overflow in complex scenes, requiring clamping and potential visual artifacts if the overflow flag is not handled gracefully by the application [S1, unofficial].
    *   Atomic contention on the vertex count buffer can become a bottleneck at very high resolutions or high surface densities [S1, unofficial].
    *   WebGL2 fallback is limited to screen-space fluid (ssf) path, so full MC is only available in WebGPU [S1, unofficial].

## Background
This method was introduced in the "waterfall" WebGL2 fluid simulation project by nikolai3d as the `r=mesh` renderer [S1, unofficial]. It was developed to provide a real-time, GPU-accelerated isosurface meshing alternative to screen-space techniques, leveraging WebGPU's compute shader capabilities [S1, unofficial]. The approach was designed to avoid the complexity of prefix sums while maintaining performance on consumer hardware [S1, unofficial].
