# GPU-accelerated Marching Cubes with Distance Extraction

Also called: WebGL Signed Distance Function Mesher, glsl-marching-cubes

## Overview
This method extracts an STL mesh from a Signed Distance Function (SDF) by offloading the scalar field evaluation to a GLSL fragment shader, extracting the resulting vertex distances to CPU-accessible buffers, and performing the topological Marching Cubes algorithm on the CPU [S1, unofficial]. It differs from pure GPU extraction methods by avoiding the performance penalty of transferring large triangle lists from GPU to CPU, instead transferring only the scalar distance values [S1, unofficial]. It is specifically designed for WebGL environments using libraries like Three.js and TWGL [S1, unofficial].

## How it works
**Inputs:**
*   Volume dimensions (`dims`): Array of 3 integers representing the number of cells in x, y, z.
*   Volume bounds (`bounds`): Array of 2 arrays of 3 floats, defining the min and max coordinates of the volume.
*   SDF evaluation function: Implemented in GLSL.

**Outputs:**
*   STL mesh file (potentially split into parts).

**Data Structures:**
*   `volume`: Object containing `dims` (3 ints), `bounds` (2x3 floats), `vertexCount` (int), and `size` (int, derived from `vertexCount`).
*   `blockPotentialBuffers`: Array of `ArrayBuffer` objects. Each buffer has size `volume.vertexCount * 4` bytes, storing `Float32` values.
*   `volumes`: Array of split volume chunks, generated by `splitVolume`.

**Parameters:**
*   `maxSize`: Maximum texture size for the GPU rendering buffer, capped at 4096 [S1, unofficial].
*   `numWorkers`: Number of worker threads for parallel processing, set to 4 [S1, unofficial].
*   `blocks`: Number of chunks to split the volume into for worker distribution, set to 256 [S1, unofficial].

**Algorithm Steps:**

1.  **Volume Subdivision**:
    Calculate the total vertex count: $V = (dims[0] + 1) \times (dims[1] + 1) \times (dims[2] + 1)$.
    Determine the texture size: $S = \lceil \sqrt{V} \rceil$.
    Cap $S$ at `maxSize` (4096).
    Subdivide the volume into blocks small enough to fit within the maximum texture dimensions [S1, unofficial].

2.  **Distance Extraction (GPU)**:
    For each volume block:
    a. Initialize `numWorkers` buffers of size $V \times 4$ bytes.
    b. Render the volume block using a fragment shader that evaluates the SDF at each vertex.
    c. Read the pixel data back from the GPU using `gl.readPixels`.
    d. Unpack the RGBA float values into the `blockPotentialBuffers` [S1, unofficial].

3.  **Culling**:
    Check if the block contains geometry. A block is skipped if all vertices have the same sign (all positive/outside or all negative/inside) [S1, unofficial].
    *Note: The source code checks `containsGeometry` by verifying if any vertex crosses the zero threshold relative to previous values, but the text explicitly states blocks entirely inside or outside are skipped.*

4.  **Marching Cubes (CPU)**:
    Distribute the remaining blocks among `numWorkers` threads.
    Each worker processes a subset of blocks (up to `blocks` chunks) using a standard Marching Cubes implementation [S1, unofficial].

5.  **Output**:
    Generate STL files. Large meshes may be saved in parts [S1, unofficial].

**Pseudocode:**

```python
def extract_mesh(dims, bounds, sdf_shader):
    # 1. Setup and Subdivision
    vertex_count = (dims[0] + 1) * (dims[1] + 1) * (dims[2] + 1)
    size = ceil(sqrt(vertex_count))
    max_size = min(size, 4096)
    
    # Split volume into chunks fitting max_size
    volumes = split_volume(dims, bounds, max_size)
    
    num_workers = 4
    blocks_per_worker = 256
    
    worker_pool = WorkerPool(num_workers)
    
    for volume in volumes:
        # 2. GPU Distance Extraction
        block_potential_buffers = []
        for i in range(num_workers):
            buffer = ArrayBuffer(volume.vertex_count * 4)
            block_potential_buffers.append(buffer)
            
        # Render SDF to texture and read back
        potentials = read_gpu_potentials(volume, sdf_shader, max_size)
        
        # 3. Culling
        if not contains_geometry(potentials):
            continue
            
        # 4. CPU Marching Cubes
        # Distribute blocks to workers
        worker_pool.submit_task(volume, potentials, block_potential_buffers)
        
    # 5. Combine and Save
    meshes = worker_pool.join()
    save_stl(meshes)
```

**Edge Cases and Pitfalls:**
*   **Missing Triangles**: Holes may appear in the resulting mesh [S1, unofficial].
*   **Large Meshes**: The method saves large meshes in parts, requiring external tools like MeshLab to re-combine them [S1, unofficial].
*   **Performance**: Running the entire algorithm on the GPU is slower due to data retrieval costs [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Dominated by GPU rendering and CPU Marching Cubes. Culling skips empty blocks, improving performance for sparse volumes.
*   **Memory Complexity**: Requires storing distance values for all vertices in the volume. Buffer size is $V \times 4$ bytes per worker.
*   **Strengths**: Reduces GPU/CPU round trips by extracting only distances, not triangles. Suitable for WebGL environments.
*   **Limitations**: Requires CPU processing for topology. Large meshes are split. Potential for missing triangles.
*   **When to use**: When extracting SDFs in WebGL contexts and CPU processing is acceptable.
*   **When not to use**: When real-time GPU-only extraction is required or when hole-free meshes are critical without post-processing.

## Background
This method originates from the `glsl-marching-cubes` project by tdhooper, an unofficial implementation for WebGL [S1, unofficial]. It builds on the basic Marching Cubes algorithm but adapts it for the constraints of WebGL, where GPU-to-CPU data transfer is expensive [S1, unofficial]. It relies on libraries like Three.js, TWGL, and stack.gl [S1, unofficial].
