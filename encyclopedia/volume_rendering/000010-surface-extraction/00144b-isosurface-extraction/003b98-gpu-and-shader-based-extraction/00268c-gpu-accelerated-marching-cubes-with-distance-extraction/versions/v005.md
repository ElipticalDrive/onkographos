# GPU-accelerated Marching Cubes with Distance Extraction

Also called: WebGL Signed Distance Function Mesher, glsl-marching-cubes

## Overview
This method extracts an STL mesh from a Signed Distance Function (SDF) by offloading the scalar field evaluation to the GPU via a fragment shader, while performing the topological connectivity and mesh generation on the CPU. It differs from pure GPU implementations by extracting vertex distances first to minimize expensive GPU-to-CPU data transfer costs, which are identified as the primary bottleneck for running the entire algorithm on the GPU [S1, unofficial].

## How it works
**Inputs:**
- A mathematical SDF function $f(x, y, z)$ [S1, unofficial].
- Volume dimensions `dims` (array of 3 integers) and spatial `bounds` (array of 2 arrays of 3 floats) [S1, unofficial].
- `maxSize`: The maximum texture size for the GPU rendering buffer, capped at 4096 [S1, unofficial].
- `numWorkers`: The number of CPU worker threads for parallel processing, typically set to 4 [S1, unofficial].
- `blocks`: The number of chunks to split the volume into for worker distribution, typically set to 256 [S1, unofficial].

**Outputs:**
- An STL mesh file. Note that large meshes are saved in parts and must be re-combined externally (e.g., with MeshLab) [S1, unofficial].

**Data Structures:**
- `volume`: An object containing:
  - `dims`: Array of 3 integers defining the grid resolution.
  - `bounds`: Array of 2 arrays of 3 floats defining the spatial extent.
  - `vertexCount`: Integer, calculated as $(dims[0] + 1) \times (dims[1] + 1) \times (dims[2] + 1)$ [S1, unofficial].
  - `size`: Integer, calculated as $\lceil \sqrt{vertexCount} \rceil$, used for texture dimensions [S1, unofficial].
- `blockPotentialBuffers`: An array of `ArrayBuffer` objects. Each buffer has a size of `volume.vertexCount * 4` bytes, storing `Float32` values representing the extracted distances [S1, unofficial].

**Algorithm Steps:**

1.  **Volume Subdivision**: Subdivide the volume defined by `dims` and `bounds` into blocks small enough to fit within `maxSize` (capped at 4096) [S1, unofficial]. This ensures the vertex data fits into the GPU texture buffer [S1, unofficial].
2.  **Distance Extraction**: For each block, render a geometry representing the cube vertices to a framebuffer using a fragment shader that evaluates the SDF $f(x, y, z)$ for each vertex [S1, unofficial].
3.  **Pixel Readback**: Read the rendered pixel values from the GPU using `gl.readPixels` to populate the `blockPotentialBuffers` with the scalar field values [S1, unofficial].
4.  **Empty Space Culling**: Analyze the extracted distances. If all vertices in a block have negative distances (entirely inside) or positive distances (entirely outside), skip processing that block [S1, unofficial]. This optimization saves time for models with significant empty space [S1, unofficial].
5.  **CPU Marching Cubes**: For blocks containing geometry (mixed signs), pass the `blockPotentialBuffers` to CPU worker threads [S1, unofficial].
6.  **Mesh Generation**: The CPU workers execute the standard Marching Cubes algorithm using the extracted distances to determine edge intersections and triangle topology [S1, unofficial].
7.  **Output**: Combine the generated triangles into an STL file [S1, unofficial].

**Pseudocode:**

```python
def gpu_accelerated_marching_cubes(sdf_function, dims, bounds, max_size=4096, num_workers=4, blocks=256):
    # 1. Subdivide volume
    # Calculate vertex count and texture size
    vertex_count = (dims[0] + 1) * (dims[1] + 1) * (dims[2] + 1)
    texture_size = ceil(sqrt(vertex_count))
    effective_max_size = min(texture_size, max_size)
    
    # Split volume into chunks that fit within effective_max_size
    volume_chunks = split_volume(dims, bounds, effective_max_size)
    
    # Initialize worker pool
    worker_pool = WorkerPool(num_workers)
    
    all_mesh_parts = []
    
    for chunk in volume_chunks:
        # 2. Distance Extraction via Shader
        # Setup framebuffer and shader uniforms with chunk bounds and dims
        uniforms = {
            'boundsA': chunk.bounds[0],
            'boundsB': chunk.bounds[1],
            'dims': chunk.dims
        }
        
        # Render vertices to texture using SDF shader
        render_sdf_to_texture(sdf_function, uniforms, effective_max_size)
        
        # 3. Readback distances
        # Allocate buffers for each worker
        block_potential_buffers = []
        for _ in range(num_workers):
            buffer = ArrayBuffer(chunk.vertex_count * 4)
            block_potential_buffers.append(buffer)
            
        # Read pixels from GPU to CPU buffers
        gl_read_pixels(0, 0, effective_max_size, effective_max_size, block_potential_buffers)
        
        # 4. Empty Space Culling
        # Check if chunk contains geometry (mixed signs)
        contains_geometry = False
        previous_value = None
        
        for buffer in block_potential_buffers:
            values = Float32Array(buffer)
            for value in values:
                if previous_value is not None:
                    if (value > 0) != (previous_value > 0):
                        contains_geometry = True
                        break
                previous_value = value
            if contains_geometry:
                break
        
        if not contains_geometry:
            continue
            
        # 5. CPU Marching Cubes
        # Distribute work to workers
        worker_pool.init(block_potential_buffers)
        
        # Process blocks
        cubes_in_chunk = chunk.dims[0] * chunk.dims[1] * chunk.dims[2]
        start = 0
        end = 0
        remaining_blocks = blocks
        
        while remaining_blocks > 0:
            start = end
            # Calculate end for this block
            end = start + floor((cubes_in_chunk - start) / remaining_blocks)
            
            # Extract sub-block data and run marching cubes
            sub_block_data = extract_sub_block(block_potential_buffers, start, end)
            triangles = marching_cubes_cpu(sub_block_data)
            all_mesh_parts.append(triangles)
            
            remaining_blocks -= 1
            
    # 7. Output
    return combine_meshes(all_mesh_parts)
```

**Edge Cases and Pitfalls:**
- **Missing Triangles**: Holes may appear in the resulting mesh [S1, unofficial].
- **Large Meshes**: The method saves large meshes in parts; they must be re-combined externally [S1, unofficial].
- **Precision**: The method relies on reading floating-point values from the GPU framebuffer, which may introduce precision limitations depending on the framebuffer format [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Dominated by GPU rendering and CPU readback for distance extraction, followed by CPU-based Marching Cubes. The culling step reduces the number of blocks processed by the CPU [S1, unofficial].
- **Memory Complexity**: Requires memory for `blockPotentialBuffers` proportional to `vertexCount * 4` bytes per worker [S1, unofficial].
- **Performance**: Running the entire algorithm on the GPU was found to be too slow due to data retrieval costs, making this hybrid approach faster [S1, unofficial].
- **Strengths**: Reduces GPU/CPU round trips by extracting distances first; effective culling of empty space [S1, unofficial].
- **Limitations**: Potential for missing triangles (holes); large meshes require external recombination; limited by maximum texture size (capped at 4096) [S1, unofficial].

## Background
This method originates from the "WebGL Signed Distance Function Mesher" project by tdhooper, which implements a technique to extract STL meshes from GLSL distance functions [S1, unofficial]. It builds on the basic Marching Cubes algorithm but modifies the data flow to optimize for WebGL environments where CPU-GPU communication is costly [S1, unofficial]. The implementation uses libraries such as three.js, stack.gl, and TWGL [S1, unofficial].
