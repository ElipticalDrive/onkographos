# GPU Marching Cubes Terrain Pipeline with Indirect Rendering

Also called: GPU Marching Cubes with Indirect Rendering, Indirect Marching Cubes, Keijiro's GPU Marching Cubes (modified), Marching Cubes/MeshBuilderIndirect, TerrainMeshBuilderIndirect

## Overview
This method generates terrain meshes from voxel data on the GPU using Marching Cubes, utilizing indirect rendering to allow the GPU to generate and render the mesh directly without CPU readback, avoiding performance stalls [S1, unofficial]. It manages multiple LOD levels and renders generated triangles via indirect draw calls to minimize CPU-GPU synchronization overhead [S1, unofficial]. Unlike CPU implementations or earlier GPU versions that required readback, this approach keeps RenderThread time low (~1.5ms) by eliminating CPU mesh copy operations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Voxel data buffer (`ComputeBuffer`), voxel resolution (`int3`), voxel size (`float`), isovalue (`float`, typically 0.0), chunk center in world space (`float3`), and the precomputed `triangleTable` (256 `ulong` values) [S1, unofficial].
*   **Outputs:** A vertex buffer containing triangles (`AppendStructuredBuffer`) and indirect draw arguments (`ComputeBuffer` of 5 `uint`s) [S1, unofficial].

**Data Structures:**
*   **VertexGPU:** Contains `float3 posWS` (world position), `float3 nrmWS` (world normal), and `float2 uv` [S1, unofficial]. Size: 32 bytes (assuming 8 bytes per float).
*   **Triangle:** Contains three `VertexGPU` structs (`v0`, `v1`, `v2`) [S1, unofficial]. Size: 96 bytes ($3 \times 32$) [S1, unofficial].
*   **IndirectArgBuffer:** 5 `uint` values. Index 0: total vertex count, Index 1: instance count, Index 2: start vertex, Index 3: start instance, Index 4: unused [S1, unofficial].
*   **TerrainLod:** Contains `LOD` (int), `VoxelResolution` (int3), and `chunkRadius` (int) [S1, unofficial]. LODs must be ordered highest-to-lowest resolution [S1, unofficial].

**Parameters:**
*   **Isovalue:** 0.0f [S1, unofficial].
*   **HalfVoxelOffset:** `voxelSize * -0.5f` applied to all three axes to center the voxel grid relative to the chunk origin [S1, unofficial].
*   **Shader Target:** 4.5 [S1, unofficial].
*   **Thread Group:** $4 \times 4 \times 4$ [S1, unofficial].

**Algorithm Steps:**

1.  **Buffer Allocation:** For each LOD level $i$, compute the active chunk count using `ManhattanFloodFillCount3D`. For LOD 0, use the full count; for $i>0$, subtract the previous LOD's count. Allocate `VertexBuffers` as `AppendStructuredBuffer` sized to `voxelRes.x * voxelRes.y * voxelRes.z * activeChunks`. Allocate `IndirectArgBuffers` as 5 `uint` values [S1, unofficial].
2.  **Initialize Indirect Arguments:** Set `IndirectArgBuffers` to `{3, 1, 0, 0, 0}` (vertexCountPerInstance=3, instanceCount=1, startVertex=0, startInstance=0, unused=0) [S1, unofficial].
3.  **Dispatch Marching Cubes Compute Kernel:**
    *   Bind `voxelBuffer`, `vertexBuffer` (as append buffer), `triangleTable`, and material.
    *   Set uniforms: `Dims` (resolution), `Scale` (voxel size), `Isovalue` (0.0), `HalfVoxelOffset` (`Scale * -0.5`), `chunkCenter` (world space center).
    *   Dispatch with group counts `ceil(res/4)` in each dimension [S1, unofficial].
    *   *Kernel Logic:* Each thread processes one voxel. It samples the 8 corners, computes the cube index, and uses `triangleTable` to emit triangles to the append buffer. The vertex shader (used in the rendering phase, see below) fetches corner vertices: if corner index is 0, return `t.v0`; if 1, return `t.v1`; else return `t.v2` [S1, unofficial].
4.  **Update Vertex Count:** Copy the triangle append counter from `VertexBuffers` to `indirectArgsBuffer` at byte offset 0. Dispatch a helper compute shader (`indirectArgumentSetter`) to multiply `args[0]` by 3 (vertices per triangle) and `args[1]` by 1 [S1, unofficial].
5.  **Enqueue Draw Call:** Create an `IndirectDrawCall` entry containing the triangle buffer, indirect args buffer, terrain material, and identity transform matrix. Register it with `GpuIndirectDrawRegistry.Add()` [S1, unofficial].
6.  **Reset Append Counter:** After enqueueing, call `vertexBuffer.SetCounterValue(0)` to clear the triangle append buffer for the next frame [S1, unofficial].

**Rendering Shader Details:**
*   **Vertex Shader:** Transforms the world-space position to clip space using `TransformWorldToHClip(o.posWS)` [S1, unofficial].
*   **Fragment Shader:** Normalizes the normal vector `N`. If `dot(N, V) < 0` (where `V` is view direction), flip `N` to ensure it points towards the camera. Calculate Lambertian lighting using a fixed light direction `float3(1,1,0)` and return a value interpolated between 0.25 and 1.0 based on the dot product [S1, unofficial].

**Pseudocode:**

```python
# Pseudocode for the GPU Compute Kernel (Marching Cubes)
[numthreads(4, 4, 4)]
void MarchingCubesKernel(uint3 id : SV_DispatchThreadID) {
    // Boundary check
    if (id.x >= Dims.x || id.y >= Dims.y || id.z >= Dims.z) return;

    // Sample 8 corners of the voxel
    float3 cornerPos = float3(id, 0) + HalfVoxelOffset;
    float values[8];
    for (int i = 0; i < 8; i++) {
        int3 cornerIdx = id + int3((i>>0)&1, (i>>1)&1, (i>>2)&1);
        values[i] = Voxels[cornerIdx.x, cornerIdx.y, cornerIdx.z];
    }

    // Compute cube index
    int cubeIndex = 0;
    for (int i = 0; i < 8; i++) {
        if (values[i] >= Isovalue) {
            cubeIndex |= (1 << i);
        }
    }

    // Lookup triangle table
    // triangleTable is a ComputeBuffer of 256 ulong values
    ulong triConfig = TriangleTable[cubeIndex];
    
    // Extract edge indices (16 entries, 4 bits each)
    int edgeIndices[12];
    for (int i = 0; i < 12; i++) {
        edgeIndices[i] = (triConfig >> (i * 4)) & 0xF;
    }

    // Emit triangles
    // The triangle table defines triangles as triplets of edge indices
    // Assuming standard Marching Cubes triangle table format
    int triCount = 0;
    while (edgeIndices[triCount * 3] != -1) {
        int e0 = edgeIndices[triCount * 3];
        int e1 = edgeIndices[triCount * 3 + 1];
        int e2 = edgeIndices[triCount * 3 + 2];

        // Interpolate vertices on edges
        VertexGPU v0 = InterpolateVertex(values, e0, cornerPos, Scale);
        VertexGPU v1 = InterpolateVertex(values, e1, cornerPos, Scale);
        VertexGPU v2 = InterpolateVertex(values, e2, cornerPos, Scale);

        // Append to buffer
        g_Tris.Append(Triangle(v0, v1, v2));
        
        triCount++;
    }
}

VertexGPU InterpolateVertex(float values[8], int edgeIndex, float3 cornerPos, float scale) {
    // Map edge index to two corner indices
    int c0, c1;
    // ... edge to corner mapping logic ...
    
    float v0 = values[c0];
    float v1 = values[c1];
    
    // Linear interpolation
    float t = (Isovalue - v0) / (v1 - v0);
    float3 p0 = cornerPos + float3((c0>>0)&1, (c0>>1)&1, (c0>>2)&1) * scale;
    float3 p1 = cornerPos + float3((c1>>0)&1, (c1>>1)&1, (c1>>2)&1) * scale;
    
    return VertexGPU(p0 + t * (p1 - p0), normalize(cross(...)), float2(0,0));
}
```

## Subtopics

### [Marching Cubes Chunk Generation Pipeline](3925-marching-cubes-chunk-generation-pipeline.md)
This method is a procedural terrain generation pipeline that divides a 3D volume into overlapping chunks, populates them with noise-derived node values, and prepares chunk meshes for Marching Cubes surface extraction. It builds on [GPU Marching Cubes Terrain Pipeline with Indirect Rendering](3803-gpu-marching-cubes-terrain-pipeline-with-indirect-rendering.md) by handling the CPU-side data preparation and chunk management required for the GPU-accelerated extraction. Unlike single-volume extraction, this approach manages spatial locality and boundary continuity through overlapping node grids, ensuring seamless transitions between adjacent chunks.

## Operating characteristics
*   **Time Complexity:** The compute kernel runs in $O(V)$ where $V$ is the number of voxels. The indirect rendering setup is $O(1)$ per LOD.
*   **Memory Complexity:** Memory scales linearly with voxel volume and active chunks per LOD: $O(\text{VoxelResolution.x} \times \text{VoxelResolution.y} \times \text{VoxelResolution.z} \times \text{activeChunks})$ [S1, unofficial]. Each triangle consumes 96 bytes in the append buffer [S1, unofficial].
*   **Performance:** RenderThread time is kept low (~1.5ms) by avoiding CPU mesh copy and readback [S1, unofficial].
*   **Strengths:** Eliminates CPU-GPU synchronization overhead; supports multiple LOD levels; efficient for dynamic terrain.
*   **Limitations:** Requires custom physics/collision solutions since the mesh is not available on the CPU [S1, unofficial]. Voxel resolution must be odd; even resolutions trigger a validation error and break the pipeline [S1, unofficial]. Chunk dimensions must be cube-like ($x == y == z$); non-cubic chunks trigger a validation error [S1, unofficial].
*   **When to Use:** Real-time terrain rendering in Unity where CPU overhead is a bottleneck.
*   **When Not to Use:** When CPU-side mesh access is required for physics or collision detection.

## Background
This method is implemented in Unity terrain rendering pipelines using `ComputeShader` for surface extraction and `GpuIndirectDrawRegistry` for batched rendering [S1, unofficial]. It is a modification of Keijiro's GPU Marching Cubes, adapted to use indirect rendering instead of CPU readback [S1, unofficial].
