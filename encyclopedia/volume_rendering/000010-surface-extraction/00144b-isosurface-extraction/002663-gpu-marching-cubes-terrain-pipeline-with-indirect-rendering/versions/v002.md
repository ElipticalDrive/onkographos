# GPU Marching Cubes Terrain Pipeline with Indirect Rendering

Also called: GPU Marching Cubes with Indirect Rendering, Indirect Marching Cubes, Keijiro's GPU Marching Cubes (modified), Marching Cubes/MeshBuilderIndirect, TerrainMeshBuilderIndirect

## Overview
This method generates terrain meshes from voxel data on the GPU using Marching Cubes, utilizing indirect rendering to allow the GPU to generate and render the mesh directly without CPU readback, avoiding performance stalls [S1, unofficial]. It manages multiple LOD levels and renders generated triangles via indirect draw calls to minimize CPU-GPU synchronization overhead [S1, unofficial]. Unlike original CPU implementations or Keijiro's GPU version which read back to CPU, this method keeps RenderThread time low (~1.5ms) and avoids CPU mesh copy, requiring custom physics/collision solutions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Voxel data buffer (scalar field), voxel resolution (must be odd), voxel size (scale), isovalue (typically 0.0), chunk center in world space, and a precomputed Marching Cubes triangle lookup table (256 `ulong` values).
*   **Outputs:** A mesh (triangle list) stored in a GPU append buffer, rendered via indirect draw calls.

**Data Structures:**
1.  **VertexGPU:**
    *   `float3 posWS`: World-space position.
    *   `float3 nrmWS`: World-space normal.
    *   `float2 uv`: Texture coordinates.
    *   Size: 32 bytes.
2.  **Triangle:**
    *   `VertexGPU v0`, `v1`, `v2`.
    *   Size: 96 bytes (3 vertices * 32 bytes).
3.  **IndirectArgBuffer:**
    *   Array of 5 `uint` values.
    *   Index 0: Total vertex count (set by compute shader * 3).
    *   Index 1: Instance count (triangle count).
    *   Index 2: Start vertex (0).
    *   Index 3: Start instance (0).
    *   Index 4: Unused (0).
4.  **TerrainLod:**
    *   `int LOD`: Level of detail identifier.
    *   `int3 VoxelResolution`: Resolution of the voxel grid for this LOD.
    *   `int chunkRadius`: Spatial radius of the chunk.
    *   LODs must be ordered highest-to-lowest resolution.

**Algorithm Steps:**

1.  **Buffer Allocation:**
    For each LOD level $i$, compute the active chunk count using a flood fill or spatial query (`ManhattanFloodFillCount3D`).
    *   For LOD 0, use the full active chunk count.
    *   For $i > 0$, subtract the previous LOD's count to determine unique chunks for this level.
    *   Allocate `VertexBuffers` as `AppendStructuredBuffer<Triangle>` sized to:
        $$ \text{Size} = \text{VoxelResolution}_x \times \text{VoxelResolution}_y \times \text{VoxelResolution}_z \times \text{ActiveChunks} $$
    *   Allocate `IndirectArgBuffers` with 5 `uint` values.

2.  **Initialize Indirect Arguments:**
    Set `IndirectArgBuffers` initial values to `{3, 1, 0, 0, 0}`.
    *   `vertexCountPerInstance` = 3 (vertices per triangle).
    *   `instanceCount` = 1 (placeholder, updated later).
    *   `startVertex` = 0.
    *   `startInstance` = 0.
    *   `unused` = 0.

3.  **Dispatch Marching Cubes Compute Kernel:**
    Dispatch the compute shader kernel for each chunk.
    *   **Thread Group:** Dispatch with group counts $\lceil \text{Resolution} / 4 \rceil$ in each dimension, implying a $4 \times 4 \times 4$ thread group.
    *   **Shader Inputs:**
        *   `Dims`: Voxel resolution $(x, y, z)$.
        *   `Scale`: Voxel size.
        *   `Isovalue`: 0.0f.
        *   `HalfVoxelOffset`: $\text{Scale} \times -0.5f$ (applied to all axes to center the grid).
        *   `chunkCenterWS`: World-space center of the chunk.
        *   `TriangleTable`: Precomputed 256 `ulong` lookup table.
        *   `Voxels`: The scalar field buffer.
    *   **Shader Outputs:**
        *   `g_Tris`: `AppendStructuredBuffer<Triangle>`.

    **Compute Shader Logic (Per Cell):**
    The compute shader processes each voxel cell. For each cell, it determines the edge intersections based on the scalar values at the 8 corners against the `Isovalue`. It uses the `TriangleTable` to determine which triangles to generate.
    *   *Vertex Fetching:* If the corner index is 0, return `t.v0`; if 1, return `t.v1`; else return `t.v2` (referring to the specific vertex structure in the triangle definition).
    *   *Append:* Write generated `Triangle` structs to `g_Tris`.

4.  **Update Indirect Arguments:**
    After the compute kernel finishes, the GPU has written the triangle count to the append buffer's internal counter.
    *   Copy the triangle append counter from `VertexBuffers` to `indirectArgsBuffer` at byte offset 0.
    *   Dispatch a helper compute shader (`indirectArgumentSetter`) to update the indirect arguments:
        *   `args[0]` (vertex count) = `triangle_count * 3`.
        *   `args[1]` (instance count) = `triangle_count`.
        *   `args[2]` = 0.
        *   `args[3]` = 0.
        *   `args[4]` = 0.

5.  **Enqueue Indirect Draw Call:**
    Create an `IndirectDrawCall` entry containing:
    *   `tris`: The `VertexBuffers` (triangle buffer).
    *   `args`: The `IndirectArgBuffers`.
    *   `material`: The terrain material.
    *   `trs`: Identity transform matrix (or chunk-specific transform if not baked into world space).
    *   Register it with `GpuIndirectDrawRegistry.Add()`.

6.  **Reset Append Counter:**
    Call `vertexBuffer.SetCounterValue(0)` to clear the triangle append buffer for the next frame.

**Vertex Shader:**
*   Fetches the corner vertex: if corner is 0, return `t.v0`; if 1, return `t.v1`; else return `t.v2`.
*   Transforms the world-space position to clip space: `TransformWorldToHClip(o.posWS)`.

**Fragment Shader:**
*   Normalizes the normal vector `N`.
*   If $\text{dot}(N, V) < 0$ (where $V$ is view direction), flip `N` to ensure it points towards the camera.
*   Calculates Lambertian lighting using a fixed light direction `float3(1, 1, 0)`.
*   Returns a value interpolated between 0.25 and 1.0 based on the dot product.

**Pseudocode:**

```python
# Initialization
def init_pipeline(lods, chunk_resolution):
    # Allocate buffers for each LOD
    vertex_buffers = []
    indirect_arg_buffers = []
    
    for lod in lods:
        # Calculate active chunks for this LOD
        active_chunks = calculate_active_chunks(lod)
        
        # Allocate AppendStructuredBuffer for triangles
        # Size = voxel_res_x * voxel_res_y * voxel_res_z * active_chunks
        # Each triangle is 96 bytes
        vb = AppendStructuredBuffer(size=lod.voxel_res.x * lod.voxel_res.y * lod.voxel_res.z * active_chunks)
        vertex_buffers.append(vb)
        
        # Allocate Indirect Arg Buffer (5 uints)
        # Initial: {3, 1, 0, 0, 0}
        iab = ComputeBuffer(size=5, type=uint)
        iab.set_data([3, 1, 0, 0, 0])
        indirect_arg_buffers.append(iab)
        
    return vertex_buffers, indirect_arg_buffers

def calculate_mesh(chunk_index, voxel_buffer, voxel_size, voxel_resolution, chunk_center_ws, lod):
    # Get vertex buffer for this LOD
    vertex_buffer = vertex_buffers[lod.lod - 1]
    
    # Reset counter for new frame
    vertex_buffer.set_counter_value(0)
    
    # Dispatch Marching Cubes Compute Shader
    # Thread group: 4x4x4
    dispatch_groups = ceil(voxel_resolution / 4)
    
    marching_cubes_shader.set_buffer(0, "g_Tris", vertex_buffer)
    marching_cubes_shader.set_ints("Dims", voxel_resolution)
    marching_cubes_shader.set_float("Scale", voxel_size)
    marching_cubes_shader.set_float("Isovalue", 0.0)
    marching_cubes_shader.set_floats("HalfVoxelOffset", voxel_size * -0.5, voxel_size * -0.5, voxel_size * -0.5)
    marching_cubes_shader.set_floats("chunkCenter", chunk_center_ws.x, chunk_center_ws.y, chunk_center_ws.z)
    marching_cubes_shader.set_buffer(0, "TriangleTable", triangle_table_buffer)
    marching_cubes_shader.set_buffer(0, "Voxels", voxel_buffer)
    
    marching_cubes_shader.dispatch(0, dispatch_groups.x, dispatch_groups.y, dispatch_groups.z)

def build_lod(lod):
    indirect_args_buffer = indirect_arg_buffers[lod.lod - 1]
    vertex_buffer = vertex_buffers[lod.lod - 1]
    
    # Copy triangle count from append buffer to indirect args
    # This requires a copy operation or a compute shader to read the append counter
    copy_triangle_count_to_indirect_args(vertex_buffer, indirect_args_buffer)
    
    # Dispatch helper to multiply args[0] by 3 and args[1] by 1
    indirect_argument_setter.dispatch(0, 1, 1, 1)
    
    # Create indirect draw call
    indirect_draw_call = {
        "tris": vertex_buffer,
        "args": indirect_args_buffer,
        "material": terrain_material,
        "trs": identity_matrix
    }
    
    # Enqueue for rendering
    gpu_indirect_draw_registry.add(indirect_draw_call)
    
    # Reset counter for next frame
    vertex_buffer.set_counter_value(0)

def vertex_shader(vertex):
    # Fetch vertex from triangle structure
    if vertex.corner_index == 0:
        pos = vertex.t.v0.posWS
        normal = vertex.t.v0.nrmWS
    elif vertex.corner_index == 1:
        pos = vertex.t.v1.posWS
        normal = vertex.t.v1.nrmWS
    else:
        pos = vertex.t.v2.posWS
        normal = vertex.t.v2.nrmWS
        
    # Transform to clip space
    clip_pos = transform_world_to_hclip(pos)
    return clip_pos, normal

def fragment_shader(normal):
    # Normalize normal
    n = normalize(normal)
    
    # View direction (assuming camera at origin looking down -Z or similar, 
    # but typically V is derived from view matrix)
    # If dot(N, V) < 0, flip N
    if dot(n, view_direction) < 0:
        n = -n
        
    # Lambertian lighting
    light_dir = float3(1, 1, 0)
    light_dir = normalize(light_dir)
    
    diff = dot(n, light_dir)
    # Interpolate between 0.25 and 1.0
    color = lerp(0.25, 1.0, diff)
    return color
```

**Parameters:**
*   **Shader Target:** 4.5.
*   **Isovalue:** 0.0f.
*   **HalfVoxelOffset:** $\text{voxelSize} \times -0.5f$.
*   **Triangle Size:** 96 bytes.

**Edge Cases and Pitfalls:**
*   **Voxel Resolution:** Must be odd. Even resolutions trigger a validation error and break the pipeline [S1, unofficial].
*   **Chunk Dimensions:** Must be cube-like ($x == y == z$). Non-cubic chunks trigger a validation error [S1, unofficial].
*   **Precision:** The use of `ulong` for the triangle table suggests 64-bit indexing or packed data, ensuring robust lookup for all 256 cases.

### [Marching Cubes Chunk Generation Pipeline](3925-marching-cubes-chunk-generation-pipeline.md)
This method is a procedural terrain generation pipeline that divides a 3D volume into overlapping chunks, populates them with noise-derived node values, and prepares chunk meshes for Marching Cubes surface extraction. It builds on [GPU Marching Cubes Terrain Pipeline with Indirect Rendering](3803-gpu-marching-cubes-terrain-pipeline-with-indirect-rendering.md) by handling the CPU-side data preparation and chunk management required for the GPU-accelerated extraction. Unlike single-volume extraction, this approach manages spatial locality and boundary continuity through overlapping node grids, ensuring seamless transitions between adjacent chunks.

## Operating characteristics
*   **Time Complexity:** The compute shader dispatch is $O(V)$ where $V$ is the number of voxels in the active chunks. The indirect rendering setup is $O(1)$ per LOD level.
*   **Memory Complexity:** Memory scales linearly with voxel volume and active chunks per LOD: $O(\text{VoxelResolution}_x \times \text{VoxelResolution}_y \times \text{VoxelResolution}_z \times \text{activeChunks})$. Each triangle consumes 96 bytes in the append buffer [S1, unofficial].
*   **Performance:** RenderThread time is low (~1.5ms) due to the avoidance of CPU-GPU synchronization and mesh copying [S1, unofficial].
*   **Strengths:** High performance on GPU, suitable for real-time terrain generation, supports multiple LODs.
*   **Limitations:** Requires custom physics/collision solutions since the mesh is not available on the CPU [S1, unofficial]. Strict constraints on voxel resolution (odd) and chunk shape (cube).

## Background
This method is implemented in Unity terrain rendering pipelines using ComputeShader for surface extraction and GpuIndirectDrawRegistry for batched rendering [S1, unofficial]. It is a modification of Keijiro's GPU Marching Cubes, adapted for indirect rendering to improve performance in a game engine context [S1, unofficial].
