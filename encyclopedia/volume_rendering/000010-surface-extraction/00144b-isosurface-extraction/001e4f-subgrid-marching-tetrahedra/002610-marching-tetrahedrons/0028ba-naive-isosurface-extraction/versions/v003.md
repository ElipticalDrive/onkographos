# Naive Isosurface Extraction

Also called: Simple Isosurface Extraction, Naive Tetrahedral Surfacing (variant)

## Overview
Naive Isosurface Extraction is a surface extraction algorithm that processes each tetrahedron independently to generate a collection of individual, unconnected polygons [S1, unofficial]. It differs from standard Marching Tetrahedra by iterating through all pairs of sample points to find intersections with an isosurface, rather than using the standard 14-case lookup table based on vertex signs [S1, unofficial]. This approach builds on [Marching Tetrahedrons](3720-marching-tetrahedrons.md) by operating on the tetrahedral subgrid structure.

## How it works
**Inputs:**
- A tetrahedral mesh (input tet-mesh) containing $N$ tetrahedra.
- A scalar field defined at the vertices of the mesh.
- A scalar isovalue $f_{iso}$ defining the level set.

**Outputs:**
- A polygonal surface representation (e.g., `vtkPolyData` or `vtkUnstructuredGrid`) consisting of a list of vertices and a list of polygons.

**Data Structures:**
- **Input Tetrahedron:** Defined by 4 vertex indices $(v_0, v_1, v_2, v_3)$ and associated scalar values $(f_0, f_1, f_2, f_3)$.
- **Output Points:** A dynamic list of 3D coordinates.
- **Output Cells:** A dynamic list of polygons, where each polygon is defined by a list of vertex indices into the Output Points list.

**Algorithm Steps:**

1.  **Initialize Output:** Create empty lists for output vertices and polygons.
2.  **Loop over Tetrahedra:** For each tetrahedron $T_i$ in the input mesh:
    a.  **Check Intersection:** Call `IsCellOnLevelSet(T_i, f_{iso})`.
        -   Retrieve scalar values $f_j$ for all vertices $v_j$ of $T_i$.
        -   Determine if the level set intersects $T_i$. A tetrahedron is intersected if the scalar values at its vertices are not all strictly greater than $f_{iso}$ and not all strictly less than $f_{iso}$. Formally, if $\min(f_j) \le f_{iso} \le \max(f_j)$. [S1, unofficial]
        -   If not intersected, continue to the next tetrahedron.
    b.  **Compute Intersection Polygon:** Call `ComputeSimpleIntersection(T_i, f_{iso})`.
        -   Initialize an empty list `pointIds` to store vertex indices of the resulting polygon.
        -   **Loop over Edges:** Iterate through all 6 edges of the tetrahedron. Each edge connects two vertices $v_a$ and $v_b$ with scalars $f_a$ and $f_b$.
        -   **Check Edge Intersection:** For each edge, call `IsCellOnLevelSet(edge, f_{iso})`.
            -   An edge is intersected if $(f_a - f_{iso}) \times (f_b - f_{iso}) < 0$. [G] (Note: Strict inequality assumes non-degenerate cases where $f \neq f_{iso}$ at vertices. If $f=f_{iso}$, special handling is required, but the naive approach typically ignores or handles arbitrarily).
        -   **Compute Intersection Point:** If the edge is intersected, call `ComputeEdgeIntersection(edge, f_{iso})`.
            -   Calculate the intersection point $P$ using linear interpolation:
                $$ P = v_a + \frac{f_{iso} - f_a}{f_b - f_a} (v_b - v_a) $$
            -   Add $P$ to the Output Points list. Let the returned index be $idx$.
            -   Append $idx$ to `pointIds`.
        -   **Order Vertices:** The vertices in `pointIds` must be ordered to form a consistent winding around the tetrahedron to avoid visual artifacts like cracks. Call `ReOrderTetEdges(pointIds, T_i)`.
            -   This step reorders the vertex indices such that they form a continuous loop. [S1, unofficial]
        -   **Insert Polygon:** Call `Output->InsertNextCell(VTK_POLYGON, pointIds)`.
3.  **Finalize:** Return the constructed output surface.

**Pseudocode:**

```python
def naive_isosurface_extraction(tet_mesh, scalar_field, isovalue):
    """
    Extracts isosurface from a tetrahedral mesh using the naive approach.
    
    Args:
        tet_mesh: List of tetrahedra, each defined as [v0, v1, v2, v3] (vertex indices).
        scalar_field: Array of scalar values indexed by vertex index.
        isovalue: The scalar value defining the isosurface.
        
    Returns:
        output_points: List of 3D coordinates.
        output_polys: List of polygons, each defined as a list of vertex indices.
    """
    output_points = []
    output_polys = []
    
    # Helper: Check if a cell (edge or tet) is intersected by the level set
    def is_cell_on_level_set(cell_vertices, isovalue):
        """
        Returns True if the cell is traversed by the level set.
        cell_vertices: List of vertex indices.
        """
        scalars = [scalar_field[v] for v in cell_vertices]
        min_s = min(scalars)
        max_s = max(scalars)
        # Intersects if isovalue is between min and max (inclusive)
        return min_s <= isovalue <= max_s

    # Helper: Compute intersection point on an edge
    def compute_edge_intersection(v0, v1, f0, f1, isovalue):
        """
        Computes the 3D point where the edge intersects the isovalue.
        v0, v1: 3D coordinates of edge endpoints.
        f0, f1: Scalar values at endpoints.
        """
        # Linear interpolation
        # t = (isovalue - f0) / (f1 - f0)
        # P = v0 + t * (v1 - v0)
        # Guard against division by zero if f0 == f1
        if abs(f1 - f0) < 1e-10:
            return (v0[0] + v1[0]) / 2.0, (v0[1] + v1[1]) / 2.0, (v0[2] + v1[2]) / 2.0
        
        t = (isovalue - f0) / (f1 - f0)
        x = v0[0] + t * (v1[0] - v0[0])
        y = v0[1] + t * (v1[1] - v0[1])
        z = v0[2] + t * (v1[2] - v0[2])
        return (x, y, z)

    # Helper: Reorder vertices to form a consistent winding
    def reorder_tet_edges(point_ids, tet_vertices):
        """
        Reorders point_ids to form a consistent loop around the tetrahedron.
        This is a placeholder for the specific logic described in [S1, unofficial].
        In practice, this involves traversing the edges of the tetrahedron
        that are intersected and ordering the resulting vertices sequentially.
        """
        # The naive implementation often fails here, leading to cracks.
        # A correct implementation would map the intersected edges to a cycle.
        # For the purpose of this "Naive" definition, we assume a basic reorder
        # or no reorder if the source implies the naive version lacks this.
        # However, [S1, unofficial] mentions ReOrderTetEdges fixes cracks, so it is part of the 
        # "Simple" implementation which is still naive in terms of vertex duplication.
        return point_ids

    # Main Loop
    for tet in tet_mesh:
        v0, v1, v2, v3 = tet
        scalars = [scalar_field[v0], scalar_field[v1], scalar_field[v2], scalar_field[v3]]
        
        # Check if tetrahedron is intersected
        if not is_cell_on_level_set(tet, isovalue):
            continue
            
        # Compute intersection polygon
        point_ids = []
        
        # Define edges of the tetrahedron
        edges = [
            (v0, v1), (v0, v2), (v0, v3),
            (v1, v2), (v1, v3),
            (v2, v3)
        ]
        
        for v_a, v_b in edges:
            f_a = scalar_field[v_a]
            f_b = scalar_field[v_b]
            
            # Check if edge is intersected
            # Edge intersects if signs of (f - isovalue) are different
            if (f_a - isovalue) * (f_b - isovalue) < 0:
                # Compute intersection point
                p_a = get_vertex_coordinates(v_a) # Assume helper to get 3D pos
                p_b = get_vertex_coordinates(v_b)
                
                p_intersect = compute_edge_intersection(p_a, p_b, f_a, f_b, isovalue)
                
                # Add to output points
                idx = len(output_points)
                output_points.append(p_intersect)
                point_ids.append(idx)
        
        # Reorder vertices for consistent winding
        # Note: The naive approach may still have issues if this step is not robust.
        point_ids = reorder_tet_edges(point_ids, tet)
        
        # Insert polygon
        output_polys.append(point_ids)

    return output_points, output_polys
```

**Parameters:**
- `isovalue`: The scalar threshold. Typical values depend on the dataset.
- `tolerance`: Not explicitly defined in the naive source, but precision issues with floating-point comparisons in `is_cell_on_level_set` can cause cracks [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Duplicate Vertices:** The naive approach creates a new vertex for every intersection on every tetrahedron. Shared edges between tetrahedra result in duplicate vertices at the same location, leading to non-manifold surfaces and cracks [S1, unofficial].
- **Inconsistent Winding:** If the order of vertices in the generated polygon is inconsistent, visual artifacts like cracks appear [S1, unofficial].
- **Performance:** The approach is slow compared to optimized implementations because it does not reuse vertex data and may perform redundant calculations [S1, unofficial].

## Subtopics

### Adaptive Octree Marching Tetrahedra
Adaptive Octree Marching Tetrahedra is a variant that uses an adaptive octree structure to refine the mesh only where necessary, reducing the number of tetrahedra processed. It differs from Naive Isosurface Extraction by dynamically adjusting resolution based on scalar field gradients, rather than processing a uniform or pre-defined tetrahedral mesh. Choose this when high-resolution details are localized and computational resources are limited. [Link to sibling article](3897-adaptive-octree-marching-tetrahedra.md).

### [Naive Tetrahedral Surfacing](6833-naive-tetrahedral-surfacing.md)
Naive Tetrahedral Surfacing is an isosurface extraction method that processes each tetrahedron independently to generate a collection of individual, unconnected polygons. It differs from standard Marching Tetrahedra by iterating through all pairs of sample points to find intersections with an isosurface, rather than using the standard 14-case lookup table based on vertex signs. This approach builds on [Naive Isosurface Extraction](4328-naive-isosurface-extraction.md) by operating on the tetrahedral subgrid structure. ## Operating characteristics
- **Time Complexity:** $O(N \cdot E)$, where $N$ is the number of tetrahedra and $E$ is the number of edges per tetrahedron (constant 6). However, due to the lack of vertex reuse and potential inefficiencies in polygon construction, it is significantly slower than optimized methods [S1, unofficial].
- **Memory Complexity:** $O(V_{out} + F_{out})$, where $V_{out}$ is the number of output vertices and $F_{out}$ is the number of output polygons. Since vertices are duplicated, $V_{out}$ can be up to 6 times larger than necessary for a manifold surface.
- **Measured Performance:** The naive implementation is notably slower than VTK's optimized implementation, as noted in the exercise comparison [S1, unofficial].
- **Strengths:** Simple to implement; no complex data structures for neighbor lookup or vertex merging required.
- **Limitations:** Produces non-manifold surfaces with cracks due to duplicate vertices and inconsistent winding. Not suitable for applications requiring manifold connectivity or efficient rendering.
- **When to Use:** Educational purposes or simple visualization where manifold connectivity is not critical.
- **When Not to Use:** Production rendering, simulation, or any application requiring manifold surfaces or high performance.
