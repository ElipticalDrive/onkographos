# Sparse Marching Cubes

Also called: Sparse Marching Cubes from Points

## Overview
Sparse Marching Cubes generates a triangle mesh from a sparse set of 3D points with associated scalar values (e.g., Signed Distance Fields), avoiding the memory overhead of dense 3D grids [S1, unofficial]. It differs from standard Marching Cubes by dynamically gathering corner values for active voxels via lookup, rather than iterating over a fixed dense volume [S1, unofficial].

## How it works
**Inputs:**
1.  `coords`: Integer tensor of shape $[N, 3]$ containing the $(x, y, z)$ coordinates of active voxels or points.
2.  `corners` OR `point_values`:
    *   Option A: `corners` Float tensor of shape $[N, 8]$ containing pre-computed scalar values at the 8 corners of each voxel.
    *   Option B: `point_values` Float tensor of shape $[N]$ or $[N, 1]$ containing scalar values at the coordinates in `coords`.
3.  `iso`: Float value representing the iso-level threshold.
4.  `default_value`: Float value assumed for corner points not present in the input set (typically $1.0$ for SDFs, indicating "outside") [S1, unofficial].
5.  `ensure_consistency`: Boolean flag; if `True`, averages corner values at shared locations to ensure topological consistency [S1, unofficial].

**Outputs:**
1.  `verts`: Float tensor of shape $[V, 3]$ with vertex positions.
2.  `tris` (or `faces`): Int tensor of shape $[T, 3]$ with triangle indices [S1, unofficial].

**Data Structures:**
*   The method operates on a list of active voxels defined by integer coordinates.
*   Corner values are stored in a dense tensor $[N, 8]$ for the direct input mode, or gathered on-the-fly for the point input mode.

**Steps:**

1.  **Input Validation and Preparation:**
    *   Ensure `coords` and `corners` (or `point_values`) have the same number of elements $N$ [S1, unofficial].
    *   Move tensors to the target device (e.g., CUDA) and ensure they are contiguous [S1, unofficial].
    *   Cast `coords` to integer and `corners`/`point_values` to float [S1, unofficial].

2.  **Corner Value Gathering (if using `sparse_marching_cubes_from_points`):**
    *   If input is `point_values` (shape $[N]$) rather than `corners` (shape $[N, 8]$), the algorithm must construct the corner values for each voxel.
    *   For each voxel $i$ at `coords[i]`, identify its 8 corner coordinates:
        $$ C_{ijk} = \text{coords}[i] + (i, j, k) \quad \text{for } i,j,k \in \{0, 1\} $$
    *   Look up the scalar value for each corner coordinate in the input `point_values` set.
    *   If a corner coordinate exists in `coords`, use its corresponding `point_values` entry.
    *   If a corner coordinate does not exist, use `default_value` [S1, unofficial].
    *   Store the resulting 8 values in a tensor `corners` of shape $[N, 8]$.

3.  **Consistency Enforcement (Optional):**
    *   If `ensure_consistency` is `True`, identify shared corner coordinates among adjacent active voxels.
    *   Average the scalar values assigned to these shared corners across all voxels that share them. This prevents topological artifacts caused by inconsistent scalar assignments at shared vertices [S1, unofficial].

4.  **Case Index Calculation:**
    *   For each voxel $i$, determine the marching cubes case index based on its 8 corner values $v_0, \dots, v_7$ and the iso-level `iso`.
    *   Compute a binary mask for each corner:
        $$ b_k = \begin{cases} 1 & \text{if } v_k < \text{iso} \\ 0 & \text{otherwise} \end{cases} $$
    *   Calculate the case index $I_i$ as a weighted sum:
        $$ I_i = \sum_{k=0}^{7} b_k \cdot 2^k $$
    *   This results in an integer tensor of shape $[N]$ containing the case index for each voxel [S1, unofficial].

5.  **Mesh Generation:**
    *   For each voxel, use the standard Marching Cubes lookup table (or equivalent logic) to determine which edges are intersected by the isosurface based on $I_i$.
    *   Interpolate vertex positions on the intersected edges.
    *   Generate triangles connecting these interpolated vertices.
    *   Handle vertex merging to ensure a watertight mesh. If `ensure_consistency` was used, shared vertices are already averaged; otherwise, standard vertex merging based on spatial proximity is applied [S1, unofficial].

6.  **Output Assembly:**
    *   Collect all generated vertices into `verts` $[V, 3]$.
    *   Collect all generated triangles into `tris` $[T, 3]$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of active voxels $N$ and the complexity of the lookup/gathering step. The gathering step is $O(N)$ with an efficient hash map or sorted array. The Marching Cubes step is $O(N)$ as it processes each active voxel once.
*   **Memory Complexity:** $O(N)$ for storing coordinates, corner values, and the resulting mesh. This is significantly lower than dense Marching Cubes, which requires $O(V_x V_y V_z)$ memory for the volume grid.
*   **Performance:** The method is typically implemented on GPUs (CUDA) to leverage parallelism for thousands of voxels simultaneously [S1, unofficial].
*   **Strengths:**
    *   Memory efficient for sparse data.
    *   No need to allocate dense 3D grids.
    *   High performance on GPUs.
*   **Limitations:**
    *   Requires careful handling of shared corners to ensure topological consistency (`ensure_consistency` flag).
    *   Performance may degrade if the sparse set is very dense, approaching the cost of dense methods.
    *   Dependent on the quality of the `default_value` for missing corners.

## Background
Sparse Marching Cubes is an adaptation of the classic Marching Cubes algorithm designed for sparse data structures. It is particularly useful in applications involving sparse Signed Distance Fields (SDFs) or point-based representations where the domain is not uniformly sampled. The method described here is implemented in the `spcumc` library, which provides CUDA-accelerated implementations for both triangle and quad mesh generation from sparse voxel data [S1, unofficial].
