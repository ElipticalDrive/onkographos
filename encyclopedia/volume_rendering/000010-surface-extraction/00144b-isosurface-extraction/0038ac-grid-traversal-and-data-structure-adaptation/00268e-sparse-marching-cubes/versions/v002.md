# Sparse Marching Cubes

Also called: Sparse Marching Cubes from Points

## Overview
Sparse Marching Cubes generates a triangle mesh from a sparse set of 3D points with associated scalar values (e.g., Signed Distance Fields), avoiding the memory overhead of dense 3D grids [S1, unofficial]. It differs from standard Marching Cubes by dynamically gathering corner values for active voxels via lookup, rather than iterating over a fixed dense volume [S1, unofficial].

## How it works
**Inputs:**
1.  `coords`: Integer tensor of shape $[N, 3]$ containing the $(x, y, z)$ coordinates of the active voxels (or points defining the scalar field).
2.  `point_values` (or `sdfs`): Float tensor of shape $[N]$ or $[N, 1]$ containing the scalar value at each coordinate in `coords`.
3.  `iso`: Float value representing the iso-level to contour at.
4.  `default_value`: Float value assumed for corner points not present in the input `coords`. This value must be known to be completely inside or outside the surface relative to the iso-level [S1, unofficial]. Default is 1.0.
5.  `ensure_consistency`: Boolean flag; if True, averages corner values at shared locations to ensure topological consistency in the generated mesh [S1, unofficial].

**Outputs:**
1.  `verts`: Float tensor of shape $[V, 3]$ with vertex positions.
2.  `tris` (or `faces`): Int tensor of shape $[T, 3]$ or $[K, 3]$ with triangle indices (int32) [S1, unofficial].

**Data Structures:**
The method operates on a sparse representation. Instead of a dense 3D array, it maintains a list of active voxel coordinates and their associated scalar values. For the `sparse_marching_cubes_from_points` variant, it implicitly constructs the 8 corner values for each voxel by querying the input point set.

**Algorithm Steps:**

1.  **Input Validation and Preparation:**
    Ensure `coords` and `point_values` are contiguous tensors on the target device (typically CUDA GPU) [S1, unofficial]. Convert `coords` to integer type and `point_values` to float type [S1, unofficial].

2.  **Corner Value Gathering (Implicit for `from_points`):**
    For each active voxel coordinate $c_i = (x_i, y_i, z_i)$ in `coords`:
    a. Identify the 8 corner coordinates of the voxel. These are $(x_i \pm 1, y_i \pm 1, z_i \pm 1)$ relative to the voxel's position, depending on the specific grid convention. *Note: The source implies the input `coords` are the points with defined scalar values, and the method gathers the 8 corners for each voxel defined by these points. If the input is `coords` and `point_values`, the corners are derived from the voxel grid structure implied by the coordinates.*
    b. For each corner, check if its coordinate exists in the input `coords`.
    c. If the corner exists, retrieve its scalar value from `point_values`.
    d. If the corner does not exist, assign `default_value` [S1, unofficial].
    e. Store the 8 corner values in a tensor `corners` of shape $[N, 8]$ for each active voxel [S1, unofficial].

3.  **Case Index Calculation:**
    For each voxel with corner values $v_0, \dots, v_7$:
    Calculate the binary case index $I$ using the formula:
    $$ I = \sum_{j=0}^{7} b_j 2^j $$
    where $b_j = 1$ if $v_j < \text{iso}$, and $b_j = 0$ otherwise [S1, unofficial].
    *Note: The bit ordering in the source code is specific: $b_0$ corresponds to corner 0, $b_1$ to corner 1, etc., with weights $1, 2, 4, \dots, 128$ [S1, unofficial].*

4.  **Mesh Generation:**
    For each voxel, use the standard Marching Cubes lookup table (or equivalent logic) based on the case index $I$ to determine the set of edges intersected by the isosurface.
    a. Interpolate the intersection points on the edges. The interpolation position $p$ on an edge between corners with values $v_a$ and $v_b$ is calculated as:
    $$ p = \frac{\text{iso} - v_a}{v_b - v_a} $$
    b. Generate triangles from the intersection points according to the case configuration.
    c. If `ensure_consistency` is True, average the scalar values at shared vertices across adjacent voxels before interpolation to ensure consistent mesh topology [S1, unofficial].

5.  **Vertex and Face Assembly:**
    Collect all generated vertices and triangles. Handle vertex merging to ensure watertightness and avoid duplicates. The output is a list of unique vertices and triangle indices [S1, unofficial].

**Pseudocode:**

```python
def sparse_marching_cubes_from_points(coords, point_values, iso, default_value=1.0, ensure_consistency=False):
    """
    Performs sparse marching cubes from a sparse set of points.
    
    Args:
        coords: Tensor of shape [N, 3], integer coordinates of points.
        point_values: Tensor of shape [N], scalar values at points.
        iso: Float, iso-level.
        default_value: Float, value for missing corners.
        ensure_consistency: Bool, average corner values for consistency.
        
    Returns:
        verts: Tensor of shape [V, 3], vertex positions.
        tris: Tensor of shape [T, 3], triangle indices.
    """
    # 1. Prepare inputs
    # Ensure tensors are on GPU and contiguous
    coords = coords.int().contiguous()
    point_values = point_values.float().contiguous()
    
    # 2. Gather corner values for each voxel
    # The input coords are treated as the centers or defining points of active voxels.
    # We need to find the 8 corners for each voxel.
    # Let's assume coords are voxel centers or grid points. 
    # The source implies coords are the points with defined scalar values.
    # We need to map corner coordinates to values.
    
    # Create a hash map or lookup structure for fast corner value retrieval
    # Key: (x, y, z), Value: scalar
    corner_lookup = {}
    for i in range(coords.shape[0]):
        corner_lookup[(coords[i, 0].item(), coords[i, 1].item(), coords[i, 2].item())] = point_values[i].item()
        
    N = coords.shape[0]
    corners = torch.zeros((N, 8), dtype=torch.float32)
    
    for i in range(N):
        x, y, z = coords[i, 0].item(), coords[i, 1].item(), coords[i, 2].item()
        # Define the 8 corners of the voxel. 
        # Note: The exact definition of "voxel" relative to "coords" is critical.
        # In many sparse MC implementations, coords are the grid points where SDF is known.
        # A voxel is defined by 8 such points. 
        # However, the source says "coords... coordinates of the active voxels".
        # This suggests coords are voxel centers or IDs. 
        # Let's assume the standard interpretation: coords are the locations of the scalar values.
        # To define a voxel, we need 8 scalar values. 
        # The source code `sparse_marching_cubes_from_points` takes `coords` and `point_values`.
        # It then "gathers the 8 corner values required for each voxel".
        # This implies the input `coords` are the voxel centers, and we need to find the 8 surrounding grid points?
        # Or, more likely, `coords` are the grid points, and we are marching cubes on the cells defined by them.
        # But Marching Cubes operates on cells. If `coords` are sparse, we only process cells where all 8 corners are present?
        # No, the source says "If a corner does not exist... a default value is used."
        # This implies we iterate over a set of voxels. What defines these voxels?
        # The source says "coords... coordinates of the active voxels".
        # So, `coords` are the voxel centers (or IDs). We need to find the 8 corners of each voxel.
        # The corners are at (x-1, y-1, z-1) to (x+1, y+1, z+1) if coords are integer grid indices.
        
        # Let's assume coords are integer grid indices of the voxel centers.
        # The 8 corners of voxel i at (x,y,z) are:
        corners_coords = [
            (x-1, y-1, z-1), (x, y-1, z-1), (x-1, y, z-1), (x, y, z-1),
            (x-1, y-1, z), (x, y-1, z), (x-1, y, z), (x, y, z)
        ]
        
        for j, (cx, cy, cz) in enumerate(corners_coords):
            if (cx, cy, cz) in corner_lookup:
                corners[i, j] = corner_lookup[(cx, cy, cz)]
            else:
                corners[i, j] = default_value
                
    # 3. Calculate case indices
    # v < iso -> 1, else 0
    v = corners.float()
    cube_indices = (v < iso).int()
    cube_indices = (
        cube_indices[:, 0] * 1 |
        cube_indices[:, 1] * 2 |
        cube_indices[:, 2] * 4 |
        cube_indices[:, 3] * 8 |
        cube_indices[:, 4] * 16 |
        cube_indices[:, 5] * 32 |
        cube_indices[:, 6] * 64 |
        cube_indices[:, 7] * 128
    ).int()
    
    # 4. Generate mesh
    # This step is implemented in the C++/CUDA backend.
    # It uses the standard Marching Cubes algorithm with the calculated case indices.
    # If ensure_consistency is True, it averages corner values at shared locations.
    
    # Pseudocode for the backend call:
    verts, tris = _backend.sparse_marching_cubes(coords, corners, iso, ensure_consistency)
    
    return verts, tris
```

**Edge Cases and Pitfalls:**
*   **Missing Corners:** If a corner is not in the input point set, `default_value` is used. This value must be chosen such that it does not create spurious surface intersections. For SDFs, a large positive value (outside) or negative value (inside) is appropriate [S1, unofficial].
*   **Consistency:** Without `ensure_consistency`, shared vertices between adjacent voxels may have slightly different interpolated positions due to different corner value averages, leading to non-watertight meshes or artifacts [S1, unofficial].
*   **Precision:** Floating-point precision in interpolation and comparison with `iso` can affect mesh topology.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of active voxels $N$, assuming constant-time lookup for corner values. The CUDA implementation leverages parallelism to process thousands of voxels simultaneously [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of active voxels and their corner values. Significantly lower than dense Marching Cubes for sparse data, as it avoids storing values for empty space [S1, unofficial].
*   **Performance:** High performance on NVIDIA GPUs due to CUDA acceleration. Suitable for real-time applications with sparse SDF data [S1, unofficial].
*   **Strengths:** Memory efficiency for sparse data, ease of use with point-based SDF representations, GPU acceleration.
*   **Limitations:** Requires careful selection of `default_value`. Topological consistency requires additional processing (`ensure_consistency`). Not suitable for dense data where the overhead of sparse structures outweighs the benefits.

## Background
Sparse Marching Cubes is an adaptation of the classic Marching Cubes algorithm designed for sparse data structures. It is particularly useful in applications involving sparse Signed Distance Fields (SDFs) or point cloud-based surface reconstruction, where the scalar field is only defined at a limited set of points. The method was popularized by libraries such as `spcumc` for efficient GPU-based mesh generation from sparse inputs [S1, unofficial].
