# Adaptive Marching Cubes

Also called: AR Isosurface Algorithm, Adaptive Marching Cubes on Multiresolution Octree, Adaptive Marching Cubes on Octree

## Overview
Adaptive Marching Cubes is an extension of the standard Marching Cubes algorithm designed to extract isosurfaces from Adaptive Resolution (AR) octree data [S1, unofficial]. It solves the problem of topological inconsistencies and geometric artifacts that arise when adjacent cubes in the mesh have different resolutions [S1, unofficial]. It handles missing vertices and isosurface discontinuities by deferring the processing of coarser nodes that conflict with finer neighbors, ensuring consistent triangle vertex interpolation across resolution boundaries [S1, unofficial]. Builds on [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) and differs from [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md) and [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md) by using a two-pass octree traversal with deferred vertex lists.

## How it works
The algorithm performs two passes over the octree to resolve inconsistencies between adjacent cells of differing resolutions [S1, unofficial].

### Inputs and Outputs
*   **Input:** An adaptive resolution octree representing a volume dataset [S1, unofficial].
*   **Output:** A triangle mesh representing the isosurface [S1, unofficial].

### Data Structures
Each octree node maintains the following fields:
1.  **Triangle List:** A list of triangles generated for this node [S1, unofficial].
2.  **Fine Edge Vertex List:** A per-edge list storing deferred intersection vertices for coarser nodes [S1, unofficial].
3.  **Resolution Level:** The octree depth indicating the node's voxel sampling rate [S1, unofficial].
Exact sizes and bit packing are not given in the sources. A global **Intersection List** serves as a vertex array referenced by triangle lists, storing edge intersection points which may be updated later [S1, unofficial]. A **Second Pass List** holds octree nodes requiring post-processing for subdivision or final triangle generation [S1, unofficial].

### Algorithm Steps
1.  **First Pass:** Traverse all cubes in the AR representation and generate triangles using the standard MC algorithm [S1, unofficial].
2.  **Handle Missing Vertices:** If a finer cube finds an intersection on an edge but the coarser neighbor has no vertex on that edge (coarse vertices are on the same side of the isosurface), create a new entry in the coarser neighbor's fine edge vertex list [S1, unofficial].
3.  **Queue for Post-Processing:** Add the coarser neighbor node to the Second Pass List [S1, unofficial].
4.  **Second Pass Trigger:** After the entire octree has been processed, process all octree nodes on the Second Pass List [S1, unofficial].
5.  **Subdivision Check:** If a coarser resolution node on the Second Pass List discovers it has two vertices on the same edge of its edge vertex list, subdivide the cube [S1, unofficial].

### Pseudocode
```python
def adaptive_marching_cubes(root_node, isovalue):
    intersection_list = []  # Global vertex array storing edge intersection points
    second_pass_list = []   # List of octree nodes requiring post-processing

    # First Pass: Traverse octree and generate initial triangles
    traverse_octree(root_node, isovalue, intersection_list, second_pass_list)

    # Second Pass: Process deferred nodes
    while second_pass_list:
        node = second_pass_list.pop()
        process_deferred_node(node, isovalue, intersection_list, second_pass_list)

def traverse_octree(node, isovalue, intersection_list, second_pass_list):
    if node.is_leaf():
        # Standard MC lookup table generates triangles referencing intersection_list
        triangles = standard_mc_lookup(node, isovalue, intersection_list)
        node.triangle_list.extend(triangles)
        # Check coarser neighbors for missing vertices
        for edge in node.edges:
            neighbor = node.get_coarser_neighbor(edge)
            if neighbor is not None and not neighbor.has_vertex_on_edge(edge):
                vertex = interpolate_edge(edge, isovalue)
                neighbor.fine_edge_vertices[edge].append(vertex)
                if neighbor not in second_pass_list:
                    second_pass_list.append(neighbor)
    else:
        for child in node.children:
            traverse_octree(child, isovalue, intersection_list, second_pass_list)

def process_deferred_node(node, isovalue, intersection_list, second_pass_list):
    # Check if coarser node has two vertices on the same edge
    for edge, vertices in node.fine_edge_vertices.items():
        if len(vertices) >= 2:
            # Subdivide the coarse cube by interpolating between known cube vertex values
            children = node.subdivide()
            for child in children:
                traverse_octree(child, isovalue, intersection_list, second_pass_list)
            return
    # No conflict: generate triangles using deferred vertices
    triangles = standard_mc_lookup(node, isovalue, intersection_list)
    node.triangle_list.extend(triangles)

def interpolate_edge(edge, isovalue):
    # Linear interpolation between edge vertex values to find isosurface crossing
    t = (isovalue - edge.v1_value) / (edge.v2_value - edge.v1_value)
    return edge.v1 + t * (edge.v2 - edge.v1)
```

### Parameters and Edge Cases
*   **Isosurface Value:** The threshold value for extraction [S1, unofficial].
*   **Missing Vertices:** Occur when a finer cube intersects an edge that a coarser neighbor does not, handled by creating deferred vertices and subdividing the coarser node [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on octree depth and conflict frequency, but unnecessary computation is avoided by skipping large sets of volume data deemed uninteresting [S1, unofficial].
*   **Memory Complexity:** Higher than uniform MC due to the octree structure and deferred vertices, but memory space is saved by leaving uninteresting voxels out of the octree data structure [S1, unofficial].
*   **Strengths:** Efficiently handles large datasets by focusing resolution where needed and produces consistent meshes across resolution boundaries [S1, unofficial].
*   **Limitations:** The two-pass design and potential for frequent subdivision in highly heterogeneous data add implementation complexity and overhead [S1, unofficial].

## Background
The algorithm was implemented by Westermann et al. on multiresolution octree data [S2, unofficial]. It addresses the limitations of standard marching cubes when applied to multiresolution data structures, specifically topological inconsistencies at resolution boundaries [S1, unofficial]. The isosurface generation algorithm is derived from The Visualization Toolkit by Schroeder [S1, unofficial]. It has been cited in subsequent works on implicit surface rendering and interactive visualization [S2, unofficial]. Multiresolution data generation typically samples every other data point in each dimension to build coarser levels, with level 0 being the finest resolution containing a 128^3 representation where each cube contains eight vertices [S1, unofficial].
