# Marching Cubes with Octree


## Overview
Marching Cubes with Octree extracts isosurfaces from scalar fields defined on an adaptive octree domain, combining the topological robustness of the Marching Cubes algorithm with the memory efficiency of hierarchical spatial subdivision. Unlike uniform grid methods, it dynamically refines the domain based on a split predicate, allowing high-resolution detail where the field varies significantly while skipping uniform regions. It sets itself apart from sibling methods like [Transvoxel](6277-transvoxel.md) by relying on a standard lookup-table-based triangulation per cell rather than specialized transition cells, and from [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) by providing a specific domain abstraction (`MC_Domain`) that handles the traversal and vertex interpolation logic internally within the CGAL framework.

## How it works
The method operates by constructing an octree that adapts to the scalar field, then applying the standard Marching Cubes topology to each leaf node. The implementation relies on the CGAL library's `Isosurfacing_3` module.

### Inputs and Outputs
*   **Input:**
    *   `bbox`: A 3D bounding box defined by minimum and maximum points ($P_{min}, P_{max}$).
    *   `split_predicate`: A function $S(C)$ returning true if cell $C$ must be subdivided.
    *   `scalar_function`: A function $f(P)$ returning the scalar value at point $P$.
    *   `isovalue`: The threshold scalar value $I$ for surface extraction.
*   **Output:**
    *   `points`: A container of 3D vertices ($V$).
    *   `triangles`: A container of triangle indices or vertex triplets ($T$).

### Data Structures
The core data structure is the **Octree**. Each node represents a cubic cell.
*   **Node Layout:** The CGAL implementation uses a pointerless or hierarchical structure. The exact internal bit-packing is not specified in the public API documentation, but the logical structure is a tree where each node has up to 8 children.
*   **MC_Domain:** An adapter object that wraps the `Octree` and `scalar_function`. It implements the interface required by the marching cubes algorithm, providing methods to access cell corners and interpolate values on edges.

### Algorithm Steps

1.  **Initialize Bounding Box:** Define the root cell bounds using $P_{min}$ and $P_{max}$.
2.  **Construct Octree:** Create an empty octree rooted at the bounding box.
3.  **Refine Octree:** Recursively traverse and subdivide the octree. For each cell $C$:
    *   Evaluate the `split_predicate` $S(C)$.
    *   If $S(C)$ is true, split $C$ into 8 child cells.
    *   Recurse on children.
    *   If $S(C)$ is false, $C$ becomes a leaf node.
4.  **Create Domain:** Instantiate `MC_Domain` with the refined `octree` and `scalar_function`.
5.  **Execute Marching Cubes:** Call `CGAL::Isosurfacing::marching_cubes` with the `MC_Domain`, `isovalue`, and output containers.
    *   The algorithm iterates over all leaf nodes.
    *   For each leaf, it determines the intersection of the isosurface with the cell edges.
    *   It generates triangles based on the standard 256 Marching Cubes cases (normalized to 15 unique cases via symmetry).
    *   Vertices are interpolated linearly along edges where the scalar function changes sign across the isovalue.
6.  **Merge Vertices:** The domain abstraction handles vertex sharing between adjacent cells to ensure a watertight mesh, provided the octree refinement is consistent (see Pitfalls).

### Pseudocode

```python
# Pseudocode representing the logical flow of the CGAL implementation
# Note: This is a high-level representation of the C++ API usage.

def run_marching_cubes_octree(bbox_min, bbox_max, split_predicate, scalar_func, isovalue):
    """
    bbox_min: Point3 (xmin, ymin, zmin)
    bbox_max: Point3 (xmax, ymax, zmax)
    split_predicate: Function(Cell) -> bool
    scalar_func: Function(Point3) -> float
    isovalue: float
    """
    
    # 1. Initialize Octree
    # The octree is initialized with the root bounding box
    octree = Octree()
    octree.set_root_bounds(bbox_min, bbox_max)
    
    # 2. Refine the Octree
    # The refinement is typically done via a recursive function or a queue-based approach
    # defined by the split_predicate.
    refine_octree(octree.root, split_predicate, scalar_func)
    
    # 3. Prepare Domain and Output Containers
    # MC_Domain wraps the octree and the scalar function
    domain = MC_Domain(octree, scalar_func)
    
    points = []      # List of Point3
    triangles = []   # List of Triangle (indices or vertices)
    
    # 4. Execute Marching Cubes
    # This function traverses the leaf nodes of the octree
    # and populates points and triangles.
    # It uses parallel execution if available.
    marching_cubes(domain, isovalue, points, triangles)
    
    return points, triangles

def refine_octree(node, split_predicate, scalar_func):
    """
    Recursively subdivides the octree node based on the predicate.
    """
    if split_predicate(node):
        # Split the node into 8 children
        children = node.split()
        
        # Recurse on each child
        for child in children:
            refine_octree(child, split_predicate, scalar_func)
    else:
        # Node is a leaf, do not subdivide
        pass
```

### Parameters and Typical Values
*   **Isovalue:** Depends on the scalar field. For signed distance fields, it is typically $0$. For density fields, it is often a small positive threshold (e.g., $0.3$ in CGAL examples).
*   **Split Predicate:** Common predicates include:
    *   `Refine_one_eighth`: Refines if the cell contains the isovalue and has a certain size constraint.
    *   `Refine_around_isovalue`: Refines based on the gradient or value variation near the isovalue.
*   **Parallelism:** The CGAL implementation supports `Parallel_if_available_tag`, enabling multi-threaded traversal.

### Edge Cases and Pitfalls
*   **Cracks at Level Boundaries:** If the octree has varying depths around the isosurface (i.e., a fine cell is adjacent to a coarse cell), standard Marching Cubes will produce cracks (non-manifold edges) because the coarse cell's edge is not subdivided to match the fine cell's vertices. The method "behaves well" only if nodes are split with uniform size around the surface or if a post-processing step merges vertices across level boundaries.
*   **Discontinuous Density Fields:** In sparse voxel implementations, if adjacent voxels belong to different octree levels, the density field may not be continuous, leading to disconnected triangles. Subdividing all voxels to the finest level removes these discontinuities but increases memory usage.

## Subtopics

### [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md)
Linear Hashed Marching Cubes extracts triangle meshes from implicit scalar fields by applying the Marching Cubes algorithm over a linear hashed octree. It replaces the standard grid-based traversal with a pointerless octree structure to reduce memory overhead and improve performance. It builds on [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) but uses a linear hash table for node storage instead of a primal grid.

### [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md)
This method extracts isosurfaces from adaptive resolution (AR) octree volume data by decoupling geometry generation from discontinuity resolution. It solves the topological inconsistencies that arise when fine-resolution cubes share edges or faces with coarser, unsubdivided neighbors. Unlike uniform resolution methods, it reduces data access and processing time by skipping large uniform regions, while the two-pass approach ensures a watertight mesh without requiring complex on-the-fly edge matching logic during the primary traversal.

### [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md)
Adaptive Marching Cubes is an extension of the standard Marching Cubes algorithm designed to extract isosurfaces from Adaptive Resolution (AR) octree data. It solves the problem of topological inconsistencies and geometric artifacts that arise when adjacent cubes in the mesh have different resolutions. Unlike uniform marching cubes, it handles missing vertices and discontinuities by deferring the processing of coarser nodes that conflict with finer neighbors, ensuring a watertight mesh across resolution boundaries.

### [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md)
DMC Octree Contour Extraction is an adaptive isosurface extraction method that generates a manifold triangle mesh from volumetric scalar field data using a dual-contouring approach on an octree structure. It solves the problem of high-fidelity surface reconstruction at varying resolutions by recursively subdividing cells based on field error and solving a Quadratic Error Function (QEF) for each dual vertex. It sets itself apart from its sibling [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md) by using dual vertices and QEF solving rather than linear interpolation on grid edges, and from [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) by explicitly managing topological consistency through a recursive face/edge/vertex processing pipeline that ensures shared boundaries between adjacent octree nodes are handled deterministically.

### Sparse-Voxel TSDF Fusion and Marching Cubes
This variant adapts TSDF-Fusion and Marching Cubes into a sparse voxel representation. It computes truncated signed distance values of sparse grid points and extracts the zero-level set surface. Duplicated vertices from adjacent voxels are merged. If adjacent voxels belong to different octree levels, the method subdivides all voxels to the finest level to remove discontinuities in the density field. Unlike methods relying on coarse geometry priors, this method models the scene only with a density field. It tends to produce unnecessary geometric bumps for texture details. When adjacent voxels belong to different octree levels, the extracted triangle may not be connected because the density field is not continuous for voxels in different levels [S2].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of leaf nodes in the octree. The constant factor depends on the split predicate's cost and the number of triangles generated per cell.
*   **Memory Complexity:** $O(N)$ for storing the octree nodes and the output mesh. The octree structure itself is more memory-efficient than a uniform grid for sparse or adaptive fields.
*   **Performance:** Performance is highly dependent on the split predicate. Uniform refinement yields predictable performance, while adaptive refinement can significantly reduce the number of cells processed if the field is smooth in large regions.
*   **Strengths:** Memory efficiency for sparse data; ability to capture fine details without global high resolution; robust topological handling within uniform regions.
*   **Limitations:** Cracks appear if the octree refinement is not uniform around the surface; requires careful handling of level boundaries to ensure watertightness; interpolation artifacts may occur if the scalar function is not smooth.
*   **When to Use:** Ideal for implicit surfaces defined by complex scalar fields where resolution requirements vary spatially.
*   **When Not to Use:** When the field is uniform or when strict watertightness is required without post-processing level-boundary artifacts.

## Background
The method originates from the CGAL (Computational Geometry Algorithms Library) project, specifically the `Isosurfacing_3` module. It implements the classic Marching Cubes algorithm (1987) adapted for octree domains. The `MC_Domain` abstraction allows the algorithm to work with various spatial data structures, including octrees, without modifying the core marching cubes logic. The approach is widely used in scientific visualization and 3D reconstruction where adaptive resolution is beneficial.
