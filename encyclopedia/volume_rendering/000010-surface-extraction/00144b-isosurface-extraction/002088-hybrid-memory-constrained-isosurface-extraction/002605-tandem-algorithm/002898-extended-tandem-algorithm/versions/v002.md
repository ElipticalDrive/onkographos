# Extended Tandem Algorithm

Also called: Parallel Tandem Algorithm with Component Dumping, Parallel tandem with dumping

## Overview
The Extended Tandem Algorithm is a parallel, block-wise extension of the Tandem Algorithm [3675-tandem-algorithm.md] that simplifies an isosurface on the fly while minimizing memory consumption via block splitting/merging and component dumping [S1]. It solves the scalability limits of the sequential tandem algorithm by combining on-the-fly simplification with a component-based dumping strategy and a hierarchical block splitting mechanism [S1]. Unlike the parent method, which processes a single volume sequentially, this method distributes the workload across multiple workers using a manager-worker architecture, allowing it to handle datasets that exceed available RAM by dumping completed surface components to disk [S1].

## How it works
The algorithm operates on a distributed dataset split into blocks [S1]. It uses a worker-manager architecture to dynamically dispatch tasks, ensuring that adjacent blocks are processed together to maintain mesh continuity while keeping memory usage low [S1].

### Inputs and Outputs
- **Input**: A volumetric dataset $V$, an isosurface value, and an error threshold $E_0$ for simplification [S1].
- **Output**: A simplified isosurface mesh, split into components stored on disk with a meta-data index (oriented bounding box, volume, etc.) [S1].

### Data Structures
**Task Structure**:
Each task sent from the manager to a worker is a tuple containing:
- `type`: Enum {EXTRACT, SEND, MERGE, FINISHED}
- `worker_id`: Integer ID of the target worker (for SEND tasks) or the requesting worker (for others) [S1].
- `block_id`: Integer ID of the block to extract (for EXTRACT tasks) [S1].

**Worker State**:
Each worker maintains a `current_surface`, which is the aggregate of semi-simplified meshes extracted locally and merged from neighbors [S1].

### Algorithm Steps
1. **Dataset Splitting**: The input volume is recursively split into blocks and assigned to compute nodes (workers) [S1].
2. **Worker Loop**: Each worker runs an infinite loop requesting tasks from the manager until a `FINISHED` task is received [S1].
3. **Task Execution**:
   - **EXTRACT**: The worker extracts a local isosurface from a sub-block using the Tandem Algorithm. Sub-block boundaries (except dataset boundaries) prevent edge collapse in their neighborhood using time lag. The extracted surface is appended to the worker's `current_surface` [S1].
   - **SEND**: The worker sends its `current_surface` to a target worker. After sending, the worker's `current_surface` is emptied [S1].
   - **MERGE**: The worker merges its `current_surface` with a mesh received from another worker. After merging, the new surface is simplified, and finished components are dumped [S1].
   - **FINISHED**: The worker stops execution [S1].
4. **Manager Dispatching**: The worker manager iterates as long as the global surface is not totally extracted. For each worker request, it checks conditions in priority order: if the worker has a waiting surface (`has_waiting_surface(id)`), send a `MERGE` task; else if the worker has a neighbor worker with restricted adjacency (`has_neighbor_worker(id)`), send a `SEND` task with the target ID; else if there is an unprocessed block with restricted adjacency (`has_unprocessed_block(blockId)`), send an `EXTRACT` task; else send a `FINISHED` task [S1].
5. **Component Dumping**: As soon as a surface component is detected as terminated (fully extracted and simplified), it is saved to disk along with meta-data and cleared from memory [S1].

### Formulas
**Triangle Aspect Ratio**:
The quality of a triangle $t$ with vertices $a, b, c$ is measured by its aspect ratio $\rho(t)$:
$$ \rho(t) = \sqrt{\frac{\lambda_2}{\lambda_1}} $$
where $\lambda_1 \ge \lambda_2$ are the greatest eigenvalues of the inertia matrix $M_t$:
$$ M_t = \frac{1}{3}[(a - \hat{t})(a - \hat{t})^T + (b - \hat{t})(b - \hat{t})^T + (c - \hat{t})(c - \hat{t})^T] $$
and $\hat{t}$ is the centroid of triangle $t$ [S1]. $\rho(t) = 1$ for equilateral triangles and $\rho(t) = 0$ for flat triangles [S1].

**Mesh Anisotropy**:
The global anisotropy (skewness) of a triangulation $K$ with $n$ triangles is:
$$ anisotropy(K) = 1 - \frac{1}{n} \sum_{t \in K} \rho(t) $$
The range is $0 \le anisotropy(K) \le 1$, where $0$ indicates all triangles are equilateral [S1].

### Parameters
- **$E_0$**: The error threshold used in the tandem algorithm's edge collapse operations. It determines the maximum allowed deviation for collapsed edges [S1].
- **$\alpha$**: The isotropy parameter in the mesh quality cost function. It balances the cost between shape quality and distance from the original surface. A value of $\alpha = 0.4$ is recommended as a good compromise. Values $> 0.9$ ignore shape criteria, leading to degenerate triangles rejected by $E_0$ [S1].

### Pseudocode
```python
# Worker Algorithm
def worker(E0: float):
    finished = False
    current_surface = []
    waiting_mesh = None

    while not finished:
        task = get_task()

        if task.type == "EXTRACT":
            local_mesh = tandem(E0, task.block_id)
            current_surface = merge(current_surface, local_mesh)

        elif task.type == "SEND":
            send_mesh(task.target, current_surface)
            current_surface = []

        elif task.type == "MERGE":
            received_mesh = waiting_mesh if waiting_mesh else get_received_mesh()
            waiting_mesh = None
            current_surface = merge(current_surface, received_mesh)
            simplify(current_surface, E0)
            dumping(current_surface)

        elif task.type == "FINISHED":
            if waiting_mesh:
                current_surface = merge(current_surface, waiting_mesh)
            simplify(current_surface, E0)
            dumping(current_surface)
            finished = True

# Worker Manager Algorithm
def worker_manager():
    global_extraction_finished = False
    waiting_surfaces = {}
    neighbor_map = {}
    unprocessed_blocks = {}

    while not global_extraction_finished:
        id = get_task_request_id()

        if has_waiting_surface(id):
            send_task(id, "MERGE")
        elif has_neighbor_worker(id) is not False:
            target_id = has_neighbor_worker(id)
            send_task(id, "SEND", target_id)
        elif has_unprocessed_block(id) is not False:
            block_id = has_unprocessed_block(id)
            send_task(id, "EXTRACT", block_id)
        else:
            send_task(id, "FINISHED")

# Dumping Function
def dumping(surface):
    for component in surface.components:
        if is_component_finished(component):
            save_to_disk(component)
            clear_component(surface, component)

# Manager helper functions
def has_waiting_surface(id: int) -> bool:
    return id in waiting_surfaces

def has_neighbor_worker(id: int) -> int:
    return neighbor_map.get(id, False)

def has_unprocessed_block(id: int) -> int:
    return unprocessed_blocks.get(id, False)
```

## Subtopics

### Extended Tandem Algorithm with Dumping
This variant refers to the core sequential extension of the tandem algorithm that introduces the component dumping mechanism. It processes cross-sections sequentially, activating them one by one, simplifying the mesh, and dumping finished components. The loop runs from $k=1$ to $N-1$ (number of cross-sections), activating cross-section $k$, simplifying with $E_0$, and dumping. Finally, it activates all remaining components with infinity and simplifies again [S1].

## Operating characteristics
- **Time Complexity**: The parallel version significantly reduces extraction time compared to the sequential tandem algorithm. On a seismic dataset of size $1626 \times 7028 \times 2000$ (40 GB), extraction takes 5 minutes with 56 processors, compared to over three hours for the sequential tandem algorithm [S1].
- **Memory Complexity**: By dumping completed components and processing blocks, the algorithm minimizes memory consumption. It avoids storing the entire isosurface in memory, which is critical for large datasets where the sequential algorithm fails due to memory limits (e.g., generating 1,250,000 triangles per layer in noisy datasets) [S1].
- **Scalability**: The algorithm scales well with the number of processors, limited primarily by the communication overhead between workers and the manager. The hierarchical block splitting allows efficient load balancing [S1].
- **Mesh Quality**: The parallel algorithm produces a mesh with equivalent quality (anisotropy variation) to the sequential approach. The use of time lag at block boundaries ensures that the mesh quality is not degraded by the parallel processing [S1].
- **Strengths**: Handles very large datasets that exceed RAM; reduces memory footprint via dumping; maintains high mesh quality; enables interactive exploration via component indexing [S1].
- **Limitations**: Requires a manager-worker infrastructure; complex task scheduling logic; performance depends on the distribution of surface components across blocks [S1].

## Background
The Extended Tandem Algorithm was introduced by Guilhem Dupuy and Bruno Jobard in 2009 [S1]. It addresses the limitations of the original Tandem Algorithm [3675-tandem-algorithm.md], which, while effective for large datasets, suffered from limited scalability on very large, noisy datasets due to high memory consumption during queue updates and simplification [S1]. The extension was motivated by the need to process geophysical datasets (such as seismic cubes) that are often large and contain numerous small, disconnected components [S1]. The method builds on the tandem algorithm's simplification strategy and incorporates component dumping and parallel block processing to enable the extraction of isosurfaces from datasets exceeding available memory [S1].
