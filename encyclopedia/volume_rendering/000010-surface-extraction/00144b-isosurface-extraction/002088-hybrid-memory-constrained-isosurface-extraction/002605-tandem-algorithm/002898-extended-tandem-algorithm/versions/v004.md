# Extended Tandem Algorithm

Also called: Parallel Bloc-wise Extension, Parallel Tandem Algorithm, Parallel Tandem Algorithm with Component Dumping, Parallel tandem with dumping

## Overview
The Extended Tandem Algorithm is a parallel, bloc-wise extension of the Tandem Algorithm [3675-tandem-algorithm.md] designed to extract and simplify isosurfaces from very large volumetric datasets while minimizing memory consumption. It solves the scalability bottleneck of the sequential Tandem Algorithm, where queue updates and simplification steps become too memory-intensive for high-resolution data (e.g., generating millions of triangles per layer) [S1, S2]. Unlike its parent, which processes the entire volume in a single pass, this method splits the dataset into blocks, distributes extraction across computing nodes, and introduces a component dumping mechanism to persist finalized surface components to disk, allowing the process to continue on remaining sub-parts without exhausting main memory [S1, S2].

## How it works
The algorithm operates using a worker-manager architecture. The dataset is split into blocks (see Subtopics for splitting strategies) and distributed to computing nodes. Each node extracts a local isosurface, semi-simplifies it, and merges it with adjacent semi-simplified surfaces from other nodes. Completed components are dumped to disk.

### Inputs and Outputs
- **Input**: A volumetric dataset $V$, an isovalue $iso$, and a maximum shape error threshold $E_0$.
- **Output**: A simplified isosurface mesh, potentially stored as multiple components on disk with associated metadata.

### Data Structures
1.  **Priority Queue Q**: Stores edge candidates for collapse, ordered by their global cost $\epsilon_\alpha(c)$.
2.  **Priority Queue W**: Stores blocked edges, ordered by their reach value. Used to delay collapses near the advancing front.
3.  **Task Structure**: Composed of a `task_type` and a `worker_id`.
    -   `EXTRACT`: Extract surface from a sub-block.
    -   `SEND`: Send mesh to a target worker.
    -   `MERGE`: Merge received mesh with current surface.
    -   `FINISHED`: Stop worker execution.

### Core Formulas
The edge collapse cost $\epsilon_\alpha(c)$ balances shape measure and mesh isotropy:
$$ \epsilon_\alpha(c) = c^T \left[ (1 - \alpha) \frac{H_c}{W_c} + \alpha \frac{G_c}{W} \right] c $$
Where:
-   $c$ is the candidate vertex position.
-   $\alpha$ is the isotropy parameter (typically 0.4).
-   $H_c$ is the positive definite matrix for the shape measure.
-   $W_c$ is the sum of areas of the patch $U_c$ of neighboring triangles.
-   $G_c$ is the matrix for the mesh isotropy criterion.
-   $W$ is a normalization factor.

**Shape Measure Criterion $h_c(x)$**:
$$ h_c(x) = \frac{1}{W_c} \sum_{t \in U_c} w_t d^2(x, P_t) = \frac{1}{2} x^T H_c x $$
Where $P_t$ is the plane of triangle $t$, $w_t$ is its area, and $U_c$ is the patch of neighboring triangles.

**Mesh Isotropy Criterion $g_c(x)$**:
$$ g_c(x) = \sum_{t \in S_{ab}} w_t (\|x - \hat{t}\|^2 + \text{avg}(t)) = x^T G_c x $$
Where $S_{ab}$ is the set of triangles containing vertices $a, b$ or both, $\hat{t}$ is the barycenter of triangle $t$, and $\text{avg}(t) = \frac{1}{2}(\|p\|^2 + \|q\|^2 + \|r\|^2)$ with $p, q, r$ vectors from $\hat{t}$ to vertices.

**Aspect Ratio $\rho(t)$**:
$$ \rho(t) = \sqrt{\frac{\lambda_2}{\lambda_1}} $$
Where $\lambda_1 \ge \lambda_2$ are the greatest eigenvalues of the inertia matrix $M_t$. $\rho(t)=1$ for equilateral triangles, $0$ for flat triangles.

**Anisotropy of Triangulation $K$**:
$$ \text{anisotropy}(K) = 1 - \frac{1}{n} \sum_{t} \rho(t) $$

### Time Lag and Reach
To prevent artifacts near the advancing front, edge collapses are delayed based on the "reach" value.
-   $\text{rank}(u)$: Coordinate along the extraction direction.
-   $\text{height}(c) = (\text{rank}(a) + \text{rank}(b))/2$.
-   $\text{rad}(c) = (\|a - b\| + \text{rad}(a) + \text{rad}(b))/2$.
-   $\text{reach}(c) = \text{height}(c) + \text{rad}(c)$.

An edge collapse is prevented if $\text{reach}(c) \ge \text{rank}(\text{front})$. Blocked edges are stored in $W$.

### Worker Algorithm
Workers run an infinite loop requesting tasks from the manager.

```python
def worker(E0: float):
    finished = False
    while not finished:
        task = get_task()
        if task.type == EXTRACT:
            # Extract local isosurface from sub-block using tandem logic
            # Sub-block boundaries prevent edge collapse in neighborhood via time lag
            tandem(E0)
            # Append extracted surface to worker's current surface
        elif task.type == SEND:
            # Send current mesh to target worker
            send_surface(task.target)
            # Empty current surface
        elif task.type == MERGE:
            # Merge current surface with mesh from another worker
            merge_surface(get_surface(), E0)
            # Simplify new current surface
            # Detect termination of components and dump to disk
        elif task.type == FINISHED:
            # Merge any remaining surface and dump
            merge_surface(get_surface(), E0)
            finished = True
```

### Worker Manager Algorithm
The manager dispatches tasks based on the state of workers and the hierarchical block structure.

```python
def worker_manager():
    while not global_extraction_finished:
        id = get_task_request_id()
        if has_waiting_surface(id):
            # Worker has a waiting surface from another worker
            send_task(id, MERGE)
        elif has_neighbor_worker(id):
            # Worker has a neighbor fulfilling restricted adjacency requirements
            target_id = get_neighbor_id(id)
            send_task(id, SEND, target_id)
        elif has_unprocessed_block(id):
            # Find best next block (prioritizing adjacency to current aggregate)
            block_id = get_unprocessed_block(id)
            send_task(id, EXTRACT, block_id)
        else:
            send_task(id, FINISHED)
```

### Tandem Loop (Inside EXTRACT)
The local extraction follows the Tandem Algorithm loop [3675-tandem-algorithm.md]:
1.  Iterate $k$ from 1 to $N-1$ (cross-sections):
    -   `extract(k)`: Add layer (vertices, edges, triangles) to current triangulation.
    -   `delay(k)`: Add all edges of layer $k$ to blocked queue $W$, ordered by reach.
    -   `activate(k)`: Move edges from $W$ to $Q$ if $\text{reach}(edge) < k$.
    -   `simplify(E0)`: Empty $Q$ by applying edge collapses. Reject if shape measure $\epsilon_0(c) > E_0$.
    -   `dumping()`: Check for completed components and dump to disk.
2.  `activate(∞)`: Move all remaining edges from $W$ to $Q$.
3.  `simplify(E0)`: Final simplification.
4.  `dumping()`: Final dump.

### Merging and Simplification
When merging two semi-simplified surfaces:
1.  Combine the meshes.
2.  Apply simplification with **relaxed edge constraints** at the common interface to remove seams.
3.  Check for component termination. A component is terminated when its extraction and simplification are complete.

### Parameters
-   **$E_0$**: Maximum shape error threshold. Positive constant. Candidates exceeding this are rejected.
-   **$\alpha$**: Isotropy parameter. Balances shape measure vs. anisotropy. Recommended value: **0.4**. Values $> 0.9$ ignore shape measure, leading to degenerate cases rejected by $E_0$ [S1, S2].

### Edge Cases and Pitfalls
-   **High Isotropy Parameter**: If $\alpha > 0.9$, the shape criterion is ignored. Collapses are based only on triangle shape quality, proposing points far from the original surface. These are rejected by $E_0$, increasing anisotropy [S2].
-   **Blocked Edges**: Edges near the advancing front must not be collapsed immediately. The time lag mechanism prevents contraction if $\text{reach}(c) \ge \text{rank}(\text{front})$. If vertices $a, b$ are in the last layer, $\text{height}(c) = \text{rank}(\text{front})$, and since $\text{rad}(c) > 0$, $\text{reach}(c) > \text{rank}(\text{front})$, preventing seams [S1].
-   **Memory Exhaustion**: Without dumping, queue updates and simplification for large layers (e.g., 1.25 million triangles) exhaust memory [S2].

## Subtopics

### Hierarchical Binary Partitioning
A hierarchical scheme where the dataset is split recursively into sub-blocks to allow parallel extraction and merging. The dataset is split recursively in two parts perpendicularly to its longest direction as long as the sub-block size is greater than a given threshold. Isosurface extraction is performed on the leaf nodes using the Extended Tandem Algorithm, and surfaces are recursively merged to recompose the global surface. The threshold value is not specified in the sources [S1].

### Parallel Tandem Algorithm with Time Lag
A parallel processing method based on dataset splitting and the time lag extension. It ensures that parallel extraction generates a mesh with equivalent quality to the sequential approach. The key parameter is the isotropy parameter $\alpha$, recommended at 0.4 to prevent degenerated cases by ensuring the shape measure is always considered. Using $\alpha > 0.9$ causes the shape criterion to be ignored, leading to collapsed points far from the original surface [S1].

## Operating characteristics
-   **Time Complexity**: Significantly faster than sequential Tandem. On a seismic dataset ($1626 \times 7028 \times 2000$, 40 GB), extraction took 5 minutes with 56 processors, compared to over 3 hours for the sequential algorithm [S2].
-   **Memory Complexity**: Minimizes memory by extracting and simplifying in one pass per block and dumping completed components. Prevents the memory exhaustion seen in brute-force approaches or the sequential Tandem on very large datasets [S1, S2].
-   **Scalability**: Scales well with the number of processors and block splitting. The hierarchical splitting allows efficient load balancing [S2].
-   **Mesh Quality**: Produces meshes with equivalent anisotropy to the sequential Tandem when $\alpha=0.4$ and time lag is correctly applied. Anisotropy ranges from 0 (equilateral) to 1 (flat) [S2].
-   **Strengths**: Handles very large geophysics datasets; reduces triangle count drastically compared to classical marching cubes; enables interactive exploration via component-based file organization [S1, S2].
-   **Limitations**: Requires a master-worker infrastructure; complex task scheduling logic; dependent on efficient I/O for dumping [S1, S2].

## Background
The Tandem Algorithm was introduced by Attali et al. in 2005 to reduce memory consumption by alternating extraction and simplification [S1]. The Extended Tandem Algorithm was developed to address the limited scalability of the Tandem Algorithm on very large, noisy datasets (e.g., $1626 \times 7028 \times 2000$), where queue updates became too memory-intensive [S1, S2]. It was proposed for use in geophysics, specifically for seismic cubes used in hydrocarbon exploration, where datasets are large and contain numerous small disconnected components [S1, S2]. The work was supported by Total company [S1].
