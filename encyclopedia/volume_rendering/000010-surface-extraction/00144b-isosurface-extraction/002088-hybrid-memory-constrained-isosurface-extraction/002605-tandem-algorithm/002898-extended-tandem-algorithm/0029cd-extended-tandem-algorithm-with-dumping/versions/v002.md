# Extended Tandem Algorithm with Dumping

Also called: Parallel Tandem Algorithm with Component Dumping, Parallel tandem with dumping

## Overview
The Extended Tandem Algorithm with Dumping is a parallel, bloc-wise extension of the Tandem algorithm designed to increase scalability for very large datasets by dumping extracted surface components to disk [S1]. It prevents memory exhaustion during queue updates and simplification steps, which are the primary bottlenecks in the standard Tandem algorithm for high-resolution data [S1]. Unlike its parent, it introduces a mechanism to persist finalized components to storage, allowing the extraction process to continue on sub-parts of the dataset without losing previously computed geometry [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar dataset, an error threshold parameter $E_0$, and a set of active surface components $\Gamma$ [S1].
*   **Output:** A set of isosurface components saved to disk (in a raw data file) and an index file containing metadata for each component [S1].

**Data Structures:**
*   $\Gamma$: The set of active surface components currently being tracked [S1].
*   $V_w$: The set of vertices currently in the processing queue [S1].
*   $E_0$: The error threshold for mesh simplification [S1].
*   Exact memory layouts and bit packing are not given in the sources.

**Definitions:**
*   A component $\gamma \in \Gamma$ is considered **finalized** if it no longer shares any vertices with the active queue $V_w$ [S1].
    $$ \gamma \text{ is finalized} \iff \gamma \cap V_w = \emptyset $$
*   `save(γ)`: Migrates component $\gamma$ to disk [S1].
*   `clear(γ)`: Deletes $\gamma$ from the current in-memory triangulation [S1].

**Parameters:**
*   $E_0$: The error threshold for simplification. Typical values are not given in the sources [S1].

**Algorithm Steps:**
1.  Initialize the algorithm with the error threshold $E_0$ [S2].
2.  Iterate through each cross-section $k$ from $1$ to $N-1$, where $N$ is the total number of cross-sections:
    a.  `extract(k)`: Extract the isosurface for cross-section $k$ [S1].
    b.  `delay(k)`: Apply the time-lag technique to manage the advancing front [S1].
    c.  `activate(k)`: Activate the newly extracted components for cross-section $k$ [S2].
    d.  `simplify(E_0)`: Simplify the current mesh using the error threshold $E_0$ [S2].
    e.  `dumping()`: Check for finalized components and persist them to disk [S1].
3.  After the loop, finalize all remaining active components by activating infinity: `activate(∞)` [S2].
4.  Simplify the final mesh: `simplify(E_0)` [S2].
5.  Call `dumping()` one final time to persist any remaining components [S1].

**Pseudocode:**
```python
def tandem_with_dumping(E0, num_cross_sections, Gamma, Vw):
    """
    Executes the Extended Tandem Algorithm with Dumping.
    
    Args:
        E0: Error threshold for simplification.
        num_cross_sections: Total number of cross-sections in the dataset.
        Gamma: Set of active surface components (each gamma is a set of vertices).
        Vw: Set of vertices in the processing queue.
    """
    # Steps extract(k), delay(k), activate(k), and simplify(E0) are defined in the parent Tandem algorithm [S1, S2]
    for k in range(1, num_cross_sections):
        # extract(k)
        # delay(k)
        # activate(k)
        # simplify(E0)
        dumping(Gamma, Vw)

    # activate(infinity)
    # simplify(E0)
    dumping(Gamma, Vw)

def dumping(Gamma, Vw):
    """
    Iterates through all active components. If a component is finalized,
    it is saved to disk and cleared from the current triangulation.
    """
    finalized_components = [gamma for gamma in Gamma if is_finalized(gamma, Vw)]
    for gamma in finalized_components:
        save_to_disk(gamma)
        clear_from_memory(gamma)
        Gamma.remove(gamma)

def is_finalized(gamma, Vw):
    """
    A component is finalized if its intersection with the set of vertices in the queue is empty.
    """
    return len(gamma & Vw) == 0
```

**Edge Cases and Pitfalls:**
*   **Simplification Delay:** Due to the time-lag technique, a component may be entirely extracted but its simplification might be prevented or delayed [S1]. The dumping function must detect the end of both extraction and simplification to correctly identify finalized components [S1].
*   **Memory Exhaustion:** Without dumping, queue updates and simplification steps become too memory-consuming for large datasets (e.g., generating 1,250,000 triangles per extraction on a $1626 \times 7028 \times 2000$ cube) [S1].

## Operating characteristics
*   **Scalability:** The method significantly increases scalability for very large datasets by preventing memory exhaustion [S1].
*   **Performance:** On a dataset of size $1626 \times 7028 \times 2000$, each extraction on the advancing front generates approximately 1,250,000 triangles [S1].
*   **Storage:** The generated file is ordered by component, allowing easy access to subsets of components by reading sub-parts of the file [S1].
*   **Time and Memory Complexity:** Not given in the sources.
*   **Hardware and Scene Metrics:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths and Limitations:** Prevents memory exhaustion on massive datasets but requires disk I/O and index management [S1].
*   **When to Use/Not Use:** Use for geophysical or similarly massive scalar fields where standard Tandem memory limits are hit; not given in the sources for specific exclusion criteria.

## Background
The method was proposed to address the limit of scalability of the Tandem algorithm when applied to very large datasets in geophysics [S1]. It builds on the hierarchical splitting scheme proposed by Müller and Stark (1993) [S1].
