# Marching Cubes with Gaussian Deformation

Also called: Geometry Shader Marching Cubes, Marching Cubes Geometry Shader Variant, Marching Cubes with Brush Deformation

## Overview
This method extracts an isosurface from a scalar field using a Geometry Shader pipeline, applying a Gaussian-based deformation to the resulting mesh vertices along a user-defined force vector [S1, unofficial]. It differs from standard GPU Marching Cubes implementations by integrating the deformation directly into the geometry shader's vertex emission phase, allowing for real-time, dynamic modification of the terrain or mesh shape without CPU-side geometry regeneration [S1, unofficial]. Unlike methods that use append buffers or histogram pyramids for output management, this variant typically relies on the geometry shader's primitive stream, often coupled with specific matrix transformations for rendering [S2, unofficial].

## How it works

### Inputs and Outputs
*   **Inputs:**
    *   A 3D grid of point primitives, where each point represents the center of a voxel in the scalar field [S1, unofficial].
    *   A 3D scalar field texture (e.g., `Texture3D`) storing the field values at voxel corners [S1, unofficial].
    *   Uniform parameters: `gridSize` (float, typical value 0.25f), `i_force` (vec3, deformation direction/magnitude), and `sigma` (float, typical value 0.8, Gaussian width) [S1, unofficial].
    *   Lookup tables: `edgeTable` and `triangleTable` stored in 2D integer textures (`GL_R16I`, size 256x1) [S1, unofficial].
*   **Outputs:**
    *   A `TriangleStream` of deformed vertices in clip space [S1, unofficial].
    *   Per-vertex attributes: position, normal, and UV coordinates passed to the fragment shader [S2, unofficial].

### Data Structures
*   **Cube Corner Indices:** A static array `cube_diff_indices` of size 24 (12 edges × 2 vertices) maps edge index $i$ to the two corner vertex indices of that edge. The layout is:
    ```text
    0,1, 1,2, 2,3, 3,0, 4,5, 5,6, 6,7, 7,4, 0,4, 1,5, 2,6, 3,7
    ```
    [S1, unofficial]
*   **Lookup Tables:** Stored as 2D textures. Access is performed via `texelFetch(tex, ivec2(index, 0), 0).r` to retrieve the 16-bit integer values for the edge and triangle tables [S1, unofficial].

### Steps
1.  **Vertex Shader:** Transform the input point position (voxel center) from object space to world space using `unity_ObjectToWorld`. Pass normal and texcoords unchanged [S2, unofficial].
2.  **Geometry Shader Entry:** Receive one point primitive per voxel. Compute the cube index by evaluating the scalar field $f(\mathbf{p})$ at the 8 corners of the voxel. If $f(\mathbf{p}) < 0.0$, set the corresponding bit in the cube index [S1, unofficial].
    *   Scalar field evaluation: $f(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - (r + s\sqrt{3})$, where $\mathbf{c} = (0, 0, -20)$, $r = 4.0$, and $s$ is the grid size [S1, unofficial].
3.  **Edge Interpolation:** Look up the `edgeTable` using the cube index. If the result is 0, discard the primitive. Otherwise, for each of the 12 edges, if the $i$-th bit is set, compute the interpolated vertex position $\mathbf{v}$ on that edge:
    $$ \mathbf{v} = (1 - \alpha)\mathbf{p}_1 + \alpha\mathbf{p}_2 $$
    where $\alpha = \frac{|f(\mathbf{p}_1)|}{|f(\mathbf{p}_1)| + |f(\mathbf{p}_2)|}$, and $\mathbf{p}_1, \mathbf{p}_2$ are the corner positions [S1, unofficial].
4.  **Gaussian Deformation:** For each interpolated vertex position $\mathbf{v}$, apply the Gaussian deformation to get $\mathbf{v}'$:
    $$ \mathbf{v}' = \mathbf{v} + \mathbf{F} \cdot 5 \cdot \mathcal{N}(\sigma, d_{\perp}^2) $$
    where $\mathcal{N}(\sigma, x) = \frac{e^{-x / (2\sigma^2)}}{\sigma\sqrt{2\pi}}$ and $d_{\perp}^2 = \|\mathbf{v} - \mathbf{c}\|^2 - \frac{(\mathbf{v} - \mathbf{c}) \cdot \mathbf{F}^2}{\|\mathbf{F}\|^2}$ [S1, unofficial].
    *   Note: If the dot product of the displacement vector and force is non-positive, the deformation is skipped to prevent backward pushing [S1, unofficial].
5.  **Triangle Emission:** Look up the `triangleTable` using the cube index. Iterate through the table in steps of 3. For each valid triangle vertex index (retrieved from `cube_diff_indices`), retrieve the undeformed interpolated position, apply the deformation, and emit the vertex. End the primitive after three vertices [S1, unofficial].
6.  **Clip Space Transformation:** Transform the deformed vertex positions to clip space. The source code uses `mul(UNITY_MATRIX_MVP, unity_WorldToObject)`, which is noted as potentially incorrect for standard MVP transformation (typically $VP \cdot World \cdot Vertex$) [S2, unofficial].
7.  **Fragment Shader:** Compute lighting using a normalized light vector $\mathbf{L}$ derived from `lightPos` and input position. Calculate diffuse lighting as $\max(\mathbf{N} \cdot \mathbf{L}, 0)$. Sample a sprite texture and multiply by the diffuse light [S2, unofficial].

### Pseudocode

```python
# Geometry Shader Logic (Simplified Python-like representation)

def geometry_shader(point_in):
    """
    point_in: Position of the voxel center in world space.
    """
    # 1. Evaluate Scalar Field at 8 corners
    cube_index = 0
    for corner_idx in range(8):
        corner_pos = get_corner_position(point_in, corner_idx, grid_size)
        field_val = evaluate_scalar_field(corner_pos)
        if field_val < 0.0:
            cube_index |= (1 << corner_idx)
    
    # 2. Check if triangle needs to be generated
    edge_mask = texel_fetch(edge_table_tex, cube_index)
    if edge_mask == 0:
        return # Discard primitive

    # 3. Compute interpolated vertices on active edges
    interpolated_vertices = []
    for edge_idx in range(12):
        if (edge_mask >> edge_idx) & 1:
            # Get corner indices for this edge
            v1_idx, v2_idx = cube_diff_indices[edge_idx * 2], cube_diff_indices[edge_idx * 2 + 1]
            
            # Get corner positions and field values
            p1 = get_corner_position(point_in, v1_idx, grid_size)
            p2 = get_corner_position(point_in, v2_idx, grid_size)
            f1 = evaluate_scalar_field(p1)
            f2 = evaluate_scalar_field(p2)
            
            # Handle degenerate case: both values are 0
            if abs(f1) + abs(f2) == 0.0:
                alpha = 0.5 # [G] Default midpoint if both are zero
            else:
                alpha = abs(f1) / (abs(f1) + abs(f2))
            
            # Linear interpolation
            v = (1 - alpha) * p1 + alpha * p2
            
            # 4. Apply Gaussian Deformation
            v_deformed = apply_gaussian_deformation(v, i_force, sigma)
            
            interpolated_vertices.append(v_deformed)

    # 5. Emit Triangles
    tri_indices = texel_fetch(triangle_table_tex, cube_index)
    for i in range(0, 16, 3):
        idx1, idx2, idx3 = tri_indices[i], tri_indices[i+1], tri_indices[i+2]
        if idx1 == -1 or idx2 == -1 or idx3 == -1:
            break
            
        # Retrieve deformed vertices for the triangle
        # Note: The triangle table indices refer to the edge indices, 
        # which map to the interpolated_vertices list.
        # However, standard MC triangle table indices refer to edge indices 0-11.
        # We need to map edge index to the correct interpolated vertex.
        
        v1 = interpolated_vertices[idx1]
        v2 = interpolated_vertices[idx2]
        v3 = interpolated_vertices[idx3]
        
        # Transform to clip space
        # Warning: Source uses mul(MVP, WorldToObject) which is likely incorrect
        clip_v1 = transform_to_clip_space(v1)
        clip_v2 = transform_to_clip_space(v2)
        clip_v3 = transform_to_clip_space(v3)
        
        # Compute normal for lighting
        normal = compute_normal(v1, v2, v3)
        
        # Emit vertices
        emit_vertex(clip_v1, normal)
        emit_vertex(clip_v2, normal)
        emit_vertex(clip_v3, normal)
        end_primitive()

def evaluate_scalar_field(p):
    """
    f(p) = ||p - c|| - (r + s*sqrt(3))
    """
    c = vec3(0, 0, -20)
    r = 4.0
    s = grid_size
    dist = length(p - c)
    return dist - (r + s * sqrt(3))

def apply_gaussian_deformation(p, force, sigma):
    """
    p' = p + F * 5 * N(sigma, d_perp^2)
    """
    if length(force) == 0.0:
        return p # [G] Guard against division by zero
    
    c = vec3(0, 0, -20)
    # d_perp^2 = ||p - c||^2 - ((p - c) . F)^2 / ||F||^2
    diff = p - c
    dot_prod = dot(diff, force)
    d_perp_sq = dot(diff, diff) - (dot_prod * dot_prod) / dot(force, force)
    
    # Gaussian
    exponent = -d_perp_sq / (2 * sigma * sigma)
    gaussian_val = exp(exponent) / (sigma * sqrt(2 * pi))
    
    # Check for backward pushing
    if dot(p - c, force) <= 0:
        return p
        
    return p + force * 5.0 * gaussian_val

def transform_to_clip_space(world_pos):
    # Source uses: mul(UNITY_MATRIX_MVP, unity_WorldToObject)
    # This is likely a bug. Standard is: MVP * world_pos
    # Assuming standard MVP for correctness in implementation
    return unity_Matrix_MVP * world_pos
```

### Parameters
*   `gridSize`: Float, defines the voxel edge length. Typical value: 0.25f [S1, unofficial].
*   `i_force`: Vec3, defines the deformation direction and magnitude. Passed from CPU [S1, unofficial].
*   `sigma`: Float, controls the width of the Gaussian deformation falloff. Typical value: 0.8 [S1, unofficial].
*   `lightPos`: Vec3, light position in world space [S2, unofficial].

### Edge Cases and Pitfalls
*   **Zero Force Vector:** If `i_force` is zero, the division by `||F||` in the deformation formula causes NaN. The source code does not explicitly guard against this [S1, unofficial].
*   **Degenerate Interpolation:** If both scalar field values at an edge's endpoints are exactly 0.0, the interpolation denominator becomes 0.0, causing division by zero. The source code does not handle this [S1, unofficial].
*   **Matrix Multiplication Order:** The geometry shader uses `mul(UNITY_MATRIX_MVP, unity_WorldToObject)`, which multiplies MVP by WorldToObject. Standard transformation is `VP * World * Vertex`. This likely produces incorrect clip-space positions [S2, unofficial].
*   **Backward Pushing:** If the dot product of the displacement vector and force is non-positive, the deformation is skipped to prevent backward pushing [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** O(1) per voxel processed by the geometry shader, as it performs a fixed number of texture fetches and arithmetic operations regardless of grid resolution. Total complexity is O(N) for N voxels [S1, unofficial].
*   **Memory Complexity:** O(1) additional memory per voxel for temporary storage of interpolated vertices and triangle indices. Lookup tables are stored in GPU memory [S1, unofficial].
*   **Performance:** Implemented in a custom OpenGL 3.3+ application for real-time deformable terrain/mesh interaction [S1, unofficial]. Performance depends on the number of voxels and the complexity of the Gaussian deformation calculation.
*   **Strengths:** Real-time deformation without CPU-side geometry updates. Simple implementation using standard geometry shader pipeline.
*   **Limitations:** Geometry shader performance can be lower than compute shader approaches for large grids. Potential numerical instability with degenerate cases. Matrix transformation bug in source code may affect rendering correctness [S2, unofficial].
*   **When to use:** Real-time interactive applications requiring dynamic deformation of isosurfaces, such as terrain editing or fluid simulation visualization.
*   **When not to use:** High-performance offline rendering or large-scale static meshes where compute shader or CPU-side extraction is more efficient.

## Background

*   **Origin:** This method is a variant of the Marching Cubes algorithm implemented in a geometry shader, as seen in the `ntsl-graphics` project [S1, unofficial]. It applies a Gaussian-based deformation to the mesh vertices based on a user-provided force vector.
*   **History:** The base Marching Cubes algorithm was introduced by Lorensen and Cline in 1987. The geometry shader variant leverages the programmable pipeline introduced in OpenGL 3.2+ to perform surface extraction and deformation on the GPU.
*   **Usage:** Used in real-time deformable terrain/mesh interaction in custom OpenGL applications [S1, unofficial]. Also referenced in Unity-based GPU Marching Cubes implementations [S2, unofficial].
