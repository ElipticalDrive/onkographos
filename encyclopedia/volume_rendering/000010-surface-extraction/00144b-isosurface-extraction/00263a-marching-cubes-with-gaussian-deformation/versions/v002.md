# Marching Cubes with Gaussian Deformation

Also called: Geometry Shader Marching Cubes, Marching Cubes Geometry Shader Variant, Marching Cubes with Brush Deformation

## Overview
This method extracts a triangle mesh from a scalar field defined by a sphere function using the Marching Cubes algorithm, implemented within a GPU geometry shader pipeline. It applies a Gaussian-based deformation to the extracted vertices along a user-provided force vector, enabling real-time, deformable surface interaction [S1, unofficial]. Unlike standard static Marching Cubes, this variant integrates the deformation logic directly into the primitive generation stage, allowing for dynamic, brush-like modifications to the isosurface without re-evaluating the entire volume on the CPU [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   **Voxel Grid:** A set of point primitives representing the centers of voxels in a 3D grid. Each point corresponds to a cube corner or cell center depending on the specific implementation variant, but the primary source describes processing voxel grid positions [S1, unofficial].
*   **Scalar Field Parameters:** Center $\mathbf{c}$, radius $r$, and grid size $s$ defining the implicit sphere [S1, unofficial].
*   **Deformation Force:** A uniform 3D vector $\mathbf{F}$ (i_force) defining the direction and magnitude of the Gaussian deformation [S1, unofficial].
*   **Lookup Tables:** Standard Marching Cubes edge and triangle tables stored in 2D integer textures [S1, unofficial].

**Outputs:**
*   **Triangle Stream:** A stream of triangles (`TriangleStream`) emitted by the geometry shader, containing deformed vertex positions, normals, and UVs [S1, unofficial][S2, unofficial].

### Data Structures

**Cube Edge Indices (`cube_diff_indices`):**
A static integer array of size 24, mapping the 12 edges of a cube to their two vertex indices. The layout is:
`{0,1, 1,2, 2,3, 3,0, 4,5, 5,6, 6,7, 7,4, 0,4, 1,5, 2,6, 3,7}` [S1, unofficial].

**Lookup Tables:**
*   `edgeTableTex`: A 2D texture (`GL_R16I`, size $256 \times 1$) storing the 256-entry edge configuration table. Accessed via `texelFetch(tex, ivec2(index, 0), 0).r` [S1, unofficial].
*   `triTableTex`: A 2D texture storing the 256-entry triangle configuration table. Accessed similarly [S1, unofficial].

**Geometry Shader Input/Output Structure:**
*   **Input:** `float4 pos`, `float3 normal`, `float2 tex0` (or similar UV/Color attributes) [S2, unofficial].
*   **Output:** Transformed position in clip space, interpolated normal, and UVs [S2, unofficial].

### Algorithm Steps

1.  **Vertex Shader Pre-processing:**
    *   Transform the input vertex position from object space to world space using the model matrix (`unity_ObjectToWorld`) [S2, unofficial].
    *   Pass the normal and texture coordinates unchanged to the geometry shader [S2, unofficial].

2.  **Geometry Shader: Cube Index Calculation:**
    *   For each input point (representing a voxel grid position), evaluate the scalar field $f(\mathbf{p})$ at the 8 corners of the cube associated with that point.
    *   The scalar field is defined as:
        $$f(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - (r + s\sqrt{3})$$
        where $\mathbf{c} = (0, 0, -20)$, $r = 4.0$, and $s$ is the grid size [S1, unofficial].
    *   Construct the `cube_index` (0-255) by setting the $i$-th bit if $f(\mathbf{p}_i) < 0.0$ [S1, unofficial].

3.  **Geometry Shader: Edge Intersection:**
    *   Fetch the edge configuration from `edgeTableTex` using `cube_index`. If the result is 0, discard the primitive [S1, unofficial].
    *   Iterate over the 12 edges. For each edge $i$ where the corresponding bit is set:
        *   Retrieve the two corner vertices $\mathbf{p}_1$ and $\mathbf{p}_2$ using `cube_diff_indices`.
        *   Compute the interpolation factor $\alpha$:
            $$\alpha = \frac{|f(\mathbf{p}_1)|}{|f(\mathbf{p}_1)| + |f(\mathbf{p}_2)|}$$
        *   Compute the undeformed intersection point $\mathbf{v}$:
            $$\mathbf{v} = (1 - \alpha)\mathbf{p}_1 + \alpha\mathbf{p}_2$$
        *   [G] Guard against division by zero if both $f(\mathbf{p}_1)$ and $f(\mathbf{p}_2)$ are 0.0. If so, default to $\mathbf{v} = \mathbf{p}_1$ or skip [G].

4.  **Geometry Shader: Gaussian Deformation:**
    *   For each valid triangle vertex index from the triangle table:
        *   Retrieve the undeformed position $\mathbf{p}$ (the intersection point $\mathbf{v}$ calculated in Step 3).
        *   Apply the Gaussian deformation to get $\mathbf{p}'$:
            $$\mathbf{p}' = \mathbf{p} + \mathbf{F} \cdot 5 \cdot \mathcal{N}(\sigma, d_{\perp}^2)$$
            where $\mathcal{N}(\sigma, x) = \frac{e^{-x / (2\sigma^2)}}{\sigma\sqrt{2\pi}}$ and $d_{\perp}^2 = \|\mathbf{p} - \mathbf{c}\|^2 - \frac{((\mathbf{p} - \mathbf{c}) \cdot \mathbf{F})^2}{\|\mathbf{F}\|^2}$ [S1, unofficial].
        *   [G] Check if $\|\mathbf{F}\|^2$ is near zero to prevent NaN. If so, skip deformation [G].
        *   [G] Check if the dot product of the displacement vector and force is non-positive; if so, skip deformation to prevent backward pushing [S1, unofficial].
        *   Set the output position to $\mathbf{p}'$.

5.  **Geometry Shader: Primitive Emission:**
    *   Look up the triangle configuration from `triTableTex` using `cube_index`.
    *   Iterate through the table in steps of 3. For each valid triangle:
        *   Retrieve the three deformed vertex positions.
        *   Compute the normal for the triangle (e.g., via cross product of edge vectors) [S1, unofficial].
        *   Transform the position to clip space. Note: The source implementation uses `mul(UNITY_MATRIX_MVP, unity_WorldToObject)`, which is noted as likely incorrect for standard MVP transformation (should be `VP * World * Vertex`) [S2, unofficial].
        *   Emit the vertex with its position, normal, and UVs.
        *   After three vertices, call `EndPrimitive()` [S1, unofficial][S2, unofficial].

6.  **Fragment Shader:**
    *   Compute lighting using a normalized light vector $\mathbf{L}$ derived from `lightPos` and the fragment position.
    *   Calculate diffuse lighting: $\text{diffuse} = \max(\mathbf{N} \cdot \mathbf{L}, 0)$ [S2, unofficial].
    *   Sample the sprite texture and multiply by the diffuse light intensity [S2, unofficial].

### Pseudocode

```python
# Constants
C_CENTER = (0.0, 0.0, -20.0)
R_RADIUS = 4.0
SIGMA = 0.8
GRID_SIZE = 0.25

# Lookup tables (simplified representation)
# edge_table: 256 entries, each 12 bits
# tri_table: 256 entries, each 24 integers (3 vertices * 8 edges)
# cube_diff_indices: [0,1, 1,2, 2,3, 3,0, 4,5, 5,6, 6,7, 7,4, 0,4, 1,5, 2,6, 3,7]

def scalar_field(p):
    """Evaluate the implicit sphere field."""
    dist = length(p - C_CENTER)
    return dist - (R_RADIUS + GRID_SIZE * sqrt(3.0))

def gaussian_deformation(p, force):
    """Apply Gaussian deformation along the force vector."""
    if length_sq(force) < 1e-6:
        return p # Guard against NaN
    
    # Calculate perpendicular distance squared
    # d_perp^2 = ||p - c||^2 - ((p - c) . F)^2 / ||F||^2
    diff = p - C_CENTER
    dot_prod = dot(diff, force)
    len_sq_f = length_sq(force)
    d_perp_sq = length_sq(diff) - (dot_prod * dot_prod) / len_sq_f
    
    # Gaussian kernel
    exponent = -d_perp_sq / (2.0 * SIGMA * SIGMA)
    kernel = exp(exponent) / (SIGMA * sqrt(2.0 * PI))
    
    # Deformation
    # p' = p + F * 5 * N
    deformed_p = p + force * 5.0 * kernel
    return deformed_p

def interpolate_edge(p1, p2, f1, f2):
    """Linear interpolation on an edge."""
    denom = abs(f1) + abs(f2)
    if denom < 1e-6:
        return p1 # Guard against division by zero
    alpha = abs(f1) / denom
    return (1.0 - alpha) * p1 + alpha * p2

def process_voxel(voxel_pos, force, edge_table_tex, tri_table_tex):
    """
    Process a single voxel/cube in the geometry shader.
    Returns a list of triangles (each triangle is a list of 3 deformed vertices).
    """
    # 1. Evaluate scalar field at 8 corners
    # Assuming voxel_pos is the center or a corner; adjust based on grid setup
    # Here we assume voxel_pos is the origin of the cube for simplicity, 
    # or the input points are the cube corners. 
    # Based on S1, input points represent voxel grid positions.
    # We need the 8 corners of the cube associated with this point.
    # Let's assume voxel_pos is the min-corner (0,0,0) of the cube relative to grid.
    
    corners = []
    for i in range(8):
        # Generate corner offset
        x = (i & 1) * GRID_SIZE
        y = (i & 2) * GRID_SIZE
        z = (i & 4) * GRID_SIZE
        p = voxel_pos + (x, y, z)
        corners.append(p)
        
    f_values = [scalar_field(p) for p in corners]
    
    # 2. Compute cube index
    cube_index = 0
    for i in range(8):
        if f_values[i] < 0.0:
            cube_index |= (1 << i)
            
    # 3. Check edge table
    edge_config = texel_fetch(edge_table_tex, (cube_index, 0))
    if edge_config == 0:
        return []
        
    # 4. Compute intersection points for active edges
    intersections = {}
    for edge_idx in range(12):
        if (edge_config >> edge_idx) & 1:
            v1_idx, v2_idx = cube_diff_indices[edge_idx*2], cube_diff_indices[edge_idx*2+1]
            p1, p2 = corners[v1_idx], corners[v2_idx]
            f1, f2 = f_values[v1_idx], f_values[v2_idx]
            interp_p = interpolate_edge(p1, p2, f1, f2)
            intersections[edge_idx] = interp_p
            
    # 5. Generate triangles
    triangles = []
    tri_config = texel_fetch(tri_table_tex, (cube_index, 0))
    
    # Iterate through tri_config in steps of 3
    for i in range(0, 24, 3):
        v1_idx = tri_config[i]
        v2_idx = tri_config[i+1]
        v3_idx = tri_config[i+2]
        
        if v1_idx == -1:
            break
            
        p1 = intersections[v1_idx]
        p2 = intersections[v2_idx]
        p3 = intersections[v3_idx]
        
        # Apply deformation
        dp1 = gaussian_deformation(p1, force)
        dp2 = gaussian_deformation(p2, force)
        dp3 = gaussian_deformation(p3, force)
        
        # Compute normal (optional for this step, needed for fragment shader)
        # normal = normalize(cross(dp2 - dp1, dp3 - dp1))
        
        triangles.append([dp1, dp2, dp3])
        
    return triangles
```

### Parameters
*   **gridSize:** Uniform float defining the voxel edge length. Typical value: `0.25f` [S1, unofficial].
*   **i_force:** Uniform `vec3` defining the deformation direction and magnitude. Passed from CPU [S1, unofficial].
*   **sigma:** Constant float set to `0.8`, controlling the width of the Gaussian deformation falloff [S1, unofficial].
*   **lightPos:** Light position in world space [S2, unofficial].

### Edge Cases and Pitfalls
*   **Zero Force Vector:** If $\mathbf{F}$ is zero, the division by $\|\mathbf{F}\|^2$ in the deformation formula causes a NaN. The source code does not explicitly guard against this [S1, unofficial].
*   **Degenerate Edges:** If both scalar field values at an edge's endpoints are exactly 0.0, the interpolation denominator becomes 0.0, causing a division by zero. The source code does not handle this degenerate case [S1, unofficial].
*   **Matrix Multiplication Order:** The geometry shader in the Unity variant uses `mul(UNITY_MATRIX_MVP, unity_WorldToObject)`, which multiplies MVP by WorldToObject. Standard transformation is `VP * World * Vertex`. This code likely produces incorrect clip-space positions [S2, unofficial].
*   **Backward Pushing:** If the dot product of the displacement vector and force is non-positive, the deformation is skipped to prevent backward pushing. This is handled by an early return in the source [S1, unofficial].

## Operating characteristics

*   **Time Complexity:** $O(1)$ per voxel processed by the geometry shader, as it performs a fixed number of texture fetches and arithmetic operations regardless of grid resolution. Total complexity is $O(N)$ for $N$ voxels [S1, unofficial].
*   **Memory Complexity:** Dominated by the storage of the lookup tables in GPU texture memory and the input voxel grid. The lookup tables are small ($256 \times 1$ integers) [S1, unofficial].
*   **Performance:** Implemented in a custom OpenGL 3.3+ application for real-time deformable terrain/mesh interaction [S1, unofficial]. The use of geometry shaders allows for on-the-fly deformation without CPU-GPU synchronization for mesh updates.
*   **Strengths:** Real-time performance, dynamic deformation, simple implementation on GPU.
*   **Limitations:** Limited to regular grids, potential numerical instability with degenerate cases, incorrect matrix multiplication in some variants.

## Background

*   **Origin:** The method is based on the standard Marching Cubes algorithm [30-isosurface-extraction.md], adapted for real-time rendering using geometry shaders. The specific implementation with Gaussian deformation was developed for the NtslMaterial geometry shader in a custom OpenGL application [S1, unofficial].
*   **History:** Marching Cubes was originally introduced by Lorensen and Cline in 1987. The geometry shader variant leverages the programmable pipeline introduced in OpenGL 3.2+ to perform surface extraction and deformation in a single pass.
*   **Usage:** Used in real-time applications requiring dynamic surface deformation, such as terrain editing or fluid interaction simulations [S1, unofficial].
