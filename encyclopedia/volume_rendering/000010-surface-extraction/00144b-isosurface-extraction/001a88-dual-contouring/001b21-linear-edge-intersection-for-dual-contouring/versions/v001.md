# Linear Edge Intersection for Dual Contouring

Also called: Dual Contouring (Simple Mean Intersection), Simple Mean Intersection

## Overview
Linear Edge Intersection is a method for determining the position of a single vertex inside a grid cell that intersects an isosurface. It solves the vertex placement problem in Dual Contouring by computing the arithmetic mean of the points where the cell's edges cross the isosurface [S1]. Unlike Topologically Accurate Dual Isosurfacing, which uses ray casting to handle complex topology, or the QEF Solver, which minimizes a quadratic error function based on surface normals, this method relies solely on geometric interpolation of edge crossings [S1]. It is chosen for its simplicity and speed, serving as the baseline vertex placement strategy when gradient information is unavailable or when topological accuracy is not the primary concern [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   `origin`: The 3D coordinates of the cell's corner with the lowest indices (e.g., $(i, j, k)$) [S1].
*   `dirs`: An array of 3 vectors representing the cell's edge directions (typically $\Delta x \hat{x}, \Delta y \hat{y}, \Delta z \hat{z}$) [S1].
*   `vertices`: An array of 8 scalar values corresponding to the function values at the cell's 8 vertices, ordered in Morton (Z-order) [S2].
*   `level`: The isovalue threshold (default 0.0) [S2].
*   `compute_normals`: Boolean flag. If `True`, normals are computed; if `False`, only points are returned [S2].

**Outputs:**
*   `surface_point`: A 3D vector representing the estimated isosurface location within the cell [S1].
*   `valid`: A boolean indicating whether the cell intersects the isosurface [S1].
*   `points`: (Optional) An $(N, 3)$ float32 tensor of intersection points on the edges [S2].
*   `normals`: (Optional) An $(N, 3)$ float32 tensor of normals at those points [S2].

### Data Structures
*   **Edge Lookup Table**: A static array of 24 integers defining the 12 edges of the cube. Each edge is defined by two vertex indices. The order is:
    ```python
    edges = [
        0, 4, 1, 5, 2, 6, 3, 7,  # Edges along X-axis (conceptually, based on Morton order mapping)
        0, 2, 1, 3, 4, 6, 5, 7,  # Edges along Y-axis
        0, 1, 2, 3, 4, 5, 6, 7   # Edges along Z-axis
    ]
    ```
    *Note: The specific mapping of vertex indices to Morton order is: v0:(0,0,0), v1:(0,0,1), v2:(0,1,0), v3:(0,1,1), v4:(1,0,0), v5:(1,0,1), v6:(1,1,0), v7:(1,1,1) [S2].*

### Algorithm Steps
1.  **Check Intersection**: Iterate through the 8 `vertices`. If all values are $\ge level$ or all are $< level$, the cell does not intersect the isosurface. Return `false` [S1].
2.  **Initialize Accumulators**: Set `mean = (0, 0, 0)` and `count = 0` [S1].
3.  **Iterate Edges**: Loop over $i$ from 0 to 11 (representing the 12 edges).
    a.  Get vertex indices: $v_1 = edges[2i]$, $v_2 = edges[2i+1]$ [S1].
    b.  Get values: $a = vertices[v_1]$, $b = vertices[v_2]$ [S1].
    c.  **Check Crossing**: If $a \cdot b > 0$ (after adjusting for `level`), the edge does not cross the isosurface. Skip to next edge [S1].
    d.  **Interpolate**: Calculate the interpolation parameter $x$:
        $$ \text{denom} = |b - a| $$
        $$ x = \begin{cases} 0.5 & \text{if } \text{denom} < \epsilon \\ \frac{|a|}{\text{denom}} & \text{otherwise} \end{cases} $$
        Where $\epsilon = 10^{-15}$ [S1].
    e.  **Calculate Point**: Compute the intersection point $p$:
        $$ p = \text{origin} + \text{dirs}[0] \cdot \lfloor v_1 / 4 \rfloor + \text{dirs}[1] \cdot \lfloor (v_1 \pmod 4) / 2 \rfloor + \text{dirs}[2] \cdot (v_1 \pmod 2) + \text{dirs}[i // 4] \cdot x $$
        Add $p$ to `mean` and increment `count` [S1].
4.  **Finalize Point**: If `count > 0`:
    $$ \text{surface\_point} = \text{origin} + \frac{\text{mean}}{\text{count}} $$
    Return `true` and `surface_point` [S1].
5.  **Gradient-Based Refinement (Optional)**: If gradients are provided and `count >= 3`:
    a.  Construct matrix $A$ where row $i$ is the gradient at the $i$-th intersection point.
    b.  Construct vector $b$ where $b_i = \text{dot}(\text{gradient}_i, \text{point}_i)$ [S1].
    c.  Solve $A q = b$ using least squares.
    d.  **Boundary Check**: If $q$ is outside the cell bounds ($\text{origin}$ to $\text{origin} + \sum \text{dirs}$), fallback to the mean calculated in Step 4 [S1].

### Pseudocode
```python
def compute_cell(origin, dirs, vertices, level=0.0, compute_normals=False):
    """
    Computes the dual contouring vertex for a single cell using linear edge intersection.
    
    Args:
        origin: Vector3, corner of the cell.
        dirs: List of 3 Vectors, edge directions (delta_x, delta_y, delta_z).
        vertices: List of 8 floats, function values at cell vertices (Morton order).
        level: Float, isovalue.
        compute_normals: Bool, whether to compute normals (not implemented in basic linear intersection).
        
    Returns:
        (valid: bool, point: Vector3)
    """
    SMALL_NUMBER = 1e-15
    
    # Adjust vertices relative to level
    adjusted_vertices = [v - level for v in vertices]
    
    # Check if cell intersects isosurface
    has_negative = any(v < 0 for v in adjusted_vertices)
    has_positive = any(v > 0 for v in adjusted_vertices)
    
    if not has_negative or not has_positive:
        return False, None

    # Edge lookup table (Morton order vertices: 000, 001, 010, 011, 100, 101, 110, 111)
    edges = [
        0, 4, 1, 5, 2, 6, 3, 7,  # X-like edges
        0, 2, 1, 3, 4, 6, 5, 7,  # Y-like edges
        0, 1, 2, 3, 4, 5, 6, 7   # Z-like edges
    ]
    
    mean = Vector3(0, 0, 0)
    count = 0
    
    for i in range(12):
        v1_idx = edges[2 * i]
        v2_idx = edges[2 * i + 1]
        
        a = adjusted_vertices[v1_idx]
        b = adjusted_vertices[v2_idx]
        
        # If signs are same, no intersection
        if a * b > 0:
            continue
            
        denom = abs(b - a)
        
        # Linear interpolation parameter
        if denom < SMALL_NUMBER:
            x = 0.5
        else:
            x = abs(a) / denom
            
        # Base position of vertex v1
        # v1 is encoded as: bit0=z, bit1=y, bit2=x in Morton order? 
        # Based on C++ code: dirs[0]*(v1/4) + dirs[1]*((v1%4)/2) + dirs[2]*(v1%2)
        # This implies: v1/4 selects X-dir, (v1%4)/2 selects Y-dir, v1%2 selects Z-dir
        # This corresponds to Morton order where X is MSB? 
        # Let's stick to the formula provided in S1 exactly.
        
        base_point = (
            dirs[0] * (v1_idx // 4) + 
            dirs[1] * ((v1_idx % 4) // 2) + 
            dirs[2] * (v1_idx % 2)
        )
        
        # Add edge direction component
        edge_dir = dirs[i // 4]
        intersection_point = origin + base_point + edge_dir * x
        
        mean += intersection_point
        count += 1
        
    if count == 0:
        return False, None
        
    surface_point = origin + mean / count
    return True, surface_point
```

### Parameters
*   `SMALL_NUMBER`: $10^{-15}$, used to prevent division by zero during interpolation [S1].
*   `level`: Default 0.0 [S2].

### Edge Cases and Pitfalls
*   **Degenerate Edges**: If $a \approx b$ (denom < $\epsilon$), the interpolation parameter is set to 0.5 [S1].
*   **No Intersection**: If all vertex values are on one side of the isosurface, the function returns false, and no vertex is generated for that cell [S1].
*   **Gradient Fallback**: If gradient-based positioning is used but the resulting point lies outside the cell, the method falls back to the mean intersection point [S1].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per cell, as it iterates over a fixed 12 edges and 8 vertices.
*   **Memory Complexity**: $O(1)$ auxiliary memory per cell.
*   **Performance**: Very fast due to simple arithmetic operations. Suitable for real-time applications or large grids where QEF solving is too expensive [S1].
*   **Strengths**: Simple implementation, no need for gradient computation or matrix solvers, robust for simple isosurfaces.
*   **Limitations**: Less accurate than QEF-based methods, especially for curved surfaces. Does not guarantee topological correctness in complex scenarios [S1].
*   **When to Use**: When speed is critical, gradients are unavailable, or the isosurface is relatively smooth and simple.
*   **When Not to Use**: When high geometric accuracy is required, or when the isosurface has complex topology that requires topological guarantees.

## Background
The method originates from the basic implementation of Dual Contouring, where the vertex position is approximated by the mean of edge intersections [S1]. It is often referred to as "Simple Mean Intersection" in contrast to more advanced variants that use QEF solvers [S1]. The implementation details are found in open-source libraries such as `salvipeter/dual-contouring` [S1] and `GuangyanCai/isoext` [S2].
