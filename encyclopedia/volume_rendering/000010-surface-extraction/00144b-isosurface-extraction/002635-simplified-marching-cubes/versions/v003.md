# Simplified Marching Cubes

Also called: SMC discretization, binarized Marching Cubes

## Overview
Simplified Marching Cubes (SMC) is an isosurface extraction method that generates meshes using only vertices from the regular 3D grid, eliminating the need for linear interpolation and large lookup tables [S1]. It produces meshes with approximately half the vertices and triangles of standard Marching Cubes (MC) and Cuberille, resulting in significantly lower memory requirements and faster computation, particularly for simulations involving moving boundaries [S1]. Unlike standard MC, SMC guarantees manifold meshes without holes by analyzing cube configurations independently using integer arithmetic and cumulative node coordinates [S1].

## How it works
SMC operates by binarizing the input scalar field and processing each voxel (cube) to determine triangle connectivity based on the count and position of "positive" vertices (nodes) relative to a threshold [S1].

### Inputs and Outputs
*   **Input**: A 3D scalar field $F(x, y, z)$ and a threshold value $\lambda$.
*   **Output**: A list of triangles, where each triangle is defined by three indices into a vertex list. The vertices are restricted to the integer grid coordinates.

### Data Structures
1.  **Vertex List**: Stores integer coordinates. Each vertex uses 3 `short` (2-byte) integers, allowing coordinates $< 65535$ [S1].
2.  **Triangle List**: Stores vertex indices. Each triangle uses 3 `long` (4-byte) integers [S1].
3.  **Cube State**: For each cube, the algorithm determines the set of positive vertices (nodes).

### Vertex and Coordinate Definitions
Each cube has 8 vertices indexed $n \in \{0, \dots, 7\}$. The normalized coordinates $c_x^n \in \{0, 1\}$ for axes $x \in \{i, j, k\}$ are derived from the index $n$:
$$
c_i^n = n \% 2, \quad c_j^n = (n \% 4) / 2, \quad c_k^n = n / 4
$$
where `/` is integer division and `%` is the remainder [S1].

A vertex is a **node** (positive) if $F(v) \ge \lambda$, otherwise it is a **negative vertex** [S1].
An **interface node** is a node that has at least one negative neighbor in 6-connectivity [S1].

### Triangle Types
SMC produces three types of triangles, classified by a criterion $C_L$:
1.  **Type I**: Isosceles-right triangle. $C_L = 6$.
2.  **Type II**: Right triangle. $C_L = 14$.
3.  **Type III**: Equilateral triangle. $C_L = 12$ [S1].

The criterion $C_L$ for a triangle with vertices $n_1, n_2, n_3$ is:
$$
C_L(n_1, n_2, n_3) = \sum_{l=1}^3 \sum_{m=l+1}^3 \left( \sum_{x=i,j,k} (c_x^{n_l} - c_x^{n_m})^2 \right)^2
$$
[G: This formula calculates the squared sum of squared edge lengths, effectively distinguishing the geometric shape of the triangle formed by grid vertices.]

### Algorithm Steps
The algorithm processes each cube independently. It does not use a global lookup table for case identification but evaluates the configuration based on the number of nodes and their cumulative coordinates.

**Step 1: Binarization and Node Identification**
Identify all positive vertices (nodes) in the current cube. Let $N_{nodes}$ be the count of nodes.

**Step 2: Cumulative Coordinates**
Compute the cumulative coordinates $C_x$ for each axis $x \in \{i, j, k\}$:
$$
C_x = \sum_{n \in \{\text{nodes}\}} c_x^n
$$
These values help identify subcases without a lookup table [S1].

**Step 3: Case Handling**
Based on $N_{nodes}$, determine the output triangles. If $N_{nodes} \in \{0, 1, 2, 8\}$, output no triangles [S1].

*   **3 Nodes**:
    *   If $C_x = 0$ or $3$ for any axis $x$, the three nodes lie on a single face. Output **one Type I triangle** [S1].
    *   Otherwise, no triangles (degenerate/invalid in this context per source logic, though standard MC might handle differently; SMC logic implies specific geometric constraints) [S1]. *Note: The source lists cases 5, 6, 7. Only the subcase with $C_x=0$ or $3$ yields a triangle.*

*   **4 Nodes**:
    *   **Case 8**: If $C_x = 0$ or $4$ for any axis $x$, the nodes lie on a face. Output **two Type I triangles** on that face [S1].
    *   **Cases 10/13**: If $C_x = 2$ for all axes $x$, output **no triangles** [S1].
    *   **Case 9**: Identify the single non-interface node (a node with 3 node neighbors). Output **one Type III triangle** formed by the remaining three interface nodes [S1].
    *   **Case 12**: Identify the singular node with only negative neighbors. Switch its status to positive (conceptually), then re-process as 3 nodes (Case 8 logic) to build **one Type I triangle** [S1].
    *   **Cases 11/14**: Output **two Type II triangles**. These are identified by iterating over the nodes [S1].

*   **5 Nodes**:
    *   **Case 17**: If $C_x = 1$ or $4$ for any axis $x$, output **two Type II triangles** [S1].
    *   **Case 15**: Identify the singular node with only negative neighbors. Switch its status, then re-process as 3 nodes (Case 9 logic) to build **one Type III triangle** [S1].
    *   **Case 16**: Identify the Type III triangle via nested loops. Find the negative vertex with node neighbors, switch its status, then re-process as 6 nodes (Case 20 logic) to build the remaining triangles (**two Type II, one Type III**) [S1].

*   **6 Nodes**:
    *   **Cases 18/19**: Identify two negative vertices that have only node neighbors. Build **two Type III triangles** formed by their respective neighbors [S1].
    *   **Case 20**: Output **two Type II triangles** formed by correctly ordered interface nodes [S1].

*   **7 Nodes**:
    *   Identify the single negative vertex. Form **one Type III triangle** using its three neighbors (which are interface nodes) [S1].

        C_i = sum(get_coords(n)[0] for n in node_indices)
        C_j = sum(get_coords(n)[1] for n in node_indices)

        # Neighbors in 6-connectivity

            if neighbor not in node_set:

### Parameters and Edge Cases
*   **Threshold $\lambda$**: Only the binary status (above/below) matters. The magnitude of the difference is ignored [S1].
*   **Precision**: SMC uses integer arithmetic exclusively, avoiding floating-point interpolation errors [S1].
*   **Ambiguity**: SMC avoids the topological ambiguities of standard MC (cases 46, 47, etc.) by using the "MC-patch" logic and treating configurations 11 and 14 as identical (symmetrical), ensuring manifold meshes [S1].
*   **Bias**: SMC systematically produces negative volume biases for convex objects and positive surface bias for concave objects. The volume bias is larger than in MC or Cuberille [S1].

## Operating characteristics
*   **Time Complexity**: SMC is faster than standard MC, with speedup increasing as the internal surface area increases [S1].
*   **Memory Complexity**: Memory requirements are half of MC and Cuberille. Vertices use 2 bytes per coordinate (3 shorts), triangles use 4 bytes per index (3 longs) [S1].
*   **Accuracy**: SMC accuracy is lower than standard MC but higher than Cuberille. For a discretized sphere, SMC surface error converges to 7%, while MC converges to ~0.4% [S1]. Normal RMS errors are comparable in binarized images (~10-12 degrees) but higher in smooth images compared to MC [S1].
*   **Strengths**: Efficient for large images, moving boundary problems, and simulations (e.g., CVI, ablation) where integer arithmetic and manifold guarantees are critical [S1].
*   **Limitations**: Lower geometric accuracy for smooth surfaces compared to interpolated MC. Systematic bias in volume/surface area estimation [S1].

## Background
Simplified Marching Cubes was developed for materials science simulations, specifically for computing effective diffusivities in porous media and simulating matrix deposition in Chemical Vapor Infiltration (CVI) and ablation modeling [S1]. It was proposed as an efficient alternative to standard MC to handle large-scale 3D blocks and moving boundaries without the computational overhead of interpolation and large lookup tables [S1].
