# Simplified Marching Cubes

Also called: SMC discretization, binarized Marching Cubes

## Overview
Simplified Marching Cubes (SMC) is a surface extraction method that generates meshes using only vertices from the input voxel grid, eliminating the need for linear interpolation and large lookup tables [S1]. It produces manifold meshes with approximately half the vertices and triangles of standard Marching Cubes (MC) and Cuberille, significantly reducing memory usage while maintaining intermediate accuracy [S1]. Unlike MC, which interpolates intersection points, SMC relies on integer arithmetic and cumulative coordinate analysis to determine triangle topology [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A scalar field $F(x, y, z)$ sampled on a regular 3D grid (cuberille grid).
- **Output:** A triangular mesh consisting of vertices from the grid and triangles connecting them.

**Data Structures:**
- **Grid:** Regular 3D grid where each cell is a cube defined by 8 vertices.
- **Vertex Coordinates:** Each vertex $n$ ($0 \le n \le 7$) in a cube has normalized binary coordinates $c_x^n \in \{0, 1\}$ for axes $x \in \{i, j, k\}$. The mapping is:
  $$c_i^n = n \% 2$$
  $$c_j^n = (n \% 4) / 2$$
  $$c_k^n = n / 4$$
- **Triangle Memory:** 3 long (4-byte) integers per triangle, storing vertex indices.
- **Vertex Memory:** 3 short (2-byte) integers per vertex, storing integer coordinates (must be $< 65535$) [S1].
- **Cube Data Structure (for simulation coupling):** 1 byte for case indicator (0-7), 2 bytes for normal coefficients $(h, k, l)$ of up to two planes, and 4 bytes for integer $m$ of up to two planes, totaling 7 bytes [S1].

**Parameters:**
- **Threshold $\lambda$:** Scalar value defining the isosurface. Vertices with $F(x, y, z) \ge \lambda$ are "positive" (nodes); others are "negative" [S1]. Only the relative status matters, not the magnitude [S1].

**Algorithm Steps:**
The algorithm processes each cube independently. It does not use a lookup table to identify equivalent cases but evaluates the configuration directly [S1].

1.  **Binarization:** Convert the scalar field $F$ into a binary field $F_B$:
    $$F_B = \begin{cases} 1 & \text{if } F(x, y, z) \ge \lambda \\ 0 & \text{else} \end{cases}$$
    Identify the set of "nodes" (positive vertices) in the current cube [S1].

2.  **Count Nodes:** Compute the total number of nodes $N_{nodes}$ in the cube.
    - If $N_{nodes} \in \{0, 1, 2, 8\}$, output no triangles [S1].

3.  **Compute Cumulative Coordinates:** For each axis $x \in \{i, j, k\}$, compute the cumulative coordinate $C_x$:
    $$C_x = \sum_{n \in \{\text{nodes}\}} c_x^n$$
    This sum helps identify subcases without a lookup table [S1].

4.  **Identify Interface Nodes:** An interface node is a positive vertex with at least one negative neighbor in 6-connectivity. The number of node neighbors $N_x(n)$ for vertex $n$ along axis $x$ is computed as:
    $$N_i(n) = \overline{c_i^n} + 2 \times c_j^n + 4 \times c_k^n$$
    where $\overline{c}$ is the complement to 1 of $c$ [S1]. Interface nodes have fewer than 3 node neighbors in 6-connectivity [S1].

5.  **Classify Triangles:** Determine triangle types using the criterion $C_L$:
    $$C_L(n_1, n_2, n_3) = \sum_{l=1}^3 \sum_{m=l+1}^3 \left( \sum_{x=i,j,k} (c_x^{n_i} - c_x^{n_m})^2 \right)^2$$
    - Type I (isosceles-right): $C_L = 6$
    - Type II (rectangle): $C_L = 14$
    - Type III (equilateral): $C_L = 12$ [S1]

6.  **Generate Triangles based on Node Count:**
    - **3 Nodes:**
        - If $C_x = 0$ or $3$ for any $x \in \{i, j, k\}$, output one Type I triangle (nodes on a single face) [S1].
    - **4 Nodes:**
        - **Case 8:** If $C_x = 0$ or $4$ for any $x$, output two Type I triangles on the adequate face [S1].
        - **Cases 10/13:** If $C_x = 2$ for all $x$, output no triangles [S1].
        - **Case 9:** Identify the single non-interface node via exhaustive test. Output one Type III triangle formed by the remaining interface nodes [S1].
        - **Case 12:** Identify the singular node with only negative neighbors. Switch its status to positive, then re-process as 3 nodes (Case 8 logic) to build one Type I triangle [S1].
        - **Cases 11/14:** Output two Type II triangles, identified by nested loops over nodes [S1].
    - **5 Nodes:**
        - **Case 17:** If $C_x = 1$ or $4$ for any $x$, output two Type II triangles, identified by nested loops over nodes [S1].
        - **Case 15:** Identify singular node with only negative neighbors. Switch its status, then re-process as 3 nodes (Case 9 logic) to build one Type III triangle [S1].
        - **Case 16:** Identify Type III triangle via nested loops. Find the negative vertex with node neighbors, switch its status, then re-process as 6 nodes (Case 20 logic) to build the remaining triangles (two Type II, one Type III) [S1].
    - **6 Nodes:**
        - **Cases 18/19:** Identify two negative vertices that have only node neighbors via exhaustive test. Build two Type III triangles formed by their neighbors [S1].
        - **Case 20:** Output two Type II triangles formed by correctly ordered interface nodes [S1].
    - **7 Nodes:**
        - Identify the single negative vertex. Form one Type III triangle using its three neighbors (which are interface nodes) [S1].

def get_6_neighbors(n):
    # Returns indices of 6-connected neighbors within the cube
    # Neighbors are those differing by 1 bit in binary representation
    neighbors = []
    for i in range(3):
        neighbor = n ^ (1 << i)
        if 0 <= neighbor <= 7:
            neighbors.append(neighbor)
    return neighbors

def find_singular_node(nodes):
    # Find node with only negative neighbors
    for n in nodes:
        neighbors = get_6_neighbors(n)
        if all(not is_node(nb) for nb in neighbors):

    return None

## Operating characteristics
- **Time Complexity:** SMC computation is faster than standard MC, with speedup increasing as internal surface area increases [S1].
- **Memory Complexity:** Memory requirements are half of MC and Cuberille. Vertices use 3 short integers (6 bytes), triangles use 3 long integers (12 bytes) [S1].
- **Accuracy:** SMC accuracy is lower than standard MC but higher than Cuberille. For a discretized sphere, SMC surface error converges to 7%, while MC converges to ~0.4% and Cuberille to 90% [S1]. In binarized images, normal RMS errors are comparable (~10-12 degrees); in smooth images, MC error is ~4-6 degrees while SMC remains ~10-12 degrees [S1].
- **Bias:** SMC systematically produces negative volume biases for convex objects (negative surface bias) and positive surface bias for concave objects. The volume bias is larger than MC or Cuberille [S1].
- **Strengths:** Efficient for large images and moving boundary problems (e.g., deposition/ablation). Guarantees manifold meshes without holes [S1].
- **Limitations:** Lower accuracy for smooth surfaces compared to MC. Approximation of smooth surfaces introduces a non-vanishing positive bias in surface estimation regardless of sampling rate [S1].

## Background
Simplified Marching Cubes was developed for materials science simulations, specifically for computing effective diffusivities in porous media and simulating matrix deposition in Chemical Vapor Infiltration (CVI) and ablation modeling [S1]. It was proposed as an efficient alternative to MC for simulations of deposition/ablation in complex media, where computational speed and memory efficiency are critical [S1]. The method relies on the "MC-patch" logic to ensure topological consistency, treating configurations 11 and 14 as identical [S1].
