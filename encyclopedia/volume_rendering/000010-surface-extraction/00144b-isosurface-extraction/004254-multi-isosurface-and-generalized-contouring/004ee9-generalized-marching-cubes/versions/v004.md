# Generalized Marching Cubes

Also called: Multi-material Contouring, Multi-material Marching Cubes Extraction

## Overview
Generalized Marching Cubes extracts triangulated mesh surfaces from volumetric data containing multiple distinct materials, rather than a single scalar field thresholded against one isovalue [S1, unofficial][S2]. It solves the problem of identifying boundaries between different material types within a voxel grid by dynamically selecting isovales based on the specific pair of materials adjacent to a voxel edge [S2]. Unlike standard Marching Cubes which assumes a uniform background or single material interface, this method generates non-manifold surface meshes where three or more materials meet, ensuring that each individual material boundary remains a manifold surface [S2].

## How it works
The method operates on a classified volumetric model where each voxel possesses both a material type identifier and a continuous CT value (or intensity). The process differs from standard Marching Cubes by replacing the global binary sign test with a material-pair boundary detection logic.

### Inputs and Outputs
*   **Input:** A 3D volume tensor `vol` of shape $(D, H, W)$, where each voxel stores a material label and a CT value.
*   **Output:** A triangulated mesh (OBJ format) containing vertices and faces. Vertices are offset by material index to prevent index collisions [S1, unofficial].

### Data Structures
1.  **Voxel Grid:** A 3D array where each element contains:
    *   `material_id`: Integer identifier for the material class (e.g., 0 for Air, 1 for Aluminum).
    *   `ct_value`: Floating-point intensity value.
2.  **Edge Table:** Derived from the parent [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md), but modified. Instead of binary signs, the configuration is determined by whether the two endpoints of an edge belong to different materials.
3.  **Triangle Table:** Standard connectivity table from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md), mapping the edge intersection configuration to triangle indices.

### Parameters
*   `nmaterials`: Number of distinct attenuation ranges or material classes [S1, unofficial].
*   `pitch`: Voxel spacing (default 1.0) [S1, unofficial].
*   `iso(A, B)`: The isovalue used to detect the boundary between material A and material B. This value is typically derived from the average CT values of the two materials or determined via multi-Otsu thresholding [S1, unofficial][S2].

### Steps

1.  **Preprocessing and Classification:**
    *   If the input is raw intensity data, classify voxels into material types. This can be done using region growing, Graph-cut, or multi-Otsu thresholding [S1, unofficial][S2].
    *   Normalize the volume to $[0, 1]$ if required by the implementation:
        $$ vol_{norm} = \frac{vol - vol_{min}}{vol_{max} - vol_{min} + \epsilon} $$
        where $\epsilon = 10^{-12}$ to avoid division by zero [S1, unofficial].

2.  **Isovalue Determination:**
    *   For every pair of materials $(A, B)$ that are adjacent in the grid, determine the specific isovalue $iso(A, B)$ [S2].
    *   The condition for a boundary between material A (voxel $p$) and material B (voxel $q$) is that the CT value $I_p$ and $I_q$ must bracket the isovalue:
        $$ I_p < iso(A, B) < I_q \quad \text{or} \quad I_q < iso(A, B) < I_p $$
        [S2].

3.  **Voxel Processing (Generalized Marching Cubes):**
    *   Iterate over every cubic cell in the volume. The corners of the cell are voxels with associated material types and CT values.
    *   For each of the 12 edges of the cube, check the material types of the two endpoints.
    *   **Case 1: Same Material.** If both endpoints have the same material type, no vertex is inserted on this edge.
    *   **Case 2: Different Materials.** If the endpoints have different material types (e.g., Material A and Material B), insert a vertex on the edge.
    *   **Vertex Position:** Compute the position of the vertex using linear interpolation based on the CT values of the endpoints. Let the edge connect voxel $p$ (CT value $I_p$, material $A$) and voxel $q$ (CT value $I_q$, material $B$). The interpolation factor $t$ is:
        $$ t = \frac{iso(A, B) - I_p}{I_q - I_p} $$
        The vertex position $V$ is:
        $$ V = (1 - t) P_p + t P_q $$
        where $P_p$ and $P_q$ are the geometric coordinates of the voxel corners [S2].

4.  **Mesh Construction:**
    *   Determine the triangle connectivity using the standard Marching Cubes triangle table, but only for edges where intersections were created (i.e., edges with different material endpoints) [S2].
    *   If multiple materials meet at a vertex (non-manifold junction), the mesh will contain non-manifold edges. However, the surface for any single material pair remains manifold [S2].
    *   Write the output to an OBJ file. Vertices are offset by `vert_start` (often the material index or a cumulative count) to ensure unique indices across different material segments [S1, unofficial].

### Pseudocode

```python
def generalized_marching_cubes(volume, material_labels, isovalue_map, pitch=1.0):
    """
    Extracts multi-material isosurfaces.
    
    Args:
        volume: 3D numpy array of CT values.
        material_labels: 3D numpy array of integer material IDs.
        isovalue_map: Dictionary mapping tuple (mat_A, mat_B) to float isovalue.
        pitch: Voxel spacing.
        
    Returns:
        vertices: List of (x, y, z) coordinates.
        faces: List of (v1, v2, v3) indices.
    """
    D, H, W = volume.shape
    vertices = []
    faces = []
    vert_offset = 0
    
    # Standard Marching Cubes edge table and triangle table from parent article
    edge_table = get_edge_table() # From 2518-marching-cubes-lookup-and-configuration.md
    triangle_table = get_triangle_table() # From 2518-marching-cubes-lookup-and-configuration.md

    for z in range(D - 1):
        for y in range(H - 1):
            for x in range(W - 1):
                # Get 8 corners of the cube
                corners = [
                    (x, y, z), (x+1, y, z), (x+1, y+1, z), (x, y+1, z),
                    (x, y, z+1), (x+1, y, z+1), (x+1, y+1, z+1), (x, y+1, z+1)
                ]
                
                corner_materials = [material_labels[c] for c in corners]
                corner_cts = [volume[c] for c in corners]
                
                # Determine edge intersections
                edge_intersections = []
                for edge_idx in range(12):
                    # Map edge index to corner indices (standard MC mapping)
                    c1_idx, c2_idx = get_edge_corners(edge_idx)
                    mat1 = corner_materials[c1_idx]
                    mat2 = corner_materials[c2_idx]
                    
                    if mat1 != mat2:
                        # Different materials: insert vertex
                        ct1 = corner_cts[c1_idx]
                        ct2 = corner_cts[c2_idx]
                        
                        # Get isovalue for this material pair
                        # Ensure consistent ordering for map lookup
                        pair = tuple(sorted([mat1, mat2]))
                        iso_val = isovalue_map.get(pair)
                        
                        if iso_val is None:
                            # Fallback: average of CT values if map not provided
                            iso_val = (ct1 + ct2) / 2.0
                            
                        # Interpolate
                        denom = ct2 - ct1
                        if abs(denom) < 1e-12:
                            t = 0.5
                        else:
                            t = (iso_val - ct1) / denom
                            
                        # Interpolate position
                        p1 = corners[c1_idx]
                        p2 = corners[c2_idx]
                        v_pos = (1 - t) * p1 + t * p2
                        edge_intersections.append((edge_idx, v_pos))
                    else:
                        edge_intersections.append((edge_idx, None))

                # Determine cube configuration based on which edges have intersections
                # In standard MC, config is based on sign. Here, config is based on 
                # presence of intersection (different materials).
                # However, standard MC triangle table assumes a specific topology.
                # Generalized MC uses the same triangle table but only considers 
                # edges with valid intersections.
                
                # Create binary mask for edges: 1 if intersection exists, 0 otherwise
                edge_mask = [1 if v is not None else 0 for _, v in edge_intersections]
                
                # Convert to integer configuration index (standard MC style)
                config = 0
                for i, bit in enumerate(edge_mask):
                    if bit:
                        config |= (1 << i)
                        
                # Look up triangles
                tri_indices = triangle_table[config]
                
                if tri_indices is not None:
                    for i in range(0, len(tri_indices), 3):
                        v1_idx = tri_indices[i]
                        v2_idx = tri_indices[i+1]
                        v3_idx = tri_indices[i+2]
                        
                        # Check if all three edges have valid intersections
                        # If an edge has no intersection (same material), 
                        # the triangle is invalid for this generalized step 
                        # unless the topology allows it (non-manifold).
                        # Standard generalized MC only forms triangles from 
                        # intersected edges.
                        
                        if edge_intersections[v1_idx][1] is not None and \
                           edge_intersections[v2_idx][1] is not None and \
                           edge_intersections[v3_idx][1] is not None:
                           
                            p1 = edge_intersections[v1_idx][1]
                            p2 = edge_intersections[v2_idx][1]
                            p3 = edge_intersections[v3_idx][1]
                            
                            # Add vertices with offset
                            idx1 = vert_offset
                            idx2 = vert_offset + 1
                            idx3 = vert_offset + 2
                            
                            vertices.append(p1)
                            vertices.append(p2)
                            vertices.append(p3)
                            
                            faces.append((idx1, idx2, idx3))
                            
                            vert_offset += 3
                        else:
                            # Edge case: Some edges don't intersect.
                            # In strict generalized MC, these triangles are skipped 
                            # or handled via non-manifold logic.
                            # For simplicity, we skip if any vertex is missing.
                            pass

    return vertices, faces
```

### Edge Cases and Pitfalls
*   **Division by Zero:** When interpolating, if $I_q = I_p$, the denominator is zero. Use a small epsilon ($10^{-12}$) or default to midpoint [S1, unofficial].
*   **Isovalue Selection:** If the isovalue map is not provided, the method may fail to correctly separate materials if CT values overlap. Accurate classification is critical [S2].
*   **Non-Manifold Geometry:** Where three or more materials meet, the resulting mesh is non-manifold. Standard mesh viewers may struggle with this. Each individual material surface, however, remains manifold [S2].
*   **Index Collisions:** Vertices from different materials must be offset to avoid index collisions in the final OBJ file [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels, as each voxel is processed once. The constant factor is higher than standard Marching Cubes due to material checks and interpolation.
*   **Memory Complexity:** $O(N)$ for storing the volume and labels. Output mesh size depends on the number of material interfaces.
*   **Strengths:** Accurately captures boundaries between multiple distinct materials in a single pass. Handles non-manifold junctions correctly.
*   **Limitations:** Requires pre-classified material labels. Performance degrades if the number of materials is very large due to the complexity of isovalue mapping. Non-manifold output may require post-processing for certain applications.
*   **When to Use:** Multi-material CT scans, segmented volumetric data with distinct material classes.
*   **When Not to Use:** Single-material scalar fields (use standard Marching Cubes).

## Background
Generalized Marching Cubes was introduced by Suzuki et al. in 2007 as an extension of the original Marching Cubes algorithm [S2, Suzuki et al. 2007]. It was developed to address the limitations of standard isosurfacing in medical and industrial CT imaging, where objects are composed of multiple materials (e.g., bone, soft tissue, air, or metal parts). The method allows for the extraction of boundary surfaces between different materials by dynamically adjusting the isovalue based on the material pair [S2]. It has been used in applications such as the extraction of isosurfaces from multi-material CT volumetric data of mechanical parts [S2].
