# Generalized Marching Cubes

Also called: Multi-material Contouring, Multi-material Marching Cubes Extraction

## Overview
Generalized Marching Cubes extracts triangulated mesh surfaces from volumetric data containing multiple distinct materials, rather than a single scalar field thresholded against one isovalue [S1, unofficial][S2]. It solves the problem of identifying boundaries between different material types within a voxel grid by dynamically selecting isovales based on the specific pair of materials adjacent to a voxel edge [S2]. Unlike standard Marching Cubes which assumes a uniform background or single material interface, this method generates non-manifold surface meshes where three or more materials meet, ensuring that each individual material boundary remains a manifold surface [S2].

## How it works
The method operates on a classified volumetric model where each voxel possesses both a material type identifier and a continuous CT value (or intensity) [S2]. The process differs from standard Marching Cubes by replacing the global binary sign test with a material-pair boundary detection logic [S2].

### Inputs and Outputs
* **Input:** A 3D volume tensor `vol` of shape $(D, H, W)$, where each voxel stores a material label and a CT value [S1, unofficial][S2].
* **Output:** A triangulated mesh (OBJ format) containing vertices and faces. Vertices are offset by `vert_start` to prevent index collisions across materials [S1, unofficial].

### Data Structures
1. **Voxel Grid:** A 3D array where each element contains:
   * `material_id`: Integer identifier for the material class (e.g., 0 for Air, 1 for Aluminum) [S2].
   * `ct_value`: Floating-point intensity value [S2].
2. **Edge Table:** Derived from the parent [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md), but modified to trigger intersections based on material-pair boundaries rather than scalar sign flips [S2].
3. **Triangle Table:** Standard connectivity table from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md), mapping the edge intersection configuration to triangle indices [S2].

### Parameters
* `nmaterials`: Number of distinct attenuation ranges or material classes [S1, unofficial].
* `pitch`: Voxel spacing (default 1.0) [S1, unofficial].
* `iso(A, B)`: The isovalue used to detect the boundary between material A and material B. This value is typically derived from the average CT values of the two materials or determined via multi-Otsu thresholding [S1, unofficial][S2].

### Steps

1. **Preprocessing and Classification:**
   * If the input is raw intensity data, classify voxels into material types. For two materials, apply Otsu thresholding and TV denoising [S1, unofficial]. For more than two materials, compute multi-Otsu thresholds and binarize the volume per material [S1, unofficial]. Alternatively, classification can be performed using region growing or Graph-cut segmentation [S2].
   * Normalize the volume to $[0, 1]$ if required by the implementation:
     $$ vol_{norm} = \frac{vol - vol_{min}}{vol_{max} - vol_{min} + 10^{-12}} $$
     where $\epsilon = 10^{-12}$ avoids division by zero [S1, unofficial].

2. **Isovalue Determination:**
   * For every pair of materials $(A, B)$ that are adjacent in the grid, determine the specific isovalue $iso(A, B)$ [S2].
   * The condition for a boundary between material A (voxel $p$, CT $I_p$) and material B (voxel $q$, CT $I_q$) is that the CT values must bracket the isovalue:
     $$ I_p < iso(A, B) < I_q \quad \text{or} \quad I_q < iso(A, B) < I_p $$
     [S2].

3. **Voxel Processing (Generalized Marching Cubes):**
   * Iterate over every cubic cell in the volume [S2]. The corners of the cell are voxels with associated material types and CT values [S2].
   * For each of the 12 edges of the cube, check the material types of the two endpoints [S2].
   * **Case 1: Same Material.** If both endpoints have the same material type, no vertex is inserted on this edge [S2].
   * **Case 2: Different Materials.** If the endpoints have different material types, insert a vertex on the edge [S2].
   * **Vertex Position:** Compute the position using linear interpolation based on the CT values of the endpoints [S2]. Let the edge connect voxel $p$ (CT $I_p$, material $A$) and voxel $q$ (CT $I_q$, material $B$) [S2]. The interpolation factor $t$ is:
     $$ t = \frac{iso(A, B) - I_p}{I_q - I_p} $$
     The vertex position $V$ is:
     $$ V = (1 - t) P_p + t P_q $$
     where $P_p$ and $P_q$ are the geometric coordinates of the voxel corners [S2].

4. **Mesh Construction:**
   * Determine triangle connectivity using the standard Marching Cubes triangle table, considering only edges with intersections (different material endpoints) [S2].
   * If multiple materials meet at a vertex (non-manifold junction), the mesh will contain non-manifold edges [S2]. However, the surface for any single material pair remains manifold [S2].
   * Write the output to an OBJ file. Vertices are offset by `vert_start` (often the material index or a cumulative count) to ensure unique indices across different material segments [S1, unofficial].

### Pseudocode

```python
def generalized_marching_cubes(volume, material_labels, isovalue_map, pitch=1.0):
    """
    Extracts multi-material isosurfaces using Generalized Marching Cubes.
    
    Args:
        volume: 3D numpy array of CT values, shape (D, H, W).
        material_labels: 3D numpy array of integer material IDs, shape (D, H, W).
        isovalue_map: Dict mapping frozenset({mat_A, mat_B}) to float isovalue.
        pitch: Voxel spacing.
        
    Returns:
        vertices: List of (x, y, z) coordinates.
        faces: List of (v1, v2, v3) indices.
    """
    D, H, W = volume.shape
    vertices = []
    faces = []
    vertex_cache = {}

    EDGE_CORNERS = (
        (0, 1), (1, 2), (2, 3), (3, 0),  # Bottom face
        (4, 5), (5, 6), (6, 7), (7, 4),  # Top face
        (0, 4), (1, 5), (2, 6), (3, 7)   # Vertical edges
    )
    
    # Standard 256-entry triangle table from Marching Cubes Lookup and Configuration [G]
    TRIANGLE_TABLE = MARCHING_CUBES_TRIANGLE_TABLE

    for z in range(D - 1):
        for y in range(H - 1):
            for x in range(W - 1):
                corners = [
                    (x, y, z), (x+1, y, z), (x+1, y+1, z), (x, y+1, z),
                    (x, y, z+1), (x+1, y, z+1), (x+1, y+1, z+1), (x, y+1, z+1)
                ]
                
                corner_materials = [material_labels[c] for c in corners]
                corner_cts = [volume[c] for c in corners]
                edge_intersections = [None] * 12
                
                for edge_idx in range(12):
                    c1_idx, c2_idx = EDGE_CORNERS[edge_idx]
                    mat1 = corner_materials[c1_idx]
                    mat2 = corner_materials[c2_idx]
                    
                    if mat1 != mat2:
                        ct1 = corner_cts[c1_idx]
                        ct2 = corner_cts[c2_idx]
                        
                        pair = frozenset({mat1, mat2})
                        iso_val = isovalue_map.get(pair, (ct1 + ct2) / 2.0)
                            
                        denom = ct2 - ct1
                        t = 0.5 if abs(denom) < 1e-12 else (iso_val - ct1) / denom
                            
                        p1 = corners[c1_idx]
                        p2 = corners[c2_idx]
                        v_pos = ((1 - t) * p1[0] + t * p2[0],
                                 (1 - t) * p1[1] + t * p2[1],
                                 (1 - t) * p1[2] + t * p2[2])
                        
                        cache_key = (x, y, z, edge_idx)
                        if cache_key not in vertex_cache:
                            vertex_cache[cache_key] = len(vertices)
                            vertices.append(v_pos)
                        edge_intersections[edge_idx] = vertex_cache[cache_key]

                config = sum(1 << i for i, v in enumerate(edge_intersections) if v is not None)
                tri_indices = TRIANGLE_TABLE[config]
                
                if tri_indices is not None:
                    for i in range(0, len(tri_indices), 3):
                        e1, e2, e3 = tri_indices[i], tri_indices[i+1], tri_indices[i+2]
                        if edge_intersections[e1] is not None and \
                           edge_intersections[e2] is not None and \
                           edge_intersections[e3] is not None:
                            faces.append((edge_intersections[e1], edge_intersections[e2], edge_intersections[e3]))

    return vertices, faces
```

### Edge Cases and Pitfalls
* **Division by Zero:** When interpolating, if $I_q = I_p$, the denominator is zero. Use a small epsilon ($10^{-12}$) or default to midpoint [S1, unofficial].
* **Isovalue Selection:** If the isovalue map is not provided, the method may fail to correctly separate materials if CT values overlap. Accurate classification is critical [S2].
* **Non-Manifold Geometry:** Where three or more materials meet, the resulting mesh is non-manifold. Each individual material surface, however, remains manifold [S2].
* **Index Collisions:** Vertices from different materials must be offset to avoid index collisions in the final OBJ file [S1, unofficial].

## Operating characteristics
* **Time Complexity:** $O(N)$, where $N$ is the number of voxels, as each voxel is processed once [G].
* **Memory Complexity:** $O(N)$ for storing the volume and labels [G]. Output mesh size depends on the number of material interfaces [G].
* **Strengths:** Accurately captures boundaries between multiple distinct materials in a single pass. Handles non-manifold junctions correctly [S2].
* **Limitations:** Requires pre-classified material labels. Performance degrades if the number of materials is very large due to the complexity of isovalue mapping [G]. Non-manifold output may require post-processing for certain applications [G].
* **When to Use:** Multi-material CT scans, segmented volumetric data with distinct material classes [G].
* **When Not to Use:** Single-material scalar fields (use standard Marching Cubes) [G].

## Background
Generalized Marching Cubes was introduced by Suzuki et al. in 2007 as an extension of the original Marching Cubes algorithm [S2]. It was developed to address the limitations of standard isosurfacing in medical and industrial CT imaging, where objects are composed of multiple materials (e.g., bone, soft tissue, air, or metal parts) [S2]. The method allows for the extraction of boundary surfaces between different materials by dynamically adjusting the isovalue based on the material pair [S2]. It has been used in applications such as the extraction of isosurfaces from multi-material CT volumetric data of mechanical parts [S2].
