# Dual Marching Cuboids

Also called: Adaptive Skeleton Climbing mesh extraction, Marching Cubes variant

## Overview
Dual Marching Cuboids is a surface extraction method that generates axis-aligned cuboids from a voxel grid, merging adjacent cuboids to reduce polygon count while preserving the Marching Cubes topology at boundaries [S1, unofficial]. It operates by identifying 'cuboids' (initially 1x1x1 cubes) at seed cells, determining their topology via Marching Cubes cases, interpolating vertex positions based on the cell's axis orientation, and merging adjacent cuboids to reduce polygon count before triangulation [S1, unofficial]. It sets itself apart from standard Marching Cubes by producing a mesh composed of merged rectangular prisms rather than individual triangles per cell, and from Dual Contouring by using a greedy, topology-preserving merge strategy on a regular grid rather than optimizing vertex positions via quadratic error functions.

## How it works
### Inputs and Outputs
**Inputs:**
*   A `VoxelGrid` containing scalar data or occupancy flags. The grid is typically stored in a 1D array with row-major ordering: `index = z * width * height + y * width + x` [S1, unofficial].
*   An isovalue or occupancy threshold to determine surface presence. The implementation uses an `occupiedFlag` bit in the grid data [S1, unofficial].
*   A `DISTORTION_THRESHOLD` parameter, typically `0.2`, which limits the geometric deviation allowed during cuboid merging [S1, unofficial].

**Outputs:**
*   A list of `Polygon` objects (triangles) representing the extracted surface mesh.

### Data Structures
**Cuboid:**
Stores the state of a merged surface element.
*   `x, y, z`: Int. Grid position of the cuboid's minimum corner.
*   `width, height, depth`: Int. Dimensions of the cuboid in grid units.
*   `seedIndex, seedIndexMax`: Int. Indices of the first and last seed cells that formed this cuboid.
*   `marchingCubesCase`: Int. The 8-bit topology case index (0-255) derived from neighbor sampling.
*   `vertex1..4`: Vector. Up to four surface vertices. If more than 4 vertices are required by the topology, `vertex1` is set to the cuboid center and the rest are cleared [S1, unofficial].
*   `surfaceNormal`: Vector. The normal of the surface plane.
*   `axis`: Enum. Indicates the primary growth direction (`.xy`, `.yz`, `.none`, `.multiple`).

**VoxelGrid:**
*   `data`: Array of Int. Stores voxel values. Bits are used for occupancy (`occupiedFlag`) and visitation status (`visitedFlag`, value `0x8`) [S1, unofficial].
*   `cuboids`: Dictionary mapping grid index to `Cuboid`.
*   `seedCells`: Queue of indices to process.

### Algorithm Steps

1.  **Initialization**:
    *   Initialize the `DualMarchingCuboids` generator with the `VoxelGrid`.
    *   Calculate `localFaceOffsets` using `MarchingCubes.faceOffsets` mapped to linear grid indices: `x + y * grid.width + z * grid.width * grid.height` [S1, unofficial].
    *   Identify seed cells. A seed cell is a voxel that lies on the surface. In the reference implementation, seeds are generated during voxelization by checking transparency and depth, but generally, any voxel with an occupied neighbor is a candidate [S1, unofficial]. Add valid seed indices to `grid.seedCells`.

2.  **Cuboid Generation (Seed Processing)**:
    *   While `grid.seedCells` is not empty:
        1.  Dequeue `cubeIndex`.
        2.  Check if `grid.cuboids[cubeIndex]` already exists. If so, skip (already processed as part of a larger cuboid).
        3.  Check if the cell has been visited using `DualMarchingCuboids.visitedFlag` (`0x8`). If `(grid.data[index] & visitedFlag) != 0`, return.
        4.  Mark the cell as visited: `grid.data[index] |= visitedFlag`.
        5.  Sample the 8 corners of the cuboid relative to the grid data. Indices are calculated using `nextZ = grid.width * grid.height * depth` and `nextY = grid.width * height`. Boundary checks return `0` if out of bounds (e.g., `z + depth < grid.depth`) [S1, unofficial].
        6.  Determine the Marching Cubes case index from neighbor occupancy flags:
            ```python
            cubeIndex = 0
            for vertexIndex, value in enumerate(neighbors):
                if (value & VoxelGrid.occupiedFlag) != 0:
                    cubeIndex |= 1 << vertexIndex
            ```
        7.  Create a new `Cuboid` with dimensions 1x1x1 at the seed position. Set `marchingCubesCase` to the calculated index.
        8.  Determine the `axis` of the cuboid based on the topology. For example, if the case implies a surface primarily oriented in the XY plane, the axis is `.xy`.
        9.  **Grow the Cuboid**:
            *   Iterate along the determined axis (e.g., Z for `.xy` axis) in both directions.
            *   Update neighbor samples for the new slice.
            *   Break if any neighbor is occupied, visited, or already part of another cuboid.
            *   Break if the Marching Cubes case changes for the new position.
            *   Extend the cuboid's dimensions (`width`, `height`, or `depth`) accordingly.
            *   Mark all grid indices within the cuboid's bounds to point to this cuboid index and set the `visitedFlag`.
        10. **Ugly Corner Detection**:
            *   Check if the cuboid forms an "ugly corner" (a sliver-like geometry). This occurs if the cuboid has a seed cube 'in front' and touches specific faces (e.g., faces 1, 3, 4, 5 for `.xy` axis). If so, add the index to `grid.uglyCubes` [S1, unofficial].

3.  **Cuboid Merging**:
    *   Merge adjacent cuboids in two passes to maximize size while preserving topology.
    *   **Pass 1 (Fix Ugly Corners)**:
        *   Iterate over `uglyCubes`.
        *   Fix `vertex1` by copying from the adjacent neighbor in the axis perpendicular to the cuboid's axis (e.g., if axis is `.xy`, look for neighbor in `.z`) [S1, unofficial].
    *   **Pass 2 (Greedy Merge)**:
        *   Sort cuboid keys.
        *   Iterate through each cuboid.
        *   Determine `directions` based on `cuboid.axis`:
            *   If `.xy`: `[.z, .x, .y]`
            *   If `.yz`: `[.x, .z, .y]`
            *   Else: `[.x, .y, .z]`
        *   For each `direction`:
            *   Loop while `cuboid.findNeighbour(direction, grid)` returns a neighbor that satisfies:
                1.  `canMerge`: They share two dimensions (e.g., same x, y, width, height for Z-adjacency) and are adjacent along the third.
                2.  `shouldMerge`:
                    *   Same Marching Cubes case (`myCase == otherCase`).
                    *   Both cases are 'simple' (`MarchingCubes.surfaceCount[myCase] <= 1`).
                    *   Distortion between them is `<= DISTORTION_THRESHOLD`. Distortion is measured as the absolute distance from the neighbor's `vertex1` to the plane defined by the current cuboid's `surfaceNormal` and `vertex1`: `abs(neighbour.vertex1.distance(from: plane))` [S1, unofficial].
            *   If conditions are met, merge:
                *   Extend dimensions along the axis of adjacency (e.g., `result.width += self.width`).
                *   Update `vertex1` from the non-zero vertex of either cuboid.
                *   Update `surfaceNormal` by averaging: `(self.surfaceNormal + other.surfaceNormal) / 2.0`.
                *   Update the cuboid reference.

4.  **Vertex Interpolation**:
    *   Iterate all cuboids. If `cuboid.vertex1 == Vector.zero`, interpolate based on `cuboid.axis`:
        *   If `.xy`: Find neighbors using `findNeighboursXY` and interpolate using `interpolatePositionXY`.
        *   If `.yz`: Find neighbors using `findNeighboursYZ` and interpolate using `interpolatePositionYZ`.
        *   If `.none`: Try `.xy` neighbors first. If none, try `.yz`. If neither, use `surfaceCentre(grid: grid)`.
        *   If `.multiple`: Use `surfaceCentre(grid: grid)`.
    *   The `surfaceCentre` is calculated as:
        ```python
        Vector(
            (Double(x1) + Double(x2 + 1)) / 2.0,
            (Double(y1) + Double(y2 + 1)) / 2.0,
            (Double(z1) + Double(z2 + 1)) / 2.0
        )
        ```
        where `(x1, y1, z1)` is the seed index position and `(x2, y2, z2)` is the seed index max position [S1, unofficial].

5.  **Triangulation**:
    *   Iterate all cuboids.
    *   Check `marchingCubesCase >= 0`.
    *   Get `edges = MarchingCubes.edgeTable[marchingCubesCase]`.
    *   Determine `solidXYZ = marchingCubesCase & (1 << 6) > 0`.
    *   Generate triangles by checking specific bits in `edges` and finding neighboring cuboids. For example, if `edges & (1 << 6) > 0` and `edges & (1 << 10) > 0`, find `rightCuboid`, `upCuboid`, and `forwardsCuboid` using specific offset logic (e.g., `findRightCuboid` uses `x + width`, `y` or `y + height - 1`, `z + depth - 1`) [S1, unofficial].
    *   For each triangle in `polyPoints`, create a `Plane` from the three points. Create a `Polygon` using the points and the plane's normal (or `Vector.zero` if plane is nil). Append to `polygons`.

### Edge Cases and Pitfalls
*   **Boundary Conditions**: Neighbor sampling returns `0` for out-of-bounds indices. If `0` is a valid non-zero threshold in the voxel data, this may incorrectly classify edge cases [S1, unofficial].
*   **YZ Slice Vertex Ordering**: The YZ slice iteration reverses vertex order to correct for axis alignment. The author notes a potential lurking bug in this reversal logic [S1, unofficial].
*   **Ugly Corners**: Specific topological configurations (e.g., slivers) require special handling to prevent degenerate geometry. These are identified and fixed in a pre-merge pass [S1, unofficial].
*   **Distortion Threshold**: A threshold of `0.2` is used. If the surface is highly curved, this may lead to over-merging or under-merging.

## Operating characteristics
*   **Time Complexity**: The algorithm is generally linear with respect to the number of voxels, $O(N)$, where $N$ is the number of voxels, as each voxel is processed a constant number of times during seed generation, cuboid growth, and merging.
*   **Memory Complexity**: $O(N)$ for storing the grid and cuboid data structures.
*   **Performance**: In the reference implementation, a "French Tiles" grid with 25,020 polygons (standard Marching Cubes) was reduced to 4,302 polygons in 0.1 seconds on a 2014 MacBook Pro [S1, unofficial].
*   **Strengths**: Significant mesh reduction compared to standard Marching Cubes; preserves topology; simple implementation.
*   **Limitations**: Mesh quality may be lower than Dual Contouring for complex surfaces; sensitive to the `DISTORTION_THRESHOLD`; potential bugs in YZ slice handling.

## Background
Dual Marching Cuboids was introduced by Andy Geers in 2020 as part of the "Adaptive Skeleton Climbing" approach [S1, unofficial]. It is an unofficial implementation available on GitHub. The method builds on the principles of Marching Cubes but introduces a greedy meshing strategy to merge adjacent cells into cuboids, reducing the polygon count while maintaining the topological correctness of the Marching Cubes algorithm.
