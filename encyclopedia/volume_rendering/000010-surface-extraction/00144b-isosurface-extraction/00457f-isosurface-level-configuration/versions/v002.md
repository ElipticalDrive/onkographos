# Isosurface Level Configuration

Also called: Contour Value, Isovalue, Threshold Value

## Overview
Isosurface Level Configuration specifies the scalar threshold value used to extract a geometry surface from a discretized volume grid [S1]. It determines which cells are included in mesh generation by ignoring cells below the specified value, effectively defining the boundary between the interior and exterior of the extracted object [S1]. This configuration is used only in Isosurface, Mesh, Ocean Mesh, and Cap Mesh modes [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume grid and a scalar parameter `surflevel` [S1].
*   **Output:** A selection state for each grid cell indicating whether it participates in surface generation; cells below `surflevel` are ignored [S1].

**Data Structures:**
*   The scalar grid is typically stored as a 3D array of floating-point or integer values [G].
*   The `surflevel` is a single scalar value [S1].

**Steps:**
1.  Retrieve the scalar value $v$ for each voxel in the volume grid [S1].
2.  Compare $v$ against the configured `surflevel` threshold $T$ [S1].
3.  If $v < T$, mark the voxel as outside or ignored for surface extraction [S1].
4.  If $v \ge T$, mark the voxel as inside or active for surface extraction [S1].
5.  Pass the active voxels to the parent isosurface extraction algorithm for mesh generation [S1].

**Pseudocode:**
```python
def compute_isosurface_threshold(img, nvox, requested_level):
    if requested_level is NaN:
        return setThreshold(img, nvox, 2)
    elif requested_level is -inf:
        return setThreshold(img, nvox, 1)
    elif requested_level is +inf:
        return setThreshold(img, nvox, 3)
    else:
        return requested_level
```

**Parameters and Typical Values:**
The correct value for $T$ depends entirely on the numerical range and semantic meaning of the source data channel [S1]:
*   **Phoenix Liquids (0–1 range):** $T = 0.5$. In this range, 0 represents no liquid and 1 represents 100% full. A value of 0.5 visualizes the surface between air and liquid [S1].
*   **Houdini Imported Caches (Positive/Negative):** $T = 0.0$. These caches use positive values for inside and negative values for outside, making 0.0 the correct "halfway" boundary [S1].
*   **Phoenix Smoke:** $T \approx 0.01$. This value is appropriate for smoke density fields [S1].
*   **Phoenix Temperature (Kelvins):** $T$ is several hundred. The value must match the specific temperature threshold of interest [S1].

**Edge Cases and Pitfalls:**
*   **Range Mismatch:** Using a default threshold (e.g., 0.5) on data with a different range (e.g., Houdini's signed distance) results in incorrect surface placement or empty meshes [S1].
*   **Inversion:** Some systems offer an "Invert volume" or "solidbelow" option. By default, values above the surface level are considered internal. When enabled, this option swaps the inside and outside, making values below the surface level internal and values above external [S1].
*   **Semi-transparency:** If the isosurface is rendered as a semi-transparent shell, the interior may appear empty unless an interior solid color or volume is explicitly set, or a fog filter is applied to fill the interior [S2].

## Subtopics

### Isosurface Filter
Constructs an isosurface using a critical value (threshold). By default, it renders the isosurface as an empty shell [S2]. To fill the isosurface with a solid color, one must either set an interior solid color/volume (useful for semi-transparent isosurfaces) or apply a fog filter targeting the isosurface [S2].

## Operating characteristics
*   **Complexity:** The configuration step involves a simple scalar comparison per voxel during preprocessing or culling [G].
*   **Performance Impact:** Incorrect threshold selection can lead to empty meshes (if the threshold is too high) or overly dense meshes (if the threshold is too low and includes noise), impacting downstream rendering and memory usage [G].
*   **Limitations:** It does not handle topological changes or smoothing; it is a pure selection criterion. Smoothing requires separate parameters like `Mesh smooth` [S1].

## Background
This configuration is a standard parameter in volumetric visualization software, particularly in fluid simulation and rendering pipelines such as Phoenix for 3ds Max [S1].
