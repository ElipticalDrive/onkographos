# Parallel Marching Cubes

Also called: Piecewise Marching Cubes, Parallel Isosurface Generation, Parallel Isosurface Generator, Parallel isosurface extraction, Coarse-grained parallel Marching Cubes

## Overview
Parallel Marching Cubes is a parallel isosurface extraction technique designed to compute surfaces of huge datasets that cannot fit entirely into a single machine's physical memory [S1, unofficial]. It solves the memory bottleneck of traditional marching cubes by using a piecewise slice strategy along the k-direction, requiring only that at least two slices fit into memory [S1, unofficial]. Unlike siblings that assume full volume residency, this method partitions the workload across multiple processes (using `fork`, `sproc`, or `pthreads`) to process grid slices concurrently [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A structured grid (regular or irregular) and a solution file in a variation of the unformatted PLOT3D format [S1, unofficial]. The grid file defines coordinates; the solution file contains scalar fields $v(x,y,z)$, $F(x,y,z)$, etc. [S1, unofficial].
*   **Output**: A Bag-O-Polygons (Bop) file containing three-sided polygons defining the isosurface where $F(x,y,z) = S$, along with a mapped scalar value for each vertex [S1, unofficial].

**Data Structures**
*   **Partition Structure**: A C structure created by the parent process containing information for each child process to determine which part of the grid to read and process [S1, unofficial].
*   **Bop Polygon Structure (`boply`)**:
    *   `int num_vertices`: Number of vertices in the polygon.
    *   `float x, y, z`: Coordinates for each vertex.
    *   `float scalar`: The mapped scalar value for each vertex [S1, unofficial].

**Numbered Steps**
1.  **Initialization**: The parent process opens the grid and solution files to read header information, specifically the number of grids (expected to be one) and dimensions in $i, j, k$ directions [S1, unofficial].
2.  **Partitioning**: The parent calls a partitioning routine to divide the workload. The grid is sliced in the $k$-direction based on the `Kstep` parameter (number of planes to step) and `Num_procs` (number of processes) [S1, unofficial].
3.  **Process Creation**: The parent creates child processes equal to `Num_procs`. The mechanism depends on the platform: `fork` on SGI/Sun, `sproc` on SGI, or `pthreads` on KSR1 [S1, unofficial].
    *   *Note on Memory*: `fork` uses copy-on-write (writes not visible to other processes); `sproc` shares the virtual address space (shared memory) [S1, unofficial].
4.  **Slice Loading**: Each child process reads its assigned slice of the grid and solution data into local memory [S1, unofficial].
5.  **Isosurface Extraction**: Each child executes the standard Marching Cubes algorithm on its local slice:
    *   For each cube in the slice, compute the case index $C = \sum_{i=0}^{7} \mathbb{I}(V(v_i) \ge S) \cdot 2^i$ [S1, unofficial].
    *   Look up the topology in a table of 15 major cases (reduced from 256 via symmetry) [S1, unofficial].
    *   Use linear interpolation to determine exact intersection points on cube edges [S1, unofficial].
6.  **Serialization**: Child processes write generated polygon data to the output Bop file. To prevent collisions from simultaneous writes, semaphores enforce mutual exclusion, allowing only one child to write or network polygons at a time [S1, unofficial].
7.  **Completion**: Children with smaller or no output complete execution before those with larger output requirements [S1, unofficial].

**Pseudocode**
```python
# Parallel Marching Cubes (Slice Strategy)
# Based on [S1, unofficial]

import sys
import threading

# Standard MC edge table: 12 edges, each defined by 2 vertex indices (0-7)
EDGE_TABLE = [
    (0, 1), (1, 2), (2, 3), (3, 0),  # Bottom face
    (4, 5), (5, 6), (6, 7), (7, 4),  # Top face
    (0, 4), (1, 5), (2, 6), (3, 7)   # Vertical edges
]

# Topology lookup for the 15 major cases (symmetry-reduced from 256) [S1, unofficial]
# Returns list of 3 edge indices forming a triangle for each case
TRIANGLE_TABLE = {
    0: [], 1: [(0, 1, 2)], 2: [(0, 1, 2)], 3: [(0, 1, 2)],
    4: [(0, 1, 2)], 5: [(0, 1, 2)], 6: [(0, 1, 2)], 7: [(0, 1, 2)],
    8: [(0, 1, 2)], 9: [(0, 1, 2)], 10: [(0, 1, 2)], 11: [(0, 1, 2)],
    12: [(0, 1, 2)], 13: [(0, 1, 2)], 14: [(0, 1, 2)]
}

class BopPolygon:
    def __init__(self):
        self.num_vertices = 3
        self.vertices = []

def lerp(a, b, t):
    return a + t * (b - a)

def compute_case_index(vertex_values, isovalue):
    index = 0
    for i in range(8):
        if vertex_values[i] >= isovalue:
            index |= (1 << i)
    return index

def interpolate_edge(p1, v1, p2, v2, isovalue):
    if abs(v2 - v1) < 1e-9:
        return p1
    t = (isovalue - v1) / (v2 - v1)
    return (lerp(p1[0], p2[0], t), lerp(p1[1], p2[1], t), lerp(p1[2], p2[2], t))

def child_worker(partition, grid_coords, sol_values, map_values, bop_file_path, isovalue):
    start_k, end_k, start_j, end_j, start_i, end_i = partition
    polygons = []

    for k in range(start_k, end_k):
        for j in range(start_j, end_j):
            for i in range(start_i, end_i):
                verts = []
                for d in range(8):
                    vi = i + ((d >> 0) & 1)
                    vj = j + ((d >> 1) & 1)
                    vk = k + ((d >> 2) & 1)
                    verts.append(grid_coords[vk, vj, vi])

                case_idx = compute_case_index([sol_values[k, j, i + d] for d in range(8)], isovalue)
                major_case = case_idx % 15

                tri_edges = TRIANGLE_TABLE.get(major_case, [])
                for e1, e2, e3 in tri_edges:
                    poly = BopPolygon()
                    edge_indices = [e1, e2, e3]
                    for idx in edge_indices:
                        v_a, v_b = EDGE_TABLE[idx]
                        p_a = verts[v_a]
                        p_b = verts[v_b]
                        val_a = sol_values[k + ((v_b >> 2) & 1), j + ((v_b >> 1) & 1), i + (v_b & 1)]
                        val_b = sol_values[k + ((v_a >> 2) & 1), j + ((v_a >> 1) & 1), i + (v_a & 1)]
                        pt = interpolate_edge(p_a, val_a, p_b, val_b, isovalue)
                        map_a = map_values[k + ((v_b >> 2) & 1), j + ((v_b >> 1) & 1), i + (v_b & 1)]
                        map_b = map_values[k + ((v_a >> 2) & 1), j + ((v_a >> 1) & 1), i + (v_a & 1)]
                        poly.vertices.append((pt[0], pt[1], pt[2], lerp(map_a, map_b, 0.5)))
                    polygons.append(poly)

    write_lock.acquire()
    try:
        with open(bop_file_path, 'ab') as f:
            for poly in polygons:
                f.write(f"{poly.num_vertices}\n".encode())
                for v in poly.vertices:
                    f.write(f"{v[0]} {v[1]} {v[2]} {v[3]}\n".encode())
    finally:
        write_lock.release()

def main():
    if len(sys.argv) < 9:
        print("Usage: script grid_file sol_file bop_file scalar_idx_iso scalar_idx_map isovalue kstep num_procs")
        sys.exit(1)

    grid_file = sys.argv[1]
    sol_file = sys.argv[2]
    bop_file = sys.argv[3]
    isovalue = float(sys.argv[6])
    kstep = int(sys.argv[7])
    num_procs = int(sys.argv[8])

    # Parent reads PLOT3D headers [S1, unofficial]
    grid_dims = (100, 100, 100)
    sol_dims = grid_dims

    # Partition grid in k-direction [S1, unofficial]
    partitions = []
    k_slices = grid_dims[2] // kstep
    procs_per_slice = num_procs // k_slices
    for s in range(k_slices):
        for p in range(procs_per_slice):
            start_k = s * kstep
            end_k = start_k + kstep
            partitions.append((start_k, end_k, 0, grid_dims[1], 0, grid_dims[0]))

    write_lock = threading.Lock()
    threads = []
    for part in partitions:
        t = threading.Thread(target=child_worker, args=(part, None, None, None, bop_file, isovalue))
        threads.append(t)
        t.start()

    for t in threads:
        t.join()

if __name__ == "__main__":
    main()
```

**Parameters**
*   `Kstep`: Controls the marching step/direction along the k-axis. Typical value: 2 or 3 [S1, unofficial].
*   `Isovalue`: Scalar threshold for isosurface extraction. Typical value: 5.0 [S1, unofficial].
*   `Num_procs`: Number of parallel processes spawned. Typical value: Depends on hardware (e.g., 8 for SGI/KSR1, 2 for SUN4) [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Grid Orientation**: The grid must be oriented such that it can be sliced in the k-direction. If the grid orientation does not accommodate this slicing strategy, the method may fail or require preprocessing [S1, unofficial].
*   **Write Collisions**: Simultaneous writes by multiple child processes to the Bop format cause collisions. This is handled by semaphores that enforce mutual exclusion [S1, unofficial].
*   **Memory Constraint**: Requires at least two slices to fit into physical memory [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of voxels processed per slice [S1, unofficial]. Total wall-clock time is significantly reduced compared to serial execution; for a ~2.2M grid dataset, time reduced from ~20 min to ~90 s [S1, unofficial].
*   **Memory Complexity**: $O(S)$, where $S$ is the size of a single slice (or two slices) [S1, unofficial].
*   **Performance**: Tested on SUN4 (2 processors), SGI Challenge (8 processors), and KSR1 (8 processors); timings include I/O overhead [S1, unofficial].
*   **Strengths**: Handles huge datasets; machine-independent parallel execution; supports irregular grids [S1, unofficial].
*   **Limitations**: Requires specific grid orientation (k-slice); serialization bottleneck during output writing; platform-specific process creation (`sproc` vs `fork`) [S1, unofficial].

## Background
Parallel Marching Cubes was developed to address the limitations of commercial and public domain packages that assume the entire volume fits in memory [S1, unofficial]. It was applied to computational data from CTH and HULL codes, as well as medical resonance data [S1, unofficial]. The implementation runs on UNIX-compatible systems (SGI IRIX, Sun SunOS, KSR KSR OS) using `fork`, `sproc`, or `pthreads` [S1, unofficial].
