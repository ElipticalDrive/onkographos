# Batched Marching Cubes

Also called: Batched Marching Cubes Mesh Extraction, Batched Marching Cubes Meshing, Batched SDF Marching Cubes, Marching Cubes Mesh Extraction

## Overview
Batched Marching Cubes extracts a triangular mesh from a Signed Distance Field (SDF) by processing the volume data in memory-constrained chunks along the X-axis [S1, unofficial]. It solves the problem of boundary artifacts and invalid geometry that arise when processing discrete voxel grids or large latent field evaluations by integrating a strict validity mask check and a 27-neighbor consistency filter [S1, unofficial]. It sets itself apart from standard Marching Cubes implementations by combining batched memory management with post-extraction topological validation to ensure the resulting mesh is sound within the processed block [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   `_res`: Integer resolution of the voxel grid (e.g., 100) [S1, unofficial].
    *   `k_vis_batch_pt_num`: Maximum number of points processed in a single batch to limit memory usage (e.g., 250,000) [S1, unofficial].
    *   `k_vis_attribute`: Boolean flag (0 or 1) indicating whether to compute and color vertices by normal [S1, unofficial].
    *   `k_vis_batch_pt_num`: Parameter for batch size calculation [S1, unofficial].
    *   SDF Field: A 3D volume of scalar values, typically evaluated from a neural decoder or sampled from a grid [S2, unofficial].
    *   `valid_mask`: A boolean grid indicating valid spatial regions [S1, unofficial].
*   **Outputs**:
    *   Triangular mesh (vertices, faces, optional colors/normals) [S1, unofficial].

**Data Structures**
*   **3D Mesh Grid**: A tensor of shape `(N, 3)` containing coordinates. For a resolution of 100 spanning `[-1, 1]`, the step size is `0.02` [S2, unofficial].
*   **SDF Tensor**: A 3D array of shape `(res, res, res)` storing signed distance values [S2, unofficial].
*   **Valid Mask**: A boolean array of shape `(res, res, res)` marking valid voxels [S1, unofficial].
*   **Edge Intersection Table & Triangle Connection Table**: As defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).

**Numbered Steps**
1.  **Grid Setup**: Calculate grid dimensions based on resolution `_res` and spatial bounds. For a standard unit cube, coordinates span `[-1, 1]` with step size `0.02` for `res=100` [S2, unofficial].
2.  **Batch Sizing**: Determine the batch size along the X-axis. Calculate `yz_res = y_res * z_res`. Calculate `x_step = k_vis_batch_pt_num / yz_res + 1` [S1, unofficial]. Calculate total steps: `steps = x_res / x_step + 1` [S1, unofficial].
3.  **SDF Evaluation (Batched)**:
    *   Split the full set of grid points into batches of size `k_vis_batch_pt_num` (e.g., 250,000 points) [S2, unofficial].
    *   For each batch, evaluate the SDF decoder at the grid points [S2, unofficial].
    *   Clamp predicted SDF values to the range `[-0.1, 0.1]` [S2, unofficial].
    *   Reshape flattened SDF values into a 3D volume of shape `(res, res, res)` [S2, unofficial].
4.  **Volume Assembly**:
    *   Initialize `mesh_sdf` tensor with `1e-6f` (representing outside) [S1, unofficial].
    *   Loop over X-steps. For each step, define start/end X coordinates [S1, unofficial].
    *   Create a 3D meshgrid for the current batch [S1, unofficial].
    *   Filter points outside the valid map region using `get_valid_mask`. If no valid points, skip the batch [S1, unofficial].
    *   Query SDF for valid points and fill the corresponding regions in `mesh_sdf` [S1, unofficial].
5.  **Isosurface Extraction**:
    *   Run the standard Marching Cubes algorithm on the assembled `mesh_sdf` volume at isovalue `0.0` [S1, unofficial].
    *   Use the `edgeTable` and `triangleTable` from the parent article to generate vertices and faces [G].
6.  **Boundary Artifact Filtering**:
    *   Convert mesh vertices to integer grid coordinates `qpts` [S1, unofficial].
    *   Check if all 27 neighbors (including self) of each vertex are valid using `get_valid_mask` [S1, unofficial].
    *   Keep only faces where all 3 vertices have valid neighbors [S1, unofficial]. This removes holes and noise caused by batch edges or invalid regions [S1, unofficial].
7.  **Vertex Coloring (Optional)**:
    *   If `k_vis_attribute == 1`:
        *   Compute normals via gradient estimation `get_gradient` [S1, unofficial].
        *   Normalize normals.
        *   Map normal components from `[-1, 1]` to color `[0, 1]` via `normal_cu / 2.0 + 0.5` [S1, unofficial].
    *   If `k_vis_attribute == 0`: Set color to `0.5` [S1, unofficial].
8.  **Output**:
    *   Publish mesh via ROS if subscribers exist [S1, unofficial].
    *   If `_save` is true, accumulate vertices, faces, and colors into persistent vectors, adjusting face indices by `count` [S1, unofficial].

**Formulas**
*   **Grid Step**: $step = \frac{scale}{res}$ [S1, unofficial].
*   **Batch X-Step**: $x\_step = \frac{k\_vis\_batch\_pt\_num}{y\_res \times z\_res} + 1$ [S1, unofficial].
*   **Color Mapping**: $C = \frac{N}{2} + 0.5$, where $N \in [-1, 1]$ is the normalized normal component [S1, unofficial].

**Parameters**
*   `_res`: Resolution of the voxel grid (e.g., 100) [S1, unofficial].
*   `k_vis_batch_pt_num`: Max points per batch (e.g., 250,000) [S1, unofficial].
*   `isovalue`: 0.0 for SDF zero-crossing [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Boundary Artifacts**: Vertices near the edge of a batch or map may have invalid neighbors, causing holes or noise. Mitigated by the 27-neighbor validity check [S1, unofficial].
*   **Memory Constraints**: Large grids (e.g., $100^3$) require splitting evaluation into multiple batches (e.g., 4 splits of 250,000 points) [S2, unofficial].
*   **Zero SDF Values**: The code adds `1e-6f` to outside regions to avoid exact zero SDFs, which might cause issues with the marching cubes threshold or interpretation [S1, unofficial].

    Extracts mesh from SDF in batches with boundary filtering.
    """
    # 1. Grid Setup
    # Assuming unit cube [-1, 1]
    step = 2.0 / res
    x = np.linspace(-1, 1, res)
    y = np.linspace(-1, 1, res)
    z = np.linspace(-1, 1, res)
    xx, yy, zz = np.meshgrid(x, y, z, indexing='ij')
    points = np.stack((xx, yy, zz), axis=-1).reshape(-1, 3)
    
    y_res = res
    z_res = res
    yz_res = y_res * z_res
    
    # 2. Batch Sizing
    x_step = k_vis_batch_pt_num // yz_res + 1
    x_res = res
    steps = x_res // x_step + 1
    
    # 3 & 4. SDF Evaluation and Volume Assembly
    mesh_sdf = np.full((res, res, res), 1e-6)
    
    for step_idx in range(steps):
        x_start = step_idx * x_step
        x_end = min((step_idx + 1) * x_step, res)
        
        # Create batch grid
        x_batch = np.linspace(-1, 1, x_end - x_start)
        y_batch = np.linspace(-1, 1, res)
        z_batch = np.linspace(-1, 1, res)
        xx_b, yy_b, zz_b = np.meshgrid(x_batch, y_batch, z_batch, indexing='ij')
        batch_points = np.stack((xx_b, yy_b, zz_b), axis=-1).reshape(-1, 3)
        
        # Evaluate SDF
        if sdf_decoder:
            # Placeholder for decoder call, clamped to [-0.1, 0.1]
            sdf_vals = np.clip(sdf_decoder(batch_points), -0.1, 0.1)
        else:
            # Fallback: assume mesh_sdf is pre-filled or use dummy
            sdf_vals = np.zeros(len(batch_points))
            
        # Reshape to 3D slice
        slice_shape = (x_end - x_start, res, res)
        sdf_slice = sdf_vals.reshape(slice_shape)
        
        # 4. Filter and Fill
        # Get valid mask for this slice
        # Note: valid_mask is assumed to be (res, res, res)

    # 6. Boundary Artifact Filtering
    # Convert vertices to grid coordinates
    # Assuming verts are in continuous space, map to integer grid
    # qpts = (verts + 1) * (res - 1) / 2  (approximate mapping)
    # For exact implementation, use the grid coordinates from the extraction step
    # Here we assume we have integer grid indices for each vertex
    # Let's assume 'vertex_grid_coords' is available from the MC implementation
    # or re-derived.

    valid_faces = []
    for face in faces:
        v0, v1, v2 = face
        # Check if v0, v1, v2 are within bounds and have valid 27-neighbors
        if is_vertex_valid(v0, valid_mask) and is_vertex_valid(v1, valid_mask) and is_vertex_valid(v2, valid_mask):
            valid_faces.append(face)

    valid_vertex_indices = np.unique(valid_faces)
    final_verts = verts[valid_vertex_indices]
    final_faces = np.zeros_like(valid_faces)

    index_map[valid_vertex_indices] = np.arange(len(valid_vertex_indices))

        # Gradient of mesh_sdf

        # Or use the 'normals' output from marching_cubes if it provides vertex normals

def is_vertex_valid(vertex_idx, valid_mask):
    """
    Checks if a vertex (assumed to be integer grid coordinates) 
    has all 27 neighbors valid.
    """
    x, y, z = vertex_idx
    res = valid_mask.shape[0]
    
    # Check bounds
    if not (0 <= x < res and 0 <= y < res and 0 <= z < res):
        return False
        
    # Check 27 neighbors
    for dx in [-1, 0, 1]:
        for dy in [-1, 0, 1]:
            for dz in [-1, 0, 1]:
                nx, ny, nz = x + dx, y + dy, z + dz
                if not (0 <= nx < res and 0 <= ny < res and 0 <= nz < res):
                    return False
                if not valid_mask[nx, ny, nz]:
                    return False
    return True

## Subtopics

### [Marching Cubes Mesh Extraction with Boundary Artifact Filtering](20020-marching-cubes-mesh-extraction-with-boundary-artifact-filter.md)
Extracts a triangular mesh from an SDF using Marching Cubes, specifically designed to operate on batches of volume data. It sets itself apart by integrating a strict validity mask check and a 27-neighbor consistency filter to ensure the resulting mesh is topologically sound within the processed block. Choose this when processing large SDF volumes that exceed memory limits or when boundary artifacts from discrete voxel grids are a concern.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of voxels $N$ for SDF evaluation and Marching Cubes extraction $O(N)$. The filtering step is linear with respect to the number of faces $F$ and vertices $V$, $O(F + V)$, assuming constant-time neighbor lookup [S1, unofficial].
*   **Memory Complexity**: Dominated by the SDF evaluation batch size. By splitting the grid into batches of $k\_vis\_batch\_pt\_num$ points, memory usage is capped at $O(k\_vis\_batch\_pt\_num)$ for the active batch, plus $O(res^3)$ for the final SDF volume and mesh storage [S2, unofficial].
*   **Measured Performance**: For a $100 \times 100 \times 100$ grid (1,000,000 points), splitting into 4 batches of 250,000 points prevents out-of-memory errors on standard GPUs [S2, unofficial].
*   **Strengths**: Handles large volumes that do not fit in memory; reduces boundary artifacts and invalid geometry through neighbor validation [S1, unofficial].
*   **Limitations**: Requires a valid mask for filtering; batch processing introduces overhead for grid assembly; clamping SDF values may affect precision near the isosurface [S2, unofficial].
*   **When to Use**: Large-scale SDF reconstruction, neural implicit surface extraction with memory constraints, scenarios requiring topological consistency at batch boundaries [S1, unofficial].
*   **When Not to Use**: Small volumes that fit in memory; applications requiring exact boundary preservation without filtering; real-time applications where batch overhead is prohibitive.

## Background
Batched Marching Cubes is an implementation strategy for extracting meshes from Signed Distance Fields (SDFs), particularly in the context of neural implicit representations and large-scale 3D reconstruction. It was developed to address memory limitations and boundary artifacts in batched processing pipelines [S1, unofficial]. The method is used in projects such as GS-SDF and VC-SDFGen2 for generating meshes from latent codes or point clouds [S1, unofficial][S2, unofficial].
