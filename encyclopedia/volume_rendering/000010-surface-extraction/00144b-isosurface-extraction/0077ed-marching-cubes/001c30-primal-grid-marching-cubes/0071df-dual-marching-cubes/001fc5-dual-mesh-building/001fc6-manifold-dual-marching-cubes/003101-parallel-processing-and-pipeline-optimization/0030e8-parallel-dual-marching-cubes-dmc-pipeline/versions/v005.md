# Parallel Dual Marching Cubes (DMC) Pipeline

Also called: Multi-staged DMC pipeline, Parallel DMC on Regular Grids

## Overview
The Parallel Dual Marching Cubes (DMC) Pipeline is a surface extraction method that generates a manifold quadrilateral mesh with full connectivity information, including 1-ring neighbors, from a regular 3D grid [S1, unofficial]. It solves the problem of unconnected primitives and missing adjacency data inherent in standard parallel extraction by combining static and dynamic lookup tables with parallel reduction algorithms [S1, unofficial]. Unlike standard parallel Marching Cubes which produces redundant and unconnected fragments, this method ensures topological consistency through a multi-staged pipeline that switches from block-based to cell-based processing [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A regular 3D grid $L$ of scalar values $v_{i,j,k}$ representing a function $f: \mathbb{R}^3 \to \mathbb{R}$, and an isovalue $\alpha$ [S1, unofficial].
*   **Output:** A manifold quadrilateral surface mesh with vertex positions, face connectivity, and 1-ring neighbor adjacency data [S1, unofficial].

**Data Structures:**
The pipeline relies on static lookup tables precomputed for all 23 canonical cell cases and dynamic tables generated during execution [S1, unofficial].

1.  **Vertex-Edges Table:** Maps a cell case and a specific cell vertex to a 12-bit vector (1 bit per edge) representing the set of associated active edges [S1, unofficial].
2.  **Edge-Vertex Table:** Maps a cell case and a specific edge to a 24-bit vector (2 bits per edge) identifying the associated cell vertex [S1, unofficial].
3.  **Vertex-Adjacencies Table:** Maps a cell case and a cell vertex to a sorted set of tuples $(V_{zyx}, e)$, where $V_{zyx}$ is the offset to the adjacent cell and $e$ is the associated edge, sorted in 1-ring order [S1, unofficial].
4.  **Case Table:** A 3D array of dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$ storing the cell case for each cell in the volume [S1, unofficial].
5.  **Index Table:** A 3D array of dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$ storing the index of the first face and vertex for each cell in the mesh buffers [S1, unofficial]. For a cell $(i,j,k)$ and its $x$-th vertex, the location in the vertex buffer is $I_{i,j,k} + x$ [S1, unofficial].

**Steps:**

1.  **Block Selection:** The volume is decomposed into blocks [S1, unofficial]. For each block, the minimum and maximum density values are evaluated in parallel [S1, unofficial]. If the condition $\min \le \alpha < \max$ holds, the block is marked as selected, and its index is stored in a buffer [S1, unofficial].
2.  **Classification:** One block is mapped to one thread group [S1, unofficial]. Grid values for the block are loaded into local memory [S1, unofficial]. For each cell $(i,j,k)$ within the block, the 8 corner values are inspected relative to $\alpha$ [S1, unofficial]. A point $v_{i,j,k}$ is classified as **inside** if $v_{i,j,k} > \alpha$ and **outside** if $v_{i,j,k} \le \alpha$ [S1, unofficial]. The resulting case is stored in the Case Table [S1, unofficial].
3.  **Indexing:** A parallel all-prefix-sum (scan) algorithm is performed on vertex and face counts to compute total buffer sizes and map cells to unique locations in mesh buffers [S1, unofficial]. The total count is transferred to the host for buffer allocation [S1, unofficial]. During this scan, the number of relevant cells is counted, and their indices $(i,j,k)$ are written to a buffer [S1, unofficial]. This switches processing from block-based to cell-based [S1, unofficial].
4.  **Mesh Generation Phase 1 (Vertices):** For each relevant cell, vertices are relocated using a Quadric Error Metric (QEM) based approach [S1, unofficial]. The storage location in the mesh buffers is determined via dynamic lookup tables (derived from the Index Table) [S1, unofficial]. The 1-ring neighbors are gathered using the Vertex-Adjacencies Table [S1, unofficial].
5.  **Mesh Generation Phase 2 (Faces):** Faces are generated using a parallel scheme where each cell chooses three edges sharing the same origin (along the x, y, and z axes) [S1, unofficial]. This results in four grid values being classified and 16 possible configurations [S1, unofficial]. An extended Face Table maps local edges to adjacent cell edges to form quadrilaterals [S1, unofficial].

**Pseudocode:**

```python
def parallel_dmc_pipeline(grid_values, isovalue, blocks, Nx, Ny, Nz):
    # Helper: compute min/max for a block
    def compute_min_max(block):
        return min(block.values), max(block.values)

    # Helper: parallel prefix sum (scan)
    def parallel_scan(arr):
        offsets = [0] * len(arr)
        current = 0
        for i in range(len(arr)):
            offsets[i] = current
            current += arr[i]
        return offsets

    # 1. Block Selection
    selected_block_indices = []
    for block in blocks:
        min_val, max_val = compute_min_max(block)
        if min_val <= isovalue < max_val:
            selected_block_indices.append(block.index)

    # 2. Classification
    case_table = [[[0 for _ in range(Nz-1)] for _ in range(Ny-1)] for _ in range(Nx-1)]
    for b_idx in selected_block_indices:
        block = blocks[b_idx]
        # Load block values into local memory (simulated)
        local_V = block.values
        for cell in block.cells:
            i, j, k = cell.coords
            inside_mask = 0
            for corner_idx, corner in enumerate(cell.corners):
                if local_V[corner] > isovalue:
                    inside_mask |= (1 << corner_idx)
            case_table[i][j][k] = get_canonical_case(inside_mask)

    # 3. Indexing
    vertex_counts = [0] * ((Nx-1)*(Ny-1)*(Nz-1))
    for i in range(Nx-1):
        for j in range(Ny-1):
            for k in range(Nz-1):
                idx = i*(Ny-1)*(Nz-1) + j*(Nz-1) + k
                vertex_counts[idx] = count_vertices_for_case(case_table[i][j][k])

    vertex_offsets = parallel_scan(vertex_counts)
    total_vertices = vertex_offsets[-1] + vertex_counts[-1]
    vertex_buffer = [None] * total_vertices

    # Cell Selection: count relevant cells and store indices
    relevant_cells = []
    for i in range(Nx-1):
        for j in range(Ny-1):
            for k in range(Nz-1):
                if case_table[i][j][k] != 0:
                    relevant_cells.append((i, j, k))

    # 4. Mesh Generation Phase 1 (Vertices)
    adjacency_buffer = [None] * total_vertices
    for (i, j, k) in relevant_cells:
        case = case_table[i][j][k]
        base_idx = vertex_offsets[i*(Ny-1)*(Nz-1) + j*(Nz-1) + k]
        num_verts = count_vertices_for_case(case)
        for v in range(num_verts):
            pos = relocate_vertex_qem(grid_values, i, j, k, case, v)
            vertex_buffer[base_idx + v] = pos
            neighbors = get_1_ring_neighbors(case, v)
            adjacency_buffer[base_idx + v] = neighbors

    # 5. Mesh Generation Phase 2 (Faces)
    face_counts = [0] * len(vertex_counts)
    for idx in range(len(vertex_counts)):
        face_counts[idx] = count_faces_for_case(case_table_flat[idx])
    face_offsets = parallel_scan(face_counts)
    total_faces = face_offsets[-1] + face_counts[-1]
    face_buffer = [None] * total_faces

    for (i, j, k) in relevant_cells:
        case = case_table[i][j][k]
        base_face_idx = face_offsets[i*(Ny-1)*(Nz-1) + j*(Nz-1) + k]
        edges = select_origin_edges(case)
        faces = generate_quadrilaterals(case, edges, vertex_buffer)
        for f_idx, face in enumerate(faces):
            face_buffer[base_face_idx + f_idx] = face

    return vertex_buffer, face_buffer, adjacency_buffer
```

**Formulas and Parameters:**
*   **Grid Definition:** $L = \{(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z) : i = 0,...,N_x; j = 0,...,N_y; k = 0,...,N_z\}$ with values $v_{i,j,k} = f(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z)$ [S1, unofficial].
*   **Normal:** $\nabla f = \left(\frac{\partial f}{\partial x}, \frac{\partial f}{\partial y}, \frac{\partial f}{\partial z}\right)$ [S1, unofficial].
*   **Cell Geometry:** Cell $(i,j,k)$ spans diagonally from $(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z)$ to $((i+1) \cdot 4 \cdot x, (j+1) \cdot 4 \cdot y, (k+1) \cdot 4 \cdot z)$ [S1, unofficial].
*   **Classification:** $v_{i,j,k} > \alpha$ is inside, $v_{i,j,k} \le \alpha$ is outside [S1, unofficial].
*   **Grid Spacing Factor:** The regular grid uses a spacing factor of 4, implying a stride or scaling factor of 4 relative to base unit $x,y,z$ [S1, unofficial].
*   **Vertex Buffer Indexing:** For cell $(i,j,k)$ and its $x$-th vertex, the location in the vertex buffer is $I_{i,j,k} + x$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Unconnected Primitives:** Parallel processing analyzes cells independently, producing unconnected primitives and redundant computations [S1, unofficial]. This is solved by using static and dynamic lookup tables to ensure manifold connectivity and 1-ring neighborhood [S1, unofficial].
*   **Precision:** The classification uses strict inequality $v_{i,j,k} > \alpha$ for inside and $\le \alpha$ for outside [S1, unofficial].
*   **Register Limits:** The QEM-based vertex relocation is chosen over complex QEF minimization via pseudoinverse to avoid performance penalties from limited register counts on parallel hardware [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The pipeline is dominated by parallel operations: block selection, classification, and prefix sums (scan), all of which are $O(N)$ where $N$ is the number of cells or blocks [S1, unofficial]. The mesh generation is also parallelized per cell [S1, unofficial].
*   **Memory Complexity:** The method doubles memory effort due to the Case and Index tables, which are 3D arrays of size $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$ [S1, unofficial]. However, it only allocates memory for relevant parts of the volume if combined with block culling [S1, unofficial].
*   **Performance:** The switch from block-based to cell-based processing in the Cell Selection stage significantly accelerates mesh generation [S1, unofficial]. The QEM approach is less computationally complex than QEF minimization, avoiding register pressure penalties [S1, unofficial].
*   **Strengths:** Generates a manifold surface with full connectivity and 1-ring neighborhood information, suitable for interactive applications [S1, unofficial].
*   **Limitations:** The QEM-based relocation achieves lower quality than QEF minimization, though it is sufficient for preserving terrain volume [S1, unofficial].

## Background
The method is based on Dual Marching Cubes by Nielson [Nie04], which provides high-quality manifold surfaces but lacks interactivity in parallel settings [S1, unofficial]. The pipeline extends DMC with a novel parallel processing scheme using static and dynamic lookup tables and parallel reduction algorithms [S1, unofficial]. It was developed to address the lack of 1-ring neighbor information in standard surface extraction algorithms, which typically requires extensive post-processing [S1, unofficial]. The vertex relocation uses the Quadric Error Metric [GH97] [S1, unofficial].
