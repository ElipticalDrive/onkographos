# Extended Trilinear Triangulation
Also called: Extended MC33, Extended Marching Cubes 33, Extended triangulation to the Marching Cubes 33 algorithm

## Overview
Extended Trilinear Triangulation is a topologically correct isosurface extraction method that extends the Marching Cubes 33 (MC33) algorithm by introducing a three-state vertex classification (`+`, `-`, `=`) to eliminate degenerate triangles while preserving the topology of the trilinear interpolant [S1]. Unlike standard Marching Cubes, which fails on ambiguous configurations, or earlier extended lookup tables (e.g., Raman and Wenger) that only cover 23 of 33 topological behaviors, this method handles all 33 cases defined by Chernyaev by analyzing vertex and edge connectivity groups within each cube [S1]. It builds on [Topological Correctness Guarantees](1796-topological-correctness-guarantees.md) by using local geometric tests (interior tests) to resolve ambiguities that standard edge-intersection logic cannot distinguish [S1].

## How it works
### Inputs and Outputs
- **Input**: A rectilinear grid $H$ with a scalar field $f$ sampled at vertices, and an isovalue $\alpha$.
- **Output**: A triangular mesh approximating the isosurface $\bar{S}_\alpha = \{x \in \mathbb{R}^3 \mid g(x) = \alpha\}$, where $g$ is the trilinear interpolant [S1].

### Data Structures
- **Vertex Classification**: Each vertex $v_i$ of a cube is labeled:
  - `+` if $f(v_i) > \alpha$
  - `-` if $f(v_i) < \alpha$
  - `=` if $f(v_i) = \alpha$
- **Cube Classification**: A cube is **positive** if the count of vertices labeled `=` or `+` is $\le 4$; otherwise, it is **negative** [S1].
- **Groups**:
  - **Group of Vertices (GV)**: A set of vertices of the same sign (or `=`) connected by a path of the same sign (or `=`) along the edges or faces of the cube [S1].
  - **Group of Edges (GE)**: A set of edges intersected by the isosurface that are incident to vertices in the same GV [S1].
- **Intersection Points**: Midpoints of intersected edges are used as proxies for intersection locations in the convex hull construction [S1].

### Steps

1. **Classify Vertices**: For each vertex $v_i$ of the current cube, determine its label based on $f(v_i)$ relative to $\alpha$ [S1].
2. **Classify Cube**: Determine if the cube is positive or negative based on the count of `+` and `=` vertices [S1].
3. **Identify Groups**:
   - Identify all Groups of Vertices (GV) for the cube's sign. Two vertices are in the same GV if they are connected by a path of non-negative (for positive cubes) or non-positive (for negative cubes) vertices along the cube's boundary (edges/faces) [S1].
   - Identify Groups of Edges (GE) incident to each GV [S1].
4. **Interior Test**: Use the Chernyaev/Custodio interior test to determine if multiple GV groups are separated or joined inside the cube. This classifies the cube's topology into one of three categories: **Simple Leaf**, **Tunnel**, or **Interior Point** [S1]. Note: Cases 6.1.1 and 6.1.2 have identical GV/GE structures but different topologies; the interior test distinguishes them [S1].
5. **Generate Triangulation**: Based on the topology category and specific case (e.g., Case 13 subcases), apply one of the following triangulation methods [S1]:

#### Simple Leaves Triangulation
Used for Simple Leaf topologies.
1. For each Group $i$, let $G_i = GV_i \cup GE_i$.
2. Let $W_i$ be the set of intersection points (midpoints of edges in $GE_i$) and vertices in $GV_i$ labeled `=` or `+` [S1].
3. Compute the convex hull $C_i = \text{conv}(W_i)$ [S1].
4. If $C_i$ is 3D:
   - Triangulate the boundary $\partial C_i$.
   - Remove triangles that lie entirely on the faces of the cube [S1].
5. If $C_i$ is 2D (contained in cube faces):
   - Return the triangulation of $C_i$.
   - **Exception**: If all cube vertices are `=`, return no triangulation to avoid duplicates [S1].
6. **Face Tracking**: Track grid faces already triangulated to prevent adjacent cubes from triangulating the same face twice [S1].

#### Tunnel Triangulation
Used for Tunnel topologies.
1. Let $W$ be the set of midpoints of all intersected edges in the cube [S1].
2. Compute $C = \text{conv}(W)$ [S1].
3. If $C$ is 3D:
   - Triangulate the boundary $\partial C$.
   - Remove triangles where all three vertices belong to the same Group of Edges $GE_i$ [S1].

#### Interior Point Leaves Triangulation
Used for Interior Point topologies (e.g., Case 13.3, 13.5.2 specific parts).
1. Identify faces where all four edges are intersected.
2. On each such face, connect pairs of intersected edges based on the bilinear interpolant's behavior to form a polygonal curve [S1].
3. Create a vertex at the center of the cube [S1].
4. Form triangles by connecting the center vertex to the segments of the polygonal curve [S1].

#### Complex Case 13 Handling
Case 13 has six subcases. The method combines the above techniques [S1]:
- **Case 13.3**: One group of 4 positive vertices. Use the incident negative vertex. Apply Interior Point Leaves triangulation combined with Simple Leaves triangulation on the single negative vertex group [S1].
- **Case 13.5.1**: Two groups of vertices. Apply Simple Leaves triangulation to both groups [S1].
- **Case 13.5.2**: Two groups connected by the interior, with signal change diagonally opposite to one vertex group. Apply Tunnel triangulation combined with Simple Leaves triangulation in the region diagonally opposite to the one-vertex positive group [S1].

### Parameters
- **Isovalue ($\alpha$)**: The scalar threshold for the isosurface.
- **Grid Resolution**: Determines the granularity of the scalar field sampling.

### Edge Cases and Pitfalls
- **Degenerate Triangles**: Occur in standard MC when a vertex equals $\alpha$ and is classified as `+`, causing three incident edges to be intersected at the same point. This method avoids this by labeling such vertices `=` and handling them in convex hulls rather than as simple edge intersections [S1].
- **Skinny Triangles**: Can still occur if two vertices are close to a grid vertex and the third is far. The method improves quality but does not guarantee uniform triangle size [S1].
- **Duplicate Faces**: If all vertices are `=`, no triangulation is generated. Additionally, the algorithm must track grid faces to ensure adjacent cubes do not triangulate the same face twice [S1].
- **Topology Ambiguity**: Cases 6.1.1 and 6.1.2 have identical vertex/edge group structures but different topologies. The interior test is mandatory to distinguish them [S1].

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of cubes, as each cube is processed independently. The interior test and convex hull construction are constant-time operations per cube (fixed number of vertices/edges).
- **Memory Complexity**: $O(N)$ for storing the output mesh. Auxiliary data structures per cube are constant size.
- **Performance**: Produces topologically correct meshes with correct Betti numbers (e.g., $b_0=1, b_1=0, b_2=1$ for a single connected component) compared to Raman and Wenger's method which often fails (e.g., $b_0=4$) [S1].
- **Strengths**: Handles all 33 topological cases of the trilinear interpolant; avoids degenerate triangles; preserves topology better than previous extended lookup tables.
- **Limitations**: More complex implementation than standard MC; requires careful handling of the interior test and convex hulls; triangle quality may still suffer from "skinny" triangles in certain configurations [S1].

## Background
- **Origin**: The base Marching Cubes algorithm was proposed by Lorensen and Cline in 1987 [S1]. Marching Cubes 33 (MC33) was proposed by Chernyaev in 1995 to handle topological ambiguities [S1]. The extended lookup table concept was introduced by Raman and Wenger in 2008, but it only covered 23 of 33 cases [S1]. Extended Trilinear Triangulation extends MC33 by adding the `=` label and full case coverage [S1].
- **History**: The method was developed to address the trade-off between triangle quality and topological correctness. Previous methods either sacrificed topology (standard MC) or had incomplete case coverage (Raman and Wenger) [S1].
- **Usage**: Used in volume rendering and isosurface extraction for volumetric data where topological accuracy and mesh quality are critical [S1].
