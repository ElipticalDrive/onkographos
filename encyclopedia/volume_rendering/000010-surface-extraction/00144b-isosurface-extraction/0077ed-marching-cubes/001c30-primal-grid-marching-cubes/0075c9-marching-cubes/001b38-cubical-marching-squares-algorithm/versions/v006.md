# Cubical Marching Squares Algorithm
## Overview
The Cubical Marching Squares (CMS) algorithm is an isosurface extraction method that processes voxel faces using 2D Marching Squares templates to generate line segments, which are then folded back into 3D cubes to construct a triangle mesh [S2, S3]. It distinguishes itself from standard [Marching Cubes](774-marching-cubes.md) by preserving sharp features (edges and corners) and maintaining topological consistency without inter-cell dependencies, thereby eliminating cracks in multi-resolution representations [S3, S4].
## How it works
### Inputs and Outputs
*   **Input:** A 3D grid of scalar values and Hermite data (normals) at grid vertices to define sharp features [S2, S3].
*   **Output:** A polygonal mesh representing the isosurface at a specified isolevel [S3].
### Data Structures
*   **Grid:** A uniform 3D grid storing scalar values and normals at vertices [S3].
*   **Components:** Lists of line segments or vertices forming connected components on the faces of a voxel [S3].
*   **Sharp Feature Points:** 3D points $\mathbf{p}$ representing the location of sharp features, derived from Hermite data [S3].
*   Exact layouts, fields, sizes, and bit packing: Not given in the sources.
### Steps
1.  **Unfold and Process Faces:** For each voxel, consider its six faces [S2]. On each face, apply the 2D Marching Squares algorithm to determine the intersection of the isosurface with the face edges [S2]. This produces line segments (edges of the isosurface on the face) [S2]. To preserve sharp features, Hermite data is used during the interpolation on the face edges [S2, S3].
2.  **Resolve Face Ambiguities:** If a face has ambiguous edges, divide the face to resolve the ambiguity [S2]. This ensures consistent topology on the 2D level [S2].
3.  **Reconstruct 3D Components:** Fold the processed faces back into the cube [S2]. The line segments on the faces form closed loops or open segments within the voxel [S3]. These segments are grouped into connected components [S3]. Because the shared geometric component is common between neighboring cells, cracks are avoided without explicit patching [S3].
4.  **Sample Sharp Features:** For each resulting component, sample 3D sharp features [S3]. This is done by solving a linear system using Singular Value Decomposition (SVD) [S3].
5.  **Resolve Internal Ambiguity:** Internal ambiguity occurs where two components cannot be determined as joined or separated by vertex signs alone [S3]. For each component, form a cone-like volume centered at its sharp feature [S3]. Check if the cone-like volumes of two components overlap [S3]. If the volumes overlap, classify components as joined [S3]. Otherwise, classify them as separated [S3].
6.  **Triangulate Components:** If two components are separated, generate a triangle fan for each component respectively [S3]. If two components are joined, the resulting surface is topologically equivalent to a cylinder [S3]. Use a dynamic programming algorithm to connect and triangulate these two components to form the surface [S3].
### Formulas
*   $T p = n$ [S3].
    *   $p$ is the location of the sharp feature [S3].
    *   $s$ is the location of a sample point [S3].
    *   $n$ is a sample normal [S3].
    *   $T$ is the system matrix solved via singular value decomposition [S3].
### Parameters
*   **$\theta$ (theta_sharp):** A parameter affecting the quality of remeshing, defined in Extended Marching Cubes (EMC) [KBSS01] [S3]. Larger values generate more triangles for regions with higher curvatures, while flat regions remain similar [S3]. Typical values tested: 0.7, 0.8, 0.9 [S3].
### Edge Cases and Pitfalls
*   Partial implementations may lack crucial features such as sharp edge preservation [S2].
*   Incorrect resolution of face or internal ambiguities can lead to topological errors (holes or cracks) [S3].

## Operating characteristics
*   **Time Complexity:** Not explicitly given in the sources [S3]. Performance tests show extraction times scaling with triangle count: for a CSG model (cube union cylinder minus sphere), times were 16.23ms (1,688 triangles), 32.14ms (4,880 triangles), and 66.08ms (14,568 triangles) on an Intel Pentium IV 3.2GHz CPU with 1GB memory [S3].
*   **Memory Complexity:** Not explicitly given in the sources [S3]. Requires storage for the grid, Hermite data, and intermediate components [S3].
*   **Strengths:** Preserves sharp features, maintains consistent topology, generates surfaces adaptively without crack patching, and eliminates inter-cell dependency, allowing for potential GPU implementation [S3, S4].
*   **Limitations:** More complex than standard Marching Cubes due to ambiguity resolution and sharp feature sampling [S3]. The dynamic programming step for joined components adds computational overhead [S3].
*   **When to use:** CSG modeling, level of details, and remeshing polygonal meshes by converting them to distance field volume representations [S3]. Particularly useful when sharp features and topological correctness are critical [S4].
## Background
The Cubical Marching Squares algorithm was proposed to address limitations of Marching Cubes, such as the loss of sharp features and topological inconsistencies [S3, S4]. It builds on the concept of using 2D Marching Squares on voxel faces, introduced in earlier work [S2]. The method was presented in a paper by [S3] and further discussed in the context of volumetric sculpting by [S4]. It is based on the work of Kobbelt et al. [KBSS01] for sharp feature sampling [S3].
