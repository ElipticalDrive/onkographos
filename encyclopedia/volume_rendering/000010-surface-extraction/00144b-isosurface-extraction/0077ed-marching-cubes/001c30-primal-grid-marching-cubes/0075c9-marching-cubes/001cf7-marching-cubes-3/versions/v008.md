# Marching Cubes 3
## Overview
Marching Cubes 3 is a specific implementation variant of the Marching Cubes algorithm for extracting polygonal meshes from 3D scalar fields [S1, unofficial]. It provides a third implementation variant of the core algorithm, distinguished by its specific function signature and integration pattern [S1, unofficial].

## Subtopics

### [Marching Cubes with Lewiner 2003 Ambiguity Resolution](2292-marching-cubes-with-lewiner-2003-ambiguity-resolution.md)
This method resolves topological ambiguities (ambiguous faces and internal ambiguities) present in the original 1987 algorithm to guarantee a manifold surface. It differs from standard Marching Cubes by using a face ambiguity test and interior point checks to disambiguate cases where the sign configuration at cube vertices does not uniquely determine the topology. It builds on Marching Cubes 3 and is chosen when topological correctness is required over raw extraction speed.

### [Ray-Unit Parallel Marching Cubes](5169-ray-unit-parallel-marching-cubes.md)
Ray-Unit Parallel Marching Cubes (rupMC) is an enhanced Marching Cubes algorithm designed for CPU/GPU heterogeneous architectures that reduces redundant edge intersection computations and preserves topological information of the isosurface. It replaces the standard cubic voxel with a ray unit to ensure each edge intersection is calculated and stored exactly once, while parallelizing I/O via OpenMPI and computation via CUDA to handle large-scale datasets efficiently. Unlike standard MC, which suffers from repeated calculations on shared edges and lacks explicit topological connectivity, rupMC embeds topological relationships directly into the triangle composition using unique intersection indices. It is chosen for large-scale parallel rendering.

### [Isomesh](14236-isomesh.md)
Isomesh is a surface extraction technique that triangulates the level set of a 3D scalar field using the Marching Cubes algorithm and renders the result as a shaded, depth-tested mesh. It solves the visual artifacts of volume rendering approaches—specifically the striping inherent in ray-marched iso-shells and the lack of depth testing in MIP/absorption methods that forces the body to occlude the field. Unlike its siblings, it produces smooth, correctly occluded surfaces by leveraging GPU-accelerated rasterization of a pre-computed mesh rather than per-pixel ray marching. It is chosen when visual fidelity and depth testing are prioritized over raw extraction speed.

### SurfaceExtractorMC
Marching Cubes extraction over an Image3, built on the MarchingCubes 256-entry table [S2, unofficial]. The upstream Extract overloads are replaced by `extractVoxel(level, perturb, F)` returning `{ valid, mesh }` and `extract(level, perturb)` [S2, unofficial]. Only the canonical query keeps the plain name [S2, unofficial]. It is chosen when working within the gtengine-js extraction framework [S2, unofficial].
