# Finite State Machine for Interpolant Modelling


## Overview
The Finite State Machine (FSM) for Interpolant Modelling represents the evolution of isosurface topology within a voxel as the isovalue sweeps from high to low [S1]. It maps the discrete states of Marching Cubes cases to transitions triggered by vertex sign changes, thereby imposing topological constraints on the trilinear interpolant [S1]. Unlike standard Marching Cubes which relies on a static lookup table, this method models the dynamic path of cases to detect invalid configurations [S1].

## How it works
The method constructs a directed graph where nodes represent Marching Cubes cases and edges represent valid topological transitions during an isovalue sweep [S1].

**Inputs:**
- The set of valid Marching Cubes cases (e.g., the watertight cases defined by [MSS94]) [S1].
- The vertex classification logic (white if lower than $h$, black if higher than $h$) [S1].

**Outputs:**
- A transition graph defining valid state sequences [S1].
- A validation mechanism to reject invalid interpolant behaviors [S1].

**Data Structures:**
- **State:** An integer $0 \dots 255$ representing the 8-bit vertex mask of a cube [S1].
- **Transition:** A directed edge from state $S_i$ to $S_j$ if $S_j$ can be reached from $S_i$ by flipping exactly one white vertex to black [S1].

**Steps:**

1. **Initialize:** Each cube starts with case 0 (all vertices white/lower than $h$) [S1].
2. **Construct Transitions:** Define the states as the valid cases [S1]. Add a directed transition from each state to every other case that has exactly one additional black vertex [S1].
3. **Trace Path:** As $h$ decreases, vertices flip from white to black [S1]. The system traverses the FSM from the initial state through a sequence of states [S1]. At each step, verify that the transition exists in the constructed graph [S1]. If a transition is missing, the configuration is topologically invalid for the chosen interpolant [S1].

**Pseudocode:**

```python
def build_fsm(valid_cases):
    """
    Constructs the FSM for a given set of valid Marching Cubes cases.
    valid_cases: A set of integers (0-255) representing valid vertex masks.
    Returns: A dictionary mapping state -> list of next states.
    """
    fsm = {}
    for state in valid_cases:
        next_states = []
        # Iterate over all 8 vertices
        for i in range(8):
            # Check if vertex i is white (bit is 0)
            if not (state & (1 << i)):
                # Flip vertex i to black
                next_state = state | (1 << i)
                # Only add transition if the next state is also valid
                if next_state in valid_cases:
                    next_states.append(next_state)
        fsm[state] = next_states
    return fsm

def validate_sweep(vertex_order, initial_mask, fsm):
    """
    Validates if a sweep sequence follows valid FSM transitions.
    vertex_order: List of vertex indices (0-7) sorted by scalar value descending.
    initial_mask: The starting vertex mask (typically 0).
    fsm: The transition graph built by build_fsm.
    """
    current = initial_mask
    for v_idx in vertex_order:
        # Compute next state by flipping vertex v_idx to black
        next_state = current | (1 << v_idx)
        # Verify the transition exists in the FSM
        if next_state not in fsm.get(current, []):
            return False
        current = next_state
    return True
```

**Parameters:**
- **Valid Cases:** Typically the watertight cases from [MSS94] or the full set depending on the interpolant constraints [S1].
- **Isosweep Direction:** High to low [S1].

**Edge Cases:**
- Transitions that break topology are explicitly forbidden [S1]. For example, case 2 (two edge-adjacent black vertices) cannot sweep to case 7 (no edge-adjacent black vertices) because the topology forbids losing the edge adjacency [S1].
- The classification relies on vertices being strictly lower or higher than $h$ [S1].

## Subtopics

### [Marching Cubes Interpolant Extension](14166-marching-cubes-interpolant-extension.md)
The Marching Cubes Interpolant Extension is a method for modeling the geometric behavior of isosurfaces generated by the Marching Cubes algorithm through the lens of a finite state machine. It extends the concept of contour spectra to 3D by mapping distinct paths through the state machine to specific interpolant patches. Unlike standard Marching Cubes which produces a piecewise-linear surface, this extension identifies regions of polynomial spline behavior versus non-linear, piecewise-continuous behavior based on edge connectivity. It also provides a framework for detecting and reconstructing "hidden features" that linear interpolation misses.

## Operating characteristics
- **Time Complexity:** Not given in the sources [S1].
- **Memory Complexity:** Not given in the sources [S1].
- **Strengths:** Provides a rigorous topological proof for the validity of the interpolant and was used to prove the completeness of Nielson's cases [S1].
- **Limitations:** Requires pre-computation of valid cases and does not directly generate geometry; it validates or guides the generation process [S1].

## Background
The method was introduced in [S1] to model the geometric behavior of isosurfaces generated by the Marching Cubes algorithm [S1]. It builds on the concept of contour spectra [CS07] and was used to prove the completeness of Nielson's cases and model watertight Marching Cubes cases [MSS94] [S1]. It addresses the ambiguity of the trilinear interpolant by constraining the possible paths through the case space [S1].
