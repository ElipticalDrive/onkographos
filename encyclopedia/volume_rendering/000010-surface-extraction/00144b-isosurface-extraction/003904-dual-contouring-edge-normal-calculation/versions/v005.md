# Dual Contouring Edge Normal Calculation

Also called: Dual Contouring Edge Normal, Edge Normal Calculation via Vertex Gradient Averaging

## Overview
This method calculates the surface normal for a grid edge intersected by an isosurface by averaging the gradient-based normals of the two vertices defining that edge [S2, unofficial]. It builds on [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md) and provides the geometric orientation required to constrain the feature point within the quadric error function [G].

## How it works

### Inputs and Outputs
*   **Input**: `p0` and `p1` are the 3D coordinates of the grid edge endpoints [S1, S2, unofficial]. `d` is a function returning the scalar density value at integer grid coordinates [S1, S2, unofficial]. `isoLevel` is the threshold defining the isosurface [S1, S2, unofficial].
*   **Output**: `normal` is a 3D vector representing the averaged edge normal [S2, unofficial].

### Data Structures
The method uses a helper tuple `data` storing intermediate values [S1, S2, unofficial]. `data[0]` holds the density at `p0`, `data[1]` holds the density at `p1`, and `data[2]` holds `isoLevel` [S1, S2, unofficial].

### Step-by-Step Method
1.  **Sample Edge Vertex Densities**: Retrieve the density values at the two endpoints of the edge [S1, S2, unofficial].
    $$ d_0 = d(p_0) $$
    $$ d_1 = d(p_1) $$
    Store these in `data` along with the isosurface level [S1, S2, unofficial].
2.  **Calculate Vertex Gradient at $p_0$**: Compute the normal $n_0$ at vertex $p_0$ using forward differences of the density function [S1, S2, unofficial].
    $$ n_0.x = d(p_0.x + 1, p_0.y, p_0.z) - d_0 $$
    $$ n_0.y = d(p_0.x, p_0.y + 1, p_0.z) - d_0 $$
    $$ n_0.z = d(p_0.x, p_0.y, p_0.z + 1) - d_0 $$
3.  **Calculate Vertex Gradient at $p_1$**: Compute the normal $n_1$ at vertex $p_1$ using the same forward difference scheme [S1, S2, unofficial].
    $$ n_1.x = d(p_1.x + 1, p_1.y, p_1.z) - d_1 $$
    $$ n_1.y = d(p_1.x, p_1.y + 1, p_1.z) - d_1 $$
    $$ n_1.z = d(p_1.x, p_1.y, p_1.z + 1) - d_1 $$
4.  **Interpolate Edge Normal**: Blend $n_0$ and $n_1$ using linear interpolation weighted by the density values relative to the isosurface level [S1, S2, unofficial].
    $$ \text{normal} = \text{LerpByDensity}(n_0, n_1, \text{data}) $$

### Pseudocode
```python
class Vector3:
    def __init__(self, x, y, z): self.x, self.y, self.z = x, y, z
    def __mul__(self, s): return Vector3(self.x*s, self.y*s, self.z*s)
    def __add__(self, other): return Vector3(self.x+other.x, self.y+other.y, self.z+other.z)

def calculate_edge_normal(p0, p1, density_func, iso_level):
    d0 = density_func(int(p0.x), int(p0.y), int(p0.z))
    d1 = density_func(int(p1.x), int(p1.y), int(p1.z))
    data = (d0, d1, iso_level)

    n0 = Vector3(
        density_func(int(p0.x)+1, int(p0.y), int(p0.z)) - data[0],
        density_func(int(p0.x), int(p0.y)+1, int(p0.z)) - data[0],
        density_func(int(p0.x), int(p0.y), int(p0.z)+1) - data[0]
    )
    n1 = Vector3(
        density_func(int(p1.x)+1, int(p1.y), int(p1.z)) - data[1],
        density_func(int(p1.x), int(p1.y)+1, int(p1.z)) - data[1],
        density_func(int(p1.x), int(p1.y), int(p1.z)+1) - data[1]
    )

    denom = data[1] - data[0]
    t = 0.5 if abs(denom) < 1e-9 else (data[2] - data[0]) / denom
    t = max(0.0, min(1.0, t))
    normal = Vector3(
        n0.x * (1.0 - t) + n1.x * t,
        n0.y * (1.0 - t) + n1.y * t,
        n0.z * (1.0 - t) + n1.z * t
    )
    return normal
```

### Parameters and Typical Values
*   **Grid Spacing**: Implicitly 1 unit in the forward difference calculation [G].
*   **Isosurface Level**: Not given in the sources.

### Edge Cases and Pitfalls
*   **Incorrect Normals**: Interpolating normals directly can result in incorrect orientations [S1, S2, unofficial]. The source notes advise calculating per-face normals instead, though this requires triangle generation first [S1, S2, unofficial].
*   **Division by Zero**: If $d_0 = d_1$, the interpolation weight $t$ is undefined [G]. A guard clause defaulting to $0.5$ is necessary [G].
*   **Non-Unit Spacing**: If the grid cells are not unit cubes, the forward difference gradients must be scaled by the inverse of the cell dimensions to maintain correct geometric orientation [G].

## Operating characteristics

### Time and Memory Complexity
*   **Time**: $O(1)$ per edge [G]. It requires 6 density queries and a constant number of arithmetic operations [G].
*   **Memory**: $O(1)$ auxiliary space [G].

### Strengths and Limitations
*   **Strengths**: Simple to implement and uses local information only [G].
*   **Limitations**: The forward difference approximation is first-order accurate and may be noisy on sparse or low-resolution grids [G]. Averaging normals across an edge can blur sharp features if the edge crosses a high-curvature region [G].

### When to Use
Use this method when implementing a basic Dual Contouring pipeline where simplicity is prioritized over high-fidelity feature preservation [G]. It is suitable for dense grids where the forward difference approximation is sufficiently smooth [G].

## Background

### Origin and History
This specific implementation of edge normal calculation is documented in community discussions regarding the implementation of Dual Contouring in game development contexts [S1, S2, unofficial]. It appears in a Stack Exchange question from November 2015, where the author describes calculating normals for feature point projection in a Dual Contouring algorithm [S1, S2, unofficial].

### Usage
It is used as a sub-routine in Dual Contouring to define the orientation of the quadric error function constraints [G]. By providing a normal for the edge, the algorithm can better constrain the feature point to lie on the surface, improving the quality of the extracted mesh compared to using a single vertex's normal [G].
