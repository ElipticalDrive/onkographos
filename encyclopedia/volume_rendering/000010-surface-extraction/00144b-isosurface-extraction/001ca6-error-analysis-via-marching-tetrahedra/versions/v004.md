# Error Analysis via Marching Tetrahedra

Also called: Isosurface Error Evaluation

## Overview
Error Analysis via Marching Tetrahedra is a method for evaluating the geometric and topological approximation error introduced when simplifying a tetrahedral mesh by fusing two child tetrahedra into a single parent tetrahedron [S1]. It solves the problem of determining whether such a fusion is permissible in a multiresolution framework by quantifying the displacement of the isosurface [S1]. It is distinguished from sibling methods like [Subgrid Marching Tetrahedra](1737-subgrid-marching-tetrahedra.md) by its specific focus on error *evaluation* as a gating criterion for mesh simplification, rather than the subdivision or extraction mechanics themselves.

## How it works
The method operates on a tetrahedral hierarchy where the finest resolution mesh is assumed to be the ground truth [S1]. The algorithm determines if two child tetrahedra can be replaced by their parent without violating a user-defined error threshold.

**Inputs and Outputs**
*   **Input:** A parent tetrahedron $T_p$ and its two child tetrahedra $T_{c1}, T_{c2}$. Scalar density values $D(v)$ for all vertices $v$ in the hierarchy. An isovalue threshold $T_{iso}$.
*   **Output:** A scalar error value $E$. If $E > T_{threshold}$, fusion is forbidden; otherwise, it is allowed.

**Data Structures**
The method relies on the scalar field defined at the vertices of the tetrahedra. The density at any point $P$ inside a tetrahedron is evaluated via trilinear interpolation of the vertex densities [S1].

**Steps**
1.  **Sign Assignment:** Assign a sign $S(v)$ to each vertex $v$ based on the isovalue threshold $T_{iso}$:
    $$
    S(v) = \begin{cases} 
    +1 & \text{if } D(v) > T_{iso} \\
    -1 & \text{if } D(v) \le T_{iso}
    \end{cases}
    $$
    [S1]

2.  **Topological Check:** Identify the shared edge $L$ between the two child tetrahedra. Let $u, w$ be the endpoints of $L$, and $m$ be the midpoint of $L$ (the "dividing point").
    *   Calculate the density $D(m)$ using trilinear interpolation.
    *   If $S(u) == S(w)$ and $S(m) \neq S(u)$, the isosurface topology changes upon fusion (specifically corresponding to Cases a2, b2, or c3 in the source figures) [S1].
    *   Return a sufficiently large error value (e.g., $\infty$) to forbid fusion [S1].

3.  **Geometric Error Calculation:** For all other cases, calculate the physical distance between the isosurface intersection points generated by the two different density assumptions:
    *   **Assumption A:** The density at the midpoint is $D(m)$ (the actual interpolated value).
    *   **Assumption B:** The density at the midpoint is $D_{avg} = \frac{D(u) + D(w)}{2}$ (the average of the edge endpoints).
    
    For each of the four segments connecting the midpoint $m$ to the four vertices $v_i$ of the tetrahedron (excluding the endpoints of $L$ if they are not part of the specific segment logic, but generally checking the influence on the four vertices defining the local geometry):
    *   Determine if the isosurface intersects the segment connecting $m$ to $v_i$ under Assumption A. This occurs if $S(m) \neq S(v_i)$ under Assumption A.
    *   Determine if the isosurface intersects the segment connecting $m$ to $v_i$ under Assumption B. This occurs if $S_{avg}(m) \neq S(v_i)$, where $S_{avg}(m)$ is the sign derived from $D_{avg}$.
    *   If the signs of the endpoints of the segment differ under *either* assumption, calculate the position of the iso-point $P_A$ (using $D(m)$) and $P_B$ (using $D_{avg}$).
    *   The distance $d_i$ for this segment is the Euclidean distance $\| P_A - P_B \|$.
    *   If the endpoints have the same sign under both assumptions, $d_i = 0$ [S1].

4.  **Final Error:** The approximation error $E$ is the maximum of all calculated distances $d_i$ across the relevant segments:
    $$
    E = \max_i (d_i)
    $$
    [S1]

**Pseudocode**

```python
def evaluate_marching_tetrahedra_error(parent_tet, child_tets, isovalue):
    """
    Evaluates the error of fusing two child tetrahedra into a parent.
    parent_tet: dict with 'vertices' (list of 4 vertex objects)
    child_tets: list of 2 dicts, each with 'vertices' (list of 4 vertex objects)
    isovalue: float, the threshold for isosurface extraction
    """
    
    # Helper to get density
    def get_density(vertex):
        return vertex.density

    # Helper to get sign
    def get_sign(density):
        return 1 if density > isovalue else -1

    # Identify the shared edge L between the two children
    # In a standard binary split, the children share a face or edge.
    # The source specifies edge L endpoints u, w and midpoint m.
    # We assume child_tets[0] and child_tets[1] share edge L.
    
    # Find common vertices to identify edge L
    common_vertices = set(child_tets[0]['vertices']) & set(child_tets[1]['vertices'])
    
    if len(common_vertices) < 2:
        # Not a standard fusion case or invalid structure
        return float('inf')

    # Identify u and w from common vertices
    u, w = list(common_vertices)[:2]
    
    # Calculate midpoint density
    # Trilinear interpolation at midpoint of edge L
    # Since L is a straight line, linear interpolation suffices for the edge itself
    density_m = (get_density(u) + get_density(w)) / 2.0
    
    sign_u = get_sign(get_density(u))
    sign_w = get_sign(get_density(w))
    sign_m = get_sign(density_m)
    
    # Step 2: Topological Check
    if sign_u == sign_w and sign_m != sign_u:
        return float('inf')

    # Step 3: Geometric Error Calculation
    # The source mentions checking four segments connecting the dividing point (m) 
    # to the four vertices of the tetrahedra. 
    # In the context of the parent tetrahedron T_p, the vertices are V_p = [v0, v1, v2, v3].
    # The edge L is likely an internal edge or face diagonal. 
    # The source implies we check the impact on the isosurface positions relative to the parent's geometry.
    # We assume the "four vertices" refers to the vertices of the parent tetrahedron T_p.
    
    max_error = 0.0
    
    # Average density assumption for the midpoint
    density_avg = (get_density(u) + get_density(w)) / 2.0
    sign_avg = get_sign(density_avg)
    
    for v in parent_tet['vertices']:
        sign_v = get_sign(get_density(v))
        
        # Check intersection under Assumption A (density_m)
        intersects_a = (sign_m != sign_v)
        
        # Check intersection under Assumption B (density_avg)
        intersects_b = (sign_avg != sign_v)
        
        if intersects_a or intersects_b:
            # Calculate iso-point positions
            # Linear interpolation along segment m-v
            
            # Position for Assumption A
            if intersects_a:
                # t_a = (isovalue - density_m) / (density_v - density_m)
                # P_A = m + t_a * (v - m)
                # Note: If density_m == density_v, handle division by zero (should not happen if signs differ)
                denom_a = get_density(v) - density_m
                if denom_a == 0:
                    t_a = 0.0
                else:
                    t_a = (isovalue - density_m) / denom_a
                P_A = lerp_vectors(u, v, 0) # Placeholder for m position calculation
                # Actually, m is midpoint of u,w. 
                m_pos = lerp_vectors(u.position, w.position, 0.5)
                v_pos = v.position
                P_A = lerp_vectors(m_pos, v_pos, t_a)
            else:
                # If no intersection, distance contribution is 0 for this segment logic?
                # Source says: "If two endpoints ... hold the same sign ... distance is zero"
                # But here we have different signs under at least one assumption.
                # If only one assumption yields intersection, we still have a displacement?
                # The source says: "distance of two iso-points can be calculated... If two endpoints ... hold same sign when using EITHER ... distance is zero."
                # This implies if signs are same for BOTH, dist=0. If different for at least one, we calculate.
                # However, if only one assumption yields an intersection, the "other" iso-point is undefined or at infinity?
                # Re-reading: "if two endpoints hold different signs, a change ... occurs ... distance ... calculated."
                # "If two endpoints ... hold the same sign when using EITHER ... distance is zero." -> This phrasing is tricky.
                # It likely means: If sign(m) == sign(v) AND sign(avg) == sign(v), then dist=0.
                # Otherwise, we calculate the distance between the two potential iso-points.
                # If only one assumption creates an intersection, the other iso-point is effectively at the vertex or undefined.
                # Standard interpretation: Calculate P_A if intersect_a, else P_A = v (or m?).
                # Let's assume if no intersection, the iso-point is not on the segment, so the error is defined by the existing intersection?
                # Actually, if signs are same, the iso-point is not on the segment.
                # Let's stick to the max distance between P_A and P_B if both exist, or distance to the single existing point?
                # The source says "distance of two iso-points". This implies both must exist.
                # If only one exists, the error might be the distance to the vertex?
                # Given the ambiguity, we calculate P_A and P_B only if they exist on the segment.
                # If one doesn't exist, the "change" is the distance from the existing point to the vertex? 
                # No, let's look at the formula: "distance between the iso-point position using the dividing point density versus the average density".
                # This implies comparing P(m) and P(avg).
                # If P(m) is on segment and P(avg) is not, the error is the distance from P(m) to the segment endpoint?
                # Let's assume standard linear interpolation bounds.
                t_a = 0.0
                if intersects_a:
                    denom_a = get_density(v) - density_m
                    t_a = (isovalue - density_m) / denom_a if denom_a != 0 else 0.0
                    # Clamp t_a to [0,1]
                    t_a = max(0.0, min(1.0, t_a))
                P_A = lerp_vectors(m_pos, v_pos, t_a)
                
                t_b = 0.0
                if intersects_b:
                    denom_b = get_density(v) - density_avg
                    t_b = (isovalue - density_avg) / denom_b if denom_b != 0 else 0.0
                    t_b = max(0.0, min(1.0, t_b))
                P_B = lerp_vectors(m_pos, v_pos, t_b)
                
                dist = vector_distance(P_A, P_B)
                if dist > max_error:
                    max_error = dist

    return max_error

def lerp_vectors(p1, p2, t):
    return (p1[0] + t*(p2[0]-p1[0]), p1[1] + t*(p2[1]-p1[1]), p1[2] + t*(p2[2]-p1[2]))

def vector_distance(p1, p2):
    return ((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2 + (p1[2]-p2[2])**2)**0.5
```

**Parameters**
*   **Error Metric:** Physical Euclidean distance between iso-points [S1]. Projected (viewpoint-dependent) distance is an alternative but physical distance was found efficient [S1].
*   **Typical Values:** Error thresholds of 1.5, 2.5, and 4.0 were used in experiments on $129^3$ datasets [S1].

**Edge Cases and Pitfalls**
*   **Topological Change:** If the midpoint density has the opposite sign of the edge endpoints, the topology changes (Cases a2, b2, c3). Fusion must be forbidden [S1].
*   **Precision:** Trilinear interpolation is used for density evaluation [S1].
*   **Degenerate Input:** If the density values are identical, signs may be equal, resulting in zero error [S1].

## Operating characteristics
*   **Time Complexity:** Subdivision time is constant with respect to data values (e.g., 90 seconds for $129^3$) [S1]. Fusion time varies with data complexity (e.g., 19–55 seconds for $129^3$) because error evaluation depends on the density distribution [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** On an SGI Power Challenge R10000 CPU with 3GB memory:
    *   **Box Data ($129^3$):** Initial mesh: 1,646,568 tetrahedra, 182,376 triangles. With error=4.0: 114,556 tetrahedra, 51,490 triangles (93.04% fusion) [S1].
    *   **CT Head Data ($129^3$):** Initial mesh: 5,390,896 tetrahedra, 255,256 triangles. With error=4.0: 304,468 tetrahedra, 89,300 triangles (94.35% fusion) [S1].
*   **Strengths:** Efficient simplification (up to 94% fusion) while maintaining smooth transitions between levels of detail [S1].
*   **Limitations:** Fusion time depends on data complexity; topological changes are strictly forbidden, which may limit simplification in complex regions [S1].

## Background
The method was introduced in the paper "Multiresolution tetrahedral framework for visualizing regular volume data" [S1]. It is part of a framework that uses a tetrahedral hierarchy to simplify volume data visualization. The approach builds on the Marching Tetrahedra algorithm [ZCT95] for isosurface extraction.
