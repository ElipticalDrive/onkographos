# Primal Reconstruction Algorithm

Also called: Subgrid Marching Tetrahedra primal reconstruction

## Overview
The Primal Reconstruction Algorithm is a surface reconstruction method that recursively subdivides tetrahedra to construct piecewise linear surfaces, guaranteeing global embedding (no self-intersections) in $\mathbb{R}^3$ [S1]. It distinguishes itself from standard marching tetrahedra by explicitly handling non-normal curves via smeared polygons, contraction, and recursive subdivision to resolve ambiguous configurations that would otherwise produce self-intersecting or invalid meshes [S1]. It builds on [Local Surface Construction](1787-local-surface-construction.md) by providing the geometric resolution logic for the interior of the tetrahedra.

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedron with scalar field values at its vertices, defining an isosurface intersection pattern. The state is characterized by edge coordinates $(d_1, d_2)$ on its faces, where $0 \leq d_2 \leq d_1$.
*   **Output:** A set of non-intersecting, piecewise linear surface patches (triangles, smeared polygons, or curves) contained within the tetrahedron.

**Data Structures:**
The algorithm operates on the topological state of the tetrahedron's faces. The key state variable is the pair of integers $(d_1, d_2)$ representing the connectivity pattern of normal curves on a triangle-free face [S1].
*   **Edge Coordinates:** For a face with vertices $i, j, k$, the edge coordinates $e_{ij}, e_{jk}, e_{ki}$ are derived from auxiliary values $q$. At least one $q$ is zero. The remaining two are $d_1$ and $d_2$, yielding edge coordinates $d_1, d_2, d_1+d_2$ [S1].
    $$e_{ij} = q_{ik} + q_{il}$$
    $$e_{jk} = q_{ik} + q_{ij}$$
    $$e_{ki} = q_{ij} + q_{il}$$
    [S1]

**Algorithm Steps:**
1.  **Classify Surface Type:** Determine if the current configuration consists of corner triangles, contractible non-normal curves, corner-type non-normal curves, or diagonal-type curves. These classes are processed in this specific order to prove intersection freedom [S1].
2.  **Handle Corner Triangles:** Extract and remove triangles at vertices. This updates the edge coordinates of the adjacent faces according to the $(d_1, d_2)$ pattern rules [S1].
3.  **Handle Contractible Non-Normal Curves:** Identify curves that can be contracted. Apply the contraction operation to pull the curve tight at non-normal segments until it becomes normal [S1].
    *   **Contraction Operation:** On any edge where the curve has a "scoop" (a segment running along the edge), reduce the edge coordinate by 2. Repeat until the curve is normal. Smeared polygons remain smeared or are removed; this process introduces no new intersections [S1].
4.  **Handle Non-Normal Curves (Subdivision):** If non-normal curves persist (specifically corner-type or diagonal-type), check the edge coordinates $(d_1, d_2)$ on the faces.
    *   **Termination Check:** If $d_1 = d_2$, the configuration is an explicit octagon case. Construct the surface explicitly without further subdivision [S1].
    *   **Recursive Subdivision:** If $d_1 > d_2$, split the tetrahedron. Splitting creates a new vertex with incident edge coordinates $d_1, d_2, 2d_2, d_1-d_2$. The maximum edge coordinate strictly decreases, ensuring progress [S1].
    *   **Connectivity Analysis:** To determine the number of connected components for a $(d_1, d_2)$ pattern, apply a shortening operation analogous to the Euclidean algorithm: repeatedly replace $(d_1, d_2)$ with $(d_1-d_2, d_2)$ by moving the first $2d_2$ points toward their bottom-pairs until they merge. Terminate when the pair reaches $(d, 0)$ where $d = \gcd(d_1, d_2)$. The number of connected components is $d$ [S1].
5.  **Compute Component Length:** For a $(d_1, d_2)$ pattern, the length $\ell$ of every connected component is:
    $$\ell = \frac{4(d_1+d_2)}{\gcd(d_1, d_2)}$$
    When $d_1, d_2 \geq 1$, the number of segments is at least 8 [S1].
6.  **Scoop Construction Guard:** Scoops are constructed only when residual points on an edge violate the triangle inequality ($e_{ij} + e_{jk} \leq e_{ki}$). This ensures no conflicting 2D corner segments form at the opposite vertex, preventing path crossings inside scoops [S1].

**Pseudocode:**
```python
def primal_reconstruct(tetrahedron):
    """
    Reconstructs a non-intersecting surface within a tetrahedron.
    tetrahedron: Object containing vertex scalar values and face connectivity.
    Returns: List of surface primitives (triangles, polygons, curves).
    """
    # Step 1: Extract corner triangles
    # This modifies the edge coordinates of the faces.
    # Theorem B.3 implies that after removing triangles, 
    # the remaining curves form a (d1, d2) pattern.
    triangles = extract_corner_triangles(tetrahedron)
    
    # Step 2: Analyze remaining curves on faces
    # Each face now has edge coordinates derived from (d1, d2)
    # e_ij = d1, e_jk = d2, e_ki = d1 + d2 (order varies)
    faces = tetrahedron.faces
    
    # Step 3: Process non-normal curves
    for face in faces:
        curve = face.get_boundary_curve()
        if curve.is_normal():
            continue
            
        # Contraction: pull tight at non-normal segments
        while not curve.is_normal():
            for edge in curve.edges_with_scoops():
                # Reduce edge coordinate by 2 for each scoop
                edge.coordinate -= 2
            curve.update_from_edges()
            
        # If still non-normal, it requires subdivision or explicit handling
        if not curve.is_normal():
            d1, d2 = get_edge_coordinates(face)
            
            # Step 4: Check for base case (Octagon)
            if d1 == d2:
                surface = construct_octagon_surface(face, d1, d2)
                return triangles + [surface]
            else:
                # Recursive subdivision
                # Split tetrahedron creates new vertex with coords:
                # d1, d2, 2*d2, d1-d2
                new_tets = split_tetrahedron(tetrahedron, d1, d2)
                for new_tet in new_tets:
                    triangles.extend(primal_reconstruct(new_tet))
                return triangles

    return triangles

def get_edge_coordinates(face):
    """
    Returns (d1, d2) such that 0 <= d2 <= d1.
    Derived from edge coordinates e_ij, e_jk, e_ki.
    """
    e_ij, e_jk, e_ki = face.edge_coordinates()
    # The coordinates are d1, d2, d1+d2
    # Find the two smaller ones
    coords = sorted([e_ij, e_jk, e_ki])
    d2 = coords[0]
    d1 = coords[1]
    return d1, d2
```

**Edge Cases and Pitfalls:**
*   **Precision:** The algorithm relies on integer arithmetic for edge coordinates and connectivity. Floating-point errors in scalar field evaluation must be handled before entering this algorithm to ensure correct classification of edge crossings [S1].
*   **Boundary Conditions:** The algorithm assumes the tetrahedron is part of a larger mesh. The global embedding is guaranteed because surfaces are contained within their respective tetrahedra (up to $\epsilon$-perturbation) [S1].
*   **Degenerate Input:** If $d_1 = d_2$, the algorithm terminates without recursion, handling the octagon case explicitly. Failure to handle this case leads to infinite recursion or incorrect geometry [S1].

## Operating characteristics
*   **Time Complexity:** The algorithm terminates after $O(n)$ subdivisions for a tetrahedron with sum of edge coordinates $n$, running in linear time [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Guarantees a globally embedded, intersection-free mesh. Handles ambiguous non-normal configurations that standard marching tetrahedra fail to resolve correctly [S1].
*   **Limitations:** Requires recursive subdivision, which may increase the number of primitives compared to direct lookup tables. The complexity of managing the $(d_1, d_2)$ state and contraction operations adds implementation overhead [S1].
*   **When to use:** When topological correctness and non-intersection are critical, and the input data allows for the computation of edge coordinates and curve connectivity.
*   **When not to use:** When performance is paramount and approximate geometry is acceptable, or when the input data does not support the required topological analysis.

## Background
The Primal Reconstruction Algorithm is part of the Subgrid Marching Tetrahedra method. It was introduced to address the limitations of standard marching tetrahedra, which can produce self-intersecting or ambiguous configurations. The algorithm's theoretical foundation includes proofs of termination (Theorem C.1) and the no-intersection property (Theorem D.1) [S1].
