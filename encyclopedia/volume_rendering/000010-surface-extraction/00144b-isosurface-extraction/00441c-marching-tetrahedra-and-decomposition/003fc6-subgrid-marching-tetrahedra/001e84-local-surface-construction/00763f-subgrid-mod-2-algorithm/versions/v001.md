# Subgrid Mod 2 Algorithm


## Overview
The Subgrid Mod 2 Algorithm is an ablation of Subgrid Marching Tetrahedra that restricts the output to at most one intersection per edge, mimicking the connectivity of classic Marching Tetrahedra while utilizing exact input intersection locations to improve the accuracy of primal vertex positions [S1]. It solves the problem of vertex placement in isosurface extraction by averaging multiple true intersection points along an edge, thereby reducing geometric error compared to classic methods, though it cannot resolve complex topologies like multiple discs per tetrahedron [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral grid where each edge $i$ has a known set of true intersection locations with the zero set of the scalar field. Let $L_i = \{l_{i,1}, l_{i,2}, \dots, l_{i,n_i}\}$ be the list of intersection locations along edge $i$, where $n_i$ is the count of intersections.
*   **Output:** A mesh with connectivity identical to classic Marching Tetrahedra, where each edge contains at most one vertex. The position of this vertex is the aggregated intersection location.

**Data Structures:**
*   For each edge $i$ in the tetrahedral mesh, store the list of intersection coordinates $L_i$.
*   Compute the parity $p_i = n_i \bmod 2$ for each edge.

**Steps:**
1.  **Determine Parity:** For each edge $i$, calculate the number of intersections $n_i$. Compute the parity bit $p_i = n_i \bmod 2$. This parity determines if the endpoints of edge $i$ lie on different sides of the closed surface $S$, which is sufficient for detecting sign changes [S1].
2.  **Aggregate Intersection Location:** Calculate the aggregated intersection location $v_i$ for edge $i$ by averaging all true intersection positions found on that edge:
    $$ v_i = \frac{1}{n_i} \sum_{j=1}^{n_i} l_{i,j} $$
    If $n_i = 0$, no vertex is placed on this edge. If $n_i = 1$, then $v_i = l_{i,1}$, which is the exact location of the zero set [S1].
3.  **Construct Mesh Connectivity:** Use the parity bits $p_i$ to determine the connectivity of the mesh within each tetrahedron, exactly as in classic Marching Tetrahedra. If an edge has $p_i = 1$, it contributes a vertex to the mesh; if $p_i = 0$, it does not. The resulting mesh has the same connectivity as classic Marching Tetrahedra [S1].

**Pseudocode:**
```python
def subgrid_mod_2(tetrahedra, edge_intersections):
    """
    tetrahedra: List of tetrahedra, each defined by 4 vertex indices.
    edge_intersections: Dict mapping edge index (tuple of vertex indices) to a list of float intersection locations.
    
    Returns:
    vertices: List of 3D points.
    triangles: List of triangle indices into vertices.
    """
    # Map edge index to aggregated vertex position
    edge_vertices = {}
    
    for edge, locations in edge_intersections.items():
        n_i = len(locations)
        if n_i == 0:
            continue
        
        # Step 1: Determine parity
        parity = n_i % 2
        
        # Step 2: Aggregate intersection location
        # Average all true intersection positions
        avg_location = sum(locations) / n_i
        
        # Only place a vertex if parity indicates a sign change (odd number of intersections)
        if parity == 1:
            edge_vertices[edge] = avg_location
            
    # Step 3: Construct mesh connectivity (same as classic Marching Tetrahedra)
    # This part depends on the specific lookup table for Marching Tetrahedra
    # which maps the 4 edge parities to a set of triangles.
    # Since the connectivity is identical to classic Marching Tetrahedra,
    # we use the standard lookup table based on the parity bits.
    
    vertices_list = []
    triangles_list = []
    vertex_map = {} # Map edge index to vertex index in vertices_list
    
    # First pass: collect all vertices
    for edge, pos in edge_vertices.items():
        idx = len(vertices_list)
        vertices_list.append(pos)
        vertex_map[edge] = idx
        
    # Second pass: generate triangles based on classic Marching Tetrahedra logic
    # For each tetrahedron, determine the 4 edge parities
    # Use the standard 16-case lookup table for Marching Tetrahedra
    # to determine which triangles to form from the available edge vertices.
    
    for tet in tetrahedra:
        # Get the 6 edges of the tetrahedron
        edges = get_tetrahedron_edges(tet)
        
        # Determine parity for each edge
        parities = []
        for edge in edges:
            if edge in edge_intersections:
                n_i = len(edge_intersections[edge])
                parities.append(n_i % 2)
            else:
                parities.append(0)
                
        # Use classic Marching Tetrahedra lookup table to get triangle indices
        # The lookup table returns indices into the edge list
        triangle_indices = marching_tetrahedra_lookup(parities)
        
        for tri in triangle_indices:
            # tri is a tuple of 3 edge indices from the lookup table
            v_indices = []
            for edge_idx in tri:
                edge = edges[edge_idx]
                if edge in vertex_map:
                    v_indices.append(vertex_map[edge])
                else:
                    # This case should not happen if parities are consistent
                    # with the lookup table, but guard against it
                    pass
                    
            if len(v_indices) == 3:
                triangles_list.append(v_indices)
                
    return vertices_list, triangles_list

def get_tetrahedron_edges(tet):
    """Returns the 6 edges of a tetrahedron as tuples of vertex indices."""
    v0, v1, v2, v3 = tet
    return [
        (min(v0, v1), max(v0, v1)),
        (min(v0, v2), max(v0, v2)),
        (min(v0, v3), max(v0, v3)),
        (min(v1, v2), max(v1, v2)),
        (min(v1, v3), max(v1, v3)),
        (min(v2, v3), max(v2, v3))
    ]
```

**Edge Cases and Pitfalls:**
*   If $n_i = 0$, no vertex is placed.
*   If $n_i > 0$ but parity is 0 (even number of intersections), no vertex is placed, even though intersections exist. This is by design to maintain classic connectivity [S1].
*   Precision issues in averaging multiple intersection locations may introduce small errors, but this is generally more accurate than linear interpolation [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** In a $100^3$ grid comparison, Subgrid Mod 2 has slightly better geometric quality than Marching Tetrahedra [S1].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Improves the accuracy of primal vertex positions compared to classic Marching Tetrahedra by using exact intersection locations [S1].
*   **Limitations:** Cannot produce more than one disc per tetrahedron, leading to much more distortion than the full Subgrid Marching Tetrahedra algorithm [S1]. The error profile is much closer to classic Marching Tetrahedra than to Subgrid Marching Tetrahedra [S1].
*   **When to use:** When the mesh connectivity of classic Marching Tetrahedra is desired, but improved vertex accuracy is needed.
*   **When not:** When complex topologies (multiple discs per tetrahedron) are present, as it cannot resolve them.

## Background
The Subgrid Mod 2 Algorithm was introduced as an ablation study in the paper "Subgrid Marching Tetrahedra" to investigate the importance of using all intersections along each edge versus just their parity [S1]. It was developed by the authors of the Subgrid Marching Tetrahedra method [S1].
