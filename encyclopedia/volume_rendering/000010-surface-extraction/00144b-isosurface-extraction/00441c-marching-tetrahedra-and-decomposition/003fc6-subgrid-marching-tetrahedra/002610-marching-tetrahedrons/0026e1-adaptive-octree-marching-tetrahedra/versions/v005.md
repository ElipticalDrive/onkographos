# Adaptive Octree Marching Tetrahedra


## Overview
Adaptive Octree Marching Tetrahedra is an isosurface extraction method that uses an adaptive octree to subdivide a 3D volume only where the scalar field contains the target isovalue [S1, unofficial]. At the leaf nodes (1x1x1 cubes), the volume is decomposed into tetrahedra, and the Marching Tetrahedra algorithm is applied to generate the mesh [S1, unofficial]. It solves the problem of inefficient uniform-grid processing by reducing memory usage and computational cost for sparse or complex datasets [S1, unofficial]. Unlike [Naive Isosurface Extraction](4328-naive-isosurface-extraction.md) which processes every voxel, this method explicitly constructs an octree data structure to manage resolution adaptivity before decomposing leaf nodes into tetrahedra for precise surface intersection [S1, unofficial].

## How it works
**Inputs:**
- A 3D scalar field stored in a 1D array (e.g., `teapotColour`) of size $256 \times 256 \times 256$ [S1, unofficial].
- A target isovalue `iso` [S1, unofficial].

**Outputs:**
- A list of vertices (`newvert`) and implied connectivity representing the isosurface [S1, unofficial].

**Data Structures:**
- **Point**: A structure containing integer coordinates `x`, `y`, `z`. Default constructor initializes to $(-1, -1, -1)$ [S1, unofficial].
- **Octree Node**:
  - `point`: Pointer to a `Point`. If `NULL`, the node is internal. If `(-1, -1, -1)`, the node is empty [S1, unofficial].
  - `topLeftFront`: `Point*` defining the minimum corner $(x_1, y_1, z_1)$ [S1, unofficial].
  - `bottomRightBack`: `Point*` defining the maximum corner $(x_2, y_2, z_2)$ [S1, unofficial].
  - `children`: A vector of 8 pointers to child `Octree` nodes [S1, unofficial].

**Algorithm Steps:**

1. **Octree Construction (`make`)**:
   - For a node defined by `topLeftFront` $(x_1, y_1, z_1)$ and `bottomRightBack` $(x_2, y_2, z_2)$, calculate midpoints `midx`, `midy`, `midz` [S1, unofficial].
   - Iterate through all voxels in the node's bounds to find `min_iso` and `max_iso` from the scalar field using index `z * 256 * 256 + y * 256 + x` [S1, unofficial].
   - **Recursive Subdivision**: If the node dimensions are greater than 1 (checked by `(midx - x_1) > 1 || (midy - y_1) > 1 || (z_2 - midz) > 1`), create 8 child octants [S1, unofficial]. The children are defined by the bounds:
     - Child 0: $(x_1, y_1, z_1)$ to $(midx, midy, midz)$ [S1, unofficial].
     - Child 1: $(midx, y_1, z_1)$ to $(x_2, midy, midz)$ [S1, unofficial].
     - Child 2: $(x_1, midy, z_1)$ to $(midx, y_2, midz)$ [S1, unofficial].
     - Child 3: $(midx, midy, z_1)$ to $(x_2, y_2, midz)$ [S1, unofficial].
     - Child 4: $(x_1, y_1, midz)$ to $(midx, midy, z_2)$ [S1, unofficial].
     - Child 5: $(midx, y_1, midz)$ to $(x_2, midy, z_2)$ [S1, unofficial].
     - Child 6: $(x_1, midy, midz)$ to $(midx, y_2, z_2)$ [S1, unofficial].
     - Child 7: $(midx, midy, midz)$ to $(x_2, y_2, z_2)$ [S1, unofficial].
   - Recursively call `make()` on children if their dimensions exceed 1 [S1, unofficial].

2. **Leaf Processing (`explore`)**:
   - When a leaf node is reached (dimensions equal 1, i.e., $x_2 - x_1 = 1, y_2 - y_1 = 1, z_2 - z_1 = 1$), identify the 8 vertices of the cube [S1, unofficial].
   - Calculate indices into the scalar field array. Let $a$ be the index for `topLeftFront`:
     $$ a = z_1 \cdot 256^2 + y_1 \cdot 256 + x_1 $$
   - The other vertex indices are derived relative to $a$ and the fixed width 256:
     - $b = a + 1$
     - $c = a + 257$
     - $d = a + 256$
     - $e = a + 256^2$
     - $f = e + 1$
     - $g = e + 257$
     - $h = e + 256$
   - Retrieve scalar values `col` for the vertices involved in the tetrahedral decomposition [S1, unofficial]. The source code decomposes the cube into 5 tetrahedra: `(h,g,c,f)`, `(h,c,d,b)`, `(d,a,e,b)`, `(h,d,e,b)`, `(h,c,f,b)` [S1, unofficial].

3. **Marching Tetrahedra Logic (`tetra`)**:
   - Determine the case index based on which vertices are inside the isosurface ($val > iso$) [S1, unofficial].
   - For each edge connecting a vertex inside the isosurface to one outside, compute the intersection point using linear interpolation:
     $$ P_{inter} = P_1 + \frac{iso - val_1}{val_2 - val_1} (P_2 - P_1) $$
     where $P_1, P_2$ are vertex coordinates and $val_1, val_2$ are their scalar values [S1, unofficial].
   - Store resulting vertices in `newvert` and increment the pointer `p` [S1, unofficial].
   - Specific cases (e.g., `0x0C`, `0x0E`) define which edges are intersected [S1, unofficial].

**Pseudocode:**

```python
class Point:
    def __init__(self, x=0, y=0, z=0):
        self.x, self.y, self.z = x, y, z

def interpolate(p1, p2, v1, v2, iso):
    if v2 == v1: return p1
    t = (iso - v1) / (v2 - v1)
    return Point(p1.x + t * (p2.x - p1.x), p1.y + t * (p2.y - p1.y), p1.z + t * (p2.z - p1.z))

def tetra_extract(v1, v2, v3, v4, col1, col2, col3, col4, iso, newvert):
    case = 0
    if col1 > iso: case |= 1
    if col2 > iso: case |= 2
    if col3 > iso: case |= 4
    if col4 > iso: case |= 8
    
    verts = [v1, v2, v3, v4]
    cols = [col1, col2, col3, col4]
    edges = [(0,1), (0,2), (0,3), (1,2), (1,3), (2,3)]
    
    intersections = []
    for i, j in edges:
        if (cols[i] > iso) != (cols[j] > iso):
            intersections.append(interpolate(verts[i], verts[j], cols[i], cols[j], iso))
            
    # Assemble triangles from intersections based on case bitmask [G]
    if len(intersections) == 3:
        newvert.extend(intersections)
    elif len(intersections) == 4:
        newvert.extend([intersections[0], intersections[1], intersections[2]])
        newvert.extend([intersections[0], intersections[2], intersections[3]])

def process_leaf(node, scalar_field, width=256, iso=0.0, newvert=None):
    if newvert is None: newvert = []
    x1, y1, z1 = node.topLeftFront.x, node.topLeftFront.y, node.topLeftFront.z
    x2, y2, z2 = node.bottomRightBack.x, node.bottomRightBack.y, node.bottomRightBack.z
    a = z1 * width * width + y1 * width + x1
    b, c, d = a + 1, a + width + 1, a + width
    e, f, g, h = a + width * width, e + 1, e + width + 1, e + width
    
    coords = [
        Point(x1, y1, z2), Point(x2, y1, z2), Point(x1, y1, z1), Point(x2, y1, z1),
        Point(x1, y2, z2), Point(x2, y2, z2), Point(x1, y2, z1), Point(x2, y2, z1)
    ]
    vals = [scalar_field[h], scalar_field[g], scalar_field[c], scalar_field[f],
            scalar_field[d], scalar_field[b], scalar_field[a], scalar_field[e]]
    tets = [
        (0,1,2,3), (0,2,4,5), (4,6,7,5), (0,4,7,5), (0,2,3,5)
    ]
    for t in tets:
        tetra_extract([vals[i] for i in t], [coords[i] for i in t], iso, newvert)
    return newvert

def build_octree(node, scalar_field, width=256, iso=0.0, newvert=None):
    if newvert is None: newvert = []
    x1, y1, z1 = node.topLeftFront.x, node.topLeftFront.y, node.topLeftFront.z
    x2, y2, z2 = node.bottomRightBack.x, node.bottomRightBack.y, node.bottomRightBack.z
    midx, midy, midz = (x1 + x2) // 2, (y1 + y2) // 2, (z1 + z2) // 2

    if (x2 - x1 == 1) and (y2 - y1 == 1) and (z2 - z1 == 1):
        return process_leaf(node, scalar_field, width, iso, newvert)

    if (midx - x1 > 1) or (midy - y1 > 1) or (z2 - midz > 1):
        bounds = [
            ((x1,y1,z1), (midx,midy,midz)), ((midx,y1,z1), (x2,midy,midz)),
            ((x1,midy,z1), (midx,y2,midz)), ((midx,midy,z1), (x2,y2,midz)),
            ((x1,y1,midz), (midx,midy,z2)), ((midx,y1,midz), (x2,midy,z2)),
            ((x1,midy,midz), (midx,y2,z2)), ((midx,midy,midz), (x2,y2,z2))
        ]
        for (bx1, by1, bz1), (bx2, by2, bz2) in bounds:
            child = OctreeNode(bx1, by1, bz1, bx2, by2, bz2)
            node.children.append(child)
            if (bx2 - bx1 > 1) or (by2 - by1 > 1) or (bz2 - bz1 > 1):
                build_octree(child, scalar_field, width, iso, newvert)
            else:
                process_leaf(child, scalar_field, width, iso, newvert)
    return newvert
```

**Parameters:**
- `iso`: Target isovalue [S1, unofficial].
- `width`: Fixed grid width for indexing. Source hardcodes 256 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Grid Indexing Assumption**: The source code assumes a fixed grid width of 256 for index calculation (`z * 256 * 256 + y * 256 + x`). This will fail for volumes with different Y-axis dimensions or non-standard strides [S1, unofficial].
- **Vertex Labeling Ambiguity**: The variable names `a` through `h` in the source code do not consistently correspond to standard vertex positions. The mapping between `col` array indices and `Vertices` array indices in the `tetra` function is unclear and may lead to incorrect edge intersections if not carefully reverse-engineered [S1, unofficial].

## Subtopics

### [Adaptive Simplicial Partitioning with Dual Vertices](9042-adaptive-simplicial-partitioning-with-dual-vertices.md)
An extension that introduces "dual vertices" within octree cells to minimize distance to local tangent planes, improving sharp feature approximation and reducing sliver triangles. Choose this when high-fidelity geometry is required and the basic tetrahedralization produces artifacts.

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of leaf nodes in the octree [S1, unofficial]. In the worst case (uniform subdivision), $N$ is proportional to the total number of voxels [S1, unofficial]. In the best case (sparse data), $N$ is significantly smaller [S1, unofficial].
- **Memory Complexity**: $O(N)$ for storing the octree structure and the resulting mesh vertices [S1, unofficial]. The octree nodes add overhead compared to a flat grid [S1, unofficial].
- **Performance**: Reduces computation time for sparse volumes by avoiding processing empty or uniform regions [S1, unofficial]. Performance degrades if the isosurface is complex and requires deep subdivision across the entire volume [S1, unofficial].
- **Strengths**: Efficient for sparse data; adaptive resolution allows high detail where needed [S1, unofficial].
- **Limitations**: Hard-coded indexing in the reference implementation limits flexibility; vertex labeling ambiguity complicates implementation; standard MT can produce sliver triangles [S1, unofficial].
- **When to use**: When the volume is sparse or has varying feature density, and memory is a constraint [S1, unofficial].
- **When not to use**: When the volume is dense and uniform, or when strict topological correctness is required without additional post-processing (standard MT can have connectivity issues at boundaries) [S1, unofficial].
