# TetraSDF Marching Tetrahedra Extraction

Also called: Analytic Isosurface Extraction, TetraSDF extraction, TetraSDF meshing, subpoly extraction

## Overview
TetraSDF Marching Tetrahedra Extraction is an analytic isosurface extraction method that generates a triangular mesh from a trained Signed Distance Function (SDF) neural network by evaluating the network on a multi-resolution tetrahedral grid [S1, unofficial]. It differs from standard grid-based marching tetrahedra by using an adaptive, multi-resolution domain decomposition and an analytic intersection approach to handle the continuous nature of the neural network output, rather than relying solely on discrete voxel sampling [S1, unofficial].

## How it works
**Inputs:**
- `net`: A trained SDF neural network capable of evaluating $SDF(x)$ for any 3D point $x$.
- `DIM`: Dimensionality of the domain (typically 3).
- `CANVAS_SIZE`: The scale of the bounding box (typically 1.0).
- `training_data.R`: A scaling factor used to map between the normalized model space and the training data space.
- `eps_sdf`: A small epsilon threshold for determining if a point is on the surface.
- `decimal`: Number of decimal places for vertex rounding to handle floating-point precision during deduplication.
- `tol_geom`: Geometric tolerance for edge connectivity/intersection thresholds.
- `chunk_size`: Batch size for processing vertices and planes to manage memory.
- `use_fp64`: Boolean flag to enable double-precision arithmetic for edge construction.

**Outputs:**
- `vertices`: Tensor of shape $[N, 3]$ containing the mesh vertices.
- `faces`: Tensor of shape $[M, 3]$ containing face indices referencing the vertices.
- `edges`: Tensor of shape $[K, 2]$ containing edge indices (optional, depending on implementation details).

**Data Structures:**
- `verts_all`: A list of tensors, each containing vertices extracted from a specific resolution level or batch.
- `planes_u`: A tensor representing the tetrahedral grid planes or sample points.
- `trimesh.Trimesh`: A standard mesh object constructed from vertices and faces.

**Steps:**
1.  **Initialization**: Initialize `verts_all` as an empty list. Determine the device (CPU/GPU) and dtype for the output tensors.
2.  **Multi-resolution Sampling**: The method iterates over a multi-resolution tetrahedral grid. For each resolution level, a set of sample points $u$ is generated within the bounding box defined by `CANVAS_SIZE`.
3.  **Coordinate Transformation**: For each sample point $u$, compute the world coordinates:
    $$ x_{world} = u \times 2.0 - 1.0 $$
    This maps the sample points from the range $[0, 1]$ to $[-1, 1]$.
4.  **SDF Evaluation**: Query the SDF network for the transformed points:
    $$ mask\_sdf = |net.sdf(x_{world})[:, 0]| < \epsilon_{sdf} $$
    The network output is filtered to keep only points where the absolute SDF value is below the threshold `eps_sdf`.
5.  **Filtering**:
    - If any points satisfy the mask, filter the sample points: $u = u[mask\_sdf]$.
    - If no points satisfy the mask, discard the current batch and continue to the next iteration.
6.  **Vertex Collection**: If the filtered tensor $u$ has elements ($u.numel() > 0$), append $u$ (converted to the target dtype) to `verts_all`.
7.  **Empty Check**: If `verts_all` is empty after processing all resolutions, return empty tensors for vertices (shape $[0, 3]$) and edges (shape $[0, 2]$).
8.  **Concatenation and Deduplication**:
    - Concatenate all vertex lists: $vertices = \text{torch.cat}(verts\_all, dim=0)$.
    - Deduplicate vertices by rounding to `decimal` places and taking unique values:
      $$ vertices = \text{torch.unique}(\text{torch.round}(vertices, decimals=decimal), dim=0) $$
9.  **Edge Construction**: Build the edge tensor using a specialized function `build_edges_tensorized`. This function takes `vertices`, `planes_u`, `tol_geom`, `device`, `v_chunk`, `p_chunk`, and `use_fp64` as arguments. The result is cast to `torch.long`.
10. **Mesh Construction**: Construct the final mesh using `trimesh.Trimesh(vertices, triangles, process=False)`. The triangles are derived from the analytic intersections computed during the edge construction and surface determination phases.

**Edge Cases and Pitfalls:**
- **Precision Issues**: Floating-point inaccuracies during vertex merging can lead to non-watertight meshes or artifacts. Using `decimal` rounding and `use_fp64` mitigates this [S1, unofficial].
- **Empty Surface**: If no points satisfy the SDF threshold, the method returns empty tensors. This may indicate a failure in sampling or an incorrect isovalue [S1, unofficial].
- **Memory Management**: Large volumes require chunking (`chunk_size`) to avoid out-of-memory errors during SDF evaluation and edge construction [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Depends on the number of sample points and the resolution levels. The multi-resolution approach reduces the number of points needed compared to a uniform high-resolution grid.
- **Memory Complexity**: Proportional to the number of sample points and the size of the intermediate tensors. Chunking helps manage peak memory usage.
- **Strengths**: Analytic extraction provides smoother surfaces and better handling of complex topologies compared to discrete marching tetrahedra. Multi-resolution sampling allows for efficient detail capture.
- **Limitations**: Requires a trained SDF network. Performance depends on the network's inference speed. Precision issues can arise if not handled carefully.

## Background
TetraSDF was introduced by NAVER Corp. as a method for representing and extracting 3D shapes from neural networks using a tetrahedral grid decomposition [S1, unofficial]. It builds on the principles of Marching Tetrahedra but adapts them for continuous neural network outputs.
