# 4D Tetrahedron Slicing (Vertex Shader)

Also called: 4D Tetrahedron Clipping via Vertex Shader, CodeParade Method

## Overview
A GPU-based method to compute the 3D cross-section of a 4D tetrahedron against a slicing hyperplane using the Vertex Shader [S1, unofficial]. It outputs 0, 1, or 2 triangles representing the intersection [S1, unofficial]. It sets itself apart from its sibling [4D Tetrahedron Slicing (Geometry Shader)](19630-4d-tetrahedron-slicing-geometry-shader.md) by replicating vertex data four times to drive parallel computation in the Vertex Shader, at the cost of increased conditional branching [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A structure containing the four 4D vertices of a tetrahedron, replicated four times with an appended index (0–3) identifying the vertex being processed [S1, unofficial].
*   **Output:** 0, 1, or 2 triangles (0 to 6 vertices) representing the intersection polygon [S1, unofficial].

**Data Structures:**
The input stream consists of the replicated vertex data paired with a vertex ID (0–3) [S1, unofficial]. Each vertex is stored as a 4D vector $(x, y, z, w)$ [S1, unofficial].

**Steps:**
1.  **Hyperplane Evaluation:** For each vertex passed to the Vertex Shader, substitute its 4D coordinates into the slicing hyperplane equation $H(\mathbf{v}) = \mathbf{n} \cdot \mathbf{v} + d = 0$ to determine its signed distance relative to the plane [S1, unofficial].
2.  **Topology Determination:** Classify the intersection shape based on the signs of the four vertices: if all are on one side, output nothing; if split 1 vs 3, output a triangle; if split 2 vs 2, output a quadrilateral decomposed into two triangles [S1, unofficial]. This classification is resolved using a pre-computed lookup table indexed by the vertex sign configuration to avoid conditional branching in the shader [S1, unofficial].
3.  **Intersection Calculation:** Compute the exact 3D coordinates of intersection points on the tetrahedron edges where the plane crosses [S1, unofficial].
4.  **Output Generation:** Emit the calculated vertices as triangles based on the determined topology [S1, unofficial].

**Formulas:**
*   Plane evaluation: $d_i = n_x v_{i,x} + n_y v_{i,y} + n_z v_{i,z} + n_w v_{i,w} + d$ [S1, unofficial].
*   Intersection parameter: $t = \frac{d_i}{d_i - d_j}$ [S1, unofficial].
*   Intersection point: $\mathbf{p}_{3D} = \mathbf{v}_i + t(\mathbf{v}_j - \mathbf{v}_i)$, projected to 3D by discarding the $w$ component [S1, unofficial].
*   Symbols: $\mathbf{n} = (n_x, n_y, n_z, n_w)$ is the 4D plane normal, $\mathbf{v}_i = (v_{i,x}, v_{i,y}, v_{i,z}, v_{i,w})$ is the $i$-th vertex, $d$ is the plane offset, $d_i$ and $d_j$ are signed distances for vertices $i$ and $j$, and $t \in [0, 1]$ is the interpolation factor along the edge [S1, unofficial].

**Parameters:**
*   Typical values: Not given in the sources [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Branching:** The algorithm involves many conditional branches based on vertex signs to determine topology and output vertices, which hurts GPU parallel efficiency [S1, unofficial].
*   **Mitigation:** Use a pre-computed lookup table (texture) to determine the output topology and avoid conditional branches in the shader [S1, unofficial].
*   **Precision:** Degenerate cases where $d_i = d_j$ cause division by zero in the interpolation factor; these occur when an edge lies exactly on the slicing plane and should be handled with a small epsilon or treated as coincident [G].
*   **Boundaries:** Vertices exactly on the plane ($d_i = 0$) are classified as positive to ensure consistent topology mapping [G].

**Pseudocode:**
```python
def vertex_shader_slice(tet_vertices, plane_normal, plane_dist):
    """
    Simulates the Vertex Shader processing for one 4D tetrahedron.
    tet_vertices: list of 4 vectors, each (x, y, z, w)
    plane_normal: 4D vector (nx, ny, nz, nw)
    plane_dist: float d
    Returns: list of triangles, each triangle is list of 3D vectors (x, y, z)
    """
    # Step 1: Evaluate plane equation for each vertex
    signs = 0
    distances = []
    for i, v in enumerate(tet_vertices):
        d = plane_normal[0]*v[0] + plane_normal[1]*v[1] + plane_normal[2]*v[2] + plane_normal[3]*v[3] + plane_dist
        distances.append(d)
        if d >= 0:
            signs |= (1 << i)

    # Step 2: Lookup topology from pre-computed table
    # Maps bitmask to list of edge indices that form the intersection polygon
    # Edges are ordered: (0,1), (0,2), (0,3), (1,2), (1,3), (2,3) -> indices 0..5
    topology_table = {
        0b0000: [], 0b1111: [],
        0b0001: [0, 1, 3], 0b0010: [0, 2, 4], 0b0100: [1, 2, 5], 0b1000: [3, 4, 5],
        0b0011: [0, 2, 3, 4], 0b0101: [0, 1, 4, 5], 0b1001: [0, 3, 1, 5], 0b1100: [2, 3, 4, 5],
        0b0110: [1, 3, 2, 4], 0b1010: [3, 5, 4, 2], 0b1101: [4, 5, 0, 3], 0b1011: [5, 0, 1, 4]
    }
    edge_indices = topology_table.get(signs, [])
    if not edge_indices:
        return []

    # Step 3: Compute intersection points on crossing edges
    intersections = []
    edge_map = [(0,1), (0,2), (0,3), (1,2), (1,3), (2,3)]
    for e_idx in edge_indices:
        v1_idx, v2_idx = edge_map[e_idx]
        d1, d2 = distances[v1_idx], distances[v2_idx]
        t = d1 / (d1 - d2)
        p4 = [tet_vertices[v1_idx][k] + t * (tet_vertices[v2_idx][k] - tet_vertices[v1_idx][k]) for k in range(4)]
        intersections.append(p4[:3])

    # Step 4: Output triangles
    triangles = []
    if len(edge_indices) == 3:
        triangles.append(intersections)
    elif len(edge_indices) == 4:
        triangles.append([intersections[0], intersections[1], intersections[2]])
        triangles.append([intersections[0], intersections[2], intersections[3]])
    return triangles
```

## Subtopics

### 4D Rasterization Pipeline Adaptation
A technique to render 4D cross-sections on standard 3D GPUs by adapting the coordinate system [S1, unofficial]. It uses a 5D homogeneous coordinate system conceptually, but implements it using 4D vectors and a separate float to handle depth and perspective [S1, unofficial]. It is chosen when rendering on hardware that lacks native 5D support [S1, unofficial]. Steps: Transform 4D vertices to 5D homogeneous coordinates [S1, unofficial]. Since `vec5` is unavailable, store the 5th component (depth) in a separate float variable and the first 4 components in a `vec4` [S1, unofficial]. If the slicing plane is perpendicular to a coordinate axis, discard the coordinate corresponding to that axis (as it is constant for the slice) [S1, unofficial]. Reduce the homogeneous vector to 4D [S1, unofficial]. Pass the resulting 4D vector to the Vertex Shader [S1, unofficial]. The first 3 components are treated as 3D screen position, the 4th component is used for depth testing (Z-buffer), and the 4th component is also used for perspective division (w-component) [S1, unofficial].

*   **Limitations:** Data replication (4x vertex data) increases memory bandwidth usage [S1, unofficial]. Branching can reduce parallel efficiency [S1, unofficial].
*   **When to use:** When targeting platforms without Geometry Shader support (e.g., WebGL, WebGPU) or when simplicity of implementation is prioritized over memory efficiency [S1, unofficial].

## Background
Originated from the work of YouTuber CodeParade in the game "4D Golf" [S1, unofficial]. It is part of a broader effort in 4D computer graphics to render 4D objects by slicing them into 3D cross-sections [S1, unofficial]. The method was developed to overcome the limitations of CPU-based slicing and the lack of native 4D rendering support in standard 3D GPUs [S1, unofficial].
