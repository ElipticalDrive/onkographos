# Error Analysis via Marching Tetrahedra

Also called: Isosurface Error Evaluation

## Overview
Error Analysis via Marching Tetrahedra is a method for evaluating the geometric and topological approximation error introduced when two child tetrahedra in a multiresolution hierarchy are fused into their parent tetrahedron [S1]. It solves the problem of determining whether a coarser representation of the volume data preserves the isosurface geometry within a user-defined tolerance [S1]. Unlike sibling methods that may focus on pure geometric distance or view-dependent projection, this method specifically ties the error metric to the topological consistency of the isosurface extraction process itself, ensuring that fusion does not alter the connectivity of the surface [S1].

## How it works
The method operates on a tetrahedral mesh derived from a regular grid volume. It assumes that the density (scalar value) at any point within a tetrahedron is evaluated via trilinear interpolation of the vertex densities [S1]. The core mechanism compares the isosurface configuration of the two fine-grained child tetrahedra against the configuration of the single coarse parent tetrahedron.

### Inputs and Outputs
*   **Inputs**:
    *   Two child tetrahedra ($T_1, T_2$) sharing a common face.
    *   Scalar density values at all vertices of $T_1$ and $T_2$.
    *   The isovalue threshold ($\theta$) defining the isosurface.
    *   A maximum allowable error threshold ($\epsilon_{max}$).
*   **Outputs**:
    *   A boolean indicating whether fusion is permitted.
    *   The calculated approximation error (physical distance).

### Data Structures
The method requires access to the scalar values at the vertices of the tetrahedra. Let the vertices of the two child tetrahedra be defined by their scalar densities $v_i$. The "dividing point" refers to the vertex shared by the two children that lies on the internal face of the parent, or more specifically in the context of the source, the point on the edge $L$ where the isosurface intersects, or the vertex used to define the subdivision boundary. Based on the source description, the analysis focuses on a specific edge $L$ and its dividing point.

Let:
*   $L$ be an edge shared by the two tetrahedra or an internal edge involved in the subdivision.
*   $p_{div}$ be the dividing point on edge $L$ (typically the midpoint or the point where the isosurface intersects in the fine mesh).
*   $v_{end1}, v_{end2}$ be the endpoints of edge $L$.
*   $d(v)$ be the density value at vertex $v$.
*   $\theta$ be the isovalue.

### Steps
1.  **Sign Assignment**: Assign a sign to each relevant vertex. A vertex $v$ has a positive sign if $d(v) > \theta$, and negative otherwise ($d(v) \le \theta$) [S1].
2.  **Topological Check**: Check the signs of the endpoints of edge $L$ ($v_{end1}, v_{end2}$) and the dividing point $p_{div}$ (or the density at the dividing point derived from the fine mesh).
    *   If $sign(v_{end1}) == sign(v_{end2})$ AND $sign(p_{div}) \neq sign(v_{end1})$, the isosurface topology changes upon fusion (specifically corresponding to Cases a2, b2, c3 in the source figures) [S1].
    *   In this case, return an error value $> \epsilon_{max}$ (effectively forbidding fusion) [S1].
3.  **Geometric Error Calculation**: For all other cases, calculate the geometric error by analyzing four segments connecting the dividing point $p_{div}$ to the four vertices of the tetrahedra involved in the local configuration [S1].
    *   For each segment, identify the two endpoints.
    *   Calculate the position of the isosurface intersection (iso-point) using the **dividing point density** ($d(p_{div})$) for the fine mesh representation.
    *   Calculate the position of the isosurface intersection using the **average density** of the edge endpoints ($\bar{d} = (d(v_{start}) + d(v_{end}))/2$) for the coarse/parent representation approximation [S1].
    *   If the endpoints of the segment have different signs under *either* density assumption, calculate the physical distance between the two resulting iso-points [S1].
    *   If the endpoints have the same sign under both assumptions, the distance is zero [S1].
4.  **Error Aggregation**: The approximation error for the fusion is the maximum of all distance values calculated across the four segments [S1].
5.  **Decision**: If the calculated error $\le \epsilon_{max}$, fusion is allowed. Otherwise, it is forbidden [S1].

### Pseudocode

```python
def evaluate_marching_tetrahedra_error(
    density_end1: float,
    density_end2: float,
    density_dividing_point: float,
    density_vertices: list[float], # The 4 vertices of the tetrahedra configuration
    isovalue: float
) -> float:
    """
    Calculates the approximation error for fusing two tetrahedra into one.
    
    Args:
        density_end1: Density at endpoint 1 of the critical edge L.
        density_end2: Density at endpoint 2 of the critical edge L.
        density_dividing_point: Density at the dividing point on edge L (from fine mesh).
        density_vertices: List of densities at the 4 vertices of the tetrahedra being fused.
        isovalue: The threshold for isosurface extraction.
        
    Returns:
        The maximum physical distance between iso-points. Returns infinity if topology changes.
    """
    
    # Step 1: Sign Assignment
    # Positive if density > isovalue, negative otherwise
    def get_sign(density):
        return 1 if density > isovalue else -1

    sign_end1 = get_sign(density_end1)
    sign_end2 = get_sign(density_end2)
    sign_div = get_sign(density_dividing_point)

    # Step 2: Topological Check
    # If endpoints have same sign and dividing point has opposite sign, topology changes
    if sign_end1 == sign_end2 and sign_end1 != sign_div:
        return float('inf') # Forbid fusion

    # Step 3: Geometric Error Calculation
    # Analyze four segments connecting the dividing point to the four vertices.
    # Note: The source specifies "four segments which connect the dividing point 
    # to four vertices of the tetrahedra". We assume density_dividing_point 
    # represents the fine-grained value, and the coarse approximation uses 
    # the average of the segment endpoints.
    
    max_error = 0.0
    
    # The vertices involved in the segments are the dividing point and the 
    # 4 vertices of the tetrahedra. However, the dividing point lies on edge L.
    # The source implies we check segments from the dividing point to the 
    # tetrahedron vertices. Let's assume the 'density_vertices' are the 
    # non-L vertices or the relevant vertices for the local configuration.
    # To be precise to the source: "check the iso-point changes along four segments 
    # which connect the dividing point to four vertices of the tetrahedra."
    
    # We need the coordinates to calculate physical distance. 
    # Since coordinates are not in the source notes, we assume a generic 
    # interpolation function. In a real implementation, coordinates are required.
    # Here we define the logic for the density-based iso-point calculation.
    
    for v_density in density_vertices:
        # Segment endpoints: Dividing Point (DP) and Vertex (V)
        dp_dens = density_dividing_point
        v_dens = v_density
        
        # Fine mesh iso-point calculation (using DP density)
        # Linear interpolation between DP and V
        # Iso-point position t_fine such that: dp_dens + t*(v_dens - dp_dens) = isovalue
        # t_fine = (isovalue - dp_dens) / (v_dens - dp_dens)
        
        # Coarse mesh iso-point calculation (using Average Density of endpoints)
        # Avg density of the segment endpoints (DP and V)
        avg_dens = (dp_dens + v_dens) / 2.0
        
        # Check signs for coarse approximation
        sign_avg = get_sign(avg_dens)
        sign_v = get_sign(v_dens)
        
        # If endpoints have same sign under EITHER assumption, distance is zero
        # Assumption 1: Using DP density (Fine)
        sign_dp = get_sign(dp_dens)
        
        # Assumption 2: Using Avg density (Coarse)
        
        # The source says: "If two endpoints of a segment hold the same sign 
        # when using either the dividing point density or the average density, 
        # the distance is regarded as zero."
        
        # Check Fine Assumption
        same_sign_fine = (sign_dp == sign_v)
        
        # Check Coarse Assumption
        same_sign_coarse = (sign_avg == sign_v)
        
        if same_sign_fine or same_sign_coarse:
            current_error = 0.0
        else:
            # Calculate physical distance between the two iso-points
            # This requires coordinates. Let coord_dp and coord_v be the coordinates.
            # Since coordinates are not provided in the source text, we define 
            # the formula symbolically. In implementation, these must be passed.
            # t_fine = (isovalue - dp_dens) / (v_dens - dp_dens)
            # t_coarse = (isovalue - avg_dens) / (v_dens - avg_dens)
            
            # To avoid division by zero, handle equal densities
            if v_dens == dp_dens:
                t_fine = 0.0 # Or undefined, but if densities equal, no intersection unless equal to isovalue
            else:
                t_fine = (isovalue - dp_dens) / (v_dens - dp_dens)
                
            if v_dens == avg_dens:
                t_coarse = 0.0
            else:
                t_coarse = (isovalue - avg_dens) / (v_dens - avg_dens)
                
            # Physical distance = |t_fine - t_coarse| * |V - DP|
            # Since we don't have coordinates in this pure density-based pseudocode 
            # derived strictly from notes, we note that coordinates are required [G].
            # We return a placeholder for the distance calculation logic.
            current_error = calculate_physical_distance(t_fine, t_coarse, coord_dp, coord_v)
            
        if current_error > max_error:
            max_error = current_error
            
    return max_error

def calculate_physical_distance(t_fine, t_coarse, coord_dp, coord_v):
    """
    Helper to calculate physical distance given interpolation parameters.
    This is a standard vector operation [G].
    """
    import math
    # Vector from DP to V
    vec = [coord_v[i] - coord_dp[i] for i in range(3)]
    # Distance between points
    dist_vec = math.sqrt(sum(x**2 for x in vec))
    
    # The iso-points are at t_fine * vec and t_coarse * vec from DP
    diff_t = abs(t_fine - t_coarse)
    return diff_t * dist_vec
```

### Parameters
*   **Error Metric**: Physical distance between iso-points. Projected (viewpoint-dependent) distance is an alternative but was found less efficient in experiments [S1].
*   **Typical Values**: For the Box dataset ($129^3$), an error threshold of 4.0 resulted in 93.04% fusion [S1]. For the CT Head dataset ($129^3$), an error of 4.0 resulted in 94.35% fusion [S1].

### Edge Cases and Pitfalls
*   **Topological Changes**: The most critical pitfall is the topological change case (Cases a2, b2, c3). If the endpoints of edge $L$ have the same sign and the dividing point has the opposite sign, the isosurface topology changes. The method must return a large error value to forbid fusion [S1].
*   **Precision**: The method relies on the assumption that the finest resolution tetrahedral mesh is the most accurate representation of the data [S1].
*   **Coordinate Dependency**: While the error logic is density-based, the final error value is a physical distance, requiring vertex coordinates [S1].

## Operating characteristics
*   **Time Complexity**: The subdivision time is constant and independent of data values (e.g., 90 seconds for $129^3$ resolution) [S1]. The fusion time varies depending on data complexity and the number of error evaluations required (e.g., 19 seconds for Box, 55 seconds for CT Head at $129^3$) [S1].
*   **Memory Complexity**: Not given in the sources.
*   **Measured Performance**:
    *   **Box ($129^3$)**: Initial mesh has 1,646,568 tetrahedra and 182,376 triangles (error=0). With error=4.0, it reduces to 114,556 tetrahedra and 51,490 triangles [S1].
    *   **CT Head ($129^3$)**: Initial mesh has 5,390,896 tetrahedra and 255,256 triangles (error=0). With error=4.0, it reduces to 304,488 tetrahedra and 89,300 triangles [S1].
*   **Strengths**: Efficient physical distance calculation; ensures topological consistency; allows smooth changes along boundaries of different levels-of-detail [S1].
*   **Limitations**: Fusion time depends on data complexity; requires fine-resolution mesh as a baseline for accuracy [S1].
*   **When to use**: When visualizing regular volume data with isosurfaces and a multiresolution tetrahedral framework is used, and topological correctness is critical [S1].
*   **When not**: When view-dependent rendering is the primary concern (use projected distance instead) or when topological changes are acceptable [S1].

## Background
The method was introduced in the paper "Multiresolution tetrahedral framework for visualizing regular volume data" [S1]. It is part of a framework that uses a tetrahedral subdivision of regular volume data. The method builds on the Marching Tetrahedra algorithm [ZCT95] to evaluate the error introduced by simplifying the mesh. It was implemented in C with OpenGL and tested on an SGI Power Challenge – R10000 CPU with Infinite Reality graphics [S1].
