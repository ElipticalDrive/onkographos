# Streaming Marching Cubes

Also called: Hash table vertex sharing, Polygon-Vertex Identification for Isosurface Polygons

## Overview
Streaming Marching Cubes with Hash Table Vertex Sharing is a memory-optimized isosurface extraction method that processes volumetric data in a streaming fashion while ensuring topological consistency through explicit vertex sharing. It solves the dual problems of excessive memory consumption for large datasets and the generation of duplicate vertices at shared cell edges, which complicates downstream mesh processing. Unlike standard Marching Cubes, which may generate multiple vertices for the same geometric point, this method uses a hash table to link polygon vertices to cell edges, guaranteeing that adjacent polygons share identical vertex instances. It builds on [Memory and Performance Optimization](12239-memory-and-performance-optimization.md) by combining streaming data access with explicit vertex identification.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset $V$ defined on a 3D grid, an isovalue $C$, and the grid dimensions $(N_x, N_y, N_z)$.
*   **Output:** A triangle mesh representing the isosurface $S(x,y,z) = C$, where shared vertices are uniquely identified.

**Data Structures:**
1.  **Hash Table ($H$):** A dictionary mapping a unique key (representing a cell edge) to a vertex object.
    *   **Key:** A tuple or hashable representation of the two grid nodes defining the cell edge. For a grid-aligned edge, this is typically the pair of integer coordinates $(i_1, j_1, k_1)$ and $(i_2, j_2, k_2)$ of the nodes.
    *   **Value:** The 3D position $(x, y, z)$ of the interpolated vertex on that edge.
2.  **Streaming Buffer:** A memory buffer holding only two slices of the volume data (e.g., current and next $z$-slice, or current and next $y$-slice depending on traversal order) to minimize RAM usage.

**Numbered Steps:**
1.  **Initialize:** Create an empty hash table $H$. Initialize the streaming buffer with the first two slices of the volume data.
2.  **Traverse Cells:** Iterate through the volume data in a streaming manner, processing one cell at a time. For each cell, identify the 8 corner nodes.
3.  **Sign Determination:** For each of the 8 nodes $n_i$ of the current cell, compute the sign of $S(n_i) - C$, where $S(n_i)$ is the scalar value at node $n_i$.
4.  **Skip Non-Isosurface Cells:** If all 8 signs are equal (all positive or all negative), the cell does not intersect the isosurface. Skip further processing for this cell [S1, unofficial].
5.  **Identify Intersecting Edges:** Determine which cell edges intersect the isosurface. A cell edge connects two nodes $n_a$ and $n_b$. The edge intersects the isosurface if the signs of $S(n_a) - C$ and $S(n_b) - C$ are different [S1, unofficial].
6.  **Vertex Identification and Registration:** For each intersecting edge defined by nodes $n_a$ and $n_b$:
    *   Construct the edge key $K = \text{hash}(n_a, n_b)$.
    *   Check if $K$ exists in $H$.
    *   **If $K$ exists:** Retrieve the existing vertex position $V_{pos}$ from $H$. This ensures vertex sharing [S1, unofficial].
    *   **If $K$ does not exist:**
        *   Interpolate the vertex position $V_{pos}$ on the edge between $n_a$ and $n_b$ using linear interpolation based on $S(n_a)$, $S(n_b)$, and $C$.
        *   Register $V_{pos}$ in $H$ with key $K$.
7.  **Generate Triangles:** Use the standard Marching Cubes lookup table to determine the topology of the isosurface within the cell. Generate the triangles using the vertex positions retrieved or created in Step 6.
8.  **Stream Next Slice:** Advance the streaming buffer to load the next slice of the volume data, discarding the oldest slice to maintain constant memory usage [S2].
9.  **Repeat:** Continue until all cells are processed.

**Pseudocode:**
```python
def streaming_marching_cubes_with_hash_sharing(volume, isovalue, dimensions):
    """
    volume: 3D array of scalar values
    isovalue: float C
    dimensions: tuple (Nx, Ny, Nz)
    """
    H = {}  # Hash table: key=(node1_idx, node2_idx), value=(x, y, z)
    triangles = []
    
    # Helper to get or create vertex on edge
    def get_vertex_on_edge(node_idx1, node_idx2, node_val1, node_val2):
        key = (node_idx1, node_idx2)
        if key in H:
            return H[key]
        
        # Linear interpolation
        # t = (isovalue - node_val1) / (node_val2 - node_val1)
        # vertex = node_pos1 + t * (node_pos2 - node_pos1)
        # Note: Exact interpolation formula depends on coordinate system
        # [G] Assuming standard linear interpolation for isosurface
        t = (isovalue - node_val1) / (node_val2 - node_val1)
        pos1 = get_node_position(node_idx1, dimensions)
        pos2 = get_node_position(node_idx2, dimensions)
        vertex = pos1 + t * (pos2 - pos1)
        
        H[key] = vertex
        return vertex

    # Streaming loop: iterate over z-slices
    for z in range(dimensions[2] - 1):
        # Load current and next slice into memory
        slice_current = volume[:, :, z]
        slice_next = volume[:, :, z+1]
        
        # Iterate over x and y for the current slab of cells
        for y in range(dimensions[1] - 1):
            for x in range(dimensions[0] - 1):
                # Get 8 nodes of the current cell
                nodes = [
                    (x, y, z), (x+1, y, z), (x+1, y+1, z), (x, y+1, z),
                    (x, y, z+1), (x+1, y, z+1), (x+1, y+1, z+1), (x, y+1, z+1)
                ]
                values = [
                    slice_current[y, x], slice_current[y, x+1], slice_current[y+1, x+1], slice_current[y+1, x],
                    slice_next[y, x], slice_next[y, x+1], slice_next[y+1, x+1], slice_next[y+1, x]
                ]
                
                # Determine signs
                signs = [1 if v > isovalue else -1 for v in values]
                
                # Skip if no intersection
                if all(s == signs[0] for s in signs):
                    continue
                
                # Identify intersecting edges and get vertices
                # Standard MC edge indices for a cube:
                # 0:(0,1), 1:(1,2), 2:(2,3), 3:(3,0), 4:(4,5), 5:(5,6), 6:(6,7), 7:(7,4)
                # 8:(0,4), 9:(1,5), 10:(2,6), 11:(3,7)
                edges = [
                    (0, 1), (1, 2), (2, 3), (3, 0),
                    (4, 5), (5, 6), (6, 7), (7, 4),
                    (0, 4), (1, 5), (2, 6), (3, 7)
                ]
                
                edge_vertices = []
                for e_idx1, e_idx2 in edges:
                    if signs[e_idx1] != signs[e_idx2]:
                        v = get_vertex_on_edge(nodes[e_idx1], nodes[e_idx2], values[e_idx1], values[e_idx2])
                        edge_vertices.append(v)
                    else:
                        edge_vertices.append(None)
                
                # Generate triangles based on MC case
                case_index = sum(1 << i for i, s in enumerate(signs) if s == 1)
                # [G] Standard MC triangle configuration table lookup
                # This part depends on the specific MC implementation variant
                # For brevity, assuming a function that returns triangle indices into edge_vertices
                tri_indices = get_mc_triangles(case_index)
                
                for tri in tri_indices:
                    v1 = edge_vertices[tri[0]]
                    v2 = edge_vertices[tri[1]]
                    v3 = edge_vertices[tri[2]]
                    if v1 and v2 and v3:
                        triangles.append((v1, v2, v3))
                        
    return triangles
```

**Parameters:**
*   **Isovalue ($C$):** The scalar threshold for surface extraction. Typical values depend on the data range.
*   **Hash Table Size:** Not given in the sources. [G] Should be sized to accommodate the number of unique cell edges intersecting the isosurface.

**Edge Cases and Pitfalls:**
*   **Memory Limitations:** Cell-edge data is not usually preserved in volume data structures due to limited memory space, necessitating this explicit identification process [S1, unofficial].
*   **Precision:** Linear interpolation assumes the scalar field is well-behaved between nodes.
*   **Degenerate Input:** If $S(n_a) = S(n_b) = C$, the sign is zero. The sources define sign as equal or not equal. [G] Standard practice is to treat zero as positive or negative consistently to avoid ambiguity.

## Subtopics

### Marching Slices with Slab-based Caching
Processes data in slabs and caches vertex data to reduce hash table lookups. Choose when cache locality is more critical than minimal memory footprint. [9753-marching-slices-with-slab-based-caching.md]

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of cells, with a constant factor dependent on hash table operations.
*   **Memory Complexity:** $O(E)$ where $E$ is the number of unique cell edges intersecting the isosurface, plus $O(S)$ for the streaming buffer where $S$ is the size of two slices. This is significantly lower than storing the entire volume or all cell-edge data.
*   **Measured Performance:** Allows processing of extremely large datasets that would not fit in memory [S2].
*   **Strengths:** Minimal memory usage, guaranteed vertex sharing for clean mesh topology.
*   **Limitations:** Hash table overhead; potential cache misses if the hash table is large.
*   **When to Use:** Large volumetric datasets where memory is constrained and mesh quality (shared vertices) is important.
*   **When Not to Use:** Small datasets where memory is not a constraint, or when real-time performance is critical and hash table overhead is prohibitive.

## Background
The concept of vertex identification using a hash table was described in the context of patient-specific geometric modeling and isosurface propagation algorithms [S1, unofficial]. The streaming aspect of Marching Cubes, allowing processing of extremely large datasets by keeping only two slices in memory, was originally developed and patented by GE Medical Systems for use in their CT and MRI equipment [S2]. The patent has expired, placing the algorithm in the public domain [S2].
