# Marching Cubes Job Scheduling

Also called: Unity ECS Marching Cubes Job, Voxel Terrain Chunk Meshing Job

## Overview
Marching Cubes Job Scheduling is a parallel processing pattern that offloads the voxel-to-mesh conversion of a 3D volume chunk to a background worker thread or job system, decoupling mesh generation from the main application loop [S1, unofficial]. It solves the problem of frame-rate stutters caused by synchronous CPU-based surface extraction in real-time applications, such as voxel terrain rendering [S1, unofficial]. Unlike immediate-mode approaches that block the caller, this method schedules independent jobs per chunk, allowing the main thread to continue processing while geometry is generated asynchronously [S1, unofficial]. It differs from GPU-based histogram pyramids by performing the extraction on the CPU using multi-threading, and from capacity-safe pipelines by relying on dynamic allocation via atomic counters rather than pre-allocated slab buffers [S1, 4595-capacity-safe-slab-based-marching-cubes.md, unofficial].

## How it works
The method processes a single spatial chunk of the voxel world. It reads the scalar field and color data, calculates the isosurface triangles using the standard Marching Cubes algorithm, and writes the results to a shared output buffer protected by an atomic counter.

**Inputs and Outputs:**
*   **Input:** A 3D chunk of voxel data defined by `VoxelDataVolume<byte>` (scalar field) and `VoxelDataVolume<Color32>` (color/alpha). The chunk dimensions are fixed, typically $N \times N \times N$ (e.g., 16x16x16 or 32x32x32) [S1, unofficial].
*   **Input:** `Isolevel` (float), the threshold for surface extraction. Default is 0.5 [S1, unofficial].
*   **Output:** `outputVertices` (`NativeArray<MeshingVertexData>`), storing vertex positions, normals, and colors.
*   **Output:** `outputTriangles` (`NativeArray<ushort>`), storing triangle indices.
*   **Synchronization:** `VertexCountCounter` (`NativeCounter`), an atomic integer tracking the number of vertices written to the output arrays.

**Data Structures:**
1.  **`MarchingCubesJob` Struct:** Holds the input references and output pointers.
    *   `VoxelData`: Reference to the byte array of voxel densities.
    *   `VoxelColors`: Reference to the color array.
    *   `Isolevel`: The threshold float.
    *   `VertexCountCounter`: Pointer to the atomic counter.
    *   `OutputVertices`: Pointer to the vertex array.
    *   `OutputTriangles`: Pointer to the triangle index array.
2.  **Output Arrays:**
    *   `outputVertices`: Size is calculated as `maxLength = 15 * voxelCount`. This upper bound assumes the worst-case scenario where every voxel generates the maximum 5 triangles (15 vertices) [S1, unofficial].
    *   `outputTriangles`: Size is identical to `outputVertices` (`maxLength`), storing indices as `ushort` [S1, unofficial].

**Algorithm Steps:**
1.  **Chunk Validation:** Retrieve the voxel data and color chunks for the specified `chunkCoordinate`. If either chunk is missing or invalid, return null/empty [S1, unofficial].
2.  **Buffer Allocation:**
    *   Calculate `voxelCount` = `ChunkSize.x * ChunkSize.y * ChunkSize.z` [S1, unofficial].
    *   Calculate `maxLength` = `15 * voxelCount` [S1, unofficial].
    *   Allocate `outputVertices` and `outputTriangles` with capacity `maxLength` using temporary memory allocators [S1, unofficial].
    *   Initialize `VertexCountCounter` to 0 [S1, unofficial].
3.  **Job Initialization:** Populate the `MarchingCubesJob` struct with the data references, `Isolevel`, the counter, and the output arrays [S1, unofficial].
4.  **Scheduling:** Submit the job to the job scheduler (e.g., Unity's `JobHandle`) [S1, unofficial].
5.  **Execution (Inside Job):**
    *   Iterate through every voxel $(x, y, z)$ in the chunk.
    *   Sample the 8 corner vertices of the voxel from `VoxelData`.
    *   Compute the 8-bit `caseIndex` based on `Isolevel` [G].
    *   Look up the `triangleTable` for the `caseIndex` [G].
    *   For each triangle defined in the table:
        *   Calculate the intersection points on the cube edges using linear interpolation [G].
        *   Assign a unique vertex ID by atomically incrementing `VertexCountCounter` and using the previous value as the index into `outputVertices` [G].
        *   Write the vertex data (position, normal, color) to `outputVertices[vertexID]` [G].
        *   Store the vertex IDs in `outputTriangles` [G].
6.  **Completion:** The job returns a handle. The main thread waits for this handle before accessing the mesh data to construct the final `Mesh` object [S1, unofficial].

**Pseudocode:**
```python
# Data Structures
struct MarchingCubesJob:
    VoxelData: NativeArray<byte>
    VoxelColors: NativeArray<Color32>
    Isolevel: float
    VertexCountCounter: NativeCounter
    OutputVertices: NativeArray<MeshingVertexData>
    OutputTriangles: NativeArray<ushort>

# Main Thread Logic
function CreateMesh(chunkCoordinate, chunkSize):
    # 1. Retrieve Data
    voxelData = GetVoxelDataChunk(chunkCoordinate)
    voxelColors = GetVoxelColorChunk(chunkCoordinate)
    if voxelData is null or voxelColors is null:
        return null

    # 2. Allocate Buffers
    voxelCount = chunkSize.x * chunkSize.y * chunkSize.z
    maxLength = 15 * voxelCount
    
    outputVertices = AllocateNativeArray<MeshingVertexData>(maxLength)
    outputTriangles = AllocateNativeArray<ushort>(maxLength)
    vertexCountCounter = AllocateNativeCounter()
    vertexCountCounter.value = 0

    # 3. Initialize Job
    job = MarchingCubesJob(
        VoxelData=voxelData,
        VoxelColors=voxelColors,
        Isolevel=0.5f,
        VertexCountCounter=vertexCountCounter,
        OutputVertices=outputVertices,
        OutputTriangles=outputTriangles
    )

    # 4. Schedule
    jobHandle = ScheduleJob(job)
    return JobHandleWithData(jobHandle, job)

# Job Execution Logic
function Execute(job: MarchingCubesJob):
    chunkSize = GetChunkSize()
    
    for x from 0 to chunkSize.x - 1:
        for y from 0 to chunkSize.y - 1:
            for z from 0 to chunkSize.z - 1:
                # Sample 8 corners
                corners = [
                    job.VoxelData[GetVoxelIndex(x, y, z)],
                    job.VoxelData[GetVoxelIndex(x+1, y, z)],
                    job.VoxelData[GetVoxelIndex(x+1, y+1, z)],
                    job.VoxelData[GetVoxelIndex(x, y+1, z)],
                    job.VoxelData[GetVoxelIndex(x, y, z+1)],
                    job.VoxelData[GetVoxelIndex(x+1, y, z+1)],
                    job.VoxelData[GetVoxelIndex(x+1, y+1, z+1)],
                    job.VoxelData[GetVoxelIndex(x, y+1, z+1)]
                ]
                
                # Calculate Case Index
                caseIndex = 0
                for i from 0 to 7:
                    if corners[i] > job.Isolevel:
                        caseIndex |= (1 << i)
                
                # Lookup Triangles
                triangles = triangleTable[caseIndex]
                
                for tri in triangles:
                    if tri == -1: break
                    
                    # Get Edge Indices for the triangle
                    e1 = tri[0]
                    e2 = tri[1]
                    e3 = tri[2]
                    
                    # Calculate Intersection Points
                    p1 = InterpolateEdge(corners, e1, job.Isolevel)
                    p2 = InterpolateEdge(corners, e2, job.Isolevel)
                    p3 = InterpolateEdge(corners, e3, job.Isolevel)
                    
                    # Get Colors
                    c1 = GetColorForEdge(e1, job.VoxelColors, corners)
                    c2 = GetColorForEdge(e2, job.VoxelColors, corners)
                    c3 = GetColorForEdge(e3, job.VoxelColors, corners)
                    
                    # Write Vertices
                    v1_idx = job.VertexCountCounter.Increment()
                    v2_idx = job.VertexCountCounter.Increment()
                    v3_idx = job.VertexCountCounter.Increment()
                    
                    job.OutputVertices[v1_idx] = MeshingVertexData(p1, c1)
                    job.OutputVertices[v2_idx] = MeshingVertexData(p2, c2)
                    job.OutputVertices[v3_idx] = MeshingVertexData(p3, c3)
                    
                    # Write Indices
                    job.OutputTriangles[v1_idx] = v1_idx
                    job.OutputTriangles[v2_idx] = v2_idx
                    job.OutputTriangles[v3_idx] = v3_idx

function InterpolateEdge(corners, edgeIndex, isolevel):
    # Map edge index to vertex indices
    v0_idx, v1_idx = EdgeVertices[edgeIndex]
    v0 = corners[v0_idx]
    v1 = corners[v1_idx]
    
    # Linear interpolation
    t = (isolevel - v0) / (v1 - v0)
    return lerp(GetVertexPosition(v0_idx), GetVertexPosition(v1_idx), t)
```

**Parameters:**
*   `Isolevel`: Default 0.5 [S1, unofficial]. Range [0, 1] [S1, unofficial].
*   `ChunkSize`: Defined by `WorldSettings.ChunkSize` [S1, unofficial]. Typical values are powers of 2 (e.g., 16, 32) [G].

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** The output arrays are sized to `15 * voxelCount`. If the scene contains complex topology exceeding this theoretical maximum (unlikely for standard Marching Cubes but possible with modified algorithms), indices will wrap or corrupt memory [S1, unofficial].
*   **Atomic Contention:** High thread counts may contend on `VertexCountCounter`. While atomic operations are fast, extreme parallelism can cause cache-line bouncing [G].
*   **Boundary Conditions:** The job assumes the voxel data is padded or that the chunk boundaries are handled correctly to avoid sampling out-of-bounds memory [G].

## Subtopics

### Multi-Process Ground Truth Generation
A variant used for generating training data for neural networks rather than real-time rendering. It orchestrates parallel processing of 3D models (OBJ files) using multiple worker processes and a synchronization queue [S2, unofficial]. It distributes object names across processes based on `idx % num_of_process`, extracts ground truth masks by checking point cloud intersections within grid blocks, and aggregates results via a queue with timeout-based exit checks [S2, unofficial]. It is chosen when generating large-scale labeled datasets for geometry learning, not for interactive meshing.

### Tandem Algorithm with Dumping
A strategy for handling very large datasets (e.g., seismic cubes) by combining the tandem algorithm with a "dumping" mechanism to reduce triangle count and manage disconnected components [S3]. It filters small components based on geometric criteria (volume), reducing 18,111 components to 328 in a 1626x7028x2000 dataset [S3]. It is chosen for interactive exploration of massive volumes where memory and performance are critical, achieving 5 minutes extraction time on 56 processors compared to 3 hours sequentially [S3].

## Operating characteristics
*   **Time Complexity:** $O(V)$ where $V$ is the number of voxels in the chunk. The complexity is linear with respect to the chunk size.
*   **Memory Complexity:** $O(V)$ for the output buffers. The allocation is fixed at `15 * V` vertices and indices [S1, unofficial].
*   **Performance:** Depends heavily on the job scheduler's efficiency and CPU core count. In Unity's Job System, it allows the main thread to remain responsive [S1, unofficial].
*   **Strengths:** Simple implementation, no GPU dependency, easy to integrate with existing CPU-based voxel pipelines, deterministic output [S1, unofficial].
*   **Limitations:** Fixed buffer size can lead to wasted memory if the mesh is sparse; atomic counters can become a bottleneck at very high thread counts; not suitable for extremely large single-chunk volumes without tiling [G].
*   **When to use:** Real-time voxel terrain generation on CPU-bound platforms or when GPU compute shaders are unavailable.
*   **When not to use:** Extremely large static volumes where GPU-based extraction (e.g., [GPU Marching Cubes (Compute Shader)](4687-gpu-marching-cubes-compute-shader.md)) is preferred for throughput.

## Background
The method is derived from the standard Marching Cubes algorithm [10327-lookup-table-and-ambiguity-handling.md] and adapted for modern multi-threaded environments. The specific implementation details (Unity ECS, `NativeArray`, `JobHandle`) are popularized by open-source voxel terrain projects such as Eldemarkki's Marching Cubes Terrain [S1, unofficial]. The concept of job scheduling for mesh generation is a general software engineering pattern applied to graphics, allowing for asynchronous processing.
