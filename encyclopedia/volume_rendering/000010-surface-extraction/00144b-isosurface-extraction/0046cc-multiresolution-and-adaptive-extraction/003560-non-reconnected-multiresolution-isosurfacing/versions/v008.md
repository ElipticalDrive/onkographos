# Non-reconnected Multiresolution Isosurfacing

Also called: Crack Suppression via Polygon Density, deliberate crack omission, non-reconnected multiresolution cells

## Overview
Non-reconnected Multiresolution Isosurfacing is a surface extraction technique that intentionally omits geometric reconnection between adjacent cells of different resolutions to maintain interactive frame rates during dynamic Level of Detail (LOD) selection [S1]. It solves the problem of computational overhead in tracking neighbors and reconnecting surface elements in unconstrained hierarchies, relying on sufficient polygon density to keep resulting cracks visually negligible [S1]. Unlike sibling methods that enforce mesh coherence through explicit reconnection or oracle-based constraints, this method accepts visible gaps as a trade-off for speed, particularly in dynamic sculpting contexts where the surface is constantly changing [S1].

## How it works
The method operates on a discretized domain (typically a regular grid or octree) where each cell contains scalar values [G]. The core principle is the independent rendering of surface elements per cell without enforcing connectivity constraints between adjacent cells of different resolutions [S1].

**Inputs and Outputs:**
*   **Input:** A hierarchical scalar field (e.g., octree or grid hierarchy) and a dynamic stopping level selection criterion per frame [S1].
*   **Output:** A set of independent surface polygons (triangles or quads) rendered per cell; no unified mesh connectivity is generated [S1].

**Data Structures:**
*   **Cell Hierarchy:** A tree structure where nodes represent cells at various resolution levels [S1].
*   **Surface Elements:** For each active cell, a list of polygons intersecting the isosurface [S1]. The exact layout depends on the base isosurfacing algorithm (e.g., Marching Cubes) but is treated as an opaque list of vertices and indices for rendering [G].

**Steps:**
1.  **Dynamic LOD Selection:** At each frame, determine the stopping level in the cell hierarchy for display [S1]. This selection is dynamic and does not enforce connectivity constraints between adjacent cells [S1].
2.  **Independent Surface Extraction:** For each active cell at the selected level, extract the isosurface elements independently [S1]. Do not query or track neighboring cells for connectivity purposes [S1].
3.  **Render Independent Elements:** Render the surface elements found at each cell [S1]. No reconnection of surface elements between adjacent cells is performed [S1].
4.  **Visual Verification:** Rely on the density of polygons to ensure cracks remain "hardly visible" [S1]. If the polygon count is low, cracks may be visible; drawing more triangles does not solve the fundamental issue of field resolution mismatches [S1].

**Formulas:**
Not given in the sources.

**Parameters:**
*   **sufficient_polygon_threshold:** An implicit threshold where polygon density makes cracks visually negligible [S1]. This justifies the omission of reconnection [S1]. The exact numerical value is not specified in the sources [S1].

**Pitfalls and Edge Cases:**
*   **Cracks:** Visible gaps may appear due to field resolution mismatches between adjacent cells [S1]. This is a fundamental issue of the method, not a bug [S1].
*   **Distant Neighbors:** In an unconstrained hierarchy, adjacent cells may be distant by more than one resolution level [S1]. This makes neighbor tracking computationally expensive and slows display rates [S1].
*   **Dynamic Surface:** The method is designed for scenarios where the surface is always changing (e.g., sculpting), making reconnection efforts potentially wasteful [S1].
*   **Export Limitations:** The output is not a standard mesh with connectivity [S1]. If a standard mesh is required for export, a global offline reconnection process must be performed separately [S1].

def render_non_reconnected_isosurface(hierarchy, isovalue, frame_time):
    """
    Renders the isosurface by processing each cell independently.
    No connectivity is enforced between adjacent cells.
    """
    # 1. Dynamic LOD Selection
    # Sources do not specify the exact dynamic selection algorithm [S1].
    # We traverse the hierarchy and select cells meeting a per-frame budget.
    active_cells = []
    for cell in traverse_tree(hierarchy):
        if cell.meets_frame_budget(frame_time):
            active_cells.append(cell)

    all_polygons = []
    # 2. Independent Surface Extraction
    for cell in active_cells:
        # Check intersection using cell scalar bounds
        cell_min = min(cell.vertex_scalars)
        cell_max = max(cell.vertex_scalars)
        if cell_min <= isovalue <= cell_max:
            # Extract polygons independently; no neighbor tracking [S1]
            polygons = extract_isosurface_for_cell(cell, isovalue)
            all_polygons.extend(polygons)

    # 3. Render Independent Elements
    # Sources state cracks may be visible if polygon density is low [S1].
    for poly in all_polygons:
        # Fix for vec3 unpacking error: skip polygons with invalid vertex counts
        if len(poly.vertices) == 3:
            draw_triangle(poly.vertices[0], poly.vertices[1], poly.vertices[2])

def traverse_tree(node):
    """Standard recursive traversal of a tree or octree [G]."""
    yield node
    for child in node.children:
        yield from traverse_tree(child)

## Operating characteristics
*   **Time Complexity:** Lower than reconnection-based methods because it avoids neighbor tracking and surface reconnection overhead [S1]. The cost is dominated by independent surface extraction per cell [S1].
*   **Memory Complexity:** Lower memory overhead for mesh connectivity structures, as no global connectivity graph is maintained [S1].
*   **Measured Performance:** Applied in a resolution adaptive volume sculpting system to maintain interactive rates during dynamic LOD selection [S1]. Specific frame rates or hardware metrics are not provided in the sources [S1].
*   **Strengths:** High performance in dynamic environments; avoids the computational cost of neighbor tracking; suitable for unconstrained hierarchies where neighbors may be distant [S1].
*   **Limitations:** Visual cracks may appear, especially at low polygon densities; not suitable for applications requiring a watertight or connected mesh without post-processing; cracks are a fundamental issue of field resolution mismatches, not solvable by simply adding more triangles [S1].
*   **When to Use:** Interactive sculpting or visualization where frame rate is critical and the surface is constantly changing [S1].
*   **When Not to Use:** Applications requiring a standard, connected mesh output without offline reconnection; static scenes where visual perfection is prioritized over speed [S1].

## Background
The method was introduced in the context of "Resolution Adaptive Volume Sculpting" by Eric Ferley, Marie-Paule Cani, and Jean-François Dufour [S1]. It was developed to address the need for interactive performance in dynamic sculpting systems where users manipulate scalar fields in real-time [S1]. The approach contrasts with other multiresolution isosurface constructions that pay attention to cracks and enforce connectivity [S1]. The system was demonstrated with examples sculpted using a 2D-mouse with a "virtual trackball" metaphor, and additional material was available at the INRIA Imagis lab website [S1].
