# Non-reconnected Multiresolution Isosurfacing

Also called: Crack Suppression via Polygon Density, deliberate crack omission, non-reconnected multiresolution cells

## Overview
Non-reconnected Multiresolution Isosurfacing is a surface extraction technique for multiresolution grids that intentionally omits geometric reconnection between adjacent cells of differing resolutions [S1]. It solves the problem of maintaining interactive frame rates during dynamic Level-of-Detail (LOD) selection by trading visual perfection for performance, relying on sufficient polygon density to render cracks visually negligible [S1]. It sets itself apart from sibling methods like [Adaptive Minimum Projected Size Adjustment](7457-adaptive-minimum-projected-size-adjustment.md) and [Adaptive Multiresolution Extraction with Oracle](11830-adaptive-multiresolution-extraction-with-oracle.md) by rejecting the computational overhead of neighbor tracking and surface reconnection, which are typically required to ensure mesh continuity [S1].

## How it works
The method operates on a discretized domain (typically a regular grid or octree) where each cell contains scalar values [G]. Unlike connected multiresolution algorithms, this method treats surface elements as independent entities per cell.

**Inputs:**
- Scalar field data organized in a cell hierarchy (e.g., octree levels).
- A dynamic stopping level threshold per frame, determined by performance constraints or user interaction [S1].

**Outputs:**
- A set of independent surface polygons (triangles or quads) generated per cell.
- No explicit connectivity information (edges/vertices shared between cells) is computed or stored [S1].

**Data Structures:**
- **Cell Hierarchy:** A tree structure where nodes represent cells at various resolution levels.
- **Surface Elements:** A list of geometric primitives (e.g., triangles) generated by marching cubes or similar cell-local algorithms. Each element is defined by its vertex coordinates and normal, but lacks explicit neighbor references [S1].

**Steps:**
1. **Dynamic LOD Selection:** For each frame, determine the maximum resolution level to display for each cell based on current performance metrics or user input [S1]. This selection is unconstrained; adjacent cells may differ by more than one resolution level [S1].
2. **Independent Surface Generation:** For each selected cell, generate the isosurface geometry using a standard cell-local algorithm (e.g., Marching Cubes) [S1].
3. **Omission of Reconnection:** Do not attempt to match vertices or edges between adjacent cells of different resolutions. Do not track neighbors to resolve gaps [S1].
4. **Rendering:** Render the generated surface elements independently. If the polygon count is sufficiently high, cracks between cells are visually negligible [S1].

**Parameters:**
- **sufficient_polygon_threshold:** An implicit threshold where the density of polygons makes cracks "hardly visible" [S1]. This is not a fixed numerical value but a perceptual outcome of high-resolution sampling [S1].

**Edge Cases and Pitfalls:**
- **Distant Resolution Levels:** Adjacent cells may be distant by more than one resolution level in an unconstrained hierarchy. This makes neighbor tracking computationally expensive and is the primary reason reconnection is omitted [S1].
- **Field Resolution Mismatches:** Cracks may appear if the scalar field is not defined at the same resolution in adjacent cells. Drawing more triangles does not solve this fundamental issue [S1].
- **Dynamic Sculpting:** Since the surface is constantly changing during interactive sculpting, static reconnection strategies are ineffective [S1].

**Pseudocode:**
```python
def render_non_reconnected_isosurface(cell_hierarchy, stopping_levels):
    """
    Renders isosurfaces without reconnecting adjacent cells.
    
    Args:
        cell_hierarchy: A tree of cells, each containing scalar values.
        stopping_levels: A map from cell_id to the maximum resolution level to display.
        
    Returns:
        A list of independent surface polygons (triangles).
    """
    all_polygons = []
    
    for cell in cell_hierarchy:
        # Determine the active resolution level for this cell
        max_level = stopping_levels.get(cell.id, cell.max_level)
        
        # Generate surface geometry for this cell at the selected level
        # This uses a standard cell-local algorithm (e.g., Marching Cubes)
        # [G] Assumes a function that returns a list of triangles given a cell and resolution
        polygons = generate_cell_surface(cell, max_level)
        
        # Add polygons to the global list without any connectivity processing
        all_polygons.extend(polygons)
        
    return all_polygons

def generate_cell_surface(cell, level):
    """
    Generates surface polygons for a single cell at a specific resolution level.
    [G] Implementation details depend on the specific cell-local algorithm used.
    """
    # Extract scalar values at vertices for the given level
    values = cell.get_scalar_values_at_level(level)
    
    # Apply Marching Cubes or similar algorithm
    # Returns a list of triangles
    triangles = marching_cubes(values, cell.geometry)
    
    return triangles
```

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of active cells, as each cell is processed independently without neighbor lookups or global connectivity checks [S1].
- **Memory Complexity:** $O(N)$ for storing the independent surface polygons, with no additional overhead for connectivity graphs or neighbor maps [S1].
- **Measured Performance:** Enables interactive frame rates during dynamic LOD selection in resolution adaptive volume sculpting systems [S1].
- **Strengths:** Avoids the computational cost of neighbor tracking and surface reconnection; maintains high display rates even in unconstrained hierarchies [S1].
- **Limitations:** Visible cracks may appear between cells of different resolutions; not suitable for applications requiring watertight meshes or precise geometric continuity [S1].
- **When to Use:** Interactive visualization and sculpting where frame rate is critical and minor visual artifacts are acceptable [S1].
- **When Not to Use:** Applications requiring exportable, watertight meshes or high-fidelity static rendering where cracks are unacceptable [S1].

## Background
The method was introduced in the context of resolution adaptive volume sculpting by Eric Ferley, Marie-Paule Cani, and Jean-François Dufour in 2001 [S1]. It was designed to support interactive sculpting with a "virtual trackball" metaphor, allowing users to dynamically adjust resolution levels without being hindered by the computational cost of maintaining mesh connectivity [S1]. The approach contrasts with traditional multiresolution isosurfacing methods that prioritize geometric correctness over interactive performance [S1].
