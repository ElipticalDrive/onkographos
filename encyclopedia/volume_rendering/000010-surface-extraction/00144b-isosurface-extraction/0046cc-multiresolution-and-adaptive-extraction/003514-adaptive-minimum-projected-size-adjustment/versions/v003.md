# Adaptive Minimum Projected Size Adjustment

Also called: adaptive LOD control, framerate-driven projected size scaling

## Overview
Adaptive Minimum Projected Size Adjustment is a dynamic level-of-detail (LOD) control mechanism for isosurface extraction that automatically adjusts the minimum projected size of surface elements frame-to-frame to maintain a target framerate during user interaction [S1]. Unlike fixed minimum projected size approaches, which cause surface complexity to scale directly with camera distance and can result in poorly or over-populated geometry, this method balances detail and performance based on actual frame timing [S1]. It ensures that the displayed surface remains refined during idle moments while preventing excessive geometry generation during active interaction [S1].

## How it works
The method operates by modulating the minimum projected size threshold used during the surface extraction process. It does not recompute the geometry every frame but rather adjusts the criteria for which geometric primitives are generated or retained based on the rendering performance of the previous frame [S1].

**Inputs and Outputs**
*   **Input:** The measured elapsed time of the previous frame ($t_{measured}$), the desired display time ($t_{target}$), and the current minimum projected size ($s_{current}$).
*   **Output:** The updated minimum projected size ($s_{next}$) for the subsequent frame.

**Data Structures**
No specific complex data structures are required beyond the scalar variables for timing and size. The method assumes the underlying isosurface extraction algorithm (e.g., from [30-isosurface-extraction.md]) accepts a minimum projected size parameter.

**Parameters**
*   $t_{target}$: The desired frame duration (in seconds or milliseconds) used as the baseline for time-difference calculation. Typical value: Not given in the sources.
*   $\alpha$: The exponent applied to the time difference to modulate adjustment sensitivity. Value: 3 [S1].

**Algorithm Steps**
1.  **Measure Frame Time:** At the end of each frame, measure the elapsed time since the previous frame end, denoted as $t_{measured}$ [S1].
2.  **Calculate Time Difference:** Compute the difference between the measured frame time and the desired display time:
    $$ \Delta t = t_{measured} - t_{target} $$
3.  **Compute Weighted Factor:** Raise the time difference to the third power to compute the weighted growing factor, preserving the sign of the difference:
    $$ \Delta s = (\Delta t)^3 $$
    This cubic weighting minimizes the influence of the adjustment when the display time is near the goal and emphasizes it when it is far, preventing oscillation and ensuring smooth convergence [S1].
4.  **Update Minimum Projected Size:** Update the minimum projected size using the computed weighted factor. The exact update rule depends on whether the system is in interaction or idle mode:
    *   **During Interaction:** The size is adjusted based on $\Delta s$. If the frame took too long ($\Delta t > 0$), the minimum projected size increases (coarsening the mesh). If the frame was faster than desired ($\Delta t < 0$), the size decreases (refining the mesh) [S1].
    *   **During Idle:** When the user is idle, the limit projected size is progressively reduced toward zero to allow fully detailed geometry rendering over time [S1].
5.  **Apply to Extraction:** Use the updated $s_{next}$ as the minimum projected size threshold for the next frame's surface extraction pass [S1].

**Pseudocode**
```python
def update_minimum_projected_size(t_measured, t_target, s_current, is_idle):
    """
    Updates the minimum projected size for the next frame based on frame timing.
    
    Args:
        t_measured: Time taken to render the previous frame.
        t_target: Desired frame duration.
        s_current: Current minimum projected size.
        is_idle: Boolean flag indicating if the user is idle.
        
    Returns:
        s_next: The new minimum projected size.
    """
    # Step 1 & 2: Calculate time difference
    delta_t = t_measured - t_target
    
    # Step 3: Compute weighted factor using cubic exponent
    # Preserving sign: if delta_t is negative, delta_s is negative
    delta_s = delta_t ** 3
    
    # Step 4: Update size
    if is_idle:
        # During idle, progressively reduce size toward zero for full detail
        # [G] Linear interpolation towards zero is a standard approach for decay
        # when specific decay rate is not given.
        s_next = s_current * 0.9  # [G] Decay factor; exact rate not specified in sources
        if s_next < 1e-6:
            s_next = 0.0
    else:
        # During interaction, adjust based on frame time deviation
        # [G] The source states "update... using the computed weighted growing factor"
        # but does not specify the exact additive/multiplicative formula.
        # A common implementation for such adaptive controls is additive adjustment.
        s_next = s_current + delta_s
        
        # Guard against negative size
        if s_next < 0:
            s_next = 0.0
            
    return s_next
```

**Edge Cases and Pitfalls**
*   **Oscillation:** If the exponent were linear, small fluctuations in frame time could cause jittering in mesh density. The cubic exponent ($\alpha=3$) mitigates this by dampening small differences and amplifying large ones [S1].
*   **Idle Detection:** The transition between interaction and idle modes must be robust. If the system incorrectly identifies interaction as idle, the mesh may become overly dense and cause performance drops. If it fails to detect idle, the mesh may remain coarsely sampled even when the user stops interacting [S1].
*   **Boundary Conditions:** The minimum projected size must be clamped to a non-negative value. Negative sizes are invalid [G].

## Operating characteristics
*   **Time Complexity:** The adjustment logic itself is $O(1)$, involving basic arithmetic operations. The overall performance impact depends on the underlying isosurface extraction algorithm, which is typically $O(N)$ where $N$ is the number of voxels or cells [S1].
*   **Memory Complexity:** No additional memory overhead is required for the adjustment logic itself. The memory usage is determined by the resulting mesh size, which varies dynamically [S1].
*   **Strengths:**
    *   Maintains a consistent framerate during user interaction [S1].
    *   Allows for high-fidelity rendering during idle periods [S1].
    *   Adapts to varying camera distances without manual tuning [S1].
*   **Limitations:**
    *   Does not address cracks between adjacent cells of different sizes. The authors explicitly chose not to reconnect surface elements, accepting that field resolution differences may cause visual artifacts [S1].
    *   Performance is dependent on the accuracy of frame time measurement and the responsiveness of the user interaction detection [S1].
*   **When to Use:** Ideal for interactive volume sculpting and visualization systems where user interaction speed and visual fidelity need to be balanced [S1].
*   **When Not to Use:** Not suitable for applications requiring strict, predictable memory budgets or where crack-free meshes are mandatory without post-processing [S1].

## Background
The method was introduced by Eric Ferley, Marie-Paule Cani, and Jean-Dominique Gascuel in their 2001 paper "Resolution Adaptive Volume Sculpting" [S1]. It was developed as part of a system for interactive volume sculpting, addressing the limitations of fixed minimum projected size controls which failed to provide sufficient refinement during idle moments and caused poor or over-populated geometry during zooming [S1]. The approach is integrated into their resolution adaptive volume sculpting system [S1].
