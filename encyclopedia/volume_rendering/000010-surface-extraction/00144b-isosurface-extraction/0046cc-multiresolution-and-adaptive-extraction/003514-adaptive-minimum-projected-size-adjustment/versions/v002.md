# Adaptive Minimum Projected Size Adjustment

Also called: adaptive LOD control, framerate-driven projected size scaling

## Overview
Adaptive Minimum Projected Size Adjustment is a dynamic control mechanism for isosurface extraction that automatically adjusts the minimum projected size of surface elements frame-to-frame to maintain a target framerate during user interaction [S1]. Unlike fixed minimum projected size approaches that cause surface complexity to scale directly with camera distance, this method balances detail and performance based on actual frame timing, preventing poor or over-populated geometry at varying camera distances [S1].

## How it works
**Inputs and Outputs**
*   **Input:** The measured elapsed time since the previous frame end ($t_{measured}$), the desired display time ($t_{target}$), and the current minimum projected size ($s_{current}$).
*   **Output:** The updated minimum projected size ($s_{next}$) for the subsequent frame.

**Data Structures**
No specific complex data structures are required beyond scalar variables for timing and size. The method operates on the scalar parameter controlling the LOD threshold.

**Parameters**
*   $t_{target}$: Target frame duration used as the baseline for time-difference calculation to maintain interaction framerate. Value: Not given in the sources.
*   $\alpha$: The third power exponent applied to the time difference to modulate adjustment sensitivity. Value: 3 [S1].

**Steps**
1.  Measure the elapsed time since the previous frame end, denoted as $t_{measured}$ [S1].
2.  Calculate the difference between the measured frame time and the desired display time: $\Delta t = t_{measured} - t_{target}$ [S1].
3.  Compute a weighted growing factor $f$ by raising the time difference to the third power, preserving the sign of the difference: $f = \text{sign}(\Delta t) \cdot |\Delta t|^3$ [S1].
    *   Note: The cubic weighting emphasizes the adjustment if the display time deviates significantly from the goal, and minimizes influence when close, preventing oscillation and ensuring smooth convergence [S1].
4.  Update the minimum projected size using the computed weighted growing factor. The exact additive or multiplicative update rule is not specified in the sources, but the factor $f$ drives the adjustment [S1]. [G] A standard implementation would be $s_{next} = s_{current} + f$, assuming $f$ is scaled appropriately to the size domain.
5.  When the user is idle (no interaction), progressively reduce the limit projected size toward zero to allow fully detailed geometry rendering over time [S1].

**Pseudocode**
```python
def update_minimum_projected_size(current_size, measured_time, target_time, is_user_idle):
    """
    Updates the minimum projected size based on frame timing.
    
    Args:
        current_size (float): The minimum projected size from the previous frame.
        measured_time (float): Time elapsed since the previous frame end.
        target_time (float): Desired display time (target frame duration).
        is_user_idle (bool): True if the user is not interacting.
        
    Returns:
        float: The new minimum projected size.
    """
    if is_user_idle:
        # When the user is idle, progressively reduce the limit projected size toward zero
        # to allow fully detailed geometry rendering over time [S1].
        # [G] Linear decay or exponential decay towards 0 is implied.
        # A simple decay factor is used here as the exact function is not specified.
        decay_factor = 0.95 
        return max(0.0, current_size * decay_factor)
    
    # Calculate the difference between the measured frame time and the desired display time [S1]
    time_diff = measured_time - target_time
    
    # Raise the time difference to the third power to compute a weighted growing factor,
    # preserving the sign of the difference [S1]
    # The cubic weighting emphasizes the adjustment if the display time deviates significantly
    # from the goal, and minimizes influence when it's near its goal [S1]
    weighted_factor = (time_diff ** 3)
    
    # Update the minimum projected size using the computed weighted growing factor [S1]
    # [G] The exact scaling of weighted_factor to size units is not specified in the source.
    # Assuming a direct additive update with a scaling constant k for stability,
    # though the source implies a direct relationship.
    # A common practical implementation would involve a scaling constant.
    # Since the source says "use the difference ... to weight the growing factor",
    # and "update ... using the computed weighted growing factor", we apply it directly.
    # To prevent instability, a clamp or scaling might be needed, but we stick to the source description.
    new_size = current_size + weighted_factor
    
    # Ensure size remains non-negative
    return max(0.0, new_size)
```

**Edge Cases and Pitfalls**
*   **Oscillation:** If the display time deviates significantly from the goal, the cubic weighting emphasizes the adjustment. If close, it minimizes influence, preventing oscillation and ensuring smooth convergence [S1].
*   **Idle State:** If the user is idle, the limit projected size is progressively reduced close to zero, allowing fully detailed geometry to be rendered if the user waits sufficiently long [S1].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per frame for the adjustment calculation.
*   **Memory Complexity:** $O(1)$ additional memory for storing the current size and timing variables.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** The method adapts to varying camera distances and user interaction speeds by dynamically adjusting the LOD threshold.
*   **Strengths:** Maintains a target framerate during interaction; prevents over-populated or poorly populated geometry; allows high detail during idle periods.
*   **Limitations:** Does not address cracks between adjacent cells of different sizes; requires careful tuning of the target frame time and scaling of the adjustment factor (not provided in sources).
*   **When to use:** Interactive volume sculpting systems where framerate stability is critical during user manipulation.
*   **When not to use:** Non-interactive rendering where fixed LOD or other adaptive strategies might be more appropriate; scenes where crack-free connectivity between different resolution levels is mandatory without reconnection.

## Background
**Origin**
The method was introduced by Eric Ferley, Marie-Paule Cani, and Jean-Dominique Gascuel in their paper "Resolution Adaptive Volume Sculpting" [S1].

**History and Development**
The method is part of a resolution adaptive volume sculpting system designed for interactive modeling. It addresses the insufficiency of fixed control mechanisms, which fail to refine the surface during idle moments and result in poorly or over-populated models when the user zooms in or out [S1]. The authors deliberately chose not to reconnect surface elements found at each cell to solve cracks between adjacent cells of different sizes, as this would not be a solution if the field is not defined at the same resolution in adjacent cells [S1].

**Usage**
Integrated into the resolution adaptive volume sculpting system for interactive LOD control during user interaction [S1]. Examples include character model creation from scratch, where wireframe views illustrate display complexity control [S1].
