# Cluster Connection Tree Table

Also called: Cluster linkage table, Tree table

## Overview
The Cluster Connection Tree Table is a data structure used in convex contouring to summarize the topological connections between clusters of isosurface points across adjacent slices [S1]. It serves as the bridge between 2D slice processing and 3D surface construction by explicitly tracking which clusters in slice $i$ connect to clusters in slice $i+1$ [S1]. Unlike methods that infer connectivity implicitly, this table stores explicit bidirectional links (Head and Tail IDs) and a correlation metric to enable the construction of topologically consistent surfaces with local convexity properties [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A sequence of 2D slices containing clusters of isosurface points, where each cluster is defined by a set of points $\tilde{t}$ and associated probability density function (PDF) values $p$ [S1].
*   **Output:** A Tree Table where each row represents a cluster and its connections to adjacent slices [S1].

**Data Structures**
The Tree Table is a list of rows. Each row contains the following fields [S1]:
1.  **CID (Cluster ID):** Unique identifier for the cluster in the current slice [S1].
2.  **SNO (Slice Number):** The index of the current slice [S1].
3.  **HID (Head Cluster ID):** The ID of the cluster in the previous slice ($i-1$) that connects to this cluster [S1]. If no connection exists (start of a local convexity), this is 'x' [S1].
4.  **TID (Tail Cluster ID):** The ID of the cluster in the next slice ($i+1$) that this cluster connects to [S1]. If no connection exists (end of a local convexity), this is 'x' [S1].
5.  **Cr (Correlation Coefficient):** A scalar value representing the similarity between the current cluster and its Tail cluster [S1].

**Algorithm Steps**
1.  **Cluster Identification:** For each slice $i$, identify disjoint clusters of isosurface points and assign a unique CID to each [S1].
2.  **Connection Decision:** For each cluster $cid$ in slice $i$, determine its connection to clusters in slice $i+1$ using the decision function [S1]:
    $$ e(cid, i) = \max_{j} \left\{ \sum_{\tilde{t} \in cid} p_{i+1}(\tilde{t}|c_j) P_{i+1}(c_j) \right\} $$
    where $p_{i+1}(\tilde{t}|c_j)$ is the PDF value at point $\tilde{t}$ for cluster $c_j$ in slice $i+1$, and $P_{i+1}(c_j)$ is a normalization factor for that cluster [S1]. The cluster $c_j$ that maximizes this value becomes the TID for $cid$ [S1].
3.  **Similarity Calculation:** Calculate the correlation coefficient $g(c_m, c_n)$ between a cluster $c_m$ in slice $i$ and its corresponding Tail cluster $c_n$ (TID) in slice $i+1$ [S1]:
    $$ g(c_m, c_n) = \frac{\sum_k (p_i(\tilde{t}_k|c_m) p_{i+1}(\tilde{t}_k|c_n))^2}{\sqrt{\sum_k p_i(\tilde{t}_k|c_m)^2 \sum_k p_{i+1}(\tilde{t}_k|c_n)^2}} $$
    where $\tilde{t}_k$ are the points in cluster $c_m$ [S1].
4.  **Table Population:**
    *   Set `TID` for cluster $cid$ to the ID of the cluster identified in Step 2 [S1].
    *   Set `Cr` for cluster $cid$ to the value $g(c_m, c_n)$ calculated in Step 3 [S1].
    *   If a cluster has multiple tails (multiple connections to the next slice), compute an average Cr value [S1].
    *   Set `HID` for the Tail cluster in slice $i+1$ to the CID of the current cluster [S1].
    *   If a cluster has no connection to the previous slice, set `HID` to 'x' [S1].
    *   If a cluster has no connection to the next slice, set `TID` to 'x' [S1].
5.  **Validation:** Ensure no cluster has both `HID` = 'x' and `TID` = 'x' [S1]. Such a state implies an unattached cluster, which is assumed not to exist in a valid object [S1].

**Pseudocode**
```python
import math

def sample_pdf(grid, point):
    """Interpolates the PDF value at point from the volumetric grid."""
    # Standard grid lookup/interpolation. Not given in the sources. [G]
    return grid[point]

def build_tree_table(slices):
    """
    slices: List of lists of clusters.
    Each cluster: {'id': int, 'points': [(x,y,z)], 'pdf_values': [float], 'grid': grid_data}
    """
    tree_table = []
    prev_table = {}  # Maps CID -> row dict from slice i-1
    P_next = None    # Normalization factors for slice i+1. Not given in the sources. [G]

    for i, current_clusters in enumerate(slices):
        next_clusters = slices[i+1] if i < len(slices) - 1 else None
        current_table = {}

        for cluster in current_clusters:
            cid = cluster['id']
            points = cluster['points']
            pdf_vals = cluster['pdf_values']

            # Step 2: Connection Decision
            best_tcid = None
            best_score = -float('inf')

            if next_clusters:
                for next_cluster in next_clusters:
                    tcid = next_cluster['id']
                    score = 0.0
                    for pt, p_val in zip(points, pdf_vals):
                        target_pdf = sample_pdf(next_cluster['grid'], pt)
                        norm_factor = P_next[tcid] if P_next else 1.0
                        score += target_pdf * norm_factor
                    if score > best_score:
                        best_score = score
                        best_tcid = tcid

            # Step 3: Similarity Calculation
            cr_value = 0.0
            if best_tcid is not None:
                tcluster = next(c for c in next_clusters if c['id'] == best_tcid)
                num = 0.0
                den_m = 0.0
                den_n = 0.0
                for pt, p_m in zip(points, pdf_vals):
                    p_n = sample_pdf(tcluster['grid'], pt)
                    num += (p_m * p_n) ** 2
                    den_m += p_m ** 2
                    den_n += p_n ** 2
                if den_m > 0 and den_n > 0:
                    cr_value = num / math.sqrt(den_m * den_n)

            # Step 4: Table Population
            hid = 'x'
            for prev_cid, prev_row in prev_table.items():
                if prev_row['tid'] == cid:
                    hid = prev_cid
                    break

            row = {
                'cid': cid,
                'sno': i,
                'hid': hid,
                'tid': best_tcid if best_tcid is not None else 'x',
                'cr': cr_value
            }
            current_table[cid] = row
            tree_table.append(row)

        prev_table = current_table

    return tree_table
```

**Parameters**
*   **Slice Spacing:** The method assumes slices are reasonably small to ensure local convexity [S1].
*   **PDF Values:** The method relies on probability density function values associated with each point in the volumetric data [S1].
*   **Normalization Factor $P_{i+1}(c_j)$:** Not given in the sources. [G]

**Edge Cases and Pitfalls**
*   **Unattached Clusters:** A cluster must not have both `HID` and `TID` as 'x' [S1]. This indicates a disconnected component which violates the assumption of a single attached object [S1].
*   **Multiple Connections:** Non-convex objects may result in multiple `HID`s or `TID`s for a single cluster [S1]. The table structure supports this by storing one row per connection or handling multiple tails via average Cr [S1].
*   **Precision:** The correlation coefficient calculation involves squared terms, which may lead to numerical instability if PDF values are very small or very large [S1]. Normalization factors $P_{i+1}(c_j)$ are required for the decision function [S1].

## Operating characteristics
*   **Time Complexity:** The connection decision step requires comparing every cluster in slice $i$ with every cluster in slice $i+1$, leading to $O(N_i \times N_{i+1})$ comparisons per slice pair, where $N$ is the number of clusters [G]. The correlation calculation adds overhead proportional to the number of points in the clusters [G].
*   **Memory Complexity:** The Tree Table size is proportional to the number of clusters across all slices. Each cluster stores a constant number of fields (CID, SNO, HID, TID, Cr) [G].
*   **Strengths:** Provides explicit topological information, enabling robust handling of non-convex shapes and complex branching structures [G]. The correlation metric helps in selecting the most shape-consistent connections [S1].
*   **Limitations:** Requires pre-computed PDF values or a method to evaluate them at arbitrary points [G]. The assumption of "no unattached clusters" may fail for noisy data or fragmented objects [S1].
*   **When to Use:** Suitable for convex contouring methods where topological consistency and local convexity are required, especially for non-convex objects [S1].
*   **When Not to Use:** Not suitable for methods that do not rely on slice-based clustering or explicit tree structures [G].

## Background
The Cluster Connection Tree Table was introduced in the context of local hull-based surface construction of volumetric data from silhouettes [S1]. It is part of a broader family of convex contouring methods that use decision trees to manage the complexity of isosurface extraction [S1]. The method addresses the challenge of maintaining topological consistency when dealing with non-convex objects by explicitly tracking cluster connections across slices [S1].
