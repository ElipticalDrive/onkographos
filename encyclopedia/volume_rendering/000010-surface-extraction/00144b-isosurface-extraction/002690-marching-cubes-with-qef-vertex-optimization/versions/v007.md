# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that computes vertex positions using a Quadric Error Function (QEF) minimization for ambiguous cases, while using a 2D linear/binomial search for non-ambiguous cases, to produce a watertight mesh from a voxel grid [S1, unofficial]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by replacing the standard linear interpolation of classic Marching Cubes with a constrained optimization step for topologically ambiguous configurations, thereby reducing geometric artifacts while maintaining mesh coherence.

## How it works
The algorithm processes voxel indices by filtering them into two groups based on their position in the grid to optimize performance: a "fast" group for non-ambiguous cases and a "slow" group for ambiguous cases requiring QEF optimization [S1, unofficial].

**Inputs:**
- `occs`: A 3D array of occupancy bits (0 or 1) representing the voxel grid.
- `GRID`, `GRID2`, `GRID3`: Grid spacing constants (typically $1, 2, 4$ or similar powers of 2 for bit-shifting optimization).
- `GRID3_`, `GRID2_`: Precomputed constants for index calculation.
- `ERR`: A small threshold for degenerate edge detection.
- `QEF_REG`: Regularization parameter for the QEF least-squares solver.
- `SEP`: Separation constant for boundary constraints.
- Lookup tables: `amb_chks`, `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab`, `lctab_2d`, `qvntab`, `pfvtab`, `vitogi`, `cstrtab`.

**Outputs:**
- `val_pnts`: An array of computed vertex positions.

**Data Structures:**
- `pidx1`: Flattened indices of active voxels.
- `pidx3`: 3D coordinates $(x, y, z)$ derived from `pidx1`.
- `val_`: Integer occupancy pattern (0-15) for a cell, computed from neighbor bits.
- `cases`: Configuration index for the cell.

**Steps:**

1.  **Filter Indices**: Split `pidx1` into:
    -   Group 1 (Fast): indices in range $[3 \cdot GRID3, 9 \cdot GRID3)$.
    -   Group 2 (QEF): indices $\ge 9 \cdot GRID3$.
    -   Initialize `start_idx = 0`.

2.  **Process Group 1 (Non-Ambiguous)**:
    For each index in Group 1:
    a.  Compute the 8-neighbor occupancy value `val_`:
        $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
        where `axis0`, `axis1`, `axis2` are direction vectors derived from lookup tables based on the cell's relative position.
    b.  Apply ambiguity correction: If `amb_chks[pidx3]` is true, set `val\_ = 15 - val\_`.
    c.  Compute vertex positions using a 2D search function `_2d_search(pidx3, axdir, axis0, axis1, val_, cases)`.
    d.  Store results in `val_pnts` at `start_idx` and increment `start_idx` by the count of processed items.

3.  **Process Group 2 (Ambiguous/QEF)**:
    For each index in Group 2:
    a.  Compute `val_` and `cases` as in Step 2.
    b.  Call `_solve_QEF(pidx3, val_, cases)` to compute optimized vertex positions.
    c.  Store results in `val_pnts` at `current start_idx`.

**Detailed QEF Solver (`_solve_QEF`):**

1.  **Retrieve Geometry**: For each vertex index $i$ from 3 to 7:
    a.  Find indices `idx` where `qvntab[val_, cases] == i`.
    b.  Retrieve vertex coordinates `vtcs` from `pfvtab[val0_, cas, :2*i+1]`.
    c.  Retrieve edge indices `vitg` from `vitogi[vtcs]`.

2.  **Compute 3D Positions**:
    Calculate grid offsets for the vertices:
    $$ pnti = vitg[:,:,3] \cdot GRID3 + (pid3[:,0] + vitg[:,:,0]) \cdot GRID2 + (pid3[:,1] + vitg[:,:,1]) \cdot GRID + (pid3[:,2] + vitg[:,:,2]) $$
    Get global indices `pidx` and retrieve pre-computed vertex positions `vert = val_pnts[pidx]`.
    Add local offsets: `vert += vitg[:,:3]`.

3.  **Compute QEF Normals**:
    a.  Extract vertex pairs: `_1vt = vert[:, 1::2]`.
    b.  Compute normals via cross products of edge vectors:
        $$ qnrm = \text{cross}(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
    c.  Compute centroid: $cntr = \text{mean}(\_1vt, \text{dim}=1)$.
    d.  Normalize `qnrm`. If edge length is below `ERR`, treat as degenerate.

4.  **Solve QEF System**:
    Construct the least-squares system:
    $$ A = \text{cat}(qnrm, QEF\_REG \cdot I) $$
    $$ b = \text{cat}(\sum(\_1vt \cdot qnrm), QEF\_REG \cdot cntr) $$
    Solve for $qefr = A^{-1}b$ (or using least squares).
    If all normals are degenerate, use $cntr$ as the solution.

5.  **Constrain to Boundary**:
    a.  Compute ray direction: $ctoq = qefr - cpnt$ (where $cpnt$ is the cell center).
    b.  Compute length $leng = \|ctoq\|$.
    c.  Compute intersection parameter $t$ with constraint planes defined by `cstrtab`.
    d.  Concatenate boundary parameters $(1-cpnt)/ctoq$ and $-cpnt/ctoq$ with $t$.
    e.  Handle NaNs and negative values: if invalid, set $t = leng + SEP$.
    f.  Normalize by $leng$ and clamp $t$ to $[0, 1]$.
    g.  Final vertex: $v = cpnt + t \cdot ctoq$.

**Pseudocode:**

```python
def solve_qef(pidx3, val_, cases, occs, GRID, GRID2, GRID3, GRID3_, GRID2_, 
              axd_tab, ax0_tab, ax1_tab, cas_tab, qvntab, pfvtab, vitogi, 
              val_pnts, ERR, QEF_REG, SEP):
    """
    Solves the QEF for ambiguous Marching Cubes cases.
    """
    # 1. Retrieve Geometry
    # Note: Implementation details depend on specific table layouts.
    # We assume qvntab maps (val_, cases) to vertex indices.
    vertex_indices = qvntab[val_, cases]
    
    # Initialize arrays for normals and points
    normals = []
    points = []
    
    for i in range(3, 8): # Vertex indices 3 to 7
        if vertex_indices[i] is valid:
            # Retrieve coordinates and edge indices
            vtcs = pfvtab[val_, cases, :2*i+1]
            vitg = vitogi[vtcs]
            
            # Compute 3D positions
            # pid3 is pidx3 converted to 3D coordinates
            pnti = (vitg[:,:,3] * GRID3 + 
                    (pidx3[:,0] + vitg[:,:,0]) * GRID2 + 
                    (pidx3[:,1] + vitg[:,:,1]) * GRID + 
                    (pidx3[:,2] + vitg[:,:,2]))
            
            # Get global indices and pre-computed positions
            pidx = get_global_indices(pnti)
            vert = val_pnts[pidx]
            
            # Add local offsets
            vert = vert + vitg[:,:3]
            
            points.append(vert)
            
            # Compute normals
            if len(vert) >= 4: # Need at least 2 edges
                v1 = vert[:, 1::2]
                v0 = vert[:, :-1:2]
                v2 = vert[:, 2::2]
                
                edge1 = v1 - v0
                edge2 = v1 - v2
                nrm = cross(edge1, edge2)
                
                # Normalize
                len_nrm = norm(nrm, dim=1, keepdim=True)
                degenerate = len_nrm < ERR
                len_nrm[degenerate] = 1.0
                nrm = nrm / len_nrm
                
                normals.append(nrm)
    
    if not normals:
        return pidx3 # Fallback if no geometry

    # 2. Solve QEF
    # Stack normals and points
    A_normals = stack(normals)
    # Points are used to compute the right-hand side
    # b = sum(v * n)
    b_vec = sum([dot(v, n) for v, n in zip(points, normals)], dim=1, keepdim=True)
    
    # Centroid
    cntr = mean(stack(points), dim=0)
    
    # Add regularization
    A = cat([A_normals, QEF_REG * eye(3)], dim=0)
    b = cat([b_vec, QEF_REG * cntr], dim=0)
    
    # Solve least squares
    # qefr = argmin ||Ax - b||^2
    qefr = lstsq(A, b)
    
    # Check for degenerate normals
    if all_degenerate(normals):
        qefr = cntr
        
    # 3. Constrain to Boundary
    cpnt = get_cell_center(pidx3)
    ctoq = qefr - cpnt
    leng = norm(ctoq)
    
    # Compute intersection with constraint planes
    # This part depends on cstrtab implementation
    t = compute_intersection(ctoq, cstrtab)
    
    # Handle NaNs and negatives
    invalid = isnan(t) | (t < 0)
    t[invalid] = leng + SEP
    
    # Normalize and clamp
    t = t / leng
    t = clamp(t, 0, 1)
    
    return cpnt + t * ctoq
```

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
- **Time Complexity**: The method splits processing into a fast path (Group 1) using 2D search and a slow path (Group 2) using QEF minimization. The QEF step involves solving a least-squares system, which is more expensive than linear interpolation but limited to ambiguous cases.
- **Memory Complexity**: Requires storage for lookup tables (`qvntab`, `pfvtab`, etc.) and the output vertex array. The QEF solver requires temporary storage for normals and the system matrix $A$.
- **Performance**: The QEF approach is computationally heavier than standard Marching Cubes but provides higher geometric accuracy for ambiguous configurations. The QEM variant offers a trade-off, reducing register pressure on GPUs while maintaining volume preservation [S2, unofficial].
- **Strengths**: Produces watertight meshes; handles ambiguous cases more accurately than standard linear interpolation; QEM variant is efficient on parallel hardware.
- **Limitations**: QEF minimization is complex and may penalize performance on hardware with limited registers; requires pre-computed lookup tables.

## Background
The method originates from the ODC (Octree-based Discrete Contouring) project by KAIST Visual AI Group [S1, unofficial]. It was developed to address the limitations of standard Marching Cubes in handling ambiguous topological cases, which can lead to geometric artifacts. The QEF optimization minimizes the error function defined by the supporting planes of the mesh edges, providing a more accurate vertex position. The QEM variant was introduced to optimize performance on parallel hardware by reducing computational complexity [S2, unofficial].
