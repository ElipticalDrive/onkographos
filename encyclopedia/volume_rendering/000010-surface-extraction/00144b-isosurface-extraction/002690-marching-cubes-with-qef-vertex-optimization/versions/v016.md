# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that computes vertex positions using a Quadric Error Function (QEF) minimization for ambiguous cases, while using a 2D linear/binomial search for non-ambiguous cases, to produce a watertight mesh from a voxel grid [S1, unofficial]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by replacing the standard linear interpolation of classic Marching Cubes with a hybrid approach: fast geometric search for simple configurations and least-squares optimization for topologically ambiguous ones [S1, unofficial]. This distinguishes it from standard [Marching Cubes](30-isosurface-extraction.md) by reducing geometric artifacts in ambiguous regions, and from [Dual Contouring](9119-dual-contouring.md) by retaining the simpler lookup-table-driven topology of Marching Cubes while optimizing vertex placement [S1, unofficial].

## How it works
The method operates on a regular 3D grid of occupancy values. It classifies grid cells into two groups based on their index to determine the optimization strategy: "fast" cells (indices in range $[3 \cdot G^3, 9 \cdot G^3)$) and "ambiguous" cells (indices $\ge 9 \cdot G^3$), where $G$ is the grid dimension in one axis and $G^3$ is the total number of cells per layer [S1, unofficial].

### Inputs and Outputs
*   **Input**: A 3D occupancy grid `occs` of size $G \times G \times G$, where each element is a binary bit (0 or 1) representing voxel occupancy.
*   **Output**: A list of vertex positions `val_pnts` and associated mesh connectivity (implied by the generation of vertices for specific cases).

### Data Structures
*   `occs`: 3D array of integers (0 or 1).
*   `val_pnts`: 2D array of shape $(N, 3)$, storing 3D coordinates of generated vertices.
*   `amb_chks`: Boolean array indicating which cells require ambiguity correction.
*   `qvntab`, `pfvtab`, `vitogi`, `cstrtab`, `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab`: Precomputed lookup tables for vertex indices, edge indices, constraint planes, and axis directions.
*   `GRID`, `GRID2`, `GRID3`: Constants representing $G$, $G^2$, $G^3$.
*   `ERR`: Small threshold for degenerate edge detection.
*   `QEF_REG`: Regularization parameter for the QEF least-squares solver.
*   `VERTICAL_RANGE`, `HORIZNTL_RANGE`: Search ranges for the 2D search.
*   `VERTICAL_LINEAR_SEARCH`, `VERTICAL_BINARY_SEARCH`, `HORIZNTL_LINEAR_SEARCH`, `HORIZNTL_BINARY_SEARCH`: Flags controlling search type.

### Algorithm Steps

1.  **Filter and Classify Cells**:
    Identify cell indices `pidx1` that lie on the surface. Split them into:
    *   `pidx_fast`: indices where $3 \cdot G^3 \le \text{pidx1} < 9 \cdot G^3$.
    *   `pidx_slow`: indices where $\text{pidx1} \ge 9 \cdot G^3$.

2.  **Process Fast Cells (2D Search)**:
    For each cell in `pidx_fast`:
    a.  Compute the 8-neighbor occupancy pattern `val_`:
        $$ \text{val\_} = \text{occs}[pidx3] + 2 \cdot \text{occs}[pidx3 + \text{axis1}] + 4 \cdot \text{occs}[pidx3 + \text{axis0}] + 8 \cdot \text{occs}[pidx3 + \text{axis2}] $$
        where `axis0`, `axis1`, `axis2` are axis direction vectors derived from lookup tables based on the cell index.
    b.  Apply ambiguity correction: If `amb_chks[pidx3]` is true, set $\text{val\_} = 15 - \text{val\_}$.
    c.  Compute vertex positions using `_2d_search(pidx3, axdir, axis0, axis1, val_, cases)`.
    d.  Store results in `val_pnts` and update `start_idx`.

3.  **Process Slow Cells (QEF Optimization)**:
    For each cell in `pidx_slow`:
    a.  Compute `val_` and `cases` as above.
    b.  Call `_solve_QEF(pidx3, val_, cases)`.
    c.  Store results in `val_pnts`.

4.  **QEF Solver (`_solve_QEF`)**:
    For each vertex index $i$ in the cell's case (typically 3 to 7):
    a.  Find edge indices `vitg` associated with vertex $i$ using `qvntab[val_, cases]`.
    b.  Retrieve pre-computed vertex positions `vert` from `val_pnts` using global indices.
    c.  Compute local offsets and 3D positions `pnti` using grid offsets and edge indices.
    d.  Compute QEF normals `qnrm` using cross products of edge vectors:
        $$ \text{qnrm} = \text{cross}(\text{vert}_{1::2} - \text{vert}_{:-1:2}, \text{vert}_{1::2} - \text{vert}_{2::2}) $$
    e.  Compute centroid `cntr` of the vertex ring.
    f.  Normalize `qnrm`, handling zero-length edges with `ERR`.
    g.  Solve the QEF system using least squares:
        $$ A = \text{concat}(\text{qnrm}, \text{QEF\_REG} \cdot I) $$
        $$ b = \text{concat}(\sum (\text{vert}_{1::2} \cdot \text{qnrm}), \text{QEF\_REG} \cdot \text{cntr}) $$
        $$ \text{qefr} = \text{lstsq}(A, b).\text{solution} $$
        If all normals are degenerate, use `cntr` instead.
    h.  Compute ray direction `ctoq = qefr - cpnt` and length `leng`.
    i.  Compute intersection parameter `t` with constraint planes defined by `cstrtab`.
    j.  Handle NaNs and negative values by setting `t` to `leng + SEP`, then normalize by `leng` and clamp to $[0, 1]$.
    k.  Final vertex is `cpnt + t * ctoq`.

5.  **2D Search (`_2d_search`)**:
    For non-ambiguous cases:
    a.  Compute initial point `spnt` and normal `vnorm` using linear/binomial search.
    b.  Refine using horizontal search along `hnorm`.
    c.  Compute final position `rslt` and return `spnt + rslt`.

### Edge Cases and Pitfalls
*   **Degenerate Normals**: If all normals in the QEF solver are degenerate (length < `ERR`), the centroid is used instead [S1, unofficial].
*   **NaNs and Negative Values**: Intersection parameters `t` that are NaN or negative are handled by setting `t` to `leng + SEP` before normalization and clamping [S1, unofficial].
*   **Ambiguity Correction**: For certain cell configurations, the occupancy pattern `val_` must be inverted ($15 - \text{val\_}$) to resolve topological ambiguities [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: The method splits processing into two groups. Fast cells use a 2D search, which is $O(1)$ per cell. Slow cells use QEF minimization, which involves solving a least-squares system, typically $O(k^3)$ where $k$ is the number of edges/vertices in the local ring (small constant). Overall, it is $O(N)$ where $N$ is the number of surface cells.
*   **Memory Complexity**: Requires storage for the occupancy grid, lookup tables, and the output vertex list. The lookup tables are precomputed and constant size relative to the grid. Memory is $O(N)$ for the output.
*   **Measured Performance**: Not given in the sources.
*   **Strengths**: Produces watertight meshes with improved geometric accuracy in ambiguous regions compared to standard Marching Cubes. The hybrid approach balances speed and accuracy.
*   **Limitations**: More complex to implement than standard Marching Cubes. The QEF solver may be slower for highly ambiguous scenes.
*   **When to Use**: When high-quality surface reconstruction is needed, especially in regions with topological ambiguities, and performance is not the primary constraint.
*   **When Not to Use**: When real-time performance is critical and the scene has few ambiguous regions, standard Marching Cubes or QEM-based relocation may be preferable.

## Background
The method originates from the ODC (Octree-based Dual Contouring) project by KAIST Visual AI Group [S1, unofficial]. It was developed to improve the quality of surface extraction from voxel grids while maintaining the simplicity of the Marching Cubes topology. The QEF optimization is inspired by the work of Hoppe et al. on Quadric Error Metrics [S2, unofficial].
