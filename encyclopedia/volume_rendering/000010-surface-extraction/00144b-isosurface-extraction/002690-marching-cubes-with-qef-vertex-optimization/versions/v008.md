# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that computes vertex positions using a Quadric Error Function (QEF) minimization for ambiguous cases, while using a 2D linear/binomial search for non-ambiguous cases, to produce a watertight mesh from a voxel grid [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by replacing the standard linear interpolation of vertex positions with a geometric optimization step specifically for topologically ambiguous voxels, thereby resolving cracks and holes caused by inconsistent ambiguity handling [S1, unofficial].

## How it works
The method processes voxel indices by splitting them into two groups based on their topological complexity: simple cases (resolved via fast 2D search) and ambiguous cases (resolved via QEF minimization).

### Inputs and Outputs
*   **Input**: A scalar field grid (voxel values), an isovalue $I$, and the precomputed lookup tables from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) (`edgeTable`, `triangleTable`).
*   **Output**: A triangular mesh (vertices and indices) representing the isosurface.

### Data Structures
*   **Occupancy Grid (`occs`)**: A boolean or integer grid where `occs[v]` is 1 if $V(v) \ge I$ (or $< I$, consistent with the case index convention) and 0 otherwise.
*   **Ambiguity Check Table (`amb_chks`)**: A boolean array indexed by the 8-bit case index, true for ambiguous cases (46, 47, 98, 99, 210, 213, 214, 215) [S7, S8, unofficial].
*   **QEF Tables**: Precomputed tables (`qvntab`, `pfvtab`, `vitogi`, `cstrtab`) mapping case indices and vertex configurations to edge indices, vertex coordinates, and constraint planes for QEF solving [S1, unofficial].

### Algorithm Steps

1.  **Filter and Group Voxels**:
    Iterate through all voxel indices $pidx1$. Split them into two groups:
    *   **Group 1 (Simple)**: Indices in range $[3 \cdot G^3, 9 \cdot G^3)$, where $G$ is the grid dimension. These are resolved using 2D search.
    *   **Group 2 (Ambiguous)**: Indices $\ge 9 \cdot G^3$. These are resolved using QEF optimization [S1, unofficial].

2.  **Process Group 1 (2D Search)**:
    For each voxel in Group 1:
    a.  **Compute Case Index**: Calculate the 8-bit occupancy pattern `val_` by summing weighted occupancy bits from the 8 neighbors:
        $$ \text{val\_} = \text{occs}[pidx3] + 2 \cdot \text{occs}[pidx3 + \text{axis1}] + 4 \cdot \text{occs}[pidx3 + \text{axis0}] + 8 \cdot \text{occs}[pidx3 + \text{axis2}] $$
        where `axis0`, `axis1`, `axis2` are direction vectors defining the local neighborhood orientation [S1, unofficial].
    b.  **Ambiguity Correction**: If `amb_chks[val_]` is true, invert the pattern: $\text{val\_} = 15 - \text{val\_}$ [S1, unofficial].
    c.  **Vertex Search**: Call `_2d_search` using `val_`, the case configuration, and the voxel position. This function performs a linear or binary search along specific axes to find the intersection points [S1, unofficial].
    d.  **Store Vertices**: Store the resulting vertex positions in the output array `val_pnts` at `start_idx`. Increment `start_idx` by the number of vertices found [S1, unofficial].

3.  **Process Group 2 (QEF Optimization)**:
    For each voxel in Group 2:
    a.  **Retrieve Configuration**: Determine the case index and vertex indices from precomputed tables based on the voxel position [S1, unofficial].
    b.  **Solve QEF**: Call `_solve_QEF(val_, cases)` [S1, unofficial].
        i.  **Retrieve Edge Data**: For each vertex index $i$ (typically 3 to 7 for ambiguous cases), retrieve the global vertex coordinates `vert` from `val_pnts` and the local edge indices `vitg` [S1, unofficial].
        ii. **Compute Local Positions**: Calculate local 3D positions `pnti` using grid offsets and edge indices:
            $$ \text{pnti} = \text{vitg}[:, 3] \cdot G^3 + (\text{pid3}[:, 0] + \text{vitg}[:, 0]) \cdot G^2 + (\text{pid3}[:, 1] + \text{vitg}[:, 1]) \cdot G + (\text{pid3}[:, 2] + \text{vitg}[:, 2]) $$
            where `pid3` is the voxel's base position [S1, unofficial].
        iii. **Compute Normals**: Calculate QEF normals `qnrm` using cross products of edge vectors:
            $$ \text{qnrm} = \text{cross}(\text{vert}[:, 1::2] - \text{vert}[:, :-1:2], \text{vert}[:, 2::2] - \text{vert}[:, 1::2]) $$
            Compute the centroid `cntr` of the edge vertices. Normalize `qnrm`, handling zero-length edges with a threshold `ERR` [S1, unofficial].
        iv. **Solve Least Squares**: Construct the QEF system $A \mathbf{x} = \mathbf{b}$:
            $$ A = \begin{bmatrix} \text{qnrm} \\ \lambda \mathbf{I} \end{bmatrix}, \quad \mathbf{b} = \begin{bmatrix} \sum (\text{vert} \cdot \text{qnrm}) \\ \lambda \cdot \text{cntr} \end{bmatrix} $$
            where $\lambda$ is a regularization parameter (`QEF_REG`). Solve for $\mathbf{x}$ (denoted `qefr`) using least squares. If all normals are degenerate, use `cntr` as the solution [S1, unofficial].
        v.  **Constrain to Isosurface**: Compute the ray direction `ctoq = qefr - cpnt` (where `cpnt` is the voxel center). Calculate the intersection parameter $t$ with constraint planes defined by `cstrtab`. Handle NaNs and negative values by clamping $t$ to $[0, 1]$. The final vertex is:
            $$ \mathbf{v}_{final} = \text{cpnt} + t \cdot \text{ctoq} $$
    c.  **Store Vertices**: Store the optimized vertices in `val_pnts` [S1, unofficial].

4.  **Mesh Assembly**:
    Use the `triangleTable` from the parent article to connect the computed vertices into triangles for each voxel [S7, S8, unofficial].

### Parameters and Typical Values
*   **Grid Dimension ($G$)**: Depends on the resolution of the input scalar field.
*   **Regularization Parameter ($\lambda$)**: A small value (e.g., $10^{-6}$) to stabilize the least squares solution [S1, unofficial].
*   **Error Threshold (`ERR`)**: A small value (e.g., $10^{-8}$) to detect degenerate normals or zero-length edges [S1, unofficial].
*   **Vertical/Horizontal Search Ranges**: Parameters controlling the extent of the 2D search, typically related to the grid resolution [S1, unofficial].

### Edge Cases and Pitfalls
*   **Degenerate Normals**: If all edge vectors are collinear or zero, the QEF normals are degenerate. The algorithm handles this by falling back to the centroid of the edge vertices [S1, unofficial].
*   **NaNs and Negative Values**: Intersection parameters $t$ can become NaN or negative due to numerical instability. These are handled by clamping $t$ to $[0, 1]$ or setting it to a safe value like `leng + SEP` [S1, unofficial].
*   **Ambiguity Consistency**: The ambiguity correction step (`val_ = 15 - val_`) ensures that adjacent voxels resolve the ambiguity consistently, preventing cracks [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: The 2D search for non-ambiguous cases is $O(1)$ per vertex. The QEF optimization for ambiguous cases involves solving a small least squares system, which is also $O(1)$ per vertex but with a higher constant factor. Overall complexity is linear with respect to the number of voxels.
*   **Memory Complexity**: Requires storage for the occupancy grid, lookup tables, and precomputed QEF tables. The QEF tables add overhead but are necessary for the optimization step.
*   **Performance**: The QEF optimization is more computationally expensive than standard linear interpolation but provides higher quality meshes for ambiguous cases. The 2D search is fast and suitable for simple cases [S1, unofficial].
*   **Strengths**: Produces watertight meshes, resolves topological ambiguities consistently, and maintains volume preservation [S1, unofficial][S2, unofficial].
*   **Limitations**: More complex to implement than standard Marching Cubes. The QEF optimization can be slower than linear interpolation, especially on hardware with limited register counts [S2, unofficial].
*   **When to Use**: When high-quality, watertight meshes are required, especially in the presence of topological ambiguities.
*   **When Not to Use**: When performance is critical and the input data does not contain significant ambiguous cases, or when hardware constraints limit the use of QEF optimization.

## Background
The method originates from the ODC (Octree-based Densification and Compression) project by the KAIST Visual AI Group, which introduced a hybrid approach combining fast 2D search for simple cases with QEF optimization for ambiguous cases [S1, unofficial]. The use of QEF for vertex optimization in surface extraction is rooted in the work of Garland and Heckbert on Quadric Error Metrics (QEM) for mesh simplification, which was adapted for isosurface extraction to improve vertex placement accuracy [S2, unofficial].
