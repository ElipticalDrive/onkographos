# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that computes vertex positions using a Quadric Error Function (QEF) minimization for ambiguous cases, while using a 2D linear/binomial search for non-ambiguous cases, to produce a watertight mesh from a voxel grid [S1, unofficial]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by replacing the standard linear interpolation of classic Marching Cubes with a hybrid approach: fast geometric search for simple configurations and least-squares optimization for topologically ambiguous ones [S1, unofficial]. This distinguishes it from standard [Marching Cubes](30-isosurface-extraction.md) (which uses linear interpolation) and [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md) (which uses QEF for all vertices), offering a balance between computational speed and geometric accuracy [S1, unofficial].

## How it works
The method operates on a regular 3D grid of voxels. It classifies each cell based on its topology to determine whether to use a fast 2D search or a QEF minimization.

### Inputs and Outputs
*   **Input**: A 3D occupancy grid `occs` (binary or scalar values indicating inside/outside), an isovalue threshold (implicit in occupancy), and configuration tables (`lctab_2d`, `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab`, `qvntab`, `pfvtab`, `vitogi`, `cstrtab`).
*   **Output**: A set of vertex positions `val_pnts` and connectivity information (implied by the generation of triangles from the vertex positions).

### Data Structures
*   `occs`: 3D array of occupancy bits.
*   `GRID`, `GRID2`, `GRID3`: Grid dimensions or strides.
*   `lctab_2d`: Lookup table for 2D linear/binomial search results.
*   `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab`: Precomputed tables for axis directions and case indices.
*   `qvntab`: Vertex index lookup table.
*   `pfvtab`: Precomputed face vertex table.
*   `vitogi`: Vertex index to global index mapping.
*   `cstrtab`: Constraint table for boundary parameters.
*   `ERR`: Small threshold for degenerate edge detection.
*   `QEF_REG`: Regularization parameter for QEF system.
*   `VERTICAL_RANGE`, `HORIZNTL_RANGE`: Search ranges.
*   `VERTICAL_LINEAR_SEARCH`, `VERTICAL_BINARY_SEARCH`, `HORIZNTL_LINEAR_SEARCH`, `HORIZNTL_BINARY_SEARCH`: Search flags.

### Algorithm Steps

1.  **Filter and Classify Cells**:
    Filter voxel indices `pidx1` into two groups:
    *   Group 1 (Fast Path): Indices in range `[3*GRID3, 9*GRID3)`.
    *   Group 2 (QEF Path): Indices `>= 9*GRID3`.
    Initialize `start_idx` to 0.

2.  **Process Group 1 (Non-Ambiguous)**:
    For each index in Group 1:
    a. Compute the 8-neighbor occupancy value `val_` by summing weighted occupancy bits:
       $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
       where `pidx3` is the 3D index, and `axis0`, `axis1`, `axis2` are direction vectors.
    b. Apply ambiguity correction: If `tmp = amb_chks[pidx3]` is true, set `val\_ = 15 - val\_`.
    c. Compute vertex positions using `_2d_search(pidx3, axdir, axis0, axis1, val_, cases)` and store in `val_pnts` at `start_idx`.
    d. Increment `start_idx` by the count of processed indices.

3.  **Process Group 2 (Ambiguous)**:
    For each index in Group 2:
    a. Call `_solve_QEF(pidx3, val_, cases)` where `val_` is the integer occupancy pattern and `cases` is derived from `pidx1 / GRID3 - 9`.
    b. Store results in `val_pnts` at `start_idx`.

4.  **QEF Solving (`_solve_QEF`)**:
    a. For each vertex index `i` from 3 to 7, find indices `idx` where `qvntab[val_, cases] == i`.
    b. Retrieve vertex coordinates `vtcs` from `pfvtab[val0_, cas, :2*i+1]` and edge indices `vitg` from `vitogi[vtcs]`.
    c. Compute 3D positions `pnti` for the vertices using grid offsets:
       $$ pnti = vitg[:,:,3] \cdot GRID3 + (pid3[:,0] + vitg[:,:,0]) \cdot GRID2 + (pid3[:,1] + vitg[:,:,1]) \cdot GRID + (pid3[:,2] + vitg[:,:,2]) $$
       Get global indices `pidx` and retrieve pre-computed vertex positions `vert = val_pnts[pidx]`.
    d. Add local offsets `vitg[:,:3]` to `vert`.
    e. Compute QEF normals `qnrm` using cross products of edge vectors:
       $$ \_1vt = vert[:, 1::2] $$
       $$ qnrm = cross(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
    f. Compute centroid `cntr = mean(\_1vt, dim=1)`.
    g. Normalize `qnrm` handling zero-length edges with `ERR` threshold.
    h. Solve the QEF system using least squares:
       $$ A = cat(qnrm, QEF\_REG \cdot eye) $$
       $$ b = cat(sum(\_1vt \cdot qnrm), QEF\_REG \cdot cntr) $$
       Solution `qefr = lstsq(A, b).solution`. If all normals are degenerate (`cndt` all true), use `cntr` instead.
    i. Compute ray direction `ctoq = qefr - cpnt` and length `leng`.
    j. Compute intersection parameter `t` with constraint planes defined by `cstrtab`. Concatenate boundary parameters `(1-cpnt)/ctoq` and `-cpnt/ctoq` with `t`.
    k. Handle NaNs and negative values by setting `t` to `leng + SEP`, then normalize by `leng` and clamp to `[0, 1]`.
    l. Final vertex is `cpnt + t \cdot ctoq`.

5.  **2D Search (`_2d_search`)**:
    a. Compute 8-neighbor occupancy value `val_` and apply ambiguity correction.
    b. Use lookup table `lctab_2d` to get initial indices `lcres`.
    c. Compute initial point `spnt` and normal `vnorm` based on occupancy differences.
    d. Refine position using linear/binomial search in vertical and horizontal directions.
    e. Return final vertex position.

### Edge Cases and Pitfalls
*   **Degenerate Normals**: If all normals are degenerate (zero-length edges), the QEF solution falls back to the centroid [S1, unofficial].
*   **NaNs and Negative Values**: Intersection parameters `t` are handled by setting them to `leng + SEP` if they are NaN or negative, then clamping to `[0, 1]` [S1, unofficial].
*   **Ambiguity Correction**: Ambiguous cases require correction by inverting the occupancy value `val_ = 15 - val_` if `amb_chks[pidx3]` is true [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

*   **Time Complexity**: Not given in the sources.

*   **Strengths**: Balances computational speed and geometric accuracy by using fast 2D search for non-ambiguous cases and QEF for ambiguous ones [S1, unofficial]. QEM variant reduces register usage on parallel hardware [S2, unofficial].
*   **Limitations**: QEF minimization is complex and may penalize performance on parallel hardware if not optimized [S2, unofficial].
*   **When to Use**: When a watertight mesh is required from a voxel grid and geometric accuracy is important, especially for ambiguous topologies [S1, unofficial].
*   **When Not to Use**: When computational resources are extremely limited and approximate results are acceptable, or when parallel hardware register limits are a bottleneck and QEM is not sufficient [S2, unofficial].

## Background
The method originates from the ODC (Octree-based Density Compression) project by KAIST Visual AI Group [S1, unofficial]. It was developed to provide an efficient and accurate surface extraction method for voxel grids [S1, unofficial]. The QEM-based variant was introduced to address performance issues on parallel hardware by reducing computational complexity [S2, unofficial].
