# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that produces watertight meshes from voxel grids by combining fast linear/binomial search for non-ambiguous cases with Quadric Error Function (QEF) minimization for ambiguous cases [S1, unofficial]. It sets itself apart from standard Marching Cubes by resolving topological ambiguities (cases 46, 47, 98, 99, 210, 213, 214, 215) via geometric optimization rather than fixed lookup table triangulations, thereby preventing cracks and holes [S1, unofficial]. Unlike siblings that use full QEF for all vertices, this method restricts the expensive QEF solve to ambiguous regions, using a 2D search for the majority of vertices to maintain performance [S1, unofficial].

## How it works
The method processes voxel indices in two distinct groups based on their case complexity. It relies on the parent's `edgeTable` and `triangleTable` to identify ambiguous cases and determine vertex connectivity [S1, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `occs`: 3D occupancy grid (binary or scalar field sampled to binary).
    *   `GRID`, `GRID2`, `GRID3`: Grid dimensions ($N_x, N_y, N_z$).
    *   `pidx1`: List of voxel indices to process.
    *   `val_pnts`: Pre-allocated array for vertex positions.
    *   `cases`, `axd_tab`, `ax0_tab`, `ax1_tab`: Precomputed tables mapping case indices to axis directions and configuration types [S1, unofficial].
*   **Outputs**:
    *   `val_pnts`: Array of 3D vertex positions.
    *   Triangles defined by indices into `val_pnts` (derived from `triangleTable` and vertex indices).

### Data Structures
*   **Ambiguity Check Table (`amb_chks`)**: Boolean array indexed by case index. True for cases 46, 47, 98, 99, 210, 213, 214, 215 [S1, unofficial].
*   **QEF Quantization Table (`qvntab`)**: Maps `(val_, cases)` to vertex indices involved in the QEF solve [S1, unofficial].
*   **Pre-computed Vertex Table (`pfvtab`)**: Stores local offset coordinates for vertices in ambiguous cases [S1, unofficial].
*   **Vertex Index to Global Edge Map (`vitogi`)**: Maps local vertex indices to global edge indices [S1, unofficial].

### Algorithm Steps

1.  **Partition Indices**:
    Filter `pidx1` into two groups:
    *   Group A (Fast): Indices in range $[3 \cdot GRID3, 9 \cdot GRID3)$.
    *   Group B (QEF): Indices $\ge 9 \cdot GRID3$ [S1, unofficial].

2.  **Process Group A (2D Search)**:
    For each voxel index `pidx3` in Group A:
    a.  Compute the 8-bit occupancy pattern `val_`:
        $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
        where `axis0`, `axis1`, `axis2` are direction vectors from precomputed tables [S1, unofficial].
    b.  Apply Ambiguity Correction:
        If `amb_chks[val_]` is true, set $val\_ = 15 - val\_$ [S1, unofficial].
    c.  Compute vertex positions using `_2d_search`:
        This function performs a 2D linear/binomial search to find the intersection point on the cube edges based on `val_` and the case configuration [S1, unofficial].
    d.  Store result in `val_pnts` at `start_idx` and increment `start_idx` by the count of processed voxels [S1, unofficial].

3.  **Process Group B (QEF Optimization)**:
    For each voxel index `pidx3` in Group B:
    a.  Compute `val_` and `cases` as in Step 2a.
    b.  Call `_solve_QEF(pidx3, val_, cases)` [S1, unofficial].
    c.  Store results in `val_pnts` at `start_idx` [S1, unofficial].

### `_solve_QEF` Implementation Details
This function computes the optimal vertex position for ambiguous cases by minimizing the distance to the isosurface defined by the surrounding geometry.

1.  **Retrieve Local Geometry**:
    For each vertex index `i` (typically 3 to 7, depending on the case):
    a.  Find indices `idx` where `qvntab[val_, cases] == i` [S1, unofficial].
    b.  Retrieve local vertex coordinates `vtcs` from `pfvtab[val0_, cas, :2*i+1]` [S1, unofficial].
    c.  Retrieve edge indices `vitg` from `vitogi[vtcs]` [S1, unofficial].

2.  **Compute Global Positions**:
    Calculate 3D positions `pnti` using grid offsets:
    $$ pnti = vitg[:,:,3] \cdot GRID3 + (pid3[:,0] + vitg[:,:,0]) \cdot GRID2 + (pid3[:,1] + vitg[:,:,1]) \cdot GRID + (pid3[:,2] + vitg[:,:,2]) $$
    Get global indices `pidx` and retrieve pre-computed vertex positions `vert = val_pnts[pidx]`. Add local offsets `vitg[:,:3]` to `vert` [S1, unofficial].

3.  **Compute QEF Normals**:
    a.  Extract vertex pairs `_1vt = vert[:, 1::2]`.
    b.  Compute normals via cross products of edge vectors:
        $$ qnrm = \text{cross}(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
    c.  Compute centroid:
        $$ cntr = \text{mean}(\_1vt, \text{dim}=1) $$
    d.  Normalize `qnrm`. Handle zero-length edges (degenerate cases) by checking against a threshold `ERR`. If length $< ERR$, set length to 1.0 before normalizing [S1, unofficial].

4.  **Solve QEF System**:
    a.  Construct matrix $A$ and vector $b$ for least squares:
        $$ A = \text{cat}(qnrm, QEF\_REG \cdot I) $$
        $$ b = \text{cat}(\text{sum}(\_1vt \cdot qnrm), QEF\_REG \cdot cntr) $$
        where $QEF\_REG$ is a regularization constant (typically small, e.g., $10^{-6}$) [S1, unofficial].
    b.  Solve for $qefr$:
        $$ qefr = \text{lstsq}(A, b).\text{solution} $$
    c.  If all normals are degenerate (`cndt` all true), use `cntr` as the solution [S1, unofficial].

5.  **Clamp to Boundary**:
    a.  Compute ray direction $ctoq = qefr - cpnt$ and length $leng$.
    b.  Compute intersection parameter $t$ with constraint planes defined by `cstrtab`.
    c.  Concatenate boundary parameters $(1-cpnt)/ctoq$ and $-cpnt/ctoq$ with $t$.
    d.  Handle NaNs and negative values by setting $t$ to $leng + SEP$.
    e.  Normalize by $leng$ and clamp to $[0, 1]$.
    f.  Final vertex:
        $$ v = cpnt + t \cdot ctoq $$
    [S1, unofficial]

### Edge Cases and Pitfalls
*   **Degenerate Normals**: If all edge vectors in the QEF computation are zero-length (degenerate cube), the normal computation fails. The algorithm checks `cndt` and falls back to the centroid `cntr` [S1, unofficial].
*   **NaNs in Intersection**: If the ray direction `ctoq` is zero or parallel to constraint planes, `t` may become NaN. These are handled by setting `t` to `leng + SEP` and clamping [S1, unofficial].
*   **Ambiguity Consistency**: The ambiguity correction (`val_ = 15 - val_`) ensures that adjacent voxels resolve the same topological ambiguity consistently, preventing cracks [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A variant that uses the Quadric Error Metric (QEM) instead of full QEF minimization for vertex relocation during mesh generation [S2, unofficial]. Unlike pseudoinverse QEF minimization, which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial]. It is chosen when computational complexity and register usage are critical constraints, such as on GPUs, and when exact geometric quality is secondary to volume preservation [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of voxels. The majority of voxels (Group A) are processed in $O(1)$ using 2D search. Ambiguous voxels (Group B) require solving a small least-squares system, which is constant time per vertex but with a higher constant factor [S1, unofficial].
*   **Memory Complexity**: $O(N)$ for storing vertex positions and precomputed tables. The QEF solve requires temporary storage for matrices $A$ and $b$, which is small and constant per voxel [S1, unofficial].
*   **Performance**: The method is faster than full QEF for all vertices because it restricts the expensive QEF solve to ambiguous cases [S1, unofficial]. QEM-based variants offer further performance gains on parallel hardware by reducing register pressure [S2, unofficial].
*   **Strengths**: Produces watertight meshes, resolves topological ambiguities correctly, and maintains high performance by limiting QEF usage [S1, unofficial].
*   **Limitations**: More complex to implement than standard Marching Cubes. The QEF solve can be numerically unstable if not properly regularized [S1, unofficial].

## Background
The method originates from the Open Data Cube (ODC) project, specifically the KAIST Visual AI Group's implementation [S1, unofficial]. It was developed to efficiently extract surfaces from large voxel grids while maintaining topological correctness. The QEM-based variant was introduced to address performance bottlenecks on parallel hardware, such as GPUs, by reducing the computational complexity of vertex optimization [S2, unofficial].
