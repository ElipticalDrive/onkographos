# Cluster Connection Tree Table

Also called: Cluster linkage table, Tree table

## Overview
The Cluster Connection Tree Table is a data structure used in convex contouring to summarize the topological connections between clusters of isosurface points across adjacent slices [S1]. It serves as the bridge between 2D slice processing and 3D surface construction, explicitly tracking which clusters in slice $i$ connect to which clusters in slice $i+1$ [S1]. Unlike methods that infer connectivity implicitly, this table stores explicit bidirectional links (Head and Tail IDs) and a correlation metric, enabling the construction of topologically consistent surfaces with local convexity properties [S1]. It distinguishes itself by handling non-convex objects through multiple connection handling, where branching and merging are decomposed into 1:1 connections to prevent surface smoothing or duplication [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A sequence of 2D slices containing clusters of isosurface points. Each cluster is defined by a set of points $\tilde{t}$ and associated probability density function (PDF) values $p$.
*   **Output:** A Tree Table where each row represents a cluster and its connections to adjacent slices.

**Data Structures**
The Tree Table is a list of rows. Each row contains the following fields:
1.  **CID (Cluster ID):** Unique identifier for the cluster in the current slice.
2.  **SNO (Slice Number):** The index of the current slice.
3.  **HID (Head Cluster ID):** The ID of the cluster in the previous slice ($i-1$) that connects to this cluster. If no connection exists (start of a local convexity), this is 'x'.
4.  **TID (Tail Cluster ID):** The ID of the cluster in the next slice ($i+1$) that this cluster connects to. If no connection exists (end of a local convexity), this is 'x'.
5.  **Cr (Correlation Coefficient):** A scalar value representing the similarity between the current cluster and its Tail cluster.

**Algorithm Steps**
1.  **Cluster Identification:** For each slice $i$, identify disjoint clusters of isosurface points. Assign a unique CID to each cluster.
2.  **Connection Decision:** For each cluster $cid$ in slice $i$, determine its connection to clusters in slice $i+1$. The decision function $e(cid, i)$ selects the cluster $c_j$ in slice $i+1$ that maximizes the expected overlap:
    $$ e(cid, i) = \max_{j} \left\{ \sum_{\tilde{t} \in cid} p_{i+1}(\tilde{t}|c_j) P_{i+1}(c_j) \right\} $$
    where $p_{i+1}(\tilde{t}|c_j)$ is the PDF value at point $\tilde{t}$ for cluster $c_j$ in slice $i+1$, and $P_{i+1}(c_j)$ is a normalization factor for that cluster [S1]. The result of this maximization determines the TID for $cid$.
3.  **Similarity Calculation:** Calculate the correlation coefficient $g(c_m, c_n)$ between a cluster $c_m$ in slice $i$ and its corresponding Tail cluster $c_n$ (TID) in slice $i+1$. This metric estimates shape similarity:
    $$ g(c_m, c_n) = \frac{\sum_i (p_i(\tilde{t}_i|c_m) p_{i+1}(\tilde{t}_i|c_n))^2}{\sqrt{\sum_i p_i(\tilde{t}_i|c_m)^2 \sum_i p_{i+1}(\tilde{t}_i|c_n)^2}} $$
    where $\tilde{t}_i$ are the points in cluster $c_m$ [S1].
4.  **Table Population:**
    *   Set `TID` for cluster $cid$ to the ID of the cluster identified in Step 2.
    *   Set `Cr` for cluster $cid$ to the value $g(c_m, c_n)$ calculated in Step 3.
    *   If a cluster has multiple tails (multiple connections to the next slice), compute an average Cr value [S1].
    *   Set `HID` for the Tail cluster in slice $i+1$ to the CID of the current cluster.
    *   If a cluster has no connection to the previous slice, set `HID` to 'x'.
    *   If a cluster has no connection to the next slice, set `TID` to 'x'.
5.  **Validation:** Ensure no cluster has both `HID` = 'x' and `TID` = 'x'. Such a state implies an unattached cluster, which is assumed not to exist in a valid object [S1].

**Pseudocode**
```python
def build_tree_table(slices):
    """
    slices: List of objects, where slices[i] contains a list of clusters.
    Each cluster has:
      - id: int
      - points: list of (x, y, z)
      - pdf_values: list of floats corresponding to points
    """
    tree_table = []
    prev_slice_clusters = []
    
    for i, current_slice in enumerate(slices):
        current_clusters = current_slice.clusters
        next_slice_clusters = slices[i+1].clusters if i < len(slices) - 1 else None
        
        # Map CID to its connection info
        cluster_connections = {}
        
        for cid, cluster in current_clusters:
            # Step 2: Find best connection in next slice
            best_tcid = None
            best_score = -infinity
            
            if next_slice_clusters:
                for tcid, tcluster in next_slice_clusters:
                    # Calculate score based on PDF overlap
                    score = 0.0
                    for pt, pdf_val in zip(cluster.points, cluster.pdf_values):
                        # Find PDF value of this point in the target cluster
                        # Assuming a lookup or interpolation function exists for the grid
                        target_pdf = get_pdf_at_point(pt, tcluster) 
                        score += target_pdf * pdf_val
                    
                    if score > best_score:
                        best_score = score
                        best_tcid = tcid
            
            # Step 3: Calculate similarity (Cr)
            cr_value = 0.0
            if best_tcid is not None:
                tcluster = get_cluster_by_id(next_slice_clusters, best_tcid)
                cr_value = calculate_correlation(cluster, tcluster)
            
            # Determine HID from previous slice's records
            # This requires looking up if any cluster in prev_slice pointed to this CID
            hid = 'x'
            for prev_cid, prev_info in prev_slice_clusters.items():
                if prev_info['tid'] == cid:
                    hid = prev_cid
                    break
            
            cluster_connections[cid] = {
                'cid': cid,
                'sno': i,
                'hid': hid,
                'tid': best_tcid if best_tcid is not None else 'x',
                'cr': cr_value
            }
            
            # Add to table
            tree_table.append(cluster_connections[cid])
        
        # Prepare for next iteration
        prev_slice_clusters = cluster_connections

    return tree_table

def calculate_correlation(cluster_m, cluster_n):
    """
    Calculates g(cm, cn) as defined in the source.
    """
    numerator = 0.0
    denom_m = 0.0
    denom_n = 0.0
    
    # Iterate over points in cluster_m
    for pt, pdf_m in zip(cluster_m.points, cluster_m.pdf_values):
        pdf_n = get_pdf_at_point(pt, cluster_n)
        numerator += (pdf_m * pdf_n) ** 2
        denom_m += pdf_m ** 2
        denom_n += pdf_n ** 2
        
    if denom_m == 0 or denom_n == 0:
        return 0.0
        
    return numerator / (math.sqrt(denom_m) * math.sqrt(denom_n))
```

**Parameters**
*   **Slice Spacing:** The method assumes slices are reasonably small to ensure local convexity [S1].
*   **PDF Values:** The method relies on probability density function values associated with each point in the volumetric data [S1].

**Edge Cases and Pitfalls**
*   **Unattached Clusters:** A cluster must not have both `HID` and `TID` as 'x'. This indicates a disconnected component which violates the assumption of a single attached object [S1].
*   **Multiple Connections:** Non-convex objects may result in multiple `HID`s or `TID`s for a single cluster. The table structure supports this by storing one row per connection or handling multiple tails via average Cr [S1].
*   **Precision:** The correlation coefficient calculation involves squared terms, which may lead to numerical instability if PDF values are very small or very large. Normalization factors $P_{i+1}(c_j)$ are required for the decision function [S1].

Constructs surfaces from local convexities (two connected clusters in different slices). Handles non-convex objects by dividing branching/merging connections into 1:1 connections to avoid surface smoothing or duplication.

## Operating characteristics
*   **Time Complexity:** The connection decision step requires comparing every cluster in slice $i$ with every cluster in slice $i+1$, leading to $O(N_i \times N_{i+1})$ comparisons per slice pair, where $N$ is the number of clusters. The correlation calculation adds overhead proportional to the number of points in the clusters.
*   **Memory Complexity:** The Tree Table size is proportional to the number of clusters across all slices. Each cluster stores a constant number of fields (CID, SNO, HID, TID, Cr).
*   **Strengths:** Provides explicit topological information, enabling robust handling of non-convex shapes and complex branching structures. The correlation metric helps in selecting the most shape-consistent connections.
*   **Limitations:** Requires pre-computed PDF values or a method to evaluate them at arbitrary points. The assumption of "no unattached clusters" may fail for noisy data or fragmented objects.
*   **When to Use:** Suitable for convex contouring methods where topological consistency and local convexity are required, especially for non-convex objects.
*   **When Not to Use:** Not suitable for methods that do not rely on slice-based clustering or explicit tree structures.

## Background
The Cluster Connection Tree Table was introduced in the context of local hull-based surface construction of volumetric data from silhouettes [S1]. It is part of a broader family of convex contouring methods that use decision trees to manage the complexity of isosurface extraction. The method addresses the challenge of maintaining topological consistency when dealing with non-convex objects by explicitly tracking cluster connections across slices [S1].
