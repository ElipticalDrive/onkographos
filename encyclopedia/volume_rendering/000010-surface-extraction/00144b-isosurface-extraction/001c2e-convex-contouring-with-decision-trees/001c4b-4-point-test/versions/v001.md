# 4-point test
## Overview
The 4-point test is a geometric filtering method used in convex contouring to identify which triangles from a set of candidate triangulations belong to the convex contour of volumetric data [S1]. It solves the ambiguity of surface configuration by enforcing the convex hull property, ensuring that all edge intersections and negative corners lie on one side of any triangle in the contour [S1]. It distinguishes itself from sibling methods like [Multi-resolution Convex Contouring](1287-multi-resolution-convex-contouring.md) by operating as a local geometric predicate on edge intersections rather than a hierarchical data structure strategy [S1].
## How it works
**Inputs:** Four distinct edge intersection points $V_1, V_2, V_3, V_4$ in 3D space.
**Outputs:** A set of ruled-out triangles from the candidate set $S$.

The method relies on the assumption that triangles on the convex contour face inside the convex hull of the negative space [S1]. The test determines the orientation of $V_4$ relative to the triangle formed by $V_1, V_2, V_3$.

**Data Structures:**
*   Points $V_i$ are 3D coordinates $(x_i, y_i, z_i)$.
*   The "front-facing side" of a triangle $(A, B, C)$ is determined by the sign of the scalar triple product (or the dot product of the normal with the vector to the test point).

**Formulas:**
Let $N$ be the normal vector of triangle $(V_1, V_2, V_3)$:
$$ N = (V_2 - V_1) \times (V_3 - V_1) $$
Let $D$ be the signed distance (or projection) of $V_4$ onto this normal:
$$ D = N \cdot (V_4 - V_1) $$

**Steps:**
1.  Calculate $N$ and $D$ as defined above.
2.  Check the sign of $D$:
    *   If $D > 0$ (or $D \ge 0$ depending on convention, but strictly "front-facing" implies a specific side), $V_4$ lies on the front-facing side of $(V_1, V_2, V_3)$.
    *   If $D < 0$, $V_4$ does not lie on the front-facing side.
3.  Rule out triangles based on the result:
    *   **Case A ($V_4$ is front-facing):** Rule out the inverted triangle $(V_1, V_3, V_2)$ and the triangles $(V_1, V_2, V_4)$, $(V_2, V_3, V_4)$, and $(V_3, V_1, V_4)$ [S1].
    *   **Case B ($V_4$ is not front-facing):** Rule out the triangle $(V_1, V_2, V_3)$ and the triangles $(V_1, V_4, V_2)$, $(V_2, V_4, V_3)$, and $(V_1, V_3, V_4)$ [S1].
4.  **Edge Case:** If all four vertices lie on the same plane ($D = 0$), either choice of ruling out triangles can be made [S1].

**Pseudocode:**
```python
def cross_product(a, b):
    return [
        a[1]*b[2] - a[2]*b[1],
        a[2]*b[0] - a[0]*b[2],
        a[0]*b[1] - a[1]*b[0]
    ]

def dot_product(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def subtract(a, b):
    return [a[0]-b[0], a[1]-b[1], a[2]-b[2]]

def four_point_test(V1, V2, V3, V4):
    # Calculate normal of triangle (V1, V2, V3)
    edge1 = subtract(V2, V1)
    edge2 = subtract(V3, V1)
    normal = cross_product(edge1, edge2)
    
    # Calculate vector from V1 to V4
    vec_v1_v4 = subtract(V4, V1)
    
    # Project V4 onto the normal
    distance = dot_product(normal, vec_v1_v4)
    
    ruled_out = []
    
    # Define triangles as tuples of indices/points for clarity
    # Note: The specific triangles ruled out depend on the orientation definition.
    # Based on [S1]:
    
    if distance > 0: # V4 lies on the front-facing side
        # Rule out inverted triangle (V1, V3, V2)
        ruled_out.append((V1, V3, V2))
        # Rule out triangles involving V4 with the base edges
        ruled_out.append((V1, V2, V4))
        ruled_out.append((V2, V3, V4))
        ruled_out.append((V3, V1, V4))
    elif distance < 0: # V4 does not lie on the front-facing side
        # Rule out base triangle (V1, V2, V3)
        ruled_out.append((V1, V2, V3))
        # Rule out alternative triangles involving V4
        ruled_out.append((V1, V4, V2))
        ruled_out.append((V2, V4, V3))
        ruled_out.append((V1, V3, V4))
    else:
        # All vertices lie on the same plane.
        # Either choice can be made. We arbitrarily rule out the first set.
        ruled_out.append((V1, V3, V2))
        ruled_out.append((V1, V2, V4))
        ruled_out.append((V2, V3, V4))
        ruled_out.append((V3, V1, V4))
        
    return ruled_out
```
**Parameters:**
*   None. The test is purely geometric.

**Pitfalls:**
*   **Coplanarity:** If $V_1, V_2, V_3, V_4$ are coplanar, the normal is zero or the distance is zero. The source states either choice can be made, but implementation must handle the zero-distance case explicitly to avoid undefined behavior or incorrect branching [S1].
*   **Precision:** Floating-point errors in the dot product calculation may cause misclassification of points that are theoretically coplanar or on the boundary. A small epsilon tolerance may be required in practice, though not specified in the source [G].
*   **Orientation Consistency:** The definition of "front-facing" must be consistent with the winding order of the triangle vertices $(V_1, V_2, V_3)$. The source assumes a specific orientation where the normal points towards the "front" [S1].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per test, involving a constant number of vector operations (cross product, dot product).
*   **Memory Complexity:** $O(1)$.
*   **Performance:** The test is designed for speed to allow the construction of decision trees that distinguish triangulations with a minimal set of tests [S1].
*   **Strengths:** It efficiently reduces the search space of possible triangulations by enforcing the convex hull property locally [S1].
*   **Limitations:** It only rules out specific triangles; the correct triangulation is found by applying a sequence of such tests (via a decision tree) until a unique solution remains [S1].
*   **When to use:** When implementing convex contouring for isosurface extraction where topological consistency and convexity of the negative space are required [S1].
## Background
The 4-point test was introduced in the context of convex contouring of volumetric data [S1]. It is part of a table-driven contouring method that produces topologically consistent surfaces with a local convexity property [S1]. The method differentiates the correct triangulation from others by looking at edge intersections and ensuring they satisfy the convex hull property [S1].
