# Pre-triangulation of Convex Contour

## Overview
Pre-triangulation of Convex Contour is a process to identify triangles that will not appear on the convex contour during lookup table construction based on sign configuration, reducing the set of possible triangulations [S1]. It solves the combinatorial explosion of possible surface configurations by applying geometric constraints derived from the convex hull property [S1]. Unlike the [4-point test](1224-4-point-test.md), which selects among remaining candidates at runtime, this method statically prunes the search space during table generation based solely on the sign configuration of the cell corners [S1].

## How it works
The method identifies triangles that are geometrically impossible to lie on the convex hull of the negative space [S1]. It relies on the observation that for a triangle on the convex contour, the half-space on its front-facing side must contain (or partially contain) every other cell edge exhibiting a sign change [S1].

**Inputs and Outputs:**
- **Input:** A cell sign configuration (binary mask of 8 corners) and a candidate triangle defined by vertices on three distinct cell edges [S1].
- **Output:** A boolean flag indicating whether the candidate triangle is ruled out from the convex contour [S1].

**Data Structures:**
- **Cell Corners ($C_i$):** The 8 vertices of the voxel, indexed $i=1 \dots 8$ [S1].
- **Cell Edges:** Defined by pairs of corners. A sign change occurs on an edge if the scalar values at its endpoints have different signs relative to the isovalue [S1].
- **Border Triangles:** Triangles formed by selecting one endpoint from each of three distinct cell edges in order [S1].

**Steps:**
1. **Identify Intersecting Edges:** Determine all cell edges that exhibit a sign change [S1].
2. **Select Candidate Triangles:** Consider a triangle $T$ formed by three vertices $v_1, v_2, v_3$, where each $v_j$ lies on a distinct intersecting edge $E_{a}, E_{b}, E_{c}$ [S1].
3. **Construct Border Triangles:** For the three edges $E_a=(C_1, C_2)$, $E_b=(C_3, C_4)$, and $E_c=(C_5, C_6)$, construct the border triangle by taking the endpoints of these edges in order, such as $(C_1, C_3, C_5)$ [S1].
4. **Check Back-Facing Condition:** Check if any other intersecting edge $E_{other}$ (distinct from the three defining $T$) lies completely to the back of the border triangle [S1].
5. **Prune:** If such an edge $E_{other}$ exists, then any triangle $T$ whose vertices belong to the three defining edges is ruled out from the convex contour [S1]. If the edge lies partially to the front of at least one border triangle, the triangle may exist in the triangulation and is not ruled out [S1].

**Formulas:**
Let $P$ be the plane defined by a border triangle with vertices $A, B, C$. The plane equation is:
$$ \mathbf{n} \cdot (\mathbf{x} - \mathbf{A}) = 0 $$
where $\mathbf{n} = (\mathbf{B} - \mathbf{A}) \times (\mathbf{C} - \mathbf{A})$ [S1].
An edge defined by endpoints $\mathbf{U}$ and $\mathbf{V}$ lies completely to the back of $P$ if:
$$ \mathbf{n} \cdot (\mathbf{U} - \mathbf{A}) < 0 \quad \text{and} \quad \mathbf{n} \cdot (\mathbf{V} - \mathbf{A}) < 0 $$
[S1]. (Note: Strict inequality assumes non-degenerate triangles and general position.)

**Parameters:**
- **Isovalue:** Implicitly handled by the sign configuration [S1].
- **Convex Hull Property:** The fundamental constraint ensuring the front-facing half-space contains other sign-changing edges [S1].

**Edge Cases and Pitfalls:**
- **Degenerate Border Triangles:** If three selected endpoints are collinear or coplanar in a way that forms a zero-area triangle, the border triangle is degenerate and ignored in the back-facing check [S1].
- **Partial Front-Facing:** If an intersecting edge lies partially to the front of at least one border triangle, the triangle is not ruled out [S1].
- **Precision:** Floating-point comparisons for "back" vs "front" must handle near-zero values carefully to avoid incorrect pruning due to numerical noise [G].

**Pseudocode:**
```python
def is_triangle_ruled_out(cell_corners, edge_intersections, triangle_vertices):
    """
    Check if a triangle defined by triangle_vertices is ruled out by pre-triangulation.
    
    Args:
        cell_corners: List of 8 3D vectors for voxel corners.
        edge_intersections: List of edges (pairs of corner indices) that have sign changes.
        triangle_vertices: List of 3 corner indices forming the candidate triangle.
        
    Returns:
        True if the triangle is ruled out, False otherwise.
    """
    # Identify the three edges that the triangle vertices lie on
    tri_edge_indices = []
    for v in triangle_vertices:
        edge_idx = None
        for i, edge in enumerate(edge_intersections):
            if v in edge:
                edge_idx = i
                break
        if edge_idx is None:
            return False # Vertex not on an intersecting edge, invalid input
        tri_edge_indices.append(edge_idx)
    
    # Get the three edges
    e1 = edge_intersections[tri_edge_indices[0]]
    e2 = edge_intersections[tri_edge_indices[1]]
    e3 = edge_intersections[tri_edge_indices[2]]
    
    # Construct the border triangle by taking one endpoint of each edge in order
    c1, c2, c3 = e1[0], e2[0], e3[0]
    
    # Check if any other intersecting edge lies completely to the back of the border triangle
    for other_edge_idx, other_edge in enumerate(edge_intersections):
        if other_edge_idx in tri_edge_indices:
            continue # Skip the edges defining the triangle
        
        # Calculate normal of the border triangle
        v1 = cell_corners[c2] - cell_corners[c1]
        v2 = cell_corners[c3] - cell_corners[c1]
        normal = cross(v1, v2)
        
        # Check both endpoints of the other edge
        u = cell_corners[other_edge[0]]
        v = cell_corners[other_edge[1]]
        
        # Check if both are strictly on the back side
        if dot(normal, u - cell_corners[c1]) >= 0 or dot(normal, v - cell_corners[c1]) >= 0:
            continue # Edge is not completely to the back
        
        # If we reach here, the edge is completely to the back
        return True # Triangle is ruled out
            
    return False
```

## Subtopics

### [Decision tree for triangulation](1356-decision-tree-for-triangulation.md)
A pre-computed structure used to distinguish the correct triangulation from all possible triangulations in set $S$ by performing a minimal set of 4-point tests. It builds on [Pre-triangulation of Convex Contour](1226-pre-triangulation-of-convex-contour.md) by resolving the remaining ambiguity in the convex contour patches. Unlike [Marching Cubes](52-marching-cubes.md), which relies on a static lookup table for all cases, this method uses a dynamic traversal of a decision tree to select the triangulation that ensures the resulting surface is manifold and crack-less.

## Operating characteristics
Pre-triangulation is performed offline during table construction [S1]. It reduces the number of possible triangulations that need to be considered at runtime [S1]. The method only applies to convex contouring and requires careful handling of degenerate cases [S1]. Exact time and memory complexity, measured performance, and scaling behavior are not given in the sources.

## Background
The method was introduced in the context of convex contouring of volumetric data [S1]. It addresses the issue that brute-force enumeration of triangulations for patches with complex topologies results in a large number of redundant configurations that never appear on the convex hull [S1]. By leveraging the spatial restrictions of edge intersections, the method prunes these invalid configurations during table construction [S1]. This approach ensures that the resulting surface respects the convex hull property, avoiding artifacts that can arise from arbitrary triangulations [S1].
