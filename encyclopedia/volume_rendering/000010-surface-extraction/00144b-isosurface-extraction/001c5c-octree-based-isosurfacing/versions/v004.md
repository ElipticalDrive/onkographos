# Octree-based Isosurfacing

Also called: Contouring using Octrees, Isosurfacing with Octree discretization

## Overview
Octree-based isosurfacing replaces the uniform Cartesian grid with an adaptive octree spatial discretization to extract isosurfaces from volumetric data [S1]. It sets itself apart from standard grid-based methods like [Marching Cubes](30-isosurface-extraction.md) by allowing variable resolution, but it loses the topological guarantees of uniform grids, potentially causing cracks if the octree is not sufficiently adapted to the surface geometry [S1].

## How it works
**Inputs:**
1.  A bounding box defined by minimum and maximum corner points ($P_{min}, P_{max}$).
2.  A split predicate function (refinement criterion) that determines which octree nodes to subdivide.
3.  A scalar value function $V(P)$ that returns the scalar value at any point $P$.
4.  A gradient function $G(P)$ that returns the gradient vector at any point $P$ (required for Dual Contouring; optional for Marching Cubes if normals are approximated).
5.  An isovalue threshold $T$.

**Outputs:**
1.  A set of vertices $Points$.
2.  A set of triangles $Triangles$ (or polylines/edges depending on the specific algorithm variant).

**Data Structures:**
*   **Octree:** A hierarchical spatial partitioning structure. Each node represents a cubic region. Nodes are refined (split into 8 children) if the split predicate returns true.
*   **Value Function:** A callable object bound to the octree, evaluating $V(P)$ at query points.
*   **Gradient Function:** A callable object bound to the octree, evaluating $G(P)$ at query points.
*   **Domain Object:** An abstraction encapsulating the octree, value function, and gradient function, providing a uniform interface to the isosurfacing algorithm.

**Steps:**
1.  **Initialize Octree:** Create an octree instance using the bounding box defined by $P_{min}$ and $P_{max}$ [S1].
2.  **Refine Octree:** Apply the split predicate function recursively to the octree. A node is split if the predicate determines that the surface intersects the node's volume or if higher resolution is required [S1].
3.  **Traverse Octree:** Perform a traversal to collect all leaf nodes of the refined octree. This defines the active cells for surface extraction [S1].
4.  **Bind Functions:** Construct the value function and gradient function objects, binding them to the octree structure so they can evaluate data at arbitrary points within the leaf cells [S1].
5.  **Create Domain:** Instantiate the domain object, passing the octree, value function, and gradient function as arguments [S1].
6.  **Extract Surface:** Run the specific isosurfacing algorithm (e.g., Dual Contouring or Marching Cubes) on the domain object with the isovalue $T$ [S1].
    *   For Dual Contouring, parameters such as `do_not_triangulate_faces` (default true in examples) and `constrain_to_cell` (default false) can be passed to control output generation [S1].

**Pseudocode:**
```python
def octree_isosurfacing(bbox_min, bbox_max, split_predicate, value_func, gradient_func, isovalue, algorithm="dual_contouring"):
    # 1. Initialize Octree
    octree = Octree([bbox_min, bbox_max])
    
    # 2. Refine Octree
    octree.refine(split_predicate)
    
    # 3. Traverse Octree to collect leaves (implicit in domain construction for some implementations, 
    # but explicit in CGAL example for debugging/verification)
    # leaf_range = octree.traverse(Leaves_traversal(octree))
    
    # 4. Bind Functions
    # Values and Gradients are callable objects bound to the octree
    values = ValueFunction(value_func, octree)
    gradients = GradientFunction(gradient_func, octree)
    
    # 5. Create Domain
    domain = Domain(octree, values, gradients)
    
    # 6. Extract Surface
    points = []
    triangles = []
    
    if algorithm == "dual_contouring":
        # Run Dual Contouring
        # Parameters: do_not_triangulate_faces=True, constrain_to_cell=False
        dual_contouring(domain, isovalue, points, triangles, 
                        do_not_triangulate_faces=True, 
                        constrain_to_cell=False)
    elif algorithm == "marching_cubes":
        # Run Marching Cubes
        marching_cubes(domain, isovalue, points, triangles)
        
    return points, triangles
```

**Edge Cases and Pitfalls:**
*   **Cracks:** If the octree is not sufficiently adapted to the surface geometry (i.e., adjacent leaf nodes have significantly different depths), cracks may appear in the resulting mesh, particularly with Marching Cubes [S1].
*   **Loss of Guarantees:** Unlike uniform grids, octree-based methods do not inherently guarantee watertightness or manifold topology without additional constraints or post-processing [S1].

## Subtopics

### [Standard Interval Tree for Isosurface Extraction](1230-standard-interval-tree-for-isosurface-extraction.md)
Uses a binary tree of value intervals on a fixed Cartesian grid to identify active cells, decoupling spatial locality from value-based filtering.

### [IsoOctree](1744-isooctree.md)
Operates on arbitrary octrees by computing the Euclidean Distance Transform (EDT) of an input mesh, adapting resolution near the surface for mesh simplification.

### [Wilhelms and Van Gelder Octree](2107-wilhelms-and-van-gelder-octree.md)
Accelerates extraction by pruning octree branches that cannot contain the target isosurface, using stored value intervals for immediate rejection.

### [Ashida and Badla Octree Contouring](2117-ashida-and-badla-octree-contouring.md)
Extracts contours directly from octrees by identifying cycles of contour faces, avoiding uniform grids but potentially producing non-manifold edges.

### [Unconstrained Isosurface Extraction on Arbitrary Octrees](2413-unconstrained-isosurface-extraction-on-arbitrary-octrees.md)
Guarantees watertightness on arbitrary octrees by introducing isovertices on every isovalue-crossing edge and using binary edge-trees to resolve inconsistencies.

### [Consistent Isovertex Definition via Edge-Trees](2427-consistent-isovertex-definition-via-edge-trees.md)
Defines isovertex positions consistently by traversing edge-trees to unique leaves, resolving ambiguity in coarse edges with multiple sign changes.

### [Adaptive Octree Generation with Flatness Criterion](2482-adaptive-octree-generation-with-flatness-criterion.md)
Refines octrees based on geometric flatness of surface intersections, allowing coarser representation of planar regions.

### [Sampled DMC](3813-sampled-dmc.md)
Adapts Dual Marching Cubes to hashed octrees using Morton keys, constructing a dual grid with vertices at octree leaf centers.

### Point-based Isosurface Extraction with Octree Pruning
A view-dependent algorithm that divides the model into grid cells until sub-pixel resolution is achieved, using point primitives to represent smaller triangles [S2, unofficial]. It performs a front-to-back traversal of an octree, applying value-based pruning (discarding nodes with values outside the isosurface limit, requiring min/max storage at nodes) and visibility pruning (discarding nodes whose bounding boxes do not contribute to the final image) [S2, unofficial]. Robust normal positions are computed via a fragment program using world coordinates of the pixel and its neighbors [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the split predicate and the depth of the octree. Traversal is proportional to the number of leaf nodes. Surface extraction is proportional to the number of active cells (leaf nodes).
*   **Memory Complexity:** Proportional to the number of octree nodes. Adaptive resolution can significantly reduce memory usage compared to uniform grids for sparse or complex data.
*   **Strengths:** Adaptive resolution allows high detail where needed and coarser resolution elsewhere, reducing memory and computation for large datasets.
*   **Limitations:** Loss of topological guarantees (watertightness) compared to uniform grids; potential for cracks if refinement is insufficient; complexity in implementing consistent edge handling across different octree depths.
*   **When to use:** When the data has varying levels of detail or when memory constraints prevent the use of a uniform grid at high resolution.
*   **When not to use:** When strict watertightness and manifold topology are required without additional post-processing, or when the data is uniformly dense.

## Background
Octree-based isosurfacing is a technique that leverages hierarchical spatial subdivision to accelerate and optimize surface extraction from volumetric data. It is implemented in libraries such as CGAL, which provides examples for both Dual Contouring and Marching Cubes using octree discretization [S1]. The approach addresses the limitations of uniform grids by allowing adaptive refinement, though it introduces challenges related to mesh coherence at different octree levels [S1].
