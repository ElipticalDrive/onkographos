# Cage-Building Algorithm

Also called: Cage construction, Voxel grid extraction, automated cage-generation algorithm, render-reconstruct-simplify pipeline

## Overview

The Cage-Building Algorithm is an automated pipeline that generates a simple, tight, and artifact-free deformation cage enclosing a 3D Gaussian Splatting (3DGS) scene [S1, unofficial]. It solves the problem of creating a suitable proxy mesh for cage-based deformation by converting the scene into depth maps, reconstructing a solid voxel grid via Truncated Signed Distance Field (TSDF) integration, and simplifying it with a two-stage decimation process that enforces non-negative Mean Value Coordinates (MVCs) [S1, unofficial]. Unlike methods that treat the 3DGS scene directly as an opacity field, this approach extracts underlying geometry through a standardized render-reconstruct-simplify pipeline, making it robust against low-opacity floaters and applicable to both standard and non-volumetric 3DGS variants [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   A trained 3DGS scene $S$ (or its variants).
*   Configuration parameters:
    *   $n_r$: Number of evenly spaced rings for camera placement.
    *   $n_c$: Number of cameras placed per ring.
    *   $s$: Expand factor used to scale the bounding sphere radius.

**Outputs:**
*   A simplified cage mesh $C$ that encloses the scene $S$.

### Data Structures
*   **3DGS Scene $S$**: A collection of 3D Gaussians. Each Gaussian has a mean position $\mathbf{m}_i$ and other attributes (covariance, opacity, spherical harmonics).
*   **Camera Array $A$**: A set of virtual camera poses. Each pose includes position, orientation (look-at direction), and intrinsic parameters (assumed standard for depth rendering).
*   **Depth Maps $D$**: 2D images representing the distance from the camera to the nearest surface point in the scene.
*   **TSDF Volume $F_{tsdf}$**: A 3D voxel grid storing truncated signed distance values.
*   **Voxel Grid $V$**: A binary or occupancy grid representing the solid volume.
*   **Cage Mesh $C$**: A polygonal mesh (vertices and faces).

### Steps

1.  **Compute Expanded Bounding Sphere**
    Calculate the mean position of all Gaussian means in $S$:
    $$ \mathbf{m} = \text{Mean}(\{\mathbf{m}_i \mid \mathbf{m}_i \in S\}) $$
    Calculate the maximum L2 distance from any Gaussian mean to $\mathbf{m}$:
    $$ r_{max} = \max_i \|\mathbf{m}_i - \mathbf{m}\|_2 $$
    Compute the radius $r$ for camera placement:
    $$ r = r_{max} \times s $$

2.  **Generate Camera Array**
    Generate a set of cameras $A$ by placing $n_c$ cameras in $n_r$ evenly spaced rings on a sphere of radius $r$ centered at $\mathbf{m}$. Add cameras at the top and bottom poles of the sphere. Orient all cameras to look toward the center $\mathbf{m}$ [S1, unofficial].

3.  **Render Depth Maps**
    Render depth images $D$ from the 3DGS scene $S$ using the generated cameras $A$. This produces a set of depth maps corresponding to each camera in $A$ [S1, unofficial].

4.  **Reconstruct Voxel Grid**
    *   **TSDF Integration**: Fuse the rendered depth maps $D$ and camera poses $A$ into a 3D volume using Truncated Signed Distance Field (TSDF) integration (e.g., KinectFusion algorithm) to obtain $F_{tsdf}$ [S1, unofficial].
    *   **Surface Extraction**: Extract surface voxels $V_s$ from $F_{tsdf}$ [S1, unofficial].
    *   **Clean Depth Rendering**: Re-render clean depth maps $D_{clean}$ from the T-SDF volume $F_{tsdf}$ using cameras $A$ [S1, unofficial].
    *   **Depth Carving**: Perform depth carving using $D_{clean}$ and $A$ to fill the interior and carve away empty space, yielding interior voxels $V_i$ [S1, unofficial].
    *   **Merge**: Merge $V_s$ and $V_i$ into a single voxel grid $V$ [S1, unofficial].

5.  **Smooth and Simplify**
    *   **Morphological Closing**: Apply a morphological closing operator (dilation followed by erosion) to $V$ to remove noise and details, producing a simplified solid volumetric shape $V_b$ [S1, unofficial].
    *   **Marching Cubes**: Apply the Marching Cubes algorithm to $V_b$ to extract a dense polygonal mesh $C_{raw}$ [S1, unofficial].
    *   **Bilateral Filtering**: Apply bilateral filtering to $C_{raw}$ to obtain a smoothed mesh $C_s$ [S1, unofficial].
    *   **Two-Stage Decimation**: Simplify $C_s$ using a constrained edge-collapse algorithm to produce the final cage $C$ [S1, unofficial].

### Two-Stage Decimation Details

The simplification process alternates between two stages until the vertex count falls below a prescribed threshold [S1, unofficial].

**Stage 1: Constrained QEM Edge Collapse**
*   Collapse edges using a constrained Quadric Error Metric (QEM) approach [S1, unofficial].
*   **Constraint**: Ensure the new vertex does not move to the wrong side of its neighboring faces. Let $v$ be the new vertex and $f$ be a neighboring face with outward normal $\mathbf{n}_f$. The constraint ensures the signed distance remains non-negative relative to the face plane [S1, unofficial].

**Stage 2: Refinement with MVC Penalty**
*   Optimize vertex positions to reduce negative Mean Value Coordinate (MVC) weights.
*   Minimize the loss function $L_{MVC}$ using gradient descent for a fixed number of iterations [S1, unofficial]:
    $$ L_{MVC} = L_{MVC\_penalty} + \rho L_{reg} $$
    where $\rho \ge 0$ is a regularization weight that anchors vertices near their pre-refinement positions to stabilize optimization [S1, unofficial].
*   Interleave Stage 1 and Stage 2: Collapse edges in Stage 1, then optimize positions in Stage 2, repeating until the target vertex count is reached [S1, unofficial].

### Pseudocode

```python
def cage_building_algorithm(scene_S, nr, nc, s):
    # Step 1: Compute expanded bounding sphere
    M = [g.mean for g in scene_S.gaussians]
    m = mean(M)
    r_max = max(l2_distance(g.mean, m) for g in M)
    r = r_max * s

    # Step 2: Generate camera array
    A = generate_cameras_on_sphere(center=m, radius=r, num_rings=nr, cameras_per_ring=nc)
    add_pole_cameras(A, center=m)
    for cam in A:
        cam.look_at(m)

    # Step 3: Render depth maps
    D = render_depth(scene_S, A)

    # Step 4: Reconstruct voxel grid
    F_tsdf = tsdf_integration(D, A)
    Vs = extract_surface_voxels(F_tsdf)
    D_clean = render_tsdf(F_tsdf, A)
    Vi = depth_carving(D_clean, A)
    V = merge_voxels(Vs, Vi)

    # Step 5: Smooth and simplify
    Vb = morphological_closing(V)
    Craw = marching_cubes(Vb)
    Cs = bilateral_filter(Craw)
    C = two_stage_decimation(Cs, target_vertex_count)

    return C

def two_stage_decimation(mesh_Cs, target_vertex_count):
    while vertex_count(mesh_Cs) > target_vertex_count:
        # Stage 1: Constrained QEM
        mesh_Cs = constrained_qem_edge_collapse(mesh_Cs)
        
        # Stage 2: MVC Penalty Refinement
        mesh_Cs = optimize_mvc_penalty(mesh_Cs)
        
    return mesh_Cs
```

### Parameters
*   $n_r$: Number of evenly spaced rings for camera placement around the scene.
*   $n_c$: Number of cameras placed per ring.
*   $s$: Expand factor used to scale the bounding sphere radius for camera placement.
*   $\rho$: Regularization weight for MVC penalty optimization (value not specified in sources) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Noise and Floaters**: Rendering depth maps directly from 3DGS without TSDF integration can result in noise on the voxel grid (e.g., on the top of objects) due to low-opacity floaters [S1, unofficial].
*   **Porous Volumes**: Skipping the depth carving/filling step results in a porous and hollow voxel grid, which morphological closing cannot effectively remedy [S1, unofficial].
*   **Negative MVC Weights**: Standard constrained QEM may leave object vertices outside the cage, leading to negative MVC weights and deformation artifacts. The two-stage decimation is specifically designed to mitigate this [S1, unofficial].
*   **Rotation Handling**: The algorithm currently copies spherical harmonics parameters for viewpoint-dependent color without accounting for the effect of rotation during deformation [S1, unofficial].

## Operating characteristics

*   **Time Complexity**: Not given in the sources.
*   **Memory Complexity**: Not given in the sources.
*   **Measured Performance**: On the LEGO scene, the two-stage method made 8.7% of MVC entries non-negative and reduced the magnitude of negative MVC values compared to standard QEM [S1, unofficial].
*   **Scaling**: The method is agnostic to the specifics of the underlying 3DGS representation, making it applicable to both standard 3DGS and non-volumetric variants [S1, unofficial].
*   **Strengths**: Robust geometry extraction; artifact-free deformations due to non-negative MVC enforcement; works across various scenes (e.g., vase, LEGO) [S1, unofficial].
*   **Limitations**: Does not account for rotation in spherical harmonics; point-based deformation is better suited for small deformations like facial expressions [S1, unofficial].

## Background

The Cage-Building Algorithm was introduced in the paper "GSDeformer: Direct Cage-based Deformation for 3D Gaussian Splatting" [S1, unofficial]. It builds on the concept of cage-based deformation, where a proxy mesh (cage) is used to deform a scene. The algorithm addresses the limitations of previous methods that treated 3DGS as an opacity field, which were susceptible to artifacts from low-opacity floaters. By using a render-reconstruct-simplify pipeline with TSDF integration and two-stage decimation, it provides a more robust and artifact-free solution for deforming 3DGS scenes [S1, unofficial].
