# Cuberille

Also called: Opaque Cubes, Voxel Cube Visualization

## Overview
Cuberille is a surface extraction method that visualizes volume data by rendering the individual voxels intersected by an isosurface as opaque cubes [S1, unofficial][S2]. It approximates the continuous surface by the union of the faces of these discrete volume elements [S1, unofficial]. Unlike topologically accurate methods such as [Marching Cubes](30-isosurface-extraction.md) which generate triangular meshes with vertices interpolated along edges, Cuberille produces a blocky, voxel-aligned representation [S1, unofficial]. It is distinguished by its simplicity and speed, trading geometric smoothness for computational efficiency [S1, unofficial].

## How it works
**Inputs:**
*   A 3D volume dataset $V$ consisting of scalar values $v_{ijk}$ at voxel centers or grid points [G].
*   An isovalue threshold $t$ (commonly $t=0$ for signed distance fields or binary segmentation) [S1, unofficial][S2].
*   Voxel dimensions $(dx, dy, dz)$. If the dataset consists of 2D slices where the inter-slice distance differs from the in-plane pixel size, the data must be resampled to ensure cubic voxels ($dx=dy=dz$) [S1, unofficial].

**Outputs:**
*   A quad mesh representing the surface of the object [S2].

**Data Structures:**
*   The input volume is treated as a regular grid [G].
*   The output is a set of polygons (quads) or a mesh structure containing vertices and face indices [S1, unofficial][S2].

**Steps:**
1.  **Preprocessing:** Ensure voxel isotropy. If the distance between slices is larger than the pixel size, resample the data so the gap between slices equals the pixel size [S1, unofficial].
2.  **Segmentation:** Determine which voxels belong to the object. For each voxel, compare its value $v$ against the isovalue $t$ [S1, unofficial][S2]. Voxels with $v < t$ are classified as inside, and voxels with $v \ge t$ are classified as outside [S2]. Identify voxels where the value crosses the threshold, indicating the voxel is part of the surface [S1, unofficial].
3.  **Face Selection:** For each voxel identified as part of the surface, determine which of its 6 faces are exposed to the exterior [S1, unofficial][S2]. A face is selected if it separates a voxel that is inside ($v < t$) from a voxel that is outside ($v \ge t$) [S2].
4.  **Mesh Stitching:** Stitch the selected faces together to form a quad mesh [S2]. In configurations where four faces meet at an edge (ambiguous configuration), the algorithm must decide which pair of faces to stitch together. This is resolved using the asymptotic decider by Nielson and Hamann, originally invented for Marching Cubes [S2].
5.  **Rendering:** Render each polygon in an appropriate color [S1, unofficial]. Gradient shading can be applied to reduce the blocky appearance [S1, unofficial].

**Pseudocode:**
```python
def cuberille(volume, isovalue, voxel_size=(1.0, 1.0, 1.0)):
    """
    volume: 3D array of scalar values
    isovalue: threshold t
    voxel_size: (dx, dy, dz)
    Returns: list of quads (each quad is a list of 4 vertices in world coordinates)
    """
    quads = []
    X, Y, Z = volume.shape
    dx, dy, dz = voxel_size
    for x in range(X):
        for y in range(Y):
            for z in range(Z):
                val = volume[x, y, z]
                if val >= isovalue:
                    continue  # Outside voxel, skip
                # Inside voxel, check 6 neighbors to find exposed faces
                # +X face
                if x + 1 >= X or volume[x + 1, y, z] >= isovalue:
                    quads.append(make_quad(x + 1, y, z, dx, dy, dz))
                # -X face
                if x - 1 < 0 or volume[x - 1, y, z] >= isovalue:
                    quads.append(make_quad(x, y, z, dx, dy, dz, axis=0, neg=True))
                # +Y face
                if y + 1 >= Y or volume[x, y + 1, z] >= isovalue:
                    quads.append(make_quad(x, y + 1, z, dx, dy, dz, axis=1))
                # -Y face
                if y - 1 < 0 or volume[x, y - 1, z] >= isovalue:
                    quads.append(make_quad(x, y, z, dx, dy, dz, axis=1, neg=True))
                # +Z face
                if z + 1 >= Z or volume[x, y, z + 1] >= isovalue:
                    quads.append(make_quad(x, y, z + 1, dx, dy, dz, axis=2))
                # -Z face
                if z - 1 < 0 or volume[x, y, z - 1] >= isovalue:
                    quads.append(make_quad(x, y, z, dx, dy, dz, axis=2, neg=True))
    return quads

def make_quad(ix, iy, iz, dx, dy, dz, axis=0, neg=False):
    """Generate a quad at the boundary of voxel (ix, iy, iz)."""
    bx, by, bz = ix * dx, iy * dy, iz * dz
    if axis == 0:  # X-face
        vx = bx if neg else bx + dx
        verts = [(vx, by, bz), (vx, by + dy, bz), (vx, by + dy, bz + dz), (vx, by, bz + dz)]
    elif axis == 1:  # Y-face
        vy = by if neg else by + dy
        verts = [(bx, vy, bz), (bx + dx, vy, bz), (bx + dx, vy, bz + dz), (bx, vy, bz + dz)]
    else:  # Z-face
        vz = bz if neg else bz + dz
        verts = [(bx, by, vz), (bx + dx, by, vz), (bx + dx, by + dy, vz), (bx, by + dy, vz)]
    return verts
```
*Note: The pseudocode outputs a list of quads. Standard mesh construction merges adjacent quads sharing edges. Ambiguous configurations where four faces meet at an edge are resolved using the asymptotic decider by Nielson and Hamann [S2].*

**Parameters:**
*   **Isovalue ($t$):** The threshold for segmentation. Typical value is 0 for signed distance fields [S2].
*   **Voxel Size:** Must be cubic ($dx=dy=dz$) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Jagged Appearance:** The final image may look jaggy due to the discrete nature of the voxels, especially if the dataset has few cells [S1, unofficial].
*   **Small Features:** The algorithm is fundamentally bad at showing small features [S1, unofficial].
*   **Ambiguous Configurations:** When four faces meet at an edge, stitching is ambiguous. This is resolved using the asymptotic decider by Nielson and Hamann [S2].
*   **Non-Cubic Voxels:** If the distance between slices is larger than the pixel size, the result will be distorted. Resampling is required [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The first stage (finding and rendering the surface) is parallelizable at the cell level [S1, unofficial]. The algorithm is fast and straightforward to implement [S1, unofficial].
*   **Memory Complexity:** Depends on the number of surface voxels [G].
*   **Performance:** Finding and rendering the surface is fast [S1, unofficial].
*   **Strengths:** Simplicity, speed, parallelizability [S1, unofficial].
*   **Limitations:** Blocky appearance, poor representation of small features, jaggy edges [S1, unofficial].
*   **When to use:** When speed is critical and geometric smoothness is not required, or for initial visualization of voxel data [S1, unofficial].

## Background
Cuberille was one of the first widely used methods for visualizing volume data [S1, unofficial]. It was first proposed in [32] (referenced in [S1, unofficial]). The basic notion is to draw each voxel as a small cube [S2]. It is conceptually similar to Dual Contouring (originally called Surface Nets by Sarah Frisken) in that it places geometry around the grid nodes/voxels, but Cuberille uses the voxel centers as the basis for the cubes [S2].
