# Connected Component Labeling via Union-Find

Also called: Union-Find Connected Component Labeling

## Overview
This method groups same-color pixels into connected components using a Union-Find data structure, where connectivity is defined by a Chebyshev (chessboard) distance search radius [S1, unofficial]. It differs from standard 4- or 8-connectivity approaches by allowing configurable neighborhood ranges, making it suitable for identifying distinct color regions in raster images prior to 3D manufacturing format generation [S1, unofficial].

## How it works
**Inputs:** An input image (e.g., PNG) with pixel data containing RGBA values.
**Outputs:** A list of `Component` objects, each containing a `Color` and a list of pixel coordinates `(X, Y)`.

**Data Structures:**
1.  **Parent Array:** `int[] parent` of size `totalPixels = width * height`.
2.  **Rank Array:** `int[] rank` of size `totalPixels`.
3.  **Component Class:**
    *   `Color Color` (readonly)
    *   `List<(int X, int Y)> Pixels` (mutable list of pixel coordinates)

**Parameters:**
*   `searchRadius`: Maximum Chebyshev distance in pixels to search for same-color neighbors. Default value is 4. A radius of 1 is equivalent to 8-connectivity [S1, unofficial].

**Algorithm Steps:**

1.  **Initialize Union-Find:**
    Create `parent` and `rank` arrays of size `totalPixels`. Set `parent[i] = i` for all `i` in `[0, totalPixels)`. Set `rank[i] = 0` [S1, unofficial].

2.  **Precompute Neighbor Offsets:**
    Create a list of `(dx, dy)` tuples. Iterate `dy` from `-searchRadius` to `0`. For each `dy`, iterate `dx` from `-searchRadius` to `searchRadius`.
    *   Constraint: If `dy == 0`, only include offsets where `dx <= -1`.
    *   This covers previously visited pixels in raster scan order (y ascending, x ascending) within the Chebyshev distance [S1, unofficial].

3.  **Union Phase (Raster Scan):**
    Iterate pixels in raster order: `y` from `0` to `height-1`, `x` from `0` to `width-1`.
    *   Calculate `currentIndex = y * width + x`.
    *   Skip if `alpha < 255` [S1, unofficial].
    *   For each neighbor offset `(dx, dy)` in precomputed list:
        *   Calculate `nx = x + dx`, `ny = y + dy`.
        *   Skip if `(nx, ny)` is out of bounds.
        *   Skip if neighbor `alpha < 255`.
        *   If neighbor `RGB` values equal current pixel `RGB` values:
            *   Call `Union(parent, rank, currentIndex, ny * width + nx)` [S1, unofficial].

4.  **Collection Phase:**
    Create a dictionary `rootMap` mapping `root index` to `Component` object.
    Iterate pixels in raster order again: `y` from `0` to `height-1`, `x` from `0` to `width-1`.
    *   Calculate `currentIndex = y * width + x`.
    *   Skip if `alpha < 255` [S1, unofficial].
    *   Find `root = FindRoot(parent, currentIndex)`.
    *   If `root` not in `rootMap`:
        *   Create new `Component` with `Color` from current pixel.
        *   Add to `rootMap`.
    *   Add `(x, y)` to `component.Pixels` [S1, unofficial].

**Pseudocode:**

```python
def connected_component_labeling(image, search_radius=4):
    width = image.width
    height = image.height
    total_pixels = width * height
    
    # Step 1: Initialize Union-Find
    parent = list(range(total_pixels))
    rank = [0] * total_pixels
    
    # Helper: Find with path compression
    def find_root(i):
        if parent[i] != i:
            parent[i] = find_root(parent[i])
        return parent[i]
    
    # Helper: Union by rank
    def union(i, j):
        root_i = find_root(i)
        root_j = find_root(j)
        if root_i != root_j:
            if rank[root_i] < rank[root_j]:
                parent[root_i] = root_j
            elif rank[root_i] > rank[root_j]:
                parent[root_j] = root_i
            else:
                parent[root_j] = root_i
                rank[root_i] += 1

    # Step 2: Precompute neighbor offsets
    offsets = []
    for dy in range(-search_radius, 1):
        for dx in range(-search_radius, search_radius + 1):
            if dy == 0 and dx >= 0:
                continue
            offsets.append((dx, dy))
            
    # Step 3: Union Phase
    for y in range(height):
        for x in range(width):
            current_idx = y * width + x
            current_color = image.get_pixel(x, y)
            
            # Skip non-opaque pixels
            if current_color.alpha < 255:
                continue
                
            for dx, dy in offsets:
                nx, ny = x + dx, y + dy
                if 0 <= nx < width and 0 <= ny < height:
                    neighbor_idx = ny * width + nx
                    neighbor_color = image.get_pixel(nx, ny)
                    
                    # Skip non-opaque neighbors
                    if neighbor_color.alpha < 255:
                        continue
                        
                    # Check color match (RGB only, ignoring alpha as it's checked)
                    if current_color.rgb == neighbor_color.rgb:
                        union(current_idx, neighbor_idx)
                        
    # Step 4: Collection Phase
    components = {}
    
    for y in range(height):
        for x in range(width):
            current_idx = y * width + x
            current_color = image.get_pixel(x, y)
            
            # Skip non-opaque pixels
            if current_color.alpha < 255:
                continue
                
            root = find_root(current_idx)
            
            if root not in components:
                components[root] = Component(color=current_color.rgb)
                
            components[root].pixels.append((x, y))
            
    return list(components.values())

class Component:
    def __init__(self, color):
        self.color = color
        self.pixels = []
```

**Edge Cases and Pitfalls:**
*   Non-opaque pixels (`alpha < 255`) must be skipped during both the union phase and the collection phase to avoid including transparent background pixels in components [S1, unofficial].
*   The neighbor offset generation must strictly follow the raster scan order constraint (only checking `dy <= 0` and `dx < 0` when `dy=0`) to ensure each connection is processed exactly once without redundant checks [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Approximately $O(N \alpha(N))$ where $N$ is the number of pixels and $\alpha$ is the inverse Ackermann function, due to Union-Find operations. The neighbor check adds a factor proportional to the search radius squared.
*   **Memory Complexity:** $O(N)$ for parent and rank arrays, plus $O(N)$ to store pixel coordinates in components.
*   **Strengths:** Configurable connectivity allows handling of larger gaps or specific neighborhood shapes. Efficient for large images due to near-linear time complexity.
*   **Limitations:** Requires storing all pixel coordinates for output, which can be memory-intensive for high-resolution images with many small components.
*   **When to use:** When distinct color regions need to be identified with a specific neighborhood definition, particularly for preparing 2D images for 3D manufacturing formats [S1, unofficial].

## Background
This method is implemented in the `jsonger/voxelizer` project, which parses images and outputs 3D Manufacturing Format (3MF) files compatible with Bambu Studio [S1, unofficial]. It uses Union-Find to efficiently group pixels into components before mesh generation.
