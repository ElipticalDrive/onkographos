# Simplified Dual Contouring

Also called: Dual Contouring (Simplified/Naive), naive dual contouring

## Overview
Simplified Dual Contouring is an isosurface extraction method that places a single vertex at the center of every voxel cell where the scalar field values at the eight corners exhibit a sign change along any axis-aligned edge, and constructs a quad mesh by connecting these vertices based on their relative positions in the grid [S1, unofficial]. It differs from standard Dual Contouring by bypassing the Quadratic Error Function (QEF) minimization and normal-based vertex optimization, instead using a fixed geometric placement and direct quad construction based on grid topology [S1, unofficial].

## How it works
**Inputs and Outputs:** The method takes an input implementing the `DCInput` trait, which provides scalar values and gradients at integer grid coordinates, and returns a `DCOutput` struct containing vertex positions, normals, and indices [S1, unofficial].

**Data Structures:** `DCBounds` defines the processing volume with fields `x`, `y`, and `z`, each a tuple `(i32, i32)` representing inclusive start and exclusive end bounds [S1, unofficial]. `DCInput` requires `get_bounds() -> DCBounds`, `get_value(x, y, z) -> f32`, and `get_gradient(x, y, z) -> [f32; 3]` [S1, unofficial]. `DCOutput` contains `vertices: Vec<[f32; 3]>`, `normals: Vec<[f32; 3]>`, and `indices: Vec<u32>` [S1, unofficial]. Internal buffers include `vertex_buffer`, `normal_buffer`, `index_list`, and `vertex_map` (a `HashMap<IVec3, u32>` mapping grid positions to vertex indices) [S1, unofficial].

**Pseudocode:**
```python
def dc_meshing(input):
    bounds = input.get_bounds()
    vertex_buffer = []
    normal_buffer = []
    index_list = []
    vertex_map = {}
    # Fixed plane basis vectors: X, Z, Y
    planes = [(1, 0, 0), (0, 0, 1), (0, 1, 0)]

    for x in range(bounds.x[0], bounds.x[1] - 1):
        for y in range(bounds.y[0], bounds.y[1] - 1):
            for z in range(bounds.z[0], bounds.z[1] - 1):
                vertex = dc_place_vertex(input, x, y, z)
                if vertex is not None:
                    position = (x, y, z)
                    vertex_map[position] = len(vertex_buffer)
                    vertex_buffer.append(vertex)
                    normal_buffer.append(input.get_gradient(x, y, z))
                    for basis_1, basis_2 in planes:
                        check_quad(input, vertex_map, position, bounds, basis_1, basis_2, index_list)
    return DCOutput(vertices=vertex_buffer, normals=normal_buffer, indices=index_list)

def dc_place_vertex(input, x, y, z):
    points = [
        input.get_value(x, y, z), input.get_value(x + 1, y, z),
        input.get_value(x + 1, y + 1, z), input.get_value(x, y + 1, z),
        input.get_value(x, y, z + 1), input.get_value(x + 1, y, z + 1),
        input.get_value(x + 1, y + 1, z + 1), input.get_value(x, y + 1, z + 1)
    ]
    for index in range(7):
        if sign_change(points[index], points[index + 1]):
            return [x + 0.5, y + 0.5, z + 0.5]
    return None

def sign_change(a, b):
    return (max(a, b) > 0.0 and min(a, b) < 0.0) or (a == 0.0 and b != 0.0) or (a != 0.0 and b == 0.0)

def check_quad(input, vertex_map, position, bounds, basis_1, basis_2, index_list):
    top_left = (position[0] - basis_1[0], position[1] - basis_1[1], position[2] - basis_1[2])
    top_right = position
    bottom_left = (position[0] - basis_1[0] - basis_2[0], position[1] - basis_1[1] - basis_2[1], position[2] - basis_1[2] - basis_2[2])
    bottom_right = (position[0] - basis_2[0], position[1] - basis_2[1], position[2] - basis_2[2])

    if (bottom_left[0] > bounds.x[0] and bottom_left[1] > bounds.y[0] and bottom_left[2] > bounds.z[0] and
        top_left in vertex_map and bottom_left in vertex_map and bottom_right in vertex_map):
        cw = input.get_value(position[0], position[1], position[2]) > 0
        create_quad(vertex_map, top_left, bottom_left, bottom_right, index_list, cw)

def create_quad(vertex_map, top_left, bottom_left, bottom_right, index_list, cw):
    i0 = vertex_map[top_left]
    i1 = vertex_map[bottom_left]
    i2 = vertex_map[bottom_right]
    if cw:
        index_list.extend([i0, i1, i2])
    else:
        index_list.extend([i0, i2, i1])
```

**Parameters:** Grid bounds are defined by `DCBounds` [S1, unofficial]. The plane basis order is fixed to `[(X, Y), (Z, X), (Y, Z)]` [S1, unofficial].

**Edge Cases and Pitfalls:** The plane basis vector ordering is fixed to ensure outward-facing quads; changing the order causes mesh faces to invert [S1, unofficial]. The `sign_change` function explicitly handles cases where one corner is exactly zero, treating it as a sign change if the other corner is non-zero [S1, unofficial]. `check_quad` requires `bottom_left` to be strictly greater than the lower bounds to ensure valid neighbor lookups [S1, unofficial].

## Subtopics

### [Dual Contouring with Adaptive Split Selection](3667-dual-contouring-with-adaptive-split-selection.md)
Dual Contouring with Adaptive Split Selection is a mesh extraction method that converts voxel grid data into a triangle mesh by constructing quads from connected voxels and splitting them into triangles based on geometric alignment or weight products. It differs from Simplified Dual Contouring by using adaptive splitting criteria rather than fixed quad topology. Choose it when adaptive splitting is needed for better mesh quality.

### [Gradient-Consistent Quadrilateral Splitting](11144-gradient-consistent-quadrilateral-splitting.md)
Gradient-Consistent Quadrilateral Splitting is a post-processing method for converting the quadrilateral meshes produced by Simplified Dual Contouring into triangle meshes. It resolves the ambiguity of quad triangulation by selecting diagonal splits based on gradient consistency between opposite vertices, ensuring the resulting triangles align with the underlying scalar field's geometry. It differs from sibling methods by using a fixed gamma-based heuristic rather than adaptive geometric criteria. Choose it when high-quality triangle meshes are required from the initial quad output.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels in the bounds, as each voxel is processed once for vertex placement and a constant number of quad checks [S1, unofficial].
*   **Memory Complexity:** Linear with respect to the number of extracted vertices and quads. The `vertex_map` requires memory proportional to the number of active vertices [S1, unofficial].
*   **Measured Performance:** Not given in the sources [S1, unofficial].
*   **Scaling:** Not given in the sources.
*   **Strengths:** Simple implementation, no need for complex solvers, fast execution [S1, unofficial].
*   **Limitations:** Fixed vertex placement may not capture fine geometric details as well as QEF-based methods, quad-based output requires post-processing for triangle meshes [S1, unofficial].
*   **When to use:** When speed is critical and approximate geometry is acceptable, or as a baseline for comparison [S1, unofficial].
*   **When not to use:** When high geometric fidelity or strict topological correctness is required [S1, unofficial].

## Background
Simplified Dual Contouring is an implementation attempt described in an unofficial GitHub repository [S1, unofficial]. It draws inspiration from general dual-contouring tutorials and voxel-based surface extraction techniques [S1, unofficial]. The method is presented as an "unfinished" general-purpose approach, highlighting its experimental nature [S1, unofficial].
