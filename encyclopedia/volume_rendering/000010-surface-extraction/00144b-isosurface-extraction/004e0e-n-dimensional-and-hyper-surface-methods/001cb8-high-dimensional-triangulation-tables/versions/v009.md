# High-Dimensional Triangulation Tables

Also called: Bhaniramka et al. triangulation algorithm

## Overview
High-Dimensional Triangulation Tables is a method for generating lookup tables for isosurface extraction in $n$-dimensional hypercubes, designed to address the excessive simplex count produced by recursive contour-meshing [S1, book]. Unlike recursive contour-meshing, which subdivides 4-cells into 4-simplices before contouring (analogous to breaking a cube into five or six tetrahedra in 3D), this method constructs the isosurface directly within the hypercube using convex hulls and consistent triangulation [S1, book]. It serves as a generalization of the Marching Cubes algorithm to arbitrary dimensions, avoiding the intermediate simplicial decomposition step that increases triangle count [S1, book].

## How it works
The method generates a triangulation table for an $n$-dimensional hypercube and uses it to extract isosurfaces [S1, book].

**Inputs:**
- Scalar field values at the $2^n$ vertices of an $n$-dimensional hypercube cell [S1, book].
- An iso-value threshold [S1, book].

**Outputs:**
- A set of triangles (simplices) representing the isosurface intersection within the cell [S1, book].
- A precomputed triangulation table for the given dimension $n$ [S1, book].

**Data Structures:**
- **Triangulation Table:** An array indexed by the cell configuration [S1, book].
  - **Index:** A bitmask of length $2^n$, where each bit corresponds to a vertex [S1, book]. Bit $i$ is 1 if vertex $i$'s scalar value $> \text{iso-value}$, and 0 otherwise [S1, book].
  - **Content:** A list of triangles representing the isosurface faces within the cell [S1, book]. The source notes that faces might not be simplices initially and require triangulation [S1, book].

**Algorithm Steps (Table Generation):**
The table is generated once for a given dimension $n$ [S1, book]. For each of the $2^{2^n}$ possible vertex configurations:

1. **Label Vertices:** Assign a positive label to vertices with scalar values $> \text{iso-value}$ and a negative label to vertices with scalar values $< \text{iso-value}$ [S1, book].
2. **Collect Midpoints:** Identify all edges of the hypercube where one endpoint has a positive label and the other has a negative label. Collect the midpoints of these edges [S1, book].
3. **Form Convex Hull:** Create the convex hull of the collected midpoints together with the vertices in the hypercube that share the same label (positive or negative, used consistently) [S1, book]. This forms an $n$-polytope within the hypercube [S1, book].
4. **Remove Boundary Faces:** Remove any faces of the polytope that lie on the boundary of the hypercube (i.e., faces that share vertices of the hypercube) [S1, book].
5. **Identify Isosurface Faces:** The remaining faces of the polytope comprise the isosurface in $n$ dimensions [S1, book].
6. **Triangulate:** If the remaining faces are not simplices, perform triangulation. Ensure consistent triangulation between adjacent faces of the hypercube to maintain manifold continuity [S1, book].
7. **Store:** Store the resulting triangulation in the table at the index corresponding to the current vertex configuration [S1, book].

**Algorithm Steps (Extraction):**
For each cell in the grid:

1. **Compute Index:** For a cell that intersects the isosurface, encode the vertex values relative to the iso-value using one bit per vertex (1 if value $> \text{iso-value}$, 0 otherwise) [S1, book].
2. **Lookup:** Use the $2^n$-bit index to retrieve the precomputed triangulation from the table [S1, book].
3. **Generate Mesh:** The table entry dictates which edges intersect the isosurface and provides the triangulation for the surface within the cell [S1, book].

**Parameters:**
- **Dimension ($n$):** The number of dimensions of the hypercube [S1, book].
- **Table Size:** The number of cases in the table is $2^{2^n}$ [S1, book].

**Edge Cases and Pitfalls:**
- **Ambiguity:** The method requires careful handling to ensure consistent triangulation between adjacent faces of the hypercube [S1, book].
- **Complexity:** The table size grows exponentially with dimension. For $n=5$, the table exceeds four billion cases [S1, book].

**Pseudocode:**
```python
def generate_triangulation_table(n, iso_value):
    table = {}
    # Iterate over all 2^(2^n) vertex configurations
    for config in range(1 << (1 << n)):
        vertices = get_hypercube_vertices(n)
        labels = []
        for v in vertices:
            labels.append(1 if v.scalar > iso_value else 0)
        # Collect midpoints of crossing edges
        midpoints = []
        for edge in get_hypercube_edges(n):
            if labels[edge.start] != labels[edge.end]:
                midpoints.append(midpoint(vertices[edge.start], vertices[edge.end]))
        # Form convex hull of midpoints and same-label vertices
        # [G] Standard computational geometry operation
        hull = convex_hull(midpoints + [v for v, l in zip(vertices, labels) if l == labels[0]])
        # Remove boundary faces
        boundary_vertices = set(vertices)
        isosurface_faces = [f for f in hull.faces if not f.vertices.issubset(boundary_vertices)]
        # Triangulate non-simplices consistently
        # [G] Standard mesh triangulation operation
        triangles = triangulate_faces(isosurface_faces, consistent=True)
        table[config] = triangles
    return table

def extract_isosurface(cell_vertices, table):
    config = 0
    for i, v in enumerate(cell_vertices):
        if v.scalar > iso_value:
            config |= (1 << i)
    return table.get(config, [])
```

## Subtopics

### [Recursive n-simplex subdivision](8462-recursive-n-simplex-subdivision.md)
A technique that uses a recursive method to split $n$-dimensional cells into $n$-simplexes before computing surfaces. Surfaces existing in four dimensions are displayed using stereographic projection or slicing to reduce dimensionality. This approach was used to compute swept volumes of time-varying data from electromagnetic field simulations for animation.

### Complete Simplex Table
A lookup table method for $n$-dimensional surface reconstruction that uses a single large array to store all tetrahedra configurations for every possible cell orientation, ensuring correct orientation without additional disambiguation logic [S2]. The table consists of a 65,536 array with $n$ tetrahedra per index [S2]. Each tetrahedron is stored in 4 bytes, the array pointer in 4 bytes, and there are 356,817 tetrahedra for the whole table [S2]. The total memory size is 1.75M bytes, calculated as $(4 \times 356817) + (5 \times 65536)$ [S2]. The advantage is that all data is correctly oriented and can be directly applied; the disadvantage is the larger size, though considered acceptable within four dimensions [S2].

## Operating characteristics
- **Time Complexity:** Table generation is done once per dimension [S1, book]. Extraction is $O(1)$ per cell after table lookup, assuming the table fits in memory [G].
- **Memory Complexity:** The table size is $2^{2^n}$ entries [S1, book]. For $n=3$, there are 256 cases [S1, book]. For $n=4$, there are 65,536 cases [S1, book]. For $n=5$, there are over four billion cases [S1, book]. The Complete Simplex Table variant for 4D uses 1.75M bytes [S2].
- **Performance:** Compared to Marching Cubes, extracting isosurfaces after simplicial decomposition (recursive contour-meshing) creates more triangles [S1, book]. The High-Dimensional Triangulation Tables method avoids this by generating the table directly for the hypercube [S1, book].
- **Strengths:** Generalizes to $n$ dimensions; avoids excessive simplex count from recursive subdivision; ensures correct orientation in the Complete Simplex Table variant [S2].
- **Limitations:** Table size grows doubly exponentially with dimension, making it impractical for $n \ge 5$ without significant memory or compression strategies [S1, book].

## Background
The method was proposed by Bhaniramka et al. [S1, book]. It addresses the problem of excessive simplex count in recursive contour-meshing for high-dimensional data [S1, book]. It is analogous to breaking a cube into tetrahedra in 3D but applies to $n$-dimensional hypercubes [S1, book]. The Complete Simplex Table variant was explored in the context of piecewise linear hypersurfaces [S2]. Recursive n-simplex subdivision was an early example of computing surfaces in >3 dimensions by Weigle and Banks [S2].
