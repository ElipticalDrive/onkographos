# Image-to-Mesh Extraction via Neural Implicit Fields

Also called: Batch Image-to-Mesh via TripoSR, TripoSR Mesh Extraction, image_to_mesh [S1, unofficial]

## Overview
This method converts a single 2D input image into a textured 3D triangle mesh using the TripoSR neural implicit field model and Marching Cubes extraction [S1, unofficial]. It solves the problem of generating explicit surface geometry from monocular images by leveraging a pre-trained neural network to predict a scene code, which is then decoded into a signed distance field (SDF) or density field for surface extraction [S1, unofficial]. It sets itself apart from standard volume rendering pipelines by performing batch inference on multiple images in a single forward pass and directly outputting meshes with vertex colors, bypassing the need for separate color fusion steps [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A list of image paths (or PIL Images) and corresponding output paths [S1, unofficial].
- Output: 3D triangle meshes (e.g., `.glb`, `.obj`) with vertex colors [S1, unofficial].

**Data Structures:**
- `scene_codes`: Latent tensor representing the 3D structure and appearance [S1, unofficial].
- `meshes`: List of mesh objects containing vertices, faces, and vertex colors [S1, unofficial].

**Parameters:**
- `mc_resolution`: Integer specifying the Marching Cubes grid resolution. Default: 256 [S1, unofficial]. Higher values increase geometric detail [S1, unofficial].
- `foreground_ratio`: Float used during preprocessing to determine foreground segmentation size. Default: 0.85 [S1, unofficial].
- `chunk_size`: Integer for renderer chunking to manage memory. Default: 8192 [S1, unofficial].

**Steps:**
1. **Device Detection:** Detect available hardware, preferring MPS (Apple Silicon), then CUDA, then CPU [S1, unofficial].
2. **Model Loading:** Load the TripoSR model from Hugging Face (`stabilityai/TripoSR`) using `config.yaml` and `model.ckpt`, caching by device key [S1, unofficial].
3. **Renderer Configuration:** Set the renderer chunk size to 8192 and move the model to the detected device [S1, unofficial].
4. **Preprocessing:** For each input image: load and resize/pad to a square (default 512x512) on a white background, remove background using `rembg` and composite onto white, apply stylization (edge-aware shading, radial gradient) to simulate volume and lighting, and record errors if preprocessing fails [S1, unofficial].
5. **Batch Inference:** Pass all preprocessed images through the model in evaluation mode (`torch.no_grad()`) to obtain `scene_codes` [S1, unofficial].
6. **Mesh Extraction:** Call `model.extract_mesh(scene_codes, has_vertex_color=True, resolution=mc_resolution)` to generate meshes [S1, unofficial].
7. **Export:** For each mesh, create the output directory if needed, and export as `.glb` if the suffix matches, otherwise use the default format [S1, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np
from PIL import Image
from pathlib import Path
import scipy.ndimage as ndimage

def preprocess_for_triposr(image: Image.Image, foreground_ratio: float = 0.85) -> Image.Image:
    """Preprocess image: resize, remove background, apply stylization."""
    size = 512
    w, h = image.size
    scale = size / max(w, h)
    new_w, new_h = int(w * scale), int(h * scale)
    image = image.resize((new_w, new_h), Image.LANCZOS)
    result = Image.new("RGBA", (size, size), (255, 255, 255, 255))
    offset_x = (size - new_w) // 2
    offset_y = (size - new_h) // 2
    result.paste(image, (offset_x, offset_y), image)
    from rembg import remove
    result = remove(result)
    white = Image.new("RGBA", result.size, (255, 255, 255, 255))
    result = Image.alpha_composite(white, result)
    arr = np.array(result).astype(np.float32)
    h, w = arr.shape[:2]
    gray = np.mean(arr[:, :, :3], axis=2)
    white_thresh = 240
    subject_mask = np.any(arr[:, :, :3] < white_thresh, axis=2).astype(np.float32)
    if subject_mask.sum() < 100:
        return result
    coords = np.argwhere(subject_mask > 0)
    cy, cx = coords.mean(axis=0)
    dist_from_edge = ndimage.distance_transform_edt(subject_mask)
    max_dist = dist_from_edge.max()
    dist_norm = dist_from_edge / max_dist if max_dist > 0 else dist_from_edge
    yy, xx = np.mgrid[0:h, 0:w]
    radial = np.sqrt((xx - cx) ** 2 + (yy - cy) ** 2)
    max_radial = radial[subject_mask > 0].max() if subject_mask.sum() > 0 else 1.0
    radial_norm = np.clip(radial / max(max_radial, 1.0), 0, 1)
    light_dir_x, light_dir_y = -0.3, -0.5
    light_map = 1.0 - 0.15 * (
        light_dir_x * (xx - cx) / max(max_radial, 1) +
        light_dir_y * (yy - cy) / max(max_radial, 1)
    )
    light_map = np.clip(light_map, 0.7, 1.15)
    ao = 0.85 + 0.15 * dist_norm
    rgb = arr[:, :, :3]
    rgb = rgb * light_map[:, :, np.newaxis] * ao[:, :, np.newaxis]
    rgb = np.clip(rgb, 0, 255).astype(np.uint8)
    return Image.fromarray(rgb)

def extract_mesh_from_image(image_paths: list, output_paths: list, mc_resolution: int = 256, foreground_ratio: float = 0.85):
    if torch.backends.mps.is_available():
        device = torch.device("mps")
    elif torch.cuda.is_available():
        device = torch.device("cuda")
    else:
        device = torch.device("cpu")
    # Model loading and inference implementation not provided in sources [S1, unofficial]
    # model = load_tripoSR_model('stabilityai/TripoSR', device=device)
    # model.renderer.set_chunk_size(8192)
    processed_images = []
    valid_items = []
    for img_path, out_path in zip(image_paths, output_paths):
        try:
            img = Image.open(img_path).convert("RGBA")
            processed = preprocess_for_triposr(img, foreground_ratio)
            processed_images.append(processed)
            valid_items.append((img_path, out_path))
        except Exception as e:
            print(f"Error processing {img_path}: {e}")
    if not processed_images:
        return
    with torch.no_grad():
        scene_codes = model(processed_images, device=device)
    meshes = model.extract_mesh(scene_codes, has_vertex_color=True, resolution=mc_resolution)
    for mesh, (img_path, out_path) in zip(meshes, valid_items):
        Path(out_path).parent.mkdir(parents=True, exist_ok=True)
        if out_path.endswith('.glb'):
            mesh.export(out_path, file_type='glb')
        else:
            mesh.export(out_path)
```

## Subtopics

### [Voxel2Mesh](17153-voxel2mesh.md)
Voxel2Mesh is a CNN-based architecture that generates 3D surface meshes directly from 3D image volumes without post-processing, avoiding artifacts and enabling end-to-end training. It sets itself apart from standard voxel rendering or segmentation methods by outputting explicit surface representations (vertices and faces) rather than labeled voxel grids, allowing for differentiable mesh operations and better accuracy in biomedical segmentation tasks.

### Image-to-Mesh via Single Image with Multi-view and Geometry Losses
Input: Single RGBA image (RGB values I, alpha values S) [S2, unofficial]. Network F(θ) predicts position and color value for each vertex in a mesh with specified topology (e.g., sphere) [S2, unofficial]. Multi-view loss: Render from random second view and compare against ground truth renderings from this new view [S2, unofficial]. Regularize with smoothness loss Lsm (penalizes difference in normals for neighboring faces) and Laplacian loss Llap (penalizes change in relative positions of neighboring vertices) [S2, unofficial]. Formulas: $$L_{IOU}(\theta) = \mathbb{E}_I \left[ 1 - \frac{\|S \tilde{S}\|_1}{\|S + \tilde{S} - S \tilde{S}\|_1} \right]$$, $$L_{col}(\theta) = \mathbb{E}_I \|I - \tilde{I}\|_1$$, $$L_1 = L_{IOU} + \lambda_{col} L_{col} + \lambda_{sm} L_{sm} + \lambda_{lap} L_{lap}$$ [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of input images due to batch inference [S1, unofficial].
- **Memory Complexity:** Depends on `mc_resolution` and batch size; higher resolutions increase memory usage for the Marching Cubes grid [G].
- **Strengths:** End-to-end pipeline from image to textured mesh; batch processing capability; vertex colors included in the mesh [S1, unofficial].
- **Limitations:** Quality depends on the TripoSR model's training data; preprocessing steps (background removal, stylization) can introduce artifacts if the input image is complex [S1, unofficial].
- **When to use:** When generating textured meshes from single images is required, especially in batches [S1, unofficial].
- **When not to use:** When high-fidelity geometry from multi-view stereo is needed, or when the input images have complex backgrounds that are difficult to segment [G].

## Background
The method is based on the TripoSR model, which uses a neural implicit field to represent 3D shapes from single images [S1, unofficial]. It builds on [NeRF-based Mesh Extraction with Color Fusion](7372-nerf-based-mesh-extraction-with-color-fusion.md) by replacing the explicit NeRF training and color fusion steps with a direct neural prediction of scene codes and mesh extraction [S1, unofficial].
