# Marching Cubes on Structured Grids

Also called: Marching Cubes in IJK Coordinate Space

## Overview
Marching Cubes on Structured Grids is a surface extraction method that adapts the standard Marching Cubes algorithm to operate on non-uniform or deformed 3D structured grids by performing topology determination in the canonical IJK (integer) coordinate space and interpolating vertex positions back into the physical XYZ space [S1]. It solves the problem of extracting isosurfaces from volumetric data where the underlying grid cells are not unit-aligned cubes, such as in medical imaging (CT/MRI) or computational fluid dynamics. It sets itself apart from [Generalized Marching Cubes](8320-generalized-marching-cubes.md) by maintaining the strict binary topology lookup of the standard algorithm while deferring geometric complexity to a post-interpolation step, and from [Streaming Marching Cubes](6190-streaming-marching-cubes.md) by focusing on the coordinate transformation aspect rather than memory management, though it is compatible with streaming implementations [S1].

## How it works
The method relies on the precomputed data structures defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md): the `edgeTable` (256 entries, 12-bit masks) and `triangleTable` (256x16 array of edge indices).

**Inputs:**
*   Scalar field $V$ defined on a structured grid with dimensions $N_x \times N_y \times N_z$.
*   Grid geometry defined by origin $\mathbf{O}$, basis vectors $\mathbf{u}, \mathbf{v}, \mathbf{w}$, and cell sizes $\Delta x, \Delta y, \Delta z$ (which may vary per cell or be constant).
*   Isovalue $I$.

**Outputs:**
*   A triangular mesh where vertices are positioned in physical XYZ coordinates.

**Data Structures:**
*   `edgeTable`: Array of 256 integers. Bit $k$ set if edge $k$ is intersected.
*   `triangleTable`: Array of size $256 \times 16$. Contains triplets of edge indices $(e_a, e_b, e_c)$ terminated by `-1`.

**Steps:**

1.  **Iterate Voxels:** Loop through each voxel $(i, j, k)$ where $0 \le i < N_x-1$, $0 \le j < N_y-1$, $0 \le k < N_z-1$.
2.  **Determine Case Index:** Retrieve the scalar values $V_0 \dots V_7$ at the 8 corners of the voxel. The corners are indexed $0..7$ according to the standard convention (bottom face $0-3$, top face $4-7$). Compute the case index $C$:
    $$ C = \sum_{m=0}^{7} b_m 2^m $$
    where $b_m = 1$ if $V_m < I$ (or $V_m > I$, depending on the chosen convention, must be consistent with `edgeTable` generation) and $0$ otherwise.
3.  **Lookup Topology:**
    *   Retrieve the intersection mask $M = \text{edgeTable}[C]$.
    *   If $M == 0$, the voxel contains no surface; continue to next voxel.
    *   Retrieve the triangle configuration $T = \text{triangleTable}[C]$.
4.  **Generate Vertices:** For each triangle triplet $(e_a, e_b, e_c)$ in $T$ (until `-1` is reached):
    *   For each edge index $e \in \{e_a, e_b, e_c\}$:
        *   Identify the two voxel corners $(c_1, c_2)$ connected by edge $e$.
        *   Retrieve their physical coordinates $\mathbf{P}_1, \mathbf{P}_2$ and scalar values $V_1, V_2$.
        *   Compute the intersection point $\mathbf{P}_{int}$ using linear interpolation:
            $$ \mathbf{P}_{int} = \mathbf{P}_1 + \frac{I - V_1}{V_2 - V_1} (\mathbf{P}_2 - \mathbf{P}_1) $$
            *Note: In the IJK approach, $\mathbf{P}_1$ and $\mathbf{P}_2$ are first determined in IJK space (e.g., $(i, j, k)$ and $(i+1, j, k)$), then transformed to XYZ. The interpolation is performed in XYZ space.*
    *   Output the triangle formed by the three interpolated points.

**Pseudocode:**

```python
def marching_cubes_structured_grid(V, grid_origin, grid_basis, grid_cell_sizes, isovalue):
    """
    V: 3D array of shape (Nx, Ny, Nz)
    grid_origin: tuple (ox, oy, oz)
    grid_basis: tuple of 3 vectors (ux, uy, uz), (vx, vy, vz), (wx, wy, wz)
    grid_cell_sizes: tuple of 3 floats (dx, dy, dz) assuming uniform for simplicity, 
                     or arrays if non-uniform.
    """
    # Assume edgeTable and triangleTable are loaded global constants
    # edgeTable: list of 256 ints
    # triangleTable: list of 256 lists of 16 ints
    
    vertices = []
    triangles = []
    
    Nx, Ny, Nz = V.shape
    
    for i in range(Nx - 1):
        for j in range(Ny - 1):
            for k in range(Nz - 1):
                # 1. Get corner values and IJK coordinates
                # Corner ordering: 0:(0,0,0), 1:(1,0,0), 2:(1,1,0), 3:(0,1,0)
                #            4:(0,0,1), 5:(1,0,1), 6:(1,1,1), 7:(0,1,1)
                corners_ijk = [
                    (i, j, k), (i+1, j, k), (i+1, j+1, k), (i, j+1, k),
                    (i, j, k+1), (i+1, j, k+1), (i+1, j+1, k+1), (i, j+1, k+1)
                ]
                corner_vals = [
                    V[i, j, k], V[i+1, j, k], V[i+1, j+1, k], V[i, j+1, k],
                    V[i, j, k+1], V[i+1, j, k+1], V[i+1, j+1, k+1], V[i, j+1, k+1]
                ]
                
                # 2. Calculate Case Index C
                C = 0
                for m in range(8):
                    if corner_vals[m] < isovalue: # Convention: inside < isovalue
                        C |= (1 << m)
                
                # 3. Lookup
                edge_mask = edgeTable[C]
                if edge_mask == 0:
                    continue
                
                tri_config = triangleTable[C]
                
                # 4. Process Triangles
                for idx in range(0, 15, 3):
                    e_a = tri_config[idx]
                    e_b = tri_config[idx+1]
                    e_c = tri_config[idx+2]
                    
                    if e_a == -1:
                        break
                    
                    # Helper to get interpolated vertex for an edge index
                    def get_vertex(edge_idx):
                        # Map edge index to corner pairs
                        # Standard MC edge mapping:
                        # 0:(0,1), 1:(1,2), 2:(2,3), 3:(3,0)
                        # 4:(4,5), 5:(5,6), 6:(6,7), 7:(7,4)
                        # 8:(0,4), 9:(1,5), 10:(2,6), 11:(3,7)
                        edge_pairs = [
                            (0, 1), (1, 2), (2, 3), (3, 0),
                            (4, 5), (5, 6), (6, 7), (7, 4),
                            (0, 4), (1, 5), (2, 6), (3, 7)
                        ]
                        c1_idx, c2_idx = edge_pairs[edge_idx]
                        
                        # Get IJK coords
                        p1_ijk = corners_ijk[c1_idx]
                        p2_ijk = corners_ijk[c2_idx]
                        
                        # Convert IJK to XYZ
                        # P_xyz = Origin + u*ix + v*jy + w*kz
                        # Assuming uniform cell sizes for basis scaling, 
                        # or if basis vectors already include scaling.
                        # If grid_cell_sizes are separate, basis vectors are unit vectors.
                        # Here we assume basis vectors represent the physical span of one cell.
                        p1_xyz = (
                            grid_origin[0] + p1_ijk[0]*grid_basis[0][0] + p1_ijk[1]*grid_basis[1][0] + p1_ijk[2]*grid_basis[2][0],
                            grid_origin[1] + p1_ijk[0]*grid_basis[0][1] + p1_ijk[1]*grid_basis[1][1] + p1_ijk[2]*grid_basis[2][1],
                            grid_origin[2] + p1_ijk[0]*grid_basis[0][2] + p1_ijk[1]*grid_basis[1][2] + p1_ijk[2]*grid_basis[2][2]
                        )
                        p2_xyz = (
                            grid_origin[0] + p2_ijk[0]*grid_basis[0][0] + p2_ijk[1]*grid_basis[1][0] + p2_ijk[2]*grid_basis[2][0],
                            grid_origin[1] + p2_ijk[0]*grid_basis[0][1] + p2_ijk[1]*grid_basis[1][1] + p2_ijk[2]*grid_basis[2][1],
                            grid_origin[2] + p2_ijk[0]*grid_basis[0][2] + p2_ijk[1]*grid_basis[1][2] + p2_ijk[2]*grid_basis[2][2]
                        )
                        
                        v1 = corner_vals[c1_idx]
                        v2 = corner_vals[c2_idx]
                        
                        # Linear interpolation in XYZ space
                        t = (isovalue - v1) / (v2 - v1)
                        # Guard against division by zero if v1 == v2
                        if abs(v2 - v1) < 1e-9:
                            t = 0.5
                            
                        return (
                            p1_xyz[0] + t * (p2_xyz[0] - p1_xyz[0]),
                            p1_xyz[1] + t * (p2_xyz[1] - p1_xyz[1]),
                            p1_xyz[2] + t * (p2_xyz[2] - p1_xyz[2])
                        )
                    
                    v_a = get_vertex(e_a)
                    v_b = get_vertex(e_b)
                    v_c = get_vertex(e_c)
                    
                    triangles.append((v_a, v_b, v_c))

    return triangles
```

**Edge Cases and Pitfalls:**
*   **Interpolation Accuracy:** The method performs interpolation in XYZ space after determining topology in IJK space. This is technically an approximation because the isosurface intersection on a deformed cell is not exactly linear in XYZ space if the cell is not a parallelepiped or if the scalar field varies non-linearly relative to the grid distortion [S1]. However, for most applications, this difference is negligible [S1].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 suffer from topological ambiguity. The standard LUT resolves these arbitrarily, which can cause cracks if adjacent voxels resolve them inconsistently. This requires external handling (e.g., [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md)).
*   **Boundary Conditions:** The loop runs up to $N-1$. Voxels on the boundary of the volume are processed, but vertices on the exterior boundary of the volume are generated. If the volume is closed, this is correct. If not, the mesh will have open boundaries.

## Subtopics

### [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md)
Uses bitwise propagation to compute case indices, reusing bits from adjacent cells to avoid redundant lookups.

### [Uniform Marching Cubes with Snapping](7468-uniform-marching-cubes-with-snapping.md)
Snaps vertices to grid edges to reduce geometric error.

### [Smart Conversion](7489-smart-conversion.md)
Gradient-based correction of mesh vertices to align with true boundaries.

### [Flying Edges](7520-flying-edges.md)
Edge-based parallel processing to avoid point merging bottlenecks.

### [Undeformed Space Ray Start via Deformed Hull Intersection](10141-undeformed-space-ray-start-via-deformed-hull-intersection.md)
Determines ray starts in undeformed space for deformed volumes.

### [Dual Grid Isosurface Extraction](10271-dual-grid-isosurface-extraction.md)
Extracts crack-free surfaces from AMR data using a dual grid.

### [Dividing Cubes](10391-dividing-cubes.md)
Subdivides surface voxels for pixel-based rendering.

### Matveyev's Algorithm
An algorithm based on a triangulation table that correctly represents trilinear interpolant behavior using intersections on cube diagonals [S2]. Proposed by Matveyev in 1999, it addresses the ambiguity in the cube interior by testing the trilinear interpolant's behavior along the cube diagonals, providing a more accurate representation than the standard LUT for ambiguous cases [S2].

### Geomorph LOD Seam Handling
A technique to achieve watertight seams between fine and coarse LOD levels in Marching Cubes by geometrically deforming the fine surface at the boundary to match the coarse contour [S3, unofficial]. It identifies boundary vertices between LOD levels, applies a geometric morph (bending) to fine surface vertices, and deforms them toward the coarse contour to eliminate gaps [S3, unofficial].

### Cell Subdivision Isosurface Extraction
A method that retains the identity of cells (vertex/node centered data) and eliminates non-linear hanging nodes by subdividing boundary cells into pyramids, allowing standard isosurface techniques to be applied [S4, unofficial]. It subdivides lower-resolution cell faces to match higher-resolution faces, obtains values at newly created hanging nodes by linear interpolation, and subdivides 3D cells into pyramids with a common apex point [S4, unofficial]. Tested on star cluster formation, it processed 44,332 cells/10,456 triangles in 2.30 sec and 303,759 cells/77,029 triangles in 7.73 sec [S4, unofficial]. Unlike the dual grid approach, this method retains the original cell identity and uses subdivision/pyramids instead of stitch cells [S4, unofficial].

### TexF with Implicit Geometry (SDF)
An extension where TexF shares a canonical grid with an implicit Signed Distance Field (SDF). The surface is extracted via Marching Cubes, and TexF attributes are transferred to vertices for standard vertex-color rendering, avoiding per-pixel TexF queries [S5, unofficial]. The SDF and TexF share the same grid; after extracting a mesh with Marching Cubes, TexF attributes are transferred to its vertices using k-nearest-neighbor interpolation, and the rasterizer interpolates these vertex attributes across triangles [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once. The constant factor is small due to table lookups.
*   **Memory Complexity:** $O(N)$ for the input volume. The output mesh size is proportional to the surface area.
*   **Strengths:** Simple to implement; efficient; works on any structured grid (uniform or non-uniform) via the IJK-to-XYZ interpolation [S1]. Compatible with streaming implementations for large datasets [S1].
*   **Limitations:** The IJK-to-XYZ interpolation is not technically correct for highly distorted grids, though the error is usually negligible [S1]. Does not handle topological ambiguity in the cube interior without extensions (e.g., Matveyev's or Chernyaev's methods) [S2].
*   **When to use:** Standard isosurface extraction from structured volumetric data (CT, MRI, CFD) where the grid distortion is mild or the approximation is acceptable.
*   **When not to use:** When high geometric accuracy is required on highly distorted grids (consider [Generalized Marching Cubes](8320-generalized-marching-cubes.md) or [Smart Conversion](7489-smart-conversion.md)), or when topological ambiguity must be resolved exactly (consider [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md)).

## Background
The Marching Cubes algorithm was originally developed and patented by GE Medical Systems for use in their CT and MRI equipment [S1]. The patent has since expired, placing the algorithm in the public domain [S1]. It remains one of the most common visualization methods for isosurface extraction [S1]. The adaptation to structured grids via IJK coordinate space interpolation is a standard modification to handle non-uniform grids, as described in various implementations [S1].
