# Crack-free Isosurface Extraction from AMR Data

Also called: Crack-free isosurface extraction, Dual grid isosurface extraction with ghost cells, Dual grid stitch cell method, Parallel extraction of crack-free isosurfaces from AMR data, Stitch Cell Generation for AMR Isosurfaces

## Overview
This method extracts watertight, crack-free isosurfaces from block-structured Adaptive Mesh Refinement (AMR) data in a distributed-memory parallel environment [S1]. It solves the problem of T-junctions (cracks) that arise when standard Marching Cubes is applied to hierarchical data by using dual grids and ghost cells to ensure boundary consistency without requiring the entire dataset in a single processor's memory [S1]. Unlike [Octree-based Isosurfacing](1247-octree-based-isosurfacing.md) which operates on tree structures, this method operates on rectilinear boxes, and unlike [Grid Traversal and Data Structure Adaptation](8340-grid-traversal-and-data-structure-adaptation.md) which may adapt the grid structure itself, this method preserves the original AMR boxes while generating auxiliary "stitch cells" to bridge resolution gaps [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Block-structured AMR data consisting of axis-aligned rectilinear grids (boxes) organized in a hierarchy of levels. Data is cell-centered. Each box has an integer identifier. The refinement ratio between levels is a fixed integer (typically 2) [S1].
*   **Output:** A set of triangles forming a continuous isosurface.

**Data Structures:**
1.  **AMR Box:** Defined by integer indices of cells in a global reference frame. Contains regular cell values and ghost cell values.
2.  **Ghost Cells:** A one-cell wide layer of cells added around the boundary of each AMR grid box. These store values from adjacent grids or the next coarser level [S1].
3.  **Dual Grid Cell:** Defined by four vertices corresponding to the cell centers of the surrounding AMR box cells. In 3D, a dual cell is defined by 8 vertices (though the text focuses on 2D logic for Case 2, the 3D case table handles 3D tessellations) [S1].
4.  **Case Table:** Stores for each case:
    *   Number of sub-cases.
    *   Axes along which to check for identical parent level vertices (for sub-case determination).
    *   Tessellation data: lists of pyramids (P), wedges (W), tetrahedra (T), hexahedra (H), and irregular cells (I) [S1].

**Numbered Steps:**

1.  **Ghost Cell Initialization:** Extend each AMR grid (box) with a one-cell wide layer of ghost cells. Fill these ghost cells with values from adjacent grids or the next coarser level. This ensures all data required to construct stitch cells are available locally for each grid [S1].
    *   *Note:* If the simulation does not output ghost cells, the visualization tool must generate them. The coarse cell value is used to fill all ghost cells overlapping it [S1].
2.  **Neighborhood Identification:** For each ghost cell, determine the integer identifier of the neighboring box overlapping it, or -1 if there are none and the cell corresponds to the parent level [S1].
3.  **Iterate Dual Cells:** Iterate over all dual cells that contain at least one ghost cell or the original box [S1].
4.  **Compute Case Number:** Compute a case number analogous to Marching Cubes by setting bits in a 4-bit integer corresponding to refined vertices. Determine if a vertex is refined using the previously computed neighboring box information [S1].
5.  **Determine Sub-case (if applicable):** For cases requiring sub-case determination (e.g., Case 2), check along the specified axis (i or j) to determine if parent level vertices are identical.
    *   Use the modulo refinement ratio method. Let $i$ be the index of the dual cell's origin along an axis. The vertices are defined by box cells at indices $i$ and $i+1$.
    *   Formula: If $(i + 1) \pmod{\text{refinement\_ratio}} == 0$, the parent level vertices in that direction are different. If $(i + 1) \pmod{\text{refinement\_ratio}} \neq 0$, the parent level vertices are identical [S1].
6.  **Lookup Tessellation:** Look up the appropriate tessellation (pyramids, wedges, etc.) from the case table based on the case number and sub-case [S1].
7.  **Resolve Duplicate Stitch Cells:** To avoid creating the same stitch cell for multiple grids, assign the stitch cell to the grid with the lowest integer identifier. Discard any stitch cells that contain a vertex of a same-level patch with a lower integer identifier [S1].
8.  **Discard Ghost Results:** Discard the results generated from the ghost cells before rendering. Only the results from the regular (non-ghost) cells are kept [S1].

**Pseudocode:**

```python
def extract_isosurface(amr_boxes, isovalue, refinement_ratio):
    """
    Extracts crack-free isosurfaces from AMR data.
    
    Args:
        amr_boxes: List of Box objects. Each Box has:
            - id: integer identifier
            - extents: (min_i, min_j, min_k, max_i, max_j, max_k) in global cell indices
            - values: 3D array of cell-centered scalar values
            - ghost_values: 3D array of ghost cell values (initially empty)
            - neighbor_ids: map from ghost cell offset to neighbor box id
        isovalue: Scalar value for isosurface extraction
        refinement_ratio: Integer, e.g., 2
        
    Returns:
        List of triangles (vertices)
    """
    all_triangles = []
    
    # Step 1: Initialize Ghost Cells
    # This step assumes a prior function `initialize_ghost_cells` exists
    # which fills ghost_values based on adjacent boxes and coarser levels.
    # [G] Implementation detail: For a ghost cell at offset (di, dj, dk)
    # from a box boundary, find the overlapping box or parent cell.
    initialize_ghost_cells(amr_boxes)
    
    # Step 2 & 3: Iterate over all relevant dual cells
    # We process each box independently.
    for box in amr_boxes:
        box_triangles = []
        
        # Determine the range of dual cells to process.
        # A dual cell is defined by 4 (2D) or 8 (3D) surrounding box cells.
        # We need to process dual cells that contain at least one ghost cell
        # or the original box.
        # In 2D, a dual cell at (i, j) is defined by box cells (i,j), (i+1,j), (i+1,j+1), (i,j+1).
        # The box cells range from min_i to max_i.
        # Dual cells range from min_i-1 to max_i (since dual cell i uses i and i+1).
        # We must include ghost cells, so the range extends by 1 in each direction.
        
        min_i = box.extents.min_i - 1
        max_i = box.extents.max_i
        min_j = box.extents.min_j - 1
        max_j = box.extents.max_j
        min_k = box.extents.min_k - 1
        max_k = box.extents.max_k
        
        for i in range(min_i, max_i + 1):
            for j in range(min_j, max_j + 1):
                for k in range(min_k, max_k + 1):
                    
                    # Get the 8 vertices of the dual cell
                    # Vertices correspond to cell centers of surrounding box cells
                    vertices = []
                    for di in [0, 1]:
                        for dj in [0, 1]:
                            for dk in [0, 1]:
                                # Global index of the box cell
                                gi = i + di
                                gj = j + dj
                                gk = k + dk
                                
                                # Determine if this vertex is refined
                                # A vertex is refined if it belongs to a finer level box
                                # or if it is a ghost cell that overlaps a finer level box.
                                # The text says: "Whether a vertex is refined or not can be 
                                # determined using the previously computed neighboring box information."
                                # [G] Logic: Check if the global cell (gi, gj, gk) is covered
                                # by a finer level box. If so, it is refined.
                                is_refined = is_vertex_refined(gi, gj, gk, amr_boxes)
                                vertices.append(is_refined)
                    
                    # Step 4: Compute Case Number
                    # 4-bit integer, bit b set if vertex b is refined
                    case_number = 0
                    for b, is_ref in enumerate(vertices):
                        if is_ref:
                            case_number |= (1 << b)
                    
                    # Step 5: Determine Sub-case if needed
                    sub_case = 0
                    case_info = CASE_TABLE[case_number]
                    
                    if case_info.has_subcases:
                        # Check axes specified in case_info.axes_to_check
                        for axis in case_info.axes_to_check:
                            # Use modulo refinement ratio method
                            # If axis is i, check i+1
                            # If axis is j, check j+1
                            # If axis is k, check k+1
                            index_plus_one = i + 1 if axis == 'i' else (j + 1 if axis == 'j' else k + 1)
                            
                            if (index_plus_one % refinement_ratio) != 0:
                                # Parent level vertices are identical
                                # This affects the sub-case index
                                sub_case |= 1 # [G] Bitwise logic depends on specific case table definition
                            # Note: The text implies sub-case determination is more complex
                            # involving multiple axes. The case table stores which axes to check.
                            # For simplicity, we assume a single bit per axis check for now.
                            # In reality, Case 5 has 4 sub-cases.
                    
                    # Step 6: Lookup Tessellation
                    tessellation = case_info.get_tessellation(sub_case)
                    
                    # Step 7: Resolve Duplicate Stitch Cells
                    # Check if this stitch cell belongs to this box or a neighbor with lower ID
                    # A stitch cell belongs to the grid with the lowest integer identifier.
                    # Discard if it contains a vertex of a same-level patch with a lower ID.
                    # [G] Implementation: For each vertex in the tessellation, find the
                    # box ID that owns that vertex. If the minimum ID among same-level
                    # patches is lower than box.id, discard.
                    
                    min_neighbor_id = get_min_neighbor_id_for_dual_cell(i, j, k, amr_boxes)
                    if min_neighbor_id < box.id:
                        continue # Discard this stitch cell
                    
                    # Add triangles to result
                    for tri in tessellation:
                        # Get actual coordinates for the vertices
                        # Vertices are cell centers.
                        # [G] Need a function to convert global cell index to physical coordinates
                        v_coords = [get_cell_center(gi, gj, gk) for gi, gj, gk in tri]
                        box_triangles.extend(v_coords)
        
        all_triangles.extend(box_triangles)
        
    # Step 8: Discard Ghost Results
    # The pseudocode above processes dual cells including those in ghost zones.
    # However, the text says "Discard the results generated from the ghost cells".
    # This implies we should only keep triangles that are fully contained within
    # the regular cells of the box, or simply that the ghost cells are only used
    # to provide data for the boundary regular cells.
    # The text says: "Only the results from the regular (non-ghost) cells are kept".
    # In the dual grid approach, the "regular" dual cells are those fully inside
    # the box. Dual cells touching the ghost layer are used to generate stitch cells
    # at the boundary. The triangles generated from these boundary dual cells
    # are stitch cells. The triangles generated from internal dual cells are
    # standard MC triangles.
    # The text says "Discard the results generated from the ghost cells".
    # This likely means we do not render triangles that are *solely* within the
    # ghost zone, but stitch cells at the boundary are kept if they belong to this box.
    # The duplicate resolution step (Step 7) handles the ownership of stitch cells.
    # So, we keep all triangles generated by this box that passed the duplicate check.
    
    return all_triangles

def is_vertex_refined(gi, gj, gk, amr_boxes):
    """
    Determines if a global cell (gi, gj, gk) is refined (covered by a finer level box).
    """
    for box in amr_boxes:
        if box.level > 0: # Check finer levels
            if box.contains(gi, gj, gk):
                return True
    return False

def get_min_neighbor_id_for_dual_cell(i, j, k, amr_boxes):
    """
    Finds the minimum box ID among same-level patches that overlap the dual cell.
    """
    # [G] This requires checking the neighbor_ids map for the ghost cells
    # surrounding the dual cell.
    min_id = float('inf')
    # Check neighbors of the dual cell's vertices
    # If a vertex is a ghost cell, it has a neighbor_id.
    # If a vertex is a regular cell, its box ID is the box's ID.
    # We only care about same-level patches.
    # [G] Simplified: Iterate over the 8 vertices. If the vertex is in a ghost cell,
    # get its neighbor_id. If it's in a regular cell, get the box_id.
    # Filter for same-level boxes. Return min.

```

**Parameters:**
*   **Refinement Ratio:** An integer specifying how many child level cells a parent level cell contains along each axis. In the example data, the refinement ratio is 2 for all levels [S1].
*   **Ghost Cell Layer Width:** A one-cell wide layer of cells added around the boundary of each AMR grid box [S1].

**Edge Cases and Pitfalls:**
*   **T-junctions:** Cracks in the isosurface caused by re-sampling cell-centered AMR data to a vertex-centered representation for standard Marching Cubes. Solved by using dual grids (cell centers) instead [S1].
*   **Duplicate Stitch Cells:** Multiple grids might try to create the same stitch cell. This is handled by assigning the stitch cell to the grid with the lowest integer identifier and discarding cells containing a vertex of a same-level patch with a lower identifier [S1].
*   **Identical Parent Vertices:** When two parent level vertices map to the same parent level grid cell, a stitch cell must be generated connecting to that single vertex. This occurs when the modulo check indicates identical vertices [S1].
*   **Ghost Data Generation Bottleneck:** Runtime increases with core count due to increased inter-node communication, not just data volume. Communication time increases linearly with data transferred between nodes [S1].

## Operating characteristics
*   **Time Complexity:** Stitch cell generation scales well and consistently up to the largest tested number of tasks, composing the smallest runtime among pipeline phases [S1].
*   **Memory Complexity:** The method allows processing AMR data on a per-grid basis, avoiding the memory bottleneck of previous dual-grid approaches that required the entire dataset in a single processor's memory [S1].
*   **Measured Performance:**
    *   **Hydrogen Flame:** 2,581 boxes, 3 levels, 48,531,968 grid cells, 8.1GB data. Isosurface ~2.2 million triangles [S1].
    *   **Methane Flame:** 7,747 boxes, 3 levels, 1,525,420,032 grid cells, 592GB data. Isosurface ~29.7 million triangles [S1].
    *   **Hardware:** Cray X6 "Hopper" at NERSC, 6,384 nodes, 153,216 cores, AMD Magny-Cours 2.1GHz, 24 cores/node, 32GB/64GB RAM/node. Peak 1.28 Petaflops/s [S1].
*   **Scaling:** Strong scaling of stitch cell generation. Ghost data generation runtime is approximately flat up to 312 cores for the hydrogen flame problem, but increases significantly with core count due to inter-node communication (linear with data transferred) [S1].
*   **Strengths:** Produces continuous isosurfaces with no discontinuities. Parallelizable. Simplified implementation using case tables.
*   **Limitations:** Ghost data generation can become a bottleneck due to inter-node communication at high core counts. Requires at least one layer of grid cells between child level and parent level boundary for some AMR codes (BoxLib, Chombo satisfy this; Enzo may not without generalization) [S1].

## Background
The method was presented by H. Weber, H. Childs, and J. S. Meredith in 2012 [S1]. It builds on prior work utilizing dual grids and filling resulting gaps with stitch cells [S1]. Previous dual-grid approaches defined stitch cell generation procedurally with many special cases and required serial processing of the entire dataset [S1]. This method simplifies stitch cell generation using a case table and enables parallelization using ghost cells [S1]. It is designed for block-structured AMR simulation codes such as BoxLib, Chombo, SAM-RAI, and Enzo [S1].
