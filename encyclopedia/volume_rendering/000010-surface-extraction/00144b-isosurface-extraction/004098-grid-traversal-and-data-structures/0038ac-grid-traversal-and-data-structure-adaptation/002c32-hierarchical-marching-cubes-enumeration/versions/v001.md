# Hierarchical Marching Cubes Enumeration

Also called: Dual Marching Cubes Tree Traversal

## Overview
Hierarchical Marching Cubes Enumeration is a recursive octree traversal algorithm designed to extract isosurface meshes from volumetric data discretized by an octree. It solves the problem of adapting standard Marching Cubes to non-uniform spatial structures by explicitly enumerating voxel faces, edges, and vertices across potentially mismatched tree depths, delegating the actual mesh generation to a standard Marching Cubes routine only at leaf nodes [S1, unofficial]. It distinguishes itself from sibling methods by its explicit separation of traversal logic (face, edge, vertex enumeration) from the surface extraction logic, allowing for robust handling of arbitrary octree configurations without requiring a globally consistent grid [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** An octree root node, a scalar field function (or sampled values), and configuration parameters.
- **Output:** A mesh (list of vertices and triangles) representing the isosurface.

**Data Structures:**
The tree node structure contains the following fields [S1, unofficial]:
- `vector_type minimum_`: The minimum coordinate of the voxel.
- `config_type config_`: Configuration flags.
- `std::size_t grid_size_`: Size of the grid within the voxel.
- `scalar_type grid_width_`: Physical width of the grid.
- `vector<std::size_t, 3> size_`: Dimensions of the voxel in grid units.
- `std::vector<node_type*> children_`: Pointers to child nodes (if branch).
- `std::vector<boost::object_pool<branch_node_type>> branch_pool_`: Memory pool for branch nodes.
- `std::vector<boost::object_pool<leaf_node_type>> leaf_pool_`: Memory pool for leaf nodes.

**Parameters:**
- `grid_width`: Default 1.0 [S1, unofficial].
- `tolerance`: Default 0.1 [S1, unofficial].
- `maximum_depth`: Default `max(std::size_t)` [S1, unofficial].
- `nominal_weight`: Default 0.1 [S1, unofficial].

**Algorithm Steps:**
The algorithm uses three specialized recursive functions: `f_x`, `f_y`, `f_z` for faces; `e_xy`, `e_yz`, `e_xz` for edges; and `v` for vertices. These functions traverse the octree to gather the necessary geometric context for Marching Cubes.

1. **Face Enumeration (`f_x`, `f_y`, `f_z`):**
   - Takes two nodes (representing adjacent voxels sharing a face) and a receiver.
   - Checks if either node is a branch. If so, it recurses by mapping child indices to traverse the adjacent voxels.
   - For `f_x` (face perpendicular to X-axis), the recursion maps children as follows:
     - Child 2 with Child 0
     - Child 3 with Child 1
     - Child 6 with Child 4
     - Child 7 with Child 5
   - Similar mappings apply for `f_y` and `f_z` based on the face orientation.
   - If both nodes are leaves, it calls the Marching Cubes routine for the face.

2. **Edge Enumeration (`e_xy`, `e_yz`, `e_xz`):**
   - Takes four nodes (representing voxels sharing an edge) and a receiver.
   - Recurses on specific child index pairs to traverse the edge.
   - Eventually calls `enumerate_impl_v` with eight nodes.

3. **Vertex Enumeration (`v`):**
   - Takes eight nodes (representing the 8 voxels sharing a vertex) and a receiver.
   - If any node is a branch, it recurses with child indices `[7, 6, 5, 4, 3, 2, 1, 0]`.
   - If all eight nodes are leaves, it extracts vertex pointers and calls the standard Marching Cubes routine.

**Edge Cases and Pitfalls:**
- **Mismatched Tree Depths:** The algorithm handles this by using the ternary operator `b1 ? *b1->children()[i] : n1` to fall back to the current node `n1` when a child does not exist [S1, unofficial].
- **Boundary Conditions:** Care must be taken to handle voxels at the boundary of the domain, ensuring that missing neighbors are handled gracefully [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the octree depth and the number of leaves. In the worst case, it is proportional to the number of voxels in the octree.
- **Memory Complexity:** Proportional to the number of nodes in the octree.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales well with adaptive octrees, as it only processes relevant regions.
- **Strengths:** Robust handling of arbitrary octree structures, explicit separation of traversal and extraction logic.
- **Limitations:** Complexity of implementation, potential for cracks if not carefully handled.
- **When to use:** When working with adaptive octrees and needing robust isosurface extraction.
- **When not to use:** When a uniform grid is sufficient, or when performance is critical and the overhead of traversal is unacceptable.

## Background
The method originates from the "planaria/dmc" repository, an unofficial implementation of the Dual Marching Cubes algorithm [S1, unofficial]. It is part of a broader family of octree-based isosurfacing methods, building on the principles of hierarchical traversal and adaptive resolution.
