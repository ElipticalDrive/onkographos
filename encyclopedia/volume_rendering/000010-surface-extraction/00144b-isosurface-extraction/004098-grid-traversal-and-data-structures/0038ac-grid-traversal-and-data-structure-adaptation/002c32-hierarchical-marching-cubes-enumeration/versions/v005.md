# Hierarchical Marching Cubes Enumeration
Also called: Dual Marching Cubes Tree Traversal

## Overview
Hierarchical Marching Cubes Enumeration is a recursive octree traversal algorithm that extracts isosurface meshes by enumerating voxel faces, edges, and vertices, delegating the actual geometry generation to a standard Marching Cubes routine at leaf nodes [S1, unofficial]. It differs from [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) and [Sparse Marching Cubes](3825-sparse-marching-cubes.md) by explicitly separating the traversal logic into specialized functions for faces, edges, and vertices to ensure coherent mesh generation across hierarchical boundaries [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An octree data structure representing the scalar field, an isovalue threshold, and configuration parameters [S1, unofficial].
*   **Output:** A mesh (vertices and indices) generated by the underlying Marching Cubes implementation [S1, unofficial].

**Data Structures:**
The tree node structure contains the following fields [S1, unofficial]:
*   `vector_type minimum_`: Minimum coordinate of the node's domain.
*   `config_type config_`: Configuration settings for the node.
*   `std::size_t grid_size_`: Size of the grid represented by the node.
*   `scalar_type grid_width_`: Physical width of the grid.
*   `vector<std::size_t, 3> size_`: Dimensional size of the node.
*   `std::vector<node_type*> children_`: Pointers to child nodes.
*   `std::vector<boost::object_pool<branch_node_type>> branch_pool_`: Pool for branch nodes.
*   `std::vector<boost::object_pool<leaf_node_type>> leaf_pool_`: Pool for leaf nodes.

**Algorithm Steps:**
The algorithm uses specialized recursive functions for faces ($f_x, f_y, f_z$), edges ($e_{xy}, e_{yz}, e_{xz}$), and vertices ($v$) [S1, unofficial]. Each function takes two or more tree nodes and a receiver, checks if any node is a branch, and recurses with mapped child indices [S1, unofficial].

1.  **Face Enumeration ($f_x$):**
    *   Takes two nodes (representing adjacent voxels along the x-axis) [S1, unofficial].
    *   Checks if either node is a branch [S1, unofficial].
    *   If so, recurses with mapped child indices [S1, unofficial].
    *   The recursion maps child indices to traverse adjacent voxels: children[2] with children[0], children[3] with children[1], children[6] with children[4], children[7] with children[5] [S1, unofficial].
    *   If both nodes are leaves, it extracts vertex pointers and calls the Marching Cubes routine for the face [S1, unofficial].

2.  **Edge Enumeration ($e_{xy}, e_{yz}, e_{xz}$):**
    *   Takes four nodes (representing voxels sharing an edge) [S1, unofficial].
    *   Recurses on specific child index pairs [S1, unofficial].
    *   Eventually calls `enumerate_impl_v` with eight nodes [S1, unofficial].

3.  **Vertex Enumeration ($v$):**
    *   Takes eight nodes (representing the eight corners of a voxel) [S1, unofficial].
    *   If any node is a branch, it recurses with child indices `[7, 6, 5, 4, 3, 2, 1, 0]` [S1, unofficial].
    *   If all nodes are leaves, it extracts vertex pointers and calls the standard Marching Cubes routine [S1, unofficial].

**Parameters:**
*   `grid_width`: Default 1.0 [S1, unofficial].
*   `tolerance`: Default 0.1 [S1, unofficial].
*   `maximum_depth`: Default `max(std::size_t)` [S1, unofficial].
*   `nominal_weight`: Default 0.1 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Mismatched Tree Depths:** Handled by using the ternary operator `b1 ? *b1->children()[i] : n1` to fall back to the current node `n1` when a child does not exist [S1, unofficial].
*   **Boundary Conditions:** The recursion must handle cases where nodes at the boundary of the volume do not have all eight neighbors [S1, unofficial]. The fallback mechanism ensures that missing neighbors are treated as the current node or handled appropriately to avoid segmentation faults [S1, unofficial].
