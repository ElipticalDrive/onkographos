# Hierarchical Marching Cubes Enumeration

Also called: Dual Marching Cubes Tree Traversal

## Overview
Hierarchical Marching Cubes Enumeration is a recursive octree traversal algorithm that extracts isosurface meshes by enumerating voxel faces, edges, and vertices, delegating to a standard Marching Cubes routine at leaf nodes [S1, unofficial]. It differs from [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) and [Sparse Marching Cubes](3825-sparse-marching-cubes.md) by explicitly traversing the hierarchical structure to gather the eight corner nodes for each cube, rather than relying on sparse grid lookups or fixed-depth octree constraints [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: An octree data structure representing the volume, an isovalue, and configuration parameters.
- Output: A mesh (vertices and indices) generated by the underlying Marching Cubes implementation.

**Data Structures:**
The tree node structure contains the following fields [S1, unofficial]:
- `vector_type minimum_`: Minimum coordinate of the voxel.
- `config_type config_`: Configuration flags.
- `std::size_t grid_size_`: Size of the grid.
- `scalar_type grid_width_`: Width of the grid.
- `vector<std::size_t, 3> size_`: Dimensions of the voxel.
- `std::vector<node_type*> children_`: Pointers to child nodes.
- `std::vector<boost::object_pool<branch_node_type>> branch_pool_`: Pool for branch nodes.
- `std::vector<boost::object_pool<leaf_node_type>> leaf_pool_`: Pool for leaf nodes.

**Parameters:**
- `grid_width`: Default 1.0 [S1, unofficial].
- `tolerance`: Default 0.1 [S1, unofficial].
- `maximum_depth`: Default `max std::size_t` [S1, unofficial].
- `nominal_weight`: Default 0.1 [S1, unofficial].

**Algorithm Steps:**
The algorithm uses specialized recursive functions for faces (`f_x`, `f_y`, `f_z`), edges (`e_xy`, `e_yz`, `e_xz`), and vertices (`v`). Each function takes two or more tree nodes and a receiver, checks if any node is a branch, and recurses with mapped child indices [S1, unofficial].

1. **Face Enumeration (`f_x`, `f_y`, `f_z`):**
   - Takes two tree nodes.
   - Checks if any node is a branch.
   - Recurses with mapped child indices. For `f_x`, the mapping is: children[2] with children[0], children[3] with children[1], children[6] with children[4], children[7] with children[5] [S1, unofficial].

2. **Edge Enumeration (`e_xy`, `e_yz`, `e_xz`):**
   - Takes four tree nodes.
   - Recurses on specific child index pairs.
   - Eventually calls `enumerate_impl_v` with eight nodes [S1, unofficial].

3. **Vertex Enumeration (`v`):**
   - Takes eight tree nodes.
   - If any are branches, it recurses with child indices `[7, 6, 5, 4, 3, 2, 1, 0]` [S1, unofficial].
   - If all are leaves, it extracts vertex pointers and calls `marching_cubes` [S1, unofficial].

**Pseudocode:**
```python
def enumerate_impl_f_x(node1, node2, receiver):
    # Check if nodes are branches
    if node1.is_branch() or node2.is_branch():
        # Recurse with mapped child indices
        # Mapping: children[2] with children[0], children[3] with children[1],
        # children[6] with children[4], children[7] with children[5]
        enumerate_impl_f_x(node1.children[2], node2.children[0], receiver)
        enumerate_impl_f_x(node1.children[3], node2.children[1], receiver)
        enumerate_impl_f_x(node1.children[6], node2.children[4], receiver)
        enumerate_impl_f_x(node1.children[7], node2.children[5], receiver)
    else:
        # Both are leaves, process face
        receiver.process_face(node1, node2)

def enumerate_impl_e_xy(node1, node2, node3, node4, receiver):
    # Check if nodes are branches
    if any(n.is_branch() for n in [node1, node2, node3, node4]):
        # Recurse with specific child index pairs
        # This eventually leads to enumerate_impl_v
        enumerate_impl_e_xy(node1.children[0], node2.children[0], node3.children[0], node4.children[0], receiver)
        # ... other recursive calls based on edge type ...
    else:
        # All leaves, call vertex enumeration
        enumerate_impl_v(node1, node2, node3, node4, node1, node2, node3, node4, receiver)

def enumerate_impl_v(n0, n1, n2, n3, n4, n5, n6, n7, receiver):
    # Check if any node is a branch
    if any(n.is_branch() for n in [n0, n1, n2, n3, n4, n5, n6, n7]):
        # Recurse with child indices [7, 6, 5, 4, 3, 2, 1, 0]
        enumerate_impl_v(n0.children[7], n1.children[6], n2.children[5], n3.children[4],
                         n4.children[3], n5.children[2], n6.children[1], n7.children[0], receiver)
    else:
        # All leaves, extract vertex pointers and call marching_cubes
        vertices = [n.get_vertex() for n in [n0, n1, n2, n3, n4, n5, n6, n7]]
        receiver.marching_cubes(vertices)
```

**Edge Cases and Pitfalls:**
- Handles mismatched tree depths or boundary conditions by using the ternary operator `b1 ? *b1->children()[i] : n1` to fall back to the current node `n1` when a child does not exist [S1, unofficial].

## Operating characteristics
- Time Complexity: Depends on the depth of the octree and the number of leaf nodes. Recursive traversal ensures that only relevant parts of the volume are processed.
- Memory Complexity: Proportional to the size of the octree structure.
- Strengths: Efficiently handles large volumes by skipping empty regions.
- Limitations: Complexity of implementation due to recursive face/edge/vertex enumeration.
- When to use: When dealing with large, sparse volumes where hierarchical traversal can significantly reduce computation.
- When not to use: For dense, small volumes where the overhead of tree traversal may not be justified.

## Background
The method originates from the `planaria/dmc` repository [S1, unofficial]. It is an implementation of hierarchical Marching Cubes, leveraging octree structures for efficient isosurface extraction.
