# Recursive Edge Enumeration (Quadtree)
Also called: faceProc/edgeProc enumeration
## Overview
Recursive Edge Enumeration is a hierarchical traversal algorithm that identifies minimal edges shared by leaf nodes in a quadtree to extract isosurface segments. It solves the problem of efficiently enumerating geometric primitives in adaptive grids without redundant checks. It sets itself apart from sibling methods by using mutually recursive functions (`faceProc` and `edgeProc`) to propagate edge-adjacency constraints down the tree, ensuring that only the finest shared edges are processed [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** A quadtree data structure representing the volume, where each node $q$ has four children (North, South, East, West) and a classification (interior or leaf).
*   **Output:** A list of isosurface segments, each associated with a minimal edge shared by two leaf nodes.

**Data Structures:**
The quadtree node $q$ contains:
*   `is_leaf`: Boolean flag.
*   `children`: Array of 4 references to child nodes, ordered spatially (e.g., [NW, NE, SW, SE]).
*   `edge_adjacency`: Implicit via spatial position; children $i$ and $j$ are edge-adjacent if they share a grid edge.

**Algorithm Steps:**
The method relies on two mutually recursive functions: `faceProc` and `edgeProc`.

1.  **Initialization:** Call `faceProc[root]` on the root node of the quadtree.

2.  **`faceProc[q]` (Face Processing):**
    *   **Case 1: $q$ is a leaf.** Do nothing. The algorithm relies on `edgeProc` to handle leaf-level edge generation.
    *   **Case 2: $q$ is an interior node.**
        *   For each child $c_i$ in `children` ($i=0..3$):
            *   Recursively call `faceProc[c_i]`.
        *   For each pair of edge-adjacent children $(c_i, c_j)$:
            *   Recursively call `edgeProc[c_i, c_j]`.
            *   *Note:* In a standard quadtree, there are 4 such pairs (e.g., NW-NE, NE-SE, SE-SW, SW-NW).

3.  **`edgeProc[q1, q2]` (Edge Processing):**
    *   **Termination Condition:** If both $q_1$ and $q_2$ are leaves:
        *   Generate the isosurface segment for the minimal edge shared by $q_1$ and $q_2$.
        *   Return.
    *   **Recursive Step:** If at least one of $q_1$ or $q_2$ is an interior node:
        *   Identify the two pairs of edge-adjacent children spanning the common edge between $q_1$ and $q_2$. Let $q_1$ have children $c_{1a}, c_{1b}$ and $q_2$ have children $c_{2a}, c_{2b}$ such that $(c_{1a}, c_{2a})$ and $(c_{1b}, c_{2b})$ are the new edge-adjacent pairs.
        *   Recursively call `edgeProc[c_{1a}, c_{2a}]`.
        *   Recursively call `edgeProc[c_{1b}, c_{2b}]`.

## Subtopics

### Recursive Edge Enumeration (Octree)
This variant extends the quadtree method to 3D octrees. It requires three mutually recursive functions: `cellProc[q]`, `faceProc[q1, q2]`, and `edgeProc[q1, q2, q3, q4]`. `cellProc` spawns 8 `cellProc`, 12 `faceProc`, and 6 `edgeProc` calls. `faceProc` spawns 4 `faceProc` and 4 `edgeProc` calls. `edgeProc` spawns 2 `edgeProc` calls. Termination occurs when all four nodes in `edgeProc` are leaves, representing the minimal edges of the octree [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear in the size of the quadtree. There is exactly one call to `faceProc` for each square (node) in the quadtree and one call to `edgeProc` for each edge in the quadtree [S1, unofficial].
*   **Memory Complexity:** Proportional to the depth of the recursion stack, which is $O(\log N)$ for a balanced quadtree of $N$ nodes.
*   **Strengths:** Efficiently enumerates only the necessary geometric primitives for isosurface extraction in hierarchical data. Avoids redundant processing of internal edges.
*   **Limitations:** The logic for determining child adjacency (`get_edge_adjacent_child_pairs`) can be complex to implement correctly, especially for irregular or non-standard quadtree layouts. The octree variant requires managing more complex state (4 nodes) for edge processing.

## Background
The method was proposed in the context of dual contouring of Hermite data, specifically for contouring hierarchical structures like quadtrees and octrees. It addresses the need for topology-safe simplification and efficient mesh generation from adaptive grids [S1, unofficial].
