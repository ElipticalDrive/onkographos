# Sparse Marching Cubes

Also called: Sparse Marching Cubes from Points, Sparse-MC

## Overview
Sparse Marching Cubes (Sparse-MC) is a surface reconstruction method that extracts the zero-level set from signed distance values at the eight corners of surface-intersecting (active) voxels to produce a watertight surface [S1, S2, unofficial]. Unlike standard Marching Cubes which requires a dense 3D grid, Sparse-MC operates on an explicitly defined set of voxel coordinates and their corner scalar values, avoiding the memory overhead of dense grids [S2, unofficial]. It is distinguished from [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) by its explicit handling of sparse voxel lists rather than hierarchical tree structures, and from [Hierarchical Marching Cubes Enumeration](5223-hierarchical-marching-cubes-enumeration.md) by its direct application of the standard MC algorithm to a flat list of active voxels [S2, unofficial].

## How it works
Sparse-MC generates a triangle mesh (trimesh) from a sparse set of voxels defined by integer coordinates and scalar values at their 8 corners [S2, unofficial]. It performs sparse marching cubes from a sparse grid of scalar values by constructing the 8 corner values for each voxel via lookup in the provided sparse grid [S2, unofficial]. The method extracts an iso-surface mesh from sparse voxel data using the standard marching cubes algorithm, outputting vertices and triangular faces [S2, unofficial].

### Inputs and Outputs
**Inputs:**
1.  `coords`: Integer tensor of shape $[N, 3]$ containing the $(x, y, z)$ coordinates of the active voxels [S2, unofficial].
2.  `corners`: Float tensor of shape $[N, 8]$ containing the scalar values at the 8 corners of each voxel [S2, unofficial].
3.  `iso`: Float value representing the iso-level to contour at [S2, unofficial].
4.  `ensure_consistency`: Boolean flag; if True, averages corner values at shared locations to ensure a consistent mesh [S2, unofficial].

*Alternative Input Form (from Points):*
1.  `coords`: Integer tensor of shape $[N, 3]$ with coordinates of active voxels (also the points with defined scalar values) [S2, unofficial].
2.  `point_values`: Float tensor of shape $[N]$ or $[N, 1]$ with scalar value at each coordinate in `coords` [S2, unofficial].
3.  `default_value`: Float value assumed for corner points not in the input `coords`; should be known to be completely inside or outside the surface [S2, unofficial].

**Outputs:**
1.  `verts`: Float tensor of shape $[V, 3]$ with vertex positions [S2, unofficial].
2.  `tris`: Int tensor of shape $[T, 3]$ with triangle indices [S2, unofficial].

### Data Structures
The method relies on two primary input tensors:
*   **Voxel Coordinates**: A list of $N$ unique integer triplets $(x, y, z)$ identifying the active voxels in the grid [S2, unofficial].
*   **Corner Values**: For each voxel $i \in [0, N-1]$, an array of 8 floats representing the scalar field values (e.g., SDF) at the voxel's 8 corners [S2, unofficial]. The corner ordering follows the standard Marching Cubes convention (typically 0-7 corresponding to binary indices of corner presence) [S2, unofficial].

If inputs are provided as point values (`sparse_marching_cubes_from_points`), the method internally constructs the `corners` tensor by gathering values from the sparse point set for all 8 corners of each active voxel [S2, unofficial].

### Algorithm Steps

1.  **Gather Corner Values (if using Points input):**
    If the input is `coords` and `point_values`, construct the `corners` tensor of shape $[N, 8]$. For each voxel $i$ at `coords[i]`, determine the integer coordinates of its 8 corners [S2, unofficial]. Look up the scalar value for each corner in the `point_values` map [S2, unofficial]. If a corner coordinate is not present in `coords`, assign `default_value` [S2, unofficial].

2.  **Ensure Consistency (Optional):**
    If `ensure_consistency` is True, identify all unique corner coordinates across all active voxels [G]. For each unique corner, compute the average of the scalar values assigned to it by all adjacent active voxels [G]. Update the `corners` tensor with these averaged values to ensure shared corner values across adjacent voxels, producing a seamless watertight reconstruction [S1, S2, unofficial].

3.  **Compute Cube Indices:**
    For each voxel $i$, determine the Marching Cubes case index [G]. Compare each of the 8 corner values $v_j$ against the `iso` level [G].
    $$
    \text{bit}_j = \begin{cases} 
    1 & \text{if } v_j < \text{iso} \\
    0 & \text{otherwise}
    \end{cases}
    $$
    The cube index $C_i$ is the sum of bits weighted by powers of 2:
    $$
    C_i = \sum_{j=0}^{7} \text{bit}_j \cdot 2^j
    $$
    This results in an integer tensor of shape $[N]$ [S2, unofficial].

4.  **Interpolate Vertices:**
    For each voxel $i$ with case index $C_i \neq 0$ and $C_i \neq 255$:
    a. Identify the edges of the voxel that intersect the iso-surface based on $C_i$ [G].
    b. For each intersecting edge, calculate the intersection point by linear interpolation between the two corner values of that edge [G].
    c. Store the 3D coordinates of these intersection points [G].

5.  **Generate Triangles:**
    For each voxel $i$, use the standard Marching Cubes lookup table corresponding to $C_i$ to determine which edges form triangles [G]. Map the interpolated edge intersection points to triangle vertices [G]. Output the triangle indices relative to the global vertex list [S2, unofficial].

6.  **Output Mesh:**
    Return the global list of vertex positions `verts` and triangle indices `tris` [S2, unofficial].

### Parameters
*   `iso`: The iso-level to contour at. Typical value is 0.0 for Signed Distance Fields (SDFs) [S2, unofficial].
*   `default_value`: The value used if a voxel corner does not exist in the provided point set. Default is 1.0 [S2, unofficial]. This value should be known to be completely inside or outside the surface to avoid spurious geometry [S2, unofficial].
*   `ensure_consistency`: Boolean flag to enforce topological consistency in the generated mesh, defaults to false [S2, unofficial].

### Edge Cases and Pitfalls
*   **Missing Corners**: If a corner of an active voxel is not present in the input point set, a `default_value` must be provided. Choosing an inappropriate default value (e.g., one that crosses the iso-level incorrectly) can introduce artifacts [S2, unofficial].
*   **Inconsistent Corner Values**: Adjacent voxels may have different scalar values for the same shared corner if `ensure_consistency` is False. This can lead to non-watertight meshes or visual seams [S1, S2, unofficial].

## Subtopics

### Sparse Marching Cubes from SRF
Extracts 3D meshes from Sparse Radiance Fields (SRFs) by performing one pass of Marching Cubes on the 3D voxel space [S3]. Since SRF representations like SPARF and SuRFNet lie on the 3D voxel's space, extracting the mesh is straightforward with a single MC pass [S3]. This variant is specifically tailored for neural radiance field outputs that are discretized into sparse voxels [S3].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of active voxels $N$, $O(N)$, as it only processes surface-intersecting voxels [S2, unofficial].
*   **Memory Complexity**: Linear with respect to $N$, storing only the coordinates and corner values of active voxels, avoiding the $O(H^3)$ memory cost of dense grids where $H$ is grid resolution [S2, unofficial].
*   **Performance**: CUDA-accelerated implementations leverage massive parallelism to process thousands of voxels simultaneously [S2, unofficial].
*   **Strengths**: Ideal for sparse SDF representations where only a list of points and their SDF values are available [S2, unofficial]. Avoids the memory overhead of dense 3D grids [S2, unofficial].
*   **Limitations**: Requires explicit voxel coordinates and corner values; does not automatically handle hierarchical data structures like octrees [S2, unofficial]. Consistency can be enforced via the `ensure_consistency` flag, which averages corner values at shared locations [S2, unofficial].

## Background
Sparse Marching Cubes (Sparse-MC) reconstructs watertight surfaces by extracting the zero-level set from signed distance values at the eight corners of surface-intersecting (active) voxels [S1, unofficial]. These corner values jointly encode the topology and geometry of the enclosed surface patch [S1, unofficial]. The method is based on the standard Marching Cubes algorithm [37] but adapted for sparse data structures [S1, S2, unofficial]. It is used in applications such as P2Voxel for pyramid pivot voxelization [S1, unofficial] and in sparse radiance field rendering like SPARF and SuRFNet [S3].
