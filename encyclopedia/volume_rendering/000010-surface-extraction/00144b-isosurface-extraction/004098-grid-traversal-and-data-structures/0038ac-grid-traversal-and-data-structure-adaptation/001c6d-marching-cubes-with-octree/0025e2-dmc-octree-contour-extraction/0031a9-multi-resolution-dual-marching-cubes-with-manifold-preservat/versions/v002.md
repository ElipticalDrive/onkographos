# Multi-Resolution Dual Marching Cubes with Manifold Preservation

Also called: Dual Surface Extraction on Generalized Octrees, MR-DMC

## Overview
Multi-Resolution Dual Marching Cubes with Manifold Preservation (MR-DMC) generates closed, manifold meshes from segmented volumetric data using a generalized octree [S1, unofficial]. It extends Dual Marching Cubes (DMC) by introducing a cell-based criterion for dual vertex generation to prevent non-manifold configurations, specifically resolving ambiguities where standard DMC cases 17 and 20 share an ambiguous face [S1, unofficial]. Unlike Manifold Dual Contouring (MDC), which uses a bottom-up strategy, MR-DMC employs a top-down refinement strategy suitable for large datasets, and unlike standard DMC, it guarantees manifold surfaces without post-processing [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   Indicator function $F(\mathbf{x}): \mathbb{R}^3 \rightarrow \mathbb{R}$, where $F(\mathbf{x}) = 1$ if $\mathbf{x}$ is inside the segmented object and $0$ otherwise [S1, unofficial].
*   Root cell of the octree $c$ [S1, unofficial].
*   `minLevel`: Minimal subdivision level of the octree [S1, unofficial].
*   `maxLevel`: Maximal subdivision level of the octree [S1, unofficial].
*   $\delta$: Curvature threshold parameter for subdivision, $\delta \in [0, 1]$ [S1, unofficial].

**Outputs:**
*   An octree regular until level `minLevel` and adaptive between `minLevel` and `maxLevel` [S1, unofficial].
*   A multi-resolution, closed manifold surface mesh [S1, unofficial].

### Data Structures
**Octree Cell Data:**
Each octree cell stores initial and final cell coordinates, cell corner values, and a collapsed flag [S1, unofficial]. The structure uses a Morton Code for compact integer representation of hierarchical relationships and position [S1, unofficial]. An iterative `toProcess` list manages the top-down traversal [S1, unofficial].

### Definitions
*   **Cell $c$**: A graph $c = \{V, E\}$ with eight vertices $V = \{v_0, \dots, v_7\}$ and twelve edges $E = \{e_0, \dots, e_{11}\}$ with cube connectivity [S1, unofficial].
*   **Solid Vertex**: A cell vertex inside the volume where $F(\mathbf{x}) = 1$ [S1, unofficial]. The set of solid vertices in cell $c$ is $S(c)$ [S1, unofficial].
*   **Empty Vertex**: A cell vertex outside the volume where $F(\mathbf{x}) = 0$ [S1, unofficial]. The set of empty vertices in cell $c$ is $E(c)$ [S1, unofficial].
*   **Solid-Edge**: An edge whose two endpoints are solid vertices [S1, unofficial].
*   **Empty-Edge**: An edge whose two endpoints are empty vertices [S1, unofficial].
*   **Intersection-Edge**: An edge with one solid endpoint and one empty endpoint [S1, unofficial].
*   **Ambiguous Face**: A face containing two interleaved solid vertices [S1, unofficial].
*   **Connected Component $\phi(c)_s$**: A sub-graph of solid vertices in cell $c$ where all two solid vertices are connected by a path of solid-edges [S1, unofficial]. $|\phi(c)_s|$ denotes the number of solid connected components [S1, unofficial].
*   **Connected Component $\phi(c)_e$**: A sub-graph of empty vertices in cell $c$ where all two empty vertices are connected by a path of empty-edges [S1, unofficial]. $|\phi(c)_e|$ denotes the number of empty connected components [S1, unofficial].
*   **Dual Vertices $D(c)$**: The set of dual vertices generated inside cell $c$ [S1, unofficial].
*   **Complex Face**: A face that intersects $F(\mathbf{x})$, has all vertices either inside or outside $F(\mathbf{x})$, AND at least one of its edges intersects $F(\mathbf{x})$ more than once [S1, unofficial].
*   **Complex Cell**: A cell $C$ is complex if at least one of its faces is complex [S1, unofficial].
*   **Homogeneous Cell**: A cell where all corners are either inside or outside $F(\mathbf{x})$ [S1, unofficial].
*   **Non-Homogeneous Cell**: A cell that is not homogeneous [S1, unofficial].

### Algorithm Steps

#### 1. Octree Construction (Top-Down Refinement)
The octree is built iteratively using a top-bottom refinement strategy suitable for large datasets [S1, unofficial]. Cells are subdivided if they are inhomogeneous or complex, unless they have reached `maxLevel` [S1, unofficial]. The source pseudocode uses `isNotPlanar` to trigger subdivision, where a planar cell refers to a homogeneous cell with no surface intersection [S1, unofficial]. If a cell is inhomogeneous (has both solid and empty vertices), it is not planar and must be subdivided unless it is complex [S1, unofficial]. The source states: "If a cell C is inhomogeneous or is complex, it has to be subdivided" [S1, unofficial]. The algorithm checks `isNotComplex` first; if not complex, it checks `isNotPlanar` [S1, unofficial]. If `isNotPlanar` is true (inhomogeneous), it subdivides [S1, unofficial]. If `isNotPlanar` is false (planar/homogeneous), it marks the cell as a leaf and collapsed [S1, unofficial].

**Pseudocode:**
```python
def build_octree(root_cell, min_level, max_level, delta):
    to_process = [root_cell]
    
    while to_process:
        current_cell = to_process.pop(0)
        
        # Check if we can subdivide further (corrected from garbled source condition)
        if current_cell.level < max_level:
            if not is_not_complex(current_cell):
                # Cell is complex -> Subdivide
                subdivide(current_cell, to_process)
            elif is_not_planar(current_cell):
                # Cell is inhomogeneous but not complex -> Subdivide
                subdivide(current_cell, to_process)
            else:
                # Cell is homogeneous and not complex -> Mark as leaf and collapsed
                mark_as_leaf_collapsed(current_cell)
        else:
            # Reached max level -> Mark as leaf and collapsed
            mark_as_leaf_collapsed(current_cell)

def subdivide(cell, queue):
    # Divide cell into 8 children
    children = divide(cell)
    for child in children:
        queue.append(child)

def is_not_complex(cell):
    # A cell is complex if at least one face is complex
    for face in cell.faces:
        if is_complex_face(face):
            return False
    return True

def is_complex_face(face):
    if not intersects_surface(face):
        return False
    if not all_vertices_same_side(face):
        return False
    if not any_edge_intersects_more_than_once(face):
        return False
    return True

def intersects_surface(face):
    # Face intersects F(x) if it contains intersection-edges
    return len(face.intersection_edges) > 0

def all_vertices_same_side(face):
    # All vertices are either solid or empty
    return len(face.solid_vertices) == 0 or len(face.solid_vertices) == 4

def any_edge_intersects_more_than_once(face):
    # Check for multiple zero-crossings along any edge using Hermite data or dense sampling [G]
    for edge in face.edges:
        if count_sign_changes(edge) > 1:
            return True
    return False

def is_not_planar(cell):
    # Returns True if cell is inhomogeneous (has both solid and empty vertices)
    return len(cell.solid_vertices) > 0 and len(cell.solid_vertices) < 8

def mark_as_leaf_collapsed(cell):
    cell.is_leaf = True
    cell.is_collapsed = True

def divide(cell):
    # Standard octree subdivision returning 8 child cells
    return [create_child(cell, i) for i in range(8)]

def count_sign_changes(edge):
    # Standard step to count zero-crossings along an edge [G]
    return 1 if (edge.v0_value * edge.v1_value < 0) else 0
```

#### 2. Multi-Resolution Refinement (Curvature Criterion)
Cells are subdivided based on curvature to adapt resolution to the geometry of the boundary $\partial V$ [S2]. 

**Criterion 1:**
Let $C$ be a cell and $I_i$ ($i=0 \dots n$) be its intersection points with $F(\mathbf{x})$ [S1, unofficial]. Let $n_i$ be the normals at $I_i$ [S1, unofficial]. If $\max_{i \neq j} (n_i \cdot n_j) > \delta$, $C$ must be subdivided [S1, unofficial].
*   $\delta \in [0, 1]$ [S1, unofficial].
*   $\delta \to 0$ produces an almost regular mesh [S1, unofficial].
*   $\delta \to 1$ generates a highly simplified surface, potentially losing sharp features [S1, unofficial].

#### 3. Dual Vertex Generation (Manifold Preservation)
Dual vertices are generated in cells that intersect the surface [S1, unofficial]. The algorithm considers at most four surface components inside a single cell, where every component must have a single connected boundary and be well approximated by a plane [S2].

**Rule 1:** Dual vertices are only created in cells where $0 < |S(c)| < 8$ [S1, unofficial].

**Rule 2:** If $|S(c)| < 5$, then $|D(c)| = |\phi(c)_s|$ [S1, unofficial]. If $|S(c)| \ge 5$, then $|D(c)| = |\phi(c)_e|$ [S1, unofficial].

**Rule 3:** For a non-homogeneous cell, every dual vertex $d_i \in D(c)$ generated from a solid connected component $\phi(c)_s$ is associated with the set of intersection-edges that leave $\phi(c)_s$ [S1, unofficial]. Similarly for empty components $\phi(c)_e$ [S1, unofficial].

**Rule 4 (Manifold Preservation):** If cell $c$ is marked with a component (solid/empty), generate dual vertices using that component [S1, unofficial]. Otherwise, use Rules 1-3 to determine the component (solid or empty) to be used [S1, unofficial]. If $c$ has ambiguous faces, mark every adjacent cell through an ambiguous face with the component that has been used for $c$ [S1, unofficial]. This rule spreads the topological choice through ambiguous faces to ensure manifold correctness, specifically resolving cases 17 and 20 of the DMC look-up table [S1, unofficial].

### Parameters
*   **$\delta$**: Curvature threshold, $[0, 1]$ [S1, unofficial].
*   **minLevel**: Minimal subdivision level [S1, unofficial].
*   **maxLevel**: Maximal subdivision level [S1, unofficial].

### Edge Cases and Pitfalls
*   **Non-manifold configurations**: Standard DMC can produce non-manifold edges when cases 17 and 20 of the look-up table share a common ambiguous face [S1, unofficial]. MR-DMC prevents this via Rule 4 [S1, unofficial].
*   **Sharp features**: If $\delta \to 1$, the generated surface may lose sharp features due to excessive simplification [S1, unofficial].
*   **Collapsed cells**: Cells that have not been subdivided until the maximal octree depth are marked as collapsed [S1, unofficial].
*   **Complex cells**: Complex cells (containing surface pieces smaller than the current subdivision level) must be subdivided to ensure all intersected cells are processed [S1, unofficial].

## Operating characteristics
*   **Strategy**: Top-bottom refinement, suitable for large datasets [S1, unofficial].
*   **Manifold Guarantee**: Guarantees manifold surfaces by introducing a cell-based criterion for dual vertex generation, avoiding post-processing repairs [S1, unofficial].
*   **Complexity**: Not given in the sources.
*   **Performance**: Not given in the sources.
*   **Strengths**: Generates multi-resolution, closed manifold surfaces; handles large datasets efficiently via top-down approach; no post-processing needed for manifold repair [S1, unofficial].
*   **Limitations**: High $\delta$ can lose sharp features; requires segmented volumetric data (indicator function) [S1, unofficial].
