# Linear Hashed Marching Cubes

## Overview
Linear Hashed Marching Cubes is a surface extraction method that converts volumetric isosurfaces into triangle meshes by applying the Marching Cubes algorithm over a linear hashed octree data structure [S1, unofficial]. It serves as a loose implementation of the "Fast Generation of Pointerless Octree Duals" technique, designed to accelerate mesh generation compared to standard grid-based marching cubes [S1, unofficial].

## How it works
**Inputs:**
- A volumetric scalar field (implicit function) [S1, unofficial].
- An isovalue threshold for surface extraction [S1, unofficial].
- `max_depth`: The maximum depth of the internal octree, defining the resolution limit. The tree spans a cubic grid of size $2^{\text{max\_depth}}$ in each direction [S1, unofficial].

**Outputs:**
- A triangle mesh containing vertices and indices representing the isosurface [S1, unofficial].

**Data Structures:**
1. **ImplicitOctree**: A linear hashed octree traversal structure that replaces the standard `PrimalGrid` [S1, unofficial]. Nodes are indexed using `MortonKey` (Z-order curve keys) rather than `GridKey` (3D integer coordinates) [S1, unofficial].
2. **MeshTopologyBuilder**: Accumulates vertex positions and face indices, storing vertices with associated `MortonKey` identifiers to facilitate adjacency or deduplication logic [S1, unofficial].

**Algorithm Steps:**

1. **Initialization**: Create an `ImplicitOctree` instance with the specified `max_depth` and a `MeshTopologyBuilder` [S1, unofficial].
2. **Tree Traversal**: Traverse the `ImplicitOctree` [S1, unofficial]. For each visited cube, retrieve the corner keys, corner coordinates, and corner scalar values [S1, unofficial].
3. **Cube Classification**: Classify the cube corners based on their signed distance values to determine the cube index [S1, unofficial]. Let $v_i$ be the value at corner $i$ and $I$ be the isovalue [G]. If $v_i < I$, the corner is inside; otherwise, it is outside [G]. The cube index is the bitmask formed by these 8 comparisons [G].
4. **Edge Intersection Calculation**: Find the 12 edge crossing vertices for the cube using the cube index, corners, and values [S1, unofficial]. For each crossed edge connecting corners $A$ and $B$ with values $v_A$ and $v_B$, calculate the intersection point $P$ using linear interpolation:
   $$ P = A + \frac{I - v_A}{v_B - v_A} (B - A) $$
   [G].
5. **Mesh Generation (Marching)**: March the cube by iterating through the triangles defined by the cube index [S1, unofficial]. For each triangle $(a, b, c)$, add vertices to the mesh builder with MortonKey identifiers and the calculated vertex positions, then add the face [S1, unofficial].
6. **Finalization**: After traversal completes, build the mesh and extract indices to the extractor [S1, unofficial].

**Pseudocode:**

```python
def linear_hashed_marching_cubes(field, isovalue, max_depth):
    # [G] Standard Marching Cubes lookup tables
    # MARCHING_CUBES_EDGES: 12 edges, each is a pair of corner indices (0-7)
    # MARCHING_CUBES_TRIANGLES: up to 5 triangles per cube index, each is a triplet of edge indices (0-11)
    MARCHING_CUBES_EDGES = [(0,1), (1,2), (2,3), (3,0), (4,5), (5,6), (6,7), (7,4), (0,4), (1,5), (2,6), (3,7)]
    MARCHING_CUBES_TRIANGLES = {i: [] for i in range(256)}  # [G] Standard lookup populated per MC spec

    # [S1, unofficial] Linear hashed octree traversal structure
    class ImplicitOctree:
        def __init__(self, max_depth):
            self.max_depth = max_depth
        def traverse(self):
            # [G] Octree traversal yields cubes with .corners, .values, .keys. Implementation omitted.
            return []

    # [S1, unofficial] Accumulates vertices and faces
    class MeshTopologyBuilder:
        def __init__(self):
            self.vertices = []
            self.faces = []
        def add_vertex(self, pos, key):
            self.vertices.append((pos, key))
        def add_face(self, v0, v1, v2):
            self.faces.append((v0, v1, v2))
        def build(self):
            return self.vertices, self.faces

    octree = ImplicitOctree(max_depth=max_depth)
    mesh_builder = MeshTopologyBuilder()
    
    for cube in octree.traverse():
        corners = cube.corners      # List of 8 vec3 positions
        values = cube.values        # List of 8 float scalar values
        keys = cube.keys            # List of 8 MortonKey identifiers
        
        # Classify cube
        cube_index = 0
        for i in range(8):
            if values[i] < isovalue:
                cube_index |= (1 << i)
        
        # Find edge crossings
        edge_vertices = []
        for edge_idx, (i, j) in enumerate(MARCHING_CUBES_EDGES):
            denom = values[j] - values[i]
            if abs(denom) < 1e-9:
                t = 0.5
            else:
                t = (isovalue - values[i]) / denom
            edge_vertices.append(corners[i] + t * (corners[j] - corners[i]))
        
        # March the cube: add triangles
        for triangle in MARCHING_CUBES_TRIANGLES[cube_index]:
            # [G] MortonKey assignment for interpolated vertices is implementation-specific
            mesh_builder.add_vertex(edge_vertices[triangle[0]], keys[0])
            mesh_builder.add_vertex(edge_vertices[triangle[1]], keys[0])
            mesh_builder.add_vertex(edge_vertices[triangle[2]], keys[0])
            mesh_builder.add_face(triangle[0], triangle[1], triangle[2])
            
    return mesh_builder.build()
```

**Parameters:**
- `max_depth`: Integer. The maximum depth of the octree. Determines the finest resolution ($2^{\text{max\_depth}}$) [S1, unofficial].
- `isovalue`: Float. The threshold for surface extraction.

**Edge Cases and Pitfalls:**
- **Precision**: Linear interpolation assumes the scalar field is locally linear between grid points. Highly oscillatory fields may produce artifacts [G].
- **Degenerate Cases**: When $v_B - v_A = 0$, the denominator in the interpolation formula becomes zero. Standard implementations clamp or skip the edge in this case [G].
