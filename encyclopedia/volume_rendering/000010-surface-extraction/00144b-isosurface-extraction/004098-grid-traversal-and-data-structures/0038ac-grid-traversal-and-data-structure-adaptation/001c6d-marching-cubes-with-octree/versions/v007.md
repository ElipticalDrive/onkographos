# Marching Cubes with Octree


## Overview
Marching Cubes with Octree extracts isosurfaces from scalar fields defined over an adaptive octree structure, allowing for variable resolution sampling. It sets itself apart from uniform grid methods by skipping empty or uniform regions, reducing memory overhead, and by handling the topological challenges of discontinuous node depths through specific splitting predicates or post-processing. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) but replaces the fixed grid traversal with a hierarchical tree traversal.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D bounding box defined by minimum and maximum points ($P_{min}, P_{max}$); a scalar field function $f(P)$; an isovalue $I$; and a splitting predicate (refinement criterion) that determines octree depth.
*   **Output:** A set of vertices (points) and a set of triangles (polygons) representing the extracted mesh.

**Data Structures:**
1.  **Octree:** A hierarchical structure where each node represents a cubic voxel. Nodes are recursively subdivided into 8 children if the splitting predicate returns true. The tree is initialized with the bounding box.
2.  **Values Object:** Encapsulates the scalar function $f$ and the octree structure, providing access to scalar values at any point in space, interpolated from the finest available level or the leaf node's value.
3.  **MC_Domain:** A domain object that interfaces the octree and values with the marching cubes algorithm, providing the necessary geometry and scalar data for each voxel processed.
4.  **Point_range / Polygon_range:** Containers for the output vertices and triangles.

**Algorithm Steps:**
1.  **Initialize Bounding Box:** Define the spatial extent using $P_{min} = (x_{min}, y_{min}, z_{min})$ and $P_{max} = (x_{max}, y_{max}, z_{max})$.
2.  **Construct Octree:** Create an octree object initialized with the bounding box points.
3.  **Refine Octree:** Recursively split nodes based on a splitting predicate. The predicate typically evaluates the scalar field variation or error within a voxel. If the predicate returns true, the node is subdivided into 8 children. This continues until a maximum depth is reached or the predicate fails for all children.
    *   *Note:* The splitting predicate must be consistent. Common predicates include `Refine_one_eighth` (fixed depth) or `Refine_around_isovalue` (split if the isovalue lies within the range of scalar values at the node's corners). [S1]
4.  **Create Values Object:** Instantiate a `Values` object containing the scalar function $f$ and the refined octree. This object handles scalar queries, potentially interpolating values if the query point lies within a subdivided region.
5.  **Initialize Output Containers:** Create empty containers `points` (for vertices) and `triangles` (for faces).
6.  **Construct MC_Domain:** Instantiate an `MC_Domain` object passing the octree and the values object. This domain object abstracts the voxel geometry and scalar access for the marching cubes engine.
7.  **Execute Marching Cubes:** Call the marching cubes function (e.g., `CGAL::Isosurfacing::marching_cubes`) with the `MC_Domain`, the isovalue $I$, and the output containers. The algorithm traverses the octree leaves. For each leaf voxel:
    *   Retrieve the 8 corner scalar values.
    *   Compute the case index $C$ based on the sign of $V(v_i) - I$.
    *   Use the `edgeTable` and `triangleTable` from the parent article to determine edge intersections and triangle connectivity.
    *   Interpolate vertex positions on intersected edges.
    *   Add generated triangles to the `triangles` container and vertices to the `points` container.
    *   *Parallelism:* The traversal can be parallelized across octree nodes. [S1]
8.  **Post-Processing (Optional):** Merge duplicate vertices from adjacent voxels to ensure a watertight mesh. If the octree has varying depths around the isosurface, additional steps may be required to handle discontinuities (see Pitfalls).

**Pseudocode:**
```python
def run_marching_cubes_octree(bbox_min, bbox_max, scalar_function, isovalue, split_predicate):
    # 1. Initialize Octree
    octree = Octree()
    octree.initialize(bbox_min, bbox_max)
    
    # 2. Refine Octree
    # Recursively split nodes where split_predicate returns true
    octree.refine(split_predicate)
    
    # 3. Create Values Object
    # This object provides scalar values f(p) using the octree structure
    values = Values(scalar_function, octree)
    
    # 4. Initialize Output Containers
    points = []      # List of 3D points
    triangles = []   # List of triangle indices or vertex triples
    
    # 5. Construct Domain
    mcdomain = MC_Domain(octree, values)
    
    # 6. Execute Marching Cubes
    # This function traverses the octree leaves and applies MC logic
    # It populates points and triangles
    marching_cubes(mcdomain, isovalue, points, triangles)
    
    # 7. Return Results
    return points, triangles

# Example Splitting Predicate (Refine around isovalue)
def refine_around_isovalue(node, scalar_function, isovalue):
    # Get scalar values at the 8 corners of the node
    corner_values = [scalar_function(node.get_corner(i)) for i in range(8)]
    
    # Check if the isovalue lies between the min and max corner values
    # If so, the isosurface likely passes through this voxel
    min_val = min(corner_values)
    max_val = max(corner_values)
    
    if min_val <= isovalue <= max_val:
        return True
    return False
```

**Parameters:**
*   **Isovalue ($I$):** The scalar threshold for surface extraction. Typical values depend on the scalar field normalization (e.g., 0.0 for signed distance fields, 0.5 for density fields). [S1, S2]
*   **Splitting Predicate:** Determines the octree resolution. Common predicates:
    *   *Fixed Depth:* Split to a maximum depth regardless of content. [S1]
    *   *Isovalue-Based:* Split if the isovalue is within the range of corner values. [S1]
    *   *Error-Based:* Split if the interpolation error exceeds a threshold. [S1]
*   **Maximum Depth:** The deepest level of the octree. [S1]

**Edge Cases and Pitfalls:**
*   **Cracks at Discontinuous Depths:** If the octree has varying depths around the isosurface (i.e., a fine voxel is adjacent to a coarse voxel), standard Marching Cubes will produce cracks or holes because the coarse voxel's edges do not align with the fine voxel's vertices. [S1, S2]
    *   *Mitigation:* Use a splitting predicate that ensures uniform depth around the surface, or subdivide all voxels to the finest level in regions of discontinuity. [S1, S2]
*   **Non-Manifold Geometry:** Inconsistent handling of ambiguous cases (see [Topology and Ambiguity Handling](6547-topology-and-ambiguity-handling.md)) can lead to non-manifold edges, especially in adaptive settings. [S1]
*   **Scalar Field Continuity:** The scalar function must be defined consistently across the octree. If the octree levels differ, the scalar field may not be continuous across boundaries, leading to artifacts. [S2]

## Subtopics

### [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md)
Linear Hashed Marching Cubes extracts triangle meshes from implicit scalar fields by applying the Marching Cubes algorithm over a linear hashed octree. It replaces the standard grid-based traversal with a pointerless octree structure to reduce memory overhead and improve performance. It builds on [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) but uses a linear hash table for node storage instead of a primal grid.

### [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md)
This method extracts isosurfaces from adaptive resolution (AR) octree volume data by decoupling geometry generation from discontinuity resolution. It solves the topological inconsistencies that arise when fine-resolution cubes share edges or faces with coarser, unsubdivided neighbors. Unlike uniform resolution methods, it reduces data access and processing time by skipping large uniform regions, while the two-pass approach ensures a watertight mesh without requiring complex on-the-fly edge matching logic during the primary traversal.

### [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md)
Adaptive Marching Cubes is an extension of the standard Marching Cubes algorithm designed to extract isosurfaces from Adaptive Resolution (AR) octree data. It solves the problem of topological inconsistencies and geometric artifacts that arise when adjacent cubes in the mesh have different resolutions. Unlike uniform marching cubes, it handles missing vertices and discontinuities by deferring the processing of coarser nodes that conflict with finer neighbors, ensuring a watertight mesh across resolution boundaries.

### [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md)
DMC Octree Contour Extraction is an adaptive isosurface extraction method that generates a manifold triangle mesh from volumetric scalar field data using a dual-contouring approach on an octree structure. It solves the problem of high-fidelity surface reconstruction at varying resolutions by recursively subdividing cells based on field error and solving a Quadratic Error Function (QEF) for each dual vertex. It sets itself apart from its sibling [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md) by using dual vertices and QEF solving rather than linear interpolation on grid edges, and from [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) by explicitly managing topological consistency through a recursive face/edge/vertex processing pipeline that ensures shared boundaries between adjacent octree nodes are handled deterministically.

### Sparse-Voxel TSDF Fusion and Marching Cubes
This variant adapts TSDF-Fusion and Marching Cubes into a sparse voxel representation. It computes truncated signed distance values of sparse grid points and extracts the zero-level set surface. Duplicated vertices from adjacent voxels are merged. If adjacent voxels belong to different octree levels, all voxels are subdivided to the finest level to remove discontinuities in the density field. Unlike methods relying on coarse geometry priors, this method models the scene only with a density field. However, it tends to produce unnecessary geometric bumps for texture details, and triangles may not be connected if the density field is not continuous across different octree levels. [S2]

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Significantly lower than uniform grid methods for sparse or large-scale scenes, as only non-empty or high-detail regions are stored. The complexity depends on the number of leaf nodes in the octree. [S1]
*   **Time:** Proportional to the number of leaf voxels. Adaptive refinement reduces the number of voxels processed compared to a uniform grid of equivalent maximum resolution. [S1]

**Measured Performance:**
*   Performance varies based on the splitting predicate and scene complexity. For scenes with large uniform regions, octree-based methods are much faster. [S1]
*   In sparse-voxel TSDF fusion, the method achieves a good balance of accuracy and training time on large-scale datasets like Tanks&Temples and DTU, though it may require post-processing to remove geometric bumps. [S2]

**Scaling:**
*   Scales well with scene size due to adaptive resolution. [S1]
*   Parallelization is effective, as octree nodes can be processed independently. [S1]

**Strengths and Limitations:**
*   **Strengths:** Memory efficiency, ability to handle large-scale scenes, adaptive resolution. [S1]
*   **Limitations:** Potential for cracks at discontinuous depths, complexity in handling ambiguous cases in adaptive settings, potential for geometric artifacts (bumps) in density-based methods. [S1, S2]

**When to Use:**
*   Use for large-scale scenes with sparse details or varying resolution requirements. [S1]
*   Use when memory is a constraint. [S1]

**When Not to Use:**
*   Avoid for scenes requiring uniform resolution or where cracks at discontinuous depths cannot be tolerated without post-processing. [S1]
*   Avoid if high-fidelity smooth surfaces are required without additional smoothing steps, as density-based methods may produce bumps. [S2]

## Background
The method originates from the CGAL library's Isosurfacing module, which provides robust isosurfacing algorithms for 3D domains, including octrees. [S1] The underlying Marching Cubes algorithm was introduced by Lorensen and Cline in 1987. [S2] The adaptation to octrees allows for efficient handling of large-scale volumetric data. [S1] The sparse-voxel variant is based on recent work in neural radiance fields and sparse voxel representations, such as TSDF-Fusion (KinectFusion, 2011) and Marching Cubes. [S2]
