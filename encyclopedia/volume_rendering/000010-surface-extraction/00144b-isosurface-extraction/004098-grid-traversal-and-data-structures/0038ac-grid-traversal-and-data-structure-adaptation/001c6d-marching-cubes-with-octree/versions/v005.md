# Marching Cubes with Octree


## Overview
Marching Cubes with Octree extracts a manifold triangle mesh from a scalar field defined over an adaptive octree domain, replacing the uniform grid traversal of standard Marching Cubes with hierarchical spatial subdivision [S1]. It sets itself apart from its siblings by decoupling the mesh generation logic from the underlying data structure, allowing the algorithm to operate on non-uniform node sizes while relying on the domain abstraction to handle coordinate mapping [S1]. Unlike [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) which explicitly manages discontinuity artifacts through deferred processing, this method assumes uniform splitting around the isosurface to guarantee manifold connectivity [S1].

## How it works
The method operates by constructing an octree that refines based on a user-defined predicate, then applying the standard Marching Cubes topology lookup within each leaf node of the octree.

**Inputs and Outputs:**
*   **Input:** A 3D bounding box (`bbox`), a scalar field function $f(\mathbf{p})$ mapping 3D points to real values, a split predicate function $P(\text{node})$ determining refinement, and an isovalue $I$.
*   **Output:** A set of vertices (points) and a set of triangles (polygons) representing the isosurface $f(\mathbf{p}) = I$.

**Data Structures:**
1.  **Octree:** A hierarchical structure where each node represents a cubic region. Nodes are refined recursively if the split predicate returns true. The structure stores the bounding box of each node and its children.
2.  **Values:** An object encapsulating the scalar function $f$ and the octree, providing access to scalar values at any point within the domain.
3.  **MC_Domain:** An abstraction layer that maps the octree structure and scalar values to the interface expected by the Marching Cubes algorithm. It handles the translation of local node coordinates to global coordinates and provides the scalar values at the vertices of each cell.
4.  **Point_range / Polygon_range:** Containers for the output vertices and triangle indices.

**Algorithm Steps:**

1.  **Initialize Bounding Box:** Define the global domain using minimum and maximum coordinates: $\mathbf{p}_{min} = (x_{min}, y_{min}, z_{min})$ and $\mathbf{p}_{max} = (x_{max}, y_{max}, z_{max})$.
2.  **Construct Octree:** Create an `Octree` object initialized with $\mathbf{p}_{min}$ and $\mathbf{p}_{max}$.
3.  **Refine Octree:** Recursively split nodes using the split predicate $P$. A node is split if $P(\text{node})$ evaluates to true. This continues until all leaf nodes satisfy the stopping condition or a maximum depth is reached.
4.  **Wrap Data:** Create a `Values` object containing the scalar function $f$ and the constructed `Octree`.
5.  **Initialize Output:** Create empty containers `points` and `triangles`.
6.  **Create Domain:** Instantiate an `MC_Domain` object passing the `Octree` and `Values`. This domain object abstracts the grid cells as the leaf nodes of the octree.
7.  **Execute Marching Cubes:** Call the marching cubes algorithm with the `MC_Domain`, the isovalue $I$, and the output containers. The algorithm iterates over each leaf node (treated as a cubic cell):
    a.  Evaluate $f$ at the 8 vertices of the leaf node.
    b.  Determine the intersection configuration by comparing vertex values to $I$.
    c.  Interpolate intersection points on the edges where the sign of $f - I$ changes.
    d.  Generate triangles based on the configuration lookup table.
    e.  Add vertices and triangles to `points` and `triangles`.
8.  **Merge Vertices:** The implementation typically merges duplicate vertices from adjacent voxels to ensure a watertight mesh [S2].

**Pseudocode:**

```python
def run_marching_cubes_octree(bbox_min, bbox_max, scalar_function, split_predicate, isovalue):
    # Step 1 & 2: Construct Octree
    octree = Octree()
    octree.initialize(bbox_min, bbox_max)
    
    # Step 3: Refine Octree
    # The refine function recursively checks split_predicate for each node.
    # If true, the node is subdivided into 8 children.
    octree.refine(split_predicate)
    
    # Step 4: Wrap Data
    values = Values(scalar_function=scalar_function, octree=octree)
    
    # Step 5: Initialize Output
    points = []
    triangles = []
    
    # Step 6: Create Domain
    # MC_Domain maps the octree leaves to cubic cells for MC algorithm
    domain = MC_Domain(octree=octree, values=values)
    
    # Step 7: Execute Marching Cubes
    # The algorithm iterates over all leaf nodes in the octree
    for leaf_node in octree.get_leaves():
        # Get the 8 vertices of the current leaf node (cubic cell)
        cell_vertices = leaf_node.get_vertices()
        
        # Evaluate scalar field at each vertex
        scalar_values = [scalar_function(v) for v in cell_vertices]
        
        # Determine configuration based on isovalue
        # Compare each scalar value to isovalue to determine sign
        signs = [1 if s >= isovalue else -1 for s in scalar_values]
        
        # Map signs to a 8-bit index for lookup table
        config_index = 0
        for i, sign in enumerate(signs):
            if sign == 1:
                config_index |= (1 << i)
        
        # Get edge intersections
        # Interpolate position on edges where signs differ
        intersections = []
        for edge in get_edges_for_config(config_index):
            v1, v2 = edge.vertices
            s1, s2 = scalar_values[edge.v1_index], scalar_values[edge.v2_index]
            # Linear interpolation
            t = (isovalue - s1) / (s2 - s1)
            p = lerp(v1, v2, t)
            intersections.append(p)
        
        # Generate triangles from intersections based on config_index
        triangles_for_cell = get_triangles_from_config(config_index, intersections)
        
        # Add to output
        points.extend(intersections)
        triangles.extend(triangles_for_cell)
        
    # Step 8: Merge Vertices
    # Merge duplicate vertices from adjacent voxels
    points, triangles = merge_duplicate_vertices(points, triangles)
    
    return points, triangles
```

**Parameters:**
*   **isovalue:** The scalar threshold for surface extraction. Typical value depends on the data range; often 0 for signed distance fields or 0.5 for normalized density [S1, S2].
*   **split_predicate:** A function determining refinement. Common predicates include refining if the node contains the isosurface (e.g., values at corners span the isovalue) or if the node size exceeds a threshold [S1].

**Edge Cases and Pitfalls:**
*   **Cracks:** Using an octree with varying depths around the isosurface produces cracks at regions where octree levels are discontinuous [S1]. The method assumes uniform splitting around the surface to produce a manifold surface [S1].
*   **Discontinuities:** When adjacent voxels belong to different octree levels, the density field may not be continuous, leading to disconnected triangles [S2]. This can be mitigated by subdividing all voxels to the finest level [S2].

## Subtopics

### [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md)
Linear Hashed Marching Cubes extracts triangle meshes from implicit scalar fields by applying the Marching Cubes algorithm over a linear hashed octree. It replaces the standard grid-based traversal with a pointerless octree structure to reduce memory overhead and improve performance. It builds on [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) but uses a linear hash table for node storage instead of a primal grid.

### [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md)
This method extracts isosurfaces from adaptive resolution (AR) octree volume data by decoupling geometry generation from discontinuity resolution. It solves the topological inconsistencies that arise when fine-resolution cubes share edges or faces with coarser, unsubdivided neighbors. Unlike uniform resolution methods, it reduces data access and processing time by skipping large uniform regions, while the two-pass approach ensures a watertight mesh without requiring complex on-the-fly edge matching logic during the primary traversal.

### [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md)
Adaptive Marching Cubes is an extension of the standard Marching Cubes algorithm designed to extract isosurfaces from Adaptive Resolution (AR) octree data. It solves the problem of topological inconsistencies and geometric artifacts that arise when adjacent cubes in the mesh have different resolutions. Unlike uniform marching cubes, it handles missing vertices and discontinuities by deferring the processing of coarser nodes that conflict with finer neighbors, ensuring a watertight mesh across resolution boundaries.

### [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md)
DMC Octree Contour Extraction is an adaptive isosurface extraction method that generates a manifold triangle mesh from volumetric scalar field data using a dual-contouring approach on an octree structure. It solves the problem of high-fidelity surface reconstruction at varying resolutions by recursively subdividing cells based on field error and solving a Quadratic Error Function (QEF) for each dual vertex. It sets itself apart from its sibling [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md) by using dual vertices and QEF solving rather than linear interpolation on grid edges, and from [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) by explicitly managing topological consistency through a recursive face/edge/vertex processing pipeline that ensures shared boundaries between adjacent octree nodes are handled deterministically.

### Sparse-Voxel TSDF Fusion and Marching Cubes
This variant extracts mesh by adapting TSDF-Fusion and Marching Cubes into the sparse voxel representation [S2]. It implements sparse-voxel TSDF-Fusion to compute truncated signed distance values of the sparse grid points, then extracts the surface of the zero-level set using sparse-voxel Marching Cubes [S2]. Duplicated vertices from adjacent voxels are merged to produce a unique set of vertices [S2]. If adjacent voxels belong to different Octree levels, all voxels are subdivided to the finest level to remove discontinuities in the density field [S2]. Unlike methods relying on coarse geometry priors, this method models the scene only with a density field [S2]. It tends to produce unnecessary geometric bumps for texture details [S2]. When adjacent voxels belong to different Octree levels, the extracted triangle may not be connected because the density field is not continuous for voxels in different levels [S2].

## Operating characteristics
*   **Time Complexity:** Depends on the number of leaf nodes in the octree and the complexity of the split predicate. In the worst case, it is proportional to the number of cells intersecting the isosurface.
*   **Memory Complexity:** Proportional to the number of nodes in the octree. The octree structure itself consumes memory, but adaptive refinement reduces the number of nodes compared to a uniform grid for sparse or complex surfaces.
*   **Strengths:** Efficiently handles large domains with varying levels of detail. Reduces memory usage compared to uniform grids for sparse data.
*   **Limitations:** Requires careful handling of discontinuities at different octree levels to avoid cracks [S1, S2]. The quality of the mesh depends heavily on the split predicate [S1].
*   **When to use:** When the scalar field is sparse or has varying levels of detail, and memory efficiency is important.
*   **When not to use:** When uniform resolution is sufficient and simplicity is preferred, or when strict manifold guarantees are required without additional post-processing for discontinuities [S1].

## Background
The method is implemented in the Computational Geometry Algorithms Library (CGAL) as `CGAL::Isosurfacing::marching_cubes` with an `MC_Domain` abstraction [S1]. It builds on the classic Marching Cubes algorithm [27] (1987) and TSDF-Fusion [36] (KinectFusion, 2011) [S2]. The CGAL implementation provides a generic interface that allows the marching cubes algorithm to operate on different domain structures, including octrees [S1].
