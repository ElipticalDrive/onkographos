# Marching Cubes with Octree


## Overview
Marching Cubes with Octree extracts a manifold isosurface from a volumetric scalar field by applying the Marching Cubes algorithm over an octree data structure [S1]. It solves the problem of efficient surface extraction in sparse or adaptive volumetric data by traversing only the relevant octree nodes rather than a dense uniform grid [S1]. Unlike standard grid-based Marching Cubes, it adapts the domain structure to the scalar field's features, though it requires uniform node sizes around the isosurface to avoid topological cracks [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D bounding box (`bbox`), a split predicate function (`split_predicate`) that determines octree refinement, a scalar function (`function`) evaluating the field at any point, and an isovalue (`isovalue`) [S1].
*   **Output:** A set of vertices (`Point_range`) and a set of triangles (`Polygon_range`) representing the extracted mesh [S1].

**Data Structures:**
1.  **Octree:** Initialized with two diagonal corner points of the bounding box (`bbox_points`) [S1]. The structure supports refinement based on the split predicate [S1].
2.  **Values:** A container holding the scalar `function` and the `octree` instance [S1].
3.  **MC_Domain:** An object encapsulating the `octree` and `values`, providing the interface for the marching cubes algorithm [S1].

**Algorithm Steps:**
1.  Define the bounding box points from `bbox.xmin/ymin/zmin` and `bbox.xmax/ymax/zmax` [S1].
2.  Construct an `Octree` object initialized with these `bbox_points` [S1].
3.  Refine the octree by calling `octree.refine(split_predicate)` [S1]. The predicate determines which nodes are subdivided based on the scalar field [S1].
4.  Create a `Values` object containing the `function` and the refined `octree` [S1].
5.  Initialize empty containers `Point_range points` and `Polygon_range triangles` for the output vertices and triangles [S1].
6.  Construct an `MC_Domain` object (`mcdomain`) passing the `octree` and `values` [S1].
7.  Call the marching cubes function: `CGAL::Isosurfacing::marching_cubes<CGAL::Parallel_if_available_tag>(mcdomain, isovalue, points, triangles)` [S1]. This generates the mesh using parallel execution if available [S1].
8.  (Optional) Write the output to files using `CGAL::IO::write_polygon_soup` for the mesh and `octree.dump_to_polylines` for the octree structure [S1].

**Pseudocode:**
```python
def run_marching_cubes_octree(bbox, split_predicate, scalar_function, isovalue):
    # 1. Define bounding box points
    bbox_points = [
        Point(bbox.xmin, bbox.ymin, bbox.zmin),
        Point(bbox.xmax, bbox.ymax, bbox.zmax)
    ]
    
    # 2. Construct Octree
    octree = Octree(bbox_points)
    
    # 3. Refine octree using split predicate
    octree.refine(split_predicate)
    
    # 4. Create Values object
    values = Values(function=scalar_function, octree=octree)
    
    # 5. Initialize output containers
    points = Point_range()
    triangles = Polygon_range()
    
    # 6. Construct MC_Domain
    mcdomain = MC_Domain(octree=octree, values=values)
    
    # 7. Execute Marching Cubes
    # Uses parallel execution tag if available
    marching_cubes(
        domain=mcdomain,
        isovalue=isovalue,
        output_points=points,
        output_triangles=triangles,
        execution_policy=Parallel_if_available_tag
    )
    
    return points, triangles
```

**Parameters:**
*   `isovalue`: The scalar value at which the surface is extracted. Typical default is `0.3` in reference implementations [S1].
*   `bbox`: The spatial extent of the volume. Example: `[-1, -1, -1, 1, 1, 1]` [S1].

**Edge Cases and Pitfalls:**
*   **Cracks:** Using an octree with varying depths around the isosurface produces cracks at regions where octree levels are discontinuous [S1]. The method behaves well and produces a manifold surface only if nodes are split with a uniform size around the surface [S1].
*   **Discontinuity Handling:** If adjacent voxels belong to different octree levels, the density field is not continuous, leading to disconnected triangles [S2]. This can be resolved by subdividing all voxels to the finest level [S2].

An extension handling topological inconsistencies in adaptive resolution data by deferring processing of coarser nodes that conflict with finer neighbors.

Uses a dual-contouring approach on an octree structure, solving a Quadratic Error Function for dual vertices to ensure manifold topology.

Partitions space into simplices dual to minimal octree cells to guarantee manifold topology and prevent self-intersection.

### Sparse-Voxel TSDF Fusion and Marching Cubes
This method extracts a mesh by adapting TSDF-Fusion and Marching Cubes into a sparse voxel representation [S2]. It computes truncated signed distance values using sparse-voxel TSDF-Fusion and extracts the zero-level set surface using sparse-voxel Marching Cubes [S2]. Duplicated vertices from adjacent voxels are merged to produce a unique vertex set [S2]. If adjacent voxels belong to different octree levels, all voxels are subdivided to the finest level to remove discontinuities in the density field [S2]. Unlike methods relying on coarse geometry priors (e.g., SfM), it models the scene only with a density field [S2]. Pitfalls include producing unnecessary geometric bumps for texture details and potential disconnection of triangles when adjacent voxels are at different octree levels due to discontinuous density fields [S2]. It cites TSDF-Fusion (KinectFusion, 2011) and Marching Cubes (1987) [S2].

## Operating characteristics
*   **Time Complexity:** Depends on the number of leaf nodes in the octree that intersect the isosurface. The refinement step is driven by the `split_predicate` [S1].
*   **Memory Complexity:** Proportional to the number of octree nodes and the resulting mesh size [S1].
*   **Strengths:** Efficient for sparse data; avoids processing empty or uniform regions [S1]. Supports parallel execution [S1].
*   **Limitations:** Produces cracks if octree depth varies discontinuously around the isosurface [S1]. May produce geometric bumps for fine texture details [S2].
*   **When to use:** When the volumetric data is sparse or adaptive, and uniform refinement around the surface is feasible [S1].
*   **When not to use:** When the octree has varying depths around the isosurface without additional discontinuity handling, as this leads to non-manifold cracks [S1].

## Background
The method is implemented in the CGAL library as `CGAL::Isosurfacing::marching_cubes` with an `MC_Domain` interface [S1]. It builds on the shared principles of [Grid Traversal and Data Structures](10325-grid-traversal-and-data-structures.md) [S1]. The underlying Marching Cubes algorithm was introduced in 1987 [S2]. TSDF-Fusion, often used in conjunction with this approach for sparse voxels, was introduced in 2011 (KinectFusion) [S2].
