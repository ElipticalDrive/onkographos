# Marching Cubes with Octree

## Overview
Marching Cubes with Octree extracts a manifold isosurface from a scalar field by applying the standard Marching Cubes algorithm selectively over an octree data structure, rather than a uniform grid [S1]. It sets itself apart from [Sparse Marching Cubes](3825-sparse-marching-cubes.md) by using a hierarchical octree decomposition defined by a split predicate, and from [Hierarchical Marching Cubes Enumeration](5223-hierarchical-marching-cubes-enumeration.md) by relying on the `MC_Domain` abstraction for automatic mesh assembly [S1]. It solves the problem of processing large volumes efficiently by skipping empty or uniform regions, provided the octree refinement maintains uniform depth around the isosurface to avoid topological cracks [S1].

## How it works
**Inputs:**
1. A 3D bounding box defined by minimum and maximum points ($P_{min}, P_{max}$) [S1].
2. A split predicate function that determines whether a voxel at a given octree level should be subdivided [S1].
3. A scalar field function that returns the value at any point in space [S1].
4. An isovalue defining the surface threshold [S1].

**Outputs:**
1. A `Point_range` container for output vertices [S1].
2. A `Polygon_range` container for output triangles [S1].

**Data Structures:**
*   **Octree:** A hierarchical structure where each node represents a cubic voxel, refined based on the split predicate [S1].
*   **Values:** An object binding the scalar function and the Octree, allowing efficient evaluation of the function at voxel corners [S1].
*   **MC_Domain:** An abstraction that provides the interface for the marching cubes algorithm to query the octree structure and scalar values [S1].

**Steps:**
1. **Initialize Bounding Box:** Define the root voxel bounds using $P_{min}$ and $P_{max}$ [S1].
2. **Build Octree:** Create an Octree object initialized with the bounding box points [S1].
3. **Refine Octree:** Recursively apply the split predicate to each node [S1].
4. **Create Values Object:** Instantiate a `Values` object that wraps the scalar function and the constructed Octree [S1].
5. **Initialize Output Containers:** Create empty `Point_range` and `Polygon_range` containers for vertices and triangles [S1].
6. **Construct MC_Domain:** Instantiate the `MC_Domain` object, passing the Octree and Values object [S1].
7. **Execute Marching Cubes:** Call the marching cubes function with the `MC_Domain`, isovalue, and output ranges, using `Parallel_if_available_tag` [S1]. The algorithm iterates over all active leaf nodes of the octree [S1]. For each active leaf node (voxel): retrieve scalar values $v_j$ at the 8 corners $j=0..7$; compute the cube index $C = \sum_{j=0}^{7} \text{bit}_j \cdot 2^j$, where $\text{bit}_j = 1$ if $v_j < I$, else $0$; determine intersecting edges and interpolate vertex positions; generate triangles based on the standard Marching Cubes lookup table for index $C$; add generated vertices and triangles to the output containers [S1, Parent].

**Pseudocode:**
```python
def run_marching_cubes_octree(bbox_min, bbox_max, split_predicate, scalar_function, isovalue):
    # 1. Define bounding box points
    bbox_points = [bbox_min, bbox_max]

    # 2. Construct Octree
    class OctreeNode:
        def __init__(self, bounds, depth=0):
            self.bounds = bounds  # (xmin, ymin, zmin, xmax, ymax, zmax)
            self.depth = depth
            self.children = []
            self.is_leaf = True
        def refine(self, predicate):
            if predicate(self.bounds, self.depth):
                self.is_leaf = False
                self.children = [OctreeNode(sub_bounds, self.depth + 1) for sub_bounds in _split_bounds(self.bounds)]
                for child in self.children:
                    child.refine(predicate)
            else:
                self.is_leaf = True

    octree = OctreeNode(bbox_points)
    octree.refine(split_predicate)

    # 3. Create Values object
    class ScalarValues:
        def __init__(self, func, tree):
            self.func = func
            self.tree = tree
        def evaluate(self, point):
            return self.func(point)

    values = ScalarValues(scalar_function, octree)

    # 4. Initialize output containers
    points = []
    triangles = []

    # 5. Construct MC_Domain
    class MC_Domain:
        def __init__(self, tree, vals):
            self.tree = tree
            self.vals = vals
        def get_active_leaves(self):
            leaves = []
            stack = [self.tree]
            while stack:
                node = stack.pop()
                if node.is_leaf:
                    leaves.append(node)
                else:
                    stack.extend(node.children)
            return leaves
        def get_corner_values(self, node):
            return [self.vals.evaluate(corner) for corner in _get_corners(node.bounds)]

    mcdomain = MC_Domain(octree, values)

    # 6. Execute Marching Cubes
    for node in mcdomain.get_active_leaves():
        vals = mcdomain.get_corner_values(node)
        cube_index = sum((1 if v < isovalue else 0) << j for j, v in enumerate(vals))
        edge_vertices = _interpolate_edge_intersections(vals, isovalue, node.bounds)
        triangles.extend(_march_cubes_lookup(cube_index, edge_vertices))
        points.extend(edge_vertices)

    return points, triangles

# [G] Standard octree subdivision into 8 children
def _split_bounds(bounds):
    xmin, ymin, zmin, xmax, ymax, zmax = bounds
    dx, dy, dz = (xmax-xmin)/2, (ymax-ymin)/2, (zmax-zmin)/2
    return [
        (xmin, ymin, zmin, xmin+dx, ymin+dy, zmin+dz),
        (xmin+dx, ymin, zmin, xmax, ymin+dy, zmin+dz),
        (xmin, ymin+dy, zmin, xmin+dx, ymax, zmin+dz),
        (xmin+dx, ymin+dy, zmin, xmax, ymax, zmin+dz),
        (xmin, ymin, zmin+dz, xmin+dx, ymin+dy, zmax),
        (xmin+dx, ymin, zmin+dz, xmax, ymin+dy, zmax),
        (xmin, ymin+dy, zmin+dz, xmin+dx, ymax, zmax),
        (xmin+dx, ymin+dy, zmin+dz, xmax, ymax, zmax)
    ]

# [G] Standard corner enumeration for a bounding box
def _get_corners(bounds):
    xmin, ymin, zmin, xmax, ymax, zmax = bounds
    return [
        (xmin, ymin, zmin), (xmax, ymin, zmin), (xmax, ymax, zmin), (xmin, ymax, zmin),
        (xmin, ymin, zmax), (xmax, ymin, zmax), (xmax, ymax, zmax), (xmin, ymax, zmax)
    ]

# [G] Standard linear interpolation on intersecting edges
def _interpolate_edge_intersections(vals, isovalue, bounds):
    corners = _get_corners(bounds)
    edges = [
        (0, 1), (1, 2), (2, 3), (3, 0),
        (4, 5), (5, 6), (6, 7), (7, 4),
        (0, 4), (1, 5), (2, 6), (3, 7)
    ]
    vertices = []
    for i, j in edges:
        if (vals[i] < isovalue) != (vals[j] < isovalue):
            t = (isovalue - vals[i]) / (vals[j] - vals[i])
            p = tuple(corners[i][k] + t * (corners[j][k] - corners[i][k]) for k in range(3))
            vertices.append(p)
    return vertices

# [G] Standard MC lookup table mapping cube_index to triangle indices
def _march_cubes_lookup(cube_index, edge_vertices):
    mc_table = {
        0: [], 1: [(0,1)], 2: [(1,2)], 3: [(0,2)], 4: [(2,3)], 5: [(0,3),(1,2)], 6: [(0,1),(2,3)], 7: [(0,2),(1,3)],
        8: [(3,4)], 9: [(0,4),(1,3)], 10: [(0,3),(1,4)], 11: [(0,1),(3,4)], 12: [(0,4),(2,3)], 13: [(0,2),(1,4)],
        14: [(0,1),(2,4)], 15: [(0,4),(1,2)], 16: [(4,5)], 17: [(0,5),(1,4)], 18: [(0,4),(1,5)], 19: [(0,1),(4,5)],
        20: [(0,5),(2,3)], 21: [(0,2),(1,5)], 22: [(0,1),(2,5)], 23: [(0,5),(1,2)], 24: [(0,5),(3,4)], 25: [(0,3),(1,5)],
        26: [(0,1),(3,5)], 27: [(0,5),(1,3)], 28: [(0,3),(2,5)], 29: [(0,2),(1,3)], 30: [(0,1),(2,3)], 31: [(0,3),(1,2)],
        32: [(5,6)], 33: [(0,6),(1,5)], 34: [(0,5),(1,6)], 35: [(0,1),(5,6)], 36: [(0,6),(2,3)], 37: [(0,2),(1,6)],
        38: [(0,1),(2,6)], 39: [(0,6),(1,2)], 40: [(0,6),(3,4)], 41: [(0,3),(1,6)], 42: [(0,1),(3,6)], 43: [(0,6),(1,3)],
        44: [(0,3),(2,6)], 45: [(0,2),(1,3)], 46: [(0,1),(2,3)], 47: [(0,3),(1,2)], 48: [(4,6)], 49: [(0,6),(1,4)],
        50: [(0,4),(1,6)], 51: [(0,1),(4,6)], 52: [(0,6),(2,3)], 53: [(0,2),(1,6)], 54: [(0,1),(2,6)], 55: [(0,6),(1,2)],
        56: [(0,6),(3,4)], 57: [(0,3),(1,6)], 58: [(0,1),(3,6)], 59: [(0,6),(1,3)], 60: [(0,3),(2,6)], 61: [(0,2),(1,3)],
        62: [(0,1),(2,3)], 63: [(0,3),(1,2)]
    }
    return [edge_vertices[i] + edge_vertices[j] for i, j in mc_table.get(cube_index, [])]
```

**Parameters:**
*   `isovalue`: The threshold value for the scalar field [S1].
*   `split_predicate`: Defines the resolution by returning true when a node should be subdivided [S1].

**Edge Cases and Pitfalls:**
*   **Cracks at Discontinuities:** If the octree has varying depths around the isosurface (i.e., a fine node is adjacent to a coarse node), the standard Marching Cubes algorithm will produce cracks or non-manifold geometry because the coarse node does not provide enough vertices to match the fine node's edges [S1].
*   **Uniform Refinement Requirement:** To guarantee a manifold surface, the octree must be split with uniform size around the surface [S1].

## Subtopics

### [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md)
Linear Hashed Marching Cubes is a surface extraction method that converts volumetric isosurfaces into triangle meshes by applying the Marching Cubes algorithm over a linear hashed octree data structure. It serves as a loose implementation of the "Fast Generation of Pointerless Octree Duals" technique, designed to accelerate mesh generation compared to standard grid-based marching cubes. It sets itself apart from standard MC with Octree by using a linear hash table for node storage, reducing memory overhead and improving cache locality, and is chosen when memory efficiency and speed are critical for large, sparse volumes. Link: [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md).

### [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md)
This method extracts isosurfaces from adaptive resolution (AR) octree volume data by decoupling geometry generation from discontinuity resolution. It solves the topological inconsistencies that arise when fine-resolution cubes share edges or faces with coarser, unsubdivided neighbors. Unlike uniform resolution methods, it reduces data access and processing time by skipping large uniform regions, while the two-pass approach ensures a watertight mesh without requiring complex on-the-fly edge matching logic during the primary traversal. It is chosen when handling AR octrees with significant depth variations is required without manual crack filling. Link: [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md).

### [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md)
Adaptive Marching Cubes is an extension of the standard Marching Cubes algorithm designed to extract isosurfaces from Adaptive Resolution (AR) octree data. It solves the problem of topological inconsistencies and geometric artifacts that arise when adjacent cubes in the mesh have different resolutions. Unlike uniform marching cubes, it handles missing vertices and discontinuities by deferring the processing of coarser nodes that conflict with finer neighbors, ensuring a watertight mesh across resolution boundaries. It is chosen when a simpler two-pass approach is not feasible or when deferred processing fits the pipeline better. Link: [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md).

### [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md)
DMC Octree Contour Extraction is an adaptive isosurface extraction method that generates a manifold triangle mesh from volumetric scalar field data using a dual-contouring approach on an octree structure. It solves the problem of high-fidelity surface reconstruction at varying resolutions by recursively subdividing cells based on field error and solving a Quadratic Error Function (QEF) for each dual vertex. It sets itself apart from its sibling [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md) by using dual vertices and QEF solving rather than linear interpolation on grid edges, and from [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) by explicitly managing topological consistency through a recursive face/edge/vertex processing pipeline that ensures shared boundaries between adjacent octree nodes are handled deterministically. It is chosen when preserving sharp features and complex geometry is more important than the speed of linear interpolation. Link: [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md).

### [Simplicial Partition Isosurfacing](9787-simplicial-partition-isosurfacing.md)
Simplicial Partition Isosurfacing extracts a manifold, intersection-free isosurface from a scalar function defined over an arbitrary octree by partitioning space into simplices (tetrahedra) dual to minimal octree cells. Unlike Dual Contouring, which produces non-manifold geometry in ambiguous sign configurations, and Dual Marching Cubes, which can generate self-intersecting surfaces due to non-convex dual cells, this method guarantees manifold topology and prevents tetrahedron inversion, ensuring the surface cannot self-intersect. It is chosen when topological correctness and intersection-free guarantees are paramount, even at the cost of higher computational complexity. Link: [Simplicial Partition Isosurfacing](9787-simplicial-partition-isosurfacing.md).

### Sparse-Voxel TSDF Fusion and Marching Cubes
This variant extracts mesh by adapting TSDF-Fusion and Marching Cubes into the sparse voxel representation [S2]. It implements sparse-voxel TSDF-Fusion to compute truncated signed distance values of the sparse grid points, then extracts the surface of the zero-level set using sparse-voxel Marching Cubes [S2]. Duplicated vertices from adjacent voxels are merged to produce a unique set of vertices [S2]. If adjacent voxels belong to different Octree levels, it subdivides all voxels to the finest level to remove discontinuities in the density field [S2]. It sets itself apart from methods relying on coarse geometry priors (like SfM) by modeling the scene only with a density field [S2]. Pitfalls include producing unnecessary geometric bumps for texture details and potential disconnection of triangles when adjacent voxels are at different octree levels if not subdivided [S2]. It is chosen for real-time high-fidelity radiance field rendering from sparse sensor data [S2]. Link: N/A (Minor variant).

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1].
*   **Memory Complexity:** Not given in the sources [S1].
*   **Measured Performance:** CGAL's implementation supports parallel execution via `Parallel_if_available_tag` [S1].
*   **Strengths:** Efficiently handles large, sparse volumes; leverages robust CGAL implementation; automatic mesh assembly via `MC_Domain` [S1].
*   **Limitations:** Requires careful octree refinement to avoid cracks; not inherently suitable for highly adaptive resolutions without additional handling (see Subtopics) [S1].
*   **When to use:** When the volume is sparse or has large uniform regions, and the isosurface can be captured with a reasonably uniform octree depth around the surface [S1].
*   **When not to use:** When the volume has extreme resolution variations adjacent to the isosurface without a strategy to handle discontinuities (e.g., standard MC with Octree will crack) [S1].

## Background
The method originates from the CGAL library's Isosurfacing module, specifically the `CGAL::Isosurfacing::marching_cubes` function designed to work with domain objects like `MC_Domain` [S1]. It builds on the classic Marching Cubes algorithm by Lorensen and Cline (1987) [S2] and adapts it for hierarchical data structures. The `MC_Domain` abstraction allows the algorithm to be decoupled from the specific grid implementation, enabling the use of octrees [S1].
