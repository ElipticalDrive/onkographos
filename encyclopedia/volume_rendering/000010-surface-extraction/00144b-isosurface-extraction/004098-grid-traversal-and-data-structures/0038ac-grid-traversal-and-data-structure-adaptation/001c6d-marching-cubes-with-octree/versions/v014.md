# Marching Cubes with Octree


## Overview
Marching Cubes with Octree extracts a manifold isosurface from a scalar field by applying the standard Marching Cubes algorithm selectively over an octree data structure, rather than a uniform grid [S1]. It sets itself apart from [Sparse Marching Cubes](3825-sparse-marching-cubes.md) by using a hierarchical octree decomposition defined by a split predicate, and from [Hierarchical Marching Cubes Enumeration](5223-hierarchical-marching-cubes-enumeration.md) by relying on the CGAL `MC_Domain` abstraction for automatic mesh assembly [S1]. It solves the problem of processing large volumes efficiently by skipping empty or uniform regions, provided the octree refinement maintains uniform depth around the isosurface to avoid topological cracks [S1].

## How it works
**Inputs:**
1.  A 3D bounding box defined by minimum and maximum points ($P_{min}, P_{max}$).
2.  A split predicate function $S(v, level)$ that determines whether a voxel at a given octree level should be subdivided.
3.  A scalar field function $f(P)$ that returns the value at any point $P$ in space.
4.  An isovalue $I$ defining the surface threshold.

**Outputs:**
1.  A list of vertices $V$.
2.  A list of triangles $T$ (indices into $V$).

**Data Structures:**
*   **Octree:** A hierarchical structure where each node represents a cubic voxel. Nodes are refined based on $S$. The structure supports traversal and value lookup.
*   **Values:** An object binding the scalar function $f$ and the Octree, allowing efficient evaluation of $f$ at voxel corners.
*   **MC_Domain:** An abstraction that provides the interface for the marching cubes algorithm to query the octree structure and scalar values. It handles the mapping between octree nodes and the local cube indices required by the Marching Cubes lookup table.

**Steps:**
1.  **Initialize Bounding Box:** Define the root voxel bounds using $P_{min}$ and $P_{max}$.
2.  **Build Octree:** Create an empty Octree rooted at the bounding box.
3.  **Refine Octree:** Recursively apply the split predicate $S$ to each node. If $S$ returns true, subdivide the node into 8 children. This process continues until the predicate returns false for all leaf nodes or a maximum depth is reached.
4.  **Create Values Object:** Instantiate a `Values` object that wraps the scalar function $f$ and the constructed Octree. This object must support evaluating $f$ at the 8 corners of any active voxel.
5.  **Initialize Output Containers:** Create empty containers for points (vertices) and polygons (triangles).
6.  **Construct MC_Domain:** Instantiate the `MC_Domain` object, passing the Octree and Values object. This domain object abstracts the grid topology.
7.  **Execute Marching Cubes:** Call the marching cubes function with the `MC_Domain`, isovalue $I$, and output containers. The algorithm iterates over all active leaf nodes of the octree.
    *   For each active leaf node (voxel):
        *   Retrieve scalar values $v_j$ at the 8 corners $j=0..7$.
        *   Compute the cube index $C = \sum_{j=0}^{7} \text{bit}_j \cdot 2^j$, where $\text{bit}_j = 1$ if $v_j < I$, else $0$.
        *   Determine intersecting edges and interpolate vertex positions.
        *   Generate triangles based on the standard Marching Cubes lookup table for index $C$.
        *   Add generated vertices and triangles to the output containers.
8.  **Post-Processing (Implicit):** The `MC_Domain` and CGAL implementation handle the merging of shared vertices and edges to ensure a watertight mesh, assuming the octree refinement is consistent (see Pitfalls).

**Pseudocode:**
```python
def run_marching_cubes_octree(bbox_min, bbox_max, split_predicate, scalar_function, isovalue):
    # 1. Define bounding box points
    bbox_points = [bbox_min, bbox_max]
    
    # 2. Construct Octree
    octree = Octree(bbox_points)
    
    # 3. Refine Octree using split predicate
    # The split predicate takes a node and its level, returns True if it should be subdivided
    octree.refine(split_predicate)
    
    # 4. Create Values object binding scalar function and octree
    values = Values(scalar_function, octree)
    
    # 5. Initialize output containers
    points = []
    triangles = []
    
    # 6. Construct MC_Domain
    mcdomain = MC_Domain(octree, values)
    
    # 7. Call Marching Cubes
    # This function iterates over active nodes, applies MC logic, and fills points/triangles
    marching_cubes(mcdomain, isovalue, points, triangles)
    
    return points, triangles
```

**Parameters:**
*   `isovalue`: The threshold value for the scalar field. Typical values depend on the specific field (e.g., 0 for signed distance fields, 0.5 for normalized density).
*   `split_predicate`: Defines the resolution. A common strategy is to split nodes that intersect the isosurface or have high gradient magnitude.

**Edge Cases and Pitfalls:**
*   **Cracks at Discontinuities:** If the octree has varying depths around the isosurface (i.e., a fine node is adjacent to a coarse node), the standard Marching Cubes algorithm will produce cracks or non-manifold geometry because the coarse node does not provide enough vertices to match the fine node's edges [S1].
*   **Uniform Refinement Requirement:** To guarantee a manifold surface, the octree must be split with uniform size around the surface. This often implies a maximum depth constraint or a specific splitting rule that ensures neighbors do not differ by more than one level without intermediate handling [S1].

## Subtopics

### [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md)
Linear Hashed Marching Cubes is a surface extraction method that converts volumetric isosurfaces into triangle meshes by applying the Marching Cubes algorithm over a linear hashed octree data structure. It serves as a loose implementation of the "Fast Generation of Pointerless Octree Duals" technique, designed to accelerate mesh generation compared to standard grid-based marching cubes. It sets itself apart from standard MC with Octree by using a linear hash table for node storage, reducing memory overhead and improving cache locality, and is chosen when memory efficiency and speed are critical for large, sparse volumes. Link: [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md).

### [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md)
This method extracts isosurfaces from adaptive resolution (AR) octree volume data by decoupling geometry generation from discontinuity resolution. It solves the topological inconsistencies that arise when fine-resolution cubes share edges or faces with coarser, unsubdivided neighbors. Unlike uniform resolution methods, it reduces data access and processing time by skipping large uniform regions, while the two-pass approach ensures a watertight mesh without requiring complex on-the-fly edge matching logic during the primary traversal. It is chosen when handling AR octrees with significant depth variations is required without manual crack filling. Link: [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md).

### [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md)
Adaptive Marching Cubes is an extension of the standard Marching Cubes algorithm designed to extract isosurfaces from Adaptive Resolution (AR) octree data. It solves the problem of topological inconsistencies and geometric artifacts that arise when adjacent cubes in the mesh have different resolutions. Unlike uniform marching cubes, it handles missing vertices and discontinuities by deferring the processing of coarser nodes that conflict with finer neighbors, ensuring a watertight mesh across resolution boundaries. It is chosen when a simpler two-pass approach is not feasible or when deferred processing fits the pipeline better. Link: [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md).

### [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md)
DMC Octree Contour Extraction is an adaptive isosurface extraction method that generates a manifold triangle mesh from volumetric scalar field data using a dual-contouring approach on an octree structure. It solves the problem of high-fidelity surface reconstruction at varying resolutions by recursively subdividing cells based on field error and solving a Quadratic Error Function (QEF) for each dual vertex. It sets itself apart from its sibling [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md) by using dual vertices and QEF solving rather than linear interpolation on grid edges, and from [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) by explicitly managing topological consistency through a recursive face/edge/vertex processing pipeline that ensures shared boundaries between adjacent octree nodes are handled deterministically. It is chosen when preserving sharp features and complex geometry is more important than the speed of linear interpolation. Link: [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md).

### [Simplicial Partition Isosurfacing](9787-simplicial-partition-isosurfacing.md)
Simplicial Partition Isosurfacing extracts a manifold, intersection-free isosurface from a scalar function defined over an arbitrary octree by partitioning space into simplices (tetrahedra) dual to minimal octree cells. Unlike Dual Contouring, which produces non-manifold geometry in ambiguous sign configurations, and Dual Marching Cubes, which can generate self-intersecting surfaces due to non-convex dual cells, this method guarantees manifold topology and prevents tetrahedron inversion, ensuring the surface cannot self-intersect. It is chosen when topological correctness and intersection-free guarantees are paramount, even at the cost of higher computational complexity. Link: [Simplicial Partition Isosurfacing](9787-simplicial-partition-isosurfacing.md).

### Sparse-Voxel TSDF Fusion and Marching Cubes
This variant extracts mesh by adapting TSDF-Fusion and Marching Cubes into the sparse voxel representation [S2]. It implements sparse-voxel TSDF-Fusion to compute truncated signed distance values of the sparse grid points, then extracts the surface of the zero-level set using sparse-voxel Marching Cubes [S2]. Duplicated vertices from adjacent voxels are merged to produce a unique set of vertices [S2]. If adjacent voxels belong to different Octree levels, it subdivides all voxels to the finest level to remove discontinuities in the density field [S2]. It sets itself apart from methods relying on coarse geometry priors (like SfM) by modeling the scene only with a density field [S2]. Pitfalls include producing unnecessary geometric bumps for texture details and potential disconnection of triangles when adjacent voxels are at different octree levels if not subdivided [S2]. It is chosen for real-time high-fidelity radiance field rendering from sparse sensor data. Link: N/A (Minor variant).

## Operating characteristics
*   **Time Complexity:** Depends on the number of active leaf nodes in the octree. In the worst case (uniform grid), it is $O(N^3)$ where $N$ is the resolution. In sparse cases, it is proportional to the surface area of the isosurface times the average octree depth.
*   **Memory Complexity:** Proportional to the number of octree nodes. Linear hashed variants reduce overhead compared to pointer-based octrees.
*   **Measured Performance:** CGAL's implementation supports parallel execution (`Parallel_if_available_tag`), scaling well on multi-core CPUs [S1].
*   **Strengths:** Efficiently handles large, sparse volumes; leverages robust CGAL implementation; automatic mesh assembly via `MC_Domain`.
*   **Limitations:** Requires careful octree refinement to avoid cracks; not inherently suitable for highly adaptive resolutions without additional handling (see Subtopics).
*   **When to use:** When the volume is sparse or has large uniform regions, and the isosurface can be captured with a reasonably uniform octree depth around the surface.
*   **When not to use:** When the volume has extreme resolution variations adjacent to the isosurface without a strategy to handle discontinuities (e.g., standard MC with Octree will crack).

## Background
The method originates from the CGAL library's Isosurfacing module, specifically the `CGAL::Isosurfacing::marching_cubes` function designed to work with domain objects like `MC_Domain` [S1]. It builds on the classic Marching Cubes algorithm by Lorensen and Cline (1987) [S2] and adapts it for hierarchical data structures. The `MC_Domain` abstraction allows the algorithm to be decoupled from the specific grid implementation, enabling the use of octrees. The approach is part of a broader family of grid traversal and data structure adaptation methods aimed at efficient surface extraction [S1].
