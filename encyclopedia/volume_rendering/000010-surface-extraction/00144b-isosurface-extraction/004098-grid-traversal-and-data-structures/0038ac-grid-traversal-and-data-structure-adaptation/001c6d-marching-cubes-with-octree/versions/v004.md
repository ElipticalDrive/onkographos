# Marching Cubes with Octree


## Overview
Marching Cubes with Octree extracts isosurfaces from scalar fields defined over an adaptive octree structure, enabling efficient processing of sparse or high-resolution volumetric data by skipping empty or uniform regions. Unlike uniform grid methods, it adapts the computational domain to the geometry, reducing memory overhead and processing time for large scenes [S1]. It sets itself apart from sibling methods like [Sparse Marching Cubes](3825-sparse-marching-cubes.md) by explicitly managing the hierarchical tree structure during traversal, and from [Transvoxel](6277-transvoxel.md) by relying on standard linear interpolation within octree nodes rather than specialized transition cells for level-set boundaries [S1].

## How it works
The method operates by constructing an octree that subdivides a 3D bounding box based on a split predicate, then applying the standard Marching Cubes lookup logic to each leaf node that intersects the isosurface.

**Inputs and Outputs:**
*   **Input:** A 3D bounding box defined by minimum and maximum points ($P_{min}, P_{max}$), a scalar field function $f(P)$, an isovalue $I$, and a split predicate function $S(node)$ that determines if a node should be subdivided.
*   **Output:** A set of vertices (points) and a set of triangles (polygons) representing the extracted mesh [S1].

**Data Structures:**
1.  **Octree Node:** Represents a cubic volume. Each node stores its spatial bounds and a flag indicating if it is a leaf. The tree is built recursively: if $S(node)$ is true, the node is split into 8 children; otherwise, it remains a leaf [S1].
2.  **Values Object:** Encapsulates the scalar function $f$ and the octree structure, providing access to scalar values at any point in space [S1].
3.  **MC_Domain:** A domain object that interfaces the octree and values with the marching cubes algorithm. It handles the traversal and coordinate mapping [S1].
4.  **Edge Intersection Table (`edgeTable`)** and **Triangle Connection Table (`triangleTable`)**: As defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md). These tables are used for each leaf node [S1, S12].

**Algorithm Steps:**
1.  **Initialize Bounding Box:** Define the global bounding box using $P_{min} = (xmin, ymin, zmin)$ and $P_{max} = (xmax, ymax, zmax)$ [S1].
2.  **Construct Octree:** Create an octree object initialized with the bounding box points [S1].
3.  **Refine Octree:** Recursively refine the octree by applying the split predicate $S(node)$ to each node. If $S(node)$ returns true, split the node into 8 children and recurse. If false, mark as leaf [S1].
4.  **Create Values Object:** Instantiate a `Values` object containing the scalar function $f$ and the constructed octree [S1].
5.  **Initialize Output Containers:** Create empty containers for output vertices (`Point_range`) and triangles (`Polygon_range`) [S1].
6.  **Construct MC_Domain:** Create an `MC_Domain` object passing the octree and values object [S1].
7.  **Execute Marching Cubes:** Call the marching cubes function with the `MC_Domain`, isovalue $I$, and output containers. The implementation typically uses parallel execution (`Parallel_if_available_tag`) [S1].
    *   For each leaf node in the octree:
        a.  Evaluate the scalar field $f$ at the 8 vertices of the node's cube.
        b.  Compute the case index $C$ by comparing each vertex value to $I$. If $f(v_i) < I$, set bit $i$ of $C$ to 1; otherwise 0 [S7, S8].
        c.  If $C = 0$ or $C = 255$, no intersection occurs; skip the node.
        d.  Use `edgeTable[C]` to determine which edges are intersected.
        e.  Interpolate the intersection points on the intersected edges using linear interpolation:
            $$ P_{interp} = v_a + \frac{I - f(v_a)}{f(v_b) - f(v_a)} (v_b - v_a) $$
            where $v_a$ and $v_b$ are the endpoints of the intersected edge [S12].
        f.  Use `triangleTable[C]` to form triangles from the interpolated points.
        g.  Add the generated vertices and triangles to the output containers [S1].

**Parameters:**
*   **Isovalue ($I$):** The scalar value defining the surface. Typical values depend on the data range (e.g., 0.0 for normalized signed distance fields) [S1].
*   **Split Predicate ($S$):** Determines refinement. Common predicates include checking if the node contains the isovalue or if the scalar variance exceeds a threshold [S1].

**Edge Cases and Pitfalls:**
*   **Cracks at Level Discontinuities:** If the octree has varying depths around the isosurface (i.e., fine nodes adjacent to coarse nodes), standard linear interpolation produces cracks because the coarse node's single triangle does not align with the fine node's multiple triangles [S1]. The method requires uniform node sizes around the surface to guarantee a manifold result [S1].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous. The standard LUT uses a fixed triangulation, which can cause holes if adjacent voxels resolve the ambiguity differently [S7, S8].

**Pseudocode:**
```python
def run_marching_cubes_octree(bbox_min, bbox_max, scalar_func, isovalue, split_predicate):
    # Step 1: Construct Octree
    octree = Octree(bbox_min, bbox_max)
    
    # Step 2: Refine Octree
    def refine(node):
        if split_predicate(node):
            node.split_into_8_children()
            for child in node.children:
                refine(child)
        else:
            node.is_leaf = True
            
    refine(octree.root)
    
    # Step 3: Initialize Output
    points = []
    triangles = []
    
    # Step 4: Traverse and Extract
    for node in octree.get_leaves():
        # Evaluate scalar field at 8 vertices
        vertex_values = [scalar_func(node.vertex(i)) for i in range(8)]
        
        # Compute case index
        case_index = 0
        for i in range(8):
            if vertex_values[i] < isovalue:
                case_index |= (1 << i)
                
        # Skip if no intersection
        if case_index == 0 or case_index == 255:
            continue
            
        # Get intersected edges from edgeTable
        intersected_edges = get_edges_from_table(case_index, edgeTable)
        
        # Intersect points
        interp_points = []
        for edge_idx in intersected_edges:
            v_a_idx, v_b_idx = edge_endpoints[edge_idx]
            v_a = node.vertex(v_a_idx)
            v_b = node.vertex(v_b_idx)
            val_a = vertex_values[v_a_idx]
            val_b = vertex_values[v_b_idx]
            
            # Linear interpolation [G]
            t = (isovalue - val_a) / (val_b - val_a)
            p_interp = v_a + t * (v_b - v_a)
            interp_points.append(p_interp)
            
        # Generate triangles from triangleTable
        tri_indices = get_triangles_from_table(case_index, triangleTable)
        for i in range(0, len(tri_indices), 3):
            if tri_indices[i] == -1:
                break
            idx_a = tri_indices[i]
            idx_b = tri_indices[i+1]
            idx_c = tri_indices[i+2]
            
            # Map edge indices to interpolated points
            # Note: edgeTable returns edge indices, triangleTable returns edge indices
            # We need to map edge index to the position in interp_points
            # This requires a consistent mapping between edge index and interp_points order
            p_a = interp_points[edge_to_point_index[idx_a]]
            p_b = interp_points[edge_to_point_index[idx_b]]
            p_c = interp_points[edge_to_point_index[idx_c]]
            
            triangles.append((p_a, p_b, p_c))
            
    return points, triangles
```

## Subtopics

### [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md)
Linear Hashed Marching Cubes extracts triangle meshes from implicit scalar fields by applying the Marching Cubes algorithm over a linear hashed octree. It replaces the standard grid-based traversal with a pointerless octree structure to reduce memory overhead and improve performance. It builds on [Marching Cubes with Octree](1259-marching-cubes-with-octree.md) but uses a linear hash table for node storage instead of a primal grid.

### [Adaptive Resolution Isosurface Rendering with Two-Pass Discontinuity Handling](1340-adaptive-resolution-isosurface-rendering-with-two-pass-disco.md)
This method extracts isosurfaces from adaptive resolution (AR) octree volume data by decoupling geometry generation from discontinuity resolution. It solves the topological inconsistencies that arise when fine-resolution cubes share edges or faces with coarser, unsubdivided neighbors. Unlike uniform resolution methods, it reduces data access and processing time by skipping large uniform regions, while the two-pass approach ensures a watertight mesh without requiring complex on-the-fly edge matching logic during the primary traversal.

### [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md)
Adaptive Marching Cubes is an extension of the standard Marching Cubes algorithm designed to extract isosurfaces from Adaptive Resolution (AR) octree data. It solves the problem of topological inconsistencies and geometric artifacts that arise when adjacent cubes in the mesh have different resolutions. Unlike uniform marching cubes, it handles missing vertices and discontinuities by deferring the processing of coarser nodes that conflict with finer neighbors, ensuring a watertight mesh across resolution boundaries.

### [DMC Octree Contour Extraction](3661-dmc-octree-contour-extraction.md)
DMC Octree Contour Extraction is an adaptive isosurface extraction method that generates a manifold triangle mesh from volumetric scalar field data using a dual-contouring approach on an octree structure. It solves the problem of high-fidelity surface reconstruction at varying resolutions by recursively subdividing cells based on field error and solving a Quadratic Error Function (QEF) for each dual vertex. It sets itself apart from its sibling [Linear Hashed Marching Cubes](1294-linear-hashed-marching-cubes.md) by using dual vertices and QEF solving rather than linear interpolation on grid edges, and from [Adaptive Marching Cubes](1351-adaptive-marching-cubes.md) by explicitly managing topological consistency through a recursive face/edge/vertex processing pipeline that ensures shared boundaries between adjacent octree nodes are handled deterministically.

### Sparse-Voxel TSDF Fusion and Marching Cubes
This variant extracts mesh by adapting TSDF-Fusion and Marching Cubes into the sparse voxel representation [S2]. It implements sparse-voxel TSDF-Fusion to compute truncated signed distance values of the sparse grid points, then extracts the surface of the zero-level set using sparse-voxel Marching Cubes [S2]. Duplicated vertices from adjacent voxels are merged to produce a unique set of vertices [S2]. If adjacent voxels belong to different Octree levels, all voxels are subdivided to the finest level to remove discontinuities in the density field [S2]. Unlike methods relying on coarse geometry priors, this method models the scene only with a density field [S2]. Pitfalls include producing unnecessary geometric bumps for texture details and disconnected triangles when adjacent voxels are at different Octree levels due to discontinuous density fields [S2].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of leaf nodes in the octree that intersect the isosurface. The split predicate determines the number of nodes, potentially reducing $N$ significantly compared to a uniform grid of equivalent resolution [S1].
*   **Memory Complexity:** Proportional to the number of octree nodes. Adaptive subdivision reduces memory usage for sparse data compared to uniform grids [S1].
*   **Performance:** Efficient for large scenes with localized features. Parallel execution (`Parallel_if_available_tag`) can further accelerate processing [S1].
*   **Strengths:** Memory efficiency for sparse data, adaptability to complex geometries, parallelizability [S1].
*   **Limitations:** Cracks at level discontinuities if the split predicate creates non-uniform depth around the surface [S1]. Requires careful handling of topological ambiguities [S7, S8].
*   **When to Use:** Large volumetric datasets with sparse features, or when memory is a constraint.
*   **When Not to Use:** When uniform resolution is required, or when strict manifold guarantees are needed without post-processing discontinuities [S1].

## Background
The method originates from the CGAL library's Isosurfacing module, which provides robust implementations of isosurfacing algorithms including Marching Cubes on octrees [S1]. The underlying Marching Cubes algorithm was introduced by Lorensen and Cline in 1987 [S2]. The adaptation to octrees allows for efficient processing of sparse volumetric data, building on the principles of adaptive mesh refinement [S1].
