# Octree-based Isosurfacing

Also called: Contouring using Octrees, Isosurface extraction with Octree discretization

## Overview
Octree-based isosurfacing replaces the uniform Cartesian grid of traditional methods like [Marching Cubes](30-isosurface-extraction.md) with an adaptive octree spatial discretization [S1]. This allows for high-resolution representation of complex surfaces while reducing memory usage in empty regions. Unlike its siblings, it decouples the domain structure from the extraction algorithm via a generic interface, but it loses the topological guarantees of uniform grids, potentially causing cracks if the octree is not sufficiently adapted to the surface [S1].

## How it works
The method operates by constructing an octree that subdivides the domain based on a split predicate, then passing this structure to an isosurfacing algorithm (such as Marching Cubes or Dual Contouring) through a domain abstraction [S1].

**Inputs and Outputs:**
*   **Input:** A bounding box defined by minimum and maximum points, a split predicate function (determining refinement), a scalar value function, and a gradient function (optional, for Dual Contouring) [S1].
*   **Output:** A set of vertices and triangles (polygon soup) representing the isosurface [S1].

**Data Structures:**
*   **Octree:** A hierarchical spatial partition. Each node represents a rectilinear block. Leaf nodes contain the finest resolution cells [S1][S2, unofficial].
*   **Domain Object:** An abstraction that binds the octree, value function, and gradient function, providing a uniform interface to the extraction algorithm regardless of the underlying spatial structure [S1].

**Steps:**
1.  **Initialize Octree:** Create an octree with a bounding box defined by two corner points (min and max) [S1].
2.  **Refine:** Recursively subdivide nodes using a split predicate function. The predicate determines if a node should be split based on the scalar field's behavior (e.g., if the isovalue lies within the node's value range) [S1].
3.  **Traverse:** Collect all leaf nodes from the octree [S1].
4.  **Construct Functions:** Bind the scalar value function and gradient function to the octree structure [S1].
5.  **Create Domain:** Instantiate a domain object passing the octree, values, and gradients [S1].
6.  **Extract:** Run the isosurfacing algorithm (e.g., Dual Contouring or Marching Cubes) on the domain object [S1].

**Pseudocode:**
```python
def octree_isosurfacing(bbox_min, bbox_max, split_predicate, value_func, gradient_func, isovalue, algorithm="dual_contouring"):
    # 1. Initialize Octree
    bbox_points = [bbox_min, bbox_max]
    octree = Octree(bbox_points)
    
    # 2. Refine Octree
    octree.refine(split_predicate)
    
    # 3. Traverse to collect leaves
    leaf_range = octree.traverse(Leaves_traversal(octree))
    
    # 4. Construct Value and Gradient functions bound to octree
    values = ValueFunction(value_func, octree)
    gradients = GradientFunction(gradient_func, octree)
    
    # 5. Create Domain Object
    domain = Domain(octree, values, gradients)
    
    # 6. Run Isosurfacing Algorithm
    if algorithm == "dual_contouring":
        points, triangles = dual_contouring(
            domain, 
            isovalue, 
            do_not_triangulate_faces=True, 
            constrain_to_cell=False
        )
    elif algorithm == "marching_cubes":
        points, triangles = marching_cubes(
            domain, 
            isovalue
        )
    else:
        raise ValueError("Unsupported algorithm")
        
    return points, triangles
```

**Parameters:**
*   `do_not_triangulate_faces`: Boolean parameter for Dual Contouring to skip face triangulation [S1].
*   `constrain_to_cell`: Boolean parameter for Dual Contouring, typically set to `false` [S1].
*   `isovalue`: The scalar threshold for surface extraction [S1].

**Edge Cases and Pitfalls:**
*   **Cracks:** If the octree is not sufficiently adapted to the surface geometry, cracks can appear in the Marching Cubes surface because the method loses guarantees when applied to non-uniform grids [S1].
*   **Topological Integrity:** Unlike uniform grid methods, octree-based methods do not inherently guarantee watertightness without specific handling of mismatched tree depths at boundaries [S1][S2, unofficial].

## Subtopics

### [Standard Interval Tree for Isosurface Extraction](1230-standard-interval-tree-for-isosurface-extraction.md)
Uses a binary tree of value intervals on a fixed Cartesian grid to efficiently identify active cells, decoupling spatial locality from value-based filtering.

### [Marching Cubes with Octree](1259-marching-cubes-with-octree.md)
Adapts Marching Cubes to an adaptive octree via a generic `MC_Domain` interface, allowing arbitrary split predicates but lacking inherent crack prevention.

### [IsoOctree](1744-isooctree.md)
Operates on arbitrary octrees by computing the Euclidean Distance Transform (EDT) of an input mesh, enabling adaptive mesh simplification.

### [Wilhelms and Van Gelder Octree](2107-wilhelms-and-van-gelder-octree.md)
Accelerates extraction by pruning octree branches where the value interval does not contain the isovalue, focusing on efficient cell enumeration.

### [Ashida and Badla Octree Contouring](2117-ashida-and-badla-octree-contouring.md)
Extracts contours directly from octrees by identifying cycles of contour faces, avoiding uniform grids but potentially producing non-manifold edges.

### [Unconstrained Isosurface Extraction on Arbitrary Octrees](2413-unconstrained-isosurface-extraction-on-arbitrary-octrees.md)
Guarantees watertightness on arbitrary octrees using binary edge-trees to resolve inconsistencies at face boundaries without refining the tree.

### [Consistent Isovertex Definition via Edge-Trees](2427-consistent-isovertex-definition-via-edge-trees.md)
Resolves ambiguous isovertex positions on coarse edges by traversing an edge-tree to a unique leaf, ensuring watertightness.

### [Adaptive Octree Generation with Flatness Criterion](2482-adaptive-octree-generation-with-flatness-criterion.md)
Refines octrees based on geometric flatness of surface intersections, allowing coarser representation of planar regions.

### [Sampled DMC](3813-sampled-dmc.md)
Adapts Dual Marching Cubes to hashed octrees using Morton keys, constructing a dual grid with vertices at leaf centers.

### [Hierarchical Marching Cubes Enumeration](5223-hierarchical-marching-cubes-enumeration.md)
Recursively traverses the octree to enumerate faces/edges/vertices, delegating to standard Marching Cubes at leaves to handle mismatched depths.

### Canonical Enumeration
The elementary method for cell extraction that sequentially visits all cells in the volume to identify active cells [S2, unofficial]. It checks if the isovalue $t$ is contained in the half-open interval $[v_{min}, v_{max})$, where $v_{min} = \min(V_{i,j,k})$ and $v_{max} = \max(V_{i,j,k})$ [S2, unofficial]. The range of the interpolation function $\hat{f}$ in a cell is defined as $\hat{f}(C_{i,j,k}) = [v_{min}, v_{max}]$ [S2, unofficial]. Time complexity is $O(n)$ where $n$ is the volume size, with memory usage limited to the original data and small constants [S2, unofficial].

### Point-based Isosurface Extraction with Octree Pruning
A view-dependent algorithm that divides the model into grid cells until sub-pixel resolution is achieved, using point primitives [S3, unofficial]. It performs a front-to-back octree traversal with two pruning strategies: value-based pruning (discarding nodes where values are outside the isosurface limit, requiring min/max storage at nodes) and visibility pruning (discarding nodes whose bounding boxes do not contribute to the image) [S3, unofficial]. Robust normals are computed via a fragment program using world coordinates [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The canonical enumeration approach is $O(n)$, where $n$ is the number of cells [S2, unofficial]. Octree-based methods can achieve better performance by pruning inactive regions, but the complexity depends on the tree depth and the efficiency of the split predicate [S2, unofficial].
*   **Memory Complexity:** Requires storage for the octree structure and the original volume data. The octree adds overhead for node pointers and metadata (min/max values) [S2, unofficial].
*   **Strengths:** Adaptive resolution allows for detailed surface representation with fewer cells than uniform grids; efficient pruning of empty space [S1][S2, unofficial].
*   **Limitations:** Loss of topological guarantees (cracks) if the octree is not adapted to the surface; implementation complexity due to non-uniform grid handling [S1].
*   **When to use:** When the surface is complex and localized, or when memory constraints prevent uniform grid storage.
*   **When not to use:** When strict watertightness is required without additional boundary handling, or when the surface is uniformly distributed (uniform grids may be simpler and faster).

## Background
The use of octrees for isosurface extraction was proposed by Wilhelms and Van Gelder as a hierarchical spatial subdivision method to accelerate cell enumeration [S2, unofficial]. The approach is implemented in libraries such as CGAL, which provides domain abstractions to decouple the octree structure from algorithms like Marching Cubes and Dual Contouring [S1]. View-dependent point-based extraction using octree pruning has also been explored for GPU-based volume rendering [S3, unofficial].
