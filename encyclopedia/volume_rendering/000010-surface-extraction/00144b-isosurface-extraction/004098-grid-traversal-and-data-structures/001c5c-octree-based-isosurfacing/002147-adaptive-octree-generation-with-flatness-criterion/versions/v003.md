# Adaptive Octree Generation with Flatness Criterion

Also called: Adaptive Octree Generation

## Overview
This method generates an adaptive octree discretization for isosurface extraction by recursively refining nodes based on the geometric flatness of the surface intersection within them [S1, unofficial]. It differs from sibling methods that rely on uniform sampling thresholds or simple interval trees by explicitly measuring curvature-to-area ratios to determine refinement, ensuring that highly curved regions are resolved with higher density while flat regions remain coarse [S1, unofficial]. It serves as the spatial subdivision stage for subsequent surface extraction algorithms like Dual Marching Cubes [S2, unofficial].

## How it works
**Inputs:**
- A scalar field function $F(\mathbf{p})$ defined over 3D space.
- A threshold value $T$ for isosurface extraction.
- A root bounding box (the initial octree node).
- Parameters: `SamplingSize` (base spacing), `Threshold`, `Dropoff`, `HorizontalScale`, `VerticalScale` [S2, unofficial].

**Outputs:**
- An adaptive octree where leaf nodes represent voxels containing the isosurface or empty space, refined according to the flatness criterion.
- Vertex values assigned to the octree vertices via Euclidean distance transform sampling [S1, unofficial].

**Data Structures:**
The octree consists of nodes. Each node contains:
- `Bounds`: A bounding box (min/max coordinates) defining the spatial extent.
- `Depth`: Integer depth level (root is 0).
- `Children`: An array of 8 child nodes (if not a leaf), or `null` (if a leaf).
- Children are ordered in a fixed pattern based on coordinate offsets relative to the node's center:
  0. $(-X, -Y, -Z)$
  1. $(+X, -Y, -Z)$
  2. $(+X, -Y, +Z)$
  3. $(-X, -Y, +Z)$
  4. $(-X, +Y, -Z)$
  5. $(+X, +Y, -Z)$
  6. $(+X, +Y, +Z)$
  7. $(-X, +Y, +Z)$
  [S2, unofficial]

**Algorithm Steps:**

1. **Initialize:** Start with the root node covering the entire scene bounds.
2. **Iterate:** Process nodes (typically in breadth-first or depth-first order) to determine if they should be split.
3. **Calculate Sampling Interval:** For a node at `Depth`, compute the sampling interval:
   $$ \text{samplingSize} = \text{SamplingSize} \times \ln(\text{Depth} + 2) $$
   [S2, unofficial]
4. **Determine Sample Count:** Calculate the number of samples per axis ($n_x, n_y, n_z$) required to cover the node's bounds with the calculated interval:
   $$ n_{axis} = 1 + \lceil \frac{\text{Bounds.size}_{axis}}{\text{samplingSize}} \rceil $$
   [S2, unofficial]
5. **Minimum Sample Check:** If any axis has fewer than 3 samples ($n_x < 3$ or $n_y < 3$ or $n_z < 3$), do not split the node. It is considered a leaf. [S2, unofficial]
6. **Sample Field:** Iterate over the **interior** samples only. For $z$ from $1$ to $n_z-2$, $y$ from $1$ to $n_y-2$, and $x$ from $1$ to $n_x-2$:
   a. Compute sample position using linear interpolation within the node bounds:
      $$ x_F = \text{Lerp}(\text{Bounds.min}_x, \text{Bounds.max}_x, \frac{x}{n_x}) $$
      (Similarly for $y_F$ and $z_F$) [S2, unofficial]
   b. Evaluate the field $F(x_F, y_F, z_F)$.
   c. Determine if the sample is above or below the threshold $T$.
   d. Track flags: `isBelow` (if any sample $\le T$) and `isAbove` (if any sample $> T$).
   e. If both `isBelow` and `isAbove` are true, the node intersects the surface. Stop sampling this node. [S2, unofficial]
7. **Split Decision:**
   - If the node does not intersect the surface (only `isBelow` or only `isAbove`), it is a leaf (empty or fully inside).
   - If the node intersects the surface, calculate the **flatness** of the intersection.
     $$ \text{flatness} = \frac{\|\vec{H}\|}{\text{Area}} $$
     where $\vec{H}$ is the mean curvature vector of the intersected surface and $\text{Area}$ is its area. [S1, unofficial]
   - If the intersection is "too flat" (flatness below a certain implicit or explicit threshold), the node may remain a leaf or be split based on further criteria. If not too flat, split the node into 8 children. [S1, unofficial]
   - *Note:* The source code [S2, unofficial] splits the node if `isBelow` and `isAbove` are both true, without explicitly calculating the flatness formula in the provided snippet. The flatness criterion is described in the theoretical context [S1, unofficial] as the measure for deciding if an intersection is "too flat" to warrant further refinement or if it should be treated as a planar surface. The implementation in [S2, unofficial] uses the presence of intersection (sign change) as the primary split trigger in the visible code, potentially relying on the sampling density (controlled by `SamplingSize` and depth) to implicitly handle flatness, or the flatness check is applied in a post-processing or alternative branch not fully detailed in the snippet. However, the definition [S1, unofficial] explicitly states the flatness ratio is the measure.
8. **Child Creation:** If splitting, create 8 children. Each child's bounds are half the size of the parent. The min/max of each child is determined by adding/subtracting half the new size from the parent's center, following the fixed ordering defined in the Data Structures section. [S2, unofficial]
9. **Vertex Value Assignment:** Assign values to the vertices of the octree by sampling the Euclidean distance transform. [S1, unofficial]

**Pseudocode:**

```python
def generate_adaptive_octree(root_bounds, field_func, threshold, sampling_size_base):
    """
    Generates an adaptive octree based on flatness criterion and field sampling.
    """
    root = OctreeNode(bounds=root_bounds, depth=0, children=None)
    queue = [root]
    
    while queue:
        node = queue.pop(0)
        
        # 1. Calculate sampling interval based on depth
        # Note: ln is natural logarithm
        sampling_size = sampling_size_base * math.log(node.depth + 2)
        
        # 2. Determine number of samples per axis
        n_samples = count_samples(node.bounds, sampling_size)
        
        # 3. Check minimum sample requirement
        if n_samples.x < 3 or n_samples.y < 3 or n_samples.z < 3:
            continue # Cannot split, remains leaf
        
        # 4. Sample interior points
        is_below = False
        is_above = False
        intersects = False
        
        for z in range(1, n_samples.z - 1):
            for y in range(1, n_samples.y - 1):
                for x in range(1, n_samples.x - 1):
                    # Linear interpolation for position
                    pos_x = lerp(node.bounds.min.x, node.bounds.max.x, x / n_samples.x)
                    pos_y = lerp(node.bounds.min.y, node.bounds.max.y, y / n_samples.y)
                    pos_z = lerp(node.bounds.min.z, node.bounds.max.z, z / n_samples.z)
                    
                    val = field_func(Vector3(pos_x, pos_y, pos_z))
                    
                    if val <= threshold:
                        is_below = True
                    if val > threshold:
                        is_above = True
                    
                    if is_below and is_above:
                        intersects = True
                        break # Found intersection, no need to sample more for split decision
                if intersects: break
            if intersects: break
        
        # 5. Split decision
        if intersects:
            # Theoretical flatness check (from S1)
            # flatness = norm(mean_curvature_vector) / area
            # If flatness is too high (or low, depending on definition of "too flat"), 
            # the node might not be split or handled differently.
            # In the provided implementation [S2, unofficial], intersection alone triggers split.
            # We assume split occurs if intersection is detected.
            
            # Create 8 children
            new_size = node.bounds.size / 2.0
            half_new_size = new_size / 2.0
            center = node.bounds.center
            
            children = []
            # Fixed order: 0:-X-Y-Z, 1:+X-Y-Z, 2:+X-Y+Z, 3:-X-Y+Z, 4:-X+Y-Z, 5:+X+Y-Z, 6:+X+Y+Z, 7:-X+Y+Z
            # Offsets relative to center
            offsets = [
                Vector3(-1, -1, -1), Vector3(1, -1, -1), Vector3(1, -1, 1), Vector3(-1, -1, 1),
                Vector3(-1, 1, -1), Vector3(1, 1, -1), Vector3(1, 1, 1), Vector3(-1, 1, 1)
            ]
            
            for i, offset in enumerate(offsets):
                child_min = center + offset * half_new_size
                child_max = child_min + new_size
                child_bounds = Bounds(child_min, child_max)
                child_node = OctreeNode(bounds=child_bounds, depth=node.depth + 1, children=None)
                children.append(child_node)
                queue.append(child_node)
            
            node.children = children
        else:
            # Leaf node, no children
            node.children = None
            
    return root

def count_samples(bounds, sample_interval):
    """
    Returns Vector3Int with number of samples per axis.
    Formula: 1 + ceil(size / interval)
    """
    x = 1 + math.ceil(bounds.size.x / sample_interval)
    y = 1 + math.ceil(bounds.size.y / sample_interval)
    z = 1 + math.ceil(bounds.size.z / sample_interval)
    return Vector3Int(x, y, z)

def lerp(a, b, t):
    return a + (b - a) * t
```

**Parameters:**
- `SamplingSize`: Base physical spacing between samples. Default: 1.0f [S2, unofficial].
- `Threshold`: Field value threshold for surface extraction. Default: 0.5f [S2, unofficial].
- `Dropoff`: Controls vertical falloff of the field. Default: 100.0f [S2, unofficial].
- `HorizontalScale`, `VerticalScale`: Scale factors for field sampling coordinates. Default: 0.01f, 0.05f [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** The use of `Mathf.Log` for sampling size adjustment can lead to very small intervals at high depths, potentially causing floating-point precision issues in coordinate calculation.
- **Boundaries:** The sampling loop excludes boundary samples (1 to $n-2$). This ensures interior sampling but may miss surface intersections very close to the node boundaries if the grid is coarse.
- **Flatness Calculation:** The flatness formula requires computing the mean curvature vector and area of the intersected surface. In practice, this is non-trivial and may be approximated or omitted in simple implementations (as seen in [S2, unofficial] where only sign change is used). If omitted, the method degrades to a standard adaptive octree based on sign changes.
- **Depth Disparity:** To avoid cracks in subsequent marching cubes steps, the depth disparity between adjacent nodes should be restricted to at most one [S1, unofficial]. This may require post-processing refinement of leaves.

## Subtopics

### [OcMesher](4141-ocmesher.md)
OcMesher is a method for extracting memory-efficient, highly detailed triangle meshes from unbounded scenes represented by signed distance functions (SDFs). It uses a view-dependent adaptive octree structure driven by a given set of camera views to refine geometry only where visible. Unlike parent methods that generate octrees based on surface flatness alone, OcMesher incorporates camera projection metrics to prioritize resolution based on projected pixel density.

### [Octree Leaf Construction with QEF Surface Fitting](4268-octree-leaf-construction-with-qef-surface-fitting.md)
This method constructs an octree leaf node representing a voxel containing an isosurface by solving a Quadratic Error Function (QEF) to determine the precise surface position and normal from edge intersections. It builds on [Adaptive Octree Generation with Flatness Criterion](2482-adaptive-octree-generation-with-flatness-criterion.md) by refining surface location within the leaf using a least-squares geometric fit rather than Euclidean distance transform sampling. It differs from [OcMesher](4141-ocmesher.md) by relying on a global QEF solver over all edge crossings rather than local marching cubes-style triangulation.

### [Robust Watertight Manifold Surface Generation](9549-robust-watertight-manifold-surface-generation.md)
This method converts an input triangle mesh into a watertight 2-manifold surface with roughly uniformly distributed vertices using an octree-based signed distance field (SDF) representation and isosurface extraction. It differs from uniform grid marching cubes by adaptively refining only the volume near the surface, reducing storage and computation linearly with the final mesh size. Unlike sibling methods that fit explicit surface primitives (e.g., QEF) or use complex occlusion handling, this pipeline guarantees topological correctness by defining "positive" space via boundary-connected BFS and resolving non-manifold ambiguities through vertex/edge splitting.

## Operating characteristics
- **Time Complexity:** Depends on the surface complexity and the flatness criterion. In the worst case (highly detailed surface), it approaches $O(N)$ where $N$ is the number of voxels in a uniform grid of the same resolution. However, for smooth or flat surfaces, it is significantly faster due to adaptive refinement.
- **Memory Complexity:** Proportional to the number of octree nodes. Adaptive octrees use less memory than uniform grids for sparse or smooth scenes.
- **Measured Performance:** Not given in the sources.
- **Strengths:** Efficiently captures complex surfaces with high curvature while minimizing storage for flat regions. The flatness criterion provides a geometrically meaningful refinement metric.
- **Limitations:** The flatness calculation (mean curvature/area) is computationally expensive and difficult to implement accurately. The provided implementation [S2, unofficial] omits this, potentially leading to over-refinement or under-refinement in flat areas. Requires post-processing to ensure depth disparity constraints for crack-free rendering.
- **When to use:** Suitable for scenes with varying surface complexity where uniform grids are too memory-intensive.
- **When not to use:** When real-time performance is critical and the flatness calculation cannot be optimized, or when the surface is uniformly complex.

## Background
The method originates from research on unconstrained isosurface extraction on arbitrary octrees [S1, unofficial]. It was developed to address the limitations of uniform grid-based isosurfacing methods like Marching Cubes, which waste resources on empty or flat regions. The flatness criterion was introduced to provide a more robust refinement strategy based on the geometric properties of the surface intersection. The implementation details in [S2, unofficial] demonstrate a practical application of adaptive octree generation for dual marching cubes, although it simplifies the flatness check.
