# Adaptive Octree Generation with Flatness Criterion

Also called: Adaptive Octree Generation

## Overview
This method generates an adaptive octree for isosurface extraction by recursively refining nodes based on the geometric flatness of the surface intersection, assigning vertex values via Euclidean distance transform sampling [S1, unofficial]. It differs from sibling methods like [IsoOctree](1744-isooctree.md) and [Wilhelms and Van Gelder Octree](2107-wilhelms-and-van-gelder-octree.md) by using a curvature-based flatness metric rather than simple field uniformity or depth constraints to determine refinement, allowing for coarser representation of planar surface regions [S1, unofficial].

## How it works
**Inputs:**
- Root node bounding box.
- Scalar field function $F(\mathbf{p})$ and threshold $T$.
- Base sampling size $S_{base}$.
- Dropoff $D$, HorizontalScale $H_s$, VerticalScale $V_s$ (used in field evaluation) [S2, unofficial].

**Outputs:**
- An adaptive octree where leaf nodes contain surface intersections.
- Vertex values assigned via Euclidean distance transform sampling [S1, unofficial].

**Data Structures:**
- `OctreeNode`:
  - `Bounds`: Axis-aligned bounding box (min, max vectors).
  - `Depth`: Integer depth level (root is 0).
  - `Children`: Array of 8 child nodes (null if leaf).
  - Children are ordered in fixed binary index order:
    0) $(-X, -Y, -Z)$, 1) $(+X, -Y, -Z)$, 2) $(-X, +Y, -Z)$, 3) $(+X, +Y, -Z)$, 4) $(-X, -Y, +Z)$, 5) $(+X, -Y, +Z)$, 6) $(-X, +Y, +Z)$, 7) $(+X, +Y, +Z)$ [S2, unofficial].

**Flatness Metric:**
The flatness of a surface intersection is defined as the ratio of the length of the mean curvature vector to the area of the intersection [S1, unofficial]:
$$ \text{flatness} = \frac{\|\vec{H}\|}{\text{Area}} $$
where $\vec{H}$ is the mean curvature vector and Area is the surface area [S1, unofficial]. Nodes are refined if they intersect the surface and the intersection is not "too flat" [S1, unofficial]. The specific threshold for "too flat" is not given in the sources [S1, unofficial].

**Vertex Value Assignment:**
Vertex values are assigned by sampling the Euclidean distance transform [S1, unofficial]. The exact implementation of this sampling is not detailed in the provided sources [S1, unofficial].

**Algorithm Steps:**
1. Start with the root node.
2. For each node, calculate the sampling interval:
   $$ S = S_{base} \cdot \ln(\text{Depth} + 2) $$
   [S2, unofficial]
3. Calculate the number of samples per axis:
   $$ n_x = 1 + \lceil \frac{\text{size}_x}{S} \rceil, \quad n_y = 1 + \lceil \frac{\text{size}_y}{S} \rceil, \quad n_z = 1 + \lceil \frac{\text{size}_z}{S} \rceil $$
   [S2, unofficial]
4. If $n_x < 3$ or $n_y < 3$ or $n_z < 3$, do not split the node [S2, unofficial].
5. Iterate over interior sample points only:
   - $z$ from $1$ to $n_z - 2$
   - $y$ from $1$ to $n_y - 2$
   - $x$ from $1$ to $n_x - 2$
   [S2, unofficial]
6. Compute sample position using linear interpolation:
   $$ x_f = \text{Lerp}(\text{min}_x, \text{max}_x, \frac{x}{n_x}) $$
   $$ y_f = \text{Lerp}(\text{min}_y, \text{max}_y, \frac{y}{n_y}) $$
   $$ z_f = \text{Lerp}(\text{min}_z, \text{max}_z, \frac{z}{n_z}) $$
   [S2, unofficial]
7. Evaluate the field at $(x_f, y_f, z_f)$. Track if any sample is below threshold ($isBelow$) and any is above threshold ($isAbove$) [S2, unofficial].
8. If both $isBelow$ and $isAbove$ are true, split the node into 8 children [S2, unofficial].
   - Child bounds:
     $$ \text{newSize} = \text{size} \cdot 0.5 $$
     $$ \text{halfNewSize} = \text{newSize} \cdot 0.5 $$
     $$ \text{childMin} = \text{nodeMin} + \text{halfNewSize} $$
     $$ \text{childMax} = \text{nodeMax} - \text{halfNewSize} $$
   - Create children in fixed order using min/max offsets [S2, unofficial].
9. Recursively apply steps 2-8 to children.

**Pseudocode:**
```python
def generate_octree(root_bounds, depth, sampling_size_base, threshold, dropoff, h_scale, v_scale):
    """
    Recursively generates an adaptive octree based on flatness criterion.
    Note: The flatness calculation itself is not implemented as the source 
    does not provide the algorithm for computing mean curvature vector H or Area.
    This implementation follows the sampling and splitting logic from [S2, unofficial].
    """
    node = OctreeNode(bounds=root_bounds, depth=depth)
    
    # Calculate sampling interval
    sampling_size = sampling_size_base * math.log(depth + 2)
    
    # Calculate number of samples
    n_samples = count_samples(node.bounds, sampling_size)
    
    # Check minimum sample requirement
    if n_samples.x < 3 or n_samples.y < 3 or n_samples.z < 3:
        return node
    
    # Sample interior points
    is_below = False
    is_above = False
    
    for z in range(1, n_samples.z - 1):
        for y in range(1, n_samples.y - 1):
            for x in range(1, n_samples.x - 1):
                # Linear interpolation
                x_f = lerp(node.bounds.min.x, node.bounds.max.x, x / n_samples.x)
                y_f = lerp(node.bounds.min.y, node.bounds.max.y, y / n_samples.y)
                z_f = lerp(node.bounds.min.z, node.bounds.max.z, z / n_samples.z)
                
                # Evaluate field
                val = sample_field(Vector3(x_f, y_f, z_f), threshold, dropoff, h_scale, v_scale)
                
                if val > threshold:
                    is_above = True
                else:
                    is_below = True
                
                # Early exit if both states found
                if is_below and is_above:
                    break
            if is_below and is_above:
                break
        if is_below and is_above:
            break
    
    # Split if surface intersects
    if is_below and is_above:
        new_size = node.bounds.size * 0.5
        half_new_size = new_size * 0.5
        node_min = node.bounds.min
        node_max = node.bounds.max
        
        node.children = []
        for i in range(8):
            # Determine child min/max based on binary index
            # 0: -X -Y -Z, 1: +X -Y -Z, 2: -X +Y -Z, 3: +X +Y -Z
            # 4: -X -Y +Z, 5: +X -Y +Z, 6: -X +Y +Z, 7: +X +Y +Z
            cx_min = node_min.x if (i & 1) == 0 else node_min.x + new_size.x
            cx_max = node_min.x + new_size.x if (i & 1) == 0 else node_max.x
            cy_min = node_min.y if (i & 2) == 0 else node_min.y + new_size.y
            cy_max = node_min.y + new_size.y if (i & 2) == 0 else node_max.y
            cz_min = node_min.z if (i & 4) == 0 else node_min.z + new_size.z
            cz_max = node_min.z + new_size.z if (i & 4) == 0 else node_max.z
            
            child_bounds = Bounds(Vector3(cx_min, cy_min, cz_min), Vector3(cx_max, cy_max, cz_max))
            child_node = generate_octree(child_bounds, depth + 1, sampling_size_base, threshold, dropoff, h_scale, v_scale)
            node.children.append(child_node)
    else:
        node.children = None
        
    return node
```

**Parameters:**
- `SamplingSize`: Base physical spacing between samples. Default: 1.0f [S2, unofficial].
- `Threshold`: Field value threshold for surface extraction. Default: 0.5f [S2, unofficial].
- `Dropoff`: Controls vertical falloff of the field. Default: 100.0f [S2, unofficial].
- `HorizontalScale`, `VerticalScale`: Scale factors for field sampling coordinates. Default: 0.01f, 0.05f [S2, unofficial].

**Edge Cases and Pitfalls:**
- The flatness metric requires computing the mean curvature vector and area, which is not detailed in the sources [S1, unofficial]. Implementers must define how to approximate these from the sampled field or mesh [G].
- The sampling interval formula uses `Mathf.Log(node.Depth + 2)`, which grows slowly with depth, potentially leading to insufficient sampling in deep nodes if `SamplingSize` is not adjusted [S2, unofficial].
- The child ordering is fixed and specific to the implementation in [S2, unofficial]; deviations may cause cracks if not consistent with downstream rendering [S2, unofficial].

## Subtopics

### [OcMesher](4141-ocmesher.md)
OcMesher is a method for extracting memory-efficient, highly detailed triangle meshes from unbounded scenes represented by Signed Distance Functions (SDFs). It uses a view-dependent adaptive octree structure driven by a given set of camera views to refine geometry only where visible. Unlike parent methods that generate octrees based on surface flatness alone, OcMesher incorporates camera projection metrics to prioritize resolution based on projected pixel density.

### [Octree Leaf Construction with QEF Surface Fitting](4268-octree-leaf-construction-with-qef-surface-fitting.md)
This method constructs an octree leaf node representing a voxel containing an isosurface by solving a Quadratic Error Function (QEF) to determine the precise surface position and normal from edge intersections. It differs from its parent, [Adaptive Octree Generation with Flatness Criterion](2482-adaptive-octree-generation-with-flatness-criterion.md), which assigns vertex values via Euclidean distance transform sampling, by using a least-squares geometric fit to refine the surface location within the leaf. It is distinct from [OcMesher](4141-ocmesher.md) by relying on a global QEF solver over all edge crossings rather than local marching cubes-style triangulation.

## Operating characteristics
- **Time Complexity:** Not given in the sources. Depends on the cost of flatness calculation and field sampling.
- **Memory Complexity:** Not given in the sources. Depends on the number of refined nodes.
- **Measured Performance:** Not given in the sources.
- **Strengths:** Allows for coarser representation of planar regions, potentially reducing mesh complexity compared to uniform refinement [S1, unofficial].
- **Limitations:** The flatness metric calculation is complex and not fully specified [S1, unofficial]. The method may produce cracks if depth disparity is not managed, as noted in the parent article [S1, unofficial].
- **When to use:** When surface flatness is a good indicator of refinement need and computational cost of curvature calculation is acceptable [S1, unofficial].
- **When not to use:** When real-time performance is critical and curvature calculation is too expensive, or when the field does not have a well-defined curvature [S1, unofficial].

## Background
The method was introduced in the context of mesh simplification, comparing octree refinement to dual marching cubes [S1, unofficial]. It was developed to ensure that the octree is restricted so that the depth-disparity between adjacent nodes is never greater than one, following the approach of Wilhelms and Van Gelder [S1, unofficial]. The flatness criterion was defined as the ratio of the mean curvature vector length to the area [S1, unofficial].
