# View-Dependent Isosurface Extraction

Also called: View-Dependent Algorithm

## Overview
View-Dependent Isosurface Extraction is a method that extracts and renders only the visible portions of an isosurface from large volumetric datasets, reducing polygon count and rendering time by exploiting depth complexity and occlusion [S2, book]. It differs from view-independent methods by performing coarse software visibility tests during octree traversal to prune hidden cells before forwarding triangulations to the graphics accelerator [S2, book].

## How it works
The method augments the Wilhelms and Van Gelder octree traversal with a front-to-back order and software-based visibility culling [S2, book].

**Inputs and Outputs:**
*   **Input:** An octree representing the scalar field (built using Wilhelms and Van Gelder's method), a viewpoint, and an isovalue [S2, book].
*   **Output:** A set of triangles (or meta-cells) marked as visible, forwarded to the graphics accelerator for final rasterization [S2, book].

**Data Structures:**
*   **Virtual Screen:** A bitmap with one bit per pixel. Used to create an occlusion mask. Bits are set when projected triangles cover them [S2, book].
*   **Hierarchical Tiles:** A coverage map is an $8 \times 8$ rectangular bitmap where each bit represents a pixel. Tiles are organized hierarchically into meta-tiles. Precomputed coverage patterns for edge crossings are combined to form convex polygon coverage maps [S2, book].

**Steps:**
1.  **Front-to-Back Traversal:** Traverse the octree in front-to-back order relative to the viewpoint. Prune empty subtrees based on min-max values stored at octree nodes [S2, book].
2.  **Coarse Visibility Test:** For each [meta-]cell intersecting the isosurface:
    *   Project the [meta-]cell onto the virtual screen [S2, book].
    *   Check if any pixel in the projection is unset (visible) [S2, book].
    *   If any pixel is unset, the cell is visible. If all pixels are set (hidden), the cell and all its children are pruned [S2, book].
3.  **Forwarding:** Forward the triangulation of visible cells to the graphics accelerator. The hardware resolves final exact partial visibility [S2, book].

        self.height = height
        self.bits = [[0] * width for _ in range(height)]

def _recursive_tile_check(x_min, y_min, x_max, y_max, size, virtual_screen):
    if size == 1:
        return virtual_screen.is_pixel_visible(x_min, y_min)
    half = size // 2
    mid_x = (x_min + x_max) // 2
    mid_y = (y_min + y_max) // 2
    # Check only subtiles that intersect the projected bounds
    if x_max <= mid_x: return _recursive_tile_check(x_min, y_min, mid_x, y_max, half, virtual_screen)
    if x_min > mid_x: return _recursive_tile_check(mid_x + 1, y_min, x_max, y_max, half, virtual_screen)
    if y_max <= mid_y: return _recursive_tile_check(x_min, y_min, x_max, mid_y, half, virtual_screen)
    if y_min > mid_y: return _recursive_tile_check(x_min, mid_y + 1, x_max, y_max, half, virtual_screen)
    # Intersects multiple subtiles
    return (_recursive_tile_check(x_min, y_min, mid_x, mid_y, half, virtual_screen) or
            _recursive_tile_check(mid_x + 1, y_min, x_max, mid_y, half, virtual_screen) or
            _recursive_tile_check(x_min, mid_y + 1, mid_x, y_max, half, virtual_screen) or
            _recursive_tile_check(mid_x + 1, mid_y + 1, x_max, y_max, half, virtual_screen))

def view_dependent_extraction(octree, viewpoint, isovalue, screen_width, screen_height):
    virtual_screen = VirtualScreen(screen_width, screen_height)
    visible_triangles = []

    # Step 1: Front-to-back traversal
    for node in octree.traverse_front_to_back(viewpoint):
        # Prune empty subtrees based on min-max values
        if not (node.min_value <= isovalue <= node.max_value):
            continue

        # Step 2: Coarse visibility test using hierarchical tiles
        projected_bounds = project_onto_screen(node, viewpoint, screen_width, screen_height)
        if check_hierarchical_visibility(projected_bounds, virtual_screen):
            # Cell is visible
            triangles = extract_triangles(node, isovalue)
            visible_triangles.extend(triangles)

            # Update occlusion mask
            for tri in triangles:
                for tile in tiles_intersecting(tri, screen_width, screen_height):
                    coverage = compute_coverage_map(tri, tile)
                    for dy in range(tile.size):
                        for dx in range(tile.size):
                            if coverage[dy][dx]:
                                virtual_screen.set_pixel(tile.x * tile.size + dx, tile.y * tile.size + dy)
            # If all pixels are set, the cell and all children are pruned

    # Step 3: Forward triangulation to graphics accelerator
    return visible_triangles

**Parameters:**
*   **Isovalue:** The scalar value defining the isosurface. Typical values depend on the dataset (e.g., 85 for bonsai tree CT scan [S1], 1.596 for argon bubble density [S1]).
*   **Tile Size:** $8 \times 8$ pixels [S2, book].

**Edge Cases and Pitfalls:**
*   **Front-to-Back Order:** The algorithm requires strict front-to-back traversal to ensure that occlusion masks are correctly built before testing subsequent cells [S2, book].
*   **Internal Sections:** Internal sections of the isosurface (common in medical datasets) are occluded by external sections and can be pruned [S2, book].

## Operating characteristics
*   **Time Complexity:** Extraction time is linear in the number of tetrahedra traversed, with negligible overhead [S1]. Visibility tests add cost but prune hidden cells, reducing total work [S2, book].
*   **Memory Complexity:** Depends on octree size and virtual screen size. Virtual screen is $W \times H$ bits. Hierarchical tiles enable fast classification and logarithmic search for visibility determination [S2, book].
*   **Measured Performance:** For a CT scan of a bonsai tree ($256^3$), the data-dependent error metric $E_s$ reduced extraction time to about 54% compared to mean-square error $E_{MS}$ [S1].
*   **Strengths:** Reduces polygon count and rendering time by culling hidden geometry. Balances work between software and hardware [S2, book].
*   **Limitations:** Requires front-to-back traversal. Visibility tests add overhead for visible cells [S2, book].
*   **When to Use:** Large datasets with significant occlusion [S2, book].
*   **When Not to Use:** Not given in the sources.

## Background
Originated from work on fast isosurface extraction methods for large image data sets, building on Wilhelms and Van Gelder's octree approach [S2, book]. The method was developed to address the computational cost of rendering large volumetric datasets interactively by extracting only potentially visible boundary voxels [S1][S2, book].
