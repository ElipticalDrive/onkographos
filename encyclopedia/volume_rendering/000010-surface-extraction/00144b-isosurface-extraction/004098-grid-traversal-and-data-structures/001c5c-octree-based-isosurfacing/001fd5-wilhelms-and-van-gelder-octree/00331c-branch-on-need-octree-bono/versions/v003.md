# Branch-on-Need Octree (BONO)
Also called: Branch-On-Need Octree (BONO) for time-variant data, Incomplete pointer octree, branch-on-need strategy
## Overview
The Branch-on-Need Octree (BONO) is a space-efficient geometric decomposition technique for isosurface extraction that partitions volume data based on geometric positions to prune branches during traversal [S1][S3, unofficial]. It builds on the Wilhelms and Van Gelder Octree by using non-uniform subdivision to minimize empty subtrees and the ratio of nodes to data points, thereby reducing memory requirements compared to even-subdivision schemes [S1][S3, unofficial]. Unlike span space methods that index individual cells, BONO indexes groups of eight cells simultaneously, offering a trade-off between memory footprint and traversal complexity [S1].
## How it works
**Inputs and Outputs:**
- Input: A 3D scalar volume grid $V$ of dimensions $D_x \times D_y \times D_z$.
- Output: A hierarchical octree data structure where leaf nodes reference cell groups, enabling isosurface extraction.

**Data Structures:**
The BONO is an incomplete pointer octree. Each internal node stores:
- `min_value`: The minimum scalar value among all cells in its subtree.
- `max_value`: The maximum scalar value among all cells in its subtree.
- `children`: An array of 8 pointers to child nodes (or null if the node is a leaf or empty).

Leaf nodes reference a group of up to eight cells (fewer along volume boundaries). One pair of extreme values (`min_value`, `max_value`) covers these eight cells, reducing memory overhead compared to storing values for each cell individually [S1].

**Construction Algorithm:**
1. **Partitioning:** Subdivide the volume non-uniformly. In each direction, the "lower" subdivision covers the largest possible power of two cells. This strategy ensures that when volume dimensions are not powers of two, fewer nodes are created compared to even-subdivision schemes [S1][S3, unofficial].
2. **Recursion:** Recursively apply partitioning to sub-volumes until a base case is reached (e.g., a single cell group or a predefined minimum size).
3. **Value Propagation:** During construction, propagate extreme values up the tree. For any node, `min_value` is the minimum of its children's `min_value`s, and `max_value` is the maximum of its children's `max_value`s. Leaf nodes compute these values directly from the cells they reference [S1].

**Extraction Algorithm:**
1. **Traversal:** Start at the root. For each node, check if `min_value < isovalue < max_value`.
2. **Pruning:** If the condition is not met, prune the branch (the isosurface does not pass through this region).
3. **Leaf Processing:** If the condition is met and the node is a leaf, extract the isosurface from the referenced cells (e.g., using Marching Cubes) [S1].
4. **Recursion:** If the condition is met and the node is internal, recurse into its children [S1].

**Optimization (Spatial Coherence):**
- Optionally, use a hash table of edges. After interpolating a point along an edge, cells sharing that edge access the hash entry to avoid recomputing the interpolation [S1].

**Edge Cases and Pitfalls:**
- Non-power-of-two dimensions: The branch-on-need strategy produces fewer nodes than even-subdivision schemes, making traversal more efficient [S1].
- Non-uniform subdivision: Prevents the use of pure coordinate systems (like Frisken and Perry's) for direct hashing [S3, unofficial].
- Multiple parents: May require multiple parent nodes at deeper regions compared to traditional octrees, potentially causing added traversal steps [S3, unofficial].
- Indexing: BONO indexes eight cells simultaneously, unlike span space methods which index individual cells [S1].

## Operating characteristics
- **Time Complexity:** Extraction time depends on the number of nodes visited. BONO prunes branches where the isovalue is outside the [min, max] range. On Head128 ($128^3$ CT scan), average execution time is 0.58 (units not specified, likely seconds or relative time) [S1]. On Rage256 ($256^3$ CFD), it shows best performance among listed geometric decomposition techniques [S1].
- **Memory Complexity:** Space-efficient due to non-uniform subdivision and grouping of eight cells per leaf node. The ratio of nodes to data points is minimized [S3, unofficial]. However, it may require more memory than pointerless span space methods if not implemented carefully, as it still uses pointers [S1].
- **Strengths:** Reduced memory footprint compared to full octrees; efficient pruning for sparse isosurfaces; fewer nodes for non-power-of-two dimensions [S1][S3, unofficial].
- **Limitations:** Non-uniform subdivision complicates hashing and coordinate-based access; potentially more traversal steps due to multiple parent nodes in deep regions [S3, unofficial].
- **When to use:** When memory is constrained and the volume dimensions are not powers of two; when fast out-of-core rendering of time-variant data is needed (via extensions) [S2, unofficial].
- **When not to use:** When uniform grid access is required for other algorithms; when the overhead of managing non-uniform nodes outweighs the memory savings.
## Background
The Branch-on-Need Octree was proposed by Wilhelms and Van Gelder in 1992 [S3, unofficial]. It was introduced as a space-efficient variation on the traditional octree for isosurface extraction [S1]. The method was later expanded by Sutton and Hansen to time-variant data to enable fast out-of-core rendering [S2, unofficial]. It is a geometric decomposition technique, contrasting with span space algorithms like NOISE and ISSUE [S1].
