# Temporal Hierarchical Index Tree (THITree)
Also called: THITree

## Overview
The Temporal Hierarchical Index Tree (THITree) is a data structure designed for fast isosurface extraction from time-dependent volumetric data sets. It solves the problem that extracting and rendering isosurfaces separately for each time step is too slow for interactive exploration of large time-varying data. It sets itself apart from its parent [Branch-on-Need Octree (BONO)](6935-branch-on-need-octree-bono.md) and its temporal sibling Temporal Branch-on-Need Tree (TBON) by exploiting temporal coherence: cells that remain constant over a time interval are stored only once for that entire span, achieving significant data reduction and faster retrieval. Unlike the Temporal Spanning Tree (TSP Tree), which incurs huge storage overhead by storing a full binary time tree per spatial node, THITree uses a shared Binary Time Tree with Span Space and Interval Trees for efficient interval search.

## How it works
The THITree consists of three elements: a Binary Time Tree representing time, a Span Space data structure for efficient interval search, and an Interval Tree for diagonal elements.

### Data Structures

**1. Binary Time Tree**
A binary tree where nodes represent time spans.
*   **Root:** Represents the entire range of time steps $[0, T-1]$.
*   **Internal Nodes:** Represent a sub-interval of time steps.
*   **Leaves:** Represent single time steps at the highest temporal resolution.
*   **Structure:** Temporal resolution doubles with each level. A node at depth $i$ (root is depth 0) covers a time span of size $2^{D-i}$, where $D$ is the maximum depth.

**2. Span Space**
A 2D grid used to store cells as points $(min, max)$ and classify their temporal variation.
*   **Lattice Construction:**
    1.  Collect all distinct extreme values (min/max) of all cells across all time steps.
    2.  Sort these values into a list.
    3.  Find $L+1$ scalar values that divide the list into $L$ equal-length sublists.
    4.  These $L+1$ values form the boundaries of the Span Space grid, creating $L \times L$ lattice elements.
*   **Cell Representation:**
    *   In leaf nodes (single time step), a cell is represented by its actual $(min, max)$ for that step.
    *   In internal nodes (time span), a cell changing over multiple steps is represented by a single point corresponding to its temporal extreme values over that span: $(\min_{t \in span}(min_t), \max_{t \in span}(max_t))$.
*   **Storage per Node:**
    *   For each row $j$ of the Span Space (where row index corresponds to the discretized minimum value):
        *   List $A_j$: Points sorted by minimum value in ascending order.
        *   List $D_j$: Points sorted by maximum value in descending order.
    *   These lists exclude points falling on the diagonal element ($min\_bin = max\_bin$).

**3. Interval Tree**
*   Stores points from the diagonal lattice elements of the Span Space (where the discretized minimum bin equals the discretized maximum bin).
*   Used for min-max searches required when the isovalue falls within the diagonal band.

### Parameters
*   **$L$**: The number of subdivisions in the Span Space grid. Smaller grid elements (larger $L$) result in fewer false positives but larger memory usage.
*   **MaxVariation**: The maximum number of grid elements a cell may occupy in Span Space while still being classified as "constant" for a time interval. If a cell's points over a time span occupy $\le$ MaxVariation grid elements, it is stored once in the parent node rather than in its children. Increasing this parameter increases false positives but reduces memory size.

### Preprocessing (Construction)
1.  **Classify Cells:** For each cell, determine its temporal variation over the entire time range using the Span Space lattice.
2.  **Determine Tree Location:**
    *   Calculate the number of grid elements occupied by the cell's points in Span Space for various time intervals.
    *   If the variation is low (occupies $\le$ MaxVariation elements) for a specific time interval, the cell is stored in the node representing that interval.
    *   Cells with low temporal variation over long spans are placed high in the tree.
    *   Cells with high variation are pushed down to leaf nodes.
3.  **Store Cells:**
    *   For each node in the Binary Time Tree, create a Span Space.
    *   Insert each cell assigned to that node into the Span Space as a point $(min, max)$.
    *   Sort points into lists $A_j$ and $D_j$ for each row.
    *   Insert diagonal points into the Interval Tree.

### Query (Retrieval)
To retrieve isosurface cells for a specific time step $t$ and isovalue $V$:

1.  **Determine Lattice Element:** Identify the Span Space lattice element (row $r$, column $c$) that contains the isovalue $V$. Since all nodes share the same lattice subdivision, this is computed once.
2.  **Traverse Tree:** Traverse the Binary Time Tree from root to the leaf node representing time step $t$.
3.  **Search Span Space:** For each node $N$ visited:
    *   Search the Span Space of $N$ for cells intersecting $V$.
    *   **Non-Diagonal Search:**
        *   Search rows $j < r$ in list $A_j$ (ascending min) for intervals where $min \le V$.
        *   Search rows $j > r$ in list $D_j$ (descending max) for intervals where $max \ge V$.
        *   Search row $r$ in both $A_r$ and $D_r$ appropriately.
    *   **Diagonal Search:**
        *   Query the Interval Tree for intervals containing $V$.
4.  **Collect Results:** Append all cells found in each node to a result vector.
5.  **Completion:** The process is complete when the leaf node is reached. All cells intersecting the isosurface at time $t$ are collected.

**Note on False Positives:** Cells found in internal nodes are represented by temporal extremes over a span. If the isovalue $V$ lies between the span's min and max, the cell is returned. However, at the specific time step $t$, the cell's actual values might not span $V$. These are false positives.

### Incremental Search
An optimization for searching consecutive time steps $t_{old}$ and $t_{new}$.
*   **State:** Maintain a result vector $R$ and an integer vector $V[d]$ storing the cumulative number of cells found at each depth $d$ of the tree during the previous search.
*   **Algorithm:**
    1.  Traverse the tree from root to leaf for $t_{new}$.
    2.  At each node $N_i$ at depth $i$:
        *   Check if both $t_{old}$ and $t_{new}$ are within $N_i$'s time span.
        *   If yes: Reuse the first $V[i]$ cells from $R$ (skip search in this node).
        *   If no: Truncate $R$ to $V[i-1]$ cells (common cells). Perform a full search in $N_i$ for $t_{new}$ and append new cells to $R$. Update $V[i]$ with the new cumulative count.
*   **Overhead:** Only requires storing vector $V$ of size $d$ (tree depth).

    Searches a list sorted by min ascending.

    """
    candidates = []
    for cell in sorted_list:
        if cell.min > isovalue:
            break
        if cell.max >= isovalue:
            candidates.append(cell)

def search_list_descending(sorted_list, isovalue):
    """
    Searches a list sorted by max descending.
    Returns cells where max >= isovalue AND min <= isovalue.
    """
    candidates = []
    for cell in sorted_list:
        if cell.max < isovalue:
            break
        if cell.min <= isovalue:
            candidates.append(cell)
    return candidates

## Subtopics

### Incremental Search
An optimization for searching consecutive time steps in the THITree by reusing results from previous searches. It leverages the binary tree structure where parent nodes cover time spans of child nodes. It uses a result vector storing found cells and an integer vector $V[d]$ storing the cumulative number of cells found so far at each depth $d$. If the previous and current time steps fall within the same node's time span, the cells found in that node are reused. If they diverge, the result vector is truncated to the common cells, and the rest of the tree is searched normally. This offers a performance gain of a factor of 3 when searching 50 consecutive time steps compared to 50 full searches, with negligible space overhead (at most $d$ integers).

## Operating characteristics
*   **Time Complexity:** Query time depends on the number of cells intersecting the isosurface and the tree depth. Incremental search reduces this significantly for consecutive time steps.
*   **Memory Complexity:** Depends on $L$ and MaxVariation. Smaller grid elements (larger $L$) and lower MaxVariation increase memory usage but reduce false positives.
*   **Performance:** False positive rates range from ~0.1% (largest tree size, small MaxVariation) to 5% (smallest tree size, large MaxVariation). Default settings yield approximately 0.5% false positives.
*   **Strengths:** Fast retrieval for time-dependent data; data reduction through temporal coherence; efficient incremental search.
*   **Limitations:** False positives require post-processing or filtering; parameter tuning ($L$, MaxVariation) affects accuracy vs. memory trade-off.

## Background
The THITree was introduced by Shen [S1] as a data structure for isosurface extraction from time-varying fields. It builds on the idea of storing voxels that remain constant throughout a time span only once. It was extended and implemented by the authors of [S1] for fast time-dependent isosurface extraction and rendering, contrasting with TBON (which lacks temporal coherence) and TSP Tree (which has high storage overhead).
