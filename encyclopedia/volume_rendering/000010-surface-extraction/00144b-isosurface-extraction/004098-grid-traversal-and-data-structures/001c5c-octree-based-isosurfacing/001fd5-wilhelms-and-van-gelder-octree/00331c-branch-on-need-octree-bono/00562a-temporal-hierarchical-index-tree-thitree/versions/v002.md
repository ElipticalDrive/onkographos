# Temporal Hierarchical Index Tree (THITree)

Also called: THIT, THITree, Time Tree

## Overview
The Temporal Hierarchical Index Tree (THITree) is a data structure for fast isosurface extraction from time-dependent volumetric data sets [S1][S2, unofficial]. It solves the problem that extracting and rendering isosurfaces separately for each time step is too slow for interactive exploration of large time-varying data [S1]. It sets itself apart from its parent [Branch-on-Need Octree (BONO)](6935-branch-on-need-octree-bono.md) and the Temporal Branch-on-Need Tree (TBON) by explicitly exploiting temporal coherence: cells that remain constant (or nearly constant) over a time span are stored only once in a higher-level node, achieving significant data reduction [S1][S2, unofficial]. Unlike the Temporal Spanning Tree (TSP Tree), which incurs huge storage overhead by storing a full binary tree per octree node, THITree uses a Span Space and Interval Trees for efficient interval search [S1].

## How it works
The THITree consists of three core elements: a Binary Time Tree representing time, a Span Space data structure for efficient interval search, and an Interval Tree for diagonal elements [S1][S2, unofficial].

### Data Structures

**1. Binary Time Tree**
A binary tree where nodes represent time spans. The root represents the entire time range $[0, T-1]$. Leaf nodes represent single time steps. The tree is constructed recursively by dividing time intervals in half. Temporal resolution doubles with each level [S1][S2, unofficial].

**2. Span Space**
A 2D space where each cell is represented as a point $(min, max)$, where $min$ and $max$ are the extreme scalar values of the cell [S1][S2, unofficial].
*   **Lattice Subdivision:** The Span Space is divided into an $L \times L$ grid of non-uniformly spaced rectangles called lattice elements [S2, unofficial].
    *   Collect all distinct extreme values (min/max) of all cells from all time steps into a sorted list.
    *   Find $L+1$ scalar values $\{d_0, d_1, ..., d_L\}$ that evenly separate the list into $L$ sublists of equal length [S2, unofficial].
    *   Use these values to draw $L+1$ vertical and $L+1$ horizontal lines, forming the lattice [S2, unofficial].
*   **Cell Representation:**
    *   In non-leaf nodes (representing time spans $[i, j]$), a cell is represented by a single point $(min_i^j, max_i^j)$, where $min_i^j$ and $max_i^j$ are the temporal extremes over the span [S1][S2, unofficial].
    *   In leaf nodes (representing single time step $t$), a cell is represented by $(min_t, max_t)$ [S2, unofficial].

**3. Search Index (per Node)**
For each node in the Binary Time Tree, a search index is built using the Span Space lattice [S2, unofficial].
*   **Off-Diagonal Elements:** For lattice elements not on the diagonal ($x \neq y$), cells in each row are stored in two sorted lists:
    1.  Sorted by representative minimum values in ascending order.
    2.  Sorted by representative maximum values in descending order [S1][S2, unofficial].
*   **Diagonal Elements:** For lattice elements on the diagonal ($x = y$), an Interval Tree is created for each element to store cell intervals [S1][S2, unofficial].

### Construction Algorithm

1.  **Classify Cells:** For each cell, determine its temporal variation. Plot points in Span Space for each time step. If all points for a cell within a time interval $[i, j]$ occupy an area of at most $MaxVariation \times MaxVariation$ lattice elements (typically $2 \times 2$), the cell is classified as having low temporal variation [S1][S2, unofficial].
2.  **Build Tree Recursively:**
    *   Start with root node $N_0^{T-1}$.
    *   For a node representing interval $[i, j]$:
        *   Identify cells with low temporal variation (occupying $\le MaxVariation^2$ lattice elements). Store these cells in the current node's Span Space index. These cells are *not* stored in any descendant nodes [S1][S2, unofficial].
        *   For cells that do not satisfy the low variation criterion, split the interval $[i, j]$ into two halves: $[i, i + \lfloor(j - i + 1)/2\rfloor - 1]$ and $[i + \lceil(j - i + 1)/2\rceil, j]$ [S2, unofficial].
        *   Recursively classify cells into the left and right child subtrees [S2, unofficial].
    *   Leaf nodes $N_t^t$ contain cells with the highest scalar variations, represented by time-specific extremes [S2, unofficial].
3.  **Build Search Index:** For each node, construct the Span Space lattice and populate the two sorted lists (min-ascending, max-descending) and Interval Trees for diagonal elements [S1][S2, unofficial].

### Query Algorithm

To extract the isosurface for isovalue $V_{iso}$ at time step $t$:

1.  **Traverse Tree:** Recursively traverse from the root $N_i^j$ to the leaf $N_t^t$. At each node $N_a^b$, if $a \le t \le b$, traverse to the appropriate child. Perform isosurface cell search at *every* node along this path [S1][S2, unofficial].
2.  **Search Span Space at Node:**
    *   Locate the lattice element $[l, l]$ containing the point $(V_{iso}, V_{iso})$ in the Span Space [S2, unofficial].
    *   Candidate cells are in the "upper-left" region defined by $x \le V_{iso}$ and $y \ge V_{iso}$ [S2, unofficial].
    *   Collect candidates from three categories:
        1.  **Rows $R$ where $l < R \le L-1$:** In the list sorted by minimum values (ascending), collect cells from the start until the first cell has $min > V_{iso}$ [S2, unofficial].
        2.  **Row $l$:** In the list sorted by maximum values (descending), collect cells from the start until the first cell has $max < V_{iso}$ [S2, unofficial].
        3.  **Diagonal Element $[l, l]$:** Collect cells from the Interval Tree for this element [S2, unofficial].
3.  **Triangulation:** Use the actual scalar data at time step $t$ for the collected candidate cells to perform triangulation [S2, unofficial].
    *   **Filtering:** Cells found in non-leaf nodes are represented by temporal extremes $(min_i^j, max_i^j)$. These may be false positives if $min_i^j \le V_{iso} \le max_i^j$ but the actual values at time $t$ do not span $V_{iso}$ [S1][S2, unofficial]. The triangulation step detects this and creates no triangles for such cells [S2, unofficial].

### Incremental Search Optimization
For searching consecutive time steps, results from previous searches can be reused [S1].
1.  Maintain a result vector of found cells and an integer vector $V[d]$ storing the cumulative number of cells found at each depth $d$ of the tree [S1].
2.  When searching for time step $t_n$ given previous result for $t_o$:
    *   Traverse from root to leaf for $t_n$.
    *   At node $N_i$ at depth $i$, if both $t_n$ and $t_o$ are in $N_i$'s time span, reuse the first $V[i]$ cells from the result vector (skip search) [S1].
    *   If not, truncate the result vector after $V[i-1]$ cells (the common cells) and search the rest of the tree normally, updating $V$ and the result vector [S1].

### Parameters
*   **$L$:** The resolution of the lattice subdivision ($L \times L$). Controls the trade-off between storage space and extraction time. Higher $L$ reduces false positives but increases index size [S2, unofficial].
*   **$MaxVariation$:** The maximum allowed variation of a "constant" cell, defined as the number of grid elements a cell may occupy in Span Space while still being classified as constant (e.g., $2 \times 2$). Increasing this parameter increases false positives but reduces memory size [S1].

### Edge Cases and Pitfalls
*   **False Positives:** Non-leaf nodes may yield cells that are not actual isosurface cells at time $t$ because their temporal extremes contain the isovalue but their time-specific extremes do not. This causes performance overhead but not incorrect geometry, as triangulation filters them out [S2, unofficial].
*   **Memory Management:** If the tree does not fit in memory, nodes are output to a file. A replacement policy based on node depth (smaller depth = higher priority) and Least Recently Used (LRU) is used to manage memory [S2, unofficial].

## Subtopics

### Incremental Search
An optimization for searching consecutive time steps in the THITree by reusing results from previous searches, leveraging the binary tree structure where parent nodes cover time spans of child nodes [S1]. It uses a result vector and an integer vector $V[d]$ (space overhead of $d$ integers) to skip searches for nodes whose time spans contain both the current and previous time steps [S1]. This offers a performance gain of a factor of 3 when searching 50 consecutive time steps compared to 50 full searches [S1].

## Operating characteristics
*   **Time Complexity:** The interval tree method for diagonal elements has optimal efficiency of $O(\log N)$, where $N$ is the number of cells [S2, unofficial]. Collection from categories 1 and 2 (sorted lists) requires no search, making it efficient [S2, unofficial].
*   **Memory Complexity:** Depends on $L$ and $MaxVariation$. Smaller grid elements (higher $L$) and lower $MaxVariation$ result in larger tree sizes but fewer false positives [S1].
*   **Performance:** False positive rates range from ~0.1% (largest tree size) to 5% (smallest tree size), with default settings yielding approximately 0.5% false positives [S1].
*   **Strengths:** Fast isosurface extraction for time-dependent data; data reduction via temporal coherence; supports incremental search [S1].
*   **Limitations:** Preprocessing time to build the tree; potential false positives requiring triangulation filtering; memory usage can be high for large $L$ [S1][S2, unofficial].
*   **When to use:** Interactive exploration of large time-dependent volumetric data sets where isovalue changes or time-step traversal is required [S1].
*   **When not to use:** Static data (use BONO or other spatial structures); data with no temporal coherence (TBON or standard methods may be simpler) [S1].

## Background
The THITree was introduced by Shen in 1998 [S1][S2, unofficial]. It was designed to address the slowness of extracting isosurfaces for each time step in time-varying data sets [S1]. It builds on the concept of Span Space [Livnat et al. 1996] and Interval Trees [Cignati et al. 1997] [S1]. It is distinct from the Temporal Branch-on-Need Tree (TBON) [Sutton and Hansen 1999], which does not use temporal coherence, and the TSP Tree, which has high storage overhead [S1].
