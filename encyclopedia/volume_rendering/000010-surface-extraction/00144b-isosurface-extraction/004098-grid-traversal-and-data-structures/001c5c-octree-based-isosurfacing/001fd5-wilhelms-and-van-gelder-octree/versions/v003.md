# Wilhelms and Van Gelder Octree

Also called: Wilhelms and Van Gelder method, Octree acceleration for cell extraction

## Overview
The Wilhelms and Van Gelder Octree is a hierarchical spatial subdivision method that accelerates isosurface extraction by pruning branches of an octree that cannot contain the target isosurface [S1, unofficial]. It differs from sibling methods like [Standard Interval Tree for Isosurface Extraction](1230-standard-interval-tree-for-isosurface-extraction.md) by using a strict rectilinear block hierarchy where each node stores the union of value intervals of its constituent cells, allowing for immediate rejection of empty regions during recursive traversal [S1, unofficial]. Unlike [Marching Cubes with Octree](1259-marching-cubes-with-octree.md), which may require specific adaptation to prevent cracks, this method focuses purely on accelerating the cell enumeration phase by ignoring inactive branches [S1, unofficial].

## How it works
**Inputs:**
- A 3D volume dataset defined on a rectilinear grid.
- An interpolation function $\hat{f}$ (typically trilinear) that maps spatial coordinates to scalar values.
- A target isovalue $t \in \mathbb{R}$.

**Outputs:**
- A list of active cells (voxels) intersected by the isosurface $\hat{f}(x,y,z) = t$.

**Data Structures:**
The volume is organized into an octree. Each node $n$ in the tree corresponds to a rectilinear block $B$ of cells $C_{i,j,k}$.
- **Interval Attribute:** Each node $n$ is attributed an interval $[n_{min}, n_{max})$.
- **Interval Definition:** This interval is the union of the value intervals of all cells belonging to the block $B$. Specifically, for a cell $C_{i,j,k}$, the value range is $[\hat{v}_{min}, \hat{v}_{max})$, where:
  $$ \hat{v}_{min} = \min_{V_{i,j,k}} f $$
  $$ \hat{v}_{max} = \max_{V_{i,j,k}} f $$
  The node's interval is:
  $$ [n_{min}, n_{max}) = \bigcup_{C_{i,j,k} \in B} [\hat{v}_{min}, \hat{v}_{max}) $$
  In practice, this is computed as:
  $$ n_{min} = \min_{C_{i,j,k} \in B} (\hat{v}_{min}) $$
  $$ n_{max} = \max_{C_{i,j,k} \in B} (\hat{v}_{max}) $$
  This interval denotes the range of values the interpolation function $\hat{f}$ attains in the portion of the volume corresponding to node $n$ [S1, unofficial].

**Algorithm Steps:**
1. **Tree Construction:** Build the octree over the volume data. For each node, compute $n_{min}$ and $n_{max}$ by aggregating the min/max values of its child nodes (for internal nodes) or its constituent cells (for leaf nodes).
2. **Recursive Traversal:** Start at the root node.
3. **Pruning Check:** For the current node $n$, check if the target isovalue $t$ lies within the node's interval $[n_{min}, n_{max})$.
   - If $t \notin [n_{min}, n_{max})$, the branch rooted at $n$ is ignored (pruned). No further processing of this subtree occurs.
   - If $t \in [n_{min}, n_{max})$, the node is investigated.
4. **Leaf Processing:** If the current node is a leaf node and $t \in [n_{min}, n_{max})$, investigate the cell(s) within this leaf node cell-by-cell using the standard enumeration algorithm (e.g., Marching Cubes) to extract the isosurface geometry.
5. **Internal Node Processing:** If the current node is internal and $t \in [n_{min}, n_{max})$, recursively apply steps 3-4 to all eight children.

**Pseudocode:**
```python
def wilhelms_van_gelder_extract(root_node, t):
    """
    Extract isosurface cells using Wilhelms and Van Gelder octree pruning.
    
    Args:
        root_node: The root of the octree.
        t: The target isovalue.
        
    Returns:
        List of active cells intersected by the isosurface.
    """
    active_cells = []
    traverse(root_node, t, active_cells)
    return active_cells

def traverse(node, t, active_cells):
    """
    Recursively traverse the octree, pruning branches where t is not in [nmin, nmax).
    """
    # Check pruning condition
    if not (node.nmin <= t < node.nmax):
        return

    # If leaf node, process cells individually
    if node.is_leaf():
        for cell in node.cells:
            # Standard enumeration algorithm (e.g., Marching Cubes)
            # Check if isosurface intersects this specific cell
            if isosurface_intersects_cell(cell, t):
                active_cells.append(cell)
    else:
        # Internal node: recurse into children
        for child in node.children:
            traverse(child, t, active_cells)
```

**Parameters:**
- $t$: Target isovalue. Typical values depend on the dataset (e.g., 0.5 for normalized data).
- Tree depth: Determined by the volume resolution and desired granularity. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** The interval check $t \in [n_{min}, n_{max})$ relies on floating-point comparisons. Precision errors near boundaries may cause incorrect pruning or unnecessary processing.
- **Degenerate Input:** If $n_{min} = n_{max}$, the interval is a single point. If $t$ equals this value, the cell is processed; otherwise, it is pruned.
- **Boundary Conditions:** The interval is defined as half-open $[n_{min}, n_{max})$. Consistency in interval definition across all nodes is critical to avoid missing cells at boundaries.

## Subtopics

### Octree Search Structure
A variant implementation detail where the octree is explicitly used as an external search structure to skip inactive cells [S2]. It reduces computational load by avoiding analysis of inactive regions but incurs construction overhead [S2]. Construction time and memory usage are significant costs. For single or dual surface extraction, the total time (construction + extraction) may be slower than exhaustive methods like WWMC [S2]. Reusing the same index for multiple surfaces can mitigate this cost [S2]. Parallel construction requires a global coordinator and may yield sublinear speedup due to I/O and communication overheads [S2].

## Operating characteristics
**Time Complexity:**
- **Construction:** $O(N)$, where $N$ is the number of cells, to build the octree and compute intervals [S1, unofficial].
- **Extraction:** Best case $O(1)$ if the isosurface is confined to a small region; worst case $O(N)$ if the isosurface permeates the entire volume. Average case depends on the sparsity of the isosurface. The method achieves linear time complexity relative to the number of *active* cells, but with a constant factor overhead for tree traversal [S1, unofficial].

**Memory Complexity:**
- Requires moderate additional CPU storage space for the octree structure and interval attributes [S1, unofficial]. The size of the octree is proportional to the number of nodes, which is typically $O(N)$ for a full octree but can be smaller for sparse data.

**Measured Performance:**
- In experiments, using the octree allowed skipping up to 99% of cells for sparse isosurfaces (e.g., XT-180), reducing extraction time to about one-third of WWMC [S2]. However, for dense isosurfaces (e.g., XT-25, where >50% of cells are active), performance was comparable to WWMC [S2].
- When considering total time (construction + extraction), the octree method was slower than WWMC for single surface extraction [S2]. For multiple surfaces, reusing the index improved performance but still lagged behind WWMC in some cases (169 sec vs 165.4 sec) [S2].

**Strengths and Limitations:**
- **Strengths:** Significant acceleration for sparse isosurfaces; simple recursive implementation; effective pruning of large inactive regions.
- **Limitations:** Construction overhead; memory usage; less effective for dense isosurfaces; parallelization is challenging due to global coordination needs [S2].

**When to Use:**
- Use when the isosurface is sparse and the volume is large, and multiple extractions with the same isosurface are planned.
- Avoid when the isosurface is dense or when single-extraction performance is critical and construction overhead is prohibitive.

## Background
The method was proposed by Wilhelms and Van Gelder [S1, unofficial]. It is based on the idea of using a hierarchical spatial subdivision to accelerate cell extraction by ignoring branches that cannot contain the isosurface [S1, unofficial]. The approach leverages the property that if the target isovalue $t$ is not within the range of values attained by a node's block, that block can be safely ignored. This method is a foundational technique in adaptive isosurface extraction and has influenced subsequent work on octree-based isosurfacing.
