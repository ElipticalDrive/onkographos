# Out-of-core Interval Tree Extraction

Also called: Chiang, Silva, and Schroeder method, External Interval Tree Indexing, I/O-optimal interval tree, Out-of-Core Interval Tree, Out-of-core stabbing query, Parallel Out-of-Core Isocontour Query Processing, Parallel isosurface extraction

## Overview
Out-of-core Interval Tree Extraction is a parallel, I/O-optimal method for isosurface extraction that stores the auxiliary interval tree index structure on disk to handle datasets larger than main memory [S1][S2, unofficial]. It solves the problem of memory bottlenecks in standard interval tree methods by partitioning the tree into disk blocks, allowing efficient stabbing queries (finding blocks intersecting a specific isovalue) with optimal I/O complexity [S1][S2, unofficial]. It distinguishes itself from [Standard Interval Tree for Isosurface Extraction](1230-standard-interval-tree-for-isosurface-extraction.md) by moving the index structure from RAM to disk [S1][S2, unofficial].

## How it works
The method operates in two phases: preprocessing (partitioning and index building) and query processing (isosurface extraction) [S1]. It assumes a parallel environment where data is distributed across multiple processors, each with local disk storage [S1].

### Inputs and Outputs
*   **Inputs:** A volume dataset $D$, an isovalue $t$, and an optional memory constraint $M$ for optimization [S1][S2, unofficial].
*   **Outputs:** A set of polygons representing the isosurface, or a stream of rendered images composited by a Metabuffer [S1].

### Data Structures
1.  **Data Block ($B$):** The atomic unit of data distribution [S1].
    *   **Fields:** `ID` (unique integer), `Origin` (3D coordinates), `Dimensions` (width, height, depth), `Span` ($[min\_val, max\_val]$ of function values), and `Vertex Values` [S1].
    *   **Layout:** Stored sequentially on disk starting at a disk block boundary [S1].
2.  **External Interval Tree:** Stored on disk [S1].
    *   **Partitioning:** The logical interval tree is partitioned into disk blocks. Each block stores a subtree of depth $K_1$ [S2, unofficial].
    *   **Node Labeling:** Nodes $\eta$ are labeled $\ell(\eta) \in \{0, \dots, K_1\}$ to define block boundaries [S2, unofficial]:
        $$
        \ell(\eta) := \begin{cases} 
        K_1 & \text{if } \eta \text{ is a leaf} \\
        \ell_0(\eta) & \text{if } \eta \text{ is not a leaf and not the root} \\
        0 & \text{if } \eta \text{ is the root}
        \end{cases}
        $$
        Where $\ell_0(\eta) := \min(\{K_1\} \cup \{\ell(\eta') - 1 \mid \eta' \in \{\eta_l, \eta_r\} \text{ exists and } \ell(\eta') > 0\})$ [S2, unofficial]. Nodes labeled 0 define the root of a subtree stored in a single disk block [S2, unofficial].
    *   **Intermediate File:** During build, an intermediate file maps each block's `ID` to its `Span` and location, used to construct the external tree [S1].
3.  **Min/Max Lists:** Associated with interval tree nodes, storing min/max values of children [S2, unofficial]. Stored in disk blocks of capacity $K_2$ entries [S2, unofficial].

### Parameters
*   $K_1$: Depth of binary subtree per disk block for interval tree nodes. Typical value: 3 (holding $2^{3+1}-1 = 15$ nodes per block) [S2, unofficial].
*   $K_2$: Maximum number of min- or max-list entries per disk block. Typical value: 85 [S2, unofficial].
*   $\alpha_6$: Time to read one disk block. Experimental value: 2287 (units unspecified) [S2, unofficial].
*   Block Size: 512 bytes (in experimental setup) [S2, unofficial].

### Steps

#### Phase 1: Preprocessing
1.  **Initial Partitioning:** Divide the volume data into slabs, assigning one slab to each processor [S1].
2.  **Block Division:** Divide each slab into blocks aligned with disk block boundaries. Store `ID`, `Origin`, `Dimensions`, `Span`, and vertex values in each block [S1].
3.  **Redistribution:** Each processor $p_i$ determines which blocks to send to other processors $p_j$ to balance workload [S1]. A deterministic or random method ensures approximately equal number of blocks and workload histogram across processors [S1]. Processors communicate block counts and actual blocks [S1].
4.  **Block Storage:** Each processor writes its assigned blocks to a local file, starting each block at a disk block boundary [S1]. Simultaneously, it writes an intermediate file containing the `ID` and `Span` of each block [S1].
5.  **External Tree Construction:** Build an external interval tree on each local disk using the intermediate file [S1]. Partition the tree nodes into blocks of depth $K_1$ using the labeling scheme [S2, unofficial]. Store min/max lists in separate blocks of capacity $K_2$ [S2, unofficial].
6.  **Cache Allocation (Optional):** Allocate a portion of main memory as a block cache to reduce I/O operations [S1]. Cache blocks, seed sets, and interval tree nodes to avoid disk reads [S1].

#### Phase 2: Query Processing (Isocontour Extraction)
For a given isovalue $t$:
1.  **Stabbing Query:** Each processor independently searches its local external interval tree to find all blocks whose `Span` intersects $t$ [S1]. A block $B_i$ is read if $t \in I(B_i)$, where $I(B_i)$ is the interval of the first node (label 0) in the block [S2, unofficial].
2.  **Block Loading:** If a block is found, check the cache. If present, use the cached pointer [S1]. If not in cache, load the block from disk [S1].
3.  **Polygon Extraction:** Extract polygons from the loaded block using standard isosurface algorithms [S1]. If using seed propagation, use the cached seed set if available [S1].
4.  **Output:** Write extracted polygons to local disk or stream to parallel rendering servers [S1]. Rendered images are composited by a Metabuffer [S1].

def preprocess_volume(volume_data, num_processors, disk_block_size=512, K1=3, K2=85):
    # 1. Initial Partitioning: Slabs
    slab_size = len(volume_data) // num_processors
    slabs = [volume_data[i*slab_size:(i+1)*slab_size] for i in range(num_processors)]
    
    # 2. Block Division
    blocks = []
    for proc_id, slab in enumerate(slabs):
        for i in range(0, len(slab), disk_block_size):
            chunk = slab[i:i+disk_block_size]
            block = {
                'id': proc_id * 10000 + i // disk_block_size,
                'origin': (i, 0, 0),
                'dimensions': (min(disk_block_size, len(slab)-i), 1, 1),
                'span': (min(chunk), max(chunk)),
                'vertex_values': chunk
            }
            blocks.append(block)
            
    # 3. Redistribution (Round-robin for load balancing)
    block_assignments = [[] for _ in range(num_processors)]
    for idx, block in enumerate(blocks):
        target_proc = idx % num_processors
        block_assignments[target_proc].append(block)
        
    # 4. Block Storage & Intermediate File
    intermediate_files = [[] for _ in range(num_processors)]
    for proc_id in range(num_processors):
        block_file = open(f"blocks_proc_{proc_id}.dat", "wb")
        for block in block_assignments[proc_id]:
            block_file.write(block['vertex_values'])
            intermediate_files[proc_id].append((block['id'], block['span'], block_file.tell()))
        block_file.close()
        
    # 5. External Tree Construction
    for proc_id in range(num_processors):
        build_external_interval_tree(intermediate_files[proc_id], K1, K2)

    # Construct tree nodes from intermediate data
    nodes = [{'id': bid, 'span': span, 'offset': off, 'left': None, 'right': None} for bid, span, off in intermediate_data]
    if not nodes: return
    root = nodes[0]
    # Build binary tree structure (simplified standard insertion)
    for i in range(1, len(nodes)):
        curr = root
        while True:
            if nodes[i]['id'] < curr['id']:
                if curr['left'] is None: curr['left'] = nodes[i]; break
                curr = curr['left']
            else:
                if curr['right'] is None: curr['right'] = nodes[i]; break
                curr = curr['right']
    # Apply labeling scheme
    def label_node(node):
        if node is None: return -1
        if node.get('left') is None and node.get('right') is None: return K1

### Edge Cases and Pitfalls
*   **Precision:** Floating-point comparisons for interval intersection must handle boundary cases (e.g., isovalue exactly equal to min/max) consistently [S1][S2, unofficial].
*   **Cache Eviction:** If cache size is insufficient, frequent disk I/O will degrade performance. Seed propagation requires caching additional state [S1].
*   **Load Imbalance:** Random or deterministic redistribution ensures approximately equal workload, but extreme isovalue distributions may still cause imbalance [S1].
*   **Disk Block Alignment:** Blocks must start at disk block boundaries to ensure efficient I/O [S1].

## Subtopics

### Discrete Lagrangian Optimization for Fixed Partitions
A variant that optimizes the assignment of extraction methods (e.g., in-core vs. out-of-core) to blocks under a memory constraint [S2, unofficial]. It converts the constrained optimization problem into an unconstrained discrete Lagrangian problem using a Lagrangian multiplier $\lambda \ge 0$ [S2, unofficial]. The complexity is reduced to linear by exploiting separability, minimizing terms independently for each block $B_k$ [S2, unofficial].

## Operating characteristics
*   **I/O Complexity:** The external memory interval tree has optimal $O(\log N + K)$ I/O operations for stabbing queries, where $K$ is the number of active cells [S1]. Solving the stabbing query problem requires optimal $O(T/B + \log_B N)$ I/O operations, where $T$ is the number of active blocks and $B$ is the block size [S1].
*   **Time Complexity:** Expected time to read interval tree disk blocks: $T_1 = \alpha_6 \sum_{i=1}^{N_B} \Pr(I(B_i))$, where the sum is over blocks whose root node has label 0 [S2, unofficial]. Expected time to read min/max lists: $T_2 \approx \alpha_6 \frac{\Pr(I)}{K_2} + \sum_{I_{cell}} \Pr(I_\eta) \frac{1}{2}$ [S2, unofficial]. Total expected cell extraction time: $E[T(B_\nu, 4, t)] = E[T(B_\nu, 2, t)] + T_1 + T_2$ [S2, unofficial].
*   **Memory Usage:** Minimal main memory requirement, limited to cache size and tree traversal stack. Scales to datasets much larger than RAM [S1][S2, unofficial].
*   **Strengths:** Handles massive datasets; I/O optimal; parallelizable [S1].
*   **Limitations:** High overhead for small datasets; disk I/O latency can dominate if cache misses are frequent; requires careful tuning of $K_1, K_2$ [S2, unofficial].
*   **When to Use:** Large datasets that do not fit in memory; parallel clusters with local disk storage [S1].
*   **When Not to Use:** Small datasets; environments with very slow disk I/O; real-time applications with strict latency constraints [S1][S2, unofficial].

## Background
The method was devised by Chiang, Silva, and Schroeder to overcome memory bottlenecks in isosurface extraction for large volume datasets [S2, unofficial]. It builds on the concept of external interval trees for optimal I/O performance [S1]. It is used in parallel and out-of-core isocontouring on commodity clusters [S1].
