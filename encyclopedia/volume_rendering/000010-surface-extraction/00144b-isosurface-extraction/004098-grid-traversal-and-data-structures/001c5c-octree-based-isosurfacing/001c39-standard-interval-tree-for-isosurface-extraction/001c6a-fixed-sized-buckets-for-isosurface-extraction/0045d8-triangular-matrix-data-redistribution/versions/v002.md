# Triangular Matrix Data Redistribution

Also called: Greedy Data Decomposition Algorithm, Greedy data redistribution, Range-based bucketing

## Overview
Triangular Matrix Data Redistribution is a deterministic greedy algorithm used to approximate the optimal data distribution for load balancing in parallel isosurface extraction [S1]. It addresses the NP-hard problem of minimizing workload differences among processors by categorizing volume data blocks into a triangular matrix of buckets based on their functional value ranges [S1]. Unlike [Fixed-Sized Buckets for Isosurface Extraction](1252-fixed-sized-buckets-for-isosurface-extraction.md), which sorts cells by intensity ranges into fixed-sized buckets, this method explicitly constructs a triangular matrix in the range space to handle blocks with varying spans, ensuring that blocks with similar range spans are distributed evenly across processors [S1].

## How it works
**Inputs:**
- A set of $N$ volume data blocks [S1].
- Each block $b_i$ has a functional value range $[x_i, y_i]$ where $x_i$ is the minimum and $y_i$ is the maximum scalar value in the block [S1].
- The global dataset range $[V_{min}, V_{max}]$ [S1].
- The number of processors $P$ [S1].
- The number of segments $n$ for dividing the global range [S1].
- The bucket range interval size $a = (V_{max} - V_{min}) / n$ [S1].

**Outputs:**
- A mapping of each block to a specific processor $p_j$ ($0 \le j < P$) [S1].

**Data Structures:**
- **Triangular Matrix:** A 2D structure where each element $M[r, c]$ represents a bucket [S1].
  - $r$: The row index, corresponding to the start of the block's range [S1].
  - $c$: The column index, corresponding to the size (span) of the block's range [S1].
  - The matrix is "triangular" because for a valid block range $[x, y]$, the span $y-x$ is always non-negative, and the start index is bounded by the global minimum [S1].
- **Processor Lists:** Each processor maintains a list of blocks assigned to it [S1].

**Steps:**
1. **Construct the Triangular Matrix:** Divide the global function value range $[V_{min}, V_{max}]$ into $n$ segments: $[V_0, V_1], [V_1, V_2], \dots, [V_{n-1}, V_n]$, where $V_0 = V_{min}$ and $V_n = V_{max}$ [S1]. The bucket range interval size is $a = (V_{max} - V_{min}) / n$ [S1].
2. **Assign Blocks to Buckets:** For each block $b_i$ with range $[x_i, y_i]$, determine its matrix element $(r, c)$ [S1]:
   $$ r = \lceil (x_i - V_{min}) / a \rceil $$
   $$ c = \lceil (y_i - x_i) / a \rceil $$
   The block is added to the list of blocks in matrix element $M[r, c]$ [S1].
3. **Sort Blocks within Each Bucket:** For each matrix element $e$ (i.e., each non-empty bucket $M[r, c]$), every processor collects the blocks it holds that belong to element $e$ [S1]. Each processor sorts its local collection of blocks for element $e$ in decreasing order of range size ($y_i - x_i$) [S1].
4. **Round-Robin Assignment:** For each matrix element $e$, distribute the sorted blocks to the $P$ processors in a round-robin fashion [S1]. Let the sorted list of blocks for element $e$ on processor $p_i$ be $(b_1, b_2, \dots, b_k)$ [S1]. The block $b_j$ (where $j$ is the 1-based index in the sorted list) is assigned to processor $p_{dest}$ where:
   $$ dest = (i + j - 1) \pmod P $$
   Here, $i$ is the index of the processor holding the block (0-based), and $j$ is the position in the sorted list (1-based) [S1]. This ensures that blocks with similar range spans are distributed evenly across all processors [S1].
5. **Data Redistribution:** Each processor collects all blocks it needs to send to other processors [S1]. Transmits these blocks to the destination processors in rounds [S1].

**Pseudocode:**
```python
import math

def triangular_matrix_redistribution(blocks, V_min, V_max, n, P):
    """
    blocks: List of tuples (block_id, x, y, orig_proc) where [x, y] is the functional range.
    V_min: Global minimum value.
    V_max: Global maximum value.
    n: Number of segments.
    P: Number of processors.
    Returns: Dict mapping block_id to processor_id.
    """
    a = (V_max - V_min) / n
    buckets = {}
    
    for block_id, x, y, orig_proc in blocks:
        # Guard against floating-point precision errors [G]
        x = max(x, V_min)
        y = min(y, V_max)
        
        # Calculate row index r and column index c [S1]
        r = math.ceil((x - V_min) / a)
        c = math.ceil((y - x) / a)
        
        if (r, c) not in buckets:
            buckets[(r, c)] = []
        buckets[(r, c)].append((block_id, x, y, orig_proc))
        
    assignments = {}
    
    for (r, c), block_list in buckets.items():
        # Sort by decreasing order of range size [S1]
        block_list.sort(key=lambda b: b[2] - b[1], reverse=True)
        
        # Round-robin assignment across processors [S1]
        for j, (block_id, x, y, orig_proc) in enumerate(block_list, start=1):
            dest_proc = (orig_proc + j - 1) % P
            assignments[block_id] = dest_proc
            
    return assignments
```

**Parameters:**
- $n$: Number of segments. Not given in the sources.
- $a$: Bucket range interval size. Derived from $n$.
- $P$: Number of processors.

**Edge Cases and Pitfalls:**
- **Precision:** The use of `ceil` requires careful handling of floating-point precision [G]. If $x$ is exactly $V_{min}$, $(x - V_{min})/a = 0$, and `ceil(0) = 0` [G]. If $x$ is slightly less than $V_{min}$ due to error, it might map to a negative index [G]. A guard clamping $x \ge V_{min}$ and $y \le V_{max}$ is required [G].
- **Empty Buckets:** Some matrix elements may be empty [S1]. The algorithm only processes non-empty elements [S1].
- **Degenerate Input:** If a block has $x = y$ (zero span), $c = 0$ [S1]. This is a valid bucket in the triangular matrix [S1].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** Experimental results verify that the number of blocks loaded by each processor is approximately the same, ensuring good load balancing [S1].
- **Strengths:** Deterministic, simple to implement, provides reasonably good load balancing for parallel isosurface extraction [S1].
- **Limitations:** It is an approximation algorithm because finding the optimal distribution is NP-hard [S1]. It may not achieve perfect load balance in all cases [S1].
- **When to use:** When parallel isosurface extraction requires load balancing and the data blocks have varying functional ranges [S1].
- **When not to use:** When exact optimal load balancing is required and computational resources allow for solving the NP-hard bin-packing problem [S1].

## Background
- **Origin:** The method was introduced in the paper "Scalable isosurface visualization of massive datasets on commodity off-the-shelf clusters" [S1].
- **History:** It is part of a suite of data redistribution techniques for parallel and out-of-core isocontouring, including a randomized algorithm [S1].
- **Usage:** Used in parallel isosurface extraction to balance the workload among processors [S1].
