# Incremental Isosurface Extraction

Also called: Incremental extraction, Incremental search

## Overview
Incremental isosurface extraction is an optimization for isosurface extraction that reuses the state from a previous query (with isovalue $q$) to accelerate a new query (with isovalue $q'$), avoiding full re-scanning of the data structure by tracking active/inactive cell boundaries via markers [S1]. It builds on [Fixed-Sized Buckets for Isosurface Extraction](1252-fixed-sized-buckets-for-isosurface-extraction.md) by maintaining boundary markers that allow the algorithm to skip over cells whose active status is known to be unchanged, rather than re-evaluating every cell in the active range [S1].

## How it works
**Inputs and Outputs:**
- Input: The fixed-sized bucket data structure (min-dictionary, cell records, and optional marker cells), the previous isovalue $q$, the new isovalue $q'$, and the previous set of active buckets/cells [S1].
- Output: The set of active cells for isovalue $q'$ [S1].

**Data Structures:**
The method relies on the data structure from Fixed-Sized Buckets, extended with markers for incremental operation [S1]:
- **Cell Records:** $N$ records, one for each cell in the dataset [S1].
- **Min-Dictionary:** $N/B + 1$ values, storing the minimum intensity value for each bucket [S1].
- **Marker Cells:** $N/B + 1$ additional cells (one per bucket) used to track the boundary between active and inactive cells within a bucket. These are only required if incremental extraction is used [S1].
- **Memory Complexity:** $O(N + 2 \cdot N/B + 2) = O(N)$ [S1].

**Parameters:**
- $B$: Bucket size (number of cells per bucket). Typical value is 4096. Empirical results show average active cell lookup time decreases toward 4096 and increases past 8192. The optimal choice is not related to input data size [S1].

**Algorithm Steps:**
The algorithm distinguishes between increasing isovalue ($q' > q$) and decreasing isovalue ($q' < q$) [S1]. Let $c^*_0, \dots, c^*_a$ be the set of active buckets for the previous isovalue $q$, and $c^*_0, \dots, c^*_{a'}$ be the set for the new isovalue $q'$ [S1].

### Increasing Isovalue ($q' > q$)
The buckets to visit fall into three categories [S1]:

1. **Buckets $c^*_0 \dots c^*_{a-1}$ remain active:**
   - These buckets were active in the previous query and remain active [S1].
   - Markers are pushed upward to deactivate cells that are no longer active [S1].
   - Only the max-criterion is checked when updating markers because the bucket satisfies the min-criterion (it is already known to be active) [S1].

2. **The former last active bucket $c^*_a$:**
   - This bucket now has a single contiguous block of active cells and a single contiguous block of inactive cells [S1].
   - Cells are traversed one by one to determine activation/deactivation status [S1].

3. **Buckets $c^*_{a+1} \dots c^*_{a'}$ have just become active:**
   - These buckets were inactive in the previous query but are now active [S1].
   - The full extraction method is applied starting at bucket $c^*_{a+1}$ rather than $c^*_0$ [S1].

### Decreasing Isovalue ($q' < q$)
The buckets to visit fall into three categories [S1]:

1. **Buckets $c^*_0 \dots c^*_{a'-1}$ remain active:**
   - These buckets were active in the previous query and remain active [S1].
   - Markers are pushed downward to activate cells that are newly active [S1].
   - Only the max-criterion is checked in updating markers [S1].

2. **The new last active bucket $c^*_{a'}$:**
   - This bucket contains non-contiguous blocks of cells that must be activated and deactivated [S1].
   - Cells are traversed to determine status [S1].

3. **Buckets $c^*_{a'+1} \dots c^*_a$ have become inactive:**
   - These buckets were active in the previous query but are now inactive [S1].
   - The full extraction method is applied starting at bucket $c^*_{a'+1}$, but instead of activating cells, the visited cells are deactivated [S1].

**Pseudocode:**
```python
def incremental_extraction(min_dict, cell_values, prev_active_buckets, prev_markers, q, q_prime, B):
    """
    Incremental isosurface extraction using fixed-sized buckets.
    
    Args:
        min_dict: List of minimum intensity values per bucket.
        cell_values: List of intensity values for all N cells.
        prev_active_buckets: List of bucket indices active for isovalue q.
        prev_markers: List of marker indices per bucket from previous query.
        q: Previous isovalue.
        q_prime: New isovalue.
        B: Bucket size (cells per bucket).
        
    Returns:
        active_cells: List of cell indices active for q_prime.
        new_markers: Updated marker indices per bucket.
    """
    # Determine new active buckets: bucket is active if its minimum value <= isovalue
    new_active_buckets = [b for b in range(len(min_dict)) if min_dict[b] <= q_prime]
    
    active_cells = []
    new_markers = list(prev_markers)
    
    if q_prime > q:
        # === Increasing Isovalue ===
        
        # 1. Buckets c*0...c*a-1 remain active
        for i in range(len(prev_active_buckets) - 1):
            b = prev_active_buckets[i]
            marker = prev_markers[b]
            start = b * B
            # Push marker upward to deactivate cells passed along the way
            # Only max-criterion checked (cell_value <= q_prime) because bucket satisfies min-criterion
            for idx in range(marker, start, -1):
                if cell_values[idx] > q_prime:
                    marker -= 1
                else:
                    break
            new_markers[b] = marker
            # Cells from start to new marker are active
            active_cells.extend(range(start, marker + 1))
            
        # 2. Former last active bucket c*a
        if prev_active_buckets:
            b = prev_active_buckets[-1]
            start = b * B
            end = min(start + B, len(cell_values))
            # Traverse cells one by one to determine activation/deactivation
            for idx in range(start, end):
                if cell_values[idx] <= q_prime:
                    active_cells.append(idx)
                    
        # 3. Buckets c*a+1...c*a' have just become active
        start_idx = len(prev_active_buckets)
        for i in range(start_idx, len(new_active_buckets)):
            b = new_active_buckets[i]
            start = b * B
            end = min(start + B, len(cell_values))
            # Full extraction method applied starting at this bucket
            for idx in range(start, end):
                if cell_values[idx] <= q_prime:
                    active_cells.append(idx)
                    
    else:
        # === Decreasing Isovalue ===
        
        # 1. Buckets c*0...c*a'-1 remain active
        for i in range(len(new_active_buckets) - 1):
            b = new_active_buckets[i]
            marker = prev_markers[b]
            start = b * B
            end = min(start + B, len(cell_values))
            # Push marker downward to activate cells passed along the way
            # Only max-criterion checked
            for idx in range(marker, end):
                if cell_values[idx] <= q_prime:
                    marker += 1
                else:
                    break
            new_markers[b] = marker
            active_cells.extend(range(start, marker + 1))
            
        # 2. New last active bucket c*a'
        if new_active_buckets:
            b = new_active_buckets[-1]
            start = b * B
            end = min(start + B, len(cell_values))
            # Traverse cells to determine status
            for idx in range(start, end):
                if cell_values[idx] <= q_prime:
                    active_cells.append(idx)
                    
        # 3. Buckets c*a'+1...c*a have become inactive
        start_idx = len(new_active_buckets)
        for i in range(start_idx, len(prev_active_buckets)):
            b = prev_active_buckets[i]
            start = b * B
            end = min(start + B, len(cell_values))
            # Full extraction method applied, but visited cells are deactivated
            for idx in range(start, end):
                pass # Cells are deactivated by not being added to active_cells
                
    return active_cells, new_markers
```

**Edge Cases and Pitfalls:**
- **Pathological Worst-Case:** If only one cell is active and located at the bottom of the last bucket, the algorithm traverses $N/B$ buckets and $B$ inactive cells. This is extremely rare in real application data [S1].

## Operating characteristics
- **Time Complexity:**
    - **Average-Case:** $O(K + B)$, where $K$ is the number of active cells and $B$ is the bucket size. This is derived from at most three comparisons per cell in a normal bucket (one max-criterion per active cell, one min-dictionary check, one failed max-criterion check per bucket) and at most two comparisons per cell in the last active bucket (bounded by $B$). Total: $O(3K + 2B) = O(K + B)$ [S1].
    - **Worst-Case:** $O(N/B + B) = O(N)$, if only one cell is active and located at the bottom of the last bucket, traversing $N/B$ buckets and $B$ inactive cells [S1]. If $B = \sqrt{N}$, the average and worst case extraction is upper-bounded to $O(K + \sqrt{N})$ [S1].
- **Memory Complexity:** $O(N)$, with a constant factor increase of $3 + 1/B$ without incremental extraction markers and $3 + 2/B$ with incremental extraction markers [S1].
- **Measured Performance:**
    - **RockerArm Dataset:** Full extraction average search time 0.967 ms; Incremental extraction 0.444 ms; Coherence 63% [S1].
    - **Engine Dataset:** Full extraction average search time 2.285 ms; Incremental extraction 0.432 ms; Coherence 88% [S1].
- **Strengths:** Competitive with the interval tree method, an optimal technique. Achieves $O(K)$ performance on average for real datasets [S1].
- **Limitations:** Performance depends on the coherence of the data. Pathological worst-case is rare but possible [S1].

## Background
Incremental isosurface extraction was proposed in the paper "Isosurface Extraction Using Fixed-Sized Buckets" (2005) as an optimization for the fixed-sized bucket method [S1]. It was designed to improve performance in scenarios where isovalue changes are frequent and coherent, such as in interactive visualization or animation [S1]. The method is competitive with the interval tree method, which is considered an optimal technique for isosurface extraction [S1].
