# Standard Interval Tree for Isosurface Extraction

Also called: Cignoni et al. Interval Tree, Interval Tree, Interval-Tree Based Isosurface Extraction, Normal Interval Tree

## Overview
The Standard Interval Tree is a spatial indexing method for isosurface extraction that identifies all volume cells intersecting a specific isovalue with optimal output-sensitive query complexity $O(\log n + k)$, where $n$ is the number of cells and $k$ is the number of active cells [S1, S4, unofficial]. It solves the problem of inefficiently scanning the entire volume to find active cells by grouping cells into a balanced binary tree based on their scalar value intervals [S2]. Unlike sibling methods such as [IsoOctree](1744-isooctree.md) which rely on hierarchical spatial subdivision of the domain, or [Span Space Isosurface Extraction](1750-span-space-isosurface-extraction.md) which maps extrema to a 2D plane, the Standard Interval Tree explicitly organizes cells by their min/max scalar ranges in a 1D hierarchical structure [S2][S4, unofficial]. Its primary trade-off is high memory overhead, which can be prohibitive for large datasets [S1, unofficial][S2].

## How it works
**Inputs:** A set of $m$ cells, where each cell $c_i$ is defined by its scalar minimum $v_{min}^i$ and scalar maximum $v_{max}^i$.
**Outputs:** A balanced binary tree data structure.
**Query Input:** An isovalue $t$.
**Query Output:** A list of all cells $c_i$ such that $v_{min}^i \le t \le v_{max}^i$.

### Data Structures
The data structure is a balanced binary tree. Each node in the tree contains:
1.  A threshold value $t_0$.
2.  A **min-list**: A list of pointers to cells, sorted in ascending order of their $v_{min}$ values.
3.  A **max-list**: A list of pointers to cells, sorted in descending order of their $v_{max}$ values.

**Memory Layout:**
*   Each cell is stored twice in the tree (once in a min-list, once in a max-list) via pointers [S4, unofficial].
*   Storage per cell reference: 2 values ($v_{min}, v_{max}$) + 2 pointers.
*   For 2-byte values and 4-byte pointers, this amounts to 12 bytes per cell [S4, unofficial].
*   Total memory overhead for the general representation is $3h + 2m$ words, where $h$ is the number of distinct interval extremes and $m$ is the number of cells [S3, book].
*   For structured volumes of dimensions $\Delta x, \Delta y, \Delta z$, the number of cells is $(\Delta x - 1)(\Delta y - 1)(\Delta z - 1)$. With 4-byte pointers, the space overhead is $8(\Delta x - 1)(\Delta y - 1)(\Delta z - 1)$ bytes, resulting in total space usage of approximately nine times the size of the volume data [S1, unofficial].

### Construction Algorithm
1.  **Input:** A set of intervals $I = \{[v_{min}^i, v_{max}^i] \mid i = 1 \dots m\}$.
2.  **Threshold Selection:** Choose a threshold $t_0$. The choice of $t_0$ determines the balance of the tree. To guarantee asymptotic optimality, $t_0$ should be chosen such that the number of intervals below and above $t_0$ is balanced [S2][S4, unofficial].
3.  **Partitioning:** Partition $I$ into three disjoint subsets:
    *   $I_{contain}$: Intervals where $v_{min}^i \le t_0 \le v_{max}^i$.
    *   $I_{below}$: Intervals where $v_{max}^i < t_0$.
    *   $I_{above}$: Intervals where $v_{min}^i > t_0$.
4.  **Node Creation:** Create a new tree node.
    *   Set the node's threshold to $t_0$.
    *   Assign all cells in $I_{contain}$ to this node.
    *   Sort $I_{contain}$ by $v_{min}$ ascending to form the node's **min-list**.
    *   Sort $I_{contain}$ by $v_{max}$ descending to form the node's **max-list**.
5.  **Recursion:**
    *   If $I_{below}$ is not empty, recursively build the left child using $I_{below}$ and a new threshold $t_{left}$.
    *   If $I_{above}$ is not empty, recursively build the right child using $I_{above}$ and a new threshold $t_{right}$.
6.  **Termination:** The recursion terminates when all intervals are attached to a node [S4, unofficial].

### Query Algorithm
Given an isovalue $t$ and the root node:
1.  **Check Root Threshold:** Let the current node's threshold be $t_0$.
2.  **Case $t < t_0$:**
    *   Iterate through the node's **min-list** from the beginning.
    *   Report each cell $c$ as active if $v_{min}^c \le t$.
    *   Stop iterating when the first cell is found with $v_{min}^c > t$ (or the list ends).
    *   Recursively query the left child with $t$.
3.  **Case $t > t_0$:**
    *   Iterate through the node's **max-list** from the beginning.
    *   Report each cell $c$ as active if $v_{max}^c \ge t$.
    *   Stop iterating when the first cell is found with $v_{max}^c < t$ (or the list ends).
    *   Recursively query the right child with $t$.
4.  **Case $t = t_0$:**
    *   Report all cells in the node's min-list (or max-list) as active.
    *   Terminate search (no further recursion needed as all containing intervals are stored here) [S4, unofficial].

### Pseudocode

```python
class IntervalTreeNode:
    def __init__(self, threshold):
        self.threshold = threshold
        self.min_list = []  # List of (vmin, cell_ptr), sorted ascending by vmin
        self.max_list = []  # List of (vmax, cell_ptr), sorted descending by vmax
        self.left_child = None
        self.right_child = None

def build_interval_tree(intervals):
    """
    intervals: List of tuples (vmin, vmax, cell_ptr)
    Returns: Root IntervalTreeNode
    """
    if not intervals:
        return None

    # Determine threshold t0 to balance the tree
    # In practice, t0 is often chosen as the median of all vmin and vmax values
    # to ensure O(log n) depth.
    all_extremes = [vmin for vmin, vmax, _ in intervals] + \
                   [vmax for vmin, vmax, _ in intervals]
    all_extremes.sort()
    t0 = all_extremes[len(all_extremes) // 2]

    node = IntervalTreeNode(t0)

    contain = []
    below = []
    above = []

    for vmin, vmax, cell_ptr in intervals:
        if vmin <= t0 <= vmax:
            contain.append((vmin, vmax, cell_ptr))
        elif vmax < t0:
            below.append((vmin, vmax, cell_ptr))
        elif vmin > t0:
            above.append((vmin, vmax, cell_ptr))

    # Sort contain lists
    # min_list: ascending vmin
    contain.sort(key=lambda x: x[0])
    node.min_list = [(vmin, cell_ptr) for vmin, vmax, cell_ptr in contain]

    # max_list: descending vmax
    contain.sort(key=lambda x: x[1], reverse=True)
    node.max_list = [(vmax, cell_ptr) for vmin, vmax, cell_ptr in contain]

    # Recurse
    node.left_child = build_interval_tree(below)
    node.right_child = build_interval_tree(above)

    return node

def query_interval_tree(node, t, active_cells):
    """
    node: Current IntervalTreeNode
    t: Isovalue
    active_cells: List to append active cell pointers to
    """
    if node is None:
        return

    t0 = node.threshold

    if t < t0:
        # Scan min_list
        for vmin, cell_ptr in node.min_list:
            if vmin <= t:
                active_cells.append(cell_ptr)
            else:
                # Since min_list is sorted ascending, all subsequent vmin > t
                break
        # Recurse left
        query_interval_tree(node.left_child, t, active_cells)

    elif t > t0:
        # Scan max_list
        for vmax, cell_ptr in node.max_list:
            if vmax >= t:
                active_cells.append(cell_ptr)
            else:
                # Since max_list is sorted descending, all subsequent vmax < t
                break
        # Recurse right
        query_interval_tree(node.right_child, t, active_cells)

    else: # t == t0
        # All cells in this node contain t0, so they contain t
        for vmin, cell_ptr in node.min_list:
            active_cells.append(cell_ptr)
        # Terminate: no need to recurse as all containing intervals are stored here
        return
```

### Parameters and Edge Cases
*   **Threshold Selection:** The performance depends heavily on the balance of the tree. An unbalanced tree degrades query time to $O(n)$. The threshold $t_0$ should be chosen to split the intervals as evenly as possible [S2][S4, unofficial].
*   **Precision:** Floating-point comparisons must handle equality carefully. The condition $v_{min} \le t \le v_{max}$ defines containment. In the query, stopping conditions rely on sorted order, so precision errors in sorting or comparison can lead to missed cells or false positives [G].
*   **Empty Sets:** If $I_{below}$ or $I_{above}$ is empty, the corresponding child is `None` [S4, unofficial].

## Subtopics

### [Fixed-Sized Buckets for Isosurface Extraction](1252-fixed-sized-buckets-for-isosurface-extraction.md)
Fixed-Sized Buckets replaces the complex tree structure with a logical 2D array, requiring only standard sorting for construction. It works equally well for floating-point data unlike the Interval Table which may require quantization, and offers a simple implementation with a small memory footprint.

### [Interval Tree with Cell Grouping](1342-interval-tree-with-cell-grouping.md)
This variant reduces memory overhead by having each pointer reference a group of eight adjacent cells rather than a single cell, resulting in a tree size approximately 1/8th that of a regular interval tree. This reduction comes at the cost of increased query time, as intersecting groups require checking all eight constituent cells individually.

### [Span Space Isosurface Extraction](1750-span-space-isosurface-extraction.md)
Span Space Isosurface Extraction maps cell scalar extrema into a 2D coordinate system ("span space") to reduce the search to a 2D range query, achieving $O(\sqrt{n} + k)$ worst-case complexity. It differs from the Standard Interval Tree by explicitly leveraging geometric properties in a 2D plane rather than relying on hierarchical 1D subdivision.

### [Out-of-core Interval Tree Extraction](2146-out-of-core-interval-tree-extraction.md)
This method stores the auxiliary interval tree index structure on disk to handle datasets larger than main memory. It partitions the tree into disk blocks, allowing efficient "stabbing queries" with optimal I/O complexity, distinguishing it from the in-memory Standard Interval Tree.

### [Interval Table for Isosurface Extraction](4357-interval-table-for-isosurface-extraction.md)
The Interval Table maps scalar value intervals to tetrahedron IDs, allowing the extraction algorithm to skip tetrahedra whose function span does not contain the isovalue. Unlike the Standard Interval Tree which visits neighbors, the Interval Table allows skipping tetrahedra entirely based on their scalar range, drastically reducing visited tetrahedra.

### [Search Data Structure Based Isosurface Extraction](6738-search-data-structure-based-isosurface-extraction.md)
This family of methods accelerates isosurface extraction for multiple queries by constructing external indices to disregard regions containing only non-active cells. Unlike simple traversal, these methods trade upfront index construction time for faster subsequent queries, making them distinct from single-pass techniques.

### Matryoshka Layer Insertion
A construction optimization where cells are inserted into layers defined by six planes based on coordinate minima, allowing $O(1)$ insertion and $O(k)$ total construction time for $k$ cells [S1, unofficial]. The layer index is determined by $\min(\min(cellx, celly, cellz), \min((\Delta x-1)-cellx, (\Delta y-1)-celly, (\Delta z-1)-cellz))$ [S1, unofficial]. To avoid a second processing round, the insertion of a cell in the layers is merged into the query process of the interval tree [S1, unofficial].

### Edge-Covering Space Reduction
A space reduction technique that restricts the data structure to a subset of cells that covers all edges, reducing storage by a factor of 4 [S4, unofficial]. Since an edge is shared by four cells, only one out of four neighboring cells needs to be considered. After extraction, the isosurface is propagated from the reported active cells onto neighboring cells that were not covered in the data structure [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Query time is $O(\log n + k)$, where $n$ is the number of cells and $k$ is the number of active cells [S1, S4, unofficial]. For scalar data volumes, $k$ usually dominates $\log n$ [S1, unofficial].
*   **Memory Complexity:** $O(n)$. The space overhead is significant. For 8-bit volumes, the overhead is about 8 times the size of the volume data (due to 2 pointers per cell, 4 bytes each), leading to total space usage of 9 times the volume size [S1, unofficial]. Other estimates cite memory overhead as approximately five times the original data size [S2].
*   **Performance:** On the Rage256 dataset, the Interval Tree executes slower than every algorithm except Marching Cubes [S2]. This poor performance is attributed to poor memory behavior, specifically high TLB and cache miss rates, as the algorithm visits data in an order different from its memory layout [S2].
*   **Strengths:** Asymptotically optimal worst-case efficiency for active cell identification [S2]. Output-sensitive complexity [S3, book].
*   **Limitations:** High memory consumption can be prohibitive for large datasets [S1, S4, unofficial]. Poor cache locality can negate theoretical time complexity benefits on large datasets [S2].

## Background
The Standard Interval Tree for isosurface extraction was introduced by Cignoni, Marino, Montani, and Puppo [S3, book]. It was proposed as an alternative to kd-trees, which had a worst-case search time of $O(k + \sqrt{n})$ [S4, unofficial]. The method guarantees asymptotically optimal worst-case efficiency by grouping cells into a balanced binary tree based on their extreme value intervals [S2]. It is widely used in visualization handbooks as a standard method for accelerating the traversal phase of isosurface extraction [S3, book].
