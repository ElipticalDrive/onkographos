# Marching Cubes with QEF Vertex Optimization

Also called: MC-QEF, Optimized Marching Cubes

## Overview
Marching Cubes with QEF Vertex Optimization is a surface extraction method that computes vertex positions by minimizing a Quadric Error Function (QEF) for ambiguous cube configurations, while employing a fast 2D linear/binomial search for non-ambiguous cases, to produce a watertight mesh from a voxel grid [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) for topology determination and applies the shared principles of [Vertex Position Optimization and Error Minimization](10991-vertex-position-optimization-and-error-minimization.md) to reduce geometric error $E$ between extracted vertices and the scalar field $f(\mathbf{x})$ [S1, unofficial]. Unlike standard linear interpolation, this method explicitly solves for vertex positions that satisfy the gradient constraints of the surrounding edges, ensuring higher fidelity in complex topological regions.

## How it works
The method processes voxel indices by categorizing them into two groups based on their configuration complexity: a "fast" group for non-ambiguous cases and a "slow" group for ambiguous cases requiring QEF minimization [S1, unofficial].

### Inputs and Outputs
*   **Input**: A voxel grid of occupancy bits `occs`, grid dimensions `GRID`, `GRID2`, `GRID3` (where $GRID2 = GRID \times GRID$, $GRID3 = GRID \times GRID \times GRID$), and pre-computed lookup tables (`lctab_2d`, `axd_tab`, `ax0_tab`, `ax1_tab`, `cas_tab`, `qvntab`, `pfvtab`, `vitogi`, `cstrtab`).
*   **Output**: A list of optimized vertex positions `val_pnts` and associated triangle indices.

### Data Structures
*   `occs`: 3D array of integer occupancy bits (0 or 1).
*   `pidx1`: 1D array of linear voxel indices to process.
*   `val_pnts`: 2D array of vertex positions, indexed by global vertex ID.
*   `GRID`, `GRID2`, `GRID3`: Integer constants representing grid strides.
*   `ERR`: Floating-point threshold for degenerate edge detection (e.g., $10^{-6}$).
*   `QEF_REG`: Regularization parameter for the QEF least-squares solver.
*   `SEP`: Separation constant for boundary handling.

### Algorithm Steps

1.  **Filter and Initialize**:
    Split `pidx1` into two groups:
    *   Group 1 (Fast): Indices in range $[3 \cdot GRID3, 9 \cdot GRID3)$.
    *   Group 2 (QEF): Indices $\ge 9 \cdot GRID3$.
    Initialize `start_idx` to 0.

2.  **Process Group 1 (Non-Ambiguous)**:
    For each index `pidx1` in Group 1:
    a.  Compute the 8-neighbor occupancy value `val_`:
        $$ val\_ = occs[pidx3] + 2 \cdot occs[pidx3 + axis1] + 4 \cdot occs[pidx3 + axis0] + 8 \cdot occs[pidx3 + axis2] $$
        where `pidx3` is the 3D coordinate of the voxel, and `axis0`, `axis1` are direction vectors from lookup tables.
    b.  Apply ambiguity correction: If `amb_chks[pidx3]` is true, set `val\_ = 15 - val\_`.
    c.  Compute vertex positions using `_2d_search(pidx3, axdir, axis0, axis1, val_, cases)`.
    d.  Store results in `val_pnts` at `start_idx` and increment `start_idx` by the count of processed vertices.

3.  **Process Group 2 (Ambiguous/QEF)**:
    For each index `pidx1` in Group 2:
    a.  Derive the case index: $cases = pidx1 / GRID3 - 9$.
    b.  Compute `val_` (occupancy pattern) similarly to Step 2.
    c.  Call `_solve_QEF(pidx3, val_, cases)` to compute optimized vertex positions.
    d.  Store results in `val_pnts` at `start_idx`.

4.  **`_solve_QEF` Implementation**:
    For each vertex index $i$ from 3 to 7:
    a.  Find indices `idx` where `qvntab[val_, cases] == i`.
    b.  Retrieve vertex coordinates `vtcs` from `pfvtab[val0_, cas, :2*i+1]` and edge indices `vitg` from `vitogi[vtcs]`.
    c.  Compute 3D positions `pnti` using grid offsets:
        $$ pnti = vitg[:,:,3] \cdot GRID3 + (pid3[:,0] + vitg[:,:,0]) \cdot GRID2 + (pid3[:,1] + vitg[:,:,1]) \cdot GRID + (pid3[:,2] + vitg[:,:,2]) $$
    d.  Get global indices `pidx` and retrieve pre-computed vertex positions `vert = val_pnts[pidx]`.
    e.  Add local offsets `vitg[:,:3]` to `vert`.

5.  **QEF Normal and Centroid Calculation**:
    a.  Compute QEF normals `qnrm` using cross products of edge vectors:
        $$ \_1vt = vert[:, 1::2] $$
        $$ qnrm = \text{cross}(\_1vt - vert[:, :-1:2], \_1vt - vert[:, 2::2]) $$
    b.  Compute centroid `cntr = mean(\_1vt, dim=1)`.
    c.  Normalize `qnrm`. Handle zero-length edges by checking if length $< ERR$; if so, set length to 1.0 before normalization.

6.  **Solve QEF System**:
    a.  Construct matrix $A$ and vector $b$:
        $$ A = \text{cat}(qnrm, QEF\_REG \cdot I) $$
        $$ b = \text{cat}(\sum(\_1vt \cdot qnrm), QEF\_REG \cdot cntr) $$
    b.  Solve least squares: $qefr = \text{lstsq}(A, b).\text{solution}$.
    c.  If all normals are degenerate (`cndt` all true), use `cntr` instead of `qefr`.

7.  **Boundary Constraint and Final Position**:
    a.  Compute ray direction $ctoq = qefr - cpnt$ and length $leng$.
    b.  Compute intersection parameter $t$ with constraint planes defined by `cstrtab`.
    c.  Concatenate boundary parameters $(1-cpnt)/ctoq$ and $-cpnt/ctoq$ with $t$.
    d.  Handle NaNs and negative values: if invalid, set $t = leng + SEP$.
    e.  Normalize by $leng$ and clamp $t$ to $[0, 1]$.
    f.  Final vertex: $v = cpnt + t \cdot ctoq$.

### Parameters
*   `ERR`: Threshold for degenerate edges. Typical value: $10^{-6}$ [S1, unofficial].
*   `QEF_REG`: Regularization weight for QEF. Typical value: Not given in the sources.

*   `VERTICAL_RANGE`, `HORIZNTL_RANGE`: Search ranges for 2D search. Typical value: Not given in the sources.

### Edge Cases and Pitfalls
*   **Degenerate Normals**: If all edge vectors are zero-length (length $< ERR$), the QEF system is singular. The method falls back to using the centroid `cntr` [S1, unofficial].
*   **NaNs and Negative Values**: Intersection parameters $t$ that are NaN or negative are handled by setting $t = leng + SEP$ before clamping to $[0, 1]$ [S1, unofficial].
*   **Ambiguity Correction**: For certain configurations, the occupancy value `val_` must be inverted ($15 - val\_$) to resolve topological ambiguities [S1, unofficial].

## Subtopics

### QEM-based Vertex Relocation
A vertex relocation method used in the Mesh Generation phase to move vertices to the isosurface, using the Quadric Error Metric (QEM) instead of full QEF minimization to reduce computational complexity and register usage on parallel hardware [S2, unofficial]. Unlike pseudoinverse QEF minimization which is complex and penalizes performance on parallel hardware due to register limits, QEM minimization is stable with supporting planes and produces accurate results sufficient for volume preservation [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: The method splits processing into two groups. The fast group uses 2D linear/binomial search, which is $O(1)$ per vertex. The slow group uses QEF least-squares solution, which is $O(1)$ per vertex but with a higher constant factor due to matrix operations. Overall complexity is linear with respect to the number of voxels $N$, i.e., $O(N)$.
*   **Memory Complexity**: Requires storage for `val_pnts` (one position per vertex), lookup tables, and intermediate arrays for QEF solving. Memory usage is $O(N)$.
*   **Measured Performance**: Not given in the sources.
*   **Strengths**: Produces watertight meshes with high geometric accuracy for ambiguous cases. The hybrid approach (fast search for non-ambiguous, QEF for ambiguous) balances speed and quality.
*   **Limitations**: QEF solving is computationally expensive compared to linear interpolation. Register usage can be high on parallel hardware if not optimized (as noted in QEM variant [S2, unofficial]).
*   **When to Use**: When high geometric fidelity is required, especially in regions with topological ambiguities.
*   **When Not to Use**: When performance is critical and approximate geometry is acceptable; consider standard Marching Cubes or QEM-based variants [S2, unofficial].

## Background
The method originates from the ODC (Octree-based Density Compression) project by KAIST Visual AI Group [S1, unofficial]. It is designed for efficient surface extraction from voxel grids, particularly in contexts where topological ambiguity is common. The QEM-based variant is discussed in the context of generating smooth high-quality isosurfaces for interactive modeling and visualization of complex terrains [S2, unofficial].
