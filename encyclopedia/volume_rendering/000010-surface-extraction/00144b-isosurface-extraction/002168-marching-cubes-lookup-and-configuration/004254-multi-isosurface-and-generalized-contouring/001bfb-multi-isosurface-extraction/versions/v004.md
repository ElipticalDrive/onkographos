# Multi-Isosurface Extraction

Also called: Multiple Isosurface Extraction, Multi-Resolution Isosurface Extraction

## Overview
Multi-Isosurface Extraction is a technique to extract and render multiple isosurfaces from the same scalar volume data simultaneously by running the Marching Cubes algorithm for each selected isovalue [S1, unofficial]. It solves the problem of visualizing distinct structural features within a single dataset that correspond to different density or intensity thresholds. Unlike single isosurface extraction, this method requires managing multiple triangle lists and potentially multiple rendering passes or state changes for different isovalue colors [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by iteratively applying the core mechanism for each distinct isovalue in a provided list, maintaining separate output data structures for each threshold [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset `dataset` of dimensions $X \times Y \times Z$, and a list of isovalue inputs `isovalues` from the user.
*   **Output:** A collection of triangle lists, one for each isovalue, and rendered geometry for each.

**Data Structures:**
The method uses a linked list structure to store extracted triangles. Based on the reference implementation [S1, unofficial], the node structure is defined as:
```cpp
struct NODE {
    TRIANGLE t; // Contains 3 vertices
    NODE *next;
};
```
The `TRIANGLE` structure contains three vertices, where each vertex has position $(x, y, z)$ and potentially normal/color attributes. The `GRIDCELL` structure holds the values and positions of the 8 corners of a voxel.

**Parameters:**
*   `isovalues`: A list of floating-point values representing the thresholds.
*   `inc`: An integer step size for voxel iteration. `inc = 1` is full resolution. `inc > 1` reduces resolution by skipping voxels [S1, unofficial].

**Steps:**
1.  Initialize an empty list of triangle lists, `all_triangles`, where each entry corresponds to an isovalue.
2.  For each `isoValue` in `isovalues`:
    a.  Initialize an empty `NODE *list` for this isovalue.
    b.  Determine the resolution step `inc`. If multi-resolution is not specified for this isovalue, `inc = 1`. Otherwise, set `inc` to the desired reduction factor (e.g., 2, 4) [S1, unofficial].
    c.  Iterate through the volume grid with step `inc`:
        $$ \text{for } i = 0 \text{ to } X - \text{inc} \text{ step } \text{inc} $$
        $$ \text{for } j = 0 \text{ to } Y - \text{inc} \text{ step } \text{inc} $$
        $$ \text{for } k = 0 \text{ to } Z - \text{inc} \text{ step } \text{inc} $$
    d.  For each voxel $(i, j, k)$, retrieve the 8 corner values from `dataset`.
    e.  Compute the binary configuration index by comparing each corner value to `isoValue` (1 if $> isoValue$, 0 otherwise).
    f.  Use the `edgeTable` and `triangleTable` from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) to determine which edges are intersected and how to form triangles.
    g.  Calculate intersection points using linear interpolation between corner values.
    h.  Create `TRIANGLE` objects for the generated triangles and append them to the `NODE *list` for this `isoValue`.
3.  Render the generated triangles for each isovalue, potentially on different viewports or in the same viewport with distinct colors/materials [S1, unofficial].

**Pseudocode:**
```python
def multi_isosurface_extraction(dataset, isovalues, resolutions=None):
    """
    Extracts isosurfaces for multiple isovales.
    dataset: 3D array of shape (X, Y, Z)
    isovalues: list of float thresholds
    resolutions: dict mapping isovalue to int 'inc' step. Default 1.
    """
    if resolutions is None:
        resolutions = {v: 1 for v in isovalues}
    
    all_triangle_lists = {}
    
    for iso_value in isovalues:
        inc = resolutions.get(iso_value, 1)
        triangle_list = [] # List of Triangle objects
        
        X, Y, Z = dataset.shape
        
        # Iterate with step 'inc'
        for i in range(0, X - inc, inc):
            for j in range(0, Y - inc, inc):
                for k in range(0, Z - inc, inc):
                    # Get 8 corner values and positions
                    # Indices follow standard Marching Cubes ordering
                    corners = [
                        dataset[i, j, k],
                        dataset[i + inc, j, k],
                        dataset[i + inc, j + inc, k],
                        dataset[i, j + inc, k],
                        dataset[i, j, k + inc],
                        dataset[i + inc, j, k + inc],
                        dataset[i + inc, j + inc, k + inc],
                        dataset[i, j + inc, k + inc]
                    ]
                    
                    positions = [
                        (i, j, k),
                        (i + inc, j, k),
                        (i + inc, j + inc, k),
                        (i, j + inc, k),
                        (i, j, k + inc),
                        (i + inc, j, k + inc),
                        (i + inc, j + inc, k + inc),
                        (i, j + inc, k + inc)
                    ]
                    
                    # Compute configuration index
                    config = 0
                    for idx, val in enumerate(corners):
                        if val > iso_value:
                            config |= (1 << idx)
                    
                    # Get triangles from lookup tables
                    # edge_table and triangle_table are from parent article
                    edge_indices = edge_table[config]
                    if edge_indices == 0:
                        continue # No intersection
                    
                    tri_indices = triangle_table[config]
                    
                    # Generate triangles
                    for tri_idx in tri_indices:
                        if tri_idx == -1:
                            break
                        
                        # Get 3 edge indices for this triangle
                        e1 = tri_indices[0]
                        e2 = tri_indices[1]
                        e3 = tri_indices[2]
                        
                        # Interpolate points on edges
                        p1 = interpolate_edge(corners, positions, e1, iso_value)
                        p2 = interpolate_edge(corners, positions, e2, iso_value)
                        p3 = interpolate_edge(corners, positions, e3, iso_value)
                        
                        triangle_list.append(Triangle(p1, p2, p3))
        
        all_triangle_lists[iso_value] = triangle_list
        
    return all_triangle_lists

def interpolate_edge(corners, positions, edge_idx, iso_value):
    """
    Interpolates the intersection point on a specific edge.
    Edge indices are defined by the Marching Cubes lookup table.
    """
    # Map edge index to the two corner indices it connects
    # This mapping is specific to the MC convention (e.g., edge 0 connects corner 0 and 1)
    # Standard MC edge mapping:
    edge_map = [
        (0, 1), (1, 2), (2, 3), (3, 0), # Bottom face
        (4, 5), (5, 6), (6, 7), (7, 4), # Top face
        (0, 4), (1, 5), (2, 6), (3, 7)  # Vertical edges
    ]
    
    c1_idx, c2_idx = edge_map[edge_idx]
    v1 = corners[c1_idx]
    v2 = corners[c2_idx]
    p1 = positions[c1_idx]
    p2 = positions[c2_idx]
    
    # Linear interpolation
    # t = (iso - v1) / (v2 - v1)
    denom = v2 - v1
    if denom == 0:
        # Avoid division by zero; return midpoint if values are equal
        t = 0.5
    else:
        t = (iso_value - v1) / denom
        
    # Interpolate position
    x = p1[0] + t * (p2[0] - p1[0])
    y = p1[1] + t * (p2[1] - p1[1])
    z = p1[2] + t * (p2[2] - p1[2])
    
    return (x, y, z)
```

## Subtopics

### [Multi-Isosurface Visualization](1240-multi-isosurface-visualization.md)
Multi-Isosurface Visualization is the rendering phase that recombines multiple extracted isosurface segments into a single scene for display. It solves the problem of correctly blending several isosurfaces, each potentially having different opacities, by processing corresponding planes across all layers concurrently. It sets itself apart from single-isosurface methods by maintaining a separate Matryoshka layer per isosurface and using a unified auxiliary buffer to enforce global front-to-back ordering across all structures.

### Multi-Resolution Extraction
A scheme where selected isosurfaces are rendered at high resolution (original voxel grid) while others are rendered at lower resolutions by skipping voxels during extraction [S1, unofficial]. For low-resolution isosurfaces, set the iteration step `inc` to a value greater than 1 (e.g., 2, 4, etc.) to skip voxels, effectively reducing the grid density [S1, unofficial]. The parameter `inc` controls resolution; `inc=1` is full resolution, and `inc>1` reduces resolution by processing every `inc`-th voxel [S1, unofficial].

## Operating characteristics
**Time Complexity:** $O(N \cdot M)$, where $N$ is the number of voxels in the volume and $M$ is the number of isovales. Each isovalue requires a full pass (or reduced pass) over the volume.
**Memory Complexity:** $O(T \cdot M)$, where $T$ is the average number of triangles per isosurface. Separate lists are maintained for each isovalue.
**Measured Performance:** In a reference implementation [S1, unofficial], loading a dataset took ~0.15-0.18 seconds. Creating the triangle lists for 6 isovales took ~0.027 seconds. Display times varied per isovalue, ranging from ~0.001 to ~0.005 seconds per frame, with total display time scaling with the number of isovales and complexity of surfaces.
**Strengths:** Allows simultaneous visualization of distinct features (e.g., bone and soft tissue in medical imaging) without multiple volume rendering passes.
**Limitations:** Managing multiple triangle lists increases memory usage. Rendering multiple surfaces with correct transparency blending requires careful handling of depth buffers and sorting.
**When to use:** When distinct structural components in a scalar field correspond to different intensity ranges and need to be visualized together.
**When not to use:** When the number of isovales is very large, leading to excessive memory and rendering overhead.

## Background
Originating from academic projects on data visualization, this method extends the classic Marching Cubes algorithm [10327-lookup-table-and-ambiguity-handling] to handle multiple thresholds. It is commonly used in medical imaging and scientific visualization to display different tissue types or material phases simultaneously. The specific implementation details and performance metrics cited here come from an unofficial student project repository [S1, unofficial].
