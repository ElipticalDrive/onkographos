# Multi-Isosurface Visualization

Also called: Multi-surface-structure Visualization

## Overview
Multi-Isosurface Visualization is the rendering phase that recombines multiple extracted isosurface segments into a single scene for display [S1, unofficial]. It solves the problem of correctly blending several isosurfaces, each potentially having different opacities, by processing corresponding planes across all layers concurrently [S2, unofficial]. It sets itself apart from single-isosurface methods by maintaining a separate Matryoshka layer per isosurface and using a unified auxiliary buffer to enforce global front-to-back ordering across all structures [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of isosurface layers, where each layer contains surface structures extracted from a specific isovalue. Each layer is associated with a specific opacity value [S2, unofficial].
*   **Outputs:** A composite image where all isosurfaces are rendered with correct depth ordering and opacity blending [S1, S2, unofficial].

**Data Structures:**
*   **Matryoshka Layers:** One layer per isosurface. All layers share the same set of corresponding planes for concurrent processing, but each maintains its own active cells [S2, unofficial].
*   **Auxiliary Buffer:** A single 2D buffer matching the screen resolution, used to mark cells as "drawable" across all layers simultaneously [S2, unofficial].

**Steps:**
1.  **Recombination:** Recombine surface structures extracted from different isosurfaces into a single scene [S1, unofficial].
2.  **Plane Synchronization:** Identify the set of corresponding planes for all isosurfaces. These planes are processed concurrently [S2, unofficial].
3.  **Marking Drawability:** For the current set of corresponding planes, mark all active cells from all layers as drawable in the single auxiliary buffer [S2, unofficial].
4.  **Ordered Processing:** Process the auxiliary buffer following an order dependent on the viewing camera to ensure correct front-to-back ordering across all isosurfaces and within each layer [S2, unofficial].

**Pseudocode:**
```python
def dot(v1, v2):
    return sum(a * b for a, b in zip(v1, v2))

def screen_to_world(x, y, camera, plane_z):
    # Standard inverse projection [G]
    nx = (2.0 * x / camera['screen_res'][0] - 1.0)
    ny = (2.0 * y / camera['screen_res'][1] - 1.0)
    return [nx, ny, plane_z]

def world_to_screen(pos, camera):
    # Standard projection [G]
    x = int((pos[0] + 1.0) * camera['screen_res'][0] / 2.0)
    y = int((pos[1] + 1.0) * camera['screen_res'][1] / 2.0)
    return x, y

def render_multi_isosurface(layers, camera, volume_bounds, step_size):
    w, h = camera['screen_res']
    aux_buffer = [[False] * w for _ in range(h)]
    image = [[0.0, 0.0, 0.0, 0.0] for _ in range(w * h)]
    cam_dir = camera['direction']
    cam_origin = camera['origin']
    cam_dir_norm = [d / max(1e-8, max(abs(d) for d in cam_dir)) for d in cam_dir]

    # 1. Identify corresponding planes across all layers
    plane_indices = sorted(set(p for layer in layers for p in layer['cells'].keys()))

    for p in plane_indices:
        # 2. Mark all active cells from all layers as drawable in auxiliary buffer
        for layer in layers:
            for cell in layer['cells'].get(p, []):
                x, y = cell['screen_x'], cell['screen_y']
                if 0 <= x < w and 0 <= y < h:
                    aux_buffer[y][x] = True

        # 3. Compute front-to-back render order for marked cells based on camera
        render_order = []
        for y in range(h):
            for x in range(w):
                if aux_buffer[y][x]:
                    pos_3d = screen_to_world(x, y, camera, p)
                    # Depth along ray direction [G]
                    depth = dot([pos_3d[i] - cam_origin[i] for i in range(3)], cam_dir_norm)
                    render_order.append((x, y, depth))
        render_order.sort(key=lambda item: item[2])

        # 4. Ray march and blend for each marked cell
        for cx, cy, _ in render_order:
            ray_origin = camera['origin']
            ray_dir = cam_dir_norm
            accumulated_color = [0.0, 0.0, 0.0, 0.0]
            t = 0.0
            while t < volume_bounds['max_dist']:
                pos = [ray_origin[i] + ray_dir[i] * t for i in range(3)]
                cell_x, cell_y = world_to_screen(pos, camera)
                if cell_x == cx and cell_y == cy:
                    for layer in layers:
                        if any(c['screen_x'] == cx and c['screen_y'] == cy for c in layer['cells'].get(p, [])):
                            new_color = layer['cells'][p][0]['color'] # Cell color from extracted structure [G]
                            new_alpha = layer['opacity']
                            alpha_factor = new_alpha * (1.0 - accumulated_color[3])
                            accumulated_color[0] += new_color[0] * alpha_factor
                            accumulated_color[1] += new_color[1] * alpha_factor
                            accumulated_color[2] += new_color[2] * alpha_factor
                            accumulated_color[3] += alpha_factor
                    break
                t += step_size
            image[cy * w + cx] = accumulated_color
        # Clear buffer for next plane
        for y in range(h):
            for x in range(w):
                aux_buffer[y][x] = False
    return image
```

**Parameters:**
*   **Opacity:** Each isosurface layer has an associated opacity value. Typical value: 100% (fully opaque) [S2, unofficial].
*   **Screen Resolution:** Tests were conducted at 512×512 [S2, unofficial].

## Subtopics

### Isosurface Segmentation
A technique to extract specific structures from isosurfaces using seed voxels and selection-based coloring [S1, unofficial]. It sets itself apart by allowing intuitive user-driven extraction [S1, unofficial]. Choose it when you need to isolate specific anatomical or physical structures [S1, unofficial].

### Matryoshka Algorithm
A speed-up technique for isosurfacing using layered plane processing [S2, unofficial]. It sets itself apart by reusing plane computations [S2, unofficial]. Choose it for performance-critical isosurface extraction [S2, unofficial].

## Background
Multi-Isosurface Visualization recombines surface structures extracted from different isosurfaces into a single scene for display [S1, unofficial]. It utilizes the Matryoshka Algorithm's layered plane processing to render multiple isosurfaces concurrently with correct front-to-back ordering [S2, unofficial]. The technique allows for the intuitive extraction of structures via user-selected seed voxels and their subsequent recombination into a single scene [S1, unofficial].
