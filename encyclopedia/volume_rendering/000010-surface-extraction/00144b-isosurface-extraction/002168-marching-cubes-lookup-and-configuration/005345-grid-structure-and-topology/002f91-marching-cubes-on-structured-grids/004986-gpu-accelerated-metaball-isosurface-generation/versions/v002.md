# GPU-Accelerated Metaball Isosurface Generation

Also called: Transform-Feedback Metaballs, Two-stage GPU Metaballs

## Overview
This method generates an isosurface from a combined field of metaballs using a two-stage GPU pipeline, utilizing vertex shaders for field evaluation and geometry shaders for mesh generation [S1, unofficial]. It is distinguished from standard CPU-based or single-pass GPU implementations by its explicit separation of field computation and mesh topology generation, coupled with Transform-Feedback caching to avoid recomputing geometry when the camera moves but the metaball configuration remains static [S1, unofficial]. It builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by offloading the structured grid vertex evaluation and cube processing to the GPU [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of metaball parameters (position, radius, color, negative flag, superquadratic flag, and optional scale/exponents/rotation for superquadratic types); a grid resolution (e.g., $64 \times 64 \times 64$) [S1, unofficial].
*   **Outputs:** A vertex array buffer containing the generated triangle mesh [S1, unofficial].

**Data Structures:**
*   **Metaball Parameters:** Each metaball is defined by:
    *   Position (3D vector)
    *   Radius ($r_0$)
    *   Color
    *   Negative flag (boolean: emits negative field) [S1, unofficial].
    *   Superquadratic flag (boolean) [S1, unofficial].
    *   If superquadratic: Scale factors along X, Y, Z axes; X, Y, Z exponents; Rotation matrix (specifies orientation of Z axis) [S1, unofficial].
*   **Grid Vertices:** A 3D grid of vertices. Each vertex stores:
    *   Combined field effect value
    *   Surface normal direction
    *   Color [S1, unofficial].

**Field Evaluation Formulas:**
The combined field value $F(\mathbf{x})$ at a point $\mathbf{x}$ is the sum of contributions from all metaballs [S1, unofficial]. For a single metaball, the contribution $f(r)$ depends on the type:

1.  **Regular Quadratic Metaball:** Uses the Wyvill polynomial [66] in [S1, unofficial]:
    $$ f(r) = 1 - 3\left(\frac{r}{r_0}\right)^2 + 2\left(\frac{r}{r_0}\right)^3 $$
    where $r$ is the distance from $\mathbf{x}$ to the metaball's center, and $r_0$ is the metaball's radius [S1, unofficial].
2.  **Superquadratic Metaball:** Uses the function [67] in [S1, unofficial]:
    $$ f(r) = 1 - \left(\frac{r}{r_0}\right)^{n_1} - \left(\frac{r}{r_0}\right)^{n_2} $$
    where $r$ is the distance to the center, $r_0$ is the size, and $n_1, n_2$ are exponents defining the shape [S1, unofficial]. For superquadratic metaballs, $r$ is computed in the metaball's local space after applying scale factors and rotation [S1, unofficial].

**Numbered Steps:**

1.  **Stage 1: Field Evaluation (Vertex Shader)**
    1.  Generate a grid of user-specified dimensions and resolution (e.g., $64 \times 64 \times 64$) [S1, unofficial].
    2.  Execute OpenGL vertex shader programs in parallel, with each shader processing a single vertex in the grid [S1, unofficial].
    3.  For each vertex, evaluate all specified metaballs to calculate the combined field effect value, surface normal direction, and color [S1, unofficial].
    4.  Write these results into a separate array (vertex buffer) for the next stage [S1, unofficial].
2.  **Stage 2: Mesh Generation (Geometry Shader)**
    1.  Each shader program handles a cube composed of 8 previously computed vertices and their attributes [S1, unofficial].
    2.  Determine if the cube is intersected by the isosurface (using Marching Cubes logic on the field values) [S1, unofficial].
    3.  If intersected, emit appropriate triangles via the OpenGL geometry shader [S1, unofficial].
    4.  For every emitted triangle, interpolate normal and vertex color values using the information calculated in Stage 1 [S1, unofficial].
3.  **Caching (Transform-Feedback)**
    1.  Capture the geometry generated by the two-stage approach in a dynamically allocated vertex array buffer using Transform-Feedback [S1, unofficial].
    2.  Reuse this vertex array for rendering without recalculating geometry if the metaball configuration has not changed (e.g., during camera rotation or zoom) [S1, unofficial].

**Pseudocode:**
```python
import math

# Constants
ISOSURFACE_THRESHOLD = 0.5  # Standard threshold between field peak (1.0) and falloff (0.0)
GRID_RESOLUTION = 64
GRID_SIZE = 10.0  # World units, assumed for grid generation

def compute_local_r(pos_world, ball):
    """Transform world position to metaball local space and compute distance."""
    local_pos = pos_world - ball.position
    # Apply inverse rotation (simplified as identity for axis-aligned)
    # Apply inverse scale
    local_pos = vec3(local_pos.x / ball.scale_x, local_pos.y / ball.scale_y, local_pos.z / ball.scale_z)
    return length(local_pos)

def evaluate_metaball_field(vertex_pos, metaballs):
    """Evaluate combined field, normal, and color for a vertex."""
    combined_field = 0.0
    normal = vec3(0.0, 0.0, 0.0)
    color = vec3(0.0, 0.0, 0.0)
    for ball in metaballs:
        r = compute_local_r(vertex_pos, ball)
        ratio = r / ball.radius
        if ball.is_superquadratic:
            contribution = 1.0 - ratio**ball.n1 - ratio**ball.n2
        else:
            contribution = 1.0 - 3.0 * ratio**2 + 2.0 * ratio**3
        if ball.negative:
            contribution = -contribution
        combined_field += contribution
        color += ball.color * contribution
        # [G] Analytical gradient for normal calculation
        df_dr = -6.0 * ratio + 6.0 * ratio**2 if not ball.is_superquadratic else -ball.n1 * ratio**(ball.n1-1) - ball.n2 * ratio**(ball.n2-1)
        grad_dir = normalize(vertex_pos - ball.position)
        normal += ball.color * df_dr * grad_dir
    normal = normalize(normal)
    return combined_field, normal, color

def generate_grid_vertices(metaballs):
    """Stage 1: Evaluate field for all grid vertices."""
    vertices = []
    step = GRID_SIZE / GRID_RESOLUTION
    for z in range(GRID_RESOLUTION + 1):
        for y in range(GRID_RESOLUTION + 1):
            for x in range(GRID_RESOLUTION + 1):
                pos = vec3(x * step, y * step, z * step)
                field_val, normal, color = evaluate_metaball_field(pos, metaballs)
                vertices.append({'pos': pos, 'field': field_val, 'normal': normal, 'color': color})
    return vertices

def get_cube_vertex_indices(cube_idx, grid_res):
    """Map cube index to 8 vertex indices in the grid."""
    cx, cy, cz = cube_idx // (grid_res**2), (cube_idx // grid_res) % grid_res, cube_idx % grid_res
    offsets = [0, 1, grid_res+1, grid_res+2, (grid_res+1)**2, (grid_res+1)**2+1, (grid_res+1)**2+grid_res+1, (grid_res+1)**2+grid_res+2]
    base = cx + cy * (grid_res+1) + cz * (grid_res+1)**2
    return [base + off for off in offsets]

def marching_cubes_lookup(field_vals):
    """Standard Marching Cubes case index generation."""
    case = 0
    for i in range(8):
        if field_vals[i] >= ISOSURFACE_THRESHOLD:
            case |= (1 << i)
    return case

def generate_triangles_from_case(case, cube_verts):
    """Generate triangles for a given MC case using standard edge table."""
    # [G] Standard MC edge table and vertex interpolation
    edges = [
        (0,1), (1,2), (2,3), (3,0), (4,5), (5,6), (6,7), (7,4),
        (0,4), (1,5), (2,6), (3,7)
    ]
    # Standard triangle list for all 256 cases (simplified for brevity, full table omitted)
    # In practice, a lookup table maps case -> list of edge pairs.
    # Here we implement a minimal valid case (case 1) to demonstrate structure.
    triangles = []
    if case == 1: # Example case
        # Interpolate vertices on edges
        def interp(v1, v2):
            t = (ISOSURFACE_THRESHOLD - v1['field']) / (v2['field'] - v1['field'])
            return vec3(v1['pos'] + t*(v2['pos']-v1['pos']), v1['normal'] + t*(v2['normal']-v1['normal']), v1['color'] + t*(v2['color']-v1['color']))
        # Edge 0-1
        p0 = interp(cube_verts[0], cube_verts[1])
        p1 = interp(cube_verts[3], cube_verts[0])
        p2 = interp(cube_verts[0], cube_verts[4])
        triangles.append([p0, p1, p2])
    return triangles

def stage1(metaballs):
    """Execute Stage 1 and return vertex buffer."""
    return generate_grid_vertices(metaballs)

def stage2(grid_vertices, grid_res):
    """Execute Stage 2 and return triangle mesh."""
    triangles = []
    num_cubes = grid_res * grid_res * grid_res
    for i in range(num_cubes):
        v_indices = get_cube_vertex_indices(i, grid_res)
        cube_verts = [grid_vertices[idx] for idx in v_indices]
        field_vals = [v['field'] for v in cube_verts]
        case = marching_cubes_lookup(field_vals)
        if case != 0:
            tri_list = generate_triangles_from_case(case, cube_verts)
            triangles.extend(tri_list)
    return triangles

def transform_feedback_cache(triangles):
    """Capture geometry in vertex array buffer for reuse."""
    # [G] OpenGL Transform-Feedback binding and draw call
    return triangles # In practice, stored in GPU VBO
```

**Parameters:**
*   Grid resolution: $64 \times 64 \times 64$ voxels was used in the source implementation [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Recomputation:** Recomputing the isosurface for every frame during camera rotation or zoom is wasteful [S1, unofficial]. Solution: Use Transform-Feedback to cache the geometry [S1, unofficial].
*   **Noise in Normals:** For superquadratic metaballs, the 2D buffer or map containing normal values can be noisy, leading to abrupt changes in orientation [S1, unofficial]. Solution: Use a 5-step isosurface refinement routine (subdividing ray stepping size) and apply a Gaussian blurring kernel to the normal map [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** The two-stage approach leverages the massively parallel architecture of modern GPUs for optimum performance [S1, unofficial].
*   **Strengths:** Interactive frame-rates for metaball rendering; efficient caching for static scenes [S1, unofficial].
*   **Limitations:** Requires GPU support for Transform-Feedback and Geometry Shaders; noise in normals for superquadratic metaballs requires additional processing [S1, unofficial].

## Background
This method was implemented as part of a thesis on context-preserving volume image exploration using a 3D painting metaphor [S1, unofficial]. It was designed to provide interactive frame-rates for metaball-based volumetric objects, particularly for surface painting and peeling operations [S1, unofficial]. The approach builds on the Marching Cubes algorithm and utilizes OpenGL's vertex and geometry shaders [S1, unofficial].
