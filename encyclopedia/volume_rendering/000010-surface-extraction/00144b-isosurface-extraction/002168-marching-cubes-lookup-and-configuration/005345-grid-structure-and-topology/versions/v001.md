# Grid Structure and Topology


## Overview
This family defines the geometric and topological data structures used to represent the scalar field domain for isosurface extraction. It solves the problem of mapping discrete volumetric data to a continuous mesh by establishing how grid vertices, cells, and boundaries are organized. It sets itself apart from sibling methods by focusing on the underlying grid topology (structured, dual, or hierarchical) rather than the specific triangulation rules or ambiguity resolution strategies.

## Shared principles
The family relies on two precomputed data structures derived from the 256 possible binary configurations of a voxel's eight corner signs relative to an isovalue [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md).

1.  **Edge Intersection Table (`edgeTable`)**: An array of 256 integers (or shorts). Each entry is a 12-bit bitmask. Bit $k$ ($0 \le k \le 11$) is set to 1 if the isosurface intersects the $k$-th edge of the cube, and 0 otherwise. The standard edge numbering convention is:
    *   Bottom face ($z=0$): $e_0=(0,1), e_1=(1,2), e_2=(2,3), e_3=(3,0)$
    *   Top face ($z=1$): $e_4=(4,5), e_5=(5,6), e_6=(6,7), e_7=(7,4)$
    *   Vertical edges: $e_8=(0,4), e_9=(1,5), e_{10}=(2,6), e_{11}=(3,7)$ [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md)

2.  **Triangle Connection Table (`triangleTable`)**: A 2D array of size $256 \times 16$.
    *   Rows are indexed by the case index $C \in [0, 255]$.
    *   Columns store integer indices. Indices $0–11$ refer to the 12 cube edges.
    *   Indices are grouped in triplets $(a, b, c)$ to form triangles.
    *   The sequence is terminated by the value `-1`.
    *   The maximum number of triangles per voxel is 5, requiring 15 indices plus 1 terminator [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md)

**Case Index Calculation**: For each voxel, the 8-bit case index $C$ is determined by the scalar field values $V$ at the 8 vertices $v_i$ ($i=0..7$). If $V(v_i) < I$ (or $> I$, depending on convention), bit $i$ of $C$ is set to 1; otherwise 0. The bit assignment must strictly match the vertex ordering assumed by the LUT generation [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md).

**Ambiguity**: Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous (the isosurface passes through the cube center). The standard LUT uses a fixed triangulation for these, which can cause cracks or holes if adjacent voxels resolve the ambiguity differently [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md).

**Pseudocode**:
```python
def compute_case_index(values, isovalue):
    case_index = 0
    for i in range(8):
        if values[i] < isovalue:
            case_index |= (1 << i)
    return case_index

def extract_triangles(case_index, edge_table, triangle_table, edge_intersections):
    triangles = []
    edge_mask = edge_table[case_index]
    tri_indices = triangle_table[case_index]
    for i in range(0, len(tri_indices), 3):
        if tri_indices[i] == -1:
            break
        e1, e2, e3 = tri_indices[i], tri_indices[i+1], tri_indices[i+2]
        p1 = edge_intersections[e1]
        p2 = edge_intersections[e2]
        p3 = edge_intersections[e3]
        triangles.append((p1, p2, p3))
    return triangles
```

## Subtopics

### [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md)
Extracts a 3D polygonal mesh from a discretized scalar field defined on a regular Cartesian grid. It sets itself apart by operating directly on the structured IJK grid topology using a fixed lookup table for cell triangulation, whereas methods like [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md) optimize vertex positions for accuracy, and [Marching Tetrahedra and Decomposition](11174-marching-tetrahedra-and-decomposition.md) decompose cells to resolve topological ambiguities.

### [Dual Grid Isosurface Extraction](10271-dual-grid-isosurface-extraction.md)
Extracts crack-free isosurfaces from Adaptive Mesh Refinement (AMR) data by constructing a dual grid where cell centers serve as vertices. It solves the "dangling node" problem inherent in standard Marching Cubes when applied to resampled vertex-centered AMR data, where mismatched interpolation at coarse-fine boundaries causes topological discontinuities. Unlike sibling methods that fix cracks by post-processing polygons or collapsing polylines, this approach eliminates dangling nodes structurally by leveraging the geometric gap between coarse and fine dual grids.

#### Octree for Marching Cubes
The 3D analogous structure of a quadtree, partitioning a 3D space region into eight subregions (octants) [S1]. The tree is built directly from the volume data. For non-regular grids (dimensions not power of two), subregions have different sizes as they partition cell regions [S1].
