# Grid Structure and Topology

## Overview
This family defines the geometric and topological data structures used to represent the scalar field domain for isosurface extraction [G]. It solves the problem of mapping discrete volumetric data to a continuous mesh by establishing how grid vertices, cells, and boundaries are organized [G]. It sets itself apart from sibling methods by focusing on the underlying grid topology (structured, dual, or hierarchical) rather than the specific triangulation rules or ambiguity resolution strategies [G].

## Shared principles
Builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) for the precomputed lookup tables, case index calculation, and ambiguity handling [G]. The family relies on a consistent vertex ordering and edge indexing scheme to map discrete scalar values to continuous surface geometry [G].

**Pseudocode**:
```python
def compute_case_index(values, isovalue):
    case_index = 0
    for i in range(8):
        if values[i] < isovalue:
            case_index |= (1 << i)
    return case_index

def interpolate_edge_intersection(v1, v2, p1, p2, isovalue):
    if abs(v2 - v1) < 1e-8:
        return (p1 + p2) / 2.0
    t = (isovalue - v1) / (v2 - v1)
    return p1 + t * (p2 - p1)

def extract_triangles(case_index, triangle_table, edge_intersections):
    triangles = []
    tri_indices = triangle_table[case_index]
    for i in range(16):
        if tri_indices[i] == -1:
            break
        e1 = tri_indices[i]
        e2 = tri_indices[i+1]
        e3 = tri_indices[i+2]
        p1 = edge_intersections[e1]
        p2 = edge_intersections[e2]
        p3 = edge_intersections[e3]
        triangles.append((p1, p2, p3))
    return triangles
# Note: edge_intersections must be precomputed by interpolating field values along the 12 cube edges [G].
```

## Subtopics

### [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md)
Extracts a 3D triangular mesh from a scalar field defined on a regular 3D grid by evaluating the field at grid vertices, determining intersection cases, and interpolating edge crossings. It sets itself apart from siblings by operating directly on the grid vertices rather than cell centers, making it the standard approach for implicit volumes, neural fields, and medical imaging data. Choose it when a regular Cartesian grid is available.

### [Dual Grid Isosurface Extraction](10271-dual-grid-isosurface-extraction.md)
Extracts crack-free isosurfaces from Adaptive Mesh Refinement (AMR) data by treating cell centers as vertices of a new grid. It sets itself apart by leveraging the natural gap between coarse and fine grid levels in the dual representation to prevent dangling nodes, rather than using post-processing fixes or polygon collapsing. Choose it when working with AMR datasets to ensure manifold continuity across refinement levels.

### [Dual-Grid Non-Manifold Contouring](14936-dual-grid-non-manifold-contouring.md)
Extracts non-manifold meshes from segmented volumes containing multiple materials by utilizing a dual grid structure where material attributes are associated with voxel centers rather than cell corners. It sets itself apart by avoiding large lookup tables entirely, generating quadrilateral faces at voxel boundaries and resolving topological ambiguities through a priority-based vertex splitting mechanism. Choose it for multi-material segmentation where non-manifold connectivity is required.

### [Hypertree Grid Isocontouring](18933-hypertree-grid-isocontouring.md)
Uses a hypertree data structure to represent the grid topology, allowing for efficient traversal and isosurface extraction on hierarchical data. It sets itself apart by optimizing memory access patterns for hierarchical datasets. Choose it when memory efficiency and adaptive traversal are critical for large-scale volumetric datasets.

### [Batched Marching Cubes](19943-batched-marching-cubes.md)
Processes multiple voxels or grid regions in parallel batches to optimize memory access patterns and throughput on modern hardware. It sets itself apart by grouping voxel processing to improve cache locality and parallel execution. Choose it for high-performance rendering pipelines where latency and throughput are prioritized over per-voxel precision.

### [Sparse and Hierarchical Grid Methods](21072-sparse-and-hierarchical-grid-methods.md)
Adapts the grid structure to store only non-empty or active regions, reducing memory footprint and computation time for sparse volumetric data. It sets itself apart by dynamically allocating grid cells based on data density. Choose it when the scalar field is highly sparse or when dynamic grid updates are necessary.

### [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md)
Maps the grid traversal and triangle generation steps to GPU parallel execution models, leveraging shared memory and coalesced memory access. It sets itself apart by offloading the entire extraction pipeline to the graphics processor. Choose it for real-time applications requiring massive parallelism and low CPU overhead.

### [Surface-following Marching Cubes with Blocking](8966-surface-following-marching-cubes-with-blocking.md)
Optimizes traversal by following the surface across grid cells, reducing the number of empty voxels processed. It sets itself apart by skipping large volumes of empty space through surface-aware culling. Choose it when the isosurface is localized or when processing large volumes with significant empty space.

### [Real-time particle isosurface extraction](10275-real-time-particle-isosurface-extraction.md)
Adapts the grid structure to handle particle-based scalar fields, often using kernel density estimation on a grid. It sets itself apart by converting discrete particle data into a continuous grid representation on-the-fly. Choose it for fluid dynamics or particle simulations where the scalar field is derived from discrete particles.

### [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md)
Focuses on the generation and modification of the `edgeTable` and `triangleTable` to resolve topological ambiguities and ensure manifold output. It sets itself apart by providing alternative triangulation strategies for ambiguous cases like saddle points. Choose it when standard LUTs produce cracks or non-manifold artifacts in ambiguous cases.

### [Algorithmic Modifications and Improvements](11203-algorithmic-modifications-and-improvements.md)
Covers enhancements to the base grid topology processing, such as adaptive grid refinement and error minimization. It sets itself apart by integrating geometric error bounds into the extraction process. Choose it when higher geometric accuracy or adaptive resolution is required.

### [Fiber Surface Extraction](14192-fiber-surface-extraction.md)
Modifies the grid topology to extract tubular structures, often using a directional grid or anisotropic interpolation. It sets itself apart by aligning the grid cells with fiber orientations to preserve anisotropic features. Choose it for diffusion tensor imaging or fiber tractography where anisotropy is dominant.

### [Mesh Post-processing and Simplification](14742-mesh-post-processing-and-simplification.md)
Applies topological simplification and cleaning to the extracted mesh, often adjusting vertex positions on the grid structure. It sets itself apart by decoupling mesh optimization from the extraction step. Choose it when reducing polygon count or fixing minor topological defects is necessary.

### [Analytical Error Approximation for Edge-Crossing](15100-analytical-error-approximation-for-edge-crossing.md)
Refines the edge intersection calculation using analytical error bounds to improve geometric accuracy on the grid. It sets itself apart by replacing linear interpolation with higher-order approximations where error exceeds a threshold. Choose it when sub-voxel precision is critical for the application.

### Octree for Marching Cubes
The 3D analogous structure of a quadtree, partitioning a 3D space region into eight subregions (octants) [S1]. It sets itself apart by building the tree directly from the volume data, allowing subregions to have different sizes for non-regular grids where dimensions are not powers of two [S1]. Choose it when hierarchical spatial partitioning is required for adaptive volume traversal.
