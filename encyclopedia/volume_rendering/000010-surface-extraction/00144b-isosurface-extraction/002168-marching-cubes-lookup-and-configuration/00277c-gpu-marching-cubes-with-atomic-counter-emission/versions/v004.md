# GPU Marching Cubes with Atomic Counter Emission

Also called: atomic-counter MC, indirect-draw MC, r=mesh

## Overview
This method is a real-time GPU-based isosurface extraction technique that generates a mesh from a scalar density field by dispatching one compute thread per grid cell [S1, unofficial]. It distinguishes itself from sibling methods by avoiding prefix sums or histogram pyramids for output management; instead, it reserves vertex slots via atomic addition directly on indirect draw arguments and renders the result using `drawIndirect` with vertex pulling [S1, unofficial]. This approach minimizes synchronization overhead and CPU-GPU readback, making it suitable for real-time applications like fluid simulation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tent-blurred density grid (scalar field) and an isosurface threshold parameter (`?iso=`) [S1, unofficial].
*   **Output:** A triangle mesh rendered via `drawIndirect`, depth-tested against a raytraced background [S1, unofficial].

**Data Structures:**
1.  **Indirect Draw Arguments Buffer:** A buffer containing standard `drawIndirect` parameters (vertex count, instance count, first vertex, first instance) plus an overflow flag [S1, unofficial].
    *   Layout: Words 0-3 contain standard draw arguments. Word 4 contains the overflow flag [S1, unofficial].
    *   Note: The overflow flag is placed in word 4, not `firstInstance` (word 3), because a non-zero `firstInstance` no-ops the indirect draw without the `indirect-first-instance` feature [S1, unofficial].
2.  **Vertex Pool:** A pre-allocated buffer storing vertex positions and gradient normals [S1, unofficial].
    *   Size: 1.5 million vertices (48 MB) [S1, unofficial].
    *   Access: Vertex pulling (shader samples positions/normals from this buffer during rendering) [S1, unofficial].
3.  **MC Triangle Table:** Generated at load time rather than hardcoded [S1, unofficial].
    *   Generation: Marching squares per cube face $\rightarrow$ closed loops $\rightarrow$ fan triangulation [S1, unofficial].
    *   Properties: Rotation-invariant ambiguity rule, crack-free by construction, validated against all 256 cases [S1, unofficial].

**Algorithm Steps:**

1.  **Dispatch:** Launch one compute thread per grid cell [S1, unofficial].
2.  **Boundary Check:** If the thread's voxel coordinates are out of range, treat the sample as density 0 to cap the isosurface against the walls [S1, unofficial]. Specifically, lattice index 0 is treated as outside density [S1, unofficial]. Blur bleed outside the walls (cells $2 \dots \text{GRID}-2$) is discarded [S1, unofficial].
3.  **Classification:** Sample the 8 corners of the current voxel from the tent-blurred density grid [S1, unofficial]. Compare each corner density against the `?iso=` threshold to determine the 256-case index [S1, unofficial].
4.  **Lookup:** Use the case index to look up the pre-generated triangle table to determine which edges are cut [S1, unofficial].
5.  **Slot Reservation:** Perform an `atomicAdd` on the vertex count field within the Indirect Draw Arguments Buffer to reserve slots for the new vertices [S1, unofficial]. This returns the base index for writing vertices [S1, unofficial].
6.  **Vertex Emission:** For each cut edge defined by the triangle table:
    *   Compute the interpolated vertex position using trilinear interpolation [S1, unofficial].
    *   Compute the gradient normal at the vertex [S1, unofficial].
    *   Write the position and normal into the Vertex Pool at the reserved index [S1, unofficial].
    *   Optimization: Cache interpolated position + normal per unique cut edge to avoid recomputation per triangle corner [S1, unofficial].
7.  **Finalization:** Run a separate finalize kernel with one thread [S1, unofficial].
    *   Clamp the vertex count in the Indirect Draw Arguments Buffer to the pool cap (1.5M) [S1, unofficial].
    *   If the pre-clamp count exceeded the cap, raise the overflow flag in word 4 [S1, unofficial].
    *   This ensures only whole triangles are drawn and prevents garbage rendering [S1, unofficial].
8.  **Rendering:** Issue a `drawIndirect` call using the updated arguments [S1, unofficial].
    *   The mesh is depth-tested against the raytraced scene background in the same pass [S1, unofficial].
    *   Shading: Fresnel reflection over the analytic scene along one refracted ray [S1, unofficial].
    *   Absorption: Beer-Lambert law using 6 interior density taps [S1, unofficial].
    *   Effects: Momentum foam effects are added [S1, unofficial].

**Pseudocode:**

```python
# Compute Shader: One thread per voxel
fn compute_mesh(voxel_coord: vec3<u32>) {
    // 1. Boundary and Density Check
    // If out of range, density is 0 (caps surface against walls)
    let densities = vec3<f32>[8];
    for i in 0..8 {
        let corner = get_corner_coord(voxel_coord, i);
        if (corner.x < 0 || corner.x >= GRID_SIZE ||
            corner.y < 0 || corner.y >= GRID_SIZE ||
            corner.z < 0 || corner.z >= GRID_SIZE) {
            densities[i] = 0.0;
        } else {
            densities[i] = sample_density(corner);
        }
    }

    // 2. Classification
    let case_index = 0;
    for i in 0..8 {
        if (densities[i] > ISO_THRESHOLD) {
            case_index |= (1u << i);
        }
    }

    // 3. Lookup and Emission
    let triangles = get_triangles_from_table(case_index);
    let num_triangles = length(triangles);
    let num_vertices = num_triangles * 3;

    // 4. Reserve Slots via Atomic Add on Indirect Draw Args
    // The vertex count is stored in indirect_args[0]
    let base_index = atomicAdd(&indirect_args[0], num_vertices);

    // 5. Write Vertices to Pool
    for t in 0..num_triangles {
        let tri = triangles[t];
        for e in 0..3 {
            let edge_idx = tri[e];
            let vert_idx = base_index + (t * 3) + e;
            
            // Interpolate position and gradient normal
            let pos = interpolate_edge_position(voxel_coord, edge_idx);
            let normal = compute_gradient_normal(voxel_coord, edge_idx);
            
            // Write to vertex pool
            vertex_pool[vert_idx].position = pos;
            vertex_pool[vert_idx].normal = normal;
        }
    }
}

// Finalize Kernel: One thread
fn finalize_mesh() {
    let current_count = indirect_args[0];
    let cap = 1500000; // 1.5M vertex cap
    
    if (current_count > cap) {
        // Clamp count to cap
        indirect_args[0] = cap;
        // Raise overflow flag in word 4
        indirect_args[4] = 1;
    } else {
        indirect_args[4] = 0;
    }
}
```

**Parameters:**
*   **Vertex Pool Size:** 1.5 million vertices [S1, unofficial].
*   **Isosurface Threshold:** Controlled by the `?iso=` parameter [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Overflow:** If the generated vertex count exceeds the 1.5M cap, the finalize kernel clamps the count and sets an overflow flag. This prevents rendering garbage data [S1, unofficial].
*   **Wall Capping:** Lattice index 0 is treated as outside density to ensure the isosurface is capped on all six walls [S1, unofficial].
*   **First Instance:** The overflow flag is stored in `indirect_args[4]`, not `firstInstance`, to avoid no-oping the draw call on hardware lacking `indirect-first-instance` support [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed by one thread [S1, unofficial].
*   **Memory Complexity:** Dominated by the Vertex Pool (48 MB for 1.5M vertices) and the Indirect Draw Arguments buffer [S1, unofficial].
*   **Performance:** 4.12 ms/frame at $128^3$ resolution and $384^2$ screen size on M-series hardware [S1, unofficial].
*   **Strengths:** Real-time performance; no CPU-GPU synchronization for buffer sizing (via atomic counters and indirect draw); crack-free mesh generation [S1, unofficial].
*   **Limitations:** Fixed vertex pool size (1.5M) may overflow for very complex scenes; WebGL2 fallback uses a different renderer (ssf) [S1, unofficial].
*   **When to use:** Real-time fluid simulation or dynamic isosurface rendering where performance is critical and scene complexity is bounded [S1, unofficial].
*   **When not to use:** Scenes requiring arbitrarily large meshes without capping; environments where `indirect-first-instance` is not available and overflow handling via `firstInstance` is preferred [S1, unofficial].

## Background
This method was introduced by nikolai3d in the "waterfall" WebGL2 fluid simulation project as the `r=mesh` renderer [S1, unofficial]. It was developed to provide a real-time isosurface meshing alternative to screen-space fluid rendering, leveraging WebGPU compute shaders for parallel processing [S1, unofficial]. The technique was verified on $64^3$–$128^3$ resolutions with WebGL2 fallback and WebGPU support [S1, unofficial].
