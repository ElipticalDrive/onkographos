# GPU Marching Cubes with Atomic Counter Emission

Also called: atomic-counter MC, indirect-draw MC, r=mesh

## Overview
This method performs real-time isosurface meshing by dispatching one compute thread per grid cell to classify density, reserve vertex slots via atomic addition on indirect draw arguments, and write vertices directly into a capped pool, thereby avoiding the latency of prefix sums [S1, unofficial]. It is distinguished from sibling methods like [GPU Marching Cubes with Histogram Pyramid](2317-gpu-marching-cubes-with-histogram-pyramid.md) by its use of atomic counters on draw arguments rather than hierarchical prefix-sum structures, and from [GPU Marching Cubes (Compute Shader)](4687-gpu-marching-cubes-compute-shader.md) by its specific integration with `drawIndirect` for rendering [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A tent-blurred density grid (scalar field) and an isosurface threshold $\tau$ (controlled by `?iso=`) [S1, unofficial].
*   **Output:** A triangle mesh rendered via `drawIndirect`, depth-tested against a raytraced background [S1, unofficial].

**Data Structures:**
1.  **Indirect Draw Args Buffer:** A buffer containing standard `drawIndirect` arguments (vertex count, instance count, first vertex, first instance) plus an overflow flag [S1, unofficial].
    *   Layout: Words 0-3 contain standard draw parameters. Word 4 stores the overflow flag [S1, unofficial].
    *   Note: The overflow flag is placed in word 4, not `firstInstance` (word 3), because a non-zero `firstInstance` no-ops the indirect draw without the `indirect-first-instance` feature [S1, unofficial].
2.  **Vertex Pool:** A fixed-size buffer storing vertex positions and gradient normals [S1, unofficial].
    *   Size: 1.5 million vertices (48 MB) [S1, unofficial].
    *   Access: Vertex pulling [S1, unofficial].
3.  **Triangle Table:** Generated at load time rather than hardcoded [S1, unofficial].
    *   Generation: Marching squares per cube face $\rightarrow$ closed loops $\rightarrow$ fan triangulation [S1, unofficial].
    *   Properties: Rotation-invariant ambiguity rule; crack-free by construction; validated against all 256 cases; max 5 triangles per case [S1, unofficial].

**Numbered Steps:**

1.  **Dispatch:** Launch one compute thread per grid cell. The dispatch dimensions match the grid resolution $(N_x-1) \times (N_y-1) \times (N_z-1)$ [S1, Parent, unofficial].
2.  **Classification:** Each thread samples the 8 corner densities of its assigned voxel from the tent-blurred grid. It computes the 256-case index by comparing these values against the isosurface threshold $\tau$ [S1, Parent, unofficial].
    *   *Edge Case (Walls):* Lattice index 0 is treated as outside density (density 0) to cap the isosurface on all six walls. Out-of-range lattice samples are also treated as density 0 [S1, unofficial]. Blur bleed outside the walls (cells $2 \dots \text{GRID}-2$) is discarded [S1, unofficial].
3.  **Lookup:** The thread uses the case index to look up the pre-generated triangle table to determine which edges are cut [S1, unofficial].
4.  **Slot Reservation:** The thread reserves vertex slots in the indirect-draw argument buffer using `atomicAdd` on the vertex count field [S1, unofficial].
5.  **Vertex Emission:** For each cut edge, the thread computes the interpolated vertex position and the gradient normal [S1, Parent, unofficial].
    *   *Position:* Linear interpolation along the edge:
        $$
        \mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1)
        $$
        where $V_1, V_2$ are scalar values at corners $\mathbf{p}_1, \mathbf{p}_2$ [S1, Parent, unofficial].
    *   *Normal:* Computed via trilinear density gradient interpolation [S1, unofficial].
    *   *Optimization:* Interpolated position and normal are cached per unique cut edge to avoid recomputation per triangle corner [S1, unofficial].
    *   The vertex data is written into the 1.5M-vertex pool buffer [S1, unofficial].
6.  **Finalization:** A finalize kernel with one thread clamps the vertex count in the indirect-draw args to the pool cap (1.5M) [S1, unofficial].
    *   *Overflow Handling:* If the pre-clamp vertex count exceeds the cap, the finalize kernel raises the overflow flag in args word 4 [S1, unofficial]. The count is clamped to ensure only whole triangles are drawn and no garbage is rendered [S1, unofficial].
7.  **Rendering:** The mesh is rendered using `drawIndirect`, pulling vertices from the pool buffer [S1, unofficial].
8.  **Shading:** The mesh is depth-tested against the raytraced scene background in the same pass [S1, unofficial]. Shading applies:
    *   Fresnel reflection over the analytic scene along one refracted ray.
    *   Beer-Lambert absorption using 6 interior density taps.
    *   Momentum foam effects [S1, unofficial].

**Pseudocode:**

```python
# Compute Shader: mcEmit (one invocation per voxel)
# Inputs: density_grid[GRID][GRID][GRID], isovalue, indirect_draw_args, vertex_pool, triangle_table
# Outputs: indirect_draw_args (vertex count updated), vertex_pool (vertices written)

def mcEmit(thread_id):
    # 1. Map thread to voxel coordinates
    x, y, z = thread_id
    
    # 2. Sample 8 corners and classify
    case_index = 0
    for i in range(8):
        # Handle wall capping: lattice 0 and out-of-range are density 0
        if is_out_of_bounds(i, x, y, z):
            density = 0.0
        else:
            density = density_grid[x + corner_offsets[i].x][y + corner_offsets[i].y][z + corner_offsets[i].z]
        
        if density > isovalue:
            case_index |= (1 << i)
            
    # 3. Lookup triangle table
    # triangle_table is generated at load time: marching squares -> closed loops -> fan triangulation
    num_triangles = triangle_table.num_tris[case_index]
    tri_edges = triangle_table.edges[case_index] # Array of edge indices
    
    # 4. Reserve slots via atomic add on indirect draw args
    # indirect_draw_args[0] is the vertex count
    start_slot = atomic_add(&indirect_draw_args[0], num_triangles * 3)
    
    # 5. Emit vertices
    current_slot = start_slot
    for t in range(num_triangles):
        # Get 3 edges for this triangle
        e0 = tri_edges[t * 3]
        e1 = tri_edges[t * 3 + 1]
        e2 = tri_edges[t * 3 + 2]
        
        # Emit vertex for e0
        v0 = emit_vertex(e0, case_index, x, y, z)
        vertex_pool[current_slot] = v0
        current_slot += 1
        
        # Emit vertex for e1
        v1 = emit_vertex(e1, case_index, x, y, z)
        vertex_pool[current_slot] = v1
        current_slot += 1
        
        # Emit vertex for e2
        v2 = emit_vertex(e2, case_index, x, y, z)
        vertex_pool[current_slot] = v2
        current_slot += 1

def emit_vertex(edge_index, case_index, x, y, z):
    # Determine the two corners of the edge
    c1, c2 = edge_corners[edge_index]
    
    # Get densities, handling out-of-bounds as 0
    d1 = get_density(x, y, z, c1)
    d2 = get_density(x, y, z, c2)
    
    # Linear interpolation for position
    p1 = corner_position(c1)
    p2 = corner_position(c2)
    
    # Guard against division by zero if densities are equal
    if d1 == d2:
        p = (p1 + p2) / 2.0
        normal = compute_gradient(x, y, z)
    else:
        t = (isovalue - d1) / (d2 - d1)
        p = lerp(p1, p2, t)
        normal = compute_gradient(x, y, z)
        
    return Vertex(position=p, normal=normal)

def get_density(x, y, z, corner_idx):
    # Map corner index to relative grid offset
    dx, dy, dz = corner_offsets[corner_idx]
    gx, gy, gz = x + dx, y + dy, z + dz
    
    # Check bounds and wall capping
    if gx < 0 or gx >= GRID or gy < 0 or gy >= GRID or gz < 0 or gz >= GRID:
        return 0.0
    return density_grid[gx][gy][gz]

# Compute Shader: mcFinalize (one invocation)
def mcFinalize():
    # Clamp vertex count to pool cap
    current_count = indirect_draw_args[0]
    cap = 1500000
    
    if current_count > cap:
        # Raise overflow flag in word 4
        indirect_draw_args[4] = 1
        indirect_draw_args[0] = cap
    else:
        indirect_draw_args[4] = 0
```

**Parameters:**
*   **Vertex Pool Size:** 1.5 million vertices [S1, unofficial].
*   **Isosurface Threshold:** Controlled by `?iso=` parameter [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Overflow:** If the pre-clamp vertex count exceeds the 1.5M cap, the overflow flag is raised. The count is clamped to the cap to ensure only whole triangles are drawn and no garbage is rendered [S1, unofficial].
*   **First Instance:** The overflow flag is placed in args word 4, not `firstInstance`, because non-zero `firstInstance` no-ops the indirect draw without the `indirect-first-instance` feature [S1, unofficial].
*   **Wall Capping:** Lattice 0 is treated as outside density to cap the isosurface on all six walls. Only blur bleed outside the walls (cells $2 \dots \text{GRID}-2$) is discarded [S1, unofficial].
*   **Out-of-Range Samples:** `mcEmit` treats out-of-range lattice samples as density 0 to cap the isosurface against the walls [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed by one thread [S1, Parent, unofficial].
*   **Memory Complexity:** $O(N)$ for the density grid and $O(C)$ for the vertex pool, where $C$ is the pool capacity (1.5M vertices) [S1, unofficial].
*   **Measured Performance:** 4.12 ms/frame at $128^3$ resolution and $384^2$ screen size on M-series hardware [S1, unofficial].
*   **Strengths:** Avoids the latency of prefix sums; simple implementation using atomic counters; real-time capable [S1, unofficial].
*   **Limitations:** Fixed-size vertex pool requires clamping and overflow handling; potential for atomic contention on high-density scenes [S1, unofficial].
*   **When to use:** Real-time isosurface extraction where prefix sums are too slow or complex, and a fixed vertex budget is acceptable [S1, unofficial].
*   **When not to use:** When exact vertex counts are required without clamping, or when the scene density exceeds the pool capacity significantly [S1, unofficial].

## Background
This method was introduced in the 'waterfall' WebGL2 fluid simulation project as the `r=mesh` renderer [S1, unofficial]. It was developed by nikolai3d and merged into the main branch in July 2026 [S1, unofficial]. The triangle table generation method (marching squares faces $\rightarrow$ closed loops $\rightarrow$ fan triangulation) was designed to be rotation-invariant and crack-free, avoiding the transcription of the classic 256x16 constant table [S1, unofficial]. WebGL2 falls back to the `ssf` (screen-space fluid) path for `r=mesh`, while WebGPU uses the full marching cubes implementation [S1, unofficial].
