# Lookup Table and Configuration


## Overview
Lookup Table and Configuration provides the static data structures that map the 256 binary sign configurations of a voxel's eight corners to specific triangulations of the isosurface within that voxel [G]. It solves the problem of determining edge intersections and triangle connectivity without runtime branching logic for topology [G]. Unlike [Symmetry Mapping](869-symmetry-mapping.md) which reduces table size via rotation, or [Watt & Watt Marching Cubes](7787-watt-watt-marching-cubes.md) which adds system-level optimizations, the standard configuration relies on a fixed, static mapping for all 256 cases, prioritizing O(1) lookup speed [G].

## Shared principles
The family relies on two precomputed data structures derived from the 256 possible binary configurations of a voxel's eight corner signs relative to an isovalue [G].

1.  **Edge Intersection Table (`edgeTable`)**: An array of 256 integers (or shorts). Each entry is a 12-bit bitmask. Bit $k$ ($0 \le k \le 11$) is set to 1 if the isosurface intersects the $k$-th edge of the cube, and 0 otherwise [G]. The standard edge numbering convention is:
    *   Bottom face ($z=0$): $e_0=(0,1), e_1=(1,2), e_2=(2,3), e_3=(3,0)$ [G]
    *   Top face ($z=1$): $e_4=(4,5), e_5=(5,6), e_6=(6,7), e_7=(7,4)$ [G]
    *   Vertical edges: $e_8=(0,4), e_9=(1,5), e_{10}=(2,6), e_{11}=(3,7)$ [G]

2.  **Triangle Connection Table (`triangleTable`)**: A 2D array of size $256 \times 16$ [G].
    *   Rows are indexed by the case index $C \in [0, 255]$ [G].
    *   Columns store integer indices. Indices $0–11$ refer to the 12 cube edges [G].
    *   Indices are grouped in triplets $(a, b, c)$ to form triangles [G].
    *   The sequence is terminated by the value `-1` [G].
    *   The maximum number of triangles per voxel is 5, requiring 15 indices plus 1 terminator [G].

**Case Index Calculation**: For each voxel, the 8-bit case index $C$ is determined by the scalar field values $V$ at the 8 vertices $v_i$ ($i=0..7$) [G]. If $V(v_i) < I$ (or $> I$, depending on convention), bit $i$ of $C$ is set to 1; otherwise 0 [G]. The bit assignment must strictly match the vertex ordering assumed by the LUT generation [G].

**Ambiguity**: Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous (the isosurface passes through the cube center) [G]. The standard LUT uses a fixed triangulation for these, which can cause cracks or holes if adjacent voxels resolve the ambiguity differently [G].

```python
def compute_case_index(values, isovalue):
    case_index = 0
    for i in range(8):
        if values[i] < isovalue:
            case_index |= (1 << i)
    return case_index

def extract_triangles(case_index, triangle_table, edge_intersections):
    triangles = []
    tri_indices = triangle_table[case_index]
    for i in range(0, 16, 3):
        e1 = tri_indices[i]
        if e1 == -1:
            break
        e2 = tri_indices[i + 1]
        e3 = tri_indices[i + 2]
        triangles.append((edge_intersections[e1], edge_intersections[e2], edge_intersections[e3]))
    return triangles
```
Note: `edge_intersections` must be precomputed by interpolating field values along the 12 cube edges [G].

## Subtopics

### [Symmetry Mapping](869-symmetry-mapping.md)
Reduces the 256 possible binary configurations into a smaller set of canonical base cases by exploiting the geometric symmetries of the cube. Sets apart by mapping each configuration to one of 23 unique base cases and a specific rotation, simplifying triangle generation logic. Choose when memory is constrained.

### [Marching Cubes Lookup Table](4800-marching-cubes-lookup-table.md)
Maps the 256 possible binary configurations of a voxel's eight corner signs relative to an isovalue to a specific triangulation of the isosurface within that voxel. Sets apart by relying on a fixed, static configuration for all 256 cases, prioritizing O(1) lookup speed over topological correctness at saddle points. Choose for standard speed priority.

### [Watt & Watt Marching Cubes](7787-watt-watt-marching-cubes.md)
An optimized implementation of the Marching Cubes algorithm designed to address topological inconsistencies, redundant vertex computation, and I/O bottlenecks in large-scale volume rendering. Sets apart by integrating a modified lookup table for consistent triangulation, vertex deduplication via auxiliary data structures, and dynamic I/O buffering. Choose for large datasets exceeding main memory capacity.

### [Improved Marching Cubes Algorithm](9090-improved-marching-cubes-algorithm.md)
A variant of the standard Marching Cubes method designed to enhance computational efficiency and topological robustness in 3D reconstruction, particularly for medical imaging. Sets apart by expanding the topological configuration set from 15 to 24 cases and employing a tunable interpolation scheme. Choose when topological voids in ambiguous configurations must be avoided.

### Patch Boundary Detection
#### definition
- [S1] Process to detect patch boundaries as groups of rings of linear contours on cell faces for automatic construction of look-up tables.
#### step
- [S1] Construct a single ring using face-tracing: starting from a cell edge with a sign change, facing the positive end, look for the next edge with a sign change by turning counter-clockwise on the face boundary.
- [S1] Repeat the search process until it returns to the starting edge, forming a closed ring.
- [S1] Orient the linear contour on the cell face so that the negative region on that face lies to its left when looking from outside.
- [S1] Group rings constructed around the same edge-connected component of positive corners to form the boundary of a single patch.
