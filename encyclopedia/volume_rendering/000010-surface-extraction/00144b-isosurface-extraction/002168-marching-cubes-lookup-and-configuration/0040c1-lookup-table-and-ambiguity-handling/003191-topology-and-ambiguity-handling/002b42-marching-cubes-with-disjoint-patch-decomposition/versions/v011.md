# Marching Cubes with Disjoint Patch Decomposition

Also called: Disjoint patch MC, MC with edge grouping

## Overview
Marching Cubes with Disjoint Patch Decomposition is a surface extraction method that resolves topological ambiguities in the standard Marching Cubes algorithm by decomposing the surface within a voxel into disjoint connected components (patches) [S1, unofficial]. It solves the problem of non-manifold geometry and self-intersections that arise in ambiguous cases (e.g., saddle points) where the standard lookup table arbitrarily selects a triangulation [S1, unofficial]. It sets itself apart from its parent [Topology and Ambiguity Handling](6547-topology-and-ambiguity-handling.md) by using a graph-based coloring approach on a decomposed cube structure to ensure that intersected edges are grouped into consistent, non-overlapping patches, rather than relying on pre-defined ambiguous case resolutions [S1, unofficial].

## How it works
The method modifies the standard Marching Cubes framework by introducing a 15-point decomposition of the cube and a graph-based connectivity analysis to determine edge grouping [S1, unofficial].

### Inputs and Outputs
- **Input**: A scalar field $V$ defined on a 3D grid, an isovalue $\theta$ (default 0.7 [S1, unofficial]), and the voxel grid dimensions.
- **Output**: A triangle mesh (or quad mesh) representing the isosurface.

### Data Structures
1.  **Point Indices**: Each voxel is decomposed into 15 points:
    -   Vertices $0-7$: The 8 corners of the cube.
    -   Face Centers $8-13$: The center of each of the 6 faces.
    -   Cube Center $14$: The center of the cube.
2.  **Face Definition**: The 6 faces are defined by their vertex indices:
    $$
    \text{cubefaces}[6][4] = \begin{bmatrix}
    0 & 2 & 6 & 4 \\
    1 & 5 & 7 & 3 \\
    0 & 4 & 5 & 1 \\
    2 & 3 & 7 & 6 \\
    0 & 1 & 3 & 2 \\
    4 & 6 & 7 & 5
    \end{bmatrix}
    $$
3.  **Tetrahedron Decomposition**: The cube is decomposed into tetrahedra for scalar evaluation. For each face $f \in [0, 5]$, 4 tetrahedra are formed using vertices from the face, the face center ($8+f$), and the cube center ($14$):
    $$ \text{tet} = \{ \text{cubefaces}[f][(j+1)\&3], \text{cubefaces}[f][j], 8+f, 14 \} \quad \text{for } j=0..3 $$
4.  **Edge Map**: A map from unique edge IDs (computed as $\min(u,v) \times 100 + \max(u,v)$ for edge endpoints $u,v$) to sequential indices $0..N-1$.
5.  **Graph Adjacency**: An adjacency list or matrix representing connectivity between edges within the tetrahedral decomposition.
6.  **Edge Group Lookup Table (`edgeGroup`)**: An array of 256 unsigned integers. Each integer encodes the 6 cube edges with 4 bits per edge (24 bits total). Values $0-3$ represent patch assignments or uncategorized edges.

### Algorithm Steps

1.  **Scalar Evaluation**:
    For a given voxel with case index $C$ (8-bit vertex sign pattern):
    -   Set values for vertices $0-7$: $val[i] = 1$ if bit $i$ of $C$ is set, else $0$.
    -   Set values for face centers $8-13$: $val[8+f] = \frac{1}{4} \sum_{v \in \text{face } f} val[v]$.
    -   Set value for cube center $14$: $val[14] = \frac{1}{8} \sum_{v=0}^{7} val[v]$.

2.  **Edge Classification**:
    For each edge $(u, v)$ in the decomposition:
    -   If $(val[u] > \theta) \oplus (val[v] > \theta)$ is true, mark the edge as **cut** ($0$).
    -   Otherwise, mark the edge as **uncut/ambiguous** ($-1$).

3.  **Connected Components of Uncut Edges**:
    -   Build an adjacency matrix $A$ where $A(u,v)=1$ if both $u$ and $v$ are uncut edges and are connected in the tetrahedral graph.
    -   Compute the transitive closure of $A$ by iterating $A = \text{sign}(A \times A)$ until convergence. This identifies clusters of uncut edges that are topologically linked.

4.  **Patch Coloring (Disjoint Decomposition)**:
    -   Initialize all cut edges as uncolored.
    -   Iterate through all cut edges. If an edge is uncolored, assign it a new **Color ID** (patch ID).
    -   Propagate this Color ID to all other cut edges connected to it in the graph, using the transitive closure matrix $A$ to determine connectivity.
    -   Increment the Color ID for the next uncolored cut edge.

5.  **Lookup Code Generation**:
    -   For each of the 6 cube edges (connecting two vertices $v_1, v_2 < 8$):
        -   Determine the patch mark $mkid$ from the coloring step.
        -   If $mkid = -1$ (uncut), map to $3$.
        -   If $mkid \ge 0$ (cut), map to $mkid - 1$.
    -   Pack these 4-bit values into a 24-bit integer code (6 edges $\times$ 4 bits). This code indexes into `edgeGroup` or is used directly to determine geometry.

6.  **Mesh Generation**:
    -   For each cut edge, compute the intersection point using linear interpolation:
        $$ w = \frac{\theta - val[u]}{val[v] - val[u]} $$
        $$ P_{\text{intersect}} = (1-w)P_u + wP_v $$
    -   Group intersection points by their assigned Color ID (patch).
    -   For each patch, compute the centroid of its intersection points:
        $$ P_{\text{patch}} = \frac{1}{N} \sum_{i=1}^{N} P_{\text{intersect}, i} $$
    -   Generate geometry based on the patch type. The source indicates support for both triangle and quad generation.
        -   **Quad Mode**: If the patch corresponds to a quad configuration, add a quad face using the patch point and relevant vertices/centers.
        -   **Triangle Mode**: If the patch corresponds to a triangle configuration, split the quad into two triangles. The split direction is determined by a quality metric (ratio of inradius to circumradius) to minimize degenerate triangles [S1, unofficial].
    -   Handle boundary conditions using a `cubeflag` bitmask to clamp points to the voxel boundaries if necessary [S1, unofficial].

### Pseudocode

```python
def marching_cubes_disjoint_patch_decomposition(grid, level=0.7):
    """
    grid: 3D array of scalar values
    level: isovalue threshold
    Returns: list of triangles or quads
    """
    vertices = []
    faces = []
    
    # Precompute face definitions
    cubefaces = [
        [0, 2, 6, 4], [1, 5, 7, 3], [0, 4, 5, 1],
        [2, 3, 7, 6], [0, 1, 3, 2], [4, 6, 7, 5]
    ]
    
    # Iterate over all voxels
    for cube in grid.voxels():
        # 1. Scalar Evaluation
        vals = [0.0] * 15
        for i in range(8):
            vals[i] = 1.0 if grid[cube][i] > level else 0.0
            
        for f in range(6):
            face_verts = cubefaces[f]
            vals[8 + f] = sum(vals[v] for v in face_verts) / 4.0
            
        vals[14] = sum(vals[i] for i in range(8)) / 8.0
        
        # 2. Edge Classification and Graph Construction
        # Define edges in the 15-point decomposition
        # Edges are defined by pairs of point indices
        # We need to map unique edges to IDs
        edge_map = {}
        edge_list = []
        
        # Generate tetrahedra and their edges
        tets = []
        for f in range(6):
            face_verts = cubefaces[f]
            for j in range(4):
                v1 = face_verts[(j + 1) & 3]
                v2 = face_verts[j]
                v3 = 8 + f
                v4 = 14
                tets.append([v1, v2, v3, v4])
                
        for tet in tets:
            for i in range(6):
                u = tet[[0, 0, 0, 1, 1, 2][i]]
                v = tet[[1, 2, 3, 2, 3, 3][i]]
                edge_id = min(u, v) * 100 + max(u, v)
                if edge_id not in edge_map:
                    edge_map[edge_id] = len(edge_list)
                    edge_list.append((u, v))
                    
        # Build adjacency for uncut edges
        # First, classify edges
        edge_status = {} # edge_id -> -1 (uncut) or 0 (cut)
        for edge_id, (u, v) in edge_list.items():
            if (vals[u] > level) ^ (vals[v] > level):
                edge_status[edge_id] = 0
            else:
                edge_status[edge_id] = -1
                
        # Build adjacency matrix for uncut edges
        # Two uncut edges are connected if they share a vertex in the tet decomposition
        # For simplicity, we assume the graph connectivity is defined by the tet structure
        # In practice, this requires building an adjacency list of edges sharing vertices
        adj = {}
        for edge_id, (u, v) in edge_list.items():
            if edge_status[edge_id] == -1:
                adj[edge_id] = []
                
        # Connect edges sharing vertices
        for tet in tets:
            tet_edges = []
            for i in range(6):
                u = tet[[0, 0, 0, 1, 1, 2][i]]
                v = tet[[1, 2, 3, 2, 3, 3][i]]
                edge_id = min(u, v) * 100 + max(u, v)
                if edge_status.get(edge_id) == -1:
                    tet_edges.append(edge_id)
            for i in range(len(tet_edges)):
                for j in range(i + 1, len(tet_edges)):
                    adj[tet_edges[i]].append(tet_edges[j])
                    adj[tet_edges[j]].append(tet_edges[i])
                    
        # Compute transitive closure
        # A = adjacency matrix of uncut edges
        # Iterate A = sign(A * A)
        # This is complex to implement directly in pseudocode without matrix ops,
        # so we use BFS/DFS for connected components of uncut edges
        uncut_components = {}
        visited = set()
        comp_id = 0
        for edge_id in adj:
            if edge_id not in visited:
                # BFS
                queue = [edge_id]
                visited.add(edge_id)
                comp = []
                while queue:
                    curr = queue.pop(0)
                    comp.append(curr)
                    for neighbor in adj[curr]:
                        if neighbor not in visited:
                            visited.add(neighbor)
                            queue.append(neighbor)
                for eid in comp:
                    uncut_components[eid] = comp_id
                comp_id += 1
                
        # 3. Patch Coloring for Cut Edges
        # Cut edges are grouped if they are connected in the graph,
        # but NOT connected via uncut edges? 
        # The source says: "Propagate this color to all other cut edges connected to it in the graph (using the transitive closure matrix A)"
        # This implies we use the same connectivity graph, but only propagate through cut edges?
        # Or does it mean we use the transitive closure of the FULL graph to determine if two cut edges are "blocked" by uncut edges?
        # The source says: "Color cut edges (0) into disjoint patches. Iterate edges. If an edge is cut (0) and not yet colored, assign a new color ID. Propagate this color to all other cut edges connected to it in the graph (using the transitive closure matrix A)."
        # This suggests we use the transitive closure of the UNcut edges to define "blocks", and cut edges within the same block are grouped?
        # Actually, the source says "connected to it in the graph". Let's assume standard graph connectivity for cut edges.
        
        patch_colors = {}
        color_id = 0
        for edge_id, (u, v) in edge_list.items():
            if edge_status[edge_id] == 0 and edge_id not in patch_colors:
                # BFS for cut edges only
                queue = [edge_id]
                patch_colors[edge_id] = color_id
                while queue:
                    curr = queue.pop(0)
                    # Find neighbors in the original graph that are also cut
                    # We need to rebuild adjacency for cut edges or filter the full adj
                    # For simplicity, assume we have a cut_adj
                    for neighbor in adj.get(curr, []):
                        if edge_status.get(neighbor) == 0 and neighbor not in patch_colors:
                            patch_colors[neighbor] = color_id
                            queue.append(neighbor)
                color_id += 1
                
        # 4. Generate Geometry
        # Group cut edges by patch color
        patches = {}
        for edge_id, (u, v) in edge_list.items():
            if edge_status[edge_id] == 0:
                pid = patch_colors[edge_id]
                if pid not in patches:
                    patches[pid] = []
                patches[pid].append((u, v))
                
        for pid, edges in patches.items():
            # Compute intersection points
            pts = []
            for u, v in edges:
                w = (level - vals[u]) / (vals[v] - vals[u])
                # Interpolate position
                p_u = grid.get_point(u) # Assuming grid provides world coords for point indices
                p_v = grid.get_point(v)
                p = (1 - w) * p_u + w * p_v
                pts.append(p)
                
            # Compute centroid
            centroid = sum(pts) / len(pts)
            
            # Add face based on patch type
            # The source uses a lookup code to determine the face type
            # For now, we assume a simple case: if 4 points, add quad; if 3, add triangle
            # The source code shows `add_face` taking 4 points for quad or 3 for triangle
            if len(pts) == 4:
                faces.append([pts[0], pts[1], pts[2], pts[3]])
            elif len(pts) == 3:
                faces.append([pts[0], pts[1], pts[2]])
            else:
                # Handle other cases as per the lookup table logic
                pass
                
    return faces
```

### Parameters
-   **$\theta$ (level)**: The isovalue threshold. Default is 0.7 [S1, unofficial].

### Edge Cases and Pitfalls
-   **Precision**: Linear interpolation assumes linear variation between vertices. In regions of high curvature, this may introduce artifacts.
-   **Boundary Conditions**: The `cubeflag` bitmask is used to clamp points to the voxel boundaries if the voxel is on the grid boundary [S1, unofficial].
-   **Degenerate Input**: If all vertex values are equal, no edges are cut, and no geometry is generated.
-   **Ambiguous Cases**: The method specifically targets ambiguous cases where the standard MC fails. If the input is not ambiguous, the method should behave similarly to standard MC but with potentially different patch grouping.

## Subtopics

### [Ambiguous Face Handling with Connected Components](6727-ambiguous-face-handling-with-connected-components.md)
This method handles ambiguous faces in contouring to avoid non-manifold edges by selecting specific connected components (white vs. blue) based on the number of ambiguous faces per cell. It prevents non-manifold geometry by choosing white components when only one ambiguous face exists per cell, and blue components when a cell contains three ambiguous faces with multiple blue components.

### [Mesh Extraction](14720-mesh-extraction.md)
Mesh Extraction is the final step in the Patch-Grid pipeline, responsible for converting the implicit representation into a valid triangle mesh. It solves the problem of topological errors (such as self-intersections or non-manifold edges) that arise when multiple surface patches intersect within the same grid volume. It sets itself apart from standard Marching Cubes by restricting mesh generation to specific cell types: it applies the algorithm only to cells containing a single patch or to a specialized "merge grid" for intersecting regions, thereby ensuring mesh validity through patch and merge loss constraints.

## Operating characteristics
-   **Time Complexity**: The method involves graph construction and transitive closure computation for each voxel, which is more expensive than standard MC. The complexity is roughly $O(V \cdot E)$ per voxel, where $V$ is the number of points (15) and $E$ is the number of edges in the decomposition.
-   **Memory Complexity**: Requires storing the 15-point decomposition, edge map, and graph adjacency for each voxel. This is higher than standard MC.
-   **Strengths**: Guarantees topological correctness (manifold mesh) in ambiguous cases. Handles saddle points correctly.
-   **Limitations**: Higher computational cost. More complex implementation.
-   **When to Use**: When topological correctness is critical and the scalar field contains ambiguous cases (e.g., medical imaging, scientific visualization).
-   **When Not to Use**: When performance is the primary concern and the scalar field is known to be free of ambiguous cases.
