# Marching Cubes with Disjoint Patch Decomposition

Also called: Disjoint patch MC, MC with edge grouping

## Overview
This method resolves topological ambiguities in Marching Cubes by decomposing the cube into a graph of 15 points (8 vertices, 6 face centers, 1 cube center) and grouping intersected edges into disjoint, non-overlapping patches using graph-based coloring [S1, unofficial]. It sets itself apart from sibling methods like Hermite Dual Marching Cubes by relying on scalar field averaging and connectivity analysis rather than normal vectors or dual-space representations, ensuring manifold output without requiring additional geometric data [S1, unofficial].

## How it works
**Inputs:** A scalar field $V$ defined on a 3D grid, an isovalue $\theta$ (default 0.7 [S1, unofficial]), and the current cube's 8 vertex indices.
**Outputs:** A set of triangles (or quads) representing the isosurface within the cube.

**Data Structures:**
1.  **15-Point Layout:**
    *   Indices 0–7: Cube vertices.
    *   Indices 8–13: Face centers (one per face).
    *   Index 14: Cube center.
2.  **Face Definition:**
    The 6 faces are defined by their 4 vertex indices:
    `cubefaces[6][4] = {{0, 2, 6, 4}, {1, 5, 7, 3}, {0, 4, 5, 1}, {2, 3, 7, 6}, {0, 1, 3, 2}, {4, 6, 7, 5}}` [S1, unofficial].
3.  **Tetrahedral Decomposition:**
    The cube is decomposed into 24 tetrahedra to define edge connectivity. For each face $f \in [0, 5]$, 4 tetrahedra are formed using the face vertices, the face center ($8+f$), and the cube center (14):
    $T_{f,j} = \{ \text{cubefaces}[f][(j+1)\&3], \text{cubefaces}[f][j], 8+f, 14 \}$ for $j \in [0, 3]$ [S1, unofficial].
4.  **Edge Map:**
    Each tetrahedron has 6 edges. The edges are indexed by pairs $(i, j)$ where $i \in \{0,0,0,1,1,2\}$ and $j \in \{1,2,3,2,3,3\}$. An edge is identified by the pair of point indices $(u, v)$. A unique edge ID is computed as $\min(u,v) \times 100 + \max(u,v)$ [S1, unofficial].
5.  **Adjacency Graph:**
    An adjacency list `graph` is built where nodes are unique edge IDs. An undirected edge exists between two edge IDs if they share a tetrahedron in the decomposition [S1, unofficial].
6.  **Lookup Table:**
    `edgeGroup[256]`: An array of 256 unsigned integers. Each integer encodes the 6 cube edges with 4 bits per edge. Values 0–3 represent patch assignments or uncategorized states [S1, unofficial].

**Algorithm Steps:**

1.  **Compute Scalar Values:**
    For the current cube case (8-bit sign pattern), compute values for all 15 points:
    *   $vals[0..7]$: 0 or 1 based on the case bits relative to $\theta$.
    *   $vals[8..13]$: Average of the 4 vertex values of the corresponding face.
    *   $vals[14]$: Average of the 8 vertex values of the cube [S1, unofficial].

2.  **Mark Edges:**
    For each of the 12 cube edges $(u, v)$:
    *   If $(vals[u] > \theta) \oplus (vals[v] > \theta)$ is false, mark the edge as `-1` (uncut/ambiguous).
    *   Otherwise, mark the edge as `0` (cut) [S1, unofficial].

3.  **Compute Connected Components of Uncut Edges:**
    *   Build an adjacency matrix $A$ for the graph of uncut edges. $A(u,v) = 1$ if both $u$ and $v$ are uncut and connected in `graph`.
    *   Compute the transitive closure by iterating $A = \text{sign}(A \times A)$ until convergence [S1, unofficial].

4.  **Color Cut Edges into Disjoint Patches:**
    *   Initialize all cut edges as uncolored.
    *   Iterate through cut edges. If an edge is uncolored, assign a new color ID $C$.
    *   Propagate color $C$ to all other cut edges connected to it in the graph using the transitive closure matrix $A$.
    *   Increment $C$ for the next uncolored cut edge [S1, unofficial].

5.  **Generate Lookup Code:**
    For each of the 6 cube edges $k \in [0, 5]$:
    *   Let $mkid$ be the patch mark of the edge.
    *   If $mkid == -1$, map to 3.
    *   Else, map to $mkid - 1$.
    *   Pack these 4-bit values into a 24-bit integer code (6 edges $\times$ 4 bits) [S1, unofficial].

6.  **Generate Geometry:**
    *   Use the lookup code to determine the patch configuration.
    *   For each cut edge, compute the intersection point using linear interpolation:
        $w = \frac{\theta - vals[u]}{vals[v] - vals[u]}$
        $P = V_u + w(V_v - V_u)$ [S1, unofficial].
    *   Aggregate points by patch ID. For each patch with $N$ points, compute the centroid:
        $P_{patch} = \frac{1}{N} \sum_{i=1}^{N} P_i$ [S1, unofficial].
    *   If boundary flags are set, clamp the centroid to the cube boundary [S1, unofficial].
    *   Generate faces (triangles or quads) from the patch centroids. If `NON_SYMMETRIC_SPLIT` is enabled, use a quality metric to decide triangulation; otherwise, split quads by adding a center point [S1, unofficial].

**Pseudocode:**

```python
def marching_cubes_disjoint_patch(cube_vertices, level):
    # 1. Define 15 points
    # 0-7: cube vertices
    # 8-13: face centers
    # 14: cube center
    
    # 2. Compute values
    vals = [0.0] * 15
    for i in range(8):
        vals[i] = 1.0 if cube_vertices[i] > level else 0.0
    
    # Face centers: average of 4 vertices
    for f in range(6):
        face_verts = cubefaces[f]
        vals[8 + f] = sum(vals[v] for v in face_verts) / 4.0
    
    # Cube center: average of 8 vertices
    vals[14] = sum(vals[i] for i in range(8)) / 8.0
    
    # 3. Mark edges
    edge_marks = [-1] * 12  # -1: uncut, 0: cut
    for e_idx, (u, v) in enumerate(cube_edges):
        if (vals[u] > level) == (vals[v] > level):
            edge_marks[e_idx] = -1
        else:
            edge_marks[e_idx] = 0
            
    # 4. Build graph and compute transitive closure for uncut edges
    # Graph nodes are edge indices 0-11
    # Edges in graph if they share a tetrahedron in the 24-tet decomposition
    graph = build_adjacency_list()
    
    # Transitive closure for uncut edges
    A = adjacency_matrix(graph, edge_marks)
    while True:
        A_new = sign_matrix_multiply(A, A)
        if A_new == A:
            break
        A = A_new
        
    # 5. Color cut edges
    patch_colors = [-1] * 12
    color_id = 0
    for e_idx in range(12):
        if edge_marks[e_idx] == 0 and patch_colors[e_idx] == -1:
            # Assign new color
            patch_colors[e_idx] = color_id
            # Propagate
            for other_e in range(12):
                if edge_marks[other_e] == 0 and A[e_idx][other_e]:
                    patch_colors[other_e] = color_id
            color_id += 1
            
    # 6. Generate Lookup Code
    lookup_code = 0
    for e_idx in range(6):
        mkid = patch_colors[e_idx]
        if mkid == -1:
            mapped = 3
        else:
            mapped = mkid - 1
        lookup_code |= (mapped << (4 * e_idx))
        
    # 7. Generate Geometry
    points_by_patch = {i: [] for i in range(color_id)}
    
    for e_idx, (u, v) in enumerate(cube_edges):
        if edge_marks[e_idx] == 0:
            w = (level - vals[u]) / (vals[v] - vals[u])
            p = interpolate(cube_vertices[u], cube_vertices[v], w)
            pid = patch_colors[e_idx]
            points_by_patch[pid].append(p)
            
    triangles = []
    for pid, pts in points_by_patch.items():
        if pts:
            centroid = sum(pts) / len(pts)
            # Generate faces based on lookup_code and pid
            # This part depends on the specific lookup table entries
            # For simplicity, assume a standard triangulation of the patch
            triangles.extend(generate_faces_from_patch(centroid, pid, lookup_code))
            
    return triangles
```

## Operating characteristics
**Time Complexity:** Dominated by the graph construction and transitive closure computation, which is $O(E^3)$ or $O(E^\omega)$ depending on the matrix multiplication implementation, where $E$ is the number of edges in the graph (constant 12 for cube edges, but the graph includes internal edges from tet decomposition). In practice, the graph size is small and fixed per cube, making it $O(1)$ per cube.
**Memory Complexity:** $O(1)$ per cube for the lookup table and graph structures.
**Performance:** The method is computationally more expensive than standard Marching Cubes due to the graph operations and averaging steps. However, it guarantees topological correctness without post-processing.
**Strengths:** Handles all 256 cases correctly, including ambiguous ones. Produces manifold meshes.
**Limitations:** More complex implementation. The averaging of face and cube center values can introduce slight geometric inaccuracies compared to direct edge interpolation.

## Background
The method originates from the work on disjoint patch decomposition for Marching Cubes, specifically as implemented in the `uranix/mcubes` repository [S1, unofficial]. It addresses the topological ambiguities inherent in the standard 256-case lookup table by using a graph-based approach to group edges into consistent patches.
