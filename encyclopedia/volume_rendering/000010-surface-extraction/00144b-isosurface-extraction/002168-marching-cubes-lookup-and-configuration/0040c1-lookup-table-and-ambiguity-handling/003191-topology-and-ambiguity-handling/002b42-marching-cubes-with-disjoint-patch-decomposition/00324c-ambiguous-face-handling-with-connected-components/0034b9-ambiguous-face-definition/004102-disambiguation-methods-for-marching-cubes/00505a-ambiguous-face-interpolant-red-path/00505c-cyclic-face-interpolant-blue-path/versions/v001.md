# Cyclic Face Interpolant (Blue Path)
Also called: Blue Path Interpolant
## Overview
The Cyclic Face Interpolant is a surface reconstruction method for Marching Squares cells containing an ambiguous face, specifically addressing the topology ambiguity where the standard linear interpolation fails to define a unique surface [S1, book]. It constructs a continuous surface by sweeping vertices in a cyclic order around the face (the "blue path"), differing from the Red Path interpolant by allowing one vertex to move along the top edge and another along the bottom edge during the transition, resulting in non-polynomial behavior [S1, book].
## How it works
**Inputs and Outputs:**
*   **Input:** A Marching Squares cell with an ambiguous face (cases 8 or 15), defined by four vertex values $h_{00}, h_{01}, h_{10}, h_{11}$ and their corresponding spatial positions. The isovalue $h$ is the target scalar value.
*   **Output:** A set of surface primitives (edges and triangles) representing the isosurface within the cell.

**Data Structures:**
The method relies on the standard Marching Squares vertex labeling:
*   $v_{00}$: Bottom-left vertex position.
*   $v_{01}$: Top-left vertex position.
*   $v_{10}$: Bottom-right vertex position.
*   $v_{11}$: Top-right vertex position.
*   $h_{00}, h_{01}, h_{10}, h_{11}$: Scalar values at respective vertices.

**Steps:**
1.  **Identify Case:** Determine if the cell is in Case 8 (single edge) or Case 11 (triangular surface) or an intermediate state in the cyclic transition. The cyclic path transitions from Case 8 to Case 11.
2.  **Define Edge Points:** For a given isovalue $h$, calculate the intersection points $p(h)$ and $q(h)$ on the edges of the cell.
    *   $p(h)$ is the point on the top edge (between $v_{00}$ and $v_{01}$? No, standard labeling usually implies edges. Let's follow the source formula strictly).
    *   The source formula defines $p(h)$ and $q(h)$ as linearly interpolated points.
    *   Based on the formula $L(h) = \|p(h) - q(h)\|$, where $p(h)$ involves $v_{00}, v_{01}$ and $q(h)$ involves $v_{10}, v_{11}$, we infer:
        *   $p(h)$ lies on the left vertical edge (between $v_{00}$ and $v_{01}$).
        *   $q(h)$ lies on the right vertical edge (between $v_{10}$ and $v_{11}$).
        *   *Correction/Refinement:* The source text says "one vertex moving along the top edge and one along the bottom edge" in the description, but the formula uses indices 00, 01 (left) and 10, 11 (right). Let's look at the formula terms:
            $$ p(h) = v_{00} + \frac{h - h_{00}}{h_{01} - h_{00}} (v_{01} - v_{00}) $$
            This is linear interpolation on the edge $(v_{00}, v_{01})$, i.e., the **left** edge.
            $$ q(h) = v_{10} + \frac{h - h_{10}}{h_{11} - h_{10}} (v_{11} - v_{10}) $$
            This is linear interpolation on the edge $(v_{10}, v_{11})$, i.e., the **right** edge.
            The text description "top edge and one along the bottom edge" might refer to a specific orientation or a different labeling convention, but the formula is explicit. The formula calculates the distance between the intersection on the left edge and the intersection on the right edge.
3.  **Calculate Edge Length:** Compute the length $L(h)$ of the segment connecting $p(h)$ and $q(h)$:
    $$ L(h) = \| p(h) - q(h) \| $$
    Where:
    $$ p(h) = v_{00} + \left( \frac{h - h_{00}}{h_{01} - h_{00}} \right) (v_{01} - v_{00}) $$
    $$ q(h) = v_{10} + \left( \frac{h - h_{10}}{h_{11} - h_{10}} \right) (v_{11} - v_{10}) $$
4.  **Generate Surface:**
    *   In Case 8, the surface is a single edge connecting $p(h)$ and $q(h)$.
    *   In Case 11, the surface is a triangular patch.
    *   In intermediate states, the surface is defined by the evolving positions of $p(h)$ and $q(h)$ as $h$ varies, creating a non-polynomial surface patch between the edge and triangle configurations.

**Pitfalls:**
*   **Non-Polynomial Behavior:** Unlike the Red Path interpolant which uses piecewise polynomial (linear) sweeps, the Cyclic Face Interpolant involves rational functions due to the division by $(h_{01} - h_{00})$ and $(h_{11} - h_{10})$. This makes frequency domain analysis difficult [S1, book].
*   **Division by Zero:** If $h_{01} = h_{00}$ or $h_{11} = h_{10}$, the interpolation factor is undefined. This requires a guard condition [G].
*   **Topology Ambiguity:** This method resolves the ambiguity by choosing a specific cyclic path, but it may not always represent the true underlying topology if the data is noisy [S1, book].

    """
    Computes the surface segment for a Marching Squares cell with an ambiguous face
    using the Cyclic (Blue) Path interpolant.
    
    Args:
        v00, v01, v10, v11: 3D positions of the cell vertices.
        h00, h01, h10, h11: Scalar values at the cell vertices.
        h: The isovalue.
        
    Returns:
        A list of surface primitives (e.g., edges or triangles).
    """
    # Guard against division by zero in interpolation
    if h01 == h00:
        # Handle degenerate case: if h01 == h00, the edge is constant.
        # If h is within the range, the intersection is undefined or entire edge.
        # Standard practice: clamp or use midpoint. [G]
        t_left = 0.5 
    else:
        t_left = (h - h00) / (h01 - h00)
        
    if h11 == h10:
        t_right = 0.5
    else:
        t_right = (h - h10) / (h11 - h10)
        
    # Clamp t to [0, 1] to stay within edge bounds
    t_left = max(0.0, min(1.0, t_left))
    t_right = max(0.0, min(1.0, t_right))
    
    # Calculate intersection points p(h) and q(h)
    # p(h) on left edge (v00 to v01)
    p_h = v00 + t_left * (v01 - v00)
    
    # q(h) on right edge (v10 to v11)
    q_h = v10 + t_right * (v11 - v10)
    
    # Determine surface primitive based on case
    # Case 8: Single edge
    # Case 11: Triangular surface
    # Intermediate: Non-polynomial patch
    
    # For implementation, we typically output the edge for Case 8.
    # For Case 11, the source implies a triangular surface.
    # The exact triangulation for Case 11 in the Blue Path is not fully detailed in the snippet,
    # but it ends with a triangular surface.

## Subtopics

### Zigzag Face Interpolant (Green Path)
An interpolant for Marching Squares cells where vertices are swept in a zigzag fashion [S1, book]. It shares characteristics with cyclic faces, including non-polynomial intermediate sections [S1, book]. Triangles are swept through when the edges defining the contour share a vertex, and an intermediate section with non-polynomial behavior occurs between the triangular sweeps [S1, book]. It is chosen when the zigzag topology is preferred over the cyclic topology for resolving ambiguity.

### Asymptotic Decider
An alternative method to adjudicate ambiguous faces, resulting in four triangular sections induced by the actual contours and a flat diamond in the middle connecting them [S1, book]. It is not an interpolant in the same sense as the Red/Blue/Green paths but serves as a disambiguation strategy.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per cell, as it involves a constant number of arithmetic operations.
*   **Memory Complexity:** $O(1)$ per cell.
*   **Strengths:** Provides a continuous surface for ambiguous cases.
*   **Limitations:** The non-polynomial nature makes it unsuitable for frequency domain analysis [S1, book]. It is data-dependent, meaning the interpolant is not the same in every cell, which poses a problem for frequency domain analysis [S1, book].
*   **When to use:** When a continuous surface is required for ambiguous faces and the non-polynomial behavior is acceptable.
*   **When not to use:** When frequency domain analysis is required or when polynomial interpolants are preferred for simplicity.

## Background
The Cyclic Face Interpolant is described in the context of "Interpolants Induced by Marching Cases" [S1, book]. It is one of several methods (along with the Red Path and Green Path) for handling ambiguous faces in Marching Squares/Marching Cubes algorithms. The work is attributed to H. Carr and E. Murphy [S1, book].
