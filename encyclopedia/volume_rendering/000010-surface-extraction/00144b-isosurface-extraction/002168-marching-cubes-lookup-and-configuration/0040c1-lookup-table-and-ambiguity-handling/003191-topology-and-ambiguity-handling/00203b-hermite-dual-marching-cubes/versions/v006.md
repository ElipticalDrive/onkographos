# Hermite Dual Marching Cubes

Also called: Dual Marching Cubes with Hermite data, Hermite Dual Contouring, Hermite extension to Dual MC, Nielson's Dual Marching Cubes with QEF

## Overview
Hermite Dual Marching Cubes is a surface extraction method that combines the topological guarantees of Dual Marching Cubes with the feature-preserving capabilities of Dual Contouring [S1][S2, unofficial]. It solves the problem of non-manifold artifacts in standard Dual Contouring on uniform grids while accurately reproducing sharp features using Hermite data (normals) [S2, unofficial]. Unlike standard Dual Contouring, which may produce non-manifold vertices and edges in ambiguous configurations, this method always produces a topological manifold [S1][S2, unofficial]. Unlike standard Marching Cubes, which produces a manifold but fails to reproduce sharp features, this method preserves sharp features by minimizing a Quadratic Error Function (QEF) [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A uniform 3D grid where each edge intersecting the isosurface has associated Hermite data: an intersection point $\mathbf{p}$ and a normal vector $\mathbf{n}$. The scalar field values at grid vertices determine the topology via the standard Marching Cubes case index $C$ [S2, unofficial].
*   **Output:** A manifold quadrilateral mesh representing the isosurface.

**Data Structures:**
*   **Grid:** Uniform 3D grid.
*   **Edge Data:** For each grid edge intersecting the isosurface, store the intersection point $\mathbf{p}$ and normal $\mathbf{n}$.
*   **Vertex List:** A list of vertices, where each vertex corresponds to a cycle of intersected edges within a grid cell.
*   **Polygon List:** A list of quadrilaterals, where each quadrilateral corresponds to a grid edge shared by four adjacent cells.

**Steps:**
1.  **Identify Intersected Edges:** For each cell in the grid, determine the sign-change edges based on the scalar field values at the vertices relative to the isovalue.
2.  **Determine Topology:** Use a modified Marching Cubes lookup table to identify the contour topology within the cell. This identifies cycles of intersected edges [S2, unofficial].
3.  **Construct QEF for Vertices:** For each identified cycle (representing a contour component within the cell), construct a Quadratic Error Function (QEF) using the Hermite data (intersection points and normal vectors) from all edges associated with that cycle [S2, unofficial].
    *   The QEF for a vertex $\mathbf{v}$ is defined as:
        $$ E(\mathbf{v}) = \sum_{i} ((\mathbf{v} - \mathbf{p}_i) \cdot \mathbf{n}_i)^2 $$
        where $\mathbf{p}_i$ and $\mathbf{n}_i$ are the intersection point and normal of the $i$-th edge in the cycle [S1][S2, unofficial].
4.  **Place Vertices:** Place the vertex for each cycle at the location that minimizes the constructed QEF [S2, unofficial]. This is typically solved by finding the null space of the QEF matrix or using least-squares minimization [S1].
5.  **Generate Polygons:** For each sign-change edge in the grid, construct a quadrilateral polygon by connecting the vertices associated with that edge in the four adjacent cells sharing that edge [S2, unofficial]. This creates a surface dual to the Marching Cubes surface.

**Pseudocode:**
```python
def hermite_dual_marching_cubes(grid, isovalue):
    """
    Extracts a manifold isosurface from a uniform grid using Hermite Dual Marching Cubes.
    
    Args:
        grid: A 3D grid structure containing scalar field values and Hermite data on edges.
        isovalue: The scalar value defining the isosurface.
        
    Returns:
        vertices: List of vertex positions.
        polygons: List of quadrilaterals (each is a list of 4 vertex indices).
    """
    vertices = []
    polygons = []
    
    # Map from edge index to vertex index in the output mesh
    edge_to_vertex = {}
    
    # Step 1 & 2: Identify intersected edges and determine topology per cell
    for cell in grid.cells:
        # Determine the 8-bit case index C based on scalar field values at vertices
        case_index = compute_marching_cubes_case(cell.vertices, isovalue)
        
        # Identify intersected edges and cycles using modified lookup table
        intersected_edges = get_intersected_edges(case_index)
        cycles = get_edge_cycles(case_index, intersected_edges)
        
        # Step 3 & 4: Construct QEF and place vertices for each cycle
        for cycle in cycles:
            # Collect Hermite data for all edges in the cycle
            hermite_data = []
            for edge in cycle:
                hermite_data.append((edge.intersection_point, edge.normal))
            
            # Construct and minimize QEF to find vertex position
            vertex_position = minimize_qef(hermite_data)
            
            # Create a new vertex in the output mesh
            vertex_index = len(vertices)
            vertices.append(vertex_position)
            
            # Map each edge in the cycle to this vertex
            for edge in cycle:
                edge_to_vertex[edge.id] = vertex_index
                
    # Step 5: Generate polygons for each intersected edge
    for edge in grid.all_intersected_edges:
        # Get the four adjacent cells sharing this edge
        adjacent_cells = get_adjacent_cells(edge)
        
        # Retrieve the vertex indices associated with this edge from each adjacent cell
        vertex_indices = []
        for cell in adjacent_cells:
            # The vertex index is stored in edge_to_vertex for this edge
            # Note: In a consistent implementation, all four cells must agree on the vertex index
            # for this edge. Dual Marching Cubes ensures this by associating one vertex per cycle
            # and one cycle per edge in the dual topology.
            v_idx = edge_to_vertex.get(edge.id)
            if v_idx is not None:
                vertex_indices.append(v_idx)
        
        # Create a quadrilateral polygon
        if len(vertex_indices) == 4:
            polygons.append(vertex_indices)
            
    return vertices, polygons

def minimize_qef(hermite_data):
    """
    Minimizes the Quadratic Error Function E(v) = sum((v - p_i) . n_i)^2.
    
    Args:
        hermite_data: List of tuples (p_i, n_i).
        
    Returns:
        The vertex position v that minimizes the error.
    """
    # Construct the QEF matrix A and vector b
    # E(v) = v^T A v - 2 b^T v + c
    # A = sum(n_i * n_i^T)
    # b = sum((n_i . p_i) * n_i)
    
    A = zero_matrix(3, 3)
    b = zero_vector(3)
    
    for p, n in hermite_data:
        # Outer product of normal
        A += outer_product(n, n)
        # Projection of point onto normal
        projection = dot(n, p)
        b += projection * n
        
    # Solve the linear system A * v = b for v
    # If A is singular, use pseudo-inverse or regularization [G]
    v = solve_linear_system(A, b)
    
    return v
```

**Parameters:**
*   **Isovalue:** The scalar value defining the isosurface. Typical values depend on the data range.
*   **QEF Solver:** The method for solving the linear system $A\mathbf{v} = \mathbf{b}$. Least-squares or pseudo-inverse is common [S1].

**Edge Cases and Pitfalls:**
*   **Singular QEF Matrix:** If the Hermite data is degenerate (e.g., all normals are parallel), the matrix $A$ may be singular. Regularization or pseudo-inverse is required [G].
*   **Ambiguous Configurations:** Standard Dual Contouring fails in ambiguous Marching Cubes cases. Hermite Dual Marching Cubes handles these by using the modified lookup table to identify cycles, ensuring manifold topology [S2, unofficial].
*   **Precision:** Minimizing the QEF requires numerical stability, especially when normals are nearly parallel or points are collinear [G].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of grid cells. Each cell is processed independently, and QEF minimization is a constant-time operation per cycle (typically small number of edges).
*   **Memory Complexity:** $O(N)$ for storing the grid, edge data, and output mesh.
*   **Strengths:** Always produces a manifold mesh; accurately reproduces sharp features using Hermite data; handles ambiguous Marching Cubes cases correctly.
*   **Limitations:** Requires Hermite data (normals) on edges, which may need to be computed or provided; more complex than standard Marching Cubes; QEF minimization adds computational overhead.
*   **When to Use:** When a manifold mesh is required and sharp features must be preserved, especially in ambiguous configurations.
*   **When Not to Use:** When Hermite data is not available; when computational speed is critical and feature preservation is not important.

## Background
Hermite Dual Marching Cubes was developed as an extension of Nielson's Dual Marching Cubes algorithm to incorporate Hermite data for feature preservation [S1][S2, unofficial]. Standard Dual Contouring, while capable of reproducing sharp features, can produce non-manifold topology in ambiguous Marching Cubes configurations on uniform grids [S2, unofficial]. Nielson's Dual Marching Cubes ensures manifold topology but does not inherently preserve sharp features. The Hermite extension combines these approaches by using QEF minimization within the Dual Marching Cubes framework [S1][S2, unofficial]. The method was presented in the paper "Manifold Dual Contouring" [S1][S2, unofficial].
