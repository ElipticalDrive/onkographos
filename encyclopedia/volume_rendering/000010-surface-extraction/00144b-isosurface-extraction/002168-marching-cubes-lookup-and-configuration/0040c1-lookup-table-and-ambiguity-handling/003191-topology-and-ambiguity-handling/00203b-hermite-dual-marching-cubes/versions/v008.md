# Hermite Dual Marching Cubes

Also called: Dual Marching Cubes with Hermite data, Hermite Dual Contouring, Hermite extension to Dual MC, Nielson's Dual Marching Cubes with QEF

## Overview
Hermite Dual Marching Cubes is an isosurface extraction method that combines the topological guarantees of Dual Marching Cubes with the feature-preserving capability of Dual Contouring [S1][S2, unofficial]. It solves the problem of non-manifold vertices and edges that arise in standard Dual Contouring when applied to uniform grids with ambiguous sign configurations, while simultaneously reproducing sharp features that standard Marching Cubes fails to capture [S1][S2, unofficial]. Unlike standard Dual Contouring, which may produce non-manifold topology, this method always produces a topological manifold by leveraging the dual structure of the Marching Cubes lookup table [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A uniform 3D grid of scalar field values $f(x,y,z)$ and associated Hermite data (normal vectors) at grid vertices or edge intersections.
*   **Output:** A manifold triangular or quadrilateral mesh representing the isosurface.

**Data Structures:**
The method relies on the precomputed data structures defined in [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md), specifically the `edgeTable` and `triangleTable`. However, instead of generating triangles directly from the `triangleTable`, it identifies cycles of edges within each voxel to associate vertices with those cycles.

**Algorithm Steps:**

1.  **Identify Sign-Change Edges:** For each voxel in the grid, determine which edges intersect the isosurface (where the scalar field changes sign).
2.  **Determine Topology via Lookup Table:** Use a modified Marching Cubes lookup table to identify the contour topology within the voxel. This step identifies cycles of edges that form closed loops on the voxel boundary [S2, unofficial]. Each cycle corresponds to a potential vertex location in the dual surface.
3.  **Construct Quadratic Error Function (QEF):** For each identified cycle (which represents a contour component within the cell), construct a Quadratic Error Function (QEF) using the Hermite data (intersection points and normal vectors) from all edges associated with that cycle [S1][S2, unofficial].
    *   Let $E$ be the set of edges associated with a cycle.
    *   For each edge $e \in E$, let $p_e$ be the intersection point of the edge with the isosurface and $n_e$ be the normal vector at that point.
    *   The QEF for a candidate vertex position $v$ is defined as:
        $$ Q(v) = \sum_{e \in E} ((v - p_e) \cdot n_e)^2 $$
    *   This minimizes the distance from $v$ to the planes defined by the Hermite data on the associated edges [S1][S2, unofficial].
4.  **Minimize QEF to Place Vertex:** Solve for the vertex position $v^*$ that minimizes the QEF. This is typically done by solving the linear system derived from setting the gradient of $Q(v)$ to zero:
    $$ \left( \sum_{e \in E} n_e n_e^T \right) v^* = \sum_{e \in E} (n_e \cdot p_e) n_e $$
    *   Let $A = \sum_{e \in E} n_e n_e^T$ and $b = \sum_{e \in E} (n_e \cdot p_e) n_e$. Then $v^* = A^{-1} b$ [S1][S2, unofficial].
    *   If the system is singular (e.g., all normals are parallel), a fallback strategy is needed [G].
5.  **Generate Polygons:** For each sign-change edge in the grid, construct a polygon connecting the vertices associated with that edge in the four adjacent cells sharing that edge [S2, unofficial]. This creates a quadrilateral surface that is dual to the Marching Cubes surface [S2, unofficial].

**Pseudocode:**

```python
def hermite_dual_marching_cubes(grid, isovalue):
    """
    Extracts a manifold isosurface using Hermite Dual Marching Cubes.
    
    Args:
        grid: A 3D array of scalar values f(x,y,z).
        isovalue: The scalar value defining the isosurface.
        
    Returns:
        vertices: List of vertex positions.
        faces: List of triangular or quadrilateral faces.
    """
    vertices = []
    faces = []
    
    # Map from edge index to vertex index in the output mesh
    # Edge index can be uniquely identified by (voxel_origin, edge_id)
    edge_to_vertex = {}
    
    # Precompute Hermite data (normals) at edge intersections
    # This assumes normals are available or can be computed from the gradient of the scalar field
    edge_data = compute_edge_hermite_data(grid, isovalue)
    
    # Process each voxel
    for voxel in grid.voxels:
        # 1. Identify sign-change edges
        sign_change_edges = []
        for edge in voxel.edges:
            if sign_change(edge.start_value, edge.end_value, isovalue):
                sign_change_edges.append(edge)
        
        # 2. Determine topology using modified Marching Cubes lookup table
        # This identifies cycles of edges within the voxel
        cycles = identify_cycles(voxel, sign_change_edges)
        
        # 3 & 4. Construct QEF and minimize to place vertices
        cycle_vertices = []
        for cycle in cycles:
            # Collect Hermite data for all edges in the cycle
            hermite_data = []
            for edge in cycle:
                hermite_data.append(edge_data[edge])
            
            # Construct and solve QEF
            A = zero_matrix(3, 3)
            b = zero_vector(3)
            for data in hermite_data:
                n = data.normal
                p = data.intersection_point
                A += outer_product(n, n)
                b += dot(n, p) * n
            
            # Solve Av = b for v
            # Note: In practice, use a robust linear solver. 
            # If A is singular, handle degenerate case [G]
            v = solve_linear_system(A, b)
            cycle_vertices.append(v)
            
            # Store vertex in a global list and map cycle to vertex index
            vertex_index = len(vertices)
            vertices.append(v)
            cycle.vertex_index = vertex_index
            
        # 5. Generate polygons
        # For each sign-change edge, connect vertices from adjacent voxels
        for edge in sign_change_edges:
            # Get the vertex associated with this edge from the current voxel
            # The edge is part of a cycle, so we need to find which cycle contains this edge
            current_voxel_vertex = None
            for cycle in cycles:
                if edge in cycle.edges:
                    current_voxel_vertex = cycle.vertex_index
                    break
            
            # Get vertices from adjacent voxels sharing this edge
            adjacent_voxel_vertices = []
            for adjacent_voxel in edge.adjacent_voxels:
                if adjacent_voxel == voxel:
                    continue
                # Find the vertex associated with this edge in the adjacent voxel
                # This requires a global map of edge to vertex
                if edge in edge_to_vertex:
                    adjacent_voxel_vertices.append(edge_to_vertex[edge])
                else:
                    # This case should not happen if processing is consistent
                    pass
            
            # Create polygon connecting vertices
            # The polygon connects the vertex from the current voxel to vertices from adjacent voxels
            # The exact connectivity depends on the dual structure
            if current_voxel_vertex is not None and len(adjacent_voxel_vertices) > 0:
                # Construct quadrilateral or triangle
                face = [current_voxel_vertex] + adjacent_voxel_vertices
                faces.append(face)
                
            # Store edge to vertex mapping for adjacent voxels
            edge_to_vertex[edge] = current_voxel_vertex
            
    return vertices, faces

def compute_edge_hermite_data(grid, isovalue):
    """
    Computes intersection points and normals for all edges crossing the isosurface.
    """
    edge_data = {}
    for edge in grid.edges:
        if sign_change(edge.start_value, edge.end_value, isovalue):
            # Linear interpolation for intersection point
            t = (isovalue - edge.start_value) / (edge.end_value - edge.start_value)
            p = lerp(edge.start_position, edge.end_position, t)
            
            # Compute normal (gradient of scalar field)
            # This can be approximated using finite differences or provided as input
            n = compute_gradient(grid, p)
            n = normalize(n)
            
            edge_data[edge] = {'intersection_point': p, 'normal': n}
    return edge_data

def sign_change(v1, v2, isovalue):
    """
    Checks if the scalar values at v1 and v2 straddle the isovalue.
    """
    return (v1 - isovalue) * (v2 - isovalue) < 0
```

**Parameters:**
*   **Isovalue:** The scalar value defining the isosurface. Typical values depend on the application (e.g., 0 for signed distance fields).
*   **Grid Resolution:** The resolution of the input scalar field. Higher resolution yields more accurate surfaces but increases computational cost.

**Edge Cases and Pitfalls:**
*   **Singular QEF:** If the normals associated with a cycle are linearly dependent (e.g., all parallel), the matrix $A$ in the QEF minimization is singular. A fallback strategy, such as using the centroid of the intersection points, is required [G].
*   **Ambiguous Configurations:** The method relies on the modified Marching Cubes lookup table to handle ambiguous configurations. Incorrect handling of these cases can lead to non-manifold topology [S2, unofficial].
*   **Precision:** Numerical precision issues in solving the QEF or computing gradients can affect the accuracy of the vertex positions [G].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels in the grid. Each voxel is processed independently, and the QEF minimization involves solving a small linear system (3x3 matrix inversion), which is constant time.
*   **Memory Complexity:** $O(N)$, for storing the grid data and the resulting mesh. The number of vertices and faces is proportional to the number of sign-change edges.
*   **Measured Performance:** Performance depends on the implementation of the linear solver and the efficiency of the grid traversal. On uniform grids, the method is efficient due to the regular structure.
*   **Scaling:** The method scales well with grid resolution, but the memory usage increases linearly. Parallelization is straightforward as voxel processing is independent.
*   **Strengths:** Always produces a manifold surface; reproduces sharp features; robust to ambiguous configurations.
*   **Limitations:** Requires Hermite data (normals); may produce more complex polygons than standard Marching Cubes; sensitive to noise in the Hermite data.
*   **When to use:** When a manifold surface is required and sharp features need to be preserved, especially on uniform grids.
*   **When not to use:** When Hermite data is not available; when computational resources are extremely limited and simplicity is preferred over feature preservation.

## Background
Hermite Dual Marching Cubes was introduced as an extension to Nielson's Dual Marching Cubes algorithm to incorporate Hermite data for sharp feature preservation [S1][S2, unofficial]. It addresses the limitations of standard Dual Contouring, which can produce non-manifold topology on uniform grids, and standard Marching Cubes, which fails to reproduce sharp features [S1][S2, unofficial]. The method builds on the topological guarantees of Dual Marching Cubes while leveraging the feature-preserving capabilities of Dual Contouring [S1][S2, unofficial].
