# Hermite Dual Marching Cubes

Also called: Dual Marching Cubes with Hermite data, Hermite Dual Contouring, Hermite extension to Dual MC, Nielson's Dual Marching Cubes with QEF

## Overview
Hermite Dual Marching Cubes is a surface extraction method that combines the topological guarantees of Dual Marching Cubes with the feature-preserving capability of Dual Contouring [S1][S2, unofficial]. It solves the problem of non-manifold vertices and edges that arise in standard Dual Contouring when processing ambiguous sign configurations on uniform grids, while simultaneously reproducing sharp features that standard Marching Cubes fails to capture [S2, unofficial]. Unlike standard Dual Contouring, which may produce non-manifold topology, this method always produces a topological manifold by leveraging the dual structure of the Marching Cubes topology [S1][S2, unofficial].

## How it works
**Inputs:**
*   A uniform 3D grid of scalar field values $f(v)$ at vertices $v$.
*   Hermite data associated with the grid edges: for each edge intersecting the isosurface, the intersection point $p$ and the normal vector $n$ (gradient direction) [S1][S2, unofficial].

**Outputs:**
*   A manifold triangular or quadrilateral mesh representing the isosurface [S2, unofficial].

**Data Structures:**
*   **Grid:** Uniform 3D lattice.
*   **Edge Data:** For each grid edge, store the Hermite data $(p, n)$ if the edge intersects the isosurface (sign change between endpoints) [S2, unofficial].
*   **Cell Lookup:** A modified Marching Cubes lookup table that identifies cycles of intersected edges within a cell [S2, unofficial].
*   **Vertex Map:** A mapping from each identified cycle (or edge, depending on implementation detail) to a vertex position [S2, unofficial].

**Steps:**

1.  **Identify Intersections:** For each cell in the grid, determine which edges intersect the isosurface by checking for sign changes in the scalar field values at the cell's vertices [S2, unofficial].

2.  **Determine Topology (Cycle Identification):** For each cell, use a modified Marching Cubes lookup table to identify the contour topology [S2, unofficial]. This table groups the intersected edges into disjoint cycles. Each cycle represents a closed loop of edges on the cell boundary that forms a contour component [S2, unofficial].

3.  **Construct QEF for Vertices:**
    *   **For Dual Marching Cubes Vertices:** Nielson's Dual Marching Cubes associates one vertex with each cycle identified in Step 2 [S2, unofficial]. For each cycle, construct a Quadratic Error Function (QEF) using the Hermite data (intersection points $p_i$ and normal vectors $n_i$) from all edges associated with that cycle [S2, unofficial].
    *   **For Edge Vertices (Standard Dual MC):** In the base Dual Marching Cubes algorithm, a vertex is associated with each intersected edge. For each such vertex, construct a QEF using the Hermite data on the edges associated with that vertex [S1].
    *   *Note:* The sources describe incorporating Hermite data into Nielson's Dual MC by constructing a QEF for each vertex (associated with a cycle) using the Hermite data on the edges associated with that cycle [S1][S2, unofficial].

4.  **Minimize QEF:** Place the vertex at the location that minimizes the constructed QEF error [S1][S2, unofficial]. The QEF for a set of Hermite constraints is defined as:
    $$ E(x) = \sum_{i} (n_i^T (x - p_i))^2 $$
    where $n_i$ is the normal vector and $p_i$ is the intersection point for the $i$-th Hermite constraint [S1][S2, unofficial]. Minimizing this quadratic function yields the optimal vertex position $x^*$ [S1][S2, unofficial].

5.  **Generate Polygons:** Construct polygons by connecting the vertices associated with each sign-change edge across the four adjacent cells sharing that edge [S2, unofficial]. This creates a quadrilateral surface that is dual to the surface created using standard Marching Cubes [S2, unofficial].

**Pseudocode:**

```python
def hermite_dual_marching_cubes(grid, isovalue):
    """
    Extracts a manifold isosurface using Hermite Dual Marching Cubes.
    
    Args:
        grid: 3D array of scalar field values.
        isovalue: The scalar value defining the isosurface.
        
    Returns:
        vertices: List of vertex positions.
        faces: List of triangular or quadrilateral faces.
    """
    vertices = {}  # Map from (cycle_id or edge_id) to vertex position
    faces = []
    
    # Step 1 & 2: Identify intersections and cycles for each cell
    for each cell in grid:
        intersected_edges = get_intersected_edges(cell, grid, isovalue)
        cycles = identify_cycles(intersected_edges, cell)
        
        # Step 3 & 4: Construct QEF and minimize for each cycle
        for cycle in cycles:
            hermite_data = get_hermite_data(cycle, grid) # List of (p, n)
            qef = construct_qef(hermite_data)
            vertex_pos = minimize_qef(qef)
            vertices[cycle.id] = vertex_pos
            
    # Step 5: Generate polygons
    for each edge in grid:
        if edge intersects isosurface:
            # Get vertices from the four adjacent cells sharing this edge
            cell_vertices = []
            for adjacent_cell in edge.adjacent_cells:
                # Find the cycle or vertex associated with this edge in the adjacent cell
                cycle = find_cycle_for_edge(edge, adjacent_cell)
                if cycle.id in vertices:
                    cell_vertices.append(vertices[cycle.id])
            
            # Connect vertices to form a polygon (typically a quad)
            if len(cell_vertices) == 4:
                faces.append(cell_vertices)
            elif len(cell_vertices) == 3:
                faces.append(cell_vertices)
                
    return vertices.values(), faces

    edges = []

        if (grid[v1] - isovalue) * (grid[v2] - isovalue) < 0:

def construct_qef(hermite_data):
    """
    Constructs a QEF from Hermite data.
    E(x) = sum((n_i . (x - p_i))^2)
    """
    # The QEF can be represented as Ax = b, where A = sum(n_i * n_i^T) and b = sum((n_i . p_i) * n_i)
    A = zero_matrix(3, 3)
    b = zero_vector(3)
    for p, n in hermite_data:
        A += outer_product(n, n)
        b += dot(n, p) * n
    return {'A': A, 'b': b}
```

*   **Isovalue:** The scalar threshold for surface extraction.

**Edge Cases and Pitfalls:**
*   **Singular QEF:** If the Hermite data is degenerate (e.g., all normals are parallel), the matrix $A$ may be singular. A fallback or regularization is required [G].
*   **Ambiguity Resolution:** The modified Marching Cubes lookup table must be consistent across shared edges of adjacent cells to prevent cracks [S2, Parent, unofficial].
*   **Sharp Features:** The method preserves sharp features by using Hermite data in the QEF minimization, but the accuracy depends on the quality of the normal estimates [S2, unofficial].

## Subtopics

### Dual Marching Cubes
The topological foundation. It produces a manifold surface by associating vertices with cycles of intersected edges and generating dual polygons. It guarantees manifold topology but does not inherently preserve sharp features without Hermite data. [Link](6547-topology-and-ambiguity-handling.md)

### Dual Contouring
A method that uses Hermite data and QEF minimization to place vertices accurately, preserving sharp features. However, it can produce non-manifold topology on uniform grids for ambiguous configurations. [Link](6547-topology-and-ambiguity-handling.md)

### Marching Cubes with Disjoint Patch Decomposition
An alternative approach that decomposes the voxel into smaller sub-elements to resolve ambiguities. It produces a manifold surface but may not preserve sharp features as effectively as Hermite-based methods. [Link](5004-marching-cubes-with-disjoint-patch-decomposition.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of cells in the grid. Each cell is processed independently to identify cycles and solve small linear systems (QEF minimization).
*   **Memory Complexity:** $O(N)$ for storing the grid, Hermite data, and output mesh.
*   **Strengths:**
    *   Always produces a topological manifold [S1][S2, unofficial].
    *   Reproduces sharp features using Hermite data [S1][S2, unofficial].
    *   Robust against non-manifold configurations that affect standard Dual Contouring [S2, unofficial].
*   **Limitations:**
    *   Requires Hermite data (normals) on edges, which may need to be estimated or provided.
    *   More complex implementation than standard Marching Cubes due to cycle identification and QEF solving.
    *   Performance may be impacted by the cost of solving QEFs for each vertex/cycle.
*   **When to Use:** When a manifold surface is required, sharp features must be preserved, and the input data includes or can be augmented with Hermite data (normals).
*   **When Not to Use:** When Hermite data is unavailable and cannot be estimated, or when computational resources are extremely limited and sharp feature preservation is not critical.

## Background
Hermite Dual Marching Cubes was developed as an extension of Nielson's Dual Marching Cubes algorithm to incorporate Hermite data for sharp feature preservation [S1][S2, unofficial]. It addresses the limitations of standard Dual Contouring, which can produce non-manifold topology on uniform grids, while maintaining the manifold guarantee of Dual Marching Cubes [S1][S2, unofficial]. The method was introduced in the paper "Manifold Dual Contouring" [S1][S2, unofficial].
