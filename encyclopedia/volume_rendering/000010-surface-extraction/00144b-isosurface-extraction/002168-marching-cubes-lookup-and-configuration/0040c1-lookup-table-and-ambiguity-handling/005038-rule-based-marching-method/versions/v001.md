# Rule-based Marching Method


## Overview
The rule-based marching method is a segmentation technique for generating cell-level interface topology in volume fraction data, specifically designed for mixed cells in multi-material problems [S1, unofficial]. It derives partial vertex labeling from volume fractions and uses lookup tables for binary- and multi-label segmentation cases to determine material interface configurations [S1, unofficial]. Unlike traditional isosurface extraction which forces labels or casts data onto dual meshes, this method implies labels via a small set of logical rules, leaving topology uninitialized if the labeling is ambiguous or insufficient to account for residual materials [S1, unofficial].

## How it works
The method operates on a mesh where cells contain volume fraction data for $n$ materials. The input is the mesh connectivity and the volume fraction values for each material in each cell. The output is a set of interface fragments (topology) for each cell, or an uninitialized state if the rules cannot determine a valid configuration.

### Data Structures
1.  **Vertex Label Map ($L$)**: A map from vertex index $v$ to a label. Labels are integers $\{1, \dots, n\}$ representing known materials, or a special value `undefined` representing unknown material.
2.  **Edge Crossing Count ($\chi$)**: For each edge $e$, an integer representing the number of interface crossings.
3.  **Segmentation Case Tables**: Precomputed tables (binary and multi-label) that map a cell's vertex labeling configuration to a set of interface fragments (edges/vertices). These tables must support multiple intersections per edge and detect ambiguity.

### Steps

1.  **Initialization**:
    Initialize $L(v) = \text{undefined}$ for all vertices $v$ in the mesh. Volume fraction data lacks explicit vertex information, so no initial labels are assumed [S1, unofficial].

2.  **Vertex Labeling**:
    For each vertex $v$, evaluate the following rules to assign a label. Let $N(v)$ be the set of cells neighboring vertex $v$. Let $M(c)$ be the set of materials with non-zero volume fraction in cell $c$.
    
    *   **Pure Cells Rule**:
        Let $P(v)$ be the subset of $N(v)$ containing only "pure" cells (cells with exactly one material with non-zero volume fraction).
        *   If $P(v)$ is not empty:
            *   Let $S$ be the set of materials present in all cells in $P(v)$.
            *   If $S$ contains exactly one material $i$, set $L(v) = i$.
            *   If $S$ contains multiple materials (i.e., neighboring pure cells have different materials), set $L(v) = \text{undefined}$.
        *   If $P(v)$ is empty, proceed to the Neighborhood Rule.
    
    *   **Neighborhood Rule**:
        Let $M_{common}$ be the intersection of materials present in all cells in $N(v)$:
        $$ M_{common} = \bigcap_{c \in N(v)} M(c) $$
        *   If $|M_{common}| = 1$, let $i$ be the single material in $M_{common}$. Set $L(v) = i$.
        *   Otherwise, $L(v)$ remains `undefined`.

3.  **Edge Labeling**:
    For each edge $e$ connecting vertices $v_1$ and $v_2$, determine the number of crossings $\chi(e)$. Let $N(e)$ be the set of cells neighboring edge $e$.
    
    *   **Pure Cells Rule**:
        If any cell $c \in N(e)$ is pure, then $\chi(e) = 0$.
    
    *   **Neighborhood Rule**:
        Let $M_{edge\_common}$ be the intersection of materials present in all cells in $N(e)$:
        $$ M_{edge\_common} = \bigcap_{c \in N(e)} M(c) $$
        *   If $|M_{edge\_common}| = 1$, then $\chi(e) = 0$.
        *   Otherwise, the rule does not force $\chi(e)=0$. The value of $\chi(e)$ is constrained by vertex labels:
            *   If $L(v_1) = L(v_2)$, then $\chi(e) = 0$ or $\chi(e) \ge 2$.
            *   If $L(v_1) \neq L(v_2)$, then $\chi(e) \ge 1$.
            *   [G] In implementation, if vertex labels are defined and mismatched, a common default is $\chi(e)=1$ unless higher-order information suggests otherwise. If labels are undefined, $\chi(e)$ is typically left undefined or handled by the cell lookup.

4.  **Cell Topology Generation**:
    For each cell $c$:
    *   **Check Vertex Labels**: If any vertex $v$ of $c$ has $L(v) = \text{undefined}$, leave the cell topology uninitialized.
    *   **Lookup**: If all vertices are labeled, perform a lookup in the segmentation case table using the vertex labels of $c$.
    *   **Check Ambiguity**: If the case table indicates ambiguity (multiple valid segmentations for the given labeling), leave the topology uninitialized.
    *   **Check Residual Material**:
        Let $M_{cell}$ be the set of materials with non-zero volume fractions in cell $c$.
        Let $M_{verts}$ be the set of material labels assigned to the vertices of $c$.
        *   If $M_{cell} \neq M_{verts}$, the cell has "residual" material (internal pockets or multiple intersections not captured by the vertex labels). Leave the topology uninitialized.
        *   If $M_{cell} = M_{verts}$, the topology returned by the case table is valid.

### Pseudocode

```python
def rule_based_marching(mesh, volume_fractions, n_materials):
    """
    mesh: object with methods get_vertices(), get_edges(), get_cells(), 
          get_neighbor_cells(vertex), get_neighbor_cells(edge)
    volume_fractions: dict mapping (cell_id, material_id) -> float
    n_materials: int
    """
    
    # 1. Initialize Vertex Labels
    L = {}
    for v in mesh.get_vertices():
        L[v] = None  # None represents 'undefined'
        
    # Helper: Get materials with non-zero volume fraction in a cell
    def get_cell_materials(cell_id):
        mats = set()
        for m in range(1, n_materials + 1):
            if volume_fractions.get((cell_id, m), 0.0) > 1e-9:
                mats.add(m)
        return mats

    # Helper: Check if a cell is pure (exactly one material)
    def is_pure(cell_id):
        return len(get_cell_materials(cell_id)) == 1

    # 2. Vertex Labeling
    for v in mesh.get_vertices():
        neighbor_cells = mesh.get_neighbor_cells(v)
        if not neighbor_cells:
            continue
            
        # Pure Cells Rule
        pure_neighbors = [c for c in neighbor_cells if is_pure(c)]
        if pure_neighbors:
            # Intersection of materials in all pure neighbors
            common_mats = None
            for c in pure_neighbors:
                mats = get_cell_materials(c)
                if common_mats is None:
                    common_mats = mats
                else:
                    common_mats = common_mats.intersection(mats)
            
            if len(common_mats) == 1:
                L[v] = common_mats.pop()
            else:
                L[v] = None # Ambiguous pure neighbors
            continue # Skip Neighborhood rule if Pure Cells rule applied
        
        # Neighborhood Rule
        # Intersection of materials in ALL neighbors (pure and mixed)
        common_mats = None
        for c in neighbor_cells:
            mats = get_cell_materials(c)
            if common_mats is None:
                common_mats = mats
            else:
                common_mats = common_mats.intersection(mats)
        
        if common_mats and len(common_mats) == 1:
            L[v] = common_mats.pop()
        else:
            L[v] = None

    # 3. Edge Labeling (Crossings)
    # Note: The source describes constraints on chi, not a single deterministic value for all cases.
    # We store constraints or a best-effort value. For topology lookup, we often just need vertex labels.
    # However, the cell lookup depends on vertex labels. Edge crossings are implicitly handled 
    # by the case table if the table supports multiple intersections.
    # The source states: "edges with matching labels... chi=0 or chi>=2; mismatched... chi>=1".
    # We do not explicitly compute chi for the cell lookup step in the standard algorithm description,
    # but we note the constraints for validation if needed.
    
    # 4. Cell Topology Generation
    cell_topologies = {}
    
    for c in mesh.get_cells():
        vertices = mesh.get_cell_vertices(c)
        
        # Check if all vertices are labeled
        if any(L[v] is None for v in vertices):
            cell_topologies[c] = None
            continue
            
        # Get vertex labels for this cell
        vertex_labels = [L[v] for v in vertices]
        
        # Lookup in segmentation case table
        # The table must handle n-material labeling
        topology = lookup_case_table(vertex_labels, n_materials)
        
        if topology is None or topology.is_ambiguous:
            cell_topologies[c] = None
            continue
            
        # Check Residual Material
        cell_mats = get_cell_materials(c)
        vert_mats = set(vertex_labels)
        
        if cell_mats != vert_mats:
            cell_topologies[c] = None
        else:
            cell_topologies[c] = topology
            
    return cell_topologies
```

## Subtopics

### Lookup Table and Ambiguity Handling
The core mechanism for translating vertex labels into geometry. The rule-based method relies on custom tables that support multiple intersections and detect ambiguity, differing from standard Marching Cubes [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md).

### Algorithmic Modifications and Improvements
Techniques to resolve uninitialized cells (e.g., using a discretized boundary method or volume-adaptive active interface optimization) after the rule-based marching pass [Algorithmic Modifications and Improvements](11203-algorithmic-modifications-and-improvements.md).

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of vertices, edges, and cells, as each element is processed a constant number of times using local neighborhood information.
*   **Memory Complexity**: Linear, storing vertex labels, edge constraints, and output topology.
*   **Strengths**: Handles complex multi-material interfaces, thin filaments, and shells better than standard binary isosurfacing. It avoids the "forcing" of labels which can introduce artifacts.
*   **Limitations**: Leaves many cells uninitialized if the volume fraction data is complex or noisy, requiring a fallback method (like the discretized boundary method) to complete the reconstruction [S1, unofficial].
*   **When to use**: When dealing with volume fraction data (e.g., from Volume of Fluid methods) where material interfaces are sharp and topology is critical.
*   **When not to use**: For smooth scalar fields where standard Marching Cubes is sufficient and faster.

## Background
The rule-based marching method was developed for the visualization of volume fraction data in multi-material problems, such as those arising in computational fluid dynamics [S1, unofficial]. It was proposed as an improvement over previous methods like Bonnell et al. (who cast data onto dual meshes) and Meredith (who forced vertex labels via volume averaging) by implying labels through logical rules [S1, unofficial]. The method is part of a broader pipeline that may include post-processing steps like volume-adaptive active interface optimization to refine the final surface [S1, unofficial].
