# Rule-based Marching Method
## Overview
The rule-based marching method is a topology generation technique for volume fraction data that derives partial vertex labeling and uses lookup tables to determine material interface configurations in mixed cells [S1, unofficial]. Unlike methods that force vertex labels via volume averaging or cast data onto dual meshes, this approach implies labels through a small set of logical rules, leaving topology uninitialized when the labeling is ambiguous or insufficient [S1, unofficial]. It is specifically designed to handle multiple materials and complex features like thin filaments by allowing multiple intersections per edge, which standard binary marching cubes do not support [S1, unofficial].
## How it works
The method operates on a mesh where vertices are initially unlabeled because volume fraction data lacks explicit vertex information [S1, unofficial]. It proceeds by deriving a partial labeling of vertices and edges, then using segmentation lookup tables to generate cell-level interface topologies [S1, unofficial].

### Inputs and Outputs
*   **Input**: A mesh structure (vertices, edges, cells) and volume fraction data $V$ for each cell, specifying the fraction of each material present [S1, unofficial].
*   **Output**: A set of cell-level interface topologies (surface fragments) for cells where the topology can be unambiguously determined [S1, unofficial]. Cells that fail the rules remain uninitialized [S1, unofficial].

### Data Structures
1.  **Vertex Label Map $L$**: A map from vertex index $v$ to a material label or `undefined` [S1, unofficial].
    *   Domain: $\{1, \dots, n\}$ for $n$ materials, or `undefined` [S1, unofficial].
2.  **Edge Intersection Count $\chi$**: A map from edge index $e$ to an integer representing the number of interface crossings [S1, unofficial].
    *   Values: $0$, $1$, or $\ge 2$ [S1, unofficial].
3.  **Segmentation Case Tables**: Precomputed lookup tables for 2D and 3D cells [S1, unofficial].
    *   These tables map a cell's vertex labeling configuration to a set of surface fragments [S1, unofficial].
    *   Unlike standard Marching Cubes, these tables support multiple intersections per edge and may indicate "ambiguity" or "residual material" states [S1, unofficial].

### Algorithm Steps
**1. Initialize Vertex Labels**
Initialize $L(v) = \text{undefined}$ for all vertices $v$ in the mesh [S1, unofficial].

**2. Label Vertices**
For each vertex $v$, evaluate the following rules in order [S1, unofficial]. If a rule assigns a label, it is set; otherwise, it remains `undefined` [S1, unofficial].
*   **Pure Cells Rule**: Let $P_v$ be the set of pure cells (cells containing only one material) neighboring $v$ [S1, unofficial].
    *   If $P_v$ is non-empty and all cells in $P_v$ are of the same material $i$, then $L(v) = i$ [S1, unofficial].
    *   If $P_v$ contains cells of different materials, $L(v)$ remains `undefined` [S1, unofficial].
    *   If $P_v$ is empty, proceed to the next rule [S1, unofficial].
*   **Neighborhood Rule**: Let $M_v$ be the set of materials common to all (pure and mixed) cells neighboring $v$ [S1, unofficial].
    *   If $|M_v| = 1$, let $M_v = \{i\}$. Then $L(v) = i$ [S1, unofficial].
    *   Otherwise, $L(v)$ remains `undefined` [S1, unofficial].

**3. Label Edges and Determine Intersections**
For each edge $e$ connecting vertices $v_1$ and $v_2$:
*   **Initial Intersection Estimate**:
    *   If $L(v_1) = L(v_2)$, then $\chi(e) \in \{0, \ge 2\}$ [S1, unofficial].
    *   If $L(v_1) \neq L(v_2)$, then $\chi(e) \ge 1$ [S1, unofficial].
    *   If either $L(v_1)$ or $L(v_2)$ is `undefined`, $\chi(e)$ is not yet determined [S1, unofficial].
*   **Pure Cells Rule**: Let $C_e$ be the set of cells sharing edge $e$ [S1, unofficial].
    *   If any cell in $C_e$ is pure (contains only one material), then $\chi(e) = 0$ [S1, unofficial].
*   **Neighborhood Rule**: Let $M_e$ be the set of materials common to all cells in $C_e$ [S1, unofficial].
    *   If $|M_e| = 1$, then $\chi(e) = 0$ [S1, unofficial].

**4. Generate Cell Topology**
For each cell $c$:
*   **Check Vertex Labeling**: If any vertex $v$ of $c$ has $L(v) = \text{undefined}$, leave $c$'s topology uninitialized [S1, unofficial].
*   **Lookup**: If all vertices are labeled, perform a lookup in the appropriate segmentation case table (2D or 3D) using the vertex labels [S1, unofficial].
*   **Check Ambiguity**: If the case table indicates ambiguity (multiple valid segmentations for the labeling), leave $c$'s topology uninitialized [S1, unofficial].
*   **Check Residual Material**:
    *   Let $M_c$ be the set of materials with nonzero volume fractions in cell $c$ [S1, unofficial].
    *   Let $M'_c$ be the set of material labels assigned to the vertices of $c$ [S1, unofficial].
    *   If $M_c \neq M'_c$, the cell has residual material (internal pockets or multiple intersections not captured by the vertex labels) [S1, unofficial]. Leave $c$'s topology uninitialized [S1, unofficial].
*   **Assign Topology**: If all checks pass, assign the surface fragments returned by the case table to cell $c$ [S1, unofficial].

### Pseudocode
```python
def rule_based_marching(mesh, volume_fractions):
    # Step 1: Initialize Vertex Labels
    L = {v: None for v in mesh.vertices}

    # Step 2: Label Vertices
    for v in mesh.vertices:
        pure_neighbors = [c for c in mesh.neighbors(v) if is_pure(c, volume_fractions)]
        if pure_neighbors:
            materials = set(volume_fractions[c].keys() for c in pure_neighbors)
            L[v] = materials.pop() if len(materials) == 1 else None
        else:
            common = None
            for c in mesh.neighbors(v):
                s = set(volume_fractions[c].keys())
                common = s if common is None else common & s
            L[v] = common.pop() if common and len(common) == 1 else None

    # Step 3: Label Edges
    chi = {}
    for e in mesh.edges:
        l1, l2 = L[e.v1], L[e.v2]
        # Initial estimate based on vertex labels
        if l1 is not None and l2 is not None:
            chi[e] = 0 if l1 == l2 else 1
        else:
            chi[e] = -1
        # Pure Cells Rule for Edge
        if any(is_pure(c, volume_fractions) for c in mesh.neighbors(e)):
            chi[e] = 0
            continue
        # Neighborhood Rule for Edge
        common = None
        for c in mesh.neighbors(e):
            s = set(volume_fractions[c].keys())
            common = s if common is None else common & s
        if common and len(common) == 1:
            chi[e] = 0

    # Step 4: Generate Cell Topology
    topologies = {}
    for c in mesh.cells:
        labels = [L[v] for v in c.vertices]
        if None in labels:
            continue
        # The sources do not specify the exact table structure or lookup implementation [G]
        # result = lookup_segmentation_table(c.dimension, labels)
        # if result is None or result.is_ambiguous: continue
        cell_materials = set(volume_fractions[c].keys())
        vertex_materials = set(labels)
        if cell_materials != vertex_materials:
            continue
        topologies[c] = [] # Surface fragments returned by the case table
    return topologies

def is_pure(cell, volume_fractions):
    return len([m for m, f in volume_fractions[cell].items() if f > 0]) == 1
```

### Parameters and Edge Cases
*   **Ambiguity**: If the segmentation case table indicates multiple valid segmentations for a given labeling, the cell topology is left uninitialized [S1, unofficial].
*   **Residual Material**: If the set of materials in the cell does not match the set of vertex labels, the topology is left uninitialized [S1, unofficial]. This handles cases with internal pockets or multiple intersections [S1, unofficial].
*   **Multiple Intersections**: The method supports $\chi \ge 2$ intersections per edge, unlike standard Marching Cubes which assumes $\chi \in \{0, 1\}$ [S1, unofficial]. This requires custom 2D and 3D case tables [S1, unofficial].
*   **Uninitialized Cells**: Cells that fail any rule are skipped [S1, unofficial]. A subsequent method (e.g., discretized boundary method) may handle these [S1, unofficial].
## Operating characteristics
*   **Complexity**: The vertex and edge labeling steps are linear in the number of vertices and edges, respectively [S1, unofficial]. The cell topology generation is constant time per cell (lookup table access) provided the labeling is complete [S1, unofficial].
*   **Strengths**: It avoids the artifacts of forced labeling (e.g., volume averaging errors) and handles complex multi-material interfaces with thin filaments better than standard binary methods [S1, unofficial].
*   **Limitations**: It leaves many cells uninitialized, requiring a fallback method [S1, unofficial]. It is specific to volume fraction data and not directly applicable to general scalar fields without adaptation [S1, unofficial].
*   **When to use**: When processing volume fraction data for multi-material reconstruction where interface accuracy is critical and standard marching cubes produce cracks or incorrect topology due to ambiguity or multiple intersections [S1, unofficial].
## Background
The rule-based marching method was developed for the visualization of volume fraction data, particularly in the context of Multi-Interface Reconstruction (MIR) [S1, unofficial]. It was proposed as an improvement over previous approaches such as those by Bonnell et al., who cast volume fraction data onto a dual mesh, and Meredith, who forced vertex labels through volume averaging [S1, unofficial]. The method draws inspiration from the ambiguity handling in Marching Cubes (Nielson and Hamann) but extends it to support multiple intersections per edge [S1, unofficial].
