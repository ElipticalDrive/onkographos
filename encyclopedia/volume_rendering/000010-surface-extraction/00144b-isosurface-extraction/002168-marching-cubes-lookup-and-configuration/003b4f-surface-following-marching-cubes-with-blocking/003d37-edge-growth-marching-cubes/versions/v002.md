# Edge Growth Marching Cubes

Also called: Edge growth MC, Edge-growing MC algorithm, Marching Cube Algorithm Based on Edge Growth

## Overview
Edge Growth Marching Cubes is a surface extraction algorithm that resolves the topological ambiguities and disconnected holes inherent in standard Marching Cubes by treating the iso-surface as a connected manifold grown from seed triangles rather than processed voxel-by-voxel [S1]. Unlike standard Marching Cubes, which evaluates each cube independently and may produce inconsistent topology at shared edges, this method propagates the surface through adjacent cubes via a queue of "growth edges," ensuring topological consistency across the entire reconstructed model [S1]. It is particularly suited for 3D reconstruction where only the main contour is required or for isolating specific connected components from scattered data by controlling the seed region [S1].

## How it works
The algorithm operates by initializing a set of seed triangles, typically derived from specific topological configurations, and then iteratively expanding the surface into neighboring voxels using a queue of edges that define the boundary of the currently reconstructed surface [S1].

### Inputs and Outputs
*   **Input:** A 3D scalar field (volume data) with associated voxel coordinates and gray values; an iso-surface threshold $Y$ [S1].
*   **Output:** A triangular mesh representing the iso-surface [S1].

### Data Structures
The algorithm relies on three primary data structures [S1]:
1.  **Growth Queue:** A queue storing growth edge entries [S1]. Each entry contains the 3D coordinates of the two endpoints of the edge, the gradient values at the two endpoints, and the 3D coordinates of the cube to which the edge is to be grown [S1].
2.  **Labeled Arrays:** Two arrays of size equal to the volume grid dimensions used to track processing state [S1]: one records whether each cube has been processed to generate triangles, and the other records whether a cube has already been added to the growth queue to prevent duplicate processing [S1].

### Parameters
*   **Threshold ($Y$):** The scalar value defining the iso-surface [S1].
*   **Interpolation Limits:** The "three-segment interpolation" method requires four constants $q, m, n, p$ such that $0 < q < m < n < p < 1$ and $q + p = 1$ [S1].
*   **Seed Selection Strategy:** Typically, all triangles generated from **Topology Configuration 1** in a single middle layer (where curvature changes are significant) are selected as seeds [S1]. Alternatively, seeds can be manually selected or restricted to a designated 3D area [S1].

### Algorithm Steps
1.  **Seed Selection:** Identify seed triangles from the selected region [S1]. For each seed triangle, extract its three edges [S1]. Insert these edges into the growth queue as initial growth edge entries [S1]. Mark the corresponding adjacent cubes as queued [S1].
2.  **Growth Loop:** While the growth queue is not empty:
    a.  Dequeue a growth edge [S1]. Let the associated cube be $C$ [S1].
    b.  **Interpolation:** Calculate the intersection points of the iso-surface with the edges of cube $C$ using the three-segment interpolation method [S1].
    c.  **Mesh Generation:** Connect the calculated intersection points to form the triangular mesh for cube $C$, based on the topological configuration determined by the signs of the scalar values at the cube's vertices relative to $Y$ [S1].
    d.  **Identify New Edges:** Determine which edges of cube $C$ intersect the newly generated iso-surface [S1].
    e.  **Queue Update:** For each intersecting edge, check if the adjacent cube sharing the edge has been processed or queued [S1]. If not, create a new growth edge entry pointing to the adjacent cube, enqueue it, and mark it as queued [S1].
3.  **Termination:** The algorithm terminates when the growth queue is empty, implying the connected component defined by the seeds has been fully reconstructed [S1].

### Interpolation Formula
The source describes a "three-segment interpolation" method that modifies standard linear interpolation to handle edge cases or specific topological requirements [S1].

Given two vertices $p_1$ and $p_2$ with scalar values $hu_1$ and $hu_2$, and an iso-surface threshold $Y$:

1.  Calculate the standard linear interpolation ratio $k_{linear}$:
    $$ k_{linear} = \frac{Y - hu_1}{hu_2 - hu_1} $$
2.  The actual interpolation ratio $k$ is determined by comparing $|k_{linear}|$ against the limits $m$ and $n$:
    *   If $|k_{linear}| < m$, then $k = q \cdot \text{sign}(k_{linear})$ [S1].
    *   If $|k_{linear}| > n$, then $k = p \cdot \text{sign}(k_{linear})$ [S1]. *Note: The source text cuts off after "greater than...", but the condition $q+p=1$ and the symmetric range constraints imply clamping to $\pm p$ for large ratios [G].*
    *   If $m \le |k_{linear}| \le n$, then $k = k_{linear}$ (standard linear interpolation) [S1].
3.  Calculate the intersection point $p$:
    $$ p = p_1 + k(p_2 - p_1) $$

### Pseudocode
```python
from collections import deque
import numpy as np

def edge_growth_marching_cubes(volume, threshold, q, m, n, p):
    """
    volume: 3D numpy array of scalar values
    threshold: float Y
    q, m, n, p: float interpolation limits
    """
    D, H, W = volume.shape
    processed = np.zeros((D, H, W), dtype=bool)
    queued = np.zeros((D, H, W), dtype=bool)
    queue = deque()

    # Standard MC 12 edges (vertex index pairs) [G]
    EDGES = [
        (0,1), (2,3), (4,5), (6,7),
        (0,2), (1,3), (4,6), (5,7),
        (0,4), (1,5), (2,6), (3,7)
    ]
    # Standard MC 14-case lookup: case_index -> list of edge pairs forming triangles [G]
    MC_LOOKUP = [
        [], [], [], [], [], [], [], [],
        [(0,1)], [(2,3)], [(4,5)], [(6,7)],
        [(0,2), (1,3)], [(0,4), (1,5)], [(2,6), (3,7)], [(4,6), (5,7)],
        [(0,1), (2,3)], [(0,4), (1,5), (2,6), (3,7)], [(0,2), (1,3), (4,6), (5,7)],
        [(0,1), (2,3), (4,6), (5,7)], [(0,4), (1,5), (2,6), (3,7), (0,2), (1,3)],
        [(0,1), (2,3), (4,6), (5,7), (0,4), (1,5)], [(0,2), (1,3), (4,6), (5,7), (0,4), (1,5)],
        [(0,1), (2,3), (4,6), (5,7), (0,4), (1,5), (2,6), (3,7)]
    ]

    def clamp_k(k_lin):
        abs_k = abs(k_lin)
        sign = 1.0 if k_lin >= 0 else -1.0
        if abs_k < m:
            return sign * q
        elif abs_k > n:
            return sign * p
        return k_lin

    def get_cube_vertices(c):
        d, h, w = c
        return [
            volume[d, h, w], volume[d, h, w+1], volume[d, h+1, w], volume[d, h+1, w+1],
            volume[d+1, h, w], volume[d+1, h, w+1], volume[d+1, h+1, w], volume[d+1, h+1, w+1]
        ]

    def get_neighbor_sharing_edge(c, e_idx):
        d, h, w = c
        v1, v2 = EDGES[e_idx]
        # Determine edge direction to find adjacent cube [G]
        if v1 == 0 and v2 == 1: return (d, h, w+1)
        if v1 == 2 and v2 == 3: return (d, h+1, w+1)
        if v1 == 4 and v2 == 5: return (d+1, h, w+1)
        if v1 == 6 and v2 == 7: return (d+1, h+1, w+1)
        if v1 == 0 and v2 == 2: return (d, h+1, w)
        if v1 == 1 and v2 == 3: return (d, h+1, w+1)
        if v1 == 4 and v2 == 6: return (d+1, h, w)
        if v1 == 5 and v2 == 7: return (d+1, h+1, w)
        if v1 == 0 and v2 == 4: return (d+1, h, w)
        if v1 == 1 and v2 == 5: return (d+1, h, w+1)
        if v1 == 2 and v2 == 6: return (d+1, h+1, w)
        if v1 == 3 and v2 == 7: return (d+1, h+1, w+1)
        return None

    def process_cube(c):
        if processed[c]: return []
        processed[c] = True
        verts = get_cube_vertices(c)
        idx = 0
        for i, v in enumerate(verts):
            if v > threshold: idx |= (1 << i)
        if idx == 0 or idx == 255: return []

        intersecting_edges = []
        for e_idx, (v1, v2) in enumerate(EDGES):
            if (verts[v1] - threshold) * (verts[v2] - threshold) < 0:
                k_lin = (threshold - verts[v1]) / (verts[v2] - verts[v1])
                k = clamp_k(k_lin)
                p1 = np.array(c) + np.array([v1%2, (v1>>1)%2, (v1>>2)%2])
                p2 = np.array(c) + np.array([v2%2, (v2>>1)%2, (v2>>2)%2])
                pt = p1 + k * (p2 - p1)
                intersecting_edges.append((e_idx, pt))

        triangles = []
        edge_to_pt = {e: pt for e, pt in intersecting_edges}
        for pair in MC_LOOKUP[idx]:
            triangles.append((edge_to_pt[pair[0]], edge_to_pt[pair[1]]))

        for e_idx, _ in intersecting_edges:
            neighbor = get_neighbor_sharing_edge(c, e_idx)
            if neighbor is not None and not queued[neighbor]:
                v1, v2 = EDGES[e_idx]
                p1 = np.array(c) + np.array([v1%2, (v1>>1)%2, (v1>>2)%2])
                p2 = np.array(c) + np.array([v2%2, (v2>>1)%2, (v2>>2)%2])
                queue.append({
                    'p1': p1, 'p2': p2,
                    'g1': volume[tuple(c) + (v1%2, (v1>>1)%2, (v1>>2)%2)],
                    'g2': volume[tuple(c) + (v2%2, (v2>>1)%2, (v2>>2)%2)],
                    'cube_coord': neighbor
                })
                queued[neighbor] = True
        return triangles

    # Step 1: Seed Selection
    mid_layer = D // 2
    for h in range(H - 1):
        for w in range(W - 1):
            c = (mid_layer, h, w)
            verts = get_cube_vertices(c)
            idx = 0
            for i, v in enumerate(verts):
                if v > threshold: idx |= (1 << i)
            # Select seeds from Topology Configuration 1 [S1]
            if idx == 1:
                process_cube(c)
                for e_idx, _ in enumerate(EDGES):
                    if (verts[EDGES[e_idx][0]] - threshold) * (verts[EDGES[e_idx][1]] - threshold) < 0:
                        neighbor = get_neighbor_sharing_edge(c, e_idx)
                        if neighbor is not None and not queued[neighbor]:
                            v1, v2 = EDGES[e_idx]
                            p1 = np.array(c) + np.array([v1%2, (v1>>1)%2, (v1>>2)%2])
                            p2 = np.array(c) + np.array([v2%2, (v2>>1)%2, (v2>>2)%2])
                            queue.append({
                                'p1': p1, 'p2': p2,
                                'g1': volume[tuple(c) + (v1%2, (v1>>1)%2, (v1>>2)%2)],
                                'g2': volume[tuple(c) + (v2%2, (v2>>1)%2, (v2>>2)%2)],
                                'cube_coord': neighbor
                            })
                            queued[neighbor] = True

    # Steps 2-4: Growth Loop
    all_triangles = []
    while queue:
        edge_entry = queue.popleft()
        c = edge_entry['cube_coord']
        all_triangles.extend(process_cube(c))
    return all_triangles
```

### Edge Cases and Pitfalls
*   **Seed Selection Balance:** Selecting too few seed triangles may fail to reconstruct the model due to noise or disconnected components, while selecting too many wastes computational time on seed selection [S1].
*   **Ambiguity Resolution:** By growing from seeds and propagating connectivity, the algorithm avoids the standard MC ambiguity problem where independent cube processing leads to holes or inconsistent topology at shared edges [S1].
*   **Incomplete Source Details:** The exact behavior of the three-segment interpolation for negative interpolation ratios and the precise definition of the "17 topological configurations" mentioned in the source are not fully detailed in the provided text [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Ensures topological consistency; handles disconnected components by controlling seeds; efficient for extracting main contours or specific parts [S1].
*   **Limitations:** Requires careful seed selection; performance depends on the connectivity of the iso-surface; not suitable for extracting all iso-surfaces in a volume simultaneously without multiple seed sets [S1].

## Background
The Edge Growth Marching Cubes algorithm was proposed to address the limitations of standard Marching Cubes, specifically the topological ambiguities and holes caused by independent cube processing [S1]. It was introduced in a 2021 paper by authors publishing in *Virtual Reality & Intelligent Hardware* [S1]. The method leverages the continuity of iso-surfaces, treating the reconstruction as a growth process from seed triangles, a concept distinct from the voxel-centric approach of traditional MC [S1].
