# Surface-following Marching Cubes with Blocking


## Overview
This method enables unbounded rendering of particle-based isosurfaces by combining surface-following traversal with a blocking algorithm and a 3D lookup cache [S1]. It distinguishes itself from sibling methods like [Snap Marching Cubes](2181-snap-marching-cubes.md) by avoiding the coarse-grained grid lookups that return excessive false positives; instead, it performs exact lookups within a spherical radius $R_c$, eliminating the need for subsequent floating-point distance culling [S1].

## How it works
The algorithm extracts the isosurface by traversing only those voxels that contain the surface, rather than iterating over a fixed bounding box. It relies on the [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) principles for geometry generation.

**Inputs and Outputs:**
*   **Input:** A set of particles with positions and scalar values; an isovalue $I$; a lookup radius $R_c$.
*   **Output:** A triangle mesh representing the isosurface.

**Data Structures:**
1.  **3D Lookup Cache:** A hash map or grid structure storing particle indices or references, optimized for point insertion and lookup [S1].
2.  **Voxel Queue:** A queue of voxel coordinates to process, initialized with seed voxels containing the surface [S1].
3.  **Visited Set:** A set of voxel coordinates to prevent re-processing [G].

**Steps:**
1.  **Initialization:** Identify seed voxels containing the isosurface. Insert these into the Voxel Queue and Visited Set [S1].
2.  **Surface Following:** While the Voxel Queue is not empty:
    a. Dequeue a voxel $V$.
    b. Perform a point insert and 3D lookup to retrieve relevant particles within radius $R_c$ using the 3D Lookup Cache [S1].
    c. Compute the case index $C$ for voxel $V$ based on particle values at the 8 corners relative to $I$ [2518-marching-cubes-lookup-and-configuration.md].
    d. Use the `edgeTable` and `triangleTable` from [10327-lookup-table-and-ambiguity-handling] to generate triangles for $V$ [2518-marching-cubes-lookup-and-configuration.md].
    e. Identify adjacent voxels sharing faces with $V$ that have not been visited.
    f. For each adjacent voxel, check if it contains surface data (via the lookup cache or particle density check). If so, enqueue it and add to Visited Set [S1].
3.  **Termination:** The process ends when the queue is empty, ensuring all connected surface components are extracted [S1].

**Parameters:**
*   $R_c$: Lookup radius. The sources note that using a separate grid with cube size $R_c$ keeps traversal volume to $3 \times 3 \times 3$ [S1].

**Edge Cases:**
*   **Disconnected Components:** The surface-following nature requires proper seed selection to ensure all disconnected surface islands are found [S1].
*   **Lookup Precision:** The method claims exact lookup without returning particles outside $R_c$, unlike approaches that use a coarser grid and cull later [S1].

## Subtopics

## Operating characteristics
*   **Performance:** The method was compared against Marching Slices with block subdivision and 2D projection 1D lookup [S1]. It was tested on a 3.2Ghz Intel Core 2 Duo with 4MB L2 cache [S1].
*   **Accuracy:** It returns fewer particles than approaches using a separate coarse grid for lookup, which return 6.5 times more particles by searching a $(3R_c)^3$ volume instead of the $(4/3)\pi R_c^3$ volume, requiring additional culling [S1].
*   **Scalability:** Increasing the lookup grid resolution to reduce false positives can dominate overall isosurface extraction costs [S1].

## Background
This approach was presented in the context of real-time particle isosurface extraction, offering an alternative to methods using point insertion with 3D lookup or 3D insertion with point lookup [S1]. It addresses the inefficiency of returning excess particles due to coarse grid approximations in prior work [S1].
