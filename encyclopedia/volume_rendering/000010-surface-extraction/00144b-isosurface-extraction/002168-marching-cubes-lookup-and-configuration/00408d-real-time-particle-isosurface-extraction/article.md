# Real-time particle isosurface extraction

Also called: Block subdivision particle isosurface, Particle isosurface extraction

## Overview
Real-time particle isosurface extraction is a technique for the fast, high-quality polygonization of isosurfaces generated by thousands of particles in an unbounded spatial domain, using minimal working memory [S1]. It solves the bottleneck of high computational cost and memory requirements typical in particle-based rendering by combining block subdivision, slice-by-slice extraction, and a specialized particle cache [S1]. Unlike standard Marching Cubes which operates on a dense grid, this method extracts surfaces directly from discrete particle positions, enabling real-time performance for dynamic entities like fluid blobs or monsters in video games [S1].

## How it works
The algorithm takes as input a list of particles with $(x, y, z)$ coordinates, a cutoff radius $R_c$, a cube grid size $S$, and a threshold value $T$ [S1]. It outputs a list of triangles represented by a vertex and index buffer [S1]. The method relies on an implicit field function that is radially monotonic, continuous, and has a limited radius of influence [S1].

### Data Structures
1.  **Particle List**: An array of structures containing 3D coordinates $(x, y, z)$ [S1].
2.  **Block List**: A list of spatial blocks covering the render volume [S1]. Each block defines a sub-volume to be processed independently [S1].
3.  **Particle Cache**: A 2D data structure used to store particles within a specific influence radius for a given slice [S1]. This structure is optimized for 2D texture lookups on graphics hardware [S1].
4.  **Vertex/Index Buffers**: Standard triangle mesh buffers for the output geometry [S1].

### Implicit Field Function
The scalar field value $f(r)$ at a distance $r$ from a particle center is defined as [S1]:

$$
f(r) = \begin{cases} 
(r/\sqrt{2}R_c)^4 - (r/\sqrt{2}R_c)^2 + 0.25 & \text{if } r < R_c \\
0 & \text{otherwise}
\end{cases}
$$

Where:
*   $r$ is the Euclidean distance from the sample point to the particle center [S1].
*   $R_c$ is the cutoff radius (influence radius) [S1].

### Parameters
*   $R_c$: Cutoff radius. Defines the limited radius of influence for each particle's implicit field [S1]. Typical value: $3.0$ [S1].
*   $S$: Size of the cube grid. The side length of the voxels used in the marching cubes grid [S1]. Typical value: $0.5$ [S1].
*   $T$: Threshold value. The isovalue where the surface is generated [S1]. A threshold of $0.2$ corresponds to an isosurface of radius $1$ for a single particle [S1]. Typical value: $0.2$ or $0.75$ [S1].

### Algorithm Steps

1.  **Block Subdivision**: Divide the unbounded render volume into seamless blocks. This limits memory usage, avoids seams between adjacent blocks, and enables multi-threaded rendering [S1].
2.  **Iterate Blocks**: Process each block independently [S1].
3.  **Marching Slices**: Within a block, extract the isosurface slice-by-slice. This approach avoids excessive growth of cached data and guarantees a single visit to each cube intersecting the isosurface [S1].
4.  **Particle Cache Construction**: For each slice, build a 2D insert 1D lookup particle cache. This cache contains all particles within the fixed influence radius $R_c$ that contribute to sample points in the current slice. This lookup is exact and excludes particles outside the radius [S1].
5.  **Field Calculation**: For each cube in the current slice, calculate the field value at its 8 vertices by summing the contributions of all particles in the cache that influence those vertices [S1].
    *   For a vertex at position $v$, the field value $V(v)$ is:
        $$ V(v) = \sum_{p \in \text{Cache}} f(\|v - p\|) $$
6.  **Isosurface Extraction**: Use the calculated vertex field values to determine the case index and extract triangles using the standard Marching Cubes lookup tables (as defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md)) [S1].
7.  **Output**: Append the generated triangles to the vertex and index buffer [S1].
8.  **Cache Cleanup**: Discard the particle cache for the current slice to maintain low memory usage [S1].

```python
def real_time_particle_isosurface_extraction(particles, R_c, S, T):
    """
    Extracts isosurface from particles using block subdivision and marching slices.
    
    Args:
        particles: List of Particle objects with x, y, z attributes.
        R_c: Cutoff radius.
        S: Cube grid size.
        T: Threshold value.
        
    Returns:
        vertices: List of vertex positions.
        indices: List of triangle indices.
    """
    vertices = []
    indices = []
    
    # 1. Block Subdivision
    # Compute bounding box of particles and divide into blocks.
    # Block size is not specified in the sources [G].
    min_x = min(p.x for p in particles)
    max_x = max(p.x for p in particles)
    min_y = min(p.y for p in particles)
    max_y = max(p.y for p in particles)
    min_z = min(p.z for p in particles)
    max_z = max(p.z for p in particles)
    
    # Iterate over blocks (implementation detail for block size omitted [G])
    for block in generate_blocks(min_x, max_x, min_y, max_y, min_z, max_z, S):
        # 2. Marching Slices
        # Iterate slices along Z axis within the block
        z_start = max(min_z, block.min_z)
        z_end = min(max_z, block.max_z)
        z = z_start
        while z <= z_end:
            # 3. Particle Cache Construction
            # Build 2D insert 1D lookup cache for particles influencing this slice
            cache = []
            for p in particles:
                if abs(p.z - z) < R_c:
                    # Check projected distance to slice plane
                    dx = p.x - block.min_x
                    dy = p.y - block.min_y
                    if dx*dx + dy*dy < R_c*R_c:
                        cache.append(p)
            
            # 4. Field Calculation and Extraction
            # Iterate cubes in the current slice
            x = block.min_x
            while x < block.max_x:
                y = block.min_y
                while y < block.max_y:
                    # Cube vertices (relative to block origin)
                    verts = [
                        (x, y, z), (x+S, y, z), (x+S, y+S, z), (x, y+S, z),
                        (x, y, z+S), (x+S, y, z+S), (x+S, y+S, z+S), (x, y+S, z+S)
                    ]
                    
                    # Calculate field values at 8 vertices
                    vertex_values = []
                    for v in verts:
                        val = 0.0
                        for p in cache:
                            dx = v[0] - p.x
                            dy = v[1] - p.y
                            dz = v[2] - p.z
                            r = (dx*dx + dy*dy + dz*dz)**0.5
                            if r < R_c:
                                r_norm = r / (2**0.5 * R_c)
                                val += r_norm**4 - r_norm**2 + 0.25
                        vertex_values.append(val)
                    
                    # 5. Isosurface Extraction
                    # Compute case index: bit i set if vertex_values[i] < T
                    case_index = 0
                    for i in range(8):
                        if vertex_values[i] < T:
                            case_index |= (1 << i)
                    
                    # Extract triangles using standard Marching Cubes LUT
                    # (edgeTable and triangleTable from parent article)
                    edge_mask = edgeTable[case_index]
                    tri_indices = triangleTable[case_index]
                    
                    for k in range(0, len(tri_indices), 3):
                        if tri_indices[k] == -1:
                            break
                        e1, e2, e3 = tri_indices[k], tri_indices[k+1], tri_indices[k+2]
                        
                        # Interpolate edge intersections
                        p1 = interpolate_edge(verts, vertex_values, e1, T)
                        p2 = interpolate_edge(verts, vertex_values, e2, T)
                        p3 = interpolate_edge(verts, vertex_values, e3, T)
                        
                        # Add to output buffers
                        indices.append(len(vertices))
                        indices.append(len(vertices) + 1)
                        indices.append(len(vertices) + 2)
                        vertices.append(p1)
                        vertices.append(p2)
                        vertices.append(p3)
                    
                    y += S
                x += S
            z += S
            # 6. Cache Cleanup
            del cache
    return vertices, indices

def interpolate_edge(verts, values, edge_idx, T):
    # Standard edge numbering from parent article
    edges = [
        (0, 1), (1, 2), (2, 3), (3, 0), # bottom
        (4, 5), (5, 6), (6, 7), (7, 4), # top
        (0, 4), (1, 5), (2, 6), (3, 7)  # vertical
    ]
    v1, v2 = edges[edge_idx]
    val1, val2 = values[v1], values[v2]
    if val1 == val2:
        return verts[v1] # Degenerate case
    t = (T - val1) / (val2 - val1)
    return (
        verts[v1][0] + t * (verts[v2][0] - verts[v1][0]),
        verts[v1][1] + t * (verts[v2][1] - verts[v1][1]),
        verts[v1][2] + t * (verts[v2][2] - verts[v1][2])
    )
```

### Edge Cases and Pitfalls
*   **Seams**: The block subdivision must be seamless to avoid inconsistencies in the surface between adjacent blocks [S1].
*   **Memory Growth**: The marching slices approach is designed to avoid excessive growth of cached data by discarding slices that will not be reused [S1].
*   **Parallelization**: The algorithm was presented in a single thread, but parallelization at the block-level offers potential for nearly linear speedup for particle distributions spanning more than one block [S1].
*   **GPU Implementation**: The algorithm operates with 2D data structures, making it amenable to implementation on programmable graphics hardware optimized for 2D texture lookups [S1].

## Operating characteristics
*   **Performance**: In the Fountain scene with 3000 particles, $R_c=3.0$, $T=0.2$, $S=0.5$, Approach 1 achieves 1,859,083 Cubes/Sec, 3,657,317 Tris/Sec, 0.741 MB Render Mem, 1.548 MB Cache Mem, and 29.1 FPS [S1].
*   **Memory**: The technique demonstrates significant memory reductions compared to existing approaches. Approach 1 uses ~0.74 MB render memory and ~1.55 MB cache memory, whereas Approach 2 uses ~10.5 MB render memory and ~8.0 MB cache memory [S1].
*   **Scalability**: The block subdivision allows for rendering in an unbounded volume and enables multi-threaded rendering [S1].
*   **Strengths**: Fast, high-quality polygonization; small working memory; real-time performance; seamless blocks; single visit to each cube [S1].
*   **Limitations**: Requires radially monotonic, continuous implicit field functions with limited radius of influence. Performance depends on the number of particles and the cutoff radius [S1].

## Background
The technique was presented in a paper by [S1] titled "Real-time particle isosurface extraction". It was employed in a video game environment to render dynamic particle-based entities, such as a blob monster that can be blown to bits and reassemble. The blob monster demo runs interactively at 50-60fps depending on the number of physics objects the monster is colliding with and at 60-70fps during replay [S1]. The implicit field function used is described by Triquet [TMC01].
