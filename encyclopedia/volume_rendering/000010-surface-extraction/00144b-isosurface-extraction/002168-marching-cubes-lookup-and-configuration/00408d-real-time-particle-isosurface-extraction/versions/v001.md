# Real-time particle isosurface extraction

Also called: Block subdivision particle isosurface, Particle isosurface extraction

## Overview
Real-time particle isosurface extraction is a technique for the fast, high-quality polygonization of isosurfaces generated by thousands of particles in an unbounded spatial domain, using minimal working memory [S1]. It solves the bottleneck of high computational cost and memory requirements typical in particle-based rendering by combining block subdivision, slice-by-slice extraction, and a specialized particle cache [S1]. Unlike standard Marching Cubes which operates on a dense grid, this method extracts surfaces directly from discrete particle positions, enabling real-time performance for dynamic entities like fluid blobs or monsters in video games [S1].

## How it works
The algorithm takes as input a list of particles with $(x, y, z)$ coordinates, a cutoff radius $R_c$, a cube grid size $S$, and a threshold value $T$ [S1]. It outputs a list of triangles represented by a vertex and index buffer [S1]. The method relies on an implicit field function that is radially monotonic, continuous, and has a limited radius of influence [S1].

### Data Structures
1.  **Particle List**: An array of structures containing 3D coordinates $(x, y, z)$.
2.  **Block List**: A list of spatial blocks covering the render volume. Each block defines a sub-volume to be processed independently.
3.  **Particle Cache**: A 2D data structure used to store particles within a specific influence radius for a given slice. This structure is optimized for 2D texture lookups on graphics hardware [S1].
4.  **Vertex/Index Buffers**: Standard triangle mesh buffers for the output geometry.

### Implicit Field Function
The scalar field value $f(r)$ at a distance $r$ from a particle center is defined as [S1]:

$$
f(r) = \begin{cases} 
(r/\sqrt{2}R_c)^4 - (r/\sqrt{2}R_c)^2 + 0.25 & \text{if } r < R_c \\
0 & \text{otherwise}
\end{cases}
$$

Where:
*   $r$ is the Euclidean distance from the sample point to the particle center.
*   $R_c$ is the cutoff radius (influence radius).

### Parameters
*   $R_c$: Cutoff radius. Defines the limited radius of influence for each particle's implicit field. Typical value: $3.0$ [S1].
*   $S$: Size of the cube grid. The side length of the voxels used in the marching cubes grid. Typical value: $0.5$ [S1].
*   $T$: Threshold value. The isovalue where the surface is generated. A threshold of $0.2$ corresponds to an isosurface of radius $1$ for a single particle. Typical value: $0.2$ or $0.75$ [S1].

### Algorithm Steps

1.  **Block Subdivision**: Divide the unbounded render volume into seamless blocks. This limits memory usage, avoids seams between adjacent blocks, and enables multi-threaded rendering [S1].
2.  **Iterate Blocks**: Process each block independently.
3.  **Marching Slices**: Within a block, extract the isosurface slice-by-slice. This approach avoids excessive growth of cached data and guarantees a single visit to each cube intersecting the isosurface [S1].
4.  **Particle Cache Construction**: For each slice, build a 2D insert 1D lookup particle cache. This cache contains all particles within the fixed influence radius $R_c$ that contribute to sample points in the current slice. This lookup is exact and excludes particles outside the radius [S1].
5.  **Field Calculation**: For each cube in the current slice, calculate the field value at its 8 vertices by summing the contributions of all particles in the cache that influence those vertices.
    *   For a vertex at position $v$, the field value $V(v)$ is:
        $$ V(v) = \sum_{p \in \text{Cache}} f(\|v - p\|) $$
6.  **Isosurface Extraction**: Use the calculated vertex field values to determine the case index and extract triangles using the standard Marching Cubes lookup tables (as defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md)).
7.  **Output**: Append the generated triangles to the vertex and index buffer.
8.  **Cache Cleanup**: Discard the particle cache for the current slice to maintain low memory usage [S1].

    """
    Extracts isosurface from particles using block subdivision and marching slices.

        particles: List of Particle objects with x, y, z attributes.
        R_c: Cutoff radius.
        S: Cube grid size.
        T: Threshold value.

        vertices: List of vertex positions.
        indices: List of triangle indices.
    """
    vertices = []
    indices = []
    
    # 1. Block Subdivision
    # Determine the bounding box of all particles and divide into blocks.
    # The exact block size is not specified, but it must cover the volume.
    blocks = compute_blocks(particles, R_c, S)
    
    for block in blocks:
        # 2. Marching Slices
        # Iterate through slices along one axis (e.g., Z) within the block.
        # The slice step size is typically related to S.
        for z_slice in block.z_slices:
            
            # 3. Particle Cache Construction
            # Build a cache of particles influencing this slice.
            # A particle influences the slice if its distance to any point 
            # in the slice's cubes is < R_c.
            cache = build_particle_cache(particles, z_slice, R_c, S)
            
            # 4. Field Calculation and Extraction
            # Iterate through cubes in the current slice.
            for cube in z_slice.cubes:
                # Calculate field values at the 8 vertices of the cube.
                vertex_values = []
                for vertex in cube.vertices:
                    field_val = 0.0
                    for p in cache:
                        dist = distance(vertex, p)
                        if dist < R_c:
                            # Implicit field function
                            r_norm = dist / (sqrt(2) * R_c)
                            field_val += r_norm**4 - r_norm**2 + 0.25
                    vertex_values.append(field_val)
                
                # 5. Isosurface Extraction
                # Determine case index based on vertex_values and threshold T.
                case_index = compute_case_index(vertex_values, T)
                
                # Extract triangles using Marching Cubes LUT.
                # This relies on the parent article's edgeTable and triangleTable.
                triangles = extract_triangles(case_index, vertex_values, cube.vertices, T)
                
                # Add to output buffers.

                    for v_idx in tri:

### Edge Cases and Pitfalls
*   **Seams**: The block subdivision must be seamless to avoid inconsistencies in the surface between adjacent blocks [S1].
*   **Memory Growth**: The marching slices approach is designed to avoid excessive growth of cached data by discarding slices that will not be reused [S1].
*   **Parallelization**: The algorithm was presented in a single thread, but parallelization at the block-level offers potential for nearly linear speedup for particle distributions spanning more than one block [S1].
*   **GPU Implementation**: The algorithm operates with 2D data structures, making it amenable to implementation on programmable graphics hardware optimized for 2D texture lookups [S1].

## Operating characteristics
*   **Performance**: In the Fountain scene with 3000 particles, $R_c=3.0$, $T=0.2$, $S=0.5$, Approach 1 achieves 1,859,083 Cubes/Sec, 3,657,317 Tris/Sec, 0.741 MB Render Mem, 1.548 MB Cache Mem, and 29.1 FPS [S1].
*   **Memory**: The technique demonstrates significant memory reductions compared to existing approaches. Approach 1 uses ~0.74 MB render memory and ~1.55 MB cache memory, whereas Approach 2 uses ~10.5 MB render memory and ~8.0 MB cache memory [S1].
*   **Scalability**: The block subdivision allows for rendering in an unbounded volume and enables multi-threaded rendering [S1].
*   **Strengths**: Fast, high-quality polygonization; small working memory; real-time performance; seamless blocks; single visit to each cube.
*   **Limitations**: Requires radially monotonic, continuous implicit field functions with limited radius of influence. Performance depends on the number of particles and the cutoff radius.

## Background
The technique was presented in a paper by [S1] titled "Real-time particle isosurface extraction". It was employed in a video game environment to render dynamic particle-based entities, such as a blob monster that can be blown to bits and reassemble. The blob monster demo runs interactively at 50-60fps depending on the number of physics objects the monster is colliding with and at 60-70fps during replay [S1]. The implicit field function used is described by Triquet [TMC01].
