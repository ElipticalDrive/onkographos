# Position Error Minimized Marching Cubes

Also called: UMC, Unified Marching Cubes

## Overview
Position Error Minimized Marching Cubes (PEM-MC), also known as Unified Marching Cubes (UMC), is a surface extraction method that reduces geometric error by snapping grid vertices to the isosurface when they lie sufficiently close to it [S1, unofficial]. It distinguishes itself from standard Marching Cubes by using a 2-bit sign encoding to identify vertices exactly on the isosurface and adjusting their positions to minimize the distance to $f(\mathbf{x}) = I$ [S1, unofficial]. This method builds on [Vertex Position Optimization and Error Minimization](10991-vertex-position-optimization-and-error-minimization.md) by integrating the optimization directly into the lookup and configuration phase rather than as a post-processing step.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field $f$ defined on a grid of dimensions $(dim+1) \times (dim+1) \times (dim+1)$, an isovalue $I$ (ISOLEVEL), a boolean flag `pem` enabling Position Error Minimization, and a `snap_threshold` controlling the precision of vertex adjustment.
*   **Output:** A triangle mesh $M$ consisting of vertices $V$ and triangles $T$, where vertex positions are optimized if they are close to the isosurface.

**Data Structures:**
The implementation uses the following structures [S1, unofficial]:

1.  **`grid_signs`**: An array of `uint16_t` with size $(dim/2)^3$. Each 16-bit word stores the sign classification for 8 grid vertices in a $2 \times 2 \times 2$ block.
    *   In **PEM mode**, each vertex uses 2 bits packed based on its parity $(x\&1, y\&1, z\&1)$ within the block.
    *   In **Standard mode**, each vertex uses 1 bit.
2.  **`grid_verts`**: An array of `struct UMC_Isovertex` with size $(dim+1)^3$. Each element contains:
    *   `value` (float): The scalar field value $f(x,y,z)$.
    *   `index` (int32): The index of the vertex in the output mesh. A value of `-2` indicates the vertex is marked for snapping.
    *   `position` (vec3): The 3D coordinates of the grid vertex.
3.  **`edges`**: An array of `struct UMC_Edge` with size $(dim+1)^3 \times 3$. Each edge stores:
    *   `grid_v0` (int32): Index into `grid_verts` for the start vertex.
    *   `grid_v1` (int32): Index into `grid_verts` for the end vertex.

**Algorithm Steps:**

1.  **Grid Labeling:** Iterate over all grid vertices $(x, y, z)$ from $0$ to $dim$.
    *   Compute floating-point coordinates and sample the scalar field $s = f(x, y, z)$.
    *   If `pem` is false, set a 1-bit sign: $0$ if $s < I$, $1$ if $s \ge I$.
    *   If `pem` is true, set a 2-bit sign:
        *   $0$ if $s < I$
        *   $1$ if $s == I$
        *   $2$ if $s > I$
    *   Pack these signs into `grid_signs` based on vertex parity.

2.  **Edge Labeling and Crossing Detection:** Iterate over all grid vertices and check the three outgoing edges (X, Y, Z directions).
    *   For each edge, determine if an isosurface crossing exists using the sign bits of the endpoints.
    *   If a crossing is detected (or if a specific PEM bit 4 is set indicating a potential snap), compute the isovector intersection point.
    *   Store the intersection details in the `edges` array.

3.  **Vertex Snapping Marking:** In PEM mode, after computing edge crossings:
    *   If `result_mask & 1` is true, mark the start vertex of the edge for snapping by setting its `index` in `grid_verts` to `-2`.
    *   If `result_mask & 2` is true, mark the end vertex of the edge for snapping.
    *   This identifies vertices that lie on or very close to the isosurface and should be adjusted.

4.  **Vertex Snapping:** Iterate over the output indices in `grid_verts`.
    *   Extract the grid coordinates $(x, y, z)$ for each vertex.
    *   **Boundary Check:** If the vertex is on the boundary (i.e., $x=0$, $x=dim$, $y=0$, $y=dim$, $z=0$, or $z=dim$), skip snapping to prevent out-of-bounds access or incorrect geometric adjustments [S1, unofficial].
    *   If not on the boundary and marked for snapping (index is `-2`), adjust the vertex position to lie exactly on the isosurface $f(\mathbf{x}) = I$. This is typically done by solving for the root along the relevant edge or using a local optimization step constrained by the `snap_threshold` [S1, unofficial].

5.  **Mesh Generation:** Proceed with standard Marching Cubes lookup using the `edgeTable` and `triangleTable` [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md), using the potentially snapped vertex positions to generate the final triangles.

**Pseudocode:**

```python
def pem_marching_cubes(f, dim, isolevel, pem, snap_threshold):
    # Initialize data structures
    # grid_signs: size (dim/2)^3, uint16_t
    # grid_verts: size (dim+1)^3, struct { value, index, position }
    # edges: size (dim+1)^3 * 3, struct { grid_v0, grid_v1 }
    
    grid_signs = [0] * ((dim // 2) ** 3)
    grid_verts = [UMC_Isovertex() for _ in range((dim + 1) ** 3)]
    edges = [UMC_Edge() for _ in range((dim + 1) ** 3 * 3)]
    
    # Step 1: Grid Labeling
    for x in range(dim + 1):
        for y in range(dim + 1):
            for z in range(dim + 1):
                idx = x * (dim + 1) ** 2 + y * (dim + 1) + z
                pos = vec3(x, y, z)
                val = f(pos)
                grid_verts[idx].value = val
                grid_verts[idx].position = pos
                grid_verts[idx].index = -1 # Not yet assigned to mesh
                
                # Compute sign
                if pem:
                    if val < isolevel:
                        sign = 0
                    elif val == isolevel:
                        sign = 1
                    else:
                        sign = 2
                else:
                    sign = 1 if val >= isolevel else 0
                
                # Pack sign into grid_signs based on parity
                block_x = x // 2
                block_y = y // 2
                block_z = z // 2
                block_idx = block_x * (dim // 2) ** 2 + block_y * (dim // 2) + block_z
                bit_offset = (x & 1) + 2 * (y & 1) + 4 * (z & 1)
                if pem:
                    grid_signs[block_idx] |= (sign << (2 * bit_offset))
                else:
                    grid_signs[block_idx] |= (sign << bit_offset)

    # Step 2 & 3: Edge Labeling and Snapping Marking
    for x in range(dim + 1):
        for y in range(dim + 1):
            for z in range(dim + 1):
                idx = x * (dim + 1) ** 2 + y * (dim + 1) + z
                for edge_dir in [0, 1, 2]: # X, Y, Z
                    # Determine neighbor index
                    if edge_dir == 0:
                        nx, ny, nz = x + 1, y, z
                    elif edge_dir == 1:
                        nx, ny, nz = x, y + 1, z
                    else:
                        nx, ny, nz = x, y, z + 1
                    
                    if nx <= dim and ny <= dim and nz <= dim:
                        n_idx = nx * (dim + 1) ** 2 + ny * (dim + 1) + nz
                        edge_idx = idx * 3 + edge_dir
                        
                        # Check for crossing
                        # Simplified: assume UMC_Chunk_calc_edge_crossing logic
                        # If crossing detected or PEM bit 4 set:
                        if has_crossing(grid_verts[idx], grid_verts[n_idx], isolevel, pem):
                            # Compute intersection
                            intersect = calc_edge_isov(grid_verts[idx], grid_verts[n_idx], isolevel)
                            edges[edge_idx].grid_v0 = idx
                            edges[edge_idx].grid_v1 = n_idx
                            
                            # Mark vertices for snapping if in PEM mode
                            if pem:
                                # result_mask logic from sources
                                # If result_mask & 1, mark start vertex
                                # If result_mask & 2, mark end vertex
                                # Assuming specific conditions trigger these bits
                                if should_snap_start(idx, n_idx, isolevel):
                                    grid_verts[idx].index = -2
                                if should_snap_end(idx, n_idx, isolevel):
                                    grid_verts[n_idx].index = -2

    # Step 4: Vertex Snapping
    for x in range(dim + 1):
        for y in range(dim + 1):
            for z in range(dim + 1):
                idx = x * (dim + 1) ** 2 + y * (dim + 1) + z
                
                # Skip boundary vertices
                if x == 0 or x == dim or y == 0 or y == dim or z == 0 or z == dim:
                    continue
                
                if grid_verts[idx].index == -2:
                    # Snap vertex to isosurface
                    # This involves adjusting position to satisfy f(pos) = isolevel
                    # within snap_threshold
                    snapped_pos = snap_to_isosurface(grid_verts[idx].position, f, isolevel, snap_threshold)
                    grid_verts[idx].position = snapped_pos
                    grid_verts[idx].index = idx # Assign temporary index for mesh generation

    # Step 5: Mesh Generation
    # Use standard Marching Cubes lookup tables with the updated grid_verts positions
    mesh = generate_mesh(grid_verts, edges, grid_signs, dim, isolevel)
    return mesh
```

**Parameters:**
*   `pem`: Boolean flag. When `true`, enables 2-bit sign encoding and vertex snapping. Default: `false` [S1, unofficial].
*   `ISOLEVEL`: The threshold value for the scalar field. Determines the sign classification. [S1, unofficial].
*   `snap_threshold`: Float controlling the snapping distance/precision. [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Vertices:** Vertices on the grid boundary ($x=0, x=dim, y=0, y=dim, z=0, z=dim$) are skipped during snapping to prevent out-of-bounds access or incorrect geometric adjustments [S1, unofficial].
*   **Precision:** The 2-bit sign encoding relies on exact equality $s == I$. Floating-point precision issues may require a tolerance check instead of strict equality [S1, unofficial].
*   **Degenerate Input:** If the scalar field is constant, no crossings occur, and the mesh is empty.

## Operating characteristics
*   **Time Complexity:** $O(dim^3)$ for grid labeling and edge processing [S1, unofficial].
*   **Memory Complexity:** $O(dim^3)$ for storing grid vertices, edges, and signs [S1, unofficial].
*   **Strengths:** Reduces geometric error by snapping vertices to the isosurface, improving accuracy for vertices close to the surface. Integrates optimization into the main loop, avoiding separate post-processing steps.
*   **Limitations:** Boundary vertices are not snapped, which may lead to inconsistencies at the mesh boundaries. The 2-bit encoding increases memory usage for signs compared to standard 1-bit encoding.
*   **When to use:** When high geometric accuracy is required and the scalar field has vertices very close to the isovalue.
*   **When not to use:** When memory is constrained (due to 2-bit signs) or when boundary accuracy is not critical.

## Background
Position Error Minimized Marching Cubes (PEM-MC), also referred to as Unified Marching Cubes (UMC), is described in the context of the "Pushing Voxels Forward" project [S1, unofficial]. It extends the standard Marching Cubes algorithm by incorporating a vertex snapping mechanism to minimize the distance between the mesh vertices and the true isosurface. The method is part of a broader effort to optimize voxel-based rendering and surface extraction techniques.
