# Marching Cubes Vertex List Generation

Also called: Edge Vertex Calculation, GenerateInnerCellVertices, GenerateOuterCellVertices, Marching Cubes Vertex Interpolation, Vertex Interpolation for Marching Cubes, Voxel Marching Cubes Vertex Generation

## Overview
This method calculates the precise 3D positions of vertices lying on the edges of a voxel cube where the scalar field crosses a specified isolevel, using linear interpolation between corner values [S1, unofficial]. It generates the list of vertices for the polygon(s) inside a voxel based on the cube index, forming the geometric foundation for the subsequent triangle assembly steps defined in the parent algorithm [S1, unofficial]. Unlike sibling methods that optimize vertex positions via QEF or error minimization, this method relies strictly on linear interpolation along the grid edges [S1, unofficial].

## How it works
**Inputs:**
- `cubeIndex`: An integer (0–255) representing the configuration of the voxel, derived from the `edgeTable` lookup [S1, unofficial].
- `voxelLocalPosition`: The 3D world position of the voxel's origin (corner 0) [S1, unofficial].
- `voxelDensities`: An array of 8 scalar values (densities) corresponding to the 8 corners of the voxel, indexed 0 to 7 [S1, unofficial].
- `isolevel`: The threshold density value where the surface is defined [S1, unofficial].

**Outputs:**
- `vertexList`: A list of 3D points representing the intersection points on the intersected edges [S1, unofficial].

**Data Structures:**
- `EdgeIndexTable`: An array of integers where entries at indices $2i$ and $2i+1$ give the indices of the two corners forming edge $i$ (for $i=0..11$) [S1, unofficial].
- `CubeCorners`: An array of 8 3D vectors representing the local coordinates of the 8 corners of a unit cube, indexed 0 to 7 [S1, unofficial].

**Steps:**
1. Initialize an empty `vertexList` [S1, unofficial].
2. Iterate $i$ from 0 to 11 (representing the 12 edges of a cube) [S1, unofficial].
3. Check if the $i$-th bit of `cubeIndex` is set; if not, continue to the next edge [S1, unofficial].
4. If the bit is set, the edge is intersected:
   a. Retrieve the start and end corner indices from `EdgeIndexTable` at positions $2i$ and $2i+1$ [S1, unofficial].
   b. Calculate the world positions of these corners by adding `voxelLocalPosition` to `CubeCorners[startIndex]` and `CubeCorners[endTime]` [S1, unofficial].
   c. Retrieve the densities for the two corners from `voxelDensities`, dividing by 255 to normalize to [0,1] [S1, unofficial].
   d. Calculate the intersection vertex $p$ using linear interpolation with the normalized `isolevel/255` [S1, unofficial].
   e. Add $p$ to `vertexList` [S1, unofficial].

**Pseudocode:**
```python
def generate_vertex_list(cube_index, voxel_local_position, voxel_densities, isolevel, edge_index_table, cube_corners):
    vertex_list = []
    # Normalize densities and isolevel to [0, 1] as per source implementation [S1, unofficial]
    isolevel_norm = isolevel / 255.0
    for i in range(12):
        # Check if the i-th bit is set in cube_index [S1, unofficial]
        if (cube_index >> i) & 1:
            # Get corner indices for this edge [S1, unofficial]
            c1 = edge_index_table[2 * i]
            c2 = edge_index_table[2 * i + 1]
            
            # Calculate world positions of corners [S1, unofficial]
            p1 = voxel_local_position + cube_corners[c1]
            p2 = voxel_local_position + cube_corners[c2]
            
            # Retrieve and normalize densities [S1, unofficial]
            v1 = voxel_densities[c1] / 255.0
            v2 = voxel_densities[c2] / 255.0
            
            # Sources state division by zero occurs if v1 == v2 and is unhandled [S1, unofficial]
            t = (isolevel_norm - v1) / (v2 - v1)
            p = p1 + t * (p2 - p1)
            
            vertex_list.append(p)
    return vertex_list
```

**Parameters:**
- `isolevel`: The density level where a surface is created. Densities below this are inside (solid), above are outside (air) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Division by Zero:** Occurs if $v_1 = v_2$. The source code does not explicitly handle this, implying inputs are assumed distinct or the case is degenerate/unhandled [S1, unofficial].
- **Boundary Conditions:** Boundary checks are required for inner cells (`cellID > numberOfVoxels - 3`) and outer cells (`cellID > numberOfVoxels - 2`) to prevent out-of-bounds access [S2, unofficial].

## Subtopics

### [Marching Cubes Surface Point Extraction](6417-marching-cubes-surface-point-extraction.md)
This method computes the 3D position of points on an isosurface (value 0) within a voxel grid by identifying grid edges that cross the isosurface and calculating their intersection points. It operates as a compute shader kernel that extracts surface points for a voxel grid by determining which edges of a cube are intersected and calculating the intersection point using one of three strategies: Quadratic Error Function (QEF), Centroid, or Blocky (cube center). It aggregates intersections into a single point per voxel, prioritizing computational efficiency on the GPU over topological correctness.

### Vertex-centered Data Interpolation
A technique to transition from cell-centered to vertex-centered data by 'diffusing' data values from cells to vertices using interpolation, preparing data for Marching Cubes [S3]. It derives a vertex's value from its adjacent cells using bi-linear or tri-linear interpolation, contingent on the data's dimensionality [S3]. For a vertex, the value is calculated using neighbor cell values (e.g., a vertex with value 6 is calculated using neighbors 8, 6, 6, and 4) [S3]. After interpolation, the size of each dimension of the vertex data increases by one relative to the original cell-centered data [S3]. A pitfall is that re-sampled vertex-centered data leads to conflicts between AMR levels, specifically dangling nodes, resulting in discontinuities or cracks in the iso-surfaces [S3].
