# Modified Marching Cubes with Triangle Decimation

Also called: 3D Isosurface Generation (Marching Cubes), Marching Cubes with Decimation

## Overview
This method generates an isosurface from a 3D scalar field using a modified marching cubes algorithm that explicitly removes topological ambiguities and reduces polygon count via triangle decimation [S1, unofficial]. It distinguishes itself from standard Marching Cubes by adding a post-processing decimation step that collapses triangles with large aspect ratios and re-triangulates, thereby improving visual quality and reducing storage requirements [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) for the base surface extraction.

## How it works
**Inputs:**
*   A 3D scalar field defined on a structured grid (FDS grid).
*   An isovalue threshold $L$.
*   Data uncertainty bounds $\Delta T$ for each grid node.

**Outputs:**
*   A triangle mesh representing the isosurface.
*   Vertex normals for shading.

**Data Structures:**
*   **Cube Vertices:** 8 corners per voxel, indexed $0$ to $7$. The indexing convention must match the parent article's `edgeTable` and `triangleTable` definitions [S1, S12, unofficial].
*   **Case Index:** An 8-bit integer ($0-255$) derived from the scalar values at the 8 corners relative to $L$.
*   **Triangle List:** Stores vertex coordinates and connectivity.

**Algorithm Steps:**

1.  **Grid Partitioning:** Split the region to be contoured into cubes, each aligned with the underlying grid [S1, unofficial].
2.  **Case Index Calculation:** For each cube:
    *   Number corners $0$ to $7$ [S1, unofficial].
    *   For each corner $i$, assign bit $i$ of the case index $C$ to $1$ if the scalar value $V_i > L$, and $0$ otherwise [S1, unofficial].
    *   Use $C$ to look up the triangulation configuration in the `triangleTable` from the parent article [S1, S12, unofficial].
3.  **Triangulation:** Triangulate the cube surface using the looked-up case, storing vertex locations and edge numbers [S1, unofficial].
4.  **Triangle Decimation:** Reduce the number of triangles by eliminating small or degenerate ones [S1, unofficial]:
    *   Identify triangles where two or more vertices are closest to the same grid node (indicating large aspect ratios or redundancy) [S1, unofficial].
    *   Remove these triangles.
    *   Compute a new vertex coordinate as the average of the coordinates of the removed vertices [S1, unofficial].
    *   Re-triangulate the affected region using this new averaged vertex [S1, unofficial].
5.  **Normal Estimation:** Estimate normal directions for each vertex to support smooth shading [S1, unofficial]:
    *   Identify all triangles sharing the vertex.
    *   Compute the unit normal vector for each triangle.
    *   Compute a harmonic weighted average of these normals, where the weight for each triangle is inversely proportional to its area [S1, unofficial].

**Formulas:**

The uncertainty in the isosurface location $\Delta x$ between two data nodes $(x_1, T_1)$ and $(x_2, T_2)$ is bounded by [S1, unofficial]:

$$
\left| \frac{\Delta x}{x_2 - x_1} \right| \leq \frac{\max(|\Delta T_1|, |\Delta T_2|)}{|T_2 - T_1|}
$$

where $\Delta T_1$ and $\Delta T_2$ are the uncertainties in the scalar values $T_1$ and $T_2$ at positions $x_1$ and $x_2$ respectively.

The vertex normal $V_i$ for vertex $i$ is calculated by summing over all $n$ connected triangles [S1, unofficial]:

$$
V_i = \frac{\sum_n \frac{U_n}{A_n}}{\sum_n \frac{1}{A_n}} = \frac{\sum_n \frac{u_n \times v_n}{\|u_n \times v_n\|^2}}{\sum_n \frac{1}{\|u_n \times v_n\|}}
$$

where for the $n$-th triangle:
*   $u_n$ and $v_n$ are two edge vectors of the triangle.
*   $A_n = \|u_n \times v_n\|$ is the area of the triangle.
*   $U_n = \frac{u_n \times v_n}{A_n}$ is the unit normal vector to the triangle.

**Edge Cases and Pitfalls:**
*   **Ambiguity:** The method claims to remove ambiguities, but the specific mechanism (beyond decimation) is not detailed in the source. Standard Marching Cubes ambiguities (cases 46, 47, etc.) may still cause cracks if not handled by the lookup table or a specific ambiguity resolution step not fully described [S1, S7, S8, unofficial].
*   **Decimation Logic:** The criterion "two or more vertices closest to the same node" requires a robust spatial mapping. If grid resolution is coarse, this may over-collapse. If fine, it may under-collapse.
*   **Re-triangulation:** The source mentions "Re-triangulate using this new vertex" but does not specify the algorithm (e.g., Delaunay, constrained triangulation). This is a significant implementation gap [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the Marching Cubes pass $O(N)$ where $N$ is the number of voxels, plus the decimation pass which depends on the density of small triangles. Normal computation is $O(F)$ where $F$ is the number of faces.
*   **Memory Complexity:** $O(V + F)$ for vertices and faces. Decimation reduces $F$, lowering memory usage compared to standard MC [S1, unofficial].
*   **Performance:** The decimation step reduces storage requirements and improves visual quality by removing high-aspect-ratio triangles [S1, unofficial].
*   **Strengths:** Reduces polygon count; improves visual appearance by smoothing out jagged edges caused by degenerate triangles; provides smooth normals via harmonic weighting.
*   **Limitations:** The re-triangulation step is underspecified; ambiguity handling is claimed but not detailed; uncertainty bounds depend on data variation [S1, unofficial].

## Background
The method originates from the Smokeview visualization tool for Fire Dynamics Simulation (FDS) data [S1, unofficial]. It was designed to handle the large datasets generated by FDS, providing a way to visualize isosurfaces (e.g., temperature contours) with reduced computational and storage overhead. The technique was documented in the Smokeview Technical Reference Guide [S1, unofficial].
