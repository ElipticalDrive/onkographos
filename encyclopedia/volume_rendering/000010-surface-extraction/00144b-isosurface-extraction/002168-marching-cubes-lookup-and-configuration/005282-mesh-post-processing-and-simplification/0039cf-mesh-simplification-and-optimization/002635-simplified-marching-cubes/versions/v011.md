# Simplified Marching Cubes

Also called: SMC discretization, binarized Marching Cubes

## Overview
Simplified Marching Cubes (SMC) is a surface extraction method that produces meshes using only vertices from the regular 3D grid, eliminating interpolation and lookup tables [S1]. It yields approximately half the vertices and triangles of standard Marching Cubes (MC) and Cuberille, reducing memory usage by 50% while maintaining manifold topology [S1]. Unlike MC, SMC uses integer arithmetic exclusively and analyzes cube configurations independently via cumulative coordinates [S1].

## How it works
**Inputs:** A scalar field $F(x, y, z)$ sampled on a cuberille grid; a threshold $\lambda$.
**Outputs:** A mesh consisting of triangles with vertices at grid coordinates.

**Data Structures:**
*   **Vertex:** 3 short integers (2 bytes each) representing integer coordinates $(x, y, z)$. Coordinates must be $< 65535$ [S1].
*   **Triangle:** 3 long integers (4 bytes each) representing vertex indices [S1].
*   **Cube State:** For each cube, a case indicator (0-7) and coefficients for up to two planes $hx + ky + lz + m = 0$, where $(h,k,l) \in \{-1, 0, 1\}^3$ and $m \in \mathbb{N}$. Total size: 7 bytes (1 byte case, 2 bytes normal coefficients, 4 bytes integer $m$) [S1].

**Definitions:**
*   **Binarization:** $F_B(x,y,z) = 1$ if $F(x,y,z) \geq \lambda$, else $0$ [S1].
*   **Node:** A vertex with value $1$ (positive).
*   **Negative Vertex:** A vertex with value $0$.
*   **Interface Node:** A node with at least one negative neighbor in 6-connectivity [S1].
*   **Vertex Index:** For vertex $n \in \{0..7\}$ in a cube, coordinates are $c_i^n = n\%2$, $c_j^n = (n\%4)/2$, $c_k^n = n/4$ [S1].
*   **Cumulative Coordinate:** $C_x = \sum_{n \in \text{nodes}} c_x^n$ [S1].
*   **Neighbor Count:** $N_x(n)$ is the number of node neighbors of vertex $n$ along axis $x$. $N_i(n) = \overline{c_i^n} + 2 c_j^n + 4 c_k^n$, where $\overline{c}$ is the bitwise NOT of $c$ (complement to 1) [S1].
*   **Triangle Type Criterion:** $C_L(n_1, n_2, n_3) = \sum_{l=1}^3 \sum_{m=l+1}^3 \left( \sum_{x=i,j,k} (c_x^{n_l} - c_x^{n_m})^2 \right)^2$. Values: Type I = 6, Type II = 14, Type III = 12 [S1].

**Algorithm Steps:**
1.  Binarize the input field $F$ using $\lambda$ to obtain $F_B$ [S1].
2.  Iterate over every cube formed by 8 neighboring vertices [S1].
3.  Identify all nodes (vertices with value 1) in the current cube [S1].
4.  Count the total number of nodes ($N_{nodes}$) [S1].
5.  If $N_{nodes} \in \{0, 1, 2, 8\}$, output no triangles [S1].
6.  If $N_{nodes} = 3$:
    *   If $C_x = 0$ or $3$ for any axis $x \in \{i, j, k\}$, output one Type I triangle [S1].
7.  If $N_{nodes} = 4$:
    *   If $C_x = 0$ or $4$ for any axis $x \in \{i, j, k\}$ (Case 8), output two Type I triangles on the corresponding face [S1].
    *   If $C_x = 2$ for all axes $x \in \{i, j, k\}$ (Cases 10/13), output no triangles [S1].
    *   If Case 9: Identify the single non-interface node via exhaustive test. Output one Type III triangle formed by the remaining three interface nodes [S1].
    *   If Case 12: Identify the singular node with only negative neighbors. Switch its status to positive (conceptually), then process as 3 nodes (Case 8 logic) to build one Type I triangle [S1].
    *   If Cases 11/14: Output two Type II triangles, identified by nested loops over nodes [S1].
8.  If $N_{nodes} = 5$:
    *   If $C_x = 1$ or $4$ for any axis $x \in \{i, j, k\}$ (Case 17), output two Type II triangles, identified by nested loops over nodes [S1].
    *   If Case 15: Identify singular node with only negative neighbors. Switch its status, then re-process as 3 nodes (Case 9 logic) to build one Type III triangle [S1].
    *   If Case 16: Identify Type III triangle via nested loops. Find the negative vertex with node neighbors, switch its status, then re-process as 6 nodes (Case 20 logic) to build the remaining triangles (two Type II, one Type III) [S1].
9.  If $N_{nodes} = 6$:
    *   If Cases 18/19: Identify two negative vertices that have only node neighbors via exhaustive test. Build two Type III triangles formed by their neighbors [S1].
    *   If Case 20: Output two Type II triangles formed by correctly ordered interface nodes [S1].
10. If $N_{nodes} = 7$:
    *   Identify the single negative vertex. Form one Type III triangle using its three neighbors (which are interface nodes) [S1].

def extract_smc_cube(nodes_mask, cube_origin):
    """
    nodes_mask: list of 8 booleans, True if node (value >= threshold), False otherwise.
    cube_origin: tuple (x, y, z) of the cube's minimum corner.
    Returns: list of triangles, each triangle is a list of 3 vertex coordinates.
    """
    # Identify node indices
    node_indices = [i for i in range(8) if nodes_mask[i]]
    num_nodes = len(node_indices)
    
    if num_nodes in [0, 1, 2, 8]:
        return []

    # Compute cumulative coordinates
    # c_x^n is 0 or 1. 
    # n=0: (0,0,0), n=1: (1,0,0), n=2: (0,1,0), n=3: (1,1,0), 
    # n=4: (0,0,1), n=5: (1,0,1), n=6: (0,1,1), n=7: (1,1,1)
    # c_i (x) = n % 2
    # c_j (y) = (n % 4) // 2
    # c_k (z) = n // 4
    
    C_i = sum((n % 2) for n in node_indices)
    C_j = sum(((n % 4) // 2) for n in node_indices)
    C_k = sum((n // 4) for n in node_indices)
    
    triangles = []

    if num_nodes == 3:
        if C_i in [0, 3] or C_j in [0, 3] or C_k in [0, 3]:
            # Type I triangle
            # Type I is isosceles-right, edge length sqrt(2). 
            # Vertices are on a single face.
            # Implementation detail: Identify the face and the 3 nodes on it.
            # Since we only have 3 nodes, if they are on a face, they form the triangle.
            # We need to find the 3 node indices.
            tri_nodes = [get_vertex_coords(cube_origin, n) for n in node_indices]
            triangles.append(tri_nodes)
            
    elif num_nodes == 4:
        if C_i in [0, 4] or C_j in [0, 4] or C_k in [0, 4]:
            # Case 8: Two Type I triangles on a face
            # Identify the face axis where C is 0 or 4.
            # If C_i=0, nodes are on x=0 face. If C_i=4, nodes are on x=1 face.
            # The 4 nodes form a square on that face. Split into 2 triangles.
            face_nodes = [get_vertex_coords(cube_origin, n) for n in node_indices]
            # Split square into 2 triangles (arbitrary diagonal, consistent with MC-patch)
            triangles.append([face_nodes[0], face_nodes[1], face_nodes[2]])
            triangles.append([face_nodes[0], face_nodes[2], face_nodes[3]])
        elif C_i == 2 and C_j == 2 and C_k == 2:
            # Cases 10/13: No triangles
            pass
        else:
            # Cases 9, 11, 12, 14
            # Determine specific case by checking neighbor counts or specific configurations
            # Case 9: One non-interface node.
            # Case 12: One singular node with only negative neighbors.
            # Case 11/14: Two Type II triangles.
            
            # Helper to check if a node is interface
            def is_interface(node_idx):
                # Check 6-neighbors in the cube
                neighbors = get_6_neighbors(node_idx)
                for nb in neighbors:
                    if not nodes_mask[nb]:
                        return True
                return False

            interface_nodes = [n for n in node_indices if is_interface(n)]
            
            # Check for Case 12: Singular node with only negative neighbors
            # This node is a node but has no node neighbors in 6-connectivity
            singular_node = None
            for n in node_indices:
                neighbors = get_6_neighbors(n)
                has_node_neighbor = any(nodes_mask[nb] for nb in neighbors)
                if not has_node_neighbor:
                    singular_node = n
                    break

                # Case 12: Switch status, process as 3 nodes (Case 8 logic)
                # Effectively, we treat this node as if it were negative, 
                # leaving 3 nodes. But the text says "switch status... re-process as 3 nodes (Case 8)".

                # If we switch it to NEGATIVE, we have 3 nodes.

                # Case 8 is "4 nodes on a cube face". 
                # There is a contradiction or typo in the source text "Case 8" vs "3 nodes".
                # However, Step 7 says: "Switch its status to positive, then re-process as 3 nodes (Case 8) to build one Type I triangle."
                # If it switches to positive, it stays positive. 
                # Let's look at Case 15: "Switch its status, then re-process as 3 nodes (Case 9)".
                # Case 9 is 4 nodes. 
                # It seems the text means: Switch the singular node to NEGATIVE. 
                # Then we have 3 nodes. 
                # But it references Case 8 or 9. 
                # Let's look at the geometry. 
                # Case 12: 4 nodes. One is isolated. The other 3 form a triangle? 
                # If the isolated node is removed, 3 nodes remain. 
                # If those 3 are on a face, it's Type I. 
                # The text says "build one Type I triangle".

                remaining_nodes = [n for n in node_indices if n != singular_node]
                tri_nodes = [get_vertex_coords(cube_origin, n) for n in remaining_nodes]
                triangles.append(tri_nodes)
            else:
                # Check for Case 9: One non-interface node.
                # Interface nodes are those with at least one negative neighbor.
                # Non-interface node is a node with ALL node neighbors.
                non_interface = []
                for n in node_indices:
                    neighbors = get_6_neighbors(n)
                    all_nodes = all(nodes_mask[nb] for nb in neighbors)
                    if all_nodes:
                        non_interface.append(n)
                
                if len(non_interface) == 1:
                    # Case 9: Output one Type III triangle from interface nodes
                    iface = [n for n in node_indices if n != non_interface[0]]
                    tri_nodes = [get_vertex_coords(cube_origin, n) for n in iface]
                    triangles.append(tri_nodes)

                    tri_nodes = [get_vertex_coords(cube_origin, n) for n in node_indices]

            # Usually 5 nodes in MC (Case 17) produces a quad or two triangles.
            # SMC produces 2 Type II.
        else:
            # Cases 15, 16
            # Check for singular node (only negative neighbors)
            singular_node = None
            for n in node_indices:
                neighbors = get_6_neighbors(n)
                has_node_neighbor = any(nodes_mask[nb] for nb in neighbors)
                if not has_node_neighbor:
                    singular_node = n
                    break
            
            if singular_node is not None:
                # Case 15: Switch status (to negative), re-process as 3 nodes (Case 9 logic -> Type III)
                remaining = [n for n in node_indices if n != singular_node]
                # Case 9 logic with 3 nodes? 
                # Text: "re-process as 3 nodes (Case 9) to build one Type III triangle."
                # Case 9 normally has 4 nodes. 
                # If we have 3 nodes, and we build a Type III triangle, we just use the 3 nodes.
                tri_nodes = [get_vertex_coords(cube_origin, n) for n in remaining]
                triangles.append(tri_nodes)
            else:
                # Case 16
                # Identify Type III triangle via nested loops
                # Find negative vertex with node neighbors, switch status, process as 6 nodes (Case 20)
                # This is complex. 
                # Type III is equilateral. 
                # In 5 nodes, Case 16, we output 3 triangles (2 Type II, 1 Type III).
                # The text says: "Identify Type III triangle... find negative vertex... switch... process as 6 nodes (Case 20) to build remaining (2 Type II, 1 Type III)."
                # This implies the Type III is built first, then the rest.
                # Let's identify the Type III triangle. 
                # It is formed by 3 nodes.
                # The remaining 2 nodes + the switched negative node = 6 nodes? 
                # No, 5 nodes + 1 switched = 6 nodes.
                # Case 20 with 6 nodes produces 2 Type II triangles.
                # So total: 1 Type III + 2 Type II.
                
                # Heuristic for Case 16 Type III:
                # It is the triangle formed by the 3 nodes that are mutually adjacent?
                # Or simply the 3 nodes that form an equilateral triangle.
                # We can check C_L.
                from itertools import combinations
                type_iii = None
                for combo in combinations(node_indices, 3):
                    if compute_CL(combo) == 12:
                        type_iii = combo
                        break
                
                if type_iii:
                    tri_nodes = [get_vertex_coords(cube_origin, n) for n in type_iii]
                    triangles.append(tri_nodes)
                    
                    # Remaining nodes
                    remaining = [n for n in node_indices if n not in type_iii]
                    # Find negative vertex with node neighbors
                    # In the original cube, there is 1 negative vertex.
                    neg_vertex = [n for n in range(8) if not nodes_mask[n]][0]
                    # Check if it has node neighbors
                    neighbors = get_6_neighbors(neg_vertex)
                    if any(nodes_mask[nb] for nb in neighbors):
                        # Switch status
                        # Conceptually, this node becomes a node.
                        # Now we have 6 nodes.
                        # Process as Case 20.
                        # Case 20: 6 nodes. Output 2 Type II triangles.

        # Cases 18, 19, 20
        # Check for Case 20 first (simplest)
        # Case 20: 2 Type II triangles
        # Cases 18/19: 2 Type III triangles
        
        # Identify negative vertices
        neg_vertices = [n for n in range(8) if not nodes_mask[n]]
        
        # Check if two negative vertices have only node neighbors
        candidates = []
        for nv in neg_vertices:
            neighbors = get_6_neighbors(nv)
            has_only_node_neighbors = all(nodes_mask[nb] for nb in neighbors)
            if has_only_node_neighbors:

            triangles.append([tri_nodes[0], tri_nodes[2], tri_nodes[3]])
            # Note: This is a simplification. The exact connectivity depends on the node indices.

    elif num_nodes == 7:
        # Case 21: One Type III triangle
        neg_vertex = [n for n in range(8) if not nodes_mask[n]][0]
        neighbors = get_6_neighbors(neg_vertex)
        tri_nodes = [get_vertex_coords(cube_origin, n) for n in neighbors]
        triangles.append(tri_nodes)

def get_vertex_coords(origin, index):
    x = origin[0] + (index % 2)
    y = origin[1] + ((index % 4) // 2)
    z = origin[2] + (index // 4)
    return (x, y, z)

def get_6_neighbors(index):
    # Returns indices of 6-connected neighbors within the cube
    # i-neighbor: index ^ 1
    # j-neighbor: index ^ 2
    # k-neighbor: index ^ 4
    return [index ^ 1, index ^ 2, index ^ 4]

def compute_CL(indices):
    # indices is a tuple of 3 node indices
    coords = [get_vertex_coords((0,0,0), i) for i in indices] # Relative coords
    # c_x^n is just the coordinate value (0 or 1)
    # Formula: sum_{l=1}^3 sum_{m=l+1}^3 ( sum_{x=i,j,k} (c_x^{n_l} - c_x^{n_m})^2 )^2
    # This is the squared distance between nodes? No.
    # It's the sum of squared edge lengths squared?
    # Let's calculate squared edge lengths first.
    # d^2 = sum (dx^2 + dy^2 + dz^2)
    # Then CL = sum (d^2)^2 for all pairs.
    
    def dist_sq(n1, n2):
        c1 = get_vertex_coords((0,0,0), n1)
        c2 = get_vertex_coords((0,0,0), n2)
        return (c1[0]-c2[0])**2 + (c1[1]-c2[1])**2 + (c1[2]-c2[2])**2
    
    d12 = dist_sq(indices[0], indices[1])
    d13 = dist_sq(indices[0], indices[2])
    d23 = dist_sq(indices[1], indices[2])
    
    return d12**2 + d13**2 + d23**2

**Edge Cases and Pitfalls:**
*   **Ambiguity:** SMC avoids MC face configuration ambiguities (holes) by using MC-patch logic and treating configurations 11 and 14 as identical [S1].
*   **Bias:** SMC systematically produces negative volume biases for convex objects and positive for concave objects. The volume bias is larger than MC or Cuberille [S1].
*   **Accuracy:** Surface error for a discretized sphere converges to 7% for SMC, compared to ~0.4% for MC. Cuberille has a 90% error [S1].
*   **Normals:** In binarized images, SMC normal RMS error is ~10-12 degrees, comparable to MC. In smooth images, MC is ~4-6 degrees, while SMC remains ~10-12 degrees [S1].

## Operating characteristics
*   **Time Complexity:** Faster than standard MC. Speedup increases as internal surface area increases [S1].
*   **Memory Complexity:** Half the memory of MC and Cuberille. Vertices use 6 bytes (3 shorts), triangles use 12 bytes (3 longs) [S1].
*   **Strengths:** Integer arithmetic only, no interpolation, no large lookup table, manifold meshes, efficient for large images and moving boundaries [S1].
*   **Limitations:** Lower accuracy than MC, larger volume bias, higher normal error in smooth fields [S1].
*   **When to Use:** Simulations of deposition/ablation, porous media diffusivity, where memory and speed are critical and moderate accuracy is acceptable [S1].
*   **When Not to Use:** When high geometric accuracy or precise normal estimation is required [S1].

## Background
Simplified Marching Cubes was developed for materials science simulations, specifically Chemical Vapor Infiltration (CVI) and ablation modeling [S1]. It was proposed as an efficient alternative to MC for managing physically complex simulations in large 3D blocks [S1]. The method relies on the "MC-patch" configuration list to ensure topological consistency [S1].
