# Streaming Marching Cubes

Also called: Hash table vertex sharing, Polygon-Vertex Identification for Isosurface Polygons

## Overview
Streaming Marching Cubes with Hash Table Vertex Sharing extracts isosurfaces from volumetric datasets by combining memory-efficient streaming processing with explicit vertex sharing to ensure topological consistency [S1, unofficial][S2]. It solves the problem of generating watertight, shared-vertex meshes from massive data that cannot fit entirely in memory, while avoiding the vertex duplication common in naive streaming implementations [S1, unofficial][S2]. It differs from standard [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by explicitly managing vertex identity across cell boundaries via a hash table, and from [Sparse Marching Cubes](3825-sparse-marching-cubes.md) by focusing on the streaming memory constraint rather than spatial sparsity [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
- Input: A scalar field $S(x, y, z)$ defined on a 3D grid, an isovalue $C$, and the grid dimensions [S1, unofficial][S2].
- Output: A triangle mesh where adjacent polygons share identical vertex coordinates and indices [S1, unofficial].

**Data Structures:**
- **Hash Table:** A mapping from a cell edge identifier to a generated vertex [S1, unofficial].
  - Key: A tuple representing the two grid nodes defining the cell edge, e.g., $(node_i, node_j)$ [S1, unofficial].
  - Value: The 3D coordinates of the interpolated vertex on that edge [S1, unofficial].
- **Streaming Buffer:** A 2D slice of the scalar field data. Only two adjacent slices (e.g., $z$ and $z+1$) are held in memory at any time [S2].

**Numbered Steps:**
1. **Initialize:** Create an empty hash table $H$. Initialize the streaming buffer with the first two slices of the volume data [S1, unofficial][S2].
2. **Iterate Slices:** For each pair of adjacent slices in the volume:
   a. **Process Cells:** For each cell in the current slice pair:
      i. **Sign Determination:** Determine the sign of $S(x, y, z) - C$ at all 8 nodes of the cell [S1, unofficial].
      ii. **Skip Empty Cells:** If all signs are equal, the cell does not intersect the isosurface; skip further processing for this cell [S1, unofficial].
      iii. **Identify Intersected Edges:** Extract the cell edges that intersect the isosurface. Each edge is defined by a pair of nodes $(n_a, n_b)$ [S1, unofficial].
      iv. **Vertex Generation/Sharing:** For each intersected edge:
          - Compute the key $k = \text{sort}(n_a, n_b)$ to ensure consistent ordering regardless of cell orientation [G].
          - Check if $k$ exists in $H$.
          - If $k \in H$: Retrieve the existing vertex $v$ from $H$ [S1, unofficial].
          - If $k \notin H$: Interpolate the vertex position $v$ on the edge between $n_a$ and $n_b$ using linear interpolation based on $S(n_a)$ and $S(n_b)$ [G]. Insert $(k, v)$ into $H$ [S1, unofficial].
      v. **Triangulation:** Use the standard Marching Cubes lookup table to determine the triangle connectivity for the cell, using the vertices retrieved from $H$ for the edge intersections [G].
      vi. **Output Triangles:** Emit the triangles for the current cell [S1, unofficial].
   b. **Slide Window:** Discard the older slice and load the next slice into the buffer to process the next pair of slices [S2].
3. **Finalize:** The hash table $H$ contains all unique vertices for the isosurface. The output mesh consists of all emitted triangles [S1, unofficial].

**Formulas:**
- Sign determination: $\sigma_i = \text{sign}(S(n_i) - C)$ for node $i$ [S1, unofficial].
- Linear interpolation on edge between nodes $n_a$ and $n_b$ with scalar values $S_a$ and $S_b$:
  $$ v = n_a + \frac{C - S_a}{S_b - S_a} (n_b - n_a) $$
  [G: Standard linear interpolation formula implied by "interpolated vertex position".]

**Parameters:**
- Isovalue $C$: Specific to the dataset [S1, unofficial].
- Hash Table Size: Depends on the surface complexity; dynamic resizing may be required [G].

**Edge Cases and Pitfalls:**
- **Memory Limitations:** Cell-edge data is not usually preserved in volume data structures due to limited memory space, necessitating this explicit identification process [S1, unofficial].
- **Hash Collisions:** Ensure the key generation for the hash table is robust to avoid collisions between distinct edges [G].
- **Streaming Boundary:** Ensure the hash table persists across slice boundaries to share vertices between cells in adjacent slices [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of cells, assuming hash table operations are $O(1)$ on average [G].
- **Memory Complexity:** $O(S)$ where $S$ is the size of the isosurface (number of unique vertices), plus $O(V_{slice})$ for the streaming buffer [G].
- **Measured Performance:** Allows processing of extremely large datasets that would otherwise exceed memory limits [S2].
- **Scaling:** Scales well with dataset size as only a small portion of the volume is in memory at any time [S2].
- **Strengths:** Memory efficiency, topological consistency (shared vertices), suitability for large datasets [S1, unofficial][S2].
- **Limitations:** Hash table overhead, potential for hash collisions, not suitable for real-time streaming if the hash table grows too large [G].
- **When to Use:** Large volumetric datasets where memory is a constraint and topological consistency is required [S1, unofficial][S2].
- **When Not to Use:** Real-time applications with strict memory limits where the hash table overhead is prohibitive, or when the volume is small enough to fit in memory [G].

## Background
The concept of vertex identification using a hash table was described in the context of isosurface propagation algorithms to share vertices across generated polygons [S1, unofficial]. The streaming aspect, allowing processing of extremely large data sets by keeping only two slices in memory, was highlighted in discussions of the Marching Cubes algorithm's implementation [S2]. The algorithm was originally developed and patented by GE Medical Systems for use in CT and MRI equipment, and has since entered the public domain [S2].
