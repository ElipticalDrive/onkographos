# Streaming Marching Cubes

Also called: Hash table vertex sharing, Polygon-Vertex Identification for Isosurface Polygons

## Overview
Streaming Marching Cubes with Hash Table Vertex Sharing is a method for extracting isosurfaces from large volumetric datasets that combines memory-efficient streaming processing with explicit vertex sharing to ensure topological consistency. It solves the problem of generating watertight, shared-vertex meshes from massive data that cannot fit entirely in memory, while avoiding the vertex duplication common in naive streaming implementations. It differs from standard [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by explicitly managing vertex identity across cell boundaries via a hash table, and from [Sparse Marching Cubes](3825-sparse-marching-cubes.md) by focusing on the streaming memory constraint rather than spatial sparsity.

## How it works
**Inputs and Outputs:**
- Input: A scalar field $S(x, y, z)$ defined on a 3D grid, an isovalue $C$, and the grid dimensions.
- Output: A triangle mesh where adjacent polygons share identical vertex coordinates and indices.

**Data Structures:**
- **Hash Table:** A mapping from a cell edge identifier to a generated vertex.
  - Key: A tuple representing the two grid nodes defining the cell edge, e.g., $(node_i, node_j)$.
  - Value: The 3D coordinates of the interpolated vertex on that edge.
- **Streaming Buffer:** A 2D slice of the scalar field data. Only two adjacent slices (e.g., $z$ and $z+1$) are held in memory at any time.

**Numbered Steps:**
1. **Initialize:** Create an empty hash table $H$. Initialize the streaming buffer with the first two slices of the volume data.
2. **Iterate Slices:** For each pair of adjacent slices in the volume:
   a. **Process Cells:** For each cell in the current slice pair:
      i. **Sign Determination:** Determine the sign of $S(x, y, z) - C$ at all 8 nodes of the cell [S1, unofficial].
      ii. **Skip Empty Cells:** If all signs are equal, the cell does not intersect the isosurface; skip further processing for this cell [S1, unofficial].
      iii. **Identify Intersected Edges:** Extract the cell edges that intersect the isosurface. Each edge is defined by a pair of nodes $(n_a, n_b)$ [S1, unofficial].
      iv. **Vertex Generation/Sharing:** For each intersected edge:
          - Compute the key $k = \text{sort}(n_a, n_b)$ to ensure consistent ordering regardless of cell orientation.
          - Check if $k$ exists in $H$.
          - If $k \in H$: Retrieve the existing vertex $v$ from $H$.
          - If $k \notin H$: Interpolate the vertex position $v$ on the edge between $n_a$ and $n_b$ using linear interpolation based on $S(n_a)$ and $S(n_b)$. Insert $(k, v)$ into $H$.
      v. **Triangulation:** Use the standard Marching Cubes lookup table to determine the triangle connectivity for the cell, using the vertices retrieved from $H$ for the edge intersections.
      vi. **Output Triangles:** Emit the triangles for the current cell.
   b. **Slide Window:** Discard the older slice and load the next slice into the buffer to process the next pair of slices.
3. **Finalize:** The hash table $H$ contains all unique vertices for the isosurface. The output mesh consists of all emitted triangles.

**Formulas:**
- Sign determination: $\sigma_i = \text{sign}(S(n_i) - C)$ for node $i$ [S1, unofficial].
- Linear interpolation on edge between nodes $n_a$ and $n_b$ with scalar values $S_a$ and $S_b$:
  $$ v = n_a + \frac{C - S_a}{S_b - S_a} (n_b - n_a) $$
  [G: Standard linear interpolation formula implied by "interpolated vertex position".]

**Parameters:**
- Isovalue $C$: Specific to the dataset.
- Hash Table Size: Depends on the surface complexity; dynamic resizing may be required.

**Edge Cases and Pitfalls:**
- **Memory Limitations:** Cell-edge data is not usually preserved in volume data structures due to limited memory space, necessitating this explicit identification process [S1, unofficial].
- **Hash Collisions:** Ensure the key generation for the hash table is robust to avoid collisions between distinct edges.
- **Streaming Boundary:** Ensure the hash table persists across slice boundaries to share vertices between cells in adjacent slices.

**Pseudocode:**
```python
def streaming_marching_cubes_with_hash_sharing(volume, isovalue, grid_dims):
    # volume: 3D array of scalar values
    # grid_dims: (nx, ny, nz)
    # isovalue: float C
    
    hash_table = {}  # Key: (node_idx1, node_idx2), Value: (x, y, z)
    triangles = []
    
    # Helper to get node index from grid coordinates
    def get_node_idx(i, j, k):
        return i + j * grid_dims[0] + k * grid_dims[0] * grid_dims[1]
    
    # Helper to sort edge key
    def get_edge_key(node1, node2):
        return (min(node1, node2), max(node1, node2))
    
    # Helper to interpolate vertex on edge
    def interpolate_vertex(node1_idx, node2_idx, val1, val2):
        # Get coordinates of nodes
        n1_coords = get_node_coords(node1_idx, grid_dims)
        n2_coords = get_node_coords(node2_idx, grid_dims)
        
        # Linear interpolation
        t = (isovalue - val1) / (val2 - val1)
        vertex = n1_coords + t * (n2_coords - n1_coords)
        return vertex
    
    # Helper to get node coordinates
    def get_node_coords(node_idx, dims):
        k = node_idx // (dims[0] * dims[1])
        rem = node_idx % (dims[0] * dims[1])
        j = rem // dims[0]
        i = rem % dims[0]
        return (i, j, k) # Assuming unit spacing for simplicity
    
    # Process slices
    for k in range(grid_dims[2] - 1):
        # Load current and next slice into buffer
        slice1 = volume[:, :, k]
        slice2 = volume[:, :, k+1]
        
        for j in range(grid_dims[1] - 1):
            for i in range(grid_dims[0] - 1):
                # Get 8 nodes of the cell
                n000 = get_node_idx(i, j, k)
                n100 = get_node_idx(i+1, j, k)
                n010 = get_node_idx(i, j+1, k)
                n110 = get_node_idx(i+1, j+1, k)
                n001 = get_node_idx(i, j, k+1)
                n101 = get_node_idx(i+1, j, k+1)
                n011 = get_node_idx(i, j+1, k+1)
                n111 = get_node_idx(i+1, j+1, k+1)
                
                nodes = [n000, n100, n010, n110, n001, n101, n011, n111]
                values = [
                    slice1[j, i], slice1[j, i+1], slice1[j+1, i], slice1[j+1, i+1],
                    slice2[j, i], slice2[j, i+1], slice2[j+1, i], slice2[j+1, i+1]
                ]
                
                # Determine signs
                signs = [1 if v - isovalue >= 0 else -1 for v in values]
                
                # Skip if all signs are equal
                if all(s == signs[0] for s in signs):
                    continue
                
                # Identify intersected edges and generate/share vertices
                edge_map = {} # Map from edge key to vertex
                
                # Define edges for the cell (standard MC edges)
                edges = [
                    (n000, n100), (n010, n110), (n001, n101), (n011, n111), # x-edges
                    (n000, n010), (n100, n110), (n001, n011), (n101, n111), # y-edges
                    (n000, n001), (n100, n101), (n010, n011), (n110, n111)  # z-edges
                ]
                
                for n1, n2 in edges:
                    v1 = values[nodes.index(n1)]
                    v2 = values[nodes.index(n2)]
                    
                    # Check if edge intersects isosurface
                    if (v1 - isovalue) * (v2 - isovalue) < 0:
                        edge_key = get_edge_key(n1, n2)
                        if edge_key in hash_table:
                            vertex = hash_table[edge_key]
                        else:
                            vertex = interpolate_vertex(n1, n2, v1, v2)
                            hash_table[edge_key] = vertex
                        edge_map[edge_key] = vertex
                
                # Triangulate using standard MC lookup
                # Determine cube index
                cube_index = sum(1 << idx for idx, s in enumerate(signs) if s == 1)
                
                # Get triangles for this cube index
                # Note: This part relies on the standard MC lookup table configuration
                # For brevity, assuming a function that returns triangle indices based on edge_map
                triangles.extend(get_triangles_for_cube(cube_index, edge_map))
    
    return triangles
```

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of cells, assuming hash table operations are $O(1)$ on average.
- **Memory Complexity:** $O(S)$ where $S$ is the size of the isosurface (number of unique vertices), plus $O(V_{slice})$ for the streaming buffer. This is significantly lower than storing the entire volume if the volume is much larger than the surface.
- **Measured Performance:** Allows processing of extremely large datasets that would otherwise exceed memory limits [S2].
- **Scaling:** Scales well with dataset size as only a small portion of the volume is in memory at any time.
- **Strengths:** Memory efficiency, topological consistency (shared vertices), suitability for large datasets.
- **Limitations:** Hash table overhead, potential for hash collisions, not suitable for real-time streaming if the hash table grows too large.
- **When to Use:** Large volumetric datasets where memory is a constraint and topological consistency is required.
- **When Not to Use:** Real-time applications with strict memory limits where the hash table overhead is prohibitive, or when the volume is small enough to fit in memory.

## Background
The concept of vertex identification using a hash table was described in the context of isosurface propagation algorithms to share vertices across generated polygons [S1, unofficial]. The streaming aspect, allowing processing of extremely large data sets by keeping only two slices in memory, was highlighted in discussions of the Marching Cubes algorithm's implementation [S2]. The algorithm was originally developed and patented by GE Medical Systems for use in CT and MRI equipment, and has since entered the public domain [S2].
