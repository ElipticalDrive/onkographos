# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based isosurface extraction method that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It differs from modern batched or GPU-accelerated approaches by computing the scalar field and geometry on the CPU every frame and flushing small batches of primitives to the GPU, serving primarily as a reference implementation for comparison [S1, unofficial].

## How it works
The method operates on a 3D regular grid (voxel grid) containing a scalar field. It iterates over each cell, determines surface intersections using lookup tables, and outputs triangles directly to the rendering pipeline.

### Inputs and Outputs
- **Input**: A 3D scalar field $F(x,y,z)$ defined on a grid of resolution $N_x \times N_y \times N_z$. The field is typically generated by accumulating contributions from metaballs and a floor term [S1, unofficial].
- **Output**: A stream of triangle vertices and normals rendered to the screen.

### Data Structures
The implementation uses fixed-size typed arrays for batching geometry before sending it to the GPU [S1, unofficial].

**Buffers and Arrays**:
- `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
- `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(nx, ny, nz)$.
- `uvArray`: `Float32Array` of size `maxCount * 2`. Stores UV coordinates (if enabled).
- `colorArray`: `Float32Array` of size `maxCount * 4`. Stores vertex colors (if enabled).
- `maxCount`: Integer, typically 4096 [S1, unofficial]. This defines the batch size.

**State Variables**:
- `count`: Integer, current number of vertices in the current batch.
- `prim`: Primitive type (`TRIANGLES`, `LINES`, `POINTS`).
- `primsize`: Integer, 3 for triangles, 2 for lines, 1 for points.
- `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated.

### Numbered Steps

1.  **Initialize Batch**:
    - Set `prim` to the desired primitive type.
    - Calculate `primsize` (3, 2, or 1).
    - Store program reference.
    - Reset `count` to 0.
    - Reset `hasPos`, `hasNormal`, `hasUV`, `hasColor` to `false`.

2.  **Field Generation (Per Frame)**:
    - For each voxel $(i, j, k)$ in the grid:
        - Initialize $F(i,j,k) = 0$.
        - For each metaball source $m$ with position $P_m$ and radius $R_m$:
            - Calculate distance $d = \sqrt{(i-P_{mx})^2 + (j-P_{my})^2 + (k-P_{mz})^2}$.
            - Accumulate contribution: $F(i,j,k) += \text{contribution}(d, R_m)$.
        - Add floor term contribution to $F(i,j,k)$.
    - [G] The specific contribution function for metaballs is typically $f(d) = \frac{R^2}{d^2}$ or similar falloff, but the exact formula is not specified in the source [S1, unofficial].

3.  **Marching Cubes Extraction**:
    - For each cube (cell) in the grid:
        - Determine the cube index by comparing vertex values to the isovalue (typically 0.5 for normalized fields).
        - Use precomputed lookup tables (e.g., Paul Bourke's tables) to identify intersected edges [S1, unofficial].
        - For each intersected edge:
            - Interpolate the vertex position on the edge using linear interpolation based on the scalar values at the edge endpoints.
            - Calculate the vertex normal using the gradient of the scalar field at the intersection point.
        - Generate triangles based on the cube index configuration.

4.  **Add Vertex Position**:
    - Store $x, y, z$ into `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`.
    - Set `hasPos` to `true`.

5.  **Add Vertex Normal**:
    - Store $x, y, z$ into `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`.
    - Set `hasNormal` to `true`.

6.  **Add Triangle**:
    - Copy positions from `posArray` at offsets $o_1, o_2, o_3$ and normals from `normalArray` at offsets $o_1, o_2, o_3$ into `posArray` and `normalArray` starting at index `count*3`.
    - Increment `count` by 3.
    - If `count >= maxCount - 3`, call `draw()` to flush the buffer.

7.  **Advance Vertex Count**:
    - Increment `count`.
    - If `count >= maxCount - 3` and `count` is divisible by `primsize`, call `draw()` to flush the buffer.

8.  **Flush and Render**:
    - If `count` is 0, return.
    - Zero out remaining `posArray` entries from `count*3` to length.
    - Bind buffers for any enabled attributes (pos, normal, uv, color) using `gl.bufferData` with `DYNAMIC_DRAW`.
    - Enable vertex attribute arrays and set pointers.
    - Call `gl.drawArrays` with the primitive type, offset 0, and count.
    - Reset `count` to 0.

### Parameters and Typical Values
- `maxCount`: 4096 [S1, unofficial].
- Grid Resolution: 16³, 32³, 64³, 128³ [S1, unofficial].
- Number of Blobs: 1, 10, 50, 100 [S1, unofficial].

### Edge Cases and Pitfalls
- **Buffer Overflow**: The code checks if `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].
- **Precision**: Using `Float32Array` may lead to precision issues at high resolutions or with large coordinate values [S1, unofficial].
- **Degenerate Input**: If the scalar field does not cross the isovalue, no geometry is generated [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N^3)$ for field generation and mesh extraction, where $N$ is the grid resolution. The immediate mode rendering adds overhead due to frequent `gl.drawArrays` calls.
- **Memory Complexity**: $O(N^3)$ for the scalar field and $O(1)$ for the mesh buffer (fixed size `maxCount`).
- **Performance**: Limited by CPU bottlenecks at high resolutions or blob counts. It is slower than GPU-based approaches [S1, unofficial].
- **Strengths**: Simple implementation, serves as a good reference, minimal CPU-GPU transfer for small batches.
- **Limitations**: Poor performance at scale, not suitable for real-time high-resolution rendering.

## Background
The CPU Immediate Mode Marching Cubes method is inspired by Greggman's metaballs demo [S1, unofficial]. It uses classic Marching Cubes tables from Paul Bourke [S1, unofficial]. The implementation is part of the `WebGL2-GPU-Marching-Cubes` project by 3merillon [S1, unofficial].
