# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals and renders them directly via graphics API draw calls (e.g., WebGL) without storing a persistent mesh buffer in application memory [S1, unofficial]. It differs from buffered approaches by flushing geometry to the GPU every frame, making it suitable for dynamic scenes like metaballs where the geometry changes rapidly, but it is limited by CPU bottlenecks at high resolutions or high blob counts [S1, unofficial].

## How it works
The method operates in two phases: scalar field generation on the CPU, followed by immediate-mode mesh extraction and rendering. It builds on the precomputed lookup tables defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).

### Inputs and Outputs
*   **Inputs**:
    *   A set of metaballs (or scalar field sources), each defined by position, radius, and strength.
    *   A 3D grid of voxels with resolution $N_x \times N_y \times N_z$.
    *   An isovalue $I$ for surface extraction.
    *   A floor term (constant scalar value) added to the field.
*   **Outputs**:
    *   A rendered mesh of triangles displayed in the viewport.

### Data Structures
The implementation uses fixed-size typed arrays to store vertex attributes for batching. The maximum number of vertices per batch is `maxCount` (typically 4096) [S1, unofficial].

*   `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
*   `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(n_x, n_y, n_z)$.
*   `uvArray`: `Float32Array` of size `maxCount * 2`. Stores UV coordinates (if enabled).
*   `colorArray`: `Float32Array` of size `maxCount * 4`. Stores vertex colors (if enabled).
*   `count`: Integer tracking the number of vertices currently in the buffer.
*   `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated for the current batch.

### Algorithm Steps

1.  **Field Generation**:
    For each voxel center $(x, y, z)$ in the grid:
    *   Initialize scalar value $V = 0$.
    *   For each metaball $j$ with center $C_j$, radius $R_j$, and strength $S_j$:
        *   Calculate distance $d = \| (x, y, z) - C_j \|$.
        *   If $d < R_j$, add contribution: $V += S_j \cdot \frac{R_j^2 - d^2}{R_j^2}$ (or similar smooth falloff).
    *   Add floor term: $V += V_{floor}$.
    *   Store $V$ in the voxel grid.

2.  **Marching Cubes Extraction**:
    For each voxel in the grid:
    *   Sample the scalar field values $V_i$ at the 8 corners $v_i$ ($i=0..7$).
    *   Compute the case index $C$ based on the sign of $V_i - I$.
    *   Look up the `edgeTable` and `triangleTable` for case $C$.
    *   If $C$ indicates no intersection, skip.
    *   For each triangle defined in `triangleTable`:
        *   For each vertex of the triangle, determine the intersected edge index $e_k$.
        *   Interpolate the vertex position $P$ on edge $e_k$ using linear interpolation between the corner values.
        *   Compute the normal $N$ at $P$ by interpolating the gradients at the corners or computing the gradient of the scalar field at $P$.
        *   Add vertex $P$ and normal $N$ to the batch buffers.

3.  **Immediate Mode Rendering**:
    *   **Batching**: As vertices are added, check if `count >= maxCount - 3`. If so, flush the buffer immediately to avoid overflow [S1, unofficial].
    *   **Flush**:
        *   If `count == 0`, return.
        *   Zero out unused entries in `posArray` and `normalArray` from index `count * 3` to the end.
        *   Bind `posBuf` and `normalBuf` (WebGL buffers) using `gl.bufferData` with `DYNAMIC_DRAW`.
        *   Enable vertex attribute arrays for position and normal.
        *   Call `gl.drawArrays(gl.TRIANGLES, 0, count)`.
        *   Reset `count` to 0.

### Pseudocode

```python
# Constants
MAX_COUNT = 4096
PRIMITIVE_TYPE = TRIANGLES
PRIMITIVE_SIZE = 3

# State
count = 0
hasPos = False
hasNormal = False
posArray = Float32Array(MAX_COUNT * 3)
normalArray = Float32Array(MAX_COUNT * 3)

def flush_buffer(gl, posBuf, normalBuf):
    """Flushes the current batch to the GPU."""
    global count, hasPos, hasNormal
    
    if count == 0:
        return

    # Zero out remaining buffer space to prevent garbage data
    for i in range(count * 3, MAX_COUNT * 3):
        posArray[i] = 0.0
        normalArray[i] = 0.0

    # Upload data to GPU
    gl.bufferData(posBuf, posArray, gl.DYNAMIC_DRAW)
    gl.bufferData(normalBuf, normalArray, gl.DYNAMIC_DRAW)

    # Enable attributes
    gl.enableVertexAttribArray(0) # Position
    gl.vertexAttribPointer(0, 3, gl.FLOAT, False, 0, 0)
    
    if hasNormal:
        gl.enableVertexAttribArray(1) # Normal
        gl.vertexAttribPointer(1, 3, gl.FLOAT, False, 0, 0)

    # Draw
    gl.drawArrays(PRIMITIVE_TYPE, 0, count)

    # Reset state
    count = 0
    hasPos = False
    hasNormal = False

def add_vertex(x, y, z, nx, ny, nz):
    """Adds a vertex to the current batch, flushing if necessary."""
    global count, hasPos, hasNormal
    
    # Check for overflow before adding a full triangle
    if count >= MAX_COUNT - PRIMITIVE_SIZE:
        flush_buffer(gl, posBuf, normalBuf)

    # Add position
    idx = count * 3
    posArray[idx] = x
    posArray[idx + 1] = y
    posArray[idx + 2] = z
    hasPos = True

    # Add normal
    if hasNormal or nz != 0: # Assuming normals are always added if present
        normalArray[idx] = nx
        normalArray[idx + 1] = ny
        normalArray[idx + 2] = nz
        hasNormal = True

    count += 1

def add_triangle(o1, o2, o3):

def render_frame(gl, posBuf, normalBuf, voxels, isovalue, blobs):
    """Main loop for CPU Immediate Mode Marching Cubes."""
    
    # 1. Field Generation
    grid = compute_scalar_field(voxels, isovalue, blobs)
    
    # 2. Marching Cubes Extraction
    for each voxel in voxels:
        case_index = compute_case_index(grid, voxel)
        triangles = get_triangles(case_index)
        
        for tri in triangles:

                pos = interpolate_vertex(grid, voxel, vertex.edge_index)
                normal = compute_normal(grid, voxel, pos)

    # 3. Flush
    flush_buffer(gl, posBuf, normalBuf)
```

### Edge Cases and Pitfalls
*   **Buffer Overflow**: The code must check `count >= maxCount - 3` before adding a triangle to ensure there is space for 3 vertices. If exceeded, it flushes immediately [S1, unofficial].
*   **Ambiguity**: Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points. The standard LUT uses a fixed triangulation, which can cause cracks if adjacent voxels resolve ambiguity differently. This method does not inherently resolve ambiguity; it relies on the parent's configuration [S1, unofficial].
*   **Performance**: CPU bottlenecks occur at high resolutions or high blob counts due to the per-voxel field computation and immediate mode overhead [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N \cdot B)$ for field generation, where $N$ is the number of voxels and $B$ is the number of blobs. $O(N)$ for marching cubes extraction.
*   **Memory Complexity**: $O(N)$ for the voxel grid and $O(1)$ for the immediate mode buffer (fixed size).
*   **Performance**: Limited by CPU throughput. Suitable for low-to-medium resolutions (e.g., $64^3$) and small numbers of blobs. Not suitable for high-resolution static scenes or very large numbers of dynamic objects [S1, unofficial].
*   **Strengths**: Simple implementation, no persistent mesh management, good for dynamic scenes like metaballs.
*   **Limitations**: High CPU usage, limited by batch size, no culling of empty voxels (unless optimized with blob influence culling) [S1, unofficial].

## Background
The method is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript, which demonstrated real-time marching cubes on the CPU using WebGL immediate mode [S1, unofficial]. It is a classic approach used in early web-based 3D graphics and educational contexts.
