# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It differs from buffered or GPU-accelerated siblings by performing all field computation and geometry generation on the CPU every frame, sending only small batches of vertices to the GPU for immediate rendering [S1, unofficial]. This approach serves as a reference implementation and for performance comparison, but is limited by CPU bottlenecks at high resolutions or complex scenes [S1, unofficial].

## How it works
The method operates on a 3D grid where each voxel contains a scalar value. It consists of three main phases: field generation, marching cubes extraction, and immediate rendering with batching.

### Inputs and Outputs
- **Input**: A 3D grid of scalar values (field), an isovalue threshold, and a primitive type (TRIANGLES, LINES, or POINTS).
- **Output**: Rendered geometry via WebGL draw calls. No persistent mesh data structure is retained between frames.

### Data Structures
The implementation uses typed arrays to store vertex attributes for batching. The maximum number of vertices per batch is `maxCount = 4096` [S1, unofficial].

- `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
- `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(n_x, n_y, n_z)$.
- `uvArray`: `Float32Array` of size `maxCount * 2`. Stores UV coordinates (optional).
- `colorArray`: `Float32Array` of size `maxCount * 4`. Stores vertex colors (optional).
- `count`: Integer tracking the number of vertices currently in the batch.
- `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated for the current batch.

### Field Generation
For each voxel in the 3D grid, the scalar field value is computed by accumulating contributions from all metaballs (or sources) and a floor term [S1, unofficial]. The specific formula for the field value $F(x, y, z)$ at a voxel center is not explicitly detailed in the source, but it is described as an accumulation of blob contributions [S1, unofficial].

### Marching Cubes Extraction
For each cube in the grid:
1.  Determine the cube index based on the sign of the scalar values at the 8 vertices relative to the isovalue.
2.  Use precomputed tables (e.g., Paul Bourke's tables) to determine which edges of the cube are intersected by the isosurface [S1, unofficial].
3.  Interpolate vertex positions at the intersection points on the edges.
4.  Compute vertex normals, typically by averaging the gradients of the scalar field at the interpolated positions.

### Immediate Rendering with Batching
Vertices are added to the batch arrays. If the batch reaches capacity, it is flushed to the GPU.

#### Parameters
- `maxCount`: 4096 [S1, unofficial].
- `primsize`: 3 for TRIANGLES, 2 for LINES, 1 for POINTS.

#### Pseudocode

```python
# Initialization
maxCount = 4096
posArray = Float32Array(maxCount * 3)
normalArray = Float32Array(maxCount * 3)
uvArray = Float32Array(maxCount * 2)
colorArray = Float32Array(maxCount * 4)
count = 0
hasPos = False
hasNormal = False
hasUV = False
hasColor = False
prim = "TRIANGLES" # or "LINES", "POINTS"
primsize = 3 if prim == "TRIANGLES" else (2 if prim == "LINES" else 1)

def flush_buffer():
    """Flush the current batch to the GPU."""
    global count, hasPos, hasNormal, hasUV, hasColor
    if count == 0:
        return
    
    # Zero out remaining entries to ensure clean state
    for i in range(count * 3, maxCount * 3):
        posArray[i] = 0.0
    # Note: Other arrays (normal, uv, color) should also be zeroed or managed appropriately
    
    # Bind buffers and set pointers
    # This involves WebGL calls: gl.bufferData, gl.enableVertexAttribArray, gl.vertexAttribPointer
    # For posArray:
    gl.bufferData(gl.ARRAY_BUFFER, posArray, gl.DYNAMIC_DRAW)
    gl.enableVertexAttribArray(0) # Position attribute
    gl.vertexAttribPointer(0, 3, gl.FLOAT, False, 0, 0)
    
    # For normalArray (if hasNormal is true):
    if hasNormal:
        gl.bufferData(gl.ARRAY_BUFFER, normalArray, gl.DYNAMIC_DRAW)
        gl.enableVertexAttribArray(1) # Normal attribute
        gl.vertexAttribPointer(1, 3, gl.FLOAT, False, 0, 0)
        
    # For uvArray (if hasUV is true):
    if hasUV:
        gl.bufferData(gl.ARRAY_BUFFER, uvArray, gl.DYNAMIC_DRAW)
        gl.enableVertexAttribArray(2) # UV attribute
        gl.vertexAttribPointer(2, 2, gl.FLOAT, False, 0, 0)
        
    # For colorArray (if hasColor is true):
    if hasColor:
        gl.bufferData(gl.ARRAY_BUFFER, colorArray, gl.DYNAMIC_DRAW)
        gl.enableVertexAttribArray(3) # Color attribute
        gl.vertexAttribPointer(3, 4, gl.FLOAT, False, 0, 0)
        
    # Draw
    gl.drawArrays(prim, 0, count)
    
    # Reset
    count = 0
    hasPos = False
    hasNormal = False
    hasUV = False
    hasColor = False

def add_vertex_position(x, y, z):
    """Add a vertex position to the batch."""
    global count, hasPos
    if count >= maxCount - 3:
        flush_buffer()
    posArray[count * 3 + 0] = x
    posArray[count * 3 + 1] = y
    posArray[count * 3 + 2] = z
    hasPos = True
    count += 1

def add_vertex_normal(nx, ny, nz):
    """Add a vertex normal to the batch."""
    global count, hasNormal
    # Normals are stored per vertex, so we assume count is already incremented for the vertex
    # This function is typically called after add_vertex_position for the same vertex index
    normalArray[count * 3 + 0] = nx
    normalArray[count * 3 + 1] = ny
    normalArray[count * 3 + 2] = nz
    hasNormal = True

def add_triangle(o1, o2, o3):
    """Add a triangle defined by offsets into the pos/norm arrays."""
    global count
    # Copy positions
    posArray[count * 3 + 0] = posArray[o1 * 3 + 0]
    posArray[count * 3 + 1] = posArray[o1 * 3 + 1]
    posArray[count * 3 + 2] = posArray[o1 * 3 + 2]
    posArray[count * 3 + 3] = posArray[o2 * 3 + 0]
    posArray[count * 3 + 4] = posArray[o2 * 3 + 1]
    posArray[count * 3 + 5] = posArray[o2 * 3 + 2]
    posArray[count * 3 + 6] = posArray[o3 * 3 + 0]
    posArray[count * 3 + 7] = posArray[o3 * 3 + 1]
    posArray[count * 3 + 8] = posArray[o3 * 3 + 2]
    
    # Copy normals
    normalArray[count * 3 + 0] = normalArray[o1 * 3 + 0]
    normalArray[count * 3 + 1] = normalArray[o1 * 3 + 1]
    normalArray[count * 3 + 2] = normalArray[o1 * 3 + 2]
    normalArray[count * 3 + 3] = normalArray[o2 * 3 + 0]
    normalArray[count * 3 + 4] = normalArray[o2 * 3 + 1]
    normalArray[count * 3 + 5] = normalArray[o2 * 3 + 2]
    normalArray[count * 3 + 6] = normalArray[o3 * 3 + 0]
    normalArray[count * 3 + 7] = normalArray[o3 * 3 + 1]
    normalArray[count * 3 + 8] = normalArray[o3 * 3 + 2]
    
    count += 3
    if count >= maxCount - 3:
        flush_buffer()

def advance_vertex_count():
    """Increment count and flush if necessary."""
    global count
    count += 1
    if count >= maxCount - 3 and count % primsize == 0:
        flush_buffer()
```

### Edge Cases and Pitfalls
- **Buffer Overflow**: The code checks if `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].
- **Precision**: Floating-point precision in `Float32Array` is used for vertex positions and normals.
- **Boundary Conditions**: The field generation must handle the boundaries of the 3D grid correctly, ensuring all voxels are processed.

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of voxels in the grid. Each voxel is processed once for field generation and once for marching cubes.
- **Memory Complexity**: $O(1)$ persistent memory (buffers are reused), but $O(V)$ temporary memory for the batch, where $V$ is the number of vertices in the batch (max 4096 * 3 floats for positions).
- **Measured Performance**: Limited by CPU bottlenecks at high resolutions or blob counts [S1, unofficial]. Performance degrades as the number of blobs and grid resolution increase.
- **Strengths**: Simple implementation, serves as a good reference, minimal CPU-GPU transfer overhead for small batches.
- **Limitations**: Poor scalability for large volumes or high-resolution grids due to CPU processing time.
- **When to Use**: Reference implementations, educational purposes, or scenes with very low resolution and few objects.
- **When Not to Use**: High-resolution volumes, real-time applications with complex scenes, or when GPU acceleration is available.

## Background
The CPU Immediate Mode Marching Cubes method is inspired by Gregg Tavares' (Greggman) metaballs demo [S1, unofficial]. It uses classic marching cubes tables from Paul Bourke [S1, unofficial]. The implementation is part of the `WebGL2-GPU-Marching-Cubes` project by 3merillon [S1, unofficial].
