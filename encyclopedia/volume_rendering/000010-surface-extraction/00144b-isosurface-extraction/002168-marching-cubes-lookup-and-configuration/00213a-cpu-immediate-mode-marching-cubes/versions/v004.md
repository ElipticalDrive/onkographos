# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based implementation of the marching cubes algorithm that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It differs from modern GPU-accelerated or persistent-buffer approaches by computing the scalar field and geometry on the CPU every frame and streaming primitives directly to the GPU, serving primarily as a reference implementation for comparison [S1, unofficial].

## How it works
The method operates on a 3D grid where each voxel's scalar value is computed by accumulating contributions from metaballs and a floor term [S1, unofficial]. The algorithm traverses the grid, uses precomputed lookup tables to determine edge intersections, interpolates vertex positions, and batches the resulting triangles for immediate rendering [S1, unofficial].

### Inputs and Outputs
- **Input**: A 3D grid of resolution $N \times N \times N$, a list of metaball definitions (position, radius, strength), and an isovalue threshold.
- **Output**: A stream of triangle primitives rendered to the screen.

### Data Structures
The implementation uses a fixed-size batching buffer to hold vertex attributes before flushing to the GPU [S1, unofficial].

- **`maxCount`**: Integer, typically 4096 [S1, unofficial].
- **`posArray`**: `Float32Array` of size `maxCount * 3` [S1, unofficial].
- **`normalArray`**: `Float32Array` of size `maxCount * 3` [S1, unofficial].
- **`uvArray`**: `Float32Array` of size `maxCount * 2` [S1, unofficial].
- **`colorArray`**: `Float32Array` of size `maxCount * 4` [S1, unofficial].
- **`count`**: Integer, tracks the number of vertices currently in the batch [S1, unofficial].
- **`hasPos`, `hasNormal`, `hasUV`, `hasColor`**: Boolean flags indicating which attributes are populated [S1, unofficial].
- **`prim`**: Primitive type (`TRIANGLES`, `LINES`, or `POINTS`) [S1, unofficial].
- **`primsize`**: Integer, 3 for triangles, 2 for lines, 1 for points [S1, unofficial].

### Steps

1. **Initialize Batching**: Set `prim` to the desired primitive type, calculate `primsize`, store the shader program reference, reset `count` to 0, and reset all attribute flags (`hasPos`, etc.) to false [S1, unofficial].
2. **Field Generation**: For each voxel in the 3D grid, compute the scalar field value $f(x,y,z)$ by summing contributions from all metaballs and a floor term [S1, unofficial].
3. **Marching Cubes Extraction**: Iterate over each cube in the grid:
    - Determine the cube index based on the sign of the scalar values at the 8 vertices relative to the isovalue.
    - Use precomputed tables (e.g., Paul Bourke's tables) to identify which edges are intersected by the isosurface [S1, unofficial].
    - Interpolate the exact vertex positions and normals at the intersection points [S1, unofficial].
4. **Add Vertex Position**: Store the interpolated position $(x, y, z)$ into `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos` to true [S1, unofficial].
5. **Add Vertex Normal**: Store the interpolated normal $(nx, ny, nz)$ into `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal` to true [S1, unofficial].
6. **Add Triangle**: For each triangle generated by the cube configuration:
    - Copy positions from `posArray` at offsets $o_1, o_2, o_3$ and normals from `normalArray` at offsets $o_1, o_2, o_3$ into `posArray` and `normalArray` starting at index `count*3` [S1, unofficial].
    - Increment `count` by 3 [S1, unofficial].
    - **Buffer Overflow Check**: If `count >= maxCount - 3`, call `draw()` to flush the buffer immediately [S1, unofficial].
7. **Advance Vertex Count**: Increment `count`. If `count >= maxCount - 3` and `count` is divisible by `primsize`, call `draw()` to flush the buffer [S1, unofficial].
8. **Flush and Render**: After processing all cubes:
    - If `count` is 0, return [S1, unofficial].
    - Zero out remaining entries in `posArray` from `count*3` to the end of the array [S1, unofficial].
    - Bind buffers for any enabled attributes (pos, normal, uv, color) using `gl.bufferData` with `DYNAMIC_DRAW` [S1, unofficial].
    - Enable vertex attribute arrays and set pointers [S1, unofficial].
    - Call `gl.drawArrays` with the primitive type, offset 0, and `count` [S1, unofficial].
    - Reset `count` to 0 [S1, unofficial].

### Pitfalls
- **Buffer Overflow**: The code checks if `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N^3)$ for field generation and mesh extraction, where $N$ is the grid resolution [S1, unofficial].
- **Memory Complexity**: $O(N^3)$ for the scalar field storage and $O(1)$ for the batching buffer (fixed size) [S1, unofficial].
- **Performance**: Limited by CPU bottlenecks at high resolutions or high blob counts [S1, unofficial].
- **Strengths**: Simple implementation, serves as a good reference, minimal CPU-GPU transfer for uniforms/textures [S1, unofficial].
- **Limitations**: Poor performance at scale, not suitable for real-time high-resolution rendering [S1, unofficial].
- **When to use**: For educational purposes, reference implementations, or low-resolution scenes [S1, unofficial].
- **When not to use**: For high-performance applications, large volumes, or real-time rendering with many objects [S1, unofficial].

## Background
The CPU Immediate Mode Marching Cubes implementation is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript [S1, unofficial]. It uses classic marching cubes tables from Paul Bourke [S1, unofficial]. The project is part of a WebGL2 GPU Marching Cubes repository, providing a CPU mode for comparison [S1, unofficial].
