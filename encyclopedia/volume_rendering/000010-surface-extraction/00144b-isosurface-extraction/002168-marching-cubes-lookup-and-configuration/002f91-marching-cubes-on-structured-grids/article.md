# Marching Cubes on Structured Grids

Also called: MC extraction, Marching Cubes in IJK Coordinate Space, Marching Cubes mesh extraction from implicit volume

## Overview
Marching Cubes on Structured Grids extracts a 3D polygonal mesh from a discretized scalar field defined on a regular 3D grid (structured grid) by identifying the isosurface where the scalar value equals a specified threshold [S1, unofficial][S2]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by processing each voxel cell independently to determine local topology [S2]. Unlike [Advancing Front Framework for Implicit Surfaces](819-advancing-front-framework-for-implicit-surfaces.md) which grows a mesh from a seed, or [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md) which optimize vertex positions for accuracy, Marching Cubes relies on a fixed lookup table to triangulate intersections within each cell [S2].

## How it works
**Inputs:**
1.  **Scalar Field:** A 3D array of scalar values $V$ with dimensions $R_x \times R_y \times R_z$ (resolution).
2.  **Isosurface Threshold:** A float value $T$ defining the surface level [S1, unofficial].
3.  **Grid Bounds:** Lower bounds $c_1 = [x_{min}, y_{min}, z_{min}]$ and upper bounds $c_2 = [x_{max}, y_{max}, z_{max}]$ defining the physical space covered by the grid [S1, unofficial].
4.  **Network/Function (Optional):** If the scalar field is generated by a neural network (e.g., NeRF), the network parameters and evaluation configuration [S1, unofficial].

**Outputs:**
1.  **Vertices:** A list of 3D coordinates $(x, y, z)$ in physical space.
2.  **Triangles:** A list of indices referencing the vertices, forming the mesh faces.

**Data Structures:**
*   **Grid:** A 3D array `sigmas` of shape `(R_x, R_y, R_z)`.
*   **Lookup Table:** A standard 256-entry table mapping 8-bit vertex sign masks (0-255) to triangle configurations (sets of edge indices) [S2].

**Steps:**

1.  **Grid Generation:**
    Generate a 3D grid of query points in IJK (index) coordinate space. If using a neural network, these points represent the latent space coordinates.
    $$ P_{ijk} = \text{grid}(i, j, k) \quad \text{for } i \in [0, R_x), j \in [0, R_y), k \in [0, R_z) $$
    [S1, unofficial]

2.  **Scalar Field Evaluation:**
    Evaluate the scalar field $\sigma$ at each grid point.
    *   If using a neural network:
        *   Check if the network uses view directions. If true, warn that results may be invalid as sigma becomes view-dependent [S1, unofficial].
        *   If view directions are used, compute fake view directions pointing to the origin:
            $$ \vec{v}_{ijk} = -\frac{P_{ijk}}{\|P_{ijk}\|} $$
        *   Split the grid points into batches of size $B$ (e.g., 100,000) to manage memory [S1, unofficial].
        *   For each batch, perform a forward pass through the network to extract the sigma value at the specified index [S1, unofficial].
        *   Concatenate results and reshape into the 3D grid `sigmas` of shape $(R_x, R_y, R_z)$ [S1, unofficial].
    *   If using a static volume:
        *   Directly read the scalar values from the volume data structure into `sigmas` [S2].

3.  **Marching Cubes Extraction:**
    Apply the standard Marching Cubes algorithm to the `sigmas` grid using threshold $T$ [S1, unofficial].
    *   For each cell $(i, j, k)$:
        *   Determine the 8-bit configuration mask $M$ by comparing the 8 corner values of the cell to $T$.
        *   Use $M$ to look up the set of edges intersected by the isosurface.
        *   Calculate the intersection points on these edges using linear interpolation. For an edge between vertices $V_a$ and $V_b$ with values $\sigma_a$ and $\sigma_b$:
            $$ P_{interp} = V_a + \frac{T - \sigma_a}{\sigma_b - \sigma_a} (V_b - V_a) $$
        *   Generate triangles from the intersection points based on the lookup table configuration [S2].

4.  **Coordinate Transformation:**
    The extracted vertices are initially in IJK (index) space or normalized space depending on the implementation. Transform them to physical XYZ space:
    $$ V_{xyz} = V_{ijk} \times \frac{c_2 - c_1}{R} + c_1 $$
    Where $R$ is the resolution vector $(R_x, R_y, R_z)$ [S1, unofficial].
    *Note: Performing the Marching Cubes algorithm in IJK space and interpolating back to XYZ is not technically correct for non-uniform grids, but the difference is negligible for most applications [S2].*

5.  **Post-processing:**
    *   Restore network training state if it was modified during evaluation [S1, unofficial].
    *   Return the final vertices and triangles [S1, unofficial].

**Pseudocode:**

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def marching_cubes_on_structured_grid(network, c1, c2, reso, isosurface, eval_batch_size=100000):
    """
    Extracts a mesh from a structured grid using Marching Cubes.
    
    Args:
        network: Neural network or scalar field function.
        c1: List[int] Lower bounds (x,y,z). Default [-1, -1, -1].
        c2: List[int] Upper bounds (x,y,z). Default [1, 1, 1].
        reso: List[int] Resolution (x,y,z). Default [128, 128, 128].
        isosurface: Float Sigma threshold. Default 50.0.
        eval_batch_size: Int Points per batch. Default 100000.
        
    Returns:
        vertices: Array of shape (N, 3) in XYZ space.
        triangles: Array of shape (M, 3) of vertex indices.
    """
    # 1. Generate 3D grid in IJK/index space
    # util.gen_grid creates a meshgrid and flattens it
    grid_points = util.gen_grid(*zip(c1, c2, reso), ij_indexing=True)
    
    # 2. Handle network state and view directions
    is_train = network.training
    network.eval()
    
    # Check for view directions (invalid for static sigma extraction)
    if network.uses_viewdirs:
        print("Warning: Network uses viewdirs. Using fake viewdirs to origin.")
        # Compute fake viewdirs pointing to origin
        # grid_points are relative to c1, so we normalize them
        norms = torch.norm(grid_points, dim=-1, keepdim=True)
        # Avoid division by zero
        norms = torch.where(norms == 0, torch.ones_like(norms), norms)
        fake_viewdirs = -grid_points / norms
    else:
        fake_viewdirs = None
        
    # 3. Evaluate scalar field in batches
    all_sigmas = []
    grid_batches = torch.split(grid_points, eval_batch_size, dim=0)
    viewdir_batches = torch.split(fake_viewdirs, eval_batch_size, dim=0) if fake_viewdirs is not None else [None] * len(grid_batches)
    
    for pnts, vd in zip(grid_batches, viewdir_batches):
        # Forward pass
        outputs = network(pnts, coarse=False, viewdirs=vd)
        # Extract sigma (assuming sigma is at index 0 or specific channel)
        sigmas = outputs[..., 0] # sigma_idx typically 0 for occupancy/density
        all_sigmas.append(sigmas)
        
    # 4. Concatenate and reshape
    sigmas = torch.cat(all_sigmas, dim=0)
    sigmas = sigmas.view(*reso).cpu().numpy()
    
    # 5. Run Marching Cubes
    # mcubes.marching_cubes returns vertices in IJK/normalized space relative to the grid bounds
    vertices_ijk, triangles = mcubes.marching_cubes(sigmas, isosurface)
    
    # 6. Scale to physical XYZ space
    # Formula: V_xyz = V_ijk * (c2 - c1) / reso + c1
    # Note: mcubes.marching_cubes typically returns vertices in [0, 1] range if input is normalized,
    # or in grid index units. The source code applies scaling directly.
    scale_factor = (np.array(c2) - np.array(c1)) / np.array(reso)
    vertices_xyz = vertices_ijk * scale_factor + np.array(c1)
    
    # 7. Restore state and return
    if is_train:
        network.train()
        
    return vertices_xyz, triangles
```

**Edge Cases and Pitfalls:**
*   **View Directions:** If the scalar field depends on view direction (e.g., standard NeRF), extracting a static isosurface is invalid because the sigma value changes with the camera position. The code substitutes fake viewdirs pointing to the origin, which produces incorrect geometry [S1, unofficial].
*   **IJK to XYZ Interpolation:** Interpolating intersection points in IJK space and then transforming to XYZ is an approximation. For strictly uniform grids, this is exact. For non-uniform structured grids, it introduces geometric error, though often negligible [S2].
*   **Boundary Conditions:** The algorithm assumes the grid covers the entire volume of interest. Vertices on the boundary of the grid may result in open meshes if not capped [S2].

## Subtopics

### [Uniform Marching Cubes with Snapping](7468-uniform-marching-cubes-with-snapping.md)
Uniform Marching Cubes with Snapping is a uniform-grid polygonization algorithm that computes cell topology masks from coarse grid vertex signs and optionally snaps iso-surface vertices to edges by minimizing distance to grid vertices. It builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by introducing a snapping mechanism that reduces geometric error, distinguishing it from standard UMC and other siblings like [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md) which prioritize bitwise operations over positional accuracy.

### [Smart Conversion](7489-smart-conversion.md)
Smart Conversion is an advanced, gradient-based voxel-to-mesh conversion algorithm that prioritizes geometric accuracy by correcting errors arising from noise, multiple materials, or inaccurate iso-values. Unlike standard isosurface extraction methods such as [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) which rely on fixed threshold crossings, Smart Conversion iteratively "pulls" the mesh vertices to align with the true boundary of the scan by locating points of steepest gradient along local surface normals. This makes it particularly suitable for medical or high-precision industrial contexts where the initial voxel data may contain flaws or where the iso-value does not perfectly represent the physical boundary.

### [Flying Edges](7520-flying-edges.md)
Flying Edges is a parallel, threaded algorithm for volumetric isocontouring of continuous scalar fields that addresses the performance limitations of Marching Cubes by processing volume edges rather than voxel cells. It eliminates point merging bottlenecks by using an edge-based iterator to generate output points and triangle cells, avoiding the need for hashing duplicate points.

### [Undeformed Space Ray Start via Deformed Hull Intersection](10141-undeformed-space-ray-start-via-deformed-hull-intersection.md)
This method finds the ray start point $\hat{x}_0 = D^{-1}(p)$ in undeformed space without computing the inverse deformation map $D^{-1}$ directly. It solves the problem where $D$ may not be invertible or well-defined at the camera position by intersecting the deformed view ray with a deformed explicit hull mesh that contains the surface.

### [Dividing Cubes](10391-dividing-cubes.md)
Dividing Cubes is an isosurface extraction method that replaces the triangular mesh primitives of Marching Cubes with 3D points. It solves the problem of excessive triangle counts and the subsequent scan-conversion overhead in Marching Cubes by adaptively subdividing cells intersected by the surface until each subcell projects onto a single pixel. Unlike its siblings, it generates a point cloud rather than a fixed mesh, allowing for gradient-shaded rendering without explicit triangle rasterization.

### [Analytic Marching](12525-analytic-marching.md)
Analytic Marching (AM) is a meshing algorithm that extracts the exact zero-level isosurface of an implicit function represented by a ReLU-based Multi-Layer Perceptron (MLP) as a polygon mesh, without relying on discrete 3D grid sampling. Unlike [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md), whose accuracy depends on discretization resolution, AM exploits the piecewise linear nature of ReLU networks to identify linear regions intersected by the surface and solve for vertices analytically, making its precision independent of grid resolution.

### [GPU-Accelerated Metaball Isosurface Generation](12526-gpu-accelerated-metaball-isosurface-generation.md)
This method generates an isosurface from a combined field of metaballs using a two-stage GPU pipeline, utilizing vertex shaders for field evaluation and geometry shaders for mesh generation. It is distinguished from standard CPU-based or single-pass GPU implementations by its explicit separation of field computation and mesh topology generation, coupled with Transform-Feedback caching to avoid recomputing geometry when the camera moves but the metaball configuration remains static. It builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by offloading the structured grid vertex evaluation and cube processing to the GPU.

### Matveyev's Algorithm
An algorithm based on a triangulation table that correctly represents trilinear interpolant behavior using intersections on cube diagonals [S3]. Proposed by Matveyev in 1999 [S3].

### Geomorph LOD Seam Handling
A technique to achieve watertight seams between fine and coarse LOD levels in Marching Cubes by geometrically deforming the fine surface at the boundary to match the coarse contour [S4, unofficial]. Steps: 1. Identify boundary vertices between fine and coarse LOD levels. 2. Apply a geometric morph (bending) to fine surface vertices at the boundary. 3. Deform vertices toward the coarse contour to eliminate gaps [S4, unofficial].

### Cell Subdivision Isosurface Extraction
A method that retains the identity of cells (vertex/node centered data) and eliminates non-linear hanging nodes by subdividing boundary cells into pyramids, allowing standard isosurface techniques to be applied [S5, unofficial]. Steps: 1. Subdivide lower-resolution cell faces to match higher-resolution faces, eliminating hanging nodes along edges. 2. Obtain values at newly created hanging nodes by linear interpolation. 3. Subdivide 3D cells into pyramids with a common apex point to eliminate non-linear hanging nodes. 4. Apply standard isosurface techniques on the subdivided pyramid cells [S5, unofficial]. Tested on star cluster formation: 2.30 sec for 44,332 cells/10,456 triangles (first level) and 7.73 sec for 303,759 cells/77,029 triangles (multiple levels) [S5, unofficial]. Unlike the dual grid approach, this method retains the original cell identity and uses subdivision/pyramids instead of stitch cells [S5, unofficial].

### TexF with Implicit Geometry (SDF)
An extension where TexF shares a canonical grid with an implicit Signed Distance Field (SDF). The surface is extracted via Marching Cubes, and TexF attributes are transferred to vertices for standard vertex-color rendering, avoiding per-pixel TexF queries [S6, unofficial]. Steps: 1. Grid Sharing: The SDF and TexF share the same canonical grid. 2. Surface Extraction: Extract a mesh from the SDF using Marching Cubes. 3. Attribute Transfer: Transfer TexF attributes to the mesh vertices using k-nearest-neighbor interpolation. 4. Rendering: Rasterize the mesh using a standard vertex-color pipeline, where the rasterizer interpolates vertex attributes across triangles [S6, unofficial].

### 3-Edge Cube Sampling with Corner Extension
Instead of calculating intersection points for all 12 edges of a cube, compute intersections for only the 3 edges in the bottom-left corner of each cube [S7, unofficial]. Add an extra row in the top-right corner of the processing zone to ensure all necessary grid values are accessible for the reduced edge set [S7, unofficial]. The indexing logic requires a special upgrade/mapping to correctly access grid values, making it complicated to implement correctly [S7, unofficial].

### Octree-Based Isolevel Culling
Build an octree structure over the volume to assess the ISO level distribution, allowing the algorithm to skip processing areas far from the target isolevel [S7, unofficial]. Propagation-based culling methods are noted as unreliable and inefficient compared to direct octree assessment [S7, unofficial].

### Coarse Sampling Dead-Space Elimination
Perform an initial pass sampling the volume at a coarser spatial rate to identify and eliminate regions where field strength is well below the isolevel [S7, unofficial]. Coarse sampling provides virtually no performance gain for non-trivial fields, as safe sampling borders still capture most of the grid [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels in the grid. Each voxel is processed independently [S2].
*   **Memory Complexity:** $O(N)$ for storing the scalar field and the output mesh. The algorithm can be implemented as a streaming operation requiring only two slices of data in memory at any given time, allowing it to work on extremely large datasets [S2].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with resolution. Parallelization is straightforward due to cell independence [S2].
*   **Strengths:** Simple to implement; robust; produces watertight meshes for well-behaved scalar fields; streaming capability allows handling of large volumes [S2].
*   **Limitations:** Accuracy is limited by grid resolution; artifacts may occur near boundaries or with ambiguous topologies (e.g., saddle points) without advanced disambiguation; view-dependent fields cannot be accurately extracted as static meshes [S1, unofficial].
*   **When to use:** When a quick, robust mesh extraction from a regular grid is needed, and the grid resolution is sufficient to capture the desired detail.
*   **When not to use:** When high geometric accuracy is required at low resolution (consider [Dual Contouring and Surface Nets](6319-dual-contouring-and-surface-nets.md)); when the scalar field is view-dependent; when the grid is unstructured (consider [Unstructured and Arbitrary Grid Methods](11103-unstructured-and-arbitrary-grid-methods.md)).

## Background
The algorithm was originally developed and patented by GE Medical Systems for use in their CT and MRI equipment. The patent has since expired, placing the algorithm in the public domain [S2]. It is one of the most common visualization methods in use today [S2].
