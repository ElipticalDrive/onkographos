# GPU-Accelerated Metaball Isosurface Generation

Also called: Transform-Feedback Metaballs, Two-stage GPU Metaballs

## Overview
This method generates an isosurface from a combined field of metaballs using a two-stage GPU pipeline, utilizing vertex shaders for field evaluation and geometry shaders for mesh generation [S1, unofficial]. It is distinguished from standard CPU-based or single-pass GPU implementations by its explicit separation of field computation and mesh topology generation, coupled with Transform-Feedback caching to avoid recomputing geometry when the camera moves but the metaball configuration remains static [S1, unofficial]. It builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by offloading the structured grid vertex evaluation and cube processing to the GPU [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of metaball parameters (position, radius, color, negative flag, superquadratic flag, and optional scale/exponents/rotation for superquadratic types); a grid resolution (e.g., $64 \times 64 \times 64$) [S1, unofficial].
*   **Outputs:** A vertex array buffer containing the generated triangle mesh [S1, unofficial].

**Data Structures:**
*   **Metaball Parameters:** Each metaball is defined by:
    *   Position (3D vector)
    *   Radius ($r_0$)
    *   Color
    *   Negative flag (boolean: emits negative field)
    *   Superquadratic flag (boolean)
    *   If superquadratic: Scale factors along X, Y, Z axes; X, Y, Z exponents; Rotation matrix (specifies orientation of Z axis) [S1, unofficial].
*   **Grid Vertices:** A 3D grid of vertices. Each vertex stores:
    *   Combined field effect value
    *   Surface normal direction
    *   Color [S1, unofficial].

**Field Evaluation Formulas:**
The combined field value $F(\mathbf{x})$ at a point $\mathbf{x}$ is the sum of contributions from all metaballs. For a single metaball, the contribution $f(r)$ depends on the type:

1.  **Regular Quadratic Metaball:** Uses the Wyvill polynomial [66] in [S1, unofficial]:
    $$ f(r) = 1 - 3\left(\frac{r}{r_0}\right)^2 + 2\left(\frac{r}{r_0}\right)^3 $$
    where $r$ is the distance from $\mathbf{x}$ to the metaball's center, and $r_0$ is the metaball's radius [S1, unofficial].

2.  **Superquadratic Metaball:** Uses the function [67] in [S1, unofficial]:
    $$ f(r) = 1 - \left(\frac{r}{r_0}\right)^{n_1} - \left(\frac{r}{r_0}\right)^{n_2} $$
    where $r$ is the distance to the center, $r_0$ is the size, and $n_1, n_2$ are exponents defining the shape [S1, unofficial].

**Numbered Steps:**

1.  **Stage 1: Field Evaluation (Vertex Shader)**
    1.  Generate a grid of user-specified dimensions and resolution (e.g., $64 \times 64 \times 64$) [S1, unofficial].
    2.  Execute OpenGL vertex shader programs in parallel, with each shader processing a single vertex in the grid [S1, unofficial].
    3.  For each vertex, evaluate all specified metaballs to calculate the combined field effect value, surface normal direction, and color [S1, unofficial].
    4.  Write these results into a separate array (vertex buffer) for the next stage [S1, unofficial].

2.  **Stage 2: Mesh Generation (Geometry Shader)**
    1.  Each shader program handles a cube composed of 8 previously computed vertices and their attributes [S1, unofficial].
    2.  Determine if the cube is intersected by the isosurface (using Marching Cubes logic on the field values) [S1, unofficial].
    3.  If intersected, emit appropriate triangles via the OpenGL geometry shader [S1, unofficial].
    4.  For every emitted triangle, interpolate normal and vertex color values using the information calculated in Stage 1 [S1, unofficial].

3.  **Caching (Transform-Feedback)**
    1.  Capture the geometry generated by the two-stage approach in a dynamically allocated vertex array buffer using Transform-Feedback [S1, unofficial].
    2.  Reuse this vertex array for rendering without recalculating geometry if the metaball configuration has not changed (e.g., during camera rotation or zoom) [S1, unofficial].

**Pseudocode:**

```python
# Stage 1: Vertex Shader Execution
def evaluate_metaball_field(vertex_pos, metaballs):
    """
    Evaluates the combined field value, normal, and color for a vertex.
    """
    combined_field = 0.0
    normal = vec3(0.0, 0.0, 0.0)
    color = vec3(0.0, 0.0, 0.0)
    
    for ball in metaballs:
        # Calculate distance r
        r = length(vertex_pos - ball.position)
        
        # Calculate contribution based on type
        if ball.is_superquadratic:
            # Superquadratic formula
            # Note: Scale factors and rotation matrix would transform the position
            # relative to the ball's local space before calculating r.
            # For simplicity, assuming r is already in local space or ball is axis-aligned.
            term1 = (r / ball.radius) ** ball.exponent_x
            term2 = (r / ball.radius) ** ball.exponent_y
            # The source formula uses n1, n2. Assuming isotropic or simplified here.
            # Actual implementation would use specific exponents for X, Y, Z.
            # Using generic n1, n2 as per source description.
            contribution = 1.0 - (r / ball.radius) ** ball.n1 - (r / ball.radius) ** ball.n2
        else:
            # Regular quadratic Wyvill polynomial
            ratio = r / ball.radius
            contribution = 1.0 - 3.0 * ratio**2 + 2.0 * ratio**3
            
        # Apply negative flag
        if ball.negative:
            contribution = -contribution
            
        combined_field += contribution
        color += ball.color * contribution # Simple color blending
        
        # Calculate normal (gradient of field)
        # Numerical gradient or analytical derivative needed here.
        # Source mentions normal direction is calculated.
        # [G] Analytical gradient for Wyvill: df/dr = -6(r/r0) + 6(r/r0)^2
        # Normal = -grad(F) / |grad(F)|
        # This is a placeholder for the actual gradient computation logic.
        normal += ball.color * gradient(contribution, vertex_pos, ball.position)
        
    # Normalize normal
    normal = normalize(normal)
    
    return combined_field, normal, color

def stage1_vertex_shader(grid_vertex_index, metaballs, grid_resolution):
    """
    Executed in parallel for each vertex in the grid.
    """
    vertex_pos = get_grid_vertex_position(grid_vertex_index, grid_resolution)
    field_val, normal, color = evaluate_metaball_field(vertex_pos, metaballs)
    
    # Write to output buffer for Stage 2
    write_to_buffer(grid_vertex_index, field_val, normal, color)

# Stage 2: Geometry Shader Execution
def stage2_geometry_shader(cube_vertex_indices, metaballs, grid_resolution):
    """
    Executed for each cube in the grid.
    """
    # Retrieve attributes for the 8 vertices of the cube
    cube_vertices = []
    for idx in cube_vertex_indices:
        cube_vertices.append(read_from_buffer(idx))
        
    # Determine cube case (Marching Cubes lookup)
    cube_case = determine_marching_cubes_case(cube_vertices, isosurface_threshold)
    
    if cube_case != 0:
        # Generate triangles based on cube case
        triangles = generate_marching_cubes_triangles(cube_vertices, cube_case)
        
        for tri in triangles:
            # Interpolate normals and colors for the triangle vertices
            # [G] Standard linear interpolation of vertex attributes
            emit_triangle(tri)
```

**Parameters:**
*   Grid resolution: $64 \times 64 \times 64$ voxels was used in the source implementation [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Recomputation:** Recomputing the isosurface for every frame during camera rotation or zoom is wasteful. Solution: Use Transform-Feedback to cache the geometry [S1, unofficial].
*   **Noise in Normals:** For superquadratic metaballs, the 2D buffer or map containing normal values can be noisy, leading to abrupt changes in orientation. Solution: Use a 5-step isosurface refinement routine (subdividing ray stepping size) and apply a Gaussian blurring kernel to the normal map [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Stage 1 is $O(V \cdot N)$ where $V$ is the number of grid vertices and $N$ is the number of metaballs. Stage 2 is $O(C)$ where $C$ is the number of cubes. With Transform-Feedback, subsequent frames are $O(1)$ for geometry generation if the field is unchanged.
*   **Memory Complexity:** $O(V)$ for storing vertex attributes (field, normal, color) and $O(T)$ for the output triangle buffer, where $T$ is the number of triangles.
*   **Performance:** The two-stage approach leverages the massively parallel architecture of modern GPUs for optimum performance [S1, unofficial].
*   **Strengths:** Interactive frame-rates for metaball rendering; efficient caching for static scenes.
*   **Limitations:** Requires GPU support for Transform-Feedback and Geometry Shaders; noise in normals for superquadratic metaballs requires additional processing.

## Background
This method was implemented as part of a thesis on context-preserving volume image exploration using a 3D painting metaphor [S1, unofficial]. It was designed to provide interactive frame-rates for metaball-based volumetric objects, particularly for surface painting and peeling operations [S1, unofficial]. The approach builds on the Marching Cubes algorithm and utilizes OpenGL's vertex and geometry shaders [S1, unofficial].
