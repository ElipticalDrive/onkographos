# Marching Cubes on Structured Grids

Also called: Marching Cubes in IJK Coordinate Space

## Overview
Marching Cubes on Structured Grids is a surface extraction method that generates a triangular mesh from voxel data by performing the standard Marching Cubes algorithm in the discrete IJK coordinate space and subsequently interpolating the resulting vertex positions into continuous XYZ space [S1]. It solves the problem of applying a grid-centric algorithm to data defined on arbitrary 3D structured grids (e.g., non-uniform or curved grids) by decoupling topology determination from geometric positioning. It differs from standard implementations by deferring coordinate mapping to a post-processing interpolation step, which is noted as technically approximate but negligible for most applications [S1].

## How it works
The method processes a scalar field $V$ defined on a structured grid. The grid has dimensions $N_x \times N_y \times N_z$ in IJK indices. The physical coordinates of grid vertices are given by a mapping function $\mathbf{P}(i, j, k)$, where $(i, j, k)$ are integer indices.

**Inputs:**
*   Scalar field $V[i][j][k]$ for $0 \le i < N_x, 0 \le j < N_y, 0 \le k < N_z$.
*   Physical coordinate mapping $\mathbf{P}(i, j, k)$ returning a 3D vector.
*   Isovalue $I$.
*   Lookup tables: `edgeTable` (256 entries) and `triangleTable` (256x16 entries) as defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).

**Outputs:**
*   A list of triangles, each defined by three 3D vertices in XYZ space.

**Data Structures:**
*   `edgeTable`: Array of 256 integers. Bit $k$ set if edge $k$ intersects the isosurface.
*   `triangleTable`: Array of size $256 \times 16$. Contains triplets of edge indices $(a, b, c)$ terminated by `-1`.

**Algorithm Steps:**

1.  **Iterate Voxels:** Loop through each voxel cell defined by indices $(i, j, k)$ where $0 \le i < N_x-1$, $0 \le j < N_y-1$, $0 \le k < N_z-1$.
2.  **Determine Case Index:** Calculate the 8-bit case index $C$ for the current voxel. The 8 vertices of the voxel are indexed $v_0$ to $v_7$. The bit assignment must match the vertex ordering assumed by the LUTs (typically $v_0=(0,0,0), v_1=(1,0,0), \dots, v_7=(1,1,1)$ in local IJK space).
    $$
    C = \sum_{m=0}^{7} \text{bit}_m \cdot 2^m
    $$
    where $\text{bit}_m = 1$ if $V(v_m) < I$ (or $> I$, depending on convention), else $0$.
3.  **Lookup Edge Intersections:** Retrieve the bitmask $M = \text{edgeTable}[C]$. If $M == 0$, the voxel contains no intersection; continue to the next voxel.
4.  **Identify Intersected Edges:** Iterate through the 12 edges of the cube. For each edge index $e \in [0, 11]$, check if bit $e$ is set in $M$.
5.  **Compute Local Intersection Points:** For each intersected edge, determine the position of the intersection point in **IJK space** (normalized $[0,1]^3$). Let the edge connect local vertices $v_a$ and $v_b$ with scalar values $V_a$ and $V_b$. The interpolation parameter $t$ is:
    $$
    t = \frac{I - V_a}{V_b - V_a}
    $$
    The local intersection point $\mathbf{p}_{local}$ is:
    $$
    \mathbf{p}_{local} = (1-t)\mathbf{v}_a + t\mathbf{v}_b
    $$
    where $\mathbf{v}_a, \mathbf{v}_b$ are the local coordinates $(0 \text{ or } 1)$ of the vertices.
6.  **Map to XYZ Space:** Convert the local intersection point $\mathbf{p}_{local} = (x_{loc}, y_{loc}, z_{loc})$ to physical XYZ space. This is done by interpolating the physical coordinates of the voxel's corners. Let $\mathbf{P}_{m} = \mathbf{P}(i + x_m, j + y_m, k + z_m)$ be the physical coordinates of the 8 corners of the current voxel. The physical position $\mathbf{p}_{xyz}$ is computed via trilinear interpolation:
    $$
    \mathbf{p}_{xyz} = \sum_{m=0}^{7} w_m \mathbf{P}_m
    $$
    where $w_m$ are the trilinear weights corresponding to the local position $\mathbf{p}_{local}$. Specifically, if $\mathbf{p}_{local} = (x, y, z)$, the weights are products of $(1-x)$ or $x$, $(1-y)$ or $y$, and $(1-z)$ or $z$ based on the binary representation of $m$.
7.  **Generate Triangles:** Retrieve the triangle configuration from `triangleTable[C]`. Iterate through the triplets $(a, b, c)$ until the terminator `-1` is reached. For each triplet, the vertices of the triangle are the physical positions $\mathbf{p}_{xyz}$ computed for edges $a, b, c$. Add the triangle to the output mesh.

**Pseudocode:**

```python
def marching_cubes_structured_grid(V, P, I, edge_table, triangle_table):
    """
    V: 3D array of scalar values [Nx, Ny, Nz]
    P: function or 4D array mapping (i, j, k) to XYZ vector
    I: isovalue
    edge_table: list of 256 integers
    triangle_table: list of 256 lists, each containing 16 integers
    """
    triangles = []
    Nx, Ny, Nz = V.shape
    
    # Precompute corner physical coordinates for the current voxel to avoid repeated lookups
    # P is assumed to be accessible as P[i][j][k] or a callable
    
    for i in range(Nx - 1):
        for j in range(Ny - 1):
            for k in range(Nz - 1):
                # 1. Get scalar values at the 8 corners
                # Vertex ordering must match the LUT convention
                # v0=(0,0,0), v1=(1,0,0), v2=(1,1,0), v3=(0,1,0)
                # v4=(0,0,1), v5=(1,0,1), v6=(1,1,1), v7=(0,1,1)
                vals = [
                    V[i][j][k],       # v0
                    V[i+1][j][k],     # v1
                    V[i+1][j+1][k],   # v2
                    V[i][j+1][k],     # v3
                    V[i][j][k+1],     # v4
                    V[i+1][j][k+1],   # v5
                    V[i+1][j+1][k+1], # v6
                    V[i][j+1][k+1]    # v7
                ]
                
                # 2. Calculate Case Index C
                C = 0
                for m in range(8):
                    if vals[m] < I: # Convention: inside if < I
                        C |= (1 << m)
                
                # 3. Lookup edge table
                edge_mask = edge_table[C]
                if edge_mask == 0:
                    continue
                
                # 4. Get physical coordinates of the 8 corners for interpolation
                # P(i,j,k) returns a vector (x,y,z)
                corners_xyz = [
                    P(i, j, k),
                    P(i+1, j, k),
                    P(i+1, j+1, k),
                    P(i, j+1, k),
                    P(i, j, k+1),
                    P(i+1, j, k+1),
                    P(i+1, j+1, k+1),
                    P(i, j+1, k+1)
                ]
                
                # Helper to get intersection point in XYZ for a given edge index
                def get_intersection_xyz(edge_idx):
                    # Edge definitions (local vertex indices)
                    edges = [
                        (0, 1), (1, 2), (2, 3), (3, 0), # Bottom
                        (4, 5), (5, 6), (6, 7), (7, 4), # Top
                        (0, 4), (1, 5), (2, 6), (3, 7)  # Vertical
                    ]
                    va_idx, vb_idx = edges[edge_idx]
                    va_val = vals[va_idx]
                    vb_val = vals[vb_idx]
                    
                    # Interpolation factor
                    denom = vb_val - va_val
                    if denom == 0:
                        t = 0.5 # Fallback, though usually handled by ambiguity logic
                    else:
                        t = (I - va_val) / denom
                    
                    # Local intersection point (normalized 0-1)
                    # va and vb are local coordinates (0 or 1)
                    va_local = [va_idx & 1, (va_idx >> 1) & 1, (va_idx >> 2) & 1]
                    vb_local = [vb_idx & 1, (vb_idx >> 1) & 1, (vb_idx >> 2) & 1]
                    
                    p_local = [
                        (1-t)*va_local[0] + t*vb_local[0],
                        (1-t)*va_local[1] + t*vb_local[1],
                        (1-t)*va_local[2] + t*vb_local[2]
                    ]
                    
                    # Trilinear interpolation to XYZ
                    # Weights based on p_local
                    x, y, z = p_local
                    w = [
                        (1-x)*(1-y)*(1-z),
                        x*(1-y)*(1-z),
                        x*y*(1-z),
                        (1-x)*y*(1-z),
                        (1-x)*(1-y)*z,
                        x*(1-y)*z,
                        x*y*z,
                        (1-x)*y*z
                    ]
                    
                    p_xyz = [0.0, 0.0, 0.0]
                    for m in range(8):
                        p_xyz[0] += w[m] * corners_xyz[m][0]
                        p_xyz[1] += w[m] * corners_xyz[m][1]
                        p_xyz[2] += w[m] * corners_xyz[m][2]
                    
                    return p_xyz

                # 5. Generate Triangles
                tri_config = triangle_table[C]
                idx = 0
                while idx < 15:
                    a = tri_config[idx]
                    b = tri_config[idx+1]
                    c = tri_config[idx+2]
                    
                    if a == -1:
                        break
                    
                    # Compute vertices
                    v_a = get_intersection_xyz(a)
                    v_b = get_intersection_xyz(b)
                    v_c = get_intersection_xyz(c)
                    
                    triangles.append((v_a, v_b, v_c))
                    
                    idx += 3

    return triangles
```

**Edge Cases and Pitfalls:**
*   **Interpolation Accuracy:** The method interpolates the intersection point in IJK space and then maps to XYZ. This is not technically correct for non-linear grids, as the isosurface intersection in physical space does not necessarily correspond to the linear interpolation in index space [S1]. However, the difference is negligible for most applications [S1].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points. The standard LUT uses a fixed triangulation, which can cause cracks if adjacent voxels resolve ambiguity differently. This applies to the topology determined in IJK space as well [S1, Parent].
*   **Streaming:** Since each cell is processed individually, the algorithm can be implemented as a streaming operation requiring only two slices of data in memory at any given time, allowing it to handle extremely large datasets [S1].

## Subtopics

### [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md)
Bitwise Marching Cubes is a surface extraction algorithm that generates a triangular mesh from voxel data by determining the topology of an isosurface within each voxel cube. It distinguishes itself from standard Marching Cubes implementations by using a bitwise propagation technique to compute the cube index (case number) for the current cell, reusing bits from the previous cell in the X, Y, and Z directions to avoid redundant voxel lookups for shared corners. This method builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by optimizing the state management of corner values across the grid traversal.

### [Uniform Marching Cubes with Snapping](7468-uniform-marching-cubes-with-snapping.md)
Uniform Marching Cubes with Snapping is a uniform-grid polygonization algorithm that computes cell topology masks from coarse grid vertex signs and optionally snaps iso-surface vertices to edges by minimizing distance to grid vertices. It builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by introducing a snapping mechanism that reduces geometric error, distinguishing it from standard UMC and other siblings like [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md) which prioritize bitwise operations over positional accuracy.

### [Smart Conversion](7489-smart-conversion.md)
Smart Conversion is an advanced, gradient-based voxel-to-mesh conversion algorithm that prioritizes geometric accuracy by correcting errors arising from noise, multiple materials, or inaccurate iso-values. Unlike standard isosurface extraction methods such as [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) which rely on fixed threshold crossings, Smart Conversion iteratively "pulls" the mesh vertices to align with the true boundary of the scan by locating points of steepest gradient along local surface normals. This makes it particularly suitable for medical or high-precision industrial contexts where the initial voxel data may contain flaws or where the iso-value does not perfectly represent the physical boundary.

### [Flying Edges](7520-flying-edges.md)
Flying Edges is a parallel, threaded algorithm for volumetric isocontouring of continuous scalar fields that addresses the performance limitations of Marching Cubes by processing volume edges rather than voxel cells. It eliminates point merging bottlenecks by using an edge-based iterator to generate output points and triangle cells, avoiding the need for hashing duplicate points.

### [Undeformed Space Ray Start via Deformed Hull Intersection](10141-undeformed-space-ray-start-via-deformed-hull-intersection.md)
This method determines the starting point $\hat{x}_0$ in undeformed (object) space for a ray tracing trajectory in a deformed volume, avoiding the direct computation of the inverse deformation map $D^{-1}$. It solves the problem where $D$ may not be invertible or well-defined at the camera position by intersecting the deformed view ray with a deformed explicit hull mesh that contains the surface. It differs from [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md) and [Position Error Minimized Marching Cubes](7435-position-error-minimized-marching-cubes.md) by prioritizing the robust generation of a bounding hull for inverse approximation rather than optimizing the isosurface extraction itself.

### [Dual Grid Isosurface Extraction](10271-dual-grid-isosurface-extraction.md)
Dual Grid Isosurface Extraction extracts continuous, crack-free isosurfaces from cell-centered Adaptive Mesh Refinement (AMR) data by treating cell centers as vertices of a new grid, thereby avoiding the dangling nodes inherent in standard Marching Cubes on vertex-centered resampled data. It differs from previous crack-fixing solutions that create polygons, collapse polylines, or use triangle fans by using a dual grid and tessellated "stitch cells" to maintain topological consistency without interpolation artifacts.

### [Dividing Cubes](10391-dividing-cubes.md)
Dividing Cubes is a surface extraction method that replaces the triangular mesh output of Marching Cubes with point-based representations or pixels, primarily used when data points are sufficiently dense that triangles become smaller than a pixel. It eliminates the traditional scan conversion step by subdividing surface voxels into smaller cubes and projecting intensity directly to the viewing plane.

### Matveyev's Algorithm
An algorithm based on a triangulation table that correctly represents trilinear interpolant behavior using intersections on cube diagonals [S2]. Proposed by Matveyev in 1999 [S2].

### Geomorph LOD Seam Handling
A technique to achieve watertight seams between fine and coarse LOD levels in Marching Cubes by geometrically deforming the fine surface at the boundary to match the coarse contour [S3, unofficial]. Steps: 1. Identify boundary vertices between fine and coarse LOD levels. 2. Apply a geometric morph (bending) to fine surface vertices at the boundary. 3. Deform vertices toward the coarse contour to eliminate gaps [S3, unofficial].

### Cell Subdivision Isosurface Extraction
A method that retains the identity of cells (vertex/node centered data) and eliminates non-linear hanging nodes by subdividing boundary cells into pyramids, allowing standard isosurface techniques to be applied [S4, unofficial]. Steps: Subdivide lower-resolution cell faces to match higher-resolution faces, eliminating hanging nodes along edges. Obtain values at newly created hanging nodes by linear interpolation. Subdivide 3D cells into pyramids with a common apex point to eliminate non-linear hanging nodes. Apply standard isosurface techniques on the subdivided pyramid cells [S4, unofficial]. Tested on star cluster formation: 2.30 sec for 44,332 cells/10,456 triangles (first level) and 7.73 sec for 303,759 cells/77,029 triangles (multiple levels) [S4, unofficial]. Unlike the dual grid approach, this method retains the original cell identity and uses subdivision/pyramids instead of stitch cells [S4, unofficial].

### TexF with Implicit Geometry (SDF)
An extension where TexF shares a canonical grid with an implicit Signed Distance Field (SDF). The surface is extracted via Marching Cubes, and TexF attributes are transferred to vertices for standard vertex-color rendering, avoiding per-pixel TexF queries [S5, unofficial]. Steps: Grid Sharing: The SDF and TexF share the same canonical grid. Surface Extraction: Extract a mesh from the SDF using Marching Cubes. Attribute Transfer: Transfer TexF attributes to the mesh vertices using k-nearest-neighbor interpolation. Rendering: Rasterize the mesh using a standard vertex-color pipeline, where the rasterizer interpolates vertex attributes across triangles [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once. The constant factor depends on the number of intersected edges and triangles per voxel.
*   **Memory Complexity:** $O(1)$ auxiliary memory if implemented as a streaming operation, requiring only two slices of the input data in memory at any time [S1]. The output mesh size depends on the surface complexity.
*   **Performance:** The method is efficient on modern graphics hardware and is one of the most common visualization methods in use [S1].
*   **Strengths:** Simple to implement; supports streaming for large datasets; works on any 3D structured grid via interpolation [S1].
*   **Limitations:** The IJK-to-XYZ interpolation is technically incorrect for non-linear grids, though the error is usually negligible [S1]. Ambiguity cases can lead to topological errors if not handled [Parent].
*   **When to use:** When working with structured grid data (uniform or non-uniform) and a quick, standard isosurface extraction is needed.
*   **When not to use:** When high geometric accuracy on highly non-linear grids is required, or when crack-free topology is critical without additional ambiguity handling.

## Background
The Marching Cubes algorithm was originally developed and patented by GE Medical Systems for use in their CT and MRI equipment [S1]. The patent has since expired, placing the algorithm in the public domain [S1]. It is used by several other algorithms such as Metaballs and Part Extraction [S1]. The specific approach of performing the algorithm in IJK space and interpolating back to XYZ is a modification to allow extraction on any 3D structured grid [S1].
