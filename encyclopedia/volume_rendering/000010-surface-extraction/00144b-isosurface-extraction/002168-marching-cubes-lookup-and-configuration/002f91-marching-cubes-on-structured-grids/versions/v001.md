# Marching Cubes on Structured Grids

Also called: Marching Cubes in IJK Coordinate Space

## Overview
Marching Cubes on Structured Grids is a surface extraction method that computes the isosurface of a scalar field defined on a regular, axis-aligned grid by performing the standard Marching Cubes topology lookup in the discrete IJK (index) coordinate space and subsequently mapping the resulting vertices into continuous XYZ (physical) space [S1]. It solves the problem of extracting meshes from volumetric data that is stored in a structured array (e.g., CT scans, fluid simulations) where the logical grid indices do not directly correspond to the physical world coordinates. It differs from direct XYZ-space implementations by decoupling the topological decision-making (which relies on the regular connectivity of the IJK grid) from the geometric positioning, allowing the algorithm to handle arbitrary affine or non-linear grid transformations via post-interpolation [S1].

## How it works
The method processes the scalar field $V$ defined on a structured grid with dimensions $N_x \times N_y \times N_z$. The grid vertices are indexed by integer coordinates $(i, j, k)$ where $0 \le i < N_x$, $0 \le j < N_y$, and $0 \le k < N_z$. Each vertex $v_{i,j,k}$ has an associated physical position $P_{i,j,k}$ and a scalar value $V_{i,j,k}$.

**Inputs:**
*   Scalar field array $V$ of size $N_x \times N_y \times N_z$.
*   Physical position mapping function $P(i, j, k)$ that returns the 3D vector $\mathbf{x}$ for any integer grid index $(i, j, k)$.
*   Isovalue $I$.
*   Lookup Tables: `edgeTable` (256 entries) and `triangleTable` (256 rows) as defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).

**Outputs:**
*   A list of triangles, where each triangle consists of three vertices. Each vertex is a 3D vector in physical XYZ space.

**Data Structures:**
*   **Vertex Cache:** A temporary structure to store the interpolated physical positions of edge intersections for the current voxel to avoid redundant calculations for shared edges.
*   **Edge Interpolation:** Linear interpolation is used to find the intersection point on an edge between two vertices $A$ and $B$ with values $V_A$ and $V_B$:
    $$ \mathbf{x}_{int} = \mathbf{x}_A + \frac{I - V_A}{V_B - V_A} (\mathbf{x}_B - \mathbf{x}_A) $$

**Steps:**
1.  **Iterate Voxels:** Loop through every voxel in the grid. A voxel is identified by its lower-corner index $(i, j, k)$. The 8 corners of the voxel are indexed $0$ to $7$ according to the standard Marching Cubes convention (e.g., $v_0=(i,j,k)$, $v_1=(i+1,j,k)$, etc.).
2.  **Compute Case Index:** For the current voxel, determine the 8-bit case index $C$. For each corner $m \in [0, 7]$, if $V(v_m) < I$ (or $> I$, consistent with the LUT generation convention), set bit $m$ of $C$ to 1; otherwise 0.
3.  **Lookup Topology:** Retrieve the edge intersection mask from `edgeTable[C]`. If the mask is 0, the voxel contains no surface, and the loop continues to the next voxel.
4.  **Identify Intersected Edges:** Iterate through the 12 edges of the cube. For each edge $e$ where the corresponding bit in the mask is set:
    a. Identify the two physical vertices $A$ and $B$ defining the edge in IJK space.
    b. Retrieve their physical positions $\mathbf{x}_A = P(i_A, j_A, k_A)$ and $\mathbf{x}_B = P(i_B, j_B, k_B)$.
    c. Retrieve their scalar values $V_A$ and $V_B$.
    d. Compute the intersection point $\mathbf{x}_{int}$ using linear interpolation.
    e. Store $\mathbf{x}_{int}$ in the Vertex Cache associated with edge index $e$.
5.  **Generate Triangles:** Retrieve the triangle definitions from `triangleTable[C]`. The table provides triplets of edge indices $(a, b, c)$.
    a. For each triplet, retrieve the pre-computed intersection points $\mathbf{x}_a, \mathbf{x}_b, \mathbf{x}_c$ from the Vertex Cache.
    b. Add the triangle $(\mathbf{x}_a, \mathbf{x}_b, \mathbf{x}_c)$ to the output mesh.
6.  **Handle Ambiguities:** If the case index $C$ is one of the ambiguous cases (46, 47, 98, 99, 210, 213, 214, 215), the standard LUT provides a fixed triangulation. Note that this may cause topological inconsistencies (cracks) if adjacent voxels resolve the ambiguity differently [S1, Parent]. Advanced ambiguity handling requires external logic not covered in the basic structured grid implementation.
7.  **Repeat:** Continue until all voxels are processed.

**Pseudocode:**
```python
def marching_cubes_structured_grid(V, P, I, edge_table, triangle_table):
    """
    V: 3D array of scalar values, shape (Nx, Ny, Nz)
    P: function mapping (i, j, k) -> (x, y, z)
    I: isovalue
    edge_table: list of 256 integers (bitmasks)
    triangle_table: list of 256 lists of integers (terminated by -1)
    """
    triangles = []
    Nx, Ny, Nz = V.shape
    
    # Iterate over all voxels. 
    # A voxel at (i, j, k) has corners from (i,j,k) to (i+1,j+1,k+1)
    for i in range(Nx - 1):
        for j in range(Ny - 1):
            for k in range(Nz - 1):
                # 1. Get scalar values at the 8 corners
                # Corner indexing follows standard MC:
                # 0:(0,0,0), 1:(1,0,0), 2:(1,1,0), 3:(0,1,0)
                # 4:(0,0,1), 5:(1,0,1), 6:(1,1,1), 7:(0,1,1) relative to (i,j,k)
                corners = [
                    V[i,   j,   k],
                    V[i+1, j,   k],
                    V[i+1, j+1, k],
                    V[i,   j+1, k],
                    V[i,   j,   k+1],
                    V[i+1, j,   k+1],
                    V[i+1, j+1, k+1],
                    V[i,   j+1, k+1]
                ]
                
                # 2. Compute Case Index C
                C = 0
                for bit in range(8):
                    if corners[bit] < I: # Convention: < I sets bit to 1
                        C |= (1 << bit)
                
                # 3. Lookup Edge Mask
                edge_mask = edge_table[C]
                if edge_mask == 0:
                    continue
                
                # 4. Compute Intersection Points
                # Map edge index (0-11) to corner indices
                edge_corners = [
                    (0, 1), (1, 2), (2, 3), (3, 0), # Bottom
                    (4, 5), (5, 6), (6, 7), (7, 4), # Top
                    (0, 4), (1, 5), (2, 6), (3, 7)  # Vertical
                ]
                
                intersections = {}
                
                for edge_idx in range(12):
                    if (edge_mask >> edge_idx) & 1:
                        c1_idx, c2_idx = edge_corners[edge_idx]
                        
                        # Get physical positions and values
                        # Corner global indices
                        c1_global = (
                            i + (c1_idx & 1),
                            j + ((c1_idx >> 1) & 1),
                            k + (c1_idx >> 2)
                        )
                        c2_global = (
                            i + (c2_idx & 1),
                            j + ((c2_idx >> 1) & 1),
                            k + (c2_idx >> 2)
                        )
                        
                        x1 = P(c1_global[0], c1_global[1], c1_global[2])
                        x2 = P(c2_global[0], c2_global[1], c2_global[2])
                        v1 = corners[c1_idx]
                        v2 = corners[c2_idx]
                        
                        # Linear Interpolation
                        # t = (I - v1) / (v2 - v1)
                        # x_int = x1 + t * (x2 - x1)
                        # Guard against division by zero if v1 == v2
                        if abs(v2 - v1) < 1e-9:
                            x_int = x1 # [G] Fallback for degenerate edge
                        else:
                            t = (I - v1) / (v2 - v1)
                            x_int = x1 + t * (x2 - x1)
                            
                        intersections[edge_idx] = x_int
                
                # 5. Generate Triangles
                tri_defs = triangle_table[C]
                idx = 0
                while idx < len(tri_defs) and tri_defs[idx] != -1:
                    e1 = tri_defs[idx]
                    e2 = tri_defs[idx+1]
                    e3 = tri_defs[idx+2]
                    
                    # Retrieve points from cache
                    p1 = intersections[e1]
                    p2 = intersections[e2]
                    p3 = intersections[e3]
                    
                    triangles.append((p1, p2, p3))
                    idx += 3
                    
    return triangles
```

**Parameters:**
*   **Isovalue $I$:** The scalar threshold. Typical values depend on the data range (e.g., 0.5 for normalized [0,1] data).
*   **Interpolation Method:** Linear interpolation is standard. Higher-order interpolation (trilinear) is not used for vertex placement in the standard algorithm to maintain linear complexity per voxel, though it may be used in variants [S2].

**Edge Cases and Pitfalls:**
*   **IJK-to-XYZ Mapping:** The method assumes that the topological structure is determined in IJK space and geometry in XYZ space. If the grid is highly distorted, the linear interpolation in physical space combined with the standard MC topology (derived from a unit cube) may produce geometrically incorrect results or self-intersections. However, for most applications, this difference is negligible [S1].
*   **Ambiguity:** Standard LUTs do not resolve the 8 ambiguous cases correctly for trilinear interpolants. This can lead to holes or cracks in the mesh if the grid is not perfectly aligned with the isosurface topology [S1, Parent].
*   **Boundary Conditions:** The loop runs from $0$ to $N-1$ for each dimension. Voxels on the boundary of the grid are processed, but vertices outside the grid are not accessed.

## Subtopics

### [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md)
Optimizes state management by reusing corner values from adjacent cells to avoid redundant lookups.

### [Position Error Minimized Marching Cubes](7435-position-error-minimized-marching-cubes.md)
Variant focusing on reducing geometric error in vertex placement.

Gradient-based correction for noise and inaccurate isovalues.

### [Flying Edges](7520-flying-edges.md)
Processes volume edges rather than cells for parallel performance.

### [Marching Slices with Slab-based Caching](9753-marching-slices-with-slab-based-caching.md)
Uses slab caching to prevent revisiting processed cubes.

### Matveyev's Algorithm
An algorithm based on a triangulation table that correctly represents trilinear interpolant behavior using intersections on cube diagonals [S2]. Proposed by Matveyev in 1999, it differs from standard Marching Cubes by using diagonal intersections to resolve the topology of the trilinear interpolant inside the cube, providing a more accurate representation of the surface than the standard linear edge intersections for ambiguous cases [S2].

### Improved Marching Cubes with Voxel Changes
An improved MC algorithm that increases the side length of voxels to reduce the number of voxels traversed during 3D reconstruction, thereby improving operation efficiency [S3]. By coarsening the voxel representation, the number of processed cells decreases significantly. Benchmarks show efficiency improvements of 61.09% to 93.54% compared to traditional MC, with minimal impact on visual accuracy for large datasets [S3].

### Geomorph LOD Seam Handling
A technique to achieve watertight seams between fine and coarse LOD levels in Marching Cubes by geometrically deforming the fine surface at the boundary to match the coarse contour [S4, unofficial]. It identifies boundary vertices between LOD levels and applies a geometric morph (bending) to deform fine vertices toward the coarse contour, eliminating gaps [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels. Each voxel is processed in constant time (lookup and interpolation).
*   **Memory Complexity:** $O(N)$ for the input scalar field. The output mesh size depends on the surface area. The algorithm can be implemented in a streaming fashion, requiring only two slices of data in memory at any given time [S1].
*   **Performance:** Performance is heavily dependent on the cost of the $P(i,j,k)$ function. If $P$ is a simple affine transformation, it is very fast. If $P$ involves complex non-linear mappings, the interpolation cost dominates. The "Improved Marching Cubes with Voxel Changes" variant demonstrates that reducing the number of voxels (by increasing voxel size) can yield significant speedups (up to 93.5%) [S3].
*   **Strengths:** Simple to implement; works on any structured grid regardless of physical distortion; streaming capability allows processing of massive datasets that do not fit in memory [S1].
*   **Limitations:** Topological ambiguities are not resolved by the basic algorithm; the IJK-to-XYZ mapping approximation may be inaccurate for highly distorted grids [S1].

## Background
The Marching Cubes algorithm was originally developed and patented by GE Medical Systems for use in their CT and MRI equipment [S1]. The patent has since expired, placing the algorithm in the public domain. The method is one of the most common visualization techniques for isosurface extraction [S1]. The specific approach of performing the algorithm in IJK coordinate space and interpolating back to XYZ is a modification to handle structured grids with arbitrary physical mappings, as noted in early documentation of the algorithm's application to general 3D structured grids [S1].
