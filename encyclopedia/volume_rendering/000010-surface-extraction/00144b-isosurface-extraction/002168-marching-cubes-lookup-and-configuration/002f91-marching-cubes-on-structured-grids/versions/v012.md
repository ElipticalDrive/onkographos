# Marching Cubes on Structured Grids

Also called: MC extraction, Marching Cubes in IJK Coordinate Space, Marching Cubes mesh extraction from implicit volume

## Overview
Marching Cubes on Structured Grids extracts a 3D triangular mesh from a scalar field defined on a regular 3D grid (voxel grid) by evaluating the field at grid vertices and applying the standard Marching Cubes topology rules [S1, unofficial][S2]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by assuming the input data is strictly structured (uniform or logically regular), allowing for efficient batched evaluation and coordinate transformation [S1, unofficial][S2]. Unlike [Dual Grid Isosurface Extraction](10271-dual-grid-isosurface-extraction.md) which operates on cell centers, or [Flying Edges](7520-flying-edges.md) which processes edges directly to avoid point merging, this method processes voxel cells individually, generating vertices on edges and triangles within cells [S2].

## How it works
**Inputs:**
1.  **Scalar Field Function ($F$):** A function that returns a scalar value for any 3D coordinate $(x, y, z)$. In neural implicit contexts, this is a neural network outputting a sigma value [S1, unofficial]. In traditional contexts, it is a lookup into a 3D array [S2].
2.  **Grid Bounds:** Two 3D vectors $c_1 = (x_{min}, y_{min}, z_{min})$ and $c_2 = (x_{max}, y_{max}, z_{max})$ defining the spatial extent of the volume [S1, unofficial].
3.  **Resolution:** A 3D integer tuple $R = (R_x, R_y, R_z)$ defining the number of grid points along each axis [S1, unofficial].
4.  **Isovalue ($I$):** The scalar threshold at which the surface is extracted [S1, unofficial].

**Outputs:**
1.  **Vertices:** A list of 3D coordinates $(x, y, z)$ in world space.
2.  **Triangles:** A list of triplets of vertex indices.

**Data Structures:**
*   **Grid Points:** A 3D array of shape $(R_x, R_y, R_z)$ storing the scalar values.
*   **Lookup Tables:** The `edgeTable` and `triangleTable` from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) are required.

**Steps:**

1.  **Grid Generation:** Generate the 3D grid of query points in IJK (index) space. For a resolution $R$, the indices are $i \in [0, R_x-1]$, $j \in [0, R_y-1]$, $k \in [0, R_z-1]$.
    *   *Note:* If using a neural network, the grid points must be converted to world coordinates for evaluation [S1, unofficial].

2.  **Scalar Field Evaluation:** Evaluate the scalar field $F$ at every grid point.
    *   If $F$ depends on view direction (e.g., NeRF), fake view directions must be computed. A common heuristic is to point them toward the origin or camera center [S1, unofficial].
    *   To manage memory, split the grid points into batches of size $B$ (e.g., 100,000) [S1, unofficial].
    *   Compute $V_{ijk} = F(x_i, y_j, z_k)$ for all points.

3.  **Reshape:** Reshape the flat list of scalar values into a 3D array of shape $(R_x, R_y, R_z)$ [S1, unofficial].

4.  **Marching Cubes Extraction:** Apply the standard Marching Cubes algorithm to the 3D scalar array.
    *   Iterate over each voxel $(i, j, k)$ where $i \in [0, R_x-2]$, $j \in [0, R_y-2]$, $k \in [0, R_z-2]$.
    *   Retrieve the 8 corner values $V_0 \dots V_7$ from the grid.
    *   Compute the case index $C$ based on the sign of $V_m - I$ [S2].
    *   Use `edgeTable` and `triangleTable` to determine intersections and triangle connectivity [S2].
    *   Interpolate intersection points on the cube edges using linear interpolation:
        $$ P = V_a + \frac{I - V_a}{V_b - V_a} (V_b - V_a) $$
        where $V_a$ and $V_b$ are the scalar values at the two endpoints of the edge [S2].
    *   *Coordinate Note:* The interpolation is typically performed in IJK space (grid indices), and the resulting vertices are mapped to XYZ space afterward [S2]. While not strictly mathematically correct for non-uniform grids, it is negligible for uniform grids [S2].

5.  **Coordinate Transformation:** Convert the extracted vertices from IJK index space to World XYZ space.
    *   For a vertex with index coordinates $(u, v, w)$:
        $$ x = x_{min} + u \cdot \frac{x_{max} - x_{min}}{R_x - 1} $$
        $$ y = y_{min} + v \cdot \frac{y_{max} - y_{min}}{R_y - 1} $$
        $$ z = z_{min} + w \cdot \frac{z_{max} - z_{min}}{R_z - 1} $$
    *   *Implementation Detail:* Some implementations scale by $1/R$ instead of $1/(R-1)$ depending on whether the bounds represent cell centers or corners [S1, unofficial]. The source code in [S1, unofficial] uses:
        ```python
        vertices *= (c2 - c1) / np.array(reso)
        vertices += c1
        ```
        This implies the grid spans $[c_1, c_2]$ with $R$ steps, effectively treating the grid as covering the range with step size $(c_2-c_1)/R$. This is a specific implementation choice that may shift vertices slightly compared to the standard $R-1$ denominator [S1, unofficial].

6.  **Return:** Output the transformed vertices and the triangle index list.

**Pseudocode:**

```python
import numpy as np
import mcubes # Assuming a standard mcubes library implementation

def marching_cubes_structured_grid(field_func, c1, c2, reso, isosurface, eval_batch_size=100000, use_viewdirs=False):
    """
    Extracts isosurface from a structured grid.
    
    Args:
        field_func: Callable that takes (N, 3) points and returns (N,) scalars.
        c1: List[int], lower bounds (x_min, y_min, z_min).
        c2: List[int], upper bounds (x_max, y_max, z_max).
        reso: List[int], resolution (Rx, Ry, Rz).
        isosurface: Float, threshold value.
        eval_batch_size: Int, batch size for field evaluation.
        use_viewdirs: Bool, if True, handles view-dependent fields.
        
    Returns:
        vertices: (V, 3) array in world space.
        triangles: (T, 3) array of vertex indices.
    """
    Rx, Ry, Rz = reso
    
    # 1. Generate Grid in IJK Space
    # Create meshgrid for indices
    ix = np.arange(Rx)
    iy = np.arange(Ry)
    iz = np.arange(Rz)
    IJ, JK, KL = np.meshgrid(ix, iy, iz, indexing='ij')
    
    # Flatten to list of points in IJK space
    grid_points_ijk = np.stack([IJ.ravel(), JK.ravel(), KL.ravel()], axis=-1)
    
    # 2. Convert to World Space for Evaluation
    # Map IJK to XYZ
    # Using the scaling factor from [S1, unofficial]: scale = (c2 - c1) / reso
    scale = np.array(c2) - np.array(c1)
    scale = scale / np.array(reso)
    
    grid_points_xyz = grid_points_ijk * scale + np.array(c1)
    
    # 3. Handle View Directions if necessary
    viewdirs = None
    if use_viewdirs:
        # Compute fake viewdirs pointing to origin [S1, unofficial]
        # Normalize the vector from point to origin
        norms = np.linalg.norm(grid_points_xyz, axis=1, keepdims=True)
        # Avoid division by zero
        norms = np.where(norms == 0, 1, norms)
        viewdirs = -grid_points_xyz / norms
        # Split viewdirs similarly
        viewdirs_list = np.split(viewdirs, np.array_split_indices(eval_batch_size, len(viewdirs)))
    else:
        viewdirs_list = [None] * len(np.array_split(grid_points_xyz, np.array_split_indices(eval_batch_size, len(grid_points_xyz))))

    # 4. Evaluate Field in Batches
    all_sigmas = []
    points_list = np.array_split(grid_points_xyz, np.array_split_indices(eval_batch_size, len(grid_points_xyz)))
    
    for points, vd in zip(points_list, viewdirs_list):
        # Call field function
        sigmas = field_func(points, viewdirs=vd)
        all_sigmas.append(sigmas)
        
    sigmas = np.concatenate(all_sigmas)
    
    # 5. Reshape to 3D Grid
    # Note: mcubes expects (Z, Y, X) or (X, Y, Z) depending on implementation.
    # Standard numpy meshgrid with 'ij' indexing produces (X, Y, Z) layout in memory if raveled correctly.
    # However, mcubes.marching_cubes typically expects (Z, Y, X) order for the first dimension to be Z.
    # We must reshape carefully.
    sigmas_3d = sigmas.reshape((Rz, Ry, Rx))
    
    # 6. Run Marching Cubes
    # mcubes.marching_cubes returns (vertices, triangles)
    # Vertices are in grid index space (0..R-1)
    vertices_ijk, triangles = mcubes.marching_cubes(sigmas_3d, isosurface)
    
    # 7. Transform Vertices to World Space
    # Apply the same transformation used for evaluation
    vertices_xyz = vertices_ijk * scale + np.array(c1)
    
    return vertices_xyz, triangles

def array_split_indices(batch_size, total_size):
    """Helper to mimic torch.split or np.array_split indices logic"""
    num_splits = (total_size + batch_size - 1) // batch_size
    return np.linspace(0, total_size, num_splits + 1, dtype=int)[1:]
```

**Edge Cases and Pitfalls:**
*   **View-Dependent Fields:** If the scalar field depends on view direction (e.g., NeRF), the isosurface is not well-defined as a static geometry. Using fake view directions (e.g., pointing to the origin) produces incorrect geometry [S1, unofficial].
*   **Coordinate Mapping:** The transformation from IJK to XYZ can be ambiguous. Using $R$ as the divisor (as in [S1, unofficial]) vs $R-1$ (standard linear interpolation between endpoints) shifts the mesh. Consistency between evaluation and reconstruction is critical [S1, unofficial][S2].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 suffer from topological ambiguity. The standard LUT resolves these arbitrarily, potentially causing cracks if adjacent voxels resolve differently [2518-marching-cubes-lookup-and-configuration.md].
*   **Memory:** Evaluating large grids (e.g., $128^3$) requires significant memory for the scalar field array and intermediate batches [S1, unofficial].

## Subtopics

### [Uniform Marching Cubes with Snapping](7468-uniform-marching-cubes-with-snapping.md)
Uniform Marching Cubes with Snapping is a variant that computes cell topology masks from coarse grid vertex signs and optionally snaps iso-surface vertices to edges by minimizing distance to grid vertices. It builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by introducing a snapping mechanism that reduces geometric error, distinguishing it from standard UMC and other siblings like [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md) which prioritize bitwise operations over positional accuracy.

### [Smart Conversion](7489-smart-conversion.md)
Smart Conversion is an advanced, gradient-based voxel-to-mesh conversion algorithm that prioritizes geometric accuracy by correcting errors arising from noise, multiple materials, or inaccurate iso-values. Unlike standard isosurface extraction methods such as [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) which rely on fixed threshold crossings, Smart Conversion iteratively "pulls" the mesh vertices to align with the true boundary of the scan by locating points of steepest gradient along local surface normals. This makes it particularly suitable for medical or high-precision industrial contexts where the initial voxel data may contain flaws or where the iso-value does not perfectly represent the physical boundary.

### [Flying Edges](7520-flying-edges.md)
Flying Edges is a parallel, threaded algorithm for volumetric isocontouring of continuous scalar fields that addresses the performance limitations of Marching Cubes by processing volume edges rather than voxel cells. It eliminates point merging bottlenecks by using an edge-based iterator to generate output points and triangle cells, avoiding the need for hashing duplicate points.

### [Undeformed Space Ray Start via Deformed Hull Intersection](10141-undeformed-space-ray-start-via-deformed-hull-intersection.md)
This method finds the ray start point $\hat{x}_0 = D^{-1}(p)$ in undeformed space without computing the inverse deformation map $D^{-1}$ directly. It solves the problem where $D$ may not be invertible or well-defined at the camera position by intersecting the deformed view ray with a deformed explicit hull mesh that contains the surface.

### [Dividing Cubes](10391-dividing-cubes.md)
Dividing Cubes is an isosurface extraction method that replaces the triangular mesh primitives of Marching Cubes with 3D points. It solves the problem of excessive triangle counts and the subsequent scan-conversion overhead in Marching Cubes by adaptively subdividing cells intersected by the surface until each subcell projects onto a single pixel. Unlike its siblings, it generates a point cloud rather than a fixed mesh, allowing for gradient-shaded rendering without explicit triangle rasterization.

### [Analytic Marching](12525-analytic-marching.md)
Analytic Marching (AM) is a meshing algorithm that extracts the exact zero-level isosurface of an implicit function represented by a ReLU-based Multi-Layer Perceptron (MLP) as a polygon mesh, without relying on discrete 3D grid sampling. Unlike [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md), whose accuracy depends on discretization resolution, AM exploits the piecewise linear nature of ReLU networks to identify linear regions intersected by the surface and solve for vertices analytically, making its precision independent of grid resolution.

### [GPU-Accelerated Metaball Isosurface Generation](12526-gpu-accelerated-metaball-isosurface-generation.md)
This method generates an isosurface from a combined field of metaballs using a two-stage GPU pipeline, utilizing vertex shaders for field evaluation and geometry shaders for mesh generation. It is distinguished from standard CPU-based or single-pass GPU implementations by its explicit separation of field computation and mesh topology generation, coupled with Transform-Feedback caching to avoid recomputing geometry when the camera moves but the metaball configuration remains static. It builds on [Marching Cubes on Structured Grids](6051-marching-cubes-on-structured-grids.md) by offloading the structured grid vertex evaluation and cube processing to the GPU.

### Matveyev's Algorithm
Matveyev's Algorithm is an algorithm based on a triangulation table that correctly represents trilinear interpolant behavior using intersections on cube diagonals [S3]. Proposed by Matveyev in 1999, it addresses the ambiguity of the trilinear interpolant inside the cube by using diagonal intersections to determine the correct topology [S3].

### Geomorph LOD Seam Handling
Geomorph LOD Seam Handling is a technique to achieve watertight seams between fine and coarse LOD levels in Marching Cubes by geometrically deforming the fine surface at the boundary to match the coarse contour [S4, unofficial]. It identifies boundary vertices between fine and coarse LOD levels and applies a geometric morph (bending) to fine surface vertices at the boundary, deforming them toward the coarse contour to eliminate gaps [S4, unofficial].

### Cell Subdivision Isosurface Extraction
Cell Subdivision Isosurface Extraction is a method that retains the identity of cells (vertex/node centered data) and eliminates non-linear hanging nodes by subdividing boundary cells into pyramids, allowing standard isosurface techniques to be applied [S5, unofficial]. It subdivides lower-resolution cell faces to match higher-resolution faces, obtaining values at newly created hanging nodes by linear interpolation, and then subdivides 3D cells into pyramids with a common apex point [S5, unofficial]. Unlike the dual grid approach, this method retains the original cell identity and uses subdivision/pyramids instead of stitch cells [S5, unofficial].

### TexF with Implicit Geometry (SDF)
TexF with Implicit Geometry (SDF) is an extension where TexF shares a canonical grid with an implicit Signed Distance Field (SDF). The surface is extracted via Marching Cubes, and TexF attributes are transferred to vertices for standard vertex-color rendering, avoiding per-pixel TexF queries [S6, unofficial]. The SDF and TexF share the same grid; after extracting a mesh with Marching Cubes, TexF attributes are transferred to its vertices using k-nearest-neighbor interpolation [S6, unofficial].

### 3-Edge Cube Sampling with Corner Extension
This optimization computes intersections for only the 3 edges in the bottom-left corner of each cube instead of all 12, adding an extra row in the top-right corner of the processing zone to ensure all necessary grid values are accessible [S7, unofficial]. The indexing logic requires a special upgrade/mapping to correctly access grid values, making it complicated to implement correctly [S7, unofficial].

### Octree-Based Isolevel Culling
This method builds an octree structure over the volume to assess the ISO level distribution, allowing the algorithm to skip processing areas far from the target isolevel [S7, unofficial]. Propagation-based culling methods are noted as unreliable and inefficient compared to direct octree assessment [S7, unofficial].

### Coarse Sampling Dead-Space Elimination
This technique performs an initial pass sampling the volume at a coarser spatial rate to identify and eliminate regions where field strength is well below the isolevel [S7, unofficial]. However, coarse sampling provides virtually no performance gain for non-trivial fields, as safe sampling borders still capture most of the grid [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once. The constant factor depends on the cost of evaluating the scalar field $F$ [S1, unofficial][S2].
*   **Memory Complexity:** $O(N)$ to store the scalar field grid and the output mesh. Batched evaluation reduces peak memory usage for the field evaluation phase [S1, unofficial].
*   **Performance:** Performance is heavily dependent on the cost of $F$. For neural networks, batch size and GPU utilization are critical [S1, unofficial]. For simple lookup tables, CPU cache efficiency dominates [S2].
*   **Strengths:** Simple to implement; well-understood; parallelizable by voxel [S2].
*   **Limitations:** Resolution-dependent accuracy; artifacts from view-dependent fields; ambiguity cases [S1, unofficial][S2].
*   **When to Use:** When the input data is naturally structured (voxels, grids) and the scalar field is view-independent [S1, unofficial][S2].
*   **When Not to Use:** When view-dependent effects are critical (use Analytic Marching or ray-marching); when adaptive resolution is needed (use [Flying Edges](7520-flying-edges.md) or [Dividing Cubes](10391-dividing-cubes.md)); when exact trilinear topology is required (use [Matveyev's Algorithm](10391-dividing-cubes.md) or ambiguity-resolving variants) [S3].

## Background
The Marching Cubes algorithm was originally developed and patented by GE Medical Systems for use in their CT and MRI equipment. The patent has since expired, placing the algorithm in the public domain [S2]. It is one of the most common visualization methods for isosurface extraction [S2]. The specific implementation on structured grids with IJK-to-XYZ interpolation is a standard adaptation for processing 3D arrays [S2]. Variants like Matveyev's Algorithm (1999) were proposed to address topological ambiguities in the trilinear interpolant [S3].
