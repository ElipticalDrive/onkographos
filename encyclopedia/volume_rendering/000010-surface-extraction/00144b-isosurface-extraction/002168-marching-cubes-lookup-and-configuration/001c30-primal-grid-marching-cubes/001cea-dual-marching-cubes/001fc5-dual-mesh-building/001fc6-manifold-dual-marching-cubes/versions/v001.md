# Manifold Dual Marching Cubes

Also called: Dual Marching Cubes (Comparison Baseline), DualMC, DualMC problematic configurations, Manifold DualMC table generation

## Overview
Manifold Dual Marching Cubes (Manifold DualMC) is a surface extraction algorithm that generates a topologically correct, manifold mesh from a voxel grid by resolving the ambiguous configurations (C16 and C19) inherent in standard Dual Marching Cubes [S2, S4]. While standard Dual Marching Cubes places vertices at dual points (face centers) to ensure a manifold surface, it fails to handle specific cell configurations where the topology of the isosurface crossing a face is ambiguous, potentially leading to non-manifold vertices or edges [S4]. Manifold DualMC solves this by precomputing a lookup table that maps these problematic configurations to their ambiguous face direction, allowing the algorithm to check neighboring cells and invert the cell code when necessary to ensure consistent manifold connectivity [S2, S4]. It differs from standard Dual Marching Cubes by explicitly handling these ambiguous cases to guarantee a watertight mesh [S4].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid of scalar values (e.g., signed distance field or density), an isosurface threshold `iso`, and a bounding box defined by `startX, startY, startZ` and `endX, endY, endZ` [S3, S4].
*   **Output:** A manifold triangle mesh consisting of vertices, normals, and triangle indices [S3, S4].

**Data Structures:**
1.  **Corner Bitmasks:** Eight constants representing the 8 corners of a cube cell:
    *   $C_0=1, C_1=2, C_2=4, C_3=8, C_4=16, C_5=32, C_6=64, C_7=128$ [S2].
    *   The cell configuration (cell code) is the sum of active corner bits where the vertex value $\ge iso$ [S2, S4].
2.  **Edge Codes:** Twelve constants representing the 12 edges of a cube, defined as powers of two:
    *   $EDGE_0=1, EDGE_1=2, \dots, EDGE_{11}=2048$ [S2, S4].
3.  **Problematic Configs Table:** A precomputed array `problematicConfigs[256]` of type `uint8_t` (or packed into `uint32_t` arrays for memory efficiency) [S2, S4].
    *   Indexed by the 8-bit cell configuration (0-255).
    *   Stores the direction of the ambiguous face as a `uint32_t` axis value (0-5, mapping to NX, PX, NY, PY, NZ, PZ) or 255 if the configuration is non-problematic [S2].
    *   The table is generated by rotating the two representative problematic configurations (C16 and C19) through all 6 face directions and 4 rotations per axis [S2].
    *   C16 corners: $0, 1, 2, 6, 7$ active. C19 corners: $0, 1, 2, 4, 6, 7$ active [S2].
4.  **Dual Points List:** A lookup table mapping each of the 256 cell configurations and one of 4 possible dual points to a dual point code (index) [S4].
    *   Stored as `DualPointsList[512]` `uint`s, where each `uint` packs two 16-bit shorts [S4].
5.  **Volume Data Buffer:** Stores volume data packed as two 16-bit shorts per 32-bit `uint`, indexed by 6-bit Morton codes [S4].

**Algorithm Steps:**

1.  **Precomputation (Table Generation):**
    *   Initialize `problematicConfigsMap` [S2].
    *   Define representative C16 and C19 configurations with the ambiguous face on the positive X direction [S2].
    *   For each of the 6 face directions (PX, PY, NX, NY, NZ, PZ):
        *   Rotate the configuration to align the ambiguous face with the current direction using axis rotation functions [S2].
        *   Apply 4 rotations around that axis using `registerConfigAxisRotations`, storing `config -> axis` in the map [S2].
    *   Write the map to `problematicConfigs[256]`, filling non-problematic entries with 255 [S2].

2.  **Geometry Counting (Optional First Pass):**
    *   Iterate through the voxel grid in reverse order (end to start) [S3].
    *   For each voxel, compute the cell code [S4].
    *   Use lookup tables `DM_VERT_COUNT` and `DM_QUAD_COUNT` indexed by the cell code to accumulate total vertex and quad counts [S3].
    *   Adjust for grid traversal index wrapping using `X_WIN_SIZE`, `Y_WIN_SIZE`, and stride constants [S3].

3.  **Mesh Generation (Main Loop):**
    *   Iterate over $x, y, z$ within the bounding box [S4].
    *   **Boundary Check:** If any coordinate $\ge$ `REDUCED` (e.g., 34 for a 36x36x36 grid), skip to avoid out-of-bounds neighbor access [S4].
    *   **Cell Code Calculation:**
        *   Sample the 8 vertices of the cell using Morton encoding [S4].
        *   Bit $i$ (0-7) is set if $Value_i \ge iso$ [S4].
    *   **Ambiguous Case Resolution:**
        *   Retrieve `direction = problematicConfigs[cellCode]` [S4].
        *   If `direction != 255`:
            *   Decode `component = direction >> 1` (0=X, 1=Y, 2=Z) and `delta = (direction & 1) ? 1 : -1` [S4].
            *   Calculate neighbor coordinates: `neighbourCoords = cellPos + delta * axis_vector` [S4].
            *   Check if neighbor is within valid bounds [S4].
            *   If valid, get `neighbourCellCode` and check `problematicConfigs[neighbourCellCode]` [S4].
            *   If the neighbor is also problematic, invert the current cell code: `cellCode ^= 0xFF` [S4].
    *   **Edge Intersection and Quad Generation:**
        *   Iterate over the 3 primary edges of the cell (X, Y, Z) [S4].
        *   For each edge, check if it intersects the isosurface:
            *   **X-edge** (between $xyz$ and $xyz+(1,0,0)$): Intersected if $(Value_{xyz} < iso \land Value_{xyz+(1,0,0)} \ge iso)$ or vice versa [S4]. Requires $z>0$ and $y>0$ [S4].
            *   **Y-edge** (between $xyz$ and $xyz+(0,1,0)$): Intersected similarly. Requires $z>0$ and $x>0$ [S4].
            *   **Z-edge** (between $xyz$ and $xyz+(0,0,1)$): Intersected similarly. Requires $x>0$ and $y>0$ [S4].
        *   If intersected:
            *   Compute 4 dual points for the quad surrounding the edge [S4].
                *   Example for X-edge: `vert0` at $xyz$ (EDGE0), `vert1` at $xyzZ1$ (EDGE2), `vert2` at $xyzY1Z1$ (EDGE6), `vert3` at $xyzY1$ (EDGE4) [S4].
            *   Calculate dual point positions:
                *   If cached, return cached value [S4].
                *   Otherwise, compute as the mean of interpolated intersection coordinates on the intersected edges of the face [S4].
                *   Linear interpolation for edge intersection: $x = (iso - V_{start}) / (V_{end} - V_{start})$ [S4].
            *   Reserve triangle indices [S4].
            *   Output 2 triangles.
                *   **Entering** (negative to positive gradient): $(v_0, v_1, v_2)$ and $(v_2, v_3, v_0)$ [S4].
                *   **Exiting** (positive to negative gradient): $(v_2, v_1, v_0)$ and $(v_0, v_3, v_2)$ [S4].
            *   Calculate face normals using cross product of edge vectors [S4].

**Pseudocode:**

def manifold_dual_marching_cubes(volume_data, iso, start, end):
    # Precomputed tables assumed available
    # problematic_configs: array[256] uint8
    # dual_points_list: array[512] uint32
    
    triangles = []
    vertices = []
    
    # Bounding box constants
    REDUCED_X, REDUCED_Y, REDUCED_Z = 34, 34, 34
    
    for z in range(start.z, end.z + 1):
        for y in range(start.y, end.y + 1):
            for x in range(start.x, end.x + 1):
                # Boundary check
                if x >= REDUCED_X or y >= REDUCED_Y or z >= REDUCED_Z:
                    continue
                
                cell_pos = (x, y, z)
                
                # Get cell code
                cell_code = get_cell_code(volume_data, cell_pos, iso)
                
                # Resolve ambiguous cases
                direction = problematic_configs[cell_code]
                if direction != 255:
                    component = direction >> 1
                    delta = 1 if (direction & 1) else -1
                    
                    neighbor_pos = list(cell_pos)
                    if component == 0: # X
                        neighbor_pos[0] += delta
                        if not (0 <= neighbor_pos[0] < REDUCED_X - 1):
                            direction = 255 # Out of bounds, treat as non-problematic
                    elif component == 1: # Y
                        neighbor_pos[1] += delta
                        if not (0 <= neighbor_pos[1] < REDUCED_Y - 1):
                            direction = 255
                    else: # Z
                        neighbor_pos[2] += delta
                        if not (0 <= neighbor_pos[2] < REDUCED_Z - 1):
                            direction = 255
                    
                    if direction != 255:
                        neighbor_code = get_cell_code(volume_data, tuple(neighbor_pos), iso)
                        if problematic_configs[neighbor_code] != 255:
                            cell_code ^= 0xFF # Invert code
                
                # Process edges
                # X-edge
                if z > 0 and y > 0:
                    v0_val = get_value(volume_data, x, y, z)
                    v1_val = get_value(volume_data, x + 1, y, z)
                    if (v0_val < iso and v1_val >= iso) or (v0_val >= iso and v1_val < iso):
                        generate_quad(triangles, vertices, cell_pos, EDGE0, EDGE2, EDGE6, EDGE4, volume_data, iso)
                
                # Y-edge
                if z > 0 and x > 0:
                    v0_val = get_value(volume_data, x, y, z)
                    v1_val = get_value(volume_data, x, y + 1, z)
                    if (v0_val < iso and v1_val >= iso) or (v0_val >= iso and v1_val < iso):
                        generate_quad(triangles, vertices, cell_pos, EDGE8, EDGE11, EDGE10, EDGE9, volume_data, iso)
                
                # Z-edge
                if x > 0 and y > 0:
                    v0_val = get_value(volume_data, x, y, z)
                    v1_val = get_value(volume_data, x, y, z + 1)
                    if (v0_val < iso and v1_val >= iso) or (v0_val >= iso and v1_val < iso):
                        generate_quad(triangles, vertices, cell_pos, EDGE3, EDGE1, EDGE5, EDGE7, volume_data, iso)
                        
    return triangles, vertices

## Subtopics

### [Hermite Dual Marching Cubes](2197-hermite-dual-marching-cubes.md)
A contouring method that combines the topology guarantees of Dual Marching Cubes (which produces a manifold surface) with the feature-preserving capability of Dual Contouring (which uses Hermite data to place vertices accurately) [2197-hermite-dual-marching-cubes.md]. It solves the problem of non-manifold vertices/edges in standard Dual Contouring on uniform grids while preserving sharp features. Choose this when feature preservation is critical and the input provides gradient/Hermite data.

### [Dual Marching Cubes with Adaptive Octree and QEF Feature Isolation](2291-dual-marching-cubes-with-adaptive-octree-and-qef-feature-iso.md)
A surface extraction method that uses an adaptive octree to subdivide space based on a QEF (Quadratic Error Function) threshold, and extracts the isosurface using a dual marching cubes algorithm on the leaf nodes [2291-dual-marching-cubes-with-adaptive-octree-and-qef-feature-iso.md]. Choose this for large datasets with varying detail levels where adaptive resolution is needed.

### Dual Marching Cubes Problematic Config Packing
A variant focused on the memory layout of the ambiguous configuration table. It packs four consecutive 8-bit direction codes from the `problematicConfigs` array into a single 32-bit `uint` entry in the `ProblematicConfigs` array (size 64 uints for 256 bytes) using bitwise shifts and OR operations to reduce memory footprint [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(V)$ where $V$ is the number of voxels in the bounding box, as it performs a single pass with constant-time bitmask updates and table lookups [S3].
*   **Memory Complexity:** Depends on the volume size and mesh output. The `ProblematicConfigs` table is small (256 bytes or 64 uints) [S4]. The `DualPointsList` is 512 uints [S4]. The output mesh size scales with the surface area.
*   **Measured Performance:** Tested on a 36x36x36 grid (derived from 64^3 volume with boundary reduction) [S4]. Theoretical worst-case triangle buffer size is $34^3 \times 18 = 707,472$ triangles [S4].
*   **Strengths:** Guarantees a manifold mesh by resolving C16/C19 ambiguities [S4]. Efficient table-based lookup for ambiguous cases [S2].
*   **Limitations:** Requires precomputation of the problematic config table [S2]. Boundary handling requires careful neighbor checks to avoid out-of-bounds access [S4]. In flat regions with coarse adaptive octrees, dual partitioning may fail to generate interior samples, leading to topological holes [S1].
*   **When to use:** When a watertight, manifold mesh is required from a uniform voxel grid and standard Dual Marching Cubes produces non-manifold artifacts.
*   **When not to use:** When feature preservation is more important than manifold topology (use Hermite DualMC) or when the grid is highly adaptive and coarse in flat regions (use Primal methods) [S1].

## Background
Manifold Dual Marching Cubes was developed to address the topological inconsistencies in Dual Marching Cubes, specifically the ambiguous configurations C16 and C19 identified in Nielsen's work [S2]. The method relies on precomputing a lookup table that maps these problematic configurations to their ambiguous face direction, allowing for neighbor-based resolution [S2]. It is used in GPU-based implementations for real-time surface extraction [S4]. The underlying dual marching cubes approach was introduced by Sweldens and Schröder [SW04] (cited in S1), and the manifold resolution technique is detailed in works by Wodniok [S2] and others [S4].
