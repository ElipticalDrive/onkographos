# Dual Marching Cubes

Also called: Dual Grid Marching Cubes, MC-Dual, MC-Dual surface, dual to marching cubes

## Overview
Dual Marching Cubes (MC-Dual) is an isosurface extraction method that generates a mesh of quad patches dual to the triangular mesh produced by the standard Marching Cubes algorithm [S3, unofficial]. It operates on a dual grid where each 2x2x2 cube in the dual grid spans a 3x3x3 region in the primal grid, computing vertex positions and distances at dual grid points to feed into a cube callback for mesh extraction [S1, unofficial]. The method eliminates the poorly shaped triangles common in standard Marching Cubes isosurfaces while maintaining the same separating properties [S3, unofficial]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by providing a topological dual to the primal grid traversal.

## How it works
**Inputs and Outputs:**
*   **Input:** A three-dimensional array of values $F_{ijk}$ representing samples of a function over a rectilinear grid with lattice points $(x_i, y_j, z_k)$ [S3, unofficial]. An isosurface threshold level (default `0.0f`) [S2, unofficial]. Intersection data structure `its` containing edge crossings and cell indices [S2, unofficial]. A method string specifying the Marching Cubes variant (default `"vega"`, options: `'vega'`, `'lewiner'`, `'nagae'`, `'lorensen'`) [S2, unofficial].
*   **Output:** A tuple containing an `NDArray<float3>` of vertices and an `NDArray<int>` of indices forming the mesh [S2, unofficial].

**Data Structures:**
*   **DualGrid:** Contains:
    *   `size`: `usize` (N).
    *   `primal_grid`: `PrimalGrid<D>` storing the input field values.
    *   `duals`: Array of two layers `[Vec<(Vec3, D)>; 2]`. Each layer has size $(N-1) \times (N-1)$. Each element is a tuple of `Vec3` (position) and `D` (distance/value) [S1, unofficial].
*   **Intersection:** Contains `edges` (crossed edges), `is_out` (boolean flags), and `cell_indices` mapping edges to cells [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:** Create `DualGrid` with size $N$. Initialize `duals` layers with size $(N-1) \times (N-1)$. Each element is initialized to `(Vec3::zero(), D::zero())` [S1, unofficial].
2.  **Intersection Computation:** If an `Intersection` object is not provided, compute intersections from the grid at the given level without normals: `get_intersection(grid, level, false)` [S1, unofficial].
3.  **Dual Vertex Computation:** For each primal cube, compute the dual vertex position and value.
    *   Define `vertex_callback` taking `&[Vec3; 8]` (primal corners) and `&[D; 8]` (primal values) returning `Option<Vec3>`.
    *   Define `cube_callback` taking `&[(usize, usize, usize); 8]` (dual indices), `&[Vec3; 8]` (dual corners), and `&[D; 8]` (dual values).
    *   If `vertex_callback` is `Some`, call it with `primal_corners` and `primal_values`. Otherwise, default to `lerp(primal_corners[0], primal_corners[6], 0.5)` [S1, unofficial].
    *   Calculate the index in the `duals` layer based on `z % 2`. Store `(vertex, lerp(primal_values[0], primal_values[6], 0.5))` at `duals[z % 2][y * size_minus_one + x]` [S1, unofficial].
    *   *Note on Normals:* If intersection data includes normals, patch vertices are placed using the same QEF (Quadratic Error Function) as dual contouring to reproduce sharp features; without normals, the centroid of the patch's crossings is used [S2, unofficial].
4.  **Mesh Generation (Dual Mesh Building):**
    *   Build a dual mesh from per-cell vertices. One quad is created around every crossed edge from the per-cell vertices (aligned with its `cell_indices`), split into triangles and welded into an indexed mesh [S2, unofficial].
    *   Alternatively, for a simple splatting algorithm: Visit each edge of the lattice that has a sign change. Determine which patch the edge lies in for each of the four voxels sharing this edge. Compute the dual vertex value (assumed to be the centroid of the midpoints of the edges associated with this vertex) for each of the four voxels. Render the quad patch connecting these four dual vertices [S3, unofficial].
    *   Cells crossed by several surface sheets get one vertex per sheet, avoiding the connectivity defects of dual contouring [S2, unofficial].
5.  **Callback Invocation:**
    *   If `x > 0 && y > 0 && z > 0`, iterate `i` from 0 to 7. Compute `keys[i]` using `CORNERS` offsets. Retrieve corner and value from `duals` using `(z + CORNERS[i][2]) % 2` as layer index. Call `cube_callback` with `keys`, `corners`, and `values` [S1, unofficial].

        vertices: NDArray<float3>

    N = grid.shape[0]
    size_minus_one = N - 1
    
    # Initialize DualGrid
    duals = [None, None]
    for layer in range(2):
        duals[layer] = [[(Vec3(0,0,0), 0.0) for _ in range(size_minus_one)] for _ in range(size_minus_one)]
    
    # Compute intersections if not provided
    if intersection is None:
        intersection = get_intersection(grid, level, normals=False)
    
    # Helper for default vertex position
    def default_vertex_callback(primal_corners, primal_values):
        # Default to midpoint of diagonal (0 to 6)
        return lerp(primal_corners[0], primal_corners[6], 0.5)
    
    # Step 1: Compute Dual Vertices
    for z in range(N - 1):
        for y in range(N - 1):
            for x in range(N - 1):
                # Get primal corners for the cube at (x, y, z)
                primal_corners = [grid.get_corner(x + dx, y + dy, z + dz) for dx in [0,1] for dy in [0,1] for dz in [0,1]]
                primal_values = [grid.get_value(x + dx, y + dy, z + dz) for dx in [0,1] for dy in [0,1] for dz in [0,1]]

                vertex = default_vertex_callback(primal_corners, primal_values)
                value = lerp(primal_values[0], primal_values[6], 0.5)

                layer_idx = z % 2
                duals[layer_idx][y][x] = (vertex, value)
    
    # Step 2: Build Mesh from Dual Vertices
    vertices = []
    indices = []
    
    # Iterate over crossed edges to form quads
    for edge in intersection.edges:

            vertices.extend(quad_vertices)

**Edge Cases and Pitfalls:**
*   **Boundary Condition:** The cube callback is only invoked if `x > 0`, `y > 0`, and `z > 0` to ensure valid indices when accessing previous dual grid cells [S1, unofficial].
*   **Grid Boundary:** The resulting mesh ends half a cell short of the grid boundary [S2, unofficial].
*   **Complex Topology:** Cells crossed by several surface sheets get one vertex per sheet, avoiding the connectivity defects of dual contouring [S2, unofficial].

## Subtopics

### Dual Mesh Building
Builds a dual mesh from per-cell vertices. One quad is created around every crossed edge from the per-cell vertices (aligned with its `cell_indices`), split into triangles and welded into an indexed mesh [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of voxels and crossed edges. The dual grid initialization is $O(N^2)$ for each layer, and mesh generation is proportional to the number of surface crossings.
*   **Memory Complexity:** Requires storage for the dual grid, which is $2 \times (N-1)^2$ elements, plus the intersection data. This is comparable to the primal grid storage for the field values.
*   **Performance:** The method produces quad patches which can be more efficient for rendering and texturing than triangles, but requires additional logic to handle the dual topology. The use of QEF for sharp features (when normals are available) adds computational cost similar to Dual Contouring [S2, unofficial].
*   **Strengths:** Eliminates poorly shaped triangles common in Marching Cubes [S3, unofficial]. Maintains topological correctness and separating properties. Handles multiple surface sheets per cell better than Dual Contouring [S2, unofficial].
*   **Limitations:** The mesh ends half a cell short of the grid boundary [S2, unofficial]. Requires careful handling of boundary conditions. The dual topology can be complex to manage for certain operations.
*   **When to use:** When quad meshes are preferred for rendering or further processing, and when the input data has sharp features that can be captured with normals.
*   **When not to use:** When strict boundary adherence is required without post-processing, or when the overhead of dual grid management is prohibitive.

## Background
Dual Marching Cubes was introduced by Gregory M. Nielson in 2004 [S3, unofficial]. It is defined as a class of surfaces dual to the isosurface produced by the Marching Cubes algorithm. The method extends the MC surface to a patch version where each vertex is included in exactly four patches, and then associates a dual vertex with each patch. The resulting dual surface consists of quad patches connected in the same manner as the connectivity of the vertices of the patch surface [S3, unofficial]. It is used in visualization and segmentation post-processing to smooth binary volumes [S3, unofficial].
