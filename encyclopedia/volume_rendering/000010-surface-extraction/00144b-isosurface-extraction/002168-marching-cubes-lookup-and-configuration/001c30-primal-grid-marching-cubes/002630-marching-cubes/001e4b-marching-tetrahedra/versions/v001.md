# Marching Tetrahedra

Also called: 5-tetrahedron decomposition, MarchTetrahedron, Marching Tetrahedrons, Tetrahedral Marching, sliced Marching Cubes

## Overview

Marching Tetrahedra is an isosurface extraction algorithm that decomposes each cubic voxel into tetrahedra to resolve the topological ambiguities inherent in [Marching Cubes](774-marching-cubes.md). By processing each tetrahedron independently, it guarantees a unique, unambiguous intersection for every configuration, producing a crack-free mesh without the need for special case handling [S1, S2, S3, S4, S5].

## How it works

### Inputs and Outputs
- **Input**: A 3D scalar field $V(x,y,z)$ defined on a regular grid, an isovalue $I$, and grid dimensions $(N_x, N_y, N_z)$.
- **Output**: A polygonal mesh (list of vertices and triangles) representing the isosurface $V(x,y,z) = I$.

### Data Structures

**Voxel Decomposition**
Each voxel (cube) is decomposed into 6 tetrahedra. The vertices of the cube are indexed 0–7. A common decomposition shares the main diagonal between vertex 0 and vertex 7 [S2, S5, S6]. The 6 tetrahedra are defined by the following vertex indices (0-based):
1. $T_1: (0, 1, 3, 2)$
2. $T_2: (0, 7, 3, 2)$
3. $T_3: (0, 7, 2, 6)$
4. $T_4: (0, 4, 6, 7)$
5. $T_5: (0, 6, 1, 2)$
6. $T_6: (0, 6, 1, 4)$
*Note: Source [S5] lists a slightly different set $\{0,7,3,2\}, \{0,7,2,6\}, \{0,4,6,7\}, \{0,6,1,2\}, \{0,6,1,4\}, \{5,6,1,4\}$. Source [S6] uses a mapping where edges are defined by pairs $(0,1), (1,2), (2,0), (0,3), (1,3), (2,3)$ for a local tetrahedron. The specific decomposition must be consistent across all voxels to ensure shared edges are identified correctly.*

**Edge Intersection Cache**
To prevent gaps (cracks) due to floating-point precision errors, intersection points on shared edges must be identical for adjacent tetrahedra/voxels. A cache maps a unique edge identifier to the computed 3D position.
- **Edge Key**: A unique integer or tuple identifying an edge. It is typically derived from the voxel coordinates and the edge index within the voxel, or simply the sorted pair of global vertex indices if the grid vertices are shared.
- **Cache Structure**: `Map<EdgeKey, Vector3>` or a pre-allocated array if the number of edges is known.

**Lookup Tables**
- **Tetrahedron Configuration**: A 4-bit mask (16 entries) indicating which of the 4 vertices are above the isovalue.
- **Triangle Output**: For each of the 16 configurations, a table specifies which edges are intersected. Each intersected edge yields a vertex. The table outputs 0, 1, or 2 triangles defined by these edge indices.
    - Example from [S6]: `tetrahedronTriangles[16][7]` where each entry contains up to two triangles (3 indices each), terminated by -1.
    - Example from [S1]: `tetTri` array where each row has 6 entries (3 vertices per triangle, 2 triangles max).

### Steps

1. **Precompute Scalar Values**:
   Sample the scalar field at all grid points $(i,j,k)$ for $0 \le i < N_x, 0 \le j < N_y, 0 \le k < N_z$. Store in a 3D array `grid[N_x][N_y][N_z]` [S5].

2. **Initialize Cache and Output**:
   Create an empty vertex cache `edge_cache` and an empty list `triangles` [S1, S5].

3. **Iterate Voxels**:
   For each voxel at grid coordinates $(i,j,k)$:
   
   a. **Read Vertices**:
      Retrieve the 8 scalar values from `grid` at the voxel corners. Map them to local indices 0–7 based on the chosen decomposition [S3, S5].
      
   b. **Decompose into Tetrahedra**:
      For each of the 6 tetrahedra $T_m$ ($m=1..6$):
      
      i. **Get Vertex Values**:
         Retrieve scalar values $v_0, v_1, v_2, v_3$ for the 4 vertices of $T_m$ [S2, S5].
         
      ii. **Compute Configuration Mask**:
         Create a 4-bit integer `mask`. If vertex $k$ is above the isovalue ($v_k > I$), set bit $k$.
         $$ \text{mask} = \sum_{k=0}^{3} \begin{cases} 1 & \text{if } v_k > I \\ 0 & \text{otherwise} \end{cases} \cdot 2^k $$
         *Note: Some implementations use $\ge$ or $<$; consistency is key. Source [S2] uses $>$, Source [S5] uses $<$. We assume $>$ for "inside" or "positive" for this description, but the lookup table must match the sign convention.*
         
      iii. **Lookup Triangles**:
         Use `mask` to index into the triangle lookup table to get a list of edge indices that are intersected. The table returns 0, 1, or 2 triangles. Each triangle is defined by 3 edge indices (0–5) [S1, S6].
         
      iv. **Generate Vertices**:
         For each edge index $e$ in the triangle definition:
         - Identify the two vertices of the tetrahedron connected by edge $e$. Let them be $P_a$ and $P_b$ with scalar values $S_a$ and $S_b$.
         - Compute the global edge key for this edge (based on voxel $(i,j,k)$ and edge $e$).
         - If the key is in `edge_cache`, retrieve the cached vertex position $P_{int}$.
         - Else, compute $P_{int}$ using linear interpolation:
           $$ t = \frac{I - S_a}{S_b - S_a} $$
           $$ P_{int} = P_a + t \cdot (P_b - P_a) $$
           *Guard*: If $|S_b - S_a| < \epsilon$ (e.g., $10^{-6}$), use the midpoint to avoid division by zero [S5]. Clamp $t$ to $[0, 1]$ if necessary to handle precision issues at boundaries [S1].
           Store $P_{int}$ in `edge_cache` and add to the vertex list if not already present (depending on implementation; caching by edge key is sufficient for consistency).
         
      v. **Add Triangles**:
         For each triangle defined by edge indices $(e_0, e_1, e_2)$, retrieve the corresponding intersection points $P_{e_0}, P_{e_1}, P_{e_2}$ from the cache. Add the triangle $(P_{e_0}, P_{e_1}, P_{e_2})$ to `triangles`.
         *Note*: Ensure consistent winding order. The lookup table must provide edges in an order that produces consistent normals across shared faces [S3].

4. **Post-Processing (Optional)**:
   If disconnected shells are required, perform a connectivity traversal on the generated triangles [S2].

### Pseudocode

```python
def marching_tetrahedra(grid, dims, isovalue):
    """
    grid: 3D array of scalar values, shape (Nx, Ny, Nz)
    dims: tuple (Nx, Ny, Nz)
    isovalue: float, the threshold for isosurface extraction
    """
    # Define the 6 tetrahedra per voxel. 
    # Vertices are local indices 0-7 of the cube.
    # Decomposition: T1(0,1,3,2), T2(0,7,3,2), T3(0,7,2,6), T4(0,4,6,7), T5(0,6,1,2), T6(0,6,1,4)
    # Note: This specific decomposition is one valid option. The lookup table must match.
    tetra_vertices = [
        [0, 1, 3, 2],
        [0, 7, 3, 2],
        [0, 7, 2, 6],
        [0, 4, 6, 7],
        [0, 6, 1, 2],
        [0, 6, 1, 4]
    ]
    
    # Define edges for a tetrahedron with vertices 0,1,2,3
    # Edge 0: (0,1), Edge 1: (0,2), Edge 2: (0,3), Edge 3: (1,2), Edge 4: (1,3), Edge 5: (2,3)
    tetra_edges = [
        (0, 1), (0, 2), (0, 3),
        (1, 2), (1, 3), (2, 3)
    ]
    
    # Lookup table: mask -> list of triangles. 
    # Each triangle is a tuple of 3 edge indices (0-5).
    # This table assumes mask bit k is 1 if vertex k > isovalue.
    # Example entries (must be derived or looked up from a source like [S6]):
    # mask 0 (0000): no triangles
    # mask 1 (0001, V0>iso): triangle on edges connected to V0? No, edges NOT connected to V0?
    # Standard MT: If V0 is inside (1), others outside (0), the surface cuts the 3 edges connected to V0.
    # Edges connected to V0 are 0, 1, 2.
    # So mask 1 -> [(0, 1, 2)]
    # This table needs to be fully populated. For brevity, we assume a function get_triangles(mask) exists.
    def get_triangles(mask):
        # Placeholder for the actual 16-entry lookup table
        # See [S6] for specific edge indices.
        # Example:
        if mask == 0: return []
        if mask == 1: return [(0, 1, 2)] # V0 inside
        if mask == 2: return [(0, 3, 4)] # V1 inside (edges 0,3,4 connect to V1? No. V1 is index 1. Edges (0,1)=0, (1,2)=3, (1,3)=4. Yes.)
        if mask == 3: return [(3, 4, 5), (0, 1, 2)] # V0, V1 inside. Two triangles.
        # ... other cases ...
        return []

    edge_cache = {} # Key: (voxel_i, voxel_j, voxel_k, edge_index), Value: Vector3
    triangles = []
    
    Nx, Ny, Nz = dims
    
    for i in range(Nx - 1):
        for j in range(Ny - 1):
            for k in range(Nz - 1):
                # Get 8 corner values
                # Map local cube indices 0-7 to grid coordinates
                # Assuming standard ordering:
                # 0:(i,j,k), 1:(i+1,j,k), 2:(i+1,j+1,k), 3:(i,j+1,k)
                # 4:(i,j,k+1), 5:(i+1,j,k+1), 6:(i+1,j+1,k+1), 7:(i,j+1,k+1)
                # Note: This ordering must match the tetra_vertices definition.
                corners = [
                    grid[i, j, k],
                    grid[i+1, j, k],
                    grid[i+1, j+1, k],
                    grid[i, j+1, k],
                    grid[i, j, k+1],
                    grid[i+1, j, k+1],
                    grid[i+1, j+1, k+1],
                    grid[i, j+1, k+1]
                ]
                
                # Get world coordinates for corners (assuming unit spacing for simplicity)
                # In practice, scale by voxel size and add origin
                corner_coords = [
                    (i, j, k), (i+1, j, k), (i+1, j+1, k), (i, j+1, k),
                    (i, j, k+1), (i+1, j, k+1), (i+1, j+1, k+1), (i, j+1, k+1)
                ]

                for tet_idx in range(6):
                    v_indices = tetra_vertices[tet_idx]
                    v_vals = [corners[v] for v in v_indices]
                    v_coords = [corner_coords[v] for v in v_indices]
                    
                    # Compute mask
                    mask = 0
                    for idx, val in enumerate(v_vals):
                        if val > isovalue:
                            mask |= (1 << idx)
                            
                    # Get triangles for this mask
                    tri_edge_indices = get_triangles(mask)
                    
                    for tri in tri_edge_indices:
                        e0, e1, e2 = tri
                        pts = []
                        for e in [e0, e1, e2]:
                            # Get edge vertices
                            v_a_idx, v_b_idx = tetra_edges[e]
                            va = v_coords[v_a_idx]
                            vb = v_coords[v_b_idx]
                            sa = v_vals[v_a_idx]
                            sb = v_vals[v_b_idx]
                            
                            # Create cache key
                            # Use sorted vertex coordinates to ensure consistency
                            key = tuple(sorted([va, vb]))
                            
                            if key in edge_cache:
                                pt = edge_cache[key]
                            else:
                                # Interpolate
                                denom = sb - sa
                                if abs(denom) < 1e-6:
                                    t = 0.5
                                else:
                                    t = (isovalue - sa) / denom
                                # Clamp t
                                t = max(0.0, min(1.0, t))
                                pt = va + t * (vb - va)
                                edge_cache[key] = pt
                            pts.append(pt)
                        
                        triangles.append(pts)
                        
    return triangles
```

### Parameters
- **isovalue**: The scalar value defining the surface. Default 0.0. Typical values depend on the data (e.g., 100, 140, 150, 200 for medical CT) [S1, S2].
- **eps**: Tolerance for degenerate cases (e.g., $10^{-6}$) [S5].

### Edge Cases and Pitfalls
- **Degenerate Triangles**: If a vertex value equals the isovalue, the interpolation parameter $t$ may be undefined or result in a zero-area triangle. Filter these out by checking if the resulting triangle vertices are distinct [S2].
- **Cracks**: Without caching edge intersections, floating-point errors can cause gaps between adjacent tetrahedra. Always cache and reuse intersection points for shared edges [S5].
- **Winding Order**: Incorrect vertex ordering in the lookup table or tetrahedron decomposition can lead to inverted normals. The decomposition and lookup table must be consistent [S3].
- **Ambiguity**: Unlike Marching Cubes, Marching Tetrahedra has no topological ambiguities. However, the choice of decomposition (which diagonal is shared) can influence the visual appearance (e.g., bumps along diagonals) [S4].

## Operating characteristics

- **Time Complexity**: $O(N)$, where $N$ is the number of voxels. Each voxel is processed independently in constant time (6 tetrahedra, 16 cases).
- **Memory Complexity**: $O(N)$ for the scalar field. The output mesh size is proportional to the surface area. The edge cache requires $O(N)$ space if all edges are stored, or can be optimized by processing slices [S5].
- **Performance**: Generally slower than Marching Cubes due to more triangles generated (up to 19 edge samples per cube vs 12) and the overhead of tetrahedral decomposition [S4, S5].
- **Strengths**: Unambiguous, crack-free, topologically correct. No special cases needed.
- **Limitations**: More triangles than MC. The choice of decomposition can introduce artifacts (bumps) along the diagonals of the cubes [S4].

## Background

Marching Tetrahedra was introduced in 1991 by Doi and Koide as a crack-free, historically patent-free alternative to Marching Cubes [S4]. It resolves the 15 ambiguous cases of Marching Cubes by decomposing the cube into tetrahedra, each of which has a unique intersection topology.
