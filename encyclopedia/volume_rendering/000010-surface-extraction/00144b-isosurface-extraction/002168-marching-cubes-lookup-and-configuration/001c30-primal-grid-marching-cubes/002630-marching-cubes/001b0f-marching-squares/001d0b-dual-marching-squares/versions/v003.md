# Dual Marching Squares

Also called: Schaefer's and Warren's Dual Marching Cubes (2D variant)

## Overview
Dual Marching Squares (DMS) is a 2D surface extraction method that adaptively samples a scalar field using a quadtree, placing a single vertex per leaf node at the dual grid position (the center of the leaf cell) to approximate the isosurface [S1]. Unlike standard [Marching Squares](918-marching-squares.md), which places vertices on cell edges, DMS simplifies topology by using one vertex per region but does not preserve sharp features because dual vertices remain in cell centers rather than being projected onto the function's features [S1].

## How it works
**Inputs and outputs:**
- Input: A 2D scalar field $f(x,y)$, an isovalue threshold $T$, a minimum leaf size $min\_size$, a grid scaling factor $grid\_size$, and a splitting heuristic constant $minSplitDistanceDiagonalFactor$ (default 1000.0) [S1].
- Output: A list of vertices (position, normal, color) and a list of quad indices forming the mesh [S1].

**Data structures:**
1. **QuadtreeNode**:
   - `position`: Vector2, top-left corner of the node's domain in grid coordinates.
   - `size`: int, side length of the square node.
   - `children`: QuadtreeNode[4], ordered as {top-left, top-right, bottom-left, bottom-right}.
   - `dualgrid_pos`: Vector2, offset from `position` to the center (always `0.5 * size * (1,1)`).
   - `isovalue`: float, sampled value at `dualgrid_pos`.
   - `normal`: Vector2, gradient direction at `dualgrid_pos`.
   - `leaf`: bool, true if this node is a leaf.
   - `vertex_index`: int, index in the global vertex list (if leaf).
   - `index`: int, node identifier.
2. **VertexPositionColorNormal**:
   - `Position`: Vector3 (x, y, 0).
   - `Color`: Color (default (210, 220, 210)).
   - `Normal`: Vector3 (nx, ny, 0).
3. **Connectivity Tables** (used during mesh construction):
   - `edges[4][2]`: `{{0, 2}, {1, 3}, {0, 1}, {2, 3}}`. Maps edge index to the two corner indices of the quad [S1].
   - `edge_children[2][2][2]`: `{{{2, 0}, {3, 1}}, {{1, 0}, {3, 2}}}`. Maps parent edge children to child quad edges [S1].
   - `vertex_children[2][2][2]`: `{{{2, 3}, {0, 1}}, {{1, 3}, {0, 2}}}`. Maps parent vertex children to child quad vertices [S1].
   - `middle_points[4]`: `{3, 2, 1, 0}` [S1].
   - `connect_points[4]`: `{0, 2, 3, 1}` [S1].

    s = node.size
    # Sample 5 positions: corners and midpoints
    corner_vals = [
        sample_field(Vector2(p.x, p.y)),
        sample_field(Vector2(p.x + s, p.y)),
        sample_field(Vector2(p.x, p.y + s)),
        sample_field(Vector2(p.x + s, p.y + s))
    ]
    center_val = sample_field(Vector2(p.x + 0.5 * s, p.y + 0.5 * s))
    interpolated = bilinear_interpolate(corner_vals[0], corner_vals[1], corner_vals[2], corner_vals[3], 0.5, 0.5)
    grad = compute_gradient(Vector2(p.x + 0.5 * s, p.y + 0.5 * s))
    grad_mag = math.sqrt(grad.x**2 + grad.y**2)
    error = abs(center_val - interpolated) / max(1.0, grad_mag)
    return error

def try_split(node, min_size, threshold, grid_size, vertices, minSplitDistanceDiagonalFactor=1000.0):
    center_val = sample_field(Vector2(node.position.x + 0.5 * node.size, node.position.y + 0.5 * node.size))
    cond1 = center_val > node.size * math.sqrt(2) * minSplitDistanceDiagonalFactor
    cond2 = node.size <= min_size
    error = get_error(node, threshold)
    cond3 = error < threshold
    if cond1 or cond2 or cond3:
        node.leaf = True
        node.isovalue = center_val
        node.normal = compute_gradient(Vector2(node.position.x + 0.5 * node.size, node.position.y + 0.5 * node.size))
        world_pos = Vector3(node.position.x + node.dualgrid_pos.x, node.position.y + node.dualgrid_pos.y, 0) * grid_size
        normal_3d = Vector3(node.normal.x, node.normal.y, 0)
        color = Color(210, 220, 210)
        vertex = VertexPositionColorNormal(world_pos, color, normal_3d)
        vertices.append(vertex)
        node.vertex_index = len(vertices) - 1
        return
    half_size = node.size // 2
    for i in range(4):
        dx = (i // 2) * half_size
        dy = (i % 2) * half_size
        child_pos = Vector2(node.position.x + dx, node.position.y + dy)
        child = QuadtreeNode(child_pos, half_size, node.index * 4 + i)
        node.children[i] = child
        try_split(child, min_size, threshold, grid_size, vertices, minSplitDistanceDiagonalFactor)

    if node.leaf:
        return
    for child in node.children:
        process_face(child, cells)
    process_edge(node.children[0], node.children[1], 0, cells)

    process_face(root, cells)

def build_quadtree(grid_size, min_size, threshold, vertices, minSplitDistanceDiagonalFactor=1000.0):
    root = QuadtreeNode(Vector2(0, 0), grid_size, 0)
    try_split(root, min_size, threshold, grid_size, vertices, minSplitDistanceDiagonalFactor)
    return root

def extract_mesh(grid_size, min_size, threshold, vertices, minSplitDistanceDiagonalFactor=1000.0):
    root = build_quadtree(grid_size, min_size, threshold, vertices, minSplitDistanceDiagonalFactor)
    cells = []
    construct_tree_grid(root, cells)

**Parameters:**
- `threshold`: The scalar value defining the isosurface [S1].
- `min_size`: The minimum size of a quadtree leaf node. Splitting stops when node size equals this value [S1].
- `minSplitDistanceDiagonalFactor`: A constant used in the splitting heuristic. Default value is 1000.0f. It scales the diagonal size of the node to determine if the center sample is far enough from the threshold to warrant splitting [S1].

**Edge cases and pitfalls:**
- **Error Calculation Flaw**: The `GetError` function calculates error as `|center_value - interpolated| / max(1.0, |gradient|)`. If sampled points have very similar values, the error calculation becomes negligible even if the surface is complex. Fixes suggested include sampling more points (corners, midpoints, in-between), using a maximum container size, or sampling random points. Uniform grid sampling with early break is recommended [S1].
- **Sharp Features**: Because dual vertices are placed in the centers of their cells instead of being moved to the features of the function, this approach does not preserve sharp features [S1].

## Subtopics

### Dual Marching Squares Error Function
The Dual Marching Squares implementation substitutes the standard error-reducing function with a separate, faster alternative function. The standard function calculates error based on the difference between the center sample and the bilinearly interpolated value from the corners, normalized by the gradient magnitude. The alternative function is not detailed in the sources but is noted as being faster [S1].

## Operating characteristics
- **Time Complexity**: Not given in the sources. Depends on the quadtree depth and the number of leaves.
- **Memory Complexity**: Not given in the sources. Depends on the number of vertices and cells generated.
- **Measured Performance**: Not given in the sources.
- **Strengths**: Simplifies topology by using a single vertex per leaf. Adaptive sampling allows for higher resolution in complex areas.
- **Limitations**: Does not preserve sharp features. The error calculation can be flawed for complex surfaces if not augmented with additional sampling.
- **When to use**: When adaptive sampling is needed for 2D scalar fields and sharp feature preservation is not critical.
- **When not to use**: When sharp features must be preserved or when a fixed-grid method like standard Marching Squares is sufficient and simpler to implement.

## Background
Dual Marching Squares is the 2D variant of Dual Marching Cubes, which is based on the work of Schaefer and Warren. It is used in surface extraction from 2D scalar fields, particularly in contexts where adaptive resolution is beneficial [S1].
