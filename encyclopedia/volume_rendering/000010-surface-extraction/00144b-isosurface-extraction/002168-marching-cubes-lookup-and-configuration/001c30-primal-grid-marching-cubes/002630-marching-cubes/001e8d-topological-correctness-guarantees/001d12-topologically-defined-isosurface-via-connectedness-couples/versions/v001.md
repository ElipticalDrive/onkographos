# Topologically Defined Isosurface via Connectedness Couples

Also called: MC with (alpha, lambda) couples, Marching-Cubes with topological constraints

## Overview
This method extracts a topologically correct isosurface from a binary volumetric image by defining the surface geometry through valid foreground-background connectivity couples $(\alpha, \lambda)$. It solves the topological inconsistencies (such as self-intersections or disconnected components) inherent in standard Marching Cubes by ensuring the output is a closed, oriented triangulated manifold without singularities. It differs from [Topologically Correct Marching Cubes](1368-topologically-correct-marching-cubes.md) by relying on a formal combinatorial manifold definition based on connectedness couples rather than heuristic case fixes, and from [Topologically Defined Isosurfaces](1428-topologically-defined-isosurfaces.md) by explicitly utilizing the $(\alpha, \lambda)$ validity constraints to determine local triangulation.

## How it works
**Inputs and Outputs:**
- Input: A binary volumetric image (picture) $I$ of size $n \times n \times n$.
- Output: A closed, oriented triangulated surface $S_\lambda(I)$ embedded in $\mathbb{R}^3$ without self-crossing.

**Data Structures:**
- **Connectedness Couple $(\alpha, \lambda)$:** A pair defining foreground and background connectivity. Valid couples are $(26, 6)$, $(18, 6)$, $(6, 26)$, and $(6, 18)$.
- **Complete Graph $G_\lambda(I)$:** An oriented two-dimensional combinatorial manifold without boundary, formed by the union of local graphs from all 8-cubes (voxels) in $I$.
- **Local Configuration Table:** A precomputed table of size 256 entries for each valid couple, storing the triangulation for each voxel configuration.

**Algorithm Steps:**

1.  **Precomputation:** For a chosen valid connectedness couple $(\alpha, \lambda)$, compute the 256 local configuration tables. This is done by calling `Build-Local_Surface` for each of the 256 possible voxel configurations.
2.  **Surface Extraction:**
    -   Initialize the global surface structure.
    -   Iterate through the volume. For each voxel, determine its configuration (binary state of 8 corners).
    -   Retrieve the precomputed triangulation from the local configuration table corresponding to the configuration and the chosen couple.
    -   Assemble the triangles into the global mesh.
    -   *Optimization:* If using surface tracking to build the complete graph $G_\lambda(I)$, the complexity reduces to $O(s)$ where $s$ is the number of surfels, rather than $O(n^3)$.

**Pseudocode for Local Surface Construction:**

The core logic for generating the local triangulation for a single voxel configuration $C$ is defined by `Build-Local_Surface`.

```python
def Build_Local_Surface(Configuration C, Connectedness alpha):
    """
    Computes the local triangulated manifold S_lambda(C8) for a specific 
    voxel configuration C and foreground connectivity alpha.
    """
    # Initialize edge set E
    E = EmptySet()
    
    # Extract edges from all inner 6-faces of the configuration C
    # Inner 6-faces are the faces shared with neighboring voxels
    for F in Get_Inner_6_Faces(C):
        EF = Extract_Edges(F, connectivity=6)
        E = Union(E, EF)
        
    # Extract loops from the edge set
    L = Extract_Loops(E)
    
    # Define the convex hull H
    # Vertices of E plus the 1-voxels (corners) of C that are part of the configuration
    Vertices_E = Get_Vertices(E)
    Voxels_C = Get_1_Voxels(C)
    H = Convex_Hull(Union(Vertices_E, Voxels_C))
    
    # Subdivide long loops
    # s represents the current set of loops/surfaces being constructed
    s = L
    
    while s contains a loop L of length > 3:
        # Remove one loop of length > 3 from s
        L = Remove_A_Loop_Of_Length_Greater_Than_3(s)
        
        # L is an ordered set of vertices (a1, ..., ak)
        k = Length(L)
        exit = False
        i = 1
        j = i + 2
        
        while not exit:
            # Check if the chord (ai, aj) is inside the convex hull H
            if Is_In_Convex_Hull(ai, aj, H):
                exit = True
            else:
                j = j + 1
                if j == k:
                    i = i + 1
                    j = i + 2
                    # Note: If i reaches the end without finding a chord in H,
                    # the loop structure implies a specific topological constraint.
                    # Based on the source, the loop continues until a chord in H is found.
        
        # Insert the subdivided loop and the chord
        # The loop L is split into (a1...ai, aj...ak) and (ai...aj)
        Insert_Loop((a1, ..., ai, aj, ..., ak), s)
        Insert_Loop((ai, ..., aj), s)
        
    # Handle strict 26-adjacency case
    if Configuration.Has_Strict_26_Adjacency(C) and alpha == 26:
        s = Build_Special_Loops_26_Adj(s)
        
    return s
```

**Definitions:**
-   **Strict 26-adjacency:** A configuration where the foreground voxels touch only at corners/edges in a specific way that violates standard 26-adjacency assumptions for simple subdivision.
-   **Convex Hull $H$:** The smallest convex set containing the vertices of the extracted edges and the active voxel corners.
-   **Loop Subdivision:** The process of splitting a loop of length $>3$ by inserting a chord $(a_i, a_j)$ that lies within the convex hull of the loop's vertices, effectively triangulating the interior.

**Parameters:**
-   **Connectedness Couple:** Must be one of $(26, 6)$, $(18, 6)$, $(6, 26)$, or $(6, 18)$.
-   **$\lambda$ (Background Connectivity):** Fixed at 6 in the primary definition of the local graph construction for $\alpha=18$ or $\alpha=26$ (non-strict).

**Edge Cases and Pitfalls:**
-   **Strict 26-Adjacency:** If the configuration exhibits strict 26-adjacency and $\alpha=26$, the standard loop subdivision is replaced by `Build_Special_Loops_26_Adj`. If $\alpha=18$, the local graph is not modified in this case.
-   **Precision:** The convex hull check must be robust to floating-point errors if coordinates are not integer-aligned.
-   **Boundary Conditions:** The method assumes a binary picture $I$. Handling boundaries requires defining the connectivity of voxels outside the volume (typically assumed to be background).

## Operating characteristics
-   **Time Complexity:** Standard Marching Cubes is $O(n^3)$ where $n^3$ is the volume size. Using surface tracking to build the complete graph $G_\lambda(I)$, the complexity is $O(s)$, where $s$ is the number of surfels (typically $O(n^2)$).
-   **Memory Complexity:** Requires storage for 256 local configuration tables per valid connectedness couple. The size of each table depends on the maximum number of triangles per voxel, which is bounded.
-   **Performance:** Validated on medical image segmentation, specifically CT scans with resolutions such as $256 \times 256 \times 113$.
-   **Strengths:** Guarantees a closed, oriented triangulated surface without singularities or self-crossings. The use of precomputed tables allows for efficient runtime execution similar to standard MC.
-   **Limitations:** Requires binary input. The topological correctness depends on the validity of the connectedness couple. Strict 26-adjacency cases require special handling.

## Background
The method was introduced by [S1] as a topologically and formally proved approach for extracting consistent isosurfaces from volumetric images. It establishes the identity between the underlying graph of the isosurface and the surfel-adjacency graph of the digital surface. The algorithm has been implemented and validated with synthetic data and is used in the segmentation of medical images.
