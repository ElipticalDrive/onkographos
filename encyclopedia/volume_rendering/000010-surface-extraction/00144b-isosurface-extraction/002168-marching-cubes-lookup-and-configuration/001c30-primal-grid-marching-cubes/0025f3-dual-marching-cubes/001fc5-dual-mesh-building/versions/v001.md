# Dual Mesh Building

Also called: Dual Mesh Construction

## Overview
Dual Mesh Building is the core geometric construction phase of the Dual Marching Cubes (DMC) surface extraction method. It solves the problem of converting the topological information of iso-surface intersections within a hexahedral grid into a consistent, manifold, quad-only mesh. Unlike standard Marching Cubes, which outputs a triangle mesh with vertices on grid edges, Dual Mesh Building creates a dual mesh where each vertex corresponds to a face (MC polygon) of the standard algorithm, and each face corresponds to a grid edge [S1, S2]. This approach typically yields meshes with fewer vertices and better-shaped elements than standard MC [S2]. The method is distinguished by its ability to generate watertight, quad-only meshes without relying on large lookup tables for topology, instead using sampling and hash-based vertex sharing [S2].

## How it works
The method constructs the mesh in two parallel stages: computing vertex representatives for each iso-surface branch within cells, and collecting these representatives into quadrilaterals shared by grid edges.

### Inputs and Outputs
*   **Input:** A scalar volume grid $V$ of dimensions $D_x \times D_y \times D_z$, an isovalue $\iota_0$, and a boolean flag `generateManifold` (optional, for Wenger's correction) [S1, S2].
*   **Output:** A list of vertices $P$, a list of quadrilateral indices $Q$, and optionally a halfedge data structure for connectivity [S2].

### Data Structures
1.  **Vertex:** Struct with fields `x`, `y`, `z` of type `float` [S1].
2.  **Quad:** Struct with fields `i0`, `i1`, `i2`, `i3` of type `int32_t` (indices into the vertex list) [S1].
3.  **DualPointKey:** Struct with fields `linearizedCellID` (`int32_t`) and `pointCode` (`int`) [S1].
4.  **Hash Table:** Maps `DualPointKey` to `QuadIndexType` (vertex index) to ensure shared vertices are unique [S1].
5.  **Edge Hash Table:** Maps edge index (key) to an array of four vertex indices (value) for quad construction [S2].
6.  **Lookup Tables (Optional):**
    *   `dualPointsList[256][4]`: Encodes edge vertices for the 256 MC cases [S1].
    *   `problematicConfigs[256]`: Encodes ambiguous face configurations for manifold correction [S1].

### Formulas
The trilinear interpolant $T$ on a unit reference cell is defined as [S2]:
$$
F(u, v, w) = (1 - w)[f_0(1 - u)(1 - v) + f_1u(1 - v) + f_2(1 - u)v + f_3uv] + w[f_4(1 - u)(1 - v) + f_5u(1 - v) + f_6(1 - u)v + f_7uv]
$$
where $(u, v, w) \in [0, 1]^3$ are local coordinates and $f_i$ are scalar values at cell vertices $v_i$ [S2].

To find the position of a vertex representative, two parameters (e.g., $u, v$) are sampled, and the third ($w$) is computed by solving $F(u, v, w) = \iota_0$ [S2]:
$$
w = \frac{\iota_0 - g_1(u, v)}{g_2(u, v) - g_1(u, v)}
$$
where:
$$
g_1(u, v) = f_0(1 - u)(1 - v) + f_1u(1 - v) + f_2(1 - u)v + f_3uv
$$
$$
g_2(u, v) = f_4(1 - u)(1 - v) + f_5u(1 - v) + f_6(1 - u)v + f_7uv
$$
$\iota_0$ is the isovalue [S2].

### Steps

1.  **Initialization:** Create buffers for vertices, quads, and hash tables. Initialize atomic counters for vertex indexing [S2].
2.  **Cell-wise Processing (Kernel 1):** For each cell $(cx, cy, cz)$:
    a.  **Check Intersection:** Compute the 8-bit cell code (in-out mask) relative to $\iota_0$. If no intersection, return [S1, S2].
    b.  **Compute MC Polygons:** Determine the intersected edges. If using lookup tables, use `dualPointsList` to identify edges. Resolve ambiguous cases using the asymptotic decider if necessary [S1, S2].
    c.  **Select Vertex Representatives:** For each branch of the iso-surface intersecting the cell (up to 4):
        i.  Determine the sampling space $(u, v)$, $(u, w)$, or $(v, w)$ where the MC polygon has the largest projection [S2].
        ii. Sample points in the chosen 2D space. Compute the third coordinate using the formula above. Discard samples outside the cell ($<0$ or $>1$) or within the bounding boxes of other branches [S2].
        iii. Use a 7x7 grid of samples; if no valid position is found, retry with 25x25. If still invalid, use the center of gravity of the MC polygon [S2].
        iv. Select the sample closest to the center of gravity of the MC polygon as the vertex representative [S2].
    d.  **Compute Normal:** Estimate the gradient at cell vertices using central differences. Interpolate the gradient trilinearly at the vertex representative position and normalize [S2].
    e.  **Store Vertex Index:** Compute a unique global index for the vertex representative using an atomic counter. Store this index in the hash table keyed by `(linearizedCellID, pointCode)` [S1, S2].
    f.  **Store Edge Indices:** For each intersected edge, store the vertex index in the Edge Hash Table at the correct position to ensure consistent quad orientation (see Quad Construction) [S2].
3.  **Quad Collection (Kernel 2):** For each edge in the grid:
    a.  Retrieve the four vertex indices from the Edge Hash Table [S2].
    b.  If all four indices are valid (not boundary cells), create a quad `{B, A, D, C}` and add to the output list [S2].
    c.  If any entry is invalid (boundary), skip quad generation for that edge [S2].
4.  **Manifold Correction (Optional):** If `generateManifold` is true, apply Wenger's correction using `problematicConfigs` to resolve non-manifold edges caused by ambiguous configurations [S1].
5.  **Halfedge Construction (Optional):** Build a halfedge data structure to store connectivity, handling non-manifold edges (shared by four faces) if tunnels exist [S2].

### Pseudocode

```python
# Data Structures
struct Vertex:
    x: float
    y: float
    z: float

struct Quad:
    i0: int32
    i1: int32
    i2: int32
    i3: int32

struct DualPointKey:
    linearizedCellID: int32
    pointCode: int

# Helper Functions
def getCellCode(cx, cy, cz, iso, data, dims):
    # Returns 8-bit mask of corners relative to iso
    code = 0
    for k in 0..1:
        for j in 0..1:
            for i in 0..1:
                idx = cx + i + (cy + j) * dims[0] + (cz + k) * dims[0] * dims[1]
                if data[idx] >= iso:
                    code |= (1 << (i + 2*j + 4*k))
    return code

def compute_w(u, v, f0, f1, f2, f3, f4, f5, f6, f7, iso):
    g1 = f0*(1-u)*(1-v) + f1*u*(1-v) + f2*(1-u)*v + f3*u*v
    g2 = f4*(1-u)*(1-v) + f5*u*(1-v) + f6*(1-u)*v + f7*u*v
    if g2 == g1: return 0.5 # Fallback
    return (iso - g1) / (g2 - g1)

def getSharedVertexIndex(cellID, pointCode, iso, data, dims, hash_table, vertex_counter):
    if pointCode in hash_table:
        return hash_table[pointCode]
    
    # Compute representative position (simplified)
    # In practice, this involves sampling and selecting the best point
    pos = compute_vertex_representative(cellID, pointCode, iso, data, dims)
    
    # Compute normal
    grad = compute_gradient(pos, data, dims)
    normal = normalize(grad)
    
    # Store vertex
    idx = atomic_add(vertex_counter, 1)
    vertices[idx] = Vertex(pos.x, pos.y, pos.z)
    normals[idx] = normal
    
    hash_table[pointCode] = idx
    return idx

def build_dual_mesh(data, dims, iso, generateManifold=False):
    vertices = []
    quads = []
    hash_table = {} # DualPointKey -> VertexIndex
    edge_hash = {}  # EdgeIndex -> [v0, v1, v2, v3]
    vertex_counter = 0
    
    # Kernel 1: Cell-wise processing
    for cz in 0..dims[2]-1:
        for cy in 0..dims[1]-1:
            for cx in 0..dims[0]-1:
                cell_code = getCellCode(cx, cy, cz, iso, data, dims)
                if cell_code == 0 or cell_code == 255:
                    continue
                
                cellID = cx + dims[0] * (cy + dims[1] * cz)
                
                # Determine intersected edges and MC polygons
                # This step identifies up to 4 branches
                branches = compute_mc_polygons(cell_code, cx, cy, cz, iso, data, dims)
                
                for branch in branches:
                    # Compute vertex representative for this branch
                    # Returns a unique pointCode for this branch in this cell
                    pointCode = get_branch_point_code(branch, cellID)
                    
                    v_idx = getSharedVertexIndex(cellID, pointCode, iso, data, dims, hash_table, vertex_counter)
                    
                    # Store vertex index in edge hash for each intersected edge
                    for edge in branch.intersected_edges:
                        edge_idx = get_global_edge_index(edge, cx, cy, cz, dims)
                        # Determine position in quad array based on edge orientation
                        pos_in_quad = get_quad_position(edge, cx, cy, cz)
                        if edge_idx not in edge_hash:
                            edge_hash[edge_idx] = [None, None, None, None]
                        edge_hash[edge_idx][pos_in_quad] = v_idx

    # Kernel 2: Collect Quads
    for edge_idx, quad_indices in edge_hash.items():
        if None not in quad_indices:
            # Order is [B, A, D, C] as per standard DMC orientation
            quads.append(Quad(quad_indices[0], quad_indices[1], quad_indices[2], quad_indices[3]))
            
    return vertices, quads
```

### Parameters and Edge Cases
*   **Isovalue ($\iota_0$):** Clamped to $[0, 1]$ in some implementations; defaults to 0.0 if NaN or out-of-bounds [S1].
*   **Manifold Flag:** When true, applies Wenger's correction to resolve non-manifold meshes [S1].
*   **Boundary Cells:** If a bucket in the edge hash table has an invalid index (e.g., from a boundary cell), no quadrilateral is generated for that edge [S2].
*   **Non-manifold Edges:** Tunnels covering two neighbor cells can create non-manifold edges shared by four faces. This requires special handling in the halfedge data structure [S2].
*   **Numerical Instability:** In extreme cases, the fallback to the center of gravity may be required, though rarely observed [S2].

## Subtopics

### [Dual Marching Cubes Table Generation](2069-dual-marching-cubes-table-generation.md)
An algorithm to generate the lookup table for the Dual Marching Cubes (DualMC) surface extraction method. It maps each of the 256 possible cube corner configurations (inside/outside) to a set of dual point edge masks that define the extracted surface geometry.

### [Manifold Dual Marching Cubes](2135-manifold-dual-marching-cubes.md)
Precomputes a lookup table to resolve ambiguous configurations in Dual Marching Cubes by mapping each problematic cube configuration (0-255) to its ambiguous face direction, or 255 if non-problematic.

### [Mesh simplification via face coloring](2141-mesh-simplification-via-face-coloring.md)
Reduces mesh element count by removing quadrilaterals based on vertex valence patterns and face coloring.

### [Halfedge Data Structure Construction](2310-halfedge-data-structure-construction.md)
A data structure computed in two parallel kernels to store connectivity information (vertices, faces, next halfedges, twin edges) for the quadrilateral mesh, handling boundary and non-manifold edges.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of cells and intersected edges. The parallel implementation uses two CUDA kernels, making it efficient for large volumes [S2].
*   **Memory Complexity:** Proportional to the number of intersected edges and vertices. Hash tables are used, sized twice the expected number of elements to handle collisions via quadratic probing [S2].
*   **Performance:** On an NVIDIA GeForce RTX 4090, DMC achieves ~1.0 billion faces/s on sparse Fandisk CAD at $1024^3$ resolution (3.44 ms latency for 3.43 M faces) [S4]. It is 4.3x faster than Dual Contouring and 4.8x faster than Marching Cubes Asymptotic (MCA) on the same data [S4].
*   **Strengths:** Generates high-quality, manifold, watertight quad-only meshes with fewer vertices than standard MC. No lookup tables required for topology in the base algorithm [S2].
*   **Limitations:** Cannot reconstruct tunnels of sub-voxel size. May generate non-manifold edges in specific tunnel configurations across two cells [S2]. Newton-Raphson projection can blur sharp features compared to Dual Contouring [S4].
*   **When to Use:** When a high-quality quad mesh is required for further processing (e.g., subdivision, simplification) and performance on GPU is critical.
*   **When Not to Use:** When sub-voxel tunnel reconstruction is necessary, or when triangle meshes are strictly required without post-processing.

## Background
Dual Marching Cubes was introduced by Gregory M. Nielson as a dual approach to the standard Marching Cubes algorithm [S1]. The original algorithm can create non-manifold meshes under rare circumstances, which was addressed by Rephael Wenger in his book "Isosurfaces: Geometry, Topology, and Algorithms" (Chapter 3.3.5) through the Manifold Dual Marching Cubes algorithm [S1]. A parallel GPU implementation without lookup tables was later presented by Grosso and Zint, enabling efficient processing of huge amounts of data [S2].
