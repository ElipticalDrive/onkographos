# Marching Lines Algorithm

Also called: Marching Squares-like method [S2, unofficial]

## Overview
The Marching Lines Algorithm (MLA) extracts 1D isocontour line segments from a discrete 2D scalar field by processing grid cells in a linear, row-by-row manner [S2, unofficial]. It serves as the 1D analog to [Marching Squares](918-marching-squares.md) [S2, unofficial]. Unlike template-based methods, MLA is not template-based and requires further processing to properly resolve apparent cell ambiguities [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D scalar field $f(x, y)$ defined on a regular grid of vertices [G].
*   **Output:** A set of line segments connecting points where the scalar field crosses a specified isovalue $I$ [S2, unofficial].

**Data Structures:**
*   **Grid:** A 2D array of scalar values [G].
*   **Edge List:** A list of line segments, each defined by two endpoints [G].

**Pseudocode:**
```python
def marching_lines(grid, isovalue):
    segments = []
    rows, cols = grid.shape
    for y in range(rows - 1):
        for x in range(cols - 1):
            v00, v10, v01, v11 = grid[y, x], grid[y, x + 1], grid[y + 1, x], grid[y + 1, x + 1]
            s00 = v00 >= isovalue
            s10 = v10 >= isovalue
            s01 = v01 >= isovalue
            s11 = v11 >= isovalue
            intersections = []
            if s00 != s10: intersections.append(interpolate(x, y + 1, x + 1, y + 1, v00, v10, isovalue))
            if s10 != s11: intersections.append(interpolate(x + 1, y + 1, x + 1, y + 2, v10, v11, isovalue))
            if s11 != s01: intersections.append(interpolate(x + 1, y + 2, x, y + 2, v11, v01, isovalue))
            if s01 != s00: intersections.append(interpolate(x, y + 2, x, y + 1, v01, v00, isovalue))
            if len(intersections) == 2:
                segments.append((intersections[0], intersections[1]))
            elif len(intersections) > 2:
                segments.append(resolve_ambiguity(intersections))
    return segments

def interpolate(x1, y1, x2, y2, v1, v2, isovalue):
    t = (isovalue - v1) / (v2 - v1)
    return ((1 - t) * x1 + t * x2, (1 - t) * y1 + t * y2)

def resolve_ambiguity(intersections):
    # Further processing to resolve apparent cell ambiguities [S1, unofficial]
    # Connect intersections based on topological consistency across adjacent cells [G]
    return [(intersections[0], intersections[1]), (intersections[2], intersections[3])]
```

**Parameters:**
*   **Isovalue ($I$):** The scalar threshold for extraction [G].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision issues near the isovalue can lead to inconsistent sign determinations [G].
*   **Degenerate Input:** If a vertex value exactly equals the isovalue, special handling is required to avoid division by zero during interpolation [G].

## Subtopics

### [Cubical Marching Squares](2780-cubical-marching-squares.md)
Cubical Marching Squares (CMS) is an adaptive surface extraction method that partitions space in a binary fashion using X-Y, Y-Z, and X-Z planes to extract surfaces while preserving sharp features and topology. It extends the 2D marching squares algorithm to 3D by unfolding a cube into six 2D faces, applying marching squares to generate isocurves on each face, and reconnecting these segments in 3D to form components and triangles. This approach eliminates inter-cell dependency and crack patching by sampling sharp features on faces, making it suitable for adaptive multiresolution representations. It is significantly more complicated to implement than Dual Contouring but offers advantages in sharp feature preservation and crack-free guarantees.

### Marching Squares on Triangular Meshes
Application of the Marching Squares algorithm to triangular meshes (connected triangles with data at vertices), such as those from Delaunay triangulation of scattered data points [S3]. A triangular cell is always planar (a 2-simplex), ensuring a unique linear interpolant across it and no possibility of an ambiguous saddle [S3]. For isolines, the analysis involves 3 binary digits at vertices, resulting in 8 possibilities [S3]. For isobands, it involves 3 ternary trits, resulting in 27 possibilities [S3].

## Operating characteristics
*   **Usage:** Used by the visualization program PyMOL to render electron density meshes [S2, unofficial].
*   **Strengths:** Simple implementation; low memory overhead [G].
*   **Limitations:** Requires post-processing to resolve ambiguities; not template-based [S1, unofficial].
