# Modified Marching Cubes

Also called: Lee et al. algorithm, Lengyel's Modified Marching Cubes

## Overview
Modified Marching Cubes (MMC) is a surface extraction method that regularizes the connectivity of the isosurface mesh to achieve a maximum vertex valence of six [S1]. It solves the topological inconsistencies and potential holes in terrain generation caused by the original Marching Cubes lookup tables [S2, unofficial]. By reconsidering the triangulation of voxel cubes, MMC improves mesh topology and significantly reduces connectivity coding costs compared to the original algorithm [S1].

## How it works
MMC retains the fundamental structure of the original Marching Cubes algorithm but replaces the standard lookup tables with modified versions provided by Eric Lengyel [S2, unofficial]. The method relies on the same case index calculation and edge intersection logic as the parent article, but the resulting triangles are defined by Lengyel's tables to ensure consistent manifold connectivity [S2, unofficial].

**Inputs and Outputs:**
*   **Input:** Scalar field values at voxel vertices, isovalue, Lengyel's modified `triangleTable` and `edgeTable` [S2, unofficial].
*   **Output:** A manifold mesh with maximum vertex valence of six [S1].

**Data Structures:**
The core difference lies in the `triangleTable` [G]. While the parent article describes the standard 256x16 table, MMC uses Lengyel's variant [G]. The layout remains a 2D array indexed by case $C \in [0, 255]$, storing edge indices in triplets terminated by `-1` [S2, unofficial]. The specific edge indices differ from the standard table to resolve ambiguities and enforce the valence constraint [G].

**Steps:**
1.  **Compute Case Index:** For each voxel, calculate the 8-bit case index $C$ based on the sign of $(V(v_i) - I)$ at the 8 vertices [G].
2.  **Lookup Triangles:** Retrieve the triangle configuration from Lengyel's `triangleTable[C]` [S2, unofficial].
3.  **Intersect Edges:** Calculate the intersection points on the 12 cube edges using linear interpolation [G].
4.  **Generate Vertices:** Position each vertex at the midpoint of the lattice edge joining an inside sample and an outside sample [S1].
5.  **Assemble Mesh:** Connect the vertices according to the triplets in the lookup table [S2, unofficial].

**Formulas:**
Vertex position on edge $e$ between vertices $v_a$ (inside) and $v_b$ (outside) is calculated as:
$$P_e = \frac{v_a + v_b}{2}$$
where $v_a$ and $v_b$ are the 3D coordinates of the voxel corners [S1].

**Pseudocode:**
```python
def extract_triangles_mmc(case_index, lengyel_triangle_table, edge_intersections):
    """
    Extracts triangles using Lengyel's modified lookup table.
    edge_intersections: list of 12 points, one for each cube edge.
    lengyel_triangle_table: 2D array [256][16] containing edge indices.
    """
    triangles = []
    tri_indices = lengyel_triangle_table[case_index]
    
    # Iterate through the table entries
    for i in range(0, 16, 3):
        e1 = tri_indices[i]
        e2 = tri_indices[i+1]
        e3 = tri_indices[i+2]
        
        # Check for termination marker (-1)
        if e1 == -1:
            break
            
        # Retrieve precomputed intersection points
        p1 = edge_intersections[e1]
        p2 = edge_intersections[e2]
        p3 = edge_intersections[e3]
        
        triangles.append((p1, p2, p3))
        
    return triangles
```

**Edge Cases and Pitfalls:**
*   **Ambiguity:** The modified tables are designed to handle the ambiguous cases (46, 47, etc.) more robustly than the original tables, reducing the risk of cracks [S2, unofficial].
*   **Valence:** The primary goal is to limit vertex valence to six. Implementations should verify that the resulting mesh adheres to this constraint for optimal connectivity coding [S1].

## Operating characteristics
*   **Time Complexity:** Comparable to standard Marching Cubes, $O(N)$ where $N$ is the number of voxels, due to the per-voxel lookup and interpolation [G].
*   **Memory Complexity:** Requires storage for Lengyel's lookup tables, which maintain the same dimensions as the standard tables [G].
*   **Strengths:** Produces manifold meshes with regular connectivity (max valence six), which is beneficial for compression and subsequent processing [S1]. Fixes holes in terrain generation [S2, unofficial].
*   **Limitations:** Not given in the sources.

## Background
The Modified Marching Cubes algorithm was proposed by Lee et al. [S1]. It was later popularized in the context of terrain rendering and the Transvoxel algorithm by Eric Lengyel, who provided the specific modified lookup tables [S2, unofficial]. The method was developed to address inconsistencies in the original Marching Cubes tables that could lead to non-manifold geometry or holes in terrain meshes [S2, unofficial].
