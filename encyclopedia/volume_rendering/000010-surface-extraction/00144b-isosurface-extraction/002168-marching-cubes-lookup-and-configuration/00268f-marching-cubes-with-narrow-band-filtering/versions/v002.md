# Marching Cubes with Narrow-Band Filtering

Also called: MeshReconstruction::MarchCube

## Overview
This method reconstructs a triangle mesh from a Signed Distance Function (SDF) by evaluating the function on a regular grid of cubes, filtering out cubes that are too far from the surface (narrow-band filtering), and applying the standard Marching Cubes algorithm to the remaining cubes [S1, unofficial]. It differs from standard Marching Cubes by skipping the vast majority of the domain volume, significantly reducing computation time for sparse or localized surfaces, while maintaining the topological correctness and geometric detail of the original algorithm [S1, unofficial].

## How it works
**Inputs:**
- `domain`: A bounding box defined by `min` (Vec3) and `size` (Vec3).
- `sdf`: A function `Fun3s` that returns a scalar value for any 3D position.
- `cubeSize`: The dimensions of the cubic cells (Vec3). If not provided, it is derived from `NumCubes` (default 50) as `domain.size / NumCubes` [S1, unofficial].
- `isoLevel`: The threshold value for surface extraction (default 0) [S1, unofficial].
- `sdfGrad`: An optional gradient function for vertex normals. If `nullptr`, normals are approximated numerically [S1, unofficial].

**Outputs:**
- A triangle mesh containing vertices and indices.

**Data Structures:**
- **Cube**: Represents a single grid cell.
  - `pos[8]`: Array of 8 vertex positions (Vec3).
  - `sdf[8]`: Array of 8 scalar SDF values at the vertices.
  - `intersect`: Result of intersection test, containing intersection points on edges.
- **Edge Configuration**:
  - The 12 edges of a cube are indexed 0–11.
  - Each edge has a bit flag: `1, 2, 4, ..., 2048` (powers of 2).
  - A 256-entry lookup table `signConfigToIntersectedEdges` maps the 8-bit sign configuration of the cube vertices to a 12-bit bitmask of intersected edges [S1, unofficial].
  - The `edges` array maps edge indices to their two vertex indices (0–7):
    - Edge 0: Vertices 0,1
    - Edge 1: Vertices 1,2
    - Edge 2: Vertices 2,3
    - Edge 3: Vertices 3,0
    - Edge 4: Vertices 4,5
    - Edge 5: Vertices 5,6
    - Edge 6: Vertices 6,7
    - Edge 7: Vertices 7,4
    - Edge 8: Vertices 0,4
    - Edge 9: Vertices 1,5
    - Edge 10: Vertices 2,6
    - Edge 11: Vertices 3,7 [S1, unofficial]

**Steps:**

1.  **Calculate Grid Dimensions**:
    Determine the number of cubes along each axis:
    $$
    \text{NumX} = \lceil \frac{\text{domain.size.x}}{\text{cubeSize.x}} \rceil
    $$
    $$
    \text{NumY} = \lceil \frac{\text{domain.size.y}}{\text{cubeSize.y}} \rceil
    $$
    $$
    \text{NumZ} = \lceil \frac{\text{domain.size.z}}{\text{cubeSize.z}} \rceil
    $$
    [S1, unofficial]

2.  **Calculate Geometric Constants**:
    $$
    \text{HalfCubeDiag} = \frac{\|\text{cubeSize}\|}{2.0}
    $$
    $$
    \text{HalfCubeSize} = \text{cubeSize} \times 0.5
    $$
    [S1, unofficial]

3.  **Iterate Grid**:
    For each grid index $(i_x, i_y, i_z)$ where $0 \le i_x < \text{NumX}$, etc.:
    
    a.  **Calculate Cube Position**:
        $$
        \text{min} = \text{domain.min} + \{i_x \cdot \text{cubeSize.x}, i_y \cdot \text{cubeSize.y}, i_z \cdot \text{cubeSize.z}\}
        $$
        $$
        \text{cubeCenter} = \text{min} + \text{HalfCubeSize}
        $$
        [S1, unofficial]

    b.  **Narrow-Band Filter**:
        Calculate the distance from the cube center to the isosurface:
        $$
        \text{dist} = |\text{sdf}(\text{cubeCenter}) - \text{isoLevel}|
        $$
        If $\text{dist} > \text{HalfCubeDiag}$, the cube is too far from the surface to intersect it. Continue to the next cube [S1, unofficial].

    c.  **Construct Cube**:
        Create a `Cube` object. Sample the SDF at the 8 vertices of the cube to populate `Cube.sdf` and store positions in `Cube.pos` [S1, unofficial].

    d.  **Intersect**:
        Call `cube.Intersect(isoLevel)`.
        - Determine the sign configuration index $C = \sum_{k=0}^{7} (s_k < \text{isoLevel} ? 2^k : 0)$, where $s_k$ is the SDF value at vertex $k$.
        - Look up `intersectedEdgesMask = signConfigToIntersectedEdges[C]`.
        - For each edge $e$ where `(intersectedEdgesMask >> e) & 1`:
          - Get vertex indices $v_0, v_1$ from `edges[e]`.
          - Calculate intersection point $P$ using linear interpolation:
            $$
            \mu = \frac{\text{isoLevel} - \text{sdf}[v_0]}{\text{sdf}[v_1] - \text{sdf}[v_0]}
            $$
            $$
            P = \text{pos}[v_0] + \mu (\text{pos}[v_1] - \text{pos}[v_0])
            $$
            *Note*: If $|\text{isoLevel} - \text{sdf}[v_0]| < \epsilon$ or $|\text{sdf}[v_1] - \text{sdf}[v_0]| < \epsilon$, handle precision edge cases by returning the respective vertex position [S1, unofficial].
        - Store intersection points in `Cube.intersect`.

    e.  **Triangulate**:
        Call `Triangulate(intersect, sdfGrad, mesh)`.
        - Use the standard Marching Cubes lookup table (or equivalent logic) to generate triangles from the intersection points.
        - If `sdfGrad` is provided, use it for vertex normals; otherwise, compute numerical gradients [S1, unofficial].
        - Add generated triangles to the output mesh [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of cubes in the narrow band. The narrow-band filter reduces the effective $N$ significantly compared to the full grid volume, especially for smooth, localized surfaces [S1, unofficial].
- **Memory Complexity**: $O(K)$ where $K$ is the number of intersected cubes. Only cubes intersecting the surface are processed and stored in the mesh [S1, unofficial].
- **Performance**: The library is described as "fast" due to the narrow-band approach excluding cubes far from the surface and the use of precomputed lookup tables [S1, unofficial].
- **Strengths**: Efficient for sparse SDFs; avoids processing empty space; simple implementation using standard MC tables.
- **Limitations**: Requires the SDF to be available; narrow-band filtering may miss very thin features if the cube size is too large relative to the feature width (since the filter uses the cube diagonal) [S1, unofficial].

## Background
The method is implemented in the `MeshReconstruction` library by Magnus2 [S1, unofficial]. It builds upon the classic Marching Cubes algorithm [S1, unofficial] and is designed to be self-contained with no external dependencies, requiring only C++14 [S1, unofficial]. It is used for reconstructing triangle meshes from SDF data, such as in the demo example of a sphere [S1, unofficial].
