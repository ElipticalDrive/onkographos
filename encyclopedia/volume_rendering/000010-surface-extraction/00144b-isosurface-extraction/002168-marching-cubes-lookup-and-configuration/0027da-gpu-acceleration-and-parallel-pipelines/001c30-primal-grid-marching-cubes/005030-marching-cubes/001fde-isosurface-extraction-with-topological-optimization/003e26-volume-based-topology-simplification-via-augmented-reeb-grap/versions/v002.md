# Volume-Based Topology Simplification via Augmented Reeb Graph

Also called: Augmented Reeb Graph Handle Detection, Augmented Reeb Graph Method, Intraribbon handle identification, Reeb graph cycle detection, Sweep-based Topology Simplification

## Overview
This method removes topological noise (specifically handles) from isosurfaces extracted from volumetric scalar data by sweeping through the volume, encoding topology in an augmented Reeb graph, isolating handles, measuring their size, and removing small ones [S1]. It differs from polygon-by-polygon traversal methods by using an axis-aligned sweep that allows for out-of-core processing and produces a less dense Reeb graph, and from cut-graph methods by searching for nonseparating cuts locally rather than analyzing the entire surface [S1].

## How it works
**Inputs and Outputs:**
The input is a regularly sampled 3D grid of scalar values $F(x)$, where the interior is defined as $F(x) < 0$ and the exterior as $F(x) \ge 0$ [S1]. The output is a topologically simplified isosurface mesh with small handles removed [S1].

**Data Structures:**
A grid cube is bounded by 8 grid data points and contains up to 4 polygons from the isosurface generation algorithm [S1]. A slice is the set of grid cubes between two adjacent data planes (z-intervals) [S1]. A contour is an oriented closed polyline formed by the intersection of the isosurface with a planar cross-section (data plane) [S1]. A ribbon is a connected component of the surface within a slice, with boundaries consisting of one or more contours in the two adjacent planes [S1]. An augmented Reeb graph stores geometric information for each contour and ribbon, where nodes correspond to contours and ribbons, edges represent adjacency, and cycles correspond to handles [S1]. A disjoint-set data structure manages component labels for ribbons and contours [S1].

**Connectivity Rule:**
The method uses Lachaud [1996] connectivity rules for isosurface generation to ensure a closed oriented surface without singularities or self-intersections [S1].

**Algorithm Steps:**
1. Sweep and Encode Topology: Sweep through the volume along parallel data planes (z-intervals) [S1]. Within each slice, identify ribbons and contours using breadth-first search (BFS) [S1]. Contour construction searches from an arbitrary edge in the plane until the contour is closed [S1]. Ribbon construction runs a BFS in the slice starting with polygons adjacent to one contour and ending with polygons adjacent to the previous contour [S1]. Graph construction creates nodes in the Reeb graph for ribbons and contours, records adjacency as graph edges, and associates a label with every ribbon and contour node to identify the connected component [S1].
2. Detect Intraribbon Handles: Standard z-interval traversal may miss handles entirely contained within a single ribbon (slice), which occur in 1–10% of slices [S1]. The algorithm computes the Euler characteristic $\chi$ of the isosurface within each z-interval using $\chi = |V| - |E| + |F|$ [S1]. If the slice has nonzero genus ($g = (2-\chi)/2 > 0$), it contains handles [S1]. For such slices, the distance function is analyzed on a polygon-by-polygon basis using a BFS over polygons in the current slice [S1]. Contour construction is modified to be defined by this polygon BFS so the Reeb graph encodes the intra-ribbon handle topology [S1]. A final check confirms overall correspondence by ensuring a match between the Euler characteristic of the surface traversed thus far and the number of cycles in the Reeb graph [S1].
3. Isolate Handles: Handles are detected as cycles in the Reeb graph formed when two contour nodes with the same connected component label are merged into a single ribbon node [S1]. When adding a ribbon node $r$ and its adjacent previous contours $C$, the algorithm checks if any pair of contours $c_1, c_2 \in C$ have the same label [S1]. If $label(c_1) = label(c_2)$, a Reeb cycle is formed [S1]. The handle is isolated by performing a BFS through the graph to find the shortest graph cycle between $c_1$ and $c_2$ [S1]. The Reeb cycle path consists of alternating ribbon and contour nodes and defines the handle [S1]. If a ribbon has $k$ child contours with the same component labels ($k \ge 2$), the algorithm considers all pairs of child contours to test reasonable ways to isolate a handle [S1].
4. Measure and Remove: For each handle found, the algorithm measures its size [S1]. If the size is sufficiently small, the handle is removed [S1].

**Pseudocode:**
```python
def add_ribbon_to_reeb_graph(ribbon, graph):
    graph.add_node(ribbon)
    label(ribbon) = generate_unique_label()
    contours = get_adjacent_contours(ribbon)
    for i in range(len(contours)):
        for j in range(i + 1, len(contours)):
            c1, c2 = contours[i], contours[j]
            if label(c1) == label(c2):
                path = shortest_path(c1, c2, graph)
                cycle = (c2, ribbon) + (ribbon, c1) + path
                report_cycle(cycle)
    for contour in contours:
        graph.add_edge(contour, ribbon)
        union_labels(contour, ribbon)

def union_labels(node1, node2, parent):
    root1 = find_set(node1, parent)
    root2 = find_set(node2, parent)
    if root1 != root2:
        parent[root2] = root1

def find_set(node, parent):
    if parent.get(node, node) != node:
        parent[node] = find_set(parent[node], parent)
    return parent[node]
```
*Note: `generate_unique_label`, `get_adjacent_contours`, `shortest_path`, `report_cycle`, and graph methods are standard graph operations [G]. The Union-Find implementation fills a standard initialization gap [G].*

**Edge Cases and Pitfalls:**
Intraribbon handles are entirely contained within a single ribbon (slice) and are not detected by the standard z-interval traversal, requiring Euler characteristic computation and polygon-by-polygon BFS within that slice [S1]. A ribbon may have $k \ge 2$ child contours with the same component label, corresponding to a region with a degenerate critical point (multiple saddle), requiring the algorithm to consider all pairs of child contours to find the best nonseparating cut [S1]. The method relies on the connectivity rules of Lachaud [1996] to ensure a closed oriented surface, as deviations may result in singularities or self-intersections [S1].

## Operating characteristics
Time complexity is not given in the sources [S1]. Memory complexity supports out-of-core processing due to ordered traversal through slices, keeping surface access local [S1]. Measured performance is not given in the sources [S1]. The z-interval sweep allows out-of-core processing, unlike polygon-by-polygon traversal which requires irregular data access [S1]. Strengths include out-of-core capability, a less dense Reeb graph than polygon-by-polygon traversal, and fast approximations of nonseparating cuts [S1]. Limitations include not being guaranteed to find globally minimum cuts due to local search only [S1]. The method should be used when processing large volumes that do not fit in memory, or when a fast approximation of topology simplification is sufficient [S1]. It should not be used when globally minimal cuts are required, or when the surface topology is simple enough that local simplification is unnecessary [S1].

## Background
The method was introduced by Wood et al. [S1] as a way to remove excess topology from isosurfaces [S1]. It builds on the concept of Reeb graphs for topology analysis [S1]. The approach contrasts with cut-graph methods which analyze the entire surface to find nearly-minimal cuts, whereas this method searches for nonseparating cuts locally, one handle at a time [S1].
