# Marching Cubes 33

Also called: 33-case Marching Cubes, Advanced Marching Cubes, Construction of Topologically Correct Isosurfaces, MC33

## Overview
Marching Cubes 33 (MC33) is an algorithm for constructing isosurfaces from volumetric datasets on a cuberille grid that resolves the topological ambiguities inherent in the original 15-configuration Marching Cubes method [S1, unofficial]. It processes each cell independently to produce a triangle model whose topology coincides exactly with the topology of the trilinear function defining the isosurface [S1, unofficial]. Unlike its sibling [Extended Trilinear Triangulation](1618-extended-trilinear-triangulation.md), which uses convex hulls of intersection points, MC33 relies on an expanded lookup table of 33 entries derived from analytical tests for face and internal connectivity [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field sampled on a cubic grid; a specific cube cell defined by 8 corner node values $F_{000}, \dots, F_{111}$; and an isovalue (typically 0).
*   **Output:** A set of triangles representing the isosurface within that cube.

**Data Structures:**
*   **Advanced Lookup Table:** A table with 33 entries. Each entry specifies the connectivity pattern (which edges are connected) and whether an additional internal vertex is required.
*   **Node Signs:** Each corner node is classified as positive ($F > 0$) or negative ($F \le 0$).

**Definitions:**
*   **Trilinear Interpolation:** The scalar function $F$ over a cube with local coordinates $q, s, t \in [0, 1]$ is:
    $$F(q,s,t) = F_{000}(1-q)(1-s)(1-t) + F_{100}q(1-s)(1-t) + F_{010}(1-q)s(1-t) + F_{110}qs(1-t) + F_{001}(1-q)(1-s)t + F_{101}q(1-s)t + F_{011}(1-q)st + F_{111}qst$$
*   **Separated vs. Joined:** Two nodes of the same sign are **joined** (non-separated) if there exists a path between them along which $F$ does not change sign. They are **separated** if no such path exists [S1, unofficial].
*   **Ambiguous Face:** A face with two positive and two negative diagonally opposed nodes. The node signs alone are insufficient to determine connectivity [S1, unofficial].
*   **Internal Ambiguity:** A situation where nodes are separated on the faces but may be joined inside the cube (e.g., Configuration 4) [S1, unofficial].

**Algorithm Steps:**

1.  **Determine Base Configuration:**
    Compute the 8-bit index based on the signs of the 8 corner nodes. Map this to one of the 15 standard configurations.

2.  **Resolve Face Ambiguity:**
    For any face with diagonally opposed positive nodes $A, C$ and negative nodes $B, D$:
    *   Calculate products $P = AC$ and $N = BD$.
    *   If $AC > BD$, the positive nodes are joined and negative nodes are separated.
    *   Otherwise ($AC \le BD$), the positive nodes are separated and negative nodes are joined.
    *   *Note:* The denominator $A+C-B-D$ in the full asymptote test is always positive, simplifying the comparison to just the products [S1, unofficial].

3.  **Resolve Internal Ambiguity:**
    Depending on the configuration, check for internal joining of nodes.
    *   **Method 1 (Hyperbola Intersection):** Compare hyperbolas on opposite faces. If the projections intersect, areas are joined. This is determined by checking if $(A_1-A_0)(C_1-C_0) - (B_1-B_0)(D_1-D_0) > 0$ [S1, unofficial].
    *   **Method 2 (Quadratic Inequality - Preferred):** Check for a plane parallel to a face where nodes of the same sign become joined.
        1.  Derive the quadratic inequality $at^2 + bt + c > 0$ from bilinear interpolation on parallel faces.
        2.  Check if $a < 0$ (parabola opens downward).
        3.  Check if the maximum $t_{max} = -b/2a$ lies within $(0, 1)$.
        4.  Check if the corner nodes at $t=t_{max}$ have the required signs and the inequality holds.
        5.  If all true, the areas are joined inside the cube [S1, unofficial].

4.  **Select Case and Generate Triangles:**
    Based on the resolution of face and internal ambiguities, select the specific case from the 33-entry table.
    *   **Simple Configurations (0, 1, 2, 5, 8, 9, 11, 14):** No ambiguous faces, no internal ambiguity. All positive nodes joined, all negative nodes joined.
    *   **Configuration 4:** No ambiguous faces, but internal ambiguity.
        *   Case 4.1.1: Positive diagonal nodes completely separated.
        *   Case 4.1.2: Positive diagonal nodes joined inside the cube.
    *   **Configuration 6:** One ambiguous face.
        *   Case 6.1.1: Positive nodes of ambiguous face completely separated.
        *   Case 6.1.2: Positive nodes of ambiguous face joined inside cube.
        *   Case 6.2: Positive nodes on ambiguous face not separated.
    *   **Configuration 7:** Three adjacent ambiguous faces with a common negative node.
        *   Case 7.3: Positive nodes joined on two ambiguous faces, separated on the third. Requires an **additional vertex** inside the cube.
        *   Case 7.4.1: Positive nodes joined on all ambiguous faces; common negative node completely separated.
        *   Case 7.4.2: Positive nodes joined on all ambiguous faces; common negative node joined inside the cube.
    *   **Configuration 10:** Equal positive/negative nodes. Ensure positive nodes on the "top" face are separated.
        *   Case 10.1.1: Positive nodes on top/bottom separated; large diagonal positive nodes separated.
        *   Case 10.1.2: Positive nodes on top/bottom separated; large diagonal positive nodes joined inside cube.
        *   Case 10.2: Positive nodes on top separated, bottom not separated. Requires an **additional vertex**.
    *   **Configuration 12:** Two ambiguous faces.
        *   Case 12.1.1: Separated on both; common positive node completely separated.
        *   Case 12.1.2: Separated on both; common positive node joined inside cube.
        *   Cases 12.2/12.3: Mirror cases (separated on one, not the other). Require an **additional vertex**.
    *   **Configuration 13:** All six faces ambiguous.
        *   Case 13.1: Separated on all faces.
        *   Case 13.2: Separated on five, joined on one.
        *   Case 13.3: Separated on four, joined on two adjacent faces. Requires an **additional vertex**.
        *   Case 13.4: Three faces with separated positive nodes, common node is negative. Requires an **additional vertex**.
        *   Case 13.5.1: Common node is positive, completely separated.
        *   Case 13.5.2: Common node is positive, joined inside cube.
    *   **Additional Vertex Handling:** In cases requiring an additional vertex (e.g., 7.3, 10.2, 12.2, 12.3, 13.3, 13.4), the vertex is situated inside the cube and serves as a common node for all triangles. A simple choice is the average of all other vertices [S1, unofficial].

5.  **Vertex Generation:**
    Real vertices are formed by the intersection of the isosurface with the edges. Linear interpolation along the edges is used to determine the coordinates of these vertices [S1, unofficial].

**Pseudocode:**

```python
def marching_cubes_33(cube_values, isovalue=0.0):
    """
    cube_values: list of 8 floats, F_000 to F_111
    Returns: list of triangles, each triangle is a list of 3 vertices (x,y,z)
    """
    # 1. Determine signs and base index
    signs = [1 if v > isovalue else -1 for v in cube_values]
    index = 0
    for i, s in enumerate(signs):
        if s > 0:
            index |= (1 << i)
            
    # 2. Identify ambiguous faces and resolve face ambiguity
    # Map cube indices to faces. 
    # Face 0 (bottom, t=0): nodes 0,1,2,3 (F000, F100, F010, F110)
    # Face 1 (top, t=1): nodes 4,5,6,7 (F001, F101, F011, F111)
    # Face 2 (front, s=0): nodes 0,1,4,5
    # Face 3 (back, s=1): nodes 2,3,6,7
    # Face 4 (left, q=0): nodes 0,2,4,6
    # Face 5 (right, q=1): nodes 1,3,5,7
    
    face_ambiguities = []
    for face_idx in range(6):
        nodes = get_face_nodes(face_idx) # Returns 4 indices
        vals = [cube_values[n] for n in nodes]
        # Check for 2 positive, 2 negative diagonally opposed
        if is_ambiguous_face(vals):
            A, B, C, D = vals # Diagonals A-C, B-D
            if A * C > B * D:
                face_ambiguities.append((face_idx, 'joined_pos'))
            else:
                face_ambiguities.append((face_idx, 'separated_pos'))

    # 3. Resolve internal ambiguity based on configuration
    # This logic selects the specific case from the 33 entries
    case_id = determine_case(index, face_ambiguities, cube_values)
    
    # 4. Generate triangles based on case_id
    triangles = []
    additional_vertex = None
    
    if case_id in CASES_REQUIRING_ADDITIONAL_VERTEX:
        # Calculate additional vertex as average of edge intersection vertices
        edge_vertices = get_edge_intersections(cube_values, isovalue)
        additional_vertex = sum(edge_vertices) / len(edge_vertices)
        
    # Retrieve connectivity pattern for case_id
    pattern = lookup_table[case_id]
    
    for tri_indices in pattern:
        vertices = []
        for idx in tri_indices:
            if idx == 'ADD':
                vertices.append(additional_vertex)
            else:
                # Linear interpolation on edge idx
                vertices.append(interpolate_edge(cube_values, isovalue, idx))
        triangles.append(vertices)
        
    return triangles

def is_ambiguous_face(vals):
    # vals are the 4 corner values of a face
    pos = [v for v in vals if v > 0]
    neg = [v for v in vals if v <= 0]
    if len(pos) == 2 and len(neg) == 2:
        # Check if they are diagonally opposed
        # Assuming vals order is A, B, C, D where A-C and B-D are diagonals
        return True
    return False
```

## Subtopics

### Extended Trilinear Triangulation
A method to generate a topologically correct, degenerate-free triangulation of the isosurface within a cube by tracking the connectivity of vertices and edges via positive/negative regions defined by the trilinear interpolant, using convex hulls of intersection points. Choose this when a geometric convex-hull approach is preferred over analytical case enumeration. [Link](1618-extended-trilinear-triangulation.md)

### Marching Cubes (15-case)
The original method using a 15-entry lookup table. It fails to resolve face and internal ambiguities, leading to topological errors. Choose this only for legacy compatibility or when topological correctness is not required. [Link](1617-marching-cubes.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of cells, as each cell is processed independently. The constant factor is higher than standard Marching Cubes due to the additional arithmetic for resolving ambiguities (multiplications, comparisons, and potentially quadratic root checks).
*   **Memory Complexity:** $O(1)$ per cell for the lookup table (33 entries). No global data structures are required.
*   **Measured Performance:** Implemented in the PAW/HIGZ project at CERN [S1, unofficial].
*   **Strengths:** Guarantees topological correctness for the trilinear interpolant. Resolves holes that appear in standard Marching Cubes when adjacent cells have complementary ambiguous configurations (e.g., Config 6 sharing a face with Complement of Config 3) [S1, unofficial].
*   **Limitations:** The lookup table is larger (33 vs 15). Some cases require an additional internal vertex, which can complicate mesh post-processing (e.g., smoothing) as it introduces a vertex not on the grid edges.
*   **When to use:** When topological fidelity is critical and the scalar field is interpolated trilinearly.
*   **When not to use:** If performance is the sole constraint and approximate topology is acceptable, or if the scalar field uses a different interpolation scheme (e.g., linear in each dimension but not bilinear on faces).

## Background
The method was introduced by A.P. Yushchenko in the paper "Marching cubes 33: construction of topologically correct isosurfaces" [S1, unofficial]. It was implemented in the HIGZ graphics package as part of the PAW (Physics Analysis Workstation) project at CERN (European Organization for Nuclear Research) [S1, unofficial]. The work addresses the limitations of the original Marching Cubes algorithm by Lorensen and Cline (1987) [S1, unofficial], specifically the topological discrepancies arising from the 15-case lookup table.
