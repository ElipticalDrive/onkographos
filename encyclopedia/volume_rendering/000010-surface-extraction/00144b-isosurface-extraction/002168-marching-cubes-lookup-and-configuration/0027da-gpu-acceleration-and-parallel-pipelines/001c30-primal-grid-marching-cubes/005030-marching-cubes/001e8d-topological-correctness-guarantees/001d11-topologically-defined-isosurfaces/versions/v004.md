# Topologically Defined Isosurfaces

Also called: Digital Geometry Connectedness Marching Cubes

## Overview
Topologically Defined Isosurfaces is a method for extracting a closed, oriented 2-manifold from a binary volumetric image by modifying the Marching Cubes configuration table based on digital geometry connectedness [S1]. It solves the problem of topological ambiguity and self-intersection inherent in standard Marching Cubes by ensuring the generated surface strictly separates foreground from background according to chosen voxel adjacency rules [S1]. Unlike empirical corrections or continuous-field deciders, this approach guarantees consistency by deriving the surface topology directly from the discrete connectivity of the voxel grid, ensuring the surface lies within limits defined by voxel connections [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A binary volumetric image $I$ (voxels are 0 or 1) and a valid connectedness couple $(\eta, \lambda)$, where $\eta$ is the foreground (1-voxel) connectivity and $\lambda$ is the background (0-voxel) connectivity [S1].
*   **Output:** A closed, oriented, 2-manifold mesh without self-intersections or singularities [S1].

**Data Structures:**
*   **Binary Picture $I$:** A 3D grid of voxels. The method assumes 0-voxels or 1-voxels on the border of the support [S1].
*   **8-cube:** A set of 8 voxels $\{v_0, \dots, v_7\}$ forming a cell in the grid. Voxels are ordered by the binary coding of their index. Two voxels $v_i, v_j$ are 26-connected if $i \neq j$ [S1].
*   **4-face:** One of the six faces of an 8-cube, composed of 4 voxels. Each inner 4-face is shared by exactly two adjacent 8-cubes [S1].
*   **Link:** A couple of two 6-connected voxels on a 4-face. The value of a link is the pair of voxel values $(v_a, v_b)$ [S1].
*   **Local Graph $G_{gs}$:** A graph constructed for each 8-cube, consisting of oriented edges and vertices generated on its six inner 4-faces [S1].
*   **Complete Graph $G(I)$:** The union of all local graphs from all 8-cubes in $I$ [S1].

**Parameters:**
*   **Connectedness Couple $(\eta, \lambda)$:** Must be one of the valid couples: $(6, 18)$, $(6, 26)$, $(18, 6)$, or $(26, 6)$ [S1].
    *   $\eta \in \{6, 18, 26\}$: Connectivity for foreground (1-voxels).
    *   $\lambda \in \{6, 18, 26\}$: Connectivity for background (0-voxels).
*   **Invalid Couples:** Couples such as $(6,6), (18,18), (18,26), (26,18), (26,26)$ are invalid because they produce locally different surfaces in the inverse picture, violating the consistency property [S1].

**Steps:**

1.  **Decomposition:** Decompose the binary picture $I$ into all possible 8-cubes [S1].
2.  **4-face Orientation:** For each 8-cube, identify its six inner 4-faces. Orient each inner 4-face such that they are ordered (e.g., using Hamming coding for the 4-face configuration) [S1].
3.  **Link Identification:** For each ordered 4-face, identify its four links (couples of 6-connected voxels) in clockwise order [S1].
4.  **Local Graph Construction (4-face rules):** Apply the following rules to each link on an ordered 4-face based on its value $(v_a, v_b)$:
    *   If $(0,0)$ or $(1,1)$: No vertex is created.
    *   If $(0,1)$: Create one vertex between the voxels. Add an **incoming** oriented edge on this vertex staying on the 4-face.
    *   If $(1,0)$: Create one vertex between the voxels. Add an **outgoing** oriented edge on this vertex staying on the 4-face.
    *   *Note:* Cases 6 and 9 of the 4-configuration are indeterminate under these basic rules and require special handling based on the valid connectedness couple $(\eta, \lambda)$ [S1]. The valid couples ensure a coherent solution that satisfies the inverse image property [S1].
5.  **Handle Strict 26-Adjacency:** Check if the 8-cube contains two strictly 26-adjacent 1-voxels (if $\eta=26$) or two strictly 26-adjacent 0-voxels (if $\lambda=26$).
    *   If such a configuration exists, the local graph is transformed: the two disconnected loops generated on the 4-faces are triangulated to prevent the surface from intersecting the adjacency 3-map of the strictly adjacent voxels [S1].
6.  **Assemble Local Graph:** Gather all oriented edges generated on the six oriented inner 4-faces of the 8-cube to form the local graph $G_{gs}$ [S1]. According to Theorem 3, for a valid couple, $G_{gs}$ is a set of oriented loops of length $\ge 3$, disconnected from each other [S1].
7.  **Assemble Complete Graph:** Extend the set of all local graphs to form the complete graph $G(I)$ [S1]. Each edge of the complete graph belongs to exactly two loops with different orientations [S1].
8.  **Triangulation:** Derive the final isosurface from the complete graph. If loops have length $> 3$, subdivide (triangulate) them to form a combinatorial manifold [S1]. The embedding of this redefined local graph in $\mathbb{R}^3$ does not intersect the adjacency 3-map of strictly 26-adjacent voxels [S1].

**Edge Cases and Pitfalls:**
*   **Invalid Connectedness Couples:** Using couples like $(6,6), (18,18), (18,26), (26,18), (26,26)$ produces locally different surfaces in the inverse picture, violating the consistency property (iii) [S1].
*   **Cases 6 and 9:** These 4-configuration cases are indeterminate under the basic link rules. They must be resolved using the chosen valid connectedness couple [S1].
*   **Strict 26-Adjacency:** If the 8-cube contains two strictly 26-adjacent voxels of the same type (1s if $\eta=26$, 0s if $\lambda=26$), the local graph must be transformed (triangulated) to prevent intersection with the adjacency 3-map [S1].
*   **Boundary Conditions:** The method assumes 0-voxels or 1-voxels on the border of the support [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Guarantees a closed, oriented 2-manifold without singularities or self-intersections. Ensures the surface separates foreground from background according to the chosen connectedness. Consistent with the inverse image.
*   **Limitations:** Requires a binary image. The topology is constrained by the discrete voxel connectivity, which may not represent the underlying continuous volume exactly if the volume has features smaller than the voxel grid.
*   **When to use:** When topological correctness and manifold guarantees are critical, and the input data can be thresholded to a binary volume.
*   **When not to use:** When the underlying continuous field is known and a smoother, more accurate representation is needed, or when the input is not binary.

## Background
The method was introduced in the paper "Topologically defined isosurfaces" [S1]. It is based on digital geometry considerations, specifically the relationships between digital surfaces (Jordan surfaces) and isosurfaces locally computed. The method provides a formal proof of the validity of the generated isosurface, demonstrating that it is a simple, closed, oriented surface without self-crossing, and that it separates the foreground from the background. The complete definitions and demonstrations are found in reference [7] of the source [S1].
