# Topologically Defined Isosurface via Connectedness Couples

Also called: MC with (alpha, lambda) couples, Marching-Cubes with topological constraints

## Overview
This method extracts a topologically correct isosurface from a binary volumetric image by enforcing valid connectedness couples $(\alpha, \lambda)$ for foreground and background voxels, ensuring the output is a closed, oriented 2-manifold without singularities or self-intersections [S1]. Unlike continuous-field disambiguation methods such as the [Asymptotic Decider](790-asymptotic-decider.md) or [Extended Trilinear Triangulation](1618-extended-trilinear-triangulation.md) which analyze trilinear interpolants, this approach operates on discrete connectivity constraints, guaranteeing that the resulting mesh is a canonical embedding of the complete graph of the binary picture [S1]. It differs from [Topologically Defined Isosurfaces](1428-topologically-defined-isosurfaces.md) by explicitly defining the local triangulation cases for specific valid couples (26,6), (18,6), (6,26), and (6,18) to resolve ambiguities in strict 26-adjacency configurations [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A binary volumetric image $I$ of size $n \times n \times n$, where each voxel is either foreground (1) or background (0).
*   **Output:** A triangulated 2-manifold surface $S_\lambda(I)$ representing the isosurface.

**Data Structures:**
*   **Configuration Table:** A precomputed lookup table of size $256 \times 4$. Each entry corresponds to one of the 256 possible binary configurations of an $8$-cube (voxel and its 7 neighbors). The 4 entries correspond to the valid connectedness couples: $(26, 6)$, $(18, 6)$, $(6, 26)$, and $(6, 18)$. Each table entry contains a set of oriented loops (sequences of vertices) that define the local triangulation [S1].
*   **Complete Graph $G_\lambda(I)$:** An oriented two-dimensional combinatorial manifold without boundary, formed by the union of local graphs from all $8$-cubes in the image [S1].
*   **Local Graph $G_\lambda(C_8)$:** For a specific $8$-cube $C_8$, this is a set of oriented loops $L_1, \dots, L_k$ derived from the inner 6-faces [S1].

**Parameters:**
*   **Connectedness Couple $(\alpha, \lambda)$:** Defines foreground connectivity $\alpha$ and background connectivity $\lambda$. Valid couples are $(26, 6)$, $(18, 6)$, $(6, 26)$, and $(6, 18)$ [S1].
*   **Strict 26-Adjacency:** A boolean flag indicating if the current configuration $C$ exhibits strict 26-adjacency (all 26 neighbors of a foreground voxel are also foreground, or vice versa, creating a specific topological ambiguity) [S1].

**Steps:**

1.  **Precomputation of Local Tables:**
    For each of the 256 possible voxel configurations $C$ and for each valid connectedness couple $(\alpha, \lambda)$, compute the local triangulated manifold $S_\lambda(C_8)$ using the `Build-Local_Surface` procedure. Store these in the lookup table [S1].

2.  **Surface Extraction (Global):**
    Iterate through all voxels in the image. For each voxel, identify the $8$-cube configuration. Retrieve the precomputed loops from the lookup table corresponding to the chosen $(\alpha, \lambda)$ couple. Assemble the global surface by merging these local loops into the complete graph $G_\lambda(I)$ [S1].

3.  **Local Triangulation (`Build-Local_Surface`):**
    Given a configuration $C$ and foreground connectivity $\alpha$:
    *   Initialize an empty set of edges $E \leftarrow \emptyset$.
    *   For all inner 6-faces $F$ of $C$:
        *   Extract edges $E_F$ from $F$ using 6-adjacency connectivity.
        *   $E \leftarrow E \cup E_F$.
    *   Extract loops $L$ from the edge set $E$. Let $s$ be the set of these loops [S1].
    *   Compute the convex hull $H$ of the vertices in $E$ and the 1-voxels (center points) of $C$: $H \leftarrow \text{Convex\_Hull}(\text{get\_vertices}(E) \cup \text{get\_1-voxels}(C))$.
    *   **Loop Subdivision:** While $s$ contains a loop $L$ of length $> 3$:
        *   Remove $L$ from $s$. Let $L = (a_1, \dots, a_k)$ be the ordered vertices.
        *   Initialize `exit` $\leftarrow$ false, $i \leftarrow 1$, $j \leftarrow i + 2$.
        *   Repeat:
            *   If the chord $(a_i, a_j)$ lies inside $H$ (i.e., $(a_i, a_j) \in H$), set `exit` $\leftarrow$ true.
            *   Else, increment $j$. If $j = k$, reset $i \leftarrow i + 1$ and $j \leftarrow i + 2$.
        *   Until `exit` is true.
        *   Insert the subdivided loop $(a_1, \dots, a_i, a_j, \dots, a_k)$ back into $s$.
        *   Insert the chord loop $(a_i, \dots, a_j)$ into $s$.
    *   **Special Case Handling:** If $C$ has strict 26-adjacency and $\alpha = 26$:
        *   Replace the current loops in $s$ with special loops generated by `build_special_loops_26-adj(s)` [S1].
        *   If $\alpha = 18$, the local graph is not modified in this case [S1].
    *   Return $s$ [S1].

**Pseudocode:**

```python
def build_local_surface(configuration: List[int], alpha: int) -> List[List[int]]:
    """
    Computes the local triangulated manifold for a given 8-cube configuration
    and foreground connectivity alpha.
    
    Args:
        configuration: List of 8 integers (0 or 1) representing the binary state 
                       of the 8-cube vertices.
        alpha: Foreground connectivity (6, 18, or 26).
        
    Returns:
        List of loops, where each loop is a list of vertex indices.
    """
    # Step 1: Extract edges from inner 6-faces
    edges = []
    # Inner 6-faces are the faces shared by the 8-cube's internal structure.
    # In a standard 8-cube (voxel + neighbors), these correspond to the 
    # faces between the central voxel and its 6 face-adjacent neighbors.
    # We assume a helper function to map face index to vertex indices.
    for face_idx in range(6): # 6 inner faces
        face_vertices = get_face_vertices(configuration, face_idx)
        # Extract edges based on 6-adjacency on the face
        face_edges = extract_edges_from_face(face_vertices)
        edges.extend(face_edges)
    
    # Step 2: Extract loops from edges
    loops = extract_loops(edges)
    
    # Step 3: Compute Convex Hull
    # Vertices involved are the endpoints of the extracted edges
    # and the 1-voxels (centers) of the configuration.
    vertex_set = get_vertices(edges)
    voxel_centers = get_1_voxels(configuration)
    hull = compute_convex_hull(vertex_set.union(voxel_centers))
    
    # Step 4: Subdivide long loops
    while loops contains a loop L with length > 3:
        L = remove_loop_of_length_gt_3(loops)
        # L is an ordered set (a1, ..., ak)
        k = len(L)
        exit_flag = False
        i = 1
        j = i + 2
        
        while not exit_flag:
            # Check if chord (ai, aj) is in the convex hull
            if is_chord_in_hull(L[i], L[j], hull):
                exit_flag = True
            else:
                j += 1
                if j == k:
                    i += 1
                    j = i + 2
        
        # Insert subdivided loops
        # Loop 1: a1 ... ai aj ... ak
        loop1 = L[0:i] + [L[j]] + L[j:k] # Note: indices depend on 0-based or 1-based
        # Assuming L is 0-indexed in Python, but logic uses 1-based i,j
        # Re-mapping for Python 0-based:
        # i is 1-based index, so L[i-1] is the vertex.
        # The loop is (a1...ai, aj...ak). 
        # In 0-based: L[0]...L[i-1], L[j-1]...L[k-1]
        # But the chord is (ai, aj).
        
        # Correct Python 0-based implementation of the logic:
        # i and j are 1-based indices into the sequence a1...ak
        # a_i is L[i-1], a_j is L[j-1]
        
        # Loop 1: a1 ... ai, aj ... ak
        part1 = L[0:i] # a1 to ai (inclusive, 0-based index i-1 is included? No, i is 1-based count)
        # If i=1, part1 is [a1]. If i=2, part1 is [a1, a2].
        # So part1 = L[0:i]
        
        # part2: aj ... ak
        part2 = L[j-1:k] # a_j to a_k
        
        new_loop_1 = part1 + part2
        
        # Loop 2: ai ... aj (the chord loop)
        # This is the sequence from a_i to a_j along the original loop?
        # The text says "Insert_loop(ai, ..., aj)". This usually implies the chord 
        # itself or the path along the loop? 
        # In the context of subdivision, it splits the loop into two: 
        # one containing the "inside" and one the "outside" or simply splitting 
        # the polygon. The text says "Insert_loop((a1...ai, aj...ak), s)" and 
        # "Insert_loop(ai...aj), L)". 
        # Actually, looking at the loop structure: 
        # Original: a1, a2, ..., ai, ..., aj, ..., ak
        # Split into: 
        # 1. a1, ..., ai, aj, ..., ak (skipping the segment ai+1...aj-1)
        # 2. ai, ..., aj (the segment that was skipped)
        
        segment_chord = L[i-1:j-1] # a_i to a_j inclusive
        
        loops.append(new_loop_1)
        loops.append(segment_chord)
        
    # Step 5: Handle strict 26-adjacency
    if is_strict_26_adj(configuration) and alpha == 26:
        loops = build_special_loops_26_adj(loops)
        
    return loops

def is_chord_in_hull(p1, p2, hull):
    """
    Checks if the segment (p1, p2) lies within the convex hull.
    In the context of the algorithm, this determines if the chord 
    is "internal" to the configuration's geometry.
    """
    # Implementation detail: [G]
    # Typically involves checking if the midpoint or the segment 
    # intersects the interior of the hull. 
    # For a convex hull of voxel centers and face vertices, 
    # this often simplifies to checking if the chord does not 
    # cross the boundary defined by the hull edges.
    return segment_intersects_interior(p1, p2, hull)
```

**Edge Cases and Pitfalls:**
*   **Strict 26-Adjacency:** If the configuration exhibits strict 26-adjacency and $\alpha=26$, the standard loop subdivision must be replaced by `build_special_loops_26-adj`. Failure to do so results in topological errors [S1]. If $\alpha=18$, this case is handled by the standard subdivision [S1].
*   **Boundary Conditions:** The manifold guarantee holds provided the isosurface does not intersect the domain boundaries [S1]. Boundary voxels require special handling or padding to maintain the 8-cube structure [G].
*   **Precision:** The algorithm operates on discrete binary data, avoiding floating-point precision issues associated with trilinear interpolation [S1].

## Subtopics

### Asymptotic Decider
Uses the asymptotic decider to resolve ambiguous cases by analyzing the trilinear interpolant's critical points. Choose when continuous field accuracy is prioritized over strict topological guarantees from discrete connectivity [S1, 790-asymptotic-decider.md].

### Marching Cubes with Hermite Data and Full Case Table
Uses Hermite data (gradients) to resolve ambiguities. Choose when gradient information is available and higher geometric fidelity is needed [S1, 961-marching-cubes-with-hermite-data-and-full-case-table.md].

### Topologically Correct Marching Cubes
Resolves ambiguity by inserting additional vertices at cell centers. Choose when a manifold mesh is required but discrete connectivity constraints are not the primary focus [S1, 1368-topologically-correct-marching-cubes.md].

### Topologically Defined Isosurfaces
The broader family of methods using connectedness couples. This article details the specific implementation via connectedness couples with precomputed tables [S1, 1428-topologically-defined-isosurfaces.md].

### Extended Trilinear Triangulation
Analyzes the trilinear interpolant within the cell to determine connectivity. Choose when continuous field analysis is preferred [S1, 1618-extended-trilinear-triangulation.md].

### Topology/Normal Consistency Loss
A differentiable loss function for neural networks. Choose for learning-based surface extraction [S1, 4351-topology-normal-consistency-loss.md].

## Operating characteristics
*   **Time Complexity:** The standard Marching-Cubes algorithm is $O(n^3)$ where $n^3$ is the volume size. However, using surface tracking to build the complete graph $G_\lambda(I)$, the complexity is $O(s)$ where $s$ is the number of surfels (surface elements), which is typically $O(n^2)$ [S1].
*   **Memory Complexity:** Requires storage for the 256 local configuration tables (4 tables for the 4 valid couples). The size of each table depends on the maximum number of loops and vertices per configuration, which is constant and small [S1].
*   **Measured Performance:** Validated on medical images, specifically CT scans with resolutions such as $256 \times 256 \times 113$ [S1].
*   **Strengths:** Guarantees a topologically correct, closed, oriented 2-manifold without singularities or self-crossings. Compatible with classical Marching-Cubes optimizations [S1].
*   **Limitations:** Restricted to binary volumes. The choice of connectedness couple $(\alpha, \lambda)$ affects the surface topology and may not be suitable for all types of data [S1].

## Background
The method was introduced by [S1] as a topologically and formally proved approach for extracting consistent isosurfaces from volumetric images. It establishes the identity between the underlying graph of the isosurface and the surfel-adjacency graph of the digital surface. The algorithm has been implemented and validated with synthetic data and is used in the segmentation of medical images [S1].
