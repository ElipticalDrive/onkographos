# Face Culling Voxel Meshing

Also called: Adjacent Face Culling, Naive Voxel Meshing with Culling, Voxel Mesh Generation with Face Culling, Voxel Chunk Mesh Generation with Face Culling, Visible Block Faces

## Overview
Face Culling Voxel Meshing generates a static triangle mesh for a 3D voxel chunk by iterating through every voxel and emitting geometry only for faces adjacent to empty space (air) or the chunk boundary [S1, S7, S12, unofficial]. It solves the problem of excessive geometry and draw calls inherent in naive per-voxel meshing by culling internal faces shared between adjacent solid voxels [S1, S7, S10, unofficial]. Unlike [Greedy Meshing](3670-gpu-voxel-mesh-generation.md), which merges adjacent coplanar faces into larger rectangles to reduce triangle count, Face Culling generates exactly one quad (two triangles) per exposed face, resulting in a simpler, faster algorithm that produces a larger number of triangles [S2, S7, S10, unofficial]. It serves as the "oracle" or ground-truth reference for verifying the correctness of more complex merging algorithms [S10, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid (chunk) where each voxel has a state (e.g., material ID or solid/empty flag). The grid dimensions are typically $W \times H \times D$ (e.g., $32 \times 32 \times 32$ or $16 \times 64 \times 16$) [S5, S6, S11, unofficial].
*   **Output:** A list of quads (or a vertex/index buffer) representing the visible surface. Each quad corresponds to one exposed face of a solid voxel [S7, S12, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 3D array or hash map storing voxel states. In array-based implementations, the index for $(x, y, z)$ is often linearized as $x + y \cdot W + z \cdot W \cdot H$ or similar, depending on memory layout [S2, S6, unofficial].
*   **Quad Representation:** Each generated face is represented by its axis, direction, slice coordinate, position, dimensions, and material ID [S1, S12, unofficial]. A minimal quad struct includes:
    *   `axis`: The normal axis (0=X, 1=Y, 2=Z).
    *   `dir`: The direction sign (+1 or -1).
    *   `slice`: The integer coordinate along the axis where the face lies.
    *   `u, v`: The starting coordinates on the plane's local axes.
    *   `w, h`: The width and height of the face (always 1 for naive culling).
    *   `material`: The ID of the voxel material.
    [S1, S12, unofficial]

**Boundary Policy:**
The behavior at chunk edges is defined by a policy parameter [S1, S2, unofficial]:
*   **Air:** Treats out-of-bounds neighbors as empty (material 0). This exposes the chunk's outer surface, creating a visible boundary. If adjacent chunks both use "Air", double walls may appear at the seam [S1, unofficial].
*   **Solid:** Treats out-of-bounds neighbors as solid. This hides the chunk's outer surface, requiring the renderer to handle multiple chunks seamlessly without gaps or double geometry [S1, unofficial].

**Algorithm Steps:**
1.  Initialize an empty list for quads.
2.  Iterate through every voxel $(x, y, z)$ in the chunk grid [S9].
3.  If the current voxel is empty (state 0), skip to the next voxel [S1, unofficial][S9][S11, unofficial].
4.  For each of the 6 face directions (e.g., $\pm X, \pm Y, \pm Z$):
    a. Calculate the neighbor's coordinates $(nx, ny, nz)$ [S11, unofficial].
    b. Determine the neighbor's state:
        i. If $(nx, ny, nz)$ is outside the chunk bounds, apply the Boundary Policy (return 0 for Air, non-0 for Solid) [S6, unofficial].
        ii. If inside bounds, lookup the voxel state at $(nx, ny, nz)$ [S2, unofficial].
    c. If the neighbor is empty (state 0), the face is exposed [S1, unofficial]. Generate a quad for this face.
    d. If the neighbor is solid, the face is internal and is culled (not generated) [S1, S6, S11, unofficial].
5.  Return the list of generated quads.

**Pseudocode:**
```python
def face_culling_meshing(chunk_width, chunk_height, chunk_depth, get_voxel, boundary_policy="air"):
    """
    Generates a mesh for a voxel chunk using face culling.
    
    Args:
        chunk_width, chunk_height, chunk_depth: Dimensions of the chunk.
        get_voxel(x, y, z): Function returning the material ID of a voxel.
                           Returns 0 for empty/air.
        boundary_policy: "air" or "solid".
        
    Returns:
        A list of Quad objects.
    """
    quads = []
    
    # Define the 6 face directions: (axis_index, direction_sign, neighbor_offset_axis, neighbor_offset_sign)
    # axis_index: 0=X, 1=Y, 2=Z
    # direction_sign: +1 for positive axis face, -1 for negative axis face
    # neighbor_offset: how to get to the neighbor (e.g., +1 in X for +X face)
    faces = [
        (0, 1, 1, 0, 0),  # +X face: normal +X, neighbor at x+1
        (0, -1, -1, 0, 0), # -X face: normal -X, neighbor at x-1
        (1, 1, 0, 1, 0),  # +Y face: normal +Y, neighbor at y+1
        (1, -1, 0, -1, 0), # -Y face: normal -Y, neighbor at y-1
        (2, 1, 0, 0, 1),  # +Z face: normal +Z, neighbor at z+1
        (2, -1, 0, 0, -1)  # -Z face: normal -Z, neighbor at z-1
    ]
    
    for z in range(chunk_depth):
        for y in range(chunk_height):
            for x in range(chunk_width):
                # Step 3: Skip empty voxels
                current_material = get_voxel(x, y, z)
                if current_material == 0:
                    continue
                
                # Step 4: Check each of the 6 faces
                for axis, dir_sign, nx_off, ny_off, nz_off in faces:
                    # Calculate neighbor coordinates
                    nx = x + nx_off
                    ny = y + ny_off
                    nz = z + nz_off
                    
                    # Determine neighbor state
                    # Check bounds
                    if nx < 0 or nx >= chunk_width or \
                       ny < 0 or ny >= chunk_height or \
                       nz < 0 or nz >= chunk_depth:
                        # Apply boundary policy
                        if boundary_policy == "air":
                            neighbor_material = 0
                        else: # solid
                            neighbor_material = 1 # Non-zero implies solid
                    else:
                        neighbor_material = get_voxel(nx, ny, nz)
                    
                    # Step 4c: If neighbor is empty, generate face
                    if neighbor_material == 0:
                        # Determine slice coordinate and local u,v
                        # For axis 0 (X), slice is x (for -X) or x+1 (for +X)
                        # Local axes u, v are the other two dimensions
                        if axis == 0:
                            slice_coord = x if dir_sign == -1 else x + 1
                            u, v = y, z
                        elif axis == 1:
                            slice_coord = y if dir_sign == -1 else y + 1
                            u, v = z, x
                        else: # axis == 2
                            slice_coord = z if dir_sign == -1 else z + 1
                            u, v = x, y
                            
                        quads.append({
                            "axis": axis,
                            "dir": dir_sign,
                            "slice": slice_coord,
                            "u": u,
                            "v": v,
                            "w": 1,
                            "h": 1,
                            "material": current_material
                        })
                        
    return quads
```

**Edge Cases and Pitfalls:**
*   **Precision:** Integer coordinates are used for slice and position, avoiding floating-point errors in face placement [S1, unofficial].
*   **Boundaries:** Incorrect handling of out-of-bounds checks leads to crashes or incorrect culling. The boundary policy must be consistent across adjacent chunks to avoid gaps or double geometry [S1, S6, unofficial].
*   **Translucency:** The basic algorithm assumes opaque voxels. If translucent blocks (e.g., water, glass) are present, the culling logic must be extended to check if the neighbor is opaque vs. translucent, as translucent faces may need to be rendered even if adjacent to another translucent block [S7, S10, unofficial].

## Subtopics

### [Culled Voxel Meshing](2392-culled-voxel-meshing.md)
Culled Voxel Meshing is a surface extraction method that generates a single mesh for a voxel chunk by omitting faces shared between adjacent solid voxels. It solves the problem of excessive geometry and draw calls inherent in naive per-voxel meshing by merging adjacent voxels into one large mesh. It is distinguished from its parent [Face Culling Voxel Meshing](2268-face-culling-voxel-meshing.md) by its explicit handling of chunk boundaries via a `BoundaryPolicy` parameter, and from [Greedy Meshing](3670-gpu-voxel-mesh-generation.md) by its lack of face merging (it produces more polygons but is simpler and faster).

### [GPU Voxel Mesh Generation](3670-gpu-voxel-mesh-generation.md)
GPU Voxel Mesh Generation is a technique to generate a static triangle mesh from a 3D voxel grid entirely on the GPU, avoiding CPU readback. It identifies exposed faces of active voxels and generates geometry for each face using a multi-pass compute shader pipeline. Unlike CPU-based meshing, which is significantly slower (e.g., 5 FPS vs >1000 FPS for generation alone), this method leverages parallel processing to achieve high performance. It builds on [Voxel Mesh Generation with Face Culling](2411-voxel-mesh-generation-with-face-culling.md) by implementing the face culling logic within a GPU compute shader environment using indirect drawing.

### [Face Visibility Check](3701-face-visibility-check.md)
Face Visibility Check determines whether a specific voxel face needs to be meshed based on its own visibility state, the neighbor's visibility state, and whether the voxel has already been processed. It solves the problem of redundant geometry generation by culling hidden faces between two opaque full cubes. Unlike complex partial-shape culling which checks area coverage, this method relies on boolean opacity states to decide if a face is visible.

### [Voxel Visibility Map Computation](4046-voxel-visibility-map-computation.md)
Voxel Visibility Map Computation is a preprocessing step in voxel meshing that determines which faces of solid voxels are exposed to empty space or the chunk boundary, producing a 3D map of visible face flags. It differs from sibling methods by explicitly computing a per-voxel bitmask of visible faces rather than generating mesh primitives directly; [Culled Voxel Meshing](2392-culled-voxel-meshing.md) and [GPU Voxel Mesh Generation](3670-gpu-voxel-mesh-generation.md) may integrate this map or perform visibility checks inline, while [Face Visibility Check](3701-face-visibility-check.md) describes the atomic predicate used within this algorithm.

### Quad Data Structure
Represents a merged rectangular face with axis, direction, slice, position, dimensions, and material [S1, unofficial]. The interface includes fields: `axis` (0|1|2), `dir` (1|-1), `slice` (number), `u` (number), `w` (number), `v` (number), `h` (number), and `material` (number) [S1, unofficial]. The local axes $u$ and $v$ are derived from the normal axis: $u = (axis + 1) \pmod 3$, $v = (axis + 2) \pmod 3$ [S1, unofficial]. This ordering ensures the cross product $\hat{u} \times \hat{v}$ aligns with the normal direction [S1, unofficial].

### Validator Expected Faces Generation
A method to generate expected faces for validation purposes [S14, unofficial]. It iterates through all voxels, checks neighbors, and computes face tokens (axis, positive/negative, depth, u, v, material) for each exposed face [S13, unofficial]. The resulting list is sorted to allow comparison with the actual mesh output [S13, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels in the chunk. Each voxel is visited once, and 6 neighbor checks are performed [S1, unofficial].
*   **Memory Complexity:** $O(F)$, where $F$ is the number of exposed faces [G]. In the worst case (all voxels isolated), $F \approx 6N$ [G]. In typical terrain, $F \ll 6N$ but still proportional to the surface area [S7, unofficial].
*   **Performance:** On a single core of a 2.5 GHz Intel Core i7, the algorithm can generate approximately 40 million quads per second [S7, unofficial][S8, unofficial]. It is significantly faster than greedy meshing, which takes about 3 times longer to produce a mesh with 1/3 of the quads [S7, unofficial][S8, unofficial].
*   **Strengths:** Simplicity of implementation, high speed, deterministic output, serves as a correct reference for testing [S7, S10, unofficial].
*   **Limitations:** Generates more triangles than greedy meshing, leading to higher GPU draw call overhead and vertex buffer size [S7, S10, unofficial]. Does not merge coplanar faces [S10, unofficial].
*   **When to use:** When mesh generation speed is critical, or as a baseline for testing more complex meshing algorithms [S7, S10, unofficial].
*   **When not to use:** When minimizing triangle count and draw calls is more important than generation speed, such as in large-scale open worlds with limited GPU bandwidth [S7, S10, unofficial].

## Background
Face Culling Voxel Meshing is a fundamental technique in voxel-based game development. It was originally described in early Minecraft source code analysis and tutorials, where it was used to generate chunk meshes by iterating over blocks and checking for adjacent air blocks [S3, S6, S11, unofficial]. The method is often referred to as "naive" meshing because it does not perform any face merging, distinguishing it from later optimizations like greedy meshing [S7, S10, unofficial]. It is widely used in educational contexts and as a reference implementation for more advanced voxel rendering techniques [S10, unofficial].
