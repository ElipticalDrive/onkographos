# Visible Block Faces

Also called: Mesh Culled, optimizeVoxels, simple meshing

## Overview
Visible Block Faces is a voxel surface extraction method that generates a single quad for every visible face of a voxel block, culling faces where the neighbor is solid [S1, S3, unofficial][S4]. It solves the problem of redundant geometry generation by removing hidden faces between adjacent opaque full cubes [S2, unofficial]. Unlike [Greedy Meshing](3674-gpu-marching-cubes-face-based.md), which merges adjacent coplanar faces into larger rectangles, Visible Block Faces produces suboptimal but quickly generated meshes with minimal computational overhead [S3, unofficial][S4]. It builds on [Voxel Chunk Meshing with Culling](2523-voxel-chunk-meshing-with-culling.md) by implementing the culling logic directly during mesh generation rather than as a post-processing step [G].

## How it works
**Inputs:** A 3D voxel grid (array or hash map) storing voxel states (e.g., material ID or color), grid dimensions ($W \times H \times D$), and a boundary policy ("air" or "solid") [S1, S2, unofficial].
**Outputs:** A list of quads, where each quad represents a single visible unit face [S3, unofficial].

**Data Structures:**
*   **Voxel State:** An integer or enum representing the material. $0$ typically denotes empty/air [S1, S2, unofficial].
*   **Quad:** A structure containing:
    *   `axis`: The normal axis ($0, 1, 2$ for X, Y, Z) [S1, unofficial].
    *   `dir`: The direction of the normal ($1$ for positive, $-1$ for negative) [S1, unofficial].
    *   `slice`: The integer coordinate of the plane the face sits on along the axis [S1, unofficial].
    *   `u, v`: The starting coordinates of the quad on the two perpendicular axes [S1, unofficial].
    *   `w, h`: The width and height of the quad (always $1$ for this method) [S1, unofficial].
    *   `material`: The material ID of the face [S1, unofficial].
*   **Axis Constants:**
    *   `AXES = [0, 1, 2]`
    *   `AXIS_U = [1, 2, 0]` ($u = (axis + 1) \pmod 3$) [S1, unofficial].
    *   `AXIS_V = [2, 0, 1]` [S1, unofficial].

**Algorithm Steps:**
1.  Initialize an empty list `quads`.
2.  Determine `outsideIsSolid` based on the boundary policy: `true` if "solid", `false` if "air" [S1, unofficial].
3.  Iterate through every voxel position $(x, y, z)$ in the grid bounds ($0 \le x < W, 0 \le y < H, 0 \le z < D$) [S1, unofficial].
4.  Get the material of the current voxel: `mat = chunk.get(x, y, z)` [S1, unofficial].
5.  If `mat == 0` (empty), continue to the next voxel [S1, unofficial].
6.  For each `axis` in `AXES` (0, 1, 2) [S1, unofficial]:
    a.  Calculate `u = AXIS_U[axis]` and `v = AXIS_V[axis]` [S1, unofficial].
    b.  For each `dir` in $[1, -1]$ [S1, unofficial]:
        i.  Calculate neighbor position: $n_x = x, n_y = y, n_z = z$; then $n_{axis} += dir$ [S1, unofficial].
        ii. Check if neighbor is outside chunk bounds: `outside = (n_axis < 0 || n_axis >= size[axis])` [S1, unofficial].
        iii. Determine neighbor material:
            *   If `outside`: `neighbor_mat = (outsideIsSolid ? 1 : 0)` [S1, unofficial].
            *   Else: `neighbor_mat = chunk.get(n_x, n_y, n_z)` [S1, unofficial].
        iv. If `neighbor_mat != 0` (neighbor is solid/opaque), the face is hidden; `continue` to the next direction [S1, unofficial].
        v.  Calculate `slice`:
            *   If `dir == 1`: `slice = p[axis] + 1`
            *   If `dir == -1`: `slice = p[axis]` [S1, unofficial].
        vi. Create a quad: `makeQuad(axis, dir, slice, p[u], p[v], 1, 1, mat)` [S1, unofficial].
        vii. Add the quad to `quads` [S1, unofficial].

**Pseudocode:**
```python
def visible_block_faces(chunk, width, height, depth, boundary_policy="air"):
    quads = []
    outside_is_solid = (boundary_policy == "solid")
    
    # Helper to get voxel material, handling bounds
    def get_voxel(x, y, z):
        if x < 0 or x >= width or y < 0 or y >= height or z < 0 or z >= depth:
            return 1 if outside_is_solid else 0
        return chunk.get(x, y, z)

    for z in range(depth):
        for y in range(height):
            for x in range(width):
                material = get_voxel(x, y, z)
                if material == 0:
                    continue
                
                # Axis 0 (X), 1 (Y), 2 (Z)
                for axis in [0, 1, 2]:
                    u = (axis + 1) % 3
                    v = (axis + 2) % 3
                    
                    for dir in [1, -1]:
                        # Neighbor coordinates
                        nx, ny, nz = x, y, z
                        if axis == 0: nx += dir
                        elif axis == 1: ny += dir
                        else: nz += dir
                        
                        # Check bounds and get neighbor material
                        if nx < 0 or nx >= width or ny < 0 or ny >= height or nz < 0 or nz >= depth:
                            neighbor_mat = 1 if outside_is_solid else 0
                        else:
                            neighbor_mat = chunk.get(nx, ny, nz)
                        
                        # Cull if neighbor is solid
                        if neighbor_mat != 0:
                            continue
                        
                        # Determine slice plane
                        if dir == 1:
                            slice_val = (x if axis == 0 else y if axis == 1 else z) + 1
                        else:
                            slice_val = (x if axis == 0 else y if axis == 1 else z)
                        
                        # Create quad
                        # u_start is x if u==0 else y if u==1 else z
                        # v_start is x if v==0 else y if v==1 else z
                        u_start = x if u == 0 else y if u == 1 else z
                        v_start = x if v == 0 else y if v == 1 else z
                        
                        quads.append({
                            "axis": axis,
                            "dir": dir,
                            "slice": slice_val,
                            "u": u_start,
                            "v": v_start,
                            "w": 1,
                            "h": 1,
                            "material": material
                        })
    return quads
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The behavior of faces on the chunk boundary depends on the `boundary_policy`. "Air" treats the outside as empty, emitting an outer surface (which can cause double walls if chunks are adjacent). "Solid" treats the outside as solid, hiding the outer surface [S1, unofficial].
*   **Precision:** Integer coordinates are used for slices and positions, avoiding floating-point errors in face placement [S1, unofficial].
*   **Degenerate Input:** Empty chunks produce no quads [S1, unofficial]. Fully solid chunks produce no quads under "solid" policy, or $6 \times W \times H \times D$ quads under "air" policy (if all voxels are solid) [S1, unofficial].

## Subtopics

### [Face Visibility Check](3701-face-visibility-check.md)
Face Visibility Check determines whether a specific voxel face needs to be meshed based on its own visibility state, the neighbor's visibility state, and whether the face has already been processed. It solves the problem of redundant geometry generation by culling hidden faces between two opaque full cubes. Unlike complex partial-shape culling which checks area coverage, this method relies on boolean opacity states to decide if a face is visible.

### Quad Data Structure
Represents a merged rectangular face with axis, direction, slice, position, dimensions, and material [S1, unofficial]. It is the output format for naive, culled, and greedy meshing, allowing comparison of the generated geometry sets [S1, unofficial]. The `makeQuad` function returns an object with fields: `axis` (0|1|2), `dir` (1|-1), `slice` (number), `u` (number), `w` (number), `v` (number), `h` (number), `material` (number) [S1, unofficial]. The triangle indices for a quad depend on `dir`: if `dir=1`, indices are `[0,1,2,0,2,3]`; if `dir=-1`, indices are `[0,3,2,0,2,1]` [S1, unofficial]. The axes `u` and `v` are derived from `axis` using `AXIS_U = [1, 2, 0]` and `AXIS_V = [2, 0, 1]`, ensuring the cross product $\hat{u} \times \hat{v}$ points in the `axis` direction [S1, unofficial].

### Culled Voxel Meshing
This variant omits faces that are adjacent to another solid voxel [S1, unofficial]. It generates geometry for voxels but culls faces based on a boundary policy (`"air"` or `"solid"`) [S1, unofficial]. On a solid $32^3$ cube, it produces 6,144 quads [S1, unofficial]. On a $32^3$ terrain chunk with 17,191 solid voxels, it produces 6,654 quads, 26,616 vertices, and 13,308 triangles [S1, unofficial]. It reduces geometry compared to naive meshing (6,654 vs 103,146 quads) but produces more than greedy meshing (6,654 vs 2,416 quads) on the same terrain chunk [S1, unofficial]. Performance on an Apple M2 Pro is approximately 2.06 ms median time for the terrain chunk [S1, unofficial].

### Validator Expected Faces Generation
Used to verify meshing correctness by generating a sorted list of expected face tokens. It iterates through every voxel, checks all 6 directions for empty neighbors, and constructs a 64-bit token encoding axis, direction, depth, u, v, and material [S5, unofficial]. The tokens are sorted and returned to allow exact set-equality comparisons against the mesher's output [S5, unofficial].

## Operating characteristics
**Time Complexity:** $O(N)$, where $N$ is the number of voxels in the chunk. Each voxel is visited once, and for each solid voxel, 6 neighbor checks are performed [S1, S3, unofficial].
**Memory Complexity:** $O(F)$, where $F$ is the number of visible faces. The output buffer stores one quad per visible face [S3, unofficial].
**Performance:** Visible Block Faces is very fast, generating about 40 million quads per second on a single core of a 2.5 GHz Intel Core i7 [S3, unofficial][S4]. It is significantly faster than Greedy Meshing, which takes about 3 times longer to produce a more optimal mesh with 1/3 of the quads [S3, unofficial][S4].
**Strengths:** Simplicity, speed, and deterministic output [S3, unofficial][S4]. It is suitable for real-time applications where mesh generation speed is critical and mesh size is less of a concern [S3, unofficial][S4].
**Limitations:** Produces suboptimal meshes with many more triangles than Greedy Meshing. It does not merge adjacent coplanar faces, leading to higher vertex and index counts [S3, unofficial][S4].

## Background
Visible Block Faces is a fast algorithm for generating voxel block meshes, introduced as part of the `block_mesh` Rust crate [S3, unofficial][S4]. It is designed to be a simple, high-performance alternative to Greedy Meshing [S3, unofficial]. The method is also referenced in TypeScript implementations of voxel greedy meshing, where it is compared against Naive and Greedy meshers [S1, unofficial]. A C++ implementation using bitmasks and BFS was also documented [S2, unofficial].
