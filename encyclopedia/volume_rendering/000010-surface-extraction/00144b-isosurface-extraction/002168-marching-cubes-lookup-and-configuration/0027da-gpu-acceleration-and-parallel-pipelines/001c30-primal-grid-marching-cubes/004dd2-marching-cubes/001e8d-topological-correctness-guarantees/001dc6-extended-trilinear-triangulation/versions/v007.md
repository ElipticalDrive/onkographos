# Extended Trilinear Triangulation

Also called: Extended MC33, Extended Marching Cubes 33, Extended triangulation to the Marching Cubes 33 algorithm

## Overview
Extended Trilinear Triangulation is a topologically correct isosurface extraction method that resolves the ambiguities of the standard Marching Cubes algorithm by introducing a three-state vertex classification ("+", "-", "=") and analyzing the connectivity of these states within the trilinear interpolant [S1]. It solves the problem of degenerate triangles and topological errors (such as incorrect Betti numbers) in ambiguous cases by constructing triangulations based on the convex hulls of vertex groups and interior connectivity tests [S1]. Unlike the standard 15-case lookup table, it extends the Marching Cubes 33 topology to handle the "=" label, ensuring a 2-manifold mesh that correctly represents the continuous field's topology while avoiding degenerate geometry [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field $f$ sampled on a rectilinear grid $H$, an isovalue $\alpha$, and a unit cube defined by 8 vertices $v_0, \dots, v_7$.
*   **Output:** A triangular mesh approximating the isosurface $\bar{S}_\alpha = \{x \in \mathbb{R}^3 | g(x) = \alpha\}$ within the cube.

**Data Structures:**
*   **Vertex Labels:** Each vertex $v_i$ is assigned a label $L(v_i) \in \{+, -, =\}$.
*   **Groups:**
    *   **Group of Vertices (GV):** A set of vertices with the same label (positive or negative) connected by a path of that same label along the cube's edges or faces.
    *   **Group of Edges (GE):** A set of edges intersected by the isosurface that are incident to vertices in the same GV.
*   **Face Tracking:** A boolean flag or set tracking which cube faces have already been triangulated to prevent duplicates between adjacent cubes.

**Formulas:**
The trilinear interpolant $g(x,y,z)$ within a unit cube is:
$$
\begin{aligned}
g(x,y,z) &= (1-x)(1-y)(1-z)f(v_0) + (1-x)(1-y)zf(v_4) \\
&\quad + (1-x)y(1-z)f(v_3) + (1-x)yzf(v_7) \\
&\quad + x(1-y)(1-z)f(v_1) + x(1-y)zf(v_5) \\
&\quad + xy(1-z)f(v_2) + xyzf(v_6)
\end{aligned}
$$
where $v_0$ is at $(0,0,0)$, $v_1$ at $(1,0,0)$, $v_2$ at $(1,1,0)$, $v_3$ at $(0,1,0)$, $v_4$ at $(0,0,1)$, $v_5$ at $(1,0,1)$, $v_6$ at $(1,1,1)$, and $v_7$ at $(0,1,1)$ [S1].

**Steps:**

1.  **Classify Vertices:** For each vertex $v_i$ of the cube:
    *   If $f(v_i) > \alpha$, label $L(v_i) = +$.
    *   If $f(v_i) < \alpha$, label $L(v_i) = -$.
    *   If $f(v_i) = \alpha$, label $L(v_i) = =$ [S1].

2.  **Classify Cube Polarity:**
    *   Count $N_{=+}$, the number of vertices labeled "=" or "+".
    *   If $N_{=+} \le 4$, the cube is **Positive**.
    *   Otherwise, the cube is **Negative** [S1].

3.  **Identify Groups:**
    *   **Positive Cube:** Identify **Groups of Vertices (GV)** consisting of "+" vertices connected by "+" paths on edges/faces. Identify **Groups of Edges (GE)** incident to each GV.
    *   **Negative Cube:** Identify **Groups of Vertices (GV)** consisting of "-" vertices connected by "-" paths on edges/faces. Identify **Groups of Edges (GE)** incident to each GV.
    *   Note: Vertices labeled "=" are treated as part of the "+" group in a Positive cube and "-" group in a Negative cube for connectivity purposes, but their specific handling depends on the triangulation type [S1].

4.  **Interior Test:** Determine if groups of vertices are separated or joined inside the cube using the interior test (Chernyaev/Custodio) [S1]. Classify the cube into one of three categories:
    *   **Simple Leaf:** Groups are separated.
    *   **Tunnel:** Groups are joined.
    *   **Interior Point:** Complex topology (e.g., Case 13 subcases).

5.  **Generate Triangulation:** Based on the category and specific case (e.g., Case 13 subcases), apply one of the following methods:

    *   **Simple Leaves Triangulation:**
        *   For each group $i$, let $G_i = GV_i \cup GE_i$.
        *   Let $W_i$ be the set of intersection points (midpoints of edges in $G_i$) and vertices in $GV_i$ labeled "=" or "+".
        *   Construct the convex hull $C_i = \text{conv}(W_i)$.
        *   If $C_i$ is 3D, triangulate the boundary $\partial C_i$. Remove triangles lying on the cube faces.
        *   If $C_i$ is 2D (contained in faces), return the triangulation of $C_i$.
        *   **Exception:** If all cube vertices are "=", no triangulation is generated to avoid duplicates [S1].

    *   **Tunnel Triangulation:**
        *   Let $W$ be the set of midpoints of all intersected edges.
        *   Construct $C = \text{conv}(W)$.
        *   If $C$ is 3D, triangulate $\partial C$.
        *   Remove triangles where all three vertices belong to the same Group of Edges $GE_i$ [S1].

    *   **Interior Point Leaves Triangulation:**
        *   Used for complex cases (e.g., Case 13).
        *   If a face has all four edges intersected, connect pairs of edges based on bilinear interpolant behavior to form a polygonal curve.
        *   Add a vertex at the cube center.
        *   Form triangles connecting the center vertex to the segments of the polygonal curve [S1].

    *   **Case 13 Specifics:**
        *   **13.3:** One group of 4 positive vertices. Use the incident negative vertex. Apply Interior Point Leaves combined with Simple Leaves on the single negative vertex group [S1].
        *   **13.5.1:** Two groups of vertices. Apply Simple Leaves to both groups [S1].
        *   **13.5.2:** Two groups connected by interior, with signal change diagonally opposite to one vertex group. Apply Tunnel triangulation combined with Simple Leaves in the region diagonally opposite to the one vertex positive group [S1].

6.  **Face Deduplication:** Track grid faces already triangulated. If a triangle lies on a cube face, check if the adjacent cube has already processed it. If so, skip [S1].

**Edge Cases and Pitfalls:**
*   **Degenerate Triangles:** Standard MC creates degenerate triangles when $f(v_i) = \alpha$ because the vertex is treated as positive, causing three intersected edges meeting at the same point. The "=" label prevents this by explicitly handling the zero case [S1].
*   **Skinny Triangles:** Occur when two vertices are close to a grid vertex and the third is far. The convex hull approach helps mitigate this by distributing vertices more evenly [S1].
*   **Duplicate Faces:** If all vertices are "=", no triangulation is generated. Additionally, face tracking prevents adjacent cubes from triangulating the same face [S1].
*   **Topology Ambiguity:** Cases 6.1.1 and 6.1.2 have identical vertex/edge groups but different interpolant topology. The interior test is required to distinguish them [S1].

## Operating characteristics
*   **Time Complexity:** Higher than standard Marching Cubes due to the interior test and convex hull construction per ambiguous cell. The interior test is $O(1)$ but involves evaluating the trilinear interpolant at specific points. Convex hull construction is $O(N \log N)$ where $N$ is the number of points in the group (typically small, $\le 8$).
*   **Memory Complexity:** $O(1)$ per cell for local data structures. Global face tracking requires $O(F)$ memory where $F$ is the number of faces in the grid.
*   **Performance:** Produces topologically correct meshes with correct Betti numbers, unlike Raman and Wenger's method which fails for ambiguous configurations like Case 10 [S1]. In a 5x5x5 test, it produced correct Betti numbers (1, 0, 1) compared to Raman and Wenger's (4, 0, 4) [S1].
*   **Strengths:** Handles the "=" label to avoid degenerate triangles; extends Marching Cubes 33 to cover all 33 topological cases; produces high-quality triangles.
*   **Limitations:** More complex implementation than standard MC; requires careful handling of face deduplication; interior test adds computational overhead.

## Background
*   **Origin:** The base Marching Cubes algorithm was proposed by Lorensen and Cline in 1987 [S1]. Marching Cubes 33 was proposed by Chernyaev in 1995 to address topological ambiguities [S1]. The extended lookup table concept was introduced by Raman and Wenger in 2008, but their method only covered 23 of 33 cases [S1]. Extended Trilinear Triangulation extends the topologically correct Marching Cubes 33 table to handle the "=" label, preserving topology while avoiding degenerate triangles [S1].
*   **History:** The method was developed to address the lingering problems of triangle quality and topology correctness in Marching Cubes. It builds on the work of Montani et al. (1994) and Chernyaev (1995), improving upon Raman and Wenger's (2008) extended lookup table by covering all 33 cases [S1].
