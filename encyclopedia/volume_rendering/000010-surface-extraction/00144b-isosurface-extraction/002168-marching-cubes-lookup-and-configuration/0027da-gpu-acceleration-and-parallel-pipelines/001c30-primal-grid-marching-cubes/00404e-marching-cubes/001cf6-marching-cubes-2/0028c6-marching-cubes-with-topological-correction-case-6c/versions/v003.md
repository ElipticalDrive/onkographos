# Marching Cubes with Topological Correction (Case 6c)

Also called: Case 6c, MC with alternate facetization

## Overview
Marching Cubes with Topological Correction (Case 6c) is a variant of the Marching Cubes algorithm that resolves topological inconsistencies (holes) in the extracted isosurface by applying an alternate facetization for specific cube configurations [S1, unofficial]. It specifically addresses the topological error that occurs when a Case 3 cube is adjacent to a Case 6 cube [S1, unofficial]. It differs from standard Marching Cubes by detecting this specific adjacency and swapping the triangle connectivity for the Case 6 cube, and differs from [Marching Cubes 2](1393-marching-cubes-2.md) by focusing on this specific topological correction rather than a general lookup table reimplementation [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A 3D scalar field defined on a Cartesian grid [S1, unofficial].
*   An isovalue (scalar threshold) for surface extraction [S1, unofficial].
*   A numerical tolerance for precision handling ($10^{-5}$) [S1, unofficial].

**Outputs:**
*   A set of triangular facets representing the isosurface [S1, unofficial].
*   In the cited implementation, these are encoded in KML format for visualization in Google Earth [S1, unofficial].

### Data Structures
**Vertex Encoding:**
The state of the 8 vertices of a cube is encoded as an 8-bit integer [S1, unofficial]. Each bit corresponds to a vertex, indicating whether it is above (1) or below (0) the isosurface [S1, unofficial]. The vertex indices are ordered $v_0$ to $v_7$ [S1, unofficial].

**Edge Encoding:**
The state of the 12 edges of a cube is encoded as a 12-bit integer [S1, unofficial]. Each bit indicates if the edge is intersected by the isosurface [S1, unofficial]. This 12-bit value is represented as three hexadecimal values for lookup purposes [S1, unofficial].

**Edge Table:**
A lookup table where the index is the 8-bit vertex state and the value is the 12-bit edge state (encoded as hex) [S1, unofficial]. This table determines which edges are intersected for a given vertex configuration [S1, unofficial].

### Steps
1.  **Grid Traversal:** Iterate through each cube in the 3D grid [S1, unofficial].
2.  **Vertex Classification:** Determine the state of each of the 8 vertices of the current cube relative to the isovalue. Construct the 8-bit vertex index [S1, unofficial].
3.  **Edge Intersection Lookup:** Use the vertex index to look up the 12-bit edge state in the Edge Table. Identify which edges are intersected by the isosurface [S1, unofficial].
4.  **Intersection Point Calculation:** For each intersected edge, calculate the exact point where the isosurface crosses the edge using linear interpolation [S1, unofficial].
5.  **Topological Correction Check:**
    *   Identify if the current cube is a Case 6 configuration [S1, unofficial].
    *   Check if any adjacent cube is a Case 3 configuration [S1, unofficial].
    *   If a Case 6 cube is adjacent to a Case 3 cube, determine if the default facetization results in a topological inconsistency (a hole) [S1, unofficial].
    *   **Condition for Inconsistency:** The inconsistency occurs for specific vertex configurations within the Case 6 cube. If the default facetization is used, a hole is created [S1, unofficial].
    *   **Condition for Consistency:** If the lower right corner on the back face of the Case 6 cube is above the surface AND the upper right corner on the front face of the same cube is below the surface, the default facetization is topologically consistent, and no correction is needed [S1, unofficial].
    *   If an inconsistency is detected, use the alternate facetization for Case 6 (Case 6c) [S1, unofficial].
6.  **Triangle Generation:** Generate triangles based on the intersected edges [S1, unofficial]. If using Case 6c, use the alternate connectivity pattern [S1, unofficial]. The implementation supports up to 5 facets per cube (following Bourke, 1994), unlike the original Lorensen and Cline (1987) limit of 4 [S1, unofficial].
7.  **Vertex Ordering:** Determine the winding order of the triangle vertices. This depends on whether the "marked vertex" (the vertex used to distinguish between topologically equivalent cases) is above or below the isosurface [S1, unofficial].
8.  **Output:** Output the generated triangles [S1, unofficial].

### Formulas
**Linear Interpolation for Scalar Value:**
The scalar value $s$ at a point $(x,y,z)$ along an edge between vertex $v_0$ (value $s_{v0}$) and vertex $v_1$ (value $s_{v1}$) is given by:
$$ s(x, y, z) = \frac{s_{v1} - s_{v0}}{x_{v1} - x_{v0}} (x - x_{v0}) + s_{v0} $$
This derivation assumes the edge is aligned with the x-axis, but the principle applies to any edge [S1, unofficial].

**Intersection Point Coordinates:**
To find the intersection point $t_0$ on an edge between $v_0$ and $v_1$ for a given isovalue $s$, solve for the coordinates [S1, unofficial]. The x-coordinate is:
$$ x_{t0} = \frac{(s - s_{v0})(x_{v1} - x_{v0})}{s_{v1} - s_{v0}} + x_{v0} $$
The general intersection point coordinates $(x_{t0}, y_{t0}, z_{t0})$ are:
$$ x_{t0} = \frac{(s - s_{v0})(x_{v1} - x_{v0})}{s_{v1} - s_{v0}} + x_{v0} $$
$$ y_{t0} = \frac{(s - s_{v0})(y_{v1} - y_{v0})}{s_{v1} - s_{v0}} + y_{v0} $$
$$ z_{t0} = \frac{(s - s_{v0})(z_{v1} - z_{v0})}{s_{v1} - s_{v0}} + z_{v0} $$

### Parameters
*   **Isosurface threshold value (isovalue):** The scalar value at which the isosurface is extracted. Input by the user [S1, unofficial].
*   **Numerical tolerance:** $10^{-5}$. Used to determine if an intersection is effectively at a vertex to avoid division by zero or precision errors [S1, unofficial].

### Edge Cases and Pitfalls
*   **Numerical Stability:** If $|s - s_{v0}| < 10^{-5}$ OR $|s_{v1} - s_{v0}| < 10^{-5}$, the intersection point is assigned to the vertex coordinates $(x_{v0}, y_{v0}, z_{v0})$ to avoid division by zero or precision errors [S1, unofficial].
*   **Topological Inconsistency Scope:** Topological inconsistency does not occur for all Case 3/Case 6 combinations. It only occurs for specific vertex configurations within the Case 6 cube. If the lower right corner on the back face of the Case 6 cube is above the surface AND the upper right corner on the front face of the same cube is below the surface, the default facetization is topologically consistent [S1, unofficial].

## Background
The method was implemented in Fortran90 and visualized in Google Earth via KML files for microscale meteorological model isosurface display [S1, unofficial]. It adopts and implements a revised method discussed and made available by Bourke (1994), which supports up to 5 facets per cube, whereas the original Lorensen and Cline (1987) exposition limited the number of facets to 4 [S1, unofficial].
