## Subtopics

### Extended Trilinear Triangulation
A method to generate a topologically correct, degenerate-free triangulation of the isosurface within a cube by tracking the connectivity of vertices and edges via positive/negative regions defined by the trilinear interpolant, using convex hulls of intersection points [G]. Choose this when a geometric convex-hull approach is preferred over analytical case enumeration [G]. [Link](1618-extended-trilinear-triangulation.md)

### Marching Cubes (15-case)
The original method using a 15-entry lookup table [S1, unofficial]. It fails to resolve face and internal ambiguities, leading to topological errors [S1, unofficial]. Choose this only for legacy compatibility or when topological correctness is not required [G]. [Link](1617-marching-cubes.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of cells, as each cell is processed independently [S1, unofficial]. The constant factor is higher than standard Marching Cubes due to the additional arithmetic for resolving ambiguities (multiplications, comparisons, and potentially quadratic root checks) [S1, unofficial].
*   **Memory Complexity:** $O(1)$ per cell for the lookup table (33 entries) [S1, unofficial]. No global data structures are required [S1, unofficial].
*   **Measured Performance:** Implemented in the HIGZ graphics package [S1, unofficial].
*   **Strengths:** Guarantees topological correctness for the trilinear interpolant [S1, unofficial]. Resolves holes that appear in standard Marching Cubes when adjacent cells have complementary ambiguous configurations (e.g., Config 6 sharing a face with Complement of Config 3) [S1, unofficial].
*   **Limitations:** The lookup table is larger (33 vs 15) [S1, unofficial]. Some cases require an additional internal vertex, which can complicate mesh post-processing (e.g., smoothing) as it introduces a vertex not on the grid edges [S1, unofficial].
*   **When to use:** When topological fidelity is critical and the scalar field is interpolated trilinearly [S1, unofficial].
*   **When not to use:** If performance is the sole constraint and approximate topology is acceptable, or if the scalar field uses a different interpolation scheme (e.g., linear in each dimension but not bilinear on faces) [S1, unofficial].

## Background
The method was introduced to address the limitations of the original Marching Cubes algorithm by Lorensen and Cline (1987) [S1, unofficial]. It was implemented in the HIGZ graphics package [S1, unofficial]. The work addresses the topological discrepancies arising from the 15-case lookup table by expanding the configuration set to 33 topologically distinct patterns permitted by the trilinear function [S1, unofficial].
