# GPU Marching Cubes with Lookup Tables

Also called: Compute Shader Marching Cubes, GPU Marching Cubes with Fixed-Size Buffer, MC GPU, Marching Cubes GPU Implementation, Marching Cubes GPU Mesh Reconstruction

## Overview
GPU Marching Cubes with Lookup Tables is a surface extraction technique that generates a triangle mesh from a 3D scalar field (voxels) entirely on the GPU using compute shaders [S2, S3, unofficial]. It differs from CPU implementations by offloading voxel processing and triangle generation to the GPU, and from other GPU variants by using pre-computed lookup tables stored in textures or structured buffers to determine edge intersections and triangle configurations [S1, S2, unofficial]. It builds on [Primal Grid Marching Cubes](1211-primal-grid-marching-cubes.md) by operating on a primal grid where cubes are formed by adjacent sample points [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field (voxels) of dimensions $W \times H \times D$ (typically $N \times N \times N$), an isovalue threshold ($\text{Target}$), and pre-computed lookup tables for edge intersections and triangle configurations [S2, S3, unofficial].
*   **Output:** A fixed-size buffer containing vertex data (position and normal) for the generated mesh [S2, unofficial].

**Data Structures:**
1.  **Voxel Buffer (`_Voxels`):** A structured buffer or `Texture3D` storing scalar values, accessed via linear index $idx = x + y \cdot W + z \cdot W \cdot H$ [S2, unofficial].
2.  **Normals Buffer (`_Normals`):** A `Texture3D` (e.g., `ARGBHalf`) storing pre-computed gradients/normals for each voxel [S2, unofficial].
3.  **Edge Table (`_CubeEdgeFlags`):** A lookup table mapping the 8-bit vertex flag index (0-255) to a 12-bit edge intersection mask [S2, unofficial]. Stored in a 2D texture `edge_table_tex` (size 256x1, `GL_R16I`) or structured buffer [S1, S2, unofficial].
4.  **Triangle Connection Table (`_TriangleConnectionTable`):** A lookup table storing up to 16 vertex indices (defining up to 5 triangles) for each of the 256 cube configurations [S2, unofficial]. Stored in a 2D texture `tri_table_tex` (size 16x256, `GL_R16I`) or structured buffer [S1, S2, unofficial].
5.  **Output Buffer (`_Buffer`):** A `RWStructuredBuffer<Vert>` of size $N \cdot N \cdot N \cdot 15$ vertices (where 15 is the maximum vertices per voxel: 5 triangles $\times$ 3 vertices) [S2, unofficial]. Each `Vert` struct contains `float4 position` ($w=1.0$) and `float3 normal` [S2, unofficial]. The total buffer size in floats is $105 \cdot N^3$ [S2, unofficial].
6.  **Edge Geometry Constants:**
    *   `edgeConnection[12]`: Array of 12 `int2` pairs defining the vertex indices for each edge. Order: bottom face (0-3), top face (4-7), vertical edges (8-11) [S2, unofficial].
    *   `edgeDirection[12]`: Array of 12 `float3` vectors indicating the direction of each edge [S2, unofficial].
    *   `vertexOffset[8]`: Array of 8 `float3` vectors for the 8 corners of a unit cube [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Initialize the output `_Buffer` with a marker value (e.g., -1.0f in position.w) to indicate unused vertices [S2, unofficial].
    *   Dispatch compute shaders to generate voxel scalar values (e.g., using Perlin noise) and voxel normals if not pre-computed [S2, unofficial].

2.  **Voxel Processing (Compute Shader):**
    *   Each thread processes one voxel cube, identified by `SV_DispatchThreadID` $(id_x, id_y, id_z)$ [S3, unofficial].
    *   **Boundary Check:** If any coordinate exceeds $W-1-\text{Border}$, return immediately to avoid out-of-bounds access [S2, unofficial].
    *   **Sample Vertices:** Sample the scalar value and gradient at the 8 vertices of the current cube [S3, unofficial]. Store in `samples[8]` where `xyz` is gradient and `w` is scalar value [S3, unofficial]. Clamp indices to $[1, Dims-1]$ if necessary [S3, unofficial].
    *   **Compute Configuration Selector:** For each vertex $i \in [0, 7]$, if `samples[i].w < Target`, set bit $i$ in the selector integer `flagIndex` [S2, S3, unofficial]:
        $$ \text{flagIndex} = \sum_{i=0}^{7} (\text{samples}[i].w < \text{Target}) \cdot 2^i $$
    *   **Empty/Filled Check:** If `flagIndex` is 0 or 255 (0xff), return immediately (no intersection) [S3, unofficial].
    *   **Edge Intersections:** For each of the 12 edges $i \in [0, 11]$:
        *   Check if bit $i$ is set in the edge flags for `flagIndex` (retrieved from `_CubeEdgeFlags` or `edge_table_tex`) [S2, S3, unofficial].
        *   If set, get the two vertex indices $v_1, v_2$ from `edgeConnection[i]` [S2, unofficial].
        *   Get scalar values $val_1 = \text{samples}[v_1].w$, $val_2 = \text{samples}[v_2].w$ [S3, unofficial].
        *   Compute interpolation parameter:
            $$ \text{param} = \frac{\text{Target} - val_1}{val_2 - val_1} \quad \text{if } val_2 \neq val_1, \text{ else } 0.5 $$
        *   Compute intersection position in local space:
            $$ \text{pos}_{edge} = \text{vertexOffset}[v_1] + \text{param} \cdot \text{edgeDirection}[i] $$
        *   Transform to world space: $\text{pos}_{world} = \text{chunkCenter} + \text{pos}_{edge} \cdot \text{gridSize} + \text{HalfVoxelOffset}$ [S3, unofficial].
        *   Compute normal: Interpolate gradient using `param` and normalize, or sample from `_Normals` buffer at the intersection UV [S2, S3, unofficial].
        *   Store the resulting vertex (position, normal) in a temporary array `edgeVertex[12]` [S2, unofficial].
    *   **Emit Triangles:**
        *   Retrieve triangle data for `flagIndex` from `_TriangleConnectionTable` [S2, S3, unofficial].
        *   Iterate through the table in steps of 3 to get edge indices for each triangle [S3, unofficial].
        *   If the first edge index is 15 (or -1, depending on table encoding), stop processing this cube [S3, unofficial].
        *   For each valid triangle (up to 5), get the three edge indices $e_a, e_b, e_c$ [S3, unofficial].
        *   Retrieve the pre-computed vertex positions and normals from `edgeVertex` for these edges [S2, unofficial].
        *   Write the vertex data to the output buffer `_Buffer` at index $idx \cdot 15 + (3 \cdot t + v)$, where $idx$ is the linear voxel index, $t$ is the triangle index (0-4), and $v$ is the vertex index (0-2) [S2, unofficial].
        *   If flat shading is used, calculate the face normal via cross product of two edges and assign it to all three vertices [S3, unofficial].

3.  **Rendering:**
    *   Render the `_Buffer` using `Graphics.DrawProceduralNow` with `MeshTopology.Triangles` and total vertex count `SIZE` [S2, unofficial].
    *   The vertex shader runs for each vertex [S2, unofficial]. Vertices with zero area (unused, zero-filled) generate no fragments [S2, unofficial].

**Pseudocode:**

```python
def compute_marching_cubes(id, Width, Height, Depth, Border, Target, gridSize, chunkCenter, HalfVoxelOffset, Voxels, Normals, CubeEdgeFlags, TriangleConnectionTable, edgeConnection, vertexOffset, edgeDirection, Buffer):
    x, y, z = id
    if x >= Width - 1 - Border or y >= Height - 1 - Border or z >= Depth - 1 - Border:
        return

    samples = [None] * 8
    for i in range(8):
        vx = x + vertexOffset[i][0]
        vy = y + vertexOffset[i][1]
        vz = z + vertexOffset[i][2]
        # Clamp indices to [1, Dims-1] as per VoxelValueWithGradient
        vx = max(1, min(vx, Width - 2))
        vy = max(1, min(vy, Height - 2))
        vz = max(1, min(vz, Depth - 2))
        # samples[i] stores gradient (xyz) and scalar (w)
        samples[i] = (Normals[vx, vy, vz], Voxels[vx, vy, vz])

    flag_index = 0
    for i in range(8):
        if samples[i][1] < Target:
            flag_index |= (1 << i)

    if flag_index == 0 or flag_index == 255:
        return

    edge_vertex_pos = [None] * 12
    edge_vertex_norm = [None] * 12

    for i in range(12):
        edge_flags = CubeEdgeFlags[flag_index]
        if (edge_flags >> i) & 1:
            v1, v2 = edgeConnection[i]
            val1, val2 = samples[v1][1], samples[v2][1]
            delta = val2 - val1
            param = 0.5 if delta == 0 else (Target - val1) / delta

            local_pos = vertexOffset[v1] + param * edgeDirection[i]
            world_pos = chunkCenter + local_pos * gridSize + HalfVoxelOffset
            edge_vertex_pos[i] = world_pos

            norm1, norm2 = samples[v1][0], samples[v2][0]
            local_norm = normalize(norm1 + param * (norm2 - norm1))
            edge_vertex_norm[i] = local_norm

    linear_idx = x + y * Width + z * Width * Height
    buffer_offset = linear_idx * 15
    table_base = flag_index * 16

    for t in range(5):
        e1 = TriangleConnectionTable[table_base + 3 * t]
        if e1 == 15:
            break
        e2 = TriangleConnectionTable[table_base + 3 * t + 1]
        e3 = TriangleConnectionTable[table_base + 3 * t + 2]

        for v in range(3):
            edge_idx = e1 if v == 0 else (e2 if v == 1 else e3)
            vert_pos = edge_vertex_pos[edge_idx]
            vert_norm = edge_vertex_norm[edge_idx]
            Buffer[buffer_offset + 3 * t + v] = (vert_pos, vert_norm)
```

**Parameters:**
*   `N`: Grid dimension (e.g., 64 or 40). Must be divisible by 8 for thread group alignment [S2, unofficial].
*   `Target`: Isovalue threshold (default 0.0f) [S2, unofficial].
*   `Border`: Border width to exclude (default 1) [S2, unofficial].
*   `gridSize`: Physical size of a single voxel cube in world units [S1, unofficial].
*   `SIZE`: Output buffer size = $N \cdot N \cdot N \cdot 15$ vertices [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $val_2 - val_1 = 0$, `param` defaults to 0.5 to handle flat regions [S2, unofficial].
*   **Boundary Access:** Explicit boundary checks prevent out-of-bounds sampling [S2, S3, unofficial]. Normals at borders may require special handling or clamping [S2, S3, unofficial].
*   **Fixed-Size Buffer:** The output buffer is pre-allocated to the maximum possible size [S2, unofficial]. Unused entries are zero-filled, which is inefficient for sparse fields but avoids atomic operations [S2, unofficial].
*   **Texture Filtering:** Lookup tables must use `NEAREST` filtering and `CLAMP_TO_EDGE` wrapping to prevent interpolation artifacts [S1, unofficial].

## Subtopics

### [Marching Cubes on GPU](3767-marching-cubes-on-gpu.md)
A GPU-based surface extraction technique that constructs an isosurface mesh from a 3D scalar volume using compute shaders. It differs from this method by using structured buffers for data storage rather than render textures/lookup tables, which is noted as slower but functional.

## Operating characteristics
*   **Time Complexity:** $O(N^3)$, where $N$ is the grid dimension. Each voxel is processed by one thread group [S2, unofficial].
*   **Memory Complexity:** $O(N^3)$ for the voxel buffer and output buffer. The output buffer is fixed at $15 \cdot N^3$ vertices [S2, unofficial].
*   **Performance:** Rendering performance is comparable to converting the buffer to a standard Unity mesh, though unused vertices cause unnecessary vertex shader invocations [S2, unofficial]. For complex scenes, an append buffer or counter buffer might be more efficient [S2, unofficial].
*   **Strengths:** Fully GPU-based, no CPU-GPU synchronization for mesh generation, parallelizable [S2, unofficial].
*   **Limitations:** Fixed-size buffer wastes memory and processing power on empty space. No dynamic resizing or culling of empty voxels within the shader [S2, unofficial].

## Background
This method is a GPU implementation of the Marching Cubes algorithm [S2, S3, unofficial]. The specific implementation using compute shaders and fixed-size buffers with `DrawProcedural` is exemplified in open-source projects such as "Marching-Cubes-On-The-GPU" by Scrawk [S2, unofficial]. It leverages modern GPU compute capabilities to parallelize the voxel processing and triangle generation steps [S2, S3, unofficial].
