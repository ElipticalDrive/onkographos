# Marching Cubes 33

Also called: 33-case Marching Cubes, Advanced Marching Cubes, Chernyaev 1995, Construction of Topologically Correct Isosurfaces, MC33

## Overview
Marching Cubes 33 is an isosurface extraction algorithm that resolves the topological ambiguities inherent in the original 15-configuration Marching Cubes method by analyzing the trilinear interpolant within each voxel [S2, unofficial]. It increases the lookup table from 15 to 33 entries to ensure the generated triangle mesh topology coincides exactly with the topology of the underlying trilinear function, preventing artifacts such as holes at shared faces between adjacent cells [S2, unofficial]. Unlike [Marching Cubes 2](1393-marching-cubes-2.md), which may use alternative lookup strategies, MC33 explicitly derives sub-cases based on face and internal connectivity tests [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A volumetric scalar field defined on a cubic grid. For each voxel (cube), the scalar values at the 8 corner nodes ($F_{000}$ to $F_{111}$) and a target isovalue (typically 0).
*   **Output:** A set of triangles representing the isosurface within the voxel.

**Data Structures**
*   **Lookup Table:** An array of 33 entries. Each entry corresponds to a specific topological configuration derived from the 16 standard binary cases, split into sub-cases (e.g., 4.1.1, 4.1.2, 7.3, 13.3) based on ambiguity resolution.
*   **Vertex Data:** Coordinates of vertices on the cube edges (via linear interpolation) and potentially one additional vertex inside the cube for complex cases.

**Definitions**
*   **Trilinear Interpolation:** The scalar function $F(q,s,t)$ over a cube with local coordinates $q,s,t \in [0,1]$ is:
    $$F(q,s,t) = F_{000}(1-q)(1-s)(1-t) + F_{100}q(1-s)(1-t) + F_{010}(1-q)s(1-t) + F_{110}qs(1-t) + F_{001}(1-q)(1-s)t + F_{101}q(1-s)t + F_{011}(1-q)st + F_{111}qst$$
    [S2, unofficial]
*   **Separated vs. Joined Nodes:** Two nodes of the same sign are **joined** (non-separated) if there exists a path between them along which $F$ does not change sign. They are **separated** if no such path exists [S2, unofficial].
*   **Ambiguous Face:** A face with two positive and two negative diagonally opposed nodes. The node signs alone are insufficient to determine connectivity [S2, unofficial].
*   **Internal Ambiguity:** A situation where nodes are separated on the faces but joined inside the cube (e.g., Configuration 4) [S2, unofficial].

**Algorithm Steps**

1.  **Determine Base Configuration:**
    Compute the binary index $I$ based on the signs of the 8 corner nodes relative to the isovalue. Map $I$ to one of the 16 base configurations. If $I$ corresponds to a symmetric case, use the canonical form (e.g., ensure positive nodes $\ge$ negative nodes) [S2, unofficial].

2.  **Resolve Face Ambiguity:**
    For each face of the cube that is ambiguous (two positive, two negative diagonally opposed nodes):
    Let the corner values on the face be $A, B, C, D$ such that $A, C$ are positive and $B, D$ are negative.
    Compare the products $AC$ and $BD$:
    *   If $AC > BD$: Positive nodes are joined; negative nodes are separated.
    *   If $AC < BD$: Positive nodes are separated; negative nodes are joined.
    *   If $AC = BD$: The asymptotes intersect on the face boundary; handle as a degenerate case (typically treated as separated or joined based on implementation preference, but sources imply strict inequality determines the topology) [S2, unofficial].

3.  **Resolve Internal Ambiguity:**
    For configurations with internal ambiguity (e.g., 4, 6, 7, 10, 12, 13), determine if separated nodes on faces are joined inside the cube.
    
    *Method 1 (Hyperbola Intersection):*
    Compare hyperbolas on opposite faces. If the projections intersect, nodes are joined. This is determined by:
    $$(A_1 - A_0)(C_1 - C_0) - (B_1 - B_0)(D_1 - D_0) > 0$$
    [S2, unofficial]
    
    *Method 2 (Quadratic Inequality - Preferred):*
    Check for a plane parallel to a face where nodes of the same sign become joined. Define a quadratic inequality $at^2 + bt + c > 0$ derived from bilinear interpolation on parallel faces.
    1.  Calculate coefficients $a, b, c$ from the node values on the parallel faces.
    2.  Check if $a < 0$ (parabola opens downward).
    3.  Check if the maximum $t_{max} = -b/2a$ lies in $(0, 1)$.
    4.  Check if the corner nodes at $t=t_{max}$ have the required signs and the inequality holds.
    If all conditions are met, the areas are joined inside the cube [S2, unofficial].

4.  **Select Sub-Case:**
    Based on the results of face and internal ambiguity tests, select the specific sub-case from the 33-entry lookup table.
    *   **Simple Configurations (0, 1, 2, 5, 8, 9, 11, 14):** No ambiguous faces, no internal ambiguity. All positive nodes joined, all negative nodes joined.
    *   **Configuration 4:** No ambiguous faces. Internal ambiguity resolved to Case 4.1.1 (separated) or 4.1.2 (joined) [S2, unofficial].
    *   **Configuration 6:** One ambiguous face. If positive nodes separated on face, internal ambiguity leads to Cases 6.1.1, 6.1.2, or 6.2 [S2, unofficial].
    *   **Configuration 7:** Three adjacent ambiguous faces. Leads to Cases 7.1–7.4.2. Case 7.3 requires an additional vertex [S2, unofficial].
    *   **Configuration 10:** Equal positive/negative nodes. Top face positive nodes separated. Bottom face ambiguity leads to Cases 10.1.1, 10.1.2, or 10.2 (additional vertex) [S2, unofficial].
    *   **Configuration 12:** Two ambiguous faces. Leads to Cases 12.1.1, 12.1.2, 12.2, 12.3 [S2, unofficial].
    *   **Configuration 13:** All six faces ambiguous. Impossible to have separated positive nodes on two opposite faces and joined on others. Leads to Cases 13.1–13.5.2. Cases 13.3, 13.4 require additional vertices [S2, unofficial].

5.  **Generate Vertices:**
    *   **Edge Vertices:** For each edge intersected by the isosurface, compute the vertex position using linear interpolation:
        $$V = V_1 + \frac{0 - F_1}{F_2 - F_1} (V_2 - V_1)$$
        where $V_1, V_2$ are cube corners and $F_1, F_2$ are their scalar values [S2, unofficial].
    *   **Additional Vertex:** For cases requiring an internal vertex (e.g., 7.3, 10.2, 12.2, 12.3, 13.3, 13.4), place a vertex inside the cube. A simple choice is the average of all other generated vertices in the cell [S2, unofficial].

6.  **Construct Triangles:**
    Use the selected sub-case pattern to connect the generated vertices into triangles. If an additional vertex exists, it serves as a common node for all triangles in the model [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels. Each voxel is processed independently. The constant factor is higher than standard Marching Cubes due to the additional arithmetic for ambiguity resolution (multiplications, comparisons, and potentially quadratic root finding).
*   **Memory Complexity:** $O(N)$ for the output mesh. The lookup table is small (33 entries).
*   **Performance:** The algorithm is computationally more expensive than the original 15-case MC due to the branching and arithmetic required for ambiguity resolution. However, it avoids post-processing steps to fix topological errors.
*   **Strengths:** Guarantees topological correctness of the isosurface relative to the trilinear interpolant. Eliminates holes and self-intersections caused by ambiguous face/internal connectivity mismatches between adjacent cells.
*   **Limitations:** More complex implementation. The "additional vertex" in cases like 7.3 and 13.3 can introduce non-manifold geometry or visual artifacts if not handled carefully in rendering. The choice of the additional vertex (e.g., average) is heuristic and may not perfectly represent the true isosurface geometry.
*   **When to use:** When topological correctness is critical (e.g., medical imaging, scientific visualization) and the underlying data is well-sampled enough that the trilinear interpolant is a valid approximation.
*   **When not to use:** For real-time applications where performance is paramount and minor topological artifacts are acceptable. For data with high-frequency noise where the trilinear interpolant is not a good model.

## Background
The Marching Cubes 33 algorithm was proposed by Boris E. Chernyaev in 1995 in the paper "Construction of Topologically Correct Isosurfaces" [S2, unofficial]. It was implemented in the PAW/HIGZ project at CERN (European Organization for Nuclear Research) [S2, unofficial]. The work addressed the limitations of the original Marching Cubes algorithm by Lorensen and Cline (1987), which used a 15-configuration lookup table and suffered from topological ambiguities [S1]. Chernyaev demonstrated that the trilinear function permits 33 topologically distinct configurations within a cube, necessitating an enlarged lookup table.
