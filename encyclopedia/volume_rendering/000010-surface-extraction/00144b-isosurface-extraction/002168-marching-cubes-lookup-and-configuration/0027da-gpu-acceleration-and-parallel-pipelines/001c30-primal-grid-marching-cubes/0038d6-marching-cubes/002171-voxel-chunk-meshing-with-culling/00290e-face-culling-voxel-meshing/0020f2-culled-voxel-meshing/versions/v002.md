# Culled Voxel Meshing

Also called: Culled Meshing, Visible Face Generation with Boundary Policy

## Overview
Culled Voxel Meshing generates a single mesh for a voxel chunk by omitting faces shared between adjacent solid voxels [S1, S2, unofficial]. It differs from its parent [Face Culling Voxel Meshing](2268-face-culling-voxel-meshing.md) by explicitly handling chunk boundaries via a `BoundaryPolicy` parameter, and from [Greedy Meshing](3670-gpu-voxel-mesh-generation.md) by emitting individual unit quads rather than merging coplanar faces [S2, unofficial].

## How it works
**Inputs:** A voxel chunk data structure containing material IDs (where 0 represents air) and a `BoundaryPolicy` enum (`"air"` or `"solid"`) [S2, unofficial].
**Outputs:** An array of `Quad` objects representing the visible surface [S2, unofficial].

**Data Structures:**
*   `VoxelChunk`: A 3D grid of size $S \times S \times S$. Access is linearized via index $i = x + y \cdot S + z \cdot S^2$ [S2, unofficial]. Out-of-bounds reads return 0 (air) by default, but the boundary policy overrides this for chunk edges [S2, unofficial].
*   `Quad`: Defined by axis, direction, slice position, 2D coordinates $(u, v)$, dimensions, and material ID [S2, unofficial].

**Algorithm Steps:**
1.  Initialize an empty list `quads`.
2.  Iterate through every voxel $(x, y, z)$ in the chunk [S2, unofficial].
3.  If the voxel material is 0 (air), skip it [S2, unofficial].
4.  For each of the 6 face directions (defined by axis index $a \in \{0,1,2\}$ and direction $d \in \{1, -1\}$):
    a.  Compute neighbor coordinates $(n_x, n_y, n_z)$ by adding $d$ to the coordinate on axis $a$.
    b.  Check if the neighbor is outside chunk bounds $[0, S)$.
    c.  Determine the neighbor's material value: if inside bounds, read from chunk data; if outside bounds, use `BoundaryPolicy` (`"air"` $\rightarrow$ 0, `"solid"` $\rightarrow$ 1) [S2, unofficial].
    d.  If the neighbor's material is non-zero (solid), the face is internal and is **culled** (not emitted) [S2, unofficial].
    e.  If the neighbor is air, emit a `Quad` for this face [S2, unofficial].
        *   The quad's axis is the current axis.
        *   The quad's direction is $d$.
        *   The quad's slice position is the boundary plane coordinate: $z_{slice} = (d=1 ? z+1 : z)$ (mapped to the current axis) [S2, unofficial].
        *   The quad's 2D coordinates correspond to the current voxel's position on the other two axes [S2, unofficial].
        *   The dimensions are $1 \times 1$ and the material ID is the current voxel's material [S2, unofficial].
5.  Return `quads` [S2, unofficial].

**Pseudocode:**
```python
def meshCulled(chunk: VoxelChunk, policy: str) -> list:
    quads = []
    s = chunk.size
    # Each tuple: (axis_index, u_index, v_index)
    AXES = [(0, 1, 2), (0, 2, 1), (1, 0, 2), (1, 2, 0), (2, 0, 1), (2, 1, 0)]
    for x in range(s):
        for y in range(s):
            for z in range(s):
                material = chunk.get(x, y, z)
                if material == 0:
                    continue
                for axis, u, v in AXES:
                    for dir in (1, -1):
                        nx, ny, nz = x, y, z
                        if axis == 0: nx += dir
                        elif axis == 1: ny += dir
                        else: nz += dir
                        outside = nx < 0 or nx >= s or ny < 0 or ny >= s or nz < 0 or nz >= s
                        if outside:
                            neighbor = 1 if policy == "solid" else 0
                        else:
                            neighbor = chunk.get(nx, ny, nz)
                        if neighbor != 0:
                            continue
                        p = (x, y, z)
                        slice_pos = (p[axis] + 1) if dir == 1 else p[axis]
                        quads.append({
                            "axis": axis, "dir": dir, "slice": slice_pos,
                            "u": p[u], "v": p[v], "w": 1, "h": 1, "material": material
                        })
    return quads
```

**Parameters:**
*   `BoundaryPolicy`: `"air"` (treats outside as empty space) or `"solid"` (treats outside as solid) [S2, unofficial].

**Edge Cases:**
*   **Solid Chunk:** With `"air"` policy, a fully solid chunk produces only the outer shell; with `"solid"` policy, it produces 0 quads [S2, unofficial].
*   **Determinism:** The algorithm produces deterministic output for a given chunk seed [S2, unofficial].

## Operating characteristics
**Time Complexity:** $O(N)$ where $N$ is the number of voxels in the chunk, as each voxel is visited once and 6 neighbors are checked [S2, unofficial].
**Performance:** On an Apple M2 Pro, culled meshing for a 32³ terrain chunk (17,191 solid voxels) takes a median of 2.06 ms [S2, unofficial]. It is significantly faster than naive meshing (5.60 ms) but slower than greedy meshing due to the lack of face merging [S2, unofficial].
**Geometry Reduction:** Reduces polygon count compared to naive meshing (6,654 quads vs 103,146 quads for the same terrain) but produces more geometry than greedy meshing (6,654 vs 2,416 quads) [S2, unofficial].
**Strengths:** Deterministic execution and low latency (2.06 ms median on M2 Pro) [S2, unofficial].
**Limitations:** Still results in a large number of polygons compared to greedy meshing, and does not merge adjacent coplanar faces [S1, S2, unofficial].
**When to use:** When chunk boundaries are handled externally or a simple boundary policy is sufficient, and greedy merging is too slow or complex [S2, unofficial].

## Background
Culled meshing is a standard technique in voxel game engines, notably featured in the NOA voxel game engine [S1, unofficial]. The specific implementation details and benchmarks described here originate from a TypeScript implementation and accompanying article by m2-md [S2, unofficial].
