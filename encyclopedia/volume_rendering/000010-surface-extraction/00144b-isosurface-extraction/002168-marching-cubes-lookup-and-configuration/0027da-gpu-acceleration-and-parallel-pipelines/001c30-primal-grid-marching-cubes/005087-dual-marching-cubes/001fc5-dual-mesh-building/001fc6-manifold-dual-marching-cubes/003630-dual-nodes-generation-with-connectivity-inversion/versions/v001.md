# Dual Nodes Generation with Connectivity Inversion

Also called: DMC with Ambiguous Face Handling, Tunnel Recovery

## Overview
This method resolves non-manifold edge configurations in Manifold Dual Marching Cubes (MDMC) by generating two dual nodes instead of one for cells sharing ambiguous faces, thereby recovering topological tunnels [S1]. It differs from standard DMC by analyzing the connectivity of both interior (blue) and exterior (white) vertex components to determine node placement, whereas standard DMC relies solely on interior components [S1].

## How it works
**Inputs:**
- A voxel grid or octree cell $c$ with 8 vertices.
- Scalar field values at vertices to determine inside/outside status relative to isosurface $\partial V$.
- The Manifold Dual Marching Cubes (MDMC) lookup table configuration for the cell.

**Outputs:**
- A set of dual nodes (surface points) within cell $c$ and its adjacent cells $A_c$.
- Connectivity information linking these nodes to form manifold triangles.

**Data Structures:**
- **Cell Graph:** A graph $G=(V, E)$ where $V$ contains the 8 vertices of the cell and $E$ contains the 12 edges connecting them.
- **Vertex Status:** Each vertex $v \in V$ is classified as:
  - **Blue:** Inside $\partial V$ (scalar value indicates interior).
  - **White:** Outside $\partial V$ (scalar value indicates exterior).
- **Connected Components:** Sets of vertices connected by edges where both endpoints share the same status (Blue-Blue or White-White).

**Steps:**
1. **Graph Construction:** Represent the current cell $c$ as a graph with 8 vertices and 12 edges.
2. **Vertex Classification:** Classify each of the 8 vertices as Blue (inside) or White (outside) based on the scalar field threshold [S1].
3. **Component Identification:**
   - Identify all **Blue Connected Components (BCCs)**: maximal sets of blue vertices connected by blue-blue edges.
   - Identify all **White Connected Components (WCCs)**: maximal sets of white vertices connected by white-white edges [S1].
4. **Ambiguity Check:** Determine if the cell configuration corresponds to an ambiguous face case identified by the MDMC LUT.
5. **Node Generation Logic:**
   - **Standard Case:** If the cell has a single Blue Connected Component and no ambiguous faces, generate one dual node per BCC using standard DMC rules [S1].
   - **Ambiguous Case:** If the cell has a single Blue Connected Component but contains one or more ambiguous faces:
     a. Enumerate the set of adjacent cells $A_c$ that share these ambiguous faces.
     b. For each cell in $A_c$, extract its White Connected Components.
     c. Verify that the existence of an ambiguous face implies at least two White Connected Components in the local topology [S1].
     d. Use the White Connected Components to generate dual nodes in cell $c$ and all adjacent cells in $A_c$. This results in the creation of **two** dual nodes instead of one [S1].
6. **Tunnel Recovery:** The generation of two nodes at ambiguous interfaces ensures that tunnels in $\partial V$ are preserved and non-manifold edges are eliminated [S1].

**Pseudocode:**
```python
def generate_dual_nodes(cell, scalar_field, mcmc_lut):
    """
    Generates dual nodes for a single cell using connectivity inversion.
    
    Args:
        cell: Object containing 8 vertex indices and 12 edge definitions.
        scalar_field: Array of scalar values at vertex positions.
        mcmc_lut: Lookup table from Manifold Dual Marching Cubes.
        
    Returns:
        List of dual node positions and connectivity data.
    """
    # 1. Get vertex values and classify
    vertex_values = [scalar_field[v] for v in cell.vertices]
    # Assume threshold is 0.5 or normalized 0-1; inside if value > threshold
    threshold = 0.5
    is_inside = [v > threshold for v in vertex_values]
    
    # 2. Build adjacency graph for the cell
    # Edges connect specific pairs of the 8 vertices
    edges = cell.edges # List of (v1_idx, v2_idx)
    
    # 3. Find Connected Components
    # Blue components: vertices inside connected by edges where both endpoints are inside
    blue_components = find_connected_components(is_inside, edges, target_status=True)
    
    # White components: vertices outside connected by edges where both endpoints are outside
    white_components = find_connected_components(is_inside, edges, target_status=False)
    
    # 4. Check for ambiguous configuration via MDMC LUT
    # The LUT index is derived from the binary mask of is_inside
    config_index = get_lut_index(is_inside)
    is_ambiguous = mcmc_lut.is_ambiguous(config_index)
    
    # 5. Determine node generation strategy
    dual_nodes = []
    
    if is_ambiguous and len(blue_components) == 1:
        # Ambiguous case with single blue component
        # Requires connectivity inversion using white components
        # This typically involves checking adjacent cells to resolve the tunnel
        # For the current cell, we generate nodes based on white components
        # Note: In practice, this may require iterating over adjacent cells Ac
        # as described in the source. Here we assume local resolution or 
        # a helper that handles the adjacent cell context.
        
        # Generate two nodes based on the separation of white components
        # The exact geometric position is usually the centroid of the white components
        # or a specific intersection point derived from them.
        
        # Simplified geometric placement:
        # Node 1: Center of mass of White Component 1
        # Node 2: Center of mass of White Component 2
        if len(white_components) >= 2:
            node1 = compute_centroid(white_components[0], cell.vertices, scalar_field)
            node2 = compute_centroid(white_components[1], cell.vertices, scalar_field)
            dual_nodes.append(node1)
            dual_nodes.append(node2)
        else:
            # Fallback if white components are not distinct enough (should not happen in valid ambiguous case)
            node = compute_centroid(blue_components[0], cell.vertices, scalar_field)
            dual_nodes.append(node)
            
    else:
        # Standard DMC behavior: one node per blue component
        for comp in blue_components:
            node = compute_centroid(comp, cell.vertices, scalar_field)
            dual_nodes.append(node)
            
    return dual_nodes

def find_connected_components(is_inside, edges, target_status):
    """
    Finds connected components of vertices that satisfy target_status.
    """
    n = len(is_inside)
    visited = [False] * n
    components = []
    
    # Build adjacency list only for edges where both endpoints match target_status
    adj = [[] for _ in range(n)]
    for v1, v2 in edges:
        if is_inside[v1] == target_status and is_inside[v2] == target_status:
            adj[v1].append(v2)
            adj[v2].append(v1)
            
    for i in range(n):
        if not visited[i] and is_inside[i] == target_status:
            comp = []
            stack = [i]
            visited[i] = True
            while stack:
                u = stack.pop()
                comp.append(u)
                for v in adj[u]:
                    if not visited[v]:
                        visited[v] = True
                        stack.append(v)
            components.append(comp)
            
    return components

def compute_centroid(vertex_indices, cell_vertices, scalar_field):
    """
    Computes the geometric centroid of the given vertices.
    [G] In a real implementation, this would use the 3D coordinates of the vertices,
    not just indices. scalar_field is passed for context but centroid is geometric.
    """
    coords = [cell_vertices[i] for i in vertex_indices]
    centroid = sum(coords) / len(coords)
    return centroid
```

**Parameters:**
- **Threshold:** The scalar value separating inside/outside. Typical value: 0.5 for normalized data [S1].
- **$\lambda$ (Curvature Parameter):** Used in the broader adaptive extraction context to determine refinement. Typical value: 0.9 [S1].
- **Max Octree Depth:** Limits the resolution of the adaptive grid. Typical value: 7 [S1].

**Edge Cases and Pitfalls:**
- **Non-Manifold Edges:** Standard DMC LUT may create non-manifold edges if it only considers blue connected components in cells sharing an ambiguous face [S1]. This method specifically addresses this by inverting to white components [S1].
- **Degenerate Triangles:** Standard DMC2 can produce more degenerated triangles and struggle with sharp edges compared to this method [S1].
- **Multiple Ambiguous Faces:** If a cell has multiple ambiguous faces (e.g., three), the logic must ensure that the white component analysis correctly separates all relevant surface portions [S1].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of cells, with a constant factor increase due to the additional graph traversal for white components in ambiguous cases.
- **Memory Complexity:** Requires storing the graph structure for each cell and the connected components. Minimal overhead compared to standard DMC.
- **Performance:** On the 'Block' dataset (512x512x128 voxels, $\lambda=0.9$, max depth 7), this method produced 46,888 triangles, compared to 54,888 triangles for DMC2 [S1].
- **Strengths:** Recovers tunnels, eliminates non-manifold edges, produces fewer triangles, and captures sharp edges better than DMC2 [S1].
- **Limitations:** Requires analysis of adjacent cells for full connectivity resolution in some ambiguous configurations [S1].

## Background
This method was developed as part of an adaptive surface extraction algorithm from anisotropic volumetric data using generalized octrees [S1]. It addresses specific topological failures in Dual Marching Cubes when handling ambiguous face configurations, which are common in complex volumetric data [S1].
