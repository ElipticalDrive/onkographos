# Dual Marching Cubes Table Generation

Also called: Dual Marching Cubes Edge Encoding, DualMC table builder, DualMC table generation

## Overview
Dual Marching Cubes Table Generation is the offline algorithm that constructs the lookup table used by the Dual Marching Cubes (DualMC) surface extraction method [S1, unofficial]. It maps each of the 256 possible cube corner configurations (inside/outside) to a set of dual point edge masks that define the extracted surface geometry [S1, unofficial]. The table generation process determines which edges are intersected by the isosurface for every possible configuration, encoding these intersections as bitmasks to facilitate efficient parallel mesh construction on the GPU [S1, unofficial]. It builds on [Dual Mesh Building](1423-dual-mesh-building.md), which consumes these masks to create the final indexed mesh.

## How it works
The algorithm generates a static lookup table by iterating through all 256 possible cube configurations [S1, unofficial]. For each configuration, it identifies connected subgraphs of "inside" corners and determines the edges that connect these inside corners to "outside" corners [S1, unofficial]. These edges form the boundaries of the dual surface patches [S1, unofficial].

### Inputs and Outputs
*   **Input:** None. The algorithm is deterministic and static [S1, unofficial].
*   **Output:** A flat array `dualPointsList` of size $256 \times 4$ [S1, unofficial]. Each row $i$ (where $i \in [0, 255]$) contains up to 4 `uint32_t` values representing edge masks for the dual points generated by configuration $i$ [S1, unofficial]. Unused entries in a row are set to 0 [S2, unofficial].

### Data Structures
1.  **Corner Edge Mapping (`cornerEdges`):** A static table of size $8 \times 3$ [S1, unofficial]. It maps each of the 8 cube corners (indexed by Morton code $c \in [0, 7]$) to the edge codes of the three adjacent edges in the x, y, and z directions [S1, unofficial].
    *   The edge codes are defined by the enum `DMCEdgeCode`, where `EDGE0` to `EDGE11` correspond to powers of 2 from $2^0$ to $2^{11}$ (i.e., $1, 2, 4, \dots, 2048$) [S2, unofficial].
    *   The coordinate system is defined as:
        ```
              y
              |
              |
              |
              0-----x
             /
            /
           z
        ```
    *   The specific mapping for corner $c$ to edges $(e_x, e_y, e_z)$ is:
        *   Corner 0: `{EDGE0, EDGE8, EDGE3}`
        *   Corner 1: `{EDGE0, EDGE9, EDGE1}`
        *   Corner 2: `{EDGE2, EDGE8, EDGE7}`
        *   Corner 3: `{EDGE4, EDGE9, EDGE5}`
        *   Corner 4: `{EDGE2, EDGE11, EDGE3}`
        *   Corner 5: `{EDGE2, EDGE10, EDGE1}`
        *   Corner 6: `{EDGE6, EDGE11, EDGE7}`
        *   Corner 7: `{EDGE6, EDGE10, EDGE5}` [S1, unofficial]

2.  **Cube Corner Code:** A helper structure representing a single corner of the cube [S1, unofficial]. It stores the Morton code index and provides a method `getMask()` which returns a `uint32_t` with the bit at position $c$ set (i.e., $1 \ll c$) [G].

3.  **Dual Points List:** The output table. In C++, this is often declared as `int32_t const DualMC<T>::dualPointsList[256][4]` or `glm::uint dualPointsList[256][4]` [S1, S2, unofficial].

### Algorithm Steps
1.  **Initialize Output:** Allocate `dualPointsList` as a vector or array of size $256 \times 4$ [S1, unofficial].
2.  **Iterate Configurations:** Loop through all cube configuration indices `i` from 0 to 255 [S1, unofficial]. Let `cubeMask` be the integer `i`.
3.  **Handle Empty/Full Cases:** If `cubeMask == 0` (all outside) or `cubeMask == 255` (all inside), there are no intersection edges [S1, unofficial]. Set all 4 entries in `dualPointsList[i]` to 0 and continue to the next iteration [S1, unofficial].
4.  **Handle Ambiguous Configurations:** If `cubeMask` is 126, 189, 219, or 231, invert the mask: `cubeMask ^= 0x000000ffu` [S1, unofficial]. This is because the standard traversal merges two original Marching Cubes patches into one for these cases, and the correct patches are identical to the results of the inverted configurations [S1, unofficial].
5.  **Initialize Traversal State:**
    *   `processedCornersMask = 0`
    *   `numDualPoints = 0`
    *   `cornerStack` (empty stack of `CubeCornerCode`) [S1, unofficial]
    *   Pointer `cubeDualPointCodes` to `dualPointsList[i]` [S1, unofficial]
6.  **Find Connected Subgraphs:** Loop through all 8 corners `c` from 0 to 7:
    *   Create `startCorner` with index `c` [S1, unofficial].
    *   Check if `startCorner` has already been visited: if `(startCorner.getMask() & processedCornersMask) != 0`, mark it as visited (`processedCornersMask |= startCorner.getMask()`) and continue [S1, unofficial].
    *   Check if the corner is outside: if `(cubeMask & startCorner.getMask()) == 0`, mark it as visited and continue [S1, unofficial].
    *   **Start New Subgraph:**
        *   Push `startCorner` onto `cornerStack` [S1, unofficial].
        *   Initialize `connectedCornersMask = startCorner.getMask()` and `dualPointCode = 0` [S1, unofficial].
        *   **Traverse Subgraph:** While `cornerStack` is not empty:
            *   Pop `currentCorner` from `cornerStack` [S1, unofficial].
            *   For each of the 3 adjacent edges of `currentCorner` (using `cornerEdges[currentCorner.index][dir]` for `dir` in $\{0, 1, 2\}$):
                *   Let `edgeCode` be the edge mask [S1, unofficial].
                *   Determine the `neighborCorner` index [G].
                *   If the `neighborCorner` is classified as **outside** (i.e., `(cubeMask & neighborCorner.getMask()) == 0`):
                    *   Add `edgeCode` to `dualPointCode` (bitwise OR) [S1, unofficial].
                *   If the `neighborCorner` is classified as **inside** and has not been visited in this subgraph:
                    *   Add `neighborCorner` to `connectedCornersMask` [S1, unofficial].
                    *   Push `neighborCorner` onto `cornerStack` [S1, unofficial].
            *   Mark `currentCorner` as visited in `processedCornersMask` [S1, unofficial].
        *   **Store Result:** Add all corners in `connectedCornersMask` to the global `processedCornersMask` [S1, unofficial]. Set `cubeDualPointCodes[numDualPoints] = dualPointCode` and increment `numDualPoints` [S1, unofficial].
7.  **Finalize Row:** Set any remaining entries in the current row (from `numDualPoints` to 3) to 0 [S1, unofficial].

### Pseudocode
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Constants
NUM_CORNERS = 8
MAX_DUAL_POINTS_PER_CELL = 4

# Static Corner Edge Mapping [S1, unofficial]
# cornerEdges[c][0] = x-edge, [1] = y-edge, [2] = z-edge
# Edge codes are powers of 2: EDGE_k = 1 << k
cornerEdges = [
    [1<<0, 1<<8, 1<<3],  # Corner 0
    [1<<0, 1<<9, 1<<1],  # Corner 1
    [1<<2, 1<<8, 1<<7],  # Corner 2
    [1<<4, 1<<9, 1<<5],  # Corner 3
    [1<<2, 1<<11, 1<<3], # Corner 4
    [1<<2, 1<<10, 1<<1], # Corner 5
    [1<<6, 1<<11, 1<<7], # Corner 6
    [1<<6, 1<<10, 1<<5]  # Corner 7
]

# Precomputed neighbor indices for each (corner, edge_direction) pair [G]
# Derived from standard cube topology and the cornerEdges mapping.
NEIGHBOR_MAP = [
    [1, 6, 2],  # Corner 0 neighbors for x, y, z edges
    [0, 7, 5],  # Corner 1 neighbors
    [4, 0, 3],  # Corner 2 neighbors
    [7, 1, 1],  # Corner 3 neighbors
    [0, 6, 0],  # Corner 4 neighbors
    [0, 7, 1],  # Corner 5 neighbors
    [2, 4, 2],  # Corner 6 neighbors
    [2, 5, 3]   # Corner 7 neighbors
]

def generate_dual_mc_table():
    # Initialize output table [S1, unofficial]
    dual_points_list = [[0] * MAX_DUAL_POINTS_PER_CELL for _ in range(256)]
    
    # Ambiguous configurations [S1, unofficial]
    ambiguous_configs = {126, 189, 219, 231}
    
    for i in range(256):
        cube_mask = i
        
        # Handle empty/full cases [S1, unofficial]
        if cube_mask == 0 or cube_mask == 255:
            continue # Already initialized to 0
            
        # Handle ambiguous configurations [S1, unofficial]
        if cube_mask in ambiguous_configs:
            cube_mask ^= 0xFF # Invert all 8 bits
            
        processed_corners_mask = 0
        num_dual_points = 0
        
        for c in range(NUM_CORNERS):
            corner_mask = 1 << c
            
            # Skip if already processed or outside [S1, unofficial]
            if (processed_corners_mask & corner_mask) or not (cube_mask & corner_mask):
                processed_corners_mask |= corner_mask
                continue
                
            # Start new subgraph [S1, unofficial]
            stack = [c]
            connected_corners_mask = corner_mask
            dual_point_code = 0
            
            while stack:
                current_c = stack.pop()
                
                # Process all 3 edges of current corner [S1, unofficial]
                for dir in range(3):
                    edge_code = cornerEdges[current_c][dir]
                    neighbor_c = NEIGHBOR_MAP[current_c][dir]
                    neighbor_mask = 1 << neighbor_c
                    
                    if not (cube_mask & neighbor_mask):
                        # Neighbor is outside: this edge is intersected [S1, unofficial]
                        dual_point_code |= edge_code
                    else:
                        # Neighbor is inside
                        if not (connected_corners_mask & neighbor_mask):
                            # Not yet visited in this subgraph [S1, unofficial]
                            connected_corners_mask |= neighbor_mask
                            stack.append(neighbor_c)
                
                processed_corners_mask |= (1 << current_c)
            
            # Store the dual point code [S1, unofficial]
            if num_dual_points < MAX_DUAL_POINTS_PER_CELL:
                dual_points_list[i][num_dual_points] = dual_point_code
            num_dual_points += 1
            
        # Remaining entries are already 0 [S1, unofficial]

    return dual_points_list
```

### Parameters and Edge Cases
*   **Corner Edge Mapping:** The `cornerEdges` table is critical. Any error in this mapping will result in incorrect dual points [S1, unofficial]. The edge codes are indexed by Morton code $c \in [0, 7]$ [S1, unofficial].
*   **Ambiguous Configurations:** Configurations 126, 189, 219, and 231 are handled by inverting the mask [S1, unofficial]. This relies on the topological symmetry that the dual mesh generated by the inverted configuration is identical to the correct dual mesh for the ambiguous case [S1, unofficial].
*   **Precision:** The algorithm uses integer bitmasks, so there are no floating-point precision issues during table generation [S1, unofficial].
*   **Boundaries:** The table is static and covers all 256 cases. No boundary checks are needed during generation [S1, unofficial].

## Subtopics

### Dual Marching Cubes Edge Lookup Table
A variant of the lookup table structure used in some Dual Marching Cubes implementations [S2, unofficial]. It contains 232 entries (indexed 0 to 231), where each entry consists of four fields [S2, unofficial]. The first two fields are bitmasks of edges (EDGE0-EDGE11) representing the active edges for the case, and the last two fields are always zero [S2, unofficial]. This structure is a compact representation of the edge configurations for the 232 non-trivial cases [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The table generation is an offline, static process. It iterates through 256 configurations, and for each, performs a constant-time traversal of at most 8 corners and 12 edges. The total time is $O(1)$ relative to the input data size, but depends on the fixed constant of 256 cases [S1, unofficial].
*   **Memory Complexity:** The output table is fixed at $256 \times 4 \times 4$ bytes = 4 KB (assuming `uint32_t`) [S1, S2, unofficial]. This is negligible.
*   **Performance:** The generation is extremely fast, taking milliseconds on modern hardware. It is typically run once at application startup or precomputed and embedded in the binary [S1, unofficial].
*   **Strengths:** The bitmask-based approach allows for very efficient runtime lookup and bitwise operations on the GPU. The handling of ambiguous configurations via inversion simplifies the runtime logic [S1, unofficial].
*   **Limitations:** The table is specific to the Dual Marching Cubes topology. It cannot be easily adapted for other isosurface extraction methods without regeneration. The reliance on the `cornerEdges` mapping requires careful verification [S1, unofficial].

## Background
Dual Marching Cubes is a surface extraction method that generates a dual mesh, placing vertices on the edges of the voxel grid [S1, unofficial]. The table generation algorithm was developed as part of the DualMC project by Dominik Wodniok [S1, unofficial]. It was designed to provide a robust and efficient way to handle the complex topology of isosurface extraction, particularly in the context of GPU-based volume rendering [S1, unofficial]. The method addresses the ambiguities and topological issues present in standard Marching Cubes by working in the dual space [S1, unofficial]. The implementation is available in the `gentables` application of the DualMC repository [S1, unofficial].
