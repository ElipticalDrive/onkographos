# Halfedge Data Structure Construction

Also called: Dual mesh connectivity, Halfedge linking

## Overview
This method constructs the connectivity information for the quadrilateral mesh generated by Dual Marching Cubes, specifically storing vertices, faces, next halfedges, and twin edge relationships [S1]. It solves the problem of efficiently linking halfedges across cell boundaries on the GPU by using a hash table to group halfedges by their incident vertex pairs, handling boundary and non-manifold edges in parallel [S1].

## How it works
### Inputs and Outputs
**Inputs:**
- List of quadrilateral faces, where each face is defined by four vertex indices [S1].

**Outputs:**
- `vertex_halfedge`: Array mapping each vertex index to the index of one outgoing halfedge [S1].
- `face_halfedge`: Array mapping each face index to the index of its first halfedge [S1].
- `halfedge_start_vertex`: Array mapping each halfedge index to its start vertex [S1].
- `halfedge_face`: Array mapping each halfedge index to its face index [S1].
- `halfedge_next`: Array mapping each halfedge index to the index of the next halfedge in the face loop [S1].
- `halfedge_twin`: Array mapping each halfedge index to its twin halfedge index (or -1 if boundary) [S1].

### Data Structures
**Hash Table:**
- **Key:** 64-bit unsigned integer (`unsigned long long int`) [S1].
  - Bits 0–31: Smaller vertex index of the edge [S1].
  - Bits 32–63: Larger vertex index of the edge [S1].
  - This ordering ensures that distinct threads processing the same geometric edge compute the identical key [S1].
- **Value:** A counter representing the number of halfedges currently stored in the bucket [S1].
- **Bucket Storage:** An array or dynamic structure where halfedge indices are appended at the position determined by the counter value before incrementing [S1].

### Steps
1. **Kernel 1 (Local Information):** Each thread processes one quadrilateral face [S1]. For each of the four vertices, the thread determines the halfedge indices [S1]. For each of the four halfedges in the quadrilateral, the thread stores the index of the start vertex, the face index, and the index of the next halfedge [S1]. The thread computes a hash key from the start and end vertices, uses `atomicAdd` on the hash table counter for this key to find the insertion position within the bucket, and stores the halfedge index in the bucket at that position [S1]. The thread also updates the `vertex_halfedge` entry for the start vertex and the `face_halfedge` entry for the face [S1].
2. **Kernel 2 (Global Information):** The kernel iterates through all entries in the hash table to connect twin edges [S1]. For each bucket (edge), if it contains only one halfedge, it is marked as a boundary edge [S1]. If it contains two halfedges, they are set as twins [S1]. If it contains four halfedges (non-manifold edge, e.g., a tunnel between cells), the algorithm connects twins by pairing halfedges that point in opposite directions to ensure consistent face orientation [S1].

### Formulas
- Hash key construction: $$\text{key} = (\min(u, v) \ \& \ 0\text{xFFFFFFFF}) \ | \ ((\max(u, v) \ \& \ 0\text{xFFFFFFFF}) \ll 32)$$ where $u$ and $v$ are the start and end vertex indices of the halfedge [S1].
- Bucket insertion position: $$\text{pos} = \text{atomicAdd}(\text{counters}, \text{key}, 1)$$ [S1].

### Pseudocode
```python
def kernel_local_info(quads, hash_table, counters, he_start_v, he_face, he_next, vertex_he, face_he):
    for face_idx, quad in enumerate(quads):
        v0, v1, v2, v3 = quad
        vertices = [v0, v1, v2, v3]
        for i in range(4):
            he_idx = face_idx * 4 + i
            start_v = vertices[i]
            end_v = vertices[(i + 1) % 4]
            next_he_idx = face_idx * 4 + ((i + 1) % 4)

            he_start_v[he_idx] = start_v
            he_face[he_idx] = face_idx
            he_next[he_idx] = next_he_idx

            if vertex_he[start_v] == -1:
                vertex_he[start_v] = he_idx
            if face_he[face_idx] == -1:
                face_he[face_idx] = he_idx

            u, v = (start_v, end_v) if start_v < end_v else (end_v, start_v)
            key = (u & 0xFFFFFFFF) | ((v & 0xFFFFFFFF) << 32)

            pos = atomic_add(counters, key, 1)
            hash_table[key][pos] = he_idx

def kernel_global_info(hash_table, he_start_v, he_twin):
    for key, bucket in hash_table.items():
        halfedges = bucket
        n = len(halfedges)
        if n == 1:
            he_twin[halfedges[0]] = -1
        elif n == 2:
            he_twin[halfedges[0]] = halfedges[1]
            he_twin[halfedges[1]] = halfedges[0]
        elif n == 4:
            min_v = key & 0xFFFFFFFF
            max_v = (key >> 32) & 0xFFFFFFFF
            fwd = [h for h in halfedges if he_start_v[h] == min_v]
            bwd = [h for h in halfedges if he_start_v[h] == max_v]
            he_twin[fwd[0]] = bwd[0]
            he_twin[bwd[0]] = fwd[0]
            he_twin[fwd[1]] = bwd[1]
            he_twin[bwd[1]] = fwd[1]
```
*Note: `atomic_add` is a standard GPU primitive for atomic addition [G].*

### Parameters
- Atomic operations: `atomicAdd` used for counter increment [S1].
- Hash table size: Not given in the sources.

### Edge Cases and Pitfalls
- **Non-manifold edges:** Tunnels between cells may result in an edge containing four halfedges. The algorithm must correctly identify and pair these to maintain consistent face orientation [S1].
- **Precision:** The hash key uses 64-bit integers to avoid collisions. Vertex indices must fit within 32 bits [S1].
- **Boundary edges:** Edges with only one halfedge are correctly identified as boundaries [S1].

- **Limitations:** Hash table overhead, potential for collisions if vertex indices exceed 32 bits [S1].

## Background
The method is part of the Dual Marching Cubes (DMC) approach for quad-only surface reconstruction [S1]. It was developed to efficiently generate connectivity for the dual mesh on the GPU, addressing the limitations of previous methods that struggled with non-manifold cases or required sequential processing [S1].
