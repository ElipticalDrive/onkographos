# Parallel Dual Marching Cube

## Overview
Parallel Dual Marching Cube (PDMC) is an intersection-free iso-surface extraction method that processes a 3D signed distance field (SDF) grid on the GPU to produce a triangle or quadrilateral mesh [S1, unofficial]. It is implemented as a CUDA kernel accessible via a PyTorch C++ extension [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D signed distance field (SDF) grid tensor `grid` of shape `[dimX, dimY, dimZ]` residing on a CUDA device. The values must be contiguous [S1, unofficial].
*   **Parameters:**
    *   `isovalue` (scalar): The threshold for extraction. Default: `0.0` [S1, unofficial].
    *   `dtype` (`torch.float32` or `torch.float64`): Precision for vertex coordinates and grid processing [S1, unofficial].
    *   `return_quads` (bool): If `True`, output quad faces `[F, 4]`; if `False`, output triangle faces `[F, 3]` [S1, unofficial].
    *   `normalize` (bool): If `True`, vertices are normalized to `[0, 1]`; if `False`, they remain in `[0, dim-1]` [S1, unofficial].
*   **Outputs:**
    *   `verts`: Tensor of shape `[V, 3]` containing vertex coordinates [S1, unofficial].
    *   `faces`: Tensor of shape `[F, 3]` or `[F, 4]` containing face indices (starting from 0) [S1, unofficial].

**Data Structures:**
The CUDA kernel uses the following device storage structures [S1, unofficial]:
*   `Vertex<T>`: Struct with fields `x, y, z` of type `T`, stored contiguously.
*   `Quad<T>`: Struct with fields `i, j, k, l` of type `T`, stored contiguously.
*   `Triangle<T>`: Struct with fields `i, j, k` of type `T`, stored contiguously.
*   `Edge<T>`: Struct with fields `i, j` of type `T`, stored contiguously.
*   `CUDualMC` device storage:
    *   `temp_storage`: `IndexType*` for prefix sums.
    *   `first_cell_used`: `IndexType*`.
    *   `used_cell_index`: `IndexType*`.
    *   `used_to_first_mc_vert`: `IndexType*`.
    *   `used_cell_code`: `uint8_t*`.
    *   `used_to_first_mc_patch`: `IndexType*`.
    *   `mc_vert_to_cell`: `IndexType*`.
    *   `mc_vert_to_edge`: `Edge<Vertex<Scalar>>*`.
    *   `mc_vert_type`: `uint8_t*` (values 0-2 indicate x/y/z entering, 3-5 indicate x/y/z exiting) [S1, unofficial].
    *   `quads`: `Quad<IndexType>*`.
    *   `tris`: `Triangle<IndexType>*`.
    *   `first_tris_create`: `IndexType*`.
    *   `first_verts_create`: `IndexType*`.
    *   `verts`: `Vertex<Scalar>*`.

**Linearization Functions:**
To map 3D grid coordinates to 1D indices, the method uses [S1, unofficial]:
$$gA(x, y, z) = z + \text{dims}[2] \times (y + \text{dims}[1] \times x)$$
where $x$ is the slowest-varying dimension and $z$ is the fastest, and $\text{dims} = [\text{dimX}, \text{dimY}, \text{dimZ}]$ [S1, unofficial].

The inverse linearization functions are [S1, unofficial]:
$$gX(\text{id}) = \text{id} / (\text{dims}[2] \times \text{dims}[1])$$
$$gY(\text{id}) = (\text{id} / \text{dims}[2]) \% \text{dims}[1]$$
$$gZ(\text{id}) = \text{id} \% \text{dims}[2]$$

**Algorithm Steps:**
1.  **Degeneracy Check:** Check if the input grid values are entirely above or below the isovalue; if so, return empty vertex and face tensors to skip degenerate cases [S1, unofficial].
2.  **Padding:** Pad the input SDF grid with a 1-voxel border filled with `isovalue + 1` on all six sides to handle boundary conditions during extraction [S1, unofficial].
3.  **Kernel Launch:** Pass the padded grid and isovalue to the CUDA kernel, which populates device buffers for vertices, quads, and triangles [S1, unofficial].
4.  **Coordinate Offset:** Subtract 1 from all output vertex coordinates to offset the padding added in step 2 [S1, unofficial].
5.  **Normalization (Optional):** If normalization is enabled, divide vertex coordinates by `(dimX-1, dimY-1, dimZ-1)` to map them to the `[0, 1]` range; otherwise, keep them in `[0, dim-1]` [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def parallel_dual_marching_cube(grid, isovalue=0.0, return_quads=False, normalize=True, dtype=torch.float32):
    # Convert input to tensor to handle list inputs and ensure CUDA residency [G]
    grid = torch.as_tensor(grid, dtype=dtype, device="cuda")
    
    # Step 1: Degeneracy Check
    if grid.min() >= isovalue or grid.max() <= isovalue:
        return torch.zeros((0, 3), dtype=dtype, device=grid.device), torch.zeros((0, 4), dtype=torch.int32, device=grid.device)
    
    dimX, dimY, dimZ = grid.shape
    
    # Step 2: Padding
    grid = F.pad(grid, (1, 1, 1, 1, 1, 1), "constant", isovalue + 1)
    
    # Step 3: Kernel Launch
    # The CUDA kernel implementation is not provided in the sources.
    # It processes the padded grid and isovalue to populate device buffers for vertices, quads, and triangles.
    verts_raw = torch.empty(0, 3, dtype=dtype, device=grid.device) # Placeholder for kernel output
    quads = torch.empty(0, 4, dtype=torch.int32, device=grid.device)
    tris = torch.empty(0, 3, dtype=torch.int32, device=grid.device)
    
    # Step 4: Coordinate Offset
    verts = verts_raw - 1
    
    # Step 5: Normalization (Optional)
    if normalize:
        verts = verts / (torch.tensor([dimX, dimY, dimZ], dtype=verts.dtype, device=grid.device) - 1)
        
    if return_quads:
        return verts, quads
    else:
        return verts, tris
```

## Subtopics

### [Dual Marching Cubes with GPU Mesh Simplification](2139-dual-marching-cubes-with-gpu-mesh-simplification.md)
Dual Marching Cubes with GPU Mesh Simplification is a parallel isosurface extraction method that computes cell intersections using an asymptotic decider to resolve ambiguities, outputting a quadrilateral mesh stored in a halfedge data structure. It extends the Parallel Dual Marching Cube method by adding a GPU-based mesh simplification step to reduce vertex count and improve mesh quality. Unlike standard Marching Cubes which produces triangles, this method produces quadrilaterals, offering better surface quality for smooth fields while maintaining topological correctness in most cases.

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial].
*   **Measured Performance:** Not given in the sources [S1, unofficial].
*   **Strengths:** Intersection-free extraction, parallel processing on GPU, supports both triangle and quad outputs [S1, unofficial].
*   **Limitations:** Requires a CUDA-capable GPU; the input grid must be contiguous and reside on the CUDA device [S1, unofficial].
*   **When to use:** When extracting isosurfaces from large 3D SDF grids on the GPU with a need for intersection-free results [S1, unofficial].
*   **When not to use:** When running on CPU-only systems, or when the input grid is not a signed distance field or does not reside on the GPU [S1, unofficial].

## Background
Parallel Dual Marching Cube was introduced as part of the PaMO (Parallel Mesh Optimization) project by Oh et al. in 2025 [S1, unofficial]. It is an intersection-free iso-surface extraction module used in [PaMO](https://github.com/SarahWeiii/pamo) [S1, unofficial].
