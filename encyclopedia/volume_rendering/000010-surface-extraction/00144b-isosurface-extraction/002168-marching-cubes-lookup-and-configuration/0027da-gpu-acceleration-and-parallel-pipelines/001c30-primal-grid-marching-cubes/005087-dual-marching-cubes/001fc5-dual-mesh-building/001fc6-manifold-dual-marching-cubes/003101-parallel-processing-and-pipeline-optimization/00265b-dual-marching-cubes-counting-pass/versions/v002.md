# Dual Marching Cubes (Counting Pass)

Also called: DM counting pass, segment vertex/quad counter

## Overview
The Dual Marching Cubes (DM) counting pass is the first phase of a two-pass algorithm for extracting manifolds from segmented voxel data [S1, unofficial]. It computes the exact number of vertices and quads required for a specific segment ID within a defined bounding box, using corner bitmasks and precomputed lookup tables to avoid geometry generation overhead [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- `voxelToSegId`: A 1D array of `uint16_t` mapping linear voxel indices to segment IDs [S1, unofficial].
- `segId`: The target segment identifier for which geometry is being counted [S1, unofficial].
- `startX, startY, startZ, endX, endY, endZ`: Inclusive bounding box coordinates defining the region of the voxel grid to traverse [S1, unofficial].
- `X_OFF, Y_OFF, Z_OFF`: Stride constants for converting 3D coordinates to linear indices [S1, unofficial].

**Outputs:**
- A `struct dmc_result` containing:
  - `vertCount`: Total number of vertices required [S1, unofficial].
  - `quadCount`: Total number of quads required [S1, unofficial].
  - `vertices`: A dynamically allocated array of floats for vertex positions (size `vertCount * 3`) [S1, unofficial].
  - `normals`: A dynamically allocated array of floats for vertex normals (size `vertCount * 3`) [S1, unofficial].
  - `triangles`: A dynamically allocated array of `uint32_t` for triangle indices (size `quadCount * 6`) [S1, unofficial].

### Data Structures
- `DM_VERT_COUNT[256]`: A static `int8_t` array mapping cube configuration masks (0-255) to the number of vertices generated by that configuration [S1, unofficial].
- `DM_QUAD_COUNT[256]`: A static `int8_t` array mapping cube configuration masks (0-255) to the number of quads generated by that configuration [S1, unofficial].
- `counts`: A temporary array sized for the bounding box, used to accumulate corner bitmasks for the current window [S1, unofficial].
- `EDGE_TO_CELLS_EDGES[10*3]` and `EDGE_TO_CELLS_OFFS[10*3]`: Static `int8_t` arrays used in the geometry generation phase to map edge indices to cell edge indices and offsets [S1, unofficial].

### Steps
1. **Initialize Bounds:** Decrement `startX` and `startY` by 1 to adjust for counting overshoot [S1, unofficial].
2. **Calculate Window Dimensions:** `X_WIN_SIZE = endX - startX + 1` and `Y_WIN_SIZE = endY - startY + 1` [S1, unofficial].
3. **Initialize Index:** Set linear grid index `i` to `endX + endY * Y_OFF + endZ * Z_OFF` [S1, unofficial].
4. **Iterate Voxel Grid:** Iterate `z` from `endZ` down to `startZ`, `y` from `endY` down to `startY`, and `x` from `endX` down to `startX` [S1, unofficial].
5. **Compute Offset:** Calculate `w_i = i - count_offset`, where `count_offset = startZ * Z_OFF` [S1, unofficial].
6. **Check Segment ID:** If `voxelToSegId[i]` equals `segId`:
   - Accumulate corner bits into `counts[w_i]` using bitwise OR: `counts[w_i] |= 1`, `counts[w_i] |= 2`, `counts[w_i] |= 4`, `counts[w_i] |= 8`, `counts[w_i] |= 16`, `counts[w_i] |= 32`, `counts[w_i] |= 64`, `counts[w_i] |= 128` [S1, unofficial].
   - Accumulate vertex and quad counts using lookup tables: `vertCount += DM_VERT_COUNT[counts[w_i]]` and `quadCount += DM_QUAD_COUNT[counts[w_i]]` [S1, unofficial].
7. **Update Index for Y-Loop:** Decrement `i` by 1, then adjust for Y-loop wrap: `i = i + X_WIN_SIZE - Y_OFF` [S1, unofficial].
8. **Update Index for Z-Loop:** Adjust for Z-loop wrap: `i = i + Y_WIN_SIZE * Y_OFF - Z_OFF` [S1, unofficial].
9. **Allocate Buffers:** Allocate vertex buffer: `vertices = calloc(vertCount * 3, sizeof(float))` [S1, unofficial].

### Pseudocode
```python
def dual_marching_cubes_counting_pass(voxel_to_seg_id, seg_id, start_x, start_y, start_z, end_x, end_y, end_z, x_off, y_off, z_off, dm_vert_count, dm_quad_count):
    # Step 1: Adjust bounds
    start_x -= 1
    start_y -= 1

    # Step 2: Calculate window dimensions
    x_win_size = end_x - start_x + 1
    y_win_size = end_y - start_y + 1
    z_win_size = end_z - start_z + 1

    # counts array sized for the bounding box
    counts = [0] * (z_win_size * y_win_size * x_win_size)

    vert_count = 0
    quad_count = 0

    # Step 3: Initialize index
    i = end_x + end_y * y_off + end_z * z_off

    # Step 4: Iterate voxel grid backwards
    for z in range(end_z, start_z - 1, -1):
        for y in range(end_y, start_y - 1, -1):
            for x in range(end_x, start_x - 1, -1):
                # Step 5: Compute offset
                count_offset = start_z * z_off
                w_i = i - count_offset

                # Step 6: Check segment ID and accumulate
                if voxel_to_seg_id[i] == seg_id:
                    # Zero and accumulate corner bits
                    counts[w_i] = 0
                    counts[w_i] |= 1
                    counts[w_i] |= 2
                    counts[w_i] |= 4
                    counts[w_i] |= 8
                    counts[w_i] |= 16
                    counts[w_i] |= 32
                    counts[w_i] |= 64
                    counts[w_i] |= 128

                    # Accumulate vertex and quad counts
                    vert_count += dm_vert_count[counts[w_i]]
                    quad_count += dm_quad_count[counts[w_i]]

                # Step 7: Update index for Y-loop
                i -= 1
                i = i + x_win_size - y_off

            # Step 8: Update index for Z-loop
            i = i + y_win_size * y_off - z_off

    # Step 9: Allocate buffers
    vertices = [0.0] * (vert_count * 3)
    normals = [0.0] * (vert_count * 3)
    triangles = [0] * (quad_count * 6)

    return {
        'vertCount': vert_count,
        'quadCount': quad_count,
        'vertices': vertices,
        'normals': normals,
        'triangles': triangles
    }
```

### Parameters
- `DM_VERT_COUNT` and `DM_QUAD_COUNT`: Static lookup tables mapping the 256 possible cube configurations to the number of vertices and quads generated [S1, unofficial].
- `X_OFF, Y_OFF, Z_OFF`: Stride constants for 3D-to-1D grid mapping [S1, unofficial].

### Edge Cases and Pitfalls
- **Grid Traversal Direction:** The traversal is reversed (from `end` to `start`), which requires explicit index reset logic using `X_WIN_SIZE`, `Y_WIN_SIZE`, and stride constants to maintain the correct 3D-to-1D mapping [S1, unofficial].
- **Boundary Conditions:** The bounding box coordinates are inclusive [S1, unofficial].
- **Memory Allocation:** The buffers are allocated based on the counts [S1, unofficial].
- **Segment ID Mismatch:** If no voxels in the bounding box match the `segId`, the counts will be zero, and empty buffers will be allocated [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(V)$, where $V$ is the number of voxels in the bounding box, as it performs a single pass with constant-time bitmask updates and table lookups [S1, unofficial].
- **Memory Complexity:** $O(V)$ for the `counts` array, with output buffers proportional to the mesh size [S1, unofficial].
- **Strengths:** Efficiently determines buffer sizes without generating geometry, allowing for memory pre-allocation and reducing fragmentation [S1, unofficial].
- **Limitations:** Requires two passes (counting and generation), which may increase overall latency if the mesh size is small [S1, unofficial].
- **When to Use:** When the mesh size is unknown or varies significantly, and memory pre-allocation is desired [S1, unofficial].
- **When Not to Use:** When memory is extremely constrained and the mesh size is known or can be estimated [S1, unofficial].

## Background
The Dual Marching Cubes (DM) algorithm is an extension of the classic Marching Cubes algorithm, designed to produce manifold meshes from segmented voxel data [S1, unofficial]. The counting pass is a specific optimization within the DM pipeline, introduced to address the challenges of dynamic memory allocation and buffer sizing in GPU-based rendering pipelines [S1, unofficial]. The method is described in the unofficial source [S1, unofficial], which provides a C implementation and associated JavaScript worker code.
