# Parallel Dual Marching Cubes (DMC) Pipeline

Also called: Multi-staged DMC pipeline, Parallel DMC on Regular Grids

## Overview
The Parallel Dual Marching Cubes (DMC) Pipeline is a surface extraction method that generates a manifold quadrilateral mesh with full connectivity information (1-ring neighbors) from a regular 3D grid [S1, unofficial]. It solves the problem of unconnected primitives and missing adjacency data inherent in standard parallel extraction by combining static and dynamic lookup tables with parallel reduction algorithms [S1, unofficial]. Unlike standard parallel Marching Cubes which produces redundant and unconnected fragments, this method ensures topological consistency through a multi-staged pipeline that switches from block-based to cell-based processing [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A regular 3D grid $L$ of scalar values $v_{i,j,k}$ representing a function $f: \mathbb{R}^3 \to \mathbb{R}$, and an isovalue $\alpha$ [S1, unofficial].
*   **Output:** A manifold quadrilateral surface mesh with vertex positions, face connectivity, and 1-ring neighbor adjacency data [S1, unofficial].

**Data Structures:**
The pipeline relies on static lookup tables precomputed for all 23 canonical cell cases and dynamic tables generated during execution [S1, unofficial].

1.  **Vertex-Edges Table:** Maps a cell case and a specific cell vertex to a 12-bit vector (1 bit per edge) representing the set of associated active edges [S1, unofficial].
2.  **Edge-Vertex Table:** Maps a cell case and a specific edge to a 24-bit vector (2 bits per edge) identifying the associated cell vertex [S1, unofficial].
3.  **Vertex-Adjacencies Table:** Maps a cell case and a cell vertex to a sorted set of tuples $(V_{zyx}, e)$, where $V_{zyx}$ is the offset to the adjacent cell and $e$ is the associated edge, sorted in 1-ring order [S1, unofficial].
4.  **Case Table:** A 3D array of dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$ storing the cell case for each cell in the volume [S1, unofficial].
5.  **Index Table:** A 3D array of dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$ storing the index of the first face and vertex for each cell in the mesh buffers [S1, unofficial]. For a cell $(i,j,k)$ and its $x$-th vertex, the location in the vertex buffer is $I_{i,j,k} + x$ [S1, unofficial].

**Steps:**

1.  **Block Selection:** The volume is decomposed into blocks. For each block, the minimum and maximum density values are evaluated in parallel. If the condition $\min \le \alpha < \max$ holds, the block is marked as selected, and its index is stored in a buffer [S1, unofficial].

2.  **Classification:** One block is mapped to one thread group. Grid values for the block are loaded into local memory. For each cell $(i,j,k)$ within the block, the 8 corner values are inspected relative to $\alpha$. A point $v_{i,j,k}$ is classified as **inside** if $v_{i,j,k} > \alpha$ and **outside** if $v_{i,j,k} \le \alpha$ [S1, unofficial]. The resulting case is stored in the Case Table [S1, unofficial].

3.  **Indexing:** A parallel all-prefix-sum (scan) algorithm is performed on vertex and face counts to compute total buffer sizes and map cells to unique locations in mesh buffers [S1, unofficial]. The total count is transferred to the host for buffer allocation. During this scan, the number of relevant cells is counted, and their indices $(i,j,k)$ are written to a buffer [S1, unofficial]. This switches processing from block-based to cell-based [S1, unofficial].

4.  **Mesh Generation Phase 1 (Vertices):** For each relevant cell, vertices are relocated using a Quadric Error Metric (QEM) based approach [S1, unofficial]. The storage location in the mesh buffers is determined via dynamic lookup tables (derived from the Index Table) [S1, unofficial]. The 1-ring neighbors are gathered using the Vertex-Adjacencies Table [S1, unofficial].

5.  **Mesh Generation Phase 2 (Faces):** Faces are generated using a parallel scheme where each cell chooses three edges sharing the same origin (along the x, y, and z axes) [S1, unofficial]. This results in four grid values being classified and 16 possible configurations [S1, unofficial]. An extended Face Table maps local edges to adjacent cell edges to form quadrilaterals [S1, unofficial].

**Pseudocode:**

```python
# Input: Grid values V, isovalue alpha, block bounds
# Output: Vertex buffer, Face buffer, Adjacency data

def parallel_dmc_pipeline(V, alpha, blocks):
    # 1. Block Selection
    selected_blocks = []
    for block in blocks:
        min_val, max_val = compute_min_max(block)
        if min_val <= alpha < max_val:
            selected_blocks.append(block.index)
            
    # 2. Classification (Parallel per block)
    case_table = empty_3d_array(Nx-1, Ny-1, Nz-1)
    
    for block_idx in selected_blocks:
        block = get_block(block_idx)
        # Load block values into local memory
        local_V = load_local_memory(block)
        
        for cell in block.cells:
            i, j, k = cell.coords
            # Classify 8 corners
            inside_mask = 0
            for corner in cell.corners:
                if local_V[corner] > alpha:
                    inside_mask |= (1 << corner_index)
            case_table[i, j, k] = get_canonical_case(inside_mask)
            
    # 3. Indexing (Parallel Scan)
    # Compute vertex counts per cell based on case_table
    vertex_counts = compute_vertex_counts(case_table)
    
    # Parallel prefix sum (scan)
    # A'[i] = sum(A[0]...A[i-1])
    vertex_offsets = parallel_scan(vertex_counts)
    
    # Transfer total count to host
    total_vertices = vertex_offsets[-1] + vertex_counts[-1]
    host.allocate_vertex_buffer(total_vertices)
    
    # Count relevant cells and store their indices
    relevant_cells = []
    for i in range(Nx-1):
        for j in range(Ny-1):
            for k in range(Nz-1):
                if case_table[i, j, k] != 0: # 0 is empty case
                    relevant_cells.append((i, j, k))
                    
    # 4. Mesh Generation Phase 1 (Vertices)
    for (i, j, k) in relevant_cells:
        case = case_table[i, j, k]
        base_idx = vertex_offsets[i, j, k]
        
        # Get edges for this case and vertex
        # Vertex-Edges Table: (case, vertex) -> 12-bit vector
        # Edge-Vertex Table: (case, edge) -> 24-bit vector
        
        for v_idx in range(num_vertices_for_case(case)):
            # Relocate vertex using QEM
            pos = relocate_vertex_qem(V, i, j, k, case, v_idx)
            
            # Store in buffer
            buffer_idx = base_idx + v_idx
            vertex_buffer[buffer_idx] = pos
            
            # Gather 1-ring neighbors using Vertex-Adjacencies Table
            # Table returns sorted tuples (V_zyx, e)
            neighbors = get_1_ring_neighbors(case, v_idx)
            adjacency_buffer[buffer_idx] = neighbors

    # 5. Mesh Generation Phase 2 (Faces)
    # Face generation relies on parallel scheme [SDC09]
    # Each cell generates faces based on 3 edges sharing origin
    face_count = compute_face_counts(case_table)
    face_offsets = parallel_scan(face_count)
    total_faces = face_offsets[-1] + face_count[-1]
    host.allocate_face_buffer(total_faces)
    
    for (i, j, k) in relevant_cells:
        case = case_table[i, j, k]
        base_face_idx = face_offsets[i, j, k]
        
        # Choose 3 edges sharing same origin (x, y, z axes)
        # This defines 4 grid values and 16 configurations
        edges = select_origin_edges(case)
        
        # Use extended Face Table to map local edges to adjacent cell edges
        # Form quadrilaterals
        faces = generate_quadrilaterals(case, edges, vertex_buffer)
        
        for f_idx, face in enumerate(faces):
            face_buffer[base_face_idx + f_idx] = face
```

**Parameters:**
*   **Grid Spacing Factor:** The regular grid definition uses a spacing factor of 4, defined as $L = \{(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z) : i = 0,...,N_x; j = 0,...,N_y; k = 0,...,N_z\}$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Unconnected Primitives:** Standard parallel processing analyzes cells independently, leading to unconnected primitives and redundant computations [S1, unofficial]. This is mitigated by the static/dynamic lookup tables ensuring manifold connectivity [S1, unofficial].
*   **Precision:** The classification uses strict inequality $v_{i,j,k} > \alpha$ for inside and $\le \alpha$ for outside [S1, unofficial].
*   **Register Limits:** The QEM-based vertex relocation is chosen over complex QEF minimization via pseudoinverse to avoid performance penalties from limited register counts on parallel hardware [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The pipeline is dominated by parallel operations: block selection, classification, and prefix sums (scan), all of which are $O(N)$ where $N$ is the number of cells or blocks. The mesh generation is also parallelized per cell [S1, unofficial].
*   **Memory Complexity:** The method doubles memory effort due to the Case and Index tables, which are 3D arrays of size $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$ [S1, unofficial]. However, it only allocates memory for relevant parts of the volume if combined with block culling [S1, unofficial].
*   **Performance:** The switch from block-based to cell-based processing in the Cell Selection stage significantly accelerates mesh generation [S1, unofficial]. The QEM approach is less computationally complex than QEF minimization, avoiding register pressure penalties [S1, unofficial].
*   **Strengths:** Generates a manifold surface with full connectivity and 1-ring neighborhood information, suitable for interactive applications [S1, unofficial].
*   **Limitations:** The QEM-based relocation achieves lower quality than QEF minimization, though it is sufficient for preserving terrain volume [S1, unofficial].

## Background
The method is based on Dual Marching Cubes by Nielson [Nie04], which provides high-quality manifold surfaces but lacks interactivity in parallel settings [S1, unofficial]. The pipeline extends DMC with a novel parallel processing scheme using static and dynamic lookup tables and parallel reduction algorithms [S1, unofficial]. It was developed to address the lack of 1-ring neighbor information in standard surface extraction algorithms, which typically requires extensive post-processing [S1, unofficial]. The vertex relocation uses the Quadric Error Metric [GH97] [S1, unofficial].
