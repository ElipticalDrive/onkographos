# Parallel Processing and Pipeline Optimization

Also called: Parallel DMC Pipeline, Dual Marching Cubes Counting Pass

## Overview
This family defines a two-pass parallel algorithm for extracting manifold quadrilateral meshes from segmented voxel data or scalar fields on GPUs [S1]. It solves the problem of unconnected primitives and missing adjacency data inherent in standard parallel extraction by combining static and dynamic lookup tables with parallel reduction algorithms [S1]. Unlike standard parallel Marching Cubes which produces redundant and unconnected fragments, this method ensures manifold connectivity through a multi-staged pipeline that switches from block-based to cell-based processing [S1]. It builds on [Manifold Dual Marching Cubes](2135-manifold-dual-marching-cubes.md) but extends it for interactive performance on parallel hardware.

## Shared principles
The method relies on a two-phase approach: a counting pass to determine buffer sizes and a geometry generation pass to construct the mesh.

**Data Structures:**
*   **Static Lookup Tables:**
    *   `DM_VERT_COUNT[256]` and `DM_QUAD_COUNT[256]`: Map cube configuration masks (0-255) to the number of vertices and quads generated [S1].
    *   **Vertex-Edges Table:** Maps a cell case and a cell vertex to a 12-bit vector representing active edges [S1].
    *   **Edge-Vertex Table:** Maps a cell case and an edge to a 24-bit vector identifying the associated cell vertex [S1].
    *   **Vertex-Adjacencies Table:** Maps a cell case and a cell vertex to a sorted set of tuples $(V_{zyx}, e)$, where $V_{zyx}$ is the offset to the adjacent cell and $e$ is the associated edge, sorted in 1-ring order [S1].
    *   **Face Table:** Maps a cell case to a set of faces generated by the cell [S1].
*   **Dynamic/Intermediate Tables:**
    *   **Case Table:** Dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$. Stores the cell case for each cell [S1].
    *   **Index Table:** Dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$. Stores the index of the first face and vertex for each cell in the mesh buffers [S1].

**Grid Definition:**
The regular grid $L$ uses a spacing factor of 4 relative to base units $x,y,z$:
$$L = \{(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z) : i = 0,...,N_x; j = 0,...,N_y; k = 0,...,N_z\}$$
Cell $(i,j,k)$ is defined by the diagonal from $(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z)$ to $((i+1) \cdot 4 \cdot x, (j+1) \cdot 4 \cdot y, (k+1) \cdot 4 \cdot z)$ [S1].

**Classification:**
Inspect 8 corner values $v_{i,j,k}$ relative to isovalue $\alpha$. Classify $v_{i,j,k} > \alpha$ as inside and $v_{i,j,k} \le \alpha$ as outside [S1]. Determine the cell case (one of 23 canonical configurations) [S1].

**Indexing:**
Perform a parallel all-prefix-sum (scan) on vertex and face counts to compute total buffer sizes and map cells to unique locations [S1]. The scan transforms an array $A = \{a_0, ..., a_{n-1}\}$ to $A_0 = \{I, a_0, (a_0 \oplus a_1), ..., (a_0 \oplus ... \oplus a_{n-2})\}$ where $I$ is the identity and $\oplus$ is addition [S1].

**Vertex Buffer Location:**
$$vertex\_buffer[I_{i,j,k} + x] = vertex\_data$$
where $I_{i,j,k}$ is the index from the Index Table [S1].

## Subtopics

### [Dual Marching Cubes (Counting Pass)](3766-dual-marching-cubes-counting-pass.md)
The Dual Marching Cubes (DM) counting pass is the first phase of a two-pass algorithm for extracting manifolds from segmented voxel data. It computes the exact number of vertices and quads required for a specific segment ID within a defined bounding box, using corner bitmasks and precomputed lookup tables to avoid the overhead of geometry generation during the count. Unlike the subsequent geometry generation pass, this pass only determines buffer sizes and prepares the data structures needed for the final mesh construction. It is chosen when segment-based processing is required. See [Dual Marching Cubes (Counting Pass)](3766-dual-marching-cubes-counting-pass.md).

### [Parallel Dual Marching Cubes (DMC) Pipeline](6387-parallel-dual-marching-cubes-dmc-pipeline.md)
The Parallel Dual Marching Cubes (DMC) Pipeline is a surface extraction method that generates a manifold quadrilateral mesh with full connectivity information (1-ring neighbors) from a regular 3D grid. It solves the problem of unconnected primitives and missing adjacency data inherent in standard parallel extraction by combining static and dynamic lookup tables with parallel reduction algorithms. Unlike standard parallel Marching Cubes which produces redundant and unconnected fragments, this method ensures manifold connectivity through a multi-staged pipeline that switches from block-based to cell-based processing. It builds on [Dual Marching Cubes (Counting Pass)](3766-dual-marching-cubes-counting-pass.md) but extends it for interactive performance on parallel hardware. See [Parallel Dual Marching Cubes (DMC) Pipeline](6387-parallel-dual-marching-cubes-dmc-pipeline.md).

### Parallel Vertex and Face Coloring
A scheme to encode neighborhood and connectivity information in the DMC mesh, enabling parallel processing and simplification [S1]. Used to facilitate parallel simplification methods by identifying irregular elements based on face colors [S1].

## Background
The method originates from "A parallel dual marching cubes approach to quad only surface reconstruction" [S1]. It addresses topological consistency and parallel reconstruction issues in volume data. The source code is available in the associated repository.
