# Dual Marching Cubes

Also called: Dual MC, Nielson 2004 Dual MC, Nielson's Dual Marching Cubes, Regular Octree Dual Vertex Placement

## Overview
Dual Marching Cubes (DMC) is an isosurface extraction algorithm that generates topological manifold surfaces by unifying Marching Cubes (MC) surface fragments into polygonal patches [S2, unofficial]. It solves the problem of non-manifold geometry and "primitive soup" outputs common in standard MC and Dual Contouring by replacing each polygonal patch with a single vertex and each patch vertex with a quadrilateral face, resulting in a quadrilateral mesh with full connectivity [S2, unofficial]. Unlike standard MC, which outputs triangles from edge intersections, DMC outputs quads by connecting vertex representatives from the four cells sharing an intersected grid edge [S3, unofficial]. It differs from [Manifold Dual Marching Cubes](2135-manifold-dual-marching-cubes.md) by relying on the asymptotic decider for topological consistency rather than explicit ambiguous configuration correction, and from [Parallel Dual Marching Cube](2131-parallel-dual-marching-cube.md) by focusing on the general algorithmic construction of the dual topology and geometry [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D scalar field $F_{ijk}$ defined on a rectilinear grid with lattice points $(x_i, y_j, z_k)$ [S8, unofficial].
- Output: A quadrilateral mesh (or triangulated quad mesh) where vertices correspond to surface patches and faces correspond to grid edges intersecting the isosurface [S2, unofficial].

**Data Structures:**
1.  **Grid/Tree Structure:** The scalar field is represented either as a regular grid or a hierarchical tree (branch and leaf nodes) [S1, unofficial].
    -   `tree` class: Stores a 3D grid of nodes. `size_` is a 3D vector of grid dimensions. `children_` is a vector of node pointers of size `size_.product()`, indexed by `iz * size_.y() * size_.x() + iy * size_.x() + ix` [S1, unofficial].
    -   `DualGrid` struct (for regular grid traversal): Contains `size` (N), `primal_grid`, and `duals` array. `duals` has two layers, each of size $(N-1) \times (N-1)$, storing tuples of `(Vec3 position, D distance)` [S4, unofficial].
2.  **Lookup Table:** A pre-computed table of 256 entries derived from 23 canonical dual configurations [S3, unofficial]. Each entry maps an 8-bit key (from vertex signs) to the bipolar edges intercepted and the resulting dual vertex positions/connectivity [S3, unofficial].
3.  **Dual Point:** Represents a vertex in the dual mesh. Contains `Position` (Vec3), `IsValid` (bool), and `Gradient` (Vec3) [S7, unofficial].

**Parameters:**
-   `IsoValue`: Scalar threshold for surface extraction. Default 0.0 [S7, unofficial].
-   `config_.tolerance`: Error threshold for leaf node creation in hierarchical implementations. Default 0.001 [S1, unofficial].
-   `config_.maximum_depth`: Maximum recursion depth for tree nodes [S1, unofficial].
-   `config_.nominal_weight`: Regularization weight for the linear system in QEF minimization [S1, unofficial].
-   `bSmooth`: Boolean flag. If false, dual points are at voxel centers. If true, dual points are averaged from Hermite points (if available) [S7, unofficial].

**Steps:**

1.  **Initialization:**
    -   Compute grid size from bounding box and cell width. Resize node vectors [S1, unofficial].
    -   Initialize dual layers or point arrays. For a grid of size $N$, dual dimensions are $(N-1) \times (N-1) \times (N-1)$ [S4, unofficial]. Initialize counters `vertCount` and `quadCount` to 0 [S6, unofficial].

2.  **Classification and Key Generation:**
    -   For each cell (or dual cell), access the 8 vertex values $v_0 \dots v_7$ [S3, unofficial].
    -   Construct an 8-bit key $K = \sum_{i=0}^{7} (v_i < \text{IsoValue} ? 2^i : 0)$ [S3, unofficial].
    -   Classify the cell into one of the 23 canonical dual configurations [S2, unofficial].

3.  **Dual Vertex Position Calculation:**
    -   **Simple Mode:** If `bSmooth` is false, set the dual vertex position to the center of the voxel: $P = (x+0.5, y+0.5, z+0.5)$ [S7, unofficial].
    -   **Smooth Mode (Hermite Average):** If `bSmooth` is true and Hermite points exist, calculate position as the average of Hermite points: $P = \frac{1}{n} \sum P_{Hermite}$ [S7, unofficial]. Note: Full QEF minimization using Eigen/Unreal matrix inversion may yield incorrect results; a simplified average is often used [S7, unofficial].
    -   **QEF Mode (Advanced):** For cases with normals (e.g., from intersection data), solve the overdetermined linear system $A x = b$ using SVD [S1, unofficial].
        -   Matrix $A$ is $11 \times 4$. Rows 0-7 correspond to 8 corners: $A(i, 0..2)$ are gradient components, $A(i, 3) = -1$. Rows 8-10 are regularization: $A(8,0)=A(9,1)=A(10,2)=\text{nominal\_weight}$.
        -   Vector $b$ is $11 \times 1$. $b(i) = \text{dot}(\text{grad}_i, \text{points}_i - \text{medium}) - \text{value}_i$ for $i=0..7$. $b(8..10) = 0$.
        -   Solution $x$ gives the offset from the box center `medium`. Estimated center: $\text{medium} + x[0..2]$ [S1, unofficial].

4.  **Connectivity and Mesh Generation:**
    -   Identify intersected lattice edges. For each intersected edge, associate it with the four vertices forming a quadrilateral surface fragment [S2, unofficial].
    -   For each of the four adjacent cells containing the edge, construct the key, access the lookup table, and calculate the dual vertex position [S3, unofficial].
    -   Connect the four vertices to form two triangles (or one quad) [S3, unofficial].
    -   **Ambiguity Resolution:** If a cell has configuration 2B or 3B and shares an ambiguous face with another cell of configuration 2B or 3B, return an alternative edge configuration to prevent non-manifold edges [S3, unofficial].

5.  **Enumeration (Tree-based):**
    -   Iterate over all grid cells in shuffled order for parallel processing [S1, unofficial].
    -   Recursively generate tree nodes (`generate_impl`). If depth limit reached or error < tolerance, create leaf node with center/offset. Otherwise, split into 8 octants [S1, unofficial].
    -   Enumerate faces, edges, and vertices to assemble the final mesh, handling boundary conditions (skip if $x,y,z=0$ for dual grid access) [S4, unofficial].

        for y in range(dual_dims[1]):
            for x in range(dual_dims[0]):

                # Corners are at (x,y,z) to (x+1,y+1,z+1)

## Subtopics

### [Dual Mesh Building](1423-dual-mesh-building.md)
Dual Mesh Building constructs a quadrilateral mesh from a scalar volume grid by mapping the vertices of standard Marching Cubes (MC) polygons to vertices in a dual mesh, where each dual vertex represents an MC polygon and each dual face corresponds to an MC vertex. It solves the problem of generating manifold, watertight meshes with better-shaped elements and fewer vertices than standard MC. Unlike standard MC, which outputs triangles from edge intersections, Dual Mesh Building outputs quads by connecting vertex representatives from the four cells sharing an intersected grid edge. It differs from [Manifold Dual Marching Cubes](2135-manifold-dual-marching-cubes.md) by relying on the asymptotic decider for topological consistency rather than explicit ambiguous configuration correction, and from [Parallel Dual Marching Cube](2131-parallel-dual-marching-cube.md) by focusing on the general algorithmic construction of the dual topology and geometry.

### [Parallel Dual Marching Cube](2131-parallel-dual-marching-cube.md)
Parallel Dual Marching Cube (PDMC) is an intersection-free iso-surface extraction method that processes a 3D signed distance field (SDF) grid on the GPU to produce a triangle or quadrilateral mesh. It is implemented as a CUDA kernel accessible via a PyTorch C++ extension.

### [Dual Marching Cubes Vertex Processing](3688-dual-marching-cubes-vertex-processing.md)
Dual Marching Cubes Vertex Processing (`vertProc`) processes a dual cell (8 nodes) to generate mesh vertices and triangles using Marching Cubes on the dual vertices. It handles hierarchical subdivision by recursively resolving child nodes before generating geometry.

### [Dual Methods](8116-dual-methods.md)
Dual methods are a class of isosurface extraction algorithms that generate surface topology by creating an $(n-1)$-cell for every edge crossing the boundary in 3D, resulting in a mesh where topology is completely determined by the sample complex. Unlike primal methods such as Marching Cubes, which suffer from topological ambiguity in non-simplicial cells, dual methods resolve ambiguities by construction, though they may produce non-manifold vertices.

### [Dual Marching Cubes with Ambiguity Resolution and Regularization](11165-dual-marching-cubes-with-ambiguity-resolution-and-regulariza.md)
This method extracts an isosurface from a voxel grid by computing dual vertices for grid cubes based on topology cases, resolving topological ambiguities (specifically cases C16 and C19) by checking adjacent cubes, and optionally optimizing vertex positions using a Quadratic Error Function (QEF) with gradient normals or linear interpolation with learned weights. It builds on [Dual Marching Cubes](906-dual-marching-cubes.md) by adding explicit ambiguity resolution and regularization mechanisms to ensure manifold geometry and improved surface fidelity.

### Generalized Symmetric Dual Marching Cubes
A method for extracting constant-wind-speed isosurfaces from 3D wind-field data (e.g., ERA5, WRF, generic layouts) stored in 3D NetCDF format [S11, unofficial]. It computes case-index for all cells simultaneously using vectorised 8-bit computation. For each active cell, it performs QEF minimisation to determine the dual vertex position, using edge intersection points and finite-difference gradient normals, applying Tikhonov regularisation towards the mass point for rank-deficient cases. It assembles the dual mesh by finding active primal edges using `np.where`, forms quads from four adjacent-cell dual vertices, and splits them into triangles with correct outward winding [S11, unofficial]. The isovalue is typically a percentile (e.g., 90th) of the wind speed array. It supports QEF minimisation mode and average-point mode for dual vertex placement [S11, unofficial].

### Novel Interpolation for Dual Marching Cubes on Octree Volume Fraction Data
A surface extraction method for volume fraction data stored on an octree. It modifies the computation of mesh vertex positions in dual marching cubes to be more appropriate for volume fraction data by approximating octant shapes as spheres rather than cubes [S12]. It computes the dual grid from the input octree grid, computes a surface mesh vertex on each dual edge that crosses the object's surface using the novel interpolation scheme, and connects all mesh vertices to form a surface mesh [S12]. Unlike Dual Contouring, this method does not require gradient vectors, making it suitable for volume fraction data where only scalar values are available. Unlike Poisson surface reconstruction, this method does not require Hermite data (normals), which are not always available for X-ray CT volumes [S12]. Conventional linear interpolation on octrees causes severe artifacts (ripples/deformations) because volume fraction values vary steeply at boundaries and cell sizes are non-uniform [S12].

## Operating characteristics
-   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each cell is processed once. Parallel implementations (GPU) achieve near-linear scaling with grid size [S2, unofficial].
-   **Memory Complexity:** $O(N)$ for storing the grid and dual vertices. The output mesh size is proportional to the surface area, typically $O(N^{2/3})$ for smooth surfaces [S2, unofficial].
-   **Performance:** Generates manifold surfaces with full connectivity, allowing for efficient smoothing and subdivision [S2, unofficial]. Avoids the "primitive soup" overhead of standard parallel MC [S2, unofficial].
-   **Strengths:** Topological manifold guarantee, better mesh quality (quads vs triangles), fewer vertices than MC, suitable for procedural terrain modeling and medical imaging [S2, unofficial][S7, unofficial].
-   **Limitations:** May produce non-manifold edges in ambiguous configurations (2B/3B) if not handled [S3, unofficial]. The resulting mesh ends half a cell short of the grid boundary [S5, unofficial]. Boundary checks are required to avoid out-of-bounds access [S7, unofficial].
-   **When to Use:** When manifold geometry, smooth shading, and connectivity are required. Ideal for procedural terrain generation and medical volume visualization [S2, unofficial][S8, unofficial].
-   **When Not to Use:** When simple, fast triangle soup is sufficient, or when the grid is extremely sparse and hierarchical traversal overhead is prohibitive.

## Background
Dual Marching Cubes was introduced by Gregory Nielson in 2004 [S2, unofficial][S8, unofficial]. It was designed to address the topological ambiguities and non-manifold issues of standard Marching Cubes and Dual Contouring. The method unifies MC surface fragments into polygonal patches, creating a dual surface that is always a topological manifold. It is used for rendering enumerated volumes from segmented medical data (e.g., MRI) where original field function values are irrelevant and no threshold exists [S8, unofficial].
