# Dual Isosurfacing with Analytical Trilinear Intersection

Also called: Analytical Isosurface Extraction, Ray Intersection Isosurfacing, Topologically Accurate Dual Isosurfacing, Trilinear Ray Intersection

## Overview
Dual Isosurfacing with Analytical Trilinear Intersection extracts the topology of an analytical isosurface defined by a trilinear function within a voxel cell by determining the optimal set of diagonals to intersect with rays, ensuring one point per disjoint surface component [S1][S2]. Unlike standard Marching Cubes which uses linear interpolation and fixed lookup tables, this method uses the trilinear function exhaustively to determine the topology of the analytical isosurface, allowing for more accurate diagonal selection [S1][S2]. It builds on [Manifold Dual Marching Cubes](2135-manifold-dual-marching-cubes.md) by resolving ambiguous configurations through analytical ray intersection rather than precomputed lookup tables [S1].

## How it works
### Inputs and Outputs
**Inputs:**
- Scalar field values at the 8 vertices of a voxel cell: $v_0, \dots, v_7$ [S1][S2].
- The isovalue $I$ [S1][S2].
- The cell sign configuration index $C \in [0, 13]$ derived from the signs of the 8 vertices relative to $I$ [S1][S2].

**Outputs:**
- A set of intersection points on the cell diagonals [S1][S2].
- For each point, the diagonal index and the parameter $t \in [0, 1]$ along the diagonal where the trilinear function equals $I$ [S1][S2].

### Data Structures
The method relies on the classification of the 14 sign-configurations (numbered 0 to 13) of the MC-case table into five categories based on the number of ambiguous faces: 0, 1, 2, 3, or 6 [S1][S2].

**Ambiguous Face (AF):** A cell face with four same-sign ended diagonals and four $(+/-)$ edges. An AF is separated with respect to a specific sign if the contour on the face is a rectangular hyperbola. The sign is determined by the vertices in the quadrants containing the hyperbola, using the asymptotic decider [S2].
- $(+)$ ambiguous-face: Separated with respect to positive sign [S2].
- $(-)$ ambiguous-face: Separated with respect to negative sign [S2].

**Topological Configuration Index:** Configurations are represented as $x$, $x.y$, or $x.y.z$, where $x$ is the sign configuration, $y$ is the topological configuration, and $z$ is the sub-configuration [S1][S2].

**DeVella's Necklace Test:** Used to distinguish topological sub-configurations (specifically for tunnels) by checking if two vertices on a diagonal are internally connected. A positive result indicates the presence of a tunnel [S1][S2].

### Numbered Steps

1.  **Determine Cell Sign and Ambiguous Faces:**
    - Calculate the sign of the cell: Positive if more vertices are positive, Negative if more are negative, Neutral if equal [S2].
    - Identify ambiguous faces on the cell boundaries using the asymptotic decider [S2].
    - Categorize the cell into one of the five groups based on the count of ambiguous faces (0, 1, 2, 3, or 6) [S1][S2].

2.  **Select Diagonals for Ray Intersection:**
    Based on the category and specific topological sub-configuration, select diagonals to intersect. The goal is one point per disjoint component, relaxed for tunnels to capture manifold complexity [S1][S2].

    **Category 0 Ambiguous Faces (Sign Configurations 0, 1, 2, 4, 5, 8, 9, 11):**
    - Ignore Case 0 (no intersection) [S1][S2].
    - For Cases 1, 2, 5, 8, 9, 11: Use one $(+/-)$ diagonal for intersection [S1][S2].
    - For Case 4:
        - Use DeVella's necklace test to distinguish sub-configurations 4.1 (disjoint surfaces) and 4.2 (tunnel) [S1][S2].
        - If 4.1: Use the $(-/-)$ diagonal [S1][S2].
        - If 4.2: Use 2 of the 3 $(+/+)$ diagonals to obtain multiple points for the tunnel [S1][S2].

    **Category 1 Ambiguous Face (Sign Configurations 3, 6):**
    - If a $(+)$ cell has a $(+)$ ambiguous face: Single isosurface component occurs. Use one $(+/-)$ diagonal [S1][S2].
    - If a $(+)$ cell has a $(-)$ ambiguous face: Two isosurface components occur [S1][S2].
        - Cases 3.1 and 6.1.1 (two disjoint components, no tunnels):
            - Use one $(-/-)$ diagonal to obtain two intersection points [S1][S2].
            - If no $(-/-)$ diagonal exists (Case 3.1): Use two $(+/-)$ diagonals to obtain one intersection point each [S1][S2].
        - Case 6.1.2 (tunnel): Use both $(+/+)$ diagonals to obtain four intersection points on the tunnel [S1][S2].
        - Cases 3.2 and 6.2 (single isosurface component): Use one $(+/-)$ diagonal [S1][S2].

    **Category 2 Ambiguous Faces (Sign Configurations 10, 12):**
    - If ambiguous faces have different signs: Single component occurs (Cases 10.2, 12.2). Use one $(+/-)$ diagonal [S1][S2].
    - If ambiguous faces have the same sign:
        - Disjoint surfaces with two $(+)$ AF: Use one $(+/+)$ diagonal [S1][S2].
        - Disjoint surfaces with two $(-)$ AF: Use one $(-/-)$ diagonal [S1][S2].
        - Tunnel with two $(+)$ AF (Case 10.1.2): Use two $(-/-)$ diagonals [S1][S2].
        - Tunnel with two $(-)$ AF (Case 12.1.2): Use one $(-/-)$ diagonal and two $(+/-)$ diagonals [S1][S2].

    **Category 3 Ambiguous Faces (Sign Configuration 7):**
    - Case 7.1 (three $(+)$ AF): Three disjoint surfaces. Use three $(+/-)$ diagonals [S1][S2].
    - Case 7.2 (two $(+)$ AF, one $(-)$ AF): Two disjoint surfaces. Use two $(+/-)$ diagonals through the $(+)$ vertices in one of the $(+)$ ambiguous faces [S1][S2].
    - Case 7.3 (one $(+)$ AF, two $(-)$ AF): One surface. Use any one $(+/-)$ diagonal [S1][S2].
    - Case 7.4 (three $(-)$ AF):
        - Use DeVella's necklace test to distinguish 7.4.1 (disjoint surfaces) and 7.4.2 (tunnel) [S1][S2].
        - If 7.4.1: Use one $(+/+)$ diagonal to obtain two intersection points [S1][S2].
        - If 7.4.2: Use all three $(+/-)$ diagonals to obtain three points on the tunnel [S1][S2].

    **Category 6 Ambiguous Faces (Sign Configuration 13):**
    - Reduce seven possibilities to four cases using mirror symmetry pairs: (1) and (7), (2) and (6), (3) and (5) [S1][S2].
    - Case 13.1 (six $(+)$ AF): Four disjoint surfaces. Use all four $(+/-)$ diagonals [S1][S2].
    - Case 13.2 (five $(+)$ AF, one $(-)$ AF): Three disjoint surfaces. Use three $(+/-)$ diagonals, excluding the one through one of the two $(+)$ vertices in the $(-)$ ambiguous face [S1][S2].
    - Case 13.3 (four $(+)$ AF, two $(-)$ AF): Two disjoint surfaces. Find the $(+)$ vertex common to all three $(+)$ ambiguous faces. Use the $(+/-)$ diagonal through this vertex as one ray, and any one of the remaining three diagonals as the second ray [S1][S2].
    - Case 13.4 (equal $(+)$ and $(-)$ AF, common vertex signs differ from faces): One isosurface piece. Use any one of the four $(+/-)$ diagonals [S1][S2].
    - Case 13.5 (equal $(+)$ and $(-)$ AF, common vertex signs same as faces):
        - Use DeVella's necklace test to distinguish 13.5.1 (three disjoint surfaces) and 13.5.2 (two disjoint surfaces, one is a tunnel) [S1][S2].
        - If 13.5.1: Use the $(+/-)$ diagonal through the common vertex of the three same-signed ambiguous faces to get three points [S1][S2].
        - If 13.5.2: Use the diagonal through the common vertex of the three same-signed ambiguous faces as a ray. Use the remaining three diagonals as rays to find points for the tunnel. Store diagonal differences for connectivity [S1][S2].

3.  **Compute Intersection Points:**
    For each selected diagonal, solve the trilinear equation $f(t) = I$ along the diagonal to find the intersection point. The trilinear function $f(x,y,z)$ is defined by the vertex values. Along a diagonal, this reduces to a cubic equation in one parameter $t$ [S1][S2].

4.  **Output Points:**
    Return the set of computed intersection points.

### Pseudocode
```python
def dual_isosurfacing_analytical_trilinear(vertex_values, isovalue):
    """
    Extracts isosurface points for a single voxel cell using analytical trilinear intersection.
    
    Args:
        vertex_values: List of 8 scalar values [v0, ..., v7] at cell vertices.
        isovalue: The scalar isovalue I.
        
    Returns:
        List of intersection points (t, diagonal_index) for the cell.
    """
    # 1. Determine Cell Sign and Ambiguous Faces
    signs = [1 if v > isovalue else -1 for v in vertex_values]
    num_pos = sum(1 for s in signs if s == 1)
    num_neg = sum(1 for s in signs if s == -1)
    
    if num_pos > num_neg:
        cell_sign = 1 # (+) cell
    elif num_neg > num_pos:
        cell_sign = -1 # (-) cell
    else:
        cell_sign = 0 # Neutral cell
    
    # Determine sign configuration index C (0-13) based on signs
    # Map 8-bit sign pattern to canonical MC cases 0-13
    C = get_mc_case_index(signs)
    
    # Identify Ambiguous Faces (AF)
    # An AF has 4 same-sign ended diagonals and 4 (+/-) edges.
    # Determine sign of each AF using asymptotic decider
    ambiguous_faces = []
    for face_idx in range(6):
        if is_ambiguous_face(vertex_values, face_idx, isovalue):
            af_sign = get_af_sign(vertex_values, face_idx, isovalue)
            ambiguous_faces.append((face_idx, af_sign))
            
    num_af = len(ambiguous_faces)
    
    # 2. Select Diagonals based on Category and Topology
    selected_diagonals = []
    
    if num_af == 0:
        # Cases 0, 1, 2, 4, 5, 8, 9, 11
        if C == 0:
            return [] # No intersection
        elif C == 4:
            # Use DeVella's necklace test
            is_tunnel = devellas_necklace_test(vertex_values, C)
            if not is_tunnel: # 4.1 disjoint
                selected_diagonals.append(diagonal_type_neg_neg)
            else: # 4.2 tunnel
                selected_diagonals.extend([diagonal_type_pos_pos, diagonal_type_pos_pos]) # 2 of 3
        else:
            # Cases 1, 2, 5, 8, 9, 11
            selected_diagonals.append(diagonal_type_pos_neg)
            
    elif num_af == 1:
        # Cases 3, 6
        af_sign = ambiguous_faces[0][1]
        if cell_sign == af_sign:
            # Single component (3.2, 6.2)
            selected_diagonals.append(diagonal_type_pos_neg)
        else:
            # Two components
            is_tunnel = devellas_necklace_test(vertex_values, C)
            if not is_tunnel: # 3.1, 6.1.1
                if diagonal_type_neg_neg_exists():
                    selected_diagonals.append(diagonal_type_neg_neg)
                else: # Case 3.1
                    selected_diagonals.extend([diagonal_type_pos_neg, diagonal_type_pos_neg])
            else: # 6.1.2 tunnel
                selected_diagonals.extend([diagonal_type_pos_pos, diagonal_type_pos_pos])
                
    elif num_af == 2:
        # Cases 10, 12
        af_signs = [af[1] for af in ambiguous_faces]
        if af_signs[0] != af_signs[1]:
            # Different signs -> Single component (10.2, 12.2)
            selected_diagonals.append(diagonal_type_pos_neg)
        else:
            # Same signs
            if af_signs[0] == 1: # Two (+) AF
                is_tunnel = devellas_necklace_test(vertex_values, C)
                if not is_tunnel: # Disjoint
                    selected_diagonals.append(diagonal_type_pos_pos)
                else: # Tunnel (10.1.2)
                    selected_diagonals.extend([diagonal_type_neg_neg, diagonal_type_neg_neg])
            else: # Two (-) AF
                is_tunnel = devellas_necklace_test(vertex_values, C)
                if not is_tunnel: # Disjoint
                    selected_diagonals.append(diagonal_type_neg_neg)
                else: # Tunnel (12.1.2)
                    selected_diagonals.extend([diagonal_type_neg_neg, diagonal_type_pos_neg, diagonal_type_pos_neg])
                    
    elif num_af == 3:
        # Case 7
        af_signs = [af[1] for af in ambiguous_faces]
        pos_af_count = sum(1 for s in af_signs if s == 1)
        
        if pos_af_count == 3: # 7.1
            selected_diagonals.extend([diagonal_type_pos_neg, diagonal_type_pos_neg, diagonal_type_pos_neg])
        elif pos_af_count == 2: # 7.2
            # Use 2 (+/-) diagonals through (+) vertices in one (+) AF
            selected_diagonals.extend([diagonal_type_pos_neg, diagonal_type_pos_neg])
        elif pos_af_count == 1: # 7.3
            selected_diagonals.append(diagonal_type_pos_neg)
        else: # 7.4 (three (-) AF)
            is_tunnel = devellas_necklace_test(vertex_values, C)
            if not is_tunnel: # 7.4.1 disjoint
                selected_diagonals.append(diagonal_type_pos_pos)
            else: # 7.4.2 tunnel
                selected_diagonals.extend([diagonal_type_pos_neg, diagonal_type_pos_neg, diagonal_type_pos_neg])
                
    elif num_af == 6:
        # Case 13
        af_signs = [af[1] for af in ambiguous_faces]
        pos_af_count = sum(1 for s in af_signs if s == 1)
        
        # Reduce by mirror symmetry
        if pos_af_count == 6 or pos_af_count == 0: # 13.1 / 13.7
            selected_diagonals.extend([diagonal_type_pos_neg, diagonal_type_pos_neg, diagonal_type_pos_neg, diagonal_type_pos_neg])
        elif pos_af_count == 5 or pos_af_count == 1: # 13.2 / 13.6
            # Exclude diagonal through (+) vertex in (-) AF
            # Implementation: Select 3 specific (+/-) diagonals
            selected_diagonals.extend([diagonal_type_pos_neg, diagonal_type_pos_neg, diagonal_type_pos_neg])
        elif pos_af_count == 4 or pos_af_count == 2: # 13.3 / 13.5
            # Find common vertex
            common_vertex = find_common_vertex(vertex_values, af_signs)
            # Use diagonal through common vertex and one other
            selected_diagonals.append(diagonal_type_pos_neg) # Through common
            selected_diagonals.append(diagonal_type_pos_neg) # Any remaining
        else: # pos_af_count == 3 (13.4 / 13.5)
            # Check vertex signs vs face signs
            is_tunnel = devellas_necklace_test(vertex_values, C)
            if not is_tunnel: # 13.4 or 13.5.1
                if pos_af_count == 3 and cell_sign == 1: # 13.5.1
                    # Unique case: 1 (+/-) ray leads to 3 solutions
                    selected_diagonals.append(diagonal_type_pos_neg) # Through common vertex
                else: # 13.4
                    selected_diagonals.append(diagonal_type_pos_neg)
            else: # 13.5.2 tunnel
                # Use diagonal through common vertex and remaining 3
                selected_diagonals.append(diagonal_type_pos_neg) # Through common
                selected_diagonals.extend([diagonal_type_pos_neg, diagonal_type_pos_neg, diagonal_type_pos_neg])

    # 3. Compute Intersection Points
    points = []
    for diag in selected_diagonals:
        t = solve_trilinear_diagonal(vertex_values, diag, isovalue)
        if t is not None:
            points.append((t, diag))
            
    return points

def solve_trilinear_diagonal(vertex_values, diagonal_index, isovalue):
    """
    Solves f(t) = I along the specified diagonal.
    Returns t in [0, 1] or None if no intersection.
    """
    # Define endpoints of the diagonal
    v_start_idx, v_end_idx = get_diagonal_endpoints(diagonal_index)
    v_start = vertex_values[v_start_idx]
    v_end = vertex_values[v_end_idx]
    
    # Trilinear interpolation along diagonal reduces to a cubic equation
    # Coefficients depend on the 8 vertex values and the diagonal geometry
    # This is a standard root-finding problem for a cubic polynomial
    roots = solve_cubic_for_trilinear_diagonal(v_start, v_end, vertex_values, isovalue)
    
    # Return valid root in [0, 1]
    for t in roots:
        if 0 <= t <= 1:
            return t
    return None
```

### Parameters
- **Cell Sign Configuration:** Integer index from 0 to 13 [S1].
- **Ambiguous Face Sign:** Determined by asymptotic decider [S2].
- **DeVella's Necklace Test Threshold:** Not given in the sources. [G] Typically involves checking the sign of the trilinear function at the center of the diagonal or comparing vertex signs with the function value at the midpoint.

### Pitfalls
- **Precision:** Evaluating the intersection point requires significant computational operations. Floating-point precision errors in solving the cubic equation may lead to missed intersections or incorrect topology [S1].
- **Tunnels:** The "one-point-per-disjoint-component" rule is relaxed for tunnels. Sufficient points are needed to capture the complexity of the manifold [S1][S2].
- **Ambiguous Face Detection:** Incorrect identification of ambiguous faces or their signs leads to wrong diagonal selection [S2].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel, as it involves a fixed number of case checks and cubic root solving. However, solving the cubic equation is more expensive than linear interpolation used in standard MC.
- **Memory Complexity:** $O(1)$ per voxel, storing only the vertex values and selected diagonals.
- **Strengths:** Topologically accurate representation of the analytical isosurface. Handles ambiguous configurations correctly without lookup tables.
- **Limitations:** Computationally more expensive than linear MC due to cubic root solving. Complex logic for diagonal selection.
- **When to use:** When topological accuracy is critical and the scalar field is well-approximated by trilinear interpolation.
- **When not to use:** When performance is paramount and linear approximation is sufficient.

## Background
Originated from the need to accurately extract topologies of analytical isosurfaces defined by trilinear functions. The method analyzes the 31 cases from the exhaustive MC case-table (Chernyaev, 1995; Nielson, 2003; Lopes and Brodlie, 2003) [S1][S2]. It builds on the work of Nielson and Hamann (1991) on ambiguous faces and DeVella's necklace test [S1][S2].
