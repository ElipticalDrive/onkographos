# Topologically Defined Isosurface via Connectedness Couples

Also called: MC with (alpha, lambda) couples, Marching-Cubes with topological constraints

## Overview
This method extracts a topologically correct isosurface from a binary volumetric image by enforcing valid **connectedness couples** $(\alpha, \lambda)$, where $\alpha$ defines foreground connectivity and $\lambda$ defines background connectivity [S1]. Unlike standard Marching Cubes, which relies on a fixed 15-case lookup table that fails for ambiguous trilinear configurations, this approach constructs a local triangulated manifold for each of the 256 voxel configurations based on the specific connectivity constraints, ensuring the resulting mesh is a closed, oriented 2-manifold without singularities [S1]. It is distinguished from sibling methods like the Asymptotic Decider by its reliance on discrete graph-theoretic connectivity rules rather than continuous field analysis or geometric insertion of cell-center vertices [S1, S2].

## How it works
### Inputs and Outputs
- **Input:** A binary volumetric image $I$ (voxels are 0 or 1) and a chosen valid connectedness couple $(\alpha, \lambda)$.
- **Output:** A triangular mesh representing the isosurface $\tilde{S}_\lambda(I)$, defined as the canonical embedding of the complete graph $G_\lambda(I)$ [S1].

### Data Structures
- **Configuration Table:** A precomputed lookup table of size 256. Each entry corresponds to one of the $2^8$ possible binary states of a voxel's 8 corners. The entry stores the local triangulation (set of triangles or loops) for that configuration under the specified $(\alpha, \lambda)$ constraints [S1].
- **Complete Graph $G_\lambda(I)$:** An oriented two-dimensional combinatorial manifold without boundary, formed by the union of local graphs from all 8-cubes in $I$ [S1].
- **Local Graph $G_\lambda(C_8)$:** For a single voxel $C_8$, this is a set of oriented loops $L_1, \dots, L_k$ derived from the voxel's configuration [S1].

### Precomputation
Before processing the volume, the algorithm precomputes the 256 local configuration tables for the chosen connectedness couple [S1]. This is done using the `Build-Local_Surface` procedure for each of the 256 possible binary configurations [S1].

### Algorithm Steps

1.  **Precompute Local Tables:**
    For each of the 256 binary configurations $C$ of a voxel:
    - Call `Build-Local_Surface(C, \alpha)` to determine the local surface subdivision.
    - Store the result in the lookup table for configuration $C$ [S1].

2.  **Construct Complete Graph:**
    Build the complete graph $G_\lambda(I)$ by assembling the local graphs from all voxels in the image. This can be done efficiently using surface tracking, resulting in complexity $O(s)$ where $s$ is the number of surfels (typically $O(n^2)$ for an $n \times n \times n$ volume) [S1].

3.  **Surface Extraction:**
    For each voxel in the volume:
    - Determine the binary configuration of its 8 corners.
    - Retrieve the precomputed local triangulation from the lookup table.
    - Insert the triangles/loops into the global mesh structure, ensuring consistent orientation across shared faces [S1].

### `Build-Local_Surface` Procedure
This procedure computes the local triangulated manifold $S_\lambda(C_8)$ for a given voxel configuration $C$ and foreground connectivity $\alpha$ [S1].

**Inputs:**
- $C$: The binary configuration of the voxel (8 bits).
- $\alpha$: The foreground connectivity (18 or 26).

**Outputs:**
- $s$: The set of loops/triangles defining the local surface.

**Pseudocode:**
```python
def Build_Local_Surface(Configuration C, int alpha):
    # Initialize edge set E
    E = EmptySet()
    
    # Extract edges from all inner 6-faces of the voxel
    # Note: "inner 6-faces" refers to the faces of the voxel cube
    for each inner_face F in C:
        EF = Extract_Edges(F, g=6, connectivity=6)
        E = E union EF
    
    # Extract loops from the edge set
    L = Extract_Loops(E)
    
    # Compute the convex hull H of the vertices involved in the edges
    # and the 1-voxels (foreground voxels) in C
    H = Convex_Hull(get_vertices(E) union get_1_voxels(C))
    
    # Subdivide long loops
    while s contains a loop L of length > 3:
        # Remove a loop L of length > 3 from s
        # L is an ordered set (a1, ..., ak) of vertices
        L = Remove_A_Loop_Of_Length_Greater_Than_3(s)
        
        exit = false
        i = 1
        j = i + 2
        
        repeat:
            if (ai, aj) is in H:
                exit = true
            else:
                j = j + 1
                if j == k:
                    i = i + 1
                    j = i + 2
            until exit
        
        # Insert the subdivided loop and the chord
        Insert_Loop((a1, ..., ai, aj, ..., ak), s)
        Insert_Loop(ai, ..., aj, L)
    
    # Handle strict 26-adjacency case
    if Configuration.strict_26_adj(C) and alpha == 26:
        s = Build_Special_Loops_26_Adj(s)
    
    return s
```

**Helper Definitions:**
- `Extract_Edges(F, g, 6)`: Extracts the edges of the face $F$ that cross the isosurface threshold, based on the connectivity $g=6$ (background connectivity) [S1].
- `Extract_Loops(E)`: Constructs the oriented loops from the edge set $E$ [S1].
- `Convex_Hull(V)`: Computes the convex hull of the set of vertices $V$ [S1].
- `Build_Special_Loops_26_Adj(s)`: Generates special loops for the strict 26-adjacency case [S1].

### Parameters
- **Connectedness Couple $(\alpha, \lambda)$:** Must be one of the valid couples: $(26, 6)$, $(18, 6)$, $(6, 26)$, or $(6, 18)$ [S1].
- **Strict 26-Adjacency:** A boolean flag indicating if the configuration exhibits strict 26-adjacency. If true and $\alpha=26$, special loop construction is used; if $\alpha=18$, the local graph is not modified in this case [S1].

### Edge Cases and Pitfalls
- **Strict 26-Adjacency:** If the configuration has strict 26-adjacency and $\alpha=26$, the standard subdivision is replaced by special loops generated by `build_special_loops_26-adj`. If $\alpha=18$, the local graph is not modified in this case [S1].
- **Ambiguity Resolution:** The method resolves topological ambiguities inherent in the trilinear interpolant by enforcing connectivity constraints, avoiding the need for continuous field evaluation [S1].

## Operating characteristics
- **Time Complexity:** Standard Marching Cubes is $O(n^3)$ where $n^3$ is the volume size. Using surface tracking to build the complete graph, the complexity is $O(s)$ where $s$ is the number of surfels (typically $O(n^2)$) [S1].
- **Memory Complexity:** Requires storage for the 256 precomputed local configuration tables. The size of each table depends on the maximum number of triangles/loops in a local configuration, which is small and constant [S1].
- **Strengths:** Guarantees topological correctness (2-manifold without singularities) for binary volumes. Efficient for large volumes due to $O(s)$ complexity. Compatible with classical Marching Cubes optimizations [S1].
- **Limitations:** Only applicable to binary volumes. Requires precomputation of lookup tables. The method is discrete and may not capture fine details of continuous fields as accurately as asymptotic methods [S1].
- **When to Use:** Segmentation of medical images (e.g., CT scans) where topological correctness is critical and the data is binary [S1].

## Background
The method was introduced by [S1] as a topologically and formally proved approach for extracting consistent isosurfaces from volumetric images. It establishes the identity between the underlying graph of the isosurface and the surfel-adjacency graph of the digital surface. The algorithm has been implemented and validated with synthetic data and is used in the segmentation of medical images, specifically for CT scans (e.g., 256x256x113 resolution) [S1].
