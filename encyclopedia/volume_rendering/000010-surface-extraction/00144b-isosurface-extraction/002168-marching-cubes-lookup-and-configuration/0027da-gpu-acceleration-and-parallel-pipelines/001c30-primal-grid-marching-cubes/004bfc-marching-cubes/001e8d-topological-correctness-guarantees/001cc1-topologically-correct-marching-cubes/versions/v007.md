# Topologically Correct Marching Cubes


## Overview
Topologically Correct Marching Cubes (TMC) is an extension to the standard Marching Cubes algorithm that guarantees the output mesh is homeomorphic to the trilinear interpolant of the input scalar field within each voxel [S1, unofficial][S2]. It solves the problem of topological errors in standard Marching Cubes, such as the creation of disconnected sheets where a tunnel or saddle point exists, by inserting additional vertices within ambiguous cells [S1, unofficial][S2]. Unlike standard Marching Cubes, TMC accurately represents small complex features and ensures the mesh is 2-manifold and watertight, provided the isosurface does not intersect the domain boundaries [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field defined on a 3D grid (domain), an isovalue, and the standard Marching Cubes vertex values at grid corners.
*   **Output:** A triangular mesh (list of vertices and polygons) that is homeomorphic to the trilinear isosurface [S1, unofficial][S2].

**Data Structures:**
The method extends the standard voxel processing. When a cell is identified as ambiguous (specifically the cases involving saddle points or tunnels, such as cases 7, 8, 11, 12 in the standard 15-case table), the algorithm requires the ability to place a new vertex inside the cell.
*   **Cell Center Vertex:** A new vertex is inserted at the center of the ambiguous cell (or at an optimized position) to resolve the topology [S1, unofficial][S2].

**Algorithm Steps:**
1.  **Standard Classification:** For each voxel, determine the standard Marching Cubes case based on the signs of the scalar values at the 8 corners relative to the isovalue.
2.  **Ambiguity Detection:** Identify cells that fall into ambiguous cases where the standard linear edge interpolation fails to capture the topology of the trilinear interpolant. These cases typically involve saddle points or tunnels within the cell [S1, unofficial][S2].
3.  **Vertex Insertion:** For ambiguous cells, insert an additional vertex. The sources indicate this vertex is placed at the center of the cell [S1, unofficial][S2]. Note: Some implementations may optimize this position using Quadric Error Metrics (QEM) similar to Dual Contouring, but the core TMC definition specifies center placement [S1, unofficial].
4.  **Topology Resolution:** Connect the edge intersection points to the newly inserted internal vertex (or between internal vertices if multiple are needed, though TMC typically uses one per cell) to form triangles that correctly represent the tunnel or saddle topology [S1, unofficial][S2]. This replaces the standard triangulation for that cell.
5.  **Mesh Assembly:** Combine the triangles from all cells. The resulting mesh is guaranteed to be 2-manifold and watertight if the isosurface does not intersect the domain boundaries [S1, unofficial][S2].

**Edge Cases and Pitfalls:**
*   **Boundary Intersection:** The guarantee of the mesh being 2-manifold and watertight holds *only* if the isosurface does not intersect the domain boundaries [S1, unofficial][S2]. If it does, the manifold property may be violated.
*   **Sharp Features:** TMC does not guarantee the recovery of sharp features present in the input field, unlike Dual Contouring [S2].
*   **Precision:** As with all Marching Cubes variants, precision issues near the isovalue can affect the position of edge intersections.

## Operating characteristics
*   **Time Complexity:** Similar to standard Marching Cubes, $O(N)$ where $N$ is the number of voxels, with a constant factor increase due to the handling of ambiguous cases and vertex insertion.
*   **Memory Complexity:** Increases slightly due to the potential insertion of additional vertices in ambiguous cells.
*   **Performance:** Accurately represents small complex features (e.g., tunnels) that standard MC misses [S2].
*   **Strengths:** Topological correctness (homeomorphic to trilinear interpolant), 2-manifold and watertight output (under boundary conditions) [S1, unofficial][S2].
*   **Limitations:** Does not recover sharp features as well as Dual Contouring [S2]. Relies on the assumption that the trilinear interpolant is the desired surface model.
*   **When to use:** When topological correctness is critical and the input data is well-behaved (no sharp features requiring higher-order interpolation).
*   **When not to use:** When sharp feature preservation is required (use Dual Contouring) or when the isosurface intersects domain boundaries (manifold guarantee fails).

## Background
Topologically Correct Marching Cubes was introduced by Roberto Grosso in the paper "Construction of topologically correct and manifold isosurfaces" published in *Computer Graphics Forum*, volume 35, pages 187–196, by Wiley Online Library in 2016 [S1, unofficial][S2]. It is implemented in the CGAL library's "3D Isosurfacing" package, available since CGAL 6.1 (released fall 2025) [S1, unofficial][S2].
