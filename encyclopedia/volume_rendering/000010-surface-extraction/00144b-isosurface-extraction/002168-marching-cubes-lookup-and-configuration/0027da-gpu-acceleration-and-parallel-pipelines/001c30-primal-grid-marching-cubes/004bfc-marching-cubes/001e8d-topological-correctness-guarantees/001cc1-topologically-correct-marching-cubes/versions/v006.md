# Topologically Correct Marching Cubes


## Overview
Topologically Correct Marching Cubes (TMC) is an extension to the standard Marching Cubes algorithm that guarantees the output mesh is homeomorphic to the trilinear interpolant of the input scalar field within each voxel [S1, unofficial][S2]. While standard Marching Cubes relies on a lookup table that can produce topologically incorrect results (such as disconnected sheets instead of a tunnel) in ambiguous cases, TMC resolves these ambiguities by inserting additional vertices within cells [S1, unofficial][S2]. This ensures the mesh accurately represents small complex features and remains a 2-manifold, provided the isosurface does not intersect the domain boundaries [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A domain defined by a grid of voxel vertices with associated scalar values, and an isovalue $\alpha$.
*   **Output:** A polygonal mesh (typically triangles) representing the isosurface $g(x,y,z) = \alpha$, where $g$ is the trilinear interpolant.

**Data Structures:**
The implementation maintains a list of output vertices and polygons. When TMC is active, it may generate new vertices inside the voxel volume that are not present in the original grid.

**Algorithm Steps:**
1.  **Standard Lookup:** For each voxel, determine the standard Marching Cubes case based on the signs of the eight vertex values relative to the isovalue.
2.  **Ambiguity Detection:** Identify cases where the standard lookup table is insufficient to determine the topology of the trilinear interpolant. These are the "ambiguous" cases (typically cases 6, 7, 10, and 11 in the standard 15-case table) where the surface may contain a saddle point or tunnel [S1, unofficial][S2].
3.  **Topology Resolution:** For ambiguous cases, TMC inserts additional vertices within the cell to resolve the topology. The sources indicate these vertices are placed at the center of the cell or optimized using Quadric Error Metrics (QEM) for Dual Contouring [S1, unofficial].
4.  **Mesh Generation:** Generate triangles connecting the edge intersection points and the newly inserted internal vertices to form a mesh homeomorphic to the trilinear interpolant [S1, unofficial][S2].
5.  **Boundary Check:** Ensure the mesh is 2-manifold and watertight. This guarantee holds only if the isosurface does not intersect the domain boundaries [S1, unofficial][S2].

**Pseudocode:**
The following pseudocode illustrates the decision logic for a single voxel, assuming a standard Marching Cubes implementation is extended with TMC logic.

```python
def marching_cubes_tmc(voxel, isovalue):
    # 1. Determine standard case index
    case_index = 0
    for i in range(8):
        if voxel.vertices[i].value > isovalue:
            case_index |= (1 << i)
    
    # 2. Check if TMC is enabled and case is ambiguous
    if use_topologically_correct_marching_cubes and case_index in AMBIGUOUS_CASES:
        # 3. Insert additional vertex at cell center (or optimized position)
        center_vertex = create_vertex_at_center(voxel)
        
        # 4. Resolve topology by connecting edge intersections to center
        # The specific triangulation depends on the sign of the trilinear 
        # interpolant at the center or other topological criteria.
        # Note: Exact formula for center value evaluation is not detailed in sources [S1, unofficial][S2].
        # [G] Typically, the value at the center is computed via trilinear interpolation.
        center_value = trilinear_interpolate(voxel, center_vertex.position)
        
        # 5. Generate triangles based on resolved topology
        triangles = resolve_ambiguous_topology(case_index, edge_intersections, center_vertex)
        return triangles
    else:
        # Standard Marching Cubes lookup
        return standard_marching_cubes_lookup(case_index, edge_intersections)
```

**Parameters:**
*   `use_topologically_correct_marching_cubes`: Boolean flag. Set to `true` to enable TMC [S2].

**Edge Cases and Pitfalls:**
*   **Domain Boundaries:** The guarantee of the mesh being 2-manifold and watertight holds only if the isosurface does not intersect the domain boundaries [S1, unofficial][S2].
*   **Sharp Features:** TMC does not guarantee the recovery of sharp features present in the input field [S2].
*   **Complexity:** TMC accurately represents small complex features (e.g., tunnels) but may produce poor mesh quality (needle or cap-shaped triangles) if not combined with mesh improvement techniques [S2].

## Operating characteristics
*   **Time Complexity:** Higher than standard Marching Cubes due to the need for ambiguity detection and additional vertex insertion/triangulation logic.
*   **Memory Complexity:** Increased memory usage due to the potential creation of additional internal vertices per ambiguous voxel.
*   **Performance:** TMC accurately represents small complex features and ensures topological correctness [S2]. However, it does not guarantee recovery of sharp features [S2].
*   **Strengths:** Guarantees a mesh homeomorphic to the trilinear interpolant; resolves tunnels and complex topologies within single cells [S1, unofficial][S2].
*   **Limitations:** Mesh quality can be poor (needle/cap triangles) without post-processing; does not handle sharp features well; boundary conditions must be managed to maintain watertightness [S1, unofficial][S2].
*   **When to use:** When topological correctness is critical, especially for volumes with complex internal structures like tunnels or handles.
*   **When not to use:** When sharp feature preservation is required or when computational resources are extremely limited and topological errors are acceptable.

## Background
Topologically Correct Marching Cubes was introduced by Roberto Grosso in the paper "Construction of topologically correct and manifold isosurfaces" published in *Computer Graphics Forum*, volume 35, pages 187–196, by Wiley Online Library in 2016 [S1, unofficial]. The method is implemented in the CGAL "3D Isosurfacing" package, which became available in CGAL 6.1 (released fall 2025) [S1, unofficial][S2].
