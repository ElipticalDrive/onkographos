# Extended Marching Cubes

Also called: Feature Sensitive Surface Extraction

## Overview
Extended Marching Cubes (EMC) is a surface extraction method that enhances the classic Marching Cubes algorithm by improving the reproduction of sharp edges and corners, even when they are not aligned with the grid [S1, S2, unofficial]. It achieves this by modifying the field function to return a 3D distance vector for exact intersection computation and employing Quadric Error Functions (QEF) to reconstruct sharp features detected via normal vector analysis [S2, unofficial]. Unlike standard Marching Cubes, which produces smooth approximations, EMC explicitly places new vertices at feature locations to preserve geometric detail [S1, unofficial].

## How it works
### Inputs and Outputs
- **Input**: A 3D scalar field (implicit surface) defined on a primal grid. The field function $f(x, y, z)$ is modified to return a 3D vector representing the distance from the contour on each axis [S2, unofficial].
- **Output**: A polygonal mesh (vertices and indices) representing the isosurface [S1, unofficial].

### Data Structures
- **Primal Grid**: The domain is traversed voxel by voxel [S1, unofficial].
- **Vertices**: Stored in a mesh builder. Feature vertices are marked with `None` as their grid key, while standard intersection vertices retain their grid association [S1, unofficial].
- **Features Set**: A `HashSet` of vertex indices that have been identified as feature points (sharp corners/edges) [S1, unofficial].
- **Tangent Planes**: Computed from edge crossings to define the local geometry for QEF solving [S1, unofficial].
- **Edge Loops**: Precomputed topology data (`EDGE_LOOPS`) indicating the number of loops and vertices per loop for each of the 256 cube configurations [S1, unofficial].

### Steps

1.  **Field Function Modification**: The implicit field function is extended to return three values: the distance from the contour along the X, Y, and Z axes independently [S2, unofficial].
    $$
    \begin{aligned}
    n_x &= f(x + E, y, z) - f(x, y, z) \\
    n_y &= f(x, y + E, z) - f(x, y, z) \\
    n_z &= f(x, y, z + E) - f(x, y, z)
    \end{aligned}
    $$
    where $E$ is a small epsilon [S2, unofficial].

2.  **Grid Traversal**: Traverse the primal grid. For each voxel (cube), retrieve the corner values [S1, unofficial].

3.  **Cube Index Classification**: Classify the 8 corners of the cube relative to the isolevel to determine the `cube_index` (0–255) [S1, unofficial].

4.  **Edge Crossing Detection**: Identify which edges of the cube are intersected by the isosurface. Populate the `vertices` array with the intersection points [S1, unofficial].
    - Intersection coordinates are computed using linear interpolation on the respective components of the modified field function. For example, the X coordinate is computed using only the X component of the field result [S2, unofficial].

5.  **Normal Sampling**: Sample the normal vectors at each edge crossing point. The normal is approximated as the gradient of the field function [S2, unofficial].

6.  **Feature Detection**: Compute the angle between the normal vectors of adjacent intersection points on the cube edges [S2, unofficial].
    - If the angle is smaller than a threshold (e.g., 90 degrees), a sharp feature is detected [S2, unofficial].
    - [G] The angle $\theta$ between two normal vectors $\mathbf{n}_1$ and $\mathbf{n}_2$ is computed as $\theta = \arccos(\mathbf{n}_1 \cdot \mathbf{n}_2)$.

7.  **Feature Point Placement**: If a feature is detected (non-planar configuration):
    - Create tangent planes from the edge crossings [S1, unofficial].
    - Solve for the feature point location by minimizing the Quadric Error Function (QEF) using the tangent planes [S1, unofficial].
    - Add this `feature_point` as a new vertex to the mesh with no grid key [S1, unofficial].
    - Insert the new vertex index into the `features` HashSet [S1, unofficial].

8.  **Mesh Construction (Triangle Fan)**: For each edge loop in the cube configuration:
    - Get the number of loops and vertices from `EDGE_LOOPS` [S1, unofficial].
    - For each vertex in the loop, form a triangle using the existing edge vertices and the `center_index` (the feature point if present, or the standard center if no feature is detected) [S1, unofficial].
    - Specifically, for vertices $e_0$ and $e_1$ in the loop, add face $(a, b, \text{center\_index})$ [S1, unofficial].

9.  **Edge Flipping (Post-Processing)**: After traversal, iterate over all edges in the mesh to resolve topological inconsistencies at feature boundaries [S1, unofficial].
    - For each edge, check if both start and end vertices are in the `features` set. If so, skip [S1, unofficial].
    - Get the adjoining faces of the edge [S1, unofficial].
    - If specific topological conditions are met (implied by "If condition met" in source), add the edge to a `flips` set [S1, unofficial].
    - Iterate over `flips` and call `mesh.rotate_edge(edge)` to flip the edge connectivity [S1, unofficial].

### Parameters
- **Feature Threshold**: Angle threshold for detecting sharp features. Typical value: 90 degrees [S2, unofficial].
- **Epsilon (E)**: Small value for gradient approximation in field function modification [S2, unofficial].

### Pitfalls
- **Neighboring Dependencies**: The edge-flipping step requires information from neighboring chunks, which can complicate parallel or chunked processing [S1, unofficial].
- **Sliver Triangles**: The method may produce small triangle slivers on sharp edges [S1, unofficial].
- **Normal Convergence**: The extracted surface normals may not converge to the true surface normals [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Similar to Marching Cubes per voxel, but with additional overhead for QEF solving and normal analysis [S2, unofficial].
- **Memory Complexity**: Increased due to storage of feature vertices and the `features` HashSet [S1, unofficial].
- **Strengths**: Better reproduction of sharp edges and corners compared to standard Marching Cubes [S1, S2, unofficial].
- **Limitations**: Potential for sliver triangles; requires post-processing edge flipping which has chunk dependencies [S1, unofficial].

## Background
Extended Marching Cubes was introduced in the paper "Feature Sensitive Surface Extraction from Volume Data" [S1, S2, unofficial]. It addresses the limitations of classic Marching Cubes in handling sharp features by using QEFs and modified field functions [S2, unofficial].
