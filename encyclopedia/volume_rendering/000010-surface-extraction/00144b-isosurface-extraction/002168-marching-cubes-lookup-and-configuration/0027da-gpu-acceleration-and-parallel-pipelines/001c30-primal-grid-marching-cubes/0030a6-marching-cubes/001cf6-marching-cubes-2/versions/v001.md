# Marching Cubes 2


## Overview
Marching Cubes 2 is a variant of the Marching Cubes algorithm that modifies the standard lookup table and configuration logic to resolve topological ambiguities, specifically face-saddle ambiguities in the trilinear interpolant [S3, unofficial]. It increases the number of topological configurations from 15 to 24 to effectively avoid the generation of voids in the extracted mesh [S4, abstract only, unofficial]. It is also used as a helper method for resolving these ambiguities via the Asymptotic Decider [S3, unofficial].

## How it works
**Inputs:**
*   A 3D scalar field (grid) of size $N_x \times N_y \times N_z$ [S1, unofficial][S4, abstract only, unofficial].
*   An isovalue (isolevel) $I$ [S1, unofficial][S4, abstract only, unofficial].
*   The grid data array [S1, unofficial].

**Outputs:**
*   A list of vertices (points) and polygons (triangles) representing the isosurface [S1, unofficial][S4, abstract only, unofficial].
*   Alternatively, individual points at the isovalue surface if the resolution is high enough that triangle count exceeds pixel count [S2, unofficial].

**Data Structures:**
*   **Grid:** A 3D array of scalar values.
*   **Lookup Table:** An extended table with 24 topological configurations (increased from the standard 15) [S4, abstract only, unofficial].
*   **Thread Classification:** The 24 configurations are divided into three types for parallel processing [S4, abstract only, unofficial].

**Steps:**
1.  **Preparation:** Validate the 3D grid dimensions. Extract the shape and compute bounds, $N_x$, $N_y$, and $N_z$. Initialize output vectors for vertices and polygons [S1, unofficial][S4, abstract only, unofficial].
2.  **Configuration Classification:** Divide the 24 topological configurations into three classes. Each class corresponds to a specific thread for multi-thread parallel processing [S4, abstract only, unofficial].
3.  **Ambiguity Resolution:** For each cube, determine the case index. If the case involves a face-saddle ambiguity, call the `Asymptotic_Decider` or `Disambiguate_Face` helper function to resolve the topology [S3, unofficial].
4.  **Vertex/Point Generation:**
    *   For standard meshing: Use the lookup table to determine the triangulation.
    *   **Midpoint Selection:** To improve speed, use midpoint selection instead of linear interpolation for vertex positions [S4, abstract only, unofficial].
    *   For point cloud generation: Generate individual points at each isovalue surface intersection instead of triangles [S2, unofficial]. The density of points is controlled by the relative difference between pixel and volume element sampling rates [S2, unofficial].
5.  **Parallel Processing:**
    *   Divide the grid processing among threads based on the configuration classes [S4, abstract only, unofficial].
    *   Use a critical region to realize multi-thread synchronization [S4, abstract only, unofficial].
    *   Design a protocol mapping table (based on message mapping table ideas) to encapsulate the processing functions. Trigger the function pointer by macro to call the processing function [S4, abstract only, unofficial].
6.  **Output Assembly:** Collect the generated vertices and polygons/triangles/points into the final output structures [S1, unofficial][S4, abstract only, unofficial].

## Subtopics

### [Extended Marching Cubes with No Degenerate Triangles](2186-extended-marching-cubes-with-no-degenerate-triangles.md)
A variant that uses an extended lookup table to avoid degenerate triangles and ensures separation of positive/negative regions.

### [Extended Marching Cubes Lookup Table](2187-extended-marching-cubes-lookup-table.md)
A lookup table distinguishing scalar values equal to the isovalue from those greater, avoiding degenerate triangles.

### [Contouring Discrete Indicator Functions](4087-contouring-discrete-indicator-functions.md)
A method for DIFs that replaces linear interpolation with area-matching solutions on a dual grid.

### [2D Reduction for 3D DIF Contouring](4301-2d-reduction-for-3d-dif-contouring.md)
Uses 2D intersection formulas for 3D grid edges for more accurate approximation of linear functions.

### [Marching Cubes with Topological Correction (Case 6c)](4349-marching-cubes-with-topological-correction-case-6c.md)
Resolves topological inconsistencies (holes) by using alternate facetization for Case 6 adjacent to Case 3.

### CUDA Isosurface Extraction with Overlapped Execution
An optimization for CUDA-based isosurface extraction that overlaps data transfers and kernel executions to hide latency [S5]. It executes three overlapping pairs of operations: 1) calculation of vertices and transfer of triangles from the previous slice pair; 2) calculation of triangles and transfer of vertices; 3) compaction of triangles and transfer of the next slice [S5]. Constant memory is used for the lookup table and isovalue [S5]. Device initialization takes ~4 seconds, negligible for large datasets but significant for small ones (<100 MB) [S5]. For a 2048x2048x6936 dataset (23 GB), 16 GTX480 devices achieved speedups of 752.3x (isovalue 1000) and 1489.7x (isovalue 4000) [S5].

### Finite State Machine for Interpolant Modelling
A representation of isosurface evolution by sweeping from high to low isovalues, where states are cases and transitions occur when a vertex changes from white (lower than $h$) to black (higher than $h$) [S6, unofficial]. The FSM is constructed by defining states as cases and adding transitions from each state to each other case with one extra black vertex [S6, unofficial]. Each cube starts with case 0. For example, case 2 (two edge-adjacent black vertices) cannot sweep to case 7 (no edge-adjacent black vertices) because topology forbids losing edge adjacency [S6, unofficial]. This is used to model watertight Marching Cubes cases and prove completeness of Nielson's cases [S6, unofficial].

## Operating characteristics
*   **Speed:** The improved MC algorithm (with 24 configurations and midpoint selection) is approximately 30% faster than the standard MC algorithm and 40% faster than the Masala algorithm [S4, abstract only, unofficial].
*   **Parallelism:** Uses multi-thread parallel processing with 3 thread types for 24 configurations, synchronized via critical regions [S4, abstract only, unofficial].
*   **Memory:** Uses constant memory for lookup tables and isovalue in GPU implementations [S5].
*   **Accuracy:** Increases topological configurations to 24 to avoid voids [S4, abstract only, unofficial]. Resolves face-saddle ambiguities using the Asymptotic Decider [S3, unofficial].
*   **Use Cases:** Medical image 3D reconstruction, where accuracy and speed are critical [S4, abstract only, unofficial]. Also used when data resolution increases such that triangle count exceeds pixel count, generating points instead of triangles [S2, unofficial].

## Background
Marching Cubes 2 was introduced by Nielson & Hamann in 1991 in the paper "The asymptotic decider: Resolving the ambiguity in marching cubes" [S3, unofficial]. It was developed to address the face-saddle ambiguities present in the original trilinear interpolant used in the standard Marching Cubes algorithm [S3, unofficial]. The variant with 24 configurations and midpoint selection was later proposed in a 2020 paper for improved 3D reconstruction speed and void avoidance [S4, abstract only, unofficial].
