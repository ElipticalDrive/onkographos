# Dual Marching Squares

Also called: Schaefer's and Warren's Dual Marching Cubes (2D variant)

## Overview
Dual Marching Squares (DMS) extracts a polygonal mesh from a 2D implicit scalar field by placing a single vertex inside each grid cell that intersects the isosurface, rather than on the cell edges [S1, unofficial]. It uses a Quadratic Error Function (QEF) to determine the optimal vertex position that best fits the sampled surface normals and intersection points within that cell [S1, unofficial]. Unlike standard [Marching Squares](918-marching-squares.md), which produces line segments with vertices on grid edges, DMS produces a quad-based topology (in its adaptive quadtree variant) or a simplified mesh where vertices are "dual" to the grid cells, allowing for smoother surfaces but potentially losing sharp feature preservation [S2, unofficial].

## How it works
The method operates on a 2D scalar field $f(x,y)$. It identifies cells where the isosurface passes and computes a representative vertex for each such cell. The implementation can be uniform (grid-based) or adaptive (quadtree-based) [S1, S2, unofficial].

### Inputs and Outputs
**Inputs:**
- Scalar field function $f(x,y)$ or sampled grid values.
- Isosurface threshold value $t$.
- Grid bounds and resolution (for uniform) or max/min quadtree sizes (for adaptive).

**Outputs:**
- A list of vertices $P$, each with position, normal, and value.
- A list of indices defining the mesh topology (quads or lines, depending on the variant's final assembly).

### Data Structures

#### Uniform Grid Variant (QEF-based) [S1, unofficial]
- **QEF Coefficients Array `f`**: Flat array storing 7 coefficients per cell. Layout:
  - `f[0]`: $A^T A_{00}$
  - `f[1]`: $A^T A_{01}$ (symmetric to `f[2]`)
  - `f[2]`: $A^T A_{11}$
  - `f[3]`: $(A^T b)_0$
  - `f[4]`: $(A^T b)_1$
  - `f[5]`: $p_{c,x}$ (mass point x)
  - `f[6]`: $p_{c,y}$ (mass point y)
- **Index Buffer `ibuffer`**: Integer array initialized to -1. Stores cell indices for each grid vertex to track ownership across tiles. Size: $2 \times (N_x - 1) \times N_y$ (or similar, depending on tiling) [S1, unofficial].
- **Edges Array `edges`**: Flat integer array storing vertex pairs. Layout: `{self, node}` and `{self, down}` in consecutive slots `2*ei` and `2*(ei+1)` [S1, unofficial].

#### Adaptive Quadtree Variant [S2, unofficial]
- **QuadtreeNode**:
  - `position`: Vector2 (top-left or center, depending on implementation; notes suggest position + offset logic).
  - `size`: int (width/height of the node).
  - `children`: QuadtreeNode[4].
  - `dualgrid_pos`: Vector2 (offset from position to the dual vertex).
  - `isovalue`: float (sampled value at dual position).
  - `normal`: Vector2 (gradient normal at dual position).
  - `leaf`: bool.
  - `vertex_index`: int (index in the global vertices list).
  - `index`: int.
- **VertexPositionColorNormal**: Contains `Vector3 Position`, `Color Color`, `Vector3 Normal`.
- **Connectivity Tables**:
  - `edges[4][2]`: {{0, 2}, {1, 3}, {0, 1}, {2, 3}}. Maps edge index to corner indices.
  - `edge_children[2][2][2]`: {{{2, 0}, {3, 1}}, {{1, 0}, {3, 2}}}. Maps parent edge children to child quad edges.
  - `vertex_children[2][2][2]`: {{{2, 3}, {0, 1}}, {{1, 3}, {0, 2}}}. Maps parent vertex children to child quad vertices.
  - `middle_points[4]`: {3, 2, 1, 0}.
  - `connect_points[4]`: {0, 2, 3, 1}.

### Steps

#### 1. Sampling and Gradient Estimation
Sample the scalar field at grid points. Compute normals using finite differences [S1, unofficial].
- Step size for gradient: $dh = 10^{-5}$ [S1, unofficial].
- Gradient $\nabla f$ at point $(x,y)$:
  $$ \frac{\partial f}{\partial x} \approx \frac{f(x+dh, y) - f(x-dh, y)}{2dh} $$
  $$ \frac{\partial f}{\partial y} \approx \frac{f(x, y+dh) - f(x, y-dh)}{2dh} $$
- Normalize the gradient to get the surface normal $\mathbf{n}$ [S1, unofficial].

#### 2. Cell Classification and QEF Construction (Uniform) [S1, unofficial]
For each cell, determine if the isosurface intersects it. If so, collect intersection points and normals.
- Let $\mathbf{p}_i$ be intersection points and $\mathbf{n}_i$ be normals.
- Construct the QEF matrix $A$ and vector $b$ where each row $i$ is $\mathbf{n}_i^T$ and $b_i = \mathbf{n}_i \cdot \mathbf{p}_i$.
- Compute $A^T A$ diagonal elements:
  $$ f[2] = A[1]^2 + A[3]^2 + A[5]^2 + A[7]^2 $$
  (Note: Source [S1, unofficial] implies specific indexing for a 2x2 case or specific number of intersections. Generally, $A^T A = \sum \mathbf{n}_i \mathbf{n}_i^T$) [S1, unofficial].
- Compute $A^T b$ vector:
  $$ f[3] = \sum A_{i,0} b_i, \quad f[4] = \sum A_{i,1} b_i $$
- Compute mass point (centroid of intersections):
  $$ p_c = \frac{1}{k} \sum \mathbf{p}_i $$
  where $k$ is the number of intersections [S1, unofficial].

#### 3. QEF Solution
Solve for the vertex position $\mathbf{p}$ that minimizes the QEF [S1, unofficial].
- Assemble $A^T A$ in row-major layout:
  $$ ATA = \begin{bmatrix} f[0] & f[1] \\ f[1] & f[2] \end{bmatrix} $$
- Compute $A^T A p_c$:
  $$ ATAg[0] = ATA[0]p_{c,x} + ATA[1]p_{c,y} $$
  $$ ATAg[1] = ATA[2]p_{c,x} + ATA[3]p_{c,y} $$
- Compute residual $d$:
  $$ d[0] = f[3] - ATAg[0] $$
  $$ d[1] = f[4] - ATAg[1] $$
- Compute pseudo-inverse of $ATA$, denoted $pinv$. For a 2x2 symmetric matrix:
  $$ ATA^{-1} = \frac{1}{\det(ATA)} \begin{bmatrix} ATA[3] & -ATA[1] \\ -ATA[1] & ATA[0] \end{bmatrix} $$
  (Handle singular matrices with epsilon $\epsilon = 10^{-6}$) [S1, unofficial].
- Compute offset $c$:
  $$ c[0] = pinv[0]d[0] + pinv[1]d[1] $$
  $$ c[1] = pinv[2]d[0] + pinv[3]d[1] $$
- Final position:
  $$ \mathbf{p} = p_c + c $$
  $$ px = c[0] + f[5], \quad py = c[1] + f[6] $$
- Store vertex coordinates in output array `p` at index `2*pi` and cell index `pi` in `ibuffer[bi]` [S1, unofficial].

#### 4. Adaptive Quadtree Construction [S2, unofficial]
1. Initialize root node with size, position, and parameters.
2. Call `TrySplit(node, min_size, threshold, grid_size, vertices)`:
   - Check split conditions:
     1. Center sample value > size * $\sqrt{2}$ * `minSplitDistanceDiagonalFactor` (default 1000.0).
     2. `node.size` <= `min_size`.
     3. `GetError(threshold)` < `threshold`.
   - If any condition is true, create a leaf:
     - Set `dualgrid_pos` = $0.5 \times \text{size} \times (1,1)$.
     - Sample isovalue and normal at `position + dualgrid_pos`.
     - Create vertex with position `(position + dualgrid_pos) * grid_size`, color (210, 220, 210), and normal.
     - Add to vertices list, set `leaf = true`, return.
   - If not a leaf, split into 4 children:
     - For $i \in \{0,1,2,3\}$:
       - Create child node.
       - `child.index` = $i$.
       - `child.position` = `position` + $\frac{\text{size}}{2} (i/2, i\%2)$.
       - `child.size` = $\text{size} / 2$.
       - Recursively call `TrySplit` on child.

#### 5. Mesh Topology Assembly (Adaptive) [S2, unofficial]
Call `ConstructTreeGrid` to generate indices.
- `ProcessFace(node)`:
  - Recursively process 4 children.
  - Process 4 edges between children.
  - Process 4 vertices of the node.
- `ProcessEdge(q1, q2, edge_index)`:
  - If both `q1` and `q2` are leaves, return.
  - Recursively process sub-edges using `edge_children` mapping.
  - Call `ProcessVertices` on the 4 leaf nodes surrounding the edge.
- `ProcessVertices(q1, q2, q3, q4)`:
  - If any child is not a leaf, resolve to middle-point children and recurse.
  - If all are leaves, create a Cell (quad).
  - Add indices for 4 vertices in order using `connect_points`: `connect_points[i]` and `connect_points[(i+1)%4]`.
  - Set Cell's positions, values, and normals from leaf nodes' `dualgrid_pos`, `isovalue`, and `normal`.

### Parameters
- `threshold`: Isosurface value [S2, unofficial].
- `min_size`: Minimum quadtree leaf size [S2, unofficial].
- `minSplitDistanceDiagonalFactor`: Splitting heuristic factor, default 1000.0 [S2, unofficial].
- `dh`: Finite difference step, $10^{-5}$ [S1, unofficial].
- `eps`: Pseudo-inverse convergence epsilon, $10^{-6}$ [S1, unofficial].

### Edge Cases and Pitfalls
- **Tile Boundaries**: In tiled implementations, boundary vertices require cross-tile synchronization and shared memory reduction to correctly compute edge counts and prefix sums. Boundary vertices at tile edges must be handled to avoid duplicate edges or missing connections [S1, unofficial].
- **Error Function Flaw**: The `GetError` function can fail when sampled points have very similar values, leading to negligible error calculation even for complex surfaces. Fixes include sampling more points (corners, midpoints, in-between) or using a maximum container size [S2, unofficial].
- **Sharp Features**: Standard DMS places vertices at cell centers (dual grid positions) and does not preserve sharp features [S2, unofficial].

### Dual Marching Squares Error Function
A variant that substitutes the standard error-reducing function with a separate, faster alternative function to optimize the adaptive splitting decision [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Depends on the variant. Uniform grid is $O(N)$ where $N$ is the number of cells. Adaptive quadtree is $O(N \log N)$ or better depending on surface complexity, as it only subdivides cells near the isosurface.
- **Memory Complexity**: $O(N)$ for uniform. Adaptive uses quadtree nodes, which can be more or less memory-intensive depending on the depth and distribution of the surface.
- **Performance**: The adaptive quadtree variant allows for high-resolution details where needed and coarser representation elsewhere, reducing overall vertex count for smooth surfaces [S2, unofficial]. The QEF solve is a small 2x2 linear system, which is computationally cheap per cell [S1, unofficial].
- **Strengths**: Produces smoother meshes than Marching Squares; adaptive resolution reduces data size; single vertex per cell simplifies topology in some contexts [S2, unofficial].
- **Limitations**: Does not preserve sharp features (corners/edges) as well as methods that move vertices to features (like standard Dual Contouring in 3D) or Marching Cubes with feature preservation [S2, unofficial]. Requires careful handling of connectivity in adaptive variants [S2, unofficial].

## Background
Dual Marching Squares is the 2D variant of Dual Marching Cubes, which itself is a 2D slice of Dual Contouring. Dual Contouring was introduced by Schaefer and Warren [S1, S2, unofficial]. The method places vertices in the dual grid (cell centers) and uses QEFs to position them optimally. The adaptive quadtree implementation described in [S2, unofficial] is a specific software realization of this concept for 2D implicit fields.
