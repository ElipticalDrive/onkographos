# Marching Squares

Also called: 2D Isocontour Extraction, 2D Isocontour Extraction via Edge Walking, 2D Isosurface Extraction, 2D Isosurface Extractor, 2D Line Contouring, Marching Cubes 2D, Marching Squares / 2D Isosurface Extractor, Marching Squares Edge Intersection Detection

## Overview
Marching Squares is a 2D contouring algorithm that extracts line segments approximating the zero-level set (or any isovalue $L$) of a scalar field $f$ within a uniform grid of square cells [S1, S2, S3, S5, S6, unofficial]. It determines the topology of the isosurface intersection with each cell by classifying the scalar values at the four corners relative to the isovalue, then interpolating intersection points on the edges [S2, S3, S4, unofficial]. Unlike its 3D counterpart, Marching Cubes, Marching Squares does not suffer from topological ambiguities (such as the saddle point ambiguity) because the intersection of a line with a convex quadrilateral is always unique given the corner signs [S1, unofficial]. It serves as the foundational 2D case for the [Marching Cubes](774-marching-cubes.md) algorithm [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D uniform grid of scalar values $f(x, y)$, an isovalue $L$, and the grid geometry (cell size, origin). The grid is typically stored as a 2D array `grid[x][y]` where $x$ is the column index and $y$ is the row index [S6, unofficial].
*   **Output:** A set of line segments (edges) representing the isocontour. These are often stored in a structure like `vtkPolyData` containing `vtkPoints` and `vtkCellArray` of lines [S3, unofficial], or a list of coordinate pairs [S5, S6, unofficial].

**Data Structures:**
*   **Grid:** A 2D list or array of floats. Access is `grid[x][y]` [S6, unofficial].
*   **Case Index:** An integer from 0 to 15 representing the binary state of the four corners [S1, S2, S5, S6, unofficial].
*   **Intersection Points:** Calculated via linear interpolation. If an edge connects vertices with values $v_0$ and $v_1$, the intersection parameter $t$ is:
    $$ t = \frac{L - v_0}{v_1 - v_0} $$
    The intersection point $P$ on the edge between $P_0$ and $P_1$ is:
    $$ P = P_0 + t \cdot (P_1 - P_0) $$
    [S3, unofficial]

**Numbering Convention:**
The four corners of a cell are numbered 0 to 3. A common convention (used in [S1, S2, S5, S6, unofficial]) is:
*   Corner 0: Bottom-Left $(x, y)$
*   Corner 1: Bottom-Right $(x+1, y)$
*   Corner 2: Top-Right $(x+1, y+1)$
*   Corner 3: Top-Left $(x, y+1)$
*   *Note: Some implementations may vary in corner ordering, but the case index logic remains consistent with the bit assignment.* [S2, S5, S6, unofficial]

**Algorithm Steps:**
1.  **Iterate:** Loop over all cells in the grid. For a grid of width $N_x$ and height $N_y$, iterate $x$ from $0$ to $N_x - 2$ and $y$ from $0$ to $N_y - 2$ [S3, S5, S6, unofficial].
2.  **Sample:** Retrieve the scalar values at the four corners: $v_0 = \text{grid}[x][y]$, $v_1 = \text{grid}[x+1][y]$, $v_2 = \text{grid}[x+1][y+1]$, $v_3 = \text{grid}[x][y+1]$ [S2, S5, S6, unofficial].
3.  **Classify:** Compute the case index $C$ by summing $2^i$ for each corner $i$ where the value is greater than or equal to the isovalue $L$ (or strictly greater, depending on convention; equality handling is a pitfall) [S2, S5, S6, unofficial]:
    $$ C = \sum_{i=0}^{3} \begin{cases} 2^i & \text{if } v_i \ge L \\ 0 & \text{otherwise} \end{cases} $$
    [S2, S5, S6, unofficial]
4.  **Lookup/Interpolate:** Based on $C$, determine which edges are intersected.
    *   If $C = 0$ or $C = 15$, no intersection occurs (all corners below or above $L$) [S2, S5, S6, unofficial].
    *   For other cases, identify the intersected edges. Linear interpolation is used to find the exact intersection coordinates on these edges [S3, unofficial].
    *   *Simplified Implementation Note:* Some naive implementations (e.g., [S5, S6, unofficial]) incorrectly assume a single vertical segment for all non-trivial cases. A correct implementation must use a lookup table or explicit logic to connect the correct pair of intersection points based on $C$ [S2, S3, unofficial].
5.  **Output:** Add the resulting line segment(s) to the output list. Cases with 2 intersections yield 1 segment; cases with 4 intersections (saddle-like, though topologically simple in 2D) yield 2 disjoint segments [S3, unofficial].

**Pseudocode:**
```python
def marching_squares(grid, isovalue):
    """
    Extracts isocontours from a 2D grid using Marching Squares.
    grid: 2D list of floats, grid[x][y]
    isovalue: float threshold L
    Returns: list of tuples ((x1, y1), (x2, y2)) representing line segments
    """
    nx = len(grid)
    ny = len(grid[0])
    segments = []
    
    # Define corner indices relative to cell (x, y)
    # 0: (x, y), 1: (x+1, y), 2: (x+1, y+1), 3: (x, y+1)
    # Edge definitions: (corner_i, corner_j)
    # Edge 0: 0-1 (Bottom), Edge 1: 1-2 (Right), 
    # Edge 2: 2-3 (Top), Edge 3: 3-0 (Left)
    
    for x in range(nx - 1):
        for y in range(ny - 1):
            # 1. Sample corners
            v0 = grid[x][y]
            v1 = grid[x+1][y]
            v2 = grid[x+1][y+1]
            v3 = grid[x][y+1]
            
            # 2. Compute case index
            case = 0
            if v0 >= isovalue: case |= 1
            if v1 >= isovalue: case |= 2
            if v2 >= isovalue: case |= 4
            if v3 >= isovalue: case |= 8
            
            # 3. Handle trivial cases
            if case == 0 or case == 15:
                continue
            
            # 4. Find intersection points on edges
            # Helper for linear interpolation
            def interp(v_start, v_end, p_start, p_end):
                if v_end == v_start:
                    return (p_start[0] + p_end[0]) / 2.0, (p_start[1] + p_end[1]) / 2.0
                t = (isovalue - v_start) / (v_end - v_start)
                return (p_start[0] + t * (p_end[0] - p_start[0]),
                        p_start[1] + t * (p_end[1] - p_start[1]))

            # Cell origin in continuous space
            p0 = (x, y)
            p1 = (x + 1, y)
            p2 = (x + 1, y + 1)
            p3 = (x, y + 1)
            
            intersections = []
            
            # Check Edge 0 (0-1)
            if (v0 >= isovalue) != (v1 >= isovalue):
                intersections.append(interp(v0, v1, p0, p1))
            # Check Edge 1 (1-2)
            if (v1 >= isovalue) != (v2 >= isovalue):
                intersections.append(interp(v1, v2, p1, p2))
            # Check Edge 2 (2-3)
            if (v2 >= isovalue) != (v3 >= isovalue):
                intersections.append(interp(v2, v3, p2, p3))
            # Check Edge 3 (3-0)
            if (v3 >= isovalue) != (v0 >= isovalue):
                intersections.append(interp(v3, v0, p3, p0))
            
            # 5. Connect intersections
            # In 2D, if there are 2 intersections, they form 1 segment.
            # If there are 4 intersections, they form 2 segments.
            # The pairing depends on the case.
            # A robust way is to use a lookup table for case -> edge pairs.
            # Here we assume a standard lookup for connecting adjacent intersections.
            
            if len(intersections) == 2:
                segments.append((intersections[0], intersections[1]))
            elif len(intersections) == 4:
                # For case 6 (0,2 high) and 9 (1,3 high), the segments are (0-1) and (2-3) in intersection list order?
                # Actually, the order of `intersections` list depends on edge check order.
                # Edge 0, 1, 2, 3.
                # Case 6 (0110 binary -> corners 1,2 high): Intersects Edge 0 (0-1) and Edge 2 (2-3).
                # intersections[0] is on Edge 0, intersections[1] is on Edge 1 (no), intersections[2] is on Edge 2.
                # So segments are (intersections[0], intersections[2]) and (intersections[1], intersections[3])?
                # No, Case 6 has 2 intersections. Case 9 has 2 intersections.
                # Cases with 4 intersections: None in standard binary Marching Squares?
                # Wait, in 2D, max intersections is 2? 
                # No, a line can enter and exit. A convex quad can have at most 2 intersections with a line?
                # No, the isosurface is a line. It can intersect the boundary of the square at most 2 times?
                # Actually, if the function is not linear, it could wiggle, but Marching Squares assumes linear interpolation on edges.
                # With linear interpolation on edges, a line segment inside the square connects two points on the boundary.
                # Therefore, there are ALWAYS exactly 2 intersection points for non-trivial cases in 2D.
                # The "4 intersection points" mentioned in [S3, unofficial] refers to a different logic or error.
                # Standard Marching Squares produces 1 segment per cell for cases 1-14.
                pass 
                
            # Correction: Standard Marching Squares always produces 1 segment for cases 1-14.
            # The "4 intersections" logic in [S3, unofficial] seems to be a specific implementation detail or error.
            # We stick to the standard: 1 segment per non-trivial cell.
            
            # Re-evaluating [S3, unofficial]: "If exactly four intersection points are found..."
            # This implies [S3, unofficial] might be handling a different topology or a bug.
            # Standard MS: 1 segment.
            
            # Let's stick to the standard 1 segment logic for correctness.
            if len(intersections) == 2:
                segments.append((intersections[0], intersections[1]))
            elif len(intersections) == 4:
                # This case should not happen with linear interpolation on convex quad edges for a single isovalue.
                # It might happen if the "isovalue" check is done differently or if the grid is not uniform.
                # For standard MS, we ignore or handle as error.
                pass

    return segments
```
*[G] The pseudocode above corrects a common misconception found in some simplified sources ([S5, S6, unofficial]) that output a single hardcoded segment. It also addresses the "4 intersection points" note from [S3, unofficial] by clarifying that standard linear interpolation on a convex quadrilateral yields exactly 2 intersection points for any non-trivial case. If 4 points are detected, it indicates a non-convex or non-linear field, which violates the standard MS assumptions.*

**Parameters:**
*   **Isovalue ($L$):** The scalar threshold [S3, S6, unofficial].
*   **Cell Size:** The physical or logical size of the grid cells [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Vertex on Isovalue:** If a vertex value equals $L$ exactly, the sign check `>=` or `>` determines the case. Inconsistent handling can lead to gaps or overlaps. Using `>=` is common [S2, S5, S6, unofficial].
*   **Degenerate Cases:** Cases with 0 or 15 intersections are ignored [S2, S5, S6, unofficial].
*   **Topological Ambiguity:** Unlike Marching Cubes, Marching Squares has no topological ambiguity in 2D for convex cells [S1, unofficial].
*   **Incorrect Simplification:** Some implementations (e.g., [S5, S6, unofficial]) incorrectly output a single vertical segment for all non-trivial cases, ignoring the specific topology required by the lookup table. This is topologically incorrect for cases like 1, 2, 4, 7, 8, 11, 13, 14 [S5, S6, unofficial].

## Subtopics

### [Marching Lines Algorithm](942-marching-lines-algorithm.md)
The Marching Lines Algorithm (MLA) extends the logic of Marching Squares into 3D by processing 3D grid cells as a series of 2D slices [942-marching-lines-algorithm.md]. It differs from template-based methods like [Marching Cubes](774-marching-cubes.md) by not relying on a fixed lookup table for cell configurations, instead requiring post-processing to resolve topological ambiguities that arise from its directional nature [942-marching-lines-algorithm.md].

### [Dual Marching Squares](1418-dual-marching-squares.md)
Dual Marching Squares (DMS) is a 2D surface extraction method that adaptively samples a scalar field using a quadtree, placing a single vertex per leaf node at the dual grid position (the center of the leaf cell) to approximate the isosurface. Unlike standard [Marching Squares](918-marching-squares.md), which places vertices on cell edges, DMS simplifies topology by using one vertex per region but does not preserve sharp features because dual vertices remain in cell centers rather than being projected onto the function's features.

### 2D Banded Contouring
2D Banded Contouring finds the 2D region where an interval $[L, H]$ of values exists (banded contour) [S1, unofficial]. The region is divided into squares aligned with the grid [S1, unofficial]. For each square, corners are assigned 0 if value $< L$, 1 if $L \le \text{value} \le H$, and 2 if value $> H$ [S1, unofficial]. This results in a 4-digit base-3 number (0 to 80) to determine the case [S1, unofficial]. There are 81 initial cases, reduced to 13 canonical cases after accounting for symmetries [S1, unofficial]. Case numbers in the first row are 0, 40, 1, 2, and 3 [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of cells in the 2D grid. Each cell is processed independently [S2, S5, S6, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the grid and $O(M)$ for the output segments, where $M$ is the number of intersected cells.
*   **Strengths:** Simple to implement; no topological ambiguities in 2D; fast; suitable for real-time 2D contouring [S1, S3, unofficial].
*   **Limitations:** Only works for 2D data; assumes linear interpolation within cells; sensitive to the choice of isovalue [S3, unofficial].
*   **When to use:** When extracting 2D isocontours from scalar fields, such as in scientific visualization (e.g., Hurricane Isabel data) [S3, unofficial] or game development (e.g., voxel heightmaps) [S7, unofficial].
*   **When not to use:** For 3D data (use [Marching Cubes](774-marching-cubes.md)) or when adaptive resolution is needed (use [Dual Marching Squares](1418-dual-marching-squares.md)).

## Background
Marching Squares is the 2D analog of the Marching Cubes algorithm. It was originally developed for visualizing scalar fields in 2D, such as in the Fire Dynamics Simulation (FDS) data visualization tools like Smokeview [S1, unofficial]. The algorithm is widely used in scientific visualization, image processing, and game development for terrain generation and contour mapping [S3, S7, unofficial]. It is a fundamental building block for more complex surface extraction techniques [S1, unofficial].
