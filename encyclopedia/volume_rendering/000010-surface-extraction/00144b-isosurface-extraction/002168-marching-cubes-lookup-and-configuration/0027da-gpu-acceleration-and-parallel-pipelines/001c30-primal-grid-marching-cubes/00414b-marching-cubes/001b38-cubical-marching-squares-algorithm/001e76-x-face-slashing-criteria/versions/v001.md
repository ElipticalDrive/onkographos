# X-face slashing criteria

Also called: Criterion 1, Criterion 2, Criterion 3, Criterion 4

## Overview
X-face slashing criteria are a set of four decision rules used in the Cubical Marching Squares Algorithm to resolve topological ambiguities on X-faces (faces shared by two cubes where the isosurface topology is ambiguous). An X-face slash merges two loops, altering the loop count of the incident cubes. These criteria determine whether to merge or split loops based on global topological objectives, such as maximizing or minimizing the total loop count $L$ or the number of equivalence classes (shells) $S$. They build on [Cubical Marching Squares Algorithm](941-cubical-marching-squares-algorithm.md) by providing the specific logic for handling the most complex ambiguity case in cubic grid extraction.

## How it works
**Inputs:**
- A volumetric dataset discretized into a grid of cubes.
- The state of the isosurface extraction, specifically the current loop configurations and equivalence classes for each cube.
- The X-face propagation graph (see Subtopics) which identifies cubes with X-faces and their connectivity.

**Outputs:**
- A binary decision for each X-face: "slash" (merge loops) or "no slash" (split loops).
- Updated loop counts $L_c$ for each cube $c$ sharing the face.
- Updated equivalence class counts $S$ (number of shells).

**Data Structures:**
- **X-face Propagation Graph $G=(V, E)$**:
  - Nodes $V$: Each node represents a cube $(i, j, k)$ that contains at least one X-face.
  - Edges $E$: An edge exists between node $(i, j, k)$ and a neighbor $(i', j', k')$ if they share an X-face. To avoid duplication in this undirected graph, edges are only created for neighbors in directions $\{X+, Y+, Z+\}$.
  - Edge Attributes: Each edge is assigned a binary value indicating the slashing choice (0 or 1).
- **Loop Count $L_c$**: An integer representing the number of loops in cube $c$.
- **Equivalence Classes $S$**: The number of distinct shells in the mesh.

**Steps:**
1. **Construct the X-face Propagation Graph**:
   - Traverse the volumetric model.
   - For each cube $(i, j, k)$, determine if it has any X-faces.
   - If yes, insert a node labeled $(i, j, k)$ into $V$.
   - Check the three face-neighbors in directions $\{X+, Y+, Z+\}$. If the shared face is an X-face, add an edge between the current node and the neighbor's node in $E$.
   - Assign a binary value to each edge, initially undefined or based on a default heuristic.

2. **Apply Slashing Criteria**:
   For each X-face $f$ shared by two cubes $c_1$ and $c_2$:
   - Determine the two possible outcomes of the slash:
     - **Option A**: Slash the face. This merges two loops in one cube (decreasing $L$ by 1) and splits two loops in the other (increasing $L$ by 1), or vice versa, depending on the pre-slash loop configuration. The total loop count $L$ may remain unchanged, increase by 2, or decrease by 2.
     - **Option B**: Do not slash the face. The loops remain as they are.
   - Evaluate the four criteria to select the option:
     - **Criterion 1 (Maximize Loops)**: Choose the option that maximizes $L_c$ in every cube $c$ sharing $f$. If $L_c$ increases by one in one cube, the neighbor's $L$ cannot decrease by more than one, ensuring the total count $L$ never decreases. This is used in greedy algorithms for maximizing $L$.
     - **Criterion 2 (Minimize Loops)**: Choose the option that minimizes $L_c$ in every cube $c$ sharing $f$. This tends to minimize the total loop count $L$.
     - **Criterion 3 (Maximize Shells)**: Choose the option that does not decrease the number of equivalence classes $S$ (if one choice decreases it, pick the other). This tends to maximize $S$, preserving more shells.
     - **Criterion 4 (Minimize Shells)**: Choose the option that decreases the number of equivalence classes $S$ (if one choice decreases it). This tends to minimize $S$, simplifying the mesh topology.

3. **Assign Sheets**:
   - Once the slashing decisions are made, assign a single sheet to each loop obtained. This is because loops in cubes with X-faces cannot be joined by triangulations that do not include additional vertices or triangles coplanar with a cube's face.

**Formulas:**
- Loop Count Change: Let $L_c$ be the loop count in cube $c$. If an X-face $f$ is slashed, the change in $L_c$ depends on whether the borders of $f$ were part of the same loop or different loops before the slash.
  - If borders were in the same loop: Slash splits the loop, $L_c \leftarrow L_c + 1$.
  - If borders were in different loops: Slash merges the loops, $L_c \leftarrow L_c - 1$.
- Total Loop Count $L = \sum_c L_c$.
- Equivalence Classes $S$: The final number of equivalence classes equals the number of shells in the mesh.

**Parameters:**
- Criterion Selection: One of {1, 2, 3, 4}.
- Graph Construction: Linear time traversal.

**Edge Cases and Pitfalls:**
- **Graph Cycles**: The X-face propagation graph may contain cycles, although they are rare in practice. Most connected components are trees.
- **Loop Joining**: Once loops are set by X-face slashing, they cannot be joined by subsequent triangulations without adding extra vertices or coplanar triangles.
- **Cube Configurations**: Cubes can have 0, 1, 2, 3, or 6 X-faces. Configurations with 4 or 5 X-faces do not exist.

## Subtopics

### [X-cube loop connection criteria](2091-x-cube-loop-connection-criteria.md)
X-cube loop connection criteria determine how to resolve topological ambiguities within X-cubes after X-faces have been processed. Unlike X-face slashing criteria, which merge loops across cube faces, these criteria operate on loops contained entirely within an X-cube. The choice of criterion directly influences the topological invariants of the resulting mesh, specifically the number of shells ($S$) and handles ($H$), allowing the algorithm to prioritize either mesh simplicity (fewer shells) or feature preservation (more shells). See [X-cube loop connection criteria](2091-x-cube-loop-connection-criteria.md).

### X-face propagation graph
The X-face propagation graph is an abstract graph $G = (V, E)$ used to decide on X-face slashing. Nodes represent cubes with at least one X-face. Edges represent X-faces connecting incident cubes. Construction time is linear with respect to the model size. Graph cycles may appear, although very rarely in practice. Most connected components are trees. Each graph edge is assigned a binary value indicating its slashing choice. Cubes can have 0, 1, 2, 3, or 6 X-faces. Frequencies over 256 configurations: 0 X-faces (135 configs, 52.7%), 1 X-face (72 configs, 28.1%), 2 X-faces (30 configs, 11.7%), 3 X-faces (16 configs, 6.2%), 6 X-faces (2 configs, 0.7%). Cubes with 4 or 5 X-faces do not exist.

## Operating characteristics
- **Time Complexity**: Construction of the X-face propagation graph is linear with respect to the model size. The application of criteria is local to each X-face, making it efficient.
- **Memory Complexity**: Proportional to the number of cubes with X-faces, as only these cubes and their connections are stored in the graph.
- **Performance**: The X-face graph is sparse, with a small number of edges connecting nodes and only a few high-order nodes. This sparsity contributes to efficient processing.
- **Strengths**: Provides a systematic way to resolve complex topological ambiguities in cubic grids. Allows control over global topological properties (loop count, shell count).
- **Limitations**: Requires global information (the propagation graph) to make local decisions. The final mesh topology is dependent on the chosen criterion, which may not always produce the desired aesthetic or topological result.
- **When to Use**: When extracting isosurfaces from cubic grids with ambiguous X-faces and when control over the resulting mesh topology is required.
- **When Not to Use**: When a simpler method (like standard Marching Cubes) suffices and topological ambiguity is not a concern.

## Background
The X-face slashing criteria were introduced in the context of optimizing the topological and combinatorial complexity of isosurfaces extracted from volumetric data. They are part of the Cubical Marching Squares Algorithm, which extends the principles of Marching Squares to 3D cubic grids. The method addresses the limitations of earlier algorithms that struggled with topological ambiguities in cubic cells. The approach uses global information, such as the X-face propagation graph and the merge tree of equivalence classes, to make informed local decisions about loop merging and splitting.
