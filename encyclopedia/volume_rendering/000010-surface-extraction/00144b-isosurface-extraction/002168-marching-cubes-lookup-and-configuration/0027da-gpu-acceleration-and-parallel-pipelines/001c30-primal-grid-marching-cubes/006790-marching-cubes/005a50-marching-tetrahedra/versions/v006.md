# Marching Tetrahedra

Also called: Marching tetras, Tetrahedral Marching, Tetrahedral Marching Cubes, marching tets

## Overview
Marching Tetrahedra (MT) is an isosurface extraction algorithm that decomposes each cubic voxel into tetrahedra to resolve the topological ambiguities present in [Marching Cubes](774-marching-cubes.md) [S3][S17, unofficial]. By processing tetrahedra independently, it guarantees a manifold mesh without cracks or ambiguous configurations, producing higher-quality surfaces at the cost of increased triangle count and computational overhead [S2][S5, unofficial][S6].

## How it works
**Inputs:** A 3D scalar field $V$ defined on a regular grid of dimensions $N_x \times N_y \times N_z$, and an isovalue $I$ [S14, unofficial][S8, unofficial].
**Outputs:** A triangle mesh representing the isosurface $V(x,y,z) = I$ [S12, unofficial].

### Data Structures
1.  **Scalar Field:** A 1D or 3D array storing scalar values, indexed by $idx = x + N_x(y + N_z z)$ [S14, unofficial].
2.  **Vertex Lookup Cache:** A dictionary mapping unique edge keys (defined by the global coordinates of the two endpoints) to the generated vertex index. This ensures shared edges between adjacent tetrahedra produce identical intersection points, preventing holes [S17, unofficial].
3.  **Tetrahedron Decomposition Table:** A static array defining the 4 vertex indices (0-7) for each tetrahedron within a voxel. The standard 6-tetrahedron decomposition uses the following vertex indices:
    *   $T_0: \{0, 7, 3, 2\}$, $T_1: \{0, 7, 2, 6\}$, $T_2: \{0, 4, 6, 7\}$
    *   $T_3: \{0, 6, 1, 2\}$, $T_4: \{0, 6, 1, 4\}$, $T_5: \{5, 6, 1, 4\}$
    [S17, unofficial]
    *Note: A 5-tetrahedron scheme exists but requires alternating splitting patterns to maintain continuity [S1, S5, unofficial].*
4.  **Edge-Vertex Mapping:** A static array `tetrahedronEdgeConnection[6][2]` mapping the 6 edges of a tetrahedron to its 4 vertices. Standard ordering:
    *   Edge 0: $\{0, 1\}$, Edge 1: $\{0, 2\}$, Edge 2: $\{0, 3\}$
    *   Edge 3: $\{1, 2\}$, Edge 4: $\{1, 3\}$, Edge 5: $\{2, 3\}$
    [S17, unofficial]
5.  **Triangle Lookup Table:** A static array `tetrahedronTriangles[16][7]` mapping the 16 possible vertex sign configurations (4-bit index) to the resulting triangles. Each entry contains up to two triangles (3 edge indices each), terminated by -1 [S7, S21, unofficial].

### Algorithm Steps
1.  **Initialize:** Create empty vertex list, index list, and edge cache [S8, unofficial].
2.  **Iterate Voxels:** Loop through all voxels $(x, y, z)$ in the grid [S8, unofficial].
3.  **Sample Vertices:** Retrieve scalar values $v_0 \dots v_7$ and positions $p_0 \dots p_7$ for the 8 corners of the current voxel [S14, unofficial].
4.  **Decompose:** For each of the 6 tetrahedra in the voxel:
    a.  **Get Vertices:** Retrieve the 4 vertex indices $(i_0, i_1, i_2, i_3)$ from the decomposition table.
    b.  **Compute Case Index:** Determine the 4-bit configuration mask `flagIndex`:
        ```python
        flagIndex = 0
        if v[i_0] < I: flagIndex |= 1
        if v[i_1] < I: flagIndex |= 2
        if v[i_2] < I: flagIndex |= 4
        if v[i_3] < I: flagIndex |= 8
        ```
        [S10, S17, unofficial]
    c.  **Lookup Triangles:** Retrieve the triangle definitions from `tetrahedronTriangles[flagIndex]`. If the first entry is -1, continue to the next tetrahedron [S7, unofficial].
    d.  **Generate Vertices:** For each triangle in the lookup result (up to 2):
        i.  Get the 3 edge indices $(e_a, e_b, e_c)$ from the lookup table.
        ii. For each edge index, determine the two global vertex indices $(u, v)$ using `tetrahedronEdgeConnection`.
        iii. Calculate the intersection point on the edge. If the edge has not been cached, compute it and store it in the cache using the key $(\min(u,v), \max(u,v))$ [S17, unofficial].
        iv. **Interpolation:** Compute the intersection point $P$ on the edge between vertices $A$ and $B$ with values $f_A$ and $f_B$:
            $$ t = \frac{I - f_A}{f_B - f_A} $$
            $$ P = A + t(B - A) $$
            [S9, S17, unofficial]
            *Guard:* If $|f_B - f_A| < \epsilon$ (e.g., $10^{-6}$), return the midpoint $(A+B)/2$ to avoid division by zero [S14, unofficial].
        v.  Add the vertex to the mesh if new, or retrieve its index from the cache.
    e.  **Add Triangle:** Add the 3 vertex indices to the mesh index list. Ensure consistent winding order (e.g., using a global `WindingOrder` array) [S7, S10, unofficial].

### Formulas
*   **Case Index:** $\text{flagIndex} = \sum_{k=0}^{3} \mathbb{I}(v_k < I) \cdot 2^k$ [S10, S17, unofficial].
*   **Edge Intersection Parameter:** $t = \frac{I - f_A}{f_B - f_A}$ [S9, S17, unofficial].
*   **Intersection Point:** $P = A + t(B - A)$ [S9, S17, unofficial].

### Parameters
*   **Isovalue ($I$):** The threshold scalar value. Default 0.0 [S7, S8, unofficial].
*   **Decomposition Scheme:** 6 tetrahedra per voxel is standard for continuity [S5, S17, unofficial]. 5 tetrahedra is an alternative but requires alternating schemes to maintain continuity [S1, S19, unofficial].
*   **Epsilon ($\epsilon$):** Tolerance for degenerate cases (value == isovalue or equal edge values). Default $10^{-3}$ [S8, unofficial], with $10^{-6}$ used for near-identical vertex values [S14, unofficial].

### Edge Cases and Pitfalls
*   **Ambiguity Resolution:** Unlike Marching Cubes, MT has no topological ambiguities because a tetrahedron has only 4 vertices, reducing the case logic to 16 symmetric configurations [S13, S17, unofficial].
*   **Mesh Holes:** Without caching edge intersections, floating-point errors can cause gaps where tetrahedra share edges. Caching is mandatory for a manifold mesh [S17, unofficial].
*   **Degenerate Triangles:** If a vertex lies exactly on the isovalue, the interpolation parameter $t$ may be 0 or 1, resulting in duplicate vertices. These are filtered out or handled by tracking zero-isovalue points in a map [S9, S12, unofficial].
*   **Winding Order:** Incorrect vertex ordering in the decomposition table or lookup table leads to inverted normals. The ordering of the tetrahedrons matters to generate correctly sided output [S10, unofficial].
*   **Performance:** MT generates more triangles than Marching Cubes (approx. 2-3x) and requires more memory for the vertex cache [S5, S14, unofficial].

### Pseudocode
```python
def marching_tetrahedra(grid, dims, isovalue):
    vertices = []
    indices = []
    edge_cache = {}  # Maps (v0_idx, v1_idx) -> vertex_index

    # 6 tetrahedra per cube, each with 4 vertex indices (0-7)
    tetra_decomp = [
        [0, 7, 3, 2], [0, 7, 2, 6], [0, 4, 6, 7],
        [0, 6, 1, 2], [0, 6, 1, 4], [5, 6, 1, 4]
    ]
    # Edge-vertex mapping for a tetrahedron: 6 edges, each connects 2 vertices (0-3)
    edge_vertices = [
        [0, 1], [0, 2], [0, 3], [1, 2], [1, 3], [2, 3]
    ]
    # Triangle lookup table: 16 cases, each up to 2 triangles (3 edge indices each), -1 terminator
    tri_lookup = [...]  # Standard 16-entry table, e.g., case 0: [-1], case 1: [0, 3, 2, -1, -1, -1, -1] [S7, S21, unofficial]

    for z in range(dims[2]):
        for y in range(dims[1]):
            for x in range(dims[0]):
                # Sample 8 voxel corners using linear index
                base_idx = x + dims[0] * (y + dims[1] * z)
                offsets = [0, 1, dims[0], dims[0]+1, dims[0]*dims[1], dims[0]*dims[1]+1, dims[0]*dims[1]+dims[0], dims[0]*dims[1]+dims[0]+1]
                voxel_vals = [grid[base_idx + off] for off in offsets]
                voxel_pos = [get_grid_position(x, y, z, off) for off in offsets]

                for tet in tetra_decomp:
                    v0, v1, v2, v3 = tet
                    vals = [voxel_vals[v0], voxel_vals[v1], voxel_vals[v2], voxel_vals[v3]]
                    pos = [voxel_pos[v0], voxel_pos[v1], voxel_pos[v2], voxel_pos[v3]]

                    # Compute case index
                    flag = 0
                    if vals[0] < isovalue: flag |= 1
                    if vals[1] < isovalue: flag |= 2
                    if vals[2] < isovalue: flag |= 4
                    if vals[3] < isovalue: flag |= 8

                    # Lookup triangles
                    tri_defs = tri_lookup[flag]
                    if tri_defs[0] == -1: continue

                    # Process up to 2 triangles
                    for i in range(0, len(tri_defs), 3):
                        if tri_defs[i] == -1: break
                        e0, e1, e2 = tri_defs[i], tri_defs[i+1], tri_defs[i+2]

                        # Generate vertices for each edge
                        verts = []
                        for e in [e0, e1, e2]:
                            u, v = edge_vertices[e]
                            edge_key = (min(u, v), max(u, v))
                            if edge_key in edge_cache:
                                verts.append(edge_cache[edge_key])
                            else:
                                # Intersect edge
                                fa, fb = vals[u], vals[v]
                                if abs(fb - fa) < 1e-6:
                                    t = 0.5
                                else:
                                    t = (isovalue - fa) / (fb - fa)
                                p = pos[u] + t * (pos[v] - pos[u])
                                new_idx = len(vertices)
                                vertices.append(p)
                                edge_cache[edge_key] = new_idx
                                verts.append(new_idx)

                        indices.extend(verts)
    return vertices, indices
```

## Subtopics

### Tetrahedralization-based Mesh Extraction
A variant that decouples mesh resolution from Gaussian distribution, enabling fine meshing of restricted scene segments [S22]. It performs tetrahedralization of vertices, classifies tets as inside/outside based on sampled interior points, and extracts separating faces [S22]. It prioritizes smoothness and artifact reduction over raw metric gains, producing topologically clean surfaces for complex scenes like those in MipNeRF 360 [S22].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels. Each voxel is processed independently, making it highly parallelizable [S4, unofficial].
*   **Memory Complexity:** $O(N)$ for the scalar field. Additional memory is required for the output mesh, which is larger than Marching Cubes. The edge cache adds overhead proportional to the number of unique edges [S5, S17, unofficial].
*   **Performance:** Generally slower than Marching Cubes due to the higher number of tetrahedra (6 vs 1) and the cost of edge caching. Benchmarks report MT taking approximately 1.8x to 3.7x longer than Marching Cubes depending on the scene and implementation [S4, S5, unofficial].
*   **Strengths:** Topologically correct, no cracks, works on irregular tetrahedral meshes [S2][S17, unofficial].
*   **Limitations:** Higher triangle count, more complex implementation due to caching, potential for degenerate geometry if not handled [S5, S12, unofficial].
*   **When to Use:** When topological correctness is critical (e.g., medical imaging, simulation) and cracks are unacceptable. When working with unstructured tetrahedral grids [S2].
*   **When Not to Use:** When performance is the primary constraint and approximate surfaces are acceptable.

## Background
Marching Tetrahedra was developed as an extension to Marching Cubes to circumvent the Marching Cubes patent (US 4,710,876) and to solve the topological ambiguity problem present in some Marching Cubes configurations [S3, S6]. The patent expired in 2005 [S3]. The method was introduced in 1991 [S18] and later applied natively to tetrahedral meshes by Doi and Koide [S19, unofficial]. It is widely used in scientific visualization and medical imaging where mesh quality and topology are paramount [S2][S5, unofficial].
