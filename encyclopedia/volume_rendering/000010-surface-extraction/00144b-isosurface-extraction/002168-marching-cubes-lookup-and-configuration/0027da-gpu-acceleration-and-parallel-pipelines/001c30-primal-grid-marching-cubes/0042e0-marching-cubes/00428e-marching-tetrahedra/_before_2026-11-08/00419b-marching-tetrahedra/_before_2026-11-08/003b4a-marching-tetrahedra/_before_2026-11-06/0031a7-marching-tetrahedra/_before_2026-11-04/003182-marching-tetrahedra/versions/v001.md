# Marching Tetrahedra

Also called: Marching Tetrahdra

## Overview
Marching Tetrahedra is an isosurface extraction method that decomposes a volumetric grid into tetrahedra to resolve topological ambiguities inherent in Marching Cubes [S1, unofficial]. It achieves this by using significantly fewer configuration cases than its cubic counterpart, ensuring a manifold and unambiguous surface representation [S1, unofficial].

## How it works
**Inputs:** A 3D grid of vertices with associated implicit function values (scalar field).
**Outputs:** A set of triangles defining the isosurface.

**Data Structures:**
1.  **Vertex Grid ($V$):** A matrix of size $N \times 3$, where $N = n_x n_y n_z$. Each row contains the $(x, y, z)$ coordinates of a grid vertex.
2.  **Tetrahedron List ($T$):** A list of tetrahedra. Each cube in the grid is decomposed into 6 tetrahedra. The total number of tetrahedra is $6(n_x-1)(n_y-1)(n_z-1)$. Each tetrahedron is defined by 4 vertex indices.

**Algorithm Steps:**

1.  **Grid Generation:**
    Define the grid dimensions $n_x, n_y, n_z$ and bounds $[x_{min}, x_{max}], [y_{min}, y_{max}], [z_{min}, z_{max}]$. Generate vertex positions using linear spacing:
    $$ x_i = x_{min} + i \cdot \Delta x, \quad i \in [0, n_x-1] $$
    (Analogous for $y$ and $z$). Store these in $V$.

2.  **Tetrahedral Decomposition:**
    For each cube in the grid defined by indices $(i, j, k)$ where $i \in [0, n_x-2]$, $j \in [0, n_y-2]$, $k \in [0, n_z-2]$, decompose it into 6 tetrahedra. The specific connectivity pattern (which 8 cube corners map to which 4 tetrahedron vertices) must be consistent across the grid to ensure shared faces are handled correctly. Let the 8 corners of a cube be $C_0 \dots C_7$. A common decomposition assigns:
    -   $T_0: (C_0, C_1, C_2, C_3)$ ? No, standard decomposition usually involves diagonals. A robust implementation defines 6 tets per cube. For example, using a central point or specific diagonal splits. The source code implies a fixed mapping. We assume a standard split where each tetrahedron shares edges with neighbors.
    *Note: The exact vertex ordering for the 6 tetrahedra per cube is critical for consistency. A common approach splits the cube into 6 tetrahedra by connecting one corner to the opposite face diagonals, or using a central vertex. The source [S1, unofficial] uses a fixed decomposition.*

3.  **Configuration Calculation:**
    For each tetrahedron, retrieve the 4 vertex positions $p_0, p_1, p_2, p_3$ and their scalar values $v_0, v_1, v_2, v_3$.
    Calculate the configuration integer $C$:
    $$ C = \sum_{k=0}^{3} 2^k \cdot \mathbb{I}(v_k < 0) $$
    where $\mathbb{I}(\cdot)$ is the indicator function. $C$ ranges from 0 to 15.

4.  **Triangle Generation:**

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of tetrahedra (proportional to the volume of the grid). Each tetrahedron is processed in constant time.
- **Memory Complexity:** $O(N)$ for storing the tetrahedron list and output triangles.
- **Performance:** The source notes that dynamic vector insertion can consume unused memory if pre-allocated to size $9 \times |Tets|$ [S1, unofficial]. Pre-allocation is recommended.
- **Strengths:** No topological ambiguities compared to Marching Cubes [S1, unofficial]. Fewer configuration cases to implement [S1, unofficial].
- **Limitations:** Requires decomposition logic. The source implementation uses Eigen and dynamic vectors, which may have overhead [S1, unofficial].

## Background
Marching Tetrahedra is a variation of Marching Cubes used for isosurface extraction from implicit functions [S1, unofficial]. It was developed to resolve the topological ambiguities present in the original Marching Cubes algorithm [S1, unofficial]. The method is used in surface reconstruction pipelines, such as the Moving Least Squares implicit method [S1, unofficial].
