# Extended Trilinear Triangulation

Also called: Extended MC33, Extended Marching Cubes 33, Extended triangulation to the Marching Cubes 33 algorithm

## Overview
Extended Trilinear Triangulation is a method for generating topologically correct, degenerate-free triangulations of isosurfaces within a voxel grid by extending the Marching Cubes 33 algorithm with a three-state vertex classification and convex hull-based geometry construction [S1]. It solves the dual problems of topological ambiguity in standard Marching Cubes and the generation of degenerate or skinny triangles caused by vertices lying exactly on the isovalue [S1]. Unlike the Asymptotic Decider, which resolves ambiguity by analyzing the critical points of the trilinear interpolant, this method resolves ambiguity by tracking the connectivity of positive and negative regions via an interior test, and unlike the basic Marching Cubes 33, it explicitly handles the "=" (zero) label to prevent degenerate geometry while preserving the topology of the trilinear interpolant [S1].

## How it works
### Inputs and Outputs
- **Input:** A rectilinear grid $H$ containing a scalar field $f$, an isovalue $\alpha$, and a specific voxel (unit cube) with scalar values $f(v_i)$ at its 8 vertices $v_0, \dots, v_7$ [S1].
- **Output:** A set of triangles forming the isosurface patch $\bar{S}_\alpha$ within the cube, or an empty set if no intersection exists [S1].

### Data Structures
- **Vertex Label:** Each vertex $v_i$ is assigned a label $L(v_i) \in \{+, -, =\}$ [S1].
- **Group of Vertices (GV):** A set of vertices in the same cube connected by a path of vertices with the same non-zero label (positive or negative) along the edges or faces of the cube [S1].
- **Group of Edges (GE):** A set of edges intersected by the isosurface that are incident to vertices in a specific GV [S1].
- **Intersection Points:** For each intersected edge, the midpoint is used as a representative point for convex hull construction [S1].

### Numbered Steps

1.  **Vertex Classification:**
    For each vertex $v_i$ of the cube, determine its label based on the scalar field value $f(v_i)$ and isovalue $\alpha$:
    $$
    L(v_i) = \begin{cases} 
    + & \text{if } f(v_i) > \alpha \\
    - & \text{if } f(v_i) < \alpha \\
    = & \text{if } f(v_i) = \alpha
    \end{cases}
    $$
    [S1]

2.  **Cube Classification:**
    Count the number of vertices labeled "+" or "=". [S1]
    - If the count is $\le 4$, the cube is classified as **Positive**. [S1]
    - Otherwise, the cube is classified as **Negative**. [S1]

3.  **Group Identification:**
    - **Positive Cube:** Identify all **Groups of Vertices (GV)**. [S1]
    A GV is a set of "+" vertices connected by a path consisting only of "+" vertices along the cube's edges or faces. [S1]
    - **Negative Cube:** Identify all **Groups of Vertices (GV)**. [S1]
    A GV is a set of "-" vertices connected by a path consisting only of "-" vertices along the cube's edges or faces. [S1]
    - For each GV, identify the corresponding **Group of Edges (GE)**: the set of edges intersected by the isosurface that are incident to the vertices in that GV. [S1]

4.  **Interior Test (Topology Resolution):**
    Use the interior test (Chernyaev/Custodio) to determine the connectivity of the GV groups inside the cube volume. [S1]
    Classify the cube into one of three categories:
    - **Simple Leaf:** The isosurface forms a single patch or disconnected patches within the cube. [S1]
    - **Tunnel:** The isosurface passes through the cube, connecting opposite sides. [S1]
    - **Interior Point:** The isosurface forms a closed loop or complex structure involving the cube center (typically associated with Case 13 subcases) [S1].

5.  **Triangulation Construction:**
    Depending on the category and specific case, construct the mesh using one of the following methods:

    **A. Simple Leaves Triangulation:**
    For each group $i$ (with vertex set $GVi$ and edge set $GEi$):
    1.  Let $W_i$ be the set containing:
        - The midpoints of all edges in $GEi$.
        - All vertices in $GVi$ that are labeled "+" or "=". [S1]
    2.  Compute the convex hull $conv(W_i)$.
    3.  If $conv(W_i)$ is 3-dimensional:
        - Triangulate the boundary $\partial(conv(W_i))$. [S1]
        - Remove any triangles that lie entirely on the faces of the cube. [S1]
    4.  If $conv(W_i)$ is 2-dimensional (contained in a cube face):
        - Return the triangulation of $conv(W_i)$. [S1]
        - **Exception:** If all 8 vertices of the cube are labeled "=", return no triangulation to avoid duplicate faces.
    5.  **Face Deduplication:** Track grid faces that have already been triangulated by adjacent cubes to prevent duplicate output [S1].

    **B. Tunnel Triangulation:**
    1.  Let $W$ be the set of midpoints of *all* intersected edges in the cube. [S1]
    2.  Compute the convex hull $conv(W)$.
    3.  If $conv(W)$ is 3-dimensional:
        - Triangulate the boundary $\partial(conv(W))$. [S1]
        - Remove any triangles where all three vertices belong to the same Group of Edges ($GE_i$). [S1]

    **C. Interior Point Leaves Triangulation:**
    1.  Identify faces where all four edges are intersected. [S1]
    2.  Connect pairs of intersection points on these faces based on the bilinear interpolant behavior to form a simple closed polygonal curve. [S1]
    3.  Add a vertex at the center of the cube.
    4.  Form triangles connecting the center vertex to the segments of the polygonal curve [S1].

    **D. Case 13 Specific Combinations:**
    Case 13 is the most complex, with all faces ambiguous. [S1]
    - **Case 13.3:** One group of 4 positive vertices. Use the incident negative vertex. Apply **Interior Point Leaves** triangulation combined with **Simple Leaves** triangulation on the single negative vertex group [S1].
    - **Case 13.5.1:** Two groups of vertices. Apply **Simple Leaves** triangulation to both groups [S1].
    - **Case 13.5.2:** Two groups of vertices connected by the interior, with a signal change diagonally opposite to one vertex group. Apply **Tunnel** triangulation combined with **Simple Leaves** triangulation in the region diagonally opposite to the one-vertex positive group [S1].

### Formulas
The trilinear interpolant $g(x,y,z)$ within a unit cube is defined as [S1]:
$$
\begin{aligned}
g(x,y,z) &= (1-x)(1-y)(1-z)f(v_0) + (1-x)(1-y)zf(v_4) \\
&\quad + (1-x)y(1-z)f(v_3) + (1-x)yzf(v_7) \\
&\quad + x(1-y)(1-z)f(v_1) + x(1-y)zf(v_5) \\
&\quad + xy(1-z)f(v_2) + xyzf(v_6)
\end{aligned}
$$
The extracted isosurface is $\bar{S}_\alpha = \{x \in \mathbb{R}^3 | g(x) = \alpha\}$ [S1].

### Parameters
- **Isovalue ($\alpha$):** The scalar threshold for the isosurface.
- **Vertex Labeling Threshold:** Equality check $f(v_i) = \alpha$. In floating-point implementations, a small epsilon tolerance may be required for robustness [G].

### Edge Cases and Pitfalls
- **Degenerate Triangles:** Occur in standard Marching Cubes when $f(v_i) = \alpha$ is treated as positive, causing three intersected edges to meet at a single point. This method avoids this by explicitly labeling such vertices as "=" and including them in the vertex sets $W_i$ for convex hull generation, which naturally prevents degenerate geometry [S1].
- **Skinny Triangles:** Generated when two vertices are close to a grid vertex and the third is far [S1].
- **Duplicate Faces:** If a cube has all vertices "=", no triangulation is generated. Additionally, the algorithm must maintain a state of triangulated grid faces to prevent adjacent cubes from triangulating the same face twice [S1].
- **Topology Ambiguity:** Cases 6.1.1 and 6.1.2 have identical vertex/edge groups but different interpolant topologies. The interior test is mandatory to distinguish them [S1].

## Operating characteristics
- **Time Complexity:** The algorithm processes each cube independently. The complexity per cube is dominated by the interior test and convex hull construction, which are constant time for a fixed number of vertices (8) and edges (12). Thus, it is $O(N)$ for $N$ voxels.
- **Memory Complexity:** $O(N)$ to store the output mesh. The algorithm requires minimal auxiliary memory per cube (labels, groups, hull points).
- **Measured Performance:** In a 5x5x5 piecewise-trilinear field test, the method produced correct Betti numbers (b0=1, b1=0, b2=1), whereas the Raman and Wenger method (which uses a lookup table covering only 23 of 33 behaviors) produced incorrect Betti numbers (b0=4, b1=0, b2=4) [S1].
- **Strengths:** Guarantees topological correctness for all 33 cases of the trilinear interpolant; avoids degenerate and skinny triangles; handles the "=" label explicitly.
- **Limitations:** More complex implementation than standard Marching Cubes due to the need for group identification and interior testing.
- **When to use:** When topological correctness and mesh quality (avoiding degenerate triangles) are critical, and the underlying scalar field is assumed to be interpolated by a trilinear function.

## Background
The base Marching Cubes algorithm was proposed by Lorensen and Cline in 1987 [S1]. Marching Cubes 33, which guarantees topological correctness for the trilinear interpolant, was proposed by Chernyaev in 1995 [S1]. The concept of an extended lookup table including "+" and "-" labels was introduced by Raman and Wenger in 2008, but their table only covered 23 of the 33 possible behaviors, leading to topological errors in ambiguous cases like Case 10 [S1]. Extended Trilinear Triangulation extends the Marching Cubes 33 table to handle the "=" label and correctly resolves all 33 cases using convex hulls and interior tests, as presented in the source paper [S1].
