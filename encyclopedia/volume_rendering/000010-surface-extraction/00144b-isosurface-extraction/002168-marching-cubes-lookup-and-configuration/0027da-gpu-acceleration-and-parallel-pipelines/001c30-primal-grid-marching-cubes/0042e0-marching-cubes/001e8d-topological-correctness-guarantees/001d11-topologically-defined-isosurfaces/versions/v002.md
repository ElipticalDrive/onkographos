# Topologically Defined Isosurfaces

Also called: Digital Geometry Connectedness Marching Cubes

## Overview
Topologically Defined Isosurfaces is a method for extracting a topologically correct, closed, oriented 2-manifold isosurface from a binary volumetric image by modifying the Marching Cubes configuration table based on digital geometry connectedness [S1]. It ensures the surface separates foreground from background without singularities or self-intersections, guaranteeing consistency with the inverse image, unlike empirical corrections which may not represent the underlying volume exactly [S1].

## How it works
**Inputs and Outputs:**
- Input: A binary volumetric image $I$ (voxels are 0 or 1) and a valid connectedness couple $(\eta, \lambda)$ where $\eta \in \{6, 18, 26\}$ is the foreground connectedness and $\lambda \in \{6, 18, 26\}$ is the background connectedness [S1].
- Output: A triangulated isosurface represented as a combinatorial manifold [S1].

**Data Structures:**
- **8-cube ($gs$):** A set of 8 voxels $v_0 \dots v_7$ ordered by binary coding of the index, where $v_i$ and $v_j$ are 26-connected if $i \neq j$ [S1].
- **4-face:** One of the six inner faces of an 8-cube, composed of 4 voxels and shared by exactly two 8-cubes [S1]. Inner 4-faces are oriented and ordered (e.g., clockwise) [S1].
- **Link:** A couple of two 6-connected voxels on a 4-face, with a value based on its voxel values (0 or 1) [S1].
- **Local Graph ($G_{gs}$):** A graph constructed for each 8-cube, consisting of oriented edges and vertices generated on its six oriented inner 4-faces [S1].
- **Complete Graph ($G(I)$):** The union of all local graphs from all 8-cubes in $I$ [S1].

**Steps:**

1.  **Decomposition:** Decompose the binary picture $I$ into all 8-cubes [S1].
2.  **Orientation:** Identify the six inner 4-faces for each 8-cube and orient each inner 4-face such that they are ordered [S1].
3.  **Link Identification:** For each ordered 4-face, identify its four links (couples of 6-connected voxels) and determine the value of each link based on the voxel values [S1].
4.  **Vertex and Edge Generation:** Apply the following rules to each link on the 4-face to generate vertices and oriented edges:
    - If link value is $(0,0)$ or $(1,1)$: No vertex is created [S1].
    - If link value is $(0,1)$: Create one vertex between the voxels; add an **incoming** oriented edge on this vertex staying on the 4-face [S1].
    - If link value is $(1,0)$: Create one vertex between the voxels; add an **outgoing** oriented edge on this vertex staying on the 4-face [S1].
5.  **Handle Indeterminate Cases (4-configuration):** For 4-configurations 6 and 9, the result depends on the valid connectedness couple $(\eta, \lambda)$ [S1]. Arbitrary choices for couples like $(6,6), (18,18), (18,26), (26,18), (26,26)$ produce locally different surfaces in the inverse picture, violating consistency [S1]. Only valid couples $(6, 18), (6, 26), (18, 6), (26, 6)$ guarantee topological correctness [S1].
6.  **Handle Strict 26-Adjacency:** If an 8-cube contains two strictly 26-adjacent 1-voxels and $\eta=26$ (or two strictly 26-adjacent 0-voxels and $\lambda=26$), the local graph is transformed: the two disconnected loops are triangulated to prevent the surface from intersecting the adjacency 3-map [S1].
7.  **Construct Local Graph:** Gather all oriented edges generated on the six oriented inner 4-faces to form the local graph $G_{gs}$ for the 8-cube. Theorem 3 states that for a valid couple, this graph is a set of oriented loops of length $\ge 3$, disconnected from each other [S1].
8.  **Construct Complete Graph:** Extend the set of all local graphs to form the complete graph $G(I)$. Each edge of the complete graph belongs to exactly two loops with different orientations [S1].
9.  **Triangulation:** Derive the final isosurface from the complete graph. If loops have length $> 3$, they are subdivided (triangulated) to form a combinatorial manifold. The embedding of this redefined local graph in $\mathbb{R}^3$ does not intersect the adjacency 3-map of strictly 26-adjacent voxels [S1].

**Pseudocode:**

```python
def topologically_defined_isosurfaces(image, eta, lambda_val):
    """
    Extracts a topologically correct isosurface from a binary image.
    
    Args:
        image: 3D binary array (0 or 1).
        eta: Foreground connectedness (6, 18, or 26).
        lambda_val: Background connectedness (6, 18, or 26).
        
    Returns:
        List of triangles (tuples of 3 vertex keys).
    """
    valid_couples = [(6, 18), (6, 26), (18, 6), (26, 6)]
    if (eta, lambda_val) not in valid_couples:
        raise ValueError(f"Invalid connectedness couple ({eta}, {lambda_val}). Must be one of {valid_couples}")

    # Graph storage: nodes are link midpoints, identified by sorted voxel coordinates
    # adj[u] = v means directed edge u -> v
    adj = {}
    nodes = set()

    dim_x, dim_y, dim_z = image.shape
    # Face definitions: each face is a list of 4 voxel indices in clockwise order
    faces = [
        [0, 1, 3, 2], # bottom
        [4, 5, 7, 6], # top
        [0, 1, 5, 4], # front
        [2, 3, 7, 6], # back
        [0, 2, 6, 4], # left
        [1, 3, 7, 5]  # right
    ]

    for x in range(dim_x - 1):
        for y in range(dim_y - 1):
            for z in range(dim_z - 1):
                # Extract 8-cube voxels and coordinates
                voxels = [
                    image[x, y, z], image[x+1, y, z],
                    image[x, y+1, z], image[x+1, y+1, z],
                    image[x, y, z+1], image[x+1, y, z+1],
                    image[x, y+1, z+1], image[x+1, y+1, z+1]
                ]
                voxel_coords = [
                    (x, y, z), (x+1, y, z),
                    (x, y+1, z), (x+1, y+1, z),
                    (x, y, z+1), (x+1, y, z+1),
                    (x, y+1, z+1), (x+1, y+1, z+1)
                ]

                for face_indices in faces:
                    face_voxels = [voxels[i] for i in face_indices]
                    face_coords = [voxel_coords[i] for i in face_indices]

                    # Identify links (edges of the 4-face)
                    links = []
                    for i in range(4):
                        v1, v2 = face_coords[i], face_coords[(i+1)%4]
                        val1, val2 = face_voxels[i], face_voxels[(i+1)%4]
                        link_key = (min(v1, v2), max(v1, v2))
                        links.append((link_key, val1, val2, i))

                    # Apply rules: (0,0)/(1,1) -> no vertex. (0,1) -> incoming. (1,0) -> outgoing.
                    crossing_links = []
                    for link_key, val1, val2, idx in links:
                        if val1 == 0 and val2 == 1:
                            crossing_links.append((link_key, 'incoming', idx))
                        elif val1 == 1 and val2 == 0:
                            crossing_links.append((link_key, 'outgoing', idx))

                    # Handle indeterminate cases (configurations 6 and 9)
                    # The exact resolution requires a lookup table based on (eta, lambda) [G].
                    # For standard valid couples, consecutive crossing links on the face boundary
                    # are connected respecting the incoming/outgoing direction.
                    if len(crossing_links) == 2:
                        # Connect outgoing to incoming along face traversal
                        out_link = [l for l in crossing_links if l[1] == 'outgoing'][0]
                        in_link = [l for l in crossing_links if l[1] == 'incoming'][0]
                        adj[out_link[0]] = in_link[0]
                        # The return edge is handled by the adjacent 8-cube sharing this face
                    elif len(crossing_links) == 4:
                        for i in range(4):
                            out_link = crossing_links[i]
                            in_link = crossing_links[(i+1)%4]
                            adj[out_link[0]] = in_link[0]

                    for lk in crossing_links:
                        nodes.add(lk[0])

    # Extract loops from the complete graph
    loops = []
    visited = set()
    for start_node in nodes:
        if start_node in visited:
            continue
        loop = []
        curr = start_node
        while curr not in visited:
            visited.add(curr)
            loop.append(curr)
            curr = adj.get(curr)
            if curr is None:
                break
        if len(loop) >= 3:
            loops.append(loop)

    # Triangulate loops to form combinatorial manifold
    triangles = []
    for loop in loops:
        if len(loop) == 3:
            triangles.append(loop)
        else:
            # Fan triangulation from first vertex
            v0 = loop[0]
            for i in range(1, len(loop) - 1):
                triangles.append((v0, loop[i], loop[i+1]))

    return triangles
```

**Parameters:**
- $\eta$ (foreground connectedness): $\{6, 18, 26\}$ [S1].
- $\lambda$ (background connectedness): $\{6, 18, 26\}$ [S1].
- Valid couples: $(6, 18), (6, 26), (18, 6), (26, 6)$ [S1].

**Edge Cases and Pitfalls:**
- **Indeterminate Cases:** Cases 6 and 9 of the 4-configuration are indeterminate and require special handling based on the chosen valid connectedness couple [S1].
- **Invalid Couples:** Arbitrary choices for couples like $(6,6), (18,18), (18,26), (26,18), (26,26)$ produce locally different surfaces in the inverse picture, violating property (iii) (consistency with the inverse image) [S1].
- **Strict 26-Adjacency:** If an 8-cube contains two strictly 26-adjacent 1-voxels and $\eta=26$ (or two strictly 26-adjacent 0-voxels and $\lambda=26$), the local graph must be transformed by triangulating disconnected loops to prevent intersection with the adjacency 3-map [S1].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Strengths:** Guarantees topological correctness (closed, oriented 2-manifold, no self-intersections) and consistency with the inverse image [S1].
- **Limitations:** Requires binary input. The choice of connectedness couple affects the surface shape.
- **When to use:** When topological correctness and consistency with the underlying voxel connectivity are critical.
- **When not to use:** When smoothness is more important than strict topological correctness, or when gradient data is available.

## Background
The method was introduced in "Topologically defined isosurfaces" [S1]. It addresses the limitations of the standard Marching Cubes algorithm, which can produce topologically incorrect surfaces [S1]. The approach is based on digital geometry considerations, specifically the relationship between digital surfaces (Jordan surfaces) and isosurfaces [S1].
