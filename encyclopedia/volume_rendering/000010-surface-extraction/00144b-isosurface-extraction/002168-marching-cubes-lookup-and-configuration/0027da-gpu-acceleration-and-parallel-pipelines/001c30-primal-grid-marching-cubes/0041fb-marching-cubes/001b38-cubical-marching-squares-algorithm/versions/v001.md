# Cubical Marching Squares Algorithm


## Overview
The Cubical Marching Squares Algorithm (CMS) is a surface extraction method for 3D scalar fields that preserves sharp features and maintains consistent topology without generating cracks between adjacent cells [S2]. Unlike standard Marching Cubes, which may produce topological errors or lose sharp features, CMS uses Hermite data and resolves cell ambiguities by analyzing 2D features on cell faces and 3D features within cells [S2]. It eliminates inter-cell dependency, making it suitable for parallel implementation, and generates adaptive surfaces without the need for post-processing crack patching [S2].

## How it works
CMS operates on a uniform grid of scalar values, augmented with normal vectors (Hermite data) to define sharp features. The algorithm processes 2x2x2 voxel neighborhoods, using templates for the faces of these neighborhoods to resolve ambiguities [S1, unofficial]. It reconstructs 3D features from 2D features located on cell faces, ensuring that shared geometric components between neighboring cells are identical, thus preventing cracks [S2].

### Inputs and Outputs
- **Input**: A 3D scalar field defined on a uniform grid. Each grid point may be associated with a normal vector (Hermite data) to represent sharp features.
- **Output**: A polygonal mesh (triangle soup) representing the isosurface.

### Data Structures
The algorithm relies on:
1.  **Grid Data**: Scalar values $f(x,y,z)$ and normal vectors $\mathbf{n}(x,y,z)$ at each grid vertex.
2.  **Face Features**: 2D sharp features identified on the faces of the cubes.
3.  **Component Data**: Lists of vertices and segments forming surface components within a cell or neighborhood.

### Steps

1.  **Face Ambiguity Resolution**:
    For each face of the voxel grid, determine the intersection of the isosurface with the face. If the face configuration is ambiguous (e.g., the "X-face" case where diagonals have the same sign), use the 2D sharp features on that face to resolve the topology. The specific criteria for X-face slashing are defined in [X-face slashing criteria](1777-x-face-slashing-criteria.md).

2.  **Component Formation**:
    Identify connected components of the isosurface intersection within the 2x2x2 neighborhood. A component consists of vertices (segment vertices and face sharp features) and the segments connecting them.

3.  **Sharp Feature Sampling**:
    For each resulting component, sample its 3D sharp feature. This is done by solving a linear system using Singular Value Decomposition (SVD) [S2]:
    $$ T \mathbf{p} = \mathbf{n} $$
    Where:
    - $\mathbf{p}$ is the location of the sharp feature.
    - $T$ is a matrix constructed from sample points $\mathbf{s}_i$ and their normals $\mathbf{n}_i$. Specifically, if there are $k$ sample points, $T$ is a $k \times 3$ matrix where the $i$-th row is $\mathbf{s}_i^T$, and $\mathbf{n}$ is a $k \times 1$ vector where the $i$-th element is $\mathbf{s}_i \cdot \mathbf{n}_i$ [S2].
    - $\mathbf{s}_i$ is the location of a sample point on the component.
    - $\mathbf{n}_i$ is the sample normal at $\mathbf{s}_i$.
    
    [G] In practice, this system is often overdetermined. The SVD solution minimizes the least-squares error $||T\mathbf{p} - \mathbf{n}||^2$.

4.  **Internal Ambiguity Resolution**:
    Determine if two components within the neighborhood are joined or separated. This is done by checking if the 3D sharp features of the two components overlap [S2].
    - For each component, form a cone-like volume centered at its sampled sharp feature $\mathbf{p}$.
    - If the volumes of two components overlap, classify them as **joined**.
    - If they do not overlap, classify them as **separated**.

5.  **Triangulation**:
    - **Separated Components**: For each separated component, generate a triangle fan.
        - If a sharp feature $\mathbf{p}$ exists for the component, use $\mathbf{p}$ as the center.
        - If no sharp feature exists, calculate the average point $\mathbf{c}$ of all sample points on the component and use $\mathbf{c}$ as the center.
        - Let the vertices of the component boundary be $v_1, \dots, v_n$ (including segment vertices and face sharp features).
        - Generate triangles: $p v_1 v_2, p v_2 v_3, \dots, p v_{n-1} v_n, p v_n v_1$ [S2].
    - **Joined Components**: If two components are classified as joined, the resulting surface is topologically equivalent to a cylinder. Use a dynamic programming algorithm to connect and triangulate these two components to form the surface [S2].

### Parameters
- **$\theta$ (theta_sharp)**: A parameter affecting the quality of remeshing, defined in Extended Marching Cubes (EMC) [KBSS01]. Larger values generate more triangles for regions with higher curvatures, while flat regions remain similar. Typical values tested: 0.7, 0.8, 0.9 [S2].

### Edge Cases and Pitfalls
- **Inter-cell Dependency**: CMS eliminates inter-cell dependency by reconstructing 3D features from 2D features on cell faces. This ensures that shared geometric components between neighboring cells are common, preventing cracks without patching [S2].
- **Degenerate Input**: The method assumes well-defined normals for Hermite data. If normals are missing or inconsistent, the sharp feature sampling may fail.
- **Precision**: The SVD calculation for sharp feature location requires numerical stability.

def solve_sharp_feature(sample_points, sample_normals):
    """
    Solves for the sharp feature location p using SVD.
    T * p = n
    T is a matrix where each row is a sample point s_i.
    n is a vector where each element is s_i . n_i.
    """
    # T is (N, 3)
    T = np.array(sample_points)
    # n is (N,)
    n = np.array([np.dot(s, n_vec) for s, n_vec in zip(sample_points, sample_normals)])
    
    # Solve T * p = n using least squares (SVD)
    # p = (T^T T)^-1 T^T n, or via SVD
    U, S, Vt = np.linalg.svd(T, full_matrices=False)
    # Pseudo-inverse of T
    T_pinv = Vt.T @ np.diag(1.0 / S) @ U.T
    p = T_pinv @ n
    return p

## Subtopics

### [X-face slashing criteria](1777-x-face-slashing-criteria.md)
A set of four decision rules used to resolve topological ambiguities on X-faces. These criteria determine whether to merge or split loops based on global topological objectives, such as maximizing or minimizing the total loop count or the number of equivalence classes.

## Operating characteristics
- **Time Complexity**: Not explicitly given in the sources. Performance tests show extraction times scaling with the number of triangles. For a CSG model (cube union cylinder minus sphere), times were 16.23ms (1,688 triangles), 32.14ms (4,880 triangles), and 66.08ms (14,568 triangles) on an Intel Pentium IV 3.2GHz CPU with 1GB memory [S2].
- **Memory Complexity**: Not explicitly given. The algorithm requires storage for grid data, face features, and components.
- **Strengths**: Preserves sharp features, maintains consistent topology, generates surfaces adaptively without crack patching, and eliminates inter-cell dependency [S2]. Lower average geometric error than Dual Contouring and Extended Marching Cubes [S2].
- **Limitations**: The dynamic programming algorithm for joined components adds complexity. GPU implementation was partially done but speed was only comparable to CPU [S2].
- **When to use**: CSG modeling, level of details, and remeshing polygonal meshes by converting them to distance field volume representations [S2].

## Background
The Cubical Marching Squares Algorithm was proposed by researchers at NTU (National Taiwan University) [S2]. It builds on the idea of using templates for faces of 2x2x2 voxel neighborhoods, similar to previous cubically based approaches [S1, unofficial]. The method was developed to address the limitations of Marching Cubes, such as topological errors and loss of sharp features. It was partially implemented on GPU, though performance gains were limited compared to CPU [S2].
