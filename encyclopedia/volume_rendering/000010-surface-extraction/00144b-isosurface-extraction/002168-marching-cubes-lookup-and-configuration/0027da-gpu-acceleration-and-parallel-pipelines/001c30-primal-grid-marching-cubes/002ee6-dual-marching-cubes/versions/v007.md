# Dual Marching Cubes

Also called: DMC, Dual MC, Nielson 2004 Dual MC, Nielson's Dual Marching Cubes, Regular Octree Dual Vertex Placement

## Overview
Dual Marching Cubes (DMC) is an isosurface extraction algorithm that generates topological manifold surfaces by unifying standard Marching Cubes (MC) surface fragments into polygonal patches, then constructing a dual mesh where each patch becomes a vertex and each patch vertex becomes a quadrilateral face [S2, unofficial]. Unlike standard MC, which outputs a triangle soup with potential topological ambiguities and non-manifold edges, DMC ensures manifold connectivity by associating dual vertices with lattice edges shared by four cells [S2, unofficial]. It differs from [Dual Contouring](1211-dual-contouring.md) by relying on a lookup-table-based classification of 23 canonical configurations rather than explicit QEF minimization for vertex placement, and from [Primal Grid Marching Cubes](1211-primal-grid-marching-cubes.md) by operating on a dual grid structure where vertices are placed at cell centers or edge intersections rather than primal grid points [S4, unofficial][S8, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A 3D scalar field $F_{ijk}$ defined on a rectilinear grid of lattice points $(x_i, y_j, z_k)$ [S8, unofficial].
- **Output:** A quadrilateral mesh (or triangulated quad mesh) where vertices correspond to surface patches and faces correspond to primal grid edges intersecting the isosurface [S2, unofficial].

**Data Structures:**
1.  **Dual Grid:** A grid of dimensions $(X-1) \times (Y-1) \times (Z-1)$, where each cell corresponds to a primal voxel [S4, unofficial][S9, unofficial].
2.  **Dual Points:** An array of size $(X-1)(Y-1)(Z-1)$ storing dual vertex positions and validity flags [S7, unofficial].
3.  **Lookup Table:** A table of 256 entries (derived from 23 base cases) mapping an 8-bit configuration key to bipolar edge indices and dual vertex positions [S3, unofficial].
4.  **Tree Structure (Optional):** For hierarchical implementations, a tree of branch and leaf nodes representing the scalar field, where leaf nodes store a center and offset [S1, unofficial].

**Steps:**

1.  **Initialization:**
    - Compute grid dimensions from the bounding box and cell width [S1, unofficial].
    - Initialize the dual grid and dual point arrays [S4, unofficial][S7, unofficial].
    - If using a hierarchical tree, initialize thread-local pools for branch and leaf nodes [S1, unofficial].

2.  **Classification and Key Generation:**
    - For each primal voxel (or cell), identify the scalar values at its 8 vertices [S3, unofficial].
    - Construct an 8-bit key $K$ where the $i$-th bit is 1 if $F_i \ge \text{IsoValue}$ and 0 otherwise [S3, unofficial].
    - If using a hierarchical tree, evaluate the object's value and gradient at each corner, sanitize NaN gradients to 0.0, and recursively split cells if the error exceeds a tolerance [S1, unofficial].

3.  **Dual Vertex Placement:**
    - For each intersected lattice edge (where endpoint values differ), associate it with the four adjacent cells [S2, unofficial].
    - For each of the four cells, compute the key and access the lookup table to determine the bipolar edges and the dual vertex position [S3, unofficial].
    - **Position Calculation:**
        - **Simple Mode:** Place the dual vertex at the center of the voxel (or cell) [S7, unofficial].
        - **Smooth Mode:** Calculate the position using Hermite points (intersections) or a simplified Quadratic Error Function (QEF) average [S7, unofficial]. If normals are available, use QEF minimization; otherwise, use the centroid of crossings [S5, unofficial].
        - **Linear Interpolation:** For edge intersections, compute the position $P$ using linear interpolation:
          $$ t = \frac{\text{IsoValue} - v_1}{v_2 - v_1} $$
          $$ P = p_1 + t \cdot (p_2 - p_1) $$
          If $|\text{IsoValue} - v_1| < \epsilon$, use $p_1$ directly [S7, unofficial].

4.  **Mesh Construction:**
    - For each intersected lattice edge, retrieve the four dual vertices (one from each adjacent cell) [S3, unofficial].
    - Connect these four vertices to form two triangles (a quad) [S3, unofficial].
    - **Ambiguity Resolution:** If a cell has configuration 2B or 3B and shares an ambiguous face with another cell of the same type, use an alternative edge configuration to prevent non-manifold edges [S3, unofficial].

5.  **Enumeration (Tree-based):**
    - Iterate over all cells in shuffled order for parallel processing [S1, unofficial].
    - For leaf nodes, enumerate triangles directly [S1, unofficial].
    - For branch nodes, recursively process children [S1, unofficial].
    - Handle boundary conditions: The cube callback is invoked only if $x>0, y>0, z>0$ [S4, unofficial].

**Pseudocode:**

```python
def dual_marching_cubes(grid, iso_value, method='vega'):
    """
    Extract isosurface from a 3D scalar grid using Dual Marching Cubes.
    
    Args:
        grid: 3D array of scalar values (X, Y, Z)
        iso_value: Threshold for surface extraction
        method: Variant ('vega', 'lewiner', 'nagae', 'lorensen')
        
    Returns:
        vertices: Array of (x, y, z) positions
        indices: Array of triangle indices
    """
    X, Y, Z = grid.shape
    # Dual grid dimensions are (X-1) x (Y-1) x (Z-1)
    dual_points = [None] * ((X-1) * (Y-1) * (Z-1))
    
    # Precompute lookup table based on method
    lookup_table = build_lookup_table(method)
    
    # Step 1: Classify cells and place dual vertices
    for z in range(Z - 1):
        for y in range(Y - 1):
            for x in range(X - 1):
                # Get 8 corner values
                corners = [
                    grid[x, y, z], grid[x+1, y, z], grid[x, y+1, z], grid[x+1, y+1, z],
                    grid[x, y, z+1], grid[x+1, y, z+1], grid[x, y+1, z+1], grid[x+1, y+1, z+1]
                ]
                
                # Build 8-bit key
                key = 0
                for i, val in enumerate(corners):
                    if val >= iso_value:
                        key |= (1 << i)
                
                # Determine active edges and dual vertex position
                config = lookup_table[key]
                if config.num_vertices == 0:
                    continue
                
                # Place dual vertex for this cell
                # Simple mode: center of voxel
                pos = (x + 0.5, y + 0.5, z + 0.5)
                
                # Smooth mode: average of Hermite points or QEF
                # For implementation, assume get_dual_point computes this
                if use_smooth_mode:
                    pos = get_dual_point(grid, x, y, z, iso_value)
                
                dual_points[index(x, y, z)] = pos
    
    # Step 2: Connect dual vertices into quads/triangles
    vertices = []
    indices = []
    
    for z in range(Z - 1):
        for y in range(Y - 1):
            for x in range(X - 1):
                # Check for intersected edges
                # An edge intersects if endpoints have different signs relative to iso_value
                # For each intersected edge, connect the 4 adjacent dual vertices
                edges = get_intersected_edges(grid, x, y, z, iso_value)
                
                for edge in edges:
                    # Get the 4 adjacent cells sharing this edge
                    adjacent_cells = get_adjacent_cells(edge, x, y, z)
                    
                    # Retrieve dual vertices for these cells
                    dual_verts = []
                    for cell in adjacent_cells:
                        cx, cy, cz = cell
                        if 0 <= cx < X-1 and 0 <= cy < Y-1 and 0 <= cz < Z-1:
                            dual_verts.append(dual_points[index(cx, cy, cz)])
                        else:
                            dual_verts.append(None)
                    
                    if len(dual_verts) == 4 and all(v is not None for v in dual_verts):
                        # Add vertices to global list
                        v_indices = []
                        for v in dual_verts:
                            if v not in vertices:
                                vertices.append(v)
                            v_indices.append(vertices.index(v))
                        
                        # Create two triangles from the quad
                        # Order depends on edge orientation and method
                        indices.extend([v_indices[0], v_indices[1], v_indices[2]])
                        indices.extend([v_indices[0], v_indices[2], v_indices[3]])
    
    return vertices, indices

def get_dual_point(grid, x, y, z, iso_value):
    """
    Calculate smoothed dual vertex position using Hermite points.
    """
    # Collect intersection points on edges of the voxel
    hermite_points = []
    for edge in voxel_edges:
        p1, p2 = edge.endpoints
        v1, v2 = edge.values
        if (v1 - iso_value) * (v2 - iso_value) < 0:
            t = (iso_value - v1) / (v2 - v1)
            point = lerp(p1, p2, t)
            hermite_points.append(point)
    
    if not hermite_points:
        return (x + 0.5, y + 0.5, z + 0.5)
    
    # Simplified QEF: average of Hermite points
    avg = sum(hermite_points) / len(hermite_points)
    return avg
```

**Parameters:**
- `IsoValue`: Scalar threshold. Default 0.0 [S7, unofficial].
- `config_.tolerance`: Error threshold for leaf node creation in hierarchical trees [S1, unofficial].
- `config_.maximum_depth`: Max recursion depth for tree [S1, unofficial].
- `config_.nominal_weight`: Weight for regularization in QEF [S1, unofficial].
- `bSmooth`: Boolean flag for smoothed vertex placement [S7, unofficial].

**Edge Cases and Pitfalls:**
- **Ambiguous Configurations:** Cells with configurations 2B or 3B sharing an ambiguous face can create non-manifold edges. Resolve by checking adjacent cells and using alternative edge configurations [S3, unofficial].
- **Boundary Conditions:** The dual grid is smaller than the primal grid. Ensure boundary checks when accessing neighbors [S7, unofficial].
- **Normal Orientation:** Geometric normals may be inverted. Flip if dot product with average gradient is negative [S7, unofficial].
- **Precision:** Use epsilon comparison for value checks to avoid numerical instability [S7, unofficial].

## Subtopics

### [Dual Mesh Building](1423-dual-mesh-building.md)
Dual Mesh Building constructs a quadrilateral mesh from a scalar volume grid by mapping MC polygon vertices to dual mesh vertices, where each dual vertex represents an MC polygon and each dual face corresponds to an MC vertex. It solves the problem of generating manifold, watertight meshes with better-shaped elements and fewer vertices than standard MC. Unlike standard MC, which outputs triangles from edge intersections, Dual Mesh Building outputs quads by connecting vertex representatives from the four cells sharing an intersected grid edge. It differs from [Manifold Dual Marching Cubes](2135-manifold-dual-marching-cubes.md) by relying on the asymptotic decider for topological consistency rather than explicit ambiguous configuration correction, and from [Parallel Dual Marching Cube](2131-parallel-dual-marching-cube.md) by focusing on the general algorithmic construction of the dual topology and geometry.

### [Parallel Dual Marching Cube](2131-parallel-dual-marching-cube.md)
Parallel Dual Marching Cube (PDMC) is an intersection-free iso-surface extraction method that processes a 3D signed distance field (SDF) grid on the GPU to produce a triangle or quadrilateral mesh. It is implemented as a CUDA kernel accessible via a PyTorch C++ extension.

### [Dual Marching Cubes Vertex Processing](3688-dual-marching-cubes-vertex-processing.md)
Dual Marching Cubes Vertex Processing (`vertProc`) processes a dual cell (8 nodes) to generate mesh vertices and triangles using Marching Cubes on the dual vertices. It handles hierarchical subdivision by recursively resolving child nodes before generating geometry.

### [Dual Methods](8116-dual-methods.md)
Dual methods are a class of isosurface extraction algorithms that generate surface topology by creating an $(n-1)$-cell for every edge crossing the boundary in 3D, resulting in a mesh where topology is completely determined by the sample complex. Unlike primal methods such as Marching Cubes, which suffer from topological ambiguity in non-simplicial cells, dual methods resolve ambiguities by construction, though they may produce non-manifold vertices.

### [Dual Marching Cubes with Ambiguity Resolution and Regularization](11165-dual-marching-cubes-with-ambiguity-resolution-and-regulariza.md)
A differentiable isosurface extraction method that computes dual vertices for grid cubes based on topology cases, resolving topological ambiguities (C16/C19) by checking adjacent cubes, and optionally optimizing vertex positions using a Quadratic Error Function (QEF) with gradient normals or linear interpolation with learned weights.

### Generalized Symmetric Dual Marching Cubes
A method for extracting constant-wind-speed isosurfaces from 3D wind-field data (e.g., ERA5, WRF) stored in 3D NetCDF format [S11, unofficial]. It computes case-indices using vectorized 8-bit computation, performs QEF minimization with Tikhonov regularization for rank-deficient cases, and assembles the dual mesh by finding active primal edges and forming quads split into triangles with correct outward winding [S11, unofficial]. It supports QEF minimization and average-point modes for dual vertex placement [S11, unofficial].

### Novel Interpolation for Dual Marching Cubes on Octree Volume Fraction Data
A surface extraction method for volume fraction data stored on an octree that approximates octant shapes as spheres rather than cubes to avoid artifacts from steep value variations [S12]. It computes dual grid vertices on dual edges crossing the surface using novel interpolation, connecting them to form a mesh. Unlike Dual Contouring, it does not require gradient vectors, and unlike Poisson reconstruction, it does not require Hermite data [S12].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed once [S2, unofficial]. Parallel implementations achieve near-linear scaling on GPUs [S2, unofficial].
- **Memory Complexity:** $O(N)$ for storing the dual grid and output mesh [S4, unofficial].
- **Performance:** Generates manifold surfaces with fewer vertices than standard MC, reducing memory overhead for smoothing and subdivision [S2, unofficial].
- **Strengths:** Topological manifold guarantee, better mesh quality (quads vs. thin triangles), suitable for procedural terrain modeling and medical imaging [S2, unofficial][S7, unofficial].
- **Limitations:** May produce non-manifold edges in ambiguous configurations if not resolved [S3, unofficial]. The resulting mesh ends half a cell short of the grid boundary [S5, unofficial].
- **When to Use:** When manifold connectivity and smooth subdivision are required, or when rendering enumerated volumes from segmented medical data where threshold values are irrelevant [S2, unofficial][S8, unofficial].
- **When Not to Use:** When simple, fast extraction is prioritized over mesh quality, or when the input data is not on a regular grid [S2, unofficial].

## Background
Dual Marching Cubes was introduced by Gregory Nielson in 2004 [S2, unofficial][S8, unofficial]. It was designed to address the topological ambiguities and poor mesh quality of standard Marching Cubes, particularly for procedural terrain modeling and volume visualization [S2, unofficial]. The method unifies MC surface fragments into polygonal patches, creating a dual surface that is always a topological manifold [S2, unofficial]. It has been extended to parallel GPU implementations and adapted for various data types, including wind fields and octree volume fraction data [S2, unofficial][S11, unofficial][S12].
