# Mesh simplification via face coloring

Also called: Cell-based coloring, DMC simplification, Uniform structure coloring, Vertex and face coloring for parallel mesh processing

## Overview
Mesh simplification via face coloring is a parallel method for reducing the element count of dual marching cubes (DMC) meshes by identifying and removing quadrilaterals based on vertex valence patterns [S1]. It solves the problem of excessive mesh density in isosurface extraction by leveraging the uniform structure of volume data to assign colors to cells, vertices, and faces, enabling conflict-free parallel simplification [S1]. It sets itself apart from sibling methods by using a derived 5-color face scheme to identify specific valence patterns (3-X–3-Y and 3-3-3-3) for removal, whereas siblings like [Manifold Dual Marching Cubes](2135-manifold-dual-marching-cubes.md) focus on topological consistency and [Halfedge Data Structure Construction](2310-halfedge-data-structure-construction.md) focuses on connectivity representation [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A dual marching cubes mesh consisting of quadrilaterals, where each quadrilateral is associated with a cell edge from the volume grid. The mesh is derived from [Dual Mesh Building](1423-dual-mesh-building.md).
*   **Output:** A simplified mesh with reduced element count and a recomputed halfedge data structure.

**Data Structures:**
*   **Cell Index:** 3D integer tuple $(i, j, k)$ representing the position in the volume grid.
*   **Cell Color ($c_v$):** Integer in $[0, 7]$.
*   **Edge Color ($c_e$):** Integer in $[0, 23]$.
*   **Quadrilateral Color ($c_q$):** Integer in $[0, 4]$.
*   **Vertex Valence:** The number of quadrilaterals incident to a vertex.

**Formulas:**
1.  **Cell Color:** Derived from the 3D cell index $(i, j, k)$ using bitwise operations [S1]:
    $$c_v = (i \& 1) \ | \ ((j \& 1) \ll 1) \ | \ ((k \& 1) \ll 2)$$
    This results in 8 distinct colors.

2.  **Edge Color:** Derived from the cell color $c_v$ and the local edge index $e$ incident to vertex $v_0$ [S1]:
    $$c_e = 3 \times c_v + e$$
    where $e \in \{0, 1, 2\}$ corresponds to local edges $e_0, e_3, e_8$. This results in 24 distinct edge colors.

3.  **Quadrilateral Color:** Each cell edge corresponds to a maximum of one quadrilateral. The edge color is transferred directly to the quadrilateral. A reduction kernel then maps colors $\ge 5$ to the range $[0, 4]$ [S1].

**Numbered Steps:**

1.  **Compute Cell Colors:** For every active cell in the volume grid, compute $c_v$ using the formula above.
2.  **Transfer Colors to Vertices:** Vertices inherit colors from their adjacent cells. Since vertices in the dual mesh only have neighbors in adjacent cells, this transfer is straightforward [S1].
3.  **Compute Edge Colors:** For each cell, compute the colors of its edges $e_0, e_3, e_8$ using $c_e = 3 \times c_v + e$.
4.  **Transfer Colors to Quadrilaterals:** Assign the computed edge color $c_e$ to the quadrilateral associated with that edge.
5.  **Reduce Quadrilateral Colors:**
    *   Initialize a second kernel to process faces.
    *   Iterate through all quadrilaterals with current color $c_q \ge 5$.
    *   For each such quadrilateral, check the colors of its neighboring quadrilaterals.
    *   Assign a new color $c_q' \in \{0, 1, 2, 3, 4\}$ that does not appear in its immediate neighborhood.
    *   This ensures that no two adjacent quadrilaterals share the same color, using only 5 colors [S1].
6.  **Identify Simplification Candidates:**
    *   Identify quadrilaterals based on the valence patterns of their incident vertices [S1].
    *   **Pattern 3-X–3-Y:** Vertices with valence 3, X, 3, Y (where X and Y are other valences).
    *   **Pattern 3-3-3-3:** All four incident vertices have valence 3.
7.  **Simplify Elements:**
    *   Remove quadrilaterals identified in Step 6.
    *   For the 3-X–3-Y pattern, vertices are repositioned during simplification [S1].
    *   For the 3-3-3-3 pattern, elements are removed directly [S1].
8.  **Recompute Halfedge Data Structure:** After each simplification step, the halfedge data structure must be recomputed to maintain connectivity integrity [S1].

**Pseudocode:**

```python
def compute_cell_color(i, j, k):
    """Compute cell color from 3D index."""
    return (i & 1) | ((j & 1) << 1) | ((k & 1) << 2)

def compute_edge_color(cell_color, local_edge_index):
    """Compute edge color from cell color and local edge index."""
    # local_edge_index is 0, 1, or 2 for edges e0, e3, e8
    return 3 * cell_color + local_edge_index

def reduce_quadrilateral_colors(quads):
    """
    Reduce quadrilateral colors to 5 colors.
    quads: list of quadrilaterals, each with a 'color' attribute.
    Returns: updated list of quadrilaterals.
    """
    # Note: In a parallel implementation, this would be a kernel.
    # Here we simulate the logic for clarity.
    
    # First pass: mark quads with color >= 5 for reduction
    quads_to_reduce = [q for q in quads if q.color >= 5]
    
    for quad in quads_to_reduce:
        # Get neighbors of the quad
        neighbors = get_neighbors(quad)
        # Get colors of neighbors
        neighbor_colors = {n.color for n in neighbors}
        
        # Find smallest color in [0, 4] not in neighbor_colors
        new_color = 0
        while new_color in neighbor_colors:
            new_color += 1
        
        quad.color = new_color
        
    return quads

def simplify_mesh(mesh):
    """
    Simplify the mesh based on valence patterns.
    mesh: Dual marching cubes mesh object.
    """
    # Step 1: Compute cell colors
    cell_colors = {}
    for cell in mesh.cells:
        cell_colors[cell.id] = compute_cell_color(cell.i, cell.j, cell.k)
        
    # Step 2: Transfer colors to vertices
    for vertex in mesh.vertices:
        # Vertices inherit colors from adjacent cells
        # In practice, this might involve averaging or picking one
        vertex.color = get_vertex_color_from_cells(vertex, cell_colors)
        
    # Step 3 & 4: Compute and transfer edge colors to quads
    for quad in mesh.quads:
        edge_index = quad.local_edge_index # 0, 1, or 2
        cell_color = cell_colors[quad.cell_id]
        quad.color = compute_edge_color(cell_color, edge_index)
        
    # Step 5: Reduce colors
    mesh.quads = reduce_quadrilateral_colors(mesh.quads)
    
    # Step 6 & 7: Simplify based on valence
    # Identify quads with valence patterns
    quads_to_remove = []
    for quad in mesh.quads:
        valences = get_vertex_valences(quad)
        if is_pattern_3x3y(valences):
            quads_to_remove.append(quad)
        elif is_pattern_3333(valences):
            quads_to_remove.append(quad)
            
    # Remove quads
    for quad in quads_to_remove:
        mesh.remove_quad(quad)
        
    # Step 8: Recompute halfedge structure
    mesh.recompute_halfedge_structure()
    
    return mesh
```

**Parameters:**
*   Number of cell colors: 8 [S1].
*   Number of edge colors: 24 [S1].
*   Final number of quadrilateral colors: 5 [S1].

**Edge Cases and Pitfalls:**
*   **Precision and Boundaries:** Boundary cells do not generate quadrilaterals if an entry in the hash table bucket is an invalid index [S1].
*   **Valence Patterns:** The 3-X–3-Y pattern simplification repositions vertices, which increases the deviation from the iso-value [S1].
*   **Quality Trade-off:** Simplification improves quadrilateral quality but reduces triangle quality and increases the number of irregular vertices for triangular meshes [S1].
*   **Halfedge Recomputation:** The halfedge data structure must be recomputed after each simplification step, which is computationally expensive due to global memory access on the GPU [S1].

## Operating characteristics
*   **Time Complexity:** The coloring steps are parallel and efficient. However, the halfedge data structure computation is time-consuming due to many global memory accesses on the GPU [S1].
*   **Memory Complexity:** Requires storage for cell, edge, and quadrilateral colors. The reduction step requires temporary storage for neighbor checks.
*   **Measured Performance:** For the human skull surface, 352,337 elements with the 3-X–3-Y pattern were simplified, compared to 167,537 with the previous method [S1]. The 3-3-3-3 pattern simplification reduces the total number of elements by 5% [S1].
*   **Scaling:** The method is designed for parallel execution on GPUs, leveraging the uniform structure of volume data.
*   **Strengths:** Significantly reduces element count compared to previous methods. Improves quadrilateral quality.
*   **Limitations:** Increases deviation from the iso-value for 3-X–3-Y patterns. Reduces triangle quality. Requires expensive halfedge recomputation.
*   **When to Use:** When a high-quality quad-only mesh is desired and element count reduction is important.
*   **When Not to Use:** When strict adherence to the iso-value is critical (due to vertex repositioning in 3-X–3-Y patterns) or when triangle quality is more important than quad quality.

## Background
The method was introduced in a parallel dual marching cubes approach to quad-only surface reconstruction [S1]. It builds on the uniform structure of volume data to enable efficient parallel processing. The method was evaluated on various datasets including torso, body, synthetic iWP, and gen2 data sets [S1].
