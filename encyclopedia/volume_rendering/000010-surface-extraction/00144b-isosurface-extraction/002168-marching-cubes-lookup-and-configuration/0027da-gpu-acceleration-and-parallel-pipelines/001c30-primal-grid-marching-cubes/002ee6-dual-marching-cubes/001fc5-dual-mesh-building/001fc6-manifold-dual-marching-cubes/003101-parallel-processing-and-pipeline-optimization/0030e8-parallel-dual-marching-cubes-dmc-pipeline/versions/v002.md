# Parallel Dual Marching Cubes (DMC) Pipeline

Also called: Multi-staged DMC pipeline, Parallel DMC on Regular Grids

## Overview
The Parallel Dual Marching Cubes (DMC) Pipeline is a surface extraction method that generates a manifold quadrilateral mesh with full connectivity information (1-ring vertex neighborhoods) from a regular 3D grid [S1, unofficial]. It solves the problem of unconnected primitives and missing adjacency data inherent in standard parallel extraction by combining static and dynamic lookup tables with parallel reduction algorithms [S1, unofficial]. Unlike standard parallel Marching Cubes which produces independent fragments, this method ensures topological correctness and provides immediate neighbor access for downstream applications like smoothing or physics, distinguishing it from its sibling [Dual Marching Cubes (Counting Pass)](3766-dual-marching-cubes-counting-pass.md) by adding explicit connectivity generation and vertex relocation [S1, unofficial].

## How it works
The pipeline operates in a multi-stage sequence: Block Selection, Classification, Indexing, Cell Selection, and Mesh Generation (split into Vertex and Face phases). It relies on a regular grid definition and specific lookup tables to decouple stages and ensure manifold connectivity.

### Inputs and Outputs
*   **Input:** A regular 3D grid $L$ of scalar values $v_{i,j,k}$, an isovalue $\alpha$, and block-level min/max density bounds.
*   **Output:** A vertex buffer, a face buffer, and an index table mapping cells to buffer locations. The mesh is a manifold surface with 1-ring neighbor information available per vertex.

### Data Structures
The method uses static lookup tables (precomputed) and dynamic tables (generated per volume).

**Static Lookup Tables:**
1.  **Vertex-Edges Table:** Maps a cell case and a cell vertex to a 12-bit vector representing the set of active edges associated with that vertex [S1, unofficial].
2.  **Edge-Vertex Table:** Maps a cell case and an edge to a 24-bit vector identifying the associated cell vertex [S1, unofficial].
3.  **Vertex-Adjacencies Table:** Maps a cell case and a cell vertex to a sorted set of tuples $(V_{zyx}, e)$, where $V_{zyx}$ is the offset to the adjacent cell and $e$ is the associated edge, sorted in 1-ring order [S1, unofficial].
4.  **Face Table:** Maps a cell case to a set of faces generated by the cell [S1, unofficial].
5.  **DM_VERT_COUNT[256]** and **DM_QUAD_COUNT[256]**: Map cube configuration masks (0-255) to the number of vertices and quads generated [S1, unofficial].

**Dynamic/Intermediate Tables:**
1.  **Case Table:** Dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$. Stores the cell case for each cell [S1, unofficial].
2.  **Index Table:** Dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$. Stores the index of the first face and vertex for each cell in the mesh buffers [S1, unofficial].

### Grid Definition
The input is a regular grid $L$ defined with a spacing factor of 4 relative to base units $x, y, z$:
$$L = \{(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z) : i = 0,...,N_x; j = 0,...,N_y; k = 0,...,N_z\}$$
Values are sampled as $v_{i,j,k} = f(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z)$ [S1, unofficial].
Cell $(i,j,k)$ is defined by the diagonal from $(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z)$ to $((i+1) \cdot 4 \cdot x, (j+1) \cdot 4 \cdot y, (k+1) \cdot 4 \cdot z)$ [S1, unofficial].

### Classification
For each cell, inspect the 8 corner values $v_{i,j,k}$ relative to the isovalue $\alpha$:
*   $v_{i,j,k} > \alpha$ is classified as **inside**.
*   $v_{i,j,k} \le \alpha$ is classified as **outside** [S1, unofficial].
This yields 256 possible configurations, grouped into 23 canonical configurations [S1, unofficial].

### Indexing (Parallel Scan)
An all-prefix-sum (scan) is performed on vertex and face counts to compute total buffer sizes and map cells to unique locations [S1, unofficial].
The scan transforms an array $A = \{a_0, ..., a_{n-1}\}$ to $A_0 = \{I, a_0, (a_0 \oplus a_1), ..., (a_0 \oplus ... \oplus a_{n-2})\}$, where $I$ is the identity and $\oplus$ is addition [S1, unofficial].
The total buffer sizes are the sum of the last elements of the transformed arrays. The total count is transferred to the host for allocation [S1, unofficial].

### Vertex Buffer Location
For a cell $(i,j,k)$ with index $I_{i,j,k}$ from the Index Table, the location of the $x$-th vertex in the vertex buffer is:
$$vertex\_buffer[I_{i,j,k} + x] = vertex\_data$$
Indices for the face buffer are computed analogously [S1, unofficial].

### Parameters
*   **Grid Spacing Factor:** 4. The grid is defined as $L = \{(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z)\}$ [S1, unofficial].
*   **Isovalue ($\alpha$):** The threshold for classification.
*   **Block Size:** Mapped to thread groups; size not specified in sources [S1, unofficial].

### Edge Cases and Pitfalls
*   **Unconnected Primitives:** Standard parallel processing produces unconnected primitives because cells are analyzed independently. This is solved by the static/dynamic lookup tables ensuring manifold connectivity [S1, unofficial].
*   **Performance Penalties:** Complex QEF minimization using pseudoinverse leads to performance penalties due to limited register counts on parallel hardware. The proposed QEM-based relocation is less computationally complex, achieving lower quality but sufficient for terrain volume preservation [S1, unofficial].
*   **Memory Usage:** The dynamic tables double the memory effort compared to standard methods [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The pipeline is dominated by parallel scan and grid traversal. The scan is $O(N)$ where $N$ is the number of cells. Mesh generation is proportional to the number of surface cells.
*   **Memory Complexity:** The method uses static lookup tables and dynamic Case/Index tables of size $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$. The sources note that "The tables double the memory effort" compared to non-table-based approaches [S1, unofficial].
*   **Performance:** The method is designed for interactivity. The switch from block-based to cell-based processing in the Cell Selection stage "significantly accelerates the mesh generation" [S1, unofficial].
*   **Strengths:** Generates manifold surfaces with full 1-ring connectivity; suitable for interactive applications; parallelizable.
*   **Limitations:** Lower vertex quality compared to full QEF minimization (though sufficient for terrain); higher memory usage due to lookup tables.

## Background
The method is based on Dual Marching Cubes by Nielson [Nie04] [S1, unofficial]. It was developed to address the lack of interactivity and connectivity in standard parallel surface extraction. The specific implementation described in [S1, unofficial] introduces a multi-staged pipeline with static/dynamic lookup tables and QEM-based vertex relocation. It builds on [Parallel Processing and Pipeline Optimization](6411-parallel-processing-and-pipeline-optimization.md) by applying the shared two-phase (counting/generation) approach with specific optimizations for DMC.
