# Parallel Dual Marching Cubes (DMC) Pipeline

Also called: Multi-staged DMC pipeline, Parallel DMC on Regular Grids

## Overview
The Parallel Dual Marching Cubes (DMC) Pipeline is a surface extraction method that generates a manifold quadrilateral mesh with full connectivity information (1-ring neighbors) from a regular 3D grid [S1, unofficial]. It solves the problem of unconnected primitives and missing adjacency data inherent in standard parallel extraction by combining static and dynamic lookup tables with parallel reduction algorithms [S1, unofficial]. Unlike standard parallel Marching Cubes which produces redundant and unconnected fragments, this method ensures manifold connectivity through a multi-staged pipeline that switches from block-based to cell-based processing [S1, unofficial]. It builds on [Dual Marching Cubes](3766-dual-marching-cubes-counting-pass.md) but extends it for interactive performance on parallel hardware.

## How it works
**Inputs and Outputs:**
*   **Input:** A regular 3D grid $L$ of scalar values $v_{i,j,k}$ representing a function $f: \mathbb{R}^3 \rightarrow \mathbb{R}$, and an isovalue $\alpha$ [S1, unofficial].
*   **Output:** A quadrilateral surface mesh with vertex positions, face connectivity, and 1-ring neighbor adjacency data [S1, unofficial].

**Data Structures:**
The method relies on several lookup tables and buffers. All tables are precomputed or computed during the pipeline.

1.  **Static Lookup Tables:**
    *   **Vertex-Edges Table:** Maps a cell case and a cell vertex to a 12-bit vector (1 bit per edge) representing the set of associated active edges [S1, unofficial].
    *   **Edge-Vertex Table:** Maps a cell case and an edge to a 24-bit vector (2 bits per edge) identifying the associated cell vertex [S1, unofficial].
    *   **Vertex-Adjacencies Table:** Maps a cell case and a cell vertex to a sorted set of tuples $(V_{zyx}, e)$, where $V_{zyx}$ is the offset to the adjacent cell and $e$ is the associated edge, sorted in 1-ring order [S1, unofficial].
    *   **Face Table:** Maps a cell case to a set of faces generated by the cell [S1, unofficial].

2.  **Dynamic/Intermediate Tables (3D Arrays):**
    *   **Case Table:** Dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$. Stores the cell case for each cell in the volume [S1, unofficial].
    *   **Index Table:** Dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$. Stores the index of the first face and vertex for each cell in the mesh buffers. For a cell $(i,j,k)$ and its $x$-th vertex, the location in the vertex buffer is $I_{i,j,k} + x$ [S1, unofficial].

**Parameters:**
*   **Grid Spacing Factor:** The regular grid definition uses a spacing factor of 4 relative to base units $x,y,z$ [S1, unofficial].
*   **Isovalue ($\alpha$):** The threshold for classification [S1, unofficial].

**Numbered Steps:**

1.  **Block Selection:**
    *   Evaluate the condition $\min \le \alpha < \max$ for each block's minimum and maximum density values in parallel [S1, unofficial].
    *   Store the indices of selected blocks in a buffer [S1, unofficial].

2.  **Classification:**
    *   Map one block to one thread group [S1, unofficial].
    *   Load grid values for the block into local memory [S1, unofficial].
    *   For each cell $(i,j,k)$ in the block, inspect the 8 corner values $v_{i,j,k}$ relative to $\alpha$ [S1, unofficial].
    *   Classify $v_{i,j,k} > \alpha$ as inside and $v_{i,j,k} \le \alpha$ as outside [S1, unofficial].
    *   Determine the cell case (one of 23 canonical configurations) and store it in the Case Table [S1, unofficial].

3.  **Indexing:**
    *   Perform a parallel all-prefix-sum (scan) on vertex and face counts to compute total buffer sizes and map cells to unique locations [S1, unofficial].
    *   The scan transforms an array $A = \{a_0, ..., a_{n-1}\}$ to $A_0 = \{I, a_0, (a_0 \oplus a_1), ..., (a_0 \oplus ... \oplus a_{n-2})\}$ where $I$ is the identity and $\oplus$ is the associative operator (addition) [S1, unofficial].
    *   Transfer the total count to the host for buffer allocation [S1, unofficial].
    *   Count relevant cells and write their indices $(i,j,k)$ to a buffer [S1, unofficial].
    *   Switch from block-based to cell-based processing [S1, unofficial].

4.  **Mesh Generation Phase 1 (Vertices):**
    *   For each relevant cell, relocate vertices using a Quadric Error Metric (QEM) based approach [S1, unofficial].
    *   Determine storage location in mesh buffers via the Index Table [S1, unofficial].
    *   Gather 1-ring neighbors using the Vertex-Adjacencies Table [S1, unofficial].

5.  **Mesh Generation Phase 2 (Faces):**
    *   Generate faces using a parallel scheme [SDC09] [S1, unofficial].
    *   For each cell, choose three edges sharing the same origin (along x, y, z axes) [S1, unofficial].
    *   Use the extended Face Table and Vertex-Edges Table to map local edges to adjacent cell edges to form quadrilaterals [S1, unofficial].

**Formulas:**
*   **Grid Definition:** $L = \{(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z) : i = 0,...,N_x; j = 0,...,N_y; k = 0,...,N_z\}$ [S1, unofficial].
*   **Cell Definition:** Cell $(i,j,k)$ is defined by the diagonal from $(i \cdot 4 \cdot x, j \cdot 4 \cdot y, k \cdot 4 \cdot z)$ to $((i+1) \cdot 4 \cdot x, (j+1) \cdot 4 \cdot y, (k+1) \cdot 4 \cdot z)$ [S1, unofficial].
*   **Normal:** $\nabla f = (\frac{\partial f}{\partial x}, \frac{\partial f}{\partial y}, \frac{\partial f}{\partial z})$ [S1, unofficial].
*   **Vertex Buffer Location:** $vertex\_buffer[I_{i,j,k} + x] = vertex\_data$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The pipeline is dominated by parallel operations (scan, classification, mesh generation) which scale with the number of cells. The switch from block-based to cell-based processing accelerates mesh generation by only processing relevant cells [S1, unofficial].
*   **Memory Complexity:** The method doubles memory effort due to the Case and Index tables, which have dimensions $(N_x - 1) \times (N_y - 1) \times (N_z - 1)$ [S1, unofficial]. However, it only allocates memory for relevant parts of the volume if combined with block selection [S1, unofficial].
*   **Performance:** The QEM-based vertex relocation is less computationally complex than common QEF approaches using pseudoinverse, avoiding performance penalties from limited register counts on parallel hardware [S1, unofficial]. This results in lower quality than full QEF but is sufficient for preserving terrain volume [S1, unofficial].
*   **Strengths:** Generates manifold surfaces with full connectivity (1-ring neighbors) in parallel, suitable for interactive applications [S1, unofficial].
*   **Limitations:** The QEM approach yields lower quality than full QEF minimization [S1, unofficial]. The memory overhead for lookup tables is significant [S1, unofficial].

## Background
The method is based on Dual Marching Cubes by Nielson [Nie04] and extends it for parallel processing [S1, unofficial]. It was developed to address the lack of connectivity information in parallel surface extraction algorithms, which typically produce unconnected primitives [S1, unofficial]. The approach uses static and dynamic lookup tables and parallel reduction algorithms to generate a quadrilateral surface mesh with full connectivity information [S1, unofficial]. It is used in interactive modeling and visualization of complex terrains [S1, unofficial].
