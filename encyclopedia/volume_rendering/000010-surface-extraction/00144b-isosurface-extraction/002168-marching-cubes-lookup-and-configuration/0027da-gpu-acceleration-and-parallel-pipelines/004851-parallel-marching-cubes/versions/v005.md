# Parallel Marching Cubes

Also called: Marching Cubes with Slice Strategy, PBIG, Parallel Isosurface Generator, Piecewise Marching Cubes

## Overview
Parallel Marching Cubes is a parallel implementation of the Marching Cubes algorithm designed to compute isosurfaces of huge datasets that cannot fit entirely into a single machine's memory [S1, unofficial]. It solves the memory bottleneck of traditional sequential Marching Cubes by using a piecewise slice strategy along the k-direction, requiring only that at least two slices fit into physical memory [S1, unofficial]. Unlike siblings that assume the entire volume fits in RAM, this method distributes the workload across multiple processes or threads, enabling the processing of datasets with millions of grid values on multi-processor architectures [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A structured grid (regular or irregular) defined by a PLOT3D grid file (`xyz`) and a PLOT3D solution file (`Q`) containing scalar fields [S1, unofficial].
*   **Parameters:**
    *   `grid_filename`: Path to the PLOT3D grid file [S1, unofficial].
    *   `solution_filename`: Path to the PLOT3D solution file [S1, unofficial].
    *   `output_filename`: Path for the Bop output file [S1, unofficial].
    *   `scalar_index`: Integer index into the Q-file defining the scalar for the isosurface [S1, unofficial].
    *   `map_scalar_index`: Integer index into the Q-file for the scalar mapped onto the surface (e.g., for color) [S1, unofficial].
    *   `isosurface_value`: Floating-point threshold $S$ [S1, unofficial].
    *   `kstep`: Integer number of planes to step in the k-direction (slice thickness/stride). Typical value: 2 or 3 [S1, unofficial].
    *   `num_procs`: Integer number of parallel processes/threads to spawn [S1, unofficial].
*   **Output:** A Bop (Bag-O-Polygons) file containing three-sided polygons defining the isosurface and a secondary scalar mapped to each vertex [S1, unofficial].

**Data Structures**
The method relies on the precomputed data structures defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md):
1.  **Edge Intersection Table (`edgeTable`)**: 256 entries, 12-bit bitmask per entry [S1, unofficial].
2.  **Triangle Connection Table (`triangleTable`)**: $256 \times 16$ array, terminated by `-1` [S1, unofficial].

**Partitioning Structure**
The parent process calls a partitioning routine to divide the workload [S1, unofficial]. This routine creates a C structure containing information for each child process to determine which part of the grid it will read and process [S1, unofficial]. The structure includes:
*   Start and end indices for the k-dimension slice assigned to the child [S1, unofficial].
*   Full dimensions of the grid ($N_i, N_j, N_k$) to allow local coordinate calculation [S1, unofficial].
*   File paths and scalar indices required to read the assigned slice [S1, unofficial].

**Algorithm Steps**
1.  **Initialization:** The parent process opens the grid and solution files to read header information, specifically the number of grids (expected to be one) and the dimensions in $i, j, k$ directions [S1, unofficial].
2.  **Partitioning:** The 3D volume is sliced along the k-direction [S1, unofficial]. The parent creates a partitioning structure for each child based on `num_procs` [S1, unofficial].
3.  **Process Creation:** The parent creates `num_procs` child processes [S1, unofficial]. The mechanism depends on the platform:
    *   `fork` on SGI and Sun workstations [S1, unofficial].
    *   `sproc` on SGI workstations (share group process, shared virtual address space) [S1, unofficial].
    *   `pthreads` on KSR1 machines [S1, unofficial].
4.  **Slice Processing (Child Process):**
    *   Each child reads its assigned slice of the grid and solution data into local memory [S1, unofficial].
    *   The child iterates through every voxel in its assigned slice [S1, unofficial].
    *   For each voxel, the child calculates the 8-bit case index $C$ based on the scalar values $V$ at the 8 vertices relative to `isosurface_value` [S1, unofficial].
    *   The child looks up the topology in `triangleTable` using $C$ [S1, unofficial].
    *   For each triangle defined by the lookup, the child calculates the exact intersection points on the cube edges using linear interpolation [S1, unofficial].
    *   The child constructs `boply` structures for each triangle [S1, unofficial].
5.  **Serialization and Output:**
    *   Child processes write their generated polygon data to the output Bop file [S1, unofficial].
    *   To prevent collisions from simultaneous writes, semaphores are employed to enforce mutual exclusion, allowing only one child to write or network polygons at a time [S1, unofficial].
    *   Children with smaller or no output complete execution before those with larger output requirements [S1, unofficial].
6.  **Termination:** The parent waits for all children to finish and closes the output file [S1, unofficial].

```python
import sys
import threading

# [G] Standard Marching Cubes Lookup Tables (256 entries)
EDGE_TABLE = [0] * 256
TRIANGLE_TABLE = [[-1] * 16 for _ in range(256)]

def parse_p3d_headers(grid_path, sol_path):

    return 100, 100, 100  # Placeholder dimensions for structure validity

def read_slice(grid_path, sol_path, k_start, k_end, Ni, Nj, Nk, scalar_idx, map_scalar_idx):
    # [G] Reads vertex coordinates and two scalar fields for k in [k_start, k_end].
    # Returns coords: list of (x,y,z)
    # Returns scalars: list of float (isosurface field)
    # Returns map_scalars: list of float (mapping field)
    return [], [], []  # Placeholder for structure validity

def linear_interpolate(val_a, val_b, isovalue, pos_a, pos_b):
    t = (isovalue - val_a) / (val_b - val_a) if abs(val_b - val_a) > 1e-9 else 0.5
    return (
        pos_a[0] + t * (pos_b[0] - pos_a[0]),
        pos_a[1] + t * (pos_b[1] - pos_a[1]),
        pos_a[2] + t * (pos_b[2] - pos_a[2])
    )

def interpolate_scalar(val_a, val_b, isovalue):
    t = (isovalue - val_a) / (val_b - val_a) if abs(val_b - val_a) > 1e-9 else 0.5
    return val_a + t * (val_b - val_a)

def process_slice(partition, semaphore):
    coords, scalars, map_scalars = read_slice(
        partition.grid_file, partition.sol_file,
        partition.k_start, partition.k_end,
        partition.Ni, partition.Nj, partition.Nk,
        partition.scalar_idx, partition.map_scalar_idx
    )

    with open(partition.output_file, 'ab') as f:
        for k in range(partition.k_start, partition.k_end - 1):
            for j in range(partition.Nj - 1):
                for i in range(partition.Ni - 1):
                    # Standard vertex ordering for voxel (i,j,k)
                    v_idx = [
                        (i, j, k), (i+1, j, k), (i+1, j+1, k), (i, j+1, k),
                        (i, j, k+1), (i+1, j, k+1), (i+1, j+1, k+1), (i, j+1, k+1)
                    ]
                    # Map (i,j,k) to linear index in loaded arrays [G]
                    def linear_idx(ix, iy, iz):
                        return ix + iy * partition.Ni + iz * partition.Ni * partition.Nj
                    v_lin = [linear_idx(ix, iy, iz) for ix, iy, iz in v_idx]

                    vals = [scalars[idx] for idx in v_lin]
                    map_vals = [map_scalars[idx] for idx in v_lin]
                    pts = [coords[idx] for idx in v_lin]

                    # Case index calculation [S1, unofficial]
                    case_idx = 0
                    for bit in range(8):
                        if vals[bit] >= partition.isovalue:
                            case_idx |= (1 << bit)

                    triangles = TRIANGLE_TABLE[case_idx]
                    tri_ptr = 0
                    while tri_ptr < 15 and triangles[tri_ptr] != -1:
                        e1, e2, e3 = triangles[tri_ptr], triangles[tri_ptr+1], triangles[tri_ptr+2]
                        tri_ptr += 3

                        # Edge to vertex mapping [S1, unofficial]
                        edge_map = [
                            (0, 1), (1, 2), (2, 3), (3, 0),
                            (4, 5), (5, 6), (6, 7), (7, 4),
                            (0, 4), (1, 5), (2, 6), (3, 7)
                        ]
                        p1, p2 = edge_map[e1]
                        p3, p4 = edge_map[e2]
                        p5, p6 = edge_map[e3]

                        pt1 = linear_interpolate(vals[p1], vals[p2], partition.isovalue, pts[p1], pts[p2])
                        pt2 = linear_interpolate(vals[p3], vals[p4], partition.isovalue, pts[p3], pts[p4])
                        pt3 = linear_interpolate(vals[p5], vals[p6], partition.isovalue, pts[p5], pts[p6])

                        map1 = interpolate_scalar(map_vals[p1], map_vals[p2], partition.isovalue)
                        map2 = interpolate_scalar(map_vals[p3], map_vals[p4], partition.isovalue)
                        map3 = interpolate_scalar(map_vals[p5], map_vals[p6], partition.isovalue)

                        # Bop format: integer num_vertices, then x,y,z,map per vertex [S1, unofficial]
                        poly_data = struct.pack('i', 3)
                        for pt, m in zip([pt1, pt2, pt3], [map1, map2, map3]):
                            poly_data += struct.pack('ffff', pt[0], pt[1], pt[2], m)

                        semaphore.acquire()
                        try:
                            f.write(poly_data)
                        finally:
                            semaphore.release()

def main():
    grid_file = sys.argv[1]
    sol_file = sys.argv[2]
    output_file = sys.argv[3]
    scalar_idx = int(sys.argv[4])
    map_scalar_idx = int(sys.argv[5])
    isovalue = float(sys.argv[6])
    kstep = int(sys.argv[7])
    num_procs = int(sys.argv[8])

    Ni, Nj, Nk = parse_p3d_headers(grid_file, sol_file)

    k_slices_per_proc = Nk // num_procs
    remainder = Nk % num_procs
    partitions = []
    k_start = 0
    for p in range(num_procs):
        count = k_slices_per_proc + (1 if p < remainder else 0)
        k_end = k_start + count
        partitions.append(type('Partition', (), {
            'k_start': k_start, 'k_end': k_end,
            'Ni': Ni, 'Nj': Nj, 'Nk': Nk,
            'grid_file': grid_file, 'sol_file': sol_file,
            'scalar_idx': scalar_idx, 'map_scalar_idx': map_scalar_idx,
            'isovalue': isovalue, 'output_file': output_file
        })())
        k_start = k_end

    semaphore = threading.Semaphore(1)
    threads = []
    for part in partitions:
        t = threading.Thread(target=process_slice, args=(part, semaphore))
        threads.append(t)
        t.start()
    for t in threads:
        t.join()

if __name__ == '__main__':
    main()
```

**Edge Cases and Pitfalls**
*   **Grid Orientation:** The grid must be oriented such that it can be sliced in the k-direction. If the grid orientation does not accommodate this slicing strategy, the method may fail or require preprocessing [S1, unofficial].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous. The standard LUT uses a fixed triangulation, which can cause cracks or holes if adjacent voxels resolve the ambiguity differently [G].
*   **Output Collisions:** Simultaneous writes by multiple child processes to the Bop format output function cause collisions. This is handled by semaphores that enforce mutual exclusion [S1, unofficial].
*   **Memory Constraints:** The method requires that at least two slices fit into physical memory [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N/P)$ where $N$ is the number of voxels and $P$ is the number of processes [S1, unofficial].
*   **Memory Complexity:** $O(S)$ where $S$ is the size of a single slice, allowing processing of datasets larger than physical RAM [S1, unofficial].
*   **Measured Performance:** On a dataset of ~2.2M grid values and ~11M scalar values, generating ~60,000 polygons, wall-clock time was reduced from ~20 minutes (sequential) to ~90 seconds (parallel) on multi-processor machines (SGI Challenge, KSR1) [S1, unofficial].
*   **Strengths:**
    *   Handles datasets too large for main memory [S1, unofficial].
    *   Scalable across multiple processors (fork, sproc, pthreads) [S1, unofficial].
    *   Platform-independent (UNIX-compatible) [S1, unofficial].
*   **Limitations:**
    *   Requires specific grid orientation (k-slicing) [S1, unofficial].
    *   I/O bound due to frequent file writes and semaphore contention [S1, unofficial].
*   **When to Use:** When processing huge volumetric datasets (millions/billions of points) on multi-processor systems where the entire volume cannot fit in RAM [S1, unofficial].
*   **When Not to Use:** When the entire volume fits in RAM and a simpler, faster sequential method is preferred, or when the grid cannot be sliced in the k-direction [S1, unofficial].

## Background
Parallel Marching Cubes, also known as the Parallel Isosurface Generator (PBIG), was developed by researchers at the Supercomputer Research Institute and Florida State University [S1, unofficial]. It was designed to address the limitations of commercial and public domain visualization packages that assumed the entire volume fits in memory [S1, unofficial]. The method was tested on SUN4, SGI, and KSR1 architectures and applied to computational data from CTH and HULL codes, as well as medical resonance data [S1, unofficial]. The implementation utilizes the Bop (Bag-O-Polygons) format and Bop_View for visualization [S1, unofficial].
