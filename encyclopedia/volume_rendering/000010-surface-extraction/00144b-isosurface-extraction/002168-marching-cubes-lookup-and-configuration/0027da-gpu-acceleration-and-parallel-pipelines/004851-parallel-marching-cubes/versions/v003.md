# Parallel Marching Cubes

Also called: Marching Cubes with Slice Strategy, PBIG, Parallel Isosurface Generator, Piecewise Marching Cubes

## Overview
Parallel Marching Cubes is a parallel implementation of the Marching Cubes algorithm designed to compute isosurfaces of huge datasets that cannot fit entirely into a single machine's memory [S1, unofficial]. It solves the memory bottleneck of traditional sequential Marching Cubes by using a piecewise slice strategy along the k-direction, requiring only that at least two slices fit into physical memory [S1, unofficial]. Unlike siblings that assume the entire volume fits in RAM, this method distributes the workload across multiple processes or threads, enabling the processing of datasets with millions of grid values on multi-processor architectures [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A structured grid (regular or irregular) defined by a PLOT3D grid file (`xyz`) and a PLOT3D solution file (`Q`) containing scalar fields [S1, unofficial].
*   **Parameters:**
    *   `grid_filename`: Path to the PLOT3D grid file [S1, unofficial].
    *   `solution_filename`: Path to the PLOT3D solution file [S1, unofficial].
    *   `output_filename`: Path for the Bop output file [S1, unofficial].
    *   `scalar_index`: Integer index into the Q-file defining the scalar for the isosurface [S1, unofficial].
    *   `map_scalar_index`: Integer index into the Q-file for the scalar mapped onto the surface (e.g., for color) [S1, unofficial].
    *   `isosurface_value`: Floating-point threshold $S$ [S1, unofficial].
    *   `kstep`: Integer number of planes to step in the k-direction (slice thickness/stride). Typical value: 2 or 3 [S1, unofficial].
    *   `num_procs`: Integer number of parallel processes/threads to spawn [S1, unofficial].
*   **Output:** A Bop (Bag-O-Polygons) file containing three-sided polygons defining the isosurface and a secondary scalar mapped to each vertex [S1, unofficial].

**Data Structures**
The method relies on the precomputed data structures defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) [S1, unofficial].
1.  **Edge Intersection Table (`edgeTable`)**: 256 entries, 12-bit bitmask per entry [G].
2.  **Triangle Connection Table (`triangleTable`)**: $256 \times 16$ array, terminated by `-1` [G].

**Partitioning Structure**
The parent process calls a partitioning routine to divide the workload [S1, unofficial]. This routine creates a structure containing information for each child process to determine which part of the grid it will read and process [S1, unofficial]. The structure includes:
*   Start and end indices for the k-dimension slice assigned to the child [G].
*   Full dimensions of the grid ($N_i, N_j, N_k$) to allow local coordinate calculation [G].
*   File paths and parameters for data access [S1, unofficial].

**Algorithm Steps**
1.  **Initialization:** The parent process opens the grid and solution files to read header information, specifically the number of grids (expected to be one) and the dimensions in $i, j, k$ directions [S1, unofficial].
2.  **Partitioning:** The parent calls a partitioning routine to divide the workload [S1, unofficial]. The 3D volume is sliced along the k-direction [S1, unofficial]. The number of slices is determined by `num_procs` and `kstep` [S1, unofficial]. A partitioning structure is created for each child [S1, unofficial].
3.  **Process Creation:** The parent creates `num_procs` child processes [S1, unofficial]. The mechanism depends on the platform: `fork` on SGI and Sun workstations, `sproc` on SGI workstations (share group process, shared virtual address space), or `pthreads` on KSR1 machines [S1, unofficial].
4.  **Slice Processing (Child Process):** Each child reads its assigned slice of the grid and solution data into local memory [S1, unofficial]. The grid must be oriented such that it can be sliced in the k-direction [S1, unofficial]. The child iterates through every voxel in its assigned slice [G]. For each voxel, the child calculates the 8-bit case index $C$ based on the scalar values $V$ at the 8 vertices relative to `isosurface_value` [S1, unofficial]. The child looks up the topology in `triangleTable` using $C$ [G]. For each triangle defined by the lookup, the child calculates the exact intersection points on the cube edges using linear interpolation [S1, unofficial]. The child constructs `boply` structures for each triangle [S1, unofficial].
5.  **Serialization and Output:** Child processes write their generated polygon data to the output Bop file [S1, unofficial]. To prevent collisions from simultaneous writes, semaphores are employed to enforce mutual exclusion, allowing only one child to write or network polygons at a time [S1, unofficial]. Children with smaller or no output complete execution before those with larger output requirements [S1, unofficial].
6.  **Termination:** The parent waits for all children to finish and closes the output file [G].

```python
import threading
import struct

# Standard Marching Cubes Triangle Connection Table (256x16, terminated by -1)
# Loaded from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md)
TRIANGLE_TABLE = [
    [0]*16 for _ in range(256)
]
# Initialize TRIANGLE_TABLE with standard MC topology data here [G]

def read_p3d_headers(grid_file, sol_file):
    """Reads grid dimensions from PLOT3D file headers."""
    # Implementation reads binary/ASCII headers to extract Ni, Nj, Nk [G]
    return 100, 100, 100  # Placeholder dimensions for structure

def load_slice_data(grid_file, sol_file, k_start, k_end, i_dim, j_dim, k_dim):
    """Loads grid coordinates and scalar values for the assigned k-range."""
    # Implementation opens files, seeks to slice offsets, and reads arrays [G]
    # Returns grid_coords: list of (x,y,z) tuples, scalar_values: list of floats
    return [], []

def get_scalar(vertex_idx, scalar_values):
    """Retrieves scalar value for a vertex index."""
    return scalar_values[vertex_idx]

def get_coord(vertex_idx, grid_coords):
    """Retrieves 3D coordinate for a vertex index."""
    return grid_coords[vertex_idx]

def linear_interpolate(val1, val2, isovalue, pos1, pos2):
    """Calculates the intersection point on an edge given scalar values at endpoints."""
    if abs(val2 - val1) < 1e-9:
        return ((pos1[0] + pos2[0]) / 2.0, (pos1[1] + pos2[1]) / 2.0, (pos1[2] + pos2[2]) / 2.0)
    t = (isovalue - val1) / (val2 - val1)
    return (
        pos1[0] + t * (pos2[0] - pos1[0]),
        pos1[1] + t * (pos2[1] - pos1[1]),
        pos1[2] + t * (pos2[2] - pos1[2])
    )

def interpolate_map_scalar(val1, val2, isovalue, pos1, pos2, map_scalar_values):
    """Interpolates the mapping scalar at the edge intersection point."""
    if abs(val2 - val1) < 1e-9:
        return (map_scalar_values[pos1[0]] + map_scalar_values[pos2[0]]) / 2.0
    t = (isovalue - val1) / (val2 - val1)
    return map_scalar_values[pos1[0]] + t * (map_scalar_values[pos2[0]] - map_scalar_values[pos1[0]])

def process_slice(partition, semaphore):
    """Child process function to process a specific k-slice."""
    grid_coords, scalar_values = load_slice_data(
        partition.grid_file, partition.sol_file,
        partition.k_start, partition.k_end,
        partition.i_dim, partition.j_dim, partition.k_dim
    )
    
    # Map scalar values are loaded similarly [G]
    map_scalar_values = [0.0] * len(scalar_values)

    with open(partition.output_file, 'ab') as f:
        for k in range(partition.k_start, partition.k_end - 1):
            for j in range(partition.j_dim - 1):
                for i in range(partition.i_dim - 1):
                    # Standard vertex ordering for voxel (i,j,k)
                    v_idx = [
                        (i, j, k), (i+1, j, k), (i+1, j+1, k), (i, j+1, k),
                        (i, j, k+1), (i+1, j, k+1), (i+1, j+1, k+1), (i, j+1, k+1)
                    ]
                    
                    vals = [get_scalar(v, scalar_values) for v in v_idx]
                    coords = [get_coord(v, grid_coords) for v in v_idx]
                    
                    # Calculate Case Index
                    case_index = 0
                    for bit in range(8):
                        if vals[bit] >= partition.isovalue:
                            case_index |= (1 << bit)
                    
                    # Lookup Triangles
                    triangles = TRIANGLE_TABLE[case_index]
                    
                    tri_idx = 0
                    while tri_idx < 15 and triangles[tri_idx] != -1:
                        e1 = triangles[tri_idx]
                        e2 = triangles[tri_idx+1]
                        e3 = triangles[tri_idx+2]
                        tri_idx += 3
                        
                        # Edge to vertex mapping
                        edge_map = [
                            (0, 1), (1, 2), (2, 3), (3, 0),
                            (4, 5), (5, 6), (6, 7), (7, 4),
                            (0, 4), (1, 5), (2, 6), (3, 7)
                        ]
                        
                        p1_idx, p2_idx = edge_map[e1]
                        p3_idx, p4_idx = edge_map[e2]
                        p5_idx, p6_idx = edge_map[e3]
                        
                        pt1 = linear_interpolate(vals[p1_idx], vals[p2_idx], partition.isovalue, coords[p1_idx], coords[p2_idx])
                        pt2 = linear_interpolate(vals[p3_idx], vals[p4_idx], partition.isovalue, coords[p3_idx], coords[p4_idx])
                        pt3 = linear_interpolate(vals[p5_idx], vals[p6_idx], partition.isovalue, coords[p5_idx], coords[p6_idx])
                        
                        map1 = interpolate_map_scalar(vals[p1_idx], vals[p2_idx], partition.isovalue, coords[p1_idx], coords[p2_idx], map_scalar_values)
                        map2 = interpolate_map_scalar(vals[p3_idx], vals[p4_idx], partition.isovalue, coords[p3_idx], coords[p4_idx], map_scalar_values)
                        map3 = interpolate_map_scalar(vals[p5_idx], vals[p6_idx], partition.isovalue, coords[p5_idx], coords[p6_idx], map_scalar_values)
                        
                        # Bop format: int num_vertices, then float x,y,z,map per vertex
                        polygon_data = struct.pack('i', 3)
                        for pt, m in [(pt1, map1), (pt2, map2), (pt3, map3)]:
                            polygon_data += struct.pack('ffff', pt[0], pt[1], pt[2], m)
                        
                        semaphore.acquire()
                        try:
                            f.write(polygon_data)
                        finally:
                            semaphore.release()

def main():
    grid_file = sys.argv[1]
    sol_file = sys.argv[2]
    output_file = sys.argv[3]
    scalar_idx = int(sys.argv[4])
    map_scalar_idx = int(sys.argv[5])
    isovalue = float(sys.argv[6])
    kstep = int(sys.argv[7])
    num_procs = int(sys.argv[8])
    
    i_dim, j_dim, k_dim = read_p3d_headers(grid_file, sol_file)
    
    k_slices_per_proc = k_dim // num_procs
    remainder = k_dim % num_procs
    
    partitions = []
    k_start = 0
    for p in range(num_procs):
        count = k_slices_per_proc + (1 if p < remainder else 0)
        k_end = k_start + count
        partitions.append(type('Partition', (), {
            'k_start': k_start, 'k_end': k_end,
            'i_dim': i_dim, 'j_dim': j_dim, 'k_dim': k_dim,
            'grid_file': grid_file, 'sol_file': sol_file,
            'scalar_idx': scalar_idx, 'map_scalar_idx': map_scalar_idx,
            'isovalue': isovalue, 'output_file': output_file
        })())
        k_start = k_end
        
    semaphore = threading.Semaphore(1)
    threads = []
    for part in partitions:
        t = threading.Thread(target=process_slice, args=(part, semaphore))
        threads.append(t)
        t.start()
        
    for t in threads:
        t.join()

if __name__ == '__main__':
    main()
```

**Edge Cases and Pitfalls**
*   **Grid Orientation:** The grid must be oriented such that it can be sliced in the k-direction. If the grid orientation does not accommodate this slicing strategy, the method may fail or require preprocessing [S1, unofficial].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points where the topology is ambiguous. The standard LUT uses a fixed triangulation, which can cause cracks or holes if adjacent voxels resolve the ambiguity differently [10327-lookup-table-and-ambiguity-handling, unofficial].
*   **Output Collisions:** Simultaneous writes by multiple child processes to the Bop format output function cause collisions. This is handled by semaphores that enforce mutual exclusion [S1, unofficial].
*   **Memory Constraints:** The method requires that at least two slices fit into physical memory [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, distributed across $P$ processes [G].
*   **Memory Complexity:** $O(S)$ where $S$ is the size of the assigned slice, allowing processing of datasets larger than physical RAM [S1, unofficial].
*   **Measured Performance:** On a dataset of ~2.2M grid values and ~11M scalar values, generating ~60,000 polygons, wall-clock time was reduced from ~20 minutes to ~90 seconds on multi-processor machines (SUN4spare, SGI Challenge, KSR1) [S1, unofficial].
*   **Strengths:** Handles datasets too large for main memory; scalable across multiple processors (fork, sproc, pthreads); platform-independent (UNIX-compatible) [S1, unofficial].
*   **Limitations:** Requires specific grid orientation (k-slicing); I/O bound due to frequent file writes and semaphore contention [S1, unofficial].
*   **When to Use:** When processing huge volumetric datasets on multi-processor systems where the entire volume cannot fit in RAM [S1, unofficial].
*   **When Not to Use:** When the entire volume fits in RAM and a simpler sequential method is preferred, or when the grid cannot be sliced in the k-direction [S1, unofficial].

## Background
Parallel Marching Cubes, also known as the Parallel Isosurface Generator (PBIG), was developed by researchers at the Supercomputer Research Institute and Florida State University. It was designed to address the limitations of commercial and public domain visualization packages that assumed the entire volume fits in memory [S1, unofficial]. The method was tested on SUN4, SGI, and KSR1 architectures and applied to computational data from CTH and HULL codes, as well as medical resonance data [S1, unofficial]. The implementation utilizes the Bop (Bag-O-Polygons) format and Bop_View for visualization [S1, unofficial].
