# GPU Marching Cubes with Atomic Counter Emission

Also called: atomic-counter MC, indirect-draw MC, r=mesh

## Overview
This method performs real-time isosurface meshing by dispatching one compute thread per grid cell to classify density, reserve vertex slots via atomic addition on indirect draw arguments, and write vertices directly into a capped pool, thereby avoiding prefix sums [S1, unofficial]. It is distinguished from sibling methods like the Histogram Pyramid approach [2317-gpu-marching-cubes-with-histogram-pyramid.md] and Capacity-Safe Pipelines [4596-capacity-safe-marching-cubes-pipeline.md] by its use of atomic counters on the draw indirect buffer itself to manage output allocation, allowing for a simpler, single-pass emission structure without intermediate histogram reduction steps.

## How it works
**Inputs:**
*   A tent-blurred density grid (scalar field) [S1, unofficial].
*   An isosurface threshold $\tau$ (controlled by the `?iso=` parameter) [S1, unofficial].
*   The Marching Cubes Lookup and Configuration data structures, specifically the `triangleTable` and `edgeTable` [S4, S8, S12, unofficial].

**Outputs:**
*   A mesh rendered via `drawIndirect`, consisting of vertices and normals stored in a pool buffer [S1, unofficial].
*   An overflow flag indicating if the vertex count exceeded the pool capacity [S1, unofficial].

**Data Structures:**
1.  **Indirect Draw Args Buffer:** A buffer containing standard `drawIndirect` arguments (vertex count, instance count, first vertex, first instance). The vertex count is updated atomically. An overflow flag is stored in word 4 (offset 16 bytes from the start, assuming 4-byte integers), distinct from the standard `firstInstance` field [S1, unofficial].
2.  **Vertex Pool:** A buffer with a fixed capacity of 1.5 million vertices (48 MB). Each vertex entry stores a 3D position and a 3D gradient normal [S1, unofficial].
3.  **Triangle Table:** Generated at load time rather than hardcoded. It maps the 256 case indices to sequences of edge indices forming triangles [S1, unofficial].

**Algorithm Steps:**

1.  **Dispatch:** Launch a compute shader with one thread group per grid cell (or one thread per cell, depending on implementation granularity), ensuring independent processing of each voxel [S1, S2, unofficial].
2.  **Case Classification:** For the current cell, sample the density values $V$ at its 8 vertices. Compare each $V$ against the isosurface threshold $\tau$ to determine the 8-bit configuration index $C$.
    *   *Pitfall (Wall Capping):* Lattice indices at 0 are treated as having outside density (0) to cap the isosurface on all six walls. Samples outside the valid lattice range are treated as density 0 [S1, unofficial].
3.  **Edge Intersection Lookup:** Use the configuration index $C$ to look up the `triangleTable` to identify which of the 12 edges are intersected by the isosurface [S4, S8, S12, unofficial].
4.  **Slot Reservation:** Perform an atomic addition (`atomicAdd`) on the vertex count field within the Indirect Draw Args buffer. The return value of this atomic operation provides the starting index in the Vertex Pool for this cell's vertices [S1, unofficial].
5.  **Vertex Emission:** For each cut edge identified in step 3:
    *   Compute the intersection point $P$ along the edge using trilinear interpolation of the density values at the edge's endpoints.
    *   Compute the gradient normal $N$ at $P$ using the density gradient.
    *   Write the position $P$ and normal $N$ into the Vertex Pool at the reserved index.
    *   *Optimization:* Cache interpolated position and normal per unique cut edge to avoid recomputation per triangle corner [S1, unofficial].
6.  **Finalization:** Run a separate finalize kernel with one thread. This thread reads the current vertex count from the Indirect Draw Args buffer.
    *   If the count exceeds the pool cap (1.5 million), set the overflow flag in word 4 of the Indirect Draw Args buffer.
    *   Clamp the vertex count in the Indirect Draw Args buffer to the pool cap [S1, unofficial].
7.  **Rendering:** Execute `drawIndirect` using the Indirect Draw Args buffer. This pulls vertices from the Vertex Pool. The mesh is depth-tested against the raytraced scene background in the same pass [S1, unofficial].

**Pseudocode:**

```python
# Compute Shader: One thread per cell
fn mc_compute(cell_idx: uint, grid_size: uint3, iso: float, 
              indirect_args: buffer<uint>, vertex_pool: buffer<float3>, 
              vertex_normals: buffer<float3>, triangle_table: buffer<uint>) {
    
    // 1. Sample 8 corners
    // Determine grid coordinates from cell_idx
    let x = cell_idx % grid_size.x
    let y = (cell_idx / grid_size.x) % grid_size.y
    let z = (cell_idx / (grid_size.x * grid_size.y)) % grid_size.z
    
    // Sample densities, treating out-of-bounds as 0
    var densities[8]
    for i in 0..8:
        let corner = get_corner_coords(x, y, z, i)
        densities[i] = (is_valid(corner)) ? sample_density(corner) : 0.0
        
    // 2. Compute Case Index C
    var C: uint = 0
    for i in 0..8:
        if densities[i] >= iso:
            C |= (1 << i)
            
    // 3. Lookup Triangle Table
    // triangle_table maps C to a list of edge indices
    // Assume table returns an array of edge indices and a count
    let edges = lookup_triangle_table(C)
    let num_edges = edges.length
    
    // 4. Reserve Slots
    // atomicAdd returns the starting index for this cell's vertices
    let start_idx = atomicAdd(indirect_args[0], num_edges) // args[0] is vertex count
    
    // 5. Emit Vertices
    for i in 0..num_edges:
        let edge_idx = edges[i]
        
        // Compute intersection and normal for this edge
        let pos = interpolate_edge_intersection(edge_idx, densities, grid_size, cell_idx, iso)
        let normal = compute_gradient_normal(edge_idx, densities, grid_size, cell_idx)
        
        // Write to pool
        vertex_pool[start_idx + i] = pos
        vertex_normals[start_idx + i] = normal
        
    // Note: Indirect args[0] is automatically updated by atomicAdd
}

// Finalize Kernel: One thread
fn mc_finalize(indirect_args: buffer<uint>, pool_cap: uint) {
    let current_count = indirect_args[0]
    
    if current_count > pool_cap:
        indirect_args[4] = 1 // Set overflow flag in word 4
        indirect_args[0] = pool_cap // Clamp vertex count
    else:
        indirect_args[4] = 0 // Clear overflow flag
}
```

**Triangle Table Generation:**
Unlike classic implementations that use a hardcoded 256x16 constant table, this method generates the table at load time. The generation process involves:
1.  Computing marching squares faces for each cube face.
2.  Connecting these faces into closed loops.
3.  Triangulating the loops using fan triangulation.
4.  Applying a rotation-invariant ambiguity rule to ensure crack-free surfaces.
The generated table is validated against all 256 cases to ensure it matches the cut-edge set of the classic table [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of grid cells, as each cell is processed by one thread. The finalization is $O(1)$.
*   **Memory Complexity:** Dominated by the Vertex Pool size. The sources specify a fixed pool of 1.5 million vertices (48 MB) [S1, unofficial]. The Indirect Draw Args buffer is minimal.
*   **Performance:** Benchmarked at 4.12 ms/frame on M-series hardware for a $128^3$ resolution grid and $384^2$ screen size [S1, unofficial].
*   **Strengths:** Avoids the overhead of prefix sums or histogram pyramids for output allocation. Simple implementation with direct atomic counter usage.
*   **Limitations:** Fixed pool size requires clamping, which may lead to overflow flags if the scene complexity exceeds the cap. WebGL2 fallback uses a different renderer (ssf) [S1, unofficial].
*   **When to use:** Real-time applications requiring efficient GPU-based isosurface extraction where prefix sum overhead is undesirable and a fixed vertex budget is acceptable.

## Background
This method was introduced in the "waterfall" WebGL2 fluid simulation project as the `r=mesh` renderer [S1, unofficial]. It was developed by nikolai3d and merged into the main branch in July 2026 [S1, unofficial]. It was designed to provide a real-time isosurface meshing solution for WebGPU, with a graceful fallback to screen-space fluids for WebGL2. The approach was inspired by the need to avoid prefix sums for output allocation, leveraging atomic counters on indirect draw arguments instead [S1, unofficial].
