# GPU Marching Cubes with Histogram Pyramid

Also called: GPU Marching Cubes with HistoPyramid, GPU Marching Cubes with HistoPyramid-style Compaction, GPU-MC, Histogram Pyramid Marching Cubes, OpenCL Marching Cubes

## Overview
GPU Marching Cubes with Histogram Pyramid is a parallel isosurface extraction method that uses a Histogram Pyramid (HP) to count and locate surface triangles without atomic operations or sorting [S1, S2, unofficial]. It builds on [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by replacing global atomic counters with a hierarchical reduction structure, enabling efficient compaction of active voxels and direct vertex placement into a Vertex Buffer Object (VBO) [S1, unofficial]. Unlike [GPU Marching Cubes (Compute Shader)](4687-gpu-marching-cubes-compute-shader.md) which often relies on atomics or sorting, this method uses the HP to determine exact output offsets for each triangle [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: Raw scalar volume data (8-bit unsigned integer), isovalue $I$, grid dimensions $(sizeX, sizeY, sizeZ)$, subsampling factors $(stepSizeX, stepSizeY, stepSizeZ)$, and voxel spacing $(dx, dy, dz)$ [S1, S2, unofficial].
*   **Output**: A Vertex Buffer Object (VBO) containing triangle vertices and normals, ready for OpenGL rendering [S1, unofficial].

**Data Structures**
1.  **Volume Grid**: Padded to a cubic power-of-two size $SIZE \times SIZE \times SIZE$ [S1, unofficial].
    *   If using 3D textures: `CL_R, CL_UNSIGNED_INT8` [S1, unofficial].
    *   If using buffers: `char` buffer of size $SIZE^3$ [S1, unofficial].
2.  **Histogram Pyramid (HP)**: A hierarchical structure storing partial sums of active voxels/triangles.
    *   **3D Texture Path**:
        *   Level 0: `CL_RGBA, CL_UNSIGNED_INT8`, size $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
        *   Level 1: `CL_R, CL_UNSIGNED_INT8`, size $SIZE/4 \times SIZE/4 \times SIZE/4$ [S1, unofficial].
        *   Levels 2–4: `CL_R, CL_UNSIGNED_INT16`, size halving each level [S1, unofficial].
        *   Level 5+: `CL_R, CL_UNSIGNED_INT32`, size halving each level until 1 [S1, unofficial].
    *   **Buffer Path** (used when 3D texture writes are unsupported, e.g., NVIDIA):
        *   Level 0: `char`, size $SIZE^3/8$ [S1, unofficial].
        *   Level 1: `char`, size $SIZE^3/64$ [S1, unofficial].
        *   Level 2: `short`, size $SIZE^3/512$ [S1, unofficial].
        *   Level 3: `short`, size $SIZE^3/4096$ [S1, unofficial].
        *   Level 4: `short`, size $SIZE^3/32768$ [S1, unofficial].
        *   Level 5+: `int`, size halving by 8 each level [S1, unofficial].
    *   **Top Level**: Contains 8 integers representing the total triangle count [S1, unofficial].
3.  **Lookup Tables**:
    *   `numVertsTable[256]`: Number of vertices for each case index [S2, unofficial].
    *   `triTable[256 \times 16]`: Triangle connection table as defined in [Marching Cubes Lookup and Configuration](10327-lookup-table-and-ambiguity-handling.md) [S2, unofficial].
4.  **Intermediate Buffers**:
    *   `voxelVerts`: `uint` array, size $numVoxels$, storing vertex count per voxel [S2, unofficial].
    *   `voxelOccupied`: `uint` array, size $numVoxels$, 1 if active, 0 otherwise [S2, unofficial].
    *   `voxelOccupiedScan`: `uint` array, size $numVoxels$, exclusive scan of `voxelOccupied` [S2, unofficial].
    *   `compactedVoxelArray`: `uint` array, size $numVoxels$, storing indices of active voxels [S2, unofficial].
    *   `cubeIndexesBuffer`: `char` buffer, size $SIZE^3$, storing 8-bit cube indices [S1, unofficial].
5.  **VBO**: Stores triangle data. Each vertex has 3 floats for position and 3 floats for normal (24 bytes total). Total size: $totalSum \times 18 \times sizeof(cl\_float)$ [S1, unofficial].

**Algorithm Steps**

1.  **Input Preparation**:
    *   Read raw volume data.
    *   Apply subsampling if $stepSize > 1$ [S1, unofficial].
    *   Determine $largestSize = \max(sizeX, sizeY, sizeZ)$ [S1, unofficial].
    *   Calculate $SIZE = 2^{\lceil \log_2(largestSize) \rceil}$ [S1, unofficial].
    *   Allocate `newVoxels` of size $SIZE^3$ initialized to 0.
    *   Copy data from original grid to `newVoxels` using index $x + y \cdot SIZE + z \cdot SIZE^2$ [S1, unofficial].

2.  **Voxel Classification**:
    *   Launch kernel `classifyVoxel` (or `classifyCubesKernel`) with one thread per voxel [S1, S2, unofficial].
    *   For voxel at `gridPos`, compute field values $V_0 \dots V_7$ at the 8 corners [S2, unofficial].
    *   Calculate case index $C$:
        $$ C = \sum_{k=0}^{7} \mathbb{I}(V_k < I) \cdot 2^k $$
        where $\mathbb{I}$ is the indicator function [S2, unofficial].
    *   Look up `numVerts = numVertsTable[C]` [S2, unofficial].
    *   Store `numVerts` in `voxelVerts[i]`.
    *   Set `voxelOccupied[i] = 1` if `numVerts > 0`, else `0` [S2, unofficial].
    *   Store $C$ in `cubeIndexesBuffer` (buffer mode) or `cubeIndexesImage` (texture mode) [S1, unofficial].

3.  **Histogram Pyramid Construction**:
    *   **Base Level**: Compute the base of the HP from `voxelOccupied` (or `cubeIndexes` counts) [S1, unofficial].
        *   Texture: Kernel `constructHPLevelKernel` reads `images[0]`, writes `images[1]`. Work group $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
        *   Buffer: Kernel `constructHPLevelCharCharKernel` reads `buffers[0]`, writes `buffers[1]` [S1, unofficial].
    *   **Intermediate Levels**: Iterate from level 1 to $\log_2(SIZE)-2$ [S1, unofficial].
        *   Texture: Kernel `constructHPLevelKernel` reads `images[i]`, writes `images[i+1]` [S1, unofficial].
        *   Buffer: Use type-specific kernels for transitions:
            *   Level 1→2: `constructHPLevelCharShortKernel` (char to short) [S1, unofficial].
            *   Level 2→3: `constructHPLevelShortShortKernel` (short to short) [S1, unofficial].
            *   Level 3→4: `constructHPLevelShortShortKernel` (short to short) [S1, unofficial].
            *   Level 4→5: `constructHPLevelShortIntKernel` (short to int) [S1, unofficial].
            *   Level 5+: `constructHPLevelKernel` (int to int) [S1, unofficial].
        *   Work group size halves each iteration [S1, unofficial].

4.  **Triangle Count Retrieval**:
    *   Read the top of the HP (8 integers) [S1, unofficial].
    *   Sum them to get `totalSum` [S1, unofficial].
    *   If `totalSum == 0`, return early (no triangles) [S2, unofficial].

5.  **Voxel Compaction**:
    *   Perform an exclusive scan on `voxelOccupied` to produce `voxelOccupiedScan` [S2, unofficial].
    *   Launch `compactVoxels` kernel. For each thread $i$, if `voxelOccupied[i]` is true, write $i$ to `compactedVoxelArray[voxelOccupiedScan[i]]` [S2, unofficial].

6.  **Triangle Compaction and Vertex Generation**:
    *   Allocate VBO of size `totalSum * 18 * sizeof(cl_float)` [S1, unofficial].
    *   Launch `extractIsosurface` kernel for each active voxel index $i$ in `compactedVoxelArray` [S2, unofficial].
    *   For each active voxel:
        *   Compute corner positions $v_0 \dots v_7$ and field values/gradients [S2, unofficial].
        *   Calculate $C$ as in Step 2 [S2, unofficial].
        *   Compute 12 edge intersection points `vertlist[0]...vertlist[11]` using linear interpolation:
            $$ t = \frac{I - f_0.w}{f_1.w - f_0.w}, \quad p = p_0 + t \cdot (p_1 - p_0) $$
            where $f_0, f_1$ are field values at edge endpoints and $p_0, p_1$ are their positions [S2, unofficial].
        *   Get `numVerts` from `numVertsTable[C]` [S2, unofficial].
        *   For each triangle vertex $j$ from $0$ to `numVerts-1`:
            *   Get edge index $edge = triTable[C \times 16 + j]$ [S2, unofficial].
            *   Calculate output index $idx = numVertsScanned[compactedVoxelArray[i]] + j$ [S2, unofficial].
            *   Write `vertlist[edge]` to `result[idx]` [S2, unofficial].

7.  **Rendering**:
    *   Bind VBO.
    *   Set vertex pointer (3 floats, stride 24, offset 0) and normal pointer (3 floats, stride 24, offset 12) [S1, unofficial].
    *   Draw triangles using `glDrawArrays(GL_TRIANGLES, 0, totalSum * 3)` [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ for classification and HP construction, where $N$ is the number of voxels. The traversal is proportional to the number of triangles [S1, unofficial].
*   **Memory Complexity**: $O(N)$ for the volume and intermediate buffers. The HP requires additional memory proportional to the volume size, with decreasing levels [S1, unofficial].
*   **Performance**: Efficient on GPUs that support 3D texture writes. On NVIDIA GPUs, the buffer-based fallback is slower due to the lack of native 3D texture write support and the need to emulate caching with morton codes [S1, unofficial].
*   **Strengths**: Avoids atomic operations and sorting, which can be bottlenecks in other GPU MC implementations [S1, unofficial].
*   **Limitations**: Requires power-of-two dimensions, leading to padding overhead for non-power-of-two volumes [S1, unofficial]. CUDA grid dimension limits (65535) require careful launch configuration for very large volumes [S2, unofficial].

## Background
The method is based on the "High-speed Marching Cubes using HistoPyramids" paper by Dyken et al. (2008) [S2, unofficial]. It was implemented as an OpenCL and OpenGL application by Erik Smistad, later integrated into the FAST framework [S1, unofficial]. The approach leverages the Histogram Pyramid data structure to perform parallel reduction and traversal, enabling efficient surface extraction on the GPU [S1, unofficial].
