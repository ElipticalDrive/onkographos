# GPU Marching Cubes with Histogram Pyramid

Also called: GPU Marching Cubes with HistoPyramid, GPU Marching Cubes with HistoPyramid-style Compaction, GPU-MC, Histogram Pyramid Marching Cubes, OpenCL Marching Cubes

## Overview
GPU Marching Cubes with Histogram Pyramid is a parallel isosurface extraction method that uses a Histogram Pyramid (HP) to count and locate surface triangles without atomic operations or sorting [S1, unofficial]. It builds on [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by replacing global atomic counters with a hierarchical reduction structure, enabling efficient compaction of active voxels and direct vertex placement into a Vertex Buffer Object (VBO) [S1, unofficial]. Unlike [GPU Marching Cubes (Compute Shader)](4687-gpu-marching-cubes-compute-shader.md) which often relies on atomics or sorting for output buffering, this method uses the HP to deterministically compute output indices [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: Raw scalar volume data (8-bit unsigned integer), isovalue threshold, grid dimensions ($sizeX, sizeY, sizeZ$), and optional subsampling factors ($stepSizeX, stepSizeY, stepSizeZ$) [S1, S2, unofficial].
*   **Output**: A Vertex Buffer Object (VBO) containing triangle vertices and normals, ready for OpenGL rendering [S1, unofficial].

**Data Structures**
1.  **Volume Grid**: Padded to a cubic grid of size $SIZE \times SIZE \times SIZE$, where $SIZE$ is the smallest power of two greater than or equal to $\max(sizeX, sizeY, sizeZ)$ [S1, unofficial]. Stored as `CL_R, CL_UNSIGNED_INT8` (or `char` buffer) [S1, unofficial].
2.  **Histogram Pyramid (HP)**: A hierarchical structure of 3D images or buffers.
    *   **3D Texture Path**:
        *   Level 0: `CL_RGBA, CL_UNSIGNED_INT8`, size $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
        *   Level 1: `CL_R, CL_UNSIGNED_INT8`, size $SIZE/4 \times SIZE/4 \times SIZE/4$ [S1, unofficial].
        *   Levels 2–4: `CL_R, CL_UNSIGNED_INT16`, size halving each level ($SIZE/8, SIZE/16, SIZE/32$) [S1, unofficial].
        *   Level 5+: `CL_R, CL_UNSIGNED_INT32`, size halving each level until 1 (or forced to 2 if 1) [S1, unofficial].
    *   **Buffer Path** (used when 3D texture writes are unsupported, e.g., NVIDIA):
        *   Level 0: `char`, size $SIZE^3/8$ [S1, unofficial].
        *   Level 1: `char`, size $SIZE^3/64$ [S1, unofficial].
        *   Level 2: `short`, size $SIZE^3/512$ [S1, unofficial].
        *   Level 3: `short`, size $SIZE^3/4096$ [S1, unofficial].
        *   Level 4: `short`, size $SIZE^3/32768$ [S1, unofficial].
        *   Level 5+: `int`, size halving by 8 each level [S1, unofficial].
    *   **Top Level**: Contains 8 integers representing the total triangle count [S1, unofficial].
3.  **Voxel Metadata**:
    *   `voxelVerts`: `uint` array, size $numVoxels$, storing the number of vertices per voxel [S2, unofficial].
    *   `voxelOccupied`: `uint` array, size $numVoxels$, binary flag (1 if active, 0 if empty) [S2, unofficial].
    *   `voxelOccupiedScan`: `uint` array, size $numVoxels$, result of exclusive scan on `voxelOccupied` [S2, unofficial].
    *   `compactedVoxelArray`: `uint` array, size $numVoxels$, storing indices of active voxels [S2, unofficial].
    *   `cubeIndexesBuffer`: `char` buffer, size $SIZE^3$, storing the 8-bit cube index for each voxel [S1, unofficial].
4.  **Lookup Tables**:
    *   `numVertsTable`: `uint[256]`, number of vertices for each case [S2, unofficial].
    *   `triTable`: `uint[256 \times 16]`, triangle configuration for each case [S2, unofficial].
5.  **VBO**: Stores triangle data. Each triangle has 3 vertices. Each vertex has 3 floats for position and 3 floats for normal (24 bytes total). Total size: $totalSum \times 18 \times sizeof(cl\_float)$ [S1, unofficial].

**Numbered Steps**

1.  **Input Preparation**:
    *   Read raw volume data.
    *   If dimensions are not equal powers of two, pad the volume to the next power of two size ($SIZE$) with zeros [S1, unofficial].
    *   If step sizes $> 1$, subsample the volume [S1, unofficial].
    *   Allocate `newVoxels` of size $SIZE^3$ initialized to 0. Copy data from original dimensions to `newVoxels` using index $x + y \cdot SIZE + z \cdot SIZE^2$ [S1, unofficial].

2.  **Voxel Classification**:
    *   Launch kernel `classifyCubesKernel` (or `classifyVoxel` in CUDA variant) with one thread per voxel ($SIZE^3$ threads) [S1, S2, unofficial].
    *   For each voxel at `gridPos`, compute field values at 8 corners ($field_0$ to $field_7$) using `computeValue` [S2, unofficial].
    *   Calculate `cubeindex` using the formula:
        $$ cubeindex = \sum_{k=0}^{7} \mathbb{I}(field_k < isoValue) \cdot 2^k $$
        where $\mathbb{I}$ is the indicator function [S2, unofficial].
    *   Look up `numVerts = numVertsTable[cubeindex]` [S2, unofficial].
    *   Store `numVerts` in `voxelVerts[i]`.
    *   Set `voxelOccupied[i] = 1` if `numVerts > 0`, else `0` [S2, unofficial].
    *   Store `cubeindex` in `cubeIndexesBuffer` (buffer mode) or `cubeIndexesImage` (texture mode) [S1, unofficial].

3.  **Histogram Pyramid Construction**:
    *   **Base Level**: Compute the base of the HP.
        *   Texture mode: Kernel `constructHPLevelKernel` reads `images[0]` (voxel counts) and writes to `images[1]`. Work group: $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
        *   Buffer mode: Kernel `constructHPLevelCharCharKernel` reads `buffers[0]` and writes to `buffers[1]`. Work group: $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
    *   **Intermediate Levels**: Iterate from level 1 to $\log_2(SIZE)-2$.
        *   For each level $i$, kernel reads `images[i]` (or `buffers[i]`) and writes to `images[i+1]` (or `buffers[i+1]`) [S1, unofficial].
        *   Work group size is `previous/2` where `previous` starts at $SIZE/2$ and halves each iteration [S1, unofficial].
        *   Buffer mode switches types: `Char->Char` (Level 0-1), `Char->Short` (Level 1-2), `Short->Short` (Level 2-4), `Short->Int` (Level 4-5) [S1, unofficial].
    *   **Top Level**: The final level contains 8 integers representing the total triangle count [S1, unofficial].

4.  **Triangle Count Retrieval**:
    *   Read the top of the HistoPyramid (8 integers) [S1, unofficial].
    *   Sum them to get `totalSum`. If `totalSum` is 0, no triangles were extracted [S1, unofficial].

5.  **VBO Allocation**:
    *   Create a new VBO with size `totalSum * 18 * sizeof(cl_float)` [S1, unofficial].

6.  **Exclusive Sum Scan and Compaction** (CUDA/Thrust variant, [S2, unofficial] notes this step explicitly; OpenCL variant may integrate this into the traversal or use a separate scan kernel):
    *   Perform an exclusive scan on `voxelOccupied` to produce `voxelOccupiedScan` [S2, unofficial].
    *   Launch `compactVoxels` kernel. For each thread `i`, if `voxelOccupied[i]` is true, write the original index `i` to `compactedVoxelArray[voxelOccupiedScan[i]]` [S2, unofficial].

7.  **Triangle Compaction and Extraction**:
    *   Call `histoPyramidTraversal(totalSum)` [S1, unofficial].
    *   Launch kernel `traverseHPKernel`.
    *   Arguments: `rawData` (or skipped in texture mode), `cubeIndexesImage`, HP levels, VBO buffer, `isolevel`, `sum` [S1, unofficial].
    *   Work group size: `sum + 64 - (sum - 64*(sum / 64))` (next multiple of 64), local size 64 [S1, unofficial].
    *   **Traversal Logic**:
        *   Traverse the HP from top to bottom to find triangle indices [S1, unofficial].
        *   For each active voxel index `i` in `compactedVoxelArray`:
            *   Compute corner positions $v_0$-$v_7$ and field values/gradients using `computeValue4` to get $field_0$-$field_7$ (`float4` containing dx, dy, dz, value) [S2, unofficial].
            *   Calculate `cubeindex` [S2, unofficial].
            *   Compute 12 edge intersection points `vertlist[0]`-`vertlist[11]` using linear interpolation:
                $$ t = \frac{isoValue - f_0.w}{f_1.w - f_0.w}, \quad p = p_0 + t \cdot (p_1 - p_0) $$
                where $f_0.w$ and $f_1.w$ are the scalar values at the edge endpoints, and $p_0, p_1$ are their positions [S2, unofficial].
            *   Determine `numVerts` from `numVertsTable` [S2, unofficial].
            *   For each triangle vertex $j$ in $0..numVerts-1$:
                *   Get edge index `edge = triTable[cubeindex * 16 + j]` [S2, unofficial].
                *   Write `vertlist[edge]` to `result[numVertsScanned[compactedVoxelArray[i]] + j]` [S2, unofficial]. Note: `numVertsScanned` likely refers to the cumulative offset derived from the HP traversal or the exclusive scan [S2, unofficial].

8.  **Rendering**:
    *   Set up OpenGL matrices (projection, modelview) [S1, unofficial].
    *   Apply translation, rotation, and scaling [S1, unofficial].
    *   Bind VBO. Set vertex pointer (3 floats, stride 24, offset 0) and normal pointer (3 floats, stride 24, offset 12) [S1, unofficial].
    *   Draw triangles using `glDrawArrays(GL_TRIANGLES, 0, totalSum*3)` [S1, unofficial].

**Parameters**
*   `isolevel`: Threshold value for surface extraction. Default 51. Normalized to [0, 1] for display by dividing by 255.0 [S1, unofficial].
*   `stepSizeX, stepSizeY, stepSizeZ`: Subsampling factors. Default 1 [S1, unofficial].
*   `SIZE`: Dimension of the cubic voxel grid, always a power of two. Passed to OpenCL kernel via `-DSIZE=<value>` [S1, unofficial].
*   `scalingFactor`: 3D vector used to scale the volume during rendering. Calculated as `spacing * 1.5f / size` [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Power of Two Requirement**: The algorithm requires volume dimensions to be powers of two. If not, the volume is padded to the next power of two of the largest dimension [S1, unofficial].
*   **NVIDIA GPU Limitation**: Due to lack of 3D texture write support on NVIDIA GPUs, a slower version using regular buffers and morton codes is used to emulate 3D caching [S1, unofficial].
*   **Grid Dimension Limit**: CUDA grid dimensions are limited to 65535 in each dimension. If `numVoxels` requires a larger grid, the launch configuration is adjusted (e.g., `grid.x = 32768`, `grid.y = grid.x / 32768`) [S2, unofficial].
*   **Image Size Constraint**: OpenGL/OpenCL images cannot be 1x1x1. If `bufferSize` becomes 1 during HP construction, it is forced to 2 [S1, unofficial].
*   **Empty Volume**: If no voxels are active (`num_activeVoxels == 0`), the function returns early with `successful = false` and `num_resultVertices = 0` [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: Classification is $O(N)$ where $N$ is the number of voxels. HP construction is $O(N)$ with a small constant factor due to hierarchical reduction. Traversal is $O(T)$ where $T$ is the number of triangles.
*   **Memory Complexity**: Requires storage for the volume, HP levels, and VBO. HP levels consume approximately $N/8 + N/64 + \dots$ memory, which is negligible compared to the volume and output mesh.
*   **Measured Performance**: The method avoids atomic operations and sorting, which can be bottlenecks in other GPU implementations [S1, unofficial]. However, the buffer-based fallback on NVIDIA GPUs is noted as slower than the texture-based approach on AMD/Intel GPUs [S1, unofficial].
*   **Strengths**: Efficient parallel reduction, no need for sorting or atomics, direct VBO population.
*   **Limitations**: Requires power-of-two dimensions, dependent on 3D texture write support for optimal performance, limited by CUDA grid dimension limits for very large volumes.

## Background
The method is based on the "High-speed Marching Cubes using HistoPyramids" paper by Dyken et al. (2008) [S2, unofficial]. It was implemented as an OpenCL/OpenGL application by Erik Smistad, later integrated into the FAST framework [S1, unofficial]. The approach leverages the Histogram Pyramid data structure to perform parallel counting and compaction, enabling efficient surface extraction on GPUs [S1, unofficial].
