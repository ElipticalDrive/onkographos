# GPU Marching Cubes with Histogram Pyramid

Also called: GPU Marching Cubes with HistoPyramid, GPU Marching Cubes with HistoPyramid-style Compaction, GPU-MC, Histogram Pyramid Marching Cubes, OpenCL Marching Cubes

## Overview
GPU Marching Cubes with Histogram Pyramid is a parallel isosurface extraction method that uses a hierarchical histogram structure (HistoPyramid) to count and locate surface triangles without atomic operations or sorting [S1, S2, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) and [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md). Unlike [GPU Marching Cubes (Compute Shader)](4687-gpu-marching-cubes-compute-shader.md) which often relies on atomics or sorting for compaction, this method uses the HistoPyramid to deterministically map voxel contributions to a compact Vertex Buffer Object (VBO) [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Raw scalar volume data (8-bit unsigned integer), isovalue, grid dimensions ($sizeX, sizeY, sizeZ$), and optional subsampling factors ($stepSizeX, stepSizeY, stepSizeZ$) [S1, S2, unofficial].
*   **Output:** A Vertex Buffer Object (VBO) containing triangle vertices and normals, ready for OpenGL rendering [S1, unofficial].

**Data Structures:**
1.  **Volume Grid:** Padded to a cubic power-of-two dimension $SIZE \times SIZE \times SIZE$ [S1, unofficial].
    *   *Texture Path:* `Image3D` with format `CL_R, CL_UNSIGNED_INT8` [S1, unofficial].
    *   *Buffer Path:* `Buffer` of `char` with size $SIZE^3$ [S1, unofficial].
2.  **Cube Indexes:** 8-bit index per voxel ($0-255$) indicating the Marching Cubes case [S1, S2, unofficial].
    *   *Texture Path:* `Image3D` with format `CL_R, CL_UNSIGNED_INT8` [S1, unofficial].
    *   *Buffer Path:* `Buffer` of `char` with size $SIZE^3$ [S1, unofficial].
3.  **Histogram Pyramid (HP):** A hierarchy of buffers/images storing partial sums of triangle counts.
    *   *Texture Path:*
        *   Level 0: `CL_RGBA, CL_UNSIGNED_INT8`, size $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
        *   Level 1: `CL_R, CL_UNSIGNED_INT8`, size $SIZE/4 \times SIZE/4 \times SIZE/4$ [S1, unofficial].
        *   Levels 2-4: `CL_R, CL_UNSIGNED_INT16`, size halving each level [S1, unofficial].
        *   Level 5+: `CL_R, CL_UNSIGNED_INT32`, size halving each level until 1 [S1, unofficial].
    *   *Buffer Path:*
        *   Level 0: `char`, size $SIZE^3/8$ [S1, unofficial].
        *   Level 1: `char`, size $SIZE^3/64$ [S1, unofficial].
        *   Level 2: `short`, size $SIZE^3/512$ [S1, unofficial].
        *   Level 3: `short`, size $SIZE^3/4096$ [S1, unofficial].
        *   Level 4: `short`, size $SIZE^3/32768$ [S1, unofficial].
        *   Level 5+: `int`, size halving by 8 each level [S1, unofficial].
    *   *Top Level:* Contains 8 integers representing the total triangle count [S1, unofficial].
4.  **VBO:** Stores triangle data. Each triangle has 3 vertices. Each vertex has 3 floats for position and 3 floats for normal (24 bytes total). Size: $totalSum \times 18 \times sizeof(cl\_float)$ [S1, unofficial].
5.  **Lookup Tables:**
    *   `numVertsTable`: `uint[256]`, number of vertices for each case [S2, unofficial].
    *   `triTable`: `uint[256 \times 16]`, edge indices for triangles, terminated by `-1` [S2, unofficial].

**Parameters:**
*   `isolevel`: Threshold for surface extraction. Default 51 (normalized to $[0,1]$ by dividing by 255.0) [S1, unofficial].
*   `SIZE`: Cubic grid dimension, power of two. Passed to OpenCL as `-DSIZE=<value>` [S1, unofficial].
*   `stepSize`: Subsampling factors. Default 1 [S1, unofficial].

**Algorithm Steps:**

1.  **Input Preparation:**
    *   Calculate `largestSize = max(sizeX, max(sizeY, sizeZ))` [S1, unofficial].
    *   Find smallest power of two $SIZE$ such that $SIZE \ge largestSize$ [S1, unofficial].
    *   Allocate new volume array of size $SIZE^3$ initialized to 0.
    *   Copy input data into the new array, preserving original dimensions [S1, unofficial].
    *   If `stepSize > 1`, subsample the volume [S1, unofficial].

2.  **Voxel Classification:**
    *   Launch kernel `classifyCubesKernel` (or `classifyVoxel` in CUDA variant) with work group $SIZE \times SIZE \times SIZE$ [S1, S2, unofficial].
    *   For each voxel, compute field values at 8 corners.
    *   Calculate `cubeindex`:
        $$ cubeindex = \sum_{k=0}^{7} \mathbb{I}(field_k < isoValue) \cdot 2^k $$
        where $\mathbb{I}$ is the indicator function [S2, unofficial].
    *   Store `cubeindex` in `cubeIndexesBuffer`/`cubeIndexesImage` [S1, unofficial].
    *   Look up `numVerts = numVertsTable[cubeindex]` [S2, unofficial].
    *   Store `numVerts` in `voxelVerts` and set `voxelOccupied[i] = 1` if `numVerts > 0`, else `0` [S2, unofficial].

3.  **Histogram Pyramid Construction:**
    *   **Base Level:** Compute the base of the HP from `voxelVerts` (or `cubeIndexes` count).
        *   *Texture:* Kernel `constructHPLevelKernel` reads `images[0]`, writes to `images[1]`. Work group $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
        *   *Buffer:* Kernel `constructHPLevelCharCharKernel` reads `buffers[0]`, writes to `buffers[1]`. Work group $SIZE/2 \times SIZE/2 \times SIZE/2$ [S1, unofficial].
    *   **Intermediate Levels:** Iterate from level 1 to $\log_2(SIZE)-2$.
        *   *Texture:* Kernel `constructHPLevelKernel` reads `images[i]`, writes to `images[i+1]`. Work group size halves each iteration [S1, unofficial].
        *   *Buffer:* Use type-specific kernels for transitions:
            *   Level 1->2: `constructHPLevelCharShortKernel` (char->short) [S1, unofficial].
            *   Level 2->3: `constructHPLevelShortShortKernel` (short->short) [S1, unofficial].
            *   Level 3->4: `constructHPLevelShortShortKernel` (short->short) [S1, unofficial].
            *   Level 4->5: `constructHPLevelShortIntKernel` (short->int) [S1, unofficial].
            *   Level 5+: `constructHPLevelKernel` (int->int) [S1, unofficial].
        *   *Constraint:* If buffer size becomes 1, force it to 2 to avoid 1x1x1 image errors [S1, unofficial].

4.  **Triangle Count Retrieval:**
    *   Read the top 8 integers of the HP (last level) [S1, unofficial].
    *   Sum them to get `totalSum` [S1, unofficial].
    *   If `totalSum == 0`, return early (no surface) [S2, unofficial].

5.  **VBO Allocation:**
    *   Create VBO with size `totalSum * 18 * sizeof(cl_float)` [S1, unofficial].

6.  **Histogram Pyramid Traversal (Compaction and Extraction):**
    *   Launch kernel `traverseHPKernel` [S1, unofficial].
    *   Work group size: Next multiple of 64 greater than or equal to `totalSum` [S1, unofficial].
        $$ global\_work\_size = totalSum + 64 - (totalSum - 64 \cdot (totalSum / 64)) $$
    *   Local size: 64 [S1, unofficial].
    *   The kernel traverses the HP from top to bottom to determine the exact output index for each triangle vertex in the VBO, avoiding sorting [S1, unofficial].
    *   For each active voxel, it computes edge intersection points:
        $$ t = \frac{isoValue - f_0.w}{f_1.w - f_0.w}, \quad p = p_0 + t \cdot (p_1 - p_0) $$
        where $f_0, f_1$ are field values at edge endpoints and $p_0, p_1$ are their positions [S2, unofficial].
    *   It writes vertices to the VBO using indices derived from the HP traversal [S1, unofficial].

7.  **Rendering:**
    *   Bind VBO.
    *   Set vertex pointer (3 floats, stride 24, offset 0) and normal pointer (3 floats, stride 24, offset 12) [S1, unofficial].
    *   Draw triangles: `glDrawArrays(GL_TRIANGLES, 0, totalSum * 3)` [S1, unofficial].

**Pseudocode:**

```python
def prepare_volume(raw_voxels, size_x, size_y, size_z):
    largest_size = max(size_x, max(size_y, size_z))
    size = 1
    while (1 << size) < largest_size:
        size += 1
    padded_size = 1 << size
    new_voxels = [0] * (padded_size ** 3)
    for x in range(size_x):
        for y in range(size_y):
            for z in range(size_z):
                new_voxels[x + y * padded_size + z * padded_size ** 2] = raw_voxels[x + y * size_z + z]
    return new_voxels, padded_size

def classify_voxels(volume, size, isovalue):
    cube_indexes = [0] * (size ** 3)
    voxel_occupied = [0] * (size ** 3)
    for i in range(size ** 3):
        # Extract 8 corner values from volume (simplified indexing)
        # In reality, this is done in parallel on GPU
        corners = get_voxel_corners(volume, i, size)
        cube_index = 0
        for k in range(8):
            if corners[k] < isovalue:
                cube_index |= (1 << k)
        cube_indexes[i] = cube_index
        num_verts = num_verts_table[cube_index]
        if num_verts > 0:
            voxel_occupied[i] = 1
    return cube_indexes, voxel_occupied

def build_histo_pyramid(voxel_occupied, size):
    # Base level: count occupied voxels per block
    # Intermediate levels: sum up from base
    # Returns list of buffers/images representing the pyramid
    hp_levels = []
    current_data = voxel_occupied
    current_size = size
    while current_size > 1:
        next_size = current_size // 2
        next_data = [0] * (next_size ** 3)
        # Sum 2x2x2 blocks from current_data into next_data
        for x in range(next_size):
            for y in range(next_size):
                for z in range(next_size):
                    s = 0
                    for dx in range(2):
                        for dy in range(2):
                            for dz in range(2):
                                s += current_data[(x*2+dx) + (y*2+dy)*current_size + (z*2+dz)*current_size**2]
                    next_data[x + y*next_size + z*next_size**2] = s
        hp_levels.append(next_data)
        current_data = next_data
        current_size = next_size
    return hp_levels

def traverse_histo_pyramid(hp_levels, cube_indexes, size, isovalue):
    total_sum = hp_levels[-1][0] # Top level sum
    if total_sum == 0:
        return []
    
    vbo = [0] * (total_sum * 18) # 3 vertices * 6 floats per vertex
    # Traverse from top to bottom to assign indices
    # This part is complex and typically done in a GPU kernel
    # Here is a simplified conceptual representation
    output_index = 0
    for i in range(size ** 3):
        if voxel_occupied[i]:
            cube_index = cube_indexes[i]
            num_verts = num_verts_table[cube_index]
            corners = get_voxel_corners(volume, i, size)
            edge_intersections = compute_edge_intersections(corners, isovalue)
            
            tri_indices = tri_table[cube_index]
            for j in range(0, 15, 3):
                if tri_indices[j] == -1:
                    break
                e1, e2, e3 = tri_indices[j], tri_indices[j+1], tri_indices[j+2]
                p1 = edge_intersections[e1]
                p2 = edge_intersections[e2]
                p3 = edge_intersections[e3]
                # Write to VBO at output_index
                vbo[output_index * 6] = p1.x
                vbo[output_index * 6 + 1] = p1.y
                vbo[output_index * 6 + 2] = p1.z
                vbo[output_index * 6 + 3] = p1.normal_x # Assuming normals computed
                vbo[output_index * 6 + 4] = p1.normal_y
                vbo[output_index * 6 + 5] = p1.normal_z
                output_index += 1
                
                vbo[output_index * 6] = p2.x
                vbo[output_index * 6 + 1] = p2.y
                vbo[output_index * 6 + 2] = p2.z
                vbo[output_index * 6 + 3] = p2.normal_x
                vbo[output_index * 6 + 4] = p2.normal_y
                vbo[output_index * 6 + 5] = p2.normal_z
                output_index += 1
                
                vbo[output_index * 6] = p3.x
                vbo[output_index * 6 + 1] = p3.y
                vbo[output_index * 6 + 2] = p3.z
                vbo[output_index * 6 + 3] = p3.normal_x
                vbo[output_index * 6 + 4] = p3.normal_y
                vbo[output_index * 6 + 5] = p3.normal_z
                output_index += 1
    return vbo

def render(vbo, total_sum):
    glBindBuffer(GL_ARRAY_BUFFER, vbo_id)
    glVertexPointer(3, GL_FLOAT, 24, BUFFER_OFFSET(0))
    glNormalPointer(GL_FLOAT, 24, BUFFER_OFFSET(12))
    glDrawArrays(GL_TRIANGLES, 0, total_sum * 3)
```

**Edge Cases and Pitfalls:**
*   **Power of Two Requirement:** The algorithm requires volume dimensions to be powers of two. Non-power-of-two inputs must be padded with zeros [S1, unofficial].
*   **NVIDIA GPU Limitation:** Lack of 3D texture write support on NVIDIA GPUs forces a fallback to regular buffers and morton codes, which is slower [S1, unofficial].
*   **Grid Dimension Limit:** CUDA grid dimensions are limited to 65535. If `numVoxels` exceeds this, the launch configuration must be adjusted (e.g., capping x at 32768) [S2, unofficial].
*   **Empty Volume:** If no voxels are active, the function returns early with `successful = false` [S2, unofficial].
*   **Image Size Constraint:** OpenGL/OpenCL images cannot be 1x1x1. If buffer size becomes 1 during HP construction, it is forced to 2 [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for classification and HP construction, where $N$ is the number of voxels. Traversal is $O(T)$ where $T$ is the number of triangles.
*   **Memory Complexity:** $O(N)$ for volume and HP storage. HP storage is slightly more than $N$ due to hierarchy. VBO storage is $O(T)$.
*   **Performance:** High-speed extraction due to avoidance of atomics and sorting [S1, unofficial]. Performance depends on GPU support for 3D texture writes [S1, unofficial].
*   **Strengths:** Deterministic compaction, no race conditions from atomics, efficient for large volumes [S1, unofficial].
*   **Limitations:** Requires power-of-two dimensions, slower on NVIDIA GPUs without 3D texture write support [S1, unofficial].

## Background
Originated from the work of Dyken, Ziegler, Theobalt, and Seidel (2008) on "High-speed marching cubes using histopyramids" [S2, unofficial]. It is implemented in the FAST framework and the smistad/GPU-Marching-Cubes repository [S1, unofficial].
