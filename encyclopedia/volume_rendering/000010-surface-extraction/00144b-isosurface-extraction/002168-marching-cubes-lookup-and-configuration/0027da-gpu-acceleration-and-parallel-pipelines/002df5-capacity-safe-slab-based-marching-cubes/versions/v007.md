# Capacity-safe slab-based Marching Cubes

Also called: Capacity-safe slab-based isososurface extraction, Capacity-safe slab-based isosurface extraction pipeline, Capacity-safe tiled Marching Cubes, Two-pass tiled Marching Cubes, inclusive slab partitioning with exact allocation, slab-based two-pass GPU isosurface extraction

## Overview
This method is a GPU-accelerated isosurface extraction pipeline that partitions the z-axis into slabs to compute exact vertex counts per slab via a two-pass strategy (classify/scan then generate), allowing for exact buffer allocation and crack-free surfaces at slab boundaries [S1]. It differs from standard Marching Cubes by resolving topological discontinuities and holes via boundary-consistent slab processing, and differs from HistoPyramids/Flying Edges by specializing counting/compaction for tightly coupled extraction, rendering, and engine integration [S1]. Unlike implicit isosurface raycasting, this method generates explicit geometric assets (vertices/normals) suitable for mesh-based interaction tools and OBJ export, whereas raycasting is more memory-efficient for direct visualization of single isovalues [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $V$ defined on a grid of dimensions $N_x \times N_y \times N_z$, where $V: \{0, \dots, N_x-1\} \times \{0, \dots, N_y-1\} \times \{0, \dots, N_z-1\} \to \mathbb{R}$ [S1]. An isovalue $\tau \in \mathbb{R}$ [S1].
*   **Output:** A Vertex Buffer Object (VBO) containing two arrays: `pos` (positions) and `nrm` (normals). The total capacity is $N$ vertices, where $N$ is the exact sum of vertices generated by all cells [S1]. Each triangle writes 3 consecutive vertices. For each vertex, `pos` stores a 3D vector and `nrm` stores a 3D vector [S1].

**Data Structures:**
*   **Linear Index:** Cells are mapped to a linear index for array storage:
    $$
    \text{lin}(x,y,z) = (z N_y + y) N_x + x
    $$
    where $N_x, N_y, N_z$ are grid dimensions [S1].
*   **Slab Definition:** The z-axis is partitioned into slabs of thickness $S$. The set of valid cells for slab $s$ is defined as the closed interval:
    $$
    \mathcal{K}_s = \{k \mid k_{\text{begin}}(s) \le k \le k_{\text{end}}(s)\}
    $$
    This inclusive definition ensures that the $k+1$ corner access required by Marching Cubes remains valid even at slab boundaries [S1].
*   **Count Arrays:** For each slab $s$, a local count array `count_s` is indexed by the linear cell index $\text{lin}(i,j,k)$ [S1].
*   **Offset Array:** An exclusive prefix-sum (scan) result `offset` is computed for each cell $\ell$ within a slab [S1].
*   **Slab Base:** `base[s]` stores the cumulative vertex count for all slabs $t < s$ [S1].

**Parameters:**
*   **Slab Thickness ($S$):** Recommended value is in the range $[48, 96]$ for a $512^3$ grid [S1].
*   **Partial Slabs:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].
*   **Grid Resolution:** Tested up to $512^3$ [S1].

**Algorithm Steps:**
1.  **Pass 1 (Classify/Scan):**
    1.  Initialize global vertex count $N \leftarrow 0$ [S1].
    2.  For each slab $s$:
        a.  For each cell $(i,j,k)$ with $k \in [k_{\text{begin}}(s), k_{\text{end}}(s)]$:
            i.  Compute the case index $c = \text{caseIndex}(V, i, j, k, \tau)$ using the logic from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) [S1, Parent].
            ii. Retrieve the vertex count $n_{ijk} = \text{numVerts}[c]$ [S1].
            iii. Store $n_{ijk}$ in `count_s[lin(i,j,k)]` [S1].
        b.  Compute an exclusive prefix-sum (scan) over `count_s` to generate `offset[ℓ]` for each cell $\ell$ in the slab [S1].
        c.  Calculate the slab-level total $N_s = \text{offsets}[\text{last}] + \text{count}_s[\text{last}]$ [S1].
        d.  Set `base[s]` $\leftarrow N$ [S1].
        e.  Update global count $N \leftarrow N + N_s$ [S1].
    3.  Allocate an interoperable Vertex Buffer Object (VBO) with exactly $N$ vertex capacity for `pos` and `nrm` [S1].

2.  **Pass 2 (Generate):**
    1.  For each slab $s$:
        a.  For each cell $(i,j,k)$ with $k \in [k_{\text{begin}}(s), k_{\text{end}}(s)]$:
            i.  Compute $c = \text{caseIndex}(V, i, j, k, \tau)$ [S1].
            ii. If $\text{numVerts}[c] \neq 0$:
                1.  Compute edge vertices via linear interpolation: $\text{edgeVerts}[0..11] \leftarrow \text{edge\_lerp}(V, i, j, k, \tau)$ [S1]. The interpolation for an edge between corners $\mathbf{p}_1, \mathbf{p}_2$ with values $V_1, V_2$ is:
                    $$
                    \mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1)
                    $$
                    [S1, Parent].
                2.  Determine the destination address in the VBO: $\text{dst} = \text{base}[s] + \text{offsets}[\text{lin}(i,j,k)]$ [S1].
                3.  Iterate through the triangle edge list $\text{triTable}[c][t..t+2]$ for $t$ from $0$ to $\text{numVerts}[c]-1$ with step 3 [S1].
                4.  Let $(e_0, e_1, e_2) = \text{triTable}[c][t..t+2]$ [S1].
                5.  If any edge index $e_0, e_1, \text{ or } e_2 < 0$, break the triangle loop [S1].
                6.  Retrieve vertices $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ from $\text{edgeVerts}[e_0], \text{edgeVerts}[e_1], \text{edgeVerts}[e_2]$ [S1].
                7.  Compute the face normal $\mathbf{n}$ to enforce counterclockwise winding:
                    $$
                    \mathbf{n} = \frac{(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)}{\|(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)\|}
                    $$
                    [S1].
                8.  Write positions $\{\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2\}$ to `pos[dst:dst+2]` and normals $\{\mathbf{n}, \mathbf{n}, \mathbf{n}\}$ to `nrm[dst:dst+2]` [S1].
                9.  Increment $\text{dst} \leftarrow \text{dst} + 3$ [S1].

**Edge Cases and Pitfalls:**
*   **Boundary Cracks:** Using inclusive slab indexing ($\mathcal{K}_s$ includes $k_{\text{end}}(s)$) ensures that the $k+1$ corner access required by MC is valid at slab boundaries, eliminating omissions/duplications and cracks caused by off-by-one inconsistencies [S1].
*   **Empty Triangles:** The algorithm checks if edge indices $e_0, e_1, e_2$ are $< 0$. If so, it breaks the triangle loop, handling cases where the triangle table entry indicates no triangle for that specific triplet [S1].
*   **Partial Slabs:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].

## Operating characteristics
*   **Time Complexity:** $O(M)$ for both passes, where $M = (N_x-1)(N_y-1)(N_z-1)$ is the number of cells [S1].
*   **Memory Complexity:** The additional storage consists of the slab-local count and offset arrays, while the output buffers are allocated according to the exact number of generated vertices $N$ [S1]. The method uses less than 11 GB GPU memory for a $512^3$ grid [S1].
*   **Measured Performance:** On electromagnetic-potential fields with resolutions up to $512^3$, the method generates approximately 42.81 million vertices in 44.7 ms, uses less than 11 GB GPU memory, and renders the resulting geometry at 28.6 FPS [S1].
*   **Strengths:** Prevents slab-boundary omissions and output-buffer overflow; generates exact buffer sizes; zero-copy streaming to OpenGL via CUDA-OpenGL interoperability; crack-free surfaces [S1].
*   **Limitations:** Less suitable for sharp-feature preservation than methods such as Dual Contouring or MC33; limited to volumes that fit within the memory of a single GPU [S1].
*   **When to Use:** When explicit geometric assets are required for mesh-based interaction, OBJ export, or integration into engines like Unreal Engine, and when large scalar grids need to be processed without buffer overruns or boundary cracks [S1].
*   **When Not to Use:** When implicit isosurface raycasting is more appropriate (e.g., for direct visualization of single isovalues with flexible transfer functions without explicit geometry generation) [S1].

## Background
*   **Origin:** The method was presented in a paper titled "Visual tools for 3D plasma simulation: GPU-based isosurface extraction..." [S1].
*   **History and Development:** It was developed to address the challenges of visualizing fusion-plasma simulation data, which involves extremely large-scale interactions and data volumes reaching hundreds of gigabytes to several terabytes [S1]. The method combines inclusive slab partitioning with a two-pass counting and exact allocation strategy to prevent slab-boundary omissions and output-buffer overflow while supporting large scalar grids [S1].
*   **Usage:** It is used in a standalone renderer and integrated into Unreal Engine for volume rendering, explicit-isosurface inspection, particle-trajectory visualization, clipping, and VR-based spatial exploration [S1]. It is also used in the proposed framework for visualizing 3D plasma simulation data (fusion-plasma electromagnetic potential) on GPUs with CUDA-OpenGL interoperability [S1].
