# Capacity-safe slab-based Marching Cubes

Also called: Capacity-safe slab-based isososurface extraction, Capacity-safe slab-based isosurface extraction pipeline, Capacity-safe tiled Marching Cubes, Two-pass tiled Marching Cubes, inclusive slab partitioning with exact allocation, slab-based two-pass GPU isosurface extraction

## Overview
This method is a GPU-accelerated isosurface extraction pipeline that partitions the z-axis into slabs to compute exact vertex counts per slab via a two-pass strategy (classify/scan then generate), allowing for exact buffer allocation and crack-free surfaces at slab boundaries [S1]. It differs from standard Marching Cubes by resolving topological discontinuities and holes via boundary-consistent slab processing, and differs from HistoPyramids/Flying Edges by specializing counting/compaction for tightly coupled extraction, rendering, and engine integration [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $V$ defined on a grid with dimensions $N_x \times N_y \times N_z$, and an isovalue $\tau$.
*   **Output:** An explicit mesh consisting of vertex positions and normals, stored in a CUDA-OpenGL interoperable Vertex Buffer Object (VBO).

**Data Structures:**
*   **Grid Dimensions:** $N_x, N_y, N_z$ (number of samples). The number of cells is $M = (N_x-1)(N_y-1)(N_z-1)$.
*   **Linear Index:** Maps 3D cell coordinates $(x,y,z)$ to a 1D index:
    $$ \text{lin}(x,y,z) = (z N_y + y) N_x + x $$
    where $0 \le x \le N_x-2$, $0 \le y \le N_y-2$, $0 \le z \le N_z-2$ [S1].
*   **Slab Configuration:** The z-axis is partitioned into slabs of thickness $S$. For slab $s$, the set of valid cell indices $k$ is the closed interval $\mathcal{K}_s = \{k \mid k_{\text{begin}}(s) \le k \le k_{\text{end}}(s)\}$. This inclusive indexing ensures that the $k+1$ corner access required by Marching Cubes remains valid at slab boundaries [S1].
*   **Count Arrays:** For each slab $s$, a local array `countss` stores the vertex count $n_{ijk}$ for each cell in $\mathcal{K}_s$, indexed by `lin(i,j,k)`.
*   **Offset Arrays:** For each slab $s$, an array `offsets` stores the exclusive prefix-sum of `countss`.
*   **VBO Layout:** Contains two arrays, `pos` and `nrm`. Each triangle writes 3 consecutive vertices. For each vertex, `pos` stores a 3D vector (position) and `nrm` stores a 3D vector (normal). The total capacity is $N$ vertices, where $N$ is the sum of vertices generated by all cells [S1].

**Parameters:**
*   **Slab Thickness ($S$):** Recommended value is in the range $[48, 96]$ for a $512^3$ grid [S1].
*   **Partial Slabs:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].

**Algorithm Steps:**

1.  **Pass 1: Classify and Scan (Counting)**
    *   Initialize global vertex count $N \leftarrow 0$.
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ where $k \in \mathcal{K}_s$:
            *   Compute the Marching Cubes case index $c = \text{caseIndex}(V, i, j, k, \tau)$ using the edge intersection table and vertex comparisons against $\tau$ [S4, S12, unofficial].
            *   Retrieve the number of vertices for this case: $n_{ijk} = \text{numVerts}[c]$ [S8, S12, unofficial].
            *   Store $n_{ijk}$ in `countss[lin(i,j,k)]`.
        *   Compute an exclusive prefix-sum (scan) over `countss` to generate `offsets[ℓ]` for each cell $\ell$ in the slab [S1].
        *   Calculate the slab-level total $N_s = \text{offsets}[\text{last}] + \text{countss}[\text{last}]$ [S1].
        *   Set the slab base offset $\text{base}[s] = N$.
        *   Update global count: $N \leftarrow N + N_s$.
    *   Allocate an interoperable Vertex Buffer Object (VBO) with exactly $N$ vertex capacity for positions and normals [S1].

2.  **Pass 2: Generate (Emission)**
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ where $k \in \mathcal{K}_s$:
            *   Compute $c = \text{caseIndex}(V, i, j, k, \tau)$ [S1].
            *   If $\text{numVerts}[c] \neq 0$:
                *   Compute edge vertices via linear interpolation: $\text{edgeVerts}[0..11] \leftarrow \text{edge\_lerp}(V, i, j, k, \tau)$ [S1].
                *   Determine the destination address in the VBO: $\text{dst} = \text{base}[s] + \text{offsets}[\text{lin}(i,j,k)]$ [S1].
                *   Iterate through the triangle edge list $\text{triTable}[c][t..t+2]$ for $t$ from $0$ to $\text{numVerts}[c]-1$ with step 3 [S8, S12, unofficial].
                *   If any edge index $e_0, e_1, e_2$ is $< 0$, break the loop (handles empty triangles) [S1].
                *   Retrieve vertices $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ from $\text{edgeVerts}$ using indices $e_0, e_1, e_2$ [S1].
                *   Compute the face normal $\mathbf{n}$ to enforce counterclockwise winding:
                    $$ \mathbf{n} = \frac{(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)}{\|(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)\|} $$
                    [S1]
                *   Write positions $\{\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2\}$ to `pos[dst:dst+2]` and normals $\{\mathbf{n}, \mathbf{n}, \mathbf{n}\}$ to `nrm[dst:dst+2]` [S1].
                *   Increment $\text{dst} \leftarrow \text{dst} + 3$ [S1].

**Edge Cases and Pitfalls:**
*   **Boundary Cracks:** Using inclusive slab indexing ($\mathcal{K}_s$ includes $k_{\text{end}}(s)$) ensures that the $k+1$ corner access required by MC is valid at slab boundaries, eliminating omissions/duplications and cracks caused by off-by-one inconsistencies [S1].
*   **Empty Triangles:** The algorithm checks if edge indices $e_0, e_1, e_2$ are $< 0$. If so, it breaks the triangle loop, handling cases where the triangle table entry indicates no triangle for that specific triplet [S1].
*   **Partial Slabs:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].

## Operating characteristics
*   **Time Complexity:** $O(M)$ for both passes, where $M = (N_x-1)(N_y-1)(N_z-1)$ is the number of cells [S1].
*   **Memory Complexity:** The additional storage consists of the slab-local count and offset arrays. The output buffers are allocated according to the exact number of generated vertices $N$ [S1].
*   **Measured Performance:** On electromagnetic-potential fields with resolutions up to $512^3$, the method generates approximately 42.81 million vertices in 44.7 ms, uses less than 11 GB of GPU memory, and renders the resulting geometry at 28.6 FPS [S1].
*   **Strengths:** Prevents slab-boundary omissions and output-buffer overflow; supports large scalar grids; zero-copy streaming to OpenGL buffers; crack-free surfaces.
*   **Limitations:** Less suitable for sharp-feature preservation than methods such as Dual Contouring or MC33; limited to volumes that fit within the memory of a single GPU [S1].
*   **When to Use:** When explicit geometric assets (vertices/normals) are required for mesh-based interaction tools, OBJ export, or integration into engines like Unreal Engine, rather than direct volume rendering [S1].

## Background
*   **Origin:** The method was introduced in a paper presenting a GPU-accelerated visualization framework for interactive exploration of fusion-plasma simulation data [S1].
*   **History:** It combines inclusive slab partitioning with a two-pass counting and exact allocation strategy to address issues in large-scale scalar grid visualization [S1].
*   **Usage:** Used in a standalone renderer and integrated into Unreal Engine for volume rendering, explicit-isosurface inspection, particle-trajectory visualization, clipping, and VR-based spatial exploration [S1]. Specifically used for visualizing 3D plasma simulation data (fusion-plasma electromagnetic potential) on GPUs with CUDA-OpenGL interoperability [S1].
