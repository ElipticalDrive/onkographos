# Capacity-safe slab-based Marching Cubes

Also called: Capacity-safe slab-based isososurface extraction, Capacity-safe slab-based isosurface extraction pipeline, Capacity-safe tiled Marching Cubes, Two-pass tiled Marching Cubes, inclusive slab partitioning with exact allocation, slab-based two-pass GPU isosurface extraction

## Overview
A GPU-accelerated isosurface extraction pipeline that uses inclusive slab partitioning and a two-pass counting/exact allocation strategy to prevent slab-boundary omissions and output-buffer overflow for large scalar grids [S1]. It differs from standard Marching Cubes by resolving topological discontinuities and holes via boundary-consistent slab processing, and differs from HistoPyramids/Flying Edges by specializing counting/compaction for tightly coupled extraction, rendering, and engine integration [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $V$ defined on a grid of dimensions $N_x \times N_y \times N_z$, where $V: \{0, \dots, N_x-1\} \times \{0, \dots, N_y-1\} \times \{0, \dots, N_z-1\} \to \mathbb{R}$ [S1]. An isovalue $\tau \in \mathbb{R}$ [S1].
*   **Output:** A Vertex Buffer Object (VBO) containing two arrays: `pos` (positions) and `nrm` (normals). The total capacity is $N$ vertices, where $N$ is the exact sum of vertices generated by all cells [S1]. Each triangle writes 3 consecutive vertices. For each vertex, `pos` stores a 3D vector and `nrm` stores a 3D vector [S1].

**Data Structures:**
*   **Grid Dimensions:** $N_x, N_y, N_z$ [S1].
*   **Cell Index:** $(i, j, k)$ where $0 \le i \le N_x-2$, $0 \le j \le N_y-2$, $0 \le k \le N_z-2$ [S1].
*   **Linear Index:** $lin(x, y, z) = (z N_y + y) N_x + x$ [S1].
*   **Lookup Tables:** `edgeTable` (12-bit bitmask) and `triangleTable` (256x16 array) as defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) [Parent].
*   **Vertex Count Table:** `numVerts[c]` denotes the number of vertices associated with case $c$ [S1].
*   **Slab Parameters:** Slab thickness $S$. Recommended range $[48, 96]$ for a $512^3$ grid [S1].
*   **Slab Definition:** The z-axis is partitioned into slabs. The set of valid cells for slab $s$ is the closed interval $\mathcal{K}_s = \{k \mid k_{begin}(s) \le k \le k_{end}(s)\}$ [S1]. This inclusive indexing ensures that the $k+1$ corner access required by MC remains valid at slab boundaries [S1]. If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].
*   **Intermediate Arrays (Per Slab):**
    *   `countss`: Array indexed by linear cell index $lin(i,j,k)$, storing $n_{ijk} = numVerts[c]$ [S1].
    *   `offsets`: Exclusive prefix-sum (scan) result over `countss` for the slab [S1].
*   **Global State:**
    *   $N_s$: Total vertices on slab $s$, calculated as $offsets[last] + countss[last]$ [S1].
    *   $N$: Global total vertices, $N = \sum_s N_s$ [S1].
    *   $base[s]$: Cumulative sum of $N_t$ for all slabs $t < s$ [S1].

**Algorithm Steps:**

1.  **Pass 1: Classify and Scan (Counting)**
    For each slab $s$:
    1.  Initialize `countss` array for the slab.
    2.  For each cell $(i, j, k)$ where $k \in \mathcal{K}_s$:
        a.  Compute case index $c = caseIndex(V, i, j, k, \tau)$ [S1].
        b.  Compute vertex count $n_{ijk} = numVerts[c]$ [S1].
        c.  Store $n_{ijk}$ in `countss[lin(i,j,k)]` [S1].
    3.  Compute exclusive prefix-sum (scan) over `countss` to generate `offsets` [S1].
    4.  Calculate slab vertex count $N_s = offsets[last] + countss[last]$ [S1].
    5.  Set $base[s] = N$ (current global total) [S1].
    6.  Update global total $N \leftarrow N + N_s$ [S1].

2.  **Allocation**
    1.  Allocate an interoperable VBO (CUDA-OpenGL) with exactly $N$ vertex capacity for `pos` and `nrm` arrays [S1].

3.  **Pass 2: Generate (Rendering)**
    For each slab $s$:
    1.  For each cell $(i, j, k)$ where $k \in \mathcal{K}_s$:
        a.  Compute case index $c = caseIndex(V, i, j, k, \tau)$ [S1].
        b.  If $numVerts[c] \neq 0$:
            i.  Compute edge vertices: $edgeVerts[0..11] \leftarrow edge\_lerp(V, i, j, k, \tau)$ [S1].
            ii. Compute destination address: $dst = base[s] + offsets[lin(i,j,k)]$ [S1].
            iii. Iterate through triangle edge list $triTable[c][t..t+2]$ for $t$ from $0$ to $numVerts[c]-1$ with step 3 [S1].
            iv. If any edge index $e_0, e_1, e_2$ is $< 0$, break the loop [S1].
            v.  Retrieve vertices $p_0, p_1, p_2$ from $edgeVerts[e_0], edgeVerts[e_1], edgeVerts[e_2]$ [S1].
            vi. Compute face normal $n = \frac{(p_1 - p_0) \times (p_2 - p_0)}{\|(p_1 - p_0) \times (p_2 - p_0)\|}$ to enforce counterclockwise winding [S1].
            vii. Write positions $\{p_0, p_1, p_2\}$ to `pos[dst:dst+2]` and normals $\{n, n, n\}$ to `nrm[dst:dst+2]` [S1].
            viii. Increment $dst \leftarrow dst + 3$ [S1].

        slabs.append((k, k_end))

    slab_counts = []

    # Pass 1: Classify and Scan

**Edge Cases and Pitfalls:**
*   **Boundary Cracks:** Using inclusive slab indexing ($\mathcal{K}_s$ includes $k_{end}(s)$) ensures that the $k+1$ corner access required by MC is valid at slab boundaries, eliminating omissions/duplications and cracks caused by off-by-one inconsistencies [S1].
*   **Empty Triangles:** The algorithm checks if edge indices $e_0, e_1, e_2$ are $< 0$. If so, it breaks the triangle loop, handling cases where the triangle table entry indicates no triangle for that specific triplet [S1].
*   **Partial Slabs:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].
*   **Memory Limits:** The method is limited to volumes that fit within the memory of a single GPU [S1].

## Operating characteristics
*   **Time Complexity:** $O(M)$ for both passes, where $M = (N_x-1)(N_y-1)(N_z-1)$ is the number of cells [S1].
*   **Memory Complexity:** The additional storage consists of the slab-local count and offset arrays, while the output buffers are allocated according to the exact number of generated vertices [S1].
*   **Measured Performance:** On electromagnetic-potential fields with resolutions up to $512^3$, the method generates approximately 42.81 million vertices in 44.7 ms, uses less than 11 GB of GPU memory, and renders the resulting geometry at 28.6 FPS [S1].
*   **Strengths:** Prevents buffer overruns, eliminates boundary cracks, enables zero-copy streaming to OpenGL via CUDA-OpenGL interoperability, and integrates directly into game engines like Unreal Engine [S1].
*   **Limitations:** Less suitable for sharp-feature preservation than methods such as Dual Contouring or MC33 [S1]. Limited to volumes fitting in single-GPU memory [S1].

## Background
The method was introduced in a paper presenting a GPU-accelerated visualization framework for interactive exploration of fusion-plasma simulation data [S1]. It addresses the challenges of large-scale electromagnetic field data, which can reach hundreds of gigabytes to several terabytes [S1]. The pipeline is integrated into a standalone renderer and Unreal Engine for volume rendering, explicit-isosurface inspection, particle-trajectory visualization, clipping, and VR-based spatial exploration [S1].
