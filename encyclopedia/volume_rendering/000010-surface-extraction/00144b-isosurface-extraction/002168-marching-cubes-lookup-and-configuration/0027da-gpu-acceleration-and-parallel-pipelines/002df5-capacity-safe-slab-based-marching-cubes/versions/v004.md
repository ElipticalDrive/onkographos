# Capacity-safe slab-based Marching Cubes

Also called: Capacity-safe slab-based isososurface extraction, Capacity-safe slab-based isosurface extraction pipeline, Capacity-safe tiled Marching Cubes, Two-pass tiled Marching Cubes, inclusive slab partitioning with exact allocation, slab-based two-pass GPU isosurface extraction

## Overview
Capacity-safe slab-based Marching Cubes is a GPU-accelerated isosurface extraction pipeline that partitions the z-axis into slabs to compute exact vertex counts per slab via a two-pass strategy (classify/scan then generate), allowing for exact buffer allocation and crack-free surfaces at slab boundaries [S1]. It differs from standard Marching Cubes by resolving topological discontinuities and holes via boundary-consistent slab processing, and differs from HistoPyramids/Flying Edges by specializing counting/compaction for tightly coupled extraction, rendering, and engine integration [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $V$ defined on a grid of dimensions $N_x \times N_y \times N_z$, where $V: \{0, \dots, N_x-1\} \times \{0, \dots, N_y-1\} \times \{0, \dots, N_z-1\} \to \mathbb{R}$ [S1]. An isovalue $\tau \in \mathbb{R}$ [S1].
*   **Output:** A Vertex Buffer Object (VBO) containing two arrays: `pos` (positions) and `nrm` (normals). The total capacity is $N$ vertices, where $N$ is the sum of vertices generated by all cells. Each triangle writes 3 consecutive vertices. For each vertex, `pos` stores a 3D vector and `nrm` stores a 3D vector [S1].

**Data Structures:**
*   **Lookup Tables:** The method relies on the precomputed data structures from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md): the `edgeTable` (256-entry bitmask) and `triangleTable` (256x16 edge index array) [S1, Parent].
*   **Slab Partitioning:** The z-axis is partitioned into slabs of thickness $S$. The set of valid cells for slab $s$ is defined as the closed interval $\mathcal{K}_s = \{k \mid k_{begin}(s) \le k \le k_{end}(s)\}$ [S1].
*   **Count/Offset Arrays:** For each slab, a count array stores the number of vertices per cell, and an offset array stores the exclusive prefix sum [S1].

**Parameters:**
*   **Slab Thickness ($S$):** Recommended value is in the range $[48, 96]$ for a $512^3$ grid [S1].
*   **Boundary Handling:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].

**Algorithm Steps:**
1.  **Partitioning:** Define slab ranges $\{[k_b(s), k_e(s)]\}$ for all slabs $s$. Ensure inclusive indexing so that the $k+1$ corner access required by MC remains valid at slab boundaries [S1].
2.  **Pass 1 (Classify/Scan):**
    *   Initialize global vertex count $N \leftarrow 0$ [S1].
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ with $k \in [k_b(s), k_e(s)]$:
            *   Compute case index $c = \text{caseIndex}(V, i, j, k, \tau)$ [S1].
            *   Compute vertex count $n_{ijk} = \text{numVerts}[c]$ [S1].
            *   Store $n_{ijk}$ in a count array indexed by the linear cell index $\ell = \text{lin}(i,j,k)$ [S1].
        *   Compute an exclusive prefix-sum (scan) over the count array to generate `offsets`[$\ell$] for each cell $\ell$ [S1].
        *   Calculate the slab-level total $N_s = \text{offsets}[\text{last}] + \text{countss}[\text{last}]$ [S1].
        *   Set the slab base offset $\text{base}[s] = N$ [S1].
        *   Update global count $N \leftarrow N + N_s$ [S1].
    *   Allocate an interoperable VBO with exactly $N$ vertex capacity [S1].
3.  **Pass 2 (Generate):**
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ with $k \in [k_b(s), k_e(s)]$:
            *   Compute $c$ and $n_{ijk}$ (or reuse cached values) [S1].
            *   If $n_{ijk} \neq 0$:
                *   Compute edge vertices via linear interpolation: $\text{edgeVerts}[0..11] \leftarrow \text{edge\_lerp}(V, i, j, k, \tau)$ [S1].
                *   Determine destination address: $\text{dst} = \text{base}[s] + \text{offsets}[\text{lin}(i,j,k)]$ [S1].
                *   Iterate through the triangle edge list $\text{triTable}[c][t..t+2]$ for $t$ from $0$ to $\text{numVerts}[c]-1$ with step 3 [S1].
                *   If any edge index $e_0, e_1, e_2$ is $< 0$, break the loop [S1].
                *   Retrieve vertices $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ from $\text{edgeVerts}$ [S1].
                *   Compute face normal $\mathbf{n} = \frac{(\mathbf{p}_1-\mathbf{p}_0) \times (\mathbf{p}_2-\mathbf{p}_0)}{\|(\mathbf{p}_1-\mathbf{p}_0) \times (\mathbf{p}_2-\mathbf{p}_0)\|}$ to enforce counterclockwise winding [S1].
                *   Write positions $\{\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2\}$ and normals $\{\mathbf{n}, \mathbf{n}, \mathbf{n}\}$ to $\text{pos}[\text{dst}:\text{dst}+2]$ and $\text{nrm}[\text{dst}:\text{dst}+2]$ [S1].
                *   Increment $\text{dst}$ by 3 [S1].

**Edge Cases and Pitfalls:**
*   **Boundary Cracks:** Using inclusive slab indexing ($\mathcal{K}_s$ includes $k_{end}(s)$) ensures that the $k+1$ corner access required by MC is valid at slab boundaries, eliminating omissions/duplications and cracks caused by off-by-one inconsistencies [S1].
*   **Empty Triangles:** The algorithm checks if edge indices $e_0, e_1, e_2$ are $< 0$. If so, it breaks the triangle loop, handling cases where the triangle table entry indicates no triangle for that specific triplet [S1].
*   **Partial Slabs:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].

## Operating characteristics
*   **Time Complexity:** $O(M)$ for both passes, where $M = (N_x-1)(N_y-1)(N_z-1)$ is the number of cells [S1].
*   **Memory Complexity:** The additional storage consists of the slab-local count and offset arrays. The output buffers are allocated according to the exact number of generated vertices $N$ [S1].
*   **Measured Performance:** On electromagnetic-potential fields with resolutions up to $512^3$, the method generates approximately 42.81 million vertices in 44.7 ms, uses less than 11 GB of GPU memory, and renders the resulting geometry at 28.6 FPS [S1].
*   **Strengths:** Prevents slab-boundary omissions and output-buffer overflow; supports large scalar grids; zero-copy streaming to OpenGL via CUDA-OpenGL interoperability [S1].
*   **Limitations:** Less suitable for sharp-feature preservation than methods such as Dual Contouring or MC33; limited to volumes that fit within the memory of a single GPU [S1].

## Background
*   **Origin:** The method was presented in a paper titled "Visual tools for 3D plasma simulation: GPU-based isosurface extraction..." [S1].
*   **History and Development:** It was developed to address the challenges of visualizing fusion-plasma simulation data, which involves extremely large-scale interactions and data volumes reaching hundreds of gigabytes to several terabytes [S1]. The framework integrates isosurface extraction with particle-based rendering into a single lightweight GPU workflow, utilizing CUDA-OpenGL interoperability for zero-copy streaming [S1].
*   **Usage:** Used in a standalone renderer and integrated into Unreal Engine for volume rendering, explicit-isosurface inspection, particle-trajectory visualization, clipping, and VR-based spatial exploration [S1]. Specifically used for visualizing 3D plasma simulation data (fusion-plasma electromagnetic potential) on GPUs with CUDA-OpenGL interoperability [S1].
