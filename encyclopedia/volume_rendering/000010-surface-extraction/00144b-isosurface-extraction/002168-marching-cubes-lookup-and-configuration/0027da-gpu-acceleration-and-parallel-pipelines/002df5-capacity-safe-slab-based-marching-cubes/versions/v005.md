# Capacity-safe slab-based Marching Cubes

Also called: Capacity-safe slab-based isososurface extraction, Capacity-safe slab-based isosurface extraction pipeline, Capacity-safe tiled Marching Cubes, Two-pass tiled Marching Cubes, inclusive slab partitioning with exact allocation, slab-based two-pass GPU isosurface extraction

## Overview
This method is a GPU-accelerated isosurface extraction pipeline that partitions the z-axis into slabs to compute exact vertex counts per slab via a two-pass strategy (classify/scan then generate), allowing for exact buffer allocation and crack-free surfaces at slab boundaries [S1]. It differs from standard parallel Marching Cubes by resolving topological discontinuities and holes via boundary-consistent slab processing, and differs from Histogram Pyramid or Atomic Counter approaches by specializing counting/compaction for tightly coupled extraction, rendering, and engine integration [S1]. Unlike implicit isosurface raycasting, this method generates explicit geometric assets (vertices/normals) suitable for mesh-based interaction tools and OBJ export [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $V$ defined on a uniform Cartesian grid with dimensions $N_x \times N_y \times N_z$ (samples), where cell indices range $0 \le i \le N_x-2$, $0 \le j \le N_y-2$, $0 \le k \le N_z-2$. An isovalue $\tau \in \mathbb{R}$.
*   **Output:** A Vertex Buffer Object (VBO) containing two arrays: `pos` (positions) and `nrm` (normals). The total capacity is $N$ vertices, where $N$ is the exact sum of vertices generated by all cells. Each triangle writes 3 consecutive vertices. For each vertex, `pos` stores a 3D vector and `nrm` stores a 3D vector.

**Data Structures:**
*   **Lookup Tables:** Uses the standard `edgeTable` (256-entry bitmask) and `triangleTable` (256x16 edge index array) as defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) [S1, Parent].
*   **Slab Configuration:** The z-axis is partitioned into slabs of thickness $S$. The set of valid cells for slab $s$ is defined as the closed interval $\mathcal{K}_s = \{k \mid k_{begin}(s) \le k \le k_{end}(s)\}$. This inclusive indexing ensures that the $k+1$ corner access required by Marching Cubes remains valid at slab boundaries [S1].
*   **Count/Offset Arrays:** Per-slab arrays `countss` and `offsets` indexed by the linear cell index $\ell = lin(i,j,k)$ [S1].

**Parameters:**
*   **Slab Thickness ($S$):** Recommended range $[48, 96]$ for a $512^3$ grid [S1].
*   **Boundary Handling:** If $N_z-1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z-2$ [S1].

**Formulas:**
*   **Linear Index:** $\text{lin}(x,y,z) = (z N_y + y) N_x + x$ [S1].
*   **Case Index:** $c = \text{caseIndex}(V, i, j, k, \tau)$, computed by comparing the 8 corner samples of cell $(i,j,k)$ against $\tau$ [S1, Parent].
*   **Vertex Count:** $n_{ijk} = \text{numVerts}[c]$ [S1].
*   **Edge Interpolation:** For active edges, intersection points are computed via linear interpolation:
    $$ \mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1) $$
    where $V_1, V_2$ are scalar values at corners $\mathbf{p}_1, \mathbf{p}_2$ [S1, Parent].
*   **Face Normal:** Enforced counterclockwise winding:
    $$ \mathbf{n} = \frac{(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)}{\|(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)\|} $$
    This normal is duplicated at all three vertices for flat shading [S1].

**Algorithm Steps:**
1.  **Pass 1 (Classify/Scan):**
    *   Initialize global vertex count $N \leftarrow 0$.
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ with $k \in \mathcal{K}_s$:
            *   Compute $c \leftarrow \text{caseIndex}(V, i, j, k, \tau)$.
            *   Compute $n_{ijk} \leftarrow \text{numVerts}[c]$.
            *   Store $n_{ijk}$ in `countss[lin(i,j,k)]`.
        *   Compute exclusive prefix-sum (scan) over `countss` to generate `offsets[ℓ]` for each cell $\ell$ in the slab [S1].
        *   Compute slab-level total $N_s \leftarrow \text{offsets}[\text{last}] + \text{countss}[\text{last}]$ [S1].
        *   Set slab base offset $\text{base}[s] \leftarrow N$.
        *   Update global count $N \leftarrow N + N_s$.
    *   Allocate an interoperable VBO with exactly $N$ vertex capacity [S1].

2.  **Pass 2 (Generate):**
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ with $k \in \mathcal{K}_s$:
            *   Compute $c \leftarrow \text{caseIndex}(V, i, j, k, \tau)$ [S1].
            *   If $\text{numVerts}[c] \neq 0$:
                *   Compute edge vertices: $\text{edgeVerts}[0..11] \leftarrow \text{edge\_lerp}(V, i, j, k, \tau)$ [S1].
                *   Compute destination address: $\text{dst} \leftarrow \text{base}[s] + \text{offsets}[\text{lin}(i,j,k)]$ [S1].
                *   Iterate through the triangle edge list $\text{triTable}[c][t..t+2]$ for $t$ from $0$ to $\text{numVerts}[c]-1$ with step 3 [S1].
                *   If any edge index $e_0, e_1, e_2$ is $< 0$, break the loop [S1].
                *   Retrieve vertices $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ from $\text{edgeVerts}$ [S1].
                *   Compute face normal $\mathbf{n}$ [S1].
                *   Write positions $\{\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2\}$ to $\text{pos}[\text{dst}:\text{dst}+2]$ and normals $\{\mathbf{n}, \mathbf{n}, \mathbf{n}\}$ to $\text{nrm}[\text{dst}:\text{dst}+2]$ [S1].
                *   Increment $\text{dst} \leftarrow \text{dst} + 3$ [S1].

    slab_bases = []

    nrm = [None] * (global_N * 3)
    
    # Pass 2: Generate

        base_offset = slab_bases[s_idx]
        
        for k in range(k_start, k_end + 1):
            for j in range(Ny - 1):

                    n_verts = num_verts[c]

                        p1 = edge_verts[e1]
                        p2 = edge_verts[e2]

                        v2 = p2 - p0
                        normal = normalize(cross(v1, v2))

                        nrm[(dst+1)*3 : (dst+2)*3] = normal
                        nrm[(dst+2)*3 : (dst+3)*3] = normal
                        
                        dst += 3
                        t += 3
                        
    return pos, nrm

**Edge Cases and Pitfalls:**
*   **Boundary Cracks:** Using inclusive slab indexing ($\mathcal{K}_s$ includes $k_{end}(s)$) ensures that the $k+1$ corner access required by MC is valid at slab boundaries, eliminating omissions/duplications and cracks caused by off-by-one inconsistencies [S1].
*   **Empty Triangles:** The algorithm checks if edge indices $e_0, e_1, e_2$ are $< 0$. If so, it breaks the triangle loop, handling cases where the triangle table entry indicates no triangle for that specific triplet [S1].
*   **Memory Limits:** The method is limited to volumes that fit within the memory of a single GPU [S1].

## Operating characteristics
*   **Time Complexity:** $O(M)$ for both passes, where $M = (N_x-1)(N_y-1)(N_z-1)$ is the number of cells [S1].
*   **Memory Complexity:** The additional storage consists of the slab-local count and offset arrays. The output buffers are allocated according to the exact number of generated vertices $N$ [S1].
*   **Performance:** On electromagnetic-potential fields with resolutions up to $512^3$, the method generates approximately 42.81 million vertices in 44.7 ms, uses less than 11 GB of GPU memory, and renders the resulting geometry at 28.6 FPS [S1].
*   **Strengths:** Prevents buffer overruns and slab-boundary omissions; enables zero-copy streaming to OpenGL via CUDA-OpenGL interoperability; suitable for explicit mesh-based interaction and engine integration (e.g., Unreal Engine) [S1].
*   **Limitations:** Less suitable for sharp-feature preservation than methods such as Dual Contouring or MC33; requires the entire volume to fit in GPU memory; explicit geometry generation is more memory-intensive than implicit raycasting for single-isovalue visualization [S1].
*   **When to Use:** When explicit geometric assets are required for mesh-based interaction, OBJ export, or integration into game engines like Unreal Engine, and when large scalar grids need crack-free, capacity-safe extraction [S1].
*   **When Not to Use:** When memory is constrained and the volume does not fit in a single GPU, or when only direct volume rendering/implicit visualization is needed without explicit mesh export [S1].

## Background
*   **Origin:** The method was presented in a paper titled "Visual tools for 3D plasma simulation: GPU-based isosurface extraction..." [S1].
*   **History and Development:** It was developed to address the challenges of visualizing fusion-plasma simulation data, which involves extremely large-scale interactions and data volumes reaching hundreds of gigabytes to several terabytes [S1]. The method combines inclusive slab partitioning with a two-pass counting and exact allocation strategy to prevent slab-boundary omissions and output-buffer overflow [S1].
*   **Usage:** It is used in a standalone renderer and integrated into Unreal Engine for volume rendering, explicit-isosurface inspection, particle-trajectory visualization, clipping, and VR-based spatial exploration [S1]. It is also used in the proposed framework for visualizing 3D plasma simulation data (fusion-plasma electromagnetic potential) on GPUs with CUDA-OpenGL interoperability [S1].
