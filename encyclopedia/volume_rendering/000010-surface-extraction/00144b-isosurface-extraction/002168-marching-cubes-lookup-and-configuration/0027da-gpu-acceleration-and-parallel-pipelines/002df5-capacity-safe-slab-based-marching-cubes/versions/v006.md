# Capacity-safe slab-based Marching Cubes

Also called: Capacity-safe slab-based isososurface extraction, Capacity-safe slab-based isosurface extraction pipeline, Capacity-safe tiled Marching Cubes, Two-pass tiled Marching Cubes, inclusive slab partitioning with exact allocation, slab-based two-pass GPU isosurface extraction

## Overview
This method is a GPU-accelerated isosurface extraction pipeline that partitions the z-axis into slabs and uses a two-pass counting/exact allocation strategy to prevent output-buffer overflow and eliminate boundary cracks in large scalar grids [S1]. It differs from standard parallel Marching Cubes by using inclusive slab indexing to ensure topological consistency at slab boundaries, and differs from histogram-pyramid or atomic-counter approaches by computing exact vertex counts per slab to allocate buffers precisely, avoiding the need for dynamic resizing or large over-allocations [S1].

## How it works
**Inputs and Outputs**
*   **Input**: A 3D scalar volume $V$ defined on a grid of dimensions $N_x \times N_y \times N_z$, and a scalar isovalue $\tau$.
*   **Output**: A Vertex Buffer Object (VBO) containing two arrays: `pos` (positions) and `nrm` (normals). The total capacity is $N$ vertices, where $N$ is the exact sum of vertices generated by all cells. Each triangle writes 3 consecutive vertices. For each vertex, `pos` stores a 3D vector and `nrm` stores a 3D vector [S1].

**Data Structures**
*   **Slab Definition**: The z-axis is partitioned into slabs of thickness $S$. For slab $s$, the set of valid cell indices $k$ is the closed interval $\mathcal{K}_s = \{k \mid k_{begin}(s) \le k \le k_{end}(s)\}$ [S1].
*   **Linear Index**: The linear index for a cell $(x,y,z)$ is computed as:
    $$ \text{lin}(x,y,z) = (z N_y + y) N_x + x $$
    where $N_x, N_y, N_z$ are the grid dimensions [S1].
*   **Count Arrays**: Per-slab arrays `countss` and `offsets` store the number of vertices per cell and the exclusive prefix-sum offsets, respectively, indexed by the linear cell index [S1].

**Parameters**
*   **Slab Thickness ($S$)**: Recommended range $[48, 96]$ for a $512^3$ grid [S1].
*   **Boundary Handling**: If $N_z - 1$ is not divisible by $S$, the final slab is processed as a partial slab without padding, with its upper cell index clamped to $N_z - 2$ [S1].

**Algorithm Steps**
The method consists of two passes: Classification/Scan and Generation.

1.  **Pass 1 (Classify/Scan)**:
    *   Initialize global vertex count $N \leftarrow 0$.
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ where $k \in \mathcal{K}_s$:
            *   Compute case index $c = \text{caseIndex}(V, i, j, k, \tau)$ using the logic from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).
            *   Retrieve vertex count $n_{ijk} = \text{numVerts}[c]$.
            *   Store $n_{ijk}$ in `countss[lin(i,j,k)]`.
        *   Compute exclusive prefix-sum (scan) over `countss` to generate `offsets[ℓ]` for each cell $\ell$ in the slab [S1].
        *   Calculate slab-level total $N_s = \text{offsets}[\text{last}] + \text{countss}[\text{last}]$.
        *   Set slab base offset $\text{base}[s] \leftarrow N$.
        *   Update global count $N \leftarrow N + N_s$.
    *   Allocate an interoperable VBO with exactly $N$ vertex capacity [S1].

2.  **Pass 2 (Generate)**:
    *   For each slab $s$:
        *   For each cell $(i,j,k)$ where $k \in \mathcal{K}_s$:
            *   Compute $c = \text{caseIndex}(V, i, j, k, \tau)$.
            *   If $\text{numVerts}[c] \neq 0$:
                *   Compute edge intersection vertices $\text{edgeVerts}[0..11]$ via linear interpolation:
                    $$ \mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1) $$
                    where $\mathbf{p}_1, \mathbf{p}_2$ are corner positions and $V_1, V_2$ are scalar values [S1, Parent].
                *   Determine destination address: $\text{dst} = \text{base}[s] + \text{offsets}[\text{lin}(i,j,k)]$.
                *   Iterate through the triangle edge list $\text{triTable}[c][t..t+2]$ for $t$ from $0$ to $\text{numVerts}[c]-1$ with step 3:
                    *   Let $(e_0, e_1, e_2) = \text{triTable}[c][t..t+2]$.
                    *   If any edge index $e_0, e_1, e_2 < 0$, break the loop [S1].
                    *   Retrieve vertices $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ from $\text{edgeVerts}[e_0], \text{edgeVerts}[e_1], \text{edgeVerts}[e_2]$.
                    *   Compute face normal $\mathbf{n}$ to enforce counterclockwise winding:
                        $$ \mathbf{n} = \frac{(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)}{\|(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)\|} $$
                    *   Write positions $\{\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2\}$ to `pos[dst:dst+2]` and normals $\{\mathbf{n}, \mathbf{n}, \mathbf{n}\}$ to `nrm[dst:dst+2]`.
                    *   Increment $\text{dst} \leftarrow \text{dst} + 3$.

**Pseudocode**
```python
def capacity_safe_slab_marching_cubes(V, Nx, Ny, Nz, tau, S):
    # Pass 1: Classify and Scan
    global_N = 0
    slab_bases = []
    
    # Determine slab ranges
    num_slabs = (Nz - 1 + S - 1) // S # Ceiling division for number of slabs needed to cover Nz-1 cells
    
    for s in range(num_slabs):
        k_begin = s * S
        k_end = min(k_begin + S - 1, Nz - 2) # Clamp to valid cell index Nz-2
        
        # Initialize slab-local count array
        # Size depends on number of cells in x and y dimensions for this slab
        # Cells are (i, j, k) where 0<=i<=Nx-2, 0<=j<=Ny-2, k_begin<=k<=k_end
        num_cells_in_slab = (Nx - 1) * (Ny - 1) * (k_end - k_begin + 1)
        countss = [0] * num_cells_in_slab
        offsets = [0] * num_cells_in_slab
        
        cell_idx = 0
        for k in range(k_begin, k_end + 1):
            for j in range(Ny - 1):
                for i in range(Nx - 1):
                    # Compute case index using standard MC logic
                    c = compute_case_index(V, i, j, k, tau)
                    n_ijk = num_verts_table[c] # From Marching Cubes Lookup and Configuration
                    countss[cell_idx] = n_ijk
                    cell_idx += 1
        
        # Exclusive prefix sum (scan)
        if num_cells_in_slab > 0:
            current_sum = 0
            for idx in range(num_cells_in_slab):
                offsets[idx] = current_sum
                current_sum += countss[idx]
            
            N_s = current_sum
        else:
            N_s = 0
            
        slab_bases.append(global_N)
        global_N += N_s
        
    # Allocate VBO with capacity global_N
    # pos and nrm arrays of size global_N * 3 (assuming float3)
    pos = [None] * (global_N * 3)
    nrm = [None] * (global_N * 3)
    
    # Pass 2: Generate
    for s in range(num_slabs):
        k_begin = s * S
        k_end = min(k_begin + S - 1, Nz - 2)
        
        base_s = slab_bases[s]
        cell_idx = 0
        
        for k in range(k_begin, k_end + 1):
            for j in range(Ny - 1):
                for i in range(Nx - 1):
                    c = compute_case_index(V, i, j, k, tau)
                    n_ijk = num_verts_table[c]
                    
                    if n_ijk != 0:
                        # Compute edge vertices
                        edge_verts = compute_edge_intersections(V, i, j, k, tau)
                        
                        dst = base_s + offsets[cell_idx]
                        
                        # Iterate through triangle table
                        t = 0
                        while t < n_ijk:
                            e0 = tri_table[c][t]
                            e1 = tri_table[c][t+1]
                            e2 = tri_table[c][t+2]
                            
                            if e0 < 0 or e1 < 0 or e2 < 0:
                                break
                                
                            p0 = edge_verts[e0]
                            p1 = edge_verts[e1]
                            p2 = edge_verts[e2]
                            
                            # Compute normal
                            v1 = p1 - p0
                            v2 = p2 - p0
                            cross = cross_product(v1, v2)
                            norm = normalize(cross)
                            
                            # Write to VBO
                            # pos[dst:dst+2] means indices dst, dst+1, dst+2
                            pos[dst] = p0
                            pos[dst+1] = p1
                            pos[dst+2] = p2
                            
                            nrm[dst] = norm
                            nrm[dst+1] = norm
                            nrm[dst+2] = norm
                            
                            dst += 3
                            t += 3
                            
                    cell_idx += 1
                    
    return pos, nrm

def compute_case_index(V, i, j, k, tau):
    # Standard MC case index calculation
    # V is accessed at vertices (i,j,k) to (i+1,j+1,k+1)
    # Bit i is set if V(vertex_i) < tau (or > tau depending on convention)
    # This matches the parent article's definition
    case = 0
    for v in range(8):
        # Map v to (dx, dy, dz)
        dx = v & 1
        dy = (v >> 1) & 1
        dz = (v >> 2) & 1
        val = V[i+dx][j+dy][k+dz]
        if val < tau: # Convention from parent article
            case |= (1 << v)
    return case

def compute_edge_intersections(V, i, j, k, tau):
    # Returns array of 12 vertices
    # Edge 0: (0,0,0) to (1,0,0)
    # ... standard interpolation for all 12 edges
    verts = [None] * 12
    # Helper to interpolate edge between vertex indices v1_idx and v2_idx
    def lerp(v1_idx, v2_idx):
        p1 = get_vertex_pos(v1_idx, i, j, k)
        p2 = get_vertex_pos(v2_idx, i, j, k)
        v1 = V[v1_idx]
        v2 = V[v2_idx]
        t = (tau - v1) / (v2 - v1)
        return p1 + t * (p2 - p1)
        
    # Edge definitions from parent article
    # Bottom face (z=0): e0=(0,1), e1=(1,2), e2=(2,3), e3=(3,0)
    # Top face (z=1): e4=(4,5), e5=(5,6), e6=(6,7), e7=(7,4)
    # Vertical edges: e8=(0,4), e9=(1,5), e10=(2,6), e11=(3,7)
    # Vertex indices 0..7 relative to cell (i,j,k)
    
    verts[0] = lerp(0, 1)
    verts[1] = lerp(1, 2)
    verts[2] = lerp(2, 3)
    verts[3] = lerp(3, 0)
    verts[4] = lerp(4, 5)
    verts[5] = lerp(5, 6)
    verts[6] = lerp(6, 7)
    verts[7] = lerp(7, 4)
    verts[8] = lerp(0, 4)
    verts[9] = lerp(1, 5)
    verts[10] = lerp(2, 6)
    verts[11] = lerp(3, 7)
    
    return verts

def get_vertex_pos(v_idx, i, j, k):
    dx = v_idx & 1
    dy = (v_idx >> 1) & 1
    dz = (v_idx >> 2) & 1
    return (i + dx, j + dy, k + dz)

def cross_product(a, b):
    return (a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0])

def normalize(v):
    mag = sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    if mag == 0: return (0,0,0)
    return (v[0]/mag, v[1]/mag, v[2]/mag)
```

## Operating characteristics
*   **Time Complexity**: $O(M)$ for both passes, where $M = (N_x-1)(N_y-1)(N_z-1)$ is the number of cells [S1].
*   **Memory Complexity**: The additional storage consists of slab-local count and offset arrays. The output buffers are allocated exactly to the number of generated vertices $N$ [S1].
*   **Performance**: On electromagnetic-potential fields with resolutions up to $512^3$, the method generates approximately 42.81 million vertices in 44.7 ms, uses less than 11 GB of GPU memory, and renders the resulting geometry at 28.6 FPS [S1].
*   **Strengths**: Prevents buffer overruns by exact allocation; eliminates boundary cracks via inclusive slab indexing; supports zero-copy streaming to OpenGL via CUDA-OpenGL interoperability [S1].
*   **Limitations**: Limited to volumes that fit within the memory of a single GPU; less suitable for sharp-feature preservation than methods like Dual Contouring or MC33 [S1].

## Background
The method was introduced in a framework for visualizing 3D plasma simulation data (fusion-plasma electromagnetic potential) on GPUs [S1]. It addresses the challenges of large-scale data volumes (hundreds of gigabytes to terabytes) and the need for explicit geometric assets for mesh-based interaction tools and engine integration (e.g., Unreal Engine) [S1]. It builds on the principles of [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) and [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) [S1, Parent].
