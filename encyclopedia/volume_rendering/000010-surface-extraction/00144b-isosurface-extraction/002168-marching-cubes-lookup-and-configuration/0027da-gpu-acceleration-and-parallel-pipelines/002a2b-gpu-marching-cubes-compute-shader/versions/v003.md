# GPU Marching Cubes (Compute Shader)

Also called: Marching Cubes GPU, Unity Marching Cubes Compute Shader

## Overview
This method implements the Marching Cubes isosurface extraction algorithm using a GPU compute shader, specifically designed for integration within the Unity engine [S1, unofficial]. It solves the problem of real-time surface generation from volumetric data by offloading the geometric processing of voxel cubes to the GPU [S1, unofficial]. Unlike CPU-based implementations, this approach leverages parallel dispatch to process voxels simultaneously, though it relies on a CPU-generated density field for input [S1, unofficial]. It is distinguished by its use of an append buffer for variable-length triangle output and indirect draw calls, making it suitable for dynamic scenes where the number of triangles per frame varies [S1, unofficial].

## How it works
The implementation builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md). Specifically, it utilizes the precomputed `edgeTable` and `triangleTable` to determine geometry for each voxel [S1, S4, S8, S12, unofficial].

### Inputs and Outputs
*   **Input**: A 3D texture (`Texture3D`) containing scalar field values (density) at grid vertices. The resolution is defined by the integer `Resolution` [S1, unofficial].
*   **Output**: A structured buffer (`AppendStructuredBuffer<Triangle>`) containing the generated triangles, which are subsequently rendered [S1, unofficial].

### Data Structures
The following buffers and structures are used:

1.  **`triangleRW` (AppendStructuredBuffer)**: Stores the output triangles.
    *   **Layout**: Each element is a `Triangle` struct.
    *   **`Triangle` struct**: Contains 3 `Vertex` structs.
    *   **`Vertex` struct**: Contains `float3 vPosition` and `float3 vNormal` [S1, unofficial].
    *   **Size**: Each vertex is 12 bytes (3 floats * 4 bytes). Each triangle is 3 vertices * 12 bytes = 36 bytes. The buffer is allocated with a capacity sufficient for the maximum possible triangles [S1, unofficial].

2.  **`appendVertexBuffer` (ComputeBuffer)**: The underlying append buffer for `triangleRW`.
    *   **Capacity**: $(Resolution - 1) \times (Resolution - 1) \times (Resolution - 1) \times 5$ elements [S1, unofficial].

3.  **`argBuffer` (ComputeBuffer)**: Indirect argument buffer for drawing.
    *   **Layout**: 4 integers (16 bytes) [S1, unofficial].
    *   **Content**: `{vertex_count, instance_count, start_vertex, start_instance}` [S1, unofficial].

4.  **Lookup Tables**:
    *   `edgeTable`: 256-entry array of hex values, defining edge intersections [S1, S4, unofficial].
    *   `triTable`: 256x16 array of integers, defining triangle indices for each configuration, padded with -1 [S1, S8, unofficial].

### Parameters
*   **`_gridSize`**: Integer, set to `Resolution` [S1, unofficial].
*   **`_isoLevel`**: Float, default `0.5f` [S1, unofficial].

### Numbered Steps

1.  **Initialization**:
    *   Find the compute shader kernel: `kernelMC = MarchingCubesCS.FindKernel("MarchingCubes")` [S1, unofficial].
    *   Allocate `appendVertexBuffer` with capacity $(Resolution - 1)^3 \times 5$ elements of size 18 bytes (as per source note, though struct implies 36 bytes) [S1, unofficial].
    *   Allocate `argBuffer` with 4 integers [S1, unofficial].
    *   Set shader parameters: `_gridSize` to `Resolution`, `_isoLevel` to `0.5f` [S1, unofficial].
    *   Bind `appendVertexBuffer` to the `triangleRW` buffer in the kernel [S1, unofficial].

2.  **Per-Frame Execution**:
    *   Reset the append buffer counter: `appendVertexBuffer.SetCounterValue(0)` to clear previous frame's output [S1, unofficial].
    *   Dispatch the compute shader: `Dispatch(kernelMC, Resolution/8, Resolution/8, Resolution/8)` [S1, unofficial]. This assumes a thread group size of $8 \times 8 \times 8$ [S1, unofficial].
    *   Retrieve vertex count: Initialize `argBuffer` with `{0, 1, 0, 0}`. Use `ComputeBuffer.CopyCount` to copy the append buffer's current count to `argBuffer[0]` [S1, unofficial].
    *   Read back the count from `argBuffer` to the CPU [S1, unofficial].
    *   Adjust draw arguments: Calculate total index count as `vertex_count * 3` (assuming 3 indices per triangle). Update `argBuffer[0]` with this value [S1, unofficial].
    *   Draw procedural geometry: In the render pass, set the material, bind `appendVertexBuffer` to the shader's triangle buffer, set the model matrix, and call `Graphics.DrawProceduralIndirect` with `MeshTopology.Triangles` and `argBuffer` [S1, unofficial].

class MarchingCubesGPU:
    def __init__(self, resolution, compute_shader, material):
        self.resolution = resolution
        self.compute_shader = compute_shader
        self.material = material
        
        # Find kernel
        self.kernel_id = compute_shader.FindKernel("MarchingCubes")
        
        # Allocate buffers
        # Note: Source specifies element size 18 bytes, but struct implies 36 bytes.
        # We follow the source's explicit allocation formula for capacity.
        max_triangles = (resolution - 1) ** 3 * 5
        element_size_bytes = 18 # As per source note [S1, unofficial]
        self.append_buffer = ComputeBuffer(max_triangles, element_size_bytes, ComputeBufferType.Append)
        
        self.arg_buffer = ComputeBuffer(4, sizeof(int), ComputeBufferType.IndirectArguments)
        
        # Set shader parameters
        compute_shader.SetInt("_gridSize", resolution)
        compute_shader.SetFloat("_isoLevel", 0.5f)
        
        # Bind buffer to shader
        compute_shader.SetBuffer(self.kernel_id, "triangleRW", self.append_buffer)

    def update(self, density_texture):
        # Bind density texture to shader
        self.compute_shader.SetTexture(self.kernel_id, "DensityTexture", density_texture)
        
        # Reset append buffer counter
        self.append_buffer.SetCounterValue(0)
        
        # Dispatch compute shader
        # Thread group size is assumed to be 8x8x8 based on source [S1, unofficial]
        group_count_x = (self.resolution + 7) // 8
        group_count_y = (self.resolution + 7) // 8
        group_count_z = (self.resolution + 7) // 8
        self.compute_shader.Dispatch(self.kernel_id, group_count_x, group_count_y, group_count_z)
        
        # Get vertex count
        # Initialize argBuffer with {0, 1, 0, 0}
        arg_data = [0, 1, 0, 0]
        self.arg_buffer.SetData(arg_data)
        
        # Copy count from append buffer to argBuffer
        ComputeBuffer.CopyCount(self.append_buffer, self.arg_buffer, 0)
        
        # Read back count
        arg_data = self.arg_buffer.GetData()
        vertex_count = arg_data[0]
        
        # Adjust draw arguments
        # Multiply vertex count by 3 to get index count
        index_count = vertex_count * 3
        arg_data[0] = index_count
        self.arg_buffer.SetData(arg_data)
        
        # Draw
        self.material.SetPass(0)
        Graphics.DrawProceduralIndirect(self.material, Bounds, MeshTopology.Triangles, self.arg_buffer)

### Edge Cases and Pitfalls
*   **Hardware Compatibility**: The implementation assumes DX11 hardware. Mobile support is uncertain and likely unsupported [S1, unofficial].
*   **Density Field Bottleneck**: The example generates the density field on the CPU. For real-time applications, this should be replaced with a `RenderTexture` generated on the GPU [S1, unofficial].
*   **Buffer Overflow**: The append buffer capacity is fixed. If the number of triangles exceeds the allocated capacity, data will be lost or cause errors. The capacity is estimated as $(Resolution - 1)^3 \times 5$ [S1, unofficial].
*   **Lighting**: The default shader uses a barebone diffuse lighting model. Custom shaders are required for advanced rendering [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of voxels, as each voxel is processed in parallel by a thread group [S1, unofficial].
*   **Memory Complexity**: $O(N)$ for the input texture and output buffer. The output buffer size is fixed based on the maximum possible triangles [S1, unofficial].
*   **Performance**: Performance depends on GPU compute capabilities and the resolution of the volume. The use of append buffers allows for variable output size but may introduce synchronization overhead [S1, unofficial].
*   **Strengths**: Real-time extraction, parallel processing, integration with Unity's rendering pipeline [S1, unofficial].
*   **Limitations**: CPU-bound density generation in the example, fixed buffer capacity, DX11 dependency [S1, unofficial].
*   **When to use**: Real-time volumetric visualization in Unity applications on DX11-capable hardware [S1, unofficial].
*   **When not to use**: Mobile platforms (likely), applications requiring dynamic density generation on the GPU without additional setup, or when higher precision is needed than the fixed buffer capacity allows [S1, unofficial].
