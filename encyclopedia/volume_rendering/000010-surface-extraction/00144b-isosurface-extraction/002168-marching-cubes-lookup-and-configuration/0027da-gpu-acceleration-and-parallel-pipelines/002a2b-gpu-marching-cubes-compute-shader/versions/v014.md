# GPU Marching Cubes (Compute Shader)
Also called: Marching Cubes GPU, Unity Marching Cubes Compute Shader

## Overview
This method extracts an isosurface from a 3D scalar field by executing the Marching Cubes algorithm within a GPU compute shader, utilizing append buffers for dynamic triangle generation and indirect draw calls for rendering [S1, unofficial]. It differs from CPU-based implementations by offloading the voxel traversal and topology lookup to the GPU, and from other GPU variants by relying on a barebone append buffer structure rather than hierarchical data structures like histogram pyramids [S1, unofficial]. The approach is designed for real-time applications within the Unity engine, assuming DX11 hardware support [S1, unofficial].

## How it works
The implementation processes a 3D grid of voxels in parallel. Each thread group handles a sub-volume of the grid, determining the intersection case for each voxel, looking up the corresponding triangle configuration, computing vertex positions and normals, and appending the resulting geometry to a global buffer.

### Inputs and Outputs
**Inputs:**
*   `DensityTexture`: A `Texture3D` containing the scalar field values. The source example uses `TextureFormat.RFloat` [S1, unofficial].
*   `Resolution`: An integer defining the dimensions of the cubic grid ($N \times N \times N$) [S1, unofficial].
*   `isoLevel`: The scalar threshold for surface extraction. Default value is $0.5$ [S1, unofficial].
*   `edgeTable`: A static constant array of 256 integers (hex values), representing the 12-bit bitmask for edge intersections [S1, unofficial].
*   `triTable`: A static constant 2D array of size $256 \times 16$, storing triangle indices for each of the 256 cases, terminated by `-1` [S1, unofficial].

**Outputs:**
*   `appendVertexBuffer`: An `AppendStructuredBuffer` containing the generated triangles. Each element is a `Triangle` struct, which contains 3 `Vertex` structs. Each `Vertex` struct contains `float3 vPosition` and `float3 vNormal` [S1, unofficial].

### Data Structures
1.  **Append Vertex Buffer**:
    *   Type: `ComputeBufferType.Append`
    *   Size: $(Resolution - 1)^3 \times 5$ elements. This capacity assumes the maximum of 5 triangles per voxel [S1, unofficial].
    *   Element Size: $18$ bytes ($3 \text{ vertices} \times 2 \text{ attributes} \times 3 \text{ floats/attribute}$) [S1, unofficial].
    *   Layout: Sequential storage of `Triangle` structs.

2.  **Argument Buffer**:
    *   Type: `ComputeBufferType.IndirectArguments`
    *   Size: 4 integers (16 bytes) [S1, unofficial].
    *   Layout: `[vertexCount, instanceCount, startVertex, startInstance]`. Used to pass the dynamic triangle count from the compute shader to the draw call [S1, unofficial].

### Algorithm Steps
1.  **Initialization**:
    *   Find the compute shader kernel named `"MarchingCubes"` [S1, unofficial].
    *   Allocate `appendVertexBuffer` with capacity $(Resolution - 1)^3 \times 5$ elements of 18 bytes each [S1, unofficial].
    *   Allocate `argBuffer` with 4 integers [S1, unofficial].
    *   Set shader parameters: `_gridSize` to `Resolution`, `_isoLevel` to the threshold value [S1, unofficial].
    *   Bind `appendVertexBuffer` to the `"triangleRW"` buffer in the kernel [S1, unofficial].

2.  **Dispatch**:
    *   Reset the append buffer counter to 0 using `SetCounterValue(0)` to clear previous frame output [S1, unofficial].
    *   Dispatch the compute shader with thread groups of size $(Resolution/8, Resolution/8, Resolution/8)$. This implies 8x8x8 threads per group [S1, unofficial].

3.  **Compute Shader Kernel Execution** (per voxel):
    *   Calculate global voxel coordinates $(x, y, z)$ from thread IDs.
    *   Sample the 8 corner values of the voxel from `DensityTexture`.
    *   Compute the case index $C$ by comparing corner values against `isoLevel`. If $V(v_i) < isoLevel$, set bit $i$ of $C$ to 1 [G].
    *   Check `edgeTable[C]`. If 0, no intersection; exit.
    *   Retrieve triangle indices from `triTable[C]`. Iterate through triplets until `-1` is encountered.
    *   For each intersected edge, compute the intersection point using linear interpolation:
        $$ P = V_1 + \frac{isoLevel - V_1}{V_2 - V_1} (V_2 - V_1) $$
        where $V_1, V_2$ are the scalar values at the edge endpoints [G].
    *   Compute the vertex normal by sampling the gradient of the scalar field at the intersection point [S1, unofficial].
    *   Append the resulting triangle (3 vertices with position and normal) to `triangleRW` [S1, unofficial].

4.  **Readback and Rendering**:
    *   Initialize `argBuffer` with `{0, 1, 0, 0}` [S1, unofficial].
    *   Use `ComputeBuffer.CopyCount` to copy the current count of `appendVertexBuffer` to `argBuffer[0]` [S1, unofficial].
    *   Read back the count from `argBuffer` to the CPU [S1, unofficial].
    *   Update `argBuffer[0]` by multiplying the vertex count by 3 (indices per triangle) [S1, unofficial].
    *   Bind `appendVertexBuffer` to the `"triangles"` buffer in the rendering shader [S1, unofficial].
    *   Call `Graphics.DrawProceduralIndirect` with `MeshTopology.Triangles` and the `argBuffer` [S1, unofficial].

### Parameters

### Edge Cases and Pitfalls
*   **Hardware Support**: The implementation assumes DX11 hardware. Mobile support is uncertain and likely unsupported [S1, unofficial].
*   **Density Field Generation**: The example generates the density field on the CPU, which is a bottleneck. For real applications, `Texture3D` should be replaced with `RenderTexture` [S1, unofficial].
*   **Ambiguity**: The standard lookup tables are used. Cases 46, 47, 98, 99, 210, 213, 214, 215 may exhibit topological ambiguity if adjacent voxels resolve them differently, potentially causing cracks [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md).
*   **Buffer Capacity**: The append buffer is sized for the maximum possible triangles per voxel (5). If the grid is sparse, this may waste memory, but it ensures no overflow [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N^3)$ for a grid of size $N$, as each voxel is processed by a thread.
*   **Memory Complexity**: $O(N^3)$ for the input texture and output buffer capacity. The output buffer is pre-allocated to the worst-case scenario (5 triangles per voxel) [S1, unofficial].
*   **Performance**: Performance is limited by the density field generation on the CPU in the provided example. GPU compute performance is generally high for dense volumes but depends on the complexity of the normal calculation and texture sampling [S1, unofficial].
*   **Strengths**: Simple implementation, leverages GPU parallelism, suitable for real-time rendering in Unity [S1, unofficial].
*   **Limitations**: CPU-bound density generation in the example, potential for high memory usage due to pre-allocated append buffer, limited to DX11 hardware [S1, unofficial].
*   **When to Use**: Real-time isosurface extraction in Unity for dense volumes where CPU generation is acceptable or replaced by GPU-generated textures.
*   **When Not to Use**: Sparse volumes where memory efficiency is critical (use Histogram Pyramid), or non-DX11 hardware.
