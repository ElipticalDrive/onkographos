# GPU Marching Cubes (Compute Shader)

Also called: Marching Cubes GPU, Unity Marching Cubes Compute Shader

## Overview
This method implements the Marching Cubes isosurface extraction algorithm using a GPU compute shader, typically within a framework like Unity, to parallelize the processing of volumetric data. It solves the bottleneck of CPU-based surface extraction by distributing voxel processing across thousands of GPU threads. It differs from CPU implementations by leveraging parallel execution models and append buffers for dynamic output management, and from other GPU variants (like Histogram Pyramid approaches) by using a simpler atomic counter or fixed-capacity append buffer strategy for triangle storage [S1, unofficial].

## How it works
The implementation processes a 3D scalar field (density texture) to generate a triangle mesh representing an isosurface. It relies on the precomputed lookup tables (`edgeTable` and `triangleTable`) defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).

### Inputs and Outputs
*   **Input:** A 3D texture (`Texture3D`) containing scalar density values. In production, this is often a `RenderTexture` generated on the GPU; the example uses a CPU-generated `Texture3D` [S1, unofficial].
*   **Output:** A structured buffer of triangles, which is then rendered using indirect draw calls.

### Data Structures
The implementation uses specific buffer types and layouts:

1.  **Density Texture:** A `Texture3D` of size `Resolution x Resolution x Resolution`. Format is typically `RFloat` (single channel, 32-bit float) [S1, unofficial].
2.  **Append Vertex Buffer (`appendVertexBuffer`):**
    *   Type: `ComputeBufferType.Append`.
    *   Size: `(Resolution - 1) * (Resolution - 1) * (Resolution - 1) * 5` elements.
    *   Element Size: `sizeof(float) * 18` bytes (18 bytes per element).
    *   Content: Each element stores 3 triangles (15 vertices). Each vertex has 3 floats for position and 3 floats for normal (6 floats total). $3 \times 6 = 18$ floats [S1, unofficial].
3.  **Argument Buffer (`argBuffer`):**
    *   Type: `ComputeBufferType.IndirectArguments`.
    *   Size: 4 integers (16 bytes).
    *   Content: Stores draw call arguments: `[vertexCount, instanceCount, startVertex, startInstance]` [S1, unofficial].
4.  **Structured Buffer (`triangleRW`):**
    *   Type: `RWStructuredBuffer<Triangle>`.
    *   Layout: `Triangle` struct contains 3 `Vertex` structs. `Vertex` struct contains `float3 vPosition` and `float3 vNormal` [S1, unofficial].

### Lookup Tables
The compute shader contains static constant arrays for the Marching Cubes logic:
*   `edgeTable`: 256-entry array of hex values (uint32), defining which edges are intersected for each of the 256 cube configurations [S1, unofficial].
*   `triTable`: 256x16 array of integers. Each row defines up to 5 triangles (15 indices) for a given configuration, padded with -1 [S1, unofficial].

### Algorithm Steps

1.  **Initialization:**
    *   Find the compute shader kernel: `kernelID = shader.FindKernel("MarchingCubes")` [S1, unofficial].
    *   Allocate `appendVertexBuffer` with capacity `(Resolution-1)^3 * 5` elements [S1, unofficial].
    *   Allocate `argBuffer` with 4 integers [S1, unofficial].
    *   Set shader parameters: `_gridSize` to `Resolution`, `_isoLevel` to the threshold (default 0.5f) [S1, unofficial].
    *   Bind `appendVertexBuffer` to the `triangleRW` buffer in the kernel [S1, unofficial].

2.  **Reset Output:**
    *   Before each frame, reset the append buffer counter to 0: `appendVertexBuffer.SetCounterValue(0)` [S1, unofficial].

3.  **Dispatch Compute Shader:**
    *   Dispatch the kernel with thread groups sized `(Resolution/8, Resolution/8, Resolution/8)`. This implies 8x8x8 threads per group [S1, unofficial].
    *   Each thread processes one voxel cube.

4.  **Compute Shader Kernel Logic (Per Voxel):**
    *   **Thread Indexing:** Calculate global thread ID $(i, j, k)$ from `DispatchThreadID`.
    *   **Case Index Calculation:** Sample the 8 vertices of the voxel cube from the density texture. Determine the 8-bit case index $C$. If vertex value $V < I$ (isosurface level), set bit $i$ to 1; otherwise 0. The bit assignment must match the vertex ordering in the lookup tables [S1, Lookup, unofficial].
    *   **Early Exit:** If $C=0$ or $C=255$, terminate the thread (no triangles) [S1, Parent, unofficial].
    *   **Edge Intersection:** Use `edgeTable[C]` to identify intersected edges. Calculate intersection points via linear interpolation of scalar values at edge endpoints. Calculate normals by interpolating the gradient (e.g., using central differences) at the intersection point [S1, Parent, unofficial].
    *   **Triangle Generation:** Use `triTable[C]` to retrieve the triangle indices.
    *   **Output:** Write the generated triangles to the `triangleRW` structured buffer. The write offset is determined by an atomic counter or append buffer mechanism [S1, Parent, unofficial].

5.  **Retrieve Vertex Count:**
    *   Initialize `argBuffer` with `{0, 1, 0, 0}` [S1, unofficial].
    *   Use `ComputeBuffer.CopyCount` to copy the append buffer's current count to `argBuffer[0]` [S1, unofficial].
    *   Read back the count from `argBuffer` on the CPU [S1, unofficial].

6.  **Adjust Draw Arguments:**
    *   Multiply the vertex count (`args[0]`) by 3 to get the total index count for triangles (assuming 3 indices per triangle) [S1, unofficial].
    *   Update `argBuffer` with the new arguments [S1, unofficial].

7.  **Render:**
    *   In the rendering pass, set the material pass.
    *   Bind `appendVertexBuffer` to the `triangles` buffer in the shader.
    *   Set the model matrix.
    *   Call `Graphics.DrawProceduralIndirect` with `MeshTopology.Triangles` and the `argBuffer` [S1, unofficial].

# Compute Shader Kernel: MarchingCubes
# Inputs: Texture3D density, int gridSize, float isoLevel, RWStructuredBuffer<Triangle> triangleRW
# Outputs: triangleRW (appended)

struct Vertex {
    float3 position;
    float3 normal;
};

struct Triangle {
    Vertex v[3];
};

// Static lookup tables from Marching Cubes Lookup and Configuration
// edgeTable[256], triTable[256][16]

void MarchingCubesKernel(uint3 id : SV_DispatchThreadID) {
    int x = id.x;
    int y = id.y;
    int z = id.z;

    // Boundary check: only process voxels within the grid
    if (x >= gridSize - 1 || y >= gridSize - 1 || z >= gridSize - 1) {
        return;
    }

    // 1. Sample 8 vertices of the voxel
    float v[8];
    v[0] = density.SampleLevel(sampler, float3(x, y, z), 0).r;
    v[1] = density.SampleLevel(sampler, float3(x+1, y, z), 0).r;
    v[2] = density.SampleLevel(sampler, float3(x+1, y+1, z), 0).r;
    v[3] = density.SampleLevel(sampler, float3(x, y+1, z), 0).r;
    v[4] = density.SampleLevel(sampler, float3(x, y, z+1), 0).r;
    v[5] = density.SampleLevel(sampler, float3(x+1, y, z+1), 0).r;
    v[6] = density.SampleLevel(sampler, float3(x+1, y+1, z+1), 0).r;
    v[7] = density.SampleLevel(sampler, float3(x, y+1, z+1), 0).r;

    // 2. Calculate Case Index C
    int C = 0;
    for (int i = 0; i < 8; i++) {
        if (v[i] < isoLevel) {
            C |= (1 << i);
        }
    }

    // 3. Early Exit
    if (C == 0 || C == 255) {
        return;
    }

    // 4. Get Edge Intersections and Normals
    // Helper function to get intersection point and normal on an edge
    // Edge indices are defined by edgeTable[C]
    // This part requires implementing the standard MC edge lookup and linear interpolation
    // For brevity, assuming a helper function exists that returns (point, normal) for a given edge index
    // and voxel coordinates
    
    // 5. Generate Triangles
    // triTable[C] contains up to 5 triangles, each with 3 edge indices
    // Pad with -1 if fewer than 5 triangles
    
    int numTriangles = 0;
    int triangleIndices[16];
    for (int i = 0; i < 16; i++) {
        triangleIndices[i] = triTable[C][i];
        if (triangleIndices[i] == -1) break;
        if (i % 3 == 2) numTriangles++;
    }

    // 6. Write to Append Buffer
    // Use atomic counter to get unique offset for this thread's output
    uint offset = atomicAdd(triangleRWCounter, numTriangles);
    
    for (int t = 0; t < numTriangles; t++) {
        int e0 = triangleIndices[t * 3];
        int e1 = triangleIndices[t * 3 + 1];
        int e2 = triangleIndices[t * 3 + 2];
        
        // Get intersection points and normals for edges e0, e1, e2
        // This requires mapping edge index to vertex indices and interpolating
        Vertex v0 = GetVertexOnEdge(e0, x, y, z, v);
        Vertex v1 = GetVertexOnEdge(e1, x, y, z, v);
        Vertex v2 = GetVertexOnEdge(e2, x, y, z, v);
        
        triangleRW[offset + t] = Triangle({v0, v1, v2});
    }
}

### Parameters
*   **Resolution:** The grid resolution for the marching cubes volume. Used to calculate buffer sizes and dispatch threads [S1, unofficial].
*   **isoLevel:** The scalar threshold value for isosurface extraction. Default value is 0.5f [S1, unofficial].

### Edge Cases and Pitfalls
*   **Hardware Support:** The implementation assumes DX11 hardware. Mobile support is uncertain and may not work [S1, unofficial].
*   **Density Field Generation:** The example generates the density field on the CPU, which is a bottleneck. For real applications, `Texture3D` should be replaced with `RenderTexture` generated on the GPU [S1, unofficial].
*   **Buffer Capacity:** The append buffer is pre-allocated with a maximum capacity. If the scene complexity exceeds this, triangles will be dropped. The capacity is `(Resolution-1)^3 * 5` triangles [S1, unofficial].
*   **Lighting:** The default shader uses a barebone diffuse lighting model. It should be replaced with a custom shader for better visual results [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each voxel is processed by one thread.
*   **Memory Complexity:** $O(N)$ for the density texture and output buffers. The output buffer is pre-allocated with a fixed maximum size, which can lead to memory waste if the isosurface is sparse [S1, unofficial].
*   **Performance:** Performance scales with GPU compute power and resolution. The use of append buffers avoids the need for a two-pass counting algorithm but may involve atomic contention if many threads write simultaneously [S1, Parent, unofficial].
*   **Strengths:** Simple implementation, leverages GPU parallelism, easy to integrate with Unity's rendering pipeline.
*   **Limitations:** Fixed buffer size may limit complexity, CPU density generation is slow, mobile support is not guaranteed [S1, unofficial].

## Background
This implementation is an unofficial GPU-based Marching Cubes algorithm for Unity, developed by Pavel Kouril. It was created with Unity 5.6 and may work on older versions. It relies on the algorithm and lookup tables by Paul Bourke and gradient normals calculation from an Angelfire page. The implementation was debugged and troubleshooted by Vilém Otte [S1, unofficial].
