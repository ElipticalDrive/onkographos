# GPU Marching Cubes (Compute Shader)
Also called: Marching Cubes GPU, Unity Marching Cubes Compute Shader

## Overview
This method extracts an isosurface from a 3D scalar field by mapping the Marching Cubes algorithm to a GPU compute shader, processing voxels in parallel [S1, unofficial]. It differs from CPU-based implementations by leveraging hardware parallelism for voxel classification and triangle generation, and from geometry shader approaches by using explicit compute kernels with append buffers for output management [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) for the topological logic and [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) for the dispatch and data access patterns.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field (density) stored in a `Texture3D` or `RWTexture3D`, and a scalar threshold (`isoLevel`) [S1, unofficial].
*   **Output:** A structured buffer (`AppendStructuredBuffer`) containing the generated triangles, where each triangle consists of 3 vertices, and each vertex contains a position (`float3`) and a normal (`float3`) [S1, unofficial].

**Data Structures:**
1.  **Lookup Tables:** The `edgeTable` (256-entry bitmask) and `triangleTable` (256x16 integer array) are embedded as static constant arrays in the compute shader code [S1, unofficial].
2.  **Append Buffer:** A `ComputeBuffer` of type `Append` with capacity $(N-1)^3 \times 5$ elements, where $N$ is the grid resolution. Each element is 18 bytes (3 vertices $\times$ 2 attributes $\times$ 3 floats/attribute) [S1, unofficial].
3.  **Indirect Argument Buffer:** A `ComputeBuffer` of type `IndirectArguments` with 4 integers (16 bytes) to store draw call parameters [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Find the compute shader kernel named "MarchingCubes" [S1, unofficial].
2.  **Buffer Allocation:** Allocate `appendVertexBuffer` with size $(N-1)^3 \times 5 \times 18$ bytes and `argBuffer` with 4 integers [S1, unofficial].
3.  **Parameter Setup:** Set `_gridSize` to $N$ and `_isoLevel` to the threshold (default 0.5) [S1, unofficial]. Bind the density texture and the `appendVertexBuffer` to the shader's `triangleRW` buffer [S1, unofficial].
4.  **Counter Reset:** Reset the append buffer counter to 0 before each frame to clear previous output [S1, unofficial].
5.  **Dispatch:** Launch the compute shader with thread groups of size $(N/8, N/8, N/8)$, implying 8 threads per dimension per group [S1, unofficial].
6.  **Count Retrieval:** Copy the append buffer's current count to `argBuffer` at offset 0 using `ComputeBuffer.CopyCount` [S1, unofficial].
7.  **Argument Adjustment:** Read the vertex count from `argBuffer`, multiply by 3 to get the index count (assuming 3 indices per triangle), and update `argBuffer` [S1, unofficial].
8.  **Rendering:** Call `Graphics.DrawProceduralIndirect` with `MeshTopology.Triangles` and the `argBuffer`, binding the `appendVertexBuffer` to the shader's `triangles` buffer [S1, unofficial].

**Pseudocode:**
```python
# Compute Shader Kernel: MarchingCubes
# Inputs: Texture3D density, float isoLevel, int gridSize
# Output: AppendStructuredBuffer<float3> triangleRW (interleaved pos/normal)

kernel void MarchingCubes(uint3 id : SV_DispatchThreadID) {
    // 1. Boundary Check
    if (id.x >= gridSize - 1 || id.y >= gridSize - 1 || id.z >= gridSize - 1) {
        return;
    }

    // 2. Sample 8 Corners
    float3 cornerPos = float3(id.x, id.y, id.z);
    float values[8];
    for (int i = 0; i < 8; i++) {
        int3 offset = int3((i & 1), (i & 2) >> 1, (i & 4) >> 2);
        values[i] = density.SampleLevel(sampler_linear, cornerPos + offset, 0).r;
    }

    // 3. Determine Cube Index
    int cubeIndex = 0;
    for (int i = 0; i < 8; i++) {
        if (values[i] < isoLevel) {
            cubeIndex |= (1 << i);
        }
    }

    // 4. Lookup Edges and Triangles
    // edgeTable and triTable are static const arrays defined in the shader
    int edgeMask = edgeTable[cubeIndex];
    int* triIndices = &triangleTable[cubeIndex * 16];

    // 5. Generate Triangles
    int triangleCount = 0;
    for (int i = 0; i < 16; i += 3) {
        int e1 = triIndices[i];
        int e2 = triIndices[i + 1];
        int e3 = triIndices[i + 2];
        if (e1 == -1) break; // End of triangle list

        // Interpolate vertices for each edge
        float3 v1 = interpolateEdge(cornerPos, values, e1, gridSize);
        float3 v2 = interpolateEdge(cornerPos, values, e2, gridSize);
        float3 v3 = interpolateEdge(cornerPos, values, e3, gridSize);

        // Calculate normals (gradient approximation)
        float3 n1 = calculateNormal(density, v1, gridSize);
        float3 n2 = calculateNormal(density, v2, gridSize);
        float3 n3 = calculateNormal(density, v3, gridSize);

        // Write to Append Buffer
        // Atomically increment counter and write 3 vertices (6 floats each)
        uint index = triangleRW.Append();
        triangleRW[index * 6 + 0] = v1.x;
        triangleRW[index * 6 + 1] = v1.y;
        triangleRW[index * 6 + 2] = v1.z;
        triangleRW[index * 6 + 3] = n1.x;
        triangleRW[index * 6 + 4] = n1.y;
        triangleRW[index * 6 + 5] = n1.z;

        index = triangleRW.Append();
        triangleRW[index * 6 + 0] = v2.x;
        triangleRW[index * 6 + 1] = v2.y;
        triangleRW[index * 6 + 2] = v2.z;
        triangleRW[index * 6 + 3] = n2.x;
        triangleRW[index * 6 + 4] = n2.y;
        triangleRW[index * 6 + 5] = n2.z;

        index = triangleRW.Append();
        triangleRW[index * 6 + 0] = v3.x;
        triangleRW[index * 6 + 1] = v3.y;
        triangleRW[index * 6 + 2] = v3.z;
        triangleRW[index * 6 + 3] = n3.x;
        triangleRW[index * 6 + 4] = n3.y;
        triangleRW[index * 6 + 5] = n3.z;
    }
}

float3 interpolateEdge(float3 cornerPos, float values[8], int edgeIndex, int gridSize) {
    // Map edge index to two corner indices
    int c1, c2;
    // ... mapping logic based on standard MC edge table ...
    float v1 = values[c1];
    float v2 = values[c2];
    float t = (isoLevel - v1) / (v2 - v1);
    float3 p1 = cornerPos + float3((c1 & 1), (c1 & 2) >> 1, (c1 & 4) >> 2);
    float3 p2 = cornerPos + float3((c2 & 1), (c2 & 2) >> 1, (c2 & 4) >> 2);
    return lerp(p1, p2, t);
}

float3 calculateNormal(Texture3D density, float3 pos, int gridSize) {
    float eps = 1.0 / gridSize;
    float dx = density.SampleLevel(sampler_linear, pos + float3(eps, 0, 0), 0).r - density.SampleLevel(sampler_linear, pos - float3(eps, 0, 0), 0).r;
    float dy = density.SampleLevel(sampler_linear, pos + float3(0, eps, 0), 0).r - density.SampleLevel(sampler_linear, pos - float3(0, eps, 0), 0).r;
    float dz = density.SampleLevel(sampler_linear, pos + float3(0, 0, eps), 0).r - density.SampleLevel(sampler_linear, pos - float3(0, 0, eps), 0).r;
    return normalize(float3(dx, dy, dz));
}
```

**Parameters:**
*   `Resolution` ($N$): The grid resolution. Used for buffer sizing and dispatch. Typical values depend on memory capacity [S1, unofficial].
*   `isoLevel`: The scalar threshold. Default is 0.5 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Handling:** Threads with coordinates $\ge N-1$ must return immediately to prevent out-of-bounds access [S1, unofficial].
*   **Hardware Support:** The implementation assumes DX11 hardware; mobile support is uncertain [S1, unofficial].
*   **CPU Bottleneck:** If the density field is generated on the CPU, it may become a bottleneck. Using `RenderTexture` instead of `Texture3D` is recommended for real-time applications [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N^3)$ for processing all voxels, where $N$ is the resolution. The parallel nature allows near-linear scaling with the number of GPU cores [S1, unofficial].
*   **Memory Complexity:** $O(N^3)$ for the input texture and $O(N^3)$ for the output buffer (worst-case 5 triangles per voxel) [S1, unofficial].
*   **Performance:** Performance depends heavily on the GPU's compute capability and the efficiency of the append buffer implementation. Indirect rendering minimizes CPU-GPU synchronization overhead [S1, unofficial].
*   **Strengths:** High parallelism, flexible output management via append buffers, and integration with modern graphics APIs [S1, unofficial].
*   **Limitations:** Requires DX11 or higher; potential memory pressure from large output buffers; CPU density generation can be a bottleneck if not offloaded [S1, unofficial].
*   **When to Use:** Real-time isosurface extraction in Unity or similar engines where CPU processing is insufficient [S1, unofficial].
*   **When Not to Use:** Mobile devices with uncertain DX11 support or scenes requiring extremely high resolution where memory bandwidth becomes a bottleneck [S1, unofficial].

## Background
This implementation was developed for Unity 5.6, leveraging the Marching Cubes algorithm by Paul Bourke and gradient-based normal calculation techniques [S1, unofficial]. It adapts the classic algorithm for GPU compute shaders, using append buffers for dynamic triangle emission and indirect rendering for efficient draw calls [S1, unofficial].
