# GPU Marching Cubes (Compute Shader)

Also called: Marching Cubes GPU, Unity Marching Cubes Compute Shader

## Overview
This method implements the Marching Cubes isosurface extraction algorithm using a GPU compute shader, specifically designed for integration within the Unity engine environment [S1, unofficial]. It solves the problem of real-time surface extraction from volumetric data by offloading the voxel processing and triangle generation to the GPU, while relying on the CPU for density field generation in its basic form [S1, unofficial]. It differs from CPU-based immediate mode implementations by utilizing parallel thread execution and append buffers for variable-length output, and from histogram-pyramid approaches by using atomic counters or fixed-capacity append buffers for output buffering [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D texture (`Texture3D`) containing scalar density values, a grid resolution integer, and an isosurface threshold value.
*   **Output:** A structured buffer (`AppendStructuredBuffer`) containing a list of triangles, where each triangle consists of three vertices. Each vertex contains a position (`float3`) and a normal (`float3`) [S1, unofficial].

**Data Structures:**
1.  **Lookup Tables:** Static constant arrays within the compute shader.
    *   `edgeTable`: 256-entry array of hex values (bitmasks) [S1, unofficial].
    *   `triTable`: 256x16 array of integers. Each row defines up to 5 triangles (15 indices) for a given cube configuration, padded with -1 [S1, unofficial].
2.  **Append Buffer (`appendVertexBuffer`):** A `ComputeBuffer` of type `Append`. Size is calculated as $(Resolution - 1)^3 \times 5$ elements. Each element is 18 bytes ($3 \text{ vertices} \times 6 \text{ floats}$) [S1, unofficial].
3.  **Argument Buffer (`argBuffer`):** A `ComputeBuffer` of type `IndirectArguments`. Size is 4 integers (16 bytes) [S1, unofficial].

**Parameters:**
*   `_gridSize`: Integer, set to `Resolution` [S1, unofficial].
*   `_isoLevel`: Float, default 0.5f [S1, unofficial].

**Algorithm Steps:**

1.  **Kernel Initialization:** Locate the compute shader kernel named "MarchingCubes" using `FindKernel("MarchingCubes")` [S1, unofficial].
2.  **Buffer Allocation:**
    *   Allocate `appendVertexBuffer` with capacity $(Resolution - 1)^3 \times 5$ elements of 18 bytes each [S1, unofficial].
    *   Allocate `argBuffer` with 4 integers [S1, unofficial].
3.  **Parameter Setup:** Set `_gridSize` to `Resolution` and `_isoLevel` to the desired threshold. Bind the density texture and the `appendVertexBuffer` to the shader's "triangleRW" buffer [S1, unofficial].
4.  **Counter Reset:** Call `SetCounterValue(0)` on `appendVertexBuffer` to clear previous frame's output [S1, unofficial].
5.  **Dispatch:** Dispatch the compute shader kernel with thread groups of size $(Resolution/8, Resolution/8, Resolution/8)$. This implies an 8x8x8 thread group size [S1, unofficial].
6.  **Count Retrieval:**
    *   Initialize `argBuffer` with `{0, 1, 0, 0}` [S1, unofficial].
    *   Use `ComputeBuffer.CopyCount` to copy the append buffer's current element count to `argBuffer` at offset 0 [S1, unofficial].
    *   Read back the count from `argBuffer` [S1, unofficial].
7.  **Argument Adjustment:** Multiply the retrieved vertex count (`args[0]`) by 3 to get the total index count for triangles (assuming 3 indices per triangle). Update `argBuffer` with the new arguments [S1, unofficial].
8.  **Rendering:** In the rendering pass (`OnRenderObject`), set the material pass, bind `appendVertexBuffer` to the shader's "triangles" buffer, set the model matrix, and call `Graphics.DrawProceduralIndirect` with `MeshTopology.Triangles` and the `argBuffer` [S1, unofficial].

**Pseudocode:**

```python
# Compute Shader Kernel: MarchingCubes
# Inputs: Texture3D Density, int gridSize, float isoLevel
# Output: AppendStructuredBuffer<Triangle> triangleRW

struct Vertex {
    float3 vPosition;
    float3 vNormal;
};

struct Triangle {
    Vertex v[3];
};

[numthreads(8, 8, 8)]
void MarchingCubes(uint3 id : SV_DispatchThreadID) {
    // 1. Calculate voxel coordinate
    uint x = id.x;
    uint y = id.y;
    uint z = id.z;

    // Boundary check: Marching Cubes operates on cubes defined by grid points.
    // If grid size is N, valid cube indices are 0 to N-2.
    if (x >= gridSize - 1 || y >= gridSize - 1 || z >= gridSize - 1) {
        return;
    }

    // 2. Sample the 8 vertices of the current voxel cube
    // Note: Exact sampling coordinates depend on texture coordinate mapping.
    // Assuming normalized coordinates or direct index access.
    float v0 = Density.SampleLevel(sampler, float3(x, y, z), 0).r;
    float v1 = Density.SampleLevel(sampler, float3(x + 1, y, z), 0).r;
    float v2 = Density.SampleLevel(sampler, float3(x + 1, y + 1, z), 0).r;
    float v3 = Density.SampleLevel(sampler, float3(x, y + 1, z), 0).r;
    float v4 = Density.SampleLevel(sampler, float3(x, y, z + 1), 0).r;
    float v5 = Density.SampleLevel(sampler, float3(x + 1, y, z + 1), 0).r;
    float v6 = Density.SampleLevel(sampler, float3(x + 1, y + 1, z + 1), 0).r;
    float v7 = Density.SampleLevel(sampler, float3(x, y + 1, z + 1), 0).r;

    // 3. Compute Case Index C
    float iso = isoLevel;
    uint C = 0;
    if (v0 < iso) C |= 1 << 0;
    if (v1 < iso) C |= 1 << 1;
    if (v2 < iso) C |= 1 << 2;
    if (v3 < iso) C |= 1 << 3;
    if (v4 < iso) C |= 1 << 4;
    if (v5 < iso) C |= 1 << 5;
    if (v6 < iso) C |= 1 << 6;
    if (v7 < iso) C |= 1 << 7;

    // 4. Lookup Triangle Configuration
    // edgeTable[C] gives the bitmask of intersected edges
    // triTable[C] gives the list of triangle indices
    uint edgeMask = edgeTable[C];
    int* triIndices = triTable[C];

    // 5. Generate Triangles
    // Iterate through the triangle list until -1 is encountered
    int idx = 0;
    while (triIndices[idx] != -1) {
        // Extract 3 edge indices for the current triangle
        int e0 = triIndices[idx];
        int e1 = triIndices[idx + 1];
        int e2 = triIndices[idx + 2];
        idx += 3;

        // Calculate intersection points on the edges
        // Helper function to interpolate vertex position and normal on an edge
        Vertex p0 = InterpolateEdge(v0, v1, v2, v3, v4, v5, v6, v7, e0, iso);
        Vertex p1 = InterpolateEdge(v0, v1, v2, v3, v4, v5, v6, v7, e1, iso);
        Vertex p2 = InterpolateEdge(v0, v1, v2, v3, v4, v5, v6, v7, e2, iso);

        // 6. Append to Output Buffer
        // Use atomic counter to get unique index for append buffer
        uint appendIndex = InterlockedAdd(triangleRWCounter, 1) - 1;
        
        // Write triangle to structured buffer
        triangleRW[appendIndex] = Triangle({p0, p1, p2});
    }
}

// Helper: Interpolate vertex on edge
Vertex InterpolateEdge(float v0, float v1, float v2, float v3, float v4, float v5, float v6, float v7, int edgeIndex, float iso) {
    // Map edge index (0-11) to vertex pairs and interpolate
    // This requires mapping the 12 edges of a cube to the 8 vertices
    // Example for edge 0 (v0-v1):
    if (edgeIndex == 0) {
        float t = (iso - v0) / (v1 - v0);
        float3 pos = lerp(float3(0,0,0), float3(1,0,0), t);
        float3 normal = normalize(float3(0,0,0)); // Placeholder for gradient calc
        return Vertex(pos, normal);
    }
    // ... (Other 11 edges handled similarly)
    // Note: Normal calculation requires gradient of the density field
    return Vertex(float3(0,0,0), float3(0,0,0));
}
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** The algorithm operates on cubes defined by grid points. If the grid resolution is $N$, valid cube indices range from $0$ to $N-2$. Threads outside this range must return early [S1, unofficial].
*   **Precision:** Floating-point interpolation may introduce small artifacts. Gradient-based normal calculation is recommended for smooth shading [S1, unofficial].
*   **Hardware Dependency:** The implementation assumes DX11 hardware support. Mobile support is uncertain [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N^3)$ for a grid of resolution $N$, as each voxel is processed by one thread group.
*   **Memory Complexity:** $O(N^3)$ for the input density texture and $O(N^3)$ for the output buffer (worst-case 5 triangles per voxel) [S1, unofficial].
*   **Performance:** Depends heavily on GPU compute capabilities and the efficiency of the append buffer implementation. Atomic counters can cause contention; histogram-based approaches may offer better scalability [S1, unofficial].
*   **Strengths:** Real-time extraction on GPU; leverages Unity's compute shader infrastructure.
*   **Limitations:** CPU-bound density generation in the basic implementation; fixed maximum output size requires careful buffer sizing; DX11 dependency [S1, unofficial].

## Background
This implementation was developed for Unity 5.6, building upon the original Marching Cubes algorithm and lookup tables by Paul Bourke [S1, unofficial]. It incorporates gradient-based normal calculations from an advanced Marching Cubes resource [S1, unofficial]. The code is hosted on GitHub as an unofficial repository [S1, unofficial].
