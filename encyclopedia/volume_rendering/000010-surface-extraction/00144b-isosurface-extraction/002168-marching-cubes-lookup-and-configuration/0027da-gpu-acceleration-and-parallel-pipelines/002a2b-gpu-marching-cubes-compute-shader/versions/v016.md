# GPU Marching Cubes (Compute Shader)
Also called: Marching Cubes GPU, Unity Marching Cubes Compute Shader

## Overview
A GPU-based implementation of the Marching Cubes algorithm that extracts an isosurface from a 3D scalar density field using a compute shader [S1, unofficial]. It differs from CPU-based immediate mode implementations by leveraging massive parallelism for voxel processing and hardware-supported append buffers for dynamic geometry output [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) for topology determination and [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) for execution structure.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar density field (typically a `Texture3D` or `RenderTexture`) of resolution $N \times N \times N$.
*   **Output:** A structured buffer containing vertices (position and normal) and indices forming triangles.
*   **Parameters:** Grid resolution ($N$), isovalue threshold ($\tau$, default 0.5).

**Data Structures:**
1.  **Lookup Tables:** Static constant arrays in the shader.
    *   `edgeTable[256]`: 12-bit bitmask indicating which edges are intersected.
    *   `triTable[256][16]`: Defines up to 5 triangles (15 indices) per case, padded with -1.
2.  **Append Buffer (`appendVertexBuffer`):** A `ComputeBuffer` of type `Append`.
    *   Size: $(N-1)^3 \times 5$ elements.
    *   Element size: 18 bytes (3 vertices $\times$ 6 floats per vertex).
    *   Layout: Each element is a `Triangle` struct containing 3 `Vertex` structs. Each `Vertex` has `float3 vPosition` and `float3 vNormal`.
3.  **Indirect Argument Buffer (`argBuffer`):** A `ComputeBuffer` of type `IndirectArguments`.
    *   Size: 4 integers (16 bytes).
    *   Layout: `[vertexCount, instanceCount, startVertex, startInstance]`.

**Algorithm Steps:**
1.  **Initialization:**
    *   Find the compute shader kernel named "MarchingCubes" [S1, unofficial].
    *   Allocate `appendVertexBuffer` with capacity $(N-1)^3 \times 5$ [S1, unofficial].
    *   Allocate `argBuffer` with 4 integers [S1, unofficial].
    *   Set shader parameters: `_gridSize` to $N$, `_isoLevel` to $\tau$ [S1, unofficial].
    *   Bind the density texture and `appendVertexBuffer` to the shader [S1, unofficial].
2.  **Dispatch:**
    *   Reset the append buffer counter to 0 [S1, unofficial].
    *   Dispatch the kernel with thread groups of size $(N/8, N/8, N/8)$, implying 8x8x8 threads per group [S1, unofficial].
3.  **Per-Voxel Processing (Compute Shader):**
    *   Each thread maps to a voxel coordinate $(i, j, k)$ within $[0, N-2]^3$.
    *   **Boundary Check:** If $(i, j, k)$ is out of bounds, terminate [Parent].
    *   **Case Index:** Sample the 8 corner values of the voxel from the density texture. Compute the 8-bit case index $C$ by comparing each value to $\tau$ [Parent].
    *   **Early Exit:** If $C=0$ or $C=255$, terminate [Parent].
    *   **Edge Intersections:** Use `edgeTable[C]` to identify intersected edges. Calculate intersection points using linear interpolation between corner values.
    *   **Triangle Generation:** Use `triTable[C]` to determine vertex connectivity. Generate up to 5 triangles.
    *   **Normal Calculation:** Compute vertex normals using gradient estimation (e.g., central differences) [S1, unofficial].
    *   **Output:** Append the generated triangles to `appendVertexBuffer` using atomic operations or hardware append buffer semantics [S1, unofficial].
4.  **Result Retrieval:**
    *   Copy the append buffer count to `argBuffer[0]` using `ComputeBuffer.CopyCount` [S1, unofficial].
    *   Update `argBuffer[0]` by multiplying the count by 3 (indices per triangle) [S1, unofficial].
5.  **Rendering:**
    *   Draw procedural geometry using `Graphics.DrawProceduralIndirect` with `MeshTopology.Triangles` and `argBuffer` [S1, unofficial].

**Pseudocode:**
```python
# Compute Shader Kernel: MarchingCubes
[numthreads(8, 8, 8)]
void MarchingCubes(uint3 id : SV_DispatchThreadID) {
    int3 voxel = id.xyz;
    int gridSize = _gridSize;
    float isoLevel = _isoLevel;

    // Boundary check
    if (voxel.x >= gridSize - 1 || voxel.y >= gridSize - 1 || voxel.z >= gridSize - 1) {
        return;
    }

    // Sample 8 corners
    float values[8];
    for (int i = 0; i < 8; i++) {
        int3 corner = voxel + _cornerOffsets[i];
        values[i] = DensityTexture.SampleLevel(sampler, corner / float3(gridSize, gridSize, gridSize), 0).r;
    }

    // Compute case index
    int caseIndex = 0;
    for (int i = 0; i < 8; i++) {
        if (values[i] < isoLevel) {
            caseIndex |= (1 << i);
        }
    }

    // Early exit for empty or full cubes
    if (caseIndex == 0 || caseIndex == 255) {
        return;
    }

    // Get edge intersections
    float3 edgePoints[12];
    int edgeMask = edgeTable[caseIndex];
    int edgeCount = 0;
    for (int i = 0; i < 12; i++) {
        if ((edgeMask & (1 << i)) != 0) {
            edgePoints[edgeCount++] = GetEdgeIntersection(voxel, i, values, isoLevel);
        }
    }

    // Generate triangles
    int* triTable = triTable[caseIndex];
    int idx = 0;
    while (triTable[idx] != -1) {
        int v1 = triTable[idx++];
        int v2 = triTable[idx++];
        int v3 = triTable[idx++];

        float3 p1 = edgePoints[v1];
        float3 p2 = edgePoints[v2];
        float3 p3 = edgePoints[v3];

        float3 n1 = ComputeNormal(p1, voxel, 0); // Placeholder for normal calculation
        float3 n2 = ComputeNormal(p2, voxel, 1);
        float3 n3 = ComputeNormal(p3, voxel, 2);

        // Append triangle to buffer
        // Note: Actual append logic depends on GPU API (e.g., AppendStructuredBuffer in HLSL)
        AppendTriangle(p1, n1, p2, n2, p3, n3);
    }
}

float3 GetEdgeIntersection(int3 voxel, int edgeIndex, float values[8], float isoLevel) {
    // Determine the two vertices defining the edge
    int3 v1, v2;
    GetEdgeVertices(edgeIndex, v1, v2);
    
    float val1 = values[v1.x + v1.y * _gridSize + v1.z * _gridSize * _gridSize];
    float val2 = values[v2.x + v2.y * _gridSize + v2.z * _gridSize * _gridSize];
    
    // Linear interpolation
    float t = (isoLevel - val1) / (val2 - val1);
    return lerp(voxel + v1, voxel + v2, t);
}
```

## Operating characteristics
*   **Time Complexity:** $O(N^3)$ for processing, where $N$ is the grid resolution. Each voxel is processed by one thread group.
*   **Memory Complexity:** $O(N^3)$ for the density texture and output buffer. The output buffer is pre-allocated to $(N-1)^3 \times 5$ triangles to avoid reallocation [S1, unofficial].
*   **Performance:** Depends heavily on GPU hardware and driver support for append buffers and indirect draw calls. Requires DX11 hardware [S1, unofficial].
*   **Strengths:** High throughput for large volumes; dynamic geometry generation; suitable for real-time applications if density field generation is optimized (e.g., using `RenderTexture` instead of CPU-generated `Texture3D`) [S1, unofficial].
*   **Limitations:** Ambiguity handling is not addressed in this basic implementation, potentially causing cracks in adjacent voxels for cases 46, 47, 98, 99, 210, 213, 214, 215 [Lookup Table and Ambiguity Handling]. Mobile support is uncertain [S1, unofficial]. CPU-based density field generation can be a bottleneck [S1, unofficial].

## Background
This implementation was developed for Unity 5.6, leveraging the engine's compute shader and procedural rendering capabilities [S1, unofficial]. It is based on the original Marching Cubes algorithm by Paul Bourke and uses gradient-based normal calculation [S1, unofficial]. The approach demonstrates a practical application of GPU acceleration for surface extraction in a game engine context.
