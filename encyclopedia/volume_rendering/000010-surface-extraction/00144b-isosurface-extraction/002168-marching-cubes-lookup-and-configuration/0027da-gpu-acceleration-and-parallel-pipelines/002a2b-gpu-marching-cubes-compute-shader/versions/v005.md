# GPU Marching Cubes (Compute Shader)

Also called: Marching Cubes GPU, Unity Marching Cubes Compute Shader

## Overview
This method implements the Marching Cubes isosurface extraction algorithm using a GPU compute shader, designed for integration within the Unity engine environment [S1, unofficial]. It solves the problem of real-time surface generation from volumetric scalar fields by offloading the voxel classification and triangle emission steps to the GPU [S1, unofficial]. It differs from CPU-based implementations by leveraging parallel thread execution for voxel processing and uses an append buffer strategy to handle variable output sizes without pre-allocation of exact triangle counts [S1, unofficial]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) for the geometric logic and [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) for the dispatch model.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field represented as a `Texture3D` of resolution $N \times N \times N$ [S1, unofficial].
*   **Input:** An isovalue threshold $\tau$ (default 0.5) [S1, unofficial].
*   **Output:** A structured buffer containing a list of triangles, where each triangle consists of 3 vertices, and each vertex contains a position (`float3`) and a normal (`float3`) [S1, unofficial].

**Data Structures:**
1.  **Lookup Tables:** Static constant arrays in the compute shader.
    *   `edgeTable`: 256-entry array of hex values (bitmasks) [S1, unofficial].
    *   `triTable`: 256x16 integer array. Each row defines up to 5 triangles (15 indices) for a specific cube configuration, padded with -1 [S1, unofficial].
2.  **Append Buffer (`appendVertexBuffer`):** A `ComputeBuffer` of type `Append` [S1, unofficial].
    *   Capacity: $(N-1) \times (N-1) \times (N-1) \times 5$ elements [S1, unofficial].
    *   Element Size: 18 bytes (3 triangles $\times$ 3 vertices $\times$ 2 floats per vertex attribute $\times$ 2 attributes? No, 3 verts $\times$ 6 floats = 18 bytes) [S1, unofficial].
    *   Note: The source notes a discrepancy in the byte calculation description but confirms the 18-byte size [S1, unofficial].
3.  **Argument Buffer (`argBuffer`):** A `ComputeBuffer` of type `IndirectArguments` [S1, unofficial].
    *   Size: 4 integers (16 bytes) [S1, unofficial].
    *   Usage: Stores draw call arguments (vertex count, instance count, start vertex/index, start instance) [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Find the compute shader kernel named "MarchingCubes" [S1, unofficial].
    *   Allocate `appendVertexBuffer` with the calculated capacity [S1, unofficial].
    *   Allocate `argBuffer` with 4 integers [S1, unofficial].
    *   Set shader parameters: `_gridSize` to $N$ and `_isoLevel` to $\tau$ [S1, unofficial].
    *   Bind `appendVertexBuffer` to the "triangleRW" buffer in the kernel [S1, unofficial].

2.  **Reset:**
    *   Reset the append buffer counter to 0 before each frame to clear previous output [S1, unofficial].

3.  **Dispatch:**
    *   Dispatch the compute shader kernel with thread groups of size $(N/8, N/8, N/8)$ [S1, unofficial]. This implies 8x8x8 threads per group [S1, unofficial].
    *   Each thread processes one voxel cube [Parent, unofficial].

4.  **Compute Shader Execution (Per Voxel):**
    *   **Voxel Classification:** Sample the scalar field values at the 8 corners of the assigned voxel. Compute the 8-bit case index (selector) by comparing these values against $\tau$ [Parent, unofficial].
    *   **Edge Interpolation:** For active edges (where `edgeTable[selector]` has the corresponding bit set), compute the intersection point using linear interpolation:
        $$
        \mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1)
        $$
        where $V_1, V_2$ are the scalar values at corners $\mathbf{p}_1, \mathbf{p}_2$ [Parent, unofficial].
    *   **Normal Calculation:** Compute normals via gradient interpolation or finite differences [Parent, unofficial].
    *   **Triangle Emission:** Look up `triTable[selector]` to determine which edges form triangles. Emit these triangles to the `appendVertexBuffer` using atomic operations or hardware-supported append buffer mechanisms [Parent, unofficial].

5.  **Output Management & Indirect Rendering:**
    *   Initialize `argBuffer` with `{0, 1, 0, 0}` [S1, unofficial].
    *   Use `ComputeBuffer.CopyCount` to copy the append buffer's current count to `argBuffer` at offset 0 [S1, unofficial].
    *   Read back the count from `argBuffer` to the CPU [S1, unofficial].
    *   Adjust draw arguments: Multiply the vertex count (`args[0]`) by 3 to get the total index count for triangles (assuming 3 indices per triangle) [S1, unofficial]. Update `argBuffer` with the new args [S1, unofficial].
    *   Draw procedural geometry: Set the material pass, bind `appendVertexBuffer` to the "triangles" buffer in the shader, set the model matrix, and call `Graphics.DrawProceduralIndirect` with `MeshTopology.Triangles` and the `argBuffer` [S1, unofficial].

**Pseudocode:**

```python
# Initialization (CPU-side, Unity C# context)
kernel_id = MarchingCubesCS.FindKernel("MarchingCubes")
N = Resolution
tau = 0.5f

# Allocate buffers
# Capacity: (N-1)^3 * 5 triangles per voxel max
append_buf_size = (N - 1) * (N - 1) * (N - 1) * 5
append_vertex_buffer = ComputeBuffer(append_buf_size, 18, ComputeBufferType.Append)
arg_buffer = ComputeBuffer(4, 4, ComputeBufferType.IndirectArguments) # 4 ints

# Set parameters
MarchingCubesCS.SetInt("_gridSize", N)
MarchingCubesCS.SetFloat("_isoLevel", tau)
MarchingCubesCS.SetBuffer(kernel_id, "triangleRW", append_vertex_buffer)

# Reset counter
append_vertex_buffer.SetCounterValue(0)

# Dispatch
# Thread groups: (N/8, N/8, N/8)
group_x = N // 8
group_y = N // 8
group_z = N // 8
MarchingCubesCS.Dispatch(kernel_id, group_x, group_y, group_z)

# Get count and prepare indirect draw
arg_buffer.SetData([0, 1, 0, 0])
ComputeBuffer.CopyCount(append_vertex_buffer, arg_buffer, 0)
count_data = arg_buffer.GetData() # Read back to CPU
vertex_count = count_data[0]
index_count = vertex_count * 3 # 3 indices per triangle

# Update args for indirect draw
arg_buffer.SetData([index_count, 1, 0, 0])

# Render
Graphics.SetGlobalTexture("_DensityTexture", density_texture)
material.SetPass(0)
material.SetBuffer("triangles", append_vertex_buffer)
material.SetMatrix("_ModelMatrix", model_matrix)
Graphics.DrawProceduralIndirect(MeshTopology.Triangles, arg_buffer)
```

## Operating characteristics
*   **Time Complexity:** $O(N^3)$ for processing all voxels, where $N$ is the grid resolution [Parent, unofficial].
*   **Memory Complexity:** $O(N^3)$ for the input texture and $O(N^3)$ for the output buffer capacity [S1, unofficial].
*   **Performance:** The implementation assumes DX11 hardware [S1, unofficial]. Mobile support is uncertain [S1, unofficial].
*   **Strengths:** Real-time extraction on GPU; simple implementation using Unity's compute shaders; append buffer handles variable output size automatically [S1, unofficial].
*   **Limitations:** The density field generation is done on CPU, which may be a bottleneck [S1, unofficial]. The output buffer is pre-allocated to a maximum capacity, which may waste memory for sparse fields [S1, unofficial]. The provided shader uses a barebone diffuse lighting model [S1, unofficial].
*   **When to use:** Real-time visualization in Unity with DX11 hardware [S1, unofficial].
*   **When not to use:** Mobile platforms (uncertain support) [S1, unofficial]; scenes requiring high-performance density generation (use RenderTexture instead of Texture3D) [S1, unofficial].
