# Capacity-Safe Marching Cubes Pipeline

Also called: Proposed Framework, Two-pass exact-allocation strategy

## Overview
The Capacity-Safe Marching Cubes Pipeline is a GPU-accelerated isosurface extraction method that prevents buffer overflow by determining the exact vertex count before geometry generation [S1]. Unlike fixed-capacity baselines that reserve static buffers and risk failure at high resolutions, this method uses a two-pass approach: first computing counts and offsets, then allocating exact buffers and generating triangles [S1]. It builds on [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by replacing its variable-output management strategies with a deterministic prefix-sum-based allocation.

## How it works
The pipeline consists of four sequential stages: cell classification, prefix-sum computation, exact VBO (Vertex Buffer Object) allocation, and triangle generation [S1].

**Inputs and Outputs:**
*   **Input:** A 3D scalar field grid of resolution $N_x \times N_y \times N_z$. Scalar values are normalized to the range $[0, 1]$ using the dataset's minimum and maximum values [S1].
*   **Output:** A Vertex Buffer Object (VBO) containing position and normal data for the extracted isosurface [S1].

**Data Structures:**
1.  **Input Scalar Volume:** 3D array of normalized scalar values.
2.  **Count Buffer:** 1D array of integers, size equal to the number of voxels $(N_x-1)(N_y-1)(N_z-1)$, storing the number of vertices generated per voxel.
3.  **Offset Buffer:** 1D array of integers, size equal to the number of voxels, storing the exclusive prefix sum of the count buffer [S1].
4.  **Output VBO:** Dynamic buffer sized exactly to the total vertex count.

**Parameters:**
*   **Isovalue ($\tau$):** Specified in the normalized range $[0, 1]$. Typical values for testing topology variations are 0.35, 0.50, and 0.65 [S1].

**Algorithm Steps:**

1.  **Cell Classification:**
    Each GPU thread processes one voxel cube. It samples the scalar values at the 8 corners. It computes the 8-bit case index (selector) by comparing corner values against $\tau$. It determines the number of vertices to be generated for this voxel based on the `triangleTable` from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md). Note: Each triangle has 3 vertices. The count for a voxel is $3 \times (\text{number of triangles in } \text{triangleTable}[\text{selector}])$ [S1, Parent].

2.  **Prefix-Sum Computation:**
    An exclusive prefix sum (scan) is performed on the per-voxel vertex counts [S1].
    Let $C[i]$ be the vertex count for voxel $i$.
    Let $O[i]$ be the offset for voxel $i$.
    $$ O[i] = \sum_{j=0}^{i-1} C[j] $$
    The total vertex count $V_{total}$ is $O[\text{last\_voxel}] + C[\text{last\_voxel}]$ [S1].

3.  **Exact Buffer Allocation:**
    Allocate the output VBO with a capacity of exactly $V_{total}$ vertices. This prevents the buffer overflow seen in fixed-capacity implementations at high resolutions (e.g., $512^3$) [S1].

4.  **Triangle Generation:**
    For each voxel, threads compute the intersection points using linear interpolation:
    $$ \mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1) $$
    where $V_1, V_2$ are scalar values at corners $\mathbf{p}_1, \mathbf{p}_2$ [S1, Parent]. Normals are computed via gradient interpolation or finite differences [S1, Parent]. The thread writes the resulting vertices to the VBO at the base offset $O[i]$ plus the local vertex index within the voxel's triangles [S1].

**Pseudocode:**

```python
# Stage 1: Classification and Counting
# Each thread handles one voxel (x, y, z)
def classify_voxel(x, y, z, scalar_field, isovalue):
    # Sample 8 corners
    corners = [
        scalar_field[x, y, z],
        scalar_field[x+1, y, z],
        scalar_field[x, y+1, z],
        scalar_field[x+1, y+1, z],
        scalar_field[x, y, z+1],
        scalar_field[x+1, y, z+1],
        scalar_field[x, y+1, z+1],
        scalar_field[x+1, y+1, z+1]
    ]
    
    # Compute case index
    case_index = 0
    for i, val in enumerate(corners):
        if val > isovalue:
            case_index |= (1 << i)
            
    # Get triangle count from lookup table
    # triangleTable is 256x16, storing edge indices
    # We count how many triangles are defined for this case
    # A triangle is defined if the first edge index is not -1
    triangle_count = 0
    for k in range(0, 16, 3):
        e1 = triangleTable[case_index][k]
        if e1 != -1:
            triangle_count += 1
            
    # Each triangle has 3 vertices
    return triangle_count * 3

# Stage 2: Prefix Sum
# Input: counts array of size N
# Output: offsets array of size N, total_count
def exclusive_prefix_sum(counts):
    n = len(counts)
    offsets = [0] * n
    current_sum = 0
    for i in range(n):
        offsets[i] = current_sum
        current_sum += counts[i]
    return offsets, current_sum

# Stage 3: Generation
def generate_geometry(x, y, z, scalar_field, isovalue, offsets, output_buffer):

    corners = [...] # As above
    case_index = 0
    for i, val in enumerate(corners):
        if val > isovalue:
            case_index |= (1 << i)
            
    # Generate vertices
    vertex_local_index = 0
    for k in range(0, 16, 3):
        e1 = triangleTable[case_index][k]
        if e1 == -1:
            break
            
        e2 = triangleTable[case_index][k+1]
        e3 = triangleTable[case_index][k+2]
        
        # Interpolate points for edges e1, e2, e3
        p1 = interpolate_edge(e1, corners, voxel_corners_coords, isovalue)
        p2 = interpolate_edge(e2, corners, voxel_corners_coords, isovalue)
        p3 = interpolate_edge(e3, corners, voxel_corners_coords, isovalue)
        
        # Write to buffer
        output_buffer[base_offset + vertex_local_index] = p1
        output_buffer[base_offset + vertex_local_index + 1] = p2
        output_buffer[base_offset + vertex_local_index + 2] = p3
        
        vertex_local_index += 3

def interpolate_edge(edge_index, corner_values, corner_coords, isovalue):
    # Map edge index to the two corner indices
    # Edge 0: 0-1, Edge 1: 1-3, etc. (Standard MC edge mapping)
    c1_idx, c2_idx = edge_to_corners[edge_index]
    v1 = corner_values[c1_idx]
    v2 = corner_values[c2_idx]
    p1 = corner_coords[c1_idx]
    p2 = corner_coords[c2_idx]
    
    # Linear interpolation
    t = (isovalue - v1) / (v2 - v1)
    return p1 + t * (p2 - p1)
```

## Operating characteristics
*   **Time Complexity:** Dominated by the prefix-sum operation, which is $O(N)$ where $N$ is the number of voxels. The generation pass is also $O(N)$ but proportional to the number of active voxels.
*   **Memory Complexity:** Peak VRAM usage includes the input scalar volume, intermediate count and offset buffers, and the generated position and normal buffers [S1].
*   **Measured Performance:**
    *   At $512^3$ resolution with isovalue 0.35: 42.81 million vertices, 44.7 ms extraction time, 10.9 GB peak VRAM, 28.6 FPS rendering [S1].
    *   At $128^3$ resolution with isovalue 0.35: 1.28 million vertices, 5.8 ms extraction time, 1.9 GB peak VRAM, 221.4 FPS rendering [S1].
*   **Strengths:** Guarantees no buffer overflow by allocating exact capacity. Stable at high resolutions where fixed-capacity methods fail [S1].
*   **Limitations:** Requires two passes (counting and generation) and additional memory for count/offset buffers compared to single-pass atomic counter approaches.
*   **When to use:** When exact memory allocation is required, or when processing high-resolution datasets where buffer overflow is a risk.
*   **When not to use:** When memory is extremely constrained and approximate allocation is acceptable, or when the overhead of the prefix sum is prohibitive for very small datasets.

## Background
The method was proposed in a study on visual tools for 3D plasma simulation, specifically for extracting isosurfaces from fusion-plasma electromagnetic potential data [S1]. It addresses the limitations of fixed-capacity GPU Marching Cubes implementations that fail at high resolutions (e.g., $512^3$) due to buffer overflows [S1]. The evaluation was performed on a workstation with an NVIDIA RTX 3090 GPU [S1].
