# Capacity-Safe Marching Cubes Pipeline

Also called: Proposed Framework, Two-pass exact-allocation strategy

## Overview
A GPU-based isosurface extraction method that avoids buffer overflow by determining the exact vertex count before geometry generation, using a two-pass approach: first computing counts/offsets, then allocating exact buffers and generating triangles [S1]. Unlike fixed-capacity baselines that reserve static buffers, this method determines the exact vertex count before generation, ensuring stability and preventing buffer overflow without excessive static reservation [S1]. It builds on [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by adding a precise memory management layer to the parallel voxel processing [G].

## How it works
The extraction process consists of four sequential stages: cell classification, prefix-sum computation, exact VBO (Vertex Buffer Object) allocation, and triangle generation [S1].

**Inputs and Outputs:**
*   **Input:** A 3D scalar field volume $V$ of resolution $N_x \times N_y \times N_z$. Scalar values are normalized to the range $[0, 1]$ using the dataset's minimum and maximum values [S1]. An isovalue $\tau$ is specified within this normalized range [S1].
*   **Output:** A vertex buffer containing positions and normals for the extracted isosurface.

**Data Structures:**
1.  **Cell Classification Array:** A 3D array (or flattened 1D array) storing the 8-bit case index $C$ for each voxel, derived from the scalar field values $V$ at the 8 vertices relative to $\tau$ [G].
2.  **Count Buffer:** A 1D array of size equal to the number of voxels, storing the number of triangles generated by each voxel [S1].
3.  **Offset Buffer:** A 1D array of size equal to the number of voxels, storing the starting index in the output vertex buffer for each voxel's triangles, computed via exclusive prefix sum [S1].
4.  **Output Vertex Buffer:** A dynamically allocated buffer sized exactly to the total number of vertices required, determined by the sum of triangle counts [S1].

**Steps:**
1.  **Cell Classification:** For each voxel, calculate the case index $C$ based on the sign of $V(v_i) - \tau$ for its 8 vertices $v_i$ [G].
2.  **Triangle Counting:** For each voxel, determine the number of triangles $T_v$ generated using the `triangleTable` [G]. Store $T_v$ in the Count Buffer.
3.  **Prefix-Sum Computation:** Perform an exclusive prefix sum (scan) on the Count Buffer to generate the Offset Buffer. The offset for voxel $v$ is the sum of triangle counts for all voxels $u < v$. This determines the starting write index for each voxel's output in the final buffer [S1].
4.  **Exact Buffer Allocation:** Calculate the total number of vertices $V_{total} = \sum T_v \times 3$ (assuming 3 vertices per triangle). Allocate the Output Vertex Buffer with exactly this capacity [S1].
5.  **Triangle Generation:** For each voxel, using the case index $C$, interpolate vertex positions on the intersected edges. Write the resulting triangle vertices to the Output Vertex Buffer at the exact positions specified by the Offset Buffer for that voxel [S1].

**Pseudocode:**
```python
def capacity_safe_marching_cubes(volume, isovalue):
    # volume: 3D array of scalars, normalized to [0, 1]
    # isovalue: float in [0, 1]
    Nx, Ny, Nz = volume.shape
    num_voxels = Nx * Ny * Nz
    triangle_counts = [0] * num_voxels

    # Stage 1: Cell Classification and Triangle Counting
    for v in range(num_voxels):
        z = v // (Nx * Ny)
        y = (v % (Nx * Ny)) // Nx
        x = v % Nx
        # Sample 8 corners of the voxel
        vals = [
            volume[x, y, z], volume[x+1, y, z], volume[x+1, y+1, z], volume[x, y+1, z],
            volume[x, y, z+1], volume[x+1, y, z+1], volume[x+1, y+1, z+1], volume[x, y+1, z+1]
        ]
        # Compute 8-bit case index C
        C = sum((1 << i) for i, val in enumerate(vals) if val < isovalue)
        # Count triangles for case C using standard MC triangle table [G]
        triangle_counts[v] = len(triangle_table[C]) // 3

    # Stage 2: Prefix-Sum Computation
    # Exclusive prefix sum to generate offsets for exact allocation
    offsets = [0] * num_voxels
    current_offset = 0
    for v in range(num_voxels):
        offsets[v] = current_offset
        current_offset += triangle_counts[v]

    # Stage 3: Exact Buffer Allocation
    total_triangles = sum(triangle_counts)
    total_vertices = total_triangles * 3
    output_vertices = [None] * total_vertices
    output_normals = [None] * total_vertices

    # Stage 4: Triangle Generation
    for v in range(num_voxels):
        if triangle_counts[v] == 0:
            continue
        z = v // (Nx * Ny)
        y = (v % (Nx * Ny)) // Nx
        x = v % Nx
        vals = [
            volume[x, y, z], volume[x+1, y, z], volume[x+1, y+1, z], volume[x, y+1, z],
            volume[x, y, z+1], volume[x+1, y, z+1], volume[x+1, y+1, z+1], volume[x, y+1, z+1]
        ]
        C = sum((1 << i) for i, val in enumerate(vals) if val < isovalue)
        base_index = offsets[v]
        edge_indices = triangle_table[C]
        # Iterate through edge indices in groups of 3 for each triangle
        for tri_idx in range(0, len(edge_indices), 3):
            e1, e2, e3 = edge_indices[tri_idx], edge_indices[tri_idx+1], edge_indices[tri_idx+2]
            # Linear interpolation on the specified edges [G]
            p1 = interpolate_edge(volume, x, y, z, e1, isovalue)
            p2 = interpolate_edge(volume, x, y, z, e2, isovalue)
            p3 = interpolate_edge(volume, x, y, z, e3, isovalue)
            # Write vertices to exact positions in output buffer
            output_vertices[base_index] = p1
            output_vertices[base_index + 1] = p2
            output_vertices[base_index + 2] = p3
            base_index += 3

    return output_vertices, output_normals

def interpolate_edge(volume, x, y, z, edge_idx, isovalue):
    # Standard MC edge indices 0-11 map to corner pairs.
    # Returns interpolated (x, y, z) position [G]
    return (0.0, 0.0, 0.0)
```

**Parameters:**
*   **Isovalue ($\tau$):** Specified in the normalized scalar range $[0, 1]$. Typical tested values are 0.35, 0.50, and 0.65 [S1].

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** Using a fixed-capacity single-pass output buffer causes failure at high resolutions (e.g., $512^3$) because the generated output exceeds available buffer capacity, resulting in overwritten or missing vertex data and incomplete geometry [S1].
*   **Precision:** Scalar values must be normalized to $[0, 1]$ before comparison with $\tau$ to ensure consistent behavior across different datasets [S1].

A GPU-accelerated Marching Cubes pipeline that classifies voxels, uses exclusive prefix sums to count active voxels and required vertices, compacts the voxel index array to remove empty voxels, and extracts the isosurface only for active voxels. It sets itself apart from naive parallel Marching Cubes by avoiding buffer overflow and dynamic memory allocation during geometry generation through a two-pass counting and compaction strategy, building on the [Capacity-Safe Marching Cubes Pipeline](4596-capacity-safe-marching-cubes-pipeline.md).

## Background
The method was proposed in the context of visualizing 3D plasma simulation data, specifically electromagnetic potential values from fusion plasma datasets [S1]. It was developed to address the limitations of fixed-capacity GPU Marching Cubes implementations that fail at high resolutions due to buffer overflow [S1]. The evaluation was performed on a workstation equipped with an AMD Ryzen Threadripper PRO 3955WX CPU, 256 GB of system memory, and an NVIDIA RTX 3090 GPU with 24 GB of VRAM [S1].
