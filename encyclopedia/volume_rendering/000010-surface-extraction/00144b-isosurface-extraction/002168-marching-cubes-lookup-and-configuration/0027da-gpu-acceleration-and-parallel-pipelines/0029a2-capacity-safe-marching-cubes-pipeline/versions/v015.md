# Capacity-Safe Marching Cubes Pipeline

Also called: Proposed Framework, Two-pass exact-allocation strategy

## Overview
A GPU-based isosurface extraction method that avoids buffer overflow by determining the exact vertex count before geometry generation, using a two-pass approach: first computing counts/offsets, then allocating exact buffers and generating triangles [S1]. It sets itself apart from naive parallel Marching Cubes by avoiding buffer overflow and dynamic memory allocation during geometry generation through a two-pass counting and compaction strategy, building on [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) [S1]. Unlike fixed-capacity baselines that reserve static buffers, this method determines the exact vertex count before generation, ensuring stability and preventing buffer overflow without excessive static reservation [S1].

## How it works
The extraction process consists of four sequential stages: cell classification, prefix-sum computation, exact VBO (Vertex Buffer Object) allocation, and triangle generation [S1].

**Inputs and Outputs:**
*   **Input:** A 3D scalar field $V$ defined on a grid of resolution $N_x \times N_y \times N_z$. The scalar values are normalized to the range $[0, 1]$ using the minimum and maximum values of the dataset [S1]. An isovalue $\tau$ is specified within this normalized range [S1].
*   **Output:** A set of vertices and normals representing the isosurface, stored in a Vertex Buffer Object (VBO) [S1].

**Data Structures:**
Uses the standard lookup tables defined in [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md): the 256-entry `edgeTable` bitmask and the $256 \times 16$ `triangleTable` [S1].

**Algorithm Steps:**
1.  **Cell Classification:** For each voxel in the grid, compute the case index $C$ based on the scalar values at its 8 corners relative to the isovalue $\tau$ [S1]. Determine if the voxel is "active" (i.e., $C \neq 0$ and $C \neq 255$) and calculate the number of triangles $T_v$ generated by this voxel using the `triangleTable`. The number of triangles is the count of non-terminating triplets in the row $C$ of `triangleTable` [G].
2.  **Prefix-Sum Computation:** Compute an exclusive prefix sum (scan) of the triangle counts $T_v$ for all active voxels [S1]. This produces an offset array where each entry indicates the starting index in the output buffer for the triangles generated by the corresponding voxel [G]. This step determines the exact total number of vertices required, as each triangle consists of 3 vertices [G]. Let $N_{total}$ be the total number of triangles [G]. The required vertex buffer size is $3 \times N_{total}$ vertices [G].
3.  **Exact VBO Allocation:** Allocate a Vertex Buffer Object (VBO) and a Normal Buffer Object with exact sizes derived from the prefix sum [S1]. The size is $3 \times N_{total}$ vertices [G]. This prevents buffer overflow and avoids the need for large static reservations [S1].
4.  **Triangle Generation:** For each active voxel, use the case index $C$ to look up the intersected edges in `edgeTable` [S1]. Interpolate the intersection points on the edges using the scalar values at the vertices [G]. Use `triangleTable` to determine the connectivity of the triangles [G]. Write the vertex positions and normals to the pre-allocated buffers at the offsets computed in Step 2 [S1].

**Pseudocode:**

```python
def capacity_safe_marching_cubes(volume, isovalue, resolution, edge_table, triangle_table):
    Nx, Ny, Nz = resolution
    num_cells = (Nx - 1) * (Ny - 1) * (Nz - 1)
    
    # Step 1: Cell Classification
    triangle_counts = [0] * num_cells
    for z in range(Nz - 1):
        for y in range(Ny - 1):
            for x in range(Nx - 1):
                v = [
                    volume[x, y, z], volume[x+1, y, z], volume[x+1, y+1, z], volume[x, y+1, z],
                    volume[x, y, z+1], volume[x+1, y, z+1], volume[x+1, y+1, z+1], volume[x, y+1, z+1]
                ]
                C = 0
                for i in range(8):
                    if v[i] < isovalue:
                        C |= (1 << i)
                if C != 0 and C != 255:
                    row = triangle_table[C]
                    t_count = 0
                    idx = 0
                    while row[idx] != -1:
                        t_count += 1
                        idx += 3
                    voxel_idx = z * (Ny - 1) * (Nx - 1) + y * (Nx - 1) + x
                    triangle_counts[voxel_idx] = t_count
                else:
                    voxel_idx = z * (Ny - 1) * (Nx - 1) + y * (Nx - 1) + x
                    triangle_counts[voxel_idx] = 0

    # Step 2: Prefix-Sum Computation
    offsets = [0] * num_cells
    current_sum = 0
    for i in range(num_cells):
        offsets[i] = current_sum
        current_sum += triangle_counts[i]
    total_triangles = current_sum
    total_vertices = 3 * total_triangles
    
    # Step 3: Exact VBO Allocation
    vbo_positions = [0.0] * (total_vertices * 3)
    vbo_normals = [0.0] * (total_vertices * 3)
    
    # Step 4: Triangle Generation
    for voxel_idx in range(num_cells):
        t_count = triangle_counts[voxel_idx]
        if t_count == 0:
            continue
        offset = offsets[voxel_idx]
        z = voxel_idx // ((Ny - 1) * (Nx - 1))
        y = (voxel_idx % ((Ny - 1) * (Nx - 1))) // (Nx - 1)
        x = voxel_idx % (Nx - 1)
        
        v = [
            volume[x, y, z], volume[x+1, y, z], volume[x+1, y+1, z], volume[x, y+1, z],
            volume[x, y, z+1], volume[x+1, y, z+1], volume[x+1, y+1, z+1], volume[x, y+1, z+1]
        ]
        C = 0
        for i in range(8):
            if v[i] < isovalue:
                C |= (1 << i)
        
        edge_mask = edge_table[C]
        tri_row = triangle_table[C]
        
        points = []
        for e in range(12):
            if (edge_mask >> e) & 1:
                p = interpolate_edge(v, e, isovalue)
                points.append(p)
        
        idx = 0
        tri_idx = 0
        while tri_row[idx] != -1:
            e1 = tri_row[idx]
            e2 = tri_row[idx+1]
            e3 = tri_row[idx+2]
            
            p1, p2, p3 = points[e1], points[e2], points[e3]
            n = cross_product(p2 - p1, p3 - p1)
            n = normalize(n)
            
            base = offset + tri_idx * 3
            vbo_positions[base * 3] = p1[0]; vbo_positions[base * 3 + 1] = p1[1]; vbo_positions[base * 3 + 2] = p1[2]
            vbo_normals[base * 3] = n[0]; vbo_normals[base * 3 + 1] = n[1]; vbo_normals[base * 3 + 2] = n[2]
            vbo_positions[(base + 1) * 3] = p2[0]; vbo_positions[(base + 1) * 3 + 1] = p2[1]; vbo_positions[(base + 1) * 3 + 2] = p2[2]
            vbo_normals[(base + 1) * 3] = n[0]; vbo_normals[(base + 1) * 3 + 1] = n[1]; vbo_normals[(base + 1) * 3 + 2] = n[2]
            vbo_positions[(base + 2) * 3] = p3[0]; vbo_positions[(base + 2) * 3 + 1] = p3[1]; vbo_positions[(base + 2) * 3 + 2] = p3[2]
            vbo_normals[(base + 2) * 3] = n[0]; vbo_normals[(base + 2) * 3 + 1] = n[1]; vbo_normals[(base + 2) * 3 + 2] = n[2]
            
            tri_idx += 1
            idx += 3
            
    return vbo_positions, vbo_normals

def interpolate_edge(v, edge_idx, isovalue):
    if edge_idx < 4:
        v0, v1 = v[edge_idx], v[(edge_idx + 1) % 4]
        coord0, coord1 = get_vertex_coords(edge_idx), get_vertex_coords((edge_idx + 1) % 4)
    elif edge_idx < 8:
        v0, v1 = v[edge_idx], v[(edge_idx + 1) % 4 + 4]
        coord0, coord1 = get_vertex_coords(edge_idx), get_vertex_coords((edge_idx + 1) % 4 + 4)
    else:
        v0, v1 = v[edge_idx - 8], v[edge_idx - 8 + 4]
        coord0, coord1 = get_vertex_coords(edge_idx - 8), get_vertex_coords(edge_idx - 8 + 4)
    t = (isovalue - v0) / (v1 - v0)
    return [coord0[i] + t * (coord1[i] - coord0[i]) for i in range(3)]

def get_vertex_coords(idx):
    x = idx % 2
    y = (idx // 2) % 2
    z = idx // 4
    return [float(x), float(y), float(z)]

def cross_product(a, b):
    return [a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0]]

def normalize(v):
    mag = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return [v[0]/mag, v[1]/mag, v[2]/mag]
```

**Parameters:**
*   **Isovalues ($\tau$):** Specified in the normalized scalar range $[0, 1]$. Typical tested values are 0.35, 0.50, and 0.65 [S1].

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** Using a fixed-capacity single-pass output buffer causes failure at high resolutions (e.g., $512^3$) because the generated output exceeds available buffer capacity, resulting in overwritten or missing vertex data and incomplete geometry [S1].

## Subtopics

### [GPU Marching Cubes with Scan-Based Compaction](6632-gpu-marching-cubes-with-scan-based-compaction.md)
A GPU-accelerated Marching Cubes pipeline that classifies voxels, uses exclusive prefix sums to count active voxels and required vertices, compacts the voxel index array to remove empty voxels, and extracts the isosurface only for active voxels. It optimizes Marching Cubes by using stream compaction to avoid processing voxels that do not contain the isosurface. It builds on [Capacity-Safe Marching Cubes Pipeline](4596-capacity-safe-marching-cubes-pipeline.md) by implementing the two-pass capacity-safe approach on GPU hardware.

### [GPU-accelerated Marching Cubes Pipeline](14714-gpu-accelerated-marching-cubes-pipeline.md)
This method is a six-stage hybrid CPU-GPU pipeline for isosurface extraction that maximizes performance by balancing memory hierarchy usage and parallelizing the Marching Cubes algorithm. It differs from sibling methods like [Capacity-Safe Marching Cubes Pipeline](4596-capacity-safe-marching-cubes-pipeline.md) by offloading the spatial traversal and active cell identification to the CPU using pre-constructed spatial data structures, while the GPU handles the exact buffer allocation and triangle generation in parallel. Unlike [GPU Marching Cubes with Scan-Based Compaction](6632-gpu-marching-cubes-with-scan-based-compaction.md), which typically handles all active cells on the GPU, this approach reduces GPU memory pressure and bandwidth by transferring only the necessary active cell indices from CPU to GPU.

### Marching Cubes Optimization via Lazy Reverse Mapping
An optimization for GPU-based isosurface extraction that eliminates stream compaction (`copy_if`) and excessive global memory movement by inverting the standard cell-to-vertex mapping into a vertex-to-cell mapping [S2, unofficial]. It replaces the forward filter (input cell ID -> output vertex ID) with a reverse mapping (output vertex ID -> input cell ID) [S2, unofficial]. For a given output vertex ID, it only applies geometric operations to the specific cell that would generate that vertex, skipping non-contributing cells entirely [S2, unofficial]. It extends the reverse mapping to cover ranges of output vertex IDs, allowing batched processing of multiple vertices per cell [S2, unofficial]. It differs from the naive approach by removing two `copy_if` passes (cell compaction and vertex compaction), directly reducing global memory bandwidth pressure and improving throughput [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The method involves a linear pass over all voxels for classification and prefix sum, followed by a linear pass for triangle generation. The complexity is $O(N)$ where $N$ is the number of voxels [G].
*   **Memory Complexity:** Peak VRAM usage includes the input scalar volume, intermediate count and offset buffers, and the generated position and normal buffers [S1].
*   **Measured Performance:**
    *   At $512^3$ resolution with isovalue 0.35, the method generates 42.81 million vertices in 44.7 ms with 10.9 GB peak VRAM usage, rendering at 28.6 FPS [S1].
    *   At $128^3$ resolution with isovalue 0.35, the method generates 1.28 million vertices in 5.8 ms with 1.9 GB peak VRAM usage, rendering at 221.4 FPS [S1].
    *   At $128^3$ resolution with isovalue 0.50, the method generates 0.94 million vertices in 4.9 ms with 1.7 GB peak VRAM usage, rendering at 264.7 FPS [S1].
    *   At $128^3$ resolution with isovalue 0.65, the method generates 0.61 million vertices in 4.1 ms with 1.6 GB peak VRAM usage, rendering at 312.5 FPS [S1].
*   **Scaling:** Increasing the grid resolution increases both the number of processed cells and the amount of generated geometry [S1].
*   **Strengths:** Ensures stability and prevents buffer overflow without excessive static reservation [S1]. Remains stable at high resolutions where fixed-capacity methods fail [S1].
*   **Limitations:** Requires two passes over the data (classification and generation), which may introduce overhead for very small datasets [G]. The prefix sum computation can be a bottleneck if not optimized [G].
*   **When to use:** When extracting isosurfaces from large volumes where the number of triangles is unknown or variable, and buffer overflow is a concern [G].
*   **When not to use:** When the number of triangles is small and known in advance, or when memory bandwidth is extremely limited and the overhead of the prefix sum is prohibitive [G].

## Background
The method was proposed in the context of visualizing 3D plasma simulation data, specifically for examining morphological changes and identifying regions of interest in simulated plasma fields [S1]. It was evaluated on a workstation equipped with an AMD Ryzen Threadripper PRO 3955WX CPU, 256 GB of system memory, and an NVIDIA RTX 3090 GPU with 24 GB of VRAM [S1]. The evaluation focused on geometric continuity, extraction time, rendering performance, and GPU memory usage [S1].
