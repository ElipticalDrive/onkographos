# Capacity-Safe Marching Cubes Pipeline

Also called: Proposed Framework, Two-pass exact-allocation strategy

## Overview
The Capacity-Safe Marching Cubes Pipeline is a GPU-accelerated isosurface extraction method that prevents buffer overflow by determining the exact vertex count before geometry generation [S1]. Unlike fixed-capacity single-pass approaches that reserve static buffers and fail at high resolutions, this method uses a two-pass strategy: first computing counts and offsets, then allocating exact buffers and generating triangles [S1]. It builds on [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by adding explicit memory management for variable output sizes.

## How it works
The extraction process consists of four sequential stages: cell classification, prefix-sum computation, exact VBO (Vertex Buffer Object) allocation, and triangle generation [S1].

**Inputs and Outputs:**
*   **Input:** A 3D scalar volume grid $V$ of resolution $N_x \times N_y \times N_z$. Scalar values are normalized to $[0, 1]$ using the dataset's minimum and maximum values [S1].
*   **Input:** An isovalue $\tau \in [0, 1]$ [S1].
*   **Output:** A vertex buffer containing positions and normals for the extracted isosurface [S1].

**Data Structures:**
1.  **Cell Classification Array:** A 3D array of integers (case indices) matching the volume resolution. Each entry is computed using the standard logic from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md): for each voxel, the 8-bit case index $C$ is determined by comparing corner scalar values to $\tau$ [S1, Parent].
2.  **Count Buffer:** A 1D array storing the number of triangles generated by each voxel. Since a voxel generates at most 5 triangles, this value is in $[0, 5]$ [S1, Parent].
3.  **Offset Buffer:** A 1D array derived from an exclusive prefix sum of the Count Buffer, indicating the starting index in the output vertex buffer for each voxel's triangles [S1].
4.  **Output Vertex Buffer:** A dynamically allocated buffer of size $N_{verts} = \sum (\text{triangles per voxel}) \times 3$ [S1].

**Steps:**

1.  **Cell Classification:** Each GPU thread processes one voxel. It samples the 8 corner scalar values, computes the case index $C$, and determines the intersecting edges using the `edgeTable` from the parent article [S1, Parent].
2.  **Triangle Counting:** For each voxel, the thread looks up the number of triangles in the `triangleTable` (0 to 5) and writes this count to the Count Buffer at the voxel's index [S1, Parent].
3.  **Prefix-Sum Computation:** An exclusive prefix sum (scan) is performed on the Count Buffer to generate the Offset Buffer. The offset for voxel $i$ is the sum of triangle counts for all voxels $j < i$ [S1].
4.  **Exact Allocation:** The total number of vertices $N_{verts}$ is calculated as the last element of the Offset Buffer plus the triangle count of the last voxel. A vertex buffer of exactly $N_{verts}$ positions is allocated [S1].
5.  **Triangle Generation:** Each thread processes one voxel again. It uses the Offset Buffer to determine the starting index in the vertex buffer. For each intersecting edge, it computes the intersection point $\mathbf{p}$ via linear interpolation:
    $$
    \mathbf{p} = \mathbf{p}_1 + \frac{\tau - V_1}{V_2 - V_1} (\mathbf{p}_2 - \mathbf{p}_1)
    $$
    where $\mathbf{p}_1, \mathbf{p}_2$ are corner positions and $V_1, V_2$ are corner scalar values [S1, Parent]. The resulting triangle vertices are written to the vertex buffer at the calculated offset [S1]. Normals are computed via gradient interpolation or finite differences [S1, Parent].

**Parameters:**
*   **Isovalue ($\tau$):** Specified in the normalized range $[0, 1]$. Typical tested values are 0.35, 0.50, and 0.65 [S1].

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** Using a fixed-capacity single-pass output buffer causes failure at high resolutions (e.g., $512^3$) because the generated output exceeds available buffer capacity, resulting in overwritten or missing vertex data and incomplete geometry [S1].
*   **Empty Voxels:** Voxels with no intersection generate 0 triangles. The prefix sum correctly handles these by assigning them zero offset range, but they still consume a thread [S1].

**Pseudocode:**

```python
# Kernel 1: Cell Classification and Counting
@kernel
def classify_and_count(volume: Volume, isovalue: float, counts: Array[int]):
    voxel_idx = get_global_thread_id()
    if voxel_idx >= volume.size:
        return
    
    # Sample 8 corners and compute case index C
    # (Logic from Marching Cubes Lookup and Configuration)
    C = compute_case_index(volume, voxel_idx, isovalue)
    
    # Get number of triangles for this case (0-5)
    num_tris = get_triangle_count(C)
    
    # Write count to buffer
    counts[voxel_idx] = num_tris

# Kernel 2: Exclusive Prefix Sum
@kernel
def exclusive_scan(counts: Array[int], offsets: Array[int]):
    # Perform exclusive prefix sum on counts array
    # offsets[i] = sum(counts[0]...counts[i-1])
    # Implementation depends on GPU scan primitive
    offsets = exclusive_prefix_sum(counts)

# Kernel 3: Triangle Generation
@kernel
def generate_triangles(volume: Volume, isovalue: float, offsets: Array[int], vertices: Array[Vec3]):
    voxel_idx = get_global_thread_id()
    if voxel_idx >= volume.size:
        return
    
    # Compute case index C
    C = compute_case_index(volume, voxel_idx, isovalue)
    
    # Get triangle indices for this case
    tri_indices = get_triangle_indices(C)
    
    # Base offset for this voxel's triangles
    base_offset = offsets[voxel_idx]
    
    # For each triangle in the case
    for i in range(0, len(tri_indices), 3):
        if tri_indices[i] == -1:
            break
            
        # Generate 3 vertices for this triangle
        for j in range(3):
            edge_idx = tri_indices[i + j]
            
            # Get corner positions and values for this edge
            p1, p2 = get_edge_corners(volume, voxel_idx, edge_idx)
            v1, v2 = get_edge_scalar_values(volume, voxel_idx, edge_idx)
            
            # Interpolate intersection point
            t = (isovalue - v1) / (v2 - v1)
            p = p1 + t * (p2 - p1)
            
            # Write to vertex buffer
            vertices[base_offset + i + j] = p
```

## Subtopics

### [GPU Marching Cubes with Scan-Based Compaction](6632-gpu-marching-cubes-with-scan-based-compaction.md)
A GPU-accelerated Marching Cubes pipeline that classifies voxels, uses exclusive prefix sums to count active voxels and required vertices, compacts the voxel index array to remove empty voxels, and extracts the isosurface only for active voxels. It sets itself apart from naive parallel Marching Cubes by avoiding buffer overflow and dynamic memory allocation during geometry generation through a two-pass counting and compaction strategy, building on the [Capacity-Safe Marching Cubes Pipeline](4596-capacity-safe-marching-cubes-pipeline.md).

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, due to the two-pass nature (classification/counting and generation) plus the prefix sum [S1].
*   **Memory Complexity:** $O(N)$ for the count and offset buffers, plus $O(V)$ for the output vertex buffer where $V$ is the number of vertices [S1].
*   **Measured Performance:**
    *   At $512^3$ resolution with isovalue 0.35: 42.81 million vertices generated in 44.7 ms, 10.9 GB peak VRAM, 28.6 FPS rendering [S1].
    *   At $128^3$ resolution with isovalue 0.35: 1.28 million vertices generated in 5.8 ms, 1.9 GB peak VRAM, 221.4 FPS rendering [S1].
*   **Strengths:** Prevents buffer overflow at high resolutions; stable memory usage; no excessive static reservation [S1].
*   **Limitations:** Requires two passes over the data; additional memory for count/offset buffers [S1].
*   **When to use:** High-resolution volume rendering where the number of intersecting voxels is unknown or variable [S1].
*   **When not to use:** Low-resolution scenes where fixed buffers are sufficient and simpler [S1].

## Background
The method was proposed in a study on visual tools for 3D plasma simulation, specifically for extracting isosurfaces from fusion plasma datasets [S1]. It addresses the limitations of fixed-capacity baselines that fail at high resolutions like $512^3$ [S1]. The evaluation was performed on an NVIDIA RTX 3090 GPU [S1].
