# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals and renders them directly via WebGL draw calls without storing a persistent mesh buffer in application memory [S1, unofficial]. It serves as a reference implementation for comparison against GPU-accelerated variants, solving the problem of visualizing scalar fields (such as metaballs) on the CPU by batching geometry generation and immediate rendering [S1, unofficial]. It differs from sibling methods like [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by performing all field computation and geometry generation on the CPU and using immediate mode rendering rather than parallel compute shaders or persistent buffer management.

## How it works
**Inputs and Outputs:**
- **Input:** A 3D grid of voxels representing a scalar field. The field is generated by accumulating contributions from all metaballs and a floor term for each voxel [S1, unofficial].
- **Output:** Rendered triangles via WebGL `drawArrays` calls. No persistent mesh object is created in CPU memory.

**Data Structures:**
The implementation uses a fixed-size buffer system to batch geometry before flushing to the GPU [S1, unofficial].
- `maxCount`: Integer, typically 4096 [S1, unofficial].
- `posArray`: `Float32Array` of size `maxCount * 3` [S1, unofficial].
- `normalArray`: `Float32Array` of size `maxCount * 3` [S1, unofficial].
- `uvArray`: `Float32Array` of size `maxCount * 2` [S1, unofficial].
- `colorArray`: `Float32Array` of size `maxCount * 4` [S1, unofficial].
- `count`: Integer tracking the number of vertices currently in the buffer [S1, unofficial].
- `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated [S1, unofficial].
- WebGL buffers (`posBuf`, `normalBuf`, etc.) are bound to these arrays using `gl.bufferData` with `DYNAMIC_DRAW` [S1, unofficial].

**Algorithm Steps:**
1. **Field Generation:** For each voxel in the 3D grid, compute the scalar field value by summing contributions from all metaballs and a floor term [S1, unofficial].
2. **Marching Cubes Extraction:** For each cube (voxel), use the precomputed `edgeTable` and `triangleTable` from [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) to determine intersected edges and triangle configurations [S1, unofficial].
3. **Vertex Interpolation:** Calculate intersection points on edges via linear interpolation between scalar values at edge endpoints. Compute normals by interpolating the gradient or using central differences at the intersection point [S1, unofficial].
4. **Batching Initialization:** Set primitive type (`TRIANGLES`, `LINES`, or `POINTS`), calculate `primsize` (3, 2, or 1), store program reference, reset `count` to 0, and reset attribute flags (`hasPos`, etc.) to false [S1, unofficial].
5. **Vertex Addition:**
   - To add a position: Store $x, y, z$ into `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`, and set `hasPos = true` [S1, unofficial].
   - To add a normal: Store $x, y, z$ into `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`, and set `hasNormal = true` [S1, unofficial].
6. **Triangle Generation:**
   - Copy positions from `posArray` at offsets $o_1, o_2, o_3$ and normals from `normalArray` at offsets $o_1, o_2, o_3$ into `posArray` and `normalArray` starting at index `count*3` [S1, unofficial].
   - Increment `count` by 3 [S1, unofficial].
   - Check for buffer overflow: If `count >= maxCount - 3`, flush the buffer (see Step 7) [S1, unofficial].
7. **Flush and Render:**
   - If `count == 0`, return [S1, unofficial].
   - Zero out remaining `posArray` entries from `count*3` to `length` [S1, unofficial].
   - Bind buffers for any enabled attributes using `gl.bufferData` with `DYNAMIC_DRAW` [S1, unofficial].
   - Enable vertex attribute arrays and set pointers [S1, unofficial].
   - Call `gl.drawArrays` with the primitive type, offset 0, and count [S1, unofficial].
   - Reset `count` to 0 [S1, unofficial].

**Pseudocode:**
```python
# Constants
MAX_COUNT = 4096
PRIM_SIZE_TRIANGLES = 3

# Data structures
pos_array = [0.0] * (MAX_COUNT * 3)
normal_array = [0.0] * (MAX_COUNT * 3)
count = 0
has_pos = False
has_normal = False

def add_vertex_position(x, y, z):
    global count, has_pos
    idx = count * 3
    pos_array[idx] = x
    pos_array[idx + 1] = y
    pos_array[idx + 2] = z
    has_pos = True

def add_vertex_normal(nx, ny, nz):
    global count, has_normal
    idx = count * 3
    normal_array[idx] = nx
    normal_array[idx + 1] = ny
    normal_array[idx + 2] = nz
    has_normal = True

def flush_and_render(gl, primitive_type):
    global count
    if count == 0:
        return
    
    # Zero out unused buffer space to prevent garbage data
    for i in range(count * 3, len(pos_array)):
        pos_array[i] = 0.0
        
    # Bind buffers
    if has_pos:
        gl.bufferData(gl.ARRAY_BUFFER, pos_array, gl.DYNAMIC_DRAW)
        gl.enableVertexAttribArray(0)
        gl.vertexAttribPointer(0, 3, gl.FLOAT, False, 0, 0)
        
    if has_normal:
        gl.bufferData(gl.ARRAY_BUFFER, normal_array, gl.DYNAMIC_DRAW)
        gl.enableVertexAttribArray(1)
        gl.vertexAttribPointer(1, 3, gl.FLOAT, False, 0, 0)
        
    # Draw
    gl.drawArrays(primitive_type, 0, count)
    
    # Reset state
    count = 0
    has_pos = False
    has_normal = False

def process_voxel(cube_index, edge_table, triangle_table, field_values):
    global count
    
    # Determine case index C based on field values at 8 vertices
    # If V(v_i) < I, bit i is set to 1
    C = 0
    for i in range(8):
        if field_values[i] < ISOSURFACE_THRESHOLD:
            C |= (1 << i)
            
    # Early exit for empty or full cubes
    if C == 0 or C == 255:
        return

    # Get edges and triangles from lookup tables
    edges = edge_table[C]
    triangles = triangle_table[C]
    
    # If no triangles for this case, return
    if triangles == -1:
        return

    # Process each triangle in the configuration
    tri_idx = 0
    while triangles[tri_idx] != -1:
        v1 = triangles[tri_idx]
        v2 = triangles[tri_idx + 1]
        v3 = triangles[tri_idx + 2]
        tri_idx += 3
        
        # Calculate intersection points and normals for v1, v2, v3
        # This involves linear interpolation on the specific edges
        p1, n1 = interpolate_vertex(v1, field_values)
        p2, n2 = interpolate_vertex(v2, field_values)
        p3, n3 = interpolate_vertex(v3, field_values)
        
        # Add vertices to batch
        add_vertex_position(p1[0], p1[1], p1[2])
        add_vertex_normal(n1[0], n1[1], n1[2])
        
        add_vertex_position(p2[0], p2[1], p2[2])
        add_vertex_normal(n2[0], n2[1], n2[2])
        
        add_vertex_position(p3[0], p3[1], p3[2])
        add_vertex_normal(n3[0], n3[1], n3[2])
        
        # Check for buffer overflow before next triangle
        if count >= MAX_COUNT - PRIM_SIZE_TRIANGLES:
            flush_and_render(gl, gl.TRIANGLES)

# Main loop
for each voxel in grid:
    field_values = compute_field(voxel)
    process_voxel(voxel_index, edge_table, triangle_table, field_values)

# Final flush
flush_and_render(gl, gl.TRIANGLES)
```

**Parameters:**
- `maxCount`: 4096 [S1, unofficial].
- `primsize`: 3 for triangles [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Buffer Overflow:** The code checks if `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].
- **Precision:** Linear interpolation is used for vertex positions and normals [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot M)$ where $N$ is the number of voxels and $M$ is the number of metaballs (for field generation). Marching cubes extraction is $O(N)$ per frame.
- **Memory Complexity:** $O(1)$ persistent memory for mesh data, as geometry is not stored. Fixed buffer size of $4096 \times 3 \times 4$ bytes $\approx 48$ KB for positions [S1, unofficial].
- **Measured Performance:** Limited by CPU bottlenecks at high resolutions or blob counts [S1, unofficial].
- **Strengths:** Simple implementation, serves as a good reference, minimal CPU-GPU transfer for small scenes.
- **Limitations:** Poor scalability due to CPU-bound field generation and geometry processing. Immediate mode rendering incurs overhead from frequent draw calls if batching is not efficient.
- **When to use:** Reference implementation, educational purposes, or very small scenes where GPU setup overhead is prohibitive.
- **When not to use:** Large-scale volume rendering, real-time applications with high resolution or many objects.

## Background
The CPU Immediate Mode Marching Cubes implementation is inspired by Gregg Tavares' (Greggman) "Metaballs in JavaScript" demo [S1, unofficial]. It uses classic Marching Cubes tables from Paul Bourke [S1, unofficial]. The project is part of the `WebGL2-GPU-Marching-Cubes` repository by 3merillon [S1, unofficial].
