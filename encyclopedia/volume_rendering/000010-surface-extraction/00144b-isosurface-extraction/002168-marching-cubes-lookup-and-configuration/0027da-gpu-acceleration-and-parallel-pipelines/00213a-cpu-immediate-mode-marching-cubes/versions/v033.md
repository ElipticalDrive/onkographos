# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It differs from sibling methods like [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by performing all field generation and geometry computation on the CPU, bypassing GPU parallel dispatch and atomic buffer management [S1, unofficial]. This approach serves as a reference implementation for correctness but is limited in performance at high resolutions or high blob counts due to CPU bottlenecks [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   A 3D scalar field grid of size $N_x \times N_y \times N_z$.
*   A list of metaballs (or sources) defining the scalar field contributions.
*   An isosurface threshold value.
*   Precomputed Marching Cubes lookup tables (`edgeTable`, `triangleTable`) as defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).
*   WebGL context and shader programs.

**Outputs:**
*   Rendered triangles on the screen via WebGL `drawArrays` calls.
*   No persistent mesh data structure is retained in CPU memory between frames.

### Data Structures
The implementation uses typed arrays to store vertex attributes for batching. The maximum number of vertices per batch is `maxCount` = 4096 [S1, unofficial].

*   `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
*   `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(nx, ny, nz)$.
*   `uvArray`: `Float32Array` of size `maxCount * 2`. Stores UV coordinates (optional).
*   `colorArray`: `Float32Array` of size `maxCount * 4`. Stores vertex colors (optional).
*   `count`: Integer tracking the number of vertices currently in the batch.
*   `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated.

### Steps

1.  **Field Generation**: Compute the scalar value for each voxel in the $N_x \times N_y \times N_z$ grid. For each voxel, accumulate contributions from all metaballs and a floor term [S1, unofficial].
    *   Formula for metaball contribution at position $\mathbf{p}$ from source $\mathbf{s}_i$ with radius $r_i$:
        $$ V_i(\mathbf{p}) = \frac{r_i^2}{\|\mathbf{p} - \mathbf{s}_i\|^2} $$
    *   Total field value $V(\mathbf{p}) = \sum_i V_i(\mathbf{p}) + V_{floor}$ [S1, unofficial].

2.  **Primitive Batching Initialization**:
    *   Set primitive type `prim` (e.g., `TRIANGLES`).
    *   Calculate `primsize` (3 for triangles).
    *   Store program reference.
    *   Reset `count` to 0.
    *   Reset `hasPos`, `hasNormal`, `hasUV`, `hasColor` to `false` [S1, unofficial].

3.  **Voxel Processing**: Iterate through each voxel $(i, j, k)$ in the grid.
    *   **Boundary Check**: Verify that all 8 corner vertices exist within the volume bounds. If not, skip or handle appropriately to avoid out-of-bounds access [S1, unofficial].
    *   **Case Determination**: Sample the scalar field at the 8 corners. Determine the case index $C$ by comparing each corner value to the isosurface threshold.
    *   **Lookup**: Access `edgeTable[C]` to identify intersected edges and `triangleTable[C]` to identify triangle vertex indices [S1, unofficial].
    *   **Vertex Interpolation**: For each intersected edge, interpolate the vertex position and normal.
        *   Position $\mathbf{v}$ on edge between corners $\mathbf{c}_1$ (value $v_1$) and $\mathbf{c}_2$ (value $v_2$):
            $$ \mathbf{v} = \mathbf{c}_1 + \frac{T - v_1}{v_2 - v_1} (\mathbf{c}_2 - \mathbf{c}_1) $$
            where $T$ is the isosurface threshold.
        *   Normal $\mathbf{n}$ is computed via gradient of the scalar field at $\mathbf{v}$ or interpolated from corner normals.
    *   **Add Vertex**:
        *   Store position in `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos = true` [S1, unofficial].
        *   Store normal in `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal = true` [S1, unofficial].
    *   **Add Triangle**:
        *   Copy positions and normals for the three vertices of the triangle into `posArray` and `normalArray` starting at index `count * 3`.
        *   Increment `count` by 3.
        *   **Overflow Check**: If `count >= maxCount - 3`, call `draw()` to flush the buffer [S1, unofficial].

4.  **Flush and Render**:
    *   If `count == 0`, return.
    *   Zero out remaining entries in `posArray` and `normalArray` from `count * 3` to `length` to prevent garbage data [S1, unofficial].
    *   Bind buffers for any enabled attributes using `gl.bufferData` with `DYNAMIC_DRAW`.
    *   Enable vertex attribute arrays and set pointers.
    *   Call `gl.drawArrays` with `prim`, offset 0, and count [S1, unofficial].
    *   Reset `count` to 0.

def cpu_immediate_marching_cubes(grid, blobs, threshold, max_count=4096):
    """
    Renders marching cubes mesh using immediate mode WebGL calls.
    grid: 3D array of scalar values [Nx, Ny, Nz]
    blobs: list of metaball definitions
    threshold: isosurface value
    """
    # Initialize batching state
    count = 0
    has_pos = False
    has_normal = False
    prim_size = 3  # For triangles
    
    # Pre-allocate arrays
    pos_array = [0.0] * (max_count * 3)
    normal_array = [0.0] * (max_count * 3)
    
    # 1. Field Generation (Optimization: Blob Influence Culling)
    # In a full implementation, only update voxels influenced by blobs.
    # Here, we assume grid is pre-computed or computed on the fly.
    # For each voxel, accumulate contributions from blobs and floor.
    
    # 2. Process Voxels
    for i in range(Nx - 1):
        for j in range(Ny - 1):
            for k in range(Nz - 1):
                # Boundary check: ensure 8 corners exist
                if not all_valid(i, j, k, Nx, Ny, Nz):
                    continue
                
                # Get corner values
                v000 = grid[i][j][k]
                v100 = grid[i+1][j][k]
                v010 = grid[i][j+1][k]
                v110 = grid[i+1][j+1][k]
                v001 = grid[i][j][k+1]
                v101 = grid[i+1][j][k+1]
                v011 = grid[i][j+1][k+1]
                v111 = grid[i+1][j+1][k+1]
                
                # Determine case index C
                C = determine_case(v000, v100, v010, v110, v001, v101, v011, v111, threshold)
                
                if C == 0:
                    continue
                
                # Lookup tables from [Marching Cubes Lookup and Configuration]
                edges = edge_table[C]
                triangles = triangle_table[C]
                
                # Interpolate vertices for intersected edges
                vertices = []
                normals = []
                for edge_idx in edges:
                    if edge_idx == -1:
                        break
                    p1, p2 = get_edge_corners(i, j, k, edge_idx)
                    v1, v2 = get_corner_values(p1, p2, grid)
                    # Linear interpolation
                    t = (threshold - v1) / (v2 - v1)
                    pos = lerp(p1, p2, t)
                    norm = lerp(normal(p1), normal(p2), t) # Gradient-based or interpolated
                    vertices.append(pos)
                    normals.append(norm)
                
                # Add triangles
                for tri in triangles:
                    if tri == -1:
                        break
                    v1_idx, v2_idx, v3_idx = tri
                    # Add vertex 1
                    add_vertex(pos_array, normal_array, vertices[v1_idx], normals[v1_idx], count)
                    # Add vertex 2
                    add_vertex(pos_array, normal_array, vertices[v2_idx], normals[v2_idx], count)
                    # Add vertex 3
                    add_vertex(pos_array, normal_array, vertices[v3_idx], normals[v3_idx], count)
                    count += 3
                    
                    # Overflow check
                    if count >= max_count - 3:
                        flush_and_draw(pos_array, normal_array, count, has_pos, has_normal)
                        count = 0
                        has_pos = False
                        has_normal = False
    
    # Final flush
    if count > 0:
        flush_and_draw(pos_array, normal_array, count, has_pos, has_normal)

def add_vertex(pos_array, normal_array, pos, norm, count):
    pos_array[count * 3] = pos[0]
    pos_array[count * 3 + 1] = pos[1]
    pos_array[count * 3 + 2] = pos[2]
    normal_array[count * 3] = norm[0]
    normal_array[count * 3 + 1] = norm[1]
    normal_array[count * 3 + 2] = norm[2]

### Parameters
*   `maxCount`: 4096 [S1, unofficial].
*   `primsize`: 3 for triangles [S1, unofficial].

### Edge Cases and Pitfalls
*   **Buffer Overflow**: If `count >= maxCount - 3`, the buffer must be flushed immediately to ensure space for a full triangle (3 vertices) [S1, unofficial].
*   **Boundary Access**: Threads/voxels at the grid boundary must verify that all 8 corner vertices exist to avoid out-of-bounds memory access when sampling the scalar field [S1, unofficial].
*   **Precision**: Linear interpolation assumes smooth fields; sharp discontinuities may cause artifacts.

## Operating characteristics
*   **Time Complexity**: $O(N_x N_y N_z)$ for field generation and voxel processing. Each voxel requires constant-time lookup and interpolation.
*   **Memory Complexity**: $O(N_x N_y N_z)$ for the scalar field grid. $O(maxCount)$ for the immediate mode buffers.
*   **Measured Performance**: Limited by CPU bottlenecks at high resolutions (e.g., $128^3$) or high blob counts (e.g., 100 blobs) [S1, unofficial].
*   **Strengths**: Simple implementation, serves as a reference for correctness, minimal GPU memory management overhead.
*   **Limitations**: Poor scalability, high CPU usage, limited by single-threaded or poorly parallelized CPU execution.
*   **When to Use**: Reference implementation, debugging, low-resolution scenes, or when GPU resources are unavailable.
*   **When Not to Use**: High-resolution volumes, real-time applications with many objects, or when GPU acceleration is available.

## Background
The CPU Immediate Mode Marching Cubes method is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript [S1, unofficial]. It implements the classic marching cubes algorithm on the CPU, generating geometry and rendering it immediately via WebGL. This approach predates modern GPU-based parallel pipelines and serves as a foundational reference for understanding the algorithm's core logic without the complexity of GPU memory management and parallel dispatch [S1, unofficial].
