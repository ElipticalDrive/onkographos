# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals and renders them directly via immediate mode graphics calls (e.g., WebGL `gl.drawArrays`) without storing a persistent mesh buffer in GPU memory [S1, unofficial]. It differs from its siblings, such as [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md), by performing all scalar field computation and geometry generation on the CPU, transferring only small uniform updates and texture data per frame, rather than offloading the heavy lifting to the GPU [S1, unofficial]. It serves primarily as a reference implementation and for performance comparison against GPU-accelerated variants [S1, unofficial].

## How it works
The method operates on a 3D grid of voxels. For each voxel, it computes a scalar field value, determines the isosurface intersection using lookup tables, and immediately streams the resulting triangles to the graphics API.

### Inputs and Outputs
*   **Input**: A 3D grid of voxels defined by dimensions $(N_x, N_y, N_z)$. A scalar field $V(x,y,z)$ is computed for each voxel center or corner. An isovalue $I$ defines the surface threshold.
*   **Output**: A stream of triangle vertices and normals rendered to the screen.

### Data Structures
The implementation uses a batching system to manage immediate mode rendering.

**Buffers and Arrays:**
The `ImmSim` class maintains the following data structures [S1, unofficial]:
*   `posArray`: A `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
*   `normalArray`: A `Float32Array` of size `maxCount * 3`. Stores vertex normals $(nx, ny, nz)$.
*   `uvArray`: A `Float32Array` of size `maxCount * 2`. Stores UV coordinates.
*   `colorArray`: A `Float32Array` of size `maxCount * 4`. Stores vertex colors.
*   `maxCount`: The maximum number of vertices per batch, typically set to 4096 [S1, unofficial].
*   `count`: The current number of vertices added to the current batch, initialized to 0.
*   `prim`: The primitive type (e.g., `TRIANGLES`, `LINES`, `POINTS`) [S1, unofficial].
*   `primsize`: The number of vertices per primitive (3 for triangles, 2 for lines, 1 for points) [S1, unofficial].
*   `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated for the current batch [S1, unofficial].

**Lookup Tables:**
The algorithm relies on the standard Marching Cubes lookup tables described in [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md) [G]:
1.  **`edgeTable`**: 256-entry array of 12-bit bitmasks indicating intersected edges.
2.  **`triangleTable`**: $256 \times 16$ array of integers defining triangle vertex indices on cube edges, terminated by `-1`.

### Steps

1.  **Field Generation**: For each voxel in the 3D grid, compute the scalar field value $V$ at its 8 corners. In the reference implementation, this involves accumulating contributions from metaballs and a floor term [S1, unofficial].
2.  **Case Index Calculation**: For each voxel, calculate the 8-bit case index $C$ based on the signs of $(V(v_i) - I)$ at the 8 vertices $v_i$ [G].
3.  **Lookup and Interpolation**:
    *   Retrieve the edge mask from `edgeTable[C]`.
    *   For each intersected edge, compute the intersection point $P$ by linear interpolation between the two vertices of the edge. Let vertices be $A$ and $B$ with values $V_A$ and $V_B$. The interpolation factor $t$ is:
        $$ t = \frac{I - V_A}{V_B - V_A} $$
        $$ P = A + t(B - A) $$
    *   Compute the normal $N$ at $P$ by interpolating the gradients at $A$ and $B$, or by computing the gradient of the scalar field at $P$ [S1, unofficial].
4.  **Triangle Generation**:
    *   Retrieve the triangle indices from `triangleTable[C]`.
    *   For each triplet of edge indices $(e_a, e_b, e_c)$, generate a triangle using the previously computed intersection points $P_a, P_b, P_c$ and their normals $N_a, N_b, N_c$.
5.  **Immediate Mode Batching**:
    *   **Add Vertex**: Store $P$ into `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos = true` [S1, unofficial].
    *   **Add Normal**: Store $N$ into `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal = true` [S1, unofficial].
    *   **Add Triangle**: Copy positions and normals for the three vertices into the arrays starting at `count*3`. Increment `count` by 3 [S1, unofficial].
    *   **Overflow Check**: If `count >= maxCount - 3`, call the flush function to render the current batch and reset [S1, unofficial].
6.  **Flush and Render**:
    *   If `count == 0`, return.
    *   Zero out remaining entries in `posArray` and `normalArray` from `count*3` to the end to prevent garbage data [S1, unofficial].
    *   Bind `posArray` to `posBuf` and `normalArray` to `normalBuf` using `gl.bufferData` with `DYNAMIC_DRAW` [S1, unofficial].
    *   Enable vertex attribute arrays for any active flags (`hasPos`, `hasNormal`, etc.) and set pointers using `gl.vertexAttribPointer` [S1, unofficial].
    *   Call `gl.drawArrays(prim, 0, count)` [S1, unofficial].
    *   Reset `count` to 0.

```python
# Constants
MAX_COUNT = 4096
PRIM_SIZE = 3  # For TRIANGLES

# Data structures
pos_array = [0.0] * (MAX_COUNT * 3)
normal_array = [0.0] * (MAX_COUNT * 3)
count = 0
has_pos = False
has_normal = False

def add_vertex(pos, normal):
    global count, has_pos, has_normal
    idx = count * 3
    pos_array[idx] = pos[0]
    pos_array[idx + 1] = pos[1]
    pos_array[idx + 2] = pos[2]
    normal_array[idx] = normal[0]
    normal_array[idx + 1] = normal[1]
    normal_array[idx + 2] = normal[2]
    has_pos = True
    has_normal = True
    count += 1
    if count >= MAX_COUNT - 3:
        flush_and_render()

def flush_and_render():
    global count, has_pos, has_normal
    if count == 0:
        return
    
    # Zero out remaining buffer space to avoid garbage
    for i in range(count * 3, MAX_COUNT * 3):
        pos_array[i] = 0.0
        normal_array[i] = 0.0
        
    # Bind buffers (pseudo-code for WebGL context)
    # gl.bindBuffer(gl.ARRAY_BUFFER, pos_buf)
    # gl.bufferData(gl.ARRAY_BUFFER, pos_array, gl.DYNAMIC_DRAW)
    # gl.bindBuffer(gl.ARRAY_BUFFER, normal_buf)
    # gl.bufferData(gl.ARRAY_BUFFER, normal_array, gl.DYNAMIC_DRAW)
    
    # Enable attributes
    # if has_pos:
    #     gl.enableVertexAttribArray(pos_attr)
    #     gl.vertexAttribPointer(pos_attr, 3, gl.FLOAT, False, 0, 0)
    # if has_normal:
    #     gl.enableVertexAttribArray(normal_attr)
    #     gl.vertexAttribPointer(normal_attr, 3, gl.FLOAT, False, 0, 0)
        
    # Draw
    # gl.drawArrays(gl.TRIANGLES, 0, count)
    
    # Reset state
    count = 0
    has_pos = False
    has_normal = False

def process_voxel(v_min, v_max, isovalue, edge_table, triangle_table):
    # v_min and v_max are the 8 corner values of the voxel
    # Calculate case index C
    C = 0
    for i in range(8):
        if v_min[i] < isovalue:
            C |= (1 << i)
            
    # Get edge mask
    edge_mask = edge_table[C]
    
    # Compute intersection points and normals for intersected edges
    intersections = []
    normals = []
    for e in range(12):
        if (edge_mask >> e) & 1:
            # Get vertices of edge e
            v1, v2 = get_edge_vertices(e)
            val1, val2 = v_min[v1], v_min[v2]
            
            # Interpolate position
            t = (isovalue - val1) / (val2 - val1)
            p = lerp(get_voxel_corner(v1), get_voxel_corner(v2), t)
            
            # Interpolate normal (simplified)
            n = lerp(get_gradient(v1), get_gradient(v2), t)
            n = normalize(n)
            
            intersections.append(p)
            normals.append(n)
            
    # Generate triangles from triangle_table
    tri_indices = triangle_table[C]
    i = 0
    while tri_indices[i] != -1:
        e1 = tri_indices[i]
        e2 = tri_indices[i+1]
        e3 = tri_indices[i+2]
        
        add_vertex(intersections[e1], normals[e1])
        add_vertex(intersections[e2], normals[e2])
        add_vertex(intersections[e3], normals[e3])
        
        i += 3
```

### Parameters and Edge Cases
*   **maxCount**: Set to 4096 in the reference implementation [S1, unofficial].
*   **Buffer Overflow**: The check `count >= maxCount - 3` ensures there is space for a full triangle (3 vertices) before adding it. If this condition is met, the buffer is flushed immediately [S1, unofficial].
*   **Ambiguity**: Cases 46, 47, 98, 99, 210, 213, 214, 215 may produce topological errors if not handled. The standard LUT is used, which may cause cracks if adjacent voxels resolve ambiguities inconsistently [Lookup Table and Ambiguity Handling](10327-lookup-table-and-ambiguity-handling.md) [G].

## Operating characteristics
*   **Time Complexity**: $O(N_x N_y N_z)$ for field generation and mesh extraction. The constant factor is high due to CPU-bound scalar field computation and per-vertex overhead.
*   **Memory Complexity**: $O(N_x N_y N_z)$ for the scalar field grid. The immediate mode buffer is fixed at `maxCount` vertices, independent of scene size, but limits the number of triangles rendered per frame to `maxCount / 3`.
*   **Performance**: Limited by CPU bottlenecks at high resolutions or high blob counts. It is significantly slower than GPU-based methods for large grids [S1, unofficial].
*   **Strengths**: Simple implementation, serves as a good reference, minimal GPU memory usage for mesh storage.
*   **Limitations**: Poor scalability, high CPU usage, limited by `maxCount` per frame (requires multiple draw calls for large scenes).

## Background
The CPU Immediate Mode Marching Cubes implementation is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript [S1, unofficial]. It uses classic Marching Cubes tables from Paul Bourke [S1, unofficial]. The project is part of the `WebGL2-GPU-Marching-Cubes` repository by 3merillon, which provides both CPU and GPU implementations for comparison [S1, unofficial].
