# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals and renders them directly via graphics API draw calls (e.g., WebGL `gl.drawArrays`) without storing a persistent, complex mesh data structure in application memory [S1, unofficial]. It solves the problem of visualizing scalar fields (such as metaballs) by computing the geometry on the CPU every frame and streaming it to the GPU. It is distinguished from its siblings, such as [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md), by performing all field evaluation, topology classification, and vertex interpolation on the CPU, whereas the GPU siblings offload these computations to shaders [S1, unofficial].

## How it works
The method operates in two main phases: field generation and immediate-mode mesh extraction/rendering. It builds on the topology logic defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md).

### Inputs and Outputs
**Inputs:**
*   A 3D grid of voxels with dimensions $N_x \times N_y \times N_z$.
*   A set of metaballs (or scalar field sources), each defined by a center position $\mathbf{c}_i$, a radius $r_i$, and an intensity $k_i$.
*   An isovalue $I$ for surface extraction.
*   A maximum vertex buffer capacity `maxCount` (typically 4096) [S1, unofficial].

**Outputs:**
*   Rendered triangles on the screen via immediate mode draw calls.

### Data Structures
The implementation maintains a set of typed arrays to buffer vertex attributes before flushing to the GPU [S1, unofficial]:

1.  **`posArray`**: A `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
2.  **`normalArray`**: A `Float32Array` of size `maxCount * 3`. Stores vertex normals $(n_x, n_y, n_z)$.
3.  **`uvArray`**: A `Float32Array` of size `maxCount * 2`. Stores UV coordinates (if enabled).
4.  **`colorArray`**: A `Float32Array` of size `maxCount * 4`. Stores vertex colors (if enabled).
5.  **`count`**: An integer tracking the number of vertices currently stored in the arrays.
6.  **`prim`**: The primitive type (e.g., `TRIANGLES`, `LINES`, `POINTS`).
7.  **`primsize`**: The number of vertices per primitive (3 for triangles, 2 for lines, 1 for points).

### Steps

#### 1. Field Generation
For each voxel in the 3D grid, compute the scalar field value $V$ at the voxel's center or corners by accumulating contributions from all metaballs and a floor term [S1, unofficial]. For a metaball $i$ with center $\mathbf{c}_i$, radius $r_i$, and intensity $k_i$, the contribution to a point $\mathbf{p}$ is typically:
$$ V_i(\mathbf{p}) = \frac{k_i}{\|\mathbf{p} - \mathbf{c}_i\|^2 + \epsilon} $$
The total field value is the sum of all $V_i$ plus any background/floor terms.

#### 2. Marching Cubes Extraction
Iterate over each voxel in the grid. For each voxel:
1.  **Case Index Calculation**: Determine the 8-bit case index $C$ by comparing the scalar field values $V$ at the 8 vertices of the voxel against the isovalue $I$ [S7, S8, S12, unofficial].
2.  **Edge Intersection Lookup**: Use the `edgeTable` to identify which edges of the voxel are intersected by the isosurface [S4, S12, unofficial].
3.  **Vertex Interpolation**: For each intersected edge, interpolate the exact position of the intersection point using the scalar field values at the edge's endpoints. Calculate the vertex normal by computing the gradient of the scalar field at the intersection point.
4.  **Triangle Emission**: Use the `triangleTable` to determine the sequence of edge indices that form triangles [S8, S12, unofficial]. For each triangle, emit the three vertices and their normals.

#### 3. Immediate Mode Rendering
The emitted vertices are added to the buffer arrays and flushed to the GPU in batches to minimize draw calls [S1, unofficial].

1.  **Initialize Batching**: Set `prim` to the desired primitive type, calculate `primsize`, and reset `count` to 0. Initialize flags `hasPos`, `hasNormal`, `hasUV`, `hasColor` to false.
2.  **Add Vertices**: For each vertex generated by the extraction step:
    *   Store position $(x, y, z)$ into `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos = true`.
    *   Store normal $(n_x, n_y, n_z)$ into `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal = true`.
    *   Increment `count`.
3.  **Flush Check**: If `count >= maxCount - 3`, flush the buffer immediately to prevent overflow (see Pitfalls).
4.  **Flush and Render**: When the frame is complete or the buffer is full:
    *   If `count == 0`, return.
    *   Zero out remaining entries in `posArray` and other arrays from `count*3` to the end to ensure clean state.
    *   Bind the buffers (`posBuf`, `normalBuf`, etc.) to the WebGL context using `gl.bufferData` with `DYNAMIC_DRAW`.
    *   Enable vertex attribute arrays and set pointers to the data.
    *   Call `gl.drawArrays` with `prim`, offset 0, and `count`.
    *   Reset `count` to 0.

def marching_cubes_frame(grid, isovalue, edge_table, triangle_table):
    """Main extraction loop."""
    for each voxel in grid:
        case_index = compute_case_index(voxel.vertices, isovalue)
        intersected_edges = edge_table[case_index]
        
        if intersected_edges is empty:
            continue

### Parameters
*   `maxCount`: The maximum number of vertices in the immediate mode buffer. Default is 4096 [S1, unofficial].
*   `isovalue`: The scalar threshold for surface extraction.
*   `prim`: The primitive type for rendering (e.g., `TRIANGLES`) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Buffer Overflow**: If the number of generated vertices exceeds `maxCount - 3`, the buffer cannot hold a complete triangle. The implementation must check `count >= maxCount - 3` before adding a vertex and flush immediately if true [S1, unofficial].
*   **Precision**: Using `Float32Array` for vertex storage may introduce precision errors at high resolutions or large coordinate values.
*   **Degenerate Input**: Voxels with no intersected edges (case index 0 or 255) should be skipped to avoid unnecessary processing.

## Operating characteristics
*   **Time Complexity**: $O(N \cdot M)$, where $N$ is the number of voxels and $M$ is the number of metaballs (for field generation). The extraction step is $O(N)$ assuming constant-time table lookups.
*   **Memory Complexity**: $O(maxCount)$ for the vertex buffers. The scalar field grid requires $O(N_x N_y N_z)$ memory.
*   **Performance**: Limited by CPU bottlenecks, especially at high resolutions or with many metaballs. It is significantly slower than GPU-based methods [S1, unofficial].
*   **Strengths**: Simple implementation, serves as a good reference for the algorithm, minimal CPU-GPU data transfer overhead for small meshes.
*   **Limitations**: Poor scalability, high CPU usage, limited by `maxCount` buffer size.
*   **When to use**: For educational purposes, debugging, or small-scale visualizations where GPU implementation is not available or practical.
*   **When not to use**: For real-time applications with high-resolution grids or complex scenes.

## Background
The CPU Immediate Mode Marching Cubes method is inspired by Gregg Tavares' (Greggman) metaballs demo in JavaScript [S1, unofficial]. It represents a classic approach to real-time volume rendering before the widespread adoption of GPU-based compute shaders and parallel pipelines. The method relies on the precomputed Marching Cubes tables originally described by Paul Bourke [S1, unofficial].
