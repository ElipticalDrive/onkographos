# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals in immediate mode, rendering them directly via WebGL draw calls without storing a persistent mesh buffer [S1, unofficial]. It differs from sibling methods like [GPU Marching Cubes (Compute Shader)](4687-gpu-marching-cubes-compute-shader.md) by performing all field generation and geometry calculation on the CPU, relying on immediate-mode rendering APIs rather than parallel compute shaders or complex buffering strategies [S1, unofficial]. It serves as a reference implementation and for performance comparison, though it is limited by CPU bottlenecks at high resolutions or high blob counts [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field (voxel grid) representing the volume, typically generated by accumulating contributions from metaballs and a floor term for each voxel [S1, unofficial].
*   **Output:** A stream of triangles rendered directly to the screen via WebGL. No intermediate mesh object is stored in CPU memory between frames [S1, unofficial].

**Data Structures:**
The implementation uses a fixed-capacity buffer strategy with typed arrays for performance [S1, unofficial].
*   `maxCount`: The maximum number of vertices per frame, set to 4096 [S1, unofficial].
*   `posArray`: A `Float32Array` of size `maxCount * 3` storing vertex positions $(x, y, z)$ [S1, unofficial].
*   `normalArray`: A `Float32Array` of size `maxCount * 3` storing vertex normals $(x, y, z)$ [S1, unofficial].
*   `uvArray`: A `Float32Array` of size `maxCount * 2` (optional, for UV coordinates) [S1, unofficial].
*   `colorArray`: A `Float32Array` of size `maxCount * 4` (optional, for vertex colors) [S1, unofficial].
*   `posBuf`, `normalBuf`, `uvBuf`, `colorBuf`: WebGLBuffer objects corresponding to the data arrays [S1, unofficial].

**Precomputed Tables:**
The method relies on the standard Marching Cubes lookup tables defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md):
1.  **Edge Intersection Table (`edgeTable`)**: 256-entry bitmask array.
2.  **Triangle Connection Table (`triangleTable`)**: 256x16 array of edge indices.

**Algorithm Steps:**

1.  **Field Generation:** For each voxel $(i, j, k)$ in the 3D grid, compute the scalar field value $V(i, j, k)$ by accumulating contributions from all metaballs and a floor term [S1, unofficial].
    *   *Optimization:* Blob influence culling limits updates to only affected voxels [S1, unofficial].
2.  **Immediate Mode Setup:** Initialize the rendering state for the current frame [S1, unofficial]:
    *   Set primitive type `prim` (e.g., `TRIANGLES`).
    *   Calculate `primsize` (3 for triangles).
    *   Store program reference.
    *   Reset vertex `count` to 0.
    *   Reset attribute flags `hasPos`, `hasNormal`, `hasUV`, `hasColor` to false.
3.  **Voxel Processing:** Iterate through each voxel cube in the grid:
    *   Compute the case index $C$ using the 8 corner values $V(v_0) \dots V(v_7)$ and the isosurface threshold $I$:
        $$ C = \sum_{i=0}^{7} \mathbb{I}(V(v_i) < I) \cdot 2^i $$
    *   Look up `triangleTable[C]` to determine which edges are intersected.
    *   For each triangle defined by the table:
        *   Interpolate vertex positions at the edge intersections.
        *   Compute vertex normals (typically by averaging gradients or using precomputed gradient data).
        *   **Add Vertex Position:** Store $x, y, z$ into `posArray` at indices `[count*3 + 0]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasPos = true`.
        *   **Add Vertex Normal:** Store $x, y, z$ into `normalArray` at indices `[count*3]`, `[count*3 + 1]`, `[count*3 + 2]`. Set `hasNormal = true`.
        *   **Add Triangle:** Copy positions and normals for the three vertices into the arrays starting at `count*3`. Increment `count` by 3.
        *   **Overflow Check:** If `count >= maxCount - 3`, flush the buffer immediately (see Step 4).
4.  **Flush and Render:**
    *   If `count == 0`, return.
    *   Zero out remaining entries in `posArray` and `normalArray` from `count*3` to `length` to prevent garbage data [S1, unofficial].
    *   Bind buffers for any enabled attributes using `gl.bufferData` with `DYNAMIC_DRAW` [S1, unofficial].
    *   Enable vertex attribute arrays and set pointers to the data arrays [S1, unofficial].
    *   Call `gl.drawArrays` with the primitive type, offset 0, and count [S1, unofficial].
    *   Reset `count` to 0.

**Pseudocode:**

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Constants and state
MAX_COUNT = 4096
PRIM_SIZE = 3
pos_array = [0.0] * (MAX_COUNT * 3)
normal_array = [0.0] * (MAX_COUNT * 3)
count = 0
has_pos = False
has_normal = False

def interpolate_vertex(v0, v1, val0, val1, isosurface):
    """Linear interpolation between two cube corners to find isosurface intersection [G]."""
    t = (isosurface - val0) / (val1 - val0)
    return v0 + t * (v1 - v0)

def add_vertex_position(x, y, z):
    global count, has_pos
    pos_array[count * 3 + 0] = x
    pos_array[count * 3 + 1] = y
    pos_array[count * 3 + 2] = z
    has_pos = True

def add_vertex_normal(nx, ny, nz):
    global count, has_normal
    normal_array[count * 3 + 0] = nx
    normal_array[count * 3 + 1] = ny
    normal_array[count * 3 + 2] = nz
    has_normal = True

def add_triangle(o1, o2, o3):
    global count
    # Copy positions and normals for the three vertices into the arrays starting at count*3
    for i in range(3):
        pos_array[count * 3 + i] = pos_array[o1 * 3 + i]
        pos_array[count * 3 + 1 + i] = pos_array[o2 * 3 + i]
        pos_array[count * 3 + 2 + i] = pos_array[o3 * 3 + i]
        normal_array[count * 3 + i] = normal_array[o1 * 3 + i]
        normal_array[count * 3 + 1 + i] = normal_array[o2 * 3 + i]
        normal_array[count * 3 + 2 + i] = normal_array[o3 * 3 + i]
    count += 3
    if count >= MAX_COUNT - 3:
        flush_and_render(gl, PRIM_TYPE, pos_buf, normal_buf, has_pos, has_normal, count)

def flush_and_render(gl, prim_type, pos_buf, normal_buf, has_pos, has_normal, count):
    global count, has_pos, has_normal
    if count == 0:
        return
    # Zero out remaining entries to prevent garbage data
    for i in range(count * 3, len(pos_array)):
        pos_array[i] = 0.0
        normal_array[i] = 0.0
    # Bind buffers and set pointers (conceptual WebGL calls)
    if has_pos:
        gl.buffer_data(gl.ARRAY_BUFFER, pos_buf, pos_array, gl.DYNAMIC_DRAW)
        gl.enable_vertex_attrib_array(0)
        gl.vertex_attrib_pointer(0, 3, gl.FLOAT, False, 0, 0)
    if has_normal:
        gl.buffer_data(gl.ARRAY_BUFFER, normal_buf, normal_array, gl.DYNAMIC_DRAW)
        gl.enable_vertex_attrib_array(1)
        gl.vertex_attrib_pointer(1, 3, gl.FLOAT, False, 0, 0)
    # Draw
    gl.draw_arrays(prim_type, 0, count)
    # Reset
    count = 0
    has_pos = False
    has_normal = False
```

**Parameters:**
*   `maxCount`: 4096 [S1, unofficial].
*   Grid Resolution: $16^3, 32^3, 64^3, 128^3$ [S1, unofficial].
*   Blob Count: 1, 10, 50, 100 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** The code checks if `count >= maxCount - 3` before drawing to ensure space for a triangle (3 vertices). If exceeded, it flushes immediately [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** $O(N)$ for the field grid, plus $O(1)$ for the immediate mode buffer (fixed size 4096 vertices) [S1, unofficial].
*   **Measured Performance:** Limited by CPU bottlenecks. Performance is acceptable for low resolutions (e.g., $16^3, 32^3$) and few blobs, but degrades rapidly at $64^3$ or higher, or with many blobs [S1, unofficial].
*   **Strengths:** Simple implementation, serves as a good reference, minimal CPU-GPU transfer overhead (only uniform and texture updates per frame) [S1, unofficial].
*   **Limitations:** Poor scalability, CPU-bound, not suitable for real-time high-resolution rendering [S1, unofficial].
*   **When to Use:** For educational purposes, reference implementations, or low-performance scenarios where GPU acceleration is unavailable or undesirable [S1, unofficial].
*   **When Not to Use:** For real-time applications requiring high resolution or many dynamic objects [S1, unofficial].

## Background
The CPU Immediate Mode Marching Cubes method is inspired by Gregg Tavares (Greggman)'s "Metaballs in JavaScript" demo [S1, unofficial]. It was implemented as part of the `WebGL2-GPU-Marching-Cubes` project by 3merillon to provide a CPU-based alternative to the GPU compute shader implementation [S1, unofficial]. The project uses Paul Bourke's Marching Cubes tables for the lookup configuration [S1, unofficial].
