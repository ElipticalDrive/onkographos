# CPU Immediate Mode Marching Cubes

Also called: CPU Immediate Sim, Immediate Mode Marching Cubes, Legacy Marching Cubes

## Overview
CPU Immediate Mode Marching Cubes is a classic CPU-based surface extraction method that generates mesh vertices and normals and renders them directly via graphics API draw calls (e.g., WebGL) without storing a persistent mesh buffer in application memory [S1, unofficial]. It differs from sibling methods like [GPU Acceleration and Parallel Pipelines](4136-gpu-acceleration-and-parallel-pipelines.md) by performing the scalar field evaluation and geometry generation on the CPU, and from [Capacity-safe slab-based Marching Cubes](4595-capacity-safe-slab-based-marching-cubes.md) by using immediate-mode batching rather than pre-allocated capacity buffers. It serves primarily as a reference implementation for correctness and simplicity [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D grid of voxels. For each voxel, a scalar field value $V$ is computed. The scalar field is generated by accumulating contributions from metaballs (blobs) and a floor term for each voxel [S1, unofficial].
*   **Output:** A stream of triangles (positions and normals) rendered immediately to the GPU.

**Data Structures:**
The method uses fixed-size typed arrays to buffer vertex data before flushing to the GPU [S1, unofficial].
*   `posArray`: `Float32Array` of size `maxCount * 3`. Stores vertex positions $(x, y, z)$.
*   `normalArray`: `Float32Array` of size `maxCount * 3`. Stores vertex normals $(nx, ny, nz)$.
*   `uvArray`: `Float32Array` of size `maxCount * 2`. Stores UV coordinates (if enabled).
*   `colorArray`: `Float32Array` of size `maxCount * 4`. Stores vertex colors (if enabled).
*   `maxCount`: Integer, typically 4096 [S1, unofficial].
*   `count`: Integer, tracking the number of vertices currently in the buffer.
*   `hasPos`, `hasNormal`, `hasUV`, `hasColor`: Boolean flags indicating which attributes are populated [S1, unofficial].

**Lookup Tables:**
The algorithm relies on the precomputed data structures defined in [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md):
1.  **Edge Intersection Table (`edgeTable`)**: 256 entries, 12-bit bitmask per entry.
2.  **Triangle Connection Table (`triangleTable`)**: $256 \times 16$ array. Rows indexed by case index $C$. Columns store edge indices grouped in triplets, terminated by `-1`.

**Algorithm Steps:**

1.  **Field Evaluation:** For each voxel in the 3D grid, compute the scalar field value $V$ by summing contributions from all metaballs and the floor term [S1, unofficial].
2.  **Case Index Calculation:** Determine the 8-bit case index $C$ for the current voxel based on the scalar values $V(v_i)$ at its 8 vertices relative to the isovalue $I$. If $V(v_i) < I$, bit $i$ is set to 1; otherwise 0. The bit assignment must match the vertex ordering assumed by the LUT [10327-lookup-table-and-ambiguity-handling].
3.  **Lookup:** Use $C$ to index into `edgeTable` to find intersected edges and `triangleTable` to find the triangle connectivity (triplets of edge indices) [S1, unofficial].
4.  **Vertex Interpolation:** For each intersected edge, interpolate the vertex position and normal on the isosurface.
    *   Position $P$ on edge between vertices $v_a$ and $v_b$ with values $V_a$ and $V_b$:
        $$ t = \frac{I - V_a}{V_b - V_a} $$
        $$ P = v_a + t \cdot (v_b - v_a) $$
    *   Normal $N$ is typically the normalized gradient of the scalar field at $P$, or interpolated from vertex normals [S1, unofficial].
5.  **Immediate Mode Batching:**
    *   Initialize `count = 0`.
    *   For each triangle generated:
        *   Add the 3 vertices to `posArray` and `normalArray`.
        *   Check for buffer overflow: If `count >= maxCount - 3`, flush the buffer (see Flush step).
        *   Increment `count` by 3.
    *   **Flush:**
        *   If `count == 0`, return.
        *   Zero out remaining entries in `posArray` and `normalArray` from `count * 3` to `length` to prevent garbage data [S1, unofficial].
        *   Bind `posArray` and `normalArray` to GPU buffers using `gl.bufferData` with `DYNAMIC_DRAW` [S1, unofficial].
        *   Enable vertex attribute arrays and set pointers to the buffer data [S1, unofficial].
        *   Call `gl.drawArrays` with primitive type `TRIANGLES`, offset 0, and count `count` [S1, unofficial].
        *   Reset `count = 0`.

**Edge Cases and Pitfalls:**
*   **Buffer Overflow:** The code checks `count >= maxCount - 3` before drawing to ensure space for a triangle. If exceeded, it flushes immediately [S1, unofficial].
*   **Ambiguity:** Cases 46, 47, 98, 99, 210, 213, 214, 215 contain saddle points. The standard LUT uses a fixed triangulation, which can cause cracks if adjacent voxels resolve ambiguity differently [10327-lookup-table-and-ambiguity-handling].
*   **Precision:** Floating-point interpolation errors may cause small gaps at high resolutions.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels. Each voxel is processed independently.
*   **Memory Complexity:** $O(1)$ auxiliary memory (fixed-size buffers). The scalar field storage is $O(N)$ if stored, or $O(1)$ if computed on the fly per voxel (though typically stored for efficiency).
*   **Measured Performance:** Limited by CPU bottlenecks at high resolutions or high blob counts [S1, unofficial].
*   **Strengths:** Simple implementation, easy to debug, serves as a reference for GPU implementations.
*   **Limitations:** Poor scalability due to CPU-bound field evaluation and geometry generation. High CPU-GPU transfer overhead if not batched effectively.
*   **When to use:** Reference implementation, low-resolution previews, or educational purposes.
*   **When not to use:** High-resolution real-time rendering, large datasets.

## Background
The CPU Immediate Mode Marching Cubes implementation is inspired by Gregg Tavares' (Greggman) metaballs demo [S1, unofficial]. It uses classic Marching Cubes tables from Paul Bourke [S1, unofficial]. The project is part of the `WebGL2-GPU-Marching-Cubes` repository by 3merillon [S1, unofficial].
