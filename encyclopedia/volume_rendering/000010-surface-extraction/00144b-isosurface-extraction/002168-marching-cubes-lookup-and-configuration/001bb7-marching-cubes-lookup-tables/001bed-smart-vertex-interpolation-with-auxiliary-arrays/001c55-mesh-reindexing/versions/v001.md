# Mesh Reindexing

Also called: Global ID Assignment, Isosurface Point Deduplication, Vertex Deduplication via Mapping

## Overview
Mesh Reindexing deduplicates vertices generated during isosurface extraction (such as Marching Cubes or Marching Tetrahedra) by assigning contiguous global IDs to geometrically unique points and reconstructing the final vertex and index buffers [S1, S2]. It ensures that vertices shared by adjacent cells (e.g., cubes or tetrahedra) share the same index in the final output, preventing duplicate geometry and reducing memory usage [S1, S2].

## How it works
**Inputs:**
- `vertexMapping`: A mapping from local edge/cell identifiers to vertex coordinates (and potentially normals). In [S1], this is a `std::map<size_t, IdPoint>` where `IdPoint` contains `id`, `x`, `y`, `z`. In [S2], vertices are stored in a structure allowing lookup by coordinate string keys.
- `triangles`: A list of triangles, where each triangle references vertices by their local identifiers (indices into `vertexMapping` or temporary local IDs).

**Outputs:**
- `vertices`: An array of unique vertex positions.
- `normals`: An array of unique vertex normals (if computed).
- `faces`: An array of triangle indices referencing the unique `vertices` array.

**Data Structures:**
- `PointIdMapping` (from [S1]): `std::map<size_t, IdPoint>`. Key is a unique edge ID (e.g., `edgeId(x, y, z, edgeIndex, xDim, yDim)`). Value is `IdPoint` struct with `size_t id` and `float x, y, z`.
- `pointIndex` (from [S2]): A hash map or dictionary mapping a string representation of coordinates (e.g., `toString()`) to a global integer index.
- `isosurfacePoints` (from [S2]): A list/vector of unique vertex coordinates.
- `isosurfaceTriangles` (from [S2]): A list/vector of `vtkTriangle` or similar structures containing three global vertex indices.

**Steps:**
1. **Initialize:** Create an empty `pointIndex` map (if using [S2] style) or prepare to iterate `vertexMapping` (if using [S1] style). Initialize `nextId = 0`.
2. **Iterate and Deduplicate:**
   - For each entry in `vertexMapping` (or for each unique vertex coordinate):
     - **Method A ([S1]):** Iterate through the `vertexMapping` map. Assign a sequential global ID to each vertex.
       - `globalId = nextId++`
       - Store the mapping from the local key to `globalId`.
     - **Method B ([S2]):** Convert vertex coordinates to a string key using `toString()`.
       - If `key` is not in `pointIndex`:
         - Insert the point into `isosurfacePoints`.
         - Store `nextId` in `pointIndex[key]`.
         - `nextId++`
       - Else:
         - Retrieve the existing index from `pointIndex[key]`.
3. **Update Triangle Indices:**
   - For each triangle in the input list:
     - Replace each local vertex identifier with its corresponding global ID from the mapping established in Step 2.
     - In [S1], this involves looking up the global ID for each of the three points.
     - In [S2], create a `vtkTriangle` using the deduplicated vertex indices and insert it into `isosurfaceTriangles`.
4. **Construct Final Buffers:**
   - Allocate a `Point` array for vertices of size `nextId`.
   - Copy coordinates from `vertexMapping` (or `isosurfacePoints`) into the final vertex array.
   - Allocate a `size_t` array for triangle indices of size `3 * faceCount`.
   - Copy the updated global point IDs from the triangles vector into the final face array.
   - [S1] also computes vertex normals by accumulating normals from adjacent triangles and normalizing them [S1].

**Pseudocode:**
```python
def mesh_reindex(vertex_mapping, triangles):
    """
    vertex_mapping: dict mapping local_id -> (x, y, z)
    triangles: list of tuples (local_id_1, local_id_2, local_id_3)
    Returns: (vertices, faces)
    """
    # Step 1: Create a mapping from local_id to global_id
    local_to_global = {}
    next_id = 0
    
    # Iterate through all unique vertices in the mapping
    # Note: vertex_mapping keys are unique local identifiers for edges/vertices
    for local_id in vertex_mapping:
        local_to_global[local_id] = next_id
        next_id += 1
        
    # Step 2: Build the unique vertices array
    # We need to preserve the order or map back. 
    # Since vertex_mapping is a dict, we can iterate it again or store coords during ID assignment.
    # Let's assume we store coords in a list as we assign IDs.
    vertices = []
    for local_id in vertex_mapping:
        x, y, z = vertex_mapping[local_id]
        vertices.append((x, y, z))
        
    # Step 3: Update triangle indices
    faces = []
    for tri in triangles:
        global_ids = []
        for local_id in tri:
            # If a local_id was not in vertex_mapping (e.g., degenerate case), handle appropriately
            if local_id in local_to_global:
                global_ids.append(local_to_global[local_id])
            else:
                # [G] Fallback: assign a new ID if missing, though this indicates a logic error in prior steps
                global_ids.append(next_id)
                next_id += 1
                vertices.append((0, 0, 0)) # [G] Placeholder for missing vertex
        faces.append(global_ids)
        
    return vertices, faces
```

**Edge Cases and Pitfalls:**
- **Degenerate Triangles:** Triangles with identical vertices (e.g., all three points are the same) should be filtered out before or during reindexing [S2].
- **Precision:** Floating-point comparisons for deduplication must use a tolerance. Using string keys [S2] implies a specific formatting precision; slight floating-point errors may cause duplicate vertices to be treated as distinct if not handled with a tolerance-based hash or spatial grid.
- **Boundary Conditions:** In [S1], specific edge cases at grid boundaries (`x == xDim - 1`, etc.) are handled explicitly to ensure all relevant edges are processed [S1].

## Operating characteristics
- **Time Complexity:** $O(V \log V)$ or $O(V)$ depending on the data structure used for `vertexMapping` (hash map vs. tree map), where $V$ is the number of unique vertices. Iterating through triangles is $O(F)$, where $F$ is the number of faces.
- **Memory Complexity:** $O(V + F)$ to store the unique vertices and the final face indices. The intermediate `vertexMapping` also requires $O(V)$ space.
- **Strengths:** Significantly reduces the size of the final mesh by eliminating duplicates. Essential for efficient rendering and further processing (e.g., smoothing, collision detection).
- **Limitations:** Requires an additional pass over the data. Hash-based deduplication [S2] may have overhead for very large meshes if hash collisions are frequent or if string conversion is expensive.

## Background
Mesh Reindexing is a standard post-processing step in isosurface extraction algorithms like Marching Cubes [S1] and Marching Tetrahedra [S2]. It addresses the inherent redundancy in cell-based extraction methods where each cell independently computes vertices on shared edges. The technique is widely used in scientific visualization libraries such as VTK [S2] and custom implementations like those in ilastik [S1].
