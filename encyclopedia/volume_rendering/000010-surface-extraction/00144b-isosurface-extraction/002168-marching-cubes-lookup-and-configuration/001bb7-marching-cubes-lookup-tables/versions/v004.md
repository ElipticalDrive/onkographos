# Marching Cubes Lookup Tables

Also called: MC Lookup Table, MC Case Tables, Tri Table, Cube Configuration Tables, Lorensen and Cline Lookup Tables, Paul Bourke's table, Precalculated lookup table for Marching Cubes

## Overview
Marching Cubes Lookup Tables are precomputed data structures that map the 256 possible binary configurations of a voxel's corner signs relative to an isovalue to the triangle definitions required for mesh generation [S2, S3, S4]. This method solves the problem of determining mesh topology without runtime branching logic, enabling efficient traversal on both CPU and GPU architectures [S2, S5]. It builds on [Isosurface extraction](30-isosurface-extraction.md) by replacing conditional topology checks with direct table indexing [S4].

## How it works
The method uses precomputed tables to determine which edges of a cubic voxel are intersected by the isosurface and how to connect those intersections into triangles [S2, S4]. Implementations typically use a Triangle Table, and optionally an Edge Table for bitmask optimization [S3, S6].

### Inputs and Outputs
*   **Input:** Scalar field values at the 8 vertices of a cubic voxel and a scalar isovalue [S2, S4].
*   **Output:** A list of triangle vertex indices representing the isosurface intersection within that voxel [S2, S5].

### Data Structures

#### Edge Table (`edgeTable`)
A 1D array of 256 integers. Each entry corresponds to a cube index $0 \dots 255$ [S3, S6]. The integer is a bitmask where bits $0$ through $11$ correspond to the 12 edges of a cube. A set bit indicates the isosurface intersects that edge [S3, S6].
*   **Layout:** `int edgeTable[256]` [S3, S6].
*   **Size:** 256 entries [S3, S6].
*   **Bit Packing:** Bit $k$ ($0 \le k < 12$) is 1 if edge $k$ is intersected, 0 otherwise [S3, S6].

#### Triangle Table (`triangleTable`)
A 2D array mapping each cube index to a sequence of indices forming triangles [S2, S4, S5]. The table is structured as `int triangleTable[256][16]` (or packed into `ulong` arrays for GPU memory bandwidth optimization) [S2, S4]. Each row contains a sequence of integers representing vertex or edge indices, terminated by $-1$ [S3, S4, S5]. The maximum number of triangles per cube is 5 (15 indices), leaving the 16th column for the terminator [S4].
*   **Layout:** `int triangleTable[256][16]` [S4].
*   **Size:** 256 rows, 16 columns [S2, S4].
*   **Content:** Each row contains a sequence of integers. Values reference the cube's 8 vertices ($0-7$) and 12 edges ($8-19$ or $0-11$ depending on implementation) [S3, S4, S5]. A triplet $(a, b, c)$ means "connect the intersection point on index $a$, index $b$, and index $c$ to form a triangle" [S2, S4].
*   **Terminator:** The sequence is terminated by $-1$ [S2, S3, S5].
*   **Padding:** The array is padded to 16 integers per row to allow fixed-size memory access [S2, S3].

### Numbered Steps

1.  **Calculate Cube Index:**
    For a given voxel with corner scalar values $v_0, \dots, v_7$, calculate the `cubeIndex` (0-255) based on which of the 8 corners are above the isovalue [S2, S4].
    $$ \text{cubeIndex} = \sum_{i=0}^{7} b_i 2^i $$
    where $b_i = 1$ if $v_i \ge u_{\text{isolevel}}$, else $0$ [S4].

2.  **Check for Empty/Full Cube:**
    If `cubeIndex` is 0 or 255, the isosurface does not intersect the cube [G]. Skip to the next voxel.

3.  **Lookup Triangle Configuration:**
    Access the Triangle Table:
    $$ \text{triConfig} = \text{triangleTable}[\text{cubeIndex}] $$
    This returns an array of integers [S2, S3, S4].

4.  **Generate Triangles:**
    Iterate through `triConfig` in steps of 3. Each triplet defines a triangle by connecting the intersection points on the referenced indices [S4, S5]. Stop when a $-1$ terminator is encountered [S2, S5].

5.  **Intersect and Connect:**
    For each referenced edge index, compute the exact intersection point using linear interpolation between the edge's endpoints [Parent]. Connect the three interpolated points to form a triangle [Parent].

### Formulas

**Vertex Interpolation:**
For an edge connecting corner $A$ (value $v_A$) and corner $B$ (value $v_B$), the intersection point $P$ is:
$$ P = V_a + \frac{u_{\text{isolevel}} - v_a}{v_b - v_a} (V_b - V_a) $$
If $v_A = v_B$, the edge is not intersected (handled by the lookup table logic) [G].

**Cube Index Calculation:**
$$ \text{cubeIndex} = \sum_{i=0}^{7} b_i 2^i $$
where $b_i = 1$ if $v_i \ge u_{\text{isolevel}}$, else $0$ [S4].

### Parameters
*   **$u_{\text{isolevel}}$:** Float uniform passed to the marching cubes compute shader. Threshold value for scalar field comparison. UI slider range: $-1.0$ to $1.0$ [S5].

### Edge Cases and Pitfalls
*   **Ambiguous Cases:** Cube indices 210 and 213 (and their symmetric counterparts) represent configurations where the isosurface passes through the center of the cube, allowing multiple topologically valid triangulations. The standard lookup tables use a single default triangulation, which can cause cracks or holes if adjacent cubes resolve ambiguities inconsistently [S2, S3].
*   **Terminator Check:** The implementation must strictly check for $-1$ in the Triangle Table. Reading past the terminator results in garbage memory access or out-of-bounds errors [S2, S5].
*   **Precision:** Floating-point comparison $v_i \ge u_{\text{isolevel}}$ can be sensitive to precision errors near the isovalue. Consistent handling of equality is required [G].

### Pseudocode (CPU Reference)

```python
# Standard edge-to-vertex mapping for a unit cube [S3]
EDGE_VERTICES = [
    (0, 1), (1, 2), (2, 3), (3, 0), # Face 0 edges
    (4, 5), (5, 6), (6, 7), (7, 4), # Face 1 edges
    (0, 4), (1, 5), (2, 6), (3, 7)  # Connecting edges
]

def interpolate_vertex(edge_idx, corners, values, isovalue):
    c1, c2 = EDGE_VERTICES[edge_idx]
    v1 = values[c1]
    v2 = values[c2]
    # Linear interpolation [Parent]
    t = (isovalue - v1) / (v2 - v1)
    return corners[c1] + t * (corners[c2] - corners[c1])

def process_voxel(corners, values, isovalue, triangle_table):
    # 1. Calculate cube index
    cube_index = 0
    for i in range(8):
        if values[i] >= isovalue:
            cube_index |= (1 << i)
            
    # 2. Check if cube is empty or full
    if cube_index == 0 or cube_index == 255:
        return []
        
    # 3. Get triangle configuration
    tri_config = triangle_table[cube_index]
    
    triangles = []
    idx = 0
    MAX_ENTRIES = 16 # 5 tris * 3 verts + 1 terminator
    
    # 4. Iterate through triangle list
    while idx < MAX_ENTRIES and tri_config[idx] != -1:
        e1 = tri_config[idx]
        e2 = tri_config[idx+1]
        e3 = tri_config[idx+2]
        
        # Interpolate vertices on the edges
        p1 = interpolate_vertex(e1, corners, values, isovalue)
        p2 = interpolate_vertex(e2, corners, values, isovalue)
        p3 = interpolate_vertex(e3, corners, values, isovalue)
        
        triangles.append((p1, p2, p3))
        idx += 3
        
    return triangles
```

## Subtopics

### [Smart Vertex Interpolation with Auxiliary Arrays](1137-smart-vertex-interpolation-with-auxiliary-arrays.md)
A technique to avoid duplicate vertex calculation in Marching Cubes by computing vertex coordinates only the first time an active edge is considered, storing the index in auxiliary arrays to be reused by adjacent cells [G].

### [Layer-Based Cube Traversal](1358-layer-based-cube-traversal.md)
Traverses a 3D grid of cubes layer by layer, maintaining only two layers in memory to reduce space complexity while fetching corner data for each cube [G].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels. Each voxel requires a constant number of operations (lookup, interpolation, triangle generation) [G].
*   **Memory Complexity:** $O(1)$ for the lookup tables (fixed size: 256 entries) [S4].
*   **Performance:** GPU implementations upload the tables to Shader Storage Buffer Objects (SSBOs), dispatch compute shaders with grid dimensions divided by the local workgroup size, and synchronize barriers for shader storage and vertex attribute arrays [S5].
*   **Strengths:** Simple to implement, fast, deterministic topology, well-understood [S2, S4].
*   **Limitations:** Does not guarantee topological correctness in ambiguous cases (cracks). Precision issues near the isovalue can cause artifacts [S2].
