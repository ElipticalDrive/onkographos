# Symmetry Mapping

Also called: MapToBase, RotationAndBaseCase

## Overview
Symmetry Mapping reduces the 256 possible voxel configurations in Marching Cubes isosurface extraction to a smaller set of canonical base cases by exploiting geometric symmetries [S1, unofficial]. It maps each configuration index to a specific base case and a rotation transformation, allowing triangle generation logic to be implemented for only the unique cases [S1, unofficial]. This approach simplifies the lookup table structure and reduces code complexity compared to handling all 256 cases individually [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A cube configuration index $C \in [0, 255]$ derived from the signs of the scalar field values at the 8 vertices of a voxel.
- Output: A base case index $B \in [0, 22]$ and a rotation index $R \in [0, 23]$.

**Data Structures:**
The method relies on precomputed lookup tables and configuration definitions. The layout is defined as follows [S1, unofficial]:

1.  `RotationAndBaseCase` struct:
    -   `int Rot`: The index of the rotation transformation.
    -   `int BaseCase`: The index of the canonical base case.
2.  `MapToBase` array:
    -   Type: `RotationAndBaseCase[256]`
    -   Maps each of the 256 input configurations to its corresponding base case and rotation.
3.  `BaseRotat` array:
    -   Type: `Rotation[24]`
    -   Defines the 24 possible rotation transformations (symmetries of the cube).
4.  `BaseConfig` array:
    -   Type: `Configuration[23]`
    -   Defines the 23 unique base cases, including their edge intersections and triangle lists.

**Steps:**
1.  Given a cube configuration index $C$, retrieve the entry from `MapToBase[C]`.
2.  Extract the base case index $B = \text{MapToBase}[C].\text{BaseCase}$ and the rotation index $R = \text{MapToBase}[C].\text{Rot}$.
3.  Retrieve the rotation transformation $T_R$ from `BaseRotat[R]`.
4.  Retrieve the triangle list for base case $B$ from `BaseConfig[B]`.
5.  Apply the rotation $T_R$ to the edge indices or vertex positions defined in the base case's triangle list to generate the final triangles for the original configuration $C$.

**Parameters:**
-   Number of unique base cases: 23 [S1, unofficial].
-   Number of rotations: 24 [S1, unofficial].

**Edge Cases and Pitfalls:**
-   The mapping must be exhaustive; every index from 0 to 255 must have a valid entry in `MapToBase`.
-   The rotation transformations must be consistent with the vertex ordering of the voxel. If the vertex ordering changes, the `BaseRotat` table must be adjusted accordingly.
-   Precision issues are minimal as this method operates on integer indices and precomputed mappings.

**Pseudocode:**
```python
# Precomputed data structures (loaded from source or generated)
# MapToBase: array of 256 tuples (BaseCase, Rotation)
# BaseRotat: array of 24 Rotation objects
# BaseConfig: array of 23 Configuration objects

def get_triangles(config_index):
    """
    Generate triangles for a given Marching Cubes configuration index.
    
    Args:
        config_index (int): Integer from 0 to 255 representing the voxel state.
        
    Returns:
        list: List of triangles (each triangle is a list of 3 vertex indices or positions).
    """
    # Step 1: Lookup base case and rotation
    base_case_idx, rotation_idx = MapToBase[config_index]
    
    # Step 2: Get rotation transformation
    rotation = BaseRotat[rotation_idx]
    
    # Step 3: Get base case configuration
    base_config = BaseConfig[base_case_idx]
    
    # Step 4: Generate triangles by applying rotation to base case edges/vertices
    triangles = []
    for triangle in base_config.triangles:
        # Apply rotation to the edge indices or vertex positions
        rotated_triangle = []
        for vertex_or_edge in triangle:
            rotated_vertex = rotation.apply(vertex_or_edge)
            rotated_triangle.append(rotated_vertex)
        triangles.append(rotated_triangle)
        
    return triangles
```

## Subtopics

### Manifold Rotation Logic
Auxiliary logic for rotating cube configurations, likely used for generating manifold dual marching cubes tables or handling symmetry [S2, unofficial]. It rotates the corner bits of a configuration [S2, unofficial]. Rotation around the X-axis involves shifting corner bits: corners 0 and 1 shift left by 2, corners 2 and 3 shift left by 4, corners 4 and 5 shift right by 4, and corners 6 and 7 shift right by 2 [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(1)$ per voxel for the lookup and rotation application, assuming constant-time array access and rotation application.
-   **Memory Complexity:** Requires storage for `MapToBase` (256 entries), `BaseRotat` (24 entries), and `BaseConfig` (23 entries). This is significantly smaller than storing full triangle lists for all 256 cases.
-   **Strengths:** Reduces code size and complexity; simplifies maintenance of the triangle generation logic.
-   **Limitations:** Requires precomputation of the symmetry mappings; rotation application adds a small computational overhead per triangle.
-   **When to use:** When memory is constrained or when code simplicity is prioritized over raw lookup speed.
-   **When not to use:** When the overhead of rotation application is unacceptable and direct lookup for all 256 cases is feasible.

## Background
Symmetry Mapping was introduced as a method to simplify the Marching Cubes algorithm by reducing the number of unique cases that need to be handled [S1, unofficial]. It leverages the rotational symmetries of the cube to map all 256 configurations to a smaller set of canonical cases [S1, unofficial]. This technique is commonly used in implementations where code size and maintainability are important considerations [S1, unofficial].
