# Symmetry Mapping

Also called: MapToBase, RotationAndBaseCase

## Overview
Symmetry Mapping maps one of the 256 possible cube configurations to one of 23 canonical base cases using precomputed rotation and base case mappings to simplify triangle generation logic [S1, unofficial]. It exploits geometric symmetries to reduce the decision logic to a lookup of a base case index and a rotation transformation, allowing triangle generation to be implemented for only the unique cases [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A cube configuration index $C \in [0, 255]$ derived from the signs of the scalar field values at the 8 vertices of a voxel [S1, unofficial].
- Output: A base case index $B \in [0, 22]$ and a rotation index $R \in [0, 23]$ [S1, unofficial].

**Data Structures:**
The method relies on three precomputed arrays defined as follows [S1, unofficial]:
1. `RotationAndBaseCase` struct: Contains `int Rot` (rotation index) and `int BaseCase` (base case index) [S1, unofficial].
2. `MapToBase` array: Type `RotationAndBaseCase[256]` [S1, unofficial]. Maps each of the 256 input configurations to its corresponding base case and rotation [S1, unofficial].
3. `BaseRotat` array: Type `Rotation[24]` [S1, unofficial]. Stores 24 rotation transformations (symmetries of the cube) [S1, unofficial]. Each rotation is represented as a permutation of the 8 vertex indices [S1, unofficial].
4. `BaseConfig` array: Type `Configuration[23]` [S1, unofficial]. Defines the 23 unique base cases, including their edge intersections and triangle lists [S1, unofficial]. Each triangle is a triplet of edge indices $(0 \le k \le 11)$ [S1, unofficial].

**Steps:**
1. Given a cube configuration index $C$, retrieve the entry from `MapToBase[C]` [S1, unofficial].
2. Extract the base case index $B = \text{MapToBase}[C].\text{BaseCase}$ and the rotation index $R = \text{MapToBase}[C].\text{Rot}$ [S1, unofficial].
3. Retrieve the rotation permutation $P_R$ from `BaseRotat[R]` [S1, unofficial].
4. Retrieve the triangle list for base case $B$ from `BaseConfig[B]` [S1, unofficial].
5. Apply the rotation permutation $P_R$ to the edge indices in the base case's triangle list to generate the final triangles for configuration $C$ [S1, unofficial].

**Parameters:**
- Number of unique base cases: 23 [S1, unofficial].
- Number of rotations: 24 [S1, unofficial].

**Edge Cases and Pitfalls:**
- The rotation transformations must be consistent with the vertex ordering of the voxel. If the vertex ordering changes, the `BaseRotat` table must be adjusted accordingly [G].

**Pseudocode:**
```python
# Precomputed data structures (generated offline)
# MapToBase: list of 256 tuples (base_case_idx, rotation_idx)
# BaseRotat: list of 24 lists, each containing 8 integers representing a vertex permutation
# BaseConfig: list of 23 lists of triangles, each triangle is a tuple of 3 edge indices (0-11)

# Standard Marching Cubes edge-to-vertex mapping
EDGE_VERTICES = [
    (0,1), (1,2), (2,3), (3,0),  # Bottom face (z=0)
    (4,5), (5,6), (6,7), (7,4),  # Top face (z=1)
    (0,4), (1,5), (2,6), (3,7)   # Vertical edges
]

def generate_triangles(config_index):
    # Step 1: Lookup base case and rotation
    base_case_idx, rotation_idx = MapToBase[config_index]
    
    # Step 2: Get rotation permutation
    vertex_perm = BaseRotat[rotation_idx]
    
    # Step 3: Get base case triangles
    base_triangles = BaseConfig[base_case_idx]
    
    # Step 4: Apply rotation to edge indices
    triangles = []
    for tri in base_triangles:
        rotated_tri = []
        for edge_idx in tri:
            # Map base case edge to original cube edge using vertex permutation
            v0, v1 = EDGE_VERTICES[edge_idx]
            rv0 = vertex_perm[v0]
            rv1 = vertex_perm[v1]
            
            # Find the edge index in the original cube that connects (rv0, rv1)
            rotated_edge = -1
            for i, (ev0, ev1) in enumerate(EDGE_VERTICES):
                if (rv0 == ev0 and rv1 == ev1) or (rv0 == ev1 and rv1 == ev0):
                    rotated_edge = i
                    break
            rotated_tri.append(rotated_edge)
        triangles.append(rotated_tri)
        
    return triangles
```

## Subtopics

### [Simplified Marching Cubes Case Handling](3678-simplified-marching-cubes-case-handling.md)
Simplified Marching Cubes (SMC) Case Handling is a deterministic algorithm for resolving the ambiguous topological configurations in Marching Cubes isosurface extraction by classifying cube states based on the count of positive-valued nodes and their spatial distribution. It solves the problem of self-intersecting triangles and topological errors inherent in the original 256-case lookup table by reducing the decision logic to a switch on the number of active nodes (`nnodes`), using modular arithmetic on node sums to distinguish between ambiguous cases. Unlike the standard lookup table which relies on precomputed edge indices, SMC dynamically constructs triangles by identifying "interface nodes" or switching the status of specific vertices to reduce complex cases to simpler, unambiguous base cases.

### Manifold Rotation Logic
Auxiliary logic for rotating cube configurations, likely used for generating manifold dual marching cubes tables or handling symmetry [S2, unofficial]. It rotates the corner bits of a configuration [S2, unofficial]. Rotation around the X-axis involves shifting corner bits: corners 0 and 1 shift left by 2, corners 2 and 3 shift left by 4, corners 4 and 5 shift right by 4, and corners 6 and 7 shift right by 2 [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel for the lookup and rotation application, assuming constant-time array access and permutation application [G].
- **Memory Complexity:** Requires storage for `MapToBase` (256 entries), `BaseRotat` (24 entries), and `BaseConfig` (23 entries) [S1, unofficial].
- **Strengths:** Reduces the number of unique triangle generation cases that must be implemented [S1, unofficial].
- **Limitations:** Requires precomputation of the symmetry mappings; rotation application adds a small computational overhead per triangle [G].
- **When to use:** When implementation simplicity is prioritized over raw lookup speed [G].
- **When not to use:** When direct lookup for all 256 cases is feasible and rotation overhead is unacceptable [G].

## Background
Symmetry Mapping was introduced as a method to simplify the Marching Cubes algorithm by reducing the number of unique cases that need to be handled [S1, unofficial]. It leverages the rotational symmetries of the cube to map all 256 configurations to a smaller set of canonical cases [S1, unofficial].
