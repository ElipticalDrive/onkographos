# Importance-driven Isosurface Decimation

Also called: Importance-driven mesh decimation, Importance-driven parallel mesh simplification, Mesh simplification based on OpenCL

## Overview
Importance-driven isosurface decimation is a parallel mesh simplification strategy that generates decimated meshes progressively without first generating the full-resolution original surface [S1]. It solves the problem of excessive mesh density in large scientific and medical datasets, which often exceeds memory limits or hinders interactive visualization [S1]. Unlike traditional incremental decimation methods (e.g., edge collapse) that are difficult to parallelize due to data sorting dependencies, this method uses vertex clustering and crack patching to enable efficient GPU parallelization via OpenCL [S1]. It distinguishes itself from sibling methods like [Bitwise Marching Cubes](7374-bitwise-marching-cubes.md) by operating on a hierarchical pyramid structure to decide decimation *before* mesh generation, rather than simplifying a generated mesh.

## How it works
The method operates on a structured 3D grid, building on the foundational isosurface extraction logic of [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md). It consists of three stages: Pre-processing, Pyramid Construction, and Pyramid Peeling. The algorithm is designed for parallel execution on heterogeneous computing systems (specifically OpenCL) [S1].

### Inputs and Outputs
*   **Input:** A 3D scalar field (volumetric data), an isovalue, and user-defined transfer functions mapping domain-specific features (e.g., pressure, velocity, texture) and geometric properties to importance values.
*   **Output:** A sequence of decimated triangle meshes, rendered progressively from coarsest to finest resolution.

### Data Structures
For each cube in the hierarchy, the algorithm stores exactly three values to control decimation quality [S1]:
1.  **Gradient Moment 1:** The sum of weighted normalized gradient vectors from child cubes.
2.  **Gradient Moment 2:** The sum of the norms of the weighted normalized gradient vectors from child cubes.
3.  **Mesh Count:** The number of meshes generated by the child cubes.

These values are aggregated in a feature pyramid and a histogram pyramid [S1].

### Parameters
*   $N = 8$: The total number of child cubes of a parent cube in the octree hierarchy [S1].
*   $l$: The resolution level in the pyramid hierarchy.
*   $\eta$: A threshold value used to decide whether a cube should be decimated [S1].
*   Transfer Function: A mapping (typically 1D, but extensible to multidimensional) from feature values to importance scores [S1].

### Formulas
**Smoothness Feature ($s_c^{(l)}$):**
The smoothness feature for cube $c$ at resolution level $l$ is computed from its 8 children at level $l-1$ [S1]:

$$ s_c^{(l)} = 1 - \left(1 + \frac{\sum_{i=1}^N n_{ci} \|\mathbf{g}_i^{(l-1)}\|}{\|\sum_{i=1}^N n_{ci} \mathbf{g}_i^{(l-1)}\|}\right)^{-1} $$

Where:
*   $n_{ci}$ is the number of meshes generated by child cube $i$.
*   $\mathbf{g}_i^{(l-1)}$ is the normalized gradient vector of child cube $i$, computed using central difference [S1].
*   $\|\cdot\|$ denotes the Euclidean norm.

**Aggregated Feature ($f_c^{(l)}$):**
User-defined domain-specific features are aggregated similarly [S1]:

$$ f_c^{(l)} = \frac{\sum_{i=1}^N n_{ci} f_i^{(l-1)}}{\sum_{i=1}^N n_{ci}} $$

Where $f_i^{(l-1)}$ is the feature value of child cube $i$.

**Importance and Decimation:**
The aggregated features $s_c^{(l)}$ and $f_c^{(l)}$ are mapped to importance values via the transfer function. If the importance is below a threshold $\eta$, the cube is marked for decimation. If decimated, the cube becomes a "representative" of its descendants, meaning the meshes belonging to this cube are updated to represent the aggregated detail of its children [S1].

### Steps

**Stage 1: Pre-processing (Initialization/Classification)**
1.  Classify cubes using the standard Marching Cubes infrastructure [S1].
2.  Compute geometric features (smoothness) and extract user-defined features for each cube at the finest resolution.
3.  Compute the normalized gradient vector $\mathbf{g}_i^{(l-1)}$ for each leaf cube using central differences on the scalar field [S1].

**Stage 2: Pyramid Construction (Bottom-Up)**
1.  Initialize the histogram and feature pyramids at the finest resolution level.
2.  Iterate from the finest resolution level up to the coarsest level ($l = L_{max}$ down to $1$):
    a. For each parent cube $c$ at level $l$:
    b. Retrieve the mesh counts $n_{ci}$, gradient vectors $\mathbf{g}_i^{(l-1)}$, and feature values $f_i^{(l-1)}$ from its 8 children.
    c. Compute the smoothness feature $s_c^{(l)}$ using the formula above.
    d. Compute the aggregated feature $f_c^{(l)}$ using the formula above.
    e. Map $s_c^{(l)}$ and $f_c^{(l)}$ to importance values using the user-defined transfer function.
    f. Compare importance against threshold $\eta$.
    g. If the cube is to be decimated, mark it as a representative. Update the mesh count $n_{ci}$ for the parent to reflect that it now represents the descendants.
    h. Store the aggregated moments and counts in the pyramid structure for the next level [S1].

**Stage 3: Pyramid Peeling (Top-Down Rendering)**
1.  Iterate from the coarsest resolution level to the finest level.
2.  For each resolution level:
    a. **Gathering Step:** Traverse the histogram pyramid to determine the total number of meshes to be generated at this level.
    b. **Assembling Step:**
        i. Compute mesh positions, normals, and color attributes for the meshes.
        ii. If a cube was marked as a representative in Stage 2, generate a single mesh for it that represents the aggregated surface of its descendants.
        iii. **Crack Patching:** Refine coarse meshes by recomputing positions and normals based on detail information from finer levels to ensure continuity and patch cracks generated by discontinuous meshes between resolutions [S1].
    c. **Rendering Step:** Render all meshes generated at this level [S1].

### Pseudocode

```python
# Constants
N = 8  # Number of child cubes

def compute_gradient_norms(field, cube_indices):
    """
    Computes the normalized gradient vector for each cube.
    Uses central difference on the scalar field.
    Returns list of normalized gradient vectors.
    """
    gradients = []
    for idx in cube_indices:
        # Central difference calculation [G]
        grad = central_difference(field, idx)
        norm = vector_norm(grad)
        if norm > 0:
            gradients.append(grad / norm)
        else:
            gradients.append(vec3(0, 0, 0))
    return gradients

def aggregate_features(parent_children_data):
    """
    Aggregates features from children to parent.
    parent_children_data: list of tuples (n_ci, g_i, f_i) for 8 children.
    Returns (smoothness, aggregated_feature, total_mesh_count).
    """
    sum_weighted_grad = vec3(0, 0, 0)
    sum_weighted_norm = 0.0
    sum_weighted_feature = 0.0
    total_mesh_count = 0

    for n_ci, g_i, f_i in parent_children_data:
        sum_weighted_grad += n_ci * g_i
        sum_weighted_norm += n_ci * vector_norm(g_i)
        sum_weighted_feature += n_ci * f_i
        total_mesh_count += n_ci

    # Compute smoothness
    # s_c = 1 - (1 + (sum_weighted_norm / ||sum_weighted_grad||)^-1 )
    # Note: If ||sum_weighted_grad|| is 0, smoothness is 0 or handled as edge case [G]
    if vector_norm(sum_weighted_grad) > 0:
        ratio = sum_weighted_norm / vector_norm(sum_weighted_grad)
        smoothness = 1.0 - (1.0 + ratio)**(-1)
    else:
        smoothness = 0.0

    # Compute aggregated feature
    if total_mesh_count > 0:
        aggregated_feature = sum_weighted_feature / total_mesh_count
    else:
        aggregated_feature = 0.0

    return smoothness, aggregated_feature, total_mesh_count

def importance_driven_decimation(field, isovalue, transfer_function, threshold_eta):
    """
    Main algorithm.
    """
    # Stage 1: Pre-processing
    # Get leaf cubes (finest resolution)
    leaf_cubes = get_leaf_cubes(field)
    
    # Compute initial features for leaves
    leaf_gradients = compute_gradient_norms(field, leaf_cubes)
    leaf_features = extract_user_features(field, leaf_cubes) # e.g., pressure, velocity
    
    # Initialize pyramid levels
    # Each level stores: {cube_id: {smoothness, feature, mesh_count, is_representative}}
    pyramid_levels = []
    
    current_level_data = []
    for i, cube in enumerate(leaf_cubes):
        current_level_data.append({
            'id': cube.id,
            'smoothness': 0.0, # Leaf smoothness is not defined by children, set to 0 or max importance [G]
            'feature': leaf_features[i],
            'mesh_count': 1, # Each leaf generates 1 mesh initially
            'gradient': leaf_gradients[i],
            'is_representative': False
        })
    pyramid_levels.append(current_level_data)

    # Stage 2: Pyramid Construction (Bottom-Up)
    # Iterate from finest (index 0) to coarsest
    for level_idx in range(len(pyramid_levels) - 1):
        current_level = pyramid_levels[level_idx]
        parent_level_data = []
        
        # Group children by parent
        children_by_parent = group_by_parent(current_level)
        
        for parent_id, children in children_by_parent.items():
            # Prepare data for aggregation
            child_data = []
            for child in children:
                child_data.append((
                    child['mesh_count'],
                    child['gradient'],
                    child['feature']
                ))
            
            smoothness, agg_feature, total_mesh_count = aggregate_features(child_data)
            
            # Map to importance
            importance = transfer_function(smoothness, agg_feature)
            
            # Decide decimation
            is_rep = importance < threshold_eta
            
            parent_level_data.append({
                'id': parent_id,
                'smoothness': smoothness,
                'feature': agg_feature,
                'mesh_count': total_mesh_count if is_rep else 1, # If rep, count aggregates; else 1
                'gradient': sum(c['gradient'] * c['mesh_count'] for c in children) / total_mesh_count if total_mesh_count > 0 else vec3(0,0,0), # Store representative gradient [G]
                'is_representative': is_rep
            })
        
        pyramid_levels.append(parent_level_data)

    # Stage 3: Pyramid Peeling (Top-Down)
    meshes = []
    
    # Iterate from coarsest (last index) to finest (index 0)
    for level_idx in range(len(pyramid_levels) - 1, -1, -1):
        level_data = pyramid_levels[level_idx]
        
        # Gathering Step: Count meshes
        total_meshes = sum(1 for item in level_data if not item['is_representative'])
        # Note: Representatives are handled in Assembling step as single meshes representing descendants
        
        # Assembling Step
        for item in level_data:
            if item['is_representative']:
                # Generate mesh for representative
                # Position and normal are computed based on aggregated detail [S1]
                mesh = generate_representative_mesh(item, field, isovalue)
                meshes.append(mesh)
            else:
                # Generate standard mesh for this cube
                mesh = generate_standard_mesh(item, field, isovalue)
                meshes.append(mesh)
        
        # Crack Patching and Refinement
        # Refine coarse meshes using detail from finer levels (already processed in previous iterations of this loop? 
        # No, peeling is top-down, so finer levels are processed *after* coarse. 
        # The source says "coarse meshes are prominent, we first improve their qualities... re-compute mesh positions".
        # This implies the refinement happens during the rendering of the coarse level, using data from the pyramid.
        meshes = patch_cracks(meshes, pyramid_levels, level_idx)
        
        # Render Step
        render(meshes)
```

### Edge Cases and Pitfalls
*   **Zero Gradient Norm:** If the sum of weighted gradients is zero, the smoothness formula involves division by zero. The implementation must handle this, typically by setting smoothness to 0 or a default value [G].
*   **Topology Changes:** The method acknowledges that topology changes during simplification. It prioritizes continuity and smoothness over topological correctness [S1].
*   **Cracks:** Discontinuous meshes between different resolutions generate cracks. The crack patching step is critical for visual quality [S1].

## Operating characteristics
*   **Time Complexity:** The algorithm is parallelized on GPU using OpenCL. The pyramid construction is $O(N)$ where $N$ is the number of cubes, with a constant factor for the 8 children aggregation. The peeling step is also parallel.
*   **Memory Complexity:** Requires storing the feature and histogram pyramids. For each cube, only two gradient moments and one mesh number are stored, minimizing memory overhead compared to storing full mesh data at all levels [S1].
*   **Performance:** Evaluated on large medical and scientific datasets. It enables interactive visualization during ongoing simulations, which traditional methods cannot handle due to memory limits [S1].
*   **Strengths:** Highly parallelizable; allows interactive visualization of large datasets; user-defined importance via transfer functions.
*   **Limitations:** Topology is not preserved; relies on OpenCL for parallelization; requires careful tuning of transfer functions and thresholds [S1].

## Background
The method was proposed by Y. Peng, L. Chen, and J.H. Yong from Tsinghua University [S1]. It was published in *Computing in Science and Engineering* in 2013 (received October 21, 2012; revised October 29, 2012) [S1]. The work addresses the limitations of traditional mesh simplification (edge collapse, vertex removal) which are difficult to parallelize due to data sorting dependencies [S1]. It builds on the infrastructure of [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) but adds a hierarchical decimation layer.
