# SDF to PLY Conversion

Also called: Implicit to Mesh Conversion, Marching Cubes from SDF

## Overview
This method converts a Signed Distance Field (SDF) defined on a structured 3D grid into a polygonal triangle mesh (PLY format) using the Marching Cubes algorithm. It solves the problem of visualizing or exporting implicit surface representations derived from neural networks or analytical functions. It differs from its siblings by focusing on the complete pipeline from raw grid evaluation to file I/O, often handling memory constraints via chunked evaluation, whereas [Marching Cubes with Narrow-Band Filtering](3826-marching-cubes-with-narrow-band-filtering.md) optimizes for sparse boundary detection and [Two-Step Surface Reconstruction Method](7364-two-step-surface-reconstruction-method.md) separates coarse and fine passes.

## How it works
**Inputs:**
- `implicit_fn`: A callable function that takes a 3D coordinate tensor and returns the SDF value.
- `grid_size`: Integer resolution of the grid per dimension (default 128).
- `scale`: Spatial extent of the grid, defining the range `[-scale, scale]` (default 0.5).
- `thresh`: Isosurface threshold, typically 0.0 for SDFs.
- `chunk_size`: Number of points to evaluate per batch to limit memory usage (default 262144).
- `voxel_size`: Physical size of a single voxel (used for spacing in extraction).
- `voxel_grid_origin`: Offset to transform from voxel space to world space.

**Outputs:**
- A PLY file containing vertices and faces.

**Data Structures:**
- `grid`: A 3D tensor of shape `(grid_size+1, grid_size+1, grid_size+1, 3)` storing 3D coordinates.
- `sdfs`: A 1D array or tensor of shape `(grid_size+1)^3` storing SDF values.
- `vertices`: NumPy structured array with fields `x, y, z` of type `float32`.
- `faces`: NumPy structured array with field `vertex_indices` of type `int32` and shape `(3,)`.

**Steps:**

1.  **Grid Generation**: Create a 3D grid of points. For each axis $i \in \{x, y, z\}$, generate `grid_size + 1` points linearly spaced between `-scale` and `scale`. Stack these into a grid tensor $G$ of shape $(N, N, N, 3)$ where $N = \text{grid\_size} + 1$.
    $$ G[x, y, z] = (x_{coord}, y_{coord}, z_{coord}) $$

2.  **SDF Evaluation (Chunked)**: Evaluate the implicit function on the grid points. To manage memory, process the flattened grid points in chunks of size `chunk_size`.
    - Flatten $G$ to a 1D array of points $P$.
    - For each chunk $P_{chunk}$:
      $$ S_{chunk} = \text{implicit\_fn}(P_{chunk}) $$
    - Reshape the resulting SDF values back to the 3D grid dimensions:
      $$ \text{SDF}_{grid} = S_{\text{flat}}.\text{reshape}(N, N, N) $$

3.  **Marching Cubes Extraction**: Run the Marching Cubes algorithm (e.g., `skimage.measure.marching_cubes_lewiner`) on $\text{SDF}_{grid}$ with `level=thresh` and `spacing=[voxel\_size, voxel\_size, voxel\_size]`.
    - Inputs: The 3D SDF grid and the threshold.
    - Outputs: `vertices_mc`, `faces_mc`, `normals_mc`, `values_mc`.
    - Note: `vertices_mc` are in voxel grid indices (floats representing intersection positions).

4.  **Coordinate Transformation**: Transform the extracted vertices from voxel grid space to world/camera space.
    - Normalize voxel indices to $[0, 1]$ range if necessary, then scale to world coordinates.
    - Apply the origin offset:
      $$ V_{world} = V_{mc} \times \text{voxel\_size} + \text{voxel\_grid\_origin} $$
    - Alternatively, if the grid was generated directly in world coordinates (Step 1), the vertices from Marching Cubes (which are interpolated based on grid indices) must be mapped back. If `skimage` is used with `spacing`, it handles the scaling internally, but the origin offset must still be applied if the grid does not start at $(0,0,0)$ in world space.
    - Specific implementation note from [S2, unofficial]: Vertices are normalized to `[-scale, scale]` via:
      $$ V_{final} = \left(\frac{V_{mc}}{\text{grid\_size}} - 0.5\right) \times 2 \times \text{scale} $$
      *Note: This specific normalization assumes `skimage` returns indices in $[0, \text{grid\_size}]$. If `spacing` is provided, `skimage` returns world coordinates directly, and this step may be redundant or require adjustment based on the specific library version.*

5.  **PLY Construction**:
    - Create a NumPy structured array for vertices with fields `x`, `y`, `z` of type `float32`.
    - Create a NumPy structured array for faces with field `vertex_indices` of type `int32` and shape `(3,)`.
    - Use `plyfile.PlyElement.describe` to create PLY elements.
    - Write the PLY data to the output file.

**Pseudocode:**

```python
import numpy as np
import torch
from skimage import measure
import plyfile

def sdf_to_ply(implicit_fn, grid_size=128, scale=0.5, thresh=0.0, 
               chunk_size=262144, voxel_size=1.0, voxel_grid_origin=np.array([0,0,0])):
    # 1. Generate Grid
    # Create linspace for one dimension
    coords = np.linspace(-scale, scale, grid_size + 1)
    # Create 3D grid
    x, y, z = np.meshgrid(coords, coords, coords, indexing='ij')
    grid_points = np.stack((x, y, z), axis=-1) # Shape: (N, N, N, 3)
    
    # Flatten grid for evaluation
    flat_grid = grid_points.reshape(-1, 3)
    n_points = flat_grid.shape[0]
    
    # 2. Evaluate SDF in chunks
    sdf_values = np.zeros(n_points)
    for i in range(0, n_points, chunk_size):
        end = min(i + chunk_size, n_points)
        chunk = flat_grid[i:end]
        # Evaluate implicit function (assuming it returns numpy array or can be converted)
        # If implicit_fn is a PyTorch model, convert to numpy
        chunk_tensor = torch.from_numpy(chunk).float()
        sdf_chunk = implicit_fn(chunk_tensor).cpu().numpy()
        sdf_values[i:end] = sdf_chunk.flatten()
        
    # Reshape to 3D grid
    sdf_grid = sdf_values.reshape(grid_size + 1, grid_size + 1, grid_size + 1)
    
    # 3. Marching Cubes
    # spacing is in world units. If voxel_size is 1.0 and grid spans [-scale, scale],
    # the physical spacing is (2*scale)/grid_size.
    # However, skimage expects spacing consistent with the grid dimensions.
    # If grid_points are already in world coordinates, spacing should be the physical voxel size.
    physical_voxel_size = (2 * scale) / grid_size
    spacing = [physical_voxel_size, physical_voxel_size, physical_voxel_size]
    
    verts, faces, normals, values = measure.marching_cubes(
        sdf_grid, 
        level=thresh, 
        spacing=spacing
    )
    
    # 4. Transform Vertices
    # marching_cubes with spacing returns vertices in world coordinates relative to the grid origin (0,0,0)
    # If the grid was centered at 0, this is correct. 
    # If voxel_grid_origin is non-zero, add it.
    verts = verts + voxel_grid_origin
    
    # 5. Construct PLY
    # Vertices
    vertices = np.zeros(verts.shape[0], dtype=[('x', 'f4'), ('y', 'f4'), ('z', 'f4')])
    vertices['x'] = verts[:, 0]
    vertices['y'] = verts[:, 1]
    vertices['z'] = verts[:, 2]
    
    # Faces
    faces_struct = np.zeros(faces.shape[0], dtype=[('vertex_indices', 'i4', (3,))])
    faces_struct['vertex_indices'] = faces
    
    # Create PLY elements
    v_element = plyfile.PlyElement.describe(vertices, 'vertex')
    f_element = plyfile.PlyElement.describe(faces_struct, 'face')
    
    # Write file
    plyfile.PlyData([v_element, f_element]).write('output.ply')
    
    return verts, faces
```

**Edge Cases and Pitfalls:**
- **Memory Overflow**: Evaluating the SDF on the entire grid at once can exceed GPU/CPU memory for large `grid_size`. Chunking is essential [S2, unofficial].
- **Coordinate System Mismatch**: `skimage.measure.marching_cubes` assumes the input array indices correspond to $(x, y, z)$. If the grid generation order differs, the mesh will be rotated or flipped. Ensure `meshgrid` uses `indexing='ij'` to match array dimensions $[z, y, x]$ or $[x, y, z]$ consistently with the library's expectation.
- **Spacing Definition**: The `spacing` parameter in `marching_cubes` defines the physical distance between grid points. If `voxel_size` is not provided, it must be derived from `scale` and `grid_size`. Incorrect spacing leads to distorted geometry [S1, unofficial].
- **Origin Offset**: If the SDF grid does not start at world $(0,0,0)$, the resulting mesh will be shifted. The `voxel_grid_origin` must be added to the final vertices [S1, unofficial].

## Subtopics

### SDF to Mesh Extraction
Extracts a mesh from a known SDF using FlexiCubes, a differentiable mesh extraction method. Unlike standard Marching Cubes, FlexiCubes uses a flexible cube topology that can handle arbitrary grid configurations and gradients. It is chosen when differentiability is required for optimization or when the grid topology is non-standard. It splits quadrilaterals along diagonals with more consistent gradients if a gradient function is provided [S3, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N^3)$ for SDF evaluation, where $N$ is `grid_size`. Marching Cubes is $O(V)$ where $V$ is the number of voxels.
- **Memory Complexity**: $O(N^3)$ for storing the SDF grid and grid points. Chunking reduces peak memory usage for evaluation to $O(\text{chunk\_size})$.
- **Performance**: Dependent on the cost of `implicit_fn`. For neural networks, this is the bottleneck.
- **Strengths**: Simple, robust, produces watertight meshes.
- **Limitations**: Fixed resolution grid; aliasing artifacts at low resolutions; memory intensive for high resolutions.

## Background
This method is a standard post-processing step in neural implicit surface reconstruction pipelines. It bridges the gap between learned implicit representations (like SDFs from neural networks) and standard 3D mesh formats (PLY) used in rendering and simulation. The use of `skimage.measure.marching_cubes` is a common implementation choice in open-source repositories [S1, S2, unofficial].
