# SDF to Mesh Extraction

Also called: Conversion to triangle mesh, Marching Cubes extraction, SDF-based Mesh Extraction, known SDF extraction

## Overview
Extracts a triangle mesh from a signed distance field (SDF) grid at a specified isosurface value [S1]. It builds on [SDF to PLY Conversion](2343-sdf-to-ply-conversion.md) by converting the volumetric representation into a polygonal surface [G]. Unlike optimized extraction methods that may simplify topology, this approach performs a direct extraction [S1].

## How it works
**Inputs:**
- `sdf_grid`: A 3D array of shape $(D, H, W)$ containing quantized SDF values [S1].
- `isovalue`: The threshold for the zero-crossing (typically $0.0$ for the $0$-level set) [S1].

**Outputs:**
- `vertices`: List of 3D coordinates [S1].
- `faces`: List of triangle index triplets [S1].
- `colors`: List of RGB values sampled at vertex positions [S1].

**Data Structures:**
- `sdf_grid`: Dense 3D array storing scalar distance values per voxel [G].
- `edge_cache`: Dictionary mapping `(cell_index, edge_index)` to interpolated 3D points to ensure shared vertices and manifold topology [G].
- `vertices`, `faces`, `colors`: Dynamic lists for output geometry and attributes [G].

**Steps:**
1. Quantize the SDF to a fixed-size grid [S1].
2. Extract its $0$-level set (zero-crossings) via marching cubes to obtain vertices and triangles [S1].
3. Sample colors from the radiance field by querying the network at vertex positions [S1].

**Formulas:**
- Cell configuration bit: $C = \sum_{i=0}^{7} b_i 2^i$, where $b_i = 1$ if $\text{sdf\_grid}[d + (i \gg 2) \& 1, h + (i \gg 1) \& 1, w + i \& 1] > \text{isovalue}$, else $0$ [G].
- Linear edge interpolation: $\mathbf{p} = \mathbf{p}_0 + \frac{\text{isovalue} - \text{sdf}_0}{\text{sdf}_1 - \text{sdf}_0} (\mathbf{p}_1 - \mathbf{p}_0)$ [G].

**Parameters:**
- `isovalue`: $0.0$ (standard for $0$-level set extraction) [S1].
- Grid resolution: Fixed-size, determined during quantization [S1].

**Edge Cases and Pitfalls:**
- Requires SDF representation; vanilla EG3D does not support this direct extraction [S1].
- Boundary cells must be padded or clamped to avoid out-of-bounds interpolation [G].
- Degenerate cells (all corners on one side of the isovalue) are skipped to prevent empty triangles [G].

**Pseudocode:**
```python
def extract_mesh(sdf_grid, grid_size, isovalue=0.0):
    """
    Extracts a triangle mesh from a quantized SDF grid using Marching Cubes.
    Args:
        sdf_grid: 3D array of shape (D, H, W) containing SDF values.
        grid_size: Tuple (D, H, W) defining the grid dimensions.
        isovalue: Scalar threshold for zero-crossings (default 0.0).
    Returns:
        vertices: List of [x, y, z] coordinates.
        faces: List of [i, j, k] triangle indices.
        colors: List of [r, g, b] values sampled at vertices.
    """
    # Standard Marching Cubes lookup tables [G]
    # EDGE_TABLE: 256 configs x 12 edges, each edge maps to 2 corner indices (0-7)
    # TRI_TABLE: 256 configs x 15 triangle indices (-1 terminated)
    
    vertices = []
    faces = []
    colors = []
    edge_cache = {}
    
    def lerp(p0, p1, v0, v1, iso):
        t = (iso - v0) / (v1 - v0)
        return [p0[k] + t * (p1[k] - p0[k]) for k in range(3)]
    
    def get_edge_intersection(cell, edge_idx, config):
        key = (cell, edge_idx)
        if key in edge_cache:
            return edge_cache[key]
        c0, c1 = EDGE_TABLE[config][edge_idx * 2], EDGE_TABLE[config][edge_idx * 2 + 1]
        v0 = sdf_grid[cell[0] + (c0 >> 2) & 1, cell[1] + (c0 >> 1) & 1, cell[2] + c0 & 1]
        v1 = sdf_grid[cell[0] + (c1 >> 2) & 1, cell[1] + (c1 >> 1) & 1, cell[2] + c1 & 1]
        p0 = [cell[0] + (c0 >> 2) & 1, cell[1] + (c0 >> 1) & 1, cell[2] + c0 & 1]
        p1 = [cell[0] + (c1 >> 2) & 1, cell[1] + (c1 >> 1) & 1, cell[2] + c1 & 1]
        pt = lerp(p0, p1, v0, v1, isovalue)
        edge_cache[key] = pt
        return pt

    for d in range(grid_size[0] - 1):
        for h in range(grid_size[1] - 1):
            for w in range(grid_size[2] - 1):
                config = 0
                for i in range(8):
                    if sdf_grid[d + (i >> 2) & 1, h + (i >> 1) & 1, w + i & 1] > isovalue:
                        config |= 1 << i
                if config == 0 or config == 255:
                    continue
                
                intersections = []
                for e in range(12):
                    if (config >> e) & 1:
                        intersections.append(get_edge_intersection((d, h, w), e, config))
                
                idx = 0
                while TRI_TABLE[config][idx] != -1:
                    faces.append(intersections[TRI_TABLE[config][idx]])
                    faces.append(intersections[TRI_TABLE[config][idx + 1]])
                    faces.append(intersections[TRI_TABLE[config][idx + 2]])
                    idx += 3

    # Step 3: Sample colors from the radiance field at vertex positions [S1]
    # colors = [sample_color_from_radiance_field(v) for v in vertices] [G]
    return vertices, faces, colors
```

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each cell is processed exactly once [G].
- **Memory Complexity:** $O(V + F)$ for the output vertex and face lists, plus $O(E)$ for the edge cache during traversal [G].
- **Strengths:** Direct, unoptimized extraction preserves geometric detail without topology simplification [S1].
- **Limitations:** Does not include advanced optimization or simplification; requires SDF representation (vanilla EG3D lacks this) [S1].
- **When to use:** When a quick, unoptimized mesh extraction from an SDF is needed, or as a preprocessing step for further mesh processing [S1].

## Background
Introduced in a 2023 CVPR paper for radiance field inversion, enabling direct mesh generation from generated objects [S1]. FlexiCubes offers a differentiable quad-based alternative that splits quadrilaterals along diagonals with consistent gradients [S2, unofficial].
