# Sub-case decomposition for n-dimensional marching cubes

Also called: Major-case secondary table, Sub-case method, Sub-case secondary table

## Overview
Sub-case decomposition reduces the configuration space explosion in n-dimensional marching cubes by decomposing major cases into edge-connected sub-cases, where vertices share the same status relative to the threshold [S1]. Unlike [Lookup Table and Case Reduction](15794-lookup-table-and-case-reduction.md) which groups cases by symmetry, this method further fragments major cases into simpler geometric primitives (simplices) to manage higher-dimensional complexity, addressing the limitations of sibling methods like [Improved Marching Cubes with New Table and Displacement](14182-improved-marching-cubes-with-new-table-and-displacement.md) which do not explicitly handle the combinatorial growth in dimensions $n > 3$ [S1].

## How it works

### Inputs and Outputs
*   **Input:** An n-dimensional hypercube grid with scalar field values at vertices and a threshold value.
*   **Output:** A set of simplices (tetrahedra in 3D, hyper-tetrahedra in n-D) representing the isosurface.

### Data Structures

**1. Orientation Matrix**
Represents the transformation from the primary table index to individual simplex elements.
*   **Layout:** 32-bit integer.
*   **Encoding:** Uses 2 bits per position in the transformation matrix.
*   **Values:** Rotations are by $90^\circ$. Values $1, 0, -1$ are mapped to binary `00`, `01`, `10` respectively.
*   **Calculation:** Computed by rotating each sub-case into a standard sub-case and calculating the inverse transformation matrix [S1].

**2. Primary Table**
Maps the 256 (or $2^n$) vertex configurations to a secondary table entry.
*   **Method 3a (Major Cases):** Array of 65,536 tuples `(orientation, major-index)`.
    *   Size: 5 bytes per entry (4 bytes orientation, 1 byte major-index). Total ~328 KB [S1].
*   **Method 3b (Sub-Cases):** Array of 65,536 pointers to arrays of `(orientation, sub-index)` tuples.
    *   The array size represents the number of sub-cases per major case [S1].

**3. Secondary Table**
Contains the geometric definitions (simplices) for the cases.
*   **Method 3a:** Array of pointers to arrays of tetrahedra for the 222 major cases (in 4D).
*   **Method 3b:** Contains simplices for the sub-cases.
*   **Tetrahedron Storage:** 4 bytes per tetrahedron (1 byte for each of the 4 vertex labels) [S1].

### Pre-processing: Generating Major and Sub-Cases

The pre-processing phase identifies unique cases and decomposes them.

1.  **Initialize Lists:** Create two lists: `searched_cases` and `major_cases`.
2.  **Identify Major Cases:**
    *   Take the next unmarked index from the search list.
    *   Add it to `major_cases`.
    *   Exhaustively transform this index using rotation (R), mirror (M), and complement (C) operators.
    *   Mark all generated configurations as searched.
    *   Repeat until all indices are searched [S1].
3.  **Decompose into Sub-Cases:**
    *   For each major case, divide it into disjoint edge-connected sub-components.
    *   A **sub-case** is defined as an edge-connected fragment of the boundary where all vertices have the same status with respect to the threshold [S1].

### Tetrahedronization of Sub-Cases

This step converts the geometric definition of a sub-case into a list of simplices.

1.  **Representation:** Represent the sub-case object as a list of vertices. Each vertex is linked to a list of its neighbors. Initially, all vertices have three connections (in the context of the local cell geometry) [S1].
2.  **Vertex Selection:** Select the next vertex (in order on the list) with the fewest incident edges. This strategy is empirically most effective [S1].
3.  **Splitting:**
    *   Remove the selected vertex from the object.
    *   This generates one or two tetrahedra.
    *   It is straightforward to split a vertex with three edge connections into one tetrahedron, or four connections into two [S1].
4.  **Connectivity Update:** Update the connectivity of the remaining object by connecting the remaining vertices in the same configuration as the base of the split tetrahedron.
5.  **Backtracking:** If any vertex has five or more incident edges, backtrack to the previous level and attempt a different split. In practice, using the "fewest edges" method and taking a maximum of two tetrahedra at once, backtracking occurs for only three of the 74 sub-cases in 3D [S1].

### Disambiguation Strategy

Ambiguities occur when the surface intersects one face of the n-cube through each of its four edges, potentially generating spurious holes or additional surface segments. This face occurs in 2D and propagates to higher dimensions [S1].

*   **Strategy:** Use separate complementary case configurations.
*   **Logic:** For each ambiguous face $f$, there are $2^{\#f}$ possible sub-case configurations, but in practice only a subset is required (similar under rotation).
*   **Implementation:** Maintain vertex order (clockwise relative to the surface-object) to aid the renderer and ensure topological correctness [S1].

### Pseudocode

```python
def preprocess_major_cases(num_vertices):
    """
    Identifies unique major cases using symmetry operations.
    Returns a list of major case indices.
    """
    total_configs = 1 << num_vertices
    searched = [False] * total_configs
    major_cases = []
    
    for i in range(total_configs):
        if not searched[i]:
            major_cases.append(i)
            # Mark all symmetric equivalents as searched
            equivalents = get_symmetric_equivalents(i)
            for eq in equivalents:
                searched[eq] = True
                
    return major_cases

def decompose_subcase(major_case_index):
    """
    Decomposes a major case into edge-connected sub-cases.
    Returns a list of sub-case definitions.
    """
    # Get the vertex configuration for the major case
    config = get_vertex_config(major_case_index)
    
    # Identify edge-connected components where vertices have same status
    sub_cases = find_edge_connected_components(config)
    return sub_cases

def tetrahedronize_subcase(sub_case_vertices):
    """
    Converts a sub-case geometry into a list of tetrahedra.
    """
    # Represent as adjacency list
    graph = build_adjacency_list(sub_case_vertices)
    tetrahedra = []
    
    # Sort vertices by degree (number of incident edges)
    vertices_by_degree = sort_vertices_by_degree(graph)
    
    for vertex in vertices_by_degree:
        if is_backtracking_required(graph, vertex):
            # Backtrack logic would be implemented here by retrying
            # with a different vertex selection or split strategy.
            # For simplicity, we assume the "fewest edges" heuristic
            # minimizes this to rare cases.
            pass
            
        # Remove vertex and generate tetrahedra
        # A vertex with 3 connections -> 1 tetrahedron
        # A vertex with 4 connections -> 2 tetrahedra
        new_tets = split_vertex(graph, vertex)
        tetrahedra.extend(new_tets)
        
        # Update graph connectivity
        update_graph_connectivity(graph, new_tets)
        
    return tetrahedra

def get_orientation_matrix(sub_case, standard_sub_case):
    """
    Calculates the 32-bit orientation matrix.
    """
    # Rotate sub_case to match standard_sub_case
    # Calculate inverse transformation
    matrix = calculate_inverse_transformation(sub_case, standard_sub_case)
    
    # Encode matrix: 2 bits per position
    # Values 1, 0, -1 map to 00, 01, 10
    encoded = 0
    for val in matrix.flatten():
        if val == 1:
            bits = 0b00
        elif val == 0:
            bits = 0b01
        elif val == -1:
            bits = 0b10
        else:
            bits = 0b11 # Should not happen
            
        encoded = (encoded << 2) | bits
        
    return encoded

def render_n_cube(grid, threshold, primary_table, secondary_table):
    """
    Main rendering loop for an n-cube.
    """
    # 1. Determine vertex configuration
    config_index = 0
    for i, vertex in enumerate(grid.vertices):
        if vertex.value > threshold:
            config_index |= (1 << i)
            
    # 2. Lookup Primary Table
    # Method 3a: (orientation, major_index)
    # Method 3b: pointer to (orientation, sub_index) array
    primary_entry = primary_table[config_index]
    
    # 3. Determine Secondary Table Entry
    if method == 3a:
        orientation, major_idx = primary_entry
        # Lookup major case simplices
        simplices = secondary_table[major_idx]
    else: # Method 3b
        # Find the specific sub-case index based on local geometry
        sub_idx = find_sub_case_index(config_index, grid)
        orientation, sub_idx = primary_entry[sub_idx]
        simplices = secondary_table[sub_idx]
        
    # 4. Generate vertices for simplices using orientation
    output_mesh = []
    for tet in simplices:
        # Apply orientation transformation to vertex indices
        transformed_tet = apply_orientation(tet, orientation)
        # Map indices to actual intersection points on edges
        mesh_vertices = get_intersection_points(transformed_tet, grid)
        output_mesh.append(mesh_vertices)
        
    return output_mesh
```

### Parameters and Numbers

*   **3D Cases:** 14 major cases (or 15 if Complement operator is used) and 74 sub-cases [S1].
*   **4D Cases:** 222 major cases (using R, M) and 74 sub-cases [S1].
*   **Tetrahedron Storage:** 4 bytes per tetrahedron (1 byte per vertex label) [S1].
*   **Memory Usage (Method 2 - Complete Simplex Table):** 1.75 Mbytes.
    *   Calculation: $4 \times 356,817$ (tetrahedra data) + $5 \times 65,536$ (array pointers) for 356,817 tetrahedra across 222 major cases [S1].

### Edge Cases and Pitfalls

*   **Ambiguities:** Occur when the surface intersects one face of the n-cube through each of its four edges. This creates spurious holes or additional surface segments. This phenomenon occurs in 2D and propagates to higher dimensions [S1].
*   **Backtracking:** During tetrahedronization, if a vertex has five or more incident edges, the algorithm must backtrack. Using the "fewest edges" method, this occurs for only 3 of the 74 sub-cases in 3D [S1].
*   **False Negatives:** Adjacent complementary cases can lead to false negatives if not handled via the disambiguation strategy [S1].

## Operating characteristics

*   **Time Complexity:**
    *   **Pre-processing:** High. Decomposing major cases into sub-cases and tetrahedronizing them is computationally expensive. Method 1 (Dynamic Simplex Enumeration) takes the longest to calculate [S1].
    *   **Runtime:** Depends on the table method. Method 3a/3b allow fast lookup but require managing the primary/secondary table indirection.
*   **Memory Complexity:**
    *   **Method 1 (Dynamic):** Least memory, but slowest runtime [S1].
    *   **Method 2 (Complete Simplex):** 1.75 Mbytes for 4D (356,817 tetrahedra) [S1].
    *   **Method 3a (Major Cases):** ~328 KB for primary table + ~10.2 KB for secondary table (2,332 tetrahedra) [S1]. Note: Architectures may pad structures to 6-8 bytes, increasing primary table size.
    *   **Method 3b (Sub-Cases):** Primary table is an array of pointers to arrays of tuples. Secondary table contains simplices for sub-cases.
*   **Strengths:**
    *   Reduces the configuration space explosion in dimensions $n > 3$ where the number of major cases grows rapidly (e.g., 222 in 4D vs 256 in 3D) [S1].
    *   Simplifies the geometry associated with major cases by breaking them into edge-connected sub-cases [S1].
*   **Limitations:**
    *   Ambiguities still exist and require specific disambiguation strategies (complementary cases) [S1].
    *   High memory usage for complete simplex tables (Method 2) [S1].
    *   Pre-processing is complex due to the need for tetrahedronization and backtracking [S1].

## Background

*   **Origin:** The method is described in "Piecewise linear hypersurfaces using the marching cubes algorithm" [S1].
*   **History:** The approach addresses the limitations of standard Marching Cubes in higher dimensions. While 3D has 256 configurations (manageable), 4D has $2^{16} = 65,536$ configurations, with 222 major cases. The geometry becomes more complex, prompting the need for sub-case decomposition [S1].
*   **Usage:** Used in volume rendering and surface extraction for n-dimensional data, particularly when extending Marching Cubes to 4D or higher [S1].
