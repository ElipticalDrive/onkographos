# Sub-case decomposition for n-dimensional marching cubes

Also called: Major-case secondary table, Sub-case method, Sub-case secondary table

## Overview
Sub-case decomposition reduces the combinatorial explosion of configuration cases in n-dimensional marching cubes by decomposing major cases into edge-connected sub-cases, where vertices share the same status relative to the threshold [S1]. Unlike standard marching cubes that treat all 256 (in 3D) or exponentially many (in higher dimensions) configurations as distinct or grouped only by symmetry, this method groups configurations into a smaller set of "major cases" and further breaks them down into "sub-cases" to simplify table storage and generation for 4D and higher [S1]. It builds on [Marching Cubes Lookup and Configuration](2518-marching-cubes-lookup-and-configuration.md) by introducing a two-level lookup structure (primary and secondary tables) to handle the increased complexity of n-cube intersections [S1].

## How it works
The method operates by pre-computing a set of major cases and their constituent sub-cases, then storing them in a hierarchical table structure. The core innovation is the decomposition of a major case (a set of configurations equivalent under rotation, mirror, and complement) into edge-connected fragments (sub-cases) to manage the geometry of the isosurface intersection [S1].

### Inputs and Outputs
*   **Input:** An n-dimensional structured grid of scalar field values.
*   **Output:** A triangle (or simplex) mesh representing the isosurface.
*   **Pre-computed Data:** Primary and Secondary lookup tables containing orientation matrices and simplex indices for major and sub-cases [S1].

### Data Structures

#### 1. Orientation Matrix
Represents the transformation from the primary table index to individual simplex elements.
*   **Layout:** 32-bit integer.
*   **Encoding:** Uses 2 bits per position in the transformation matrix.
*   **Values:** Rotations are by 90°. Values $1, 0, -1$ are mapped to binary `00`, `01`, `10` respectively [S1].
*   **Calculation:** Calculated by rotating each sub-case into a standard sub-case and computing the inverse transformation matrix of the whole operation [S1].

#### 2. Primary Table
Maps the cell configuration index (0 to $2^n - 1$) to a secondary table index and orientation.
*   **Method 3a (Major Cases):** Array of 65,536 tuples `(orientation, major-index)`. Size: ~328 KB (assuming 5 bytes per tuple, though padding may increase this) [S1].
*   **Method 3b (Sub-Cases):** Array of 65,536 pointers to arrays of `(orientation, sub-index)` tuples. The array size includes the number of sub-cases per major case [S1].

#### 3. Secondary Table
Contains the actual geometric data (simplices/tetrahedra) for the cases.
*   **Method 2 (Complete Simplex):** A single large table for all indices. Size: 1.75 MB for 3D/4D hybrid stats (356,817 tetrahedra + pointers) [S1].
*   **Method 3a (Major Cases):** Array of pointers to arrays of tetrahedra for the 222 major cases. Size: ~10.2 KB for tetrahedra data + pointers (2,332 tetrahedra total for major cases) [S1].
*   **Method 3b (Sub-Cases):** Array of pointers to arrays of tetrahedra for the sub-cases.

#### 4. Tetrahedron Storage
*   **Layout:** 4 bytes per tetrahedron.
*   **Content:** One byte for each of the 4 vertex labels [S1].

### Algorithm Steps

#### Phase 1: Pre-processing (Generating Major and Sub-Cases)
This phase identifies the unique major cases and decomposes them into sub-cases.

1.  **Initialize Lists:** Create two lists: `searched_cases` (indices already processed) and `major_cases` (unique representatives).
2.  **Iterate Indices:** Take the next unmarked index from the search list.
3.  **Identify Major Case:** Add this index to the `major_cases` list.
4.  **Mark Equivalents:** Exhaustively transform this index using rotation ($R$), mirror ($M$), and complement ($C$) operators. Mark all resulting configurations as `searched`.
5.  **Repeat:** Continue until all indices are searched [S1].
6.  **Decompose into Sub-Cases:** For each major case, divide it into disjoint edge-connected sub-components. A sub-case is defined as a fragment of the boundary where vertices have the same status with respect to the threshold [S1].

#### Phase 2: Tetrahedronization of Sub-Cases
This phase generates the geometric simplices for each sub-case.

1.  **Representation:** Represent the sub-case object as a list of vertices, each linked to a list of neighbors. Initially, all vertices have three connections [S1].
2.  **Vertex Selection:** Select the next vertex (in order on the list) with the fewest incident edges.
3.  **Split:** Remove this vertex from the object, generating one or two tetrahedra.
    *   A vertex with 3 edges generates 1 tetrahedron.
    *   A vertex with 4 edges generates 2 tetrahedra.
4.  **Update Connectivity:** Update the connectivity of the remaining object by connecting the vertices of the remaining object in the same configuration as the base of the split tetrahedron.
5.  **Backtracking Check:** If any vertex has five or more incident edges, backtrack to the previous level and attempt a different split.
    *   *Note:* Using the "fewest edges" strategy, backtracking occurs for only 3 of the 74 sub-cases in 3D [S1].

#### Phase 3: Disambiguation Strategy
Ambiguities occur when the surface intersects one face of the n-cube through each of its four edges, potentially generating spurious holes or additional segments. This occurs in 2D and propagates to higher dimensions [S1].

1.  **Identify Ambiguous Faces:** For each ambiguous face $f$ in a given n-cube, there are $2^{\#f}$ possible sub-case configurations.
2.  **Select Configurations:** In practice, only a subset is required (similar under rotation).
3.  **Use Complementary Cases:** Use separate complementary case configurations for each ambiguous face. This maintains vertex order (clockwise relative to the surface-object), aiding the renderer [S1].

    """

    """
    total_configs = 2 ** n_dimensions
    searched = [False] * total_configs
    major_cases = []
    
    for index in range(total_configs):
        if searched[index]:
            continue

        major_cases.append(index)
        
        # Mark all symmetric equivalents as searched
        equivalents = get_symmetric_equivalents(index)
        for eq_idx in equivalents:
            searched[eq_idx] = True
            
    return major_cases

def decompose_into_subcases(major_case_index):
    """
    Decomposes a major case into edge-connected sub-cases.
    Returns a list of sub-case definitions.
    """
    # 1. Identify vertices in the major case configuration
    vertices = get_vertices_for_config(major_case_index)
    
    # 2. Build adjacency graph based on edge connections
    # A sub-case is an edge-connected component where vertices 
    # have the same status (inside/outside) relative to threshold.
    subcases = []
    visited = set()
    
    for vertex in vertices:
        if vertex in visited:
            continue
        
        # BFS/DFS to find edge-connected component
        component = []
        queue = [vertex]
        while queue:
            v = queue.pop(0)
            if v in visited:
                continue
            visited.add(v)
            component.append(v)
            
            # Add neighbors connected by edges
            for neighbor in get_edge_neighbors(v):
                if neighbor not in visited:
                    queue.append(neighbor)
        
        subcases.append(component)
        
    return subcases

def tetrahedronize_subcase(subcase_vertices):
    """
    Generates tetrahedra for a sub-case using the 'fewest edges' strategy.
    """

    vertex_list = []

        vertex_list.append({'id': v, 'neighbors': neighbors, 'removed': False})

            break

        # 4. Update connectivity

### Parameters and Typical Values
*   **3D Major Cases:** 14 (or 15 if Complement operator is used) [S1].
*   **3D Sub-Cases:** 74 [S1].
*   **4D Major Cases:** 222 (under R, M operators) [S1].
*   **4D Sub-Cases:** 74 [S1].
*   **Tetrahedron Size:** 4 bytes (1 byte per vertex label) [S1].
*   **Memory (Method 2 - Complete Simplex):** 1.75 MB for 356,817 tetrahedra and 65,536 array pointers ($4 \times 356,817 + 5 \times 65,536$ bytes) [S1].
*   **Memory (Method 3a - Major Cases):** ~328 KB for primary table (65,536 tuples) + ~10.2 KB for secondary table (2,332 tetrahedra) [S1].

### Edge Cases and Pitfalls
*   **Ambiguities:** Occur when the surface intersects one face of the n-cube through each of its four edges. This can generate spurious holes or additional surface segments. This phenomenon occurs in 2D and propagates to higher dimensions [S1].
*   **Backtracking:** During tetrahedronization, if a vertex has 5 or more incident edges, the algorithm must backtrack. Using the "fewest edges" strategy, this happens for only 3 of the 74 sub-cases in 3D [S1].
*   **Discontinuity:** At high magnifications, anomalies from local cell tilings may become visible, resulting in surface discontinuity. Subdivision techniques (e.g., Dividing Cubes) can mitigate this but increase computational cost [S1].

## Operating characteristics
*   **Time Complexity:** Pre-processing (table generation) is expensive, especially for higher dimensions. Method 1 (Dynamic Simplex Enumeration) takes the longest to calculate but uses the least memory. Method 2 (Complete Simplex Enumeration) is pre-calculated and fast at runtime but requires significant memory [S1].
*   **Memory Complexity:**
    *   Method 2 (Complete): 1.75 MB (for the specific 3D/4D stats cited) [S1].
    *   Method 3a (Major Cases): ~328 KB (primary) + ~10.2 KB (secondary) [S1].
    *   Method 3b (Sub-Cases): Primary table size depends on pointer overhead; secondary table size depends on the number of sub-cases.
*   **Strengths:** Reduces the number of cases that need to be explicitly stored or computed for higher dimensions (4D+), where the number of major cases explodes. Simplifies the geometry associated with major cases by breaking them into simpler sub-cases [S1].
*   **Limitations:** Requires complex pre-processing to generate the sub-case tables. Ambiguities still exist and require disambiguation strategies. At high magnifications, local discontinuities may still be visible [S1].
*   **When to Use:** When working in 4D or higher dimensions where storing all configurations or even all major cases is prohibitive. When memory is constrained but pre-computation is acceptable.
*   **When Not to Use:** In 3D, where storing all 256 cases is trivial and the overhead of sub-case decomposition may not be justified. When real-time table generation is required and pre-computation is not possible.

## Background
The sub-case decomposition method was introduced in the context of extending marching cubes to n-dimensional hypersurfaces. The primary motivation is the exponential growth of configuration cases in higher dimensions. In 3D, there are 256 configurations, which is manageable. However, in 4D, the number of major cases grows to 222 (under rotation and mirror symmetries), and the geometry becomes more complex [S1]. The method was developed to reduce the size of the lookup tables required for n-dimensional marching cubes by decomposing major cases into edge-connected sub-cases [S1]. It is part of a broader effort to handle topological correctness and ambiguity in higher-dimensional surface extraction [S1].
